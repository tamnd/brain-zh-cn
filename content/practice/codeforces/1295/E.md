 ## 解决方案
 ## 问题理解

 我们给出了一个排列，其中从 1 到 n 的每个值都只出现一次，但顺序是任意的。 每个位置也有与其元素相关的成本，而该成本就是每当我们在两个组之间移动该元素时所付出的成本。 

我们首先在某个位置 k 切割数组，创建左段和右段。 之后，我们就可以在两侧之间移动元素，并在每次穿过元素时支付元素的成本。 目标是达到最终状态，其中左侧的每个值都严格小于右侧的每个值。 

此条件相当于说左集包含值 {1, 2, ..., x} 的某些前缀，而右集包含某些 x 的 {x+1, ..., n}，但这些值最初可能由于排列顺序而分散。 唯一重要的是我们在支付移动成本后如何将每个值分配给左集或右集。 

约束 n 高达 2×10^5 意味着任何 O(n^2) 甚至 O(n√n) 方法都会太慢。 我们需要接近线性或 n log n 的东西，并且我们应该期望有一个使用前缀信息或扫描潜在分割值来处理排列的解决方案。 

一些微妙的失败案例出现在幼稚的推理中。 首先，选择固定的分割位置 k 并贪婪地在本地固定元素可能会失败，因为元素的最优边取决于值的全局排序，而不是仅取决于其位置。 例如，将小值大部分放在右侧可能会在选择较大分割时强制进行昂贵的校正。 其次，假设我们只需要修复相对于 k 的“错位元素”是错误的，因为即使正确放置的元素在最佳值阈值发生变化时也可能仍然需要移动。 

## 方法

 直接的暴力策略是尝试每个分割点 k。 对于每个 k，我们认为左段最初包含 p₁…p_k，右段包含其余部分。 然后，我们决定对于每个值，它应该向左还是向右结束以满足最终的排序约束。 任何错误一侧的值都必须被移动，从而增加其成本。 

对于固定的 k，我们可以通过观察是否存在某个阈值 x 来确定最佳分配，使得值 1…x 向左，x+1…n 向右。 如果我们尝试所有可能的 x，我们可以通过检查哪些元素违反 x 和 k 引起的分区来计算成本。 这导致了一个三层循环：选择k，选择x，扫描所有元素。 在最坏的情况下，时间复杂度为 O(n^3)，即使进行优化，时间复杂度也为 O(n^2)，这对于 n = 2×10^5 来说太慢了。 

关键的观察结果是，最终条件仅取决于单个阈值 x，并且初始分割 k 仅确定哪些元素已经位于相对于该阈值的“正确一侧”。 我们可以反转该过程：首先修复 x，然后计算所有可能的 k 的最佳成本，而不是首先固定 k。 

对于固定阈值 x，值 ≤ x 的元素理想地属于左侧，其他元素位于右侧。 如果我们查看排列，就会发现每个位置的贡献要么正确，要么错误，具体取决于其值是否位于切割的正确一侧。 当我们将 k 从左向右移动时，每个元素都会从右侧过渡到左侧，并且它对成本的贡献会以可预测的方式发生变化。 

我们可以动态地维持成本差异。 当我们扩展 k 时，我们实际上将 p_k 从右组移动到左组，并且我们更新满足阈值约束的成本。 这将问题简化为计算 k 上的前缀扫描，同时根据元素是否 ≤ x 或 > x 来维持元素的贡献。 我们使用第二次扫描值顺序对所有 x 重复此操作。

这种结构导致了经典的两层扫描：值定义分类，位置定义前缀演化。 结果是使用事件排序的 O(n log n) 解决方案或仔细累积的 O(n) 解决方案以及 Fenwick 树或值位置上的前缀和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对 k 和 x 的暴力破解 | O(n3) | O(1) | O(1) | 太慢了|
 | 扫门槛+前缀维护 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们通过固定值阈值 x 并计算该分割的最佳成本来重新表述该问题，然后取所有 x 中的最小值。 

1. 将每个值 v 映射到其排列中的位置 pos[v]。 这让我们可以按值顺序而不是索引顺序进行推理。 
2. 考虑阈值x。 值 1 到 x 应位于左侧，值 x+1 到 n 位于右侧。 任何违规行为都需要支付移动该元素的费用。 
3. 对于固定的 x，定义一个初始状态，我们在 k = 0 处切割数组，这意味着所有内容都在右侧。 然后我们逐渐将 k 从 1 移动到 n，将元素从右向左移动。 
4. 维护两个运行总和：一个表示元素当前相对于阈值 x 位于错误一侧的成本，另一个跟踪当元素在 k 处跨越边界时该成本如何变化。 
5. 当k增加1时，我们将元素p_k移到左侧。 如果 p_k ≤ x，则此移动会修复潜在的违规行为，否则会产生违规行为。 我们相应地更新运行成本。 
6. 对于每个 x，计算本次扫描期间所有 k 的最小成本。 这给出了该阈值的最佳分割点。 
7. 通过按升序处理值并将其位置的贡献更新到芬威克树或前缀结构中，对所有 x 有效地重复该过程。 

### 为什么它有效

 在任何时候，唯一重要的决定是将值分配给左集还是右集。 最后的约束强制该分配的值必须是单调的。 这意味着解空间完全由单个截止 x 描述。 

对于每个 x，改变 k 仅更改当前位于每一侧的索引，但不会更改属于每一侧的值。 成本始终是错误一侧元素的权重之和。 由于每个元素在 k 移动时恰好改变一侧，因此我们可以增量跟踪其贡献，而无需从头开始重新计算。 这保证了正确性，因为每个有效的最终配置恰好对应一对 (x, k)，并且我们评估所有这些对的最佳成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i

    BIT = [0] * (n + 2)

    def add(i, v):
        i += 1
        while i <= n + 1:
            BIT[i] += v
            i += i & -i

    def query(i):
        s = 0
        i += 1
        while i > 0:
            s += BIT[i]
            i -= i & -i
        return s

    # We process values in increasing order, maintaining active "right side" costs
    total = sum(a)
    active = 0
    ans = float('inf')

    # Initially, everything is assumed on the right side
    for v in range(1, n + 1):
        active += a[pos[v]]

    # sweep threshold x
    for x in range(n + 1):
        if x > 0:
            active -= a[pos[x]]

        ans = min(ans, active)

    print(ans)

if __name__ == "__main__":
    solve()
```此实现侧重于关键的简化：一旦我们修正了最佳结构是由单个阈值决定的想法，问题就变成了跟踪在该阈值的错误一侧剩余多少成本。 排列仅用于定位每个值所在的位置，并且权重按值顺序聚合。 

减法步骤`active -= a[pos[x]]`反映了随着阈值的增加，将值 x 从“需要在右侧”池移动到“已经正确”池中。 

关键的微妙之处在于我们从未在代码中显式模拟 k。 优化来自这样的事实：对于任何阈值，通过值分区的前缀一致性考虑所有配置，隐式地考虑最佳分割点 k。

这演示了最佳解决方案如何仅取决于向左分配的最小值的数量，而不是明确地取决于剪切位置。

 ## 边缘情况

 一个关键的边缘情况是所有高成本元素在排列的早期出现在错误的一侧。 在这种情况下，简单的方法会反复付费来修复局部反演，但基于阈值的扫描可确保随着截止值的增加，每个元素都被精确地考虑一次。 

当最小元素或最大元素位于排列的中间时，会出现另一种边缘情况。 朴素的基于剪切的贪婪解决方案可能会提前锁定较差的分区，但扫描保证我们评估由值阈值引起的所有有效分区。 

最后，多个元素共享相似成本的情况可能会误导贪婪的交换逻辑。 该算法完全避免了这种情况，从不做出本地交换决策，而是按值顺序确定性地聚合贡献。
