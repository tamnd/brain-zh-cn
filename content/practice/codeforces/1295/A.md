 ## 解决方案

 ## 问题理解

 任务是使用数字显示模型构建尽可能大的整数，其中每个数字消耗固定数量的发光段。 每个测试用例都给出一个预算`n`，这是我们允许打开的段总数。 我们可以放置任意数量的数字，只要它们的分段成本之和不超过`n`。 目标是最大化结果数字的数值。 

一个关键的微妙之处在于，我们并不是试图最大化位数或最小化未使用的段，而是尝试在约束下按字典顺序排列最大数字。 这立即意味着应该优先选择更高的数字，但它们也可能消耗更多的段，因此在数字价值和成本之间需要权衡。 

约束条件`n ≤ 10^5`每个测试用例的总和为`10^5`，排除对数字分区的任何指数或组合搜索。 任何解决方案都必须在每个测试用例的线性或接近线性时间内运行。 

一个天真的错误是假设我们应该贪婪地重复选择可能的最大数字而不考虑剩余的段。 例如，总是选择`9`第一个可能会导致死胡同，其中剩余的段无法形成任何有效的数字组合，即使较小的初始数字将允许更长或更大的最终数字。 另一个微妙的失败来自于尝试首先最大化数字计数，这可能会产生更多的数字，但前导数字更小，从而减少最终的数值。 

正确的方法取决于认识到只有一个数字放置策略主导所有其他策略：尽可能多次地使用分段成本最小的数字，同时从左侧升级数字以最大化价值。 

## 方法

 每个数字都有固定的分段成本，我们希望在总预算下组装尽可能多的数字。 暴力解释是尝试所有可能的数字序列，其成本总和最多为`n`，然后计算最大数值。 这是正确的，但不可行，因为序列的数量呈指数增长`n`，大致顺序为`10^n`在最坏的情况下。 

一旦我们观察到在所有数字中，数字`1`使用最少的段 (2)。 这使得它成为最大化长度的最佳选择：任何以更高成本替换数字的解决方案都可能被多个替换`1`s，如果排列正确，会增加数字计数，从而增加词典价值。 因此，最佳策略是使用最大化位数`1`，然后通过将一些领先位置升级到更大的数字来改善结果，同时尊重成本预算。 

关键的见解是我们首先仅使用`1`s。 然后，由于较大的数字在较高的位置总是更有价值，因此我们贪婪地尝试替换前导`1`其替换不超过剩余段预算的最大数字。

 ## 算法演练

 1. 预先计算每个数字的分段成本`0`到`9`。 这允许在评估替换时进行恒定时间查找。 
2. 对于每个测试用例，计算如果我们只使用数字，我们可以放置多少个数字`1`，因为它的成本最小（2 段）。 这给出了`k = n // 2`。 
3.如果`k`为零，我们甚至不能放置一个数字，但是因为`n ≥ 2`，这永远不会发生。 我们将结果初始化为字符串`k`那些。 
4. 计算形成此基线数后剩余多少额外段：`remaining = n % 2`。 
5.我们尝试从左到右改进数字。 对于每个位置，我们检查是否可以替换当前数字`1`具有更大的数字`d`。 如有费用差异则换货有效`(cost[d] - cost[1])`小于或等于剩余预算。 
6. 当可以更换时，我们会分配该数字并相应减少剩余预算。 我们总是首先尝试更大的数字以最大化词典价值。 
7. 继续，直到无法再升级或所有位置均已处理完毕。 

### 为什么它有效

 构造总是从最大可能的位数开始，这是最佳的，因为当我们可以控制数字位置时，增加位数总是可以改善或保留字典顺序。 一旦长度固定，任何改进都必须来自于增加更高位置的数字。 由于替换更重要的位置中的数字总是占主导地位，因此用最大可能的数字进行贪婪的从左到右升级可以保持最优性。 不变的是，在每一步中，到目前为止构建的前缀是剩余预算下某些最优解决方案的最佳可能前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

cost = [0] * 10
cost[0] = 6
cost[1] = 2
cost[2] = 5
cost[3] = 5
cost[4] = 4
cost[5] = 5
cost[6] = 6
cost[7] = 3
cost[8] = 7
cost[9] = 6

for _ in range(int(input())):
    n = int(input())

    k = n // 2
    res = ['1'] * k

    remaining = n - 2 * k

    for i in range(k):
        for d in range(9, -1, -1):
            if i == 0 and d == 0:
                continue
            if cost[d] <= 2 + remaining:
                if d != 1:
                    remaining -= (cost[d] - 2)
                res[i] = str(d)
                break

    print("".join(res))
```该代码首先对段成本进行编码，这避免了重复重新计算数字结构。 对于每个测试用例，基线构建仅使用数字`1`最大化长度。 循环数字`9`下降到`0`确保我们始终首先尝试最有价值的替代品。 

条件`i == 0 and d == 0`防止前导零，这会人为地增加数字计数而不增加数值。 仅当我们实际升级时才会调整剩余预算`1`，因为基线已经考虑了成本`2`。

 ## 边缘情况

 对于最小的有效输入`n = 2`，该算法恰好产生一位数字`"1"`因为无法升级。 施工开始于`k = 1`，且除此之外没有任何数字`1`在不减少位数的情况下满足成本限制，因此输出稳定。 

对于以下情况`n`刚好高于 2 的倍数，例如`n = 3`，算法仍然构建一位数字并使用额外的段来升级该数字。 这表明剩余容量总是被消耗在提高数字值而不是增加长度上，这与最大化整数的最佳结构相匹配。
