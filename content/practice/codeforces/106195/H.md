 ## 解决方案
 ## 问题理解

 该问题要求我们计算有多少个不同的操作序列可以创建给定数量的等价类。 我们从`n`全部被认为是相同的元素。 每个操作都会选择元素的某个子集，并将所选元素与未选择元素分开。 在所有操作之后，当每个操作始终以相同的方式处理两个元素时，它们仍然完全相同。 任务是输出每个可能数量的最终等价类`1`到`n`，有多少个操作序列恰好产生那么多的类。 这是 Codeforces Gym 106195 中标题为“Equivalenceclasss”的问题。 

查看操作的关键方法是为每个元素分配一个二进制签名。 对于每个操作，一个元素都会收到一个`0`如果它在所选子集之外并且`1`如果它在里面的话。 后`k`操作，每个元素都有一个长度的二进制字符串`k`。 当两个元素的签名相等时，它们完全相等，因此等价类的数量就是所使用的不同签名的数量。 

有`2^k`可能的签名。 约束条件允许`n`达到`10000`，所以一个`O(n^2)`解决方案是现实的，但任何事情都取决于`2^k`直接是不可能的，因为`k`可以大到`10^18`。 我们需要只使用的公式`n`和模运算。 

微妙的部分是类的数量不能超过`n`，尽管可能有很多可能的签名。 一个常见的错误是计算选择类别的方法而不考虑元素是否已标记。 例如，如果`n = 2`和`k = 1`，有两个可能的签名，`0`和`1`。 

对于输入：```
2 1
```有四种可能的操作顺序。 选择空集给出两个元素的签名`0`，选择全套给出两个签名`1`，并且选择任一单元素子集都会给出两个不同的签名。 答案是：```
2
2
```第一行表示有两种方法创建一个类，第二行表示有两种方法创建两个类。 只计算可能的签名集的粗心方法会导致第一个值错误，因为元素是可区分的。 

另一个边缘情况出现时`k`很大但是`n`很小。 例如：```
3 1000000000000000000
```可能的签名有很多，但我们只需要下降阶乘的前几个值`(2^k)(2^k-1)...`，因为实际上最多可以使用三个不同的签名。 任何尝试枚举签名的方法都会立即失败。 

## 方法

 蛮力的想法是考虑所有可能的最终签名。 每个`n`元素可以接收任何`2^k`二进制字符串，所以有`(2^k)^n`可能的任务。 我们可以生成每个作业，计算不同签名的数量，并增加该数量的类的答案。 

这是正确的，因为一系列操作与为每个元素选择一个签名完全相同。 然而，任务的数量是无法处理的。 即使对于中等值，例如`n = 100`和`k = 100`，搜索空间远远超出任何程序可以访问的范围。 

有用的观察是，我们并不关心使用了哪些特定签名，只关心出现了多少个不同的签名。 假设最终的班级数是`i`。 首先，我们需要选择哪个`i`使用签名。 有`C(2^k, i)`选择。 然后我们需要分配`n`标记元素到这些`i`选择签名，以便每个签名至少出现一次。 

第二部分是来自的onto函数的数量`n`元素到`i`类。 这个值是`i! * S(n, i)`， 在哪里`S(n, i)`是第二类斯特林数。 将两部分相乘得出：```
C(2^k, i) * i! * S(n, i)
```可以重写为：```
(2^k)(2^k - 1)...(2^k - i + 1) * S(n, i)
```第一个因子是下降阶乘。 因为我们只需要高达`i = n`，我们永远不需要超过`10000`项，所以我们可以直接计算它的模`998244353`。 

斯特林数通过递推式计算：```
S(n, i) = S(n - 1, i - 1) + i * S(n - 1, i)
```递归来自于考虑最后一个元素。 它要么自己形成一个新的类，要么加入现有的类之一`i`类。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((2^k)^n) | O((2^k)^n) | O(n) | 太慢了|
 | 最佳 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 计算 的值`2^k`模数`998244353`。 我们永远不需要实际值，因为公式中的每个乘法和减法都是在模下完成的。 
2. 计算所有斯特林数`S(n, i)`为了`1 <= i <= n`使用动态规划。 递归逐行构建答案，其中每行表示将元素前缀拆分为给定数量的非空组的方法数。 
3. 构建下降阶乘值。 开始于`1`，然后重复乘以`(2^k - i)`对于每个可能的类数。 之后的值`i`乘法表示选择和排序的方式数量`i`不同的签名。 
4. 对于每个可能的类数`i`，将下降阶乘乘以`S(n, i)`。 这给出了精确产生的操作序列的数量`i`等价类。 

这样做的原因是每个最终状态都由元素的签名唯一地表示。 如果确切地说`i`出现签名，使用过的签名可以在`P(2^k, i)`方式，并且元素必须划分为`i`分配给这些签名的非空组。 斯特林数精确地计算这些分区，因此每个有效序列都被计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())

    sig = pow(2, k, MOD)

    dp = [0] * (n + 1)
    dp[0] = 1

    for elements in range(1, n + 1):
        nxt = [0] * (n + 1)
        for groups in range(1, elements + 1):
            nxt[groups] = (dp[groups - 1] + groups * dp[groups]) % MOD
        dp = nxt

    ans = [0] * (n + 1)
    fall = 1
    for i in range(1, n + 1):
        fall = fall * ((sig - i + 1) % MOD) % MOD
        ans[i] = fall * dp[i] % MOD

    print("\n".join(map(str, ans[1:])))

if __name__ == "__main__":
    solve()
```代码的第一部分计算`2^k`具有模幂。 这可以处理非常大的值`k`无需构建可能签名的实际数量。 

动态编程数组存储当前行的斯特林数。 添加新元素时，该元素要么创建一个新类（由前一行移动一位表示），要么加入现有类，这会导致可用组数的乘法。 

下降阶乘是增量构建的。 表达式使用`sig - i + 1`因为选择之后`i - 1`签名，剩下的选择就少了很多。 在乘法之前应用模运算以保持所有值有界。 

最终的乘法结合了两个独立的选择：选择实际的签名并在其中分配标记的元素。

 ## 边缘情况

 当`n = 1`，只有一个元素，因此每种可能的操作序列都恰好留下一个等价类。 该算法处理这个问题是因为唯一需要的斯特林值是`S(1,1)=1`，并且下降阶乘有一项。 

什么时候`k`非常大，可能的签名数量非常巨大，但算法只需要`2^k mod 998244353`。 例如，与`n = 3`和`k = 10^18`，代码从不存储签名本身，而只计算所需的三个下降阶乘项。 

当所需类别的数量大于可用签名的数量时，下降阶乘自动变为零。 发生这种情况是因为最终我们尝试选择比现有的更多不同的签名，因此这些类计数的答案正确地为零。
