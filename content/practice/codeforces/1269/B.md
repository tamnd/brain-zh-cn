 **标签：** 暴力破解，排序
 **求解时间：** 1m 58s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组。 我们可以选择一个非负值`x`，将其添加到第一个数组的每个元素，并对所有结果取模`m`。 

经过此转换后，元素的顺序并不重要。 我们可以任意重新排列转换后的数组。 任务是找到最小的`x`变换后的多重集与第二个数组表示的多重集完全相同。 

关键细节是我们正在比较多重集，而不是位置。 如果两个数组包含具有相同频率的相同值，则在某些排列后它们被认为是相等的。 

这些限制异常显着。 数组长度最多为2000，而`m`可以大到`10^9`。 迭代所有可能值的解决方案`x`这是不可能的，因为搜索空间太大了。 另一方面，`n = 2000`足够小以至于`O(n² log n)`解决方案是完全可以接受的。 在期限内可以管理大约 800 万次操作。 

一些边缘情况很容易破坏粗心的实现。 

考虑重复值：```
n = 3, m = 5
a = [0, 0, 0]
b = [2, 2, 2]
```正确答案是`2`。 

假设所有元素都是不同的并尝试匹配位置而不是频率的解决方案将会失败。 

环绕模算术是错误的另一个来源：```
n = 2, m = 10
a = [8, 9]
b = [0, 1]
```正确答案是`2`因为：```
(8 + 2) mod 10 = 0
(9 + 2) mod 10 = 1
```使用普通减法而不进行模处理会错误地产生负移位。 

当几个转变看起来似乎合理时，就会出现更微妙的情况：```
n = 3, m = 7
a = [0, 1, 2]
b = [1, 2, 3]
```两个数组都已排序，有效移位为`1`。 不验证整个多重集的贪婪匹配策略可能会错误地接受另一个候选者。 

该问题保证至少存在一个有效答案，但我们仍然必须找到最小的一个。 

## 方法

 一个简单的暴力想法是尝试每一个可能的转变`x`从`0`到`m - 1`。 对于每个候选者，变换每个元素`a`，对结果数组进行排序，并将其与排序后的版本进行比较`b`。 

这是可行的，因为条件仅取决于值的多重集。 如果排序后的变换数组等于排序后的目标数组，则存在某种排列。 

问题是大小`m`。 自从`m`可以达到`10^9`，检查每个班次是完全不可行的。 

关键的观察来自排序。 

让：```
A = sorted(a)
B = sorted(b)
```假设有一些转变`x`是有效的。 申请后`x`模数`m`, 的最小元素`B`必须源自某些元素`A`。 

认为`A[i]`成为最小元素`B[0]`。 然后：```
(A[i] + x) mod m = B[0]
```这意味着```
x = (B[0] - A[i] + m) mod m
```对于每个职位`i`，该公式生成一种可能的转变。 只有`n`这样的候选人。 

为什么这就足够了？ 因为在任何有效的转换中，某些元素`A`必须映射到最小值`B`。 其中就会出现相应的shift`n`候选人。 

现在问题变得小多了。 生成从匹配元素派生的所有候选移位`A`到`B[0]`。 对于每个候选者，变换每个值`A`，对结果进行排序，并与`B`。 

在所有有效候选者中，返回最小值。 

由于只有`n`候选人和每次验证费用`O(n log n)`，总复杂度变为`O(n² log n)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(m·n log n) | O(m·n log n) | O(n) | 太慢了 |
 | 最佳| O(n² log n) | O(n² log n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`m`，以及两个数组。 
2. 对两个数组进行排序并将它们存储为`A`和`B`。 
3. 对于每个索引`i`在`A`，计算候选位移```
x = (B[0] - A[i] + m) mod m
```这对应于强制`A[i]`成为目标多重集中的最小值。 
4. 将这个候选转变应用到每个元素`A`:```
transformed[j] = (A[j] + x) mod m
```5. 对转换后的数组进行排序。 
6. 将排序后的转换数组与`B`。 

如果它们相等，则此移位有效。 
7. 保留遇到的最小有效班次。 
8. 输出最小移位。 

### 为什么它有效

 假设`x*`是正确的答案。 

申请后`x*`，变换后的值恰好形成由下式表示的多重集`B`。 的最小值`B`，即`B[0]`，必须来自某个元素`A[i]`。 

对于该元素，```
(A[i] + x*) mod m = B[0]
```重新排列为```
x* = (B[0] - A[i] + m) mod m
```因此`x*`是生成的候选者之一。 

通过显式构造变换后的多重集并将其与`B`。 当且仅当候选生成完全所需的多重集时，该候选才被接受。 

由于每个有效的转变都会被检查并且我们返回最小的有效转变，因此算法总是会产生正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b.sort()

    answer = m

    for v in a:
        x = (b[0] - v) % m

        transformed = sorted((num + x) % m for num in a)

        if transformed == b:
            answer = min(answer, x)

    print(answer)

if __name__ == "__main__":
    solve()
```第一步是对两个数组进行排序，因为问题实际上是比较多重集。 一旦排序，多重集的相等性就变成普通的数组相等性。 

循环结束`a`生成所有候选班次。 每个候选者都来自这样的观察：已排序的源数组的某些元素必须映射到已排序的目标数组的最小元素。 

对于每个候选者，代码使用模算术转换每个元素。 表达式```
(num + x) % m
```必须严格按照这种形式使用。 忘记模运算在环绕情况下会失败。 

转换后的值在比较之前先进行排序。 即使转换是正确的，模运算也可以改变元素的顺序，因此不排序进行比较也是不正确的。 

变量`answer`存储迄今为止找到的最小有效移位。 该问题要求最小的有效移位，而不仅仅是任何有效移位。

 ## 边缘情况

 考虑重复值：```
3 5
0 0 0
2 2 2
```排序后：```
A = [0,0,0]
B = [2,2,2]
```每个候选人都会产生：```
x = (2 - 0) mod 5 = 2
```变换给出：```
[2,2,2]
```哪个匹配`B`。 该算法比较多重集，而不是位置，因此可以自然地处理重复项。 

考虑环绕算法：```
2 10
8 9
0 1
```候选人源自`8`是：```
x = (0 - 8 + 10) mod 10 = 2
```应用转变：```
(8 + 2) mod 10 = 0
(9 + 2) mod 10 = 1
```变换后的多重集正好变成`[0,1]`。 负差异永远不会引起问题，因为所有候选移位都是按模计算的`m`。 

考虑一个不正确的候选者看起来似乎合理的情况：```
3 7
0 1 2
1 2 3
```候选生成自`A[0]`是：```
x = 1
```成功了。 

另一位候选人可能会正确对齐一个元素，但会产生与以下不同的转换后的多重集`B`。 由于每个候选者都是通过比较整个排序数组来验证的，因此不会意外地接受部分匹配。
