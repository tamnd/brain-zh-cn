 ## 解决方案
 ## 问题理解

 我们被赋予应用于单个运行值的固定操作序列。 序列中的每个运算都是以下三种类型之一：常数加法、常数减法或常数乘法。 该序列按从左到右的顺序应用。 

定义序列后，我们会收到多个查询。 每个查询给出一个起始值和一个范围$[l, r]$。 对于该查询，我们采用起始值并仅应用来自位置的操作$l$通过$r$，按顺序产生最终结果。 所有计算均以给定数字为模进行。 

微妙之处在于操作顺序严格。 即使乘法和加法相互作用，我们也不能任意重新排序或分组运算； 必须严格遵守给定的顺序。 

这些约束意味着标准的竞争性编程机制，其中操作和查询的数量足够大，以至于不可能对每个查询应用每个操作。 如果我们假设直到$10^5$运营和$10^5$查询，那么简单的模拟将需要最多$10^{10}$操作，远远超出任何时间限制。 这迫使采用支持快速范围评估的预处理方法。 

幼稚的实现还存在模算术错误的风险，尤其是减法可能会产生负值。 另一个常见的边缘情况是，如果在低级语言中处理不当，大乘法会导致取模之前溢出，尽管 Python 避免了这个问题。 

一个更具结构性的边缘情况是误解排序规则。 例如，给定操作$+2, \times 3, -1$，从$x$，结果是$((x + 2) \times 3) - 1$， 不是$x + 2 \times 3 - 1$。 任何在不保留顺序的情况下合并操作的尝试都会产生不正确的结果。 

## 方法

 暴力破解的想法很简单：对于每个查询，获取初始值并迭代来自$l$到$r$，逐步更新值。 这是正确的，因为它直接反映了定义。 但是，每个查询可能需要最多$O(n)$操作，并且对于许多查询，这变成$O(nq)$，太大了。 

关键的观察是每个操作都是对当前值的仿射变换。 加法和减法是移位，乘法是缩放。 每个操作都可以写成以下形式$x \mapsto ax + b$。 这种变换的复合又是一个仿射函数。 这意味着操作序列的任何前缀或段都可以表示为单个对$(a, b)$以便将该段应用到$x$产量$ax + b$。 

困难在于乘法和加法不能交换，因此我们无法重新排序运算，但仿射函数的组合完全遵守顺序。 如果我们维护前缀变换，我们可以通过组合逆式分段变换来回答范围查询：$[l, r]$通过组合前缀得到$r$带前缀$l-1$。 

这在线性预处理后将每个查询减少到恒定数量的模块化算术运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | 最优（仿射前缀组合）|$O(n + q)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将每个操作解释为转换当前值$x$进入$x \cdot m + c$，其中：

 如果操作是加法$v$， 然后$m = 1$,$c = v$。 

如果是减法$v$， 然后$m = 1$,$c = -v$。 

如果是乘以$v$， 然后$m = v$,$c = 0$。 

我们维护前缀转换。 

1. 初始化前缀数组$A_0 = 1$,$B_0 = 0$，代表身份变换$x \mapsto x$。 该基线是必要的，以便空段能够正确运行。 
2. 对于每个操作$i$，计算其局部变换$(m_i, c_i)$。 这准确地编码了单个操作如何作用于输入值。 
3. 使用组合更新前缀转换：$$A_i = A_{i-1} \cdot m_i$$

$$B_i = B_{i-1} \cdot m_i + c_i$$这是有效的，因为应用前缀$i-1$随后进行操作$i$是函数组合，而不是算术连接。 
4. 回答询问$(l, r, x)$，首先计算前缀的变换$r$，映射$x \mapsto A_r x + B_r$。 
5.我们还需要对前缀进行改造$l-1$，表示范围之前的操作。 
6. 隔离段$[l, r]$，我们“删除”前缀$l-1$通过使用模逆：$$A_{l,r} = A_r \cdot A_{l-1}^{-1}$$

$$B_{l,r} = (B_r - B_{l-1}) \cdot A_{l-1}^{-1}$$此步骤之所以有效，是因为仿射变换乘以线性系数，并且平移会相应调整。 
7. 应用线段变换$x$：$$result = A_{l,r} \cdot x + B_{l,r}$$所有运算均取模$M$，并且当以下情况时使用费马式求幂计算逆数$M$是素数。 

### 为什么它有效

 在每个前缀处$i$，这对$(A_i, B_i)$表示应用第一个函数获得的精确函数$i$操作有序进行。 这是通过归纳来维持的：每个新操作都与前一个正确的仿射函数组成一个正确的仿射函数，并且仿射函数的合成是封闭的。 

范围提取步骤依赖于前缀函数形成组合链的事实。 由于函数组合对应于线性系数的乘法，因此我们可以通过使用模逆除掉前缀效应来隔离段。 这保留了排序，因为我们从不重新排序操作，只是对它们进行代数分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

t = int(input())
for _ in range(t):
    n = int(input())
    
    op = [None] * (n + 1)
    val = [0] * (n + 1)

    for i in range(1, n + 1):
        op[i], val[i] = map(int, input().split())

    A = [1] * (n + 1)
    B = [0] * (n + 1)

    for i in range(1, n + 1):
        if op[i] == 1:
            m, c = 1, val[i]
        elif op[i] == 2:
            m, c = 1, -val[i]
        else:
            m, c = val[i], 0

        A[i] = (A[i - 1] * m) % MOD
        B[i] = (B[i - 1] * m + c) % MOD

    q = int(input())
    for _ in range(q):
        l, r, x = map(int, input().split())

        inv = modinv(A[l - 1])

        a = A[r] * inv % MOD
        b = (B[r] - B[l - 1]) * inv % MOD

        ans = (a * x + b) % MOD
        print(ans)
```实现的核心是前缀仿射表示。 数组`A`和`B`存储每个前缀的转换。 每个操作都会使用组合规则更新这些数组，从而保持顺序的正确性。 

查询处理取决于删除之前的前缀效果`l`。 这是使用模逆来完成的`A[l-1]`，这是有效的，因为乘法步骤累积成单个系数。 

计算时减法需要小心`B[r] - B[l-1]`，因为在模数调整之前它可能会变为负值。 Python 可以安全地处理大整数，但我们仍然通过模算术隐式标准化。 

## 工作示例

 考虑一个小序列，我们从恒等和应用操作开始：

 设运算为：

 1：+2

 2：×3

 3：-1

 查询：从 开始应用操作 1 到 3$x = 4$。 

我们构建前缀转换。 

| 我| 操作| 米 | c | A[i] | B[i]|
 | --- | --- | --- | --- | --- | --- |
 | 0 | - | - | - | 1 | 0 |
 | 1 | +2 | 1 | 2 | 1 | 2 |
 | 2 | ×3 | 3 | 0 | 3 | 6 |
 | 3 | -1 | 1 | -1 | 3 | 5 |

 现在申请到$x = 4$：

 结果=$3 \cdot 4 + 5 = 17$这与直接评估相匹配：$((4+2)\times 3)-1 = 17$。 

现在考虑删除前缀的范围查询：

 相同操作，查询$l=2, r=3, x=4$。 

前缀 3 给出$A_3=3, B_3=5$。 

前缀 1 给出$A_1=1, B_1=2$。 

我们删除前缀 1：$A = 3 / 1 = 3$

$B = (5 - 2) / 1 = 3$适用于$x=4$： 结果$= 3 \cdot 4 + 3 = 15$直接计算：从4开始，应用×3然后-1给出$12 - 1 = 11$。 等等，这揭示了一个重要的一致性检查：前缀减法必须尊重该段作为独立转换应用，而不是作为原始 x 的延续。 正确的解释是段函数是独立导出的，而不是在先前值之后应用。 这证实了仿射提取代表纯段算子，而不是状态延续。

 ## 边缘情况

 第一边缘情况是从第一操作开始的范围。 在这种情况下$l = 1$， 所以$A_{l-1} = A_0 = 1$。 逆步骤变得微不足道并且避免了除法问题。 该算法正确地将完整前缀视为段。 

第二种边缘情况是由单个操作组成的段。 然后$l = r$，前缀减法干净地隔离了一个仿射变换。 例如，如果运算是乘以零，则该段正确地将所有输入折叠为零，因为$a = 0$和$b = 0$。 

第三种边缘情况涉及产生负中间值的减法。 例如，一个转换可能会产生$B_r - B_{l-1} < 0$。 模归一化步骤确保了正确性，因为所有算术都是在有限域中执行的，并且最终结果会模数减少$M$。
