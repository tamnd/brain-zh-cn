 ## 解决方案
 ## 问题理解

 我们得到了一系列卡片。 每张牌都有四种类型的花色和一个数字。 在每个花色中，数字都是唯一的并且来自相同的范围，因此每个花色的行为就像相同值集的排列。 

我们可以一张一张地取出卡片并将它们重新插入到任何地方，这相当于将初始序列转换为任何最终序列，其成本是我们有效需要移动的卡片数量。 这是一种经典的说法，我们希望保留尽可能多的牌，同时重新排列其余的牌。 

目标安排受到两个方面的限制。 首先，在每种花色中，如果我们只查看最终序列中该花色的牌，它们的数字必须按升序出现。 其次，这副牌的最后一部分必须完全由花色 U 卡组成。 

任务是尽量减少必须移动的卡片数量，以便我们能够达到满足这两个约束的某种安排。 

输入由多个测试用例组成，每个测试用例描述一个这样的套牌。 每个测试用例的输出是一个整数，即所需的最小移动次数。 

由于每个测试用例的卡总数可能很大，达到典型的竞争性编程限制，因此每个测试用例的 O(n²) 或更差方法会太慢。 我们应该期望每个测试用例有一个大约 O(n log n) 或 O(n) 的解决方案。 

当我们忽略“U 卡必须在末尾”约束时，就会出现微妙的失败情况。 

例如，假设 U 卡在原始序列中出现较早，但我们还想保留一些出现在它们之后的非 U 卡。 如果我们选择两者作为“保留子序列”的一部分，则子序列中的相对顺序将违反最终排列中所有 U 卡必须位于所有其他卡之后的要求。 每种花色的幼稚 LIS 式解决方案会忽略这种跨花色排序约束，并且会过量计算有效“保留”的牌。 

当我们假设我们可以独立处理诉讼时，另一个失败案例就会出现。 尽管套装内排序是独立的，但 U 卡的放置引入了将所有套装耦合在一起的全局拆分约束。 

## 方法

 蛮力解释是考虑选择我们保留哪些牌和移动哪些牌的所有方法。 对于每个候选选择，我们都会检查是否可以将保留的卡片排列成有效的最终序列。 这将涉及验证每个套装的顺序并确保 U 卡形成后缀。 子集的数量与卡片的数量呈指数关系，因此除了非常小的输入之外，这立即变得不可行。 

更结构化的观点是翻转视角。 我们不是构造最终的排列，而是尝试识别已经满足最终约束的原始数组的最大子序列。 不在该子序列中的每张牌都对应一个动作。 

在每种花色中，要求很简单，数字必须按递增顺序出现。 如果我们修复数组的一部分，这就是最长递增子序列问题。 困难在于第二个约束：U 卡必须出现在保留结构中所有非 U 卡之后。 这迫使所选子序列进行全局分割：所有非 U 保留的牌必须来自比所有 U 保留的牌更早的位置。 

这表明了一种自然的结构。 想象一下在原始序列中选择一个剪切点。 它之前的所有内容仅贡献非U卡，其之后的所有内容仅贡献U卡。 对于每种花色，在切割的每一侧内，我们都希望获得超过牌值的最长递增子序列，因为子序列中的顺序必须尊重原始位置和递增值。

我们可以计算，对于每个前缀，我们可以保留多少张每种花色的牌，同时考虑到不断增加的数字。 我们可以对仅限于 U 卡的后缀执行相同的操作。 然后我们尝试所有的分割点，并将非U卡的最佳前缀贡献与U卡的最佳后缀贡献结合起来。 

关键的观察结果是，每个花色都可以使用 Fenwick 树对值进行独立处理，从而在头寸上保持类似 LIS 的 DP。 这避免了每次分割时从头开始重新计算 LIS。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集检查 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 每套带有 LIS 的前缀/后缀 DP | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们读完所有牌，并按花色将它们分成四个序列，保持它们出现的顺序。 这保留了对子序列约束重要的唯一顺序。 
2.我们构建一个前缀DP。 当我们从左到右扫描时，对于每种花色，我们维护一个按牌值索引的芬威克树。 该树存储以每个值结尾的最佳子序列长度。 当我们处理一张非 U 套装的牌时，我们会更新该套装的结构。 位置 i 处的前缀状态代表我们可以从前 i 张牌中保留的非 U 卡的最佳数量，同时尊重每个花色中递增的顺序。 

Fenwick 在这里工作的原因是，一旦我们按照原始顺序处理卡片，“在一套花色中增加数字”就成为标准的 LIS 值。 
3.我们以对称的方式构建后缀DP，但仅针对U卡。 我们从右向左扫描，再次维护每套芬威克树，但现在代表我们可以从该后缀形成的最佳递增子序列。 这给出了对于每个位置 i，我们可以保留从 i 开始的 U 卡的最大数量。 
4.我们尝试每一个可能的分割点i。 对于每个分割，候选答案是 i 之前的非 U 卡的最佳前缀值加上 i 之后的 U 卡的最佳后缀值。 
5. 我们取所有分割点的最大值。 最终的答案是卡片总数减去最大保留计数。 

正确性取决于任何有效子序列必须在非 U 卡和 U 卡之间存在边界。 所有非 U 卡必须出现在子序列中所有 U 卡之前，因此此边界始终可表示为原始顺序中的剪切。 

## 为什么它有效

 任何有效的保留卡组都会产生一个唯一的分割点：保留的非 U 卡的最大原始索引。 此后保留的所有内容都必须是 U 卡。 这将全局约束减少到数组的单个分区中。 

在分区的每一侧中，剩下的唯一限制是按套装递增顺序，这正是原始排序下值的 LIS。 Fenwick DP 可以正确计算该限制下的最佳可能选择。 

由于每个有效的解决方案都对应于一个分割，并且每个分割都会被评估，因此始终会捕获最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            res = max(res, self.bit[i])
            i -= i & -i
        return res

def solve():
    t = int(input())
    for _ in range(t):
        cards = input().split()
        if not cards:
            cards = input().split()

        n = len(cards)

        suit_idx = {'H': 0, 'Z': 1, 'C': 2, 'U': 3}

        values = [[] for _ in range(4)]
        seq = []

        for c in cards:
            s = suit_idx[c[0]]
            v = int(c[1:])
            seq.append((s, v))

        maxv = max(v for _, v in seq)

        pref = [[0] * (maxv + 2) for _ in range(4)]
        fenw = [Fenwick(maxv + 2) for _ in range(4)]

        best_pref = [0] * (len(seq) + 1)

        for i, (s, v) in enumerate(seq, 1):
            if s != 3:
                cur = fenw[s].query(v - 1) + 1
                fenw[s].update(v, cur)
                best_pref[i] = best_pref[i - 1] + max(0, cur - (best_pref[i - 1] - best_pref[i - 1]))
            else:
                best_pref[i] = best_pref[i - 1]

        fenw_r = [Fenwick(maxv + 2) for _ in range(4)]
        best_suf = [0] * (len(seq) + 2)

        for i in range(len(seq) - 1, -1, -1):
            s, v = seq[i]
            if s == 3:
                cur = fenw_r[3].query(v - 1) + 1
                fenw_r[3].update(v, cur)
                best_suf[i] = best_suf[i + 1] + cur
            else:
                best_suf[i] = best_suf[i + 1]

        ans_keep = 0
        for i in range(len(seq) + 1):
            ans_keep = max(ans_keep, best_pref[i] + best_suf[i])

        print(len(seq) - ans_keep)

if __name__ == "__main__":
    solve()
```前缀和后缀结构是分开的，因为 U 约束仅适用于尾部。 芬威克树确保我们仅按值扩展递增子序列。 对分割点的最终扫描强制执行 U 卡和非 U 卡之间的全局排序约束。 

一个微妙的一点是，我们永远不会在同一个 DP 结构中混合 U 和非 U。 这种分离使得分割公式有效。

 ## 边缘情况

 当所有 U 卡都出现在开头时，就会出现一种边缘情况。 在这种情况下，天真的 LIS 方法很乐意将它们保留在适当的位置，但拆分约束迫使它们被移动，除非我们决定将它们从保留的前缀中排除。 

对于输入：```
U1 U2 H1 Z1 C1
```最佳分割将所有非 U 卡放在子序列中的第一位，并且所有 U 卡都被有效地推到构建的排列中的后缀。 该算法评估分割点并正确避免对无效前缀位置的 U 卡进行计数。 

当 U 卡末尾已经连续但非 U LIS 由于排序混乱而较小时，会出现另一种边缘情况。 在这种情况下，后缀 DP 占主导地位，算法自然会选择 U 块开头的边界，在不违反约束的情况下最大化组合的保留计数。
