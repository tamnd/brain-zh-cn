 ## 解决方案
 ## 问题理解

 我们有一个冠军池，每个冠军都由一组固定特征上的二进制字符串来描述。 一个`1`在位置`j`意味着冠军拥有特质`j`。 我们还为每个特性提供了所需数量的独特冠军，这些冠军必须具备该特性才能激活。 

任务不是决定固定选择的可行性，而是选择规模最多为给定限制的冠军子集，以便尽可能多的特征变得活跃。 仅当在选定的冠军中，至少其所需数量的冠军包含该特征时，该特征才会激活。 

因此，决策是两层组合的。 首先，我们选择一个冠军子集，然后每个特征独立检查是否有足够多的所选冠军对其做出贡献。 

这些约束（与这种形式的 Codeforces F 级问题中的典型大规模问题相比，冠军数量相对较少）意味着对冠军的指数推理是可以接受的，而任何依赖于迭代所有特征子集或在没有结构的情况下进行每个子集重新计算的任何事情都会失败。 

一个幼稚的尝试是贪婪地挑选能够最大化立即特性激活的冠军。 这失败了，因为特征通过共同的冠军相互作用。 一个有助于完成一项特质的英雄可能对另一项特质也至关重要，过早的选择可能会阻碍更好的组合。 

第二个天真的想法是评估冠军的每个子集并计算有多少特征得到满足。 这是正确的，但一旦冠军数量超过大约 25 个，就变得不可行，因为子集的数量随着$2^m$，每个子集都需要扫描所有特征。 

关键的隐藏困难是，我们正在子集上优化单调但非线性的目标：添加冠军永远不会损害任何特征计数，但好处只有在跨越阈值后才会出现。 这种“每个特征的阶跃函数”结构使得蛮力可以通过修剪或小 m 来使用，但如果没有更强的结构，则很难进一步加速。 

当多个特征具有相同或重叠的需求时，就会出现微妙的边缘情况。 例如，一个冠军组合可能几乎同时满足两个特征，但是提前完成一个特征的贪婪选择会降低第二个特征的灵活性，从而导致总激活特征变得更差。 这就是任何本地选择策略都会失败的原因。 

## 方法

 暴力方法是枚举每个可能的冠军子集，只要我们保持在插槽限制内。 对于每个子集，我们针对每个特征计算有多少选定的冠军具有该特征，然后检查其是否满足激活阈值。 这是直接且正确的，因为它直接评估定义而不进行近似。 

这种方法的成本来自于子集爆炸。 如果有$m$冠军，有$2^m$子集。 对于每个子集，我们可能需要重新计算最多可达的特征计数$t$特征，给出最坏情况的复杂性$O(2^m \cdot m \cdot t)$。 这一旦变得不可行$m$大于约25。 

关键的观察是，决策空间从根本上取决于冠军，而不是特质。 特质只是一种评分机制。 这使我们能够接受指数复杂度$m$只要$m$足够小，并使用位操作或预先计算的掩码增量计算特征满意度。 每个子集都可以通过聚合其冠军的特质面具来有效评估。 

这将问题转化为具有增量累积的干净子集枚举，其中每个状态都是独立的，并以每个特征位的恒定摊销工作进行评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^m \cdot m \cdot t)$|$O(1)$或者$O(t)$| 如果 m 大则太慢 |
 | 使用位掩码优化子集枚举 |$O(2^m \cdot t)$|$O(m \cdot t)$| 接受小m |

 ## 算法演练

 我们将每个冠军视为特征的位掩码。 目标是尝试最多达到插槽限制的所有可能的冠军子集，并计算有多少特征变得活跃。 

1. 预先计算每个冠军的特质位掩码，以便检查冠军是否对特质有贡献是一个恒定时间的位操作。 这避免了在子集评估期间重复扫描字符串。 
2. 使用位掩码迭代所有冠军子集`0`到`(1 << m) - 1`。 
3. 对于每个子集，首先检查其大小是否超出槽位限制。 如果是，请立即跳过它，因为它不是有效的选择。 
4. 对于有效子集，计算一个数组`cnt[j]`存储有多少个选定的冠军包含特征`j`。 这是通过迭代子集的设置位并累积它们的贡献来完成的。 
5. 计算计数后，评估每个特征：如果`cnt[j]`至少是该特征所需的阈值，增加该子集的分数。 
6. 跟踪所有子集的最大分数并将其输出。 

我们能够负担得起这个枚举的关键原因是每个子集的评估与特征和所选冠军的数量呈线性关系，并且子集的数量对于预期的约束来说足够小。 

### 为什么它有效

 每个有效的冠军选择都精确对应一个子集掩码。 该算法针对每个此类子集评估问题中定义的目标函数。 由于除了那些违反大小限制的子集之外，不会跳过任何子集，并且每个评估的子集都根据特征激活的定义精确评分，因此最大记录值是所有有效选择的真正最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, S = map(int, input().split())
    k = list(map(int, input().split()))

    masks = []
    for _ in range(m):
        s = input().strip()
        mask = 0
        for i, ch in enumerate(s):
            if ch == '1':
                mask |= 1 << i
        masks.append(mask)

    best = 0

    for sub in range(1 << m):
        if sub.bit_count() > S:
            continue

        cnt = [0] * n

        i = 0
        x = sub
        while x:
            if x & 1:
                mp = masks[i]
                for j in range(n):
                    if (mp >> j) & 1:
                        cnt[j] += 1
            x >>= 1
            i += 1

        score = 0
        for j in range(n):
            if cnt[j] >= k[j]:
                score += 1

        if score > best:
            best = score

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个冠军压缩为整数位掩码，以便特征成员资格检查变成位操作。 然后它枚举冠军的所有子集并按槽位约束进行过滤。 对于每个子集，它通过仅迭代选定的冠军并检查它们对哪些特征做出贡献来重建特征计数。 

子集上的位迭代是使用移位掩码方法完成的，这避免了重复调用昂贵的操作，例如索引的列表转换。 最后的评分步骤直接实现激活规则。 

这里的一个常见错误是通过重新解析字符串从头开始重新计算每个子集的特征贡献。 这会增加字符串长度的额外因素并且变得太慢。 另一个微妙的问题是忘记尽早强制执行槽限制，这会导致对无效子集进行不必要的计算。

 ## 边缘情况

 一种特殊情况是，所有英雄都对所有特性做出贡献，但插槽限制太小而无法满足任何阈值。 例如，如果每个冠军都具有所有特征，但每个特征需要比允许的插槽更多的选择，则每个子集都会失败。 该算法仍然评估所有子集，但没有一个子集超过阈值，从而正确生成零。 

另一种情况是当阈值最小时，例如所有阈值$k_j = 1$。 然后，对至少一个选定冠军中存在的任何特征进行计数，并且最佳解决方案通常对应于在槽位约束下简单地最大化覆盖范围。 枚举仍然可以正确处理这个问题，因为它不假定独立性或结构。 

第三种情况是槽位限制等于冠军数量。 枚举中包含完整的集合，并且由于考虑了所有子集，因此保证在没有特殊情况下找到最佳解决方案。
