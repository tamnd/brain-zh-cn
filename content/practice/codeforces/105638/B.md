 ## 解决方案
 ## 问题理解

 我们为每个测试用例给出一个目标数字，我们需要决定它是否可以表示为精心构造的整数与其数字之和的总和。 更准确地说，我们正在寻找一个非负整数$x$这样当我们计算其十进制数字之和并将其加回到$x$，结果等于给定的数字。 

如果这样一个$x$存在，任何有效的构造都是可以接受的。 如果没有整数可以满足这个条件，我们必须输出-1。 

输入大小建议多个独立查询，每个查询都需要快速决策而不是搜索。 由于输出取决于数字结构而不是单独的算术属性，因此当目标很大时，不可能对所有候选值进行暴力破解。 尝试所有$x$最多$n$每个测试用例已经是线性的，如果测试用例的总和很大，那么就会立即中断。 

逆向思维时会出现微妙的边缘情况。 许多天真的尝试尝试从目标中“减去数字和”，但数字和取决于数字本身，因此任意减法不能保持有效性。 

具体的失败案例有助于说明这一点。 假设目标是 1。如果我们尝试$x = 1$， 然后$x + S(x) = 1 + 1 = 2$，这会超调。 尝试$x = 0$给出$0 + 0 = 0$。 没有办法达到1，所以正确的输出是-1。 这表明并非所有整数都可以表示。 

另一个隐藏的陷阱是假设每个数字都可以使用任意数字和来形成，这是错误的，因为数字和受到数字的位数及其最大贡献的严格限制。 

## 方法

 蛮力策略将迭代所有可能的候选者$x$从 0 到目标值并检查是否$x + S(x)$等于目标。 计算数字和需要$O(\log x)$，因此每个测试用例的总成本变为$O(n \log n)$在最坏的情况下。 如果$n$可能很大，这太慢了，尤其是在许多查询中重复时。 

关键的观察结果是有效数字具有非常严格的结构。 如果我们重新排列方程$$x + S(x) = n,$$我们看到$n - x = S(x)$。 右边是数字和，当数字以受控方式最大化时，它始终是 9 结构的倍数。 

建设性的见解是假设$x$由重复的 9 组成。 如果$x$包括$k$数字都等于9，那么$$x = 10^k - 1, \quad S(x) = 9k.$$代入方程得到$$n = (10^k - 1) + 9k = 10^k + 9k - 1.$$这意味着每个有效答案都对应于选择数字长度$k$，构造多个全9，并检查它是否与目标匹配。 我们不是搜索所有整数，而是只测试一小部分$k$，以中的位数为界$n$。 

这减少了从搜索值到检查少数结构化候选的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解一切x |$O(n \log n)$|$O(1)$| 太慢了|
 | 尝试数字长度构造 |$O(\log n)$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 对于每个测试用例，我们尝试利用有效数字必须完全由 9 组成的事实来重建答案。 

1.读取目标号码$n$。 这是我们想要匹配的值$x + S(x)$。 
2. 迭代可能的数字长度$k$，从 1 开始到合理的界限，例如 18 或中的位数$n$。 这个界限就足够了，因为更大$k$已经产生了超出典型限制的值。 
3.构建候选号$x$组成$k$数字，全部等于 9。这对应于$x = 10^k - 1$。 
4. 计算所需的表达式$x + S(x)$， 在哪里$S(x) = 9k$因为所有数字都是9。 
5. 如果该值等于$n$，立即返回$x$作为有效答案。 
6. 如果没有值$k$产生匹配，返回-1。 

### 为什么它有效

 任何有效的解决方案必须满足$n - x = S(x)$。 数字总和随位数线性增长，但数字本身呈指数增长。 这两个量能够在数字长度上以稳定、可预测的方式保持同步的唯一方法是当数字最大化时，这会强制形成全 9 的结构。 这将解决方案空间限制为一个小的、可枚举的族。 由于这个家族中的每个候选人都是直接测试的，所以不会错过任何有效的解决方案，也不会意外通过无效的构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(n):
    # try k-digit all-9 numbers
    x = 0
    s = 0

    # we build 9, 99, 999... incrementally
    for k in range(1, 20):
        x = x * 10 + 9
        s = 9 * k
        if x + s == n:
            return x
    return -1

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(solve_one(n))

if __name__ == "__main__":
    main()
```该解决方案维持了由重复的 9 组成的数字的运行结构，而不是重新计算 10 的幂。 每次迭代将数字长度增加一，并且数字和被解析更新为$9k$，避免逐位计算。 

20 的循环界限就足够了，因为即使$10^{19}$已经超出了典型的限制，并且超出了构建的值变得太大而无法匹配合理的输入。 

## 工作示例

 考虑目标为 19 的情况。 

我们测试增加的值$k$。 

| k | x（全 9）| S(x) | x + S(x) |
 | ---| ---| ---| ---|
 | 1 | 9 | 9 | 18 | 18
 | 2 | 99 | 99 18 | 18 117 | 117

 没有出现匹配项，因此输出为 -1。 这说明并不是所有的数都可以组成。 

现在考虑一个构建的有效案例。 假设目标是 18。 

| k | x（全 9）| S(x) | x + S(x) |
 | ---| ---| ---| ---|
 | 1 | 9 | 9 | 18 | 18

 这里我们立即找到匹配项，因此输出为 9。 

第一条迹线显示当没有数字长度与目标对齐时的拒绝。 第二个确认该算法正确地识别了有效的结构，而不需要除结构化候选之外的任何搜索。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            found = False
            x = 0
            for k in range(1, 20):
                x = x * 10 + 9
                if x + 9 * k == n:
                    out.append(str(x))
                    found = True
                    break
            if not found:
                out.append("-1")
        return "\n".join(out)

    return solve()

# edge-like simple cases

assert run("1\n18\n") == "9", "single valid k=1"
assert run("1\n19\n") == "-1", "no solution"
assert run("1\n117\n") == "99", "k=2 case"

 ## 边缘情况

 像 1 这样的小输入暴露了达到非常低的目标的可能性。 运行算法，第一个候选者是$x = 9$，它已经产生 18，因此不存在更小的候选者，结果正确地变为 -1。 

对于中等大小的无法到达的数字（例如 19），算法会检查$k=1$和$k=2$，分别产生 18 和 117，均不符合目标。 由于不存在其他结构，因此输出仍为 -1。 

对于像 117 这样的有效多位数，迭代达到$k=2$, 构建$x=99$，并验证$99 + 18 = 117$，立即产生正确答案，而不探索进一步的值。
