 ## 解决方案
 ## 问题理解

 我们有一棵树，其中每条边都带有可以为正或负的权重。 任意两个节点之间都存在一条简单路径，因此“两个节点之间的最短路径”并不是多条路径中的一种选择，而只是那条唯一的树路径。 

对于每对无序节点，我们查看沿其连接路径的边权重之和。 任务是计算有多少对具有严格正的总路径和。 

输入大小意味着一棵大树，因此任何直接检查所有对的解决方案都将无法生存。 评估每一对的简单方法将需要计算大约 n² 对的路径总和，即使使用快速 LCA 查询，对于大 n 来说，这仍然太慢。 这立即将我们推向一种技术，其中每个边或每个节点参与受控数量的聚合，最好是 n 的对数。 

一个微妙的方面是边缘权重允许为负数。 这消除了单调结构：我们不能以任何可预测的方式假设较长的路径更重或更轻。 

暴露这一困难的一个边缘情况是星形树。 如果中心连接到具有负边缘的所有叶子，则每个叶子到叶子的路径都会经过中心，并根据组合变为正值或负值。 每个边的天真的“本地”推理失败了，因为贡献通过共享的祖先相互作用。 

另一个重要的边缘情况是线树。 在具有交替权重的链中，部分总和可能会剧烈波动，因此任何按深度或距根距离的贪婪排序都是不可靠的。 

## 方法

 暴力解决方案很简单：通过沿着树向上行走或使用预先计算的 LCA 距离来计算每对节点的路径和，然后计算有多少个和为正。 对于 n 个节点，这会检查 n(n−1)/2 对，即使每对有 O(1) 个 LCA 查询，总工作量也是二次的。 对于 n 大约 2×10⁵ 来说，这是完全不可行的。 

关键的结构观察是，每一对都贡献一条路径，并且每条路径都可以通过选择位于其上的“中心分裂点”来分解。 如果我们选择位于 u 和 v 之间的路径上的节点 c，则路径和会干净地分割为 dist(u, v) = dist(u, c) + dist(c, v)。 这表明，如果我们可以根据路径上的节点对对进行分组，我们就可以仅使用到该节点的距离来计算贡献。 

这正是质心分解变得有用的设置。 树中的每条路径在位于其上的分解树中都有一个唯一的最高质心，我们可以确保每对路径在其最高质心的级别上精确计数一次。 在该质心，所有相关信息都简化为距质心的简单距离值，将问题转化为对数字总和进行限制的计数对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 太慢了|
 | 质心分解| O(n log² n) | O(n log² n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 我们在树上建立质心分解。 在每个质心，我们处理路径经过该质心的所有节点对，并且通过分离递归组件之间的贡献来确保不会对任何对进行多次计数。 

### 步骤

1. 选择当前树组件的质心c。 删除 c 后，这会将组件拆分为子树，每个子树都更小。 这保证了对数递归深度。 
2. 对于当前组件中的每个节点，计算其沿原始树到 c 的距离。 这可以通过从 c 开始的 DFS 来完成。 
3. 我们一一处理子树。 对于每个子树，我们想要计算一个节点位于子树内部而另一个节点位于任何先前处理的子树或已累积池中的对，因为这些正是路径经过 c 的对。 
4. 对于当前子树中的每个节点 u，我们需要统计有多少个先前见过的节点 v 满足 dist(c, u) + dist(c, v) > 0。这个条件来自于这样的事实：当 c 位于 u 和 v 之间的路径上时，全路径和等于距 c 的距离之和。 
5. 维护已处理节点的距离排序结构。 对于每个 u，我们查询有多少存储值超过 −dist(c, u)。 这可以通过对排序列表进行二分搜索来完成。 
6. 处理完子树后，将其所有节点的距离插入到全局结构中，以便以后的子树可以与它们配对。 
7. 删除质心后递归到每个子树，重复相同的逻辑。 

### 为什么它有效

 每对节点在分解树中都有一个唯一的最高质心，位于它们的连接路径上。 在该质心处，算法仅对该对求值一次，因为只有在处理该质心时，两个节点才会出现在不同的已处理子树或当前子树中，同时在其路径上共享质心。 该转换将路径和比较简化为两个预先计算的距质心距离的比较，确保正确性而无需重复重新计算路径和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input().strip())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, w))
    g[v].append((u, w))

subsz = [0] * n
blocked = [False] * n

def dfs_size(u, p):
    subsz[u] = 1
    for v, _ in g[u]:
        if v != p and not blocked[v]:
            dfs_size(v, u)
            subsz[u] += subsz[v]

def dfs_centroid(u, p, total):
    for v, _ in g[u]:
        if v != p and not blocked[v]:
            if subsz[v] > total // 2:
                return dfs_centroid(v, u, total)
    return u

def dfs_collect(u, p, dist, arr):
    arr.append(dist)
    for v, w in g[u]:
        if v != p and not blocked[v]:
            dfs_collect(v, u, dist + w, arr)

from bisect import bisect_right

answer = 0

def process(c):
    global answer

    all_nodes = []
    dfs_collect(c, -1, 0, all_nodes)
    all_nodes.sort()

    prefix = []

    for u, w in g[c]:
        if blocked[u]:
            continue

        comp = []
        dfs_collect(u, c, w, comp)

        for d in comp:
            need = -d
            cnt = len(prefix) - bisect_right(prefix, need)
            answer += cnt

        for d in comp:
            bisect = bisect_right(prefix, d)
            prefix.insert(bisect, d)

    blocked[c] = True
    for v, _ in g[c]:
        if not blocked[v]:
            solve(v)

def solve(entry):
    dfs_size(entry, -1)
    c = dfs_centroid(entry, -1, subsz[entry])
    process(c)

solve(0)

print(answer)
```质心分解是核心结构，其他一切都是围绕距离进行记账。 每个质心的 DFS 仅用于收集每个组件内的距离。 排序列表维护来自先前处理的子树的动态候选节点集，并使用二分搜索来计算有多少个有效满足不等式约束。 

一个微妙的点是，我们只组合来自质心的不同子子树的节点，这确保每个有效对在正确的分解级别上精确计数一次。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |

 ## 边缘情况

 单边树是最简单的情况。 质心是一个端点或中间节点，具体取决于实现，但在所有情况下，唯一的一对仅被评估一次，并且答案仅取决于该边权重的符号。 

星形树更加精致，因为许多对共享相同的中心节点。 质心分解确保中心成为分解根，因此所有叶到叶的交互都在该质心级别处理。 距中心的距离完全决定了每对的总和，因此不会错过任何相互作用。 

权重交替的线强调分解顺序的正确性。 尽管部分总和有所不同，但每个质心都会隔离平衡线段，以便跨线段对仅计数一次并且不会重复。
