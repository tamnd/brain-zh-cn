 ## 解决方案
 ## 问题理解

 问题提出了一个场景，其中有`n`队列，最初是空的，以及一系列`n`离散时刻。 每时每刻，每个队列都会接收一定数量的新顾客。 到达后，可以为单个队列提供服务，从而将其客户数量重置为零。 毕竟`n`过了一会儿，我们被要求最大化所有队列中剩余客户的最小排除数量（MEX）。 

MEX 是剩余客户计数集中不存在的最小非负整数。 例如，如果最终计数是`[0, 1, 3]`，墨西哥是`2`因为`0`和`1`出现，但是`2`没有。 目标是通过最佳选择每次服务的队列来确定可实现的最大 MEX。 

鉴于`n`最多可达 300 个，并且总和`n^2`所有测试用例最多`2×10^5`，任何迭代服务订单的所有可能排列的解决方案都太慢。 一种天真的暴力方法需要`n!`模拟，这是完全不可行的。 边缘情况包括所有队列接收相同数字的序列，或者某些队列提前接收非常大的数字的序列，如果服务做得不好，则无法构建具有较小 MEX 值的最终序列。 

## 方法

 暴力方法将尝试模拟每个时刻要服务的队列的每种可能的顺序。 对于每个排列，我们将跟踪累积客户计数，在每个步骤重置所选队列，并计算最终的 MEX。 这种方法原则上是正确的，但完全棘手，因为`n!`增长速度快于`10^300`为了`n=300`。 

关键的见解来自于观察，目标是生成最终队列计数，以便它们包含尽可能多的从零开始的连续整数。 我们可以将问题解释为构造表示最终队列大小的整数多重集。 每个队列只会被服务一次，因此每个队列的最终计数是它收到的所有增量的总和，减去它被服务时的增量。 由于增量严格为正数，因此服务后队列中可达到的最小顾客数量是**服务前**到达的累积总和。 为了最大化 MEX，我们应该始终为当前尚未服务的到达累积总和最小的队列提供服务。 换句话说，尽可能小的最终数字应该分配给从零开始的最小整数。 

因此，最优策略简化为对所有`n×n`客户按非递减顺序递增，并将它们贪婪地分配给最终计数`0, 1, 2, …`。 具体来说，对行和进行排序后，可达到的最大MEX是最大整数`k`这样至少`k`队列的最终计数不少于`0, 1, …, k-1`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n^2) | O(n! × n^2) | O(n^2) | O(n^2) | 太慢了|
 | 贪婪/建设性| O(n^2 log n) | O(n^2 log n) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和`n×n`到达矩阵`a`。 
3. 计算每个队列的到达总和`total[i] = sum(a[i])`。 
4. 排序`total`按非递减顺序。 
5. 初始化`mex = 0`。 
6. 迭代排序后的总计，并且对于每个`total[i]`， 如果`total[i] >= mex`, 增量`mex`1. 这确保了对于 MEX`k`，至少存在一个队列，其最终计数可以表示`k-1`。 
7. 输出`mex`对于测试用例。 

**为什么有效：** 在每个时刻以最小的累积和服务队列可以保证最小可能的最终计数占据从 0 向上的连续整数。 通过迭代排序的总数并递增`mex`每当队列可以满足下一个所需的整数时，我们就有效地计算最大可能的连续前缀，即最大 MEX。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    total = []
    for _ in range(n):
        row = list(map(int, input().split()))
        total.append(sum(row))
    total.sort()
    mex = 0
    for val in total:
        if val >= mex:
            mex += 1
    print(mex)

t = int(input())
for _ in range(t):
    solve()
```**说明：** 该解决方案读取所有到达，对行进行求和以获得潜在的最终总计数，并对它们进行排序。 迭代排序后的总数允许我们以最大化 MEX 的方式贪婪地将最小整数分配给队列。 比较`val >= mex`确保从 0 开始的每个数字都可以表示。

 ## 边缘情况

 如果所有队列在每个时刻都收到相同的数字，则算法正确地识别出最大 MEX 是`n`，因为每个队列可以代表从 0 到 的连续整数之一`n-1`。 如果一个队列较早收到非常大的增量，那么它自然会在贪婪排序中最后被服务，而较小的队列会收到最大化 MEX 所需的较小数字。 这种方法可以安全地处理大值，因为它只将总和与范围内的整数进行比较`[0, n]`。
