 ## 解决方案
 ## 问题理解

 给定二维平面上的一组点和一个正偶整数`d`。 任务是确定我们是否可以选择三个不同的点，使得每对之间的曼哈顿距离恰好为`d`。 回想一下点之间的曼哈顿距离`(x1, y1)`和`(x2, y2)`是`|x1 - x2| + |y1 - y2|`。 输出是任何这样三个点的索引，或者`0 0 0`如果不存在这样的三元组。 

输入尺寸可以达到`n = 2 * 10^5`单个测试用例中的点，以及`n`所有测试用例都不超过这个。 给定 3 秒的时间限制，任何迭代所有三元组点的算法都需要 O(n³) 运算，这显然是不可行的。 因此，对所有点三元组进行强力检查太慢。 

当发生微妙的边缘情况时`d`相对于坐标范围较大，或者点聚集在一起，使得曼哈顿三角形不存在。 例如，如果所有点都位于一条直线上或者点之间的距离始终小于`d`，输出应该是`0 0 0`。 粗心的实现可能会返回无效的索引或错过不存在的情况。 

## 方法

 蛮力方法将迭代所有三元组`(i, j, k)`并计算所有三对之间的曼哈顿距离。 这是正确的，但需要 O(n³) 时间，这对于`n ~ 2*10^5`。 

关键的见解来自对曼哈顿距离的几何推理。 曼哈顿距离形成菱形轮廓，并且对于具有相等曼哈顿距离的三个点`d`，它们必须以特定的轴平行模式对齐。 具体来说，对于甚至`d`，曼哈顿三角形总是可以由沿轴的直角等腰图案形成：从某个点开始`(x, y)`，另外两点是`(x + d/2, y + d/2)`和`(x + d/2, y - d/2)`或类似的对称变化。 

因此，我们可以有效地检查每个点是否存在于集合中完成三角形所需的其他两个点。 使用哈希集进行 O(1) 查找使得整体复杂度与点的数量成线性关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 最佳 | 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，阅读全部`n`点并将它们存储在列表中。 构造一组点元组以进行 O(1) 成员资格检查。 
2. 迭代每个点`(x, y)`作为三角形的潜在顶点。 
3. 对于每个点，根据曼哈顿三角形模式计算其他两个顶点的候选位置：`d/2`沿轴移动。 四种可能的配置是`(x ± d/2, y ± d/2)`y 偏移的符号相反。 
4. 对于每个配置，检查点集中是否存在两个候选点。 
5. 如果找到这样的一对，则返回三个点的索引。 如果检查所有点后没有找到三角形，则输出`0 0 0`。 
6. 对所有测试用例重复此操作。 

为什么它有效：根据几何对称性，任何距离相等的曼哈顿三角形`d`必须符合轴对齐模式之一。 我们的方法枚举每个候选顶点的所有对称可能性并验证存在性。 哈希集成员资格可确保快速查找，使这种方法既正确又高效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    results = []

    for _ in range(t):
        n, d = map(int, input().split())
        points = []
        point_set = set()
        for i in range(n):
            x, y = map(int, input().split())
            points.append((x, y))
            point_set.add((x, y))

        found = False
        half_d = d // 2
        for idx, (x, y) in enumerate(points):
            candidates = [
                ((x + half_d, y + half_d), (x + half_d, y - half_d)),
                ((x - half_d, y + half_d), (x - half_d, y - half_d)),
                ((x + half_d, y + half_d), (x - half_d, y + half_d)),
                ((x + half_d, y - half_d), (x - half_d, y - half_d))
            ]
            for (p1, p2) in candidates:
                if p1 in point_set and p2 in point_set:
                    idx1 = points.index(p1) + 1
                    idx2 = points.index(p2) + 1
                    results.append(f"{idx+1} {idx1} {idx2}")
                    found = True
                    break
            if found:
                break
        if not found:
            results.append("0 0 0")

    sys.stdout.write("\n".join(results))

solve()
```### 解释

 我们将点存储在列表中以检索索引，并将点存储在集合中以进行 O(1) 存在检查。 这`half_d = d // 2`简化可以有效地计算三角形其他两个顶点的相对位置。 我们迭代所有点作为潜在的锚点，并且四种配置上的嵌套循环确保检查所有对称可能性。 这`index`呼叫是安全的，因为所有点都是不同的。

 ## 边缘情况

 如果所有点都线性对齐，则不存在曼哈顿三角形。 例如，点`(0,0),(0,2),(0,4)`和`d=2`产生没有有效的三角形。 算法正确迭代，没有找到候选者，并返回`0 0 0`。 大坐标仅使用整数来处理，并且`d//2`移位是精确的，因为`d`保证是均匀的。
