 ## 解决方案
 ## 问题理解

 我们有两个整数，`x`和`y`。 使用它们，我们定义了两个无限序列：$$a_n=n\oplus x$$和$$b_n=n\oplus y.$$指数从`1`。 每个元素都是通过将索引与固定值进行异或来获得的。 

任务是找到两个序列中出现的连续块的最大长度。 该块可以在两个序列中的不同位置开始，但是一旦选择了开始位置，元素就必须在整个长度上一一匹配。 

就测试数量而言，约束很小，但值`x`和`y`可以大到$10^9$。 序列本身是无限的，因此任何尝试显式生成项的解决方案都是不可能的。 即使检查前几百万个元素也是不够的，因为答案可能大到$2^{25}$，如示例所示。 

问题实际上在于理解 XOR 如何转换连续整数。 一旦我们找到了底层的位模式，就可以在每个测试用例的恒定时间内计算出答案。 

出现微妙的边缘情况时`x`和`y`仅在最低有效位上有所不同。 

例如：```
x = 0
y = 1
```然后：```
d = x xor y = 1
```答案是`1`。 一个常见的错误是认为答案应该是`2`因为 XOR 只改变一位。 连续整数的进位行为会立即中断任何更长的匹配段。 

另一个容易发生的错误发生在`x xor y`是二的幂。 

例如：```
x = 12
y = 4
```然后：```
x xor y = 8
```答案是`8`， 不是`4`。 长度取决于最低不同位的位置，而不取决于不同位的数量。 

## 方法

 一个蛮力的想法是生成两个序列的大前缀并搜索最长的公共子数组。 这是正确的，因为定义实际上要求一个公共的连续段。 

问题是序列是无限的。 即使我们生成了前一百万个元素，也不能保证最佳片段出现在那里。 答案本身可能超过三千万，所以任何直接模拟都是没有希望的。 

关键的观察结果来自于重写相等条件。 

假设一个公共段从以下位置开始`i`和`j`。 然后对于每个偏移量`t`段内，$$(i+t)\oplus x=(j+t)\oplus y.$$应用异或`x`两边都给出$$(i+t) \oplus (j+t)=x\oplus y.$$让$$d=x\oplus y.$$问题变成：

 找出连续值的最长间隔`t`这样$$(i+t)\oplus(j+t)=d.$$现在我们只需要研究当两个数字同时增加时 XOR 的表现如何。 

关键的事实是最大可能长度仅取决于最低设置位`d`。 

如果最低设置位`d`处于位置`k`，那么答案就是$$2^k.$$等价地，$$\text{answer}=d\ \&\ (-d).$$该数量是最低有效设置位的值。

 ## 算法演练

 1. 计算$$d=x\oplus y.$$自从`x ≠ y`，我们知道`d > 0`。 
2. 找到最低有效设置位`d`。 

在二进制算术中这是$$d\ \&\ (-d).$$3. 输出该值。 

整个解决方案由这三个步骤组成。 

### 为什么它有效

 让最低设置位`d`处于位置`k`。 

该位置以下的所有位`k`为零`d`。 这意味着对于任何匹配的数字对`u`和`v`满意的$$u\oplus v=d,$$他们的下级`k`位必须相同。 

当我们同时增加两个数字时，那些较低的数字`k`位的演化完全相同`2^k`进位到达位之前的连续值`k`。 

当进位发生时，位`k`一侧的变化与另一侧不同，因为`d`包含一个`1`在那个位置。 平等$$(u+t)\oplus(v+t)=d$$不能再继续了。 

所以没有段可以长于`2^k`。 

这个界限可以通过选择合适的起始值来实现，其较低值`k`位从零开始。 那么 XOR 仍然等于`d`正是为了`2^k`连续的步骤。 

因此最长可能的公共段的长度$$2^k=d\&(-d).$$## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        x, y = map(int, input().split())
        d = x ^ y
        ans.append(str(d & -d))

    sys.stdout.write("\n".join(ans))

solve()
```实现直接遵循数学结果。 

表达式`x ^ y`计算不同位的掩码。 由于数字不同，因此该值始终为正。 

表达式`d & -d`隔离最低设置位。 在补码算术中，`-d`翻转最低设置位以上的所有位，并在与与进行 AND 运算时准确保留该位`d`。 

不存在溢出问题，因为 Python 整数具有任意精度。 这些值最多约为`2^30`，因此即使是固定宽度的 64 位整数也足够了。

 ## 边缘情况

 考虑：```
x = 7
y = 6
```然后$$x\oplus y = 1.$$最低设置位是`1`，所以答案是`1`。 

一个错误的直觉是，非常相似的数字应该允许很长的公共段。 单个增量后生成的进位立即到达不同的位，因此该段不能超出一个元素。 

现在考虑：```
x = 0
y = 32
```然后$$x\oplus y=32.$$最低设置位是`32`，答案是`32`。 XOR 掩码中的所有低五位都是相同的，从而允许精确地`32`进位到达第一个不同位之前的连续位置。 

最后考虑：```
x = 13
y = 9
```然后$$x\oplus y=4.$$尽管几个较高位可能不同，但从底部开始的第一个不同位置是位`2`，给出答案`4`。 该算法会忽略每个较高位，因为它们不会影响第一个不可避免的进位何时打破相等性。
