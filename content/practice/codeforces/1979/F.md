 ## 解决方案
 ## 问题理解

 我们得到一个未知的图，它最初是一个完整的图$n$顶点，但准确地说$n-2$边缘被移除。 这意味着最终的图非常密集：它恰好具有$\frac{n(n-1)}{2} - (n-2)$边缘，因此仅缺少$n-2$连接总数。 

我们不能直接看到图表。 相反，我们使用“?d”形式的查询与系统交互。 每个查询执行一个非常具体的操作：它标识一个顶点$v$满足度数阈值条件，并在所有此类顶点中选择度数最小的顶点，然后选择索引最小的顶点。 它还返回一个未连接到的顶点$v$，如果存在这样的顶点，则优先选择最小的标签。 报告此信息后，顶点$v$与其所有关联边一起从图中删除。 

目标是在原始图中重建哈密顿路径，最多使用$n$此类查询。 这里的哈密顿路径只是所有顶点的排序，使得每个顶点只出现一次； 它不要求连续顶点之间存在原始图的边。 

约束条件$n \le 10^5$跨所有测试用例意味着我们无法显式地模拟或重建邻接关系。 任何解决方案都必须依赖于在常量或对数查询中提取每个顶点的结构信息，而交互本身就是计算瓶颈。 这是一个交互式重建问题，其中每个查询都会产生一个顶点移除，因此该算法本质上必须在线性时间内“剥离”图。 

一个关键的微妙之处是每个查询都会选择和删除一个顶点。 这使得系统的行为就像一个受控的消除过程，而不是一个纯粹的查询预言机。 我们可以重复探测度数而不影响结构的天真假设会立即破裂，因为每个查询都会改变图。 

典型的失败案例来自于尝试重复查询固定阈值而不跟踪删除。 例如，假设顶点度数保持稳定，即使在很小的情况下也会失败：

 输入想法：```
4
```如果我们假设度数高的顶点在查询后仍保持高度，我们可能会重复选择同一个顶点，但交互器在第一次选择后将其删除。 任何未明确将查询视为破坏性的解决方案都会很快失去同步。 

另一个微妙的边缘情况是当多个顶点共享相同的最小度数并且最小索引平局决定输出时。 例如，在星状残差结构中，天真的贪婪选择可能会选择“错误”的中心，除非仔细利用选择规则。 

## 方法

 蛮力视角将尝试重建整个图或通过跨阈值重复探测每个顶点的度数行为来模拟交互器。 由于每个查询已经删除了一个顶点，因此一个天真的想法可能是尝试每个步骤的所有可能候选者或重复扫描阈值，直到隔离正确的顶点。 这很快就变得不可行，因为每个顶点移除在心理上“模拟”的成本都很高，并且任何重复的探测都需要每个顶点进行多个查询，从而导致$O(n^2)$最坏情况下的相互作用。 

关键的结构见解是该图几乎完整，仅缺少$n-2$边缘。 这意味着补图是一个大小为$n$，正好与$n-2$边，因此它恰好由两个连接的树组成，或者更直接地说，原始图是“减去树的完整图”。 这是关键的减少：缺失的边形成树结构。 

原始图中的哈密顿路径对应于避免丢失树边的遍历。 由于仅$n-2$边缺失，补集结构有足够的约束，我们可以通过识别非邻居来增量重建邻接关系。 

交互式查询旨在为每个删除的顶点揭示一个非邻居。 在整个过程中，每个顶点恰好贡献一个“禁止边提示”（缺失边树结构中的端点除外），使我们能够重建补树，然后导出哈密顿路径。 

该策略变为：迭代删除顶点，同时记录返回的单个非邻居，建立类似父级的关系。 这有效地在补图上重建了一棵树，然后我们将该树的任何 DFS 或 BFS 排序输出为原始图中的有效哈密顿路径。 

这样做的原因是，在补树中，每条边都对应于原始图中的缺失边，因此避免这些边可确保原始图中的邻接性。

 ## 算法演练

 我们使用交互过程隐式地重建补集结构。 

1.我们维护一个剩余顶点的列表，最初是所有$1 \ldots n$。 在每一步中，我们都会发出具有最小可能阈值的查询$d$， 通常$d = 0$，以保证我们始终获得有效的顶点，除非结构已经耗尽。 这确保我们始终取得进步。 
2.每次查询返回一个顶点$v$被移除的顶点$u$未连接到$v$（如果不存在则为 0）。 我们诠释$u$作为唯一的缺失边邻居$v$在补体结构中。 
3.我们存储关系$v \leftrightarrow u$作为补图中的一条边，忽略以下情况$u = 0$。 
4. 我们重复这个过程，直到所有顶点都被移除。 由于每个查询只删除一个顶点，因此我们最多执行$n$查询。 
5. 在所有查询之后，我们有一个代表补图的森林结构。 然后，我们从任意顶点开始运行 DFS，以生成顶点排序。 
6. 该 DFS 阶数作为原始图中的哈密顿路径返回。 

关键的推理步骤是交互者返回的“非邻居”不是任意的。 因为原始图几乎是完整的，所以每个顶点恰好有一个或很少的缺失连接，并且选择规则确保了删除之间的一致性，使我们能够重建树状结构而不是密集的模糊图。 

### 为什么它有效

 补图恰好有$n-2$边缘，这迫使它成为一个仅具有两个组成部分的森林或一个单一的树状结构，具体取决于解释。 每个查询都会为每个删除的顶点暴露一个缺失的邻接，因此在所有查询中，我们只恢复所有补边一次。 由于原始图减去这些边是完整的，因此任何避免补边的遍历都会在原始图中产生有效的哈密顿路径。 

因为我们总是一次删除一个顶点并记录它们独特的禁止连接，所以我们永远不会丢失结构信息。 重建是无损的，并且 DFS 排序尊重所有约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    
    parent = [-1] * (n + 1)
    adj = [[] for _ in range(n + 1)]
    alive = [True] * (n + 1)

    for _ in range(n):
        print("? 0")
        sys.stdout.flush()
        v, u = map(int, input().split())
        if v == 0:
            break
        alive[v] = False
        if u != 0:
            parent[v] = u
            adj[v].append(u)
            adj[u].append(v)

    visited = [False] * (n + 1)
    order = []

    def dfs(x):
        visited[x] = True
        order.append(x)
        for y in adj[x]:
            if not visited[y]:
                dfs(y)

    start = 1
    dfs(start)

    print("! " + " ".join(map(str, order)))
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve()
```该实现通过始终查询最小阈值来对每个顶点执行一次查询。 这保证了进度，因为交互器始终返回有效的可移动顶点，直到耗尽。 

邻接列表是根据返回的非邻居信息构建的，将其解释为补集结构中的边。 然后 DFS 构建最终排序。 

一个微妙的实现细节是必须增加递归深度，因为重构的结构可能会退化为长链。 另一个重要的点是每次查询后刷新，因为解决方案是交互式的。

现在考虑一种稍微倾斜的结构，其中一个顶点直到后期才丢失边。 该算法仍然有效，因为即使是孤立的顶点最终也会通过返回的非邻居来显示和连接，从而确保重建的连通性。

 ## 边缘情况

 一个关键的边缘情况是当补体结构高度倾斜时，例如长链。 在这种情况下，DFS 递归深度变为$O(n)$，并且在不增加递归限制的情况下，即使逻辑正确，解决方案也会失败。 该实现显式设置了较高的递归限制来处理此问题。 

另一个边缘情况是交互器返回时$u = 0$对于靠近末端的多个顶点。 这些顶点对应于补集结构中的叶子，并且未能忽略零边缘将破坏邻接构造。 该算法处理$u = 0$仅作为该顶点的终止信号。 

最后，当图极其密集且缺失边集中时，多个顶点可能具有相似的结构作用。 确定性选择规则确保一致性，但任何在不使用返回的非邻居的情况下“猜测”结构的尝试都会破坏对称性并产生无效的哈密顿阶。
