 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，都有多个学生，对于每个学生，我们都会被告知一天$a_i$。 瓦迪姆那天和那个学生打赌$a_i$，并且下注取决于正确预测从第二天开始的两天模式，即几天$a_i+1$和$a_i+2$。 

每一天都有一个隐藏的结果，可以采取两种形式之一。 瓦迪姆事先并不知道结果的实际顺序，但他希望以这样一种方式进行预测：无论实际结果如何，至少一名学生能够保证接下来两天的预测都是正确的。 

关键的困难在于瓦迪姆必须事先决定所有的预测，而实际的结果是对抗性的。 所以这是一个最坏情况的保证问题：我们正在检查是否存在固定的预测分配，以便每个可能的真实序列仍然留下至少一个“完全正确”的学生。 

输入是测试用例的集合，每个测试用例最多包含$10^5$学生在所有案例中的总体情况。 这立即表明，任何比每个测试用例的线性或近线性更差的解决方案都将无法生存。 排序和频率计数是可以接受的，但任何二次方$n$每个测试用例都不是。 

当学生的投注日过于分散时，就会出现微妙的失败案例。 例如，如果所有$a_i$是不同的，并且在同一两天的窗口中没有两个投注重叠，那么每个学生对应一个独立的约束。 在这种情况下，Vadim 无法在预测之间重用结构，并且问题会简化为用太少的确定性分配覆盖太多的独立可能性。 相反，当许多$a_i$重合或聚集，重叠会产生可利用的冗余。 

一个天真的误解是独立对待每个学生，并假设我们总是可以为每个学生分配模式。 但这失败了，因为所有学生都共享同一天的结果。 

## 方法

 暴力方法会尝试模拟无限二进制序列的所有可能结果，并检查是否存在保证至少一个学生对每个结果感到满意的预测选择。 甚至将注意力限制在相关日期，如果我们有$k$涉及不同的日子，有$2^k$可能的结果分配。 对于每项作业，我们需要检查任何学生的两天窗口是否与他们的预测相符，然后尝试推理所有可能的预测作业。 这在结果和战略空间上很快就会呈指数级增长。 

关键的观察是，白天对学生来说唯一重要的事情$a_i$是一对$(a_i+1, a_i+2)$。 每个学生本质上都在试图“覆盖”一个长度为 2 的窗口。 如果我们反过来思考，瓦迪姆会为每一天选择预测，每个学生都会检查这些选择中的一对。 

所以问题就变成了：我们能否为天分配二进制值，使得至少一个查询的长度为 2 的窗口与预选的模式匹配？ 关键的简化在于，只有平等之间的相对结构$a_i$很重要。 如果很多同学都有相同的情况$a_i$，他们都在询问同一个窗口，我们可以在他们之间分配不同的预测。 

这变成了一种鸽笼式的情况：在固定的一天$a$，只有四种可能的模式$(a+1, a+2)$。 如果我们至少有四个学生有相同的$a$，我们可以分配所有四种模式并保证任何实际结果的成功。 如果少于四个，我们就无法完全涵盖该窗口的所有可能性。 

因此，整个问题简化为检查是否有任何值$a_i$至少出现 4 次。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 按投注日对学生进行分组$a_i$。 这是使用频率图来完成的。 原因是只有相同的$a_i$值共享相同的两天窗口结构，因此分组隔离了独立的约束。 
2. 对于每个不同的日子$a$，数一数有多少学生对此下注。 这个计数代表我们可以分配给同一个窗口的预测槽数量$(a+1, a+2)$。 
3. 检查是否有任何计数至少为 4。如果存在这样的一天，我们立即得出结论，保证成功。 原因是两天内恰好有四种可能的二元结果：00、01、10、11。在同一窗口有四个学生的情况下，我们可以为每个模式分配一个预测，确保覆盖每一种可能的实际结果。 
4. 如果不存在这样的一天，则输出“否”，因为每个窗口的尝试次数少于四次，因此无法涵盖该窗口的所有可能结果。 这意味着至少存在一种结果分配可以同时避免所有预测。 

正确性取决于每个学生独立地要求匹配四种可能性之一，并且只有同一窗口的多重性才能实现完全覆盖。 

### 为什么它有效

 每个学生都对应于在位置上匹配特定位对的要求$a_i+1$和$a_i+2$。 由于这些对在不同的环境中是独立的$a_i$，强制保证成功的唯一方法是完全覆盖单个对的所有四种可能的分配。 如果有的话$a_i$出现四次后，我们可以将所有四种模式分配给这些学生，确保无论该对的实际结果如何，都存在一个匹配。 如果不存在这样的多重性，则对于每个窗口，至少有一种未分配的模式，并且对手可以为该窗口全局选择该模式，从而击败所有赌注。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        ok = False
        for v in freq.values():
            if v >= 4:
                ok = True
                break
        
        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```该解决方案使用哈希图来计算每个投注日的频率。 这是我们唯一需要的状态，因为分组之外的学生身份是无关紧要的。 

对频率 ≥ 4 的检查直接对两天序列的四种可能的二进制模式进行编码。 一旦找到这样的组，循环就会提前终止，从而确保效率。

 ## 边缘情况

 一种极端情况是只有一名学生。 例如，输入`n = 1, a = [100]`。 频率为 1，低于 4，因此输出为“No”。 该算法正确地得出结论：单个预测无法涵盖两天窗口的所有四种可能结果。 

另一个极端情况是同一天恰好有三名学生。 尽管它们严重重叠，但未来两天仍有四种可能的结果，其中一种尚未发现。 该算法正确地输出“否”，反映出至少一个对抗性分配避免了所有预测。 

最后的边缘情况是大的同质输入，例如$10^5$相同的值。 频率检查立即触发成功$O(n)$时间，证明算法可以扩展，而不需要检查超出计数的结构。
