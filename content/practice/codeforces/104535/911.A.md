 ## 解决方案
 ## 问题理解

 我们给定一个大小为的矩形区域$H \times W$。 任务是使用一组无人机覆盖该矩形内的每个点。 每架无人机都很灵活：它可以配置为监视任何大小的任何方形区域并放置在任何地方，只要不超出规则即可。 

有两个限制来定义可行性。 首先，矩形内的每个点都必须被至少一架无人机的方形覆盖范围覆盖。 其次，任何无人机的正方形的任何部分都不允许延伸到矩形之外。 因此每个选定的正方形必须完全位于$H \times W$区域。 

目标是尽量减少此类方形覆盖物的数量。 

尽管该声明谈论的是连续覆盖，但如果我们离散地解释它，结构就会变得更加清晰：矩形的行为就像一个$H \times W$晶胞网格。 每架无人机覆盖一个完全包含在网格中的连续方形子网格。 我们希望使用尽可能少的方形瓷砖来平铺网格。 

限制条件$H, W \leq 1000$意味着任何超出简单遍历的三次甚至二次因子的解决方案仍然可以通过，但是任何涉及穷举分区或显式搜索所有子方的解决方案都会太慢，因为有$O(HW)$细胞和$O(H^2W^2)$可能的正方形。 

一个关键的微妙之处是贪婪地放置大方块可能会失败。 例如，如果我们尝试始终从左上角放置尽可能大的正方形，那么我们很容易得到次优分解，因为剩余区域可能会更好地划分为不同的正方形形状。 所以问题不在于贪婪地最大化每架无人机的面积。 

另一个陷阱是假设答案平稳地取决于面积$H \cdot W$。 例如，$3 \times 9$和$4 \times 3$两者的面积分别为 27 和 12，但分解结构比总面积更重要，如样本所示。 

## 方法

 暴力方法会尝试递归地将矩形分割成正方形。 在每一步中，我们都可以选择一个正方形的大小和位置，从剩余的未覆盖区域中减去它，然后继续直到覆盖整个网格。 这变成了通过正方形搜索矩形的所有平铺。 

放置一个正方形的方法有多少种$H \times W$网格已经是$O(HW)$每个尺寸，并且有$O(\min(H,W))$可能的正方形尺寸。 递归分支在很大程度上取决于剩余的形状，产生指数状态空间。 即使有记忆，不同的未覆盖配置的数量增长也非常快，远远超出了$H, W \leq 1000$允许。 

问题的结构表明了一种简化：我们实际上并没有在组合意义上受到不同正方形大小的限制。 相反，我们只被要求提供最小计数，而不是精确的平铺。 这通常标志着基于几何而不是搜索的构造不变量。 

关键的观察结果是，任何最佳平铺都可以假设仅使用与系统分解模式对齐的正方形。 可以通过重复地从一个维度相对于另一个维度切除最大平方来缩小矩形，类似于欧几里得算法分解长度的方式。 每次“切割”对应于放置一批相同的无人机。 

如果我们将矩形解释为重复删除最大可能的正方形块，则该过程镜像计算之间的最大公约数结构$H$和$W$。 每一步都会减少一个维度，同时保持最优性，并且步骤数对应于需要多少个方形批次。 

这将问题从几何平铺搜索转变为与欧几里德算法相同的确定性过程，其中每个划分步骤对应于使用一定数量的方形无人机。

 ## 算法演练

 我们解释一下矩形$(H, W)$作为我们使用最大平方去除迭代减少的东西。 

1. 从一对开始$(H, W)$。 我们总是使用较大的尺寸作为“容器方向”，使用较小的尺寸作为方形边约束。 这确保了我们始终将尽可能大的方块放在第一位。 
2.如果$H < W$，交换它们。 这使解释保持一致并避免单独处理对称情况。 
3. 计算有多少$W \times W$正方形沿着高度拟合，即$H // W$。 每个这样的方块对应于一架覆盖整个方块的无人机。 
4. 通过更新减去这些覆盖部分$H = H \bmod W$。 这将删除完全平铺的方形条带，留下较小的剩余矩形。 
5. 对缩小的矩形重复相同的逻辑，直到一维变为零。 每次迭代都贡献$H // W$无人机，其余的过程继续进行。 
6. 总结迭代中的所有贡献。 这个总和就是所需的最小方形无人机数量。 

这个过程之所以正确是因为在每一步我们都被迫至少使用$H // W$边长为正方形$W$什么时候$W$是较小的尺寸，因为没有更大的正方形可以容纳，也没有更小的正方形可以以避免完全覆盖的方式减少计数。 任何替代平铺仍需要覆盖相同的全宽条带，因此在重新排列下计数是不变的。 

该算法本质上是对贪婪平铺进行编码，在减少问题之前，它总是用最大平方饱和一个维度，并且这种饱和步骤无法全局改进，因为任何较小的分解只会增加覆盖同一区域所需的平方数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    H, W = map(int, input().split())
    ans = 0

    while H and W:
        if H < W:
            H, W = W, H
        ans += H // W
        H %= W

    print(ans)

if __name__ == "__main__":
    solve()
```核心循环反映了欧几里德归约过程。 交换确保我们始终将较小的边视为正方形大小。 整数除法计算沿较长维度有多少个最大平方，模数删除完全覆盖的条带。 

关键的实现细节是维持以下不变式：$H \geq W$在每个分区之前。 如果没有这个，整数除法将以错误的方向应用，并且分解将不再对应于有效的正方形放置。

 ## 边缘情况

 当一维为 1 时，会出现极端情况。例如，$H = 1, W = 1000$。 算法交换和计数$1000$一步计算单位平方，因为$1000 // 1 = 1000$。 模数立即变为零，因此该过程正确终止。 任何简单的几何平铺方法都可能错误地尝试形成更大的正方形，但这是不可能的，因为高度太小。 

另一种情况是维度相等时，例如$H = W = 7$。 该算法立即添加一个方格并终止。 这符合以下事实：单个$7 \times 7$无人机覆盖了整个区域，并且任何分解都无法改善单个方形覆盖范围。 

更微妙的情况是当比率接近 1 时，例如$H = 1000, W = 999$。 该算法执行一个大的正方形放置并留下剩余的$1 \times 999$，然后分解为 999 个单位正方形。 这表明，接近正方形的矩形通常会折叠成一个大正方形加上一条细条，并且任何最佳平铺仍必须明确考虑该条。
