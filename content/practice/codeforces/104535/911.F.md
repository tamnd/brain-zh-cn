 ## 解决方案
 ## 问题理解

 我们得到了三个短字符串，它们是单个隐藏单词的片段。 这些片段的顺序不正确，但如果我们正确地重新排列它们并将它们连接起来，它们就会形成一个已知的目标词“Izhevsk”。 我们的任务不是重建或修改字符串本身，而只是确定三个给定片段的正确顺序，以便它们的串联成为目标。 

输入大小非常小，因为只有三个字符串，每个字符串的长度最多为 5。 这立即排除了对效率限制的任何担忧。 即使多次尝试所有可能的排列或重新计算串联的解决方案也很容易足够快，因为排列总数固定为六。 

一个微妙的问题是输入字符串是任意片段。 它们在本地看起来可能不相关，并且没有单个字符串可以保证作为目标单词的开头或结尾。 唯一可靠的结构是三个字符串的一次排列恰好产生完整的单词。 

一个天真的错误是假设按字典顺序排序或贪婪地匹配前缀会起作用。 例如，如果输入是“he Iz vsk”，贪婪方法可能会尝试首先选择以“I”开头的字符串，然后根据部分匹配附加其他字符串，但在多个有效延续在本地显示正确的情况下，这可能会失败。 由于数据很小，因此对所有排序进行暴力破解是安全且确定的方法。 

## 方法

 思考这个问题的最简单方法是，我们正在搜索三个元素的排列，使得它们的串联等于已知的目标字符串。 对于三个字符串，只有六种可能的顺序。 对于每个订单，我们连接字符串并将结果与​​目标单词进行比较。 

这是有效的，因为正确性仅取决于全局结构，而不取决于局部对齐。 每一个不正确的排序都无法通过相等性检查，而正确的排序则完全匹配。 

暴力解决方案枚举所有排列，为每个排列构建一个串联字符串，并检查相等性。 成本是恒定的，因为排列的数量固定为 6，并且每个串联最多涉及 15 个字符。 

不需要更先进的技术，例如通过修剪或散列进行回溯，因为输入大小是固定的且很小。 该问题本质上是恒定域上的排列匹配任务。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(6·L) | O(1) | O(1) | 已接受 |
 | 最佳| O(6·L) | O(1) | O(1) | 已接受 |

 这里 L 是所有字符串组合的总长度，以 15 为界。 

## 算法演练

 1. 读取三个输入字符串并将它们存储在列表中。 这使它们可以轻松排列，而不会丢失其原始顺序。 
2. 将目标字符串定义为“Izhevsk”。 每个候选排序都将与这个确切的字符串进行比较。 
3. 生成三个字符串的所有可能排列。 因为 3 的阶乘等于 6，所以这样的排列正好有 6 个。 
4. 对于每个排列，按该顺序连接三个字符串。 这产生了预期海报的候选重建。 
5. 将连接结果与目标字符串进行比较。 如果它们完全匹配，则此顺序是正确的。 
6. 按找到的顺序输出三个字符串并立即终止。 

### 为什么它有效

 正确性取决于这样一个事实：恰好有一个排列形成了目标字符串。 由于我们详尽地测试了所有排列，并且每次检查都是精确的字符串相等，因此我们不能错过正确的排序。 不存在歧义，因为该问题保证存在有效的安排。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve():
    a, b, c = input().split()
    arr = [a, b, c]
    target = "Izhevsk"
    
    for p in permutations(arr):
        if "".join(p) == target:
            print(*p)
            return

solve()
```该解决方案读取三个片段并将它们存储在一个列表中，以便排列生成非常简单。 排列函数生成所有六种可能的排序。 对于每个排序，我们连接字符串并直接与“Izhevsk”进行比较。 一旦找到匹配项，我们就会打印该顺序并停止。 

一个微妙的实现细节是打印后立即返回的使用。 如果没有它，如果未来的逻辑添加不正确，程序可能会继续运行并可能打印多行。 在这里，它还确保我们在找到有效排列后不会浪费周期，即使成本可以忽略不计。

 ## 边缘情况

 一种边缘情况是输入的顺序已经正确。 例如，输入：```
I zh evsk
```该算法检查第一个排列并立即匹配“Izhevsk”，因此它会按原样打印输入。 这证实了没有不必要的重新排列逻辑会干扰正确答案。 

另一种情况是最后一次检查排列是否正确。 例如：```
he Iz vsk
```前两个排列失败，因为它们的串联与目标不匹配。 仅当排列`(Iz, he, vsk)`达到条件是否成功。 该算法仍然正确终止，因为它详尽地探索了所有可能性。 

最后，即使片段在内部具有误导性，例如具有类似于单词其他部分的前缀或后缀，相等性检查也可以防止部分匹配错误。 该算法不依赖启发式方法，因此在所有有效输入下它都保持正确。
