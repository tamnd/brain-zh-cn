 ## 解决方案
 ## 问题理解

 我们得到一个数字，表示为一串具有长度的数字$n$。 这些数字均非零，因此该数字只是一个干净的序列，如 43153 或 654321。唯一允许的操作是选择一个连续的数字段并按非降序对该段进行排序，同时保持其他所有内容不变。 我们最多允许执行一次此操作，目标是使结果为偶数，这意味着它的最后一位数字必须是偶数。 

输出要么是一个声明，表明没有任何单个段排序操作可以使数字为偶数，要么是段边界的有效选择$L, R$，后跟对该段进行排序后得到的转换后的数字。 

关键约束是$n \le 1000$，如果需要仔细重复模拟，则排除二次或近线性策略之外的任何内容。 然而，由于我们只进行了一次操作，因此我们实际上是在选择一个间隔并评估其效果。 

微妙的一点是，该操作不是任意数字重新排列。 它只对连续的块进行排序，因此它保留所选段之外的相对顺序。 这使得结构非常受限：数字的后缀尤其重要，因为只有最后一位数字决定奇偶校验。 

一种边缘情况是数字已经是偶数。 在这种情况下，选择任何段是可选的，但我们仍然必须产生一个有效的操作来保持它均匀。 另一个边缘情况是，没有段可以以保留有效排序行为而不破坏早期约束的方式将偶数位移动到最后一个位置。 

一个天真的错误是假设我们应该始终通过选择以该数字结尾的段来将最小的偶数数字带到末尾。 这可能会失败，因为对段进行排序也会扰乱内部结构，可能会将奇数数字推到末尾。 

另一个失败的情况是假设我们可以独立选择最后一位数字。 由于排序会影响整个段，因此最后一个位置取决于所选区间内的所有数字，而不仅仅是原始端点。 

## 方法

 蛮力方法尝试每一个可能的部分$[L, R]$，应用排序，并检查结果数字是否以偶数结尾。 各段评估费用$O(n)$构造修改后的字符串，有$O(n^2)$段，所以总复杂度是$O(n^3)$。 和$n = 1000$，这变得太慢了。 

我们可以通过观察真正决定成功的因素来改进。 对段进行排序后，奇偶校验只有两件事重要：哪个数字成为整个数字的最后位置，以及它是否是偶数。 仅当以下情况时，最后一个位置才会受到影响$R = n$，因为只有接触末尾的段才能改变最后的数字。 这立即极大地减少了搜索空间。 

现在问题变成：选择一个结尾为$n$，即选择$L$，这样排序后$s[L:n]$，最后一位数字是偶数。 排序意味着该段的最后一位数字成为该段中的最大数字。 因此，最后一位数字成为最大数字$s[L:n]$。 那么条件就变成：选择$L$这样后缀中的最大数字$[L, n]$是均匀的。 

如果没有后缀具有偶数最大数字，则这是不可能的。 否则，我们选择向右延伸保持最大值均匀的最早位置并选择$L$。 任何这样的有效段都有效。

 | 最佳|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 从左到右扫描，同时保持从右侧考虑时每个后缀起始点迄今为止看到的最大数字。 我们正在有效地准备评估一切可能的情况$L$高效。 
2. 对于每个索引$L$，计算其中的最大数字$s[L:n]$。 这可以通过从右侧扫描一次并存储后缀最大值来完成。 此步骤确保我们不会重复重新计算段属性。 
3. 检查该后缀最大值是否为偶数。 如果是，则选择$[L, n]$排序后会将最大值放在最后，因为排序会将最大的元素推到最后一个位置。 
4.一旦我们找到第一个这样的$L$，我们停下来。 选择最早有效的$L$是安全的，因为任何有效的后缀都已经保证了正确的最终数字，并且进一步向左扩展只会引入较小的数字，如果最大值已经固定，则不会改变最大值。 
5、输出$L = L$,$R = n$，并通过对子字符串进行排序来构造结果字符串$s[L:n]$以及连接前缀和后缀。 
6.如果没有这样的$L$如果存在，则打印 NO，因为没有任何在最后位置结束的操作可以使最后一位数字为偶数。 

### 为什么它有效

 对段进行排序后，该段的最后一位数字始终是其中的最大数字。 因为只有在位置结束的段$n$可以影响整个数字的最后一位，问题减少到选择最大数字为偶数的后缀。 每个有效的解决方案都与选择这样的后缀完全对应，因此算法不会错过任何有效的配置，也不会产生无效的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = list(input().strip())

    suf_max = [0] * (n + 1)

    for i in range(n - 1, -1, -1):
        suf_max[i] = max(suf_max[i + 1], int(s[i]))

    best_l = -1
    for i in range(n):
        if suf_max[i] % 2 == 0:
            best_l = i
            break

    if best_l == -1:
        print("NO")
        return

    seg = sorted(s[best_l:])
    res = s[:best_l] + seg

    print("YES")
    print(best_l + 1, n)
    print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案首先构建后缀最大值，以便可以在恒定时间内评估每个后缀的最大数字。 下一个循环找到最大数字为偶数的最早后缀，这保证了排序时会将偶数数字放在整个数字的末尾。 最后的构造步骤对该后缀执行一次排序操作，并将其与未更改的前缀连接回去。 

一个常见的实现陷阱是忘记只有以$n$事情。 另一个是重新计算循环内每个后缀的最大值，这会不必要地降低性能。

 ## 边缘情况

 一种边缘情况是数字包含偶数位，但没有一个可以成为任何后缀的最大值。 例如，在像 13579 这样的序列中，偶数位根本不存在，因此每个后缀最大值都是奇数。 该算法扫描后缀最大值并正确地发现没有有效的起始索引，从而产生 NO。 

另一种情况是唯一的偶数不是后缀最大值的一部分。 例如，2193 有一个偶数位 2，但包含它的任何后缀随后也会包含一个更大的奇数位，因此后缀最大值始终为奇数。 该算法正确地拒绝了它，因为对以 4 结尾的任何后缀进行排序仍将以奇数数字结尾，因此不存在有效的操作。
