 ## 解决方案
 ## 问题理解

 给定一个数组，我们希望将其重新排列为非递减顺序，但交换受到限制。 仅当两个值中至少有一个是“幸运数字”时，才允许两个位置之间的交换，这意味着其十进制表示形式仅由数字 4 和 7 组成。我们的任务不仅仅是确定可行性，而是实际生成有效的交换序列，上限为最多 2n 次操作，或者报告在这些规则下无法实现排序。 

关键对象不是位置本身，而是“幸运”元素如何充当连接器。 只有在至少触及一个幸运值时才可能进行交换，因此除非幸运元素参与调解交换，否则非幸运元素无法自由交互。 

n 最大为 100000 的约束立即排除了对数组进行交换或贪婪冒泡的任何 O(n²) 模拟。 我们需要一些线性或近线性的东西，可能是 O(n log n) 或 O(n)。 最多 2n 次交换的输出约束强烈建议采用一种建设性方法，该方法可以在每个索引的少量移动中修复元素，而不是重复的局部调整。 

当根本没有幸运数字时，就会出现一个微妙的问题。 在这种情况下，除非数组已经排序，否则任何交换都是有效的。 另一个边缘情况是当幸运数字存在但被困在无法帮助移动元素跨越断开区域的位置时，例如当所有放错位置的元素都是非幸运元素并且没有幸运枢轴来促进移动时。 

一个最小的失败例子是：

 输入：

 n = 3

 arr = [3, 2, 1]

 如果这些都不幸运，则不允许交换，因此即使数组在通常意义上是可排序的，输出也必须为“-1”。 

另一个案例：

 n = 3

 arr = [4, 2, 1]

 这里4是幸运的。 如果没有4作为枢纽，我们无法直接交换2和1，但可以使用4与它们进行交换。 除非明确使用幸运元素作为中介，否则仅尝试相邻交换的幼稚策略会失败。 

## 方法

 蛮力的想法是直接模拟排序。 人们可以重复扫描数组，找到相邻的反转，并尝试交换它们。 然而，即使我们将其推广到邻接之外，每次交换都需要检查有效性并可能尝试许多中间步骤。 在最坏的情况下，解决单个反转可能需要 O(n) 次交换，并且存在 O(n²) 次反转，这会导致在所有可能的交换的简单模拟中出现 O(n³) 行为。 这已经远远超出了极限。 

关键的观察结果是，幸运数字就像通用中介一样。 如果我们选择任何幸运位置，我们可以将其用作临时存储来模拟非幸运元素之间的任意交换。 这个想法类似于图重新配置中的缓冲区节点如何允许我们模拟否则不可能的交换。 

一旦我们至少有一个幸运索引，每个元素都可以与其交换，并且从那里我们可以间接地重新排列值。 问题归结为构建一个模仿标准排序过程的序列，但通过固定的幸运枢轴路由所有交换。 

这将问题转化为受控排列结构：我们保留一个幸运的位置作为中心，并用它将元素一个接一个地放置到正确的位置。 每个放置最多需要恒定数量的交换，这解释了 2n 界限。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力交换模拟| 最坏情况 O(n3) | O(n) | 太慢了 |
 | 使用幸运指数的枢纽建设 | O(n log n) 由于排序 + O(n) 交换 | O(n) | 已接受 |

 ## 算法演练

1. 识别所有包含幸运数字的索引。 如果不存在，则只有在数组已经排序的情况下才可能进行排序，因为否则任何交换都是合法的。 这充当了硬可行性检查。 
2、选择一个幸运指数作为固定“支点”。 它将用作所有交换操作的临时存储。 修复单个枢轴可以避免处理多个助手的复杂性。 
3. 对数组值的副本进行排序，以了解每个值的目标最终位置。 这给出了从值到正确位置的映射。 
4. 从左到右迭代数组位置。 在位置 i，如果当前值已经正确，则不执行任何操作。 否则，确定应进入位置 i 的值。 
5. 查找该目标值在数组中的当前位置 j。 要将其移动到位置 i，请使用枢轴：

 首先将 j 处的元素与枢轴交换，然后将枢轴与位置 i 交换。 这有效地将正确的元素放置在 i 处，同时保持交换合法性。 
6. 由于值会发生变化，因此每次交换后都会更新位置跟踪。 即使枢轴的值发生变化，它始终仍然是有效的中介。 
7. 继续，直到数组完全排序。 每个放错位置的元素的交换次数最多为两次，保持在 2n 范围内。 

### 为什么它有效

 正确性来自于将幸运元素视为永久的门户。 两个任意位置之间的任何交换都可以分解为涉及主元的交换序列，因为主元始终可以合法地与当前不幸运或本身不幸运的任何元素进行交换。 这为我们提供了足够的灵活性来模拟任意换位。 由于我们总是在每一步放置一个正确的元素，并且从不撤消之前的放置，因此该过程会保持正确固定位置的前缀不断增长。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_lucky(x):
    while x > 0:
        d = x % 10
        if d != 4 and d != 7:
            return False
        x //= 10
    return True

n = int(input())
a = list(map(int, input().split()))

pos = {}
for i, v in enumerate(a):
    pos[v] = i

sorted_a = sorted(a)

lucky_indices = [i for i, v in enumerate(a) if is_lucky(v)]

if not lucky_indices:
    if a == sorted_a:
        print(0)
    else:
        print(-1)
    sys.exit()

pivot = lucky_indices[0]

ops = []

def do_swap(i, j):
    a[i], a[j] = a[j], a[i]
    pos[a[i]] = i
    pos[a[j]] = j
    ops.append((i + 1, j + 1))

for i in range(n):
    correct = sorted_a[i]
    if a[i] == correct:
        continue

    j = pos[correct]

    if i == pivot:
        do_swap(pivot, j)
        pivot = j
    elif j == pivot:
        do_swap(pivot, i)
        pivot = i
    else:
        do_swap(pivot, j)
        do_swap(pivot, i)

print(len(ops))
for x, y in ops:
    print(x, y)
```该代码维护一个位置图，以便定位任何值的当前位置的时间复杂度为 O(1)。 枢轴用作动态缓冲区，每次交换都更新数组并保持地图一致。 小心的部分是在移动时更新枢轴索引，否则后续交换将引用过时的位置。

 ### 示例 1

 输入：```

```排序后的目标是[1,2,4]。 枢轴是索引 0（值 4）。

 | --- | --- | --- | --- |
 | 开始| [4,2,1]| 0 | 初始|
 | 我=0 | [4,2,1]| 0 | 正确 |

 两次交换后，2 被正确放置，并且枢轴帮助将 1 放置到位。 跟踪显示，尽管 1 和 2 不能直接交换，但通过 4 的路由使其成为可能。

 ## 边缘情况

 当没有幸运数字时，算法会立即拒绝，除非数组已经排序。 这是必要的，因为如果没有有效的主元，则根本无法执行交换。 例如，`[3,1,2]`没有幸运值产生`-1`直接，符合没有任何操作是合法的事实。 

当主元元素本身在排序过程中移动时，算法会在每次交换后更新其索引。 如果省略此更新，后续的交换将引用错误的位置并默默地破坏结构。 这在枢轴参与固定早期位置并导致其多次穿过阵列的情况下尤其明显。
