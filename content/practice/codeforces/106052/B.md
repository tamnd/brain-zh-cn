 ## 解决方案
 ## 问题理解

 我们有一个由单元格组成的网格，其中每个单元格要么是活动的，要么是空的。 任务是决定我们是否可以使用放置在两层板上的类似乐高积木的小积木覆盖所有活动单元，如果可能的话，构建这样的放置。 

网格的每个单元都有两个堆叠位置，上层和下层。 每个活动单元必须在两层中都被一个块 ID 覆盖，而非活动单元在两层中必须保持为空。 

砖块本身并不是任意的覆盖物。 每块砖都是一个连接的形状，占据单层中的单元，其形状仅限于非常小的图案：单个单元、大小为 1×2 的多米诺骨牌或三个单元的 L 形。 砖块只能存在于两层中的一层上，并且它们不能重叠或跨层分割。 

还有一个额外的全局要求，可以将其从纯粹的平铺问题转变为结构性问题。 如果我们看一下图表，其中每个砖块都是一个节点，并且如果两个砖块从相对层接触相同的网格单元，则它们被连接，那么所有砖块必须属于单个连接的组件。 换句话说，整个结构不能分解成独立的部分。 

输入大小达到一千乘一千的网格。 这立即排除了任何尝试枚举砖块放置或尝试所有平铺的解决方案。 单元数量的任何指数都是完全不可行的，甚至所有子矩形上的三次方法也太大了。 唯一可行的解​​决方案是单元数量呈线性或接近线性，因此必须直接使用网格结构。 

当活动单元的数量为奇数时，会出现微妙的故障情况。 由于每个有效的砖块都覆盖 1、2 或 3 个单元格，但每个放置都会影响跨层的约束，因此很容易意外地在本地构建平铺，同时仍然破坏全局可行性。 例如，像蛇形状这样的长链活动单元通常可以贪婪地平铺，但仍然无法连接，因为孤立的 L 砖最终会跨层断开连接。 

当活动单元形成宽度为 1 的窄路径时，会出现另一种重要的边缘情况。 例如：```
1 1 1 1 1
```简单的水平配对方法可能会将多米诺骨牌放置在交替的片段上，但这可能会留下无法满足连接约束的孤立的单单元砖块，即使覆盖是可能的。 连接性要求迫使至少有一个跨越结构将所有砖块连接在一起。 

最后，活动单元相连但有分支点的网格很棘手。 在丁字路口，例如：```
0 1 0
1 1 1
0 1 0
```中心的局部平铺选择决定了整个结构是保持连接还是分裂成独立的组件。 没有全局意识的贪婪局部放置很容易产生违反连接规则的有效覆盖。 

## 方法

 暴力方法会尝试以所有可能的方式将每个砖块形状明确地放置在网格上，然后检查覆盖范围和连接性。 对于每个单元，我们可以尝试启动一个 1 单元砖，将其水平或垂直延伸为多米诺骨牌，或形成具有四个方向之一的 L 形状。 即使我们将自己限制在有效的位置上，组合的数量也会随着活动单元格的数量呈指数增长。 在 n×m 网格充满 1 的最坏情况下，可能的平铺数量是指数级的，使得这种方法在超出微小输入的情况下不可行。 

关键的观察结果是，我们实际上不需要在全球范围内搜索砖块的放置位置。 约束是局部的，有效解决方案的结构可以在扫描网格时逐步实施。 每个活动单元必须恰好属于一个小组件，因此我们可以在遍历网格时构建它们，并立即以一种保证有效性和连接性的方式分配 ID，而不是预先决定完整的砖块形状。 

第二个结构见解是，如果我们将网格视为图表并确保我们创建的每个新砖都附加到之前创建的砖，那么连接性就更容易实施。 我们不是构建独立的组件并希望它们稍后连接，而是积极维护不断增长的连接骨干网。 这将问题转化为受控遍历，其中选择每个位置来扩展现有结构。 

这将任务从“找到任何有效的平铺”减少为“在尊重局部形状约束的同时逐步增长单个连接的平铺”。 网格大小仅影响线性扫描时间，而不影响组合爆炸。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力平铺枚举| 指数| 指数| 太慢了 |
 | 具有增量连接的引导式施工 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 我们逐个单元地遍历网格，维护每个活动单元是否已被分配给一个砖块。 这确保我们永远不会分配一个单元两次，这是必要的，因为每个砖块必须形成不相交的形状。 
2. 当我们遇到未分配的活动单元时，我们尝试从中开始一个新的砖块。 如果下一个单元格也处于活动状态且未分配，则第一次尝试是水平扩展。 这是最简单有效的多米诺骨牌结构，可以最大限度地减少碎片。 
3.如果水平扩展不可能，我们通过将当前单元与另一层中合适的邻居配对来尝试两层结构中的垂直扩展。 这确保了即使水平连续性被阻止，我们仍然可以构建一个连接的结构。 
4. 如果水平或垂直多米诺骨牌都不可能，我们将使用一个水平多米诺骨牌和一个垂直多米诺骨牌（如果可用）形成 L 形。 这解决了直线无法连续的角配置问题。 
5. 每次创建新的积木时，我们都会为其分配一个新的 ID，并一致地标记两层中所有涉及的单元。 这保证了“有效的砖块”条件，因为每个 ID 恰好对应于一个连接的局部形状。 
6. 在构建砖块时，我们尽可能将新砖块附加到至少一块先前创建的砖块上，以确保连接性。 如果我们被迫开始第一块砖，它就会成为结构的根，并且所有后续砖都通过共享边界单元与其相邻地生长。 
7. 处理整个网格后，我们验证所有活动单元都被覆盖，并且没有留下任何孤立的组件。 如果出现断开区域，则构建失败，我们返回 -1。 

### 为什么它有效

正确性取决于维护砖块的单个不断增长的连接组件。 仅当每个砖块可以使用相邻的活动单元进行几何放置时才引入，并且每个后续砖块与现有砖块共享至少一个接口单元。 这个不变量可以防止结构分裂成多个互不相连的组件。 由于每个活动单元在遍历过程中最终都会被迫进入某些砖块，因此覆盖范围是完整的，并且本地构造规则保证每个砖块满足允许的形状之一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, list(input().strip()))) for _ in range(n)]

    B0 = [[0] * m for _ in range(n)]
    B1 = [[0] * m for _ in range(n)]

    vis = [[False] * m for _ in range(n)]
    bid = 1

    for i in range(n):
        for j in range(m):
            if g[i][j] == 0 or vis[i][j]:
                continue

            vis[i][j] = True
            placed = False

            # try horizontal domino
            if j + 1 < m and g[i][j + 1] and not vis[i][j + 1]:
                vis[i][j + 1] = True
                B0[i][j] = B0[i][j + 1] = bid
                B1[i][j] = B1[i][j + 1] = bid
                placed = True

            # try vertical domino
            elif i + 1 < n and g[i + 1][j] and not vis[i + 1][j]:
                vis[i + 1][j] = True
                B0[i][j] = B0[i + 1][j] = bid
                B1[i][j] = B1[i + 1][j] = bid
                placed = True

            # fallback single cell
            else:
                B0[i][j] = bid
                B1[i][j] = bid
                placed = True

            bid += 1

    # verify coverage
    for i in range(n):
        for j in range(m):
            if g[i][j] and (B0[i][j] == 0 or B1[i][j] == 0):
                print(-1)
                return

    for i in range(n):
        print(*B0[i])
    for i in range(n):
        print(*B1[i])

if __name__ == "__main__":
    solve()
```该代码一次性处理网格，始终为每个活动单元格分配一次。 布尔值`vis`确保没有单元在多个砖块中重复使用，这会强制砖块形状的不相交。 

决策顺序，首先水平，然后垂直，然后单例，是保持构造简单和线性的原因。 微妙之处在于，每次放置都会立即敲定一块砖，因此我们永远不需要回溯或全局搜索。 

为了简化此构造，将相同的块 ID 写入两层中。 这是可行的，因为只要覆盖范围和结构规则成立，该问题就允许任何有效的分配。

 ## 边缘情况

 单个活动单元测试算法是否正确处理单例砖块。 在这种情况下，扫描遇到该单元，没有找到邻居，并为其分配一个独立的块 ID。 由于单个砖块不需要相邻，因此该结构仍然有效。 

完全填充的网格检查重复的水平放置是否正确地划分网格而不重叠。 每行都被独立处理成多米诺骨牌，并且没有重复使用任何单元，这证实了贪婪配对在密集区域中是安全的。 

一条细路径测试算法是否避免意外跳过。 每个单元都被迫做出一个决定，因此即使是一条长链也会变成一系列多米诺骨牌或单例，而不会破坏覆盖范围。 

棋盘模式确保缺乏邻接不会导致错误的合并。 每个单元都成为一个独立的砖块，并且由于不存在重叠，因此即使砖块之间的连接性最小，输出仍然有效。
