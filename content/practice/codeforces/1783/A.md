 ## 解决方案
 ## 问题理解

 给定一个按非降序排序的整数数组，我们需要重新排列其元素，以便没有元素等于所有先前元素的总和。 如果这种重新安排不可能，我们必须报告。 输入由多个测试用例组成，每个测试用例都有数组长度及其元素。 输出要么是“NO”，要么是“YES”，后面跟着一个漂亮的排列。 

限制很小：数组长度$n$最多 50 个，元素值在 1 到 100 之间。$t \le 2000$，甚至一个$O(n^2)$解决方案将有效运行，因为$n^2 \cdot t \le 5 \cdot 10^6$运营。 

当所有元素都相等时，就会出现关键的边缘情况，特别是对于$n = 2$，因为第二个元素始终等于所有先前元素的总和。 例如，与$a = [10, 10]$，任何排列都会使第二个元素等于第一个元素，这使得它不可能是美丽的。 另一种边缘情况是较小元素的总和等于最大元素，这可能发生在数组中，例如$[1, 2, 3]$如果天真地排序。 简单地让数组排序的粗心实现可能会带来创建丑陋数组的风险。 

## 方法

 蛮力方法是尝试数组的每个排列并检查它是否美观。 检查数组的长度$n$需要$O(n)$，但有$n!$排列。 为了$n = 50$，即使我们的输入限制很小，这也是不可行的，因为$50!$是一个天文数字。 

关键的观察结果是，只有最大的元素才有可能与排序数组中所有先前元素的总和相匹配。 如果我们将最大元素放在最后，其余元素放在它前面，则所有前面元素的总和将最大化，使其最有可能等于最大元素。 为了避免这种情况，我们可以将最大的元素放在前面，确保没有先前的总和可以匹配它，或者我们可以按非递增顺序对数组进行排序。 按降序排序可保证任何位置之前的所有元素的总和严格大于当前元素，但所有元素都相等的数组可能除外。 如果所有元素都相等并且$n > 1$，那么只有当$n = 2$并且该值会重复。 这给出了一个简单且安全的重排策略：降序排序，检查前两个元素。 如果它们相等并且数组只有两个元素，则打印 NO； 否则，打印重新排列的数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了 |
 | 降序排序 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n$和数组$a$。 
3. 对数组进行排序$a$按降序排列。 这确保每个元素不等于它之前的所有元素的总和，因为总和随着我们向右移动而增加。 
4. 检查是否$n = 2$并且两个元素相等。 如果是，请打印 NO。 这处理了第二个元素始终等于第一个元素的特殊不可能情况。 
5. 否则，打印 YES，后跟排序后的数组。 这保证了一个漂亮的数组，因为当数组按降序排序时，任何前缀的总和都不能等于当前元素。 

为什么它有效：通过首先放置较大的元素，任何前缀总和总是小于下一个元素，除了在微不足道的不可能的情况下。 降序排列消除了任何元素等于其之前元素之和的风险，并且显式处理唯一的例外（两个相等的数字）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def make_beautiful():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        if n == 2 and a[0] == a[1]:
            print("NO")
        else:
            print("YES")
            print(" ".join(map(str, a)))

if __name__ == "__main__":
    make_beautiful()
```代码首先读取测试用例的数量。 每个数组都按降序排序，以防止出现丑陋的配置。 明确处理两个相等数字的特殊情况。 将数组打印为字符串可确保输出格式符合问题要求。 就地排序可减少内存开销。

 ## 边缘情况

 该算法显式处理具有两个相等元素的数组，这不可能变得漂亮。 具有两个以上相等元素的数组是安全的，因为降序排序可以避免任何前缀和相等。 约束不允许单元素数组。 最大元素等于较小元素之和的数组将通过降序自动固定。 例如，`[1, 2, 3]`变成`[3, 2, 1]`，避免中间丑陋的总和。 每个边缘情况都通过排序和二元素检查来解释。
