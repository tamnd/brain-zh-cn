 ## 解决方案
 ## 问题理解

 有两支足球队，分别有 (a_1) 和 (a_2) 名球员。 第一队的一名球员在收到 (k_1) 张黄牌后被除名，而第二队的一名球员在收到 (k_2) 张黄牌后被除名。 我们只知道出示的黄牌总数 (n)，而不知道哪些球员收到了黄牌。 

任务是找到两个极端。 第一个数字是在分配 (n) 张牌的所有有效方式中被移除的玩家的最小可能数量。 第二个数字是被移除的玩家的最大可能数量。 该问题也称为 Codeforces 1215A，具有相同的陈述和约束。 

玩家数量和卡牌阈值最多为（1000），因此卡牌总数最多为

 [
 1000\cdot1000+1000\cdot1000=2\cdot10^6。 
]

 这使得在低级语言中对 (n) 个可能的牌计数进行线性扫描是可行的，但这是不必要的。 两个团队的结构使我们能够将两个答案都减少为恒定数量的算术运算。 更重要的是，枚举实际的卡片分配是完全不可能的，因为每张最多 (2\cdot10^6) 张卡片最多可以有 (2000) 个可能的收件人。 

第一个棘手的边界是每个玩家都可以在不离开的情况下收到 (k_i-1) 张牌。 例如，```
1
1
2
3
3
```第一个玩家可以安全地收到一张牌，第二个玩家可以安全地收到两张牌，因此所有三张牌都可以分配，而无需任何人离开。 答案是`0 1`。 使用 (a_1k_1+a_2k_2) 作为安全容量的粗心最小计算也会在这里碰巧返回零，但一旦 (n) 超过错误定义的安全容量，它就会失败。 相关的安全限值始终比移除阈值小一。 

当阈值为 (1) 时，会出现另一种边缘情况。 例如，```
1
1
1
5
1
```第一队球员被唯一一张黄牌除名，所以答案是`1 1`。 正确使用(k_1-1=0)意味着第一个玩家根本没有安全牌。 

第三个重要的情况是两个阈值不同。 考虑```
2
3
5
1
8
```每个第二队球员都被一张牌消除，因此最多可以通过向三名第二队球员每人发一张牌，向一名第一队球员每人发五张牌来获得最大数量。 这给出了四次删除，与样本输出相匹配`0 4`。 如果我们贪婪地先使用阈值较大的队伍，我们就会浪费牌并错过最大值。 

最后，牌的总数可以等于所有玩家的总容量。 为了```
3
1
6
7
25
```总共有 (3\cdot6+1\cdot7=25) 张可能的牌。 每个玩家都必须收到其阈值数量的牌，因此所有四名玩家都离开，答案是`4 4`。 

## 方法

 一个完全暴力的解决方案可以考虑每张黄牌的每一个可能的接收者。 对于 (a_1+a_2) 名玩家和 (n) 张牌，这会产生 ((a_1+a_2)^n) 种可能的分配。 最大限制为 (2000^{2,000,000})，这是遥不可及的。 这种方法是正确的，因为考虑了每种可能的分布，但其搜索空间随着卡片的数量呈指数增长。 

稍微更实用的暴力方法是枚举有多少 (n) 张牌属于第一队。 对于选定的值 (x)，移除玩家的最大数量为

 [
 \min(a_1,\lfloor x/k_1\rfloor)
 +
 \min(a_2,\lfloor(n-x)/k_2\rfloor)。 
]

 尝试每个 (x) 需要 (O(n)) 时间，在这些约束下最多仍需要约 200 万次迭代并且可以工作。 然而，该问题具有更强的贪婪结构，因此没有理由执行此枚举。 

至少，想象一下首先尽可能安全地分发卡片。 每个第一队球员都可以收到 (k_1-1) 张牌而不被移除，每个第二队球员都可以收到 (k_2-1) 张牌。 因此，无需移除即可吸收的卡牌数量为

 [
 S=a_1(k_1-1)+a_2(k_2-1)。 
]

 如果 (n\le S)，则没有人必须离开。 如果 (n>S)，每张额外的牌都会迫使另外一名玩家达到其移除阈值。 因此最小值是

 [
 \max(0,n-S)。 
]

 最大值的关键观察是不同的。 被移除的玩家恰好消耗 (k_i) 张牌。 为了消除尽可能多的玩家，我们应该首先将牌花在需要较少牌的玩家身上。 如果 (k_1<k_2)，移除一线队球员比移除第二队球员花费更少的牌，因此在使用牌移除第二队球员之前，应先采取所有可负担的一线队移除。 如果 (k_2<k_1)，则角色互换。 当阈值相等时，任一顺序都是等效的。 

假设较小的阈值是(k_s)，有(a_s)个对应的玩家，另一个阈值是(k_l)，有(a_l)个玩家。 我们可以删除

 [
 x=\min(a_s,\lfloor n/k_s\rfloor)
 ]

 来自廉价球队的球员。 剩下的牌有(n-xk_s)张，所以我们可以去掉

 [
 \min(a_l,\lfloor(n-xk_s)/k_l\rfloor)
 ]

 来自另一支球队的球员。 

这种贪婪的选择是最优的，因为用昂贵的移除替换廉价的移除永远不会增加从固定数量的牌中获得的移除数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 详尽的作业| (O((a_1+a_2)^n)) | (O(n)) 递归深度 | 太慢了|
 | 枚举团队分裂 | (O(n)) | (O(n)) | (O(1)) | (O(1)) | 已接受但没有必要 |
 | 贪心算术 | (O(1)) | (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 计算在不移除任何人的情况下可以给每个玩家的牌张数：

 [
 安全=a_1(k_1-1)+a_2(k_2-1)。 
]

 最小移除次数为`max(0, n - safe)`。 每张牌超出`safe`必须完成先前安全玩家的阈值，并且一个完成的阈值将恰好删除一名玩家。 
2. 比较(k_1)和(k_2)，将阈值较小的队伍作为第一队伍进行最大计算。 

从该团队中移除消耗的卡牌较少，因此首先使用它可以提供最佳的移除次数。 
3. 从阈值较小的球队中移除尽可能多的球员：

 [
 x=\min(a_s,n//k_s).
 ]

这`min`是必要的，因为该团队中只有 (a_s) 名球员。 
4. 减去那些被移除的玩家使用的(xk_s)张牌。 

剩余的牌可用于移除另一队的玩家。 任何低于其阈值的剩余金额都可以简单地分配给玩家，而无需删除该玩家。 
5. 尽可能多地从对方队伍中移除球员：

 [
 y=\min(a_l,(n-xk_s)//k_l)。 
]

 最大答案是(x+y)。 

### 为什么它有效

 每个玩家至少可以在游戏中吸收 (k_i-1) 张牌。 这给出了总安全容量（安全）。 一旦使用了这些牌，每张额外的牌都必须是某个玩家的第 (k_i) 张牌，从而导致删除。 由于输入保证(n)不超过总容量(a_1k_1+a_2k_2)，因此总是有足够的玩家来吸收所有多余的牌。 

对于最大值，请考虑任何一组被移除的玩家。 每次第一队移除需要花费 (k_1) 张牌，每个第二队移除需要花费 (k_2) 张牌。 如果 (k_1<k_2)，用一张第一队移除替换一张第二队移除永远不需要更多牌，并且只能留下至少同样多的牌可用于进一步移除。 因此，最佳布置总是可以转化为在较大阈值移除之前使用尽可能多的较小阈值移除的布置。 同样的论点也适用于当 (k_2<k_1) 时球队逆转的情况。 当所有选择的移除都被支付后，未使用的卡可以放置在未达到其阈值的玩家中，因此贪婪计数是可以实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a1 = int(input())
    a2 = int(input())
    k1 = int(input())
    k2 = int(input())
    n = int(input())

    safe = a1 * (k1 - 1) + a2 * (k2 - 1)
    minimum = max(0, n - safe)

    if k1 <= k2:
        small_count, small_k = a1, k1
        large_count, large_k = a2, k2
    else:
        small_count, small_k = a2, k2
        large_count, large_k = a1, k1

    removed_small = min(small_count, n // small_k)
    remaining = n - removed_small * small_k

    removed_large = min(large_count, remaining // large_k)
    maximum = removed_small + removed_large

    print(minimum, maximum)

if __name__ == "__main__":
    solve()
```前五个输入调用读取两个球队的规模、各自的移除阈值以及黄牌总数。 此问题中没有多个测试用例，因此只需调用一次`solve()`就足够了。 

这`safe`表达用途`k_i - 1`， 不是`k_i`。 恰好到达 (k_i) 张牌会移除玩家，因此当我们要求不移除任何人时，只有 (k_i-1) 张牌可用。 

为了最大程度地实现，代码会交换团队的概念角色，而不是实际修改输入值。 对比之后，`small_k`保证不大于`large_k`。 除以这些阈值的整数得出可以产生消除的完整卡片组的数量。 

这`min`与球队规模相比，可以防止计算出比球员人数更多的移除数。 支付这些移除费用后，剩余的牌除以较大的阈值，即可得出有多少额外的玩家可以离开。 

Python 整数具有任意精度，因此不存在溢出问题。 即使是固定宽度的 32 位整数也足够了，因为每个团队的最大乘积仅为 (10^6)，但使用 Python 整数可以完全消除这个问题。

 ## 边缘情况

 对于精确的安全容量边界，```
1
1
2
3
3
```第一个玩家可以安全地收到一张牌，第二个玩家可以安全地收到两张牌。 因此`safe = 1 + 2 = 3`，至少给出`max(0, 3 - 3) = 0`。 对于最大值，第二个玩家可以收到所有三张牌并离开，所以答案是`0 1`。 该算法不会错误地将第三张牌视为从第一个玩家手中强制移除。 

对于阈值 1，```
1
1
1
5
1
```第一个玩家有安全能力（1-1=0）。 单张卡立即达到其阈值，因此最少为一张。 同一张卡也足以达到最大值，给予`1 1`。 安全容量计算中减一可以准确处理该边界。 

对于较小阈值属于第二队的情况，```
2
3
5
2
9
```安全容量为(2(5-1)+3(2-1)=11)，因此可以在不移除的情况下分发九张牌，并且最小值为零。 为了最大化移除，该算法首先处理阈值二队。 它可以使用六张牌移除所有三名玩家，留下三张牌。 这三张牌无法移除门槛为 5 的玩家，因此最大值实际上是三张，而不是四张。 

这个例子揭示了为什么上面的测试必须使用精确的算术。 相应的断言特意更正如下：```
assert solve_io("""2

5
2
9
""") == "0 3\n", "greedy must use team 2 first"

2000000

 [
 2,000,000-2,000(999)=2,000,
 ]

 而最大计算会删除所有（2000）名玩家。 因此输出是`2000 2000`。

3
