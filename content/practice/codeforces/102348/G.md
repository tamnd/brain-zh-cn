 ## 解决方案
 ## 问题理解

 我们有两个字符串`s`和`t`长度相同，并且每个字符都是`a`或者`b`。 在一次操作中，我们可以选择任意位置`s`以及任何位置`t`，然后交换两个字符。 目标是使用尽可能少的跨字符串交换来使两个字符串相同。 

输出必须包含最小交换数量以及实现该交换的一系列索引对。 如果没有序列可以使字符串相等，我们打印`-1`。 

第一个有用的观察是关于字符计数。 交换永远不会改变总数量`a`两个字符串中的字符。 如果最终的字符串相等，则每个位置为两个字符串贡献相同的字符，因此总数`a`字符必须是偶数。 等价地，位置的数量`s[i] != t[i]`必须是均匀的。 如果是奇数，则任何交换序列都不起作用。 

和`n`一样大`2 * 10^5`，具有二次或指数行为的算法不适合。 两秒的限制意味着我们应该以线性或接近线性的工作为目标，大致与输入大小成正比。 存储不匹配的位置也很便宜，因为最多可以有`n`其中。 

有两种不匹配类型。 在一个位置`s[i] = a`和`t[i] = b`，称其为`ab`不匹配。 在一个位置`s[i] = b`和`t[i] = a`，称其为`ba`不匹配。 这些类型在配对时表现不同，忽视这种区别是错误解决方案的主要原因。 

考虑`n = 1`,`s = "a"`,`t = "b"`。 有 1 个不匹配，因此不匹配的总数为奇数。 粗心的解决方案可能会尝试交换索引处的两个字符`1`，但是该操作交换`a`和`b`在字符串之间，简单地将字符串保留为`"b"`和`"a"`。 正确答案是`-1`。 

另一个重要的情况是每种类型都有一个不匹配。 例如，与`s = "ab"`和`t = "ba"`，不匹配项是`ab`在位置`1`和`ba`在位置`2`。 它们不能通过这两个不同位置之间的一次交换来修复。 需要进行两个操作：交换`s[1]`和`t[1]`，然后交换`s[1]`和`t[2]`。 答案是`2`。 始终配对的解决方案`ab`与一个`ba`并假设一项操作就足够了，在这里将会失败。 

最后，当同一类型有两个不匹配时，一次操作就足够了。 为了`s = "aabb"`和`t = "bbaa"`, 职位`1`和`2`都是`ab`不匹配。 交换`s[1]`和`t[2]`同时固定两个位置。 独立处理每个不匹配位置的解决方案将使用太多操作。 

## 方法

 直接的暴力方法可以模拟所有可能的排列`2n`两个字符串中的字符作为一种状态。 从一个州有`n^2`可能的跨字符串交换，因此广度优先搜索可以探索操作数量不断增加的状态，并在两个字符串相等时停止。 这是正确的，因为 BFS 在未加权状态图中找到最短路径。 

问题在于该图的大小。 总数`a`字符被保留，所以如果有`k`其中，可以有`C(2n, k)`不同的状态。 这是最大化的`k = n`，大致给出`C(2n, n)`，其增长为`4^n / sqrt(n)`。 探索直至`n^2`每个状态的转换给出了最坏情况的规模`Theta(n^2 C(2n, n))`，即使是几十个位置也是完全不可行的。 

一种更有针对性的贪婪方法可以检查不匹配并尝试一一修复它们。 关键的见解是不匹配可以配对。 如果两个位置具有相同的不匹配类型，则一次跨字符串交换即可修复这两个位置。 例如，两个`ab`位置可以通过交换来配对`a`从第一个位置开始`b`从第二个开始。 同样的论点适用于两个人`ba`职位。 

重复配对相同类型后，最多只能有一个`ab`不匹配且至多有一个`ba`留下不匹配。 如果两者都不存在，我们就结束了。 如果恰好剩下一个，则不匹配的总数是奇数，因此该实例是不可能的。 如果两者都保留，则需要进行两次手术。 第一个操作将字符串中剩余位置之一的两个字符与自身交换，从而更改那里的不匹配类型。 剩下的两个不匹配就会变成相同的类型，并且可以通过第二次交换来解决。 

因此，整个问题简化为收集不匹配位置、配对相同类型以及分别处理可能的两个剩余部分。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`Theta(n^2 C(2n,n))`在最坏的情况下| 指数| 太慢了 |
 | 最佳 |`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 从左到右扫描所有位置。 如果`s[i] == t[i]`，该位置已经同意，无需操作。 否则，将其从 1 开始的索引附加到任一`ab`或者`ba`，取决于这对是否是`(a, b)`或者`(b, a)`。 

将两种不匹配类型分开可以让我们识别何时一个操作可以解决两个位置。 
2.如果总数不匹配，`len(ab) + len(ba)`, 为奇数，打印`-1`。 

每次操作都会保留总数量`a`字符，而相同的最终字符串包含偶数个`a`总共字符数。 因此奇偶条件是必要的。 对于二进制字符串来说也足够了。 
3. 连续配对`ab`不匹配。 对于每对`ab[i]`和`ab[i + 1]`，添加操作`(ab[i], ab[i + 1])`。 

在第一位置，`s`包含`a`和`t`包含`b`。 在第二个位置上，`s`包含`a`和`t`包含`b`。 交换`s[ab[i]]`和`t[ab[i + 1]]`将两个位置更改为`(b, b)`或者，根据该对的方向，同时修复两个不匹配。 同样的道理也适用于两个`ba`不匹配。 
4. 连续配对`ba`以完全相同的方式不匹配。 对于每对`ba[i]`和`ba[i + 1]`， 添加`(ba[i], ba[i + 1])`。 

每个这样的操作都会删除两个不匹配，因此在这一步之后，每种类型最多只能有一个不匹配。 
5. 如果两者都`ab`和`ba`有一个未配对的位置，例如`x`和`y`， 履行`(x, x)`第一的。 

在位置`x`，字符是`a`在`s`和`b`在`t`。 交换这两个字符会改变不匹配的情况`ab`到`ba`。 现在剩下的两个位置都具有相同的不匹配类型。 
6. 执行`(x, y)`作为第二次操作。 

剩余的两个相等类型不匹配现在由之前使用的相同配对参数修复。 
7. 输出前面步骤中收集的操作。 

每个操作都会删除两个不匹配项，除了剩余情况中的第一个操作会更改它们的排列，以便第二个操作可以删除最后两个不匹配项。 由于每个操作都用于最大可能的减少，因此得到的计数是最小的。 

### 为什么它有效

 不变的是收集到的不匹配位置准确地描述了两个字符串仍然不一致的位置。 同一类型的两个不匹配始终可以通过一次操作来删除，因此将它们配对是最佳选择，因为单个操作无法修复两个以上的不匹配位置。 

删除所有此类对后，每种类型至多保留一个不匹配。 如果只剩下一个，则不匹配计数为奇数并且不可能相等。 如果剩下两个，它们必然具有相反的类型。 一次自索引交换将一种类型更改为另一种类型，最终的交叉索引交换修复了这两种类型。 因此，每个可能的可解配置都被处理，并且每个操作都以实现最小可能数量的方式使用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()

    ab = []
    ba = []

    for i in range(n):
        if s[i] == t[i]:
            continue
        if s[i] == 'a':
            ab.append(i + 1)
        else:
            ba.append(i + 1)

    if (len(ab) + len(ba)) % 2:
        print(-1)
        return

    ans = []

    for i in range(0, len(ab) - 1, 2):
        ans.append((ab[i], ab[i + 1]))

    for i in range(0, len(ba) - 1, 2):
        ans.append((ba[i], ba[i + 1]))

    if len(ab) % 2 == 1:
        x = ab[-1]
        y = ba[-1]

        ans.append((x, x))
        ans.append((x, y))

    print(len(ans))
    for x, y in ans:
        print(x, y)

if __name__ == "__main__":
    solve()
```第一次扫描将每个不一致分类到两个不匹配数组中的一个中。 这`i + 1`转换是经过深思熟虑的，因为该算法内部使用 Python 的从零开始的索引，而问题需要从`1`。 

配对循环前进两个。 例如，如果`ab = [2, 5, 7, 9]`，操作是`(2, 5)`和`(7, 9)`。 循环绑定`len(ab) - 1`当数组长度为奇数时，防止访问不存在的第二个元素。 

剩下的案例是微妙的部分。 什么时候`ab`有一个未配对的位置，`ba`也必须有一个，因为总的不匹配计数是偶数。 操作`(x, x)`是合法的，因为两个选定的位置可能具有相同的数字索引，前提是其中一个属于`s`另一个到`t`。 它翻转了不匹配`x`，之后`(x, y)`固定两个位置。 

不需要对弦进行模拟。 我们只需要对原始字符串进行不匹配分类，因为构造的运算已经通过代数进行了推理。 Python 整数也没有溢出问题，最多`n`操作产生。 

## 工作示例

 ### 示例 1

 输入是：```
4
abab
aabb
```失配分类如下。 

| 位置 |`s[i]`|`t[i]`| 不匹配类型 | 存储位置|
 | ---| ---| ---| ---| ---|
 | 1 | 一个 | 一个 | 等于| 无 |
 | 2 | 乙| 一个 | 巴| 2 |
 | 3 | 一个 | 乙| ab | 3 |
 | 4 | 乙| 乙| 等于| 无 |

 有一个`ab`不匹配和一`ba`不匹配，因此两者都不能与相同类型的另一个不匹配配对。 

| 步骤|`ab`|`ba`| 运营| 原因 |
 | ---| ---| ---| ---| ---|
 | 初始|`[3]`|`[2]`| 无 | 两个相反类型的剩菜|
 | 1 |`[3]`|`[2]`|`(3, 3)`| 转换`ab`3 进不匹配`ba`|
 | 2 |`[3]`|`[2]`|`(3, 2)`| 配对并删除两者`ba`不匹配 |

 后`(3, 3)`，字符串变成`abbb`和`aaab`。 最后的交换`(3, 2)`使两个字符串等于`abab`。 该算法输出两个操作，这是最优的，因为一个操作不能直接解决两个相反类型的不匹配。 

### 示例 2

 输入是：```
1
a
b
```只有一个位置，而且是一个`ab`不匹配。 

| 位置 |`s[i]`|`t[i]`|`ab`|`ba`| 总不匹配|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 一个 | 乙|`[1]`|`[]`| 1 |

 不匹配的总数是奇数，因此算法立即返回`-1`。 

这说明了为什么在尝试配对剩余数据之前必须进行奇偶校验。 没有第二个不匹配可以吸收不匹配的字符，因此没有交换序列可以产生相同的字符串。

 ## 边缘情况

 第一个边缘情况是奇数个不匹配。 为了```
1
a
b
```不匹配的数组是`ab = [1]`和`ba = []`。 他们的总大小是`1`，所以算法打印`-1`在构建任何操作之前。 这避免了尝试通过交换位置来修复唯一不匹配的错误想法`1`与它自己。 这种交换只是交换`a`和`b`并使两个字符串不同。 

第二个边缘情况是同一类型的两个不匹配。 考虑```
2
aa
bb
```两个职位都是`ab`不匹配，所以`ab = [1, 2]`。 配对循环生成`(1, 2)`。 操作交换`s[1] = a`和`t[2] = b`，生产`s = "ba"`和`t = "ba"`。 一次操作就足够了，而且显然是最小的，因为字符串最初不相等。 

第三种边缘情况是每种类型都有一个不匹配：```
2
ab
ba
```这里`ab = [1]`和`ba = [2]`。 有两个不匹配，因此该实例是可能的，但两种类型都没有配对。 该算法首先执行`(1, 1)`，将字符串更改为`ab`和`ba`到`bb`和`aa`。 现在位置上剩余的概念不匹配`1`已更改类型，允许`(1, 2)`交换`s[1] = b`和`t[2] = a`。 字符串变成`ab`和`ab`。 需要两次操作，因为当其余两个类型不同时，第一个操作只能更改一个不匹配。 

最终的边界情况是最大尺寸输入，其中字符串已经相等。 和`n = 200000`两个字符串都完全由`a`，扫描没有遇到不匹配，两个数组都保持为空，答案是`0`。 这证实了该算法不会意外地创建匹配位置的操作，并且即使在允许的最大输入大小下，其内存使用量也保持线性。
