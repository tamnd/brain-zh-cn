 ## 解决方案
 ## 问题理解

 我们有两个二进制字符串`s`和`t`相同长度的。 在一次操作中，我们可以选择任意位置`s`以及任何位置`t`，然后交换这两个字符。 这两个位置不必相等，因此一个操作可以同时修复两个不同的不匹配。 

目标是使用尽可能少的跨字符串交换来使整个字符串相同。 我们必须要么打印最少的交换次数以及一个最佳序列，要么打印`-1`当没有序列可以工作时。 

查看位置的有用方法是比较它的两个字符。 只有四种可能。 职位包含`aa`或者`bb`已经是正确的了。 一个位置包含`ab`方法`s[i] = a`和`t[i] = b`， 尽管`ba`意思是相反的。 合适位置之间的交换可以同时消除两个不匹配。 

长度可以达到`2 * 10^5`，因此扫描所有位置对的算法已经太慢了。 二次算法可以大致执行`4 * 10^10`pair 在最坏的情况下进行检查，远远超出了 2 秒的限制所允许的范围。 我们需要一个解决方案，其工作量随字符串长度线性增长，除了我们实际打印的操作数量之外。 

还有一个全球可行性条件。 每个操作只是在两个字符串之间交换字符，因此总数`a`两个字符串中的字符永远不会改变。 为了使最终的字符串相等，每个字符在两个字符串中出现的次数必须为偶数。 因此，如果总数量`a`字符是奇数，答案是不可能的。 相同的条件可以使用不匹配更直接地表达：`ab`位置加上数量`ba`位置必须均匀。 

第一个边缘情况是单个不匹配。 用于输入```
1
a
b
```唯一的位置是`ab`，所以不匹配的总数是奇数。 正确的输出是`-1`。 简单地记录不匹配并对任何可用的内容进行配对的粗心实现可能会留下一个不匹配的位置并错误地打印序列。 

当存在一种情况时，会出现第二种边缘情况`ab`不匹配和一`ba`不匹配。 例如，```
2
ab
ba
```需要进行两次操作。 第一次交换可以改变`ab`位置进入`ba`，但这并没有解决问题。 需要进行第二次交换才能解析结果对。 将每一对不匹配视为可在一次操作中解决会错误地声称一次操作就足够了。 

第三种边缘情况是所有位置都可以匹配。 例如，```
3
aba
aba
```需要零操作。 假设存在至少一个不匹配的实现可能会意外访问空的不匹配列表或打印不必要的操作。 

## 方法

 一种直接的方法是检查不匹配的位置并重复搜索两个可以交换字符的位置以取得进展。 由于存在两种不匹配，因此可以尝试每一对可能的索引并测试交换相应的字符是否会减少不匹配的数量。 这是正确的，因为详尽的搜索考虑了每一个合法的交换，但它太昂贵了。 和`n`职位，有`n²`可能的跨字符串交换，并且重复搜索它们可能需要以下顺序`n²`检查。 在`n = 2 * 10^5`，这大约是`4 * 10^10`候选人互换。 

关键的观察是实际字符仅通过不匹配类型起作用。 假设职位`i`和`j`都是类型`ab`。 在这两个位置我们都有`s = a`和`t = b`。 交换`s[i]`和`t[j]`交流`a`和`b`，所以两个位置都变成`bb`和`aa`。 因此两个`ab`不匹配可以通过一项操作来修复。 同样的论点适用于两个人`ba`不匹配。 

这立即建议分别存储两种不匹配类型的索引。 同一类型中的每一对都只需要一次操作，并且没有理由寻找更好的排列，因为一次操作是修复两个不匹配的理论上的最小值。 

唯一有趣的情况是两个不匹配列表的大小均为奇数。 在将尽可能多的位置配对后，`ab`和一个`ba`保持。 它们无法在一次操作中修复，因为它们的字符方向相反。 然而，两次操作就足够了。 如果`i`是剩余的`ab`位置和`j`是剩余的`ba`位置，第一次交换`s[i]`和`t[i]`。 位置`i`变化自`ab`到`ba`。 现在职位`i`和`j`都是`ba`，所以交换`s[i]`和`t[j]`修复两者。 

最小值来自相同的结构。 每个操作最多可以修复两个不匹配位置，因此在一个操作中配对两个相等的不匹配类型是最佳的。 当每种类型都存在一个不匹配时，一次操作无法修复两者，而上面的结构恰好将它们修复为两个。 因此，最终的操作次数是最少的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n²)`或更糟的是重复搜索|`O(n)`| 太慢了 |
 | 最佳|`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 扫描每个位置`i`从`0`到`n - 1`。 如果`s[i] = t[i]`，那里不需要做任何事情。 如果`s[i] = a`和`t[i] = b`， 店铺`i`在`ab`列表。 如果`s[i] = b`和`t[i] = a`， 店铺`i`在`ba`列表。 这两个列表恰好包含了仍然需要注意的位置。 
2. 检查两个不匹配列表的奇偶性。 如果`len(ab) + len(ba)`为奇数，打印`-1`。 不匹配的数量不能以允许每个位置变得相等的方式改变奇偶校验，因为两个字符串中每个字符的总数被保留。 
3. 将连续位置配对`ab`。 对于每对`ab[i]`和`ab[i + 1]`，添加操作`(ab[i], ab[i + 1])`。 两个位置的形式均为`ab`，所以交换`a`从第一个位置开始`s`与`b`从第二个位置开始`t`将两个位置更改为相等的对。 
4. 将连续位置配对`ba`以同样的方式。 对于每对`ba[i]`和`ba[i + 1]`， 添加`(ba[i], ba[i + 1])`。 由于两个位置的形式都是`ba`，同样的推理可以通过一次操作解决这两个问题。 
5. 如果两个列表的长度均为奇数，则一个位置`i`仍留在`ab`和一个位置`j`仍留在`ba`。 添加操作`(i, i)`。 自位置`i`是`ab`，交换它自己的两个字符将其变为`ba`。 
6.添加第二个操作`(i, j)`。 位置`i`现在是`ba`，和位置`j`已经是`ba`，所以交换`s[i]`和`t[j]`将两个位置更改为相等的对。 
7. 打印时将每个存储的从零开始的索引转换为从一开始的索引。 输出操作对后的操作数。 

### 为什么它有效

 不变的是每个位置不存储在`ab`或者`ba`已经相等，而每个存储的位置都由恰好一种不匹配类型表示。 相同类型的对总是可以在一次操作中移除，因此所有此类对都可以独立消除。 如果仍然存在两个奇数大小的不匹配列表，则第一个操作会更改剩余的一个`ab`进入`ba`，之后两个剩余物具有相同的类型，第二个操作将删除它们。 如果总的不匹配计数是奇数，则每个字符的保守总数使得目标状态无法到达。 每个操作最多修复两个不匹配，只要两个不匹配可以修复在一起，算法就使用一个操作，对于不可避免的相反类型的剩余部分，恰好使用两个操作。 因此，生成的序列既有效又最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()

    ab = []
    ba = []

    for i in range(n):
        if s[i] == t[i]:
            continue
        if s[i] == 'a':
            ab.append(i)
        else:
            ba.append(i)

    if (len(ab) + len(ba)) % 2:
        print(-1)
        return

    ans = []

    for i in range(0, len(ab) - 1, 2):
        ans.append((ab[i], ab[i + 1]))

    for i in range(0, len(ba) - 1, 2):
        ans.append((ba[i], ba[i + 1]))

    if len(ab) % 2 == 1:
        i = ab[-1]
        j = ba[-1]
        ans.append((i, i))
        ans.append((i, j))

    out = [str(len(ans))]
    for x, y in ans:
        out.append(f"{x + 1} {y + 1}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一个循环对每个位置精确分类一次。 相同的位置将被忽略，而两个可能的不匹配方向将被单独存储。 因为字母表只包含`a`和`b`，没有第三种不匹配类型需要处理。 

两个配对循环前进二。 这就是为什么上限是`len(ab) - 1`而不是`len(ab)`：最后的未配对元素必须保持不变，直到处理特殊的两次操作情况。 这同样适用于`ba`。 

仅检查特殊情况`len(ab) % 2`。 一旦已知不匹配的总数是偶数，`ab`和`ba`必然具有相同的奇偶性。 因此如果`ab`是奇数，`ba`也是奇数，并且配对后两者都只有一个剩余元素。 

操作索引在内部存储为从零开始的值，因为 Python 字符串使用从零开始的索引。 输出需要从一开始的位置，所以`x + 1`和`y + 1`被打印。 不需要模拟交换。 对的分类证明了该操作的作用，并且避免模拟使实现变得简单。 

Python 中不存在整数溢出问题。 最大操作次数最多为`n + 1`，足够小，可以直接存储和打印。 输出本身可以包含`O(n)`行，因此将其构建为字符串列表并写入一次比执行许多单独的操作更有效`print`来电。

    t = data[2]

    possible = (sum(c == 'a' for c in s) +

## 边缘情况

 在任何配对之前处理奇数不匹配情况。 为了```
1
a
b
```这`ab`列表的大小为一，并且`ba`列表的大小为零。 它们的总数是奇数，因此算法立即打印`-1`。 不会访问无效的伙伴。 

相反类型的情况是微妙的。 为了```
2
ab
ba
```我们得到`ab = [0]`和`ba = [1]`。 两个列表都很奇怪。 该算法首先添加`(0, 0)`，将第一个位置更改为`ab`到`ba`。 然后它添加`(0, 1)`。 在那一刻，两个位置都有类型`ba`，所以交换`s[0] = b`和`t[1] = a`使位置 1 等于`aa`位置 2 等于`bb`。 使用两次操作，一次操作是不够的。 

对于已经相等的输入，例如```
3
aba
aba
```两个不匹配列表都保持为空。 总不匹配计数为零，配对循环不执行任何操作，特殊情况也不执行任何操作，并且程序打印`0`。 这是正确的最小值，因为不需要交换。 

对于同一类型的两个不匹配，考虑```
2
aa
bb
```两个职位都是`ab`， 所以`ab = [0, 1]`。 第一个配对循环添加`(0, 1)`。 交换`s[0] = a`和`t[1] = b`产生`bb`在第一位置并且`aa`在第二个中，因此字符串在一次操作后变得相等。 该算法达到了一次操作的下限。 

最后，最大尺寸的情况```
200000
aaaaaaaaaa...aaaaaaaaaa
bbbbbbbbbb...bbbbbbbbbb
```有`200000` `ab`不匹配。 它们可以分为`100000`成对，每对需要一次交换。 该算法执行一次线性扫描并准确生成`100000`运营。 它从不粗略地检查`4 * 10^10`可能的跨字符串索引对，这是它保持足够快的关键原因。
