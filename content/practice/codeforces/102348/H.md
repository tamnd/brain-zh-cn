 ## 解决方案
 ## 问题理解

 我们有`n`灯笼放置在严格递增的整数坐标处`x[0], x[1], ..., x[n-1]`。 我们可以选择它们的任何子集保持打开状态。 如果至少选择三个灯笼，它们的坐标必须形成算术级数，这意味着每个连续选择的灯笼具有相同的距离。 选择零个、一个或两个灯笼，没有限制。 

任务是找到尽可能多的灯笼，其坐标形成这样的算术级数。 

灯笼数量最多为`3000`。 二次算法的性能约为`9,000,000`状态转换，这对于编译实现来说是合理的，并且也可以在具有紧凑存储和恒定时间坐标查找的Python中变得实用。 三次算法的执行顺序为`27,000,000,000`最坏情况下的基本转换，远远超出了两秒的限制。 坐标可以大到`10^18`，因此解决方案不能依赖于小坐标数组，而是 Python 整数直接处理算术。 

在许多情况下，粗心的实施可能会失败。 例如，对于三个灯笼，输入```
3
1 2 4
```有答案`2`， 因为`1, 2, 4`不是算术级数，并且仍然允许有任何两个灯笼。 假设三个灯笼必须始终形成一个级数的解决方案将错误地打印`3`。 

进程不必使用输入中的连续灯笼。 为了```
5
1 2 4 6 7
```答案是`3`，使用坐标`1, 4, 7`。 仅检查相邻输入坐标的方法会看到间隙`1, 2, 2, 1`并可能错误地得出没有有用进展的结论。 

所需的前驱也可以位于坐标范围之外。 为了```
3
0 10 20
```答案是`3`，同时对于```
3
0 10 21
```答案是`2`。 当检查一对是否可以扩展时，计算出的前任`2*x[i] - x[j]`可能为负数或可能超过`10^18`。 这些值根本不存在于坐标图中，因此查找必须处理不存在的情况，而不是假设坐标有效。 

上坐标边界也是无害的。 为了```
3
0 500000000000000000 1000000000000000000
```答案是`3`。 该算术使用周围的值`10^18`，但不需要坐标索引存储。 

## 方法

 直接的方法是选择所需进程的前两个灯笼。 一旦他们的坐标是`a`和`b`，公差固定为`d = b - a`，所以后面的每个坐标都是强制的：`b + d`， 然后`b + 2d`， 等等。 如果我们在整个数组中搜索每个强制的下一个坐标，我们可以尝试所有`O(n^2)`开始配对并花费`O(n)`努力扩展每一项。 这给出了`O(n^3)`时间，大致`3000^3 = 27 billion`在最坏的情况下进行检查。 

如果我们制定一个动态程序，但通过扫描所有较早的灯笼来搜索前驱程序，也会出现同样的立方瓶颈。 对于每对`(i, j)`，我们需要找到一个索引`k`满意的`x[k] = 2*x[i] - x[j]`。 

方程的结构给出了优化的关键。 前驱坐标由两个当前坐标唯一确定。 由于所有坐标都是不同的，我们可以构建一个从坐标到其索引的字典并找到`k`在预期的`O(1)`时间。 

定义`dp[i][j]`为了`i < j`作为最长算术级数的长度，其最后两个灯笼是`i`和`j`。 如果进程有先前的灯笼`k`， 然后`x[i] - x[k] = x[j] - x[i]`。 

重新排列给出`x[k] = 2*x[i] - x[j]`。 

因为`x[k] < x[i]`，任何这样的`k`自动早于`i`。 因此，当计算`dp[i][j]`，所需状态`dp[k][i]`已经计算出来了。 

如果前驱不存在，则该对`(i, j)`本身就是长度的算术级数`2`，所以它的状态是`2`。 如果前任存在，我们将扩展最佳级数，结束于`(k, i)`由一盏灯笼。 

这就把问题变成了`O(n^2)`动态规划。 唯一实际的 Python 特有问题是内存。 普通整数的完整 Python 矩阵不必要地大，因此实现将 DP 值存储在紧凑的无符号短数组中。 因为答案永远不可能超过`3000`，每个状态都适合 16 位。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n^3)`|`O(n)`| 太慢了 |
 | 最佳DP |`O(n^2)`|`O(n^2)`| 已接受 |

 ## 算法演练

 1.读取坐标并创建字典`pos`将每个坐标映射到其索引。 坐标是唯一的，因此每次查找都只有一个可能的索引。 
2. 分配`dp[i][j]`对于每对`i < j`。 最初，每对代表长度的算术级数`2`，所以它的值为`2`。 
3、处理可能的中间索引`i`从左到右。 对于每一个`j > i`，计算之前必须的坐标`x[i]`如果`(x[i], x[j])`是算术级数的最后两项。 那个坐标是`target = 2*x[i] - x[j]`。 
4. 向上看`target`在`pos`。 如果不存在，则无法扩展该对`(i, j)`， 所以`dp[i][j]`遗迹`2`。 
5. 如果`target`存在于索引处`k`， 然后`k < i`因为`x[j] > x[i]`意味着`2*x[i] - x[j] < x[i]`。 进展结束于`k, i`已经有了正确的公差，所以设置`dp[i][j] = dp[k][i] + 1`。 
6. 保持所看到的最大 DP 值。 该值是可以打开的灯笼的最大数量。 

### 为什么它有效

 不变的是之后`dp[i][j]`计算出来，正是最长的以灯笼结尾的等差数列`i`和`j`。 任何在那里结束的进程必须有一个等于`2*x[i] - x[j]`，因此至多有一个可能的前身。 如果该坐标存在，则每个有效的进程都以`(i, j)`通过扩展结束于的有效级数获得`(k, i)`。 如果不存在，则长度至少为 3 的级数不能以`(i, j)`，留下底边长度`2`。 自从`k < i`，所需的状态已经计算出来。 因此，对所有对取最大值会考虑所有可能的算术级数。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    x = list(map(int, input().split()))

    pos = {value: i for i, value in enumerate(x)}

    # Every pair initially represents a progression of length 2.
    # n <= 3000, so every answer fits into an unsigned short.
    dp = array('H', [2]) * (n * n)

    ans = 2

    for i in range(n):
        xi = x[i]
        row = i * n

        for j in range(i + 1, n):
            target = 2 * xi - x[j]
            k = pos.get(target)

            if k is not None:
                length = dp[k * n + i] + 1
                dp[row + j] = length
                if length > ans:
                    ans = length

    print(ans)

if __name__ == "__main__":
    solve()
```字典`pos`是算法中的恒定时间查找结构。 表达式`2 * xi - x[j]`是算术级数条件强制的精确前驱坐标。 

DP 被扁平化为一维`array('H')`。 对应的状态为`(i, j)`存储在`i * n + j`。 平面数组避免了由数百万个 Python 整数组成的 Python 列表会带来的每个对象的巨大开销。 

每个州开始于`2`，因为任何一对不同的坐标都是有效的选定集。 当存在前驱时，状态将被前一个状态加一覆盖。 

循环顺序很重要。 对于国家来说`(i, j)`，前身是`k < i`， 所以`dp[k][i]`属于较早的行并且已经被计算过。 代码不需要搜索`k`手动因为`pos`直接供给它。 

Python 中不存在整数溢出问题。 最大的中间坐标仅约为`2 * 10^18`，Python 整数准确表示。 

答案初始化为`2`。 自从`n >= 3`，有效的对总是存在，并且长度递增`2`总是允许的。 

## 工作示例

 对于样品 1，```
3
1 2 3
```相关的 DP 转换为：

 |`i`|`j`|`target`|`k`|`dp[i][j]`|
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 0 | 缺席| 2 |
 | 0 | 2 | -1 | 缺席| 2 |
 | 1 | 2 | 1 | 0 | 3 |

 加工时`(1, 2)`，所需的前驱坐标为`2*2 - 3 = 1`，这是第一个灯笼。 已经计算出的状态`dp[0][1] = 2`延伸到长度`3`。 答案是`3`。 

对于样品 2，```
5
1 2 4 6 7
```完整的对轨迹是：

 |`i`|`j`|`target`|`k`|`dp[i][j]`|
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 0 | 缺席| 2 |
 | 0 | 2 | -2 | 缺席| 2 |
 | 0 | 3 | -4 | 缺席| 2 |
 | 0 | 4 | -5 | 缺席| 2 |
 | 1 | 2 | 0 | 缺席| 2 |
 | 1 | 3 | -2 | 缺席| 2 |
 | 1 | 4 | -3 | 缺席| 2 |
 | 2 | 3 | 2 | 1 | 3 |
 | 2 | 4 | 1 | 0 | 3 |
 | 3 | 4 | 5 | 缺席| 2 |

 这对`(2, 4)`对应坐标`4`和`7`。 其所需的前身是`1`，在索引处找到`0`，所以它形成了级数`1, 4, 7`长度`3`。 没有一对延伸到长度`4`，给出所需的答案`3`。 

这些迹线还说明了为什么前驱不需要与输入中的当前对相邻。 转换使用坐标而不是相邻索引。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n^2)`| 每对订购的`i < j`被处理一次，并具有预期的`O(1)`字典查找。 |
 | 空间|`O(n^2)`| 扁平化的 DP 包含`n^2`紧凑的 16 位状态，加上坐标字典。 |

 为了`n = 3000`，有少于`4.5 million`与`i < j`，虽然分配的正方形 DP 包含`9 million`紧凑的条目。 在每个条目两个字节的情况下，DP 占用大约 18 MB，大大低于 512 MB 内存限制。 转换的二次数是此约束的预期规模，而三次替代方案则过于昂贵。

## 边缘情况

 对于最小尺寸的情况```
3
1 2 4
```该算法将每对初始化为`2`。 对于这对`(1, 2)`，所需的前导是`0`，这是不存在的。 其他对也没有有效的前驱，因此仍保留最大值`2`。 这是正确的，因为选择任意两个灯笼总是很漂亮。 

对于跳过灯笼的进度，请考虑```
5
1 2 4 6 7
```当算法到达坐标时`4`和`7`，它计算`2*4 - 7 = 1`。 坐标`1`存在，所以`dp[2][4] = dp[0][2] + 1 = 3`。 选定的坐标是`1, 4, 7`。 中间输入坐标`2`和`6`没关系，因为问题需要一个子集，而不是数组的连续段。 

对于边界坐标，```
3
0 500000000000000000 1000000000000000000
```由最后两个坐标组成的对需要前一个坐标`0`。 字典立即找到它，给出长度`3`。 Python 精确地执行乘法和减法，因此大坐标值不需要任何特殊的算术处理。 

对于不能有前身的坐标，请考虑```
3
0 10 21
```对于这对`10, 21`，所需的前导是`-1`，字典中没有这个词。 对于这对`0, 10`，所需的前导是`-10`，也缺席。 每个州都停留在`2`，所以答案是`2`。 字典查找自然会处理允许的坐标区间之外的目标。 

对于最大尺寸级数，```
3000
0 1 2 3 ... 2999
```每对可以继续差异的对都有一个有效的前驱。 DP反复延长现有状态，最终达到长度`3000`。 紧凑型`array('H')`代表性就足够了，因为任何国家都不能超越`3000`。
