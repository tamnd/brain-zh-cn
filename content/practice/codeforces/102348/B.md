 ## 解决方案
 ## 问题理解

 我们有一棵树，其顶点编号从 1 到 (n)，并且恰好 (k) 个顶点是彩色的。 对于未着色的顶点 (x)，想象一下从树上切掉 (x)。 (x) 的每个邻居都成为一个连通分量的根。 当这些组件中的每一个都包含至少一个彩色顶点时，顶点 (x) 就很有趣。 

任务是找到满足该条件的每个未着色顶点并按升序打印它们的索引。 

核心困难在于该定义暂时将树植根于每个可能的 (x) 处。 直接实现似乎需要对每个未着色的顶点进行单独的树遍历。 当 (n) 与 (2\cdot10^5) 一样大时，这对于两秒的限制来说太昂贵了。 (O(n^2)) 算法在最坏的情况下可以执行大约 (4\cdot10^{10}) 次顶点访问，远远超出了实际情况。 我们需要从一次遍历中提取有关所有可能根的信息。 

有几种边缘情况可能会使看似合理的实现变得错误。 首先，未着色的叶子总是很有趣，因为移除叶子后只剩下一个组件，并且该组件包含所有 (k) 个彩色顶点。 例如，```
2 1
1
1 2
```有输出```
1
2
```要求顶点至少有两个颜色方向的解决方案会错误地拒绝顶点 2。 

当候选本身是彩色的时，会出现第二种边缘情况。 这样的顶点可能在每个方向上都有彩色顶点，但它不符合条件，因为只有未着色的顶点才能作为答案。 例如，```
3 1
2
1 2
2 3
```有输出```
2
1 3
```着色顶点 2 必须被排除，即使通过删除它获得的两个分量都不包含着色顶点，这已经使其在这里失败。 更一般地说，实现应该明确排除彩色顶点，而不是依赖定向测试来执行此操作。 

第三种边缘情况是单色顶点。 如果 (k=1)，则度数至少为 2 的无色顶点不可能是有趣的，因为只有其关联分量之一可以包含唯一的有色顶点。 每片无色的叶子都很有趣。 例如，```
5 1
3
1 2
2 3
3 4
4 5
```有输出```
2
1 5
```仅检查整个子树是否包含颜色的粗心实现可能会意外地接受内部顶点，即使它们的方向之一是无色的。 

最后，保证彩色顶点是不同的，因此所有彩色值都相等的测试用例在问题约束下是无效的。 最接近的有意义的边界情况是 (k=1)，将单独介绍。 

## 方法

 暴力解决方案首先选择每个无色顶点 (x) 作为根。 一旦树以 (x) 为根，我们就可以遍历它并确定 (x) 的每个子树的子树是否包含彩色顶点。 如果每个子子树都包含一个，我们将 (x) 添加到答案中。 

这是正确的，因为这些子子树正是删除 (x) 时生成的连接组件。 问题在于重复工作量。 在最坏的情况下，可能有 (n-1) 个无色候选者，并且检查一个候选者需要 (O(n)) 工作。 以（k=1）为例，这可以达到

 [
 (n-1)(n-1)=O(n^2),
 ]

 当 (n=2\cdot10^5) 时，大约是 (4\cdot10^{10}) 次操作。 

关键的观察是，我们实际上并不需要为每个候选者建立树根。 固定任意根，例如顶点 1。对于每个顶点 (v)，计算其普通有根子树中的彩色顶点数。 

考虑父项 (u) 和子项 (v) 之间的边。 删除这条边会将树分成正好两个部分。 一个是 (v) 的子树，包含`sub[v]`彩色顶点。 另一个包含所有剩余的彩色顶点，因此它包含

 [
 k-\text{sub}[v]
 ]

 彩色顶点。 

这完全决定了该边缘对于任一端点是否是坏方向。 如果`sub[v] == 0`，(v) 侧的分量不包含有色顶点，因此 (u) 不可能有趣。 如果`sub[v] == k`，每个彩色顶点都在 (v) 的子树内部，因此 (u) 一侧的分量不包含彩色顶点，并且 (v) 不可能是有趣的。 

每个其他值`sub[v]`意味着边的两侧都至少包含一个彩色顶点，因此这条边对于两个端点都是安全的。 

暴力破解之所以有效，是因为它明确地检查候选者周围的每个组件，但当为许多候选者重新计算相同的组件时，就会失败。 通过观察每条边只有两个可能的边，我们可以同时对所有方向进行分类。 计算子树颜色计数后，每条边最多对一个端点造成一次故障，因此可以在线性时间内处理整个树。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n^2)) | (O(n)) | (O(n)) | 太慢了 |
 | 最佳| (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 阅读树并标记每个彩色顶点。 我们保留一个布尔数组，因为最终的答案必须排除彩色顶点，即使它们的结构属性会以其他方式限定它们。 
2. 在顶点任意求树根 1. 构建一个`parent`数组和一个`order`使用迭代 DFS 的数组。 这`order`数组以父在子之前的顺序存储顶点，这将让我们稍后可以在不递归的情况下反向处理它们。 
3. 初始化`sub[v]`对于每个有色顶点为 1，对于每个无色顶点为 0。 因此`sub[v]`最终将表示 (v) 的根子树中彩色顶点的数量。 
4. 以逆DFS顺序处理顶点。 对于每个非根顶点 (v)，添加`sub[v]`到`sub[parent[v]]`。 当一个顶点被处理时，它的所有子节点都已经贡献了它们的颜色计数。 
5. 创建`bad[v]`，最初为零。 对于每个非根顶点 (v)，考虑从其父顶点 (p) 到 (v) 的边。 如果`sub[v] == 0`，该边的整个 (v) 侧是无色的，因此该边对于 (p) 来说是一个不好的方向，并且我们递增`bad[p]`。 
6.如果`sub[v] == k`，所有彩色顶点都位于 (v) 边内。 因此，父侧分量是无色的，因此相同的边对于 (v) 来说是一个不好的方向，并且我们递增`bad[v]`。 
7. 最后，扫描每个顶点。 当一个顶点没有着色并且`bad[v] == 0`。 在打印这些索引之前对其进行排序。 排序需要 (O(n\log n))，但由于顶点已经从 1 到 (n) 编号，我们可以按数字顺序扫描它们并直接获得排序输出，从而保留整体 (O(n)) 复杂度。 

### 为什么它有效

 对于每条边 (p-v)，通过删除该边形成的两个分量恰好包含`sub[v]`和 (k-\text{sub[v]}) 彩色顶点。 恰好当以下情况时，边缘对 (p) 不利`sub[v] == 0`，并且恰好在以下情况下对 (v) 不利`sub[v] == k`。 因此`bad[x]`精确计算 (x) 中不包含彩色顶点的事件分量。 

对于无色顶点 (x)，原始定义表示 (x) 周围的每个分量都必须包含有色顶点。 这相当于说它的入射边都不是坏的，这正是`bad[x] == 0`。 由于显式排除了彩色顶点，因此每个报告的顶点都满足定义，并且报告每个有趣的顶点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    colored = [False] * (n + 1)
    for x in map(int, input().split()):
        colored[x] = True

    graph = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    # Root the tree at vertex 1.
    parent = [0] * (n + 1)
    order = [1]
    parent[1] = -1

    for u in order:
        for v in graph[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            order.append(v)

    # sub[v] = number of colored vertices in v's rooted subtree.
    sub = [0] * (n + 1)
    for v in range(1, n + 1):
        if colored[v]:
            sub[v] = 1

    for v in reversed(order[1:]):
        sub[parent[v]] += sub[v]

    # bad[v] = number of incident components of v containing no color.
    bad = [0] * (n + 1)

    for v in order[1:]:
        p = parent[v]

        if sub[v] == 0:
            bad[p] += 1

        if sub[v] == k:
            bad[v] += 1

    answer = []
    for v in range(1, n + 1):
        if not colored[v] and bad[v] == 0:
            answer.append(v)

    print(len(answer))
    print(*answer)

if __name__ == "__main__":
    solve()
```第一部分将彩色顶点存储在`colored`。 使用布尔数组可以进行恒定时间的成员资格检查，并避免以后搜索彩色索引列表的任何需要。 

邻接表表示具有 (O(n)) 内存的树。 由于树正好有 (n-1) 条边，因此所有邻接表中的条目总数为 (2(n-1))。 

DFS 是故意迭代的。 (2\cdot10^5) 个顶点路径上的递归 DFS 会超出 Python 的正常递归深度，并且可能会失败，即使算法本身是正确的。 这`order`数组只需向后迭代即可为我们提供方便的后序。 

的初始化`sub`在每个彩色顶点放置一个单位。 加工`order`向后然后将这些单位向根累积，所以`sub[v]`成为 (v) 的整个子树中彩色顶点的数量。 

边缘分类是最重要的实现细节。 对于一条边从`p`到`v`,`sub[v] == 0`意味着子端组件没有颜色，所以只有`p`被该边取消资格。 反过来，`sub[v] == k`意味着所有颜色都在子端，所以只有`v`被取消资格。 这两种情况不能互换。 

根不需要特殊处理。 与根相关的每条边都在有根树中显示为父子边，并且其子边计数完全确定该边是否对根不利。 

最后的循环从 1 到 (n)，因此输出已经排序。 不需要单独排序，运行时间保持线性。

## 边缘情况

 ### 单色顶点

 考虑```
5 1
3
1 2
2 3
3 4
4 5
```以 1 为根后，子树计数为`1, 1, 1, 0, 0`从顶点 1 到 5，除了顶点 3 周围的适当累积之外。更直接地，对于任何内部未着色顶点，至少有两个事件分量，但只有一个可以包含顶点 3。因此，每个内部顶点都有一个坏方向。 顶点 1 和 5 是叶子，因此删除其中任何一个后，都会有一个包含顶点 3 的组件。该算法给出`bad[1] = 0`和`bad[5] = 0`，而内部候选人至少收到一个错误计数，产生`1 5`。 

### 一片无色的叶子

 考虑```
2 1
1
1 2
```求根于 1 给出`sub[2] = 0`，因为顶点 2 是未着色的。 条件`sub[2] == 0`增量`bad[1]`， 不是`bad[2]`。 顶点 2 没有子边，因此不会收到不良方向。 由于它是无色的，因此可以接受。 将坏边分配给正确的端点是很容易引入相差一概念错误的地方。 

### 绝不能报告彩色顶点

 考虑```
3 1
2
1 2
2 3
```彩色数组标记顶点 2。该算法可以像其他每个顶点一样计算它的结构信息，但最终条件明确要求`not colored[v]`。 因此只有顶点1和3可以输入答案，并且都是叶子。 输出是```
2
1 3
```这种显式排除比试图证明每个彩色顶点都会自动收到错误计数更好，因为定义本身是资格方面最明确的权威。 

### 具有多个无色分支的顶点

 在第一个样本中，```
4 1
3
1 2
2 3
2 4
```顶点 2 有三个入射方向。 朝向顶点 3 的方向包含唯一的颜色，而朝向顶点 1 和 4 的方向不包含任何颜色。 以 4 为根的子树有`sub[4] = 0`，这会增加`bad[2]`。 朝向父级 1 的边在 2 侧具有所有颜色，因此`sub[2] == k`增量`bad[2]`再次。 因此，顶点 2 有两个错误方向并被拒绝。 

相同的基于边缘的会计处理这种情况，无需单独推理候选人的程度。 每个事件分量都由边的一个有向边表示，因此检查每个这样的边是否包含颜色可以简化为两个子树计数边界情况`0`和`k`。
