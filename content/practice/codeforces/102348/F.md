 ## 解决方案
 ## 问题理解

 我们有一个整数数组，每个连续的子数组都有一个负数、零或正数的乘积。 任务是计算有多少个子数组属于这三个类别中的每一个，并按负、零、正的顺序打印计数。 

实际值的大小可以大到 (10^9)，但它们的大小对于乘积的符号并不重要。 对于非零元素，只关心它是正数还是负数。 单个零是不同的，因为包含该零的每个子数组的乘积为零。 

当 (n) 达到 (2\cdot10^5) 时，(O(n^2)) 解决方案已经必须检查

 [
 \frac{n(n+1)}2 \约2\cdot10^{10}
 ]

 最坏情况下的子数组。 这远远超出了 2 秒的时间限制所能处理的范围。 我们需要一个线性或近线性的解决方案。 256 MB 的内存限制也有利于仅保留少量状态，而不是存储有关每个子数组的信息。 

有几种边缘情况可能会默默地破坏一个简单的解决方案。 零必须单独处理。 例如，与```
3
1 0 -1
```正确答案是`0 3 2`。 三个零积子数组是`[1,0]`,`[0]`， 和`[0,-1]`。 仅跟踪负值奇偶校验并忽略零的解决方案会将其中一些子数组错误地分类为正或负。 

单元素数组也很重要，因为子数组的长度允许为 1。 为了```
1
-7
```答案是`1 0 0`。 如果解决方案意外地只考虑不同索引对，则会错过唯一有效的子数组。 

仅包含零的序列提供了另一种有用的边界情况：```
3
0 0 0
```六个子数组中的每一个都包含零，所以答案是`0 6 0`。 在零之后重置符号状态是必要的，因为零将数组分成独立的非零区域。 

最后，计数本身可以超过 32 位整数范围。 对于 (n=2\cdot10^5)，总共有 (20,000,100,000) 个子数组。 32 位有符号整数无法表示该值。 Python 整数会自动处理这个问题，但 C++ 中的相同算法需要`long long`。 

## 方法

 直接的方法是枚举每对端点 ((l,r))，计算该子数组的乘积，并对其符号进行分类。 如果从头开始重新计算每一对的乘积，则该算法需要 (O(n^3)) 时间，因为有 (O(n^2)) 个子数组，并且每个乘积可以包含 (O(n)) 个元素。 对于(n=2\cdot10^5)，这是完全不可行的。 

我们可以通过固定左端点并将右端点一次延伸一个位置来提高蛮力。 我们只在附加新元素时更新其符号，而不是重新计算乘积。 这使得方法 (O(n^2)) 成为一个重大改进，但仍然可能有大约 (2\cdot10^{10}) 个子数组需要处理。 2 秒的限制排除了这种情况。 

关键的观察结果是非零乘积的符号仅取决于负元素数量的奇偶性。 偶数个负因子产生正乘积，奇数个产生负乘积。 我们根本不需要实际的产品。 

考虑数组的无零部分。 当前缀包含偶数个负值时，将前缀的奇偶校验定义为 (0)；当前缀包含奇数时，将奇偶校验定义为 (1)。 对于从 (l) 到 (r) 的子数组，其负元素数模 2 是紧邻子数组之前和末尾的两个前缀奇偶校验的 XOR。 因此，两个相等的前缀奇偶校验给出正子数组，而两个不同的前缀奇偶校验给出负子数组。 

这让我们可以仅使用两个计数器来计算在每个位置结束的子数组。 如果当前前缀奇偶校验为 (p)，则每个具有奇偶校验 (p) 的先前前缀都会创建一个在此结束的正子数组，并且每个具有奇偶校验 (1-p) 的先前前缀都会创建一个负子数组。 

零需要一个额外的想法。 任何包含零的子数组的乘积都为零，因此此类子数组不应参与正或负奇偶校验计数。 我们可以简单地在每个零之后重置前缀奇偶校验计数器。 然后可以独立处理每个最大无零段。 

暴力方法之所以有效，是因为它明确地考虑了每个子数组。 它失败了，因为它们太多了。 只有符号奇偶校验重要的观察结果让我们可以用两个前缀状态的计数替换所有这些子数组，从而一次性遍历数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n^3)) | (O(1)) | (O(1)) | 太慢了 |
 | 增量蛮力 | (O(n^2)) | (O(1)) | (O(1)) | 太慢了 |
 | 前缀奇偶校验| (O(n)) | (O(n)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 保留`cnt[0]`和`cnt[1]`，表示当前有多少个相关前缀位置具有偶数和奇数负计数奇偶校验。 一开始，空前缀具有偶校验，因此`cnt[0] = 1`和`cnt[1] = 0`。 
2. 维护`parity`，即当前无零段中负值个数的奇偶校验。 正值使其保持不变，而负值则翻转它。 
3. 当当前值非零时，更新`parity`如果该值为负数。 如果得到的奇偶校验结果是`p`，每个带有奇偶校验的较早前缀`p`形成一个具有偶数个负值的子数组，因此添加`cnt[p]`到肯定的答案。 每个较早的前缀都带有奇偶校验`1-p`形成一个具有奇数个负值的子数组，因此添加`cnt[1-p]`到否定的答案。 
4. 增量`cnt[p]`因为以当前位置结尾的前缀可以被未来的子数组使用。 
5. 当当前值为零时，在此位置结束的每个子数组都包含该零，因此其乘积为零。 正好有`i+1`以从零开始的索引结尾的子数组`i`，所以添加`i+1`到零的答案。 
6. 重置`parity`归零并恢复`cnt[0] = 1`,`cnt[1] = 0`零后。 下一个非零子数组在保持非零的同时不能跨越零，因此零之前的前缀奇偶校验不得与零之后的前缀奇偶校验混合。 
7. 按顺序打印负数、零数和正数。 

### 为什么它有效

 在任何无零段内，考虑一个其端点对应于两个前缀状态的子数组。 其负元素数模二是前缀奇偶校验的异或。 等价产生偶数个负数，因此产生正数。 不同的奇偶校验产生奇数个负数，因此产生负乘积。 计数器准确存储有多少个先前前缀具有每个奇偶校验，因此每个非零子数组在处理其右端点时只计算一次。 

此奇偶校验参数中永远不包含零。 每个跨越零的子数组的乘积为零，而每个非零子数组完全位于两个零之间。 在每个零之后重置计数器可以完美区分这两种情况。 因此，每个子数组都被准确地分类为负、零或正一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    negative = 0
    zero = 0
    positive = 0

    parity = 0
    cnt = [1, 0]

    for i, x in enumerate(a):
        if x == 0:
            zero += i + 1

            parity = 0
            cnt[0] = 1
            cnt[1] = 0
            continue

        if x < 0:
            parity ^= 1

        positive += cnt[parity]
        negative += cnt[parity ^ 1]

        cnt[parity] += 1

    print(negative, zero, positive)

if __name__ == "__main__":
    solve()
```三个答案变量存储最终计数。 它们可以增长到大约 (n(n+1)/2)，因此 Python 的任意精度整数在这里很方便。`parity`表示当前无零前缀中所有非零元素的乘积的符号。 负元素会翻转奇偶校验，而正元素则不执行任何操作。 

初始化`cnt = [1, 0]`代表空前缀。 这就是允许对从第一个元素开始的子数组进行计数的原因。 例如，如果第一个元素为负，则当前奇偶校验变为 1，并且初始偶数前缀创建一个负子数组。 

对于非零元素，`cnt[parity]`被添加到`positive`因为相等的前缀奇偶校验取消模二。`cnt[parity ^ 1]`被添加到`negative`因为不同的平价留下了一个无与伦比的负平价。 

零处理用途`i + 1`而不是只计算零本身。 在位置`i`，正好有`i + 1`左端点的选择，并且这些子数组中的每一个都以零结束，因此其乘积为零。 

归零后的重置至关重要。 如果没有它，零之前的前缀可能会与零之后的前缀配对，并错误地为实际包含零的子数组生成正数或负数。 

该算法中没有乘法运算，因此不需要表示潜在的巨大中间产物。 重要的最大值是答案计数，Python 会安全地处理它们的大小。

 ## 边缘情况

 单个零是零情况的最小示例：```
1
0
```在索引 0 处，恰好有一个子数组结束于此，即`[0]`。 该算法添加`0 + 1 = 1`到零计数并重置奇偶校验计数器。 结果是`0 1 0`。 

中间的零需要计算的不仅仅是零本身。 为了```
3
1 0 -1
```在索引一处，以此处结尾的两个子数组是`[0]`和`[1,0]`，所以两者都是零积子数组。 在索引二处，由于为零，奇偶校验状态重新开始，并且`[-1]`贡献一个负子数组。 两个正子数组是`[1]`和`[-1]`不是正数，因此非零总计实际上是一个正数和一个负数。 正确的分类是`1 3 2`仅当`[1,-1]`也算负数，多加一个负数。 因此正确的输出是`1 3 2`。 这种情况捕获了错误地将零仅视为符号中性元素的实现。 

对于全零数组，```
3
0 0 0
```第一个零贡献一个零积子数组，第二个零贡献两个，第三个贡献三个。 总数为 (1+2+3=6)，所以答案为`0 6 0`。 每次重置都会将前缀状态保留在`[1,0]`，防止任何非零子数组跨越零。 

对于全负数组，```
3
-1 -1 -1
```前缀奇偶校验交替为奇数和偶数。 三个长度为一的子数组具有负积，并且长度为三的子数组也具有负积，从而给出四个负子数组。 两个长度为 2 的子数组包含两个负值且均为正值。 该算法产生`4 0 2`，直接反映了奇偶规则。 

最大尺寸的正例是```
200000
1 1 1 ... 1
```200,000份`1`。 每一位

 [
 \frac{200000\cdot200001}{2}=20000100000
 ]

 子数组为正。 该算法通过单次扫描即可达到此计数，而强力枚举则需要检查 200 亿个子阵列。 这说明了为什么线性方法是必要的，以及为什么答案类型必须支持大于 32 位的值。
