 ## 解决方案
 ## 问题理解

 我们有一个由 (n) 个整数组成的数组，每个连续的子数组根据其乘积的符号进行贡献。 对于每对端点 (l \le r)，(a_l,a_{l+1},\ldots,a_r) 的乘积要么是负数，要么是零，要么是正数。 我们需要计算每个类别有多少个子数组，并按顺序打印三个计数。 

非零乘积的实际值是无关紧要的。 只有它的符号才重要。 当子数组包含奇数个负元素时，乘积为负，当子数组包含偶数个负元素时，乘积为正。 任何包含至少一个零的子数组的乘积为零。 

该数组最多可包含 (2\cdot10^5) 个元素。 二次算法将大致检查 (n(n+1)/2) 个子数组，当 (n=2\cdot10^5) 时，大约为 (2\cdot10^{10})。 这远远超出了 2 秒限制所能处理的范围。 我们需要一个 (O(n)) 或 (O(n\log n)) 的解决方案。 答案本身也可以在 (n(n+1)/2) 左右，因此在具有固定宽度整数类型的语言中需要 64 位整数。 Python 整数已经安全地处理这些值。 

零需要单独处理，因为零会破坏符号信息。 例如，使用输入```
1
0
```正确答案是```
0 1 0
```将零视为既不正也不负但继续先前前缀状态的符号奇偶校验算法将错误地允许子数组跨越零并按旧符号对它们进行分类。 零必须将数组分割成独立的非零段。 

另一个容易错误处理的情况是仅包含正值的数组。 为了```
3
1 1 1
```(6) 个子数组中的每一个都有正积，所以答案是```
0 0 6
```仅对改变符号的乘积进行计数的方法可能会忘记对单个元素和正元素的偶数长度组合进行计数。 

负值还需要正确计算空前缀。 为了```
3
-1 -1 -1
```正确答案是```
4 0 2
```负积子数组具有奇数长度，即 (3+1=4)，而两个偶数长度子数组具有正积。 忘记第一个元素之前的前缀会丢失从索引 (1) 开始的子数组。 

最后，零可能出现在边界处。 为了```
3
0 1 0
```正确答案是```
0 5 1
```总共有六个子数组，只有 ([2,2]) 具有非零正积。 其他五个包含零。 仅当遇到零时才对包含零的子数组进行计数的任何解决方案都可能会错过继续超出该零的子数组。 

## 方法

 直接的方法是枚举每对端点 ((l,r))。 对于固定的左端点，我们可以一次将右端点延伸一个位置并保持当前的乘积符号。 不需要乘以实际值，因为只有负元素的数量是奇数还是偶数才重要，并且可以立即检测到零。 

这种强力方法是正确的，因为每个连续的子数组都只被考虑一次。 问题是子数组的数量。 它们有 (n(n+1)/2) 个，对于 (n=200,000) 达到 (20,000,100,000) 个。 即使每个子阵列的恒定时间处理也太多了，因此排除了二次方法。 

关键的观察结果是，非零子数组的符号仅取决于其中负元素数量的奇偶校验。 我们可以将此奇偶校验编码为 (0)（对于偶数个负数）和 (1)（对于奇数数）。 

考虑前缀奇偶校验。 令 (p_i) 为当前非零段中直到位置 (i) 的负元素数量的奇偶校验。 对于从 (l) 到 (r) 的子数组，其负元素数模 (2) 为

 [
 p_r \oplus p_{l-1}。 
]

 因此，如果两个前缀奇偶校验相等，则子数组的乘积为正。 如果它们不同，则子数组的乘积为负。 

从左到右扫描时，我们只需要知道前面有多少个前缀具有偶数和奇数奇偶校验。 如果当前前缀奇偶校验为偶数，则每个先前的偶数前缀形成一个在此结束的正积子数组，而每个先前的奇数前缀形成一个负积子数组。 当当前奇偶校验为奇数时，情况相反。 

零只是分隔独立的段。 当出现零时，没有有效的非零子数组可以与其交叉，因此前缀奇偶校验计数将重置为其初始状态。 

一旦计算完所有非零乘积，每个剩余的子数组都必须具有乘积零。 总共有 (n(n+1)/2) 个子数组，所以

 [
 \text{零} =
 \frac{n(n+1)}2-\text{负}-\text{正}。 
]

 这避免了直接计算包含零的子数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^2)) | (O(1)) | (O(1)) | 太慢了 |
 | 前缀符号奇偶校验| (O(n)) | (O(n)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 从 1 个偶数前缀和 0 个奇数前缀开始。 初始前缀表示第一个元素之前的空序列，其负值的数量为零。 
2. 维护`even`和`odd`，具有偶数和奇数负计数奇偶校验的先前前缀状态的数量。 还保持当前的奇偶校验，其中`0`意味着偶数和`1`意思是奇数。 
3. 对于每个数组元素，首先检查它是否为零。 如果为零，则重置`even`至 (1),`odd`为 (0)，当前奇偶校验为偶数。 零分隔数组的非零部分，因此它之前的前缀不能与它之后的前缀配对。 
4. 如果元素为负，则翻转当前奇偶校验。 如果该元素为正，则保持奇偶校验不变。 只有符号很重要，因此元素的大小永远不会进入计算。 
5. 如果当前奇偶校验为偶数，则添加`even`到正计数和`odd`到负数。 每个先前的偶数前缀在两个前缀之间产生偶数个负数，而每个先前的奇数前缀产生奇数个。 
6. 如果当前奇偶校验为奇数，则添加`odd`到正计数和`even`到负数。 这两种情况相反，因为相等的前缀奇偶校验仍然抵消偶差。 
7. 将当前前缀添加到适当的计数器。 这必须在计算以当前位置结束的子数组之后发生，因为当前前缀不能用作以同一位置结束的子数组的左边界。 
8. 处理整个数组后，计算子数组的总数为 (n(n+1)/2)。 将正数和负数相减，得到乘积为零的数。 

### 为什么它有效

 对于每个非零子数组，其符号由其负元素数量的奇偶校验确定。 ([l,r]) 内的负计数的奇偶校验是紧接在 (r) 后面和紧接在 (l) 之前的前缀奇偶校验的异或。 因此，相同的前缀奇偶性代表正产品，而不同的前缀奇偶性代表负产品。 柜台`even`和`odd`恰好包含所需的先前前缀，因此每个非零子数组在处理其右端点时都会被计数一次。 零后重置可防止任何包含零的子数组进入这些计数。 由于每个子数组要么为正，要么为负，要么为零，因此从总数中减去两个非零计数正好得出零计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_products(a):
    n = len(a)

    # Number of previous prefix parities in the current nonzero segment.
    even = 1
    odd = 0

    parity = 0

    negative = 0
    positive = 0

    for x in a:
        if x == 0:
            # No nonzero subarray can cross a zero.
            even = 1
            odd = 0
            parity = 0
            continue

        if x < 0:
            parity ^= 1

        if parity == 0:
            positive += even
            negative += odd
            even += 1
        else:
            positive += odd
            negative += even
            odd += 1

    total = n * (n + 1) // 2
    zero = total - positive - negative

    return negative, zero, positive

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    negative, zero, positive = count_products(a)
    print(negative, zero, positive)

if __name__ == "__main__":
    solve()
```功能`count_products`包含整个线性扫描。`even = 1`表示第一个元素之前的前缀。 此初始化允许对从第一个数组位置开始的子数组进行计数。 

对于负值，`parity ^= 1`翻转奇偶校验，因为又遇到了一个负元素。 正值使奇偶校验保持不变。 从不使用非零值的实际大小。 

的补充`positive`和`negative`发生在递增之前`even`或者`odd`。 此时，这些计数器仅描述严格位于当前元素之前的前缀，这正是端点公式所要求的。 首先更新它们会引入无效的空长度贡献。 

什么时候`x == 0`，当前非零段结束。 重置为`even = 1`,`odd = 0`， 和`parity = 0`紧接着零之后开始一个新的前缀序列。 包含零的子数组被有意排除在正计数和负计数之外。 

表达式`n * (n + 1) // 2`计算每对可能的端点。 Python 的任意精度整数使得潜在的大答案是安全的，无需任何特殊处理。

 ## 边缘情况

 对于单个零，输入为```
1
0
```初始状态是`even = 1`,`odd = 0`。 零触发重置，使非零计数为零。 总共只有一个子数组，所以`zero = 1 - 0 - 0 = 1`。 输出是`0 1 0`。 

对于所有正值，```
3
1 1 1
```奇偶校验永远不会改变。 第一个元素对具有初始偶数前缀，第二对具有两个偶数前缀，第三对具有三个偶数前缀。 正数变为(1+2+3=6)，即每个子数组。 输出是`0 0 6`。 

对于所有负值，```
4
-1 -1 -1 -1
```奇偶校验在奇数和偶数之间交替。 负计数收到 (1)、(2)、(1) 和 (2) 贡献，总计 (6)。 正计数收到 (1)、(0)、(2) 和 (1) 贡献，总计 (4)。 没有零，所以结果是`6 0 4`。 

对于两个边界处的零，```
3
0 1 0
```第一个零会在计算任何非零子数组之前重置状态。 这`1`然后恰好创建一个正子数组。 最后的零再次重置状态。 由于总共有 6 个子数组，并且只有一个非零，因此零计数为 (5)。 输出是`0 5 1`。 

对于内部零，```
5

```第一段`[1,-1]`贡献一个正子数组和一个负子数组。 零可防止任何子数组交叉位置 (3) 进入任一非零类别。 第二段`[-1,1]`贡献相同的计数。 因此有 (2) 个正子数组和 (2) 个负子数组。 共有 (15) 个子数组，其余 (11) 个子数组的乘积为零，给出`2 11 2`。

 # \frac{200000\cdot200001}{2}

 20000100000。 
]
