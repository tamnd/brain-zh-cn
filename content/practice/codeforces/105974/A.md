 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们在保持顺序的同时考虑通过选择元素的任何子集形成的所有可能的子序列。 对于每个选定的子序列，我们计算其所有元素的按位异或。 任务是确定可以在所有子序列中生成多少个不同的 XOR 值。 

尽管子序列保留顺序，但 XOR 运算本身会忽略顺序，因此重要的是选择哪些元素而不是它们出现的位置。 两个不同的子序列仍然可以产生相同的 XOR 值，并且要求我们计算可能有多少个唯一结果。 

如果数组长度达到 10^5 左右，任何直接枚举子序列的方法都是不可能的。 子序列的数量为 2^n，一旦 n 相当大，就已经超出了任何可行的计算。 这立即排除了任何指数枚举策略，并推动我们以压缩形式表示所有子集 XOR 的集合。 

一个常见的失败案例来自于尝试增量地“跟踪集合中的所有异或”。 例如，如果数组是 [1, 2, 3]，则可以模拟添加元素并更新一组可到达的 XOR。 这适用于较小的 n，但在最坏的情况下，每一步的状态空间都会加倍。 当 n = 30 时，这已经成为边界，而当 n = 10^5 时这是不可能的。 

另一个微妙的问题是重复元素。 例如，[5, 5] 生成子序列 XOR {0, 5}。 一个在没有结构的情况下独立处理事件的简单实现可能会过度计数或错过取消，除非它明确地正确处理 XOR 代数。 

## 方法

 暴力破解的想法很简单：生成每个子序列，计算其异或，并将其插入到集合中。 这是正确的，因为它直接遵循问题的定义。 然而，子序列的数量为 2^n，每次 XOR 计算的成本高达 O(n)，因此总工作量约为 O(n · 2^n)。 对于 25 左右的 n 来说，这已经变得不可行了。 

关键的观察结果是子集上的异或在二进制字段上形成了线性结构。 每个数字都可以解释为位向量，XOR 对应于向量加法 mod 2。所有子集 XOR 的集合恰好是给定向量的线性跨度。 我们不需要枚举组合，只需要了解这个跨度的维度即可。 

这就引出了线性基（也称为 XOR 基）的概念。 我们维护一组独立的向量，以便任何数组元素都可以表示为某些基本元素的异或。 每次插入新数字时，我们都会尝试使用先前存储的基础向量来减少它。 如果不能归零，那就成为一个新的独立方向。 

如果最终基的大小为 k，则每个子集 XOR 对应于独立地选择是否包括每个基向量。 这恰好产生 2^k 个不同的 XOR 值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 线性基础| O(n log A) | O(n log A) | O(1) 到 O(log A) | 已接受 |

 这里A是数组中的最大值。 

## 算法演练

1. 初始化一个空的异或基础结构，其中每个位置从高到低对应一位。 该结构将在每个位位置最多存储一个向量。 
2. 迭代数组中的每个数字。 对于当前的数量，尝试在现有的基础上减少它。 对于从最高到最低的每一位，如果设置了该位并且我们已经有了该位的基本向量，则将数字与该基本向量进行异或以消除前导位。 此步骤逐渐简化数字，同时保留其在跨度中的可表示性。 
3. 约简后，如果数字变为零，则说明它已经可以由现有的基本元素组成，因此不会增加空间的维数。 
4. 如果该数字不为零，则找到其最高设置位并将其插入到该位置的基础中。 这扩展了向量的独立集合。 
5. 处理完所有数字后，计算插入了多少个基向量。 令该计数为 k。 
6.答案是2^k，代表独立方向的所有可能的异或组合。 

### 为什么它有效

 该基维护一组线性独立的 XOR 向量。 每个插入的向量要么位于现有向量的范围内，要么将维度增加一倍。 因为 XOR 是向量空间中 GF(2) 上的加法，所以每个子集 XOR 唯一对应于基向量的选择。 因此，可到达的 XOR 值的数量正是跨度中元素的数量，其维度增加了 2。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    B = [0] * 60  # basis for bits up to 2^59
    rank = 0

    for x in arr:
        v = x
        for b in range(59, -1, -1):
            if (v >> b) & 1:
                if B[b]:
                    v ^= B[b]
                else:
                    B[b] = v
                    rank += 1
                    break

    # number of distinct XOR subsets
    print(1 << rank)

if __name__ == "__main__":
    solve()
```该解决方案维护一个固定大小的数组`B`其中每个条目存储一个代表向量，其最高位位于该位置。 这保证了每个新的插入要么取消自身，要么引入一个新的独立方向。 变量`rank`追踪已经发现了多少个这样的独立方向。 

最后的移位操作`1 << rank`有效计算 2^rank。 由于标准 64 位整数的等级最多为 60，因此这是安全的。

 ### 示例 1

```我们处理每个数字并维护基本向量。 

| 步骤| x| 减少x | 基础变化| 排名|

 ## 边缘情况

 单个零元素输入（例如 [0]）应该恰好产生一个不同的 XOR 值，因为唯一的子序列是空和 [0]，两者都产生零。 该算法将 0 视为可立即约简，并且不会增加等级，因此结果为 2^0 = 1。 

每个元素都相同的数组（例如 [9, 9, 9]）也仅产生两个不同的 XOR：零和值本身。 第一次插入建立一个基础向量，并且每个后续相同值在该基础下减少到零，保留排名 1 并产生 2^1 = 2。 

诸如 [1, 2, 4, 8] 之类的满秩构造可确保每个数字都成为独立的基向量。 每次插入都会将排名增加 1，最终结果 2^4 = 16 符合所有子集 XOR 都是不同的事实。
