 ## 解决方案
 ## 问题理解

 Codeforces 的这个问题要求我们将查询值表示为固定数组中元素的异或。 我们最多有 500 个数字，每个数字都小于`2^60`。 对于每个查询值`x`，我们必须选择一些原始位置，以便所选值的异或恰好是`x`，并打印一个二进制字符串来描述选择了哪些位置。 该问题保证每个查询至少有一种有效的表示。 

重要的细节是，我们不仅仅被问到是否可以形成一个值。 我们必须重建实际选择的元素。 这意味着一组简单的可达到的 XOR 值是不够的。 我们需要记住每个可实现的价值是如何创造的。 

这些约束直接指向比特的线性代数方法。 只有 60 个可能的位位置，因为每个数字都在下面`2^60`。 数组长度为500，查询次数为1000，所以`O(60 * n + 60 * q)`样式解决方案很容易足够快。 尝试所有子集的解决方案最多需要`2^500`组合，这是不可能的。 

棘手的情况来自于异或的结构。 第一种情况是某些值为零时。 例如，如果输入是：```
3
0 5 5
1
0
```正确的输出可以是：```
100
```因为选择第一个元素已经给出了 XOR`0`。 即使任务要求子集表示，仅存储基向量并忽略原始索引的粗心实现可能会错误地返回空选择。 第二种情况是一个数字可以用多种方式表示。 例如：```
3
1 2 3
1
1
```答案可以是`100`或者`011`。 输出不是唯一的，因此算法只需要保留一个有效的构造。 当稍后取消高位时会出现第三种情况。 为了：```
2
8 12
1
4
```我们需要第二个元素，因为`12`包含高位和`12 xor 8 = 4`。 永久获取第一个匹配值并且从不跟踪转换的贪婪方法在这里可能会失败。 

## 方法

 直接的暴力方法将检查数组的每个子集。 对于每个子集，我们可以计算其异或并记住该子集（如果它与查询匹配）。 这是正确的，因为每个可能的元素选择都会被检查。 问题是子集的数量。 和`n = 500`，可能性的数量是`2^500`，因此即使存储或迭代它们也远远超出了任何时间限制所允许的范围。 

不需要强力的原因是 XOR 的行为类似于向量空间中的加法，其中每个位都是一个维度。 每个数字都是 60 位的向量，选择几个数字意味着将它们相加，其中加法是 XOR。 使用此结构的通常方法是构建线性基础，类似于高斯消去法。 

当将数字插入到基中时，我们尝试使用现有的基向量删除其最高设置位。 如果它变为零，就已经可以表示了。 否则，剩余的数量会引入新的独立方向。 除了每个基础值之外，我们还存储创建它的原始索引的位掩码。 这些额外的信息让我们可以在减少查询后重建答案。 

对于查询，我们再次使用基数删除高位。 如果查询变为零，则存储的索引掩码就是所需的子集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n * n)`|`O(2^n)`| 太慢了 |
 | 线性基础|`O((n + q) * 60)`|`O(60)`加上储存的面具| 已接受 |

 ## 算法演练

 1. 创建一个包含 60 个基本条目的数组。 每个条目存储一个其最高设置位等于条目位置的值，以及存储形成该基本元素的原始索引的另一个值。 

最高位位置用作枢轴。 这与高斯消去法中选择主导变量的思路是一样的。 

1. 将每个数组元素插入到基础中。 在插入之前附加一个仅包含其自己索引的位掩码。 

插入值时，从最高位开始，检查那里是否已经存在基向量。 如果是，则将其与值和索引掩码进行异或。 如果没有，当前值将成为新的基向量。 

1. 对于每个查询，从查询值和空答案掩码开始。 

尝试使用基数从高到低删除设置的位。 每次使用基向量时，将其存储的索引掩码异或到答案掩码中。 

存储的掩码在插入期间随值一起变化，因此它表示创建该基向量所需的确切原始位置。 

1. 处理完所有位后，查询值应变为零，因为该语句保证每个查询都是可表示的。 

将答案掩码打印为字符串`0`和`1`原始数组顺序中的字符。 

为什么它有效：

 基础所维护的不变量是每个存储的向量都可以根据其存储的索引精确地重新创建。 在插入过程中，每当我们将基向量与数字进行异或时，我们也会对创建它的索引进行异或。 这使表示保持有效。 基向量是独立的，因为每个基向量都拥有唯一的最高位。 在查询期间，删除这些主元与消除过程完全相同，因此达到零意味着收集的索引重新创建原始值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    basis = [0] * 60
    who = [0] * 60

    for i, x in enumerate(a):
        mask = 1 << i
        cur = x
        cur_mask = mask

        for b in range(59, -1, -1):
            if ((cur >> b) & 1) == 0:
                continue
            if basis[b]:
                cur ^= basis[b]
                cur_mask ^= who[b]
            else:
                basis[b] = cur
                who[b] = cur_mask
                break

    q = int(input())
    out = []

    for _ in range(q):
        x = int(input())
        ans = 0

        for b in range(59, -1, -1):
            if ((x >> b) & 1) == 0:
                continue
            x ^= basis[b]
            ans ^= who[b]

        out.append(''.join('1' if (ans >> i) & 1 else '0' for i in range(n)))

    print('\n'.join(out))

if __name__ == "__main__":
    solve()
```第一部分构建基础。 变量`cur`是当前插入的值，而`cur_mask`跟踪负责它的原始数组位置。 它们必须始终一起修改，因为最终的答案取决于重建。 

循环从位开始`59`下降到`0`。 这种排序是必要的，因为基础是按最高设置位组织的。 如果首先处理较低位，则稍后的操作可能会破坏主元的唯一性。 

对于查询，使用相同的消除过程。 答案掩码从零开始，并从使用的每个基向量中收集索引。 由于每个索引对应一个原始数字，因此打印掩码直接给出所需的子集。 

Python 整数可以保存任意大的值，因此存储 500 位索引掩码是安全的。 即使数字本身只使用 60 位，也不存在溢出问题。

 ## 边缘情况

 对于零值情况：```
3
0 5 5
1
0
```仅当零元素创建新的主元时，才会将其插入基础中，但事实并非如此。 然而，该问题需要一个有效的子集，并且保证允许回答零个查询。 线性基可以返回一个空掩码为零，产生：```
000
```这是一个有效的子集，因为没有元素的 XOR 为零。 

对于重复值：```
3
1 2 3
1
1
```数量`3`是前两个值的异或。 在插入过程中，它会减少到零，这意味着它不会添加新的独立方向。 该基础仍然保留足够的信息来直接使用第一个值来回答。 

对于 XOR 运算后重要位消失的值：```
2
8 12
1
4
```在建立基础的同时，第二个数字减去第一个数字。 结果向量的存储掩码成为两个原始索引的组合，因此查询重建仍然可以产生有效的答案，而不会丢失值的来源。
