 ## 解决方案
 ## 问题理解

 每个查询都会给出三堆糖果。 Alice 必须拿走一整堆，Bob 必须拿走剩下的一堆，最后一堆可以在他们之间任意分配。 

分配后，如果一个人比另一个人拥有更多糖果，则可以简单地丢弃多余的糖果。 最终的结果是两个人得到的糖果数量相同。 我们的目标是最大化这个共同数字。 

关键的观察是丢弃的糖果是允许的。 我们不需要使用每一种糖果。 我们只需要最大化 Alice 和 Bob 可以保留的金额即可。 

查询的数量最多为1000，这是很小的。 然而，每堆最多可以包含$10^{16}$糖果，因此任何依赖于堆大小本身的算法都是不可能的。 我们需要一个直接的数学公式，可以在每个查询的恒定时间内进行计算。 

一个常见的错误是假设答案总是糖果总数的一半。 考虑桩$(1,1,100)$。 总计为$102$，所以一半是$51$。 但这两个小堆只包含$2$总共糖果。 一个人可以拿走一堆$100$，但对方无法到达$51$糖果，因为只有$2$糖果存在于最大的一堆之外。 正确答案是$2$。 

另一个容易犯的错误是认为最大的堆直接限制了答案。 考虑$(4,4,4)$。 最大的桩有尺寸$4$，但答案是$6$。 爱丽丝可以收到$4$从一堆和$2$从剩余的一堆中取出，而鲍勃则收到另一堆$4$另一个$2$。 

当一堆压倒其他堆时，就会出现第三种边缘情况。 为了$(1,10,100)$，总计为$111$，所以理论上限是$\lfloor 111/2 \rfloor = 55$。 这个值是可以实现的，给出答案$55$。 

## 方法

 蛮力的观点是尝试每一个可能的任务。 我们可以选择爱丽丝拿走哪一堆，鲍勃拿走哪一堆，然后考虑分割剩余那堆的所有方法。 

这个推理是正确的，因为每个有效的分布都会被检查。 问题是剩余的堆最多可以包含$10^{16}$糖果，所以枚举所有可能的分裂是完全不可能的。 

为了取得进展，我们需要考虑到底是什么限制了最终的等量。 

假设堆大小已排序：$$a \le b \le c.$$让$$S = a+b+c.$$由于两个人最终的金额相同$x$，他们一起保持$2x$糖果。 他们不能保留比现有更多的糖果，所以$$2x \le S,$$这给出了$$x \le \left\lfloor \frac{S}{2} \right\rfloor.$$这是第一个上限。 

还有另外一个。 给两个人$x$糖果，至少$x$糖果必须来自两堆较小的糖果的总和，因为最大的一堆最多将自己的所有糖果贡献给一侧。 最大堆外的总金额为$$a+b.$$因此$$x \le a+b.$$这是唯一重要的限制。 如果$$x \le \min\left(a+b,\left\lfloor \frac{S}{2}\right\rfloor\right),$$那么这样的分布总是可以构造出来的。 

因此答案很简单$$\min\left(a+b,\left\lfloor \frac{a+b+c}{2}\right\rfloor\right),$$排序后使得$c$是最大的一堆。

 ## 算法演练

 1. 读取三个堆的尺寸。 
2. 对它们进行排序，以便$a \le b \le c$。 
3. 计算糖果总数：$$S=a+b+c.$$4. 计算第一个上限：$$\left\lfloor \frac{S}{2} \right\rfloor.$$两个结局相同的人不能一起持有比现有更多的糖果。 
5. 计算第二个上限：$$a+b.$$两个较小的堆仅包含$a+b$糖果总数，所以最终等量不能超过这个值。 
6. 输出$$\min\left(a+b,\left\lfloor \frac{S}{2}\right\rfloor\right).$$### 为什么它有效

 价值$x$不能超过$\lfloor S/2 \rfloor$因为只有$S$糖果可用。 也不能超过$a+b$因为仅靠最大的一堆无法为两个参与者提供足够的糖果。 

这两个不等式给出了一个上限：$$x \le \min\left(a+b,\left\lfloor \frac{S}{2}\right\rfloor\right).$$这个界限总是可以实现的。 如果最大的一堆非常大，那么$a+b$成为限制因素。 否则，糖果总数就会成为限制因素。 无论哪种情况，剩余的一堆都可以适当地分割以准确地实现该值。 因此，该公式既是上限，又是可实现的值，证明了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

q = int(input())

for _ in range(q):
    a, b, c = map(int, input().split())
    a, b, c = sorted((a, b, c))

    total = a + b + c
    print(min(a + b, total // 2))
```实现直接遵循数学公式。 

这三个值被排序，使得最大的堆总是存储在`c`。 这让我们可以确定数量`a + b`，这是最大堆之外的糖果总数。 

价值`total // 2`如果只考虑糖果总数，则表示最大可能的平等份额。 

答案是这两个界限中的最小值。 

Python 整数自动处理比以下值大得多的值$10^{16}$，所以溢出不是问题。 整个解决方案每个查询仅使用少量算术运算。

 ## 边缘情况

 考虑输入：```
1
1 1 100
```排序后，$a=1$,$b=1$,$c=100$。 该算法计算：$$a+b=2,$$

$$\left\lfloor \frac{102}{2} \right\rfloor = 51.$$答案是$\min(2,51)=2$。 

这个案例说明了为什么只使用总数的一半是不正确的。 几乎所有糖果都被困在一堆里。 

现在考虑：```
1
4 4 4
```该算法计算：$$a+b=8,$$

$$\left\lfloor \frac{12}{2} \right\rfloor = 6.$$答案是$6$。 

只关注最大堆的幼稚策略可能会预测$4$，这太小了。 拆分剩余的一堆允许两个参与者超过任何单个堆的大小。 

最后，考虑：```
1
2 3 5
```该算法计算：$$a+b=5,$$

$$\left\lfloor \frac{10}{2} \right\rfloor = 5.$$答案是$5$。 

此边界情况是两个上限相等的情况。 算法很自然地处理它，不需要任何特殊的逻辑。
