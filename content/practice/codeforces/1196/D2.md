 ## 解决方案
 ## 问题理解

 给定一个仅由字母 R、G 和 B 组成的字符串。我们要从该字符串中选取一个固定长度 k 的连续块并修改字符，以便该块与无限重复模式“RGBRGBRGB...”的某些片段匹配。 

关键的自由度是我们可以选择字符串内任何长度为 k 的窗口，并且还可以选择周期模式的任何对齐方式作为目标。 每个对齐对应于“RGB”的三个循环移位之一。 一旦目标模式被固定，我们就会计算所选窗口中有多少位置已经与它匹配，并且其他所有内容都必须更改。 

因此，任务简化为找到长度为 k 的窗口和最小化不匹配的模式阶段。 

约束很大：所有查询的总长度最多为 200000。这立即排除了以简单的方式独立为每个窗口重新计算不匹配的情况。 任何尝试所有子字符串并从头开始重新计算比较的解决方案都会像 O(nk) 一样，当两者都很大时，这会太慢。 

当 k 等于 n 时，会出现微妙的边缘情况。 在这种情况下，只有一个窗口，但仍然需要考虑所有三相对齐。 另一个极端情况是，字符串已经与模式完美对齐，但开始时的相位与我们假设的相位不同，因此错误修复相位的算法可能会错过最佳解决方案。 

## 方法

 一种直接的方法是在字符串上滑动长度为 k 的窗口。 对于每个窗口，我们尝试重复模式的所有三种可能的对齐方式。 对于固定窗口和固定阶段，我们将每个字符与预期字符进行比较并计算不匹配的数量。 

这是正确的，因为答案正是所有选择的最小不匹配。 然而，每个窗口的成本为 O(k)，并且有 O(n) 个窗口，每个查询的复杂度为 O(nk)。 在最坏的情况下，k 与 n 成正比，因此每个查询都会变成二次方，这在全局约束下是不可行的。 

关键的观察结果是目标模式是周期性的，周期为 3。这意味着对于任何起始位置，预期特征仅取决于索引模 3 加上相移。 我们可以为整个字符串的三个阶段中的每个阶段预先计算不匹配数组，而不是重新计算每个窗口的比较。 然后每个窗口查询就成为这些数组上的范围求和查询。 

具体来说，对于 {0, 1, 2} 中的每个阶段 p，我们构建一个数组，其中位置 i 存储 s[i] 是否与阶段 p 下该位置处的预期字符不同。 这些数组上的前缀和允许对任何窗口中的不匹配进行恒定时间计算。 然后我们滑动窗口一次，并在所有位置和相位上取最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(nk) | O(1) 额外 | 太慢了 |
 | 每相前缀不匹配 | 每个查询 O(n) | O(n) | 已接受 |

 ## 算法演练

1. 对于 RGB 循环的三个可能的起始阶段中的每一个，在字符串上构造一个不匹配数组。 在索引 i 处，如果 s[i] 与该阶段下的预期字符不匹配，则该数组存储 1，否则存储 0。分隔阶段的原因是模式对齐是目标字符串中唯一的歧义。 
2. 将每个不匹配数组转换为前缀和数组，以便我们可以在 O(1) 内计算任意区间 [l, r] 内的不匹配数。 这避免了为每个窗口重新计算字符比较。 
3. 将长度为 k 的窗口滑过字符串中所有可能的起始位置。 对于每个起始索引，使用前缀和计算该窗口中三个阶段中每个阶段的不匹配计数。 
4. 在所有窗口和所有阶段保持运行最小值。 该值表示使某些子字符串与有效的 RGB 对齐模式段匹配所需的最小更改数。 
5. 处理完所有窗口后输出最小值。 

为什么有效：每个可能的有效解决方案都是由窗口选择和阶段选择唯一定义的。 该算法显式地评估每个这样的对，但使用前缀和将每个评估压缩为 O(1)。 由于不匹配计数对于每个配置都是准确的，因此保证找到所有配置的全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    base = "RGB"
    
    for _ in range(q):
        n, k = map(int, input().split())
        s = input().strip()

        # prefix sums for 3 phases
        pref = [[0] * (n + 1) for _ in range(3)]

        for p in range(3):
            for i, ch in enumerate(s):
                expected = base[(i + p) % 3]
                mismatch = 1 if ch != expected else 0
                pref[p][i + 1] = pref[p][i] + mismatch

        ans = k  # worst case: all mismatched

        for l in range(0, n - k + 1):
            r = l + k
            for p in range(3):
                cost = pref[p][r] - pref[p][l]
                if cost < ans:
                    ans = cost

        print(ans)

if __name__ == "__main__":
    solve()
```该实现构建了三个前缀数组，每个编码与“RGB”的一个循环移位不匹配。 重要的细节是索引：使用 (i + p) % 3 计算预期字符，以便每个阶段对应于模式的不同对齐方式。 

然后使用前缀差异在 O(1) 中提取窗口成本。 窗口和相位上的双循环是可以接受的，因为它只对每个状态执行恒定时间操作。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    def input():
        return sys.stdin.readline()

                ans = min(ans, pref[p][l + k] - pref[p][l])

 ## 边缘情况

 第一种边缘情况是整个字符串已经匹配移位的 RGB 模式但不匹配默认相位。 例如，输入 k = 3 的“GBR”。该算法正确检查所有三相，因此其中一相产生零失配。 假定固定起始阶段的解决方案将错误地报告 3 个更改。 

另一种情况是所有字符都相同，例如“BBBBB”。 没有对齐会产生很多匹配，但滑动窗口仍然很重要。 前缀数组确保每个窗口正确累积不匹配，并且仍然正确识别最小窗口成本。 

最后，当k等于1时，每个位置都是它自己的窗口。 该算法简化为检查哪个单个字符最接近正确相位位置中的 R、G 或 B 之一。 前缀方法自然地处理这个问题，无需特殊逻辑，因为每个窗口只是一个前缀差异范围。
