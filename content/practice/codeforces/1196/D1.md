 ## 解决方案
 ## 问题理解

 给定一个仅由 R、G 和 B 三个字符组成的字符串。我们希望从该字符串中找到固定长度的连续段`k`尽可能接近重复模式`RGBRGBRGB...`。 我们可以修改原始字符串中的字符，每次修改将R、G、B中的一个字符更改为另一个字符。目标是使至少一个长度-`k`子字符串完美匹配无限周期模式的某些片段，同时在原始字符串中更改尽可能少的字符。 

重要的不是整个字符串，而是是否存在长度窗口`k`可以将其转化为重复循环的完美对齐片段。 一旦我们选择了循环中的起始阶段，任何有效的目标子串就完全确定了。 该阶段只有三种可能性：从 R 开始、从 G 开始或从 B 开始。 

约束很小：每个查询都有`n ≤ 2000`，以及总和`n`跨查询也最多 2000。这会立即排除每个查询的任何立方或更差的解决方案，但允许`O(n^2)`舒适地接近。 即使是三个模式的常数因子倍数也可以。 

一个天真的错误是假设目标模式是固定的。 例如，如果我们总是比较`RGBRGB...`从 R 开始，我们错过了最佳对齐从 G 或 B 开始的情况。另一个微妙的问题是假设我们必须修改整个字符串，而不是仅修改单个长度 -`k`窗户。 最佳解决方案取决于选择最佳窗口位置以及最佳相位。 

一个简单的对齐失败案例：

 输入：```
n = 3, k = 3
s = "GBR"
```如果我们只比较`RGB`，我们需要两个改变。 但如果我们与从 G 开始的模式对齐（`GBRGBR...`），子串已经完美匹配，因此答案为 0。任何仅修复一个相位的解决方案都会错误地高估。 

## 方法

 蛮力的想法很简单：对于每个长度的子串`k`，并且对于无限模式的三个可能的起始阶段中的每一个，计算必须更改多少个字符才能完全匹配该模式。 对于每个窗口，我们计算不匹配`RGB...`,`GBR...`， 和`BRG...`，并取最小值。 

对于固定窗口，计算失配成本需要`O(k)`。 有`O(n)`窗口和 3 个模式，因此总复杂度变为`O(3nk)`每个查询，在最坏的情况下是`O(n^3)`。 和`n = 2000`，这太慢了。 

关键的观察是，一旦我们选择了一个阶段，目标模式就完全确定了。 我们可以预先计算每个位置和每个阶段的失配贡献，而不是独立地重新计算每个窗口。 然后每个长度-`k`窗口变成滑动范围内的简单求和。 

我们将问题转化为每个阶段的评估`p ∈ {0,1,2}`，不匹配数组，其中位置`i`期待性格`(RGB)[(i + p) mod 3]`。 然后我们计算每个阶段的不匹配前缀和。 每个窗口成本变成一个恒定时间范围查询。 这将问题减少到`O(3n)`每个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了 |
 | 前缀不匹配+滑动窗口| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将 R、G、B 视为一个循环中的索引 0、1、2。 

1. 将字符串中的每个字符转换为其索引形式，以便比较是数字。 这简化了循环模式检查。 
2. 对于每个阶段`p`在`{0, 1, 2}`，在整个字符串上构造一个不匹配数组。 在位置`i`，预期的字符是`(i + p) % 3`。 如果与实际字符不同，我们将成本标记为1； 否则为 0。这将模式匹配转换为数值成本问题。 
3. 在这个不匹配数组上为每个阶段构建一个前缀和数组。 前缀和允许我们计算 O(1) 中任何子字符串的不匹配计数，这至关重要，因为我们将测试许多重叠窗口。 
4. 滑动一个长度的窗口`k`穿过字符串。 对于每个起始位置`i`，计算制造成本`s[i:i+k]`使用前缀和来匹配三个阶段中的每一个阶段。 取所有阶段的最小值。 
5. 跟踪所有窗口的最小值并将其输出。 

前缀和很重要的原因是相邻窗口严重重叠，并且从头开始重新计算将重复重做相同的工作。 前缀和将重复的工作压缩为可重用的部分和。 

### 为什么它有效

 每个有效的目标子串都由两个选择唯一确定：它在字符串中的起始位置及其在重复循环中的阶段。 该算法隐式评估所有此类组合。 失配数组对每个阶段下每个位置的精确变换成本进行编码。 前缀和保留了范围聚合的正确性，因此每个窗口成本每阶段精确计算一次，没有近似或遗漏。 

因为每个可能的候选子串都会被评估，并且每个成本都会被精确计算，所以所有计算值的最小值是真正的全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    mp = {'R': 0, 'G': 1, 'B': 2}
    pattern = [0, 1, 2]

    for _ in range(q):
        n, k = map(int, input().split())
        s = input().strip()
        a = [mp[c] for c in s]

        best = 10**9

        for p in range(3):
            pref = [0] * (n + 1)

            for i in range(n):
                expected = (i + p) % 3
                pref[i + 1] = pref[i] + (a[i] != expected)

            for i in range(n - k + 1):
                cost = pref[i + k] - pref[i]
                if cost < best:
                    best = cost

        print(best)

if __name__ == "__main__":
    solve()
```该解决方案首先将字符编码为整数，以便循环比较变成算术模 3。对于每个阶段，它都会构建一个前缀和，其中每个条目都会计算到该索引的不匹配项。 然后，每个窗口成本被计算为两个前缀值的差，这避免了每次重新计算整个子字符串。 各阶段的外循环大小恒定，因此不会影响渐近复杂度。 

一个常见的实现陷阱是忘记每个阶段都需要自己的前缀数组。 重复使用一个数组会混合不兼容的不匹配定义并产生不正确的结果。

 ## 边缘情况

 对于单字符的情况，例如`s = "R", k = 1`，该算法计算每个阶段的失配。 在阶段 0，预期为 R，因此成本为 0，并且单个元素窗口上的前缀减法正确返回 0。 其他阶段的成本为 1，因此最小值正确为 0。 

对于完全统一的字符串，例如`BBBBBB`和`k = 3`，每个窗口都会针对所有三个阶段进行评估。 不匹配数组正确地计算每个位置的差异，并且前缀差异确保每个窗口成本准确反映不匹配字符的数量。 尽管所有窗口都严重重叠，但每个窗口都会通过前缀和进行独立评估，从而保持正确性而不会重复计算。
