 ## 解决方案
 ## 问题理解

 我们有几个独立的数组。 对于每一个，我们必须将其精确地切割成 k 个连续的块，其中每个块的总和为奇数。 数组顺序是固定的，因此唯一的自由是选择剪切位置。 

当子数组元素的奇偶校验加起来等于 1 模 2 时，子数组的总和为奇数。由于奇偶校验是唯一重要的事情，因此除了奇数或偶数之外，内部值不需要详细跟踪。 

输出不是片段本身，而是定义它们的剪切位置。 如果我们决定 k 个段以索引 r1, r2, ..., rk 结束，其中 rk 必须等于 n，那么我们就有效地描述了分区。 

这些约束推动每个查询的线性解决方案。 所有查询的总数组长度最多为 2 × 10^5，因此扫描每个数组一次或扫描恒定次数的任何解决方案都是可以接受的。 当 n 很大时，单个查询中的任何二次方都已经太慢了。 

关键的困难在于段和是范围的全局属性，但我们需要同时对每个段执行严格的奇偶条件。 反复尝试所有削减头寸或检查段总和的幼稚尝试很快就会变得不可行。 

一些微妙的失败案例自然会出现。 如果我们在看到奇数前缀和时贪婪地进行切割而不控制剩余的段数，那么我们可能会太早或太晚用完元素。 当奇数元素的总数不足以形成 k 个奇数和段时，即使局部贪婪选择看起来有效，也会发生另一种失败。 

## 方法

 暴力策略会尝试所有可能的方法在 n−1 个间隙中选择 k−1 个切割位置，并检查每个结果片段是否具有奇数和。 分区的数量是组合的，顺序为$\binom{n}{k}$，在最坏的情况下，它是 n 的指数。 即使验证单个分区也是线性的，因此这种方法远远超出了可行的限制。 

关键的观察来自于思考什么使线段和为奇数。 段和是奇数当且仅当它包含奇数个奇数元素时。 即使元素也不会影响奇偶校验，除非对奇偶校验贡献为零。 这将整个问题简化为跟踪数组中奇数的位置。 

如果我们固定 k 个段，则每个段必须贡献奇数个奇数。 保证这一点的最简单方法是为每个段边界结构分配一个奇数元素。 这表明我们应该使用 k−1 个奇数元素作为强制剪切锚点，因为每次剪切都必须结束一个总和为奇数的线段。 

一旦选择 k−1 个奇数元素作为前 k−1 个段的端点，最后一个段将自动包含其余元素。 为了使最后一段也具有奇数和，整个数组中奇数元素的总数必须是奇数，并且在消耗 k−1 个奇数锚点之后，剩余的后缀必须仍然包含奇数个奇数。 由于我们在 n 处结束最后一个段，这减少为要求我们总共至少有 k 个奇数，并且第 k 个选择的奇数位置必须是最后一个奇数段端点策略，该策略仍然在最终段中留下至少一个奇数元素。 

因此，该构造变得贪婪：扫描数组，收集奇数元素的索引，并使用前 k−1 个奇数索引作为分割点。 第 k 段自动在 n 结束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 贪婪的奇数锚 | 每个查询 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个查询。 

1. 扫描数组并记录所有奇数元素的位置。 这些位置代表用于形成奇数和段的所有可用奇偶校验“资源”。 
2.如果奇数元素的数量小于k，我们立即断定这是不可能的。 每个段必须至少包含一个奇数元素才能使其总和为奇数，因此我们甚至无法开始构造 k 个有效段。 
3. 如果奇数元素的数量至少为 k，我们选择前 k−1 个奇数位置作为前 k−1 个线段的端点。 每个选定的奇数索引保证以奇数结尾的段具有奇数和，因为它包含奇数个奇数元素，并且边界与奇数贡献对齐。 
4. 我们将最后一段设置为在 n 处结束。 剩余的后缀必然包含所有未使用的元素，并且因为我们从至少 k 个奇数元素开始，所以剩余的段仍然包含奇数个奇数，确保其总和为奇数。 
5. 输出收集到的切割位置。 

关键的不变量是，选择 i 个切割位置后，我们创建了 i 个段，每个段至少包含一个奇数元素，并且直到第 i 个所选奇数索引为止的前缀已被完全消耗。 这确保了每个完成的片段具有奇数总和，并且没有片段没有奇数锚点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    out = []
    
    for _ in range(q):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        odds = []
        for i, x in enumerate(a, start=1):
            if x % 2 == 1:
                odds.append(i)
        
        if len(odds) < k:
            out.append("NO")
            continue
        
        # we use first k-1 odd positions as cut points
        cuts = odds[:k-1]
        
        # last cut must be n
        cuts.append(n)
        
        out.append("YES")
        out.append(" ".join(map(str, cuts)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```代码直接实现了贪心思想。 名单`odds`存储所有奇值元素的索引。 可行性检查`len(odds) < k`强制执行每个段必须至少包含一个奇数元素的最低要求。 

通过取前 k−1 个奇数索引来形成切割列表。 附加 n 可确保输出格式所需的最终段边界条件。 

一个微妙的点是我们没有明确验证每个段的总和。 这是不必要的，因为保证每个段在其端点处恰好包含选定的奇数锚点之一，这迫使段和奇偶校验为奇数。 

## 工作示例

 ### 示例 1

 输入：```
5 3
7 18 3 14 1
```奇数位置是 1、3、5。 

我们需要 k = 3 个段，因此我们首先采用 k−1 = 2 个奇数位置。 

| 步骤| 赔率收集 | 精选剪裁| 形成的段 |
 | --- | --- | --- | --- |
 | 扫描| [1,3,5]| []| - |
 | 选择 | [1,3,5]| [1, 3] | [1]、[2,3]、[4..5] |

 最终输出是`1 3 5`。 

该迹线显示每个段边界与奇数元素对齐，确保每个段包含奇奇偶校验贡献。 

### 示例 2

 输入：```
6 2
1 2 8 4 10 2
```奇数位置是[1]。 

我们需要 k = 2，但只有一个奇数元素。 

| 步骤| 赔率收集 | 可行|
 | --- | --- | --- |
 | 扫描| [1] | 没有|

 由于我们无法为每个段分配至少一个奇数元素，因此答案是否定的。 

这表明了可行性约束而不是施工约束。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q = int(input())
    res = []
    for _ in range(q):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        odds = [i+1 for i,x in enumerate(a) if x % 2 == 1]

            res.append("NO")

 ## 边缘情况

 当所有元素都是偶数时，就会出现一种边缘情况。 例如`a = [2,4,6]`任意 k ≥ 1。每个段总和都是偶数，因此不存在有效分区。 该算法正确地检测到了这一点，因为奇数索引列表为空，立即失败`len(odds) < k`健康）状况。 

另一种边缘情况是 k 等于奇数元素的数量。 例如`a = [1,2,3]`, k = 2。奇数位置为 [1,3]。 该算法选择在 1 处进行切割并在 3 处进行最终切割，从而生成片段`[1]`和`[2,3]`，两者的总和均为奇数。 这证实了使用前 k−1 个奇数位置可以自然地对齐段，而不需要任何回溯或调整。
