 ## 解决方案
 ## 问题理解

 在这个问题中，我们被要求计算在给定层数的情况下在网格上绘制的星形图案中的单元总数。 输入是单个整数`a`，代表恒星中同心层的数量。 输出是一个整数，它是如果我们绘制所有单元格将被着色的单元格总数`a`星星的层数。 

恒星的每一层都对称地增加其尺寸，因此细胞数量按照一个简单的组合公式增长。 第一层是中心的单个细胞。 第二层在其周围添加单元，形成十字形图案和角，并且每个后续层都添加更多遵循相同对称结构的单元。 

约束条件告诉我们`a`可以达到 18257。考虑到输出可以达到 2·10⁹，这意味着任何逐层填充网格的简单模拟都会太慢并且占用内存。 我们需要一个封闭式的单元格数量公式来有效地处理最大输入。 

边缘情况是当`a = 1`。 正确的输出是 1，因为仅存在中心单元。 假设至少有两层或使用公式而不显式处理第一层的粗心方法会产生不正确的结果。 

## 方法

 蛮力方法将尝试显式地模拟绘制恒星的每一层，并对添加的每个单元进行计数。 第一层加1，第二层加12，第三层加24，以此类推。 虽然这在概念上是正确的，但它需要迭代每一层和层中的每个单元。 和`a = 18257`，细胞总数的增长大致如下`6*a^2 + 6*a + 1`，这大约是最大的 2·10⁹ 操作`a`。 如果我们尝试存储网格，这太慢并且超出了内存限制。 

关键的见解是识别细胞数量的模式。 细胞总数的序列是二次序列：第一层为1，第二层为13，第三层为37，依此类推。 通过检查层之间的差异，我们注意到每个新层都会添加`12 * (layer - 1)`细胞。 这导致了一个封闭的细胞总数公式`a`层：`1 + 6*a*(a-1)`。 

蛮力方法适用于小型`a`因为我们可以安全地模拟每一层，但总体上会失败`a`由于二次增长。 通过观察序列是二次的，我们可以在常数时间内直接计算结果，而无需迭代。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(a²) | O(a²) | 对于最大输入来说太慢 |
 | 闭式公式 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取整数`a`来自输入。 这代表了恒星的层数。 
2. 使用封闭公式计算单元格总数`1 + 6*a*(a-1)`。 这个公式是通过观察每层得出的`i`（在哪里`i ≥ 2`）添加`12*(i-1)`细胞，并将它们相加得到二次表达式。 
3. 打印计算出的总数。 

这样做的原因是该公式正确地捕获了单元格添加的模式。 第一层贡献 1。每个后续层比前一层总共添加 12 个单元格，产生差值序列 12、24、36 等，其总和为二次公式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = int(input())
result = 1 + 6 * a * (a - 1)
print(result)
```解决方案读取单个整数`a`，使用派生公式计算单元格总数，并打印它。 该公式仅使用整数运算，因此不存在浮点问题。 我们乘以`6*a*(a-1)`首先，这可以避免整数溢出，因为 Python 会自动处理大整数。

 ## 边缘情况

 对于`a = 1`，该公式计算为`1 + 6*1*(1-1) = 1`。 该算法无需特殊处理即可正确输出 1。 对于大输入，例如`a = 18257`，公式计算`1 + 6*18257*18256`直接进行，避免任何迭代或内存密集型模拟。 所有中间产品都保持在 Python 的整数范围内。 这保证了整个输入范围的正确结果。
