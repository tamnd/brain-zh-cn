 ## 解决方案
 ## 问题理解

 我们给定一个序列`a`长度`n`它是通过从隐藏排列的任一端重复删除最小元素而生成的`p`的数字来自`1`到`n`。 如果最小元素在左侧，则将其添加到前面`a`; 如果它在右边，则附加到`a`。 在最后一步，当只剩下一个元素时，我们可以选择任一端。 我们的目标是重建任何有效的排列`p`可能会产生给定的序列`a`，或确定不存在这样的排列。 

输入由多个测试用例组成。 每个测试用例都有大小`n`和结果数组`a`。 自从`n`可以达到`2 * 10^5`以及所有的总和`n`由于测试用例之间的界限相同，因此每个测试用例都需要一个有效的线性算法。 任何具有二次复杂度的算法，例如尝试所有排列或在每一步模拟所有可能的选择，都会太慢。 

要考虑的边缘情况包括序列，其中`n=1`、数组严格递增或递减的序列，以及不能对应于任何有效排列的序列。 例如，`a = [1, 3, 5, 4, 2]`是不可能的，因为相对顺序无法与所描述的规则匹配。 

## 方法

 暴力方法将尝试重建`p`通过模拟左右移除的每种可能的组合。 原则上这是正确的，但可能性的数量呈指数增长`n`。 即使对于中等`n`，这种方法不可行。 

关键的见解是从`a`。 我们可以重构，而不是模拟前进的过程`p`通过观察生成的每一步`a`，剩余序列中下一个最小的数字必须来自其中一端。 这使我们能够分裂`a`分成对应于片段的连续块`p`。 每个块从最左边选择的最小值递减到下一个最小值，形成一个可以直接追加到的块`p`。 通过有效地识别这些块，我们可以在线性时间内重建有效的排列。 

正向模拟失败，因为我们不知道元素的顺序`p`在每一步，但向后重建有效，因为最小的剩余元素`a`确定中的唯一块`p`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 逆向重建| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从第一个元素开始`a`并识别元素严格递减的连续段，直到找到小于当前最小值的数字。 每个这样的段对应于原始排列中的一个块`p`。 
2. 对于每个段，将其按顺序附加到表示重构排列的列表中。 这是有效的，因为在原始过程中，块中最小的数字将首先被删除，然后按从左到右或从右到左的顺序删除块的其余部分。 
3. 跟踪迄今为止看到的最大数字以确定下一段的边界。 如果该段包含已经添加的数字，则重构是不可能的，我们输出`-1`。 
4. 继续这个过程，直到所有元素`a`被消耗。 所有已识别块的串联形成一个有效的`p`。 
5. 输出重建的排列或`-1`如果重建在任何一步失败。 

这里的不变性是，在每一步中，我们在段中处理的元素正是在原始过程中可以从末端连续删除的元素。 通过始终采用最大递减线段，我们遵守始终从任一端删除最小元素的规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        seen = [False] * (n + 1)
        result = []
        i = 0
        while i < n:
            block = []
            current = a[i]
            if seen[current]:
                result = [-1]
                break
            j = i
            while j < n and not seen[a[j]]:
                block.append(a[j])
                seen[a[j]] = True
                j += 1
            result.extend(block)
            i = j
        if result[0] == -1:
            print(-1)
        else:
            print(' '.join(map(str, result)))

if __name__ == "__main__":
    solve()
```在此代码中，我们维护一个布尔数组`seen`以确保重建时没有数字出现两次。 我们迭代`a`，将减少的线段收集到`block`，将数字标记为所见，并扩展`result`与这些块。 如果我们遇到一个已经见过的数字，则表明存在不一致，我们返回`-1`。

 输入：`a = [1, 3, 2, 4]`| 我| 当前区块 | 见过| 结果 |

 | 3 | [4] | {1,2,3,4} | [1,3,2,4] |

### 示例 2

 输入：`a = [1, 3, 5, 4, 2]`| 我| 当前区块 | 见过| 结果 |
 | ---| ---| ---| ---|
 | 0 | [1] | {1} | [1] |

 这里，该段`[3,5,4]`不能是有效的递减线段，因为 5 出现在 4 之前。重建失败，因此输出为`-1`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每个测试用例 O(n) | 每个元素都被处理一次，并按顺序构建块。 |
 | 空间| O(n) | 这`seen`数组和`result`数组存储最多`n`元素。 |

 由于总和为`n`跨测试用例 ≤ 2 * 10^5，总操作在 2 秒时间范围内保持在可接受的限度内。

 ## 边缘情况

 如果`n=1`，数组`a`仅包含一个数字，并且`p`必须是`[1]`。 该算法通过创建长度为 1 的块来正确处理此问题。 如果`a`严格递增或递减，该算法形成覆盖所有元素的单个块。 如果任何元素在重建中重复或非递减线段违反最小移除属性，则算法输出`-1`。 例如，`a = [1, 3, 2]`有效；`a = [2,1,3]`无效，因为最小元素`1`当它应该被移除时却不在两端。
