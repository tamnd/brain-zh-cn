 ## 解决方案
 ## 问题理解

 我们有两组学生：程序员和数学家。 我们希望将这些学生组成尽可能多的团队，每个团队恰好包含 4 名学生。 

有效团队存在结构性限制：只有包含至少一名程序员和至少一名数学家的团队才是可接受的。 这立即禁止完全由一种类型组成的“纯”团队，即使它们仍然满足规模要求。 

任务是最大化不相交的有效团队的数量。 每个学生最多只能使用一次，因此一旦一个人被分配到一个团队中，他们就无法为另一个团队做出贡献。 

输入规模很大，测试用例最多为10^4个，a和b的值最多为10^9。 这排除了任何迭代可能的团队或个人的模拟。 任何方法都必须将每个测试用例的推理简化为 O(1)。 

当一组非常小时，就会出现一种幼稚但重要的边缘情况。 例如，如果 a = 10 且 b = 1，即使学生总数为 11，我们也无法组建一个需要这两种类型数量的有效团队。 像 Floor((a + b) / 4) 这样粗心的方法会错误地输出 2，忽略了组成约束。 

另一种边缘情况是当一个群体极其占主导地位时。 如果 a = 100 且 b = 1，我们仍然无法组建多个团队，因为在使用单个数学家后，无法组建更多有效团队。 

关键的困难是同时平衡两个约束：团队规模是固定的，但组成要求每组至少有一个人。 

## 方法

 思考这个问题的一种蛮力方法是尝试一个接一个地组建团队。 在每一步中，我们挑选 4 名学生并检查团队是否包含这两种类型。 如果没有，我们放弃该选择并尝试另一个分组。 这很快就变得不可行，因为即使决定选择 4 中的哪个子集也是组合性的，并且每个类别最多有 10^9 个学生，状态空间是巨大的。 

一种更结构化的暴力方法是模拟贪婪构造：重复采用 1 个程序员和 3 个数学家或 2 和 2 或所有有效的分割，以可能的为准，直到我们无法形成团队。 这仍然存在每个步骤探索多种组合的风险，并且会退化为学生数量的线性时间，考虑到最多 10^4 个测试用例以及每个测试用例可能有 10^9 个元素，这太慢了。 

关键的观察结果是，每个团队恰好需要 4 名学生，并且每个团队必须至少需要一名程序员和至少一名数学家。 这意味着每个团队将 a 和 b 至少减少 1。因此团队数量以 min(a, b) 为界。 同时，学生总数将团队限制为 (a + b) // 4。 

这两个约束是独立的，并且必须同时成立。 因此，团队的最大数量受到更严格的限制：要么我们用完一个类别，要么我们以四人为一组用完所有学生。 

问题归结为选择这两个瓶颈中的最小值。

 | 暴力模拟| 每次测试 O(a + b) | O(1) | O(1) | 太慢了 |
 | 直接配方| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 对于每个测试用例，读取值 a 和 b。 这些代表每种类型的学生数量。 
2. 计算纯粹受学生总数限制的最大团队数量为 (a + b) // 4. 假设每个团队始终只使用四个人，无论类型分布如何。 
3. 计算较小组限制的最大团队数量为 min(a, b)。 每个团队必须至少包含一名来自每个类别的学生，因此在组成 k 个团队后，a 和 b 仍必须至少减少 k。 
4. 最终答案是这两个值中较小的一个，因为必须同时满足两个约束。 

### 为什么它有效

 每个有效团队至少需要一名程序员和至少一名数学家，因此在组建 k 个团队后，我们必须有 k ≤ a 且 k ≤ b，这意味着 k ≤ min(a, b)。 独立地，每个团队恰好有 4 个学生，因此 k 个团队需要 4k ≤ a + b，这意味着 k ≤ (a + b) // 4。任何有效的构造都必须尊重两个不等式，因此真正的最大值是它们之间最紧的界限。 因为这两个界限都可以通过组合来实现（只要双方都有足够的供应，就可以适当地混合团队组成），因此两者中的最小值就是准确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        print(min(min(a, b), (a + b) // 4))

if __name__ == "__main__":
    solve()
```该代码在恒定时间内独立处理每个测试用例。 表达式 min(a, b) 满足每个团队必须包含这两种类型的要求。 表达式 (a + b) // 4 捕获每个团队的固定规模约束。 

一个微妙的点是我们从不明确地构建团队。 推理完全依赖于全局资源限制，这避免了任何排序或贪婪的陷阱。

 ## 边缘情况

 对于 a = 0 和 b = 10，公式给出 min(min(0, 10), 10 // 4) = 0。该算法正确返回 0，因为没有团队可以满足至少拥有一名程序员的要求。 

对于 a = 4 和 b = 0，我们再次得到 0。即使总大小恰好为 4，但缺少第二种类型会阻止形成任何有效的团队，这表明仅总可分性是不够的。 

对于高度不平衡的情况，如 a = 1000000000 和 b = 1，结果变为 1。计算 (a + b) // 4 会建议一个很大的数字，但 min(a, b) 约束正确地将其上限为 1，这反映出在用尽所需的多样性之前，只有一个有效的混合团队是可能的。
