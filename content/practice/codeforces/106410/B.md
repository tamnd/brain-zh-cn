 ## 解决方案
 ## 问题理解

 我们得到了几个字符串。 对于每个字符串，我们可以重复交换两个相邻的字符。 问题是这些交换是否可以将字符串转换为两个相同的连续部分。 也就是说，将字符按照任意顺序重新排列后，最终的字符串是否可以是这样的`t + t`对于一些字符串`t`？ 

输入包含多个测试用例。 每个测试用例都是一个小写字符串，该字符串的输出为`YES`当这种重排存在时，否则`NO`。 

关键约束是所有字符串的总长度，最多为`2 * 10^5`。 这意味着我们可以提供一种扫描每个字符固定次数的解决方案。 任何尝试许多可能的重新排列或模拟交换的方法都是不可能的，因为即使是单个长度的字符串`200000`有大量可能的排列。 

不明显的部分是了解相邻交换允许什么。 相邻交换可以自由移动角色，但不能创建或删除任何角色。 唯一重要的是原始字符串中每个字母的计数。 

一个幼稚的实现可能只检查长度是否是偶数。 例如：```
1
aabbc
```长度是5，所以它立即失败，但是当长度是偶数时，会出现更有趣的错误：```
1
aabbcdef
```粗心的解决方案可能只是将字符串分成两半，然后在排序后比较两半。 但是，可用的字符有`a, a, b, b, c, d, e, f`。 字母`c`,`d`,`e`， 和`f`出现一次，因此他们不能在两半场属于同一位置。 正确的输出是：```
NO
```另一个边缘情况是单个字符：```
1
a
```没有办法将长度为 1 的字符串分成两等份，所以答案是：```
NO
```相反的边缘情况是一个字符串，其中每个字符都已经有一个匹配的副本：```
1
abba
```我们可以将其重新排列成`ba + ba`，所以正确的输出是：```
YES
```## 方法

 思考这个问题的强力方法是尝试对字符串进行所有可能的重新排列，并检查它们是否具有以下形式`t + t`。 这是正确的，因为相邻交换可以产生字符的任何排列。 然而，一个长度的字符串`n`最多可以有`n!`不同的排列，即使对于非常小的值也是不可能的`n`。 

重要的观察是我们实际上不需要知道最终的安排。 如果最终的字符串是`t + t`，那么每个字符在前半部分出现两次，在后半部分出现两次，并且位置完全相同。 这意味着整个字符串中的每个字符必须出现偶数次。 

反方向也是如此。 如果每个字符出现偶数次，我们可以将每个字符的一半放入前半部分，将另一半放入后半部分。 由于相邻交换允许任意重新排列，因此这种结构始终是可达的。 

问题从搜索排列减少到计算频率。 我们只需要验证每个频率是否能被二整除。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算每个小写字母在字符串中出现的次数。 最终的排列只能使用现有的字符，因此这些计数包含所有必要的信息。 
2. 检查每个字符数。 如果某个字符出现奇数次，则答案为`NO`。 奇数金额不能在两份副本之间平分`t`。 
3. 如果所有字符数都是偶数，则输出`YES`。 每个字符可以分为两个相等的组，每个组代表最终字符串的一半。 

为什么它有效：不变的是相邻的交换保留了每个字符的频率。 形式的字符串`t + t`要求每个字符出现偶数次，因为它的出现次数均等地分为两个相同的一半。 如果所有计数都是偶数，我们可以通过在每一边取每个字符出现次数的一半来构造两半。 由于使用相邻交换可以实现任何排列，因此始终可以达到所需的形式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()
        freq = [0] * 26

        for ch in s:
            freq[ord(ch) - ord('a')] += 1

        ok = True
        for count in freq:
            if count % 2:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案读取测试用例的数量并独立处理每个字符串。 频率数组对于每个小写字母都有一个槽，因此更新每个字符需要恒定的时间。 

最后一个循环检查能否被二整除。 不需要构建重新排列的字符串，因为这种重新排列的存在仅取决于字符计数。 

该实现避免了对字符原始顺序的任何假设。 一个常见的错误是比较输入字符串的前半部分和后半部分，但允许的交换意味着输入顺序没有特殊含义。

 ## 边缘情况

 对于单字符的情况：```
1
a
```的频率`a`是一。 该算法检测到一半无法接收与另一半相同的字符，因此输出`NO`。 

对于具有奇数频率字符的偶数长度字符串：```
1
aabbcdef
```的计数为`c`,`d`,`e`， 和`f`都是一。 该算法拒绝该字符串，因为这些字符无法拆分为两个相同的两半。 

对于已经满足条件的字符串：```
1
abba
```的计数为`a`和`b`都是两个。 该算法接受它，即使它从未构建最终的排列。 可能的最终安排是`ba + ba`。 

对于较大的有效输入：```
1
abababab...
```在哪里`ab`重复多次，该算法仅执行一次字符计数和一次常量大小检查。 它不取决于可能的交换或安排的数量。
