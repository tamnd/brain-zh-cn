 ## 解决方案
 ## 问题理解

 我们给出一个无向图，其中每条边连接两个不同的顶点，并且没有重复的边。 任务是找到四个不同的顶点，使连续的对形成边：第一个连接到第二个，第二个连接到第三个，第三个连接到第四个。 换句话说，我们正在寻找仅由三个边组成的任何简单路径。 

输出要么是沿着路径按顺序排列的这样的四元组顶点，要么是不存在这样的结构的声明。 

该图可能很大，最多有二十万个顶点和三十万个边。 这个大小排除了任何试图简单地枚举所有顶点四元甚至所有长度三游走的方法。 对所有边三元组的强力攻击已经远远超出了允许的时间，因为即使迭代每个顶点周围的所有邻接对也会在密集区域中退化为二次行为。 

一个关键的限制是我们只需要找到一条有效路径。 这将问题从计数或验证全局结构转移到有效地检测局部配置。 

一些边缘情况暴露了粗心的逻辑失败的地方。 

如果图的边少于 3 条，则答案始终为 -1，因为长度为 3 条边的路径需要至少有 4 个按顺序连接的顶点。 例如，使用输入```
4 1
1 2
```正确的输出是-1。 

更微妙的情况是图有很多边但结构像星形。 例如，一个中心节点连接了许多叶子。 即使有数百条边，也不存在叶子到叶子的连接，因此不存在长度为 3 的路径。 任何假设“许多边意味着长路径”的方法在这里都会失败。 

另一个边缘情况是当路径存在但天真的遍历重新访问顶点时，意外地产生了步行而不是简单的路径。 例如，在一个附加了额外节点的三角形中，DFS 可能会循环遍历该三角形并错误地返回重复的顶点，除非我们明确强制执行不同性。 

## 方法

 直接的蛮力想法是处理每个有序的三边边$(a,b), (b,c), (c,d)$并检查所有端点是否不同。 人们可以尝试迭代每个顶点$b$，然后超过邻居$a$和$c$，然后进一步延伸$c$。 这在概念上是有效的，因为每个有效答案都必须以某个中间边缘为中心$b \to c$，但在最坏的情况下，幼稚的实现将扩展到对度数的立方进行粗略求和。 在稠密图中，它退化为$O(n^3)$，这是不可行的。 

关键的观察是我们需要的结构是极其局部的：我们只关心以某个边缘为中心的长度为 2 的路径$b-c$，然后从任一侧再进行一次扩展。 我们可以修复中间边缘并尝试向外扩展，而不是探索任意三元组。 这减少了检查边缘局部邻域的问题。 

进一步的简化来自于我们意识到我们不需要尝试所有邻居组合。 如果我们修复一个边缘$b-c$，那么任何扩展它的有效解决方案都必须选择$a$来自邻居的$b$排除$c$， 和$d$来自邻居的$c$排除$b$。 存在检查变成了检测任一端点是否至少有一个尚未在路径中使用的“新鲜”邻居的问题。 如果双方都可以延伸，我们立即得到一条有效路径。 

这提出了一种线性时间策略：迭代边缘并测试它们是否可以充当路径的中间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解三倍 |$O(n^3)$|$O(n + m)$| 太慢了|
 | Edge-centered extension check |$O(n + m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 1. 为图构建邻接表。 这允许快速查找每个顶点的邻居，这是必要的，因为我们将重复检查本地邻居。 
2.迭代每条边$(b, c)$。 将此边缘视为所需路径的潜在中间段。 
3. 对于每个这样的边，扫描其邻居$b$并选择任意顶点$a$那不等于$c$。 这确保了$a \neq c$并在此阶段保持清晰度。 
4. 同样，扫描邻居$c$并选择任意顶点$d$那不等于$b$。 
5. 如果两个这样的顶点都存在，我们就找到了一个有效的结构$a-b-c-d$。 立即输出。 
6. 如果没有边产生这样的扩展，则输出-1。 

这个过程足够的原因是任何有效的长度为 3 的简单路径必须有一个中间边缘$b-c$。 一旦识别出该边，路径的端点必须位于$b$和$c$，不包括对边的内部顶点。 因此，检查所有边可以保证我们不会错过任何有效的配置。 

正确性取决于这样一个事实：任何长度为 3 的简单路径都具有唯一的中间边缘，并且该边缘完全确定端点的存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]

edges = []
for _ in range(m):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)
    edges.append((u, v))

for b, c in edges:
    a = -1
    d = -1

    for x in adj[b]:
        if x != c:
            a = x
            break

    if a == -1:
        continue

    for x in adj[c]:
        if x != b:
            d = x
            break

    if d == -1:
        continue

    print(a)
    print(b)
    print(c)
    print(d)
    sys.exit()

print(-1)
```该实现依赖于邻接列表来实现对邻居的恒定时间迭代。 对于每条边，我们只会扫描直到在每条边上找到有效的扩展，因此一旦找到候选，我们就不会不必要地遍历完整的度列表。 

一个微妙的细节是我们必须确保所有四个顶点都是不同的。 支票`x != c`和`x != b`就足够了，因为图没有自环或多边，因此除了相反端点之外的任何邻居都保证了路径上的独特性。 

我们还单独存储边以保留对实际边的迭代，而不是从邻接列表中重建对，这避免了冗余检查。 

## 工作示例

 ### 示例 1

 输入：```
4 1
3 4
```仅存在一条边，因此没有一条边可以作为 3 边路径的中间。 

| 边 (b, c) | 发现| d 发现 | 结果 |
 | --- | --- | --- | --- |
 | (3,4) | 无 | 无 | 失败|

 输出：```
-1
```这证实了单边图不能支持长度为 3 的路径。 

### 示例 2

 输入：```
6 7
1 3
1 5
2 3
2 5
2 6
4 5
4 6
```考虑边 (5,2)。 从 5 中我们可以取 1 作为排除 2 的邻居，从 2 中我们可以取 3。 

| 边 (b, c) | a 来自 b | d 从 c | 结果 |
 | --- | --- | --- | --- |
 | (5,2) | 1 | 3 | 成功|

 我们输出：```
1
5
2
3
```这形成了有效路径1-5-2-3。 

跟踪显示我们只需要围绕一条边成功延伸一次，就可以立即停止。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        edges.append((u, v))

    for b, c in edges:
        a = -1
        d = -1
        for x in adj[b]:
            if x != c:
                a = x
                break
        if a == -1:
            continue
        for x in adj[c]:
            if x != b:
                d = x
                break
        if d == -1:
            continue
        return f"{a}\n{b}\n{c}\n{d}\n"

    return "-1\n"

 ## 边缘情况

 星形图说明了为什么仅仅拥有许多边并不意味着解决方案。 当所有边共享一个中心时，每条边都不满足扩展条件，因为一个端点除了中心之外没有邻居。 

纯路径图演示了相反的情况，其中只有一小部分边符合中间段的条件。 该算法正确地找到两个端点都有空闲邻居的内部边缘。 

具有循环的图仍然表现正常，因为任何长度至少为 4 的循环都包含长度为 3 的有效子路径，并且在迭代边缘时将检测到该子路径的中间边缘。
