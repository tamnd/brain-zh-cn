 ## 解决方案
 ## 问题理解

 我们得到一长排由二进制字符串表示的通信塔。 每个角色沿着一条线依次对应一座塔。 一个`1`表示塔位于干燥的地面上，无论是在海岸上还是在岛屿上，而`0`意味着这座塔坐落在危险的氰化物河内。 

目标是认证所有塔。 塔楼标记`1`很简单：可以在零天立即获得认证。 塔楼标记`0`更难：每个这样的塔需要一整天的时间来进行认证，并且只有在其至少一个近邻已经至少提前一天获得认证的情况下才能对其进行处理。 只要遵守依赖性规则，多个塔可以在同一天内并行处理。 

任务是确定每座塔获得认证所需的最短天数。 

字符串最多可包含 300,000 个字符的限制意味着任何数天内的二次模拟或每天重复扫描整个数组都是不可能的。 一个$O(n^2)$传播需要的顺序是$9 \times 10^{10}$最坏情况下的操作，远远超出了实际极限。 这促使我们采用线性或近线性方法，通过一两次传递来计算答案。 

一个微妙的问题是，传播取决于邻居，而邻居本身可能会在以后获得认证。 仅从原始版本扩展的简单模拟`1`除非精心设计，否则每天一步是不够的，因为新认证的职位也会成为未来传播的来源。 

当字符串有很长的运行时，就会出现边缘情况`0`s。 例如，考虑：

 输入：`100001`预期输出：取决于链上的传播速度。 

另一个边缘情况是单个块：

 输入：`101`这里是中间的`0`紧邻经过认证的塔楼，因此在第一天即可获得认证。 

一个更微妙的情况是一长段由 1 包围的 0：

 输入：`1000001`答案取决于两端的影响需要传播多远并在中间相遇。 

一种幼稚的方法，仅从一侧进行处理或假设从初始状态独立传播`1`不考虑同时扩张的情况会错误计算长期零运行中的中心位置。 

## 方法

 蛮力解释明确地模拟了日子。 我们维护哪些塔经过认证，并重复扫描阵列。 每天，任何未经认证的`0`前一天至少有一个经过认证的邻居的塔楼将获得认证。 我们重复直到所有塔都通过认证。 

这是正确的，因为它直接反映了规则。 然而，每天可能需要对字符串进行全面扫描，并且在最坏的情况下是长度为零的链$n$需要$O(n)$天。 这导致$O(n^2)$总操作，这对于$n = 300000$。 

关键的观察结果是，认证时间仅取决于距最近的已认证塔的距离。 每一个`1`从时间零开始。 一个`0`只能在其最近的机构之后获得认证`1`已经通过中间传播`0`s。 由于传播是对称地向外传播并且独立于所有`1`也就是说，问题归结为计算每个位置距离最近的位置有多远`1`以尊重以下事实的方式`1`s 从一开始就处于活动状态。 

这将过程转化为一条线上的最短距离问题：每个位置花费的时间等于其到最近位置的距离`1`，但有这样的约束`1`s 本身是零时间源。 答案是这些距离中的最大值。 

我们可以通过两次线性传递来计算这一点：一次从左到右跟踪最后看到的`1`，以及从右到左一个。 每个`0`获取到 a 的最小距离`1`两侧。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 两次通过距离计算 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将这个过程重新解释为计算每个塔必须等待多长时间才能获得认证。 

1.初始化一个数组`dist`其中每个位置将存储该塔变得可认证所需的最小天数。 我们首先将所有位置视为距离 a 无限远`1`。 
2.从左向右扫，同时保持最新的索引`1`。 当我们遇到一个`1`，我们重置跟踪器。 当我们遇到一个`0`，我们测量它与最后一次看到的距离`1`在左侧。 这给出了左侧传播何时能够到达的候选时间。 
3.同样从右向左扫动，追踪最近的`1`在右侧。 对于每个`0`，我们计算它到最近的距离`1`并通过取最小值将其与先前计算的左侧距离相结合。 
4. 对于每个位置，最终值表示在给定两个传播方向的情况下该塔获得认证的速度。 
5. 最终答案是所有位置的最大值，因为我们必须等到最慢的塔获得认证。 

这样做的原因是每个`1`充当时间零时的同步认证源。 传播约束允许信息每天向外流动一步，因此折线图上最短路径意义上的最近源有效地到达了每个位置。 无论方向如何，采用两个方向可确保我们捕获最近的源，而采用最大值可确保全局完成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

INF = 10**18
left_dist = [INF] * n

last = -1
for i in range(n):
    if s[i] == '1':
        last = i
        left_dist[i] = 0
    else:
        if last != -1:
            left_dist[i] = i - last

right_dist = [INF] * n
last = -1
for i in range(n - 1, -1, -1):
    if s[i] == '1':
        last = i
        right_dist[i] = 0
    else:
        if last != -1:
            right_dist[i] = last - i

ans = 0
for i in range(n):
    d = min(left_dist[i], right_dist[i])
    ans = max(ans, d)

print(ans)
```第一遍计算每个位置距最近的位置有多远`1`在它的左边。 第一个之前的位置`1`仅从左侧仍然无法有效到达。 第二遍从右侧开始执行相同的操作。 

组合步骤需要最少的时间，因为塔可以从任意一侧进行认证。 最终的最大值选择最慢的塔，这决定了总的完成时间。 

一个常见的错误是忘记传播可以来自两个方向。 另一种是仅治疗初始`1`s 作为源，但忽略距离是对称的，这导致在不对称布局中高估时间。

 ## 边缘情况

 一个重要的边缘情况是只有一个`1`例如，在字符串的一端`100000`。 从左到右的传递使距离从 0 增加到 5，而从右到左的传递不能改善任何东西。 该算法正确返回 5，因为最远的塔仅依赖于一个源。 

另一种边缘情况是，除了孤立的零点之外，没有内部零点，例如`1110111`。 中间的零到两边的距离都是1，所以一天就被认证了，答案就变成了1。 

第三种边缘情况是完全交替的模式，例如`1010101`。 每个零都与一个一相邻，因此每个零都在一天内得到认证。 所有位置的最大值为 1，符合不需要传播超过一步的事实。
