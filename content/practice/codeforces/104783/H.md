 ## 解决方案
 ## 问题理解

 我们得到了一系列排列在一条直线上的露台高度。 每个位置代表一个固定宽度一的露台，并且相邻位置在空间上实际上是连续的。 

我们想在选定的两对露台之间建造桥梁。 仅当两个端点具有相同的高度时，才允许在两个索引之间建立桥，并且它们之间的每个露台的高度严格小于共享端点的高度。 如果该条件成立，则桥横跨这两个位置之间的整个水平距离，并且贡献的长度等于索引之间的距离。 

目标是选择任何有效桥的集合，以便不违反任何限制并且使所有桥长度的总和最大化。 

约束 N 高达 3 · 10^5 立即排除任何检查所有索引对的解决方案。 简单的 O(N^2) 方法会尝试验证每一对，甚至稍微改进的在对之间扫描的方法在最坏的情况下也会降级为 O(N^3)。 预期的解决方案必须接近线性或线性算数。 

一个关键的结构观察是，每个有效的桥完全由两个相同高度的出现来定义，其有效性仅取决于之间是否存在更高或相等的阻塞元素。 这表明问题本质上是关于在中间最大值施加的单调性约束下配对相等值的出现。 

一些边缘情况很容易被忽略。 

如果所有高度都严格增加，则不存在有效的桥，因为永远不会出现任何两个相等的高度，因此答案为零。 

如果所有高度都相等，则每对在技术上都符合端点条件，但每个内部元素并不严格小于端点，因为它等于端点，因此没有桥有效，答案再次为零。 

如果我们有像 5 1 5 1 5 这样的模式，朴素配对可能会尝试连接较远的端点，但中间等高出现和有关中间最大值的规则迫使仔细选择不相交的有效对。 

这些案例表明，困难不在于计算相等的对，而在于执行由“阻塞”高度引起的全局结构。 

## 方法

 强力解释是考虑每对索引 i < j 使得 ai = aj。 对于每个这样的对，我们扫描段 (i, j) 以计算其最大值。 如果该最大值严格小于 ai，我们认为该桥有效，其贡献为 j − i。 对所有有效对求和并获取它们的最佳兼容子集已经是一个组合优化问题。 

即使仅进行可行性检查，每对的成本也为 O(N)。 在所有值都相等的最坏情况下，存在 θ(N^2) 对，使得这个 O(N^3) 远远超出了限制。 

关键的见解是停止以任意对的方式思考，而是思考一个值如何一次最多参与一个“活跃的外部结构”。 如果我们按降序处理高度，我们可以将较高的值视为将线切割成独立线段的障碍。 在每个段中，只有较低的值很重要，一旦处理了一个值，它的行为就像一个潜在的端点，其内部必须已经相对于较高的障碍得到解决。 

这导致单调的堆栈解释。 每个高度在我们遇到它的那一刻开始或结束一个跨度，并且只要在考虑了更高的障碍物之后它们是最接近的可用兼容对，我们就可以贪婪地匹配相同高度的出现。

问题归结为为每个高度维护一堆索引。 当我们再次看到相同的高度时，我们尝试将其与最近未匹配的高度进行匹配。 “所有之间都较低”的有效性条件自然会被强制执行，因为任何较高或相同的干扰元素都已经通过按处理顺序较早地划分结构来阻止这种配对。

 | --- | --- | --- | --- |
 | 蛮力 | O(N^3) | O(N^3) | O(1) | O(1) | 太慢了|
 | 每个高度的单调堆叠 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时为每个不同的高度维护一个堆栈（或向量）。 每个堆栈存储尚未匹配的该高度的索引。 

1. 初始化一个按高度索引的堆栈数组。 
2. 从 1 到 N 迭代位置 i。对于当前高度 h = a[i]，我们检查是否存在不匹配的先前出现的 h。 
3. 如果 h 的堆栈非空，我们弹出它的最后一个索引 j。 然后我们将贡献 i − j 添加到答案中。 这对应于在最近未匹配的相同高度和当前位置之间形成桥梁。 

我们总是与最近发生的事件配对的原因是，任何较早发生的事件都会产生更长的跨度，可能会不必要地跨越障碍并阻止未来的最佳配对。 

1. 如果 h 的堆栈为空，则将 i 压入堆栈。 这将此次事件标记为等待未来的匹配。 
2. 继续直到数组末尾。 

为什么这是有效的，因为任何有效的桥都必须连接两个相等的高度，并且没有高度≥ h 的中间元素。 如果存在这样的中间元素，它就已经“分离”了结构：要么完全阻止配对，要么强制配对发生在较小的部分内。 

通过从左到右处理和贪婪匹配，我们确保只连接当前位于相对于高度 h 的相同“活动可见性段”中的索引。 h 的每个堆栈隐式表示当前最大段中不匹配的端点，其中它们之间不存在阻塞高度 ≥ h。 

因此，每次匹配时，我们都在形成最大的安全贡献，拖延只会面临失去最佳配对结构的风险。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stacks = {}
    ans = 0

    for i, h in enumerate(a):
        if h not in stacks:
            stacks[h] = []

        if stacks[h]:
            j = stacks[h].pop()
            ans += i - j
        else:
            stacks[h].append(i)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接反映了概念模型，其中每个高度都维护自己的挂起端点。 该字典避免不必要地分配最多 10^6 的固定数组，因为仅存储观察到的高度。 

一个微妙的点是从零开始的索引，因为距离直接计算为 i − j。 另一个是我们总是匹配最近的未匹配索引，确保间隔不会重叠，从而导致未来的配对无效。

 ## 边缘情况

 具有一个露台的最小输入表明该算法正确地将答案保留为零，因为不存在第二次出现来触发匹配。 该高度的堆栈以单个不匹配的索引结束，该索引永远不会起作用。 

在完全相等的数组（如 1 1 1 1）中，算法将索引 (0,1) 和 (2,3) 配对。 跟踪显示，每次推送都会在可能的情况下立即匹配，并且不会尝试更长范围的配对，因为始终使用最近的不匹配索引。 

在 1 2 1 2 1 等交替结构中，每个高度独立维护自己的堆栈，并且每个值只有第二次出现才能配对。 堆栈的分离确保不同高度之间的干扰不会影响正确性，因为每个桥仅依赖于端点的相等性，而不依赖于其他值，除非阻塞器已经通过匹配顺序的分段隐式处理。
