 ## 解决方案
 ## 问题理解

 输入给出一个素数$P$，它代表最后一颗小行星（称为银星）在从火星开始的一维线上的位置。 沿着这条线，有一些特殊的小行星被放置在距火星等于素数的距离处，按升序排列：2、3、5、7、11等等，直到$P$。 

探测器从距离 2 处的小行星开始，并且必须在距离为 2 处的小行星结束$P$。 它可以访问中间小行星的任何子集，但必须遵守移动限制：每当它从一个访问过的小行星移动到下一个小行星时，它们位置之间的距离不得超过 14 个单位。 由于运动严格地沿着素数递增序列向前移动，因此轨迹只是从 2 开始到 2 结束的素数位置的子序列。$P$，其中连续选择的素数最多相差 14。 

任务是计算存在多少这样的有效轨迹。 

约束条件是$P \le 211$意味着我们正在处理一个非常小的素数前缀。 211以内的素数也只有几十个，所以即使是$O(n^2)$动态规划解决方案在性能方面微不足道。 这已经表明预期的解决方案是基于小型 DAG 上的简单组合，而不是任何大量的优化。 

当人们假设“最多 14 个 AU”意味着只能考虑相邻素数时，就会出现一种微妙的失败情况。 例如，我们可以从 2 直接跳到 11，因为 11 − 2 = 9，这是允许的，即使存在中间素数。 单纯的仅邻接解释会通过禁止此类跳过来错误地低估路径。 

如果假设所有素数间隔相等或尝试通过计数而不是实际数字距离来索引跳跃，则会出现另一个错误。 约束取决于实际值，而不是序列中的位置。 

## 方法

 蛮力观点将每个轨迹视为一个决策过程：在每个小行星上，我们选择是否前往 14 个单位内的任何较晚的小行星。 这可以通过 DFS 从第一个素数开始探索，递归分支到所有有效的后续步骤。 这是正确的，因为它枚举了遵守跳转约束的所有有效子序列，并对到达最后一个节点的子序列进行了计数。 

然而，这种探索在分支因子方面增长很快。 在最坏的概念情况下，每个节点都可以跳转到许多未来节点，递归路径的数量可以随着素数的数量呈指数增长，大约$O(2^n)$。 虽然$n$这里很小，这种方法在结构上效率低下且不必要。 

关键的观察结果是，由素数和有效跳跃形成的图是按递增值排序的有向无环图。 DAG 上的任何路径计数问题都可以简化为动态规划：到达某个节点的方式数量是到达可以转换到该节点的所有节点的方式之和。 

对于每个素数$p[i]$，我们只需要考虑较早的素数$p[j]$这样$p[i] - p[j] \le 14$。 由于素数不断增加且间隙很小，因此只有先前节点的一小部分后缀可以到达当前节点。 这减少了每个节点到恒定摊销时间的转换成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | DFS 枚举 |$O(2^n)$|$O(n)$| 太慢了|
 | DAG 上的 DP |$O(n^2)$或者$O(n)$优化|$O(n)$| 已接受 |

 ## 算法演练

 我们将素数视为$P$作为按递增顺序排列的节点，我们计算从一开始就可以到达每个节点的有多少种方式。 

1. 生成从 2 到 的所有素数列表$P$。 这形成了图的顶点集。 该列表的顺序已经是拓扑的，因为它是严格递增的。 
2. 创建一个DP数组，其中`dp[i]`表示结束于的有效轨迹的数量$i$-th素数。 
3. 初始化`dp[0] = 1`因为只有一种方法可以从第一个小行星（2 AU）开始，并且所有路径都必须从那里开始。 
4. 对于每个素数索引$i$从左到右，计算`dp[i]`通过总结早期指数的贡献$j < i$这样`primes[i] - primes[j] <= 14`。 每一个这样的$j$代表有效的最后一步$i$，所以每一种方法都可以到达$j$可以扩展到$i$。 
5. 通过向后扫描直到距离条件失败，或者通过保持有效前驱的滑动窗口来有效地维持总和。 由于价值增加，一旦`primes[i] - primes[j] > 14`, 都更早$j$均无效。 
6.最终答案是`dp[last]`，因为每条有效轨迹都必须以银星结束。 

### 为什么它有效

 每一个有效的轨迹都是由它最后一次跳跃到每颗小行星上来唯一定义的。 DP 确保每个状态累积从有效前驱到达该状态的所有方式，并且不会包含无效转换，因为距离约束是直接在实际小行星位置上检查的。 由于该图按递增顺序是非循环的，因此每个子问题仅依赖于已经计算的状态，通过对有序素数进行归纳来保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def sieve(n):
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(n ** 0.5) + 1):
        if is_prime[i]:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                is_prime[j] = False
    return [i for i in range(2, n + 1) if is_prime[i]]

def solve():
    P = int(input().strip())
    primes = sieve(P)

    n = len(primes)
    dp = [0] * n
    dp[0] = 1

    for i in range(1, n):
        total = 0
        j = i - 1
        while j >= 0 and primes[i] - primes[j] <= 14:
            total += dp[j]
            j -= 1
        dp[i] = total

    print(dp[-1])

if __name__ == "__main__":
    solve()
```筛子构造素数序列直到$P$，它足够小，一个简单的$O(P \log \log P)$方法就足够了。 

DP 数组对所有部分轨迹计数进行编码。 对于每个位置，我们向后扫描，直到距离条件被打破。 这是安全的，因为素数严格递增，因此一旦间隙超过 14，所有较早的素数也将超过它。 

一个常见的实现错误是忘记转换取决于数字差异而不是索引差异。 另一个微妙的问题是初始化`dp[0] = 1`; 如果没有这个基本情况，所有后续计数都将保持为零。

def run(inp: str) -> str:

    def sieve(n):
        is_prime = [True] * (n + 1)
        is_prime[0] = is_prime[1] = False
        for i in range(2, isqrt(n) + 1):
            if is_prime[i]:
                for j in range(i * i, n + 1, i):
                    is_prime[j] = False

            total += dp[j]
            j -= 1
        dp[i] = total

    return str(dp[-1])

 ## 边缘情况

 尽可能最小的输入$P = 2$由一颗小行星组成。 唯一的轨迹是在同一节点开始和结束的平凡轨迹，并且 DP 正确返回 1，因为它初始化`dp[0] = 1`并且从不执​​行转换。 

像这样的案例$P = 5$证明了允许非相邻跳跃的重要性。 从2直接跳到5是有效的，因为差值为3，DP计算时包含它`dp[2]`。 单纯的仅邻接方法会由于缺少跳过 3 的路径而错误地输出 1 而不是 2。 

对于较大的$P$，例如 211，该算法依赖于这样一个事实：只有前驱的短后缀对每个状态有贡献。 一旦距离超过 14，后向循环就会停止，确保永远不会考虑不相关的素数，即使在上限也能保持效率。
