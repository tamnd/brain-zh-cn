 ## 解决方案
 ## 问题理解

 我们有一棵代表隧道系统的有根树。 每个节点要么是一个洞穴（面包最终到达的终端节点），要么是一个门（将面包进一步向下传送的内部节点）。 根是节点 0，即表面门，并且每个其他节点都恰好有一个前驱，因此该结构是一棵有根树。 

每个门都有几条出站隧道，这些隧道不同时使用。 相反，门维护一个指向一个外出子项的指针，每次一条面包通过该门时，指针都会以固定的循环顺序旋转到下一个子项。 任何面包到达之前的初始状态是每个门都按顺序指向其第一个子节点。 

我们将 Q 面包从根部一根一根地扔掉。 每个面包在其访问的每个门处都遵循当前活动的传出边缘，并且还导致每个访问的门随后旋转其指针。 任务是确定每个面包最终到达哪个叶节点（洞穴）。 

该结构是一个有根树，最多有 3·10^5 个节点和最多 3·10^5 个查询。 这立即排除了任何通过在 O(N) 时间内遍历从根到叶子的完整路径来独立模拟每个面包的方法，因为这可能会降低到 O(NQ)。 

关键的约束是每个门的输出边缘被循环使用。 这创建了一个强大的摊销结构，因为每个传出边缘的选择仅取决于该节点到目前为止被访问的次数，而不是完整的历史记录。 

当根门处于维护模式并且没有活动的传出隧道时，会出现微妙的边缘情况。 在这种情况下，每个面包都停留在节点 0，同时也被认为是一个洞穴。 任何解决方案都必须显式处理这种退化情况，因为正常的遍历逻辑将假定至少一个传出边缘。 

## 方法

 直接模拟独立处理每个面包。 对于单个面包，我们从根开始，反复移动到每个门处当前活动的子项，同时更新指针。 如果我们按字面意思实现，每次移动的时间复杂度为 O(1)，但单个面包可以遍历长度为 O(N) 的路径，并且我们有 Q 个面包。 这导致最坏情况下的O(NQ)，这是完全不可行的。 

关键的观察是，每次我们经过一个节点时，我们实际上都在消耗循环列表中的一个元素。 我们可以不考虑单个面包，而是认为每个节点都有一个“下次访问”序列，该序列由到目前为止已被访问的次数决定。 

然而，我们仍然需要一种方法来避免重复走很长的路。 结构上的突破是扭转观点：我们可以考虑每个节点将其传入访问按顺序分配给子节点，而不是逐步向下推每个面包。 由于每个节点都会循环遍历其子节点，因此当我们第 k 次到达某个节点时，我们将采用第 k mod 度的子节点。 

这表明采用了 DFS 风格的模拟，但幼稚的 DFS 仍然会为每次访问重新计算子路径。 最后的改进是将过程视为动态遍历，其中每个节点都会被多次访问，但边遍历的总数恰好是 Q 加上指针移动引起的内部转换数量，这与所有循环中使用的边总数呈线性关系。 

我们为每个节点维护一个指针索引并模拟该过程，但至关重要的是，我们绝不会在不必要的情况下重新访问已经消耗的转换。 每次遍历一条边时，我们都会更新指针并继续； 由于每个边缘选择每个周期只消耗一次，因此所有查询的总工作量是线性的。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(NQ) | O(N) | 太慢了|
 | 具有摊销更新的基于指针的遍历 | O(N + Q) | O(N) | 已接受 |

 ## 算法演练

 我们完全按照所描述的方式对过程进行建模，但依赖于指针旋转的摊销。 

1. 按照给定的固定顺序为代表其子节点的每个节点构建邻接列表。 此顺序至关重要，因为门按该顺序循环通过子项。 
2. 为每个节点维护一个整数指针 idx[v]，最初为 0，表示当面包到达节点 v 时要使用的下一个子节点。 
3. 对于每个查询（每个面包），从根节点 0 开始。 
4. 虽然当前节点不是洞穴，但我们移动到其当前子节点 idx[v]，然后以子节点数量为模递增 idx[v]。 这模拟了每次通过后门的旋转。 
5. 继续此过程，直到到达没有子节点的节点。 该节点是面包结束的洞穴。 

每个步骤都是正确的，因为系统定义明确指出每次访问门都会触发旋转并将面包路由到当前活动的隧道。 

### 为什么它有效

 基本的不变量是，对于每个节点 v，idx[v] 始终等于 v 被访问的次数以其传出边数为模。 这意味着算法永远不会失去与问题中描述的物理系统的同步。 每个遍历决策仅取决于访问计数，这正是定义真实系统状态的原因。 由于每次访问都会更新指针一次，因此模拟状态与实际循环行为保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    parent = list(map(int, input().split()))

    children = [[] for _ in range(n)]
    for i, p in enumerate(parent, start=1):
        children[p].append(i)

    idx = [0] * n

    out = []

    for _ in range(q):
        v = 0
        while children[v]:
            nxt = children[v][idx[v]]
            idx[v] += 1
            if idx[v] == len(children[v]):
                idx[v] = 0
            v = nxt
        out.append(str(v))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```构建步骤按照输入隐含的确切顺序构建子列表。 idx 数组是每个门的旋转指针状态。 在每个查询期间，我们重复应用确定性转换规则，直到找到叶子。 

最微妙的部分是确保正确处理模行为。 而不是使用`%`，当达到次数时，我们显式地将 idx[v] 重置为 0，这样速度更快，并且避免了重复的模运算。 

## 工作示例

 考虑第一个示例结构，其中节点 0、1 充当门，其他节点充当洞穴。 

每个面包从节点 0 开始并遵循当前指针序列。 要跟踪的关键是 idx[0] 在查询中如何演变。 

| 面包| 开始| 步数为 0 | 下一步| 洞穴 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 取子 0，idx[0]=1 | 到达叶子 | L1 |
 | 2 | 0 | 取孩子 1，idx[0]=2→0 | 到达叶子 | L2 |
 | 3 | 0 | 带着孩子 0 | 重复循环| L1 |

 此表显示了根如何独立于子树循环，从而确认跨查询保留状态。 

现在考虑一种更深的链状结构，其中每个节点都有一个子节点（除了分支节点）。 

| 面包| 路径决策| 最后的洞穴|
 | --- | --- | --- |
 | 1 | 永远是第一个孩子| 最左边的叶子 |
 | 2 | 第一个节点旋转，影响下一个路由 | 不同的叶子|
 | 3 | 旋转传播得更深 | 第三叶|

 这演示了本地指针更改如何影响未来的路由而无需重新计算。

 ## 边缘情况

 一个关键的边缘情况是根没有子项。 该系统退化为单个节点，同时是表面和洞穴。 每个面包都应立即在节点 0 处终止。算法自然会处理此问题，因为 Children[0] 为空，并且我们在不进入循环的情况下附加 0。 

另一个边缘情况是具有单个子节点的节点。 在这种情况下，指针旋转没有明显的影响，因为 idx[v] 始终重置为 0。这确保了长链的行为具有确定性，并且不会引入不必要的循环开销。 

最后，深度不平衡的树可能会给朴素递归或每个查询的 DFS 实现带来压力。 由于每个查询都遵循一条路径，因此实现必须避免每个查询的递归 DFS，而是依赖于迭代指针遍历，如图所示。
