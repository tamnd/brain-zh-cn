 ## 问题理解

 我们给出了一个在非负整数上定义的函数，其中每个数字通过阶乘独立贡献，但有一个变化：该函数是根据十进制数字递归定义的。 对于一位数字，该值只是该数字的阶乘。 对于多位数字，该函数将数字拆分为最后一位数字和剩余的前缀，然后将最后一位数字的阶乘添加到前缀的函数值中。 

因此，如果我们将一个数字写为数字序列，则函数值就是其数字的阶乘之和。 

任务是反向评估。 我们不是计算给定数字的函数，而是给定一个目标值 y，并且必须找到最小的非负整数 x，使得 x 的数字阶乘之和等于 y。 

关键约束是 y 最多为 10^9。 这立即意味着我们不会构造任意大型结构：数字的阶乘是小常数。 事实上，只有数字 0 到 9 贡献从 0 开始的固定值！ 到 9! 和 9! 等于 362880，因此 y 的任何有效表示都必须使用贡献比例 9 的至多约 10 位数字！ 或更少的数字（如果使用较小的数字）。 

如果我们想象 x 本身可能非常大，就会产生天真的担忧，因为 x 没有上限。 然而，由于每个数字最多贡献 362880，因此即使是 10^9 的总和最多也只能来自大约 3000 个数字的贡献，这已经表明答案在实践中是有限长度的。 

一个微妙的边缘情况是，在数字的概念构造中允许使用前导零，但与 x 的数值无关。 例如，像 0012 这样的数字序列表示与 12 相同的整数，但在推理阶乘和时数字序列很重要。 最小整数要求迫使我们更喜欢更短或字典顺序更小的数字表示。 

另一个边缘情况是 y = 0。从 0 开始！ = 1，除非根本不使用数字，否则没有数字贡献零。 y = 0 时唯一有效的 x 是 0。 

## 方法

 暴力方法会迭代 x = 0, 1, 2, ... 并每次计算 f(x)，直到到达第一个匹配项。 计算 f(x) 与位数呈线性关系，因此其复杂度为 O(x log x)。 由于在找到匹配之前 x 本身可能很大，因此这是不可行的。 即使答案约为 10^9，这仍然太慢。 

函数的结构将问题转化为数字构造问题。 每个数字贡献一个等于其阶乘的独立权重，因此我们实际上尝试将 y 表示为数字权重之和，其中每个权重对应于数字 0 到 9。 

这将问题变成了有界硬币找零问题，其中硬币是数字阶乘，但我们也希望结果数字是尽可能小的整数。 第二个条件强制采用贪婪排序原则：为了最小化 x 的数值，我们希望更重要的数字尽可能小，这意味着我们首先希望较短的长度，并且在固定长度内，字典顺序最小的数字。 

关键的观察是，我们可以将其视为从最重要到最不重要的数字进行选择，同时确保我们仍然可以使用可用的数字阶乘来完成剩余的总和。 这变成了数字 DP 或具有可行性检查的建设性贪婪。 

我们预先计算数字 0 到 9 的阶乘。然后，我们确定阶乘之和为 y 的数字的多重集合，最后将它们排列成尽可能小的整数，这是通过按非降序对数字进行排序来实现的，限制是第一位数字不能为零，除非整个数为零。

 ## 算法演练

 1. 预先计算数字 0 到 9 的阶乘值。这给出了每个数字选择的固定成本，从而将函数转换为加权和问题。 
2. 构建按递增阶乘值排序的候选数字列表，因为较小的阶乘通常对于构建最小表示更有用。 
3. 从最高有效数字位置开始，通过按升序测试候选者来决定放置哪个数字。 对于每个候选数字d，从剩余目标中减去其阶乘值，并检查剩余值是否仍然可以使用可用数字形成。 
4. 首先使用最大阶乘数字贪婪地进行可行性检查。 这确保了如果剩余总和存在解决方案，它将被快速检测到。 
5. 继续填写数字，直到剩余的总和变为零。 此时，我们已经构建了一个数字多重集，其阶乘之和为 y。 
6. 按升序对结果数字进行排序，以获得尽可能小的整数。 此步骤可确保最小数值，因为较小的数字应在位置表示法中出现较早。 
7. 如果结果数字列表为空，则返回 0。 

### 为什么它有效

 该函数完全分解为独立的数字贡献，因此任何有效的解决方案都对应于权重总和为 y 的数字多重集。 构建过程确保我们永远不会丢弃可行的前缀，因为可行性总是与剩余的可实现的总和进行检查。 由于数字阶乘是固定常量，并且贪心构造始终保留至少一个有效的完成路径，因此生成的数字多重集是有效的。 随后的排序会产生该多重集的最小数字解释，因为一旦计数固定，数字顺序是唯一剩余的自由度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

FACT = [1] * 10
for i in range(1, 10):
    FACT[i] = FACT[i - 1] * i

def solve():
    y = int(input().strip())

    if y == 0:
        print(0)
        return

    # We want to use largest digits first to reduce digit count
    digits = []

    # Greedy: take largest factorial digits first
    for d in range(9, -1, -1):
        while y >= FACT[d]:
            y -= FACT[d]
            digits.append(d)

    if y != 0:
        # should not happen for valid inputs, but safe guard
        print(0)
        return

    # To get smallest numeric value, sort digits
    digits.sort()

    # avoid leading zero only if number is non-zero
    if digits and digits[0] == 0:
        # move first non-zero to front if possible
        for i in range(len(digits)):
            if digits[i] != 0:
                digits[0], digits[i] = digits[i], digits[0]
                break

    print("".join(map(str, digits)))

if __name__ == "__main__":
    solve()
```该解决方案首先预先计算阶乘，因此数字成本为 O(1)。 从 9 到 0 的贪婪循环将 y 的表示构造为数字阶乘之和，优先考虑较大的数字以减少数字总数。 构造后，排序可确保所得整数的字典顺序值最小。 

微妙之处在于两个目标之间的分离：首先满足总和约束，然后最小化数值。 在构建过程中混合这些目标会使正确性变得复杂，因此故意将它们分开。

 ## 边缘情况

 对于 y = 0，算法立即返回 0，因为不需要选择数字，并且空表示将被解释为零。 

对于 y 等于单个阶乘，例如 6 (3!) 或 24 (4!)，贪婪循环恰好选择一位数字并干净地停止，产生一位数字的答案。 

对于需要重复数字的值，例如 y = 10，该算法会累积多个较小的阶乘数字，并依靠最终排序来确保整数最小化。
