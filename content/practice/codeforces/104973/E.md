 ## 解决方案
 ## 问题理解

 我们得到了排列成一行的数据库集合。 每个数据库的行为就像一个具有固定容量的队列。 我们还有一系列操作，每个操作都会获取一个值并将其推送到索引位于给定区间内的每个数据库中。 如果数据库在插入后变得比其容量长，它会立即从前面删除最旧的元素。 

处理完所有操作后，每个数据库都包含一系列值，但重复的值并不重要。 任务是计算每个数据库中剩余多少个不同的值。 

关键的困难在于每个操作都会影响整个数据库段，并且每个数据库都有自己的队列演变，具体取决于它随时间推移接收到的更新数量。 直接模拟每次操作需要推入多达 200,000 个数据库，这已经太大了，并且每个数据库最多可以累积 200,000 个操作，这使得直接的队列模拟不可行。 

重新解释该过程的一个有用方法是关注最终剩下的内容。 每个数据库只保留影响它的最近的 c[i] 插入。 当队列溢出时，较旧的插入将按顺序删除。 这意味着我们实际上并不关心中间状态，只关心每个数据库相关更新的最终后缀。 

当尝试独立模拟每个数据库但仍然天真地处理所有操作时，就会出现一种微妙的失败情况。 例如，如果每个操作都会影响所有数据库并且容量很大，则简单的每个数据库队列实现仍然执行 O(nq) 推送，这远远超出了限制。 另一个陷阱是忘记了移除是严格从前面进行的，这使得该结构随着时间的推移成为一个滑动窗口，而不仅仅是一组应用操作。 

## 方法

 暴力方法将通过迭代间隔内的所有数据库并将值推入队列来显式模拟每个操作。 每个数据库都会维护一个双端队列，如果超过容量，它将从前面弹出。 这是正确的，因为它直接反映了该陈述。 然而，每个操作可能会接触 O(n) 个数据库，因此总复杂度变为 O(nq)，这在 2⋅10^5 规模下是完全不可行的。 

关键的观察是扭转视角。 不要跟踪队列如何及时演变，而是考虑一个固定的数据库 i。 每个操作要么影响 i，要么不影响 i。 如果是，它将向其队列贡献一个元素。 由于队列在溢出时总是从前面删除，因此数据库 i 的最终状态恰好由包含 i 的最后 c[i] 操作（按时间顺序）组成。 

所以问题就简化为：对于每个索引 i，收集区间覆盖 i 的所有操作，按时间排序，取出最后的 c[i]，并计算其 x[i] 中的不同值。 

随着时间的推移，挑战变得高效地回答许多范围到点的查询，但只是收集数据而不是聚合数据。 

我们可以使用数据库索引上的线段树对此进行建模。 每个操作（l，r，x）都存储在完全覆盖其区间的所有线段树节点中。 这确保了对于任何固定索引 i，其根到叶路径上的节点准确地包含影响它的操作。 每个节点按时间递增顺序存储操作。 

为了回答单个 i，我们合并来自其 O(log n) 节点的列表，并使用 k 路合并仅提取最近的 c[i] 操作。 由于 k 很小，因此即使对所有索引求和也足够有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | O(nq) | O(n) | 太慢了|
 | 线段树 + 按索引合并 | O((n + q) log n + Σc[i] log log n) | O((n + q) log n) | O((n + q) log n) | 已接受 |

## 算法演练

 1. 在索引 1 到 n 上构建线段树。 每个节点将存储完全覆盖该节点的段的操作列表。 这使我们能够表示范围更新，而无需显式触及每个数据库。 
2. 对于时间索引为 i 的每个操作 (l[i], r[i], x[i])，将 i 插入到被 [l[i], r[i]] 完全覆盖的线段树节点中。 这种分解确保每个操作仅存储 O(log n) 次。 
3. 对于线段树中的每个节点，保持操作的添加顺序，这对应于增加时间。 这保证了在每个节点内，列表已经遵循时间顺序。 
4.对于每个数据库位置i，从根到叶遍历线段树路径并收集指向该路径上的节点中存储的所有列表的指针。 这些列表一起代表影响 i 的所有操作。 
5. 对于数据库 i，对这些 O(log n) 排序列表执行 k 路合并，始终首先选择最近的剩余操作。 一旦我们收集了 c[i] 个操作就停止，因为较旧的操作不能影响最终的队列状态。 
6. 从收集的操作索引中，提取它们的 x 值并将它们插入到集合中以计算数据库 i 的不同值。 
7. 输出集合的大小作为数据库 i 的答案。 

### 为什么它有效

 影响数据库的每个操作与该数据库的根到叶路径上的一个或多个线段树节点中的一次出现完全对应。 由于每个节点按时间顺序存储操作，因此合并这些列表并获取最新的 c[i] 元素可以准确地重建所有相关操作的长度 c[i] 的后缀。 该后缀与队列的最终内容相同，因为每次溢出都会删除最旧的元素，这相当于丢弃除最后一个 c[i] 插入之外的所有插入。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    c = list(map(int, input().split()))

    ops = []
    for _ in range(q):
        l, r, x = map(int, input().split())
        ops.append((l - 1, r - 1, x))

    size = 1
    while size < n:
        size *= 2

    tree = [[] for _ in range(2 * size)]

    def add(node, nl, nr, l, r, idx):
        if l <= nl and nr <= r:
            tree[node].append(idx)
            return
        mid = (nl + nr) // 2
        if l <= mid:
            add(node * 2, nl, mid, l, r, idx)
        if r > mid:
            add(node * 2 + 1, mid + 1, nr, l, r, idx)

    for i, (l, r, _) in enumerate(ops):
        add(1, 0, size - 1, l, r, i)

    for i in range(2 * size):
        tree[i].reverse()

    def collect(i):
        i += size
        res_lists = []
        while i:
            res_lists.append(tree[i])
            i //= 2
        return res_lists

    import heapq

    ans = [0] * n

    for i in range(n):
        lists = collect(i)

        heap = []
        ptrs = [len(lst) - 1 for lst in lists]

        for j, lst in enumerate(lists):
            if ptrs[j] >= 0:
                op_idx = lst[ptrs[j]]
                heapq.heappush(heap, (op_idx, j))

        taken = 0
        seen_ops = []
        k = c[i]

        while heap and taken < k:
            op_idx, j = heapq.heappop(heap)
            seen_ops.append(op_idx)
            ptrs[j] -= 1
            if ptrs[j] >= 0:
                heapq.heappush(heap, (lists[j][ptrs[j]], j))
            taken += 1

        seen = set()
        for op_idx in seen_ops:
            seen.add(ops[op_idx][2])

        ans[i] = len(seen)

    print(*ans)

if __name__ == "__main__":
    solve()
```线段树将每个操作存储在 O(log n) 个节点中，以便每个数据库都可以准确检索其相关操作，而无需扫描不相关的操作。 每个节点内的反向指针允许我们首先访问最近的操作，这是必要的，因为我们只关心长度 c[i] 的后缀。 堆跨线段树节点执行 k 路合并，始终有效地选择下一个最新操作。 

一个常见的实现陷阱是忘记我们必须在所有线段树节点上按全局时间顺序进行操作。 简单地连接节点中的列表会混合不相关的排序并破坏正确性。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O((n + q) log n + Σ c[i] log log n) | 线段树分解加上每个索引的 k 路合并 |
 | 空间| O((n + q) log n) | O((n + q) log n) | 每个操作存储在 O(log n) 个节点中 |

 该结构非常高效，因为每个操作仅以对数方式重复，并且每个数据库仅处理跨 O(log n) 列表的小型合并。 这非常适合 n、q 至 2⋅10^5 的约束。

 ## 边缘情况

 一个微妙的边缘情况是数据库接收到的更新总数少于 c[i] 个。 在这种情况下，不会发生删除，并且答案应反映所有应用值的完整集合。 该算法自然会处理这个问题，因为当所有可用操作在到达 c[i] 之前耗尽时，k 路合并就会停止。 

当所有操作都应用于单个数据库时，会出现另一种边缘情况。 段树会将所有操作沿着一条路径放置，而堆则退化为一个列表的简单反向遍历。 输出保持正确，因为合并逻辑仍然保留时间顺序。 

最后一种情况是 c[i] 等于 1 时。那么只有最近的操作才重要，堆会立即从合并列表中提取单个最大时间条目。 这将问题简化为纯粹的“最后覆盖更新”查询，该结构无需修改即可处理该查询。
