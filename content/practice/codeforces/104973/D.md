 ## 解决方案
 ## 问题理解

 我们从一个数组开始`a`其元素构成了我们希望最大化的总和。 我们可以从中删除元素`a`，但删除不是任意的：每次删除都是通过从第二个数组中选择一个位置来触发的`b`，并从当前状态中删除相应的索引元素`a`。 每次删除后，数组都会缩小，所有索引都会左移。 

关键的限制是我们最多可以执行`k`总共删除，并且每次删除都必须来自选择一些`b[i]`这仍然是当前数组中的有效索引。 自从`b`是严格递增的，每个值`b[i]`指的是原始数组中逐渐加深的位置，但在删除之后，这些位置变得动态。 

目标是选择最多的序列`k`这种删除可以最大化剩余元素的最终总和。 

约束足够小`n ≤ 2000`，因此二次或稍微超二次的解是可以接受的。 然而，任何立方体以上`n`如果对每个可能的操作计数和位置重复，将会太慢。 微妙的困难在于删除不是独立的：删除一个元素会改变所有后面的索引，因此如果在没有结构的情况下重复进行，简单的模拟就会变得复杂。 

当人们假设可以按值贪婪地处理删除时，就会出现一种常见的失败模式。 例如，总是删除允许位置中最小的可用元素是错误的，因为小的早期删除可能会发生变化`b[i]`稍后将其定位到数组中更好或更差的部分。 

另一种微妙的情况发生在`k`相比而言较大`m`。 即使我们被允许进行许多操作，我们也不一定会使用它们，因为一旦`b[i] > |a|`，该索引变得不可用。 因此，有效删除数量取决于状态，而不是固定的。 

## 方法

 一个蛮力的想法是模拟所有删除序列。 在每一步中，我们都会选择一个索引`i`这样`b[i]`有效，删除该元素，然后递归。 这将创建一个分支因子高达`m`每一步和深度可达`k`。 即使进行了修剪，这也会很快变得指数级，因为相同的数组状态出现在许多不同的删除顺序中。 

主要观察结果是，删除的元素的身份仅通过我们在停止之前执行的删除次数以及删除的前缀来确定。`b`仍然可用。 我们可以根据选择从前缀中“消耗”多少个删除来重新解释该过程，而不是按任意顺序模拟删除`b`在不同的时间。 

一种更结构化的方法是从左到右处理数组，同时跟踪我们已经使用了多少个操作。 在任何位置，我们决定是否删除或保留该元素，但仅当它们对应于某些活动时才允许删除`b[i]`临界点。 这自然会导致动态编程公式，其中状态捕获已使用了多少删除以及我们在强制执行约束方面取得了多大进展`b`。 

关键的简化是我们永远不需要显式模拟移动索引。 相反，我们跟踪在给定位置之前删除了多少元素，这决定了是否`b[i]`变得适用。 这将问题转化为关于位置和删除数量的 DP 问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力模拟 | 指数| O(n) | 太慢了|
 | DP 过定位和删除 | O(n²k) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

 我们定义一个动态规划状态`dp[i][j]`作为考虑第一个因素我们可以获得的最大总和`i`的元素`a`准确执行后`j`删除。 

复杂的是，只有在某些情况下才允许删除`b[i]`在当前减小的数组大小下变得有效。 我们没有明确地对当前大小进行建模，而是在位置观察到`i`，如果我们删除了`j`到目前为止的元素，那么有效的原始索引对应于`i + j`。 这使我们能够确定有多少`b`到目前为止，约束已经变得“可用”。 

我们预先计算每个`i`有多少个索引`b`是 ≤`i`，它告诉我们如果我们当前处于位置，则存在多少个删除选项`i`在原始数组中。 让这成为`cnt[i]`。 

现在我们重新解释这个过程：当我们处于位置时`i`, 已使用的删除数`j`不得超过`cnt[i]`，因为我们不能执行比可用的有效删除更多的删除`b`到该点的指数。 

然后我们执行转换：

 1. 初始化`dp[0][0] = 0`和所有其他状态为负无穷大，因为在处理元素之前我们没有总和。 
2. 对于每个位置`i`从`0`到`n - 1`，我们更新所有可能的状态`j`最多`k`，结转先前的成果。 这表示跳过或处理当前元素。 
3. 对于每个州`(i, j)`，我们考虑保留`a[i]`，转换为`(i + 1, j)`有附加值`a[i]`。 
4.我们也考虑删除`a[i]`，转换为`(i + 1, j + 1)`但前提是`j + 1 ≤ cnt[i + 1]`。 这确保我们尊重仅有效的约束`b`岗位可以在轮班后使用。 
5. 我们传播所有有效的转换，保持最大总和。 

处理完所有位置后，答案就是最大值`dp[n][j]`全面的`j ≤ k`。 

关键的不变量是`dp[i][j]`正确表示处理长度前缀后可实现的最佳总和`i`恰好与`j`删除，在删除对应于有效位置的约束下`b`转移后。 强制执行条件`cnt[i]`确保我们永远不会使用比结构更多的删除操作`b`允许使用任何前缀。 由于每次转换都会以与可行性一致的方式保留或删除当前元素，因此所有有效序列都会被表示，并且不会引入无效序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    cnt = [0] * (n + 1)
    ptr = 0
    for i in range(1, n + 1):
        while ptr < m and b[ptr] <= i:
            ptr += 1
        cnt[i] = ptr

    NEG = -10**30
    dp = [[NEG] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n):
        for j in range(k + 1):
            if dp[i][j] == NEG:
                continue

            # keep a[i]
            dp[i + 1][j] = max(dp[i + 1][j], dp[i][j] + a[i])

            # delete a[i]
            if j < k and j + 1 <= cnt[i + 1]:
                dp[i + 1][j + 1] = max(dp[i + 1][j + 1], dp[i][j])

    ans = max(dp[n])
    print(ans)

if __name__ == "__main__":
    solve()
```DP 表是逐行构建的，因此我们永远不会错误地重用同一层的状态。 这`cnt`数组是使用指针计算的`b`，给出原始数组的每个前缀允许的删除索引的数量。 

一个微妙的点是条件`j + 1 ≤ cnt[i + 1]`。 这强制执行后处理`i + 1`元素，我们不能执行比有效元素更多的删除`b`可以应用的指数。 如果没有这个限制，DP 就会过多计算不可能的删除序列。

 ## 边缘情况

 当所有元素均为负并且删除受到限制时，就会出现临界边缘情况。 该算法会倾向于保留较少的元素，并且仅在允许时才删除`b`。 例如：

 输入：```
4 1 2
-5 -1 -3 -2
2
```DP 评估是否可以在以下情况下删除第二个元素`b`。 由于只有一个索引，因此最多可以使用一次删除。 最佳行为是删除约束下可达到的最差元素并保留其余元素，从而获得可实现的最小负和。 

另一个边缘情况是当`k`大于`m`。 尽管允许多次删除，`cnt`约束限制了实际删除。 民主党自然会强制执行这一点，因为各州`j > cnt[i]`永远无法到达，因此额外的容量`k`不会错误地增加删除。
