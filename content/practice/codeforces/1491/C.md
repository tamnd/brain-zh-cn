 ## 解决方案
 ## 问题理解

 我们得到了一系列排成一行的蹦床强度。 每个蹦床的行为就像一次强制跳跃：如果 Pekora 落在位置上`i`，她立即启动`i + S[i]`。 使用蹦床后，其强度会降低 1，但永远不会低于 1，因此最终每个蹦床都会稳定在强度 1。 

一次“通过”是一系列强制跳跃。 佩科拉选择一个起始蹦床，然后继续跳跃，直到她离开右侧的阵列。 她不能提前中断传球。 我们的目标是执行多次这样的传递，以便将每个蹦床的强度减少到恰好为 1，并且我们希望最大程度地减少传递次数。 

每次在一次传递中使用蹦床时，它都会精确地贡献一个减量，因此真正的约束不是我们绝对跳跃多远，而是在所有传递中访问每个索引的次数，同时尊重传递遵循随时间变化的确定性跳转链接。 

这些限制使得暴力模拟在简单意义上是不可能的。 和`n`高达 5000 且值高达 1e9，任何重复尝试所有起始点或按单位递减逐步模拟每次传递的策略都会退化为每个测试用例的二次或更差的行为。 自总计`n`测试次数也是5000，`O(n^2)`或者`O(n^2 log n)`如果常数很大，这种方法可能是边缘性的，但仍然存在风险； 任何立方体都是立即不可行的。 

棘手的边缘行为来自于大跳跃和递减强度之间的相互作用。 天真的期望是大值独立运行，但实际上单次传递可以影响固定算术级数中的多个遥远位置，并且后续传递可能会也可能不会重用这些路径，具体取决于值收缩的方式。 

一些具体的陷阱：

 一个天真的贪婪想法可能是“总是从最大的剩余值开始”，但这会失败，因为一次传递可能会也可能不会到达这些位置，具体取决于中间的减少。 例如，如果早期位置具有非常大的值，则稍后开始的传递可能永远不会到达它们，因此局部贪婪排序会破坏全局可达性结构。 

另一个微妙的问题是假设每个位置都可以独立对待。 例如，如果除了一个 100 之外所有值都是 2，天真的求解器可能会认为 100 需要从该位置开始 99 个单独的通道，但实际上，根据遍历路径，许多递减可以在通道之间共享。 

关键的隐藏结构是每次通过都会引发确定性行走，并且每次访问都会以非常受控的方式改变未来的结构。 

## 方法

 蛮力视图是显式模拟通道。 在每次传递中，我们选择一个起始索引，然后模拟跳转链，直到退出数组，减少每个访问的位置。 我们不断重复，直到所有价值观合而为一。 这是正确的，因为它完全遵循问题定义。 

然而，成本却令人望而却步。 每次传递可以遍历 O(n) 个位置，在最坏的情况下，我们可能需要 O(max S_i) 次传递某些位置，从而使复杂性爆炸超出可行的限制。 

观察的关键是倒转观点。 我们不考虑传球次数，而是考虑每个位置对未来位置的贡献。 每次我们降落在位置上`i`，我们“安排”访问`i + S[i]`。 因此，每个索引都会创建到另一个索引的有向边，并且该过程成为函数图上的动态遍历，该函数图随着权重的减小而缓慢缩小。 

一个重要的结构洞察是，尽管边缘随着时间的推移而变化，但每个指数的目标仅向左移动（因为`S[i]`减少）。 这意味着每个节点的出边只能单调“滑动”，每个单位减量对应有限数量的有效结构变化。 

我们可以以类似扫描的方式处理贡献：当使用一个位置时，它会将“需求”传播到其目标。 我们维护每个位置必须输入的次数，并且每个条目恰好对应一个通行贡献，除非它链接在同一个通行内。 

这将问题简化为维护所需访问的动态累积并计算需要多少个独立的起点来满足所有传播链。 最终答案对应于我们需要启动一条无法被已经正在进行的传播覆盖的链的次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n * 最大 S) | O(n) | 太慢了|
 | 传播/贪心流积累| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将该过程解释为构建从每个索引到其当前目的地的依赖流`i + S[i]`。 每个位置都会累积“传入需求”，这意味着在所有通行证中必须访问该位置的次数。 

1.初始化一个数组`need`尺寸的`n + 2`跟踪每个位置还需要激活多少次。 最初，所有值都为零，因为我们尚未安排任何遍历。 
2. 从左到右遍历索引。 在每个索引处`i`，我们首先考虑由于早期传播，该位置仍必须被访问多少次。 如果`need[i] > 0`，我们将每一个都视为正在进行的传递的一部分，并向前传播它们的效果。 
3.各时间位置`i`使用时，它会强制过渡到`i + S[i]`。 我们添加`need[i]`到`need[i + S[i]]`。 这代表每次需要的访问`i`链条继续向前。 
4. 传播后，我们确定必须开始多少次新的传递`i`。 如果还有剩余的“未涵盖的需求”`i`，这意味着之前的链没有到达它，因此每个这样的单元对应于开始一个新的传递。 我们相应地增加答案。 
5.自从使用以来`i`从概念上降低其强度，我们没有显式模拟递减； 相反，单调传播已经通过确保每次所需访问重复贡献恰好向前流动一次来解决未来的削弱。 

### 为什么它有效

 每次传递都可以看作是一系列确定性的前向跳跃，这会产生按索引顺序从左到右递增的贡献链。 按顺序处理索引时，所有传入的贡献`i`已经确定了。 任何剩余赤字`i`必须源自于恰好开始于的新通道`i`，因为没有更早的索引可以到达`i`尚未计入`need[i]`。 传播确保每次访问都延续相同的链结构，因此永远不需要拆分链，并且通过累积自然发生合并`need`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = list(map(int, input().split()))
        
        need = [0] * (n + 5)
        ans = 0
        
        for i in range(n):
            if need[i] > 0:
                jump = i + s[i]
                if jump <= n:
                    need[jump] += need[i]
            
            if need[i] == 0:
                continue
            
            ans += need[i]
            jump = i + s[i]
            if jump <= n:
                need[jump] += need[i]
            
            need[i] = 0
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码维护一个传播数组`need`，它跟踪当前有多少个遍历链经过每个位置。 主循环按升序处理索引，以便每一步都已知所有传入链。 

在每个索引处，任何挂起的链要么继续向前，要么如果不存在，则必须启动新的传递。 跳跃计算`i + s[i]`对蹦床转换进行编码，边界确保我们忽略数组之外的退出。 

一个微妙的实现选择是重置`need[i]`处理后。 当多个较早的索引传播到同一位置时，这可以防止重复计算。

 ## 边缘情况

 关键的边缘情况是所有值都已为 1 时。在这种情况下，不会发生传播，因此算法永远不会增加答案。 这是安全的，因为`need[i]`始终保持为零。 

另一种情况是当值非常大时。 例如，如果`S[1] = 10^9`，跳转立即退出数组，因此索引不会贡献进一步的传播。 该算法自然地处理这个问题，因为`i + S[i] > n`只是丢弃更新。 

最后一个微妙的情况是多个索引传播到同一目标时。 因为`need`累积计数，这些合并自然地组合在一起，并且每个单元仍然被视为独立的所需访问，即使在多个链收敛时也保持正确性。
