 ## 解决方案
 ## 问题理解

 我们正在使用一个二进制数组，其中每个位置都包含 0 或 1。该数组通过两种类型的操作随时间变化。 一个操作将单个位置从 0 翻转到 1 或从 1 翻转到 0。另一个操作要求提供在我们从顶部查看特定排名时出现在数组的排序版本中的值。 

关键的观察结果是该数组仅包含两个不同的值。 这意味着一旦我们按非递增顺序对其进行排序，所有的都在前面，所有的零在后面。 所以整个排序结构完全由一个数字决定：数组中当前有多少个。 

约束最多允许 100,000 个元素和 100,000 个查询。 任何从头开始为每个查询重新计算 1 数量的解决方案在最坏的情况下都将需要大约 10^10 次操作，这远远超出了一秒内可能完成的操作。 即使显式维护排序数组也会失败，因为每次翻转都需要线性更新或重新排序。 

一个幼稚的错误是尝试在每次翻转后物理地维护数组的排序。 例如，在每次切换之后，可能会重建已排序的数组并直接回答第 k 个元素。 这在长序列更新时会立即失败，因为每次重建都是 O(n)。 

另一个微妙的错误是通过在每个查询上扫描整个数组来重新计算计数。 这看起来很简单，但又会导致 O(nq) 行为。 

隐藏的结构是所有查询仅取决于 1 的数量，而不取决于它们的位置。 

## 方法

 蛮力的想法很简单。 对于每个查询，如果是翻转，我们就更新数组。 如果是查询，我们按降序对数组进行排序并选择第 k 个元素。 排序成本为 O(n log n)，最多执行 100,000 次会导致大约 10^10 log 操作，这太慢了。 

我们还可以尝试一种稍微更好的暴力方法，通过扫描数组来对每个查询进行计数。 这减少了排序开销，但每次查询的成本仍然是 O(n)，在最坏的情况下又变成了 10^10 次操作。 

关键的一点是数组始终只包含 0 和 1。 排序后，第一段全部是1，其余都是0。 因此，第 k 大元素由 k 是否位于 1 块内来确定。 如果我们只维护当前的个数，则每个查询都会变成 O(1)。 翻转只是根据该位置的先前值来增加或减少该计数。 

这减少了维护单个整数和二进制数组的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（重新计算/排序）| O(nq) 或 O(q·n log n) | O(n) | 太慢了|
 | 最佳（数个）| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们维护两条信息：数组本身和存储当前存在数量的计数器。 

1. 根据输入初始化数组，并通过对所有元素求和来计算初始的个数。 这为我们提供了回答任何查询所需的基线。 
2. 对于位置 x 处的类型 1 查询，我们翻转该索引处的值。 如果是 1，我们就减少 1 的数量。 如果它是 0，我们就增加它。 这确保计数器始终与数组的实际状态匹配，而无需重新计算。 
3. 对于参数为 k 的类型 2 查询，我们决定第 k 个最大元素是 1 还是 0。由于按排序顺序所有元素都排在前面，因此如果 k 小于或等于 1 的数量，则答案为 1。否则，它必须为 0。 
4. 对所有查询重复此过程，根据需要打印答案。

它的工作原理基于结构不变量：在每一个时刻，数组都可以在概念上被排序为由 1 后跟 0 组成的前缀，并且该前缀的长度正是维护的计数。 每次翻转都会正确地更新此前缀长度±1，因此不需要超出计数的历史信息。 第 k 个元素查询简化为检查该前缀中的成员资格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

ones = sum(a)

out = []

for _ in range(q):
    t, x = map(int, input().split())
    if t == 1:
        x -= 1
        if a[x] == 1:
            a[x] = 0
            ones -= 1
        else:
            a[x] = 1
            ones += 1
    else:
        k = x
        if k <= ones:
            out.append("1")
        else:
            out.append("0")

print("\n".join(out))
```显式存储数组只是为了支持正确翻转各个位置。 关键的优化是我们从不直接从数组结构中得出答案； 我们只维护不变的个数。 

翻转操作会在恒定时间内仔细调整数组和计数器。 这可以避免重新计算错误，否则过时计数会累积。 查询操作被简化为与维护的计数的单个比较。 

一个常见的实现错误是在翻转时忘记将索引从基于 1 的索引转换为基于 0 的索引。 另一种方法是在检查当前值之前更新计数器，这会反转逻辑。 正确的顺序始终是首先检查旧值，然后一致地更新数组和计数器。

 ## 边缘情况

 一种边缘情况是数组完全从零开始。 在这种情况下，个数计数器为零，因此每个第 k 次查询都必须返回 0，直到翻转引入个数。 例如，输入`[0,0,0,0]`带查询`2 1`正确返回 0，因为根本没有 1 的前缀。 

另一个边缘情况是重复翻转相同的索引。 如果一个元素被切换多次，其正确性完全取决于与数组同步更新计数器。 例如，从`[1,0]`，翻转位置 1 两次会使系统返回到其原始状态，并且个数计数器返回到其原始值。 该算法自然地处理这个问题，因为每次翻转都是对称的并且在 O(1) 更新中可逆。 

最后一个微妙的情况是 k 等于 n。 除非数组全部为 1，否则始终返回 0。 逻辑`k <= ones`仍然干净地处理这个问题，因为`ones`永远不能超过`n`，因此边界比较在无需特殊处理的情况下仍然有效。
