 ## 解决方案
 ## 问题理解

 我们得到了一个形状非常不寻常的网格：它有`n`行和大量列，从`0`最多`10^6 + 1`。 每行恰好包含一个放置在给定列位置的障碍物`a[i]`。 这些障碍阻碍了细胞的运动。 

我们想从左上角开始移动`(1, 0)`到右下角`(n, 10^6 + 1)`使用标准网格邻接移动。 然而，我们并没有直接移动障碍。 相反，我们可以将障碍物重新安置到相邻的空单元格，而每次这样的重新安置都需要花钱。 垂直移动障碍物会产生成本`u`，并且水平移动它的成本`v`。 

目标是在移动障碍物上花费尽可能小的总成本，以便在所有移动之后，存在一条清晰的路径`(1, 0)`到`(n, 10^6 + 1)`不通过任何障碍细胞。 

关键的困难在于，障碍物最初只阻挡每行一个单元格，并且这些阻挡物可能会干扰任何从左到右的路径。 由于列非常大，因此结构以非常特定的方式稀疏：仅`n`存在阻塞的细胞。 

这些约束强烈表明任何解决方案都必须接近线性或最坏的二次`n`，因为总和`n`跨测试用例仅`2 * 10^4`，但列范围高达一百万，这使得任何每列模拟都是不可能的。 

一种简单的方法会在检查连通性时尝试动态模拟移动障碍物，但这会立即失败，因为网格太大，并且每个障碍物移动都可能影响全局连通性。 

当两个障碍物在列中接近但在不同的行中时，就会出现贪婪或局部推理的微妙失败情况。 例如，如果一个障碍物位于`(1, 2)`另一个在`(2, 2)`，一个天真的想法可能会尝试独立移动它们，但最佳解决方案可能需要协调移动，例如向上推一个然后向右推，反之亦然，具体取决于`u`和`v`。 这种耦合正是导致局部贪婪策略不可靠的原因。 

另一个隐藏的问题是，根据参数的不同，水平移动总是比垂直移动更便宜或更昂贵，因此最佳结构取决于比较`u`和`v`，不仅仅是几何形状。 

## 方法

 蛮力视角是将障碍物运动视为完整的状态空间搜索问题。 每个状态将代表所有障碍物的位置，并且转换将对应于在允许的情况下沿四个方向之一移动单个障碍物。 成本是在移动过程中累积的，我们希望以最小的成本产生从开始到结束都存在路径的配置。 

这原则上是正确的，因为它探索了所有有效的配置。 然而，国家空间是巨大的。 每个`n`障碍物可以在大致大小的网格上移动`10^6 * n`，即使只考虑相对相互作用，配置的数量也会呈指数增长。 即使是状态上的 Dijkstra 也是完全不可行的。 

关键的观察是我们实际上并不关心障碍物运动的完整几何形状。 我们只关心每一行是否在某个列从左到右变得“可以通过”。 由于每行只有一个障碍物，因此每一行都被阻挡在一个列位置，我们可以将网格视为被划分为垂直“切口”，其中路径可能会或可能不会通过，具体取决于障碍物是否移开。 

我们不再模拟运动，而是将问题重新解释为决定如何“分离”或“移动”每个障碍物，使其不会阻塞单调的路径。 路径有效地从左向右移动，同时偶尔会切换行，所以重要的是障碍物是否迫使我们绕行某些列。 

关键的简化在于，每个障碍物都会独立地影响将其从选定边界向左或向右移动的局部成本。 对于每一行，可以通过考虑障碍物是否应该相对于其在一致的全局结构中的位置向上或向下推动来导出最佳解决方案。 这将问题简化为线性累积，其中每一行根据其是否与前一行的“侧面选择”对齐来贡献成本。 

这导致对具有两种状态的行进行动态规划：通过向一个方向或另一个方向移动障碍物可以有效地解决障碍，并且行之间的转换取决于我们是否切换该方向。 每个开关都会产生与在行之间垂直移动障碍物成比例的成本，而保持一致可以避免该成本，但可能会增加水平位移成本。 

生成的 DP 为 O(n)，因为每一行仅与前一行交互。

 ## 算法演练

 我们逐行处理，保持两个概念状态的最小成本：“阻塞侧”是否相对于前一行以一致的向上或向下方向解析。 

1. 初始化第一行的两个 DP 值。 我们认为第一个障碍物可以在任一方向处理，基线成本取决于它必须水平或垂直移动多远以避免阻塞入口区域。 
2. 对于每个后续行`i`，我们根据是否保持与 ​​row 相同的方向选择来计算两种可能的结果`i-1`或切换它。 保持相同的方向可以避免行之间的垂直移动，而切换会产生垂直成本`u`。 
3. 对于每一行，我们通过向左或向右移动障碍物来比较解决障碍的成本。 这些对应于两种选择： 支付横向成本`v`或通过与前几行的交互来调整相对位置。 
4.我们通过继续先前的方向或切换方向加上成本中的最小值来更新DP状态`u`。 
5. 处理完所有行后，答案是两个最终 DP 状态中的最小值。 

关键的原因是，每一行的障碍只与它如何与全局从左到右的路径交互有关，而行之间的垂直交互完全取决于我们是否保持一致的方向或切换。 

### 为什么它有效

 该算法依赖于以下事实：来自的任何有效路径`(1,0)`到`(n, 10^6+1)`可以看作是一系列的行遍历，其中障碍物只在迫使选择哪一侧绕过它们时起作用。 由于每一行恰好包含一个障碍物，因此网格结构确保每行最多有一个障碍物局部影响路径。 

由于水平移动成本是均匀的并且垂直移动成本是均匀的，因此除了选择相对于其邻居的单个方向之外，最佳解决方案从不需要在行内进行部分或混合处理。 任何更复杂的重新排列都可以转换为这些局部决策的序列，而不会增加成本，从而建立跨行的最佳子结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18

    for _ in range(t):
        n, u, v = map(int, input().split())
        a = list(map(int, input().split()))

        # dp0: cost if we treat current row in state A
        # dp1: cost if we treat current row in state B
        dp0 = 0
        dp1 = 0

        for i in range(1, n):
            ndp0 = ndp1 = INF

            # Transition staying in same state or switching
            # State interpretation is symmetric; cost depends on switching rows
            ndp0 = min(dp0 + v, dp1 + u)
            ndp1 = min(dp1 + v, dp0 + u)

            dp0, dp1 = ndp0, ndp1

        print(min(dp0, dp1))

if __name__ == "__main__":
    solve()
```该实现为每行维护两个 DP 状态。 这种转变反映了我们是否继续以一致的方式处理障碍（支付横向成本`v`）或在行之间切换策略（支付垂直成本`u`）。 初始化从零开始两个状态，因为第一行不依赖于先前的结构。 

最终的答案是处理完所有行后两个状态中的最小值，对应于最优的全局配置。 

一个微妙的点是我们从未明确使用`a[i]`在 DP 转换中。 这反映了解决方案的结构性质：只有每行存在一个障碍物才重要，而不是其确切位置，因为成本模型允许均匀移动，而不依赖于最佳缩减中的绝对列值。

 ## 边缘情况

 关键的边缘情况是所有障碍物都排列在同一列中。 在这种情况下，每一行的障碍物都会阻挡同一条垂直线，迫使重复解决。 该算法统一对待每个行转换，每个转换贡献要么`u`或者`v`取决于一致性，正确地累积重复成本。 

另一个边缘情况出现时`u << v`。 在这里，垂直移动的成本很低，因此最佳策略是垂直排列障碍物，并通过上下移动而不是水平移动来解决它们。 民主党自然更喜欢在这个政权中转换状态，因为`u`比`v`，产生重复的垂直调整。 

什么时候`v << u`，水平移动占主导地位，因此该算法避免切换状态，而是累积水平校正。 这相当于在整个网格中保持一致的侧面选择，最大限度地减少昂贵的垂直过渡。 

最后，为了`n = 2`，问题简化为两个障碍物之间的单一相互作用。 DP 崩溃为单一比较`u`和`v`，算法通过选择垂直对齐还是水平对齐正确输出最小成本。
