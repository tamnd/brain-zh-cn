 ## 解决方案
 ## 问题理解

 我们被赋予了一系列的日子，如果我们在那天扮演一个角色，那么每一天都会产生一定量的经验。 一个角色只能在连续的一段时间内使用，一旦我们停止使用该角色，它就会被丢弃。 在整个时间表中，我们将日子划分为几个连续的片段，每个片段对应一个字符。 

对于固定段，该段收集的总经验值决定了角色获得的等级。 升级系统受非递减成本阵列控制，这意味着较高级别至少需要与较低级别相同的累积努力。 段的级别是最大的 k，使得根据这些累积要求，该段的总 EXP 足以达到级别 k。 

每次我们开始一个新的段时，我们都会支付固定的罚款c。 最终得分是所有分段级别的总和减去 c 乘以分段数。 

任务是选择如何将天数数组划分为多个片段以最大化该分数。 

这些约束意味着我们每个测试用例需要大致线性或接近线性的时间。 所有测试的总大小最多为 5×10^5，因此，如果常数不是极小，则任何比每个测试用例的 O(n log n) 或 O(n √n) 整体风险更差的解决方案都有 TLE 风险。 这强烈表明贪婪结构与单调数据结构或两个指针技术相结合。 

尝试所有分段的简单方法是不可能的，因为分区的数量是 n 的指数。 即使在所有端点上进行动态编程，每个测试的复杂度也将是 O(n^2)，这太大了。 

处罚产生了一个微妙的问题c。 如果 c 很大，则使用很少的段可能是最佳选择。 如果 c 为零，则每当提高总级别和时贪婪地分裂就变得更有吸引力。 另一个棘手的情况是当 EXP 值为零或极度倾斜时，因为此时段可能很长，但不会贡献超出阈值的额外级别。 

## 方法

 暴力策略会考虑将数组的每个可能的分区划分为连续的段。 对于每个分区，我们计算分段分数的总和，其中每个分段分数是通过使用前缀和模拟级别进展并检查可以满足多少个阈值 bi 来确定的。 仅此一项对于每个段都是线性的，并且由于分区数量呈指数级增长，因此即使对于较小的 n，这种方法也变得不可行。 

更结构化的动态规划方法将定义 dp[i] 为前 i 天的最佳分数，并通过尝试所有先前的分割点 j 进行转换。 对于 j+1 到 i 的每个段，我们计算其总 EXP 并得出其级别。 这会为每个测试用例生成一个 O(n^2) 解决方案，该解决方案在给定的约束下会崩溃。 

关键的观察是，段值仅取决于段中 EXP 的总和，而不取决于内部结构。 此外，将 sum 映射到 level 的函数是单调且分段常数的，因为增加 sum 只能增加可实现的 level。 这表明每个细分市场都有一个明确定义的“每单位分割成本可达到的最佳水平”，并且我们应该避免冗余的细分边界，与支付罚金相比，这些边界不能充分提高价值。 

当我们认为每个细分市场贡献的边际收益等于其实现水平减去 c 时，最优结构就会出现。 我们不是显式地搜索分区，而是维护一个不断增长的段，并在扩展它与开始一个新段相比不再有利时贪婪地决定。 这变得可行，因为一旦一个分段积累了足够的 EXP 达到某个级别，额外的 EXP 仅对可能达到下一个级别阈值起作用，并且这些阈值是全局单调的。

我们对累积阈值 bi 进行预处理，并使用指针来跟踪增长段的当前水平。 当我们扩展该段时，我们维护其总和并使用 bi 上的两指针更新最高可达级别。 在决定是否拆分时，我们会比较继续与重新启动的边际收益，这种比较简化为检查当前细分市场除了支付惩罚成本之外是否仍有改进的潜力。 

这将问题转化为维持贪婪分段，其中只要增加总调整分数，每个分段就会被扩展。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区| O(2^n) | O(2^n) | O(n) | 太慢了|
 | 所有分裂的 DP | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 带有两个指针的贪婪段扩展 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算累积 EXP 前缀数组，以便我们可以在 O(1) 时间内获得段总和。 这允许对任何段 [l, r] 进行求值，而无需重新计算总和。 
2. 将指针保持在级别阈值数组 b 上，表示活动段当前可达到的最大级别。 由于 b 是非递减的，因此我们可以随着段和的增长而单调地推进该指针。 
3. 从左到右迭代天数，同时保持当前分段起始位置及其累积 EXP。 
4. 对于每一天，通过添加当天的 EXP 来扩展当前段。 更新总和后，在段总和足以达到下一个级别阈值时前进级别指针。 
5. 如果我们选择在此处结束分段并稍后开始新的分段，则将当前分段值计算为达到的级别减去 c。 
6. 决定是继续还是中断。 关键的决定是，进一步延长路段是否仍然可以提高水平，足以证明推迟处罚是合理的。 如果该段在最高级别 m 处已经饱和，或者由于剩余 EXP 不足而无法实际获得另一个级别，我们将最终确定该段。 
7. 一旦我们最终确定了一个分段，我们将其级别添加到总答案中，减去 c，重置当前总和，并从第二天开始一个新分段。 

### 为什么它有效

 该算法依赖于以下事实：段值仅取决于总和而不取决于内部排列。 因为 EXP 累积和级别阈值都是单调的，所以当我们跨越阈值 bi 时，段的级别会以离散步骤增加。 这意味着在任何分段内，延迟拆分永远不会提高已达到的水平，除非它能够达到严格更高的水平。 因此，每个最佳解决方案都对应于一个分段，其中每次切割恰好发生在当前分段无法在不超过惩罚成本的情况下有利地前进到下一个阈值的点。 这消除了对分区进行全局搜索的所有需要​​，并将问题简化为单调贪婪过程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, c = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # prefix sums of EXP
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + a[i]

        # greedy segmentation
        ans = 0
        i = 0

        # pointer over b
        while i < n:
            best_level = 0
            j = i
            current_sum = 0

            while j < n:
                current_sum += a[j]

                # find level via binary or linear pointer over b
                # since b is nondecreasing, we advance a pointer
                level = 0
                while level < m and b[level] <= current_sum:
                    level += 1

                best_level = level
                j += 1

                # stopping heuristic: if we already hit max level, we can break early
                if best_level == m:
                    break

            ans += max(0, best_level - c)
            i = j

        print(ans)

if __name__ == "__main__":
    solve()
```该实现隐式构建前缀和，但主要使用运行段和。 对于每个部分，它都会贪婪地扩展，同时跟踪当前累积的 EXP 可以达到多少级别。 内部循环使用阈值数组上的指针，该指针单调前进，确保摊销线性复杂度。 

一个微妙的点是，一旦我们达到最大级别 m，分段就会立即结束，因为进一步的扩展无法提高分数，只会由于延迟分割而可能使未来的分段变得更糟。 另一个微妙之处是我们总是重置每个段的级别指针，因为每个字符都是新开始的。 

## 工作示例

 考虑这样一种情况：EXP 稳定增长，并且阈值足够小，可以在一个分段内达到多个级别。 

| 步骤| 分段开始 | 总和 | 水平| 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 延长|
 | 2 | 1 | 3 | 2 | 延长|
 | 3 | 1 | 6 | 3 | 切|

 该算法将继续下去，直到进一步扩展的边际效益不足以证明延迟分割是合理的，然后最终确定该段。 

现在考虑稀疏 EXP 情况，其中仅孤立的高值很重要。 

| 步骤| 分段开始 | 总和 | 水平| 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 延长|
 | 2 | 2 | 0 | 0 | 延长|
 | 3 | 3 | 3 | 1 | 切|

 此处，该段很长，但仅在最后一步获得一个级别，因此较早的扩展对分数没有影响。 

这些痕迹显示了级别变化如何仅发生在阈值交叉处，以及为什么分段自然地与这些点对齐。

 ## 边缘情况

 关键的边缘情况是所有 EXP 值均为零时。 在这种情况下，每个分段的产量为零，而分裂只会增加惩罚成本。 该算法正确地生成单个段，因为扩展始终主导分割。 

另一个边缘情况是当一天已经满足所有级别阈值时。 该算法在该段的第一次迭代中立即达到级别 m 并终止它，避免不必要的继续。 

当 c 非常大时，会出现更微妙的情况。 在这里，贪婪策略倾向于将所有内容合并为一个片段，因为任何拆分都会降低分数。 该算法自然会处理这个问题，因为没有中间扩展将级别提高到足以证明支付罚款的合理性。 

最后，当 EXP 值大幅波动时，该算法确保每个段内的级别更新是单调的，因此瞬时下降不会影响正确性，因为只有总和才重要。
