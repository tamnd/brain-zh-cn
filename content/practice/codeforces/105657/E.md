 ## 解决方案
 ## 问题理解

 每个任务代表一个人，必须使用单部电梯从起始楼层接人并下降到更高的楼层。 电梯从某个初始楼层开始，一次只能运载一个人。 向上移动消耗的能量与移动的楼层数成正比，而向下移动则免费。 

每个人缴纳的固定出行费用等于其出发楼层和目的地楼层之间的距离。 这部分是不可避免的，并且不取决于为人们提供服务的顺序。 唯一取决于顺序的部分是“死行程”，即电梯从结束一个人移动到开始下一个人时，特别是当我们必须从上一个下客楼层向上移动到下一个上客楼层时。 

因此，问题不在于优化单个行程，而在于安排这些行程，以便电梯避免连续作业之间不必要的向上跳跃。 

这些限制允许每个测试用例最多 100,000 人，总共最多 300,000 人。 这立即排除了任何对排列的二次排序尝试。 任何解决方案都必须依赖于排序加上线性或近线性贪婪结构，由于优先级队列或排序，通常为 O(n log n)。 

一种幼稚的方法会尝试所有的人排列，甚至是贪婪的本地交换。 这会失败，因为成本交互是全局的：选择稍差的下一个间隔可能会在以后实现一长串零成本转换。 

当贪婪的选择忽略了未来的可用性时，就会出现微妙的失败情况。 

例如，考虑：```
f = 1
(1, 100), (2, 3), (3, 4)
```如果我们首先选择 (1, 100)，则最终结果为 100，其他所有内容都是免费的。 如果我们先选择(2, 3)，那么我们会以3结束，并且仍然可以免费获得(3, 4)，但随后我们必须跳到(1, 100)，付出很大的成本。 排序以非本地方式起作用，因此我们需要一个能够最大限度地提高未来可访问性的结构。 

## 方法

 关键的观察结果是，每个人贡献的成本等于其乘坐长度。 该部分永远不会随着订购而改变。 唯一的优化目标是连续骑行之间的向上跳跃的总和。 

这将问题简化为按时间间隔进行调度任务，其中每个作业将当前位置从 li 移动到 ri。 完成作业后，系统位于 ri。 转移到下一个工作的成本为 max(0, next_li − current_position)。 

强力解决方案将枚举所有排列并模拟该过程。 每次模拟的时间复杂度为 O(n)，总体上为 O(n · n!)，即使 n 约为 10，这也远远超出了可行性。 

更好但仍然不正确的方法是单独按 li 或 ri 排序。 按 li 增加进行排序感觉很自然，因为它减少了拾取器之间的跳跃，但它可能会使我们过早陷入较低的 r 值，限制未来的范围并迫使稍后进行昂贵的跳跃。 

正确的结构来自于将流程视为“范围扩展”问题。 一旦我们处于某个职位，我们应该总是优先选择那些我们已经可以开始而无需支付任何向上成本的工作，这意味着 li ≤ 当前职位。 其中，我们想要选择对我们推动力最高的工作，因为更高的 ri 只会增加我们可以免费从事的未来工作的范围。 如果当前没有可用的作业，我们必须跳转到下一个可用的 li。 

这导致了一个贪婪的过程，对排序的 li 进行扫描，对 ri 进行优先级队列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·n!) | O(n·n!) | O(n) | 太慢了 |
 | 贪婪+堆| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将所有人处理为区间（li，ri）。 我们维护一个排序间隔上的指针和一个由 ri 键控的最大堆。 

1. 按里升序对所有人员进行排序。 这使我们能够有效地发现当电梯向上移动时哪些工作可以进行。 
2. 在起始楼层f 初始化当前位置。 
3. 在排序列表和最大堆上维护一个指针 i。 堆存储所有 li ≤ 当前位置的人，按最大 ri 优先排序。 这确保我们总是在所有立即可行的工作中选择最能扩大我们影响范围的工作。 
4. 当还有未处理的人或者堆不为空时，我们首先将所有 li ≤ 当前位置的人压入堆。 这模拟显示我们当前可以开始的所有工作，而无需支付额外的费用。 
5. 如果堆不为空，我们弹出 ri 最大的人。 我们将此人添加到输出订单中，并概念性地将电梯移动到 ri。 此步骤中不添加向上成本，因为 li ≤ 当前位置保证拾取是免费的。 
6. 如果堆为空，则当前无法访问任何作业。 我们必须向上移动到下一个可用的工作里。 我们选择剩余作业中最小的 li，支付 max(0, li − 当前位置)，然后在处理该作业后将当前位置设置为 ri。 
7. 重复此操作，直至处理完所有人员。 

### 为什么它有效

 在任何时刻，所有 li ≤ 当前职位的工作就直接可行性而言都是可以互换的。 选择具有最大 ri 的选项会严格支配其他选项，因为它可以在不增加当前成本的情况下最大化未来的可用性。 当没有工作可及时，下一次强制跳跃是不可避免的，选择最小的li可以确保最小的必要向上移动。 这保持了不变性，即在已支付成本的情况下，当前头寸始终尽可能大，从而防止未来不必要的向上跳跃。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    T = int(input())
    for _ in range(T):
        n, f = map(int, input().split())
        people = []
        for i in range(n):
            l, r = map(int, input().split())
            people.append((l, r, i + 1))
        
        people.sort()
        
        ans = []
        heap = []
        i = 0
        cur = f
        
        while i < n or heap:
            while i < n and people[i][0] <= cur:
                l, r, idx = people[i]
                heapq.heappush(heap, (-r, l, idx))
                i += 1
            
            if heap:
                neg_r, l, idx = heapq.heappop(heap)
                ans.append(idx)
                cur = -neg_r
            else:
                l, r, idx = people[i]
                cur = max(cur, l)
                heapq.heappush(heap, (-r, l, idx))
        
        print(sum(people[idx - 1][1] - people[idx - 1][0] for idx in ans), *ans)

if __name__ == "__main__":
    solve()
```该实现首先按起始楼层对所有间隔进行排序，这允许线性扫描，随着当前电梯位置的增加逐渐暴露可用的作业。 堆存储可到达的作业，按最高目标楼层排序，确保我们始终尽可能积极地扩展可到达范围。 

每当我们完成一个工作时，当前位置就会更新，如果没有工作可到达，我们会直接跳到下一个起始楼层。 这避免了重复扫描不可行的候选者。 

一个微妙的点是，在此实现中打印的最终成本是使用常和观察根据所选顺序重新计算的。 在生产环境中，通常会在模拟过程中逐步累积转换成本，但重新计算更简单，并且可以避免堆转换中的错误。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    input = sys.stdin.readline
    import heapq

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            n, f = map(int, input().split())
            a = []
            for i in range(n):
                l, r = map(int, input().split())
                a.append((l, r, i + 1))
            a.sort()

            i = 0
            cur = f
            heap = []
            order = []

            while i < n or heap:
                while i < n and a[i][0] <= cur:
                    l, r, idx = a[i]
                    heapq.heappush(heap, (-r, l, idx))
                    i += 1
                if heap:
                    nr, l, idx = heapq.heappop(heap)
                    order.append(idx)
                    cur = -nr
                else:
                    l, r, idx = a[i]
                    cur = max(cur, l)
                    heapq.heappush(heap, (-r, l, idx))

            # cost recompute
            pos = f
            cost = 0
            for idx in order:
                l, r = [(a[j][0], a[j][1]) for j in range(n) if a[j][2] == idx][0]
                cost += max(l - pos, 0)
                cost += r - l
                pos = r

            out.append(str(cost))
            out.append(" ".join(map(str, order)))
        return "\n".join(out)

    return solve()

 ## 边缘情况

 当起始楼层已经高于所有 li 值时，就会出现关键的边缘情况。 该算法立即将所有作业视为可达，并纯粹依赖于选择最大 ri，这从一开始就避免了不必要的向上移动。 

另一种边缘情况是当间隔相距很远时，会强制进行多次重置。 在这种情况下，堆会反复变空，而正确性取决于总是跳转到下一个最小的 li。 贪婪结构确保我们永远不会跳过较小的 li，否则会减少下一个强制跳转。 

最后的边缘情况是多个间隔共享相同的 li 但具有不同的 ri。 堆保证仅首先选择 ri 最大的区间，从而保持可达性并避免过早承诺较低的目的地。
