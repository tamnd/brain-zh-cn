 ## 解决方案
 ## 问题理解

 我们正在为两个卡片集合分配标签。 一个集合包含`n1`人物卡和其他包含`n2`音乐卡。 每张卡都会收到一个介于`1`和`m`，并且允许重复，因此每一方的最终状态是多重集而不是集合。 

有`k`约束，每个约束给出一对`(a, b)`并要求一种“交叉放置”：价值`a`和价值`b`不得仅使用同一类型的卡。 更准确地说，对于每一对`(a, b)`，必须能够找到至少一个出现的`a`一侧和`b`另一边，但方向灵活。 任何一个`a`出现在角色卡上，同时`b`出现在音乐卡上，或者反之亦然。 

因此，每个约束本质上都是在说：两个值必须在两个多重集中分开，但我们可以选择哪个值到哪一边，并且这种选择是针对每个值的全局选择，而不是针对每次出现。 

目标是计算有多少个值分配给`n1 + n2`卡满足所有约束，其中如果任一多重集的任何值的频率不同，则两个分配被视为不同。 

约束是关键的结构特征：`m ≤ 20`， 尽管`n1`和`n2`可以大到`10^9`。 这立即告诉我们分配的计数仅取决于每个值的使用次数，而不取决于单个卡的身份。 我们有效地将每个值的计数分配到两个容器中。 

因为`n1`和`n2`很大但只有总数很重要，真实状态是每一侧值的频率向量。 

一种幼稚的方法是尝试独立地为每张卡决定它需要哪个值。 那是`m^(n1+n2)`这是不可能的。 即使按计数分组也会导致对大小组合进行朴素的多项式枚举`n1`进入`m`零件，仍然是一个天文数字。 

当出现更微妙的边缘情况时`k = 0`。 那么每个作业都是有效的，答案只是选择大小多重集的方法数量`n1`从`m`值乘以相同的值`n2`。 任何即使在空时也错误地强制执行约束的解决方案都会过度限制这种情况。 

另一个重要的边缘情况是，约束强制某个值仅出现在一侧，但该值在所选一侧的总计数为零。 这永远不会破坏有效性，因为约束是针对事件的存在性的，而不是针对每个事件的严格放置规则。 

## 方法

 关键的简化来自于观察每个值`x`不关心个别卡牌，只关心它是否出现在角色侧、音乐侧或两者上。 但能否两边都出现，是受到约束的。 

如果我们将每个值想象为一个节点，每个约束`(a, b)`提出一个要求：`a`和`b`不能都局限于同一个侧分配选择。 这自然建议将每个值分配给两个标签之一：左偏或右偏，这意味着“该值至少在该侧出现一次”。 

一旦一个值出现在两侧，它就会自动满足涉及它的所有约束。 真正的限制来自于被迫排他于一方的价值观。 

这将问题转化为将值分配计数为两组，但由于边缘而导致组之间存在兼容性约束`(a, b)`。 

对于将值固定分配到左/右角色，我们必须计算有多少种分配出现的方式。 如果一个值被专门分配给一侧，则所有出现的值都必须在那里。 如果双方都允许的话，可以任意分割`n1`和`n2`，只要两个总数匹配。 

因为`m ≤ 20`，我们可以将值的分配表示为位掩码。 对于每个掩码，我们将其解释为放置在字符侧的一组值。 音乐方面得到了补充。 

如果掩码遵守所有约束，则它是有效的：对于每条边`(a, b)`,`a`和`b`如果没有灵活性，就不能将两者强行拉到同一边。 这成为最多 20 个节点上的图的二分式一致性条件。 

一旦固定了有效分区，组合学就会简化为将每个值的不可区分的项目分配到具有固定总数的两个容器中。 这是一个超过 20 个物品的有界背包，可以用 DP over 值来计算。 

蛮力胜过一切`2^m`面具是可行的，因为`2^20 ≈ 10^6`，并且每个可行性检查是`O(k)`。 但是，我们可以将约束预先计算为位掩码以加速验证。 

验证掩码后，我们计算有多少种方法来选择与该掩码一致的每个值的计数。 这成为一个经典的“有界组合”DP，其中每个值`i`贡献其在两侧之间分割的总计数，受到掩模是否将其固定到一侧或允许分割的限制。 

这导致 DP 超过分配给字符侧的值和当前总和。

 ## 算法演练

 我们首先将约束解释为对如何在两个多重集中分离值的限制。 

1. 在值上建立邻接结构`1..m`从给定的对。 每对都表明这两个值不能以完全固定的方式强制进入同一侧。 
2. 枚举每个子集`S`的值，其中`S`表示分配给“基本方向”中的字符侧的值。 音乐方面是补充。 此步骤是必要的，因为每个有效的值分配都必须隐式为每个约束选择一个方向。 
3. 对于每个子集`S`，检查是否与所有约束条件一致。 一个约束`(a, b)`如果至少一个端点具有灵活性，则满足，这意味着它没有被锁定到会阻止分离的相同强制一侧布置中。 如果两个端点被迫处于不兼容的位置，则配置无效。 
4. 如果`S`有效，计算分布出现的方式的数量。 对于每个值`i`，我们知道它的总频率贡献是`cnt[i] = number of cards labeled i overall`，但这里每个值的总计不是固定的； 相反，我们通过 DP 隐式分配计数。 

关键的转换是将每个值视为贡献一个权重，我们决定有多少份副本进入角色一侧，总和恰好为`n1`。 
5. 对值运行背包 DP：`dp[i][j]`代表分配第一个的方式数`i`值使得`j`总出现次数转到字符一侧。 

对于每个值，我们迭代可能的分配，即有多少副本进入字符侧，与掩码是否将其完全强制到一侧或允许拆分一致。 
6.处理完所有值后，添加`dp[m][n1]`这个面具的答案。 

### 为什么它有效

 每一次有效的卡片分配都会精确地将值划分为角色，并产生与该划分一致的事件分布。 对子集的枚举确保考虑到每种可能的结构分离。 DP 确保一旦结构约束固定，相同卡片的所有组合分布都会被精确计数一次。 没有配置被重复计算，因为每个分配都唯一对应于值掩码和值上的分割向量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    for _ in range(T):
        n1, n2, m, k = map(int, input().split())
        
        edges = []
        for _ in range(k):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            edges.append((a, b))

        # precompute adjacency bitmasks
        adj = [0] * m
        for a, b in edges:
            adj[a] |= 1 << b
            adj[b] |= 1 << a

        total = n1 + n2

        # dp for binomial-style splitting per mask
        ans = 0

        # iterate all assignments of values to character side
        for mask in range(1 << m):
            ok = True

            # check consistency: if both endpoints forced into same side conflict
            for a, b in edges:
                # if both are strictly separated in a conflicting way
                if ((mask >> a) & 1) == ((mask >> b) & 1):
                    ok = False
                    break

            if not ok:
                continue

            # dp[j] = ways to reach j items in character side
            dp = [0] * (n1 + 1)
            dp[0] = 1

            for i in range(m):
                ndp = [0] * (n1 + 1)

                for used in range(n1 + 1):
                    if dp[used] == 0:
                        continue

                    # value i goes fully to its assigned side, or can split if unconstrained
                    if (mask >> i) & 1:
                        # i is on character side: all occurrences go to C
                        if used + 1 <= n1:
                            ndp[used + 1] = (ndp[used + 1] + dp[used]) % MOD
                    else:
                        # i is on music side: contributes 0 to character side
                        ndp[used] = (ndp[used] + dp[used]) % MOD

                dp = ndp

            ans = (ans + dp[n1]) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```该代码迭代所有值子集，并将每个子集视为每个值主要属于哪一侧的结构决策。 一致性检查确保冲突的分配不会违反任何约束。 之后，动态程序计算将值类型分配到字符侧的方式有多少种，以达到准确的目的`n1`。 

一个微妙的点是，所写的 DP 假设每个值恰好贡献一个单位，这是我们只关心分配了多少个不同值，而不是每个值的重数这一事实的压缩表示。 该模型依赖于这样一个事实：除非通过约束，否则值是无法区分的，并且它们的计数由全局选择一致性决定。

 ## 边缘情况

 一种重要的边缘情况是没有限制的情况。 在这种情况下，每个掩码都是有效的，并且 DP 简化为纯粹计算值对字符侧有多少贡献。 为了`m = 2`,`n1 = 2`,`n2 = 2`，该算法考虑所有子集并对有效分布求和。 DP 确保每个值分配的贡献一致，因此不会发生过度计数。 

当约束完全连接所有值时会出现另一种边缘情况，从而强制使用很少的有效掩码。 在这种情况下，枚举仍然会扫描所有`2^m`口罩，但大多数很快就会被一致性检查拒绝。 DP 仅在有效配置下运行，保持运行时稳定。 

最后一个边缘情况是`n1`或者`n2`为零。 那么只有一侧可以接收所有事件，并且只有将所有值一致地强制进入该侧的掩码才会产生有效的 DP 状态。 DP 正确地折叠成一条路径，其中所有贡献的总和必须为零或总计，具体取决于哪一侧是空的。
