 ## 解决方案
 # 问题理解

 任务是计算一年中书写每个日历日期的铅笔总成本`A`全年`B`。 通过连接月份数和日数来表示不带年份的日期。 例如，3 月 7 日变为`37`，而 12 月 24 日则变为`1224`。 写入日期的成本是该表示本身的数值。 

一年中唯一影响答案的部分是 2 月有 28 天还是 29 天。 输入给出两年，可能大到`10^18`，输出是所有这些年的所有日期值的总和，减少模数`104206969`。 

年份的大小立即排除了对年份或日期的迭代。 一个范围包含`10^18`年大约需要`10^18 * 365`日期计算，这远远超出了程序在合理时间内可以完成的工作。 该解决方案必须利用这样一个事实：大多数年份都是相同的，只有闰年才重要。 

有几个地方直接实施可能会失败。 年`0`就是其中之一。 它满足闰年规则，因为它可以被 400 整除，所以输入`0 0`必须使用有 29 天的二月并产生`180987`。 一种从以下位置开始计算闰年的解决方案`1`会错误地将其视为正常年份。 

另一个陷阱是世纪规则。 输入`1900 1900`是一个正常的年份，尽管它能被 4 整除，因为它也能被 100 整除，而不是被 400 整除。它的答案是`180758`。 仅使用 4 整除的解决方案将返回闰年值。 

相反的边界出现在`2000 2000`。 今年能被 400 整除，所以是闰年，答案是`180987`。 拒绝所有世纪年作为非闰年的解决方案在这里失败了。 

# 方法

 强力解决方案将处理间隔中的每一年，确定它是否是闰年，然后循环遍历其十二个月以及这些月份内的所有日期。 对于每一天，它都会构建日期值并将其添加到答案中。 这是正确的，因为它直接遵循定义。 

然而，最大可能的区间包含大约`10^18`年。 即使每年进行一次恒定时间操作也已经太慢了，并且完整的日期模拟将需要大约`3.65 * 10^20`日间运营。 日历的重复结构是消除这种需要的关键观察。 

每个正常年份的贡献量完全相同，因为它的月份长度永远不会改变。 每个闰年也贡献完全相同的金额。 我们不需要对各个年份进行求和，而只需计算该范围内出现了多少个正常年和闰年。 

一个月`m`和`L`天，前九天贡献表格的值`10m + day`，其余天数贡献以下形式的值`100m + day`。 将这两部分结合起来可以得到一个直接的公式：`month_sum = m * (100L - 810) + L(L+1)/2`对所有月份使用此值可以得到平年和闰年的固定贡献。 

剩下的问题是计算闰年`0`到给定的年份。 年数可以除以`k`从`0`通过`n`是`n//k + 1`，因为零年也包含在内。 包含-排除给出跳跃计数：`multiples of 4 - multiples of 100 + multiples of 400`使用前缀函数多年`0..n`让我们用减法来回答任何区间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(年数 * 365) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 # 算法演练

 1. 预先计算一个平年和一个闰年的贡献。 对于每个月，应用该月所有编码日期总和的公式。 这避免了重复地重新计算相同的日历模式。 
2. 创建前缀函数`pref(x)`返回所有年份的总贡献`0`通过`x`。 如果`x`为负数，前缀为零，因为零之前没有年份。 
3. 使用能被 4、100 和 400 整除的方式计算前缀范围内的闰年。其余年份为正常年份，因此将这两个计数乘以各自的年度贡献。 
4. 通过减去前缀来计算请求的间隔：`pref(B) - pref(A-1)`。 减去后应用模数以保持结果为正。 

为什么有效：每年都属于两个类别之一：正常年份或闰年。 所有正常年份都有相同的十二个月长度，因此它们的贡献量相同。 闰年也是如此。 前缀函数精确计算每种类型存在的年数，这意味着总和是这两个固定贡献的精确组合。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 104206969

def year_value(leap):
    days = [31, 29 if leap else 28, 31, 30, 31, 30,
            31, 31, 30, 31, 30, 31]

    total = 0
    for month, length in enumerate(days, 1):
        total += month * (100 * length - 810)
        total += length * (length + 1) // 2
    return total % MOD

NORMAL_YEAR = year_value(False)
LEAP_YEAR = year_value(True)

def leap_count(x):
    if x < 0:
        return 0
    return (x // 4 + 1) - (x // 100 + 1) + (x // 400 + 1)

def prefix(x):
    if x < 0:
        return 0

    leaps = leap_count(x)
    years = x + 1
    normal = years - leaps

    return (normal * NORMAL_YEAR + leaps * LEAP_YEAR) % MOD

def solve():
    A, B = map(int, input().split())
    print((prefix(B) - prefix(A - 1)) % MOD)

solve()
```

`year_value`将所有十二个月压缩为一次计算。 该公式同时处理一位数和两位数的日期，从而避免循环遍历各个日期。`leap_count`故意使用`x//k + 1`而不是仅仅`x//k`。 额外的一年代表零年，它遵循与其他年份相同的整除规则。 

前缀计算使用`x + 1`年，因为间隔从零开始并包括两个端点。 最后的减法使用`A - 1`，所以这一年`A`其本身仍然包含在内。 

Python 整数不会溢出，但中间值可能会变大。 返回前缀值时应用模数，最终答案也用`% MOD`因为减法可能是负数。

import sys
import io

MOD = 104206969

def year_value(leap):
    days = [31, 29 if leap else 28, 31, 30, 31, 30,
            31, 31, 30, 31, 30, 31]
    total = 0
    for month, length in enumerate(days, 1):
        total += month * (100 * length - 810)
        total += length * (length + 1) // 2
    return total % MOD

NORMAL_YEAR = year_value(False)
LEAP_YEAR = year_value(True)

def leap_count(x):
    if x < 0:
        return 0
    return (x // 4 + 1) - (x // 100 + 1) + (x // 400 + 1)

def prefix(x):
    if x < 0:
        return 0
    l = leap_count(x)
    return ((x + 1 - l) * NORMAL_YEAR + l * LEAP_YEAR) % MOD

def solve_case(inp):
    a, b = map(int, inp.split())
    return str((prefix(b) - prefix(a - 1)) % MOD)

assert solve_case("1 3") == "542274", "sample"
assert solve_case("0 0") == "180987", "year zero leap"
assert solve_case("1 1") == "180758", "single normal year"
assert solve_case("1900 1900") == "180758", "century non leap"
assert solve_case("2000 2000") == "180987", "century leap"
assert solve_case("1000000000000000000 1000000000000000000") == "180987", "maximum year"

 # 边缘情况

 用于输入`0 0`，算法计算`leap_count(0)`作为`1//?`通过公式`(0//4+1) - (0//100+1) + (0//400+1)`，这给出了`1`。 年份定为闰年，贡献`180987`。 

用于输入`1900 1900`，能被 4 计数整除包含年份，但能被 100 计数整除则将其删除。 由于 1900 不能被 400 整除，因此不会加回去。 结果采用正常年份贡献。 

用于输入`2000 2000`，年份被可被 100 整除的规则删除，并被可被 400 整除的规则恢复。 它收到闰年捐款。 

对于很大的范围，例如`1 10^18`，该算法永远不会循环多年。 它仅通过整数除法来评估闰年和平年的数量，因此即使在最大约束下，运行时间也保持恒定。
