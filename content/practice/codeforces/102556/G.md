 ## 解决方案
 ## 问题理解

 场地呈长方形网格状，`W`行和`L`列。 风扇从单元启动`(X, Y)`并使用曼哈顿距离在网格中传播：之后`t`秒，每个单元格的距离`t`从起始单元开始就被风扇占据。 莉安娜可以为第一个守卫选择一个起始牢房。 守卫以完全相同的方式传播，但如果守卫和粉丝同时到达同一个牢房，则守卫占领该牢房。 

目标是放置第一个守卫，使得整个网格填满后粉丝占据的单元格数量尽可能少。 如果警卫最终拥有的牢房数量并不比球迷多，则没有有效的位置。 

尺寸最多为 1000 x 1000，因此网格最多可包含一百万个单元格。 尝试每一个可能的保护位置并检查每个单元的解决方案在最大的情况下将执行大约一万亿次距离比较，这远远超出了一秒的限制。 细胞数量接近线性的解决方案是合适的。 

棘手的部分来自边界位置和联系。 从风扇旁边开始的守卫可能会丢失许多细胞，因为两个波几乎相同。 单单元网格是另一种特殊情况，因为双方立即占据唯一的单元。 

例如，输入：```
1 1
1 1
```唯一的单元在时间零时被共享。 后卫赢得平局，因此球迷占据零个单元格，但后卫单元格的数量不是严格大于零吗？ 守卫占据一个单元格，因此输出为：```
0
```将起始单元计为扇形单元的粗心实现将会失败。 

另一个例子是：```
2 2
1 1
```最好的防守位置是对角。 风扇和守卫同时到达一些单元格，这些单元格属于守卫。 正确的输出是：```
0
```一个常见的错误是对风扇距离小于或等于防护距离的单元进行计数。 平等案件属于警卫。 

## 方法

 一种直接的方法是为守卫尝试所有可能的起始单元。 对于每个候选者，我们计算每个网格单元到风扇和警卫的曼哈顿距离，然后计算风扇首先到达的单元格。 这是正确的，因为它准确地模拟了每个单元的最终所有权。 

问题是成本。 可能有 100 万个可能的警卫位置和 100 万个单元来测试每个位置，给出大约`10^12`在最大的情况下进行操作。 

关键的观察是，将守卫移离风扇更远只会有助于守卫的领地。 最好的位置是矩形的角点，因为网格中的每个点与角点处的风扇具有最大可能的曼哈顿距离。 任何非角点起点都可以向外推向角点，而不会使球迷的获胜区域变小。 

这将问题减少到仅检查四个可能的警卫位置。 对于每个角，我们扫描所有单元一次并计算有多少单元严格靠近风扇。 四个角中最小的数就是答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((WL)^2) | O((WL)^2) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(WL) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将四个角中的每一个都视为第一个后卫的可能起始位置。 一个角落就足够了，因为最佳的防守位置始终可以移动到角落，而无需增加球迷拥有的牢房数量。 
2. 对于选定的角点，迭代每个单元格`(r, c)`会场内。 计算风扇距离`|r-X|+|c-Y|`以及后卫到角球的距离。 
3. 仅当扇距严格小于防护距离时，才将单元计为扇单元。 相同的到达时间将被忽略，因为守卫赢得平局。 
4. 使所有四个角的风扇数量保持最少。 
5. 找到最小可能风扇数后，将相应的防护罩数与风扇数进行比较。 网格有`W*L`细胞，所以保护计数是`W*L - fan_count`。 仅当防护计数严格较大时才打印风扇计数。 否则打印所需的失败消息。 

正确性来自两个事实。 首先，每一侧的波到达时间恰好是其距起始位置的曼哈顿距离。 其次，在所有可能的后卫位置中，从球迷的角度来看，角球给后卫带来了最迟的到达时间，因此四个角球之一最大限度地减少了球迷的领土。 最终扫描精确计算满足粉丝所有权条件的单元格，因此计算值与最佳结果匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    W, L = map(int, input().split())
    X, Y = map(int, input().split())

    corners = [
        (1, 1),
        (1, L),
        (W, 1),
        (W, L)
    ]

    best = W * L

    for gx, gy in corners:
        fans = 0
        for r in range(1, W + 1):
            for c in range(1, L + 1):
                fan_dist = abs(r - X) + abs(c - Y)
                guard_dist = abs(r - gx) + abs(c - gy)
                if fan_dist < guard_dist:
                    fans += 1
        best = min(best, fans)

    if W * L - best > best:
        print(best)
    else:
        print("I don't wanna do this anymore!")

if __name__ == "__main__":
    solve()
```这`corners`数组存储仅有的四个需要测试的候选者。 嵌套循环对每个角的每个图块检查一次，对于最大输入大小，最多进行四百万次距离计算。 

比较使用`<`而不是`<=`。 这可以正确处理守卫优先级规则，因为在同一秒到达的信元属于守卫。 

单元格总数最多为 100 万，因此 Python 的整数大小不是问题，并且算术仍然很小。 坐标保持单索引以匹配输入，避免不必要的转换。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(WL) | 四次全扫描仍然是网格大小的常数倍 |
 | 空间| O(1) | O(1) | 仅存储计数器和角坐标 |

 最大网格有一百万个单元，因此线性扫描很容易满足限制。 该算法避免了测试每个可能的防护位置的二次爆炸。

 ## 边缘情况

 对于单间场地来说，唯一的后卫位置也是球迷位置。 该算法检查唯一的角点，发现扇形距离等于防护距离，并且不计算扇形的单元格。 最终的比较正确地处理了具有 1 个单元的防护装置和具有 0 个单元的风扇。 

对于从角落开始的风扇，例如：```
2 2
1 1
```最好的防守位置是对角。 该算法会检查所有角点，而不是假设特定方向。 排除了相等性检查，因此同时到达的单元格被分配给守卫。 

对于大型广场场地，如：```
1000 1000
306 865
```该算法不分配网格或模拟扩展过程。 它仅直接评估曼哈顿距离，在处理尽可能大的输入的同时保持内存不变。
