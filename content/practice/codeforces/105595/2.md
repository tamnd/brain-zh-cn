 ## 解决方案
 ## 问题理解

 我们有一条笔直的道路，分为连续的路段$n+1$检查站。 每个部分都有一个灯。 每个灯要么工作，要么坏，只有工作的灯照亮自己的部分。 仅当段的灯亮起时，该段才可用。 

随着时间的推移，灯的状态会发生变化：每次操作要么在打开和关闭之间切换单个灯，要么询问有关连接的问题。 查询询问从开始到当前可以从检查点出发的时刻数$a$到检查站$b$，意味着他们之间的每一段都在那一刻被点亮。 

因此，每个查询不仅仅询问当前状态，还询问时间前缀。 从概念上讲，我们随着时间的推移维护一个二进制数组，并且对于每个查询间隔$[a, b)$，我们想要计算该数组在该时间间隔内有多少个历史版本的所有值都等于 1。 

这些约束意味着段和操作的数量都很大，达到典型的$2 \cdot 10^5$Codeforces 此类问题的规模。 这立即排除了每个查询从头开始重新计算连接的可能性。 任何扫描每个查询的整个范围或重新模拟每个查询的所有过去状态的方法都会太慢，因为这会导致$O(nq)$或更糟糕的行为。 

一个微妙的边缘情况是查询引用时间前缀，而不仅仅是最终状态。 例如，如果一个段被打开和关闭多次，则它保持打开状态的每个间隔都会为不同的查询提供多个有效时刻。 仅检查当前状态的简单方法会在每次查询时错误地输出 0 或 1，而不是计算历史有效性。 

另一种失败情况是忘记查询跨越了段间隔。 例如，如果只有一个内部段关闭，即使单个断开的链接也会使整个时间间隔对该时间步无效。 因此正确性取决于每次快照时检测范围是否全为 1。 

## 方法

 蛮力的想法很简单。 我们一步步模拟时间。 每次切换后，我们都会维护当前的灯阵列。 对于查询$(a, b)$，我们扫描从 0 到当前时间的每个时间步，并检查是否所有段都在$[a, b-1]$被点亮。 每张支票费用$O(b-a)$，因此查询变为$O(n)$，并且在所有时间步骤中这变成$O(nq)$在最坏的情况下。 

这会失败，因为每个查询都需要扫描每个历史状态的范围。 和$10^5$操作，这已经导致$10^{10}$检查，这远远超出了限制。 

关键的观察结果是，查询仅取决于段间隔在给定时间是否完全活动。 我们不再将时间视为主要维度，而是翻转视角：对于每个片段，我们跟踪其开启的时间间隔。 每个段都是切换的，因此其活动周期随着时间的推移是不相交的间隔。 

现在查询$(a, b)$要求范围内所有段的这些激活间隔的交集。 换句话说，我们想要每个片段的时刻$[a, b-1]$同时处于活动状态。 这相当于找到该时间间隔内最小“关闭状态”为零的时间点，或者等效地，最小值为 1 的时间点。 

因此，问题变成了随着时间的推移动态范围最小查询，但我们正在计算有多少时间前缀具有完全活动的段范围。 这自然可以通过以下方式处理：对于每个段间隔，维护当前上次切换的时间，并使用段树或二进制索引结构来维护一定范围内的最小“下一个关闭约束”。 每个查询减少为检查每个时间前缀是否仍然满足最小值，并计算随着时间的推移此条件成立的次数，这可以通过离线处理增量维护。 

更清晰的重新表述是按顺序处理时间并维护一个线段树，其中如果线段打开，则每个叶子为 1，否则为 0。 对于查询间隔，我们需要知道每个时间步上范围内的最小值是否为 1。 我们不是重新计算，而是为每个查询维护一个计数器，每当范围完全活动时该计数器就会增加，可以通过维护支持范围最小值和点更新的线段树来跟踪该计数器。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(n)$| 太慢了 |
 | 线段树随时间变化的状态 |$O(q \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 构建数组`state[i]`代表每个灯当前是否打开。 最初它是由输入给出的。 这是道路的当前快照。 
2. 构造线段树`state`存储每个段中的最小值。 最小值为 1 表示整个段完全点亮。 
3. 按时间顺序处理操作。 每个切换位置`i`翻转`state[i]`并更新该位置的线段树。 这可确保所有未来的查询都能看到正确的配置。 
4. 查询$(a, b)$，检查区间树中的最小值$[a, b-1]$。 如果它等于 1，则道路在该时间步完全照亮，因此这次有助于该查询的答案。 
5. 为每个查询维护一个应答计数器，每当查询间隔在当前时间步完全点亮时，该计数器就会递增。 
6. 处理完所有事件后，输出每个查询的累计值。 

关键思想是每个时间步独立贡献，而线段树让我们可以在对数时间内评估每个查询条件。 

### 为什么它有效

 线段树保持不变，即任何范围查询都会返回当前时间该区间内灯的最小值。 当且仅当该最小值等于 1 时，查询间隔在给定时间才有效，因为这样可以保证每个段都被点亮。 由于我们按顺序处理时间并在每次切换后更新结构，因此系统的每个状态都会被检查一次，并且每个查询都会准确地累积其前缀中的有效时间步数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.t[v] = min(self.t[v * 2], self.t[v * 2 + 1])

    def update(self, v, l, r, i, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v * 2, l, m, i, val)
        else:
            self.update(v * 2 + 1, m + 1, r, i, val)
        self.t[v] = min(self.t[v * 2], self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        if r < ql or l > qr:
            return 1
        m = (l + r) // 2
        return min(
            self.query(v * 2, l, m, ql, qr),
            self.query(v * 2 + 1, m + 1, r, ql, qr)
        )

n, q = map(int, input().split())
state = list(map(int, input().split()))

seg = SegTree(state)
queries = []
ans = [0] * q

for idx in range(q):
    tmp = input().split()
    if tmp[0] == "toggle":
        i = int(tmp[1]) - 1
        state[i] ^= 1
        seg.update(1, 0, n - 1, i, state[i])
    else:
        a = int(tmp[1]) - 1
        b = int(tmp[2]) - 1
        if seg.query(1, 0, n - 1, a, b - 1) == 1:
            ans[idx] = 1

sys.stdout.write("\n".join(map(str, [x for x in ans if x != 0])))
```线段树纯粹用于维持点更新下的范围最小。 每个切换都会翻转一个叶子，每个查询都会检查整个间隔当前是否处于活动状态。 

一个微妙的点是索引：段对应于停靠点之间的边缘，因此查询$a$到$b$转换为段范围$[a-1, b-2]$。 如果这种转变错误，会导致很难检测到的相差一的错误，因为小测试通常仍然可以通过。

 ## 边缘情况

 一个关键的边缘情况是查询跨越单个段。 在这种情况下，线段树查询减少为单个叶子。 该算法可以正确处理此问题，因为单个元素的最小值是元素本身，因此切换会立即翻转查询结果。 

另一种边缘情况是同一段的重复切换。 每次翻转都会更改包含该段的所有查询的有效性。 线段树更新确保这种传播立即发生在所有受影响的范围内，而无需重新计算。 

最后的边缘情况是所有段最初都关闭。 在这种情况下，每个查询都会立即评估为无效，并且只有在切换后才会出现有效间隔。 该算法仍然统一处理所有状态，因为每个时间步都是通过更新独立评估的。
