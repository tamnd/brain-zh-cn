 ## 解决方案
 ## 问题理解

 每个学生都会固定一个特定的日子，而瓦迪姆本质上是试图“预测”所选日期后的接下来两天会发生什么。 重要的隐藏细节是与实际的未来过程无关； 重要的是，对于每个学生来说，Vadim 必须对从他们选择的一天开始的长度为 2 的窗口进行一次预测。 

所以对于每个索引值$a_i$，Vadim 隐式地选择 2 天的间隔模式$[a_i+1, a_i+2]$。 每个学生独立检查瓦迪姆选择的模式是否与该窗口上的现实相符。 只有当瓦迪姆选择的预测对于该学生的窗口来说是正确的时，他才会赢得与该学生的赌注。 

问题不在于预测真实的过程。 这是关于瓦迪姆是否可以选择预测，以便保证至少一名学生满意，无论实际过程如何。 这将问题变成了对长度为 2 的窗口上所有可能的局部结果的覆盖争论。 

这些约束推动每个测试用例的线性或近线性解决方案。 自从总共$n$跨测试最多是$10^5$，每个测试的任何排序或基于散列的分组都是可以接受的，但是任何与单个测试成二次方的结果都会失败。 对每个学生的所有预测组合进行天真的检查是立即不可能的，因为每个窗口都有多种可能的结果，并且相同或邻近日期之间的交互会组合爆炸。 

当所有学生都选择不同的日子而不重复时，就会出现微妙的边缘情况。 例如：```
1
3
1 2 3
```在这里，每个窗口都是隔离的。 直观上，Vadim 无法“重复使用”预测来满足多个学生的要求。 正确的答案是“否”，因为没有可利用的重复结构。 

另一个极端情况是所有学生都选择同一天：```
1
4
5 5 5 5
```在这里，Vadim 可以为不同的学生分配不同的预测，并保证至少有一个与接下来两天的真实结果相匹配，因为只有四种可能的 length-2 模式。 正确答案是“是”。 

关键区别在于重复项是否以允许枚举所有可能的本地模式的方式存在。 

## 方法

 如果我们尝试直接推理，每个学生对应一个长度为 2 的窗口。 对于固定窗口，未来可以表示为二进制对（或者更一般地，根据解释，表示为少量恒定数量的状态）。 关键的观察结果是，如果瓦迪姆能够向足够多的学生分配不同的预测，从而覆盖至少一个窗口的所有可能结果，那么他就成功了。 

强力解释将尝试为每个学生分配预测，并检查某些分配是否保证在所有可能的实现下至少为一名学生提供正确的匹配。 这很快就成为覆盖所选索引中所有可能的 2 长度模式的问题。 如果我们显式地模拟每个位置的所有可能模式并尝试所有作业，则共享结构的学生数量会导致复杂性呈指数级增长，甚至对于$n = 10^5$。 

关键的简化是，只有选择的日子的多重性才重要。 如果一天出现多次，Vadim 可以在这些学生中分配不同的预测。 由于不同的 length-2 模式的数量是恒定的，因此保证成功的唯一方法是确保至少一天有足够的重复次数来覆盖强制匹配所需的所有可能性。 这减少了检查频率分布的问题。 

具体来说，条件是验证某一天是否出现至少 4 次。 直觉是，两天的过程有四种可能的方式展开（预期模型中的二元解释），并且在同一开始日进行四个独立的投注可以覆盖所有结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解分配| 指数| O(n) | 太慢了 |
 | 频率计数| O(n log n) / O(n) | O(n log n) / O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 按天对所有学生进行分组$a_i$。 这确定了每个起点存在多少个独立投注。 
2. 计算每一天的出现频率。 
3. 如果任何频率至少为 4，则立即断定 Vadim 可以保证成功。 
4.否则，断定不可能。 

步骤 3 足够的原因是，只有当我们有足够多的相同起点时，我们才能分配足够多的不同预测来覆盖该窗口的所有可能结果。 任何较小的多重性都会导致至少一种可能的结果未被发现。 

### 为什么它有效

 每个学生都有相同的$a_i$对应于相同的未知 2 天段。 Vadim 可以为不同的学生分配不同的猜测，但正确性取决于与同一片段的实际实现的匹配。 由于 2 天流程的可能实现数量是恒定的且很小，因此保证获胜就减少为确保至少一个重复部分完全覆盖这些可能性。 如果没有足够重复的片段，则任何分配都无法涵盖任何单个窗口的所有结果，因此不可能保证获胜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1
        
        ok = False
        for v in freq.values():
            if v >= 4:
                ok = True
                break
        
        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```该解决方案首先使用哈希图聚合所有选定日期的频率。 这是必要的，因为问题的结构完全取决于重复。 支票为`v >= 4`直接编码保证覆盖 2 天窗口内所有可能结果所需的最小重复次数。 

一个常见的实现错误是先进行排序，然后尝试手动推理连续的块。 这是不必要的，并且有可能出现相差一的错误。 哈希计数在这里既简单又安全。

 ## 边缘情况

 对于输入：```
1
4
5 5 5 5
```该算法将 5 的频率计为 4，立即标记成功。 这相当于在同一个窗口上进行四个独立的投注，这足以涵盖所有可能的结果。 

对于输入：```
1
3
1 2 3
```所有频率均为 1，因此没有一天达到阈值。 该算法正确地拒绝了这种情况，反映出孤立的窗口不能保证强制获胜。 

对于输入：```
1
7
2 2 2 2 3 3 3
```第 2 天达​​到频率 4，因此算法输出“是”。 其余值并不重要，因为只需要一个足够重复的窗口即可保证成功。
