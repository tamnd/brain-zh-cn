 ## 解决方案
 ## 问题理解

 我们得到了一个具有特殊编号规则的网格：整数 1 位于原点，数字以菱形形式向外扩展。 每层由与中心距离相同的菱形意义上的所有网格点组成，并且这些层按顺序填充递增的整数。 在每一层内部，数字都是沿着边界以顺时针方向书写的，并且始终从该菱形的最顶端开始。 

任务是，给定相对于中心的坐标移动 x 和 y，确定在填充整个无限结构后哪个数字最终位于该位置。 

输入约束允许 x 和 y 的大小达到一百万，这会立即排除网格的任何模拟。 即使显式构建单个层也是不可行的，因为第 k 层已经包含 O(k) 个单元，并且 k 本身可以大到 10^6。 任何逐层或逐个单元迭代的方法都会超出时间限制许多数量级。 

一种简单的方法是尝试在扩展菱形中生成网格，直到达到所需的坐标。 这会失败，因为半径 10^6 以内的单元数量约为 10^12，这是完全不可行的。 

坐标解释中出现了一个更微妙的问题。 相同的曼哈顿距离可以将一个点放置在菱形的不同“侧面”，并且遍历的方向会改变它属于图层的哪一段。 正确的解决方案必须一致地识别该层以及沿该层的位置，而不会产生歧义。 

## 方法

 蛮力的想法很简单。 我们从中心开始逐层模拟构造，并保持不断增长的点边界。 对于每一层，我们按照所需的顺序遍历其周长并分配连续的整数。 一旦到达目标坐标，我们就停下来。 

这种方法是正确的，因为它完全反映了网格的定义。 然而，成本是关键问题。 第 k 层包含 θ(k) 个点，因此填充到半径 R 需要花费 θ(R^2) 次操作。 当 R 达到 10^6 时，这将变成大约 10^12 步，这远远超出了时间限制。 

关键的观察是每个坐标都属于一个层，并且可以直接从 x 和 y 识别该层，而无需构建任何东西。 一旦知道了该层，就可以通过闭合形式和得知该层之前的元素总数，并且该层内的位置由该点位于菱形边界的哪一侧来确定。 

金刚石层的几何形状很简单：所有满足 |x| 的点 + |y| = k 属于 k 层。 每层形成一个 4k 点的闭环。 由于我们知道起点 (0, k) 和顺时针方向，因此我们可以将边界划分为四个直线段并计算 O(1) 中的偏移量。

 | --- | --- | --- | --- |
 | 暴力模拟| O(R²) | O(1) | O(1) | 太慢了 |
 | 图层+公式分解| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们通过将问题分解为识别层、定位段和计算全局偏移来得出答案。

1. 将层 k 计算为 |x| + |y|。 这是有效的，因为每一层都是由距中心的恒定曼哈顿距离定义的，并且菱形的边界正是具有该属性的点集。 
2. 单独处理中心。 如果 k = 0，则答案为 1，因为原点被定义为整个构造的起点。 
3. 计算第k层之前存在多少个数字。 每层 i 包含 4i 个点，因此第 1 层到 k−1 层中的元素总数为 4(1 + 2 + … + (k−1)) = 2(k−1)k。 添加中心值给出的基本偏移量为 1 + 2(k−1)k。 
4. 确定菱形四个边中的哪一个包含 (x, y)。 边界由坐标符号分割：

 - 如果 x ≥ 0 且 y ≥ 0，则该点位于 x + y = k 的右上角。 
- 如果 x ≥ 0 且 y ≤ 0，则它位于 x − y = k 的右下侧。 
- 如果 x ≤ 0 且 y ≤ 0，则它位于左下角，其中 −x − y = k。 
- 如果 x ≤ 0 且 y ≥ 0，则它位于左上角，其中 -x + y = k。 
5. 计算所选边内的偏移：

 - 右上角：从 (0, k) 开始，向右移动给出偏移量 x。 
- 右下：从 (k, 0) 开始，偏移量为 k − x。 
- 左下：从 (0, −k) 开始，偏移量为 y + k。 
- 左上：从 (−k, 0) 开始，偏移量为 x + k。 
6. 合并结果。 最终答案是基数+1+偏移量，因为基数结束于先前层的中心单元，并且当前层内的索引是从零开始的。 

### 为什么它有效

 该构造通过枚举曼哈顿距离不断增加的层，然后以固定的顺时针周期遍历每个层来定义网格点和整数之间的双射。 层分解是唯一的，因为每个点都有唯一的 |x| + |y| 价值。 在一层内，遍历顺序是一个具有四个单调线性段的简单循环，因此每个点恰好映射到一个线段，并且沿其具有唯一的位置。 由于层索引和层内索引都是在没有近似的情况下计算的，因此最终的映射是确定性的且无冲突的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x = int(input())
    y = int(input())

    k = abs(x) + abs(y)

    if k == 0:
        print(1)
        return

    base = 1 + 2 * (k - 1) * k  # numbers before this layer

    if x >= 0 and y >= 0:
        offset = x
    elif x >= 0 and y <= 0:
        offset = k - x
    elif x <= 0 and y <= 0:
        offset = y + k
    else:
        offset = x + k

    print(base + offset + 1)

if __name__ == "__main__":
    solve()
```实现直接反映了分解。 第一步计算图层，该图层确定累积偏移和边界形状。 条件块隔离菱形的正确侧面，以便可以在恒定时间内计算偏移量，而无需沿周长迭代。 最后的加法将层内从零开始的索引转换为全局编号。 

必须小心基础配方。 它严格计算当前层之前的所有元素，因此当前层在转换为全局索引时必须再添加一位移位。 

## 工作示例

 ### 示例 1

 输入：

 x = 2，y = 1

 这里 k = 3，所以该点位于第 3 层。由于两个坐标均为非负且 2 + 1 = 3，因此该点位于右上角线段。 

| 步骤| 价值|
 | --- | --- |
 | k | 3 |
 | 基地| 1 + 2·2·3 = 13 |
 | 段 | x ≥ 0，y ≥ 0 |
 | 偏移| x = 2 |
 | 结果 | 13 + 2 + 1 = 16 |

 这证实了遍历如何沿着边界顺序累积。 

### 示例 2

 输入：

 x = -1，y = -2

 这里又是 k = 3。 该点位于左下区域，因为两个坐标均为非正且 −x − y = 3 成立。 

| 步骤| 价值|
 | --- | --- |
 | k | 3 |
 | 基地| 13 |
 | 段 | x ≤ 0，y ≤ 0 |
 | 偏移| y + k = -2 + 3 = 1 |
 | 结果 | 13 + 1 + 1 = 15 |

 该迹线显示了不同象限中的点如何映射到不同的线性偏移，即使它们共享同一层。

 ## 边缘情况

 原始情况 (0, 0) 很特殊，因为它不属于任何周界循环。 该算法在应用任何层逻辑之前显式返回 1，从而避免负数或无效的基础计算。 

恰好位于轴对齐对角线上的点（例如 (k, 0) 或 (0, k)）位于线段边界处。 条件结构确保每个这样的点恰好落入一个段，因为不等式以一致的方式包含在内，从而防止重复分配。 

像 (-10^6, -10^6) 这样的负坐标极值仍然可以清晰地映射，因为所有计算仅依赖于绝对值和简单算术，避免溢出或迭代增长。
