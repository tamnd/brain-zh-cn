 ## 解决方案
 ## 问题理解

 我们收到了一名员工的预定商务旅行清单。 每次行程占据连续的天数间隔并指定一个城市。 关键问题是，这些时间间隔可能会在不同的城市重叠，每当发生重叠时，就隐含地要求员工在同一天到达多个城市，这是不可能的。 任务是计算有多少日历日受到属于不同城市的至少两个重叠间隔的影响。 

输入已经按每个间隔的开始日期排序，这是一个强有力的结构提示：只有通过按顺序向前扫描并维护一组活动的正在进行的行程才能发现重叠。 

限制最多为 100,000 个间隔，日值最多为 10 亿。 这排除了任何逐日模拟或构建显式时间线数组的方法。 简单的每日模拟最多需要 10^9 次操作，这远远超出了可行的限制。 在最坏的情况下，即使每个间隔的成对比较也会导致 10^10 次操作。 

当多个间隔在很长一段时间内重叠但仅部分共享日期时，会出现微妙的边缘情况。 例如，考虑：```
1 10 1
2 3 2
4 5 3
```正确答案是 0，除了重叠结构之外，2 天不会同时在不同城市之间共享。 简单地计算任何一对间隔之间的所有重叠的简单方法可能会错误地过度计算，而无法精确跟踪冲突天数的并集。 

当多个区间共享相同的范围但不同的城市时，会出现另一种边缘情况：```
1 5 1
1 5 2
1 5 3
```从 1 到 5 的每一天都是无效的，但很容易错误地多次计算成对重叠而不是计算不同的天数。 

## 方法

 暴力方法会比较每对间隔并计算它们的交集。 对于每一对，我们将检查他们的城市是否不同以及它们的时间间隔是否重叠，然后将重叠的部分添加到全局糟糕日子集中。 虽然概念上很简单，但这种方法失败了，因为它需要 O(N^2) 对检查，每个检查都可能产生长间隔合并。 当 N 达到 10^5 时，这是不可能的。 

关键的观察结果是，问题从根本上讲是跟踪每个时间点存在多少个活跃城市。 我们可以将所有间隔边界作为时间轴上的事件处理，而不是成对比较间隔。 每个间隔在其开始日贡献一个 +1 事件，在其结束日贡献一个 -1 事件加一。 然而，因为我们需要区分城市，所以我们不能只计算活跃间隔，我们必须跟踪在任何时刻有多少个不同的城市是活跃的。 

这将问题转化为压缩事件的扫描线，我们在其中维护活跃城市的频率图。 在连续事件点之间的任何路段，如果不同的活跃城市数量至少为两个，则该路段中的所有天数均无效，应计算在内。 

这避免了每天的模拟，并减少了事件点排序和线性扫描的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 成对暴力破解 | O(N^2) | O(N^2) | O(N) | 太慢了 |
 | 活动扫线 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 1. 将每个间隔转换为两个事件：在 d1 处城市变为活跃的开始事件，以及在 d2 + 1 处城市变为非活跃的结束事件。 这确保了每一天都以半开形式一致地表示，从而避免了合并片段时出现差一的歧义。 
2. 收集所有事件并按天排序。 排序是必要的，因为重叠只能通过按时间顺序处理变化来检测。 
3. 初始化活跃城市的频率计数器和跟踪当前活跃的不同城市的变量。 
4. 按顺序浏览已排序的事件。 在两个连续的事件日之间，我们考虑活动集恒定的日子段。 
5. 如果在路段开始时，活跃城市的数量至少为 2，则该路段中的每一天都对答案有贡献，因此我们将路段的长度添加到结果中。 
6. 通过更新频率图来处理当天的所有事件：开始事件递增，结束事件递减。 当城市的计数降至零时，会将其从活动集中删除，并且不重复计数也会相应更新。 
7. 继续，直到处理完所有事件，确保最终累积的答案反映所有重叠时段。 

### 为什么它有效

 在任何时间点，该算法都会维护其间隔覆盖该天的确切城市集。 该集合仅在事件边界发生变化，因此在连续的两个事件日之间该集合是恒定的。 因此，该算法将问题简化为不相交的时间段，其中状态不会改变。 每一天都被正确分类，因为它继承了其段的状态，并且每个段都被精确地计数一次。 这保证了不会重复计数，也不会遗漏重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []
    
    for _ in range(n):
        l, r, c = map(int, input().split())
        events.append((l, c, 1))
        events.append((r + 1, c, -1))
    
    events.sort()

    from collections import defaultdict
    freq = defaultdict(int)
    active = 0

    ans = 0
    i = 0
    m = len(events)

    while i < m:
        day = events[i][0]

        if i > 0:
            prev_day = events[i - 1][0]
            if active >= 2:
                ans += day - prev_day

        while i < m and events[i][0] == day:
            _, city, typ = events[i]
            if typ == 1:
                if freq[city] == 0:
                    active += 1
                freq[city] += 1
            else:
                freq[city] -= 1
                if freq[city] == 0:
                    active -= 1
            i += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现在排序事件上使用标准扫描线模式。 每个间隔贡献两次边界更新，这确保事件点之间明确定义活动状态。 这`freq`字典跟踪每个城市的多重性，因为来自同一城市的多个重叠间隔仍应算作一个活跃城市。 

这`active`计数器跟踪当前有多少个不同的城市处于活动状态。 这一点至关重要：计算间隔而不是城市会错误地将前往同一城市的多次旅行视为冲突。 

分部贡献`day - prev_day`有效，因为在两个事件日之间活动状态不会改变，因此该间隔中的每一天在重叠状态方面都是相同的。

 ## 边缘情况

 一种微妙的情况是来自同一城市的多个区间相互重叠。 该算法可以正确处理此问题，因为频率图仅在城市从零过渡到一个活动间隔时增加活动城市计数。 例如：```
1 5 1
2 4 1
1 5 2
```即使城市 1 出现两次，它也算一次`active`。 扫描线将正确地将第 1 天到第 5 天识别为冲突，因为城市 2 始终与城市 1 重叠，但单个城市内的重复不会增加冲突计数。 

另一个边缘情况是间隔在连续几天结束和开始。 使用`r + 1`因为最终事件可确保一致地处理日期边界。 如果没有这种转变，间隔就像`[1,2]`和`[2,3]`在基于事件的表示中，第 2 天会错误地出现重叠。
