 ## 解决方案
 ## 问题理解

 我们给出一个非负整数$n$，我们被要求计算有多少个无序非负整数对$(a, b)$满足$a + b = n$，在特殊限制下：两者$a$和$b$一定是“有趣”的。 

如果一个数字以十进制形式书写时最多使用两个不同的数字，则该数字被称为有趣的数字。 例如，555 有效，因为它仅使用一位数字；272772 有效，因为它使用数字 {2, 7}；100 有效，因为它使用数字 {1, 0}。 像 123 这样的数字并不有趣，因为它使用三个不同的数字。 

输出不是关于计算的表示$n$在位置意义上，而是关于计算十进制结构满足此数字限制的实际整数对。 如果两对仅顺序不同，则认为它们相同，因此$(a, b)$和$(b, a)$被视为一体。 

约束条件$n \le 10^9$意味着我们正在处理长达 10 位数字的值。 这立即排除了任何尝试所有配对的方法$n$，因为这需要按顺序$10^{18}$运营。 甚至迭代所有分解$n$是不可能的。 相反，我们需要利用有趣数字本身的结构，因为此类整数的数量小到足以枚举。 

一个微妙的边缘情况是零的处理。 数字 0 很有趣，但在计算像这样的对时必须小心处理$(0, n)$，特别是当$n = 0$， 在哪里$(0,0)$应该只计算一次。 另一个边缘情况是在构造有趣数字期间出现前导零，除了数字零本身之外，这是不允许的。 允许自由使用前导零的简单数字构造方法会生成无效的重复项，例如代表 1 的 01 或 001。 

## 方法

 对问题的直接解释建议迭代所有对$(a, b)$这样$a + b = n$，检查两者是否有趣。 这需要迭代$a$从 0 到$n$，已经达到$10^9$，并通过扫描数字来检查每个值是否有趣。 即使有快速的数字检查，这也是远远不可行的。 

关键的观察是我们不需要所有整数$n$，仅有趣数字的子集。 最多有两个不同数字的数字是高度结构化的：它是通过选择最多两个数字并将它们排列在最多 10 个位置来确定的（因为$n \le 10^9$）。 这极大地限制了搜索空间。 

而不是迭代数字对总和$n$，我们首先生成完整的有趣数字集，直到$n$。 这个集合很小，因为对于每个数字对的选择，有效字符串的数量最多为$2^{10}$，并且只有 55 个无序数字对。 构建该集合后，我们将其存储在哈希集中以进行快速成员资格测试。 然后对于每个有趣的数字$a$，我们检查是否$n - a$也很有趣。 为了避免重复计算，我们只计算以下情况$a \le n - a$。 

这将问题从搜索巨大的数字范围转变为粗略地迭代$O(10^4 \sim 10^5)$候选人。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力胜过一切$a$|$O(n \log n)$|$O(1)$| 太慢了 |
 | 枚举有趣的数字 + 哈希查找 |$O(S)$|$O(S)$| 已接受 |

 这里$S$有趣数字的数量最多为$10^9$，它足够小，可以舒适地处理。 

## 算法演练

 我们分两个阶段构建解决方案：生成所有有趣的数字，然后计算有效对。 

1.我们迭代所有无序的数字对$(d_1, d_2)$，其中每个数字的范围是从 0 到 9。这包括情况$d_1 = d_2$，仅使用一位数字表示数字。 
2. 对于每个数字对，我们仅使用这些数字生成长度从 1 到 10 的所有可能数字。 每个位置要么是$d_1$或者$d_2$。 这最多创建$2^{10}$每对候选人。 我们会跳过任何带有前导零的数字，除非该数字本身恰好为零。 
3. 将每个生成的数字从其数字形式转换为整数并存储在集合中。 这可以消除不同结构产生相同整数的情况。 
4. 生成后，我们可以选择过滤掉大于的数字$n$，因为他们无法参与有效金额。 
5.我们迭代每个有趣的数字$a$在集合中。 对于每个$a$，我们计算$b = n - a$。 
6. 如果$b$存在于集合中并且$a \le b$，我们将其视为一种有效的无序表示。 
7. 我们输出最终计数。 

### 为什么它有效

 每个有效对$(a, b)$必须由两个有趣的数字组成，因此两个元素都必须位于生成的集合中。 由于我们将所有有趣的数字精确地枚举一次并使用哈希集测试补集，因此每个有效的数字对都会被计算在内。 条件$a \le b$确保每个无序对只计算一次，防止对称对重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def generate_fun(limit):
    fun = set()

    digits = list(range(10))

    for d1 in digits:
        for d2 in digits:
            # generate all strings of length 1 to 10
            stack = [("", 0)]
            while stack:
                s, length = stack.pop()
                if 1 <= length <= 10:
                    # skip leading zeros unless single digit 0
                    if not (s[0] == '0' and len(s) > 1):
                        val = int(s)
                        if val <= limit:
                            fun.add(val)
                if length == 10:
                    continue
                for d in (d1, d2):
                    stack.append((s + str(d), length + 1))

    return fun

def solve():
    n = int(input().strip())

    fun = generate_fun(n)

    ans = 0
    for a in fun:
        b = n - a
        if b in fun and a <= b:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```生成阶段构建所有数字，其数字被限制为选定的对，将它们扩展至长度 10。`limit`避免存储超出不必要的值$n$，这使得集合保持紧凑。 

计数阶段是直接基于散列的补码搜索。 排序约束`a <= b`强制无序对的唯一性，无需排序或额外的簿记。

 ## 边缘情况

 一个重要的案例是$n = 0$。 唯一有效的表示是$(0,0)$。 该算法自然地处理这个问题，因为 0 包含在有趣的集合中，并且$0 - 0 = 0$被计算一次$a \le b$规则。 

另一个微妙的情况是具有许多重复有效补集的数字，例如小$n$两者都在哪里$a$和$n-a$对很多人来说很有趣$a$。 排序条件确保即使在迭代期间出现两个方向，也只计算一个方向。 

前导零处理在生成过程中得到解决：像“01”这样的字符串永远不会转换为整数，因此从不同数字路径生成的重复项（例如 1）不会错误地膨胀集合。
