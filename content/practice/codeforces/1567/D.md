 ## 解决方案
 ## 问题理解

 我们遇到这样一种情况，鲍勃写下一个总和固定的正整数序列。 他唯一的自由就是如何将这笔总金额准确地分割成`n`部分。 然后，Alice 读取这些数字中的每一个，但她不是以 10 为基数解释它们，而是以 11 为基数解释它们并将它们相加。 

关键在于，Bob 的约束是纯以 10 为底的加法，而 Alice 的评估也是加法的，但在数字系统发生变化之后。 由于基数转换会改变数字位置的数值，因此 Bob 可以通过选择具有某些十进制表示形式的数字来“隐藏”基数 11 中较高数字中的值。 

输出是任何有效的分解`s`进入`n`正整数，最大化其以 11 为底的解释之和。 

约束足够严格，每个测试用例需要 O(n) 或 O(n log s) 构造。 自从`n ≤ 100`和`t ≤ 100`，即使 O(t·n) 解决方案也是微不足道的，但是如果它依赖于任何枚举分区或模拟每个数字的数字分配的尝试都会太慢`s`直接或尝试搜索配置。 

当所有数字都很小时，就会出现微妙的边缘情况。 如果鲍勃分裂了`s`进入许多 1，爱丽丝在所有位置上获得最大数字进位效应，因为每个`1`在基数 11 中独立贡献。天真的贪婪尝试在不考虑基数 11 进位结构的情况下尝试最大化基数 10 中的个体数字，在以下情况下将失败`10 9`，其中均匀分布胜过集中值。 

当一个数字变得非常大时，就会出现另一种失败情况。 例如，`100 2`可能会引发贪婪的分裂，比如`99 1`，但这减少了以 11 为基数的贡献项的数量并损失了数字扩展。 

## 方法

 暴力方法会枚举所有分裂方法`s`进入`n`正整数。 此类组合物的数量为`C(s-1, n-1)`，即使对于中等强度来说，这也是一个天文数字`s`。 即使限制每一步的小分支选择仍然会导致指数爆炸，因为每个分裂决策都会影响后面的结构。 

关键的观察结果是，Alice 的评估在 11 基数上是线性的，因此每个数字对每个数字位置都有独立的贡献。 以 11 为基数写入数字表明，引入 10 基数约束与 11 基数表示的交互效果很差：大于 9 的数字表现不同，并且拆分数字会增加独立数字扩展的数量，从而导致更高的 11 次幂。 

关键的见解是，使尽可能多的数字等于小值会增加贡献低位 11 基数的项的数量，这些项的聚合比集中质量更有效。 与此同时，我们必须确保所有数字保持正值。 

事实证明，最优结构非常简单：我们最大化 1 的数量，并将剩余的总和集中到一个额外的数字中。 这最大化了贡献常数的基数 11 项的数量`1`，同时保留总和。 

问题归结为构建`n-1`并将余数放在最后位置。

 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 首先分配尽可能小的值`1`到`n-1`数字。 这确保了每个数字都是正数，并且我们最大化了 Alice 总和中单独贡献者的数量。 
2. 将剩余值计算为`s - (n - 1)`。 该剩余部分确保完全满足总和约束。 
3. 将此余数分配给序列中的最后一个数字。 这保留了有效性，同时将多余的质量集中到单个术语中。 
4. 输出构造好的列表。 

这种结构背后的原因是，分裂成更多的数字会增加独立的 11 进制扩展的数量，从而促成最终的总和。 由于每个正整数至少贡献`1`以 11 为基数，最大化具有值的项数`1`最大化爱丽丝的总贡献基线，同时保留其余部分的灵活性。 

### 为什么它有效

 不变的是，在每一步我们都维护一个有效的分区`s`同时最大化最低有效基 11 数字中的非零贡献数量。 每个额外的数字至少贡献`1`到爱丽丝的总和，并分割任何大于`1`成两个正整数会严格增加贡献独立单位的基数 11 表示的数量，而不会减少总和。 因此，将质量推入单个余数项，同时全局最大化 1 的数量，可以最大化以 11 为基数的数字展开和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s, n = map(int, input().split())
        
        # n-1 ones
        res = [1] * (n - 1)
        
        # last element absorbs remainder
        res.append(s - (n - 1))
        
        print(*res)

if __name__ == "__main__":
    solve()
```该结构直接编码了贪婪的想法，即除了一个数字之外的所有数字都应该被最小化。 最后一个数字吸收剩余的总和，保证分区的正确性。 

实现总是小心地减去`n-1`从`s`，这确保没有数字变为零。 由于约束保证`n ≤ s`，余数总是至少`1`。

import sys, io

    for _ in range(t):
        s, n = map(int, sys.stdin.readline().split())
        res = [1] * (n - 1) + [s - (n - 1)]

 ## 边缘情况

 当`n = 1`，该算法产生一个等于`s`。 施工`[1] * 0 + [s]`自然塌陷为`[s]`，无需特殊处理即可保持正确性。 

什么时候`n = s`，每个数字都变成`1`。 余数为`1`，所以输出是`n`那些。 这是最受约束的分割，并确保 Alice 的总和通过最大术语计数最大化。 

什么时候`s`很大并且`n`很小，余数占据一个位置。 该结构仍然确保所有其他位置贡献最少的 11 进制单位，从而保持结构的最佳状态。
