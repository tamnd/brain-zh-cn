 ## 解决方案
 ## 问题理解

 这是一个针对固定但未知的对手程序的互动游戏。 对手在测试开始时选择一种确定性策略，并在 20 轮比赛中坚持使用该策略。 你的任务是玩石头剪刀布，并以交互方式探索足够的策略，以保证至少连续 10 轮获胜。 

每一轮你输出三个动作之一，然后立即收到反馈，表明你的动作是否击败了人工智能。 只有当你的举动严格击败人工智能的举动时，才会获胜，而平局将被视为你的损失。 互动会持续 20 轮，除非您能够提前赢得 10 轮连续胜利，在这种情况下，法官已经接受您的解决方案。 

就交互长度而言，约束结构非常小，因此不需要大量计算。 真正的困难在于对手是确定性的但未知的，你必须足够快地“锁定”它的行为，以便你可以在很短的时间内强制保证连胜。 

这里重要的边缘情况本质上都是交互的，而不是算法的。 首先，由于平局算作人工智能获胜，任何试图不小心“镜像”对手的策略都会默默地失败，因为平等是绝对不利的。 例如，如果AI总是玩摇滚，而玩家也反复玩摇滚，那么反馈将始终是“ai”，这看起来与针对混合对手的失败策略没有区别。 

其次，由于只有最后 10 场连续胜利才重要，因此，即使最终了解了模式，较晚识别对手但不能干净利落地转变为固定反策略的方法也可能会失败。 

第三，由于整个交互集中只有六种隐藏策略，因此该问题隐含地鼓励对行为进行完全识别或分类，而不是概率猜测。 

## 方法

 一种幼稚的方法是独立对待每一轮，并尝试对之前的结果做出贪婪的反应。 例如，如果你输了，你可以尝试以 R→P→S→R 等循环模式切换动作。这偶尔可以战胜简单的固定对手，但它不能保证产生 10 连胜，因为它实际上并没有推断出对手的确定性规则。 由于平局意味着损失，因此即使是正确的猜测也可能会因不幸的排列而立即被打破。 

另一种暴力心理模型是假设对手可能是任何可能的确定性策略，并尝试模拟观察到的动作的一致性。 在最坏的情况下，您将维护一组候选策略并在每轮之后消除不一致的策略。 这在概念上是可行的，但问题是交互格式不会暴露对手的举动，只会暴露你是赢还是输。 这意味着除非策略集非常小且结构化，否则消除受到限制。 

关键的见解是“只有 6 个固定策略”的约束使得在实践中不需要完全识别。 相反，人们可以将互动视为一个短暂的校准阶段，然后是承诺。 由于 20 轮非常小，最简单的鲁棒策略是将前 10 轮专门用于以固定顺序进行探测，以保证暴露对手的行为，然后切换到击败推断模式的确定性反击策略。 因为平局就是损失，所以探测序列必须避免退化，并应确保所有三个动作都重复执行。

一旦对手的行为被充分观察到，第二阶段就变得简单了：选择击败最常观察到的对手输出（或检测到的最后一致模式）的动作。 由于对手是确定性的，其在探测阶段的输出分布很快就会稳定下来，从而可以做出安全的基于多数的决策。 

暴力破解的想法之所以有效，是因为理论上完全一致性检查是可能的，但它失败了，因为我们无法直接看到对手的行为。 观察到对手是确定性的，使得基于频率的推理能够在恒定数量的样本中快速收敛。

 ## 算法演练

 我们将交互分为两个阶段：观察和利用。 

1. 前 10 轮采用固定重复循环的动作，例如“R、P、S、R、P、S、R、P、S、R”。 这确保了每个可能的对手响应都针对多个不同的玩家行为进行测试。 
2. 通过映射您的哪些动作成功、哪些失败，通过结果隐式记录 AI 响应。 由于你知道每轮你的行动，失败表明人工智能匹配或击败它，这缩小了对手可能的行动范围。 
3. 从前 10 轮中，计算对手的哪一个举动与在确定性假设下产生观察到的结果最一致。 在实践中，由于对手是固定的，一招将主导一致性。 
4. 选择击败推断出的优势对手棋步的棋步：如果推断AI最一致地玩R，则选择P； 如果是P，则选择S； 如果是S，则选择R。 
5. 在剩余回合中重复输出该选择的动作，确保每一回合独立但相同。 
6. 如果在任何时候之前取得了 10 连胜，则立即终止，因为裁判已经接受。 

之所以有效，是因为决定论很快就消除了不确定性。 对手无法适应，因此一旦识别出单一的一致行为，重复最佳反应就可以保证稳定的连胜。 

### 为什么它有效

 不变的是，在观察阶段之后，我们对对手的固定动作或至少是严格由我们选择的反应主导的动作有一个正确的假设。 由于剪刀石头布具有严格的循环优势关系，识别出对手的任何单一主导动作就足以保证赢得后续每一轮的反击动作。 确定性确保不会发生隐藏状态变化，因此一旦假设稳定，它对于其余的交互仍然有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

beats = {'R': 'P', 'P': 'S', 'S': 'R'}
all_moves = ['R', 'P', 'S']

def query(move):
    print(move)
    sys.stdout.flush()
    return input().strip()

def infer_best(opponent_counts):
    best_move = 'R'
    best_val = -1
    for m in all_moves:
        if opponent_counts[m] > best_val:
            best_val = opponent_counts[m]
            best_move = m
    return best_move

def main():
    opponent_counts = {'R': 0, 'P': 0, 'S': 0}

    # Phase 1: exploration
    pattern = ['R', 'P', 'S'] * 4  # 12, we will only use first 10
    for i in range(10):
        my = pattern[i]
        res = query(my)

        # crude inference: if we lose, opponent likely beats or equals us
        if res == "ai":
            opponent_counts[my] += 1

    inferred = infer_best(opponent_counts)
    answer = beats[inferred]

    # Phase 2: exploitation
    win_streak = 0
    for _ in range(10):
        res = query(answer)
        if res == "player":
            win_streak += 1
        else:
            win_streak = 0
        if win_streak >= 10:
            break

if __name__ == "__main__":
    main()
```第一阶段使用固定的探测序列，迫使对手多次响应所有三个动作。 我们并不试图重建精确的策略逻辑； 相反，我们只估计哪一步棋最符合我们的失败。 

第二阶段致力于击败推断出的占主导地位的对手的棋步。 这`beats`映射以直接的方式对石头剪刀布循环进行编码，因此一旦知道对手的主导动作，就会立即做出反应。 

每次移动后必须注意刷新输出。 如果没有刷新，即使逻辑正确，交互式判断也会阻塞，解决方案也会超时。

 ## 边缘情况

 一个重要的边缘情况是对手总是采取与部分探测周期相匹配的相同动作。 例如，如果对手总是玩R，并且探测序列从R开始，则第一轮总是失败。 这可能会误导性地表明不稳定，但由于每当玩 R 时都会重复相同的结果，因此推断正确地积累了 R 占主导地位的权重。 

另一个边缘情况是，由于平局失利，早期几轮比赛会产生好坏参半的结果。 如果玩家不小心频繁地重复相同的动作，比如 RRRRRRRRRR，那么对抗玩 R 的对手时，这只会产生“ai”结果，但仍然正确地将 R 识别为主导。 该算法仍然正确，但失去了信息效率。 

最后的边缘情况是 10 轮之前过早收敛。 如果对手足够简单，那么在完成观察阶段之前的利用阶段，一致的反击可能已经连续赢了 10 场。 即使在这种情况下，提前终止条件也能确保正确性，因为一旦达到连胜，法官就会立即接受。
