 ## 解决方案
 ## 问题理解

 我们被要求确定给定的数字是否可以表示为任意数量等于 4 或 7 的整数之和。输入是单个整数$a$1 到 99 之间，如果存在这种表示，则输出为“YES”，否则输出为“NO”。 从概念上讲，我们可以将其视为一种特殊的“硬币找零”问题，只有两种硬币面额：4 和 7。 

关键的限制是$a$最多为 99。这个较小的上限意味着我们可以考虑 4 和 7 的所有可能组合，而无需考虑性能问题。 尝试每一对的天真的方法$(x, y)$在哪里$4x + 7y = a$这是可行的，因为任一面额的硬币的最大数量都在 25 枚以下，而且组合总数也很少。 

边缘情况出现时$a$小于 4 或介于 4 和 7 之间但不等于 4 或 7。例如，如果$a = 3$，4 和 7 的组合都不可能等于 3，因此正确的输出是“NO”。 如果$a = 11$，该数可表示为$4 + 7$，所以输出为“YES”。 粗心的方法可能只会独立尝试 4 或 7 的倍数，而错过诸如$4 + 7$。 

## 方法

 暴力法迭代 4 和 7 的所有非负计数，其总和不超过$a$。 对于每个可能的 4 个数，我们检查余数是否为$a - 4x$能被 7 整除。这种方法之所以有效，是因为迭代总数受到以下限制：$\frac{a}{4} \approx 24$在最坏的情况下。 尽管从技术上讲可以使用双循环，但超过 4 秒的单循环就足够了，因为一旦 4 的数量固定，检查能否被 7 整除就是常数时间。 

最佳方法依赖于我们只需要考虑的洞察力$x$从 0 到$\lfloor a / 4 \rfloor$。 对于每个$x$， 如果$(a - 4x) \% 7 == 0$， 然后$a$可以表示为 4s 和 7s 之和。 这减少了对负数或不可能的 7 计数的不必要探索，并且保证找到解决方案（如果存在）。 由于输入范围很小，因此不需要更快的方法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(a^2) | O(a^2) | O(1) | O(1) | 由于输入较小而被接受 |
 | 单循环检查| O(a/4) = O(1) | O(1) | O(1) | 被接受且更简单|

 ## 算法演练

 1.读取整数$a$来自输入。 这是我们要检查的目标总和。 
2. 迭代$x$从 0 到$\lfloor a / 4 \rfloor$。 每个$x$表示使用的 4 的数量。 
3. 对于每个$x$，计算余数$r = a - 4x$。 这是 7s 必须覆盖的金额。 
4. 检查是否$r$可以被 7 整除，使用$r \% 7 == 0$。 如果为真，则输出“YES”并停止。 
5.如果没有$x$循环后满足该条件，输出“NO”。 

为什么有效：4s 和 7s 的每个潜在组合都可以表示为$4x + 7y = a$。 通过迭代所有可行的 4 计数，我们保证测试每个可能的值$y$这是非负的。 可除性检查确保$y$是一个整数，满足原方程。 不能跳过任何有效组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = int(input())
for x in range(a // 4 + 1):
    if (a - 4 * x) % 7 == 0:
        print("YES")
        break
else:
    print("NO")
```代码读取整数$a$并迭代$x$从 0 到$a // 4$。 表达式$(a - 4 * x) \% 7$直接检查余数是否可以完全由7组成。 使用`for`循环与`else`子句确保我们仅在无效时打印“NO”$x$被发现。 一个常见的错误是循环边界中的差一错误； 这里，`a // 4 + 1`正确地包括以下情况$x = a // 4$。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a = int(input())
    for x in range(a // 4 + 1):
        if (a - 4 * x) % 7 == 0:
            return "YES"
    return "NO"

# provided sample
assert run("5\n") == "NO", "sample 1"

# custom cases

 ## 边缘情况

 对于`a = 1`，循环以 x = 0、r = 1 运行，不能被 7 整除。输出为“NO”，正确处理下限。 为了`a = 28`，x = 0 产生 r = 28 可被 7 整除，因此算法立即打印“YES”，表明它正确找到了仅使用 7 秒的解。 这些示例证实输入范围内的所有组合都经过有效测试。
