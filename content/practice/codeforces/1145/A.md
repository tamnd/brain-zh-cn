[CF 1145A - 灭霸排序](https://codeforces.com/problemset/problem/1145/A)

 **评级：** -
 **标签：** *特殊、实施
 **求解时间：** 1m 23s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们从一个长度为 2 的幂的数组开始。 允许的操作非常不寻常：只要当前数组不是按非递减顺序排序的，我们就可以删除它的左半部分或右半部分。 之后，我们对剩下的一半重复相同的过程。 

因为每个操作都会删除当前段的一半，所以我们可以获得的唯一数组是连续段，其长度是 2 的幂，并且其边界是通过在递归分割期间重复选择左半部分或右半部分而产生的。 

任务是找到可以成为最终结果并且已经按非降序排序的段的最大可能大小。 

限制很小。 数组长度最多为 16，因此即使是指数方法也能轻松适应。 这意味着挑战不是性能，而是识别重复减半操作创建的结构。 

一个常见的错误是寻找最长的排序子数组。 Thanos 排序不能保留任意子数组。 它只能保留递归减半产生的段。 

考虑：```
8
1 2 3 4 100 0 1 2
```子数组`[1,2,3,4]`长度为 4 并已排序，这是可以获得的，因为它恰好是左半部分。 

现在考虑：```
8
100 1 2 3 4 5 6 7
```子数组`[1,2,3,4,5,6,7]`长度为7，已排序，但无法获得，因为任何半删除序列都不能留下长度为7的段。正确答案是4。 

另一个边缘情况是完全递减的数组：```
4
4 3 2 1
```长度为 2 的段没有被排序。 最终我们只能保留一个元素，并且任何单个元素都是普通排序的。 答案是1。 

第三种微妙的情况是整个数组已经排序：```
4
1 2 2 4
```答案是 4。粗心的递归实现总是继续分裂，会错误地返回 2 或 1。 

## 方法

 一个蛮力的想法是模拟灭霸决策的每一个可能的序列。 在每个部分，如果它已排序，我们可能会停止，否则我们会递归地探索两个部分。 由于每次分割都会将段长度减半，因此递归形成完整的二叉树。 

这种蛮力在这里实际上是可行的。 对于大小为 16 的数组，递归状态很少。 每个可达段对应于减半树中的一个节点。 

关键的观察结果是 Thanos 排序只能产生由递归减半产生的段。 我们永远不需要考虑任意子数组。 

假设我们检查一个段。 如果它已经排序，那么这个段本身就是一个有效的最终答案，并且它的长度是一个候选。 如果没有排序，唯一合法的下一步就是保留左半部分或右半部分。 这自然会导致递归定义：

 对于一个段：

 如果已排序，则返回其长度。 

否则，递归求解两半并取最大结果。 

递归直接反映了过程的规则。 每个可到达的段都被恰好探索一次。 

尽管约束很小，但这种递归公式也是最干净、最自然的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有可到达的段进行暴力破解 | O(n log n) | O(n log n) | O(log n) | 已接受 |
 | 递归分而治之| O(n log n) | O(n log n) | O(log n) | 已接受 |

 ## 算法演练

 1. 定义一个作用于数组段的递归函数。 
2. 检查当前段是否按非降序排序。 
3. 如果已排序，则立即返回段长度。 

这是正确的，因为一旦当前数组排序完毕，Thanos 排序可能会停止。 
4. 否则，将该段分割为左半部分和右半部分。 
5. 递归计算从左半部分获得的最佳答案。 
6. 递归计算从右半部分获得的最佳答案。 
7. 返回两个结果中较大的一个。 

当当前段未排序时，规则允许我们保留其中的一半。 可实现的最佳答案必须来自这两个选择之一。 

### 为什么它有效

 通过 Thanos 排序可获得的每个数组都对应于通过重复获取当前段的左半部分或右半部分而生成的段。 递归正好访问这些段。 

对于任何细分市场来说，只有两种可能性。 要么它已经排序，在这种情况下，它的完整长度是可以实现的，并且不能来自同一段内更大的答案，要么它没有排序，在这种情况下，第一个合法的移动必须丢弃一半并继续另一半。 因此，最佳答案是从两半中可获得的最大答案。 

通过对段长度的归纳，递归函数为其处理的每个段返回可实现的最大排序段。 将其应用于整个数组会产生正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_segment(arr):
    m = len(arr)

    sorted_segment = True
    for i in range(m - 1):
        if arr[i] > arr[i + 1]:
            sorted_segment = False
            break

    if sorted_segment:
        return m

    half = m // 2
    return max(
        solve_segment(arr[:half]),
        solve_segment(arr[half:])
    )

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_segment(a))

if __name__ == "__main__":
    solve()
```递归函数表示在某些手指打响序列之后保留的当前数组。 

第一个循环检查该段是否已经排序。 如果每个相邻对都满足`a[i] <= a[i+1]`，该段是有效的最终状态，我们返回它的长度。 

当段未排序时，唯一的合法行为是保留左半部分或保留右半部分。 递归调用与这两个选择完全对应。 

基本情况不需要显式地编写。 长度为 1 的段始终已排序，因此排序检查成功并返回 1。 

一个容易被忽视的实现细节是非递减顺序的使用。 允许相邻值相等，因此必须进行比较`>`而不是`>=`。

import io

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    def dfs(arr):
        ok = True
        for i in range(len(arr) - 1):
            if arr[i] > arr[i + 1]:
                ok = False
                break

        if ok:
            return len(arr)

        m = len(arr) // 2
        return max(dfs(arr[:m]), dfs(arr[m:]))

    print(dfs(a))

    backup_stdout = sys.stdout
    sys.stdout = out

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    globals()["input"] = backup_input

 ## 边缘情况

 ### 整个数组已经排序

 输入：```
4
1 2 2 4
```第一个排序检查成功。 该算法立即返回 4 并且从不探索更小的段。 

输出：```
4
```这可以防止由于继续不必要的分裂而失去最佳答案。 

### 无法获得最长排序子数组

 输入：```
8
100 1 2 3 4 5 6 7
```存在一个长度为 7 的已排序子数组，但 Thanos 排序不能保留任意范围。 

递归仅检查通过重复减半可到达的段：```
[100 1 2 3 4 5 6 7]
    -> [100 1 2 3]
    -> [4 5 6 7]
```右半部分已排序且长度为 4。 

输出：```
4
```这证实了该算法尊重操作的结构，而不是搜索任意排序的子数组。 

### 完全递减数组

 输入：```
4
4 3 2 1
```整个数组未排序。 两半都没有排序。 继续分裂直到达到长度为 1 的段。 

每个长度为 1 的段都已排序，因此可实现的最佳答案是 1。 

输出：```
1
```这表明即使不存在更大的排序段，递归也始终以有效答案终止。
