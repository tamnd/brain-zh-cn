 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每条边都带有两个小的正权重。 从节点 1 到节点 N 的路径分别累加这些权重：一个和是通过将路径上的所有第一分量相加形成的，另一个和是通过将所有第二分量相加形成的。 路径的值定义为这两个累加和的乘积。 

任务是找到一条从节点 1 到节点 N 的路径，使该乘积最小化。 如果多条路径达到相同的最小乘积，我们会在其中选择具有最小第一累积和的路径，如果仍然存在平局，则也会报告该所选路径的第二个总和。 

就所有测试用例的节点和总边而言，约束足够小，这表明只要我们谨慎处理状态表示，我们就可以提供相当直接的最短路径样式解决方案。 每个边的权重最多为 200，路径的长度最多可达数百条边，因此累计总和保持在可管理的范围内。 

一个天真的尝试是枚举从 1 到 N 的所有简单路径并计算它们的（总和 A，总和 B）对。 这会在小图上立即实现收支平衡，因为路径数量随着分支呈指数增长。 即使具有适度分支因子的图也会产生太多的可能性。 

一种更微妙的故障模式来自于尝试仅在一维上运行标准最短路径，例如独立地最小化 A 或最小化 B。 例如，A 很小但 B 很大的路径一旦相乘就会输给平衡路径，反之亦然，因此任何单参数缩减都会丢弃最佳候选。 

真正的困难在于目标取决于两个耦合的累积量，并且两者都不能独立优化。 

## 方法

 蛮力的观点是将每条可能的路线视为候选路线，累加其两个总和，计算乘积，并跟踪最佳结果。 这在原则上是正确的，因为它直接评估问题的定义。 然而，有向图中的路径数量会随着 N 呈指数增长，因此这种方法很快就会变得不可行，即使 N 只有几百。 

关键的观察结果是，尽管目标是非线性的，但路径成本在两个组成部分中仍然是相加的。 每条路径都由一对 (A_sum, B_sum) 完整描述，并且扩展路径只是将边缘贡献添加到两个坐标。 这建议将每个节点视为具有“最著名的对”，并通过图表传播改进，类似于最短路径，但使用对比较而不是标量比较。 

关键的想法是，我们可以使用问题的规则对这些对进行全排序：首先最小化 A × B，然后最小化 A，然后最小化 B。因为边权重是非负的，所以扩展路径可以保持两个总和的单调性，因此一旦在类似 Dijkstra 的过程中确认了节点的最佳对，以后就不会通过某些替代路径进行改进。 

这使我们能够运行标准的最短路径算法，其中距离是一对，并且通过（A × B，A，B）按字典顺序进行比较。 状态空间不需要扩展到节点之外，因为排序是完全的并且与加性转换一致。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有路径 | 指数| 指数递归栈| 太慢了 |
 | Dijkstra 具有对状态 (A, B) | O((N + M) log N) | O((N + M) log N) | O(N + M) | 已接受 |

 ## 算法演练

 我们根据问题定义的顺序将每个节点视为存储最已知的对（A，B）。

1. 使用无限成本对初始化所有节点，但从 (0, 0) 开始的节点 1 除外。 这代表我们还没有发现任何通往这些节点的路径。 
2. 使用按 (A × B, A, B) 排序的优先级队列。 我们总是扩展当前最已知的状态，因为由于非负边权重，任何更糟糕的状态都不能导致更好的最终答案。 
3. 从队列中弹出最佳状态 (u, A, B)。 如果这个状态已经比你记录的最佳状态更差，我们就跳过它。 这避免了处理过时的松弛。 
4. 对于每个权重为 (a, b) 的出边 u → v，计算新对 (A + a, B + b)。 这表示将当前路径扩展一个边沿，并且两个累加和单调增加。 
5. 使用排序 (A × B, A, B) 将此新对与当前记录的 v 最佳值进行比较。 如果更好，则更新 v 的最佳对并将其推入优先级队列。 
6. 队列耗尽后，节点 N 存储的最佳对就是答案。 

这个过程有效的原因是每个松弛步骤都保留了候选路径的正确性，并且优先级队列确保一旦节点以其最佳对完成，以后的松弛就不能产生严格更好的节点。 该排序与路径扩展一致，因为添加正值只能增加 A 和 B，因此不会使早期的最优决策失效。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**30

def better(a1, b1, a2, b2):
    p1 = a1 * b1
    p2 = a2 * b2
    if p1 != p2:
        return p1 < p2
    if a1 != a2:
        return a1 < a2
    return b1 < b2

def solve():
    T = int(input())
    for _ in range(T):
        N, M = map(int, input().split())
        g = [[] for _ in range(N + 1)]
        for _ in range(M):
            u, v, a, b = map(int, input().split())
            g[u].append((v, a, b))

        bestA = [INF] * (N + 1)
        bestB = [INF] * (N + 1)

        bestA[1], bestB[1] = 0, 0
        pq = []
        heapq.heappush(pq, (0, 0, 0, 1))  # (A*B, A, B, node)

        while pq:
            prod, A, B, u = heapq.heappop(pq)

            if not better(A, B, bestA[u], bestB[u]):
                continue

            bestA[u], bestB[u] = A, B

            for v, a, b in g[u]:
                nA = A + a
                nB = B + b
                nP = nA * nB
                if better(nA, nB, bestA[v], bestB[v]):
                    heapq.heappush(pq, (nP, nA, nB, v))

        print(bestA[N], bestB[N])

if __name__ == "__main__":
    solve()
```该解决方案仅保留每个节点最知名的对，同时仍然使用候选状态的优先级队列。 关键的微妙之处在于，比较函数不仅仅是乘积，还包括平局打破规则，并且在松弛和提取中一致使用相同的顺序。 

一个常见的陷阱是尝试仅存储像 A × B 这样的标量距离。这会丢失信息，因为两个不同的对可能具有相同的乘积，但在平局决胜时会导致不同的结果。 保留完整的一对是必要的。 

另一个微妙的点是，我们绝不会仅仅因为某个候选产品的产品较差（如果它以后在不同的扩展路径下可能是最佳的）而丢弃它。 优先级队列确保探索按照完整比较键的全局递增顺序进行，这使得过早剪枝变得安全。

 ## 边缘情况

 一个关键的边缘情况是当长路径的产品稍差但平局打破结构更好时。 该算法可以正确处理这个问题，因为每个候选者在被接受到优先级队列之前都会使用完整的排序进行比较。 即使一条路径的 A 较小但 B 较大，它也只会在乘积比较允许的情况下替换另一条路径。 

另一个微妙的情况是具有不同权重的相同节点之间的多条边。 由于在松弛中每条边都是独立处理的，因此算法自然会探索两种可能性并保留最佳对，确保平行边不需要特殊处理。
