 ## 解决方案
 ## 问题理解

 我们有一个隐藏的“加密系统”，它对长度为 3 的数字逐位工作$n$。 在每个位置$i$，有一个固定的排列$f_i$的数字$\{0,1,2\}$。 当数字被加密时，每个数字都会使用其位置的排列独立替换。 

复杂的是我们永远无法直接看到排列。 相反，我们可以提交由两个加密的三元字符串组成的查询$a$和$b$。 系统使用未知的映射对它们进行解密，将所得的纯三进制数（以基数 3 进位）相加，然后逐位重新加密结果。 

正式来说，如果$f^{-1}(a)$和$f^{-1}(b)$是解密后的值，法官以 3 为底计算它们的总和，然后应用$f$再次独立地到每个数字。 进位是仓位之间相互作用的唯一来源。 

任务是恢复每个排列$f_i$最多使用两个这样的查询。 

关键的困难在于加法引入了进位传播，它通常将位置耦合在一起。 尝试在不控制进位的情况下逐一推断数字的幼稚方法很快就会变得不可靠，因为对较低位置的错误假设会影响所有较高位置。 

限制条件很大：$n$可以达到$10^5$，并且最多有$10^4$测试用例总长度可达$10^6$。 这意味着任何解决方案都必须在线性时间内处理每个测试用例，并且仅执行恒定数量的交互式查询。 任何依赖于每个位置自适应查询的策略都是不可能的。 

朴素推理的一个微妙的失败案例是假设观察到的输出数字直接对应于固定的输入数字。 例如，如果我们尝试查询具有不同隔离模式的单个位置，则相邻位置的进位会污染结果，除非我们小心地强制进位为零。 

## 方法

 蛮力思维会尝试确定每个排列$f_i$通过隔离位置独立$i$。 人们可能会尝试构建只影响一位数字的查询，同时保持其他数字不变。 问题在于，即使较低位置的单个非零数字也可能生成改变所有较高位置的进位，从而使隔离变得昂贵且脆弱。 在最坏的情况下，这会导致$O(n)$每个位置的查询或自适应实验在总共只有两个查询的限制下是不可能的。 

关键的观察是，我们实际上不需要使用复杂的进位控制来隔离仓位。 我们只需要确保根本不产生进位。 如果我们可以保证每个数字加法都是独立的，那么每个位置的行为就像一个简单的替换密码。 

以 3 为基数的进位仅在将总和至少为 3 的数字相加时才会出现。这立即表明，如果我们将自己限制为仅数字 0 和 1，则无论未知的排列如何，都不会出现进位，因为解密的数字仍然是 0 或 1，并且它们的总和最多为 2。 

这使我们能够将交互式系统变成纯粹的按位置观察工具。 每个查询都成为独立的按数字评估的向量$f_i(x)$， 在哪里$x$是该位置处的解密数字和。 

我们可以通过两个精心选择的查询来利用这一点。 

第一个查询使用两个全零加密数字。 解密后，两个输入都为零，因此每个位置都计算$0 + 0 = 0$，产生输出数字$f_i(0)$独立。 

第二个查询使用一个全一加密数字和一个全零加密数字。 解密后，计算每个位置$1 + 0 = 1$，同样没有进位，产生输出数字$f_i(1)$。 

一旦我们知道$f_i(0)$和$f_i(1)$, 中的剩余数字$\{0,1,2\}$必须是$f_i(2)$。

 ## 算法演练

 1.构造两个长度-$n$三元字符串完全由以下组成`'0'`。 查询它们并接收结果字符串$c^{(0)}$。 每个角色$c^{(0)}_i$正是$f_i(0)$因为没有位置会经历任何进位。 
2.构造一个所有的字符串`'1'`并将其与全零字符串配对。 查询并接收$c^{(1)}$。 每个角色$c^{(1)}_i$正是$f_i(1)$出于同样的原因：每个数字独立加 1，不带进位。 
3. 对于每个位置$i$， 决定$f_i(2)$作为唯一的数字$\{0,1,2\}$没有出现在$\{f_i(0), f_i(1)\}$。 
4. 将所有排列按顺序输出为字符串。 

这样做的核心原因是我们有意将每个数字和限制为最多 1，从而防止任何进位传播。 这消除了所有跨位置交互并将交互系统简化为$n$独立的地方职能。 

### 为什么它有效

 一旦进位被消除，每个位置的行为就像一个独立的通道。 加法后加密独立应用于每个位置，因此如果解密的加法从未产生进位，则位置处的输出$i$仅取决于值$f_i^{-1}(a_i) + f_i^{-1}(b_i)$。 通过选择输入$\{0,1\}$只是，该总和永远不会超过 1，因此每个位置的映射都是直接显示的，而不受其他位置的干扰。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(a, b):
    print("?", a, b)
    sys.stdout.flush()
    return input().strip()

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())

        a0 = "0" * n
        a1 = "1" * n
        a2 = "0" * n

        # first query: 0 + 0
        c0 = ask(a0, a2)

        # second query: 1 + 0
        c1 = ask(a1, a2)

        res = []
        for i in range(n):
            used = {c0[i], c1[i]}
            for ch in "012":
                if ch not in used:
                    res.append(ch)
                    break

        print("!", "".join(res))
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```第一个查询构造了整个向量$f_i(0)$。 由于两个操作数都为零，因此没有数字位置可以生成进位，因此返回的字符串是零的直接每位置映射。 

第二个查询重复相同的结构，但在各处注入一个单位数字。 因为加法之前所有的数字要么是1，要么是0，总和永远不会达到3，所以进位仍然是不可能的。 这保证了输出编码$f_i(1)$独立。 

最后，重建每个排列纯粹是集合完成：一旦知道三个元素上的双射的两个图像，第三个就被唯一确定。

这两条轨迹表明，一旦避免进位，系统就会完全分解为独立的每个位置函数。

 ## 边缘情况

 一个潜在的问题是，即使仅使用数字 0 和 1，进位是否也会意外出现。例如，如果假定对齐不正确或意外引入更高的数字，进位就会传播并破坏所有更高的位置。 该结构通过确保两个查询仅包含使每个本地总和低于 3 的数字来完全避免这种情况。 

另一个微妙的例子是对立场独立性的误解。 尽管加密是按位置进行的，但加法却不是。 该解决方案确保通过限制数字集有效地抵消加法，因此不会存在任何隐藏的交互。
