 ## 解决方案
 ## 问题理解

 我们有一棵树，每个节点都带有一个大写字母。 一个查询要求我们计算这棵树中有多少条简单路径正好包含五个节点，如果我们按顺序读取路径上的字母，它们必须形成固定模式“S C C P C”。 

这里的简单路径意味着我们选择树中的任意两个端点并读取它们之间的唯一路径。 由于树是无向的，因此可以在任一方向遍历同一组节点，但顺序对于匹配所需字符串很重要，因此有效路径只有一个方向起作用。 

限制非常大：在所有测试用例中，节点总数可以达到 200 万。 这立即排除了任何尝试枚举所有路径甚至所有端点对的解决方案。 具有 n 个节点的树有 θ(n²) 条简单路径，因此任何隐式触及所有路径的方法都会失败。 

目标模式有固定长度5，这是关键的结构限制。 我们不是推理任意路径，而是只寻找长度为 4 的边路径（五个顶点），这表明任何有效路径都是“局部的”，并且可以通过有界深度结构上的动态编程来捕获。 

一个简单但重要的边缘情况是当模式在树结构中与自身重叠时。 例如，像 S C C P C C C 这样的链可能包含多个重叠的有效段，如果路径没有一致地锚定在起始节点，很容易意外地过度计数。 

另一个微妙的例子是方向性。 如果路径反向读取 C P C C S，则除非反向序列与模式匹配，否则该路径无效，但事实并非如此。 因此，当我们强制执行一致的“开始到结束”方向时，每个有效路径都会被精确计数一次。 

## 方法

 最直接的想法是将每对节点视为端点，计算它们的路径，并检查序列是否与模式匹配。 这在原则上是正确的，因为每条简单路径都是由其端点唯一确定的，并且我们可以使用 LCA 预处理来检索序列。 

然而，这在规模上立即失败了。 有 θ(n²) 对，每条路径提取成本为 θ(长度)，导致最坏情况约为 θ(n³)。 即使LCA将路径构造减少为沿父指针的对数或线性遍历，路径总数仍然是二次的，这远远超出了极限。 

关键的观察结果是图案长度是固定的并且非常小。 这意味着我们不需要全局路径枚举。 相反，我们可以将问题重新构造为计算长度最多为四个与模式前缀匹配的边的所有根到后代路径。 一旦我们修复了根，每个有效路径在树中都有一个唯一的“起始节点”，因此我们可以通过将每个有效路径锚定在其第一个节点来对每个有效路径进行一次计数。 

这导致了树动态规划公式。 对于每个节点，我们计算从它开始的向下路径有多少条与模式的前 k 个字符匹配，k 最多为 5。由于任何有效路径从其开始都完全包含在深度 4 子树中，因此这个 DP 就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有路径进行暴力破解 | O(n3) | O(1) | O(1) | 太慢了 |
 | 有界模式深度上的树DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们定义一个固定模式 P = “S C C P C”。 

为了方便起见，我们将树建立在任意位置，节点 1。然后，我们在有根树上计算 DP，其中 dp[u][k] 表示从节点 u 开始的向下路径的数量，这些路径与模式的前 k 个字符匹配并且仅遵循子边缘。

1. 我们对树执行深度优先遍历，在处理父级之前处理子级。 这确保了当我们计算节点的值时，其所有子树信息都已经可用。 
2. 对于每个节点 u，如果 u 处的字符等于 P[0]，则将 dp[u][1] 初始化为 1，否则为 0。这反映了这样一个事实：只有起始字符匹配，才可能进行长度为 1 的前缀匹配。 
3. 对于从 2 到 5 的 k，我们通过求和所有子项 v 的贡献来计算 dp[u][k]。如果 dp[v][k-1] 不为零并且 u 处的字符与 P[k-1] 匹配，则子项 v 对 dp[u][k] 做出贡献。 这强制路径从 u 开始并继续向下按顺序匹配模式。 
4、处理完所有节点后，最终的答案就是dp[u][5]的所有节点u的和。 每个这样的值对应于一条有效的长度为 5 的路径，该路径恰好从 u 开始并下降到树中。 

关键的设计选择是将路径锚定在其第一个节点。 这消除了歧义：在此公式中，每条有效路径都只有一个有效起点，因此不会重复计算任何路径。 

### 为什么它有效

 任何五个节点的有效路径沿其方向都有唯一的第一个节点。 通过对树进行生根，每个简单路径都具有唯一的表示，作为从其导出子树方向上的第一个节点开始的向下路径。 DP 确保每个起始节点仅对最多四个边的所有可能的长度向下延续进行探索一次。 由于转换仅沿父子边缘延伸并严格遵循模式顺序，因此无法构造无效序列，并且每个有效序列在其起始节点处仅计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

PAT = "SCCPC"

def solve():
    n = int(input())
    s = input().strip()

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    dp = [[0] * 6 for _ in range(n)]
    parent = [-1] * n

    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    for u in reversed(order):
        if s[u] == PAT[0]:
            dp[u][1] = 1

        for v in g[u]:
            if v == parent[u]:
                continue
            for k in range(2, 6):
                if s[u] == PAT[k - 1]:
                    dp[u][k] += dp[v][k - 1]

    ans = 0
    for u in range(n):
        ans += dp[u][5]

    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该解决方案首先构建树邻接表，然后使用迭代 DFS 将其转换为有根结构，以避免递归深度问题。 然后以反向遍历顺序填充 dp 表，以便在其父级之前处理子级。 

转换步骤是关键部分：对于每个节点 u，如果 u 与模式中的相应字符匹配，我们仅扩展有效前缀。 这可以防止无效的部分匹配向上传播。 

最后，我们对所有节点上的 dp[u][5] 求和。 这是安全的，因为在此 DP 公式中，每条有效路径均由其起始节点唯一标识。 

## 工作示例

 ### 示例 1

 树是一个带有标签 SCCPC 的简单链 1-2-3-4-5。 

我们从叶子向上处理。 

| 节点| s[u] | dp[1] | dp[1] | dp[2] | dp[2] | dp[3] | dp[3] | dp[4] | dp[4] | dp[5] | dp[5] |
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | S | 1 | 1 | 1 | 1 | 1 |
 | 2 | C | 0 | 1 | 1 | 1 | 1 |
 | 3 | C | 0 | 0 | 1 | 1 | 1 |
 | 4 | 普 | 0 | 0 | 0 | 1 | 1 |
 | 5 | C | 0 | 0 | 0 | 0 | 1 |

 最终答案是1，对应整条链。 

该跟踪表明，一旦形成前缀匹配，它就会沿着链精确地向上传播，而不会出现分支歧义。 

### 示例 2

 考虑以节点 1 为中心的星形，具有叶子 2、3、4、5，并且沿着一个分支仅嵌入一条有效链。 

只有匹配 S → C → C → P → C 的分支才对其起始节点处的 dp[5] 做出贡献。 所有其他分支由于字符不匹配或缺乏深度而提前失败。 

这表明无效的部分匹配不会泄漏到不相关的子树中。

 ## 边缘情况

 一种关键的边缘情况是多个分支共享前缀，但只有一个分支完成完整模式。 DP 确保只有完整的深度 4 扩展才会对 dp[u][5] 做出贡献，因此其他分支中的部分匹配永远不会累积成误报。 

另一个边缘情况是树退化为长链。 在这种情况下，DP 的行为就像链上的滑动窗口，并且每次有效出现的答案都保持准确，没有重复，因为每个起始节点独立贡献。
