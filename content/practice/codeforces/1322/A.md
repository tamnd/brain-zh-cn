 ## 解决方案
 ## 问题理解

 我们得到一个仅由括号组成的字符串，并且允许我们使用选择任何连续段并任意排列其字符的操作来修改它。 这种操作的成本等于所选段的长度。 目标是以最小的总成本将初始字符串转换为正确的括号序列，或者决定它无法完成。 

这里的正确序列具有通常的含义：它的行为就像一个有效的表达式，其中每个前缀的右括号永远不会多于左括号，并且左括号和右括号的总数相等。 

关键细节是我们不允许自由更改字符，只能在选定的段内重新排序，并且成本取决于所选段的大小。 这从根本上解决了我们如何以低廉的成本将左括号“移动”到需要它们的位置的问题。 

约束条件可达$10^6$字符立即排除任何尝试所有子字符串或显式模拟操作的解决方案。 任何有效的方法都必须是线性或近线性的，因为即使$O(n \log n)$根据常数，可能会很紧。 

第一个微妙的边缘情况是当字符串包含太多前缀意义上的右括号而无法全局补偿时。 例如，如果字符串以“)))((”开头，则第一个前缀已经无效，即使允许重新排序，总体上仍然需要足够的左括号。如果“(”总数小于“)”，则不可能形成任何正确的序列，因此答案必须为-1。

 另一个棘手的情况是，当字符串总体上已经平衡但严重错序时，例如“))((”。天真的直觉可能会建议进行局部修复，但成本模型使括号的位置变得至关重要，因为跨长段移动有用的“(”的成本很高。

 ## 方法

 暴力策略将尝试重复选择段并模拟所有可能的重新排序，以将字符串推向有效的配置。 即使我们限制自己进行“有用”的重新排序，可能的段选择数量也是$O(n^2)$，并且每个操作可能需要扫描或重建字符串的部分内容，使其远远超出可行的限制。 

关键的观察是，我们实际上从不关心段内的内部顺序，只关心重新定位括号的能力。 每个操作实际上都是从字符串后面获取一些“(”并将其放在前面的方法，从而修复前缀余额变为负数的点。

 这建议从左到右扫描字符串，同时保持当前平衡。 每当我们遇到右括号超过左括号的不平衡时，我们必须从未来“导入”左括号。 最便宜的有效导入始终是右侧最接近的可用“(”，因为获取一段的成本与其长度成正比。

 因此，我们不再考虑任意排列，而是将问题简化为使用最近的可用“(”重复修复负前缀平衡。

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力重新排序| 指数| O(n) | 太慢了|
 | 贪婪最近 '(' 修复 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护所有左括号的位置，并从左到右扫描字符串，跟踪当前余额，就像在正常的有效性检查中一样。 

1. 预先计算并将“(”的所有索引存储在列表中。这使我们始终可以按顺序访问下一个可用的左括号。
 2. 初始化一个指向该列表的指针，表示我们已经消耗了多少个“(”来修复早期的问题。
 3. 将余额变量初始化为零。 这会跟踪模拟修正后我们在当前前缀中看到的“(”比“)”多了多少个。 
4. 从左到右迭代字符串的每个位置 i。 

如果字符是“(”，则余额增加一。如果是“)”，则余额减少一。 

当余额为负数时，当前前缀无效。 此时，我们必须通过从未来获取下一个未使用的“(”来解决这种情况。

 让'('位于位置j。如果不存在这样的位置，则转换是不可能的，因为我们无法补偿多余的右括号。

 然后，我们对段 [i, j] 应用概念操作，将“(”移动到位置 i。添加的成本为 (j - i + 1)。

 进行此修复后，我们将效果视为当前位置 i 现在是“(”，因此余额变为 1 而不是保持负数，并且我们将指针移到使用的“(”上。
 5. 继续扫描直到字符串末尾。 
6. 总累计成本就是答案。 

关键的不变量是，在任何时刻，所有前缀赤字都可以使用最早可用的左括号来解决。 这确保了未来的步骤不会变得比必要的更昂贵，因为推迟修复只会将所需的“(”推得更远，从而增加成本。

 该算法不可能找不到最佳解决方案，因为每次出现赤字时，任何有效的最终序列都必须将一些“(”分配给该位置或更早的位置，并且选择最接近的此类“(”可以最大限度地减少该分配的成本贡献。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    opens = [i for i, c in enumerate(s) if c == '(']
    total_opens = len(opens)
    if total_opens * 2 != n:
        print(-1)
        return

    ptr = 0
    bal = 0
    ans = 0

    opens = opens  # list of positions

    for i, c in enumerate(s):
        if c == '(':
            bal += 1
        else:
            bal -= 1

        if bal < 0:
            if ptr >= total_opens:
                print(-1)
                return
            j = opens[ptr]
            ptr += 1

            ans += (j - i + 1)
            bal = 1  # we effectively placed '(' at position i

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先通过检查左括号和右括号的总数是否匹配来确保可行性。 如果没有这个条件，重排就不能产生正确的序列。 

主循环模拟标准有效性检查，同时修复任何无效的前缀。 左括号上的指针保证每个“(”最多用作修复源一次。

 一个微妙的点是修复后平衡重置为1。 这反映出当前位置已有效纠正为左括号，因此前缀不再为负数。

 ## 边缘情况

 在第一个字符处变为负数的前缀是通过立即消耗第一个可用的左括号来处理的。 该算法不假设任何缓冲区，因此即使后面存在“(”，即使以“)”开头的字符串也会被正确修复。 

当所有左括号都聚集在末尾时，每个早期右括号都会触发修复。 指针确保每个左括号按顺序使用，并且随着不可能进行越来越短的跳跃，成本会累积，这反映了跨大间隙移动角色的必要性。 

当左括号数量不足时，初始可行性检查会在任何模拟开始之前检测到这一点，从而避免错误的部分处理。
