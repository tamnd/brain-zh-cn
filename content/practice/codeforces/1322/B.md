 ## 解决方案

 ## 问题理解

 给定一个整数数组，我们考虑每对无序的不同元素。 对于每一对，我们计算它们的总和。 收集所有这些成对和后，我们不是对它们求和或最小化，而是使用按位异或将它们组合起来。 任务是有效地计算最终的 XOR 值。 

直接解释很简单：生成表单的所有值$a_i + a_j$为了$i < j$，然后将它们异或在一起。 困难来自于此类对的数量。 由于元素多达 400,000 个，对的数量大约达到 8 × 10^10，这远远超出了任何显式枚举的处理能力。 这立即排除了任何依赖于迭代对或存储所有总和的解决方案。 

主要挑战是加法和异或都在位级别交互，但方式不同。 加法引入了跨位进位，而异或则每个位独立运行。 这种不匹配是天真的推理往往失败的地方。 

打破简单方法的典型边缘情况是当许多数字相同或进位主导加法结构时。 例如，如果所有元素均为 2，则每对的和为 4，并且 XOR 仅取决于对的数量是奇数还是偶数。 暴力方法仍然可以在概念上处理这个问题，但是任何试图通过每个元素聚合错误地压缩总和而不处理进位的任何尝试都会失败，因为进位取决于对结构，而不是单个值。 

另一个微妙的情况是小型数组，其中对的结构最少。 例如，对于`[1, 2, 3]`，总和是`3, 4, 5`，异或行为取决于这些结果的二进制重叠。 任何试图独立地对每个元素进行异或贡献的方法都会失败，因为成对相互作用是不可分离的。 

## 方法

 强力方法会迭代所有对，计算它们的总和，并对它们进行异或。 这是正确的，但立即不可行。 当 n = 400,000 时，运算次数约为 n² / 2，大约是 8 × 10^10 次加法和异或运算，远远超出了时间限制。 

为了改进这一点，我们关注最终答案的按位结构。 关键的观察结果是 XOR 是按位独立的，这意味着最终答案的每一位仅取决于有多少对和设置了该位。 

因此，我们不是直接计算和，而是问：对于固定位 k，有多少对 (i, j) 产生第 k 位为 1 的和？ 如果计数为奇数，则答案的第 k 位为 1； 否则为0。 

现在的困难转移到确定对于每个位，产生设置该位的进位结构的对的数量是奇数还是偶数。 直接的每比特对计数看起来仍然是二次的，但是我们可以通过分离比特的贡献并使用较低比特的前缀频率计数来避免重新计算对和。 

我们从低位到高位处理位。 对于每个位 k，我们只关心模 2^(k+1) 的值，因为较高位不影响加法后是否设置位 k。 这允许我们按较低位对数字进行存储，并使用排序和两指针式计数或频率图对有效对进行计数。 

主要的结构技巧是，对于固定的 k，(a[i] + a[j]) 设置位 k 的条件仅取决于 (a[i] mod 2^(k+1)) 和 (a[j] mod 2^(k+1))。 这将问题简化为在循环间隔中对对进行计数，这可以在每位 O(n log n) 的时间内完成，或者使用排序和两指针扫描进一步优化。 

由于位数是有界的（a[i] ≤ 10^7），因此我们最多只需要考虑大约 24 位，从而使总复杂性易于管理。

 ## 算法演练

 1. 我们迭代从 0 到 24 的每个位位置 k。每次迭代都决定最终答案中是否设置了该位。 

我们隔离位的原因是 XOR 可以干净地分解每个位。 
2. 对于固定的 k，我们将每个数组元素减少到其值模 2^(k+1)。 这准确地保留了影响和的第 k 位是否变为 1 的信息。 
3. 我们对这个缩减后的数组进行排序。 排序允许我们使用两个指针而不是嵌套循环来计算每个值的有效伙伴元素。 
4. 我们计算有多少对产生第 k 位为 1 的和。此条件对应于落入 [0, 2^(k+1)) 内特定区间的和，因为当和位于该位切换的范围内时，位 k 恰好为 1。 
5. 我们通过用两个指针扫过排序后的约简值，计算有多少补数落入所需的区间结构，从而有效地计算此类对的数量。 
6. 如果有效对的总数是奇数，我们在答案中设置位 k。 否则，我们将其保留为未设置。 

### 为什么它有效

 对于每个位k，高位的贡献不影响加法后是否设置位k，因为加法仅取决于低位的进位。 通过模 2^(k+1)，我们完全捕获与位 k 相关的所有进位交互。 所有对的异或仅取决于贡献的奇偶性，因此一旦我们正确计算了有多少对和设置了位 k，我们就完全确定了答案的该位。 各个位之间的独立性确保了组合结果时的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    MAXB = 25
    ans = 0
    
    for b in range(MAXB):
        mod = 1 << (b + 1)
        half = 1 << b
        
        vals = [x % mod for x in a]
        vals.sort()
        
        cnt = 0
        
        j1 = j2 = n
        
        for i in range(n):
            while j1 > i and vals[i] + vals[j1 - 1] >= half:
                j1 -= 1
            while j2 > i and vals[i] + vals[j2 - 1] >= mod:
                j2 -= 1
            
            cnt += (j2 - j1)
        
        if cnt % 2 == 1:
            ans |= (1 << b)
    
    print(ans)

if __name__ == "__main__":
    solve()
```核心实现重复地减少 2 的模幂数，以便仅保留相关的较低位。 对于每个位，我们将对和分类为该位变为 1 的范围。两指针结构有效地维护这些范围的边界，确保我们在排序后在每个位的线性时间内对有效对进行计数。 

必须注意指针更新的顺序：两个指针在 i 上都是单调的，这确保了总复杂度在每位上保持线性。

 ## 边缘情况

 对于所有值都相同的数组，每对和都相同，因此答案仅取决于对的数量是否为奇数。 例如，与`[5, 5, 5, 5]`，有 6 个对，总和为 10，因此 XOR 为 0。该算法可以正确处理此问题，因为对于每个位，贡献对的计数是偶数。 

对于 n = 2 的小数组，该算法简化为计算单个和，并且每个位都直接根据该和确定。 基于模的计数仍然准确地产生一对有效的，从而确保了正确性。 

对于接近 10^7 的最大值，超过 24 的较高位始终保持为零，因此限制位循环不会错过任何贡献。
