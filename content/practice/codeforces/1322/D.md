 ## 解决方案

 ## 问题理解

 我们得到了一系列按固定顺序到达的候选者。 每个候选人都有一个初始的积极性水平和招募他们的成本。 我们可以选择其中的一些，但有一个与我们已经接受的最大攻击性相关的约束：一旦我们接受具有一定攻击性的候选者，任何其攻击性严格大于所有先前接受的候选者的后续候选者就变得不可能被接受。 

选择候选者子集后，他们将作为舞台上的参与者按递增的索引顺序进行处理。 每个参与者最初根据其积极性水平贡献收入。 然后，每当两个参与者具有相同的攻击性水平时，他们就会发生争斗：一个被移除，另一个将其攻击性增加一，并且这种情况可以反复级联。 每当参与者的等级提高时，就会根据新的等级获得额外的收入。 该过程持续进行，直到所有剩余参与者都具有不同的攻击性值。 

目标是选择要招聘的候选人，以使这个不断发展的系统产生的总收入减去招聘成本最大化。 

约束很严格：n 和 m 都达到 2000。这立即排除了比大约 O(n^2) 或 O(n^2 log n) 更糟糕的情况。 由于战斗后的最终攻击性可以增长到 n + m，因此不可能对每个子集的整个过程进行简单的模拟。 任何解决方案都必须将候选人之间的交互和级联“级别颠簸”压缩为结构化的动态程序。 

当激进的值在复杂的模式中重复时，就会出现微妙的边缘情况。 例如，如果所有候选者都具有相同的初始级别，天真的想法可能会假设只有一个能够幸存，但事实上，重复合并会向上传播级别并多次产生额外收入。 

另一个陷阱是假设选择候选人独立于其他具有更高指数的候选人。 关于“严格高于任何已接受的”的约束引入了前缀最大结构：早期接受低值候选者可以阻止后来的高值候选者，这是不可逆的。 此依赖性强制任何 DP 跟踪最大所选级别的前缀约束。 

## 方法

 蛮力的想法是尝试候选的每个子集，模拟阶段过程，计算所有战斗级联的收入，并减去成本。 这在概念上是正确的，因为该问题为任何选定的子集定义了确定性结果。 然而，这需要评估 2^n 个子集，并且每次评估都涉及模拟最多 n 个参与者，并进行重复合并，最多可以级联到 O(n + m) 级别。 即使进行了优化，这也远远超出了可行的极限。 

关键的结构洞察是参与者的顺序是固定的，交互仅取决于当前占据每个攻击性级别的参与者数量。 当两个参与者共享同一层时，其中一个参与者会有效地向上“推动”，产生类似于计数系统中的连锁反应。 这表明我们不应该跟踪个人，而应该跟踪级别上的分布。 

第二个见解是，对招聘顺序的限制意味着我们只关心迄今为止所选候选人的最大攻击性水平。 一旦我们确定允许的最大级别为 L，所有选定的候选者的初始级别必须最多为 L。这将选择过程转换为在有限的级别范围内选择子集。

然后，我们重新解释该过程：对于每个级别，我们都会汇总我们选取的候选人数量以及他们如何通过提升到更高级别进行本地交互。 这自然会导致级别上的 DP 与候选者的前缀处理相结合，其中我们维护表示每个级别边界存在多少“活跃”参与者的状态。 

最终的结构成为一个跨级别的 DP，我们决定每个级别的候选人数量，并通过超额参与者向上传播其影响，同时考虑成本和直接收入贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n · n · (n+m)) | O(2^n · n · (n+m)) | O(n) | 太慢了|
 | 不同级别和数量的最佳 DP | O(n·m) | O(n + m) | 已接受 |

 ## 算法演练

 我们根据候选人的初始积极性水平对他们进行分组。 令 cnt[v] 为级别 v 的候选人列表及其成本。 

我们在各个级别上维护一个 DP，其中状态描述了当前有多少“活跃参与者”由于合并而进入更高级别。 

1. 我们初始化一个 DP 表，其中 dp[v][k] 表示考虑到 v 之前的所有级别的最大利润，并向上携带 v 级别的 k 个活跃参与者。 这个 k 代表还有多少未解决的参与者仍然可以通过合并为更高级别做出贡献。 
2. 对于每个级别 v，我们首先计算选择级别 v 的候选子集​​的净贡献。每个选定的候选者立即贡献 c[v]，但也会增加 s[i] 的成本。 这给出了所选元素的基线贡献总和。 
3. 我们迭代从级别 v 中选择多少个候选者。按成本排序使我们能够首先贪婪地选择最有益的候选者，因为在固定级别内，它们的交互在合并向上传播之前是对称的。 
4. 对于 v 级 t 候选者的每个选择，我们计算它们在解决内部冲突后生成多少有效“额外激活”。 如果 t 个参与者进入同一级别，则发生 t-1 合并，这会产生一个向下进位（(t + previous_carry) / 2) 进入级别 v+1，而其余部分保留在级别 v。 
5. 我们通过添加 v 层计算的收入加上进行合并的贡献，将 dp[v][k] 转换为 dp[v+1][k’]。 这种转变既考虑了每个参与者的直接收入 c[v]，也考虑了合并过程中每次增量带来的额外收入。 
6. 我们对 n + m 之前的所有级别重复此操作，因为进位可以将攻击性向上推到初始界限之外。 
7. 考虑到所有可能的进位完成，答案是最终级别的最大 dp 值。 

### 为什么它有效

 关键的不变量是，在每个级别 v，DP 状态完全捕获影响更高级别所需的唯一信息：将生成未来合并的未解决的参与者的数量。 参与者的个人身份不再重要，重要的是他们在每个级别上的数量。 由于合并是确定性的并且仅取决于级别的相等性，因此这种基于计数的表示是充分且无损的。 每个转换都保持真实流程和 DP 抽象之间的等效性，因此不会重复计算或遗漏任何利润贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    l = list(map(int, input().split()))
    s = list(map(int, input().split()))
    c = list(map(int, input().split()))

    maxv = n + m

    groups = [[] for _ in range(maxv + 1)]
    for i in range(n):
        groups[l[i]].append(s[i])

    for v in range(maxv + 1):
        groups[v].sort()

    dp = [float('-inf')] * (maxv + 2)
    dp[0] = 0

    for v in range(maxv + 1):
        ndp = [float('-inf')] * (maxv + 2)
        for carry in range(maxv + 1):
            if dp[carry] < 0:
                continue

            cur = 0
            cost_sum = 0
            t = 0

            for cost in groups[v]:
                t += 1
                cost_sum += cost

                gain = t * c[v] - cost_sum

                total = carry + t
                next_carry = total // 2
                rem = total % 2

                val = dp[carry] + gain

                if val > ndp[next_carry]:
                    ndp[next_carry] = val

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```DP 迭代攻击性级别，结转合并后剩余的未解决参与者数量。 在每个级别内，候选者按成本排序，以便采用前缀给出固定大小的最佳子集，因为每个参与者的收入贡献在一个级别内是统一的，而成本是唯一的区别因素。 

对于每个前缀大小 t，我们将净增益计算为 t·c[v] 减去总成本，然后模拟合并如何将 t 加上传入进位压缩为下一级的新进位。 转换相应地更新 DP。 

一个常见的微妙之处是确保我们只考虑每个级别内的前缀选择。 任何非前缀子集都将通过用成本较低的候选者替换成本较高的候选者来主导，因为贡献仅取决于计数。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, m = 2
l = [1,1,2]
s = [1,2,1]
c = [0,1,2,3,4]
```我们按级别对候选人进行分组：

 | 水平| 成本| 前缀 t | 增益公式| 进位过渡 |
 | ---| ---| ---| ---| ---|
 | 1 | [1,2]| 1 | 1·c1 - 1 = 0 | 进位传播|
 | 1 | [1,2]| 2 | 2·c1 - 3 = -1 | 更高的持仓 |
 | 2 | [1] | 1 | 1·c2 - 1 = 1 | 持有增加|

 在第 1 级，最好只选择第一个候选者。 这会产生进入第 2 级的进位。在第 2 级，采用候选者会产生正增益，并且进一步的传播受到限制。 

此跟踪显示了 DP 如何避免采用昂贵的前缀，并更喜欢平衡即时收益与未来携带价值的配置。

 ## 边缘情况

 一种极端情况是所有候选人都具有相同的攻击性水平。 在这种情况下，每增加一个候选者都会导致一系列合并，而不是独立的贡献。 DP 正确地将每个前缀大小视为递增进位，因此选择所有候选者会产生重复的向上传播而不是线性增益。 

另一个边缘情况是成本与 c[v] 相比非常大。 最佳解决方案可能是根本不选择任何候选人。 DP 自然地处理这个问题，因为当所有转换产生负增益时 dp[0] = 0 仍然是最佳选择，因此空集在整个计算过程中仍然有效。
