 ## 解决方案
 ## 问题理解

 我们从一个二进制字符串开始。 我们必须准确执行\(k\)运营。 

在一次操作中我们选择一个位置\(i\)。 所选位保持不变，而字符串中的所有其他位都会翻转。 毕竟\(k\)操作我们希望结果字符串按字典顺序尽可能大。 我们还必须输出每个位置被选择的次数。 

首先要了解的是重复操作的效果。 选择一个职位并不会直接修改该职位。 相反，它会修改所有其他位置。 因为只有奇偶性才重要，所以我们不关心一个位置被选择了多少次，只关心它被选择的次数是奇数还是偶数。 

这些限制立即排除了任何操作模拟。 单次操作影响\(n-1\)职位，以及\(k\)可以大到\(10^9\)。 甚至一一追踪操作也是不可能的。 由于所有字符串的总长度最多为\(2 \cdot 10^5\)，每个测试用例的 \(O(n)\) 或 \(O(n \log n)\) 解决方案是目标。 

出现微妙的边缘情况时\(k\)很奇怪。 考虑：```text
1 1
0
```只有一个位置。 我们必须在某个地方进行一次手术。 最后一点变成\(1\)， 不是\(0\)。 任何贪婪地将零变成一而不考虑未使用操作的奇偶校验的解决方案都会失败。 

另一个重要的情况是当操作数量多于有用位置时。```text
3 10
111
```最大化字符串后，仍然存在一些操作。 这些操作不能消失。 它们的奇偶校验会影响最终的字符串，并且必须分配到某个地方。 仅跟踪贪婪阶段期间明确使用的位置的解决方案将产生错误的答案。 

第三个陷阱是最后一个位置。 标准贪婪策略有意将所有剩余操作转储到最后一个索引中。 如果忘记了特殊处理，计数之和将不会为\(k\)。 

## 方法

 暴力方法会尝试对每个操作进行建模。 在每一步中，我们都会选择一个位置并更新字符串。 即使我们以某种方式知道最佳选择，每个操作的成本都是 O(n)，产生 O(nk) 工作量。 和\(k\)最多\(10^9\)，这是没有希望的。 

关键的观察是只有平等才重要。 

假设位置\(i\)被选中\(f_i\)次。 让$$
K = \sum_i f_i = k.
$$位置有点\(i\)除了那些选择的操作之外，在每个操作期间都会翻转\(i\)。 因此它被翻转了$$
k - f_i
$$次。 

仅有奇偶校验\(k-f_i\)很重要。 最后一点是$$
s_i \oplus ((k-f_i)\bmod 2).
$$现在问题变成了建设性的奇偶校验分配问题。 

首先考虑以下情况\(k\)很奇怪。 一个位置包含\(0\)可以成为\(1\)如果我们选择那个位置一次。 由于字典顺序由前面的位置主导，因此我们应该从左到右进行操作，将尽可能多的前面的 0 变成 1。 

什么时候\(k\)是偶数，对称命题成立。 一个位置包含\(1\)可以成为\(1\)如果我们选择一次，就会在最终字符串中。 我们再次从左到右贪婪地处理。 

在耗尽有用位置或可用操作后，所有剩余操作都将转储到最后一个位置。 只有它们的奇偶性很重要，因此这在满足精确使用要求的同时保留了最优性\(k\)移动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---:|---:|---|
 | 蛮力 | \(O(nk)\) | \(O(n)\) | 太慢了|
 | 最优贪心构造 | \(O(n)\) | \(O(n)\) | 已接受 |

 ## 算法演练

 1. 创建数组`cnt`长度\(n\)，最初全为零。 这将存储每个位置被选择的次数。 

2.让`rem = k`。 

3. 从左到右扫描位置，不包括最后一个位置。 

4.如果\(k\)是奇数，当前位是`'0'`，一旦选择该位置，其最终值变为`'1'`。 如果`rem > 0`， 放：$$
cnt[i] = 1
$$并减少`rem`。 

5. 如果\(k\)是偶数，当前位是`'1'`，选择这个位置一旦保持领先`'1'`在最终的答案中。 如果`rem > 0`， 放：$$
cnt[i] = 1
$$并减少`rem`。 

6. 后加工位置\(1\)通过\(n-1\)，将所有剩余操作放在最后一个位置：$$
cnt[n-1] = rem.
$$7. 构建最终的字符串。 对于职位\(i\)，对其应用的翻转次数等于$$
k - cnt[i].
$$如果这个数量是奇数，则翻转原始位。 否则保持不变。 

8.输出最终的字符串和数组`cnt`。 

### 为什么它有效

 字典顺序由两个字符串不同的第一个位置确定。 每当操作可以将较早的位置转变为`1`，这样做总是至少与将该操作保存到以后的位置一样好。 贪婪扫描正是按照这个优先级顺序处理位置。 

每个有用的位置只需要一次操作，因为只有奇偶校验才重要。 在同一位置上执行 3 次、5 次或 7 次操作与执行 1 次操作具有相同的效果。 因此，贪婪阶段使用最大化最早位置所需的最少操作数。 

贪婪阶段之后剩下的任何操作都无法改善任何早期的位置。 将它们全部分配给最后一个索引可以保留最佳前缀并满足精确使用的要求\(k\)移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, k = map(int, input().split())
        s = list(input().strip())

        cnt = [0] * n
        rem = k

        target = '0' if k % 2 else '1'

        for i in range(n - 1):
            if rem > 0 and s[i] == target:
                cnt[i] = 1
                rem -= 1

        cnt[-1] += rem

        ans = []

        for i in range(n):
            flips = (k - cnt[i]) & 1

            bit = int(s[i])

            if flips:
                bit ^= 1

            ans.append(str(bit))

        print("".join(ans))
        print(*cnt)

if __name__ == "__main__":
    solve()
```数组`cnt`存储准确的操作计数。 变量`target`捕获依赖于奇偶性的贪婪规则。 什么时候\(k\)奇怪的是我们的目标为零。 什么时候\(k\)甚至是我们的目标。 

最终的重建使用了一个位置被精确翻转的公式\(k-cnt[i]\)次。 只有奇偶性才重要，所以我们计算```python
flips = (k - cnt[i]) & 1
```并根据需要应用翻转。 

最后一个位置接收所有未使用的操作。 这保证了$$
\sum_i cnt[i] = k.
$$## 工作示例

 ## 边缘情况

 考虑：```text
1
1 5
0
```只有一个位置。 贪婪循环永远不会运行，因为最后一个之前没有位置。 所有五个操作都分配给该位置。 自从$$
k-cnt[0]=5-5=0,
$$该位永远不会翻转并保持不变`0`。 计数和正好是五。 

考虑：```text
1
3 10
111
```这里\(k\)是均匀的。 贪婪阶段在前两个位置上花费一次操作，并为最后一个位置留下八次操作。 重建仅取决于奇偶校验，而不取决于十的数量级。 该算法使用所有的移动，同时保留字典顺序上最大的可达到的前缀。 

考虑：```text
1
4 1
0000
```第一个位置立即转换为最佳可能的前导位。 一旦没有剩余操作，其余位置就无关紧要。 这证实了最早位置上的贪婪选择始终是最优的。
