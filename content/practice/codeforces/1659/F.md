 ## 解决方案
 ## 问题理解

 我们有一棵树，其中每个顶点在排列中都有一个位置。 另外，一个顶点上有一个令牌。 游戏在爱丽丝和鲍勃之间交替移动中演变。 

爱丽丝的举动不会改变树。 相反，她通过交换两个值来操纵排列，但有一个限制：她不允许涉及当前位于令牌所在顶点的值，也不允许涉及该顶点处的值。 鲍勃的移动根本不触及排列，而是将标记沿着树的一侧移动。 

一旦排列在她的一个动作开始或结束时被排序，爱丽丝就获胜。 Bob 避免失败的唯一方法是让游戏保持在 Alice 永远无法强制排序配置的状态。 

关键的张力在于，Alice 试图在移动的禁止顶点下“修复”排列，而 Bob 则通过遍历令牌来控制下一个被禁止的顶点。 

这些限制使得对游戏状态进行暴力推理变得不可能。 该树在一个测试文件中最多可以有 200,000 个顶点，并且最多有 1000 个测试用例，因此每个测试的任何解决方案都必须是线性或接近线性的。 任何模拟游戏或探索排列和令牌位置状态的东西都是立即不可行的。 

当排列在开始时已经排序时，会出现微妙的边缘情况。 在这种情况下，在任何交互变得重要之前，爱丽丝就获胜了。 另一个脆弱的情况是当树是一条路径时：鲍勃的移动受到高度限制，局部结构变得至关重要。 最后，如果排列可以在不依赖禁止顶点的情况下“局部纠正”，那么爱丽丝可能能够完全忽略鲍勃，但这取决于树中的结构可达性。 

真正的困难在于，游戏不仅仅是关于排列或树，而是关于鲍勃是否可以强制禁止顶点阻止爱丽丝执行排序所需的一系列交换的能力。 

## 方法

 暴力模型将模拟所有游戏状态，跟踪排列、令牌位置以及轮到谁。 每个 Alice 在所有有效交换上移动分支，每个 Bob 在所有相邻移动上移动分支。 即使我们忽略排列复杂度并仅跟踪位置，分支因子仍然与顶点度数成正比，并且排列状态空间是阶乘的。 它立即在小树之外爆炸。 

转折点来自于重新解释爱丽丝的交换。 Alice 有效地对除当前令牌位置之外的所有顶点执行任意交换。 这意味着在任何时刻，她都可以自由地排列一个禁止顶点之外的多组值。 因此，唯一真正的限制是禁止顶点是否可以永久阻碍对完成排序所需的关键值位置交互的访问。 

可排序的排列仅取决于相对于其目标的位置周期。 每个循环都必须通过允许至少一次涉及其元素的交换来“打破”。 Bob 唯一的权力是通过保持所需的交互顶点被占用来确保某个循环始终被阻止解决。 

关键的观察是鲍勃的令牌的行为就像一个移动的禁止节点。 如果鲍勃可以将令牌保留在分隔树的区域内，并且总是阻止至少一个未解决的排列周期的进展，那么他可以强制进行无限游戏。 否则，Alice 最终可以围绕 Bob 的位置进行交换并完成排序。

这将问题简化为分析树中的距离以及如何“清除”排列循环，同时避免移动禁止顶点。 最终的表征简化为Alice能否保证在Bob无休止地阻碍进度之前完成，这取决于起始令牌的可达性结构和排列错位的分布。

 ## 算法演练

 核心思想是将排列转换为一组目标位置，并测量 Bob 通过移动禁止顶点可以延迟完成“多远”。 

我们将树的根设在令牌的起始顶点并计算距它的距离。 

1. 首先，检查排列是否已排序。 如果是，Alice 会立即获胜，因为在任何阻塞交互发生之前条件就已满足。 
2. 构建树并使用 BFS 计算距起始令牌顶点的距离。 这给出了鲍勃可以到达任何顶点的最早时间。 
3. 对于每个顶点 i，将其当前值 p[i] 与正确值 i 进行比较。 如果 p[i] = i，则它已经是正确的并且不会导致无序。 
4. 对于每个不匹配，将其解释为该值最终必须交换到位置 i 的要求。 只有当 Alice 可以在 i 不被禁止的某个时刻执行涉及 i 的交换时，才能满足此要求。 
5. 关键的减少是，如果存在一个始终可以足够快地到达以保持受令牌“保护”的不匹配顶点，Bob 可以永久阻止完成。 这相当于检查所有不匹配的顶点是否都位于 Bob 可以连续重新访问或捕获的区域内。 
6、判定条件为是否存在至少一个与起始令牌的距离超过由树径结构相对于游戏轮换确定的临界阈值的失配。 如果存在这样的顶点，Alice 最终可以隔离并修复它； 否则 Bob 可以无限期地循环并阻止解决。 

实际的实现简化为计算距离并检查所有放错位置的元素是否位于令牌周围的受限区域中。 

### 为什么它有效

 Alice 的力量来自于能够交换任意两个未阻塞的顶点，这有效地将排列结构折叠为全局灵活性减去一个禁止点。 Bob 的约束纯粹是位置性的，因此他的影响完全取决于他在排序过程中可以使关键顶点不可用的时间长度。 

不变的是，只要爱丽丝最终能够访问该循环的至少一个顶点而没有永久阻塞，则可以解决该排列的任何循环。 如果 Bob 可以无限期地阻止同时访问所有关键顶点，他就会强制执行无限循环。 否则，Alice 最终会打破每个循环并完成排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        x -= 1

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            g[a].append(b)
            g[b].append(a)

        p = list(map(int, input().split()))
        p = [v - 1 for v in p]

        # already sorted
        ok = True
        for i in range(n):
            if p[i] != i:
                ok = False
                break
        if ok:
            print("Alice")
            continue

        dist = [-1] * n
        dist[x] = 0
        q = deque([x])
        while q:
            v = q.popleft()
            for to in g[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    q.append(to)

        max_dist = 0
        for i in range(n):
            if p[i] != i:
                max_dist = max(max_dist, dist[i])

        # key condition: if all mismatches are too close to Bob, Bob can sustain obstruction
        # otherwise Alice can force resolution
        if max_dist <= 1:
            print("Bob")
        else:
            print("Alice")

if __name__ == "__main__":
    solve()
```BFS 计算距初始令牌位置的最短距离，这是对 Bob 影响力唯一重要的动态约束。 然后，我们识别排列不正确的所有位置，并跟踪距令牌最远的此类位置。 如果每个不匹配都与令牌位置直接相邻或相同，那么鲍勃可以不断地重新进入阻塞位置并阻止爱丽丝建立干净的交换序列。 否则，爱丽丝至少有一个足够远的不匹配，最终变得无法被鲍勃控制，从而使她能够完成排序过程。 

早期排序检查是必要的，因为如果排列开始排序，游戏定义允许 Alice 在任何交换之前获胜。

 ## 边缘情况

 当排列已经排序时，算法会在任何 BFS 或结构推理之前立即返回 Alice。 这符合爱丽丝可以在回合开始时宣布胜利的规则。 

当所有不匹配都与起始标记直接相邻时，这些顶点的 BFS 距离将全部为 0 或 1。 条件`max_dist <= 1`触发鲍勃的胜利，反映出鲍勃可以不断地重新定位禁止顶点以干扰每个必要的交换区域，而无需允许安全的全局校正步骤。 

当存在单个距离不匹配时，BFS 会确保至少有一个顶点具有较大的距离值。 这迫使爱丽丝获胜，因为鲍勃无法无限期地阻止树上所有所需交换参与者的访问。
