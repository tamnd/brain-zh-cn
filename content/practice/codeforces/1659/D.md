 ## 解决方案
 ## 问题理解

 我们从一个未知的二进制数组开始$A$。 对于每个前缀长度$k$，我们对第一个进行排序$k$的元素$A$，其余不变。 这会产生$n$数组$B_1, B_2, \dots, B_n$。 

我们不是直接看到这些数组，而是得到它们的按列总和$C$。 任务是重建任何二进制数组$A$可能会生成给定的$C$。 

关键的观察是我们没有被要求验证存在。 该语句保证至少存在一个有效的数组。 我们唯一的工作就是找回一个。 

数组长度可以达到$2 \cdot 10^5$跨所有测试用例。 任何明确构建所有的解决方案$B_k$数组需要$O(n^2)$工作量太大了。 我们需要一个在每个测试用例中以线性时间运行的重建过程。 

错误的常见来源是误解转换保留了哪些信息。 例如，其中的总数$A$没有丢失。 每个已排序的数组$B_k$包含的个数与$A$，因为排序不会改变元素计数。 自从$C$是所有的总和$B_k$，总和$C$等于$$n \cdot (\text{number of ones in } A).$$这个事实是重建的起点。 

当许多位置$C$are equal. 例如，```
n = 3
C = [0,0,0]
```正确答案是```
0 0 0
```只要有可能就贪婪地插入的重建过程将立即失败。 

一个不同的边缘情况是```
n = 4
C = [0,0,0,4]
```答案是```
0 0 0 1
```仅最后一个位置就携带了足够的信息来迫使最后一个位置。 

## 方法

 最直接的想法就是尝试每一个二进制数组$A$，生成所有排序前缀数组，计算$C$，并将其与输入进行比较。 

这是正确的，但速度慢得令人绝望。 有$2^n$候选数组。 即使是为了$n=40$，这已经超过万亿种可能性了。 

真正的突破来自于研究单个元素如何对最终数组做出贡献$C$。 

假设我们知道在从右到左重建答案时还需要放置多少个。 一个放置在位置$i$以非常有规律的方式影响一系列连续的早期位置。 我们可以用差异数组来表示这些效果，而不是直接模拟排序过程。 

这会将重建转换为贪婪的从右到左扫描。 在每个位置我们决定当前元素是否必须是$0$或者$1$，通过差异数组延迟应用该决策的贡献，然后继续。 

所得算法是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n^2)$|$O(n^2)$| 太慢了|
 | 最佳 |$O(n)$每个测试用例|$O(n)$| 已接受 |

 ## 算法演练

 ### 关键观察

 让$$k = \frac{\sum C_i}{n}.$$由于每个数组$B_j$包含的个数与$A$,$k$正是未知数组中 1 的数量。 

我们重建$A$从右到左。 

让`ones`表示还有多少个尚未修复。 

我们维护一个差异数组，用于存储先前选择的累积效果。 

### 重建规则

 在位置$i$，应用所有主动更新后，我们获得调整后的值$$v = C_i + \text{current\_effect}.$$然后：

 1.如果$v = \text{ones}$，当前位置必须是$0$。 
2. 否则当前位置必须是$1$。 

当我们放置一个时：

 1.我们设定$A_i = 1$。 
2.我们减少`ones`一个。 
3. 我们使用差异数组来延迟添加其贡献。 

### 为什么比较有效

 当从右向左扫描时，每个已经决定的位置都会为较早的位置贡献可预测的数量。 除去这些贡献后，该位置的剩余价值$i$如果原始位为零，则只能匹配当前未放置的数量。 

如果不匹配，则唯一有效的可能性是原始位为 1。 存在保证确保这个决定永远不会含糊。 

### 逐步算法

 1. 计算$$\text{ones} = \frac{\sum C_i}{n}.$$2. 创建差异数组`diff`。 
3. 从右向左扫描位置。 
4. 应用挂起的差异更新以获得当前累积的效果。 
5.让$$v = C_i + \text{current\_effect}.$$6. 如果`v == ones`， 放$A_i = 0$。 
7.否则设置$A_i = 1$， 减少`ones`，并在差异结构中记录这个新放置的贡献。 
8. 输出重建的二进制数组。 

### 为什么它有效

 该算法保持了以下不变性：已重建位置的所有贡献已从当前正在处理的后缀中删除。 

在位置$i$，调整后的值准确地代表了尚未解释的信息。 零使剩余 1 的当前计数保持不变，而 1 消耗剩余 1 的一个并创建已知的贡献区间。 因为保证输入有效，所以这些选择之一恰好与不变量一致。 

通过从右到左处理位置，每个贡献区间仅影响稍后将访问的位置，这允许差异数组在恒定时间内处理所有更新。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        c = list(map(int, input().split()))

        ones = sum(c) // n

        diff = [0] * (n + 1)
        cur = 0
        ans = [0] * n

        for i in range(n - 1, -1, -1):
            cur += diff[i]

            val = c[i] + cur

            if val == ones:
                ans[i] = 0
            else:
                ans[i] = 1

                ones -= 1

                cur -= 1

                pos = i - ones
                if pos >= 0:
                    diff[pos] += 1

        print(*ans)

solve()
```第一步计算 1 的总数。 这直接源于每个排序前缀数组都会保留 1 的数量这一事实。 

变量`cur`存储当前位置的总活跃贡献。 我们不是单独更新每个受影响的索引，而是使用差异数组并在向左移动时累积其值。 

当放置一个 1 时，它的贡献会扩展到一个连续的范围。 更新内容```
cur -= 1
```立即激活该贡献，同时```
diff[pos] += 1
```安排贡献停止影响未来职位的时刻。 

实现中最微妙的部分是```
pos = i - ones
```必须在递减后计算`ones`。 颠倒该顺序会将每个间隔移动一个位置并破坏重建。

 ## 边缘情况

 考虑```
n = 1
C = [0]
```1 的总数为零。 扫描立即发现调整后的值等于剩余的个数，所以答案是`[0]`。 

考虑```
n = 1
C = [1]
```现在总数是1。 调整后的值与剩余计数不同，迫使唯一位置变为 1。 

考虑```
n = 4
C = [0,0,0,4]
```计算出的个数是 1。 最右边的位置被迫为一。 它的贡献通过差异数组传播，并且所有较早的位置变为零。 这捕获了间隔更新逻辑中最常见的差一错误。 

考虑```
n = 3
C = [0,0,0]
```没有任何更新被激活。 差异数组在整个扫描过程中保持为空，从而确认该实现在没有任何特殊情况的情况下处理了数组的缺失。
