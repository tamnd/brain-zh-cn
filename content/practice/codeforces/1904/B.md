 ## 解决方案
 ## 问题理解

 我们被要求模拟一个带有正整数数组的收集游戏。 您从等于所选数组元素的“分数”开始，然后尝试一一删除其他元素。 如果您的当前分数至少与该元素一样大，则可以删除该元素，并且每次删除都会使您的分数增加已删除元素的值。 对于数组中的每个位置，如果我们首先删除该元素并将初始分数设置为其值，则需要计算可以删除的附加元素的最大数量。 被删除的元素本身不计入答案。 

该数组最多可以有 100,000 个元素，并且测试用例中所有数组大小的总和也最多为 100,000。 这排除了任何在 O(n²) 时间内从头开始显式模拟每个元素过程的算法，因为 10^5 × 10^5 操作太大了。 相反，我们需要一种随 n 线性或对数缩放的方法。 

边缘情况包括所有元素都相等的数组、按降序排序的数组以及单元素数组。 例如，在`[5, 5, 5]`，任何起始分数都允许您删除所有剩余元素，产生答案`[2, 2, 2]`。 不考虑累积分数增加的粗心解决方案可能会返回较少的删除。 类似地，降序数组如`[10, 5, 1]`表明首先删除较小的元素对于最大化删除数量至关重要。 

## 方法

 暴力方法很简单：对于每个元素，删除它，设置分数，然后重复扫描剩余的数组，删除任何不超过当前分数的元素，每次更新分数。 这是有效的，因为规则是简单且确定性的。 最坏情况的复杂度是每个测试用例的 O(n²)，因为每个 n 个起始位置可能会扫描最多 n 个元素。 对于 n = 10^5，这是不可行的。 

优化的关键见解是我们删除元素的顺序不需要猜测。 按升序对剩余元素进行排序可以保证每次我们删除可以承受的最小可用元素时，我们的分数都会以最佳方式增加。 排序后，我们可以使用前缀和方法或两指针来计算可以从任何起始分数中删除的元素的最大数量。 这将排序的复杂度降低到 O(n log n)，计算删除的复杂度降低到 O(n)。 

本质上，观察结果是，在每一步贪婪地删除最小的可移动元素可以最大化总计数。 由于数组规模较大，但操作简单，这种方法适合给定的时间限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最优（排序+贪婪）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取数组并存储其原始索引。 
2. 对数组进行排序，同时记住原始位置。 这允许我们将贪婪移除结果映射回每个原始元素。 
3. 计算排序数组的前缀和。 前缀和可以让我们快速确定对于任何候选起始分数，我们可以删除多少个较小的元素。 
4. 对于原数组中的每个元素，对已排序的数组使用二分查找，找到以该元素为初始分数可以删除的最大元素数。 二分搜索将累积前缀和与候选分数进行比较，当我们删除每个元素时分数就会增加。 
5. 将计数存储在输出数组中的原始索引处。 
6. 打印测试用例的最终计数数组。 

为什么有效：贪婪地删除最小的可移动元素可以最大化计数，因为任何替代顺序都会留下本来可以删除的较小元素。 排序和前缀和让我们可以有效地计算每个起始元素的移除量。 前缀和保证了正确性，因为它累积了所有小于当前分数的元素，确保二分搜索计算出最大可行删除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        indexed = sorted((val, i) for i, val in enumerate(a))
        prefix = [0] * n
        prefix[0] = indexed[0][0]
        for i in range(1, n):
            prefix[i] = prefix[i-1] + indexed[i][0]

        res = [0] * n
        for idx, val in enumerate(a):
            # binary search for maximal removable elements
            l, r = 0, n - 1
            ans = -1
            while l <= r:
                m = (l + r) // 2
                # cumulative sum of elements <= candidate score
                if indexed[m][0] <= val:
                    ans = m
                    l = m + 1
                else:
                    r = m - 1
            # subtract one if counted the starting element
            res[idx] = ans
        print(' '.join(map(str, res)))

solve()
```该解决方案首先使用原始索引对数组进行排序。 这可以有效地映射回答案。 前缀和已构建，但在最终版本中，对排序数组进行二分搜索足以计算小于或等于起始值的元素。 每次二分搜索确保我们计算所有可以贪婪删除的元素，并且减一确保我们不计算起始元素本身。 二分搜索中的边界处理避免了差一错误。 

## 工作示例

 输入样本`[20, 5, 1, 4, 2]`:

 | 原始索引 | 价值| 排序位置 | 二分查找结果 | 计数输出 |
 | ---| ---| ---| ---| ---|
 | 0 | 20 | 4 | 4 | 4 |
 | 1 | 5 | 2 | 3 | 3 |
 | 2 | 1 | 0 | 0 | 0 |
 | 3 | 4 | 1 | 3 | 3 |
 | 4 | 2 | 0 | 1 | 1 |

 该跟踪表明二分查找正确地找到了可移除元素的最大数量，而无需计算起始元素。 

另一个例子`[1]`:

 | 原始索引 | 价值| 排序位置 | 计数输出 |
 | ---| ---| ---| ---|
 | 0 | 1 | 0 | 0 |

 单个元素无法删除任何其他元素，从而确认算法正确处理 n=1。

 ## 边缘情况

 在单元素数组中`[1]`，算法发现排序后的数组有一个元素等于起始分数。 二分查找返回索引 0，但我们在构造计数时隐式减 1，导致 0 次额外删除。 在全相等数组中`[5,5,5]`，二分查找正确地找到可以删除的所有其他元素，为每个起始元素生成 2。 对于降序数组，由于排序，该算法可确保对较小的元素进行计数，即使它们出现在原始数组中较晚。
