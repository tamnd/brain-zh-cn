 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组。 我们重复执行一个操作，选择两个现有位置并将这两个值的绝对差附加到数组的末尾。 原始元素永远不会被删除，因此数组只会增长，并且新值完全由先前存在的值的差异决定。 

完全这样做之后$k$有时，我们会被要求提供数组中可能存在的最小值，假设我们每次都选择最佳的对。 

关键的难点在于$k$可以非常大，最多$10^9$，所以我们无法模拟操作。 然而，数组大小$n$足够小，我们可以最初检查所有对，因为总数$\sum n^2$的边界是$4 \cdot 10^6$。 

一个微妙但重要的观察是，当我们引入差异时，值只会减少，并且每个新值仅取决于已经存在的数字。 这意味着多次操作后的最小值不是关于复杂状态空间中的序列演化，而是关于通过重复差异可以生成什么数字。 

一个天真的误解是认为我们必须模拟$k$贪婪地迈出脚步。 当$k$很大，因为许多操作在某个点之后可能不会改变最小值。 另一种失效模式是假设最小值只能减少一到两次； 实际上，重复的差异最终可以稳定在固定的最小可实现值。 

## 方法

 如果我们强力执行该过程，我们会重复尝试所有对$(i, j)$, 计算$|a_i - a_j|$，追加它，并更新数组。 每次操作费用$O(n)$或更多，如果我们保持配对，并且这样做$k$当$k$很大。 即使我们优化对选择，生成的元素数量也会爆炸，我们被迫$O(k n)$行为。 

关键的结构见解是，该操作只会产生与现有数字有差异的数字，一旦我们有足够的差异，系统就会基本上稳定。 特别是，我们能达到的最小值是由差异的最大公约数结构决定的。 每个新数字都位于由成对差异生成的加法群中，并且重复的差异最终会向所有成对差异的最大公约数崩溃。 

然而，我们还有第二个约束：我们只执行$k$运营。 如果$k$很小，我们可能还没有达到稳定的结构，并且答案可能大于最终极限。 所以我们一定要区分小$k$行为和大$k$饱和。 

关键的观察是，在最多几次操作内，我们已经可以在任何两个元素之间生成最小可能的差异，并且一旦存在最小正差异，当且仅当该差异可以与自身相互作用时，进一步的操作才能产生零。 否则，最佳可实现的最小值稳定在最小成对差异处，并且重复操作不会进一步改善它。 

这将问题简化为计算最多之后出现的最小可能值$k$差异生成步骤，完全由初始成对差异以及是否可以达到零来控制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(k n^2)$|$O(n)$| 太慢了 |
 | 差异收敛分析|$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 计算最小元素$m$数组中的和最小的差异$d = \min |a_i - a_j|$超过所有对。 最小元素已经为答案设置了硬下限。 
2.如果$d = 0$，则存在两个相等的元素。 一个操作可以立即追加零，并且所有后续操作都可以通过再次选择相等的元素来继续追加零。 所以如果$k \ge 1$，答案变成零。 
3.如果$k = 0$，不执行任何操作，答案只是初始最小元素。 
4. 如果$k \ge 1$，我们总是可以执行至少一项操作。 第一个生成的值至少为$d$，并且任何操作序列都不能产生小于$d$，因为每个操作都是现有值的差异，并且不能引入低于最小现有差距的任何内容。 
5. 因此，如果不存在相等的对，则保留最小值$\min(m, d)$。 自从$d$总是至少$0$，并且已经处理了零情况，答案是$\min(m, d)$，这简化为$d$如果我们考虑到$d \le m$仅当存在相同或更接近的值时，否则$m$持续存在。 

### 为什么它有效

 每个新创建的值都是原始值的整数线性组合，其系数的绝对值总和为零。 这意味着可达到的值集在减法下是封闭的，并且可实现的最小正值是所有成对差值的最大公约数。 一旦产生最小的差异，最小值立即稳定下来，并且进一步的操作不能绕过这个界限。 唯一的例外是存在零差异时，在这种情况下，零将永久可达。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        m = min(a)
        
        if k == 0:
            print(m)
            continue
        
        # compute minimum pairwise difference
        d = 10**30
        a.sort()
        for i in range(n):
            for j in range(i + 1, n):
                d = min(d, a[j] - a[i])
                if d == 0:
                    break
            if d == 0:
                break
        
        if d == 0:
            print(0)
        else:
            print(min(m, d))

if __name__ == "__main__":
    solve()
```实施分离案例$k = 0$，其中不允许更改。 为了$k \ge 1$，它计算初始最小值和最小成对差值。 排序确保差异被计算为非负间隙，并且提前停止于零可以避免不必要的工作。 

最终的决策直接比较初始最小值和最小可实现生成值。 其背后的原因是，所有新值都是由成对差异构建的，因此除了这组间隙之外不会出现任何内容。 

## 工作示例

 ### 示例 1

 输入：```
n = 5, k = 2
a = [3, 9, 7, 15, 1]
```我们计算最小元素和成对差异。 

| 步骤| 行动| 最低可见 | 最小差异|
 | ---| ---| ---| ---|
 | 1 | 初始数组 | 1 | 信息 |
 | 2 | 扫描对 | 1 | 2（来自 3 和 1）|
 | 3 | 继续扫描 | 1 | 1（来自差异后的 2 个元素）|

 最小元素已经是 1，任何操作都不能产生更小的元素。 尽管我们可以生成更小的中间差异，但没有一个会低于 1。最终答案是 1。 

### 示例 2

 输入：```
n = 4, k = 3
a = [7, 4, 15, 12]
```| 步骤| 行动| 最低可见 | 最小差异|
 | ---| ---| ---| ---|
 | 1 | 初始数组 | 4 | 信息 |
 | 2 | 计算配对差异 | 4 | 3 |
 | 3 | 检测可实现的零 | 4 | 链接后 3 → 0 |
 | 4 | 使用 k 操作 | 4 | 0 |

 在这里，我们观察到重复的差异最终会产生零，因为差异在各对之间一致重复。 一旦可以实现零，最小值就变为 0。 

这证明了饱和效应：一旦系统可以生成自取消对，所有进一步的操作都会崩溃最小值。

 ## 边缘情况

 当所有元素相等时，每个成对差值为零。 该算法在扫描期间立即检测到这一点，因此第一个操作已经产生零。 即使$k$很大时，答案仍为零，因为零总是可以再次生成。 

什么时候$k = 0$，根本没有差异。 数组永远不会改变，因此答案严格是初始最小值，任何计算差异的尝试都是无关紧要的。 

当数组只有两个元素时，唯一可能生成的值是它们的差异。 如果它们相等，则可以达到零； 否则，过程将在该差异处稳定，因为无法形成更小的值。
