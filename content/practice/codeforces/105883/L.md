 ## 解决方案
 ## 问题理解

 我们得到了一个整数数组，并且我们需要反复回答对子段的查询。 对于任何选定的子数组，我们可以将其元素分为两组。 一组贡献其元素的按位或，另一组贡献其元素的按位与。 分割的分数是这两个结果的总和，我们想要最好的分割。 

查询给出数组的一部分，我们必须计算所有可能的方法的最大可实现分数，以将每个元素分配到“或”侧或“与”侧。 

关键的困难在于每个元素以非线性方式影响 OR 和 AND，并且每个查询都在任意范围内，最多可达一百万个查询。 这会立即排除该段上的任何每次查询线性甚至对数重新计算，因为最坏情况的工作将达到大约 10^11 次操作。 

这些约束强烈表明每个元素必须对某种预先计算的结构做出贡献，并且每个查询必须在对数或恒定时间内得到回答。 

一些边缘行为很容易被低估。 

如果所有元素都为零，则任何分区都会产生零分，因为无论分组如何，OR 和 AND 都为零。 

如果该段只有一个元素 x，则答案是 max(x, x)，因为任何一方都可以获取它。 所以答案就是x。 

如果所有元素都等于 x > 0，则将所有元素放入 S1 中给出 OR = x，AND = 0，得分 x。 将所有内容放入 S2 中，OR = 0，AND = x，得分 x。 任何混合分区都不会超过 x，因为 OR 和 AND 不能同时超过 x。 所以答案总是x。 

这些案例表明答案的结构与全局位行为紧密相关，而不是与组合分区相关。 

## 方法

 暴力解决方案考虑子数组的每个可能的分区。 对于长度为 m 的段，有 2^m 次分配。 对于每个分配，我们计算一个子集的 OR 和另一个子集的 AND。 如果简单地计算每个分数需要 O(m) 时间，因此单个查询变为 O(m 2^m)，这对于 m 超过 20 时已经不可行。 

即使我们使用预先计算的掩码将每个分区的评估提高到 O(1)，分区的指数数量仍然是瓶颈。 

关键的观察是目标函数按位分解。 每个位位置的行为都是独立的，因为 OR 和 AND 按位运算，不同位位置之间没有交互。 这表明我们可以单独考虑每一位，然后将贡献相加。 

稍微修正一下 B. 每个元素要么设置该位，要么不设置。 如果我们将一个设置为 b 位的元素放入 S1，它将为 OR 端贡献 2^b。 如果我们将其放入 S2 中，则仅当 S2 中的所有元素都设置了位 b 时，它才会对 AND 起作用，否则 AND 会完全丢失该位。 

这产生了尖锐的结构约束：对于给定的位，S2 要么只包含全部共享该位的元素，要么该位对 AND 没有任何贡献。 

这将问题简化为推理段中包含多少个元素以及如何对它们进行分组。 

最终的简化来自于认识到对于每个位，最佳策略是局部的：要么我们将具有该位的所有元素放入 S1 中以最大化 OR 贡献，要么我们尝试通过将仔细选择的子集放入 S2 中来保留 AND 贡献，这仅当该子集包含段中携带该位的所有元素时才有用。 

由此得出的结论是，最佳值仅取决于段上每个比特的频率模式，并且可以使用每个比特的前缀计数来预先计算。 

因此，我们预处理位计数并通过在 O(30) 时间内评估每位的最佳配置来回答每个查询。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次查询 O(m·2^m) | O(1) | O(1) | 太慢了|
 | 位分解+前缀计数| 每次查询 O(30 · 1) | O(30n) | O(30n) | 已接受 |

 ## 算法演练

 1. 预先计算数组中从 0 到 29 的每个位位置的前缀和。 这使我们能够快速了解​​任何段中有多少元素具有给定的位集。 
2. 对于每个查询段 [l, r]，计算段中包含每个位 b 的元素数量。 令此计数为 cnt[b]。 
3.对于每一位b，计算两个候选贡献。 首先，如果我们将所有具有位 b 的元素分配给 S1，那么如果 cnt[b] > 0，则 OR 会获得 2^b。其次，如果我们尝试保留 AND，则位 b 在 AND 中生存的唯一方法是 S2 中的每个元素都设置了位 b，这迫使 S2 恰好是段中所有设置了位 b 的元素的子集。 仅当我们将至少一个这样的元素放入 S2 并确保一致性时，这才会贡献 2^b。 
4. 观察到跨位的混合策略是独立的，因此对于每个位，我们只需决定其贡献是通过 OR 还是通过潜在的 AND 保留来获取。 
5. 最终答案是通过对所有位的贡献求和来获得的，其中如果 cnt[b] > 0，则每个位贡献 2^b，并且不会因分区而受到进一步的惩罚，因为通过放置至少一个适当地携带它的元素，可以最佳地实现每一位。 

### 为什么它有效

 每个位位置都是独立的，因为 OR 和 AND 不会混合位。 对于固定位，任何将其保留在 AND 一侧的尝试都会严重限制 S2，而 OR 总是通过在 S1 中包含至少一个携带该位的元素来最大化。 由于我们可以自由选择每个元素的分区，因此我们始终可以通过适当地分配元素来同时满足每个位的最佳条件。 这将问题分解为 30 个独立的二元决策，每一位一个，其贡献只是相加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

B = 30

pref = [[0] * (n + 1) for _ in range(B)]

for i in range(n):
    x = a[i]
    for b in range(B):
        pref[b][i + 1] = pref[b][i] + ((x >> b) & 1)

out = []

for _ in range(q):
    l, r = map(int, input().split())
    res = 0
    for b in range(B):
        if pref[b][r] - pref[b][l - 1] > 0:
            res += (1 << b)
    out.append(str(res))

print("\n".join(out))
```预处理步骤构建一个二进制前缀表，其中每行对应一个位位置，每列跟踪该位在该索引中出现的次数。 这允许对任何查询段中包含给定位的元素数量进行恒定时间计数。 

每个查询只需扫描所有 30 位，并添加该位值（如果该位值在范围内至少出现一次）。 其逻辑是，由于可分离性，任何存在的比特都可以在最佳分区中实现，而不会受到其他比特的干扰。 

一个微妙的点是我们从来没有显式地构造分区。 正确性来自这样一个事实：评分函数仅取决于段中是否存在位，而不取决于它们的排列。 

## 工作示例

 考虑数组`[5, 4, 2]`并查询`[1, 3]`。 

| 位| 在范围内计数 | 贡献 |

 | 0 | 1 | 1 |
 | 1 | 1 | 2 |
 | 2 | 2 | 4 |

 答案是7。 

这表明多个元素之间的重叠位不会干扰贡献； 每个位都独立贡献。 

现在考虑`[1, 1, 1]`带查询`[1, 3]`。 

| 位| 计数 | 贡献 |
 | --- | --- | --- |
 | 0 | 3 | 1 |

 答案是 1，证实重复不会放大价值。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    B = 30
    pref = [[0] * (n + 1) for _ in range(B)]

    for i in range(n):
        x = a[i]
        for b in range(B):
            pref[b][i + 1] = pref[b][i] + ((x >> b) & 1)

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        res = 0
        for b in range(B):
            if pref[b][r] - pref[b][l - 1]:
                res += (1 << b)
        out.append(str(res))

    return "\n".join(out)

# minimal
assert run("1 1\n5\n1 1\n") == "5"

# all equal
assert run("3 1\n7 7 7\n1 3\n") == "7"

# mixed bits
assert run("3 2\n5 4 2\n1 3\n2 3\n") == "7\n6"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 | 单元素| 5 | 基本情况正确性 |
 | 所有相同的值 | 7 | 重复项下的稳定性 |
 | 混合位| 7 / 6 | 正确的前缀聚合 |

 ## 边缘情况

 对于单个元素数组`[x]`，对于 x 中设置的所有位，前缀逻辑产生 cnt[b] = 1，并且答案变为 x。 该算法自然会返回正确的结果，因为每个位都只计算一次。 

对于所有元素都相同的段，值中存在的每个位都会出现在所有位置。 前缀差异正确报告非零计数，求和重建相同的数字而不膨胀，匹配正确的分区行为。 

对于具有不相交位模式的段，例如`[1, 2, 4]`，每个位在该段中恰好出现一次。 该算法将所有贡献相加，产生 7，这对应于可实现的最佳分割，其中放置每个元素以保留其独特的位贡献。
