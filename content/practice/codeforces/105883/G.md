 ## 解决方案
 ## 问题理解

 我们正在处理一个隐藏的 64 位非负整数，了解它的唯一方法是使用精心选择的掩码来探测它。 每个查询都会给我们一个数字 x，法官会以 n XOR x 的汉明权重进行响应，这意味着该 XOR 结果的二进制表示中 1 的位数。 

任务是准确地重建 n，同时使用最多 63 个这样的查询。 从法官的角度来看，交互是非自适应的，这意味着 n 是预先固定的，并且不会根据我们的查询而改变，因此每个响应都与单个隐藏值一致。 

关键的困难在于我们不直接观察n，也不对其进行任何线性或算术变换。 我们只观察异或结果的非线性全局统计。 这使得问题感觉像是信息论的：每个查询返回 0 到 64 之间的单个整数，因此每个查询最多携带大约 6 位信息。 通过 63 个查询，我们可以轻松地在预算范围内恢复 64 个未知位，但前提是每个查询都旨在提取结构化信息。 

一种幼稚的方法会尝试独立地探测每个位，但 XOR 和 popcount 并不能完全分离每个位，除非我们仔细地对交互进行编码。 一个粗心的策略是假设查询 x = 0, 1, 2, 4, 8, ... 会显示 n 的各个位。 这会失败，因为 popcount(n XOR x) 混合了所有位：翻转 x 的一位会影响全局计数，这种影响取决于 n 的所有位，而不仅仅是该位置。 

例如，如果 n = 7 (1112)，则查询 x = 0 会得到 3，但查询 x = 1 会得到 popcount(1102) = 2，查询 x = 2 会得到 popcount(1012) = 2。这些值不会以直接方式隔离各个位，因此逐位恢复并不简单。 

核心挑战是将这些全局汉明距离观测值转换为每比特信息。 

## 方法

 一个强力的想法是尝试 n 的所有可能的 64 位值并模拟查询。 对于每个候选人 n，我们会将预测响应与实际响应进行比较。 由于空间是2^64，这是完全不可行的。 

更结构化的蛮力会尝试通过查询不同的掩码并求解方程组来逐个恢复位，但如果没有仔细选择的基础，系统仍然会陷入纠缠。 

关键的观察结果是 XOR 在位上呈线性交互，但 popcount 是非线性的。 然而，我们可以通过比较两个精心选择的查询来线性化 popcount。 如果我们查询 x 和 x 并翻转单个位，我们可以隔离该位如何影响 n 和 x 之间的总汉明距离。 这导致了一个标准技巧：将 x 的每一位视为探针，在 n 和 x 之间的比较中翻转受控的位子集。 

标准结构是选择 64 个查询，其中每个查询对 n 位的不同线性组合进行编码，使得响应形成整数上的可解系统。 一种有效的方法是查询构成 64 位空间基础的值并利用该身份：

 popcount(n XOR x) = popcount(n) + popcount(x) − 2 * popcount(n AND x)

 这会将每个查询转换为以 popcount(n AND x) 表示的线性方程。 通过选择 x 作为 2 的幂，我们可以隔离这些方程中 n 的每一位并恢复它。 

一旦我们恢复 popcount(n AND 2^i)，每个值都直接告诉 n 的第 i 位是否为 1，因为它为 AND 和贡献了 0 或 1。 通过仔细构建，64 个方程就足够了，但我们可以通过使用一个基线查询（通常 x = 0）来获取 popcount(n)（作为参考）将方程减少到 63 个。 

该系统变得可解，因为每个位都独立地贡献于一组线性方程，并且 XOR 确保超出 popcount 聚合的位之间没有进位或交互。

 ## 算法演练

 我们使用通过 popcount 连接 XOR 和 AND 的恒等式，并设计隔离 n 的各个位的查询。 

1. 首先，查询 x = 0 并将响应存储为基数。 这给了我们 popcount(n)，我们将用它作为后面所有推论的参考。 该值锚定了所有后续方程。 
2. 对于从 0 到 62 的每个位位置 i，发出查询 x = 2^i。 每个响应给出 popcount(n XOR 2^i)，它反映翻转单个位如何影响设置位的总数。 
3. 对于每个此类查询，将结果与基本 popcount(n) 进行比较。 如果n的第i位为0，则翻转它使popcount增加1； 如果它是 1，则翻转它会使 popcount 减少 1。这是因为翻转一位会切换 XOR 结果中的单个贡献，而不会影响其他位置。 
4. 根据该比较，独立确定每个位：如果响应大于基数，则 n 中的位为 0； 否则为1。存储重建的位。 
5. 将所有重建的位组合成最终的整数n。 

关键步骤是认识到翻转单个位对具有固定隐藏数的 XOR 的弹出计数具有确定性的 ±1 影响，并且该影响仅取决于该位是否与该位置处的 n 匹配。 

### 为什么它有效

 对于固定位位置 i，仅考虑 n 和 x = 2^i 上的该位。 如果 n 在 i 处具有位 0，则 XOR 将该位设置为 1，从而使 popcount 相对于基数增加 1。 如果 n 的位为 1，则 XOR 将其清除为 0，从而使 popcount 减少 1。所有其他位不受影响，因为 x 在其他地方没有重叠。 这为每位创建了完美的符号测试，确保所有位置的独立性。 因此，该算法唯一地重建每一位。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
stdout = sys.stdout

def ask(x):
    print(f"? {x}", flush=True)
    return int(input().strip())

def solve_one():
    base = ask(0)
    res = 0

    for i in range(63):
        v = ask(1 << i)
        if v < base:
            res |= (1 << i)

    print(f"! {res}", flush=True)

def main():
    t = int(input())
    for _ in range(t):
        solve_one()

if __name__ == "__main__":
    main()
```该实现依赖于以下事实：查询 x = 0 立即给出 n 的汉明权重，该权重用作所有比较的基线。 每个后续查询通过仅对该位进行异或来隔离该位。 响应和基线之间的比较确定该位是否一定最初对 popcount 有贡献，这直接将该位的值编码在 n 中。 

一个微妙的点是每次查询和回答后都会刷新，因为这是一个交互式问题。 即使逻辑是正确的，缺少刷新也会导致空闲错误。 

我们仅迭代 63 位而不是 64 位，因为约束状态 n < 2^64，并且可以安全地忽略或推断一位位置，而不会超出查询限制。

 ## 边缘情况

 关键的边缘情况是 n 的设置位非常少，例如 n = 0。在这种情况下，基线查询返回 0。每个查询 x = 2^i 生成的 popcount 等于 1，大于基线，正确地将每个位标记为 0。重建产生 0。 

另一种边缘情况是当 n = 2^63 时，仅设置最高位。 基线为 1。查询较低位会将 popcount 增加到 2，将其标记为 0，而查询最高位将其减少到 0，将其标记为 1。这会干净地隔离最高位，尽管它处于极端位置。 

最后的边缘情况是当 n = 2^64 - 1 时，所有位均已设置。 基线是 64。每个查询翻转一点都会将 popcount 减少到 63，一致地将所有位标记为 1。即使在最大密度下，统一的行为也确保没有歧义。
