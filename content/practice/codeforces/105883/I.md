 ## 解决方案
 ## 问题理解

 我们得到了平面上不同格点的集合。 从这些点来看，如果这四个点可以作为任意方向（不一定是轴对齐）的正方形的顶点，则这四个点的任何子集都被认为是“好的”。 

任务不是直接计算给定集合中存在多少个这样的正方形。 相反，我们被迫首先删除一个点，然后计算幸存点中剩余多少个有效的方顶点四元组。 目标是选择删除的点，以便最终计数尽可能大。 

这里的核心对象是纯粹由距离约束定义的几何结构：如果所有边都相等、对角线相等并且对角线比边长 √2 倍，则一组四个点形成一个正方形。 同样，对于任何可以充当相邻顶点的有序点对，其余两个顶点由 90 度旋转唯一确定。 

约束 n ≤ 5000，测试用例的总和也≤ 5000 表明每个测试用例的 O(n² log n) 或 O(n²) 方法是可以接受的，但任何立方或更差的方法都将无法生存。 所有四元组的简单枚举已经达到 n⁴ 的量级，即使对于单个测试来说，这也是完全不可行的。 

一个微妙的边缘情况来自对称性：单个正方形由多对点确定。 每个方块都有四种方法来选择有序边缘，因此，除非仔细进行重复数据删除，否则简单的计数方法通常会过度计数。 

另一个边缘情况是删除后过滤的简并性。 一个点可能属于多个方格，移除它可能会同时破坏其中的许多方格，因此效果是高度非局部的。 例如，如果许多正方形共享一个公共中心或顶点簇，则删除该共享点可以大大减少计数，即使它参与许多结构也是如此。 

## 方法

 蛮力的想法很简单：枚举所有四元组点，使用成对距离测试它们是否形成正方形，然后模拟删除每个点并重新计算总数。 这立即给出了正确的解决方案，因为它直接检查正方形的定义并准确地评估目标。 

然而，成本却令人望而却步。 有 O(n⁴) 个四元组，对于每个测试用例，我们将重新计算每个可能删除的点的计数，乘以另一个 n 因子。 即使经过仔细的修剪，当 n 达到 5000 时，它也会远远超出任何可行的界限。 

关键的结构观察是正方形可以由成对的点而不是四元组生成。 如果我们将两个点 A 和 B 作为正方形的连续顶点，那么另外两个顶点可以通过围绕 A 和 B 旋转向量 AB ±90 度来唯一确定。这将问题转化为对点对的推理并导出几何补全。 

我们不是直接枚举正方形，而是枚举候选边。 对于每一对 (A, B)，我们计算使用 AB 作为边的两个可能的正方形。 每个这样的候选方格可以通过检查集合中是否存在其他两个计算点来验证。 这将平方枚举减少为 O(n²) 条候选边，每个边通过哈希进行 O(1) 次检查。 

一旦我们可以有效地枚举所有方格，我们就可以计算每个点参与了多少个方格。删除一个点然后精确地减去它所属的方格数。 因此，最优选择是参与方格最多的点。 

这将整个问题简化为计算平方和累积每个顶点的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n⁵) | O(n) | 太慢了|
 | 基于边缘的枚举 | O(n²) | O(n²) | 已接受 |

 ## 算法演练

我们将任务重新表述为计算，对于每个点，有多少个正方形将其作为其四个顶点之一。 

1. 将所有点存储在哈希集中，以进行 O(1) 存在性检查。 这是必要的，因为当我们生成潜在正方形的剩余两个顶点时，我们必须有效地验证它们的存在。 
2. 迭代所有有序对的不同点 A 和 B。将 A 和 B 视为正方形的连续顶点。 
3. 对于每对 (A, B)，计算向量 AB = (dx, dy)。 通过在两个方向上将该向量旋转 90 度可以形成一个正方形。 旋转向量为 (-dy, dx) 和 (dy, -dx)。 这些对应于正方形的两个可能的方向。 
4. 对于每个旋转方向，计算两个缺失的顶点 C 和 D：

 C = A + 旋转向量

 D = B + 旋转向量

 这个想法是，将 AB 的两个端点移动相同的垂直向量即可完成平行四边形，当旋转正确时，该平行四边形保证是正方形。 
5. 检查C和D是否都存在于点集中。 如果他们这样做了，我们就找到了一个有效的方块。 
6. 每个有效方格由于同一方格的不同有向边缘而被多次检测。 为了避免过度计数，我们在存储或更新计数之前使用四个顶点的规范排序来标准化表示。 
7. 为每个点维护一个计数器，指示有多少个不同的方块包含该点。 每次确认一个新方块时，都会增加所有四个顶点计数器。 
8. 处理完所有对后，答案是方格总数减去每点的最大贡献。 这相当于删除破坏最多方块的点。 

为什么它有效：

 每个正方形都有四个边，每条边都可以通过其两个方向之一生成正方形。 这保证了所有方格的完全覆盖。 由于我们在对每个发现的方格进行计数之前对其进行归一化，因此每个方格只被计数一次。 然后，每个顶点的累积精确地跟踪平方入射。 删除一个点会精确消除计入其发生值的那些方格，因此最大化最终计数会减少到最小化被破坏的方格，这相当于最大化参与度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = []
    s = set()

    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))
        s.add((x, y))

    cnt = [0] * n
    idx = {pts[i]: i for i in range(n)}

    seen = set()
    total = 0

    for i in range(n):
        x1, y1 = pts[i]
        for j in range(n):
            if i == j:
                continue
            x2, y2 = pts[j]

            dx = x2 - x1
            dy = y2 - y1

            # rotate 90 degrees: (-dy, dx)
            for rx, ry in [(-dy, dx), (dy, -dx)]:
                c = (x1 + rx, y1 + ry)
                d = (x2 + rx, y2 + ry)

                if c in s and d in s:
                    quad = tuple(sorted([pts[i], pts[j], c, d]))
                    if quad not in seen:
                        seen.add(quad)
                        total += 1
                        cnt[i] += 1
                        cnt[j] += 1
                        cnt[idx[c]] += 1
                        cnt[idx[d]] += 1

    print(total - max(cnt))

t = int(input())
for _ in range(t):
    solve()
```该解决方案首先构建所有点的哈希集，以便验证计算的顶点是否存在是恒定时间。 它还构建一个索引图，将坐标转换回数组位置，以进行每点计数。 

i 和 j 上的嵌套循环枚举所有有向段。 对于每个段，测试两个垂直方向。 每个方向都会产生一个正方形的候选完成。 存在性检查确保几何有效性。 

这`seen`设置至关重要，因为每个方块都会通过不同的边缘和方向被多次检测到。 对四个顶点进行排序提供了规范表示，因此重复项可以正确折叠。 

最后，我们计算每个点参与了多少个方格，并减去该值的最大值，这对应于删除消除最多方格的点。 

一个微妙的实现细节是，边的两个端点都贡献于同一个正方形，因此每个正方形的所有四个顶点的计数必须对称更新一次。 如果没有规范的重复数据删除，过度计数会破坏总统计数据和每个顶点的统计数据。

 ## 边缘情况

 一个退化但重要的情况是许多候选边多次生成相同的正方形。 该算法通过在插入之前对顶点进行规范排序来处理这个问题`seen`放。 对于顶点为 (0,0)、(1,0)、(1,1)、(0,1) 的正方形，所有四个边最终都会生成它，但只计算第一个遇到的排序。 

另一种情况是多个正方形共享一个顶点。 每个方块都独立地对该顶点的计数器做出贡献，并且移除会立即正确地减去所有方块。 例如，如果一个点是 k 个不同正方形的一部分，则删除它会使总数恰好减少 k，因为每个正方形仅计算一次，并且在其四个增量中包含该顶点。
