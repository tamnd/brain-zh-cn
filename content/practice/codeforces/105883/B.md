 ## 解决方案
 ## 问题理解

 我们给定一个非常大的整数$N$以十进制形式和一个数字书写$x$1 到 9 之间。任务是检查每个正整数$M$从 1 到$N$, 数一下这个数字有多少次$x$出现在每个内部$M$，并按该计数对数字进行分组。 

更准确地说，对于每个$k$从 0 到 的位数$N$，我们需要计算有多少个整数$M \le N$包含数字$x$确切地$k$次。 输出是模 998244353 的频率分布。 

关键的难点在于$N$最多可以有 200,000 个数字，因此我们无法迭代最多 200,000 个数字$N$。 该解决方案必须直接对数字表示进行操作$N$，将其视为字符串。 

一个天真的解释会尝试枚举直到$N$，计算数字计数，并对它们进行存储。 即使对于像这样的小值，这也会立即失败$N = 10^{18}$，因为候选人的数量随着数字的数量呈指数增长。 

出现微妙的边缘情况时$N$具有限制前缀的前导结构。 例如，如果$N = 1000$和$x = 0$，那么像 999、1000 这样的数字在数字计数的累积方式上会有不同的表现。 另一个边缘情况是当$x$是 9 并且$N$充满了 9，其中严格的约束传播到每个数字位置。 

主要的结构性挑战是，我们不需要提供单个计数，而是要求对所有数字进行完整的计数分布，最多可达$N$。 这表明数字动态编程状态可以跟踪有多少次出现$x$到目前为止已经使用过。 

## 方法

 强力解决方案将迭代每个整数$M$从 1 到$N$，将其转换为字符串，统计数字出现的次数$x$，并增加频率数组。 这是正确的，因为它直接匹配的定义$f(k)$。 然而，成本主要是迭代所有整数直到$N$，这是不可能的，当$N$最多有 200,000 位数字。 即使写下所有这些数字也是不可行的。 

关键的观察是我们永远不需要显式地构造数字。 我们只需要计算给定长度和前缀结构的数字有多少个产生一定数量的数字$x$。 这是一个经典的数字 DP 情况，但有一个额外的聚合维度：我们不需要单个计数，而是需要完整的出现次数直方图。 

我们处理$N$一个数字一个数字。 在每个位置，我们维护某个前缀的正确使用数量$k$的出现次数$x$。 当我们扩展前缀时，我们要么放置一个比相应数字小的数字$N$，这使得后缀完全自由，或者我们匹配数字$N$，这使限制保持活动状态。 

核心思想是预先计算，对于固定长度$len$, 到底有多少个数字$k$的出现次数$x$。 这可以组合完成：选择$k$之间的位置$len$放置数字$x$，并用除$x$。 这给出了二项式和 9 的幂结构。 

然后我们将贡献逐个位置组合起来，同时尊重前缀约束$N$。 每当我们遇到一个位置，我们放置的数字小于$N[i]$，我们可以自由添加任何后缀，为剩余位置提供完整的组合计数。 

这减少了从迭代所有数字到迭代数字位置并通过组合分配计数的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数的位数$N$| O(1) | O(1) | 太慢了|
 | 组合数学的数字 DP |$O(n^2)$或者$O(n)$取决于实施| O(n) | 已接受 |

 ## 算法演练

 我们用数字来表示$N$作为字符串$s$长度$n$。 

我们还预先计算阶乘和逆阶乘，直到$n$，因为二项式系数会重复出现。 

我们定义一个辅助数组$ways[i][j]$表示构造长度的方法数量$i$数字正好与$j$数字出现次数$x$。 这是使用以下方法计算的：$$ways[i][j] = \binom{i}{j} \cdot 1^j \cdot 9^{i-j}$$因为每个选择的位置$x$是固定的，其他位置都有9种选择（除数字外）$x$）。 

然后我们处理前缀$N$。 

1.我们初始化一个答案数组$ans[k] = 0$为所有人$k$。 我们还维护一个正在运行的前缀状态，表示有多少个有效数字等于前缀$N$迄今为止。 
2.我们迭代每个位置$i$在$N$。 在这个位置，我们考虑放置一个小于$s[i]$。 如果我们放置这样一个数字$d$，然后剩余的长度后缀$n - i - 1$是完全免费的。 对于每一个可能的$k$，我们添加后缀的数量$k - c$的出现次数$x$， 在哪里$c$是是否$d = x$。 

此步骤是正确的，因为选择较小的数字会打破严格的前缀约束，因此所有补全都变得独立于$N$。 

1.如果$d = s[i]$，我们继续严格约束并移动到下一个位置。 如果$s[i] = x$，我们增加这条路径上当前出现的次数。 
2、处理完所有仓位后，我们还必须统计数量$N$本身，因为它包含在范围内。 
3. 我们仔细地累积贡献，以便每个数字都按照与它不同的第一个位置精确地计算一次$N$。 

为什么它有效是基于对集合的分区$[1, N]$通过第一个索引，其中数字不同于$N$。 每个数字都恰好是$N$，或在一个独特的位置发散$i$。 一旦发散，后缀就不受限制，因此组合计数可以独立应用。 DP 确保每个分歧点准确贡献正确的完成数量，并且不会重复计算任何数字，因为每个分歧点都有唯一的最早不匹配位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    s = input().strip()
    x = int(input().strip())
    n = len(s)

    # factorials
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    pow9 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow9[i] = pow9[i - 1] * 9 % MOD

    def ways(len_, k):
        return C(len_, k) * pow9[len_ - k] % MOD

    ans = [0] * (n + 1)

    cnt_x = 0

    for i in range(n):
        digit = int(s[i])
        rem = n - i - 1

        for d in range(digit):
            add_x = cnt_x + (1 if d == x else 0)
            for k in range(n + 1):
                need = k - add_x
                ans[k] = (ans[k] + ways(rem, need)) % MOD

        if digit == x:
            cnt_x += 1

    ans[cnt_x] = (ans[cnt_x] + 1) % MOD

    print(*ans)

if __name__ == "__main__":
    solve()
```该实现首先构建阶乘表以支持快速二项式系数计算。 这是必要的，因为每个后缀计数都取决于选择数字的位置$x$。 

功能`ways(len_, k)`编码后缀的组合结构：select$k$数字的位置$x$，并用其他 9 个数字中的任意一个填充其余部分。 这直接对应于$\binom{len}{k} 9^{len-k}$。 

主循环维护有多少次出现$x$已经出现在前缀中$N$。 当我们放置一个比当前数字小的数字时$N$，我们使用以下方法切换到自由计数`ways`剩余后缀的函数。 当我们匹配数字时，我们继续收紧。 

最后，我们明确地计算了数量$N$本身，这是唯一的完全紧路径。 

## 工作示例

 考虑一个小例子$N = 123$,$x = 1$。 我们跟踪在每个数字处分支时有多少有效数字。 

在第一个数字上，我们考虑选择小于 1 的数字，即只有 0。这会产生从 0 开始的所有长度为 3 的数字，这些数字实际上作为严格意义上的 3 位数字是无效的，但在这个框架中对应于较短的有效前缀，并通过后缀的组合计数来处理。 

| 职位| 前缀 | cnt_x | 数字| 分行数字| 雷姆 | 添加_x | 贡献 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | “” | 0 | 1 | 0 | 2 | 0 | 方式(2, k) |
 | 1 | “1”| 1 | 2 | 0,1 | 1 | 1 或 0 | 方式(1, k - add_x) |
 | 2 | “12”| 1 | 3 | 0,1,2 | 0 | 更新 | 终端|

 这显示了每个前缀不匹配如何生成完整的后缀贡献。 

现在考虑$N = 111$,$x = 1$。 紧密路径中的每个数字都会增加 cnt_x，并且所有较早发散的数字都通过后缀组合进行完全计数。 

| 职位| 数字| cnt_x | 雷姆 | 行动|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0→1 | 2 | 收紧|
 | 1 | 1 | 1→2 | 1 | 收紧|
 | 2 | 1 | 2→3 | 0 | 收紧|

 只有完全紧路径才有贡献$k = 3$，并且所有较小前缀分支正确分配计数。 

这些痕迹表明，每个数字都根据其第一个偏离点被精确分配一次$N$。

 ## 边缘情况

 对于$N = 111$和$x = 1$，该算法正确地跟踪完全紧密的路径，其中每个前缀选择都会强制选择下一个数字。 每一步，`cnt_x`递增，并且不采用任何自由后缀分支。 仅在最后一步我们才将贡献添加到$f(3)$，与单个数字 111 匹配。 

对于$N = 1000$和$x = 0$，前缀分支很早就变得重要。 在第一个数字处，选择 0 会产生一大组较短的有效数字，并且组合`ways`函数确保所有后缀完成都以正确的重数进行计数。 紧路径继续经过 1，然后是三个零，有助于正确计数$k = 3$，而所有早期的分歧都将质量分配为更小的$k$根据前缀和后缀中引入了多少个零来划分桶。
