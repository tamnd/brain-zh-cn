 ## 解决方案
 ## 问题理解

 我们需要构造一个二进制前缀码。 

输入给出了该语言中所有单词的长度。 每个单词可能只包含`0`和`1`，并且任何单词都不允许成为另一个单词的前缀。 我们必须要么建立这样的一组词，要么确定这是不可能的。 

例如，如果长度是`[1, 2, 3]`，一种有效的构造是：```
0
10
110
```这些字符串都不是另一个字符串的前缀。 这个词`0`不是以下的前缀`10`因为`10`开始于`1`， 和`10`不是以下的前缀`110`因为`110`开始于`11`。 

关键的困难在于长度是固定的。 我们不能自由选择任意码字长度，只能选择实际的二进制字符串。 

约束足够小，我们可以负担得起周围的算法`O(n log n)`甚至`O(total_length^2)`在实践中，由于`n ≤ 1000`每个长度最多为`1000`。 尽管如此，暴力破解二进制字符串是完全不可行的，因为长度为`1000`意味着有`2^1000`可能的候选人。 

无前缀二进制字符串的结构强烈建议按照二进制特里树进行思考。 每个节点对应一个前缀，选择一个单词就意味着将一个节点标记为终端。 一旦节点成为终端，它的整个子树就变得不可用，因为它下面的较长字符串将以该单词作为前缀。 

一些边缘情况很容易被错误处理。 

假设所有长度都是`1`：```
3
1 1 1
```长度只有两个二进制字符串`1`，即`0`和`1`。 粗心的贪婪算法可能会不断尝试更深的字符串，但更深的字符串会将这些单词之一作为前缀。 正确的输出是：```
NO
```另一个棘手的情况是重复长度：```
4
2 2 2 2
```这是有效的，因为正好有四个长度的二进制字符串`2`：```
00
01
10
11
```一个错误的实现会错误地阻止 trie 中的兄弟姐妹，可能会拒绝这个有效的情况。 

当短单词占用太多空间时，会出现一种更微妙的情况：```
3
1 2 2
```选择一个长度为 1 的单词后，特里树中只剩下一个分支可用。 该分支仅包含两个长度的字符串`2`，但其中一个以所选的 length-1 单词开头并被禁止。 长度为 2 的单词的最大可能数量下降。 正确答案是：```
NO
```除非仔细处理特里结构，否则这种交互会使局部贪婪选择变得危险。 

## 方法

 蛮力的想法很简单。 一一生成所需长度的二进制字符串，并检查新字符串是否与之前选择的字符串冲突。 如果两个字符串中的一个是另一个的前缀，则两个字符串会发生冲突。 

这适用于较小的长度。 对于每个候选字符串，我们可以将其与之前选择的每个单词进行比较。 问题在于搜索空间。 即使是单一长度`1000`词有`2^1000`的可能性。 在最坏的情况下，再多的修剪也无法挽救这种方法。 

真正的观察是，无前缀集合自然对应于二元特里树中的叶子。 

将所有二进制字符串视为无限二叉树中的路径。 向左移动追加`0`, 向右移动追加`1`。 一个字的长度`k`对应深度的一个节点`k`。 

在此视图中前缀条件变得简单。 如果我们选择一个节点作为单词，我们将被禁止选择该节点的任何祖先或后代。 因此，每个选定的单词必须是选定节点中的叶子。 

这表明了贪婪的构造。 

如果我们首先处理较短的长度，我们总是可以在该深度分配按字典顺序最小的当前可用节点。 一旦使用一个节点，它的子树就会自动从考虑中消失。 

实现此目的的一种简洁方法是维护当前可用的前缀集。 最初仅存在空字符串。 为了生成更大深度的字符串，我们通过替换前缀来重复扩展节点`x`和`x0`和`x1`。 

关键的不变量是可用的集合始终包含成对不冲突的前缀。 当我们需要一个长度的单词时`L`，我们扩展直到一些可用的前缀达到深度`L`。 如果不存在这样的节点，则无法构建。 

这将指数搜索变成了确定性的贪婪特里遍历。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n log n + 总长度) | O(总长度) | 已接受 |

 ## 算法演练

 1. 读取所有长度及其原始索引。 

我们必须按输入顺序输出答案，但按排序顺序处理长度要容易得多，因为较短的单词会限制较长的单词。 
2. 按长度对单词进行排序。 

首先分配短单词是安全的，因为短单词会阻塞整个子树。 拖延简短的言语可能会在以后引发冲突。 
3. 维护当前可用前缀的队列。 

最初队列仅包含空字符串`""`。 
4. 对于每个所需的长度`L`，重复扩展最短的可用前缀，直到队列前面有长度`L`。 

扩展前缀`x`意味着将其移除并插入`x0`和`x1`。 

这模拟了二进制特里树中更深一层的下降。 
5、扩容后，检查前面的前缀长度是否准确`L`。 

如果所有可用的前缀都已经比`L`，则没有长度有效的单词`L`不再存在了。 输出`NO`。 
6. 否则，将前面的前缀作为该请求的所选单词并将其从队列中删除。 

删除它可以防止以后使用任何后代，这会自动保留无前缀条件。 
7. 将所选单词存储在其原始索引处。 
8.处理完所有请求后，输出`YES`并按输入顺序打印存储的单词。 

### 为什么它有效

 该算法保持了每个可用前缀都代表二叉树的未使用子树的不变性。 

当我们扩展前缀时`x`进入`x0`和`x1`，我们对以`x`进入其两个子子树，而不会丢失任何可能的未来字符串。 

当我们选择一个词的时候`x`，我们将其子树从未来的考虑中永久删除。 这保证了后面的单词不能有`x`作为前缀。 

按递增顺序处理长度使得贪婪选择有效。 较短的单词总是比较长的单词占用更多的空间，因此延迟短单词只会降低灵活性。 通过始终在所需深度处采用字典顺序最小的可用前缀，我们永远不会浪费可用的特里空间。 

如果算法在一定长度上失败`L`，每个剩余的可用前缀都已经比`L`。 由于trie深度仅在扩展期间增加，因此无法在深度创建新节点`L`。 有效的构造不可能存在。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    lengths = list(map(int, input().split()))

    arr = [(lengths[i], i) for i in range(n)]
    arr.sort()

    q = deque([""])
    ans = [""] * n

    for length, idx in arr:
        while q and len(q[0]) < length:
            cur = q.popleft()
            q.append(cur + "0")
            q.append(cur + "1")

        if not q or len(q[0]) != length:
            print("NO")
            return

        ans[idx] = q.popleft()

    print("YES")
    print("\n".join(ans))

solve()
```解决方案直接遵循 trie 解释。 

队列按字典顺序存储可用的前缀。 最初仅存在空字符串。 展开一个节点相当于用它的两个子节点替换它。 

这`while`循环不断扩展，直到最浅的可用前缀达到所需的深度。 这很重要，因为比目标深度短的前缀还不能用作单词。 

失败的情况很微妙：```
if not q or len(q[0]) != length:
```如果最短的可用前缀已经比`length`，那么每个可用的前缀也更深。 我们永远无法在特里树中向上移动，因此构造一个如此精确长度的单词是不可能的。 

从队列中删除选定的前缀可以强制实现无前缀。 一旦选择了一个单词，它的子树就会永久消失。 

队列大小永远不会变得大到足以引起问题。 每次扩展，节点数增加1，选择的单词总数仅为`1000`。

 ## 边缘情况

 考虑输入：```
3
1 1 1
```该算法将空字符串扩展为`0`和`1`。 它同时使用这两种方法来处理前两个请求。 在第三个请求之前队列变空。 由于没有剩余未使用的子树，因此该算法正确打印：```
NO
```现在检查重复的相等长度：```
4
2 2 2 2
```该算法重复扩展前缀直到深度 2：```
00, 01, 10, 11
```每一个都只被选择一次。 由于同一深度的节点不能互为前缀，因此构造成功。 

最后，考虑短单词消耗 trie 容量的情况：```
5
1 2 2 2 2
```选择一个长度为1的单词后，只剩下一半的trie。 那一半正好包含两个深度 2 的叶子。 该算法成功分配了两个长度为 2 的字，然后队列变空，而请求仍然存在。 它输出：```
NO
```这与二进制特里树的实际组合限制相匹配。
