 ## 解决方案
 ## 问题理解

 我们有一排炉子，每个炉子都有一个整数温度，开始时可能是负值，也可能是正值。 目标是执行一系列本地操作，以便每个炉子最终都具有非负值。 

唯一允许的移动应用于内部炉子，而不是端点。 当我们选择位置时`i`，其值按符号翻转，同时将其值添加到两个邻居中。 因此，中间的元素改变了符号，它的“影响力”对称地向外推向左右邻居。 

这创建了一个系统，其中每个操作都会在本地重新分配值，但也会永久更改数组的总体结构。 由于值在两个方向上向外传播，因此决策在数组中紧密耦合，并且贪婪的本地修复显然并不安全。 

这些约束促使我们寻求线性或近线性的解决方案。 和`N ≤ 10^5`，子阵列上的任何二次策略或操作的重复模拟都是不可能的。 甚至一个`O(N^2)`逐一尝试操作的贪婪模拟将超出限制几个数量级。 我们需要一种策略，其中每个索引都被处理恒定的次数，或者贡献在一次传递中被聚合。 

边界处出现了一个微妙的问题。 因为我们永远无法对指数进行操作`1`和`N`，末端的任何负值必须通过传播间接纠正。 如果结构不允许足够的“流动”到末端，则某些配置是不可能的。 天真的贪婪方法常常会失败，因为它会修复内部的消极性，而不考虑它可能会破坏边缘的可行性。 

当多个负值相互作用时，会出现第二种故障模式。 由于每次操作都会翻转并传播一个值，因此单独处理负值会导致计数过多或振荡，其中固定一个位置会在其他位置重新引入负值。 

## 方法

 暴力解释是模拟所有可能的有效操作序列，并选择产生完全非负数组的最小长度。 每个状态通过选择一个索引来转换`i`并应用确定性更新。 这形成了一个大的隐式图，其中每个状态都是一个整数数组，边对应于操作。 

即使我们假设我们可以生成邻居`O(N)`，状态空间是指数的。 分支因子是`O(N)`而且深度是无界的，所以即使是BFS也会立即爆炸。 关键的困难在于状态不是独立的：一个操作改变三个位置，并且可以通过重复应用任意级联。 

突破在于停止从状态角度思考，而是将这一过程重新解释为控制每个指数“使用”作为再分配来源的程度。 每次操作在`i`翻转`A[i]`，这意味着它有效地切换一个符号并将贡献向外推。 如果我们固定每个位置的使用次数，最终值将成为初始数组与确定性系数的线性组合。 

更有用的观点是从左到右处理数组，并将每个索引视为在继续之前必须“中和”的东西。 由于只能选择内部索引，因此位置上的任何不平衡`i`必须使用操作来纠正`i`或附近，然后我们就失去了影响它的能力。 

这导致了贪婪的构造，我们根据当前累积的不平衡来决定每个位置的操作数量。 这个过程的行为就像沿线携带一个带符号的流：一旦我们移动了一个索引，我们必须确保它永远不会再次变成负值，因为它不能在以后直接修复。 

核心思想是，每个头寸的最终价值仅取决于以结构化方式对相邻指数进行的操作，从而使我们能够保持运行平衡并在本地决定需要多少操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 | 指数| 指数| 太慢了|
 | 线性贪婪传播 | O(N) | O(1) 额外（除了数组） | 已接受 |

 ## 算法演练

 我们从左到右扫描并决定在每个有效内部位置必须应用多少次操作以确保前缀保持非负。 

1. 考虑所有之前的操作后，初始化一个代表当前有效温度的运行值。 该值跟踪有多少“赤字或盈余”被带入下一个指数。 
2. 从索引迭代`2`到`N-1`。 在每个位置`i`，结合当前有效值`i`进入运行状态。 这反映了先前的操作如何改变了原始数组。 
3. 如果当前位置的值`i`已经是非负的，我们什么也不做。 没有理由应用一项操作，因为翻转它会给两个邻居带来不必要的干扰。 
4. 如果该值为负数，我们被迫使用以下操作来修复它`i`。 每次操作都会翻转`A[i]`，将负面贡献转变为正面贡献，同时还将其幅度向外推向两个邻居。 
5、该位置所需的操作次数`i`正是在当前累积状态下使其达到零或以上所需的绝对赤字。 我们将此计数添加到答案中。 
6. 应用这些操作后，我们更新正在运行的贡献以反映已推送的数量`i-1`和`i+1`。 这确保了未来的头寸处于正确的调整状态。 
7. 继续直到倒数第二个索引，因为最后一个索引无法操作，必须间接修复。 

处理后，如果第一个或最后一个元素在所有传播效应下仍然为负，则该配置是不可能的，因为没有剩余位置可以影响它。 

### 为什么它有效

 关键的不变量是在处理索引之前`i`, 所有指数`< i`已经确定并且不会再改变。 我们执行的每项操作`i`或稍后仅影响位置`≥ i-1`，并且由于我们从不重新访问早期的指数，因此它们的最终状态在我们经过它们时就已确定。 

因为每次操作在`i`对邻居有确定性的线性影响，一旦我们知道当前的累积值，每个位置所需的操作数量就会被强制。 任何偏差都会留下负值`i`或者引入不必要的额外操作，这对未来的可行性没有帮助，因此贪婪的选择在本地和全局都是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n <= 2:
        # no valid operation exists
        return 0 if all(x >= 0 for x in a) else -1
    
    ans = 0
    
    # we simulate propagated effect using a difference-like carry
    # left_effect[i] represents accumulated change coming from i-1 operations
    carry = 0
    
    for i in range(1, n - 1):
        a[i] += carry
        
        if a[i] >= 0:
            carry = 0
            continue
        
        need = -a[i]
        ans += need
        
        # applying operation at i, need times
        # flips a[i] and adds original value effect to neighbors
        # net effect: a[i] becomes +need
        # neighbors receive +(-a[i]) each time before flip adjustment
        
        # after fixing, current becomes non-negative, and we push influence outward
        carry += need
    
    # apply final carry to last element
    a[-1] += carry
    
    if a[-1] < 0:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```该代码维护对数组的单次传递，使用`carry`代表从左侧推动了多少影响力。 每次遇到负调整值时，我们都被迫花费足够的操作来抵消它。 该成本累计在`ans`。 

重要的实现细节是我们从未在每一步显式模拟完整的邻居更新。 相反，我们将所有从左到右的传播压缩到`carry`多变的。 这避免了 O(N²) 更新，并通过保留早期操作的所有效果已被编码到的不变性来确保正确性`a[i]`当我们处理它的时候。 

最后一个元素是单独检查的，因为它不能直接操作，所以它必须吸收所有剩余的传播效果。

 ## 边缘情况

 最小数组`N = 1`或者`N = 2`立即暴露边界约束：无法应用任何操作，因此根据符号，答案为零或不可能。 忽略这一点的简单解决方案通常会返回错误的正计数。 

中间值严重为负但相邻值较小或为零的配置显示传播是否得到正确处理。 在这种情况下，算法必须认识到，如果局部校正在末端溢出约束，则局部校正可能不够充分，而这正是最终可行性检查所要防止的。 

小正值和负值的长交替模式测试每次修正后进位累积是否正确重置。 任何忘记重置传播的解决方案都会错误地放大后面的索引。
