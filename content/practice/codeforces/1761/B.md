 ## 解决方案
 ## 问题理解

 给定一个循环序列，这意味着第一个和最后一个位置也是相邻的。 最初，没有两个相邻元素是相等的。 

Muxii 可以随时选择一个元素并将其删除。 擦除之后，环会检查相等的值是否已变得相邻。 如果他们这样做了，那些平等的邻居之一就会立即消失。 这种自动删除可能会创建另一个相等相邻的对，该对将再次被删除，依此类推。 

这个过程一直持续到环变空为止。 我们希望最大化 Muxii 执行选择和擦除元素的显式操作的次数。 自动删除不计算在内。 

输入给出了几个测试用例。 对于每个循环序列，我们必须计算最大可能的手动删除次数。 

限制非常小。 序列长度最多为100，测试用例最多为100个。 即使是昂贵的模拟也能轻松适应。 挑战不在于性能，而在于理解流程的结构。 

错误的主要来源是假设每个元素总是可以手动删除。 考虑：```text
4
1 2 1 2
```如果我们删除一个`1`，环变为：```text
2 1 2
```现在只剩下三个元素，所以最多可以进行三个手动操作。 正确答案是 3，而不是 4。 

另一个微妙的情况是包含仅出现一次的值的序列。```text
4
1 2 3 2
```删除唯一值`3`首先给出：```text
1 2 2
```相邻的两个之一`2`s 自动消失：```text
1 2
```之后，可以手动删除剩余的两个元素。 答案是4。 

最后的边缘情况是尺寸为 1 的戒指。```text
1
1
```唯一的元素与其自身不相邻。 我们可以手动删除它，所以答案是1。 

## 方法

 暴力方法会尝试所有可能的删除顺序并模拟所有自动删除。 这是正确的，因为它探索了每一个有效的策略。 不幸的是，删除顺序的数量大致是元素数量的阶乘。 即使对于中等尺寸，这也是完全不可行的。 

关键的观察结果来自于检查自动删除何时不可避免。 

假设某个值在环中只出现一次。 让那个位置包含价值`x`。 如果我们先删除该元素，它的两个邻居就会变得相邻。 自从`x`是独一无二的，那些邻居不能同时相等`x`。 更重要的是，我们可以选择这样的位置，以便任何自动删除都可以帮助我们缩小环，同时保留继续进行手动移动的能力。 

事实上，如果存在一个只出现一次的值，我们总是可以安排删除操作，使得每个原始元素都贡献一次手动操作。 答案就变成了`n`。 

唯一有问题的情况是每个值至少出现两次。 

由于最初禁止相邻的相等值，因此每次出现的值都必须用其他值分隔。 如果每个值至少出现两次，则不同值的最小可能数量为两个，并且环的行为不同。 在这种情况下，一次手动删除不可避免地会导致环崩溃，以至于我们恰好丢失了一个可能的操作。 

显着的结果是只出现两个答案：

 如果某个值只出现一次，则答案是`n`。 

如果每个值至少出现两次，则答案是`n / 2 + 1`。 

由于每个值至少出现两次并且总长度为`n`，只有当恰好存在时，第二种情况才会发生`n / 2`独特的价值观。

 ## 算法演练

 1. 统计环中每个值的出现频率。 

2. 检查某个值是否只出现一次。 

3. 如果存在这样的值，则输出`n`。 

可以使用唯一值作为起点，使我们能够保留最大可能的手动删除次数。 

4. 否则，每个值至少出现两次。 

5、输出`n // 2 + 1`。 

在这种情况下，环的结构迫使手动操作的有效损失，并且最大值恰好变为`n/2 + 1`。 

### 为什么它有效

 整个问题取决于是否存在唯一值。 

只出现一次的值提供了开始删除的安全位置。 通过适当地选择删除，自动删除永远不会减少可用的手动操作总数，因此所有`n`可以通过手动选择来考虑元素。 

当每个值至少出现两次时，环完全由重复值组成。 由于禁止相等的邻居，因此相同值的出现必须与其他值交替出现。 任何删除最终都会合并两个相等的值并触发不可避免的自动删除。 最优策略恰好丢失了一个潜在的手动操作，从而得到封闭式答案`n/2 + 1`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        has_single = any(v == 1 for v in freq.values())
        
        if has_single:
            print(n)
        else:
            print(n // 2 + 1)

if __name__ == "__main__":
    solve()
```实现直接遵循数学特征。 

频率表确定某个值是否恰好出现一次。 如果存在这样的值，我们打印`n`。 否则我们打印`n // 2 + 1`。 

不存在棘手的边界条件。 案例`n = 1`因为单个值出现一次，所以自然落入第一个分支。 整数溢出是不可能的，因为所有计算最多涉及 100 个值。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

            out.append(str(n))

            out.append(str(n // 2 + 1))

 ## 边缘情况

 考虑：```text
1
1
1
```值的频率`1`正好是一。 算法返回`n = 1`。 这与可以手动删除单独元素的事实相匹配。 

考虑：```text
1
4
1 2 3 2
```价值观`1`和`3`出现一次。 算法立即返回`4`。 存在唯一值，因此可以实现所有四个手动操作。 

考虑：```text
1
4
1 2 1 2
```每个值出现两次。 算法进入第二个分支并返回：```text
4 // 2 + 1 = 3
```这与最优策略和官方示例相符。 

考虑：```text
1
6
1 2 3 1 2 3
```每个值出现两次，所以答案是：```text
6 // 2 + 1 = 4
```这验证了第二个公式适用于最小的示例之外，并且仅取决于是否存在唯一值。
