 ## 解决方案
 ## 问题理解

 我们没有被要求构建排列。 我们只需要判断两个长度排列是否`n`可以存在使得它们完全共享`a`位置在开始并且正好`b`位置在最后。 

考虑两种排列`p`和`q`。 如果它们的最长公共前缀有长度`a`，然后位置`0...a-1`必须平等且位置`a`必须不同，除非`a = n`。 类似地，如果它们的最长公共后缀的长度`b`，那么最后一个`b`位置必须相等，并且后缀之前的位置必须不同，除非`b = n`。 

限制很小。 排列长度最多为`100`，并且最多可以有`10^4`测试用例。 甚至一个`O(n)`或者`O(n^2)`每个测试用例的检查都是微不足道的。 挑战不是性能，而是发现确定有效对是否存在的正确条件。 

一些边缘情况很容易被忽略。 

考虑：```
n = 1, a = 1, b = 1
```答案是`Yes`。 只有一种排列，`[1]`，因此两个排列必须相同。 盲目拒绝以下情况的解决方案`a + b >= n`会错误输出`No`。 

考虑：```
n = 2, a = 1, b = 1
```答案是`No`。 如果第一个位置匹配且第二个位置也匹配，则排列完全相同。 它们的共同前缀和后缀长度都是`2`， 不是`1`。 

考虑：```
n = 4, a = 1, b = 1
```答案是`Yes`。 一对有效的是：```
p = [1,2,3,4]
q = [1,3,2,4]
```常见的前缀长度为`1`常见的后缀长度是`1`。 

一个常见的错误是只检查是否`a + b <= n`。 例如：```
n = 3, a = 1, b = 1
```这里`a + b = 2 <= 3`，但答案仍然是`No`。 固定前一后一共用位置后，只剩下中间一位置。 两个排列不能在一个位置上完全相同，因为任何更改都必须移动至少两个值。 

## 方法

 一个蛮力的想法是生成所有长度的排列`n`，检查每一对，并计算它们的最长公共前缀和后缀。 这是正确的，因为它直接测试定义。 不幸的是，排列的数量是`n!`。 即使是为了`n = 10`, 已经有`3,628,800`排列，使完整的搜索变得毫无希望。 

关键的观察来自于计算位置。 

第一个`a`地位被迫平等。 最后一个`b`地位也被迫平等。 这意味着`a + b`位置已经固定为匹配，尽管有些位置可能重叠。 

其余位置形成排列可能不同的唯一区域。 

让```
free = n - a - b
```如果`free < 0`，那么所需的公共前缀和后缀重叠太多。 发生这种情况的唯一方法是排列变得完全相同。 这仅适用于特殊情况`n = a = b`。 

如果`free = 0`，每个位置都被迫匹配，因此排列又是相同的。 除非`n = a = b`，无法达到所需的最长前缀和后缀长度。 

如果`free = 1`，正好有一个不固定的位置。 两个排列不能在一个位置完全相同，因为移动一个值必然也会影响另一个位置。 

为了创建不同的排列，我们至少需要两个空闲位置。 然后我们可以交换该空闲区域内的两个值并获得所需的不匹配。 

所以条件就变成：```
n - a - b >= 2
```或特殊情况：```
a = n and b = n
```Codeforces 的社论通常表达相同的想法：```
a + b <= n - 2
```或者```
a = n and b = n
```这些条件是等效的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((n!)²·n) | O((n!)²·n) | O(n!) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`a`， 和`b`。 
2. 检查是否`a == n`和`b == n`。 

在这种情况下，两种排列可能完全相同。 答案是`Yes`。 
3. 否则，计算是否`a + b <= n - 2`。 

这意味着至少有两个位置保留在强制公共前缀和公共后缀之外。 
4. 如果条件成立，输出`Yes`。 

通过至少两个空闲位置，我们可以在该区域内安排交换，创建不同的排列，同时保留所需的前缀和后缀。 
5.否则，输出`No`。 

少于两个自由位置意味着排列要么相同，要么需要在一个位置上恰好不同，这对于排列来说是不可能的。 

### 为什么它有效

 第一个`a`位置和最后`b`两个排列之间的位置固定为相等。 任何差异都必须发生在其余位置。 

一个排列不能在一个位置上与另一个排列不同。 任何移动的值都会迫使至少一个附加位置发生变化。 因此，不相同的对至少需要两个允许更改的位置。 

什么时候`a + b <= n - 2`，至少有两个这样的位置，并且该区域内的简单交换会创建一个有效的对。 什么时候`a + b > n - 2`，剩下的空闲位置少于两个。 唯一可行的情况是每个位置都是共享的，即`a = b = n`，其中相同的排列满足要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, a, b = map(int, input().split())

    if (a == n and b == n) or (a + b <= n - 2):
        print("Yes")
    else:
        print("No")
```实现直接遵循数学条件。 

第一个分支处理两个最长公共长度等于整个排列长度的独特情况。 在这种情况下，两个排列可以是相同的。 

第二个分支检查是否至少有两个位置仍在强制匹配前缀和后缀之外。 使用`a + b <= n - 2`避免显式计算空闲位置的数量，尽管它是完全相同的条件。 

不存在溢出问题，因为所有值最多都是`100`。 唯一微妙的部分是记住特殊情况`a = b = n`。 如果没有它，输入如`1 1 1`会错误地产生`No`。

def solve():

 ## 边缘情况

 考虑：```
n = 1
a = 1
b = 1
```该算法首先检查是否`a == n`和`b == n`。 两个条件都成立，因此输出`Yes`。 

痕迹：```
a == n -> true
b == n -> true
answer -> Yes
```这正确地处理了唯一的排列`[1]`。 

考虑：```
n = 2
a = 1
b = 1
```特殊情况失败是因为`a`和`b`不等于`n`。 

然后：```
a + b = 2
n - 2 = 0
```条件`2 <= 0`是假的，所以算法输出`No`。 

每个位置都将被强制相等，从而使排列相同。 它们的最长公共前缀和后缀将变为`2`， 不是`1`。 

考虑：```
n = 3
a = 1
b = 1
```该算法评估：```
a + b = 2
n - 2 = 1
```自从`2 <= 1`为假，则答案为`No`。 

只剩下一个中间位置可用。 任何改变排列的尝试都需要改变至少两个位置，而这在只有一个空闲槽位的情况下是不可能的。 

考虑：```
n = 4
a = 1
b = 1
```该算法评估：```
a + b = 2
n - 2 = 2
```自从`2 <= 2`是真的，答案是`Yes`。 

恰好有两个位置尚未确定。 交换这些位置中的值会产生具有所需公共前缀和后缀长度的有效排列。
