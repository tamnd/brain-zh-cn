 ## 解决方案
 ## 问题理解

 我们总共得到了三张麻将牌。 每块牌由 1 到 9 的数字和一套花色组成，其中花色是以下之一`m`,`p`， 或者`s`。 

在这个简化的游戏中，一手胜利只需要存在一个门苏。 门津可以是相同牌的三元组，也可以是同一花色的三个连续数字的序列。 

我们可以绘制任何我们想要的附加图块，并且图块存在的数量没有限制。 任务是找到所需的最小数量的额外图块，以便在我们持有的图块中至少存在一个有效的三元组或序列。 

输入大小异常小。 我们总是收到正好三块瓷砖。 游戏中只有 27 种不同的图块类型，因此即使相当暴力的方法也是可行的。 挑战不在于表现，而在于正确识别当前牌局距离形成有效组合有多近。 

一些边缘情况很容易导致错误的实现。 

考虑：```
1m 1m 2m
```正确答案是：```
1
```画另一个`1m`完成三连音。 仅检查序列的解决方案将错误地返回 2。 

考虑：```
1m 2m 4m
```正确答案是：```
1
```绘画`3m`创建序列`1m 2m 3m`。 仅查找已存在的相邻数字的粗心实现可能会错过这一点。 

考虑：```
1m 3m 5m
```正确答案是：```
2
```没有任何一对牌足够接近，可以通过一次抽牌完成一个序列。 任何有效的组合都需要至少两个额外的瓷砖。 

考虑：```
9m 9m 9m
```正确答案是：```
0
```这手牌已经包含三连音，因此不需要听牌。 

关键的观察结果是，答案只能是 0、1 或 2。从三个图块开始，如果我们选择任何一个图块，则两个附加副本始终会创建一个三元组。 因此，两次平局总是足够的。 

## 方法

 暴力方法会尝试所有可能绘制的图块。 由于有 27 种图块类型，我们可以测试每一个可能的单图块扩展和每一个可能的两图块扩展，然后检查是否存在融合。 总的工作量很小：

 - 一次抽奖有 27 种可能性。 
-$27^2 = 729$两次抽签的可能性。 

对于每一手候选牌，我们只检查少数牌。 即使这种方法也很容易满足限制。 

然而，这个问题的结构要简单得多。 我们永远不需要构建实际的未来牌。 我们只需要知道当前牌局距离某种组合有多接近。 

混合由三块瓷砖组成。 由于我们已经持有三张牌，因此每个潜在的组合都必须使用其中的一张、两张或全部三张。 

如果所有三个当前图块已形成融合，则答案为 0。 

如果当前两个图块在添加一个图块后可以成为融合的一部分，则答案为 1。 

否则答案是2。 

这减少了测量已经对某种融合做出贡献的最大数量的图块的任务。 

对于三元组，相同的图块一起贡献。 两个相同的图块需要多一份。 三张相同的牌不需要。 

对于序列来说，只有相同花色的牌才重要。 两张相同花色的牌可以是：

 - 连续的，例如`4m`和`5m`，需要一个端点图块；
 - 间隔一个间隙，例如`4m`和`6m`，需要中间的瓷砖；
 - 相同，这对序列没有用，但可能对三联体有帮助。 

我们评估每一对瓷砖并确定已经存在多少个混合瓷砖。 找到的最佳值决定了答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(27²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读三块图块。 
2. 将答案初始化为2。 

抽两次总是足够的，因为任何瓷砖都可以通过再抽两张来变成三联体。 
3. 单独检查每块瓷砖。 

单个图块已经为未来的某些融合贡献了一个图块，因此答案不能超过 2。 
4. 检查每对瓷砖。 

如果两块瓷砖相同，它们就已经形成了三分之二的三分之二。 将答案更新为最多 1。 
5. 对于每对具有相同花色的，比较它们的数字。 

设数字之间的差为`d`。 
6. 如果`d = 0`，这对人为三元组贡献了两张牌。 

将答案更新为最多 1。 
7.如果`d = 1`或者`d = 2`，添加一个合适的图块后，这对可以成为一个序列。 

示例：

 -`3m, 4m`需要`2m`或者`5m`。 
-`3m, 5m`需要`4m`。 

将答案更新为最多 1。 
8. 检查所有三块图块是否已形成三元组。 

如果是这样，答案是 0。 
9. 检查所有三张牌是否组成同花色的序列。 

对数字进行排序并验证它们是连续的。 

如果是这样，答案是 0。 
10.输出答案。 

### 为什么它有效

 每个融合恰好包含三块瓷砖。 这手牌已经包含三张牌，所以唯一重要的是某些组合中已经存在多少张牌。 

如果组合中的所有三块牌都存在，则不需要抽牌。 

如果组合中存在两块牌，则抽牌即可完成。 

如果没有一个牌组包含多于一张的当前牌，则至少需要进行两次抽牌。 由于通过从任何现有图块中完成三元组来完成两次抽取总是足够的，因此答案恰好是两次。 

该算法明确检查两个图块可以属于同一三元组或序列的每种方式，以及所有三个图块已经形成融合的每种方式。 因此它总是返回所需的最小抽奖次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

tiles = input().split()

ans = 2

for i in range(3):
    for j in range(i + 1, 3):
        a, sa = int(tiles[i][0]), tiles[i][1]
        b, sb = int(tiles[j][0]), tiles[j][1]

        if tiles[i] == tiles[j]:
            ans = min(ans, 1)

        if sa == sb:
            d = abs(a - b)
            if d <= 2:
                ans = min(ans, 1)

# triplet
if tiles[0] == tiles[1] == tiles[2]:
    ans = 0

# sequence
nums = []
suit = tiles[0][1]

same_suit = True
for t in tiles:
    if t[1] != suit:
        same_suit = False
        break
    nums.append(int(t[0]))

if same_suit:
    nums.sort()
    if nums[0] + 1 == nums[1] and nums[1] + 1 == nums[2]:
        ans = 0

print(ans)
```解决方案首先观察到答案永远不会超过 2。我们初始化`ans = 2`然后寻找证据表明只需要一次平局或零次平局。 

嵌套循环检查每对图块。 由于只有三块图块，因此恰好存在三对。 如果两个瓷砖相同，则它们已经是三元组的三分之二。 如果两个牌具有相同的花色并且它们的数字最多相差两个，则单个牌可以完成一个序列。 

处理完对后，我们检查这手牌是否已经完成。 三元组很容易检测，因为所有三个图块字符串必须相等。 

对于一个序列，所有三种花色都必须匹配。 然后我们对数字进行排序并验证它们是否形成连续值。 排序避免了对输入顺序的依赖。 

一个常见的错误是忘记了间隙恰好为 2 的情况，例如`3m`和`5m`。 一块瓷砖，即`4m`，完成序列。 检查`d <= 2`正确处理相邻对和单间隙对。
