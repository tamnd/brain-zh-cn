 ## 解决方案
 ## 问题理解

 我们有一个数组和一个特殊的取消过程，其行为就像一个带有湮灭的堆栈。 我们从左到右扫描数组，维护一个堆栈。 当我们看到一个值时，如果栈顶不同，我们就压入它。 如果相同，我们删除顶部而不是推送新元素。 因此，相等的相邻“相互作用”消除了配对。 

如果以这种方式处理所有元素后，堆栈变空，则称完整数组为良好。 任务是计算给定数组中有多少子数组在此过程中是好的。 

每个查询都是独立的，并且所有查询的总输入大小足够大，以至于不可能对所有子数组进行任何二次方法。 

直接解释就足以看出其中的困难：每个子数组都需要模拟一个可以双向取消的堆栈过程，而取消取决于不断演变的历史，而不仅仅是局部结构。 

主要约束含义是总长度最多为3e5。 每个测试的任何解决方案都必须接近线性或最坏的接近线性对数。 枚举子数组并模拟是 O(n^2) 个子数组，每个子数组可能是 O(n)，这是完全不可行的。 

一个更微妙的问题是取消并不是单调的。 扩展子数组既可以创建也可以破坏取消模式，因此两个相邻的子数组不是独立的。 

打破天真的直觉的边缘情况包括：

 像这样的数组`[1, 2, 3, 2, 1]`其中不存在直接重复项，但取消取决于深度配对结构，而不是邻接。 

另一个例子是交替结构`[1, 2, 1, 2, 1, 2]`幼稚的“对计数”会失败，因为堆栈状态会振荡而不是稳定。 

最后，统一数组如`[x, x, x, x]`看似简单：它们完全成对抵消，但只有当长度相等时。 

这些模式显示了关键的困难：堆栈过程相当于在动态归约后重复取消相邻的相等块，而不仅仅是局部删除。 

## 方法

 暴力解决方案很简单。 对于每个子数组，完全按照描述模拟堆栈过程。 每个元素要么被推送，要么取消前一个顶部，因此每个模拟在子数组长度上都是线性的。 对于 O(n^2) 个子数组，在最坏的情况下会导致 O(n^3)，或者如果每个子数组开始仔细优化的话会导致 O(n^2)。 对于 n 达到 3e5 来说这太慢了。 

关键的观察结果是，堆栈过程的行为就像重复删除相邻的相等对，但至关重要的是，它不仅仅是数组中相邻的删除。 相反，它是一个取决于当前简化形式的简化过程。 重要的结构见解是，每个数组都有一个通过此取消过程获得的规范“简化堆栈形式”，并且可以通过这些简化形式如何交互来分析段的串联。 

如果我们通过其简化的堆栈状态来表示每个前缀，则扩展段对应于在堆栈状态之间应用转换。 关键属性是堆栈状态始终是相邻值不同的序列，并且它仅通过压入或弹出最后一个值来演变。 

这允许分而治之的想法：我们通过固定中点并向外扩展来计算有效子数组，同时保持堆栈状态的压缩表示。 扩展期间遇到的不同堆栈状态的数量是有限的，因为每个推入-弹出操作仅更改顶部，并且可以增量地维护该结构。 

官方解决方案中使用的更深层次的技巧是将每个位置视为有助于“减少后缀的状态”之间的转换，然后通过散列这些状态来计算有效匹配。 当子数组的两半完美抵消时，它们的简化形式必须是彼此兼容的逆，这可以通过比较编码的堆栈状态来检测。 

因此，我们不是模拟每个子数组，而是枚举可能的简化堆栈签名，并使用散列和两指针或分而治之计数策略来匹配互补签名。

 ## 算法演练

 1. 预先计算前缀的堆栈过程的滚动表示，不仅维护最终堆栈，还维护其整个结构的散列。 每次压入或弹出时，我们都会更新表示当前堆栈序列的滚动哈希。 这允许在 O(1) 内进行堆栈状态之间的相等检查。 
2. 对于每个位置，在处理完该位置的前缀后计算缩减堆栈。 我们存储堆栈内容及其哈希签名。 这为我们提供了一种间接比较后缀行为的方法。 
3. 观察一个子数组`[l, r]`当且仅当从空堆栈处理它导致空堆栈时才有效。 这相当于说处理后减少的堆栈`[l, r]`是空的。 
4. 我们不是从头开始重新计算，而是解释处理`[l, r]`从前缀的缩减堆栈开始`l-1`然后应用元素`l..r`。 当最终状态恰好返回为空时，子数组有效。 
5. 当我们扫描右端点时，我们维护一个从堆栈状态（通过哈希编码）到它们的频率的映射。 对于每个右端点，我们增量更新堆栈状态，并计算有多少个先前的左端点可以完全取消它。 
6. 取消条件是前缀引发的堆栈状态`l-1`必须完全匹配后缀的逆演化`[l, r]`。 使用散列，我们在 O(1) 中匹配兼容状态。 
7. 我们迭代数组，同时维护堆栈状态的动态结构，并使用由状态签名作为键控的哈希映射来累积匹配计数。 

### 为什么它有效

 堆栈过程是确定性和可逆的，因为每个状态都准确编码完全取消后剩余的内容。 任何减少为空的子数组都必须表示前缀状态的完美反转。 将每个中间堆栈编码为散列可以保留状态的标识，并且由于转换仅修改顶部，因此相同的散列意味着相同的堆栈配置。 这减少了检查子数组有效性的问题，以计算变换状态空间中的相等状态对，这是通过频率累积来处理的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # stack of (value, hash of prefix-stack)
    st = []
    
    # rolling hash parameters
    MOD = (1 << 61) - 1
    BASE = 91138233

    def mul(a, b):
        return (a * b) % MOD

    def add(a, b):
        return (a + b) % MOD

    # hash of empty stack
    empty_hash = 0

    freq = {empty_hash: 1}
    cur_hash = 0
    ans = 0

    # we simulate the cancellation process but track prefix states
    for x in a:
        if st and st[-1][0] == x:
            # pop
            st.pop()
            if st:
                cur_hash = st[-1][1]
            else:
                cur_hash = 0
        else:
            # push
            prev_hash = cur_hash
            cur_hash = (prev_hash * BASE + x) % MOD
            st.append((x, cur_hash))

        # count occurrences of this state
        ans += freq.get(cur_hash, 0)
        freq[cur_hash] = freq.get(cur_hash, 0) + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码将当前的缩减堆栈维护为具有滚动哈希的序列。 每次推送都会附加一个值并更新哈希值，而每次弹出都会恢复堆栈中存储的先前哈希值。 这确保了我们始终拥有前缀状态的精确简化表示。 

频率图计算每个堆栈状态出现的频率。 每当我们重新访问一个状态时，这意味着存在一个先前的前缀，其减少的堆栈与当前的堆栈匹配，这意味着它们之间的子数组完全取消。 

微妙的部分是在每个堆栈深度存储散列，而不是在弹出后重新计算它，这在每次操作的 O(1) 中保持了正确性。

 ## 边缘情况

 单个重复值数组，例如`[x, x, x, x]`表明取消取决于配对顺序。 该算法处理它是因为每个相同的空状态返回都是通过空堆栈状态的哈希相等性来计数的。 

像这样的交替数组`[1,2,1,2]`表明堆栈状态可以重新访问中间配置而无需完全取消。 频率图确保只有精确的全栈匹配才会做出贡献。 

严格递增的数组在前几步之后永远不会产生匹配的堆栈状态，因此答案仍然为零，这是正确捕获的，因为所有散列都保持不同。
