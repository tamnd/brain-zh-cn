 ## 解决方案
 ## 问题理解

 我们得到了多个独立的序列，对于每个序列，我们希望使用非常特定的操作将其转换为非递减数组。 唯一允许的移动是选择一个值`x`并采取所有出现的`x`在数组中，然后将它们全部重新定位到前面或完全到后面，保留它们的内部顺序，但不保留它们的原始位置。 

此操作非常强大，因为它可以将一个值“聚集”到数组最末端的单个块中。 然而，它也是有限制的，因为我们不能将一个值的出现分成多个组或以任意方式交错它们而不需要支付额外的操作。 

目标是计算使每个数组按非降序排序所需的此类操作的最小数量。 

约束很大：所有查询的元素总数最多为 300,000。 这立即排除了任何每次查询都是二次的解决方案。 即使每个查询采用 O(n log n) 方法也需要仔细实施，但每个测试用例方法都需要整体线性或接近线性。 

当值以复杂模式重复时，就会出现一个微妙的问题。 天真的直觉可能是我们应该计算“反转”或与排序数组的不匹配，但这会失败，因为一个操作可以一次修复一个值的许多分散出现。 例如，如果一个值出现在多个段中，移动一次可以同时修复多个紊乱点。 

常见的失败情况是值以交替模式出现。 

示例：

 输入：`[1, 2, 1, 2, 1, 2]`一种幼稚的方法可能会认为需要进行多次修复，但实际上对单个值进行仔细分组可以大大减少操作。 “等价区块”的结构比个人立场更重要。 

另一个边缘情况是数组已经排序。 任何正确的解决方案都必须立即返回零，但是依赖转换或贪婪移动的方法如果不显式检查排序性，可能会意外地仍然对操作进行计数。 

## 方法

 蛮力的想法是模拟这个过程：在每一步尝试所有可能的值`x`和两个方向（前或后），应用该操作，并递归计算剩余成本。 这很快就会呈指数增长，因为每个状态都会分支到`2 * distinct_values`的可能性，并且序列长度仍然很大。 即使使用记忆化，状态空间也太大，因为重复值的排列会创建许多等效但不同的表示。 

关键的见解是停止从立场角度思考，而是从价值转变角度思考。 所有操作完成后，每个不同的值将在最终排序数组中占据一个连续的段。 因此，问题归结为决定我们必须主动重新安排多少“价值细分”。 

如果我们在压缩连续的相等值后查看数组，我们会得到一个块序列。 重要的观察是，一个操作最多可以修复不同值块之间的一个“坏边界”，事实上，最佳策略与序列相对于排序顺序改变方向的次数密切相关。 

更精确的看待它的方法是：我们希望最小化操作，以便相等的值变得连续，并且不同值的顺序变得单调。 这简化为计算我们需要从自然运行结构中分离出多少“价值组”。 

压缩连续的重复项后，我们检查不同值之间的转换。 答案取决于必须调整多少个不相交的值出现段，以便每个值按排序顺序形成一个连续的区间。 一个值与其他值的每次“交错”都会强制执行至少一次操作，而最佳合并可确保我们只需为每次必要的分离支付一次费用。 

因此，解决方案变成对压缩块的线性扫描，跟踪有多少段违反排序的分组结构。

 ## 算法演练

 我们独立解决每个查询。 

1. 将数组压缩为具有相等值的连续块。 这消除了冗余结构，其中重复值已经形成局部连续性并且不影响操作计数。 
2. 扫描压缩序列并记录值从一个块更改为另一块的转换。 
3. 对于每个值，跟踪其出现情况是否出现在多个单独的区域中。 这相当于检查该值是否出现在压缩结构中多个不连续的块组中。 
4. 计算存在多少个这样的“分割值”，因为每个分割值至少需要一次操作来合并。 
5. 返回此计数作为答案。 

步骤 3 背后的直觉至关重要：如果一个值出现在由其他值分隔的多个不相交区域中，则在不显式移动该值至少一次的情况下，我们无法修复它。 每个这样的值都会贡献一个不可避免的操作。 

### 为什么它有效

 该操作允许我们获取某个值的所有出现并将它们向一个方向移动，但它不允许部分重新排列。 因此，每个值都可以在单个操作中“纠正”，但前提是我们选择解决它。 我们需要多个操作的唯一原因是当多个值以这样一种方式交错时，修复一个值不会自动修复其他值。 压缩块结构确保我们只计算真实的交织而不是重复的局部噪声。 这会产生一个不变量：处理后，每个计数值必然在数组中分段，这种方式如果没有至少一个专用操作就无法解析。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))

        # compress consecutive duplicates
        b = []
        for x in a:
            if not b or b[-1] != x:
                b.append(x)

        # count segments per value
        first_pos = {}
        last_pos = {}

        for i, x in enumerate(b):
            if x not in first_pos:
                first_pos[x] = i
            last_pos[x] = i

        # count how many values are "split" in compressed array
        ans = 0
        for x in first_pos:
            if first_pos[x] != last_pos[x]:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先删除连续的重复项，因为只有转换对于确定值是否碎片很重要。 然后，我们记录这个压缩序列中每个值的第一次和最后一次出现。 如果一个值出现在多个单独的块中，则其第一个和最后一个位置不同，这意味着它在结构中被分割。 

最终的答案是计算存在多少个这样的值。 每个都贡献了一个所需的操作。 

一个微妙的点是我们永远不需要显式地模拟移动值。 压缩表示已经捕获了所有有意义的结构信息。 

## 工作示例

 ### 示例 1

 输入：`[3, 1, 6, 6, 3, 1, 1]`压缩序列：`[3, 1, 6, 3, 1]`| 步骤| 压缩| 第一个/最后一个跟踪 | 分割值 |
 | ---| ---| ---| ---|
 | 开始 | [3,1,6,3,1] | 空 | 0 |
 | 流程| 相同| 3:(0,3)、1:(1,4)、6:(2,2) | 3,1 |

 这里 3 和 1 都出现在多个分开的位置，因此都被计算在内。 答案变成2。 

这表明，即使值在本地重复，重要的是它们是否出现在压缩结构中的多个断开区域中。 

### 示例 2

 输入：`[1, 1, 4, 4, 4, 7, 8, 8]`压缩：`[1, 4, 7, 8]`| 步骤| 压缩| 追踪 | 分割值 |
 | ---| ---| ---| ---|
 | 开始 | [1,4,7,8] | 1:(0,0)、4:(1,1)、7:(2,2)、8:(3,3) | 无 |

 没有值被分割，所以答案是 0。 

这证实了已经单调的块结构不需要任何操作。

 ## 边缘情况

 对于像这样的单元素数组`[5]`, 压缩率`[5]`，并且没有分割值，所以答案为零。 该算法正确地产生零，因为第一次出现和最后一次出现一致。 

对于具有所有相同值的数组，例如`[2,2,2,2]`，压缩将其减少为单个块。 没有值会多次单独出现，因此答案同样为零。 

对于高度交替的阵列，例如`[1,2,1,2,1,2]`，压缩保持交替。 两个值都出现在多个单独的位置中，因此都会对两个值进行计数，从而产生两个操作，满足隔离两个值以实现单调排序的必要性。
