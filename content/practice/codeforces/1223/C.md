[CF 1223C - 拯救自然](https://codeforces.com/problemset/problem/1223/C)

 **评分：** 1600
 **标签：** 二分查找，贪心
 **求解时间：** 1m 52s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有门票价格集合，可以自由选择售票顺序。 

存在两个捐赠计划。 每一个`a`第 - 张售出的门票贡献`x%`它的价格，以及每一个`b`第 - 张售出的门票贡献`y%`它的价格。 如果票证位置可被两者整除`a`和`b`，两个百分比均适用，贡献变为`(x + y)%`。 

对于每个查询，我们想知道售出的门票的最小数量，以便在最佳排列门票后，总贡献至少达到`k`。 如果连卖完票都达不到`k`，我们输出`-1`。 

至关重要的自由是我们可以按照自己的喜好重新订购门票。 实际的门票身份并不重要，重要的是它们的价格。 

这些约束立即排除了任何尝试多种排列的解决方案。 单个查询最多可以包含`2 · 10^5`票证，所有查询的票证总数也是`2 · 10^5`。 任何涉及对每个候选答案进行重复排序或尝试多种排列的方法都将过于昂贵。 

目标值`k`可以大到`10^14`，因此所有计算都必须使用 64 位整数运算。 

一些边缘情况很容易被错误处理。 

假设一个百分比大于另一个。```
prices = [1000, 100]
x = 10, a = 1
y = 50, b = 2
```第一张售出的门票仅获得 10%，而第二张则获得 60%。 最贵的票应该分配到 60% 的位置。 任何以任意顺序处理百分比的实现都可能会造成损失，并错误地得出需要更多票证的结论。 

当职位同时属于两个项目时，就会出现另一种微妙的情况。```
prices = [1000]
x = 50, a = 1
y = 50, b = 1
```贡献是门票价格的 100%，而不是两张单独的门票获得奖金。 正确的捐款是 1000。重复计算彩票会产生不可能的结果。 

最后一个极端情况是不可能的。```
1
100
50 1
49 1
100
```唯一一张票贡献了99，还不到100。答案是`-1`。 二分查找必须验证即使使用所有票据也无法到达目标。 

## 方法

 蛮力视角有助于揭示结构。 

假设我们猜测答案是`m`。 我们需要确定从第一个获得的最大贡献`m`卖出头寸。 由于门票订单在我们的控制之下，我们可以尝试以各种可能的方式将门票分配到位置，并选择最佳的安排。 

这显然是不可行的。 即使是几十张票，排列的数量也会变得巨大。 

关键的观察结果是，职位的不同仅在于捐赠百分比。 如果一个职位贡献 60%，另一个职位贡献 10%，则较大比例的人应该收到一张价格至少与分配给较小比例的人的价格一样大的门票。 

这是一个经典的交换论证。 如果较大的票分配到较小的百分比，而较小的票分配到较大的百分比，则交换它们只能增加总贡献。 

因此，一旦我们知道有多少职位收到`(x+y)%`, 有多少只收到`x%`，以及有多少只收到`y%`，最优排列就显而易见了：

 按降序排列门票价格。 将最大的价格分配给最大的百分比。 

现在考虑一个候选答案`m`。 

职位之间`1..m`:

 - 位置可被两者整除`a`和`b`收到`(x+y)%`。 
- 位置只能被整除`a`收到`x%`。 
- 位置只能被整除`b`收到`y%`。 

这些计数可以使用最小公倍数来计算`a`和`b`。 

一旦我们可以有效地检查是否`m`票就够了，答案就变成了二分查找`m`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最佳 | O(n log n + n log n) | O(n log n + n log n) | O(n) | 已接受 |

 第二个`n log n`因素来自二分搜索执行`O(log n)`可行性检查，每项最多需要`O(n)`工作。 

## 算法演练

 ### 预处理

 将所有门票价格按降序排列。 

由于每个价格都是 100 的倍数，因此立即将每个价格除以 100。 这允许我们使用整数算术直接处理百分比值。 

### 可行性检查

 对于候选值`m`:

 1. 计算`l = lcm(a, b)`。 
2. 计算第一个中的位置`m`获得两种奖金的销售。`both = m // l`3. 计算仅获得第一笔奖金的仓位。`only_x = m // a - both`4. 计算仅获得第二个奖金的仓位。`only_y = m // b - both`5. 确保首先处理较大百分比的部分。 

如果`y > x`， 交换`(x, only_x)`和`(y, only_y)`。 

这保证了更大的百分比与更高的票价相匹配。 
6. 从最高票价开始。 
7.分配第一个`both`门票百分比`(x+y)`。 
8.分配下一个`only_x`门票百分比`x`。 
9.分配下一个`only_y`门票百分比`y`。 
10. 计算这些作业产生的总贡献。 
11. 如果贡献至少为`k`， 然后`m`门票就够了。 

### 二分查找

 1. 检查是否全部使用`n`门票可以到达`k`。 
2.如果没有，输出`-1`。 
3. 否则对答案范围进行二分查找`[1, n]`。 
4. 对于每个中点，运行可行性检查。 
5. 如果中点有效，则搜索左半部分。 
6. 否则搜索右半部分。 
7. 第一个可行值就是答案。 

### 为什么它有效

 对于任何固定数量的已售门票`m`，每个位置贡献三个百分比之一：`(x+y)`,`x`， 或者`y`。 

考虑两张指定的门票和价格`p1 > p2`和百分比`c1 < c2`。 

他们的贡献是`p1*c1 + p2*c2`。 

交换后：`p1*c2 + p2*c1`。 

区别在于`(p1-p2)(c2-c1) > 0`。 

因此，为更大的比例分配更高的价格永远不会有坏处，有时甚至会有所帮助。 

反复应用这种交换论点可以将任何安排转变为门票价格与降序排列的百分比相匹配的安排，从而产生最大可能的贡献。 

可行性检查准确地计算了第一个的最佳贡献`m`职位。 二分查找是有效的，因为如果`m`门票足够了，那么任何更多的门票也足够了。 可行性谓词是单调的。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    q = int(input())

    for _ in range(q):
        n = int(input())

        p = list(map(int, input().split()))
        p = [x // 100 for x in p]
        p.sort(reverse=True)

        x, a = map(int, input().split())
        y, b = map(int, input().split())

        k = int(input())

        if x < y:
            x, y = y, x
            a, b = b, a

        l = a * b // gcd(a, b)

        def check(m):
            both = m // l
            cnt_x = m // a - both
            cnt_y = m // b - both

            idx = 0
            total = 0

            for _ in range(both):
                total += p[idx] * (x + y)
                idx += 1

            for _ in range(cnt_x):
                total += p[idx] * x
                idx += 1

            for _ in range(cnt_y):
                total += p[idx] * y
                idx += 1

            return total >= k

        if not check(n):
            print(-1)
            continue

        lo, hi = 1, n

        while lo < hi:
            mid = (lo + hi) // 2

            if check(mid):
                hi = mid
            else:
                lo = mid + 1

        print(lo)

solve()
```第一个重要的实施细节是在开始时对价格进行一次排序。 每个可行性检查都依赖于使用相同的票值降序排列。 

第二个微妙点是交换时执行的`x < y`。 较大的百分比必须始终先于较小的百分比分配。 如果没有这种交换，贪婪的分配可能会将昂贵的门票浪费在较弱的奖金上。 

贡献是使用已除以 100 的价格计算的。由于所有原始价格都是 100 的倍数，因此贡献为```
(price / 100) * percentage
```在数字上等于实际的货币贡献。 这完全避免了浮点运算。 

可行性函数永远不需要构建实际的销售订单。 它只计算有多少位置收到每个百分比类别，并贪婪地分配最大的剩余票值。

 ## 边缘情况

 考虑：```
1
100
50 1
49 1
100
```每张售出的门票将获得其价值的 99%。 唯一一张票贡献99。可行性检查`m = 1`计算：```
both = 1
contribution = 100 * 99 / 100 = 99
```由于 99 < 100，`check(1)`失败并且算法输出`-1`。 

现在考虑：```
1
1000
10 1
50 2
500
```较大的百分比是 50%，而不是 10%。 该算法在内部交换程序描述，以便 50% 的仓位首先消耗最大的票据价值。 如果没有这一步，贪婪分配将是错误的。 

最后考虑：```
1
1000
50 1
50 1
1000
```每个职位都属于两个计划。```
both = 1
only_x = 0
only_y = 0
```该票仅一次收到 100% 的贡献。 该算法计算：```
1000 * (50 + 50) / 100 = 1000
```并返回答案 1。重叠计数正确，没有重复使用票据。
