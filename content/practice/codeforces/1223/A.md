 ## 解决方案
 ## 问题理解

 我们得到了一些匹配项，我们希望将它们排列成“a + b = c”形式的有效算术方程，其中每个数字都是严格正数。 每个数字都用火柴棒以经典问题所暗示的通常的七段样式表示，但关键的简化是我们只关心需要多少匹配，而不是数字的确切形状。 

任务不是自由选择使用多少火柴。 我们必须使用所有给定的比赛，但如果需要，我们可以购买额外的比赛，以便可以将总数重新排列成一些有效的方程。 

每个查询的输出是所需的最小附加匹配数，以便匹配总数可以分为三个正整数 a、b 和 c，满足 a + b = c。 

约束 n ≤ 10^9 和最多 100 个查询立即排除对可能的数字结构的任何模拟。 任何解决方案都必须将问题简化为每个查询的恒定时间算术检查。 

一个微妙的问题是，幼稚的方法可能会尝试贪婪地形成数字或测试小方程。 这样做会失败，因为数字使用的匹配数取决于其十进制表示形式，并且有无限多种组合。 另一个错误的想法是尝试直接推理加法进位，但问题不在于数字和；而在于数字和。 它是关于n是否可以分解为与有效正整数对应的匹配计数。 

关键的隐藏约束是，在比赛中形成有效的 a + b = c 的最小“结构成本”是固定的，只有对该结构取模的余数决定我们是否需要购买额外的比赛。 

## 方法

 如果我们尝试暴力破解，我们将枚举所有正整数三元组（a、b、c），计算需要多少个匹配来表示它们，并检查总数是否等于或超过 n。 这已经是不可行的，因为数字可以任意大，甚至限制到 n 以内的值仍然需要 n² 的 (a, b) 候选对，每个候选对产生 c。 对于 n 最大为 10^9 的情况，这是不可能的。 

关键的观察结果是，实际的数字结构分解为一个非常简单的不变量：a + b = c 的每个有效构造都会消耗一些始终与 n 模 2 一致的匹配数。直观地说，当使用火柴棍数字构建方程时，每次添加匹配都会改变奇偶校验，并且有效方程的结构在所有组件之间强制执行固定的奇偶校验模式。 形成 CME 的最小“有效块”匹配每单位不平衡使用 2 个匹配，唯一重要的是 n 是否可以划分为这样的块而没有剩余。 

具体来说，解决方案简化为检查n是否已经可以形成有效的配置； 如果没有，我们需要添加 1 或 2 个匹配项才能到达最接近的有效结构。 由于每个有效配置都对应于远离基本结构的偶数总偏移，因此答案最终仅取决于 n mod 2。 

因此，最佳策略是确定 n 是否已经适合有效的奇偶校验类； 如果没有，我们递增到下一个有效配置。

 ## 算法演练

 该解决方案基于识别可以形成有效方程结构的最接近的匹配数。

1. 为每个查询读取 n，因为每个查询都是独立的并且没有共享状态。 
2. 检查 n 是否已经允许使用火柴数字有效分解为 a + b = c。 这简化为检查 n 是否能被 2 整除，或者更准确地说，检查 n 是否属于有效结构的可达集合。 
3. 如果 n 已经匹配有效配置，则输出 0，因为不需要额外的匹配。 
4. 否则，计算必须添加多少个匹配才能达到下一个有效配置。 由于有效配置以 2 个匹配的固定周期发生，因此调整始终为 1 或 2，具体取决于 n 距最近的有效结构有多远。 
5. 输出差值。 

### 为什么它有效

 任何有效的方程 a + b = c 都使用形成稳定算术结构的匹配计数。 可以在不破坏积极性约束的情况下改变可行性的最小构建块通过固定奇偶校验模式改变总匹配计数。 结果，所有可达到的总数与步骤 2 形成一个算术级数。因此，答案是将 n 移入该级数的最小非负增量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        
        # If n is even, it can be arranged into a valid CME configuration.
        # If n is odd, we need to add 1 match to make it even.
        if n % 2 == 0:
            print(0)
        else:
            print(1)

if __name__ == "__main__":
    solve()
```该代码独立处理每个查询。 关键的决定是对n 的奇偶校验。 如果 n 是偶数，则不需要额外的匹配。 如果 n 是奇数，我们正好添加一个匹配项以达到偶数总数，这对应于下一个有效的构造类。 

微妙的一点是我们从不尝试明确地构建方程。 推理依赖于这样一个结构事实：所有有效的匹配分布都需要偶数奇偶校验，因此奇偶校验本身就完全决定了可行性。

 ## 边缘情况

 关键的边缘情况是最小可能的输入 n = 2。这已经允许形成“1 + 1 = 2”，因此答案必须为 0。算法检查 2 % 2 = 0 并正确输出 0。 

对于 n = 3，我们无法仅使用 3 个匹配项来形成有效的方程，因为任何有效的构造都需要偶数总数。 该算法识别出 3 % 2 = 1 并输出 1，这意味着我们必须购买一根火柴才能达到 4。 

对于像 n = 10^9 这样的大值，奇偶校验仍然决定一切。 如果 n 是偶数，则不需要添加。 如果奇数，则需要恰好一场比赛。 该算法不依赖于幅度，因此即使在上限也保持稳定。
