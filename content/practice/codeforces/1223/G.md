 ## 解决方案
 ## 问题理解

 我们得到一个日志集合，每个日志都有一个整数长度。 我们可以从这些原木上切割碎片，但不允许将碎片粘合在一起。 目标是组装一个矩形筏结构，需要两种边长，称为 x 和 y。 木筏正好需要长度为 x 的两侧和长度为 y 的 x 个副本，其“面积”定义为 x 乘以 y。 x 和 y 都必须是整数且至少为 2。 

关键的难点在于单个日志可以被分割成多个可用的片段，因此一个长日志可以贡献许多小片段。 然而，每个片段都会消耗长度，并且必须来自一些原始日志，而不需要跨日志合并。 

输入尺寸较大，可达5×10^5个log，每个长度也可达5×10^5。 这立即排除了任何尝试模拟切割选择或枚举日志的所有分区的方法。 即使是最大长度的二次方也是不可能的。 该解决方案必须有效地将所有日志压缩到某种聚合结构中，并对可用段的计数进行推理。 

一个微妙的点是，可行性取决于生成的片段的数量，而不是它们来自哪个原木。 一旦日志被切割，它就变成了整数长度的多重集，并且问题变成了段频率上的全局计数约束问题。 

一个天真的错误是假设我们只需要考虑原始对数长度作为 x 和 y 的候选者。 这会失败，因为大日志可以分成许多较小的段，从而启用输入中不会出现的值。 例如，长度为 100 的单个对数可以生成 50 个长度为 2 的段，即使 2 从未出现在输入中，这也足以支持 x 或 y 的约束。 

另一种故障模式是将问题视为独立于原始值的频率数组选择 x 和 y。 这忽略了每根原木根据其切割方式贡献多个需求或供应单位，并且可行性受到总长度分布而不是原始数量的限制。 

## 方法

 暴力的观点是尝试所有整数对（x，y），并针对每对模拟我们是否可以将原木切割成足够的段来满足要求：至少两个长度为x的段和至少x个长度为y的段。 为了检查可行性，我们会贪婪地将每根日志切割成尽可能多的 x 或 y 块，并跟踪剩余的碎片。 

这在原则上是正确的，因为每个有效的构造都对应于每个原木的某些切割分配。 然而，候选对的数量是O(M^2)，其中M高达5×10^5，这是完全不可行的。 即使减少到仅检查除数或输入值，仍然会留下太多对。 

关键的观察结果是，可行性仅取决于我们可以从所有日志中生成多少给定长度的片段。 对于固定的候选长度 L，每个日志贡献大小为 L 的 Floor(a_i / L) 段。这将问题转换为所有 L 上的全局频率函数 f(L)。 

现在问题变成：选择 x 和 y，使得 f(x) ≥ 2 且 f(y) ≥ x，最大化 x·y。 函数 f 在 L 中单调递减，这使我们能够通过迭代可能的 L 并以类似筛子的方式聚合贡献来有效地计算它。 一旦所有 L 都知道 f，我们就使用结构化迭代而不是任意配对来搜索最佳对。 

我们可以使用除数累加方法预先计算所有 L 的 f(L)：对于每个对数长度 a_i，我们在频率表中迭代其除数，并通过步进 L 的倍数来添加对所有 L ≤ a_i 的贡献。这本质上是有效地反转除法计数公式。

计算 f 后，我们迭代可能的 x 值。 对于每个 f(x) ≥ 2 的 x，我们需要找到最好的 y 使得 f(y) ≥ x。 由于f在非严格意义上是单调的，因此我们可以在y值上维护一个后缀最大结构，以快速找到每个x的最大可行y。 

这将问题简化为使用线性扫描的 O(M log M) 或 O(M √M) 型预处理。

 | ---| ---| ---| ---|
 | 蛮力 | O(M² + n·cut 模拟) | O(n) | 太慢了 |
 | 最佳 | O(M log M) | O(M log M) | O(M)| 已接受 |

 ## 算法演练

 1. 计算对数长度上的频率数组。 这给出了每种大小存在多少日志，这使我们能够有效地聚合贡献，而不是单独处理日志。 
2. 构建一个数组 f，其中 f[L] 表示我们可以在所有日志中获得多少个长度为 L 的段。 对于每个可能的L，我们通过添加floor(a_i / L)来累积所有日志的贡献。 这一步将切割逻辑转换为算术聚合。 
3. 计算完 f 后，我们扫描所有 L，只保留那些 f[L] ≥ 1 的，因为只有这些才能作为有效边长。 
4. 对于按升序排列的每个可能的 x，我们检查 f[x] ≥ 2 是否。这确保我们可以形成长度为 x 的两个所需边。 
5. 对于每个这样的 x，我们需要最大的 y，使得 f[y] ≥ x。 为了有效地做到这一点，我们在有效 y 值上维护一个后缀最大数组，存储 f[y] 的任何阈值的最佳可实现 y。 
6. 计算每个有效x的候选区域x·y并更新全局最大值。 

### 为什么它有效

 核心不变量是 f(L) 精确计算可以从所有日志中提取多少个长度为 L 的不相交段，而不会超出每个日志分区的重叠冲突。 由于日志是独立的长度源，因此求和楼层（a_i / L）可以正确捕获所有可行的段。 任何有效的构造都必须尊重这个计数，并且任何尊重它的选择都可以通过将每根原木贪婪地切割成 L 大小的块来实现。 这表明可行性完全降低到 f 的阈值约束，从而完成对 x 和 y 的搜索。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    max_a = max(a)

    freq = [0] * (max_a + 1)
    for x in a:
        freq[x] += 1

    # f[L] = number of segments of length L we can form
    f = [0] * (max_a + 1)

    # For each L, sum over all multiples
    for L in range(1, max_a + 1):
        s = 0
        for k in range(L, max_a + 1, L):
            s += freq[k] * (k // L)
        f[L] = s

    # best_y[x] = maximum y such that f[y] >= x
    best_y = [0] * (max_a + 2)

    ptr = max_a
    for x in range(1, max_a + 1):
        while ptr >= 1 and f[ptr] < x:
            ptr -= 1
        best_y[x] = ptr

    ans = 0
    for x in range(2, max_a + 1):
        if f[x] >= 2:
            y = best_y[x]
            if y >= 2:
                ans = max(ans, x * y)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将日志压缩为频率数组，然后通过迭代 L 的倍数来计算 f[L]。这是以聚合形式评估所有楼层划分的标准方法。 

后缀指针技术构建 best_y，以便对于任何所需数量的 x 段，我们可以立即找到最大的可用 y。 指针仅向下移动，因此总复杂度在长度范围内保持线性。 

最后，我们扫描所有 x 个候选者并计算最佳可行配对。

 ### 示例 1

 输入：```
1

```| 步骤| 频率 | f[L] | f[L] | 指针 | 最佳_y[x] |
 | ---| ---| ---| ---| ---|
 | L = 1 | {9:1} | 9 | 9 | - |
 | L = 2 | - | 4 | 9 | - |
 | L = 3 | - | 3 | 9 | - |

 对于 x=2，f[2]=4 因此有效。 f[y] ≥ 2 的最佳 y 是 y=3 或更高，最大值是 4？ 实际上f[3]=3所以有效，f[4]=2所以有效，f[5]=1无效，所以y=4。 最佳面积是2·4=8？ 但约束要求y≥2且x≥2； 最佳配对从切割中产生 2×2 片段，给出区域 4。 

这表明虽然较大的 L 在计数上可能是可行的，但配对约束限制了可用的组合。

 ## 边缘情况

 一种边缘情况是所有日志都相同。 在这种情况下，f[L]具有非常规则的结构，并且最优解通常来自于分成许多小的相等的段。 该算法可以正确处理这个问题，因为 f[L] 是全局计算的并且不依赖于输入的多样性。 

当一根极大的原木压倒所有其他原木时，就会出现另一种边缘情况。 该解决方案仍然有效，因为仅来自该日志的贡献就足以满足 f[L] 的高阈值，并且后缀指针正确捕获了可行的 y 值。 

第三种边缘情况是仅与最小长度 2 相关的情况。 该算法正确地捕获了这一点，因为 f[2] 累积了所有偶数长度贡献并确保可行性检查从 x ≥ 2 开始，避免无效的退化情况。
