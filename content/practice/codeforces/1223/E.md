 ## 解决方案
 ## 问题理解

 我们有一棵树，每条边都有一个权重。 任务是根据非常具体的规则为顶点分配颜色：每个顶点准确接收$k$颜色，任何特定颜色在整棵树上最多可以出现两次。 这意味着每种颜色要么不执行任何操作，要么恰好连接两个顶点，在它们之间创建配对关系。 

仅当一条边的两个端点至少共享一种颜色时，它才变得有价值。 换句话说，如果两个顶点被分配了一种共同的颜色，那么该颜色就会“激活”它们的连接，并允许我们收集该边的权重。 每种颜色最多只能促成一种这样的配对，因为它最多允许出现两次。 

目标是在所有有效分配中最大化端点共享至少一种颜色的所有边的权重总和。 

每个查询给出一个单独的树和一个值$k$，并且我们必须独立计算这个最大值。 

约束很大：所有查询的顶点总数最多为$5 \cdot 10^5$，并且最多可以有$5 \cdot 10^5$queries. 这会立即排除任何以超过线性或接近线性时间处理每个查询的情况。 A solution that is even$O(n \log n)$除非大量摊销，否则每次查询都会太慢。 树的结构表明可能需要排序或单遍贪婪策略，并且由于颜色放置的组合爆炸，任何尝试显式模拟颜色分配的解决方案都是不可能的。 

一个微妙的陷阱来自于误解“每种颜色最多出现两次”的含义。 天真的解释可能会将颜色视为每个顶点独立的颜色，但实际上每种颜色的行为就像配对资源，最多创建一个边缘贡献。 另一个错误是假设问题取决于路径或子树结构； 事实上，只有边缘很重要，并且每条边缘要么被“激活”，要么未被激活。 

例如，在权重为 1 和 100 的三个节点的简单链中，尝试本地匹配顶点的天真贪婪可能会错误地优先考虑第一条边，而最佳解决方案可能取决于总共有多少对$k$允许。 

## 方法

 关键的困难是理解颜色实际上允许我们组合做什么。 每种颜色最多出现两次，因此每种颜色对应于一个顶点或一对顶点。 由于每个顶点都准确地接收到$k$颜色，我们可以认为每个顶点都有$k$“端口”可用于通过共享颜色将其连接到其他顶点。 

这将问题转化为选择最多$k$每个顶点的事件“连接”，但全局约束，以便每个连接同时消耗来自两个端点的容量。 每个选定的边对应于将一种颜色专用于两个端点，并且由于颜色不能在两个顶点之外重复使用，因此除了选定结构中的顶点度数限制之外，每个选定的边在颜色消耗方面是独立的。 

关键的观察是，在最佳解决方案中，我们只关心选择一组边，以便没有顶点使用超过$k$选定的入射边。 如果一个顶点使用的数量少于$k$，我们总是可以浪费额外的颜色而不影响分数。 因此，问题简化为选择边的最大权重子集，使得所选子集中每个顶点的度最多为$k$。 

这是一个经典的转换：我们在顶点容量约束下选择树中的边。 树结构允许贪婪的解决方案：我们希望在尊重度数限制的同时包含最重的边，并且因为没有循环，所以我们可以按权重对边进行全局排序，并在两个端点仍然有剩余容量的情况下贪婪地包含它们。 

树结构至关重要，因为树中的任何边集都不会创建会引入更复杂依赖关系的循环。 这使得简单的容量感知贪心算法变得有效。 

蛮力方法将尝试所有边子集并检查可行性，这是指数级的$n$。 考虑到查询的数量，即使尝试在每个查询的树上使用流或 DP 也会太慢。 

贪婪排序方法将问题简化为每个查询对边进行一次排序并线性处理它们。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于每个查询，读取树并存储所有边及其权重。 树结构本身不直接在边列表之外使用，因为决策纯粹是关于在约束下选择边。 
2. 按权重降序对所有边进行排序。 这确保了每当我们考虑一条边时，所有较重的边都已被考虑包含在内。 这种排序至关重要，因为在可行的情况下我们总是更喜欢较重的边缘。 
3.维护数组`used[v]`计算每个顶点有多少条选定的边。 最初全部为零。 
4. 按排序顺序迭代边。 对于边缘$(u, v, w)$，检查两者是否`used[u] < k`和`used[v] < k`。 
5. 如果两个端点仍然有可用容量，则将边缘包含在答案中并增量`used[u]`和`used[v]`。 Otherwise skip it. 这强制了每个顶点最多参与的约束$k$选定的边缘。 
6. 将所有选定边的权重相加并输出结果。 

### 为什么它有效

 该过程强制执行每个顶点的度数上限，同时始终首先选择最重的可用边。 由于每个选定的边仅消耗两个端点的一个容量单位，并且容量在各个顶点上是相同且独立的，因此稍后用较轻的边替换选定的较重的边没有任何好处。 任何有效解都对应于相同容量约束下的可行边集，排序保证我们总是贪婪地构造最大权重可行集，而不需要回溯。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n, k = map(int, input().split())
        edges = []
        for _ in range(n - 1):
            u, v, w = map(int, input().split())
            u -= 1
            v -= 1
            edges.append((w, u, v))

        edges.sort(reverse=True)

        used = [0] * n
        ans = 0

        for w, u, v in edges:
            if used[u] < k and used[v] < k:
                used[u] += 1
                used[v] += 1
                ans += w

        print(ans)

if __name__ == "__main__":
    solve()
```代码直接实现了贪心策略。 我们维护的唯一状态是每个顶点选定的入射边的数量，它对应于该顶点在配对中已经有效使用的颜色数量。 

按降序对边进行排序可确保我们始终优先考虑高价值贡献。 对两个端点的检查强制将颜色约束转化为程度限制下的可行性。 

一个微妙的实现细节是我们永远不需要显式地建模颜色。 配对抽象完全崩溃为具有容量限制的边缘选择。

 ## 边缘情况

 一个关键的边缘情况是当$k$大于任何顶点度数。 在这种情况下，没有活动的容量约束，算法只是选择所有边。 对于四个节点的路径，包括所有边，答案是所有权重的总和。 

另一种情况是星形树，其中心度数很高，但$k=1$。 贪心算法仅选择与中心相关的单个最重边缘，并且所有其他边缘都被拒绝，因为中心立即达到容量。 追踪算法表明，每次拒绝都是由以下原因引起的`used[center]`达到 1，符合预期的约束行为。 

最后一个微妙的情况是具有混合边权重的平衡树，其中早期选择会阻止后来的高值边。 排序顺序确保如果后面的边被阻塞，这是因为两个端点已经被用在至少相等权重的边上，从而保持最优性。
