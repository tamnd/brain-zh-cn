 ## 解决方案
 ## 问题理解

 每个查询给出两个长度相同的字符串。 您可以对任一字符串重复应用操作：选择两个相邻的字符并用另一个字符覆盖一个。 这意味着信息可以沿着相邻位置流动，但只能通过复制现有字母，而不是引入新字母。 

从结构的角度来看，每个字符串的行为就像一行单元格，其中任何字母都可以通过重复传播遍布整个字符串。 但是，任何操作都不会引入在开始时该字符串中不存在的字符。 

任务是确定在对两个字符串独立应用任意数量的此类传播步骤后，是否可以使它们相同。 

约束很小：最多 100 个查询，每个字符串长度最多 100。这立即排除了对字符串的转换或状态模拟的任何指数探索。 即使每个查询的三次或二次模拟也能轻松通过，但真正的目标是找到潜在的不变量而不是模拟任何东西。 

一个常见的错误直觉是认为顺序很重要或者我们必须匹配频率。 这会导致推理过于复杂。 另一个错误是假设我们需要模拟移动角色，这很快就会变得混乱，并且仍然无法捕捉到操作的真正自由度。 

当字符串除了通过转换间接地共享之外根本不共享字母时，就会出现微妙的边缘情况。 例如，如果一个字符串仅由`a`另一个仅`b`，没有办法调和它们。 另一方面，如果它们共享一个字母，则两者都可以完全变成该字母，使它们变得平等。 

## 方法

 蛮力的想法是尝试对所有可到达的字符串进行建模`s`和来自`t`。 由于每个位置都可以被邻居重复覆盖，因此每个步骤都有多种可能性。 可能的字符串数量随着长度呈指数增长，即使长度为 100，这也变得完全不可行。 

关键的观察结果是该操作永远不会创建新字符，它只会复制现有字符。 这意味着在转换中幸存下来的唯一信息是每个字符串中最初存在哪些不同的字符。 一旦字符存在于字符串中的任何位置，它就可以传播到每个位置，从而有效地擦除字符串内的任何结构。 

这将每个字符串简化为一组简单的字母。 如果这两个集合至少有一个共同的字母，我们可以选择该字母作为目标并将其独立地在两个字符串中传播，直到两者变得一致。 如果没有共同的字母，就没有办法同步它们。 

因此，问题归结为一组交叉检查。

 ## 算法演练

 我们独立处理每个查询。 

首先，我们扫描字符串`s`并记录其中出现的字母。 我们对字符串做同样的事情`t`。 由于字母表只是小写英文字母，我们可以使用大小为 26 的固定布尔数组来表示。 

接下来，我们检查是否存在两个集合中都出现的字符。 这相当于检查这两个字符集的交集是否非空。 

如果我们找到至少一个共享字符，我们立即得出结论，两个字符串都可以转换为完全由该字符组成的字符串，并且我们输出`YES`。 否则，我们输出`NO`。 

### 为什么它有效

 该操作允许在整个字符串中不受限制地传播任何现有字符。 这使得初始字符串中的每个字符在该字符串中有效地全局可用。 由于不会出现新字符，因此对最终公共字符串的唯一限制是使用的每个字符必须同时存在于两个原始字符串中。 单个共享字符就足够了，因为它可以扩展以完全填充两个字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    out = []
    
    for _ in range(q):
        s = input().strip()
        t = input().strip()
        
        seen_s = [False] * 26
        seen_t = [False] * 26
        
        for ch in s:
            seen_s[ord(ch) - 97] = True
        for ch in t:
            seen_t[ord(ch) - 97] = True
        
        ok = False
        for i in range(26):
            if seen_s[i] and seen_t[i]:
                ok = True
                break
        
        out.append("YES" if ok else "NO")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案独立处理每个查询。 对于每个字符串，它都会在字母表上构建一个存在数组。 最后的循环检查任何共享索引。 一旦发现共同字符，提前退出可确保恒定时间行为。 

一个常见的实施错误是尝试比较完整的字符串或频率。 频率是无关紧要的，因为该操作不保留计数。 另一个错误是尝试逐步模拟转换，这是不必要的，因为可达性仅取决于角色的存在。 

## 工作示例

 考虑一个查询，其中`s = "xabb"`和`t = "aabx"`。 

我们按如下方式跟踪字符集。 

| 步骤| s 角色 | t 字符 | 发现共同字符 |
 | --- | --- | --- | --- |
 | 扫描后| {x, a, b} | {a，b，x} | 是的 |

 由于至少有一个共享字符，因此两个字符串都可以简化为所有`a`例如，所以答案是`YES`。 

现在考虑`s = "a"`和`t = "z"`。 

| 步骤| s 角色 | t 字符 | 发现共同字符 |
 | --- | --- | --- | --- |
 | 扫描后| {一} | {z} | 没有|

 没有重叠，因此任何允许的操作序列都无法弥补差距，从而给出`NO`。 

第一个例子表明结构和排序是不相关的，而第二个例子表明不相交的字母表使得转换不可能。

 ## 边缘情况

 当两个字符串已经相同时，就会出现一种边缘情况。 对于像这样的输入`s = "abba"`和`t = "abba"`，算法为两个字符串标记相同的字符集，因此交集非空，输出为`YES`。 该过程不依赖于平等，但仍然正确地接受它。 

另一种边缘情况是当字符串包含重复字符但不相交的集合时，例如`s = "aaaa"`和`t = "bbbb"`。 尽管两者都是统一的，但没有共享特征，因此没有传播序列可以协调它们。 算法正确返回`NO`因为相交检查立即失败。 

第三种情况是字符串很长但只共享一个字母，例如`s = "abcabc..."`和`t = "zzzazzz..."`。 尽管大多数角色有所不同，但共同点`a`足以将两个字符串折叠成一个统一的字符串`a`，算法通过非空交集条件捕获。
