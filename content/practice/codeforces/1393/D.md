 ## 解决方案
 ## 问题理解

 我们得到一个字符网格，其中每个单元格代表一个彩色图块。 从这个网格中，我们想要计算存在多少“有效的着装模式”。 有效的图案是菱形，其边相对于网格倾斜 45 度，并且形状内的每个单元格必须具有相同的字符。 图案必须完全位于网格内。 

重新表述该问题的一个有用方法是，我们计算以任何单元为中心的所有单色菱形，其中菱形在曼哈顿几何中定义：距中心固定曼哈顿距离内的所有点形成菱形。 对于每个中心单元，每个可能的半径定义一个候选形状，如果边界上直到该半径的所有单元共享相同的颜色，我们就对其进行计数。 

网格大小可以在 2000 到 2000 之间达到 2000，因此通过全面验证来检查每个可能的中心和每个可能的半径的简单方法将涉及大约$O(n^3)$在最坏的情况下工作。 这太慢了，因为它需要数十亿次的细胞检查。 

当网格均匀时，会出现微妙的边缘情况。 例如：```
3 3
aaa
aaa
aaa
```在这里，每个中心都支持多个半径不断增加的有效菱形，答案不仅仅是单元格的数量。 任何仅计算单个单元格或仅考虑大小为 1 的局部配置的方法都会严重低估。 

当尝试通过扫描钻石内部的所有单元来独立验证每个钻石时，会出现另一种故障模式。 即使对于单个中心，半径$k$钻石含有$O(k^2)$单元格，所有中心的总和变成三次方。 

## 方法

 蛮力的想法很简单：尝试以每个单元格为中心，逐步扩大菱形半径，并在每一步验证边界或整个菱形中的所有单元格是否具有相同的特征。 这是正确的，因为它直接遵循定义，但它变得昂贵，因为验证半径$k$钻石需要检查$O(k^2)$细胞，并且对所有中心执行此操作会导致总体$O(n^3)$或更糟糕的行为。 

关键的观察结果是，我们不需要从头开始重新检查整个钻石的每个半径。 半径有效的菱形$k$以$(i, j)$由四个较小的有效结构组成，在其中心相遇。 如果我们知道相邻位置的最大有效菱形半径，我们可以根据这些值构建当前单元格的答案。 这是一种经典的动态编程模式，其中较大的几何结构由较小的移动版本组成。 

其见解是预先计算，对于单元格周围的每个方向，我们可以在保持所有字符相等的情况下延伸多远。 一旦我们有了方向一致性信息，我们就可以通过采用四个对角线方向施加的最小约束来计算恒定时间内每个单元的最大可能菱形半径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$额外 | 太慢了 |
 | 对角线上的最佳 DP |$O(nm)$|$O(nm)$| 已接受 |

 ## 算法演练

 我们将问题转化为计算，对于每个单元格，在保持颜色不变的情况下，我们可以在四个对角线方向上延伸多远。 

1. 我们预先计算四个 DP 表，对应于相同字符的对角线：左上、右上、左下和右下。 每个条目存储我们可以从该单元格开始沿该方向扩展的最大连续相同字符数。 这是有效的，因为任何有效的菱形仅取决于沿对角线的直线一致性。 
2. 对于每个单元格，我们使用简单的递归关系计算这些值。 例如，左上角的值$(i, j)$是 1 加上左上角的值$(i-1, j-1)$如果当前单元格与前一个单元格匹配； 否则重置为 1。相同的逻辑适用于所有四个方向，只是索引移位不同。 
3. 计算完这四个表后，我们将它们解释为对钻石中心尺寸的约束$(i, j)$可以。 半径有效的菱形$r$要求在所有四个对角线方向上，我们至少可以延伸$r$保持在同一角色内的步骤。 
4. 因此，对于每个单元格，最大有效半径是四个方向DP值中的最小值减1（因为中心在所有方向上都被计算在内）。 
5. 我们将所有单元格的最大半径相加，因为从 0 到最大值的每个半径恰好贡献了一个有效菱形。 

### 为什么它有效

 该算法依赖于这样一个事实：半径处的菱形边界$r$完全由四个对角线段确定。 如果所有四个方向至少都支持$r$连续相同的字符，则菱形边界上的每个单元格都保证与中心字符匹配。 相反，如果任何方向较早突破，菱形就无法进一步延伸。 这将 2D 区域验证问题减少为四个独立的 1D 问题，其重叠充分表征了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    # four diagonal DP arrays
    tl = [[0]*m for _ in range(n)]
    tr = [[0]*m for _ in range(n)]
    bl = [[0]*m for _ in range(n)]
    br = [[0]*m for _ in range(n)]

    # top-left
    for i in range(n):
        for j in range(m):
            if i > 0 and j > 0 and g[i][j] == g[i-1][j-1]:
                tl[i][j] = tl[i-1][j-1] + 1
            else:
                tl[i][j] = 1

    # top-right
    for i in range(n):
        for j in range(m-1, -1, -1):
            if i > 0 and j < m-1 and g[i][j] == g[i-1][j+1]:
                tr[i][j] = tr[i-1][j+1] + 1
            else:
                tr[i][j] = 1

    # bottom-left
    for i in range(n-1, -1, -1):
        for j in range(m):
            if i < n-1 and j > 0 and g[i][j] == g[i+1][j-1]:
                bl[i][j] = bl[i+1][j-1] + 1
            else:
                bl[i][j] = 1

    # bottom-right
    for i in range(n-1, -1, -1):
        for j in range(m-1, -1, -1):
            if i < n-1 and j < m-1 and g[i][j] == g[i+1][j+1]:
                br[i][j] = br[i+1][j+1] + 1
            else:
                br[i][j] = 1

    ans = 0
    for i in range(n):
        for j in range(m):
            r = min(tl[i][j], tr[i][j], bl[i][j], br[i][j]) - 1
            ans += r + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码构建了四个方向 DP 表，对相同字符沿对角线延伸的距离进行编码。 每次重复都是对以下思想的直接翻译：当且仅当当前字符沿该方向与前一个字符匹配时，才可以扩展运行。 

最后的聚合步骤减一，因为 DP 会在所有方向上对中心单元进行计数。 每个单元提供从 0 到最大值的所有有效半径，这简化了添加$r + 1$。

 ## 边缘情况

 一个关键的边缘情况是完全均匀的网格。 该算法通过在各处产生最大对角线来解决这个问题，但边界单元自然会限制扩展。 例如，在 3x3 均匀网格中的角单元处，所有 DP 值均为 1，因此其贡献仅为 1，从而防止过度计数。 

另一个边缘情况是棋盘格等交替图案。 即使存在相邻单元，对角线连续性也会立即中断，因此所有 DP 值仍为 1。这可确保不会形成半径为 1 的假菱形，因为半径为 1 的菱形需要在所有四个方向上保持一致的对角线连续性。 

第三种边缘情况发生在对角线被网格本身截断的边界处。 DP 公式自然地对此进行编码，因为丢失的邻居只是重置游程长度，确保不会计算无效的越界菱形。
