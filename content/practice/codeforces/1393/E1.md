 ## 解决方案
 ## 问题理解

 我们得到了一个单词序列，该序列应该来自最初排序的列表，其中原始列表按字典顺序不递减。 然而，每个原始单词可能已通过在其内部某处插入一个额外字符而被修改，因此每个观察到的单词都比其真实的原始版本长一个字符。 

我们的任务是通过从每个单词中删除一个字符来从概念上“修复”每个单词，然后计算有多少种不同的方式在所有单词中选择这种删除，以便最终的清理序列再次在字典顺序上变得不减。 最终答案是与观察到的损坏单词一致的有效原始序列的数量，取模$10^9+7$。 如果不存在一致的原始序列，则答案为零。 

关键的困难在于，每个单词都有多个可能的“父母”，这些“父母”是通过删除一个字符而获得的，并且选择会在单词之间相互作用，因为字典顺序必须在全局范围内保持。 

这些约束足够严格，任何试图显式地独立尝试每个单词的所有删除的方法都会爆炸。 每个字的长度$L$给出$L$候选者，并且在总长度达到 20000 的最坏情况下，天真的组合将是天文数字。 除非对转换进行了极其优化，否则即使对所有单词选择进行动态编程而不进行修剪也将变得不可行。 

当某些候选删除在不同位置或单词上产生相同的字符串时，就会出现微妙的边缘情况。 另一个棘手的情况是，当某个单词在前一个单词的任何选择中没有有效的前趋时，这应该立即消除整个分支。 最后，即使存在局部选择，全局一致性也可能由于跨序列的词典编排约束而失败。 

## 方法

 直接暴力解释很简单。 对于每个单词，我们考虑通过删除一个字符而形成的所有字符串。 这给出了每个职位的一组候选人。 然后，我们尝试各种方法为每个单词挑选一个候选者，并检查结果序列是否已排序。 

这在概念上是有效的，因为它准确地列举了我们所要求的内容。 然而，组合的数量是$\prod_i |s_i|$，在最坏的情况下表现得像$20^{1000}$——规模增长。 即使生成所有候选者也已经花费了成本$O(\text{total length}^2)$，并且检查所有序列是完全不可能的。 

关键的观察是我们永远不需要显式枚举完整序列。 “字典顺序非递减”条件仅取决于连续单词之间的关系。 这自然表明对序列中的位置进行动态编程，我们在其中传播有效选择的计数。 

然而，重复比较完整的字符串仍然是昂贵的。 第二个见解是，每个候选字符串都是通过删除一个字符形成的，因此我们可以有效地生成所有候选字符串，并使用哈希或后缀比较等预先计算的结构来比较它们。 一旦候选可用，问题就简化为计算分层图中的非递减序列：每个单词都是一层，每个候选都是一个节点，并且边存在于单词中$i-1$到$i$如果候选人订单有效。 

这将问题转化为分层 DP，其中转换受到字典顺序的限制。 最终的优化是通过对每层内的候选进行排序并使用前缀聚合来有效地计算转换来避免显式检查所有对。

 ## 算法演练

 我们通过删除一个字符来为每个单词构建所有可能的“父字符串”。 对于一个字的长度$m$，我们生产$m$候选人。 

然后，我们从左到右处理单词，维护当前单词的每个候选者可以到达的方式。 

1. 对于每个单词，删除一个字符生成所有候选字符串。 这一步是必要的，因为每个有效的解决方案都必须为每个单词选择一次删除，因此我们完全具体化了状态空间。 
2. 按字典顺序对第一个单词的候选进行排序，并为每个单词分配 DP 值 1。这表示这些清理后的字符串中的任何一个都可以是有效序列的开始。 
3. 对于每个下一个单词，还生成其候选单词并按字典顺序对它们进行排序。 我们将根据前一层计算这些候选者的 DP 值。 
4. 对于当前单词中的固定候选，我们需要按字典顺序统计前一个单词中有多少个候选小于或等于该候选。 我们不是比较每一对，而是扫描两个排序列表并维护前一层 DP 值的前缀和。 这使我们能够计算每层线性时间的所有转换。 
5.计算完当前层中所有候选的DP值后，我们将前一层替换为当前层并继续。 
6. 处理完所有单词后，将最后一层的所有 DP 值相加即可得到答案。 

其有效工作的关键原因是字典顺序在排序的候选列表上引入了单调结构。 一旦两个层都被排序，有效的转换就会形成一个前缀结构，而不是一个任意的二分图。 

### 为什么它有效

 在每一步中，DP[i][j] 表示在保持排序顺序的同时到达单词 i 的第 j 个候选的方式数。 由于字典顺序是完整的并在排序时保留，因此候选者的所有有效前任在先前排序的列表中形成前缀。 这保证了前缀和正确聚合所有有效转换，而不会重复计算或遗漏。 DP 不变量是在处理单词 i 后，所有计数准确反映直到 i 的有效部分重建的数量，从而保持全局单调性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def gen_candidates(s):
    # generate all strings formed by deleting one character
    res = []
    n = len(s)
    for i in range(n):
        res.append(s[:i] + s[i+1:])
    return res

n = int(input())
words = [input().strip() for _ in range(n)]

# build first layer
prev = sorted(gen_candidates(words[0]))
dp = [1] * len(prev)

# precompute nothing else; we rely on lex ordering

for i in range(1, n):
    cur = sorted(gen_candidates(words[i]))

    # prefix DP over previous layer
    new_dp = [0] * len(cur)

    j = 0
    pref = 0

    for k in range(len(cur)):
        # advance j while prev[j] <= cur[k]
        while j < len(prev) and prev[j] <= cur[k]:
            pref = (pref + dp[j]) % MOD
            j += 1
        new_dp[k] = pref

    prev = cur
    dp = new_dp

print(sum(dp) % MOD)
```此代码通过删除一个字符来显式构造每一层。 对每个层进行排序可确保字典顺序表示为简单的索引顺序。 DP 数组跟踪每个候选点结束的有效路径数。 

转换循环是经典的双指针扫描：由于两层都已排序，因此我们维护一个指向前一层的指针，并累积每个当前候选的所有有效贡献。 

一个常见的微妙问题是忘记这里的字符串比较是对完整字符串进行字典顺序比较，而不是逐个字符的手动检查。 Python 字符串比较已经匹配所需的顺序，因此我们直接依赖它。 

另一个微妙的问题是，我们永远不会错误地重置内部循环中的前缀和； 当我们浏览已排序的候选者时，它必须单调累积。

 ## 边缘情况

 当多次删除产生相同的字符串时，就会出现一种重要的边缘情况。 例如，在这样的词中`aaa`，删除任何字符会产生`aa`，因此候选层在排序后会折叠成重复项。 该算法自然地处理了这个问题，因为在 DP 中每次出现都是独立处理的，并且前缀和正确聚合相同的字符串。 

当一个单词产生的候选词按字典顺序都小于下一个单词的所有候选词时，就会出现另一种边缘情况。 在这种情况下，整个先前的 DP 和都会流入每个下一个状态，前缀扫描可以正确捕获这些状态，而无需特殊的大小写。 

失败的情况是尝试仅匹配相等的字符串而不是使用`<=`订购； 这会错误地丢弃有效的严格递增转换。
