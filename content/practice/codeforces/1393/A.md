 ## 解决方案
 ## 问题理解

 我们有一个大小为的正方形网格$n \times n$。 目标是用棋盘图案中的两种颜色完全覆盖每个单元格，这意味着相邻单元格必须始终具有相反的颜色。 

构建过程受到限制：最初，只有网格的外边界被认为是“可用的”，从那里开始，每回合一次添加一个或多个图块。 每个新放置的瓷砖必须沿着边缘接触至少一个先前存在的瓷砖。 在一个回合中，只有一个玩家行动，但只要满足放置规则，她可以放置多个自己颜色的图块。 

问题纯粹是关于调度：假设两个玩家之间的最佳合作，需要多少轮才能完全构建网格的任何有效的国际象棋着色。 

约束条件$n \le 10^9$立即排除任何网格模拟。 任何尝试对电路板或贴装过程逐个单元进行建模的解决方案都需要$O(n^2)$工作或记忆，这是不可能的。 甚至$O(n)$如果给出许多查询，在最坏的情况下每个测试用例都会太慢。 

关键的难点在于，答案不在于复杂意义上的网格几何形状，而在于如何在邻接约束下将国际象棋图案“分层”。 

一个幼稚的错误来自于假设因为有两种颜色，所以答案总是 2。这会立即失败$n = 4$。 在这种情况下，样本输出为 3，表明某些结构限制阻止在两个交替移动中完成所有操作。 

另一个微妙的陷阱是假设偶数和奇数之间是对称的$n$。 例如，$n = 3$需要 2 圈，同时$n = 4$需要 3 圈，因此奇偶校验本身并不是全部。 

## 方法

 强力解释将模拟构建过程。 我们将维护一个网格，每轮重复放置有效的单元集，并明确强制执行邻接约束。 即使我们贪婪地尝试每回合填充最大有效扩展，我们仍然需要跟踪$n \times n$结构。 这至少导致$O(n^2)$状态或重复扫描，当$n$达到$10^9$。 

关键的观察结果是，问题并不取决于单独的放置，而是取决于网格结构中存在多少强制交替“层”。 

在棋盘着色中，网格可以被认为是交替的奇偶校验单元。 当我们从边界开始时，每一次移动都可以有效地“向内推”一层一致的颜色，但对角线结构迫使某些单元格只有在多次扩展波之后才能到达。 

关键的简化在于，答案仅取决于是否$n$是偶数还是奇数，更准确地说，是关于从边界向内扩展时存在多少个完整的依赖“环”。 

对于奇数$n$，中心单元充当扩展的自然交汇点，允许稍微更有效的分层。 对于甚至$n$，网格分裂得更加对称，需要额外一圈来协调中间的奇偶校验结构。 

这导致了一个简单的封闭形式：$$\text{answer} = \left\lfloor \frac{n}{2} \right\rfloor + 1$$这与两个示例案例匹配：

 对于$n = 3$，我们得到$1 + 1 = 2$。 

为了$n = 4$，我们得到$2 + 1 = 3$。 

更深层次的原因是，每一对行（或列）都贡献一个“层”的构造，并且需要额外的一轮来完成剩余奇偶校验不匹配的国际象棋交替约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(n^2)$|$O(n^2)$| 太慢了|
 | 公式$\lfloor n/2 \rfloor + 1$|$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 读取每个值$n$。 每个测试用例都是独立的，因此它们之间不共享任何状态。 
2. 计算$n // 2$。 该值表示从边界向内扩展时，网格存在多少个完整的“配对层”。 
3. 将结果加 1。 这解释了最后的巩固步骤，其中国际象棋着色约束迫使除了简单的层配对之外进行额外的回合。 
4. 立即输出每个测试用例的计算值。 

### 为什么它有效

 施工过程有效地减少了对称层向内剥离网格。 每一对相对的边都贡献一个完整的扩展步骤。 然而，国际象棋着色的奇偶校验约束在所有情况下都无法实现完美配对，从而强制执行一个额外步骤来解决最终配置。 由于每个有效的构造都必须尊重来自边界的邻接传播，因此没有任何策略可以减少下面的层数$\lfloor n/2 \rfloor$，最终的奇偶校验会强制执行额外的常数项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n = int(input())
    print(n // 2 + 1)
```该解决方案直接实现派生的封闭式表达式。 唯一的微妙之处是确保使用整数除法，因为该公式取决于底数行为。 每个测试用例在恒定时间内独立处理。

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        out.append(str(n // 2 + 1))
    return "\n".join(out)

# provided samples
assert solve("2\n3\n4\n") == "2\n3"

# minimum case
assert solve("1\n1\n") == "1"

# small odd/even mix
assert solve("3\n2\n3\n5\n") == "2\n2\n3"

# large value sanity
assert solve("1\n1000000000\n") == str(1000000000 // 2 + 1)

 ## 边缘情况

 当$n = 1$，网格是单个单元格。 公式给出$1 // 2 + 1 = 1$，符合除了初始放置之外不需要分层的事实。 

对于非常大的$n$， 例如$10^9$，计算保持恒定时间。 Python中不存在溢出风险，并且公式仅依赖于整数除法，因此无需模拟，结果仍然准确。
