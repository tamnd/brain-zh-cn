 ## 解决方案
 ## 问题理解

 我们反复运行一个随机过程，该过程在三个结果上形成一个小概率分布。 在任何时刻，最多有三个“活动”单据，其中一个是最终成功状态（粉单），另外两个是瞬态状态。 每场比赛对应于当前分布中的一次抽签，并且在每次抽签之后，根据抽签的项目及其当前概率质量以确定性方式修改分布。 

第一次开除解雇通知单时，该过程结束。 任务是计算终止之前的预期抽奖次数。 

尽管系统以三个概率开始，但规则意味着当它们的概率质量被推为零时，物品可能会永久消失。 当这种情况发生时，剩余的概率质量将在幸存的项目之间重新分配，或者根据阈值参数 v 进行按比例调整。这意味着系统的状态不是固定的，但它仍然完全取决于哪个项目子集保持活动状态及其当前概率。 

键输入大小是恒定的。 最多有 3 个初始状态和最多 10 个测试用例，因此任何解决方案都可以针对由消除和重新分布引起的可能分布提供指数或状态枚举技术。 这立即排除了对渐近有效图遍历或大规模动态编程的任何需要。 如果状态空间得到正确控制，对状态的强力攻击是可行的。 

一个微妙的问题是概率是连续演化的，而不是在一个小的整数网格上离散演化的。 由于精度不稳定和状态爆炸，使用原始浮点三元组来记忆状态的天真尝试将失败。 另一个常见的陷阱是将转换视为独立于绘制的概率。 重新分配规则以打破朴素线性期望分解的方式将转移概率和下一个状态耦合起来。 

当非终结概率之一相对于 v 变得非常小，导致立即消除，或者当重复消除将系统降低为二态或一态链时，就会出现主要边缘情况。 在这些情况下，过程很快就会崩溃，但简单的递归模拟可能会过度计算步骤，或者在删除后无法正确传播概率质量。 

## 方法

 直接强力方法将过程模拟为连续状态上的马尔可夫链。 从给定的状态，我们考虑绘制每个活动项，根据规则更新概率，并递归计算预期的剩余步数。 这在概念上是正确的，因为期望满足由转移概率加权的所有可能的下一个状态的递归。 

然而，困难在于，每次抽奖后，概率都会以确定性但依赖于值的方式发生变化。 这意味着如果简单地跟踪，相同的结构状态可以产生无限多个数字变体。 如果我们试图将每一个可能的实数三元组视为不同的状态，则递归将永远不会合并状态，也不会以记忆的方式终止。 

关键的观察结果是该系统非常小且高度结构化。 在任何时候，唯一有意义的状态取决于哪个项目子集仍然处于活动状态以及它们当前的概率。 由于消除只能通过将概率设置为零来发生，因此结构状态的数量是有限的。 更重要的是，在任何状态下，我们只需要考虑最多三个转换的期望，并且下一个状态由简单的算术变换唯一确定。

这允许我们定义当前概率向量的递归函数。 尽管值具有连续性，但递归深度是有限的，因为每次消除都会严格减少活动项的数量，并且在固定的活动集中，递归通过可通过直接评估求解的线性期望方程收敛。 

因此，我们不是模拟长序列，而是使用函数方程计算期望：从状态 (c, m, p) 开始，期望值是 1 加上以每次可能抽签为条件的下一个状态的加权期望，其中权重是当前概率。 

最佳解决方案直接通过状态记忆来评估这种递归，其中概率在每次转换后归一化，并且浮点容差就足够了，因为仅存在少量可到达的状态。

 ## 算法演练

 我们定义一个递归函数`solve(c, m, p)`返回从当前概率分布到达解雇通知书的预期步骤数。 

1. 如果解雇概率实际上为 1，则期望为 0，因为该过程已经完成。 这是重现的基本情况。 
2. 否则，每次抽签花费 1 步，因此我们从 1 开始期望。 
3. 我们考虑以概率 c 提取现金单。 如果抽到了，我们就根据规则更新分布。 如果 c 至多为 v，则消除该项目，并将其概率质量平均重新分配给剩余项目。 如果 c 大于 v，我们从 c 中减去 v 并平均重新分配移除的质量。 
4. 我们对概率为 m 的中间滑动执行相同的操作，应用相同的变换规则。 
5. 我们还考虑概率为 p 的解雇通知书。 如果它被绘制，则该过程停止，因此它不会贡献进一步的期望。 
6. 我们线性组合这些转换：期望值是 1 加上 c 乘以提取现金后的状态期望，加上 m 乘以提取 m 后的状态期望，加上 p 乘以 0。 
7. 由于状态空间非常小，我们在对浮点值进行归一化后记住每个三元组（c，m，p）的计算期望，以避免重复重新计算。 

正确性依赖于马尔可夫过程中的期望满足第一步转换的线性分解这一事实。 每个状态完全决定下一个状态的分布，并且通过在第一次绘制时扩展，每个可能的未来轨迹都被精确捕获一次。 即使状态值是连续的，递归结构也确保我们只评估由消除和重新分配规则引起的有限多个不同配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from functools import lru_cache

@lru_cache(None)
def solve(c, m, p, v):
    # if pink slip dominates
    if p > 0.999999:
        return 0.0

    res = 1.0

    # cash
    if c > 1e-12:
        if c <= v:
            nc, nm, np = 0.0, m + c / 2, p + c / 2
        else:
            nc, nm, np = c - v, m + v / 2, p + v / 2
        res += c * solve(nc, nm, np, v)

    # middle
    if m > 1e-12:
        if m <= v:
            nc, nm, np = c + m / 2, 0.0, p + m / 2
        else:
            nc, nm, np = c + v / 2, m - v, p + v / 2
        res += m * solve(nc, nm, np, v)

    return res

def main():
    t = int(input())
    for _ in range(t):
        c, m, p, v = map(float, input().split())
        ans = solve(c, m, p, v)
        print(f"{ans:.12f}")

if __name__ == "__main__":
    main()
```该解法直接实现了第一步期望递推。 功能`solve`独立处理每次抽签，并根据问题的重新分配规则更新概率向量。 记忆化确保重复的状态不会被重新计算。 

当概率实际上为零时，与小 epsilon 的浮点比较可以防止由数值噪声引起的无限递归。 每个转换都显式地构造下一个状态，并且递归结构确保终止，因为至少有一个概率质量朝着消除或向最终状态重新分布的方向移动。 

## 工作示例

 我们追踪第一个样本输入`(c, m, p, v) = (0.2, 0.2, 0.6, 0.2)`。 

在初始状态，我们将期望计算为 1 加上每次非最终抽签的贡献。

 这显示了每个分支如何通过消除一个活动组件或将质量移向最终状态来立即减少状态空间。 

对于第二个例子，考虑一个概率低于 v 的情况，例如`(0.1, 0.2, 0.7, 0.2)`。 

| 步骤| 状态| 行动| 下一个状态 |

 这证明了小概率如何提前消失，从而加速收敛。

def run(inp: str) -> str:

        @lru_cache(None)

            if p > 0.999999:
                return 0.0
            res = 1.0
            if c > 1e-12:
                if c <= v:
                    nc, nm, np = 0.0, m + c/2, p + c/2
                else:

                    nc, nm, np = c + m/2, 0.0, p + m/2
                else:
                    nc, nm, np = c + v/2, m - v, p + v/2
                res += m * solve(nc, nm, np, v)

 ## 边缘情况

 一个重要的边缘情况是当概率恰好处于阈值 v 时。在这种情况下，该项目将被完全消除而不是部分减少。 该算法通过检查来处理这个问题`c <= v`和`m <= v`，这会强制归零和重新分配行为。 例如，与`(c,m,p,v) = (0.1,0.2,0.7,0.2)`，图c将其完全移除并产生`(0,0.25,0.75)`。 然后，递归仅在两个活动状态上继续，从而防止错误保留小概率质量。 

当重复的重新分配累积浮点误差时，会出现另一种边缘情况，从而使概率稍微偏离总和为 1。该实现通过从精确的算术表达式构造每个下一个状态并且从不启发式地重新规范化来避免这种情况。 这保留了每个转换代表有效概率分布的不变性，确保期望重现在整个执行过程中保持一致。
