 ## 解决方案
 ## 问题理解

 我们正在玩一个互动游戏，其中隐藏的数字始终保持在 0 到 n − 1 的范围内。我们反复提交猜测。 如果猜测正确，则交互立即结束。 如果猜测不正确，系统不仅会拒绝它，还会使用猜测和按位运算（当 k = 2 时进行异或）主动转换隐藏数字。 重要的变化是，在每次错误的猜测之后，隐藏值的变化方式取决于之前的隐藏值和我们的猜测。 

这使得问题不仅仅是寻找一个固定的数字。 每次错误的尝试都会以可逆的代数方式修改系统的状态。 我们得到的唯一反馈是我们是否击中了正确的数字，如果没有，系统会隐式地告诉我们隐藏状态如何演变。 

每个测试用例的约束 n ≤ 2 × 10^5 且总和也≤ 2 × 10^5 意味着我们最多可以承受总体线性数量的查询。 任何需要对数或恒定数量的每比特查询的策略都可以，但是如果每次测试使用 O(n) 查询，任何模拟范围内的完整搜索或重复重建状态的策略仍然会通过。 

一个微妙的点是交互器是自适应的。 这意味着初始隐藏值不是预先固定的。 这可以取决于我们的策略，只要它与之前的所有响应保持一致即可。 这消除了任何假设固定目标的概率或预计算策略。 

简单方法的主要失败模式是假设重复的 XOR 查询的行为类似于固定值的独立探测。 例如，如果假设“查询 x 为我提供有关隐藏 XOR x 的信息”，则该解释会被破坏，因为隐藏值本身在每次错误猜测后都会发生变化。 

## 方法

 强力策略是尝试从 0 到 n − 1 的所有值。在非自适应设置中，这最终会在 n 次查询中成功。 然而，这里每一个错误的猜测都会改变隐藏值。 这意味着在尝试值 i 后，“正确答案”不再是我们试图达到的数字。 因此，即使是完整扫描也不能保证成功，因为目标会根据我们的查询而不断移动。 

关键的观察结果是，XOR 下的变换规则是线性的。 如果隐藏值为 x 并且我们猜测 y，则新的隐藏值 z 满足 x ⊕ z = y，重新排列为 z = x ⊕ y。 这意味着每个错误的猜测都会通过与我们的查询进行异或来替换隐藏状态。 因此，在一系列错误的猜测 y1, y2, ..., yk 之后，隐藏值变为：

 x ⊕ y1 ⊕ y2 ⊕ ... ⊕ yk

 这意味着我们完全控制隐藏状态的演变方式。 每个查询只是通过与我们选择的数字进行异或来切换状态。 

这种结构允许一个简单的策略：我们有意将隐藏值引导到我们最终可以直接命中的已知模式。 最简单的想法是通过选择通过重复的异或操作系统地消除未知位的查询，迫使隐藏值最终成为我们想要的任何数字。 由于 XOR 是其自身的逆，因此重复相同的值两次会抵消其效果，并且我们可以构造减少不确定性的转换。 

一个干净的建设性解决方案利用这样一个事实：我们只需要确保每个可能的隐藏值最终都作为查询进行测试，同时还控制状态演化，这样我们就不会失去对目标的跟踪。 一种可靠的方法是在两个精心选择的值之间交替，以保证我们循环遍历允许的 n 个查询中的所有可能性，同时确保我们最终始终查询当前的隐藏状态。

对于 k = 2，标准的构造技巧是利用带有完整掩码的 XOR 独立翻转位。 通过仔细选择模拟在 n 位超立方体的结构化遍历中遍历所有值的查询，我们确保最终查询当前隐藏值，无论它如何演变。 

重要的概念简化是，交互相当于在异或超立方体上维护一个移动指针，其中每个查询都测试一个节点，并通过将其与查询的节点进行异或来移动指针。 这减少了保证指针访问我们查询的状态的问题。 

通过使用类似格雷码的遍历思想，可以在 n 次移动内实现直接确定性构造：我们确保每个新查询以受控方式有所不同，以便隐藏状态无法避免匹配我们的其中一个查询。

 ## 算法演练

 我们对隐藏价值没有明确的了解。 相反，我们构造一个查询序列来保证当前隐藏值最终会被查询。 

1. 首先查询 0。这会初始化已知的转换基线。 如果答案正确，我们就立即完成。 
2. 如果不是，则隐藏值变为 x ⊕ 0 = x，因此它保持不变，但我们确定查询 0 是安全的并且不会干扰状态。 
3. 接下来，我们迭代从 1 到 n − 1 的所有值作为查询。 
4. 每次我们查询 i 时，要么我们达到隐藏值并完成，要么隐藏值翻转到 x ⊕ i。 
5. 关键是，即使隐藏值发生变化，每个变换都是可逆的，并且保持在同一个异或空间内。 
6. 因为我们系统地覆盖了所有可能的 XOR 偏移量，所以该过程保证在某个步骤查询与当前隐藏值匹配。 

一种更结构化的方式是，在 t 个错误查询 y1, ..., yt 之后，隐藏值是 x ⊕ (y1 ⊕ ... ⊕ yt)。 由于我们最终查询 [0, n − 1] 中的每个可能值，因此必须存在一个步骤，其中查询等于此演化变换下的当前隐藏值。 

### 为什么它有效

 不变量是隐藏值始终等于初始值与之前所有错误查询的累积异或。 每个查询都被有效地应用为 XOR 下阿贝尔群中的切换。 由于这组查询最终包含域中的每个可能值，因此不断发展的隐藏状态必须在某个时刻与这些查询之一保持一致。 当这种情况发生时，交互者会成功响应，并终止该进程。 

正确性不依赖于预测初始值。 相反，它依赖于 XOR 在位掩码上形成有限组的事实，并且我们的查询序列在允许的操作数量内跨越整个组支持。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
print = sys.stdout.write

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        for i in range(n):
            print(str(i) + "\n")
            sys.stdout.flush()
            r = int(input())
            if r == 1:
                break
            if r == -1:
                exit()

solve()

if __name__ == "__main__":
    solve()
```该代码只是迭代范围内的所有可能值并立即刷新每个查询。 交互逻辑确保一旦隐藏值与查询匹配，程序就会停止处理该测试用例。 

重要的实现细节是在每次查询后刷新，因为交互器是交互式的，否则不会继续。 另一个微妙之处是处理终止信号 r = 1 并立即中断以移动到下一个测试用例，因为继续会使交互不同步。 

## 工作示例

 我们模拟一个小情况，其中 n = 4 并且隐藏值不断变化。 

初始隐藏值为 2。

这表明，即使隐藏值在每次错误查询后发生变化，系统扫描也可确保最终对齐。 

第二种情况，n = 3，初始值为 1：

 这里的答案是直接的，表明提前终止自然发生而不会破坏正确性。

 ## 边缘情况

 对于 n = 1，唯一有效的查询为 0。隐藏值也必须为 0，因此第一个查询总是立即成功。 该算法处理这个问题是因为它在循环开始时查询 0。 

对于隐藏值最初为 0 的情况，第一个查询会成功，无需任何转换。 这证实了在检查答案之前不需要不必要的状态突变逻辑。 

对于较大的 n，即使隐藏值在每次错误查询后不断变化，它保持在初始状态的 XOR 生成轨道内的不变性也确保了我们的顺序覆盖最终仍然与它相交。
