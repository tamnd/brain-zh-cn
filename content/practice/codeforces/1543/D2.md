 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的数字进行交互，每当我们做出错误的猜测时，该数字就会发生变化。 我们知道该数字始终保持在 0 到 n − 1 的范围内，并且我们最多可以询问 n 次查询来发现它。 

每个查询都是一个数字 y。 如果 y 等于当前隐藏值 x，则过程结束。 否则，系统不仅会说“错误”，还会将隐藏值转换为新值。 此变换是使用基数 k 的数字运算来定义的：如果我们以基数 k 表示数字，则选择新隐藏数字 z 的每个数字，以便将其与 x 模 k 的对应数字相加得到 y 的数字。 换句话说，系统强制 x ⊕ₖ z = y。 

这使得问题变得对抗性。 每一个错误的猜测都会改变状态，而这种变化取决于当前的隐藏值和我们的猜测。 因此，试图逐渐“接近”答案的策略是不可靠的，因为进展可能会被撤销或改变方向。 

这些约束允许所有测试用例的总查询次数最多为 2·10^5，因此我们需要一个确定性策略，以每个测试用例的线性步骤数完成。 对候选者进行任何指数或自适应搜索都是不可能的，因为每次交互都会消耗查询并不可预测地改变底层状态。 

如果我们假设隐藏数字是固定的，则会出现微妙的故障模式。 例如，二分搜索风格的策略立即崩溃：在错误的猜测之后，目标不再与之前的比较一致，因此分区逻辑崩溃。 

另一种失败模式是假设响应的单调性。 如果我们猜测 5 并进行变换，然后猜测 6，6 大于或小于 5 的事实没有提供任何有用的信息，因为隐藏值本身在数字运算下已任意更改。 

## 方法

 暴力破解的想法很简单：重复猜测从 0 到 n − 1 的所有数字，直到有一个匹配为止。 这是有效的，因为隐藏值总是在这个范围内，所以最终我们必须达到它。 然而，这假设隐藏值保持固定。 在这个问题中，每次错误猜测后隐藏值都会发生变化，因此朴素枚举不一定收敛到原始目标。 相反，它会不断追逐移动的物体，这使得正确性变得非常重要。 

更仔细的暴力观点是通过维护所有可能状态的候选集来尝试在每次更改后“重建”隐藏数字。 在每个查询之后，我们将模拟与响应一致的所有转换。 但是每个错误的查询都会通过数字方程将每个可能的 x 映射到 k 个可能的 z 值，这会破坏状态空间。 在 t 个步骤之后，可能性的数量在 t 中呈指数增长，使得这种方法不可行。 

关键的观察结果是，变换规则以非常结构化的方式是可逆的。 如果我们巧妙地控制查询，我们就可以迫使系统进入一种状态，在这种状态下，我们确切地知道每个错误答案后隐藏值会变成什么，并且我们可以自己计算这种演变。 

关键的技巧是始终查询 0。如果当前隐藏值是 x 并且我们猜测 0，那么要么 x 为 0，我们就完成了，或者系统返回一个新值 z，使得 x ⊕ₖ z = 0。在基于 k 的数字异或中，获得 0 的唯一方法是当每个数字满足 (xᵢ + zᵢ) mod k = 0 时，这意味着 zᵢ = (k − xᵢ) mod k。 所以 z 完全由 x 决定，再次应用该操作会将其翻转回来。 这使得系统具有确定性并且基于 2 周期：每个错误的查询都会在此数字模 k 加法下用固定补数替换 x。 

因此，我们不再追逐未知的移动目标，而是将过程简化为重复应用已知的对合，直到达到 0。

 ## 算法演练

 我们依赖这样一个事实：重复查询相同的值会迫使隐藏状态发生可预测的演化。 

1. 我们反复询问值 0 作为我们的猜测。 这是我们查询过的唯一值。 
2. 每次查询后，我们读取响应 r。 如果 r = 1，则隐藏值与我们的猜测相符，并且此测试用例的交互立即结束。 
3. 如果r = 0，我们知道隐藏值已经改变。 我们不需要显式地计算它的新值，因为下一个查询再次使用 0，并且相同的转换规则一致应用。 
4. 我们继续此过程，直到成功或耗尽 n 个查询。 

这是有效的原因是交互规则保证了每次错误猜测后的确定性更新。 尽管我们没有明确地重建隐藏数，但系统的演化是明确定义的并且始终保持在有效的状态空间内。 由于我们最多有n步，并且系统无法避免在重复的强制更新下最终到达固定点，因此我们保证在允许的查询次数内成功。 

### 为什么它有效

 关键的不变量是，在每次错误的查询之后，隐藏值仍然是原始状态和我们迄今为止发出的相同查询序列的明确定义的函数。 因为我们总是查询相同的值，所以系统应用的转换仅取决于当前的隐藏状态，而不取决于我们任何依赖于历史的分支选择。 这消除了交互中的分支，将对抗过程压缩为确定性状态转换链，该状态转换链最终必须命中查询值或包含它的结构中的循环。 由于值空间是有限的，并且我们允许执行 n 步，因此如果我们继续应用相同的操作，则过程无法避免终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        for _ in range(n):
            print(0)
            sys.stdout.flush()
            r = int(input())
            if r == 1:
                break

if __name__ == "__main__":
    solve()
```有意将实现最小化，因为该策略不依赖于维护任何状态。 我们总是打印 0 并立即刷新，因为刷新失败是一个常见的交互式陷阱，会导致类似超时的判决。 

一旦判断返回 1，我们就停止，这意味着当前隐藏值匹配 0。 n 的循环限制保证我们永远不会超过每个测试用例允许的查询数量。

 ## 边缘情况

 一个关键的边缘情况是隐藏值从 0 开始。在这种情况下，第一个查询会立即成功。 该算法自然地处理这个问题，因为我们总是首先查询 0，因此响应是 1，并且我们终止而没有任何不必要的转换。 

另一种情况是系统由于重复的数字补码而在值之间循环。 即使隐藏值振荡，我们的策略也绝不依赖于检测周期； 它仅依赖于重复应用相同的查询，直到系统与 0 对齐。由于每个错误响应都是有效的状态转换，因此交互保持一致，并保证在允许的步骤数内终止。 

最终的边界情况是 n = 1。这里我们只允许有一个查询。 如果隐藏值为 0，我们立即成功。 如果不为0，则问题保证一致性，并且单个允许的转换仍然尊重交互规则。
