 ## 解决方案
 ## 问题理解

 我们正在寻找代表可能的果仁蜜饼层数的 9 位数字。 每个这样的数字都是有效的配置，因此搜索空间只是从 100,000,000 到 999,999,999（含）的所有整数。 

有效配置附加两个条件。 首先，如果我们反转数字的数字，得到的数字必须能被 5 整除。其次，原始数字本身必须能被给定值整除$K$，它会随着测试用例的变化而变化。 对于每个$K$，我们需要统计有多少个9位数字同时满足这两个条件。 

关于能被 5 整除的一个关键观察结果是，它仅取决于倒数的最后一位数字。 一个数能被 5 整除当且仅当其最后一位数字是 0 或 5 时。将 9 位数字反转后，最后一位数字将成为原数字的第一位数字。 由于所有有效数字都是 9 位整数，它们的第一位数字在 1 到 9 的范围内，因此反转后的数字以 0 或 5 结尾的唯一方法是原始数字以 5 开头。这将问题归结为计算以 5 开头且可被$K$。 

因此，我们正在有效地处理以下形式的数字：$$5xxxxxxx x$$其中剩余 8 位数字是空闲的。 

限制条件非常大。 测试用例的数量最多可达$10^5$，每个查询都要求一个范围内的计数，最多可达$10^8$数字。 任何超出该范围的每次查询线性扫描都是不可能的。 甚至一个$O(\sqrt{N})$或者$O(\log N)$按数量策略将会失败。 

边缘情况出现时$K$是大还是小。 如果$K = 1$，每个以 5 开头的有效 9 位数字都会被计算在内。 如果$K > 999,999,999$，根据整除结构，答案变为 0 或 1，但是强制每个候选者的整除性是不可行的。 另一个微妙的边缘情况是，推理错误地假设了范围内的均匀整除性，而不考虑倍数的对齐。 

## 方法

 蛮力方法会迭代所有 9 亿个可能的 9 位数字，检查第一个数字是否为 5，并测试整除性：$K$。 即使检查整除性是常数时间，这也大约是$10^9$每个查询的操作次数，这远远超出了限制。 

问题的结构更多的是算术而不是组合。 一旦我们限制以 5 开头的数字，我们本质上就是在考虑算术级数：$$500000000 \text{ to } 599999999$$我们需要计算这个区间内有多少个整数可以被整除$K$。 

这将问题转化为经典的倍数范围计数问题。 我们不是枚举值，而是计算有多少个倍数$K$使用前缀除法位于闭区间内：$$\text{count} = \left\lfloor \frac{R}{K} \right\rfloor - \left\lfloor \frac{L-1}{K} \right\rfloor$$被 5 整除的约束已经被吸收到区间限制中，因此不需要额外的过滤。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(10^9)$每个查询|$O(1)$| 太慢了|
 | 最佳 |$O(1)$每个查询|$O(1)$| 已接受 |

 ## 算法演练

 1. 将有效数字的范围限制为反转形式以 0 或 5 结尾的数字。这迫使原始数字以数字 5 开头，因此我们定义区间$[L, R] = [500000000, 599999999]$。 这通过将数字反转条件转换为数字本身的结构约束来完全消除数字反转条件。 
2. 对于每个测试用例，读取整数$K$，它定义了原始数字的整除条件。 任务变成计算有多少个数字$[L, R]$可以被整除$K$。 
3. 计算有多少个倍数$K$小于或等于$R$使用整数除法$R // K$。 这给出了上限的有效倍数的总数。 
4. 计算有多少个倍数$K$严格小于$L$使用$(L-1) // K$。 这会删除所有低于该区间的无效倍数。 
5. 将两个值相减以获得范围内有效倍数的数量。 这直接对应于该有效果仁蜜饼配置的数量$K$。 

### 为什么它有效

 每个有效配置恰好对应于区间中的一个整数$[500000000, 599999999]$。 整除条件为$K$将整数划分为不相交的算术级数$K$。 计算一个区间中有多少个元素位于这样的级数中完全由边界对齐决定，因此地板划分公式是精确的，并且避免了过多计算或遗漏边缘元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

L = 500_000_000
R = 599_999_999

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())
        if k == 0:
            print(0)
            continue
        ans = R // k - (L - 1) // k
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案在开始时修复一次有效的 Universe，这避免了为每个查询重新计算边界。 然后，每个查询减少为两次整数除法和一次减法。 

一个微妙的点是处理$K = 0$，尽管约束通常会阻止它。 该保护确保了鲁棒性，但从逻辑上讲，这种情况会贡献零个有效数字，因为被零整除是未定义的。

 ## 边缘情况

 一个棘手的情况是当$K$大于上限$R = 599999999$。 例如，如果$K = 10^9$， 两个都$R // K$和$(L-1) // K$为零，产生零答案。 该算法自然地处理这个问题，无需特殊的分支。 

另一种情况是当$K = 1$。 那么区间内的每个数字都是有效的。 公式给出：$$599999999 - 499999999 = 100000000$$与以 5 开头的 9 位数字完全匹配。 

最后，当$K$将边界附近的值相除，例如$K = 500000000$，该区间恰好包含一个倍数，即 500000000 本身。 减法正确地保留了边界点的包含，确认了边缘的正确性。
