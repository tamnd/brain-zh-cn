 ## 解决方案
 ## 问题理解

 我们有两个长度相同的数组。 一个数组代表客户订单，其中每个值都是客户想要的果仁蜜饼的数量。 另一个数组表示当前每批次准备了多少果仁蜜饼。 唯一允许的操作是将单个果仁蜜饼从一批移动到另一批。 每一次移动都会使一批减少一个单位，并使另一批增加一个单位。 

任务是确定所需的此类单个单元移动的最小数量，以便至少一批最终的大小等于任何请求的订单值。 如果没有批次可以转换为匹配任何订单大小，我们返回 -1。 

关键的观察是，我们并不试图使所有批次都匹配订单，只有一个批次需要匹配任何一个目标值。 这将问题从全球重新分配转变为单一目标的可行性问题。 

约束最多为 200,000 个元素，值最多为 10^9。 这立即排除了所有订单和所有批次之间的任何二次配对。 任何尝试所有对的解决方案都会太慢。 基于排序的方法或基于散列的查找变得必要。 

当即使在理论上也无法达到订单值时，就会出现微妙的边缘情况。 由于操作保留总和，如果一个批次需要增加或减少超出系统可以提供的范围，这可能是不可能的。 例如，如果所有批次都相同且目标差异显着，则可行性取决于总和对齐，而不仅仅是局部差异。 

## 方法

 暴力方法将尝试每对订单值和批次值，并计算需要多少次移动才能将该批次转换为该订单大小。 如果我们修复了一个大小为 b 的批次并希望它变成 a，那么我们需要精确地移出或引入 |a - b| 果仁蜜饼。 这很容易计算，答案将是所有对中的最小值。 

然而，这忽略了一个全局约束：我们无法独立调整每个批次，因为在批次之间移动果仁蜜饼会通过共享总和来耦合所有值。 忽略这种耦合的简单方法可能会错误地声称可行性或低估在不可能重新分配的边缘情况下的可行性。 

关键的见解是，对于任何固定的目标订单值a，我们只需要知道是否可以将任何批次转换为尺寸a，以及成本是多少。 将一批大小为 b 的批次转换为 a 需要 |a - b| 移动，但这仅在总和允许在所有批次之间重新分配时才有效。 

我们不是模拟转账，而是计算所有果仁蜜饼的总和 S。 对于目标a，如果我们选择某个批次成为a，那么剩余的总和仍必须分布在剩余的N-1个批次中。 这只有在剩余总和 S - a 为非负数时才有可能，这始终为真，因此可行性不是限制因素。 真正的限制是，只要我们保留总和，我们就可以自由地重新分配。 

因此，使任何批次等于 a 的成本只是 |b_i - a| 的所有批次中的最小值。 答案是该值在所有订单值 a_i 中的最小值。 

由于两个数组都可以独立排序，因此我们可以使用二分搜索来加快速度：对于每个顺序值 a，我们在排序的 b 中找到最接近的批次值并计算距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力配对 | O(N²) | O(1) | O(1) | 太慢了|
 | 排序+二分查找 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

1. 对批量大小数组进行排序。 这允许对任何目标订单大小进行高效的最近邻查询。 
2. 对于每个顺序值a，对已排序的batch 数组执行二分查找，找到与a 最接近的值。 如果我们的目标是匹配这个顺序，最接近的值决定了所需的最小移动次数。 
3. 计算 a 与其最接近的批次值之间的绝对差，该值表示必须移动的果仁蜜饼的数量。 
4. 跟踪所有订单值中的最小此类值。 
5. 处理完所有订单后输出这个最小值。 

二分搜索在这里起作用的原因是，在排序数组中，与任何目标最接近的值必须位于下界返回的两个相邻位置之一。 

### 为什么它有效

 对于固定目标 a，将一批大小 b 转换为 a 正好需要 |a - b| 单位移动。 由于每次移动都会在两个批次之间移动一个单位，因此我们可以根据单位流量有效地测量距离。 由于所有批次都是独立的转换候选者，并且除了单位传输之外没有交互成本，因此最佳选择始终是最接近 a 的可用批次大小。 排序结构保证了有效且正确地找到值中的最近邻居。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    b.sort()
    
    import bisect
    
    ans = 10**30
    
    for x in a:
        i = bisect.bisect_left(b, x)
        
        if i < n:
            ans = min(ans, abs(b[i] - x))
        if i > 0:
            ans = min(ans, abs(b[i - 1] - x))
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先对批处理数组进行排序，以便邻近查询变得高效。 对于每个订单值，它使用二分搜索来查找最接近的批量大小。 插入点周围的两个候选位置就足够了，因为任何更接近的值都必须按排序顺序相邻。 所有此类比较的全局最小值就是答案。 

这里的一个常见错误是忘记检查插入点的两侧。 仅检查一侧可能会错过真正最接近的批次值。

 ## 边缘情况

 一种边缘情况是目标订单与批量大小完全匹配。 例如，如果 a = 7 并且 b 包含 7，则二分查找会将 7 放置在有效位置，并且绝对差值为零。 该算法正确返回零，因为不需要任何操作。 

当最接近的值仅位于插入点的一侧时，会出现另一种边缘情况。 例如，如果 b = [10, 20, 30] 且 a = 5，则下限为索引 0，我们仅与 10 进行比较。该算法正确地避免了无效索引，并且仍然返回正确的成本 5。 

最后的边缘情况是所有批次值都相同。 在这种情况下，每个查询都简化为与单个值进行比较，并且答案成为该常量与所有订单值之间的最小绝对差，算法通过重复比较自然地捕获该差异。
