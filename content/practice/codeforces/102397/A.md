 ## 解决方案
 ## 问题理解

 巴沙尔想买的正是`x`沙威玛三明治。 每个三明治的价格正好是 2 JD，因此所需的金额是一个三明治的价格乘以三明治的数量。 

输入包含一个整数`x`，代表巴沙尔想要购买的三明治数量。 输出应包含以 JD 为单位的总成本。 

约束条件`1 <= x <= 30`使问题变得非常小。 即使每个三明治执行一次添加的循环也最多需要 30 次迭代，这在 1.5 秒的时间限制内是微不足道的。 更重要的是，每个三明治的固定价格意味着无需检查单个三明治或保持任何复杂的状态。 答案直接由`x`。 

不存在涉及零的困难边界情况，因为最小允许值为 1。例如，输入`1`，正确的输出是`2`，因为巴沙尔买了一个三明治。 一个不小心导致意外打印的解决方案`x`会产生`1`，混淆了三明治的数量和总价。 

在另一个边界处，输入`30`需要`60`JD。 仅执行一次与错误价格相乘的解决方案，或者意外地将上限视为 29，将产生不正确的结果。 因为答案总是恰好两次`x`，两个边界都由相同的公式处理。 

## 方法

 直接的暴力方法将从零总成本开始，并为每个三明治添加 2 个 JD。 这是正确的，因为每次迭代只考虑一个三明治，所以之后`x`迭代次数累计量为`2 + 2 + ... + 2`， 和`x`2 的副本。在最大输入值时，这仅执行 30 次加法，因此对于给定的约束来说它已经足够快了。 

蛮力方法之所以有效，是因为输入很小，但没有必要。 关键的观察结果是每次迭代都会添加相同的固定量，即 2 个 JD。 重复添加相同的值`x`时间正好乘以`x`。 因此整个循环可以用表达式替换`2 * x`。 

在规定的约束下，暴力方法没有有意义的性能故障点，因为 30 次迭代可以忽略不计。 最优解仍然更可取，因为它直接表达了数学结构并将实现简化为单个乘法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(x)，至多 O(30) | O(1) | O(1) | 已接受，但没有必要 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`x`，巴沙尔想要购买的沙威玛三明治数量。 这是唯一需要的值，因为每个三明治的价格都相同。 
2. 乘法`x`经过`2`。 每个三明治正好贡献 2 JD，因此将三明治的数量乘以固定价格即可得出总成本。 
3. 打印结果值。 不需要舍入、除法或额外的处理，因为三明治的价格和数量都是整数。 

### 为什么它有效

 总价是每个三明治价格的总和。 由于每个`x`三明治的价格正好是 2 JD，总和是`2 + 2 + ... + 2`和`x`条款。 根据乘法的定义，这个和等于`2 * x`。 该算法精确计算该值，因此打印的答案始终是所需的总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x = int(input())
print(2 * x)
```一线进口`sys`， 和`input`被分配给`sys.stdin.readline`作为竞争性编程的标准快速输入模式。 输入仅由一个整数组成，因此不需要特殊的解析逻辑。 

读入的值`x`代表三明治的数量。 表达式`2 * x`直接实现总成本的数学公式。 

不存在相差一的问题，因为计算不使用循环或索引。 Python 中也不存在整数溢出问题，即使在给定的约束下，最大可能的结果也只是`60`。 

然后程序打印结果，后跟换行符，这正是所需的输出格式。

 ## 边缘情况

 对于最小输入，确切的输入是`1`。 算法读取`x = 1`，计算`2 * 1 = 2`，并打印`2`。 一个常见的错误是直接打印输入，这会将三明治的数量与所需的金额混淆。 

对于最大输入，确切的输入是`30`。 该算法计算`2 * 30 = 60`和打印`60`。 由于计算没有循环边界，因此不存在意外只处理 29 个三明治的可能性。 

价值`2`对于发现对价格的误解也很有用。 有输入`2`，巴沙尔买了两个三明治，需要的数量是`2 + 2 = 4`，所以正确的输出是`4`。 该公式恰好产生该值。 

中间值，例如`15`给出`30`JD。 这证实了该解决方案不依赖于任一端点的特殊情况，并且相同的固定价格关系适用于整个有效输入范围。
