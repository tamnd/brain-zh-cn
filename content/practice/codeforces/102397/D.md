 ## 解决方案
 ## 问题理解

 有`n`房子排成一排，房子`i`包含`a[i]`硬币。 巴沙尔可以选择任何房子作为他的起点，也可以选择任何房子作为他的终点。 当他在他们之间行走时，他参观了该路段上的每一栋房子并收集了所有的硬币。 

任务是找到收集至少所需的最小步行距离`x`硬币。 如果所选航段从自家开始`l`并在房子结束`r`，其步行距离为`r - l`，因为相邻的房屋相距一个单元。 如果没有段包含足够的硬币，答案是`-1`。 

输入包含`x`和`n`，随后是`n`硬币价值。 约束条件有`n <= 1000`，所以即使是一个`O(n^2)`算法最多执行约 50 万个段检查，这很容易管理。 小约束使得暴力解决方案成为可能，但问题的结构也允许`O(n)`解决方案。 

事实是每一个`a[i]`为正是关键属性。 在一个段中添加另一栋房屋只能增加其总数，而从左侧删除一座房屋只能减少其总数。 这种单调行为使我们能够保持移动间隔，而无需重新考虑每对可能的端点。 

有几种边界情况可能会导致错误的实现以静默方式返回错误的距离。 例如，如果一所房子已经包含足够的硬币```
5 1
5
```答案是`0`，因为巴沙尔可以在同一个房子开始和停止。 至少将答案初始化为的实现`1`会错的。 

第二种情况是整个数组仍然不够：```
6 5
1 1 1 1 1
```总计仅`5`，所以正确的输出是`-1`。 粗心的滑动窗口实现可能会使其初始答案保持不变并打印无效距离。 

第三种情况测试距离与房屋数量的关系。 为了```
7 3
2 5 1
```包含前两栋房屋的部分有`7`硬币。 它有两栋房子，但巴沙尔只从房子里走出来`1`到房子`2`，所以答案是`1`， 不是`2`。 

## 方法

 直接的方法是尝试每一种可能的起始房屋并将最终房屋一次延伸一个位置。 对于每对端点，我们可以计算或维护总和并检查它是否达到`x`。 有`n(n+1)/2`连续的段，所以最坏的情况大致是`500,500`分段时`n = 1000`。 通过前缀和，可以在恒定时间内检查每个段，给出`O(n^2)`算法。 它是正确的，因为明确考虑了每个可能的区间，并选择了最小的有效区间。 

暴力方法之所以有效，是因为答案保证是连续的段之一。 然而，它做了不必要的工作，因为许多间隔重叠。 如果一个区间`[l, r]`已经有足够的硬币了，再向右延伸并不能提高步行距离。 更重要的是，由于所有币值都是正数，一旦窗口达到所需的总和，我们就可以安全地将其左边界向前移动，看看它是否可以变得更短。 

这给出了滑动窗口解决方案。 我们维护一个窗口`[left, right]`及其当前硬币总数。 作为`right`继续前进，我们将新房子添加到窗口。 每当总和至少为`x`，当前窗口是有效的，因此我们记录它的距离，并在窗口保持有效的情况下重复从左侧移除房屋。 此过程仅检查每栋房屋固定次数，从而将复杂性降低到`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 因简单的限制而被接受|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化`left = 0`,`current_sum = 0`， 和`answer = n`作为一个大于每个可能的步行距离的值。 窗户将代表来自`left`通过当前的右端点。 
2. 移动`right`从`0`通过`n - 1`。 添加`a[right]`到`current_sum`，因为新的右端点刚刚进入活动窗口。 
3.同时`current_sum >= x`，当前窗口已经包含足够的硬币。 其步行距离为`right - left`，所以更新`answer`当前答案和这个距离中较小的一个。 
4. 删除`a[left]`从`current_sum`并增加`left`。 这试图使有效窗口更短。 我们继续这样做，而剩余的窗口仍然至少包含`x`硬币。 
5. 处理完所有可能的右端点后，检查是否`answer`已更新。 如果没有，则没有到达连续的段`x`，所以打印`-1`; 否则打印`answer`。 

我们可以永久丢弃旧左端点的原因是所有硬币值都是正值。 一次`[left, right]`有足够的金币，保留`left`延伸时固定`right`永远不可能产生比我们已经找到的间隔更短的间隔。 移动`left`前进是提高距离的唯一途径。 

### 为什么它有效

 在每一个点上，`current_sum`正好是当前窗口中房屋的总和`[left, right]`。 每当该金额达到`x`，窗口有效，我们记录它的距离。 然后我们移动`left`在保持有效性的同时尽可能向前推进，因此对于这个特定的`right`，所得窗口是结束于的最短有效窗口`right`。 每个可能的右端点都会被处理，因此必须考虑全局最短的有效段。 由于所有值都是正数，因此在右端点向前移动后，丢弃的左端点以后不会变得有用，这就是使单遍算法正确的原因。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, n = map(int, input().split())
    a = list(map(int, input().split()))

    left = 0
    current_sum = 0
    answer = n

    for right in range(n):
        current_sum += a[right]

        while current_sum >= x:
            answer = min(answer, right - left)
            current_sum -= a[left]
            left += 1

    if answer == n:
        print(-1)
    else:
        print(answer)

if __name__ == "__main__":
    solve()
```第一行读取所需的硬币数量和房屋数量。 然后存储该数组，以便滑动窗口可以在恒定时间内从其左边界删除值。 

主循环添加`a[right]`正是在房子的时候`right`进入窗口。 内部`while`循环仅在当前段有足够的硬币时运行。 移除前`a[left]`，我们记录当前距离`right - left`，这是两个端点房屋之间的距离。 

这里的顺序很重要。 在移除最左边的房子之前，我们必须评估有效的窗口。 否则，可以跳过一屋解决方案。 例如，如果`a[left] >= x`，正确的距离是`0`，并且必须在房屋拆除之前记录该价值。 

最初的答案是`n`。 最大可能距离是`n - 1`， 所以`n`安全地超出了真实答案的范围。 扫描后，值不变意味着未找到有效窗口。 

Python 整数不会溢出，最大可能总数仅为`1000 * 1000 = 10^6`反正。

所述示例解释描述了从第二个房子走到第四个房子，这对应于最后一个窗口。 因此答案是`2`根据距离的定义，房屋位置之间的差异。 所提供的语句显示的示例输出在提示中已损坏，但所描述的移动的预期结果是`2`。

这个例子说明了为什么该算法不会盲目缩小窗口。 它只在记录当前有效间隔后才删除最左边的房子，并且一旦删除另一房子导致总和太小，它立即停止。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) |`right`进步`n`次，同时`left`最多也进步`n`次。 |
 | 空间| O(n) | 输入数组被存储； 滑动窗口状态本身使用 O(1) 额外空间。 |

 和`n <= 1000`，这完全在给定的范围内。 即使二次解也适合简单的约束，但一旦识别出正值属性，线性解就会更简单，并且也可以自然地扩展到更难的版本。

 ## 边缘情况

 包含足够硬币的单个房屋必须产生距离`0`。 为了```
7 1
7
```该算法将唯一的值相加，发现总和至少为`7`, 记录`right - left = 0`，然后移除那所房子。 最终的答案是`0`。 

如果黄金总量不足，则任何窗口都不会进入收缩循环。 为了```
6 5
1 1 1 1 1
```最终总和仅达到`5`， 所以`answer`保持等于其初始值`n`。 算法打印`-1`。 

有效窗口可以出现在数组的最末尾。 为了```
7 4
1 1 4 3
```最后两栋房子包含`4 + 3 = 7`。 什么时候`right = 3`，窗口最终缩小到`[2, 3]`，记录的距离为`3 - 2 = 1`。 这会捕获在处理最终房屋之前意外停止的实现。 

该距离比一段中的房屋数量少一。 为了```
10 4
1 2 3 4
```所有四栋房子都是必需的，因为它们的总数正好是`10`。 算法记录`right - left = 3`， 不是`4`。 这种区别至关重要，因为巴沙尔在房屋之间行走，而不是数房屋本身。 

最后，必须将完全匹配视为有效。 为了```
9 5
2 3 4 1 1
```前三栋房子正好包含`9`硬币，所以算法记录距离`2`。 使用`>`而不是`>=`会错误地拒绝该段，并且是滑动窗口实现中的常见边界错误。
