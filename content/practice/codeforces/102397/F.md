 ## 解决方案
 ## 问题理解

 有`n`纸杯蛋糕放在桌子上，马哈茂德迈出了第一步。 在每一回合中，当前玩家只能吃一个纸杯蛋糕。 如果当前纸杯蛋糕的数量是偶数，玩家还可以选择吃掉其中的一半。 恰好面对一个纸杯蛋糕的玩家立即失败，因此游戏在回合开始时结束`1`。 

任务是当两个玩家都选择最佳动作时确定哪一个玩家获胜。 输入包含一个整数`n`，代表纸杯蛋糕的初始数量。 输出是`Mahmoud`如果第一个玩家有获胜策略并且`Bashar`否则。 

约束条件`n <= 10^9`是关键难点。 检查每个值的解决方案`1`通过`n`需要多达 10 亿个状态，这远远超出了 1.5 秒的时间限制所能支持的。 甚至一个`O(n)`动态程序在这里太慢了。 我们需要将游戏简化为恒定时间属性`n`。 

最小的状态揭示了几种可能欺骗直接实现的边缘情况。 为了`n = 1`，Mahmoud 立即失败，因为起始位置已经包含一个纸杯蛋糕，所以正确的输出是`Bashar`。 第一次尝试采取行动的粗心实现会错误地将其视为正常的游戏状态。 

为了`n = 2`, 马哈茂德可以吃一块纸杯蛋糕然后离开`1`，所以巴沙尔输了，答案是`Mahmoud`。 这里也存在半操作，但它产生相同的状态，这意味着假设半操作总是有意义的不同的实现可能会错误地处理这个边界。 

为了`n = 3`，马哈茂德只能吃一个纸杯蛋糕，离开`2`。 巴沙尔随后离开`1`，所以马哈茂德输了。 正确的输出是`Bashar`。 这是继之后最小的奇数亏损头寸`1`对于捕获仅检查是否存在的解决方案很有用`n`大于一。 

为了`n = 4`，正确答案是`Mahmoud`。 马哈茂德可以吃一块纸杯蛋糕然后离开`3`。 巴沙尔随后被迫离开`2`，马哈茂德离开`1`。 关键是Mahmoud不需要使用half运算。 始终选择的解决方案`n / 2`如果可能的话，可能会产生错误的获胜者。 

## 方法

 一种直接的方法是将每个数量的纸杯蛋糕分类为获胜或失败。 如果每一次合法的举动都给对手带来了获胜的位置，那么这个位置就是失败的。 如果至少有一个合法的举动给对手带来了失败的局面，那么它就获胜了。 开始于`1`作为失败，我们可以计算答案`2, 3, ..., n`。 

这个动态程序是正确的，因为每一步都是从`x`导致较小的数字，要么`x - 1`或者`x / 2`。 因此，当我们处理`x`，每个可能的目的地的结果都是已知的。 然而，它需要检查最多`n`州。 为了`n = 10^9`，这意味着大约 10 亿次状态评估，并且检查可用的转换可以使工作接近 20 亿次转换检查。 内存要求也是`O(n)`如果整个表都被存储了。 

暴力计算之所以有效，是因为游戏图总是向较小的数字移动，但它会失败，因为上限太大。 解锁更快解决方案的观察来自于观察位置的奇偶性。 位置`1`正在失去。 每个大于的奇数`1`只有一种可能的移动，从`x`到`x - 1`，这是偶数。 每个偶数都有一个移动`x - 1`，这很奇怪。 如果所有奇数位置都输了，而所有偶数位置都赢了，那么对于每个更大的数字，这种关系都会重现。 

因此，奇数位置会失败，因为它唯一的移动会导致偶数获胜位置。 偶数位置获胜，因为吃一个纸杯蛋糕会导致奇数失败位置。 半操作不会干扰这种分类：当偶数减半时，结果可以是偶数或奇数，但偶数位置已经有获胜的棋步`n - 1`，所以额外的一步不能让它输。 

因此，整个游戏仅取决于纸杯蛋糕的初始数量是奇数还是偶数。 如果`n`势均力敌，马哈茂德获胜。 如果`n`奇怪的是，巴沙尔获胜。

 ## 算法演练

 1.读取纸杯蛋糕的初始数量`n`。 推导游戏模式后我们需要的唯一属性是它的奇偶性。 
2.如果`n`为偶数，输出`Mahmoud`。 势均力敌的一方获胜，因为马哈茂德只能吃掉一个纸杯蛋糕然后离开`n - 1`，这很奇怪，因此下一个玩家会输。 
3.如果`n`为奇数，输出`Bashar`。 马哈茂德只能从奇数开始移动`n`到偶数`n - 1`，并且均匀的位置对于收到它的玩家来说是获胜的。 
4. 特殊情况`n = 1`已经被奇怪的情况覆盖了。 Mahmoud 从一个纸杯蛋糕开始，输了，所以输出是`Bashar`。 

### 为什么它有效

 不变量是，每个奇数个纸杯蛋糕都是失败的位置，每个偶数个纸杯蛋糕都是获胜的位置。 基本情况`1`正在失去。 对于一个奇怪的`n > 1`，唯一合法的举动是`n - 1`，这是均匀的，因此对手获胜。 因此，奇怪的位置正在丢失。 对于一个均匀的`n`，吃一个纸杯蛋糕移动到`n - 1`，这是奇数，因此对手输了，所以偶数位置获胜。 这证明了每个正整数的分类，包括最大范围`10^9`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

if n % 2 == 0:
    print("Mahmoud")
else:
    print("Bashar")
```输入由一个整数组成，因此一次调用`input()`就足够了。 我们将其转换为整数并检查`n % 2`。 

偶数枝印`Mahmoud`因为马哈茂德总是可以拿走一个纸杯蛋糕并留下一个奇怪的失败位置。 奇怪的分支印记`Bashar`，包括边界情况`n = 1`。 

无需模拟走法、构造动态规划表或使用递归。 Python 整数可以轻松地表示给定值，尽管即使是固定宽度的 32 位有符号整数也足以满足`10^9`。 模运算不存在差一问题，因为失败条件恰好是奇校验，包括`1`。

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    if n % 2 == 0:
        print("Mahmoud")
    else:
        print("Bashar")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("4\n") == "Mahmoud", "sample 1"
assert run("3\n") == "Bashar", "sample 2"

# Minimum-size input
assert run("1\n") == "Bashar", "n = 1 is immediately losing"

# Smallest even input
assert run("2\n") == "Mahmoud", "n = 2 is winning"

# Odd boundary
assert run("999999999\n") == "Bashar", "large odd input"

# Maximum-size input
assert run("1000000000\n") == "Mahmoud", "maximum even input"

 ## 边缘情况

 对于`n = 1`，算法采用奇数分支并打印`Bashar`。 不尝试任何移动，这正确地模拟了回合开始时拥有一个纸杯蛋糕的玩家失败的规则。 

为了`n = 2`，该算法采用偶数分支并打印`Mahmoud`。 马哈茂德可以吃一个纸杯蛋糕，产生`1`对于巴沙尔来说。 这也说明了为什么解决方案不能将半操作视为强制操作。 无论马哈茂德考虑吃一份还是一半，这个职位仍然对他有利。 

为了`n = 3`，算法采用奇数分支并打印`Bashar`。 马哈茂德只能搬到`2`，这是巴沙尔的胜利。 巴沙尔随后移至`1`，让马哈茂德处于失败的终端位置。 

为了`n = 4`，该算法采用偶数分支并打印`Mahmoud`。 获胜的举动是`4 -> 3`。 自从`3`正在输，马哈茂德已经制定了必胜策略。 半个动作`4 -> 2`无关紧要，因为获胜位置只需要一步获胜动作。 

对于最大输入`n = 10^9`，数字是偶数，因此程序打印`Mahmoud`经过一次奇偶校验后。 没有循环取决于大小`n`，这正是解在最大允许输入下保持恒定时间的原因。
