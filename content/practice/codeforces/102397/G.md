 ## 解决方案
 ## 问题理解

 每个玩家拥有一个长度数组`n`。 对于固定目标总和`k`, 一对位置`(i, j)`很好，当`i < j`这两个值加起来是`k`。 我们需要独立地计算 Mahmoud 数组和 Bashar 数组中的好对，然后比较两个计数。 拥有更多好对的玩家获胜，而相同数量的玩家则为平局。 

订单条件`i < j`意味着在计数对时位置很重要。 例如，在`[1, 2]`和`k = 3`，正好有一对好。 在`[1, 2, 1]`，有两对好对，`(1, 2)`和`(2, 3)`。 我们计算的是成对的位置，而不仅仅是不同的值组合。 

数组长度可以达到`10^5`，因此检查每对位置的算法将执行大约`n(n-1)/2`检查。 最大尺寸是`4,999,950,000`配对检查，远远超出了大约 1.5 秒的竞争性编程限制所能支持的范围。 我们需要一个工作量近似线性增长的解决方案`n`。 

值本身也受到以下限制`10^5`，但我们实际上并不需要迭代每个可能的值。 处理数组时有用的信息是每个值之前出现的次数。 

一些边缘情况很容易破坏粗心的实现。 首先，一个值可以与其自身配对。 例如：```
1 2
1
1
```只有一个位置，所以正确的结果是`Draw`，不是一对数。 更一般地，对于`[1, 1]`和`k = 2`，两个相等的值恰好形成一对，因为位置`(1, 2)`是不同的。 

其次，相同的值不得计算两次。 为了`[1, 2]`和`k = 3`，这对值`1`和`2`是一对，而不是两对。 基于频率的解决方案可同时计算`cnt[1] * cnt[2]`和`cnt[2] * cnt[1]`如果不限制处理哪个补集，则会将其计算两次。 

第三，必须尊重岗位顺序。 为了`[2, 1]`和`k = 3`，这对`(1, 2)`仍然有效，因为第一个位置包含`2`第二个包含`1`。 这些值不需要按递增的数字顺序出现。 重要的是第一个位置在第二个位置之前处理。 

最后，对的数量可以远大于`n`。 和`n = 100000`，仅包含与其自身配对的值的数组可以包含`4,999,950,000`好对。 在具有固定宽度整数的语言中，32 位整数会在这样的结果上溢出，因此计数变量必须使用足够大的整数类型。 Python 整数会自动处理这个问题。 

## 方法

 直接解完全遵循定义。 对于每个职位`i`，我们检查每个后面的位置`j`并测试是否`a[i] + a[j] == k`。 每个有效对都只计算一次，因为我们只考虑`j > i`。 这立即给出了正确答案，但是有`n(n-1)/2`配对进行检查。 什么时候`n = 100000`， 那是`4,999,950,000`检查，使该方法无法使用。 

条件的结构为我们提供了更好的计数方法。 假设我们当前正在处理一个值`x`。 当前一个值是时，前一个位置恰好与其形成良好的配对`k - x`。 我们不需要单独了解各个位置。 我们只需要知道有多少次`k - x`已经出现了。 

这导致了单通频率方法。 维持`seen[v]`, 值出现的次数`v`已处理的位置中。 当当前值为`x`，正好有`seen[k - x]`较早的位置与其形成良好的配对。 将该数字添加到答案中，然后增加`seen[x]`。 

订购条件`i < j`通过从左到右处理数组来自然地处理。 当遇到第二个端点时，每对都会被计数。 这也自动解决了等值情况。 如果`x == k - x`，仅计算之前的出现次数，因此出现次数永远不会与自身配对。 

相同的过程独立地应用于两个阵列。 然后我们比较他们的两个计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 频率计数 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和目标总和`k`，其次是马哈茂德和巴沙尔的阵列。 
2. 要计算一个数组中的好对，请创建一个频率图`seen`包含到目前为止遇到的值。 最初它是空的，因为没有处理任何位置。 
3. 从左到右处理数组。 对于当前值`x`，将其所需的伙伴计算为`k - x`。 
4. 添加`seen[k - x]`到答案。 那里记录的每个出现都属于较早的位置，因此每个出现都与当前位置恰好创建一对有效的对。 
5. 增加`seen[x]`一个。 当前位置必须可用作所有后续元素的前一个位置，但不得用于与自身配对。 
6. 对 Bashar 数组重复相同的计数过程。 
7. 比较两对计数。 如果 Mahmoud 的计数更大，则打印`Mahmoud`。 如果 Bashar 的计数更大，则打印`Bashar`。 否则，打印`Draw`。 

### 为什么它有效

 处理完数组的任意前缀后，`seen[v]`等于该前缀中的位置数，其值为`v`。 当处理下一个值时`x`，每个在当前位置结束的好对必须有一个更早的值等于`k - x`，并且正好有`seen[k - x]`这样的职位。 因此，该算法将每个新完成的好对恰好添加一次。 因为当前值被插入到`seen`只有在计算了其伙伴后，一个位置才不能与自身配对。 由于每一对都有一个较晚的端点，因此每一对都被计数一次且仅一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_pairs(arr, k):
    seen = {}
    pairs = 0

    for x in arr:
        pairs += seen.get(k - x, 0)
        seen[x] = seen.get(x, 0) + 1

    return pairs

def solve():
    n, k = map(int, input().split())
    mahmoud = list(map(int, input().split()))
    bashar = list(map(int, input().split()))

    mahmoud_pairs = count_pairs(mahmoud, k)
    bashar_pairs = count_pairs(bashar, k)

    if mahmoud_pairs > bashar_pairs:
        print("Mahmoud")
    elif bashar_pairs > mahmoud_pairs:
        print("Bashar")
    else:
        print("Draw")

if __name__ == "__main__":
    solve()
```这`count_pairs`函数实现了算法中从左到右的不变量。`seen[x]`存储有多少个较早的位置包含`x`， 尽管`pairs`存储两个端点已被处理的好对的数量。 

查找`seen.get(k - x, 0)`当所需的补数尚未出现时为零。 这避免了必须为每个可能的值初始化频率数组，尽管大小固定的数组`100001`也可以工作，因为输入值是有界的。 

循环内两条语句的顺序至关重要。 我们数数`seen[k - x]`增加之前`seen[x]`。 如果增量首先发生，那么当`x == k - x`，当前位置将被错误地算作其自己的伙伴。 

Python 的任意精度整数还可以处理最大可能的对计数而不会溢出。 不需要特殊处理`x == k - x`，因为当前值的频率仅包含较早的位置。 

这两个数组是单独计算的，因此 Mahmoud 数组中的出现次数永远不会与 Bashar 数组中的出现次数交互。

        finally:

 ## 边缘情况

 当数组仅包含一个元素时，不能有一对，因为需要两个不同的位置。 例如：```
1 2
1
1
```计数循环看到`1`，寻找`1`在以前的位置中，找到零个出现的位置，然后才记录当前的位置`1`。 两个数组都接收零对，所以答案是`Draw`。 

当一个值是它自己的补码时，算法必须对不同出现的值之间的对进行计数，而不将出现的值与自身配对。 考虑：```
2 2
1 1
1 1
```对于第一个`1`,`seen[1]`为零，因此贡献为零。 插入后，第二个`1`查找上一个`1`并贡献一对。 两名玩家都恰好有一对，产生`Draw`。 查找和插入的顺序是正确的。 

当值处于输入范围的极限时，仍然可以处理所需的补码，无需特殊情况。 考虑：```
2 100001
1 100000
1 1
```Mahmoud 的第二个值是`100000`，其补集是`1`。 早一点`1`存在，所以 Mahmoud 得到了一双好鞋。 巴沙尔没有`100000`，所以它变为零。 结果是`Mahmoud`。 

当相同的值出现多次时，即使算法本身保持线性，对的数量也会呈二次方增长。 为了：```
4 10
5 5 5 5
5 5 5 4
```马哈茂德有`C(4, 2) = 6`很好的配对，因为每两个不同`5`头寸总和为`10`。 巴沙尔有`C(3, 2) = 3`这样的对。 该算法增量地生成这些计数：`0 + 1 + 2 + 3`和`0 + 1 + 2`，分别给出`Mahmoud`。 

最后，最大数组大小可以产生近 50 亿个良好对。 和`100000`的副本`1`和`k = 2`，每对都很好，给予`100000 * 99999 / 2 = 4,999,950,000`对。 该算法仍然只执行`100000`该数组的迭代，而 Python 的整数算术安全地存储结果计数。
