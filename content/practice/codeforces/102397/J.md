 ## 解决方案
 ## 问题理解

 我们有`n`解决方案文件，并且每个文件恰好占用`x`GB。 单个闪存最多可容纳`a`GB，并且文件必须完全保留在一个内存中。 目标是找到存储所有内容所需的最少闪存数量`n`文件。 

关键的数量不是一个内存的总存储量，而是它能容纳多少个完整的文件。 由于每个文件的大小相同，因此一个内存可以准确存储`floor(a / x)`文件。 一旦知道这个数字，问题就变成了需要多少个该大小的组来包含所有`n`文件。 

约束条件`n <= 10^5`这意味着即使是线性算法也能在 1.5 秒的限制下轻松达到足够快的速度。 然而，问题的结构比一般的包装问题简单得多，因此我们可以在常数时间内解决它。 的界限`x`和`a`对于普通整数运算来说也足够小，并且 Python 整数在这里不存在溢出问题。 

有几种边界情况可能会暴露出不正确的实现。 考虑`1 5 5`。 一个文件正好占满一个内存，所以答案是`1`。 粗心的实现使用严格的不平等而不是允许平等可能会错误地拒绝文件。 

另一个重要案例是`5 2 5`。 每个记忆都承载着`floor(5 / 2) = 2`文件，因此需要三个存储器。 正确的输出是`3`。 只需将总文件大小除以内存容量即可得出`ceil(10 / 5) = 2`，这是错误的，因为每个内存中未使用的 1 GB 无法组合起来存储文件。 

最后，当`x = a`， 例如`4 7 7`，每个内存只能容纳一个文件，所以答案是`4`。 由于整数舍入而意外假设可以容纳多个文件的任何公式都会在此边界上失败。 

## 方法

 完全通用的暴力解决方案可以将问题视为打包问题，并尝试将文件分配给内存。 对于固定数量`k`回忆里的每一个`n`文件最初可以分配给其中任何一个`k`回忆、给予`k^n`可能的任务。 尝试一切可能`k`从`1`通过`n`总共产生`1^n + 2^n + ... + n^n`作业。 在最坏的情况下`n = 10^5`，这是一个天文数字，大致由`10^(500000)`，所以这种方法是完全不可行的。 

这种暴力方法是正确的，因为它考虑了分发文件的所有可能方式，并且可以识别是否存在有效的打包。 问题在于它忽略了最强大的结构属性：每个文件都具有完全相同的大小。 

因为所有文件都是平等的，所以没有理由决定单个文件的去向。 我们只需要知道一个内存可以容纳的完整文件的最大数量。 如果这个数字是`k = floor(a / x)`，那么每个内存最多可以容纳`k`文件，我们总是可以准确地实现`k`只要剩余足够的文件，就会将文件存储在内存中。 因此`n`文件要求上限`n / k`回忆。 

上限除法可以用整数算术计算为`(n + k - 1) // k`。 自从`x <= a`，我们总是有`k >= 1`，所以除法有效。 

暴力破解之所以有效，是因为它显式地搜索有效的打包，但当可能的分配数量变得巨大时就会失败。 所有文件都具有相同大小的观察结果让我们完全放弃文件的身份，并将问题简化为一个整数除法。

 | ---| ---| ---| ---|
 | 蛮力 | 当考虑所有内存计数时，O(n^n) 或更糟 | O(n) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`x`， 和`a`。 这里`n`是文件的数量，`x`是每个文件的大小，并且`a`是一个闪存的容量。 
2. 计算`files_per_memory = a // x`。 这是一个内存可以容纳的完整文件的最大整数。 容量的任何剩余部分都无法使用，因为文件无法分割。 
3. 使用上限除法计算内存数量：`answer = (n + files_per_memory - 1) // files_per_memory`。 本轮`n / files_per_memory`向上，因为最终内存可能包含比其他内存更少的文件。 
4. 打印`answer`。 

### 为什么它有效

 让`k = floor(a / x)`。 内存不能包含超过`k`文件，因为`k + 1`文件需要`(k + 1) * x > a`GB。 同时，任意一组至多`k`文件适合，因为`k * x <= a`。 因此，文件总是可以分为最多`k`文件，并且此类组的最小数量恰好是`ceil(n / k)`。 该算法精确地计算这两个量，因此它产生尽可能少的存储器数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, x, a = map(int, input().split())

files_per_memory = a // x
answer = (n + files_per_memory - 1) // files_per_memory

print(answer)
```第一行读取所有三个输入值。 只有一个测试用例，因此不需要循环测试用例。 

表达式`a // x`使用楼层划分，这是必不可少的。 例如，如果内存有容量`7`GB 和每个文件使用`2`英国，`7 // 2`是`3`，意味着只适合三个完整的文件。 剩余的 1 GB 不能用于第四个文件。 

最终表达式执行上限除法而不使用浮点运算。 使用`(n + files_per_memory - 1) // files_per_memory`避免精度问题并正确处理精确整除性。 例如，`10`文件与`3`每个内存的文件给出`(10 + 3 - 1) // 3 = 4`， 尽管`9`文件给出`(9 + 3 - 1) // 3 = 3`。 

Python中不存在整数溢出问题，这里的最大中间值与Python的整数容量相比很小。 

## 工作示例

 对于第一个样本，输入是`10 2 7`。 

|`n`|`x`|`a`|`a // x`| 回答 |
 | ---| ---| ---| ---| ---|
 | 10 | 10 2 | 7 | 3 | 4 |

 每个内存最多可容纳三个文件，因为`3 * 2 = 6`GB 适合同时`4 * 2 = 8`GB 没有。 十个文件形成三个完整的组，每组三个文件和一个剩余文件，因此需要四个存储器。 这说明了为什么一个存储器的未使用容量不能与另一个存储器组合。 

对于第二个样本，输入是`3 5 15`。 

|`n`|`x`|`a`|`a // x`| 回答 |
 | ---| ---| ---| ---| ---|
 | 3 | 5 | 15 | 15 3 | 1 |

 一个内存可以容纳三个文件，因为`3 * 5 = 15`GB。 因此，所有三个文件都适合单个内存。 这确认了允许与容量相等并且上限除法正确返回`1`当文件数量恰好可以被每内存容量整除时。

import sys
import io

def solve():
    input = sys.stdin.readline
    n, x, a = map(int, input().split())

    files_per_memory = a // x
    answer = (n + files_per_memory - 1) // files_per_memory

    print(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    output = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return output

 ## 边缘情况

 当文件与内存容量完全匹配时，算法会正确允许它。 用于输入`1 5 5`,`a // x`是`5 // 5 = 1`， 所以`(1 + 1 - 1) // 1 = 1`。 输出是`1`。 这会捕获意外使用的实现`<`而不是`<=`在推理容量时。 

当内存的未使用空间对于另一个文件来说太小时，该空间无法帮助任何其他内存。 用于输入`5 2 5`，每个记忆都保存`5 // 2 = 2`文件。 计算变为`(5 + 2 - 1) // 2 = 3`，所以输出是`3`。 两个存储器可为四个文件提供空间，第五个文件需要第三个存储器。 

什么时候`x = a`，每个内存中只能容纳一个文件。 用于输入`4 7 7`,`a // x = 1`，所以答案是`(4 + 1 - 1) // 1 = 4`。 每个文件都需要自己的内存，这正是算法报告的内容。 

当所有文件都装入一个内存时，上限除法自然会返回 1。 用于输入`3 5 15`，每块内存容量为`15 // 5 = 3`, 给予`(3 + 3 - 1) // 3 = 1`。 这种情况不需要特殊情况，这是该公式的一个有用的属性。
