 ## 解决方案
 ## 问题理解

 我们得到了一个用未知数字系统写成的单一加法。 三个字符串代表两个加数及其和，但未提供底数。 每个字符串都用数字书写`0-9`和大写字母`A-Z`，这意味着如果我们将其解释为数字，则每个字符可以表示 0 到 35 之间的值。 

任务是确定是否存在恰好一个有效碱基$b$这样如果我们将所有三个字符串解释为基数中的数字$b$，添加正确。 如果这样的基数存在并且是唯一的，我们就输出它。 如果多个碱基起作用或没有起作用，我们输出 0。 

关键点是所有三个数字必须使用相同的基数，并且所有数字值在该基数中都必须有效，这意味着基数必须严格大于三个字符串中任何一个中出现的最大数字值。 

长度限制（每个数字最多 256 个字符）意味着我们不能尝试通过对每个候选基数重复使用朴素大整数算术将所有内容转换为任意基数的标准整数来解释值。 对最多 36 个碱基的直接模拟是可行的，但我们必须小心避免溢出和重复的大量转换。 

当数字强制使用最小基数，但算术相等在多个较大基数中成立时，就会出现一种微妙的边缘情况。 例如，像这样的小表达`1 + 2 = 3`每个碱基都至少有 4，所以答案不是唯一的，应该是 0。 

另一个重要的情况是当候选碱基中的前导数字无效时，这会导致该碱基完全无效。 例如，如果一个字符`Z`看来，底数必须至少为 36。 

## 方法

 一个天真的想法是尝试从最小有效基数到某个大界限的所有可能基数，将所有三个字符串转换为该基数中的整数，然后检查加法是否成立。 对于每个碱基，转换所需的时间与字符串长度呈线性关系，因此整体复杂性变为$O(B \cdot n)$， 在哪里$B$最多可达 36 个并且$n$最多 256，这是单独可以接受的。 

然而，真正的问题是正确性和唯一性检查。 许多基可能会意外地满足该方程，尤其是当数字关系在多个基中结构上有效时。 因此，我们必须收集所有有效碱基并确保恰好有一个。 

关键的观察是我们只需要从一个受限的范围内评估碱基：$\max(digits)+1$最多 36 个。超过 36 个，则无法表示输入中的任何数字，因此在给定的字母表限制下，更大的基数是不相关的。 

然后，我们使用反向逐位评估（如手动加法）来模拟每个基数的加法，避免完全整数转换。 这使我们能够有效、稳健地检查有效性。

 ## 算法演练

 我们评估所有候选碱基并检查方程是否成立。 

1. 计算三个字符串中任意一个出现的最大数字值。 这确定了最小有效基数。 如果一个字符对应于值$v$，那么任意基数$\le v$无效，因为该数字不能存在于这样的基数中。 
2. 迭代从该最小值到 36 的所有碱基。每个碱基都是方程可能成立的候选系统。 
3. 对于每个基数，从右到左逐位模拟加法，就像手工算术一样。 在每一步中，从每个数字中取出相应的数字（如果用尽则为 0），将其转换为其数值，并计算总和加进位是否与该基数中的结果数字匹配。 
4. 如果在任何时候当前基数中的数字无效或算术约束失败，请立即拒绝该基数。 
5. 如果完整遍历完成并且没有剩余进位，则将该基标记为有效。 
6. 检查完所有碱基后，计算有多少碱基是有效的。 如果恰好存在，则输出它。 否则输出0。 

### 为什么它有效

 该算法直接强制执行位置数字系统的定义：每个数字都被分解为基数$b$数字，当且仅当每个数字列遵循进位规则时，加法才是一致的。 由于每个可能的碱基在唯一有意义的范围内都被检查一次，因此我们既不会错过有效的解决方案，也不会接受无效的解决方案。 通过显式计算有效碱基而不是返回第一个匹配来保证唯一性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def char_val(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    return ord(c) - ord('A') + 10

def check(a, b, c, base):
    i, j, k = len(a) - 1, len(b) - 1, len(c) - 1
    carry = 0

    while i >= 0 or j >= 0 or k >= 0:
        va = char_val(a[i]) if i >= 0 else 0
        vb = char_val(b[j]) if j >= 0 else 0
        vc = char_val(c[k]) if k >= 0 else 0

        if va >= base or vb >= base or vc >= base:
            return False

        total = va + vb + carry
        if total % base != vc:
            return False

        carry = total // base

        i -= 1
        j -= 1
        k -= 1

    return carry == 0

def main():
    a = input().strip()
    b = input().strip()
    c = input().strip()

    max_digit = 0
    for s in (a, b, c):
        for ch in s:
            max_digit = max(max_digit, char_val(ch))

    valid_bases = []

    for base in range(max_digit + 1, 37):
        if check(a, b, c, base):
            valid_bases.append(base)

    if len(valid_bases) == 1:
        print(valid_bases[0])
    else:
        print(0)

if __name__ == "__main__":
    main()
```解决方案首先将所有基数的字符一致地转换为数值。 这`check`函数通过进位传播执行标准的按列加法。 关键部分是拒绝任何无法表示数字的基数，当数字值大于或等于基数时，会立即强制执行。 

基数上的循环很小且有界，因此我们依赖于直接模拟而不是代数重建。 这可以避免精度问题并安全地处理大字符串长度。

 ## 边缘情况

 一个关键的边缘情况是所有数字都为零。 任何大于最大数字允许的基数`0 + 0 = 0`，如此多的碱基都是有效的，由于非唯一性，正确的输出为0。 该算法处理这个问题是因为每个碱基都通过了检查并且`valid_bases`最终大于一。 

另一种情况是当数字强制基数为 36 时，例如`Z`。 如果存在有效方程，该算法仍显式检查基数 36，因为循环包含上限。 如果多个碱基也满足该方程，则唯一性将按要求失败。 

最后，当进位传播超出最高有效数字时，检查函数会正确拒绝基数，除非准确地形成额外的前导数字，从而确保严格的位置正确性。
