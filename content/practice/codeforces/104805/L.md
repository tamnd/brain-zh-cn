 ## 解决方案
 ## 问题理解

 我们得到了一系列连续放置的塔高度。 每个塔都有一个数字高度，我们可以选择其中的一些，同时保留它们从左到右的顺序。 在所有这些子序列中，我们想要最长的子序列，其中每个选定的高度与前一个选定的高度相比都严格增加。 

换句话说，我们正在寻找从左向右移动的最长索引链的长度，其中值不断上升。 输出是一个数字：在这样的最优递增链中可以选择多少个塔。 

该约束允许最多 300,000 个塔，每个高度可以大到 10^9。 这立即排除了任何尝试检查所有子序列的解决方案，因为子序列的数量随 n 呈指数增长。 即使是 O(n^2) 方法在最坏的情况下也会太慢，因为 3·10^5 时的 n^2 大约是 9·10^10 次操作，这远远超出了一秒的实际限制。 

一个微妙的点是，这并不要求连续的段，因此滑动窗口技术不适用。 子序列可以任意跳过元素，这使得朴素动态编程变得必要但昂贵。 

经常打破朴素推理的边缘情况包括严格递减、已排序或包含重复模式的序列。 

一个严格递减的例子，比如`5 4 3 2 1`答案为 1，因为不存在递增对。 严格递增的数组，例如`1 2 3 4 5`有答案 5。假设连续选择或忘记严格不平等的粗心实现可能会错误地处理相等值或相邻结构。 

## 方法

 最直接的思想就是动态规划。 假设我们将 dp[i] 定义为以位置 i 结束的最长递增子序列的长度。 为了计算 dp[i]，我们检查所有 j < i 并在 a[j] < a[i] 时更新 dp[i]。 这是正确的，因为每个以 i 结尾的有效子序列都必须来自某个较早的位置。 

这立即导致所有对 (j, i) 上的双循环。 总工作量约为 n(n-1)/2 次比较。 对于n = 3·10^5，这是完全不可行的。 

关键的观察是，我们实际上不需要知道每个精确高度的所有可能的 dp 值，只需要知道不同长度的增加子序列的最佳可能尾部值。 如果我们为每个长度 L 维护长度 L 的递增子序列的最小可能结束值，我们就可以有效地更新该结构。 

当处理一个新值x时，我们想知道x可以扩展的最长子序列。 这相当于找到最大的 L 使得 tail[L] < x。 如果我们按排序顺序存储 tail，这就变成了二分搜索问题。 

然后我们适当地替换或延长尾巴。 如果 x 大于所有现有尾部，我们就延长 LIS 长度。 否则，我们会在一定长度内改进最佳可能的最终值。 

这将问题转化为经典的耐心排序风格 LIS 计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 所有对的 DP | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 贪心+二分查找（尾部） | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 维护一个空列表，名为`tail`， 在哪里`tail[k]`表示长度为 k+1 的递增子序列的最小可能结束值。 
2. 从左到右迭代每个塔的高度 x。 
3. 对于当前的x，执行二分查找`tail`找到第一个索引 i 使得`tail[i] >= x`。 
4、如果存在这样的索引i，则替换`tail[i]`与 x. 这改进了长度为 i+1 的子序列的最小结束值。 
5. 如果不存在这样的索引，则将 x 附加到`tail`，这意味着我们发现了比以前更长的递增子序列。 
6.处理完所有元素后，得到的长度`tail`就是答案。 

二分查找有效的原因是`tail`始终保持严格递增的顺序。 每个位置代表该长度子序列的最佳可能“最后值”，并且更好（更小）的结尾总是首选，因为它们允许更多的扩展机会。 

### 为什么它有效

 每一步，`tail`存储最佳边界：对于每个长度 L，它保留长度 L 的任何递增子序列的最小可能结束值。如果长度 L 有更好的候选者且具有较小的结束值，我们总是会更喜欢它，因为它为未来元素留下了更多空间。 二分搜索放置确保我们永远不会破坏子序列长度的递增特性，并且替换永远不会减少可实现的最大长度，只会提高未来的灵活性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    tail = []
    
    for x in a:
        lo, hi = 0, len(tail)
        while lo < hi:
            mid = (lo + hi) // 2
            if tail[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        if lo == len(tail):
            tail.append(x)
        else:
            tail[lo] = x
    
    print(len(tail))

if __name__ == "__main__":
    solve()
```实现的核心是二分查找，找到当前值可以替换或扩展子序列的第一个位置。 条件`tail[mid] < x`确保严格的递增子序列，因为不允许相同的值延伸递增链。 

一个常见的错误是使用`<=`而不是`<`，它错误地允许非严格序列。 另一个微妙的问题是忘记了`tail`不是实际的子序列； 它是一种簿记结构。

 ## 边缘情况

 减少输入，例如`5 4 3 2 1`驱动器`tail`重复重置第一个元素。 处理完每个值后，`tail`遗迹`[1]`。 该算法正确地避免了扩展序列，因为每个新值都小于或等于先前的尾部状态。 

完全相等的输入，例如`7 7 7 7`总是在索引 0 处触发替换，保持`tail`作为`[7]`。 这证实了严格比较是强制执行的，并且相等的元素不能扩展子序列。 

严格增加的输入演示了重复的追加。 为了`1 2 3 4`,`tail`单调增长而无需替换，表明该算法正确识别完全可扩展的序列。
