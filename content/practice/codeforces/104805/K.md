 ## 解决方案
 ## 问题理解

 我们得到一个整数的小集合，每个整数在 2 到 15 之间。从这个集合中，我们可以重复执行一个操作，通过从原始集合中选择允许重复的元素来构建新的多重集。 从这样一个选择的多重集中，我们计算一个数字：对于该多重集的每个子集，我们将子集中的元素相乘，并将所有子集的这些乘积相加。 

空子集对该和贡献 1，因此该操作相当于取多重集$Y$并生产$$\sum_{S \subseteq Y} \prod_{y \in S} y.$$生成这些值后，我们可以继续重复该过程任意有限次，始终仅使用原始数字作为构建块。 任务是计算有多少个不超过的不同值$L$永远可以被生产出来。 

关键的结构观察隐藏在乘积子集和表达式中。 如果我们扩大产品范围$$\prod_{y \in Y} (1 + y),$$我们准确地获得了所有子集的总和$Y$，包括空子集。 因此，每个操作都会产生以下形式的值$$\prod_{y \in Y} (1 + y) - 1.$$这将问题从子集的推理转化为常数乘法构造的推理$1 + x_i$，每个位于 3 到 16 之间。 

初始元素数量较少，最多 20 个，但取值范围可达$10^{12}$。 这立即排除了任何显式枚举所有多重集或所有子集组合的方法。 即使是对值进行简单的 BFS 也会爆炸，因为每个数字都可以通过多种方式重新组合，但结构是乘法且高度冗余的。 

当所有的情况出现时，就会出现微妙的边缘情况$x_i$是平等的。 许多不同的多重集会产生相同的值，并且计算结构而不是不同的结果会严重超算。 另一个问题是，该操作总是产生比纯乘积至少大 1 的值，因此在与$L$。 

## 方法

 直接模拟将尝试枚举每个可能的多重集$Y$，计算结果值，并根据新生成的值重复该过程。 多重集的数量无限增长，因为允许重复，甚至限制有界大小也已经导致指数爆炸$N$。 每个状态内部的计算是可控的，但状态空间本身是无界的，并且很快就会超过任何可行的限制。 

关键的简化来自于将操作重写为产品。 每个生成的值都有以下形式$$\prod (1 + x_i)^{c_i} - 1,$$在哪里$c_i$是元素的次数$x_i$是在多重集中选择的。 这意味着每个可达值都对应于一小组基本整数重复相乘所形成的乘积$b_i = 1 + x_i$，每个在 3 到 16 之间。 

这完全删除了子集结构，并将问题转变为生成由上限下的一小组整数形成的所有不同乘积$L + 1$。 乘法的顺序并不重要，因此搜索空间变成了指数选择的组合探索，但由于乘积的快速增长而进行了大量剪枝。 

最佳方法是对不同碱基值进行深度优先枚举，选择每个碱基对产品贡献的次数。 由于值增长很快，每个分支在超过之前的深度非常有限$L + 1$，使搜索变得可行。

 ## 算法演练

 我们首先通过替换每个来压缩输入$x_i$和$b_i = x_i + 1$，因为每个运算仅依赖于这些乘法值。 

1. 提取所有值中的不同值$b_i$，因为除了允许更多指数选择之外，重复项不会改变可达产品集。 这减少了不必要的分支。 
2. 定义一个从 1 开始构建乘积的递归搜索。在每一步，我们决定乘以当前基值多少次。 
3. 对于每个基地$b_i$，尝试将当前乘积乘以$b_i^k$， 在哪里$k \ge 0$，只要结果不超过$L + 1$。 每一个选择$k$代表选择该元素$k$多重集中的时间。 
4. 确定当前底数的指数后，递归处理下一个底数索引。 这确保了我们永远不会重新访问早期的碱基，从而防止以不同的顺序计算相同的组合。 
5. 每当我们处理完所有碱基时，我们就会得到一个有效的产品$P$。 如果$P > 1$，我们记录$P - 1$作为一个可达到的值。 

递归系统地枚举受极限限制的基集的所有乘法组合。 

### 为什么它有效

 每个有效的构造都唯一对应于一个指数向量$(c_1, c_2, \dots, c_m)$，映射到产品$\prod b_i^{c_i}$。 DFS 通过强制执行基数的固定排序，仅枚举每个指数向量一次。 由于乘法是可交换的，因此没有两条不同的路径会产生相同的指数配置。 修剪条件$P \le L + 1$确保没有分支可以贡献允许范围之外的值，因此搜索空间既完整又有限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, L = map(int, input().split())
    x = list(map(int, input().split()))

    bases = sorted(set(v + 1 for v in x))
    limit = L + 1

    seen = set()

    def dfs(i, cur):
        if i == len(bases):
            if cur > 1:
                seen.add(cur - 1)
            return

        dfs(i + 1, cur)

        b = bases[i]
        nxt = cur
        while True:
            nxt *= b
            if nxt > limit:
                break
            dfs(i + 1, nxt)

    dfs(0, 1)
    print(len(seen))

if __name__ == "__main__":
    solve()
```该实现直接反映了该过程的指数解释。 递归索引`i`对基数强制执行固定排序，确保唯一性。 循环乘法`nxt`经过`b`在单个分支中重复编码该基数的所有指数选择。 这`limit = L + 1`移位至关重要，因为实际存储的值总是比乘积小一。 

一个常见的错误是忘记删除重复的基值，这会导致冗余探索，但仍然保持正确，只是速度较慢。 另一个微妙之处是从乘积 1 开始，而不是从类似零的哨兵值开始，因为该结构是纯粹的乘法。

 ## 边缘情况

 当所有输入数字都相同时，每个乘法结构都会分解为单个基数的重复幂。 DFS 仍然探索指数选择，但重复数据删除可确保仅计算不同的乘积。 例如，使用输入`2 10 / 2 2`，唯一可达的乘积是 1、3 和 9，减一后产生两个有效值。 

什么时候$L$非常小，许多分支在第一次乘法后立即终止。 例如，与`2 5 / 2 3`，两个基数都变为 3 和 4，但任何第二次乘法都已经超出了限制，因此只有单基数贡献得以幸存。 递归仍然访问这两个选择，但几乎立即进行修剪。 

什么时候$L$非常大，搜索深度略有增加，但碱基的指数增长确保即使长链也保持浅。 例如，重复乘以 3 超过$10^{12}$不到 25 个步骤，因此没有分支可以无限期地生长。
