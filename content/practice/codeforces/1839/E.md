 ## 解决方案
 ## 问题理解

 我们正在玩一个关于正整数数组的两人游戏。 在每一轮中，第一个玩家选择一个具有正值的位置，然后第二个玩家必须选择另一个也是正值的位置。 两个选定的值同时减少两者中较小的一个，这保证了至少其中一个在回合结束时变为零。 这个过程一直持续到一个玩家无法做出有效的动作为止：如果第一个玩家不存在可供选择的积极元素，则第一个玩家失败，如果在第一个玩家的选择之后没有第二个不同的积极元素可用，则第二个玩家失败。 

关键结构是，每一轮都会“消耗”两个不同指数的一定量的总价值，并且每当选择一对时，至少有一个指数变为零。 这意味着活跃（正）指数的数量随着时间的推移严格减少，因此游戏总是结束。 

约束很小，n 最大为 300，值最大为 300。这强烈表明 O(n^2) 或 O(n^3) 推理是可以接受的，并且解决方案可能取决于正质量如何配对的结构属性，而不是对所有可能的移动进行任何深度模拟。 

一种简单的方法可能会尝试贪婪地模拟交互，甚至在正指数的所有子集上动态地模拟最佳游戏。 这会失败，因为第二个玩家是对抗性的，并且配对的选择会以高度非局部的方式影响未来的移动可用性。 例如，如果第一个玩家重复瞄准同一个大堆，粗心的模拟可能会过早地消除灵活性并错误地得出对手被迫获胜或失败的结论。 

微妙的边缘情况是只有一个指数保持为正值。 在这种情况下，谁被迫先行动，谁就会立即失败，因为不存在有效的伙伴。 这意味着游戏的结果取决于是否可以在对手的回合中强制以单个非零堆结束该过程。 

## 方法

 关键的观察是，每次移动都会减少两个正堆，而游戏结束的唯一方式是当剩下的正堆少于两个时。 因此，游戏的结构完全取决于我们能保持至少两个指数为正的时间有多长。 

每轮有效地将两个不同的正指数配对，并将两者减少一定的正数。 无论值如何减少，每次操作都会消除至少一个正索引。 因此，最大轮数与初始多重值中存在多少“配对机会”紧密相关。 

从全局角度来看，游戏简化为从两个不同的指数中重复删除一个单位的“配对容量”，直到最多一个指数保持非零。 这相当于经典条件：如果一种元素占主导地位太强，它最终将独自生存，否则质量可以平衡，直到所有值消失。 

令 S 为所有值的总和，M 为最大元素。 如果 M 大于 S − M，则在尽可能多地配对后，即使所有其他堆都耗尽后，最大的堆仍将具有剩余质量。 这保证了游戏最终会达到只有一个正指数的状态，而在这种情况下移动的玩家就会失败。 

如果 M 不大于 S − M，则可以始终保持至少两个正索引，直到所有内容以平衡方式耗尽。 在这种情况下，第一个玩家有必胜策略，应该先开始； 否则，第二个玩家更安全。 

该决策简化为最大元素与数组其余部分之间的简单比较。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全游戏模拟| O(S) 或更差的指数 | O(n) | 太慢了 |
 | 最优贪心结构检查 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算所有元素的总和并确定最大元素。 
2. 将最大元素 M 与剩余元素之和 S − M 进行比较。 
3.如果M严格大于S−M，则选择玩第二，否则选择玩第一。 

选择背后的原因是，当最大的桩超过所有其他桩的“支撑”总和时，它不可避免地会独自生存。 在这种情况下，首先进入最后阶段的玩家将被迫进入没有伙伴存在的失败状态。 如果不存在这样的统治，那么游戏的结构总是可以成对进行消除，而不会过早地隔离一堆。 

### 为什么它有效

 不变的是，每次移动都会从两个不同的索引中删除相同的数量，因此总质量会减少，而正索引的数量每轮至少减少一个。 避免单一正指数的早期终止状态的唯一方法是确保没有任何单一指数能够比所有其他指数的总和更持久。 如果存在这种优势，则最终的配置将被强制并决定失败的一方。 否则，配对的灵活性确保了可以安排该过程，以便最后一步不会让双方玩家被迫失去位置优势。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    mx = max(a)
    
    if mx > total - mx:
        print("Second")
    else:
        print("First")

if __name__ == "__main__":
    solve()
```该解决方案读取数组，计算其总和和最大值，然后直接应用优势测试。 该比较对游戏的整个策略行为进行编码，而不模拟任何回合。 

微妙的实施细节确保了严格的不平等。 平等仍然允许平衡的配对序列，其中没有单个堆单独生存，因此它属于先胜的情况。 

## 工作示例

 考虑数组`[10, 4, 6, 3]`。 总和为 23，最大值为 10。由于 10 不大于 13，因此第一个玩家可以避免陷入单幸存者场景。 决定先玩。 

| 步骤| 总和| 最大| 状况 |
 | ---| ---| ---| ---|
 | 初始| 23 | 23 10 | 10 10≤13|

 这表明没有任何元素支配其余元素，因此配对可以继续，直到数组完全崩溃。 

现在考虑`[1, 1, 1, 10]`。 总和为 13，最大值为 10。由于 10 > 3，所以在所有其他元素都耗尽后，最大的元素将不可避免地保留下来。 

| 步骤| 总和| 最大| 状况 |
 | ---| ---| ---| ---|
 | 初始| 13 | 10 | 10 10 > 3 | 10 > 3

 这里，游戏被迫进入只有一个指数保持正值的状态，而第二个玩家的选择首先变得不可能，所以选择第二个是最优的。 

这些痕迹显示了不等式如何直接捕捉游戏是否可以避免单堆的孤立。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    mx = max(a)
    print("Second" if mx > total - mx else "First")

# provided sample

# single element
assert run("1\n7\n") == "First"

 ## 边缘情况

 对于像这样的单元素数组`[7]`，从一开始就没有有效的第二步棋，因此如果强制下棋，第一个玩家会立即失败。 该算法输出 First，因为没有任何元素支配其余元素，并且游戏最终平淡结束。 

为了`[1, 1, 10]`，最大的元素严格超过其他元素的总和。 每次配对每次互动时最多会从大堆中移除一个单位，而较小的堆会很快消失。 最终只剩下一大堆，迫使对手陷入不存在有效第二选择的位置，与输出 Second 相匹配。 

为了`[5, 5, 5]`，没有任何元素占主导地位。 总是可以安排配对，以便消除均匀地进行，不留下强制的单堆，这对应于选择第一。 

每个案例都证实，不平等完全表征了游戏是崩溃为单幸存者状态还是保持平衡直到耗尽。
