 ## 解决方案
 ## 问题理解

 输入描述了一个有根的士兵树，没有明确的边进行编码。 每个士兵都以一个整数 ID 的形式出现，紧接着该 ID 之后是零个或多个带括号的对其直接下属的描述。 一对括号恰好包含一个完整的子树。 例如，`2(3(4))(1)`描述一棵树，其根为士兵 2，其子节点为 3 和 1，而 3 则有子节点 4。 

任务是找回每个士兵的父母。 对于从 1 到`n`，我们输出其直接主管的ID。 根部的唯一士兵的父级为 0。 

第一个约束最多给出 140,000 名士兵，而编码字符串最多可以包含 100 万个字符。 这意味着与士兵或角色数量成正比的算法很容易适用，但为每个士兵重复扫描大部分字符串的成本太高。 对于一秒的时间限制，我们应该瞄准线性时间，或者最坏的情况是接近线性时间。 超过一百万个字符的字符串的二次算法可能需要大约`10^12`字符操作，远远超出了极限。 

第一个边缘情况是单个士兵。 输入```
1
1
```根本没有括号，正确的输出是```
0
```假设每个士兵至少有一个孩子的解析器在这里会失败。 

另一种边缘情况是一条链，其中每个士兵都有一个孩子：```
4
1(2(3(4)))
```正确的输出是```
0 1 2 3
```一个粗心的实现，在遇到后将最近解析的士兵视为兄弟姐妹`)`可能会失去祖宗关系。 士兵 4 完成后，解析器必须返回士兵 3，然后返回士兵 2，然后返回士兵 1。 

第三种情况是几个兄弟姐妹：```
4
1(2)(3)(4)
```答案是```
0 1 1 1
```在解析士兵 3 之前，士兵 2 的右括号必须将士兵 1 恢复为当前主管。 忘记从其活动路径中删除已完成的士兵的实现可能会错误地使 2 成为 3 的父级。 

最后，ID 可能有多个数字，因此一次将一个字符解析为单独的 ID 是不正确的。 例如，```
3
10(2)(30)
```将描述 ID 10、2 和 30（如果所选的 ID 允许）`n`; 解析器在处理士兵之前必须消耗完整的数字序列。 在实际约束下，ID 恰好为 1 到`n`，每当出现同样的问题`n >= 10`。 

## 方法

 一种直接的方法是独立处理每个士兵。 找到 ID 出现的位置后，我们可以向后扫描字符串并确定哪个士兵的括号包含该位置。 括号提供了足够的信息来恢复封闭的子树，因此这种方法是正确的。 

问题是相同的字符被一遍又一遍地扫描。 考虑一棵深度嵌套的树，例如`1(2(3(4(...)))`。 对于靠近底部的士兵来说，向后搜索几乎可以遍历字符串的整个前缀。 如果有`n`士兵和绳子有长度`L`，最坏情况的工作是`O(nL)`。 和`n = 140000`和`L`附近`10^6`，这大约可以达到`1.4 × 10^11`性格检查。 尽管这两个量的精确最大值不可能在每种形状中独立出现，但这个界限已经太大了。 

编码的结构使我们能够更好地观察。 在从左到右读取字符串时的任何一点，从根到当前正在描述的士兵都有一条独特的路径。 这条路正是由士兵组成，他们的开口`(`已经遇到但是其对应的`)`目前还没有遇到过。 

该活动路径可以通过堆栈来维护。 当读取一个新的士兵ID时，堆栈的顶部是其主管。 然后我们推动新士兵，因为它的所有子级（如果有的话）都属于它。 什么时候`)`遇到时，当前士兵的整个描述已经结束，所以我们将其弹出。 每个字符都被处理一次，每个士兵都被推入和弹出一次。 

蛮力方法之所以有效，是因为括号隐含地告诉我们哪个士兵包含另一个士兵，但它会从头开始重复重建这种关系。 活动祖先实际上是一个堆栈的观察结果将问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(nL)`在最坏的情况下|`O(n)`| 太慢了 |
 | 堆栈解析 |`O(L)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 阅读`n`和编码的字符串。 分配长度的答案数组`n + 1`， 在哪里`parent[x]`最终将包含士兵的主管`x`。 
2. 初始化一个空堆栈。 堆栈表示从根到正在处理其描述的士兵的当前路径。 它的顶部始终是当前活跃的士兵。 
3. 从左到右扫描字符串。 当找到数字时，继续消耗数字，直到读取完整的整数 ID。 这是必要的，因为 ID 例如`123`是一名士兵，而不是三名单独的士兵。 
4. 完成ID后`x`已经解析完毕，检查堆栈。 如果非空，则其顶层是`x`，所以设`parent[x]`到那个值。 如果栈为空，`x`是根，其父项仍为 0。 
5. 推`x`到堆栈上。 从这一点到相应的右括号，`x`是其子树中遇到的每个直接子级的活动主管。 
6.当扫描遇到`(`，只需前进即可。 左括号并没有引入新的士兵，因此不需要执行堆栈操作。 
7.当扫描遇到`)`，弹出顶兵。 它的完整子树刚刚结束，因此它不能再是活动的监督者。 新的栈顶是它的父栈。 
8. 扫描完整字符串后，输出`parent[1]`通过`parent[n]`。 每个士兵都只遇到过一次，所以每一个父母关系都已经确定了。 

### 为什么它有效

 关键的不变量是，在读取士兵 ID 之前，堆栈恰好包含该士兵的祖先（按根到父级的顺序）。 打开一个士兵的描述会导致该士兵被推送，因此它的子级会在堆栈的顶部看到它。 当到达它的右括号时，它的整个子树就完成了，弹出它会恢复它自己的父元素作为顶部元素。 因此，每当解析一个 ID 时，栈顶就是它的直接主管。 root 是唯一用空堆栈解析的 ID，因此它正确地接收到了父级 0。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(data):
    lines = data.splitlines()
    n = int(lines[0])
    s = lines[1].strip()

    parent = [0] * (n + 1)
    stack = []

    i = 0
    length = len(s)

    while i < length:
        c = s[i]

        if '0' <= c <= '9':
            x = 0

            while i < length:
                c = s[i]
                if c < '0' or c > '9':
                    break
                x = x * 10 + (ord(c) - 48)
                i += 1

            if stack:
                parent[x] = stack[-1]

            stack.append(x)
        elif c == ')':
            stack.pop()
            i += 1
        else:
            # '('
            i += 1

    return ' '.join(map(str, parent[1:]))

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```解析器使用索引`i`而不是分割字符串。 这避免了创建大量临时子字符串的集合，并让我们可以直接处理输入。 

什么时候`s[i]`是一个数字，内部循环以数字方式构建完整的 ID。 完成后，`i`已经指向第一个非数字字符，因此数字分支末尾没有额外的增量。 此细节可防止跳过后面的括号。 

堆栈存储整数 ID，而不是字符串位置。 这使得父级查找立即进行，因为`stack[-1]`正是我们需要的主管。 

对于堆栈为空时读取的 ID，不需要进行赋值，因为答案数组已用零初始化。 恰好有一名这样的士兵，因为输入代表一棵有根的树。 

什么时候`)`处理完毕后，对于有效输入，堆栈不能为空。 pop操作移除了描述刚刚结束的士兵。 一个开口`(`不需要堆栈操作，因为正在打开的士兵在读取其 ID 时会被推送。 

Python 整数在这里不存在溢出问题。 最大的ID只有14万，而字符串本身最多包含100万个字符。 

实现使用`sys.stdin.read()`里面`solve`而不是反复调用`input()`。 这方便了百万字符的输入，也使得求解器易于测试。 所需的`input = sys.stdin.readline`被定义为标准竞争编程快速 I/O，尽管主求解器会立即读取整个输入。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(L)`| 每个字符都会被检查一次，每个 ID 都会被推送一次。 |
 | 空间|`O(n)`| 答案数组和堆栈各最多包含`n`整数。 |

 这里`L`是编码字符串的长度，其中`L <= 10^6`， 和`n <= 1.4 × 10^5`。 百万字符线性扫描适合一秒的限制，而堆栈最多可以包含单个链中的所有士兵，这完全在 256 MB 内存限制之内。

## 边缘情况

 单兵情况在任何堆栈操作之前处理。 为了```
1
1
```解析器读取 ID 1 且堆栈为空，然后离开`parent[1]`等于 0，并压入 1。然后扫描结束，产生`0`。 不需要右括号，因为根的描述不包含从属。 

深链案例```
4
1(2(3(4)))
```产生`parent[1] = 0`,`parent[2] = 1`,`parent[3] = 2`， 和`parent[4] = 3`。 读取4后，堆栈为`[1, 2, 3, 4]`。 每个`)`恰好移除了一名士兵，因此活动祖先从 4 移动到 3，然后从 3 移动到 2，最后从 2 移动到 1。这正是括号编码的嵌套信息。 

兄弟姐妹的案例```
4
1(2)(3)(4)
```从堆栈开始`[1]`。 读取 2 分配父级 1 并产生`[1, 2]`。 它的右括号弹出 2，恢复`[1]`。 3 和 4 发生相同的序列。结果是`0 1 1 1`。 只推入而不弹出的解析器会错误地将兄弟姐妹变成链。 

多位数情况```
3
3(1)(2)
```将 3 读取为一个完整的 ID，而不是独立解释其数字。 它将父级 0 分配给 3，然后将父级 3 分配给 1 和 2。输出为`3 3 0`。 内部数字读取循环使其适用于以下允许的每个 ID 大小`n`。 

对于最大尺寸的结构应力情况，输入从士兵 1 开始，后跟 139,999 个兄弟子树：```
140000
1(2)(3)(4)...(140000)
```当 1 位于堆栈顶部时，每个孩子都会被读取，因此每个赋值都是`parent[x] = 1`。 每个右括号立即删除该子项，为下一个子项留下 1 处于活动状态。 该算法一次性处理整个大约一百万个字符的字符串，而不是重复搜索它，这正是线性方法在最大输入大小下仍然实用的原因。
