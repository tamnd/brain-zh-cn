 ## 解决方案
 ## 问题理解

 我们需要将给定的素数（n）分成两个素数（a）和（b），这样

 [
 a+b=n。 
]

 任何有效的对都被接受，因此如果存在多个，则无需查找特定的分解。 如果不存在这样的对，我们打印 (-1)。 

界限 (n\le 10^7) 足够大，以至于在 1 秒的时间限制内检查每个可能的对并重复测试数字的素数成本太高。 然而，(10^7) 足够小，以至于通过试除进行的单个素性测试非常便宜，因为它的平方根仅为 (3162) 左右。 主要挑战不是 (n) 的大小，而是认识到 (n) 本身是素数这一事实极大地限制了哪些对是可能的。 

有3种边界情况很容易导致错误。 对于 (n=2)，最小素数，将其写为正素数之和的唯一方法将需要小于 (2) 的素数，因此正确的输出是`-1`。 对于(n=3)，最小素数唯一可能的用途是(2+1)，但(1)不是素数，所以答案也是`-1`。 将 (1) 视为质数的粗心实现会错误地接受这种情况。 

数字的奇偶性造成了另一个常见的陷阱。 例如，对于 (n=11)，两个素数不能都是奇数，因为奇数加奇数是偶数。 唯一可能的对是 (2+9)，但 (9) 是合数，因此正确的输出是`-1`。 在不使用奇偶校验的情况下尝试任意对可能会浪费大部分可用时间。 

## 方法

 直接的暴力解决方案可以尝试从 (2) 到 (n-2) 的所有可能的 (a)，设置 (b=n-a)，并测试两个数字的素数。 该方法是正确的，因为每个可能的分解都有一个在该范围内的素数，因此最终会考虑每个候选对。 然而，如果通过试除法检查素性，则每个测试可能需要 (O(\sqrt n)) 次除法。 在最坏的情况下，这会产生 (O(n\sqrt n)) 的工作。 在 (n=10^7) 处，大约是 (10^7\cdot3162\approx3.16\times10^{10}) 次试除，远远超出了一秒的范围。 

输入的结构为我们提供了更强有力的观察。 除 (2) 之外的每个素数都是奇数。 由于 (n) 是质数，因此它要么是 (2)，要么是奇数。 对于奇素数 (n)，两个奇素数之和将为偶数，因此有效对必须包含 (2)。 只有一对可能：

 [
 2+(n-2)=n。 
]

 因此，整个问题已简化为检查 (n-2) 是否为素数。 我们不需要搜索候选者、建立筛子或检查多对。 

蛮力方法之所以有效，是因为它明确地探索了所有分解，但它失败了，因为它执行了远远多于必要的素性检查。 奇偶观察将搜索空间从 (O(n)) 个候选对减少到恰好一个候选对。 对于给定的限制，单个试除素性测试很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n\sqrt n)) | (O(1)) | (O(1)) | 太慢了|
 | 最佳| (O(\sqrt n)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取素数 (n)。 如果(n=2)，立即打印`-1`，因为两个素数都至少为 (2)，所以它们的和至少为 (4)。 
2. 对于奇素数 (n)，通过奇偶校验得出所需的两个素数之一必须是 (2)。 另一个值强制为 (n-2)，因此没有理由尝试任何其他候选值。 
3. 使用试除法测试 (n-2) 是否为素数。 测试最大 (\sqrt{n-2}) 的除数就足够了，因为如果合数有一个大于其平方根的因子，则其对应的因子必须小于平方根。 
4. 如果 (n-2) 是素数，则打印`2 n-2`。 否则打印`-1`，因为奇素数 (n) 的每个有效对都必须恰好是这一对。 

### 为什么它有效

 对于每个奇素数 (n)，假设 (n=a+b)，其中 (a) 和 (b) 都是素数。 如果两者都是奇数，则它们的和将为偶数，这与 (n) 是奇数的事实相矛盾。 因此，其中之一必定是唯一的偶素数 (2)。 因此另一个必须等​​于 (n-2)。 该算法准确地检查这个强制候选者，并在 (n-2) 为素数时准确地接受它。 对于 (n=2)，不存在任何对，因为两个素数的最小和为 (4)。 因此，每个可能的输入都会被正确处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False

    if x % 2 == 0:
        return x == 2

    d = 3
    while d * d <= x:
        if x % d == 0:
            return False
        d += 2

    return True

def solve():
    n = int(input())

    if n == 2:
        print(-1)
        return

    other = n - 2

    if is_prime(other):
        print(2, other)
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```这`is_prime`函数首先拒绝低于 (2) 的值，它处理 (n=3) 的情况，因为然后`other`等于(1)。 它还单独处理偶数。 之后，只需要考虑奇数除数，因此循环从 (3) 开始并增加 (2)。 

条件`d * d <= x`是试分割的标准边界。 如果没有已经测试过的较小互补因子，则测试超出 (\sqrt{x}) 的除数无法发现新因子。 使用乘法而不是计算浮点平方根也可以避免精度问题。 

主函数在形成候选之前处理 (n=2)。 对于每个其他有效输入，`other = n - 2`是唯一可能的第二素数。 该程序从不执行不必要的对枚举。 

Python整数在这里不会溢出，并且素性测试中的最大乘法仅在(3162^2)左右，因此不存在数值问题。 

## 工作示例

 对于第一个样本，(n=5)。 由于 (5) 是奇数，唯一可能的对必须包含 (2)，剩下 (5-2=3)。 

| (n) | 候选人 (n-2) | 除数检查 | 结果 |
 | --- | --- | --- | --- |
 | 5 | 3 | 除了偶数检查之外不需要任何东西 |`2 3`|

 候选者 (3) 是素数，因此强制对有效。 该跟踪说明了为什么不需要考虑其他对。 

对于第二个样本，(n=11)。 同样，奇偶校验迫使一个素数成为 (2)，留下 (9)。 

| (n) | 候选人 (n-2) | 除数检查 | 结果 |
 | --- | --- | --- | --- |
 | 11 | 11 9 | (3\中9) |`-1`|

 在需要继续循环之前找到除数 (3)。 由于 (9) 是复合的，因此唯一可能的一对失败，证明不存在答案。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(\sqrt n)) | 仅执行一次素性测试，检查奇数除数直至 (\sqrt{n-2})。 |
 | 空间| (O(1)) | (O(1)) | 该算法仅存储恒定数量的整数。 |

 对于 (n\le10^7)，素性测试最多检查粗略 (3162) 个可能的除数值，而实际上只检查其中大约一半，因为甚至会跳过除数。 这完全在 1 秒的时间限制之内，并且与 256 MB 的限制相比，使用的内存可以忽略不计。 

## 测试用例```python
import sys
import io

def is_prime(x):
    if x < 2:
        return False

    if x % 2 == 0:
        return x == 2

    d = 3
    while d * d <= x:
        if x % d == 0:
            return False
        d += 2

    return True

def solve():
    n = int(input())
    if n == 2:
        print(-1)
        return

    other = n - 2
    if is_prime(other):
        print(2, other)
    else:
        print(-1)

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    output = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = output

    try:
        solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = old_input

    return output.getvalue().strip()

assert run("5\n") == "2 3", "sample 1"
assert run("11\n") == "-1", "sample 2"

assert run("2\n") == "-1", "minimum prime"
assert run("3\n") == "-1", "n - 2 equals 1"
assert run("7\n") == "2 5", "smallest successful odd case"
assert run("9999991\n") == "-1", "maximum valid prime input"

print("All tests passed.")
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`2`|`-1`| 最小输入和不可能的等质边界 |
 |`3`|`-1`| 防止将 (1) 视为素数 |
 |`7`|`2 5`| 小成功分解并正确的（n-2）边界|
 |`9999991`|`-1`| 接近最大输入大小和大型复合候选 |

 (10^7) 以下的最大素数是 (9,999,991)，使其成为有效的最大尺寸测试输入。 它的强制候选 (9,999,989) 是复合的，具有因子 (223) 和 (44,843)，因此预期答案是`-1`。 

## 边缘情况

 对于`n = 2`，算法进入显式边界检查并打印`-1`。 原因比简单地说候选失败更强有力：两个素数至少各为 (2)，因此它们的总和不可能为 (2)。 盲目计算的解决方案`n - 2`会得到 (0)，它不是素数，但明确地处理这种情况可以使推理清晰。 

为了`n = 3`，强制的第二个值为(3-2=1)。 素性函数立即返回`False`因为 (2) 以下的值不是质数，所以程序会打印`-1`。 这会发现一个常见错误，即自定义素数测试在 (2) 处开始其除数循环，并意外地将 (1) 视为素数，因为它找不到除数。 

为了`n = 5`，强制对是(2+3)。 素性测试接受 (3)，因此程序打印`2 3`。 这是存在分解的最小有效输入，并确认候选边界已正确处理。 

为了`n = 11`，强制对是(2+9)。 素性测试检查 (3)，发现 (9) 能被 (3) 整除，并返回`False`。 程序打印出`-1`。 尝试另一对也无济于事，因为两个奇数素数之和将为偶数，因此 (2+9) 是唯一可能的结构。 

对于等素分解，假设 (a=b=p)。 那么(n=2p)，它是偶数。 由于输入 (n) 是素数，因此唯一的偶数可能性是 (n=2)，但对于任何素数 (p)，(2) 不能等于 (2p)。 因此，有效输入不能使两个输出素数相等。 最小理论等素数和为 (2+2=4)，但 (4) 不是允许的输入，因为它不是素数。 

对于最大的有效输入 (n=9,999,991)，算法仍然仅执行一次素性测试，这次是在 (9,999,989) 上。 该候选值可被 (223) 整除，因此一旦找到该因子并且程序输出，测试就会停止`-1`。 (n) 的大小不会改变基本策略，因为候选对的数量仍然是 1。
