 ## 解决方案
 ## 问题理解

 我们有一个最大的整型俄罗斯套娃`S`。 如果一个娃娃被放置在另一个娃娃里面，那么里面的娃娃最多只能是`1/X`外娃娃的尺寸。 我们想要尽可能最长的嵌套链，所以问题是从原始尺寸可以出现多少个娃娃`S`减小到最小的正整数大小。 

假设当前的娃娃有尺寸`A`。 下一个娃娃的最大可能尺寸是`floor(A / X)`。 选择较小的娃娃永远不会有帮助，因为下一个较大的娃娃至少为后面的每个娃娃留下了同样多的空间。 重复这个选择会得到尽可能长的链。 

这些约束足够小，足以使对数算术成为自然目标。 自从`X >= 2`，每个嵌套步骤都会将大小至少减少两倍。 最多从`10^9`，在大小变为零之前，减少的次数可以少于 31 次。 对所有尺寸进行线性扫描，最大可达`10^9`对于一秒的限制来说太昂贵了，而`O(log S)`解决方案仅执行几十次迭代。 

在几种边界情况下，实现可能会出现相差一的错误。 为了`S = 1, X = 2`，答案是`1`，因为原来的娃娃本身也算数，但里面不能容纳正整数大小。 只计算成功除法的粗心循环可能会输出`0`。 

为了`S = 10, X = 2`，最优链为`10 -> 5 -> 2 -> 1`, 给予`4`。 使用普通除法而不显式取底的实现在 Python 中是安全的，因为整数除法已经取底，但使用浮点除法并稍后转换可能会引入不必要的精度风险。 

为了`S = 9, X = 2`，链条是`9 -> 4 -> 2 -> 1`,再次给予`4`。 第二个尺寸是`4`， 不是`4.5`，因为娃娃尺寸必须是整数。 任何将大小视为实数的方法都可能产生不正确的链长度。 

什么时候`S = X = 10^9`，链条是`10^9 -> 1`，所以答案是`2`。 一个常见的错误是要求下一个娃娃的尺寸严格小于`S / X`，但条件允许相等，所以大小`1`是有效的。 

## 方法

 直接的暴力方法可以搜索下一个娃娃的所有可能的整数大小。 对于当前尺寸`A`，它可以检查所有候选人`1`通过`floor(A / X)`并确定哪一个最大且有效。 这是正确的，因为会检查下一个娃娃的每一个可能的选择，并且采取最大的有效选择会产生最佳的延续。 

问题在于大量不必要的工作。 和`S = 10^9`和`X = 2`，这样的搜索大致检查`floor(10^9 / 2) + floor(10^9 / 4) + floor(10^9 / 8) + ...`整个链条的候选人。 这个金额是`10^9 - popcount(10^9) = 999,999,987`，所以最坏的情况本质上是十亿次迭代。 这无法在一秒的限制内轻松完成。 

蛮力方法之所以有效，是因为它正在搜索一个空间，一旦考虑了所有候选者，下一个最佳尺寸就很明显。 关键的观察是我们实际上不需要搜索该空间。 对于当前尺寸`A`，每个有效的下一个尺寸最多是`floor(A / X)`，并且准确地选择该最大值可以为剩余的娃娃提供最大的可能起点。 因此，问题简化为重复应用整数除法`X`。 

开始于`S`，我们计算当前的娃娃，将其大小替换为`S // X`，并在新尺寸为正值时继续。 自从`X`至少是`2`，迭代次数是对数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(S)`在最坏的情况下|`O(1)`| 太慢了|
 | 最佳|`O(log_X S)`|`O(1)`| 已接受 |

 ## 算法演练

 1. 阅读`S`和`X`。 当前娃娃尺寸最初为`S`，答案从`1`因为最大的娃娃本身已经是嵌套链的一部分。 
2. 虽然当前大小至少为`X`，将其替换为`current // X`并增加答案。 

仅当除法`current >= X`相当于检查里面是否可以容纳另一个正整数娃娃。 如果`current < X`， 然后`floor(current / X) = 0`和尺寸`0`不是娃娃，所以链条必须停止。 
3. 打印累计答案。 

正确性来自每次迭代之前的不变量，`current`是所有最佳链中该深度处娃娃的最大可能尺寸。 从一个娃娃大小`current`，有效的内娃娃不能超过`floor(current / X)`，只要它是正数，该精确大小就有效。 选择最大可能的下一个尺寸不能减少后续娃娃的最大可实现数量，因为每个后续约束相对于当前尺寸都是单调的。 因此，每次除法都会产生最好的下一个玩偶，并且当不存在正的内部玩偶时，循环恰好停止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    S, X = map(int, input().split())

    ans = 1
    while S >= X:
        S //= X
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```变量`ans`开始于`1`因为即使里面不能放置更小的娃娃，原始娃娃也会被计算在内。 这处理`S = 1`正确。 

条件`S >= X`是干净的边界检查。 如果成立的话，`S // X`至少是`1`，所以存在另一个正尺寸的娃娃。 如果不成立，商将为零并且必须停止嵌套。 

更新直接使用整数除法。 由于大小是整数，`S // X`正是下一个娃娃的最大有效整数大小。 不需要浮点运算。 

Python 整数还消除了任何溢出问题，尽管输入值已经足够小，32 位有符号整数足以存储值。 

输入仅包含一个测试用例，因此不存在外部测试用例循环。 所需的`sys.stdin.readline`setup 仍然用于快速和传统的竞争性编程输入。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(log_X S)`| 每次迭代都会将当前大小除以`X`， 和`X >= 2`。 |
 | 空间|`O(1)`| 仅存储当前大小、除数和答案。 |

 和`S <= 10^9`和`X >= 2`，在该值达到之前最多有 30 个分区`1`。 因此，即使在最坏的情况下，该算法也只执行几十次迭代，很容易适应一秒的时间限制，并且使用的内存可以忽略不计。

 ## 边缘情况

 对于`S = 1, X = 2`，算法开始于`ans = 1`和`S = 1`。 条件`1 >= 2`为 false，因此循环不执行，输出为`1`。 这可以防止只计算内部玩偶而不计算原始最大玩偶的常见错误。 

为了`S = 9, X = 2`，第一个更新是`9 // 2 = 4`。 以下更新是`4 // 2 = 2`和`2 // 2 = 1`。 算法停止于`1`并返回`4`。 这说明了为什么商必须被视为整数，因为假设的实值链涉及`4.5`是不允许的。 

为了`S = X = 10^9`，初始条件`10^9 >= 10^9`是真的，所以算法接受一个尺寸为内部的娃娃`10^9 // 10^9 = 1`并将答案增加到`2`。 下一个条件失败，因为`1 < 10^9`。 因此输出是`2`，确认边界条件允许内部娃娃完全等于`S / X`。 

为了`S = 5, X = 10`，初始条件`5 >= 10`是假的。 算法立即返回`1`，这是正确的，因为任何正内部整数大小最多必须是`floor(5 / 10) = 0`。 

对于尽可能最大的链，`S = 10^9, X = 2`，该算法在达到`1`，所以原来的娃娃加上那 29 个内部娃娃给出`30`。 即使这种极端情况也只需要对数次操作，这是该解决方案轻松满足约束的核心原因。
