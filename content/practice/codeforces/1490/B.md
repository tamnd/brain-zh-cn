 ## 解决方案
 ## 问题理解

 我们得到一个长度总是能被三整除的数组。 对于每个数字，只有其模 3 的余数才重要。 

一次移动将数组的一个元素加 1。从余数的角度来看，一个数加 1 会沿着循环移动：

 0 → 1 → 2 → 0

 我们的目标是使余数为 0、1、2 的数个数都相等。 由于数组长度可被 3 整除，因此每个余数类最终必须精确包含`n / 3`元素。 

数组中的实际值很大程度上无关。 影响答案的唯一信息是当前有多少数字属于每个余数类别。 如果我们知道计数`c[0]`,`c[1]`,`c[2]`那么任务就变成使用循环余数图周围最便宜的可能传输来平衡这三个桶。 

约束条件非常友好。 所有测试用例的数组元素总数最多为 150,000。 任何处理每个元素恒定次数的算法都足够快。 甚至一个`O(n)`每个测试用例的解决方案在限制内是微不足道的。 不需要动态编程、图形算法或繁重的数据结构。 

当所有多余元素必须经过多个剩余类时，就会出现微妙的边缘情况。 

考虑：```
n = 6
remainders: [0,0,0,0,0,0]
```计数是：```
c0 = 6, c1 = 0, c2 = 0
target = 2
```正确答案是 6。 

两个元素从 0 类移动到 1 类，总共花费 2 次移动。 另外两个元素必须从类 0 移动到类 2。由于没有从余数 0 到余数 2 的直接操作，因此每次这样的转移花费 2 次移动，从而多贡献 4 次移动。 总数为6。 

只直接转移到有缺陷的类的粗心解决方案会错误地计算 4。 

另一个容易犯的错误是在完成一次平衡后停止。 

考虑：```
n = 6
remainders: [2,2,2,2,2,2]
```计数：```
c0 = 0, c1 = 0, c2 = 6
target = 2
```将两个元素从 2 类移动到 0 类需要花费 2 次移动，从而创建：```
c0 = 2, c1 = 0, c2 = 4
```阵列仍然不平衡。 2 类仍然过多，必须再向 1 类发送两个元素。最终答案是 6。单遍重新分配会错过第二次更正。 

当阵列已经平衡时，会出现第三种边缘情况。```
n = 6
a = [0,1,2,3,4,5]
```计数：```
c0 = c1 = c2 = 2
```答案是 0。任何不检查剩余计数而盲目执行转移的解决方案都可能会增加不必要的移动。 

## 方法

 最直接的想法就是模拟个体操作。 每当某个剩余类包含太多元素时，请从该类中选取一个元素并重复增加它，直到达到不足的类。 

这种方法是正确的，因为它完全遵循允许的操作。 问题在于，当只有计数很重要时，我们却在考虑个体数字。 在这个想法的更大变体中，我们可能会执行许多不必要的模拟。 跟踪实际元素不会提供额外信息。 

关键的观察是每个操作仅更改剩余类。 一旦将一项从类中移出，就增加一个数字`r`去上课`(r+1) mod 3`。 

我们可以操作计数，而不是操作元素。 

假设类`i`目前含量超过目标量。 多余的```
c[i] - target
```最终必须离开这个班级。 最便宜的目的地始终是循环中的下一个剩余类，因为一个增量恰好执行该转换。 

每当一个类有多余的元素时，我们将所有多余的元素转移到下一类，为每个转移的元素支付一次移动费用，并更新计数。 这可能会在下一堂课中产生盈余，稍后再处理。 

由于只有三个剩余类别，因此在循环中反复传播多余的部分很快就会达到平衡。 多跑几遍课程就足够了。 标准解决方案执行六次迭代，这保证了任何盈余最多可以在循环中运行两整轮。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 元素的强力模拟 | O(n + 答案) | O(n) | 不必要的缓慢 |
 | 计数重新分配 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算有多少个数组元素的余数为 0、1 和 2 模 3。 
2. 计算每个类别的目标大小：```
target = n / 3
```3. 将答案初始化为零。 
4. 多次迭代剩余类。 六次迭代就足够了，因为只有三个类，并且剩余的可能需要多次循环。 
5. 每个班级`i`，检查是否`c[i] > target`。 
6. 如果过多，让```
extra = c[i] - target
```将所有这些元素移动到类中`(i + 1) % 3`。 
7. 每传输一个元素都需要一个增量，所以添加`extra`到答案。 
8. 更新计数：```
c[i] -= extra
c[(i + 1) % 3] += extra
```9. 所有通过后，计数平衡，累计成本为最小移动次数。 

### 为什么它有效

 唯一允许的操作从剩余类中移动一个元素`r`到余下班级`(r+1) mod 3`并且只花费一步。 每当一个类包含的元素数量超过目标数量时，每个多余的元素最终都必须离开该类。 将多余的部分直接发送到下一类是最便宜的可能操作，因为这正是一个增量所做的事情。 

该算法保持不变式，即除非元素属于剩余类，否则不会移动任何元素。 每次转移都尽可能减少当前阶级的剩余。 如果接收类变得过多，则多余的部分会在稍后传播。 由于盈余只能在循环中向前移动，并且每次移动都只计算一次，因此总成本等于达到平衡计数所需的最小增量数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0, 0, 0]
        for x in a:
            cnt[x % 3] += 1

        target = n // 3
        moves = 0

        for i in range(6):
            r = i % 3

            if cnt[r] > target:
                extra = cnt[r] - target
                cnt[r] -= extra
                cnt[(r + 1) % 3] += extra
                moves += extra

        ans.append(str(moves))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```第一部分计算三个余数计数。 这将问题从阵列平衡任务减少为三桶平衡任务。 

变量`target`存储每个桶所需的大小。 自从`n`能被三整除，不存在舍入问题。 

重新分配循环是解决方案的核心。 每当一个类包含超过`target`元素，所有多余的都被向前推进了一个余数步骤。 每个传输的元素恰好对应一个增量操作，因此`moves`增加相同的量。 

该循环运行六次而不是三次。 一次完整的通过可能会在下一堂课中创造新的盈余。 第二遍允许盈余继续移动。 只有三个剩余类别，六次迭代足以使所有多余的完全传播。 

不存在整数溢出问题，因为与 Python 的整数范围相比，最大答案很小。

 ## 边缘情况

 考虑：```
1
6
0 3 6 9 12 15
```所有数字都属于余数类别 0。 

初始计数：```
(6,0,0)
```目标：```
2
```该算法将四个多余元素从类 0 移动到类 1，成本为 4。计数变为：```
(2,4,0)
```第 1 类现在有盈余 2，转移到第 2 类，成本增加 2。 最终计数：```
(2,2,2)
```总答案：```
6
```这证实了多余的人可能需要通过中级旅行。 

考虑：```
1
6
2 5 8 11 14 17
```初始计数：```
(0,0,6)
```第一次重新分配将四个元素从​​类 2 发送到类 0：```
(4,0,2)
```成本变为4。 

接下来，类 0 向类 1 发送两个多余的元素：```
(2,2,2)
```成本变为6。 

这说明了为什么需要多次通过。 平衡一个阶级可以在其他地方创造新的盈余。

(2,2,2)
```没有班级超过目标。 重新分配循环不执行任何传输，结果仍为 0。这证实了当数组已经平衡时，该算法不会引入不必要的移动。
