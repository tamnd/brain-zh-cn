 ## 解决方案
 ## 问题理解

 我们得到了几个小正整数数组。 对于每个数组，我们可以在任何位置插入新数字，包括在现有元素之间。 插入数字后，我们希望每对相邻元素都是“平滑”的，即两个元素都不超过另一个元素的两倍。 

任务是计算所需插入值的最小数量，以便此条件适用于最终数组中的每个相邻对。 

约束结构很重要。 每个数组最多有 50 个元素，最多有 1000 个测试用例。 这使得总输入大小保持较小，从而允许解决方案为每个相邻对执行少量工作，即使该工作涉及迭代或模拟插入。 n 中的任何三次方仍然可以，但问题的结构表明我们应该瞄准直接的贪婪公式而不是模拟。 

当两个相邻的数字相差很大时，就会出现一个微妙的点。 例如，从 2 移动到 100 无法通过单次插入来修复，因为 100 仍然比 4、8、16 等的两倍大。 关键的困难在于，所需插入的次数取决于我们在范围内重复乘以或除以 2 的次数。 

常见的失败情况是尝试仅插入中点或单个值（如 (a + b) / 2）。例如，在 1 到 100 之间，插入 50 仍然不够，因为 100 比 50 的两倍大。正确的策略需要链接中间值。 

## 方法

 一种简单的方法尝试在本地修复每个坏的相邻对。 每当我们看到两个邻居其中一个大于另一个的两倍时，我们就插入它们的中点并重复，直到条件成立。 这种模拟最终有效，但效率低下，而且概念上很混乱，因为一对上的插入会影响未来的邻接关系，迫使重复扫描。 

在最坏的情况下，如果值增长得像两个差距的幂或更糟，每次修复都会在双方造成新的违规，并且我们最终可能会反复重新访问相同的部分。 尽管 n 很小，但这种方法掩盖了问题的真实结构。 

关键的观察是我们实际上并不关心中间数组状态。 我们只关心使用允许的转换将一个数字转换为另一个数字需要多少步骤，其中每个步骤最多可以将一个值加倍或减半。 在两个相邻值 a 和 b 之间，问题变成：必须插入多少个数字，以便我们可以使用每个连续比率最多为 2 的序列从 a 移动到 b。 

这变成了一个纯粹的比率算术问题。 如果 a ≤ b，我们重复将 a 加倍，直到达到或超过 b。 每次加倍都对应于插入一个弥合间隙的值。 插入次数取决于我们在穿过 b 之前可以乘以 2 的次数，减去一个端点调整。 

这将整个问题简化为独立地对所有相邻对的贡献进行求和。

 ## 算法演练

 我们独立处理每个测试用例。

1. 迭代数组中的每个相邻对。 每对都被视为一个独立的“间隙”，必须使其变得密集。 
2. 对于一对 (x, y)，确定哪个较大。 如果 x 等于 y，则无需执行任何操作，因为条件已满足。 
3. 如果 x 大于 y，从概念上讲，我们希望使用重复加倍从 y 移动到 x。 我们使用临时变量 cur = y 来模拟这个过程。 
4. 虽然 cur * 2 仍然严格小于 x，但我们将 cur 加倍，并为每次加倍计数一次插入。 每次插入都表示放置一个中间值，使比率约束在本地有效。 
5. 将这一对所需的加倍次数添加到全局答案中。 
6. 对所有对重复并输出总和。 

微妙的一点是，当 cur 已经在 x 的 2 倍之内时，我们就停止。 此时，最后一段不需要额外插入数字，因为最终的邻接条件已经满足。 

### 为什么它有效

 两个数字之间的过程独立于其他数字对，因为插入的数字仅影响局部邻接性。 对于任何对 (x, y)，最优解始终构建最短的可能链，其中每个步骤最多乘以 2。任何最优序列都必须传递保持在 2 的幂所限制的几何级数范围内的值，因为跳过必要的中间值将立即违反约束。 这迫使独特的最小长度双链，使贪婪结构达到最佳。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        
        for i in range(n - 1):
            x, y = a[i], a[i + 1]
            
            if x == y:
                continue
            
            if x < y:
                x, y = y, x
            
            cur = y
            while cur * 2 < x:
                cur *= 2
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```代码直接反映了概念过程。 每个相邻对都经过标准化，以便 x 始终是较大的值。 然后，我们通过重复加倍来模拟从较小值向上爬升。 循环条件`cur * 2 < x`确保我们仅在绝对必要时插入中间值； 较早停止会留下超过 2 倍的间隙，而较晚停止则会过多计算不必要的插入。

 ## 边缘情况

 一种重要的边缘情况是两个数字相等。 对于像这样的输入`[7, 7]`，不需要插入，因为比率条件已经成立。 该算法会立即跳过这些对，因此不会执行不必​​要的工作。 

另一种情况是当值已经在因子 2 内但不相等时，例如`[3, 5]`。 尽管 5 不是 3 的 2 的倍数，但比率小于 2，因此不需要插入。 循环条件`cur * 2 < x`确保我们不会插入任何内容，除非存在真正的违规行为。 

一个更有趣的场景是像这样的大差距`[1, 50]`。 该算法重复将 1 加倍为 1 → 2 → 4 → 8 → 16 → 32，然后停止，因为再次加倍将超过或等于 50。这恰好产生所需中间体的最少数量，与任何最佳构造的结构相匹配。
