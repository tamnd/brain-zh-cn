 ## 解决方案
 ## 问题理解

 三个朋友独立评估每个竞赛问题。 对于每个问题，我们都会得到三个值，每个值要么`0`或者`1`。 

值为`1`意味着朋友确信他们知道如何解决问题。 值为`0`意味着他们不自信。 

该团队有一个简单的规则：只有当三个朋友中至少有两个有信心时，他们才会尝试一个问题。 我们的任务是计算有多少问题满足该规则。 

输入开始于`n`，问题的数量。 然后跟随`n`行，每行包含三个二进制值，描述 Petya、Vasya 和 Tonya 对一个问题的看法。 输出是一个整数，即团队将解决的问题数量。 

限制非常小。 最多有 1000 个问题，每个问题仅包含三个数字。 即使是独立处理每个问题的简单解决方案也只执行几千次操作。 任何线性时间解决方案在 2 秒限制内都足够快。 

一个常见的错误是检查是否所有三个朋友都有信心，而不是至少两个朋友。 

例如：```
1
1 1 0
```正确的输出是：```
1
```两个朋友意见一致，所以这个问题应该算。 粗心的实现使用`sum == 3`会错误输出`0`。 

另一个错误是在至少有一个朋友有信心的情况下计算问题。 

例如：```
1
1 0 0
```正确的输出是：```
0
```只有一个朋友有信心，这不符合球队的规则。 

最后一个边缘情况是恰好有两个朋友有信心。```
1
0 1 1
```正确的输出是：```
1
```条件是“至少两个”，而不是“多于两个”。 

## 方法

 最直接的方法是针对每个问题分别进行检查。 对于给定的问题，我们将三个二进制值相加。 由此得出的总和告诉我们有多少朋友有信心。 

如果总和至少为 2，我们就增加答案。 

这种蛮力方法已经足够了，因为只有 1000 个问题。 最坏的情况执行大约 3000 次整数读取和 1000 次加法，这是微不足道的。 

关键的观察结果是输入值是二进制的。 这三个数字的总和正是自信好友的数量。 这意味着我们不需要任何复杂的逻辑或成对检查。 一个简单的补充就可以立即告诉我们团队是否会解决问题。 

由于每个问题都独立且恰好处理一次，因此最佳解决方案是对输入进行简单的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 对于这个问题，强力方法和最优方法实际上是相同的，因为约束非常小并且直接扫描已经是最优的。 

## 算法演练

 1.读取整数`n`，问题的数量。 
2. 初始化`answer = 0`。 
3. 对于每一个`n`问题，读取三个二进制值。 
4. 计算它们的总和。 总和等于对该问题有信心的朋友数量。 
5. 如果总和至少为`2`, 增量`answer`。 

这符合团队的规则，即至少有两个朋友必须确定解决方案。 
6.处理完所有问题后，打印`answer`。 

### 为什么它有效

 对于每个问题，每个自信的朋友都做出了准确的贡献`1`到总和。 由于只有三个朋友，所以总和就是有信心的团队成员的数量。 

当且仅当至少有两个朋友有信心时，团队才能解决问题。 检查总和是否至少为`2`因此完全等同于检查问题的接受条件。 由于我们将此测试应用于每个问题并计算所有成功的问题，因此最终答案是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
answer = 0

for _ in range(n):
    a, b, c = map(int, input().split())
    if a + b + c >= 2:
        answer += 1

print(answer)
```程序首先读取问题的数量。 

对于每个问题，它读取三个二进制值并计算它们的总和。 因为这些值只是`0`或者`1`，这个和直接代表了有多少朋友有信心。 

每当总和至少为`2`，计数器增加。 处理完所有问题后，计数器将准确记录团队将尝试的问题数量。 

不存在棘手的边界条件。 条件必须是`>= 2`， 不是`== 2`，因为三个朋友都自信的问题也应该算在内。

 ## 边缘情况

 考虑恰好有两个朋友有信心的情况：```
1
1 1 0
```该算法计算：```
sum = 1 + 1 + 0 = 2
```自从`2 >= 2`，答案就变成了`1`。 这是正确的，因为团队的规则要求至少有两个有信心的成员。 

现在考虑一个只有一个朋友有信心的问题：```
1
1 0 0
```该算法计算：```
sum = 1
```自从`1 < 2`，答案依然是`0`。 团队没有足够的共识来尝试解决该问题。 

最后，考虑一下所有三个朋友都很自信：```
1
1 1 1
```该算法计算：```
sum = 3
```自从`3 >= 2`，问题就计算出来了。 这证实了条件是“至少两个”而不是“恰好两个”。
