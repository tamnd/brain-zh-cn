 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并要求多次执行特殊转换。 对于数组中的每个元素，我们将其替换为数组中其他任何位置都没有出现的最小非负整数。 此转换同时应用于所有元素，并且我们重复指定的次数。 在所有操作之后，我们被要求提供数组的总和。 

关键的挑战是操作数量可能非常大，高达十亿，并且数组也可能很大，高达二十万个元素。 这排除了任何显式模拟每个操作的解决方案，因为即使单次通过大型数组十亿次也会花费太长时间。 

当数组包含从零到某个最大值且没有间隙的所有整数时，会出现微妙的边缘情况。 在这种情况下，每个元素最终都会收敛到最大元素加一。 另一种边缘情况是数组已包含重复值，或者初始范围内缺少整数。 这些条件以不明显的方式影响转换：一些元素可能在一步后变得恒定，而另一些元素可能会增长。 

例如，考虑数组`[0, 0]`有两个操作。 第一次运算后，每个零都会看到另一个零，因此另一个元素的 MEX 为`1`。 第二次操作后，两个元素再次相遇，MEX 仍然存在`1`。 不考虑收敛的简单实现会浪费时间进一步迭代。 

## 方法

 暴力方法将完全按照描述来模拟操作。 对于每个步骤，我们将根据所有其他元素计算每个元素的 MEX。 对于大小的数组`n`，计算一个元素的 MEX 成本为 O(n)，因此一次完整传递的成本为 O(n^2)。 重复此操作`k`步骤导致 O(n^2 * k)，这对于 n 高达 2×10^5 和 k 高达 10^9 来说是不可行的。 

关键的见解是注意到阵列非常快地稳定下来。 最多两次操作后，数组要么保持不变，要么以可预测的方式增长。 具体来说，第一个操作填充最小的缺失数，第二个操作最多只能产生一个新值，即最大值和 MEX 的平均值的上限。 此后，如果 k 大于 2，进一步的操作不会改变总和。 

我们可以通过识别两个关键值来利用这个属性：数组的当前 MEX 和最大元素。 如果MEX大于最大元素，则每次操作都会用MEX替换元素，所有元素立即收敛到MEX。 否则，每次操作只能创建一个新元素，并且数组最多经过一到两步就稳定下来。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 * k) | O(n^2 * k) | O(n) | 太慢了|
 | 最佳| 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取数组并确定当前MEX和最大元素。 MEX 是不在数组中的最小非负整数。 最大值是数组中的最大值。 
2. 如果MEX大于最大元素，数组立即稳定。 每个小于 MEX 的元素都会在一次操作中被 MEX 替换，但由于所有后续操作都没有效果，因此之后的总和`k`操作是`n * MEX`。 
3. 如果 MEX 小于或等于最大值，则计算新的候选值：`(max + MEX + 1) // 2`。 这表示通过插入新值而不减少任何现有值可以出现的大于 MEX 的最小整数。 如果数组元素尚不存在，则将其添加到数组元素集中。 
4. 添加新值后，数组稳定下来，因为接下来的操作不能产生任何新值； 所有未来的元素要么已经存在，要么新元素成为 MEX 本身。 计算更新后的数组的总和。 
5. 输出总和。 

为什么有效：每个操作都会增加或维护数组中的数字集。 一旦数组包含从 0 到最大值的所有整数，添加`(max + MEX + 1) // 2`是唯一可能的变化，进一步的操作不会改变总和。 这个不变量保证我们不需要模拟所有`k`步骤。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        s = set(a)
        mex = 0
        while mex in s:
            mex += 1
        mx = max(a)
        if k == 0:
            print(sum(a))
            continue
        if mex > mx:
            # All numbers less than mex exist; array will be filled with new mex
            print(sum(a) + k * mex)
        else:
            new_elem = (mx + mex + 1) // 2
            if new_elem not in s:
                s.add(new_elem)
                print(sum(s))
            else:
                print(sum(a))

if __name__ == "__main__":
    solve()
```该解决方案首先使用 O(1) 成员资格检查集有效地计算 MEX 和最大元素。 然后我们检查两种情况：MEX 是否超过最大值。 对于第二种情况，我们计算候选值并仅在它是新的时才添加它。 像 k = 0 这样的边缘情况是单独处理的。 

## 工作示例

 对于数组`[0, 2, 1]`和`k = 3`，初始 MEX 为`3`最大值是`2`。 由于 MEX > max，任意次数运算后的总和为`0 + 2 + 1 = 3`。 阵法立即稳定下来。 

为了`[0, 0]`和`k = 2`，初始 MEX 为`1`最大值是`0`。 MEX > max，因此数组变为`[1, 1]`第一次手术后。 Sum = 2。任何进一步的操作都会将总和保持为 2。 

| 步骤| 数组 | 墨西哥 | 最大| 总和 |
 | --- | --- | --- | --- | --- |
 | 初始| [0,0]| 1 | 0 | 0 |
 | 第一次手术后 | [1,1]| 2 | 1 | 2 |
 | 第 2 次手术后 | [1,1]| 2 | 1 | 2 |

 该迹线证实阵列在一次操作后稳定下来。

 ## 边缘情况

 当k=0时，数组不变。 该算法正确返回初始总和。 

对于 MEX > max 的数组，例如`[0,2,1]`，数组已经稳定并且 sum 立即正确。 对于元素重复的数组，例如`[0,0]`，第一个操作将它们替换为MEX，并且总和更新一次。 该算法通过检查稳定性条件来处理极大的 k，而不是进行不必要的迭代。
