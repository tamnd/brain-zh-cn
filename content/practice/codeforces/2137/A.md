 ## 解决方案
 ## 问题理解

 我们得到了精确运行 Collatz 操作的结果`k`次数和最终值`x`。 任务不是唯一地找到原始值，因为许多不同的起始值可能会导致相同的结果。 我们只需要构造任何起始整数，在恰好之后产生给定的最终值`k`运营。 

操作简单。 如果当前数字是偶数，则下一个数字变为`x / 2`。 如果当前数字是奇数，则下一个数字变为`3x + 1`。 

限制非常小。 两个都`k`和`x`至多是`20`，并且最多有`400`测试用例。 即使是指数结构也很容易拟合。 这表明预期的解决方案不是关于优化，而是关于了解如何逆转该过程。 

主要困难是 Collat​​z 运算并不总是可逆的。 例如，如果我们知道当前值为`4`，之前的值可能是`8`因为`8 → 4`通过偶数规则，或者它可能是`1`因为`1 → 4`通过奇数规则。 

粗心的逆向构造可能会尽可能尝试使用奇怪的前导。 考虑：```
k = 1, x = 5
```等式`(5 - 1) / 3`不是整数，因此没有奇数前驱。 正确答案是`10`， 自从`10 → 5`。 

另一个陷阱是忘记我们只需要一个有效的答案。 为了```
k = 1, x = 4
```两个都`1`和`8`是有效的前任。 寻找所有的可能性是没有必要的。 

当重复反转许多步骤时，会出现第三种微妙的情况。 为了```
k = 5, x = 4
```一种有效的重建是```
4 ← 8 ← 16 ← 32 ← 64 ← 21
```这给出了答案`21`。 反向策略必须保证每个后退步骤都对应于有效的 Collat​​z 前向移动。 

## 方法

 最直接的想法就是暴力。 我们可以尝试每一个可能的起始数字并模拟`k`Collat​​z 运算，直到找到最终值等于给定值的一个`x`。 

这是可行的，因为约束很小，但正确的起始值可能有多大没有明显的上限。 即使对于小`k`，许多候选人需要接受测试。 该方法没有明确的保证。 

关键的观察是我们可以逆转这个过程。 

假设当前值为`y`。 

如果前一个值是偶数，则向前移动将其除以二：```
previous = 2y
```这个前任永远存在。 

如果先前的值为奇数，则：```
3 · previous + 1 = y
```这给出了```
previous = (y - 1) / 3
```但这仅在以下情况下有效`(y - 1)`可以整除`3`结果很奇怪。 

关键的事实是我们不需要每一位前辈。 我们每一步只需要一个有效的前驱。 由于加倍总是会产生有效的前驱，因此我们可以重复应用：```
y ← 2y
```确切地`k`次。 

倒车后`k`如此下去，得到的数为：```
x · 2^k
```从该编号向前运行 Collat​​z 进程会执行`k`连续除以二并精确返回`x`。 

这提供了一个直接的建设性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 无界搜索 | O(1) | O(1) | 不切实际|
 | 最佳| O(k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`k`和`x`。 
2. 处理给定值`x`为所有操作完成后的状态。 
3. 通过选择有保证的前趋来反转 Collat​​z 一步`2x`。 

这始终有效，因为每个偶数在前向过程中都映射为其值的一半。 
4. 完全重复上一步`k`次。 

经过一个反向步骤后，该值变为`2x`，两步后就变成了`4x`，以及之后`k`步骤它变成`x · 2^k`。 
5. 输出结果数。 

### 为什么它有效

 每个反向步骤都会构造一个数字，该数字的向前 Collatz 移动是除以二。 如果我们从`x · 2^k`，第一个操作产生`x · 2^(k-1)`，第二个产生`x · 2^(k-2)`， 等等。 恰好之后`k`我们到达的操作`x`。 

由于每个中间值都是偶数，因此 Collat​​z 过程在每一步都遵循除以二的规则，从而使重建有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    k, x = map(int, input().split())
    print(x * (1 << k))
```该方案直接实现逆向构造。 

对于每个测试用例，我们需要一个数字，其下一个`k`Collat​​z 运算都是除以二的。 乘以`2^k`恰好创建了这样一个数字。 

表达式`1 << k`计算`2^k`有效地使用位移位。 自从`k ≤ 20`，结果非常小，很容易适合 Python 整数。 

不需要模拟。 我们立即构建答案并打印出来。

 ## 边缘情况

 考虑：```
1
1 5
```价值`5`没有有效的奇数前驱，因为`(5 - 1) / 3`不是奇数。 该算法从不依赖于奇怪的前辈。 它只是加倍一次并返回`10`。 运行一个 Collat​​z 步骤给出`10 → 5`，所以答案是有效的。 

考虑：```
1
1 4
```有多个有效的前任，包括`1`和`8`。 算法选择`8`因为加倍总是有效的。 运行一步给出`8 → 4`。 

考虑：```
1
20 20
```该算法返回：```
20 × 2^20 = 20971520
```所有 20 个 Collat​​z 运算均被二除：```
20971520 → 10485760 → ... → 20
```即使在最大允许值下，该结构仍然有效。 

考虑：```
1
5 1
```该算法输出：```
32
```前向序列为：```
32 → 16 → 8 → 4 → 2 → 1
```经过五次运算后，结果就是所需的最终值`1`，确认重复加倍正确地重建了有效的起始数字。
