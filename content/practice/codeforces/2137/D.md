 ## 解决方案
 ## 问题理解

 我们得到了一个数字序列，我们希望将该序列中的每个数字解释为我们必须构造的某些未知数组的频率要求。 具体来说，我们必须构建一个数组`a`使得每个位置`i`包含一个值`a[i]`，以及写入的值`b[i]`必须等于次数`a[i]`出现在整个数组中。 

这创造了一种自我参照的条件。 每个位置并不直接描述其自身的值，而是描述该值应在全局范围内重复多少次。 如果我们分配一个值`x`到某个位置，然后每个位置包含`x`必须就相同的总数达成一致`x`在最终的数组中。 

输出是这样的数组`a`，或不存在一致赋值的声明。 

约束允许跨测试用例最多有 2·10^5 个元素。 这立即排除了每个测试用例的任何二次方。 我们需要一个线性或近线性的结构，可能基于分组或计数频率。 

当值在`b`内部不一致。 例如，如果一个位置要求频率为 2，另一个位置要求频率为 3，但没有足够的位置来同时满足这两个要求，则不存在构造。 当从结构上考虑冲突时会出现另一个问题。 例如，`b = [2, 2, 3]`是不可能的，因为出现 2 次的值不能满足要求出现 3 次的位置，但所有位置都必须属于某个值类别。 

一个小的说明性矛盾是`b = [1, 2, 3]`。 如果我们给要求频率为 3 的位置分配一个值，那么该值必须出现 3 次，但要求为 3 的位置只有一个，没有空间形成一组大小为 3 的组。 

## 方法

 强力尝试将尝试为位置分配值并检查感应频率计数的一致性。 对于每个位置，我们可以猜测一个值，维护一个运行数组，重新计算频率，并验证每个位置是否与其所需的频率相匹配。 即使我们将值限制为`1..n`，这变成组合：每个`n`职位最多为`n`选择，导致分配数量呈指数级增长，甚至每个分配的验证也是线性的。 这远远超出了任何可行的限度。 

关键的观察结果是，该条件仅取决于具有相同指定值的分组索引。 一旦我们决定了一个值`x`被使用`k`次，每个索引分配`x`必须有`b[i] = k`。 这意味着分配相同值的所有位置必须具有相同的`b[i]`，并且此类位置的数量必须等于该值。 

因此，问题简化为按所需频率对索引进行分组，并确保每个组的大小与定义它的值一致。 如果一个频率`k`出现`c`次在`b`，那么那些`c`位置必须分为几组，每一组代表一个完全出现的不同值`k`次。 因此，每组消耗的量恰好是`k`指数，所以`c`必须能整除`k`。 

一旦检查了可行性，构建就很简单：对于每个值`k`，将所有索引与`b[i] = k`，将它们分成大小块`k`，并为每个块分配一个新标签。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 频率分组 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算每个值出现了多少次`k`出现在`b`。 

这告诉我们有多少位置要求某些值必须准确出现`k`次。 
2. 对于每个不同的值`k`,检查是否计数`cnt[k]`可以整除`k`。 

如果不是，我们立即得出结论：不可能进行有效的分组。 

原因是每个有效值分配给有要求的位置`k`必须恰好占据`k`位置，不允许有剩余。 
3. 对于每个有效的`k`，获取索引列表，其中`b[i] = k`。 
4. 将此列表划分为连续的大小块`k`。 每个块对应于最终数组中的一个不同值`a`。 
5. 为每个块分配一个新的唯一整数标签，并将该标签写入该块的所有索引中`a`。 
6. 输出构造好的数组。 

### 为什么它有效

 所有分配相同值的位置都来自具有相同索引的同一组`b[i]`。 每组都有准确的尺寸`k`，因此该组中的每个位置都能正确看到频率`k`在最终的数组中。 由于组是不相交的并且涵盖每个频率类别中的所有索引，因此不同频率值之间不会出现冲突。 可分性条件保证在其频率类别内没有索引是未配对的，从而防止部分组违反定义`f(x)`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        
        pos = [[] for _ in range(n + 1)]
        for i, x in enumerate(b):
            pos[x].append(i)
        
        a = [-1] * n
        ok = True
        label = 1
        
        for k in range(1, n + 1):
            if not pos[k]:
                continue
            if len(pos[k]) % k != 0:
                ok = False
                break
            
            for i in range(0, len(pos[k]), k):
                for j in range(i, i + k):
                    a[pos[k][j]] = label
                label += 1
        
        if not ok:
            print(-1)
        else:
            print(*a)

if __name__ == "__main__":
    solve()
```实施组按所需频率进行索引`b[i]`。 这`pos`结构有效地存储这些组。 对于每个频率`k`，我们在分配标签之前验证整除性。 

一个微妙的点是，标签是按组尺寸引入的`k`，不按值`k`。 这是必要的，因为中有多个不同的值`a`可以共享相同的频率要求，但必须保持可区分以满足组的唯一性。 

嵌套循环为每个块分配一个新的标识符，确保每个组都成为不同的值`a`。 

## 工作示例

 ### 示例 1

 输入：```
n = 6
b = [1, 2, 2, 3, 3, 3]
```我们构建位置桶：

 | k | 职位 |
 | --- | --- |
 | 1 | [0]|
 | 2 | [1, 2] |
 | 3 | [3,4,5]|

 现在我们分配：

 | k | 行动| 标签分配 |
 | --- | --- | --- |
 | 1 | 尺寸为 1 的单块 | a[0] = 1 |
 | 2 | 块 [1,2] | a[1]=2, a[2]=2 | a[1]=2, a[2]=2 |
 | 3 | 块 [3,4,5] | a[3]=3，a[4]=3，a[5]=3 |

 最终数组：```
[1, 2, 2, 3, 3, 3]
```这表明每个构造值出现的次数与所有具有该要求的位置所要求的次数完全相同。 

### 示例 2

 输入：```
n = 4
b = [1, 2, 3, 4]
```桶：

 | k | 职位 |
 | --- | --- |
 | 1 | [0]|
 | 2 | [1] |
 | 3 | [2] |
 | 4 | [3] |

 我们检查整除性：

 | k | 计数| k 除数？ |
 | --- | --- | --- |
 | 1 | 1 | 是的 |
 | 2 | 1 | 没有|

 自从`1 % 2 != 0`，施工立即失败。 

这表明分组可行性中的单个不匹配会使整个构造无效，即使其他值看起来局部一致。

 ## 边缘情况

 当所有值都相同时会出现一种边缘情况，例如`b = [n, n, n, ..., n]`。 该算法将所有索引放入一个桶中并验证`n % n == 0`，它成立，产生一个单一的群。 每个索引都接收相同的标签，并且结果数组满足条件，因为每个值都完全出现`n`次。 

另一种边缘情况是当值大部分都很小时但出现一个大的要求时，例如`b = [1, 1, 1, 4]`。 桶用于`4`大小为 1，不能被 4 整除，因此算法立即拒绝。 任何为该位置分配值的尝试都需要出现四次，因为该类中只有一个候选位置，这是不可能的。 

最终的结构边缘情况是交错的有效组，例如`b = [2, 2, 1, 1, 1, 1]`。 这里两个桶都满足整除性：两个位置`2`, 四个为`1`。 该算法正确地将它们分为一组大小为 2 的组和一组大小为 4 的组，并独立分配不同的标签。 这证实了跨频率类别的独立性是足够的，因为没有约束链接不同的值`k`在最后的施工中。
