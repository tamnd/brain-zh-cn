 ## 解决方案
 ## 问题理解

 我们有一个矩形行星，分为多个单元。 有些单元可以用于建造，有些则被封锁。 目标是建造尽可能最大的船。 该船呈十字形，由五个相等的正方形组成：一个正方形位于中心，四个侧面各附有一个正方形。 如果每个正方形的边长是`k`，整个十字占据了`3k × 3k`区域，但只有该区域的中央行块和中央列块必须可用。 

输入给出网格的高度和宽度，后跟网格本身。 一个`#`细胞可用于建筑，而`.`细胞不能。 输出是最大值`k`存在该十字的某些位置。 该声明保证一艘尺寸至少为`1`总是可以建造的。 

网格尺寸可达`2000 × 2000`，释放多达四百万个细胞。 尝试每个可能的中心并一次将跨层扩展的解决方案可以接近数十亿次操作，这对于典型的一秒限制来说太多了。 我们需要一种与细胞数量接近线性或接近线性的方法。 因为答案最多是`min(n, m) / 3`，二分查找的对数因子是可以接受的。 

棘手的情况大多与十字架的几何形状有关。 一艘有尺寸的船`k`不只是正常的`k × k`正方形，因此仅检查中心正方形会给出错误的答案。 例如：```
3 9
...###...
...###...
#########
```正确答案是`1`，因为中间行可用但垂直部分不能有高度`3`。 一个粗心的解决方案，仅检查是否存在`3 × 3`阻止某个地方会失败。 

另一种边缘情况是当十字接触边界时。 例如：```
5 5
..#..
.###.
#####
.###.
..#..
```正确答案是`1`。 中心的正方形可以放置，但没有足够的空间放置更大的十字架。 假定候选十字中心的实现必须具有`k`周围的空行和空列可能会意外跳过有效的边框位置。 

最后一个常见的错误是将整个图形的大小与一个正方形的大小混淆。 对于一艘大小的船`k`，总边界框为`3k × 3k`， 不是`k × k`。 

## 方法

 直接的方法是尝试每个可能的值`k`，每个可能的中心位置，并检查十字的所有五个方块。 这是正确的，因为船舶定义正是这五个方块的并集。 然而，检查单个候选人的交叉成本`O(k²)`，并且可以有`O(nm)`可能的中心和`O(min(n,m))`可能的尺寸。 在最坏的情况下，这变得太大了。 

关键的观察是对于固定的`k`，我们不需要检查每个候选者的每个单元格。 我们只需要回答是否某个`k × k`正方形是完全可以建造的。 这可以使用二维前缀和在恒定时间内完成。 

一旦我们可以检查固定的`k`，我们可以二分查找答案。 如果十字尺寸`k`存在，每个较小的尺寸也可以通过取该十字架的中心部分来建造。 这种单调属性意味着可能的答案集看起来像`true, true, ..., true, false, false, ...`，这正是二分查找所需要的。 

暴力破解之所以有效，是因为它直接检查定义，但失败是因为它多次重复几乎相同的区域检查。 前缀和消除了重复的工作，二分搜索消除了测试每个可能的大小的需要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下为 O(nm·min(n,m)³) | O(1) | O(1) | 太慢了 |
 | 二分查找+前缀和 | O(nm log(min(n,m))) | O(nm log(min(n,m))) | O(纳米) | 已接受 |

 ## 算法演练

 1. 构建一个二维前缀和数组，其中每个位置存储矩形中从左上角到该位置的可用单元格数量。 

前缀和让我们可以查询在恒定时间内任意矩形内有多少个被阻止的单元格。 当矩形的可用单元数等于其面积时，矩形对于构造来说是有效的。 

1.二分查找边长`k`十字中的一个正方形。 

下限开始于`1`因为保证存在一个解决方案。 上限是`min(n, m) // 3`，因为整个十字架在两个维度上都占据了三个这样的正方形。 

1. 对于候选人`k`，扫描中心的所有可能位置`k × k`正方形。 

中心方格必须有四个相邻的方格`k × k`方块：上、下、左、右。 如果所有五个矩形仅包含可用单元格，则大小的十字`k`存在。 

1. 如果检查成功，则将二分查找向上移动。 否则，将其向下移动。 

较大的十字架包含较小十字架的所有要求，因此一种尺寸的失败意味着每个较大的尺寸也会失败。 

1、二分查找结束后，输出最大的成功值。 

### 为什么它有效

 对于每个测试尺寸`k`，检查程序精确检查定义有效船舶的五个方块。 前缀和给出了每个方格中可用单元格的确切数量，因此当且仅当其中的每个单元格都可用时，方格才被接受。 

二分查找是正确的，因为谓词“a cross of size`k`存在”是单调的。如果大小的交叉`k`存在，取内`k' × k'`任何较小的零件`k'`创建一个更小的有效交叉。 如果某个尺寸不合格，则无法容纳更大的尺寸，因为每个较大的交叉都将包含较小的无效要求。 因此二分查找找到最大可能的大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n):
        row_sum = 0
        for j in range(m):
            if grid[i][j] == '#':
                row_sum += 1
            pref[i + 1][j + 1] = pref[i][j + 1] + row_sum

    def rect_sum(r1, c1, r2, c2):
        return pref[r2][c2] - pref[r1][c2] - pref[r2][c1] + pref[r1][c1]

    def good_square(r, c, k):
        return rect_sum(r, c, r + k, c + k) == k * k

    def check(k):
        for r in range(n - 3 * k + 1):
            for c in range(m - 3 * k + 1):
                if good_square(r, c + k, k):
                    if (good_square(r + k, c, k) and
                        good_square(r + k, c + k, k) and
                        good_square(r + k, c + 2 * k, k) and
                        good_square(r + 2 * k, c + k, k)):
                        return True
        return False

    lo, hi = 1, min(n, m) // 3
    ans = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```前缀构造存储仅对可用单元进行计数。 这使得矩形查询独立于矩形大小，这是重复检查每个单元格的主要优化。 

这`good_square`函数将候选方格中可用单元格的数量与`k * k`。 如果它们相等，则该正方形中的每个单元格都可用。 

这`check`函数仅迭代完整的位置`3k × 3k`边界框适合。 这五个呼召直接对应于十字架的五个块。 保持中心广场在`(r + k, c + k)`避免了相差一的错误，因为周围的块自然地精确偏移`k`。 

Python 整数在这里不会溢出，但乘法会溢出`k * k`仍保留为整数表达式，因为前缀值表示单元格计数。

 ## 边缘情况

 对于边界情况：```
5 5
..#..
.###.
#####
.###.
..#..
```二分查找首先尝试更大的值，但是`check(1)`是唯一成功的调用。 检查尺寸时`2`, 一切可能的`4 × 4`边界框需要缺少一个单元格，所以答案仍然存在`1`。 

对于假方情况：```
3 9
...###...
...###...
#########
```前缀和正确拒绝大小的垂直正方形`3`。 虽然有一个很大的水平区域，但十字的四个边正方形并不全部存在，因此算法返回`1`。

...###...
