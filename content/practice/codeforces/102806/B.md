 ## 解决方案
 ## 问题理解

 我们有一个序列`n`珍珠一颗一颗的产出。 第二次生产的珍珠的颜色`i`被给出。 有效的引擎组必须包含每种颜色的一颗珍珠，因此它始终包含`k`珍珠。 一组珍珠的生产时间必须接近：该组中最早和最晚的珍珠最多可能相差`m`秒。 每颗珍珠只能使用一次。 任务是构建尽可能多的这样的集合并输出每个集合中珍珠的索引。 

输入包含生产的珍珠数量、最大允许时间差、颜色数量，以及生产订单中每颗珍珠的颜色。 输出从完整集的最大数量开始，然后是为每个集选择的索引。 

限制很大：两者`n`和`k`可以达到`100000`。 重复扫描所有颜色或所有先前珍珠的每个位置的算法将变得二次并且无法完成。 我们需要一种解决方案，使每颗珍珠仅被处理固定次数。 

主要的边缘情况来自颜色可用性和时间窗口之间的相互作用。 如果当前窗口中缺少一种颜色，即使其他颜色丰富也无法形成集合。 例如：```
6 2 3
1 2 2 1 3 3
```第一个可能的集合是由珍珠组成的`4, 3, 5`，因为它们的颜色是`1, 2, 3`时间差是`5 - 3 = 2`。 一个粗心的解决方案，只计算每种颜色出现的次数，会期望有两组，因为每种颜色出现两次，但时间限制阻止了它。 

另一个棘手的情况是，当一种颜色的最后一个珍珠位于当前窗口之外，而较早出现的其他颜色仍然存在时。 例如：```
5 2 3
1 2 2 2 3
```彩色珍珠总数足够了`2`，但只有一颗彩色珍珠`1`而且现在看来还为时过早。 答案是`0`。 仅跟踪全局计数的解决方案将错误地产生肯定的答案。 

## 方法

 一个直接的方法是尝试每一个可能的组`k`珍珠并检查它是否包含所有颜色并且在期限内。 这是正确的，因为它准确地测试了有效集合的定义。 然而，最多可以有`100000`珍珠，因此即使查看许多可能的窗口并快速检查所有颜色也会变得太慢。 在最坏的情况下，扫描每个位置的所有颜色都会产生成本`O(nk)`运营。 

问题的结构给出了更好的方向。 有效的集合必须包含在长度为移动的窗口内`m + 1`职位。 当从左到右扫描珍珠时，我们只需要知道每种颜色当前有哪些未使用的珍珠位于该窗口内。 如果每种颜色至少有一颗可用珍珠，则立即选取每种颜色中最旧的可用珍珠创建一组有效珍珠。 

取最旧的珍珠有效的原因是当前窗口已经保证所有存储的珍珠都足够接近当前位置。 使用较旧的珍珠不会使未来的设置变得更糟，因为保留较新的珍珠可以为以后的窗口提供更大的灵活性。 创建一组后，这些珍珠将从其颜色队列中删除，并继续扫描。 

蛮力方法之所以有效，是因为它会检查所有可能性，但它会多次重复相同的工作。 滑动窗口队列将问题简化为仅维护仍然可以参与未来答案的信息。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了 |
 | 最佳 | O(n + k) | O(n + k) | 已接受 |

 ## 算法演练

 1. 为每种颜色创建一个队列。 每个队列存储活动时间窗口内当前可用的该颜色珍珠的索引。 还要保留一个计数器，记录当前有多少种颜色具有非空队列。 
2. 从左到右处理珍珠。 当珍珠`i`出现时，将其索引添加到其颜色的队列中。 如果该颜色队列在插入之前为空，请增加可用颜色的数量。 
3. 取出不再位于窗口内的珍珠。 处理索引时`i`，最旧的允许索引是`i - m`，所以索引`i - m - 1`如果存在则必须将其删除。 如果删除它会使颜色队列变空，请减少可用颜色的数量。 
4.如果全部`k`颜色队列非空，从每个队列中取出第一个元素。 这些`k`珍珠具有不同的颜色，并且都位于当前窗口内，因此它们形成了一个有效的集合。 存储它们的索引并将它们从队列中删除。 
5. 继续，直到所有珍珠都加工完毕。 存储的组是最大可能的组数。 

为什么它有效：

 每时每刻，每个队列都恰好包含一种颜色的未使用珍珠，这些珍珠仍然可以在以当前位置结束的集合中使用。 仅当每种颜色至少有一个候选颜色时才能创建一个集合，因此该算法恰好在当时存在有效选择时创建一个集合。 获取每种颜色中最早的候选者是安全的，因为队列中的所有候选者都满足相同的时间限制，并且删除最早可用的珍珠将为未来的窗口留下最新的珍珠。 因此，每个创建的集合都使用无法被更好的选择替代的珍珠，并且贪婪过程永远不会减少未来可能的集合的数量。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    colors = list(map(int, input().split()))

    queues = [deque() for _ in range(k)]
    non_empty = 0
    ans = []

    for i, c in enumerate(colors):
        c -= 1

        if not queues[c]:
            non_empty += 1
        queues[c].append(i + 1)

        old = i - m - 1
        if old > 0:
            oc = colors[old - 1] - 1
            queues[oc].popleft()
            if not queues[oc]:
                non_empty -= 1

        if non_empty == k:
            cur = []
            for q in queues:
                cur.append(q.popleft())
            ans.append(cur)

            non_empty = 0
            for q in queues:
                if q:
                    non_empty += 1

    out = [str(len(ans))]
    for group in ans:
        out.append(" ".join(map(str, group)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```队列数组是滑动窗口思想的直接实现。 队列`c`包含当前可用的彩色珍珠的位置`c`。 

当读取新珍珠时，它会被添加到其颜色队列中。 去除步骤使用`i - m - 1`因为索引在存储的答案中是从一开始的，但在循环中是从零开始的。 正是一颗珍珠`m`远一点的位置仍然有效，而远一点的珍珠则无效。 

当所有队列都非空时，选择每个队列的前面。 正面代表该颜色最古老的可用珍珠。 从所有队列中删除这些选定的珍珠为寻找下一个独立集合的结构做好准备。 

变量`non_empty`避免每次插入后扫描所有颜色。 仅当队列在空状态和非空状态之间变化时才会更新，从而保持整个算法的线性。

 创建的集合包含索引`4 3 5`。 其最早的索引是`3`最新的是`5`，所以差异恰好是`2`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + k) | 每颗珍珠进入一个队列一次，最多离开一次。 |
 | 空间| O(n + k) | 队列存储所有当前未使用的珍珠，并且有`k`队列。 |

 该解决方案仅对每颗珍珠执行恒定的工作，这符合`100000`元素限制。 内存使用也是线性的，因为每个珍珠索引最多存储一次。

 ## 边缘情况

 当每种颜色出现足够多的次数但外观是分开的时，全局计数会产生误导。 为了：```
6 2 3
1 2 2 1 3 3
```颜色计数表明有两种可能的组合。 在扫描过程中，算法仅将珍珠保持在一定距离内`2`当前位置。 在索引处`5`，可用队列包含颜色`1`,`2`， 和`3`，所以它创建了集合`4, 3, 5`。 剩余颜色`3`不能与另一个完整的组配对。 

当所需的颜色仅存在于窗外过去时，则必须将其丢弃。 为了：```
5 2 3
1 2 2 2 3
```索引处的珍珠`1`有颜色`1`。 到时候颜色`3`珍珠到达指数`5`，有效窗口从索引处开始`3`，所以颜色`1`队列为空。 该算法在检查一组之前删除过时的珍珠，因此它永远不会创建无效的组。 

当所有珍珠都具有相同颜色时，除非只有一种颜色，否则任何珍珠组都不完整。 为了：```
6 3 2
1 1 1 1 1 1
```第二个颜色队列永远不会变为非空。 这`non_empty`柜台保持在下方`k`，算法正确返回`0`。
