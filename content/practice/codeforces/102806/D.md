 ## 解决方案
 ## 问题理解

 我们有几种蚂蚁类型。 类型`i`有`a[i]`蚂蚁可用。 在一次移动中，丹尼可以扔掉一些蚂蚁，但同时存在两个限制：移动中蚂蚁的总数不能超过`m`，并且从任何单一类型中取出的蚂蚁数量不能超过`k`。 

目标是找到所需的最少移动次数，以便至少`p`蚂蚁被扔掉了。 

输入包含多个测试用例。 对于每种情况，该数组描述了每种蚂蚁类型的数量，后跟必须移除的蚂蚁的目标数量。 输出是可以实现该目标的最小移动次数。 

全部的总和`n`测试用例的值最多是`10^6`。 这排除了任何处理每种类型的许多可能的移动计数的情况。 解决方案围绕`O(n log answer)`是合适的，因为`log`可能的答案很小，而`O(n * answer)`当蚂蚁数量很多时，这是不可能的。 

的价值观`a[i]`,`m`,`k`， 和`p`可以比 32 位整数大得多，因此在重要的语言中，实现必须使用 Python 整数或 64 位算术。 

一个常见的错误是只考虑总移动能力。 例如：```
1
2 10 1
100 100
150
```答案不是`15`， 虽然`15 * 10 = 150`蚂蚁可投掷的总容量。 每次移动只能从一种类型中带走一只蚂蚁，所以`15`每种类型最多贡献的动作`15`蚂蚁。 真正的最大值是`30`，所以正确的输出是：```
100
```另一种边缘情况是一种类型几乎包含所有蚂蚁：```
1
3 5 100
1000 1 1
10
```答案是`2`，因为总移动限制就是限制。 仅考虑每种类型限制的解决方案可能会高估移动次数。 

## 方法

 一种直接的方法是尝试所有可能的移动次数并模拟可以扔掉多少只蚂蚁。 对于固定次数的移动`x`，每种类型最多可以贡献`min(a[i], x * k)`蚂蚁，因为类型限制在每一步中独立适用。 我们也会有全球限制`x * m`蚂蚁。 检查所有可能的值`x`将它们一一增加在概念上是有效的，但答案可能非常大。 如果`p`就在附近`10^18`，尝试所有值以获得答案的速度太慢。 

The key observation is that if`x`步数足够了，那么任何更多的步数也足够了。 这种单调属性允许对答案进行二分搜索。 

对于固定的`x`，最多可以投掷的蚂蚁数量为：```
min(x * m, sum(min(a[i], x * k)))
```第一项限制了所有动作中蚂蚁的总数。 第二项分别限制每种类型。 这两个限制完全描述了最大可能数量，因为每种类型都可以独立地分布在同一组移动中，直到其供应或其每次移动限制耗尽。 

可行性检查变为线性`n`。 二分查找找到最小的`x`检查成功的地方。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n * 答案) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n 对数答案) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.二分查找之间的答案`1`和足够大的上限。 搜索值代表我们正在测试的移动次数。 
2. 对于中间值`x`,计算最多可以扔进去的蚂蚁数量`x`移动。 对于每种蚂蚁类型，添加`min(a[i], x * k)`因为这是该类型所能做出的最大贡献。 累计达到后停止添加`p`，因为较大的值不会影响决策。 
3. 将计算总数限制为`x * m`，因为即使存在足够多的蚂蚁，移动能力也不能超过。 
4. 如果抛出的蚂蚁的最大可能数量至少为`p`，继续寻找更小的答案。 否则，丢弃较小的值并搜索较大的一半。 
5. 返回通过可行性检查的第一个移动计数。 

为什么有效：二分查找依赖于单调属性。 如果`x`动作就够了，那么`x + 1`移动也足够了，因为我们总是可以不使用额外的移动。 可行性函数精确计算了可能存在的最大蚂蚁数量`x`移动，因此第一个可行值是最小有效答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    p = int(input())

    def can(x):
        total = 0
        limit = x * k
        for v in a:
            total += v if v < limit else limit
            if total >= p:
                return True
        return min(total, x * m) >= p

    lo, hi = 1, (p + m - 1) // m
    hi = max(hi, 1)

    while not can(hi):
        hi *= 2

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid):
            hi = mid
        else:
            lo = mid + 1

    return str(lo)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_case())
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```可行性函数是解决方案的核心。`x * k`计算一次，因为每种类型都有相同的每次移动限制。 对于每种类型，贡献都受到可用蚂蚁和此限制的限制。 

金额达到后提前返还`p`避免对大型案例进行不必要的工作。 决赛`min(total, x * m)`应用总容量限制。 之所以可以安全地将其推迟到最后，是因为类型贡献仅用于确定总供给侧限制是否能够满足目标。 

初始上限来自于至少`ceil(p / m)`如果唯一的限制是总移动能力，那么移动总是必要的。 加倍循环处理每种类型的限制需要更多移动的情况。 

Python 整数在乘以大值时避免溢出，例如`x * k`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log A) | O(n log A) | 每个二分搜索步骤都会扫描所有蚂蚁类型，并且`A`是答案范围。 |
 | 空间| 除了输入存储之外，O(1) | 仅需要计数器和二分搜索变量。 |

 ## 边缘情况

 对于第一个边缘情况：```
1
2 10 1
100 100
150
```粗心的解决方案可能会导致分裂`p`经过`m`并返回`15`。 算法测试`15`移动和计算每种类型只能贡献`15`蚂蚁, 给予`30`总计，因此它拒绝该值。 二分查找一直持续到`75`，其中每种类型都有贡献`75`蚂蚁和目标变得可以到达。 

对于第二种边缘情况：```
1
3 5 100
1000 1 1
10
```每种类型的限制不是限制性的，因为一次移动可能需要最多`100`蚂蚁来自一种类型，但总移动能力仅为`5`。 可行性检查对于一次移动返回 false，对于两次移动返回 true，给出正确答案`2`。 

对于相等的值：```
1
5 4 2
1 1 1 1 1
5
```类型限制每次移动每种类型允许两只蚂蚁，但总容量限制每次移动最多四只蚂蚁。 一步不能消除所有五只蚂蚁，而两次移动可以消除它们，因此算法返回`2`。 

对于最小情况：```
1
1 100 100
7
7
```只有一种类型和一种可能的动作。 类型容量和移动容量都足够大，因此第一个成功的二分查找值是`1`。
