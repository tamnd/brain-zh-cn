 ## 解决方案
 ## 问题理解

 电梯始终显示两位数的楼层号`00`到`99`。 每个数字均使用七段显示器绘制。 

一个片段可能会被破坏。 当某个部分损坏时，即使应该点亮也无法点亮。 关键的观察是，损坏的段只能将预期点亮的段变成不亮的段。 它们永远无法产生额外的光。 

我们得到了显示屏上当前可见的两位数字。 我们必须数一下原来的楼层数有多少`x`从`00`到`99`在某些段子集损坏后可能会产生这个可见的数字。 

由于显示始终包含两位数，因此十位和个位是独立的。 地板如`03`必须被视为两位数`0`和`3`，不作为整数`3`。 

限制很小。 原始楼层号只有 100 个可能。 即使我们将每个候选人与显示的数字逐位、逐段进行比较，总的工作量也可以忽略不计。 几千次操作就足够了。 

错误的主要来源是误解破碎段的行为方式。 

考虑输入：```
88
```显示的数字`8`使用全部七个段。 由于由于破损而无法出现额外的段，因此原始数字也必须是`8`。 因此只有`88`和`89`可以生产`89`， 因为`9`不同于`8`恰好有一个可能被破坏的部分。 

另一个容易犯的错误是忘记前导零。 

对于输入：```
00
```候选人`08`是有效的。 正确的数字`8`可能会丢失除所需的段之外的所有段`0`。 如果我们将楼层存储为普通整数并忽略前导零，我们就会错过这种可能性。 

第三个微妙的情况是假设如果显示的片段是原始片段的子集，则候选者在全局范围内有效。 必须对两个数字位置分别进行检查。 例如，即使个位数字兼容，十位数字也可能不兼容。 

## 方法

 最直接的解决办法就是测试每一个可能的原始楼层号`00`到`99`。 

对于候选号码，将其两位数字中的每一位与相应显示的数字进行比较。 如果在显示数字中点亮的每个段也在原始数字中点亮，则可以从原始数字实现显示数字。 

假设显示屏中的某个段亮起，但原始数字未亮起。 这需要一个断裂的部分来产生光，这是不可能的。 这样的候选人必须被拒绝。 

这种蛮力方法已经足够快了。 只有100名候选人。 每位考生需要检查两个数字，每个数字包含七个部分。 总工作量约为`100 × 2 × 7 = 1400`段比较。 

关键的观察结果是，段故障只会删除点亮的段。 如果我们用应该打开的一组段来表示每个数字，那么显示的数字`d`可以来自原始数字`o`确切的时间：`segments(d)`是一个子集`segments(o)`。 

这将问题转化为数字之间的简单兼容性测试。 我们可以预先计算，对于每个显示的数字，有多少个原始数字可以产生它。 

由于该号码由两个独立的位置组成，因此有效楼层号码的总数等于：`compatible[tens] × compatible[ones]`。 

这避免了枚举所有 100 个楼层号并导致更简单的实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(100 × 14) | O(1) | O(1) | 已接受 |
 | 最佳 | O(10²) 预处理 + O(1) 查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 段表示

 我们通过为该数字点亮的七段来对每个十进制数字进行编码。 

例如：`0 = "1111110"`

`1 = "0110000"`等等。 

字符串中的每个位置对应于显示的一个段。 

### 兼容的原始数字数量

 1. 对于每个显示的数字`d`从`0`到`9`，初始化一个计数器。 
2. 对于每一个可能的原始数字`o`从`0`到`9`，检查是否`d`可以从`o`。 
3. 要验证兼容性，请检查所有七个部分。 
4. 如果某段亮起`d`但未点亮`o`，拒绝该对，因为断裂的片段不能产生光。 
5. 否则，该对有效，因此增加计数器`d`。 

兼容性条件正是点亮段上的子集条件。 

### 处理输入数字

 1. 读取显示的两位数字。 
2.设第一个数字为`a`第二位数字是`b`。 
3. 两个位置是独立的，因此有效的原始楼层号总数等于：`count[a] × count[b]`。 
4. 输出结果。 

### 为什么它有效

 对于任何数字位置，显示的段只有在最初点亮的情况下才能保持点亮。 损坏的灯段可能会关闭点亮的灯段，但不能以产生新光的方式选择性地关闭灯段。 因此，当所有点亮的段都已经属于原始数字时，就可以精确地实现显示的数字。 

十位和个位使用单独的显示，因此一个位置的故障不会影响另一个位置。 每个有效的原始十位数字都可以与每个有效的原始个位数字组合。 因此，将计数相乘即可准确得出有效的两位数楼层号码的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

SEG = [
    "1111110",  # 0
    "0110000",  # 1
    "1101101",  # 2
    "1111001",  # 3
    "0110011",  # 4
    "1011011",  # 5
    "1011111",  # 6
    "1110000",  # 7
    "1111111",  # 8
    "1111011",  # 9
]

count = [0] * 10

for shown in range(10):
    for original in range(10):
        ok = True
        for k in range(7):
            if SEG[shown][k] == '1' and SEG[original][k] == '0':
                ok = False
                break
        if ok:
            count[shown] += 1

s = input().strip()

a = int(s[0])
b = int(s[1])

print(count[a] * count[b])
```第一部分存储每个数字的七段模式。 一个`'1'`表示该段已点亮。 

预处理循环计算有多少个原始数字可以产生每个显示的数字。 条件```
SEG[shown][k] == '1' and SEG[original][k] == '0'
```检测到一种不可能的情况，即显示屏显示原始数字从未有过的亮段。 

预处理后，立即求解实际输入。 我们读取显示的两个数字，查找每个位置的兼容原稿数量，然后将它们相乘。 

一个常见的错误是颠倒兼容性检查。 我们必须验证显示数字中的每个亮起的段也存在于原始数字中，而不是相反。 

另一个常见错误是将整个输入转换为整数。 输入`"03"`必须保留两个字符的字符串，以便保留前导零。

import sys, io

SEG = [
    "1111110",
    "0110000",
    "1101101",
    "1111001",
    "0110011",
    "1011011",
    "1011111",
    "1110000",

def solve():
    count = [0] * 10

    for shown in range(10):
        for original in range(10):
            ok = True
            for k in range(7):

    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

 ## 边缘情况

 考虑输入：```
00
```对于每个位置，显示的数字是`0`。 仅原始数字`0`和`8`包含所需的所有段`0`。 该算法计算的计数为`2`对于每个位置和返回`2 × 2 = 4`。 将输入视为整数`0`而不是字符串`"00"`会丢失一位数字并产生错误的答案。 

考虑输入：```
88
```每个部分都会亮起。 任何原始数字即使缺少一个片段也不能产生一个`8`，因为破碎的片段只会去除光。 预处理给出`count[8] = 1`，所以答案就变成了`1 × 1 = 1`。 这捕获了错误地允许段出现的实现。 

考虑输入：```
89
```十位数`8`仅有一个兼容源，即`8`。 个位数字`9`有两个兼容的来源，`8`和`9`。 乘法产量`2`。 该算法独立处理每个数字位置，这是正确的，因为显示是分开的。
