 ## 解决方案
 ## 问题理解

 凯文有几种炸玉米饼类型。 每种类型都有一个正常的购买价格，并且他还知道一组可能的交换。 一家交易所表示，如果他目前拥有一份类似类型的炸玉米饼`i`，他可能会支付一些金额并收到一份类似类型的炸玉米饼`j`。 交换可以重复进行，并且不必双向进行。 

目标是在支付尽可能低的金额的情况下购买所需数量的每种类型的炸玉米饼。 输入给出了炸玉米饼类型的数量、交换规则、直接购买每种类型的成本以及每种类型所需的炸玉米饼数量。 输出是满足所有请求数量所需的最小总金额。 

限制足够大，不可能检查每个可能的交换序列。 最多可以有`10^4`炸玉米饼类型和`10^5`交流。 尝试所有炸玉米饼类型对的解决方案已经需要大约`10^8`操作，并且模拟可能的交换路径会更糟糕，因为路径可以任意长。 交换价格是非负的，这强烈表明最短路径技术是合适的。 

一个微妙的情况是直接购买玉米卷类型并不便宜。 例如，假设输入是：```
2 1
10
1
0 1 1
0
5
```答案是`5`， 不是`50`。 粗心的解决方案可能会认为每个请求的炸玉米饼都应该直接购买。 在这里，购买类型`1`成本`1`，但购买类型`0`以及交换成本`10 + 1`，所以直接价格还是比较好。 该示例表明，每个目标类型都需要独立评估，而不是假设交换总是有用的。 

另一个棘手的情况是最佳起始炸玉米饼与目标炸玉米饼不同。 考虑：```
3 2
100
5
100
0 1 1
1 2 1
0
0
3
```答案是`21`。 三型`2`炸玉米饼可以通过购买类型制作`1`为了`5`并交换两次，成本为`7`每个。 仅检查直接购买或一次交易所的方法会错过这条路径。 

最后一个边缘情况是没有交换时：```
2 0
4
7
3
2
```答案是`26`。 每个炸玉米饼都必须直接购买，因为不同类型之间不可能移动。 该算法必须允许炸玉米饼类型使用自己的购买价格作为有效的起点。 

## 方法

 直接的方法是单独考虑每个请求的炸玉米饼类型。 对于目标类型`j`，我们可以尝试每一种可能的起始类型`i`，找到最便宜的交换路径`i`到`j`，并取最小值`cost[i] + path_cost`。 这是正确的，因为每个炸玉米饼最终都必须来自直接购买的炸玉米饼，然后进行零次或多次交换。 

问题是最短路径计算的数量。 从每种炸玉米饼类型运行图形搜索需要`10^4`在图表上搜索`10^5`边缘。 即使使用 Dijkstra 算法，这也太慢了，因为复杂度变得粗略`O(t * (t + e) log t)`，远远超出了极限。 

关键的观察是我们不需要分别知道每个目的地的最佳来源。 当可以先购买任何起始炸玉米饼时，我们只需要以最便宜的方式到达每个目的地。 这与添加连接到每个 taco 类型的虚拟源节点完全相同，其边缘等于其购买价格。 从该虚拟源到每种类型的炸玉米饼的最短距离给出了获取每种类型的炸玉米饼的最便宜的方法。 

我们可以使用优先级队列中已有的每种 taco 类型来初始化 Dijkstra，而不是显式创建此节点。 类型的初始距离`i`是它的直接购买价格。 然后每个交换边缘正常松弛。 由于交换描述了从我们拥有的 taco 到我们想要的 taco 的移动，因此最短路径需要直接遵循交换方向。 

比较结果为：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(t(t + e) log t) | O(t(t + e) log t) | O(t + e) | 太慢了 |
 | 最佳 | O((t + e) log t) | O(t + e) | 已接受 |

 ## 算法演练

 1. 阅读每种炸玉米饼的直接购买价格和兑换规则。 构建一个图，其中一条边`i -> j`重量等于交换炸玉米饼的成本`i`进入炸玉米饼`j`。 
2. 用其直接购买价格初始化每种 taco 类型的最短距离。 使用此初始值将每个 taco 类型插入优先级队列。 这将每种炸玉米饼类型都视为最终购买的可能起点。 
3. 在交换图上运行 Dijkstra 算法。 每当炸玉米饼类型`u`可以通过成本获得`d`，尝试每一次交换`u`到另一种类型`v`。 如果`d + exchange_cost`提高了已知成本`v`，更新一下。 
4. Dijkstra完成后，输入的距离`i`是一种炸玉米饼的最便宜价格`i`，包括所有可能的交换链。 
5. 将每个最终距离乘以该类型所需的炸玉米饼数量，然后将这些值相加。 总和是最小的总成本，因为每个炸玉米饼都可以独立获取。 

工作原理：Dijkstra 的不变量是，每当从当前距离最小的优先级队列中删除一个节点时，该距离就是获取该 taco 类型的最便宜的可能方法。 初始距离代表直接购买任何炸玉米饼，每次放松代表进行一次有效的兑换。 由于所有交换成本都是非负的，Dijkstra 永远不需要重新考虑最终确定的炸玉米饼类型。 当所有节点都确定后，每个可能的购买和交换序列都已通过图中相应的路径进行了考虑。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t, e = map(int, input().split())

    cost = []
    for _ in range(t):
        cost.append(int(input()))

    graph = [[] for _ in range(t)]
    for _ in range(e):
        i, j, p = map(int, input().split())
        graph[i].append((j, p))

    need = []
    for _ in range(t):
        need.append(int(input()))

    dist = cost[:]
    pq = []

    for i in range(t):
        heapq.heappush(pq, (dist[i], i))

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        for v, w in graph[u]:
            nd = cur + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    ans = 0
    for i in range(t):
        ans += dist[i] * need[i]

    print(ans)

if __name__ == "__main__":
    solve()
```输入解析遵循图的结构：首先是 taco 类型和交易所的数量，然后是直接价格，然后是有向交易所边，最后是请求的数量。 

这`dist`数组从直接购买价格开始，而不是无穷大。 这是将普通 Dijkstra 转变为多源版本的主要实现细节。 每种类型的炸玉米饼都已经可以买到，因为凯文总是可以直接购买。 

优先级队列可能包含过时的条目，因为在插入旧值后，taco 类型可以接收更好的距离。 这`if cur != dist[u]`检查丢弃那些过时的条目。 

所有成本都安全地适合 Python 整数。 只有在已知最短路径后才进行所需数量的乘法，因此最终计算时不存在重复的图形操作。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((t + e) log t) | 每种 taco 类型都会进入优先级队列，并且每个交换边缘都会在 Dijkstra 期间进行处理。 |
 | 空间| O(t + e) | 图存储所有交换规则，数组存储距离和要求。 |

 最大的输入仅包含`10^4`炸玉米饼类型和`10^5`交换，因此单个 Dijkstra 运行很容易符合预期限制。 即使对于稀疏图，堆的使用也可以使算法保持高效。

import sys
import io
import heapq

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t, e = map(int, input().split())
    cost = [int(input()) for _ in range(t)]

    graph = [[] for _ in range(t)]
    for _ in range(e):
        i, j, p = map(int, input().split())
        graph[i].append((j, p))

    need = [int(input()) for _ in range(t)]

    dist = cost[:]
    pq = [(dist[i], i) for i in range(t)]
    heapq.heapify(pq)

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return str(sum(dist[i] * need[i] for i in range(t)))
