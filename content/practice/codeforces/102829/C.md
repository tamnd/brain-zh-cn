 ## 解决方案
 ## 问题理解

 凯文（Kevin）在他的帖子上有一个反应，从而启动了一条模因反应链。 每天晚上，当前的反应数量都会自动加倍。 早上，Kevin 可以手动添加一个反应，新的反应会立即计数。 目标是准确达到`n`总反应数，同时最大限度地减少凯文做出的手动反应数量，计算启动连锁反应的第一个反应。 该问题要求手动添加的最少数量。 

查看流程的关键方法是查看每个手动反应所贡献的价值。 如果凯文添加了一个反应并且它通过了`k`翻倍之夜，它的贡献正是`2^k`对最终总数的反应。 最初的反应就是这样的贡献之一`k = 0`。 

输入包含单个整数`n`，代表所需的最终反应数。 输出是 Kevin 必须手动添加的单个反应的最小数量，才能达到精确的总数。 

约束条件`n <= 10^9`意味着我们无法模拟每一个可能的早晨和夜晚的顺序。 对所有放置反应的方法的搜索将呈指数级增长，因为每个可能的手动反应都可能在不同的时间发生。 我们需要一个只执行少量操作的解决方案，最好是对数操作`n`， 因为`10^9`只有大约 30 位二进制数字。 

主要的边缘情况来自看起来需要多个步骤但实际上不需要的值。 例如，当输入为：```
8
```正确的输出是：```
1
```粗心的模拟可能会增加额外的反应，但一个初始反应会加倍三倍，变成`8`。 

另一个棘手的情况是答案不是所需的天数。 例如：```
5
```正确的输出是：```
2
```链条可以达到`4`使用一种反应，然后凯文再添加一种反应，得到`5`。 计算加倍次数会给出错误的数量，因为该问题需要手动反应，而不是经过的天数。 

最终的边界情况是：```
1
```正确的输出是：```
1
```第一个反应是强制性的，因为它是该过程的起点。 将第一反应视为自由的实现将错误地返回零。 

## 方法

 直接的方法是尝试不同的手动反应时间表。 我们可以想象每天早上决定凯文是否做出反应或等待，然后模拟夜间加倍，直到达到目标。 这适用于较小的值，因为最终可以检查每个可能的计划，但计划的数量增长得太快。 对于附近的目标`10^9`，探索所有选择所需的时间远远超过可用时间。 

有用的观察来自于忽略时间线并仅关注每个手动反应的贡献。 每个手动反应在最终计数中都会变成 2 的幂。 如果凯文一开始就做出反应，那么该反应就会起作用`1`,`2`,`4`,`8`，依此类推，具体取决于经过了多少个夜晚。 后来的反应贡献了较小的二的幂。 

这意味着最终的数字`n`必须构建为 2 的幂之和。 形成一个数所需的最小二的幂数恰好是`1`其二进制表示形式中的位。 每个设置位代表 2 的一次幂，必须由单独的手动反应提供。 

例如，`13`二进制是`1101`，这意味着：`13 = 8 + 4 + 1`这三个二的幂对应于三个手动反应。 任何安排都不能使用更少的组件，因为每个手动反应仅贡献一个二的幂分量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 可能的反应时间数量呈指数增长 | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取目标反应数`n`。 
2. 计算有多少位相等`1`在二进制表示中`n`。 每个这样的位代表 2 的一次方，必须来自一个手动反应。 
3. 输出该计数作为凯文必须做出的最小反应数。 

为什么有效：Kevin 手动添加的每个反应都会为最终总数贡献 2 的一次方，因为唯一的未来操作是加倍。 的二进制表示`n`是它独特的分解为二的幂。 由于每个设置位都需要一个贡献并且分解不能缩短，因此对设置位进行计数给出了手动反应的最少数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    print(n.bit_count())

if __name__ == "__main__":
    solve()
```解决方案读取目标数字并使用Python的内置`bit_count()`操作来计算其二进制表示中设置的位数。 这直接符合算法的数学观察。 

没有模拟循环，因此不会出现错误的时序计算或边界转换。 唯一重要的细节是`n = 1`必须产生`1`，这是自然处理的，因为二进制表示包含一组位。

 ## 边缘情况

 对于`n = 8`，算法将数字转换为二进制形式`1000`并计算一组位。 结果是`1`，与仅初始反应可以通过加倍增长以达到目标这一事实相匹配。 

为了`n = 5`，二进制形式为`101`，因此有两个设置位。 该算法将所需的贡献确定为`4`和`1`，给出正确答案`2`。 仅基于计算加倍步数的方法在这里会失败，因为最终调整需要额外的手动反应。 

为了`n = 1`，二进制形式为`1`，所以答案是`1`。 该算法将起始反应保留在计数中，避免了将起始反应视为免费的常见错误。
