 ## 解决方案
 # 问题理解

 任务是判断一个数是否`N`可以写成精确的总和`K`其中每一项都是非负整数幂`X`。 如果存在这样的表示，则必须按降序打印术语，并且在所有有效的降序序列中，我们需要字典顺序最小的一个。 输入包含一个大的目标值`N`, 所需的被加数数量`K`，和基数`X`。 输出要么是一个不可能的答案，要么是精心选择的权力列表`X`其总和恰好是`N`。 

的价值`N`可以达到`10^18`，因此尝试建立所有可能的权力组合是不可能的。 甚至迭代每个值直到`N`需要太多的操作。 基地最多是`9`，这意味着基本表示`N`只有大约 60 位数字。 的价值`K`仅限于`2 * 10^5`，因此该算法可以承担与`K`和基数位数，但不是任何二次方`K`。 

一个常见的错误是只检查普通基地`X`代表并就此停止。 基本表示给出了最少数量的项，但问题要求精确`K`条款，所以我们可能需要将权力分割成更小的权力。 另一个错误是在不考虑字典顺序的情况下任意分割权力。 

例如，考虑：```
9 4 2
```的二进制表示`9`是`1001`，给出条件`8`和`1`。 这只使用了两个术语。 粗心的做法可能会分裂`8`立即分成八个，但这给出了太多项。 正确答案是：```
YES
4 2 2 1
```这四项之和为`9`，并且这种排序在字典顺序上比诸如`2 2 2 2 1`，甚至没有所需的长度。 

另一种边缘情况是当请求的项数小于基本表示中已存在的项数时。 例如：```
10 1 2
```二进制表示是`1010`， 意义`10 = 8 + 2`。 没有办法在合并权力的同时保持每个任期的权力`2`，所以正确的输出是：```
NO
```当无法实现所需的项数增加时，就会出现最终的边缘情况。 每一次分裂`X^i`进入`X`的副本`X^(i-1)`精确增加项数`X - 1`。 例如：```
5 2 3
```三元表示`5`是`12`，给出三个项：`3 + 1 + 1`。 我们已经需要比要求更多的条款，所以答案是：```
NO
```## 方法

 直接的方法是产生所有可能的分裂权力的方法。 我们可以从基础开始`X`代表并反复选择权力`X^i`替换为`X`的副本`X^(i-1)`。 此操作保留总和并将项数增加`X - 1`。 该方法是正确的，因为每个有效表示都可以通过反转这些分割来转换回基本表示。 然而，搜索所有可能的选择是不可能的。 可能的分裂序列的数量呈爆炸性增长，甚至尝试所有选择以获得一个中等大的序列`K`会超出限制。 

关键的观察是基本表示已经给出了最少的项数。 我们唯一需要的操作就是分裂。 每个拆分对术语计数都有相同的影响，并且词典编序要求告诉我们哪些拆分是最好的。 如果我们先分割一个较大的幂，则最终降序列表中出现的最大值会更早变小，从而提高字典顺序。 

所需的分割数量是固定的。 如果基本表示包含`C`条款，我们需要`K - C`附加条款。 由于每次分割都会增加`X - 1`条款中，分割数必须是：```
(K - C) / (X - 1)
```如果这不是整数，则不存在解。 否则，我们会贪婪地执行这么多次分割，总是采用最大的可用功率。 只有大约 60 种可能的权力，因为`N`至多是`10^18`，所以这个过程很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(状态数) | 太慢了 |
 | 最佳 | O(log_X(N) + K) | O(log_X(N)) | O(log_X(N)) | 已接受 |

 ## 算法演练

 1. 转换`N`进入基地`X`。 位置上的数字`i`告诉我们有多少个副本`X^i`我们目前有。 这是起始表示，因为它使用尽可能少的术语。 
2. 计算该表示中的项数。 如果这个计数大于`K`， 输出`NO`因为分裂只能增加项数。 
3. 计算需要多少个额外项。 如果`K - count`不能被整除`X - 1`， 输出`NO`因为每个可能的操作都会准确地改变术语计数`X - 1`。 
4. 从最大的幂开始，在仍然需要分割的情况下分割尽可能多的项。 分裂`X^i`删除一项大项并创建`X`较小的项，因此对最大的幂执行此操作首先会产生字典顺序上最小的答案。 
5. 执行所有必需的分割后，将存储的计数展开为幂列表，并从最大到最小打印它们。 

为什么它有效：

 基本表示是具有最少项的唯一表示。 任何其他有效的表示只能通过对其应用分割来获得。 该算法精确地执行了所需的分割次数，因此它达到了精确的表示`K`条款。 Among all possible choices of splits, replacing larger powers earlier always decreases the first position where two descending sequences could differ, which makes the produced sequence lexicographically minimal.

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K, X = map(int, input().split())

    cnt = []
    temp = N
    while temp:
        cnt.append(temp % X)
        temp //= X

    if not cnt:
        cnt = [0]

    current = sum(cnt)

    if current > K:
        print("NO")
        return

    diff = K - current
    if diff % (X - 1) != 0:
        print("NO")
        return

    need = diff // (X - 1)

    for i in range(len(cnt) - 1, 0, -1):
        if need == 0:
            break
        take = min(cnt[i], need)
        if take:
            cnt[i] -= take
            if i - 1 == len(cnt):
                cnt.append(0)
            cnt[i - 1] += take * X
            need -= take

    if need != 0:
        print("NO")
        return

    ans = []
    power = 1
    powers = []
    for _ in range(len(cnt)):
        powers.append(power)
        power *= X

    for i in range(len(cnt) - 1, -1, -1):
        ans.extend([str(powers[i])] * cnt[i])

    print("YES")
    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```代码首先存储基数`X`中的数字`cnt`。 的索引为`cnt`代表指数，所以`cnt[3] = 2`意味着有两个副本`X^3`。 

变量`current`是最小表示中的项数。 可除性检查`X - 1`避免尝试不可能的情况，因为每次分割都会改变计数的确切数量。 

循环从高到低处理指数。 量`take`是我们分割当前指数的次数。 在较小的权力之前删除较大的权力是强制执行词典编纂要求的部分。 

最终的扩展是按相反的指数顺序完成的，因此打印的序列已经是降序的。 Python 整数处理较大的值`N`安全地，产生的项总数受以下限制`K`，这最多是`200000`。

 ## 边缘情况

 对于这个案例：```
9 4 2
```基本表示给出了计数`2^3`和`2^0`。 该算法发现需要两个附加项。 由于每次二元分割都会添加一项，因此它会对最大的可用幂执行两次分割。 结果项是`4, 2, 2, 1`，这正是所需的计数，并且具有尽可能小的主值。 

对于这个案例：```
10 1 2
```初始表示已经包含两项，`8`和`2`。 该算法检测到当前计数大于`K`。 由于拆分无法减少项数，因此立即返回`NO`。 

对于这个案例：```
5 2 3
```基本表示包含三个术语：`3, 1, 1`。 请求的计数较小，因此没有有效的序列。 该算法在尝试任何拆分之前会拒绝它。 

对于具有许多必需条款的大型案例，例如：```
1000000000000000000 200000 2
```该算法从不迭代该值本身。 它仅处理大约 60 个二进制位置并执行足够的分割来创建所请求的输出大小。 这使得运行时间与必须处理的实际信息量成正比。
