 ## 解决方案
 ## 问题理解

 我们的任务是模拟向具有固定数量的存储桶的哈希表中的插入。 每个桶最多可以容纳一个元素。 哈希函数很简单：对于一个数字$x$，目标桶是$x \mod p$。 我们收到一个数字序列，必须按顺序插入它们。 如果某个号码指向的桶已被占用，则会发生冲突。 目标是报告导致第一个冲突的插入索引，如果没有发生冲突则报告 -1。 

输入给出$p$，桶的数量，以及$n$，要插入的数字数量，后跟$n$数字。 两个都$p$和$n$最多 300 个，每个数字可以大到$10^9$。 这确保了即使是简单的 O(n) 或 O(n²) 模拟也是可行的，但我们应该避免不必要的嵌套循环。 

不明显的边缘情况包括多次插入相同的数字或在模运算下发生冲突但不同的数字。 例如，如果$p=3$输入序列为1,4,7，取模结果全为1。前两次插入成功占桶，但第三次触发冲突。 不检查模数下先前插入的粗心实现将错误地允许多次插入到同一个存储桶中。 

## 方法

 蛮力方法是维护一个大小的数组$p$代表桶。 每次插入都会检查目标桶是否被占用。 如果是，则返回索引。 这种方法是正确的，因为它忠实地模拟了哈希表的行为。 操作计数最多为 300 次插入 × 每次插入 1 次检查，这对于给定的限制来说是微不足道的。 不需要嵌套循环或花哨的数据结构。 

稍微优雅的解决方案的关键见解是认识到模运算保证桶索引在 0 到$p-1$。 这允许使用固定大小的数组来存储占用标志，从而无需动态数据结构。 因为数组索引直接对应桶号，所以每次查找和更新都是O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(p) | 已接受 |
 | 最佳| O(n) | O(p) | 已接受 |

 对于这个问题，暴力破解本质上是最优的，因为输入量很小并且不可能进行渐近改进。 

## 算法演练

 1. 阅读$p$和$n$来自输入。 初始化一个数组`occupied`尺寸的$p$所有元素设置为 False。 该数组将跟踪哪些桶已经被填满。 
2. 使用从 1 开始的索引迭代数字序列$i$。 对于每个数字$x$，计算目标桶为`bucket = x % p`。 
3. 检查是否`occupied[bucket]`是真的。 如果是，则发生了冲突，所以立即打印$i$并退出。 
4. 如果桶是空闲的，则设置`occupied[bucket]`为 True 并继续下一个数字。 
5. 如果所有数字均已处理且未遇到冲突，则打印 -1。 

该算法之所以有效是因为`occupied`数组始终准确地反映正在使用哪些存储桶。 每次插入要么将存储桶标记为已占用，要么检测到冲突。 由于每个数字都被检查一次，因此不会遗漏冲突。 不变量是`occupied[bucket]`当且仅当之前的某个数字已插入到该存储桶中并且索引为 True$i$返回保证是第一个冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

p, n = map(int, input().split())
occupied = [False] * p

for i in range(1, n + 1):
    x = int(input())
    bucket = x % p
    if occupied[bucket]:
        print(i)
        break
    occupied[bucket] = True
else:
    print(-1)
```第一行读取桶数和数字。 这`occupied`数组被初始化以跟踪存储桶的使用情况。 该循环使用从 1 开始的索引进行迭代，以直接匹配问题对插入索引的要求。 模运算计算出正确的桶。 这`else`仅当循环完成且未中断时，for 循环才会执行，从而干净地处理“无冲突”情况。 

一个微妙的实现点是对结果使用基于 1 的索引。 如果您不小心返回，这里很常见差一错误`i-1`或从零开始循环。

 ## 边缘情况

 该算法处理大于的数字$p$因为模将它们减少为有效的桶索引。 重复的数字在第一次重复时被正确识别为冲突。 对于最小尺寸的输入，循环完成时不会中断，从而触发`else`子句并返回-1。 所有痕迹都证实`occupied`忠实记录桶的使用情况，并且返回的索引始终对应于第一个冲突。
