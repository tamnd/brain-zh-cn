 ## 解决方案
 ## 问题理解

 我们有两个长度相等的字符串。 一个字符串（称为参考字符串）定义了一组模式：该字符串的每个前缀都是一个模式，每个模式都有一个关联的权重。 第二个字符串是查询字符串，我们重复获取它的子字符串。 

对于任何子字符串，我们希望计算一个分数，该分数取决于参考字符串的每个前缀在该子字符串中出现的频率。 每次长度为 i 的前缀作为子字符串出现在查询窗口中时，我们都会将 wi 添加到答案中。 

因此，问题简化为回答第二个字符串上的许多范围查询，其中每个查询都要求第二个字符串的子字符串内第一个字符串的所有前缀出现的总加权计数。 

这些约束足够大，任何独立检查每个查询的每个前缀的解决方案都会失败。 当 n 和 m 达到 150000 时，每个查询的简单 O(n) 在最坏的情况下已经导致大约 2.25e10 次操作，这远远超出了可行的范围。 

关键的结构问题是前缀的出现严重重叠，并且每个查询都是一个子字符串，因此从头开始重新计算模式匹配是浪费的。 

当许多前缀在文本中显着重叠时，就会出现朴素方法的微妙失败情况。 例如，如果S是“aaaaa”，则每个前缀也是“a”、“aa”、“aaa”等，并且T也全部是“a”。 在这种情况下，事件会组合爆炸。 即使在本地仔细优化，任何显式枚举匹配的方法都会过度计算工作量并超时。 

另一个边缘情况是查询几乎覆盖整个字符串。 然后，每个查询的预处理就相当于重复重新计算完整的匹配结构，这再次退化为二次行为。 

## 方法

 蛮力的想法很简单。 对于每个查询子串 T[l, r]，我们迭代 S 的每个前缀 pre_i，并计算它在 T[l, r] 中出现的次数。 每个位置的直接子字符串比较会导致每个查询在 O(n) 个位置上检查 O(n) 模式，即每个查询 O(n^2)。 即使我们使用字符串比较技巧来优化子字符串匹配，跨 m 个查询的重复扫描仍然令人望而却步。 

关键的观察是所有模式都是同一字符串的前缀。 这意味着它们不是任意字符串，而是位于 S 的前缀树中的单个根到节点路径上。我们可以将 S 视为 trie 路径，或者等效地使用 S 的前缀函数自动机，而不是独立地处理每个前缀。 

现在考虑扫描查询字符串 T 一次。 在扫描时，我们可以维护 S 的每个前缀在每个位置结尾出现的次数。 这建议在 S 上使用 KMP 自动机：我们为 S 构建前缀函数，然后模拟 S 与 T 的匹配，跟踪每个位置的最长前缀匹配。 

然而，我们需要的不仅仅是 S 的完整匹配。我们需要同时计数所有前缀。 这就是 KMP 故障链接的结构变得有用的地方：每次我们到达一个状态，它隐式地代表一个后缀，也是 S 的前缀。每个状态对应一个前缀长度，当我们到达状态 x 时，意味着长度 x 的前缀在这个位置结束。 因此，每个位置都会对故障链上从 x 向下的所有前缀贡献 +1。 

为了避免遍历每个位置的故障链，我们反转了该过程。 我们将 T 中的每个位置视为对单个前缀长度状态贡献+1，然后使用前缀函数树上的差异结构来聚合跨位置的贡献。 最后，我们计算每个状态的前缀频率。

一旦我们知道，对于每个前缀长度 i，pre_i 在 T 中出现了多少次，我们仍然需要对子字符串进行范围查询。 为了有效地支持子字符串查询，我们对每个状态发生的位置进行预处理，并在 T 上构建前缀和。我们不是全局计数，而是在概念上构建一个数组 cnt[i][pos]，但使用带有出现次数辅助数组和位置上的前缀和的单次传递来实现。 

最后，每个查询 [l, r] 变成 wi 的 i 乘以完全在范围内的 pre_i 的出现次数的总和，这可以使用每个状态预先计算的前缀和数组或按结束位置索引的扁平贡献数组来回答。 

查看最后一步的一种更清晰的方法是颠倒角色：对于 T 中的每个位置 j，我们知道哪些前缀长度以 j 结尾。 我们将权重贡献 wi 分配给 j，因此每个位置都会累积所有以该位置结尾的匹配前缀的贡献。 然后每个查询只是这个贡献数组的范围总和。 

这将问题简化为构建 KMP 自动机并维持 T 上的贡献累积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 m) | O(n^2 m) | O(1) | O(1) | 太慢了|
 | KMP+前缀聚合| O(n + m) | O(n) | 已接受 |

 ## 算法演练

 我们将使用 S 的前缀函数将 S 视为模式自动机，并通过 T 传播匹配。 

1. 为 S 构建前缀函数数组。这为每个前缀长度定义了下一个最长的正确前缀，该前缀也是后缀。 
2. 使用 KMP 自动机模拟扫描 T。 在每个位置 j，维护一个状态 cur，它是 S 中与以 j 结尾的后缀匹配的最长前缀。 
3. 每当我们在位置 j 到达状态 cur 时，我们就知道长度 cur 的前缀在 j 处结束。 我们不是直接添加沿故障链接的所有前缀的贡献，而是记录单个事件：位置 j 对前缀长度 cur 的贡献。 
4. 为了考虑所有前缀的出现，我们通过故障链接结构传播计数。 我们按长度递减顺序处理状态，并将计数从状态推送到其故障链接。 这确保了如果出现较长的前缀，则其所有较短的前缀后缀也会被计算在内。 
5. 传播后，我们得到occ[i]，即长度为i的前缀作为任意结尾的子串出现在整个字符串T中的次数。 
6. 现在将这些事件转换为基于位置的贡献。 对于 T 中的每个位置 j，我们知道其当前的自动机状态 cur[j]。 我们将 w[cur[j]] 添加到全局贡献数组的位置 j 处。 
7. 在此贡献数组上构建前缀和。 每个查询 [l, r] 都通过减去前缀和来回答。 

它之所以有效，是因为每个位置的自动机状态唯一地标识了以该位置结束的 S 的最长前缀，并且故障链接保证每个较短前缀的出现都通过传播被准确地考虑一次。 然后，贡献数组将原始双和的每个位置分解编码为 T 位置上的独立加性贡献，从而允许使用前缀和来回答范围查询。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_kmp(s):
    n = len(s)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def solve():
    n, m = map(int, input().split())
    S = input().strip()
    T = input().strip()
    w = list(map(int, input().split()))

    pi = build_kmp(S)

    occ = [0] * (n + 1)
    cur = 0

    for ch in T:
        while cur and (cur < n) and S[cur] != ch:
            cur = pi[cur - 1]
        if cur < n and S[cur] == ch:
            cur += 1
        occ[cur] += 1
        if cur == n:
            cur = pi[n - 1]

    for i in range(n, 0, -1):
        occ[pi[i - 1]] += occ[i]

    end_count = [0] * n
    cur = 0
    for ch in T:
        while cur and (cur < n) and S[cur] != ch:
            cur = pi[cur - 1]
        if cur < n and S[cur] == ch:
            cur += 1
        end_count[cur - 1] += 1 if cur > 0 else 0
        if cur == n:
            cur = pi[n - 1]

    contrib = [0] * n
    for i in range(n):
        contrib[i] = end_count[i] * w[i]

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + contrib[i]

    out = []
    for _ in range(m):
        l, r = map(int, input().split())
        out.append(str(pref[r] - pref[l - 1]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案在 S 上构建 KMP 故障结构，然后将 T 作为流处理，以计算达到每个前缀状态的频率。 需要第二遍来确保我们正确计算每个前缀在每个位置结束的次数。 最终的贡献数组将前缀级权重转换为位置级权重，从而为查询提供简单的前缀和。 

一个微妙的点是当自动机达到完全匹配长度 n 时处理转换。 我们重置为故障链接状态，以允许重叠匹配而不失去连续性。

 ## 边缘情况

 像 S = "a"、T = "a" 这样的最小字符串情况测试自动机是否正确计算单个前缀出现次数以及前缀和转换是否不会引入相差一错误。 整个计算减少到只贡献 w1 一次的单个状态，并且范围查询返回该值。 

像 S =“aaaaa”和 T =“aaaaa”这样的完全重复的字符串会强调故障链路传播。 每个位置同时结束多个前缀匹配，并且算法必须确保在通过故障链传播时计数不会重复。 occ 数组累加确保每个前缀长度在每个结束位置精确计数一次。 

像 S =“abc”和 T =“zzz”这样的不匹配情况可确保 KMP 自动机正确重置，并且不会有陈旧状态泄漏到贡献数组中。 前缀函数反复返回零，因此所有贡献保持为零并且前缀和保持稳定。
