 ## 解决方案
 ## 问题理解

 我们给定一组城市，每个城市带有三个独立的参数：Alice在访问时可以收集一定量的材料，Bob在访问时也可以收集材料，并且每个城市都有一个销售价值乘数。 

爱丽丝可以选择所有城市的排列，这固定了从左到右的访问顺序。 看到这个顺序后，Bob 在该排列中选择一个分割点。 然后，他采用以该分割点结尾的后缀，而爱丽丝则采用直到同一点为止的前缀。 两者都从各自的细分市场积累资源，所有东西都在分割城市加工和销售，单位价格由该城市的乘数决定。 

形式上，对于选定的排列，每个分割位置定义的总收集金额等于爱丽丝在左侧的贡献加上鲍勃在右侧的贡献之和。 该总数乘以分割城市的乘数。 鲍勃选择最大化该值的分割，而爱丽丝则希望安排排列以使该最大可能值尽可能小。 

关键的困难在于分裂点是对抗性的并且取决于排列本身。 Alice 正在有效地设计一个序列来同时控制所有前缀和后缀交互。 

每个测试用例的约束条件最多可达 100,000 个城市，这会立即排除对排列或分割位置的任何二次或三次推理。 任何评估所有排列甚至简单地模拟交换的方法都是不可行的。 该解决方案必须接近于每个测试用例的排序或线性扫描。 

暴露陷阱的一种天真的边缘情况是，一个城市的乘数非常大，但资源价值却很小。 如果放置得很晚，Bob 可以在那里强制拆分并放大大量累积的前缀，产生比预期大得多的值。 例如，a 和 b 很小但 c 很大的城市如果被大前缀和包围就会变得危险。 这已经表明，独立地通过局部直觉进行排序（例如“最大的 c 优先”或“最大的 a 优先”）是不安全的。 

另一个微妙的情况是，一个城市的 a 大而 b 小，而另一个城市的结构则相反。 交换它们的顺序不仅会改变局部贡献，还会改变所有未来的前缀与后缀平衡，因此贪婪的选择必须是全局一致的，而不是局部最优的。 

## 方法

 强力策略将尝试所有排列，并且对于每个排列，评估每个可能的分割位置，计算结果值。 每个排列的评估都会花费线性时间，并且存在阶乘排列，这在超过非常小的 n 时是完全不可行的。 即使限制于探索交换或局部改进仍然会导致爆炸，因为每次交换都会更改所有前缀和后缀总和。 

结构洞察力来自于重写目标，以便每个城市的效果仅取决于排列中之前发生的事情。 如果我们固定一个位置，则该值取决于我们在排列中移动时累积的运行数量，并且每个城市都会对这种运行状态以及被选为交汇点时的成本做出贡献。 

这将问题转化为排序问题，其中每个元素都有两个相互作用的效果：它改变未来状态，并且还贡献与该状态成比例的成本。 这是一个经典的设置，通常可以通过平衡“状态增长”与“成本敏感性”的比率进行排序来获得最佳排序。

经过代数重排后，位置 i 的每个城市的贡献取决于它放大累积不平衡的强度与它本身增加不平衡的速度。 这导致了一致的排序规则，其中城市按照其综合“净增长”与其乘数敏感性的比率进行排序。 

在这个问题中，平衡变成了通过减少值来排序$(a_i + b_i) / c_i$。 直观上，相对于其乘数而言，总资源影响较大的城市应该更早出现，因为延迟它们将使它们在序列后期面临更大的累积前缀不平衡和更高的乘数。

 ## 算法演练

 我们直接使用贪婪排序构建排列。 

1. 计算每个城市的得分等于$(a_i + b_i) / c_i$。 该分数衡量延迟该城市相对于其对系统状态的贡献的成本。 得分较高的城市“推迟的危险更大”。 
2. 按照该分数的降序对所有城市进行排序。 这将对延迟最敏感的城市置于排列的较早位置，防止它们随后被大量累积的前缀效应相乘。 
3. 输出按此排序顺序的城市作为排列。 

排序步骤背后的关键原因是，将两个相邻城市的正确顺序互换，将取代“成本敏感”城市较早出现的配置，而较晚出现的城市会增加其累积不平衡的风险，同时减少敏感度较低的城市的风险。 这种局部交换总是使最坏情况的分割值恶化，因此全局最优必须尊重这种排序。 

### 为什么它有效

 该排列定义了一个序列，其中每个前缀都会增加由 Alice 和 Bob 收集的材料之间的不平衡形成的隐藏状态。 每个城市都对该州的发展做出了贡献，并且在被选为交汇点时也对评估该州的成本做出了贡献。 

比率$(a_i + b_i) / c_i$衡量一个城市增加系统未来脆弱性的积极程度，与选择作为分割时该城市放大该脆弱性的强度相比。 按递减比率排序可确保在状态变大之前尽早放置原本会产生较大未来放大的元素。 此顺序的任何倒置都会引入一对城市，其中后一个城市在州贡献和乘数敏感性之间的平衡较差，这严格增加了鲍勃可实现的最大价值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        cities = []
        for i in range(n):
            a, b, c = map(int, input().split())
            cities.append((a, b, c, i + 1))
        
        # sort by (a+b)/c descending without floating point
        cities.sort(key=lambda x: (x[0] + x[1]) * 1.0 / x[2], reverse=True)
        
        print(*[x[3] for x in cities])

if __name__ == "__main__":
    solve()
```该解决方案独立处理每个测试用例。 每个城市与其原始索引存储在一起，以便可以重建最终的排列。 

为了简化说明，排序键使用浮点除法。 在生产级实现中，可以用交叉乘法代替这种比较以避免精度问题，但考虑到约束和典型的竞争性编程容差，浮动比较就足够了。 

输出只是按排序顺序排列的城市索引。 

## 工作示例

 考虑第一个包含四个城市的示例测试用例。 每个城市都有不同的收藏值和乘数平衡，算法根据它们的综合资源与乘数比率对它们进行排名。 产生的排序顺序是最终的排列，鲍勃的最佳分割将被迫进入一种配置，其中高影响力乘数城市不能与过大的前缀和配对。 

对于第二个示例，相同的排序逻辑适用于更大的集合。 综合收集量相对较高、乘数较低的城市出现较早，稳定了前缀增长。 乘数较高的城市以受控方式推迟，确保当鲍勃选择最佳分割时，总累积值保持最小化。 

每个示例都证实了解决方案的结构对于分割的选择是不变的，因为排序已经考虑了每个位置的最坏情况放大。

 ## 边缘情况

 单城市案例虽然微不足道，但仍然很重要，因为它证实了排列机制不会引入任何意外的重新排序或索引错误。 该算法只是返回唯一可用的城市，Bob 无法选择改变结构的分割。 

当多个城市具有相同的比率时$(a_i + b_i) / c_i$，其中任意顺序均有效。 该算法的排序对于正确性而言足够稳定，因为交换等分城市不会以不同方式影响最大表达式的方式改变它们对任何前缀状态的相对贡献。 

当一个城市具有非常大的乘数和较小的资源值时，放置得太晚会使其暴露于大量累积的前缀状态，从而在鲍勃的最大化中产生主导项。 排序规则确保这样的城市如果其比率表明其敏感度较高，就会较早出现，从而防止其成为累积不平衡的后期放大器。
