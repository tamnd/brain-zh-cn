 ## 解决方案
 ## 问题理解

 我们正在研究一个无限的二维整数网格，其中每个格点最初都具有相同的默认字符`"."`。 然后，我们得到一系列绘画操作，用新字符覆盖该网格的区域。 有两种类型的更新：一种绘制圆内的所有整数点，另一种绘制轴对齐矩形内的所有整数点。 第三种类型的操作要求我们在按顺序应用所有先前的绘画效果后输出网格的有限子矩形。 

关键的解释是每个操作都按顺序应用并覆盖以前的颜色。 当多个形状重叠时，后面的操作会完全替换受影响点处较早的颜色。 渲染查询仅询问应用所有先前更新后有界区域的最终状态。 

坐标范围非常大，数量级可达 10^9，因此我们无法显式模拟网格。 然而，所有渲染查询的总面积很小，总共最多 10^4。 这是我们被迫具体化实际网格单元的输入的唯一部分。 所有其他操作都是在巨大的坐标空间上以几何方式定义的。 

一个幼稚的错误是尝试迭代受每个圆形或矩形影响的每个点。 半径最大为 10^9 的圆最多可以包含 10^18 个整数点，因此即使单个操作也不可能显式扩展。 另一个微妙的错误是直接更新渲染查询，而没有仔细遵守操作顺序。 由于操作会覆盖之前的操作，因此最终颜色完全取决于最近的覆盖操作，而不取决于有多少操作相交。 

关键的边缘情况是不同形状的重叠更新。 例如，先绘制矩形，然后绘制部分与渲染区域重叠的圆形，必须确保圆形完全覆盖其区域内的矩形。 任何在不考虑顺序的情况下预先计算单个最终网格的方法都会失败。 

## 方法

 蛮力的想法在概念上很简单：维护所有绘制点的字典或网格图。 对于每个圆形或矩形操作，迭代其几何区域中的每个整数点并分配给定的颜色。 当渲染查询到达时，迭代请求的区域并输出存储的值或`"."`如果未上漆。 

这是正确的，因为它直接模拟了问题定义。 问题是运行时。 一个矩形可以有 2·10^18 的面积那么大，即使渲染区域很小，更新也完全占主导地位。 扩展圆更糟糕，因为检查半径为 r 的圆盘中的所有整数点的时间复杂度为 O(r^2)。 对于多达2000次操作，这是完全不可行的。 

关键的观察是我们永远不需要显式模拟整个网格。 我们只查询小区域，并且只需要这些点的最终颜色。 我们没有全局扩展形状，而是颠倒了视角：对于每个渲染查询，我们通过按相反顺序检查操作来直接独立计算每个请求点的颜色。 

对于固定点 (x, y)，其最终颜色由覆盖它的最后一个操作决定。 因此，我们向后扫描操作，并在找到符合该点的操作后立即停止。 由于我们最多只评估 10^4 个总查询点，并且最多有 2000 个操作，因此这给出了 2×10^7 几何检查的可管理上限。 

每次检查都是恒定时间：矩形包含是简单的不等式，圆形包含是平方距离检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力网格模拟| O(总涂漆面积) | O(网格) | 太慢了 |
 | 反向每个查询评估 | O(n·q) 其中 q ≤ 10^4 | O(1) 额外 | 已接受 |

 ## 算法演练

 我们处理一次操作，存储它们，并独立地回答每个渲染查询。 

1. 读取所有操作并按顺序存储在列表中。 我们不会尝试立即应用它们，因为渲染需要最终状态查询，并且稍后的操作可以覆盖之前的操作。 
2. 当我们遇到渲染操作时，我们将其矩形区域扩展为点列表。 由于所有渲染区域的总和最多为 10^4，因此这种扩展是安全的。 
3. 对于渲染区域中的每个点，我们从最后一个操作向后扫描操作列表到第一个操作。 
4. 对于每个操作，我们检查它是否覆盖了当前点。 

对于矩形，我们检查是否 x1 ≤ x ≤ x2 且 y1 ≤ y ≤ y2。 

对于圆，我们检查是否 (x - cx)^2 + (y - cy)^2 ≤ r^2。 
5. 我们发现覆盖该点的第一个逆序操作决定了它的最终颜色。 我们分配该字符并停止进一步扫描该点。 
6. 如果没有操作覆盖该点，我们输出`"."`。 

我们向后扫描的原因是后面的操作会覆盖前面的操作。 这保证了反向遇到的第一个匹配正是最后应用的油漆。 

### 为什么它有效

 在任何固定的网格点，其最终颜色仅取决于包含它的最新操作。 由于操作是按顺序应用并覆盖以前的值，因此绘制过程会在每个单元格中引入最后写入者获胜的规则。 以相反顺序扫描操作会直接重建最后一个写入器。 由于每个点都是独立评估的，因此不需要全局状态，并且正确性来自于几何包含检查与操作是否影响该点完全匹配这一事实。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

ops = []
renders = []

n = int(input())
for _ in range(n):
    parts = input().split()
    if parts[0] == "Circle":
        x, y, r = map(int, parts[1:4])
        col = parts[4]
        ops.append(("C", x, y, r, col))
    elif parts[0] == "Rectangle":
        x1, y1, x2, y2 = map(int, parts[1:5])
        col = parts[5]
        ops.append(("R", x1, y1, x2, y2, col))
    else:
        x1, y1, x2, y2 = map(int, parts[1:5])
        renders.append((x1, y1, x2, y2))

out_lines = []

for x1, y1, x2, y2 in renders:
    for y in range(y2, y1 - 1, -1):
        row = []
        for x in range(x1, x2 + 1):
            color = "."
            for op in reversed(ops):
                if op[0] == "R":
                    _, a1, b1, a2, b2, c = op
                    if a1 <= x <= a2 and b1 <= y <= b2:
                        color = c
                        break
                else:
                    _, cx, cy, r, c = op
                    dx = x - cx
                    dy = y - cy
                    if dx * dx + dy * dy <= r * r:
                        color = c
                        break
            row.append(color)
        out_lines.append("".join(row))

sys.stdout.write("\n".join(out_lines))
```该解决方案将所有操作保留在列表中，并将评估延迟到渲染。 每个渲染的单元独立地向后扫描操作。 渲染区域上的嵌套循环是必要的，因为每个单元都明确需要输出，但约束确保总工作量仍然很小。 

一个微妙的细节是输出中 y 的反向迭代，因为该问题需要从 y2 打印到 y1。 该方向对于匹配所需的视觉方向很重要。 

圆检查使用平方距离来避免浮点运算，确保整数运算的正确性。

 ## 边缘情况

 一个微妙的边缘情况是渲染区域包含从未受任何操作影响的点。 在这种情况下，扫描所有操作都不会产生匹配，并且输出必须保留`"."`。 例如，如果我们只在远处绘制一个矩形并渲染原点，则每个点都应该保留`"."`。 反向扫描可以正确处理此问题，因为它会在不分配颜色的情况下完成所有操作。 

另一种边缘情况是圆几乎不接触其边界上的点。 由于条件包含`(u-x)^2 + (v-y)^2 <= r^2`，边界点必须着色。 整数平方距离检查可确保精确包含而不会出现浮点错误。 

最后的边缘情况是矩形和圆形重叠，其中圆形稍后应用，但仅部分重叠渲染区域。 由于每个单元格独立地反向检查操作，因此只有受影响的单元格子集才会拾取圆圈颜色，而其他单元格仍由早期操作或默认值确定`"."`。
