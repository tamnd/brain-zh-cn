 ## 解决方案
 ## 问题理解

 我们得到一个定义位置之间排序约束的序列和另一个为每个位置分配权重的序列。 由此，我们考虑所有可能的索引子序列，其中索引顺序和第一个序列的值都严格递增。 每个有效子序列都会从第二个数组收集权重并生成总和。 收集所有这些总和形成一个非常大的多重集，我们被要求以非递增顺序输出其中的 K 个最大值，或者当存在少于 K 时输出 -1。 

关键结构是子序列仅在满足两个同时增加条件时才有效。 一种来自于在数组中从左向右移动，另一种来自于排列中增加值。 这使得有效子序列恰好是二维偏序中的递增链。 

这些约束意味着直接枚举所有子序列是不可能的。 即使对于中等的 N，有效的递增子序列的数量也可以呈指数增长。 任何尝试显式列出甚至计数所有这些的解决方案都将立即失败。 成功的方法必须使用子序列集的压缩表示，并且仅提取前 K 个结果。 

当排列已按值排序时，会出现微妙的边缘情况。 在这种情况下，索引的每个子序列都是有效的，因此问题退化为计算权重数组的所有子集和。 这会产生 2^N 个值，并且简单的枚举显然是不可能的，但它很重要，因为它表明任何正确的解决方案都必须隐式处理指数分支，即使在最简单的结构中也是如此。 

另一个极端情况是当 K 超过有效子序列的数量时。 输出必须用 -1 值填充，因此算法必须计数或检测生成的和的耗尽。 

## 方法

 最直接的想法是使用深度优先搜索或子集动态规划生成所有有效的递增子序列，累加它们的和。 这在原则上是正确的，因为它显式地构造每个链并计算其权重总和。 但是，每个元素都可以包含或排除，并且有效性取决于排序约束，因此状态数量呈指数增长。 在最坏的情况下，当排列被排序时，它会退化为 2^N 个子序列，这使得即使对于小 N 的枚举也是不可行的。 

关键的观察是，每个有效子序列都可以看作有向无环图中的一条路径，其中每个节点代表一个索引，并且当 i < j 且 A[i] < A[j] 时，存在从 i 到 j 的边。 每个子序列和恰好是该 DAG 中路径上的节点权重之和。 问题变成在具有正节点权重的 DAG 中找到 K 个最大路径和。 

这种结构允许动态编程，对于每个节点，我们维护以该节点结束的最佳子序列和的列表。 任何结束于节点 j 的子序列都可以通过扩展结束于某个可以到达 j 的较早节点 i 的子序列来形成。 这建议合并所有有效前任的候选列表。 挑战在于每个节点可能有许多前驱节点，并且每个节点都携带一个最多包含 K 个部分和的列表。 

为了提高效率，我们使用排列值维度上的数据结构来压缩前驱聚合。 由于 A 是一个排列，我们可以将值视为第二个坐标并按升序处理节点，维护一个支持查询具有较小 A 值的所有先前状态的结构。 每个结构条目存储一个最佳总和的有界列表，并且通过将其元素与当前权重相结合来获取 K 个最大结果来合并两个列表。

这将指数枚举减少为结构化前缀上的受控 K 路合并，其中每个状态仅保留最相关的 K 个候选者。

 ## 算法演练

 我们按照排列中值的递增顺序处理元素，因为子序列的有效性取决于索引和值的递增，固定值顺序可确保我们只扩展有效链。 

1. 将 A 中的每个值映射到其位置，这样我们就可以处理从 1 到 N 的值，同时知道它们出现在原始数组中的位置。 这将问题转化为处理按值排序的序列，其中转换也必须尊重递增的位置。 
2. 在位置上维护 Fenwick 树或线段树。 每个位置存储最多 K 个以该位置结束的最佳子序列和的列表。 单个元素始终提供仅由其自身组成的基本子序列，因此每个位置都以自己的权重开始。 
3. 对于按升序排列的每个值 v，找到其在原始数组中的位置 p。 我们需要所有可以扩展到 p 的子序列，它们对应于其值之前被处理过的所有位置 q < p。 我们在前缀范围 [1, p−1] 上查询 Fenwick 树并检索候选和的合并列表。 
4. 从这个合并列表中，我们通过将 p 处的权重添加到每个候选和来构造以 p 结尾的新子序列。 我们还包括仅由 p 组成的单元素子序列。 
5. 我们将所有生成的总和合并到位置 p 的最终列表中，仅保留 K 个最大值。 这种截断是必要的，因为只有每个州的前 K 个才能对全局前 K 个结果做出贡献。 
6. 将此列表插入到 Fenwick 树的位置 p 处，以便后面的元素可以扩展这些子序列。 
7. 处理完所有位置后，我们收集所有存储的列表并提取总体上的 K 个最大值。 如果存在的条目少于 K，我们用 -1 填充剩余条目。 

正确性依赖于以下不变量：处理一个位置后，该结构准确存储以该位置结束的 K 个最大有效子序列和。 任何对全局 top-K 答案做出贡献的子序列都必须在某个位置结束，并且保证保留其最佳扩展，因为在处理该位置时会立即形成所有扩展。 由于每次转换都遵循递增的索引和递增的值，因此不会错过任何有效的子序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [[] for _ in range(n + 1)]

    def merge_lists(self, a, b, k):
        # merge two sorted descending lists, keep top k
        res = []
        i = j = 0
        while len(res) < k:
            va = a[i] if i < len(a) else None
            vb = b[j] if j < len(b) else None
            if va is None and vb is None:
                break
            if vb is None or (va is not None and va > vb):
                res.append(va)
                i += 1
            else:
                res.append(vb)
                j += 1
        return res

    def query(self, idx, k):
        res = []
        while idx > 0:
            res = self.merge_lists(res, self.bit[idx], k)
            idx -= idx & -idx
        return res

    def update(self, idx, values, k):
        while idx <= self.n:
            self.bit[idx] = self.merge_lists(self.bit[idx], values, k)
            idx += idx & -idx

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i + 1

    fw = Fenwick(n)
    all_vals = []

    for v in range(1, n + 1):
        p = pos[v]
        best_prev = fw.query(p - 1, k)

        cur = [b[p - 1]]
        for x in best_prev:
            cur.append(x + b[p - 1])

        cur.sort(reverse=True)
        if len(cur) > k:
            cur = cur[:k]

        fw.update(p, cur, k)
        all_vals.extend(cur)

    all_vals.sort(reverse=True)
    for i in range(k):
        if i < len(all_vals):
            print(all_vals[i], end=" ")
        else:
            print(-1, end=" ")
    print()

if __name__ == "__main__":
    main()
```该实现首先将排列转换为位置图，以便值顺序成为处理顺序。 芬威克树在每个索引处存储以该区域结尾的最佳子序列和的压缩列表。 每个查询都会从较早的位置收集所有可扩展的子序列，并且每次更新都会向前传播新形成的子序列。 

关键的实现细节是每次合并后将列表截断为大小 K。 如果没有这个，中间列表将呈指数增长并破坏性能。 另一个微妙的点是，每个扩展都会显式地添加当前节点权重，确保子序列始终通过累加而不是重新计算来构建。

 ## 边缘情况

 一个关键的边缘情况是排列严格按值增加。 在这种情况下，每个子序列都是有效的，并且该算法有效地简化为生成所有子集和。 Fenwick 结构仍然有效，因为每个前缀查询都会返回所有先前看到的组合，并且每次更新都会正确地向前传播扩展和。 

另一种边缘情况是排列严格按值递减。 这里，长度大于 1 的子序列都是有效的，因为无法满足值约束。 每个位置仅贡献其单例权重，并且输出成为各个 B 值的排序列表。 

最后，当 K 超过有效子序列的总数时，算法将耗尽所有生成的和并用 -1 填充余数。 当存在少于 K 个值时，这是在最终收集期间自然处理的。
