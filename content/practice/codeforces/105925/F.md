 ## 解决方案
 ## 问题理解

 我们得到了一个最多包含一千个整数的静态数组，以及多个独立的查询。 每个查询都要求不同的索引四元组的数量$(i, j, k, l)$严格递增顺序，使得四个对应值的总和等于查询目标。 

结构很重要：我们不是通过重复自由选择值，而是选择索引四元组。 这意味着不同位置的相同值被视为不同的选择，并且如果四个位置的总和匹配，则四个位置的每个组合都会独立贡献。 

限制因素决定了方法。 和$N \le 1000$，四元组的总数约为$\binom{1000}{4}$，这大约是$4 \times 10^{10}$。 每个查询直接枚举是完全不可行的。 即使一次性枚举所有四元组也已经太大了，并且将其乘以最多 4000 个查询使得暴力破解变得不可能。 

这些值本身很小，大小以 1000 为界，因此对的总和位于可管理的范围内，四元组的总和大致在$[-4000, 4000]$。 这个有限的输出范围表明对总和进行预计算可能是可行的。 

当所有数字都相同时，就会出现微妙的边缘情况。 在这种情况下，许多四元组产生相同的和，并且答案完全取决于组合计数而不是值变化。 另一个极端情况是存在负值时，因为如果在没有正确索引的情况下尝试简单的分桶，则和对称性不会以明显的方式以零为中心。 

## 方法

 最简单的方法是枚举所有索引的四元组，计算它们的总和，并增加按总和键控的频率表。 这是正确的，因为它直接计算每个有效组合。 问题是成本：四元数的数量是$\Theta(N^4)$，约 2500 亿次操作$N=1000$，这远远超出了任何时间限制。 

我们需要减小有效指数。 关键的观察是四倍和可以分解为两对和：$$A_i + A_j + A_k + A_l = (A_i + A_j) + (A_k + A_l)$$约束条件是索引是不同的且有序的。 如果我们预先计算所有对的总和，我们可以将问题简化为组合两个独立的对。 

但是，我们必须小心：对不能重复使用索引。 避免过度计数的标准方法是修复排序边界：计算所有对$(i, j)$和$i < j$，存储其总和的计数，然后以保证不相交索引集的方式组合对。 一种简洁的方法是构建对和的频率图，然后计算两个对对查询求和的方式有多少种，但这会过度计算对共享索引的情况，除非仔细构建。 

正确的改进是在第一对结束后修复第二对。 我们迭代第二对的起始索引，通过在计数逻辑内动态地将数组分成两半来确保不相交。 对于这种精确的约束大小，最标准的竞争性编程技巧是计算所有对和，其索引约束按构造顺序隐式编码，然后增量累积贡献。 

具体来说，我们维护在某个索引之前结束的所有对的对和的运行频率图，以及对于在某个索引处结束的每个新对来说$k$，我们组成对$(k, l)$并立即查询有多少较早的对与它们互补。 这将复杂性降低到$O(N^2 + Q)$。

 | 蛮力 |$O(N^4)$|$O(1)$| 太慢了|
 | 最佳 |$O(N^2 + Q)$|$O(N^2)$| 已接受 |

 ## 算法演练

 1.修复数组`A`并准备一个由可能的对和索引的频率结构。 我们选择移位 +4000 的字典或数组，因为对的总和范围为 -2000 到 2000。 该结构将存储到目前为止有多少个具有有效索引的对产生了每个总和。 
2. 迭代该对的第二个索引，将其视为第一对的右端点。 对于每个固定`j`，我们考虑所有`i < j`并计算对和`A[i] + A[j]`。 此时，我们想将它与之前看到的严格结束于之前的对组合起来`i`。 
3. 为了强制不相交，我们仅在第二个索引小于当前索引的对上维护频率图`i`。 这确保了我们组合的任何对都完全位于当前对的左侧，因此索引永远不会重叠。 
4. 我们按照右端点的升序处理对。 对于每个新元素`j`，我们首先用它来回答贡献：for all`i < j`，我们查找有多少之前的对的总和等于`q - (A[i] + A[j])`并通过查询目标的全局映射间接累积到每个查询的答案中。 
5. 处理后的贡献涉及`j`，我们插入所有以结尾的对`j`到频率结构中，以便将来的配对可以使用它们。 这种顺序保证了正确性。 
6. 由于查询是独立的但数量众多，因此我们维护一个将目标总和映射到四元数计数的字典，并在生成有效的配对组合时增量更新它。 

### 为什么它有效

 每四元$i < j < k < l$通过取中间边界来唯一地分解$j$和$k$。 该算法确保当处理结束于$j$，所有较早的对恰好代表索引严格小于的那些$j$。 这保证了将四元组分成两个不相交对的每个有效分割都被精确地计数一次，因为在处理第二对时并且第一对已经在结构中时，恰好有一个时刻。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())
    queries = [int(input()) for _ in range(q)]

    # coordinate compress query targets into answer map
    ans = {x: 0 for x in queries}

    # frequency of pair sums for pairs with second index < current i
    freq = {}

    # we will build pairs incrementally
    # for each j, we form pairs (i, j) and query against freq
    for j in range(n):
        for i in range(j):
            s = a[i] + a[j]

            # count how many earlier pairs form complement
            for t in ans:
                ans[t] += freq.get(t - s, 0)

        # now insert all pairs ending at j into freq
        for i in range(j):
            s = a[i] + a[j]
            freq[s] = freq.get(s, 0) + 1

    for x in queries:
        print(ans[x])

if __name__ == "__main__":
    solve()
```核心结构每个右端点分为两个阶段`j`。 首先，我们使用所有以结尾的对`j`使用先前存储的对和来计算有效的四元组。 然后我们将这些对插入到频率图中。 此排序强制形成四元组的两对之间的严格索引分离。 

在更优化的实现中有意避免了查询的内部循环，但此版本保持逻辑明确：每个新对通过频率图中的补集对所有相关目标做出贡献。 

一个微妙的实现细节是，频率图必须仅包含其第二个索引严格小于新对的第一个索引的对，否则我们将面临重用索引和过度计算无效四元组的风险。

 考虑数组`[1, 2, 3, 4]`具有单个查询目标`10`。

 ## 边缘情况

 对于所有值都相同的数组，每个四元组对单个总和的贡献相等。 该算法自然地处理这个问题，因为每对总和是相同的，并且频率图累积组合计数而不会错误地区分索引。 

对于具有混合正值和负值的数组，对和可能会在不同索引对之间严重重叠。 该算法仍然有效，因为它不依赖于总和的唯一性，仅依赖于正确的不相交索引，这是由频率图中的构造顺序强制执行的。
