 ## 解决方案
 ## 问题理解

 在雪莉到达之前，我们已经排了队。 每个人都可以从共享池中获取食物，其中包括披萨片、炸玉米饼和酱汁。 每个人最多可以自由携带两件物品，其中一件物品是披萨片或炸玉米饼。 此外，如果一个人选择恰好两种酱汁，他们将获得一份额外的奖励。 

问题不在于队列的固定行为，而在于可能性。 我们必须确定是否存在某种方式可以让雪莉前面的人做出选择，以便在轮到她之前吃完所有披萨片或所有炸玉米饼。 

关键点是我们正在推理最坏情况的消耗：我们正在询问资源是否足以保证在雪莉到达之前披萨和炸玉米饼都不会完全耗尽。 

这些限制允许最多 100,000 人和最多 100,000 个单位的每种资源。 我们尝试枚举每个人的选择的简单模拟会太慢，因为原则上每个人都可以做出多个组合决策。 任何方法都必须将问题简化为计算最大可能的消耗，而不是模拟个人决策。 

A subtle edge case arises from sauces. 天真的读者可能会认为每个人都可以独立地获取额外的物品，但额外的物品是由共享的有限酱汁资源控制的。 这造成了人与人之间的耦合：额外的物品在全球范围内受到酱汁总量的限制，而不是每人的限制。 

例如，如果有很多人但只有一两种酱料，则无论有多少人排队，都只能出现少量额外的物品。 忽视这一点会导致高估消费能力。 

Another edge case is when sauces are plentiful. 那么每个人可以有效地拿走三件物品，但前提是每次额外的转换都有足够的酱汁。 

## 方法

 思考这个问题的一种暴力方式是模拟 n 个人中的每一个并尝试每一种可能的选择：他们可以在披萨和炸玉米饼中选择 0、1 或 2 种食物，并可能将酱汁转换成额外的物品。 对于每种配置，我们都会跟踪剩余的披萨和炸玉米饼，并检查在到达 Shelly 之前是否达到零。 

这种方法在概念上是正确的，因为它探索了所有有效的决策序列。 然而，每个人的分支因素使其不可行。 每个人都有多种选择，组合的数量随着n呈指数增长。 即使简化的模拟每个场景也是 O(n)，但场景的数量是 n 级的组合，这远远超出了限制。 

关键的观察结果是，我们不关心个体之间的分配，只关心雪莉到达之前可以消耗的物品总数。 每个人最多贡献两项强制性项目，如果酱汁允许，还可能贡献一项额外项目。 由于每个项目在消耗方面都是可以互换的（披萨或炸玉米饼），因此耗尽特定资源的最坏情况是所有项目都分配给该资源。 

因此，问题简化为计算 n 个人可以集体拿走的最大物品总数，尊重全局酱汁约束，并检查该总数是否足够大以耗尽披萨或炸玉米饼。 

每个额外物品恰好需要两种酱汁，因此额外物品的总数受到人数和酱汁对数量的限制。

 ## 算法演练

1. 计算酱汁可能产生多少额外物品。 每个额外物品恰好消耗两种酱汁，因此额外物品的最大数量为 Z // 2。这是一个硬性全局限制。 
2. 将额外物品进一步限制为人数 n，因为每个人最多可以贡献一件额外物品。 
3. 计算消耗的最大物品总数为 2n 加上额外物品的数量。 值 2n 代表所有人的保证最大基本消费。 
4. 将此总数与可用供应量进行比较。 如果总容量至少为 X 片披萨，则存在一种方法将所有消耗分配给披萨并在 Shelly 到达之前耗尽它。 
5、同样，如果总容量至少为Y个tacos，则tacos可以用完。 
6. 如果任一条件成立，则输出“yes”，否则输出“no”。 

### 为什么它有效

 关键的不变量是，任何人的每一次行动最多为所采取的每件物品贡献一个消耗单位，并且每件物品在其消耗的资源方面是无法区分的。 由于我们仅检查是否可能完全耗尽至少一种资源，因此对抗策略始终可以将所有可用的项目槽分配给单一资源类型。 因此，任何单一资源的最大可能消耗恰好是所有人可用的物品槽总数，即 2n 加上所有可能的额外物品。 如果此最大值未达到资源总量，则任何有效的分配都不会耗尽该资源。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    X, Y, Z = map(int, input().split())

    extra = min(n, Z // 2)
    total = 2 * n + extra

    if total >= max(X, Y):
        print("yes")
    else:
        print("no")

if __name__ == "__main__":
    solve()
```该实现直接计算 Shelly 到达之前可以消耗的最大物品数量。 线路`extra = min(n, Z // 2)`对酱料的使用施加了两个限制：每件额外的物品消耗两种酱料，并且每个人只能触发一个这样的奖励。 

价值`total = 2 * n + extra`代表了全球的消费能力。 最终比较使用`max(X, Y)`因为耗尽披萨或炸玉米饼就足以得到“是”的结果，并且这两种资源共享相同的最坏情况分配能力。 

一个常见的错误是将酱汁视为每人独立可用，这会错误地使用`Z // 2`没有`min(n, ...)`帽。 另一个是在检查可能性时忘记相同的总容量可以完全集中在一个资源上。

 ## 边缘情况

 一种重要的边缘情况是没有酱汁。 在这种情况下，无法生成额外的物品，因此系统崩溃为严格的 2n 容量模型。 用于输入`n = 5, X = 20, Y = 3, Z = 0`，我们得到总计 = 10。披萨可以用完，但炸玉米饼不能，所以答案仍然是“是”，因为至少有一个资源是可访问的。
