 ## 解决方案
 ## 问题理解

 我们得到一堆披萨，每个披萨被切成 8 个相同的片。 和$n$披萨，总片数固定为$8n$。 这些切片必须分布在$m$朋友们。 

该分布同时有两个约束。 每个朋友必须收到完全相同数量的切片，并且该数量必须至少为$k$。 我们不允许给任何人留下比另一个人更少的切片，也不允许给某人低于最低满意度阈值的正数切片。 

所以问题就变成了检查披萨的总量是否可以平均分成$m$相同的部分，以及每个部分是否足够大。 

从约束的角度来看，$n$可以大到$10^5$，所以切片总数可以达到$8 \cdot 10^5$。 好友数量最多100个，数量很少。 任何逐片模拟分配或尝试搜索可能分配的解决方案在复杂性上仍然微不足道，但没有必要。 问题的结构强烈表明恒定时间算术检查就足够了。 

这里的一个天真的错误是忽略可分性要求，只检查每人的平均切片数是否超过$k$。 例如，如果$n = 2$,$m = 3$,$k = 1$，那么总切片为 16，并且$16/3 \ge 1$在数值上成立，但除法是不可能的，因为 16 不能被 3 整除。正确的输出是 false。 

另一个常见的错误是只检查整除性而忘记了最低要求。 例如，如果$n = 1$,$m = 4$,$k = 3$，则总切片为 8，可被 4 整除，每人 2 个，但 2 低于最低要求，因此必定失败。 

这两个约束必须同时实施。 

## 方法

 思考这个问题最直接的方法是想象实际分配切片。 人们可以迭代给每个朋友所有可能的切片分配，确保每个朋友至少收到$k$，并验证是否存在有效的相等分区。 然而，由于切片是相同的并且只有计数很重要，因此这很快就会陷入计数问题而不是组合分配问题。 

即使我们尝试暴力构造，我们本质上也会尝试分区$8n$进入$m$相等的整数，每个至少$k$。 对于每个朋友唯一有意义的候选值是平均值$x = \frac{8n}{m}$，前提是这种划分是准确的。 如果除法不精确，则任何枚举都无法修复它。 如果准确的话，剩下的唯一检查就是是否$x \ge k$。 

关键的观察是有效分布的结构完全由算术约束决定。 一旦平等被强制执行，就没有灵活性：每个朋友都必须准确地收到$x$，因此可行性减少为检查这样的整数是否$x$存在且满足下界。 

这将问题从指数或组合搜索简化为常数时间计算。

 ## 算法演练

 1. 计算切片总数为$total = 8 \cdot n$。 这表示必须进行无剩余分区的完整资源池。 
2. 检查是否$total$可以整除$m$。 如果它不可整除，则不可能进行均等分割，因为至少一个朋友必然会收到不同数量的切片。 
3. 如果可以整除，计算每人的分配量$x = total / m$。 该值是强制的，在等式约束下没有替代的有效分布。 
4. 检查是否$x \ge k$。 这确保同时满足每个朋友的最低满意度要求。 
5. 仅当两个条件都成立时才返回 true，否则返回 false。 

### 为什么它有效

 一旦我们强制平等分配，每个有效的解决方案都必须分配完全相同的整数$x$给每一位朋友。 这意味着总和完全由下式决定$m \cdot x$，因此可行性完全取决于是否$8n$可以用那种形式来表达。 可除性检查保证结构可行性，不等式检查强制执行最小约束。 除了该单个候选值之外不存在其他配置，因此决策已完成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    m = int(input().strip())
    k = int(input().strip())

    total = 8 * n

    if total % m != 0:
        print("FALSE")
        return

    each = total // m

    if each >= k:
        print("TRUE")
    else:
        print("FALSE")

if __name__ == "__main__":
    solve()
```该实现准确地反映了推导过程。 乘法$8 * n$是在常数时间内完成的，并且安全地适合 Python 整数。 可分割性检查首先进行，因为它避免了对不存在的每人分配进行计算或推理。 只有当分割有效时我们才计算$each$，代表每个好友的强制分配。 

最终比较强制执行最低要求。 不存在涉及部分赋值的极端情况，因为相等消除了所有灵活性。

 ## 边缘情况

 一种极端情况是只有一个朋友。 用于输入$n = 1, m = 1, k = 8$，总切片为 8，整除性成立，每个朋友得到 8。算法计算$each = 8$并通过阈值检查，产生 TRUE。 这证实了逻辑正确地处理了普通分区。 

另一个边缘情况是总数不能被好友数量整除。 为了$n = 2, m = 3, k = 1$，总计为 16。由于 16 % 3 非零，因此算法立即拒绝这种情况。 这避免了对部分分配的错误推理。 

最后一种情况是整除性成立但最小约束失败。 为了$n = 1, m = 4, k = 3$，总数为8，每个为2，阈值检查失败。 这证实了该算法不会混淆分裂的可行性与满足约束。
