 ## 解决方案
 ## 问题理解

 我们得到了一系列按固定顺序到达的学生，每个学生都会吃掉特定数量的披萨片。 准备了 K 个披萨，每个披萨必须有相同的片数，称之为值 X。披萨是一个接一个地提供的：如果可能的话，每个学生从当前的披萨中取出所需数量的披萨，但如果剩余的切片不够，则立即丢弃当前的披萨，并为该学生打开一个新的披萨。 

目标是选择尽可能小的 X，以便为所有学生提供服务而无需超过 K 个披萨。 

关键细节是这个过程是贪婪的和线性的：每个学生要么适合当前的披萨，要么强制重置。 这意味着使用的披萨数量完全取决于前缀和超过 X 倍数的频率。 

这些约束允许最多 100000 名学生和 100000 个披萨，因此任何尝试所有候选 X 值并对每个值进行简单模拟的解决方案都会太慢。 对 X 进行暴力破解直到所有需求的总和是不可能的，因为需求可以达到 10^6，总数可以达到 10^11。 即使对每个候选人进行线性扫描也会超出时间限制。 

当单个学生要求超过 X 时，就会出现微妙的边缘情况。在这种情况下，当前模型意味着我们仍然给他们新鲜披萨中的披萨，因此 X 必须始终至少为 max(d_i)。 另一个边缘情况是，当 K 足够大时，即使非常小的 X 也可能起作用，但最小的 X 仍然受到序列中局部“溢出点”的限制，而不仅仅是总和。 

## 方法

 一种直接的方法是猜测值X并模拟服务过程。 对于固定的 X，我们迭代学生，跟踪当前披萨中剩余的切片，并计算使用了多少个披萨。 每当学生无法适应时，我们就会开始制作新的披萨。 此模拟每 X 的复杂度为 O(N)。 

困难在于选择X。由于X至少为max(d_i)且至多为sum(d_i)，所以我们可以对它进行二分查找。 然而，可行性函数是单调的：如果给定的 X 起作用，任何更大的 X 也起作用，因为更大的披萨永远不会增加休息的次数。 这种单调性允许对 X 进行二分搜索。 

关键的见解是，可行性仅取决于贪婪打包是否最多产生 K 个分段，其中每个分段是一组连续的学生，其总和不超过 X。当分段超过 X 时，它会强制进行切割。 因此，检查 X 可以简化为计算创建了多少个此类段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解 X 与模拟 | O(N·sum(d)) | O(N·sum(d)) | O(1) | O(1) | 太慢了|
 | 二分查找+贪心检查| O(N 对数和(d)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们定义一个函数`can(X)`如果每个披萨有 X 片，则返回 K 个披萨是否足够。 

1. 从使用的披萨数为零且当前披萨的剩余容量为零开始。 

我们从概念上将其视为尚未打开披萨。 
2. 按顺序遍历学生。 

对于每个有需求 d_i 的学生，尝试将他们放入当前的披萨中。 
3. 如果当前披萨至少剩余 d_i 片，则从中减去 d_i。 

该模型无需打开新的披萨即可为他们提供服务。 
4. 否则，我们必须为该学生开一个新的披萨。 

将披萨数量增加 1，将剩余容量设置为 X，并减去 d_i。 
5. 如果在任何时候有一个学生 d_i > X，则立即返回 false。 

这是必要的，因为否则即使是新鲜的披萨也无法满足他们。 
6.处理完所有学生后，返回所使用的披萨总数是否最多为K个。 

曾经`can(X)`定义后，我们在 max(d_i) 和 sum(d_i) 之间进行二分搜索 X，选择最小的 X，使得`can(X)`是真的。 

为什么它有效：每个固定的 X 定义了数组的确定性贪婪分割。 增加X只能合并段，而不能分割它们，因此使用的披萨数量在X中是单调非增加的。这保证了二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(a, k, x):
    used = 1
    rem = x
    for v in a:
        if v > x:
            return False
        if rem >= v:
            rem -= v
        else:
            used += 1
            rem = x - v
            if used > k:
                return False
    return used <= k

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo = max(a)
    hi = sum(a)

    while lo < hi:
        mid = (lo + hi) // 2
        if can(a, k, mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```该解决方案将可行性检查与 X 上的搜索分开。`can`函数准确模拟披萨的消费方式，跟踪剩余的切片并计算需要多少披萨。 

一个常见的错误是忘记了，不适合的学生不会吃掉部分披萨，而是会吃掉剩余的部分并立即强制吃新鲜的披萨。 这就是我们重置的原因`rem = x - v`而不是试图将剩余产能继续推进。 

另一个微妙的点是初始化`used = 1`。 我们只在需要时打开披萨，但第一个学生总是从到达后必须存在的披萨中消费。

 ## 边缘情况

 一种边缘情况是当 K 与 N 相比非常大时。对于像这样的输入`N = 5, K = 100`，答案就是 max(d_i)。 该算法可以处理这个问题，因为二分搜索从 lo = max(a) 开始，并且`can(lo)`立即成功，因为没有学生超出容量，并且每个学生都可以在需要时吃到新鲜的披萨。 

另一个极端情况是每个需求都相同。 为了`a = [3,3,3,3]`，候选人 X = 3 导致每个学生一份披萨，因此使用 4 个披萨。 可行性检查正确递增`used`每当减法后剩余为零时，确保不会少算。 

最后的边缘情况是中间有一个大尖峰的序列。 为了`a = [1,1,100,1,1]`，由于显式检查，任何 X < 100 都会立即失败`if v > x`。 这可以防止模拟错误地尝试部分服务不可能的请求，并确保二分搜索不会漂移到无效范围。
