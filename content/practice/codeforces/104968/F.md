 ## 解决方案
 ## 问题理解

 我们正在安排披萨的排列，标签为 1 到$n$，其中每个标签是该披萨的半径。 一旦我们选择了一个订单，我们就会查看堆栈中的所有位置对：如果较大的披萨出现在较小的披萨下方，我们称该对为“正确”。 

这与计算排列中的反转完全相同，只是定义是用堆栈中的“下方”和“上方”来表述的。 如果我们把栈从上到下写成排列$p$，那么真对是任意对$i < j$这样$p_i > p_j$。 

所以任务是：计算有多少种排列$\{1,2,\dots,n\}$正好有$k$倒置。 

限制条件$n \le 1000$,$k \le 1000$立即表明我们正在用有界反转计数来计算排列，而不是枚举排列。 完整的枚举是不可能的，因为$n!$增长极其迅速，即使是$n = 20$。 上的界限$k$是关键信号：虽然排列很大，但我们关心的反转计数很小，因此动态规划$k$是有道理的。 

一个微妙的边缘情况是$k = 0$或者$k = \frac{n(n-1)}{2}$。 为了$k = 0$，只有递增排列才有效，所以答案是 1。对于大的$k$，我们必须记住，即使$k \le 1000$，最大可能的反转$n = 1000$更大，所以许多状态对应于零有效排列，并且必须通过 DP 边界而不是假设来自然处理。 

另一个常见的失败是将其视为简单的组合插入问题而不控制过度计数。 每个插入步骤都会以范围相关的方式影响反转计数，因此天真的贪婪放置不会保持正确性。 

## 方法

 蛮力方法将生成所有大小的排列$n$并对每个反转进行计数，当它等于时增加计数器$k$。 这是正确的，但不可行。 甚至$n = 12$已经生产了$479001600$排列，以及每个排列的计算反转将使该成本成倍增加，导致远远超出任何时间限制的爆炸。 

关键的观察是逐步构建排列。 假设我们已经知道有多少种排列方式$i-1$具有一定反转计数的元素。 当我们插入元素时$i$，我们在当前序列中选择一个位置。 配售$i$在位置$j$准确贡献$i - 1 - j$新的反转，因为位置之后的所有元素$j$小于$i$创建反转。 自从$i$是第一个元素中最大的元素$i$，其右侧的每个元素都较小，因此每个右侧元素贡献一次反转。 

这将问题简化为关于前缀大小和反转计数的标准动态规划公式。 该结构与通过反转数（也称为马洪数）计数排列相同。 

我们维护一个 DP，其中$dp[i][j]$是排列的数量$\{1..i\}$恰好与$j$倒置。 转换来自插入元素$i$进入大小排列中所有可能的位置$i-1$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了|
 | 最佳DP |$O(nk)$|$O(nk)$| 已接受 |

 ## 算法演练

 我们定义一个 DP 表，其中每个状态记录前缀长度的多少种排列实现给定的反转计数。 

### 步骤

 1.初始化一个大小的DP表$(n+1) \times (k+1)$带零。 放$dp[0][0] = 1$。 

这表示只有一种方法可以用零反转来排列零元素：空排列。 
2. 迭代前缀大小$i$从 1 到$n$。 

在每一步中，我们都融入元素$i$作为当前前缀中的最大值。 
3. 对于每个$i$，计算转换为$dp[i]$从$dp[i-1]$。 

我们考虑插入$i$进入长度排列中的每个可能的位置$i-1$。 如果我们插入它$pos$从右边开始的位置，它准确地创建了$pos$新的反转。 
4. 对于每个反转计数$j$从 0 到$k$，累积有效插入的贡献：$$dp[i][j] = \sum_{x=0}^{\min(j, i-1)} dp[i-1][j-x]$$这里$x$表示放置所贡献的反转数量$i$，范围从 0（放在最后）到$i-1$（放在前面）。 
5. 为了有效地计算，请使用前缀和$dp[i-1]$。 

这避免了重新计算每个的总和$j$，降低复杂度$O(n^2k)$到$O(nk)$。 
6. 返回$dp[n][k]$模数$10^9 + 7$。 

### 为什么它有效

 在步骤$i$，每个有效的大小排列$i$通过大小排列唯一形成$i-1$并插入$i$恰好在一个位置。 该插入贡献了确定数量的新反转，等于向左移动的元素数量$i$。 这给出了大小状态之间的双射$i-1$并转变为尺寸状态$i$。 DP 对每个结构只计数一次，因此不会发生多算或遗漏的情况。
