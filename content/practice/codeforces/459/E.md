 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每条边都有一个权重。 我们希望通过边的数量来衡量最长的可能路径，但有一个限制：每当我们从一条边移动到下一条边时，新边的权重必须严格大于前一条边的权重。 

路径不必很简单。 可以重新审视顶点。 图中允许出现循环。 唯一重要的是沿所选路径的边权重序列严格递增。 

对于每个有向边`(u → v, w)`，我们可以将其视为某些先前构建的路径的可能扩展，其结尾为`u`，但前提是该路径中使用的最后一条边的权重小于`w`。 

该图最多可以包含`3 · 10^5`顶点和`3 · 10^5`边缘。 任何显式探索路径的算法都是不可能的。 甚至一个`O(m²)`动态规划解决方案大约需要`9 · 10^10`最坏情况下的操作。 我们需要一些接近线性或`O(m log m)`。 

最危险的情况来自于共享相同权重的边。 

考虑：```
3 2
1 2 5
2 3 5
```正确答案是：```
1
```两条边不能链接在一起，因为权重必须严格增加。 在处理重量边缘时立即执行不小心的 DP 更新`5`可能会错误地产生长度`2`。 

另一个重要的情况是权重增加的循环：```
3 3
1 2 1
2 3 2
3 1 3
```正确答案是：```
3
```尽管该图包含循环，但增加权重可以防止无限路径。 答案是有限的，因为每一条下一条边都必须具有更大的权重。 

第三种微妙的情况是具有相同权重的多个传入边：```
3 3
1 2 1
1 3 1
2 3 2
```正确答案是：```
2
```两条权重 1 的边都创建长度为 1 的路径。权重 2 的边应延伸终止于顶点 2 的最佳路径。DP 必须保留每个顶点的最大值。 

## 方法

 蛮力方法会尝试构建每条有效的权重递增路径。 从每条边开始，我们可以递归地跟踪具有较大权重的所有传出边。 这是正确的，因为它准确地枚举了问题允许的路径。 

问题在于此类路径的数量可能呈指数级增长。 即使每个顶点只有几个分支选择的图也可以生成大量的递增序列。 高达`3 · 10^5`边缘，穷举探索是完全不可行的。 

关键的观察结果是，实际的路径结构比端点和最后使用的权重重要得多。 

假设我们按权重递增的顺序处理边。 当考虑边缘时`(u → v, w)`，每条有效路径结束于`u`其最后的边权重严格小于`w`可以通过这条边延伸。 

让`dp[x]`表示结束于顶点的最佳路径长度`x`仅使用已经处理过的权重。 

然后是边缘`(u → v, w)`可以创建一条长度的路径：```
dp[u] + 1
```复杂的是重量相等。 

如果两条边的权重相同，则它们一定不能互相影响，因为路径需要严格增加。 一一处理并更新`dp`立即会意外地允许链接等权重的边。 

解决方法是将所有相同权重的边一起处理。 

对于重量的每一个边缘`w`，我们首先使用权重之前存在的 DP 状态计算其候选值`w`开始了。 仅在重量的每个边缘之后`w`已评估我们是否提交更新。 

这在较小的重量和当前重量之间形成了清晰的分离。 

按权重对边进行排序后，每条边都被处理一次，给出`O(m log m)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳| O(m log m) | O(n) | 已接受 |

 ## 算法演练

 1.读取所有边并将它们存储为`(weight, from, to)`。 
2. 按重量对边缘进行排序。 

排序保证了我们处理重量时`w`，所有较小的权重都已经对 DP 状态做出了贡献。 
3.维护数组`dp[v]`。`dp[v]`表示终止于顶点的有效递增权重路径的最大长度`v`，仅使用严格小于当前处理组的权重。 
4. 处理按相等权重分组的边。 

所有具有相同重量的边必须一起处理，这样它们就不能相互延伸。 
5. 对于每一个边缘`(u → v)`在当前权重组中，计算：```
candidate = dp[u] + 1
```这是结束于的最佳路径`u`使用较小的权重，并由当前边缘扩展。 
6. 暂时存储这些候选更新，而不是直接写入`dp`。 

这可以防止相同权重的边相互影响。 
7. 评估组中的每条边后，应用：```
dp[v] = max(dp[v], candidate)
```对于所有存储的更新。 
8. 继续下一个重量组。 
9. 答案是中存在的最大值`dp`。 

### 为什么它有效

 不变量是在处理权重组之前`w`,`dp[v]`等于结束于的有效路径的最大长度`v`其最后的边权重严格小于`w`。 

当我们评估一条边时`(u → v, w)`，值`dp[u] + 1`表示可以合法位于该边之前的每条有效路径，因为所有此类路径都以较小的权重结束。 

更新会延迟到整个小组完成为止。 结果，重量没有边缘`w`可以使用重量的另一个边缘`w`作为它的前身。 这完全符合严格的不平等要求。 

通过增加权重的归纳，每条有效路径都被表示，并且每条表示的路径都是有效的。 因此最终的最大DP值就是最长的权重递增路径的长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u, v))

    edges.sort()

    dp = [0] * (n + 1)

    i = 0
    while i < m:
        j = i
        updates = []

        while j < m and edges[j][0] == edges[i][0]:
            _, u, v = edges[j]
            updates.append((v, dp[u] + 1))
            j += 1

        for v, val in updates:
            if val > dp[v]:
                dp[v] = val

        i = j

    print(max(dp))

if __name__ == "__main__":
    solve()
```第一步将每条边及其权重存储在一起并对列表进行排序。 这给出了从较小权重到较大权重的自然处理顺序。`dp[v]`存储结束于顶点的最佳路径长度`v`。 最初每个值都为零，因为没有使用边缘。 

最重要的实施细节是临时的`updates`大批。 在检查重量组时，我们从不修改`dp`直接地。 每个候选值都是根据旧的 DP 状态计算的。 只有在处理完整个组之后才会提交更新。 

如果没有这种分离，两个等权重的边可能会相互延伸并违反严格的增加条件。 

最终答案只是存储在 DP 数组中任何位置的最大路径长度。

 ## 边缘情况

 考虑两条等权边：```
3 2
1 2 5
2 3 5
```两条边都属于同一权重组。 在评估过程中，算法使用旧的 DP 状态计算候选：```
(2,1)
(3,1)
```只有在收集了两个候选者之后才会应用更新。 第二条边永远看不到第一条边的效果，所以答案仍然存在`1`，这是正确的。 

现在考虑一个循环：```
3 3
1 2 1
2 3 2
3 1 3
```权重组按顺序处理`1`,`2`,`3`。 DP 值变为：```
dp[2] = 1
dp[3] = 2
dp[1] = 3
```算法输出`3`。 允许重新访问顶点，但增加权重会阻止无限增长。 

最后，考虑汇聚到同一顶点的多条路径：```
4 4
1 3 1
2 3 2
3 4 3
1 4 10
```处理后的权重`1`和`2`, 顶点`3`存储最佳可能的路径长度。 当体重`3`处理完毕后，边缘`3 → 4`延伸最强的可用路径。 DP更新使用`max`，因此较弱的替代方案永远不会覆盖更好的替代方案。 结果的答案是`2`，对应于任一`1→3→4`或者`2→3→4`。
