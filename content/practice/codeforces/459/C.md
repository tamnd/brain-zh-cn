 ## 解决方案
 ## 问题理解

 我们需要将每个学生分配给其中之一`k`巴士上的每个`d`天。 

对于每个学生，我们可以将他们的作业视为长度序列`d`。 例如，如果`d = 3`，学生可能会乘坐公共汽车`(2, 1, 2)`这三天里。 

如果两个学生的整个序列相同，他们就会成为亲密的朋友。 他们可以在某些日子共享一辆公共汽车，但如果他们每天共享同一辆公共汽车，则他们的顺序匹配并且安排无效。 

任务是为`n`学生，以便每个学生都有一个独特的序列。 如果这是不可能的，我们必须打印`-1`。 

这些约束立即表明我们没有处理搜索问题。 两个都`n`和`d`可以达到1000，同时`k`可以大到`10^9`。 通过分配进行强力搜索是没有希望的，因为可能的调度数量呈指数级增长。 由于输出本身包含`n × d`数字，任何被接受的解决方案可能会花费大部分时间直接生成答案。 

核心问题是我们能否付出一切`n`学生不同的长度序列`d`，其中每个位置可以取其中之一`k`价值观。 

正好有`k^d`不同长度的序列`d`超过一个字母表大小`k`。 如果`n > k^d`，那么即使在最好的排列中也没有足够的不同序列，因此一对学生必须接收相同的序列。 根据鸽巢原理，答案是不可能的。 

一些边缘情况很容易被错误处理。 

考虑：```
3 1 2
```只有一辆公共汽车。 每个学生每天必须乘坐1路公交车。 所有学生都会收到相同的序列`(1,1)`，所以正确答案是：```
-1
```忽略唯一性要求的粗心构造将错误地输出分配。 

考虑：```
1 1 1
```只有一名学生。 唯一性是自动的，因为不存在成对的学生。 正确的输出是：```
1
```一些实现错误地拒绝所有情况`k = 1`。 

另一个微妙的情况是：```
8 2 3
```自从`2^3 = 8`，有足够多的不同序列。 正确的解决方案必须使用所有可能的序列。 编号系统中存在相差一错误的实现可能仅生成七个不同的分配并错误地报告失败。 

## 方法

 思考问题最直接的方法是给每个学生分配一个序列，然后检查所有序列是否不同。 

暴力方法会每天生成作业，比较每一对学生，并不断修改时间表，直到所有冲突消失。 这种策略很快就变得不可行，因为搜索空间包含`k^(n·d)`可能的时间表。 即使对于非常小的输入，详尽的探索也是不可能的。 

关键的观察是学生只需要不同的序列。 

每个学生的时间表都是一个长度-`d`大小字母表上的字符串`k`。 可能的调度数恰好是`k^d`。 这将问题转化为编号问题：为每个学生分配不同的代码字。 

生成不同代码字的自然方法是将学生索引写入基数中`k`。 

假设我们对学生进行编号`0`到`n-1`。 

学生`0`对应于：```
000...
```学生`1`对应于：```
001...
```学生`2`对应于：```
002...
```等等，准确地使用`d`根据-`k`数字。 

如果`n ≤ k^d`，那么所有学生指数都适合`d`根据-`k`数字。 不同的数字具有不同的数字表示形式，因此每个学生都会自动收到一个独特的时间表。 

声明中的公交车号码编号为`1`到`k`，而基数`k`数字范围从`0`到`k-1`。 我们只需在打印时添加一项即可。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳| O(n·d) | O(n·d) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`k`， 和`d`。 
2. 确定是否至少`n`存在不同的时间表。 

的计算能力`k`直到长度`d`，一旦值达到或超过就提前停止`n`。 
3. 如果之后`d`乘法的值仍然小于`n`， 打印`-1`。 

这意味着`k^d < n`，因此没有足够的不同序列供所有学生使用。 
4. 创建一个`d × n`答案矩阵。 

排`i`将代表当天的作业`i`。 
5. 对于每个学生索引`s`从`0`到`n-1`， 写`s`在基地`k`。 

准确提取`d`数字。 缺少高位数字将被视为零。 
6. 将提取的数字存储到答案矩阵中。 

这`i`第 - 位数字决定当天使用的巴士`i`。 
7. 处理完所有学生后，打印时将每个存储的数字加一。 

这将转换数字`0..k-1`转换成公交车号码`1..k`。 

### 为什么它有效

 每个学生都被分配了基地 -`k`之间不同整数的表示`0`和`n-1`。 

因为基地-`k`表示是唯一的，没有两个学生会收到相同的数字序列。 因此，对于任何一对学生来说，至少有一天他们所分配的巴士有所不同。 

施工完全采用`d`数字。 当所有学生指数都存在这种表示时`n ≤ k^d`。 如果`n > k^d`，可能的序列比学生的少，因此不存在有效的排列。 因此该算法既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())

    cnt = 1
    for _ in range(d):
        if cnt >= n:
            break
        cnt *= k

    if cnt < n:
        print(-1)
        return

    ans = [[0] * n for _ in range(d)]

    for student in range(n):
        x = student
        for day in range(d):
            ans[day][student] = x % k
            x //= k

    out = []
    for day in range(d):
        out.append(" ".join(str(ans[day][student] + 1) for student in range(n)))

    sys.stdout.write("\n".join(out))

solve()
```第一部分检查是否存在足够的不同时间表。 我们永远不需要确切的值`k^d`一旦超过`n`，因此乘法可以提前停止。 

该矩阵按天而不是按学生组织，因为所需的输出格式每行打印一天。 这避免了稍后的转置操作。 

对于每个学生，我们反复采取`x % k`并除以`k`。 这提取了基数-`k`从最低有效位到最高有效位的数字。 由于每个学生的索引不同，因此他们的数字向量也不同。 

一个常见的错误是忘记公交车号码的起始位置是`1`。 内部表示使用数字`0..k-1`，所以我们只在打印时添加一个。 

另一个常见的错误是尝试计算`k^d`直接地。 虽然Python可以处理大整数，但这是没有必要的。 提前停止使检查变得简单而高效。

 | 日 | 学生 0 | 学生 1 | 学生 2 |

 输入：```
8 2 3
```自从`2^3 = 8`，需要每个可能的长度为三的二进制序列。 

| 学生| 数字 |
 | --- | --- |

 | 1 | 001|
 | 2 | 010|
 | 3 | 011|

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n·d) | 每个学生都做出了准确的贡献`d`根据-`k`数字|
 | 空间| O(n·d) | 输出矩阵存储`d × n`价值观 |

 最大可能的输出已经包含一百万个数字，因为`n`和`d`可以是 1000。`O(n·d)`结构与输出尺寸相匹配并在限制范围内舒适地安装。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n, k, d = map(int, input().split())

    cnt = 1
    for _ in range(d):
        if cnt >= n:
            break
        cnt *= k

    if cnt < n:
        return "-1"

    ans = [[0] * n for _ in range(d)]

    for student in range(n):
        x = student
        for day in range(d):
            ans[day][student] = x % k
            x //= k

    return "\n".join(
        " ".join(str(ans[day][student] + 1) for student in range(n))
        for day in range(d)
    )

# minimum case
assert run("1 1 1\n") == "1"

# impossible case
assert run("3 1 2\n") == "-1"

# boundary n = k^d
out = run("8 2 3\n")
assert out != "-1"

# sample-sized case
out = run("3 2 2\n")
assert out != "-1"

# another impossible boundary
assert run("9 2 3\n") == "-1"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 1 1`|`1`| 最小有效实例 |
 |`3 1 2`|`-1`| 只有一个可用序列 |
 |`8 2 3`| 任何有效的时间表| 精确的容量边界`n = k^d`|
 |`3 2 2`| 任何有效的时间表| 基础建设|
 |`9 2 3`|`-1`| First impossible value above capacity |

 ## 边缘情况

 考虑：```
3 1 2
```该算法计算：```
1^2 = 1
```自从`1 < 3`，它立即打印：```
-1
```只有一种可能的顺序`(1,1)`，因此不能为三个不同的学生分配唯一的时间表。 

考虑：```
1 1 1
```容量检查成功是因为`1^1 = 1`。 学生`0`接收数字`0`，变成总线`1`添加一项后：```
1
```单学生案例是有效的，因为不需要多个学生之间的唯一性。 

考虑：```
8 2 3
```容量检查准确达到`8`。 学生指数`0`通过`7`生成长度为三的所有二进制字符串。 由于 2 进制表示是唯一的，每个学生都有不同的时间表，并且构建在严格的边界上成功。 

考虑：```
9 2 3
```该算法计算：```
2^3 = 8
```自从`8 < 9`，它输出：```
-1
```鸽笼原则保证了不可能，因为只有八个不同的时间表存在，而九个学生需要独特的时间表。
