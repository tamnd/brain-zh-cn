 **标签：** 数据结构、分而治之、排序
 **求解时间：** 2m 17s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一个数组`a[1..n]`。 

对于每个职位`i`，定义值`L[i] = number of occurrences of a[i] in the prefix [1..i]`。 

对于每个职位`j`， 定义`R[j] = number of occurrences of a[j] in the suffix [j..n]`。 

任务是数对`(i, j)`和`i < j`这样`L[i] > R[j]`。 

原语句通过函数描述了这些值`f(l,r,x)`，但是一旦我们预先计算这两个数组，整个问题就会变得更加清晰。 

考虑示例：```
1 2 1 1 2 2 1
```前缀频率是```
L = [1,1,2,3,2,3,4]
```后缀频率为```
R = [4,3,3,2,2,1,1]
```现在的问题很简单：

 数对`(i,j)`和`i < j`和`L[i] > R[j]`。 

正是这些限制使问题变得有趣。 数组长度可以达到一百万。 二次算法大约需要```
10^12
```比较，这是完全不可能的。 甚至一个`O(n√n)`解决方案太大。 我们需要一些接近的东西`O(n log n)`。 

有一些容易被忽视的案例。 

假设所有值都是不同的：```
3
1 2 3
```然后```
L = [1,1,1]
R = [1,1,1]
```没有一对满足`1 > 1`，所以答案是`0`。 一个粗心的解决方案使用`>=`而不是`>`会错误地计算每一对。 

考虑：```
4
5 5 5 5
```这里```
L = [1,2,3,4]
R = [4,3,2,1]
```答案不只是所有配对。 有些对满足不等式，而另一些则不满足。 任何仅基于值本身的快捷方式都会失败，因为条件取决于出现次数，而不是存储在数组中的数字。 

另一个微妙的情况是许多不同的值产生相同的频率。 例如：```
4
1 2 1 2
```我们得到```
L = [1,1,2,2]
R = [2,2,1,1]
```该问题变成了频率计数问题，而不是原始数组值的计数问题。 单独处理相等的值会错过有效的对。 

## 方法

 直接解首先计算`L`和`R`。 

然后对于每一对`(i,j)`和`i<j`，我们测试是否```
L[i] > R[j]
```并在答案成立时增加答案。 

这是正确的，因为它从字面上检查定义。 不幸的是有```
n(n-1)/2
```对。 为了`n = 10^6`，这大约是`5 × 10^11`对，远远超出了可以处理的范围。 

关键的观察结果是计算后`L`和`R`，原始数组值不再重要。 我们只需要计算对```
i < j
L[i] > R[j]
```这是一个类似于倒数计数的经典计数问题。 

在普通的倒数计数中，我们计算对```
i < j
A[i] > A[j]
```使用归并排序。 这里右侧来自不同的数组，但结构几乎相同。 

在分而治之的过程中，假设我们将索引范围分为左半部分和右半部分。 

所有有效对都属于以下三类之一：

 1. 两个索引都位于左半部分。 
2. 两个指数都在右半部分。 
3.`i`在左半部分和`j`在右半部分。 

前两类是递归处理的。 

对于第三类，我们需要统计```
L[i] > R[j]
```和`i`从左侧开始`j`从右边的部分。 

如果我们对左半部分进行排序`L[i]`值和右半部分`R[j]`值，我们可以在该合并步骤的线性时间内使用两指针扫描来计算这些交叉对。 

这给出了与反转计数相同的复杂性：```
O(n log n)
```这很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最优分而治之| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### 计算频率数组

 首先计算`L`。 

从左到右遍历，同时维护频率的哈希图。 对于每个位置，增加频率`a[i]`并将结果存储在`L[i]`。 

下一步计算`R`。 

用另一个频率图从右向左遍历。 增加频率`a[i]`并将结果存储在后缀中`R[i]`。 

### 分而治之计数

 对于每个职位`i`，存储该对：```
(L[i], R[i])
```我们对索引范围执行合并排序样式递归。 

### 算法演练

 1. 构建数组`L`和`R`使用频率图。 
2. 创建位置数组。 在递归过程中，每个段将按其顺序进行排序`L`价值观。 
3. 递归求解左半部分。 
4. 递归求解右半部分。 
5. 计算交叉对，其中`i`属于左半部分并且`j`属于右半部分。 

由于左段的排序方式为`L`右段按以下顺序排序`L`，我们可以分别访问他们的`L`和`R`值并计算有多少左侧元素满足`L[i] > R[j]`。 
6. 对当前段进行排序`L`在合并步骤期间。 
7. 返回左对、右对和交叉对的总和。 

更干净的实施遵循标准 Codeforces 解决方案。 我们对索引范围本身进行递归。 在合并步骤中，原始数组中的左索引保留在右索引之前，因此每个计数的交叉对自动满足`i < j`。 

为了有效地计算交叉对，我们排序`L`。 对于右半部分的每个元素，我们计算左半部分有多少个元素```
L > R[right]
```使用移动指针。 

### 为什么它有效

 递归将所有索引对精确地划分为三组之一：完全向左、完全向右或穿过中点。 递归调用正确计算前两组。 在合并步骤中，每个交叉对的左端点在左半部分，右端点在右半部分，因此检查`L[i] > R[j]`就足够了。 因为一半是按顺序排序的`L`，两指针扫描对所有此类对进行计数，没有遗漏或重复。 每个有效对在递归级别上都被精确计数一次，其中其端点首先落入不同的两半。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cnt = {}
    L = [0] * n
    for i in range(n):
        x = a[i]
        cnt[x] = cnt.get(x, 0) + 1
        L[i] = cnt[x]

    cnt.clear()
    R = [0] * n
    for i in range(n - 1, -1, -1):
        x = a[i]
        cnt[x] = cnt.get(x, 0) + 1
        R[i] = cnt[x]

    idx = list(range(n))
    temp = [0] * n

    def dc(l, r):
        if r - l <= 1:
            return 0

        m = (l + r) // 2

        ans = dc(l, m) + dc(m, r)

        p = l
        for j in range(m, r):
            while p < m and L[idx[p]] <= R[idx[j]]:
                p += 1
            ans += m - p

        i, j, k = l, m, l
        while i < m and j < r:
            if L[idx[i]] <= L[idx[j]]:
                temp[k] = idx[i]
                i += 1
            else:
                temp[k] = idx[j]
                j += 1
            k += 1

        while i < m:
            temp[k] = idx[i]
            i += 1
            k += 1

        while j < r:
            temp[k] = idx[j]
            j += 1
            k += 1

        for t in range(l, r):
            idx[t] = temp[t]

        return ans

    print(dc(0, n))

if __name__ == "__main__":
    solve()
```第一部分计算前缀出现次数`L`和后缀出现次数`R`。 

分而治之的例程反映了合并排序。 在任何时刻，`idx[l:r]`包含该段的索引，按其排序`L`价值观。 

跨对计数是微妙的部分。 左半部分和右半部分已经排序`L`。 对于固定的右元素，所有左元素```
L > R[right]
```形成排序后的左半部分的后缀。 指针`p`仅向前移动，使整个合并的计数步骤呈线性。 

答案大约可以大到`n²/2`，因此需要一个 64 位整数。 Python 整数会自动处理这个问题。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 每级线性工作的合并排序递归 |
 | 空间| O(n) | 频率数组、索引数组和合并缓冲区 |

 和`n`高达一百万，`O(n²)`是不可能的。`O(n log n)`执行大约两千万个原始操作，这完全符合优化实现的限制，并且是预期的解决方案。

 ## 边缘情况

 考虑：```
1
7
```我们得到：```
L = [1]
R = [1]
```根本没有成对的。 递归立即触及基本情况并返回`0`。 

考虑：```
2
1 1
```这里：```
L = [1,2]
R = [2,1]
```唯一的一对是`(1,2)`我们测试：```
1 > 1
```which is false. 答案是`0`。 任何使用的实现`>=`会错误地返回`1`。 

考虑：```
4
1 2 3 4
```每个频率都等于一：```
L = [1,1,1,1]
R = [1,1,1,1]
```没有一对满足条件。 在每个合并步骤中，计数指针都会前进经过所有左侧元素，因为`L <= R`无处不在，对答案的贡献为零。 

考虑：```
4
5 5 5 5
```数组变为：```
L = [1,2,3,4]
R = [4,3,2,1]
```分而治之过程精确计算对数`(2,4)`和`(3,4)`。 订购方式`i < j`是自动保证的，因为交叉对仅在索引区间的左半部分和右半部分之间进行计数。
