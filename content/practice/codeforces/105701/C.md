 ## 解决方案
 ## 问题理解

 我们得到了一系列沿直线放置的树。 每棵树都有固定的位置和高度。 一棵树可以作为一个点保持站立，也可以被砍伐并完全向左或向右倒下，变成一段长度由其高度决定的树段。 

关键的限制是倒下的树木不得与任何已占据的位置重叠。 最初，仅占用原始树位置。 一旦一棵树倒下，它覆盖的整个部分就会被占据，未来的决策必须尊重所有先前占据的点。 

目标是在这些限制下最大限度地减少砍伐树木的数量。 

输入大小可达 100,000 棵树，坐标和高度可达 10^9。 这立即排除了任何尝试在线性时间内对所有先前树进行间隔重叠检查来简单地模拟每次切割的解决方案，因为在最坏的情况下这会降级为 O(n²) 并明显超出时间限制。 我们的目标应该是线性的或最坏的 O(n log n)，但按位置排序的输入结构表明贪婪扫描可能就足够了。 

一个微妙的点是，砍伐一棵树不仅会影响它的邻近区域，而且可能会影响左侧或右侧的大范围空间。 存储所有占用的段并检查交叉点的简单间隔簿记方法在重叠切割的长链上会失败。 

一些边缘案例说明了天真的思维的危险。 

如果所有树木都非常接近，例如位置 1、2、3、4 的高度较大（如 10），那么过早砍伐可能会阻止所有未来的砍伐，即使存在最佳交替策略也是如此。 总是在可能的情况下削减而不考虑方向的贪婪在这里可能会失败。 

如果高度非常小，例如高度为 1 的位置 1、2、3、4，则可以剪切所有内容，并且任何算法都必须正确处理紧密的间距，而不会错误地阻止有效剪切。 

如果存在较大间隙，例如位置 1、2、1000、1001，则间隙周围的树几乎独立运行，正确的解决方案必须重置其跨间隙的局部约束。 

关键的困难不是几何精度，而是局部地从左到右决定一棵树应该向左倒、向右倒还是留下来。 

## 方法

 蛮力的想法是考虑每棵树并尝试所有三种可能性：让它保持原状，向左砍，或者向右砍。 在每次选择之后，我们维护一组全局的占用点或区间，并递归地继续。 这是正确的，因为它探索了所有有效的配置，但它是指数级的，因为每棵树最多分支成三个状态，从而提供了 O(3^n) 的可能性。 

即使我们尽早修剪无效重叠，我们最终仍然会重复检查区间交集，并且每次检查的成本可能为 O(n)，因此即使在考虑分支之前，有效的最坏情况也会变成 O(n²) 或更糟。 

关键的观察结果是树已经按位置排序，并且约束在一维上是纯几何的。 这意味着一旦我们从左到右处理树，我们只需要关心左侧最近的先前占用的边界。 同样，在决定是否向右砍一棵树时，我们只需要确保它不会干扰下一棵树的原始位置即可。 

这导致了一种贪婪策略，即我们维持左侧占据的最后一个位置（可能在向左砍伐一棵树之后），并且我们还展望下一棵树的位置，以决定是否可以安全地将当前树向右砍伐。 每个决策都是局部的，并且仅取决于直接邻居和当前占用的边界。

在每一步中，我们都尝试尽可能积极地砍伐当前的树，如果它不与先前占据的位置发生碰撞，则首选向左砍伐，否则，如果它没有到达下一棵树，则尝试向右砍伐，否则使其保持原样。 这种顺序至关重要，因为向右切割可能会阻塞下一棵树，因此我们必须确保足够的空间。

 | --- | --- | --- | --- |
 | 蛮力（尝试所有切割方向）| O(3^n) | O(3^n) | O(n) 递归堆栈 | 太慢了|
 | 贪婪扫描（局部边界检查）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 排序已经由输入顺序保证，因此我们从左到右处理树而不重新排列。 
2. 维护一个变量`pos`代表当前在地面上占据的最右边的点。 最初这是负无穷大，因为尚未削减任何内容。 
3. 对于每棵树`i`，按优先顺序考虑三种可能性。 首先，尝试将其剪到左侧。 这仅在该段有效`[x_i - h_i, x_i]`严格在之后开始`pos`。 如果是这样，我们将其保留并更新`pos`到`x_i`。 

这是有效的，因为向左剪切只会影响树位置左侧的空间，因此不会干扰未来的树。 
4. 如果无法向左砍伐，请尝试保持树木直立。 这总是安全的，因为它只占据一个点`x_i`，并且我们可以确保它不会与`pos`如果`x_i > pos`。 

如果连站立都是不可能的，那么这棵树就被有效地阻挡了，对答案没有任何贡献。 
5. 否则，尝试将其向右切割。 如果该段是有效的`[x_i, x_i + h_i]`没有到达下一棵树的位置`x_{i+1}`。 如果有效，我们会对其进行修改并更新`pos`到`x_i + h_i`。 

这个条件充分的原因是未来的树仅从离散位置开始，因此只要我们不覆盖下一个起点，就不会发生未来的冲突。 
6. 将每个成功的切割操作（无论是左切割还是右切割）计为一棵已处理的树。 

### 为什么它有效

 关键的不变量是`pos`始终表示已被某些先前处理的树占据的最右边的点。 每个决策都确保新创建的段不会与此边界或排序顺序中的下一个关键锚点相交。 

由于树是按位置递增顺序处理的，因此任何重叠只能发生在紧邻的前一个占用区域或紧邻的下一个未处理的树位置。 没有必要单独跟踪早期的树，因为它们的影响已经被吸收到`pos`。 这将全局几何约束简化为局部区间可行性检查，从而保证每个接受的切割都保持全局不重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
trees = [tuple(map(int, input().split())) for _ in range(n)]

ans = 0

# last occupied coordinate
pos = -10**30

for i in range(n):
    x, h = trees[i]

    # try cut left
    if x - h > pos:
        ans += 1
        pos = x
    # try stand
    elif x > pos:
        pos = x
    # try cut right
    elif i == n - 1 or x + h < trees[i + 1][0]:
        ans += 1
        pos = x + h
    else:
        pos = x

print(ans)
```核心实现取决于维护单个边界变量`pos`。 每棵树按顺序处理一次，逻辑首先检查左切割的可行性，因为它永远不会阻塞未来的树，而右切割仅在必要且相对于下一棵树安全时才使用。 

一个微妙的实现细节是最后一棵树的处理，其中检查`i == n - 1`是必需的，因为没有下一棵树需要阻塞。 忘记这一点会导致错误地拒绝有效的最终剪辑。 

另一个微妙之处是左割条件中的严格不等式`x - h > pos`。 使用`>=`会错误地允许仍然违反“无重叠”规则的接触段，因为位置被视为占用点。

 ## 边缘情况

 对于所有树都非常接近并且高度很大的情况，算法正确地避免了无效的右切，因为下一个树位置立即阻止扩展。 每次迭代都会退回到左切或站立，确保不会发生片段重叠。 

对于最终的树，缺少下一个锚点意味着始终独立评估右切割，并且条件`i == n - 1`保证最后一棵树不会被不存在的邻居错误地限制。 

对于树与树之间间隙较大的情况，`pos`边界自然会重置，因为任何切割或支架都只会在局部向前移动，从而允许独立处理后面的树木，而不会受到早期部分的干扰。
