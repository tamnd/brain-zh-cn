 ## 解决方案
 ## 问题理解

 我们得到了一系列咖啡杯，每个咖啡杯都有固定的咖啡因值。 波利卡普可以选择其中一些杯子并在几天内分发它们。 在某一天，如果他按某种顺序喝了多杯，那么每杯的贡献不仅取决于它的咖啡因含量，还取决于它在当天饮用顺序中的位置。 一天中越早喝一杯，它就越有用，因为与前一杯相比，接下来的每一杯都会有效地损失一个单位的咖啡因影响。 

目标是决定至少需要多少天来积累`m`工作页面，其中页面来自这些调整后的咖啡因贡献。 每个杯子最多可以使用一次，并且杯子可以跨天任意分配。 

限制很小：最多 100 杯，每杯咖啡因最多 100，目标页面最多 10^4。 这立即表明，如果仔细控制的话，二次甚至三次行为是可以接受的，但对子集或分区的指数探索则不然。 

当杯子较弱时，会出现微妙的边缘情况。 一杯含有少量咖啡因的咖啡，只有在一天中的第一杯时才可能有所帮助； 否则它就变得毫无用处。 例如，价值为 1 的杯子只有在先被拿走时才会做出贡献； 否则贡献为零。 一个天真的贪婪者每天打包很多杯子而不尊重顺序可能会高估贡献并错误地假设可行性。 

当所有杯子都太弱而无法积累足够的总页数时，即使每天最佳使用一个，也会出现另一种边缘情况。 在这种情况下，每种配置产生的总贡献不足，答案必须为 -1。 

## 方法

 蛮力视角会尝试以所有可能的方式将杯子分配到天中，并且对于每个分区，尝试每天内所有可能的订单。 这已经在组合上爆炸了：即使只是将 100 个项目划分为序列也是由贝尔数控制的，这远远超出了可行性。 

关键的观察是，一旦杯子固定，一天内的结构就很简单：如果我们按照咖啡因递减的顺序对杯子进行排序，我们就可以最大化每日贡献。 一天内的惩罚随着位置线性增长，所以我们希望最强的杯子最早出现。 任何其他排序只会减少或保留贡献。 

因此，问题简化为决定如何将排序后的数组分割成段（天），其中每个段贡献一个贪婪计算的已知值。 现在我们实际上被问到：给定这些杯子，我们如何将它们分成最少数量的组，以使组分数总和至少达到`m`，同时最大化每个小组结构的总分？ 

我们不是直接最小化目标总和下的天数，而是翻转视角：在固定的天数内`d`，我们检查是否至少可以实现`m`页。 由于更多的天数总是提供更大的灵活性（永远不会减少可实现的总贡献），这成为一个单调谓词，使得二分搜索成为可能`d`。 

对于固定的`d`，最好的策略是贪婪地将杯子分配到最多`d`每天，总是把最有用的杯子放在每天最早的位置。 我们反复模拟几天，每次需要花费`d`剩余最大的杯子，计算它们的贡献，并将它们移除。 如果总贡献达到`m`，配置可行。 

因此，最佳解决方案是对答案进行二分搜索并结合贪婪的可行性检查。

 ## 算法演练

 ### 固定天数的可行性检查`d`1. 按照咖啡因含量的降序对所有咖啡杯进行排序。 

这确保了当我们将杯赛分配给日期时，我们总是在每天早些时候放置更强的杯赛，因为它们的位置惩罚是最小的。 
2. 初始化已排序数组的指针和变量`total = 0`。 

我们将模拟一天一天的建造，贪婪地喝着杯子。 
3. 每天从 1 到`d`, 直至`d`阵列中剩余的杯子按顺序排列。 

当天的第一杯贡献其全部价值，第二杯损失 1，第三杯损失 2，以此类推。 我们计算：`max(0, a[i] - position_in_day)`。 
4. 处理一天后，将指针向前移动所用杯子的数量。 

这确保每个杯子最多使用一次。 
5. 累积所有贡献。 如果在任何时候`total >= m`，我们可以早点停下来。 
6.如果毕竟`d`我们至少达到的天数`m`，配置可行。 

### 外部二分查找

 1.设置搜索范围从1到`n`，因为在最坏的情况下，每个杯子都可能在自己的一天中单独存在。 
2. 对于每个中点`d`，运行可行性检查。 
3. 如果可行，尝试较小的`d`，否则增加`d`。 
4. 返回最小的可行值，如果不起作用则返回-1。 

### 为什么它有效

 核心不变量是，在任何固定的日子里，按照咖啡因递减的顺序放置杯子可以最大化贡献，因为惩罚仅取决于位置，而不是身份。 这使得每一天都可以独立优化。 一旦天数固定，贪婪地按照剩余最强杯子的顺序填充它们会确保不存在更好的重新分配，因为用较弱的早期杯子交换较强的后杯子只能提高或保持总贡献。 这保证了可行性检查的正确性，并且天数的单调性证明了二分搜索的合理性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(m, a, days):
    n = len(a)
    i = 0
    total = 0

    while i < n:
        used = 0
        # fill one day
        for j in range(days):
            if i >= n:
                break
            gain = a[i] - j
            if gain > 0:
                total += gain
            i += 1
            used += 1

        if total >= m:
            return True

    return total >= m

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    a.sort(reverse=True)

    lo, hi = 1, n
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(m, a, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先按降序对咖啡因值进行排序，以便每天的早期位置总是充满最强的剩余杯子。 这`can`函数模拟如果我们允许最多可以写入多少页`days`每天杯数。 每天贪婪地消耗多达`days`杯，应用基于位置的线性惩罚。 二分搜索找到仍可达到所需页数的最小天数。 

一个微妙的实现细节是提前停止`total >= m`，这避免了不必要的模拟。 另一个是确保一旦杯子贡献零或负调整值，它仍然会被消耗，但不会增加总和。 

## 工作示例

 ### 示例 1

 输入：```
5 8
2 3 1 1 2
```排序数组：`[3, 2, 2, 1, 1]`我们测试可行性`d = 2`。 

| 日 | 使用过的杯子| 贡献 | 总计 |
 | --- | --- | --- | --- |
 | 1 | 3, 2 | 3 + 1 = 4 | 4 |
 | 2 | 2, 1 | 2 + 0 = 2 | 6 |
 | 2 | 1 | 1 | 7 |

 这失败了 2 天。 为了`d = 3`，我们获得足够的灵活性以达到至少 8，并且二分搜索收敛到`4`处于最佳结构的天数。 

这表明每天包装更多的杯子会因惩罚而降低每杯的效率，而正确的答案取决于平衡分组。 

### 示例 2（已构建）

 输入：```
4 10
5 4 3 1
```排序：`[5, 4, 3, 1]`测试`d = 2`:

 | 日 | 杯子| 贡献 |
 | --- | --- | --- |
 | 1 | 5, 4 | 5 + 3 = 8 |
 | 2 | 3, 1 | 3 + 0 = 3 |
 | 总计 | | 11 | 11

 我们达到 11 ≥ 10，所以 2 天就足够了。 这证实了强大的早期杯子主导了可行性。

 ## 边缘情况

 一种边缘情况是所有咖啡因值为 1。对于输入：```
3 5
1 1 1
```即使所有杯子都得到最佳使用，任何一天中也只有第一个杯子有贡献，因此最大总数为 3。该算法正确地未能通过每个杯子的可行性检查`d`，返回-1。 

另一种边缘情况是当一个非常大的杯子占主导地位时：```
1 1
100
```该算法立即成功`d = 1`，因为仅一杯就可以产生足够的贡献。 

第三种边缘情况是分组会损害性能，例如：```
3 6
5 1 1
```一天给出 5 + 0 + 0 = 5，这还不够，但是两天可以将弱杯子分开，使它们再次变得有用。 可行性检查通过调整分组大小而不是贪婪地将所有内容打包到一天中来正确地捕获这种权衡。
