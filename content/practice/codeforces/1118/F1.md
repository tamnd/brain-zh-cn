 ## 解决方案
 ## 问题理解

 我们有一棵树`n`顶点，其中每个顶点可以是红色、蓝色或不着色。 任务是计算边的数量，当删除这些边时，将树分成两个组件，使得两个组件都包含红色和蓝色顶点。 换句话说，在切割这样的边之后，得到的每个块可以仅包含红色顶点、仅包含蓝色顶点、或任意数量的无色顶点，但不能将红色和蓝色混合在一起。 

输入给出顶点数、每个顶点的颜色列表以及`n-1`定义树的边。 输出是一个整数：满足上述条件的“好边缘”的数量。 

约束很大：最多 300,000 个顶点。 这意味着我们无法模拟移除每个边缘并扫描每个结果组件的颜色。 一个天真的`O(n^2)`方法将涉及潜在的遍历`n`每个顶点`n-1`边缘，这显然太慢了。 我们需要一个在线性时间内运行的解决方案，理想情况下`O(n)`。 

不明显的边缘情况包括严重倾斜的树（如链）、所有彩色顶点都集中在一个小子树中的情况，或者直接连接到特定颜色的叶子的边缘。 例如，中间节点为红色且叶子为蓝色的三节点链必须正确识别删除接触红色节点的边可能会产生包含两种颜色的组件，并且不应将其视为良好。 

## 方法

 蛮力方法将单独检查每条边。 对于每条边，我们可以将其删除，对两个结果组件运行 DFS，并对每个边的颜色进行计数。 如果任一组件同时具有红色和蓝色顶点，则边缘效果不佳。 这在原则上是正确的，但对于`n = 3 * 10^5`，这需要`O(n^2)`的操作，这是不可行的。 

最佳解决方案的关键观察是每条边将树恰好分成两个部分。 如果我们知道整棵树中红色和蓝色顶点的总数，并计算以边的一侧为根的子树中存在多少个红色和蓝色顶点，我们可以立即确定切割这条边是否有效。 具体来说，如果以一个端点为根的子树没有红色顶点或没有蓝色顶点，并且树的其余部分也没有红色或没有蓝色顶点，则该边是好的。 这将问题简化为单个 DFS 遍历，该遍历计算每个子树的红色和蓝色顶点的计数，然后对每个边进行简单检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 子树计数 DFS | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取顶点数`n`和颜色列表。 将颜色转换为计数：`1`对于红色，`2`对于蓝色，`0`对于无色的。 
2. 构造树的邻接表`n-1`边缘。 
3. 统计整棵树中红色和蓝色顶点的总数。 这提供了检查每个子树的参考。 
4. 从任意节点（根节点）执行 DFS`1`为了方便起见）。 对于每个节点，计算其子树中红色和蓝色顶点的总数，方法是对所有子节点的计数求和，如果当前节点是彩色的，则加 1。 
5. DFS 之后，迭代所有边。 考虑来自父级的边缘`u`给孩子`v`。 子树的根为`v`有`red_v`红色和`blue_v`蓝色顶点。 互补成分有`total_red - red_v`红色和`total_blue - blue_v`蓝色顶点。 如果其中之一`red_v == 0 or blue_v == 0`并且同时`(total_red - red_v == 0 or total_blue - blue_v == 0)`，边缘很好。 
6. 统计所有满足该属性的边并输出结果。 

工作原理：DFS 保证我们准确地知道每个子树中有多少个红色和蓝色顶点。 使用总计数，我们可以导出“其他组件”中的彩色顶点的数量，而无需遍历它。 这确保了 DFS 之后在恒定时间内正确评估每个边，从而给出总体`O(n)`复杂。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

n = int(input())
colors = list(map(int, input().split()))

adj = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

total_red = sum(1 for c in colors if c == 1)
total_blue = sum(1 for c in colors if c == 2)

subtree_counts = [[0, 0] for _ in range(n)]  # [red, blue]

def dfs(u, parent):
    red = 1 if colors[u] == 1 else 0
    blue = 1 if colors[u] == 2 else 0
    for v in adj[u]:
        if v == parent:
            continue
        dfs(v, u)
        red += subtree_counts[v][0]
        blue += subtree_counts[v][1]
    subtree_counts[u] = [red, blue]

dfs(0, -1)

result = 0
for u in range(n):
    for v in adj[u]:
        if v < u:
            continue  # ensure each edge is considered only once
        red_v, blue_v = subtree_counts[v]
        red_other = total_red - red_v
        blue_other = total_blue - blue_v
        if (red_v == 0 or blue_v == 0) and (red_other == 0 or blue_other == 0):
            result += 1

print(result)
```邻接表保证了高效的遍历，`dfs`计算每个子树的红色和蓝色计数。 仅对边缘进行一次迭代可以避免重复计算。 使用`v < u`确保我们在一个方向上考虑每条边。 设置递归限制可防止深层树的堆栈溢出。
