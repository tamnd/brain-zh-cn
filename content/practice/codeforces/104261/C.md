 ## 解决方案
 ## 问题理解

 我们有两个长度相同的数组，我们想要对它们进行转换，以便两个数组中的每个元素都等于一个公共值。 唯一允许的移动是将第一个数组中的元素增加 1，或将第二个数组中的元素减少 1。每个此类更改都会花费一次操作，并且我们希望最大限度地减少使两个数组中的所有数字相同所需的操作总数。 如果无法通过这些举措达成共同价值，我们必须报告不可能。 

关键的观察是第一个数组中的元素只能向上移动，第二个数组中的元素只能向下移动。 这立即限制了最终目标值的大小。 最终值必须至少与第一个数组中的所有元素一样大，最多与第二个数组中的所有元素一样大。 如果这两个约束不重叠，则没有可行的目标。 

这些约束允许最多 100000 个元素，其值最多为 1e9，因此任何解决方案都必须以线性或接近线性的时间运行。 排序是不必要的，但需要扫描全局极值。 针对所有元素尝试每个可能目标的 O(n^2) 方法会太慢，因为在最坏的情况下最多需要 1e10 次操作。 

一些边缘案例暴露了常见的错误。 如果第一个数组的最大值大于第二个数组的最小值，则即使大多数元素看起来兼容，也不存在解决方案。 例如，a = [10], b = [1] 立即失败，因为第一个数组不能减少，第二个数组不能增加。 另一个微妙的情况是，当数组已经满足重叠但最佳成本仅取决于边界元素，而不是每个元素配对时。 

## 方法

 一个蛮力的想法是尝试任一数组中出现的最小值和最大值之间的每个可能的最终值 T。 对于每个候选 T，我们计算成本：第一个数组中的每个元素贡献 max(0, T - a[i])，因为它必须增加到 T，而第二个数组中的每个元素贡献 max(0, b[i] - T)，因为它必须减少到 T。我们取所有 T 中的最小值。 

这是正确的，因为每个有效的解决方案都必须收敛到某个整数 T，并且成本公式精确测量该 T 所需的操作。但是，可能的 T 值的范围可达 1e9，并且评估每个值是不可能的。 即使我们将候选者限制为数组中的唯一值，我们仍然有 O(n) 个候选者，并且每次评估都是 O(n)，给出 O(n^2)，这对于 1e5 个元素来说太慢了。 

关键的见解是成本函数在整数线上是凸的。 随着 T 的增加，第一个阵列贡献的成本线性增加，而第二个阵列贡献的成本线性减少。 总成本与单个最小值呈分段线性关系。 这意味着我们不需要搜索整个域； 当增加第一个阵列的“压力”与减少第二个阵列的“压力”平衡时，就会出现最小值。 实际上，我们只需要确保可行性，然后评估最小化移动的边界处的成本，结果是交叉点中的任何有效 T，并且通过将所有内容前缀为边界内一致的目标来确定最佳选择。 

这将问题简化为查找是否存在重叠，然后计算将所有内容与任何有效目标对齐的成本，通常是在方向约束下最小化总绝对偏差的边界。

 ## 算法演练

我们将问题重新表述为选择单个整数 T，仅使用允许的操作，将第一个数组中的所有值提升到 T，并将第二个数组中的所有值降低到 T。 

1. 计算第一个数组中的最大值和第二个数组中的最小值。 这些定义了 T 的可行性界限。如果第一个数组的最大值超过第二个数组的最小值，则不存在同时满足这两个移动约束的公共 T，因此答案立即不可能。 
2. 如果可行，我们实际上不需要枚举 T。区间 [max(a), min(b)] 中的任何有效 T 都是可达的并产生有效的解决方案，但我们必须计算所有此类选择中的最小操作数。 
3. 观察到对于任何固定 T，成本在阵列之间独立分配。 每个 a[i] 贡献 T - a[i]，因为在有效解中所有 a[i] 都 ≤ T。 每个 b[i] 都贡献 b[i] - T，因为所有 b[i] 都 ≥ T。 
4. 对这些贡献求和，得到 T 中的线性表达式。第一部分贡献 n_T - sum(a)，第二部分贡献 sum(b) - n_T，因此 T 完全抵消。 总成本变为 sum(b) - sum(a)，与所选的有效 T 无关。 
5. 因此，如果可行的话，我们直接计算 sum(b) - sum(a) 作为答案。 

它的工作原理来自于允许操作的结构。 第一个数组中的每一个 +1 都会使总和增加 1，第二个数组中的每一个 -1 都会使总和减少 1。由于最终状态强制两个数组等于相同的常数 T，因此最终总和固定为 2nT。 所需的净变化完全由初始金额决定，可行性确保我们只朝着允许的方向前进，而不会出现矛盾。 成本与第一个数组中所需的总向上移动和第二个数组中的向下移动完全匹配，并且索引之间的交互不会改变该总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    max_a = max(a)
    min_b = min(b)
    
    if max_a > min_b:
        print(-1)
        return
    
    print(sum(b) - sum(a))

if __name__ == "__main__":
    solve()
```该解决方案首先通过比较第一个数组中的最大元素和第二个数组中的最小元素来检查可行性。 这强制存在一个可以从两个方向达到的共同目标值，而不会违反操作约束。 

一旦可行性得到确认，答案就会简化为一个简单的算术表达式。 总和差准确地捕获了第一个数组中所需的 +1 操作和第二个数组中所需的 -1 操作的总数。 不需要每个元素匹配或排序，因为每个操作仅影响本地值并且不会干扰其他值。 

一个常见的实现错误是尝试模拟向选定目标 T 的收敛并对每个元素的调整求和，这是不必要的，并且存在边界处理中整数溢出或偏一错误的风险。 直接求和公式避免了所有这些。

 ## 边缘情况

 一种边缘情况是数组已经相同。 对于输入 a = [7, 7] 且 b = [7, 7]，max(a) = 7 且 min(b) = 7，因此可行性成立且差值之和为零。 该算法无需尝试任何操作即可正确返回 0。 

另一个边缘情况是可行性几乎失败的时候。 对于 a = [5]、b = [4]、max(a) = 5 且 min(b) = 4，因此算法立即输出 -1。 任何计算成本的尝试都会错误地假设存在共享目标，但没有整数满足两个方向约束。 

最后的边缘情况是接近 1e9 的大值。 由于该算法仅使用求和和比较，因此它避免了在所有增量和减量的简单逐元素模拟中出现的溢出问题。
