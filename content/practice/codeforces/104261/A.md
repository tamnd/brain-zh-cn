 ## 解决方案
 ## 问题理解

 我们得到一个整数$n$，表示冥王星的估计半径（以英里为单位）。 问题是这个值是否足够大，使得冥王星在特定的几何要求下有资格成为行星。 

该要求基于与固定参考物体的比较：半径为 1000 英里的“星星”。 冥王星被建模为圆形，恒星被视为五角形状。 冥王星合格的条件是半径为$n$必须足够大以完全包含恒星。 简而言之，冥王星的半径必须至少与保证恒星完全适合其内部的阈值一样大。 

所以任务简化为决定是否$n$满足或超过包围恒星所需的最小半径。 

唯一的输入是这个整数$n$，输出是一个二元决策：如果冥王星符合行星资格，则打印“YES”，否则打印“NO”。 

约束条件$1 \leq n \leq 10^9$意味着解决方案必须在恒定时间内运行。 任何尝试几何模拟或迭代构造星形的解决方案都是不必要的，而且速度太慢，即使输入大小本身足够小，正确性是唯一真正的挑战。 

边缘情况有限，但仍值得注意。 什么时候$n = 1000$，冥王星正好处于阈值，应该接受。 什么时候$n < 1000$，甚至按 1 个单位，例如$n = 999$，答案一定是拒绝。 这里最常见的错误是在错误的方向上使用严格的不等式或忘记允许相等。 

## 方法

 一种天真的解释会尝试推理五角星的实际几何形状并准确计算其边界圆。 这将涉及导出顶点坐标，计算距中心的距离，然后与冥王星的半径进行比较。 虽然在数学上是可行的，但这是不必要的，因为这个问题已经提供了关键的见解：恒星的有效遏制半径固定为 1000 英里。 

蛮力方法将模拟或重建星形，计算所有极值点，然后确定最小外接圆半径。 这将涉及常数因子重的几何运算和浮点比较。 尽管输入大小无关，但实现复杂度很高并且引入了数值稳定性风险。 

关键的简化是认识到恒星的大小已经被概括为一个标量阈值：1000 英里。 一旦这一点被接受，整个几何问题就会分解为之间的直接比较$n$和 1000。 

因此，我们不计算几何形状，而是简单地将给定半径与阈值进行比较。 如果$n \geq 1000$, 冥王星符合条件； 否则它不会。

 ## 算法演练

 1.读取整数$n$从输入。 这是冥王星的估计半径。 
2. 比较$n$1000，这是完全包含恒星所需的最小半径。 
3.如果$n \geq 1000$，输出“YES”，因为冥王星的圆足够大，满足包容条件。 
4. 否则，输出“NO”，因为圆太小，无法完全包含星星。 

### 为什么它有效

 该问题将所有几何复杂性降低为单个阈值条件。 恒星所需的包容性完全由半径 1000 来表征，这意味着任何半径低于 1000 的圆都无法完全包围它，而任何半径至少为 1000 的圆都可以。 该算法是正确的，因为它直接评估这个定义条件，而不进行近似或变换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n >= 1000:
    print("YES")
else:
    print("NO")
```该解决方案读取单个整数并执行一次比较。 关键的实现细节是确保比较是包容性的，因为“至少与 1000 一样大”的条件明确允许相等。 

不需要循环或额外的解析。 这种简单性是有意为之的：任何额外的逻辑都只会带来出现差一错误或格式错误的机会。

 ## 边缘情况

 唯一有意义的边缘行为是在阈值 1000 附近。 

用于输入$n = 999$，算法读取值并评估$999 \geq 1000$，这是假的，所以它输出“NO”。 这正确地反映了圆的不足。 

用于输入$n = 1000$，比较就变成了$1000 \geq 1000$，其计算结果为 true，产生“YES”。 这证实了平等被视为有效遏制。 

对于像这样的大值$n = 10^9$，比较仍然是简单的整数检查，在 Python 中不存在溢出或精度问题，从而确保整个输入范围内的一致正确性。
