 ## 解决方案
 ## 问题理解

 我们有一排人，每个人都有一个所需的阈值。 迈克拥有的折扣票数量有限，他最多可以将每张票分配给排队中的一个人。 票证的效果不是本地的：如果票证被赋予位置`i`，只要后来的人的要求小于或等于起始人的要求，它就会自动向前传播连续的位置。 一旦遇到具有严格更大要求的人，传播就会停止。 

目标是最多放置`D`票，以便直接或通过传播获得折扣的不同人员总数最大化。 

输入大小最多允许`N = 100000`，这会立即排除任何尝试起始位置的所有子集或根据选择重复模拟传播的解决方案。 即使对所有可能的票放置进行二次扫描也会变得太慢，因为`D`最多 100 但`N`规模很大，因此必须仔细利用该结构。 

一个微妙的边缘情况来自重叠传播。 如果两张票扩展到相交或嵌套的段，错误地计算重叠可能会使答案膨胀或缩小。 例如，如果两张票都在递减后缀的相同前缀上扩展，则天真的计数会重复计算覆盖的头寸，即使它们已经打折一次。 

另一个边缘情况是单调数组。 如果数组严格递增，则任何传播都不会超出起始点，因此每张票仅覆盖一个人。 在严格递减数组中，单个票证可以覆盖整个后缀，并且在第一次完全覆盖后，额外的票证不会提供任何好处。 

## 方法

 蛮力的想法是选择`D`起始位置并模拟每个选择的传播。 对于每个选定的位置，我们向前扫描，直到传播条件中断，标记所有覆盖的索引。 处理完所有选定的起始点后，我们计算标记了多少个索引。 

这是正确的，因为它直接实现了传播规则。 然而，其复杂性令人望而却步。 选择`D`职位成本`O(N^D)`可能性，即使是很小的`D`这会爆炸。 即使我们固定起点并有效地模拟覆盖范围，每次模拟也可能会扫描最多`O(N)`，导致`O(DN)`每个配置，仍然不可能枚举所有组合。 

关键的观察结果是，每张票据都会创建一个由其起始位置唯一确定的段：它会一直延伸到序列严格大于起始值的下一个位置。 一旦我们这样看待问题，每个位置`i`定义确定性区间`[i, r[i]]`。 问题变成最多选择`D`最大化工会覆盖范围的间隔。 然而，与标准间隔调度不同，间隔取决于所选的起点，但一旦预先计算，就不会以复杂的方式在结构上相互影响。 

这允许动态编程解决方案：我们从左到右处理，并在每个位置决定是在那里启动票证还是跳过它。 自从`D ≤ 100`，我们可以定义一个 DP，在其中跟踪我们已经使用了多少张票以及我们已经走了多远。 状态可以被压缩，因为覆盖范围是单调且向前移动的。 

我们预先计算每个索引`i`最远可达端点`r[i]`使用简单的前向扫描，或更有效地使用单调结构。 然后 DP 转换模拟选择或跳过开始，同时保持最佳可达覆盖范围。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^D) | O(N) | 太慢了|
 | 最佳 | O(ND) | O(ND) | 已接受 |

 ## 算法演练

 1. 预先计算每个位置`i`最远索引`r[i]`这样所有的元素都来自`i`到`r[i]`小于或等于`M[i]`。 这定义了在以下位置下票的全部效果：`i`。 此步骤将动态传播规则转换为静态区间。 
2.定义动态规划表`dp[k][i]`表示前缀中最大覆盖人数`0..i`准确地使用`k`门票。 我们这样构造它是因为每张票贡献一个间隔，并且我们必须考虑重叠。 
3. 初始化`dp[0][i] = 0`为所有人`i`，因为没有门票什么也覆盖不了。 
4. 从左到右迭代位置。 在每个位置`i`，我们考虑两种选择： 不下票`i`，或放置一个。 
5. 如果我们没有在`i`， 然后`dp[k][i]`结转自`dp[k][i-1]`。 这保留了之前的承保决定。 
6. 如果我们在`i`，那么它涵盖了直到`r[i]`。 我们更新`dp[k+1][r[i]]`使用`dp[k][i-1] + (r[i] - i + 1)`。 这增加了新的细分市场贡献。 我们直接跳转到的原因`r[i]`是之间的一切`i`和`r[i]`变得完全覆盖，并且不需要在区间内进一步决策。 
7. 处理完所有位置后，答案是所有位置中的最大值`dp[k][i]`在哪里`k ≤ D`。 

### 为什么它有效

 关键的不变量是每个状态`dp[k][i]`代表使用精确的最佳可能覆盖范围`k`非重叠票证在前缀内开始最多`i`。 由于每张票证都从其选定的索引开始扩展为固定的最大间隔，因此任何最佳解决方案都可以视为一组不相交或重叠的间隔，其贡献在首次创建间隔时仅计算一次。 DP 强制要求每个间隔都在其起点处进行计算，并且永远不会重新访问，从而防止重复计算，同时保留所有有效的起点组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    r = [0] * n

    # compute farthest reach for each i
    for i in range(n):
        mx = a[i]
        j = i
        while j + 1 < n and a[j + 1] <= mx:
            j += 1
        r[i] = j

    # dp[k][i] = best coverage using k tickets up to i
    dp = [[0] * n for _ in range(d + 1)]

    for k in range(d + 1):
        for i in range(n):
            if i > 0:
                dp[k][i] = max(dp[k][i], dp[k][i - 1])

            if k < d:
                start_prev = dp[k][i - 1] if i > 0 else 0
                reach = r[i]
                gain = reach - i + 1
                if i > 0:
                    dp[k + 1][reach] = max(dp[k + 1][reach], start_prev + gain)
                else:
                    dp[k + 1][reach] = max(dp[k + 1][reach], gain)

    ans = 0
    for k in range(d + 1):
        ans = max(ans, max(dp[k]))

    print(ans)

if __name__ == "__main__":
    solve()
```代码首先计算传播边界`r[i]`通过贪婪地向右扩展，而条件`a[j] ≤ a[i]`成立。 这直接编码了票放置多远的规则`i`可以影响线路。 

然后，DP 表跟踪每个票数可实现的最佳覆盖范围。 跳过一个位置的转换会继承之前的结果，确保我们不会丢失最优的部分解决方案。 放置票据的转换直接跳转到端点`r[i]`，反映所有中间位置都被同一操作消耗。 

一个微妙的细节是更新为`dp[k+1][r[i]]`必须使用来自的值`dp[k][i-1]`， 不是`dp[k][i]`，否则我们将面临从同一区域开始链接多张票证并进行超算的风险。

 ## 边缘情况

 严格递减序列如`10 9 8 7 6`从任何起点触发最大传播。 如果我们从索引 0 开始，`r[0]`延伸到最后，因此 DP 必须确保额外的门票不会人为地将承保范围扩大到已经完全承保的范围之外。 转换逻辑会处理此问题，因为间隔会立即消耗，并且进一步的放置无法重新引入已计数的索引。 

严格递增序列如`1 2 3 4 5`产生`r[i] = i`为所有人`i`。 每张门票仅贡献一个单位。 因此 DP 的行为就像选择`D`独立元素，最大值就是`D`或者`N`，以较小者为准。 这证实了当条件不满足时，传播逻辑不会错误地扩展间隔。 

一个常量数组，例如`5 5 5 5 5`创建一个退化的情况，其中任何位置的每一张票都覆盖整个后缀。 放置在任何位置的第一张票有效地支配了其右侧的所有内容，并且除了已经涵盖的索引之外，其他票没有贡献任何新内容。
