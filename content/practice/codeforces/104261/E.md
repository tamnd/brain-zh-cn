 ## 解决方案
 ## 问题理解

 我们得到一个最多有 12 个顶点的完整加权图。 每个顶点代表一个岩石碎片，成本矩阵告诉我们将任意两个碎片直接粘合在一起的成本有多大。 任务是将所有片段安排到单个循环中，每个片段恰好使用一次，以便最小化循环中所有选定边的总成本。 

用图术语来说，我们正在寻找具有对称边权重的完整无向图中的最小权重哈密顿循环。 输出是恰好形成一个循环的 N 个边的权重之和，该循环访问每个顶点一次并返回到起始顶点。 

约束 N ≤ 12 是这里的关键信号。 任何尝试枚举所有顶点排列的算法都直接以 O(N!) 运行，O(N!) 变为 12！ 约 4.79 亿个排列，每个排列需要对 N 个边求和。 一旦包含常数因子，在 4 秒限制下，Python 就已经太慢了。 这立即表明了对子集的位掩码动态编程方法。 

在简单的公式中很容易忽略一些边缘情况。 人们将循环视为一条路径，却忘记关闭它，这会导致错过回到起点的最后一条边。 例如，如果 N = 3 并且成本均为 1，则基于路径的解决方案可能会计算成本 2，而不是正确的周期成本 3。另一个问题是强力排列中的重复计算周期，因为每个周期都出现在 2N 次旋转和反转中，除非仔细标准化，否则这会使朴素最小化变得复杂。 

## 方法

 蛮力的想法很简单。 我们固定一个起始节点并生成剩余节点的所有排列。 对于每个排列，我们通过将连续节点之间的边加上返回到起点的边相加来计算循环成本。 这是正确的，因为它明确检查每个可能的哈密顿循环。 

问题在于重复的规模。 有 (N−1) 个！ 固定起始点后进行排列，每次评估成本为 O(N)，因此总复杂度变为 O(N!·N)。 对于 N = 12，这远远超出了可行的限制。 

关键的观察是，部分构造的状态仅取决于哪些节点已被使用以及我们当前位于哪个节点。 我们到达该子集的顺序对于未来的决策并不重要。 这正是位掩码动态编程捕获的结构。 

我们将 DP[mask][i] 定义为从固定节点 0 开始，精确访问 mask 中的节点，并在节点 i 结束的最小成本。 从每个状态，我们尝试扩展到任何未访问的节点 j，添加成本[i][j]。 最后，我们通过从每个端点返回到 0 来结束循环。 

这减少了 N 阶排列的指数爆炸！ 大小为 2^N 的子集，每个子​​集有 N 个转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（排列）| O(N!·N) | O(N!·N) | O(N) | 太慢了|
 | 位掩码 DP (TSP) | O(N^2·2^N) | O(N^2·2^N) | O(N·2^N) | O(N·2^N) | 已接受 |

 ## 算法演练

 我们固定一个节点作为起点，通常是节点 0。这消除了循环的旋转对称性，因为任何循环都可以旋转到从 0 开始而不改变其成本。 

我们定义一个按子集和最后访问的节点索引的 DP 表。 该子集跟踪哪些节点已包含在部分路径中。

1. 将所有 DP 值初始化为一个较大的数字，因为我们正在最小化成本。 我们设置 DP[1 << 0][0] = 0，因为从节点 0 开始，仅访问节点 0 不需要任何成本。 
2. 使用从 0 到 (1 << N) − 1 的位掩码迭代节点的所有子集。每个子集表示已访问片段的部分集。 
3. 对于每个子集，迭代该子集中包含的所有可能的最后节点。 如果 DP[mask][i] 无效，则跳过它，因为它代表不可达状态。 
4. 从状态 (mask, i)，尝试通过转到不在 mask 中的任何节点 j 来延长循环。 转换更新 DP[mask | (1 << j)][j] 与 DP[mask][i] + cost[i][j]。 这确保我们始终积累到达每个州最便宜的方式。 
5. 填充 DP 表后，所有节点都已在 mask 等于 (1 << N) − 1 的状态下被访问过。对于每个可能的最后一个节点 i，我们添加 cost[i][0] 以关闭回到起始节点的循环并取最小值。 

关键思想是 DP 将共享相同访问集和结束点的所有排列压缩为一种状态。 这就是防止重复计算相同子问题的原因。 

### 为什么它有效

 在任何一点，DP[mask][i] 表示精确访问 mask 中且以 i 结束的节点的所有可能顺序中的最小成本。 对新节点 j 的任何扩展仅取决于 i 和掩码，而不取决于我们如何达到此配置。 这建立了一个最佳子结构：较大集合的最佳解决方案可以从其子集的最佳解决方案构建。 由于每个哈密顿循环恰好对应于该动态规划中的一个状态序列，并且每个状态转换通过考虑所有可能性来保持正确性，因此所有端点上的最终最小值正确地产生了最佳循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cost = [list(map(int, input().split())) for _ in range(n)]
    
    INF = 10**18
    size = 1 << n
    dp = [[INF] * n for _ in range(size)]
    
    dp[1][0] = 0  # start from node 0, mask = 000...001
    
    for mask in range(size):
        if not (mask & 1):
            continue
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            if not (mask & (1 << i)):
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                new_mask = mask | (1 << j)
                new_cost = dp[mask][i] + cost[i][j]
                if new_cost < dp[new_mask][j]:
                    dp[new_mask][j] = new_cost
    
    full = size - 1
    ans = INF
    for i in range(n):
        ans = min(ans, dp[full][i] + cost[i][0])
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP表被初始化为一个大的哨兵值来表示不可达状态。 起始状态使用仅包含该节点的位掩码修复节点 0。 

三重循环结构是必要的：mask 枚举子集，i 枚举这些子集的端点，j 尝试扩展。 条件检查确保我们只扩展有效状态，并且永远不会重用子集中已包含的节点。 

最后的循环通过返回节点 0 显式地关闭循环。这是在不正确的实现中最常被忽略的步骤，并且它是必要的，因为 DP 仅构建哈密顿路径，而不是直接构建循环。

第二个小案例有助于确认正确性：

 输入：```

```所有循环都具有相同的成本 3。DP 将产生 2（路径成本 0→1→2），然后添加 2→0，产生 3。每个排列都会崩溃到相同的最佳值，从而确认对称处理。

 ## 边缘情况

 常见的边缘情况是所有成本为零。 DP 将在所有状态中传播零，最终的闭包也会添加零，产生正确的结果 0。这证实了该算法不依赖正权重来保证正确性。 

另一个微妙的情况是最优循环不像简单的贪婪路径。 例如，在看起来不对称的成本矩阵中，最佳路径可以避免局部便宜的边以减少后续成本。 DP 处理这个问题是因为每个状态都存储所有部分排列的真实最小值，而不是局部贪婪的选择。 

最后，最小情况N = 2 测试循环收敛的正确性。 DP 构建单个路径 0 → 1，最后一步显式添加成本[1][0]，确保循环完整并且不会意外地被视为路径。
