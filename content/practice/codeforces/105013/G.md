 ## 解决方案
 ## 问题理解

 输入描述了一个二进制字符串，该字符串以固定大小的长度块进行处理`k`。 您可以考虑将字符串分割成连续的块，每个块首先被独立处理，然后再与其邻居交互。 

在每个块内，您可以有效地决定将该块解释为全零还是全一，具体取决于哪种选择需要在块内进行更少的字符翻转。 如果该块已经具有明显多数的 0 或 1，则该决定将由该多数强制执行。 如果该块完全平衡，则两种解释都会花费相同的翻转次数，并且该块不会强加固定方向。 

在以这种方式减少每个块之后，剩余的结构是由多数选择确定的一系列“方向”，其中散布着不明确的块，这些块可以在不改变成本的情况下以任何方式分配。 最终答案需要三个量：块内翻转的最小次数、相邻确定块之间的强制转换次数以及解决歧义的不同全局方法的数量，以使总成本仍然最小。 

这些约束意味着字符串可能很大，因此任何解决方案都必须在线性时间内处理每个块。 如果在许多测试用例中重复，二次甚至对数的每块策略会太慢。 关键的限制是，除了连续块之间的简单交互模式之外，所有决策都是块本地的，这建议采用单通道聚合方法。 

当一个块完全平衡时，就会出现微妙的边缘情况，这意味着它恰好包含一半的 1 和一半的 0。 在这种情况下，两种选择都是同样最优的。 过早任意修复此类块的幼稚方法可能会扭曲有效全局配置的数量。 当两个具有不同多数方向的强制块被几个不明确的块分开时，会发生另一种失败情况。 解决这些模糊性的方法数量取决于强制决策之间存在多少“差距”，而忽视这些差距会导致低估。 

## 方法

 暴力策略将枚举为每个块分配全零或全一的所有方法，计算每个配置的翻转成本，并跟踪最佳成本以及实现该成本的配置数量。 每个块最多有两个选择，所以`m`阻止这个产生`2^m`可能性，并且评估每个配置需要扫描所有块，从而导致指数爆炸，这在非常小的输入之外是完全不可行的。 

关键的观察是，每个块独立地贡献最小的翻转成本，该成本仅取决于其组成。 一旦每个块被减少到这个最小成本决策，全局结构就变成一系列受约束的标签：一些块被强制趋向于零或一，而一些则是灵活的。 问题归结为理解这些被迫决策如何在序列中传播。 

重要的结构简化是只有连续强制块之间的转换才重要。 不明确的块不会增加成本，而是会增加有效全局解释的数量，具体取决于它们如何被相邻强制片段“吸收”。 这将全局计数问题转换为连续约束变化之间距离的乘积。 

一旦看到这一点，解决方案就变成了线性扫描：计算每个块的成本和方向，丢弃中性块，然后处理剩余的序列以累积转换和组合多重性。

 ## 算法演练

 ### 1.将字符串分割成大小的块`k`我们以以下步骤迭代字符串`k`，独立处理每个子串。 这是必要的，因为翻转是按块评估的，而跨块结构仅在压缩后才重要。 

### 2. 计算每个区块的多数成本

 对于每个块，计算 1 的数量。 如果 1 超过块大小的一半，则将 0 翻转为 1 更便宜，否则将 1 翻转为 0。 存储的成本是该块所需的最小翻转次数。 

如果块完全平衡，则两个分配都是同样最优的，因此块不会强制执行方向。 我们单独标记这些块并将它们排除在结构处理之外。 

### 3. 对每个非中性块进行编码

 每个块由一对表示`(tag, index)`在哪里`tag`编码最佳状态是否倾向于零或一，以及`index`记录其在块中的位置。 中性块被忽略，因为它们可以适应任何一方而不影响成本。 

### 4.总翻转成本

 我们直接累积每个区块的最低成本。 这会产生尽可能少的翻转次数，与全局排列无关。 

### 5. 强制块之间的进程转换

 我们扫描过滤后的阻止列表中的连续条目。 每当两个相邻块具有不同标签时，就会创建强制转换边界。 我们对这样的转换进行计数，并且对于每个转换，我们将路数乘以它们的块索引之间的距离。 

原因是它们之间的每个中间中性块都可以被吸收到任何一方而不改变成本，并且该间隙中的每个位置都会产生不同的有效配置。 

### 6. 处理空的或完全中立的情况

 如果不存在强制块，则整个字符串由中性段组成，并且两个全局分配（全零或全一）都是有效的最小解。 

### 为什么它有效

 该算法依赖于每个块都减少到其最佳局部状态的不变量，并且没有进一步的翻转可以在不增加局部惩罚的情况下提高成本。 一旦减少，只有强制块之间的分歧才能限制系统。 中性块充当自由变量，不影响成本但扩大组合自由度。 由于这些自由段仅出现在强制约束之间，因此计数减少为测量约束更改之间的距离，从而确保不会重复计算或省略任何配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def check(s, k):
    cnt1 = s.count('1')
    if cnt1 * 2 == k:
        return cnt1, -1
    if cnt1 > k // 2:
        return k - cnt1, 1
    return cnt1, 0

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    s = "?" + s

    total_cost = 0
    blocks = []

    for i in range(1, n + 1, k):
        cost, tag = check(s[i:i+k], k)
        total_cost += cost
        if tag != -1:
            blocks.append((tag, i // k))

    transitions = 0
    ways = 1

    if len(blocks) >= 2:
        for i in range(len(blocks) - 1):
            if blocks[i][0] != blocks[i + 1][0]:
                transitions += 1
                ways = (ways * (blocks[i + 1][1] - blocks[i][1])) % MOD

    if not blocks:
        ways = 2

    print(total_cost, transitions + 1, ways % MOD)

t = int(input())
for _ in range(t):
    solve()
```该实现首先将每个块压缩为其最小表示。 这`check`函数执行局部决策：它计算成本并决定块是强制一个方向还是保持中立。 主循环立即聚合成本，因为成本在各个块之间是独立的。 

名单`blocks`只存储有意义的约束。 中性块被完全删除，因为它们只提供灵活性。 这就是为什么存储的索引是`i // k`，这使我们能够测量约束之间有多少个完整块。 

转换计数发生在这个简化序列的单次传递中。 每当相邻标签不同时，我们就会累积与它们的距离成比例的贡献。 这直接编码了在不影响最优性的情况下可以分配中间中性区域的多种方式。 

特殊情况是`blocks`为空对应于整个字符串是中性块，给出两个对称的全局解决方案。

 最终结果反映了中间结构的一次强制切换和两次有效放置。 

这显示了只有不同的相邻强制块如何影响计数。

 ## 边缘情况

 完全中性的分解，其中每个块恰好有一半的 1 和一半的 0，由`if not blocks`分支。 在这种情况下，算法正确地输出等于零的成本和两个全局分配，因为没有约束破坏对称性。 

当只有一个强制块时，会出现第二种边缘情况。 在这种情况下，没有转换，因此段数被正确报告为 1，并且组合因子仍然为 1，因为不同的强制状态之间不存在间隙。 

第三种边缘情况涉及具有不同标签的两个强制块之间存在较大的中性间隙。 乘以`(next_index - current_index)`确保中性区域内边界的每个可能位置都被精确计算一次，即使间隙跨越许多块，也能保持正确性。
