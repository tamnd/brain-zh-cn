 ## 解决方案
 ## 问题理解

 该任务可以理解为有向加权图上的最短路径问题，但具有额外的状态跟踪层。 图中的每个节点都可以被访问多次，具体取决于到目前为止已通过的特殊“坏”节点的数量。 当我们遍历一个普通节点时，我们的状态不会改变。 当我们遍历一个坏节点时，我们消耗了一个单位的有限资源，这会影响我们未来仍然允许通过多少个坏节点。 

形式上，我们不仅感兴趣的是到达每个节点的最便宜的成本，而且感兴趣的是到达由一个节点组成的每对的最便宜的成本以及已经使用了多少个坏节点的计数。 对于每个节点，输出要求所有有效状态中的最小成本。 

输入描述了一个带有多达十万个节点和边的加权有向图，加上一个小约束 k，它限制了我们允许通过的坏节点的数量。 节点的子集被标记为坏节点，每次我们输入一个节点，我们都会消耗一个单位的配额。 

输出是每个节点的最短可达成本列表，如果约束下不存在有效路径，则输出为 -1。 

这些约束立即排除了任何针对每个节点或每个状态独立重新计算最短路径的方法。 每个状态的朴素最短路径会爆炸到 O(nk log n) 或更糟，具体取决于实现细节，因此我们必须将问题视为扩展状态空间上的单个统一最短路径。 

当 k = 0 时，会出现微妙的边缘情况。在这种情况下，任何接触坏节点的路径都会变得无效，因此只有通过安全节点的路径才重要。 另一个特殊情况是目的地本身很糟糕； 如果我们在进入时正好有剩余配额，我们仍然必须允许进入。 

## 方法

 一种直接的方法是将每个查询“使用 i 个坏节点后到达节点 v 的成本是多少”视为单独的距离状态并运行多状态最短路径。 这自然会导致定义一个动态编程表，其中 dist[u][i] 是使用 i 个坏节点后到达节点 u 的最小成本。 

从图的角度来看，这相当于构建一个分层图，每个节点都有 k+1 个副本。 权重 w 的每个原始边 u → v 会根据 v 是否不好而成为层之间的过渡。 如果 v 不错，则图层索引保持不变。 如果 v 不好，则层索引增加 1。 那么目标就是这个扩展图中从 (1, 0) 开始的最短路径。 

这个公式是正确的，但仍然需要一种有效的方法来计算最短路径。 蛮力方法会在没有优先级的情况下反复松弛所有状态的边缘，这会退化为类似于 SPFA 的东西，在大小为 n·k 且具有最多 m·k 转换的图上。 在最坏的情况下，由于状态的重复重新处理，这可能会变得太慢。 

关键的观察结果是，这个扩展图具有非负边权重，因此我们可以安全地将 Dijkstra 算法应用于状态图。 每个状态都是较大图中的一个节点，每个转换都是一个加权边。 一旦这样看，问题就变成了标准的单源最短路径问题。 

声明中的 SPFA 版本和 Dijkstra 版本仅在实现选择上有所不同：SPFA 尝试动态放松，而 Dijkstra 使用优先级队列强制执行顺序，防止重复不必要的放松。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对状态的蛮力（不受控制的松弛）| 最坏情况 | O(n·k·m) O(n·k) | O(n·k) | 太慢了|
 | 状态图上的 SPFA | 最坏情况 | O(n·k·m) O(n·k) | O(n·k) | 风险/边缘 |
 | 状态图上的 Dijkstra | O((n·k + m·k) log(n·k)) | O((n·k + m·k) log(n·k)) | O(n·k + m·k) | O(n·k + m·k) | 已接受 |

 ## 算法演练

我们将原始图转换为状态扩展图，其中每个节点 u 有 k+1 个版本，表示在到达 u 时到目前为止已使用了多少个坏节点。 

然后我们从初始状态运行 Dijkstra。 

1. 构建从每对（节点 u，used_bad i）到状态图中唯一索引的映射。 这允许我们将每个状态视为最短路径算法中的正常节点。 
2. 对于每个权重为 w 的原始边 u → v，我们添加状态之间的转换。 如果 v 是坏节点，那么只要 i+1 ≤ k，我们就可以从状态 (u, i) 转到 (v, i+1)。 如果 v 不错，我们就转到 (v, i)。 这将约束直接编码到图结构中。 
3. 将状态图中的所有距离初始化为无穷大，除了起始状态 (1, 0)，该距离设置为零。 
4. 将起始状态推入优先级队列。 这确保了我们始终首先扩展当前最便宜的可达状态。 
5. 反复提取距离最小的状态。 如果已经处理过，则跳过。 否则，放宽到相邻状态的所有传出转换，如果找到更短的路径则更新它们的距离。 
6. 算法结束后，对于每个原始节点u，取i从0到k的所有状态(u, i)上的最小距离。 这给出了在任何有效使用坏节点的情况下到达 u 的最佳可能成本。 

它工作的原因与一个简单的不变量有关：每当我们从优先级队列中弹出一个状态（u，i）时，我们就已经找到了达到该精确配置的最小可能成本。 由于所有转换都具有非负权重，因此任何未来的改进都将需要一条更便宜的路径到达同一状态，这与优先级队列强制执行的排序属性相矛盾。 这保证了状态一旦确定，就永远不需要重新访问。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, p, k = map(int, input().split())
    bad = [False] * (n + 1)

    for _ in range(p):
        x = int(input())
        bad[x] = True

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))

    INF = 10**18
    dist = [[INF] * (k + 1) for _ in range(n + 1)]
    dist[1][0] = 0

    pq = [(0, 1, 0)]

    while pq:
        d, u, used = heapq.heappop(pq)
        if d != dist[u][used]:
            continue

        for v, w in g[u]:
            if bad[v]:
                if used < k and dist[v][used + 1] > d + w:
                    dist[v][used + 1] = d + w
                    heapq.heappush(pq, (dist[v][used + 1], v, used + 1))
            else:
                if dist[v][used] > d + w:
                    dist[v][used] = d + w
                    heapq.heappush(pq, (dist[v][used], v, used))

    for i in range(1, n + 1):
        ans = min(dist[i])
        print(-1 if ans == INF else ans, end=" ")

if __name__ == "__main__":
    solve()
```该解决方案直接在分层状态空间上实现 Dijkstra。 距离表存储每个（节点，used_bad）对的最已知成本。 优先级队列总是扩展最有希望的状态，并且通过与当前最佳距离进行比较来忽略过时的条目。 

关键的实现细节是根据下一个节点是否不良来区分转换。 该条件决定了状态的第二维是否增加。 另一个重要的细节是最后在所有层上取最小值，因为根据路径结构，到达具有更少或更多使用的坏节点的节点都可以是最佳的。 

## 工作示例

 考虑一个具有三个节点的小图，其中节点 2 是坏节点，并且我们允许 k = 1 个坏节点。 边为 1 → 2（成本 5）、2 → 3（成本 2）和 1 → 3（成本 10）。 

我们将状态跟踪为（节点，used_bad）。 

初始状态为 (1, 0)，距离为 0。 

| 步骤| 状态弹出 | 距离 | 更新行动|
 | ---| ---| ---| ---|
 | 1 | (1,0)| 0 | 放松 1→2 给出 (2,1)=5，放松 1→3 给出 (3,0)=10 |
 | 2 | (2,1) | 5 | 放松 2→3 给出 (3,1)=7 |
 | 3 | (3,0) | 10 | 10 没有改进|
 | 4 | (3,1) | 7 | 没有改进|

 节点 3 的最终答案是 min(10, 7) = 7。 

这显示了如何使用坏节点限额来实现更长但更便宜的路线。 

现在考虑同一张图上的 k = 0。 任何进入节点2的路径都是无效的。 

| 步骤| 状态弹出 | 距离 | 更新行动|
 | ---| ---| ---| ---|
 | 1 | (1,0)| 0 | 只允许1→3，所以(3,0)=10 |
 | 2 | (3,0) | 10 | 10 完成 |

 现在，节点 3 只能通过直接边到达，从而确认约束如何阻止中间节点。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n·k + m·k) log(n·k)) | O((n·k + m·k) log(n·k)) | 每个状态都用 Dijkstra 处理一次，并且每条边最多创建 k 个转换 |
 | 空间| O(n·k + m·k) | O(n·k + m·k) | 距离表加上扩展状态图上的邻接|

 在典型约束下 k 的值很小，使得状态扩展可行。 即使 n 高达 100000，优先级队列中的对数因子也能将解轻松保持在限制范围内。

 ## 边缘情况

 关键的边缘情况是 k = 0 时。在这种情况下，必须完全阻止任何向坏节点的转换。 该算法自然会处理这个问题，因为条件`used < k`防止创建无效状态。 例如，如果节点 2 是坏节点并且 k = 0，则从 (1,0) 我们永远不会推送 (2,1)，因此通过节点 2 的所有路径都会消失。 

另一个边缘情况是目标节点出现故障。 只要状态转换发生在界限内，该算法仍然允许达到它。 如果到达节点 v 恰好消耗了最后一个可用配额，则状态 (v, k) 仍然有效并参与最终的最小计算。 

当多个不同路径以不同的used_bad 值到达同一节点时，会出现第三种情况。 该算法正确地保留了所有状态，并且所有状态的最终最小值确保我们不会错误地丢弃使用不同数量的坏节点的更好路径。
