 ## 问题理解

 我们得到了许多测试用例。 对于每个测试用例，我们收到一个长度的字符串$n$。 任务是以非常具体的方式转换字符串，并在处理后决定它与三个固定输出中的哪一个匹配。 

处理规则简单但严格。 首先，所有字符都转换为小写，以便将大写和小写版本视为相同。 然后，连续的相同字符被压缩，以便任何像这样的运行`"aaaa"`变成单身`"a"`,`"bbbbb"`变成`"b"`， 等等。 标准化后，将生成的字符串与两个特殊模式进行比较。 如果它等于`"meow"`，输出是`"0_0"`。 如果它等于`"waov"`，输出是`"*_*"`。 任何其他结果都会产生`"???"`。 

语句中的约束没有明确限制，但每个测试用例的直接字符串处理的存在强烈表明：$n$可以足够大，以至于任何比每个测试用例的线性更糟糕的事情都会有风险。 这立即排除了重复低效地重建字符串或使用可能退化为二次行为的嵌套扫描的方法。 

压缩步骤产生了微妙的边缘情况。 天真的解释可能会全局删除重复字符，而不是仅折叠连续的运行。 例如，`"mmeeooww"`应该成为`"meow"`，但是全局重复数据删除会错误地将其减少到`"meow"`仅当秩序得到仔细保存时。 另一种边缘情况是混合大小写，例如`"MeOoW"`在压缩之前仍必须正确标准化。 

## 方法

 蛮力思想遵循字面描述。 对于每个字符串，我们首先将每个字符转换为小写。 然后我们重复扫描字符串并删除重复项，直到没有相邻的相同字符为止。 一种简单的实现可能会在每次传递后重建字符串，或者重复检查相邻字符并一一删除重复项。 

这可以正确工作，因为它直接强制执行连续压缩的定义。 然而，当琴弦较长时，它的弱点就会显现出来。 每个擦除操作都可以移动剩余的后缀，并且重复执行此操作会导致每个测试用例出现最坏情况的二次行为。 对于多个测试用例，当$n$很大。 

关键的观察是我们不需要重复传递。 压缩仅取决于最终处理的字符串中每个字符是否等于前一个字符。 这意味着我们可以通过仅在与最后一个附加字符不同时附加一个字符来一次性构建结果。 结合单遍小写转换，整个转换变得线性。

 | ---| ---| ---| ---|
 | 暴力破解（重复擦除或重建）|$O(n^2)$|$O(n)$| 太慢了|
 | 一次标准化+运行压缩|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 读取字符串并将每个字符转换为小写。 这确保大小写不会影响比较，因为目标模式仅以小写形式定义。 
2. 初始化一个空结果字符串，用于存储压缩形式。 
3. 迭代规范化字符串的每个字符。 
4. 仅当该字符与结果中已存在的最后一个字符不同时，才将其附加到结果中。 如果相同，我们就跳过它，因为它属于同一个连续块。 
5. 扫描结束后，将得到的压缩字符串与`"meow"`和`"waov"`。 
6. 输出`"0_0"`如果匹配`"meow"`,`"*_*"`如果匹配`"waov"`，否则输出`"???"`。 

### 为什么它有效

 压缩步骤相当于用单个代表字符替换每个最大连续的相同字符块。 一次性结构保证每个块只保留一个字符，因为我们只抑制紧随同一字符的重复。 由于当字符发生变化时，每个块边界都会被检测一次，因此生成的字符串与重复的全字符串重复数据删除最终产生的字符串相同，但无需重复工作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    # lowercase conversion
    s = s.lower()

    # run-length compression
    t = []
    for c in s:
        if not t or t[-1] != c:
            t.append(c)

    t = ''.join(t)

    if t == "meow":
        print("0_0")
    elif t == "waov":
        print("*_*")
    else:
        print("???")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该解决方案首先使用标准化输入字符串`.lower()`，确保统一的字符比较。 压缩是使用列表完成的`t`以避免重复的字符串连接，否则会导致 Python 中的二次行为。 每个字符仅与最后保留的字符进行比较，保证线性时间处理。 最后，我们与两个目标模式进行比较。 

一个常见的陷阱是使用`t += c`重复在字符串上，这会降低性能。 另一个是忘记压缩必须保持顺序，同时仅删除连续的重复项，而不是全局的所有重复项。

 ## 边缘情况

 一种重要的边缘情况是整个字符串由单个重复字符组成，例如`"AAAAA"`。 经过小写转换和压缩后，变成`"a"`。 该算法通过附加第一个字符并跳过所有其他字符来处理它，因为它们与最后附加的字符匹配。 最终的字符串是`"a"`，两者都不匹配`"meow"`也不`"waov"`，所以输出是`"???"`。 

另一个边缘情况是交替套管与运行，例如`"MeEeOoWw"`。 小写转换产生`"meeooww"`和压缩率`"meow"`。 该算法正确地处理了这个问题，因为比较总是在标准化之后进行，并且运行边界纯粹是由相邻字符的相等性决定的，而不是原始情况。
