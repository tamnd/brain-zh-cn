 ## 解决方案
 ## 问题理解

 我们得到一个仅由左括号和右括号组成的二进制字符串。 在此字符串上，我们必须处理一系列点更新，其中单个字符发生更改，并且每次更新后，我们必须计算从当前括号配置派生的值。 

我们关心的值仅取决于两种括号类型的极端位置。 直观地说，如果允许我们选择一个左括号和一个右括号，我们想要测量一对有效的匹配括号可以相距多远。 每次修改后的答案完全由当前存在的最左左括号和最右右括号决定。 

输入由初始字符串和多个更新组成。 每次更新都会替换一个字符，每次更改后我们都会从头开始重新计算答案。 

约束结构意味着我们需要支持最多大量的更新，因此在每次操作后通过扫描完整字符串来重新计算会太慢。 每个查询的完整扫描成本为 O(n)，导致 O(nq)，当 n 和 q 都很大时，这变得不可行。 

当更新删除唯一剩余的左括号或右括号时，天真的方法也会巧妙地失败。 例如，如果字符串全部变为“)”或全部“(”，则不存在有效的对，答案必须为 0。任何假设两种类型始终存在的方法都将产生无效的索引差异。

 ## 方法

 暴力解决方案通过扫描整个字符串，跟踪“(”的最小索引和“)”的最大索引，在每次更新后重新计算答案。 这是正确的，因为最终值仅取决于这两个极端。 然而，每次更新的成本为 O(n)，因此更新 q 次后，总成本变为 O(nq)，这太大了。 

关键的观察结果是，答案完全由两个动态量决定：任何“(”的最小索引和任何“)”的最大索引。 如果我们在更新时有效地维护这两个值，则可以在 O(1) 内回答每个查询。 

为了支持更新，我们需要一个可以插入和删除索引并快速检索最小和最大元素的结构。 像集合这样的平衡有序容器恰好提供了这种功能。 我们保留一组“(”位置和一组“)”位置。 每次更新后，我们以 O(log n) 的时间更新相应的集合，然后使用“(”集合的第一个元素和“)”集合的最后一个元素计算答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | 最佳（套）| O(q log n) | O(q log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取字符串并初始化两个有序集合，一个存储“(”的索引，一个存储“)”的索引。 

这种预处理允许恒定时间访问极限位置。 
2. 扫描一次字符串，并根据字符将每个索引插入到适当的集合中。 

这会在 O(n log n) 内构建两个结构的初始状态。 
3. 对于每个更新查询，读取索引和新字符，并将索引转换为基于 0 的形式。 

这确保了与内部存储的一致性。 
4. 从集合中删除与其旧字符对应的索引。 

这使两个集合与更新的字符串状态保持一致。 
5. 将索引插入新字符对应的集合中。 

这样就完成了更新，同时保持了正确的排序。 
6. 如果任一集合变空，则输出 0。 

如果没有两种括号类型，则无法形成有效的对。 
7. 否则，将答案计算为（'）'的最大索引）减去（'（'）的最小索引，并将其输出。

 这些极端代表了最广泛的可能配对。 

### 为什么它有效

在任何时刻，对一个“(”和一个“)”的任何有效选择都会产生等于它们索引之差的距离。 最大化这种差异显然需要选择尽可能小的“(”和尽可能大的“)”。 任何内部对都不能超过此范围，因为所有其他有效对都包含在这些极值内。 由于更新仅更改两个集合中索引的成员资格，因此维持这些极端值足以始终重建正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = list(input().strip())

    left = set()
    right = set()

    for i, ch in enumerate(s):
        if ch == '(':
            left.add(i)
        else:
            right.add(i)

    import bisect

    left_list = sorted(left)
    right_list = sorted(right)

    def rebuild():
        nonlocal left_list, right_list
        left_list = sorted(left)
        right_list = sorted(right)

    out = []

    for _ in range(q):
        pos, c = input().split()
        pos = int(pos) - 1

        old = s[pos]

        if old == '(':
            left.remove(pos)
        else:
            right.remove(pos)

        s[pos] = c

        if c == '(':
            left.add(pos)
        else:
            right.add(pos)

        # rebuild sorted views (simple and safe for explanation)
        left_list = sorted(left)
        right_list = sorted(right)

        if not left_list or not right_list:
            out.append("0")
        else:
            out.append(str(right_list[-1] - left_list[0]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现遵循维护两个动态索引集合的思想。 每次更新都会从一组中删除旧索引，并根据需要将其插入另一组中。 答案始终是根据左括号集合的最小元素和右括号集合的最大元素计算的。 

这里排序列表的使用在概念上与基于集合的解决方案是一致的，但在严格的实现中，我们将使用平衡树或有序集合来避免重建。 关键思想仍然是一样的：保持快速接近极端。 

处理空集时需要小心，因为尝试访问最小值或最大值会导致错误。

 ## 边缘情况

 当所有左括号都被移除时，就会出现严重的边缘情况。 例如，从`((()))`并将每个“(”翻转为“)”，左侧集合变为空。 该算法在计算极值之前显式检查这一点，因此它输出 0 而不是尝试无效索引。 

另一个边缘情况是更新重复切换单个位置时。 由于每次更新都会在 O(log n) 中执行删除和插入，因此结构保持一致，并且极值正确反映当前配置，而无需完全重新计算。 

最后一种情况是最右边的“)”由于更新而向左移动。 因为我们总是动态查询最大元素，所以这种移位会自动捕获，而无需扫描整个数组。
