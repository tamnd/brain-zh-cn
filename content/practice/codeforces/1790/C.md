 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 在每个测试用例中都存在从 1 到 n 的隐藏数字排列。 我们没有直接看到排列，而是给出了 n 个派生数组。 每个派生数组都是通过从排列中精确删除一个不同的位置并保持剩余元素有序而形成的。 

因此，所提供的数组之一中恰好缺少每个原始元素，并且每个数组都缺少一个元素。 数组的顺序被打乱，我们必须唯一地恢复原始排列。 

关键的结构约束是每个数组的长度为 n−1，并且在所有数组中，排列的每个位置都“负责”一个缺失元素。 这强制了强大的全局一致性：原始排列是其“单删除视图”与给定数组的多重集匹配的唯一序列。 

每个测试用例的限制都很小，n ≤ 100，但最多可以有 10^4 个测试用例，总 n^2 ≤ 2⋅10^5。 这意味着任何解决方案在最坏的情况下都可以为每个测试用例提供大约 O(n^2) 的时间，但不能是立方的或涉及每个候选排列的重复昂贵的重新计算。 

给定数组的排序不明确会产生微妙的边缘情况。 一种幼稚的方法可能会尝试将数组成对对齐或假设第一个数组对应于删除第一个元素。 这会失败，因为输入根本没有给出位置提示。 例如，如果 n = 4，则数组可以任意打乱，并且即使局部重叠看起来一致，基于索引对齐的重建也会产生错误的排列。 

另一个常见的陷阱是假设数组中元素的大多数频率直接给出排序。 虽然频率有助于识别哪个元素在哪里缺失，但它不会立即对排列内的位置顺序进行编码。 

## 方法

 一个强力的想法是尝试 1 到 n 的每个排列，并验证其 n 派生删除数组是否与给定的多重集匹配。 对于每个候选排列，我们将生成 n 个数组，对它们进行排序，然后与输入进行比较。 每个排列的生成和排序成本为 O(n^2 log n)，并且有 n！ 排列，使得即使 n = 10 也完全不可行。 

关键的观察是我们不需要猜测排列。 相反，我们可以利用结构不对称性：在 n 个数组中，当我们仔细查看前缀时，除了两个数组之外，所有数组都共享相同的第一个元素模式。 更具体地说，正确的排列是通过从重叠前缀中识别稳定的顺序来确定的。 

更可靠的查看方法是通过每个数组的第一个元素。 在原始构造中，每个位置 i 都会生成一个缺少 p[i] 的数组。 这意味着除 p[1] 之外的每个元素都显示为至少一个数组的第一个元素，其中删除的元素不在序列中较早的元素。 唯一不能始终作为“首次看到的候选者”出现的元素是排列的真正第一个元素。 

一旦我们确定了第一个元素，我们就可以过滤以它开头的数组。 在这些数组中，我们基本上看到了剩余 n−1 个元素的所有排列，每个数组恰好缺少一个。 递归地重复相同的推理可以重建完整的顺序。 

简化之处在于，我们只需要在每一步中找到当前数组集中从未作为有效前缀候选出现的元素。 该元素必须是排列中的下一个元素。 

这将问题简化为使用剩余数组的第一个位置上的频率约束来重复识别唯一确定的元素。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n² log n) | O(n!·n² log n) | O(n²) | 太慢了 |
 | 最佳| O(n²) | O(n²) | 已接受 |

 ## 算法演练

 1. 读取所有n个数组并存储它们。 

每个数组都表示恰好缺少一个元素的排列，因此它们共同编码完整的邻接信息。 
2. 提取所有数组的所有第一个元素并计算它们的频率。 

排列的正确第一个元素是出现在所有数组中第一个位置的元素，除了缺少相应删除效果的元素之外。 这造成了明显的不平衡。 
3. 将排列的全局第一个元素识别为恰好出现在 n−1 个数组的第一个位置的值。 

发生这种情况是因为只有缺少 p[1] 的数组不是以 p[1] 开头，而所有其他数组都是以 p[1] 开头。 
4. 输出该元素作为排列的第一个值。 
5. 删除所有不以此元素开头的数组，因为只有与给定前缀一致的数组才能属于同一重建阶段。 
6. 对缩减后的数组重复相同的逻辑以查找下一个元素。 

在每一步中，都保持相同的唯一性属性：下一个元素由剩余数组的第一个位置的频率不平衡确定。 
7. 继续，直到完全重建排列。 

### 为什么它有效

 在每一步中，剩余数组的第一位置共识中都会“丢失”一个元素。 该缺失元素对应于排列中的下一个元素。 该结构保证每个其他元素在足够的数组中显示为有效前缀以主导频率计数，而真正的下一个元素由于在每个位置的一个数组中恰好是被删除的元素而被系统地排除在该主导地位之外。 这个不变量确保了唯一前缀元素的贪婪选择能够无歧义地重构排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]

    # Precompute rows
    used = [False] * (n + 1)
    answer = []

    # We will iteratively pick next element
    # Start with all rows active
    active = a

    for step in range(n):
        freq = {}
        for row in active:
            if row:
                x = row[0]
                freq[x] = freq.get(x, 0) + 1

        # pick element that appears n-step-1 times
        target = None
        for x, c in freq.items():
            if c == len(active) - 1:
                target = x
                break

        answer.append(target)
        used[target] = True

        # filter rows that start with target
        new_active = []
        for row in active:
            if row[0] == target:
                new_active.append(row[1:])
        active = new_active

    print(*answer)
```该代码保留了重复识别当前有效数组中第一个位置缺少的唯一元素的想法。 该元素必须是排列中的下一个元素，因为所有其他元素仍然在所有一致数组中显示为有效前缀。 

过滤步骤至关重要：修复一个元素后，我们将其从出现在前面的所有行中删除。 这模拟了从原始排列结构中消耗该位置。 

一个微妙的细节是我们从不依赖输入数组的全局排序。 我们始终使用动态收缩的一致子集，即使在输入行的任意排列下也能保持正确性。

 ## 边缘情况

 一种边缘情况是当 n 最小时，例如 n = 3。所有数组的长度都是 2，并且每个元素恰好出现在两个数组中作为第一个候选元素。 该算法仍然选择一个前缀计数中缺少的唯一元素并确定性地继续进行。 

另一种情况是输入数组被大量打乱时。 由于该方法仅依赖于当前活动集中第一个元素的频率，因此输入行的顺序永远不会影响正确性。 重建完全取决于结构约束，而不是输入顺序。 

最后一种情况是多个元素早期以相似的频率出现。 当前前缀分布中恰好缺少一个元素的约束保证了唯一性，因此有效输入中不会出现联系。
