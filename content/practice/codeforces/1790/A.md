 ## 问题理解

 每个测试用例都会给出一串数字，波利卡普在尝试记住 π 的数字后写下了这些数字。 任务是确定 π 的前导数字有多少与该字符串的前缀匹配。 

我们不是重建 π 或纠正错误。 我们只是将给定的数字字符串与已知的 π 数字参考序列进行比较，并在第一个不匹配处停止。 测试用例的答案是完全匹配的最长前缀的长度。 

限制很小：每个字符串最多 30 个字符，最多有 1000 个测试用例。 这意味着即使是与存储的参考字符串进行简单的逐字符比较也足够快。 总工作量约为 30,000 个字符比较。 

主要的微妙之处在于前导零和早期的不匹配。 一个常见的错误是假设数字比较或忽略 π 的前导数字“3”。 

一些边缘情况很重要：

 像“000”这样的字符串应该立即给出 0，因为 π 以“3”开头，因此第一个字符已经失败。 

以“3”开头但随后发散的字符串（例如“31420”）应仅计算正确的前缀“314”。 

完整正确的前缀（如“3141592653”）如果与 π 的开头匹配，则应返回其完整长度。 

## 方法

 最直接的想法是将输入字符串与预先计算的 π 前缀进行比较。 我们将 π 数字存储为字符串，例如“314159265358979323846264338327...”，其长度足以覆盖所有可能的输入。 

对于每个测试用例，我们从左到右扫描并比较字符，直到发现不匹配或到达输入字符串的末尾。 我们停止的索引就是答案。 

这种蛮力方法在这个问题上已经是最佳的，因为最大输入长度很小。 即使我们重复重新计算比较或使用切片，复杂性仍然与总输入大小呈线性关系。 

更抽象的看待它的方式是，我们正在计算两个字符串之间的最长公共前缀：给定的数字和固定的参考字符串。 由于一个字符串是恒定的，因此我们不需要任何高级预处理，例如散列或后缀结构。

 ## 算法演练

 1. 将 π 的数字存储为固定字符串，从包含前导 3 的小数点后第一位数字开始。 
2. 对于每个测试用例，读取表示 Polycarp 记住的数字的输入字符串。 
3. 将计数器初始化为零。 该计数器跟踪输入字符串和 π 之间有多少个连续数字匹配。 
4. 从左到右迭代输入字符串的字符。 对于每个位置 i，将 input[i] 与 pi_digits[i] 进行比较。 
5. 如果字符相等，则增加计数器并继续。 
6. 如果发生不匹配，请立即停止，因为任何其他数字都不能成为正确前缀的一部分。 
7. 输出计数器。 

关键思想是前缀正确性是单调的。 一旦发生不匹配，扩展比较就无法恢复正确性。 

### 为什么它有效

 在每个位置 i，该算法确保 i 之前的所有位置都与 π 完全匹配。 第一个不匹配定义了正确记忆和错误记忆之间的界限。 由于我们只关心前缀一致，而不关心重新排列或部分匹配，因此停止条件对于正确性来说既是充分也是必要的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

PI = "314159265358979323846264338327950288419716939937510"

t = int(input())
for _ in range(t):
    s = input().strip()
    ans = 0
    for i in range(len(s)):
        if i < len(PI) and s[i] == PI[i]:
            ans += 1
        else:
            break
    print(ans)
```该解决方案依赖于预先计算的 π 数字字符串。 该循环比较每个字符的位置，并在不匹配时立即停止。 边界检查`i < len(PI)`is a safety guard, though the constant is long enough for all constraints.

 A common implementation mistake is forgetting to strip newline characters, which would cause incorrect comparisons. Another is converting the string to integers unnecessarily, which complicates comparison without benefit.

 ## 边缘情况

 对于像“000”这样的输入，该算法将第一个字符与 π 中的“3”进行比较，然后立即停止，返回 0。这确认了前导无效数字已被正确处理，无需进一步扫描。 

对于完全匹配的前缀，例如“314159”，每个字符都按顺序匹配，并且计数器达到6。循环仅在耗尽字符串后自然终止，确认完全匹配的正确处理。 

对于像“31420”这样的混合情况，匹配会继续前三个字符，然后在第四个字符处失败，结果稳定在 3，这表明在第一次不匹配时正确提前终止。
