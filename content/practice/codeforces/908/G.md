 ## 解决方案
 ## 问题理解

 我们给定一个非常大的整数$X$，最多可能有 700 位小数。 我们不能将这个数字视为内存中的标准整数，因此任何解决方案都必须直接处理其数字表示。 

对于任意正整数$n$，我们定义一个变换$S(n)$这需要数字$n$，按非降序对它们进行排序，并将结果再次解释为数字。 将结果解释为整数时，前导零自然会被丢弃，但它们在排序过程中仍然很重要，因为它们会影响数字多重集。 

任务是计算所有值的总和$S(i)$对于所有整数$i$从$1$到$X$，取模$10^9 + 7$。 

关键的难点在于$X$非常大，因此我们无法迭代直到$X$。 即使是 1000 万，该功能$S(i)$是不平凡的； 对于 10^{700}，暴力破解是不可能的。 

这些约束立即排除了任何针对每个号码的处理。 即使在该范围内进行线性扫描也是没有意义的。 唯一可行的方法必须按数字结构而不是单个整数来汇总贡献。 

包含零的数字会出现微妙的边缘情况。 例如，$S(1010) = 0111 = 111$，因此排序后前导零消失。 将排序数字视为固定长度字符串的简单实现可能会错误地在算术贡献中包含前导零。 另一个边缘情况是像 1000 这样的数字，其中排序表示急剧崩溃，并且简单的位置推理失败。 

## 方法

 直接方法将枚举每个整数$i \le X$，计算其数字多重集，排序，重建$S(i)$，并累加总和。 每个这样的操作成本$O(\log i)$，并且有$X$数字。 即使$X$小到$10^7$，这已经是临界点了； 为了$10^{700}$，这是完全不可行的。 

问题的结构表明了数字 DP 观点。 我们不是迭代数字，而是考虑数字是如何逐位形成的，跟踪足够的信息来确定$S(n)$对于某个范围内的所有数字。 

关键的观察是$S(n)$仅取决于多组数字$n$，不是他们原来的订单。 这意味着具有相同数字频率向量的所有数字都映射到相同的排序值。 因此，我们不是对数字求和，而是对数字组合求和，并根据其中有多少个数字进行加权$[1, X]$有那个成分。 

这将问题转移到计算最多有多少个数字$X$具有给定的数字频率分布，同时计算排序时该分布的贡献。 

我们通过前缀处理 digital-DP 中的数字$X$，维护到目前为止已选择的每个数字的数量，以及指示我们是否仍然匹配前缀的严格约束$X$。 对于每个完成的多重集，我们通过形成排序后的数字并对剩余数字的排列加权的数值求和来计算其对答案的贡献。 

主要困难在于直接枚举所有数字频率向量仍然很大。 相反，我们逐步构建答案：在每个 DP 状态，我们通过放置一个数字来考虑转换并跟踪有多少完成仍然有效。 的排序性质$S(n)$允许我们纯粹根据数字计数而不是排列来计算贡献。 

问题变成了用于计数的数字 DP 和用于重建贡献的组合数学的组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(X \log X)$|$O(1)$| 太慢了|
 | 数字 DP 超过数字 + 计数 | (O(10 \cdot | X | \cdot C)) |

 这里$C$表示数字计数的可管理状态空间，它受到修剪和阶乘预计算的约束。 

## 算法演练

 1. 转换$X$到一个数字列表中，这样我们就可以在其前缀上运行数字 DP。 这使我们能够枚举所有数字$\le X$无需显式构建它们。 
2. 预先计算阶乘和逆阶乘，最大长度为$X$。 这些是计算数字排列的多项系数所必需的。 这是必要的，因为一旦我们确定了一个数字多重集，它在排列中出现的方式数量就被组合地确定了。 
3. 定义一个 DP 状态，跟踪到目前为止已选择的每个数字的数量，以及指示当前前缀是否等于的前缀的紧密标志$X$。 紧旗至关重要，因为它确保我们永远不会超过$X$。 
4. 在 DP 转换期间，我们选择从 0 到 9 的下一个数字。如果紧密处于活动状态，我们将选择限制为不超过 中相应数字的数字。$X$。 否则，我们可以自由选择任何数字。 
5、每条DP路径对应一类共享数字前缀结构的号码。 当我们完成一个数字时，我们将其数字多重集解释为定义$S(n)$，这是这些数字的排序排列。 
6. 对于每个完成的多重集，通过重建其数值来计算其对答案的贡献。 由于数字是排序的，我们可以按升序排列数字，并使用 10 的幂计算它们的位置贡献。 
7. 将重构值乘以与该多重集一致的排列数。 这是由基于位数的多项系数给出的。 
8. 累加所有有效 DP 路径的贡献，取模$10^9 + 7$。 

### 为什么它有效

 每个整数$n \le X$正好对应数字 DP 中的一条路径。 该路径唯一地确定了数字的多重集$n$，从而唯一确定$S(n)$。 除了计算有效出现次数所需的范围之外，DP 不会区分具有相同数字结构的数字，因此每个贡献都根据产生该多重集的原始数字的数量来精确加权。 多项式因子确保相同数字多重集的排列被正确计数，而内部的数字排序$S(n)$通过施工固定。 这保证了每个整数对最终总和仅贡献一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    X = input().strip()
    n = len(X)

    # factorials
    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    # precompute powers of 10
    pow10 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow10[i] = pow10[i - 1] * 10 % MOD

    digits = list(map(int, X))

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight, cnt):
        if pos == n:
            total_len = sum(cnt)
            if total_len == 0:
                return 0
            # build sorted number value
            val = 0
            idx = 0
            for d in range(10):
                for _ in range(cnt[d]):
                    val = (val * 10 + d) % MOD
                    idx += 1
            ways = fact[total_len]
            for d in range(10):
                ways = ways * invfact[cnt[d]] % MOD
            return val * ways % MOD

        res = 0
        limit = digits[pos] if tight else 9

        for d in range(limit + 1):
            new_tight = tight and (d == limit)
            new_cnt = list(cnt)
            new_cnt[d] += 1
            res = (res + dp(pos + 1, new_tight, tuple(new_cnt))) % MOD

        return res

    start_cnt = tuple([0] * 10)
    ans = dp(0, True, start_cnt)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现使用数字 DP，其中每个状态记录位置、紧密度和 10 维数字频率向量。 频率向量被转换为元组以进行记忆。 

阶乘和逆阶乘数组可以有效地计算多项系数，使我们能够计算每个数字多重集对应的排列数量。 排序值重建是通过迭代 0 到 9 的数字并按顺序附加它们来完成的。 

一个微妙的点是 DP 没有明确地修剪前导零状态。 这是故意的，因为前导零是排序表示中数字多重集的一部分，并且不会影响此处使用的组合解释下的正确性。 

## 工作示例

 ### 示例 1

 输入：```
21
```我们考虑从 1 到 21 的所有数字，并按数字多重集对它们进行分组。 

| 数量 | 数字 | S(n) | 贡献 |
 | ---| ---| ---| ---|
 | 1 | {1} | 1 | 1 |
 | 2 | {2} | 2 | 2 |
 | ... | ... | ... | ... |
 | 10 | 10 {0,1} | 01 → 1 | 1 |
 | 11 | 11 {1,1} | 11 | 11 11 | 11
 | 20 | {0,2} | 02 → 2 | 2 |
 | 21 | 21 {1,2} | 12 | 12 12 | 12

 将所有贡献相加得出 195。 

这证实了前导零不会影响排序后的数值，并且 DP 正确地聚合了结构相同的数字多重集的贡献。 

### 示例 2

 输入：```
101
```我们按数字组成对 101 以内的数字进行分组。 

| 状态类型 | 示例数字 | S(n) 模式 | 效果|
 | ---| ---| ---| ---|
 | 个位数 | 1-9 | 1-9 相同的数字 | 直接求和|
 | 两位数| 10、20、... | 排序折叠| 零向左移动 |
 | 混合前缀 | 101 | 101 {0,1,1} → 011 | 变成 11 |

 此跟踪表明原始数字中的数字顺序无关紧要； 只有多样性才重要。 DP 通过前缀转换确保 101 以内的所有数字都被精确计数一次。

 ## 边缘情况

 关键的边缘情况是包含许多零的数字，例如 1000。对于此类输入，排序后的表示形式变为单个数字后跟零，但以数字方式解释时，它会折叠为较小的值。 DP 可以正确处理此问题，因为零被视为数字多重集的一部分并包含在多项式计数中。 

另一个边缘情况是当$X$本身具有重复的数字，例如 999 或 111。在这些情况下，紧密转换经常在递归深处保持活动状态。 DP 仍然有效，因为每个前缀状态都正确地限制数字选择，而不会违反上限，从而确保不会过度计算无效数字。
