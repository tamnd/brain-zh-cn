 ## 解决方案
 ## 问题理解

 给定两个长度相等的数字字符串，但某些位置可能包含由以下表示的未知字符`?`。 每个`?`可以独立地替换为任意数字`0`到`9`，并且不同位置的选择不会相互作用。 

修正所有未知数后，我们得到两个具体长度的数字串`n`。 对于每一对完整的字符串，如果一个字符串在任何地方都支配另一个字符串，我们将它们分类为“坏”，这意味着它永远不会严格更大而在某个地方严格较小，或者相反的方向也永远不会发生。 “不可比较”的条件是严格优势的两个方向都出现在跨位置的某个位置：存在第一个字符串较大的索引，以及第二个字符串较大的索引。 

任务是计算两个模板的完成次数产生不可比较的对，模 1e9 + 7。 

关键约束是`n ≤ 10^5`，它排除了任何随每个位置的数字差异而增长的二次或状态空间。 任何解决方案都必须以恒定时间或恒定数量的状态处理每个位置，自然导致线性 DP 或组合前缀聚合。 

一个常见的微妙失败案例来自于将“某个位置的局部主导地位”与“全球可比性”混合在一起。 例如，两个字符串如`10`和`01`不可比较，因为一个在索引 1 处获胜，另一个在索引 2 处获胜，但是如果仅考虑总和或一阶差分，则每个位置比较的贪婪解释可能会错误地将它们标记为可比较。 

当未知因素导致灵活性不对称时，就会出现另一种失败情况。 例如，`?0`相对`00`根据任务的不同，可以产生可比较和不可比较的结果，并且独立地处理每个位置而不跟踪全局方向约束会导致计数过多。 

## 方法

 暴力方法会尝试两个模板的所有数字分配。 由于每个位置最多有 10 个独立选择，这给出`10^(2n)`最坏情况下的可能性。 即使是为了`n = 10^5`，这是完全不可行的，甚至对于`n = 10`它已经很大了。 

关键的观察是，最终的分类仅取决于是否存在至少一个位置`s > w`并且至少有一个地方`s < w`。 这表明逐个跟踪比较，同时保持我们是否已经在任一方向看到了严格的优势。 

在每个位置，根据角色，我们可以计算产生多少作业`s[i] > w[i]`, 生产多少`s[i] < w[i]`，以及有多少产生平等。 我们不是构建字符串，而是聚合三态 DP 的转换：到目前为止我们是否没有看到任何差异，看到了`s > w`, 见过`s < w`，或两者（吸收有效状态）。 

这将问题简化为线性扫描，其中每个位置更新由组合计数加权的恒定大小状态机。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(10^(2n)) | O(10^(2n)) | O(n) | 太慢了 |
 | 比较状态的最佳 DP | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们在四个概念状态上维护一个 DP，描述当前前缀之前观察到的内容。 

设各州为：

 -`00`: 还没有看到严格的比较
 -`10`: 我们看到了一个位置`s > w`-`01`: 我们看到了一个位置`s < w`-`11`: 两个方向均可见（有效吸收状态）

 我们计算每个位置有多少种方式有助于平等，`s > w`， 或者`s < w`。 

### 1. 每个职位的贡献计数

 对于每个索引`i`，我们检查字符`a = s[i]`,`b = w[i]`。 

如果两者都是数字，则只有一种结果，并且它恰好有助于相等、更大或更少之一。 

如果其中之一或两者都是`?`，我们计算有多少个数字对`(x, y)`产生各个关系。 这纯粹是数字的组合`0..9`。 

此步骤是必要的，因为我们不是全局迭代分配，而是将每个位置的所有分配压缩为计数。 

### 2. DP 转换设置

 在处理前缀后，我们维护处于每种状态的方式计数`i`。 

最初：

-`dp[00] = 1`- 其他为零

 这反映出在处理任何字符之前，没有观察到比较。 

### 3. 使用相等转换进行更新

 如果在位置`i`我们分配相同的数字，全局状态不会改变。 所有 DP 状态都乘以平等分配的数量。 

这保留了有关比较的当前知识，而不引入新信息。 

### 4. 通过严格的比较转换进行更新

 如果`s[i] > w[i]`，那么：

 - 状态`00`过渡到`10`- 状态`01`过渡到`11`- 状态`10`停留`10`- 状态`11`停留`11`同样，如果`s[i] < w[i]`，适用对称过渡。 

这一步编码了关键逻辑：一旦两个方向都出现，我们就永远有效。 

### 5.最终答案提取

 处理完所有位置后，仅说明`11`有助于得出答案，因为不可比性至少需要一个`s > w`以及至少一个`s < w`。 

### 为什么它有效

 该算法根据我们是否已经见证了两个比较方向来维护所有前缀分配的完整摘要。 任何数字分配都恰好对应于通过这些状态的一条路径，因为每个位置恰好贡献三个结果之一：相等、更大或更少。 由于转换仅取决于之前是否见过某个方向，因此未来的决策无法撤消之前见过的比较，从而使 DP 成为所有分配的正确压缩。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def count_rel(a, b):
    if a != '?' and b != '?':
        a = int(a)
        b = int(b)
        if a == b:
            return (1, 0, 0)
        elif a > b:
            return (0, 1, 0)
        else:
            return (0, 0, 1)

    res_eq = res_gt = res_lt = 0

    for x in range(10):
        for y in range(10):
            if a != '?' and x != int(a):
                continue
            if b != '?' and y != int(b):
                continue
            if x == y:
                res_eq += 1
            elif x > y:
                res_gt += 1
            else:
                res_lt += 1

    return res_eq, res_gt, res_lt

def solve():
    n = int(input())
    s = input().strip()
    w = input().strip()

    dp00 = 1
    dp10 = 0
    dp01 = 0
    dp11 = 0

    for i in range(n):
        eq, gt, lt = count_rel(s[i], w[i])

        ndp00 = ndp10 = ndp01 = ndp11 = 0

        ndp00 = dp00 * eq % MOD

        ndp10 = (dp00 * gt + dp10 * eq + dp10 * gt + dp01 * gt) % MOD
        ndp01 = (dp00 * lt + dp01 * eq + dp01 * lt + dp10 * lt) % MOD

        ndp11 = (dp11 * (eq + gt + lt) + dp10 * lt + dp01 * gt) % MOD

        dp00, dp10, dp01, dp11 = ndp00, ndp10, ndp01, ndp11

    print(dp11 % MOD)

if __name__ == "__main__":
    solve()
```该代码首先计算每个位置有多少数字分配产生相等、大于和小于关系。 这样就无需稍后推理各个数字的选择。 

然后 DP 追踪四个州。`dp00`表示没有观察到差异，`dp10`和`dp01`表示仅在一个方向上看到严格的不平等，并且`dp11`代表两个方向都已经出现了。 每次转换都会将先前的状态计数与每个位置的关系计数相结合。 

一个微妙的点是从`dp10`和`dp01`必须包括保留当前方向状态的相等情况，同时在出现相反的不平等时还允许新的转换。 这`dp11`状态吸收所有转换，因为一旦两个方向都存在，额外的位置就不能使不可比性失效。

 ## 边缘情况

 一种关键的边缘情况是，由于数字固定，一个字符串永远不能超过另一个字符串。 例如：```
1
0
9
```这里`s < w`是被迫的，所以`dp01`变得活跃并且`dp11`永远不会出现。 该算法正确地输出零，因为没有赋值可以引入这样的位置：`s > w`。 

另一种情况是完全通配符输入：```
2
??
??
```每个位置都可以相等、更大或更小。 DP 积累了许多混合路径，并且只有那些至少有一个位置有贡献的路径`>`另一个贡献`<`抵达`dp11`。 转换结构确保仅相等路径永远不会错误地进入有效状态。 

最后一个微妙的情况是，单个位置已经确定了不同任务的两个方向。 例如：```
1
?
?
```一些作业会产生`s > w`,其他人生产`s < w`，但没有一个任务会同时产生两者。 DP 正确地将这些路径分开，并且仅当不同的位置提供两个所需的方向时才将它们组合起来。
