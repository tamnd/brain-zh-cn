 ## 解决方案
 ## 问题理解

 我们得到一棵树，意味着没有循环的连通图。 任务是在两个先前未连接的节点之间添加一条新边。 添加这条边后，必须出现一个环，并且该环必须包含至少三个不同的节点。 

在树中，任何一对节点之间都已经存在一条简单路径。 当我们在两个节点 u 和 v 之间添加一条额外的边时，该边会闭合它们之间的唯一路径，并创建一个循环，其长度恰好等于 u 和 v 之间的路径上的边数，加上新边的 1。 因此，当且仅当 u 和 v 之间的原始路径包含至少 2 条边时，循环长度至少为 3，这意味着树中 u 和 v 之间的距离至少为 2。 

输入描述了具有 n 个节点和 n − 1 个边的树结构。 输出是任何有效的节点对，它们不直接由树中的边连接，因为这样的节点对保证它们的距离至少为 2（否则它们将与距离 1 相邻）。 在任何这样的对之间添加一条边会创建一个长度至少为 3 的循环。 

约束非常小，n 最多为 100。这立即排除了超出线性或近二次工作的任何内容，但问题的结构比这更简单：我们只需要找到一个非边对。 

当树是一颗星时，会出现微妙的边缘情况。 在星形中，许多对节点都是叶子并且不直接连接。 例如，如果节点 1 连接到所有其他节点，则任何一对叶子都可以工作。 如果实施不正确，仅尝试选取度 > 1 的节点或假设存在长路径的简单方法可能会失败，因为直径可能仍为 2。 

另一个极端情况是最小的有效树，n = 3。该树始终是长度为 2 的路径。唯一有效的添加边位于两个端点之间。 如果错误地避免了叶子或仅在本地检查邻接性，则仍然很容易错过正确答案是端点。 

## 方法

 一种暴力方式是尝试所有节点对（u，v），检查它们是否由边连接，如果没有，则输出它们。 由于该图最多有 100 个节点，因此检查所有对最多 10,000 个组合，并且对于每对，我们可以使用邻接矩阵或每个节点的集合来测试邻接性。 这已经很适合时间了。 

关键的观察是，除了非相邻节点始终工作这一事实之外，我们实际上并不关心距离或循环构造。 因此，问题简化为找到任意一对之间没有边的顶点。 这将问题从图形推理转移到简单的邻接检查。 

一种稍微更结构化的观点是，在任何 n ≥ 3 的树中，补图永远不会为空，这意味着总是至少有一个缺失的边。 因此，有效的对总是存在的。 这保证了简单的扫描将会成功。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 通过邻接检查暴力破解所有对 | O(n²) | O(n²) 或 O(n) | 已接受 |
 | 邻接集的最佳扫描 | O(n²) | O(n) | 已接受 |

 ## 算法演练

1. 读取树并将邻接信息存储在允许快速边缘存在检查的结构中。 每个节点的集合或布尔矩阵都可以工作。 这是必要的，因为决策仅取决于边缘是否已经存在。 
2. 迭代所有节点对 (u, v)，且 u < v。排序避免重复并确保确定性输出。 
3. 对于每一对，检查 u 和 v 是否通过边直接连接。 如果没有连接，则立即输出这一对。 
4. 在找到第一个有效对后停止，因为任何此类对在连接时都保证长度至少为 3 的循环。 
5. 如果使用邻接集实现，则存在性检查的平均时间为 O(1)，因此扫描速度仍然很快。 

选择第一个有效对背后的原因是该问题不强加优化要求，只强加存在性。 

### 为什么它有效

 在树中，任何一对节点都通过一条简单路径连接。 在两个节点之间添加一条边会创建一个由该路径加上新边组成的循环。 如果节点相邻，则该路径的长度为 1，环路的长度为 2，这是无效的。 如果它们不相邻，则路径长度至少为 2，因此循环长度至少为 3。由于每棵至少有 3 个节点的树总是包含至少一个非边对，因此保证搜索成功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
adj = [set() for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    adj[u].add(v)
    adj[v].add(u)

found = False

for u in range(1, n + 1):
    for v in range(u + 1, n + 1):
        if v not in adj[u]:
            print(u, v)
            found = True
            break
    if found:
        break
```邻接列表存储为集合，以使边存在检查的时间恒定。 双循环确保我们最终遇到非边对。 早点休息很重要，因为存在多个有效答案，而我们只需要一个。 

一个常见的实现错误是使用邻接列表，然后使用以下命令检查成员资格`in`，在最坏的情况下会降级为 O(n3)。 当 n ≤ 100 时，它可能仍然会通过，但这是不必要的风险。 

## 工作示例

 ### 示例 1

 输入：```
3
1 2
2 3
```我们建立邻接关系：

 1 → {2}

 2 → {1, 3}

 3 → {2}

 我们扫描对：

 | 你| v | 边缘存在 | 行动|
 | --- | --- | --- | --- |
 | 1 | 2 | 是的 | 跳过|
 | 1 | 3 | 没有| 输出|

 输出是`1 3`。 

这证实了路径的端点在连接时始终形成有效的循环。 

### 示例 2

 输入：```
4
1 2
1 3
3 4
```邻接：

 1 → {2,3}

 2 → {1}

 3 → {1,4}

 4 → {3}

 扫描：

 | 你| v | 边缘存在 | 行动|
 | --- | --- | --- | --- |
 | 1 | 2 | 是的 | 跳过|
 | 1 | 3 | 是的 | 跳过|
 | 1 | 4 | 没有| 输出|

 输出是`1 4`。 

这表明即使在分支树中，我们也总能在遍历的早期找到不相邻的对。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 我们检查所有节点对一次，并且使用集合|每个边检查都是 O(1)。 
| 空间| O(n) | n−1 条边的邻接存储 |

 当 n ≤ 100 时，最大操作约为 10,000 次检查，这在 1 秒限制下是微不足道的。 内存使用量也可以忽略不计。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys

    input = sys.stdin.readline

    n = int(input())
    adj = [set() for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].add(v)
        adj[v].add(u)

    for u in range(1, n + 1):
        for v in range(u + 1, n + 1):
            if v not in adj[u]:
                return f"{u} {v}"
    return ""

# sample 1
assert run("3\n1 2\n2 3\n") == "1 3"

# sample 2
assert run("4\n1 2\n1 3\n3 4\n") == "1 4"

# minimum case

# star tree
assert run("5\n1 2\n1 3\n1 4\n1 5\n") != ""

# path tree
assert run("5\n1 2\n2 3\n3 4\n4 5\n") != ""

 ## 边缘情况

 在星形树中，节点 1 连接到所有其他节点。 该算法尽早检查像 (2, 3) 这样的对，看不到边缘，并立即输出。 这证实了高度中心并不影响正确性。 

在路径形树中，邻接是局部的，因此第一对非邻接通常是由至少一个中间节点分隔的端点或节点。 扫描自然会找到 (1, n) 或另一个有效对。 

在最小的情况下 n = 3，唯一的非边对是端点。 循环正确地跳过中间邻接并返回正确的答案。
