 ## 解决方案
 ## 问题理解

 最终的条带包括`n`单位段，并且因为`n = m`在此子任务中，每种颜色`1`到`n`恰好出现一次。 输入数组只是一个排列，描述所有重绘操作完成后每个单元段上的可见颜色。 

最初整个条带都有颜色`0`。 颜色按递增顺序一一应用。 当颜色`i`使用时，Alice 必须选择当前具有单一颜色的连续区间，并用颜色重新绘制整个区间`i`。 完成所有操作后，每个位置都会显示排列中给出的颜色。 

我们需要计算有多少种音程选择恰好产生了最终的排列。 

大小限制仅为 500，因此三次动态规划是完全可以接受的。 对所有区间选择的指数搜索将立即爆炸，因为即使对于`n = 20`已经有很多可能的序列了。 二次内存也是无害的。 

主要的危险是绘画顺序是固定的。 我们不能随时重新绘制任意间隔。 为较大颜色选择的每个间隔必须完全位于先前创建的单色区域内。 

另一个容易犯的错误是独立思考立场。 认为```
3 3
1 2 3
```答案是```
5
```不是`1`。 不同的区间嵌套结构可以产生相同的排列。 

第二个微妙的情况是```
3 3
2 1 3
```谁的答案是```
2
```颜色`1`是整个数组中最小的颜色，因此它的区间成为递归的根。 任何试图从左到右处理的方法都会错过一个有效的安排。 

第三个棘手的情况是```
4 4
2 4 1 3
```最小颜色位于中间。 左侧和右侧成为独立的子问题，但每一侧都可以通过多种方式连接到根。 忘记这些附件选择就会低估答案。 

## 方法

 强力搜索将模拟每个可能的间隔序列。 每当颜色`i`应用后，我们将枚举当前可用的所有单色间隔并递归。 这正确地探索了所有绘画历史，但状态的数量呈指数级增长。 即使对于中等值`n`，可能性的数量变得太大。 

关键的观察来自于观察任何区间内最小的颜色。 

考虑一些子数组`[l,r]`。 在其颜色中，令位置`p`包含最小值。 由于颜色是按递增顺序应用的，因此该颜色必须先于内部所有其他颜色绘制`[l,r]`。 因此，左侧的每种颜色和右侧的每种颜色都必须在属于该最小颜色的区间内创建。 

这意味着位置`p`充当递归分解的根。 The left and right parts are independent, except that each side may expand toward the root in several different ways. This leads naturally to interval dynamic programming.

 对于每个间隔`[l,r]`， 定义`dp[l][r]`作为恰好产生该间隔的有效绘画历史的数量。 如果最小颜色位于位置`p`，那么我们必须合并左右子区间。 需要额外的状态来计算一侧可以连接到根的方式。 

由此产生的复杂度变成立方体，这很容易足够快`n ≤ 500`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n3) | O(n²) | 已接受 |

 ## 算法演练

 1. 对于每个间隔`[l,r]`，定位位置`p`其最小颜色。 因为`n=500`，检查每个区间内的所有候选者足够便宜。 
2. 定义`dp[l][r]`作为构建子数组的方法数`[l,r]`。 
3.引入另一个表`f[l][r]`，其中区间的根`[l,r]`被迫从左边界连接。 
4.引入对称表`g[l][r]`，其中根被迫从右边界连接。 
5. 空间隔有一种作用。 
6. 假设最小颜色为`[l,r]`处于位置`p`。 
7. 计算`f[l][r]`,选择一些分割点`k`之间`p`和`r`。 该段`[p,k]`属于根的右展开式，而`[k+1,r]`成为一个独立的子问题。 将这两个部分的方式数量相乘，然后将所有方式相加`k`。 
8. 计算`g[l][r]`通过选择左侧的分割点来对称。 
9. 最后，整个区间`[l,r]`通过将左附件计数与右附件计数相乘获得：```
dp[l][r] = f[l][p-1] × g[p+1][r]
```1. 按长度递增的顺序处理间隔，以便已经计算出每个较小的间隔。 
2.答案是`dp[0][n-1]`。 

### 为什么它有效

 在任何区间内，首先绘制该区间的所有颜色中最小的颜色。 以后的每次重新绘制都必须发生在由该最小颜色创建的单色段内。 因此，最小值左侧和右侧的颜色永远不会相互干扰，并且每一侧都可以独立处理。 

桌子`f`和`g`在将剩余后缀或前缀委托给较小的子问题之前，计算根区间吸收连续位置的所有可能方式。 每一个有效的绘画历史都恰好对应于这样的选择的一个序列，并且由递归产生的每个序列都尊重绘画规则。 因此，动态程序对所有有效历史记录进行一次计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
a = list(map(int, input().split()))

mn_pos = [[0] * n for _ in range(n)]
for i in range(n):
    pos = i
    for j in range(i, n):
        if a[j] < a[pos]:
            pos = j
        mn_pos[i][j] = pos

dp = [[1] * n for _ in range(n)]
f = [[1] * n for _ in range(n)]
g = [[1] * n for _ in range(n)]

def get_dp(l, r):
    if l > r:
        return 1
    return dp[l][r]

def get_f(l, r):
    if l > r:
        return 1
    return f[l][r]

def get_g(l, r):
    if l > r:
        return 1
    return g[l][r]

for length in range(1, n + 1):
    for l in range(n - length + 1):
        r = l + length - 1
        p = mn_pos[l][r]

        val_f = 0
        for k in range(p, r + 1):
            val_f += get_g(p + 1, k) * get_dp(k + 1, r)
            val_f %= MOD
        f[l][r] = val_f

        val_g = 0
        for k in range(l, p + 1):
            val_g += get_dp(l, k - 1) * get_f(k, p - 1)
            val_g %= MOD
        g[l][r] = val_g

        dp[l][r] = get_f(l, p - 1) * get_g(p + 1, r)
        dp[l][r] %= MOD

print(dp[0][n - 1])
```第一个预处理循环存储每个间隔的最小元素的位置。 由于只有 500 个位置，二次预处理成本很小。 

辅助函数返回`1`在空的间隔上。 这是乘法的标准中性元素，并消除了许多边界检查。 忘记这一约定通常会在数组末尾产生一个错误。 

间隔按长度递增的顺序进行处理。 每次重复仅指较短的间隔，因此所有必需的值都已可用。 

桌子`f`和`g`实施不对称附件计数。 他们的公式是彼此的镜像。 将两个表分开可以使转换清晰并避免复杂的大小写区别。

 ## 边缘情况

 考虑```
1 1
1
```只有一种颜色，因此一次重涂覆盖了整个条带。 在 DP 期间，每个空间隔都会贡献`1`，答案就变成了`1`。 

考虑```
3 3
2 1 3
```最小颜色位于位置`1`。 该算法将区间分为`[0,0]`和`[2,2]`，独立计算两者，并将它们组合起来。 答案是`2`，匹配根区间扩展的两种可能方式。 

考虑```
4 4
2 4 1 3
```最小值位于区间内而不是端点处。 桌子`f`和`g`在将剩余部分交给递归子问题之前，枚举向左和向右的所有可能的扩展量。 这可以避免计数不足并产生正确的答案`3`。
