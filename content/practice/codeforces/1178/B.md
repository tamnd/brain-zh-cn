 ## 解决方案
 ## 问题理解

 我们得到一个仅由两个字符组成的字符串，`v`和`o`。 我们需要计算该字符串有多少个子序列构成了该模式`"wow"`。 子序列意味着我们按升序选择索引，不一定是连续的，并读取这些位置的字符。 所以每个有效的索引三元组$i < j < k$这样的字符是`w`,`o`,`w`贡献一次出现。 

关键的复杂性是没有字面意义`w`输入中的字符。 相反，每次出现`"vv"`应被解释为单一势能`w`，子序列可以选择`v`以不同的方式。 这实际上意味着每对`v`角色可以充当`w`，我们正在计算有多少种方法可以选择两个`v`之前的 s`o`，和两个`v`在它之后。 

字符串长度可达$10^6$，这立即排除了任何$O(n^2)$或者更糟糕的方法。 甚至$O(n \log n)$是不必要的； 该结构表明我们应该能够通过在扫描时累积计数来在线性时间内解决它。 

一种简单的方法，枚举所有对`v`每个两边都有字符`o`会组合爆炸。 如果有$k$的出现次数`v`， 有$O(k^2)$选择其中两个的方法，并对每个都执行此操作`o`会再次成倍增加成本。 对于大量投入来说，这远远不可行。 

微妙的边缘情况来自没有`o`无论如何，答案必须为零，因为没有`"wow"`子序列可以不存在中间字符。 另一种情况是少于两个的字符串`v`总数，无论排列如何，答案都是零。 

## 方法

 蛮力的想法很简单：解释每一对`v`职位作为可能的`w`，然后检查所有选择左边的方法`w`, 中间一个`o`，和一个右`w`。 对于每个`o`，我们会扫描所有`v`其左侧的对和所有`v`对在其右侧。 如果有$L$v 在左边并且$R$在右边，我们会花$O(L^2 + R^2)$每`o`。 在最坏的情况下，字符串全部`v`除了单个`o`，这退化为$O(n^2)$，这对于$n = 10^6$。 

关键的观察是我们实际上不需要显式枚举对。 单个贡献`o`只取决于我们可以选择两个的方式有多少`v`s 在其左侧和两个`v`s 在其右侧。 如果我们知道前缀计数`v`，然后选择两种方式`v`s 来自 size 前缀$x$是$\binom{x}{2}$。 类似地，后缀贡献可以增量计算。 

因此，我们不是根据位置进行推理，而是将问题转换为计算组合。 当我们扫描字符串时，我们维护有多少`v`到目前为止我们已经看到的角色。 每次我们遇到一个`o`, 有效数量`"wow"`以该位置为中心的子序列取决于对的数量`v`左边和对的数量`v`在右侧。 这可以使用前缀和后缀预处理来有效地累积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们根据每个位置的贡献重写问题，其中包含`o`。 

1. 数一数有多少个`v`字符出现在整个字符串中。 这为我们提供了后缀计算的初始池。 我们需要这个，因为右侧的贡献取决于有多少`v`每个位置后仍保留 s。 
2. 预先计算前缀数组`pref_v`， 在哪里`pref_v[i]`是的数量`v`前缀中以索引结尾的字符`i`。 这可以让我们快速知道有多少`v`s 位于任意位置的左侧。 
3. 预先计算后缀数组`suf_v`， 在哪里`suf_v[i]`是的数量`v`索引中的字符`i`到最后。 这让我们可以在恒定时间内计算右侧贡献。 
4. 对于每个位置`i`在哪里`s[i] == 'o'`，计算有多少对`v`存在于左侧，使用$\binom{pref_v[i-1]}{2}$。 这代表我们可以用多少种方式组成左边`"w"`图案的一部分。 
5. 同样计算有多少对`v`存在于右侧使用$\binom{suf_v[i+1]}{2}$。 这代表了权利`"w"`部分。 
6. 将这两个值相乘并将结果添加到答案中。 左对和右对的每个选择恰好形成一个有效的`"wow"`以此为中心的子序列`o`。 

### 为什么它有效

 每个有效`"wow"`子序列是通过选择两个不同的来唯一确定的`v`的左侧位置`o`和两个不同的`v`位于同一位置的右侧`o`。 中间`o`是固定的。 前缀和后缀计数确保我们准确考虑这些位置，而组合确保我们对每个选择进行一次计数。 既然不同`o`作为子序列的中心，位置是不相交的，对所有位置求和即可得出没有重叠或遗漏的总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def comb2(x):
    return x * (x - 1) // 2

def solve():
    s = input().strip()
    n = len(s)

    pref_v = [0] * (n + 1)
    for i in range(n):
        pref_v[i + 1] = pref_v[i] + (s[i] == 'v')

    suf_v = [0] * (n + 2)
    for i in range(n - 1, -1, -1):
        suf_v[i] = suf_v[i + 1] + (s[i] == 'v')

    ans = 0
    for i, ch in enumerate(s):
        if ch == 'o':
            left = pref_v[i]
            right = suf_v[i + 1]
            ans += comb2(left) * comb2(right)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先构建前缀和后缀计数`v`这样每个查询有多少`v`s 位于 a 的两侧`o`变为常数时间。 辅助函数`comb2`计算选择两个的方法数`v`来自一个团体。 

当迭代每个`o`，我们故意使用`pref_v[i]`而不是`pref_v[i+1]`因为它确保我们只考虑严格位于左侧的字符。 相似地，`suf_v[i+1]`确保我们只考虑严格位于右侧的字符，避免意外重用`o`位置。

 在索引 3 处，我们有`o`。 左边`v`计数为 3，对`v`计数为 3。 

左对：$\binom{3}{2} = 3$右对：$\binom{3}{2} = 3$总贡献：$3 \times 3 = 9$然而，只有选择两个的子序列`v`每边的 s 都是有效的，并且枚举确认组合乘法正确地计算了所有此类选择。 

该迹线显示了核心不变量：每个`o`独立作为中心，贡献因素影响独立的左右选择。

 ## 边缘情况

 对于没有的字符串`o`，头寸循环永远不会触发贡献步骤，因此答案仍然为零。 例如，输入`vvvvvv`产生前缀计数但没有中心，所以没有`"wow"`子序列被计数。 

对于恰好有 1 的字符串`v`在一个的两侧`o`， 例如`vov`，组合函数返回零，因为$\binom{1}{2} = 0$。 这确保无效的部分结构不会起作用。 

对于有很多的字符串`v`只是一个`o`， 例如`vvvvovvvv`，该算法正确计算两侧组合的乘积。 前缀和后缀数组确保所有有效的对选择都被精确计数一次而不会重叠。
