 ## 解决方案
 ## 问题理解

 我们有一棵有根树，根在顶点`1`。 每个顶点都存储一个值`x[v]`。 对于任何祖先-后代对`(u, v)`，我们查看来自的路径`u`下降到`v`并计算该路径上所有值的 gcd。 任务是将树中每个祖先-后代对的 gcd 值相加。 

直接解释是有用的。 修复顶点`v`。 每条有效路径结束于`v`从某个祖先开始`v`。 如果我们能够有效地计算每个祖先到的 gcd`v`路径，然后我们可以添加它们的贡献并对所有顶点重复。 

正是这些限制使问题变得有趣。 该树最多包含`100000`顶点，每个值可以大到`10^12`。 枚举所有祖先-后代对是不可能的，因为链形树包含大约`n(n+1)/2`这样的对，大致是`5 × 10^9`什么时候`n = 100000`。 

大值范围还排除了基于值频率表或值域上的类似筛式预处理的技术。 任何可接受的解决方案都必须利用 gcd 本身的结构特性。 

一些边缘情况值得关注。 

考虑一条包含零的路径。```
2
0 6
1 2
```有效路径是：`(1,1) = 0`

`(2,2) = 6`

`(1,2) = gcd(0,6) = 6`答案是`12`。 

假设在延伸路径时 gcd 总是减小的解决方案会错误地处理零，因为`gcd(0,x)=x`。 

另一个微妙的情况是等值链。```
3
5 5 5
1 2
2 3
```每条路径 gcd 都等于`5`。 有六对祖先-后代，所以答案是`30`。 

简单的实现可能会重复地重新计算相同的 gcd 值，即使扩展路径不会改变任何内容。 

第三个重要案例是 gcd 值快速崩溃的链条。```
3
12 18 25
1 2
2 3
```路径 gcds 以顶点结束`3`是：`25`,`gcd(18,25)=1`,`gcd(12,18,25)=1`。 

两个不同的祖先产生相同的 gcd 值。 独立处理路径会错过重大优化。 

## 方法

 蛮力的想法很简单。 对于每个顶点`v`，向上遍历所有祖先并保持该路径的gcd。 每个祖先为答案贡献一个 gcd 值。 

这是正确的，因为每个祖先-后代对都被检查一次。 

问题在于复杂性。 在一条长度的链条中`n`, 顶点`i`有`i`祖先。 祖先-后代对的总数变为$$1+2+\cdots+n = O(n^2).$$为了`n = 100000`，这远远超出了时限内可以处理的范围。 

关键的观察是沿路径的 gcd 值不会经常变化。 

假设我们固定一个顶点`v`并查看所有结束于的路径`v`。 让$$g_1,g_2,\dots$$是当我们将起始祖先扩展到越来越高时获得的 gcd 值。 

每个新的 gcd 都是通过以下方式获得的$$\gcd(\text{previous gcd}, x[\text{new vertex}]).$$每当 gcd 改变时，它必须成为前一个值的真除数。 一个数只能失去对数次质因数。 对于值高达`10^{12}`，根到顶点路径上不同 gcd 值的数量非常少，大约最多几十个。 

这表明不存储单个路径，而是存储共享相同 gcd 的路径组。 

在 DFS 期间，对于我们维护的每个顶点：```
(gcd value, count of paths ending here with that gcd)
```从其父级列表派生。 

如果家长有团体`(g, cnt)`，然后将这些路径延伸通过当前顶点后，它们的 gcd 变为$$\gcd(g, x[v]).$$许多组合并成相同的gcd值，因此我们立即压缩它们。 

结束于的路径所贡献的所有 gcd 值的总和`v`那么就是$$\sum g \cdot cnt.$$由于每个顶点仅存储少量不同的 gcd 状态，因此总复杂度几乎是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n² log A) | O(n² log A) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n log² A) | O(n log² A) | O(n log A) | O(n log A) | 已接受 |

 这里`A ≤ 10^{12}`。 

## 算法演练

 1. 以顶点为树根`1`。 
2. 从根运行 DFS。 
3. 对于每个顶点`v`，从其父级接收压缩列表：```
[(g1,c1), (g2,c2), ...]
```在哪里`gi`是 gcd 值并且`ci`是产生该 gcd 的祖先到父路径的数量。 
4. 为顶点创建一个新列表`v`。 

对于每对`(g,c)`从父列表中计算：```
ng = gcd(g, x[v])
```因为每条以父级结尾的路径都可以扩展到以`v`。 
5. 合并相等的 gcd 值。 

如果几个父州产生相同的`ng`，将它们的计数加在一起，而不是存储单独的条目。 
6.添加仅由顶点组成的路径`v`。 

这会产生一个额外的状态：```
(x[v], 1)
```7. 所有合并之后，结果列表代表每个祖先到-`v`按 gcd 值分组的路径。 
8. 添加他们对全球答案的贡献：```
answer += Σ(g * count)
```模数`1e9+7`。 
9. 使用当前压缩列表递归到每个子级。 
10. 继续，直到处理完整个树。 

### 为什么它有效

 对于每个顶点，维护的列表包含以该顶点结束的所有路径，并按相等的 gcd 值分组。 

基本情况是根。 它唯一的路径是单顶点路径，表示为`(x[root],1)`。 

假设该表示对于父母来说是正确的。 每条以子节点结束的路径都是：

 1. 仅由子节点组成的单顶点路径。 
2. 由孩子延伸的父母结束路径。 

扩展路径的 gcd 正好是`gcd(parent_path_gcd, x[child])`。 每个这样的路径都会生成一次，并且具有相等结果 gcd 值的路径通过求和计数来合并。 因此，表示仍然准确。 

由于每条祖先-后代路径恰好在一个顶点处结束，并且其 gcd 通过恰好一个状态计数做出贡献，因此累加的总和正是所需的答案。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

MOD = 1000000007

def solve():
    n = int(input())
    vals = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    ans = 0

    def dfs(v, parent, prev):
        nonlocal ans

        cur = []

        for gg, cnt in prev:
            ng = gcd(gg, vals[v])

            if cur and cur[-1][0] == ng:
                cur[-1] = (ng, cur[-1][1] + cnt)
            else:
                cur.append((ng, cnt))

        if cur and cur[-1][0] == vals[v]:
            cur[-1] = (vals[v], cur[-1][1] + 1)
        else:
            cur.append((vals[v], 1))

        for gg, cnt in cur:
            ans = (ans + (gg % MOD) * cnt) % MOD

        for to in g[v]:
            if to != parent:
                dfs(to, v, cur)

    dfs(0, -1, [])
    print(ans)

if __name__ == "__main__":
    solve()
```邻接表存储树。 DFS 携带一个从父级到子级的压缩 gcd 状态列表。 

关键的细节是合并步骤。 不同的父 gcd 值在包含当前顶点后可以产生相同的 gcd。 如果我们不合并它们，状态计数将随着深度线性增长，复杂性也会降低。 

单顶点路径必须始终单独添加，因为每个顶点都是其自身的祖先。 

答案是在访问每个顶点时累积的。 每个州`(g,cnt)`准确地代表`cnt`gcd 等于的路径`g`，所以他们的总贡献是`g * cnt`。 

Python 整数安全地处理高达`10^12`，并且 gcd 计算是使用执行的`math.gcd`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log² A) | O(n log² A) | 每个顶点仅处理其路径上不同的 gcd 值 |
 | 空间| O(n log A) | O(n log A) | DFS 堆栈和压缩 gcd 状态 |

 任何根到顶点路径的不同 gcd 值的数量都很小，因为每次更改都会产生适当的除数。 对于值高达`10^12`，这仍然是有界的，使解决方案很容易符合`100000`顶点。

 ## 边缘情况

 ### 包含零的路径

 输入：```
2
0 6
1 2
```从根本上来说，状态是`(0,1)`。 

对于顶点`2`，扩展父状态给出：```
gcd(0,6)=6
```单节点路径贡献了另一个`6`。 

状态变为：```
(6,2)
```贡献是：```
0 + 12 = 12
```该算法从不特殊情况为零。 gcd 操作已经完全按照要求运行。 

### 等值长链

 输入：```
3
5 5 5
1 2
2 3
```状态演变为：```
v1: (5,1)
v2: (5,2)
v3: (5,3)
```而不是在顶点存储三个单独的 gcd 值`3`，所有路径合并为一种状态。 这使得状态大小保持较小，同时保留了精确的路径计数。 

### 多个祖先产生相同的 gcd

 输入：```
3
12 18 25
1 2
2 3
```在顶点`3`:```
gcd(6,25)=1
gcd(18,25)=1
```两条路径都会生成gcd`1`，所以它们合并为：```
(1,2)
```计数记录了两条不同的路径贡献gcd`1`。 求和`1*2`完全相当于单独处理路径，同时使用更少的内存和时间。
