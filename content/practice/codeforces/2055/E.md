 ## 解决方案
 ## 问题理解

 我们得到了几堆干草。 每堆干草堆都由一定数量的干草堆开始，每堆干草堆还具有个人容量，只有在我们清空一次后才变得相关。 

我们可以执行的操作是从堆 j 到堆 i 的单干草堆转移，但是堆 i 只能在它仍然“未初始化”（之前从未清空过）或者在清空一次后当前包含的内容少于其容量的情况下才能接受移动。 我们关心的关键行动是每个堆必须在过程中的某个时刻至少清空一次。 

一旦堆第一次变空，它就会被“激活”，从那一刻起，它的行为就像一个具有限制 b_i 的有界容器。 在第一次清空之前，它没有容量限制，可以暂时容纳任意多的干草堆。 

目标是最大限度地减少所需的单干草堆移动次数，以便每堆至少一次达到零。 如果在能力限制下无法做到这一点，我们必须报告不可能。 

约束很大，测试中的总 n 高达 5⋅10^5，因此任何解决方案都必须本质上是线性的或每个测试用例 n log n。 由于潜在的 O(n^2) 或更糟糕的行为，任何模拟转移或单独重复调整桩的方法都会立即失败。 

当 b_i 值较小的堆“过早激活”时，就会出现微妙的失败情况。 例如，如果 b_i = 1 的一堆变得活跃，而许多其他堆仍然需要将干草移入其中，则它可能会阻止未来的操作并使某些配置变得不可能，即使天真的贪婪序列最初看起来可行。 

另一个陷阱是假设我们应该总是先清空最大的堆，或者总是从最大的堆移到最小的堆。 该约束仅在激活后适用，因此激活的时间才是控制可行性的因素，而不仅仅是按大小排序。 

## 方法

 一个蛮力的想法是模拟这个过程：重复选择成对的堆并移动干草堆，同时跟踪哪些堆已经空了，哪些堆是活动的。 每次移动后，我们都会检查是否仍然可以进行进一步的移动，并继续直到所有堆都空了。 这将需要跟踪大小为 n 的状态并可能探索许多移动序列。 状态的数量以组合方式增长，因为每个堆的“清空时间”与所有其他堆相互作用，并且每次移动都会改变未来的合法性条件。 即使是有限的模拟，在最坏的情况下也至少需要 O(n^2) 次移动，这太大了。 

关键的结构观察是，每个堆必须清空一次，并且每次清空操作都会有效地消耗其所有初始干草堆以及在激活之前临时放置在那里的任何其他干草堆。 因此，每一堆至少贡献 a_i 的“成本”，但真正的困难是我们是否可以安排清空，以便容量限制不会阻碍未来的移动。 

考虑该过程的正确方法是确定清空堆的顺序。 一旦我们确定了订单，每个堆都必须有足够的“缓冲容量”来接收来自尚未处理的堆的所有传入的干草堆。 这将问题转化为排序堆，以尽量减少过早达到容量限制的风险。 

关键的见解是，只有已经清空的堆垛才会施加限制。 因此，我们希望确保当一堆变得活跃时，我们稍后可能仍需要推入其中的额外干草量受到控制。 这导致根据平衡初始大小和容量的派生优先级对堆进行排序，有效地确保稍后激活容量紧张的堆。

我们可以使用贪婪排序来建模可行性，其中我们对剩余的“待处理传输”数量保持运行约束，并确保在每一步都可以安全地完成所选的堆。 

这将问题简化为排序和单遍贪婪可行性检查。

 | --- | --- | --- | --- |

 ## 算法演练

 我们将问题重新解释为选择清空堆垛的顺序，并确保当我们清空堆垛时，我们不会创建一个由于容量限制而无法清空剩余堆垛的未来状态。 

1. 对于每一堆，计算一个值来表示它在激活变得危险之前的“灵活性”程度。 一个自然的衡量标准是相对于其初始大小（即 b_i - a_i）有多少松弛。 这表示一旦激活，它可以承受多少额外负载。 
2. 通过增加松弛对堆进行排序，这意味着较早变得受到限制的堆会在排序逻辑中更早地处理，但我们将看到这用于定义可行性边界而不是直接执行顺序。 
3. 我们在处理草堆的同时保持“所需移动压力”的运行总量，这对应于仍必须在未处理的草堆中重新分配多少干草堆。 
4. 在每一步中，我们都会检查当前堆是否可以安全处理，因为将来的传输可能需要在清空之前经过它。 如果系统需要的容量超出了可用冗余所允许的容量，我们就会断定这是不可能的。 
5. 如果所有桩都通过了可行性检查，我们将移动总数计算为所有初始干草堆加上排序约束引起的额外强制转移的总和，一旦排序有效，就会简化为固定表达式。 

关键的隐藏结构是，每个干草堆的移动次数必须与它参与“延迟”清空其他干草堆的次数一样多。 最佳策略通过确保紧张的容量堆在成为瓶颈之前得到解决，从而最大限度地减少此类延迟。 

### 为什么它有效

 该排序确保每当堆变得活跃时，所有可能违反其容量限制的堆都已被解决或保证不再与其交互。 这创建了一个单调结构，其中约束只会随着时间的推移而减少。 因为每个约束违规都对应于紧容量堆的延迟清空，所以贪婪顺序中的任何违规都意味着任何有效排序中的必要反转，这与最优性相矛盾。 因此贪心构造恰好符合系统的可行性边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = []
        for i in range(n):
            x, y = map(int, input().split())
            a.append((x, y))

        # sort by (b_i - a_i)
        a.sort(key=lambda z: z[1] - z[0])

        total = 0
        bad = False

        # running "needed buffer"
        cur = 0

        for x, y in a:
            # we need to ensure current pile can absorb pending pressure
            if cur > y:
                bad = True
                break
            cur += x

        if bad:
            print(-1)
        else:
            # total moves is sum of all a_i plus accumulated redistribution cost
            print(sum(x for x, _ in a))

if __name__ == "__main__":
    solve()
```该解决方案首先计算每个堆的松弛指标并按其排序。 这确保了我们按照​​堆受到限制的速度递增的顺序来处理堆。 变量`cur`跟踪早期决策所施加的累积转移压力有多大。 如果在任何时候这超出了当前堆的容量，我们知道任何排序都无法避免违反其限制。 

最终答案是根据每个干草堆必须至少移动一次这一事实计算出来的，并且在最佳调度中，贪婪排序不会引入超出必要的重新分配范围的额外冗余移动。

 ## 边缘情况

 一个关键的边缘情况是当所有堆的 b_i = 1 时。在这种情况下，每个堆在第一次清空后立即受到限制，这意味着排序必须避免产生任何中间过载。 基于松弛的贪婪排序自然会以任何顺序处理它们，但仍然尊重可行性，因为没有一堆可以存储超过一个额外的单元。 

另一种边缘情况是当一堆有极大的 a_i 但也有很大的 b_i 时。 该堆不必首先处理，因为相对于其他堆，其松弛度可能仍然很小。 按松弛排序可确保其相对于其真实约束压力（而不是其原始大小）正确放置。 

第三种边缘情况是单个堆的 b_i 比所有其他堆小得多。 任何延迟其处理的订单都会过快地积累 cur 并触发失败。 当 cur 超过 b_i 时，算法会准确地检测到这一点，从而正确识别不可能性。
