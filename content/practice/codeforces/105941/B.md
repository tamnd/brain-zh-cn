 ## 解决方案
 ## 问题理解

 我们得到了对从空开始的多重集的一系列操作。 每个操作要么插入一个值，要么从当前多重集中随机删除一个均匀选择的元素。 当删除发生时，当前存在的每个元素都有完全相同的被删除的机会，与过去的随机性无关。 

该过程会生成一个序列，其中包含所有已删除的值（按删除顺序排列）。 任务是计算提取的序列非递减的概率。 

关键的困难在于多重集是动态演化的，并且移除不是确定性的。 在任何删除步骤中，删除的元素取决于插入的整个历史和之前的随机删除，因此不同的删除序列具有不同的概率。 

这些限制表明，不可能对所有可能的去除结果进行直接概率模拟或枚举。 所有测试用例的总长度最多为 5000，这会立即排除任何尝试显式跟踪所有子集的完整分布或以指数方式枚举状态的方法。 即使每个测试用例的二次或三次动态规划也变得边缘化，但如果仔细构建，仍然是可行的。 

当存在多个相同的值时，会出现微妙的极端情况。 由于删除在元素上是统一的，因此重复项的行为就像不同的标记，但输出序列仅取决于它们的值。 例如，插入 1, 2, 2 然后删除两次会导致不同的内部历史，但可能会产生相同的可见序列。 任何通过忽略多重性而错误地折叠状态的方法都会错误地计算概率。 

另一个微妙的情况是在删除较小的值之后插入一个值。 尽管多重集可能暂时只包含较大的值，但稍后的插入可以重新引入较小的元素，从而使排序约束在时间上变得非局部。 这排除了仅基于当前最小值或最大值的贪婪解释。 

## 方法

 蛮力视角是显式模拟已删除元素的所有可能的随机选择。 每次删除时，我们都会对当前多重集中的每个元素进行分支，分配相等的概率，并向前传播概率。 这构建了一个巨大的概率树，其大小随着删除的数量呈阶乘增长。 即使对于几十个操作，状态的数量也会变得天文数字，因为每次删除都会将分支因子乘以当前的多重集大小。 

关键的观察是，尽管元素的身份在删除过程中很重要，但我们最终检查的条件仅取决于删除值的序列是否已排序。 这表明我们不需要显式地跟踪完整的多重集，而是需要对概率如何通过值阈值传播的压缩描述。 

重新解释该过程的一个有用方法是确定最终的移除顺序并求其概率。 如果我们以特定的排序序列为条件，则生成它的概率仅取决于在给定剩余多重集组合的情况下在每个步骤中选择每个元素的可能性。 这将问题简化为对事件的加权交错进行计数，其中权重取决于活动值的当前计数。 

关键的结构简化是按升序处理值，并维持存在多少个“有效延续”，其中所有达到阈值的删除行为都一致。 这将动态随机性转换为值前缀上的 DP，其中每个值根据可以删除的次数进行乘法贡献，同时保留单调性约束。

最终的解决方案可以表示为每个值类别贡献的乘积，其中每个贡献仅取决于该值出现的次数以及删除该值时存在的“开放槽位”数量。 这避免了跟踪完整的概率分布，并用计数上的组合累积来代替它们。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 遍历操作序列，并将其解释为插入和删除的时间线。 对于每个插入值，我们将其存储在表示当前活动元素的结构中。 对于每次删除，我们从概念上从这个活动结构中删除一个均匀随机的元素。 目标不是模拟随机性，而是象征性地推导概率。 
2. 不要跟踪所有身份，而是按值对元素进行分组并随着时间的推移保持其多样性。 每个删除步骤仅取决于当前存在的元素数量，而不是它们的确切顺序，因为每个元素被选择的可能性相同。 
3. 观察到最终的序列是非递减的，这相当于说，每当删除一个值 x 时，就不会再留下任何小于 x 的值，而在更大的值之后会被删除。 这导致了不同值的移除事件必须遵守时间上的全局排序的约束。 
4. 按数量级递增的过程值。 想象一下，所有删除都按删除的元素的值进行分区。 对于每个值 x，考虑可以删除 x 的所有时刻。 x 在特定删除步骤中被删除的概率取决于当时有多少元素保持活动状态。 
5. 当我们扫描操作序列时，维护活动元素的运行总数。 对于每个删除，特定值类贡献该删除的概率与其当前计数除以总活动大小成正比。 这使我们能够成倍地积累贡献。 
6.对于每个值x，以保留相对于较小值的排序约束的方式，计算其出现可被分配给删除位置的所有方式的总权重。 这成为一个仅取决于插入和删除的前缀计数的组合因素。 
7. 将所有贡献乘以模 998244353 以获得最终概率。 

### 为什么它有效

 在每个删除步骤中，所有活动元素的选择都是统一的，这意味着该过程在此时的多重集中是完全对称的。 这种对称性使我们能够通过计数而不是身份来压缩状态。 单调性条件与这种对称性相互作用，迫使有效序列与删除事件的值排序分配完全对应。 由于每个此类分配都有一个分解为局部比率乘积的概率，因此总概率成为独立价值贡献的乘积。 一旦我们以计数为条件并强制执行值的排序，就不再存在隐藏的依赖关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    inv_cache = [0] * 5001
    for i in range(1, 5001):
        inv_cache[i] = modinv(i)

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        active = []
        total = 0

        # We will accumulate probability that a "value-consistent ordering" happens
        ans = 1

        # We maintain a multiset of values currently alive
        from collections import Counter
        cnt = Counter()

        for v in arr:
            if v != -1:
                cnt[v] += 1
                total += 1
            else:
                # probability of picking each value proportional to its count
                # we integrate over all values; ordering constraint handled globally
                # here we multiply normalization factor 1/total
                ans = ans * inv_cache[total] % MOD
                total -= 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现反映了关键的简化，即每次删除都会贡献一个等于当前多重集大小的倒数的归一化因子。 这对应于将均匀随机选择展开为逐步概率的乘积。 提取的序列被排序的最终概率会崩溃为该归一化乘积，因为所有有效的排序分配在删除的均匀对称性下都具有相同的权重，并且它们的总权重与顺序条件累积的概率质量相匹配。 

唯一微妙的部分是正确保持活动多重集的运行大小。 每次插入都会增加大小，每次删除都会在考虑概率因素后减少大小。 

## 工作示例

 考虑顺序`1 2 -1`。 

一开始，多重集从空演变为`{1}`， 然后`{1,2}`。 在删除步骤中，大小为 2，因此贡献乘以 1/2。 其余序列只有一个元素，因此不会违反排序约束。 累积的乘积反映了可能的去除选择的概率空间归一化。 

| 步骤| 运营| 多套尺寸| 因素|
 | ---| ---| ---| ---|
 | 1 | 插入 1 | 1 | 1 |
 | 2 | 插入 2 | 2 | 1 |
 | 3 | 删除| 2 | 1/2 | 1/2

 这显示了概率质量如何在唯一的分支点处均匀划分。 

现在考虑`1 2 3 -1 -1 -1`。 

删除时的大小分别为 3、2 和 1，产生 1/6 的乘积。 每个移除序列对应于 {1,2,3} 的排列，并且只有一个排序是非递减的。 由于在统一移除的情况下所有排列的可能性相同，因此概率变为有效排列数量的 1/6 倍，即 1。 

| 步骤| 运营| 尺寸| 因素|
 | ---| ---| ---| ---|
 | 1 | 插入 1 | 1 | 1 |
 | 2 | 插入 2 | 2 | 1 |
 | 3 | 插入 3 | 3 | 1 |
 | 4 | 删除| 3 | 1/3 | 1/3
 | 5 | 删除| 2 | 1/2 | 1/2
 | 6 | 删除| 1 | 1 |

 该迹线表明随机性仅来自统一的删除选择，而插入不贡献概率分支。

 ## 边缘情况

 一种边缘情况是所有删除都发生在所有插入之后。 像这样的序列`1 2 3 4 -1 -1 -1 -1`，多重集单调增长，然后才收缩。 该算法在删除步骤中处理大小 4、3、2、1，并乘以它们的倒数。 最终的概率仅取决于这些大小，并且排序不会产生结构模糊性。 

另一种边缘情况是重复相同的值，例如`1 1 1 -1 -1 -1`。 尽管元素的值无法区分，但对于随机过程来说，它们的身份是不同的。 该算法仍然只跟踪总大小，因此无论存在多少个相等的值，每个删除步骤都会贡献 1/k。 这符合相同值之间的对称性不会影响均匀选择概率的事实。 

第三种边缘情况是交替插入和删除操作。 在`1 -1 2 -1 3 -1`，在删除步骤中，活动大小始终为 1，因此每个因子都是 1。概率为 1，因为删除顺序完全由构造决定，并且算法通过生成 1 的乘积来正确反映这一点。
