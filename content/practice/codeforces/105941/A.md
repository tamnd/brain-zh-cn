 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例提供一个长度数组$n$，其中每个元素都是介于$1$和$n$。 目标是将这个数组转换为排列$1 \ldots n$，这意味着每个数字$1$到$n$在最终数组中只出现一次。 

唯一允许的操作是选择一个连续的段$[l, r]$并覆盖该段中的每个位置。 段内的每个位置都可以分配以下任意值$1$到$n$，独立于其他操作，因此单个操作可以完全重新设计数组的一个块。 

任务是确定将初始数组转换为某种有效排列所需的此类段操作的最小数量。 

关键的观察是，我们不需要保留初始数组中的任何结构，只需达到排列的最终状态即可。 由于可以在操作段内自由分配值，因此问题减少为决定我们一次选择在一个操作块中修复哪些位置。 

限制很小：$n \le 40$，最多$10^4$测试用例。 这强烈表明我们不希望每个测试用例模拟任何指数。 相反，每个测试用例的答案结构必须可以在线性或近线性时间内提取。 

一种幼稚的解释是尝试显式构建最终排列或贪婪地一一修复不匹配。 这将是安全的，但不必要的复杂。 

一个微妙的问题是，可能存在多种最优策略，因为任何排列都是可以接受的。 这意味着我们可以自由地针对简单的规范排列，而不是对值的任意重新排列进行推理。 

## 方法

 思考这个问题的一种强力方法是模拟逐步构建最终的排列。 在每一步中，我们都可以选择任何段并分配值，以便逐渐消除数组中的冲突。 然而，由于每个操作都会影响整个区间，并且分配的选择不受限制，因此这会导致巨大的分支因子。 即使是为了$n = 40$，探索所有可能的片段序列是完全不可行的。 

关键的简化来自于视角的转变：我们不再考虑最终排列中需要哪些值，而是确定一个特定的目标排列。 最方便的选择是恒等排列$[1, 2, \ldots, n]$。 由于任何排列都是有效的，如果我们可以将数组转换为恒等式，那么我们就完成了。 

现在问题变得纯粹是位置问题了。 我们查看每一个指标$i$。 如果$a_i = i$，该位置已经与目标匹配，不需要任何操作。 如果$a_i \neq i$，然后定位$i$必须包含在至少一项操作中。 

由于每个操作覆盖一个连续的段，因此成本变为由需要修复的索引形成的连续段的数量。 通过准确地覆盖该范围，可以在一次操作中纠正每个这样的段。 

这减少了识别最大连续索引块的问题，其中$a_i \neq i$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解分段操作 | 指数| O(n) | 太慢了|
 | 计算连续不匹配块 | 每个测试用例 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1.我们读取数组并概念性地比较每个位置$i$及其索引。 如果该值已经等于$i$，我们将其视为已经正确，并且不对其执行任何操作。 
2.我们从左到右扫描，标记当前位置是否为“bad”，意思是$a_i \neq i$。 此分类是计算答案所需的唯一信息。 
3. 我们计算新的连续坏位置块开始的次数。 块从位置开始$i$如果$a_i \neq i$以及$i = 1$或者$a_{i-1} = i-1$。 
4. 每个这样的块恰好对应于一个操作，因为单个间隔操作可以重新绘制整个连续范围的不正确位置。 
5. 我们输出这些块的数量作为测试用例的答案。 

### 为什么它有效

 每个操作只能修改一个连续的段，因此我们固定在一起的任何一组位置都必须位于单个区间内。 相反，任何最大连续的不正确位置段始终可以通过精确选择该间隔在一次操作中修复。 将单个坏段拆分为多个操作没有任何好处，因为每次拆分只会增加间隔数量，而不会提高可行性。 

结果源于以下事实：成本正是索引集中与其目标值不同的连通分量的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        i = 0
        while i < n:
            if a[i] == i + 1:
                i += 1
                continue
            
            ans += 1
            j = i
            while j < n and a[j] != j + 1:
                j += 1
            i = j
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现遵循每个测试用例扫描一次数组的想法。 当发现不匹配时，它会贪婪地向右扩展，直到不匹配块结束，并将其算作一次操作。 然后指针跳过该块，确保线性复杂度。 

一个常见的陷阱是差一索引：问题是基于 1 的，而 Python 使用基于 0 的索引，因此比较使用$a[i] == i + 1$。 另一个微妙的点是我们必须立即跳过整个块； 在块内逐一递增仍然有效，但会不必要地冗长。

 ## 边缘情况

 对于已经排序的数组，例如$[1,2,\ldots,n]$，扫描没有发现不匹配块，直接输出零，因为不需要任何操作。 

对于完全不正确的数组，例如$[2,3,4,\ldots,1]$，每个位置最初都是坏的，但形成一个连续的块，因此算法正确地将其压缩为一个操作。 

对于交替的正确性模式，例如$[1,0,3,0,5,0]$调整到有效范围后，该算法独立地对每个单独的坏区域进行计数，反映出每个坏区域都需要单独的区间操作。
