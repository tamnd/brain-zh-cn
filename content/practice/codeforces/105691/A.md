 ## 解决方案
 ## 问题理解

 该任务描述了一个用数字玩的小游戏，其中每个数字贡献一个等于其自身的值，但选择一个数字有一个副作用：它“删除”了其直接邻居的值。 具体来说，如果您决定采用某个值 x 的所有出现，那么 x−1 和 x+1 的所有出现都将无法用于将来的选择。 每次您取值 x 时，您获得的积分等于 x 乘以 x 在输入中出现的次数。 目标是选择要采用的值，以便两个选定的值不会完全相差 1，同时最大化获得的总分数。 

输入只是一个整数列表。 输出是一个数字：在此约束下可达到的最大分数。 

主要约束是 n 最大为 100000，值也最大为 100000。这立即排除了尝试所有子集或模拟对所有元素进行决策的任何解决方案。 对于要选择的值的简单指数搜索将增长为 2 的不同值的幂，即使对于几十个不同的数字，这也是不可行的。 即使迭代所有出现的子集也远远超出了任何现实的限制。 

一个更微妙的问题出现在天真的贪婪尝试中。 例如，首先选择最频繁的值似乎是合理的，但它可能会严重失败，因为选择频率稍低的值可能会阻塞两个中等大的邻居并产生更高的总和。 

例如，考虑输入：

 3

 1 2 2

 贪心选择首先选择 1，获得 1，然后不能选择 2，结果总数为 1。最优解选择 2，获得 4。这表明局部频率或局部值决策是不可靠的。 

困难在于每个值仅与其直接邻居交互，这会创建结构化依赖关系而不是任意冲突。 

## 方法

 蛮力的想法是考虑不同值的每个子集并验证其是否有效，这意味着两个选定的值不会相差 1。对于每个有效子集，通过对值 × 频率求和来计算总贡献。 如果有 k 个不同的值，则需要检查 2^k 个子集，并且每个子集需要 O(k) 或 O(1) 计算和预处理。 在最坏的情况下，k 高达 100000，这种方法会立即失败，因为即使 k = 40 也已经导致超过一万亿个子集。 

关键的观察结果是，该结构与经典的“采取或跳过”线路动态规划相同。 聚合每个值的所有出现次数后，每个整数值变成单个权重：val[x] = x × count[x]。 限制“不能同时取 x 和 x+1”意味着选择 x 会强制排除一维值数组中的相邻索引。 

一旦问题以这种方式重写，它就成为标准的重现。 让 dp[x] 代表考虑 x 之前所有值的最佳答案。 对于每个 x，我们要么跳过它，保留 dp[x−1]，要么接受它，获得 val[x] 加 dp[x−2]。 该结构之所以有效，是因为取 x 引入的唯一冲突恰好是 x−1，并且所有小于 x−1 的值都保持独立。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(2^k) | O(2^k) | O(k) | 太慢了|
 | DP 超值 | O(maxA + n) | O(最大A) | 已接受 |

 ## 算法演练

1. 读取数字列表并计算每个值出现的次数。 此步骤压缩输入，因为只有频率重要，而不是位置。 
2. 将每个值 x 转换为权重贡献 x × 频率[x]。 这将问题转化为在数轴上的独立加权位置之间进行选择。 
3. 创建一个 DP 数组，其中 dp[x] 表示使用最大 x 的值可实现的最佳总和。 
4. 初始化 dp[0] = 0 和 dp[1] = value[1]，因为只有值 1 可用，唯一的选择是是否接受它。 
5. 对于从 2 到最大值的每个 x，将 dp[x] 计算为 dp[x−1] 和 dp[x−2] + value[x] 之间的最大值。 第一个选项对应于跳过 x，第二个选项对应于获取它并强制排除 x−1。 
6. 答案是dp[最大值]。 

这种递归有效的原因是，一旦值在整数行上排序，每个决策仅影响直接邻居。 任何达到 x 的最优解必须包含 x 或不包含 x。 如果排除 x，则简化为 x−1 的最优解。 如果它包含 x，则 x−1 被禁止，但 x−2 之前的所有内容均不受影响，因此最佳兼容前缀是 dp[x−2]。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    if n == 0:
        print(0)
        return

    maxv = max(arr)
    freq = [0] * (maxv + 1)

    for x in arr:
        freq[x] += 1

    val = [0] * (maxv + 1)
    for x in range(maxv + 1):
        val[x] = x * freq[x]

    if maxv == 0:
        print(0)
        return
    if maxv == 1:
        print(max(val[0], val[1]))
        return

    dp0 = 0
    dp1 = val[1]

    for x in range(2, maxv + 1):
        dp2 = max(dp1, dp0 + val[x])
        dp0, dp1 = dp1, dp2

    print(dp1)

if __name__ == "__main__":
    solve()
```该代码首先将输入压缩到频率表中，以便每个整数值独立贡献。 DP 通过仅保留前两个状态而不是完整数组在 O(1) 空间中实现。 这样可以避免最大值较大时的内存开销。 转换准确地反映了是否包含或排除当前值的决定，滚动变量 dp0 和 dp1 分别表示 dp[x−2] 和 dp[x−1]。 

一个常见的实现错误是仅迭代到输入中的最大值，但忘记中间值可能为零。 这在这里不是问题，因为 dp 转换自然会处理零：跳过空值会保留先前的最佳结果。 

## 工作示例

 考虑输入：```
3
1 2 2
```我们计算频率和值：

 | x| 频率[x] | 值[x] | dp 决定 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 采取 1 或跳过 |
 | 2 | 2 | 4 | 与 1 | 冲突

 逐步DP：

 | x| dp0 (x-2) | dp0 (x-2) | dp1 (x-1) | dp1 (x-1) | dp[x] | dp[x] |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 |
 | 2 | 1 | 1 | 4 |

 最终答案是4，通过取2得到。 

这表明即使 1 出现，牺牲它也是最佳选择，因为 2 会产生更高的总贡献。 

现在考虑：```
5
1 1 2 3 3
```频率给出的值：1→2、2→2、3→6。 

| x| dp0 | dp1 | DP |
 | --- | --- | --- | --- |
 | 1 | 0 | 2 | 2 |
 | 2 | 2 | 2 | 2 |
 | 3 | 2 | 2 | 8 |

 最终答案是8，仅取值3即可得到。 这证实了 DP 正确地传播了阻塞相邻值的效果。

 ## 边缘情况

 具有所有相同值的情况测试算法是否正确聚合频率：

 输入：```
4
7 7 7 7
```这里 freq[7] = 4，所以 value[7] = 28。没有重要的相邻约束，因为输入贡献中不存在 6 和 8。 DP 跳过所有其他值并直接选择 7，产生 28。 

另一个边缘情况是连续序列：

 输入：```
4
1 2 3 4
```DP评价：

 dp[1] = 1

 dp[2] = 最大值(1, 0 + 2) = 2

 dp[3] = 最大值(2, 1 + 3) = 4

 dp[4] = 最大值(4, 2 + 4) = 6

 最终结果 6 对应于选择值 2 和 4，显示了递归如何正确解决链上的交替选择。
