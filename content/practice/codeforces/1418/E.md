 ## 解决方案
 ## 问题理解

 我们有固定的多组怪物优势。 对于每个查询，盾牌都以耐用性开始`a`和防御值`b`。 怪物以统一的随机顺序进行战斗。 

实力至少为`b`消耗 1 点耐久值，但不造成任何伤害。 较弱的怪物什么也不做，而耐用性仍然为正。 一旦耐久度达到零，剩余的每个怪物都会造成与其强度相同的伤害。 

该问题询问所有可能订单的预期总损失。 

限制很大。 怪物数量和查询数量均达到`2·10^5`，所以任何二次方都是没有希望的。 即使在线性时间内处理每个查询也需要大约`4·10^10`运营。 我们周围需要一些东西`O((n+m) log n)`。 

当没有足够的强大怪物来耗尽护盾时，就会出现第一个微妙的情况。```
3 1
1 2 10
5 100
```至少没有怪物有实力`100`，因此耐用性永远不会降低。 伤害始终为零，答案是`0`。 一个粗心的除以强怪物数量的公式会崩溃。 

当强大怪物的数量等于耐久度时，会发生另一种棘手的情况。```
4 1
1 2 5 8
2 5
```强力的怪物有`5`和`8`。 它们正好消耗了两点耐久度，之后就没有耐久度了，但是已经没有强大的怪物可以攻击了。 只剩下较弱的怪物，因此预期伤害为`1+2=3`。 盾牌破裂后，对每只怪物一视同仁，那就太过分了。 

重复也很重要。```
3 1
7 7 7
1 7
```恰好一只怪物会消耗耐久度，而另外两只则会造成伤害。 预期伤害总是`14`，而不是不同值的平均值。 正确排序和使用多重性可以避免这种错误。 

## 方法

 蛮力视图很简单。 对于一个查询，枚举所有`n!`命令、模拟战斗并平均所造成的损失。 这在数学上是正确的，但成本却高得离谱。 

甚至用概率计算代替排列枚举并独立处理每个查询`O(n)`太慢了。 和`2·10^5`查询，这大致变成`4·10^10`运营。 

关键的观察是，只有具有至少力量的怪物`b`影响耐用性。 假设有`k`这样的怪物。 如果`k<a`，护盾永远不会破裂，答案为零。 

认为`k≥a`。 考虑一只强大的怪物。 其中`k`强大的怪物，所有相对顺序的可能性都是相同的。 盾牌首先幸存下来`a`强大的怪物，然后立即打破。 特定的强力怪物在该位置后出现时会造成伤害`a`其中`k`怪物。 

该事件发生的概率等于$$\frac{k-a}{k}.$$弱小的怪物永远不会消耗耐久度。 一旦护盾耗尽`a`强怪物，随后出现的每一个弱怪物都会造成伤害。 由于弱怪物与强怪物随机交错，因此它们在断点后出现的概率为$$\frac{k-a+1}{k+1}.$$这些概率仅取决于`k`，而不是个人优势。 对强度进行排序并构建前缀和后，我们可以在对数时间内获得强强度和弱强度之和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 最佳| O((n+m) log n) | O((n+m) log n) | O(n) | 已接受 |

 ## 算法演练

 1.对怪物强度进行排序。 
2. 构建前缀和，以便可以在恒定时间内获得任何后缀或前缀的总和。 
3. 查询`(a,b)`，二分查找第一个值至少为`b`。 
4.让`k`至少为具有实力的怪物数量`b`。 

这些正是消耗耐久的怪物。 
5. 如果`k<a`， 输出`0`。 

护盾的耐久度永远不会为零。 
6. 计算强怪物的总和，记为`Sstrong`，以及弱怪物的总和，表示为`Sweak`。 
7.每一个强大的怪物都有概率贡献`(k-a)/k`。 

他们的预期贡献等于$$S_{strong}\cdot\frac{k-a}{k}.$$1.每个弱怪都有概率贡献`(k-a+1)/(k+1)`。 

他们的预期贡献等于$$S_{weak}\cdot\frac{k-a+1}{k+1}.$$1. 将两个贡献相加并对所有内容取模`998244353`。 

### 为什么它有效

 在强大的怪物中，只有它们的相对顺序对耐久消耗很重要。 正是第一个`a`强大的怪物被阻挡，而剩下的`k-a`护盾破损后，强大的怪物会攻击。 对称性赋予每个强大怪物的概率`(k-a)/k`。 

断点立即出现在`a`第强大的怪物。 弱小的怪物同样有可能占据任何一个`k+1`强大怪物周围的缝隙。 有`k-a+1`断点后的间隙，给出概率`(k-a+1)/(k+1)`。 将所有怪物的这些独立期望相加即可得出正确的预期伤害。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
d = list(map(int, input().split()))

d.sort()

pref = [0]
for x in d:
    pref.append(pref[-1] + x)

inv = [1] * (n + 2)
for i in range(2, n + 2):
    inv[i] = pow(i, MOD - 2, MOD)

total_sum = pref[n]

ans = []

for _ in range(m):
    a, b = map(int, input().split())

    pos = bisect_left(d, b)
    k = n - pos

    if k < a:
        ans.append("0")
        continue

    strong_sum = total_sum - pref[pos]
    weak_sum = pref[pos]

    p_strong = (k - a) * inv[k] % MOD
    p_weak = (k - a + 1) * inv[k + 1] % MOD

    res = (
        strong_sum % MOD * p_strong
        + weak_sum % MOD * p_weak
    ) % MOD

    ans.append(str(res))

print("\n".join(ans))
```排序后的数组允许二分搜索来识别每个查询的强大怪物。 前缀总和给出了两组的总强度，无需扫描阵列。 

条件`k<a`必须在计算概率之前处理。 否则我们会错误地指定负分子。 

弱概率使用`k+1`在分母中，不是`k`。 这是最常见的错误来源。 一只弱小的怪物被插在强怪物周围的缝隙之中，而且比强怪物还多出一个缝隙。 

所有除法都是通过模逆来实现的，因为模数是素数。

 ## 边缘情况

 当没有足够强大的怪物时，```
3 1
1 2 10
2 100
```二分查找给出`k=0`。 自从`0<2`，算法立即输出`0`。 不执行概率计算。 

当强力怪物的数量等于耐久度时，```
4 1
1 2 5 8
2 5
```我们得到`k=2`。 强概率变为零，因为`k-a=0`。 弱怪物有概率贡献`1/3`，产生预期损害$$(1+2)\cdot\frac13=1.$$当所有值都相同时，```
3 1
7 7 7
1 7
```所有怪物都属于强者群体。 这里`k=3`，强和是`21`，每个怪物贡献的概率`2/3`。 预期伤害等于`14`。 排序会保留所有副本，因此可以自然地处理重复的强度。
