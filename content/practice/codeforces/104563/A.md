 ## 解决方案
 ## 问题理解

 我们得到一串大写字母。 我们一次显示一个字符，并且在每一步中，我们都可以在不断增长的字符串的前面或后面插入新字符。 处理完所有字符后，我们得到最终的单词。 前面或后面插入的不同选择会产生不同的最终字符串。 

任务不是模拟所有可能的结果。 相反，我们必须在遵守该规则的所有结构中确定字典顺序上可能最大的最终字符串。 这就是“胜利的硬道理”。 

每个测试用例长度最多为 1000 的约束立即排除了枚举所有 2^n 种可能性的任何尝试。 即使对于 15 左右的 n，暴力破解也几乎不起作用，而对于 1000 则更是不可能。 我们需要一个避免分支的确定性贪婪构造。 

一个微妙的点是每个字符必须只使用一次，并且其相对顺序仅部分受到插入选择的限制。 天真的直觉可能会建议排序或反转，但插入限制会创建结构化依赖关系：每个字符仅决定它最终是否更接近最终字符串的左边界或右边界。 

一个常见的失败案例来自于在没有预见未来的情况下在本地做出的贪婪的左右决策。 例如，给定像“BAA…”这样的前缀，将早期的字符放在前面可能看起来很有用，但后来的较大字符可能会使该选择全局无效。 正确的解决方案必须基于全局字典结构，而不是逐步的局部增益。 

## 方法

 蛮力观点很简单。 对于每个字符，分为两个选择，将其放置在前面或后面，并收集所有结果字符串。 这会产生 2^n 个字符串。 每个字符串的构造成本为 O(n)，因此总复杂度为 O(n·2^n)。 对于超过 25 的 n 来说这已经太大了，并且对于 n = 1000 来说完全不可行。 

关键的观察是，我们不需要跟踪所有结构，只需要跟踪字典比较下的最佳最终排序。 该操作的结构表明每个字符都被有效地插入到类似双端队列的结构中，并且最终结果取决于可以贪婪地确定的一系列决策。 

关键思想是通过维护两端来模拟最终的字符串结构，并始终根据它与当前最佳选择方向的比较来决定每个字符的放置位置。 我们不是仅根据当前字符贪婪地提交，而是确保决策与按字典顺序最大化最终字符串一致，这导致了一种贪婪策略，该策略比较已构建字符串当前末尾的字符。 

这将问题从指数分支简化为具有 O(n) 操作的单遍构造。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n·2^n) | O(n·2^n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们使用结果字符串将答案增量构建为类似双端队列的结构。 

1. 初始化一个空的结果结构。 

我们将通过在前面或后面插入字符来构建最终的字符串。 
2. 从左到右处理输入字符串。 

每个角色必须在到达后立即放置，因此我们决定其最终位置，而无需重新考虑之前的决定。 
3.对于每个角色，将其与当前最佳的“前边界”策略进行比较。

我们不是直接贪婪地决定前面或后面，而是将字符与当前结果的第一个字符进行比较。 这种比较反映了将其推到前面是否比将其推到后面更能改善词典顺序。 
4、如果当前字符大于等于结果的第一个字符，则放在前面； 否则将其放在后面。 

该规则确保较大的字符尽可能早地（左侧）保留在最终字符串中，这正是最大化字典顺序的原因。 
5. 继续，直到放置完所有字符。 

### 为什么它有效

 该算法保持贪婪不变量：在任何步骤，当前结果都是在字典序最大化的情况下处理的前缀的最佳后缀排序。 任何大于或等于当前领先字符的字符都应该主导较早的位置，因为将其放在前面会产生按字典顺序更大的前缀，而不会牺牲未来的最优性。 如果它较小，则将其推到后面可以避免污染前缀并在前面保留更强的字符。 

这个不变量确保以后的决策不能追溯性地改进前缀排序，因为每一步都根据字典优先级锁定字符的相对主导地位。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(s):
    res = []
    for ch in s:
        if not res:
            res.append(ch)
            continue
        if ch >= res[0]:
            res.insert(0, ch)
        else:
            res.append(ch)
    return "".join(res)

def main():
    t = int(input())
    for tc in range(1, t + 1):
        s = input().strip()
        print(f"Case #{tc}: {solve_case(s)}")

if __name__ == "__main__":
    main()
```该解决方案将结果维护为 Python 列表，以允许高效的追加操作。 前置插入用途`insert(0, x)`，其时间复杂度为 O(n)，但由于每个字符插入一次且 n ≤ 1000，因此在实践中对于 100 个测试用例来说仍然足够快。 

关键的实现细节是我们与`res[0]`，当前前沿。 此单一比较对优先考虑前缀最大化和后缀累积之间的贪婪决策边界进行编码。

 ## 边缘情况

 对于像“Z”这样的单个字符，算法直接初始化结果并输出“Z”，因为不需要比较，并且插入决策不会影响结果。 

对于像“AAAA”这样的统一字符串，每一步的每个字符都等于当前的前面。 该规则重复地将每个新字符放在前面，但由于所有字符都相同，因此最终字符串保持不变。 

对于像“ABCDEF”这样的严格递增的字符串，每个新字符都大于或等于当前前面的字符，因此每个字符都会插入到前面。 这有效地反转了字符串，产生“FEDCBA”，这与在允许的操作下最大化字典顺序是一致的。
