 ## 解决方案
 ## 问题理解

 我们需要计算有多少个非负整数对`(a, b)`同时满足两个方程：

 -`a² + b = n`-`a + b² = m`输入给出两个目标值`n`和`m`。 我们的工作是测试可能的值`a`和`b`并计算有多少对使两个方程同时成立。 

限制非常小。 两个都`n`和`m`至多是`1000`，这立即表明暴力破解是可行的。 甚至检查每一对`(a, b)`从`0`到`1000`只需要大约一百万次迭代，这在 Python 的 2 秒限制内是微不足道的。 

更有趣的部分是认识到方程对搜索空间的限制有多严格。 自从`a² ≤ n`，值`a`永远不能超过`√n`。 相似地，`b² ≤ m`， 所以`b`永远不能超过`√m`。 这一观察大大减少了搜索量。 

有一些容易被忽略的边缘情况。 

一种微妙的情况是一个变量变为零。 例如：```
9 3
```有效对是`(3, 0)`因为：

-`3² + 0 = 9`-`3 + 0² = 3`一个粗心的实现，从以下位置开始循环`1`而不是`0`会错误地错过这个答案。 

另一个棘手的情况是根本不存在配对。 例如：```
1 1
```尝试所有可能性都没有给出有效的对。 一些不正确的解决方案独立求解每个方程并意外地组合了不兼容的值。 

当多个候选值单独满足一个方程但不能同时满足一个方程时，就会出现一种不同的边缘情况。 例如：```
10 34
```这对`(3, 1)`满足：

 -`3² + 1 = 10`-`3 + 1² = 4`第一个方程有效，但第二个方程无效。 该算法必须始终同时验证两个方程。 

## 方法

 最直接的方法是尝试所有可能的配对`(a, b)`并检查两个方程是否成立。 

由于两个变量都是非负的并且有界`1000`，我们可以迭代：

 -`a`从`0`到`1000`-`b`从`0`到`1000`对于每一对，计算：

 -`a² + b`-`a + b²`如果两者匹配`n`和`m`，增加答案。 

这种暴力解决方案是正确的，因为它明确地检查每个可能的候选对。 什么都不能错过。 

问题是效率。 完整搜索大致执行：```
1001 × 1001 ≈ 1,000,000
```检查。 即使对于给定的约束，这仍然可以轻松通过，但我们可以通过小的观察做得更好。 

从第一个方程：```
a² + b = n
```自从`b ≥ 0`，我们知道：```
a² ≤ n
```所以`a`只需要达到`√n`。 

同样，来自：```
a + b² = m
```我们得到：```
b² ≤ m
```所以`b`只需要达到`√m`。 

这将搜索变成了对实际候选值的非常小的蛮力，而不是整个搜索`[0, 1000]`范围。 

另一个有用的观察是，一旦`a`是固定的，第一个方程唯一确定`b`:```
b = n - a²
```所以我们甚至不需要嵌套循环。 我们可以迭代`a`，计算唯一可能的`b`，并验证第二个方程。 

这将算法降低到线性复杂度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(1000²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(√n) | O(√n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整数`n`和`m`。 
2. 初始化`answer = 0`。 
3. 迭代`a`从`0`尽管`a² ≤ n`。 

任何较大的值`a`会立即违反第一个方程，因为`b`不能为负数。 
4. 计算：```
b = n - a²
```这是唯一可能的值`b`可以满足电流的第一个方程`a`。 
5. 检查第二个方程是否也成立：```
a + b² == m
```如果为真，则增加`answer`。 
6.循环结束后，打印`answer`。 

### 为什么它有效

 对于每个非负整数`a`和`a² ≤ n`，第一个方程准确确定了一个候选值`b`。 没有其他`b`可以满足：```
a² + b = n
```因此，该算法仅检查每个可能的有效对一次。 第二个方程充当过滤器，仅保留满足整个系统的对。 由于在此过程中必须出现每个可行对，因此最终计数是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

answer = 0

a = 0
while a * a <= n:
    b = n - a * a

    if a + b * b == m:
        answer += 1

    a += 1

print(answer)
```该循环仅迭代可行值`a`。 条件`a * a <= n`保证`b = n - a²`仍为非负数。 

该行：```
b = n - a * a
```直接来自重新排列第一个方程。 这完全避免了嵌套循环。 

第二个方程：```
a + b * b == m
```对于每个候选对只检查一次。 

一个微妙的细节是使用乘法而不是平方根。 使用浮点平方根计算界限可能会引入舍入问题。 循环条件`a * a <= n`完全避免了这个问题。 

另一个小的实现细节是`b`始终是整数，因为`n`和`a²`是整数。 不需要额外的验证。

import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())

    answer = 0

    a = 0
    while a * a <= n:
        b = n - a * a

        if a + b * b == m:
            answer += 1

        a += 1

    print(answer)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)

    output = sys.stdout.getvalue()

    sys.stdout = backup_stdout

 ## 边缘情况

 考虑输入：```
9 3
```该算法尝试：

 -`a = 0`,`b = 9`-`a = 1`,`b = 8`-`a = 2`,`b = 5`-`a = 3`,`b = 0`只有最后一对满足第二个方程。 由于循环开始于`0`，解与`b = 0`已正确包含在内。 

现在看：```
2 2
```该算法检查：

 -`a = 0`,`b = 2`-`a = 1`,`b = 1`都不满足`a + b² = 2`，所以答案仍然是`0`。 这证实了该算法不会错误地计算仅满足一个方程的对。 

最后，考虑：```
1 1
```执行发现：

 -`(0, 1)`-`(1, 0)`两者都是独立计算的，因为循环会检查每个可行的`a`。 这验证了对称解的处理是否正确。
