 ## 解决方案
 ## 问题理解

 我们有两个二进制字符串。 

第一个字符串`s`不是我们必须直接输出的时间表。 相反，它充当多组字符。 我们可以按任意顺序重新排列其符号，但符号总数`'0'`字符和`'1'`字符必须保持完全相同。 

第二串`t`是一个目标模式。 在所有可能的重新排列中`s`，我们想要一个能够最大化次数的`t`显示为子字符串。 

输出是任何重新排列`s`达到这个最大值。 

关键的限制是只能改变顺序。 如果`s`包含 100 个 0 和 200 个 1，答案也必须恰好包含 100 个 0 和 200 个 1。 

两个字符串的长度都可以达到500,000。 在这种规模下，二次算法是完全不可能的。 甚至一个$O(n^2)$扫描需要大约$2.5 \times 10^{11}$最坏情况下的操作。 我们需要一个与总输入大小基本呈线性的解决方案。 

主要困难在于，最大化子字符串的出现次数与贪婪地放置子字符串的副本不同。`t`独立。 不同的事件可能会重叠。 事实上，重叠正是使我们能够将更多出现次数放入固定数量的字符中的原因。 

考虑：```
t = 10101
```下一个事件可以在前一个事件完全结束之前开始，因为后缀`"101"`也是一个前缀。 忽略重叠会浪费字符并减少出现次数。 

另一个简单的错误是在构建一个副本后停止`t`。 

例子：```
s = 11110000
t = 1100
```一个简单的解决方案可能会放置一个副本：```
1100 + remaining
```但如果资源允许，我们应该尽可能继续添加重叠副本。 

当我们甚至无法构建单个副本时，就会出现第三种边缘情况`t`。 

例子：```
s = 1111
t = 000
```由于没有可用的零，因此每种排列的出现次数为零。 正确答案是使用所有字符的任何字符串`s`， 例如：```
1111
```尝试强制部分复制`t`会违反字符计数。 

## 方法

 蛮力观点是考虑字符的每一个排列`s`,数数有多少次`t`出现，然后选择最好的一个。 

这显然是正确的，因为它检查每个有效的时间表。 不幸的是，如果`|s| = 500000`，排列的数量是天文数字，完全不可行。 

一个更现实的暴力想法是重复附加完整的副本`t`每当剩下足够的零和一时。 这最大化了非重叠发生的数量。 

缺陷是允许事件重叠。 认为：```
t = 10101
```后缀`"101"`等于前缀`"101"`。 

写完一个事件后：```
10101
```我们只需要附加`"01"`创建另一个事件：```
1010101
```重叠节省了三个字符。 由于我们的零和一的供应是有限的，保存字符意味着适合更多的出现。 

这一观察直接指向前缀功能或 KMP 思维。 如果我们知道最长的正确前缀`t`这也是一个后缀，那么在写入一次后我们不需要从头开始。 我们只能附加不重叠的尾部。 

让```
k = longest border length of t
```然后：```
tail = t[k:]
```第一个副本之后`t`，每个额外的出现都可以通过附加来创建`tail`。 

由于每个附加的尾部都会创建一个新的出现，同时消耗尽可能少的字符，因此重复附加尾部始终是最佳选择。 

算法变为：

 1. 计算可用的 0 和 1`s`。 
2.检查是否有一份`t`可以形成。 
3. 如果不是，则任意输出所有字符。 
4. 否则放置一份副本`t`。 
5. 计算最长边界`t`使用 KMP。 
6. 在字符数允许的情况下，重复附加不重叠的尾部。 
7. 附加所有剩余未使用的字符。 

一切都是线性的，因为 KMP 计算边界$O(|t|)$时间。

 ## 算法演练

 1. 计算可用的 0 和 1 的数量`s`。 
2. 计算一份完整副本所需的 0 和 1 的数量`t`。 
3.如果`s`不包含足够的零或一来构建甚至一份副本`t`，任何事件都不可能存在。 以任意顺序输出所有剩余字符并停止。 
4. 计算 KMP 前缀函数`t`。 
5.让`k = pi[-1]`。 这是最长的正确前缀的长度`t`这也是一个后缀。 
6. 附上一份完整的副本`t`到答案并从可用的供应中减去其字符数。 
7. 定义：```
tail = t[k:]
```这正是在重用重叠时必须附加的部分以再创建一次。 
8. 计算其中包含的 0 和 1`tail`。 
9. 虽然还剩下足够的字符来写另一份副本`tail`，追加它并减去它的计数。 
10. 无法添加更多尾部后，附加所有剩余的零，然后附加所有剩余的。 

### 为什么它有效

 第一次出现后`t`已经写好了，未来的每一个事件都应该尽可能地与前一个事件重叠。 两个连续副本之间的最大合法重叠恰好是最长的边界`t`。 

任何较小的重叠都会消耗更多的字符，同时创建相同数量的出现次数。 由于零和一的供应是固定的，每次额外出现消耗更少的字符永远不会更糟。 

KMP 边界提供了最大可能的重叠。 因此每个附加`tail`以尽可能小的字符成本创建一个新的出现。 贪婪地重复此操作可以最大化适合可用计数的出现次数。 再来一次`tail`无法提供，没有替代结构可以创建额外的出现，因为每个出现至少需要与尾部一样多的新字符。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
t = input().strip()

cnt0 = s.count('0')
cnt1 = len(s) - cnt0

need0 = t.count('0')
need1 = len(t) - need0

if cnt0 < need0 or cnt1 < need1:
    print('0' * cnt0 + '1' * cnt1)
    sys.exit()

m = len(t)

pi = [0] * m
for i in range(1, m):
    j = pi[i - 1]
    while j > 0 and t[i] != t[j]:
        j = pi[j - 1]
    if t[i] == t[j]:
        j += 1
    pi[i] = j

k = pi[-1]
tail = t[k:]

tail0 = tail.count('0')
tail1 = len(tail) - tail0

ans = [t]

cnt0 -= need0
cnt1 -= need1

while cnt0 >= tail0 and cnt1 >= tail1:
    ans.append(tail)
    cnt0 -= tail0
    cnt1 -= tail1

ans.append('0' * cnt0)
ans.append('1' * cnt1)

print(''.join(ans))
```第一部分计算可用资源并检查是否有一个副本`t`是可能的。 如果不是，则每种排列都会产生零次出现，因此任何有效的重新排列都是最佳的。 

前缀函数计算是标准 KMP。 价值`pi[-1]`给出整个字符串的最长边框。 

微妙的想法是构建`tail = t[k:]`。 如果边界长度是`k`，那么第一个`k`下一个出现的字符已经作为前一个出现的后缀出现。 仅必须附加剩余的后缀。 

循环附加尽可能多的尾部。 每次迭代都会创建一个新的出现，同时花费尽可能少的字符数。 

最后，附加剩余的零和一。 到那时，就不能再发生任何事情了，因为我们已经未能通过另一条尾巴的承受能力测试。

import sys, io

def solve():
    s = input().strip()
    t = input().strip()

    cnt0 = s.count('0')
    cnt1 = len(s) - cnt0

    need0 = t.count('0')
    need1 = len(t) - need0

    if cnt0 < need0 or cnt1 < need1:
        print('0' * cnt0 + '1' * cnt1)

    pi = [0] * len(t)
    for i in range(1, len(t)):
        j = pi[i - 1]

            j = pi[j - 1]
        if t[i] == t[j]:
            j += 1
        pi[i] = j

    k = pi[-1]
    tail = t[k:]

    ans = [t]

    cnt0 -= need0
    cnt1 -= need1

    tail0 = tail.count('0')
    tail1 = len(tail) - tail0

    while cnt0 >= tail0 and cnt1 >= tail1:
        ans.append(tail)
        cnt0 -= tail0
        cnt1 -= tail1

    ans.append('0' * cnt0)
    ans.append('1' * cnt1)

    print(''.join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    global input
    input = sys.stdin.readline

    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old
    return out.getvalue().strip()

 ## 边缘情况

 ### 无法形成第一次出现

 输入：```
s = 1111
t = 000
```可用计数：```
zeros = 0
ones = 4
```必需的：```
zeros = 3
ones = 0
```第一次出现是不可能的。 该算法立即输出所有剩余字符：```
1111
```任何排列的出现次数为零，因此这是最佳的。 

### 带有大边框的目标

 输入：```
s = 11110000
t = 1010
```最长的边框长度为 2。```
1010
  10
```该算法仅重复追加`"10"`而不是另一个完整的`"1010"`。 这会从相同的字符源中产生更多的出现。 

### 边框长度为零

 输入：```
s = 101101
t = 110
```最长边界为零，因此：```
tail = t
```不可能有重叠。 该算法自然会退化为重复放置完整的副本`t`，当不存在重叠时，这正是最佳的。 

### 单字符目标

 输入：```
s = 00111
t = 1
```前缀函数值为零，尾部函数值为`"1"`。 

该算法放置了尽可能多的`'1'`首先尽可能的字符：```
111
```然后附加剩余的零：```
11100
```每一个`'1'`位置形成一个事件，这是可实现的最大计数。
