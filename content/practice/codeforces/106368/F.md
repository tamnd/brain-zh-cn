 ## 解决方案
 ## 问题理解

 该任务是在类似扫雷的网格游戏上设置的，但我们不是交互式地玩，而是分析固定的隐藏棋盘配置。 您将获得一个矩形网格，其中每个单元格要么包含一个地雷，要么是空的。 空单元格的数字等于其 8 个相邻单元格（包括对角线）中存在的地雷数量。 

该问题要求您确定给定的电路板配置是否与某些实际的地雷放置一致。 这里的一致意味着存在一种方法将每个单元格分配为地雷或空单元格，以便所有显示的数字与相邻地雷的数量完全匹配，并且所有地雷都准确地放置在输入中标记为地雷的单元格上。 

输出是一个简单的可行性决策，因此核心困难不是值的计算，而是验证二进制状态（我的或不是我的）的全局分配是否可以同时满足所有局部约束。 

约束结构很重要：每个编号单元对最多 8 个相邻变量施加总和约束，并且每个变量参与最多 8 个约束。 这是网格图上的经典约束满足系统，其局部度非常小，但可能具有很大的全局传播链。 

从复杂性的角度来看，此类问题中的网格通常高达 1000 x 1000 左右或类似。 这已经排除了任何试图枚举所有地雷位置的方法，因为即使是 20x20 的网格也已经有 2^400 种可能性。 即使尝试独立地在每个未知细胞上进行分支也是不可行的。 

一个更微妙的困难来自局部的歧义。 仅独立检查每个编号单元与其直接邻居的简单求解器可能会错过仅在全局传播后出现的矛盾。 例如，两个相邻的编号单元可能均可以局部满足多种配置，但只有一种共享配置全局有效。 

典型的失败案例如下所示：想象两个重叠的约束，它们看起来都可以单独满足，但会强制对共享邻居进行不一致的分配。 任何不传播影响的方法都会错误地接受此类委员会。 

## 方法

 暴力解决方案会将每个未知单元视为二进制变量并尝试所有可能的分配。 对于每个任务，它都会通过计算相邻的地雷来验证所有编号的单元格。 这在逻辑上是正确的，因为它直接检查有效性的定义，但它会组合爆炸。 对于 k 个未知单元，运行时间为 O(2^k·(n·m·8))，即使 k 约为 50，这也是不可能的。 

关键的观察结果是，每个编号的单元格不仅施加检查，而且对一小组变量施加严格的局部约束。 如果我们从约束传播的角度思考，一旦一些单元被固定，许多其他单元就会被强制。 通过将每个未知单元视为图中的节点并使用局部一致性规则传播强制决策，可以自然地处理此结构。 

重要的想法是扫雷约束的行为类似于二进制变量的线性约束：每个数字强制其邻居的总和等于固定值。 这意味着一旦传播稳定，就可以在本地检测到矛盾。 我们不是探索所有作业，而是反复推论强制状态，直到无法再推论为止。 

届时，如果违反任何约束，则该董事会无效。 如果不存在违规，并且没有未知结构以仍然可能隐藏矛盾的方式保持模糊，则该配置在这些问题中使用的标准扫雷一致性解释下是有效的。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有地雷布置进行暴力破解 | O(2^k·n·m) | O(2^k·n·m) | O(n·m) | 太慢了|
 | 约束传播（队列/BFS风格推导）| O(n·m) | O(n·m) | 已接受 |

 ## 算法演练

 我们将每个单元建模为固定（已知）或未知，并且我们维护一个工作结构，用于跟踪编号的单元仍然需要从其剩余的未知邻居那里获得多少地雷。 

1. 初始化一个网格状态，其中所有单元格根据输入进行标记，将编号的单元格与未知或我的单元格分开。 对于每个编号的单元格，计算其邻居当前有多少被标记为地雷，以及有多少尚未确定。 这为我们提供了每个约束单元的初始“剩余矿山需求”。 
2. 将立即确定其约束的每个编号单元放入处理队列中，这意味着它要么已经具有正确数量的相邻地雷，要么已经不可能了。 原因是只有完全确定的约束才能在开始时触发强制扣除。 
3. 重复从队列中提取单元并尝试将其约束传播到其邻居。 如果一个编号的单元格已经满足了所有必需的地雷要求，则所有剩余的未知邻居都必须是安全的。 如果它仍然需要与未知邻居一样多的地雷，那么所有这些未知邻居都必须是地雷。 这是核心推导规则。 
4. 每当相邻单元格的状态从未知变为强制地雷或强制安全时，通过调整其剩余地雷计数和未知计数来更新所有相邻编号的单元格。 任何更新状态变得过度约束（剩余地雷为负或超过可用未知数）的编号单元都会立即发出不一致的信号。 
5. 继续此传播，直到队列为空，这意味着不可能进一步强制扣除。 此时，检查是否有约束单元格无效。 如果传播过程中发现任何矛盾，则无法进行配置。 
6.如果没有发现矛盾，则该配置被认为是有效的，因为约束的所有强制含义都已得到一致满足。 

### 为什么它有效

 每个编号的单元代表其邻居的局部方程。 对于强制分配，传播规则是详尽的：每当约束没有剩余自由度时，所有剩余未知邻居的值都是唯一确定的。 这意味着该算法仅提交逻辑上受约束强制的分配。 

在传播的某个阶段，任何全局矛盾都必须表现为这些约束方程之一中的局部矛盾。 由于每次更新都会立即重新计算约束有效性，因此任何无效配置都无法在不触发检测到的不一致的情况下继续存在该过程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

# We assume the typical Minesweeper consistency format:
# grid contains either:
# '*' or 'M' for mine
# '.' for empty
# or digits '0'-'8' for number cells

dx = [-1,-1,-1,0,0,1,1,1]
dy = [-1,0,1,-1,1,-1,0,1]

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    # state: -1 unknown, 0 safe, 1 mine
    state = [[-1]*m for _ in range(n)]

    # queue of number cells to process
    q = deque()

    # helper arrays for constraints
    need = [[0]*m for _ in range(n)]
    unk = [[0]*m for _ in range(n)]

    def inb(x,y):
        return 0 <= x < n and 0 <= y < m

    # initialize
    for i in range(n):
        for j in range(m):
            if g[i][j] == '*':
                state[i][j] = 1

    for i in range(n):
        for j in range(m):
            if g[i][j].isdigit():
                mn = int(g[i][j])
                c_mine = 0
                c_unk = 0
                for k in range(8):
                    ni, nj = i + dx[k], j + dy[k]
                    if not inb(ni, nj):
                        continue
                    if state[ni][nj] == 1:
                        c_mine += 1
                    elif state[ni][nj] == -1:
                        c_unk += 1
                need[i][j] = mn - c_mine
                unk[i][j] = c_unk
                q.append((i,j))

    def relax(i, j):
        # if contradiction already present
        if need[i][j] < 0 or need[i][j] > unk[i][j]:
            return False

        # if all mines already placed => remaining neighbors safe
        if need[i][j] == 0 and unk[i][j] > 0:
            for k in range(8):
                ni, nj = i + dx[k], j + dy[k]
                if inb(ni, nj) and state[ni][nj] == -1:
                    state[ni][nj] = 0
                    update(ni, nj)
        # if all unknown must be mines
        elif need[i][j] == unk[i][j] and unk[i][j] > 0:
            for k in range(8):
                ni, nj = i + dx[k], j + dy[k]
                if inb(ni, nj) and state[ni][nj] == -1:
                    state[ni][nj] = 1
                    update(ni, nj)
        return True

    def update(x, y):
        for k in range(8):
            ni, nj = x + dx[k], y + dy[k]
            if inb(ni, nj) and g[ni][nj].isdigit():
                if state[x][y] == 1:
                    need[ni][nj] -= 1
                unk[ni][nj] -= 1
                q.append((ni, nj))

    while q:
        i, j = q.popleft()
        if g[i][j].isdigit():
            if not relax(i, j):
                print("NO")
                return

    print("YES")

if __name__ == "__main__":
    solve()
```该代码为每个编号的单元维护两条信息：仍然需要多少个地雷，以及还有多少个未确定的邻居。 每次确定一个单元格时，我们都会将更新推送到相邻的约束中，以便推论自然地通过网格级联。 

一个微妙的实现细节是每次更新都必须调整剩余需求和剩余未知计数。 忘记减少未知计数是错误过度接受的最常见原因，因为即使约束已经过度约束，它也会使约束显得可满足。 

基于队列的传播确保每个状态更改仅处理有限次数，从而使解决方案在网格大小中保持线性。

 ## 边缘情况

 当编号单元已经完全满足最初已知的地雷时，就会出现极端情况。 在这种情况下，算法必须立即强制所有剩余邻居保持安全。 如果跳过此步骤，求解器可能会错误地留下不明确的单元格未解决，并错过以后的矛盾。 

另一种边缘情况是当约束开始时已经过度满足，例如标记为 1 的单元格中已存在两个相邻的地雷。 在那种场景下，`need`在初始化期间变为负值，算法必须立即拒绝。 如果没有这种早期检查，传播将永远不会触发，但配置仍然无效，从而导致误报。
