 ## 解决方案
 ## 问题理解

 每辆公交车都以相同的速度沿道路行驶`x`。 公共汽车`i`从位置开始`s_i`在某个时间`0`，向右移动，到达后消失`t_i`。 

一个人从职位开始`p`。 他们可以快速行走`y`， 在哪里`y < x`。 每当一个人和一辆公共汽车同时占据同一位置时，该人就可以立即登上该公共汽车。 在公共汽车上时，他们移动速度很快`x`，他们可以随时离开公共汽车。 

对于每个起始位置`p_i`，我们必须计算到达位置处的路终点所需的最短可能时间`ℓ`。 

第一个观察结果是，所有运动都发生在一条线路上，并且所有公交车都具有相同的速度。 约束条件很大：最多`2 · 10^5`公共汽车和`2 · 10^5`查询。 任何检查每个人的所有公交车的算法都需要大约`4 · 10^10`的操作，这是完全不可行的。 我们需要一些接近的东西`O((n+m) log n)`。 

问题中最具欺骗性的部分是了解哪些总线传输实际上是可能的。 

考虑两辆巴士：```
bus A: 0 -> 10
bus B: 5 -> 20
```两者以相同的速度移动。 如果你在 A 路公交车上，你以后就不能再跳到 B 路公交车了，因为它们的距离永远保持不变。 相同的速度意味着公共汽车永远不会追上彼此。 

另一个微妙的案例是，一个人试图登上一辆在他们身后启动的公共汽车。```
x = 4, y = 1
bus: 0 -> 100
person: 10
```公共汽车比人快。 由于它是在人后面开始的，所以它最终可以追上。 相遇位置由相对速度确定，并且必须正确计算。 一个粗心的解决方案，只检查是否`s_i ≥ p`将错过这次有效的登机机会。 

第三个陷阱是假设乘坐公共汽车总是有益的。```
ℓ = 100
x = 10
y = 9

bus: 0 -> 1
person: 0
```公交车只载人一米就消失了。 直接步行几乎一样快。 最佳答案必须比较所有可能性，包括不登上任何公共汽车。 

这些观察结果表明，问题实际上在于评估独立总线机会，而不是传输顺序。 

## 方法

 暴力方法将单独处理每个人。 

对于给定的起始位置`p`，我们可以检查每辆公交车。 对于每辆公共汽车，我们确定该人是否可以在它消失之前遇到它。 如果可以召开会议，我们会计算到达该地点的最终时间`ℓ`。 答案是所有公交车和纯步行中最少的。 

这是正确的，因为每一个可行的策略都是从永远步行或登上第一辆公共汽车开始的。 不幸的是它需要`O(n)`每个查询的工作量，导致`O(nm)`总的复杂性。 当两个值都达到`2 · 10^5`，这变成了关于`4 · 10^10`检查。 

为了改进，我们需要了解单个总线的几何形状。 

假设一个人从位置开始`p`并登上巴士`(s,t)`。 

如果他们在某个时间相遇`τ`， 然后```
p + yτ = s + xτ
```这给出了```
τ = (p - s)/(x - y)
```只有在以下情况下才可以召开会议：`p ≥ s`，因为否则公交车已经在前面，并且比人走得更快。 

巴士抵达目的地后```
T = (t - s)/x
```分钟。 

因此可以登机 iff```
(p - s)/(x - y) ≤ (t - s)/x
```重新排列后：```
x p ≤ y s + (x - y) t
```这是关键的简化。 

定义```
R = y s + (x - y) t
```对于一个有职位的人来说`p`， 公共汽车`(s,t)`恰好在何时可达```
R ≥ x p
```条件仅取决于一个值`R`。 

现在计算使用该公共汽车的总行程时间。 

会议时间：```
τ = (p - s)/(x - y)
```上车后，留在巴士上直到巴士消失始终是最佳选择。 由于公交车比步行更快，早点出发只会增加剩余的出行时间。 

到达时间变为```
τ + (t - meeting_position)/x + (ℓ - t)/y
```替换会议位置并简化收益```
ℓ / y - p / (x - y)
    + s * x / (y(x-y))
    - t / y
```对于固定查询位置`p`，前两项是常数。 公交车仅贡献```
value(bus) =
s * x / (y(x-y))
- t / y
```因此每个查询都会询问：

 在所有巴士中```
R ≥ x p
```找到最小总线值。 

这成为一个一维离线问题。 巴士排序依据`R`。 按阈值对查询进行排序`x p`。 从大到小阈值扫描，同时保持所有总线中的最小总线值`R`足够大。 

每个查询的答案是```
min(
    walking_time,
    base(p) + best_bus_value
)
```在哪里```
walking_time = (ℓ - p)/y
base(p) = ℓ/y - p/(x-y)
```### 复杂性比较

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 最佳 | O((n+m) log n) | O((n+m) log n) | O(n+m) | 已接受 |

 ## 算法演练

 1. 每辆公交车`(s,t)`, 计算```
R = ys + (x-y)t
```和```
V = sx/(y(x-y)) - t/y
```2. 对所有总线进行排序`R`按降序排列。 
3.对于每个查询位置`p`，计算其阈值```
need = xp
```店铺`(need, index, p)`。 
4. 对所有查询进行排序`need`按降序排列。 
5. 从最大阈值到最小阈值扫描查询。 
6. 维护一个指向已排序总线列表的指针和一个变量`best`, 最小值`V`在所有已插入的总线中。 
7. 对于当前查询，插入每条总线```
R ≥ need
```因为这些公交车可以从以下位置到达`p`。 
8. 计算仅步行时间```
walk = (ℓ-p)/y
```9. 如果至少存在一条可达总线，则计算```
bus_answer =
ℓ/y - p/(x-y) + best
```10. 查询答案为步行时间和乘车时间中的最小值。 
11. 将答案恢复为原始查询顺序并打印。 

### 为什么它有效

 关键特性是相同的总线速度消除了所有有用的传输。 一旦两辆公共汽车开始移动，它们的相对位置就永远不会改变。 一名乘客在最佳旅程中最多只能搭乘一辆公交车。 

对于固定总线，可达性条件精确地简化为```
R ≥ xp
```由此产生的行程时间简化为一个恒定的查询相关项加上一个恒定的总线相关项。 因此，每个查询都减少为选择具有最小总线相关值的可达总线。 

扫描过程总线在减少`R`。 处理阈值时`xp`，维护的集合恰好包含满足的总线`R ≥ xp`。 变量`best`是该集合中的最小巴士值，因此它会产生最佳的巴士辅助旅程。 直接步行的最低限度覆盖了没有公共汽车帮助的可能性。 因此每个答案都是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, L, x, y = map(int, input().split())

    buses = []
    d = x - y

    for _ in range(n):
        s, t = map(int, input().split())

        R = y * s + d * t
        V = s * x / (y * d) - t / y

        buses.append((R, V))

    queries = []
    for i in range(m):
        p = int(input())
        queries.append((x * p, i, p))

    buses.sort(reverse=True)
    queries.sort(reverse=True)

    ans = [0.0] * m

    ptr = 0
    best = float('inf')

    for need, idx, p in queries:
        while ptr < n and buses[ptr][0] >= need:
            best = min(best, buses[ptr][1])
            ptr += 1

        walk = (L - p) / y
        res = walk

        if best < float('inf'):
            bus_res = L / y - p / d + best
            res = min(res, bus_res)

        ans[idx] = res

    sys.stdout.write("\n".join(f"{v:.10f}" for v in ans))

if __name__ == "__main__":
    solve()
```第一部分将每条总线转换为两个派生量。`R`决定可达性，同时`V`捕获该巴士对最终行程时间的全部贡献。 

查询转化为阈值`xp`。 按降序对总线和查询进行排序后，可以使用标准扫描线。 随着阈值降低，可以到达更多总线，因此总线仅插入一次。 

变量`best`存储最小值`V`在所有当前可到达的巴士中。 这已经足够了，因为每个与查询相关的术语都独立于所选的总线。 

一个微妙的细节是使用`>=`插入总线时。 导出的条件正好是`R ≥ xp`，所以将其更改为`>`会错误地拒绝在公交车到达目的地时恰好发生的会议。 

另一个细节是所有计算都是使用浮点值执行的。 所需精度仅为`10^-6`，并且公式包含除法，因此双精度就足够了。

 ## 边缘情况

 考虑一辆在目的地无法到达的公共汽车：```
1 1 10 4 1
0 4
3
```这里```
R = 12
xp = 12
```当巴士到达指定位置时，该人正好与巴士相遇`4`。 导出的条件是`R ≥ xp`， 不是`R > xp`。 扫描插入此总线是因为允许相等。 严格的比较会错误地丢弃它。 

考虑一个人已经到达目的地：```
1 1 100 10 1
0 50
100
```步行时间为零。 该算法计算```
walk = (100 - 100)/1 = 0
```并在使用任何基于总线的选项获取最小值后立即返回零。 

考虑一辆在人前面出发的公共汽车：```
1 1 100 10 1
50 90
0
```公交车已经在前面了，而且行驶得更快。 导出的不等式失败是因为```
xp > R
```总线在扫描期间永远不会进入活动集。 答案变成纯粹的步行时间，这是正确的。 

考虑多条可达巴士：```
2 1 100 10 2
0 50
20 90
10
```两条总线都满足可达性条件。 扫描保持所有活动总线中的最小总线值。 由于无论选择哪条总线，每个与查询相关的项都是相同的，因此选择最小的存储值完全相当于单独评估每个可到达的总线并获取最佳结果。
