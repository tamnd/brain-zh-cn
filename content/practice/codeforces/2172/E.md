 ## 解决方案
 ## 问题理解

 我们被赋予了一个由基数的数字构建的非常小的“数字宇宙”。 基数始终是三种可能之一：两位数、三位数或四位数。 从它的数字中，我们生成每个不同的排列，并按递增的数字顺序对这些排列进行排序。 

然后每个测试用例给出两个索引，我们从这个排序列表中选择相应的两个排列。 任务是使用类似于公牛和奶牛的评分系统来比较这两个选定的数字：如果数字在值和位置上都匹配，则对 A 做出贡献；如果它在值上匹配但位于不同的位置，则对 B 做出贡献。 

输出只是 xAyB 形式的一对计数。 

就结构而言，约束非常小。 最大的情况只有 4 位数字，因此最多存在 24 种排列。 即使我们重新计算每个测试用例的所有内容，我们也会在几十个字符串的范围内进行持续的工作。 这立即消除了对优化技巧或渐近问题的任何需要。 任何枚举每个测试用例排列的解决方案都可以轻松满足最多 1000 个查询的时间限制。 

主要的微妙之处在于计数逻辑的正确性。 当数字重复或 B 重复计算已用于 A 匹配的数字时，幼稚的实现通常会失败。 即使输入大小很小，匹配规则的错误处理也会在边缘情况下产生错误的答案。 

一个典型的陷阱是将 B 视为“常见数字的计数减去 A”，而不仔细跟踪重数。 当数字重复或同一数字在不同位置多次出现时，这种情况就会中断。 

失败场景示例：

 输入：122 1 2

 排列：122、212、221

 比较 122 与 221 应给出 0A3B，而不是 3A0B 或计数错误的值。 不跟踪每个位置所使用的数字的粗心方法会导致匹配计数过高。 

## 方法

 暴力方法将显式生成基数数字的所有排列，对它们进行排序，然后直接获取第 j 个和第 k 个排列。 因为最大排列数是 4！ = 24，这是微不足道的。 检索两个字符串后，我们逐个比较 A 匹配项，然后使用频率表对 B 匹配项进行计数，并仔细减去 A 匹配项。 

这已经很容易通过，但仍然有一个更清晰的观察：因为排列集非常小并且由输入大小固定，所以我们可以为每个测试用例预先计算一次所有排列并立即重用它们。 真正的工作减少到对恒定大小的列表进行排序并为其建立索引。 

唯一重要的部分是正确计算 xA yB。 正确的方法是先通过扫描位置计算A。 然后，我们构建两个字符串中不匹配数字的频率计数，并计算 B 作为最小重叠的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 + 直接比较 | 每次测试 O(1) | O(1) | O(1) | 已接受 |
 | 预计算+频率匹配 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 将基数的数字提取到列表中。 数字是所有排列的唯一来源，因此一切都取决于这个多重集。 
2. 生成数字列表的所有排列。 由于列表大小最多为 4，因此最多会生成 24 个字符串。 
3. 将所有排列按数字顺序排序，将字符串转换为整数。 这定义了索引使用的全局排序。 
4. 选择第 j 个和第 k 个排列（1 索引）。 这些成为要比较的两个代码。 
5. 通过逐位置扫描两个字符串并计算精确匹配来计算 A。 这会捕获正确放置的数字。 
6. 通过首先构建两个字符串中数字的频率计数，然后减去 A 中已计数的贡献来计算 B。最终 B 是两个字符串中最小剩余频率的数字总和。 
7. 以要求的格式输出结果。 

为什么有效：每个数字匹配都属于两个类别之一，要么它已经固定在位置 (A)，要么它是一个移位的出现 (B)。 通过在计算频率之前删除 A 匹配项，我们可以防止重复计算。 由于排列保留相同的多组数字，因此频率比较完全捕获所有有效的 B 匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import permutations

def score(a, b):
    A = 0
    fa = [0] * 10
    fb = [0] * 10

    for x, y in zip(a, b):
        if x == y:
            A += 1
        else:
            fa[int(x)] += 1
            fb[int(y)] += 1

    B = 0
    for d in range(10):
        B += min(fa[d], fb[d])

    return A, B

def solve():
    t = int(input())
    for _ in range(t):
        n, j, k = input().split()
        j = int(j)
        k = int(k)

        digits = list(n)
        perms = sorted(set(permutations(digits)))

        perms = [''.join(p) for p in perms]

        a = perms[j - 1]
        b = perms[k - 1]

        A, B = score(a, b)
        print(f"{A}A{B}B")

if __name__ == "__main__":
    solve()
```该解决方案首先枚举数字列表的所有排列。 如果基数包含重复的数字，则使用集合可以删除重复项，这一点很重要，因为否则重复排列可能会改变索引并破坏第 j 个选择。 

排序后，我们将元组转换为字符串以便于比较。 索引很简单，因为问题是从 1 开始的。 

评分函数被清晰地分割：首先处理精确匹配，并将不匹配的数字累积到频率数组中。 这种分离至关重要，因为在计算 B 时不得重复使用 A 匹配。

import sys, io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    out = []

    def score(a, b):
        A = 0
        fa = [0] * 10
        fb = [0] * 10
        for x, y in zip(a, b):
            if x == y:
                A += 1
            else:
                fa[int(x)] += 1
                fb[int(y)] += 1
        B = sum(min(fa[i], fb[i]) for i in range(10))
        return f"{A}A{B}B"

    t = int(input())
    for _ in range(t):
        n, j, k = input().split()
        j = int(j); k = int(k)

        perms = sorted(set(permutations(n)))
        perms = [''.join(p) for p in perms]

        a = perms[j - 1]
        b = perms[k - 1]
        out.append(score(a, b))

    return "\n".join(out)

 ## 边缘情况

 当基数包含重复数字（例如 122 或 212）时，会出现微妙的边缘情况。在这些情况下，原始排列生成器会生成重复项，除非进行重复数据删除，这可能会改变索引。 例如，如果没有集合，122 可能会产生多个相同的字符串，导致 j 和 k 引用不正确的排列。 

该算法通过在排序之前将排列转换为集合来处理此问题。 对于输入 122 1 3，排列变为 {122, 212, 221}。 排序产生[122,212,221]。 选择索引 1 和 3 给出 122 和 221。然后评分正确地产生 1A2B。 

另一种边缘情况是 j 等于 k ​​时。 该算法仍然有效，因为 A 变为字符串的完整长度，而 B 变为零，因为不存在不匹配的数字。
