 ## 解决方案
 ## 问题理解

 给定一条笔直的街道，表示为从 0 到 L 的连续线段。沿着该线段，在整数坐标处放置了 n 个固定灯柱。 我们不能选择它们的位置，只能选择每个灯柱安装的灯泡类型。 

有 m 种可用的灯泡类型，每种类型都由一个参数定义：它在两个方向上发光的距离。 如果我们在 x 处的灯上安装一个范围为 l 的灯泡，则该灯将照亮从 x − l 到 x + l 的整个区间。 所有灯必须使用相同的灯泡类型，我们可以选择购买哪种类型。 

目标是确定给定类型中的最小灯泡范围，使所有照明间隔的联合能够完全覆盖 [0, L] 的每个点。 如果没有灯泡类型可以实现完全覆盖，则答案为 -1。 

约束 n, m ≤ 100000 立即排除了尝试每种灯泡类型并以二次方式重新计算覆盖范围的任何方法。 在最坏的情况下，简单的 O(nm) 模拟将导致大约 10^10 的间隔检查，这远远超出了实际限制。 甚至 O(mn log n) 也会根据常数变得严格，因此我们需要对每个候选对象进行线性或近线性检查，并结合灯泡类型的对数选择策略。 

问题的一个微妙方面是覆盖范围是连续的。 这意味着部分重叠很重要，并且检查区间的端点是否覆盖整数点是不够的。 例如，如果灯覆盖 [0, 5] 和 [6, 10]，即使两端“靠近”，也存在间隙。 正确的解决方案必须推理完整区间并集，而不是离散样本。 

另一个潜在的陷阱是假设拥有足够大的灯泡以容纳极端灯可以保证覆盖范围。 如果连续的灯位置之间存在较大间隙，则这是错误的。 例如，位于位置 0 和 10 且 L = 10 的灯需要 l = 5，但像 0、4、10 这样的配置在 l = 3 时仍然会失败，即使端点看起来合理。 

最后，很容易忘记必须显式覆盖左边界 0 和右边界 L。 0 附近的覆盖丢失尤其常见，因为这完全取决于最左边的灯是否到达足够远的左侧。 

## 方法

 一种简单的方法是独立测试每种灯泡类型。 对于固定范围 l，我们计算所有区间 [p_i − l, p_i + l] 的并集，并检查该并集是否覆盖 [0, L]。 执行此操作的标准方法是按起始点对间隔进行排序，并在跟踪最远覆盖点的同时贪婪地合并它们。 如果在任何时刻我们遇到当前覆盖结束后下一个间隔开始的间隙，则覆盖失败。 

此检查是正确的，并且由于排序间隔，每个灯泡类型的运行时间为 O(n log n)，如果我们重复使用预先排序的位置顺序，则运行时间为 O(n)。 然而，对所有 m 个灯泡类型执行此操作会导致 O(mn)，这对于 100000 x 100000 来说太大了。 

关键的观察结果是可行性在 l 中是单调的。 如果灯泡范围 l 足以覆盖街道，则任何更大的范围 l' > l 也足够，因为每个间隔只会扩展。 这种单调性使我们能够将问题视为对灯泡范围排序列表的二分搜索。 

我们首先对灯泡系列进行排序。 然后我们二分查找最小的索引，使得对应的范围可行。 每次可行性检查的运行时间复杂度为 O(n)，方法是扫描一次排序的灯位置并维护当前覆盖的段。 这将问题减少到 O((n + m) log m)，这很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个灯泡的暴力破解 | O(百万) | O(1) | O(1) | 太慢了 |
 | 排序+二分查找+线性检查 | O(n + m log m) | O(n + m log m) | O(n) | 已接受 |

 ## 算法演练

我们利用这样一个事实，即每种灯泡类型都会在每个灯位置周围引起对称扩展，并且随着半径的增加，覆盖范围变得更容易。 

### 1. 对灯位置进行排序

 我们对 p 进行排序，以便我们可以从左到右推理覆盖范围。 这保证了当我们按顺序处理灯时，它们的间隔的左端点也是不递减的。 

### 2. 定义固定范围 l 的可行性检查

 对于给定的 l，每个灯都会创建一个区间 [p_i − l, p_i + l]。 我们模拟合并这些间隔而不显式存储它们。 

我们保持一个可变的电流，代表街道上已经从 0 开始连续照明的最远点。 

### 3. 从左到右扫描灯

 对于按 p_i 递增顺序的每个灯 i，我们计算其间隔开始和结束。 如果 start > current，则覆盖范围存在间隙，因此此 l 立即失败。 否则，我们将 current 扩展到 max(current, end)。 

### 4. 验证全面覆盖

 处理完所有灯后，如果电流≥L，则覆盖整条街道。 否则，右端附近有一些未覆盖的部分。 

### 5. 对灯泡范围进行二分搜索

 我们对 m 个灯泡范围进行排序，并二分查找范围通过可行性检查的最小索引。 答案就是这个范围，如果没有效果则为-1。 

### 为什么它有效

 可行性检查相当于验证所有间隔的并集是否包含从 0 到 L 的连续路径。贪婪扫描之所以有效，是因为在任何点，我们对某个位置所能拥有的最佳覆盖范围仅由在该位置之前或开始的间隔中最远的间隔决定。 任何稍后开始的间隔都无法修复一旦存在的间隙，因此尽早失败是安全的。 l 中的单调性确保一旦某个值起作用，所有较大的值也起作用，从而使二分搜索有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_cover(p, L, l):
    current = 0
    for x in p:
        start = x - l
        end = x + l
        if start > current:
            return False
        if end > current:
            current = end
        if current >= L:
            return True
    return current >= L

def solve():
    n, m, L = map(int, input().split())
    p = list(map(int, input().split()))
    lvals = list(map(int, input().split()))

    p.sort()
    lvals.sort()

    lo, hi = 0, m - 1
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can_cover(p, L, lvals[mid]):
            ans = lvals[mid]
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对灯位置进行排序，以便间隔合并成为单个从左到右的扫描。 功能`can_cover`编码贪婪覆盖逻辑。 它跟踪当前连续照明的前缀，并在出现间隙时立即拒绝灯泡范围，从而避免不必要的工作。 

在排序的灯泡范围上执行二分搜索，并使用可行性函数测试每个中点。 这种结构至关重要，因为独立地重新计算每个灯泡的覆盖范围会太慢。 

一个常见的实施错误是忘记覆盖范围是连续的，而不是离散的。 支票`start > current`是检测真实未覆盖间隙的精确条件。 另一个微妙的点是提前终止`current >= L`，一旦实现全覆盖，就可以避免不必要的扫描。

 ## 边缘情况

 一个关键的边缘情况是当第一盏灯没有到达原点时。 例如，当 p = [5, 10] 且 L = 2（L = 20）时，第一个区间为 [3, 7]，而 [0, 3] 未被覆盖。 该算法正确地检测到了这一点，因为电流从 0 开始，第一次开始是 3，从而立即触发故障。 

另一种情况是覆盖最终失败。 对于 p = [0, 4, 8]，l = 2 且 L = 15，并集达到 10，但不是 15。扫描完成并返回 false，因为当前从未达到 L。 

最后一个微妙的情况是紧密链接，其中间隔恰好在边界处相交。 对于 p = [0, 3, 6] 和 l = 3，间隔恰好在端点处接触，应被视为连续。 条件 start > current 正确地将相等视为有效连接，确保不会引入错误间隙。
