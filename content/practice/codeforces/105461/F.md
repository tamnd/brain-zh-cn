 ## 解决方案
 ## 问题理解

 我们得到了一系列按固定顺序到达的汽车。 每辆车都有最大可能速度，我们可以将每辆车分配到两条车道之一。 每条车道内的汽车顺序与原始顺序相同，因此每条车道形成一个子序列。 

当一辆车在同一车道上跟随另一辆车时，其实际速度受到其正前方车辆的限制。 具体来说，如果一辆汽车有限制$s_i$在一辆正在高速行驶的汽车后面$c$，那么它也会被迫以一定速度移动$\min(s_i, c)$。 如果它是车道上的第一辆车，它将全力行驶$s_i$。 

分配汽车的成本是所有汽车的速度损失总和，即$s_i - c_i$， 在哪里$c_i$是经过这些限制后达到的实际速度。 我们需要将汽车分成两条车道，以尽量减少总损失。 

关键结构是，每条车道的行为就像有效速度的非递增序列，因为每辆车都受到该车道中所有先前车辆的最小值的限制。 这将问题转变为决定每个元素的去向，同时维护两个正在运行的“前缀最小值”进程。 

测试用例的总规模很小，总共最多 1000 辆汽车。 这立即表明三次甚至二次动态规划解决方案是可以接受的，而子集上的任何指数都是不必要的。 

一个天真的想法是尝试将所有汽车分配到两条车道。 这导致$2^n$的可能性，这已经是不可能的$n = 1000$。 甚至评估单个任务的成本$O(n)$，使其加倍不可行。 

如果我们尝试贪婪分配，例如总是将汽车放入其直接惩罚较小的车道，则会出现更微妙的失败情况。 例如，对于速度$[5, 4, 3]$，贪婪的选择可能会迫使提前放置，从而不必要地增加后来的上限，从而产生更糟糕的全局最小值。 

另一个问题是对速度传播的误解。 该约束不仅限于相邻车辆的局部约束； 它作为前缀最小值传播。 任何仅与直接前趋进行比较而不跟踪完整车道状态的方法都会产生不正确的结果。 

## 方法

 一旦我们观察到每条车道都由其当前有效速度（始终是迄今为止分配到该车道的车辆中的最小速度）来充分描述，问题就变得可以解决。 当添加一辆新车时，它的贡献仅取决于它所加入的车道的当前最小值。 

这表明了一种动态编程状态，我们可以跟踪每个车道当前的“紧”程度。 然而，我们不需要完整的历史记录，只需要两条车道当前的最低速度。 

蛮力公式将考虑第一个的所有分配$i$将汽车分成两条车道，同时跟踪每条车道的最低速度。 对于每个状态，我们通过放置汽车来进行转换$i+1$进入任一车道，更新车道最小值并累积成本。 这是正确的，但可能有$O(n \cdot s^2)$状态，因为每个车道最小值可以涵盖所有可能的速度，从而导致$5000^2$每个位置的状态，太大了。 

关键的见解是车道最小值只会减少。 更重要的是，放置汽车的成本贡献仅取决于它是否成为新的最小值或被车道当前的最小值削减。 这种结构允许我们压缩状态空间：我们不需要跟踪任意最小值对，我们只需要考虑一个通道的当前可能最小值上的 DP，而另一个通道则由排序选择隐式确定。 

更直接、更简洁的重新表述是考虑按前缀顺序分配给每个车道的汽车数量。 由于两个通道都保持顺序，因此我们可以将该过程重新解释为将序列分成两个子序列，每个子序列都保持运行最小值。 每个通道的成本仅取决于前缀最小值如何演变，可以增量捕获。 

我们定义DP，从左到右处理汽车，并为一个车道中当前最小值的每个可能值保持最佳可能成本，并通过转换隐式推断另一车道的效果。 每辆车有两种选择：加入车道A或车道B。加入车道时，增加的成本为$\max(0, s_i - m)$， 在哪里$m$是该车道的当前最小值，新的车道最小值变为$\min(m, s_i)$。 

这会导致 DP 易于管理，因为$s_i \le 5000$，因此我们可以维护一个可能的最小值表，并使用前缀最小值更新来压缩转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配任务|$O(2^n)$|$O(n)$| 太慢了|
 | DP 超过车道最小值状态 |$O(n \cdot S)$或者$O(n \cdot S \log S)$|$O(S)$| 已接受 |

 这里$S = 5000$。 

## 算法演练

 1. 初始化一个 DP 结构，在处理汽车前缀后，我们跟踪车道最小值配置的最佳可实现成本。 我们从两条车道开始时都是空的，这意味着它们的最小值实际上是无限的，并且不会产生任何成本。 
2. 按输入顺序迭代汽车。 对于每辆车的速度$s_i$，我们考虑将其放入任一车道。 
3. 如果我们将汽车放入当前最小值为$m$，实际速度变为$\min(s_i, m)$，所以这辆车贡献的损失是$s_i - \min(s_i, m)$。 如果$s_i \le m$，没有损失； 否则损失是$s_i - m$。 这正是该车道上较早车辆所减慢的速度。 
4. 对于每个 DP 状态，我们计算两个转换：将汽车分配到车道 A 或车道 B。每个转换都会将该车道的最小值更新为$\min(m, s_i)$，而另一条车道保持不变。 
5.我们仔细更新DP，始终保持以同一对车道最小值结束的状态之间的最小成本。 此合并步骤至关重要，因为许多不同的分配历史会导致相同的有效状态。 
6.处理完所有汽车后，我们扫描所有DP状态并取其中的最小成本。 

### 为什么它有效

 车道的整个未来行为仅取决于其当前的最低速度，因为无论前面的顺序如何，后续的每一辆车都会受到该最低速度的限制。 因此，以同一对最小值结束的任何两个历史对于所有未来决策都是等效的。 由于转换准确地保留了这一属性，DP 永远不会丢失最优解，也永远不会区分与未来成本无关的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    # dp[m1][m2] = minimum cost
    # we compress using dictionary for sparsity
    dp = {(float('inf'), float('inf')): 0}

    for x in s:
        new_dp = {}

        for (m1, m2), cost in dp.items():
            # put in lane 1
            nm1 = min(m1, x)
            add1 = 0 if x <= m1 else x - m1
            state1 = (nm1, m2)
            if state1 not in new_dp or new_dp[state1] > cost + add1:
                new_dp[state1] = cost + add1

            # put in lane 2
            nm2 = min(m2, x)
            add2 = 0 if x <= m2 else x - m2
            state2 = (m1, nm2)
            if state2 not in new_dp or new_dp[state2] > cost + add2:
                new_dp[state2] = cost + add2

        dp = new_dp

    print(min(dp.values()))

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```实现直接遵循 DP 状态定义。 每个状态都存储两个当前车道最小值，并且转换反映将当前汽车放入任一车道。 

使用`float('inf')`代表分配任何车辆之前的空车道。 每次更新都会根据汽车是否被车道夹住来正确计算新的最小值和增量成本。 

一个微妙的点是我们积极地删除重复的状态`new_dp`。 如果没有这个，由于许多等效的构造路径产生相同的最小值对，状态的数量将会爆炸。 

## 工作示例

 ### 示例 1

 输入：```
3
5 4 3
```我们将状态跟踪为（m1，m2，成本）。 

| 步骤| 汽车 | 放入泳道1后的状态 | 放入泳道2后的状态 |
 | --- | --- | --- | --- |
 | 1 | 5 | (5, 无穷大, 0) | (inf, 5, 0) |
 | 2 | 4 | (4, inf, 0) 或 (5, 4, 1) | (inf, 4, 0) 或 (4, 5, 1) |
 | 3 | 3 | 最好变成 (3, inf, 0) | 对称|

 此示例表明，将所有内容放入一条通道不会造成任何损失，因为序列严格递减。 

### 示例 2

 输入：```
3
3 5 4
```| 步骤| 汽车 | 关键状态转换 |
 | --- | --- | --- |
 | 1 | 3 | (3, inf, 0), (inf, 3, 0) | (3, inf, 0), (inf, 3, 0) |
 | 2 | 5 | 放入泳道 1 会产生损失 2 → (3,5,2) |
 | 3 | 4 | 最佳分割进一步降低成本 |

 这说明了为什么贪婪会失败：提前放置 5 辆汽车会创造未来的上限，而将汽车分布在车道上可以减少总的削波。 

DP 同时捕获两个选择并保留最佳分割。

 | 测量| 复杂性 | 说明|

 | 时间 |$O(n \cdot S^2)$最坏情况的朴素DP，通常通过修剪后会低得多 每个状态每辆车分为两个转换 |
 | 空间|$O(S^2)$最坏情况但在实践中被压缩| 仅存储活动最小值对 |

 和$n \le 1000$和$S \le 5000$，稀疏DP仍然可行，因为由于单调最小演化，实际上可达状态对的数量仍然很小。 

该解决方案完全符合限制，因为随着最小值的减小和许多转换的合并，状态空间会迅速崩溃。

 ## 边缘情况

 一个关键的边缘情况是所有汽车都严格减少。 在这种情况下，任何车道分配都会产生零损失，因为每辆新车的速度永远不会低于前方的最低速度。 DP 正确地将成本保持为零，因为每次转换都会看到$s_i \le m$对于所选车道。 

另一个微妙的情况是交替高值和低值，例如$[10, 1, 9, 2, 8]$。 天真的贪婪策略倾向于将所有高点放在一起，从而创建快速下降的车道最小值，从而导致巨大损失。 相反，DP 将高速分隔在车道上，从而保持更高的有效速度。 

第三种情况是许多汽车共享相同的速度。 由于放置相等的值永远不会降低车道最小值，因此 DP 会积极合并状态，无论分布如何，都保持成本为零。
