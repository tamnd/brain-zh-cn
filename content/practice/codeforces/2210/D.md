 ## 解决方案
 ## 问题理解

 我们有两个长度相等的平衡括号字符串。 两个字符串都保证是常规括号序列，这意味着每个前缀至少具有与右括号一样多的左括号，并且总计数匹配。 

我们可以重复获取两个不相交的子字符串，它们本身就是有效的常规括号序列，并交换它们在字符串中的位置。 该操作保留了每个选定块的内部结构，但允许对整个平衡的“块”进行重新排序。 

任务是确定我们是否可以使用任意数量的此类交换将一个有效的括号序列转换为另一个有效的括号序列。 

关键约束是所有测试用例的总长度最多为 5×10^5。 这迫使每个测试用例都有 O(n) 或 O(n log n) 解决方案。 任何模拟交换或搜索子串的尝试都是立即不可行的，因为平衡括号序列中有效子串的数量可能是二次的。 

当序列在全局平衡中看起来相似但在分解为不可约平衡分量方面有所不同时，就会出现微妙的边缘情况。 例如，“()()()”和“((()))”具有相同的计数，但结构分解不同。 仅检查“(”和“)”计数的幼稚方法会错误地对所有内容说“是”，因为所有输入共享相同的计数。 

另一种失败情况是假设原始组件的任何排列都是可能的。 除非我们描述该操作实际保留的内容，否则情况并非如此。 

## 方法

 该操作允许交换两个不相交的平衡子串。 这立即表明将序列分解为原子平衡组件的思考。 

一种自然的暴力方法是将每个有效子字符串视为一个节点，并尝试对通过有效块交换可到达的所有字符串进行 BFS 或 DFS。 每次交换可以产生 O(n^2) 种区块选择，并且每个状态都是一个字符串，因此状态空间呈指数爆炸。 即使生成邻居每个状态也已经是 θ(n^2)，这使得它完全无法使用。 

关键的观察结果是，每个常规括号序列都有一个独特的分解为原始 RBS 块，其中每个块都是将余额返回零的最小有效前缀。 这些基元块在操作下表现得像不可分割的单元。 

交换操作允许交换任何两个这样的原始块，但它不允许在块内部重新排列或将块分割成更小的部分。 这意味着基元块的多重集是不变的，并且问题简化为检查两个序列是否共享相同的基元 RBS 分量的多重集。 

然后，我们将问题简化为计算原始块的规范签名并比较它们的频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 | 指数| 指数| 太慢了 |
 | 原始块多重集匹配| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从左到右扫描字符串，同时维护一个平衡计数器，其中 '(' 贡献 +1，')' 贡献 -1。 

当计数器达到零时，我们就发现了一个原始的 RBS 块。 这是以此位置结尾的最小前缀，本身就是有效的 RBS。 
2. 提取两个字符串的每个这样的基元块。 

这种分解是独特的，因为在有效的 RBS 中，余额仅在原始组件的块边界处返回到零。 
3. 对于每个基元块，计算规范表示。

我们通过记录其完整子字符串或等效地直接散列它来做到这一点，因为块是连续的并且它们在所有测试用例中的总大小是 O(n)。 
4. 计算两个字符串的每个基本块表示的出现次数。 
5. 比较两个多重集。 如果完全匹配，则输出YES； 否则输出NO。 

### 为什么它有效

 不变的是该操作仅交换整个平衡子串。 常规括号序列中的任何有效子串都可以分解为原始 RBS 块的串联。 交换两个有效的子串可以有效地交换这些基元块的组，但不会跨边界分割或合并它们。 

因此，基元块的多重集在任意数量的操作下都被保留。 相反，如果两个字符串具有相同的原始块的多重集，我们可以通过重复交换对这些块任意重新排序，因为任何两个块都可以通过一系列不相交的交换就位，而不会破坏有效性。 这给出了可达状态之间的等价性和块多重集的等价性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_blocks(s: str):
    bal = 0
    start = 0
    blocks = []
    for i, ch in enumerate(s):
        if ch == '(':
            bal += 1
        else:
            bal -= 1
        if bal == 0:
            blocks.append(s[start:i + 1])
            start = i + 1
    return blocks

def solve():
    s = input().strip()
    t = input().strip()

    bs = get_blocks(s)
    bt = get_blocks(t)

    if len(bs) != len(bt):
        return "NO"

    from collections import Counter
    return "YES" if Counter(bs) == Counter(bt) else "NO"

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        tt = input().strip()
        out.append(solve_for_case(s, tt))
    print("\n".join(out))

def solve_for_case(s, t):
    from collections import Counter
    return "YES" if Counter(get_blocks(s)) == Counter(get_blocks(t)) else "NO"

if __name__ == "__main__":
    main()
```该实现首先通过跟踪平衡并在返回到零时进行切割，将每个字符串分解为原始平衡段。 这是常规括号序列中唯一具有结构意义的分区，因为原始块内的余额不能达到零。 

每个块都存储为一个子字符串。 由于所有测试用例的所有块的总长度为 O(n)，因此直接存储它们是安全的。 

然后，我们使用哈希表比较块的频率图。 如果两个字符串包含相同的原始组件集合，则可以进行转换。 

一个常见的实现陷阱是将前缀平衡段与任意平衡子串混合在一起。 只有前缀最小的平衡段对应于允许操作下的原子单元。

 ## 边缘情况

 关键的边缘情况是两个字符串具有相同的总计数但原始分段不同。 例如，“(()())”是单个基元块，而“()()()”是三个基元。 该算法正确地生成不同的多重集，因为余额在不同的位置达到零。 

另一种情况是块相同但以不同的顺序出现。 例如，“(())()()”和“()()(())”产生相同的块多重集，并且计数器比较正确地忽略排序，这与交换可以任意重新排序整个块的事实相匹配。 

最终的边缘情况是最小输入“()”，其中分解产生单个块。 任何转换都必须保留此单例结构，因此只接受相同的字符串。
