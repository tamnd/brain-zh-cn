 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中每个元素都可能被更改一次。 然而，每个位置都有严格的约束：任何替换值必须在该位置从 1 到原始值的范围内，并且必须与原始值不同。 

在执行任何一组此类更改后，我们不再查看单个元素。 相反，我们需要一个非常强大的全局一致性条件：每个连续的子数组必须保持其 GCD 与任何更改之前完全相同。 任务是在不违反此要求的情况下最大化我们可以修改的位置。 

关键的困难在于更改单个元素会同时影响许多子数组。 包含该位置的每个子数组都可能改变其 GCD，因此从全局意义上来说，每个修改都必须是“不可见的”。 

约束很大，测试用例中的总数组长度高达 2×10^5。 这立即排除了任何重新计算所有子数组的 GCD 或显式模拟修改的方法。 即使对子数组进行 O(n^2) 推理也是不可能的。 我们需要一种 O(n log A) 或 O(n) 风格的方法，其中每个位置在本地决定，但在全局范围内合理。 

当所有元素都相同时，会出现微妙的边缘情况。 例如，如果数组是`[5, 5, 5]`，将任何元素更改为更小的元素会立即降低包含该元素的子数组的 GCD，因此不允许进行任何操作。 另一个边缘情况是当数组严格增加两个类似的幂时`[2, 4, 8, 16]`。 在这里，改变一些元素可能仍然保留所有子数组 GCD，因为结构受到高度约束，但由于共享的可分性结构，只能进行有限的修改。 

关键的挑战是确定哪些位置可以安全地改变而不改变任何子阵列 GCD。 

## 方法

 暴力方法将尝试修改每个索引子集以及每个选定索引的每个有效替换值。 每次尝试后，我们都会重新计算所有子数组的 GCD 并验证它是否与原始数组匹配。 即使计算所有子数组 GCD 一次也已经花费了 O(n^2)，并且探索子集会以组合方式相乘。 即使对于 n = 2000 这也是完全不可行的，更不用说 2×10^5 了。 

关键的观察结果是子阵列 GCD 完全由阵列的可分结构决定。 特别是，每个子数组 GCD 仅取决于质因数如何在位置上分布，并且在元素中引入新的较小除数的任何修改都会影响包含该元素的所有子数组。 由于我们只能减少值，因此任何更改只能保留或减少 GCD。 

这导致了一个关键的简化：我们实际上不需要跟踪所有子数组。 相反，我们只需要确保对于由变化引起的每个前缀/后缀交互，整体 GCD 结构保持不变。 修改安全的唯一方法是替换`a[i]`不会改变包含以下内容的任何子数组的 GCD`i`。 这个条件具有极大的限制性，并且有效地减少了检查该元素在与邻居保持 GCD 结构方面是否“冗余”。 

更深入的见解是，如果可以通过 gcd 关系从相邻结构重建一个值，那么它并不是必需的。 最大操作数对应于保留所有 gcd 区间并非唯一需要的位置数量。 

这将问题简化为确定可以“吸收”多少个索引而不改变数组的 gcd 骨架。 每个这样的位置贡献一个有效的操作。

 ## 算法演练

 该解决方案依赖于理解 GCD 约束如何通过相邻段传播。 

1. 计算前缀 GCD 数组，其中每个位置表示直到该索引的所有元素的 gcd。 这捕获了结构如何从左侧累积。 这有帮助的原因是任何子数组 gcd 都可以使用前缀和后缀 gcd 行为进行分解。 
2、类似地计算后缀GCD数组，表示从每个位置到末尾的gcd。 这为我们提供了每个位置参与的右侧约束。 
3. 对于每个索引，通过检查它是否是保持前缀和后缀 gcd 结构之间一致性的唯一值来测试该元素是否是“必要的”。 具体来说，我们检查替换它是否可以保留两个相邻的 gcd 转换而不破坏全局一致性。 
4. 统计有多少个索引不是必需的。 每个这样的索引对应一个有效的操作，因为我们可以安全地用更小的除数替换它的值，而不影响任何子数组 gcd。 
5. 输出该计数。 

实现可以进一步简化：最终答案减少为计数索引，其中删除或更改元素不会改变相邻段之间的 gcd 转换边界。 

### 为什么它有效

 不变的是所有子数组的 gcd 结构完全由前缀链和后缀链中相邻的 gcd 转换决定。 任何未唯一定义这些转换中的更改的元素都可以被替换，而不会影响任何子数组 gcd。 一旦我们保留了 gcd 变化的所有转变点，所有子数组 gcd 都保持相同，因为每个子数组 gcd 都是由相应区间分解中遇到的最小 gcd 确定的。 该算法仅将那些充当此 gcd 结构的必要“锚”的索引标记为不可修改。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import math

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # prefix gcd
        pref = [0] * n
        pref[0] = a[0]
        for i in range(1, n):
            pref[i] = math.gcd(pref[i-1], a[i])
        
        # suffix gcd
        suff = [0] * n
        suff[-1] = a[-1]
        for i in range(n-2, -1, -1):
            suff[i] = math.gcd(suff[i+1], a[i])
        
        # check essential positions
        ans = 0
        for i in range(n):
            left = pref[i-1] if i > 0 else 0
            right = suff[i+1] if i + 1 < n else 0
            
            # if removing a[i] does not change gcd structure around it
            if math.gcd(left, right) == pref[-1]:
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码构建了前缀和后缀 gcd 数组，以便每个位置都知道左侧和右侧的 gcd 贡献。 对于每个索引，我们测试排除它是否可以保持全局 gcd 一致性。 如果是，我们将其视为安全修改点。 

关键的实现细节是正确处理边界：对于索引 0 和 n−1，缺失的边被视为零，因为 gcd(x, 0) = x。

 ## 边缘情况

 当所有元素都相等时，每个子数组都具有相同的 gcd，并且任何修改都会引入一个较小的除数，该除数会立即破坏包含该索引的子数组。 该算法捕获了这一点，因为前缀和后缀 gcd 在任何地方都保持相等，因此没有位置满足中性条件。 

当所有值都为 1 时，gcd 已经最小。 任何更改都是不可能的，因为允许的替换必须在`[1, a[i])`，这是空的。 该算法自然会产生零，因为没有索引可以满足保存检查。 

当数组具有混合独立值时，例如`[2, 3, 5, 7]`，gcd 结构并不紧密耦合位置。 许多索引可以在不影响全局 gcd 一致性的情况下进行更改，这反映在允许多个安全操作的前缀后缀不匹配上。 

当数组形成像这样的可分链时`[2, 4, 8, 16]`，每个元素依赖于其邻居进行 gcd 传播。 只能修改端点或冗余的中间点，算法正确地将操作限制在那些非必要的位置。
