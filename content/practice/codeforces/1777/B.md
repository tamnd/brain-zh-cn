 ## 解决方案
 ## 问题理解

 我们被要求计算所有大小排列的总和$n$，其中每个排列贡献了从其派生的特定数组中的反转数量。 对于排列$p = [p_1, p_2, \dots, p_n]$，数组$a$是通过连接构造的$p$与其相反，$[p_1, \dots, p_n, p_n, \dots, p_1]$。 中的反转$a$都是成对的$(i, j)$和$i < j$和$a_i > a_j$。 目标是对每个长度排列的反转次数求和$n$，然后输出这个和模$10^9+7$。 

输入有多个测试用例，每个测试用例指定一个$n$。 每个$n$可以达到$10^5$，以及所有的总和$n$跨测试用例不超过$10^5$。 这告诉我们任何比以下更糟糕的算法$O(n)$每个测试用例都会太慢。 生成全部$n!$排列显然是不可能的$n \ge 10$因为阶乘增长得非常快。 我们需要一个数学公式或组合论证。 

当出现微妙的边缘情况时$n=1$。 唯一的排列是$[1]$， 所以$a = [1, 1]$具有零反转。 一个天真的尝试应用一个更大的公式推导$n$可能会错误地计算反转或除以零。 另一个边缘情况很小$n$例如$n=2$，这让我们可以手动验证美女的总和是$4$。 

## 方法

 蛮力方法很简单：生成所有$n!$排列、构造数组$a$对于每个，使用嵌套循环计算反转，并对所有排列求和。 计算反转数$a$对于单个排列需要$O(n^2)$时间，并迭代$n!$排列给出$O(n! \cdot n^2)$。 这仅适用于$n \le 5$并变得不可想象$n \ge 10$。 

关键的见解来自于对结构的考虑$a = p || reverse(p)$。 任何反转$a$属于三类之一。 完全在第一个内反转$n$元素或最后一个元素内$n$元素是对称的； 每个排列恰好贡献了反转的数量$p$，并且反向副本贡献相同的数字。 跨越边界的反转$p$其反面可以通过分析其中值的个数来系统地计数$p$比每个都大$p_j$在下半场。 通过仔细的组合推理，我们可以将总和表示为阶乘和简单函数的乘积$n$。 

事实证明，跨边界对贡献的反演总数为$n! \cdot \binom{n}{2}$，因为对于每个无序对$(i, j)$和$i < j$,$p_i$大于$p_j$刚好有一半的排列。 将此与排列内反转相结合，给出一个封闭公式：所有大小排列的美度之和$n$是$(n! \cdot (n(n-1)/2)) \cdot 2 = n! \cdot n(n-1)$。 这足够小，可以迭代计算模数$10^9 + 7$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n! * n^2) | O(n! * n^2) | O(n) | 太慢了|
 | 最佳 | 每个测试用例的 O(n)，预先计算阶乘 | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算阶乘模$10^9 + 7$达到最大$n$所有测试用例中都遇到过。 这允许$O(1)$每个测试用例的阶乘查找。 模运算用于防止整数溢出。 
2. 对于每个测试用例，检索$n$并使用以下公式计算美丽值总和$beauty_sum = n! \cdot n \cdot (n-1) \mod 10^9 + 7$。 该公式考虑了所有反转：排列内、反转内以及跨越边界。 
3. 打印每个测试用例的结果。 预计算确保每个测试用例运行$O(1)$时间，将总运行时间保持在限制范围内。 

该算法之所以有效，是因为美丽的总和仅取决于$n$而不是个别排列。 每个排列对称地贡献于反转计数，并且该公式正确地聚合了所有三类反转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXN = 100000

# Precompute factorials modulo MOD
fact = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    fact[i] = fact[i-1] * i % MOD

t = int(input())
for _ in range(t):
    n = int(input())
    ans = fact[n] * n % MOD
    ans = ans * (n-1) % MOD
    print(ans)
```The first section precomputes factorials to avoid recomputation and keep each test case fast. 我们乘以$n!$经过$n(n-1)$模数$10^9+7$计算串联数组中的反转总数。 通过模运算分阶段相乘可防止溢出。 读取输入`sys.stdin.readline`确保速度高达$10^5$测试用例。 

## 工作示例

 对于$n=1$，阶乘是$1$， 和$n(n-1) = 0$。 公式给出$1 * 0 = 0$。 唯一的数组$[1,1]$具有零反转，证实了该公式。 

为了$n=2$, 阶乘$2! = 2$和$n(n-1) = 2$。 公式给出$2 * 2 = 4$，匹配排列的总和$[1,2]$和$[2,1]$在哪里$a = [1,2,2,1]$和$[2,1,1,2]$各自贡献$2$倒置。 

| n | 阶乘 | n(n-1) | n(n-1) | 美丽总和|
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 2 | 4 |

 这证实了该公式可以处理小$n$正确区分边缘情况，例如$n=1$。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(MAXN + t) | 预先计算阶乘直至最大值$n$，然后每个测试用例 O(1) |
 | 空间| O(最大N) | 存储阶乘模$10^9+7$|

 总和为$n$跨所有测试用例$\le 10^5$，预计算和模运算很好地契合在256MB和1s的时间限制内。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 10**9 + 7

    for i in range(1, MAXN+1):
        fact[i] = fact[i-1]*i%MOD

 ## 边缘情况

 对于$n=1$，数组为[1,1]。 Fact[1] = 1，n(n-1) = 0，因此公式返回 0。该算法不会尝试对零进行除法或阶乘，并且输出正确。 

对于小$n=2$，阶乘 2，n(n-1) = 2，公式返回 4。两种排列都会产生$2$每个反转，总和为 4。该算法正确地考虑了对称排列。 

对于最大测试用例，其中$n=10^5$，阶乘以模计算$10^9+7$，并且所有算术都遵循模块化，防止溢出并在每个测试用例中以 O(1) 运行。
