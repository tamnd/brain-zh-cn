 ## 解决方案
 ## 问题理解

 我们被要求将一个整数数组转换为一个“好数组”，它被定义为一个数组，其中没有两个连续元素共享相同的奇偶校验。 奇偶校验简单地表示一个数是奇数还是偶数。 所以在一个好的数组中，奇数后面一定是偶数，偶数后面一定是奇数。 大小为 1 的数组非常好，因为没有连续的元素。 

输入由多个测试用例组成。 每个测试用例提供一个长度最大为 100 的数组，元素大小为$10^9$。 每个测试用例的输出是将数组变成良好数组所需的最少操作数。 允许的操作是选取两个具有相同奇偶校验的相邻数字，将其删除，然后用它们的乘积替换它们。 

这些约束表明，一个简单的$O(n^2)$方法是可行的，因为$n \le 100$和$t \le 500$，所以最坏的情况下我们可能会表现得大致$500 \cdot 100^2 = 5 \cdot 10^6$简单模拟中的操作。 然而，我们可以通过推理奇偶校验模式而不是显式地模拟乘法来更快地解决问题。 

一个关键的边缘情况是多个相同奇偶校验数连续出现。 例如，数组`[2, 4, 6, 1]`需要两个操作：组合`2*4 = 8`进而`8*6 = 48`达到`[48, 1]`。 仅查看第一个冲突对的简单检查可能会低估操作。 另一种边缘情况是奇偶校验已经交替的数组，例如`[1, 2, 3, 4]`，这需要零运算。 

## 方法

 暴力法是模拟操作：扫描数组，找到具有相同奇偶校验的相邻元素，执行乘法，一直持续到不存在这样的对为止。 这种方法是正确的，因为每个操作都会严格减少相同奇偶校验相邻对的数量，因此它最终会终止。 它的缺点是它执行重复的数组操作，并且对于连续的相同奇偶校验运行可能效率低下。 对于长度为100的数组来说，这是可以接受的，但是比较麻烦。 

最佳方法的关键见解是我们实际上不需要跟踪数字本身。 两个数字相乘不会改变它们的奇偶校验，因此唯一相关的信息是奇偶校验序列。 这将问题简化为计算具有相同奇偶校验的连续数字的长度。 每一段长度$k$准确贡献$k-1$将其合并为单个元素的操作。 求和$k-1$数组中所有相同奇偶校验的运行给出了最少的操作数。 这一观察结果将问题转化为简单的线性扫描。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 可以接受但没有必要 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，读取数组的长度和数组本身。 
3. 将操作计数器初始化为零。 
4. 从第二个元素开始扫描数组到末尾。 
5. 跟踪当前具有相同奇偶校验的连续数字的长度。 从游程长度 1 开始。 
6. 对于每个元素，将其与前一个元素的奇偶性进行比较。 如果相同，则增加游程长度。 如果不同，请添加`run_length - 1`到操作计数器并将运行长度重置为 1。 
7.循环后添加`run_length - 1`最后一次运行。 
8. 输出测试用例的总操作。 

为什么它有效：不变的是具有相同奇偶校验的任何连续数字序列都可以精确地减少为单个数字`length-1`操作，与顺序无关。 这确保了在处理完所有运行之后，数组是好的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    operations = 0
    run_length = 1
    for i in range(1, n):
        if a[i] % 2 == a[i-1] % 2:
            run_length += 1
        else:
            operations += run_length - 1
            run_length = 1
    operations += run_length - 1
    print(operations)
```该代码使用快速 I/O 有效地读取所有输入。 它将游程长度计数器初始化为 1，因为单个元素通常会启动一次游程。 每次奇偶校验发生变化时，都会考虑之前的运行，并重置计数器。 最后，我们添加上次运行的操作。

 ## 边缘情况
