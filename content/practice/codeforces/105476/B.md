 ## 解决方案
 ## 问题理解

 我们为每个测试用例提供一串数字，并要求计算其连续子串中有多少个表示可被 11 整除的整数。每个子串都被解释为十进制数，但子串可能以零开头，因此前导零不会影响整除性。 

直接的解释是考虑每对指数$(l, r)$，提取子串，转换为数字，测试能否被11整除。输入大小达到$10^5$每次测试，所以$O(n^2)$就原始计数而言，子字符串的枚举已经是可以接受的，但是将每个子字符串转换为整数使得它变得可以接受。$O(n^3)$在最坏的情况下，这是立即不可行的。 

真正的约束压力来自于我们必须处理的事实$10^5$每个测试的字符数，这意味着每个测试的任何超过线性或近线性工作的解决方案都将失败。 

一个微妙的边缘情况是以零开头的子字符串。 例如，在`1000`，子串如`00`或者`000`是有效数字，必须被视为零，可被 11 整除。跳过前导零或将子字符串视为无效的简单方法会严重低估。 另一个边缘情况是，能否被 11 整除取决于数字的交替和，因此忽略奇偶校验结构将导致计数不正确。 

## 方法

 暴力破解的想法很简单：迭代所有左端点，扩展右端点，维持当前数字，并在每一步测试是否能被 11 整除。 即使我们增量地维持该值，我们仍然会处理$O(n^2)$每个测试用例的子字符串。 和$n = 10^5$，这产生了大约$5 \cdot 10^9$子串，这远远超出了时间限制。 

关键的观察结果是，当用前缀交替和表示时，能被 11 整除的结构很简单。 对于带有数字的数字$d_0 d_1 \dots d_{n-1}$,定义一个前缀值$p[i]$作为交替总和到位置$i$。 一个子串$s[l:r]$当该段的交替和为零模 11 时，它可以被 11 整除。这将问题转化为对相等前缀状态对进行计数，并进行奇偶校验调整，因为符号交替取决于起始索引。 

一旦我们用两种状态表示每个前缀，一种用于偶数索引，一种用于奇数索引，问题就变成了在频率图中计算相等值。 这将问题从二次枚举简化为线性计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) 或更糟 | O(1) | O(1) | 太慢了 |
 | 前缀奇偶校验哈希 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个前缀重写为标准化交替和，以便子字符串检查变成相等检查。 

1. 从左到右扫描字符串，构建前缀交替和。 在索引处$i$，我们根据奇偶校验添加或减去数字。 这编码了能被 11 整除的结构。 
2.维护所见前缀状态的频率图。 每个状态由当前交替和值定义。 这使我们能够计算有多少先前的前缀与当前的前缀匹配。 
3. 在处理开始之前用状态零发生一次来初始化映射。 这允许正确计数从索引零开始的子字符串。 
4. 对于每个位置，更新前缀状态并将该状态之前出现的次数添加到答案中。 然后增加其频率。 

我们在递增之前添加的原因是，相同前缀状态的每个先前出现都定义了以当前位置结尾的有效子字符串。 

### 为什么它有效

 一个子串$s[l:r]$对应于两个前缀交替和之间的差。 由于交替符号根据位置翻转，因此当奇偶校验合并到状态定义中时，匹配子串与相等的前缀状态完全对应。 因此，每对相同的状态定义一个能被11整除的子串，其他子串不计算在内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        # map: (alternating prefix sum) -> frequency
        freq = {0: 1}
        
        pref = 0
        ans = 0
        
        for i, ch in enumerate(s):
            d = ord(ch) - 48
            
            # alternating sum: + - + - ...
            if i % 2 == 0:
                pref += d
            else:
                pref -= d
            
            ans += freq.get(pref, 0)
            freq[pref] = freq.get(pref, 0) + 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现保持运行交替总和`pref`。 奇偶校验与索引相关，因此每个位置都有正确的符号。 字典`freq`存储每个前缀值出现的次数。 

关键的实现细节是初始化`freq`和`{0: 1}`。 这可确保当前缀本身变为零时，将从索引 0 开始的子字符串进行计数。 另一个微妙之处是在增加频率之前更新答案，这保证了每个子字符串只被计算一次。

 ## 边缘情况

 对于像这样的字符串`0000`，每个前缀状态保持相同，因为每个数字贡献为零。 频率图演变为`1, 2, 3, 4, 5`，答案不断累积$0 + 1 + 2 + 3 = 6$，匹配所有可能的子串。 该算法自然地处理这个问题，因为零不会影响交替和。 

对于单字符输入，例如`7`，前缀状态非零且唯一，因此不存在先前的匹配。 答案保持为零，除非数字本身提供有效的可被 11 整除的条件，该条件由前缀比较逻辑正确捕获。
