 ## 解决方案
 ## 问题理解

 我们在街道上看到了几个独立的场景。 在每个场景中，都有人们站立的固定位置和一组路灯，每个路灯都放置在某个坐标处，并且每个路灯都能够照亮其周围由其半径确定的对称区间。 位置有路灯$y$有半径$r$覆盖闭区间内的每个点$[y - r, y + r]$。 如果一个人的位置至少位于一个这样的照明区间内，则认为该人是安全的。 

对于每种场景，我们必须选择要打开的路灯子集，以便每个人的位置至少被一个选定的间隔覆盖，同时最大限度地减少激活灯的数量。 如果没有任何灯光选择可以覆盖所有人，我们输出这是不可能的。 

核心抽象是点的区间覆盖，其中每个路灯产生固定的区间，我们想要覆盖所有所需点的区间的最小子集。 

这些限制推动了效率的提高。 总大小可以大到$10^5$人们和$10^5$每个测试用例有路灯，最多 100 个测试用例。 任何将每个人与每种光进行比较的解决方案都会直接导致$O(nm)$，这将是$10^{10}$最坏情况下的操作，在 3 秒限制下是不可行的。 因此，我们需要一个更接近的解决方案$O((n+m)\log n)$或者$O(n \log n + m)$。 

当贪婪方法错误地选择了覆盖一个人的第一个光，而没有考虑到稍微不同的光可能会进一步扩大覆盖范围时，就会出现微妙的失败情况。 例如，假设人们位于位置 1、2、3，并且存在两个灯光：一个仅覆盖 [1,2]，另一个覆盖 [1,3]。 基于第一个重叠进行贪婪选择可能会导致在一个灯足够时选择两个灯。 

当有些人完全处于所有区间之外时，就会出现另一种边缘情况。 例如，一个人在位置 10，所有灯光仅覆盖 [0,5] 应该立即导致不可能，但假设覆盖存在的天真的实现稍后会默默地失败。 

最后，重叠间隔需要仔细处理，因为多个灯光可以覆盖同一区域，并且最佳选择取决于全局结构，而不是局部选择。 

## 方法

 蛮力方法很简单：对于路灯的每个子集，检查它们的间隔并集是否覆盖所有人。 即使稍微改进，人们也可能会尝试对每个灯来决定是否需要它，从而导致指数或组合搜索。 甚至更简单的基线方法是，对于每个人，尝试覆盖他们的所有灯光，并建立一个没有结构的贪婪或 DP 选择。 主要成本来自重复扫描：根据所有灯光成本检查每个人的覆盖范围$O(nm)$，如果我们尝试子集枚举，它会变成指数$m$，立即无法使用。 

关键的观察是，我们实际上并不在组合意义上独立地关心个体。 我们只关心使用区间覆盖线上的点，这是一个经典的最小区间覆盖问题。 一旦知道了时间间隔，人们的实际身份就消失了； 我们只需要确保排序列表中的每个点至少包含在一个选定的区间中。 

这将问题简化为：给定一组间隔，选择其并集覆盖所有所需点的最小数。 最佳结构是通过对人员进行分类并在每一步中尽可能扩大覆盖范围而产生的。 对于当前未覆盖的位置，我们考虑所有开始时间足够早以覆盖它的区间，并选择向右延伸最远的一个。 这是点区间覆盖的标准贪婪。 

缺少的困难是有效选择适用的间隔。 我们可以对人物和间隔进行排序，然后从左到右扫描，在可以覆盖当前位置的间隔上维护一个指针。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm)$或者更糟|$O(1)$| 太慢了 |
 | 最优贪婪扫描 |$O((n+m)\log m)$|$O(m)$| 已接受 |

 ## 算法演练

 1.将每个路灯转换为其覆盖区间$[y - r, y + r]$。 这将问题转化为点的区间覆盖问题。 
2. 将所有人员职位按升序排序。 排序至关重要，因为我们希望从左到右处理未覆盖的点。 
3. 按起始坐标对所有间隔进行排序。 这使我们能够逐步仅考虑可以覆盖当前位置的间隔。 
4. 在间隔上初始化指针并为所选灯的数量设置计数器。 
5. 对于当前最左边的未覆盖人员位置，扫描起始位置小于或等于该位置的所有间隔。 其中，跟踪最大右端点。 
6. 如果没有区间可以覆盖当前位置（即最大右端点仍在该位置下方），则无法输出。 
7. 否则，选择到达最右边的区间，增加答案，并将当前位置向前移动到超出该覆盖范围的第一个人。 
8. 重复此操作，直至覆盖所有人员。 

### 为什么它有效

 每走一步，我们都被迫覆盖最左边未覆盖的人。 任何有效的解决方案都必须选择覆盖该位置的区间。 在所有这些间隔中，选择最右边延伸的间隔永远不会减少未来的可能性，因为它最大化了剩余的未覆盖前缀收缩。 任何提前结束的替代区间只能留下更多未覆盖的点，而无法改善未来的覆盖范围。 这种贪心交换论证确保每个选择都可以转化为最优解，而无需增加所选区间的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        xs = list(map(int, input().split()))

        intervals = []
        for _ in range(m):
            y, r = map(int, input().split())
            intervals.append((y - r, y + r))

        xs.sort()
        intervals.sort()

        i = 0
        ans = 0
        idx = 0

        nxs = len(xs)

        while i < nxs:
            target = xs[i]

            best = -1
            while idx < m and intervals[idx][0] <= target:
                if intervals[idx][1] >= target:
                    best = max(best, intervals[idx][1])
                idx += 1

            if best < target:
                print("imposible")
                break

            ans += 1

            # move i to first uncovered person
            cover_limit = best
            while i < nxs and xs[i] <= cover_limit:
                i += 1

        else:
            print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将每个路灯转换为其覆盖范围。 对人员和间隔进行排序可以实现线性扫描。 

指针`i`追踪第一个未被覆盖的人，同时`idx`跟踪到目前为止已经考虑了多少个间隔。 对于每个未被覆盖的人，我们前进`idx`在起点不大于该人的位置的所有间隔上，并在其中计算最远的可到达端点。 

如果没有区间可以覆盖当前人，我们立即打印`"imposible"`。 否则，我们承诺选择一盏灯并提前`i`过去该区间涵盖的所有人员。 

一个微妙的细节是`idx`永远不会重置。 这是正确的，因为间隔是按排序顺序处理的，并且一旦间隔在当前位置之后开始，它只会在稍后的扫描中变得相关。

 考虑示例：

 输入：```
1
5 3
7 10 3 4 4
3 3

```已排序的人：[3,4,4,7,10]

 区间：[0,6]、[6,8]、[6,10]

 | 步骤| 当前位置 | 可用间隔 | 选择的间隔 | 覆盖范围| 下一个索引 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | [0,6]| [0,6]| 0-6 | 3 |
 | 2 | 7 | [6,8], [6,10] | [6,10]| 6-10 | 结束 |

 我们首先使用区间 [0,6] 覆盖位置 3，这也覆盖了两个 4。 下一个未被覆盖的点是7，覆盖它的最佳区间是[6,10]，这样就完成了覆盖。 

该轨迹显示了算法如何自然地将局部覆盖合并为最大分段。

 ## 边缘情况

 一个关键的边缘情况是多个间隔严重重叠但范围略有不同。 假设人们在 [1,2,3] 处，间隔为 [1,2] 和 [1,3]。 该算法选择[1,3]，一步涵盖所有内容。 致力于覆盖 1 的第一个有效区间的幼稚方法会选择 [1,2]，然后需要另一个选择，从而产生次优答案。 

另一种情况是完全不可能的。 如果一个人存在于 100 并且所有间隔都以 50 结束，则扫描会到达该人`best = -1`，立即触发故障。 这可以防止延迟错误计数。 

第三种情况涉及具有相同起点的密集间隔。 排序确保在相等的起始位置中，我们在指针前进之前仍然正确地评估到达最远的起始位置，从而防止由于过早的指针移动而导致选择不足。
