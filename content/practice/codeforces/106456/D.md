 ## 解决方案
 ## 问题理解

 我们得到了多个独立的查询。 每个查询提供一个整数$c$。 对于每个$c$，我们必须将它分成两个正整数$a$和$b$这样$a + b = c$。 在所有这些分裂中，我们想要最大化的对$\mathrm{lcm}(a, b)$，然后我们输出该最大值。 

就测试用例数量而言，输入大小很大，最多可达$10^4$，以及每个$c$可以大到$10^9$。 这立即排除了尝试所有对的任何方法$(a, b)$每个测试用例，因为即使迭代单个测试的所有分割$c$会花费$O(c)$，当$c$高达十亿。 

一个关键的结构性限制是$a$和$b$通过总和约束紧密耦合。 这通常表明问题简化为优化除数或近平衡分区上的数论函数。 

一个天真的错误是假设最好的分割总是$a = b = c/2$。 对于最大化产品来说有时确实如此，但 LCM 的行为有所不同。 

例如，当$c = 6$, 分裂$3 + 3$给出$\mathrm{lcm} = 3$，但是分裂$2 + 4$给出$\mathrm{lcm} = 4$, which is larger. 所以对称性并不是最佳的。 

另一个微妙的失败案例出现在$c$是素数。 如果$c = 7$，可能的分割包括$(1,6), (2,5), (3,4)$。 最好的是$(1,6)$给予$\mathrm{lcm} = 6$， 不是$(3,4)$这给出了$12$但无效，因为它超出了最大化 LCM 结构推理的总和约束。 基于亲密性或平衡性的粗心启发式在这里会失败。 

因此，核心困难是理解可分结构如何与总和约束相互作用。 

## 方法

 我们从定义开始：$$\mathrm{lcm}(a, b) = \frac{a \cdot b}{\gcd(a, b)}$$自从$a + b = c$，我们可以重写一切$a$:$$b = c - a$$所以问题就变成了最大化：$$\mathrm{lcm}(a, c-a)$$暴力方法枚举所有$a \in [1, c-1]$，计算$b$，并使用 gcd 评估 LCM。 这是正确的，但是成本$O(c \log c)$每个测试用例由于 gcd 计算，对于$c$最多$10^9$。 

关键的观察结果是最佳结构受到极大限制。 如果我们观察小案例和因子行为，最大 LCM 往往会发生在$a$和$b$共享尽可能少的共同结构。 这意味着我们想要$\gcd(a, b)$理想情况下要小$1$。 

如果$\gcd(a, b) = 1$， 然后：$$\mathrm{lcm}(a, b) = a \cdot b$$所以我们正在最大化产品$a(c-a)$，这是一个在附近最大化的凹二次方程$c/2$。 然而，限制是$a$和$b$必须互质。 

所以最优策略变成：尝试分裂$c$分解为两个尽可能接近的互质数。 

最佳候选人通常是：$$a = \left\lfloor \frac{c}{2} \right\rfloor,\quad b = \left\lceil \frac{c}{2} \right\rceil$$但前提是它们互质。 如果没有，我们稍微向下调整，直到找到互质对。 

这大大减少了搜索空间：而不是$O(c)$，我们只检查周围的一个小社区$c/2$。 在实践中，尝试接近的值$c/2$就足够了，因为由于产品结构的原因，任何最佳解决方案都必须位于中心附近。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有分裂 |$O(c \log c)$每次测试 |$O(1)$| 太慢了|
 | 检查附近的候选人$c/2$|$O(\sqrt{c})$每次测试的最坏情况$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个查询，读取值$c$。 目标是有效地评估候选分割，而不枚举所有可能性。 
2. 计算一小组候选值$a$大约$c/2$，通常包括$\lfloor c/2 \rfloor$,$\lfloor c/2 \rfloor - 1$，可能还有一些附近的值。 原因是函数$a(c-a)$在中点处最大化，因此任何最优解都必须接近它。 
3. 对于每位候选人$a$， 放$b = c - a$。 这精确地强制了总和约束。 
4. 计算$g = \gcd(a, b)$。 这决定了产品的 LCM 减少了多少。 
5. 计算$\mathrm{lcm}(a, b) = \frac{a \cdot b}{g}$，并跟踪所有候选人的最大值。 
6. 输出当前找到的最佳值$c$。 

### 为什么它有效

 LCM 表达式分解为按 gcd 因子缩小的乘积。 乘积项将解决方案推向平衡分割，而 gcd 项则惩罚结构性重叠。 任何偏离远$c/2$减少乘积的速度快于改善 gcd 结构的速度，因此所有最佳候选者必须位于中点周围的一个小邻域内。 这保证了扫描周围恒定数量的候选者$c/2$足以捕获全局最大值。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def lcm(a, b):
    return a // math.gcd(a, b) * b

t = int(input())
for _ in range(t):
    c = int(input())

    best = 0
    mid = c // 2

    # try a small neighborhood around midpoint
    for a in range(max(1, mid - 5), min(c, mid + 6)):
        b = c - a
        if b <= 0:
            continue
        best = max(best, lcm(a, b))

    print(best)
```该代码完全专注于中点周围的本地搜索。 辅助函数使用 LCM 的标准标识，通过在乘法之前除法来避免中间乘法中的溢出问题。 循环边界确保我们只测试每个测试用例的恒定数量的候选者，这使得解决方案即使对于$10^4$查询。 

一个微妙的实现细节是 LCM 计算中的顺序。 写作$a // gcd(a, b) * b$避免可能发生的中间溢出$a * b$，尽管 Python 可以安全地处理大整数，但为了保持一致性，这种模式在竞争性编程中仍然是标准的。

def run(inp: str) -> str:

 ## 边缘情况

 对于$c = 2$, 唯一的分割是$1 + 1$，给予 LCM$1$。 该算法仍然在中点附近评估$1$, 正确产生$1$。 

对于总理$c = 7$，中点是$3$。 候选人包括$3+4$给予LCM$12$，这是正确的并且支配着所有其他的。 邻域搜索无需特殊的外壳即可捕获这一点。 

对于 2 的大幂，例如$c = 1024$，中点周围的所有对都具有较大的 gcd 值，并且最佳结果仍然来自接近平衡的分割，例如$512+512$或相邻对。 扫描可确保直接评估这些内容。
