 ## 解决方案
 ## 问题理解

 我们被要求准确计算最便宜的购买方式`n`一杯奶茶，商店提供两种购买选择：按成本购买单杯`a`，或者以成本价购买一捆两个杯子`b`。 每束都是不可分割的，并且恰好有两个杯子。 目标是准确达到`n`杯子，至少不是`n`，同时最小化总成本。 

关键的困难在于决定要拿多少包还是单杯。 只有当每杯的成本比购买两个单杯便宜时，捆绑包才能省钱，但即使捆绑包更便宜，平价也很重要，因为捆绑包总是贡献偶数杯。 如果`n`奇怪的是，无论捆绑包多么便宜，至少单杯是不可避免的。 

约束允许最多`10^4`测试用例和值高达`10^9`。 这意味着每个测试用例必须在恒定时间内解决，因为即使`O(n)`如果每个测试用例都太慢了`n`总量很大。 该解决方案必须避免任何数量上的模拟，而是依赖于直接算术推理。 

当错误地比较捆绑成本与单一成本时，会出现一个常见错误。 例如，如果`a = 10`,`b = 9`， 和`n = 1`，一个幼稚的策略可能会尝试使用捆绑包，因为每两个杯子更便宜，但这是不可能的，因为我们无法拆分捆绑包。 当出现另一个微妙的问题时`n = 1`：即使非常便宜，捆绑也无法使用。 

## 方法

 暴力方法会尝试所有可能数量的捆绑包`k`， 从`0`到`n // 2`，并填写剩余的`n - 2k`单次购买的杯子。 每个选择的成本为`k * b + (n - 2k) * a`。 这是正确的，因为它枚举了每个有效的分解`n`分为双人和单人。 然而，这种方法需要`O(n)`每个测试用例，因为最多有`n/2`可能的捆绑计数。 和`n`最多`10^9`，这是完全不可行的。 

关键的观察是，这不是一个组合搜索问题，而是一个简单的局部优化。 每个捆绑包替换两个单件。 购买两件单件和一件捆绑件之间的成本差异为`2a - b`。 如果该值为正，则捆绑是有利的； 否则，他们就不是。 因此，在最佳解决方案中，我们要么采用尽可能多的捆绑包，要么根本不采用任何捆绑包。 

唯一剩下的复杂问题是奇偶校验。 如果`n`是均匀的，我们可以只使用捆绑包，也可以自由地混合捆绑包和单件。 如果`n`奇怪的是，我们必须留下一个单独购买的杯子，其余的`n-1`杯子是成对处理的。 

因此，解决方案简化为检查捆绑包是否比两个单件更便宜，然后贪婪地使用尽可能多的捆绑包，并用单件装满剩余的杯子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(n) | O(1) | O(1) | 太慢了|
 | 最佳| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们根据捆绑是否划算来分别进行推理。 

1. 通过比较计算购买两件单件是否比购买一件捆绑更贵`2a`和`b`。 如果`b >= 2a`，捆绑永远没有帮助，因此最佳策略是单独购买所有杯子。 
2. 如果捆绑包更便宜（`b < 2a`），我们希望最大化我们使用的捆绑包数量，因为与两个单一捆绑包相比，每个捆绑包严格降低了成本。 
3. 计算我们可以使用多少个捆绑包`n // 2`。 这使用了所有可能的对而不违反确切的要求。 
4. 如果`n`是偶数，答案很简单`(n // 2) * b`。 
5.如果`n`很奇怪，我们取`(n // 2)`捆绑包用于`n - 1`杯子，并为剩余的一杯额外提供一个单杯。 成本变为`(n // 2) * b + a`。 

### 为什么它有效

 每束正好替代两个单独的杯子。 该决定简化为本地交换参数：如果用一个捆绑包替换两个单条可以降低成本，那么任何最佳解决方案都必须对每个可用的对执行该替换。 由于捆绑除了通过计数之外不会交互，因此任何重新排列都无法改进已经使用所有有益交换的解决方案。 唯一的全局约束是奇偶校验，当`n`很奇怪。 这完全决定了最优解的结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, a, b = map(int, input().split())

    # compare cost of 2 singles vs 1 bundle
    if b >= 2 * a:
        # bundles are not useful
        print(n * a)
    else:
        # use as many bundles as possible
        pairs = n // 2
        cost = pairs * b
        if n % 2 == 1:
            cost += a
        print(cost)
```该代码直接实现了交换参数。 比较`b >= 2a`决定任何捆绑包的使用是否值得。 如果没有，我们就会回到纯粹的单身。 否则，我们通过使用整数除法贪婪地配对元素来最大化捆绑包的使用。 

一个微妙的问题是处理溢出或大乘法，但 Python 整数可以安全地处理这个问题。 另一个重要的细节是使用`n // 2`而不是迭代，这确保了每个测试用例的时间恒定。

 我们使用 2 个捆绑包，不使用单个捆绑包。 这证实了当捆绑有益时，完全配对是最佳的。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    out = []
    for _ in range(t):
        n, a, b = map(int, input().split())
        if b >= 2 * a:
            out.append(str(n * a))
        else:
            pairs = n // 2
            cost = pairs * b
            if n % 2:
                cost += a
            out.append(str(cost))
    return "\n".join(out)

 ## 边缘情况

 当`n = 1`，该算法正确地绕过了捆绑，因为`n // 2 = 0`，只留下单次采购成本`a`。 例如，`n = 1, a = 10, b = 1`产量`10`，因为即使每杯更便宜，也不能使用捆绑包。 

什么时候`n = 2`，两种策略具有直接可比性。 如果`b < 2a`，算法选择一束； 否则，它使用两个单打。 例如，`n = 2, a = 5, b = 8`结果`10`， 尽管`n = 2, a = 5, b = 9`也导致`10`，确认正确的比较逻辑。 

什么时候`n`虽然很奇怪，而且捆绑包很便宜，但该算法仍然准确地保留了一个杯子。 为了`n = 5, a = 3, b = 4`，它使用两个捆绑包和一个单独的捆绑包，产生`11`。 由于奇偶校验，任何避免单杯的尝试都是不可能的，并且任何与完全配对的偏差都只会增加成本，因为捆绑是绝对有益的。
