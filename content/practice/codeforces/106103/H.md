 ## 解决方案
 ## 问题理解

 我们给出了多个测试用例，每个测试用例由四个棒长度组成。 每根棍子都是刚性的：我们不能切割它、延长它或弯曲它。 任务是确定这四根木棍是否可以排列成一个几何正方形。 

这里的正方形是指具有四个等长边和直角的闭环。 由于我们只允许将木棍用作直线段，因此我们唯一的自由就是如何将每根木棍分配到正方形的一边。 

关键的建模步骤是将几何要求转化为对棒长度的约束。 正方形有四个边，且四个边都相等。 因为每根棍子都是一个刚性段，所以正方形的每一边必须恰好对应一根棍子。 没有任何操作允许我们将木棍分割或合并成更小的部分，因此最终形状的结构完全由四个输入值的相等性决定。 

每个测试用例的输入大小很小，但最多可以有 10^4 个测试用例。 这意味着任何针对每个测试用例持续工作的解决方案都可以，而任何涉及对测试用例进行大型结构或嵌套循环排序的解决方案仍然可以，但没有必要。 这些限制促使我们进行直接的恒定时间检查。 

当人们试图过度考虑分组时，就会出现一种微妙的边缘情况。 例如，人们可能会想象将 1、2、1、2 这样的棍子组合起来形成长度为 2 或 3 的四个边。这是无效的，因为棍子不能被破坏或连接。 另一个错误是假设我们只需要总和能被 4 整除，这在灵活切割问题中是正确的，但在这里不行。 

具体的失败直觉：

 输入：```
1
1 2 1 2
```有些人可能会猜测我们可以形成一个边长为 1.5 的正方形，或者配对会有所帮助，但我们无法拆分木棍，因此没有任何配置可以产生四个相等的边。 正确的输出是`NO`。 

输入：```
1
5 5 5 5
```所有的棍子都已经匹配，所以我们可以直接将每根棍子分配到一边。 输出是`YES`。 

## 方法

 强力解释将尝试将木棍分配到四个侧面并验证几何可行性。 由于我们只有四根棍子，因此可以尝试所有分配的排列，甚至在允许拆分的情况下考虑分组决策。 这很快就会变得不必要的复杂性，因为目标形状的结构极其严格：每一面都必须与一根棍子完全匹配。 在意识到没有替代组装是合法的之后，即使是简单的几何构造步骤仍然会崩溃以检查边长是否相等。 

关键的观察结果是平方约束消除了所有自由度。 一旦我们接受每一面都必须是一根棍子，问题就减少到验证所有四个值是否相同。 任何偏差都会破坏至少一侧的平等条件，从而使构造变得不可能。 

因此，“几何”部分完全消失，剩下的是对四个整数的简单相等测试。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力安排| O(1)（常量排列）| O(1) | O(1) | 矫枉过正|
 | 检查所有相等 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例的四个棒长度。 这些代表了可以形成正方形的唯一可用线段。 
2. 将所有四个值与第一根棒进行比较。 推理是，如果正方形是可能的，则每条边都必须相同，因此所有边都必须匹配单个参考值。 
3. 如果任何一根棍子与第一根不同，请立即得出结论：不可能形成正方形。 
4. 如果所有四个值都匹配，则得出结论：它们直接形成正方形的四个边。 

该决策对于每个测试用例来说完全是本地的，因此用例之间没有交互，也没有累积状态。 

### 为什么它有效

 正方形需要四个相等的边。 由于棍棒无法修改，因此每一面都必须是一根棍棒。 这意味着边长的多重集必须包含重复四次的单个唯一值。 任何偏差都会导致至少一条边的长度不同，从而破坏了正方形的定义。 没有替代结构可以补偿不匹配的长度，因此相等既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, c, d = map(int, input().split())
        if a == b == c == d:
            out.append("YES")
        else:
            out.append("NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案独立读取每个测试用例并执行单个链式相等检查。 链式比较`a == b == c == d`是一种紧凑的方法，可以确保所有值都相同，而无需显式编写成对条件。 输出被缓冲以避免重复的 I/O 开销。 

一个常见的实现错误是仅检查部分相等，例如`a == b and c == d`，它错误地接受这样的情况`1 1 2 2`。 另一个错误是排序和检查相邻相等性，这仍然是正确的，但对于如此小的固定大小输入来说是不必要的开销。

 ## 边缘情况

 一个常见的失败案例是假设配对就足够了，例如治疗`(a == b and c == d)`就足够了。 用于输入`1 1 2 2`，该逻辑错误地返回 YES。 正确的算法会立即拒绝它，因为并非所有四个值都匹配。 

输入：```
1
1 1 2 2
```执行：

 第一个比较通过`a == b`， 但`a == c`失败，因此算法停止并返回`NO`。 

另一个微妙的情况是，当值全部不同但形成视觉上“平衡”的集合时，例如`2 3 4 5`。 没有任何局部结构可以提供帮助； 第二次比较时检查立即失败。 

输入：```
1
2 3 4 5
```在第一次相等扫描期间检测到不匹配，产生`NO`不需要任何进一步的推理。
