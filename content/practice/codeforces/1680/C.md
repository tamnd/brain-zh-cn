 ## 问题理解

 我们得到一个二进制字符串，并且允许我们以非常具体的方式切割它：我们选择一些要删除的前缀和后缀，在中间留下一个连续的子字符串。 剩余的子字符串是我们“保留”的内容，而它之外的所有内容都被视为已删除。 

选择保留子串的成本取决于两个数量。 首先，我们计算保留的子字符串中剩余多少个零。 其次，我们计算从原始字符串中删除了多少个，这正是所选子字符串之外的个数。 最终成本是这两个值中较大的一个。 目标是选择保留的子串，使这个最大值尽可能小，并且我们也可以什么都不保留。 

关键限制是所有测试用例的总长度最多为 200,000。 这立即排除了每个测试用例的子字符串的任何二次枚举。 在最坏的情况下，任何独立尝试所有左边界和右边界的操作都会退化为大约 10^10 次操作，并且是不可行的。 我们应该期望每个测试用例都有一个线性或接近线性的解决方案，可能使用前缀计算或滑动结构。 

当最佳策略是删除所有内容或保留整个字符串时，会出现微妙的边缘情况。 例如，最好通过删除所有内容来处理一串全为 1 的字符串，因为保留任何内容都会导致零成本为零，但可能会不必要地增加删除的成本。 相反，最好完全保留一串全零，因为删除任何内容只会增加删除的数量，而没有任何好处。 

仅尝试“平衡”剪切或假设答案必须来自字符分布均匀的中间段的幼稚方法将在单调字符串上失败，例如`00000`或者`11111`，其中最佳答案几乎为零，但任何不正确的启发式仍可能产生正成本。 

## 方法

 直接的暴力策略是考虑删除前缀和后缀后可以保留的每个可能的子字符串。 对于每个候选区间$[l, r]$，我们计算有多少个零位于其内部以及有多少个 1 位于其外部。 然后，我们将成本评估为这两个值中的最大值，并在所有间隔中取最小值。 

这是正确的，因为它详尽地检查了所有允许的配置。 然而，有$O(n^2)$每个测试用例的子字符串，并且每个评估都需要$O(1)$如果前缀和是预先计算的。 即使有前缀和，总工作量也变为$O(n^2)$，这对于$2 \cdot 10^5$总长度。 

关键的观察结果是，成本仅取决于“内部零”和“外部零”之间的平衡。 如果我们固定一个分割点并考虑前缀和后缀的贡献，那么问题就相当于选择一个边界并优化一个可以增量维护的函数。 我们没有明确选择子串，而是将问题重新表述为选择一个切割，以权衡保留的零与删除的零。 

我们定义了一个基于前缀的转换，其中我们将保留子字符串解释为删除前缀和后缀，并且我们跟踪当我们移动边界时成本如何演变。 这自然会导致扫描字符串，同时以允许我们在线性时间内评估所有有效分割的方式维护零和一的计数。

 ## 算法演练

 我们通过选择剪切位置并评估我们保留多少个零和我们丢弃多少个零来重写问题。 主要思想是考虑前缀和后缀之间的每个可能的边界，并有效地计算该配置的最佳可实现成本。 

1. 预先计算字符串中 1 的总数。 这使我们能够计算任何保留段的“删除的”，而无需重复扫描。 如果一个段包含`ones_inside`， 然后`ones_removed = total_ones - ones_inside`。 
2. 迭代所有可能的分割点，这些分割点定义了我们从左侧删除的前缀。 对于每个这样的点，我们将其视为保留段的开始。 
3. 在移动保留段的右边界时，保持段内 0 和 1 的连续计数。 这避免了重新计算每个候选间隔的计数。 
4. 对于每个候选分段，将成本计算为以下最大值：

 - 段内的零
 -total_ones 减去段内的

 这直接从定义中得出：内部的零保留，外部的零被删除。 
5. 跟踪所有有效段中此成本的最小值。 

更有效的观点避免显式独立地枚举两个边界。 相反，我们固定一个分割点并使用前缀/后缀累积来在线性时间内导出最佳值。 

### 为什么它有效

 任何有效的操作都由我们保留的单个连续段完整描述。 成本仅取决于两个数量：内部的零和外部的零。 当段扩展或缩小一个字符时，这两个数量都可以增量更新。 由于每个字符仅将计数改变 ±1，因此无需重新计算即可评估所有候选片段。 这确保了每个有效配置都被考虑一次，并且这些评估的最小值是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        total_ones = s.count('1')

        zeros_inside = 0
        ones_inside = 0

        ans = float('inf')

        l = 0
        for r in range(n):
            if s[r] == '0':
                zeros_inside += 1
            else:
                ones_inside += 1

            while l <= r:
                ones_removed = total_ones - ones_inside
                cost = max(zeros_inside, ones_removed)
                ans = min(ans, cost)

                if s[l] == '0':
                    zeros_inside -= 1
                else:
                    ones_inside -= 1
                l += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案维护一个代表保留子串的滑动窗口。 每次扩展右边界时，我们都会将一个字符合并到窗口中。 然后，我们缩小左边界，同时评估以当前右边界结束的所有有效配置。 关键的实现细节是窗口内部的计数始终保持一致，因此内部的零和外部的零都是在恒定时间内计算的。 

一个常见的陷阱是忘记允许删除整个字符串。 这是自然处理的，因为窗口可能会变空`l > r`，在这种情况下，内部的零为零，删除的零等于总的零，从而产生正确的成本候选。

 ## 边缘情况

 仅包含零的字符串，例如`00000`当我们删除整个字符串或完全保留它时，产生的成本为零。 该算法自然会达到这种状态，因为`ones_removed`始终为零，并且缩小窗口最终会在内部产生零个零。 

仅包含以下内容的字符串，例如`11111`当我们删除所有内容时是最佳的。 在这种情况下，内部的零为零，移除的零等于总数，但最小值是在两个值都为零的空窗口处实现的。 

交替的字符串就像`101010`强制算法平衡内部零的局部增加与删除的全局减少。 滑动窗口评估每个边界转变，并且当零的边际增加等于删除的边际减少时出现最佳点。
