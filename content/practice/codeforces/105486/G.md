 ## 解决方案
 ## 问题理解

 我们从一个整数列表开始，并且可以通过获取任何相邻对并使用按位运算（AND、OR 或 XOR）插入从它们派生的值来重复扩展它。 插入的值位于两个选定元素之间，并且该过程可以在新形成的数组上无限期地继续。 

The goal is not to track the array itself, but to understand what values can eventually appear anywhere in it, and specifically to maximize how many distinct values can be created in total.

 约束的重要部分是数组的大小，最多 100,000 个元素，值最多约为 2³⁰。 这立即排除了任何显式模拟插入或维护不断演变的数组的方法，因为数组可以无限制地增长。 相反，解决方案必须对值的闭包进行推理：无论操作顺序如何，最终可以到达哪一组数字。 

天真的思维的一个微妙的失败案例是假设只有原始值及其直接的成对结果才重要。 For example, given`[1, 2, 3]`，人们可能会认为只有像这样的组合`1 & 2`,`2 | 3`, etc. matter. 但是，一旦插入新值，它就会与其他元素相邻并参与进一步的操作，从而创建不直接存在于原始数组中的二阶和高阶组合。 

这从根本上解决了理解当一组数字在按位与、或和异或的重复应用下闭合时生成什么结构的问题。 

## 方法

 蛮力视角会从字面上模拟该过程：维护数组，选择每个可能的相邻对，插入所有三个派生值，然后继续，直到没有新值出现。 这很快就变得不可行，因为每个操作都会增加数组大小，并且可能的操作序列的数量会呈爆炸性增长。 即使我们尝试删除重复值，新插入元素之间的交互也会在时间和内存中造成组合爆炸。 

关键的观察是，我们对插入的_顺序_或数组的结构不感兴趣，只对值可以存在的位置感兴趣。 一旦创建了一个值，就可以像其他值一样使用它。 这意味着我们正在有效地研究三个按位运算下初始集的闭包。 

现在我们一点一点地放大这些操作的行为。 数字的每一位在 AND、OR 和 XOR 下独立演化。 如果我们隔离单个位位置，则每个数字在该位置贡献 0 或 1，并且位上的操作如下：

 From any pair of bits:

 - AND 仅当两者均为 1 时才给出 1
 - 如果至少有一个为 1，则 OR 给出 1
 - 如果恰好有 1 为 1，则 XOR 给出 1

 现在考虑一下，如果我们在某些可达值的同一位位置上同时存在 0 和 1，会发生什么情况。 从一对 (0,1) 中，我们已经可以再次生成 0 和 1。 从 (1,1) 开始，XOR 产生 0，从而重新引入缺失值。 从 (0,0) 开始，一切都保持为 0，因此该位永久固定。 

这意味着每一位的行为都是独立的：如果初始数组在给定的位位置中包含至少一个 0 和至少一个 1，则该位在闭包中变得完全可控。 否则，它在所有可达值中保持不变。 

一旦位以这种方式独立，就可以通过重复构造中间值来实现自由可控位的任意组合，因为我们可以在每个自由位位置独立地合成0或1，然后通过进一步的操作将它们组合起来。 

因此，问题归结为计算输入中“混合”了多少位位置，这意味着该位置在初始数字中同时包含 0 和 1。 如果 k 位混合，则最终可达集包含这些位的所有 2^k 种组合，而固定位保持不变。

 ## 算法演练

 1. 扫描所有数字并记录每个位位置是否看到 0 以及是否看到 1。 

这准确地捕获了确定闭包中的某个位是固定的还是空闲的所需信息。 
2. 对于从 0 到 30 的每个位位置，检查输入数字中是否同时出现这两种状态。 如果他们这样做，请将此位标记为“免费”。 

原因是只有两个位状态共存才能通过 XOR 和 AND/OR 交互重新生成两个值。 
3. 计算有多少位是空闲的，并将该计数表示为 k。 

每个这样的位可以独立地改变任何可达到的值。 
4. 返回 2^k 作为答案。 

这代表了空闲位的所有可能组合，而固定位不贡献任何可变性。 

### 为什么它有效

该算法依赖于结构不变量：每个位位置在允许的操作下独立演化，并且位的完全灵活性的唯一障碍是初始集合的一致性。 一旦某个位最初同时存在 0 和 1，重复应用 AND、OR 和 XOR 可确保两个值都不会永久丢失，因为每个操作都会保留或重新引入这两种状态。 这可以防止崩溃为受限子集，并且该位上的闭包成为完整的二进制选择。 由于位的交互方式不会限制其他位的变化能力，因此全局状态空间是独立位自由度的笛卡尔积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    has0 = [True] * 31
    has1 = [True] * 31

    # initialize: we will refine by checking actual presence
    has0 = [False] * 31
    has1 = [False] * 31

    for x in a:
        for b in range(31):
            if x & (1 << b):
                has1[b] = True
            else:
                has0[b] = True

    free_bits = 0
    for b in range(31):
        if has0[b] and has1[b]:
            free_bits += 1

    print(1 << free_bits)

if __name__ == "__main__":
    solve()
```该实现仅跟踪位统计信息，从不模拟任何数组扩展。 对于每个数字，它会更新哪些位显示为 0，哪些位显示为 1。最后的循环计算有多少个位置被混合。 使用位移位将答案计算为 2 的幂，这是安全的，因为指数最多为 31。 

一个常见的实现陷阱是忘记正确初始化两个存在数组或错误地解释位检查； 必须针对所有数字的两种状态对每个位进行独立测试。 

## 工作示例

 考虑输入`a = [1, 2]`。 

这里 1 是`01`2 是`10`。 对于每个位位置，都会出现 0 和 1。 我们追踪：

 | 位| 有0 | 有1 |
 | --- | --- | --- |
 | 0 | 是的 | 是的 |
 | 1 | 是的 | 是的 |

 所有位都是空闲的，因此 k = 2，答案是 4。 

这显示了两个互补值如何立即解锁完整的位灵活性。 

现在考虑`a = [7, 3]`。 

二进制：

 - 7 = 111
 - 3 = 011

 | 位| 有0 | 有1 |
 | --- | --- | --- |
 | 0 | 没有| 是的 |
 | 1 | 没有| 是的 |
 | 2 | 是的 | 是的 |

 只有第 2 位是空闲的，因此 k = 1，答案为 2。 

这表明，即使大多数位是固定的，单个混合位也已经使可达空间加倍。

 ## 边缘情况

 关键的边缘情况是所有数字都相同。 例如，输入`a = [8, 8, 8]`。 每个位要么始终为 0，要么始终为 1，因此不会混合任何位位置。 该算法没有标记空闲位，导致 k = 0 和答案 1。这与实际情况相符，因为当两个输入相同时，任何操作都无法引入新值。 

另一种边缘情况是整个数组中只有一位不同。 例如，`a = [0, 1, 1, 1]`。 只有最低位被混合，因此 k = 1，答案为 2。遍历算法，只有该位位置同时设置了 has0 和 has1，所有其他位保持固定，确认最终闭包中仅存在一个自由度。
