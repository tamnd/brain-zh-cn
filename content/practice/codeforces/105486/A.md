 ## 解决方案
 ## 问题理解

 我们得到一个由两个符号组成的二进制字符串，`>`和`-`。 我们从相同长度的空白画布开始，填充`*`，并且我们可以进行绘画操作。 每个操作选择一个长度至少为 5 的连续段并用非常特定的模式覆盖它：该段必须以`>`，完全以`>>>`，并且之间的所有内容都必须是`-`。 

所以每次操作都会绘制一个看起来像单一形状的形状`>`在该段的左边界，三个连续的`>`在右边界，且仅`-`在室内。 段本身可以长于 5，但扩展它只会插入更多`-`s 并且不改变数量`>`产生的人物。 

目标是确定我们是否可以从所有`*`并且，最多使用`n`这样的操作，最终得到的正是给定的目标字符串`s`。 如果可能的话，我们还必须构造一个有效的操作序列。 

约束条件意味着`n`每个测试用例可以高达 100000 个，所有测试用例的总和达到 500000 个。这立即排除了任何尝试所有段或以二次方式简单地模拟每个操作的绘制的方法。 任何有效的解决方案都必须处理每个字符恒定的次数，并贪婪地或通过直接分解来构造操作。 

一个微妙的困难是每个操作都会创建四个`>`总共有一个字符，一个位于该段的开头，三个位于该段的末尾。 这意味着`>`角色不是独立的：它们总是处于由操作几何体强加的紧密结构的组中。 另一个问题是操作的内部单元必须匹配`-`，所以任意`>`区间内会阻止某些操作的选择。 

一个天真的尝试可能会尝试贪婪地匹配每一个`>`独立地作为某些操作的开始或结束，但这会失败，因为操作以结构化方式重叠。 另一个常见的失败案例是忽略每个操作的内部必须仅包含`-`在最后的字符串中； 即使是单个`>`在该间隔内将使该操作无效。 

## 方法

 暴力破解的想法很简单：将长度至少为 5 的每个可能的子字符串视为候选操作，模拟应用它，并尝试使用回溯或字符串状态上的 BFS 来到达目标字符串。 这在原则上是正确的，因为我们探索了允许移动的完整状态空间。 然而，每个操作在字符串长度上都是线性的，并且子字符串的数量是二次方的，使得这种方法大致爆炸为$O(n^3)$每个测试用例的行为，这远远超出了任何限制。 

关键的结构观察是每个操作都会创建四个`>`字符，并且它们在段内的相对位置是固定的：开头一个，结尾连续三个。 这意味着每个操作都可以被视为选择一个起始位置`p`和结束位置`r`，其中最后三个位置`r-2, r-1, r`必须是`>`在最后的字符串中，以及位置`p`也必须是`>`。 之间的一切`p`和`r`必须是`-`在最后的字符串中。 

所以每个操作实际上都是四个的结构化分组`>`必须形成非常严格的几何图案的位置。 这减少了从任意字符串构造到分组的问题`>`位置到有效的四元组中，可以作为间隔的端点，没有其他`>`里面。 

构造策略变得贪心：从左到右处理字符串，收集`>`位置，并尽可能连续四个`>`按指数顺序持仓作为一项操作。 这四个位置也必须对应一个有效的区间，如果它们在字符串中是连续的，那么这是保证的，因为没有额外的`>`可以出现在区间内。 

这将问题变成了位置上的线性分区任务`>`。

 ## 算法演练

 1. 扫描字符串并记录该字符所在的所有索引`>`。 这些位置代表必须由操作创建的强制绘制单元。 
2. 遍历列表`>`从左到右的位置并将它们分组为该列表中四个连续位置的块。 每个块将对应于一次绘画操作。 如果在任何时候总数量`>`不能被4整除，构造是不可能的。 
3. 每组四个位置`(a, b, c, d)`按照递增的索引顺序，创建一个从位置开始的操作`a`并结束于位置`d`。 段长度为`d - a + 1`。 
4. 隐式验证`b`等于`a + 1`,`c`等于`a + 2`， 和`d`等于`a + 3`。 如果这不适用于任何组，则输出`No`因为没有有效的段可以产生非连续的内部`>`职位。 
5. 输出所有构造的操作。 

我们在每个组内强制执行连续索引的原因是操作模式将其最后三个索引`>`间隔右端连续位置的字符。 如果选择了`>`原始字符串中的位置不连续，无法将它们映射到`r-2, r-1, r`。 

### 为什么它有效

 每个操作恰好贡献四个`>`最终字符串中的位置，并且这些位置在音程内结构上是刚性的。 因此，每个有效的解决方案都会导致所有的划分`>`位置到大小为四的组中，其元素必须按递增顺序出现，并且没有任何额外的`>`在它们的封闭区间内。 贪婪的构造反映了这种诱导分区：一旦我们修复了最左边的可用分区`>`，唯一可能的有效合作伙伴是接下来的三个`>`紧随其后的位置，因为任何间隙都会引入禁止的`>`或强制非`-`内部的。 只要存在解决方案，这就会强制执行唯一的分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    pos = [i + 1 for i, ch in enumerate(s) if ch == '>']
    
    if len(pos) % 4 != 0:
        print("No")
        return
    
    ops = []
    
    for i in range(0, len(pos), 4):
        a, b, c, d = pos[i:i+4]
        
        # must be consecutive to form valid geometry
        if not (b == a + 1 and c == a + 2 and d == a + 3):
            print("No")
            return
        
        ops.append((a, d - a + 1))
    
    print("Yes", len(ops))
    for p, l in ops:
        print(p, l)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```代码首先提取出所有位置`>`。 然后它检查是否可以将它们分为四组。 每个组都经过验证，以确保它在原始字符串中形成连续的块； 这是必要的，因为每个操作的右端点强制三个连续的`>`人物。 

输出使用每组的最左边和最右边的位置来定义段。 选择这个最小跨度可确保段长度至少为 5，因为四个连续位置的块意味着长度至少为 4，并且只有当这种分组有效时，问题才能保证可行性。

 考虑一个字符串，其中`s = ">>>>---->>>>"`。 

的职位`>`是`[1, 2, 3, 4, 9, 10, 11, 12]`。 

| 步骤| 当前区块| 选择的组 | 运营|

 | 1 | [1,2,3,4] | (1,2,3,4) | (1, 4) |
 | 2 | [9,10,11,12] | (9,10,11,12) | (9, 4) |

 第一个操作从 1 到 4，生成有效的箭头结构。 第二个类似地从 9 跨越到 12。 这证实了可以单独处理独立的连续组。

 ## 边缘情况

 一个关键的边缘情况是当`>`字符不能被四整除。 例如，在像这样的字符串中`">>>>->"`，算法立即拒绝，因为一个操作总是贡献恰好四个`>`人物。 任何组建行动的尝试都将是无与伦比的`>`位置，使施工无法进行。 

另一个微妙的情况是当四个`>`字符存在但不连续，例如`">>->>"`。 即使计数是正确的，间距也会破坏所需的几何形状，因为操作会强制使用最后三个`>`在最后一段中是连续的。 该算法在每组内的连续检查期间检测到这一点并正确输出`No`。 

当存在多个有效组但被分隔开时，会出现最后一种情况`-`地区。 例如，`">>>>---->>>>"`是有效的，因为每个块都可以独立处理。 分组机制自然地将这些段隔离开来，构建独立的操作，互不干扰。
