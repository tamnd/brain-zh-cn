 ## 解决方案
 ## 问题理解

 该系统正在模拟现场比赛，在比赛进行时生成服务器日志流。 有多个级别，并且在任何时刻只有一个级别是“活动的”，由类型 1 的最新日志确定。该活动段之外的日志中的所有其他内容与评分无关。 

在活动级别窗口内，参与者可以报告完成或放弃事件。 然而，只有每个级别的每个参与者的第一个有效事件很重要，它决定了他们是否被认为已成功完成该级别。 完成事件建立一个顺序：第一个完成者获得 m 点，第二个获得 m−1 点，依此类推，其中 m 是参与者的数量。 从未完成该级别或第一次活动就放弃的参与者在该级别的得分为零。 

任务是重建所有级别的最终分数，并输出按总分降序排序的参与者，并按较小的参与者指数打破平局。 

这些约束表明我们无法模拟每个级别的日志或参与者数量的二次方。 由于每个测试最多 2·10^5 个日志事件和最多 10^4 个测试，因此不可能对所有参与者或每个参与者的所有先前事件进行任何按事件扫描。 预期的解决方案必须以接近 O(1) 或 O(log n) 的平摊时间处理每个登录，并且每个参与者只有在实际贡献有效的第一个操作时才必须更新。 

无效消息会产生一个微妙的问题。 参与者可以发送多个类型 2 或类型 3 消息，但只有活动级别下的第一个有效消息才重要。 另一个微妙之处是，必须完全忽略活动级别之外的日志，即使它们包含完成事件。 最后，级别可能永远不会出现，也可能会出现在中途，这意味着只有在第一个 1 类事件之后才开始计分。 

一个幼稚的错误是全局追加所有类型 2 事件而不检查它们是否属于当前级别。 

例如，假设级别 1 仅在类型 1 事件之后才处于活动状态，但我们处理更早的完成：

 输入：```
2 2 3
2 1 1
1 1
2 1 1
```必须忽略第一个完成，因为还没有激活的级别。 仅最后一项赛事才算数，为参与者 1 提供有效的结束结果。 

另一个常见的陷阱是在第一个有效事件之后无法阻止来自同一级别的同一参与者的后续消息。 

## 方法

 一种直接的方法是独立模拟每个级别。 对于当前的活动级别，我们维护一个集合或数组来标记每个参与者是否已经产生了他们的第一个有效事件，以及一个记录完成顺序的列表。 每次出现类型 2 事件时，如果该事件有效并且对于该级别的该参与者来说是第一个，我们会将其附加到终点列表中。 如果这是他们的第一个有效事件，则类型 3 将其标记为失败。 

这在逻辑上是可行的，但挑战是确保我们不会为每个级别重复扫描或重置大型数组。 如果我们为每一层清除一个大小为 m 的数组，并且最多有 n 层，那么这就变成了 O(nm)，这太大了。 

关键的观察是，如果我们可以对使用情况进行时间戳记，那么我们实际上永远不需要重置级别之间的状态。 每个参与者级别的交互对于每个级别仅重要一次，并且每个事件都被处理一次。 因此，我们不是清除数组，而是为每个参与者存储最后一次更新的时间，或者我们维护由参与者键入的每级字典，但仅针对活动条目。 

另一个重要的简化是我们只关心每个级别成功完成的顺序。 确切的时间已经按日志顺序给出，因此我们可以按顺序附加获胜者，并在每个级别的末尾按相反的排名顺序分配分数。 

因此我们模拟一次日志，维护：

 - 当前活动级别
 - 每个级别，成功完成者的列表
 - 每个级别都有一张从参与者到他们是否已经做出决定的地图

 当新的关卡开始时，我们将完成前一个关卡的评分。 

最后，我们计算总数并对参与者进行排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| --- | --- | --- |
 | 每关重置蛮力 | O(n·m + q) | O(n·m) | 太慢了|
 | 使用地图进行懒惰的每级跟踪| O(q + m log m) | O(q + m log m) | O(q + m) | 已接受 |

 ## 算法演练

 1. 按顺序遍历日志，跟踪当前活动级别。 如果尚未激活任何级别，请忽略所有事件。 

活动级别定义了事件重要的唯一上下文。 
2. 当类型 1 事件出现时，如果存在则结束前一级别。 这意味着为该级别的所有记录的完成者分配分数，然后仅清除该级别的本地结构。 为新级别启动一个新容器。 
3. 对于每个活动级别，维护一个字典，记录每个参与者是否已经在该级别中产生了第一个有效事件。 这可以避免重复计算。 
4. 当处理参与者 ID 的类型 2 事件时，如果尚未在该级别中看到该参与者，则将其标记为已完成并将其附加到完成列表中。 
5. 在处理类型3事件时，如果这是参赛者在该级别中的第一个有效事件，则将其标记为失败，并且不将其纳入完成列表中。 
6. 忽略其级别与当前活动级别不匹配的任何事件。 
7. 处理完所有日志后，按照步骤 2 的方式确定最后一个活动级别。 
8. 处理完所有级别后，按照每个级别的完成顺序将 m、m−1、... 分配给完成者来计算分数，并将其累积到全局分数数组中。 
9. 按总分降序对参与者进行排序，如果出现平局则按 ID 升序对参与者进行排序。 

### 为什么它有效

关键的不变量是，对于每个级别，完成列表包含按照其第一次成功完成事件的确切时间顺序排列的参与者，并且每个参与者最多出现一次。 由于评分仅取决于此顺序和参与者数量 m，而不取决于时间间隔或重复消息，因此此结构完全决定了每个级别的分数贡献。 忽略无效级别和重复消息不会更改此不变量，因为它们永远不会在活动级别下贡献第一个有效事件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, q = map(int, input().split())

        score = [0] * (m + 1)

        current_level = -1
        seen = {}
        finish_order = []

        def finalize():
            nonlocal finish_order
            pts = m
            for pid in finish_order:
                score[pid] += pts
                pts -= 1
            finish_order = []

        for _ in range(q):
            parts = input().split()
            t = int(parts[0])

            if t == 1:
                if current_level != -1:
                    finalize()
                current_level = int(parts[1])
                seen = {}
                finish_order = []

            elif t == 2:
                pid = int(parts[1])
                x = int(parts[2])
                if current_level == -1 or x != current_level:
                    continue
                if pid in seen:
                    continue
                seen[pid] = True
                finish_order.append(pid)

            else:
                pid = int(parts[1])
                x = int(parts[2])
                if current_level == -1 or x != current_level:
                    continue
                if pid in seen:
                    continue
                seen[pid] = True
                # do not add to finish_order (failure)

        if current_level != -1:
            finalize()

        result = [(i, score[i]) for i in range(1, m + 1)]
        result.sort(key=lambda x: (-x[1], x[0]))

        for pid, sc in result:
            print(pid, sc)

if __name__ == "__main__":
    solve()
```该解决方案维护一个全局分数数组，并通过一个小的本地状态独立处理每个级别。 这`seen`字典确保每个参与者在每个级别最多贡献一个有效操作。 这`finish_order`list 保留精确的完成顺序，稍后将其转换为递减的点值。 

关键的实现细节是仅重置类型 1 事件的每级状态，而不重置全局状态。 另一个重要的一点是，我们必须忽略级别与活动级别不匹配的事件，因为日志可能包含过时的操作。 

## 工作示例

 考虑一个具有两个级别和三个参与者的简化场景：

 输入：```
1
2 3 6
1 1
2 1 1
2 2 1
3 3 1
1 2
2 2 2

```我们跟踪关卡转换和完成列表。 

| 活动 | 活跃水平| 见过| 完成订单 | 行动|
 | --- | --- | --- | --- | --- |
 | 1 1 | 1 1 | {} | []| 起始级别 1 |
 | 2 1 1 | 2 1 1 1 | {1} | [1] | 参与者 1 完成 |
 | 2 2 1 | 2 2 1 1 | {1,2} | [1,2]| 参与者 2 完成 |
 | 3 3 1 | 3 3 1 1 | {1,2,3} | [1,2]| 在完成列表中被忽略 |
 | 1 2 | 2 | 重置| []| 完成第 1 级 |
 | 2 2 2 | 2 2 2 2 | {2} | [2] | 开始级别 2 |
 | 2 1 2 | 2 1 2 2 | {2,1} | [2,1]| 参与者 1 完成 |

 1 级评分后：1 得 3，2 得 2。2 级后：2 得 3，1 得 2。最终总数反映聚合。 

这证实了级别分离和排序是独立处理的。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(q + m log m) | O(q + m log m) | 每个日志事件被处理一次，排序是最后一步 |
 | 空间| O(m + k) | 分数数组加上每级临时存储|

 ## 边缘情况

 一个重要的边缘情况是来自同一级别内同一参与者的重复消息。 该算法通过以下方式处理这个问题`seen`字典。 一旦参与者被标记，任何后续事件都将被忽略，确保仅考虑第一个有效操作。 

另一个边缘情况是第一级开始之前的日志。 自从`current_level`被初始化为无效状态，所有此类事件都会被安全地跳过。 

最后，日志中永远不会结束的关卡仍然会在最后完成。 决赛`finalize()`调用确保他们的分数的计算完全就像流在最后一个事件之后立即结束一样。
