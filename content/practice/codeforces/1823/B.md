 ## 解决方案
 我仔细分析了失败的原因。 以前的解决方案尝试使用“下一个更大/上一个更大的元素”来计算贡献，但对于 Codeforces 1827B1 的简单版本来说，这种方法**不是正确的算法**。 该技术来自硬版本（具有大数字），其中确切的数组值很重要。 

对于**简单版本**，实际算法要简单得多：

 1. 子数组的美妙之处在于**必须移动的元素数量**才能使用允许的操作对其进行排序。 对于**不同整数**的数组，它等于**“未排序的相邻对”的数量**，或者等效地，位置的数量`i`在子数组中，其中`a[i] > a[i+1]`。 
2.对于长度为1的子数组，beauty = 0。 

对于长度为 2 的子数组，如果两个元素按降序排列，则 beauty = 1，否则为 0。 

对于较长的子数组，您可以通过从每个子数组开始并扩展“未排序的段”来计算美感。 
3. 具有较小的约束（`sum(n) <= 5000`），**O(n^2)** 方法足够快。 对于每个子数组`[l..r]`，我们可以从左到右扫描，跟踪到目前为止看到的最大值，并在下一个元素小于最大值时增加美观度。 

以前的解决方案失败了，因为它尝试基于数组值或段边界的公式，这对于简单版本**无效，尤其是对于任意大的数字。 

这是一个 **正确的 Python 3 解决方案**，使用在约束范围内工作的简单 O(n^2) 方法：```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    res = 0
    for l in range(n):
        mx = a[l]
        for r in range(l + 1, n):
            if a[r] < mx:
                res += 1
            else:
                mx = a[r]
    print(res)

t = int(input())
for _ in range(t):
    solve()
```### 为什么这有效：

 - 对于从索引开始的每个子数组`l`，我们跟踪最大元素`mx`到目前为止所看到的。 
- 对于每一个新元素`a[r]`， 如果`a[r] < mx`，这意味着我们需要一个范围排序操作来放置`a[r]`正确，所以我们增加了美丽计数。 
- 否则，我们会更新`mx = a[r]`。 
- 这准确地模拟了在问题规则下对每个子数组进行排序所需的最少操作数。 
- 每个测试用例的总复杂度为 O(n^2)，这是可以接受的，因为`n`所有测试用例 ≤ 5000。
