 ## 解决方案
 ## 问题理解

 我们被要求构造一个长度的数组$n$仅由 1 和 -1 组成，使得索引对的数量$i < j$具有相等的元素（均为 1 或均为 -1）恰好是$k$。 这个对的数量被称为数组的$A$-特征。 每个测试用例提供$n$和$k$，我们要么生成这样一个数组，要么声明它不可能。 

限制很小：$n \le 100$和$k \le \frac{(n-1)n}{2}$。 这意味着任何解决方案都大致运行在$O(n^2)$每个测试用例是可以接受的，但我们可以通过更结构化的方法做得更好。 关键的挑战是组合：选择放置多少个 1 和 -1，以便它们的组内对总和精确到$k$。 

当出现边缘情况时$k$是不可能实现的。 例如，与$n = 3$和$k = 2$，我们不能将 3 个元素分为两组，这样总和$\binom{c_1}{2} + \binom{c_2}{2} = 2$。 总是试图贪婪地将 1 放在第一位的幼稚算法可能会失败，因此我们需要一种公式化的方法。 

另一个微妙之处是当$k = 0$。 那么任何对都不能乘以 1，这是通过交替 1 和 -1 来实现的。 

## 方法

 暴力方法会尝试所有$2^n$可能的数组，计算$A$- 每个特征，并返回第一个匹配的$k$。 这原则上可行，但即使对于$n = 30$， 自从$2^{30}$大约有十亿种组合。 

关键的见解来自于观察$A$-characteristic 对相同元素内的对进行计数。 如果我们决定放置$x$，其余的$n-x$元素为-1。 那么相等元素对的总数为$\binom{x}{2} + \binom{n-x}{2}$。 这将问题简化为求解二次方程：$$\binom{x}{2} + \binom{n-x}{2} = k$$对于某个整数$x$0 到$n$。 一次$x$找到了，我们可以填写第一个$x$位置为 1，其余位置为 -1。 如果不存在整数解，则答案是否定的。 这可以避免尝试所有数组并保证正确性，因为$A$- 特征仅取决于计数，而不取决于位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n^2)$| O(n) | 太慢了 |
 | 基于计数的构造 |$O(n)$| O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，请阅读$n$和$k$。 初始化一个标志来指示是否找到解决方案。 
3. 迭代$x$从 0 到$n$，表示数组中 1 的数量。 
4. 计算$A$- 该分区的特征：$x \cdot (x-1)/2 + (n-x) \cdot (n-x-1)/2$。 
5.如果等于$k$，构造数组$x$后面跟着的$n-x$减去 并将解决方案标记为找到的。 打破循环。 
6.如果没有这样的$x$循环后发现，打印NO。 否则，打印 YES 和数组。 

为什么它有效：$A$-特性完全由1和-1的计数决定。 通过尝试从 0 到$n$，我们保证如果存在解决方案，我们就会找到它。 这种方法永远不会过度计数或错过可能性，因为每个计数组合都对应于唯一的对总和，并且位置并不重要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        found = False
        for x in range(n + 1):
            a_char = x * (x - 1) // 2 + (n - x) * (n - x - 1) // 2
            if a_char == k:
                result = [1] * x + [-1] * (n - x)
                print("YES")
                print(" ".join(map(str, result)))
                found = True
                break
        if not found:
            print("NO")

if __name__ == "__main__":
    solve()
```该解决方案使用有效地读取输入`sys.stdin.readline`。 对于每个测试用例，它会循环潜在的 1 计数。 这`//`运算符确保整数除法，防止浮点问题。 数组构造使用列表乘法和串联，既简单又避免了差一错误。 早期中断保证我们每个测试用例只打印一个有效数组。

 ## 边缘情况

 对于$k = 0$，算法尝试$x = 0$首先，结果全部为-1，具有A特性$\binom{0}{2} + \binom{n}{2} = \binom{n}{2}$。 由于这可能大于 0，因此算法继续$x = n//2$，最终根据需要交替使用 1 和 -1 以获得 0。对于$n = 2, k = 0$，跟踪：

 - x = 0 → a_char = 1 → 太高
 - x = 1 → a_char = 0 → 解`[1, -1]`这证实了该算法正确处理最小数组和零特性。
