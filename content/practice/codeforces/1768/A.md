 ## 解决方案
 ## 问题理解

 该问题要求我们找到最大的整数`x`小于给定整数`k`使得总和`x!`和`(x-1)!`可以整除`k`。 用简单的语言来说，我们想要一个下面的数字`k`将其阶乘与前一个数字的阶乘相加得到的倍数`k`。 每个测试用例都是一个整数`k`，我们需要输出对应的`x`或者`-1`如果不存在这样的号码。 

看看约束条件，`k`可以大到十亿，我们可能有多达一万个测试用例。 这意味着任何显式计算接近数字的阶乘的解决方案`k`是完全不可行的。 阶乘增长非常快，并且`100!`已经超过`10^157`，远远超出实践中的标准整数运算。 因此，尝试直接计算大阶乘的方法`k`不会起作用。 

一个微妙的边缘情况出现非常小的值`k`。 例如，如果`k = 3`，最大的`x`是`2`因为`2! + 1! = 2 + 1 = 3`，可被 3 整除。如果我们天真地尝试`x = k - 1`如果不检查，它可能会起作用，但我们必须理解为什么这种模式成立。 

## 方法

 蛮力方法将迭代`x`从`k-1`下降到`1`, 计算`x! + (x-1)!`，并检查整除性`k`。 这在数学上是正确的，但在计算上却失败了。 计算阶乘高达`10^9`是不可能的。 即使使用模运算，阶乘序列也会很快超过任何可行的整数大小，因此这种方法太慢并且占用内存。 

关键的观察结果是总和`x! + (x-1)!`可以重写为`(x-1)! * (x + 1)`。 我们希望这个表达式可以被`k`。 如果`x >= k`,`(x-1)!`已经包含`k`作为一个因素，当`k > 2`，但我们仅限于`x < k`。 所以最大的`x`有效的是`k-1`。 这是因为`(k-1)! + (k-2)!`简化为`(k-2)! * k`，它总是可以被整除`k`为了`k > 2`。 为了`k = 2`，唯一的候选者是`x = 1`。 

我们可以总结一下：对于任意`k >= 3`，答案是`k-1`。 为了`k = 2`，答案是`1`。 不需要显式计算阶乘，这将问题简化为简单的算术。

 ## 算法演练

 1.读取测试用例的数量，`t`。 
2. 对于每个测试用例，读取整数`k`。 
3.如果`k`等于 2，输出 1。这是最大的唯一情况`x`不是`k-1`。 
4.否则，输出`k-1`。 这有效是因为`(k-1)! + (k-2)! = (k-2)! * k`，可除以`k`。 
5. 对所有测试用例重复此操作。 

为什么它有效：关键的属性是阶乘因式分解。 对于任意整数`k > 2`,`(k-2)!`乘以`k`保证可分性。 通过始终采取`x = k-1`，我们确保我们最大化`x`同时保持小于`k`。 特殊情况`k = 2`处理阶乘模式仍然成立的最小界限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k = int(input())
    if k == 2:
        print(1)
    else:
        print(k - 1)
```代码首先读取测试用例的数量。 对于每个测试用例，它都会检查特殊情况`k = 2`因为一般公式`k-1`会产生`1`，这恰好匹配，但为了清楚起见，我们明确地处理它。 对于所有其他`k`，它打印`k-1`，使用数学简化。 快速输入`sys.stdin.readline`确保解决方案高效运行多达 10,000 个测试用例。

 ## 边缘情况

 对于`k = 2`，算法显式返回`1`。 虽然`1! + 0! = 2`可以整除`2`，单独处理可以保证代码清晰，避免公式的误解`k-1`。 为了`k = 10^9`，该算法不计算任何阶乘，直接输出`999999999`，避免溢出并在恒定时间内运行。 对于所有大于 2 的素数或合数，选择`x = k-1`是有效的，因为因式分解`(x-1)! * (x+1)`保证可分性。 这涵盖了约束范围内的所有可能的输入。
