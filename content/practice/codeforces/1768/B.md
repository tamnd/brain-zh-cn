 ## 解决方案
 ## 问题理解

 我们得到了一个排列，意味着数字从 1 到 n 的重新排列。 一步操作中，我们选择任意 k 个元素，将它们从数组中删除，仅对那些选定的元素进行排序，然后将它们追加到末尾。 数组的其余部分保持其相对顺序。 

任务是计算需要多少次这样的移动才能将排列转换为排序顺序。 

关键限制是所有测试用例中的 n 最多可达 100000，因此任何模拟操作或尝试所选子集组合的方法都会立即变得太慢。 每个测试用例必须避免任何超出线性或近线性的情况。 

一个常见的失败案例来自于假设我们总是可以在每次操作中“修复” k 个放错位置的元素。 例如，如果 k 等于 n，除非已经排序，否则答案始终为 1，因为我们会立即对所有内容进行排序。 但如果 k 很小，元素之间的相互作用就很重要。 

当 k 等于 1 时，会出现一种微妙的边缘情况。在这种情况下，每个操作都会选择一个元素并将其原封不动地附加到末尾，这意味着我们实际上是在旋转元素。 天真的贪婪者可能会认为这就像冒泡排序并低估操作。 

另一种失败模式是假设我们可以独立地将元素放置到正确的位置。 实际上，一旦元素移到后面，它们的相对顺序约束就会持续存在，因此进度受全局结构而不是局部修复的控制。 

## 方法

 强力解释将在每一步模拟 k 个元素的所有可能选择，并尝试以最少的移动达到排序顺序。 这在原则上是正确的，因为它探索了操作下可到达的排列的完整状态空间。 然而，分支因子是巨大的，因为每一步有 choice(n, k) 个可能的选择，使得它呈指数级且无法使用，即使 n = 20 也是如此。 

关键的观察是该操作只允许我们将元素“收集”到缓冲区中并在最后按排序顺序重新插入它们。 这意味着已经处于正确相对顺序的元素可以被忽略，并且难度完全取决于有多少元素已经与恒等排列结构对齐。 

正确的观点是跟踪排序排列的哪个前缀已经稳定以及有多少元素相对于它“不合适”。 每个操作最多可以修复 k 个放错位置的元素，但前提是它们选择得当。 这导致了一个计数参数，该计数参数基于有多少元素已经处于正确的相对位置以及有多少元素尚未排序。 

更精确的表征表明，答案取决于从末尾扫描时有多少元素已经位于正确的后缀中。 每个操作最多可以将此后缀扩展 k 个元素，因为每次移动我们只能正确地完全放置 k 个元素。 

这将问题简化为贪婪计数过程而不是任何模拟。

 ## 算法演练

 我们通过将排列顺序与排序顺序（即 1 到 n）进行比较来处理排列。 我们从末尾开始扫描并计算有多少元素已经处于正确的递减后缀位置。 

我们维护一个指针`need = n`，代表我们仍然期望正确放置在末尾的最大值。 我们从右向左扫描数组，每次看到`need`，我们递减`need`。 这测量了有多少后缀已经正确对齐。 

在此扫描之后，如果`need`变为 0 时，数组已排序，无需进行任何操作。 

否则，剩余的不满足前缀的大小等于`need`。 每个操作最多可以“修复” k 个尚未正确放置的元素，因为我们总是可以选择 k 个放错位置的元素并将它们按排序顺序移动到末尾，随着时间的推移，有效地将它们锁定到正确的后缀位置。 

因此所需的操作次数是上限`need / k`。 

### 为什么它有效

 后缀扫描捕获就最终位置而言最长的已经正确的尾部。 该后缀之外的所有内容都必须主动重新定位。 由于每个操作只能将 k 个元素最终确定为正确的最终块，因此我们将问题简化为打包参数：需要多少个大小为 k 的组来覆盖所有放错位置的元素。 没有操作可以修复超过 k 个元素，因为每个操作仅移动 k 个元素，并且对它们进行排序不会在这些 k 之外创建新的正确位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    p = list(map(int, input().split()))

    need = n
    for x in reversed(p):
        if x == need:
            need -= 1

    if need == 0:
        print(0)
    else:
        print((need + k - 1) // k)
```该解决方案独立读取每个测试用例并计算有多少元素已经处于正确的后缀位置。 反向扫描至关重要，因为它确保我们只匹配实际上可以按顺序形成有效最终尾部的元素。 

最终公式`(need + k - 1) // k`是一个标准的上限划分，表示需要多少次完整操作才能覆盖所有剩余的错位元素。 

## 工作示例

 考虑样本，其中`n = 4, k = 2`和`p = [1, 3, 2, 4]`。 

我们从末尾开始扫描：

 | 步骤| 元素| 之前需要 | 行动| 需要之后 |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 匹配 4 | 3 |
 | 2 | 2 | 3 | 跳过| 3 |
 | 3 | 3 | 3 | 匹配 3 | 2 |
 | 4 | 1 | 2 | 匹配 1 不匹配 2 | 2 |

 所以`need = 2`，这意味着两个元素尚未正确对齐后缀。 当 k = 2 时，一次操作就足够了。 

现在考虑`p = [2, 3, 1, 4]`,`k = 2`。 

| 步骤| 元素| 之前需要 | 行动| 需要之后 |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 比赛| 3 |
 | 2 | 1 | 3 | 跳过| 3 |
 | 3 | 3 | 3 | 比赛| 2 |
 | 4 | 2 | 2 | 比赛| 1 |

 这里`need = 1`，因此仍然需要一个操作，因为单个元素仍然会阻止完全对齐。 

这些痕迹表明，该算法不是跟踪交换，而是跟踪最终后缀的结构，该结构已经可以被视为“固定”。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))

        need = n
        for x in reversed(p):
            if x == need:
                need -= 1

        if need == 0:
            out.append("0")
        else:
            out.append(str((need + k - 1) // k))

    return "\n".join(out)

 ## 边缘情况

 当排列已经排序时，反向扫描立即消耗所有值并`need`变为零。 这确保算法正确输出零，而不执行不必要的操作。 

当 k 等于 n 时，只要排列尚未排序，公式就会减少为一次操作，这与我们可以一次选取所有元素并对它们进行排序的事实相匹配。 

当 k 等于 1 时，每个运算实际上将一个元素移动到末尾，因此答案变为尚未位于正确后缀中的元素数量，与公式的除以一个行为相匹配。
