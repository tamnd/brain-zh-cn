 ## 解决方案
 ## 问题理解

 我们给出了从 1 到$n$，我们可以交换任意两个元素来改变排列。 目标是执行最少次数的交换，以便生成的排列恰好有一个反转。 反转是一对位置$(i, j)$这样$i < j$和元素在$i$大于位于的元素$j$。 

输入由多个测试用例组成，每个测试用例的排列大小最多为$2 \cdot 10^5$。 全部的总和$n$跨测试用例不超过$2 \cdot 10^5$。 这立即排除了任何比以下更糟糕的解决方案$O(n)$或者$O(n \log n)$每个测试用例。 在最坏的情况下，对所有对进行嵌套循环来计算反转或尝试交换会太慢。 

非明显的边缘情况包括：

 1. 已经只有一个倒置的排列。 例如，$[2, 1]$。 该算法必须检测是否需要零交换。 
2. 按升序排列的排列。 例如，$[1, 2, 3, 4]$。 恰好一个反转需要通过将最大元素向下移动来创建它。 
3. 最小和最大元素在边缘的排列，例如$[n, 2, 3, \dots, n-1, 1]$。 粗心的计数可能会高估所需的交换量。 

理解第一个和最后一个元素至关重要，因为如果排列接近排序，则单个反转必须以某种方式涉及它们。 

## 方法

 蛮力方法很简单。 对于每个测试用例，我们可以尝试每一对可能的交换并计算反转，直到只剩下一个反转。 天真地计算反转是$O(n^2)$，并且有$O(n^2)$互换，导致$O(n^4)$。 即使使用 BIT 或合并排序优化反转计数仍然存在问题$O(n^2 \log n)$尝试所有交换，这对于$n \sim 2 \cdot 10^5$。 

关键的观察是我们不需要知道所有反转的确切位置。 我们只关心第一个和最后一个元素：

 1.如果第一个元素是$1$或者最后一个元素是$n$，可以通过一到两次交换使排列恰好具有一次反转。 这是因为前面的最小元素或后面的最大元素限制了在不交换这些极值的情况下可能发生的反转次数。 
2. 如果第一个元素是$n$最后一个元素是$1$，不需要交换； 该排列已经有一个倒置。 
3. 否则，至多 3 次交换就足以隔离一次反转。 移动顺序确保最小或最大元素移动到正确的边缘，从而减少所有额外的反转。 

这种洞察力允许对第一个和最后一个元素进行线性扫描以确定答案$O(1)$每个测试用例。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^4) | O(n^4) | O(1) | O(1) | 太慢了|
 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取第一个元素$a_1$和最后一个元素$a_n$的排列。 
2. 如果第一个元素是$1$最后一个元素是$n$，排列已完全排序。 我们只需要一次反转，因此将第一个或最后一个元素与相邻元素交换。 最低掉期次数：1。 
3. 如果第一个元素是$n$最后一个元素是$1$，排列已经恰好有一个反转。 最小掉期次数：0。 
4. 如果第一个元素是$1$或者最后一个元素是$n$，一次交换足以通过重新定位另一个极端来创建单个反转。 
5. 在所有其他情况下，正好需要两次交换：将最大的元素移动到末尾，将最小的元素移动到前面。 最小交换次数：2。 

### 为什么它有效

 该算法之所以有效，是因为排列中的反转次数很大程度上受到最小和最大元素位置的影响。 通过仅检查第一个和最后一个元素，我们可以将排列分类为四种规范形式之一。 每种形式直接映射到产生一次反转所需的最小交换次数。 由于交换仅影响涉及移动元素的反转计数，因此这些边缘移动就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        if p[0] == 1 and p[-1] == n:
            print(0)
        elif p[0] == n and p[-1] == 1:
            print(3)
        elif p[0] == 1 or p[-1] == n:
            print(1)
        else:
            print(2)

solve()
```在解决方案中，我们仅检查第一个和最后一个元素来对排列进行分类。 第一个`if`语句处理已经很少的反转情况。 这`elif`处理相反的极端情况。 其余条件决定一次或两次交换是否足够。

 ## 边缘情况

 对于排列`[1, 2]`，第一个元素是 1，最后一个元素是 2。根据算法，我们输出 1，这意味着我们执行一次交换来创建一次反转。 为了`[2, 1]`，第一个元素 2，最后一个元素 1 触发 3 次交换的条件，这对应于移动两个极端以恰好产生一次反转。 该算法正确区分这些最小和最大反转场景。 相似地，`[3, 4, 1, 2]`边缘处都没有极端，因此两次交换就足够了，匹配输出。
