 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组和两种可应用于元素的可选操作，具有全局限制和每个元素限制。 每个元素最多可以被每种操作类型修改一次，但是在整个数组中，我们还受到每种类型可以执行的总应用程序数量的限制。 

第一个操作将数字大约减少一半，向上舍入。 第二次运算减去一个固定值`b`，但永远不会低于零。 我们希望以任意顺序应用这些操作，尊重所有约束，以便数组的最终总和尽可能小。 

重构这一点的一个有用方法是，每个元素最多有四种可能的状态：未触及、减半一次、减去一次或以任一顺序应用。 然而，全球限制`k1`和`k2`意味着我们无法在不考虑元素间操作竞争的情况下独立为每个元素选择最佳状态。 

测试用例的总规模较小，总规模较小`n`最多 5000。这强烈表明`O(n^2)`或者`O(n log n)`每个测试用例的方法是可以接受的，但是任何三次或涉及所有候选者重复的每个元素重新计算的方法都会失败。 

当两个操作在同一元素上交互不良时，就会出现微妙但重要的边缘情况。 例如，如果`a = [10]`,`b = 6`，我们可以先减半后减，或者先减后减半，并且顺序会改变最终结果，因为减半会向上舍入。 独立处理操作的天真贪婪者会错过这种交互。 

另一个边缘情况是当`b`比大多数元素都大。 然后，操作类型 2 相当于将所选元素清零，真正的决定是对于某些较大的值是否仍然值得减半，或者应该跳过以保留操作预算以实现更好的目标。 

## 方法

 蛮力的想法是考虑每个元素并尝试所有可能的选择：不进行操作，仅减半，仅减法，或两者兼而有之。 对于每个配置，我们还需要决定哪些元素消耗有限池`k1`和`k2`。 这变成了一个组合分配问题：对于每个元素，我们选择一个状态，然后我们选择最多`k1`减半及最多的元素`k2`减法的元素，但这些选择是纠缠在一起的，因为应用运算会改变其他选择的增益。 

直接的暴力破解会枚举每个元素的状态，然后尝试遵守全局限制的所有子集。 即使每个元素只有四种状态，检查分配的可行性也会呈指数级增长，因为我们本质上是选择最多`k1 + k2`跨业务运营`n`具有依赖关系的元素。 

关键的见解是每个元素的操作在结构上是独立的，但仅通过计数进行竞争。 这使我们能够将每个元素视为贡献一小组“选项”，每个选项都有成本降低和一对资源使用`(type1, type2)`。 

我们可以计算每个元素：

 - 无操作
 - 仅类型 1
 - 仅类型 2
 - 输入 1，然后输入 2
 - 输入 2，然后输入 1（结果相同，但中间推理可能不同；事实上，我们计算每个组合的最佳最终值）

 一旦每个元素被缩减为一小组候选增益，问题就变成：最多选择`k1`类型 1 用途的项目最多`k2`类型 2 的使用，最大化总节省价值。 

这是一个经典的多项选择选择问题，但该结构允许在分离贡献后采用贪婪排序策略。 

重要的观察结果是，类型 1 和类型 2 每个元素最多应用一次，因此每个元素最多为每个池贡献一个单位。 这让我们可以评估边际收益，然后按收益对决策进行排序。 

如果我们满足以下条件，我们可以有效地计算每个元素的最佳增益：

 - 什么也不做
 - 仅适用减半
 - 仅应用减法
 - 两者都适用

 然后，我们将其转化为候选改进，并通过在尊重预算的同时优先考虑更高的收益来解决冲突。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个元素，计算其基线值和不应用任何操作后的值。 这只是原始数组的总和。 
2. 对于每个元素，计算应用类型 1 一次后的结果：replace`a[i]`和`(a[i] + 1) // 2`。 增益为`a[i] - halved_value`。 
3.应用类型2一次后计算结果：替换`a[i]`和`max(a[i] - b, 0)`。 增益为`min(b, a[i])`。 
4. 计算应用这两个运算时的结果。 由于上限划分导致顺序很重要，因此评估两个顺序：

 先减半再减半，再先减半再减半。 取其中最小的结果值并计算相对于原始值的增益。 
5. 对于每个元素，我们现在最多有四个具有不同“资源使用模式”的候选状态：none、type1、type2、both。 将每个状态转换为包含增益、类型 1 使用情况和类型 2 使用情况的元组。 
6. 收集元素中除“none”状态之外的所有候选状态。 我们将选择这些候选者的子集，以最大化总收益，同时不超过`k1`和`k2`，并确保我们为每个元素最多选择一个状态。 
7. 按收益降序对候选者进行排序。 迭代它们并贪婪地选择一个候选者，如果它不违反剩余的`k1`,`k2`，并且如果其元素尚未被使用。 
8. 从初始数组总和中减去所选增益的总和即可得到最终答案。 

为什么这种贪婪的工作与以下事实有关：每个元素最多贡献一个选定的改进，并且每个改进最多消耗每种资源的一个单位。 按增益排序可确保我们始终首先采用最有价值的可用转换，并且通过跳过已使用的元素或耗尽的预算来处理冲突。 

### 为什么它有效

 每个元素都被有效地压缩为一小组相互排斥的改进选择。 任何有效的解决方案都对应于在两个独立的容量约束下每个元素最多选择一个选择。 因为每个选择都有标量收益和单位资源使用，所以问题简化为双方资源受限的选择，其中当冲突仅通过共享资源和每个元素的排他性产生时，贪婪的收益是最优的。 不变的是，在任何步骤中，所选集合是迄今为止考虑的所有候选集合中关于排序增益顺序和可行性约束的最佳可实现子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, b, k1, k2 = map(int, input().split())
        a = list(map(int, input().split()))

        base_sum = sum(a)
        candidates = []

        for i, x in enumerate(a):
            # no operation gives no candidate

            # type 1 only
            v1 = (x + 1) // 2
            gain1 = x - v1
            candidates.append((gain1, i, 1, 0))

            # type 2 only
            v2 = max(x - b, 0)
            gain2 = x - v2
            candidates.append((gain2, i, 0, 1))

            # both operations: try both orders
            # 1 then 2
            v12 = max((x + 1) // 2 - b, 0)
            # 2 then 1
            v21 = (max(x - b, 0) + 1) // 2
            v_both = min(v12, v21)
            gain_both = x - v_both
            candidates.append((gain_both, i, 1, 1))

        candidates.sort(reverse=True)

        used = [False] * n
        rem1, rem2 = k1, k2
        total_gain = 0

        for gain, i, c1, c2 in candidates:
            if used[i]:
                continue
            if c1 > rem1 or c2 > rem2:
                continue
            used[i] = True
            rem1 -= c1
            rem2 -= c2
            total_gain += gain

        print(base_sum - total_gain)

if __name__ == "__main__":
    solve()
```该解决方案为每个元素构建所有有意义的转换选择，然后将每个元素视为候选者，并根据其相对于原始值的改进进行加权。 排序可确保首先考虑影响较大的转换。 这`used`数组强制执行以下规则：每个元素只能贡献一个选定的转换，而`rem1`和`rem2`执行全局约束。 关键细节是通过检查两个操作顺序来正确计算“两个操作”情况，因为上限除法使操作不可交换。 

## 工作示例

 ### 示例 1

 输入：```
n=3, b=2, k1=1, k2=1
a = [9, 3, 5]
```我们计算候选变换：

 | 元素| 类型 1 | 类型 2 | 两者 |
 | --- | --- | --- | --- |
 | 9 | 5（增益 4）| 7（增益2）| 3（增益 6）|
 | 3 | 2（增益 1）| 1（增益 2）| 1（增益 2）|
 | 5 | 3（增益2）| 3（增益2）| 1（增益 4）|

 按增益排序：

 （6 对 9 均）、（4 对 5 均）、（4 对 9 类型 1）、...

 我们首先选择（9 个），同时消耗 k1 和 k2。 下一个最佳有效是（5 个两者或 5 个 type1 等），但约束已用尽。 

最终结果：

 总和 = 17，增益 = 6 → 答案 = 11

 该跟踪显示了当组合操作主导单个操作时，算法如何对组合操作进行优先级排序。

最终值：

 这证实了即使一种操作类型完全禁用，该算法也遵守资源限制。

 ## 边缘情况

 一个微妙的情况是，当减法立即消除一个元素时，使得类型 2 比减半更有价值。 用于输入`a = [5], b = 10`，类型 2 产生 0，而类型 1 产生 3。算法正确地将更高的增益分配给类型 2，并在预算允许的情况下选择它，因为增益计算直接捕获全部效果。 

另一种情况是两个操作的交互顺序。 为了`a = 7, b = 3`，先减半给出 4，然后 1，而先减半给出 4，然后 2。该算法显式地评估两个阶并选择最小结果值，尽管不可交换性，但仍确保正确性。 

最后一个边缘情况是元素之间的竞争，以获取有限的资源`k1`和`k2`。 当两个元素具有相同的增益但资源使用模式不同时，贪婪排序可确保在预算发生冲突时仅选择一个元素，并且`used`数组可防止对同一元素进行双重分配转换。
