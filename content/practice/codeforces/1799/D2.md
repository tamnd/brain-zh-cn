 ## 解决方案
 ## 问题理解

 我们得到了一系列必须使用两个 CPU 按顺序执行的程序。 每个程序都有两个运行时间：冷时间（适用于 CPU 最后运行不同程序的情况）和热时间（适用于 CPU 最后运行相同程序的情况）。 我们希望在两个 CPU 上调度程序，以最大限度地减少总运行时间，同时遵守程序顺序执行的要求：一个程序不能在前一个程序完成之前启动。 

输入提供多个测试用例。 每个测试用例由程序顺序、每个程序的冷热时间以及程序数量组成。 输出是每个测试用例的最小总时间。 

约束很严格：$n$和$k$可以达到$3 \cdot 10^5$，并且所有测试用例的总和不超过此界限。 和$t$一样大$10^5$，任何每个测试用例的线性时间差的解决方案都会太慢。 具体来说，一个$O(n^2)$解决方案的性能可达$10^{10}$在最坏的情况下进行操作，这显然是不可行的。 我们的方法必须接近$O(n)$每个测试用例，或者$O(\sum n)$全面的。 

边缘情况并不明显。 例如，一个程序频繁重复的序列需要对每个 CPU 进行仔细的热/冷跟踪。 始终将下一个程序分配给第一个可用 CPU 而不考虑上一个程序历史记录的简单方法可能会过度计算冷时间。 例如，对于输入序列`[1, 1, 1]`和`cold = [10]`和`hot = [1]`，最短时间为`10 + 1 + 1 = 12`。 将第二个程序错误地分配给另一个CPU会产生`10 + 10 + 1 = 21`。 

另一个棘手的情况是当两个程序之间的序列交替时。 选择执行每个程序的 CPU 会影响热时间是否适用，并且处理每个 CPU 最后使用的程序时的小错误可能会导致调度不理想。 

## 方法

 暴力解决方案会尝试将所有可能的程序分配给 CPU，同时尊重顺序。 对于每个程序，我们可以决定在 CPU1 或 CPU2 上运行它，根据热/冷规则计算时间，然后递归。 这原则上是正确的，但是作业的数量是$2^n$，对于$n \sim 10^5$。 即使记忆每个 CPU 的最后一个程序状态也只会产生$O(n \cdot k^2)$，对于最大约束来说仍然太慢。 

关键的观察是，在任何时刻，决策仅取决于每个 CPU 上运行的最后一个程序。 我们不需要完整的历史。 我们可以维持两种状态：如果 CPU1 上执行的最后一个程序是，则最小总时间`x`CPU2 上是`y`。 当我们迭代序列时，对于每个程序，我们通过考虑它在该 CPU 上执行为热还是冷并相应地更新总时间来决定在哪个 CPU 上运行它。 这将问题简化为动态编程方法，当我们按顺序处理序列的每个元素时，该方法会更新两个“最后一个程序”状态。 

该观察结果允许线性时间解决方案。 对于序列中的每个程序，我们只需要检查两个选项：将其放置在 CPU1 或 CPU2 上。 我们根据热/冷条件计算增量成本并相应更新总时间。 仅跟踪每个 CPU 执行的最后一个程序就足以保证正确性。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化两个变量`last1`和`last2`到`-1`代表CPU1和CPU2上执行的最后一个程序。 同时初始化`time1`和`time2`为 0，表示如果最后一个程序分别在 CPU1 或 CPU2 上，则到达当前点的累积时间。 
2. 迭代每个程序`p`在序列中。 对于每个程序，如果我们将其放置在 CPU1 或 CPU2 上，请计算新时间。 成本是`hot[p]`如果CPU最后执行`p`， 否则`cold[p]`。 
3. 对于CPU1，新的累计时间是以下最小值`time1 + cost_on_CPU1`和`time2 + cost_on_CPU1`，因为我们可以切换CPU。 CPU2 的更新类似。 这里，`time1 + cost_on_CPU1`对应于在前一个 CPU1 程序之后在 CPU1 上运行，并且`time2 + cost_on_CPU1`对应于CPU2程序之后在CPU1上运行。 
4. 计算出两个新时间后，更新`last1`和`last2`适当地分配给当前程序，并将新的累积时间分配回`time1`和`time2`。 
5. 处理完整个序列后，最小总时间为`min(time1, time2)`。 这表示以最短的运行时间完成任一 CPU 上的最后一个程序。 

为什么它有效：该算法保持了以下不变式：`time1`和`time2`考虑到最后执行的程序，始终存储每个 CPU 的当前程序的最小总时间。 通过仅考虑每个 CPU 的最后一个程序历史记录并增量更新，我们探索所有可行的调度，而无需完全递归，从而确保最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        cold = list(map(int, input().split()))
        hot = list(map(int, input().split()))

        last1 = last2 = -1
        time1 = time2 = 0

        for p in a:
            p -= 1  # convert to 0-based indexing
            cost1 = hot[p] if last1 == p else cold[p]
            cost2 = hot[p] if last2 == p else cold[p]

            new_time1 = min(time1 + cost1, time2 + cost1)
            new_time2 = min(time1 + cost2, time2 + cost2)

            last1 = last2 = p
            time1, time2 = new_time1, new_time2

        print(min(time1, time2))

solve()
```我们将程序转换为基于 0 的索引以进行数组访问。 对于每个程序，我们使用最后一个程序历史记录来计算两个 CPU 选项的增量成本。 最小更新确保考虑切换 CPU。 环境`last1`和`last2`每次迭代中的当前程序简化了下一步的成本计算并避免了相差一的错误。
