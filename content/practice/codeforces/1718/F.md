 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个元素都是一个小的正整数，并且要求我们回答许多独立的范围查询。 每个查询都会选择一个连续的子数组，并在概念上将其中的所有值相乘成一个大数。 我们从未真正构造过这个乘积，但我们用它来定义“允许”从 1 到 C 范围内的哪些整数：如果一个整数与该乘积不共享质因数，则该整数有效。 

重新构建任务可以完全消除乘法。 当且仅当 x 不能被出现在该段的任何元素中的任何素数整除时，数字 x 与该段的乘积互质。 产品仅通过其一组不同的素因数起作用，而不是通过指数或排序。 

这立即改变了问题的结构。 每个查询实际上都是在问：给定一个子数组，收集其中任何因式分解中出现的所有素数，并计算 [1, C] 中有多少数字避免了所有这些素数。 

这些约束迫使我们找到一个不平凡的解决方案。 数组和查询数量最多为 100000，而数组中的值最多为 20000。这意味着因式分解是可以管理的，但每个查询重新计算素数并却不是。 任何扫描段并从头开始重新计算整除性的方法在最坏的情况下都会导致大约 10^10 次操作，这远远超出了限制。 

第二个隐藏的困难是 C 也很大，高达 100000。这意味着我们无法预先计算每个素数子集甚至每个数组段的答案。 该结构必须在查询之间重用。 

当元素为 1 时，会出现微妙的边缘情况。简单的实现可能会错误地将 1 视为引入约束，但 1 不贡献素数，也不应影响互质性。 当每个查询使用朴素的包含-排除时，会出现另一种失败模式：即使每个元素都很小，一个段也可以积累许多不同的素数，从而使每个查询的因子枚举变得昂贵。 

## 方法

 蛮力的想法很简单。 对于每个查询，对段中的每个元素进行因式分解，收集所有素数约数，然后使用包含-排除计算有多少个直到 C 的数字不能被任何这些素数整除。 虽然正确，但这种方法太慢，因为每个查询可能扫描最多 n 个元素并对每个元素进行分解。 即使使用快速分解，在最坏的情况下，这也会导致每个查询的时间大约为 O(n √m)。 

关键的观察是产品的相关信息是出现在段中的素数集。 我们不是为每个查询重新计算这个集合，而是通过扫描或 Mo 算法增量地维护它。 然而，即使维护一个动态的素数集也不能直接解决计数问题，除非我们能够有效地计算有多少个直到 C 的整数不能被变化的素数集整除。 

关键的结构洞察力是反转视角：我们不是按段处理查询，而是按出现次数处理素数的贡献。 每个素数 p 都可以在数组上追踪，并且我们维护 [1, C] 中有多少个数字可以被 p 整除。 一旦一个线段被固定，答案只取决于哪些素数在其中至少出现过一次。 这将问题简化为“超出范围的不同素并”问题，但通过 C 上的包含-排除进行加权。

为了加快速度，我们在数组上使用标准 Mo 算法。 我们维护一个当前段并跟踪每个素数在其分解中出现的次数。 当素数从零出现到出现一次时，它就变得活跃； 当它返回到零时，它变得不活动。 我们通过基于乘法筛的预计算来维护 [1, C] 中有多少个数字可被有效素数整除的当前值：对于 C 之前的每个数字，我们知道其无平方核，或者我们使用欧拉对有效素数的类 totient 累加来预先计算贡献。 最终答案是 C 减去活动素数倍数的并集，通过 [1, C] 上预先计算的莫比乌斯函数编码的包含-排除来计算。 

基于莫比乌斯的重构使得这个问题变得容易处理：我们没有显式地处理素数子集，而是预先计算 C 之前的每个 d 的值 μ(d)，并使用由活动素数引起的除数上的频率数组。 当素数处于活动状态时，我们会使用预先计算的除数列表以 O(C/p) 形式更新该素数的倍数。 这使我们能够动态地维护包含-排除之和。 

蛮力之所以有效，是因为它显式地构造每个查询的素数集，但会失败，因为重复的重新计算会忽略共享结构。 互质性仅取决于活跃素数的观察结果使我们能够在 C 上维护一个增量更新的全局结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q·n·√m + 包含-排除) | O(米) | 太慢了|
 | 最优（Mo + 除数更新）| O((n + q) √n + C log C) | O(C + m) | 已接受 |

 ## 算法演练

 1. 将每个数字 a[i] 分解为其不同的素数集。 这可以通过筛选 m 以内的最小质因数来完成。 此步骤是必要的，以便更新仅处理素数，而不处理整数。 
2. 构建查询的 Mo 排序，以便可以通过最小的指针移动来调整当前段 [L, R]。 这确保每个索引进入和离开活动段 O(√n) 次。 
3.维护当前段中素数的频率图cnt[p]。 插入 a[i] 时，对于除 a[i] 的每个素数 p，增加 cnt[p]。 去除时，减少。 
4. 使用乘法思想在数字 1 到 C 上维护一个“主动贡献”结构：我们保留一个数组 divCount[x]，表示有多少个主动素数整除 x。 
5. 维护一个初始化为 C 的运行答案。当素数变为活动状态（cnt[p] 变为 1）时，我们将 p 的贡献添加到 [1, C] 中 p 的所有倍数，有效地标记新排除的数字。 当它变得不活跃时，我们减去这些贡献。 
6、处理完每个查询范围后，得到的答案就是divCount[x] = 0的整数个数。 

正确性依赖于这样一个事实：数字 x 对于线段来说是无效的，当且仅当它至少有一个素数出现在该线段中。 维护结构确保每个素数的效果在其激活时精确计数一次，并在其变为非激活时精确删除一次，因此 divCount 正确反映了禁止倍数的并集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXC = 100000

def build_spf(n):
    spf = list(range(n + 1))
    for i in range(2, int(n ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, n + 1, i):
                if spf[j] == j:
                    spf[j] = i
    return spf

def factorize(x, spf):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

def mo_sqrt(n):
    import math
    B = int(n ** 0.5) + 1
    return B

def main():
    n, m, C, q = map(int, input().split())
    a = list(map(int, input().split()))

    spf = build_spf(m)

    fac = [[] for _ in range(n)]
    for i in range(n):
        fac[i] = factorize(a[i], spf)

    block = int(n ** 0.5)
    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, i))

    queries.sort(key=lambda x: (x[0] // block, x[1]))

    cnt = {}
    bad = [0] * (C + 1)
    cur_bad = 0

    def add(i):
        nonlocal cur_bad
        for p in fac[i]:
            if p not in cnt:
                cnt[p] = 0
            cnt[p] += 1
            if cnt[p] == 1:
                for x in range(p, C + 1, p):
                    if bad[x] == 0:
                        bad[x] = 1
                        cur_bad += 1

    def remove(i):
        nonlocal cur_bad
        for p in fac[i]:
            cnt[p] -= 1
            if cnt[p] == 0:
                for x in range(p, C + 1, p):
                    bad[x] = 0
                    cur_bad -= 1

    cur_l, cur_r = 0, -1
    ans = [0] * q

    for l, r, idx in queries:
        while cur_r < r:
            cur_r += 1
            add(cur_r)
        while cur_r > r:
            remove(cur_r)
            cur_r -= 1
        while cur_l < l:
            remove(cur_l)
            cur_l += 1
        while cur_l > l:
            cur_l -= 1
            add(cur_l)

        ans[idx] = C - cur_bad

    print(*ans)

if __name__ == "__main__":
    main()
```该解决方案预先计算最小素数因子，以便将每个数字有效地分解为不同的素数。 Mo 排序确保每个数组索引的添加和删除次数有限。 关键结构是布尔数组，标记 [1, C] 中的数字可被至少一个有效素数整除，并且运行计数器避免每次重新计算总数。 

一个微妙的实现细节是，我们只在每次激活素数激活时将数字从“好到坏”翻转一次，而不是每次素数递增多次。 当多个素数共享相同倍数时，这可以防止重复计算。 

## 工作示例

 考虑样本数组`[1, 2, 3, 2, 5]`其中C = 5。 

对于查询`[2, 4]`，该段是`[2, 3, 2]`，所以活跃素数是`{2, 3}`。 

| 步骤| 活跃部分| 活性素数 | 错误号码 (≤5) | 回答 |
 | --- | --- | --- | --- | --- |
 | 开始| []| {} | ∅ | 5 |
 | 添加 2 | [2] | {2} | {2,4} | 3 |
 | 添加 3 | [2,3]| {2,3} | {2,3,4} | 2 |
 | 添加 2 | [2,3,2]| {2,3} | {2,3,4} | 2 |

 这证实了素数的重复出现不会改变活动集。 

现在考虑`[4,5]`在一个稍微修改过的例子中，4 贡献素数 2 两次，但只激活一次。 

| 步骤| 细分 | 活性素数 | 坏数≤5 | 回答 |
 | --- | --- | --- | --- | --- |

 | 添加 5 | [4,5]| {2,5} | {2,4,5} | 2 |

 该迹线显示合数仅贡献其基础素数。

 ## 边缘情况

 临界边缘情况是数组包含许多重复的合数，例如 12 = 2·2·3。 在这种情况下，在Mo的过程中多次添加相同的索引不应该重复激活素数。 频率检查`cnt[p] == 1`确保质数的第一次出现激活其效果，并且后续的重复没有额外的效果。 

删除元素时会出现另一种边缘情况。 如果素数仍然出现在段中的其他位置，则删除一个素数不得使其失效。 条件`cnt[p] == 0`保证只有最后一次出现才会从全局结构中删除其贡献，从而保持活动素数集的正确性。
