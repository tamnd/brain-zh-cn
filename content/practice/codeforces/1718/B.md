 ## 解决方案
 ## 问题理解

 我们没有得到字符串本身。 相反，对于字母表中的每个字母，我们知道它出现了多少次。 

斐波那契字符串是由连续的相同字符块构建而成。 这些块的长度必须是

 1, 1, 2, 3, 5, 8, ...

 按照这个确切的顺序，停在某个斐波那契数处。 不同的块必须使用与其相邻块不同的字母，否则它们将合并成一个更大的块。 

问题是字母频率的多集是否可以重新排列成某些斐波那契字符串。 换句话说，我们能否将斐波那契大小的块分配给字母，以便每个字母的使用次数与其给定的频率完全相同？ 

频率可以大到$10^9$，但最多有 100 个不同的字母。 测试用例总数为$10^4$。 

第一个观察结果是总字符串长度是固定的：$$S = \sum c_i$$如果字符串是斐波那契数，那么$S$必须等于前几个斐波那契数的总和。 

由于斐波那契数呈指数级增长，因此求和所需的最大可能斐波那契指数为$100 \cdot 10^9$低于 50。这意味着每个测试用例仅涉及几十个斐波那契值，无论频率有多大。 

一些边缘情况很容易被错误处理。 

考虑：```
k = 2
c = [1, 2]
```总长度为3，等于$1+1+2$。 粗心的解决方案可能会立即回答“是”。 事实上，答案是否定的。 长度为1的两个块必须属于不同的字母，因为相邻的块不能使用相同的字母。 分配这两个单元块后，不再保留任何有效分配。 

另一个例子是：```
k = 2
c = [2, 1]
```这是肯定的。 我们可以使用长度块$1,1,2$作为：```
b a a
```其中频率为 2 的字母接收大小为 2 的块。 

一个更微妙的情况是：```
k = 3
c = [3,1,3]
```总长度为7，等于$1+1+2+3$。 许多不正确的解决方案仅检查频率是否可以分解为斐波那契数。 答案仍然是否定的，因为块消耗的顺序很重要。 在构造过程中，剩余的最大斐波那契块可能会被强行放到上一步中使用过的字母上，这是被禁止的。 

关键的困难是不匹配金额。 它在尊重块分配顺序的同时匹配总和。 

## 方法

 蛮力的观点是首先确定总长度等于所有频率之和的斐波那契块。 然后尝试将块分配给字母的每种可能的分配方式，同时确保相邻块使用不同的字母并且准确使用每个频率。 

这显然是正确的，因为它直接搜索有效斐波那契字符串的空间。 不幸的是，它的速度慢得令人绝望。 即使只有 40 个斐波那契块，将每个块分配给最多 100 个字母之一也会产生巨大的搜索空间。 

斐波那契数列的结构提供了更强有力的观察。 

假设总和等于$$f_1+f_2+\cdots+f_m.$$最大的块是$f_m$。 在任何有效的构造中，某个字母必须提供该块的所有字符。 该字母必须至少出现频率$f_m$。 

现在向后看一下构造。 如果一个字母提供了最大的块，我们可以减去$f_m$从它的频率来看。 使用该块后，下一个块$f_{m-1}$不能分配给同一个字母，因为连续的块必须对应不同的字母。 

这创建了一个非常自然的贪婪过程。 

每一步我们都必须放置最大的剩余斐波那契块。 如果没有足够大的频率来覆盖它，那么答案是不可能的。 在所有频率中，将块分配给最大的可用频率始终是安全的。 任何有效的解决方案都必须将当前的斐波那契块放置在某个地方，并且使用最大的堆可以为未来提供最大的灵活性。 

唯一的额外限制是同一个字母不能接收两个连续的斐波那契块。 我们跟踪上一步中使用的频率并暂时禁止它。 

生成的算法重复删除最大有效频率，减去当前斐波那契块，然后重新插入余数。 

这正是公认的贪婪解决方案。

 ## 算法演练

 1. 计算总频率和$S$。 
2. 生成斐波那契数$1,1,2,3,5,\dots$直至其累计金额达到或超过$S$。 
3. 如果累计总和不等于$S$， 输出`"NO"`。 

长度为斐波那契数列$S$必须恰好使用前几个斐波那契块大小。 不可能有其他总长度。 
4. 设斐波那契块为生成序列，并从大到小进行处理。 
5. 将所有频率存储在最大堆中。 
6. 维护用于前一个斐波那契块的字母的索引。 
7. 对于当前斐波那契块大小$f$，提取字母与之前使用的字母不同的最大频率。 

如果不存在这样的频率，则输出`"NO"`。 
8. 如果该频率小于$f$， 输出`"NO"`。 

最大可用频率无法覆盖当前块，因此其他频率也无法覆盖。 
9. 减法$f$从该频率开始，如果它仍然是正数，则将余数推回到堆中。 
10. 将此字母标记为之前使用的字母，并继续下一个斐波那契块。 
11. 如果所有斐波那契块都分配成功，则输出`"YES"`。 

### 为什么它有效

 关键的不变量是在处理斐波那契块之前$f_i$，堆恰好包含剩余的未使用频率。 

我们总是分配当前最大的斐波那契块。 任何有效的解决方案必须选择一些字母，其剩余频率至少为$f_i$。 在所有符合条件的字母中，取最大的剩余频率是安全的，因为它不会影响每个较小的频率。 如果最大的合格频率无法覆盖$f_i$，没有符合条件的频率可以。 

唯一的附加限制是连续的块不能属于同一字母。 该算法通过禁止上一步中使用的字母来明确强制执行此操作。 

贪婪的选择永远不会牺牲有效的解决方案。 证明遵循官方解决方案中使用的相同交换参数：每当有效的构造分配$f_i$当存在较大的合格频率时，交换这些分配不会使后续步骤变得更加困难，因为所有未来的斐波那契块都较小。 

因此，贪婪过程的失败意味着每种可能的构造都会失败。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())

    fib = [1, 1]
    pref = [1, 2]

    LIMIT = 100 * 10**9
    while pref[-1] < LIMIT:
        fib.append(fib[-1] + fib[-2])
        pref.append(pref[-1] + fib[-1])

    out = []

    for _ in range(t):
        k = int(input())
        c = list(map(int, input().split()))

        total = sum(c)

        pos = -1
        for i, s in enumerate(pref):
            if s == total:
                pos = i
                break
            if s > total:
                break

        if pos == -1:
            out.append("NO")
            continue

        blocks = fib[:pos + 1]

        pq = []
        for idx, x in enumerate(c):
            heapq.heappush(pq, (-x, idx))

        last = -1
        ok = True

        for need in reversed(blocks):
            first = heapq.heappop(pq)

            if first[1] == last:
                if not pq:
                    ok = False
                    break

                second = heapq.heappop(pq)

                if -second[0] < need:
                    ok = False
                    break

                rem = -second[0] - need

                heapq.heappush(pq, first)

                if rem:
                    heapq.heappush(pq, (-rem, second[1]))

                last = second[1]
            else:
                if -first[0] < need:
                    ok = False
                    break

                rem = -first[0] - need

                if rem:
                    heapq.heappush(pq, (-rem, first[1]))

                last = first[1]

        out.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(out))

solve()
```第一部分预先计算斐波那契数及其前缀和。 此操作只需执行一次，因为每个测试用例都使用相同的序列。 

对于每个测试用例，我们首先验证总频率是否与斐波那契前缀和匹配。 如果不是，则不可能存在斐波那契数列。 

堆存储对`(-frequency, index)`因此 Python 的最小堆的行为就像最大堆一样。 索引标识字母并允许我们强制执行“与前一个块不同”的条件。 

当最大频率属于先前使用的字母时，我们暂时将其删除并检查第二大频率。 这是唯一可以击败所有剩余频率的候选者。 如果即使该频率也无法覆盖当前的斐波那契区块，则构建是不可能的。 

一个微妙的问题是在继续之前重新插入暂时删除的元素。 忘记这一步会默默地破坏堆状态。 

另一个细节是频率降低到零不会被推迟。 保留零频率条目不会破坏正确性，但会产生不必要的堆操作。

 ## 边缘情况

 考虑：```
1
2
1 2
```总长度为3，符合斐波那契前缀$1+1+2$。 该算法首先处理块2，并将其分配给频率2。剩余的频率1属于同一字母，因此无法分配最终的单元块。 该算法返回“否”。 这捕获了仅检查总和的解决方案。 

考虑：```
1
3
3 1 3
```总长度为7。分配大小为3、2和1的块后，只剩下一个大小为1的频率，但它属于上一步中使用的字母。 堆不包含替代候选者，因此算法正确地拒绝该实例。 

考虑：```
1
1
8
```总长度为 8。斐波那契前缀和不等于 8，因为前缀和为$1,2,4,7,12,\ldots$。 该算法在任何堆处理之前检测到这一点并立即输出“否”。 

考虑：```
1
2
7 5
```总长度为12，等于$1+1+2+3+5$。 该算法按顺序分配块$5,3,2,1,1$，始终选择最大的合格频率。 每一步成功，所有频率都用尽，答案是YES。 这表明贪心策略可以构造非平凡的有效实例而无需回溯。
