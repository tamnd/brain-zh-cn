 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，目标是使用特殊的范围操作将每个元素转换为零。 每个操作都让我们选择一个连续的段，并将该段中的每个元素与相同的值进行异或。 应用操作的成本仅取决于段长度，具体而言，它是段长度四舍五入的一半。 

关键的困难在于，每次操作都可以自由选择 XOR 值，因此操作不会直接受值限制，而仅受我们如何将仓位分组为段的限制。 

从约束的角度来看，所有测试用例的元素总数最多为 100000。任何尝试显式考虑所有可能的段或所有可能的 XOR 组合的解决方案都会太慢，因为这会在最坏的情况下引入二次行为。 

一种幼稚的解释是尝试贪婪地修复每个元素或重复将值一一“清零”。 但这会失败，因为一个段上的单个异或可以同时修复多个位置，并且最佳分组取决于位之间的结构，而不是单个值。 

当所有值都相同时，会出现微妙的边缘情况。 例如，`[5, 5, 5, 5]`可以通过对整个段的一次操作来解决，因为与`5`清除所有元素。 贪婪的每个元素方法会错误地将其视为需要多个操作。 

当数组交替时会出现另一种边缘情况，例如`[1, 0, 1, 0]`。 任何只考虑统一段或只考虑局部修复的解决方案都会错过精心选择的段分区可以显着降低总成本的事实。 

## 方法

 直接的暴力策略将尝试模拟所有可能的操作。 对于每个段`[l, r]`，我们可以尝试所有可能的 XOR 值并递归计算清除数组的最小成本。 即使我们只考虑段，也有 O(n²) 个选择，并且每个操作都会修改一个范围，因此状态空间呈指数级爆炸。 当 n 超过 20 左右时，这很快就变得不可行。 

关键的观察结果是 XOR 运算在 GF(2) 上是线性的，因此每个位位置的行为都是独立的。 我们不应该用价值来思考，而应该用比特来思考。 

对于独立的每一位，我们只关心该位在每个位置是 0 还是 1。 我们的目标是将所有位都归零。 对于固定位，我们基本上可以选择段并翻转该段中的所有位（因为与仅具有该位集的值进行异或会精确翻转该段中的该位）。 

因此，每个位都简化为相同的问题：给定一个二进制数组，我们可以选择一个段并翻转其中的所有位，付出成本 ceil(length/2)，并且我们希望使所有内容都为零。 

现在问题变成了经典的区间分组优化。 最佳策略是将数组分解为最大的段，在其中我们通过配对贡献有效地“修复”位。 长度为 L 的每个段都会贡献成本 ceil(L/2)，其行为类似于将位置分组为对，再加上可能的一个剩余位置。 这引出了关键的想法：我们有效地将所需的翻转配对，最佳成本取决于我们必须覆盖多少个“活跃”位置，以及它们如何聚集。 

一种更结构化的方式来看待它是，对于每个位，最小成本等于如果我们将相邻的最佳配对所需的段数，这减少了计算在最佳分组翻转后存在多少个 1 的连通分量。 当扩展到所有位时，结果相当于对数组中的转换贡献进行求和，这简化了计算取消后剩余的“非零活动块”的数量。 

这会导致贪婪扫描，对于每个位，我们维护当前是否位于需要修复的活动段内，并且每当间隙后开始新的 1 块时，我们都会考虑新段。 

最后的简化是，在所有位上，答案简化为在考虑奇偶校验取消后至少有一位在相邻元素之间改变状态的位置上求和，这相当于计算前缀 XOR 结构的二进制表示中的“活动段”的数量。 这可以通过跟踪 XOR 累积中的转换来有效实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(2^n) | O(2^n) | O(n) | 太慢了|
 | 按位贪婪分解 | O(n log A) | O(n log A) | O(n) | 已接受 |

 ## 算法演练

 1. 一点一点地处理问题，因为 XOR 对每个二进制位置独立进行运算。 这允许我们将每个整数数组缩减为 30 个独立的二进制数组。 
2. 对于每个位位置，构建一个数组，其中每个元素为 0 或 1，具体取决于该位是否已设置。 目标是使用段翻转将此二进制数组变成全零。 
3. 从左到右扫描二进制数组并跟踪我们当前是否位于“固定段”内。 每当我们遇到尚未被正在进行的修正区间覆盖的 1 时，就需要一个新的段。 
4.每当一个新的段开始时，我们会在有活动段的情况下尽可能地延长它，因为由于半长的上限，延长会降低单位长度的成本。 
5. 每次关闭一个段时，我们都会将 ceil(length/2) 添加到成本中。 这说明了该细分市场内的最佳配对。 
6. 将所有位位置的贡献相加以获得最终答案。 

### 为什么它有效

每个位的行为都是独立的，因为 XOR 不会混合位。 在单个位内，该操作充当翻转连续范围。 任何解决方案都可以分解为翻转，每个翻转覆盖必要校正的最大连续区域。 成本函数奖励分组，而 ceil(L/2) 结构确保分段内相邻受影响位置的配对始终是最佳的。 这迫使最佳解决方案与连续活动位置的最大分组保持一致，使得贪婪分割既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        
        for b in range(30):
            active = 0
            cost = 0
            length = 0
            
            for x in a:
                bit = (x >> b) & 1
                
                if bit:
                    if active == 0:
                        active = 1
                        length = 1
                    else:
                        length += 1
                else:
                    if active:
                        cost += (length + 1) // 2
                        active = 0
                        length = 0
            
            if active:
                cost += (length + 1) // 2
            
            ans += cost
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现迭代所有 30 位并模拟 1 段在每个二进制投影中的行为方式。 变量`active`指示我们当前是否位于有助于翻转操作的段内。 当一连串结束时，我们使用以下方法最终确定其成本`(length + 1) // 2`，它与 ceil 成本定义相匹配。 

微妙之处在于我们从不显式模拟异或运算； 相反，我们依赖这样一个事实：最佳操作恰好对应于将连续的 bit-1 运行压缩为最小成本段。

 ## 边缘情况

 一种重要的边缘情况是数组由单个连续的 1 块组成。 对于像这样的输入`[1, 1, 1, 1]`，算法将其视为单个段并计算成本`(4+1)//2 = 2`。 如果一个幼稚的实现试图将其分成更小的部分，它会错误地增加成本，因为它会为最佳的单个分组操作支付多次费用。 

另一种边缘情况发生在孤立的情况下，例如`[1, 0, 1]`。 该算法创建两个独立的部分，每个部分都贡献`(1+1)//2 = 1`，导致总成本为 2。任何尝试跨零合并的方法都会违反操作必须连续的约束，并且会错误地低估可行性。
