 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，代表奥林匹克竞赛参与者的分数。 对于每对有序的参与者$(i, j)$，我们计算多少“额外”分数$j$相比于$i$，但前提是$j$更好。 正式地，对于每对我们采取$\max(a_j - a_i, 0)$，然后我们对所有对进行求和。 

查看任务的另一种方法是固定参与者$i$看看其他人。 对于每一个$j$得分高于$i$, 参与者$i$贡献为零且参与者$j$贡献差异$a_j - a_i$。 目标是所有此类比较的累计贡献总额。 

输入大小决定了解决方案必须有多激进。 直接检查所有对的二次方法一旦出现就变得不可行$n$增长超过几千，因为$n^2$操作已经超出了典型的限制$n \approx 10^5$。 这立即表明必须简化表达式的结构，以便可以汇总贡献而不是逐对枚举。 

朴素推理的一个常见失败案例是错误处理顺序或重复计算。 例如，使用输入$[1, 3, 2]$，人们可能会错误地仅对相邻差异求和，或者忘记比较的两个方向都包括在内，但由于 max 函数而不对称。 正确的答案需要考虑所有有序对，而不仅仅是相邻元素或排序邻居。 

另一个微妙的陷阱是假设对称性：表达式是有方向的。 例如，$a_j - a_i$仅当正数时才做出贡献，因此交换指数会改变货币对是否做出贡献。 任何将对视为无序的方法都会失败。 

## 方法

 蛮力方法直接遵循定义。 对于每个索引$i$，我们迭代所有$j$, 计算$a_j - a_i$，如果为正则添加。 这是正确的，因为它显式检查每个有序对并完全按照定义应用公式。 然而，这需要$n^2$评估，并且每次评估都是恒定时间，因此总工作量呈二次方增长。 对于大输入，这变得太慢。 

关键的观察是表达式仅取决于值的相对顺序，而不取决于它们在原始数组中的位置。 对于固定对$i, j$，只有值很重要：如果$a_i \ge a_j$，贡献为零； 否则就是$a_j - a_i$。 这使我们能够通过将相等或有序的值分组在一起来重新组织计算。 

一旦值被排序，每一对$i < j$准确贡献$a_j - a_i$，因为订购保证$a_j \ge a_i$。 这完全消除了对 max 函数的需要，因为负数永远不会按排序顺序出现。 该问题简化为对所有递增对的差异进行求和，这可以使用前缀和来表示：对于每个位置$i$，我们计算一下大了多少$a_i$比之前的所有元素都重要，并有效地积累这些贡献。

 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|

 ## 算法演练

 1. 对数组进行非降序排序。 这确保了对于任何一对$i < j$，我们有$a_i \le a_j$，这消除了在总和中进行条件检查的需要。 
2. 维护已处理元素的运行前缀和。 这使我们能够计算每个位置在恒定时间内早期元素的总贡献。 
3. 迭代已排序的数组。 在每个索引处$i$， 对待$a[i]$作为所有对中较大的元素$(j, i)$在哪里$j < i$。 
4. 计算贡献$a[i]$作为$i \cdot a[i] - \text{prefixSum}$。 该表达式表示之间的差异之和$a[i]$以及所有先前的元素，从代数上展开$\sum (a[i] - a[j])$。 
5. 将此贡献添加到最终答案中。 
6. 通过添加更新前缀和$a[i]$，为下一次迭代做好准备。 

关键思想是，每个元素都被处理为涉及较小元素的所有对的“右端点”，并且所有此类贡献都聚合在一个算术表达式中。 

### 为什么它有效

 排序后，每条有效贡献$\max(a_j - a_i, 0)$变得简单$a_j - a_i$什么时候$j > i$，因为排序保证了非负性。 每个元素$a[i]$作为与先前元素的所有对的较大一侧，仅贡献一次，并且前缀和确保我们正确地减去那些较小元素的总和。 这保证了每个有序对都被精确地计算一次，并且具有正确的符号差。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    res = 0
    pref = 0
    
    for i, x in enumerate(a):
        res += i * x - pref
        pref += x
    
    print(res)

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序，使比较变得定向且单调。 变量`pref`存储当前索引之前的所有元素的总和。 每一步，`i * x`表示所有先前元素都等于零时的总贡献，并减去`pref`对此进行更正以考虑其实际值，从而产生差异之和。 

一个常见的错误是更新`pref`在计算贡献之前，这会错误地将当前元素包含在其自己的计算中。 此处显示的顺序通过首先计算贡献，然后更新前缀和来避免该问题。

 ## 边缘情况

 对于相等的值，排序数组在每一步都会产生零贡献，因为`i * x`与跨相同元素缩放的前缀和完全匹配。 用于输入`5 7 7 7 7 7`，每次迭代都会产生零差异，因为没有元素严格小于或大于以产生正差异的方式。 

对于严格减少输入，例如`4 3 2 1`，排序将其反转为`1 2 3 4`，并且算法在正确的方向上计算所有成对差异。 在`i = 3`， 价值`4`贡献`3*4 - (1+2+3) = 12 - 6 = 6`，它对应于与所有先前元素的差异。 前面的每个步骤都类似地累积所有有效对，确保完全覆盖而不重复。
