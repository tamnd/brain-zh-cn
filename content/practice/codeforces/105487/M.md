 ## 解决方案
 ## 问题理解

 树以父表示形式给出，因此除根之外的每个节点都有一个父节点，并且边隐式向上指向该根。 我们被要求使用几个有向线段精确地覆盖每个树边缘一次。 每个段必须从叶子开始，然后沿着父链接向上移动，直到停在某个祖先处。 不同的线段不能在边上重叠，并且每条边必须恰好属于一个线段。 

另一种看待这一问题的方法是，我们将所有根向路径分解为叶到祖先链的集合，其中允许每个链在任何祖先处提前停止，但所有链的并集必须划分树的边缘集。 在所有此类分解中，我们关心任何链的最大长度（以边为单位），并且我们希望该最大值尽可能小。 

这些约束强烈地推动近线性解决方案。 所有测试用例的节点总数最多为 2×10^5，因此每个测试用例即使稍微超线性的任何解决方案只有在摊销线性时才会通过。 试图显式地枚举或模拟每个边或每个可能端点的段选择的简单方法将立即失败，因为如果不小心实施，即使每个测试用例的 O(n log n) 也会变得紧张，但在全局范围内仍然可以接受。 

一个微妙的问题出现在段如何在内部节点上交互。 考虑具有多个子子树的节点。 来自不同子节点的多个段可能会到达该节点，但只有一个段可以通过该边继续向上到达其父节点，因为该边必须仅使用一次。 到达该节点的所有其他段都必须在此终止。 像“总是向上扩展一切”这样天真的贪婪想法会失败，因为它会违反节点上方边缘使用的唯一性。 另一个不正确的想法是，一旦段相遇就任意终止它们，这可能会增加子树中的最大段长度，而延迟终止会更好。 

天真的直觉的一个小的说明性失败案例是一棵中心为 1、叶子为 2、3、4 的星形树。如果我们总是向上延伸所有叶子路径，则所有段都为 2→1、3→1、4→1，这是有效且最优的，最大长度为 1。但在更深的链状结构中，过早终止树中较低的长路径可能会迫使另一条路径稍后继承较大的剩余深度，从而意外地增加最大段长度。 决策必须在每个节点而不是每个边缘进行本地协调。 

## 方法

 暴力策略将尝试显式地构建分段。 在每个节点，我们可以尝试所有可能的方法来决定哪些传入子路径继续向上以及哪些子路径终止，递归地探索组合。 每个子节点都会贡献一个选择，因此 d 度的节点会在本地产生 2^d 种可能性，并且这些决策在整个树上相互作用。 即使我们根据可行性进行修剪，全局搜索空间的节点数量也会呈指数增长，因为每个节点都会引入通过共享边向上传播的分支决策。 即使 n 约为 30，这也很快变得不可行，更不用说 2×10^5 了。 

关键的结构观察是树强制执行非常严格的约束：对于除根之外的每个节点，只允许从其子树开始的一条路径通过该节点到达父节点。 所有其他路径必须在其处或下方终止。 这将问题从全局组合问题转换为每个节点的局部选择问题：在所有候选向上路径中，我们必须决定哪一条路径被向上“提升”。

一旦我们这样看待问题，目标就变得清晰了。 每个候选路径都有一个从其叶子到当前节点的当前长度。 如果我们选择一条路径继续，它的长度在传递给父级时会增加一，因此继续一条长路径是有风险的，因为它稍后可能会成为最大值。 因此，在每个节点，我们希望向上传递最短的可用路径，并强制较长的路径在此终止，因为终止会将它们的长度冻结在较小的值。 

事实证明，这种贪婪的选择是足够的，它允许我们使用 DFS 自下而上地处理树，在每个节点维护来自子节点的路径长度列表。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解分段决策 | 指数| O(n) | 太慢了|
 | 自下而上的贪婪DFS | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们使用深度优先遍历来处理树，为每个节点计算源自其子树的向上路径长度集。 

1. 从根执行 DFS。 对于每个节点，递归计算每个子节点返回的路径长度列表，其中每个长度表示从该子子树中的叶子开始并到达当前节点的路径。 
2. 从子节点返回时，将每个返回的长度加一以考虑子节点和当前节点之间的边。 这代表将所有路径向上提升一级。 
3. 将所有子级的所有此类路径长度收集到一个列表中。 每个元素代表当前结束于当前节点的候选段。 
4. 如果该节点不是根节点并且至少有一条候选路径，则选择其中长度最小的一条，并将其标记为继续向上的一条。 原因是，扩展最小路径可以最大限度地降低稍后在上面添加更多边时创建大段的风险。 
5. 该节点处的所有剩余路径均在此终止。 每条终止路径都将其最终长度贡献给全局答案。 
6. 所选的最小路径向上返回到父级，以便它可以继续穿过更高的边缘。 
7. 从根本上来说，没有任何路径需要继续向上。 所有路径都被终止，并且它们的长度被认为是最终的。 

中心不变量是每个节点都强制执行以下规则：允许从其子树开始的一条路径向上穿过其父边，并且所选择的路径始终是当时可用的最短路径。 这确保了较长的路径总是尽早确定，防止它们不必要地积累额外的长度。 由于终止决定是不可撤销的，因此延迟较长路径的终止只能增加最终的最大值，而延迟最短路径可以最大限度地减少最终扩展时最坏情况的增长。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parents = [0] + list(map(int, input().split()))
        
        g = [[] for _ in range(n + 1)]
        for i in range(2, n + 1):
            g[parents[i]].append(i)

        ans = 0

        def dfs(u):
            nonlocal ans
            paths = []

            for v in g[u]:
                child_paths = dfs(v)
                for x in child_paths:
                    paths.append(x + 1)

            if not paths:
                return [0]

            if u == 1:
                for x in paths:
                    ans = max(ans, x)
                return []

            paths.sort()
            ans = max(ans, paths[-1])

            return [paths[0]]

        dfs(1)
        print(ans)

if __name__ == "__main__":
    solve()
```DFS 返回一个最多包含一个元素的列表，表示允许从子树继续向上的单个路径。 叶节点返回单个零长度路径。 合并子项时，每条路径都会递增以考虑边缘遍历。 

在每个内部节点，排序用于识别向上传播的最小候选路径。 所有其他路径都会通过更新全局最大值立即最终确定。 根的不同之处仅在于它不能向上传播任何路径，因此所有候选都在那里最终确定。 

关键的实现细节是每个节点仅维护少量的活动路径，通常是聚合后每个子树一个，确保虽然在本地使用排序，但整体复杂性保持接近线性。 

## 工作示例

 考虑一棵小树，其中节点 1 是根，它有子节点 2 和 3，节点 2 有子节点 4。 

输入：```
1
4
1 1 2
```我们跟踪 DFS 回报如下。 

| 节点| 传入子路径（+1 之后）| 选择继续| 在节点完成 | 回答 |
 | --- | --- | --- | --- | --- |
 | 4 | [0]| 返回 [0] | 无 | 0 |
 | 2 | [1] | [1] 继续 | 无 | 0 |
 | 1 | [2,1]| 无 | 2 | 2 |

 在节点2处，唯一的路径是向上传递。 在根 1 处，两条路径都已最终确定，最长的路径为 2。 

这表明根充当所有剩余段的最终收集器。 

现在考虑一个分支结构：```
1
├──2
│   └──4
└──3
```输入：```
1
4
1 1 2
```结构相同，但侧重于根部分支。 

| 节点| 传入路径| 继续 | 定稿 | 回答 |
 | --- | --- | --- | --- | --- |
 | 2 | [0]| [0]| 无 | 0 |
 | 3 | [0]| [0]| 无 | 0 |
 | 1 | [1,1]| 无 | 1 | 1 |

 每个叶子都贡献一个单位路径，并且都终止于根，从而保持最大段长度最小。 

这些痕迹突出显示了算法如何仅延迟最小的可能路径并立即确定所有其他路径。

 ## 边缘情况

 退化链测试算法是否错误地延迟终止。 对于树 1-2-3-4-5，每个节点只向上传递一条路径，因此排序决策并不重要，并且每条边都会将路径长度增加一倍。 该算法在根处正确生成长度为 4 的单个最终路径，与预期的最大值匹配。 

纯星测试算法是否避免了不必要的传播。 在每个叶子处，都会生成一条零长度路径并立即发送到根。 由于所有路径都在根部相交，因此它们都在那里终止，并且最大值仍为 1。任何向上传播多条路径的尝试都是不必要的，但仍然无害； 关键属性是没有路径延伸到一条边之外，并且该算法通过除了每个节点处的最小候选者之外从不强制延续来保留这一点。
