 ## 解决方案
 ## 问题理解

 我们得到一个仅由大写字母组成的长字符串。 我们可以任意重新排列它的字符。 重新排列后，我们查看模式“CCPC”在结果字符串中作为连续子字符串出现的次数。 这些事件允许重叠。 

任务是计算字符串的所有排列中此类出现的最大可能数量。 

输入大小最多可达一百万个字符。 这立即排除了任何试图显式构造所有排列或以组合方式模拟模式布局的方法。 甚至二次或$O(n \log n)$多次重复扫描字符串的大部分的结构如果每个位置做任何繁重的事情，就会太慢。 

唯一重要的信息是字符的频率，因为我们可以自由地重新排序。 因此，问题的结构根本不在于原始排列，而在于我们可以使用可用字母打包模式“CCPC”的重叠副本多少次。 

重叠会产生微妙的边缘情况。 例如，如果我们有足够的字母，模式可以共享字符。 天真的解释可能会假设“CCPC”是不相交的块，但只有在计数允许仔细构造的情况下，像“CCPCC”这样的重叠才包含从位置 1 和 2 开始的两次出现。 然而，重叠仍然受到字符可用性和模式结构的限制，而不是原始字符串中的相邻性。 

另一个重要的边缘情况是计数勉强足够时。 例如，如果 C 少于两个，则无论存在多少个 P，都不可能出现，因为每个有效模式都需要三个 C 和一个 P。 

## 方法

 一个蛮力的想法是考虑构建最终的字符串并尝试将出现的“CCPC”逐一放置。 在每一步中，我们都可以尝试将模式插入到某个位置，减少字符计数，然后继续递归。 这很快就会呈指数增长，因为每个放置选择都会影响所有未来的放置，甚至贪婪的局部放置也是不可靠的，因为重叠的模式可以以多种交互方式进行排列。 

另一种粗暴的解释是尝试字符串的所有排列并计算每个排列中“CCPC”的出现次数。 这是阶乘时间，对于以下情况立即不可行$n = 10^6$。 

关键的观察是只计算物质，并且模式结构很简单：它使用三个 C 和一个 P。然而，真正的困难在于 C 可以在连续出现之间共享，而最佳排列并不是简单地“采用尽可能多的不相交 CCPC 块”。 

我们不考虑位置，而是相反：考虑最大化出现次数的长字符串必须是什么样子。 在最佳安排中，每次出现“CCPC”都会消耗多个字符集，但重叠允许重用中间的 C。 “分隔”结构的唯一字母是 P，因为每个模式恰好包含一个 P，并且 P 不能在出现之间共享。 

这表明“CCPC”的每次出现都有效地锚定在 P 周围，并得到周围 C 的支持。 事实证明，最好的结构是将 P 分组并在它们周围尽可能密集地分布 C。 

核心简化变成：每次出现需要一个 P，每次出现需要三个 C，但 C 只能以有限的方式在相邻模式之间重用。 如果我们想象构建一个最大的模式链，限制因素是我们可以在 3 个块中“花费”可用 C 的次数，同时仍然尊重通过共享 C 的模式重叠。 

生成的结构的行为类似于包装模式，其中每个新出现都会消耗第一个重叠边界之外的一个新 P 和两个新 C，这会导致基于计数的简单最大化。 

因此，我们计算 C 和 P 的计数。答案受到我们拥有的 P 数量以及可以支持链式重叠的 C 组数量的限制。 最终结果是最大 k ，这样我们就可以利用可用资源形成 k 次出现。

 ## 算法演练

 我们首先计算每个字符在字符串中出现的次数，但实际上我们只关心 C 和 P 的计数。 

然后，我们将问题解释为构建最大数量的重叠“CCPC”块。 

1、统计字符串中C字符和P字符的个数。 此步骤从输入中提取所有可用信息，因为重新排列消除了位置限制。 
2. 请注意，“CCPC”的每次有效出现都需要至少一个 P，因此出现的次数不能超过 P 的数量。 这给出了第一上限。 
3. 每次出现也需要三个 C，但由于出现可能重叠，因此我们不会立即将 C 除以 3。 相反，我们认为，如果将 k 个出现放在一个链中，则所需的不同 C 的总数将变为 k + 2。这是因为连续模式在最佳排列的边界处恰好共享一个 C。 
4. 组合约束：我们需要至少 k 个 P 和至​​少 k + 2 个 C 来实现最大重叠构造中的 k 次出现。 
5. 求解最大 k，使得 k ≤ P 且 k + 2 ≤ C。 
6. 因此，答案是 min(P, C − 2)，其下界为零。 

关键的推理步骤是认识到最佳重叠将 C 消耗从 3k 减少到 k + 2，而不是 3k。 

### 为什么它有效

 在任何实现 k 次出现的安排中，每次出现都会贡献一个 P，因此 P 是严格的每次出现要求。 对于 C，如果我们尽可能地对齐连续出现的情况，则第一个出现之后的每个新出现仅引入两个新的 C，因为一个 C 被共享为一个出现的尾部部分和下一个结构的前导部分。 这建立了紧密的线性堆积结构。 任何进一步减少 C 使用的尝试都会破坏“CCPC”所需的子字符串结构，因为每次出现都必须包含其自己的内部“CCP”前缀和结束 C 对齐。 因此，导出的界限既是必要的，也是可以实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    c = s.count('C')
    p = s.count('P')
    # k <= p and k <= c - 2
    if c < 3:
        print(0)
        return
    print(min(p, c - 2))

if __name__ == "__main__":
    solve()
```该解决方案完全依赖于频率计数，因此我们避免了最终字符串的任何构造。 条件检查为`c < 3`防止负值`c - 2`，否则会错误地建议有效的事件。 

逻辑`min(p, c - 2)`直接对算法演练中导出的两个独立约束进行编码。 

## 工作示例

 考虑输入`CCPCCPC`。 

我们计算字符数：C = 5，P = 2。 

我们计算约束：P 限制我们最多出现 2 次。 C − 2 = 3，不结合。 所以答案是2。 

| 步骤| C 计数 | P 计数 | 从 P | 绑定 从 C − 2 | 束缚 回答 |
 | --- | --- | --- | --- | --- | --- |
 | 初始化| 5 | 2 | 2 | 3 | 2 |

 这表明即使 C 丰富，P 仍然是瓶颈。 

现在考虑`CCCCP`。 

C = 4，P = 1。 

我们只能形成一次出现，因为 P = 1。C − 2 = 2，所以 C 就足够了。 

| 步骤| C 计数 | P 计数 | 从 P | 绑定 从 C − 2 | 束缚 回答 |
 | --- | --- | --- | --- | --- | --- |
 | 初始化| 4 | 1 | 1 | 2 | 1 |

 这证实了即使有额外的 C，P 也会严格限制构造。

 ## 边缘情况

 对于非常小的字符串，例如`PP`或者`CC`，算法立即返回零，因为 C 小于 3 或 P 为零，因此不存在有效的子字符串。 

对于具有多个 C 但只有一个 P 的输入，例如`CCCCCCCCCP`，算法返回 1。轨迹很简单：C = 9，P = 1，因此 min(1, 7) = 1。该构造使用单个 P 作为锚点，仅消耗必要的 C。 

对于 P 较多但 C 不足的输入，例如`CCCPPPP`，我们得到 C = 3，P = 4，所以答案是 min(4, 1) = 1。尽管 P 很丰富，但 C 约束占主导地位。 

这些案例证实该公式对称地处理这两个约束，并避免了物理上无法实现的过度计算重叠。
