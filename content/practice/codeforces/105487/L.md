 ## 解决方案
 ## 问题理解

 我们有四种拼图，分别标记为 A、B、C 和 D，每种拼图的数量有限。 每件作品都有特殊的边缘几何形状，并且只有当它们的接触边缘以互补的方式兼容时，才可以将其相邻放置，这意味着一侧必须“适合”另一侧。 

我们想要使用这些部件组装一个单一的实心矩形，无论是正方形还是非正方形。 最终形状的边界必须完全平坦，因此外边界上禁止有任何凹痕或突出。 在矩形内部，两个相邻块之间的每条共享边也必须根据相同的匹配规则完美兼容。 

目标不是最小化面积或匹配固定形状，而是最大化我们可以从给定的多重集中使用多少块，同时仍然能够组装一个有效的矩形。 

这些约束意味着我们最多有 10⁴ 个测试用例，每个测试用例的计数最多为 10³。 因此，任何解决方案都必须在每个测试用例中以恒定的时间运行。 任何涉及形状枚举、网格构建或尺寸搜索的事情都会立即变得太慢。 

当试图在不尊重全局配对的情况下进行本地推理时，会出现微妙的失败情况。 例如，假设 A 丰富，但其兼容类型 C 完全缺失。 贪婪的方法可能仍会尝试放置 A 块，但它们都不能在矩形中一致配对，因此正确的答案是该方向的可用贡献为零。 同样，混合不匹配的类型可能会导致部分“几乎有效”的程序集无法闭合为矩形。 

## 方法

 一个自然的起点是考虑实际构建矩形。 人们可以尝试枚举可能的矩形尺寸，并尝试用可用的块来平铺它们，同时尊重边缘兼容性。 这将涉及确定宽度和高度，然后运行可行性检查，将碎片分配到位置并验证所有相邻关系。 

虽然这在概念上很简单，但速度太慢了。 即使我们根据可用块总数限制尺寸，候选矩形的数量与总数成线性关系，并且每次验证都需要扫描网格。 对于多达 10⁴ 的测试用例，这很快就变得不可行。 

关键的观察结果是，问题从来不真正取决于几何布局。 矩形约束强制执行更严格的结构要求：每个暴露的边缘必须是中性的，并且每个内部邻接必须形成有效的互补对。 这迫使结构分解为不兼容类型的独立配对。 

一旦以这种方式查看，几何图形就会消失，我们就会遇到匹配问题。 每个 A 块只有与兼容的 C 块配对时才能有意义，每个 B 块只能与 D 配对。任何未配对的块都是不可用的，因为它不能在不违反约束的情况下出现在边界或内部。 

因此，整个问题简化为在两个独立组中形成尽可能多的有效对。

 | 暴力平铺| O(T·N3)| O(N²) | 太慢了|
 | 配对计数 | O(T)| O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例，并将问题简化为计算可以形成多少个互补对。 

1. 对于 (A, C) 对，计算可以进行多少次不相交匹配。 每场比赛消耗 1 个 A 和 1 个 C，因此可用对的数量为`min(A, C)`。 这代表这两种不兼容的边类型之间所有可能的有效交互。 
2. 对于 (B, D) 对，使用以下公式计算相同的数量`min(B, D)`。 这些线对独立于 A-C 对，因此不会互相干扰。 
3. 每个有效对对应于可以在矩形中安全使用而不会违反边界或邻接约束的两块。 
4. 因此，可用棋子的总数是已形成对数的两倍，即`2 * (min(A, C) + min(B, D))`。 
5. 如果不存在有效对，则结果为零，因为无法形成具有有效边缘的矩形。 

### 为什么它有效

 矩形约束强制每条边全局平衡。 放置在有效配置中的任何部件都必须使其所有暴露的边缘被兼容的邻居中和，这只有通过互补类型之间的精确配对才能实现。 由于除了边缘兼容性之外没有额外的结构限制，因此最优策略始终使用尽可能多的不相交有效对，并且没有重新排列可以增加此计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        A, B, C, D = map(int, input().split())
        ans = 2 * (min(A, C) + min(B, D))
        print(ans)

if __name__ == "__main__":
    solve()
```该实现直接对上面导出的配对逻辑进行编码。 每个测试用例都是独立读取的，不需要辅助数据结构。 

唯一的微妙之处是确保在对两个独立的计数进行求和之后再乘以 2。 早点做不会改变正确性，但保持分组会使对配对结构的依赖变得明确。

 ## 边缘情况

 当所有计数都为零时，两个配对组都为空，结果自然为零。 该算法评估两者`min(A, C)`和`min(B, D)`为零，因此输出正确地变为零，无需特殊处理。 

当一对仅存在一侧时，例如 A 为正，C 为零，`min(A, C)`变为零，防止任何不匹配件的无效使用。 这可以防止错误的直觉，即剩余的 A 块仍然可以形成部分结构。 

当所有计数高度不平衡时，例如一种类型比其伙伴大得多，算法会自动限制较小计数的使用，确保不会过度计数并正确反映在有效矩形中使用多余件的可能性。
