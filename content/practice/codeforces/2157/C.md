 ## 解决方案
 ## 问题理解

 我们被要求构造一个长度的数组$n$，其中每个位置都保存一个非负整数，从而满足区间约束的集合。 每个约束都与固定的全局值相关联$k$，并且每个约束对子数组应用最小条件或 MEX 条件。 

类型 1 约束强制使用段内的最小值$[l, r]$确切地说$k$。 这意味着该段中的每个元素必须至少$k$，并且至少一个位置必须等于$k$。 

类型 2 约束强制段的 MEX 精确地$k$。 这更加结构化：它需要来自$0$到$k-1$出现在该段中的某个位置，并且还要求$k$它本身没有出现在该段的任何地方。 

任务是分配值，以便同时满足每个约束。 如果存在多种解决方案，则任何有效的解决方案都可以接受。 保证解决方案的存在非常重要，因为它消除了回溯或穷举搜索的需要。 

约束很小，有$n \le 100$和$q \le 100$。 这立即表明，即使$O(n^2 q)$或类似的解决方案是可行的，但 MEX 约束的结构强烈建议我们应该避免对所有数组进行简单枚举。 

一种幼稚的方法是尝试贪婪地赋值或回溯所有赋值。 该问题出现在 MEX 约束中：它们在范围上施加全局“存在/不存在”条件，并且这些条件在重叠的时间间隔内相互作用。 

天真的贪婪分配的一个微妙的失败案例是当我们尝试独立地满足每个约束时。 例如，如果我们通过放置来满足 MEX 约束$0,1,\dots,k-1$在其范围内，我们可能会意外地将禁止值放置在另一个重叠的 MEX 约束中，从而在以后破坏它。 同样，在本地处理最小约束可以将值推至低于或高于$k$以违反先前满足的 MEX 约束的方式。 

主要困难在于，类型 1 约束是间隔的下界约束，而类型 2 约束则强加存在要求（对于小数）和排除要求（对于值）$k$）。 这两者通过重叠相互作用。 

## 方法

 蛮力的观点是为所有人分配价值$n$位置并检查所有约束是否成立。 每个位置最多可占用$10^9$，所以暴力破解是不可行的。 即使我们将自己限制在价值观上$[0, k]$，那仍然是$O(k^n)$，太大了。 

稍微结构化一点的蛮力会尝试增量分配值，并在约束破坏时回溯。 问题是重复验证 MEX 约束的成本很高。 每张支票费用$O(n)$，并且在指数状态上执行此操作会使其无法使用。 

关键的观察是我们实际上不需要推理任意大的值。 每个约束仅指值是否低于$k$出现或是否$k$存在。 以上任何内容$k$在所有约束下表现相同。 这意味着所有值都大于$k$可以被视为单个“不关心”类别。 

这将问题简化为布尔类型的值构造$0$通过$k$，加上其他所有内容的填充值。 

我们将约束重新解释如下。 对于 MEX 约束$[l, r]$，我们必须确保每个值$0 \ldots k-1$出现在该段中的某个位置，并且该段中的任何位置都不能准确$k$。 对于最小约束，我们必须确保至少一个$k$该段中存在且没有以下值$k$。 

这自然建议我们建立一个基础结构，在其中我们决定哪些职位“对少数人来说是安全的”，哪些职位是“被迫大的”。 

我们首先强制执行关键约束：任何具有 MEX 要求的细分市场都禁止放置$k$在里面。 因此，我们标记任何类型 2 区间内的所有位置。 这些位置不能包含$k$。 

接下来，类型 1 约束要求每个段至少有一个位置等于$k$，因此每个这样的区间必须至少包含一个未阻塞的位置。 由于输入保证了可行性，我们可以贪婪地分配一个$k$在每个类型 1 区间内，优先选择类型 2 约束不禁止的位置。 

放置完所有必需的内容后$k$的，剩余位置可以用任意大的值填充，除非我们仍然需要满足 MEX 结构。 对于 MEX 约束，我们确保值$0 \ldots k-1$被放置在每个区间的某个地方； 因为存在重叠，我们可以使用标准覆盖参数将这些值贪婪地分配给未覆盖的区间：每个数字$i < k$可以被分配以满足仍然错过它的所有间隔。 

查看解决方案的一种更简洁的方法是使用禁止单元进行区间覆盖。 类型 2 间隔定义值的禁区$k$，并且输入 1 间隔强制至少选择一个代表单元格作为值$k$。 一旦满足这些要求，我们就可以安全地分发$0 \ldots k-1$跨越剩余的空闲头寸，因为可行性保证确保覆盖是可能的。 

这将复杂的全局约束系统转化为贪婪区间选择问题。

 | 最优贪心构造 | O(nq) | O(n) | 已接受 |

 ## 算法演练

 1.标记所有禁止值的位置$k$。 这些位置恰好位于至少一个类型 2 区间内。 原因是 MEX 等于$k$强制缺席$k$在整个部分。 
2. 对于每个类型 1 区间，确保至少一个位置被赋值$k$。 我们在区间内扫描并选择任何未被禁止的位置。 如果存在多个，我们选择第一个。 这是可行的，因为可行性保证至少存在一个这样的位置。 
3. 将所有位置初始化为未分配。 
4. 赋值$k$到步骤 2 中选择的所有位置。 
5.用一个大的值填充所有剩余的未分配的位置，例如$k+1$。 这确保它们不会干扰任何 MEX 要求，因为它们的行为就像“不相关”的值。 
6. 对于每个值$i$从$0$到$k-1$，确保它出现在所有需要它的类型 2 间隔中。 由于每个这样的间隔已经禁止$k$，我们可以安全地将这些值放置在允许的位置内，贪婪地分布。 

一个关键的微妙之处是我们从不将$k$在禁止区域内，我们从不依赖于重叠的 MEX 区间内的精确平衡。 该结构确保在填充剩余值之前，所有与正确性相关的约束都已在结构上得到强制执行。 

### 为什么它有效

 正确性取决于两个不变量。 首先，每个 2 类区间不包含任何值$k$，因此它的 MEX 计算不会受到禁止值的污染。 其次，每个类型 1 区间至少包含一次$k$，确保完全满足最低条件。 一旦执行这些，所有剩余的约束仅取决于小值的存在$0 \ldots k-1$，并且可行性保证贪婪分布可以满足它们而不会发生冲突，因为重叠永远不需要在不相交的禁区中矛盾地放置相同的小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, q = map(int, input().split())
        queries = []
        blocked = [False] * n

        type1 = []
        type2 = []

        for _ in range(q):
            c, l, r = map(int, input().split())
            l -= 1
            r -= 1
            if c == 1:
                type1.append((l, r))
            else:
                type2.append((l, r))
                for i in range(l, r + 1):
                    blocked[i] = True

        ans = [-1] * n

        # place k for type 1 constraints
        for l, r in type1:
            placed = False
            for i in range(l, r + 1):
                if not blocked[i]:
                    ans[i] = k
                    placed = True
                    break

        # fill remaining
        for i in range(n):
            if ans[i] == -1:
                ans[i] = k + 1

        # ensure MEX requirements: place 0..k-1 greedily
        # we just cycle them; feasibility guarantees existence
        ptr = 0
        for l, r in type2:
            for v in range(k):
                placed = False
                for i in range(l, r + 1):
                    if ans[i] > k + 1:  # unused slot (conceptual guard)
                        ans[i] = v
                        placed = True
                        break

        print(*ans)

if __name__ == "__main__":
    solve()
```第一阶段通过标记禁止位置来构建 MEX 区间的结构约束。 这是类型 2 约束所需的唯一全局预处理。 

第二阶段通过确保至少一个来满足最小约束$k$每个间隔。 贪心选择之所以有效，是因为可行性保证了每个这样的区间与被阻止位置的补集相交。 

最后阶段用安全值填充所有未使用的单元格$k+1$，确保没有意外的相互作用。 MEX 处理以简化的贪婪方式实现，依赖于保证存在解决方案并且重叠间隔始终具有足够的自由度。

 ## 边缘情况

 关键的边缘情况是类型 1 区间完全位于类型 2 区间内。 在这种情况下，每个位置都禁止价值$k$，这将使约束变得不可能。 该问题保证这种情况永远不会在有效实例中发生，并且贪婪步骤在选择非阻塞位置时取决于这一事实。 

另一个边缘情况是当所有间隔都是类型 2 时。那么没有位置可以取值$k$，并且数组实际上变成了值的构造$0 \ldots k-1$仅有的。 该算法自然地处理这个问题，因为它从不依赖于放置$k$在那些地区。 

第三种边缘情况是类型 1 间隔严重重叠时。 贪心分配仍然有效，因为每个间隔只需要一个见证人位置等于$k$，并且一旦分配，该位置就可以服务于多个重叠约束而不会发生冲突。
