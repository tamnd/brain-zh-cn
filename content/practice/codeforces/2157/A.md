 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，目标是使其“平衡”。 一个数组是平衡的，如果每个数字`x`其中出现的内容正是如此`x`次。 因此，如果一个数字出现太少或太多次，我们需要删除一些元素来修复它。 例如，`[1, 4, 2, 4, 4, 4, 2]`是平衡的，因为`1`出现一次，`2`出现两次，并且`4`出现四次。 相比之下，`[2, 2, 2]`不平衡，因为`2`出现三次，但应该恰好出现两次。 

输入包含多个测试用例，每个测试用例都有一个大小的数组`n`和之间的值`0`和`n`。 我们的任务是找到达到平衡数组所需的最小删除次数。 

限制相当小：`n`最多 100 个，最多有 500 个测试用例。 这意味着即使是二次方法`n`每个测试用例是可以接受的，因为`100^2 * 500 = 5*10^6`操作，在一秒钟内舒适地适应。 

当数字出现多次但无法达到其“平衡计数”时，或者当数字出现多次时，就会出现一些不明显的边缘情况`0`发生。 例如，一个数组`[0, 0, 0]`应该减少以删除所有零，因为`0`可以出现 0 次，最少删除 3 次。同样，一个数字出现的次数多于其值，例如`[3, 3, 3, 3]`，需要删除以将其计数减少到恰好 3。 

## 方法

 暴力方法将枚举数组的所有可能子集并检查它们是否平衡。 这在理论上是可行的，因为我们可以自由地删除元素，但子集的数量是指数级的，即使对于`n=20`。 

更快解决方案的关键见解是阵列仅具有`n`最多是不同的值，我们可以关注每个数字的频率。 对于每个数字`x`，如果出现`f`有时，只有两个明智的选择：删除所有出现的`x`或者直接离开`x`其中。 选择这两者中较好的一个可以最大限度地减少本地删除。 由于每个不同数字的选择是独立的，因此我们可以通过对每个不同数字的最佳删除求和来计算最小删除。 

我们可以通过使用字典或字典计算频率来有效地实现这一点`Counter`并迭代数组中的所有唯一值。 如果该值为零，我们总是删除所有零，因为平衡数组不能包含零。 如果频率超过该值，我们删除超出的部分； 如果频率小于该值，我们将删除所有出现的情况，因为我们无法“创建”更多该数字。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了|
 | 最佳 | 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，读取数组大小`n`和数组本身。 
2. 使用字典或统计每个数字的出现次数`Counter`。 这给了我们频率`f`对于每个唯一的号码`x`。 
3. 初始化删除计数器。 迭代每个唯一的数字：

 - 如果`x`为零，则将其完整频率添加到删除中，因为零不能出现在平衡数组中。 
- 如果`f < x`， 添加`f`删除，因为我们不能增加出现次数； 唯一的选择就是将它们全部删除。 
- 如果`f >= x`， 添加`f - x`删除，删除多余的出现次数以完全匹配所需的计数。 
4. 处理完所有唯一数字后，输出该测试用例的总删除数。 

为什么它有效：对于每个数字，我们要么完全匹配它的值，要么删除所有实例。 这种局部最优选择保证了全局最小删除计数，因为数字的出现是独立的并且不会影响彼此的有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import Counter

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    freq = Counter(a)
    deletions = 0
    for x, f in freq.items():
        if x == 0:
            deletions += f
        elif f < x:
            deletions += f
        else:
            deletions += f - x
    print(deletions)
```该解决方案首先计算每个数字的出现次数`Counter`。 然后，它迭代唯一编号并应用算法演练中描述的删除逻辑。 使用`Counter`保证 O(n) 计数，并且最多迭代`n`键是有效的。 

## 工作示例

 ### 示例 1

 输入：`[1, 2, 2]`| x| f | 行动| 迄今为止已删除的内容 |
 | ---| ---| ---| ---|
 | 1 | 1 | f >= x → 删除 f-x = 0 | 0 |
 | 2 | 2 | f >= x → 删除 f-x = 0 | 0 |

 输出：0。数组已经平衡。 

### 示例 2

 输入：`[1, 1, 2, 2, 3]`| x| f | 行动| 迄今为止已删除的内容 |
 | ---| ---| ---| ---|
 | 1 | 2 | f >= x → 删除 f-x = 1 | 1 |
 | 2 | 2 | f >= x → 删除 f-x = 0 | 1 |
 | 3 | 1 | f < x → 删除所有 f = 1 | 2 |

 输出：2. 移除一个`1`和单身`3`来平衡。 

这些跟踪确认删除计数是根据每个数字独立计算的，并且与预期的余额相匹配。

            elif f < x:
                deletions += f
            else:
                deletions += f - x
        output.append(str(deletions))
    return "\n".join(output)

 ## 边缘情况

 对于数组`[0, 0, 0]`,`Counter`给出`{0: 3}`。 该算法将所有三个添加到删除项中，因为不能保留零，从而产生 3。`[3, 3, 3, 3]`,`Counter`给出`{3: 4}`。 该算法删除 1 将计数减少到 3，这是正确的。 对于完美平衡的阵列，如`[5, 5, 5, 5, 5]`，不需要删除。 该解决方案始终如一地处理零、计数过多和计数不足。
