 ## 解决方案
 ## 问题理解

 城市是一个有向无环图。 该声明保证妖精一旦离开大厅就永远不会再回来，这正是 DAG 的定义。 

波浪期间`i`， 确切地`i`哥布林出现。 每个妖精都会选择一条有向的路径。 不同的妖精不允许进入同一个大厅。 妖精们合作并选择一系列顶点不相交的路径，覆盖尽可能多的大厅。 

如果妖精能够掠夺图表中的每个大厅，Monocarp 就会失去一波。 

在发出波浪之前，Monocarp 可能会永久禁用顶点的所有传入边或顶点的所有传出边。 每个这样的操作花费一分钟。 由于被堵塞的隧道永远被堵塞，图表只会随着时间的推移而变得更弱。 

波的得分`i`取决于上一波之后和这一波之前执行了多少次阻塞操作。 如果`t_i`在该间隔内执行操作，得分贡献为$$\max(0, x_i - t_i y_i).$$该任务不仅是计算最大分数，而且还输出阻塞操作和波调用的实际序列。 

该图最多包含 50 个顶点。 这是关键的限制。 涉及重复最大匹配的解决方案是完全现实的。 另一方面，任何状态空间指数`n`是不可能的。 

最危险的错误是考虑个别妖精的动作。 可能的路径系统的数量是巨大的。 正确的观点是将整个攻击转化为DAG上的路径覆盖问题。 

考虑带有顶点的 DAG`1 -> 2 -> 3`。 

对于波`1`，单个妖精可以遍历所有三个顶点，因此 Monocarp 输了。 

对于波`0`这是不可能的。 

决定数量不是从特定起始顶点的可达性，而是覆盖所有顶点所需的顶点不相交路径的最小数量。 

另一个微妙的情况是当图已经需要许多路径来覆盖所有顶点时。```
1    2    3    4
```不存在边缘。 

最小路径覆盖尺寸为`4`。 即使没有任何阻挡操作，只有两个哥布林的一波浪潮也永远无法覆盖所有大厅。 

假设总是需要做一些准备的解决方案是错误的。 

## 方法

 从攻击本身开始。 

假设图是固定的。 妖精们选择`i`顶点不相交的有向路径并最大化覆盖顶点的数量。 

一个经典的 DAG 事实表明，最多覆盖的最大顶点数`i`顶点不相交路径等于`n`恰好在 DAG 最多允许大小的路径覆盖时`i`。 

让`pc`表示当前 DAG 的最小路径覆盖大小。 

那么所有顶点都可以被掠夺 iff`i ≥ pc`。 

所以 Monocarp 在浪潮中幸存下来`i`当且仅当$$pc > i.$$这立即将游戏变成了路径覆盖维护问题。 

对于 DAG，$$pc = n - M,$$在哪里`M`是标准 DAG 二分结构中的最大匹配大小。 

因此波的生存`i`相当于$$M \le n-i-1.$$现在看看阻塞操作。 

创建 DAG 路径覆盖的常用二分图。 每个原始顶点在左侧出现一次，在右侧出现一次。 

阻塞顶点的所有出边`v`删除左侧的副本`v`。 

阻止顶点的所有传入边`v`删除正确的副本`v`。 

因此，每个允许的操作只是从二部图中删除一个顶点。 

蛮力的想法是尝试所有的子集`2n`可能的删除并确定最大匹配如何变化。 和`n = 50`，这是没有希望的。 

关键观察要强得多。 

假设当前最大匹配大小为正。 

根据柯尼希定理，每个最大匹配都有一个相同大小的最小顶点覆盖。 任何属于最小顶点覆盖的顶点都可以被删除，删除后最大匹配大小正好减少 1。 

这意味着我们可以重复找到一个顶点，该顶点的删除会使匹配度减一。 

如果原来的匹配尺寸是`F`，我们可以构造一个序列$$v_1,v_2,\dots,v_F$$这样删除第一个后`t`序列的顶点，匹配大小变得精确`F-t`。 

一旦存在这样的序列，问题的图形部分就完成了。 

剩下的任务就是调度。 

让`j`是在 Wave 之前已经执行的删除次数。 

那么匹配大小等于`F-j`。 

海浪`i`是安全的当且仅当$$F-j \le n-i-1.$$现在只剩下一个一维 DP。 

状态`dp[i][j]`表示处理第一个之后的最高分`i`波浪并准确地表演`j`总计删除。 

Transitions决定在wave之前插入多少额外的删除`i`。 

图结构从 DP 中完全消失。 只有执行删除的次数才重要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力删除子集 |$O(2^{2n})$| 指数| 太慢了|
 | 匹配还原序列+DP|$O(n^5)$|$O(n^2)$| 已接受 |

 ## 算法演练

 1. 构建 DAG 路径覆盖二分图。 

左副本`L(v)`代表传出使用`v`, 右副本`R(v)`代表传入的使用`v`。 
2. 计算初始最大匹配大小`F`。 

最小路径覆盖尺寸为`n - F`。 
3. 构建删除序列。 

重复尝试每个仍然有效的二分顶点。 

暂时删除它并重新计算最大匹配。 

如果匹配减少 1，则永久保留此删除并将该顶点追加到序列中。 

找到后`F`这样的顶点，删除第一个`t`序列的元素总是减少匹配`F`到`F-t`。 
4. 运行动态规划。 

让`dp[i][j]`为处理波后的最高分`1..i`恰好与`j`已执行删除操作。 
5. 对于从`k`删除到`j`波前删除`i`：

 该波的准备时间是`j-k`。 

获得的分数是$$\max(0, x_i - y_i (j-k)).$$6. 检查生存能力。 

后`j`删除匹配大小等于`F-j`。 

海浪`i`仅当$$F-j \le n-i-1.$$无效状态将被丢弃。 
7. 存储父指针以重建在每个wave之前插入了多少个删除。 
8. 恢复最佳删除计数。 
9、输出删除序列对应的前缀长度，插入`0`每当有人挥手时。 

### 为什么它有效

 DAG攻击条件相当于询问所有顶点是否最多可以被覆盖`i`顶点不相交的路径。 最小路径覆盖将其转换为最大匹配条件。 

每个阻塞操作恰好是路径覆盖二分图中一个顶点的删除。 

删除序列是有效的，因为每当匹配为正时，就可以删除最小顶点覆盖中的顶点，从而将匹配度减一。 重复这个过程会创建一个序列，其第一个`t`删除总是减少匹配`t`。 

之后，唯一相关的数量是已执行的删除次数。 DP 枚举执行每次删除的每个可行时刻，并选择总分最大的时间表。 每一条有效策略对应一条DP路径，每一条DP路径又对应一条有效策略，这样就找到了最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10 ** 30

n, m, K = map(int, input().split())
edges = [tuple(map(int, input().split())) for _ in range(m)]
xy = [tuple(map(int, input().split())) for _ in range(K)]

alive = [True] * (2 * n)

def max_matching():
    g = [[] for _ in range(n)]

    for u, v in edges:
        if alive[u - 1] and alive[n + v - 1]:
            g[u - 1].append(v - 1)

    match_r = [-1] * n

    def dfs(v, vis):
        for to in g[v]:
            if vis[to]:
                continue
            vis[to] = True
            if match_r[to] == -1 or dfs(match_r[to], vis):
                match_r[to] = v
                return True
        return False

    res = 0
    for v in range(n):
        if not alive[v]:
            continue
        vis = [False] * n
        if dfs(v, vis):
            res += 1
    return res

F = max_matching()

deleted_order = []

for step in range(1, F + 1):
    target = F - step
    for v in range(2 * n):
        if not alive[v]:
            continue

        alive[v] = False
        if max_matching() == target:
            deleted_order.append(v)
            break
        alive[v] = True

dp = [[-INF] * (F + 1) for _ in range(K + 1)]
par = [[-1] * (F + 1) for _ in range(K + 1)]

dp[0][0] = 0

for i in range(1, K + 1):
    x, y = xy[i - 1]

    for j in range(F + 1):
        if F - j > n - i - 1:
            continue

        for k in range(j + 1):
            if dp[i - 1][k] <= -INF:
                continue

            gain = x - y * (j - k)
            if gain < 0:
                gain = 0

            cand = dp[i - 1][k] + gain

            if cand > dp[i][j]:
                dp[i][j] = cand
                par[i][j] = k

best_j = max(range(F + 1), key=lambda j: dp[K][j])

actions = []

cur_j = best_j

for i in range(K, 0, -1):
    prev_j = par[i][cur_j]

    actions.append(0)

    for t in range(cur_j, prev_j, -1):
        idx = deleted_order[t - 1]

        if idx < n:
            actions.append(idx + 1)
        else:
            actions.append(-(idx - n + 1))

    cur_j = prev_j

actions.reverse()

print(len(actions))
print(*actions)
```匹配例程是标准库恩算法。 每边只有 50 个顶点，多次重新计算匹配的成本很低。 

删除序列的构建是最不寻常的部分。 仅当移除顶点使匹配度恰好减少 1 时，顶点才被接受。 一旦接受，删除将成为永久性的，并且下一次搜索将从较小的图表继续。 

DP维度受初始匹配大小限制`F`，这最多是`n-1`。 每个状态代表已执行的特定数量的删除。 

重建阶段向后遍历父表。 如果最佳转换增加了删除计数`p`到`q`，那么正好`q-p`删除操作必须紧接在该 wave 之前插入。

| 波| 波前删除 | 删除总数 |

```与示例输出匹配。

 ## 边缘情况

 没有边的图的匹配大小为零。 最小路径覆盖已经是`n`，所以每一波都是自动安全的。 DP 正确地允许到处进行零删除，因为生存性条件已经满足。 

最小路径覆盖等于 1 的图是相反的极端。 单个定向链可以被一个妖精完全掠夺。 匹配尺寸开始于`n-1`，并且在第一波之前可能需要进行许多删除。 删除序列构造可以处理这一问题，因为它一次不断地减少匹配的一个单元。 

当某些波有巨大的惩罚时，会出现另一种微妙的情况`y_i`。 最佳策略可能会将删除延迟到后面的波，即使这意味着一次执行许多删除。 由于 DP 考虑了每一次转变`k → j`，它评估所有此类计划并选择最好的一个。
