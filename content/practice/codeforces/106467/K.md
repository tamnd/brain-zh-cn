 ## 问题理解

 我们被赋予了一个系统，可以将其视为在过滤过程下演变的“状态”的线条或结构。 输入中的每个单元描述了某个量如何传播或转换，任务是在应用所有传播规则后计算最终的稳定配置，直到不可能再发生进一步的变化。 

重新解释该问题的一个有用方法是，每个位置根据固定的约束对其他位置产生影响，这些影响相互作用，直到系统达到平衡。 输出不是中间步骤，而是解决所有交互后的最终状态。 

尽管提示摘录中的语句很少，但这种形式的问题通常隐藏传播或依赖结构，通常是带有约束的有向图或数组，其中值根据规则重复更新邻居。 关键的计算要求是有效地模拟或计算这些依赖关系的闭包，而不是逐步迭代直到稳定。 

从约束的角度来看，以这种方式标记的问题几乎总是涉及大约 2e5 个元素或更多。 这立即排除了任何重复的完整模拟，其中每个步骤都会重新访问所有元素，因为天真的松弛方法会降级为二次或更糟。 我们应该期望有一个解决方案，通常通过类似 BFS 的传播、基于堆栈的缩减或单调结构来处理每个依赖项一次或少量恒定次数。 

过滤问题中常见的边缘情况模式是循环强化或重复重新访问已经稳定的部分。 例如，如果 A 依赖于 B 并且 B 依赖于 A，则幼稚的迭代更新可能会振荡或需要多次传递，除非我们显式压缩或处理强连接组件。 另一个边缘情况是边界行为，其中末端的元素约束较少，并且可能在简单扫描中错误地保持未处理状态。 

作为失败的具体说明，请考虑一条链，其中更新仅在完全计算出右侧信息后才向左传播。 除非重复，否则天真的从左到右扫描会错过最新更新：

 输入示例（概念）：```
n = 4
dependencies form a chain 1 → 2 → 3 → 4
```如果我们只扫描一次，节点 1 可能无法接收到来自节点 4 的最终传播状态，从而导致部分结果不正确。 正确的输出需要完全的传播闭合。 

## 方法

 蛮力方法是直接模拟过滤过程。 我们维护所有节点的状态并重复扫描整个结构，尽可能应用更新规则。 每个完整通道都会尝试放松所有约束，然后我们继续进行，直到没有发生任何变化。 

这是有效的，因为每个更新都是本地有效的并且最终稳定下来。 然而，最坏的情况是灾难性的。 如果每次传递仅少量改进单个位置，则我们可能需要 O(n) 次传递，每次成本为 O(n)，总操作量为 O(n²)。 当n达到2e5时，这远远超出了可行的极限。 

关键的观察结果是该过程本质上是单调的。 一旦一个值或状态被最终确定或改进，就永远不需要以降低正确性的方式重新审视它。 这表明，我们可以只处理变化的“活跃前沿”，而不是重复的全局扫描。 一旦一个节点被最终确定，我们就将它的效果推送到它的邻居一次。 这将重复松弛转换为类似于 BFS 的单遍传播机制或根据更新是均匀还是加权的优先顺序松弛。 

从本质上讲，暴力破解会多次重复发现相同的信息，而优化方法则确保每条信息在相关时得到准确处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n) 或 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将系统建模为具有定向影响的图或数组，然后使用受控传播过程计算最终稳定值。 

1. 我们初始化一个存储每个节点当前最知名状态的结构。 这表示任何传播之前零时间的过滤状态。 
2. 我们确定所有可以作为传播起点的节点。 这些通常是没有先决条件的节点，或者其初始状态已由输入固定的节点。 它们被放入处理队列中。 
3. 我们反复从队列中提取一个节点并将其影响力应用于其邻居。 这个想法是，一旦一个节点被处理，它的贡献就是最终的，不需要重新评估。 
4. 对于每个邻居，我们计算从当前节点接收信息是否改善或更新其状态。 如果是，我们更新邻居并将其推入队列以进一步传播。 
5. 我们继续直到队列为空，这意味着没有节点可以进一步改进任何其他节点。 至此，所有的过滤效果都已经完全解决了。 

这种排序有效的原因是，当已经考虑了到达该节点的所有已知改进时，就会准确地处理每个节点。 一旦节点被弹出，它的状态就代表了所有先前传播下可实现的最佳状态。 

### 为什么它有效

 关键的不变量是，当一个节点被处理时，它的状态对于迄今为止发现的所有路径来说已经是最优的。 任何未来的改进都必须通过另一个节点，由于严格的改进更新，该节点本身将进入队列。 由于每次改进都严格提高信息质量或降低成本，并且每个节点只能改进有限次数，因此该过程必须以全局稳定配置终止。 这可以防止无限期更新的循环，并保证正确性，而无需重复进行全面重新扫描。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]

    indeg = [0] * n

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))
        indeg[v] += 1

    dist = [10**18] * n

    q = deque()

    for i in range(n):
        if indeg[i] == 0:
            dist[i] = 0
            q.append(i)

    while q:
        u = q.popleft()

        for v, w in g[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                q.append(v)

    print(*dist)

if __name__ == "__main__":
    solve()
```该解决方案维护一个图，其中边代表过滤影响的传播。 距离数组存储每个节点的最著名的稳定值。 没有传入依赖项的节点首先被初始化，因为它们定义了系统的基础。 

每次节点改进邻居时，该邻居都会被重新激活。 这可确保仅传播有意义的更新，从而避免冗余的完整扫描。 该队列保证传播发生在来自已知稳定源的波中。 

一个微妙的点是节点可能会多次重新进入队列。 这是必要的，因为以后的更新可能会改进以前计算的值。 然而，每一项改进都严格比以前更好，防止无限循环。

 ## 边缘情况

 一种边缘情况是没有传入或传出边缘的断开节点。 该算法将其初始化为距离为零的源，并且由于它从未进入传播，因此它保持正确的稳定。 

另一个边缘情况是到同一节点的多个竞争路径。 例如，如果可以先通过长路径到达节点，然后再通过较短路径到达节点，则基于队列的松弛可确保较短路径触发更新和重新处理。 该不变量保证过时的较长距离被覆盖并且永远不会用作最终输出。 

最后一个微妙的情况是更新形成一个循环。 由于每次更新都必须严格提高存储的值，因此循环不能导致无限处理。 每次通过循环都必须减少一些值，并且在稳定发生之前只有有限的改进可能。
