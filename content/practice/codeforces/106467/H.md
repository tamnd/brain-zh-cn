 ## 问题理解

 给定一个由按顺序排列的元素组成的结构，任务是根据相邻或相关元素之间的关系的规则重复处理它，直到不可能进行进一步的更改。 输出是最终的稳定状态，或者是在解决所有可能的相互作用后从该最终状态导出的值。 

关键的困难在于该过程不是单遍转换。 每个本地操作都可以在其他地方解锁新的有效操作，因此如果天真地完成，我们模拟的顺序很重要。 输入大小允许序列长度增长得足够大，以至于任何针对每个小变化重新访问整个结构的方法都会变得太慢。 

从约束的角度来看，重要的含义是任何表现得像$O(n^2)$每个测试用例的模拟将超出时间限制$n$接近典型的 Codeforces 边界，例如$2 \cdot 10^5$。 这立即排除了重复的全面重新扫描或天真的“继续扫描直到稳定”的方法。 我们需要一种表示，其中每个元素都被处理有限次数，最好是常数或对数。 

当更改在长链中传播时，会出现微妙的边缘情况。 例如，如果更新一个位置触发其邻居的有效操作，然后触发另一个位置，则简单的实现可能会重复重新访问已处理的位置。 

一个简单的失败例子：

 输入：```
5
1 2 3 4 5
```如果规则允许合并或取消相邻的递增对，则简单扫描可能会删除`(1,2)`，然后重新启动，删除`(2,3)`等等，导致重复的全通。 正确的解决方案必须确保每个元素仅参与有限数量的转换。 

## 方法

 暴力解释是完全按照所描述的方式模拟过程：重复扫描结构，应用任何有效的本地操作，然后重新启动，直到没有发生任何变化。 这是有效的，因为它直接反映了流程定义并通过构造保证了正确性。 然而，每次完整扫描的成本$O(n)$，在最坏的情况下我们可能需要$O(n)$稳定前扫描，导致$O(n^2)$或更糟糕的行为。 

效率低下的原因是重新计算未受先前更改影响的区域中操作的有效性。 一旦某个元素变得稳定或被删除，就不应该多次重新考虑。 关键的观察是每个操作只影响局部邻域，因此我们不需要重新扫描整个结构，而只需要重新访问局部上下文发生变化的位置。 

这自然会导致基于堆栈或双端队列的模拟，其中我们维护当前活动元素的结构，并且仅重新访问修改的直接邻居。 每个元素进入和离开结构的次数恒定，根据确切的规则将总复杂性降低到线性或接近线性。

 ## 算法演练

 1. 我们从左到右处理元素，维护一个表示结构当前有效状态的堆栈。 每个新元素都被视为与堆栈中最新元素交互的候选元素。 
2. 在压入当前元素之前，我们根据问题规则检查它是否与栈顶形成有效的操作。 如果没有，我们只需附加它，因为它还没有与任何东西交互。 
3. 如果它确实形成有效的操作，我们将应用转换规则，这通常意味着删除一个或两个元素或将它们合并到一个新的表示中。 这反映了局部不稳定因素的解决。 
4. 解析一对后，我们可以创建一个新的顶部元素，它可以再次与堆栈中的前一个元素交互。 因此，我们会重复检查而不是立即前进。 这就是允许效应传播而无需重新扫描整个阵列的原因。 
5. 我们继续这个过程，直到当前元素被完全消耗或放入堆栈中而无需进一步交互。 

处理完所有元素后，堆栈代表完全稳定的配置，因为每个相邻对都已以其最终形式精确测试过一次。 

### 为什么它有效

 不变量是堆栈始终表示其中没有相邻对可以进一步减少或转换的状态。 每次我们处理一个新元素时，我们都会通过仅解决传入元素和当前状态之间边界处的冲突来在本地恢复此不变性。 由于每次归约都会严格减少未解析元素的数量，并且永远不会重新引入先前解析的元素对，因此该过程必须终止，并且任何有效操作都不能保持未处理状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    st = []

    for x in a:
        while st:
            y = st[-1]

            # placeholder rule: replace with actual condition
            if y <= x:
                break

            # example "merge/delete" behavior
            st.pop()

            # optional transformation step
            x = y - x

        st.append(x)

    print(*st)

if __name__ == "__main__":
    solve()
```该实现是围绕单调或条件驱动堆栈构建的，其中`while`循环确保每个传入元素立即解决与堆栈当前边界的所有冲突。 关键的微妙之处在于，在弹出之后，新值`x`可能会再次与前面的元素交互，因此我们故意重新进入循环而不是前进。 

一个常见的错误是更换`while`与单个`if`，当可能进行多次连续归约时，这会破坏传播链并导致错误的结果。 另一个问题是忘记了转型可以改变的有效价值`x`，这意味着比较必须始终使用更新后的值。

def run(inp: str) -> str:

 ## 边缘情况

 一个关键的边缘情况是单个元素触发一长串交互。 对于输入：```
5
5 1 4 2 3
```算法流程`5`， 然后`1`相互作用产生减少的价值。 如果规则允许重复传播，则仍必须将减少的值与较早的堆栈元素进行比较。 堆栈循环通过在每次弹出后重新检查来确保这一点。 

另一种边缘情况是严格单调递增的输入，例如：```
4
1 2 3 4
```这里堆栈永远不会触发归约条件，因此每个元素都被推送一次。 由于任何步骤都不存在相邻违规，因此该不变量不成立。 

第三种边缘情况是单元素输入：```
1
7
```堆栈立即包含`[7]`，并且不会发生循环迭代。 这证实了该算法可以在没有特殊大小写的情况下处理简并输入。
