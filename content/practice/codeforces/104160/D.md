 ## 解决方案
 ## 问题理解

 我们得到一个由 5 个字符组成的固定长度序列，描述 DRX 和 T1 之间五局三胜系列赛的结果。 每个角色对应一场比赛：要么是 DRX 获胜，要么是 T1 获胜，或者是一个特殊符号，表明该系列赛已经提前结束并且剩余的比赛从未进行过。 

关键规则是先取得 3 场胜利的队伍立即成为冠军，之后的所有比赛均由该队取代。`?`象征。 这意味着该字符串不仅仅是结果列表，而是 3 场胜利的比赛记录。 

任务是确定在这个过程中哪支球队实际上最先取得了3场胜利。 

尽管字符串的长度为 5，但重要的观察是只有它的前缀包含真实结果。 第一个之后的一切`?`无关紧要，因为它代表未玩的游戏。 因此，有效信息是一个前缀，我们在该前缀中计算胜利，直到达到停止条件。 

约束条件非常小，固定长度为 5，因此任何扫描一次字符串的解决方案就足够了。 不需要高级数据结构或组合数学。 任何模拟不必要的游戏分支的尝试都是矫枉过正的，只会使正确性推理变得复杂。 

例如，一个微妙的边缘情况是系列赛仅以 3 场比赛结束`DDD??`或者`TTT??`。 另一种是获胜者在最后位置之前达到 3 点，例如`TDTT?`，其中第四场比赛决定胜负，第五场比赛无关紧要。 

一个天真的错误是计算所有字符，包括之后的字符`?`，这会将占位符错误地解释为真正的游戏。 另一个错误是假设所有 5 场比赛都会进行，这违反了截断规则。 

## 方法

 一种强力的解释是将所有 5 个位置视为真实游戏，并模拟整个字符串的获胜计数。 这看起来很简单，但在概念上是失败的，因为第一个后面的后缀`?`不代表实际比赛。 如果我们尝试将其纳入其中，我们就有可能计算不存在的游戏。 

正确的简化来自于认识到`?`是一个硬截止标记。 当它出现的那一刻，结果就已经决定了，任何进一步的处理都是没有意义的。 因此，我们不模拟完整的匹配树或考虑假设的完成，而是只处理前缀直到终止。 

这将问题简化为使用两个计数器跟踪 DRX 和 T1 获胜的单个线性扫描。 遇到的时候我们就早点停下来`?`，并立即根据当时谁已达到 3 场胜利来决定。

 | 所有 5 款游戏的暴力模拟 | O(1) | O(1) | O(1) | O(1) | 不必要但有效 |

 ## 算法演练

 我们从左到右处理字符串，维护两队的胜利计数器。 

### 步骤

 1. 初始化两个计数器，一个用于 DRX 获胜，一个用于 T1 获胜，均从零开始。 这些代表实际玩过的游戏。 
2. 从第一个字符到最后一个字符迭代字符串。 每个字符代表一个游戏结果，除非它是终止符号。 
3. 如果当前字符是`D`，增加 DRX 的计数器。 如果是的话`T`，增加T1的计数器。 这直接模拟了比赛进程。 
4. 处理完每场真实比赛后，检查任一队是否已达到 3 场胜利。 如果是，则立即确定获胜者，并且我们可以停止处理更多字符。 
5. 如果当前字符是`?`，立即停止而不处理进一步的位置，因为没有更多的比赛进行。 
6. 输出先取得3胜的队伍对应的队伍名称。 

关键的设计选择是停止在`?`而不是继续完整的长度，因为后面的位置与实际的匹配不对应。 

### 为什么它有效

 在任何前缀之前`?`，计数器准确地代表了真实的匹配状态。 当一支球队取得 3 场胜利时，系列比赛根据定义终止，字符串的其余部分是语法填充。 因为输入保证了有效性，所以不存在这样的情况：`?`出现在获胜者存在之前，因此停在`?`或在 3 胜时停止是一致的终止条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    drx = 0
    t1 = 0
    
    for c in s:
        if c == '?':
            break
        if c == 'D':
            drx += 1
        else:
            t1 += 1
        
        if drx == 3:
            print("DRX")
            return
        if t1 == 3:
            print("T1")
            return

solve()
```该实现是对比赛过程的直接模拟。 当系列确定或占位符时，循环会提前停止`?`出现。 提前返回可确保我们不会意外地继续扫描不相关的后缀字符。 

一个微妙的细节是，我们会在每次更新后立即检查是否达到 3 场胜利。 这避免了额外的迭代，并反映了现实世界的规则，即当一支球队取得 3 场胜利时，比赛立即结束。

 ## 边缘情况

 一种重要的边缘情况是比赛尽早结束，例如`DDD??`。 在这种情况下，算法恰好在第三个字符处停止，并且从不处理剩余的字符。 计数器立即达到 DRX = 3，因此输出为`DRX`。 

另一种情况是在没有任何决定的情况下决定获胜者`?`出现，例如`DTDDD`。 该算法不依赖于`?`，仅达到 3 场胜利。 扫描将继续，直到遇到第三个 DRX 胜利，然后正确终止。 

最后一种情况是交替获胜，例如`TDTDT`，两支球队都没有在早期占据主导地位。 该算法通过在每次增量后进行检查来确保正确性，因此当 T1 达到 3 胜时，即使后面的字符存在，它也会停止。
