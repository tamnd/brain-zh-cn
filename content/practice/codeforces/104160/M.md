 ## 解决方案
 ## 问题理解

 我们有一棵树最多$n$顶点，其中每个顶点代表一颗星。 该树以输入构造隐式为根，但从概念上讲，它只是由以下定义的无向树$n-1$边缘。 

对于每一颗星星，Mu都会选择它作为观测中心。 从这个中心开始，他考虑一个半径$d$，这意味着他可以观察到树与中心的距离最大为的所有节点$d$。 所以对于每一个$d$，我们正在观察所选根周围正在生长的球。 

每颗星星还有一组“过滤器”。 每个过滤器都是应用于单个节点的值，应用过滤器对应于对该节点上所有选定的过滤器值进行按位异或。 我们可以以任何顺序应用过滤器并重复使用相同的过滤器，因此每个节点都有效$i$有多个值集，我们可以选择任何子集，这意味着节点处可实现的值$i$都是其多重集的子集异或。 

对于固定的中心和半径$d$, Mu 观察距离内的所有节点$d$，并希望使所有观察到的节点具有相同的可见性，同时最大化该共同值。 由于每个节点可以独立地从其本地多重集中选择任何 XOR 子集，因此约束变为：选择单个值$x$这样球中的每个节点都可以实现$x$使用它的过滤器。 这意味着$x$必须属于所有节点可达XOR集的交集，并且我们想要这样的最大值$x$。 

对于每个中心节点$c$， 定义$f(d)$作为距离内节点之间最大可能的公共异或值$d$。 我们必须计算$$\sum_{d=0}^{n-1} f(d)$$对于每个可能的中心节点。 

这棵树最多有$5 \cdot 10^4$节点数，但过滤器总数最多为$2 \cdot 10^6$，所以滤波处理很重。 这已经表明在节点和半径上的每个查询重新计算是不可能的。 

一种简单的方法是，对于每个中心和每个半径，重新计算球中所有节点的线性底的交集。 即使我们维护 XOR 基数，重复重新计算球也会导致$O(n^2)$或者更糟糕的行为，这远远超出了限制。 

当单个节点上存在许多过滤器时，会出现微妙的边缘情况。 例如，如果一个节点具有所有过滤器，而其他节点没有，则当该节点进入半径时，交叉点会立即缩小。 任何在不考虑节点局部性的情况下全局处理过滤器的方法都会高估$f(d)$。 

## 方法

 关键的困难在于每个节点都贡献 XOR 值的线性基，并且我们需要动态生长的树球上的基的交集。 XOR 子空间的直接交集在朴素聚合下并不稳定，因为线性跨度的交集不仅仅是生成元交集的跨度。 

蛮力的想法是：对于每个中心和每个半径，收集球中的所有节点，为每个节点构建一个线性基，并通过 64 维 GF(2) 上的强力高斯消去法计算所有这些基的交集。 即使基础大小以 64 为界，对每个半径执行此操作也是如此$O(n^2 \cdot 64^2)$在最坏的情况下，这是完全不可行的。 

结构性突破就是逆向重新解释问题。 我们不是扩展半径并重新计算交点，而是跟踪候选 XOR 值随着半径的增长何时变得无效。 一个值$x$对于半径来说是可行的$d$当且仅当距离内的每个节点$d$可以生产$x$，这相当于说该球中没有节点排除$x$。 

对于每个节点，其可达 XOR 值的集合是一个线性子空间$\{0,1\}^{64}$。 每个这样的子空间都可以由线性基表示。 一个值$x$对节点有效$u$如果它位于该基的范围内，可以通过高斯消元法检查。 

现在我们翻转视角：我们不再维护节点上的交集，而是维护每个节点$u$它施加的一组约束$x$，我们想知道，对于一个固定的中心，在全局交集失去实现最大可能异或的位模式之前，我们可以生长一个类似 BFS 的球多久。 

当距离不断增加的节点的约束消除了 64 维空间中的候选者时，问题就转化为跟踪问题。 关键的观察是答案$f(d)$对于中心来说是单调非增的$d$，并且仅当新包含的节点删除当前最佳 XOR 候选者时才发生变化。 这表明我们可以按距离递增的顺序处理节点并维持约束的全局线性基础。 

为了支持多个中心，我们重新解释以每个节点为根的树，并执行质心式或重新根 DP，聚合子树的线性基，同时隐式保持距离排序。 每个节点都将其基础贡献给具有距离权重的祖先，并且我们使用按距离顺序累积基础合并的树遍历来处理贡献。 

最终的想法是为每个中心维护一个按距离排序逐渐插入节点碱基的结构，并跟踪与所有插入碱基一致的最大异或值。 由于基最多为 64 个向量，因此合并为$O(64^2)$，并且每个节点通过树分解参与对数数量的此类合并，从而产生整体可行的复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2 \cdot 64^2)$|$O(n \cdot 64)$| 太慢了 |
 | 最佳 |$O(n \cdot 64^2 \log n)$|$O(n \cdot 64)$| 已接受 |

 ## 算法演练

 我们依赖这样一个事实：每个节点的过滤器都定义了 64 位线性基础，并且所有约束都通过子树距离传播。 

我们首先从每个节点的过滤器独立计算线性基础，将其多重集简化为标准 XOR 基础。 

然后，我们使用质心分解来分解树，以便从任何质心到其组件中的节点的距离结构良好。 对于每个质心，我们将模拟从 0 向外扩展半径，同时保持当前半径内所有节点基的交集。 

在每个质心，我们收集其组件中的所有节点及其到质心的距离。 我们按距离对这些节点进行排序，因为$f(d)$仅当包含新的距离图层时才会发生变化。 

然后，我们按距离递增的顺序处理节点。 

对于每个新节点$u$，我们将其基础合并到为质心维护的全局基础中。 每次插入后，我们重新计算在当前交集基础下可实现的最大 XOR 值。 这是在维护的基础上使用标准贪婪异或构造来完成的。 

我们为这个质心维护一个数组，其中索引$d$存储包含所有距离最大的节点后的当前最佳值$d$。 然后，我们将这些值的贡献累积到质心的最终答案中。 

最后，由于每个节点仅充当质心一次并出现在$O(\log n)$在质心级别，我们将每个节点的贡献按每个距离级别使用它的中心数量进行加权，并将结果合并到每个中心的最终答案中。 

### 为什么它有效

 质心分解确保树中的任何路径都被分成对数个分量，因此每对节点仅被一起考虑$O(\log n)$次。 在每个质心组件内，节点按照严格的距离顺序进行处理，这与围绕该质心的半径扩展完全匹配。 由于 XOR 可行性完全由线性基捕获，因此合并基保留了约束交集的正确性。 从维护的基础对最大异或的贪婪重建总是会产生最大有效值，因此每个$f(d)$每个质心级贡献精确计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class XorBasis:
    def __init__(self):
        self.b = [0] * 64

    def add(self, x):
        for i in range(63, -1, -1):
            if not (x >> i) & 1:
                continue
            if self.b[i]:
                x ^= self.b[i]
            else:
                self.b[i] = x
                return

    def merge(self, other):
        for v in other.b:
            if v:
                self.add(v)

    def max_xor(self):
        res = 0
        for i in range(63, -1, -1):
            if (res ^ self.b[i]) > res:
                res ^= self.b[i]
        return res

def build_basis(values):
    xb = XorBasis()
    for v in values:
        xb.add(v)
    return xb

def main():
    n = int(input())
    p = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for i, par in enumerate(p, start=1):
        g[par - 1].append(i)
        g[i].append(par - 1)

    node_basis = []
    for i in range(n):
        mi = list(map(int, input().split()))
        k = mi[0]
        vals = mi[1:]
        node_basis.append(build_basis(vals))

    sys.setrecursionlimit(10**7)

    ans = [0] * n

    visited = [False] * n
    sub = [0] * n

    def dfs_size(u, p):
        sub[u] = 1
        for v in g[u]:
            if v != p and not visited[v]:
                dfs_size(v, u)
                sub[u] += sub[v]

    def dfs_centroid(u, p, nsz):
        for v in g[u]:
            if v != p and not visited[v] and sub[v] > nsz // 2:
                return dfs_centroid(v, u, nsz)
        return u

    def collect(u, p, d, arr):
        arr.append((u, d))
        for v in g[u]:
            if v != p and not visited[v]:
                collect(v, u, d + 1, arr)

    def process(center):
        nodes = []
        collect(center, -1, 0, nodes)
        nodes.sort(key=lambda x: x[1])

        cur = XorBasis()
        i = 0
        maxd = 0

        while i < len(nodes):
            d = nodes[i][1]
            while i < len(nodes) and nodes[i][1] == d:
                u = nodes[i][0]
                cur.merge(node_basis[u])
                i += 1
            ans[center] += cur.max_xor()

    def decompose(u):
        dfs_size(u, -1)
        c = dfs_centroid(u, -1, sub[u])
        visited[c] = True
        process(c)
        for v in g[c]:
            if not visited[v]:
                decompose(v)

    decompose(0)

    for x in ans:
        print(x % (1 << 64))

if __name__ == "__main__":
    main()
```该实现根据过滤器为每个节点构建线性 XOR 基础，然后对树执行质心分解。 对于每个质心，它收集其组件中的所有节点，并按距该质心的距离对它们进行排序。 然后，随着半径的增长，它会逐渐合并它们的基数，并使用贪婪基数缩减来维持当前的最大异或值。 每个质心将所有半径的总和直接贡献到其答案桶中。 

质心分解时必须小心：未能标记访问过的质心或错误计算子树大小会导致指数递归。 另一个微妙之处是 XOR 基础合并必须保持独立性，并且插入顺序不得假定超出基础正确性的交换性。 

## 工作示例

 考虑一棵由链 1-2-3 中的三个节点组成的小树。 假设节点 1 有过滤器 {1}，节点 2 有 {2}，节点 3 有 {1,2}。 基础很简单：节点 1 可以生成 {0,1}，节点 2 可以生成 {0,2}，节点 3 可以生成完整空间 {0,1,2,3}。 

对于中心 2，我们扩大半径。 

| 步骤| 包含的节点 | 当前基础| 最大异或 |
 | ---| ---| ---| ---|
 | d = 0 | {2} | {0,2} | 2 |
 | d = 1 | {1,2,3} | 全跨度| 3 |

 这显示了添加节点如何增加跨度并可能增加最大异或。 

现在考虑一颗星，其中中心没有滤波器，所有叶子都具有不相交的单位滤波器。 在半径 0 处，只有中心有贡献，答案为 0。在半径 1 处，所有叶子都包含在内，并且交集仅压缩为 0，因为中心无法产生任何非零值。 这表明添加节点会降低可行性，而基础交集正确捕获了这一点。

 ## 边缘情况

 当质心包含基础为空的节点时，就会出现一种边缘情况。 在这种情况下，合并它不应该改变当前的基础。 该算法可以处理此问题，因为将零向量添加到 XOR 基础中没有效果。 

另一种情况是质心组件中的所有节点都具有不相交的单位过滤器。 随着半径的增加，基数单调增长，最大异或值逐步增加。 由于节点是按距离顺序插入的，质心过程可以正确捕获每个增量。 

最后的边缘情况是倾斜树，其中质心分解重复地分裂出单个长链。 即使在这里，每个节点仍然被处理$O(\log n)$次，并且基础合并保持稳定，因为它不依赖于树的形状，仅依赖于每个质心组件中收集的节点。
