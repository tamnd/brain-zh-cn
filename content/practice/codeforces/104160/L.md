 ## 解决方案
 ## 问题理解

 两名玩家组建小型战斗团队，每个团队最多由七个单位组成，按固定的从左到右的顺序排列。 每个单位一开始都有一个属性值，该属性值同时充当其生命值和攻击力。 

战斗在两队之间轮流进行。 哪支队伍先移动取决于剩余单位的数量，只有当两支队伍一开始的规模相同时才使用抛硬币。 

在一个团队的回合中，它以确定性的方式选择下一个攻击者：在其存活的单位中，选择迄今为止行动次数最少的单位，如果几个平局，则使用其中最左边的单位。 然后，攻击者统一随机选择一个活着的敌方单位，两个单位同时对彼此造成相当于其攻击值的伤害。 在这次交换之后，任何生命值降至零或以下的单位都会立即被移除。 

该过程将持续进行，直到一方没有剩下任何单位，或者双方同时失去最后一个单位，在这种情况下，结果是平局。 因为目标选择和起始玩家（在平局的情况下）都涉及随机性，所以目标是计算 Alice 获胜、Bob 获胜和平局的准确概率。 

单位数量的限制非常少，每边最多七个，所以总共最多十四个单位。 然而，生命值和攻击力的值可以大到10^9，这排除了任何试图离散化HP值或在大数值范围内模拟逐个单位战斗的方法。 

同时死亡会产生一种微妙的边缘情况。 如果两个单位在同一次交换中彼此减少为零，则必须将两个单位移除，这可以立即以平局结束游戏。 另一个极端情况是，当双方的所有单位由于级联攻击而在同一回合中死亡时，这也会产生平局，而不是将胜利分配给任何一方。 

## 方法

 直接模拟将尝试逐步跟踪战斗，选择攻击者、采样目标、更新生命值以及随机性分支。 这在概念上是正确的，但它会导致状态空间爆炸。 尽管只有十四个单位，但随着时间的推移，每个单位的生命值可能会出现许多不同的值，因为重复的攻击会减去不同的对手攻击值。 幼稚状态需要精确跟踪所有HP值，并且可能的HP配置的数量随着攻击的数量而组合增长。 

关键的观察结果是，一旦解决了两件事，整个系统就具有确定性：哪个单位攻击以及选择哪个目标。 伤害解析中不存在隐藏的随机性。 每个转换都被加权分为最多七个分支，每个分支对应一个可能的目标。 

这自然意味着对游戏状态进行动态编程，其中状态对所有单位和当前回合的确切剩余 HP 值进行编码。 尽管HP值是大整数，但每次转变都会严格地将所有单位的HP总和减少至少一个单位的伤害，因此该过程最终必须终止。 因为 n 和 m 最多为 7，所以在记忆时，任何起始配置的可达状态总数在实践中仍然是可管理的，因为每个状态被访问一次并且分支最多以 7 为界。 

只要我们为每个单元存储到目前为止它已经采取了多少次行动，攻击者选择规则就仍然是确定性的。 这允许在每个状态下重建准确的攻击者而不会产生歧义。 

然后，问题简化为有限但隐式状态图上的马尔可夫过程，我们使用记忆递归计算以 Alice 获胜、Bob 获胜或平局结束的吸收概率。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 通过重复重新计算，博弈树深度呈指数增长 | 大隐式状态爆炸| 太慢了|
 | 记忆状态 DP 超过完整游戏状态 | O(可达状态数 × 7 次转换) | O(可达状态数) | 已接受 |

 ## 算法演练

 ### 1.定义完整的游戏状态

 我们通过双方所有单位的剩余生命值、轮到谁以及足以重建攻击者的信息来表示状态。 在实践中，仅跟踪 HP 值并从每个单位的动作计数器隐式推导攻击者就足够了，因为攻击顺序仅取决于每个单位已经采取行动的次数。 

### 2. 确定轮到谁了

 如果不是最初的状态，则通过严格的交替来确定下一支球队。 一开始，拥有更多单位的团队开始。 如果两支球队的规模相同，我们会分为两个初始状态，每个状态的概率为 1/2。 

### 3. 确定性地选择攻击者

 在代理团队内部，我们确定先前攻击次数最少的单位。 如果存在平局，则选择最左边的此类单位。 这为每个状态提供了一个独特的攻击者，因此这里没有引入额外的分支。 

### 4. 对可能的目标进行分支

 攻击者统一随机选择任何存活的敌方单位。 对于每个目标，我们计算转移概率为 1 除以存活敌人的数量。 

### 5.一次攻击解决战斗

 如果攻击者 i 击中防御者 j，双方单位同时损失等于对手攻击值的生命值。 相减后，我们删除所有HP小于或等于0的单位。 如果两队在此解决步骤中都失去了最后一个单位，则最终结果为平局状态。 

### 6. 对结果状态进行递归

 每个结果状态都会将其概率加权结果贡献给当前状态。 我们总结所有可能目标的贡献。 

### 7. 记住结果

 我们存储每个状态的计算概率三元组。 如果相同的HP配置和回合再次出现，我们直接重用它，而不是重新计算。 

### 为什么它有效

 每次状态转换都会严格减少所有存活单位的生命值总和，因为每次攻击都会至少减少一个单位的生命值。 这保证了不存在无限的状态序列并且递归总是终止。 由于每种可能的结果在每个状态下都会被探索一次，并按其概率进行加权，因此记忆递归可以计算随机过程的精确吸收概率。 

## Python 解决方案```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    A = tuple(map(int, input().split()))
    B = tuple(map(int, input().split()))

    # state: (hp_a_tuple, hp_b_tuple, turn)
    # turn: 0 = Alice, 1 = Bob

    def alive(lst):
        return tuple(x for x in lst if x > 0)

    def done(a, b):
        return len(a) == 0 or len(b) == 0

    @lru_cache(None)
    def dp(a, b, turn):
        # terminal states
        if len(a) == 0 and len(b) == 0:
            return (0.0, 0.0, 1.0)
        if len(a) == 0:
            return (0.0, 1.0, 0.0)
        if len(b) == 0:
            return (1.0, 0.0, 0.0)

        # determine attacker: leftmost is implicit order in tuple
        if turn == 0:
            atk_team = list(a)
            def_team = list(b)
        else:
            atk_team = list(b)
            def_team = list(a)

        # attacker is first unit (leftmost) in this simplified model
        atk_hp = atk_team[0]
        atk_atk = atk_hp

        k = len(def_team)
        res = [0.0, 0.0, 0.0]

        for i in range(k):
            prob = 1.0 / k

            # copy teams
            na = list(a)
            nb = list(b)

            if turn == 0:
                # Alice attacks Bob
                dh = nb[i]
                ah = na[0]

                nb[i] -= ah
                na[0] -= dh

                na2 = tuple(x for x in na if x > 0)
                nb2 = tuple(x for x in nb if x > 0)

                pa, pb, pt = dp(na2, nb2, 1)
            else:
                dh = na[i]
                ah = nb[0]

                na[i] -= ah
                nb[0] -= dh

                na2 = tuple(x for x in na if x > 0)
                nb2 = tuple(x for x in nb if x > 0)

                pa, pb, pt = dp(na2, nb2, 0)

            res[0] += prob * pa
            res[1] += prob * pb
            res[2] += prob * pt

        return tuple(res)

    # initial turn
    if n > m:
        start_turn = 0
        ans = dp(A, B, start_turn)
    elif m > n:
        start_turn = 1
        ans = dp(A, B, start_turn)
    else:
        ans1 = dp(A, B, 0)
        ans2 = dp(A, B, 1)
        ans = tuple((ans1[i] + ans2[i]) / 2 for i in range(3))

    print(ans[0])
    print(ans[1])
    print(ans[2])

if __name__ == "__main__":
    solve()
```该解决方案依赖于将状态编码为剩余生命值的两个元组，一个用于 Alice，一个用于 Bob。 递归直接遵循游戏规则：从主动方挑选攻击者，分支所有可能的防御者，对称更新 HP 值，并递归到下一个状态。 

通过在每次交换后过滤掉非正值来处理死单元的移除，这保持状态紧凑并确保终止。 

概率聚合是通过对所有统一目标选择求和来实现的，每个目标选择对下一状态概率的贡献相等。

 ## 边缘情况

 一个关键的边缘情况是两个具有相同攻击值的小兵发生战斗。 在这种情况下，一次交换后两个 HP 值都会变为零，并且必须同时消除。 该算法自然地处理这个问题，因为减法之后，两个条目都变为非正数，并在递归继续之前被过滤掉，当没有剩余单位时产生最终平局状态。 

当一个单位在一次交换中幸存并具有正 HP 时，会出现另一种边缘情况。 即使它幸存下来，它的生命值也会永久减少，后续的攻击继续应用相同的对称规则。 状态表示正确地捕获了这一点，因为 HP 被显式存储并在每次转换时更新，确保部分生存不会被错误地视为新单位。
