 ## 解决方案
 ## 问题理解

 我们从两个正整数开始，`A`和`B`，每个最多 (10^{18})。 在一次操作中，我们可以将任一值加倍，或者将一个值添加到另一个值上。 目标不是最小化操作数量。 我们只需要生成一些最多 5000 次操作的有效序列，最终使两个值相等。 

输出是一系列操作名称。 由于法官模拟了这些操作，因此我们的任务是建设性的：我们需要找到一个始终足够快终止的可靠进程。 

(10^{18}) 的大上限排除了任何试图增加数字直到某个方便选择的公共值的方法。 这样的值可能是巨大的，甚至对可能目标的对数搜索也不会自然地与允许的操作相关联。 5000 次操作的限制还告诉我们，预期的解决方案应该有强有力的减少措施，而不是仅仅依赖于最终终止。 

加倍运算中隐藏着一个有用的等价性。 从概念上假设我们当前的状态是`(A, B)`和`A`是均匀的。 如果我们输出`B+=B`，实际状态变为`(A, 2B)`。 将这个实际状态的两个坐标除以 2 给出`(A/2, B)`，并且将两个坐标乘以相同的正常数不会改变它们是否可以通过相同的加法和加倍运算序列变得相等。 因此，从两个数字之间的比率来看，`B+=B`让我们对待一个偶数`A`就好像我们已经分开了`A`2. 对称地，`A+=A`让我们从概念上划分一个偶数`B`2.

 这给出了主要的边缘情况。 

用于输入`5 5`，数字已经相等，所以正确的输出很简单`0`。 总是在检查相等性之前执行加法的粗心实现会产生不必要的操作，甚至可能偏离目标。 

用于输入`2 3`，我们可以从概念上划分`A`通过执行 2`B+=B`，给出等效的归一化状态`(1, 3)`。 然后`B+=A`对应于`(1, 4)`， 和`A`可以加倍两次达到`4`。 该示例正是使用了这个想法，产生了四个操作。 如果不小心实现，只尝试将较小的数字与较大的数字相加，则可能会无限地增加值，而不是利用 2 的幂。 

用于输入`1 1`，答案又是`0`。 这捕获了进入标准化循环而不首先检查数字是否已经相等的实现。 

## 方法

 一种简单的暴力方法会将每个可能的操作视为一个分支并搜索具有`A == B`。 从任何状态都有四种选择，因此深度为 5000 的搜索有

 [
 1+4+4^2+\点+4^{5000}
 ]

 候选操作序列，最深层次仅包含 (4^{5000}) 个可能性。 即使进行积极的修剪，也不存在有用的有限状态空间，因为数字可以无限制地增长。 这种方法是完全不切实际的。 

蛮力搜索确实有一个有用的属性：每个操作都保留正性，并且每条成功的路径最终都会达到两个相等的值。 问题是在不探索指数数量的选择的情况下找到这样的路径。 

关键的观察是，加倍可以用作概念上的除以二。 一旦我们决定使用高达公共比例因子的值，每个偶数都可以使用一个允许的操作除以二。 这意味着我们可以重复地从两个数字中删除二的因数。 

最终这两个值都是奇数。 如果它们相等，我们就完成了。 否则，假设`A < B`。 由于两者都是奇数，`A+B`是均匀的。 我们表演`B+=A`，将这对更改为`(A, A+B)`。 现在第二个值是偶数，因此我们可以在概念上将其重复除以二，直到它变为奇数。 

一次除法后，新的第二个值是

 [
 \frac{A+B}{2}。 
]

因为`A < B`，这严格小于`B`。 更重要的是，差异至少减少了一半：

 [
 \frac{A+B}{2}-A=\frac{B-A}{2}。 
]

 如果可以进行多次除法，则第二个值会变得更小，因此差异至少会减小同样多。 

因此，每次两个值都是奇数且不相等时，一次加法和一些除法会大大减少它们的差异。 由于初始差值低于 (10^{18})，因此只能有大约 60 轮这样的缩减轮次。 

同样的论点还给出了操作总数的一个合适的界限。 在两轮加法之间，每个值都除以二，直到变成奇数。 由于归一化后的值不会超过 (10^{18})，因此一轮最多需要 60 次这样的划分。 总数远低于 5000。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(4^{5000})) 候选序列 | (O(5000)) 每个搜索路径，总体上可能呈指数增长 | 太慢了|
 | 最佳| (O(\log \max(A,B))) 减少轮数，具有对数归一化工作 | (O(\log \max(A,B))) | 已接受 |

 ## 算法演练

 1. 阅读`A`和`B`。 如果它们已经相等，则输出零运算。 无需进行任何转换。 
2. 虽然`A`是偶数，记录`B+=B`并在概念上取代`A`经过`A/2`。 记录的操作将另一个坐标加倍，因此实际对是比概念对大的两个的公因数。 相同的缩放比例不会改变平等行为。 
3.同时`B`是偶数，记录`A+=A`并在概念上取代`B`经过`B/2`。 这是上一步的对称版本。 
4. 如果归一化值相等，则停止。 现在这两个值都是奇数，因此任何剩余的不相等状态都具有特别简单的结构。 
5.如果`A < B`， 记录`B+=A`。 的概念价值`B`变成`A+B`，这是偶数，因为两个输入都是奇数。 
6.划分新的`B`两个人反复录音`A+=A`对于每个概念划分。 由此产生的奇数`B`比之前的小`B`，并且两个值之间的差距至少缩小了一半。 
7.如果`B < A`，执行对称运算`A+=B`，然后反复除`A`通过录音两个`B+=B`。 
8. 重复标准化和加法过程，直到两个概念值相等。 按原始顺序输出所有记录的操作。 

不变的是，概念对始终代表实际对，直到两个坐标乘以相同的 2 的正幂。 这种共同的缩放不会改变允许的操作的未来序列是否可以使坐标相等。 记录的每一个操作正是实现相应概念转换的真实操作。 当两个值都是奇数且不相等时，将较小的值与较大的值相加会使较大的值成为偶数，之后概念上的划分将差异减少至少两倍。 由于差值是非负整数，因此该过程最终必须达到零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    operations = []

    while a != b:
        while a % 2 == 0:
            # Conceptually: a /= 2.
            # Real operation: double b, preserving the ratio.
            operations.append("B+=B")
            a //= 2

        while b % 2 == 0:
            # Conceptually: b /= 2.
            # Real operation: double a, preserving the ratio.
            operations.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            # Both are odd here, so a + b is even.
            operations.append("B+=A")
            b += a
        else:
            operations.append("A+=B")
            a += b

    print(len(operations))
    sys.stdout.write("\n".join(operations))

if __name__ == "__main__":
    solve()
```这`operations`list 存储必须打印的实际命令。 变量`a`和`b`被故意视为规范化的概念值，而不是通过模拟每个命令获得的字面值。 

什么时候`a`是偶数，代码将其除以二并记录`B+=B`。 实际执行时，加倍`B`会产生`(a, 2b)`。 这恰好是概念状态的两倍`(a/2, b)`，因此这两种表示具有相同的比率和相同的未来平等行为。 

同样的推理适用于`b`是偶数，使用`A+=A`。 

一旦两个值都是奇数，代码就会将较小的值与较大的值相加。 例如，如果`a < b`, 操作`B+=A`变化`b`到`a+b`，这是偶数。 下一次迭代立即进入除法循环并删除所有 2 的因子。 

两个归一化循环的顺序对于正确性并不重要。 第一个循环之后，`a`是奇数，在第二次循环之后，`b`很奇怪。 如果两个值在归一化过程中变得相等，则外循环将在执行不必要的加法之前终止。 

Python 整数不会溢出，因此概念加法临时产生的值是安全的。 更重要的是，归一化值仍然有界，因为在添加两个奇数并将结果除以至少二之后，新值最多是之前的较大值。

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)

        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin

    if n < 0 or n > 5000:

            a += b

 ## 边缘情况

 对于`5 5`, 外部条件`while a != b`立即为假。 操作列表仍然为空，因此程序打印`0`。 这是这里所需的唯一正确的行为，因为初始状态已经满足目标。 

为了`2 3`，第一个标准化看到`A`是均匀的。 节目记录`B+=B`并将概念状态更改为`(1,3)`。 由于现在两个值都是奇数且不相等，因此它记录`B+=A`, 给予`(1,4)`。 下一个标准化划分`B`两次，给予`(1,1)`。 实际的顺序是`B+=B`,`B+=A`,`A+=A`,`A+=A`，真实状态从`(2,3)`到`(2,6)`， 然后`(2,8)`， 然后`(4,8)`，最后`(8,8)`。 

为了`1 5`，两个值都以奇数开头。 自从`1 < 5`，程序执行`B+=A`，获得概念状态`(1,6)`。 现在偶数值可以减半，产生`(1,3)`。 差异已从`4`到`2`。 相同的流程变化`(1,3)`到`(1,1)`。 这说明了为什么奇数对不应该简单地继续添加较小的值而不进行标准化。 

为了`1000000000000000000 999999999999999999`，数字处于最大允许量级并且相差 1。 两者都是奇数，因此算法将较小的值与较大的值相加，使较大的值成为偶数。 然后，它在概念上反复删除两个因素。 每一轮这样的差异都会急剧减小，并且标准化值永远不会超出原始范围。 因此，可以在没有任何溢出或对大目标值进行搜索的情况下处理大输入大小。 

为了`576460752303423488 1`，第一个数字是 (2^{59})。 该算法可以使用一次去除其二的幂一`B+=B`，减少概念性`A`从 (2^{59}) 到`1`。 然后两个值变得相等。 这会执行最长的简单标准化链，并确认操作列表仍远低于 5000 个操作的限制。
