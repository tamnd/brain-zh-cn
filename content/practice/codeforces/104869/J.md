 ## 解决方案
 ## 问题理解

 我们有一棵最多有 50 个顶点的无根树。 两名玩家轮流轮流，每轮选择一个优势$u-v$。 此举不是端点的本地交换，而是结构性“重新布线”：$u$除了$v$脱离$u$并重新连接到$v$。 手术后，$u$只保留边缘$v$， 尽管$v$吸收所有的$u$的其他事件子树。 

还有一个额外的限制，使该游戏与标准树游戏根本不同。 仅当生成的树与前一棵树不同构时才允许移动。 换句话说，禁止玩家执行不改变树的未标记形状的转换。 

当玩家没有有效的动作时，游戏结束。 爱丽丝开始，两位玩家都发挥最佳。 

关键的困难在于，移动是在标记的顶点上定义的，但合法性仅由生成的未标记的树结构决定。 这意味着产生同构树的两个不同的重新连线操作序列实际上被认为是相同的状态，并且不允许某些移动，即使它们在结构上是有效的。 

自从$n \le 50$，暴力破解所有标记状态是不可能的。 尽管树空间的绝对值很小，但同构会破坏许多配置，并且如果简单地模拟，在最坏的情况下，每次移动的分支因子仍然是二次的。 

高度对称的树会产生微妙的边缘情况。 特别是，星形树的行为与所有其他树不同，因为任何嫁接操作都会保留其结构。 

如果树是有 4 个顶点的星形树：```
1 - 2
|
3
|
4
```任何选择中心和叶子的尝试都只是以保持树成为星星的方式重新连接叶子。 由于生成的树与原始树同构，因此任何移动都是有效的。 对于任何星星都会发生同样的情况$n$顶点：游戏立即陷入僵局，爱丽丝输了。 

另一方面，对于长度为 4 的路径：```
1 - 2 - 3 - 4
```该树不是星形，因此至少存在一个有效操作。 事实证明，这种区别是解决方案的核心。 

## 方法

 直接模拟会将每个标记树视为一个状态并尝试每个可能的边缘$u-v$，通过重新连接邻接表生成一棵新树，然后检查与先前状态的同构性。 这已经变得昂贵，因为每个转换的同构测试成本高昂，并且即使对于$n=50$。 

即使我们通过仅存储规范树形式来压缩状态，我们仍然面临树同构类的大型隐式图。 完整的游戏分析需要计算该图的获胜和失败状态，考虑到操作的结构，这有点过分了。 

关键的观察结果是，移植和移植会积极地将结构塌陷到中心。 每一次操作都会将度数质量从一个顶点转移到另一个顶点，并且重复应用往往会集中树。 从每个可能的移动都会产生同构树的意义上来说，在此操作下完全稳定的唯一配置是星形。 

一旦树不是星形树，总是存在至少一条边，其操作改变树的结构形状。 这意味着游戏永远不会因为同构约束而阻塞在中间非星态。 唯一的终点位置是星星。 

从这个角度来看，游戏简化为一个简单的可达性问题：当前玩家是否可以做出至少一个有效的动作，即树是非星形的吗？ 

如果已经是星星了，爱丽丝毫无招架之力，立刻就输了。 否则，爱丽丝有一步棋，游戏继续，最佳游戏不会改变这种基本的二分法。

 ## 算法演练

 整个解决方案简化为识别输入树是否是星形树。 

1. 计算每个顶点与输入边的度数。 
2. 检查是否存在有度数的顶点$n-1$。 
3. 如果存在这样的顶点，则该树是一颗星，Alice 没有有效的移动，因此输出“Bob”。 
4. 否则，至少有两个顶点的度数大于1，因此该树不是星形树，Alice可以移动，因此输出“Alice”。 

这足够的原因是，任何不是星形的树都至少承认一条边，其移植操作会产生不同的未标记结构，因此第一个玩家永远不会立即被卡住。 

### 为什么它有效

 同构约束仅阻止保留树的整个未标记结构的移动。 移植操作保留了星形中所有边缘的结构，因为所有叶子都无法区分，并且所有重新附着都会产生另一颗星形。 在每一棵其他树中，子树之间都存在结构不对称，这意味着至少一条边连接全局形状中具有不同角色的顶点。 在这样的边上应用移植操作会以无法通过任何顶点重新标记来匹配的方式改变度分布，因此生成的树与原始树不同构。 因此，非星树总是至少有一个合法的动作，而星树却没有。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
deg = [0] * (n + 1)

for _ in range(n - 1):
    u, v = map(int, input().split())
    deg[u] += 1
    deg[v] += 1

is_star = any(d == n - 1 for d in deg[1:])

if is_star:
    print("Bob")
else:
    print("Alice")
```该实现仅计算度数，因为整个决策取决于检测树是否具有通用中心顶点。 数组`deg`跟踪邻接计数，扫描一次就足以确定这棵树是否是一颗星。 

关键的微妙之处在于不需要模拟移植手术。 任何模拟尝试都会错误地将标记变换与同构约束混合在一起，而实际决策纯粹取决于结构对称性。

def solve():
    import sys

        u, v = map(int, input().split())
        deg[u] += 1

 主要的边缘情况是完全对称的星形配置。 在这种情况下，每个可能的移植操作都会保留树的同构类，因此不存在合法的移动。 该算法通过检查顶点的度数来检测这一点$n-1$，无论标签如何，都能正确识别星星。 

另一个微妙的例子是小树，例如$n=2$。 单边树本身就是一颗星，因为任一端点都有度数$1 = n-1$，所以爱丽丝立刻就没有任何动作了。 度数检查无需特殊外壳即可捕获这一点。 

最后，高度不平衡的非星树仍然具有结构不对称性，因此它们总是允许至少一次移动。 该解决方案不依赖于找到特定的移动，仅依赖于检测至少一个存在，这是通过不存在通用中心顶点来保证的。
