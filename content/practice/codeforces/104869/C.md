 ## 问题理解

 我们正在跟踪瑞士体系锦标赛中的一支球队，其进步完全取决于胜负之间的差异。 该团队从五轮结构的中间某个位置开始，每场比赛都会将其移动一步：胜利使获胜计数增加一，而失败使失败计数增加一。 一旦球队达到三胜或三负，球队就会立即退出比赛。 

在任何时刻，团队都由两个整数来描述$x$和$y$，每个在 0 到 2 之间，代表已经累积了多少胜负。 从这个状态来看，假设我们可以选择有利于球队的最佳结果，我们想知道保证在达到三场失利之前达到三场胜利所需的最少可能的额外比赛数量。 

每场比赛都只为其中之一贡献一个$x$或者$y$，并且该过程结束时$x = 3$（成功）或$y = 3$（失败）。 任务是计算达到获胜条件所需的最少未来比赛次数。 

限制很小：两个计数器最多为 2，因此只有九种可能的状态。 这立即表明，对所有状态进行任何指数或强力探索都是可行的，但即使这样也是不必要的，因为一旦我们考虑仍然需要多少次胜利，结构就是确定性的。 

一个微妙的边缘情况是当球队距离淘汰已经差一场的时候，例如$y = 2$。 那样的话，球队就不能再输了，所以剩下的比赛必须全胜，直到达到三胜为止。 例如，输入$x = 1, y = 2$要求恰好连续两场胜利，这意味着至少两场比赛，而不是一场。 

另一个边缘情况是当团队已经处于$x = 2$,$y = 0$。 这里只需要再赢一场，所以答案是 1。但是，如果我们误解瑞士规则并假设交替的 BO1/BO3 结构很重要，我们可能会错误地使过渡过于复杂。 关键的观察结果是，问题完全归结为计算所需的剩余胜利，同时尊重损失不能超过 2。 

## 方法

 思考问题的一种强力方法是对每个状态进行建模$(x, y)$并模拟所有可能的胜利和失败序列，直到我们达到$x = 3$或者$y = 3$。 从给定的状态，我们分为两个转换，一个用于获胜，一个用于失败，并计算首先达到获胜条件的最小深度。 由于状态空间非常小，因此在实践中这会很快终止。 然而，除非使用记忆化，否则这种方法会多次冗余地重新计算相同的状态，而且即使如此，也没有必要，因为结构是单调的。 

关键的简化在于，瑞士赛制，一局两胜或三局两胜，根本不影响这个问题的答案。 唯一重要的是还需要赢多少场才能达到3胜或3负。 由于我们被要求保证晋级所需的最少额外比赛数，因此我们假设每场比赛的结果都是最有利的，这意味着我们总是选择胜利。 唯一的限制是我们仍然必须避免达到 3 场损失，但由于我们正在尽量减少比赛，所以我们永远不会自愿接受损失。 

所以从状态$(x, y)$，团队正好需要$3 - x$更多胜利。 然而，我们必须确保在此之前我们不会遭遇 3 次损失。 如果$y = 2$，下一场比赛不可能输，所以我们被迫进入确定性的胜利序列。 如果$y \le 1$，我们仍然不会选择最优路径中的损失，因此约束永远不会绑定。 

因此答案很简单$3 - x$，除了我们还必须确保在最坏情况的安全解释下的可行性。 由于我们正在最小化，因此永远不会选择损失，因此只要我们假设最佳游戏，可行性就始终成立。

 ## 算法演练

 我们计算还需要多少场胜利才能达到 3 场胜利，同时确保我们从不考虑失败路径，因为它们只会使目标变得更糟。 

1.读取当前状态$(x, y)$。 这代表了团队在任一最终条件方面的进展程度。 
2. 计算还需要多少场胜利才能达到目标，即$3 - x$。 这直接衡量需要多少成功的游戏才能晋级。 
3. 返回$3 - x$作为答案。 

我们不模拟损失的原因是，任何损失都只是​​冒着淘汰的风险间接增加了剩余胜利的数量，而这永远不会减少最优路径上的游戏数量。 

### 为什么它有效

 状态空间在两个维度上都是单调的：每场比赛都严格增加胜利或失败，并且终止发生在固定阈值。 由于我们正在最大限度地减少游戏数量，直到达到$x = 3$，任何最佳序列总是会优先选择胜利而不是失败，因为失败对目标没有贡献，只会更接近失败。 因此，从最短有效路径$(x, y)$到$(3, \ast)$通过重复应用胜利转换直到达到 3 场胜利来实现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x, y = map(int, input().split())
print(3 - x)
```该解决方案读取当前的胜负次数，然后直接计算还需要多少胜。 损失计数不会影响计算，因为我们不会被迫以最佳序列进行任何损失。 

唯一微妙的一点是，瑞士的 BO1/BO3 结构与目标无关。 尽管它改变了实际比赛的进行方式，但它并不影响抽象状态转换模型，该模型纯粹基于递增计数器。 

## 工作示例

 ### 示例1：输入`0 1`我们开始于$x = 0, y = 1$。 目标是取得3场胜利。 

| 步骤| x| y | 需要剩余胜利|
 | ---| ---| ---| ---|
 | 0 | 0 | 1 | 3 |
 | 1 | 1 | 1 | 2 |
 | 2 | 2 | 1 | 1 |
 | 3 | 3 | 1 | 0 |

 每一步都对应于选择胜利，因为任何损失只会拖延或面临失败的风险。 三场胜利后，球队晋级。 

这证实了答案是3。 

### 示例2：输入`1 2`我们开始于$x = 1, y = 2$。 再输一场就会立即淘汰球队，所以唯一有效的途径就是纯粹的胜利。 

| 步骤| x| y | 需要剩余胜利|
 | ---| ---| ---| ---|
 | 0 | 1 | 2 | 2 |
 | 1 | 2 | 2 | 1 |
 | 2 | 3 | 2 | 0 |

 球队被迫取得两连胜，答案为2。 

这表明即使在接近淘汰的状态下，计算仍然减少到剩余的胜利。

 ## 边缘情况

 一个关键的边缘情况是当团队已经处于$y = 2$。 用于输入$1, 2$，任何失败都会立即结束锦标赛，因此唯一可行的顺序是严格获胜。 算法返回$3 - 1 = 2$，匹配所需的强制获胜次数。 逐步模拟这一过程证实不存在使用更少游戏的替代路径。 

另一个边缘情况是当$x = 2$。 用于输入$2, 1$，答案是$1$。 状态转换很简单：一场胜利立即变为三场胜利，因此瑞士的结构和损失数量不会影响结果。
