 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，表示几轮比赛的评分变化。 我们可以任意重新排序这些回合。 然后我们从零级开始进行模拟，将值一一相加。 每次运行总和严格超过运行总和的所有先前值时，我们将其视为最大评级的更新。 

任务不是找到最好的排序，而是更全局的东西：对于固定的多重值集，我们想知道通过选择数组的不同排列可以实现多少个不同的“最大更新次数”值。 每次更新更改数组的一个元素后，我们必须重新计算该数量。 

关键的约束是 n 和 q 都可以大到 200,000，因此任何尝试模拟排列的解决方案，甚至用比对数或每次更新的恒定工作更糟糕的方式推理每个查询的解决方案都不会通过。 该结构强烈表明答案必须取决于多重集的极少数全局属性，而不是其详细排列。 

当所有数字均为非正数时，就会出现微妙但重要的边缘情况。 在这种情况下，运行总和从零开始，并且永远不会严格变为正数，因此不会发生最大更新。 一种假设至少总是发生一次更新的天真的方法会在这里错误地报告肯定的答案。 另一种脆弱的情况是存在零时：零永远不会增加总和，但如果不小心检查符号，它们可能会被误认为是无害的正值。 

## 方法

 如果我们尝试直接思考，暴力的想法是枚举数组的所有排列并模拟每个排列的过程，计算前缀和设置新记录的次数。 这在原则上是正确的，因为它完全符合定义。 然而，存在 n 个阶乘排列，甚至模拟一个排列也会花费线性时间，因此这种方法在 n 非常小时就会立即爆炸。 

关键的观察是，该过程只关心前缀和何时跨越新高，而这仅取决于元素是否为正。 负值和零值可以延迟增长，但永远无法自行创造额外的破纪录事件。 同时，每个正值最多只能贡献一条新记录，因为一旦前缀和由于正数而达到新的峰值，则任何重新排列都无法使同一元素再次贡献。 

这将整个问题分解为跟踪存在多少严格正值。 一旦认识到这一点，可实现的 k 值的数量就变得极其有限：如果没有正数，则该过程永远不会增加到零以上，因此唯一可能的值是 k = 0。如果至少有一个正数，我们可以强制所有正数提前出现并为每个正数创建一个新记录，或者将所有正数延迟到最后，以便在克服累积的负数时只发生一次交叉。 中间行为也是可以实现的，但最重要的是，从 1 到正元素数量的每个值都是可能的，形成一个连续的范围。 

因此，每个数组的答案就是正计数范围的大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 | O(n!·n) | O(n!·n) | O(n) | 太慢了 |
 | 仅跟踪阳性计数 | O(n + q) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将整个问题简化为维护数组中有多少元素严格大于零。

1. 计算数组中正元素的初始数量，称为 pos。 
2. 对于每次更改单个元素的更新，首先确定该元素在更新之前是否为正，以及更新后是否为正。 
3. 如果正数变为非正数，则相应地调整 pos，如果正数变为非正数，则减 1；如果非正数变为正数，则加 1。 
4. 每次更新后，根据 pos 计算答案：如果 pos 为零，则输出 1，否则输出 pos。 

这个推理的重要部分是为什么答案仅取决于 pos。 前缀最大更新的结构确保只有严格的正增量才能创建新记录，而负数和零只会影响计时，并且不能增加破纪录事件的数量超出正数已经允许的范围。 

### 为什么它有效

 当我们添加一个元素将累积和推到所有先前可实现的值之上时，前缀和的运行最大值就会精确地增加。 任何非正元素都不能促成新的最大增加，因为将其添加到任何前缀和不能严格增加总和。 因此，只有积极因素才能引发此类事件。 

此外，可以对每个正元素进行排列，使其要么产生自己的新最大值，要么被吸收到单个最终交叉中，但没有任何排列可以使超过 pos 的不同最大更新发生，并且只要 pos 不为零，至少可以进行一次更新。 这迫使可实现的 k 值集恰好为 {1, 2, ..., pos}，并且在 pos = 0 的简并情况下，它会折叠为 {0}。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    pos = 0
    for x in a:
        if x > 0:
            pos += 1
    
    for _ in range(q):
        i, v = map(int, input().split())
        i -= 1
        
        old = a[i]
        if old > 0:
            pos -= 1
        
        a[i] = v
        
        if v > 0:
            pos += 1
        
        if pos == 0:
            print(1)
        else:
            print(pos)

if __name__ == "__main__":
    solve()
```该解决方案维护一个全局计数器`pos`，代表在任何时刻有多少元素是严格正的。 每次更新仅影响本地计数器，因此数组本身仅用于记住以前的值。 输出逻辑直接遵循导出的特征：要么所有值都是非正数，给出单个可能的结果，要么可以实现从 1 到 pos 的每个计数。 

这里的一个常见错误是在每次更新后尝试通过排序或模拟前缀和来重新计算答案，这太慢了。 关键的简化是数组的完整结构并不重要，重要的是符号分布。 

## 工作示例

 考虑数组`[1, 2, 3]`。 

最初，所有三个元素都是正数，因此 pos = 3。 

| 步骤| 数组 | 邮政 | 输出|
 | ---| ---| ---| ---|
 | 初始化| [1,2,3]| 3 | - |
 | 1 | [1,2,4]| 3 | 3 |
 | 2 | [1,-2,4]| 2 | 2 |
 | 3 | [-3,-2,4] | 1 | 1 |
 | 4 | [-3,-2,1] | 1 | 1 |
 | 5 | [-3,1,1] | 2 | 2 |

 这符合这样的想法：答案始终等于正元素的数量，除非该数量为零。 

现在考虑一个没有积极因素的情况，例如`[0, -1, -5]`。 

| 步骤| 数组 | 邮政 | 输出|
 | ---| ---| ---| ---|
 | 初始化| [0，-1，-5] | 0 | 1 |
 | 更新后 | 仍然全部 ≤ 0 | 0 | 1 |

 这里任何排序都不可能使运行总和超过零，因此唯一可实现的值为 k = 0，有效 k 值的数量为 1。 

这些痕迹证实了不变量纯粹是基于符号的并且对大小或顺序不敏感。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + q) | 每次更新都会在 O(1) 时间内调整一个计数器 |
 | 空间| O(1) 额外 | 仅维护数组和一个整数计数器 |

 这些约束最多允许 200,000 次更新，因此每个查询的恒定时间处理是必要的。 该解决方案完全符合限制，因为它每次操作都不执行大量计算。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    pos = sum(1 for x in a if x > 0)
    
    out = []
    for _ in range(q):
        i, v = map(int, input().split())
        i -= 1
        if a[i] > 0:
            pos -= 1
        a[i] = v
        if a[i] > 0:
            pos += 1
        out.append(str(1 if pos == 0 else pos))
    
    return "\n".join(out)

# minimal case
assert run("1 1\n0\n1 5\n") == "1", "single element becomes positive"

# all non-positive
assert run("3 2\n0 -1 -2\n1 -5\n2 -3\n") == "1\n1", "all non-positive stays 1"

# all positive shrinking
assert run("3 3\n1 2 3\n1 -1\n2 -2\n3 -3\n") == "2\n1\n1", "positive count decreases"

# mixed updates
assert run("4 2\n1 -1 2 -3\n2 5\n3 -4\n") == "3\n2", "toggle positives"

# already maximal positives
assert run("2 1\n10 20\n1 -5\n") == "1", "drop to single positive"

 | 全部为非正 | 每个查询 1 个 | 处理零阳性案例 |
 | 积极因素减少| 答案不断缩小| 动态更新|

 ## 边缘情况

 当所有元素均为非正数时，算法正确地保持`pos = 0`整个过程并为每个查询输出 1。 这对应于这样的事实：任何排列都不能创建正的前缀和，因此不会发生最大更新。 

当值从正值变为非正值或反之亦然时，仅需要一次计数器更新。 例如，改变`-3`到`4`增加`pos`增加一个，结果增加的答案反映了这样一个事实：现在又一个元素可以独立地促成潜在的记录事件。 

正确性不取决于大小。 即使是极端值，例如`-10^9`和`10^9`行为与`-1`和`1`，因为只有符号影响元素是否有助于`pos`。
