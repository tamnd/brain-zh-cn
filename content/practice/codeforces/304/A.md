 ## 解决方案
 ## 问题理解

 我们需要计算存在多少个整数边直角三角形，使得所有三个边最多`n`。 

有边的直角三角形`(a, b, c)`满足毕达哥拉斯方程：$a^2+b^2=c^2⟦PROTECT_24⟧b⟦PROTECT_25⟧a^2 + b^2 = c^2 \approx 225.00 + 225.00 = 450.00$调整 a 和 b 更新三角形和 c.abc 的导出值

 该问题限制了双方的顺序：```
1 ≤ a ≤ b ≤ c ≤ n
```顺序很重要，因为三角形就像`(3,4,5)`和`(4,3,5)`应被视为同一个三角形。 条件`a ≤ b`自动删除重复项。 

输入包含单个整数`n`。 输出是有效三元组的数量`(a, b, c)`满足方程和排序约束。 

上限仅为`10^4`。 这立即改变了问题的性质。 甚至一个`O(n^2)`算法执行围绕`10^8`如果在 Python 中仔细实现，最坏情况下的简单操作仍然是边缘性的，但对于轻量级算术来说通常是可以接受的。 一个`O(n^3)`解决方案是完全不可能的，因为它需要大约`10^12`迭代。 

主要挑战是避免不必要的三元组枚举。 

当意外计算重复三角形时，会出现微妙的边缘情况。 

例如：

 输入：```
5
```唯一有效的三角形是`(3,4,5)`。 

正确答案是：```
1
```循环遍历所有有序对的粗心蛮力`(a,b)`不强制执行`a ≤ b`两者都算`(3,4,5)`和`(4,3,5)`并错误地打印`2`。 

另一个容易犯的错误是忘记了`c`也必须至多`n`。 

例如：

 输入：```
10
```这对`(6,8)`产生`c = 10`，这是有效的。 

但`(8,15)`产生`c = 17`，即使它满足方程，也不能被计算在内。 

第三个陷阱来自浮点精度。 一些实现计算：```
c = int(math.sqrt(a*a + b*b))
```然后检查方程是否成立。 对于较大的数字，浮点舍入有时会产生不正确的值。 安全的方法是明确验证：```
c * c == a * a + b * b
```在数三角形之前。 

## 方法

 最直接的暴力解决方案会尝试所有可能的三元组`(a,b,c)`。 

我们循环遍历所有值：```
1 ≤ a ≤ b ≤ c ≤ n
```并检查是否：$a^2+b^2=c^2⟦PROTECT_26⟧b⟦PROTECT_27⟧a^2 + b^2 = c^2 \approx 225.00 + 225.00 = 450.00$调整 a 和 b 更新三角形和 c.abc 的导出值

 这是有效的，因为有效三角形的定义被精确检查。 没有遗漏任何内容，也没有计算任何无效内容。 

问题在于迭代次数。 大致有：$n^3$可能的三元组。 和`n = 10^4`，这变成了关于`10^12`检查时，远远超出了时限。 

关键的观察是一旦`a`和`b`是固定的，其值`c`已经完全确定了。 

由等式可知：$c=\sqrt{a^2+b^2}⟦PROTECT_28⟧b⟦PROTECT_29⟧a^2 + b^2 = c^2 \approx 225.00 + 225.00 = 450.00$调整 a 和 b 更新三角形和 c.abc 的导出值

 因此，我们不迭代三个变量，而是只迭代`(a,b)`并测试所得平方根是否为整数。 

这将搜索空间从三次减少到二次。 

对于每对`(a,b)`和`a ≤ b`，我们计算：```
s = a*a + b*b
c = int(sqrt(s))
```如果`c*c == s`和`c ≤ n`，然后我们找到了一个有效的三角形。 

二次方法成功是因为约束`n ≤ 10^4`允许大约`5 × 10^7`优化 Python 中的轻量级迭代。

 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取整数`n`。 
2. 初始化`answer = 0`。 
3. 迭代`a`从`1`到`n`。 

这将选择三角形的第一条边。 
4. 迭代`b`从`a`到`n`。 

开始于`a`保证`a ≤ b`，所以每个三角形都被计算一次。 
5. 计算：```
s = a*a + b*b
```这是斜边的平方。 
6. 计算：```
c = int(s ** 0.5)
```我们只需要检查是否`s`是一个完美的正方形。 
7. 验证这两个条件：```
c * c == s
c <= n
```第一个条件确认`c`是一个整数。 

第二个确保三角形符合问题边界。 
8. 如果两个条件都成立，则增加答案。 
9. 打印最终答案。 

### 为什么它有效

 该算法检查每个可能的有序对`(a,b)`满意的`1 ≤ a ≤ b ≤ n`。 

对于每一对，只有一个可能的值`c`可以满足毕达哥拉斯方程。 该算法计算该候选值并检查它是否是界限内的有效整数。 

每个有效的三角形都只出现一次，因为循环强制`a ≤ b`。 无法计算无效三角形，因为以下等式：$a^2+b^2=c^2⟦PROTECT_30⟧b⟦PROTECT_31⟧a^2 + b^2 = c^2 \approx 225.00 + 225.00 = 450.00$调整 a 和 b 更新三角形和 c.abc 的导出值

 是直接检查的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

answer = 0

for a in range(1, n + 1):
    for b in range(a, n + 1):
        s = a * a + b * b
        c = int(s ** 0.5)

        if c <= n and c * c == s:
            answer += 1

print(answer)
```外循环选择第一条腿`a`。 内循环从`a`而不是`1`，它会自动删除重复的订单。 

变量`s`商店：$a^2+b^2$该代码计算候选整数平方根`c`使用浮点平方根和整数转换。 关键细节是验证步骤：```
c * c == s
```如果不进行此检查，舍入错误可能会将非正方形错误地分类为正方形。 

条件：```
c <= n
```防止计算斜边超出限制的三角形。 

不需要额外的数组或数据结构，因此内存使用量保持不变。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
```仅循环测试`(1,1)`。 

该算法计算：```
1² + 1² = 2
```自从`2`不是一个完美的正方形，没有三角形被计算在内。 输出变为：```
0
```这证实了算法可以正确处理不存在有效三角形的情况。 

现在考虑重复计数问题：```
5
```一个简单的实现，独立地循环所有`a`和`b`会计算两者：```
(3,4,5)
(4,3,5)
```当前的算法避免了这种情况，因为内循环从`b = a`。 一次`(3,4)`被处理，`(4,3)`永远不会出现。 

最后，考虑斜边超出限制的情况：```
10
```这对`(8,15)`满足毕达哥拉斯方程，因为：$8^2+15^2=17^2$但`17 > 10`，所以条件：```
c <= n
```正确拒绝它。 如果没有这种检查，算法就会过多计算无效三角形。
