 ## 解决方案
 ## 问题理解

 我们以以下格式获得两个有效的公历日期`yyyy:mm:dd`。 任务是计算它们之间相隔多少天。 

公历有熟悉的闰年规则：$\text{Leap year} \iff (y\bmod 400=0) \lor (y\bmod 4=0 \land y\bmod 100\neq 0)$闰年包含 366 天，而不是 365 天，因为二月有 29 天。 

这个问题有趣的部分是“之间”的含义。 查看示例，答案恰好包含一个端点。 一个方便的解释是：

 如果我们将两个日期都转换为“自固定原点以来的天数”，那么答案很简单：$\text{answer}=|f(d_2)-f(d_1)|$在哪里`f(date)`计算该日期之前已经过去了多少天。 

年份范围仅从 1900 年到 2038 年。即使该区间的总天数约为 50,000，这么多方法也足够快了。 在两个日期之间逐日循环的解决方案仍然可以在 2 秒内顺利通过。 这意味着问题不在于大量优化，而在于如何使日历算术正确。 

危险的部分是闰年和边界处理。 小错误会默默地产生错误的答案。 

考虑这些例子。 

输入：```
2000:02:28
2000:03:01
```正确输出：```
2
```2000 年可以被 400 整除，所以二月有 29 天。 一个仅检查 4 整除性的幼稚实现可能会在这里意外地起作用，但如果对世纪年处理不当，则可能会在其他地方失败。 

现在看：

 输入：```
1900:02:28
1900:03:01
```正确输出：```
1
```1900 年可以被 100 整除，但不能被 400 整除，因此它不是闰年。 这是经典的陷阱。 

另一个微妙的情况是日期相等。 

输入：```
2012:05:17
2012:05:17
```正确输出：```
0
```如果实现意外地对两个端点进行了计数，则可能会生成 1。 

月累积是差一误差的另一个常见来源。 

输入：```
2016:03:01
2016:03:02
```正确输出：```
1
```将日期转换为绝对天数时，我们必须添加之前所有月份的长度，而不是当前月份本身。 

## 方法

 最直接的解决方案是暴力模拟。 从较早的日期开始，重复前进一天，直到到达第二个日期，计算进行了多少次转换。 

这是可行的，因为总日期范围很小。 从 1900 年到 2038 年只有大约 50,000 天，因此即使逐日模拟也很便宜。 

烦人的部分是正确实施“第二天”。 我们必须知道每个月的天数，更新闰年的二月，并正确滚动月份和年份的边界。 

更优雅的方法完全避免了模拟。 我们不是从一个日期走到另一个日期，而是将每个日期转换为绝对天数。 

假设我们定义：`days(date) = total days before this date`那么两个日期之间的距离就是它们在时间线上的绝对位置之间的差异。 

要计算日期的该值：

 1. 添加当前年份之前完整年份的所有天数。 
2. 添加当月之前完整月份的所有天数。 
3. 添加月份内的日偏移量。 

关键的观察是日历是可加的。 每个日期都可以唯一地表示为“自固定起源以来已经过去了多少天”。 一旦日期变成整数，问题就简化为减法。 

这消除了所有迭代日期转换并极大地简化了正确性推理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(日期之间的天数) | O(1) | O(1) | 已接受 |
 | 最佳 | O(年 + 月) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将两个输入字符串解析为整数`(year, month, day)`。 

日期到达为`yyyy:mm:dd`，因此分割为`:`直接给出三个分量。 
2. 编写函数`is_leap(year)`。 

如果一年能被 400 整除，或者能被 4 整除但不能被 100 整除，那么年份就是闰年。 
3. 编写函数`to_days(y, m, d)`将日期转换为绝对天数。 

该函数计算给定日期之前已经过去了多少天。 
4. 添加完整年份的贡献。 

每年从`0`到`y - 1`，根据是否是闰秒添加 365 或 366。 

我们只需要 2038 年之前的几年，所以即使是一个简单的循环也很小。 
5. 添加当年完整月份的捐款。 

使用标准月份长度：`[31,28,31,30,31,30,31,31,30,31,30,31]`如果年份是闰年，则将二月设置为 29。 

添加月份之前的所有月份`m`。 
6. 添加月份内的偏移量。 

从那天起`1`表示该月已过去零个完整天数，添加`d - 1`。 
7. 计算两个转换值之间的绝对差。 

这个差异正是日期之间的天数。 

### 为什么它有效

 转换函数在日历日期和连续日时间线上的位置之间建立一对一的映射。 

每个完整的年份都会贡献其确切的天数。 每个完整的月份都会贡献当年的确切天数。 最后，`d - 1`计算当前日期开始之前当前月份内已经过去了多少个完整天数。 

由于两个日期都是使用相同的参考原点进行转换的，因此减去两个总数即可得出将它们分开的确切天数转换数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_leap(year):
    return year % 400 == 0 or (year % 4 == 0 and year % 100 != 0)

def to_days(y, m, d):
    total = 0

    for year in range(y):
        total += 366 if is_leap(year) else 365

    month_days = [31, 28, 31, 30, 31, 30,
                  31, 31, 30, 31, 30, 31]

    if is_leap(y):
        month_days[1] = 29

    for month in range(m - 1):
        total += month_days[month]

    total += d - 1

    return total

def solve():
    y1, m1, d1 = map(int, input().strip().split(':'))
    y2, m2, d2 = map(int, input().strip().split(':'))

    ans = abs(to_days(y2, m2, d2) - to_days(y1, m1, d1))

    print(ans)

solve()
```该实现反映了算法演练中的数学分解。`is_leap`直接编码公历闰年规则。 顺序很重要。 能被 400 整除的年份必须保持闰年，即使它们能被 100 整除。 

的`to_days`函数分三个阶段构建日期的绝对位置。 

第一个循环累计当前年份之前的完整年份。 由于最大年份仅为 2038 年，因此迭代年份的成本微不足道。 

月份数组从二月开始，等于 28。如果当前年份是闰年，我们会在对前几个月求和之前用 29 覆盖它。 这可以避免重复月份表。 

该行：```
total += d - 1
```是最重要的边界细节。 第 1 天表示该月内已过去零个完整天数。 使用`d`相反，会将每个日期向前移动一天并打破日期相等的情况。 

最后，取绝对差可以使日期以任一顺序出现。

 考虑输入：```
1900:02:28
1900:03:01
```该算法首先检查 1900 是否是闰年。 自从`1900 % 100 == 0`和`1900 % 400 != 0`，结果为假。 二月保持长度28。`to_days(1900,03,01)`正好大于 1`to_days(1900,02,28)`，所以答案是：```

```这证实了世纪年的处理是正确的。 

现在检查：```
2000:02:28
2000:03:01
```2000 年可被 400 整除，因此二月长度变为 29。 

时间线看起来像：```
2000:02:28
2000:02:29

```有两天的转换，因此算法返回：```

```这验证了可被 400 整除的年份的特殊闰年例外。 

最后，考虑相同的日期：```

2012:05:17
```两个电话都打给`to_days`产生完全相同的整数，因为转换是确定性的。 他们的差异为零。 

关键的细节是添加`d - 1`而不是`d`。 第 1 天贡献该月内经过的天数为零，从而防止出现相差一的错误。
