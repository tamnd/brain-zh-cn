 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串和许多对子字符串的查询。 对于每个查询间隔，我们重复删除当前子字符串的连续部分。 唯一的限制是我们可以删除什么样的片段：删除的片段必须严格交替，这意味着其中的每个相邻对必须包含不同的字符。 

一次删除可以删除一个字符，或更长的片段，例如`0101`或者`101`，但从来没有像`00`或者`111`因为它们包含相等的相邻位。 每次删除后，字符串的剩余部分会缩小间隙并形成新的字符串，然后继续，直到没有任何内容为止。 任务是计算每个查询子字符串所需的此类删除的最小数量。 

约束很大，最多有 200,000 个字符和 200,000 个查询。 这立即排除了任何模拟删除或以线性时间处理每个查询的解决方案。 任何可接受的解决方案都必须以线性时间预处理字符串，并以常数或对数时间回答每个查询。 

这里经常出现的一个天真的错误是假设因为我们可以删除交替的子字符串，所以我们应该尝试贪婪地删除长的交替段。 这种直觉在简单的情况下就会失效。 例如，在字符串中`11011`，贪婪的删除可能会尝试`101`首先，离开`11`，然后需要再删除两次。 然而，不同的策略似乎是可能的，但仍然不能将答案减少到3以下。关键的困难在于删除受到邻接结构的限制，而不是任意选择的字符。 

另一个微妙的边缘情况是当子串已经完全交替时，例如`01010`。 在这种情况下，答案显然是 1，但是任何仅对相同字符的运行进行计数的方法仍然必须正确处理此类运行的缺失。 

## 方法

 蛮力策略很简单：模拟该过程。 对于每个查询子字符串，我们重复扫描当前字符串，找到最大交替段，将其删除，一直持续到空为止。 每次扫描都会花费线性时间，并且在最坏的情况下我们可能会执行线性删除，从而在最坏的情况下导致三次行为。 这在限制下立即失败。 

关键的观察是我们实际上根本不需要模拟删除。 相反，我们会问什么结构迫使我们执行多个操作。 唯一一次我们被迫将工作拆分到多个删除中是当原始子字符串中的两个相邻字符相等时。 无论我们如何删除字符串的其他部分，这样的一对永远不可能成为同一交替段的一部分，因为邻接相等性是任何连续段内的永久障碍。 

这导致了简化：每次我们看到一个索引`i`这样`a[i] == a[i+1]`，子字符串必须至少需要一项超出基本情况的附加操作。 相反，如果子串没有相等的相邻对，则它本身是交替的，并且可以在一次操作中将其删除。 

因此，答案纯粹变成了每个查询间隔内相邻相等对的计数问题。

 | --- | --- | --- | --- |
 | 模拟删除| 每次查询 O(n²) | O(n) | 太慢了|
 | 相邻相等对的前缀和 | O(n) 预处理后每个查询的 O(1) | O(n) | 已接受 |

 ## 算法演练

 我们将每个查询减少为预先计算的数组上的计数。 

1.构建辅助数组`bad`， 在哪里`bad[i] = 1`如果`a[i] == a[i+1]`， 否则`0`。 这准确地捕获了交替被破坏的位置。 
2. 构建前缀和数组`bad`。 这使我们能够快速计算任何间隔中存在多少个相等相邻对。 
3. 对于每个查询`[l, r]`，计算索引的数量`i`在`[l, r-1]`在哪里`a[i] == a[i+1]`使用前缀和。 
4.答案是`1 + count_of_bad_pairs`。 这`1`对应于基本操作，每个内部相等都会强制执行一个附加操作。 

这样做的原因是每个最大的相同字符块恰好贡献一个强制分离点，并且每个这样的点不能在单个交替删除中处理。 

### 为什么它有效

 不变量是任何有效的操作只能消耗不包含相等相邻字符的子字符串。 因此，每一个位置`a[i] == a[i+1]`充当两个不同“交替兼容区域”之间的强制剪切。 这些削减是独立的，因此每一次削减都会使最小操作数恰好增加 1。 删除的结构不允许跨越这些边界进行合并，因为跨越它们的任何片段都会违反交替条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())
    s = input().strip()

    bad = [0] * (n + 1)
    for i in range(n - 1):
        if s[i] == s[i + 1]:
            bad[i + 1] = 1

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + bad[i]

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        cnt = pref[r - 1] - pref[l - 1]
        out.append(str(cnt + 1))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```该实现依赖于将观察结果直接转换为前缀和。 这`bad`数组被移动，以便每个索引对应于字符之间的边界，这避免了处理查询时出现差一问题。 然后，前缀总和将每个查询转换为恒定时间范围总和。 

一个常见的错误是忘记邻接检查适用于`i`和`i+1`，而不是直接查询范围内的字符。 这就是查询使用的原因`r-1`作为计算坏位置时的上限。

 ## 边缘情况

 由单个字符组成的子字符串始终会产生零个相邻对，因此答案变为 1。该算法会处理此问题，因为查询范围`[l, r-1]`变为空并且前缀差为零。 

完全一致的子串，例如`000000`在每个边界处创建一个坏对，算法精确计数`length - 1`，产生正确的操作次数为`length - 1 + 1`。 

完全交替的子串，例如`010101`没有坏对，因此前缀和差为零，并且答案折叠为一个操作，与整个段对于单次删除已经有效的事实相匹配。
