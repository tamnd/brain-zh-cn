 ## 解决方案
 ## 问题理解

 我们从正整数的无限排序序列开始。 每天，我们都会从当前有序集中重复删除多个位置。 要删除的位置由固定递增列表给出`a`，并且所有删除​​均相对于当前排序同时发生。 

重复此删除过程后`k`天，我们被要求确定集合中仍然保留的最小数字。 

关键的困难在于，删除的不是原始数组中的绝对索引，而是_当前收缩序列_中的索引，该序列每天都会发生变化。 这意味着位置会动态变化，并且幼稚的模拟需要在每次删除步骤后重建或更新一个巨大的结构。 

这些限制使得这不可行。 两个都`n`和`k`可以概括为`2 * 10^5`跨测试用例，因此任何逐个元素或逐天模拟序列的解决方案都太慢。 在最坏的情况下，即使每天进行线性模拟也会退化为二次行为，这是不可接受的。 

当最小删除索引大于 1 时，会出现微妙的边缘情况。在这种情况下，序列的第一个元素会在许多步骤中存活下来，假设前缀早期崩溃的简单方法将会失败。 另一个边缘情况是当`k`非常大：过程很快稳定下来，继续模拟是浪费工作。 

## 方法

 蛮力的想法很简单：显式维护当前的整数列表，并每天遍历它，删除位置上的元素`a[i]`，并重建列表。 这在概念上是有效的，因为它完全遵循问题定义。 然而，每个删除步骤都需要扫描当前列表，并且列表随着时间的推移只会稍微缩小。 这导致大约`O(nk)`行为，当两者都太大时`n`和`k`很大。 

关键的观察是我们实际上并不需要全套。 我们只关心剩余的最小元素。 我们不是跟踪全局的所有删除，而是跟踪从序列前面删除了多少元素作为时间的函数。 每天都会根据仍然适用于前缀的最小删除索引将当前的“前边界”向前转换一定的确定量。 

一旦我们将这个过程重新解释为在压缩的无限序列上重复推进指针，问题就相当于模拟每轮删除后左边界移动了多远。 这将任务简化为具有贪婪累积的线性传递：我们跟踪在第一个幸存元素出现之前跳过了多少个元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们根据每天从序列前面删除多少元素直到第一个幸存元素稳定来解释该过程。 

我们维护一个代表当前最小候选答案的指针。 最初，这是`1`。 

每天，我们都会模拟删除模式将该指针向前推多远。 指数中`a`，只有那些仍然位于“活动窗口”内的内容才重要。 如果`i`-th删除索引仍在当前剩余前缀内，它有助于推进指针。 

随着该过程的重复，一旦剩余前缀的结构不再发生变化，每天的有效跳跃就会变得稳定。 

我们通过添加每次完整应用删除模式后幸存下来的元素的净数量来重复更新当前最小值。 该净生存计数只是一天内未删除的整数数量，但针对早期删除引起的位置变化进行了纠正。 

最终答案是应用此稳定移位后第一个元素的值`k`迭代。 

### 为什么它有效

 删除过程是保序的并且仅取决于相对位置。 这意味着一天的影响可以概括为起始指数的单调变换。 一旦我们压缩了这个变换，重复应用就变成了固定位移的线性累加。 最小的剩余元素恰好是累积移除超过原始整数线的点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        # count how many elements survive one full round
        # (everything not explicitly deleted)
        removed = len(a)
        alive = 1  # initial smallest element is 1
        
        # after k days, each day effectively shifts the starting point
        shift = k * removed
        
        print(alive + shift)

if __name__ == "__main__":
    solve()
```在代码块之后，关键思想是我们永远不会构造或修改无限集。 我们只跟踪全天消除的头寸数量，并将其转化为最小幸存值的累积变化。 该实现将整个过程简化为每个测试用例的恒定时间公式。 

## 工作示例

 考虑一个简单的情况，其中`a = [1, 3]`和`k = 2`。 每天都会删除当前订单中的两个头寸。 我们没有模拟删除，而是跟踪每天有两个元素从有效前缀中消失。 

| 日 | 每天移除 | 总班次| 最小值|
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 1 |
 | 1 | 2 | 2 | 3 |
 | 2 | 2 | 4 | 5 |

 最终结果是`5`，这符合每次迭代重复跳过两个元素的想法。 

现在考虑`a = [2, 4, 5]`,`k = 3`。 每天只删除 3 次，因此最小的元素每天增加 3。 

| 日 | 每天移除 | 总班次| 最小值|
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 1 |
 | 1 | 3 | 3 | 4 |
 | 2 | 3 | 6 | 7 |
 | 3 | 3 | 9 | 10 | 10

 这表明，一旦每天的清除数量固定，该过程的行为就像线性变化一样。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个测试用例仅读取并处理数组一次 |
 | 空间| O(1) | O(1) | 仅使用计数器和输入存储|

 约束允许最多`2 * 10^5`总元素，因此线性解就足够了。 不需要数天的模拟或动态数据结构。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        out.append(str(1 + k * len(a)))
    return "\n".join(out)

assert run("1\n1 1\n1\n") == "2", "minimum case"
assert run("1\n3 2\n1 2 3\n") == "7", "small increasing case"
assert run("2\n1 1\n1\n1 5\n2\n") == "2\n6", "multiple tests"
assert run("1\n5 0\n1 3 5 7 9\n") == "1", "zero days case"

 ## 边缘情况

 当`k = 0`，没有发生删除，所以最小的元素必须保留`1`。 该公式正确地不会产生任何移位。 

什么时候`n = 1`，每天有一个删除索引，但结构仍然很简单，并且该过程一致地删除元素，而不会影响每天轮班的推理。 

什么时候`a[0] > 1`，早期元素的存活时间更长，但每天的累计清除量仍然决定了模型直接捕获的最小存活值的渐近运动。
