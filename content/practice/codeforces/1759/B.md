 ## 解决方案
 ## 问题理解

 我们得到了几个肯定属于某些未知排列的数字。 缺失的数字丢失了，但我们知道所有缺失值的总和。 

问题是我们是否可以选择一些额外的数字，其总和恰好为`s`这样，与给定的数字一起，最终的数组就成为有效的排列。 

长度的排列`n`包含来自的每个整数`1`通过`n`正好一次。 这一要求比仅仅拥有独特的价值观要强烈得多。 如果最终数组中的最大值是`k`，然后每个数字`1`到`k`必须出现。 

限制非常小。 最多有 100 个测试用例，每个测试用例最多包含 50 个已知数字，并且所有值最多为 50。即使是尝试许多候选排列长度的模拟也能在时间限制内顺利运行。 我们不需要复杂的数据结构或高级算法。 

棘手的部分是理解缺失的数字是什么样的。 它们不是任意不同的值。 如果最终数组是以某个最大值结束的排列`k`，那么缺失的数字正是来自`1`到`k`尚未出现在给定数组中的内容。 

考虑一些边缘情况。 

假设输入是：```
1
1 1
1
```已知号码已经`1`。 将数字相加到`1`，我们必须添加另一个`1`，这会创建一个副本。 更大的数字不起作用，因为每个更大的数字至少`2`。 答案是`NO`。 

现在考虑：```
1
3 3
1 4 2
```之间唯一缺失的值`1`和`4`是`3`，其总和恰好是`3`。 添加它会产生`[1,2,3,4]`，所以答案是`YES`。 

另一个微妙的情况是：```
1
2 1
4 3
```粗心的解决方案可能会注意到缺少的总和是`1`并假设我们可以添加`1`。 添加后`1`，该数组将包含`{1,3,4}`，这不是一个排列，因为`2`仍然失踪。 正确答案是`NO`。 

必须存在直到最大值的所有整数的要求是防止许多错误解决方案的关键观察结果。 

## 方法

 一个蛮力的想法是尝试每一个可能的数字集合，其总和为`s`，将它们附加到给定数组，并检查结果是否是排列。 这是正确的，因为它探索了每个候选人的完成情况。 问题是子集的数量呈指数增长。 即使值以 50 为界，也没有必要枚举所有可能性，并且在概念上比问题结构所需的复杂得多。 

重要的观察是排列完全由其最大值决定。 

假设最终排列具有最大值`k`。 那么排列必须包含来自`1`通过`k`。 由于给定的数字已经固定，因此我们需要附加的数字正是该范围中缺失的整数。 

这将问题转化为简单的模拟。 

我们从总和开始`s`。 我们重复添加给定集合中尚未存在的最小正整数。 每次我们添加这样一个数字，我们都会从中减去它`s`。 

如果`s`恰好变成零，我们就找到了一个候选排列。 然后我们只需要验证结果集是否包含来自`1`直至其最大元素。 

如果`s`变为负数，我们已经超出了所需的缺失总和，并且不存在解决方案。 

因为所有值都很小，所以这个过程非常快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳 | O(M + X) | O(M + X) | 已接受 |

 这里`X`是模拟过程中检查的最大值，在给定的约束下该值很小。 

## 算法演练

 1. 读取给定的数字并将它们存储在一组中以便快速进行成员资格检查。 
2. 从`1`，向上扫描正整数。 
3. 只要当前数字尚未出现在集合中，就将其视为缺失的排列值。 从中减去它`s`并将其插入集合中。 
4. 继续直到`s`变为零或负数。 
5.如果`s`变为负数，打印`NO`。 
6. 如果`s`恰好为零，找到集合中的最大值。 
7. 检查每个整数是否来自`1`通过该集合中存在的最大值。 
8. 如果全部都存在，则打印`YES`; 否则打印`NO`。 

### 为什么它有效

 在任何时候，该算法都只会添加必须出现在包含给定元素的任何有效排列中的数字。 我们按升序处理缺失的整数，因为包含当前最大值的每个排列必须包括所有较小的正整数。 

什么时候`s`达到零时，该集合包含原始数字加上恰好缺失的值，其总和等于所需的丢失总和。 如果结果集形成一个完整的范围`1`到其最大元素，它是一个排列。 如果该范围内的某个值不存在，则无法形成有效的排列，因为每个排列也必须包含该缺失值。 

该算法永远不会跳过所需的数字，也不会添加不必要的数字，因此它完全接受有效的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    m, s = map(int, input().split())
    present = set(map(int, input().split()))

    x = 1

    while s > 0:
        if x not in present:
            s -= x
            present.add(x)
        x += 1

    if s < 0:
        print("NO")
        continue

    mx = max(present)

    ok = True
    for v in range(1, mx + 1):
        if v not in present:
            ok = False
            break

    print("YES" if ok else "NO")
```套装`present`存储所有当前已知的数字。 成员资格检查是恒定时间的，这使得可以轻松确定某个值是否已经是排列的一部分。 

该循环按升序处理正整数。 每当一个数字丢失时，如果最终数组要成为排列，它就是必须出现的值之一。 我们从中减去它`s`并将其添加到集合中。 

一旦循环停止`s`不再是积极的。 如果它变成负数，我们就超出了所需的缺失总和，并且不存在有效的完成。 

什么时候`s`恰好达到零，我们执行最终验证。 一组例如`{1,3,4}`没有重复项，但它不是排列，因为`2`缺席。 最终的范围检查会捕获此类情况。 

不存在溢出问题，因为所有数字都很小。 唯一微妙的细节是达到`s == 0`其本身是不够的。 我们仍然必须验证该集合是否形成一个完整的区间`1`至其最大值。

 ## 边缘情况

 考虑：```
1
1 1
1
```该算法从集合开始`{1}`。 第一个缺失的正整数是`2`，所以减去它就可以得到`s = -1`。 由于总和变为负数，所以答案是`NO`。 这可以正确处理所需的缺失总和太小而无法添加任何有效的新排列元素的情况。 

考虑：```
1
2 1
4 3
```该算法添加`1`， 制作`s = 0`。 该集合变为`{1,3,4}`。 最终验证检查数字`1,2,3,4`并发现`2`缺席。 答案是`NO`。 这可以防止接受不完整的范围。 

考虑：```
1
3 3
1 4 2
```该算法添加缺失值`3`， 制作`s = 0`。 该集合变为`{1,2,3,4}`。 每个数字都来自`1`通过`4`存在，所以答案是`YES`。 这证实了算法正确地识别了完整的排列。 

考虑：```
1
5 6
1 2 3 4 5
```下一个缺失值是`6`， 然后`7`， 等等。 添加`6`立即使`s = 0`。 结果集是`{1,2,3,4,5,6}`，这是一个有效的排列。 答案是`YES`。 这种情况表明，原始数字可能已经形成了最终排列的前缀。
