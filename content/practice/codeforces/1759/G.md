 ## 解决方案
 ## 问题理解

 我们给出了未知排列的成对最大值数组。 

排列的长度为偶数`n`。 如果我们将其元素分组`(p1, p2), (p3, p4), ...`并将每对替换为其最大值，我们得到一个数组`b`长度`n/2`。 

任务是重建一个排列`p`产生给定的`b`。 在所有有效排列中，我们必须输出字典顺序最小的排列。 如果没有排列可以产生`b`，我们打印`-1`。 

关键的观察是出现在`b`本身必须出现在排列中。 由于它是其对中的最大值，因此它必须占据该对中的一个位置，而另一个位置必须包含严格较小的未使用数字。 

制约因素很大。 全部的总和`n`所有测试用例最多是`2 · 10^5`，这意味着`O(n log n)`解决方案很容易足够快，而任何二次方都会太慢。 重复扫描所有剩余数字的重建大约需要`n²`在最坏的情况下运行并且无法适应极限。 

一些边缘情况很容易被忽略。 

考虑：```
n = 4
b = [4, 4]
```两对最大值相等。 由于排列只包含每个数字一次，因此该值`4`不能出现两次。 不存在解决方案，所以答案是：```
-1
```仅检查本地配对条件的重建可能会意外重用`4`。 

另一个重要案例是：```
n = 6
b = [2, 4, 6]
```未使用的号码是`{1,3,5}`。 

对于第一对，其最大值为`2`，我们需要一个小于的未使用的数字`2`。 唯一的选择是`1`。 

对于第二对，其最大值为`4`，我们需要一个小于的未使用的数字`4`。 剩下的唯一选择是`3`。 

对于第三对，我们使用`5`。 

这是有效的：```
1 2 3 4 5 6
```首先使用最大的可用较小数字的粗心贪婪在这里仍然有效，但它不一定会产生字典顺序上最小的排列。 

当一对最大值太小时，就会发生最微妙的故障。```
n = 8
b = [8, 7, 2, 3]
```未使用的号码是`{1,4,5,6}`。 

当我们达到最大值时`2`，唯一较小的数字是`1`，它仍然可用，所以我们使用它。 

为最大`3`，我们现在需要一个较小的未使用的数字，但没有剩余。 答案是：```
-1
```任何算法都必须立即检测到此类情况。 

## 方法

 暴力方法将尝试通过测试将缺失的数字分配给每对的第一个位置来重建排列。 由于大约`n/2`数字缺失，可能有以下顺序`(n/2)!`可能的任务。 即使对于中等值`n`，这是完全不可行的。 

问题的结构为我们提供了比一般重建问题更多的信息。 

中的每个值`b`必须在排列中恰好出现一次。 由于它是其对中的最大值，因此我们可以立即将其作为该对的第二个元素：```
(_, b1), (_, b2), ...
```现在唯一的任务是选择每对中的第一个元素。 

假设我们正在处理一对最大值为`x`。 第一个元素必须是未使用的数字，严格小于`x`。 在众多这样的候选人中，我们应该选择哪一位呢？ 

我们希望整个排列在字典顺序上是最小的。 第一个未确定的位置出现在其对应的最大值之前。 为了最小化排列，我们应该在那里放置尽可能小的有效数字。 

这立即表明了一种贪婪的策略。 

保留所有未出现的数字`b`在有序集合内。 对于每个最大值`x`，取仍然小于的最大未使用数`x`。 

乍一看，这似乎与词典最小化相反。 它正确的原因是最大值本身是固定的。 选择最大的可行的较小数字可以为未来的头寸保留较小的值，从而使以后的条目尽可能小。 如果我们过早地消耗微小的值，未来的某些配对可能会变得不可能。 

这正是公认的解决方案中使用的经典贪婪算法。 

我们需要高效的前驱查询：“找到小于的最大未使用值`x`“。有序集支持这一点`O(log n)`时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取数组`b`。 
2. 验证中的所有值`b`是不同的。 

排列只包含每个数字一次。 如果某个值出现两次`b`，重建是不可能的。 
3. 标记出现在的每个值`b`正如已经使用过的那样。 
4. 输入每个数字`1`到`n`没有出现在`b`到一个有序集合中。 
5. 一对一地建立答案。 
6. 求最大值`x = b[i]`，找到严格小于的最大未使用数`x`。 

这是有序集中的前驱查询。 
7. 如果不存在这样的数字，则输出`-1`。 

那么在不违反最大条件的情况下就无法形成这一对。 
8. 追加选择的前任，然后追加`x`到答案。 
9. 从有序集中删除所选的前任。 
10.处理完所有对后，输出构造的排列。 

### 为什么它有效

 每对必须包含其最大值`b[i]`，因此将所有值`b`是强制性的。 

对于最大的一对`x`，任何有效的伙伴必须小于`x`。 在所有可用的候选者中，选择最大的一个是最安全的选择。 它为后面的配对留下了所有较小的数字，这只会增加未来的选项集。 

假设存在有效的重建。 当处理具有最大值的对时`x`，可以在那里分配任何较小的未使用的数字。 用一个更大的未使用的数字替换它仍然小于`x`不能伤害当前的货币对，只能帮助未来的货币对，因为未来的最大值将至少有与以前一样多的可用较小值。 

因此，当解决方案存在时，贪婪的选择永远不会破坏解决方案。 如果算法无法找到某个最大值的较小未使用值`x`，那么根本不存在有效的重构。 

在所有有效的重建中，所产生的排列在字典顺序上也是最小的。 贪婪保留了最早的未来位置的最小值，这正是字典最小化所需要的。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def erase(self, x):
        self.parent[x] = self.find(x - 1)

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

        if len(set(b)) != len(b):
            print(-1)
            continue

        used = [False] * (n + 1)
        for x in b:
            used[x] = True

        dsu = DSU(n)

        for x in range(1, n + 1):
            if used[x]:
                dsu.erase(x)

        ans = []
        ok = True

        for x in b:
            y = dsu.find(x - 1)

            if y == 0:
                ok = False
                break

            ans.append(y)
            ans.append(x)

            dsu.erase(y)

        if ok:
            print(*ans)
        else:
            print(-1)

solve()
```第一个验证步骤检查某个值是否在`b`。 这样的输入永远不可能来自排列，因为每个最大值本身必须出现在排列中。 

DSU 充当前身结构。 对于每个值`v`,`find(v)`返回当前可用的最大数字，不超过`v`。 

最初所有数字都没有出现在`b`可用。 中出现的每个数字`b`从 DSU 中删除，因为它已被保留为最大对。 

对于最大`x`，我们查询`find(x - 1)`。 这直接返回小于的最大可用数字`x`。 

这`erase`操作将一个号码与其前身联系起来。 移除后`y`，以后的查询会自动跳过它。 

DSU 实现是范围内前驱查询的常见技巧`1..n`。 它避免了平衡树并使复杂性保持接近线性。

 ### 示例 1

2 4 1 3 5 6
```该轨迹显示了每对如何消耗最大的可行前驱。

```最初未使用的号码是`{1,4,5,6}`。 

| 配对 | 最大 x | 最大可用 < x | 剩余未使用 | 状态 |

 | 1 | 8 | 6 | {1,4,5} | 好的 |

 ## 边缘情况

 考虑：```
1
4
4 4
```第一步检测到`4`出现两次`b`。 由于排列不能包含两个副本`4`，重建是不可能的，算法立即打印：```
-1
```现在考虑：```
1
8
8 7 2 3
```保留所有最大值后，可用数字为：```
{1,4,5,6}
```处理过程如下：```
8 -> 6
7 -> 5
2 -> 1
3 -> impossible
```前一个查询为`3`回报`0`，意味着没有未使用的值小于`3`存在。 该算法正确报告：```
-1
```最后，考虑：```
1
6
2 4 6
```可用号码有：```
{1,3,5}
```每个前驱查询都会成功：```
2 -> 1
4 -> 3
6 -> 5
```结果：```
1 2 3 4 5 6
```每对都有所需的最大值，每个数字来自`1`到`6`只出现一次，重构有效。
