[CF 1759E - 人形机器人](https://codeforces.com/problemset/problem/1759/E)

 **评分：** 1500
 **标签：** 暴力破解、dp、排序
 **求解时间：** 2m 30s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有一个具有初始力量的人形生物`h`以及一群拥有超能力的宇航员`a[i]`。 

只有当宇航员的力量严格小于人形生物当前的力量时，人形生物才能吸收宇航员。 吸收后，宇航员消失，人形获得`floor(a[i] / 2)`力量。 

该人形生物还拥有三种消耗品增益。 两种绿色血清使当前功率加倍，一种蓝色血清使电流功率增加三倍。 每种精华液最多可使用一次。 

目标是最大限度地吸收宇航员数量。 

第一个观察结果是宇航员的顺序很重要。 较早吸收较弱的宇航员可能会增加足够的力量，以便稍后吸收较强的宇航员。 由于吸收需要`a[i] < h`，体型较小的宇航员总是更容易被消耗。 

约束是主要提示。 所有测试用例中的宇航员总数最多为`2 * 10^5`，所以一个`O(n log n)`解决方案是完全安全的。 任何二次方都会太慢，因为`n^2`大约可以达到`4 * 10^10`最坏情况下的操作。 

一个微妙的边缘情况来自“严格”一词。 

输入：```
1
1 5
5
```答案是：```
0
```宇航员无法被吸收，因为`5`不严格小于`5`。 粗心的实现使用`<=`会错误地返回`1`。 

另一个容易犯的错误是假设血清应该始终保存以备后用。 

输入：```
1
3 1
2 4 100
```如果不立即使用精华液，任何东西都无法被吸收。 最佳策略是从血清开始。 任何贪婪的规则，例如“当所有可能的吸收都用尽时才使用血清”仍然必须正确处理最初不可能吸收的情况。 

第三个边缘情况是血清的使用顺序很重要。 

输入：```
1
1 2
11
```首先使用蓝色精华液给予力量`6`，然后绿色血清给出`12`，使吸收成为可能。 首先使用两种绿色精华液仅给出`8`，这是不够的。 任何固定单一血清顺序的解决方案都可能会错过最佳值。 

最后观察到总共只有三种血清。 这个微小的数字改变了整个问题。 

## 方法

 暴力解决方案将对宇航员进行排序，然后尝试所有可能的操作顺序。 每时每刻我们都可以吸收一名可用的宇航员，如果剩下的话使用绿色血清，或者如果剩下的话使用蓝色血清。 

这种搜索是正确的，因为它探索了每一种法律策略。 问题在于州的数量。 人形的力量不断变化，最多可达`2 * 10^5`宇航员。 单纯的搜索很快就会变得不可行。 

关键的观察结果是，对宇航员进行分类消除了大部分复杂性。 

假设宇航员`x`功率比宇航员还小`y`。 如果我们能够吸收`y`，那么我们还可以吸收`x`。 尽早吸收较小的宇航员永远不会更糟糕，因为他们只会增加我们的力量，并且不会消耗时间以外的资源，这在这里无关紧要。 

排序后，每一个最优策略都会从左到右吸收宇航员。 唯一真正的决定是何时使用这三种精华液。 

现在请注意，正好有两种绿色血清和一种蓝色血清。 他们的使用顺序是唯一的之一`GGB`,`GBG`， 或者`BGG`。 

那只是`3! / 2! = 3`的可能性。 

对于固定的血清顺序，模拟变得简单。 按排序顺序处理宇航员。 每当当前宇航员无法被吸收时，就消耗所选顺序中的下一个血清。 如果没有剩余血清，则模拟结束。 

由于只有三种可能的血清顺序，我们可以模拟所有三种并取最大答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按非降序对宇航员能力进行排序。 

任何稍后可以被吸收的宇航员也可以在所有较弱的宇航员被吸收后被吸收，因此排序让我们可以从最小到最大处理它们。 
2. 列举三种可能的血清顺序：`[(2,2,3), (2,3,2), (3,2,2)]`这里`2`代表绿色血清和`3`代表蓝色血清。 
3. 对于一个固定的血清订单，从初始功率开始`h`, 宇航员指数`i = 0`, 和血清指数`j = 0`。 
4. 当还剩下宇航员时：

 如果`a[i] < current_power`，吸收该宇航员并增加能量`a[i] // 2`。 
5. 否则，如果所选顺序中存在另一种血清，请使用它。 

将当前功率乘以下一个血清乘数并提高血清指数。 
6、否则，宇航员将无法被吸收，血清也不会残留。 

停止模拟。 
7. 记录吸收了多少宇航员。 
8. 对所有三个血清订单重复模拟。 
9. 输出最大结果。 

### 为什么它有效

 经过排序，每一个被吸收的宇航员只会增加人形生物的力量。 没有理由跳过当前可吸收的宇航员并吸收较大的宇航员，因为较小的宇航员至少同样容易消耗并提供额外的能量。 

唯一有意义的决定是两种绿色血清和一种蓝色血清的相对位置。 由于只有三种不同的顺序，因此每种可能的血清策略都由其中一个模拟代表。 

对于固定的血清订单，在吸收可能的情况下延迟血清的使用是最佳的。 首先吸收严格增加力量并保留所有未来的选择。 仅当无法取得进展时才需要血清。 

由于每个有效策略都对应于三个血清顺序之一，并且每个模拟都遵循该顺序的最佳行为，因此在三个模拟中取最大值会产生最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def simulate(arr, h, order):
    power = h
    serum_idx = 0
    absorbed = 0
    n = len(arr)
    i = 0

    while i < n:
        if arr[i] < power:
            power += arr[i] // 2
            absorbed += 1
            i += 1
        elif serum_idx < 3:
            power *= order[serum_idx]
            serum_idx += 1
        else:
            break

    return absorbed

def solve():
    t = int(input())
    orders = [
        (2, 2, 3),
        (2, 3, 2),
        (3, 2, 2)
    ]

    answers = []

    for _ in range(t):
        n, h = map(int, input().split())
        arr = list(map(int, input().split()))
        arr.sort()

        best = 0
        for order in orders:
            best = max(best, simulate(arr, h, order))

        answers.append(str(best))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```该数组在每个测试用例开始时排序一次。 之后，每次模拟从左到右扫描数组一次。 

这`simulate`函数维护三个状态：当前功率、下一个要处理的宇航员以及接下来应该使用所选顺序中的哪种血清。 

一个常见的错误是使用`<=`而不是`<`检查吸收性时。 该语句需要严格较小的功率。 

另一个微妙之处是血清的使用。 我们仅在当前无法吸收下一位宇航员时才使用血清。 首先吸收总是至少同样好，因为它可以在不消耗有限资源的情况下增加功率。 

Python 整数自动处理重复乘法后可能出现的大幂，因此溢出不是问题。

 ## 边缘情况

 考虑：```
1
1 5
5
```排序后，唯一拥有权力的宇航员`5`。 人形也有力量`5`。 算法检查`5 < 5`，这是错误的。 它可能使用血清，但没有它们，宇航员就无法被吸收。 严格比对与声明完全一致，杜绝常见问题`<=`漏洞。 

考虑：```
1
3 1
2 4 100
```排序后的数组已经是`[2, 4, 100]`。 第一个宇航员无法被吸收，因为`2 < 1`是假的。 模拟立即开始根据所选顺序消耗血清。 这可以正确处理一开始就不可能取得进展的情况。 

考虑：```
1
1 2
11
```三种血清顺序分别进行测试。 命令`(3, 2, 2)`达到权力`12`两次血清后并吸收宇航员。 命令`(2, 2, 3)`只达到`8`在蓝色血清之前并且表现不同。 列举所有三种可能性可确保永远不会错过最佳排序。 

考虑：```
1
2 6
6 7
```第一个宇航员无法被吸收，因为功率必须严格更大。 使用血清可以提高人形生物的力量，之后两名宇航员都可以被吸收。 该算法正确地等待吸收合法，而不是认为相等就足够了。
