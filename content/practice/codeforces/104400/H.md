 ## 解决方案
 ## 问题理解

 我们收到一份编程竞赛日志，需要根据类似 ICPC 的规则重建参与者的最终排名，然后用奖牌分隔符打印排名。 

每个参与者都会提交最多 20 个问题的意见。 每次提交都有一个时间戳和一个结果。 只有每个问题最早成功提交的内容才会影响评分。 如果一个问题永远得不到解决，它就没有任何贡献。 

对于已解决的问题，分数贡献是从比赛开始到首次接受提交的分钟数，加上针对同一问题的每个早期非 CE 错误提交的 20 分钟。 编译错误很特殊，因为它们不会增加惩罚，而所有其他错误结果都会增加惩罚。 

参与者首先按解决问题的数量排名，然后按总罚分排名，最后按字典用户名顺序排名。 

排名后，我们不会简单地打印列表。 我们必须插入正好三个标记为“GOLD”、“SILVER”和“BRONZE”的分界线。 这些线定义了排名的连续部分。 最上面的部分是金牌获得者，其次是银牌获得者，然后是铜牌获得者，最后是非奖牌获得者。 

奖牌获得者的数量受参赛者总数的比例限制。 至少 10% 必须是黄金，至少 30% 必须是黄金或白银组合，至少 60% 必须是金、银或青铜组合。 在选择削减位置的所有有效方法中，我们更喜欢首先最小化金牌，然后是银牌，然后是铜牌。 

这些约束清楚地表明，需要完整的模拟，但不需要大量优化工作，因为 m 最多为 2000，t 最多为 200000。排序提交主导了复杂性，这是完全可以管理的。 

在实践中，有一些陷阱很重要。 首先，提交没有排序，因此按输入顺序进行处理会误算惩罚，因为错误的尝试只能按时间顺序计算在第一个 AC 之前。 其次，CE提交不会产生处罚，很容易被意外包括在内。 第三，必须使用楼层划分小心地将时间转换为分钟。 最后，奖牌分割是由组大小的字典最小化唯一确定的，这很容易被误读为贪婪阈值问题，但一旦正确解释约束，它实际上是确定性的。 

## 方法

 暴力模拟将尝试处理每个参与者和每个问题的每个提交，重复扫描较早的提交以确定 AC 是否是第一个以及在它之前发生了多少次错误尝试。 这可能会退化为对每个参与者问题对重复排序或重新扫描日志，在最坏的情况下导致大约 O(m·t²) 的行为。 2000 名参与者和 200000 份提交作品，这远远超出了需要。 

关键的观察结果是，每个参与者-问题对都是独立发展的，并且只有最早的 AC 才重要。 如果我们按时间对所有提交进行一次排序，我们就可以按时间顺序处理它们并增量地维护状态。 每对存储它是否已经解决以及在解决之前发生了多少与惩罚相关的错误提交。 这将整个系统减少为对排序提交的单个线性扫描。 

一旦计算出分数，排名只是按固定键对参与者进行排序。 奖牌分配变成了确定性分区问题：计算满足百分比约束的最小有效前缀大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重复扫描模拟| O(m·t²) | O(百万) | 太慢了|
 | 排序+单遍模拟| O(t log t + t + m log m) | O(百万) | 已接受 |

 ## 算法演练

1. 解析所有提交内容并将时间戳转换为从比赛时间开始算起的总秒数。 这允许独立于输入顺序的正确时间顺序。 
2. 按时间戳对提交进行排序。 如果时间戳相等，它们之间的顺序不会影响正确性，因为同一秒的提交不会与每个参与者的重复提交发生冲突。 
3. 为每个参与者和每个问题维护一个状态，包括是否已经解决，以及在解决之前发生了多少次导致惩罚的错误提交。 
4. 按时间顺序扫描提交的材料。 对于每个提交，如果该参与者的问题已经解决，请忽略它。 
5. 如果提交的内容是编译错误，则完全跳过，因为它不会导致处罚。 
6. 如果提交的答案错误、时间限制、内存限制或运行时错误，则增加该参与者-问题对的错误尝试计数器。 
7. 如果提交被接受并且问题尚未解决，则将其标记为已解决。 记录求解时间（以分钟为单位），并将惩罚计算为solve_time_分钟加上之前计算的错误尝试次数的 20 倍。 
8. 处理完所有提交后，汇总每个参与者的结果：计算已解决的问题并对所有已解决的问题进行惩罚总和。 
9. 按照先减少已解决的数量，然后增加惩罚，最后按字典顺序的用户名对参与者进行排序。 
10. 计算奖牌切割尺寸。 令 g 为黄金参与者的最小数量，使得 g 至少为 ceil(0.1m)。 令 s 为使得 g + s 至少为 ceil(0.3m) 的最小数。 令 b 为使得 g + s + b 至少为 ceil(0.6m) 的最小数。 这些选择确保了最少的词典奖牌分配。 
11. 按顺序输出参与者，在第 g 个之后插入 GOLD，在下一个 s 之后插入 SILVER，在下一个 b 之后插入 BRONZE。 

### 为什么它有效

 按排序顺序处理提交可以保证当我们遇到某个问题的第一个 AC 时，所有影响惩罚的早期提交都已经被计算在内。 这使得错误尝试计数器在求解时准确。 因为我们从不回顾之前的事件，所以每次提交都会被处理一次，每个参与者的每个问题都会最终确定一次，从而同时保持正确性和效率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def to_seconds(t):
    h = int(t[0:2])
    m = int(t[3:5])
    s = int(t[6:8])
    return h * 3600 + m * 60 + s

def main():
    n, m, t = map(int, input().split())
    users = []
    idx = {}
    for i in range(m):
        name = input().strip()
        users.append(name)
        idx[name] = i

    subs = []
    for _ in range(t):
        u, tm, prob, st = input().split()
        subs.append((to_seconds(tm), u, ord(prob) - ord('A'), st))

    subs.sort(key=lambda x: x[0])

    solved = [[False] * n for _ in range(m)]
    wrong = [[0] * n for _ in range(m)]
    solve_time = [[0] * n for _ in range(m)]

    for time, u, p, st in subs:
        i = idx[u]
        if solved[i][p]:
            continue
        if st == "CE":
            continue
        if st == "AC":
            solved[i][p] = True
            solve_time[i][p] = time
        else:
            wrong[i][p] += 1

    res = []
    for i in range(m):
        cnt = 0
        pen = 0
        for p in range(n):
            if solved[i][p]:
                cnt += 1
                pen += solve_time[i][p] // 60 + wrong[i][p] * 20
        res.append(( -cnt, pen, users[i], cnt))

    res.sort()

    def ceil_div(x, y):
        return (x + y - 1) // y

    need_g = ceil_div(m, 10)
    need_s = ceil_div(3 * m, 10)
    need_b = ceil_div(6 * m, 10)

    g = need_g
    s = max(0, need_s - g)
    b = max(0, need_b - g - s)

    out = []
    gold_end = g
    silver_end = g + s
    bronze_end = g + s + b

    for i, (_, __, name, cnt) in enumerate(res):
        if i == gold_end:
            out.append("GOLD")
        if i == silver_end:
            out.append("SILVER")
        if i == bronze_end:
            out.append("BRONZE")
        out.append(f"{name} {cnt} {sum(0 for _ in [])}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```实现的核心是按时间顺序扫描已排序的提交。 两个 2D 数组可确保每次提交时进行恒定时间的状态更新，从而避免重新扫描历史记录的需要。 

排名步骤将所有排序逻辑打包到单个元组中，其中负数求解计数确保降序排列。 处罚和用户名自然就解决了关系。 

奖牌边界直接根据比例约束计算，然后转换为排序排名中的前缀削减位置。 

## 工作示例

 考虑一个包含三个用户和两个问题的简化案例。 假设提交的内容在排序后显示，Alice 很早就解决了这两个问题，没有任何错误的尝试，Bob 在几次错误尝试后解决了一个问题，而 Carol 没有解决任何问题。 

| 活动 | 爱丽丝A | 爱丽丝B | 鲍勃·A | 鲍勃·B | 卡罗尔·A | 卡罗尔·B |
 | --- | --- | --- | --- | --- | --- | --- |
 | 西澳/其他 | 0 | 0 | 2 | 0 | 0 | 0 |
 | 交流时间| 10 分钟 | 15 分钟 | 30 分钟 | - | - | - |

 处理后，Alice 有 2 个已解决和 25 个惩罚，Bob 有 1 个已解决和 70 个惩罚，Carol 有 0 个已解决和 0 个惩罚。 

排序顺序变为 Alice、Bob、Carol。 如果 m = 3，则金牌至少需要 1 个，银牌至少需要 1 个才能达到 30%，铜牌至少需要 2 个才能达到 60%，从而导致 1, 1, 1 的分裂。 

该跟踪显示了惩罚如何仅取决于 AC 前的错误提交，以及排名如何忽略所有 AC 后的噪音。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|

 | 时间 | O(t log t + m · n) | O(t log t + m · n) | 排序提交占主导地位，然后是单一扫描和聚合|
 | 空间| O(百万) | 存储每个参与者每个问题状态 |

 该限制允许最多 200000 个提交和 2000 个参与者，因此排序和线性处理完全符合限制。
