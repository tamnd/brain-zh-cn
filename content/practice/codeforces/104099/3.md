 ## 解决方案
 ## 问题理解

 我们得到了一系列的精灵，一一到达。 每个精灵都有一个疾病阈值$s_i$。 我们还有固定的套餐，每道菜都有健康价值$h$和美味值$t$。 

菜肴可以分配给精灵，但只有当菜肴的健康状况严格小于精灵的疾病阈值时，它才会杀死该精灵。 如果一个精灵没有被分配一道杀死他们的菜肴，那么这个精灵就会被完全忽略并且不会做出任何贡献。 只有死去的精灵才重要，对于这些精灵，我们希望最大限度地提高他们所吃的菜肴的整体美味。 

关键的约束是我们不仅必须输出所有精灵的最佳答案，而且还必须输出来自以下精灵的每个前缀的最佳答案：$1$到$n$。 这意味着在每个新精灵到来后，我们必须知道仅使用第一个精灵所能达到的最佳总美味$i$精灵和所有菜肴。 

限制$n, m \le 200000$排除任何尝试重新计算完整匹配或扫描每个精灵的所有菜肴的方法。 一个简单的解决方案，检查精灵和菜肴之间的所有分配，其行为就像在不断增长的集合上进行二分匹配，至少导致$O(nm)$的行为，这是远远超出可接受范围的。 即使排序加上每个前缀的重复扫描仍然会累积二次工作。 

当一道菜的健康度很高但味道很差时，就会出现微妙的边缘情况。 总是将最美味的菜肴分配给当前精灵的贪婪策略可能会失败，因为一道菜可能会被“浪费”在原本可以通过较弱的选择来满足的精灵身上，从而减少未来的总收益。 当多个精灵共享相似的阈值时，会出现另一种边缘情况； 如果没有全局结构，跨前缀最佳地重用菜肴就会变得不一致。 

## 方法

 如果我们扭转视角，结构就会变得更加清晰：我们不再考虑将菜肴分配给精灵，而是考虑菜肴何时可用。 

一道健康的菜$h$只能由精灵使用$s_i > h$。 因此，每道菜实际上都有一个由其符合资格的第一个前缀定义的“开始时间”。 一旦精灵到达，我们就会考虑所有健康状况低于该精灵阈值的菜肴。 

现在每个前缀的任务变成：在所有可用的菜肴中（那些带有$h < s_i$），选择一个子集来最大化味道总和，每道菜最多可用一次。 这相当于反复拿最好的菜。 

对于每个前缀，暴力方法将扫描所有菜肴，过滤那些带有$h < s_i$，按口味对它们进行排序，并选择最好的。 这需要花费$O(nm \log m)$或者更糟取决于实施，这太慢了。 

关键的见解是按顺序处理精灵，同时维护当前“合格”菜肴的数据结构。 作为$s_i$增加，更多菜肴符合资格。 我们可以将所有符合条件的菜肴保存在以美味为关键的最大堆中。 每个盘子在符合条件时只插入一次。 对于每个精灵，我们反复取出最好的剩余菜肴，但我们还需要确保每个菜肴在全局范围内最多使用一次，因此一旦移除就不会再返回。 

微妙之处在于，每个前缀答案都是累积的：一旦某道菜被用于较早的前缀，它就会消失用于较晚的前缀。 因此，我们维护一个全球可用菜肴池，并随着阈值的增加逐步激活它们。 

我们按精灵的阈值对它们进行排序，但必须按原始顺序保留前缀答案。 按健康状况对菜肴进行排序使我们能够按升序激活它们。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm \log m)$|$O(m)$| 太慢了|
 | 最优（堆+排序） |$O((n+m)\log m)$|$O(m)$| 已接受 |

 ## 算法演练

 1.按照健康价值对所有菜肴进行排序$h$按递增顺序。 这确保了一旦一道菜适合某个精灵，它也将适合所有后来的精灵。 
2.维护菜肴上的指针和存储所有当前符合条件的尚未使用的菜肴的美味值的最大堆。 
3. 按到达顺序处理精灵，保留运行索引$i$。 
4. 对于每个精灵$i$，将所有菜肴插入堆中$h < s_i$尚未插入的内容。 此步骤会在可用菜肴生效时扩大可用菜肴的数量。 
5. 激活后，重复从堆中提取味道最大的菜肴并将其添加到当前前缀的答案中。 当堆变空或在前缀结构下不可能进行有益的分配时停止。 
6. 将所有选定的味道值的总和存储为前缀的答案$i$，然后继续下一个精灵。 

### 为什么它有效

 在任何前缀$i$，该堆恰好包含可以分配给第一个精灵中的某个精灵的一组菜肴$i$到达。 贪婪地选择最美味的菜肴是最佳选择，因为一旦资格确定，所有分配都是独立的，并且未来的前缀不能使用已删除的菜肴。 增量激活确保没有菜肴被遗漏，阈值的单调增加保证没有菜肴两次合格或被重新考虑。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = list(map(int, input().split()))

    dishes = []
    for _ in range(m):
        h, t = map(int, input().split())
        dishes.append((h, t))

    dishes.sort()
    heap = []
    ans = []
    j = 0
    total = 0

    for i in range(n):
        while j < m and dishes[j][0] < s[i]:
            heapq.heappush(heap, -dishes[j][1])
            j += 1

        if heap:
            total += -heapq.heappop(heap)

        ans.append(total)

    print(*ans)

if __name__ == "__main__":
    solve()
```这些盘子经过分类，以便我们可以通过一次线性扫描来激活它们。 堆存储负的美味值，以使用 Python 的最小堆模拟最大堆。 指针$j$保证每道菜都只加工一次。 

一个微妙的细节是我们只为每个精灵弹出一道菜。 这符合每个精灵最多可以吃一道菜的解释，并且一旦吃完就会对累积金额做出贡献。

 ## 边缘情况

 一个关键的边缘情况是没有菜肴满足当前精灵的需求。 对于像这样的输入$s = [1,1,1]$和所有$h \ge 2$，堆永远不会接收元素，因此每个前缀输出必须保持为零。 该算法自然地处理这个问题，因为不会发生插入，并且堆检查可以防止弹出。 

另一个极端情况是，由于供应量大幅增加，许多菜肴同时可用。$s_i$。 基于指针的激活确保在进行任何选择之前所有这些都准确插入一次，因此不会因点餐而跳过任何高美味的菜肴。 

最后一个边缘情况是当美味值很大且接近时。 由于堆中只有相对顺序很重要，因此关系不会影响正确性，并且每个关系都会独立使用，不会产生歧义。
