 ## 解决方案
 ## 问题理解

 我们得到了几个独立的数组，对于每个数组，我们都可以使用一种非常具体的操作来修改元素：选择一个索引并用它的平方替换该位置的值。 我们可以对同一个索引多次重复此操作。 我们的目标是使用尽可能少的此类操作使整个数组不减，并报告最小数量，或者确定它无法完成。 

关键的困难在于平方会以高度非线性的方式改变值。 小数字可以根据其大小缓慢或快速增长，一旦值增加，它们很容易破坏与邻居的排序。 我们不能自由地对元素重新排序，因此每个操作仅局部变换一个位置，同时影响全局排序约束。 

约束很大：所有测试用例的元素总数可以达到 2·10^5。 这立即排除了任何尝试模拟每个元素所有可能的平方序列或明确探索状态的解决方案。 每个测试用例的任何方法都必须接近线性或近线性。 由于每个元素可以多次平方，因此真正的复杂性不仅在于数组大小，还在于值的增长行为。 

当平方根本无济于事时，就会出现一个微妙的问题。 例如，如果我们有一个像 [5, 4] 这样的递减对，则 4 的平方得到 16，这修复了局部反转，但在较长的链中，它可能会打破早期的约束。 更糟糕的是，有时没有任何平方序列可以解决排序依赖关系中的矛盾，我们必须尽早发现这一点。 

另一个重要的边缘情况是当数字已经很大时。 如果一个元素相对于相邻元素变得太大，进一步平方只会使情况变得更糟，可能会妨碍可行性。 一种总是“贪婪地修复局部反转”的幼稚方法很容易使一个区域过度平滑并破坏另一个区域。 

## 方法

 强力解释会将每个索引视为具有无限可能值序列：

 a[i]、a[i]^2、a[i]^(2^2)、a[i]^(2^3) 等等。 我们可以想象搜索每个位置平方次数的所有选择，然后检查结果数组是否是非递减的并最小化总操作。 

这在原则上是正确的，但完全不可行。 即使我们将每个元素的平方数限制在一个小常数，例如最多 60（因为值迅速爆炸），状态空间在最坏的情况下会变成 60^n，这是不可能的。 即使对位置进行动态规划也会失败，因为每个位置都依赖于无限范围的可能的先前值。 

关键的观察是每个元素都不是以任意方式独立的。 对于固定元素，我们永远不需要盲目考虑平方的所有幂。 相反，重要的是所需的最小平方数，以便元素至少与先前选择的值一样大。 一旦我们决定一个元素被平方多少次，它的最终值就固定了，我们只向前传播约束。 

这表明贪婪的从左到右的构造。 在每个位置，我们都保持前一个位置允许的最小值。 对于当前元素，我们尝试应用平方，直到它足够大以满足非递减顺序。 然而，我们还必须确保我们不会过度调整，从而导致未来的元素无法赶上。

关键的结构是单调增长：平方总是增加值（对于≥2的整数），并且增长速度极快。 这意味着每个元素在超出所有未来限制之前只有极少数有意义的状态。 因此，我们可以模拟每个元素达到阈值所需的最小平方数，并将该阈值向前传播。

 | ---| ---| ---| ---|

 ## 算法演练

 我们从左到右处理数组，同时保持当前位置的最小允许值，该值是从所选转换后的前一个元素派生的。 

1. 初始化一个操作计数器，并将当前所需的下限设置为第一个元素。 第一个元素不需要调整，因为没有先前的约束。 
2. 对于每个下一个元素，将其与当前下限进行比较。 如果它已经足够大，我们不做任何操作就接受它，并将下限更新为此值。 
3. 如果它小于下限，我们重复对其进行平方，直到它至少等于下限。 每次平方算作一次操作。 
4. 如果在此过程中值停止变化或增长太慢而无法达到所需的界限（例如，0 或 1 种情况），我们就得出不可能的结论。 
5. 调整元素后，我们将新的下限设置为此调整后的值并继续。 

微妙之处在于平方不是线性增长。 我们从不试图“完全匹配”； 我们只关心跨过门槛。 所需的平方次数由重复平方下值增长的速度唯一确定。 

### 为什么它有效

 该算法保持了不变式，即在处理位置 i 后，我们为 a[i] 选择了一个有效的变换值，该值是在允许的操作下可实现的最小可能值，同时仍然满足直至 i 的非递减顺序。 这一点至关重要，因为选择大于必要值只会使未来的约束更难以满足。 

在每一步中，我们都不会重新审视之前的决定。 这是安全的，因为任何较早的元素仅通过其最终值限制未来的元素，而增加最终值只会增加后面位置的难度。 因此，局部最小可行性意味着全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ops = 0
        prev = a[0]
        
        for i in range(1, n):
            x = a[i]
            
            if x >= prev:
                prev = x
                continue
            
            # try squaring until it reaches prev
            cnt = 0
            while x < prev:
                if x <= 1:
                    x = float('inf')
                    break
                x = x * x
                cnt += 1
            
            if x < prev:
                print(-1)
                break
            
            ops += cnt
            prev = x
        else:
            print(ops)

if __name__ == "__main__":
    solve()
```该代码遵循贪婪策略的直接模拟。 变量`prev`将最后选择的值存储在转换后的数组中。 对于每个元素，如果它已经满足排序约束，我们立即接受它。 否则，我们反复对它求平方，直到它交叉`prev`，沿途计数操作。 

一个微妙的实现细节是值 0 和 1 的处理。由于平方不会增加它们，因此它们永远无法达到更大的所需界限，因此我们立即将这种情况标记为不可能。 在此问题约束中，值是正的，但防止停滞可确保扩展变体的正确性。 

该循环使用Python的`else`for 循环上的子句，用于区分成功完成和由于不可能而提前终止。

 ## 边缘情况

 关键的边缘情况是当值变为 1 时。由于 1 的平方仍然是 1，因此任何大于 1 的要求都会导致实例无法实现。 例如，输入`[1, 2]`很好，但是`[2, 1, 2]`可能会失败，具体取决于传播，因为如果约束不正确，中间元素将无法增长。 

另一个微妙的情况是早期的大平方会造成过冲。 例如，如果我们有`[2, 3, 2]`，如果我们不小心地最小化运算，第二个元素可能会不必要地平方，从而迫使第三个元素多次平方。 贪心策略通过始终选择每一步所需的最小平方来避免这种情况。 

第三种情况是长递减链，例如`10010 ... 10000`。 这些应力重复平方计数，但由于指数增长而保持安全，确保每个元素以少量步骤终止。
