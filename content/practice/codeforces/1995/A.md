 ## 解决方案
 ## 问题理解

 我们正在研究一个$n \times n$如果我们按值对单元格进行分组，则每个单元格恰好属于一个对角线的网格$i + j$。 每个这样的值都定义一条从顶部边缘向右或底部边缘延伸的对角线，具体取决于它在正方形中的位置。 

我们被给予$k$相同的芯片，并且必须将它们全部放置在不同的单元上。 如果至少有一个芯片落在属于对角线的任何单元上，则该对角线将变为“活动”。 目标是放置所有芯片以使活动对角线的数量尽可能少。 

从结构中观察到的关键是对角线的不同之处在于它们包含的单元数量。 靠近角落的一些对角线仅包含一个单元，而中心对角线则更长并且可以容纳许多芯片。 问题本质上是问如何打包$k$将项目分成组（对角线），以便我们使用尽可能少的组，因​​为每个组的容量由其对角线长度决定。 

限制很小：$n \le 100$，因此每个测试用例都可以独立推理，而不必担心每个用例的效率超出常数或线性。 即使对所有对角线进行直接模拟也是可以接受的，但该结构允许直接公式。 

边缘情况出现时$k = 0$，其中没有对角线被占用，并且当$k = n^2$，其中每个单元格都被填充并且每个对角线都被占用。 一个微妙的情况是当$k$很小：贪婪的直觉可能建议总是首先填充最长的对角线，但最佳策略仅取决于需要覆盖多少条对角线$k$，而不是实际放置细节。 

## 方法

 直接的暴力方法会尝试将芯片一个接一个地放置，并保留哪些对角线已被使用。 在每一步中，它都会尝试每个可能的空单元，模拟放置芯片，并跟踪有多少条不同的对角线变得活跃。 这很快就会呈指数增长，因为每个放置分支最多可达$n^2$选择以及选择方式的数量$k$细胞是组合的。 即使进行了修剪，这种方法也会爆炸$n = 100$。 

关键的结构见解是，除了对角线是具有已知容量的独立桶这一事实之外，网格的确切几何形状并不重要。 每条对角线对应固定数量的单元，将多个芯片放置在同一条对角线内仅花费一个“占用对角线”。 因此，为了最大限度地减少占用的对角线，我们希望在使用新的对角线之前尽可能密集地填充对角线。 

如果我们按容量（每个对角线中的单元格数量）按降序对对角线进行排序，那么最优策略就会变得贪婪：首先取出最大的对角线并完全填充它们，直到我们放置所有$k$筹码。 这个过程中使用的对角线的数量就是答案。 

由于对角结构$n \times n$网格是固定的，我们可以预先计算一次对角线尺寸列表$n$，然后贪婪地减去$k$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n^2) | O(n^2) | 太慢了 |
 | 贪心于对角线大小 | 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算一个对角线的数量$n \times n$网格。 有$2n - 1$由以下值形成的对角线$i + j$。 这给出了我们将分配芯片的结构。 
2. 计算每条对角线的大小。 对于对角线索引$d$，其大小从 1 增加到$n$，然后对称地减小回 1。这反映了有多少单元格满足$i + j = d$。 
3. 按降序对这些对角线尺寸进行排序。 直觉是，使用更大的对角线可以减少存储相同数量的芯片所需的对角线的数量。 
4. 迭代排序的对角线大小。 对于每条对角线，减去其容量$k$，并将其计为已使用。 停一次$k \le 0$。 
5. 返回使用的对角线数量。 

### 为什么它有效

 每个对角线都是一个具有固定容量的独立容器，使用其中的任何单元格所占用的对角线的数量相同。 因此，最小化占用的对角线就等于最小化需要覆盖的容器数量$k$容量单位。 始终首先使用最大的可用容器的贪婪策略是最佳的，因为用较小的对角线替换选定的对角线只能增加达到相同总容量所需的对角线数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_diagonals(n):
    sizes = []
    # i + j ranges from 2 to 2n
    for s in range(2, 2 * n + 1):
        cnt = 0
        for i in range(1, n + 1):
            j = s - i
            if 1 <= j <= n:
                cnt += 1
        sizes.append(cnt)
    sizes.sort(reverse=True)
    return sizes

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    
    if k == 0:
        print(0)
        continue

    diag = build_diagonals(n)

    used = 0
    for c in diag:
        if k <= 0:
            break
        k -= c
        used += 1

    print(used)
```代码首先通过扫描可能的和来构造所有对角线长度$i + j$。 对于每个总和，它都会计算有效的网格位置，从而给出该对角线的大小。 按降序对这些大小进行排序后，它贪婪地从$k$，每次减法都代表完全占据该对角线。 

提前退出为$k = 0$避免不必要的计算。 一旦积累了足够的容量，循环就会停止。 

一个微妙的点是，每次测试重新计算对角线仍然足够快，因为$n \le 100$，因此建设成本有限且较小。

这证实了首先获取最大对角线的贪婪选择是必要的，因为提前选择大小为 1 的对角线只会增加总计数。

 ## 边缘情况

 最小的情况是$n = 1, k = 0$。 网格只有一条对角线，但没有芯片意味着没有占用的对角线。 该算法在构建任何与定义匹配的结构之前立即返回 0。 

为了$n = 2, k = 1$，对角线尺寸为$[2,2,1]$。 贪婪循环获取第一个对角线，并在消耗完它后停止，返回 1。单个芯片的任何有效放置都恰好占据一个对角线，因此结果是一致的。 

为了$k = n^2$，每个单元格都已填充，因此必须使用所有对角线。 该算法按降序消耗所有对角线容量并返回$2n-1$，这正是网格中对角线的数量。
