 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，都有不同的花朵类型，每种类型都有花瓣价值和有限的供应。 每朵花都以硬币计算其花瓣价值，而且我们有固定的预算。 

我们想要在两个限制下构建一个花束。 首先，我们不能超出预算。 其次，所有选定的花朵的花瓣数必须位于最多两个连续整数的窗口内，这意味着我们只能混合诸如 5 和 6 之类的值，或者 10、11 甚至可能再次混合 10 之类的值，但决不能将诸如 5 和 7 之类的值混合在一起。 

对于每个测试用例，我们必须最大化在这些限制下我们可以购买的花瓣总数。 

约束足够大，任何解决方案都必须在花类型总数中以大致线性或接近线性的时间处理所有测试用例。 排序是可以接受的，但是任何尝试模拟花朵数量的所有组合或从头开始重复重新计算总和的方法都会失败。 

一个微妙的失败案例来自于忽略频率限制。 天真的贪婪总是首先获取最大的花瓣，而不考虑“最多差一个”约束，这会破坏输入，因为需要稍小的花朵才能有效地“填充窗口”。 

例如，如果我们有花瓣`[10, 9, 1]`如果数量较多且预算适中，则首先采用所有 10 可能会导致需要添加 9 才能实现可行性，但幼稚的策略可能会忽略这种耦合并产生次优或无效的组合。 

当局部最优值窗口由于数量不平衡而不是全局最优时，就会出现另一种边缘情况。 例如，一种非常高价值的花卉可能存在，但数量很少，而稍小的花卉存在大量，并主导预算使用。 

## 方法

 强力解释将尝试连续值窗口的所有有效选择，然后决定每种类型采取多少朵花。 对于每个候选窗口，我们将模拟在窗口内按成本降序取花，直到预算耗尽。 这是正确的，因为任何有效的花束都必须位于某个大小为两个连续整数的窗口内，但尝试窗口内子集的所有组合会导致重复重新计算。 

在最坏的情况下，对于每个测试用例，我们可能会检查所有窗口，并且对于每个窗口迭代所有花卉类型，从而导致每个测试用例的二次行为。 由于元素总数高达 200,000 个，这太慢了。 

关键的观察结果是，有效性仅取决于花瓣值排序顺序的相邻性。 排序后，问题就变成了：选择单个值 x 或一对 (x, x+1)，然后在预算约束下从这两个桶中取出尽可能多的花。 在每个窗口内，最优选择是贪婪的成本，但由于成本等于价值，我们可以预先计算前缀和并使用两个指针在 O(1) 或 O(log n) 中处理每个窗口。 

这减少了扫描排序数组并维护始终遵守差异约束的滑动窗口的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力窗口枚举与模拟 | O(n²) | O(n) | 太慢了 |
 | 排序+两个指针+前缀聚合| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 按花瓣价值对所有花卉类型进行排序。 这可确保任何有效的花束必须来自此排序顺序中的一个值或两个相邻值。 
2. 构建不同花瓣值及其可用总数的数组。 
3. 预先计算成本加权数量的前缀和，以便我们可以快速评估可以从连续段中获取多少。 
4. 在已排序的唯一值上使用两指针滑动窗口。 维护一个窗口，其中最小和最大花瓣值之间的差值最多为 1。 
5. 对于每个有效窗口，计算可能的最佳花束：我们尝试首先从较高的花瓣值中获取尽可能多的花朵（因为成本等于价值，较高的价值对每件商品的总和贡献更多，但也更快地消耗预算），然后填充较低的值。 
6. 跟踪所有有效窗口中可实现的最大总和。 

一个关键的实现细节是我们不需要在每个窗口内模拟逐项选择。 由于每朵花的固定成本等于其价值，因此固定窗口内的最佳策略是确定性的：始终优先考虑价值较高的花。 

### 为什么它有效

 每个有效的花束必须仅使用一个或两个连续的花瓣值。 排序可确保它们在值空间中显示为连续的段。 对于任何此类细分，预算下的最佳选择都是贪婪的，因为组中的所有项目都具有相同的成本结构，并且除了预算消耗之外没有任何交互。 因此，评估所有有效窗口涵盖了所有可行的解决方案，并且在每个窗口内我们计算最佳包装。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        c = list(map(int, input().split()))

        pairs = sorted(zip(a, c))

        vals = []
        cnt = []

        for v, k in pairs:
            if vals and vals[-1] == v:
                cnt[-1] += k
            else:
                vals.append(v)
                cnt.append(k)

        # prefix sums for counts and cost contributions
        # cost contribution inside window is handled greedily

        ans = 0
        j = 0

        for i in range(len(vals)):
            while j < len(vals) and vals[j] <= vals[i] + 1:
                j += 1

            # window is [i, j)
            total = 0
            rem = m

            # we always take from higher value first
            for k in range(j - 1, i - 1, -1):
                take = min(cnt[k], rem // vals[k])
                total += take * vals[k]
                rem -= take * vals[k]

            ans = max(ans, total)

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先聚合相同的花瓣值，因为它们表现为单个资源池。 然后，它在排序值上使用滑动窗口，确保仅考虑有效窗口。 在每个窗口内，它从最大的花瓣值开始向下贪婪地消耗预算，这保证了每花费的硬币的最大贡献。 

唯一的微妙之处是在窗口化之前正确处理聚合； 未能合并相同的值会导致错误的窗口边界和过度计数。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, m = 10
a = [1, 2, 3]
c = [2, 2, 1]
```我们形成分组值：

 | 价值| 计数|
 | ---| ---|
 | 1 | 2 |
 | 2 | 2 |
 | 3 | 1 |

 我们测试窗口：

 窗口[1,2]：

 我们可以先使用 2s，然后使用 1s。 

我们从值 2 中取出 2×2 = 4，剩下 6。 

然后从值 1 中取出 2×1 = 2，剩下 4。 

总计 = 6。 

窗口[2,3]：

 先取3个：1×3=3，剩下7个。 

然后2秒：2×2 = 4，剩余3。 

总计 = 7。 

窗口 [3]：

 只需 3 秒：1×3 = 3。 

最大值为 7。 

这证实了最佳解决方案始终位于单值或双值窗口内。 

### 示例 2

 输入：```
n = 2, m = 10000000000
a = [11, 12]
c = [1, 1]
```窗口[11,12]：

 先拿12个：1×12 = 12，剩余预算巨大，但没有更多库存。 

那么 11：1×11 = 11。 

总数 = 23，但由于每种都只存在一个，所以答案为 23。 

这表明，当数量较小时，贪婪填充仍然同时尊重可用性和预算。

 ## 边缘情况

 一种关键的边缘情况是仅存在一个花瓣值时。 在这种情况下，最优解决方案就是最小值（我们可以承受的总成本，可用数量乘以价值），并且滑动窗口不得尝试错误地扩展。 

另一种情况是值连续但数量高度不平衡。 该算法必须确保在低价值花朵之前获取所有高价值花朵并不会忽略这样一个事实：低价值花朵如果数量丰富，可能会贡献更多总和。 

最后一个边缘情况是预算与总供应量相比非常大。 该算法必须正确限制可用商品总数，而不是试图超出库存限制过度消费。
