 ## 解决方案
 ## 问题理解

 万尼亚想要完全使用三角形数字描述的模式来建造一座金字塔。 第一层包含 1 个立方体。 第二层包含 1 + 2 = 3 个立方体。 第三层包含 1 + 2 + 3 = 6 个立方体。 总体来说，水平`i`需要第一个的总和`i`正整数。 

我们给出了可用立方体的总数，`n`。 我们的任务是确定在用完立方体之前可以构建的完整关卡的最大数量。 

约束非常小。 立方体的数量最多为`10^4`，这意味着即使是简单的模拟也足够快。 可能建造的层数远小于`10^4`因为每个新关卡都需要比前一关更多的立方体。 简单的迭代解决方案很容易满足限制。 

一个常见的错误是忘记每个级别本身都是一个三角形数。 

考虑：```
Input:
4
```第一级使用 1 个立方体，第二级使用 3 个立方体。 它们总共需要 4 个立方体，所以答案是：```
2
```粗心的实现可能会错误地假定级别`i`正是需要`i`立方体并返回 3。 

另一种微妙的情况发生在立方体在完成一个关卡后恰好用完时。```
Input:
10
```这些级别需要 1、3 和 6 个立方体。 

总计为：```
1 + 3 + 6 = 10
```正确答案是：```
3
```如果在计算已完成的关卡之前剩余的立方体变为零，则立即停止的实现将错误地返回 2。 

## 方法

 最直接的想法就是逐层建造金字塔。 对于每个级别，计算该级别需要多少个立方体，从剩余供应中减去它，并在剩余足够的立方体时继续。 

这种暴力模拟已经足够快了。 自从`n ≤ 10000`，层数很少。 即使我们重复计算三角数，工作量也可以忽略不计。 

关键的观察是关卡所需的立方体数量`i`本身是一个三角形数：$$1 + 2 + \cdots + i = \frac{i(i+1)}{2}$$因此，在构建金字塔时，我们只需要跟踪当前级别及其所需的立方体即可。 只要我们能负担得起下一层的费用，我们就会减去它的成本并增加高度。 

因为关卡必须按顺序构建，并且每个关卡都有固定成本，所以从上到下贪婪地获取关卡是唯一可能的有效构建。 当我们无力承担更高一层的费用时，就不再存在更高的金字塔了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(h²) | O(1) | O(1) | 已接受 |
 | 最佳模拟| O(h) | O(1) | O(1) | 已接受 |

 这里`h`是最终的金字塔高度，最多为 30 左右`n ≤ 10000`。 

## 算法演练

 1.读取可用立方体的数量`n`。 
2. 初始化`height = 0`。 
3. 初始化`level = 1`。 
4. 使用以下公式计算当前关卡所需的立方体数量：$$\frac{\text{level}(\text{level}+1)}{2}$$5. 如果剩余足够的立方体，则从`n`， 增加`height`，并进入下一个级别。 

这相当于成功完成了金字塔的又一层。 
6. 重复此操作，直到下一级别需要的立方体数量多于可用的立方体数量。 
7. 输出`height`。 

### 为什么它有效

 在每次迭代中，算法都会保持从 1 到 1 的所有级别的不变量`height`已全部建成，剩余价值`n`等于建造立方体后剩下的立方体。 

下一个可能的动作是唯一确定的：下一个级别要么可以完成，要么不能完成。 如果可以的话，建造它会使高度增加一。 如果不能，任何更高的金字塔也将需要相同的未完成水平，这是不可能的。 因此，算法恰好停止在最大可达到的高度处。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

height = 0
level = 1

while True:
    need = level * (level + 1) // 2

    if n < need:
        break

    n -= need
    height += 1
    level += 1

print(height)
```变量`level`代表我们正在尝试构建的下一层。 表达式```
level * (level + 1) // 2
```计算该级别的三角数。 

每当剩余足够的立方体时，我们就会使用这些立方体并记录另一完成的级别。 当下一个所需层无法完成时，循环恰好终止。 

最常见的差一错误是递增`level`在计算其成本之前。 这样做会跳过大小为 1 的第一层。另一个常见错误是检查剩余立方体是否为零，而不是检查下一层是否负担得起。 精确配合，例如`n = 10`仍必须计算最终完成的级别。

# helper: run solution on input string, return output string
import sys, io

def solve():
    n = int(input())

    height = 0
    level = 1

    while True:
        need = level * (level + 1) // 2

        if n < need:
            break

        n -= need
        height += 1
        level += 1

    print(height)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("1\n") == "1\n", "sample 1"

# custom cases
assert run("4\n") == "2\n", "exactly two levels"
assert run("10\n") == "3\n", "exactly three levels"
assert run("19\n") == "3\n", "just short of fourth level"

 ## 边缘情况

 考虑精确配合的情况：```
Input:
10
```该算法构建需要 1、3 和 6 个立方体的关卡。 完成第三关后，剩余的立方体变为零。 下一关需要 10 个立方体，这是负担不起的，所以答案是 3。这验证了准确完成一个关卡的计数是否正确。 

考虑一个略低于下一个阈值的值：```
Input:
19
```前三个级别消耗：```
1 + 3 + 6 = 10
```还剩下九个立方体。 第四层需要 10 个立方体，因此施工停止，答案为 3。这将检查下一层几乎可以负担得起但又不完全负担得起的边界。 

考虑最小输入：```
Input:
1
```第一关正好需要一个立方体，所以就完成了。 此后不再保留任何立方体，算法输出 1。这确认了最小有效值的正确处理。 

考虑一个更大的精确拟合情况：```
Input:
20
```所需的立方体是：```
1 + 3 + 6 + 10 = 20
```可以构建所有四个级别，并且算法输出 4。这验证了多个连续的精确完成是否已正确处理。
