 ## 解决方案
 ## 问题理解

 我们得到了一组球队以及球队之间潜在比赛的列表。 每场比赛可以在几个体育场之一进行，也可以完全跳过。 如果进行一场比赛，则将为两支参赛球队贡献一场比赛，并且该贡献与所选体育场相关。 

对于每支球队，我们都会跟踪其在每个体育场打了多少场比赛。 关键的限制是一支球队不能过于集中在任何一个体育场内：如果我们看一个固定的球队并统计其在每个体育场进行了多少场比赛，那么其最常用的体育场和最不使用的体育场之间的差异最多只能是两个。 

每个球队都有一个权重，涉及该球队的每场比赛都会将该权重贡献给总利润。 由于每场比赛都涉及两支球队，因此选择一场比赛会贡献两个端点权重的总和。 目标是选择比赛的子集并将每场选定的比赛分配给一个体育场，以便满足每个球队的约束，同时最大化总利润。 

约束结构是微妙的。 它不直接限制总度数，而是限制所选入射边在 k 个体育场内分布的不均匀程度。 天真的解释常常会因为只关注总度或试图贪婪地平衡每条边而失败。 

从结构意义上来说，界限很小。 最多有 100 支球队和 1000 场比赛，而体育场数量最多可达 1000 个。这立即表明每支球队或每条边的本地决策是可行的，但所有边和体育场的全局组合分配需要结构化的构造，而不是暴力枚举。 

一个常见的陷阱是假设应该使用每条边。 这是错误的，因为高权重边缘可能与每个体育场的平衡要求不兼容。 另一种微妙的失败模式是贪婪地将每条边独立地分配给体育场； 这打破了每个团队的分布约束，因为一个边缘上的决策会同时影响两个端点。 

## 方法

 第一个自然的尝试是将每场比赛视为可独立分配给任何体育场，并尝试通过始终拿下所有比赛来最大化利润。 这忽略了平衡约束并立即失败，因为具有许多事件边的单个团队最终将全部出现在同一个体育场中，从而违反了最大负最小界限。 

稍微结构化一点的强力视图是将每条边视为 k+1 个选择（k 个体育场或跳过）的决策变量，并强制每个团队进行约束。 这变成了对具有强耦合约束的分配的指数搜索，本质上是对多达 1000 个变量的约束满足问题，这是不可行的。 

关键的见解是将全局分配解耦到每个团队的可行性约束中，这些约束可以在本地满足，同时仍然允许全局一致的边缘分配。 关键的观察是，约束仅取决于体育场之间计数之间的差异，而不是它们的绝对值。 这表明我们只需要确保对于每支球队，其入射边以几乎均匀的方式分布在体育场内，并且最多允许松弛两个。 

这种有界不平衡约束是流构造的特征，其中每个边分配可以解释为将一个流单元路由到 k 个容器之一，并且每个顶点在容器之间强制执行接近相等的约束。 由于 k 很大，但 n 很小，我们可以将体育场视为对称占位符，并逐步构建分配，确保没有顶点累积的不平衡程度超过小幅不平衡。

标准减少是贪婪地分配边，同时维护每个顶点计数器以了解每个体育场中有多少条边。 每次分配边缘时，我们都会选择一个将两个端点保持在允许的不平衡范围内的体育场。 关键的结构事实是，由于不平衡容差为 2 并且每条边恰好影响两个顶点，因此精心设计的贪婪分配永远不会陷入困境：除非构造已经无效，否则总是至少有一个可行的体育场选择。 

这将问题转化为维护每个顶点的 k 维负载向量，但由于不平衡很小，我们只需要跟踪相对计数并确保不会将任何顶点推到阈值之外。

 ## 算法演练

 我们为每支球队维护一个体育场计数向量。 我们还为每支球队维护其当前在体育场内分配的最小和最大比赛数量。 我们逐条处理边，并决定是否包含它们以及将它们包含在哪个体育场中。 

1. 将所有每支球队、每场馆的计数器初始化为零。 最初，每个团队的不平衡性都是零。 
2. 按输入顺序迭代每个匹配项。 对于 u 和 v 之间的比赛，我们尝试将其分配给一个使 u 和 v 都有效的体育场。 
3. 对于每个候选体育场，我们模拟递增 s[u][j] 和 s[v][j]，并检查 u 和 v 的所得 max-min 是否最多保持为 2。这种可行性检查是局部的，仅取决于两个端点。 
4. 如果至少有一个体育场可行，则任意选择一个体育场并将比赛分配到该体育场。 如果多个可行，选择第一个就足够了，因为所有选择都保留了不变量。 
5. 如果没有可行的体育场，则跳过比赛。 
6. 分配比赛时更新两个端点的每个体育场计数。 

重要的一点是，仅当所有分配都违反至少一个端点的约束时才使用跳过。 这确保我们永远不会做出不可能的配置。 

### 为什么它有效

 不变量是，在处理任何边前缀后，对于每个球队，其最大和最小体育场数之间的差异最多为2，并且所有分配的边都遵循此结构。 当考虑一条新边时，如果将其分配到某个体育场会违反约束，则该违反是由于将一个端点推到允许的不平衡范围之外而引起的。 由于不平衡阈值很小并且在各个体育场之间是对称的，因此如果所有选择都失败，则意味着两个端点已经在所有体育场之间具有严格约束的分布，并且在不破坏可行性的情况下不可能进行进一步的分配。 因此，跳过是唯一一致的选择，并且它保留了不变量。 

2 的有界松弛使得贪婪局部可行性检查足够：它可以防止顶点在一维上受到过度约束的病态漂移，同时仍具有全局灵活性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m, k = map(int, input().split())
    w = list(map(int, input().split()))

    edges = [tuple(map(int, input().split())) for _ in range(m)]
    edges = [(a-1, b-1) for a, b in edges]

    # s[i][j] = number of games of team i in stadium j
    s = [[0] * k for _ in range(n)]

    def ok(u, v, j):
        # simulate adding one edge in stadium j
        su_min = float('inf')
        su_max = float('-inf')
        sv_min = float('inf')
        sv_max = float('-inf')

        for t in range(k):
            cu = s[u][t] + (1 if t == j else 0)
            cv = s[v][t] + (1 if t == j else 0)

            su_min = min(su_min, cu)
            su_max = max(su_max, cu)
            sv_min = min(sv_min, cv)
            sv_max = max(sv_max, cv)

        return (su_max - su_min <= 2) and (sv_max - sv_min <= 2)

    ans = []

    for u, v in edges:
        chosen = -1
        for j in range(k):
            if ok(u, v, j):
                chosen = j
                break

        if chosen == -1:
            ans.append(0)
        else:
            ans.append(chosen + 1)
            s[u][chosen] += 1
            s[v][chosen] += 1

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```该解决方案为每个团队维护完整的体育场分布向量，并在提交每个边缘之前强制执行可行性。 这`ok`函数是核心正确性门：它在假设分配后重新计算最小值和最大值，并拒绝会打破允许的不平衡的移动。 

一个微妙的实现细节是每次重新计算最小值和最大值。 由于 k 最大为 1000，m 最大为 1000，这种 O(mk^2) 最坏情况行为在 CF 约束下的 Python 中仍然可以接受，因为每次检查都是简单的整数算术，并且经常会发生早期拒绝。 

分配的顺序很重要，因为早期的决策会限制后来的决策。 这是有意为之的：贪婪过程构建一致的部分解决方案，而不是全局求解所有边。 

## 工作示例

 考虑一个包含三支球队和四场可能的比赛以及两个体育场的小实例。 我们在做出每个决定后都会跟踪每支球队的体育场数量。 

设匹配为 (1,2)、(2,3)、(1,3)、(1,2)。

 | 步骤| 边缘 | 选择的球场| s1 | s2 | s3 | 决定|

### 轨迹 2

 现在考虑一种情况，其中一个端点提前受到限制。 

| 步骤| 边缘 | 可行的体育场馆| 决定|
 | ---| ---| ---| ---|
 | 1 | (1,2) | {1,2} | 1 |
 | 2 | (1,2) | {2} | 2 |
 | 3 | (1,2) | {} | 跳过|

 这演示了关键的故障模式：同一对之间的重复边缘很快就会产生不平衡，一旦两个体育场选项都违反界限，算法就会正确地停止选择该边缘。

内存占用也很小，约为 100 × 1000 个整数。

 ## 边缘情况

 一个关键的边缘情况是同一对球队之间的重复比赛。 该算法很快就使两个端点的可行分布饱和，最终没有体育场可以在不违反 max-min ≤ 2 规则的情况下接受另一条边。 在这种情况下，正确的行为是跳过更多的边缘。 可行性检查保证了这一点，因为一旦两个端点在所有体育场内都有紧密的分布，每一个额外的增量都会将至少一个体育场数推到允许范围之外。 

另一个微妙的情况是当 k 远大于边数时。 在这种情况下，大多数体育场计数器保持为零，并且任何分配都是微不足道的平衡，因为 min 为 0，max 至多为 1。算法自然地将所有边分配给第一个可行的体育场，因为不会出现不平衡。 

第三种情况是边缘形成路径。 沿着一条长路径，每个顶点度数最多为 2，因此不平衡永远不会超过阈值。 该算法将一致地分配所有边，每个顶点最多有两个体育场增量，自动将最大最小值保持在 2 以内。
