 ## 解决方案
 ## 问题理解

 我们在坐标平面上有一组不同的点。 我们必须将每个点分配给第一个点`k`颜色，每种颜色获得完全相同的点数。 一种颜色的质量由该颜色内最接近的点对决定：最接近的点对相距越远，颜色就越好。 最终分数是所有颜色的这些品质的总和，因此目标是使每个颜色类别在内部良好分离。 

输出不是单个数字答案。 它是原始点的着色。 裁判通过计算每种颜色内部的最小平方距离并对这些值求和来评估着色。 

这些约束使得完全最优的搜索变得不可能。 和`n`最多 1000，可能的分配数量为`k^n`，这远远超出了任何可以探索的范围。 即使考虑所有平衡分区，组合起来也很大。 的价值`k`很小，最多 25 个，这表明我们应该直接构建组而不是搜索它们。 

坐标范围仅为 0 到 1000，因此距离是有界的，并且平方距离适合标准整数类型。 昂贵的部分是将点与许多其他点进行比较。 一个`O(n^3)`对于最大的测试来说，该算法已经执行了大约 10 亿次操作，这在 Python 中风险太大。 一个`O(n^2)`施工是实用的，因为一百万次距离检查是可以管理的。 

在某些情况下，粗心的实施可能会损失很多分数。 如果按坐标排序后将所有点放入连续的颜色中，则靠近的点可能最终会位于同一组中。 例如，四个点形成一个正方形和两种颜色：```
4 2
0 0
1 0
1 1
0 1
```着色例如`AABB`创建两个相邻的对，给出较低的分数。 更好的着色，例如`ABAB`分离相邻点并提高最小距离。 

另一个失败案例是当`n`不是的倍数`k`，但声明保证确实如此。 使用整数除法计算组大小并忽略余数的代码将在问题的不同版本上默默地​​产生无效输出。 

案例`k = 1`也需要呵护。 只有一种颜色，因此每个点都必须收到相同的字母。 任何假设多个组的平衡逻辑都可能意外访问不存在的颜色。 

## 方法

 暴力解决方案将尝试将点的每个有效分区划分为`k`大小组`n / k`，计算每组内最近的对距离，并保留最佳分区。 这总是会找到最佳答案，因为它会检查所有可能的答案。 问题是分区的数量。 即使忽略组内的排序，可能性的数量也是$$\frac{n!}{((n/k)!)^k k!}$$即使只有几十个点，它也会变得巨大。 为了`n = 1000`，这是完全不可能的。 

关键的观察结果是，分数仅取决于相同颜色内的点的接近程度。 如果我们可以创建点排序，其中附近的点不太可能接收相同的颜色，那么我们不需要同时显式优化每种颜色。 

创建此类排序的一种有用方法是最远点遍历。 我们从一个点开始，反复选择距离所有已选择的点最远的点。 这会产生一个序列，其中早期点分布在平面上。 当我们沿着这个序列循环分配颜色时，具有相同颜色的点在整个遍历过程中被分开，而不是聚集在一起。 

蛮力方法之所以有效，是因为它考虑了所有可能的分组，但由于搜索空间太大而失败。 观察到良好分离的排序已经捕获了大部分所需的结构，这让我们可以用确定性的贪婪结构替换不可能的分区搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最远点排序 | O(n²) | O(n²) | 已接受 |

 ## 算法演练

 1. 计算每对点之间的平方距离。 平方距离就足够了，因为只需要比较，并且避免平方根可以保持计算的精确性。 
2. 选择任意起点并建立遍历顺序。 对于每个下一个位置，选择与任何已选择的点的最近距离最大的未使用的点。 

此选择将每个新点放置在距离当前集合尽可能远的位置，从而创建覆盖平面不同区域的序列。 
3. 按此顺序循环为点分配颜色。 第一个点获得颜色`A`，第二个得到颜色`B`，并且之后`k`我们重新开始的第一种颜色`A`。 

自从`n`可以整除`k`，每种颜色都准确无误地出现`n/k`次。 具有相同颜色的点由`k-1`遍历中的其他点，减少了创建紧密对的机会。 
4. 将颜色数字转换回大写字母并输出结果字符串。 

工作原理：该算法保留了遍历的每个前缀都包含为最大化平面覆盖而选择的点的属性。 贪心选择可以防止排序集中在一个区域。 然后循环着色将这些分离良​​好的点分布在所有颜色上。 该构造并不能证明数学上的最佳划分，因为这是一个评分问题，但它产生了有效的着色，并且共享颜色的点之间具有强烈的分离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, k, pts):
    dist = [[0] * n for _ in range(n)]
    for i in range(n):
        xi, yi = pts[i]
        for j in range(i):
            xj, yj = pts[j]
            d = (xi - xj) * (xi - xj) + (yi - yj) * (yi - yj)
            dist[i][j] = d
            dist[j][i] = d

    order = []
    used = [False] * n

    start = 0
    order.append(start)
    used[start] = True

    best = dist[start][:]

    for _ in range(n - 1):
        nxt = -1
        value = -1
        for i in range(n):
            if not used[i] and best[i] > value:
                value = best[i]
                nxt = i

        used[nxt] = True
        order.append(nxt)

        for i in range(n):
            if not used[i] and dist[nxt][i] < best[i]:
                best[i] = dist[nxt][i]

    ans = [''] * n
    for pos, idx in enumerate(order):
        ans[idx] = chr(ord('A') + (pos % k))

    return ''.join(ans)

def main():
    t = int(input())
    out = []
    for case in range(1, t + 1):
        n, k = map(int, input().split())
        pts = [tuple(map(int, input().split())) for _ in range(n)]
        out.append(f"Case #{case}: {solve_case(n, k, pts)}")
    print('\n'.join(out))

if __name__ == "__main__":
    main()
```首先构建距离矩阵，因为贪心遍历会反复询问点之间的距离。 存储这些值可以避免在构造过程中重新计算坐标差异。 

这`best`对于每个未选择的点，数组存储其与所选集合的当前最近距离。 当有新的点进入遍历时，只需要更新这个数组即可。 这与最远点采样的想法相同，其中每个新选择都会提高所选集合的覆盖范围。 

遍历存储原始索引而不是坐标，因此最终的着色可以按照与输入相同的顺序写回。 循环赋值使用`pos % k`，它会自动为每种颜色提供相同数量的点数，因为输入保证了整除性。 

Python 整数不会溢出，因此即使在最大坐标下，平方距离也是安全的。 唯一重要的边界条件是`k = 1`，其中模运算仍然有效，并为每个点分配相同的颜色。

 ## 边缘情况

 当`k = 1`，输入```
3 1
0 0
1 0
2 0
```要求每个点都能收到`A`。 遍历仍然运行，但最终的赋值仅使用第一个字母，因为`pos % 1`始终为零。 该算法不需要特殊处理。 

对于对称正方形：```
4 2
0 0
1 0
1 1
0 1
```坐标排序可能会意外创建`AABB`，将相邻的角放在一起。 最远的遍历首先选择相对的区域，循环分配产生一种着色，其中每种颜色接收分离的点。 

对于大型群体，重要的界限是每种颜色都必须准确接收`n/k`点。 由于分配是基于遍历中的位置并且颜色每次重复`k`元素，最终计数会自动平衡。 仅将颜色分配给遍历顺序而不转换回原始索引之类的错误将会失败，因为输出顺序必须与输入点匹配。
