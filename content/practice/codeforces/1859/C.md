 ## 解决方案
 ## 问题理解

 我们得到了以下数字的排列`1`到`n`。 对于排列`p`， 定义$$\text{cost}(p)=\sum_{i=1}^{n} p_i \cdot i-\max_{i=1}^{n}(p_i\cdot i).$$任务是在所有长度排列中找到该表达式的最大可能值`n`。 

第一项奖励将大量数字放在大指数上，因为它是加权总和。 第二项减去单个最大贡献。 这两个目标是相互竞争的。 我们希望总加权和很大，但我们也希望最大的单个产品不要变得太占主导地位。 

约束条件`n ≤ 250`对于排列问题来说异常小。 对所有排列进行强力搜索是不可能的，因为有`n!`排列。 即使是为了`n = 10`，已经有超过三百万种排列。 另一方面，较小的值`n`建议`O(n²)`甚至`O(n³)`每个测试用例的解决方案是完全可以接受的。 

一个微妙的点是，单独最大化加权和是很容易的。 通过重排不等式，得到最大值$$\sum p_i i$$通过排序排列得到`[1,2,...,n]`。 然而，这种安排也创造了最大可能的产品`n²`，然后将其减去。 最佳答案来自于平衡这两种影响。 

考虑`n = 4`。 

恒等排列给出$$1\cdot1+2\cdot2+3\cdot3+4\cdot4=30$$最大乘积为`16`，所以成本是`14`。 

最优排列是`[1,2,4,3]`，其成本为`17`。 

仅最大化加权和的解决方案将无法达到最佳值。 

另一个容易犯的错误是假设最大的乘积必须出现在位置`n`。 例如，在`[1,4,2,3]`，最大的乘积是`4·2 = 8`，不一定是最后一个位置。 任何正确的解决方案都必须明确计算最大乘积。 

## 方法

 最直接的想法就是枚举每一个排列，计算其加权和和最大乘积，然后保留最佳答案。 

这是可行的，因为成本的定义很简单。 对于固定排列，计算表达式需要`O(n)`时间。 

问题是排列的数量。 最坏的情况需要检查`250!`排列，这个数太大了，完全不可行。 

关键的观察结果是，官方解决方案依赖于特殊结构排列的非常小的搜索空间。 

假设我们从递增排列开始$$[1,2,3,\dots,n].$$这种安排使加权和最大化。 为了减少最大乘积的惩罚，我们可以将一些大值从最大索引中移开。 

一个值得注意的事实是，总是可以通过选择分割位置来获得最佳排列`k`和建造$$[1,2,\dots,k-1,n,n-1,\dots,k].$$前缀保持递增，而后缀则相反。 

自从`n ≤ 250`，我们可以简单地尝试每一个可能的分割位置。 对于每个候选排列，我们直接计算其成本并取最大值。 

只有`n`候选排列，每个排列都需要`O(n)`工作来评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有排列 | O(n·n！) | O(n) | 太慢了 |
 | 枚举分割位置 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，将答案初始化为零。 
2. 对于每个分割位置`k`从`1`到`n`，构造排列：$$[1,2,\dots,k-1,n,n-1,\dots,k].$$3. 计算加权和$$\sum p_i\cdot i.$$4. 计算所有产品中的最大值`p_i · i`。 
5. 这种排列的成本是加权和减去最大乘积。 
6. 用迄今为止看到的最大成本更新答案。 
7.检查完所有分割位置后，打印答案。 

### 为什么它有效

 增加的排列使加权和最大化。 任何最佳解决方案都必须接近该安排，因为失去太多加权和的代价是昂贵的。 

唯一重要的自由是决定哪些大值应该从最大指数中移开以减少最大乘积。 反转后缀恰好可以实现这种权衡。 对于这个问题的编辑观察是，每个最优解都属于后缀反转排列家族。 

由于我们明确评估该家庭的每个成员，因此找到的最大成本才是真正的最佳成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans_list = []

    for _ in range(t):
        n = int(input())
        best = 0

        for k in range(1, n + 1):
            p = list(range(1, k))
            p.extend(range(n, k - 1, -1))

            total = 0
            mx = 0

            for i, x in enumerate(p, start=1):
                prod = i * x
                total += prod
                if prod > mx:
                    mx = prod

            best = max(best, total - mx)

        ans_list.append(str(best))

    sys.stdout.write("\n".join(ans_list))

solve()
```外循环迭代测试用例。 对于每个分割位置`k`，我们生成上述候选排列。 

成本的计算是在单次扫描中完成的。 我们累积加权和并同时跟踪最大的乘积。 

报告所有候选人的最大答案。 

该实现使用从 1 开始的索引`enumerate(..., start=1)`因为该公式使用从 1 开始编号的位置。 

在 Python 中，整数溢出不是问题。 最大的加权和约为$$250 \cdot 250^2 = 15{,}625{,}000,$$与 Python 的整数限制相比，这是很小的。
