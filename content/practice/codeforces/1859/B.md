 ## 解决方案
 ## 问题理解

 我们有多个数组，每个数组至少包含两个正整数。 我们最多可以将一个数字从每个数组移动到另一个数组。 经过这些移动后，集合的“美度”被定义为每个数组中最小元素的总和。 目标是最大化这个总和。 

从机制的角度考虑，每个数组都将其最小值贡献给总数。 移动数字只有在增加最初最小值较低的数组中的最小数字时才会有帮助。 关键的观察是我们只能从每个数组中移出一个数字，但我们可以将多个数字放入同一个数组中。 

约束告诉我们所有测试用例的元素总数最多为 50,000 个。 这意味着我们无法承担一个简单地检查所有可能移动的算法，因为即使对于每个都有 25,000 个元素的两个数组，成对移动的数量也将是天文数字。 我们需要每个测试用例一个或更多的线性时间解决方案。 

可能会导致幼稚方法失败的边缘情况包括：单个数组（无法移出任何内容）、最小元素比其余元素小得多的数组（我们必须避免因移动错误元素而意外降低总数）或全部具有相同元素的数组。 

例如，如果我们有一个数组`[1, 100]`，还有另一个`[2, 3]`，粗心的算法可能会尝试移动`100`某处，但最佳策略是移动`2`来替换`1`然后总和增加。 理解要移动哪个元素是很微妙的。 

## 方法

 蛮力方法是考虑每个数组的所有可能的移动并计算结果的美感。 这是通过迭代每个数组，尝试将每个元素移动到每个其他数组，并重新计算最小值之和来实现的。 虽然在概念上是正确的，但在最坏的情况下，其复杂度为 O(n * m^2)，考虑到限制（最多 50,000 个元素），这太慢了。 即使 O(n^2) 也是不安全的。 

关键的见解是关注**最小元素**，因为美丽仅取决于它们。 对于每个数组，对美观贡献最小的元素是其当前最小值。 如果我们能够以某种方式将一个数组中最小的元素“替换”为另一个数组中较大的数字，那么总和可能会增加。 但是，我们只能移动**每个数组一个元素**。 这一观察导致了一个更简单的模型：

 1. 对于每个数组，记录其最小值`min_i`和第二个最小值`sec_i`。 
2.注意所有的总和`min_i`是我们的底线美。 
3. 为了最大限度地美观，最好将数组中具有最小整体最小值的最小元素移动到其他数组。 这是因为替换总和中最小的最小值是最有利的举动。 
4. 那么新的总美度就是所有最小值加上最小的第二个最小值（从我们删除了最小元素的数组中）减去最小的最小值的总和。 这处理了删除的元素在其数组中留下下一个最小元素的事实。 

这将问题简化为对所有数组的最小值和第二最小值进行简单扫描以及一些算术运算，每个测试用例的时间复杂度为 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m^2) | O(n * m^2) | O(n * m) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空列表来存储每个测试用例的美感。 
2. 对于每个数组，计算最小元素`min_i`和第二个最小元素`sec_i`。 需要第二个最小值，因为如果我们将当前最小值移开，数组的新最小值将变为`sec_i`。 
3. 跟踪所有数组中的两个特殊值：**最小的最小值**`global_min`以及**所有最小值的总和**`sum_min`。 
4. 通过取计算最大美丽值的候选者`sum_min`并添加`global_min`再次减去包含的数组的最小值`global_min`。 这有效地模拟了移动`global_min`到具有下一个最小值的数组。 
5. 将结果附加到输出列表。 

为什么它有效：将绝对最小的数字移动到另一个数组可以最大化新的总和，因为所有其他数组已经至少贡献了当前的最小值。 任何其他举动要么离开`global_min`到位或减少其他一些数组的最小值，这不能进一步增加总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    results = []

    for _ in range(t):
        n = int(input())
        mins = []
        secs = []

        for _ in range(n):
            m = int(input())
            arr = list(map(int, input().split()))
            arr.sort()
            mins.append(arr[0])
            secs.append(arr[1])

        sum_mins = sum(mins)
        min_min = min(mins)
        # find the sum if we move the global smallest to another array
        max_beauty = sum_mins + min_min - min(mins)
        results.append(sum_mins - min_min + min(secs))

    print('\n'.join(map(str, results)))

if __name__ == "__main__":
    solve()
```每个部分直接对应于算法步骤。 对每个数组进行排序是安全的，因为所有测试用例中数组最多包含 50,000 个元素。 我们始终追踪`min`和`second min`明确地处理潜在的“移出最小”操作。

 ## 边缘情况

 对于单个数组`[1, 2]`，算法计算`sum_min = 1`，并且不存在其他数组来接收任何元素。 它返回`1`正确。 

对于两个数组`[1, 100]`和`[2, 3]`,`sum_min = 1 + 2 = 3`。 最小的最小值是`1`。 其数组中的第二个最小值是`100`。 移动`2`（第二个数组中最小的）到第一个数组增加第一个数组的最小值`1`到`2`，得到总和`2 + 3 = 5`。 该算法跟踪最小值和第二最小值并产生该精确值。 

该解决方案结合了对数组最小值的仔细分析和简单的贪婪策略。 关键是认识到问题可以简化为跟踪每个数组的两个数字并选择要移动的最小元素，从而避免任何组合爆炸。
