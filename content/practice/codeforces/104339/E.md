 ## 解决方案
 ## 问题理解

 我们得到了两种十进制形式的实数文本表示，我们需要决定哪一个更大，或者它们是否相等。 问题在于格式非常宽松。 数字可以有一个可选的整数部分、一个可选的小数部分或两者都有，但绝不能同时缺失。 如果没有小数部分，则可能会缺少小数点，并且小数点的两侧也可能会丢失，这实际上表现为零。 前导零和尾随零是不相关的，并且可以以任意数量出现。 

从概念上讲，每个输入字符串都以 10 为基数编码一个非负实数，但不是规范形式。 该任务纯粹是数值的比较，而不是字符串顺序。 

约束主要取决于每个输入字符串的长度，最多可达 100,000 个字符。 这立即排除了任何通过将数字转换为浮点类型或 Python 小数来标准化数字的策略，因为精度和性能都会失败。 即使是大整数算术也必须小心处理，因为小数部分可以与整数部分一样大。 

关键的困难在于，表示被分成两个独立的部分，整数和小数，并且必须在归一化后按字典顺序比较两者，而无需构造巨大的中间数。 

一些边缘情况会导致简单的解决方案悄无声息地失败。 

第一个示例是整数部分中不同的前导零。 考虑`00012.3`相对`12.3`。 由于字典顺序，字符串比较会错误地将第一个视为较小的，但在数字上它们的整数大小相等。 

第二个例子是缺少整数部分。 输入类似`.15`代表`0.15`，并且必须与类似的东西正确比较`0.149999`。 

第三个例子是小数比较，其中一个数字具有较长的小数部分。 例如，`1.2300`和`1.23`即使原始字符串不同，它们也是相等的。 直接比较小数字符串的天真比较会错误地认为第一个字符串由于额外的字符而较大。 

这些问题表明我们必须规范结构，而不是计算数值。 

## 方法

 一种强力方法是将每个字符串解析为高精度十进制对象，或者通过将整个数字转换为按最大分数长度的 10 次方缩放的单个整数来模拟任意精度算术。 对于每个数字，我们需要确定小数长度，然后相应地填充整数部分，连接并作为大整数进行比较。 

原则上这是正确的，因为两个数字都被转换为可比较的整数表示。 然而，成本成为问题。 如果两个数字最多有 100,000 位，并且我们将它们连接成一个大整数字符串，则比较本身的时间复杂度为 O(n)，并且转换和标准化也需要 O(n)。 在实践中，这仍然是边界，但只有在仔细实现的情况下才能在 Python 中接受。 然而，重复的分配和填充使其变得脆弱。 

更好的观察是我们永远不需要构造一个组合数。 我们只需要先比较整数部分，只有当它们相等时才比较小数部分。 在每个部分中，标准化纯粹是忽略前导零或尾随零。 

因此，问题简化为受控规范化规则下的字符串比较：去除整数部分中的前导零，去除小数部分中的尾随零，然后比较长度和字典顺序。 

这减少了从构造数字到比较两个干净的字符串对的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（大整数归一化）| 每个数字的 O(n)，重常量 | O(n) | 有风险|
 | 最优（分割和规范化部分）| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个输入字符串围绕点拆分为整数部分和小数部分。 如果不存在点，则将小数部分视为空。 如果字符串以点开头，则将整数部分视为空。 
2. 通过删除前导零来标准化整数部分。 如果结果为空，则将其替换为`"0"`。 这确保了像这样的值`"000"`和`""`两者都代表零。 
3. 通过删除尾随零来标准化小数部分。 如果它变空，则将其视为`""`。 我们不强迫它`"0"`因为分数相等取决于长度和内容。 
4. 先比较整数部分。 如果一个数字多于另一个数字，则数字越长代表数字越大。 如果它们在相同长度下的字典顺序不同，则决定结果。 
5. 如果整数部分相等，则比较小数部分。 首先比较小数字符串的长度。 更长的小数部分意味着超越相等的更高的精度，所以`1.2300`变成`1.23`修剪后，它们变得相等。 
6. 如果长度相等，则按字典顺序逐位比较。 
7. 如果两个部分完全匹配，则数字相等。 

### 为什么它有效

 该问题中的每个实数都由其整数大小和去除冗余零后的小数扩展唯一确定。 规范化保证每个值映射到规范形式，其中整数比较反映大小，而小数比较仅在整数部分匹配时反映细粒度排序。 由于两个部分都是按显着性递减的顺序进行比较，因此整数优势总是首先决定，而小数比较仅解决平局问题。 此结构保留了与实数的排序等价性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def split_num(s: str):
    if '.' in s:
        a, b = s.split('.')
    else:
        a, b = s, ""

    a = a.lstrip('0')
    if a == "":
        a = "0"

    b = b.rstrip('0')
    return a, b

def cmp(a1, b1, a2, b2):
    if len(a1) != len(a2):
        return 1 if len(a1) > len(a2) else -1
    if a1 != a2:
        return 1 if a1 > a2 else -1

    if b1 == b2:
        return 0

    if len(b1) != len(b2):
        return 1 if len(b1) > len(b2) else -1

    if b1 > b2:
        return 1
    return -1

s1 = input().strip()
s2 = input().strip()

a1, b1 = split_num(s1)
a2, b2 = split_num(s2)

print(cmp(a1, b1, a2, b2))
```拆分函数负责将每个数字转换为规范表示。 整数部分去掉了前导零，确保了正确的大小比较。 小数部分去掉尾随零，确保等效的十进制扩展不会发散。 

比较函数小心地避免将字符串转换为数字类型。 首先使用长度来比较整数部分，这是最重要的决定因素。 只有当长度匹配时，我们才会回退到字典顺序比较。 

分数比较仅用作决胜局。 首先使用长度比较是因为`"123"`与`"1230"`否则，如果在没有标准化的情况下按字典顺序处理，则比较会不正确。

 ## 边缘情况

 一种微妙的情况是两个整数部分在去除零后都崩溃为空。 例如，`0000.5`和`.5`两者代表相同的整数值`0`。 规范化步骤将空整数字符串强制转换为`"0"`，因此在小数比较之前两者变得相同。 

另一种情况是修剪后小数部分变空。 例如，`1.2300`变成整数`1`和分数`23`， 尽管`1.23`变得相同。 由于小数比较仅在两个都为空或都匹配时才将空字符串视为相等，因此保留了相等性。 

最后的边缘情况是长度相等但词典值不同的大整数部分，例如`999`和`100`。 尽管按字典顺序`"999" > "100"`，长度比较是相同的，因此字典比较可以正确解析排序，而无需进行数字转换。
