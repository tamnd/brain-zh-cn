 ## 解决方案
 ## 问题理解

 我们从一副牌开始$n$不同的卡片。 固定参数$m$控制重复操作，无论卡牌值如何，该操作在牌组上始终以相同的方式运行。 

每个操作分两个阶段进行。 首先，我们将牌组分配到$m$从上到下循环堆积。 然后，我们将这些牌堆重新组合成一副新牌，但我们不是将第 1 堆牌堆放在第 2 堆牌上，以此类推，而是重新排序牌堆，以便将包含观众牌的牌堆放在顶部，然后按循环顺序放置下一堆，最后环绕。 

重要的隐藏结构是，每张牌的位置都在这个过程中确定性地演变。 观众选择的牌对于转换的机制并不重要，但它用于决定重组牌堆时的旋转。 

我们被要求提供一个值$k$，此操作的最小重复次数，使得无论牌组最初如何排列并且无论选择哪张牌，之后$k$重复选择的卡牌保证位于牌堆的顶部。 

问题是要求排列上确定性变换的最坏情况收敛时间，其中变换取决于$n$和$m$，但一旦我们对所有起始状态和所选卡片采取最坏情况，就不再考虑具体的排列。 

约束条件$n, m \le 10^9$立即排除对卡片或状态的任何模拟。 我们甚至无法显式地构建位置上的排列图。 该解决方案必须仅取决于转换的结构属性。 

一个天真的错误是假设该过程取决于纸牌的值或模拟随机洗牌。 例如，在像这样的小情况下$n=6, m=2$，人们可能会错误地跟踪实际的桩并认为收敛取决于初始排序。 然而，操作完全基于头寸，因此只有指数重要。 

另一个微妙的问题是假设答案取决于所选的卡。 旋转步骤消除了最坏情况保证中的这种依赖性：我们需要一个$k$这适用于所有选择，因此系统的行为就像是定向过程与位置的最坏情况收敛。 

## 方法

 关键是将这个技巧重新解释为位置的确定性变换$1 \dots n$。 

在一次操作中，我们首先将牌组分成$m$交错序列：

 - 第 1 堆包含位置$1, m+1, 2m+1, \dots$- 第 2 堆包含位置$2, m+2, 2m+2, \dots$- 等等

 然后我们对牌堆重新排序，使包含所选牌的牌堆成为第一堆，并循环旋转牌堆顺序。 

这意味着转换不依赖于卡身份，而仅依赖于哪个残基类模$m$所选卡位于，并结合循环移位。 

关键的观察是，我们通过将牌组的结构压缩成由模引起的块来反复减少所选牌位置的不确定性。$m$。 每个操作有效地将一个位置映射到一个由其商和余数确定的新位置$m$，并且旋转仅影响哪个块被认为是“第一个”，而不影响内部结构。 

如果我们跟踪固定卡的位置，它的索引会在一个函数下演变，该函数的行为大致类似于重复应用：$$x \mapsto \left\lceil \frac{x}{m} \right\rceil$$最多不影响渐近深度的循环移位。 

当位置变为 1 时，该过程结束，最坏情况下的步数对应于我们必须重复压缩 base 中的索引的次数$m$直到它塌陷成一个单元。 这正是表示中的位数$n$在基地$m$，或等效地最小的$k$这样：$$m^k \ge n$$所以答案是：$$k = \lceil \log_m n \rceil$$出现这种情况是因为每次操作都会将位置空间的有效“规模”减少一个因子$m$，并且我们需要足够的减少来将任何起始位置缩小到第一个槽。

 ## 算法演练

 1. 阅读$n$和$m$。 该过程仅取决于这些参数，因为最坏情况收敛忽略初始排列。 
2. 将重复的堆形成解释为重复地将索引分组为大小的块$m$。 每个分组都会减少职位的有效范围。 
3. 认识到在一次操作之后，任何卡片距顶部的最大可能“距离”大致减少为$n$到$\lceil n/m \rceil$。 这是驱动收敛的压缩步骤。 
4. 重复这个推理：之后$t$操作时，最坏情况下的剩余深度约为$\lceil n / m^t \rceil$。 
5.我们想要最小的$t$使得该值变为 1，意味着每个可能的起始位置都已折叠到顶部。 
6. 解决不等式$m^t \ge n$。 答案是最小的$t$，这是基础的天花板 -$m$的对数$n$。 

### 为什么它有效

 该过程定义了位置的确定性划分$m$交织子序列，然后对这些子序列进行循环重新排序。 对于收敛来说，唯一重要的是一个位置被“分散”了多少次$m$在它成为其组链中的第一个元素之前进行分组。 每个操作都会将有效索引规模减少一个因子$m$，所以之后$t$步骤任何初始位置必须位于第一个块内一次$m^t$超过$n$。 这保证了所选卡片被强制进入顶部位置，无论初始排序或堆旋转如何。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

# compute ceil(log_m(n)) without floating point
k = 0
cur = 1

while cur < n:
    cur *= m
    k += 1

print(k)
```该代码避免了浮点对数，对于高达以下的大值来说，浮点对数可能不稳定$10^9$。 相反，它会反复倍增，直到达到或超过$n$，直接反映条件$m^k \ge n$。 

变量`cur`代表每次操作后可达到的“压缩能力”的增长。 每次循环迭代都模拟桩重组效应在规模缩小方面的一种应用。 

循环在约束下是安全的，因为$m \ge 2$，所以迭代次数最多为$\log_2(10^9)$，大约是 30。

def run(inp: str) -> str:

 ## 边缘情况

 一种边缘情况是当$n = m$。 在这种情况下，一个操作已经将任何位置减少为单个堆结构，该结构在重新分配后立即崩溃。 该算法处理它是因为循环开始于`cur = 1`并乘以一次达到$m = n$，产生输出 1。 

另一个边缘情况是当$m = 2$和$n$非常大。 这会产生最大迭代次数，但仍保持在大约 30 步以内。 循环结构确保不会出现溢出或性能问题，因为乘法保持在 Python 整数范围内。 

最后的边缘情况是$n = 1$，但这被约束排除了$n \ge 2$，因此无需特殊处理。
