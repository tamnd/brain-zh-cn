 ## 解决方案
 ## 问题理解

 我们给定了四个正整数权重，任务是决定是否可以将它们全部放在天平秤上，以使系统完美平衡。 每个重量都可以放置在左盘或右盘上，并且每个重量必须仅使用一次。 

核心要求是分配所有四个壶铃后，左盘的总重量必须等于右盘的总重量。 除了使用所有物品外，每一侧的物品数量没有限制。 

输入大小非常小，因为总是有四个数字。 这消除了渐近优化的任何需要。 即使对所有分配进行完整枚举也是可行的，因为每个壶铃都有两个选择，左或右，仅给出 2⁴ = 16 种配置。 

此类问题中的一个天真的错误是假设对相邻值进行排序或配对就足够了。 但这是失败的，因为平衡取决于组合，而不是顺序。 例如，对于权重 1 2 3 4，像 (1 + 4) 与 (2 + 3) 这样的贪婪配对有效，但不能保证排序配对始终是唯一有意义的结构。 唯一可靠的标准是将该集合分为两组的任何划分是否具有相等的总和。 

另一个微妙的陷阱是假设总和必须能被 2 整除并立即得出可行性结论。 这个条件是必要的，但不是充分的。 例如，1 1 1 3 的总和为 6，可被 2 整除，但没有子集和为 3。 

## 方法

 蛮力的想法是尝试各种方法将每个壶铃分配到左侧或右侧。 对于每个分配，我们计算两侧之间的差异并检查它是否变为零。 由于四个项目中的每一个都独立选择一边，因此有 2⁴ = 16 种可能性。 每个配置都需要不断地进行评估，因此速度非常快。 

虽然这对于 n = 4 来说已经是最优的，但它的概括性很差。 如果有 n 个项目，蛮力方法将增长为 2ⁿ，一旦 n 在典型约束下超过 25 到 30，这就变得不可行。 这个问题的关键观察是 n 是固定的且很小，因此我们不需要寻找枚举或子集推理之外的渐近改进。 

我们还可以将问题解释为将数组划分为两个总和相等的子集。 这是经典的子集和分区检查。 通过四个元素，我们可以简单地检查大小为 0 到 4 的所有子集，并验证是否有任何子集的总和等于总数的一半。

 ## 算法演练

 我们将问题简化为检查四个权重是否可以分为总和相等的两组。 

1. 计算所有四个权重的总和。 如果这个和是奇数，立即停止并输出NO。 奇数总数不能分成两个相等的整数。 
2. 目标为总金额的一半。 我们现在需要确定这四个数字的某个子集的总和是否恰好等于该目标。 
3. 迭代四个索引的所有子集。 每个子集代表选择哪些权重进入左盘。 剩余的重量隐式地转到右侧平底锅。 
4. 对于每个子集，计算所选元素的总和。 如果它等于目标，我们可以立即断定存在有效分区。 
5. 检查所有可能性后，如果没有子集与目标匹配，则输出 NO。 

迭代子集背后的原因是平衡的每个有效排列都唯一对应于为一侧选择子集。 此表示中不存在重复或缺失的配置。 

### 为什么它有效

秤的任何有效配置都对应于将四个权重划分为两个不相交的组。 每个这样的分区都由索引子集恰好表示一次。 因此，检查所有子集会耗尽所有可能的物理布置。 由于我们直接测试每个分区的总和相等，因此成功的匹配保证了有效的平衡放置，而所有子集的失败保证不存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    p = list(map(int, input().split()))
    total = sum(p)

    if total % 2:
        print("NO")
        return

    target = total // 2
    n = 4

    for mask in range(1 << n):
        s = 0
        for i in range(n):
            if mask & (1 << i):
                s += p[i]
        if s == target:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```该实现首先读取四个整数并计算它们的总数。 当总和为奇数时，奇偶校验可以避免不必要的枚举。 

位掩码循环枚举四个权重的所有子集。 每一位代表是否在左盘上放置了重量。 内循环累加子集和。 如果任何子集与目标总和匹配，我们立即输出 YES。 

尽早返回很重要，因为我们只需要一个有效的分区。 如果 16 个子集都不起作用，则最终答案是否定的。

这证明了奇偶校验的有用性，它在搜索之前过滤不可能的情况。

 ## 边缘情况

 一种边缘情况是所有数字都相同，例如`10 10 10 10`。 该算法枚举子集并快速找到有效的分割，例如每侧两个元素。 子集枚举保证了正确性，因为许多掩码将产生相同的和结构，但至少有一个恰好达到一半。 

另一种情况是当总和为奇数时，例如`7 3 5 6`。 奇偶校验后算法立即终止。 这是安全的，因为当总数为奇数时，不存在将整数划分为两个相等的和，因此跳过子集搜索不会错过任何有效配置。 

一个更微妙的情况是`1 1 1 3`。 即使总数是偶数，子集枚举也无法找到任何总和为 3 的组。该算法在用尽所有 16 个掩码后正确拒绝，确认仅奇偶校验是不够的，即使在很小的实例中，也需要完整的子集检查。
