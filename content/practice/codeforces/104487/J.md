 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，都有一个任务列表，每个任务都有固定的持续时间（以分钟为单位）。 从这些任务中，我们必须恰好选择其中 k 个。 一旦选择，它们的持续时间就会加起来，我们的目标是使这个总数尽可能大。 

因此，问题简化为从数组中选择 k 个数字，使它们的总和最大化，然后我们为每个测试用例输出最大可能的总和。 

约束很小：n 最多为 100，值最多为 1000，并且最多有 100 个测试用例。 这立即排除了任何繁重的事情，例如以直接方式对大小为 k 的子集进行组合搜索，因为这将涉及从 n 中选择大小为 k 的组合，并且随着 n 选择 k 而增长。 即使 n = 100，这个数字在 k 的中间范围内也会变得天文数字，使得暴力破解变得不可行。 

一个简单但重要的观察是，顺序并不重要，重要的是选择哪些元素。 这表明该结构纯粹是为了挑选最大的贡献者。 

值得考虑的边缘情况是所有值都相等的情况，其中 k 等于 n，k 等于 1。例如，如果所有任务都相同，则任何选择都会给出相同的答案，因此输出应该只是该值的 k 倍。 如果 k = n，我们必须拿走一切。 如果k = 1，我们必须取最大的单个元素。 

一个幼稚的错误是尝试模拟所有选择或使用贪婪策略按输入顺序选择前 k 个元素。 例如：

 输入：

 n = 5，k = 2

 a = [1, 100, 2, 3, 4]

 取前两个元素得出 1 + 100 = 101，但正确答案是 100 + 4 = 104。这表明数组中的位置无关紧要。 

## 方法

 蛮力的想法是尝试大小为 k 的每个子集，计算其总和，并取最大值。 这在概念上很简单：生成组合，对每个组合求和，然后跟踪最佳结果。 正确性是显而易见的，因为考虑了所有可能的有效选择。 

问题在于组合的数量。 从 n 中选择 k 个元素的方法数为 n 选择 k，在 k = n/2 附近最大化。 对于 n = 100，该值约为 10^29，这远远超出了时间限制内任何可行的计算。 即使每个子集总和花费恒定时间，单独枚举也是不可能的。 

关键的见解是，由于我们只关心最大化总和，因此当有较大值可用时，我们永远不会从选择较小值中受益。 这意味着最佳策略必须包括选择数组中的 k 个最大元素。 一旦数组排序完毕，答案就是最后 k 个元素的总和。 

这减少了从组合选择到排序和切片的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（所有 k 子集）| O(2^n) 或 O(n 选择 k) | O(k) 递归堆栈 | 太慢了 |
 | 排序并选取前 k | O(n log n) | O(n log n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例T的数量，因为每个用例都是独立的，必须单独处理。 
2. 对于每个测试用例，读取 n 和 k，它们定义存在多少个任务以及允许我们选择多少个。 
3. 读取任务持续时间数组。 
4. 按非降序对数组进行排序。 排序是必要的，因为它以一种使选择变得微不足道的方式对最小值和最大值进行分组。 
5. 取出排序数组的最后 k 个元素，即最大的 k 值。 
6. 计算它们的和并输出。 

每个步骤的结构都是为了消除不确定性。 排序确保我们可以全局推理哪些元素最大，而无需重复搜索或比较子集。 

### 为什么它有效

k 个元素的任何有效选择的总和等于这些元素的总和。 如果我们考虑用更大的未选定元素替换任何选定元素，则总和会严格增加。 重复此替换参数表明任何最佳选择都必须完全由数组中的 k 个最大元素组成。 由于排序显式地按大小对元素进行排序，因此排序数组的前 k 后缀正是该集合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        out.append(str(sum(a[-k:])))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现直接遵循算法。 排序是根据测试用例进行的，因为每个数组都是独立的。 切片`a[-k:]`提取排序后最大的k个元素。 将它们相加得出最终结果。 

一个微妙的实现细节是确保我们不会意外地按降序排序然后采取错误的切片。 这两种方法都有效，但错误地混合顺序和索引是导致差一错误的常见原因。 使用升序排序和负切片是最稳定的模式。

 ## 边缘情况

 当所有值都相同时，排序不会改变任何内容，并且选择任何 k 个元素都会产生相同的总和。 用于输入`[10, 10, 10, 10, 10]`当 k = 3 时，排序给出相同的数组，最后三个元素之和为 30，这与任何有效选择匹配。 

当 k 等于 n 时，算法采用整个排序数组。 为了`[1, 2, 3, 4]`，排序后的数组顺序不变，所有元素相加得到 10。因为切片覆盖了整个范围，所以不存在丢失元素或误选的可能性。 

当k等于1时，算法简化为选择最大元素。 为了`[9, 1, 8, 2, 7]`，排序给出`[1, 2, 7, 8, 9]`，最后一个元素的结果是 9。这符合最大化单个选择的定义。
