 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，有 n 个学生。 每个学生都有一个整数值 ai，该值定义了他们与其他学生的兼容性：两个学生 x 和 y 之间的兼容性是他们值的最大公约数 gcd(ax, ay)。 

我们需要构建一个恰好包含 n − 1 个连接的网络，以便所有学生都连接起来，形成一棵树。 每个连接贡献的权重等于两个端点的 gcd。 在选择树的所有可能方法中，我们希望选择总重量最大的一种。 

因此，问题本质上是要求完整图上的最大生成树，其中边权重隐式定义为 gcd(ai, aj)。 输入约束允许跨测试用例的总节点数最多为 5 · 10^5，值最多为 10^6。 

该规模排除了任何显式考虑所有节点对的方法。 一个完整的图大约有 n^2 条边，即使 n = 10^5 也是不可能的。 即使存储所有成对的 gcd 值也是不可行的。 

一个更微妙的困难是边权重不是任意的：它们仅取决于 gcd 结构。 这意味着许多边共享相同的权重，并且可分结构是唯一重要的事情。 

一个天真的错误是尝试按 gcd 值对所有对进行排序或在所有边上运行 Kruskal。 对于 n = 5000，即使这样也已经产生了数千万条边，这将立即进行 TLE 或 MLE。 

另一个失败案例来自于贪婪的局部选择。 例如，如果我们总是将每个节点连接到最近的“高 gcd 伙伴”，我们可能会形成循环或错过更好的全局结构，其中稍小的 gcd 边缘稍后会解锁多个高价值连接。 最佳结构取决于除数的全局分组，而不是成对的最佳选择。 

## 方法

 暴力方法构建每条边 (i, j)，计算 gcd(ai, aj)，对边进行排序，并运行最大生成树算法。 这在概念上是正确的，因为一旦边缘完全已知，MST 理论就能保证正确性。 然而，生成 O(n^2) 条边已经太大了。 当 n = 10^5 时，这大约是 10^10 次运算，这是完全不可行的。 

关键的观察结果是 gcd 边是由除数构成的。 如果两个数共享一个大的 gcd d，则这两个数都是 d 的倍数。 这意味着权重 d 的边仅存在于值为 d 倍数的节点之间。 我们可以用除数桶来思考，而不是用对的方式来思考。 

我们从大到小处理可能的 gcd 值。 对于固定值 d，我们收集 ai 可被 d 整除的所有节点。 这些节点可以使用权重至少为 d 的边进行连接。 如果我们按降序处理 d，我们确保首先考虑权重较高的边，这与最大生成树构造的贪婪本质相匹配。 

为了有效地处理连接性，我们使用不相交的并集结构。 对于每个 d，我们获取其存储桶中的所有节点并尝试合并它们。 每次成功的合并都会对答案产生准确的 d 贡献，因为我们实际上在两个先前断开连接的组件之间添加了一条权重为 d 的边。 

我们还需要一种快速的方法来构建所有的倍数桶。 我们不是分解每个数字，而是反转观点：对于每个 d，我们迭代 k·d 的倍数，并将值等于 k·d 的所有索引附加到 d 的存储桶中。 运行时间大约为 O(m log m)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有对 + MST）| O(n² log n) | O(n² log n) | O(n²) | 太慢了 |
 | 除数桶 + DSU | O(m log m + n α(n)) | O(m log m + n α(n)) | O(n + m) | 已接受 |

 ## 算法演练

1. 为每个 ai 值构建一个索引列表。 我们存储位置，以便我们可以快速检索具有给定值的所有节点。 
2. 创建一个存储桶数组，其中存储桶[d] 将包含其值可被 d 整除的所有索引。 我们通过迭代倍数来填充它：对于从 1 到 m 的每个 d，我们添加值 2d、3d 等的所有索引。 
3. 在所有 n 个节点上初始化一个不相交集并集结构。 最初每个节点都是孤立的。 
4. 将 d 从 m 降到 1。对于每个 d，迭代 Bucket[d] 中的所有节点。 我们为该小组保留一名临时代表。 
5. 对于bucket[d]中的第一个节点，我们将其设置为基代表。 对于存储桶中的每个其他节点，我们尝试与代表进行并集。 如果联合成功，我们将 d 添加到答案中。 
6. 对所有 d 继续此过程。 累加的总和就是结果。 

我们从大 d 处理到小 d 的原因是我们希望首先优先考虑更强的 gcd 连接。 一旦两个节点通过较高值除数连接，它们将不再需要较弱的边，因为 DSU 确保我们不会重新连接已经统一的组件。 

### 为什么它有效

 完整图中的每条边的权重等于 gcd(ai, aj)，它恰好是最大的 d，使得 ai 和 aj 都可以被 d 整除。 当我们处理特定的 d 时，我们实际上正在考虑权重至少为 d 的所有边。 通过按降序处理，我们在按权重排序的所有隐式边上模拟克鲁斯卡尔算法。 DSU 确保我们只保留连接不同组件的边，每次我们在 d 级合并时，我们都会使用可以连接这些组件的最佳剩余边。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return False
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]
        return True

    pos = [[] for _ in range(m + 1)]
    for i, v in enumerate(a):
        pos[v].append(i)

    bucket = [[] for _ in range(m + 1)]

    for d in range(1, m + 1):
        for k in range(d, m + 1, d):
            for idx in pos[k]:
                bucket[d].append(idx)

    ans = 0

    for d in range(m, 0, -1):
        if not bucket[d]:
            continue
        rep = bucket[d][0]
        for v in bucket[d]:
            if union(rep, v):
                ans += d

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```该代码首先按索引的精确值对索引进行分组，然后使用倍数循环构建除数桶。 这避免了单独分解每个数字。 DSU 是标准的，只会在实际发生合并时增加成本，这对于性能至关重要。 

d 从 m 到 1 的循环隐式强制执行正确的边排序，因此我们永远不需要显式对边进行排序。

 ## 边缘情况

 一种边缘情况是所有值都相等。 在这种情况下，每一对都有相同的 gcd，因此最优树可以选择任何生成树，并且每条边贡献相同的值。 该算法处理这个问题是因为所有节点都出现在所有相关除数桶中，并且联合首先出现在最高可能的 d 处，然后什么都没有剩下。 

另一个边缘情况是所有值都是成对互质的。 那么每个 gcd 都是 1，因此每条边的权重实际上都是 1。该算法仅在 d = 1 时执行有意义的并集，恰好产生 n − 1 次合并，这与预期的树大小相匹配。 

最后一种边缘情况是值稀疏但共享大公约数结构，例如 1000 的倍数与小数混合。 降序扫描可确保大除数首先连接其组件，而较小的除数仅充当后备连接，从而保持最优性。
