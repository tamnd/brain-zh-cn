 ## 解决方案
 ## 问题理解

 我们得到了几个字符串，它们都具有相同的固定长度。 我们可以构造一个相同长度的新字符串。 目标是选择这个构造的字符串，使其与给定的字符串尽可能匹配。 

一场比赛是按位置计算的。 对于固定位置，如果我们构造的字符串与该位置的给定字符串具有相同的字符，我们就获得该字符串的一个相似度单位。 最终得分是所有字符串和所有位置的这些匹配的总和。 

以更具结构性的方式重新构建，最终字符串中的每个位置都独立地对总分做出贡献。 在位置 i，我们选择一个字符，该选择同时影响 n 个字符串中有多少在该位置匹配。 

约束很小，字符串的数量和长度都以 50 为界。这立即意味着，即使每个测试用例解决方案是三次或二次，也很容易足够快。 对所有位置的所有字符进行完整扫描每个测试用例最多 2500 个单元，即使 T 高达 50，总工作量也可以忽略不计。 

不存在涉及位置之间的排序或依赖关系的棘手边缘情况，因为每个位置都是独立贡献的。 唯一可能阻碍天真的方法的微妙问题是试图贪婪地构建字符串，而没有意识到每个位置都是通过局部频率最大化独立且最优地解决的。 

例如，如果在某个位置我们选择出现 2 次的角色而不是出现 3 次的角色，则该决定无法在其他地方得到补偿，因为贡献不会跨位置转移。 另一个陷阱是当只需要分数时尝试构建不必要的实际字符串，这可能导致可避免的复杂性或错误。 

## 方法

 一个蛮力的想法是在输入隐含的字母表上尝试每个可能的长度为 m 的字符串。 对于每个候选字符串，通过比较所有 m 个位置来计算其与所有 n 个给定字符串的相似度。 评估一个候选者的成本是 O(nm)，候选者的数量以 m 为指数。 即使限制输入中出现的字符，分支因子仍然很大，使得这种方法在小 m 之外不可行。 

关键的观察结果是位置之间不存在交互作用。 位置 i 的贡献仅取决于我们在位置 i 选择的角色，并且独立于所有其他位置。 这将问题分解为 m 个独立的子问题，每列一个。 

对于固定位置i，我们只需要知道该位置的每个字符有多少个字符串。 如果字符 c 在位置 i 处的 n 个字符串中出现 freq[c] 次，则选择 c 会准确给出该位置的 freq[c] 贡献。 因此，最佳选择就是该列中最常见的字符。 

因此，我们不是搜索整个字符串，而是计算每列的频率并对最大频率求和。

 ## 算法演练

 我们独立处理每个测试用例。 

1.读取n和m，然后读取所有字符串。 
2. 对于从 0 到 m−1 的每个位置 i，计算所有 n 个字符串中该列中出现的字符的频率图。 
3. 对于每一列，找出其中出现的所有字符的最大频率。 
4. 将这个最大值添加到答案中。 
5. 输出测试用例的累计和。 

关键的设计选择是独立处理每一列。 这是有效的，因为选择位置 i 处的字符仅影响位置 i 处的匹配，不会影响任何其他位置。 

### 为什么它有效

总分可以写为位置的总和，其中每一项仅取决于该位置所选的字符。 由于位置之间不存在耦合，因此独立优化每一项会产生全局最优解。 对于每一列，与最常见字符的任何偏差都会严格降低该列的贡献，而不会改善任何其他列，因此不存在权衡。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        arr = [input().strip() for _ in range(n)]
        
        ans = 0
        
        for j in range(m):
            freq = {}
            for i in range(n):
                c = arr[i][j]
                freq[c] = freq.get(c, 0) + 1
            ans += max(freq.values())
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案逐列迭代，为每列构建频率字典。 n 个字符串的内部循环是不可避免的，因为我们必须至少检查每个字符一次。 字典按列重置，确保没有跨列污染。 

一个常见的错误是试图在整个矩阵中保持全局频率，这会混合不相关的位置并破坏正确性。 另一个微妙的问题是忘记重置每列的频率图，这会错误地累积跨列的计数。 

## 工作示例

 ### 示例 1

 输入：```
3 3
abc
ebd
fbd
```我们计算列频率。 

| 专栏 | 频率 | 最大字符数 | 贡献 |
 | --- | --- | --- | --- |
 | 0 | a：1，e：1，f：1 | 任意 (1) | 1 |
 | 1 | 乙：3 | 乙| 3 |
 | 2 | c：1，d：2 | d | 2 |

 总计 = 1 + 3 + 2 = 6。 

这表明，即使最佳构造的字符串是“ebd”，我们也永远不需要显式构造它； 只有列数很重要。 

### 示例 2

 输入：```
2 3
abc
aff
```| 专栏 | 频率 | 最大字符数 | 贡献 |
 | --- | --- | --- | --- |
 | 0 | 一个：2 | 一个 | 2 |

 | 2 | c：1，f：1 | c 或 f | 1 |

 总计 = 2 + 1 + 1 = 4。 

此示例表明频率上的联系不会影响答案，因为只有计数才重要，而不是在最大值中选择哪个字符。

 ## 边缘情况

 具有一个字符串的最小情况表明，每一列的贡献恰好为 1，因为该字符串定义了唯一可能的匹配。 该算法处理此问题是因为每个列频率图都有一个等于 n = 1 的条目，因此最大值始终为 1。 

平局重的列（例如具有不同字符的两个字符串）仍然会产生正确的结果，因为最大频率仍然为 1。该算法不依赖于选择哪个字符，只依赖于它出现的次数。 

完全均匀的矩阵产生最大分数 n × m。 每列的频率图始终具有计数为 n 的单个主导字符，因此跨列求和会产生预期的最大值，而无需特殊的大小写。
