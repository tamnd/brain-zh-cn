 ## 解决方案
 ## 问题理解

 我们得到一个仅由左括号和右括号组成的括号字符串。 我们可以使用一种操作重复修改字符串，该操作不会替换字符串中的字符，而是以一种非常特定的方式增长字符串：在一次操作中，我们将一个新括号附加到左端，将一个新括号附加到右端，并且这两个括号中的每一个都可以独立选择为“(”或“)”。 

经过几次这样的操作后，我们希望生成的字符串成为常规的括号序列，这意味着可以将其解释为正确的嵌套表达式，其中每个前缀至少具有与 ')' 一样多的 '(' ，并且末尾的总计数匹配。

 任务是确定所需的此类操作的最小数量，或者确定没有任何操作序列可以使字符串有效。 

约束很大，所有测试用例的总输入长度最多为 5 · 10^5，测试用例最多为 10^5。 这立即排除了每个测试用例的任何二次方。 任何有效的解决方案都必须处理每个字符恒定的次数，或者最坏的情况是在所有测试中使用摊销线性扫描。 

一个微妙的点是，每次操作都会将长度恰好增加 2，即每一侧一个字符。 这意味着最终长度始终为 |s| + 2k。 因此奇偶校验被保留为模 2，但更重要的是，该结构被限制为对称填充。 

当字符串已经无效且仅通过添加外括号无法修复时，就会出现边缘情况。 

例如，像“)(”这样的字符串是不可能的。无论我们添加多少外层，内部反转都无法修复，因为初始前缀已经无效，无法对称偏移。

 另一种边缘情况是字符串已经是正确的括号序列，其中需要零操作。 

第三种微妙的情况是，当字符串接近平衡但早期有一个深负前缀时，例如“)((())”。即使总平衡是正数，早期的违规也会迫使至少一个封闭层，我们必须量化需要多少层。

 ## 方法

 强力解释将尝试所有可能的操作序列。 经过 k 次操作后，每一边都有 k 个左括号选择和 k 个右括号选择，给出 4^k 种配置。 对于每个配置，我们将测试生成的字符串是否是有效的括号序列。 即使对于 k = 10，这也已经很棘手，并且在最坏情况下 k 可以大到 2.5 · 10^5。 

更结构化的蛮力会尝试从 0 向上增加 k 并模拟所有可能的边界选择，但边界组合的数量再次呈指数增长。 核心困难在于操作仅影响最外面的字符，因此内部保持固定并且仅获得对称填充。 

关键的观察结果是，字符串中唯一对可行性重要的部分是其前缀平衡行为。 常规括号序列在任何前缀中的“)”数不得多于“(”。由于我们只能通过将其分层来修复该序列，因此每个操作都有效地允许我们添加一个新的外层，该外层可以“吸收”两侧的前缀缺陷单位。

 这将问题转变为从左侧测量原始字符串违反前缀有效性的程度，并从右侧对称地测量原始字符串违反前缀有效性的程度。 每个操作最多可以修复一个最差前缀不平衡的单位，并且我们还必须通过检查总计数来确保可以实现全局平衡。 

这将问题简化为计算两个值：最小前缀和（跟踪不平衡为“（”= +1，“）”= -1）以及最终总和。 答案成为前缀下降程度的函数，因为每一层都可以通过环绕来均匀地提升整个序列。

 ## 算法演练

 1. 将 '(' 转换为 +1，将 ')' 转换为 -1，并在从左到右扫描字符串时计算前缀和。 

前缀和表示序列到每个位置的平衡程度。 
2. 跟踪扫描过程中的最小前缀和值。 

这个最小值告诉我们最深的不平衡点，即右括号超过左括号。 
3. 计算整个字符串的总和。 

如果总和不为零，则该字符串永远无法成为常规括号序列，因为操作保留奇偶校验结构并且仅添加匹配的括号对整体平衡不能任意纠正。 
4. 如果总和为零，则计算前缀最小值的大小低于零的次数。 

每个负深度单位代表一个必要的外部校正层。 
5. 答案是最小前缀和的绝对值。 

### 为什么它有效

 常规括号序列恰好是前缀和永远不会低于零且以零结束的序列。 我们的操作将当前序列包装在一个新层中，可以选择以任意括号组合开始和结束，但其唯一真正的效果是移动有效边界，以便每层可以抵消一个单位的赤字。 内部结构永远不会改变，因此最深的前缀违规无法修复，除非将其封闭。 因此，所需层数恰好是最坏前缀赤字的大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    bal = 0
    min_bal = 0

    for c in s:
        if c == '(':
            bal += 1
        else:
            bal -= 1
        if bal < min_bal:
            min_bal = bal

    # total balance must be zero for any solution
    if bal != 0:
        print(-1)
        return

    # number of required layers equals depth of worst prefix deficit
    print(-min_bal)

t = int(input())
for _ in range(t):
    solve()
```该代码扫描每个字符串一次，保持运行平衡，其中“(”增加，“)”减少。 达到的最小值捕获了最严重的括号有效性违规。 如果最终余额非零，则任何对称包装都无法修复开盘和收盘之间的不匹配。 

最终答案直接从最负的前缀值得出，该值对应于需要多少个封闭层才能防止任何前缀无效。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        s = input().strip()
        bal = 0
        min_bal = 0
        for c in s:
            if c == '(':
                bal += 1
            else:
                bal -= 1
            min_bal = min(min_bal, bal)
        if bal != 0:
            return "-1"
        return str(-min_bal)

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

# provided sample (interpreted)
assert run("3\n)(()\n((\n())\n") == "-1\n-1\n0"

# minimum size valid
assert run("1\n()\n") == "0"

# minimum size invalid
assert run("1\n)\n") == "-1"

# already balanced but needs wrapping
assert run("1\n)(()\n") == "1"

 ## 边缘情况

 一种重要的边缘情况是字符串以右括号开头。 例如输入“)((())”。前缀立即变为负数，在第一个字符处达到 -1。算法在`min_bal`，最终答案变为 1。扫描正确地捕获到需要单个封闭层才能将整个序列转换为非负前缀状态。 

另一种边缘情况是完全无效的字符串，总余额正确，但前缀深度为负，例如“))((”。这里前缀最小值变为-2。算法返回2，意味着需要两次换行操作。每次操作恰好对应于纠正一个单位的前缀赤字。

 最终的边缘情况是总余额非零的字符串，如“(()”。扫描检测最终`bal != 0`并立即返回-1。 这是必要的，因为任何对称外部添加的组合都不能改变左括号和右括号的数量必须在有效序列中匹配的事实。
