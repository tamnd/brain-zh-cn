 ## 解决方案
 ## 问题理解

 每个测试用例都描述了一个下载过程，该过程准确地完成`n`等步，从`0`到`n`。 在某个中间点`x`， 在哪里`1 ≤ x ≤ n - 1`，下载地址为`x/n`完成和`(n - x)/n`其余的。 我们被要求看已完成部分与剩余部分的比率，即`x : (n - x)`，减少它，当它变成整数时只保留这个比率的整数值。 

对于固定位置`x`，比率恰好是整数，当`x / (n - x)`是一个整数。 每个这样的有效`x`将其减少的比率值贡献给总和。 任务是计算每个的总和`n`。 

约束允许最多`10^5`测试用例和每个`n`可以大到`10^6`。 这立即排除了检查每个`x`从`1`到`n - 1`对于每个查询，因为这会导致大约`10^11`最坏情况下的操作。 即使对所有位置采用对数每步方法仍然太慢，除非经过大量预处理。 

出现微妙的边缘情况时`n`是素数。 那么只存在平凡除数，并且我们必须确保逻辑不会意外地计算无效位置。 例如，当`n = 5`，必须仔细推导有效头寸，而不是假设存在许多内部比率。 一个简单的模拟可能会尝试所有`x`并且错过了只有特定代数条件才重要的结构。 

## 方法

 蛮力方法迭代每个位置`x`从`1`到`n - 1`，计算比率`x / (n - x)`，检查它是否是整数，如果是，则将其添加到答案中。 这是正确的，因为它直接遵循定义。 然而，它需要`O(n)`每个测试用例的工作量，导致`O(nT)`总体而言，这远远超出了可行的限度，当两者`n`和`T`很大。 

关键的简化来自于重写完整性条件。 比率`x / (n - x)`是一个整数`k`当且仅当`x = k(n - x)`。 重新排列给出`x(1 + k) = kn`， 所以`x = kn / (k + 1)`。 为了使这一点有效，`(k + 1)`必须划分`kn`。 自从`k`和`k + 1`是互质的，这个力`(k + 1)`划分`n`。 

这将问题从迭代位置转变为`x`迭代除数`n`。 每个除数直接对应于一个有效的比率值，使得解决方案仅依赖于数论函数`n`，不是其线性范围。 

由此，答案简化为涉及除数和和计数的简单表达式，允许对所有值进行全面预处理`10^6`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nT) | O(1) | O(1) | 太慢了 |
 | 基于除数的预计算 | O(N log N + T) | O(N log N + T) | O(N) | 已接受 |

 ## 算法演练

 我们将问题转化为除数运算并一次性预先计算所有内容`n`直至最大限制。 

1. 预先计算除数之和`sigma(n)`对于每一个`n`最多`10^6`。 这是使用筛式方法完成的，其中每个整数都贡献于其所有倍数。 这是必要的，因为每个有效比率都取决于除数结构而不是单个位置。 
2. 预先计算除数的个数`tau(n)`对于每一个`n`使用相同的筛子堆积。 每次我们为每个除数出现添加一个贡献。 
3. 对于每个测试用例，请阅读`n`并使用恒等式计算答案`answer = sigma(n) - tau(n)`。 
4. 立即输出每个查询的结果。 

步骤 3 有效的原因来自于将每个有效比率映射到除数`d`的`n`在哪里`d ≥ 2`，并且每个这样的除数都准确贡献`(d - 1)`到总和。 

### 为什么它有效

 每个有效比率对应一个值`k`这样`x / (n - x) = k`。 这迫使`x = kn / (k + 1)`，只有当`(k + 1)`划分`n`。 写作`d = k + 1`, 每个除数`d ≥ 2`恰好产生一个有效位置并做出贡献`d - 1`到总和。 对所有这些除数求和相当于`sum_{d|n, d≥2}(d - 1)`，这在代数上简化为`sigma(n) - tau(n)`。 

该算法是正确的，因为它用有效比率和除数之间的精确双射代替了基于位置的条件`n`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 10**6

sigma = [0] * (MAXN + 1)
tau = [0] * (MAXN + 1)

for i in range(1, MAXN + 1):
    for j in range(i, MAXN + 1, i):
        sigma[j] += i
        tau[j] += 1

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(sigma[n] - tau[n]))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```预处理循环以经典的筛选方式构建除数和并进行计数。 对于每一个`i`，它对所有倍数都有贡献`j`，将其值累加到`sigma[j]`并计入`tau[j]`。 

查询步骤是每个测试用例的恒定时间。 减法`sigma[n] - tau[n]`直接实现派生公式，避免查询期间的任何重新计算。 

## 工作示例

 ### 示例 1

 考虑`n = 6`。 

有效比率来自大于 1 的 6 因数，即 2、3 和 6。 

| 除数 d | 比例贡献 (d - 1) |
 | --- | --- |
 | 2 | 1 |
 | 3 | 2 |
 | 6 | 5 |

 总和是`1 + 2 + 5 = 8`。 

这匹配`sigma(6) = 1 + 2 + 3 + 6 = 12`和`tau(6) = 4`， 所以`12 - 4 = 8`。 

### 示例 2

 考虑`n = 10`。 

大于 1 的约数有 2、5、10。 

| 除数 d | 贡献 |
 | --- | --- |
 | 2 | 1 |
 | 5 | 4 |
 | 10 | 10 9 |

 总计为`14`。 

再次，`sigma(10) = 18`,`tau(10) = 4`， 所以`18 - 4 = 14`。 

这些痕迹表明，每个除数都是独立贡献的，一旦应用变换，位置之间就不存在相互作用。

 ## 边缘情况

 对于`n = 1`，根本没有中间位置，因此总和必须为零。 公式给出`sigma(1) - tau(1) = 1 - 1 = 0`，匹配定义而无需特殊处理。 

对于总理`n`， 例如`n = 5`，仅存在基于除数的贡献。 除数是`1`和`5`，所以只有`5`贡献，给予`(5 - 1) = 4`。 公式给出`sigma(5) - tau(5) = (1 + 5) - 2 = 4`，即使区间内不存在内部结构也能确认正确性。 

对于高度复合的数字，例如`n = 12`，许多除数独立贡献。 该算法自然地处理了这个问题，因为每个除数在预处理期间只贡献一次，确保不会过度计算或遗漏贡献。
