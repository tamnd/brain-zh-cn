 ## 解决方案
 ## 问题理解

 我们得到一棵以节点 1 为根的树。每个节点都有固定的权重，并且还有一系列在所有起始节点之间共享的“日值”。 如果我们从某个节点开始，沿着唯一的路径向上走到根节点，我们将第 1 天分配给起始节点，将第 2 天分配给其父节点，依此类推，直到到达根节点。 

在此行走期间，每个访问的节点都会贡献一个运行分数。 节点的贡献取决于两件事：它在树中的固定值和我们访问它的当天的值。 具体来说，如果某个节点在第 k 天被访问，我们将其节点权重与第 k 天值的乘积相加。 

任务是为每个可能的起始节点独立计算总分。 

约束模式是这里的主要信号。 所有测试用例的节点总数最多为 3×10^5，因此每个测试用例的任何解决方案都必须接近线性或线性算数。 在链形树中，任何独立地走每条路径并重新计算每个节点的东西都将降级为 O(n^2) 并立即失败。 同样，根据祖先路径重复重新计算贡献也是不可行的。 

一个微妙的边缘情况来自于理解每个起始节点的日期索引始终从 1 开始。 这会重置每个查询节点的权重方案。 一个幼稚的错误是将天视为跨节点的全局，这将完全改变含义。 

另一个极端情况是倾斜树，例如像 1-2-3-4-…-n 这样的链。 在这种情况下，每个答案都涉及一个完整的前缀和，并且日权重不断增加。 任何逐节点遍历方法都会多次重复重新计算相同的后缀，这正是必须避免的。 

## 方法

 直接方法很简单：对于每个节点，向上走到根，将第 k 天的值乘以从开始处深度为 k 的节点值，然后求和。 这是正确的，因为它确实模拟了问题中描述的过程。 然而，在链形树中，最后一个节点的根需要经过 O(n) 步才能到达，并且对所有节点执行此操作会导致 O(n^2) 工作。 

关键的观察结果是，行走的结构完全由相对于起始节点的深度决定，而树结构仅影响每个深度出现的节点。 这建议翻转视角：我们可以从根开始向下传播信息，而不是从每个节点开始向上传播，以考虑每个节点在所有可能的起始路径中如何出现的方式累积贡献。 

如果我们固定一个节点 u，它的贡献就会出现在其子树中的每个起始节点中。 对于该子树中的起始节点 x，在等于 dist(x, u) 的深度处访问 u。 因此，u 贡献 b[u] 乘以一个值，该值仅取决于其子树中每个深度出现的节点数。 

这将问题转化为为每个节点维护其子树中不同深度的所有节点的日值的聚合加权和。 挑战在于，当在父级和子级之间移动时，深度会发生变化，因此我们需要一种方法来有效地合并这些深度索引的贡献。 

这是具有“移位卷积”行为的经典树 DP。 每个子树都带有一个结构，该结构表示按距子树根的距离索引的贡献。 将子节点合并到父节点时，所有子节点的贡献深度都必须移动+1，因为子节点子树中的每个节点距离任何基于祖先的起点都更远一步。 

有效管理此问题的标准方法是为每个节点维护一个按深度聚合值的类似向量的结构，并将较小的结构合并为较大的结构（树上的 DSU 或重轻式合并），确保每个元素仅移动和添加 O(log n) 次。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每个节点向上行走）| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 从小到大合并的树DP | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将树的根设为 1，并自下而上计算子树信息。 

1. 首先，计算每个节点从根开始的深度。 这为我们提供了一种自然的方式来索引节点距根的距离，并在组合子树时允许一致的相对移动。 
2. 对于每个节点 u，我们维护一个容器 dp[u]，其中 dp[u][d] 表示 u 子树中距离 u 距离 d 的节点的总贡献，并按其 b 值加权。 这种抽象将子树结构与全局交互隔离开来。 
3. 按后序处理树。 当访问节点u时，用u本身在距离0处的贡献来初始化dp[u]，因此dp[u][0] = b[u]。 
4. 对于 u 的每个子 v，我们将 dp[v] 合并到 dp[u] 中。 每个条目 dp[v][d] 对应于距 v 距离 d 的节点，但相对于 u 这些节点距离 d+1，因此我们在合并之前将索引移动 +1。 合并将 dp[v][d] 添加到 dp[u][d+1] 中。 
5. 在合并过程中，始终将较小的 dp 结构附加到较大的 dp 结构中。 这确保每个值最多移动对数多次合并，使总复杂度接近线性。 
6. 一旦节点 u 的 dp 被完全计算出来，我们就可以得出它的最终答案。 关键的重新解释是 dp[u][k] 告诉我们从 u 开始时在深度 k 处访问的节点之间存在多少总 b 权重。 我们将 dp[u][k] 乘以 a[k]，并对所有有效 k 求和。 

这样做的原因是，对于任何起始节点 u，其子树中的每个节点 v 在等于它们与 u 的距离的深度处被访问一次，并且 dp 精确聚合按该距离分组的所有此类节点。 

## 为什么它有效

 中心不变量是，在处理节点 u 后，dp[u] 编码一个完整且正确的子树节点权重直方图，该子树节点权重以距 u 的距离为索引。 每次合并都保留了正确性，因为向上移动一级时移动 +1 与根引用的变化完全匹配。 由于每个子树都在每个祖先链中精确组合一次，因此每对（起始节点、访问节点）在正确的深度桶中精确计数一次，确保最终的加权和与过程的定义匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if parent[v] == -1:
                parent[v] = u
                stack.append(v)

    parent[0] = -1

    children = [[] for _ in range(n)]
    for v in range(1, n):
        children[parent[v]].append(v)

    dp = [dict() for _ in range(n)]

    for u in reversed(order):
        dp[u][0] = b[u] % MOD
        for v in children[u]:
            if len(dp[v]) > len(dp[u]):
                dp[u], dp[v] = dp[v], dp[u]
            ndp = dp[u]
            for d, val in dp[v].items():
                ndp[d + 1] = (ndp.get(d + 1, 0) + val) % MOD
        dp[u] = ndp

    res = [0] * n
    for u in range(n):
        s = 0
        for d, val in dp[u].items():
            if d < n:
                s = (s + val * a[d]) % MOD
        res[u] = s

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```该实现首先使用显式父数组构建有根树，然后构建子列表以进行干净的后序遍历。 dp 结构是每个节点的字典，以允许稀疏深度存储，因为在倾斜情况下完整数组会太大。 

合并步骤是关键部分：在将子地图合并到父地图之前，我们确保始终将较小的地图合并到较大的地图中。 这可以防止二次爆炸。 通过插入键 d+1 来显式处理移一位。 

最后，一旦构建了 dp[u]，我们就通过将每个存储的深度桶与相应的日期值 a[d] 配对来评估贡献。

 ## 工作示例

 考虑一条小链 1-2-3，其中 a = [1, 2, 3] 且 b = [1, 2, 3]。 

我们自下而上构建 dp。 

| 节点| dp 内容（深度 → sum b）|
 | --- | --- |
 | 3 | {0:3} |
 | 2 | {0:2, 1:3} |
 | 1 | {0:1, 1:2, 2:3} |

 对于节点 2，我们将答案计算为 2·a1 + 3·a2 = 2·1 + 3·2 = 8。这正好对应于从 2 开始，访问 2，然后访问 1。

 对于节点 1，我们计算 1·a1 + 2·a2 + 3·a3 = 1 + 4 + 9 = 14，匹配完整的向上路径。

 该轨迹表明 dp 有效地同时对所有向上路径进行编码。 

现在考虑一个根为 1 的星，其子节点为 2、3、4，全部为叶子。 

| 节点| dp 内容 |
 | --- | --- |
 | 2,3,4 | {0: b[i]} |
 | 1 | {0：b1，1：b2 + b3 + b4} |

 对于节点 1，仅存在深度 0 和 1，这与所有叶子节点恰好相距一步的事实相匹配。 每片叶子仅对深度 1 做出贡献，从而确认正确的移动行为。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 每个节点的贡献通过从小到大进行合并，确保每个值在有限的合并中移动
 | 空间| O(n) | 每个节点以聚合形式一次只贡献一个 dp 结构 |

 这些约束总共允许最多 3×10^5 个节点，因此，只要合并高效，即使使用 Python 常数因子，具有对数开销的近线性解决方案也能轻松满足限制。

 ## 边缘情况

 单节点树隔离了基本初始化，其中 dp[1][0] 必须等于 b[1]，并且答案简化为 b1·a1。 任何缺失的初始化都会立即破坏这一点。 

在深层链中，每次合并都会反复转移贡献。 该算法必须确保每次边缘遍历时每次移位恰好应用一次。 如果移位被延迟或重复，深度索引将会漂移，并且较高日乘数将附加到错误的节点，产生明显不正确的累积和。 

在星体中，所有子节点仅在相对于根的深度 1 处做出贡献。 如果合并未能正确移位，子贡献将错误地出现在深度 0 处，从而导致使用 a1 而不是 a2 进行过度计数。
