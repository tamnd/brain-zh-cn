 ## 解决方案
 ## 问题理解

 我们从一个整数值开始，必须执行两种减半操作固定次数。 

一次操作将当前值替换为该值的一半下限。 另一种则以价值一半的上限来代替。 我们必须准确地使用楼层操作`n`次数与上限操作完全一致`m`次，但我们可以选择它们的顺序。 任务是找到可以获得的最小和最大的最终值。 

首先要注意的是，这两个操作对于偶数的行为是相同的：$$\left\lfloor \frac{x}{2} \right\rfloor = \left\lceil \frac{x}{2} \right\rceil = \frac{x}{2}$$唯一有趣的情况发生在`x`是奇数：$$\left\lfloor \frac{x}{2} \right\rfloor = \frac{x-1}{2}$$

$$\left\lceil \frac{x}{2} \right\rceil = \frac{x+1}{2}$$对于奇数，下限运算产生的结果比上限运算恰好小 1。 

限制才是真正的挑战。 价值观`x`,`n`， 和`m`都可以大到`10^9`，并且最多有`10^4`测试用例。 任何试图模拟所有的方法`n + m`操作是不可能的，因为单个测试用例可能需要 20 亿次操作。 

关键的观察结果是每次操作都会将当前值大致减半。 自从`x ≤ 10^9`，大约减半 30 次后，该值变为`0`或者`1`。 一旦达到这一点，就可以分析处理剩余的操作。 这意味着每个测试用例的实际工作量可以减少到一个很小的常数。 

一些边缘情况很容易被错误处理。 

考虑：```
x = 1, n = 1, m = 100
```最小可能的答案是`0`。 随时轮流进行楼层操作`1`进入`0`，之后所有操作都将其保持在`0`。 一个粗心的实现，当它到达时就停止了`1`会错误地返回`1`。 

考虑：```
x = 1, n = 0, m = 100
```答案是`1`。 天花板`1/2`仍然是`1`，所以该值永远不会改变。 

考虑：```
x = 0, n = 10^9, m = 10^9
```答案是`0 0`。 这两种操作都使零永远保持不变。 

这些终止状态必须单独处理。 

## 方法

 暴力解决方案将尝试所有可能的操作顺序。 即使对于较小的值`n + m`，可能的订单数量是巨大的：$$\binom{n+m}{n}$$这种情况呈指数级增长，几乎立即变得毫无希望。 

更合理的蛮力可以模拟选定的顺序。 那仍然失败，因为`n + m`可能大到`2 \cdot 10^9`。 

操作的结构为我们提供了更强有力的观察。 每次操作都会将当前值减半。 最多从`10^9`，大约 30 步后，该值已减少为`0`或者`1`。 从那时起，进一步的操作就变得微不足道了。 

剩下的问题是如何最优地选择顺序。 

当当前值为奇数时，下限产生的结果小于上限。 如果我们试图最小化最终答案，我们希望尽可能对奇数进行向下取整运算。 如果我们试图最大化最终答案，我们希望尽可能对奇数进行上限运算。 

偶数是不同的，因为两个操作给出完全相同的下一个值。 由于结果是相同的，我们应该利用这些时刻来消耗稍后不太有用的操作类型。 

为了最小化，地板操作很有价值，因为它们对奇数有帮助。 对于偶数，我们应该首先消耗上限操作，并为未来的奇数值保存下限操作。 

对于最大化，上限操作很有价值，因为它们对奇数有帮助。 对于偶数，我们应该首先消耗下限操作，并为将来的奇数保留上限操作。 

这种贪心策略完全决定了最优序列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(log x) | O(1) | O(1) | 已接受 |

 ## 算法演练

 计算最小答案：

 1. 虽然`x > 1`并且还有剩余操作，检查奇偶性`x`。 
2.如果`x`是奇怪的并且有楼层操作可用，请使用它。 

这给出了可能的最小下一个值。 
3.如果`x`很奇怪并且没有保留地板操作，请使用天花板操作。 
4.如果`x`是偶数，两个操作都会产生相同的下一个值。 

如果存在上限运算，请使用上限运算，因为对于未来奇数，上限运算的用处不如下限运算有用。 
5. 继续，直到使用所有操作或`x`变成`0`或者`1`。 
6. 如果`x = 0`，答案是`0`。 
7. 如果`x = 1`，答案是`0`如果还有楼层操作，否则`1`。 

计算最大答案：

 1. 虽然`x > 1`并继续操作，检查奇偶性。 
2.如果`x`是奇数并且可以使用上限操作，请使用它。 

这给出了最大可能的下一个值。 
3.如果`x`很奇怪并且没有保留上限操作，请使用下限操作。 
4.如果`x`是偶数，如果可能的话使用地板操作。 

下限运算对于偶数是无害的，因此我们为未来的奇数值保留上限运算。 
5. 继续，直到使用所有操作或`x`变成`0`或者`1`。 
6. 如果`x = 0`，答案是`0`。 
7. 如果`x = 1`，答案是`1`仅当没有场内操作剩余时。 否则最终必须应用一些地板，从而导致结果`0`。 

### 为什么它有效

 关键的属性是下限和上限仅在奇数上有所不同。 

对于最小答案，对奇数使用的每次向下取整操作都会比向上取整操作将当前值减少一倍。 由于所有未来的操作都是当前值的单调函数，因此现在具有较小的值永远不会损害最小化目标。 因此，下限操作在奇数状态上最有价值，而上限操作应尽可能花在偶数状态上。 

最大化论证是对称的。 上限操作在奇数状态下最有价值，因为它们使值保持更大。 即使在状态上使用下限操作，也可以保留那些有价值的上限操作供以后使用。 

由于每个贪婪选择都会为下一次奇怪的遭遇保留更有用的操作类型，因此没有其他排序可以产生更好的最终结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_minimum(x, n, m):
    while x > 1 and (n > 0 or m > 0):
        if x & 1:
            if n > 0:
                x //= 2
                n -= 1
            else:
                x = (x + 1) // 2
                m -= 1
        else:
            if m > 0:
                x //= 2
                m -= 1
            else:
                x //= 2
                n -= 1

    if x == 0:
        return 0
    if x == 1:
        return 0 if n > 0 else 1
    return x

def get_maximum(x, n, m):
    while x > 1 and (n > 0 or m > 0):
        if x & 1:
            if m > 0:
                x = (x + 1) // 2
                m -= 1
            else:
                x //= 2
                n -= 1
        else:
            if n > 0:
                x //= 2
                n -= 1
            else:
                x //= 2
                m -= 1

    if x == 0:
        return 0
    if x == 1:
        return 1 if n == 0 else 0
    return x

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        x, n, m = map(int, input().split())
        mn = get_minimum(x, n, m)
        mx = get_maximum(x, n, m)
        ans.append(f"{mn} {mx}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```这两个辅助函数独立地实现了两种贪婪策略。 

循环仅在 while 时运行`x > 1`。 每次迭代都会将值减半，因此对于给定的约束，迭代次数最多约为 31 次。 即使当`n`和`m`是十亿，我们从来没有模拟过那么多的操作。 

终端处理是微妙的部分。 一次`x`变成`1`，剩下的操作很重要。 剩余楼层运营最终转向`1`进入`0`。 吊顶作业独自离开`1`不变。 这就是为什么最终逻辑仅取决于是否还有任何楼层操作可用。 

不存在溢出问题，因为该值只会减少。

 ## 边缘情况

 考虑：```
1
1 1 100
```模拟立即到达终止状态`x = 1`。 最小逻辑检查是否还有任何楼层操作。 自从`n = 1`，答案就变成了`0`。 最大逻辑得出相同的结论，因为最终必须使用楼层。 输出是：```
0 0
```考虑：```
1
1 0 100
```不存在场内操作。 天花板`1/2`仍然是`1`，因此每个剩余操作都会使该值保持不变。 两个答案都是：```
1 1
```考虑：```
1
0 1000000000 1000000000
```该算法永远不会进入主循环，因为`x = 0`。 终端检查返回`0`立即地。 输出是：```
0 0
```考虑：```
1
12 1000000000 1000000000
```值达到`0`经过几次减半之后。 该算法并不尝试模拟数十亿次操作。 一次`x = 0`，答案固定为`0`，这正是最大约束所需的行为。
