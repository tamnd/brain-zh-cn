 ## 解决方案
 ## 问题理解

 我们被赋予了一种固定的工作模式，每天都在重复，永远重复。 每天都有一个时间表`k`小时，以及每天的开始时间`n`任务出现。 任务`i`一天中的某个时间出现在已知时间`a_i`并要求在当天内`b_i`数小时的不间断处理时间。 到达时间`a_i`严格递增，因此一天内的任务按固定的时间顺序排列。 

有一个工作人员处理任务。 工作线程一旦开始就不会抢占任务，并且总是在空闲时选择最早到达的未完成任务。 由于任务每天都会重复，因此这会成为具有非常规则结构的无限任务流。 

每个查询指的是任务的特定发生，即`y`当天的第 任务`x`。 目标是计算特定任务完成时的确切时间，以天数和当天的小时数表示。 

关键的困难在于，虽然每天只有`n`任务，系统永远运行，不同日期的任务通过队列交互。 当天有任务`x`与前几天并不独立，因为前几天可能会将其推回到处理顺序中。 

这些限制迫使我们整天远离模拟。 高达`10^5`每天任务最多`5×10^5`查询天数，天真的每日模拟将爆炸到大约`5×10^10`运营。 即使重复模拟一天也是不够的，因为队列结转会产生跨日依赖性。 

系统过载会产生微妙的边缘情况。 如果每天的总工作量超过可用的`k`小时，队列永远不会完全清除，并且延迟会在几天内累积。 如果工作量足够小，每天都会独立清算，不存在结转。 这两种制度的行为根本不同，必须分开。 

一个常见的错误是独立模拟每一天，假设任务每天都会重置。 当一天中的任务发生时，会立即失败`x`取决于当天未完成的工作`x-1`。 另一种失败模式是忽略当天的到达时间并将任务视为同时到达，这会在当天早些时候存在空闲间隙时破坏正确性。 

## 方法

 直接模拟将在所有日子里维护一个待处理任务的队列，每天推送新任务并逐一处理它们。 这正确地对系统进行了建模，但是操作数量随着处理的总工作量而增加，可以达到`O(nq)`最坏的情况下几天，远远超出了可行性。 

关键的观察结果是，系统以两种模式之一运行，具体取决于一天的总工作负载是否最多为可用处理时间`k`。 

如果所有的总和`b_i`至多是`k`，那么每一天都是欠载的。 工作人员在一天结束前完成所有任务，队列每天都会变空。 在这种情况下，天是同一时间表的独立副本，我们只需要计算一天内的任务完成时间。 

如果总和超过`k`，那么每天产生的工作量就多于可以完成的工作量。 经过短暂的短暂时期后，工人就会变得永久忙碌。 一旦发生这种情况，一天内的确切到达时间就不再影响实际的订购，因为队列永远不会空。 系统退化为一个连续的流程，其中只有总工作量才重要。 

这使我们能够将无限过程减少为单日模拟（轻负载）或稳态前缀累积（重负载）。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 跨天的全面模拟 | O（总工作）| O(n) | 太慢了|
 | 单日模拟+稳态处理| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们根据一天的总工作量将解决方案分为两种情况。 

### 情况 1：每天总工作量 ≤ k

 1. 计算从时间 0 开始的单日时间表。 

我们按升序模拟任务`a_i`，维护当前时间指针。 每个任务开始于`max(current_time, a_i)`添加后完成`b_i`。 这同时考虑了到达约束和 FIFO 排序。 
2.记录当天每项任务的完成时间。 

由于总工作量适合`k`，没有任务溢出到第二天，因此这些完成时间是最终的。 
3. 查询`(x, y)`，将单日结果平移一整天。 

答案很简单`(x-1)*k + completion_time_within_day[y]`。 

这是有效的，因为系统每天都会重置，没有剩余任务。 

### 情况 2：每天总工作量 > k

 1. 观察系统最终变得永久繁忙。 

经过足够的天数后，每天开始时总会有待处理的工作，因此工人永远不会闲着。 
2、稳定状态下，一天内到达次数不再影响执行顺序。 

任务按照严格的日顺序进行有效处理，并且在每天内按照索引顺序进行处理，因为不会出现可能重新排序执行的间隙。 
3. 仅用每个任务的处理成本来替换它。 

系统变成每天重复的单一无限工作负载序列。 
4. 预先计算一天的前缀和：

 让`pref[i] = b_1 + ... + b_i`， 和`S = pref[n]`。 
5. 以连续小时数计算全局完成时间：

 任务完成时间`(x, y)`变成：`time = (x-1)*S + pref[y]`。 
6. 将连续时间转换为`(day, hour)`除以`k`。 

这是有效的，因为一旦系统饱和，工作线程就永远不会等待，因此调度相当于处理一个没有空闲间隙的连续流。 

### 为什么它有效

 在这两种情况下，关键的不变量是工作线程始终按照 FIFO 到达顺序处理任务，并且一旦系统饱和，就不会出现可能扭曲顺序的空闲间隔。 队列要么每天重置，要么在某个时间点后永远不会清空。 这是在恒定的每日输入模式下唯一可能的两种稳定行为，因此将过程简化为独立日模拟或纯前缀累积可以准确地捕获所有动态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, q = map(int, input().split())
    a = []
    b = []
    
    for _ in range(n):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + b[i]
    S = pref[n]

    # Case 1: light load, each day clears
    if S <= k:
        finish = [0] * n
        cur = 0
        for i in range(n):
            if cur < a[i]:
                cur = a[i]
            cur += b[i]
            finish[i] = cur

        out = []
        for _ in range(q):
            x, y = map(int, input().split())
            y -= 1
            day_start = (x - 1) * k
            t = day_start + finish[y]
            d = t // k + 1
            h = t % k + 1
            out.append(f"{d} {h}")

        print("\n".join(out))
        return

    # Case 2: heavy load, steady state prefix model
    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        y -= 1
        t = (x - 1) * S + pref[y]
        d = t // k + 1
        h = t % k + 1
        out.append(f"{d} {h}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现首先预先计算处理时间的前缀和，因为它们是在过载状态下唯一重要的量。 决策点是每天的总工作量`S`。 

在轻负载分支中，我们使用单个时间指针显式模拟一天。 重要的细节是`max(cur, a[i])`步骤，确保我们尊重任务发布时间和一天内的空闲时间。 

在重负载分支中，我们完全避免模拟。 使用前缀和的线性公式在恒定时间内回答每个查询。 从绝对时间到`(day, hour)`使用整数除以`k`，以 1 为基础的索引调整。 

## 工作示例

 考虑一个小型系统`k = 5`和任务：

 | 我| a_i | b_i |
 | ---| ---| ---|
 | 1 | 1 | 1 |
 | 2 | 4 | 3 |

 ### 跟踪（轻负载情况）

 这里的总工作量是`4 ≤ 5`，因此不会发生结转。 

| 步骤| 任务| 开始时间 | 完成时间 | 当前|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 1 | 2 | 2 |
 | 2 | 2 | 4 | 7 | 7 |

 两者都在同一天内完成。 

供查询`(2, 2)`，第 2 天任务 2 在连续时间完成`5 + 7 = 12`，映射到当天`3`， 小时`2`。 

这证实了每一天都是独立的。 

现在考虑一个重负载的例子：`k = 10`，任务：

 | 我| b_i |
 | ---| ---|
 | 1 | 4 |
 | 2 | 6 |
 | 3 | 7 |

 总工作量为`17 > 10`，因此积压不断累积。 

前缀和是`4, 10, 17`。 

供查询`(3, 2)`，我们计算：`time = (3-1)*17 + 10 = 44`。 

这代表连续处理时间； 转换为天/小时给出天`5`， 小时`4`。 

该迹线表明，一旦系统饱和，只有累积工作才重要。

 ## 边缘情况

 一种极端情况是每日总工作量恰好等于`k`。 在这种情况下，工人在每天结束时准确地完成工作，但不会向前推进任何东西。 例如，如果任务完全满足`k`小时内，轻载分支仍然适用。 模拟准时完成`k`，所以转移`(x-1)*k`每天都连续放置，没有重叠。 

另一种情况是第一个任务在当天晚些时候到达。 即使在轻负载系统中，工作人员也会闲置，直到`a_1`。 模拟通过以下方式处理这个问题`max(cur, a[i])`步。 如果没有它，早期的空闲时间将被忽略，并且所有完成时间将错误地提前移动。 

第三种情况是负载较重的系统，早期仍出现部分空闲状态。 即使系统最终饱和，稳态公式也仅在转变后适用。 基于每日总工作量的决策避免了混合模式，并确保我们不会错误地假设立即饱和。
