 ## 解决方案
 ## 问题理解

 我们正在模拟咖啡杯内随着时间的推移会发生什么。 杯子开始是空的，然后我们处理一系列操作，要么将一些咖啡倒入杯子中，要么从杯子里喝一些咖啡。 

重要的细节是咖啡在概念上是分层的。 每次倒出新咖啡时，它都会在现有液体的顶部形成一层新的层。 当咖啡被取出时，总是先从顶层取出，如果取出的量足够大，可能会消耗多层。 

“咖啡环”对应于在此过程中创建的咖啡层之间的边界。 即使所有咖啡最终都被取出，空杯子仍然在底部形成最后的响声。 

因此，任务不是跟踪最终的咖啡量，而是跟踪整个过程中存在多少个不同的层边界。 

输入是“添加 X”（倒 X 毫升）或“移除 X”（喝 X 毫升）形式的操作序列。 输出是执行所有操作后形成的咖啡环总数。 

约束足够大，不可能对所有毫升进行任何二次模拟。 我们必须在恒定或对数时间内处理每个操作，这意味着我们需要将咖啡视为结构化片段而不是单个单元。 

当一个操作部分消耗多个层时，就会出现微妙的失败情况。 例如，如果我们有尺寸层`[3, 5]`并删除`4`，顶层消失，第二层部分减少。 独立处理每个操作而不维护结构的简单实现将错误地计算层边界。 

另一个边缘情况是所有咖啡都被移除。 例如：

 输入：```
3
+5 -3 -2
```处理完所有事情后，杯子是空的，但答案不为零。 与杯底相对应的还有一个圆环。 只计算“现有层”的简单解决方案会错误地输出 0。 

## 方法

 强力解释将以毫升分辨率模拟咖啡。 我们会将每次倒出的饮料扩展为单独的单元，并维护一堆单元，然后通过逐个弹出单元来模拟每种饮料。 这是正确的，但立即变得不可行，因为在最坏的解释中，单个操作可能涉及多达 10^9 个单元，即使在更严格的约束下，总体积也会使这种方法无法使用。 

关键的观察是我们永远不需要跟踪单个毫升。 我们只需要跟踪共享同一“代”的连续咖啡块，这意味着它们是在一次操作中倒入的，然后再发生任何后续中断。 

每次浇注都会创建一个新层。 饮料仅从顶层去除，并且可能部分减少或完全去除它。 这自然建议维护一个堆栈，其中每个元素都是代表一个层及其剩余体积的段。 

然后，环的数量取决于已创建且未完全移除的此类分段的数量，加上杯子底部的最终边界。 

这减少了维护段大小堆栈和每次操作仅更新顶部元素的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(总体积) | O(总体积) | 太慢了|
 | 段堆栈 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将杯子建模为一堆层，其中每一层都存储该层中剩余的咖啡量。 

1. 初始化一个空堆栈。 每个元素将代表由浇筑操作创建的一个层。 
2. 对于“pour X”操作，将值为 X 的新元素推入堆栈。 这代表创建一个新的顶层，立即在杯子的结构中引入新的边界。 
3. 对于“drink X”操作，从栈顶开始反复减少。 从顶层的剩余量中减去 X。 如果顶层变为零，则将其从堆栈中完全删除并继续从下一层中减去。 这反映了喝酒总是先喝掉最上面的咖啡这一物理观念。 
4. 继续直至 X 完全消耗。 这可以确保所有受影响的层都正确更新，即使单一饮料跨越多个先前倒入的层也是如此。 
5. 处理完所有操作后，环的数量等于堆叠中剩余的层数加上杯子底部的一个附加环。 如果堆栈为空，则答案为 1。 

### 为什么它有效

 在任何时刻，堆栈都代表将杯子正确划分为由连续倾倒形成的最大连续片段。 每次我们推送时，我们都会创建一个新的段边界。 每次我们完全删除一个片段时，我们就永久地消除了该边界。 部分删除不会改变段的数量，只会改变它们的大小。 因为饮料从不重新排序层并且总是从顶部起作用，所以在整个过程中堆栈不变量被保留。 最终的段数与在任何时间点同时存在的不同咖啡层的数量完全匹配，并且每个这样的层对应于一个环边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    stack = []

    for _ in range(n):
        op = input().strip()
        if op[0] == '+':
            x = int(op[1:])
            stack.append(x)
        else:
            x = int(op[1:])
            while x > 0 and stack:
                if stack[-1] > x:
                    stack[-1] -= x
                    x = 0
                else:
                    x -= stack[-1]
                    stack.pop()

    # number of layers + bottom ring
    if not stack:
        print(1)
    else:
        print(len(stack) + 1)

if __name__ == "__main__":
    solve()
```代码直接实现了栈模型。 每次浇筑都会附加一个新层。 每杯饮料都会首先小心地减少顶层，可能会依次去除多层。 最终的答案是由剩余层数加上基环得出的。 

一个常见的实现错误是在完全删除一层后忘记继续减法。 另一种方法是独立处理每个操作，而不维护部分层的持久性。

 ## 边缘情况

 一种重要的边缘情况是所有倒出的咖啡最终都被移走。 考虑：```
2
+10
-10
```处理后栈变空。 该算法正确输出 1，因为即使没有咖啡剩余，底部边界仍然算作一个环。 简单的“层数”方法会错误地输出 0。 

当饮料跨越多层时，会出现另一种边缘情况：```
3
+3
+4
-5
```堆栈一步步演化而来`[3, 4]`到`[2]`。 顶层被完全去除，下一层被部分减少。 堆栈大小正确减小，保留每个元素对应于仍然活动的层边界的不变性。 

第三个边缘情况是重复小量饮料，逐渐消耗一层：```
4
+5
-2
-2
-1
```顶层在消失之前经历了多次操作。 该算法正确地延迟弹出，直到剩余值达到零，确保不会过早删除层边界。
