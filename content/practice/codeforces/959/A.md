 ## 解决方案
 ## 问题理解

 游戏从一个整数值开始，两个玩家交替减少它。 轮到马哈茂德时，他只能减去不超过当前值的偶数正数。 轮到 Ehab 时，他只能减去同一范围内的奇数正数。 如果玩家在其回合中没有可用的合法减法，则该玩家立即失败。 

关键在于，游戏完全由允许走棋的平价结构决定，而不是由许多值中的任何策略选择决定。 每一步都会严格减少数量，因此游戏必须在有限的步数后终止，而最佳游戏减少为确定第一个玩家的起始位置是赢还是输。 

输入大小限制允许 n 最大为 10^9。 这立即排除了任何尝试探索博弈树状态的模拟，因为即使线性遍历直到 n 的所有状态也会太慢。 任何有效的解决方案都必须将游戏压缩为基于 n 属性的恒定时间决策。 

当 n 非常小时，会出现微妙的边缘情况。 例如，当 n = 1 时，Mahmoud 无法减去任何偶数，因此他立即失败。 当 n = 2 时，Mahmoud 可以减去 2，为 Ehab 留下 0，然后 Ehab 就没有可用的奇数步，因此 Mahmoud 获胜。 这些小案例表明，可用移动的奇偶性比 n 本身的大小更重要。 

另一个潜在的陷阱是假设两个玩家总是可以移动直到 n 变为 0。这是错误的，因为允许的奇偶性不对称地限制了可用的移动，因此一个玩家可能会比预期更早地被迫进入失败位置。 

## 方法

 一种直接的方法是模拟游戏。 在每一步中，我们都会尝试当前玩家的所有有效动作，递归地评估结果状态，并确定是否有任何动作会导致对手失败。 这是从 0 到 n 的状态线上的标准极小极大游戏。 

这在概念上是有效的，因为游戏是有限的和确定性的。 然而，从任何状态 n，Mahmoud 可以尝试最多 n/2 个偶数移动，而 Ehab 最多可以尝试 (n+1)/2 个奇数移动。 每次移动都会减少状态，但会创建一个新分支。 在最坏的情况下，递归会重复探索大部分状态，如果不使用记忆化，则会导致指数行为，即使使用记忆化，也至少会导致线性行为。 由于 n 可以是 10^9，所以即使是 O(n) 也是不可能的。 

关键的观察结果是允许的移动结构将游戏压缩为简单的平价条件。 Mahmoud 仅当存在至少一个偶数 ≤ n 时才能移动，而这种情况恰好在 n ≥ 2 时发生。每当 n ≥ 1 时，Ehab 始终可以移动，因为 1 始终是有效的奇数减法。 这些约束之间的相互作用表明，唯一有意义的区别是 n 在开始时是偶数还是奇数。 如果 n 是偶数，Mahmoud 可以采取保留结构的棋步，迫使 Ehab 陷入无法继续获胜的局面。 如果 n 是奇数，马哈茂德立即无法做出完全稳定优势的偶数棋，而埃哈卜控制了局势。 

这将整个游戏简化为检查 n 的奇偶性。

 ## 算法演练

1. 读取整数n，它代表游戏的初始状态。 
2. 检查n 是偶数还是奇数，因为只有奇偶性才能决定Mahmoud 是否先手获胜。 
3. 如果 n 是奇数，则得出结论 Mahmoud 无法采取留下有利结构的棋步，因此 Ehab 立即获胜。 
4. 如果n是偶数，Mahmoud可以先减去2，为Ehab留下一个奇数，之后Mahmoud总是可以以保持对平价优势的控制的方式回应Ehab的强制奇数棋，因此Mahmoud获胜。 

### 为什么它有效

 游戏简化为跟踪哪个玩家被迫首先面对不存在合法移动的位置。 马哈茂德被限制为偶数动作，这实际上意味着当起始状态为奇数时他会失去控制，因为他无法立即以保持平衡减少模式的方式做出反应。 当 n 为偶数时，Mahmoud 总是可以首先还原到奇数状态，之后 Ehab 被迫进入不利的奇偶位置。 由于每一步棋都会严格减少 n 并且奇偶校验在最佳玩法下交替出现，因此初始奇偶校验完全决定了哪个玩家最终会被阻止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

if n % 2 == 1:
    print("Ehab")
else:
    print("Mahmoud")
```该解决方案读取单个整数并立即检查其奇偶校验。 不需要状态跟踪或模拟，因为游戏崩溃为二元分类。 模运算是常数时间，打印结果即可最终决定。 

唯一微妙的实现细节是确保对 n = 1 和 n = 2 进行正确的奇偶校验处理。这些已经包含在相同的条件中，因为 1 是奇数，2 是偶数，与已知结果匹配。

 ## 边缘情况

 当 n = 1 时，算法检查奇偶校验并输出 Ehab。 这与马哈茂德根本没有平步的事实相符，因此游戏在第一回合就立即结束。 

对于 n = 2，算法输出 Mahmoud。 追踪逻辑，n 是偶数，因此 Mahmoud 被宣布为获胜者，这与他减去 2 并迫使 Ehab 进入 n = 0 的移动顺序一致，没有合法的奇数减法。 

对于非常大的 n（例如 10^9），计算保持相同，因为仅计算模 2，并且迭代不依赖于幅度。
