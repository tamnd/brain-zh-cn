 ## 解决方案

 ## 问题理解

 我们得到一个整数数组$a$，我们必须构造另一个数组$b$在三个同时约束下具有相同的长度。 第一的，$b$按字典顺序不得小于$a$，这意味着我们从左到右进行比较，并且它们不同的第一个位置必须满足$b_i \ge a_i$。 其次，每一个要素$b$必须至少为 2。第三，中的所有元素$b$必须成对互质，因此不允许两个位置共享任何质因数。 

第二个条件本身的限制性并不大，但与成对互质相结合，它会产生强大的结构约束：每个素数最多只能出现在整个数组中的一个位置。 这意味着每一个$b_i$本质上是“分配”一组与所有其他素数不相交的素数，其值是它们的乘积。 

字典序约束耦合了所有位置：我们不能独立地为每个索引选择最小有效数字，因为增加早期元素可能会迫使以后采用完全不同的配置。 

和$n \le 10^5$和$a_i \le 10^5$，任何尝试成对测试 gcd 关系或每个位置重复测试因子数的解决方案都会太慢。 即使是通过每步试除来检查素性或互质性的天真贪婪方法也会变得$O(n \sqrt{A})$，这已经是边缘，但更重要的是错过了素数重用的全局结构。 

当早期的选择不必要地阻碍了后来的位置时，就会出现微妙的失败情况。 例如，如果我们贪婪地分配$b_1 = a_1$并且它包含许多素数，我们稍后可能会人为地强制进行大跳跃，即使稍微大一点$b_1$可以使用更少或不同的素数并允许更小的未来值。 

另一种失败模式是“选择与之前的数互质的最小数≥a_i”。 这在本地有效，但在全局范围内会破坏：一个数字可能在本地有效，但会消耗一个稀有素数，以保持后面的数字较小。 

关键的困难在于素数才是真正的资源，而不是整数本身。 

## 方法

 一个蛮力的想法是从左到右处理数组，并在每个位置尝试增加从$a_i$直到我们找到一个与所有先前选择的值互质的数字。 每次检查都需要针对所有早期元素验证 gcd，这会花费$O(n)$每个候选人。 在最坏的情况下，如果值不断在小质数上发生冲突，我们可能会在每个位置尝试许多候选者，从而导致类似的情况$O(n^2)$gcd 检查，每个 gcd 是$O(\log A)$。 这显然无法扩展到$10^5$。 

关键的观察结果是，成对互质相当于将每个质数最多分配到一个位置。 一旦使用了素数，所有其他位置都将被全局禁止。 这表明我们应该从“未使用素数的全局池”的角度来思考，并只为每个位置分配一个新素数的乘积。 

现在字典序约束将问题变成一阶差分问题。 我们想要最早的索引，我们可能需要超过$a_i$，但我们也希望最终的数组最小。 这强烈暗示了一种贪婪的结构：尝试保留$b_i = a_i$只要有可能，但如果我们无法仅使用未使用的素数来分配有效值，则必须以受控方式增加它。 

标准技巧是预先计算所有数字的最小素因子（SPF）$10^5$。 然后每个整数都可以快速分解。 我们维护一个全球“已用素数”集。 对于每个位置，我们尝试构建$b_i$开始于$a_i$：我们分解它，如果它的所有素数都未被使用，我们接受它并将它们标记为已使用。 如果不是，我们必须找到大于的最小整数$a_i$其素因数均未使用。 

这将每个位置减少为对整数的约束搜索，但至关重要的是，阻塞素数是稀疏的，并且在实践中搜索速度很快，因为每个增量都会快速消除冲突，并且我们从不重复使用素数。

 ## 算法演练

 我们预处理最小的质因数$10^5$。 这允许对任何候选数进行快速因式分解。 

我们还维护一个布尔数组或集合，指示哪些素数已经在之前的位置中使用过。 

我们从左到右处理数组，总是尝试为每个位置构造符合两个约束的最小有效值。 

1. 对于索引$i$，从$x = a_i$。 
2. 因式分解$x$使用SPF。 如果有任意素因数$x$已经使用了，$x$无效。 
3. 如果有效，则分配$b_i = x$，并将其所有主要因子标记为已使用。 
4. 如果无效，则增加$x$直至其生效。 每个增量都会重复因式分解和检查。 
5.一旦有效$x$找到，将其修复为$b_i$并继续。 

重要的结构性决定是我们永远不会重新审视之前的立场。 一旦一个位置被固定，它的素数就会被永久保留，这确保了以后的选择不会破坏之前的有效性。 

为什么它有效与贪婪的最小不变量有关。 在每个索引处$i$，在给定先前索引的固定选择的情况下，我们选择不违反全局素数约束的最小可能值。 由于字典顺序仅取决于第一个不同的位置，因此位置的任何增加$i$如果不存在有效的分配，这是不可避免的$a_i$。 一旦我们过去$a_i$，我们再次选择最小的可行数字，确保以后不会出现人为通货膨胀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 100000

spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = set()
    while x > 1:
        p = spf[x]
        res.add(p)
        while x % p == 0:
            x //= p
    return res

n = int(input())
a = list(map(int, input().split()))

used = set()
b = []

for ai in a:
    x = ai
    while True:
        primes = factorize(x)
        ok = True
        for p in primes:
            if p in used:
                ok = False
                break
        if ok:
            for p in primes:
                used.add(p)
            b.append(x)
            break
        x += 1

print(*b)
```SPF 表构建一次，使得每次分解都可以在接近对数的时间内完成。 然后，贪婪循环尝试从以下位置开始的候选者：$a_i$并且仅在之前未使用过任何质因数的情况下才接受数字。 

关键的实现细节是我们重新计算每个候选者的因式分解。 虽然这可能看起来很昂贵，但每次拒绝都是由于遇到已经使用的素数而引起的，并且一旦使用素数，它就不会再出现在未来的有效数字中，因此冲突很快就会减少。

 ## 边缘情况

 一种边缘情况是许多早期数字共享小素数。 对于像这样的输入`2 4 6 8`，第一个值消耗素数2，然后4和6都严重冲突，强制跳转。 该算法通过跳过候选者直到找到新的素数结构来正确处理这个问题，最终产生如下序列`2 3 5 7`。 

另一个边缘情况是当所有输入都已经是成对互质素数时。 在这种情况下，每个数字都会立即被接受，因为最初不存在使用过的素数，并且算法不执行增量。 为了`2 3 5 7 11`，每一步只是标记一个新的素数并继续。 

最后的边缘情况是一条长链，其中早期复合材料强制重复增量。 例如，`4 6 8 9 10`重复地在素数 2、3 和 5 上发生碰撞。该算法会最小化每个位置的升级，并且由于每次成功的分配都会永久删除素数，因此搜索空间会稳步缩小，从而防止无限制的重试。
