 ## 解决方案
 ## 问题理解

 我们有两个整数，`s`和`k`。 任务是表达`s`作为取自不同数字的总和`k`-博纳奇序列。 

该序列的行为类似于斐波那契，但不是将前两个值相加，而是每一项都是前一项的总和`k`条款。 开头很特别。 第一个`k - 1`条款是`0`， 这`k`- 第一项是`1`，并且每个后来的值都是从前一个值构建的`k`价值观。 

例如，当`k = 2`，序列变为：```
0, 1, 1, 2, 3, 5, 8, ...
```什么时候`k = 3`，则变为：```
0, 0, 1, 1, 2, 4, 7, 13, ...
```我们必须打印至少两个不同的序列值，其总和等于`s`。 

限制看似巨大。 两个都`s`和`k`可以达到`10^9`。 这排除了任何直接依赖于`k`大小的数组或动态规划`s`。 关键的观察结果是序列在前几项之后呈指数增长。 即使对于小`k`，下面生成的值的数量`10^9`很小，通常低于 50。这意味着我们可以对生成的序列进行贪婪处理。 

一个微妙的点是序列开头存在许多零。 该问题需要不同的数字，而不是不同的位置。 这意味着即使序列包含许多零，我们也不能使用多个零。 粗心的实现可能会输出两个零，这违反了唯一性。 

考虑这个输入：```
1 3
```该序列开始为：```
0, 0, 1, 1, 2, ...
```错误的解决方案可能会尝试：```
0 0 1
```但数字并不明显。 有效答案是：```
0 1
```使用贪心选择时会出现另一个容易出现的错误。 如果我们贪婪地取最大的可用值，并在剩余总和变为零时停止，那么我们最终可能只会得到一个选定的数字。 该问题明确需要至少两个数字。 

例如：```
5 2
```自从`5`本身是一个斐波那契数，天真的贪心给出：```
5
```这是无效的。 我们需要类似的东西：```
0 2 3
```额外的零是此问题中使用的标准技巧，用于保证至少有两个不同的数字。 

## 方法

 蛮力的想法是生成所有`k`-bonacci 数字高达`s`，然后尝试每个子集，看看某个子集之和是否为`s`。 

这是有效的，因为生成的术语数量相当小。 甚至斐波那契数列也超过`10^9`大约 45 个学期后。 但子集枚举仍然变得不可行。 大约有 45 个可用数字，子集数量约为`2^45`，这在2秒之内是完全不可能的。 

序列结构赋予了更强的特性。 每个项都大于所有足够小的可用项的总和，其方式类似于斐波那契和泽肯多夫表示。 这意味着贪婪策略有效：反复取最大的`k`-bonacci数量不超过剩余值。 

为什么贪婪在这里成为可能？ 

递归使得序列在初始阶段之后单调增长。 更重要的是，每个数字都是前一个数字的总和`k`数字，因此采用最大的可用值可以在不妨碍未来建设的情况下尽可能多地删除剩余目标。 贪婪斐波那契分解背后的相同逻辑自然延伸到`k`-博纳奇数。 

剩下的问题是至少需要两个不同的数字。 如果贪婪只产生一个数字，那么它一定恰好是`s`本身。 在这种情况下，我们只需附加`0`，它始终可用并且不同于每个正数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^m) | O(2^m) | O(米) | 太慢了 |
 | 最佳 | O(平方米) | O(米) | 已接受 |

 这里`m`是生成的数量`k`-bonacci 数字高达`s`，这在实践中非常小。 

## 算法演练

 1. 生成所有不同的正值`k`-bonacci 数字高达`s`。 

该序列开始于`k - 1`零和一`1`。 每个下一个值等于前一个值的总和`k`价值观。 我们只关心以下值`s`，因为更大的数字永远无法参与分解。 
2. 按升序存储生成的值。 

在初始重复之后，序列变得严格递增，因此从最大到最小的贪婪处理很简单。 
3. 开始于`remaining = s`。 

我们将反复减去最大可能的未使用值。 
4、逆序遍历生成的数字。 

每当一个数最多时`remaining`，将其包含在答案中并从中减去`remaining`。 

这是标准的贪心子集构造。 由于序列增长很快，因此选择尽可能大的值永远不会妨碍完成。 
5. 继续直到`remaining`变为零。 

此时所选数字的总和恰好为`s`。 
6. 如果答案仅包含一个数字，请附加`0`。 

这处理以下情况`s`本身就是一个`k`-博纳奇数。 该问题需要至少两个不同的数字，并且`0`总是与任何正选择的值不同。 
7. 打印答案大小和数字。 

### 为什么它有效

 关键的属性是每个`k`-bonacci数等于前一个数的总和`k`数字。 由于这种增长结构，任何小于所选术语的剩余值仍然可以使用更小的术语来表示。 贪婪永远不会产生不可能的余数。 

在每一步，算法都保持不变，即当前余数仍然可以使用较小的未使用序列值来表示。 选择最大的有效项尽可能积极地减少余数，同时保留可表示性。 

最终调整为`0`保持正确性，因为加零不会改变总和，并且零与每个正数不同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s, k = map(int, input().split())

    # Build sequence:
    # [0, 0, ..., 0, 1]
    seq = [0] * (k - 1) + [1]

    window_sum = 1

    while True:
        nxt = window_sum

        if nxt > s:
            break

        seq.append(nxt)

        window_sum += nxt
        window_sum -= seq[-k - 1]

    # Keep only distinct positive values
    vals = sorted(set(x for x in seq if x > 0))

    ans = []
    rem = s

    for x in reversed(vals):
        if x <= rem:
            ans.append(x)
            rem -= x

    # Need at least two distinct numbers
    if len(ans) == 1:
        ans.append(0)

    print(len(ans))
    print(*sorted(ans))

if __name__ == "__main__":
    solve()
```序列生成使用滑动窗口和。 直接根据前一项计算每个新项`k`元素将花费`O(k)`每一步，当`k`很大。 相反，我们增量地维护当前的窗口总和。 

假设当前窗口包含最后一个`k`序列值。 下一个序列元素正是该总和。 添加新值后，我们通过添加新项并删除最旧的项来更新窗口。 

表达式：```
window_sum -= seq[-k - 1]
```很容易出错。 添加新值后，离开窗口的元素恰好是`k + 1`从最后开始的位置。 

初始序列包含许多重复项，尤其是零，有时甚至是重复的。 由于该问题要求不同的数字，因此我们在贪婪选择之前明确删除正值。 

贪婪阶段从最大到最小处理数字。 因为序列大小很小，所以简单的反向遍历就足够了。 

决赛`0`插入是一个小但重要的细节，可以避免无效的单元素答案。

    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

 ## 边缘情况

 考虑以下情况：```
1 3
```生成的序列开始：```
0, 0, 1, 1, 2, ...
```去重后，可用值变为：```
1, 2, ...
```贪心选择`1`，留下余数`0`。 由于仅选择了一个值，因此该算法会附加`0`。 

最终答案：```
0 1
```这避免了非法使用重复的零。 

现在考虑：```
5 2
```贪婪立即采取`5`，因为它与目标完全匹配。 如果没有最后的调整，答案将只有一个数字，违反了要求。 

该算法检测到这种情况并附加`0`，生产：```
0 5
```另一个棘手的场景非常大`k`， 例如：```
2 100
```该序列在很长一段时间内保持很小，因为每一项都对前 100 个元素求和，其中大部分最初为零。 

生成的正值很简单：```
1, 2
```贪心`2`，然后附加`0`因为只选择了一个值。 

滑动窗口实现可以有效地处理这个问题，而无需为每个生成的项迭代 100 次。
