 ## 解决方案
 ## 问题理解

 我们在平面上得到一组点，没有重复点，也没有三个共线。 我们想要从这些点形成多边形，其顶点是从集合中选择的。 

有效的多边形必须是简单的，这意味着它的边除了连续的顶点之外不相交。 此外，给定集合中的每个点都必须位于多边形内部或其边界上。 因此需要多边形“覆盖”所有输入点。 

在所有这些多边形中，我们考虑顶点数最少的多边形，并将其称为大小$|R|$。 任务不是建造$R$，但是要计算存在多少个有效多边形，其顶点数最多为$|R| + 1$。 

几何条件“所有点都位于边界内部或边界上”意味着任何有效的多边形都必须是点集的超集包围。 由于没有三个点共线，并且我们有一个简单的多边形要求，因此任何有效的多边形都必然是凸包加上可能以非最佳顺序位于包结构上的一些冗余顶点，但仍保持简单性。 

关键的隐藏结构是任何最佳解决方案都必须仅使用凸包上的点，因为在不违反简单性或极小性约束的情况下，任何内部点都不能成为简单封闭多边形的顶点。 

集合的凸包，我们表示$H$，因此是中心。 让$m = |H|$。 可能的最小多边形$R$正是凸包本身，所以$|R| = m$。 

任务变成计算所有使用点的简单多边形$H$（可能还有内部点，但这些不可能作为顶点）其顶点数为$m$或者$m+1$，并且仍然形成一个包含所有点的有效简单多边形。 

自从$n \le 2000$，我们负担得起$O(n^2 \log n)$或者$O(n^2)$几何，但所有子集上的任何立方体都是不可能的。 

常见的失败情况是假设凸包点的每个排列都是有效的。 例如，对于正方形，只有顺时针和逆时针遍历才是有效的哈密顿循环； 大多数排列都会产生自交集。 另一种微妙的情况是假设插入一个额外的顶点总是保持简单性，这是错误的，除非它尊重局部凸性约束。 

## 方法

 一个天真的想法是处理大小顶点的每个子集$m$或者$m+1$，生成所有排列，并测试多边形是否简单且包含所有点。 即使限制在船体点上，这也已经是$(m!)$排列，即使对于$m = 10$。 

更结构化的强力方法是修复循环排序并测试简单性和包含性。 这仍然需要检查每个排列的交集条件，从而导致$O(m^2)$总体而言，每个排列和阶乘增长都远远超出了限制。 

关键的观察结果是，任何包含所有点的有效多边形都必须以尊重凸包的圆形顺序的方式排序其顶点，除了可能在保持简单性的同时产生单个局部偏差的一个“额外”顶点。 因此，问题不再是任意排列，而是简化为沿凸包选择最多具有一个结构偏差的序列。 

这将问题转化为计算有效的循环排序，这些循环排序要么恰好是凸包顺序，要么是在遍历中有效复制一个顶点的版本，从而生成一个多边形$m+1$vertices while still tracing the hull boundary.

 因此，我们将问题简化为组合计算有效方法，以保持船体循环完整或通过以保留凸性和简单性的方式插入顶点来“分割”一个船体边缘。 由于该集合处于一般位置，因此每个这样的插入对应于唯一的结构配置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | Brute Force over permutations |$O(m! \cdot m^2)$|$O(m)$| 太慢了 |
 | 凸包+结构计数|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 使用单调链或类似方法计算点集的凸包。 这给出了大小的有序循环$m$。 最小多边形$R$正是这个船体。 
2. 请注意，任何有效的多边形必须仅使用外壳顶点。 内部点不能出现，因为它们要么违反简单性，要么产生不必要的绕道，增加顶点数而不改变覆盖范围。 
3. 一个多边形$|R|$顶点恰好是两个方向之一的船体循环。 这贡献了 2 个有效的多边形。 
4. 考虑多边形$|R| + 1$顶点。 这样的多边形必须精确地重复一个结构“转弯”，这意味着它有效地取代了单个船体边缘$(v_i, v_{i+1})$绕道通过另一个船体顶点$v_k$同时保持订单的一致性。 
5. 对于每个船体顶点$v_k$，我们考虑将其插入船体边缘之一，以保留凸度。 因为所有点都处于一般位置，所以有效性减少为检查是否$v_k$位于与之间的遍历方向一致的角扇区中$v_i$和$v_{i+1}$。 
6. 我们计算对于每个外壳边，在不违反循环顺序约束的情况下可以插入多少个内部外壳顶点。 每个有效的插入恰好定义一个不同的简单多边形。 
7. 对所有有效插入求和，并将两个基本船体方向相加以获得最终答案。 

### 为什么它有效

 凸包定义了唯一的最小包围圈。 任何包含所有点的简单多边形都必须以循环顺序追踪外壳边界，否则它将要么将外壳顶点留在外部，要么强制自相交。 引入一个额外的顶点对应于精确地细化一个边界转换而不改变全局循环顺序。 由于没有三个点共线，因此每个可行的细化都是独立的，并且由角度顺序约束唯一确定，确保不会重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def convex_hull(points):
    points = sorted(points)
    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)
    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)
    return lower[:-1] + upper[:-1]

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    hull = convex_hull(pts)
    m = len(hull)

    if m == 1:
        print(1)
        return
    if m == 2:
        print(2)
        return

    # base: two orientations of convex hull
    ans = 2

    # count possible single-vertex insertions
    for i in range(m):
        a = hull[i]
        b = hull[(i + 1) % m]
        for k in range(m):
            if k == i or k == (i + 1) % m:
                continue
            p = hull[k]
            if cross(a, b, p) < 0:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先构建凸包，因为每个有效的多边形都受限于其边界结构。 外壳按逆时针顺序存储，这使我们能够一致地推理边缘。 

答案初始化为 2，对应于遍历船体的两个可能的循环方向。 

然后，我们尝试考虑具有一个额外顶点的多边形。 对于每个有向船体边缘，我们测试插入另一个船体顶点是否保留相对于遍历方向一致的左转结构。 这是使用叉积符号条件实现的，这确保插入的顶点不会破坏凸排序。 

每个成功的配置都会被计数一次，因为它与唯一的边和插入的顶点对相关联。

 ## 边缘情况

 三角形是最小的可能的船体。 该算法计算船体尺寸$m = 3$，将基本答案设置为 2，并且找不到有效的插入，因为任何添加的顶点都会违反严格的循环顺序要求。 输出仍然是 2，匹配仅有的两个方向。 

凸四边形引入了第一个重要的插入可能性。 Each edge is tested against the remaining two vertices, and valid cross-product conditions identify exactly the configurations that preserve left-turn consistency. 每对有效的多边形都会贡献一个额外的多边形，并且算法会正确地累积它们而不会重复。
