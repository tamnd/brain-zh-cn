 ## 解决方案
 ## 问题理解

 给定一棵树，我们想要“切割”一些边，以便剩余的连接组件都具有非常特定的大小：每个组件必须恰好包含`k`或者`k + 1`顶点。 每个有效答案都是由我们删除的边集定义的，如果两个答案删除不同的边集，即使结果分区看起来相似，它们也是不同的。 

因此，底层对象不仅仅是顶点的分区，而且是大小受到严格约束的连接子树的分区。 因为输入图是一棵树，所以删除一条边总是会将一个组件分成两部分，因此任何有效的解决方案都与选择一组将树“分隔”为允许的块的边完全对应。 

约束允许最多`n = 10^5`每个测试用例，总计`3 × 10^5`。 这立即排除了任何考虑边缘子集或尝试显式模拟切割的解决方案。 边缘中的任何指数甚至二次`n`是遥不可及的。 树的结构强烈建议采用基于根的动态规划解决方案，该解决方案处理每条边恒定的次数。 

天真的思维的一个微妙的失败案例是假设我们可以在遍历时贪婪地形成组件。 例如，在 6 个节点的链中`k = 2`，尽快关闭组件的贪婪策略可能会产生像这样的分区`[1,2],[3,4],[5,6]`，但不同的早期决策可能会在以后造成死胡同，因为子树选择是耦合的。 另一个问题是假设每个子树独立决定其分区大小，这是失败的，因为子树是向上连接还是闭合取决于组件大小的全局一致性。 

## 方法

 暴力解释很简单：尝试边缘的每个子集，计算连接的组件，并检查每个组件是否具有大小`k`或者`k + 1`。 这是正确的，因为它直接测试定义。 然而，边缘子集的数量为`2^(n-1)`，甚至评估每个子集的连接性也会花费线性时间，导致指数爆炸，使得这种方法不可能超越小树。 

关键的观察结果是，树中的切割边会产生分层结构：每个组件本身都是一棵子树，并且每个决策都是连接节点与其子节点之一的边的本地决策。 我们不需要选择任意边子集，而是可以对树进行生根，并根据子树结构决定是否剪切或保留每条边。 这将问题转化为计算自下而上“组装”组件的有效方法。 

主要困难在于，当我们处理一个节点时，我们必须知道当前正在形成的组件有多大，因为只有当它的大小恰好达到时，组件才能被最终确定`k`或者`k + 1`。 这导致树 DP，其中状态跟踪当前向上延伸的打开组件的大小。 

每个子树以两种根本不同的方式做出贡献。 它要么在子树内完全独立（意味着其父级的边缘被切断），要么合并到父级的开放组件中（意味着它向上贡献节点）。 这种二分法允许对子项进行结构化的 DP 过渡，类似于背包合并。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解边缘子集 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 组件大小状态的树 DP | O(n·k) | O(n·k) | O(n·k) | O(n·k) | 已接受 |

 ## 算法演练

 我们将树植根于任意节点，例如`1`。 对于每个节点`u`，我们定义两种类型的信息：`dp[u][s]`是子树的划分方式的数量`u`这样`u`属于当前大小的“开放”组件`s`。 这个开放组件尚未最终确定，并将扩展到父级。 

我们还维护`closed[u]`，完全划分子树的方法数量`u`这样`u`不连接到其父级，这意味着`u`属于尺寸的完整组成部分`k`或者`k + 1`在其子树内。 

我们按后序处理节点，以便子节点已经在其父节点之前计算。 

1.初始化各个节点`u`以便`dp[u][1] = 1`。 这代表仅由以下部分组成的组件`u`在合并任何子项之前。 
2. 对于每个孩子`v`的`u`，我们将其 DP 合并为`u`。 我们创建一个临时 DP 数组`u`并为每个状态处理两种可能性。 
3.第一个可能性是削减优势`(u, v)`。 在这种情况下，子树`v`变得完全独立，所以我们乘以`closed[v]`然后离开`dp[u]`不变。 这对应于治疗`v`因为内部已经形成了完整的组件。 
4.第二种可能性是连接`v`到当前打开的组件`u`。 在这种情况下，我们采用以下状态：`v`本身向上连接，我们合并大小：如果`u`目前有开放尺寸`a`和`v`贡献一个开放的尺寸`b`，新的状态变为`a + b`，只要不超过`k + 1`。 
5. 处理完所有子节点后，我们计算`closed[u]`通过检查是否打开组件`u`可以最终确定。 如果`dp[u][k]`或者`dp[u][k+1]`存在，这些对应于植根于的有效已完成组件`u`，所以我们将它们添加到`closed[u]`。 
6.整棵树的答案是`closed[root]`。 

正确性取决于结构不变量：在任何节点`u`，其子树的每个有效部分配置都由包含的开放组件的大小来完全描述`u`是，并且子树的所有其他部分已经有效地封闭为大小的组件`k`或者`k + 1`。 在合并过程中，每个边缘决策都会被捕获一次，无论是作为剪切（关闭子子树）还是作为合并（扩展开放组件）。 因为组件只有在达到大小时才最终确定`k`或者`k + 1`，任何无效组件都不能提前关闭或超出允许的范围。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    sys.setrecursionlimit(10**7)

    parent = [0] * (n + 1)
    order = []

    stack = [1]
    parent[1] = -1

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp = [None] * (n + 1)
    closed = [0] * (n + 1)

    for u in reversed(order):
        dp_u = [0] * (k + 2)
        dp_u[1] = 1

        for v in g[u]:
            if v == parent[u]:
                continue

            dp_v = dp[v]
            new_dp = [0] * (k + 2)

            for su in range(1, k + 2):
                if dp_u[su] == 0:
                    continue

                # cut edge u-v
                new_dp[su] = (new_dp[su] + dp_u[su] * closed[v]) % MOD

                # merge v into u component
                if dp_v is not None:
                    for sv in range(1, k + 2 - su):
                        if dp_v[sv]:
                            new_dp[su + sv] = (new_dp[su + sv] +
                                               dp_u[su] * dp_v[sv]) % MOD

            dp_u = new_dp

        dp[u] = dp_u
        closed[u] = (dp_u[k] + dp_u[k + 1]) % MOD

    print(closed[1])

T = int(input())
for _ in range(T):
    solve()
```该代码首先构建一个迭代遍历顺序，以便在父级之前处理子级。 对于每个节点，DP 数组跟踪包含该节点的开放组件的不同大小存在多少种方式。 合并步骤通过将每个子项切断或将其附加到开放组件中来仔细组合每个子项，这正是树分区中的两种结构可能性。 

每个节点的最终值是从开放组件有效可完成的状态中提取的，这意味着其大小达到任一允许的目标。 

一个微妙的实现细节是我们将 DP 大小限制为`k + 1`，因为任何更大的组件都是无效的并且永远不需要。 这使得转换受到限制。 

## 工作示例

 ### 示例 1

 考虑一棵小树`1 - 2 - 3 - 4`和`k = 2`。 

我们从叶节点开始，每个叶节点只有`dp[leaf][1] = 1`。 

在节点处`2`，结合子`3`，我们可以保留`3`将其分开或合并。 DP 在`2`演变如下：

 | 节点| dp[2][1] | dp[2][1] | dp[2][2] | dp[2][2] | 已关闭[2] |
 | --- | --- | --- | --- |
 | 初始化| 1 | 0 | 0 |
 | 3 后 | 1 | 1 | 1 |

 这里`closed[2] = dp[2][2] = 1`，表示根于的子树`2`可以形成有效的尺寸分量`2`。 

这展示了 DP 如何在本地捕获剪切和合并选择，同时保持全局一致性。 

### 示例 2

 取一棵以星形为中心的树`1`连接到`2,3,4`， 和`k = 2`。 

每片叶子贡献大小`1`。 在节点处`1`，我们将孩子们一一组合起来。 合并两片叶子后，我们达到了有效的大小`2`，可以将其关闭，而剩余的叶子则被切成自己的组件。 

DP表演变为：

 | 步骤| dp[1][1] | dp[1][1] | dp[1][2] | dp[1][2] | dp[1][3] | dp[1][3] |
 | --- | --- | --- | --- |
 | 开始 | 1 | 0 | 0 |
 | 2 之后 | 1 | 1 | 0 |
 | 3 后 | 1 | 2 | 1 |
 | 4 后 | 1 | 3 | 3 |

 仅状态`2`和`3`有助于有效闭包，对应于大小的组成部分`k`或者`k+1`。 

这显示了分组叶子的多种组合如何产生不同的有效边缘切割集。 

## 复杂度分析

 | 测量| 复杂性 | 说明|

 ## 边缘情况

 一个关键的边缘情况是当`k`接近于`n`。 在一棵大小的树上`n = k`，唯一有效的配置是保持整个树完整（如果它已经匹配）`k`，或以其他方式失败。 民主党自然会处理这个问题，因为只有国家`dp[root][n]`存在并且只有匹配才有效`k`或者`k + 1`。 

另一种情况是当树是一条线并且`k = 1`。 每个节点都必须成为自己的组件，这意味着每条边都被切割。 DP 退化为重复选择“剪切”过渡，并且所有合并过渡都是无效的，因为它们会超出允许的大小。 

最后一个微妙的情况是多个子项以不同的顺序合并。 DP 与顺序无关，因为它对称地聚合子级上的所有可能性，确保任何合并序列对最终计数仅贡献一次。
