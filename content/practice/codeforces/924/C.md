 ## 问题理解

 我们得到了连续几天的一系列观察结果。 每一天都对应一个水位，随着时间的推移，阿尔卡迪会在他迄今为止看到的不同水位上留下痕迹。 如果水位重复，则不会添加新标记。 

白天`i`, Arkady 报告一个值`m_i`，这是严格高于当前水位的现有标记数。 由此看来，当天严格低于水位的标记数是有一定价值的`d_i`。 仅当出现新的水位时，标记的结构才会演变，因为只有那时标记集才会增长。 

任务不是重建精确的水位，而是选择匹配所有约束并最小化所有约束的不同标记的有效演化`d_i`。 

关键的困难在于，水位相对于现有标记的位置决定了有多少标记位于其上方和有多少标记位于其下方，并且尽早引入新标记会改变所有未来的贡献。 

约束条件`m_i < i`意味着在这一天`i`，总是有足够的先前“槽”来放置水位，以便准确地`m_i`标记位于其上方。 这保证了可行性，但并没有消除我们选择随着时间的推移引入多少不同标记的模糊性。 

天真的尝试可能会尝试模拟何时引入新标记的所有可能选择。 然而，即使对于`n = 10^5`，“创建标记”和“不创建标记”之间的分支会导致指数行为。 

当未来值`m_i`显着跳跃。 例如，如果`m`突然增加，过多地延迟标记创建导致以后无法实现该配置。 因此，贪婪的政策必须在延迟标记创建与确保未来可行性之间取得平衡。 

## 方法

 直接模拟方法明确地维护一组标记，并尝试每天分配与`m_i`。 每天，人们都会决定是否引入新标记或重复使用现有配置。 这很快就会呈指数增长，因为每天决策空间都可能加倍。 

关键的观察是，影响可行性的唯一因素是每个时间点存在多少个标记，而不是它们的确切位置。 一旦我们确定了当天的分数数量`i`，表示为`k_i`，水位总是可以适当放置，只要`k_i ≥ m_i + 1`。 

关键的限制是`k_i`每天增加的数量不能超过 1，因为每次观察最多可以添加 1 个新标记。 这引入了“速度限制”，限制了我们达到更高所需值的速度。`k_i`。 

因此，不要只看当前的需求`m_i`，我们还必须确保我们仍然能够达到未来的要求。 这导致了最小可行的贪婪构造`k_i`顺序。 

我们维持`k_i`作为当天可达到的最少分数`i`使得所有未来的约束仍然可以满足，然后计算贡献`d_i`从它。

 ## 算法演练

 1. 根据未来的限制，而不仅仅是当前的限制，计算每天所需的最少分数。 我们的推理是，分数每天最多只能增加 1 个分数，因此，如果未来的一天需要许多分数，那么之前的日子必须已经支持该增长率。 
2. 每天`i`，确定最小可行标记数`k_i`保证未来的所有日子`j ≥ i`仍能达到`m_j`。 这确保我们永远不会“落后”未来的要求。 
3.一次`k_i`是固定的，水位以下的标记数唯一确定为`d_i = k_i - 1 - m_i`，因为其中`k_i`总分，准确`m_i`除当前水平外，其余均位于上方。 
4. 总和`d_i`贯穿所有日子。 

### 为什么它有效

 标记的数量是影响未来可行性和当前成本的唯一状态。 任何有效的构造都对应于某个序列`k_i`每一步最多增加 1 并且始终满足`k_i ≥ m_i + 1`。 

在所有这样的序列中，选择尽可能小的`k_i`每一步都最小化每个前缀的贡献`k_i - 1`，这直接最小化了总和`d_i`。 任何更大的选择`k_i`永久性地增加未来成本而不提高可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = list(map(int, input().split()))

    k = [0] * n

    # backward constraint: ensure feasibility of future growth
    suf = float("-inf")

    # we compute k from right to left with growth constraint
    for i in range(n - 1, -1, -1):
        suf = max(suf, m[i] - i)
        k[i] = suf + i + 1

    # enforce growth limit k[i] <= k[i-1] + 1
    for i in range(1, n):
        if k[i] > k[i - 1] + 1:
            k[i] = k[i - 1] + 1

    ans = 0
    for i in range(n):
        ans += (k[i] - 1 - m[i])

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先使用表达式构建一个向后看约束`m[i] - i`，它反映了未来的日子相对于引入新标记的剩余时间的要求有多高。 这产生了一个基线要求`k[i]`。 由于标记每一步只能增加 1，因此我们会强制执行前向修正，以确保没有任何一步超过此增长率。 

最后，每天的贡献直接根据总分、高于分数和低于分数之间的关系计算。

 ## 边缘情况

 一天的最小投入总是产生零成本，因为不存在先前的标记并且不可能进行水下贡献。 

严格递增`m_i`序列迫使算法每天增加标记数量。 计算出的`k_i`线性增长，并且贡献保持为零，因为水位始终位于最顶层的可行配置。 

具有较大跳跃的序列`m_i`演示了为什么反向传播是必要的。 如果不预测未来的需求，贪婪的仅向前策略将低估所需的增长并产生不可行的配置。 

该算法处理这些情况是因为`k_i`受到未来需求和一步增长限制的限制，确保每个前缀的可行性，同时保持最小的累积规模。
