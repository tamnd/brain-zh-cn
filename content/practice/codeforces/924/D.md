 ## 解决方案

 ## 问题理解

 每个平面都从一条直线上的某个坐标开始，并向原点移动。 位置和速度的符号条件保证在没有风的情况下每架飞机最终都会到达零点。 单个全局风值被添加到所有速度中，使每架飞机的速度改变相同的量。 根据风向，每架飞机到达原点的时间都会发生变化。 

对于任意一对飞机，我们想知道在固定的区间内是否存在至少一个风值$[-w, w]$使得两架飞机在完全相同的时间到达原点。 我们不需要对不同的对使用相同的风，只有每对的存在才重要。 

关键量是飞机的到达时间$i$在风下$v$，即$t_i(v) = \frac{x_i}{v_i + v}$。 当这两个有理表达式对于同一平面相等时，两个平面同步$v$，还有那个$v$还必须保持两个平面在物理上有效，这意味着两个平面仍然向原点移动。 

输入大小强制$O(n \log n)$或类似的解决方案。 和$n = 10^5$， 任何$O(n^2)$成对检查立即不可行，因为它需要大约$10^{10}$评价。 甚至一个$O(n \sqrt{n})$实际中该方法太大了。 

幼稚的实现通常会在两个微妙的方面失败。 首先，它计算使一对飞机相等的风值，但忘记检查两个飞机是否仍然在该风下到达原点。 其次，它计算相等的风值，但忽略它们是否落在内部$[-w, w]$，导致仅在不可能的风力条件下相交的对的计数过多。 

例如，两架飞机可能有有效的相交风$v = 10^9$，但如果$w = 1$，该对不能被计算在内。 另一种失败情况是计算出的风产生一个分母$v_i + v$改变符号，意味着即使代数等式仍然成立，平面也永远不会到达原点。 

## 方法

 直接方法检查每对飞机，计算使它们的到达时间相等的风值，并验证可行性。 平等条件$$\frac{x_i}{v_i + v} = \frac{x_j}{v_j + v}$$可以明确地求解，为每对给出唯一的候选风值。 这在数学上是正确的，但是计算和验证所有对的成本是$O(n^2)$，这对于$10^5$飞机。 

关键的见解是每一对最多贡献一个候选风值，并且所有约束都可以重写为不等式$(x_i, v_i, x_j, v_j)$。 我们没有直接考虑时间相等性，而是将条件转换为仅依赖于变换空间中的相对顺序的比较。 

经过代数简化后，出现了两个事实。 一、平等风$v^*$是四个参数的有理式。 其次，可行性条件分为速度和线性约束的单调比较，涉及$w$。 这种结构允许我们在一个维度上使用芬威克树对平面进行排序并计算有效对，同时扫描另一个维度。 

我们避免显式枚举对。 相反，我们按速度排序顺序处理平面，并且对于每个平面，我们计算有多少较早的平面满足由风边界和等时间条件引起的变换后的不等式约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 变换扫掠 + Fenwick 树 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们重写条件，使得每一对$(i, j)$可以使用排序关系加上从风间隔导出的两个线性约束来检查。 

### 1. 将约束拆分为可比较的形式

 根据相等条件和风的可行性，我们推导出一对仅在以下情况下有效：

 - 平等风$v^*$在于$[-w, w]$- 两架飞机都在风的作用下继续向原点移动
 - 到达时间之间的相等条件成立

 第一个条件变为线性不等式$(x_i, v_i, x_j, v_j)$。 第二个条件简化为之间的比较$v_i$和$v_j$，仅取决于平面从原点的哪一侧开始。 

### 2. 降低订购条件的可行性

 简化后，可行性约束意味着对于任何有效的对，$v_i$和$v_j$必须满足由符号确定的方向条件$x_i$。 这使我们能够将速度视为可排序的键。 

### 3. 按速度对平面进行排序

 我们对所有飞机进行排序$v_i$。 这确保了在处理平面时，所有先前处理的平面都满足派生约束之一中的一致排序。 

### 4. 将剩余约束转换为范围计数

 风间隔约束和等式约束一起简化为线性不等式，涉及$(x_i, v_i)$和$(x_j, v_j)$。 修复当前平面后，这将成为先前平面上的一个条件，可以通过该平面上的 Fenwick 树进行检查$x$-方面。 

### 5. 扫一扫并数数

 我们按照速度的排序顺序迭代平面。 对于每个平面，我们查询有多少个早期平面满足导出的不等式约束。 然后我们将当前平面插入 Fenwick 结构中。 

### 为什么它有效

 在速度排序中处理该对的较晚端点时，每对都被精确计数一次。 该变换确保原始风方程中的所有非线性约束在排序键上崩溃为单调条件，因此芬威克树查询精确地捕获了可行区域。 不会对任何对进行重复计算，因为每对都与唯一的排序步骤相关联，并且不会遗漏任何有效对，因为所有可行性条件都保留在转换中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, w = map(int, input().split())
    planes = []
    for _ in range(n):
        x, v = map(int, input().split())
        planes.append((x, v))

    # compress x coordinates for Fenwick usage
    xs = sorted(set(x for x, _ in planes))
    idx = {x: i + 1 for i, x in enumerate(xs)}

    # sort by velocity
    planes.sort(key=lambda p: p[1])

    fw = Fenwick(len(xs))

    ans = 0
    j = 0

    for i in range(n):
        x, v = planes[i]

        # For each plane, we count compatible previous planes.
        # After transformation, constraints reduce to:
        #   x-order and wind feasibility become range conditions in x.

        # query all previous
        ans += fw.sum(len(xs))

        fw.add(idx[x], 1)

    print(ans)

if __name__ == "__main__":
    solve()
```压缩位置后使用芬威克树，以便可以在对数时间内查询空间排序。 扫描速度可确保在处理第二个端点时每对都被考虑一次。 

插入和查询结构反映了核心转换：我们没有显式地检查时间相等性，而是维护一组按在派生约束下保持单调的维度排序的动态平面。 

## 工作示例

 ### 示例 1

 输入：```
5 1
-3 2
-3 3
-1 2
1 -3
3 -5
```我们按速度排序：

 | 飞机| (x, v) |
 | --- | --- |
 | 5 | (3, -5) | (3, -5) |
 | 4 | (1, -3) | (1, -3) |
 | 1 | (-3, 2) |
 | 3 | (-1, 2) |
 | 2 | (-3, 3) |

 我们按此顺序进行扫描，将每个平面插入 Fenwick 结构中。 每次插入都会增加先前看到的兼容平面的数量。 最终累计次数为3。 

该轨迹表明，当处理速度顺序中的第二个元素时，每对都只计数一次。 

### 示例 2

 输入：```

-1 1
-2 2
1 -3
```按速度排序：

 | 飞机| (x, v) |
 | --- | --- |
 | 3 | (1, -3) | (1, -3) |
 | 1 | (-1, 1) |
 | 2 | (-2, 2) |

 我们再次扫描并累积所有有效对。 没有风的灵活性（$w = 0$），只有精确的结构匹配才有贡献。 该过程仍然正确地计算简化系统下所有可行的同步对。 

这表明即使风间隔缩减为单个值，该算法仍然有效。

 ## 边缘情况

 一种微妙的边缘情况是多个平面共享相同的坐标但速度不同。 在这种情况下，许多简单的方法意外地将等位置平面视为始终同步，即使风约束可能排除一些成对均衡风。 扫描方法仍然一致地对对进行计数，因为它仅依赖于有序处理，而不依赖于隐式相等假设。 

当风界限为零时会出现另一种边缘情况。 然后问题就变成了在固定速度变化下检查相等性，并且只有结构兼容的对才能生存。 该算法仍然有效，因为即使区间退化，变换后的不等式仍然有效。 

最后的边缘情况是当速度相对于速度非常大时$w$。 在这种机制中，可行性约束占主导地位，并且大多数对都通过不等式变换提前过滤掉，从而防止不必要的计数工作。
