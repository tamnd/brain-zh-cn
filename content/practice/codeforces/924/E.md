 ## 解决方案

 ## 问题理解

 我们得到了一系列盒子，每个盒子都有一个正高度和一个二进制标签，指示该盒子是否重要。 我们可以任意重新排列这些盒子并将它们垂直堆叠以形成一个连续的柱，其总高度是所有单独高度的总和。 

每个盒子贡献一个临界值：最终堆叠顺序中其底部边缘的高度。 如果一个盒子从高度开始放置$x$， 然后$x$这对得分很重要。 

我们也给定了一个区间$[l, r]$。 每个底边位于该区间内的重要方框都会为得分贡献 1。 目标是对所有框重新排序，以便尽可能多的重要框的底部边界位于该高度窗口内。 

约束条件明确规定总高度总和最多为 10000，并且$n \le 10000$。 这立即表明任何取决于总高度而不是布置复杂性的解决方案都是可行的。 二次过$n$优化形式可能仍然可以接受，但是完全排除了排列的指数或阶乘推理。 

主要困难在于，放置一个盒子会影响所有后续的底部位置，因此局部决策会改变全局可行性。 尝试“将重要的盒子打包到区间中”而不跟踪前缀和的天真的贪婪方法将会失败。 

一些边缘案例揭示了其中的微妙之处。 

如果所有重要的盒子都非常高，并且单个排序以不同的方式推动间隔边界，那么贪婪的排列可能会将太多的底部边缘移到外面$[l, r]$。 例如，如果所有重要的盒子都提前放置，它们的底边就会很小并且会低于$l$，即使这组盒子是最优的，也使它们毫无用处。 

当有足够多的不重要的小盒子可以用作填充时，会出现另一种故障模式。 幼稚的策略可能会忽略它们，但它们对于将重要框转移到评分窗口至关重要。 

最后，该间隔可能完全位于总高度的中间，因此我们有效地尝试将所选项目的底部边缘“对齐”到类似背包的前缀结构内的固定窗口。 

## 方法

 蛮力的想法是尝试盒子的所有排列，计算每个排序的前缀和，并计算有多少个重要的盒子的底边在$[l, r]$。 这是正确的，因为它直接评估定义。 然而，有$n!$排列，甚至评估一种排列成本$O(n)$，导致总复杂度为$O(n! \cdot n)$，这远远超出了可行的范围。 

关键的观察是，只有所选框的相对顺序很重要，而影响所选重要框是否有贡献的唯一因素是它之前累积的总高度。 由于总高度以 10000 为界，我们可以将问题重新定义为构建前缀和时间线并确定哪些重要框落在目标区间内。 

我们不考虑排列，而是考虑选择重要框的子集并排列它们，使它们的底边落入$[l, r]$。 不重要的框纯粹用作填充，这意味着它们仅移动前缀和而不对分数做出贡献。 

这导致了高度的动态规划，我们跟踪在给定的总高度内可以放置多少个重要的盒子，以及其中有多少个盒子落入目标区间。 该结构在总高度上变成了背包式 DP，其过渡取决于我们是否放置重要或不重要的盒子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有排列）|$O(n! \cdot n)$|$O(n)$| 太慢了|
 | DP 超过高度状态 |$O(n \cdot H)$|$O(H)$| 已接受 |

 在哪里$H \le 10000$。 

## 算法演练

 我们定义一个 DP，在其中逐步构建最终的堆栈，并跟踪我们在每个总高度放置了多少个重要的盒子。 

1. 我们定义一个 DP 数组，其中索引表示堆栈的当前总高度，值表示迄今为止放置的对答案有贡献的重要框的最大数量。 我们还需要跟踪新放置的重要盒子的底边是否在$[l, r]$，仅取决于放置前的当前高度。 
2. 我们用高度 0 和零贡献来初始化 DP。 
3. 我们迭代每个框。 对于每个盒子，我们以相反的高度顺序更新 DP，以避免多次重复使用同一个盒子。 
4. 如果盒子不重要，我们只移动高度：放置它会将所有后续位置向前移动，而不影响分数。 
5.如果盒子很重要，我们考虑将其放置在每个可到达的高度状态。 如果当前高度是$h$，然后放置这个盒子使其底边等于$h$。 如果$h \in [l, r]$，我们为这个位置的答案获得 1。 
6. 我们取所有将盒子分配到高度状态的方式中的最大值。 

关键思想是 DP 不是直接优化最终结构，而是在可实现的前缀和上分配重要的框底部边缘。 

### 为什么它有效

 在构造过程中的任何一点，DP 状态都会在放置一些盒子子集后完全捕获可到达的总高度集。 由于框顺序是任意的，每个子集对应于前缀和的可能排列。 每个重要的盒子仅根据其放置的高度独立做出贡献。 因为未来的放置只会增加高度，所以它们不能追溯影响底部边缘是否位于$[l, r]$。 这使得决策在 DP 转换上局部叠加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, l, r = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    H = sum(a)
    NEG = -10**9

    dp = [NEG] * (H + 1)
    dp[0] = 0

    for i in range(n):
        ai, bi = a[i], b[i]
        new = dp[:]
        for h in range(H - ai + 1):
            if dp[h] == NEG:
                continue
            nh = h + ai
            val = dp[h]
            if bi == 1 and l <= h <= r:
                val += 1
            new[nh] = max(new[nh], val)
        dp = new

    print(max(dp))

if __name__ == "__main__":
    solve()
```DP 数组按总堆叠高度进行索引。 每个转换要么添加一个不重要的框，要么添加一个重要的框。 将重要箱子放置在高处时$h$，我们直接检查底部边缘是否对分数有贡献。 这里通过复制数组来替换反向迭代，这确保每个框最多使用一次。 

一个微妙的点是我们永远不需要显式地对排列进行建模。 DP 本质上将不同的阶数视为达到相同高度配置的不同方式，这已经足够了，因为只有底部边缘高度很重要。

 ## 边缘情况

 一个重要的边缘情况是当间隔从 0 开始时。在这种情况下，第一个放置的重要框始终具有底部边缘 0，因此如果该框很重要，则高度 0 处的任何有效 DP 状态都会立即起作用。 该算法处理这个问题是因为它检查条件`l <= h <= r`转换前直接位于高度 0。 

当所有盒子都非常大并且只有一个或两个适合间隔边界时，会出现另一种边缘情况。 DP 仍然考虑高度的所有子集，并且由于高度过渡是精确的，因此不会计算无效放置。 

最后一个微妙的情况是，多个不同的序列导致相同的总高度，但重要底部边缘的分布不同。 DP 通过保留每个高度的最佳得分来自然地合并这些状态，确保等效高度不会重复计算，同时仍然保留最佳可实现的安排。
