 ## 解决方案

 ## 问题理解

 网格开始时完全是空的，我们得到了黑色和白色单元格的最终图案。 创建黑色单元格的过程不是任意绘制，而是结构化操作：每个操作选择一些行和一些列，然后绘制所选行和列之间的每个交集。 这意味着一项操作始终会在其选定的行和列之间生成完整的矩形叉积。 

还有一个额外的限制使结构变得刚性。 总体而言，每一行和每一列最多可以参与一次操作。 因此，一旦在一个操作中使用了一行，它就永远不会对任何其他操作做出贡献，并且对于列来说也是如此。 这将构造变成了一个分区问题，而不是一系列独立的绘画步骤。 

任务是确定给定的黑白网格是否可以通过某些有效的此类操作集生成。 

约束很小，两个维度都达到 50，这立即表明每次检查的二次或稍差的解决方案就足够了。 不需要对所有子集进行组合或对操作进行回溯，因为操作的结构受到高度限制。 

当局部思考时，会出现一个微妙的问题。 天真的直觉可能会说每个黑色单元格都可以独立处理，或者我们可以根据黑色单元格出现的位置贪婪地对行或列进行分组。 当依赖关系通过共享行和列形成循环时，此操作会失败。 

例如，考虑一种配置，其中第 1 行与第 1 列和第 2 列共享黑色单元格，并且第 2 行也与这些列交互。 贪婪分组可能会错误地合并其中一些单元格，从而迫使目标网格中不存在额外的黑色单元格。 

另一个失败案例来自于假设网格中的每个黑色连接组件都是足够的。 这里的连通性是不够的，因为运算会产生完整的笛卡尔积。 如果两行两列属于同一个操作，则所有四个交点都必须为黑色。 即使其中一个是白色的，即使所有东西都通过其他黑色细胞连接，结构也会破裂。 

所以真正的困难不是可达性，而是强制每个隐含的矩形都被完全填充。 

## 方法

 强力解释会尝试直接猜测操作。 每个操作都由行子集和列子集定义，并且这些子集在操作之间必须是不相交的。 尝试所有此类分区远远超出了可行的限制，因为即使将行单独分配到组中也是指数级的，并且列必须与它们协调。 

关键的简化来自于对操作效果的重构。 我们没有从操作的角度思考，而是观察到每个操作都会创建一个规则：其行集中的每一行相对于其列集中的每一列的行为都是相同的。 特别是，在至少一个黑色单元格中一起出现的任何行和列必须属于同一隐藏操作索引。 

这暗示了一个统一的想法。 我们将每一行和每一列视为单个结构中的节点。 每当一个单元格为黑色时，我们就强制其行和列属于同一组。 这意味着我们可以使用联合结构合并它们。 处理完所有黑色单元后，每个连接的组件都代表一个潜在的操作标签。

现在我们必须验证该结构不会意外地过度生成黑色单元。 如果两个节点在同一个组件中，它们将被视为属于同一操作，这意味着组件内的每个行列对都变成黑色。 因此，如果存在一个白色单元格，其行和列位于同一组件中，则构造会错误地将其强制为黑色。 这是违反可行性的唯一方法。 

因此，整个检查简化为从黑色单元构建连接的组件，并验证单个组件对内没有白色单元。 

这种转换将复杂的组合过程简化为对二分联合查找结构的一致性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力操作 | 指数| 指数| 太慢了|
 | 并查一致性检查| O(nm α(n+m)) | O(n+m) | 已接受 |

 ## 算法演练

 我们将每一行和每一列建模为并查找结构中的单独节点。 行的索引从 0 到 n−1，列的索引从 n 到 n+m−1，以便它们位于同一个 DSU 中。 

1. 初始化一个包含 n + m 个节点的 DSU，最初将每一行和每一列视为其自己的组件。 这表示尚未应用任何约束。 
2. 扫描网格中的每个单元格。 如果单元格 (i, j) 为黑色，则将 DSU 中的第 i 行与第 j + n 列合并。 这强制生成此黑色单元的任何操作都必须包含两个端点，因此它们必须共享相同的隐藏标签。 
3. 处理完所有并集后，再次扫描网格。 对于每个白色单元格 (i, j)，检查行 i 和列 j + n 是否属于同一 DSU 组件。 如果这样做，立即返回不可能，因为这将迫使单元格在任何有效的结构中变成黑色。 
4. 如果没有白细胞违反此条件，则返回可能。 

这样做的原因是黑色单元格定义了行和列之间的等式约束，而 union-find 计算这些等式的传递闭包。 任何一致的操作分配都必须尊重这些平等性。 一旦确定了等式，每个组件的行为就像一个原子标签。 唯一剩下的要求是我们永远不要强迫白色单元位于单个原子块内，因为这会与目标网格相矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    dsu = DSU(n + m)

    def row(i):
        return i

    def col(j):
        return n + j

    for i in range(n):
        for j in range(m):
            if g[i][j] == '#':
                dsu.union(row(i), col(j))

    for i in range(n):
        for j in range(m):
            if g[i][j] == '.':
                if dsu.find(row(i)) == dsu.find(col(j)):
                    print("No")
                    return

    print("Yes")

if __name__ == "__main__":
    solve()
```DSU 用于折叠由黑色单元引起的行和列标识。 列的映射函数将索引偏移 n，以便行和列位于一个结构中而不会发生冲突。 第二遍很重要，因为它检查矛盾而不是显式地构建任何内容。 

一个常见的错误是只联合黑细胞并立即假设有效性。 这忽略了联合隐式强制网格中不存在的额外黑色单元的情况。

 ## 边缘情况

 一个关键的边缘情况是黑色单元格将所有行和列强制放入单个组件，但保留单个白色单元格。 在这种情况下，DSU 会折叠所有内容，并且白色检查会立即检测到两个端点位于同一组件中，从而正确拒绝网格。 

另一种情况是根本没有黑细胞。 DSU 仍然完全分离，并且没有工会发生。 由于强制的相同分量对中不能存在白色单元格，因此答案非常有效，对应于零操作。 

第三种情况是黑色单元形成多个不相连的区域，这些区域通过交替的行列关系意外连接。 DSU 自然地处理这个问题，因为通过任何路径的连接都会合并组件，确保即使在网格中不明确时也遵守隐藏的传递约束。
