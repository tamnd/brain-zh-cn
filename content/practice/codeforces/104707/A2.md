 ## 解决方案
 ## 问题理解

 我们正在处理一系列相继到达的项目，对于每个项目，我们必须立即决定是由 Arda 还是由 Bimala 处理。 每个作业都会根据接收者的不同产生不同的值，因此总分是所有天中所选值的总和。 

约束不仅仅与最终计数有关，还与序列的每个前缀有关。 在任何时候，如果一名员工被分配的项目比另一名员工多 k 个以上，他们就会抱怨，分配就会无效。 这意味着分配给 Arda 和 Bimala 的项目数量之间的差异在整个过程中必须始终保持在 [-k, k] 范围内。 

目标是在这种不断变化的平衡约束下最大限度地提高总体质量。 

输入大小 n 最多为 1000，k 也最多为 1000。这立即表明 O(n²) 或 O(nk) 动态规划解决方案是可行的，但任何尝试探索所有 2ⁿ 分配的操作都是不可能的，因为在最坏的情况下需要大约 10³⁰ 操作。 

天真的贪婪策略会失败，因为本地决策可能会将前缀平衡推入一个未来高价值分配变得不可能的区域。 该约束是前缀敏感的，因此早期的选择会以非本地方式影响后来的可行性。 

典型的失败案例发生在，一名工作人员对于早期任务稍有优势，但总是选择他们会导致过早达到 k 边界，从而迫使稍后进行次优分配。 

例如，如果 k = 1：```
(10, 1), (10, 1), (1, 10)
```贪心分配会选择 Arda 来完成前两项任务，立即达到 2 的差异，这是无效的。 即使我们尝试“稍后修复”，前缀约束也已经破坏了可行性。 正确的策略必须预见到未来的灵活性，而不仅仅是眼前的收益。 

## 方法

 强力方法尝试将每个项目的所有可能分配给 Arda 或 Bimala，同时跟踪分配计数的当前差异。 对于每个前缀，我们维护是否满足约束。 这是有效地探索高度为 n 的二元决策树，因此状态数为 2ⁿ。 即使尽早修剪无效状态，分支因子仍然太大，因为许多部分赋值直到递归很深时才有效。 

关键的观察是，我们做出未来决策所需的唯一信息是，与当前前缀的 Bimala 相比，Arda 收到了多少个项目。 确切的历史并不重要，重要的是这种差异。 这将状态空间压缩为范围从 -k 到 k 的一维平衡变量。 

这立即表明了前缀索引和当前余额的动态规划公式。 

我们将 dp[i][d] 定义为处理前 i 个项目后的最大总质量，其中差值 (#Arda − #Bimala) 等于 d。 对于每个状态，我们可以将项目 i+1 分配给 Arda 或 Bimala，如果余额保持在范围内，则相应地更新余额。 

这将问题从指数搜索简化为大小为 O(nk) 的结构化图，其中每个状态最多有两次转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2ⁿ) | O(n) | 太慢了|
 | 最佳DP | O(nk) | O(nk) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

 ### 第 1 步：定义状态空间

 我们定义一个 DP 表，其中 dp[i][d] 存储处理 i 个具有平衡 d 的项目后可达到的最大质量。 

余额 d 代表 Arda_count − Bimala_count。 它总是被限制在 -k ≤ d ≤ k，因为任何超出这个范围的状态都是无效的。 

### 第 2 步：初始化基本状态

 在分配任何项目之前，两个工作人员的分配都为零，因此：

 dp[0][0] = 0

 所有其他状态都初始化为负无穷大，因为它们无法到达。 

### 第 3 步：每个项目的过渡

 对于每个项目 i，我们考虑所有可能的有效余额 d。 从 dp[i][d] 开始，我们尝试两种选择：

 如果我们将项目分配给Arda，新的余额变为d + 1，分数增加a[i]。 

如果我们将其分配给 Bimala，则新余额变为 d − 1，分数增加 b[i]。 

仅当结果平衡保持在 [-k, k] 范围内时，我们才执行转换。 

这确保我们永远不会构造无效的前缀状态。 

### 步骤 4：迭代所有状态

 我们按照从1到n的顺序处理项目，逐层更新DP表。 每一层仅依赖于前一层，因此如果需要，我们可以将空间压缩为两个数组。 

### 步骤 5：提取答案

 处理完所有项目后，我们对 [-k, k] 中的 d 取所有 dp[n][d] 中的最大值，因为只要所有前缀有效，就允许任何最终平衡。 

### 为什么它有效

 DP 状态完全捕获继续决策所需的所有信息：只有当前前缀长度和当前平衡很重要。 任何以相同 (i, d) 结尾的历史都是等效的，因为未来的决策仅取决于每个工人当前有多少任务，而不是他们被分配的顺序。 由于每个有效分配恰好对应于该 DP 图的一条路径，并且所有转换都保留可行性，因此 DP 会探索所有有效的解决方案，而不会重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [0] * n
    b = [0] * n

    for i in range(n):
        a[i], b[i] = map(int, input().split())

    offset = k
    INF = -10**18

    dp = [[INF] * (2 * k + 1) for _ in range(n + 1)]
    dp[0][offset] = 0

    for i in range(n):
        for d in range(-k, k + 1):
            if dp[i][d + offset] == INF:
                continue

            cur = dp[i][d + offset]

            # assign to Arda
            if d + 1 <= k:
                nd = d + 1
                dp[i + 1][nd + offset] = max(
                    dp[i + 1][nd + offset],
                    cur + a[i]
                )

            # assign to Bimala
            if d - 1 >= -k:
                nd = d - 1
                dp[i + 1][nd + offset] = max(
                    dp[i + 1][nd + offset],
                    cur + b[i]
                )

    ans = max(dp[n])
    print(ans)

if __name__ == "__main__":
    solve()
```DP 表移动一个偏移量，以便可以在数组中安全地索引负余额。 每行对应一个前缀长度，我们只读取前一行，这确保了转换的正确性。 

使用较大的负数表示无法到达的状态。 如果没有这个，无效的转换可能会错误地影响最大值。

def solve():

    n, k = map(int, input().split())
    a = [0] * n
    b = [0] * n
    for i in range(n):
        a[i], b[i] = map(int, input().split())

    INF = -10**18
    off = k
    dp = [[INF] * (2 * k + 1) for _ in range(n + 1)]
    dp[0][off] = 0

    for i in range(n):
        for d in range(-k, k + 1):
            cur = dp[i][d + off]

                continue
            if d + 1 <= k:
                dp[i + 1][d + 1 + off] = max(dp[i + 1][d + 1 + off], cur + a[i])

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 边缘情况

 一个关键的边缘情况是当 k = 1 时，早期的贪婪不平衡看起来是最优的，但会阻碍未来的灵活性。 例如：

 输入：```
3 1
10 1
1 10
10 1
```如果我们贪婪地最大化每一步，我们可能会由于即时增益较高而提前重复选择 Arda，但这可能会将前缀差异推向允许的范围之外，或者稍后强制进行次优分配。 DP 通过尽可能保持两个平衡状态来处理这个问题。 

该算法在第一个项目之后正确地探索了两个作业。 处理完第一项后，dp[1][1]和dp[1][-1]都代表有效的可能性。 然后，第二个项目从两个状态分支，确保不会过早丢弃全局最优配置。
