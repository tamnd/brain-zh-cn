 ## 解决方案
 ## 问题理解

 每天我们都会收到一项任务，并且必须将其恰好分配给两名工人中的一名。 如果我们给 Arda 一个任务，我们就会获得价值`a_i`，如果我们将其交给 Bimala，我们将获得`b_i`。 目标是分配每项任务，同时最大化总获得价值。 

有一个公平规则，该规则取决于每个工人迄今为止收到的任务数量的差异。 在任何天数前缀下，分配给 Arda 和 Bimala 的任务数量不得相差超过 1，因为这里`k = 1`。 这意味着，虽然我们可以自由选择任务，但我们不允许一名工人在任何中间点的计数上领先太多。 

关键的困难在于决策是连续的并且受到前缀平衡的限制，因此每天的贪婪选择是不安全的。 局部最优分配可能会导致未来出现违反约束的不平衡，即使使用不同的分配顺序可以实现相同的最终计数。 

和`n ≤ 1000`， 一个`O(n^3)`甚至`O(n^2)`解决方案是可以接受的。 任何指数级的分配都是不可能的，因为有`2^n`任务量太大了。 

当一名工人在早期一直表现出色，但反复选择他们会立即打破平衡约束时，就会出现微妙的失败案例。 例如，如果 Arda 总是更好，但是`k = 1`，连续分配他两次是无效的，即使这在本地看起来是最佳的。 这迫使类似交替的行为而不是纯粹的选择。 

## 方法

 强力解释将该问题视为在每个前缀的计数差异最多为 1 的约束下探索所有有效的分配序列。 这可以看作是状态上的 DFS`(i, diff)`在哪里`i`是日指数并且`diff`是 Arda 和 Bimala 之间分配计数的当前差异。 每个步骤都会分支到将当前任务分配给任一工作人员（如果保留）`diff`之内`[-1, 1]`。 

这是正确的，因为它探索了所有合法序列。 然而，州的数量却在迅速增长。 虽然`diff`很小，每个状态分支两次，并且在没有记忆的情况下，这会呈指数增长`n`。 通过记忆，我们获得了动态规划解决方案`O(n * 3)`州，因为`diff`只能是`-1, 0, 1`。 每个转换都会检查两个分配选择。 

关键的见解是约束仅取决于计数的差异，而不取决于历史。 一旦我们知道`(i, diff)`，过去并不重要。 这将指数搜索空间折叠成一个小的固定状态机，其中的转换仅通过增加或减少差异并添加相应的奖励来确定。 

因此我们计算 DP 其中`dp[i][d]`存储第一个处理后的最大总质量`i`差异编码为的任务`d`, 移动使得`d ∈ {0,1,2}`对应实际差异`-1,0,1`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力DFS | O(2^n) | O(2^n) | O(n) | 太慢了|
 | DP 处于不同状态 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将流程建模为一项一项地完成任务，同时跟踪一名员工比另一名员工多完成多少任务。 自从`k = 1`，这种差异总是限于`-1`,`0`， 或者`1`。 

1.定义DP表`dp[i][d]`在哪里`i`是我们处理了多少任务，以及`d`编码了 Arda 和 Bimala 之间的当前差异。 我们转变`d`+1 使得索引变为`0, 1, 2`。 
2. 初始化`dp[0][1] = 0`，表示已处理的零个任务和相等的分配计数。 所有其他状态一开始都是不可能的。 
3. 对于每项任务`i`，考虑从所有可达状态的转换`dp[i][d]`。 
4.如果我们分配任务`i`对于 Arda，差异增加 1。仅当新差异不超过`1`。 用DP术语来说，我们从`d`到`d + 1`并添加`a_i`至总数。 
5.如果我们分配任务`i`到 Bimala，差值减少 1。仅当新差值不低于以下时才允许这样做`-1`。 用DP术语来说，我们从`d`到`d - 1`并添加`b_i`。 
6. 处理完所有任务后，我们取其中的最大值`dp[n][0..2]`。 

这样做的原因是每个有效的分配序列都对应于通过这些 DP 状态的一条路径，并且每个 DP 转换都保留了前缀约束的可行性。 由于所有有效路径都是隐式枚举的，并且每条路径只评分一次，因此最大 DP 值与最佳分配相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = []
    b = []
    for _ in range(n):
        x, y = map(int, input().split())
        a.append(x)
        b.append(y)

    NEG = -10**18
    dp = [[NEG] * 3 for _ in range(n + 1)]
    dp[0][1] = 0

    for i in range(n):
        for d in range(3):
            if dp[i][d] == NEG:
                continue

            cur = dp[i][d]

            if d + 1 < 3:
                dp[i + 1][d + 1] = max(dp[i + 1][d + 1], cur + a[i])

            if d - 1 >= 0:
                dp[i + 1][d - 1] = max(dp[i + 1][d - 1], cur + b[i])

    print(max(dp[n]))

if __name__ == "__main__":
    solve()
```DP 数组的大小`(n+1) × 3`因为差异状态空间固定为三个值。 常数`NEG`代表无法到达的状态，因此它们永远不会影响转换。 每个任务独立处理两个分配选项，并且仅更新下一层。 

这里的一个常见错误是忘记必须仅从前一层应用转换。 就地更新会在同一步骤中破坏状态。 另一个微妙的点是初始化：只有平衡状态在开始时才有效，因为尚未进行任何分配。 

## 工作示例

 ### 示例 1

 输入：```
2 1
2 3
1 1
```我们追踪`dp[i][diff]`其中 diff 是`-1, 0, 1`。 

| 我| 差异-1 | 差异 0 | 差异 1 |
 | ---| ---| ---| ---|
 | 0 | -inf| 0 | -inf|
 | 1 | 3 | -inf| 2 |
 | 2 | -inf| 4 | -inf|

 在第 1 天，分配给 Bimala 给出值 3 并将 diff 转换为 -1，分配给 Arda 给出值 2 并将 diff 转换为 +1。 在第 2 天，每个状态只能通过分配给相反的工人来恢复平衡。 最佳最终平衡分配的总分是 4。 

该跟踪表明，即使 Arda 在一项任务上表现更好，连续分配也会被阻止，从而强制进行交替。 

### 示例 2

 输入：```
5 1
6 7
1 3
4 10
3 2
5 5
```我们只跟踪可达状态：

 | 我| 差异-1 | 差异 0 | 差异 1 |
 | ---| ---| ---| ---|
 | 0 | -inf| 0 | -inf|
 | 1 | 7 | -inf| 6 |
 | 2 | 10 | 10 9 | 9 |
 | 3 | 19 | 19 20 | 19 | 19
 | 4 | 22 | 22 29 | 29 22 | 22
 | 5 | 27 | 27 29 | 29 27 | 27

 最终答案是 29，这是通过保持近乎平衡的分配，同时在每一步选择性地选择更高的贡献来实现的。 

这表明最佳结构对于每个工人来说并不是单调的，而是取决于在整个序列中维持可行的转换。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | n 步骤中的每一步都处理具有两个转换的恒定三态 DP |
 | 空间| O(n) | DP 工作台尺寸 (n+1) × 3 |

 线性复杂度完全符合约束条件，因为`n ≤ 1000`，并且由于恒定状态结构，甚至更大的限制也将保持有效。

 ## 边缘情况

 一项任务的最小输入会暴露初始化的正确性。 有输入`1 1`和价值观`a=5, b=10`，DP 必须立即选择 Bimala，因为两个工作人员一开始都是平衡的，并且每个选择只有一个转换有效。 正确的输出是`10`，任何错误初始化多个起始状态的解决方案都可能会过度计数或错误评估。 

在一个工人主导两项任务的双任务场景中，显示了约束的效果。 和`a=[10,9]`和`b=[1,2]`，最优被迫交替，产生`10 + 2 = 12`。 由于不平衡，将两者分配给 Arda 的贪婪方法在第二次分配时立即失败，这凸显了局部最大值无效的原因。 

所有值都相等的对称情况表明任何有效的交替路径都是最优的，并且 DP 正确聚合所有等效状态而没有偏差。
