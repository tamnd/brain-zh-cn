 ## 解决方案
 ## 问题理解

 每个访客的行为就像一个确定性时钟，从他们第一次访问的那天开始滴答作响。 从那一刻起，他们就产生了无限的访问序列，按照他们的个人时期定期间隔。 如果访问者有参数$a_i$和$b_i$，然后它们出现在几天$a_i, a_i + b_i, a_i + 2b_i, \dots$。 同一天可以出现多个访问者，当发生这种情况时，他们的访问将按输入中的索引进行排序。 

全球范围内的过程不是几天的事，而是一系列事件的合并。 每个访客的每次访问都会插入到一个时间线中，首先按天排序，然后按访客索引排序。 任务是确定哪个访问者产生了$k$此合并时间线中的第 -th 事件，其中$k$可以非常大，最多$10^{12}$，因此我们无法显式模拟访问。 

这些限制使得直接模拟变得不可能。 即使我们假设每个访问者仅贡献几百万次访问，事件总数也很容易超过$10^{12}$，甚至生成该序列的一小部分也是不可行的。 任何一一枚举访问的解决方案都会立即超时。 

一个微妙的困难来自于同一天的平局。 例如，如果第 6 天同时出现了两个访客，则必须先统计索引较小的访客。 如果没有仔细排序，天真的逐日聚合会在同一天内产生不正确的排名。 

另一个边缘情况是当$k$与最早的访问相比非常小。 如果全部$a_i$由于规模很大，前几个事件可能会反复来自单个早期访问者，因此“所有访问者从一开始就均匀贡献”的任何错误假设都将被打破。 

最后，较长的周期会导致贡献稀疏。 一位访客带着很大的$b_i$在任何合理的时间前缀中可能只出现一次，但对于$k$-第一个事件如果$k$很大。 这排除了仅考虑初始时间窗口的策略。 

## 方法

 直接的暴力方法是逐个事件地模拟流程。 在每一步中，我们都会计算每个访问者的下一次即将到来的访问，选择最短日期（按索引打破平局），输出该访问者，并提前他们的下一次访问。 这可以通过存储每个访问者的下一次访问时间的优先级队列来实现。 

这种方法是正确的，因为它完全反映了事件排序定义。 然而，它每次访问都会执行一次堆操作，并且在最坏的情况下$k$第 - 个事件是$10^{12}$，这使得它完全不可行。 甚至生成$10^8$事件已经太慢了，所以我们必须避免明确地逐步进行访问。 

关键的观察是我们实际上不需要按顺序生成访问。 相反，我们只需要回答一个计数问题：在给定时间内$T$, 迄今为止发生了多少次访问$T$？ 这将问题从序列生成问题转换为前缀计数问题。 如果我们可以有效地计算这个计数，那么我们就可以按时间进行二分搜索以找到至少$k$访问已经发生。 

一旦我们确定了一天$T$，每个访问者贡献了可预测的访问次数：如果$T < a_i$，他们什么也不贡献，否则他们贡献$\left\lfloor \frac{T - a_i}{b_i} \right\rfloor + 1$。 对所有访客进行求和，得出的访问总数为$T$。 

找到正确的日期后$T$，最后一步是识别哪个访问者产生了$k$当天内的第 - 次事件。 我们严格减去之前的访问次数$T$，然后按顺序扫描访客并仅模拟当天的访问$T$，它很小，因为它受到当天活跃算术级数数量的限制。 

这将不可能的事件模拟转换为随时间的对数搜索加上每次检查的线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | Brute Force（优先级队列模拟）|$O(k \log n)$|$O(n)$| 太慢了|
 | 最优（二分查找+计数） |$O(n \log A)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 我们定义一个函数来计算截至给定日期发生的总访问次数$T$。 对于每个访问者，我们计算他们的算术级数中有多少项$[a_i, T]$。 这给出了直接基于公式的计数而不是模拟。 
2.我们当天进行二分查找$T$。 目标是找到最小的一天，使得截至该天的访问次数至少为$k$。 这是可行的，因为前缀计数在时间上是单调的：增加$T$永远不会减少访问，只会增加更多。 
3. 使用计数函数计算二分查找中的每个中点。 如果计数小于$k$，我们将搜索向右移动； 否则我们向左移动。 这样就隔离了累计访问量达到或超过的第一天$k$。 
4. 确定目标日期后$T$，我们计算严格之前发生的访问次数$T$。 这给了我们偏移量$k'$，它告诉我们哪一天访问$T$我们需要找到。 
5. 我们迭代所有访客并收集当天访问的访客$T$。 一位访客为这一天做出了贡献$T$如果$T \ge a_i$和$(T - a_i) \bmod b_i = 0$。 我们按升序附加它们的索引，这自然尊重打破平局的规则。 
6. 我们选择$k'$该列表中的第 -th 个访问者并输出他们的索引。 

正确性取决于全局排序是按日字典顺序然后按索引排序的事实。 通过首先通过前缀计数隔离正确的日期，我们将问题减少到在一天内进行选择，其中排序是微不足道的。 

### 为什么它有效

 该算法将所有访问划分为几天。 二分查找找出累计访问次数交叉的唯一一天$k$。 由于访问严格按天排序，因此在完成前几天的所有访问之前，不会出现较后一天的访问。 在固定日期内，按索引排序直接匹配定义。 前缀计数函数与隐式合并序列中的事件总数完全匹配，因此二分搜索收敛到正确的边界，而不会丢失或重复计算任何事件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = []
    b = []
    max_a = 0
    for _ in range(n):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)
        if ai > max_a:
            max_a = ai

    def count_upto(t):
        total = 0
        for i in range(n):
            if t >= a[i]:
                total += (t - a[i]) // b[i] + 1
                if total >= k:
                    return total
        return total

    lo, hi = 1, max_a + k  # safe upper bound
    while lo < hi:
        mid = (lo + hi) // 2
        if count_upto(mid) < k:
            lo = mid + 1
        else:
            hi = mid

    day = lo

    before = 0
    for i in range(n):
        if day >= a[i]:
            cnt = (day - a[i]) // b[i] + 1
            before += cnt

    before -= sum(1 for i in range(n) if day == a[i] + ((day - a[i]) // b[i]) * b[i])

    remaining = k - (before)

    cur = []
    for i in range(n):
        if day >= a[i] and (day - a[i]) % b[i] == 0:
            cur.append(i + 1)

    cur.sort()
    print(cur[remaining - 1])

if __name__ == "__main__":
    solve()
```实现的核心是前缀计数函数，它将每个访问者转换为封闭形式的算术级数计数。 二分查找依赖于这个单调函数来定位确切的日期$k$第 - 个事件发生。 最后的选择步骤仅考虑当天的活跃访客，并依靠按索引排序来满足平局。 

唯一微妙的部分是确保二分搜索范围足够大。 使用$max(a_i) + k$是安全的，因为即使所有游客出发晚了，前进$k$超出最大开始天数可以保证足够的累积访问量。

 ## 边缘情况

 当多个访问者登陆二分搜索选择的同一边界日时，就会出现关键的边缘情况。 该算法通过隔离当天活跃的所有访问者并按索引对它们进行排序来解决此问题。 例如：```
3 4
1 2
1 2
1 2
```所有访客都会在第 1 天、第 3 天、第 5 天等进行访问。 第 4 次访问在第 3 天进行。第 3 天，所有三个访问者都出现，按索引选择会产生访问者 1，然后是 2，然后是 3，因此第四个事件的正确答案是 3。 该算法正确地重建了这一点，因为日级隔离保留了完整的贡献者集。 

另一种边缘情况是当一个访问者的周期非常长时，他们在二分搜索范围内只贡献一次。 即便如此，计数功能在适用时将它们精确地包含一次，确保它们不会在稀疏的时间线中丢失。
