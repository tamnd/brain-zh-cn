 ## 解决方案

 ## 问题理解

 我们得到了一系列玫瑰，每朵玫瑰都有一个美丽值和三种颜色之一：白色、橙色或红色。 我们需要精确地选择 k 朵玫瑰以最大化整体美丽，但选择必须遵守两个约束。 首先，我们不能挑选同时包含红玫瑰和白玫瑰的花束。 其次，我们不允许挑选所有所选玫瑰颜色相同的花束。 

因此，每个有效的花束要么是“只有橙子”，要么是“橙子加红色但没有白色”，要么是“橙子加白色但没有红色”。 禁止任何其他组合。 

任务是在这些约束下选择 k 个项目，同时最大化它们的值的总和。 

限制条件很大，最多有20万朵玫瑰。 任何尝试枚举子集或针对每种情况重复重新计算最佳选择的解决方案都会太慢。 即使是看起来像 O(nk) 或 O(n log n 每组选择重复多次) 的方法也是有风险的，除非精心构造，所以我们应该期待一种贪婪或基于排序的构造。 

一个关键的结构观察是，一旦颜色约束被固定，问题就简化为从过滤列表中选择 k 个最大值，这可以通过排序或维护排序数组的前缀和来自然地解决。 

有一些微妙的边缘情况值得隔离。 

一种失败情况是当 k 等于玫瑰总数但所有玫瑰共享一种颜色时。 例如：

 输入：```
3 3
5 4 1
RRR
```唯一可能的选择是使用所有玫瑰，但这违反了“颜色不同”规则，因此答案必须为 -1。 仅强制执行红白冲突的简单解决方案将错误地返回 10。 

当橙色不足以单独填充 k 但仅存在红色或白色之一的有效组合时，会出现另一种边缘情况。 例如，在不强制执行排他性约束的情况下混合贪婪的颜色选择可能会通过共享的“总体前 k 个”策略意外地组合红色和白色。 

最后，最危险的错误是忽视了橙子作为灵活桥梁的作用。 许多不正确的解决方案贪婪地从每个允许的组中独立地选择 k 个最大的值，而不考虑橙子可以分配到任一侧，这会导致次优组合。 

## 方法

 蛮力方法会尝试所有大小为 k 的有效子集。 对于每个子集，我们将验证它不会混合红色和白色并且不是单色的，然后计算其总和。 这需要检查大约$\binom{n}{k}$子集，即使对于很小的 n 也是不可行的，因为 n 可以是 200,000。 

另一个天真的想法是按美丽程度对所有玫瑰进行排序，然后尝试挑选前 k 个玫瑰，如果违反颜色约束则进行调整。 这会失败，因为全局前 k 可能同时包含红色和白色，并且贪婪地修复该问题（通过交换项目）并不能保证最优性。 

关键的观察结果是约束将有效解决方案仅划分为三种结构类型。 有效的花束必须恰好属于以下类别之一：仅红色 + 橙色、仅白色 + 橙色或仅橙色（但如果 k 等于整个所选集合，则不允许仅橙色，除非全局不存在其他颜色，因为“所有相同颜色”是被禁止的）。 一旦我们修复了类型，问题就简化为从多重集中选择 k 个最大元素。 

橙色玫瑰的作用至关重要。 它们可以在两种有效的混合配置中使用，因此它们应该作为候选者包含在红色兼容池和白色兼容池中。 这自然建议对每个相关组内的玫瑰进行排序，并使用前缀和或基于堆的选择。 

我们计算最佳可能的总和：

 1.只使用红色和橙色
 2.只使用白色和橙色

 我们还明确拒绝所选 k 朵玫瑰来自单一颜色的情况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n 选择 k) | O(k) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先根据颜色将玫瑰分成三个列表，并按美丽程度的降序对每个列表进行排序。 

1. 构建三个数组：红色、白色、橙色。 每个都存储该颜色的美丽值。 

这使我们能够将兼容性约束视为设置限制而不是成对检查。 
2. 按降序对每个数组进行排序。 

排序确保采用前缀对应于最大可能的部分选择。 
3. 预先计算每个数组的前缀和。 

这允许 O(1) 计算任何颜色组中最佳 x 元素的总和。 
4. 对于固定的k，我们尝试通过两种方式构造有效的花束：

 首先，我们考虑将红色和橙色结合起来。 我们迭代我们拿了多少个红色，比如说 i，然后如果可能的话我们必须拿 k - i 个橙子。 如果 k - i 超过了可用的橙子，我们就跳过这个分割。 

迭代 i 的原因是橙子是共享资源，因此我们必须明确决定有多少个橙子去红边。 
5. 同样，我们对白色和橙子重复相同的过程。 
6. 我们跟踪所有有效分割的最大总和。 任何导致仅选择一种颜色的分割都会被丢弃。 
7. 如果不存在有效的分割，我们返回-1。 

关键思想是橙子是唯一灵活的成分。 红色和白色不能共存，因此它们定义了两个独立的优化问题，仅通过橙色相交。 

为什么它有效：

 在任何最佳解决方案中，要么存在红色，要么存在白色，但绝不会同时存在两者。 固定红色（或白色）的数量完全决定了必须使用多少橙色。 由于在每种颜色中我们总是采用最高的美丽元素，任何与前缀选择的偏差都会减少总和。 这保证了对红色（或白色）数量的枚举分割可以探索所有结构上不同的最佳候选。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))
    c = input().strip()

    red = []
    white = []
    orange = []

    for i in range(n):
        if c[i] == 'R':
            red.append(b[i])
        elif c[i] == 'W':
            white.append(b[i])
        else:
            orange.append(b[i])

    red.sort(reverse=True)
    white.sort(reverse=True)
    orange.sort(reverse=True)

    def prefix(arr):
        ps = [0]
        for x in arr:
            ps.append(ps[-1] + x)
        return ps

    pr = prefix(red)
    pw = prefix(white)
    po = prefix(orange)

    INF = -10**18
    ans = INF

    def try_color(main, main_pref, other):
        nonlocal ans
        m = len(main)
        o = len(other)

        for i in range(m + 1):
            j = k - i
            if j < 0 or j > o:
                continue
            if i + j != k:
                continue
            if i == k or j == k:
                continue
            ans = max(ans, main_pref[i] + prefix(other)[j])

    try_color(red, pr, orange)
    try_color(white, pw, orange)

    if ans == INF:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先按颜色对玫瑰进行分组并对每个组进行排序，以便最佳选择成为前缀选择。 辅助函数构建前缀和，从而能够快速计算两组之间的任何固定分割。 

这`try_color`函数探索了在原色组（红色或白色）和橙色之间分配 k 个选择的所有方法。 它强制执行可行性条件，并拒绝所有 k 来自一种颜色的退化情况，因为这违反了问题约束。 

最终答案是两种有效配置的最大值。

 | 我是白人| k-i 橙子 | 有效 | 总和|

该跟踪表明，对前缀分割的可行性过滤确保我们只考虑有效的颜色分区，而前缀和保证最佳的内部选择。

 ## 边缘情况

 一个关键的边缘情况是所有玫瑰都是单色的。 该算法处理这个问题是因为`try_color`调用将无法产生两种颜色均出现的有效分割，从而留下`ans`不变并导致 -1。 

当 k 非常接近 n 时，会出现另一种边缘情况。 即使存在橙色，“并非所有颜色都相同”的约束也会迫使至少出现一种非橙色。 这`i == k`和`j == k`检查明确阻止选择单色花束。 

第三种边缘情况是橙子丰富，但所有高价值玫瑰都是红色或白色。 拆分枚举确保我们不会过度使用橙色，而代价是排除颜色更好的玫瑰，因为 i 的每次分配都会自动使用前缀和，从而保证该分区的最大选择。 

最后，当其中一个颜色组为空时，算法自然会简化为单个有效配置，并且正确性仍然成立，因为另一个分支是唯一可行的。
