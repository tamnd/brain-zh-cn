 ## 解决方案

 ## 问题理解

 给定一个一维图像，表示为长度序列$n$，其中每个位置要么是黑色，要么是白色。 解释是逐列的：每列都是统一颜色的，因此整个图片简化为二进制数组。 

任务是确定该数组是否可以分解为连续的块，其中每个块由相同的值组成，并且所有块具有相同的长度。 相邻块之间的颜色必须交替。 换句话说，数组应该是固定模式长度的重复$k$，其中每段长度$k$是常数，连续的段会翻转颜色。 

输出是一个简单的可行性检查：是否存在可以生成整个序列的均匀条带宽度。 

约束条件$n \le 100000$意味着任何解决方案都必须是线性或近线性的。 一个$O(n^2)$尝试尝试每种可能的条带宽度并直接验证它需要检查$n$候选人，每个成本$O(n)$，导致$10^{10}$最坏情况下的操作。 这远远超出了可接受的限度。 甚至一个$O(n \log n)$解决方案是不必要的，因为结构可以在单遍中验证。 

一些边缘情况很容易被低估。 

例如，如果所有元素都相同$[1,1,1,1]$，正确答案是“YES”，因为它可以被视为覆盖整个数组的单个条带。 坚持至少两个交替段的幼稚实现可能会错误地拒绝这种情况。 

如果数组长度是奇数，并且我们尝试强制大于 1 的相等条带宽度，例如$[0,0,0,1,1]$，某些实现可能会错误地假设存在有效分段，而不检查最终块是否完整。 要求是全局可分性，而不是局部一致性。 

如果数组中的每个元素交替出现，例如$[0,1,0,1,0,1]$，条纹宽度必须为 1。任何假设条纹必须长于 1 的方法在这里都会失败。 

## 方法

 暴力方法会尝试所有可能的条带宽度$k$从 1 到$n$。 对于每位候选人$k$，我们将数组分成连续的长度段$k$并验证两个条件：每个段必须一致，且相邻段必须不同。 

这是有效的，因为它直接反映了有效斑马图案的定义。 然而，成本变得令人望而却步。 对于每个$k$，我们扫描整个数组，得到$O(n)$每个候选人的工作量以及$O(n^2)$最坏情况下的总复杂度。 和$n = 100000$，这太慢了。 

关键的观察是数组完全由其游程编码决定。 一旦我们将其压缩为具有相同值的连续块，问题就减少为检查所有游程长度是否相等。 

如果数组有效，则每次连续相同值的运行都必须与条带边界完美对齐。 这意味着没有任何运行可以跨条纹分割，也没有任何条纹可以合并多个不同长度的运行。 因此，所有游程必须具有完全相同的长度，除非总共只有一个游程。 

这将问题转化为简单的扫描，我们计算游程长度并验证均匀性。

 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 从左到右遍历数组，同时跟踪连续的相等值。 每次值发生变化时，记录刚刚结束的段的长度。 此步骤将输入压缩为游程长度，从而捕获与条带形成相关的所有结构信息。 
2. 存储第一个游程长度作为参考值$k$。 这表示候选条带宽度。 
3. 对于每个后续运行，将其长度与$k$。 如果任何运行不同，则结构无法划分为等宽条带，因此答案立即无效。 
4. 如果遍历完成且没有矛盾，则接受配置。 

关键思想是有效的斑马图案强制运行边界和条纹边界之间严格对齐。 如果两个连续的运行具有不同的长度，则任何条带宽度都会分割运行或合并不匹配的运行，这两者都违反定义。 

### 为什么它有效

 任何有效的解决方案都会将数组划分为等长的块，其中值交替。 每个块都是统一的，因此每次相同值的运行都必须完全包含在单个块中。 由于所有块具有相同的大小，因此每次运行也必须具有相同的长度。 这迫使游程和条纹之间形成一一对应，使得游程长度相等既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

runs = []

cur = a[0]
length = 1

for i in range(1, n):
    if a[i] == cur:
        length += 1
    else:
        runs.append(length)
        cur = a[i]
        length = 1

runs.append(length)

ok = True
for i in range(1, len(runs)):
    if runs[i] != runs[0]:
        ok = False
        break

print("YES" if ok else "NO")
```该实现直接在单次传递中构造游程长度。 该循环维护当前段并计算它持续的时间，直到发生更改。 每个已完成的运行都会附加到列表中。 

验证步骤故意被最小化：一旦我们有了游程长度，只有相等才重要。 第一个运行定义了条带宽度，其他每个运行都必须与其匹配。 

一个微妙的点是，我们不需要显式检查值的交替，因为运行构造已经通过更改点的定义保证了交替。

 ## 边缘情况

 单个常量数组，例如$[1,1,1,1]$恰好产生一次运行。 算法记录运行=$[4]$，并且由于不存在矛盾，因此返回 YES。 这符合单个条带有效的解释。 

交替数组，例如$[0,1,0,1]$生产运行$[1,1,1,1]$。 Equality holds across all runs, so stripe width 1 is inferred correctly, confirming that the method does not assume minimum stripe size.

 A case like$[0,0,0,1,1]$生产运行$[3,2]$。 在第二次运行时立即检测到不匹配，这表明即使存在局部交替，全局对齐也会失败。
