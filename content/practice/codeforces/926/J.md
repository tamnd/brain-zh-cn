 ## 解决方案

 ## 问题理解

 我们在数轴上维护一组不断增长的闭区间。 最初，什么也没有画。 一个接一个地添加片段，每次插入后，如果我们将迄今为止看到的所有片段相结合，我们想知道存在多少个不相交的黑色区域。 

如果两个线段重叠或什至只是在一个点接触，则它们构成同一区域，因为端点被认为是连接的。 因此，我们跟踪的结构不是单独的片段，而是重叠或相邻间隔的合并并集。 

天真的心智模型是想象将每个片段绘制到一条线上，然后计算存在多少个连续的黑色延伸。 每次插入后，我们在概念上需要合并任何重叠的绘制区域并计算剩余的单独块数。 

约束很大：最多 200,000 个段，坐标最多 10^9。 这立即排除了重复扫描整个段集或在坐标上维护密集数组的任何解决方案。 即使使用 O(n^2) 方法检查所有先前段的重叠也太慢，因为在一秒的时间限制内进行 200,000 次平方运算是不可行的。 

关键的困难在于间隔是动态的，并且可能以任意方式合并现有组件。 

一些边缘案例揭示了为什么简单的方法会失败。 

一个问题是忘记了接触端点合并组件。 例如，线段 (1,3) 和 (3,5) 形成单个组件。 一个简单的实现，使用严格的重叠检查，例如`l < r`而不是`l <= r`会错误地计算两个组件。 

另一个问题是重复计算合并。 假设我们已经有一个合并区间 [1,10]，然后插入 [3,5]。 简单的重叠检查可能会检测到多个存储段的重叠，并多次减少组件计数，除非我们仔细地将合并的间隔视为单个实体。 

第三个问题是顺序敏感性。 由于段按输入顺序到达，因此我们无法在不丢失增量需求的情况下每次对它们进行排序并重新计算所有内容。 

## 方法

 蛮力的想法很简单：维护合并的不相交区间的当前列表。 对于每个新线段，扫描所有现有间隔，合并那些与其相交或接触的间隔，删除它们，然后插入生成的合并间隔。 答案很简单，就是存储的间隔数。 

这是正确的，因为不变量是显式的：我们总是存储并集的不相交、完全合并的表示。 然而，每次插入可能需要扫描所有现有间隔，并且在最坏的情况下，每个间隔与许多其他间隔重叠或者需要重复的线性扫描。 这导致总体上的 O(n^2) 行为，因为每个新段可能需要与 O(n) 现有段合并。 

关键的观察是我们实际上不需要显式地维护完整的几何图形。 我们只需要连接组件的数量。 每个新段要么创建一个新组件，要么与一个现有组件合并，要么将多个组件合并为一个。 这正是一个动态区间合并问题，我们只关心连通性，而不关心结构。 

我们可以维护当前不相交区间的排序结构。 对于每个传入的片段，我们找到它将被插入的位置，然后在间隔重叠或接触时左右扩展，计算吸收了多少组件。 每个吸收的区间都会减少组件数量，最后我们插入合并的区间。 

这是有效的，因为在整个过程中每个间隔最多被删除一次。 尽管每次插入可能会扫描几个间隔，但删除的总数受到 n 的限制，因此在使用有序结构时，摊余复杂度为 O(n log n)。 

在Python中，由于我们没有内置的间隔平衡树，因此我们使用带有二分搜索的排序列表来模拟它`bisect`，接受清除仍然是线性摊销的，但由于单调合并行为而在约束下是可以管理的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最优（有序合并）| O(n log n) 摊销 | O(n) | 已接受 |

 ## 算法演练

 我们维护一个按起始坐标排序的不相交间隔列表，以及组件的运行计数。 

1. 初始化一个空的间隔列表并将组件计数设置为零。 此时线路上没有任何内容，因此答案为零。 
2. 对于每个传入的段 [l, r]，使用二分查找根据其左端点找到该段的插入位置。 这确保我们只检查附近可能重叠的间隔。 
3. 检查紧邻左侧的区间是否有可能与新线段重叠或接触的区间。 如果该间隔在 l 处或之后结束，则必须将其合并。 我们扩展新的段以覆盖它并将其从结构中删除，从而将组件数量减少一个。 
4. 从插入位置开始继续检查前向间隔。 只要下一个间隔在当前合并的右端点或之前开始，我们就将其合并。 每次合并都会吸收一个现有组件并缩小间隔列表。 
5. 删除所有重叠或接触的间隔后，将新合并的间隔插入到正确的位置，并将组件数加一。 这表示当前段创建的最终合并块。 
6. 处理完每个段后，输出当前的元件数量。 

每个步骤正确的原因是结构中的间隔始终是不相交且已排序的。 这确保所有重叠必须出现在插入点周围的连续块中。 

### 为什么它有效

 每时每刻，我们都将数轴划分为不相交的合并区间，表示连通分量。 每个新段要么完全位于现有区间内，要么将多个相邻区间合并为一个，或者形成一个新的孤立区间。 由于间隔保持排序且不相交，因此任何重叠或接触新段的间隔都必须位于列表的连续区域中，因此不会错过任何合并。 由于每次合并都会严格减少存储间隔的数量，因此组件计数与连接组件的真实数量保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import bisect

def solve():
    n = int(input())
    intervals = []
    res = []
    comp = 0

    for _ in range(n):
        l, r = map(int, input().split())

        # find insertion position
        i = bisect.bisect_left(intervals, (l, r))

        nl, nr = l, r

        # check left interval
        j = i - 1
        if j >= 0 and intervals[j][1] >= l - 0:
            nl = min(nl, intervals[j][0])
            nr = max(nr, intervals[j][1])
            intervals.pop(j)
            comp -= 1
            i -= 1

        # merge right side
        while i < len(intervals) and intervals[i][0] <= nr:
            nl = min(nl, intervals[i][0])
            nr = max(nr, intervals[i][1])
            intervals.pop(i)
            comp -= 1

        intervals.insert(i, (nl, nr))
        comp += 1
        res.append(str(comp))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该实现维护一个不相交间隔的排序列表。 二分查找找到一个候选插入点，然后我们向左和向右扩展以吸收所有重叠或接触的间隔。 每次删除一个间隔时，我们都会减少组件计数器，因为两个组件变成了一个。 最后，插入合并间隔将精确恢复整个合并块的一个组成部分。 

一个微妙的点是条件`intervals[j][1] >= l`。 这编码了接触端点被视为已连接的规则，因此必须包括相等性。 另一个微妙之处是调整索引`i`弹出左侧间隔后，因为列表发生了变化。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) 摊销 | 每个间隔最多插入和删除一次，每次插入都进行二分搜索 |
 | 空间| O(n) | 存储当前不相交间隔集 |

 该结构确保虽然单个插入可能会触发多次合并，但每个间隔最多参与一次删除，因此总工作量在对数搜索开销范围内保持线性。 这非常适合 n 高达 200,000 的限制。

 ## 边缘情况

 关键的边缘情况是新段仅在单个点处接触现有区间。 例如，当 [1,5] 已存在时插入 [5,7] 必须将它们合并为一个组件。 该算法处理这个问题是因为左检查使用`>= l`，确保端点接触被视为重叠。 

另一种边缘情况是当一个段在一次插入中桥接多个不相交的间隔时。 例如，现有区间 [1,2] 和 [4,5]，插入 [2,4] 必须将两者合并。 右侧的扩展循环继续合并，直到没有重叠为止，确保两者都被吸收在单个操作中。 

最后一个微妙的情况是当一个段完全包含在现有间隔中时。 将 [3,4] 插入 [1,10] 不应更改组件数量。 该算法处理此问题是因为左侧间隔将吸收该段，并且除了用相同或更大的间隔替换现有间隔之外不会发生新的插入，从而使组件计数保持不变。
