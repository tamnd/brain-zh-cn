 ## 解决方案

 ## 问题理解

 我们得到一个排列成一行的正整数序列。 该过程会重复查找两个相邻的相同数字。 每当存在这样的对时，就会选择最左边的这样的对，删除两个元素，并在其位置插入等于其值加一的单个元素。 这会通过将序列长度减一来改变序列长度，并且还可以创建新的相邻相等对，因此该过程将继续，直到没有两个相邻元素相等。 

任务是在执行所有可能的合并后计算最终的稳定序列。 

序列最多可包含 200,000 个元素的约束立即排除了任何重复扫描数组并在每次操作的线性时间内执行删除的解决方案。 在最坏的情况下，每次合并都会将长度减少一，因此可能存在 O(n) 操作，并且每次也扫描最左边对的简单模拟可能会降级为 O(n²)，这太慢了。 

一个更微妙的问题是合并可以级联。 单个合并可以生成与其新邻居匹配的值，从而强制重复链接合并。 例如，在像 1, 1, 2, 2 这样的序列中，合并第一对会创建一个 2，这可能会立即形成另一个合并。 任何正确的方法都必须考虑这些级联，而无需重新启动全面扫描。 

另一种边缘情况是相等的值最初不相邻，但仅在多次合并后才变得相邻。 在这种情况下，仅查看本地且从不重新访问较早位置的天真的贪婪指针策略将失败。 

## 方法

 直接模拟将从左到右重复扫描数组，以找到第一次出现的相等邻居，执行合并，然后重新开始扫描。 这是正确的，因为它与流程定义完全匹配。 然而，每次扫描的时间复杂度为 O(n)，我们可能会执行 O(n) 合并，从而在最坏的情况下导致 O(n²) 行为，例如重复崩溃的相同元素的长期运行。 

关键的观察结果是，该过程仅修改最近插入点周围的局部结构。 一旦我们从左到右处理元素，任何涉及较早元素的潜在合并将始终由最近形成的值触发。 这建议维护一个表示当前缩减前缀的结构，并且仅在附加新元素时才在本地做出反应。 

堆栈自然地编码了这个想法。 我们从左到右处理元素，将它们推入堆栈。 每当顶部的两个元素变得相等时，我们将它们合并为一个元素，并且值加一。 这个新元素可能再次等于堆栈中的前一个元素，因此我们必须继续合并，直到顶部恢复稳定。 这种重复的局部折叠准确地模拟了如果我们总是合并原始序列中最左边的可用对会发生什么。 

重要的概念转变是，尽管原始规则全局引用最左边的对，但每次合并仅影响连续区域，并且一旦我们按顺序处理元素，最左边的活动区域始终位于堆栈表示的顶部。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力模拟 | O(n²) | O(n) | 太慢了|
 | 堆栈合并| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个堆栈，表示处理数组前缀后当前的缩减序列。

1. 从空堆栈开始。 我们将从左到右处理输入。 
2. 对于数组中的每个元素x，将x 压入堆栈。 这表示将其附加到当前序列。 
3. 每次入栈后，检查栈中最后两个元素是否相等。 如果不是，则在此位置不可能进行合并，因此我们继续处理下一个输入元素。 
4. 如果最后两个元素相等，则删除这两个元素并用等于其值加一的单个元素替换它们。 
5. 执行此替换后，新的顶部元素现在可能等于堆栈中的前一个元素，因此只要最后两个元素相等，我们就重复检查并再次合并。 
6. 继续此过程，直到堆栈顶部稳定，然后继续处理下一个输入元素。 
7、处理完所有元素后，堆栈代表最终的序列。 

顶部的重复合并至关重要，因为每次合并都可以创建一个新的向上“进位”，类似于数字系统中相同的相邻数字组合和传播的加法。 

### 为什么它有效

 堆栈保持不变式，即在处理输入的前 k 个元素后，它表示完全解析可能完全在该前缀内发生的所有合并的确切结果。 整个过程中的任何合并都必须涉及相邻元素，这些元素在它们变得相等时对应于该结构的顶部。 由于合并从不依赖于未来的元素，并且仅向上折叠连续的相等块，因此原始过程中的每个有效操作都由堆栈顶部的相应折叠来镜像。 这确保了不会错过任何合并，也不会引入无效的合并。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    st = []
    
    for x in a:
        st.append(x)
        
        while len(st) >= 2 and st[-1] == st[-2]:
            x = st[-1]
            st.pop()
            st.pop()
            st.append(x + 1)
    
    print(len(st))
    print(*st)

if __name__ == "__main__":
    solve()
```实现直接遵循堆栈流程。 每个元素都会追加一次，并且每个合并操作都会立即在堆栈顶部处理。 变量重用`x`确保在合并两个相等的值后，递增的结果正确地输入到进一步的潜在合并中。 

一个微妙的点是我们永远不会从头开始扫描。 所有必要的传播都是通过堆栈顶部的重复检查来处理的，这在保持复杂性线性的同时保留了正确性。 

## 工作示例

 考虑序列 5, 2, 1, 1, 2, 2。 

| 步骤| 输入| 堆栈状态|
 | ---| ---| ---|
 | 1 | 5 | [5]|
 | 2 | 2 | [5, 2] |
 | 3 | 1 | [5,2,1]|
 | 4 | 1 | [5, 2, 2] → 合并 → [5, 3] |
 | 5 | 2 | [5,3,2]|
 | 6 | 2 | [5, 3, 3] → 合并 → [5, 4] |

 这显示了本地合并如何触发级联，以及堆栈如何自然地捕获重复压缩，而无需重新扫描序列的早期部分。 

现在考虑 1, 1, 1, 1。 

| 步骤| 输入| 堆栈状态 |
 | ---| ---| ---|
 | 1 | 1 | [1] |
 | 2 | 1 | [2] |
 | 3 | 1 | [2, 1] |
 | 4 | 1 | [2, 2] → [3] |

 此示例显示了一个完整的链式反应，其中多个合并向上传播，最终将整个序列折叠成单个值。 

第二个示例表明合并不是独立事件，并且必须在当前结构的边界处反复重新考虑中间结果。

 | ---| ---| ---|
 | 时间 | O(n) | 每个合并事件都会将每个元素推送一次并最多弹出一次，并且每次合并都会减少总堆栈大小。 |

 ## 边缘情况

 一个关键的边缘情况是当合并向上传播多个步骤时，在堆栈中创建一系列连续的相等值。 例如，在输入 1, 1, 2, 2, 3 中，处理会创建中间状态，其中合并 1,1 生成 2，然后与相邻的 2 合并，依此类推。 堆栈会正确处理此问题，因为每次合并后，它都会重新检查顶部对，以确保立即解决任何新创建的相等性。 

另一个微妙的情况是，重复增量导致原始数组中相距很远的值在多次合并后变得相等。 由于该算法从不丢弃超出堆栈边界的历史信息，因此当这些值在简化结构中变得相邻时，所有此类潜在的交互都会被自然捕获。
