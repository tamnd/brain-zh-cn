 ## 解决方案
 ## 问题理解

 我们在坐标网格上移动`(0, 0)`到`(n, m)`。 

每一秒我们都可能将第一个坐标增加一，将第二个坐标增加一，或者留在原处。 动作后的位置是针对该秒发射的所有轨道炮射击进行检查的位置。 

带坐标的水平拍摄`x`杀死第一个坐标等于的每个位置`x`。 带坐标的垂直拍摄`y`杀死第二个坐标等于的每个位置`y`。 

目标是达到`(n, m)`尽早，而无需站在相应时间被射击击中的牢房上。 

第一个观察来自运动结构。 如果我们目前处于`(i, j)`并一直在等待`k`到目前为止，那么当前时间就完全确定了：$$t = i + j + k$$每次垂直移动都会增加`i`，每次水平移动都会增加`j`，每次等待都会增加`k`。 

这些限制看起来很不寻常。 网格最多可包含`10^4`所有测试用例中的单元总数，足够大，每个网格单元的状态都很好。 拍摄次数最多为`100`，很小。 拍摄时间可以长达`10^9`，因此任何明确模拟时间的解决方案都是不可能的。 

关键问题是我们需要考虑多少次等待。 由于只有`r ≤ 100`镜头，最佳路径永远不需要更多`r`等待。 这将状态空间从潜在的数十亿个时刻减少到仅大约`100`层。 

一些边缘情况很容易被错误处理。 

假设一个镜头发生在很长一段时间内：```
1 1
1
1000000000 1 0
```答案依然是`2`。 尝试建立最长拍摄时间的时间线的解决方案将是极其缓慢的。 

另一个微妙的情况是等待一个单元格。```
1 1
1
1 1 0
```时`1`， 排`0`被枪杀。 我们不能停留在`(0,0)`在第一秒期间。 唯一安全的举动是立即离开。 仅在移动后检查单元格但忽略等待的解决方案将错误地允许站在那里。 

第三种情况发生在整个区域被同时覆盖时。```
3 3
6
2 1 0
2 1 1
2 1 2
2 2 0
2 2 1
2 2 2
```时`2`，每个可到达的位置都被破坏。 没有路径可以生存，所以答案是`-1`。 局部贪婪决策无法检测到这一点； 我们需要一个全局可达性计算。 

## 方法

 蛮力观点是将状态视为`(x, y, time)`and run BFS. 从每个状态我们可以向下移动、向右移动或等待。 该方法是正确的，因为所有操作都花费一秒钟，并且 BFS 找到最早到达的。 

The problem is the time dimension. Shot times reach`10^9`，所以即使按时间存储可达状态也是不可能的。 

关键的观察是时间不是独立的。 If we know the position`(x, y)`以及多少等待`k`已经使用过，那么当前时间正是$$x + y + k.$$这用非常小的等待坐标代替了巨大的时间坐标。 

为什么我们可以限制`k`至多`r`？ 每一次额外的等待只是为了避免一些镜头。 最多有`r`总共拍摄了多少次，所以考虑超过`r`等待永远无法改进最优解决方案。 这是使问题得以解决的中心压缩。 

现在我们在州上建立一个DP`(x, y, k)`。 

状态意味着：

 “我们可以站在立场上吗？`(x, y)`准确使用后`k`等待，同时在迄今为止的所有射击中幸存下来？”

 来自`(x, y, k)`我们可以来自：`(x-1, y, k)`通过垂直移动。`(x, y-1, k)`通过水平移动。`(x, y, k-1)`等待一秒钟。 

唯一的附加条件是当前状态本身不能被及时杀死$$t = x + y + k.$$状态数量仅$$(n+1)(m+1)(r+1),$$在最坏的测试情况下大约为 100 万，完全在限制范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解`(x,y,time)`| 由于时间原因不可能`10^9`| 不可能| 太慢了 |
 | DP 开启`(x,y,waits)`|`O(nmr)`|`O(nmr)`| 已接受 |

 ## 算法演练

 1.创建三维数组`free[x][y][k]`。`free[x][y][k]`告诉状态是否`(x, y, k)`是安全的。 
2. 对于每次射击，标记将被该射击杀死的所有状态。 

如果水平射击击中行`x = coord`在某个时间`t`，那么每个状态都满足$$x = coord,\quad t = x + y + k$$是被禁止的。 

重新排列给出$$k = t - coord - y.$$对于每一列`y`，如果这个`k`在于`[0,r]`，将状态标记为不安全。 
3. 类似地处理垂直镜头。 

对于专栏拍摄`y = coord`和时间`t`:$$k = t - coord - x.$$与该方程匹配的每个有效状态都变得不安全。 
4.创建DP数组`dp[x][y][k]`。`dp[x][y][k] = True`意味着状态是可达且安全的。 
5. 初始化`dp[0][0][0] = True`。 
6. 按升序遍历所有状态`x`,`y`， 和`k`。 

如果该状态不安全，请跳过它。 

否则，请从以下位置到达：

 -`(x-1, y, k)`-`(x, y-1, k)`-`(x, y, k-1)`每当这些状态可以到达时。 
7. 检查所有状态`(n, m, k)`。 

如果可以到达，到达时间为$$n + m + k.$$选择最小的这样的时间。 
8. 如果不存在可达的终端状态，则输出`-1`。 

### 为什么它有效

 不变的是`dp[x][y][k]`当存在到达位置的有效动作序列时为真`(x,y)`使用后`k`等待并在遇到的每一次射击中幸存下来。 

每个法律行动都会改变三个数量中的一个`x`,`y`， 或者`k`1，因此每个有效路径对应于一系列 DP 转换。 相反，每次 DP 转换都代表一项法律行动。 由于预先删除了不安全状态，因此每个可达的 DP 状态都对应于一个可生存的游戏状态。 

因为时间是唯一决定的`x+y+k`，每个镜头约束都会在正确的时刻进行检查。 因此，DP 精确地表征了所有有效路径，并且最小可达值`n+m+k`是最早可能到达的时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        r = int(input())

        free = [[[True] * (r + 1) for _ in range(m + 1)]
                for _ in range(n + 1)]

        for _ in range(r):
            tt, d, coord = map(int, input().split())

            if d == 1:
                x = coord
                if 0 <= x <= n:
                    for y in range(m + 1):
                        k = tt - x - y
                        if 0 <= k <= r:
                            free[x][y][k] = False
            else:
                y = coord
                if 0 <= y <= m:
                    for x in range(n + 1):
                        k = tt - y - x
                        if 0 <= k <= r:
                            free[x][y][k] = False

        dp = [[[False] * (r + 1) for _ in range(m + 1)]
              for _ in range(n + 1)]

        dp[0][0][0] = free[0][0][0]

        for x in range(n + 1):
            for y in range(m + 1):
                for k in range(r + 1):
                    if x == 0 and y == 0 and k == 0:
                        continue

                    if not free[x][y][k]:
                        continue

                    ok = False

                    if x > 0 and dp[x - 1][y][k]:
                        ok = True
                    if y > 0 and dp[x][y - 1][k]:
                        ok = True
                    if k > 0 and dp[x][y][k - 1]:
                        ok = True

                    dp[x][y][k] = ok

        ans = -1

        for k in range(r + 1):
            if dp[n][m][k]:
                ans = n + m + k
                break

        print(ans)

solve()
```预处理阶段将镜头信息直接转换为禁止的 DP 状态。 这是解决方案中最优雅的部分。 我们不是询问一个州是否被枪击中，而是反转方程并直接标记每个将被杀死的州。 

DP 完全使用游戏中可用的三个动作。 垂直移动会发生变化`x`，水平移动变化`y`，并等待变化`k`。 

一个容易犯的错误就是忘记等待是一种真正的转变。 没有从过渡`(x,y,k-1)`到`(x,y,k)`，算法永远不会发现故意延迟自身的路径。 

另一个微妙的点是初始化。 如果`(0,0,0)`本身是禁止的，启动状态必须被视为无法到达。 

最终的答案是最小可达值`n+m+k`，这正是到达时间。 

## 工作示例

 ### 示例 1

 输入：```
1 3
4
1 2 0
2 2 1
3 2 2
4 1 1
```相关可达状态：

 | 职位| 等待 k | 时间 |
 | --- | --- | --- |
 | (0,0) | (0,0) | 0 | 0 |
 | (0,1)| 0 | 1 |
 | (0,2) | 0 | 2 |
 | (0,3) | 0 | 3 |
 | (0,3) | 1 | 4 |
 | (1,3) | 1 | 5 |

 搬迁至`(1,3)`在某个时间`4`将是致命的，因为行`1`被射中的时间`4`。 等待一秒将到达时间更改为`5`，确保道路安全。 

回答：`5`。 

该跟踪说明了为什么等待必须是状态空间的一部分。 最短几何路径有长度`4`，但生存需要多一秒。 

### 示例 2

 输入：```
3 3
6
2 1 0
2 1 1
2 1 2
2 2 0
2 2 1
2 2 2
```时`2`，每个状态有行`0..2`或列`0..2`被摧毁了。 

| 时间 | 安全可达状态|
 | --- | --- |
 | 0 | (0,0) | (0,0) |
 | 1 | 等待后 (1,0)、(0,1)、(0,0) |
 | 2 | 无 |

 由于每个可能的状态都可以通过时间到达`2`被禁止，DP 不能进一步传播。 

回答：`-1`。 

此示例确认 DP 正确处理消除所有可能路径的同时约束。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(nmr)`| 每一个 DP 状态`(x,y,k)`|
 | 空间|`O(nmr)`| 商店`free`和`dp`数组|

 自从`r ≤ 100`和总价值`n·m`所有测试用例最多是`10^4`，状态总数大致为`10^6`。 这完全符合时间和内存的限制。

def run(inp: str) -> str:

    out = []

    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        r = int(input())

                for _ in range(n + 1)]

            tt, d, coord = map(int, input().split())

                for y in range(m + 1):
                    k = tt - coord - y
                    if 0 <= k <= r:
                        free[coord][y][k] = False
            else:
                for x in range(n + 1):
                    k = tt - coord - x
                    if 0 <= k <= r:
                        free[x][coord][k] = False

        dp = [[[False] * (r + 1) for _ in range(m + 1)]
              for _ in range(n + 1)]

        dp[0][0][0] = free[0][0][0]

        for x in range(n + 1):
            for y in range(m + 1):

        for k in range(r + 1):
            if dp[n][m][k]:
                ans = n + m + k
                break

        out.append(str(ans))

    return "\n".join(out)

 ## 边缘情况

 考虑：```
1
1 1
1
1000000000 1 0
```枪击发生的时间远远超出了任何合理的到达时间。 在预处理期间，计算值`k`很大并且落在外面`[0,r]`，因此没有 DP 状态被标记为禁止。 DP找到正常路径长度`2`和输出：```
2
```现在考虑：```
1
1 1
1
1 1 0
```时`1`, 每个位置都有行`0`被摧毁了。 国家`(0,0,1)`被禁止，所以立即等待是不可能的。 DP反而达到了`(1,0,0)`一秒钟后然后`(1,1,0)`两秒后。 答案是：```
2
```最后：```
1
3 3
6
2 1 0
2 1 1
2 1 2
2 2 0
2 2 1
2 2 2
```每个时间可达的状态`2`被标记为禁止。 任何 DP 转换都不能跨越该层。 目的地永远无法到达，并且算法正确返回：```
-1
```这些示例涵盖了三个最常见的实施错误：处理大量的拍摄时间、错误地处理等待以及未能对同时致命约束进行建模。
