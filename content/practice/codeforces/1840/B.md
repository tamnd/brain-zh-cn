 ## 解决方案
 ## 问题理解

 我们被要求数出 Toma 在二元主题咖啡馆中选择甜点的方式有多少种。 每个甜点的成本是 2 的幂：第一个甜点花费 1 个硬币，第二个 2 个硬币，第三个 4 个硬币，依此类推，按照顺序$2^0, 2^1, 2^2, \dots, 2^{k-1}$。 托马有预算$n$并且不会多次购买任何甜点。 目标是确定他能买得起多少甜点子集，包括他不买任何东西的空子集。 

输入指定多个测试用例，每个测试用例都有自己的$n$和$k$。 约束条件允许$n$和$k$去到$10^9$。 这立即排除了任何枚举所有子集或总和的解决方案，因为子集的数量$k$甜点是$2^k$，对于$k$接近十亿。 

边缘情况包括预算小于最便宜的甜点的情况。 例如，如果$n = 1$和$k = 1$，唯一负担得起的子集是空子集和第一个甜点。 另一个微妙的情况出现时$n$大于所有的总和$k$甜点； 在这里，每个子集都是负担得起的，答案正是$2^k$。 

## 方法

 蛮力方法将枚举甜点的所有子集并将其成本相加，计算那些不超过$n$。 这适用于非常小的$k$，但即使$k = 30$产生$2^{30} \approx 10^9$子集，太多了。 为了$k = 10^9$，这是不可能的。 

关键的见解是利用成本的二元结构。 每个甜点的成本是 2 的幂，任何 2 的不同幂的和都精确对应于一个二进制数，其中每一位代表是否选择了甜点。 然后问题就简化为计算 0 到 0 之间的整数有多少个$2^k - 1$（子集总和的全部范围）小于或等于$n$。 我们无法计算$2^k$直接为大$k$，但我们可以观察到，如果$2^k \le n+1$， 全部$2^k$子集是可以承受的。 否则，子集的数量恰好是$n+1$，因为子集的和是从 0 到总和的连续整数，并且我们只需要那些不超过$n$。 

这就给出了一个简单、直接的公式：Toma 可以购买甜点的方式有：$\min(n + 1, 2^k)$。

 | ---| ---| ---| ---|
 | 蛮力 | O(2^k) | O(2^k) | O(1) | O(1) | k > 30 太慢 |
 | 最佳| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量，$t$。 我们将分别遍历每个案例。 这是多个查询的标准输入处理。 
2. 对于每个测试用例，请阅读$n$和$k$。 这里$n$是预算，并且$k$是甜点的数量。 
3. 计算$2^k$。 如果$k$很大，这可能会溢出典型的整数类型，但 Python 可以处理任意大小的整数。 然而，我们只需要与它进行比较$n+1$，所以一旦值超过我们就可以停止相乘$n+1$以节省计算量。 
4. 将答案计算为以下最小值$n+1$和$2^k$。 这说明了两种情况：$n$小于所有甜点的总和，或者$n$可以购买每个子集。 
5. 打印每个测试用例的答案。 

为什么有效：二次方成本确保甜点的每个子集都对应于唯一的整数和。 最小和为 0，并且总和按 2 的幂的所有组合而增加。 因此，计数总计为$n$相当于取最小值$n+1$和$2^k$，因为总和是从 0 到所有甜点总和的连续整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    # Compute 2^k safely without overflow using a loop if necessary
    power = 1
    for _ in range(k):
        if power > n:
            break
        power *= 2
    print(min(n + 1, power))
```该解决方案读取所有测试用例，计算$2^k$小心避免不必要的大整数，然后使用 min 函数确定可负担子集的数量。 一个微妙的点是，一旦$2^k$超过$n$，进一步的乘法是不必要的，因为最小值已经是$n+1$。 Python 处理大整数，但这种早期中断确保了极值的效率$k$。

 ## 边缘情况

 如果$n = 0$，算法正确输出 1，对应于空子集。 例如，$n = 0, k = 10$产生 1，因为只有空子集是可以承受的。 如果$k = 1$和$n = 1$，算法输出 2，因为空集和单个甜点都在预算范围内。 在每种情况下，循环都会正确地乘以 2 的幂，但只要超过$n+1$，即使在$k$非常大。
