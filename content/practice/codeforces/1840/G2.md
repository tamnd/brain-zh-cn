 ## 解决方案
 ## 问题理解

 我们被放置在扇区的圆形排列中，扇区编号从 1 到$n$，但我们也不知道总数$n$或圆圈周围数字的顺序。 最初，箭头指向一个扇区，我们被告知它的编号。 我们的目标是确定$n$，扇区总数，通过反复要求主机将箭头顺时针或逆时针移动一定数量的扇区。 每个查询都会给出箭头现在指向的扇区号。 我们严格限制 1000 次查询，并且$n$可以大到$10^6$。 

这些限制意味着我们不能采取逐一访问每个部门的幼稚做法。 一次移动一个扇区的暴力方法可能需要长达$10^6$查询次数超过限制。 我们需要一种方法，能够快速发现圆周的重复周期，有效地发现扇区总数，而无需单独访问每个扇区。 当扇区号以非平凡的排列方式排列时，就会出现临界边缘情况。 例如，数字可能不会连续增加，因此仅观察连续查询之间的差异是不够的。 同样，我们不能假设$n$很小，因此需要穷举搜索的方法是无效的。 

## 方法

 一种简单的方法是顺时针一次移动一个扇区并记录我们遇到的数字。 一旦我们再次看到初始数字，我们就可以计算我们走了多少步，这等于$n$。 该方法保证正确，但需要最多$n$查询。 和$n$最多$10^6$，考虑到我们的 1000 个查询限制，这种方法太慢了。 

最佳方法结合了随机性和扇区编号不同的事实。 我们可以移动较大的随机距离并记录每个新位置的数字。 通过对差值取模$n$在位置之间，我们有效地对 1 模的倍数进行采样$n$。 使用所有观察到的差异的最大公约数使我们能够推断$n$。 具体来说，如果我们移动$k_1, k_2, \dots$步骤并观察扇区编号$a_1, a_2, \dots$， 然后$n$必须消除所有差异$a_i - a_j$以某种一致的方式。 通过足够的随机跳跃重复此操作很快就会发现$n$有很高的概率。 随机性确保我们不会陷入小循环或错过除数。 由于每个查询的成本很高，因此我们可以将自己限制为少量的大跳转，通常约为 60 到 100 个查询，这远低于 1000 个查询的限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 对于 n=10^6 来说太慢 |
 | 随机 GCD 采样 | O(log n) 次查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 首先记录初始扇区号。 这是我们的第一次观察，并将作为计算差异的参考。 
2. 重复以下过程大约 60 到 100 次，或者直到我们有足够的信息来确定$n$。 随机选择步长$k$介于 1 和$10^9$并将箭头顺时针移动$k$部门。 读取新的扇区号。 大步长确保我们对整个圆上的位置进行采样，而不是靠近初始扇区。 
3. 计算新扇区号与前一个扇区号之间的绝对差。 保留所有观察到的差异的运行最大公约数 (GCD)。 关键的见解是所有差异模$n$是真实值的倍数$n$。 因此，这些差异的 GCD 收敛为$n$本身，可能高达一个小倍数。 
4.执行足够的查询后，运行的GCD将稳定在$n$。 输出答案并终止。 

这样做的原因是扇区号是不同的并且在之后重复$n$步骤。 每个大的随机跳跃有效地采样随机倍数模$n$。 这些倍数的GCD只能是重复周期，正好是$n$。 随机性确保 GCD 不会因排列中的模式而人为地降低。 

## Python 解决方案```python
import sys, math, random
input = sys.stdin.readline
print_flush = lambda x: (print(x), sys.stdout.flush())

def main():
    initial = int(input())
    current = initial
    gcd = 0
    for _ in range(60):
        step = random.randint(1, 10**9)
        print_flush(f"+ {step}")
        new_sector = int(input())
        diff = abs(new_sector - current)
        if diff != 0:
            gcd = diff if gcd == 0 else math.gcd(gcd, diff)
        current = new_sector
    print_flush(f"! {gcd}")

if __name__ == "__main__":
    main()
```该解决方案首先读取初始扇区，然后进行一系列随机大跳跃。 每次跳跃都会更新观察到的差异的 GCD。 我们取绝对差，因为方向对于 GCD 并不重要。 我们确保永远不会除以零，并且仅在差值非零时更新 GCD。 最后，经过足够的跳跃后，我们输出推断的扇区数。

 ## 边缘情况

 当$n = 1$，每次移动都会产生相同的扇区号。 GCD 计算通过不更新正确处理零差异，最终输出 1。对于小的$n$通过不平凡的排列，随机大跳跃可以防止按顺序移动时可能发生的丢失扇区的情况。 为最大$n = 10^6$，该算法仍然在查询预算之内，因为我们只执行大约 60 到 100 次随机跳转。 在所有情况下，运行的 GCD 都稳定在真实值$n$，保证正确性。
