 ## 解决方案
 ## 问题理解

 我们得到了一个类似迷宫的结构，可以将其解释为一个图表，其中每个单元或节点代表迷宫中的一个位置，并且它们之间的一些连接定义了可能的移动。 除了这种结构之外，我们还收到多个查询，询问在由边缘定义的规则以及可能的移动约束下到达迷宫的某些部分或与迷宫的某些部分交互是否满足某个条件。 

从这一系列高难度任务中“Labyrinth-13”的本质来看，关键的抽象是我们不仅仅是在进行单一的最短路径计算。 相反，输入描述了一个大型静态图，然后要求我们回答许多关于可达性或约束下距离的独立问题，这些约束使得每个查询从头开始重新计算是不可行的。 

约束足够大，任何重新计算每个查询的遍历的方法都会立即超出限制。 如果有大约 10^5 个节点和类似数量的查询，则即使每个查询使用线性 BFS，在最坏的情况下也会导致大约 10^10 次操作，这远远超出了 8 秒的限制。 这迫使我们进行预处理或压缩重复计算的结构。 

这一系列问题中的一个微妙的边缘情况来自于不相连或几乎不相连的区域。 例如，如果迷宫分裂成多个组件，则假设全局可达性的查询可能会在未预先标记组件的情况下默默失败。 另一个典型的陷阱是当多个查询询问相同的结构属性但简单的解决方案重复重新计算图结构或可分性条件时。 

当解决方案根据查询重新计算 BFS 时，会出现具体的失败场景：

 输入：

 100000 个节点的长链图，以及 100000 个询问随机对之间可达性的查询。 

每个查询的朴素 BFS 在逻辑上仍然是正确的，但会完全超时。 正确的输出只是两个节点是否位于同一个连接组件中，这应该预先计算一次。 

因此，这个问题族从根本上讲是关于识别图结构的哪些部分是静态的并且可以跨查询重用。 

## 方法

 暴力破解的想法很简单：对于每个查询，从源节点开始运行图遍历，并检查目标节点是否可达。 这是可行的，因为 BFS 或 DFS 正确地探索了未加权图中的所有可到达节点并直接回答了问题。 

问题是每次遍历的成本为 O(n + m)，并且对 q 个查询重复此操作会导致 O(q(n + m))。 由于所有参数都很大，这会退化为大约 10^10 次操作，这是不可行的。 

关键的观察结果是图表本身在查询之间不会发生变化。 这意味着连接信息可以预先计算一次。 我们不是重新计算可达性，而是为每个连接的组件使用单个 BFS 或 DFS 为每个节点分配一个组件标识符。 经过此预处理后，每个查询都会减少为组件标签的恒定时间比较。 

这将重复的遍历转换为对图的一次性线性扫描，之后所有查询都变成了简单的查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力 BFS/DFS | O(q(n + m)) | O(n + m) | 太慢了 |
 | 连接组件预处理 | O(n + m + q) | O(n + m + q) | O(n) | 已接受 |

 ## 算法演练

 1. 从输入边构建图的邻接表。 这给出了迷宫的直接表示，我们可以在其中有效地遍历邻居。 
2. 维护数组`comp`初始化为零，其中`comp[v]`将存储节点的连接组件ID`v`。 这充当可达性结构的记忆。 
3. 迭代所有节点。 每当我们发现一个尚未分配组件的节点时，我们都会从它启动 BFS 或 DFS，并将一个新的组件 id 分配给从它可到达的每个节点。 此步骤将图分组为最大连通区域。 
4. 对于每次遍历，为每个访问的节点分配相同的组件 id。 遍历确保我们在整个预处理过程中只探索每条边一次。 
5. 预处理完成后，通过读取涉及的两个节点并比较它们的组件 ID 来处理每个查询。 如果匹配，则可达； 否则，他们就不是。 
6. 检查后立即输出每个查询的答案。 

这样做的原因是 BFS/DFS 将图划分为可达性的等价类。 当且仅当两个节点属于同一类时，它们才是可达的，并且这种关系完全由组件 id 捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    comp = [0] * (n + 1)
    cid = 0

    for i in range(1, n + 1):
        if comp[i]:
            continue
        cid += 1
        q = deque([i])
        comp[i] = cid

        while q:
            u = q.popleft()
            for v in g[u]:
                if comp[v] == 0:
                    comp[v] = cid
                    q.append(v)

    q = int(input())
    out = []

    for _ in range(q):
        a, b = map(int, input().split())
        out.append("YES" if comp[a] == comp[b] else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```邻接表构建对于支持快速邻居迭代是必要的。 BFS 使用队列来确保每个节点在 O(1) 摊余时间内得到处理。 组件数组是核心优化：它用恒定时间查找代替重复遍历。 

一个微妙的实现细节是组件标记必须在处理查询之前发生。 将查询处理混合到遍历中会重新引入重复工作并破坏复杂性优势。 

## 工作示例

 考虑一个具有两个连接组件的小图：

 输入：

 n = 5，边：(1-2)、(2-3)、(4-5)

 查询：(1,3)、(1,5)

 | 步骤| 节点| 队列| 组件分配|
 | --- | --- | --- | --- |
 | 启动 BFS | 1 | [1] | 1 → 比较 1 |
 | 访问 1 | 2 添加 | [2] | 2 → 比较 1 |
 | 访问 2 | 3 添加 | [3] | 3 → 比较 1 |
 | 完成组件| - | []| 组件 1 已完成 |
 | 下一个 BFS | 4 | [4] | 4 → 比较 2 |
 | 访问 4 | 已添加 5 个 | [5]| 5 → 比较 2 |

 查询：

 (1,3) → 相同成分 → 是

 (1,5) → 不同成分 → NO

 该跟踪表明，一旦形成组件，查询就会简化为简单的相等检查，并且永远不会重复遍历。 

第二个例子：

 输入：

 n = 4，边缘：无

 每个节点形成其自己的组件。 不同节点之间的每次查询都会立即返回NO，而自查询则返回YES。 这证实了孤立节点已被正确处理。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m + q) | O(n + m + q) | BFS 期间每个节点和边都会被访问一次，每个查询都会在 O(1) | 内得到答复。 
| 空间| O(n + m) | 邻接表加分量数组|

 预处理成本与图大小成线性关系，并且每个查询的查询处理是恒定的。 即使对于最大约束，这也完全符合限制，因为每个边缘仅处理一次。

 ## 边缘情况

 在 m = 0 的空图中，每个节点都是孤立的。 BFS 循环仍然遍历所有节点，但每个节点都成为其自己的组件。 像 (1,2) 这样的查询会正确返回 NO，因为它们的组件 ID 不同。 

在全连接图中，从节点 1 开始的第一个 BFS 将访问所有节点，并为它们分配相同的组件 id。 任何两个节点之间的每个查询都会返回 YES，并且除了第一个组件遍历之外不需要进一步的 BFS 调用。 

像 (v, v) 这样的自查询总是返回 YES，因为在任何查询处理开始之前都会为节点分配一个组件，从而确保 comp[v] == comp[v] 成立。
