 ## 解决方案
 ## 问题理解

 我们有一个固定的学生序列，每个学生都与一个正的时间值相关。 如果一个学生被允许通过考试，他们就会消耗一定量的时间，并且这个时间严格按照顺序累积。 如果一个学生失败了，他们就会从序列中消失，并且对总时间没有任何贡献。 

对于每个位置 i，我们只考虑从 1 到 i 的学生，并提出一个单独的问题：我们必须从整个系统中移除的最少学生数量是多少，这样学生 i 仍然存在，并且所有剩余学生在 i 之前花费的总时间不超过 M。每个 i 移除的学生的选择可以不同，并且一个 i 的决策不会影响另一个学生。 

关键的困难在于，删除序列中稍后的学生对学生 i 没有帮助，只有删除前 i 个学生才关系到可行性。 此外，i 之后的删除与 i 的前缀和约束无关。 

约束 n 高达 200000 意味着任何二次甚至接近二次的每个位置重新计算都太慢。 即使 O(n^2) 方法也意味着大约 4e10 次操作，这是不可行的。 解决方案必须跨前缀重用结构，并在接近恒定或对数的时间内处理每个 i。 

天真的思维的非明显失败案例是假设我们应该始终首先删除最小的时间。 这种直觉是颠倒的。 删除小元素会低效地减少总和，因此基于最小值的贪心方法可能会失败。 

例如，假设 M = 10，前缀为 [9, 8, 1]。 为了使最后一个元素可行，与删除 9 或 8 相比，删除 1 是没有用的。首先删除最小值的简单策略将需要多次删除，而单个大删除就足够了。 

另一个微妙的陷阱是忘记在位置 i 的优化中决不能删除第 i 个学生。 对称地处理所有元素会产生错误的答案。 

## 方法

 蛮力的想法很简单。 对于每个 i，考虑前 i 个学生中必须包含 i 的所有子集。 对于每个子集，计算所得的前缀和并检查 M 下的可行性，然后采取最小的删除次数。 这是正确的，但相当于搜索子集的指数空间，这对于 n 到 200000 来说是不可能的。 

更结构化的观点是固定 i 并观察到只有删除元素的总和重要，而不是它们的位置。 令 S 为 t[1..i] 之和。 如果 S ≤ M，则不得删除任何内容。 否则，我们需要使用除 i 本身之外的前 i 个元素的删除来将总和减少至少 S − M。 每次移除都会删除一个值 t[j]，我们希望通过尽可能少的移除来达到目标​​减少。 

这将问题转化为选择具有最小基数且总和达到阈值的多组值。 最佳策略始终是首先选择最大的可用值，因为每次删除都会为每次操作带来更多的减少。 

剩下的挑战是有效地维护每个 i 的前缀信息。 由于 t_i 以 100 为界，因此我们可以为前缀维护一个值为 1 到 100 的频率数组，并且还维护前缀和。 对于每个 i，我们暂时将 t_i 从频率中排除，贪婪地消耗最大值，直到满足所需的减少量，然后恢复它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集的暴力破解 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 贪婪地按 i 排序 | O(n^2 log n) | O(n^2 log n) | O(n) | 太慢了 |
 | 频率贪婪（100 个值）| O(100n) | O(100) | 已接受 |

 ## 算法演练

1. 当我们从 1 迭代到 n 时，维护 t 值的运行前缀和。 如果直到我为止的所有学生都通过了，这给出了总时间。 
2. 维护一个频率数组 freq[x]，表示值 x 在已处理的学生中出现的次数，最多为 i。 
3. 对于每个i，计算当前前缀和S_i。 如果 S_i ≤ M，则 i 的答案为 0，因为不需要删除。 
4. 否则计算所需的约简 E = S_i − M。我们必须从前 i 个学生中删除除 i 本身之外的元素。 
5. 暂时将 freq[t_i] 减 1，以便学生 i 无法被选择移除。 
6. 从值 100 开始到 1，贪婪地从 freq[v] 中获取尽可能多的元素，从 E 中减去它们的贡献并计算使用了多少个元素。 这会产生最少的移除次数，因为值越高，每次操作 E 的减少速度就越快。 
7. 计算结果后恢复 freq[t_i]。 

### 为什么它有效

 在每一步中，我们都在解决有界值域上的经典最小基数子集和覆盖问题。 由于所有值都是正且小，因此任何实现所需总和减少的最佳解决方案都可以转换为优先考虑较大值而不增加元素数量的解决方案。 这个交换论证保证了通过递减值进行贪婪选择是最优的。 频率结构确保我们始终准确地知道前缀中每个值有多少个可用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, M = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * 101
    prefix_sum = 0
    res = [0] * n

    for i in range(n):
        x = a[i]
        prefix_sum += x
        freq[x] += 1

        if prefix_sum <= M:
            res[i] = 0
            continue

        # remove current element temporarily
        freq[x] -= 1

        need = prefix_sum - M
        cnt = 0

        for v in range(100, 0, -1):
            if need <= 0:
                break
            if freq[v] == 0:
                continue

            take = min(freq[v], (need + v - 1) // v)
            need -= take * v
            cnt += take

        res[i] = cnt

        # restore
        freq[x] += 1

    print(*res)

if __name__ == "__main__":
    solve()
```该实现依赖于增量地维护前缀和，因此每个位置都会在恒定的时间内进行处理以进行更新。 贪婪移除循环以 100 个值为界，使其在约束下高效。 暂时移除第 i 个学生可确保可行性计算的正确性。 

一个微妙的实现细节是计算从值桶中获取多少元素。 我们不是逐一计算，而是计算满足剩余要求所需的最小数量，这避免了不必要的迭代并使算法在值范围内保持线性。

 ## 边缘情况

 一种关键的边缘情况是减少总和的唯一方法是删除许多小元素。 该算法仍然可以正确处理这个问题，因为它继续下降所有价值桶，在必要时积累许多小的贡献。 

另一种情况是当 t_i 本身是前缀中的最大值时。 临时删除步骤可确保它永远不会被计入删除中，以进行其自身的可行性检查。 

例如，如果输入是：```
3 5
5 4 3
```在 i = 3 时，前缀和为 12，需求为 7。算法暂时将 3 排除在考虑范围之外，然后选择 5 和 4，以恰好 2 次删除实现减少 9，这是最小的。 

这证实了将目标学生排除在删除之外对于正确性至关重要，并且由频率调整步骤明确强制执行。
