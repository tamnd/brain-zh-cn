 ## 解决方案
 ## 问题理解

 我们得到了一小部分歌曲。 每首歌曲都有一个持续时间和一个流派，我们希望通过选择其中一些不重复的歌曲来形成一个有序的播放列表。 播放列表必须同时满足三个约束。 总收听时间必须恰好是一个固定值$T$。 任何歌曲索引都不能多次使用。 并且播放列表中相邻的歌曲必须具有不同的流派。 

输出是有效有序播放列表的数量模$10^9+7$。 顺序很重要，因此只要尊重流派规则，选择不同排列的同一组歌曲就会被视为不同的答案。 

这些约束立即表明了歌曲子集上的状态空间，因为$n \le 15$。 任何尝试在不记忆的情况下枚举所有序列的解决方案都存在探索最多的风险$15!$排列组合，这远远超出了可行的范围。 时间限制迫使我们采用位掩码动态编程方法，其中每个子集被考虑一次。 

时间维度$T \le 225$也很小，这表明我们可以安全地将其包含在 DP 状态中。 

一个天真的错误是将其视为子集上的简单排列计数问题，总和为$T$，忽略邻接约束。 这会过多地计算无效的转换，例如连续放置两首相同流派的歌曲。 另一个微妙的失败案例是假设修复歌曲集就足够了，但顺序仍然很重要，因为流派限制取决于顺序，而不仅仅是选择。 

## 方法

 暴力方法会尝试歌曲每个子集的所有可能的排序。 对于每个子集，我们将生成所有排列并检查总持续时间和邻接约束。 这已经意味着最多$15!$最坏情况下的排列，甚至按持续时间进行修剪也没有多大帮助，因为约束是全局的，不可前缀缩减。 重复约束乘以无结构的分支因子以重用中间结果。 

关键的观察是构建播放列表的过程是渐进的。 在任何时候，扩展有效部分播放列表所需的唯一信息是已经使用了哪些歌曲、当前总持续时间以及最后选择的歌曲的流派。 这表明子集上的 DP，其中转换对应于添加一首新歌曲。 

因为$n$很小，位掩码代表哪些歌曲已被使用。 我们还跟踪当前时间和上一个流派。 这将全局排序问题转换为状态 DAG 上的局部转换。 

暴力破解会失败，因为它多次重新计算相同的部分配置。 DP 之所以有效，是因为每个状态都唯一地捕获了正确扩展序列所需的所有内容，因此子问题严重重叠。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 最佳 DP（位掩码）|$O(2^n \cdot n \cdot T)$|$O(2^n \cdot T \cdot 3)$| 已接受 |

 ## 算法演练

 我们定义一个 DP 状态，它表示我们可以构建以特定配置结尾的有效前缀的多种方式。 

1.我们定义`dp[mask][time][last_genre]`作为完全使用中的歌曲形成序列的方法数量`mask`，正好消耗`time`分钟，并以一首流派歌曲结束`last_genre`。 最后一个流派是必需的，因为它决定是否可以附加下一首歌曲。 
2. 我们初始化选择单首歌曲的所有状态。 对于每首歌曲$i$，我们设置`dp[1<<i][t_i][g_i] = 1`。 这反映出播放列表可以从任何单首有效歌曲开始。 
3. 我们从小到大迭代所有掩码。 对于每个掩码，我们考虑每个可能的时间和具有非零计数的最后流派状态。 这确保我们只扩展可达的配置。 
4.我们尝试在每个州添加一首新歌$j$那不在面具中。 我们只允许这种转变，如果$g_j \ne last\_genre$。 这会在每一步本地强制执行邻接约束。 
5.如果添加歌曲$j$产生新的总时间$time + t_j \le T$，我们更新下一个状态：`dp[new_mask][new_time][g_j] += dp[mask][time][last_genre]`。 
6. 处理完所有状态后，答案就是所有状态的总和`dp[mask][T][last_genre]`涵盖所有面具和流派。 

这样做的原因是每个有效的播放列表都恰好对应于该 DP 中的一个转换序列。 每个前缀都由其使用的集合、累积时间和最后类型唯一地表示，因此除了不同的排序路径之外，不会丢失或重复计算有效的结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, T = map(int, input().split())
    songs = [tuple(map(int, input().split())) for _ in range(n)]

    dp = [[[0] * 4 for _ in range(T + 1)] for _ in range(1 << n)]

    for i, (t, g) in enumerate(songs):
        if t <= T:
            dp[1 << i][t][g] = 1

    for mask in range(1 << n):
        for time in range(T + 1):
            for last in range(1, 4):
                cur = dp[mask][time][last]
                if not cur:
                    continue

                for j in range(n):
                    if mask & (1 << j):
                        continue
                    t, g = songs[j]
                    if g == last:
                        continue
                    nt = time + t
                    if nt > T:
                        continue
                    nmask = mask | (1 << j)
                    dp[nmask][nt][g] = (dp[nmask][nt][g] + cur) % MOD

    ans = 0
    for mask in range(1 << n):
        for last in range(1, 4):
            ans = (ans + dp[mask][T][last]) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```DP表是三维的：子集、时间和最后流派。 初始层种子单首歌曲播放列表。 转换循环通过位掩码检查小心地避免重复使用歌曲，并在更新状态之前强制执行流派约束。 每次累加时都会应用模数以防止溢出。 

一个常见的陷阱是忘记最后的流派状态必须包括每首歌曲的初始值，否则第一步的转换是无效的。 另一个是索引之前没有限制时间，这会在低级语言中悄悄损坏内存或在 Python 中导致逻辑错误。

 ### 示例 1

 输入：```
3 3
1 1
1 2
1 3
```我们从单曲状态开始：

 | 面膜| 时间 | 最后| 价值|
 | ---| ---| ---| ---|
 | 001| 1 | 1 | 1 |
 | 010| 1 | 2 | 1 |
 | 100 | 100 1 | 3 | 1 |

 从每个状态，我们可以附加不同流派的任何歌曲，最终达到长度为 3 的所有排列。 

时间 3 时的最终状态：

 | 面膜| 最后| 计数|
 | ---| ---| ---|
 | 111 | 111 1 | 2 |
 | 111 | 111 2 | 2 |
 | 111 | 111 3 | 2 |

 求和得到 6。 

这证实了当所有流派不同时 DP 正确地枚举了所有排列。 

### 示例 2（已构建）```
3 3
1 1
2 2
1 1
```有效的结构必须避免连续的流派 1。DP 从每首歌曲开始，只允许流派 1 和流派 2 之间的过渡。 

有效路径是：

 从 (2, 流派 2) 开始，然后可以转到任一流派 1 歌曲，反之亦然，具体取决于剩余时间。 

DP 自然会阻止两首流派 1 歌曲之间的转换。 

该跟踪证实了重复流派邻接在每次转换时都在本地强制执行。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(2^n \cdot n \cdot T)$| 每个州都会尝试所有可能的下一首歌曲 |
 | 空间|$O(2^n \cdot T \cdot 3)$| 子集、时间和最后类型的 DP |

 和$n \le 15$,$2^n = 32768$， 和$T \le 225$，总状态空间约为几百万个条目，这完全在 Python 小心循环的限制之内。

 ## 边缘情况

 一种边缘情况是多首歌曲共享相同的流派和持续时间，这可能会产生许多排列，但也会产生许多无效的过渡。 DP 处理这个问题是因为每首歌曲都被视为一个不同的索引，并且过渡纯粹按流派而不是身份进行过滤。 

另一种边缘情况发生在$T$与歌曲持续时间相比较小。 例如：```
n=2, T=1
t=[2,3], g=[1,2]
```初始状态无效，因为所有歌曲都超过$T$，因此 DP 始终保持为零并正确返回 0。 

最后一个微妙的情况是只有一首歌曲完全适合$T$。 DP 初始化该单一状态并且从不扩展它，从而准确地生成一个有效的播放列表，这符合不允许重复但单元素序列有效的要求。
