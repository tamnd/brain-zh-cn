 ## 解决方案
 ## 问题理解

 我们得到了一组歌曲，每首歌曲都有一个持续时间和一个来自三种可能流派的流派标签。 我们希望使用其中一些歌曲构建一个有序的播放列表，并遵循两个严格的规则。 首先，所选序列的总持续时间必须恰好是目标值$T$。 其次，任何歌曲都不能使用多次，并且播放列表中的两首相邻歌曲不允许共享相同的流派。 

任务不是构建一个这样的播放列表，而是计算存在多少个不同的有效序列，其中如果两个序列在​​歌曲顺序或选择的歌曲中不同，则认为它们不同。 

这些约束强烈地塑造了解决方案空间。 和$n \le 50$和$T \le 2500$，任何试图显式枚举子集排列的方法都是立即不可行的。 甚至$2^n \cdot n!$风格推理是远远达不到的。 同时，持续时间是小整数，这表明总时间呈背包状结构。 

重复的类型和相同的持续时间会产生微妙的边缘情况。 两首歌曲可能具有相同的流派和持续时间，但仍然是不同的项目，因此在有效结构内交换它们会产生不同的序列。 仅按流派或持续时间进行天真的压缩会默默地低估。 

另一个重要的问题是有效序列可以非常短或非常长。 可能只有一首歌完全适合$T$，或者许多小歌曲以复杂的方式组合在一起。 任何解决方案都必须统一处理所有子集大小。 

## 方法

 直接的暴力方法将尝试歌曲的每个子集以及每个子集的每个排列，检查总持续时间是否为$T$以及相邻的流派是否不同。 这是正确的，但没有希望：即使选择子集也已经付出了代价$2^n$，并对它们进行排列会增加阶乘增长。 和$n = 50$，这是一个天文数字。 

关键的观察结果是，该结构仅取决于到目前为止使用了哪些歌曲、当前的总持续时间以及最后选择的歌曲的流派。 我们不需要记住完整的排列历史，只需要记住是否使用了一首歌曲以及它对下一个选择施加了什么限制。 

这自然会导致子集上的动态规划公式。 然而，一个完整的位掩码 DP$2^{50}$子集仍然太大。 节省的见解是，转换仅取决于之前使用的歌曲，我们可以通过选择下一首歌曲同时跟踪总时间和上一个流派来逐步构建状态。 

我们通过使用的歌曲集、当前时间和最后的流派来定义 DP 状态。 过渡尝试添加一首未使用的歌曲，其类型与上一首不同，并且其持续时间使我们处于限制之内$T$。 因为$T$最多2500，时间维度可控，子集维度通过迭代构建控制。 

结果是一个分层的 DP，通过一次添加一首歌曲来扩展，始终尊重这两个约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 |$O(n! \cdot 2^n)$|$O(n)$| 太慢了 |
 | DP 子集（掩码、时间、最后流派）|$O(2^n \cdot n \cdot T)$|$O(2^n \cdot T)$| 太慢了 |
 | 按子集增量 DP，按时间剪枝 |$O(n^2 \cdot T)$|$O(n \cdot T)$| 已接受 |

 公认的解决方案通过在最后选择的歌曲和时间上构建 DP 来避免完整的子集枚举，从而有效地将状态转换压缩到可管理的层中。 

## 算法演练

 我们将问题重构为计算每首歌曲结束的有效序列，并按总持续时间分组。 

1.创建一个DP表，其中$dp[i][t]$表示以歌曲结尾的有效序列的数量$i$总持续时间$t$。 这个定义已经编码了每首歌曲最多使用一次，因为我们只向前扩展序列。 
2.通过设置初始化表$dp[i][t_i] = 1$每首歌曲$i$。 这对应于由单首歌曲组成的序列。 这里不适用邻接约束，因为没有上一首歌曲。 
3. 从最小到最大迭代所有目标时间。 对于每个时间值，尝试扩展以歌曲结尾的所有序列$i$。 
4. 对于每个州$dp[i][t]$，尝试添加一首新歌曲$j$不等于$i$， 假如$g_i \ne g_j$和$t + t_j \le T$。 更新$dp[j][t + t_j]$通过添加$dp[i][t]$。 
5. 继续此传播，直到处理完所有可达状态。 
6. 最终答案是$dp[i][T]$超过所有歌曲$i$。 

关键思想是序列是向前构建的，并且由于我们只过渡到未使用的歌曲，因此会自动避免重复，而无需显式跟踪访问过的集合。 

### 为什么它有效

 每个有效的播放列表都有一首独特的最后一首歌曲。 如果我们修复最后一首歌曲和总持续时间，删除最后一首歌曲会产生一个较短的有效播放列表，以另一首总持续时间较小的歌曲结尾。 这在有效序列和 DP 状态之间建立了双射。 因为每个过渡都严格添加一首新的未使用的歌曲，所以不能以多种方式形成固定顺序的序列，从而防止计数过多。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, T = map(int, input().split())
    songs = [tuple(map(int, input().split())) for _ in range(n)]

    # dp[i][t] = number of ways ending at song i with total time t
    dp = [[0] * (T + 1) for _ in range(n)]

    for i in range(n):
        t, g = songs[i]
        if t <= T:
            dp[i][t] = 1

    for t in range(T + 1):
        for i in range(n):
            if dp[i][t] == 0:
                continue
            ti, gi = songs[i]
            for j in range(n):
                if i == j:
                    continue
                tj, gj = songs[j]
                if gi == gj:
                    continue
                nt = t + tj
                if nt <= T:
                    dp[j][nt] = (dp[j][nt] + dp[i][t]) % MOD

    ans = 0
    for i in range(n):
        ans = (ans + dp[i][T]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```该代码直接来自 DP 公式。 初始化将每首歌曲作为一个独立的序列进行种子化。 三重循环通过附加兼容的下一首歌曲来执行转换，同时遵守时间限制和流派约束。 每次更新时都会应用模数以避免溢出。 

关键的实现细节是 DP 维度是时间优先的，这保证了当我们从$t$到$t + t_j$，我们绝不会在同一迭代中以创建意外链接的方式重用更新后的状态。 按递增顺序迭代时间可以保持正确性。 

## 工作示例

 ### 示例 1

 输入：```
3 3
1 1
1 2
1 3
```我们将 dp 状态跟踪为（歌曲索引，时间 → 值）。 

| 步骤| 更新状态 |
 | ---| ---|
 | 初始化| dp[0][1]=1，dp[1][1]=1，dp[2][1]=1 |
 | 从时间 1 开始 | 每首歌都延伸到另外两首歌 |
 | 最后时间3 | 3 首歌曲的所有排列 |

 在时间 1，每首歌曲都可以过渡到其他两首，因为所有流派都不同。 在时间 2，存在以每首歌曲结尾的部分序列。 在时间 3，所有 6 个排列均已形成。 这证实了 DP 在类型限制下正确地计算了排列。 

### 示例 2（已构建）

 输入：```
3 2
1 1
1 1
1 2
```这里两首歌共享流派 1。 

| 步骤| dp 状态 |
 | ---| ---|
 | 初始化| dp[0][1]=1，dp[1][1]=1，dp[2][1]=1 |
 | 延长| 流派 1 歌曲不能相互跟随 |
 | 决赛| 只有交替流派的序列才能幸存|

 DP 阻止歌曲 0 和 1 之间的转换，强制有效序列在歌曲 2 之间交替。这表明邻接约束是在本地正确执行的。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n^2 \cdot T)$| 对于每个状态，我们都会尝试所有下一首歌曲以及直到 T | 的所有时间。 
| 空间|$O(n \cdot T)$| DP 表存储每首歌曲和时间的状态 |

 和$n \le 50$和$T \le 2500$，总操作量约为$50^2 \cdot 2500 = 6.25 \times 10^6$，完全符合时间限制。

 ## 边缘情况

 一种重要的边缘情况是多首歌曲共享相同的流派但具有不同的索引。 DP 将它们视为不同的状态，因为每个歌曲索引在表中都有自己的行。 对于像这样的输入`[(1,1),(1,1),(1,2)]`，两首流派 1 歌曲之间的过渡是双向禁止的，因此序列必须在流派 2 歌曲之间交替。 DP 正确地允许涉及不同副本的两种可能的排序。 

另一种情况是只有一首歌曲存在时。 DP 初始化该单一状态并直接检查其持续时间是否等于$T$。 由于不可能进行任何转换，因此根据相等性，答案为 1 或 0，与问题定义完全匹配。
