 ## 解决方案
 ## 问题理解

 三个人站在无限数线上的位置$a$,$b$， 和$c$。 他们被允许沿着线移动，但移动受到极大限制：每一秒只能有一个人移动，而且移动总是向左或向右移动一个单位。 目标是重新安排他们的位置，使每对人之间的距离至少$d$。 

输出是达到所有三个成对距离都满足此阈值的任何配置所需的最小秒数。 

限制条件允许持仓最多$10^9$，这立即排除了任何时间或空间上的模拟。 该系统每秒演化一个单位，但由于每秒只有一个人移动，因此总成本本质上是所有个人进行的单位调整总数。 

从约束中观察到的一个关键是只有相对位置才重要。 绝对坐标是无关紧要的，因为将所有三个点移动到一起不会改变距离。 

当两三个人从同一位置开始时，就会出现微妙的边缘情况。 例如，如果$a = b = c$，则系统被最大程度地压缩并且需要将所有点分开。 假设初始排序或假设不同位置的天真的方法在这里将失败，因为它可能错误地将重叠视为已经有效或部分有效。 

另一种边缘情况是初始配置已经满足条件时。 例如，$a = 1, b = 10, c = 20, d = 5$。 任何在不检查初始有效性的情况下盲目“传播”点的算法都会过度计算操作。 

## 方法

 一个蛮力的想法是模拟所有可能的动作。 在每一步中，我们可以尝试向左或向右移动三个点中的任何一个，并在状态上运行 BFS$(a, b, c)$。 每个状态转换花费 1 秒，当所有成对距离至少达到时我们停止$d$。 

这是正确的，但完全不可行。 每个状态最多有 6 个转换，并且坐标可以在很大的范围内漂移。 即使进行剪枝，可达状态的数量也会爆炸性增长，因为位置位于无界整数线上。 BFS 状态空间实际上是无限的。 

关键的观察是我们实际上并不关心移动的顺序，只关心最终的配置。 由于每次移动都会将一个坐标调整 1，因此总时间等于应用于所有三个点的绝对调整的总和。 

这将问题转化为选择最终位置$x \le y \le z$这样：$$y - x \ge d, \quad z - y \ge d$$并最小化：$$|a - x| + |b - y| + |c - z|$$由于只有相对间距很重要，因此我们可以修复最终位置的顺序并尝试分配的所有排列$a, b, c$到$x, y, z$。 对于每个排列，我们贪婪地首先放置中间点，然后向外强制约束。 由于成本函数在每个坐标中都是凸的，因此可以确定性地导出固定顺序的最佳位置。 

这将问题减少到检查恒定数量的配置。

 ## 算法演练

 我们将这三个点的所有排列视为最终顺序的候选者。 

1. 将三个初始位置排序或排列成一个顺序$x, y, z$。 这代表了假定的从左到右的最终排列。 
2.修复$y$首先，因为它锚定了结构。 对于给定的中间分配，我们计算最佳位置$x$和$z$相对于它。 
3. 通过强制确保间距约束$x \le y - d$和$z \ge y + d$。 这保证了固定的最小位移的有效性$y$。 
4. 将总成本计算为原始头寸和调整后头寸之间的绝对差之和。 
5. 对所有排列重复并取最小值。 

我们锚定中间元素的原因是，一旦中心固定，两个外部位置是独立的，每个位置都可以尽可能靠近放置，以降低成本，同时尊重距离限制。 

### 为什么它有效

 对于任何有效的最终配置，这三个点的顺序是固定的。 在这个顺序中，每个点都希望尽可能接近其原始位置。 固定排序的最优解是通过限制外部点以满足相对于中间点的最小距离约束来获得的。 由于成本与绝对偏差成线性关系并且约束条件是单调的，因此将任何点推得比必要的更进一步都无法提高可行性，只会增加成本。 因此，检查所有排列涵盖了所有可行的排序，并且每个排列都得到了最优解决。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cost(a, b, c, d):
    # assume b is middle
    best = float('inf')

    # we try placing b anywhere; but optimal occurs at one of candidates derived from constraints
    # derive x = b - d, z = b + d
    x = b - d
    z = b + d

    return abs(a - x) + abs(b - b) + abs(c - z)

def solve():
    a, b, c, d = map(int, input().split())
    arr = [a, b, c]
    ans = float('inf')

    import itertools
    for p in itertools.permutations(arr):
        x0, y0, z0 = p

        y = y0
        x = min(x0, y - d)
        z = max(z0, y + d)

        ans = min(ans,
                  abs(x0 - x) + abs(y0 - y) + abs(z0 - z))

    print(ans)

if __name__ == "__main__":
    solve()
```该代码迭代三个初始位置的所有排列，将每个排列视为候选最终从左到右的排序。 对于每个订单，中间元件保持固定，外部元件夹紧足以满足距离要求。 成本计算为各个位移的总和。 

重要的细节是，夹紧是相对于所选的中间位置进行的，确保以该配置的最小移动来满足间距约束。

 ## 边缘情况

 当所有三个点都从同一坐标开始时，算法会选择每个排列并强制中间点保持固定，同时将其他点向外推至少$d$。 用于输入$1,1,1,2$，任何选择的中心都会导致展示位置$-1,1,3$直到排列，计算出的成本变为 4，与所需的总扩展相匹配。 

当点已经充分分开时，例如$1,10,20,5$，每个排列都不会产生钳位，因为所有约束都已满足。 在每种情况下计算的成本都为零，正确地保留了初始配置。 

当点几乎对齐但未排序时，例如$10,0,5,4$，排列正确地识别出最佳的中间选择，并且仅移动必要的端点，从而产生最小的调整，而不是由于不正确的排序假设而过度扩展。
