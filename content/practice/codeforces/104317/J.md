 ## 解决方案
 ## 问题理解

 我们得到了一个由单一类型的原始括号结构构建的递归定义的字符串族。 基础对象是最简单的有效对“()”。 从那里，我们可以使用两个操作构建更大的结构：将现有结构包装在一对括号内，并连接两个现有结构，然后再次包装结果。 

每个查询给出一个括号字符串，并询问是否可以通过重复应用从基“()”开始的那些规则来生成它。 任务不是检查字符串是否是标准的正确括号序列，而是检查它是否属于这种更具限制性的语法。 

输入的总长度最多可包含 300,000 个字符串。 这立即排除了任何试图显式探索所有分解或模拟推导的解决方案。 任何试图以所有可能的方式分割字符串或在子字符串上维持 DP 的操作在最坏的情况下都会变成二次并超出限制。 

一个常见的陷阱是假设这相当于检查平衡的括号序列。 这会失败，因为根据语法施加的结构约束，可能无法生成像“()(())”这样的标准有效序列。 另一个陷阱是将其视为通用解析的语法隶属度问题，如果直接实现，则需要对子串进行三次DP。 

一个暴露差异的小例子是“()()”。 这是一个有效的括号序列，但是在这个语法下，如果没有派生允许两个独立的组件而不以正确的顺序包装约束，则它不一定是可构造的。 相反，某些嵌套形式是允许的，即使它们看起来受到不必要的限制。 

真正的困难在于语法不是任意的上下文无关行为，它具有非常具体的“外部包装，内部可选连接”结构，强制树状分解而不是任意交错。 

## 方法

 思考这个问题的一种强力方法是将其视为语法成员资格检查。 我们可以定义一个 DP，其中 dp[l][r] 告诉子字符串 S[l:r] 是否属于该集合。 要使子字符串有效，它必须是“(X)”（其中 X 有效）或“(X)(Y)”（其中两个部分都有效并且最外面的括号正确匹配）。 

这立即导致尝试每个间隔内的所有分割点，并为每个间隔验证匹配结构。 即使使用记忆，间隔的数量也是 O(n²)，并且每次转换都需要扫描分割点，在最坏的情况下给出 O(n³) 的行为。 当 n 总共达到 3×10⁵ 时，这是不可行的。 

关键的观察结果是，语法强制采用非常严格的结构：每个有效字符串要么是单个原始包装结构，要么是两个较小的有效结构的包装串联。 在这两种情况下，最外面的一对括号始终包含分解为连续的有效块。 

这意味着我们可以将该过程解释为在原始块上构建有根有序二元分解树，而不是任意分割。 每个节点对应一个平衡段，分割的结构完全取决于每对括号内存在多少个顶级组件。 

捕获此问题的标准方法是使用一个堆栈，该堆栈维护当前开放的结构并计算每个深度已形成多少个“完整组件”。 每次关闭括号时，我们要么最终确定一个原语，要么在当前级别合并已完成的子级。 当且仅当我们从不违反排序约束并以最外层的单个完整结构结束时，该结构才是有效的。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 子串上的暴力 DP | O(n3) | O(n²) | 太慢了 |
 | 基于堆栈的结构解析| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们使用代表嵌套构造框架的堆栈独立处理每个字符串。 每一帧都会跟踪其内部是否至少看到一个已完成的组件。 

1. 初始化一个空堆栈。 每个堆栈条目代表当前打开的括号上下文以及它是否已累积完整的子结构。 
2. 从左到右扫描字符串。 当我们看到“(”时，我们创建了一个新的帧并将其压入堆栈。这对应于在递归定义中开始一个新的构造层。
 3. 当我们看到“)”时，我们正在关闭当前框架。 此时，框架代表了一个完全构建的子结构。 如果弹出之前堆栈为空，则字符串无效，因为我们在没有打开上下文的情况下关闭。 
4. 弹出顶部框架。 如果该框架不包含完整的子结构并且不包含内部有效的组合，则它代表基本“()”情况，因此它作为单个单元仍然有效。 
5.弹出后，将这个完成的单元视为可能属于更高级别框架的“块”。 如果堆栈不为空，我们就标记父框架现在已接收到至少一个已完成的子组件。 
6. 如果在任何时候我们在没有活动帧的情况下遇到右括号，或者我们完成扫描并且有剩余的开放帧，则该字符串无效。 
7. 最后，如果在最外层形成了一个完整的结构，则该字符串是有效的，这意味着堆栈处理干净地结束，并且整个字符串折叠成单个根块。 

重要的想法是语法只允许两种构建结构的方法：包装和连接已经完整的结构。 堆栈确保我们只合并完整的子结构，而不是部分的子结构。 

### 为什么它有效

 在扫描中的任何一点，每个堆栈帧都对应于当前正在构造的子串，并且如果完成则保证是平衡的。 不变的是，每次我们弹出一个框架，它都代表完全由早期完成的组件形成的最大有效结构。 

因为语法只允许组合已经有效的组件，所以任何有效的推导都不需要在不完整的段内进行拆分。 相反，每当堆栈完成一帧时，我们就准确地构建了一个语法一致的单元。 最终接受条件强制整个字符串折叠成一个这样的单元，与集合的递归定义相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_valid(s: str) -> bool:
    stack = []
    
    for ch in s:
        if ch == '(':
            # start a new frame, no completed children yet
            stack.append(0)
        else:
            if not stack:
                return False
            
            # finish current frame
            had_child = stack.pop()
            
            # we now have a completed block; attach it to parent if exists
            if stack:
                stack[-1] = 1  # parent now has at least one component
    
    return len(stack) == 0

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print("YES" if is_valid(s) else "NO")

if __name__ == "__main__":
    main()
```该实现使用一个堆栈，其中每个条目都是一个简单的标记，指示当前帧是否已经累积了至少一个完整的内部块。 当遇到右括号时，我们弹出框架并将其视为完整的单元。 如果存在父框架，我们将其标记为已收到有效组件。 

正确性取决于确保我们永远不会接受不匹配的结束括号，并且所有打开的框架最终都会关闭。 最终堆栈为空可确保整个结构简化为单个有效结构。 

## 工作示例

 我们跟踪两个字符串来查看堆栈如何演变。 

首先考虑字符串“(()())”。

 | 1 | ( | [0] |

 在每个右括号处，我们将最里面的结构折叠成一个单元并将其向上传播。 堆栈以空结束，确认单个有效的根结构。 这对应于嵌套组合，其中内部有效块根据语法规则组合。 

现在考虑“(()))”。 

| 步骤| 查尔 | 堆栈状态 |
 | ---| ---| ---|
 | 1 | ( | [0] |
 | 2 | ( | [0, 0] |
 | 3 | ) | [0]|
 | 4 | ) | []|
 | 5 | ) | 无效|

 在第 5 步，我们尝试关闭没有活动框架的括号，这立即违反了构造规则。 这演示了堆栈如何在不需要完整解析的情况下尽早检测到结构违规。 

第一个示例确认了正确的嵌套缩减，而第二个示例则揭示了无效闭包如何破坏构造过程。

import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    for _ in range(t):
        s = input().strip()
        stack = []
        ok = True
        for ch in s:
            if ch == '(':
                stack.append(0)
            else:
                if not stack:
                    ok = False
                    break
                stack.pop()
                if stack:
                    stack[-1] = 1
        if stack:
            ok = False
        print("YES" if ok else "NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

 ## 边缘情况

 一个关键的边缘情况是通常意义上的平衡字符串，但结构上与语法不兼容，例如“()()”。 堆栈处理它时不会遇到无效的括号，但最终结构不会折叠成单个根框架，从而留下多个顶级组件。 该算法拒绝它，因为堆栈末尾不为空，这符合整个字符串必须表示单个构造对象的要求。 

另一个边缘情况是早期无效关闭，如“)(”。第一个字符尝试关闭不存在的帧，导致立即拒绝。这表明算法正确地强制执行前缀有效性，而不仅仅是全局平衡。

 第三种情况是深度嵌套的字符串，如“(((())))”，其中每个左括号创建一个新框架，每个右括号干净地折叠它。 堆栈大小线性增长，然后返回到零，确认纯嵌套在构造规则下始终有效。
