 ## 解决方案
 ## 问题理解

 每个摄像头都可以被多次黑客攻击。 第二次执行的黑客攻击`T`在间隔期间禁用该摄像头`[T + 1, T + s]`。 

唯一重要的时刻是两起盗窃案。 让第一颗钻石及时被盗`A`和第二次`B`， 和`A < B`。 

观看第一颗钻石的摄像机必须及时禁用`A`。 

观看第二颗钻石的摄像机必须及时禁用`B`。 

监视两颗钻石的摄像机必须在整个间隔期间保持禁用状态`A`到`B`，或者被黑客攻击两次，每次盗窃一次。 

关键的观察结果是，最佳时间表永远不会包含空闲时间。 每一秒要么是一次黑客攻击，要么是两次盗窃之一。 如果我们知道需要多少次黑客攻击，答案很简单```
(number of hacks) + 2
```因为两次盗窃本身也消耗秒数。 

约束在一个维度上异常小，在另一个维度上异常大。 我们最多有1500个摄像头，但摄像时长最多为`2n`，因此最多 3000。持续时间范围内的任何二次解都是可接受的，但任何类似于对摄像机子集进行指数搜索的方法都是不可能的。 

困难的部分不是安排黑客活动。 它正在决定哪些摄像头可以通过一次黑客攻击来覆盖，哪些摄像头必须被黑客攻击两次。 

当观看第一颗钻石的每个摄像机的持续时间都很短时，就会出现微妙的边缘情况。```
1
1 1
```第一个钻石可以在破解相机一次后被盗，但第二个钻石是不可能的，因为没有相机监视它。 正确答案是`2`， 不是`-1`。 坚持同步两次盗窃的解决方案在这里会失败。 

另一个重要的案例是监控两颗钻石的摄像机。```
1
3 1
```一次黑客攻击是不够的。 摄像头仅被禁用一秒钟，而两次盗窃必须在不同的秒内发生。 正确答案是`4`，匹配样本。 任何将 3 型相机视为在一次黑客攻击后同时满足两个钻石的方法都是不正确的。 

第三个陷阱是假设持续时间越长越好。 对于盗窃之间的固定距离，具有持续时间的 3 型摄像机`x`有时可以通过一次黑客攻击来覆盖，有时则不能。 该决定取决于所选的盗窃间隔。 

## 方法

 暴力方法将尝试模拟第一次盗窃的所有可能时刻、第二次盗窃的所有可能时刻以及所有可能的摄像机分配给黑客。 即使在利用持续时间最多为 3000 的事实之后，状态空间也是巨大的。 3 型摄像机可能在第一次被盗之前、第二次被盗之前被黑客入侵一次，或者两次。 由于此类摄像机多达 1500 个，彻底搜索是没有希望的。 

突破来自聚焦差距```
len = B - A
```两次盗窃之间。 

修复这个值。 现在，每个相机都可以纯粹根据其持续时间进行分类。 

对于 1 类相机，一次黑客攻击必须涵盖第一次盗窃。 

对于 2 类相机，一次黑客攻击必须覆盖第二次盗窃。 

对于持续时间至少为 3 型的相机`len`，一次黑客攻击可能涵盖两种盗窃行为。 如果其持续时间小于`len`，两次黑客攻击是不可避免的。 

修复后`len`，问题就变成了可行性测试。 我们必须确定可用的持续时间是否可以覆盖第一次盗窃之前和第二次盗窃之前的所有所需位置。 

接受的解决方案处理每个可能的值`len`。 自从`len`永远不会超过`k₂ + k₃ + 1`， 仅有的`O(n)`需要检查值。 对于每个值，都使用支持范围添加和最大查询的线段树来维护贪婪分配。 该树验证了当持续时间被解释为截止日期时出现的霍尔型容量约束。 

由此产生的复杂度大致为`O(n² log n)`，这很适合`n = 1500`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n² log n) | O(n² log n) | O(n) | 已接受 |

 ## 算法演练

 1. 根据类型将摄像机分为三组。 
2. 对每组的持续时间进行排序。 
3. 枚举每个可能的值```
len = B - A
```从`1`到`k₂ + k₃ + 1`。 
4.对于当前`len`，对每个 type-3 相机进行分类。 

3 型摄像机可以使用一次，涵盖两种盗窃行为，也可以转换为两种独立的需求。 贪婪程序最初尝试通过一次 hack 来使用尽可能多的 3 类摄像机。 
5. 维护两个需求集合。 

左侧结构代表第一次盗窃时必须处于活动状态的摄像机。 

右侧结构代表第二次盗窃时必须激活的摄像机。 
6. 使用线段树来存储所有截止期限前缀中的最大违规。 

正值意味着某些前缀需要的摄像机数量超出了可以安排的数量。 非正值意味着当前分配是可行的。 
7. 扫描 2 类摄像头。 

在扫描过程中，一些摄像机从右侧移动到左侧。 每当可行性被破坏时，贪婪修复步骤就会将一台先前共享的 3 型相机转换为被黑客攻击两次的相机。 
8. 当左右约束均可行并且盗窃之间的黑客次数不超过`len`，计算黑客攻击的总数。 
9. 此配置的答案等于```
n + extra
```黑客攻击，再加上两次盗窃行为。 
10. 取所有值中的最小值`len`。 

### 为什么它有效

 对于固定距离`len`，每个相机都提供一个截止时间类型的约束。 线段树不断检查是否可以满足每个期限前缀。 贪婪规则总是倾向于只使用 3 型相机一次，因为这样可以最大限度地减少黑客攻击的总数。 当可行性被违反时，将最大的合格共享相机转换为双黑客相机是可以改善违反前缀的唯一修复方法。 这与经典截止日期调度问题中出现的交换论证相同。 

扫描检查2型摄像机所有可能的分布，外环检查所有可能的盗窃间隙。 每个可行的调度恰好对应于算法达到的一个状态，并且线段树接受的每个状态对应于一个可实现的调度。 因此，最小报告值是最佳的。 

## Python 解决方案```python
import sys
from bisect import bisect_right
input = sys.stdin.readline

class SegTree:
    def __init__(self, sz):
        self.sz = sz
        self.tot = 0
        self.t = [0] * (4 * sz)
        self.lazy = [0] * (4 * sz)
        self._build(0, 0, sz)

    def _build(self, v, l, r):
        if l + 1 == r:
            self.t[v] = -l
            return
        m = (l + r) // 2
        self._build(v * 2 + 1, l, m)
        self._build(v * 2 + 2, m, r)
        self.t[v] = max(self.t[v * 2 + 1], self.t[v * 2 + 2])

    def _apply(self, v, x):
        self.t[v] += x
        self.lazy[v] += x

    def _push(self, v):
        if self.lazy[v]:
            x = self.lazy[v]
            self._apply(v * 2 + 1, x)
            self._apply(v * 2 + 2, x)
            self.lazy[v] = 0

    def _upd(self, v, l, r, ql, qr, x):
        if ql >= qr:
            return
        if l == ql and r == qr:
            self._apply(v, x)
            return
        self._push(v)
        m = (l + r) // 2
        self._upd(v * 2 + 1, l, m, ql, min(qr, m), x)
        self._upd(v * 2 + 2, m, r, max(ql, m), qr, x)
        self.t[v] = max(self.t[v * 2 + 1], self.t[v * 2 + 2])

    def upd(self, pos, x):
        self.tot += x
        self._upd(0, 0, self.sz, max(0, pos), self.sz, x)

    def _bad(self, v, l, r):
        if self.t[v] <= 0:
            return -1
        if l + 1 == r:
            return l
        self._push(v)
        m = (l + r) // 2
        if self.t[v * 2 + 1] > 0:
            return self._bad(v * 2 + 1, l, m)
        return self._bad(v * 2 + 2, m, r)

    def get_bad(self):
        return self._bad(0, 0, self.sz)

def solve():
    n = int(input())

    a = [[] for _ in range(4)]
    sz = 1

    for _ in range(n):
        t, s = map(int, input().split())
        a[t].append(s)
        sz = max(sz, s + 1)

    k = [0] * 4

    for t in range(1, 4):
        a[t].sort()
        k[t] = len(a[t])

    a[2].reverse()

    INF = 10000
    ans = INF

    for length in range(1, k[2] + k[3] + 2):
        L = SegTree(sz)
        R = SegTree(sz)

        used = []

        for x in a[1]:
            L.upd(x, 1)

        for x in a[2]:
            R.upd(x, 1)

        for x in a[3]:
            L.upd(x - length, 1)

            if L.t[0] <= 0:
                used.append(x - length)
            else:
                L.upd(x - length, -1)
                L.upd(x, 1)
                R.upd(x, 1)

        used.sort()

        for i in range(k[2] + 1):
            if L.t[0] <= 0 and R.t[0] <= 0 and R.tot + 1 <= length:
                ans = min(ans, n + (k[3] - len(used)) + 2)

            if i == k[2]:
                break

            x = a[2][i]
            R.upd(x, -1)
            L.upd(x - length, 1)

            while True:
                pos = L.get_bad()
                if pos == -1:
                    break

                idx = bisect_right(used, pos) - 1
                if idx < 0:
                    break

                v = used[idx]

                L.upd(v, -1)
                L.upd(v + length, 1)
                R.upd(v + length, 1)

                used.pop(idx)

    print(-1 if ans == INF else ans)

solve()
```线段树存储最大前缀违规。 对应于持续时间的叶子`d`最初包含`-d`。 每台相机都做出贡献`+1`所有持续时间至少与覆盖它所需的持续时间一样长。 正值表示某些截止时间前缀超载且无法调度。 

变量`used`包含当前由单一黑客攻击覆盖的 3 型相机。 当出现违规时，贪婪修复步骤会删除最大的允许元素`used`并将该相机转换为双重黑客相机。 这正是参考解决方案中执行的转换。 

最微妙的实现细节是范围更新。 原始解决方案解释了持续时间`d`作为对每个后缀的贡献`[d, +∞)`。 缺少后缀更新会改变可行性测试的含义并破坏贪婪不变量。

 ## 边缘情况

 考虑```
0
```根本没有相机。 Monocarp 花一秒偷第一颗钻石，一秒偷第二颗钻石。 答案是`2`。 可行性结构保持为空，算法立即接受。 

考虑```
1
3 1
```对于每一个可能的差距`len ≥ 1`，持续时间太短，无法涵盖两次盗窃。 贪婪的程序最终将相机变成了双重黑客攻击的相机。 黑客攻击总数变为`2`，给出答案`2 + 2 = 4`。 

考虑```
2
3 2
2 3
```3 型摄像机可以覆盖第一次盗窃，并且根据所选的间隙，也可以覆盖第二次盗窃。 横扫过去`len`找到最小可行配置并返回最优值`4`，与官方样品相符。
