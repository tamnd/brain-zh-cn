 ## 解决方案
 ## 问题理解

 逆向思考这个过程。 

不要从空集开始并插入数字，而是从完整集开始`{1,2,…,n}`并重复删除一个数字，直到只剩下一个数字。 

后面写的字符`(i+1)`-th 插入对应于反转过程时删除的数量。 

如果一个字符是`>`，那么在相反的过程中我们必须去除当前的最大值。 

如果一个字符是`<`，那么我们必须删除当前的最小值。 

如果一个字符是`?`，那么我们既不能删除最小值，也不能删除最大值。 

任务是计算有多少个可能的删除序列，这与计算有多少个插入排列生成给定的字符串完全相同。 

限制才是真正的挑战。 两个都`n`和`m`一样大`3·10^5`，并且我们必须在每次更新后输出一个答案。 任何重新计算整个答案的解决方案`O(n)`每个查询将大致执行`9·10^10`在最坏的情况下进行操作，这是完全不可行的。 我们周围需要一些东西`O(1)`或者`O(log n)`每次更新。 

一个微妙的边缘情况立即出现。 

为了`n = 2`，只有两个数字。 第一次插入后，第二个数字始终是新的最小值或新的最大值。 一个`?`是不可能的。 

例子：```
n = 2
s = ?
```回答：```
0
```另一个容易犯的错误是将错误的贡献分配给`?`。 

考虑：```
n = 4
s = <??
```第一个`?`发生在位置 2。此时只有一个有效的内部元素。 第二个`?`发生在位置 3 并提供两个选择。 答案不是`2·3`， 这是`1·2`。 

职位本身并不是因素。 该因子比位置减一。 

## 方法

 强力解决方案将生成以下的所有排列`1..n`，模拟插入过程，构建结果字符串，并计算有多少个排列与目标字符串匹配。 

这是正确的，因为它直接遵循定义。 不幸的是它需要`n!`排列。 即使是为了`n = 12`，这已经是无望了，而真正的极限是`3·10^5`。 

关键的观察结果出现在逆转该过程之后。 

假设当前集合大小为`k`。 

如果下一个字符是`<`，我们必须删除最小元素。 只有一种选择。 

如果下一个字符是`>`，我们必须删除最大元素。 又是一个选择。 

如果下一个字符是`?`，我们必须删除一个既不是最小值也不是最大值的元素。 该集合目前包含`k`元素，所以有`k-2`有效的选择。 

之后发生的事情并不取决于选择的内部元素。 每个有效的选择都会导致相同数量的延续。 这意味着有效序列的总数只是每个选项的数量的乘积`?`位置。 

让原始字符串位置编号为`1`。 

当我们处理位置时`i`，逆过程中当前设定大小为`i+1`。 

因此一个`?`在位置`i`贡献```
(i + 1) - 2 = i - 1
```选择。 

第一个位置比较特殊：```
i = 1  =>  i - 1 = 0
```一个`?`这意味着零个有效序列。 

所以答案是```
0                              if s[1] = '?'
Π (i - 1) over all '?' at i>1  otherwise
```每个查询仅更改一个字符。 我们可以动态地维护这个产品。 当位置变为`?`，乘以它的贡献。 当一个位置不再存在时`?`，使用模逆除以它的贡献。 

### 比较

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n! · n)`|`O(n)`| 太慢了 |
 | 最佳 |`O(n + m log MOD)`预处理,`O(1)`每个查询|`O(n)`| 已接受 |

 ## 算法演练

 1. 阅读`n`,`m`，和字符串`s`。 
2. 维护一个变量`ans`。 
3. 对于每个位置`i > 1`， 如果`s[i]`是`?`, 乘以`ans`经过`(i-1)`模数`998244353`。 
4. 维护一个单独的标志来指示是否`s[1]`是`?`。 
5. 目前的答案是：

 -`0`如果`s[1] == '?'`- 否则`ans`。 
6. 预先计算以下所有值的模逆`1`到`n`。 
7. 对于每个查询：

 1.移除旧角色的贡献度。 
2.添加新角色贡献度。 
3. 如有必要，更新特殊的第一个位置。 
4. 输出当前答案。 

### 为什么它有效

 逆过程中，当前设置的位置尺寸`i`正是`i+1`。 

人物`<`和`>`强制删除唯一元素，最小值或最大值。 他们贡献了一个因素`1`。 

一个角色`?`需要移除内部元件。 之中`i+1`元素，确切地说`i-1`是室内的。 每个内部选择都会留下相同类型的未来状态，因此有效序列的总数乘以`i-1`。 

Since choices at different positions are independent multiplicative factors, the total count is the product of all contributions. 唯一不可能的情况是`?`在位置`1`，根本没有任何内部元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
s = list(input().strip())

inv = [1] * (n + 1)
for i in range(1, n + 1):
    inv[i] = pow(i, MOD - 2, MOD)

ans = 1

for i in range(1, n - 1):
    if s[i] == '?':
        ans = ans * i % MOD

def current_answer():
    if s[0] == '?':
        return 0
    return ans

out = [str(current_answer())]

for _ in range(m):
    pos, c = input().split()
    pos = int(pos) - 1

    if pos > 0:
        if s[pos] == '?' and c != '?':
            ans = ans * inv[pos] % MOD
        elif s[pos] != '?' and c == '?':
            ans = ans * pos % MOD

    s[pos] = c
    out.append(str(current_answer()))

sys.stdout.write("\n".join(out))
```变量`ans`存储所有人贡献的产品`?`除了第一个位置之外的位置。 

该字符串使用从零开始的索引存储。 索引处的一个字符`pos`对应位置`pos + 1`在声明中。 其贡献是`(pos + 1) - 1 = pos`。 

这就是为什么更新使用`pos`而不是`pos + 1`。 

第一个字符需要单独处理。 它的贡献为零，因此不能在乘积内表示。 每当`s[0] == '?'`。 

删除贡献需要除以模`998244353`。 由于模数是素数，费马定理给出```
x^(-1) = x^(MOD-2) mod MOD
```它允许在预计算逆后进行恒定时间更新。

 ## 边缘情况

 考虑：```
n = 2
s = ?
```在第一个字符表示的时刻，该集合恰好包含两个元素。 任何选定的元素要么是最小值，要么是最大值。 没有内部元素，因此有效选择的数量为零。 该算法立即检测到这一点，因为`s[1]`是`?`，和输出`0`。 

考虑：```
n = 4
s = <??
```第一个`?`处于位置`2`, 贡献`2-1 = 1`。 

第二个`?`处于位置`3`, 贡献`3-1 = 2`。 

答案是：```
1 × 2 = 2
```一个常见的错误是乘以位置本身并获得`2 × 3 = 6`。 逆向过程的解释清楚地表明，内部元素的数量总是`set_size - 2`，等于`i - 1`， 不是`i`。
