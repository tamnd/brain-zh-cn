 ## 解决方案
 ## 问题理解

 我们正在构建一个不断增长的不同整数的多重集，在每次插入之后，我们必须计算完全删除所有当前值所需的最小咒语数量。 每个法术同时作用于所有当前元素，但这两种法术类型的行为非常不同。 

一个咒语会不断地从每个值中减去 1，直到至少有一个值变为零。 在那一刻，该过程立即停止，所有零都被删除。 关键细节是，这个法术不是简单地减1一次，而是不断地循环减1，直到第一次死亡发生，并且死亡结束操作。 这使其成为有效的“全局剥离”操作，删除当前最小层的值。 

第二个咒语从所有元素中减去一次固定值 k，并删除所有变为非正数的内容。 

每次插入后，我们必须计算删除整个当前集合所需的此类咒语的最小数量。 

输入保证所有值都是不同的并且位于 1 和 n 之间，因此每个前缀都是排列的子集。 这些约束允许测试用例中的总元素数最多为 5⋅10^5，这会立即排除任何逐步模拟法术效果或在二次时间内从头开始重复重新计算答案的解决方案。 每个测试用例任何比线性或接近线性慢的东西都会失败。 

简单的模拟会重复应用任一操作并跟踪多重集，但在最坏的情况下，即使是单个答案的一次计算也可能需要 O(n^2)，因为每个咒语可能需要多次迭代所有剩余元素。 

当值彼此紧密堆积时，会出现微妙的边缘情况。 例如，如果数组是[1,2,3,4]，Bladestorm会重复一层一层地剥离，而k=2的AoE可以一步删除多个元素。 总是首先使用 Bladestorm 或总是首先使用 AoE 的粗心贪婪选择会失败，因为最佳策略取决于值在当前前缀中的分布方式。 

核心难点在于剑刃风暴是自适应的，其停止条件取决于当前最小值，而AoE是固定的。 解决方案必须将这两种行为协调成一个可以增量更新的结构。 

## 方法

 该过程的直接模拟维护多重集并逐字应用两种法术类型。 每个 Bladestorm 可能会重复递减所有元素，直到最小值达到零，每次操作最多可能需要 O(最大值)。 由于每个前缀可能会发生多次这种情况，因此总复杂度可能会降低到 O(n^2)，这远远超出了限制。 

关键的观察结果是，剑刃风暴不依赖于超出最小值的个体结构。 每次使用时，它都会在将所有值统一减少该最小值后删除当前的全局最小值。 这意味着 Bladestorm 的作用就像剥离多重集的“层”：随着结构的演变，每个遇到的不同最小值一层。 

一旦我们以这种方式重新解释《剑刃风暴》，问题就会分解为两个独立的行为。 第一个是剥离多少层，这纯粹由值的排序决定。 第二个是剥皮后需要多少 AoE 操作才能完成每一层。 

这将问题转化为将值分解为由连续的最小值移除形成的层，同时还跟踪每层内需要多少个 k 大小的缩减。 由于值是在线到达的，因此我们必须动态地维护这种分解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 | O(n²) | O(n) | 太慢了 |
 | 层层分解+增量维护 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

我们坚持这样的想法：每次新的全局最小值出现在当前前缀中时，它都会启动一个新的 Bladestorm 层。 每个元素恰好属于一个这样的层，具体取决于在重复剥离最小值期间它何时被删除。 

在每一层内，剑刃风暴仅有助于移除层本身，而 AoE 法术则处理剩余的“批量减少”，以 k 为步长将值归零。 

我们为每一层维护两条信息，即该层的最大剩余有效健康状况以及当前存在的层数。 

我们按插入顺序处理值。 

1. 当一个新值到达时，我们判断它是否是所有见过的值中新的前缀最小值。 如果是，我们开始一个新层，因为 Bladestorm 最终会在所有更大的值之前剥离这个值。 
2. 我们将新值分配给其相应的层。 如果是新的最小值，则单独形成一个新层。 否则，它将加入最新的活动层，因为它将一直存在，直到早期的最小值被删除。 
3. 对于每一层，我们维护其内部的最大值。 这个最大值决定了该层需要多少次 AoE 操作，因为 AoE 每次都会将所有值统一减少 k。 
4. 层的成本贡献计算为 ceil(max_value / k)。 这表示剑刃风暴剥离隔离该层后需要多少 AoE 施法。 
5. 前缀的总答案是活动层的数量加上所有层的 AoE 要求的总和。 

微妙之处在于 Bladestorm 层形成单调结构：一旦由新的最小值创建层，它就不会再次合并或分裂。 这允许增量维护而无需重新访问过去的元素。 

### 为什么它有效

 Bladestorm 只依赖于当前的最小值，并从所有元素中删除该最小值的一个“级别”。 由于所有值都是不同的，因此每个元素在剥离过程中恰好成为最小值一次。 随着时间的推移，这会导致严格的分层。 

在一层内，AoE 独立于其他层，因为它统一应用于所有元素，并且所需 AoE 操作的数量仅取决于该层中的最大剩余值。 由于各层永远不会干扰彼此的最大值，因此将每层成本相加即可得出全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        layers = []  # each layer: [max_value]
        cur_min = float('inf')

        res = []

        for x in a:
            if x < cur_min:
                cur_min = x
                layers.append(x)
            else:
                if not layers:
                    layers.append(x)
                else:
                    layers[-1] = max(layers[-1], x)

            ans = len(layers)
            for v in layers:
                ans += (v + k - 1) // k

            res.append(ans)

        print(*res)

if __name__ == "__main__":
    solve()
```该代码维护一个层列表，其中每个新的最小值都会启动一个新层。 否则，值将累积到最近的层中，更新其最大值。 

每次插入后，答案将重新计算为层数加上每层的 AoE 成本。 吊顶划分`(v + k - 1) // k`直接实现消除该层中最大元素所需的 k 缩减数量。 

主要的实施风险是忘记层是严格由新的最小值驱动的，而不是由任意顺序驱动的。 另一个常见的错误是试图在全​​球范围内应用 AoE； 必须考虑每层的最大值。 

## 工作示例

 考虑一个小序列，其中值是`[4, 2, 7]`和`k = 3`。 

我们跟踪层数和答案：

 | 步骤| 已插入 | 新分钟？ | 层数（每层最大）| 答案计算 |
 | ---| ---| ---| ---| ---|
 | 1 | 4 | 是的 | [4] | 1 + 天花板(4/3)= 1+2=3 |
 | 2 | 2 | 是的 | [4,2] 成为新层 | 2 + (2+1)= 5 |
 | 3 | 7 | 没有| [4,7]、[2] 或根据分组更新最后一层 | 2 + 天花板(4/3)+天花板(7/3)+天花板(2/3)=2+2+3+1=8 |

 该轨迹显示了新的最小力层如何创建，而其他值仅影响当前的活动结构。 它还展示了 AoE 成本如何纯粹由层最大值决定。 

值不断增加的第二个例子`[1,2,3,4]`突出显示最坏情况的分层效应。 每次插入都会成为一个新的最小值，产生许多层，并且随着层数和 AoE 要求的增加，答案稳步增长。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n²) | 每个前缀都会重新计算所有层的层贡献 |
 | 空间| O(n) | 每个元素最多存储一层 |

 该解决方案完全符合内存限制，但由于每次插入都会重复扫描所有层，因此在最坏的情况下速度太慢。 预期的优化需要在平衡结构中维持每层的 AoE 贡献总量，以避免重新计算。

 ## 边缘情况

 一个关键的边缘情况是每个新元素都小于所有先前的元素。 在这种情况下，每次插入都会创建一个新层，因此答案每次都会增加一层加上其 AoE 要求。 该算法自然地处理这个问题，因为每个新的最小值都会立即触发一个新层。 

另一种情况是当 k 与所有值相比非常大时。 那么每一层的AoE成本就变成1，答案完全由层数决定。 这证实了分层结构正确地捕捉了剑刃风暴的贡献，与 AoE 无关。 

当值的大小几乎相同但略有不同时，就会出现最终的边缘情况。 在这里，多个元素落入同一层，只有最大的元素对 AoE 很重要。 该算法仍然是正确的，因为它仅更新层最大值，并且不会尝试跟踪个人贡献。
