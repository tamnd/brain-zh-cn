 ## 解决方案
 ## 问题理解

 我们得到一棵标记为 1 到 n 的顶点上的有根树，其中除根之外的每个节点都有一个指向较小索引父节点的传出边。 这种方向使得每个顶点都有到根的唯一路径。 

n 个司机依次到达。 每个驱动程序从首选顶点 si 开始。 如果该顶点是空闲的，它们就会占据它。 否则，它们沿着父指针向上移动，直到找到第一个未占用的顶点并停在那里。 如果到根的整个路径已被占用，则驱动程序将失败。 

如果每个驱动程序在此规则下成功找到自由顶点，则该序列被称为有效。 任务是计算有多少长度为 n 的序列有效，以 998244353 为模。 

输入树不是任意的。 它以非常具体的递增标签方式生成，其中每个 i 均匀地附加到前一个顶点。 这使得该结构成为一棵随机递归树，但在这个问题中，我们给出了一个固定的实现，并且必须计算它的答案。 

n 高达 100000 的约束迫使我们远离任何尝试显式模拟序列的方法。 对单个序列的简单模拟成本为 O(n)，并且有 n^n 个序列，这是完全不可行的。 即使对顶点子集的动态规划也会涉及 2^n 个状态，这也是不可能的。 

一个更微妙的问题是停车对顺序敏感。 即使对于小树来说，更换早期的驱动程序也可以极大地改变可用性模式。 例如，如果树是链 1 <- 2 <- 3，则 (3,3,3) 和 (1,2,3) 等序列的行为非常不同，并且朴素的对称性假设会立即破裂。 

关键的隐藏困难在于，每个驱动程序的最终位置仅取决于其起始节点的第一个空祖先，因此该过程相当于在不相交的路径中重复声明最高可用祖先，这建议采用结构计数方法而不是模拟。 

## 方法

 直接的强力方法将枚举所有 n 长度的首选顶点序列。 对于每个序列，我们在 O(n) 中模拟停车过程，标记占用的顶点并向上行走，直到找到空闲顶点。 每个序列的成本已经是 O(n)，并且由于有 n^n 个序列，因此总工作量是天文数字。 

即使我们将注意力限制在排列上或尝试利用对称性，选择之间的依赖性仍然是全局的，因为每个占用都会改变整个根路径上的可用性。 瓶颈在于每次模拟都重复向上遍历父指针，并且多次重新访问相同的结构。 

关键的观察是扭转观点。 我们可以考虑序列可以通过多少种方式实现给定的最终占用模式，而不是将驱动程序分配给首选顶点。 停放过程总是以所有顶点仅被占用一次而结束，并且最终状态始终是以与祖先约束一致的方式填充的顶点的排列。 

这表明将这个过程视为构建一个不断增加的森林结构，其中每个顶点“声称”对一段可能的起始位置负责。 树方向确保每个顶点仅与其祖先竞争第一个可用的停止点，并且一旦我们以子树大小为条件，这些竞争在子树之间是独立的。 

关键的简化是，对于这个特定的随机递归树，子树大小以乘法方式相互作用：每个节点仅根据其子树大小贡献一个因子。 最终答案成为组合项顶点的乘积，该组合项源自驱动程序存在多少种选择，最终在该子树边界中得到解决。

这将问题从指数枚举简化为具有子树 DP 累积贡献的单次遍历。

 | --- | --- | --- | --- |
 | 暴力模拟| O(n·n^n) | O(n·n^n) | O(n) | 太慢了 |
 | Tree DP 产品形式 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将树的根设为 1 并计算子树的大小。 

1. 使用 DFS 计算每个节点的子树大小。 节点的子树大小表示有多少顶点依赖于它作为祖先。 这一点至关重要，因为沿路径的每个停车决策都会影响一条祖先链，而子树大小衡量有多少个这样的链经过一个节点。 
2. 将答案变量初始化为1。我们将独立累积每个节点的贡献。 
3. 以与树一致的任意顺序遍历节点（后序比较方便）。 对于每个节点 u，令 su 为其子树大小。 将答案乘以 su。 出现这个因素是因为当单独考虑子树时，有多种方法可以在该子树的结构中分配“最后一个未填充的选择边界”。 
4. 输出对 998244353 取模的最终结果。 

该算法看似简单：一切都崩溃为子树大小的乘积，因为每个节点有效地贡献了一个乘法自由度，该自由度等于其子树可以吸收传入偏好链而不发生冲突的方式数量。 

### 为什么它有效

 停车过程将驱动程序划分为组，其解析顶点位于特定的祖先路径上。 一旦更高的祖先被固定，每个子树的行为就像一个独立的系统，因为从子树外部开始的驱动程序都不能在不经过该子树的根的情况下跳入子树，并且一旦该根被占用或未被占用，子树的内部结构就会独立演化。 

这种独立性意味着有效序列的总数因式分解到节点上。 每个节点贡献的重数恰好等于在其子树内“锚定”到达的方式的数量，这正是其子树的大小。 由于每个分配选择都是子树边界的局部并且不会干扰不相交的区域，因此节点上的乘法保留了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

def solve():
    n = int(input())
    p = [0] * (n + 1)
    for i in range(2, n + 1):
        p[i] = int(input().split()[0])

    g = [[] for _ in range(n + 1)]
    for i in range(2, n + 1):
        g[p[i]].append(i)

    mod = 998244353

    sz = [0] * (n + 1)

    def dfs(u):
        sz[u] = 1
        for v in g[u]:
            dfs(v)
            sz[u] += sz[v]

    dfs(1)

    ans = 1
    for i in range(1, n + 1):
        ans = (ans * sz[i]) % mod

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先根据父指针重建有根树。 DFS 在线性时间内计算子树大小。 最后的循环将所有子树大小乘以给定素数的模。 

关键的实现细节是递归深度，因为 n 可以达到 100000。增加递归限制可以避免堆栈溢出。 每次迭代时必须以 998244353 为模进行乘法步骤，以防止溢出。

```树结构是一个星形，根为 1，子节点为 2 和 3。

 这演示了更深的链如何增加中间节点的组合自由度，因为子树大小编码了可以通过每个祖先级别“冒泡”的驱动程序数量。

 线性复杂度很好地匹配约束 n ≤ 100000，即使对于最坏情况的链形树，时间和内存也都在限制之内。

 ## 边缘情况

 单链暴露子树乘法是否正确累积深度效应。 对于像 1 <- 2 <- 3 <- 4 这样的链，子树大小为 4, 3, 2, 1，乘积变为 24。 DFS 正确计算这些大小，因为每个节点都贡献了一条向上的路径，并且递归自然地累积它们而不会重复计算。 

星形树强调是否保留兄弟姐妹的独立性。 将根 1 和所有其他子树作为子节点，根的子树大小为 n，所有叶子的子树大小为 1，产生答案 n。 DFS 确保每个叶子在其自己的子树中被隔离，并且不会错误地累积来自兄弟节点的贡献，因为递归仅将每个节点的子大小聚合到父节点中一次。
