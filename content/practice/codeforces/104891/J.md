 ## 解决方案
 ## 问题理解

 我们得到了一个按循环排列的房间系统`0`到`n-1`。 每个房间都有一个整数`a[i]`显示在圆形表盘上。 从房间`i`，Bobo 有两个可能的动作，每个动作恰好花费一个单位时间。 

他可以在房间里旋转旋钮`i`顺时针方向，增加`a[i]`一个，或者他可以立即传送到房间`(i + a[i]) mod n`，使用表盘的当前值作为跳跃长度。 

波波从房间开始`0`并想要到达房间`x`在最短的总时间内。 

关键的微妙之处在于数组`a[i]`不是固定的。 每次我们决定使用房间的传送时，我们可能会事先花时间增加其价值，并且修改后的价值将持续存在于该房间的未来使用中。 

所以问题不仅仅是固定边上的最短路径。 它是一条最短路径，其中节点的边权重取决于我们在使用该节点之前增加该节点的次数。 

约束允许最多`n = 100000`，这立即排除了任何试图模拟所有状态的解决方案`(room, value of all a[i])`。 即使存储完整的全局状态也是不可能的。 解决方案必须避免将增量视为全局状态空间的一部分。 

一些边缘情况暴露了幼稚的推理失败。 如果`a[i] = 0`为所有人`i`，除非我们首先增量，否则传送不会执行任何操作，因此每个有用的移动都需要每步至少支付一个增量。 如果全部`a[i]`已经很大并直接导致`x`，最佳答案可能只是几次传送，根本没有增量。 另一种棘手的情况是，在多次使用之前重复增加一个房间可以提供更好的长期路由，因为增量是永久性的且可重复使用的。 

## 方法

 直接的强力视图是将阵列的每个配置视为一种状态。 在某个状态下，我们可以增加任何索引或从当前房间传送。 这会导致爆炸：每个增量都会改变全局状态，并且每个增量都会改变全局状态。`a[i]`可以增长任意大。 甚至限制值模`n`仍然离开`n^n`可能的状态，这是完全不可行的。 

一种更结构化的暴力方法是在扩展图上模拟最短路径，其中每个节点都是`(current room, full array state)`。 这仍然是指数级的并且无法使用。 

关键的观察是我们永远不需要跟踪增量的完整历史记录。 重要的是每个房间在下次传送使用之前增加了多少次。 每个增量都是本地的并且跨房间独立的，一旦我们决定以某个值使用房间，我们只关心可以实现特定有效偏移的最佳时间。 

对于固定房间`i`，如果我们决定之后使用它`k`增量，该房间支付的成本恰好是`k + 1`（k 递增加上一次传送），过渡变为`(i + a[i] + k) mod n`。 这意味着每个房间都会生成无限序列的可能的传出边缘，并且成本不断增加，形成单调结构。 

这种结构使我们能够将问题视为图上的最短路径，其中每个节点都有一系列成本增量不断增加的传出边。 我们可以懒惰地处理每个房间，在需要时始终考虑下一个未使用的增量级别。 这自然是通过类似 Dijkstra 的状态处理来处理的`(room, how many times we have used this room as a source)`无需显式存储完整的数组状态。 

我们始终在所有房间中扩展最便宜的可用“下一次传送使用”，这保证了由于每个房间成本增加的单调性而实现的最优性。

 ## 算法演练

 我们为每个房间建模`i`就像有一系列可能的传送动作，通过我们在使用它之前增加它的次数来索引。 使用它的`k`第 次时间成本`k + 1`该房间使用的总操作数，并使我们移动到`(i + a[i] + k) mod n`。 

然后，我们在房间上运行最短路径过程，但不是每个房间都有一条边，而是从每个房间懒惰地生成越来越好的边。 

1.初始化一个距离数组`dist`尺寸的`n`与无穷大，并设置`dist[0] = 0`因为我们从房间开始`0`。 
2. 每个房间`i`,维护一个指针`used[i] = 0`代表我们在之前的扩展中已经为该房间“消耗”了多少增量。 这确保我们永远不会两次重新考虑相同的增量级别。 
3. 推`(0, 0)`进入优先队列，代表在房间`0`零成本。 
4. 反复提取状态`(d, i)`与队列的距离最小。 如果`d`不等于`dist[i]`，跳过它，因为它已经过时了。 
5. 从房间`i`，考虑当前增量级别的下一个可用传送使用情况`used[i]`。 使用它的成本是`d + used[i] + 1`，目的地是`(i + a[i] + used[i]) mod n`。 
6. 如果新的成本有所改善`dist[j]`， 在哪里`j`是目的地房间，更新`dist[j]`并将其推入优先队列。 
7. 增量`used[i]`增加一间，从下次我们扩大房间开始`i`，我们将考虑其传送的下一个增量版本。 
8. 继续，直到优先级队列为空。 

该算法总是在所有房间中扩展最便宜的可能的下一次传送使用，并逐渐增加再次使用每个房间的成本。 

### 为什么它有效

 每个房间都会生成严格递增的可能传送操作序列，其中该房间的第 k 个操作的成本始终比前一个操作高 1。 这种单调性保证了一旦我们考虑了房间的第 k 次使用，以后对同一级别的任何使用都不会变得更便宜。 

优先级队列确保我们始终处理接下来全局最便宜的可用操作。 这相当于在隐式扩展图上运行 Dijkstra，其中每个房间都有一个按成本排序的无限传出边链。 由于每个房间的边缘成本是单调的，并且每个级别只处理一次，因此不会错误地跳过或延迟最佳路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    INF = 10**18
    dist = [INF] * n
    dist[0] = 0

    used = [0] * n
    pq = [(0, 0)]

    while pq:
        d, i = heapq.heappop(pq)
        if d != dist[i]:
            continue
        if i == x:
            print(d)
            return

        k = used[i]
        used[i] += 1

        j = (i + a[i] + k) % n
        nd = d + k + 1

        if nd < dist[j]:
            dist[j] = nd
            heapq.heappush(pq, (nd, j))

solve()
```该实现使用标准 Dijkstra 框架，但每个节点不会同时公开其所有传出边。 相反，每个房间每次从优先级队列中弹出时都会显示一个新的传出转换。 

这`used[i]`数组是必不可少的。 如果没有它，我们将重复地重新生成相同的转换，从而导致无限或重复的处理。 它强制房间的每个增量级别仅被消耗一次。 

终止检查`if i == x`是安全的，因为 Dijkstra 保证我们第一次弹出目的地时，就能以最小的成本到达目的地。

 ## 边缘情况

 一个关键的边缘情况是当所有`a[i]`为零。 在这种情况下，每个传送最初都会循环回到同一个房间，因此进度完全取决于移动之前累积的增量。 该算法通过重复扩展同一个房间、增加`used[i]`每次，有效目的地都会逐渐变化并最终到达新的房间。 

另一种情况是，单个增量将无用的转换转换为直接的快捷方式`x`。 因为每个房间都是按递增顺序扩展的`k`，第一次达到有益增量级别时，它会被发现并以其正确的成本推入队列，确保以后更昂贵的版本不会覆盖它。 

当多个房间可以以不同的增量成本到达同一目的地时，会出现最后一个微妙的情况。 优先级队列保证只有最小的成本才能存活`dist`，而冗余的较大成本到达在弹出时会被忽略，即使在状态大量重复的情况下也能保持正确性。
