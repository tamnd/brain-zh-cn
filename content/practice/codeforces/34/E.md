 ## 解决方案
 ## 问题理解

 我们有几个在一维线上移动的点状球。 每个球都从某个坐标开始，具有自己的速度和质量。 每当两个球同时占据同一位置时，它们就会发生弹性碰撞，并且它们的速度根据一维弹性碰撞的标准物理公式而变化。 

任务不仅仅是模拟速度。 我们必须准确地输出原始球的最终坐标`t`秒。 由于碰撞会改变未来的运动，因此每次碰撞都会影响所有后续事件。 

限制异常小。 球数最多 10 个，时间最多 100 个。小`n`彻底改变问题的性质。 甚至一个`O(n^3)`或者`O(n^4)`事件模拟很容易足够快。 挑战不在于渐近复杂性，而在于数值正确性以及按正确的时间顺序处理冲突。 

具有微小时间步长的简单连续模拟将会严重失败。 冲突可能发生在看起来不合理的小数时间，并且以 epsilon 增量逐步遍历时间会累积浮点错误。 预期的解决方案是事件驱动的：始终直接跳转到下一个碰撞。 

一个容易犯的错误是以错误的顺序处理碰撞。 考虑：```
3 10
0 3 1
10 0 1
20 -3 1
```左球先击中中球，然后中球击中右球。 如果我们独立更新所有对而不考虑时间顺序，我们就会产生不可能的轨迹。 

另一个微妙的情况是同时位置更新。 假设两个球同时碰撞`2.5`。 在计算新速度之前，必须更新它们在该时刻的位置。 如果我们先改变速度然后移动它们，碰撞点就会出错。 

例子：```
2 5
0 2 1
10 -2 1
```他们在某个位置相遇`5`后`2.5`秒。 等质量弹性碰撞后，它们交换速度。 最终位置变为：```
5 - 2.5*2 = 0
5 + 2.5*2 = 10
```粗心的实施可能会使用旧速度移动它们整整 5 秒并错误输出`10`和`0`。 

另一个危险的情况是碰撞次数几乎相等。 浮点比较必须使用 epsilon。 否则，由于精度噪声，算法可能会选择错误的下一次碰撞。 

该声明保证三个球不会同时相撞。 这极大地简化了实施。 我们永远不需要解决多体碰撞。 

## 方法

 最直接的想法是时间增量非常小的物理模拟。 每一步我们都会移动每一个球`v * dt`，然后检查某对是否相互交叉。 这在概念上是有效的，因为足够小的步长近似于连续运动。 

问题是精度。 如果`dt`太大，完全错过了碰撞。 如果`dt`足够小而可靠，迭代次数会爆炸。 例如，使用`dt = 1e-6`超过100秒已经意味着`10^8`模拟步骤。 即使只有 10 个球，这也是不切实际的并且在数值上不稳定。 

问题的结构给出了一条更清晰的路线。 在碰撞之间，每个球都以恒定速度线性移动。 除了碰撞时刻之外，不会发生任何有趣的事情。 这意味着我们永远不需要检查中间时间。 我们只需要最早的未来碰撞。 

对于每对球，我们可以分析计算它们何时相遇：$$x_i + v_i t = x_j + v_j t$$这给出：$t=\frac{x_j-x_i}{v_i-v_j}$有效的碰撞需要正时间和彼此相对运动。 

一旦知道最早的碰撞，我们将每个球直接推进到那个时间，使用弹性碰撞公式更新两个碰撞速度，然后重复。 

因为`n ≤ 10`，在每个事件之后重新计算所有对碰撞时间是完全没问题的。 即使有很多碰撞，总的工作量仍然很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力时间步进 | 极大，取决于精度| O(n) | 太慢且不准确 |
 | 事件驱动模拟| O(C·n²) | O(C·n²) | O(n) | 已接受 |

 这里`C`是在该时间之前发生的碰撞次数`t`。 

## 算法演练

 1. 存储每个球的当前位置、速度、质量和原始索引。 
2. 维护一个变量`cur_time`， 最初`0`。 
3. 对于每对球`(i, j)`，计算如果速度保持不变，它们何时会发生碰撞。 
4.忽略无效的碰撞次数。 

如果满足以下条件，则碰撞无效：

 - 速度相等，因为距离永远不变，
 - 碰撞时间为非正数，
 - 碰撞发生在剩余允许的模拟时间之后。 
5. 在所有有效碰撞中，选择最小的碰撞时间`dt`。 

这是系统中的下一个物理事件。 在这一刻之前，除了线性运动之外，没有任何变化。 
6. 如果在目标时间之前不存在碰撞：

 1. 将每个球向前移动剩余时间。 
2. 停止模拟。 
7. 否则：

 1. 将每个球向前移动`dt`。 
2. 增加`cur_time`经过`dt`。 
3.让球`i`和`j`成为碰撞对。 
4. 使用弹性碰撞公式计算它们的新速度：$v_1'=\frac{(m_1-m_2)v_1+2m_2v_2}{m_1+m_2}$

$v_2'=\frac{(m_2-m_1)v_2+2m_1v_1}{m_1+m_2}$1.从步骤3开始重复，直到总模拟时间达到`t`。 
2. 恢复打印答案之前的原始输入顺序。 

### 为什么它有效

 在碰撞之间，每个物体都以恒定速度移动，因此位置是时间的线性函数。 未来的第一次碰撞是唯一能够改变速度的事件。 直接前进到该事件可以保留精确的物理轨迹。 

处理碰撞后，新的速度正是弹性碰撞物理所决定的速度。 由于该语句保证不会发生三重碰撞，因此每个事件恰好涉及一对，因此顺序处理碰撞是有效的。 

通过始终选择最早的碰撞，模拟再现了系统的真实时间顺序。 后面的碰撞不会影响前面的碰撞。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

EPS = 1e-10

def solve():
    n, T = map(float, input().split())
    n = int(n)

    balls = []

    for idx in range(n):
        x, v, m = map(float, input().split())
        balls.append({
            "x": x,
            "v": v,
            "m": m,
            "idx": idx
        })

    cur_time = 0.0

    while cur_time < T - EPS:
        best_dt = float('inf')
        pair = (-1, -1)

        # Find earliest collision
        for i in range(n):
            for j in range(i + 1, n):
                xi = balls[i]["x"]
                xj = balls[j]["x"]
                vi = balls[i]["v"]
                vj = balls[j]["v"]

                rel_v = vi - vj

                if abs(rel_v) < EPS:
                    continue

                dt = (xj - xi) / rel_v

                if dt <= EPS:
                    continue

                if cur_time + dt > T + EPS:
                    continue

                if dt < best_dt:
                    best_dt = dt
                    pair = (i, j)

        # No more collisions
        if pair == (-1, -1):
            remain = T - cur_time

            for b in balls:
                b["x"] += b["v"] * remain

            break

        # Advance to collision
        for b in balls:
            b["x"] += b["v"] * best_dt

        cur_time += best_dt

        i, j = pair

        m1 = balls[i]["m"]
        m2 = balls[j]["m"]

        v1 = balls[i]["v"]
        v2 = balls[j]["v"]

        nv1 = ((m1 - m2) * v1 + 2 * m2 * v2) / (m1 + m2)
        nv2 = ((m2 - m1) * v2 + 2 * m1 * v1) / (m1 + m2)

        balls[i]["v"] = nv1
        balls[j]["v"] = nv2

    balls.sort(key=lambda b: b["idx"])

    print(*["{:.10f}".format(b["x"]) for b in balls])

solve()
```主循环重复搜索下一个碰撞事件。 自从`n`很小，每次都检查每一对比维护事件优先级队列更简单、更安全。 

碰撞公式直接来自求解线性相遇方程。 我们跳过非正时间，因为它们代表过去的碰撞或由浮点噪声引起的立即自相交。 

模拟始终在改变速度之前更新位置。 这个顺序很重要。 在碰撞瞬间，所有球必须首先到达其正确的物理坐标。 

epsilon 比较可防止浮点运算的不稳定。 如果没有它们，两个数学上相同的时间在重复更新后可能会不正确地进行比较。 

在模拟过程中，球永远不会重新排序。 我们仅在输出之前按原始索引排序，因此结果与输入顺序匹配。

 ## 边缘情况

 考虑两个球以相同速度移动的情况。```
2 10
0 3 1
5 3 2
```相对速度为零，因此会议时间公式将除以零。 该算法明确地跳过此类对。 最终位置变为：```
30
35
```因为两个球都没有接住另一个球。 

另一个微妙的情况是在最后时间发生碰撞。```
2 5
0 1 1
10 -1 1
```他们碰撞于`t = 5`。 该算法接受此事件，因为碰撞时间未超出目标时间。 两个球都到达指定位置`5`。 

使用严格的浮点实现`< T`比较可能会错误地跳过碰撞。 

现在考虑顺序碰撞：```
3 4
0 3 1
10 0 1
20 -3 1
```第一次碰撞发生在球 0 和 1 之间，时间为`10/3`。 等质量交换后，球1以速度向右移动`3`，最终与球 2 碰撞。 

该算法可以正确处理此问题，因为在每次事件发生后，它都会根据更新的状态重新计算所有未来的碰撞时间。 由于速度发生了变化，旧的预测被丢弃。
