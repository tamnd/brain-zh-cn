 ## 解决方案
 ## 问题理解

 我们从一个\(n \times n\)拉丁广场。 每一行都是一个排列\(1 \ldots n\)，每列也是排列\(1 \ldots n\)。 

一系列操作会修改矩阵。 四个操作执行行或列的循环移位。 另外两个操作比较不寻常：\(I\)将每个行排列替换为其逆排列。\(C\)将每个列排列替换为其逆排列。 

完成所有操作后，我们必须输出结果矩阵。 

第一个观察来自于约束。 全部的总和\(n\)至多是\(1000\)，因此每个测试用例打印最终矩阵的成本已经为 \(O(n^2)\)。 这部分是不可避免的。 真正的挑战是操作字符串，其总长度可以达到\(10^5\)。 

简单的模拟会将每个操作直接应用于矩阵。 每一次操作都触及\(n^2\)细胞，因此最坏的情况变成$$
O(mn^2).
$$和\(m=10^5\)和\(n=1000\)，这是完全不可行的。 

问题在于隐藏了强大的代数结构。 拉丁方格自然包含三个坐标：$$
(\text{row}, \text{column}, \text{value}).
$$这六种操作永远不会破坏拉丁方属性，因为它们只是以各种方式排列这三个坐标。 

### 不明显的边缘情况

 考虑\(n=3\)和操作\(I\)。$$
\begin{matrix}
1&2&3\\
2&3&1\\
3&1&2
\end{matrix}
$$粗心的实现可能会尝试独立反转每一行。 这确实有效，但它忽略了更深层次的结构。 求逆后矩阵变为$$
\begin{matrix}
1&2&3\\
3&1&2\\
2&3&1
\end{matrix}
$$如果列索引和值交换角色，就会发生这种情况。 这个坐标解释是最优解的关键。 

考虑运营\(C\)在同一个矩阵上。 

结果是$$
\begin{matrix}
1&3&2\\
2&1&3\\
3&2&1
\end{matrix}
$$这不是行反转。 它交换行索引和值。 混合这两种转换会产生错误的答案，但看起来仍然像有效的拉丁方。 

当许多班次累积时，就会出现另一种微妙的情况。 

例如，与\(n=5\),$$
RRRRR
$$必须产生原始矩阵。 存储移位模数\(n\)是强制性的。 允许偏移量增长而不减少最终会导致不正确的索引。 

## 方法

 蛮力方法直接将每个操作应用于矩阵。 

为了\(R,L,U,D\)，我们旋转行或列。 为了\(I\)，我们计算每一行的逆排列。 为了\(C\)，我们计算每列的逆排列。 

每个操作的成本为\(O(n^2)\)。 既然可以有\(10^5\)操作，总复杂度变为$$
O(mn^2).
$$瓶颈在于我们重复移动相同的数据。 

要找到更好的东西，请检查矩阵条目作为三元组$$
(r,c,x),
$$在哪里\(r\)是行索引，\(c\)列索引，以及\(x\)值。 

因为矩阵是拉丁方，所以每个操作都可以完全描述为这三个坐标的变换。 

移位操作仅修改一个坐标：$$
R,L : c
$$

$$
U,D : r
$$反转操作更有趣。 

对于行排列，反转会交换该行内的位置和值。 因此$$
I : c \leftrightarrow x.
$$对于列排列，反转交换行和值：$$
C : r \leftrightarrow x.
$$关键的见解是，每个操作仅排列三种坐标类型 \((r,c,x)\) 并将循环移位添加到当前扮演行、列或值角色的坐标。 

我们不变换整个矩阵，而是跟踪：

 1. 当前哪个原始坐标代表行。 
2. 当前哪个原始坐标代表列。 
3. 当前哪个原始坐标代表值。 
4. 附加到每个坐标的偏移量。 

处理完所有操作后，我们在\(O(n^2)\)中重建一次答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | \(O(mn^2)\) | \(O(n^2)\) | 太慢了|
 | 最佳 | \(O(m+n^2)\) | \(O(n^2)\) | 已接受 |

 ## 算法演练

 让坐标类型编号：$$
0=r,\quad 1=c,\quad 2=x.
$$维护一个数组\(p\)在哪里：$$
p[i]
$$告诉当前哪个原始坐标占据位置\(i\)。 

维持偏移量$$
add[0],add[1],add[2].
$$所有坐标均以从零开始的形式存储。 

1. 初始化$$
p=[0,1,2]
$$和$$
add=[0,0,0].
$$2. 处理每个操作。 

3.为了\(R\)，增加当前充当列的坐标的偏移量：$$
add[p[1]]=(add[p[1]]+1)\bmod n.
$$4. 对于\(L\)，减少相同的偏移模数\(n\)。 

5. 对于\(D\)，增加当前充当行的坐标的偏移量：$$
add[p[0]]=(add[p[0]]+1)\bmod n.
$$6. 对于\(U\)，以模数减少偏移量\(n\)。 

7. 对于\(I\)，交换列和值的角色：$$
p[1],p[2]=p[2],p[1].
$$8.为了\(C\)，交换行和值的角色：$$
p[0],p[2]=p[2],p[0].
$$9. 完成所有操作后，访问每个原始单元\((i,j)\)。 

10. 将值转换为从零开始的形式：$$
x=a_{ij}-1.
$$11. 表格$$
cur=[i,j,x].
$$12. 应用累积偏移量：$$
cur[k]=(cur[k]+add[k])\bmod n.
$$13. 使用以下命令将转换后的坐标放入其最终角色\(p\)。 

14.让$$
res[p[k]]=cur[k].
$$15.然后$$
res[0]
$$是最后一行，$$
res[1]
$$是最后一栏，

 和$$
res[2]
$$是最终值。 

16. 写$$
res[2]+1
$$进入答案矩阵的位置$$
(res[0],res[1]).
$$### 为什么它有效

 每个操作都作用于三元组\((r,c,x)\)。 移位操作添加\(1\)或者\(-1\)模数\(n\)到当前用作行或列的坐标。 行动\(I\)和\(C\)从不修改坐标值本身，它们只是交换坐标类型的含义。 

该算法准确地维护了这两条信息：排列\(p\)描述坐标类型的当前含义，以及描述所有累积循环移位的偏移量。 由于每个操作在转换坐标三元组时都会准确地更新这些结构，因此处理操作字符串后的表示与分别将操作应用于每个单元格相同。 从变换后的三元组重建矩阵产生唯一的最终矩阵。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]
        ops = input().strip()

        p = [0, 1, 2]
        add = [0, 0, 0]

        for ch in ops:
            if ch == 'R':
                add[p[1]] = (add[p[1]] + 1) % n
            elif ch == 'L':
                add[p[1]] = (add[p[1]] - 1) % n
            elif ch == 'D':
                add[p[0]] = (add[p[0]] + 1) % n
            elif ch == 'U':
                add[p[0]] = (add[p[0]] - 1) % n
            elif ch == 'I':
                p[1], p[2] = p[2], p[1]
            else:  # 'C'
                p[0], p[2] = p[2], p[0]

        ans = [[0] * n for _ in range(n)]

        for i in range(n):
            for j in range(n):
                cur = [i, j, a[i][j] - 1]

                for k in range(3):
                    cur[k] = (cur[k] + add[k]) % n

                res = [0, 0, 0]

                for k in range(3):
                    res[p[k]] = cur[k]

                ans[res[0]][res[1]] = res[2] + 1

        out = []
        for row in ans:
            out.append(" ".join(map(str, row)))
        sys.stdout.write("\n".join(out) + "\n")

solve()
```数组`p`存储坐标角色的当前排列。 每当`I`或者`C`出现，只有这个排列发生变化。 

数组`add`存储附加到原始坐标类型而不是当前角色的班次。 这个细节很容易出错。 如果坐标后来因为以下原因改变角色`I`或者`C`，其累积的位移必须随之移动。 

在重建过程中，每个单元都被解释为一个坐标三元组。 首先应用偏移，因为它们属于坐标类型。 然后是排列`p`确定哪个变换后的坐标变为行、列或值。 

模运算可处理任意长的移位序列，而不会发生溢出或索引漂移。

 ## 边缘情况

 考虑\(n=1\)。 每个坐标模\(1\)遗迹\(0\)。 每次交换都会使单个单元保持不变。 算法保持`p`和`add`，重建一个三元组，并输出`1`。 

考虑一个序列，例如`RRRRR`和\(n=5\)。 列偏移变为$$
(0+5)\bmod 5 = 0.
$$重建阶段接收原始坐标并再现原始矩阵。 任何存储原始移位而不减少模数的实现\(n\)以后可能会出现索引不正确的风险。 

考虑`IC`。 后`I`、列和值交换。 后`C`、行和值交换。 这些操作作用于坐标角色，而不是直接作用于矩阵条目。 仅跟踪行和列的移动会错过这种交互。 排列数组`p`正确记录$$
[0,1,2]
\to
[0,2,1]
\to
[1,2,0],
$$这正是操作执行的坐标变换。
