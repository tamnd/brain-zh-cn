 ## 解决方案
 ## 问题理解

 我们被要求分析两堆 Nim 博弈的一个变体。 在具有两堆的经典 Nim 中，每个玩家可以从任一堆中取出任意正数的石子。 无法采取行动的玩家就输了。 这里的不同之处在于“捷径位置”的存在，这是特定的堆配置，轮到的玩家立即输掉比赛，而不管通常的 Nim 规则如何。 我们被给予`n`快捷位置和`m`初始位置，对于每个初始位置，我们需要确定第一个玩家是否可以在最佳玩法下强行获胜。 

输入可能很大：`n`和`m`最多可达 100,000，堆大小可达 1e9。 这排除了任何尝试显式模拟所有游戏状态的解决方案，因为状态空间巨大。 枚举所有可能的堆大小的简单递归或动态编程方法是不可行的。 

边缘情况包括一个或两个堆为零的位置、与快捷方式完全一致的位置以及非常大的堆大小。 例如，初始位置为`(0, 1)`这是一个快捷方式应该返回“LOSE”，而`(0, 1)`未列为快捷方式的应使用正常 Nim 逻辑进行分析。 

## 方法

 暴力方法将为每个可能的堆对分配获胜或失败状态`(x, y)`直至给定的最大值。 这可以通过检查从一个位置开始的所有可能的移动来递归地完成。 这是正确的，因为它详尽地评估了每种情况，但速度慢得令人绝望。 对于最大 1e9 的堆大小，状态数量实际上是无界的，即使使用记忆化，也会为每个可能的状态存储一个映射`(x, y)`是不可能的。 

关键的见解来自经典的尼姆理论。 在没有捷径的两堆 Nim 中，一个位置`(x, y)`正在失败当且仅当`x XOR y = 0`。 该结果立即确定了正常 Nim 的输赢位置。 快捷方式会改变失败的位置：无论 XOR 值如何，任何快捷方式对都会失败。 现在问题可以简化为计算每个查询的 XOR 并对照快捷方式列表进行检查。 

我们可以将快捷方式存储在一组中以进行 O(1) 查找。 然后，对于每个初始位置，我们检查它是否在快捷方式集中。 如果是，则起始玩家输。 如果不是，我们计算`x XOR y`; 如果为零，则起始玩家失败，否则他们可以获胜。 这避免了迭代大量的状态空间并利用 Nim 的 XOR 属性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^max(x, y)) | O(2^max(x, y)) | O(最大(x*y)) | 太慢了|
 | 最佳 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`来自输入。 这些指示快捷方式和初始位置的数量。 
2. 阅读全部`n`快捷键位置到集合中`shortcuts`。 使用集合可确保成员资格查询的复杂度为 O(1)，对于最多 100,000 个查询，这一点至关重要。 
3. 对于每个初始位置`(a, b)`，首先检查是否`(a, b)`存在于快捷方式集中。 如果是，则立即输出“LOSE”，因为规则规定玩家在捷径处立即失败。 
4. 如果该位置不是快捷方式，则计算 XOR`a ^ b`。 如果结果为零，则这是经典的失败 Nim 位置，因此输出“LOSE”。 否则，输出“WIN”。 
5. 对所有人重复此操作`m`初始位置。 

为什么有效：该算法依赖于两个不变量。 首先，任何捷径位置总是会失败，这会凌驾于正常的 Nim 规则之上。 其次，对于不在快捷方式集中的位置，适用经典的双堆 Nim 规则：第一个玩家可以获胜当且仅当`x XOR y != 0`。 通过将快捷方式存储在一组中，我们可以有效地处理两种类型的失败位置，而无需模拟游戏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
shortcuts = set()

for _ in range(n):
    x, y = map(int, input().split())
    shortcuts.add((x, y))

results = []
for _ in range(m):
    a, b = map(int, input().split())
    if (a, b) in shortcuts:
        results.append("LOSE")
    elif a ^ b == 0:
        results.append("LOSE")
    else:
        results.append("WIN")

print("\n".join(results))
```该解决方案首先构建`shortcuts`设置然后迭代初始位置。 微妙之处在于使用元组`(x, y)`作为集合中的键，确保尊重精确的顺序。 检查`a ^ b == 0`直接应用标准 Nim 定理。 我们避免任何不必要的循环或动作模拟。

 ## 边缘情况

 如果初始位置与快捷方式重合，则算法输出“LOSE”而不检查XOR。 例如，`(2, 2)`是示例 1 中的快捷方式。即使`2 ^ 2 = 0`（正常的亏损头寸），捷径规则会加剧亏损。 集合查找保证了堆的顺序很重要，所以`(1, 0)`不同于`(0, 1)`，与问题陈述完全匹配。 大堆大小，例如`(1e9, 0)`不会导致溢出，因为 Python 本身处理大整数，并且 XOR 计算仍然很快。
