 ## 解决方案
 ## 问题理解

 我们得到一个由三种类型的字符组成的字符串：左括号、右括号和特殊占位符。 每个占位符必须扩展为正数的右括号。 完成所有替换后，结果必须成为一个非常强意义上的有效括号序列：当我们从左到右扫描时，在任何前缀下，右括号的数量都不应超过左括号的数量，并且最终左括号和右括号的总数必须完全匹配。 

关键的困难在于，每个占位符不是单个固定符号，而是贡献一定数量的右括号的灵活块，并且必须选择这些贡献，以便同时满足所有前缀约束。 

字符串长度最多可达 100,000，这会立即排除任何尝试将所有值分配给占位符的方法。 即使在没有全局结构的情况下贪婪地分配值也是有风险的，因为每个占位符都会影响所有未来的前缀余额。 

当局部平衡看起来不错但随后全局可行性破裂时，就会出现微妙的失败情况。 例如，如果为早期占位符分配的右括号太少，则后面的前缀可能会积累过多的左括号，而在不违反最终相等约束的情况下无法对其进行补偿。 相反，分配太多的早期右括号可能会立即破坏前缀条件。 

## 方法

 暴力方法会尝试为每个占位符分配整数个右括号，并验证结果序列是否有效。 即使将每个占位符限制在合理的范围内，占位符的数量仍然会出现指数组合，当占位符的数量达到 100,000 个时，这是不可行的。 

问题的结构提出了不同的观点。 最终字符串必须是平衡的括号序列，因此右括号的总数由原始字符串中左括号的数量精确确定。 这立即将问题从“选择任意正整数”转变为“在占位符之间分配固定的总量”。 

一旦我们确定了总数，剩下的条件就是前缀有效性。 这就是贪婪变得有效的地方：每个占位符应该尽早贡献尽可能少的内容，因为尽早增加右括号可以降低以后违反前缀正性的风险。 然而，一个占位符必须通过吸收所有剩余的所需右括号来进行补偿，以确保总和约束成立。 

这导致了一种结构，其中所有占位符最初都设置为恰好贡献一个右括号，并且一个选定的占位符吸收剩余的所需数量。 正确性取决于为“额外负载”选择正确的占位符：必须放置它，以便增加它不会破坏前缀有效性。 

因此，我们确定了最后一个占位符，它可以安全地承载剩余的右括号，并最少地分配其余部分。

 ## 算法演练

1. 计算字符串中左括号的数量。 这决定了最终序列中所需的右括号总数，因为有效序列必须以两种类型的相同数量结束。 
2. 从概念上讲，将每个占位符替换为至少一个右括号。 这确保我们满足每个占位符贡献正整数的约束。 
3. 计算为每个占位符分配一个右括号后还剩下多少个右括号。 该余数必须恰好放入一个占位符中。 
4. 扫描字符串并保持开头减去结束贡献的余额，假设每个占位符贡献一个结束括号。 扫描时，将占位符视为贡献一个右括号，以跟踪可行性。 
5. 确定一个可以安全地吸收剩余的额外右括号的占位符。 这要求如果我们增加它的贡献，那么它之前或包含它的前缀都将变得无效。 正确的选择是遇到的最后一个占位符，因为它是可以推迟额外右括号而不影响早期前缀余额的最远点。 
6. 将所有占位符值指定为 1，所选占位符除外，该占位符接收 1 加上剩余所需金额。 

### 为什么它有效

 该算法强制所有占位符在前缀验证期间行为最少，这是最受约束的状态。 任何额外的右括号仅出现在一个位置，并且尽可能晚地放置它们可确保它们不会干扰较早的前缀条件。 由于右括号的总数由左括号的数量精确确定，因此自动满足最终的总和约束。 前缀约束成立是因为贪婪的最小分配始终是最安全的配置，并且任何剩余都被推迟到最终可能的占位符，在该占位符中它不能追溯地使较早的前缀无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    opens = s.count('(')
    stars = s.count('#')

    total_close = opens
    base = stars  # each '#' gives at least 1 ')'
    rem = total_close - base

    # store positions of '#'
    pos = []
    for i, c in enumerate(s):
        if c == '#':
            pos.append(i)

    # assign all 1, last gets extra rem
    ans = [1] * stars
    ans[-1] += rem

    # verify feasibility (optional conceptual check)
    bal = 0
    j = 0
    for c in s:
        if c == '(':
            bal += 1
        elif c == ')':
            bal -= 1
        else:
            bal -= ans[j]
            j += 1
        if bal < 0:
            print(-1)
            return

    if bal != 0:
        print(-1)
        return

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```该实现首先计算总共必须存在多少个右括号，然后为每个占位符分配一个右括号的基线值。 剩余的盈余将附加到最后一个占位符。 

验证过程模拟最终序列，将每个占位符视为其分配的值。 这确保没有前缀变为负数并且总余额为零。 最后一个占位符的选择至关重要，因为较早的占位符必须保持最小，以保持前缀的可行性。 

## 工作示例

 ### 示例 1

 输入：```
(((#)((#)
```有 5 个左括号和 2 个占位符，因此右括号总数必须为 5。每个占位符至少贡献 1 个，剩下 3 个额外的值分配给最后一个占位符。 

| 步骤| 人物 | 平衡（开盘-收盘）| 行动|
 | ---| ---| ---| ---|
 | 1 | ( | 1 | +1 |
 | 2 | ( | 2 | +1 |
 | 3 | ( | 3 | +1 |
 | 4 | ＃| 2 | -1 |
 | 5 | ) | 1 | -1 |
 | 6 | ( | 2 | +1 |
 | 7 | ( | 3 | +1 |

 这说明了为什么最后一个占位符必须吸收额外的闭合。 分配后，第二个占位符变得足够大，前缀永远不会变为负数。 

这证实了将剩余分配给最后一个占位符在满足总余额的同时保留了前缀有效性。 

### 示例 2

 输入：```
(#(#))
```有 2 个左括号和 2 个占位符，因此右括号总数必须为 2。每个占位符得到 1，因此不存在剩余。 

| 步骤| 人物 | 平衡|

 | 1 | ( | 1 |

 分配后，前缀仍然有效，因为每个占位符贡献恰好为 1，结构自然平衡。 

这演示了无需调整的基准情况。

 ## 边缘情况

 一种重要的边缘情况是所有左括号出现在任何占位符之前。 在这种情况下，前缀平衡对提前结束分配变得非常敏感。 该算法通过确保除最后一个占位符之外的所有占位符贡献最小来处理此问题，从而防止余额过早耗尽。 

另一种边缘情况是占位符与括号大量交错。 即使如此，在除最后一个占位符之外的所有位置分配最小值可以确保没有前缀因右括号而过载。 

最后，当只有一个占位符时，它必须吸收所有必需的右括号。 该算法自然会处理这个问题，因为“最后一个占位符”也是唯一的，因此它会在不违反前缀约束的情况下接收完整的余数。
