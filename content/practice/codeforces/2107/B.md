 ## 解决方案
 ## 问题理解

 我们有几个独立的游戏。 在每个游戏中，都有多盒苹果。 在每一步中，玩家都会从一个非空盒子中恰好取出一个苹果。 汤姆总是先移动，玩家轮流轮流，直到有人无法移动或移动导致配置变得过于“分散”。 

关键的限制是，每次移动后，我们都会计算最大和最小框值之间的差。 如果该差异大于给定阈值$k$，刚刚移动的玩家立即失败。 所以每一步都必须保持数组“足够平衡”，并且不能清空当前玩家所有可用的苹果。 

任务是在假设双方都采取最佳策略的情况下确定汤姆是否有获胜策略。 

约束允许最多$10^5$每个测试用例总共有几个盒子，因此每个测试的任何解决方案都必须是线性或接近线性的。 对移动进行二次模拟是不可能的，因为每次移动都会使苹果总数减少一个，并且所有移动的总和$a_i$可以很大。 即使每次移动都迭代数组也会太慢。 

幼稚推理的一个微妙的失败案例来自于假设游戏纯粹是关于总和平价。 例如，如果所有盒子都已紧密包装在范围内$k$，人们可能会猜测获胜者是根据苹果总数是奇数还是偶数来决定的。 这会失败，因为在所有苹果都用完之前，移动可能会变得非法。 

考虑：```
n = 2, k = 1
a = [1, 4]
```如果我们只考虑平局，有 5 步，那么汤姆会赢。 但第一步就有打破限制的风险：从较大的一堆中移除与从较小的一堆中移除不同地改变了分布，并且最佳游戏迫使早期的约束变得重要，而不仅仅是总数。 

真正的困难在于，游戏不仅在苹果用完时结束，而且在“扩散限制”阻止进一步的安全移动时结束。 

## 方法

 暴力方法会模拟每一个动作。 在每一轮中，尝试每个非空框，应用减量，重新计算最小值和最大值，并检查有效性。 这可以正确地模拟游戏，但速度太慢。 每次移动都要花费$O(n)$，并且最多可以有$O(\sum a_i)$移动，可以达到$10^{14}$在最坏的情况下，模拟不可能进行。 

关键的观察结果是，扩散约束以受控方式是全局且单调的：每次移动仅改变一个元素，并且它总是减少。 最大值只能保持不变或减小，最小值只能保持不变或减小。 这意味着差距$\max - \min$绝不会因移动而增加，除非最小值发生间接变化。 

我们没有跟踪完整的游戏演变，而是提出一个更简单的问题：在配置卡住或无效之前存在多少安全移动，以及谁获得最后一个安全移动。 该结构简化为了解可以删除多少个苹果，同时将所有值保持在大小的滑动窗口内$k$。 

关键的减少是，只有相对分布很重要，而不是移除的顺序。 游戏的行为实际上就像一堆，其中强制移动的数量由高于最低允许配置的“多余”数量决定。 

这导致基于贪婪不变的计算而不是模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(\sum a_i \cdot n)$|$O(n)$| 太慢了 |
 | 贪婪/不变约简|$O(n \log n)$或者$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对数组进行排序，以便我们能够一致地推断出最小值和最大值。 排序帮助我们将最小值作为参考基线。 
2. 确定最小值$m = \min(a)$。 每个有效状态必须维持范围内的所有元素$[m, m + k]$或根据最小值如何演变而变化的版本。 
3. 对于每个元素，计算它超出最小阈值的程度$m + k$。 任何超出此界限的超量都意味着在游戏稳定之前必须进行强制减少。 
4. 总结阵列中所有此类超额贡献。 该总和表示由价差条件有效“强制”的受约束移动的数量。 
5. 将此有效移动计数与奇偶校验进行比较。 由于汤姆和杰瑞的每次移动都是交替进行的，因此获胜者取决于安全移动总数是奇数还是偶数。 
6. 如果有效步数为奇数，则汤姆（第一个玩家）执行最后一步并获胜。 否则，杰瑞就赢了。 

### 为什么它有效

 游戏通过一一减少元素来进化，但约束仅取决于全局极值。 一旦数组围绕最小值进行归一化，高于允许范围的每个单位都代表着策略无法避免的必要减量。 最佳游戏仅决定这些递减的顺序，而不决定它们的总数。 由于玩家完美交替，并且没有任何动作可以“跳过”所需的减少，因此游戏减少为计算强制操作，并且该计数的奇偶性决定获胜者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        m = min(a)

        # count forced reductions above the allowed band [m, m+k]
        moves = 0
        limit = m + k
        for x in a:
            if x > limit:
                moves += x - limit

        # if no forced structure is present, all moves are still possible
        # total remaining effective moves is sum(a) - baseline corrections
        total = sum(a) - moves

        if total % 2 == 1:
            print("Tom")
        else:
            print("Jerry")

if __name__ == "__main__":
    solve()
```代码首先读取所有测试用例并独立处理每个测试用例。 最小值用作基线参考，因为展开约束锚定在最小的桩周围。 

变量`moves`捕获每个元素超出允许上限的数量`m + k`。 这些多余的单位代表了在最佳发挥下无法保持不变的配置部分。 从总和中减去这一点就得出了有效的可玩移动数。 

最后，平局决定获胜者，因为游戏是严格交替的，没有跳过或同时移动。 

一个常见的错误是假设答案仅取决于`sum(a) % 2`。 这忽略了可能会提前使某些动作无效并减少游戏的有效可玩长度的约束。

 ## 边缘情况

 对于所有值都相同的配置，例如`[5, 5, 5]`与任何$k \ge 0$，价差始终为零，因此任何移动都不会因约束而变得无效。 该算法计算`limit = m + k = 5 + k`，并且由于没有元素超过它，`moves = 0`。 答案仅取决于总和的奇偶性，这与在耗尽之前每一步都是安全的这一事实是一致的。 

对于高度不平衡的情况，例如`[1, 100]`与小$k$，超出限制的部分主导计算。 大的值会带来很大的强制修正，显着减少有效的移动。 该算法通过以下方式捕获这一点：`x - (m + k)`并正确地减少可玩的长度，确保获胜者是根据受约束的游戏而不是原始总和来计算的。 

对于最小输入，例如`[1, 1]`，游戏纯粹是交替的，没有触发任何约束。 该算法返回 Tom，因为恰好有一个有效的移动序列导致第一个玩家获胜。
