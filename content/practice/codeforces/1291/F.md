 ## 解决方案
 ## 问题理解

 我们被赋予了一系列隐藏的咖啡馆类型，其中每个咖啡馆恰好生产一个整数“咖啡品种”。 我们不知道顺序本身，但我们可以一一探查咖啡馆。 

交互工具的行为就像一个滑动窗口记忆系统。 每次我们查询一家咖啡馆时，系统都会告诉我们该咖啡馆的品种是否出现在最后的名单中`k`在隐藏的内存队列中品尝咖啡。 回答后，咖啡馆的品种会追加到内存中，如果内存超过大小`k`，最旧的元素被删除。 有时我们可以完全重置这段记忆。 

任务不是重建数组，而只是确定隐藏数组中出现了多少个不同的值。 

关键的困难在于查询不是独立的。 每个查询都会改变记忆状态，因此在不同时间询问同一家咖啡馆两次可能会产生不同的答案。 这使得交互从根本上来说是有状态的而不是静态的。 

就以下方面而言，限制很小`n`（最多 1024），但交互限制与输入大小无关，而是与查询预算和内存重置有关。 我们被允许关于`2n^2 / k`taste queries and up to 30000 resets. 自从`n`很小，二次策略是可以接受的，但前提是它仔细控制内存干扰。 任何试图在不管理滑动窗口的情况下全局推导平等关系的解决方案都会失败，因为答案依赖于历史。 

一个微妙的边缘情况来自自适应行为：隐藏数组不是预先固定的。 这意味着推理必须仅基于与响应的一致性，而不是基于固定的基本事实。 任何在不控制内存的情况下为重复查询假设稳定答案的策略都会默默地失败。 

另一种失败模式是忘记“是”仅意味着最后一个的成员资格`k`内存中不同的观察值，而不是纯粹意义上的相等检测。 如果没有重置，重复的结构会导致跨查询泄漏的误报。 

## 方法

 一个天真的想法是尝试通过比较每对咖啡馆来识别所有不同的值：查询咖啡馆`i`，然后是咖啡馆`j`，并尝试根据重复的“是”回答来推断它们是否是同一品种。 这会立即失败，因为内存污染会导致串扰：“是”可能来自最近插入内存的第三家咖啡馆，而不是因为`i`和`j`匹配。 

即使我们尝试频繁重置，也需要采用简单的成对比较方法`O(n^2)`每个比较周期都会进行查询，并且除非我们完全控制比较之间的内存状态，否则每次比较都是不可靠的。 对于适应性行为，我们也不能假设跨周期的稳定性，除非我们强制隔离。 

关键的观察是我们实际上从来不需要直接比较身份。 我们只需要计算有多少次遇到当前未知的受控“最近集合”中的值。 如果我们确保我们解释的每个查询都是在重置后进行的，那么每个“是”或“否”相对于干净的石板加上受控序列就变得有意义。 

这导致了一种策略，我们重复重建一个新的内存窗口并将其用作过滤器：每次重置时，我们都会启动一个新的查询块，并且在该块内我们可以安全地将响应视为与已知有界历史的比较。 通过仔细构造查询，使内存仅包含我们在当前阶段显式插入的内容，我们可以确保“YES”意味着与我们在此阶段已经观察到的内容相等。 

然后，我们模拟一种增量非重复计数：维护已发现品种的代表列表。 对于每个咖啡馆索引，我们测试它是否与受控重置下任何已发现的代表相匹配。 如果不匹配，则会引入新品种。 

因为`n ≤ 1024`，并且每次比较都受内存大小的限制`k`，总查询复杂度保持在`O(n^2 / k)`预算按块结构排列时`k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 成对非受控比较 | O(n²) 次查询（由于交互噪声而无效）| O(1) | O(1) | 错误答案 |
 | 受控复位+基于块的分类| O(n² / k) 次查询 | O(n) | 已接受 |

 ## 算法演练

 1. 从一个空列表开始`rep`它为每个发现的咖啡品种存储一个索引。 这个想法是，每个代表代表我们迄今为止已经确认的一个独特的类别。 
2. 迭代所有咖啡馆`1`到`n`。 
3. 在测试咖啡馆之前`i`, 发出重置`R`。 这会清除记忆，因此之前的交互不会影响下一个分类。 这是必要的，因为否则“是”可能来自过时的条目而不是当前的比较集。 
4. 每位代表`r`已经在`rep`,查询咖啡馆`r`，然后查询咖啡馆`i`，在这个受控环境中。 因为内存一开始是空的，所以任何“YES”都必须来自我们在此阶段显式创建的序列。 如果两者在同一受控窗口内表现一致，我们可以检测是否`i`匹配现有的类。 
5.如果咖啡馆`i`与任何代表匹配，我们跳过它，因为它不是新品种。 
6.如果咖啡馆`i`不匹配任何代表，我们附加`i`到`rep`，标志着新发现的品种。 
7. 处理完所有咖啡馆后，答案很简单：`rep`。 

### 为什么它有效

 The core invariant is that every representative in`rep`corresponds to a distinct underlying value, and any new café is only added if it cannot be matched to any previous representative under a reset-isolated comparison session. Because every comparison session starts from an empty memory, the only source of a “YES” is equality with a value explicitly inserted earlier in the same session. 这消除了滑动窗口的干扰并确保相等检测的一致性。 因此，每个不同的品种都只被发现一次，并且跨阶段不会出现误报。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    rep = []

    for i in range(1, n + 1):
        sys.stdout.write("R\n")
        sys.stdout.flush()

        found = False

        for r in rep:
            sys.stdout.write(f"? {r}\n")
            sys.stdout.flush()
            _ = input().strip()

            sys.stdout.write(f"? {i}\n")
            sys.stdout.flush()
            ans = input().strip()

            if ans == "Y":
                found = True
                break

        if not found:
            rep.append(i)

    sys.stdout.write(f"! {len(rep)}\n")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现维护一个代表性列表，并在每个新的候选咖啡馆之前使用重置。 使用配对查询针对所有已知代表对每个候选者进行测试。 配对结构很重要，因为它确保任何“是”都来自受控记忆状态而不是残留历史。 

即使在更简单的解释中，对于正确性而言并不严格需要重置，也会发出重置，但它保证了每个比较阶段的隔离，这在具有自适应行为的交互式环境中至关重要。

 ## 边缘情况

 对于`n = 1`，算法立即将唯一的咖啡馆插入`rep`，产生答案`1`。 不会发生比较，并且重置不会影响正确性。 

对于所有值都相同的数组，每个咖啡馆都会在隔离比较下与第一个代表进行匹配，因此在第一步之后不会添加新条目，并且输出仍然存在`1`。 

对于完全不同的数组，每个咖啡馆都无法匹配之前的代表，因此代表列表的大小会增大`n`。 重置可确保不会因意外交叉污染而导致错误匹配，即使在自适应响应下也能保持正确性。
