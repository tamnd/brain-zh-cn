 ## 解决方案
 ## 问题理解

 我们需要恢复一个正有理数（x=p/q），其中（p）和（q）最多都是（10^9）。 我们无法直接看到（p）和（q）。 相反，对于选定的素数模 (m)，法官给出 (0\le r<m) 范围内的整数 (r)，满足

 [
 r\equiv p q^{-1}\pmod m。 
]

 由于 (m) 是素数且 (q<m)，因此存在逆元 (q^{-1})。 等价地，查询返回的信息正是语句

 [
 rq\equiv p\pmod m。 
]

 该任务是交互式的，因此对于每个测试用例，我们的程序都会打印查询，读取法官的答案，并最终打印一对表示隐藏有理数的 (p,q)。 该对不必减少。 例如，(1/2)、(2/4) 和(500000000/1000000000) 都表示相同的值，并且接受其中任何一个。 官方声明指定最多 (10^5) 个测试用例，每个用例最多 10 个查询。 

边界 (p,q\le10^9) 是中心结构约束。 对于一个测试用例，直接搜索可能的分母已经需要最多 (10^9) 次迭代。 对于 (10^5) 种情况，变成 (10^{14}) 模计算，远远超出了六秒限制所能支持的范围。 我们需要使用对数时间数论将模块化信息转化为精确的理性重构。 

独特性和重构之间也存在微妙的区别。 如果我们以某种方式知道模数的值 (M>10^{18})，那么有理数在分子和分母最多为 (10^9) 的所有分数中已经是唯一的。 事实上，如果 (p_1/q_1) 和 (p_2/q_2) 产生相同的残基，那么

 [
 p_1q_2\equiv p_2q_1\pmod M。 
]

 因此 (M) 除以 (p_1q_2-p_2q_1)。 该差值的绝对值至多为 (10^{18})，因此严格大于 (10^{18}) 的模数会强制差值为零。 这种独特性观察也是问题标准解决方案的基础。 

有几种边缘情况，粗心的实现可能会处理不当。 第一个是未约分数。 例如，隐藏值可以是(2/4)。 正确的输出是`1 2`，虽然样本选择`2 4`。 坚持恢复精确的原始对而不是有理值的实现将拒绝完全有效的答案。 

第二个是整数，例如 (2/1)。 这里模余数就是 (2)，所以正确答案可以是`2 1`。 仅搜索不平凡的连分数分母的重建例程可能会意外地跳过初始留数本身并在这种情况下失败。 

第三个是值（1/1）。 对于每个查询的模数，返回的余数为 (1)。 粗心的 CRT 或欧几里得实现假设残差很大，可能会错误地处理这个最小的可能有理数。 正确的输出是`1 1`。 

第四个是数值边界处的分数。 例如，即使 (1000000000/999999999) 的分子和分母都接近上限，它也是有效的。 浮点重建在这里是不安全的，因为 CRT 之后相关整数可能在 (10^{24}) 左右。 该解决方案必须始终使用精确的整数算术。 

## 方法

 蛮力方法从同余开始

 [
 rq\equiv p\pmod M.
 ]

 对于从 (1) 到 (10^9) 的每个可能的 (q)，我们可以计算

 [
 p=(rq)\bmod M
 ]

 并检查是否 (1\le p\le10^9)。 隐藏对保证通过此测试，因此第一个有效对给出了正确的答案。 这在概念上很简单并且完全正确，因为查询准确地告诉我们 (rq\bmod M) 必须等于真实分母。 

问题在于操作计数。 在最坏的情况下，一个测试用例需要 (10^9) 次模乘。 在 (10^5) 个测试用例中，这可以达到 (10^{14}) 次迭代。 蛮力之所以有效，是因为可以独立检查每个可能的分母，但它会失败，因为分母范围太大。 

关键的观察是我们可以选择模数。 不要使用略大于 (10^9) 的模数，而是选择两个非常接近 (10^{12}) 的固定素数：

 [
 m_1=999999999989,\qquad
 m_2=999999999997。 
]

 两者都满足查询限制并且是素数。 

两次查询就足够了。 根据中国余数定理，两个余数可以合并为一个余数 (r) 模

 [
 M=m_1m_2。 
]

 该模数大约为 (10^{24})，所以特别是

 [
 M>2\cdot10^{18}。 
]

 这个更强的界限让我们可以使用标准的连分数有理重构。 

来自

 [
 rq\equiv p\pmod M
 ]

 存在一个整数 (k) 使得

 [
 rq-kM=p。 
]

 除以 (Mq)：

 [
 \frac rM-\frac{k}{q}=\frac{p}{Mq}。 
]

 因为 (p,q\le10^9) 和 (M>2\cdot10^{18})，

 [
 \left|\frac rM-\frac{k}{q}\right|
 =\frac{p}{Mq}
 <\frac{1}{2q^2}。 
]

 经典的连分数性质表明，如此接近 (r/M) 的有理近似必定是其收敛之一。 因此，在应用于 (M) 和 (r) 的欧几里得算法期间，隐藏分母 (q) 自然出现。 连分数连接是解决这个精确有理重构问题的标准方法。 

这会将 (10^9) 个可能分母的搜索转换为 (O(\log M)) 欧几里得算法。 由于 (M) 只有大约 24 位十进制数字，因此每个测试用例只有几十次欧几里得迭代。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个测试用例 (O(10^9)) | (O(1)) | (O(1)) | 太慢了 |
 | CRT + 连分数 | 每个测试用例 (O(\log M)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 查询第一个固定素数（m_1=999999999989），并调用返回的余数（r_1）。 该查询是合法的，因为 (m_1) 是质数并且严格位于 (10^9) 和 (10^{12}) 之间。 
2、查询第二个固定素数(m_2=999999999997)，得到(r_2)。 这两个模是互质的，因为它们是不同的素数，这正是中国剩余定理所要求的。 
3. 将两个同余结合起来

 [
 R\equiv r_1\pmod {m_1},
 \qquad
 R\equiv r_2\pmod {m_2}
 ]

 转化为单个残基 (R) 模 (M=m_1m_2)。 写

 [
 R=r_1+m_1t。 
]

 代入第二个同余可得

 [
 m_1t\equiv r_2-r_1\pmod {m_2}。 
]

 由于 (m_1) 具有模 (m_2) 的逆，我们可以用一个模逆来计算 (t)。 

1. CRT之后，我们知道

 [
 R\equiv pq^{-1}\pmod M,
 ]

 所以

 [
 Rq\equiv p\pmod M。 
]

 因此有一个整数 (k) 满足

 [
 Rq-kM=p。 
]

 现在的目标是从该方程中恢复小正整数 (p,q)。 

1. 考虑有理数 (k/q)。 根据前面的方程，

 [
 \frac RM-\frac{k}{q}
 =\frac{p}{Mq}。 
]

 由于 (p,q\le10^9) 和 (M>2\cdot10^{18})，右侧严格小于 (1/(2q^2))。 因此 (k/q) 是 (R/M) 的连分式的收敛。

1. 对 (M) 和 (R) 运行欧几里得算法，同时还跟踪 (R) 每个余数中的系数。 初始化

 [
 M=0\cdot R+1\cdot M
 ]

 和

 [
 R=1\cdot R+0\cdot M。 
]

 当欧几里得使用以下方法变换两个连续余数时

 [
 a\左箭头 b,\qquad
 b\leftarrow a-\lfloor a/b\rfloor b,
 ]

 相同的变换可以应用于它们的 (R) 系数。 因此，每个欧几里德余数都具有形式

 [
 s=cR+dM。 
]

 1. 查找具有 (1\le s\le10^9) 和正系数 (c\le10^9) 的余数 (s)。 对于隐藏部分，关系恰好是

 [
 p=qR-kM,
 ]

 所以它的分子（p）是这样的欧几里得余数，而它的分母（q）是（R）的正系数。 

1. 输出该对。 如果原始分数未约简，则欧几里得重构可能会返回其约简形式，该形式表示相同的有理数并被接受。 

### 为什么它有效

 中心不变量是每个欧氏余数都表示为(R)和(M)的整数线性组合，其跟踪系数记录(R)的乘数。 隐藏对满足

 [
 p=qR-kM,
 ]

 所以 (p) 是这些具有系数 (q) 的余数之一。 大的 CRT 模量给出了近似界限

 [
 \left|\frac RM-\frac{k}{q}\right|<\frac1{2q^2},
 ]

 这迫使 (k/q) 成为连分数收敛。 欧几里得准确地列举了重建所需的收敛结构。 由于(M>10^{18})，不可能存在两个不同的有理数，其分子和分母都以(10^9)为界，因此算法找到的候选数必然是隐藏有理数。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

B = 10**9

# Both are primes and satisfy 10^9 < m < 10^12.
M1 = 999999999989
M2 = 999999999997

def crt(a1, m1, a2, m2):
    """
    Return x in [0, m1*m2) such that
        x == a1 (mod m1)
        x == a2 (mod m2)
    """
    t = ((a2 - a1) % m2) * pow(m1, -1, m2) % m2
    x = a1 + m1 * t
    return x, m1 * m2

def recover(r, mod):
    """
    Recover p, q with 1 <= p, q <= B from
        r == p * q^{-1} (mod mod).
    We have mod > 2 * B^2.
    """
    # r0 = s0 * r + ...
    # r1 = s1 * r + ...
    r0, r1 = mod, r
    s0, s1 = 0, 1

    while r1:
        # The first remainder is r itself, which matters for
        # integer answers such as 2/1.
        if 1 <= r1 <= B and 1 <= s1 <= B:
            if (r * s1) % mod == r1:
                return r1, s1

        q = r0 // r1

        r0, r1 = r1, r0 - q * r1
        s0, s1 = s1, s0 - q * s1

    raise RuntimeError("rational reconstruction failed")

def ask(m):
    print("?", m, flush=True)
    ans = int(input())
    if ans == -1:
        sys.exit(0)
    return ans

def main():
    t = int(input())

    for _ in range(t):
        r1 = ask(M1)
        r2 = ask(M2)

        r, mod = crt(r1, M1, r2, M2)
        p, q = recover(r, mod)

        print("!", p, q, flush=True)

if __name__ == "__main__":
    main()
```这两个常数被故意选择为接近 (10^{12})。 他们的产品是

 [
 M=999999999986000000000033,
 ]

 它远远大于 (2\cdot10^{18})。 使用如此大的模数使得连分数证明可以使用标准 (1/(2q^2)) 近似界限。 

这`ask`函数打印一个查询并立即刷新标准输出。 在交互式问题中，刷新是强制性的，否则法官可能会永远等待仍位于 Python 输出缓冲区中的查询。 法官回应`-1`通常会发出无效交互信号，因此程序会立即终止。 

这`crt`函数使用表示

 [
 R=r_1+m_1t。 
]

 (t) 的值是使用 (m_1) 模 (m_2) 的模逆求得的。 Python 整数具有任意精度，因此大约 (10^{24}) CRT 模数不会导致溢出。 在固定宽度语言中，该产品需要比有符号 64 位算术更宽的整数类型。 

这`recover`函数是欧几里得算法的扩展版本。`r1`是当前的余数并且`s1`是其相对于原始残差 (r) 的系数。 不变量是当前余数可以写为

 [
 r_1=s_1r+cM
 ]

 对于某个整数 (c)。 

候选检查在欧几里德更新之前完成。 对于 (2/1) 等情况，此边界是必要的，其中余数本身已经是所需的分子，而分母是 (1)。 跳过此检查将丢失整数答案。 

附加模块检查```
(r * s1) % mod == r1
```数学证明不需要，但它使候选条件变得明确，并保护实现不接受具有不相关系数的余数。 

不使用浮点运算。 特别是，（R/M）和理性答案都不会转换为`float`，因为 CRT 模数约为 (10^{24})，远远超出了浮点表示可以保留所有相关整数信息的范围。 

## 工作示例

 提供的示例是交互式转录本，而不是普通的批量输入/输出对。 它使用单一模数（1000000007），而上面的解决方案故意使用两个较大的素数，以便连分式重建具有足够强的模数。 样本的`1/2`个案回报`500000004`，并且样本接受`2/4`; 我们的算法将返回简化的表示`1/2`。 

对于第一个工作示例，取样本值 (x=1/2)。 与

 [
 m_1=999999999989
 ]

 (2) 的倒数是 (500000000000)，因此判断器返回 (500000000000)。 与

 [
 m_2=999999999997,
 ]

 (2) 的倒数是 (499999999999)。 CRT 将这些组合成

 [
 R=499999999993000000000017。 
]

 组合模量为

 [
 M=999999999986000000000033。 
]

 由于 (M=2R-1)，第一个欧几里德步骤特别简单。 

| 欧几里得状态 | 当前剩余| 系数 (R) | 候选人 |
 | ---| ---| ---| ---|
 | 初始| 499999999993000000000017 | 1 | 太大|
 | 之后 (M-R) | 499999999992999999999？ | -1 | 系数负|
 | 下一个分区之后 | 1 | 2 | (p=1,q=2) |

 确切的中间余数是（R-1=499999999993000000000016）。 最后的小余数满足

 [
 1=2R-M，
 ]

 因此 (R) 的系数为 (2)，即 (p=1,q=2)。 这说明了为什么系数跟踪很有用：欧几里得算法同时找到小分子及其相应的分母。 

对于第二个工作示例，取样本的整数值 (x=2/1)。 法官对两个大素数返回 (2)，因此 CRT 立即给出

 [
 R=2。 
]

 欧几里得重建从残差本身开始。 

| 欧几里得状态 | 当前剩余| 系数 (R) | 候选人 |
 | ---| ---| ---| ---|
 | 初始| 2 | 1 | (p=2,q=1) |
 | 下一页 | 1 | 负系数大| 被拒绝 |
 | 决赛| 0 | 不考虑| 停止|

 第一个状态已经是一个有效的答案。 这是在执行第一次欧几里德除法之前检查初始余数的边缘情况。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(t\log M)) | 每个测试用例两个查询、CRT 和一个欧几里德算法 |

 这里 (M) 约为 (10^{24})，因此欧几里得算法只需要 (O(\log M))，大约几十次迭代。 对于 (10^5) 测试用例，这在算术工作方面很容易管理。 交互协议本身在实际成本中占主导地位，因为每个测试用例都需要两次查询-响应交换，但仍在每个用例允许的十个查询之内。 

## 测试用例

 由于这是一个交互式问题，因此提供的示例无法作为正常的批输入传递给程序。 示例输入由法官回复组成，而程序预计会在收到这些回复之前打印查询。 下面的测试工具通过模拟对几个隐藏分数的判断来独立测试数学重建。```python
import io
import sys

B = 10**9
M1 = 999999999989
M2 = 999999999997

def crt(a1, m1, a2, m2):
    t = ((a2 - a1) % m2) * pow(m1, -1, m2) % m2
    return a1 + m1 * t, m1 * m2

def recover(r, mod):
    r0, r1 = mod, r
    s0, s1 = 0, 1

    while r1:
        if 1 <= r1 <= B and 1 <= s1 <= B:
            if (r * s1) % mod == r1:
                return r1, s1

        q = r0 // r1
        r0, r1 = r1, r0 - q * r1
        s0, s1 = s1, s0 - q * s1

    raise AssertionError("reconstruction failed")

def residue(p, q, mod):
    return p * pow(q, -1, mod) % mod

def solve_hidden(p, q):
    r1 = residue(p, q, M1)
    r2 = residue(p, q, M2)

    r, mod = crt(r1, M1, r2, M2)
    return recover(r, mod)

# Sample-derived cases.
assert solve_hidden(1, 1) == (1, 1), "sample value 1/1"
assert solve_hidden(1, 2) == (1, 2), "sample value 1/2"
assert solve_hidden(2, 1) == (2, 1), "sample value 2/1"

# Minimum numerator and denominator.
assert solve_hidden(1, 1) == (1, 1), "minimum values"

# Maximum values, with a reducible fraction.
assert solve_hidden(10**9, 10**9) == (1, 1), "maximum equal values"

# Both numerator and denominator are at the upper boundary,
# but the fraction is not reducible.
assert solve_hidden(10**9, 999999999) == (1000000000, 999999999), \
    "maximum boundary fraction"

# A fraction just below the upper numerator boundary.
assert solve_hidden(999999999, 1000000000) == (999999999, 1000000000), \
    "boundary numerator and denominator"

print("all tests passed")
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 | (1/1) | (1/1) | 最小值和恒定残差 |
 | (1/2) | (1/2) | 样本的非整数有理数 |
 | (2/1) | (2/1) | 初始欧几里得余数 |
 | (10^9/10^9) | (10^9/10^9) | (1/1) | 可约化最大尺寸分数 |
 | (10^9/999999999) | (10^9/999999999) | 两个值均接近上限 |
 | (999999999/10^9) | (999999999/10^9) | (999999999/10^9) | (999999999/10^9) | 边界分母和分子 |

 (10^9/10^9) 的测试特别有用，因为原始对不是互质的。 重构返回(1/1)，这与有理值相同，是合法答案。 这两个边界测试还证实，实现从不依赖于严格的不等式，例如 (p<10^9) 或 (q<10^9)。 

## 边缘情况

 对于未约化分数 (2/4)，隐藏值为 (1/2)。 对于第一个大素数，余数为 (500000000000)，第二个大素数为 (499999999999)。 CRT 产生与 (1/2) 相同的组合余数，因为模除法仅取决于有理值，而不取决于使用的分子和分母表示形式。 重建返回 (1/2)，即使样本转录本使用 (2/4)，该结果也是可以接受的。 

对于整数（2/1），两个查询的残基都恰好是（2），因此CRT返回（R=2）。 重建用系数(1)检查初始欧几里得状态(R=2)，立即获得(p=2,q=1)。 这就是为什么候选检查必须在第一次欧几里得除法之前进行。 

对于(1/1)，每次查询都返回(1)，CRT也返回(R=1)。 初始状态有余数 (1) 和系数 (1)，因此算法立即输出 (1/1)。 不需要数字 (1) 的特殊情况分支。 

对于最大相等对 (10^9/10^9)，模值仍然恰好是 (1)，因为分数减少到 (1/1)。 该算法返回 (1/1)，这说明了为什么输出必须被解释为有理值而不是精确的隐藏对。 

对于边界分数，例如 (1000000000/999999999)，分子和分母都符合允许的范围，但它们的乘积接近 (10^{18})。 CRT模数在(10^{24})左右，留有非常大的安全裕度。 欧几里得算法完全适用于整数并重建分数而不会造成任何精度损失。 

最危险的实现错误是仅使用 (10^9) 左右的模数，然后假设连分数自动就足够了。 标准收敛边界要求(M>2B^2)，而原始问题的个体查询模要小得多。 两个大素数正好解决了这个问题：它们的乘积远大于 (2B^2)，而每个单独的查询都保持在允许的范围内。 这是最终算法既短又严格的关键原因。
