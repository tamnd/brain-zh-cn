 ## 解决方案
 ## 问题理解

 我们有一个正整数数组 (a_1,\dots,a_n)。 第一个平方根始终带有加号，而后面的每一项都可以独立地接收 (+) 或 (-)。 我们需要计算有多少个选择

 [
 \sqrt{a_1}\pm\sqrt{a_2}\pm\cdots\pm\sqrt{a_n}=0。 
]

 答案计算的是符号选择，而不是不同的结果总和。 由于第一个符号是固定的，因此在应用方程之前有 (2^{n-1}) 种可能的选择。 

约束（n\le 36）是主要的算法信号。 枚举所有 (2^{35}) 个允许的符号模式已经大约为 (3.44\times10^{10})，远远超出了三秒的限制。 通常的中间相遇从 (2^n) 减少到大约 (2^{n/2}) 正是 (n) 的大小所暗示的。 

(a_i) 上更大的界限是不寻常的部分。 (a_i) 可能有超过 100,000 个十进制数字，因此对数字进行因式分解，甚至直接将它们转换为普通的 Python 整数，并不是一个合理的实现策略。 事实上，具有标准整数字符串转换限制的 Python 版本将拒绝此类输入，除非该限制被更改。 我们可以通过将每个数字读取为十进制字符串并逐位对固定素数进行取模来减少它，从而完全避免这个问题。 

有几种边缘情况暴露了粗心的解决方案。 和```
2
1 1
```答案是（1），因为（1-1=0）。 将两个符号视为独立、计算完整 (2^2) 分配并忘记全局符号对称性的解决方案将获得 (2)。 

和```
3
2 2 8
```答案是（1），因为

 [
 \sqrt2+\sqrt2-\sqrt8=0。 
]

 浮点实现可能会悄悄地将其转变为不可靠的比较，特别是对于输入允许的巨大值。 

第二个危险情况是```
4
4 9 25 49
```其答案是（0）。 每个平方根都是一个整数，因此这个特定的输入看起来像一个普通的有符号子集和，但没有选择给出 (2,3,5,7) 零和的符号。 仅检查总和是否为偶数的解决方案，或者意外允许任意系数而不是精确的 (\pm1) 的解决方案可能会错误地接受它。 

最后，值可能太大，以至于输入本身必须被视为文本。 例如，(10^{100000}) 是合法的。 尝试对其进行因式分解或执行浮点平方根会丢失问题所需的确切结构。 

## 方法

 直接的方法是尝试每一种可能的符号分配。 对于每个赋值，我们评估表达式并检查它是否为零。 这是正确的，因为每个合法分配都只出现一次。 如果我们将固定的第一个符号与所有其他符号一起枚举，则有 (2^n) 次分配，或者在最坏的情况下有 (2^{36}=68,719,476,736) 次。 即使使用常数时间算术，这也太慢了。 

对于普通大小的整数，下一步自然是写

 [
 \sqrt{x}=c\sqrt{d},
 ]

 其中 (d) 是无平方的，将具有相同 (d) 的项分组，并独立求解所得的有符号子集和。 这在数学上是干净的，但获得 100,000 位整数的无平方部分基本上需要与约束设计不可用的相同的困难因式分解信息。 

关键的观察是我们实际上并不需要无平方分解。 我们只需要平方根的表示，其中加法等式被很好地保留以区分相关的有符号和。 预期的解决方案使用一个大的素数和二次留数来构造这样的表示，然后是中间相遇。 该问题的可用解决方案文章中也描述了这种模块化方法。 

选择满足 (P\equiv3\pmod4) 的大素数 (P)。 我们使用

 [
 f(x)=x^{(P+1)/4}\pmod P。 
]

 对于非零 (x)，欧拉准则给出两种情况。 如果 (x) 是模 (P) 的二次余数，则

 [
 f(x)^2=x。 
]

 如果 (x) 是非留数，则

 [
 f(x)^2=-x。 
]

 第二种情况看起来有问题，因为它实际上并没有给出 (x) 的平方根。 有用的属性是映射是乘法的：

 [
 f(xy)=f(x)f(y)。 
]

 因此，该映射没有明确识别每个 (a_i) 的无平方部分，而是为每个根分配一个一致的代数表示。 在激进类中，可能的额外因素是固定的，并且选择 (+) 或 (-) 已经允许将固定符号吸收到符号选择中。 因此保留零符号组合的计数。 

唯一剩下的问题是有限域可以识别在有理数上不同的两个不同代数量。 对于大约 60 位素数，对于不相关的冲突，其概率约为 (1/P)，这对于预期的随机散列解释来说可以忽略不计。 最初的解决方案正是为了这个目的而使用了一个大的固定素数。 

一旦每个 (\sqrt{a_i}) 被其模代表 (b_i) 替换，问题就变成了标准的有符号和问题：

 [
 \pm b_1\pm b_2\pm\cdots\pm b_n\equiv0\pmod P.
 ]

 将术语分成两半。 生成前半部分的每个带符号和并计算其频率。 然后生成后半部分的每个有符号和，并在前半部分的表中查找其负数。 每对给出一个完整的零和分配。 

我们枚举所有 (2^n) 个符号分配，而不是固定第一个符号。 第一个符号固定的每个合法赋值正好对应于两个完整的符号赋值，一个是另一个的全局否定。 因此最终的模块计数除以二。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(2^nn)) | (O(1)) | (O(1)) | 太慢了|
 | 最佳 | (O(n2^{n/2})) | (O(2^{n/2})) | 已接受 |

 ## 算法演练

1. 将每个 (a_i) 读取为十进制字符串，并对其取模 (P) 进行减少。 我们从不构造潜在的 100,001 位 Python 整数，因为模计算只需要它的余数模 (P)。 
2. 对于每个减小的值 (x_i)，计算

 [
 b_i=x_i^{(P+1)/4}\bmod P。 
]

 选择指数是因为 (P\equiv3\pmod4)，它给出了上述二次余数行为。 

1. 将 (n) 个变换后的值分成大小为 (\lfloor n/2\rfloor) 和 (\lceil n/2\rceil) 的两半。 两半各最多有 18 个元素，因此每一边最多有 (2^{18}=262,144) 个有符号和。 
2. 生成前半部分的每个带符号和。 将每个和的负数存储在频率字典中。 存储否定意味着可以直接查询后半部分的和。 
3. 生成后半部分的每个带符号和。 对于总和 (s)，查找有多少个前半部分总和等于 (-s) 模 (P)。 将该频率添加到答案中，因为每个这样的对都形成一个完整的有符号赋值，其变换后的总和为零。 
4. 将累计计数除以二。 枚举允许第一项有两个符号，而实际表达式将第一项固定为正数。 对每个符号求反会将一个零表达式更改为另一个零表达式，并将完整的赋值完全配对。 每个第一个符号固定的合法分配都恰好有一个第一个符号为负的这样的伙伴。 
5. 打印结果整数。 

关键的不变量是字典恰好包含完成每个前半部分零符号和所需的模补。 两半匹配计数的每一对对应于一个带有变换后的和为零的完整有符号赋值，并且每个变换后的零赋值唯一地分成一个前半部分和和一个后半部分和。 有限域构造仅用于用紧凑代表代替巨大根式，而不需要因式分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# A large prime with P % 4 == 3.
# 411191981019260843 is the prime used by the standard solution.
P = 411191981019260843
EXP = (P + 1) // 4

def read_mod(s):
    x = 0
    for c in s:
        if '0' <= c <= '9':
            x = (x * 10 + ord(c) - 48) % P
    return x

def signed_sums(values):
    sums = [0]

    for x in values:
        old = sums
        sums = [v - x for v in old] + [v + x for v in old]
        sums = [v % P for v in sums]

    return sums

def solve():
    n = int(input())
    raw = input().split()

    values = [pow(read_mod(s), EXP, P) for s in raw]

    m = n // 2
    left = values[:m]
    right = values[m:]

    left_sums = signed_sums(left)

    freq = {}
    for x in left_sums:
        freq[x] = freq.get(x, 0) + 1

    answer = 0

    right_sums = signed_sums(right)
    for x in right_sums:
        answer += freq.get((-x) % P, 0)

    print(answer // 2)

if __name__ == "__main__":
    solve()
```这`read_mod`函数是最重要的实现细节之一。 它计算

 [
 (((d_1\cdot10+d_2)\cdot10+d_3)\cdots)\bmod P
 ]

 在读取小数位时。 这使得输入大小与十进制位数成线性关系，并避免了 Python 对大整数的转换限制。 

致电给`pow(x, EXP, P)`使用Python内置的模幂运算，通过平方执行幂运算，并且从不构造一个大的中间整数。 该模数的指数只有大约 59 位，因此每次变换都很便宜。 

这`signed_sums`函数以空的有符号和 (0) 开始。 当添加值 (x) 时，每个现有的和都会产生两个新的和：(s-x) 和 (s+x)。 处理 (k) 个值后，正好有 (2^k) 个条目。 模运算将每个值保持在固定范围内。 

字典存储频率而不仅仅是总和的集合。 不同的符号模式可以产生相同的模和，并且它们中的每一个都必须对答案做出贡献。 忘记频率计数会低估重复的总和，特别是对于包含相等值的数组。 

Python 中不存在整数溢出。 所有算术都是任意精度，而模值本身只有大约 59 位。 

最终除以二并不是任意修正。 该代码特意枚举了第一项的两个符号。 如果完整符号向量为 ((s_1,\dots,s_n))，则其负 ((-s_1,\dots,-s_n)) 的和也为零。 这对中恰好有一个具有 (s_1=+1)，这是原始表达式所需的约定。

## 边缘情况

 对于第一个边缘情况，```
2
1 1
```转换后的值是相同的。 四个完整的符号分配包含两个零和，即（+，+）和（-，-）。 另外两个给出非零和。 该算法记录两个匹配对并除以二，产生 (1)，它对应于所需的 (+\sqrt1-\sqrt1)。 

对于第二种边缘情况，```
2
1 4
```真正的表达式是 (1\pm2)，它永远不为零。 中间相遇过程在每一半中只有一个值。 两个带符号的值都不能是另一个的负值，因此模数为零并且输出保持 (0)。 

对于重复值，```
4
1 1 1 1
```零需要两个正号和两个负号。 有

 [
 \binom42=6
 ]

 完整的符号向量，并且正好有一半的第一个符号为正。 答案是（6/2=3）。 频率字典是必要的，因为许多不同的分配会产生相同的中间和。 

对于大输入边界，```
3
10^100000 10^100000 4*10^100000
```其中符号表示相应的十进制字符串，平方根是

 [
 10^{50000}，\quad10^{50000}，\quad2\cdot10^{50000}。 
]

 因此，符号 (+,+,-) 为零，所以答案是 (1)。 该实现永远不会将 100,001 位数字计算为 Python 整数。 它读取它们的十进制表示形式并对它们进行模 (P) 缩减，然后应用相同的模数和中间相遇过程。 

最微妙的边缘情况是非方根，例如 (\sqrt2)。 模幂并不总是返回整数模 (P) 的普通平方根，因为 (2) 可能是二次非余数。 这不是方法中的错误。 该构造特意与根式的有限域类似物一起工作，其中非留数情况贡献了固定的二次扩展因子。 因为每个项都已经有独立的 (+) 或 (-) 选择，所以这些固定方向不会改变零符号组合的数量。 这是模块化技巧可以取代原本不可能的无平方因式分解的核心原因。
