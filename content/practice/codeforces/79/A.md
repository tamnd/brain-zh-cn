 **标签：** 贪婪
 **求解时间：** 1m 20s

 ## 解决方案
 ## 问题理解

 我们被要求模拟一款回合制游戏，涉及两名玩家 Ciel 和 Hanako，他们轮流从同一堆硬币中获取硬币。 该堆最初包含`x`100日元硬币和`y`10日元硬币。 每回合，活跃玩家必须准确取出 220 日元。 夏尔喜欢尽量多拿走 100 日元硬币，而花子则喜欢尽量多拿走 10 日元硬币。 第一个拿不到 220 日元的玩家就输了。 任务是根据初始硬币数量确定谁将获胜。 

输入提供`x`和`y`（每个最多 10^6），因此算法必须足够高效，能够在几次操作中处理多达一百万个硬币。 探索所有可能的组合或尝试每个硬币移除序列的简单模拟可能需要许多不必要的计算，但仔细的贪婪推理将其减少到少量的、可管理的检查数量。 

当一名玩家由于硬币面额的原因而无法达到 220 日元时，即使还有剩余硬币，也会出现一种微妙的边缘情况。 例如，与`x=1`和`y=1`，两者都不能恰好拿走 220 日元，因此第一个玩家立即失败。 另一个棘手的情况是当存在多种支付 220 日元的方式时； 玩家的偏好（Ciel 最大化 100 日元，Hanako 最大化 10 日元）决定选择哪种组合，因此忽略此顺序的粗心实现可能会模拟错误的路径并产生错误的获胜者。 

## 方法

 蛮力方法会依次模拟游戏，根据玩家的策略减少硬币数量，直到无法支付 220 日元。 每一轮都会检查 100 日元和 10 日元硬币的所有组合，总和为 220。这在逻辑上是正确的，但效率很低，因为每轮可能会考虑多种组合，而总轮数可能会很大。 在最坏的情况下，我们可以大致执行`x + y`操作，在给定约束的情况下这是可以接受的，但是探索所有组合不必要地使解决方案变得复杂。 

关键的观察是每个玩家都有一个贪婪策略和一个独特的首选动作。 夏尔总是尽可能多地拿走100日元硬币。 由于 220 日元最多需要两个 100 日元硬币（因为 3×100 = 300 > 220），我们可以将她的移动限制为 2、1 或 0 个硬币，其余的由 10 日元硬币组成。 同样，花子最大化 10 日元硬币，因此她尝试拿走尽可能多的 10 日元硬币（最多 22 个硬币，因为 22×10 = 220），仅在必要时才使用 100 日元硬币。 这将每次决策减少为常数时间决策：计算首选组合并更新堆。 没有必要探索所有的可能性，因为玩家的偏好顺序确保每回合只有一个动作。 

贪婪的洞察让我们用一个简单的循环来模拟游戏，直到玩家输掉。 每次迭代只需要很少的算术运算，每轮的时间复杂度为 O(1)，轮数大致由`x + y`，远低于 2×10^6。 这使得解决方案在时间限制内可行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(x + y) × O(可能的组合) | O(1) | O(1) | 由于不必要的组合检查而太慢 |
 | 最优（贪婪模拟）| O(x + y) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取输入值`x`和`y`代表100日元和10日元硬币的数量。 
2. 初始化布尔变量`turn`跟踪轮到谁了。 让`turn = True`意味着轮到夏尔了，并且`turn = False`意思是轮到花子了。 
3. 进入一个循环，只要玩家能够支付恰好 220 日元，该循环就会继续。 在每次迭代中，计算当前玩家根据其策略将获取的 100 日元和 10 日元硬币的数量：

 对于夏尔来说，先尝试拿2100日元硬币。 如果不可能，请尝试 1，然后是 0，再加上 10 日元硬币，正好等于 220 日元。 如果无法组合，夏尔就输了。 

对于花子来说，尽量多带 10 日元硬币（最多 22 个）。 如果不够的话，可以用100日元硬币补充，达到220日元。 如果无法组合，花子就输了。 
4. 扣除所选数量的金币`x`和`y`。 
5. 将回合转给另一位玩家。 
6. 当一名玩家无法支付恰好 220 日元时，退出循环并宣布另一名玩家获胜。 

为什么它有效：不变的是每个玩家总是选择可行的首选组合。 由于游戏在贪婪策略下是确定性的，因此模拟每一回合可以准确地反映最优选择。 不需要回溯，因为偏好规则消除了歧义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x, y = map(int, input().split())
turn = True  # True for Ciel, False for Hanako

while True:
    if turn:  # Ciel's turn
        if x >= 2 and y >= 2:
            x -= 2
            y -= 2
        elif x >= 2 and y >= 0 and y >= 0 and 220 - 200 <= y * 10:  # redundant but check
            take_10 = 2
            x -= 2
            y -= take_10
        elif x >= 1 and y >= 12:
            x -= 1
            y -= 12
        elif y >= 22:
            y -= 22
        else:
            print("Hanako")
            break
    else:  # Hanako's turn
        if y >= 22:
            y -= 22
        elif y >= 12 and x >= 1:
            y -= 12
            x -= 1
        elif y >= 2 and x >= 2:
            y -= 2
            x -= 2
        elif x >= 2:
            x -= 2
        else:
            print("Ciel")
            break
    turn = not turn
```在代码中，每个回合都是根据玩家的策略进行处理的。 边界检查是必要的，以避免拿走多于可用的硬币。 检查的顺序反映了硬币偏好的优先级。 当不存在有效组合时退出循环可以正确识别获胜者。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(x + y) | 每回合至少消耗一枚金币，总回合数 ≤ x + y |
 | 空间| O(1) | O(1) | 只存储了几个整数计数器|

 当 x 和 y 达到 10^6 时，循环最多执行 2×10^6 次迭代，每次迭代都进行恒定时间计算，完全在 2 秒的限制之内。 空间使用量极小。
