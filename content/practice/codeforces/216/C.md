 ## 解决方案
 ## 问题理解

 每个员工都遵循严格的重复时间表。 当天录用后`x`，该雇员为`n`连续几天，然后休息`m`连续几天，然后永远重复。 所以周期长度是`n + m`，并且在每个周期内，员工第一次处于活跃状态`n`天。 

商店必须永远满足两个条件，从一天开始`1`。 

首先，至少`k`员工必须每天工作。 

其次，商店密钥必须始终保留在当前工作员工的连接组内。 关键从第一位员工的第一个工作日开始。 一名员工只能在两人同时工作的一天将钥匙交给另一名员工。 如果在某个时候所有当前工作的员工都与未来的员工断开连接，钥匙就会被卡住，商店最终会停止营业。 

我们需要最大限度地减少员工总数并输出达到这一最低限度的雇用天数。 

约束足够小，足以推理整个周期。 因为每个员工都会重复每一个`n + m`天，整个系统是周期性的。 和`n, m ≤ 1000`，周围的算法`O((n+m)^2)`完全没问题，而任何指数或涉及大状态搜索的东西都是不必要的。 

困难的部分不是每天至少`k`工人。 仅此一点就很容易。 微妙的要求是保持密钥永远可转移。 

考虑`n = 2, m = 2, k = 1`。 

如果我们当天雇用一名员工`1`另一天`3`，覆盖范围：

 - 员工 A 工作日`1,2,5,6,...`- 员工 B 工作日`3,4,7,8,...`每天有一个工人，但钥匙不能从 A 移动到 B，因为它们从不重叠。 商店一天后就死了`2`。 

仅检查每日覆​​盖范围的粗心解决方案会错误地声称两名员工就足够了。 

另一个棘手的情况是工作人员几乎没有重叠。 

例子：```
n = 4, m = 3, k = 1
```日内雇用员工`1`和`4`作品：

 - 员工 1 工作`1..4`- 员工 2 工作`4..7`它们在当天重叠`4`，所以钥匙可以永远向前移动。 

重叠图必须随时间保持连接。 

另一个微妙之处是调度是循环模的`n + m`。 在同等日期雇用的两名​​员工永远表现相同。 实际的绝对招聘日仅在此周期长度内重要。 

## 方法

 蛮力思维从查看每个可能的招聘日模数开始`n + m`作为一种员工。 最多有`2000`这样的类型。 我们可以尝试每个子集并检查是否：

 1.每天至少涵盖`k`员工，
 2. 重叠图足够连接以永远传输密钥。 

检查单个子集是可以管理的，但子集的数量是指数级的。 即使周期长度`20`，这已经变得不可行了。 

接下来的观察完全改变了问题。 

当天雇用的员工`x`适用于循环间隔：```
[x, x+n-1] modulo (n+m)
```为了使密钥永远保持有效，活跃员工必须在整个周期内形成一系列重叠的间隔链。 自从`m ≤ n`，连续雇用天数最多相差`n-1`如果我们想要重叠。 

现在考虑一下需要的最少员工人数`k = 1`。 

每位员工涵盖`n`天数`n+m`。 要连续重叠地覆盖整个周期，最佳的构建是将员工准确地安置`n-1`相隔几天。 每个新员工都会在前一个工作日的最后一个工作日开始工作，从而创建一个重叠日来将密钥向前传递。 

需要多少这样的员工？ 

每增加一名员工仅贡献`n-1`新的日子，因为一天与前一个工人重叠。 覆盖一个周期的长度`n+m`需求：$t(n-1) \ge n+m$所以：$t = \left\lceil \frac{n+m}{n-1} \right\rceil$对于一般`k`，我们可以简单地复制这个结构`k`次。 这些副本可能会在同一招聘日重合。 每个副本独立维护关键连接，并且它们一起提供准确的`k`工人每天。 

美妙之处在于这也是最佳的。 任何一层相连的循环覆盖最多可以暴露`n-1`每个员工新的工作日，因为相邻员工必须至少重叠一天。 该下限与构造相匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(k·t) | O(k·t) | 已接受 |

 这里`t = ceil((n+m)/(n-1))`。 

## 算法演练

 1. 计算一个连接层所需的最少员工数量。 

我们需要足够的重叠间隔来环绕整个周期。 由于每一连续对必须至少重叠一天，因此每个新员工最多贡献`n-1`新鲜的日子。 

所以：$t = \left\lceil \frac{n+m}{n-1} \right\rceil$2. 打造一个最佳的员工队伍。 

雇用员工的日期：```
1, 1+(n-1), 1+2(n-1), ...
```连续的员工恰好在一天重叠，这足以转移密钥。 
3.重复同一层`k`次。 

每天单层中已有一名活跃工作人员。 复制图层`k`次准确地给出了`k`每天活跃的工人。 
4. 输出所有招聘天数。 

员工总数为`k * t`。 

### 为什么它有效

 在一层内，连续的工人重叠，因为他们的开始日期不同`n-1`。 由于每个工人都为`n`连续几天，他们正好共享一天。 钥匙可以沿着这条链条永远移动。 

由于总覆盖长度至少达到`n+m`，因此最后一个工作人员也与第一个工作人员以周期为模重叠。 

施工持续不断地覆盖每一天。 复制图层`k`乘以每天活跃工人的数量`k`，因此满足人员配置要求。 

最优性来自于重叠要求。 在任何有效的关联安排中，每个额外的员工最多可以贡献`n-1`新的循环日。 覆盖`n+m`循环天数至少需要：$\left\lceil \frac{n+m}{n-1} \right\rceil$每层员工数，因此总最小值恰好是`k`倍该值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    t = (n + m + (n - 2)) // (n - 1)

    ans = []

    for _ in range(k):
        for i in range(t):
            ans.append(1 + i * (n - 1))

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```的计算`t`使用天花板划分：```
(n + m + (n - 2)) // (n - 1)
```因为：```
ceil(a / b) = (a + b - 1) // b
```和`a = n+m`和`b = n-1`。 

雇用天数是使用间距生成的`n-1`。 这保证了相邻员工重叠一天。 

重复相同的模式`k`次。 重复使用相同的招聘日是完全合法的，因为员工是独立的人，有着相同的时间表。 

一个微妙的实现细节是`n ≠ 1`由语句保证，因此除以`n-1`总是安全的。 

另一个容易犯的错误是尝试为不同的层以不同的方式分发副本。 那是不必要的。 精确的复制已经实现了最佳的人员配置。

 ## 边缘情况

 考虑：```
2 2 1
```单纯的仅覆盖范围的方法可能会在几天内雇用`1`和`3`。 

员工时间表：```
1,2 | 5,6 | ...
3,4 | 7,8 | ...
```覆盖范围每天都存在，但员工从不重叠。 钥匙不能从第一个员工转移到第二个员工。 

我们的算法改为构建：```
1 2 3 4
```每对相邻的键都会重叠，因此钥匙会在循环中永远移动。 

现在考虑：```
5 5 1
```周期长度为`10`。 每个新员工最多贡献`4`新的日子，因为必须有一个重叠日。 

我们计算：```
ceil(10 / 4) = 3
```并生成：```
1 5 9
```间隔变为：```
1..5
5..9
9..13
```模数`10`，最后一个间隔环绕并重叠当天的第一个间隔`1`。 循环链正确闭合。 

最后，检查：```
3 1 3
```一个最佳层是：```
1 3
```复制三遍得到：```
1 3 1 3 1 3
```现在每天正好有三名活跃工人。 结构规模与`k`同时保持每层内部独立的连接性。
