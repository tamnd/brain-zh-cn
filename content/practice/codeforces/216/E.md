 ## 解决方案
 ## 问题理解

 我们得到了一个用基数书写的数字序列`k`。 每个数字都介于`0`和`k - 1`，和一位特殊数字`b`被称为幸运。 

对于数字序列的每个子串，我们将该子串解释为基数`k`数字，允许前导零。 如果子串的数字根等于`b`。 

任务是计算有多少个子串是幸运的。 

第一个挑战是理解数字根在任意基数中的含义。 在十进制中，重复对数字求和最终给出的值等于数字模数`9`。 在基地`k`，同样的现象也发生在模数上`k - 1`。 

假设一个数字被写成基数`k`:$$x = d_0 + d_1 k + d_2 k^2 + \dots$$自从$$k \equiv 1 \pmod{k-1}$$我们还有$$x \equiv d_0 + d_1 + d_2 + \dots \pmod{k-1}$$重复数字和过程可以保持模值不变`k - 1`，直到只剩下一位数字。 最后一个数字正是数字根。 

这就造成了一种特殊的情况。 在普通模算术中，余数`0`对应数字根`0`。 但对于可被整除的正数`k - 1`，数字根变为`k - 1`， 不是`0`。 这与十进制数字根的行为相同：`18`有数字根`9`， 不是`0`。 

这些限制迫使我们避免二次工作。 和`n = 100000`，大约有`5 * 10^9`子字符串，因此枚举所有子字符串是不可能的。 甚至检查子字符串`O(1)`每个都还是太慢了。 我们需要接近线性时间的东西。 

有几种容易被忽略的边缘情况。 

考虑：```
2 0 1
0
```唯一的子串是`"0"`。 它的数字根是`0`，所以答案是`1`。 

仅对正数使用标准数字根公式的粗心实现会错误地拒绝零。 

现在考虑：```
10 9 2
1 8
```子串`"18"`有数字和`9`，所以它的数字根是`9`， 不是`0`。 

如果我们只检查`sum % 9 == 0`，我们会错误地将其分类为根`0`。 

另一个微妙的情况出现时`k = 2`。 

然后`k - 1 = 1`，所以每个数都等于`0 mod 1`。 除非单独处理，否则模算术将变得毫无用处。 

例子：```
2 1 3
1 0 1
```每个非零二进制数都有数字根`1`。 唯一具有数字根的子串`0`是完全由零组成的子串。 

直接基于模的解决方案在这里完全失败，因为所有前缀和都是相同的模`1`。 

## 方法

 暴力解决方案很简单。 对于每个子字符串，计算其数字之和，反复将其减少到单个基数 -`k`位，并检查结果是否等于`b`。 

有`O(n^2)`子串。 即使我们预先计算前缀和，因此每个子串和都可以在`O(1)`，我们仍然必须检查所有子字符串。 和`n = 100000`，这大致变成`5 * 10^9`子串，远远超出了限制。 

关键的观察是基数中的数字根`k`仅取决于数字和模`k - 1`。 

对于正数：$$\text{digital root}(x) = \begin{cases} k - 1 & \text{if } x \equiv 0 \pmod{k-1} \\ x \bmod (k-1) & \text{otherwise} \end{cases}$$一个子串对应一个连续的数字范围，因此它的数字和可以从前缀和中获得：$$S(l, r) = pref[r] - pref[l-1]$$这将问题转化为计算具有特定差模的前缀和对`k - 1`。 

如果`b > 0`，那么我们只需要：$$S(l,r) \equiv b \pmod{k-1}$$如果`b = 0`，只有总数字和恰好为零的子字符串才符合资格。 由于数字是非负的，这意味着子字符串中的每个数字都必须为零。 

这种区别就是整个问题。 

一旦减少到前缀和模`k - 1`，我们可以使用线性时间内的频率图来计算有效子串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读基础`k`, 幸运数字`b`，以及数字序列。 
2.特殊情况处理`b = 0`。 

数字有数字根`0`仅当数字本身为零时。 由于所有数字都是非负的，因此当子字符串中的每个数字都为零时，子字符串就准确地表示零。 

我们扫描数组并计算连续零块的长度。 一块长度`L`贡献：$$\frac{L(L+1)}{2}$$仅零子串。 
3.特殊情况处理`k = 2`。 

在二进制中，唯一可能的数字根是`0`和`1`。 

如果`b = 0`，第2步已经处理了。 

如果`b = 1`，每个非零子串都是幸运的。 子串总数为：$$\frac{n(n+1)}{2}$$我们减去之前计算的仅零子串。 
4. 对于一般情况`k > 2`和`b > 0`， 让：$$m = k - 1$$5. 构建前缀和模`m`。 

定义：$$pref[i] = (a_1 + a_2 + \dots + a_i) \bmod m$$6. 对于每个位置`r`，我们希望之前的前缀满足：$$pref[r] - pref[l-1] \equiv b \pmod m$$重新排列：$$pref[l-1] \equiv pref[r] - b \pmod m$$7. 维护频率图`cnt`以前见过的前缀残基。 

最初，`cnt[0] = 1`因为存在空前缀。 
8. 对于每个前缀残基`cur`:

 计算：$$need = (cur - b) \bmod m$$每个前面的前缀都带有残数`need`形成一个在这里结束的幸运子串。 
9. 添加`cnt[need]`到答案，然后增加`cnt[cur]`。 

### 为什么它有效

 对于任意子串，其数字和等于两个前缀和之差。 模算术保留了这种差异模`k - 1`。 

对于正数字根，该值由该模类唯一确定。 算法统计的每个子串都满足数字根对应的精确模条件`b`，并且每个有效子字符串都恰好生成一个匹配的前缀对。 

这`b = 0`由于模运算无法区分数字根，大小写被分开`0`从数字根`k - 1`。 

## Python 解决方案```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    k, b, n = map(int, input().split())
    a = list(map(int, input().split()))

    # count zero-only substrings
    zero_substrings = 0
    cur = 0

    for x in a:
        if x == 0:
            cur += 1
        else:
            zero_substrings += cur * (cur + 1) // 2
            cur = 0

    zero_substrings += cur * (cur + 1) // 2

    # digital root 0
    if b == 0:
        print(zero_substrings)
        return

    # base 2 special case
    if k == 2:
        total = n * (n + 1) // 2
        print(total - zero_substrings)
        return

    mod = k - 1

    cnt = defaultdict(int)
    cnt[0] = 1

    ans = 0
    pref = 0

    for x in a:
        pref = (pref + x) % mod

        need = (pref - b) % mod
        ans += cnt[need]

        cnt[pref] += 1

    print(ans)

solve()
```第一部分计算所有完全由零组成的子字符串。 这对于`b = 0`情况和二进制特殊情况。 

零计数逻辑使用连续的块。 如果一个块有长度`L`，那么该块内左端点和右端点的每个选择都会形成一个有效的零子串，给出`L(L+1)/2`。 

下一节将分别处理数学上棘手的情况。 

什么时候`b = 0`，只有零值数字才符合条件，因此我们可以立即打印仅零值的计数。 

什么时候`k = 2`，每个非零数都有数字根`1`。 答案变成所有子串减去仅零的子串。 

主循环实现前缀模方法。`pref`存储当前前缀和模数`k - 1`。 对于每个新位置，我们计算哪个较早的残差将使子串残差等于`b`。 哈希图`cnt`存储到目前为止每个残基出现的次数。 

顺序很重要。 我们首先查询匹配的较早前缀的数量，然后将当前前缀插入到映射中。 颠倒此顺序将错误地计算空子字符串。 

Python 整数自动安全地处理大的答案大小。 子串的最大数量约为`5 * 10^9`，无论如何，它很适合 64 位整数。

 ## 边缘情况

 考虑：```
2 0 1
0
```该算法首先计算零块。 有一个长度的块`1`， 所以：$$\frac{1 \cdot 2}{2} = 1$$自从`b = 0`，算法立即返回`1`。 

这正确地处理了数字零的数字根为零的事实。 

现在考虑：```
10 9 2
1 8
```子串之和为：$$1 + 8 = 9$$模数`9`， 这是`0`。 单纯的模方法会将其分类为数字根`0`。 

该算法避免了这个错误，因为`b = 9`在一般正根逻辑中处理，其中留数`0`对应数字根`9`。 

最后，考虑二进制情况：```
2 1 3
1 0 1
```自从`k - 1 = 1`，所有前缀和模`1`变为零。 正常的模块化解决方案会错误地计算每个正数的每个子串`b`。 

特殊处理计算：```
total substrings = 6
zero-only substrings = 1
```并返回`5`，这是正确的，因为每个非零二进制数都有数字根`1`。
