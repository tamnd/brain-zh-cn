 ## 解决方案
 ## 问题理解

 我们有一系列烘焙选项，它们都消耗有限的共享资源，即面团，其中一些还消耗额外的有限成分，即馅料。 每个选项生产一个单位的产品，产生固定的利润。 一种特殊的选择代表一种仅消耗面团的普通产品。 

任务是确定每种选项生产多少单位，以便面团的总使用量不超过给定的预算，并且每种馅料类型也不会过度使用超出其可用库存。 每个生产的单位都会立即转化为利润，任何剩余资源都无关紧要。 目标是最大化总利润。 

该结构本质上是一个具有多种项目类型的有界背包，但具有额外的全局资源约束和多个独立的每种类型的容量限制。 

约束很小，这在很大程度上建议采用动态编程或仔细的贪婪归约方法，而不是任何指数搜索。 面团总数上限为1000个左右，馅料种类最多为10种。 这种组合通常意味着我们可以负担超过面团容量的 DP，但我们必须小心如何对每种填充类型进行建模，因为每种类型所有可能计数的天真扩展很容易就会膨胀到数十万种状态。 

一些边缘情况很容易被忽略。 

一种是当馅料类型在每个面团的利润和忽略馅料限制方面都明显比普通选项差时。 例如，如果普通面包每克面团的利润比任何带馅面包都高，那么即使馅料很丰富，所有带馅的选择都是无关紧要的。 

另一种情况是，当填充量如此有限时，即使每单位可以盈利，但也不能使用超过几次，而假设无限供应的天真 DP 会多算它。 

第三个微妙的情况是，当贪婪地优先考虑每个面团的最高利润时，忽略了填充限制可能会阻碍未来的高价值组合。 例如，一种填充量大但利润高的产品可能会消耗一种稀缺成分，这种成分最好保留为更少但更有效的用途，而天真的贪婪订购可能会失败。 

## 方法

 一个蛮力的想法是将每个可能的面包视为一个项目并尝试所有计数组合。 对于每种馅料类型 i，我们可以选择从 0 到给定面团和可用馅料的最大可行值之间的任何数字。 如果我们尝试跨 m 类型的所有组合，这将成为最多 10 个变量的嵌套枚举，每个变量可能最多 100 个或更多。 即使进行剪枝，最坏的情况也类似于 100^10 配置数量级的组合爆炸，这是完全不可行的。 

第二个简单的改进是将每种填充类型转换为多个相同的项目，然后在面团上运行标准的 0/1 背包。 这对于正确性是有效的，但它打破了限制，因为将每种类型扩展到最多 100 个副本会导致大约 1000 个项目，而 DP 超过 1000 个容量乘以 1000 个项目仍然处于临界状态，但可以接受。 真正的问题不是性能，而是清晰度：这种方法隐藏了结构，并且更难推理优化。 

关键的观察结果是 m 非常小，最多 10，这表明我们应该逐一处理馅料类型，并保持 DP 超过面团容量。 对于每种类型，我们不想显式扩展所有可能的计数。 相反，我们将其视为有界背包过渡，其中物品数量受到可用填充物和面团消耗的限制。

对于每种馅料类型，我们可以生产的最大面包数量为 min(ai / bi, n / ci)。 这给出了每种类型的自然界限，因此每种类型都成为有界项集。 由于 m 很小，我们可以对有界背包应用标准优化，通常是计数的二进制分割，将每个有界项转换为 O(log limit) 0/1 项。 这将问题简化为标准背包超出面团容量的问题。 

普通小圆面包只是另一种无限供应的物品类型，因此可以通过允许其作为 DP 中的重复过渡或将其视为单独的无界背包维度来处理。 由于 n 很小，我们可以安全地运行第二个循环，使用普通面包放松 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举所有计数 | 以 m 为单位的指数和极限 | O(1) | O(1) | 太慢了|
 | 展开所有项目并运行背包 | O(n × 项目总数) | O(n) | 已接受但沉重|
 | 具有二元分裂+DP的有界背包| O(n log 100 × m) | O(n) | 已接受 |

 ## 算法演练

 1. 我们构建一个 DP 数组，其中 dp[x] 表示使用 x 克面团可实现的最大利润。 我们将所有状态初始化为负无穷大，除了 dp[0] 为零。 这种结构使我们能够在尊重资源精确使用的同时积累利润。 
2.我们独立处理每种灌装类型。 对于给定的类型，我们计算可以制作的最大面包数量，但受到馅料和面团可用性的限制。 这个界限确保我们永远不会考虑不可能的生产计数。 
3. 我们使用二元分裂将该有界量分解为 2 的幂。 例如，如果我们最多可以制作 13 个面包，我们将其表示为 1、2、4 和 6。每个块都成为一个单独的虚拟物品，具有成比例的成本和利润。 
4. 对于每个虚拟物品，我们按照面团容量的相反顺序在 dp 数组上执行标准的 0/1 背包转换。 如果提高了价值，我们就通过增加利润来从 dp[j] 更新 dp[j + cost]。 反向迭代可确保每个项目最多使用一次。 
5. 处理完所有馅料后，我们将原味包子合并起来。 由于它没有库存限制，我们将其视为无界物品，并反复放宽 dp 向前，只要面团允许，就可以多次使用。 
6. 最终答案是所有 dp 状态的最大值，因为允许使用未使用的面团，并且不需要确切地花费所有资源。 

关键的正确性属性是，在处理每种填充类型之后，dp 仅使用所有有效有界组合下先前考虑的类型对所有可实现的利润配置进行编码。 二进制分割保证了每种填充类型的每个可行计数都可以表示为所选虚拟项目的总和，并且背包转换保留了最佳子结构，因为一种类型的决策不会干扰超出共享面团容量的其他类型的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())
    
    dp = [-10**18] * (n + 1)
    dp[0] = 0

    for _ in range(m):
        a, b, c, d = map(int, input().split())

        max_cnt = min(a // b, n // c)

        k = 1
        items = []
        while max_cnt > 0:
            take = min(k, max_cnt)
            items.append((take * c, take * d))
            max_cnt -= take
            k <<= 1

        for cost, val in items:
            for j in range(n - cost, -1, -1):
                if dp[j] != -10**18:
                    dp[j + cost] = max(dp[j + cost], dp[j] + val)

    # unbounded plain buns
    for j in range(n + 1):
        if dp[j] != -10**18:
            cnt = (n - j) // c0
            dp[j + cnt * c0] = max(dp[j + cnt * c0], dp[j] + cnt * d0)

    print(max(dp))

if __name__ == "__main__":
    solve()
```第一个 DP 循环建立了面团使用的可行状态。 每种填充类型都会转换为一组有界项目，因此任何状态都不会违反成分限制。 反向迭代至关重要，因为它可以防止在一次迭代中多次重复使用相同的二进制块，从而保持 0/1 背包语义的正确性。 

第二阶段有控制地贪婪地吃素包子。 由于所有剩余容量只能在相同的块中使用，因此我们使用尽可能多的普通面包将每个状态转换为其最佳扩展。 

一个常见的陷阱是尝试将普通面包直接混合到同一个有界 DP 循环中而不进行分离。 这通常会导致不正确的重用行为，除非仔细转换为完全无界的背包结构。

 ## 边缘情况

 一种边缘情况是当一种馅料类型可以大量提供但每单位使用太多面团时。 在这种情况下，二进制分裂仍然会产生项目，但如果它们效率低下，DP 转换将永远不会选择它们。 该算法自然地通过最大化将它们过滤掉。 

另一种极端情况是所有馅料类型都比普通面包差。 DP最初对它们进行探索，但最终的无界松弛的普通面包主导了所有状态，确保了正确的答案。 

第三种边缘情况是面团很小，只能容纳一种或两种馅料。 DP 仍然有效，因为它不假设必须使用所有类型； 各州对于超大组合的成本仍然无法达到，从而保持了正确性。
