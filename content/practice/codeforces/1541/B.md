 ## 解决方案
 ## 问题理解

 我们给出了几个测试用例，每个测试用例都包含一个从 1 开始索引的不同整数数组。任务是计算有多少个索引对$(i, j)$和$i < j$满足一个非常具体的关系：这些位置存储的值的乘积等于索引的总和，这意味着$a_i \cdot a_j = i + j$。 

这是一种混合了价值观和立场的结构性约束。 由于索引的边界为$n$，右侧$i + j$也有界于$2n$，与潜在产品值范围相比较小。 这种不对称是关键：尽管值可以高达$2n$，有效对必须满足同时链接索引和值的严格算术条件。 

和$n$最多$10^5$每次测试和总和$2 \cdot 10^5$， 一个$O(n^2)$每个测试用例的解决方案是不可能的。 甚至$O(n \sqrt{n})$在最坏的情况下，每次测试都会太慢。 任何正确的解决方案都必须依赖于这样一个事实：只有少数对可能满足方程，而不是检查所有对。 

一个常见的失败案例来自于尝试所有值“看起来有希望”的对，例如限制为小值或附近的索引。 该方法会错过有效对，因为条件取决于乘法和索引和，而不是邻近度或排序。 

例如，在一种简单的过滤方法中，人们可能只检查对$a_i \cdot a_j \le 2n$，因为右侧很小。 这是必要的，但还不够，并且如果没有可能产品的结构化枚举，它仍然会导致二次行为。 

## 方法

 暴力解决方案检查每一对$(i, j)$和$i < j$，计算$a_i \cdot a_j$，并将其与$i + j$。 这是正确的，因为它直接评估所述条件。 然而，它的性能约为$n(n-1)/2$每个测试用例的检查，大致变成$5 \cdot 10^9$操作总计在允许的最差输入大小下，显然太慢了。 

关键的观察是，我们可以通过固定一个索引并导出另一个索引的约束来重新解释条件，而不是迭代索引对。 从$a_i \cdot a_j = i + j$，我们可以将其重新排列为：$$j = a_i \cdot a_j - i$$这仍然没有直接帮助，因为两者$j$和$a_j$未知。 关键的结构洞察力来自边界：因为$i + j \le 2n$，我们得到：$$a_i \cdot a_j \le 2n$$这意味着只有乘积较小的值对才是相关的。 既然所有$a_i$是不同的正整数，最多$2n$，每个值$x$只能与值有意义地配对$y \le \frac{2n}{x}$。 这大大减少了候选值对的数量。 

然后，解决方案完全翻转视角：我们不再迭代索引，而是迭代可能的值$x = a_i$，并枚举有效倍数$y$这样$x \cdot y \le 2n$。 对于每一对这样的$(x, y)$，我们检查他们的位置是否满足$i + j = x \cdot y$。 

为了有效地支持这一点，我们将每个值的索引存储在哈希图中。 然后，对于每个有效值对，我们在 O(1) 中检索索引并测试一次条件。 

这将问题从指数的二次方简化为：$$\sum_{x=1}^{2n} \frac{2n}{x} = O(n \log n)$$| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 构建从值到索引的位置图。 这允许恒定时间查找每个值出现的位置，这是至关重要的，因为条件取决于索引，而不仅仅是值。 
2. 迭代所有可能的值$x$出现在数组中。 对于每个$x$，将其视为潜在有效产品的一方面。 
3. 对于每个$x$, 迭代倍数$y$这样$x \cdot y \le 2n$。 这限制了搜索空间，因为任何有效对都必须满足索引和约束，从而满足乘积约束。 
4. 对于每个候选对$(x, y)$，使用位置图检查数组中是否存在这两个值。 
5. 如果两者都存在，则检索它们的索引$i$和$j$，并验证是否$i < j$和$i + j = x \cdot y$。 如果为 true，则计算这一对。 
6. 由于每个有效对自然会遇到两次$(x, y)$和$(y, x)$，将迭代限制为$x \le y$或强制按索引排序以避免重复计算。 

### 为什么它有效

 正确性取决于每个有效对$(i, j)$产生一对有效的值$(a_i, a_j)$其乘积等于$i + j \le 2n$。 相反，我们生成的每个候选值对最多对应一个索引对。 因为我们枚举了界限下所有可行的价值产品$2n$，我们保证不会遗漏任何有效的解决方案，并且索引检查会过滤掉错误的候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        pos = {}
        for i, v in enumerate(a, 1):
            pos[v] = i
        
        ans = 0
        
        limit = 2 * n
        
        # iterate over possible values
        for x in a:
            i = pos[x]
            # avoid double counting by enforcing x <= y in value space
            # since values are distinct, we use numeric ordering
            for y in range(1, limit // x + 1):
                v = x * y
                if v in pos:
                    j = pos[v]
                    if i < j and i + j == x * v:
                        ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```实现的核心结构是值到索引字典`pos`，它可以持续检查候选值是否存在以及出现的位置。 嵌套循环不会迭代索引，而是迭代受以下条件约束的乘法对$x \cdot y \le 2n$，这是决定性的修剪步骤。 

条件`i + j == x * v`直接对原方程进行编码，并且`i < j`检查确保我们只对每个有效对计数一次。 循环结构隐式地避免了值级别上不必要的对重复。 

一个微妙的点是我们迭代数组中的实际值`x`，不超过全范围$1 \dots 2n$，这使得实际常数因子保持较低。

 ## 边缘情况

 当值已经接近其索引时，会出现微妙的边缘情况。 考虑：```
n = 3
a = [1, 2, 3]
```算法构建`pos = {1:1, 2:2, 3:3}`。 对于每个候选对，即使存在许多产品，索引条件也到处失败，因为$i + j$与相比增长太慢$a_i \cdot a_j$。 The enumeration still checks only feasible products under$2n$，并且每个候选者都在最终验证步骤中失败。 

另一种情况是大值与小索引配对时：```
n = 3
a = [6, 1, 2]
```这里唯一合理的产品是$1 \cdot 2 = 2$，但任何对的索引和至少为 3，因此不会发生匹配。 该算法仍然考虑该对，因为它存在于值映射中，但在相等性检查时拒绝它，确保正确性而无需特殊的大小写。
