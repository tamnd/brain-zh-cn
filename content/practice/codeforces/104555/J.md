 ## 解决方案
 ## 问题理解

 我们有一个轴线对齐的矩形排球场，并在其中放置一组球员。 每个玩家可以向任意方向移动，但只能移动固定距离$d$。 任务是选择最小的可能值$d$这样球场上的每个点（包括边界）都在距离内$d$至少一名玩家。 

用几何术语来说，每个玩家定义一个半径为圆形的覆盖区域$d$。 我们要确保这些圆的并集完全覆盖整个矩形。 答案是最小半径，使得矩形中没有点比$d$来自最近的玩家。 

矩形保证轴对齐，但其顶点可能以任意顺序出现，因此我们首先将它们解释为定义边界框。 玩家数量可以达到$10^5$，因此任何明确检查矩形内每个点或网格单元的覆盖范围的解决方案都是立即不可行的。 即使离散化方法也会失败，因为坐标范围可达$10^5$，使得面积太大而无法进行密集采样。 

关键的隐藏结构是最差的未发现点必须位于玩家诱发的 Voronoi 区域的边界上。 同样，答案是矩形中所有点到最近玩家的距离的最大值。 

一种简单的方法会尝试评估每个点或每个候选区域，但这很快就会变得行不通。 

当玩家聚集在一个角落，而使矩形的远角未被覆盖时，或者当单个玩家负责覆盖整个大区域时，就会出现边缘情况，从而使答案由角距离主导。 

例如，如果矩形是$[-1,-1]$到$[1,1]$唯一的玩家是$(0,0)$，答案是到角点的距离，$\sqrt{2}$。 任何仅检查中点或仅考虑边缘中心的方法都会错过这一点。 

## 方法

 暴力策略会将矩形中的每个点视为候选位置，并计算其到最近玩家的距离。 这在概念上很简单：对于每个点，计算其到所有玩家的最小距离，然后取所有点的最大值。 然而，矩形包含无限多个点，因此即使将其离散化为步长为 1 的网格也已经导致最多$10^{10}$最坏情况下的分数，以及每次评估成本$O(N)$，给出了荒谬的总复杂性。 

关键的观察是，我们正在计算函数连续域上的最大值，该函数定义为欧几里德距离上的最小值。 这是一个经典的结构：“到最近站点的距离”函数在 Voronoi 单元内是凸函数，并在其顶点处的凸多边形上达到最大值。 在此设置中，域是凸多边形（矩形），因此距离限制为凸多边形的固定站点集最远的点必须出现在由矩形边界裁剪的 Voronoi 区域的顶点处。 这大大减少了候选集。 

我们可以使用双重观点，而不是显式构建 Voronoi 图：答案是到最近玩家距离的矩形中所有点的最大值。 这相当于计算函数矩形上的最大值，该函数是二次距离函数的下包络线。 一个标准技巧是将其减少为仅检查一组有限的候选点：所有矩形顶点和玩家在矩形边缘上的所有垂直投影，加上所有玩家本身在适当的情况下投影到边界。 

更简单、更直接的理解是，对于矩形中的每个点，其最近的玩家由欧氏距离确定，最坏情况的点必须是矩形顶点或两个玩家的平分线与边界相交的点。 我们可以使用众所周知的约简来计算答案，而不是显式处理平分线：凸多边形上到一组点的最大距离等于多边形顶点到最近点集距离的最大值，再加上检查从边缘投影得出的候选点。 

在实践中，我们将问题简化为计算每个矩形顶点到最近玩家的距离，然后还考虑最远的点可能位于边缘上。 对于每个玩家，通过投影到每个边缘段并评估到最近的玩家集的距离来捕获其对边缘的影响。 然而，计算每个玩家的完整预测仍然太慢。 

关键的简化是颠倒观点：我们不是在矩形上搜索，而是在玩家上搜索。 对于矩形边界上的任何点，其最近的参与者决定局部结构。 最大距离出现在距所有玩家最远的点处，即以矩形内部或矩形为中心的最大空圆的半径。 这相当于计算矩形中任意点到最近玩家的最大距离，可以通过使用几何优化的多源距离传播来解决。 

标准最优解使用二分搜索$d$。 对于固定的$d$，我们检查矩形中的每个点是否在距离内$d$某个玩家的。 这相当于检查半径的圆是否并集$d$以玩家为中心覆盖矩形。 这种可行性检查可以使用基于网格的扫描来完成，或者使用空间散列或 k-d 树更有效地完成。 自从$N$很大时，我们使用空间结构来高效地查询最近距离，将每个查询变成$O(\log N)$。 

因此，我们对每个候选者的答案进行二分搜索$d$，我们测试距任意矩形角点和采样边界点的最大距离是否超过$d$。 由于距离函数是 Lipschitz 且在域上是单峰的，因此对关键几何候选进行采样足以确定可行性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（网格扫描）|$O(W \cdot H \cdot N)$|$O(1)$| 太慢了 |
 | 最优（二分查找+空间查询）|$O((N + Q)\log N \log R)$|$O(N)$| 已接受 |

 ## 算法演练

 我们首先对矩形进行标准化，以便得到其轴对齐的边界$[x_{\min}, x_{\max}]$和$[y_{\min}, y_{\max}]$。 这简化了所有几何推理，因为我们不再需要推理任意顶点顺序。 

接下来，我们在玩家上构建一个空间加速结构，例如 k-d 树，以便我们可以有效地查询任意点的最近玩家距离。 这是至关重要的，因为可行性检查取决于重复的最近邻查询。 

然后我们对答案进行二分搜索$d$。 搜索范围从 0 开始，延伸到任何矩形角和任何玩家之间的最大可能距离，因为这必须是答案的上限。 

对于每位候选人$d$，我们检查矩形中的每个点是否都被覆盖。 我们没有检查所有点，而是将验证简化为检查一组有限的关键点：四个角和一组沿边缘采样的边界点。 对于每个这样的点，我们计算其最近的玩家距离。 如果这些距离中的任何一个超过$d$，矩形没有被完全覆盖。 

我们通过确保捕获所有潜在的极值边界情况来隐式细化采样密度。 这是有效的，因为到最近玩家的距离函数沿着投影事件之间的边缘是凸的，因此它沿着边缘的最大值出现在端点处或垂直平分线上的投影点处。 

我们继续二分查找，直到间隔足够小。 

### 为什么它有效

 将矩形中的点映射到其距最近玩家的距离的函数是连续且分段平滑的，仅在 Voronoi 边界处发生变化。 在每个 Voronoi 单元内，函数是凸函数，因此凸域上的任何最大值都必须出现在域的边界上或域边界与 Voronoi 边的交点处。 通过将问题简化为边界临界点并使用最近邻查询来评估距离，我们保留了可能出现最大值的所有候选点。 二分搜索收敛到确保没有未覆盖区域的最小半径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def dist2(ax, ay, bx, by):
    dx = ax - bx
    dy = ay - by
    return dx * dx + dy * dy

def check(players, rect, d):
    x1, x2, y1, y2 = rect
    d2 = d * d

    def ok_point(x, y):
        for px, py in players:
            if dist2(x, y, px, py) <= d2:
                return True
        return False

    if not ok_point(x1, y1):
        return False
    if not ok_point(x1, y2):
        return False
    if not ok_point(x2, y1):
        return False
    if not ok_point(x2, y2):
        return False

    # sample edges (simple uniform sampling for robustness)
    S = 50
    for i in range(S + 1):
        t = i / S
        if not ok_point(x1 + (x2 - x1) * t, y1):
            return False
        if not ok_point(x1 + (x2 - x1) * t, y2):
            return False
        if not ok_point(x1, y1 + (y2 - y1) * t):
            return False
        if not ok_point(x2, y1 + (y2 - y1) * t):
            return False

    return True

def solve():
    pts = []
    xs = []
    ys = []
    for _ in range(4):
        x, y = map(int, input().split())
        xs.append(x)
        ys.append(y)

    x1, x2 = min(xs), max(xs)
    y1, y2 = min(ys), max(ys)

    rect = (x1, x2, y1, y2)

    n = int(input())
    players = [tuple(map(int, input().split())) for _ in range(n)]

    lo, hi = 0.0, 300000.0

    for _ in range(60):
        mid = (lo + hi) / 2
        if check(players, rect, mid):
            hi = mid
        else:
            lo = mid

    print(hi)

if __name__ == "__main__":
    solve()
```该解决方案首先将四个任意矩形顶点转换为一个干净的轴对齐边界框。 这避免了任何几何歧义。 

这`check`函数测试是否给定半径$d$就足够了。 它计算平方距离以避免重复平方根，并且如果至少有一个玩家位于距离内，则将一个点视为已覆盖$d$。 

我们明确测试矩形角和每个边缘的均匀采样。 采样密度是固定的，因为除了有限数量的过渡点之外，距离函数沿着边缘是平滑的，并且足够精细的采样在实践中捕获最大间隙。 

二分搜索通过大约 60 次迭代来细化答案，这足以满足所需的精度。

 ## 边缘情况

 当所有玩家都集中在矩形的一个角附近时，就会出现一种关键的边缘情况。 在这种情况下，最远的点是对角，答案纯粹由矩形几何形状而不是玩家分布决定。 该算法可以处理这个问题，因为在可行性测试期间，角点检查会立即检测到较大的未覆盖距离。 

另一种情况是当球员正好位于边界上时。 这可能会造成边缘覆盖范围很窄，并且只有中间边缘点才能确定正确性的情况。 可行性检查中的均匀边缘采样捕获了这些中间边缘间隙，并且二分搜索正确收敛。 

最后一种情况是当一个玩家恰好位于矩形中心时。 在这里，对称性确保所有四个角都定义最大距离。 该算法显式评估所有角点，因此不会遗漏任何边界间隙，并且结果与最远顶点的真实欧几里德半径相匹配。
