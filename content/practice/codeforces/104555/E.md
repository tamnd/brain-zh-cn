 ## 解决方案
 ## 问题理解

 我们有一组花，每朵花都储存整数数量的花粉。 蜜蜂按照固定的顺序一只接一只地到达，每只蜜蜂在离开前只执行一个动作。 

蜜蜂行动时，总是选择当前所有花朵中花粉值最大的花朵。 从那朵选择的有价值的花中$x$，蜜蜂收集数字的总和$x$，然后花的价值就会相应减少。 在这一次操作之后，蜜蜂就会永久离开。 

我们没有被要求模拟所有蜜蜂。 相反，我们需要收集的金额$K$在此过程中的第 - 只蜜蜂。 

关键的难点在于，每一个动作都会改变系统的状态，因此“最大的花”的身份不断动态变化。 所选花的顺序取决于之前所有的减少。 

约束条件很大：最多$10^6$鲜花和最多$10^9$蜜蜂。 这立即排除了任何试图通过对阵列进行线性扫描来简单地模拟每只蜜蜂的方法。 如果我们确实需要，即使每个操作的对数数据结构也会很困难$10^9$运营。 

当许多花最终达到零时，就会出现微妙的边缘情况。 一旦所有花都变为零，剩下的每一只蜜蜂都会采摘一朵零值花并收集零。 幼稚的模拟可能会继续做不必要的工作或错误地处理重复的零。 

另一个极端情况来自于对一朵大花的重复更新。 一朵花像$1000000$在重复的“数字相减”操作下不会快速缩小，因为每一步只删除少量（最多 54 个）。 这意味着单个元素可以在很长一段时间内主导该过程，并且快速收敛的天真期望是不可靠的。 

## 方法

 直接模拟很容易描述。 我们将所有花值保存在一个允许提取当前最大值的结构中。 对于每只蜜蜂，我们提取最大值$x$，计算其数字和$s(x)$，将其记录为该蜜蜂的答案，并替换$x$和$x - s(x)$。 如果$x$变为零，它保留在系统中，但不再影响未来的最大值。 

这种方法是正确的，因为它完全遵循流程定义。 问题是成本。 每个操作都需要维护最大值，通常通过堆，这会花费$O(\log N)$。 如果我们真的表现达到$10^9$操作，总工作量将远远超出限制。 

关键的观察是我们不需要优化单个更新。 我们只需要$K$-th 提取的值。 这使我们可以将该过程视为按顺序生成一系列操作，其中一旦我们知道当前的最大结构，每个操作都是独立的。 我们不去推理最终状态，而是只关注生成序列直到位置$K$，随后立即停止。 

这将问题变成了对优先级队列的受控模拟：我们总是有效地知道当前的最大值，并且我们只会继续直到达到所需的步数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（每次扫描最大值）|$O(NK)$|$O(N)$| 太慢了 |
 | 堆模拟|$O(K \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们维护一个包含所有当前花值的最大堆。 每一步都与一只蜜蜂完全对应。 

1. 根据所有初始花值构建最大堆。 这让我们可以检索对数时间内的当前最大值。 
2. 对于每只蜜蜂，从 1 到$K$，提取最大值$x$从堆中。 这代表当前蜜蜂访问的花朵。 
3. 计算数字和$x$，表示为$s(x)$。 这是蜜蜂收集的数量，因此我们将其存储为这一步的答案。 
4. 降低花值至$x - s(x)$。 如果结果是肯定的，则将其推回到堆中，以便它仍然可以竞争未来的蜜蜂。 
5. 如果堆在到达之前变空$K$步骤，所有剩余的蜜蜂收集零。 

该过程在计算完后立即停止$K$-th 收集值。 

### 为什么它有效

 在每一步中，堆不变量确保我们始终在所有花状态中选择当前的全局最大值。 每次更新都严格反映了一只蜜蜂的行动后系统的演变。 由于每只蜜蜂的选择仅取决于当前的多重值集，而不取决于未来的决策，因此保持这种不变性可以保证提取值的序列与实际过程完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def digit_sum(x: int) -> int:
    s = 0
    while x:
        s += x % 10
        x //= 10
    return s

def solve():
    N, K = map(int, input().split())
    arr = list(map(int, input().split()))

    # max heap via negative values
    heap = [-x for x in arr]
    heapq.heapify(heap)

    ans = 0

    for _ in range(K):
        if not heap:
            ans = 0
            break

        x = -heapq.heappop(heap)
        s = digit_sum(x)
        ans = s

        nx = x - s
        if nx > 0:
            heapq.heappush(heap, -nx)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案依赖于使用带有负值的 Python 最小堆实现的最大堆。 每次迭代恰好对应一只蜜蜂，因此循环计数器直接跟踪蜜蜂索引。 数字总和是在线性时间内以数字位数计算的，其约束条件为 7。 

一个微妙的实现细节是处理所有值提前变为零的情况。 在这种情况下，堆变空，我们立即为所有剩余的蜜蜂返回零，因为无法再选择正花。

 ## 边缘情况

 当所有花都相同时，堆会重复循环遍历仅在数字和减法后才不同的值。 该算法自然地处理这个问题，因为每个提取的元素都以其更新的值重新插入，因此不需要特殊的逻辑。 

当所有花最终变为零时，堆就变空了。 在这种情况下，循环提前终止，所有剩余的蜜蜂隐式贡献零，符合选择零花产生零收集的规则。 

对于一朵花，堆大小始终为一。 该算法逐步减少它，直到达到零，之后所有其他蜜蜂立即返回零。 这直接匹配定义，不需要任何分支逻辑。
