 ## 解决方案
 ## 问题理解

 我们获得了一系列独立的合同工作，每个工作都由开始日、结束日和固定的每日收入定义。 所有工作的工资率都是相同的，因此工作盈利能力的唯一区别在于它们的时间跨度以及获得它们所需的成本。 该费用在任何工作开始之前为每个工作支付一次。 

拉斐尔一次最多只能做一份工作。 当他接受一份工作时，从开始工作之日到他选择辞职的任何一天，他每天都会赚取固定金额，但永远不会超过其正式结束日期。 辞职后，他可以在第二天立即开始另一份工作，但不能在同一天。 每项工作还有一次性的前期成本，如果该工作在所选计划的任何时间点使用，则该成本将从最终利润中扣除。 

因此，问题归结为选择一组不重叠的时间间隔，并在每个选定的时间间隔内决定在那里工作多长时间，总利润等于每日赚取的工资减去所选工作进入成本的总和。 

约束条件很大，作业数量最多为 100 万个，坐标最多为 10^9。 这立即排除了任何尝试检查所有间隔对之间兼容性的解决方案。 即使 O(N^2) 推理也是不可能的，甚至 O(N log N) 也必须仔细构造，因为排序本质上是唯一负担得起的 O(N log N) 步骤。 

一个关键的边缘情况来自这样一个事实：退出是灵活的。 天真的解释可能会假设每项工作都必须在其完整的时间间隔内完成，但这不是必需的。 这意味着最佳解决方案可能会部分使用一份工作，只是为了将时间转移到更有利可图的工作上。 例如，低密度的长作业可能仍会使用几天，然后再切换。 

另一个微妙的问题是，即使一份工作只使用一天，也要支付成本。 因此，如果净贡献为负的工作能够在以后获得更有利可图的序列，那么它仍然可能会被短暂使用。 

最后一个边缘情况是重叠作业的密度差异很大。 天真的贪婪策略（例如总是从现在开始选择每日利润最高的工作）会失败，因为它忽略了未来的兼容性和转换成本。 

## 方法

 蛮力的想法是考虑作业的每个子集以及及时排序它们的每种方式，并且对于每个配置计算每个作业花费的时间减去所有进入成本。 即使将我们限制在有效的非重叠子集上，这也成为经典的加权间隔调度问题，并增加了复杂性：允许部分执行，因此我们不仅仅是选择完整的间隔，我们实际上是沿时间线选择断点。 

即使我们忽略部分使用并假设完整间隔，蛮力也已经需要检查所有子集（即 2^N），然后验证重叠，这会为每个子集添加至少 O(N)。 当 N 达到 10^6 时，这是完全不可行的。 

关键的见解是停止考虑选择间隔，而是考虑时间顺序。 由于作业仅限制开始和结束的时间，因此我们可以按相关事件的升序处理时间，并在每个点之前保持可实现的最佳利润。 

关键的观察是，任何最佳策略都可以被视为一系列分段，其中每个分段对应于一个作业。 当换工作时，我们只关心截至完成上一份工作的最后一天所实现的最佳利润。 这将问题转化为排序端点上的动态规划。

对于从时间 l 开始的任何工作，我们想知道在第 l 天减去 1 之前可实现的最佳利润。据此，我们可以决定进入该工作，支付其成本，然后在其间隔的某些后缀上累积利润。 由于我们可以提前退出，对于从 l 开始的工作，我们在其中能做的最好的事情就是选择一个结束时间 r'，其中 r' 至多为 r，并且如果另一份工作变得更好，则可能更早切换。 该结构产生具有运行最佳值的扫描线。 

我们按开始时间对工作进行排序。 我们维护一个跟踪给定时间之前可实现的最佳利润的结构，并且我们还考虑了这样一个事实：留在工作中会产生斜率 S 的线性增长。随着时间的推移，状态变成线性函数的最大值，这可以通过保留最佳前缀 DP 并在每个工作可用时更新它来维护。

 ## 算法演练

 我们将每个工作转换为候选转换，可以从其左端点开始贡献线性利润段。 

1. 按开始日期对所有作业进行排序。 这确保了当我们处理作业时，在它之前结束的所有可能的转换都是已知的。 
2. 维护数组或映射`dp[x]`代表截至第 x 天可实现的最佳利润，但我们从未明确存储所有 x 值。 相反，我们只压缩到事件点。 
3. 对于间隔为 [l_i, r_i] 和成本 c_i 的每个作业 i，在进入之前计算我们可以获得的最佳利润。 这是 l_i - 1 时刻的最佳 dp 值。 
4. 如果我们在 l_i 天进入工作，我们立即支付 c_i，从那时起我们每天赚取 S。 因此，如果我们只从事这项工作，那么 t 天的利润将是：

 dp[l_i - 1] - c_i + S * (t - l_i + 1)。 
5. 由于允许退出，因此该作业定义了一个从 l_i 开始、斜率为 S、截距为 dp[l_i - 1] - c_i - S * (l_i - 1) 的线性增长段。 
6.我们维护一个结构，支持查询任意点的最大值并添加新行。 当我们浏览职位时，我们会更新这个结构。 
7. 答案是所有作业端点 r_i 达到的最大值。 

### 为什么它有效

 在任何时间点，有关过去决策的唯一相关信息是当时可实现的最佳利润。 任何在给定时间不是最佳的时间表在以后都永远不会成为最佳，因为未来的工作仅取决于当前积累的财富，而不取决于所采取的具体路径。 这将状态空间从指数历史减少到每次单个标量 DP。 每个作业内的线性增长确保过渡的行为类似于凸包结构中的线插入，并且随着时间的推移取最大值以保留最佳子结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    N, S = map(int, input().split())
    jobs = []
    coords = set()

    for _ in range(N):
        l, r, c = map(int, input().split())
        jobs.append((l, r, c))
        coords.add(l)
        coords.add(r)

    # coordinate compression
    coords = sorted(coords)
    idx = {v: i for i, v in enumerate(coords)}

    jobs.sort()

    # dp over compressed time
    dp = [-10**30] * len(coords)
    dp[0] = 0

    best = 0
    j = 0

    for i, t in enumerate(coords):
        if i > 0:
            dp[i] = max(dp[i], dp[i-1])

        while j < N and jobs[j][0] == t:
            l, r, c = jobs[j]
            base = dp[i] - c
            # propagate profit to end
            end_idx = idx[r]
            profit = base + S * (r - l + 1)
            dp[end_idx] = max(dp[end_idx], profit)
            j += 1

    print(max(dp))

if __name__ == "__main__":
    main()
```该实施压缩了时间，因为所有相关更改仅发生在作业边界处。 dp 数组存储截至每个压缩时间点的最已知利润。 当处理从 l 开始的作业时，我们使用该点的最佳 dp 值，减去其成本，然后假设充分利用该间隔，将利润传播到其终点。 

过渡`base + S * (r - l + 1)`相当于不间断地从头到尾完成工作。 dp 传播确保后续作业可以基于该结果构建。 

一个微妙的实现细节是 dp 值的前向传播：我们确保随着时间的推移最佳值的单调性，以便稍后坐标处的任何查询都能看到可实现的最佳早期状态。

 | 步骤| 工作 | dp 之前 | 行动| dp 更新 |

 | 1 | [1,5,10]| 0 | 接受工作 | dp 在 5 处变为 0 - 10 + 15 = 5 |

 最终答案是 37，来自链接作业 2 和作业 3。

 ## 边缘情况

 一个关键的边缘情况是工作时间极短但成本高昂。 在这种情况下，如果它充当两个高密度区间之间的桥梁，则最佳解决方案可能仍然包含它。 该算法可以处理这个问题，因为每个作业都是在其开始时间从最佳可达 dp 进行评估的，因此，如果它们解锁了更高的未来状态，即使是负的即时增益转换也会被考虑。 

当多个作业共享相同的开始或结束时间时，会出现另一种边缘情况。 由于更新是通过坐标压缩按排序顺序应用的，因此同一边界处的所有转换都会得到一致的评估，并且在重叠更新之间保留最大值。 

最后一个微妙的情况是最佳策略在重叠的工作之间反复切换。 DP 不假设工作使用单调； 相反，它总是在每个边界重新计算最佳可达到的利润，因此只要重复的重新进入模式提高了运行最大值，它们就会自然地被捕获。
