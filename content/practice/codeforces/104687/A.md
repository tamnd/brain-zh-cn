 ## 解决方案
 ## 问题理解

 我们得到三个整数，每个整数代表三角形的潜在边长。 任务是确定这三个长度是否可以形成一个有效的三角形。 

从几何角度来看，只有当没有任何一个线段太长而无法被另外两个线段“闭合”在一起时，三个线段才能形成一个三角形。 用代数术语来说，这转化为任何两侧的总和必须严格大于第三侧的条件。 由于我们正在处理三个值，因此我们需要检查所有三个排列的此条件。 

输入大小很小：正好三个整数，每个整数在 1 到 100 之间。这立即告诉我们，任何扫描少量恒定数量条件的方法就足够了。 不需要数据结构、大范围循环或优化问题。 恒定时间检查是这里唯一有意义的复杂性类别。 

主要的边缘情况来自边界平等。 天真的读者可能会错误地接受这样的案例`1 2 3`因为总和等于第三条边，但相等并不能形成三角形。 另一个微妙的情况是值未排序； 例如，`3 1 2`即使最大值不在最后位置，仍然应该被拒绝。 

## 方法

 思考这个问题的强力方法是直接应用定义。 我们检查所有三个不等式：是否`a + b > c`,`a + c > b`， 和`b + c > a`。 如果所有条件均为真，则各边形成一个三角形。 

没有任何有意义的方法可以进一步简化这个问题，因为问题的大小已经是恒定的。 “天真的”方法可能仍然尝试排列边的所有顺序并测试每个排列的三角形有效性，但这会引入不必要的重复。 对于三个值，这意味着检查六种排列，每种排列需要最多三次比较，这仍然是恒定时间但多余。 

关键的观察结果是，三角形的有效性仅取决于剩余边的成对总和。 一旦我们认识到对称性，我们就可以直接检查所有三个条件，或者对边进行排序并将条件简化为单个不等式：排序后`x ≤ y ≤ z`，我们只需要验证`x + y > z`。 排序提供了更清晰的结构，并避免了对排列的推理。 

两种方法都是有效的，但排序版本在竞争性编程中通常是首选，因为它可以干净地推广到更高维度或类似问题。

 ## 算法演练

 为了清晰起见，我们使用排序方法。 

1. 读取三个输入整数。 
2. 将它们存储在列表中。 
3. 按非降序对列表进行排序。 
4. 令排序后的值为`x`,`y`， 和`z`， 在哪里`z`是最大的一面。 
5. 检查是否`x + y > z`。 
6. 如果条件成立，输出`YES`，否则输出`NO`。 

排序步骤不是为了性能，而是为了降低推理复杂度。 一旦最大的元素被隔离，三角形条件就会崩溃为一个不等式而不是三个。 

### 为什么它有效

 只有当一条边至少与其他两条边之和一样长时，三角形才可能不存在。 排序保证我们总是将最大的一侧与其他两侧的总和进行比较。 如果该不等式严格成立，则其余两个不等式将自动满足，因为两者都涉及至少与`x + y`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())
    sides = [a, b, c]
    sides.sort()

    if sides[0] + sides[1] > sides[2]:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该代码在一行中读取三个值，将它们存储在一个列表中，并对它们进行排序，使最大值位于末尾。 唯一的决策点是两个较小值和最大值之间的三角不等式检查。 比较是严格的，它正确地拒绝了总和等于第三边的退化情况。

 | --- | --- | --- | --- |
 | 读取输入| [1,2,3]| | |
 | 排序 | [1,2,3]| [1,2,3]| |

 这里总和等于最大边，而不是严格大于，因此条件失败，输出为`NO`。 这代表了一个退化成直线的三角形。

 ## 边缘情况

 常见的边缘情况是最大边恰好等于其他两条边的总和。 例如，输入`10 10 20`。 

排序后我们得到`[10, 10, 20]`。 算法检查`10 + 10 > 20`，其评估结果为`20 > 20`， 错误的。 输出正确`NO`。 这证实了平等被正确对待并防止退化的“平坦”三角形。 

另一种情况是当输入未排序时，例如`3 1 2`。 排序将其转换为`[1, 2, 3]`，并且相同的不等式检查正确地拒绝了它。 这表明正确性不依赖于输入顺序，只依赖于相对大小。
