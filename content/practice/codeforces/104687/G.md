 ## 解决方案
 ## 问题理解

 我们有一排铅笔，每支都有一个价格，我们最终必须准确地购买$k$其中。 这个过程是连续的：我们从左到右扫描并在每个位置决定是否购买那支铅笔。 

购买一支铅笔的成本不仅仅是它的价格。 如果这是您购买的第一支铅笔，您只需支付其价格。 如果它不是第一支，那么购买它也会迫使您支付相当于之前购买的铅笔指数的额外税。 必须购买序列中的最后一支铅笔，它也包含在$k$选定的项目。 

因此，实际成本不仅取决于选择的铅笔，还取决于它们的位置引起的顺序。 任务是在这些规则下最小化总成本。 

约束允许最多$n = 10^5$，这立即排除了尝试所有子集或所有组合的任何解决方案$k$选择的铅笔。 甚至$O(nk)$在最坏的情况下，动态规划太慢。 解决方案必须将问题简化为接近排序或单遍贪婪选择。 

出现微妙的边缘情况时$k = 1$。 在这种情况下，最后一支铅笔是唯一被选择的，并且无需缴税。 对税收规则的天真解释可能仍然会根据之前的指数错误地添加一些内容，但正确的行为是答案很简单$a_n$。 

另一种失败的情况是，人们认为选择的顺序在更深层次上并不重要，而不仅仅是选择$k$最低的价格。 税收取决于指数，因此忽略指数完全会导致错误的推理，除非它被正确地纳入目标。 

## 方法

 蛮力的想法是模拟所有的选择方式$k$包括最后一支的铅笔。 对于大小的每个子集$k-1$从一开始$n-1$铅笔，我们可以通过重建采购订单并对价格和税费求和来计算成本。 这是可行的，因为一旦子集固定，该过程就是完全确定性的，但子集的数量是$\binom{n-1}{k-1}$，即使对于中等强度的情况来说，它也会变得天文数字般大$n$。 这种方法一旦规模化就会被打破。 

关键的观察是，一旦我们确定了购买哪些铅笔，订单就会通过增加指数来强制，并且税收结构会变得累加。 如果选择的索引是$i_1 < i_2 < \dots < i_{k-1} < n$，那么除了最后一支铅笔之外，每支选定的铅笔都将其索引作为税收恰好贡献一次，因为它是序列中的“前一次购买”。 这消除了所选元素之间的所有交互。 

一旦成本分解为每个所选索引的独立贡献之和，问题就变成了选择$k-1$具有最小单独成本的项目，其中每个项目都有修改后的权重，包括其价格和指数贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\binom{n}{k} \cdot k)$|$O(k)$| 太慢了|
 | 最佳|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1.观察最后一支铅笔$n$必须始终包含在内，因此我们将其作为解决方案的一部分进行修复。 它的贡献始终是$a_n$，并且它永远不会贡献额外的税收，因为它不会跟随任何东西。 
2. 重新表述剩下的选择：我们必须准确地选择$k-1$指数来自$[1, n-1]$。 这些决定了购买顺序的其余部分。 
3. 在概念上对所选索引进行排序，因为它们自然地按升序排列。 这种排序是由从左到右的过程强制进行的，因此不存在额外的排列决策。 
4. 计算所选集合的成本贡献。 每个选定的索引$i$贡献它的价格$a_i$，并贡献其索引$i$恰好一次作为税收，因为它将是序列中之前选择的铅笔恰好一次。 
5. 定义变换后的权重$w_i = a_i + i$。 总成本变为：$$a_n + \sum_{i \in S} (a_i + i)$$在哪里$S$是一组$k-1$选定的指数。 
6. 问题归结为选择$k-1$的最小值$w_i$之中$i \in [1, n-1]$。 
7. 输出$a_n$加上这些的总和$k-1$最小的变换权重。 

### 为什么它有效

 关键的属性是税收项仅取决于先前选择的索引，并且每个选择的索引恰好成为前一个元素一次（除了之前最后选择的元素）$n$，仍算一次）。 这使得税收贡献在要素上呈线性，而不是依赖于任意状态之间的转变。 一旦重写，成本函数就变成了独立项目权重的简单求和，因此任何最佳解决方案都必须选择最小的可用权重，而不考虑交互作用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    if k == 1:
        print(a[-1])
        return
    
    w = []
    for i in range(n - 1):
        w.append(a[i] + (i + 1))
    
    w.sort()
    
    ans = a[-1] + sum(w[:k - 1])
    print(ans)

if __name__ == "__main__":
    solve()
```实施直接遵循转换后的公式。 唯一的特殊情况是$k = 1$，我们避免构建或排序任何东西并立即返回$a_n$。 

指数偏移$i + 1$很重要，因为问题中铅笔索引是从 1 开始的，而 Python 数组是从 0 开始的。 错过这一转变是产生逐一错误的常见原因，这些错误会悄悄地破坏税收计算。
