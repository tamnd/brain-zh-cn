 ## 解决方案
 ## 问题理解

 我们给定两个整数区间：一个区间定义了$x$，另一个定义了所有有效值$y$。 我们也有一个目标金额$n$。 任务是数出有多少对$(x, y)$存在使得$x$在于其区间，$y$位于其区间内，它们的总和恰好是$n$。 

更具体地说，想象两个包含在内的数字范围。 我们希望从第一个范围中选取一个数字，从第二个范围中选取一个数字，以便它们加起来达到一个固定值。 输出只是执行此操作的有效方法的数量。 

约束足够小，两个范围都达到$10^5$，目标总和也达到$10^5$。 这立即排除了在最坏情况下需要对所有对进行二次迭代的任何情况，因为这将导致最多$10^{10}$运营。 相反，我们应该针对每次测试进行线性或恒定时间推理。 

一些边缘情况对于正确性很重要。 如果需要补充$y = n - x$落在第二个区间之外，即$x$没有任何贡献。 例如，如果$l_1 = 1, r_1 = 10, l_2 = 1, r_2 = 10, n = 2$，那么只有$x = 1, y = 1$有效，所以答案是 1。一种简单的方法，忘记了界限$y$会错误地计算无效对，例如$x = 2, y = 0$， 虽然$y$超出了它的范围。 

另一个微妙的问题是，如果试图独立计算有效值，就会出现过度计算。$x$和$y$值而不强制执行总和约束。 两个变量之间的依赖关系是严格的，因此不能独立对待。 

## 方法

 一个简单的方法就是尝试一切可能的方法$x$在其区间内，计算$y = n - x$，并检查这是否$y$位于第二个区间。 这是有效的，因为对于每个固定$x$, 最多有一个候选者$y$。 正确性是立即的，因为我们直接执行条件$x + y = n$。 

这种暴力方法的问题在于它的运行时间。 最坏情况下，间隔为$x$包含$10^5$值，并且每次检查都是恒定时间，因此它运行在$O(r_1 - l_1 + 1)$，这里是可以接受的。 然而，我们可以通过完全删除迭代来进一步简化。 

关键的观察是我们不是在对上搜索，而是同时交叉两个约束：$$x \in [l_1, r_1], \quad n - x \in [l_2, r_2]$$第二个条件可以重写为：$$l_2 \le n - x \le r_2$$重新排列给出：$$n - r_2 \le x \le n - l_2$$所以$x$必须位于两个区间的交点：$$[l_1, r_1] \cap [n - r_2, n - l_2]$$一旦我们计算出这个交集，每个整数$x$它里面正好对应一个有效的$y$，反之亦然。 所以答案简化为计算一个区间内的整数。

 | --- | --- | --- | --- |
 | 蛮力 | O(r1 - l1 + 1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题转化为计算两个范围交集内的整数。 

1. 计算变换后的区间$x$所暗示的$y$- 限制。 这是$[n - r_2, n - l_2]$。 这一步是必要的，因为条件$y$必须表达为$x$对齐两个约束。 
2. 计算之间的重叠$[l_1, r_1]$和$[n - r_2, n - l_2]$。 交点的左边界是两个左端点中的最大值，右边界是两个右端点中的最小值。 
3. 如果所得的左端点超过右端点，则交集为空，因此答案为零。 这对应于没有的情况$x$可以同时满足这两个约束。 
4. 否则，交集的整数个数为$r - l + 1$，直接给出有效的数量$x$，因此有效对。 

### 为什么它有效

 每个有效对$(x, y)$满足两个原始约束。 该变换取代了约束$y$具有等效约束$x$，保留有效对和整数之间的一一对应关系$x$在十字路口。 没有两个不同$x$值产生相同的对，并且每个有效对产生恰好一个$x$，所以计数有效$x$值相当于计算有效对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

l1, r1, l2, r2, n = map(int, input().split())

left = max(l1, n - r2)
right = min(r1, n - l2)

if left > right:
    print(0)
else:
    print(right - left + 1)
```代码直接应用算法中导出的区间变换。 表达式`n - r2`和`n - l2`定义有效范围$x$由第二个区间暗示。 服用`max`和`min`在恒定时间内安全地计算交叉点边界。 最终条件处理空交集情况，确保不会产生负计数。

 ## 边缘情况

 一种重要的边缘情况是变换后的区间完全位于原始区间之外$x$-范围。 用于输入`1 2 10 20 5`，导出的范围是$x \in [5 - 20, 5 - 10] = [-15, -5]$。 与 相交$[1, 2]$产生一个空区间，因为左端点变为 1，右端点变为 -5。 该算法正确返回 0，因为相交检查`left > right`触发器。 

另一种情况是当交集减少到单个值时。 用于输入`0 10 0 10 0`，两个范围都变成$[0, 10]$，所以交集也是$[0, 10]$。 算法返回$10 - 0 + 1 = 11$，它匹配对的数量，其中$x = -y$在同一区间内，包括零。 

最后一个微妙的情况是完全重叠的，其中每个$x$在原来的范围内是有效的。 用于输入`1 10 1 10 10`，变换后的区间也是$[0, 9]$，相交给出$[1, 9]$。 该算法正确计算该交点中的所有有效整数，而不会重复计算或丢失端点。
