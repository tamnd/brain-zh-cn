 ## 解决方案
 ## 问题理解

 我们得到一个从左到右索引的整数序列。 任务是准确挑选`k`该序列中的位置使得任何两个选定的位置至少分开`d`指数。 在所有有效选择中，我们希望所选值的总和最大。 

另一种看待它的方式是我们选择一个固定大小的子序列`k`，但我们不允许选择彼此太接近的元素。 该约束纯粹是位置性的，而不是基于值的，但目标是最大化所选位置处的值的总和。 

输入大小最多达到150000个元素，而`k`最多 50。距离约束`d`可以大到`n`，这迫使选择极度稀疏。 重要的结构含义是，虽然数组很大，但所选元素的数量非常少，这立即建议对具有附加维度的位置进行动态规划，以确定已选择的元素数量。 

一个天真的想法是尝试所有组合`k`满足间距约束的索引。 即使忽略有效性检查，选择的方式数量`k`150000个头寸是一个天文数字，即使进行剪枝，组合爆炸仍然存在。 另一种幼稚的尝试是贪婪地选择最大值，但这会失败，因为提前选择一个大值可能会阻止访问多个稍小但总体更好的值。 

当存在负数时，会出现微妙的边缘情况。 总是占据最佳可用下一个位置的贪婪策略可能会被迫做出糟糕的全局决策。 例如，如果一个非常大的值较早出现，但随后阻止访问几个中等大的值，则最佳解决方案可能完全跳过早期的大值。 

大的组合`n`， 小的`k`，并且间距约束强烈建议 DP，其中转换仅取决于有限数量的先前选择。 

## 方法

 暴力方法会尝试枚举所有有效的大小子集`k`。 人们可以想象递归尝试获取或跳过每个位置，跟踪已选择的元素数量并强制执行距离约束。 这会产生一个状态空间，其中每个元素分支为两个选择，但对间距的约束迫使进行额外的检查。 在最坏的情况下，即使进行了修剪，有效状态的数量也表现得像以下组合：`n`选择`k`，这远远超出了可行的限度。 

关键的观察是`k`很小，最多 50 个，而`n`很大。 这表明我们应该将问题视为选择一个精确的序列`k`位置，并优化它们之间的转换，而不是迭代所有子集。 

如果我们固定已经选择的元素数量，并从左到右处理数组，那么唯一有意义的决定是是否将当前索引作为下一个选择的元素。 一旦我们就位`i`，下一个有效选择必须来自索引`i + d`或稍后。 这种结构直接导致动态编程，其中状态跟踪已选择的元素数量和当前位置。 

我们定义`dp[i][j]`作为我们可以通过考虑位置获得的最大总和`i`往前走，已经选择了`j`元素，其约束是下一个选择的元素必须遵守与前一个选择的间距。 由于转换仅向前移动至少`d`，我们可以将DP压缩为更有效的前向迭代。 

在每个位置，我们要么跳过它，要么将其作为下一个选择的元素。 如果我们接受它，我们就会向前跳跃`d`并增加计数。 自从`k`很小，我们维持 DP 的位置和所选元素的数量。 

这本质上是一个分层的 DP`k`层，其中每层计算最佳总和以供选择`j`元素和过渡强制间隙`d`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 所有有效子集的暴力枚举 | O(C(n, k)) | O(C(n, k)) | O(k) | 太慢了|
 | DP 位置和选定计数 | O(nk) | O(nk) | O(nk) 或优化 O(nk) | 已接受 |

 ## 算法演练

 我们构建了一个动态编程解决方案，在其中跟踪选择给定数量元素的最佳总和，同时考虑间距。 

1. 初始化一个DP表，其中`dp[j][i]`代表选择后可达到的最佳总和`j`元素，与`j`-第一个元素放置在位置`i`。 该公式将每个状态锚定在最后选择的位置，这对于干净地强制间距至关重要。 
2. 设置基本案例`j = 1`，其中选择位置上的一个元素`i`只是赋予价值`A[i]`。 尚未应用任何限制，因为没有先前的选择。 
3. 对于每个元素数量`j`从 2 到`k`, 迭代位置`i`从左到右。 在位置`i`，我们考虑将其设为`j`-第一个选定的元素。 
4.如果我们选择位置`i`作为`j`-th 元素，之前选择的位置最多只能是`i - d`。 因此，我们会考虑所有有效的`p ≤ i - d`并采取最好的`dp[j-1][p]`。 
5. 为了避免扫描每个状态的所有先前位置，我们在迭代时维护一个滚动最大数组`i`。 此前缀优化减少了从每个状态线性到恒定摊销时间的转换。 
6. 更新`dp[j][i]`作为最佳先前值加上`A[i]`。 
7.填完表后，答案是所有的最大值`dp[k][i]`以获得有效的最终位置。 

### 为什么它有效

 DP 强制要求每个选定的职位都有一个明确定义的前任，该前任至少是`d`离开。 通过围绕最后选择的位置构建状态，我们确保不会发生无效间距，因为每个转换都明确遵守间隙约束。 前缀最大优化不会改变正确性，因为它仅将有效先前位置的搜索压缩为预先计算的最佳值，从而保留最佳子结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))

    NEG = -10**30

    prev = [NEG] * n
    for i in range(n):
        prev[i] = a[i]

    for j in range(2, k + 1):
        best_prefix = [NEG] * n
        dp = [NEG] * n

        best_prefix[0] = prev[0]
        for i in range(1, n):
            best_prefix[i] = max(best_prefix[i - 1], prev[i])

        for i in range(n):
            if i - d >= 0:
                dp[i] = best_prefix[i - d] + a[i]

        prev = dp

    print(max(prev))

if __name__ == "__main__":
    solve()
```该实现仅保留先前的 DP 层以节省内存。 每层对应固定选定元素的数量。 这`best_prefix`数组允许快速检索足够远的最佳先前位置。 

一个微妙的点是处理无法到达的状态，这些状态由一个大的负哨兵表示。 如果没有这个，无效的转换可能会错误地支配最大值。 另一个重要的细节是，转换仅在以下情况下发生：`i - d >= 0`，确保严格执行间距。

 ## 边缘情况

 一种边缘情况是当`d`足够大以至于只能进行非常稀疏的选择。 DP 正确处理了这个问题，因为`i - d`很快变为负数，防止无效转换。 例如，与`n = 5, k = 2, d = 4`，只有像这样的对`(0,4)`是有效的，并且 DP 只允许在这些位置进行转换。 

另一个边缘情况是最佳解决方案跳过早期的高值。 基于前缀的 DP 确保正确处理这一问题，因为它不会贪婪地提交早期最大值，它仅将它们存储为未来组合的候选者。 

最后的边缘情况涉及负值，其中采用较少的大负值优于许多小的正值，从而阻止访问更好的后续值。 由于 DP 始终认为全局最佳先前状态`i - d`，它自然地避免了局部贪婪陷阱并保留了全局最优结构。
