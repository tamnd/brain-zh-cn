 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，我们需要从中选取三个元素。 唯一的限制是结构性的：如果我们在位置选择元素$i_1 < i_2 < i_3$，那么每个连续的对必须至少分开$d$指数、含义$i_{t+1} - i_t \ge d$。 目标是最大化所选值的总和。 

关键的困难在于位置之间的相互作用。 过早选择一个大值可能会阻止访问附近的其他大值，因此局部最优选择可能会破坏全局最优值。 

限制条件很大：$n \le 150000$。 这立即排除了对所有三元组或所有有效组合的任何三次或二次探索。 甚至$O(n^2)$方法太慢。 该解必须本质上是线性的或线性算数的。 

当值为负时，就会出现一个微妙的问题。 天真的直觉可能会建议“总是采用最好的可用下一个元素”，但这会失败，因为稍小的早期选择可以解锁两个更大的后期选择。 

例如，考虑：```
n = 6, d = 2
A = [10, -100, 9, 9, 9, 9]
```贪婪的选择可能会在索引 1 处取 10，然后被迫采用次优间距。 正确的策略可能会跳过它，以便稍后根据间距允许两个或三个大值。 

另一个失败案例来自本地窗口推理。 任何只关注下一个的方法$d$或者$2d$独立的位置将会失败，因为最佳三元组取决于整个数组的全局对齐。 

## 方法

 暴力解决方案会尝试每一个三重索引$i < j < k$，检查是否满足间距约束并计算总和。 这是$O(n^3)$，这是完全不可行的$n = 150000$。 即使优化有效性检查也无济于事，因为候选三元组的数量本身就非常巨大。 

我们需要一种方法来避免枚举对，而是重用最佳子结构。 关键的观察是一旦我们修复了中间元素$j$，问题分为两个独立的子问题：左侧的最佳有效选择和右侧的最佳有效选择，每个子问题都有间距约束。 

这表明动态规划。 我们定义的状态捕获在考虑间距的同时选取 1、2 或 3 个元素达到给定索引的最佳可能总和。 

更具体地说，我们可以定义：

 -$dp1[i]$：从前缀中选择 1 个元素的最佳总和$[1..i]$-$dp2[i]$：从前缀中选择2个元素的最佳总和$[1..i]$-$dp3[i]$：从前缀中选择 3 个元素的最佳总和$[1..i]$转换取决于选择是否将最后选择的元素放置在位置$i$，并确保先前选择的元素最多为$i - d$。 

为了有效地加强间距，我们维护早期有效范围中的最佳值，而不是扫描所有先前的状态。 

过渡变为：

 - 要么跳过$i$- 或者使用$i$作为最后选取的元素，并将其与结束于或之前的最佳有效状态相结合$i - d$这将每个状态转换减少到$O(1)$使用前缀最大值进行摊销。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了|
 | 带有最大值前缀的最优 DP |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们构建了三个 DP 层，但我们使用前缀最佳跟踪在单个前向传递中计算它们。 

1. 预先计算前缀最大数组，使我们能够查询到索引的最佳 dp 值$i$。 这确保我们无需扫描即可有效找到最佳的有效先前选择。 
2、维护三个DP数组：dp1、dp2、dp3。 每个 dp 状态代表使用许多选择索引可实现的最佳总和$i$。 这种分离是必要的，因为转换取决于已选择的元素数量。 
3. 将 dp1[i] 初始化为迄今为止看到的最佳单个元素，直到 i。 这只是前缀中的最大值，因为只选择了一个元素。 
4. 对于 dp2[i]，考虑将元素 i 作为第二个选择。 第一个选择必须来自最多 i - d 的索引。 因此 dp2[i] 更新为：

 前缀 [1 .. i - d] + A[i] 中的最佳 dp1 值，或携带 dp2[i-1]。 

此步骤将间距约束直接编码到过渡中。 
5. 对于 dp3[i]，类似地考虑将 i 作为第三个选择。 我们将直到 i - d 的最佳 dp2 值与 A[i] 相结合，或进位 dp3[i-1]。 
6. 最终答案是dp3[n]。 

为什么它有效：

 在每个索引 i 处，dp1、dp2、dp3 存储以 i 结尾的前缀的最优解。 任何三个元素的最佳选择都必须有最后一个元素 k。 一旦 k 固定，剩下的两个元素就在 k - d 之前形成前缀中的最佳有效选择，因为任何重叠或偏差都会与最优性相矛盾。 这种最佳子结构保证使用前缀最大值增量构建解决方案永远不会错过更好的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))
    
    NEG = -10**30
    
    # dp arrays
    dp1 = [NEG] * n
    dp2 = [NEG] * n
    dp3 = [NEG] * n

    dp1[0] = a[0]

    # prefix bests for dp1, dp2, dp3
    best1 = [NEG] * n
    best2 = [NEG] * n
    best3 = [NEG] * n

    best1[0] = dp1[0]

    for i in range(1, n):
        # dp1: take best single element
        dp1[i] = max(dp1[i-1], a[i])

        # dp2: either skip or take i as second element
        j = i - d
        best_prev1 = best1[j] if j >= 0 else NEG
        dp2[i] = max(dp2[i-1], best_prev1 + a[i])

        # dp3: either skip or take i as third element
        best_prev2 = best2[j] if j >= 0 else NEG
        dp3[i] = max(dp3[i-1], best_prev2 + a[i])

        # update prefix bests
        best1[i] = max(best1[i-1], dp1[i])
        best2[i] = max(best2[i-1], dp2[i])
        best3[i] = max(best3[i-1], dp3[i])

    print(dp3[n-1])

if __name__ == "__main__":
    solve()
```该实现跟踪位置 i 处的精确 DP 和前缀最大值。 前缀数组是必不可少的，因为转换总是需要达到有界索引的最佳值$i - d$，不一定完全结束于$i - d$。 

负标记设置得足够大，以避免添加值时意外溢出。 结转`dpX[i-1]`确保始终考虑跳过元素。

 ## 边缘情况

 一个关键的边缘情况是，最佳的早期价值阻碍了以后获得更强的组合。 例如：```
n = 6, d = 2
A = [100, 1, 1, 1, 100, 100]
```一种幼稚的方法可能会在索引 0 处选择 100，从而迫使其余的选择相距很远，并失去在最后获取两个 100 的能力。 DP 在形成 dp2 和 dp3 时正确地跳过前 100 个，因为 dp2 和 dp3 保留了替代历史。 

另一种边缘情况是最佳选择在距离 d 边界处紧密对齐。 过渡使用`i - d`， 不是`i - d - 1`，因此边界包含是正确的。 这里任何相差一的错误要么允许无效的选择，要么错误地禁止有效的选择，立即破坏紧密包装的最佳解决方案的正确性。
