 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符组成的二进制字符串`0`和`1`。 我们关心的成本是该字符串中的反转次数，其中反转是任意一对位置`i < j`使得一个`1`出现在 a 之前`0`。 

允许我们修改字符串的唯一方法是最多执行一次相邻字符的交换，或者完全跳过该操作。 在选择性地执行此单个交换之后，我们测量结果字符串的反转计数。 任务是计算在此约束下可实现的最小可能反转计数。 

关于输入大小（最多 100000 个字符）的关键观察结果立即排除了对每个可能的交换从头开始重新计算反转计数。 尝试所有相邻交换并每次重新计算反转的简单方法每次交换都需要 O(n) 工作，导致总操作为 O(n^2)，这对于 n = 10^5 来说太慢了。 

当字符串已经是单调的时，就会出现微妙的边缘情况。 例如，`000111`反转为零，任何交换只会增加反转。 如果不与无操作情况进行比较，总是应用交换希望改善局部性的粗心贪婪策略可能会意外地使答案变得更糟。 

当恰好有一个时，会出现另一种边缘情况`10`图案。 例如，`110`有一个反转，但交换中间一对会产生`101`，即使它修复了局部模式，也不一定会减少全局反转。 这表明局部改进并不总是与全局改进相对应。 

## 方法

 基本思想很简单。 计算原始字符串的反转计数。 然后尝试每一个可能的相邻交换，重新计算反转计数，并跟踪最小值。 

这是可行的，因为只有 n 种可能的交换，并且使用前缀和或计数 1/0 的反转计数众所周知为 O(n)。 然而，在最坏的情况下，这会导致 O(n^2) 总时间，因为每次交换都需要对整个字符串进行重新计算。 

关键的见解是交换两个相邻字符只会影响涉及这两个位置的反转。 字符串中的其他内容保持不变。 这意味着如果我们了解单个`01`或者`10`对有助于全局反转。 

我们不是从头开始重新计算，而是预先计算一次总反转计数。 然后，对于每个相邻对，我们计算如果交换它们，反转计数将如何变化。 由于字符串是二进制的，因此只有两种情况很重要：交换`01`到`10`增加反转和交换`10`到`01`减少反转。 确切的变化取决于交换位置周围有多少个零和一个，但对于相邻位置，这简化为恒定的增量计算。 

这将问题简化为检查所有相邻对一次，通过常数公式更新反转计数，并取最小值。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|

 ## 算法演练

 我们计算原始字符串的反转计数，然后评估每个可能的单个交换并计算其效果。 

1. 计算零或一的前缀信息，以便我们可以快速评估反转贡献。 一种简单的方法是计算到目前为止出现了多少个，每次看到零时，我们都会将该数字添加到反转计数中。 这个直接统计所有`1 before 0`对。 
2. 将原始反转计数存储为基线答案。 这对应于不执行任何操作。 
3. 迭代每个相邻的对`s[i], s[i+1]`。 如果该对是`00`或者`11`，交换不会改变任何内容，因此我们跳过它。 
4. 如果这对是`10`，交换它产生`01`。 这消除了货币对本身造成的一个倒置，但也影响了这一点`1`与其右侧的零相互作用以及它如何`0`与其左边的相互作用。 由于交换是本地且相邻的，因此净变化简化为使用前缀计数计算的固定增量。 
5. 如果这对是`01`, 交换产生`10`。 这在本地引入了额外的反转，再次通过前缀计数计算的周围贡献进行调整。 
6. 对于每个交换位置，将新的反转计数计算为`base + delta`，如果更小则更新答案。 
7. 返回包括原始字符串在内的所有位置的最小值。 

### 为什么它有效

 反转计数是所有对的总和`(i, j)`和`i < j`。 相邻元素的交换仅影响涉及交换位置之一的对。 所有不涉及的对`i`或者`i+1`交换前后保持相同。 因此，反转计数的变化完全由交换对周围的恒定大小邻域决定。 这种局部性保证了独立评估每个交换并取得最佳结果会产生全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # initial inversion count: number of (1 before 0)
    ones = 0
    base = 0
    for ch in s:
        if ch == '1':
            ones += 1
        else:
            base += ones

    ans = base

    # prefix ones and suffix zeros to compute local deltas
    prefix_ones = [0] * (n + 1)
    for i in range(n):
        prefix_ones[i + 1] = prefix_ones[i] + (s[i] == '1')

    suffix_zeros = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_zeros[i] = suffix_zeros[i + 1] + (s[i] == '0')

    total_ones = prefix_ones[n]

    for i in range(n - 1):
        if s[i] == s[i + 1]:
            continue

        if s[i] == '1' and s[i + 1] == '0':
            # 10 -> 01 swap
            # delta = -1 (pair) + effects with left/right context
            left_ones = prefix_ones[i]
            right_zeros = suffix_zeros[i + 2] if i + 2 <= n else 0

            # before:
            # s[i]=1 contributes with zeros on right: right_zeros + (i+1 position zero counted in suffix)
            # s[i+1]=0 contributes with ones on left including s[i]
            before = right_zeros + (left_ones + 1)

            # after swap roles reversed
            after = left_ones + right_zeros

            ans = min(ans, base + (after - before))

        else:  # 01 -> 10
            left_ones = prefix_ones[i]
            right_zeros = suffix_zeros[i + 2] if i + 2 <= n else 0

            before = left_ones + right_zeros
            after = right_zeros + (left_ones + 1)

            ans = min(ans, base + (after - before))

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先通过从左到右扫描并累加每个零之前出现的个数来计算反转计数。 这是二进制字符串的标准线性时间反转计数方法。 

然后，它构建 1 的前缀计数和 0 的后缀计数，以便当我们检查交换位置时，​​我们可以快速确定每一侧有多少元素与交换的字符交互。 

对于每个相邻对，我们通过比较交换前后的贡献来计算交换的效果。 将差异添加到基本反转计数中，并跟踪最小值。 

重要的实现细节是在计算左右贡献时仔细排除交换的位置，因为这些位置是在计算之前/之后明确处理的。

 ## 边缘情况

 对于已经排序的字符串，例如`000111`，该算法评估所有交换，但每次增量计算都会产生零或正变化，因此答案仍然是零的基本反转计数。 这证实不必要的交换被正确忽略。 

对于像这样的字符串`111000`，反转次数最大。 任何相邻交换只能稍微重新分配反转，但不能一步减少所有跨块反转。 该算法正确地发现，除了微小的局部改进之外，没有任何一次交换会显着改变总体。 

对于像这样的最小字符串`10`, 交换产生`01`，将反转计数从 1 更改为 0。该算法可以正确处理此问题，因为直接评估相邻对并且其增量仅应用一次，而不需要任何周围上下文。
