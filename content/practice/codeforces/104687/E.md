 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，仅由零和一组成。 我们使用反转来测量无序性：每对出现在零之前的位置都贡献一个单位。 任务是尽可能减少这种反转计数，并具有执行最多一个交换两个相邻字符的操作的额外自由。 

因此，我们从零和一的固定配置开始，我们可以选择选择一个相邻的对并交换一次，并且我们想知道在所有此类选择中可实现的最小反转计数，包括选择不执行任何操作。 

字符串长度最多为 100，这已经表明即使每个候选操作的二次行为也是可以接受的。 任何三次或更差的方程在技术上都可以，但我们应该以干净的二次解为目标，因为结构很简单。 

当假设交换本地对仅以明显的线性方式影响涉及这两个字符的反转而无需仔细重新计算时，就会出现天真的陷阱。 例如，在像这样的字符串中`1010`，交换中间`10`到`01`不仅改变了该对形成的反转，还改变了这些角色与双方其他人的互动方式。 任何尝试使用过于局部的启发式更新反转计数的方法都可能会错过这些交叉效应。 

另一个微妙的问题是忘记了根本不进行交换的选项。 在某些情况下，初始字符串已经是最佳的，例如`000111`，任何交换只会增加无序性。 

## 方法

 思考问题的直接方法是尝试我们可以达到的每一个有效状态。 只有两种：原始字符串，以及交换相邻一对得到的所有字符串。 对于每个这样的字符串，我们可以通过扫描所有对并计算一个字符串的次数来从头开始计算反转计数。`1`在一个之前`0`。 

这是可行的，因为约束很小，但它是多余的。 如果字符串的长度为 n，则有 n-1 种可能的交换。 从头开始计算一个字符串的反转需要 O(n²)，因此总数变为 O(n³)。 对于 n ≤ 100，这仍然是可以接受的，但它浪费了结构。 

关键的观察结果是交换两个相邻元素不会全局重塑字符串。 仅交换元素相对于数组其余部分的相对顺序发生变化。 其他一切都保持不变。 这意味着如果我们愿意仔细推理反演贡献如何变化，我们不需要从头开始重新计算一切。 

然而，实际上，对于 n ≤ 100，最干净的实现仍然是对每个交换候选对象重新计算 O(n) 或 O(n²) 的反转。 该结构足够小，以简单取胜。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力重新计算每次交换的所有对 | O(n3) | O(1) | O(1) | 因限制而接受 |
 | 重新计算每次交换的反转，时间复杂度为 O(n) 或 O(n²) | O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将答案视为不执行任何操作和在某个位置仅执行一次交换之间的最小值。 

1. 计算原始字符串的反转次数。 这是我们的基准答案。 如果 i 处的字符为 1 并且 j 处的字符为 0，则 i < j 的每对 (i, j) 都有贡献。 
2. 使用该基线值初始化答案。 这对应于不执行任何交换的选择。 
3. 对于从 0 到 n − 2 的每个索引 i，考虑交换位置 i 和 i + 1 处的字符。在交换后构造结果字符串。 我们显式重建字符串的原因是n很小，正确性比微优化更重要。 
4. 对于每个交换配置，通过扫描 j < k 的所有对 (j, k) 并在 1 在 0 之前进行计数，从头开始计算其反转计数。这给出了该交换选择的确切成本，而不依赖于脆弱的增量推理。 
5. 使用所有交换位置和原始配置的最小值更新答案。 

最终存储的值是可实现的最佳反转计数。 

### 为什么它有效

 任何有效的最终配置要么是原始字符串，要么与它仅相差一个相邻的换位。 由于我们枚举了所有此类可能性并计算了它们的精确反转计数，因此不会错过任何可达状态。 由于反转计数是精确重新计算而不是近似计算，因此不存在由于局部假设而导致计数不足或计数过多的风险。 该算法对于由操作约束定义的可达状态空间是详尽的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def inversion_count(s):
    n = len(s)
    cnt = 0
    for i in range(n):
        if s[i] == '1':
            for j in range(i + 1, n):
                if s[j] == '0':
                    cnt += 1
    return cnt

def solve():
    s = input().strip()
    n = len(s)

    best = inversion_count(s)

    s = list(s)
    for i in range(n - 1):
        s[i], s[i + 1] = s[i + 1], s[i]
        best = min(best, inversion_count(s))
        s[i], s[i + 1] = s[i + 1], s[i]

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案首先定义一个直接反转计数器，用于扫描所有有序对并计算`1`随后是一个`0`。 这既用于初始配置又用于每个交换的变体。 

主循环尝试每个相邻交换一次，就地执行它，评估生成的反转计数，然后恢复原始字符串。 恢复步骤是必不可少的； 忘记它会累积多次交换并打破“最多一次操作”的限制。

 ## 边缘情况

 对于完全排序的字符串，例如`000111`，初始反转计数为零。 任何相邻的交换都会引入至少一个反转，因为它创建了一个本地`10`图案。 该算法首先评估原始字符串，因此即使所有交换都更糟，答案仍然为零。 

对于完全反转的字符串，例如`111000`，反转最初被最大化。 在边界附近（例如位置 2 和 3）进行交换可以同时减少多个跨块反转。 该算法显式地评估这些边界交换并捕获改进，因为它在每次交换后重新计算完整的反转计数，而不是假设局部效应。
