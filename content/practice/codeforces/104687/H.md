 ## 解决方案
 ## 问题理解

 我们得到一个从左到右索引的整数序列，我们需要在这个序列中选择三个位置。 约束是任何两个选定的位置必须至少分开`d`指数，意味着如果我们选择仓位`i < j < k`， 然后`j - i >= d`和`k - j >= d`。 在所有这些有效的三元组中，我们希望所选位置的值的总和最大。 

输入的结构比单独的值更重要。 每个索引都充当一个潜在的“锚点”，选择一个索引会限制其周围的禁止索引窗口，以供其余选择使用。 任务是放置三个锚点，使它们不发生冲突，并使收集到的总重量最大化。 

约束条件`n ≤ 1500`建议$O(n^3)$对所有三元组的暴力破解已经接近极限，但在某些情况下仍然可行。 然而，任何试图通过额外的内部检查来探索所有组合的方法都是有风险的。 关键信号是选择大小固定为 3，这通常意味着可以对前缀或后缀进行部分优化。 

当一个人试图首先贪婪地选择最好的元素然后扩展时，就会出现一种天真的但微妙的失败案例。 例如，考虑一个序列，其中全局最大值与其他强元素太接近，而稍小的元素可以在以后实现两个额外的大选择。 任何贪婪的“先取最好”的策略都会失败：

 输入：```
n = 6, d = 2
A = [100, 1, 1, 90, 1, 90]
```由于距离限制，索引 1（值 100）的贪婪选择会阻塞两个 90，总共产生 100。最优解跳过 100，取 90 + 90 + 1 = 181。这表明局部最大值选择在结构上是无效的。 

另一个陷阱是将其视为独立的间隔选择，而不强制对称地执行距离。 如果我们修复一个元素并尝试独立地最大化左侧和右侧而不强制间隙，我们可能会意外地允许跨分区的非法邻接。 

真正的结构是具有固定间距的约束三元组选择，这强烈建议动态编程或前缀后缀预计算。 

## 方法

 暴力解决方案枚举所有索引三元组`i < j < k`并检查两个间隙是否满足约束。 对于每个有效的三元组，我们计算`A[i] + A[j] + A[k]`并跟踪最大值。 这在正确性方面是简单的，因为它直接匹配问题的定义。 

三元组的数量约为$O(n^3)$，这对于$n = 1500$给出大约 33 亿次迭代。 即使优化代码中有非常紧密的内部循环，这也远远超出了 Python 中可接受的限制，并且在严格的时间限制下，在 C++ 中仍然太大。 瓶颈不仅在于迭代次数，还在于重复的约束检查。 

关键的观察结果是，三元组的中间元素将问题完全分成两个独立的部分：有效的左选择和有效的右选择，两者都受到距离的约束`d`。 一旦中间索引`j`是固定的，最好的左边元素必须来自索引`≤ j - d`，并且最好的正确元素必须来自索引`≥ j + d`。 这将问题转化为预先计算最佳前缀和后缀值。 

我们预先计算两个数组：`best_left[i]`它存储索引中的最大值，最多`i`， 和`best_right[i]`它存储了最大值`i`到最后。 这样，每一次中间指标的选择就成为常数时间的评价。

 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了|
 | 前缀后缀优化 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算一个数组`best_left`在哪里`best_left[i]`是其中的最大值`A[0..i]`。 这使我们可以立即查询任何中间位置的最佳有效左端点，而无需再次扫描。 
2. 预计算数组`best_right`在哪里`best_right[i]`是其中的最大值`A[i..n-1]`。 这对称地给出了任何中间位置的最佳有效右端点。 
3. 迭代每个索引`j`将其视为三元组的中间元素。 
4. 对于每个`j`，确定是否存在有效的左索引。 这需要`j - d >= 0`。 如果不是，则跳过该位置，因为无法形成三元组。 
5. 同样，通过检查确保存在有效的正确索引`j + d < n`。 如果没有，请跳过。 
6. 计算最佳左侧候选者为`best_left[j - d]`以及最合适的候选人`best_right[j + d]`。 
7. 将这些与`A[j]`并更新全局最大值。 

重要的结构思想是，一旦中间固定，最佳左右选择就变得独立，因为距离约束完全分离了它们的索引范围。 

### 为什么它有效

 对于任何有效的三元组`(i, j, k)`，约束力`i ≤ j - d`和`k ≥ j + d`。 在所有这样的`i`，最好的选择始终是最大值`A[0..j-d]`，右侧也类似。 左右选择之间不存在交互作用，因为索引约束防止影响重叠。 这会创建一个分解，其中每个中间索引都会引发具有两个独立端点的独立优化问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k, d = map(int, input().split())
a = list(map(int, input().split()))

best_left = [0] * n
best_right = [0] * n

best_left[0] = a[0]
for i in range(1, n):
    best_left[i] = max(best_left[i - 1], a[i])

best_right[n - 1] = a[n - 1]
for i in range(n - 2, -1, -1):
    best_right[i] = max(best_right[i + 1], a[i])

ans = -10**18

for j in range(n):
    if j - d < 0 or j + d >= n:
        continue
    left_best = best_left[j - d]
    right_best = best_right[j + d]
    ans = max(ans, left_best + a[j] + right_best)

print(ans)
```该实现完全依赖于前缀和后缀最大值。 这`best_left`数组是从左到右构建的，因此每个位置都会累积直到该索引的最佳可能值。 这`best_right`数组是反向构建的以反映相同的逻辑。 

循环结束`j`强制执行中间元素。 边界检查至关重要，因为它们保证两个所需的同伴都存在。 一个微妙的问题是确保指数`j - d`和`j + d`是有效范围的包容性边界，而不是偏移一位。 

最终答案被初始化为一个非常负的数，以安全地处理所有值可能为负的情况。

 ## 边缘情况

 当有效的中间位置极其有限时，就会出现微妙的边缘情况。 例如：```
n = 5, d = 2
A = [10, 100, 1, 100, 10]
```只有索引 2 可以作为有效的中间元素，因为它在距离 2 的两侧必须至少有一个元素。该算法检查`j - d`和`j + d`，所以只有`j = 2`通过。 计算结果变为`10 + 1 + 10 = 21`，这是正确的，因为最好的左和右候选人是由结构强迫的。 

另一种情况是最佳端点位于边界附近。 因为前缀和后缀数组正确包含边界，`best_left[j - d]`有效时始终包含索引 0，并且`best_right[j + d]`有效时始终包含索引 n-1。 这可以防止意外排除最佳边缘解决方案，这是从索引 1 开始前缀数组或错误地移动范围的实现中的常见错误。
