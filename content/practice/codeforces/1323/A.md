 ## 解决方案
 ## 问题理解

 我们得到了几个独立的正整数数组。 对于每个数组，我们必须选择一组非空位置，使得所选值的总和为偶数。 如果不存在这样的组，我们将报告失败。 

输出不是子集本身，而是形成有效子集的元素的索引。 任何有效的选择都是可以接受的，因此我们不优化大小或字典顺序，只优化可行性。 

限制很小：最多 100 个测试用例，每个数组最多有 100 个元素。 这立即告诉我们，即使在最坏的情况下，子集上的三次或二次方法也是可行的。 然而，由于奇偶校验是唯一重要的属性，因此我们应该期望比枚举子集简单得多的结构。 

关键的边缘情况来自非常小的数组。 如果存在单个元素，则唯一子集的总和等于该元素，因此答案完全取决于该数字是否为偶数。 如果有两个元素，奇偶相互作用就变得相关：单个偶数元素已经解决了问题，而两个奇数元素也形成偶数和。 

天真的思维的一个微妙的失败案例是假设每当至少有一个奇数和一个偶数时，我们必须同时取两个数。 这是不必要的，因为单个偶数元素已经给出了有效的答案。 另一个陷阱是假设如果所有数字都是奇数并且数量超过两个，则解决方案始终存在； 事实上，我们需要偶数个奇数才能得到偶数和。 

## 方法

 暴力解决方案将枚举所有子集并检查它们的总和是否为偶数。 有$2^n - 1$非空子集，对于每个子集，我们计算一个总和$O(n)$, 给予$O(n 2^n)$每个测试用例。 和$n = 100$，这是完全不可行的，因为它超出了天文极限。 

如果我们观察奇偶校验的行为方式，问题的结构就会大大简化。 整数之和仅取决于包含多少个奇数元素。 偶数根本不影响奇偶校验，而每个奇数都会翻转总和的奇偶校验。 

这意味着我们只需要几个元素。 如果有偶数，我们可以单独取。 否则，我们会寻找奇数对，因为两个奇数之和为偶数。 如果只有一个奇数而没有偶数，则不存在解。 

因此，问题简化为扫描一次数组并记住偶数和奇数的位置。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 扫描一次数组并记录任意偶数元素的索引。 

如果我们找到一个偶数，我们可以立即停止进一步扫描，因为单个偶数元素已经形成了一个有效的子集。 这是最优的，因为它保证了最小子集大小和正确性。 
2. 如果不存在偶数元素，则收集所有奇数元素的索引。 

此步骤是必要的，因为奇数元素不能单独产生偶数和，但它们成对可以产生偶数和。 
3. 如果我们至少有两个奇数元素，则输出前两个索引。 

它们的和为奇数加奇数，即为偶数，因此满足子集条件。 
4. 如果奇数元素少于两个且没有偶数元素，则输出 -1。 

唯一剩下的情况是单个奇数元素，它不能在任何非空子集中形成偶数和。 

### 为什么它有效

 和的奇偶性仅取决于所包含元素的奇偶性。 偶数对奇偶校验贡献为零，而每个奇数则翻转它。 因此，当所选奇数元素的数量为偶数时，总和恰好为偶数。 该算法构造一个偶数元素（零个奇数元素）或两个奇数元素（两个为偶数），涵盖了所有可行的情况。 不需要其他结构，因为任何更大的子集始终可以简化为这些规范形式之一，而不会改变可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even_idx = -1
        odd_indices = []

        for i, x in enumerate(a, 1):
            if x % 2 == 0:
                even_idx = i
            else:
                odd_indices.append(i)

        if even_idx != -1:
            print(1)
            print(even_idx)
        elif len(odd_indices) >= 2:
            print(2)
            print(odd_indices[0], odd_indices[1])
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先检查偶数元素，因为它立即给出大小为 1 的有效子集。 如果不存在，则返回到唯一剩余的建设性情况：配对奇数元素。 枚举是从 1 开始的，因为该问题需要从 1 开始的索引。 

一个常见的实现错误是在找到偶数元素后继续扫描并意外覆盖逻辑或使逻辑复杂化。 另一个是忘记只需要索引，而不需要值。 

## 工作示例

 我们跟踪两种情况：一种是存在单个偶数元素，另一种是仅存在奇数元素。

 我们在找到 4 并输出索引 2 后停止。跟踪显示，一旦出现偶数，后面的元素就不再重要。 

### 示例 2

 输入：`[3, 5, 7]`| 步骤| 当前元素 | 偶数索引 | 奇怪的列表 |
 | ---| ---| ---| ---|

 不存在偶数元素，因此我们使用前两个奇数索引 1 和 2。这证实了任何两个奇数都足够，无论其值如何。

 ## 边缘情况

 一种关键的边缘情况是数组仅包含一个元素。 如果该元素是偶数，则答案是该索引； 如果是奇数，则无解。 该算法自然地处理这个问题，因为它要么设置`even_idx`或收集单个奇数索引并且不满足第二个条件。 

另一个边缘情况是存在多个偶数元素时。 该算法返回最后看到的偶数索引，该索引仍然有效，因为任何单个偶数元素就足够了。 不存在对排序的依赖。 

第三种情况是所有元素都是奇数但它们的数量很大。 该算法仍然只选择前两个索引，这是有效的，因为无论总计数如何，两个奇数已经保证了偶数和。
