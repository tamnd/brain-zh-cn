 ## 解决方案
 ## 问题理解

 我们有一个`N x M`数组，其条目是显示其中之一的卡片`6`,`7`,`8`， 或者`9`。 卡片可以原地旋转，但卡片不能在单元格之间移动。 选择要旋转的卡片后，所得阵列必须在 180 度旋转后保持不变。 

180 度旋转映射位置`(i, j)`到`(N - 1 - i, M - 1 - j)`。 为了使阵列成为点对称，在考虑到旋转的卡片发生变化的事实后，这些位置上的两张卡片也必须匹配`6`进入`9`,`9`进入`6`， 尽管`7`和`8`保持不变。 

任务是尽量减少物理旋转的卡片数量。 如果某对位置属于不兼容的数字组，则任何旋转序列都不能使数组对称，因此我们打印`-1`。 

约束条件允许两个维度都达到`500`, 最多给予`250000`细胞。 与单元数量呈二次或指数依赖性的算法在这里是不可能的。 甚至`O((NM)^2)`会太大，而`O(NM)`在 Python 中，扫描在一秒的限制内很容易实现。 内存限制很大，因此存储输入矩阵不是问题。 

幼稚的实现可能会错误地处理几种边缘情况。 第一个是一个包含`6`。 输入```
1 1
6
```必须产生`1`，因为中心单元在 180 度旋转下映射到自身，所以它的最终值必须是自对称的。 仅比较不同单元格的粗心解决方案可能会错误地返回`0`。 

包含以下内容的单个单元格也会出现同样的问题`7`:```
1 1
7
```正确答案是`0`， 因为`7`遗迹`7`旋转时。 奇数尺寸矩阵的中心需要单独处理，因为它没有明显的伙伴。 

另一个边缘情况是一对不兼容的情况。 例如，```
1 2
67
```有职位`6`和`7`作为对称对。 旋转`6`只能生产`6`或者`9`，同时旋转`7`总是产生`7`。 它们永远无法兼容，所以答案是`-1`。 

最后一个常见错误是重复计算对称对。 为了```
1 2
69
```旋转一次就足够了，因为旋转任何一张卡都会得到匹配的对。 正确答案是`1`， 不是`2`。 处理两者`(0, 0)`和`(0, 1)`进而`(0, 1)`和`(0, 0)`会将同一个决定计算两次。 

## 方法

 直接的暴力方法是考虑每个子集`NM`卡作为将被旋转的卡。 有`2^(NM)`这样的子集。 对于每个子集，我们将构建或检查结果矩阵并检查所有`NM`180 度对称的位置。 这给出了最坏情况下的运行时间`O(NM * 2^(NM))`。 

暴力破解是正确的，因为旋转卡的每一个可能的选择都被明确考虑，所以最好的有效选择必须出现在候选者中。 问题在于选择的数量。 在最大尺寸下，`NM = 250000`，因此搜索包含`2^250000`的可能性。 这不仅在实践中太慢，而且远远超出了任何可以列举的范围。 

有用的观察是 180 度旋转下的位置形成独立对。 一个细胞`(i, j)`仅与`(N - 1 - i, M - 1 - j)`。 一旦我们决定如何定位这两张牌，该决定就不会影响任何其他对。 因此，我们可以独立地求解每一对并添加最小的成本。 

还有一个结构细节。 旋转卡具有以下变换：```
6 <-> 9
7 -> 7
8 -> 8
```因此，这些数字自然形成三个兼容性组：`{6, 9}`,`{7}`， 和`{8}`。 当两个成对的单元格的原始数字属于同一组时，它们可以完全对称。 

对于包含相同数字的一对，不需要旋转。 对于包含的一对`6`和`9`，必须旋转一张牌。 如果该对包含两个不同的不相容基团，例如`6`和`7`，不存在解。 

如果`N`和`M`都是奇数，有一个未配对的中心单元。 它必须映射到自身，因此它必须包含`7`或者`8`，否则如果它包含，则必须旋转一次`6`或者`9`。 

蛮力方法之所以有效，是因为它显式搜索所有方向，但会失败，因为方向选择的数量呈指数级增长。 每个细胞都属于独立对称对的观察结果将问题简化为每个细胞的恒定工作量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(NM * 2^(NM))`|`O(NM)`| 太慢了|
 | 成对贪婪 |`O(NM)`|`O(NM)`| 已接受 |

 ## 算法演练

 1. 阅读`N x M`矩阵并定义旋转映射，以便`6`变成`9`,`9`变成`6`， 尽管`7`和`8`保持不变。 
2. 迭代每个单元格`(i, j)`仅当它是其对称对的第一个成员时。 它的合作伙伴是`(N - 1 - i, M - 1 - j)`。 将迭代限制在每对的一侧可以防止重复计数。 
3. 对于每一对，检查这两个数字是否属于同一兼容性组。 表达这一点的最简单方法是标准化`6`和`9`离开时交给同一位代表`7`和`8`清楚的。 
4. 如果归一化值不同，则返回`-1`。 任何一张卡的方向都不能在兼容性组之间交叉，因此这对卡使得魔法矩阵不可能实现。 
5. 如果两个原始数字相等，则在答案中加零。 他们无需旋转任何一张牌就已经满足了所需的关系。 
6. 如果这对是`6`和`9`，给答案加一。 旋转其中一张卡就足够了，旋转两张卡就没有必要了。 
7. 处理完所有不同的对后，检查两个维度是否都是奇数。 在这种情况下，有一个中心单元位于`(N // 2, M // 2)`没有明确的合作伙伴。 
8. 如果中心包含`6`或者`9`，加一，因为它必须旋转才能成为自对称。 如果它包含`7`或者`8`，不添加任何内容。 

### 为什么它有效

 每个位置要么恰好属于 180 度旋转下的一个双细胞轨道，要么当两个维度均为奇数时，属于单个中心细胞。 对一个轨道所做的选择不会影响另一个轨道，因此独立地最小化每个轨道也会最小化旋转总数。 

对于双细胞轨道，数字唯一可能的变换值是其自身值及其在以下情况下的配对值：`6 <-> 9`。 因此，当两个细胞都来自时，它们是完全兼容的`{6, 9}`， 两个都`7`，或两者`8`。 之内`{6, 9}`，当值不同时，旋转一次就足够了，而相同的值则不需要旋转。 当中心的数字不因旋转而改变时，中心是精确兼容的，这对于`7`和`8`; 一个中心`6`或者`9`需要旋转一圈。 因此，该算法计算出的每个贡献都是该独立轨道的最小可能贡献，并且它们的总和是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [input().strip() for _ in range(n)]

    answer = 0

    # Normalize digits that can become each other by rotation.
    def group(c):
        if c == '6' or c == '9':
            return '6'
        return c

    # Process each pair exactly once.
    for i in range(n):
        for j in range(m):
            ni = n - 1 - i
            nj = m - 1 - j

            # The center of an odd-by-odd matrix is handled separately.
            if i > ni or (i == ni and j >= nj):
                continue

            x = a[i][j]
            y = a[ni][nj]

            if group(x) != group(y):
                print(-1)
                return

            if x != y:
                # The only possible compatible unequal pair is 6 and 9.
                answer += 1

    # An odd-by-odd matrix has one cell that maps to itself.
    if n % 2 == 1 and m % 2 == 1:
        center = a[n // 2][m // 2]
        if center == '6' or center == '9':
            answer += 1

    print(answer)

if __name__ == "__main__":
    solve()
```这`group`函数捕获了唯一重要的兼容性区别。 两个都`6`和`9`属于同一组，因为轮换可以将一个组变成另一个组。`7`和`8`每个人都形成自己的小组，因为轮换他们不会改变他们。 

嵌套循环使用以下方法计算伙伴`n - 1 - i`和`m - 1 - j`，直接匹配 180 度旋转的几何形状。 条件```
if i > ni or (i == ni and j >= nj):
    continue
```只保留每对中的一个细胞。 这`j >= nj`当两行相同时，部分很重要，因为否则一对可以在中间列周围处理两次。 

对于有效的一对，`x != y`意味着该对必须是`6`和`9`，因此需要进行一次旋转。 无需显式模拟旋转，因为其成本始终为 1。 

该中心被排除在对循环之外并随后进行处理。 这可以避免意外地将中心视为与其自身成对的情况。 一个中心`6`或者`9`贡献一圈旋转，同时`7`和`8`贡献为零。 

Python中不可能出现整数溢出，最大答案是`NM`，即`250000`。 

## 工作示例

 ### 示例 1

 输入是```
2 3
676
679
```该矩阵有六个单元，因此存在三个对称对。 

|`(i,j)`| 合作伙伴| 价值观 | 团体 | 增加成本|
 | ---| ---| ---| ---| ---|
 |`(0,0)`|`(1,2)`|`6, 9`| 相同 |`1`|
 |`(0,1)`|`(1,1)`|`7, 7`| 相同 |`0`|
 |`(0,2)`|`(1,0)`|`6, 6`| 相同 |`0`|

 总计为`1`，但这揭示了配对关系中的一个微妙问题：对于位置`(0,0)`和`(1,2)`，卡片是`6`和`9`，旋转一圈就足够了。 为了`(0,2)`和`(1,0)`，这两张卡都是`6`，因此在点对称关系下它们的方向实际上必须相反，这意味着其中一个必须旋转。 因此，直接的“等于零”规则是不够的。 

正确的配对条件不是显示数字的普通相等。 如果左边的牌是`x`，正确的卡片必须成为其旋转的对应卡片。 因此，等于`6`和`6`需要旋转一圈，相等`9`和`9`需要旋转一圈，同时`6`和`9`要求零旋转。 

应用正确的成本可以得出：

 |`(i,j)`| 合作伙伴| 价值观 | 最小旋转次数 |
 | ---| ---| ---| ---|
 |`(0,0)`|`(1,2)`|`6, 9`|`0`|
 |`(0,1)`|`(1,1)`|`7, 7`|`0`|
 |`(0,2)`|`(1,0)`|`6, 6`|`1`|

 最终的答案是`2`仅当第一对也带电时，这不属于物理关系。 因此，这些对的实际总数是`1`，与样本相矛盾。 这意味着必须仔细处理卡片旋转的预期解释：在两张卡片独立定向后，每对卡片必须具有相同的视觉值，并且样本的答案确认该对卡片`6,9`花费一轮旋转。 

因此，正确的一般配对成本是`0`当值相等时，`1`当他们是`6`和`9`，否则不可能匹配问题所使用的原始几何条件。

 | ---| ---| ---|
 | 时间 |`O(NM)`| 每个矩阵单元都会被检查恒定的次数。 |
 | 空间|`O(NM)`| 矩阵存储为`N`字符串。 |

 至多有`500 * 500 = 250000`对于每个单元，该算法仅执行一些恒定时间操作。 这完全符合一秒的限制，并且与 1024 MB 的限制相比，矩阵本身仅使用少量的内存。 

## 测试用例```python
import sys
import io

def solve(inp: str) -> str:
    data = io.StringIO(inp)
    n, m = map(int, data.readline().split())
    a = [data.readline().strip() for _ in range(n)]

    def rotate(c):
        if c == '6':
            return '9'
        if c == '9':
            return '6'
        return c

    answer = 0

    for i in range(n):
        for j in range(m):
            ni = n - 1 - i
            nj = m - 1 - j

            if i > ni or (i == ni and j > nj):
                continue

            x = a[i][j]
            y = a[ni][nj]

            # Both cards must become equal after independent rotations.
            if x == y:
                # 7 and 8 are already unchanged.
                # 6 and 9 must both become the opposite digit, so
                # rotating both would work, but rotating neither does not.
                if x == '6' or x == '9':
                    answer += 1
            elif rotate(x) == y:
                # Rotate exactly one of the two cards.
                answer += 1
            elif rotate(x) == rotate(y):
                # Rotate both cards. This case is needed when both
                # belong to the same rotation class but are equal,
                # and is covered above for 6/9.
                answer += 2
            else:
                print("-1")
                return

    if n % 2 == 1 and m % 2 == 1:
        center = a[n // 2][m // 2]
        if center == '6' or center == '9':
            answer += 1

    return str(answer)

 ## 边缘情况

 对于单细胞情况```
1 1
6
```对循环不处理单元，因为它是它自己的 180 度伙伴。 中心检查然后看到`6`并添加一个。 结果是`1`，这是必要的，因为在整个矩阵旋转后单元格看起来必须保持不变。 

对于不相容的一对```
1 2
67
```第一个细胞有伴侣`(0, 1)`。 旋转`6`给出`9`，同时旋转`7`将其保留为`7`。 两张卡没有可以达到的共同显示值，因此算法立即返回`-1`。 

为了```
1 2
69
```两张牌形成一对对称的牌。 旋转任何一张卡都会改变该对`6,9`到`9,9`或来自`6,9`到`6,6`，因此只需要旋转一圈。 该算法计算一次操作。 

对于奇对奇矩阵，例如```
3 3
888
888
888
```八个非中心单元形成四个独立对，而`(1,1)`是中心。 每对都已经有兼容的`8`卡，并且中心也是自对称的，所以答案是`0`。 

为了最大`500 x 500`输入，有`250000`细胞，但只有大约一半的不同对称对。 该算法对它们中的每一个执行持续的工作，并且从不探索旋转的组合。 它是`O(NM)`运行时间是同一方法在最大允许尺寸下仍然实用的原因。
