 ## 解决方案
 ## 问题理解

 我们在同一组顶点上有两棵加权树，顶点标签为 (1) 到 (N)。 对于两个标签 (i) 和 (j)，它们的距离不是单独在任一树中测量的。 相反，我们将第一棵树中它们之间的路径长度添加到第二棵树中它们之间的路径长度。 对于每个顶点 (i)，我们需要与其他每个顶点 (j) 相比最小的总和。 

两棵树可以具有完全不同的形状和边权重。 第一棵树中靠近 (i) 的顶点可能在第二棵树中距离很远，因此在任一棵树中独立查找最近的顶点没有帮助。 答案是两棵树的乘积度量中的最近邻查询。 

最大的实例有 (250,000) 个顶点，每棵树有 (249,999) 个边。 在最坏的情况下，二次算法将检查大约 (N(N-1)/2)，即大约 (31) 十亿个顶点对。 这远远超出了 12 秒竞赛解决方案的实际范围。 官方的问题限制是 12 秒和 1024 MiB，因此 (O(N\log^2N)) 方法是合适的。 

还有两个重要的数字细节。 单个树距离可以大到大约 (2.5\cdot10^{14})，因此组合距离需要 C++ 中的 64 位算术。 Python 整数会自动处理这个问题。 另外，决不能使用 (j=i)。 由于它的距离为零，一不小心允许它就会立即使每个答案都为零。 

考虑最小的可能树：```
2
1 2 1000000000
1 2 1000000000
```唯一可能的其他顶点是另一个端点，因此正确的输出是```
2000000000
2000000000
```包含查询顶点本身的实现将错误地打印零。 

第二个有用的边缘情况是两棵树具有相同的简单形状并且所有权重都相等：```
3
1 2 1
2 3 1
1 2 1
2 3 1
```每个顶点在组合距离 (2) 处都有另一个顶点，所以答案是```
2
2
2
```这捕获了将一棵树中的距离与所需的两个距离之和混淆的实现。 

最后，树木根本不需要具有相似的形状。 例如，```
3
1 2 1
2 3 100
1 2 100
2 3 1
```具有相邻对之间的组合距离 (101) 以及顶点 (1) 和 (3) 之间的距离 (202)。 正确的输出是```
101
101
101
```这是一个有用的检查，可以防止意外地将第一棵树的几何形状重复用于第二棵树。 

## 方法

 直接解决方案很简单。 计算两棵树中每对 (i,j) 之间的距离，并最小化每个 (i) 的总和。 由于一棵树具有唯一的路径，因此可以对每棵树求根并在线性时间内获得来自一个源的所有距离，但从每个源执行此操作仍然需要花费 (O(N^2))。 同样，显式考虑每对执行 (N(N-1)/2) 次比较，当 (N=250,000) 时，达到约 (312.5) 亿对。 

蛮力是正确的，因为它直接评估被最小化的数量。 它的失败完全是计算性的。 我们需要利用这样一个事实：树中的距离可以围绕分隔符进行分解。 

有用的分隔符是质心分解。 删除质心会将树划分为大小最多为当前组件一半的组件。 重复此操作会生成对数高度的质心树。 这个标准的平衡属性正是让我们用一对质心祖先替换任意一对顶点的原因。 

为 (T_1) 和 (T_2) 独立构建质心分解。 对于顶点 (i) 和 (j)，令 (L_1) 为它们在 (T_1) 质心树中的最低公共祖先，令 (L_2) 为它们在 (T_2) 质心树中的最低公共祖先。 通过质心分解分离分量，(T_1)中(i)和(j)之间的原始路径经过(L_1)，同样，(T_2)中的路径经过(L_2)。 因此

 [d_1(L_1,i)+d_2(L_2,i)]
 +
 [d_1(L_1,j)+d_2(L_2,j)]。 
]

 这是关键的代数变换。 一旦 (L_1,L_2) 固定，(i) 和 (j) 的贡献就完全分离。 

还有一个尴尬的情况：(L_1) 和 (L_2) 必须是两个质心树 LCA。 我们可以删除这个条件。 对于固定的 (i,L_1,L_2)，考虑每个顶点 (j)，它只是第一个质心树中 (L_1) 的后代和第二个质心树中 (L_2) 的后代。 该集合比恰好具有这两个 LCA 的集合更大。 

对于任何这样的 (j)，

 [
 d_1(L_1,i)+d_1(L_1,j)\ge d_1(i,j)
 ]

 和

 [
 d_2(L_2,i)+d_2(L_2,j)\ge d_2(i,j)
 ]

 由三角不等式。 因此，放松候选者永远不会小于真实距离。 另一方面，真正的最近顶点 (j) 具有某个精确对 (L_1,L_2)，并且该对包含在宽松情况中。 因此，在所有宽松情况下取最小值仍然可以给出正确的答案。 

对于第二次分解中的固定质心（L_2），我们可以访问其质心子树中的每个顶点。 对于每个这样的顶点 (v)，我们在第一次分解中枚举 (v) 的所有质心祖先 (L_1)。 对于固定的 (L_1)，我们插入

 [
 d_1(L_1,v)+d_2(L_2,v)
 ]

 成二元最小结构。 我们只需要最小值和次小值，因为当查询顶点 (v) 时，最小值可能来自 (v) 本身，因此必须跳过。 

每个顶点在任一分解中都只有 (O(\log N)) 个质心祖先。 因此，嵌套枚举包含 (O(N\log^2N)) 组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N^2)) | (O(N)) | 太慢了 |
 | 最佳| (O(N\log^2N)) | (O(N\log N)) | 已接受 |

 ## 算法演练

1. 构建第一棵树的质心分解。 每当选择质心 (c) 时，遍历其当前组件并记录该组件中每个顶点 (v) 的 (d_1(c,v))。 由于 (c) 成为质心树中每个此类顶点的祖先，因此这为每个顶点提供了其质心祖先的列表以及它们的原始树距离。 
2. 也构建第二棵树的质心分解，但我们不需要存储它的距离列表。 在后面的处理过程中，每当选择一个质心（c）时，我们就可以遍历它的当前分量，并直接获得每个后代（v）的（d_2（c，v））。 
3. 将每个答案初始化为无穷大。 当处理第二棵树的质心(c=L_2)时，其当前分量正是第二质心树中(c)的子树。 因此，该组件中访问的每个顶点都是宽松条件 (L_2) 作为祖先的有效候选者。 
4. 对于每个访问过的顶点 (v)，从第一棵树迭代其存储的质心祖先 ((L_1,d_1(L_1,v)))。 对于每个 (L_1)，计算
 [
 x=d_1(L_1,v)+d_2(c,v)。 
]
 为每个 (L_1) 维护 (x) 的两个最小值，以及产生每个值的顶点。 
5. 插入当前第二棵树组件中的所有顶点后，再次迭代它们。 对于每个顶点 (v) 和每个第一树祖先 (L_1)，检索属于除 (v) 之外的顶点的最小存储值。 如果最小值是由 (v) 产生的，则使用第二小的值代替。 
6. 添加 (v) 本身的值：
 [
 d_1(L_1,v)+d_2(c,v)+
 \min_{j\ne v}
 [d_1(L_1,j)+d_2(c,j)]。 
]
 使用该候选更新 (v) 的全局答案。 这正是上面导出的松弛表达式。 
7. 将当前第二棵树质心标记为已删除，并独立继续处理每个剩余组件。 因为每个组件的大小至多是先前大小的一半，所以每个顶点仅参与 (O(\log N)) 质心级别。 
8. 打印每个顶点的最小值。 每当第一个最小值属于查询的顶点时，通过选择第二个最小值来排除自对。 

### 为什么它有效

 固定两个顶点 (i\ne j)，并令 (L_1,L_2) 为它们在两个质心分解中的最低公共祖先。 由于这些质心将 (i) 和 (j) 分开，因此原始树路径会穿过相应的质心。 因此它们的真实组合距离等于

 [
 d_1(L_1,i)+d_2(L_2,i)+d_1(L_1,j)+d_2(L_2,j)。 
]

 该算法考虑这对精确的祖先，因为两者都是 (i) 的祖先，并且 (j) 位于两个相应的质心子树中。 因此，真正的最佳方案是在考虑的候选者中。 

每个放松的候选人都有表格

 [
 d_1(L_1,i)+d_1(L_1,j)+d_2(L_2,i)+d_2(L_2,j)。 
]

 根据每棵树中的三角形不等式，这至少为 (d_1(i,j)+d_2(i,j))。 因此该算法永远不会产生低于实际最佳值的值。 由于也考虑了真正的最优对，因此算法产生的最小值正是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def get_component_centroid(adj, root, removed, parent, size):
    nodes = []
    stack = [root]
    parent[root] = -1

    while stack:
        u = stack.pop()
        nodes.append(u)
        pu = parent[u]

        for v, _ in adj[u]:
            if removed[v] or v == pu:
                continue
            parent[v] = u
            stack.append(v)

    for u in reversed(nodes):
        s = 1
        for v, _ in adj[u]:
            if removed[v]:
                continue
            if parent[v] == u:
                s += size[v]
        size[u] = s

    total = len(nodes)
    centroid = nodes[0]
    best_balance = total + 1

    for u in nodes:
        largest = total - size[u]

        for v, _ in adj[u]:
            if removed[v]:
                continue
            if parent[v] == u and size[v] > largest:
                largest = size[v]

        if largest < best_balance:
            best_balance = largest
            centroid = u

    return nodes, centroid

def build_ancestors(adj, n):
    removed = bytearray(n)
    parent = [-1] * n
    size = [0] * n
    ancestors = [[] for _ in range(n)]

    tasks = [0]

    while tasks:
        root = tasks.pop()

        _, centroid = get_component_centroid(
            adj, root, removed, parent, size
        )

        stack = [(centroid, -1, 0)]

        while stack:
            u, p, d = stack.pop()
            ancestors[u].append((centroid, d))

            for v, w in adj[u]:
                if removed[v] or v == p:
                    continue
                stack.append((v, u, d + w))

        removed[centroid] = 1

        for v, _ in adj[centroid]:
            if not removed[v]:
                tasks.append(v)

    return ancestors

def solve():
    input = sys.stdin.readline
    n = int(input())

    adj1 = [[] for _ in range(n)]
    adj2 = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        adj1[u].append((v, w))
        adj1[v].append((u, w))

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        adj2[u].append((v, w))
        adj2[v].append((u, w))

    ancestors = build_ancestors(adj1, n)

    removed = bytearray(n)
    parent = [-1] * n
    size = [0] * n

    best1 = [INF] * n
    best2 = [INF] * n
    id1 = [-1] * n
    id2 = [-1] * n
    seen = [0] * n
    token = 0

    ans = [INF] * n
    tasks = [0]

    while tasks:
        root = tasks.pop()

        _, centroid = get_component_centroid(
            adj2, root, removed, parent, size
        )

        nodes_dist = []
        stack = [(centroid, -1, 0)]

        while stack:
            u, p, d = stack.pop()
            nodes_dist.append((u, d))

            for v, w in adj2[u]:
                if removed[v] or v == p:
                    continue
                stack.append((v, u, d + w))

        token += 1

        for v, d2 in nodes_dist:
            for a, d1 in ancestors[v]:
                if seen[a] != token:
                    seen[a] = token
                    best1[a] = INF
                    best2[a] = INF
                    id1[a] = -1
                    id2[a] = -1

                value = d1 + d2

                if value < best1[a]:
                    best2[a] = best1[a]
                    id2[a] = id1[a]
                    best1[a] = value
                    id1[a] = v
                elif value < best2[a]:
                    best2[a] = value
                    id2[a] = v

        for v, d2 in nodes_dist:
            for a, d1 in ancestors[v]:
                if id1[a] == v:
                    other = best2[a]
                else:
                    other = best1[a]

                if other < INF:
                    candidate = d1 + d2 + other
                    if candidate < ans[v]:
                        ans[v] = candidate

        removed[centroid] = 1

        for v, _ in adj2[centroid]:
            if not removed[v]:
                tasks.append(v)

    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```第一个帮手，`get_component_centroid`，执行完全迭代遍历。 这避免了包含 (250,000) 个顶点的路径上的 Python 递归深度问题。 它首先记录当前组件和父关系，然后逆序计算子树大小，最后选择最大剩余块尽可能小的顶点。`build_ancestors`构造第一个质心分解。 原始加权边永远不会改变。 对于每个质心，遍历记录从该质心到其当前组件中每个顶点的实际加权距离。 这正是后面需要的信息，因此不需要显式地构造质心树本身。 

第二次分解是在第一次分解存储后进行的。 对于每个第二树质心，`nodes_dist`包含该质心子树中的每个顶点及其到质心的距离。 每个这样的顶点已经知道其所有第一树质心祖先，因此迭代两个列表会枚举每个所需的 ((L_1,L_2,v)) 组合。 

四个数组`best1`,`best2`,`id1`， 和`id2`代表每个 (L_1) 的两个最小值。 这`seen`数组提供延迟清除。 每次处理质心时，不会重置所有 (N) 个条目，而是仅初始化该组件中实际遇到的 (L_1) 个值。 

当前顶点的严格排除由存储的顶点 ID 来处理。 如果`id1[a] == v`，最小的候选者是自对，并且`best2[a]`必须使用。 如果第一个候选属于另一个顶点，则它立即有效。 

所有算术运算均使用 Python 整数执行。 在C++中，需要相应的实现`long long`，因为两棵树的距离之和可能超过 (2^{31}-1)。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(N\log^2N)) | 每个顶点在每个质心分解中都有 (O(\log N)) 个祖先，并且每个第二树质心级别处理相应的祖先组合。 |

 质心分解具有对数高度，因为每次移除留下的分量最多为当前分量的一半。 因此，每个顶点仅具有 (O(\log N)) 存储的祖先。 嵌套的第一树和第二树祖先枚举给出了预期解决方案描述的 (O(N\log^2N)) 运行时间。 

对于 (N=250,000)，这是问题的 12 秒和 1024 MiB 限制所需的渐近范围。 Python 实现使用迭代遍历，因为长树上的递归 DFS 会超出 Python 的递归限制。

 ## 边缘情况

 (N=2) 情况只有一对有效。 为了```
2
1 2 1000000000
1 2 1000000000
```第一个质心分解存储距离 (0) 和 (10^9) 处的两个顶点，第二个分解执行相同的操作。 当处理任一顶点时，第一个最小值属于该顶点本身，因此算法选择第二个最小值。 结果值为 (10^9+10^9=2,000,000,000)。 

当质心子树仅包含特定祖先对的一个顶点时，自对问题尤其明显。 那么二最小值结构只有一个有限值。 实施检查`INF`在更新答案之前，因此不存在的第二个顶点不能成为假候选者。 

等距离也处理得正确。 在四顶点单元星中，其他几个顶点的组合距离完全相同。 除了值之外，二最小值结构还存储顶点 ID，因此来自不同顶点的绑定值仍然是不同的候选值。 对于每个顶点，至少有一个其他顶点具有值 (2)，给出四个等于 (2) 的答案。 

大的边权重不会影响分解本身。 质心选择仅取决于组件大小，而在计算距质心的距离时，实际边权重保持不变。 这种分离很有用，因为结构分解和度量计算不会相互干扰。 

(250,000) 个顶点的路径是 Python 中递归 DFS 的最差形状，因为它的普通深度是 (250,000)。 该实现使用显式堆栈进行组件遍历、质心距离遍历和分解任务，因此即使在这种对抗形状上，其 Python 调用堆栈也保持恒定深度。 

两棵树也可能具有完全不相关的拓扑。 该算法从不假设一棵树中的质心对应于另一棵树中具有相同标签的质心。 它仅使用标签来识别两棵树上的同一点，而 (L_1) 和 (L_2) 是独立选择的。 这种独立性使得该方法适用于任意的加权树对。
