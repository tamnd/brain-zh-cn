 ## 解决方案
 ## 问题理解

 任务是找到将给定字符串反转所需的最小相邻交换次数。 交换只能交换两个相邻的字符，因此成本衡量字符必须在字符串中移动多远。 

输入包含字符串的长度和字符串本身。 输出是重新排列原始字符串所需的最小相邻交换次数，以便每个位置的字符与反转之前镜像位置的字符相匹配。 

长度可以大到 200000。尝试直接模拟交换的解决方案是不可能的，因为字符串可能需要二次移动。 尽管最终答案可能约为 n²，但算法执行的操作数量仍然需要保持接近线性。 这排除了重复搜索角色或一一移动角色的情况。 

主要的困难来自于重复的角色。 反转字符串时，字符没有唯一的目的地。 例如，在`aaaza`, 三个`a`中间的字符难以区分，选择错误的出现会增加交换次数。 

考虑输入：```
5
aaaza
```正确的输出是：```
2
```粗心的解决方案可能与第一个方案相匹配`a`从左侧第一个`a`来自反向目标并忽略相等字符的顺序。 这可以计算不必要的移动，因为相同的字符应该按照最小化交叉的顺序配对。 

另一个重要的情况是回文：```
6
cbaabc
```输出是：```
0
```仅检查字符是否与其镜像位置不同然后移动所有不匹配的解决方案可能会导致计数过高。 该字符串已经等于其反面。 

## 方法

 一种直接的方法是反复固定绳子的两端。 我们比较第一个和最后一个剩余字符。 如果它们相等，则两者都已处于正确的最终位置。 如果它们不同，我们在一侧搜索匹配的字符，并使用相邻的交换来移动它，直到两端变得正确。 这种方法是正确的，因为每个相邻的交换代表一个移动单位，并且所选角色必须以某种方式移动到其目的地。 

问题在于移动量。 在最坏的情况下，将字符从长度为 n 的字符串的一端移动到另一侧的成本为 O(n)，并且我们可能必须对 O(n) 个位置执行此操作。 总工作量变为 O(n²)，对于 n = 200000 来说太慢了。 

关键的观察是反向操作仅改变位置，而不改变字符数。 原始字符串中的每个字符在反向目标中都有匹配的出现。 我们可以计算角色必须移动的总距离，而不是物理模拟交换。 

如果我们创建字符在目标排列中占据的位置序列，那么答案就是该序列中的反转次数。 反转表示两个字符以错误的顺序出现，并且必须穿过相邻的交换位置。 这与合并排序计算反转对的原因相同。 

剩下的挑战是处理相同的字符。 我们需要知道字符的哪个出现移动到哪个目标位置。 最佳选择是从左到右将出现的事件配对。 对于每个字符，其在原始字符串中的第一次出现应与其在反转字符串中的第一次出现相匹配，其第二次出现应与其第二次出现相匹配，依此类推。 这避免了相同字符之间不必要的交叉。 

建立目标位置后，芬威克树可以计算当前位置之后有多少个已处理的位置。 这给出了 O(n log n) 的反转计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 存储原始字符串中每个字符的位置。 位置保持递增顺序，因为相等的字符应从左到右匹配。 
2. 查看反转的字符串。 对于此相反顺序中的每个字符，从原始字符串中获取该字符最早未出现的位置。 将原始位置记录在新数组中。 

生成的数组描述了反转字符串的字符在原始字符串中的来源。 如果这些位置已经增加，则字符串的顺序已经正确。 位置之间的每次减少都代表需要交叉的字符。 
3. 使用 Fenwick 树计算位置数组中的反转次数。 

当处理位置x时，前面大于x的位置的数量就是必须穿过该字符的字符数。 芬威克树存储到目前为止出现的位置数量，允许在对数时间内进行查询。 
4. 添加所有反演贡献并打印结果。 

为什么它有效：

 最终的反转字符串具有固定的字符顺序。 通过按照原始从左到右的顺序匹配相同的字符，我们选择了唯一的排列方式，可以避免相同字母之间不必要的交换。 剩下的问题只是这些匹配事件的排序。 以与目标相反的顺序出现的每一对事件必须交叉一次，并且每个相邻的交换恰好修复一次这样的交叉。 因此，最小交换次数正是映射位置的反转次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i > 0:
            res += self.bit[i]
            i -= i & -i
        return res

def solve():
    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, c in enumerate(s):
        pos[ord(c) - 97].append(i)

    used = [0] * 26
    order = []

    for c in reversed(s):
        x = ord(c) - 97
        order.append(pos[x][used[x]])
        used[x] += 1

    fw = Fenwick(n)
    ans = 0

    for i, x in enumerate(order):
        x += 1
        already = fw.sum(n) - fw.sum(x)
        ans += already
        fw.add(x, 1)

    print(ans)

if __name__ == "__main__":
    solve()
```位置列表存储每个字母的每次出现。 由于在扫描原始字符串时列表会自然排序，因此按顺序排列位置可以在相等的字符之间提供正确的配对。 

的建设`order`扫描所需的最终字符串，即向后扫描原始字符串。 每个字符都会接收该同一字符的下一个可用原始位置。 这`used`数组可防止同一事件被分配两次。 

Fenwick 树使用基于 1 的索引，因此每个存储位置在插入之前都会加一。 对于当前位置，表达式`fw.sum(n) - fw.sum(x)`计算之前的位置严格大于它。 这些正是早期的角色，他们站在错误的一边，必须越过它。 

答案存储在 Python 的整数类型中，这是必要的，因为最大交换次数约为 n²，远大于 32 位整数限制。

 ## 边缘情况

 对于`aaaza`，该算法将反向目标顺序构建为`azaaa`。 的出现情况`a`从左到右匹配，产生位置序列`[0, 3, 2, 1, 4]`。 芬威克树计算了由`z`位置错误，仅计算必要的反转后得出正确答案 2。 

为了`cbaabc`，反转后的字符串与原始字符串相同。 映射位置已经排序，因此反转计数保持为零。 该算法自然地处理回文，因为不需要交叉字符对。 

对于只包含一个重复字符的字符串，例如`aaaaa`，每个出现都可以与相应的出现匹配，而无需改变顺序。 映射的位置不断增加，因此答案为零。 这避免了计算实际上可互换的相同字符之间的交换的常见错误。
