 ## 解决方案
 # 问题理解

 该任务给出一个二进制字符串。 一项操作选择一个现有字符并将其删除。 删除后，由相同字符组成的最长前缀也会自动删除。 目标是以尽可能最好的方式选择删除，使得字符串变空之前的操作次数尽可能多。 原始问题陈述和约束来自 Codeforces Gym 102791H。 

字符串的长度可以达到 200000。对于这个大小，每次操作后实际修改字符串的模拟成本太高，因为从中间删除可能需要移动许多字符。 具有大约的二次解$n^2$工作量已经远远超出了 2 秒的限制。 我们需要在线性时间内处理字符串。 

困难的情况不是具有许多不同字符的字符串，而是每次删除后前缀结构都发生变化的字符串。 如果处理不当，单个长块可能会立即消失，而多个单字符块可用于创建额外的操作。 

例如，输入：```
2
11
```答案是：```
1
```粗心的方法可能会单独计算两个字符，但会删除一个`1`树叶`1`，并且自动前缀删除会在同一操作中删除剩余的字符。 

另一个重要案例是：```
6
101010
```答案是：```
3
```每次运行的长度都是一。 总是立即消耗下一次运行的贪婪解决方案可能会认为答案是运行次数，但操作只能删除一个选定的字符和一个前缀，因此六个单个字符被配对为三个有用的操作。 

最终的边界情况是：```
8
10101000
```答案是：```
4
```最后一个零块不能被简单地忽略。 当早期的单角色运行被删除时，它可以被部分消耗，从而创建额外的操作。 

## 方法

 直接的方法是模拟操作。 对于字符串的每个状态，尝试删除每个可能的字符，选择提供最大未来操作次数的移动，然后重复。 这是正确的，因为它探讨了所有法律选择，但完全不切实际。 即使存储一个字符串状态也会花费$O(n)$，并且跨多个状态的可能选择数量使得总工作量呈指数级增长。 即使是总是执行选定动作的简化模拟仍然需要频繁的中间删除，这可能会变得$O(n^2)$。 

关键的观察是只有连续的相等字符才重要。 我们可以将字符串压缩成串。 例如，`111010`变成长度`[3, 1, 1, 1]`。 

大于一的游程很有价值，因为它可以提供多个操作。 当这样的运行成为前缀时，从中删除一个字符允许自动删除以删除该运行的其余部分。 单字符运行则不同：它到达前面时就完全消失，因此应尽可能长时间保存。 

贪婪的想法是始终使用长运行作为额外删除的来源。 如果当前前程的长度大于 1，则消耗它。 如果前面的串是单个字符，则搜索后面的长串并从该串中取出一个字符。 这使得单字符前缀对于其他操作保持活动状态。 当没有长游程剩余时，剩余的单游程只能配对，直接给出剩余的操作数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将字符串压缩为游程长度。 连续的相等字符成为一串，因为只有它们的长度影响未来的操作。 
2. 保留两个指针。 左指针代表尚未完全删除的第一个运行。 右指针搜索下一个长度大于 1 的游程。 
3. 如果当前左游程的长度大于 1，则对其进行一次操作并移动左指针。 可以通过自动前缀删除来删除该运行，因此不需要触及其他运行。 
4. 如果当前左侧游程的长度为 1，则尝试查找长度大于 1 的后续游程。 从稍后的运行中删除一个字符并计算一次操作。 左侧的单字符运行仍可用于将来的操作。 
5. 如果不再存在长游程，则所有剩余游程的长度均为一。 每个操作可以删除两个这样的运行，因此添加剩余运行计数的上限除以二并完成。 

为什么它有效：

 不变的是每个操作都应该保留尽可能多的未来删除。 单字符前缀是最脆弱的资源，因为一旦它成为前缀，它就会完全消失。 长串是附加操作的唯一来源，因为从中删除一个字符仍然会留下一个可以删除的前缀。 贪心算法总是在丢失之前花费较长的运行时间并延迟单字符的运行，因此不会浪费任何操作机会。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    runs = []
    cnt = 1
    for i in range(1, n):
        if s[i] == s[i - 1]:
            cnt += 1
        else:
            runs.append(cnt)
            cnt = 1
    runs.append(cnt)

    m = len(runs)
    ans = 0
    l = 0
    r = 0

    while l < m:
        if l > r:
            r = l

        if runs[l] > 1:
            ans += 1
            l += 1
        else:
            while r < m and runs[r] == 1:
                r += 1

            if r < m:
                runs[r] -= 1
                ans += 1
                l += 1
            else:
                ans += (m - l + 1) // 2
                break

    print(ans)

if __name__ == "__main__":
    solve()
```第一部分构建游程长度表示。 这消除了维护实际字符串的需要，因为字符的确切位置不再重要。 

主循环遵循演练中的贪婪决策。 左指针仅向前移动，因为删除的运行永远不会返回。 右侧指针也仅在寻找有用的长期运行时向前移动，从而给出线性总功。 

减量`runs[r] -= 1`是微妙的。 我们不会删除整个运行。 我们仅使用其中的一个字符来创建一项操作，而将其余部分留到以后使用。 忘记这一点会使算法变成错误的策略，即删除运行速度太快。 

最终的表达`(m - l + 1) // 2`处理剩余的单字符运行。 由于每个操作最多可以删除两个这样的运行，因此这是它们可以贡献的最大操作数。

 ## 边缘情况

 对于`2\n11\n`，压缩后的形式为`[2]`。 该算法立即看到长时间运行，计算一次操作，然后完成。 它不会将运行拆分为多个操作，因为自动前缀删除会立即删除剩余的字符。 

为了`6\n101010\n`，压缩形式包含六个单次运行。 没有长运行可供使用，因此算法直接跳转到最终的配对规则。 六个单次运行产生三个操作。 

为了`8\n10101000\n`，运行次数是`[1,1,1,1,1,1,2]`。 不应立即删除前六个单次运行。 该算法反复从最后的长串中借用一个字符，逐渐减少它，同时保留前面的单字符。 长跑耗尽后，剩余的单打被配对，产生四次操作。
