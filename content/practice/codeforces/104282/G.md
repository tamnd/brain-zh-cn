 ## 解决方案
 ## 问题理解

 我们得到了一系列多米诺骨牌。 每张卡都有两个值，正面值和背面值。 从全套牌中，我们首先精确地选出K张牌。 第一次选择的分数是选择的 K 张牌的前面值的总和。 

修复完这K张牌后，我们可以在其中选择L张牌并计算一个附加分数，即它们的后值之和。 最终得分是前 K 个值加上后 L 个值的总和，我们希望最大化这个总和。 

关键的约束是第二次选择仅限于已经选择的 K 张牌，因此决定实际上是要包括哪些 K 张牌以及这 K 张牌中的哪一张应该贡献其后值。 

输入大小达到 n = 100000，这会立即排除任何尝试所有子集甚至大小 K 的所有组合的解决方案。任何比大约 O(n log n) 或 O(n √n) 更差的方法都会太慢。 基于排序的策略或数据结构的贪婪选择是唯一现实的路径。 

当幼稚的策略独立对待这两个选择时，就会出现微妙的失败案例。 例如，如果尝试选择前 K 个前值，然后从中独立地选择前 L 个后值，则这可能会失败，因为最佳后值可能属于在前选择中不是最佳的卡。 

一个具体的例子：

 n = 3

 A = [100, 1, 1]

 B = [1, 100, 100]

 K = 2，L = 1

 如果我们按 A 选择前 2 张，我们会拿牌 (100,1) 和 (1,100)，前面的总和为 101。其中最好的后面是 100，所以总数为 201。 

但最佳解决方案是选择牌 (1,100) 和 (1,100)，但这是不可能的，因为 K=2 并且只有一对这样的存在，因此我们必须仔细平衡选择。 

这表明正面和背面的价值在包容性方面存在竞争，并且该结构将两个决策结合在一起。 

## 方法

 蛮力的想法是选择大小为 K 的每个子集，并为每个子集选择最好的 L 个元素进行反求和。 这是正确的，因为它直接评估问题的定义。 然而，子集的数量是$\binom{n}{K}$，即使对于中等的 n 来说，这也是一个天文数字，使得这完全不可行。 

关键的观察是第二步始终是“在选定的 K 组中选择 L 个最佳后卫”。 这表明对于任何固定的 K 集合，其贡献可以被视为两个组成部分：集合中所有 A 值的总和，加上其中最大的 L B 值的总和。 困难在于，选择最优的 K 集同时取决于 A 和 B。 

我们可以通过猜测第二阶段会使用哪些牌来重新解释这个问题。 假设我们以某种方式知道 L 卡的集合 S 将贡献其后值。 这些 L 卡必须是最终 K 选择的一部分，对于他们，我们在某种意义上已经承诺使用 B 而不是 A，因为他们的贡献被固定为 B。 

现在考虑剩余的 K − L 个槽。 对于这些，每张选定的卡仅贡献其 A 值。 对于L特殊卡，我们实际上得到A加上B而不是A的额外奖励，但如果我们仔细区分贡献，这种观点会更容易。 

一个更清晰的转换是考虑从所有贡献 A 的卡开始，然后将一些选定的卡从 A 升级到 B。如果我们选择一组 K 卡，则基本贡献是 A 与这些 K 卡的总和。 其中，选择L卡贡献B而不是A，将为这些L卡带来(B − A)的额外收益。 所以问题就变成选择K张牌，并在其中选择L个增益最大（B − A）的物品。 

这导致了一个经典的结构：我们想要 K 个元素最大化基础 A 加上 L 额外奖励。 

我们可以通过对候选进行排序并使用堆来维护 K 池的最佳选择，同时跟踪最佳的 L 改进来处理此问题。

 标准的解决方案是按照 A 降序对卡片进行排序，逐步构建候选集。 在迭代时，我们维护一个结构，跟踪所选 K 中哪些 L 项提供最佳 (B − A) 增益。 我们为这些增益维护一个最小堆，以便始终保持前 L 个改进。 

当我们添加一个新项目时，它会立即贡献 A。 那么它的潜在升级值为(B−A)，有可能进入前L个改进。 如果是这样，它将取代当前最小的改进，并相应地调整基本总数。 

我们跟踪所有前缀中的最佳可能配置，其中至少考虑了 K 项。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^K) | O(n^K) | O(K) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每张卡转换为一对（A[i]，gain[i]），其中gain[i] = B[i] − A[i]。 

我们按照 A 的降序处理卡片，确保我们始终首先考虑强大的正面贡献。 

1. 将所有卡片按 A 降序排列。 这确保了当我们考虑前缀时，我们始终使用最佳的可用基础贡献。 
2. 维护当前候选池中所有卡的 A 值的运行总和。 如果我们选择所有这些，这代表基本分数。 
3. 维护一个最小堆，存储所选卡牌的增益值，代表当前选择从 A 切换到 B 的 L 张卡。堆大小最多为 L。 
4. 按排序顺序遍历卡片，将每张卡片添加到候选池中。 如果它是迄今为止看到的最好的 L 增益之一，则将其 A 添加到运行总和中并将其增益推入堆中。 
5. 如果堆大小超过L，则移除最小增益。 这确保我们始终保持最好的 L 升级。 
6. 一旦我们考虑了至少 K 张卡，将当前分数计算为：

 总和 + 堆中收益的总和。 
7. 跟踪所有前缀的最大值。

这样做的原因是，K 张卡的任何最佳选择都可以表示为按 A 排序的前缀，并结合选择其中的 L 个最佳增益升级。 如果选择 A 较小的卡而排除 A 较大的卡，则交换它们永远不会减少基本总和，也不会以改善结果的方式减少可用的增益选择。 这个交换参数确保我们可以将注意力限制在前缀结构上，而不会失去最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))
    K, L = map(int, input().split())

    cards = []
    for i in range(n):
        cards.append((A[i], B[i]))

    cards.sort(reverse=True)

    base_sum = 0
    gain_sum = 0
    heap = []

    ans = 0

    for i, (a, b) in enumerate(cards):
        base_sum += a
        gain = b - a

        heapq.heappush(heap, gain)
        gain_sum += gain

        if len(heap) > L:
            gain_sum -= heapq.heappop(heap)

        if i + 1 >= K:
            ans = max(ans, base_sum + gain_sum)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先按 A 的降序对卡片进行排序，这是启用前缀推理的结构决策。 如果我们将所有已处理的卡片作为 K 集的一部分，则变量 base_sum 会跟踪总贡献。 堆保持最佳的 L 升级，以增益 (B − A) 的形式实现。 每次添加新卡时，我们都会乐观地将其包含在增益结构中，然后如果超过 L，则删除最差的卡，只保留最好的改进。 

支票`i + 1 >= K`确保我们仅评估前缀中至少存在 K 张卡的配置，因为需要选择 K 张卡。

 ## 边缘情况

 当 L 等于 0 时，会出现一种边缘情况。 在这种情况下，问题简化为简单地选择 K 个最大 A 值。 该算法很自然地处理这个问题，因为堆始终保持为空，因此 Gain_sum 为零，答案变为最大 K A 值的总和。 

当 K 等于 N 时，会出现另一种边缘情况。此时必须选择所有卡，唯一的自由是选择 L 个最佳收益。 该算法处理整个数组，堆正确收集顶部 L (B − A) 值，无需任何特殊的套管即可产生最佳结果。 

第三种情况是当所有增益均为负时，这意味着 B 始终小于 A。堆仍将存储危害最小的增益，但算法实际上更喜欢较大的 A 值，并通过选择最小负升级来最小化损失，匹配最佳权衡。
