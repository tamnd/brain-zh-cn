 ## 解决方案
 ## 问题理解

 我们有一个固定的单词替换词典。 每条规则都规定特定单词应始终由另一个固定单词替换。 阅读完所有规则后，我们会得到一系列单词，这些单词构成 BSQ 所说的句子。 该句子中的每个单词都保证在一个替换规则中恰好​​出现在左侧，因此每个单词恰好映射到一个输出单词。 

任务是通过使用给定规则独立替换每个单词并打印结果序列来转换句子。 

约束很小，规则数量和句子中的单词数量最多为 100，每个单词长度最多为 10。这立即告诉我们，任何输入大小至少为线性或二次的解决方案都足够快。 即使直接扫描每个单词的所有规则也最多只能执行 10,000 次字符串比较，这是微不足道的。 

不存在隐藏的结构复杂性，例如链接转换或多步重写； 使用提供的映射将每个单词精确替换一次。 

一些边缘情况仍然值得明确：

 幼稚的实现可能会错误地假设替换是迭代的。 例如，如果一个规则说“a → b”，另一个规则说“b → c”，则错误的解决方案可能会重复应用规则并将“a”变成“c”。 然而，该问题从不要求传递闭包。 只需要直接替换即可。 

另一个潜在的陷阱是忘记单词是用空格分隔的标记。 如果尝试将输入作为原始字符串进行处理并替换子字符串，则意外的部分匹配可能会损坏结果。 例如，在基于子字符串的方法中替换“wow”内的“wo”将是不正确的，尽管基于标记的处理完全避免了这种情况。 

## 方法

 解决该问题的直接方法是将规则解释为查找过程。 对于句子中的每个单词，我们扫描所有规则，直到找到左侧与该单词匹配的规则，然后输出其对应的右侧。 

这种暴力方法是正确的，因为规则形成了一个简单的关联列表。 然而，它的成本与句子单词数乘以规则数成正比。 在最坏的情况下，这会导致 100 × 100 = 10,000 次字符串比较，这在这里仍然可以接受，但如果约束扩大，就会变得浪费。 

关键的观察是我们在静态数据集中重复搜索相同的键。 这正是哈希图的设计目的。 通过预先计算从每个源单词到其替换的字典，我们将每个查询的平均查找时间减少到 O(1)。 这将问题从重复线性扫描转变为直接映射问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描| O(纳米) | O(n) | 已接受但没有必要 |
 | 哈希映射查找 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 我们首先构建一个存储每个规则的映射结构。 每个键都是一个源单词，每个值都是其替换单词。 

1. 读取整数n和m，它们定义了有多少个映射规则以及句子中出现了多少个单词。 
2. 初始化一个空字典。 
3. 对于 n 个规则中的每一个，读取对 (si, ti) 并将其存储在字典中为 si → ti。 此步骤确保稍后的恒定时间查找。 
4. 读出句子的 m 个单词。 
5. 对于句子中的每个单词，从字典中检索其映射值并将其附加到输出序列中。 
6. 按顺序打印所有转换后的单词，并用空格分隔。 

我们可以安全地依赖直接查找的原因是，该问题保证每个输入单词都作为映射中的键出现，因此不需要丢失键处理。 

### 为什么它有效

该算法构建了一个在输入单词集上定义的函数 f，其中每个单词恰好有一个图像。 由于该问题保证了左侧的总覆盖率和唯一性，因此 f 是一个明确定义的映射。 输出句子只是 f 到输入序列中每个标记的逐点应用。 由于没有规则依赖于先前的替换，因此每个转换都是独立的且保序的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    mp = {}

    for _ in range(n):
        s, t = input().split()
        mp[s] = t

    words = input().split()
    res = []

    for w in words:
        res.append(mp[w])

    print(" ".join(res))

if __name__ == "__main__":
    main()
```解决方案从构建字典开始`mp`存储所有替换规则。 每个输入对都是直接插入的，覆盖不是问题，因为这个问题保证了所有`si`是不同的。 

然后使用以下命令将句子读取为标记列表`split()`，确保我们将单词视为原子单元而不是子串。 每个单词都通过字典查找进行翻译并附加到结果列表中。 最后，输出与空格连接以重建转换后的句子。 

一个微妙但重要的细节是避免在输出构造期间重复字符串连接。 使用列表和`" ".join()`确保线性时间行为，而不是重复字符串追加带来的二次增长。

 ## 边缘情况

 一种微妙的情况是同一个单词在句子中重复出现。 例如：```
2 3
a x
b y
a a b
```该算法独立处理每个令牌。 第一个“a”变成“x”，第二个“a”再次变成“x”，“b”变成“y”。 由于字典查找不依赖于位置或历史记录，因此重复不会造成问题。 

另一种情况是确保我们永远不会尝试部分替换。 因为我们使用空格分割句子，所以每个标记都会被原子处理。 即使单词共享前缀，例如“ab”和“a”，它们在字典中也是不同的键，不会混淆。 

最后，由于保证每个输入单词都存在于映射中，因此不需要回退处理。 直接字典访问始终有效，并且在问题约束下不需要考虑 KeyError 情况。
