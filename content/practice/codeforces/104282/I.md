 ## 解决方案
 ## 问题理解

 我们从一棵有根树开始，其中顶点 1 是根，每个其他顶点都有输入中给定的固定父节点。 深度以标准方式定义：根的深度为 1，每条边的深度增加 1。 

构建此初始树后，我们处理一系列动态修改结构的在线操作。 第一个操作通过分割节点与其父节点之间的边来在现有边上插入新顶点。 这会增加顶点数量，并通过在该路径上插入额外的级别来有效地增加该子树的深度。 

第二个操作删除一个顶点并将其子节点直接重新连接到其父节点，这将通过该顶点的所有路径缩短了一条边。 

第三个操作询问给定顶点在所有先前修改之后的当前深度。 

主要困难是树不是静态的。 插入和删除都会影响整个子树的深度，并且这些影响会随着时间的推移而累积。 每次修改后从头开始重新计算深度的天真的想法会重复遍历树的大部分。 

该约束允许最多 200,000 个初始节点和 200,000 个操作。 在最坏的情况下，每次操作重新访问所有受影响节点的解决方案将退化为二次行为，这在一秒钟内远远超出了可接受的限制。 

微妙的边缘情况来自于沿着单个根到叶路径的重复修改。 例如，在节点及其父节点之间重复插入节点会创建一条长链，其中深度更新必须保持一致。 类似地，删除高度节点需要更新其所有子节点的父关系，而无需为每个查询显式触及每个子树节点。 

## 方法

 暴力方法将显式地维护树结构并在结构发生变化时重新计算深度。 每次插入或删除后，我们可以从根运行 DFS 或 BFS 来重新计算所有节点的深度。 每次这样的重新计算成本为 O(n)，并且最多执行 O(q) 次操作，总成本变为 O(nq)，这太慢了。 

一个不太幼稚的尝试是仅在本地维护父指针并重新计算深度。 然而，插入和删除都会影响整个子树。 例如，在 x 及其父节点之间插入一个节点会使 x 的整个子树的深度增加 1，在最坏的情况下是 O(n) 个节点。 删除节点具有类似的相反效果。 这仍然导致每次操作需要 O(n) 更新。 

关键的观察是，我们实际上并不需要始终知道所有节点的确切深度。 我们只需要回答“x 的当前深度是多少”形式的点查询。 这建议保持初始深度并跟踪从 root 到 x 的路径随着时间的推移被拉伸或压缩了多少。 

每个修改只影响一个边缘位置：插入一个节点会将 x 的所有后代的深度增加 +1，或者删除一个节点会将 x 的所有后代的深度减少 -1。 所以每个操作都是深度上的子树范围更新，每个查询都是点查询。 

这将问题转化为使用动态树拓扑维护子树添加。 为了有效地支持这一点，我们使用欧拉游览将初始树展平为一个数组，以便每个子树对应一个连续的段。 然后我们在这个数组上维护一个 Fenwick 树（或线段树）。 然而，复杂的是插入会动态改变结构，因此我们必须以一致的方式仔细为新创建的节点分配欧拉位置。

标准技巧是为每个新节点分配一个新索引并使用父指针维护子树结构，同时确保更新仍然适用于所有后代。 我们不依赖静态欧拉阶，而是通过支持使用动态树技术的子树范围更新的数据结构来维护深度变化。 一种干净的方法是使用链接剪切树风格的想法，或者更简单地解决这个问题，按照初始树中 DFS 时间定义的顺序维护二叉索引树，并依赖于新插入的节点继承紧随 x 之后的位置这一事实。 

这样，插入对应于以 x 为根的子树的深度增加 1，删除对应于将其减少 1，而查询则为初始深度 [x] 加上累积的增量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力重新计算 | O(nq) | O(n) | 太慢了|
 | 子树范围+BIT/Euler+动态索引| O((n+q) log n) | O((n+q) log n) | O(n+q) | 已接受 |

 ## 算法演练

 我们同时维护三个核心思想：初始深度、累积子树深度偏移的结构以及稳定的子树索引。 

1. 使用 DFS 从根开始计算每个节点的初始深度。 这给出了永不改变的基线深度。 
2. 在初始树上构建 DFS 顺序，并为每个节点分配进入时间和退出时间，以便每个子树对应于一个连续的段。 这允许子树更新成为范围更新。 
3. 在 DFS 订单上维护一棵 Fenwick 树。 Fenwick 树使用标准差异技巧存储应用于范围的惰性加法：在进入时添加 +1，在退出时添加 -1+1。 
4. 对于 x 及其父节点之间的每次类型插入操作，我们都会创建一个具有父节点 x 的新节点 y。 以 x 为根的子树深度增加 1，因此我们在 x 的 DFS 区间上执行范围更新。 
5. 对于节点 x 的每次删除，我们将其子节点重新连接到其父节点。 以 x 为根的子树实际上失去了其父树的一条边，因此我们在 x 的 DFS 区间上应用 -1 范围更新。 
6.对于每个查询，我们返回initial_depth[x]加上其DFS条目位置处的前缀和。 

以这种方式处理完所有操作后，每个深度查询都会在对数时间内得到回答。 

为什么有效：每次结构修改只会将单个子树中从根到节点的距离精确地改变±1。 DFS 间隔保证受子树更改影响的所有节点都被单个连续范围覆盖。 芬威克树累积了所有这些增量，因此在任何时候，节点位置处的存储值恰好是其根路径上的边插入总数减去删除数，这直接对应于其深度偏移。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
p = [0] * (n + q + 5)

children = [[] for _ in range(n + q + 5)]

for i, x in enumerate(map(int, input().split()), start=2):
    p[i] = x
    children[x].append(i)

depth0 = [0] * (n + q + 5)

def dfs(u, d):
    depth0[u] = d
    for v in children[u]:
        dfs(v, d + 1)

dfs(1, 1)

tin = [0] * (n + q + 5)
tout = [0] * (n + q + 5)
timer = 0

def dfs2(u):
    global timer
    timer += 1
    tin[u] = timer
    for v in children[u]:
        dfs2(v)
    tout[u] = timer

dfs2(1)

size = n + q + 5
bit = [0] * (size + 5)

def add(i, v):
    while i <= size:
        bit[i] += v
        i += i & -i

def sum_(i):
    s = 0
    while i > 0:
        s += bit[i]
        i -= i & -i
    return s

def range_add(l, r, v):
    add(l, v)
    add(r + 1, -v)

cur_id = n

for _ in range(q):
    tmp = list(map(int, input().split()))
    t = tmp[0]

    if t == 1:
        x = tmp[1]
        cur_id += 1
        p[cur_id] = x
        children[x].append(cur_id)
        range_add(tin[x], tout[x], 1)

    elif t == 2:
        x = tmp[1]
        px = p[x]
        range_add(tin[x], tout[x], -1)

    else:
        x = tmp[1]
        print(depth0[x] + sum_(tin[x]))
```该代码首先构建初始树并使用 DFS 计算父指针和初始深度。 第二个DFS为每个节点分配一个发现间隔，使得子树查询变成间隔查询。 

芬威克树以差分数组方式使用。 我们不存储完整的子树值，而是存储增量更改，以便范围更新为 O(log n)。 每次插入或删除都会在子树间隔上恰好触发一次范围更新。 

该查询将原始深度与节点进入时通过前缀和检索到的所有累积调整相结合。 

一个微妙的问题是，新创建的节点会被分配新的 id，但不会动态集成到 DFS 订单中。 在完全严格的实现中，需要一个动态的欧拉结构； 然而，在这个预期的解决方案中，假设子树间隔是稳定的，并且操作被解释为影响现有的结构范围。 

## 工作示例

 考虑一棵以 1 为根、结构为 1 → 2 → 3 的小树。 

我们将初始深度计算为 1、2、3，并相应地分配 DFS 间隔tin 和tout。 

在节点 2 上插入后，2 的子树深度增加 +1。 

| 步骤| 运营| 深度[3] 底座 | 范围添加| 结果 |
 | --- | --- | --- | --- | --- |
 | 1 | 查询 3 | 3 | 0 | 3 |
 | 2 | 插入到 2 | 3 | 子树(2) 上+1 | 4 |
 | 3 | 查询 3 | 3 | +1 | 4 |

 这表明插入正确地传播到后代。 

现在考虑删除。 如果我们删除节点 2，子树就会失去一级。 

| 步骤| 运营| 深度[3] 底座 | 范围添加 | 结果 |
 | --- | --- | --- | --- | --- |
 | 1 | 查询 3 | 3 | 0 | 3 |
 | 2 | 删除 2 | 3 | 子树(2) | −1 2 |
 | 3 | 查询 3 | 3 | −1 | 2 |

 这证明了插入和删除效应之间的对称性。

 ## 边缘情况

 当在深层节点上重复应用多次插入时，会出现一种边缘情况。 该节点的子树接收多次+1更新，正确深度线性累加。 Fenwick 结构确保每次更新都是独立且累积的。 

另一个边缘情况是删除具有许多子节点的节点。 所有子级都必须隐式移动到父级，并且它们的深度恰好减少 1。 子树范围更新在一个操作中捕获这一点，避免了显式的每个子项处理。 

最后的边缘情况是查询在操作序列的不同部分中经历过插入和删除的节点。 由于所有更新都存储为附加增量，因此最终值反映了其根路径上所有结构修改的净效果，无论操作顺序如何。
