 ## 解决方案
 ## 问题理解

 我们在飞机上得到了一组敌人的位置，所有这些位置都是相对于我们的角色所在的原点进行测量的。 角色可以旋转武器并选择方向，每当攻击时，都会消灭从该方向开始的固定 45 度角扇区内的所有敌人。 该扇区锚定在原点，因此唯一的自由度是我们如何旋转该楔形。 

任务是选择这个 45 度楔子的方向，使其内部的敌人数量最大化。 

键输入最多 100,000 个点，坐标范围为 -10⁴ 到 10⁴。 这立即排除了任何试图测试由成对或三重点定义的每个可能的楔形方向的解决方案，因为每个候选方向的简单角度比较将导致二次或更糟糕的行为。 

边界行为出现了一个微妙的问题。 必须计算正好位于形成 45 度楔形的两条射线上的点。 这很重要，因为任何角度公式都必须仔细处理相等性，否则边界上的点可能会丢失或根据浮点比较进行重复计算。 另一个边缘情况是垂直和水平方向，由于除以零或精度不稳定，简单的斜率计算失败。 

一个小例子说明了边界敏感性。 如果我们有点 (1, 2)、(2, 1) 和 (1, 1)，并且沿着 y = x 线正确定向，则 45 度的最佳楔形可以包括所有三个点。 依赖浮点角度的简单方法可能会由于精度误差而排除边界对齐的点。 

## 方法

 一种强力的想法是将每个敌方点视为楔形边界射线的候选方向。 对于每个这样的方向，我们可以扫过另一条 45 度的边界射线，并计算中间有多少个点。 对于每个固定方向，检查所有点需要 O(n)，尝试所有 n 个方向会导致 O(n²)，最坏情况下大约需要 10^10 次操作，并且不会在时间限制内运行。 

关键的观察是，一旦我们改变坐标，几何形状就会变得简单。 在平面中对齐的 45 度楔形对应于涉及坐标差异的情况。 如果我们将平面旋转 45 度，楔形就会在变换后的坐标系中变成轴对齐的间隔约束。 

具体来说，定义变换后的坐标：

 u = x + y 且 v = x − y。 

原始平面中的 45 度角扇区对应​​于选择 u 值位于与楔形方向成比例的长度区间内的点，同时尊重 v 中的排序或等效地处理单调对齐。 变换后，问题简化为在排序的角度表示上或等效地在排序的方向角上找到滑动窗口可以覆盖的最大数量的点。 

更稳健的解释完全避免了三角学：每个点定义一个角度 θ = atan2(y, x)。 楔形问题变为：找到角度位于长度为 π/4 的区间内的点的最大数量。 我们对所有角度进行排序，并在圆形数组上使用两指针扫描（通过添加 2π 来复制角度）。 这将问题转化为固定角度窗口中的经典最大点问题。 

扫描之所以有效，是因为一旦对角度进行排序，扩展窗口直到超过 π/4，然后缩小窗口即可在所有端点上保持线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 角度排序+两个指针| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们通过将几何方向转换为一维角度排序来解决该问题。

1. 使用atan2(y, x) 计算每个点的角度。 这给出了 (−π, π] 范围内的值。此步骤将几何方向转换为可排序的标量，这很重要，因为角度包含变成了区间包含。
 2. 将角度标准化为一致的范围，通常为 [0, 2π)，以便可以干净地处理圆形环绕。 
3. 按升序对所有角度进行排序。 需要进行排序，以便该列表中的任何连续段对应于角度空间中的连续扫描。 
4. 通过将每个角度加上 2π 来扩展数组。 这种重复使我们能够处理环绕间隔，而无需进行模块化算术复杂化。 
5.使用两指针滑动窗口。 保持向右扩展的指针，同时角度[r]和角度[l]之间的角度差最多为 π/4。 这确保了窗口中的所有点在楔形约束下都是有效的。 
6. 对于每个左指针位置，计算最大有效右扩展并用 r − l + 1 更新答案。然后向前移动左指针并继续。 
7. 返回找到的最大窗口大小。 

我们可以安全地使用滑动窗口的原因是，排序后，扩展右指针只会增加角度跨度。 一旦跨度超过 π/4，除非我们移动左指针，否则它对于固定的左端点将不再有效。 

### 为什么它有效

 正确性依赖于以下事实：任何有效的楔形都精确对应于长度最多为 π/4 的角度区间。 每个这样的区间都可以用等于其中最小角度的起始角度来表示。 对于该起始角度，最佳解决方案是前方 π/4 内最大的连续点块。 由于排序保留了角度顺序，因此每个有效子集在已排序的双倍数组中显示为连续段，并且两指针扫描隐式枚举所有此类段。 

## Python 解决方案```python
import sys
import math
input = sys.stdin.readline

def solve():
    n = int(input())
    angles = []
    
    for _ in range(n):
        x, y = map(int, input().split())
        ang = math.atan2(y, x)
        if ang < 0:
            ang += 2 * math.pi
        angles.append(ang)
    
    angles.sort()
    
    # duplicate for circular wrap
    extended = angles + [a + 2 * math.pi for a in angles]
    
    ans = 0
    r = 0
    window = math.pi / 4
    
    for l in range(n):
        while r < len(extended) and extended[r] - extended[l] <= window + 1e-12:
            r += 1
        ans = max(ans, r - l)
    
    print(ans)

if __name__ == "__main__":
    solve()
```实现的核心是使用atan2转换为角度，这避免了所有基于斜率的不稳定性。 标准化步骤确保所有角度在单个圆形刻度上都具有可比性。 阵列的复制允许在没有特殊情况的情况下处理环绕窗口，例如接近 350 度的角度与接近 10 度的角度组合。 

双指针逻辑小心地维护单调右指针，因此每个元素最多被处理两次，一次作为左边界，一次作为右边界。 

当点正好位于 45 度扇区的边界上时，比较中的小 epsilon 避免了浮点精度问题。 

## 工作示例

 考虑点 (1, 2)、(2, 1) 和 (1, 1)。 

转换成角度后：

 | 点| 角度（大约）|
 | --- | --- |
 | (1,2) | 1.107 | 1.107
 | (2,1) | 0.464 | 0.464
 | (1,1) | 0.785 | 0.785

 排序后的角度变为 [0.464, 0.785, 1.107]。 我们将它们复制为 [0.464, 0.785, 1.107, 6.747, 7.068, 7.389]。 

我们现在滑动一个大小为 π/4 ≈ 0.785 的窗口。 

| 我| r | 角度[l] | 角度[r-1] | 跨度| 窗户尺寸|
 | --- | --- | --- | --- | --- | --- |
 | 0 | 3 | 0.464 | 0.464 1.107 | 1.107 0.643 | 0.643 3 |
 | 1 | 3 | 0.785 | 0.785 1.107 | 1.107 0.322 | 0.322 2 |
 | 2 | 3 | 1.107 | 1.107 1.107 | 1.107 0 | 1 |

 最大值为 3，这意味着所有点都可以被 45 度的楔形覆盖。 

该迹线表明，一旦点在角度空间中排序，最佳楔就会对应于连续的线段，并且滑动窗口会正确捕获它。 

第二个示例具有广泛分离的点，例如 (1,0)、(0,1)、(-1,0)、(0,-1)，表明没有三个点落在任何 π/4 区间内，并且窗口正确地在 1 处达到峰值。

 ## 边缘情况

 非常接近 45 度扇区边界的点测试浮点稳健性。 例如，(1, 100) 和 (100, 1) 等点产生的角度非常接近 π/4 边界。 该算法通过比较中的小 epsilon 来处理此问题，确保边界包含的一致性。 

诸如接近 0 和接近 2π 的角度等环绕情况通过复制数组来处理。 如果没有重复，跨越 0 角的楔形将错误地显示为分裂成两个不相连的段。 扩展数组将这些情况合并到一个连续的窗口中，滑动指针自然地将它们拾取为有效间隔的一部分。
