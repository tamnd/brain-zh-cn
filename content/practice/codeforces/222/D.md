 ## 解决方案
 ## 问题理解

 我们得到了两组分数。 

大批`a`包含第一次巡回赛获得的分数，以及数组`b`包含第二次巡回赛中获得的分数。 两个数组之间的对应关系已经丢失，因此我们不知道哪个第一轮得分属于哪个第二轮得分。 

每个参与者在每个数组中只出现一次，因此真正的最终排名来自于之间的完美匹配`a`和`b`。 参与者的最终分数是两个匹配值的总和。 

关于 Vasya 的唯一信息是他的最终分数至少为`x`。 

我们必须在所有与数据一致的匹配中确定 Vasya 可能获得的最佳位置和最差位置。 

约束条件`n ≤ 100000`立即排除任何显式尝试匹配的方法。 有`n!`可能的配对，甚至检查所有`n²`如果重复进行，候选对的成本就太高了。 可接受的解决方案必须接近`O(n log n)`。 

这个问题最具欺骗性的部分是我们没有被要求提供瓦西亚的确切分数。 我们只知道他的分数至少是`x`。 重建排名的幼稚尝试是不必要的，而且会导致错误的方向。 

考虑一个小例子：```
n = 3, x = 10
a = [10, 0, 0]
b = [10, 0, 0]
```一名参与者可得分`20`，而另外两个得分`0`。 Vasya 可能是参与者`20`,让出位置`1`。 

现在考虑：```
n = 3, x = 5
a = [3, 3, 3]
b = [3, 3, 3]
```每位参赛者得分`6`。 根据决胜局的情况，瓦西亚可以排名第一或第三。 只计算严格较大分数的解决方案会错过这一点。 

关键的观察结果是，任何总分低于以下的参与者`x`永远不可能领先于 Vasya，因为已知 Vasya 的分数至少为`x`。 

## 方法

 暴力视图对于发现正确的抽象很有用。 

假设我们尝试所有可能的匹配`a`和`b`。 对于每个匹配，我们计算所有最终得分，确定得分至少为的参与者`x`作为 Vasya，并评估他的最佳和最差排名。 

这是正确的，但速度慢得令人绝望。 有`n!`匹配，即使对于`n = 20`，更不用说`100000`。 

关键的观察是上面的确切分数`x`没关系。 

由于 Vasya 至少得分`x`, 每个得分低于以下的参与者`x`保证在他身后。 唯一可以与 Vasya 的位置竞争的参与者是那些分数也至少为`x`。 

这彻底改变了问题。 

为了获得最佳名次，瓦斯亚可以简单地被选为所有得分至少为 的参赛者中最强的参赛者`x`。 由于领带的顺序可以任意排列，因此他总是可以排在第一位。 最好的地方永远是`1`。 

对于最差的地方，我们希望尽可能多的参与者至少获得分数`x`。 如果有`k`在这样的参赛者中，瓦夏可能是其中最弱的，打破平局至少可以让他落后于所有其他参赛者的分数`x`。 他最糟糕的地方恰恰是`k`。 

现在问题被简化为：

 > 找出最大对数`(a[i], b[j])`至少可以由 sum 组成`x`。 

对两个数组进行排序后，这成为一个经典的贪婪匹配问题。 

从中取最大的剩余值`a`。 为了保留更大的值`b`为了将来使用，将其与中的最小值相匹配`b`仍然使总和达到`x`。 如果不存在这样的值，则此`a`永远无法参与成功的配对。 

这种贪婪策略最大化了成功配对的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最优贪心 + 排序 | O(n log n) | O(n log n) | O(1) 额外（除了排序） | 已接受 |

 ## 算法演练

 1. 排序`a`按非递减顺序。 
2. 排序`b`按非递减顺序。 
3. 设置指针`j = 0`，代表最小的未使用元素`b`。 
4. 迭代`a`从最大到最小。 
5. 对于当前值`a[i]`， 进步`j`直到：

 -`a[i] + b[j] >= x`, 或
 - 的所有元素`b`已经筋疲力尽了。 
6.如果没有合适的`b[j]`存在，停止。 自从`a`从最大到最小处理，所有剩余值`a`甚至更小，也无法形成成功的配对。 
7. 否则，使用此创建成功的配对`b[j]`，数数，然后移动`j`向前。 
8. 令成功配对的数量为`k`。 
9. 输出：

 - 最好的地方=`1`- 最差的地方=`k`### 为什么它有效

 参与者得分低于`x`永远不可能超过 Vasya，因为 Vasya 的分数至少是`x`。 

对于最差排名，唯一重要的是有多少参与者能够获得至少`x`。 如果有`k`这样的参与者，瓦夏可以被安排在最后一个，让出位置`k`。 

贪婪匹配使成功配对的数量最大化。 当处理一个大值时`a[i]`，使用最小的`b[j]`有效的总是最佳的。 任何更大的选择都会浪费更强大的力量`b`稍后可能需要较小的值`a`。 这是贪婪匹配背后的标准交换参数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b.sort()

    j = 0
    cnt = 0

    for i in range(n - 1, -1, -1):
        while j < n and a[i] + b[j] < x:
            j += 1

        if j == n:
            break

        cnt += 1
        j += 1

    print(1, cnt)

solve()
```排序步骤为两个数组准备贪婪匹配。 

指针`j`始终指的是最小的未使用值`b`。 当处理大值时`a`，我们跳过每一个`b[j]`太小而无法达到阈值。 第一个成功的值是最佳选择，因为它会保留所有较大的值以供将来的匹配使用。 

早点休息是安全的。 一旦当前最大剩余值在`a`找不到匹配的`b`，每个较小的值`a`也会失败。 

最终统计的正是总分至少能达到的最大参赛人数`x`，这相当于瓦西亚最糟糕的地方。

 ## 边缘情况

 考虑：```
3 5
3 3 3
3 3 3
```每个参与者都准确得分`6`。 

该算法计算出三个成功的配对，因此`k = 3`。 

输出：```
1 3
```这正确地捕捉了平局打破规则。 即使所有总数相同，瓦夏也可能排名第一或第三。 

现在考虑：```
3 10
10 0 0
10 0 0
```排序后的数组保持不变。 

贪心匹配仅形成一对成功的匹配：```
10 + 10 = 20
```剩余值无法达到`10`。 

因此`k = 1`，答案是：```
1 1
```Vasya 必须是至少得分的唯一参与者`10`。 

最后，考虑：```
4 100
1 2 3 100
1 2 3 100
```算法立即匹配`100`和`100`，然后发现没有剩余的对可以达到阈值。 

输出：```
1 1
```早期停止条件是正确的，因为所有剩余值`a`比已经失败的小。
