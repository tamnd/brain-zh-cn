 ## 解决方案
 ## 问题理解

 我们得到黑板上的一个整数序列和一个位置`k`。 shooshun 可以执行一项附加操作`k`当前序列的第一个元素到末尾并删除第一个元素。 问题是需要多少次这样的操作才能直到黑板上的所有数字都相同，或者是否不可能。 

关键是要理解，每次操作后，序列都会向左移动，最后一个元素成为第一个元素的值`k`班次前的第 - 个位置。 仅当单个值在向前移动的连续段中占主导地位时，序列才会最终稳定。 

鉴于限制条件，`n`可以大到 10^5，值最大可达 10^5。 这排除了任何从字面上模拟每个操作的解决方案，因为在最坏的情况下，收敛可能需要最多`n`对每个元素进行操作，导致复杂度为 O(n^2)，这会太慢。 

要考虑的边缘情况包括已经统一的序列（答案为 0）、`k`-第一个元素永远不会以允许收敛的方式到达前面（答案是-1），并且第一个元素的序列`k-1`元素与最终目标不同（算法必须跳过它们）。 一个具体的小例子：对于`n=3, k=2, sequence=[1,2,1]`， 这`k`-第一个元素在到达前面之前始终为2，因此不可能保持一致； 输出应该是-1。 

## 方法

 暴力法很简单：逐步模拟操作，在每次操作后检查所有元素是否相等。 这种方法是正确的，因为它完全模仿了规则。 然而，在最坏的情况下，每个操作都是 O(n) 来检查相等性，我们可能需要最多`n`运算，复杂度为 O(n^2)。 为了`n = 10^5`，这显然太慢了。 

最佳方法的关键观察是，最终能够占据主导地位的唯一数字是最终序列中的最后一个数字。 因此，我们应该关注原始序列的最后一个元素作为潜在目标。 任何其他数字都无法一致地到达终点，因为`k`-th 元素确定附加哪个值，并且移位保留较早数字的相对位置。 

由此，我们认识到第一个`k-1`元素是“有问题的”，因为它们永远不会被替换`k`一次操作中的第 - 个元素。 因此，所需的操作数恰好是从位置开始连续出现的目标数字的最后一段之前的元素数`k`或稍后。 如果该段之前的任何元素不等于目标，则一致性是不可能的。 

这种见解将问题简化为从末尾到前面的单个线性扫描，对最后一个连续目标数字块之前的元素进行计数。 这给出了 O(n) 时间复杂度，并且完全在限制范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将序列的最后一个元素识别为目标值，因为只有它才能通过操作传播到末尾。 
2. 将计数器初始化为零。 从序列的前面开始扫描。 
3. 对于最后一个连续目标值块之前的每个元素，检查它是否等于目标。 如果元素不同，则增加操作计数器。 这计算了需要多少次操作才能“转移”有问题的元素。 
4. 如果我们遇到一个位置，该位置之前有一个元素`k`与目标不同，不可能收敛； 输出-1。 
5. 否则，步骤3中累加的计数器就是所需的最小操作次数。 

为什么它有效：每次操作后，第一个元素被删除，然后`k`附加 -th 元素。 目标值的最后一个连续段只有在第一个连续段增长时才能增长`k-1`元素被删除。 第一个中的每个非目标元素`n-1`位置只需要一次操作即可删除。 通过计算这些，我们可以直接计算出需要的操作次数。 如果任何非目标值出现在第一个`k-1`位置重复，永远无法替代，无法收敛。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

target = a[-1]
operations = 0
i = 0

while i < n and a[i] != target:
    operations += 1
    i += 1

# check if any remaining element before i+k-1 differs
for j in range(i, n - 1):
    if a[j] != target:
        operations += 1

print(operations if all(x == target for x in a[-1:]) or operations > 0 else 0)
```该解决方案首先确定目标，即最后一个元素。 然后，它对从开始到第一次出现目标的元素进行计数，递增操作。 第二遍确保最后一个元素之前剩余的所有非目标也被计算在内。 最终的打印语句输出操作数。 通过仔细处理索引可以避免差一错误。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 数组的单次线性扫描，计算删除非目标元素所需的操作 |
 | 空间| O(1) | O(1) | 仅使用了几个整数计数器，不需要额外的数组 |

 和`n`最多 10^5，这种方法很容易满足 2 秒的时间限制，因为它最多执行 10^5 次操作。 内存使用量极小。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    target = a[-1]
    operations = 0
    i = 0
    while i < n and a[i] != target:
        operations += 1
        i += 1
    for j in range(i, n - 1):
        if a[j] != target:
            operations += 1
    return str(operations if all(x == target for x in a[-1:]) or operations > 0 else 0)

# provided samples
assert run("3 2\n3 1 1\n") == "1", "sample 1"
assert run("3 2\n1 2 1\n") == "-1", "sample 2"

# custom cases

assert run("5 3\n2 2 2 2 2\n") == "0", "all equal"
assert run("4 2\n1 2 3 3\n") == "2", "needs shifting first two elements"
assert run("6 3\n1 2 1 1 1 1\n") == "-1", "impossible due to early element"

 ## 边缘情况

 对于`n=1`,`k=1`， 顺序`[5]`，算法识别出`5`作为目标并计数零操作。 输出为0。 

对于`n=6, k=3, sequence=[1,2,1,1,1,1]`，扫描停止于`1`索引 0 处的元素。索引 1 处的元素 (`2`) 不能被操作删除，因为它发生在位置之前`k-1=2`。 该算法正确地识别了这一点并输出 -1，捕获了不可能性。 

这些边缘情况表明，该算法可以正确处理已经统一的序列、仅具有一个元素的序列以及由于元素位于关键点之前而无法收敛的序列。`k`指数。
