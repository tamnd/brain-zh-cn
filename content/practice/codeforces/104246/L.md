 ## 解决方案
 ## 问题理解

 我们正在处理从 1 到 N 的编号线上的隐藏区间。在这条线上的某个地方，有一个从 A 开始到 B 结束的连续线段，我们的目标是确定其长度，即 B 减去 A 加一。 

我们无法直接访问 A 或 B。相反，我们可以提出“is x before theegment, inside, or after it”形式的查询。 响应将线划分为三个区域：A 的严格左侧的所有内容、从 A 到 B 的所有内容（包括 A 到 B）以及 B 的严格右侧的所有内容。每个查询都准确地向我们提供所选点所属的区域。 

关键限制是每个测试最多可进行 55 个查询，而 N 可以大到 10^9。 这立即排除了整个范围内的任何线性扫描或密集探测策略。 即使是对数策略也需要仔细预算，因为整个范围内的每个二分搜索大约需要 30 个查询，而天真地执行多个此类搜索将超出限制。 

一个微妙但重要的保证是间隔长度最多为 10^6。 这个额外的限制阻止了直接的“在 [1, N] 上独立查找 A 和 B”方法的查询预算紧张。 这表明，一旦知道一个端点，就可以在更小的区域中找到另一个端点。 

如果我们尝试使用 [1, N] 上的完整二分搜索来独立定位 A 和 B，就会出现天真的错误。 这需要对 A 进行大约 30 次查询，对 B 进行另外 30 次查询，总共大约 60 次查询。 这已经超过了允许的 55。另一种不正确的方法是尝试使用查询从猜测的点“扩展”，因为响应不会告诉我们距离，只告诉我们相对位置。 

因此，挑战不仅在于定位细分，而且还在于在遵守严格的查询预算的情况下这样做，这迫使我们在部分学习答案后减少搜索空间。 

## 方法

 暴力策略会扫描从 1 到 N 的每个位置，查询每个点，直到找到位于段内的第一个索引和位于段内的最后一个索引。 这是可行的，因为每个点都被明确分类，因此我们可以通过跟踪转换来识别 A 和 B。 然而，在最坏的情况下，N 是 10^9，所以即使每个查询都是常数时间，这种方法也是完全不可行的。 

一种更结构化的方法是二分搜索。 如果我们正确解释的话，响应函数是单调的，这是一种有用的方式。 对于 A，每个位置 x < A 返回“<”，而每个位置 x >= A 返回“=”或“>”。 这给出了一个干净的单调边界，允许我们对第一个不是“<”的位置进行二分搜索。 

类似地，对于 B，我们观察到每个位置 x > B 返回“>”，而每个位置 x <= B 返回“<”或“=”。 这让我们可以二分查找最后一个不是“>”的位置。 

如果我们在整个范围 [1, N] 上执行二分搜索，我们将面临使用大约 60 个查询的风险。 解决这个问题的关键是保证段长度最多为 10^6。 一旦我们确定了 A，我们就知道 B 一定位于 [A, min(N, A + 10^6)] 中。 这将第二个二分搜索域从 10^9 减少到最多 10^6，从而大大降低了查询成本。 

因此，我们将任务分为两个阶段：对 A 进行全范围二分搜索，以及在小窗口中对 B 有界二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 线性扫描| O(N) 查询 | O(1) | O(1) | 太慢了 |
 | 完整二分查找两次 | O(log N) 查询 | O(1) | O(1) | 查询太多 |
 | 优化分割搜索 | O(log N + log L) 查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 算法演练

1. 对范围 [1, N] 执行二分查找以找到 A。对于中点 x，查询它并解释响应。 如果响应为“<”，则 x 严格位于 A 之前，因此 A 必定位于右侧。 否则，x 在 A 的内部或右侧，因此 A 位于 x 或左侧。 搜索收敛到第一个非“<”的位置。 
2. 一旦 A 已知，将 B 的缩小搜索范围定义为 [A, min(N, A + 10^6)]。 这是有效的，因为该问题保证段长度最多为 10^6，因此 B 不能位于该区间之外。 
3. 执行第二次二分查找，找到最后一个不是“>”的位置。 对于中点x，如果响应是“>”，那么x严格在B之后，我们必须向左搜索。 否则，x 位于 B 处或之前，因此我们向右移动。 
4. 找到两个端点后，计算答案为 B − A + 1。 

### 为什么它有效

 正确性依赖于查询函数的两个单调分区。 谓词“x < A”在 x 中是严格单调的，谓词“x > B”在 x 中也是严格单调的。 这使得二分搜索能够精确地定位边界。 第二阶段是安全的，因为最大段长度的约束保证了缩小 A 周围的搜索空间不能排除 B。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(x):
    print(f"? {x}", flush=True)
    return input().strip()

def find_A(n):
    lo, hi = 1, n
    ans = n
    while lo <= hi:
        mid = (lo + hi) // 2
        res = ask(mid)
        if res == '<':
            lo = mid + 1
        else:
            ans = mid
            hi = mid - 1
    return ans

def find_B(n, A):
    lo = A
    hi = min(n, A + 10**6)
    ans = A
    while lo <= hi:
        mid = (lo + hi) // 2
        res = ask(mid)
        if res == '>':
            hi = mid - 1
        else:
            ans = mid
            lo = mid + 1
    return ans

def solve():
    n = int(input())
    A = find_A(n)
    B = find_B(n, A)
    print(f"! {B - A + 1}", flush=True)

if __name__ == "__main__":
    solve()
```该解决方案将交互分离为一个小的辅助函数`ask`，确保立即刷新每个查询，这在交互式问题中是强制性的。 第一个二分搜索通过将“<”视为位于左侧段之外的严格指示符来识别左边界。 第二个二分搜索有意限制在从最大可能段长度派生的安全窗口，这是保持在查询限制内的关键。 

一个常见的实现陷阱是将响应“=”视为需要单独处理的特殊情况。 实际上，“=”的行为与在两个二分搜索的段内的行为相同，因此它可以与非极端情况分组。

 ## 边缘情况

 当间隔从 1 开始时，对 A 的二分搜索永远不会看到“<”，因此它直接收敛到 1。该逻辑仍然有效，因为默认答案被初始化为上限，并且仅当出现有效候选时才收紧。 

当间隔以 N 结束时，第二次二分查找根本看不到“>”响应，因此它扩展到完全允许的范围并正确返回 B = N。 

当区间的最大允许长度为10^6时，受限的第二搜索范围与有效区域完全匹配。 这是第二个二分搜索保持足够高效以适应查询限制的唯一原因，并且它确保没有有效的 B 被排除在考虑范围之外。
