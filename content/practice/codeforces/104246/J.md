 ## 解决方案
 ## 问题理解

 我们通过数字重排操作重复变换一个小整数。 每一步都采用当前值，使用前导零将其标准化为 4 位字符串，然后从其数字形成两个新数字：一个数字按升序排序，另一个数字按降序排序。 下一个值是这两个数字之间的差。 

因此每个状态仅取决于先前的状态，并且转换是确定性的。 从小于 10000 的初始数字开始，我们精确应用此规则 k 次并报告最终值。 

尽管 k 可以非常大，达到 10^18，但状态空间却很小。 每个数字实际上都是 10000 种可能的 4 位数字配置之一。 这立即排除了直接模拟 k 步骤的可能性，因为最坏的情况将是每个测试用例 10^18 次操作，这远远超出了任何可行的限制。 即使 10^5 个测试用例对于 k 中的任何线性项来说也已经太大了。 

关键的结构约束是函数将有限集映射到自身。 这就保证了重复的应用最终一定会进入一个循环。 这种循环行为是解决方案的整个支柱。 

一些边缘行为在实践中很重要。 

一个常见的错误是忘记前导零。 例如，21 必须被视为 0021。如果我们跳过填充，排序数字将完全改变并产生不同的转换，从而破坏正确性。 

另一个微妙的情况是具有重复数字的数字，例如 7770 或 1000。这些数字通常会快速崩溃为稳定的循环或固定点。 如果数字填充或排序实施不正确，这些情况往往会立即暴露出来。 

最后，k可以为零。 在这种情况下，输出必须是未更改的原始数字，如果假设至少有一次迭代，则很容易出现错误处理。 

## 方法

 最简单的方法是直接模拟。 对于每个步骤，将数字转换为带有前导零的 4 字符字符串，对数字进行两次排序以形成 p 和 q，计算 q 减去 p，然后继续。 这是正确的，对于 k 小的单个测试用例来说就可以了。 

问题在于 k 的大小。 每个步骤都是 O(1)，因为数字排序超过固定大小，但 k 可以达到 10^18。 即使每个步骤只需要几次操作，将其乘以 k 也是不可能的。 

关键的观察结果是该变换在具有 10000 个状态的固定宇宙中进行。 有限集上的确定性函数最终必须重复。 一旦一个状态重复，序列就进入一个循环。 此后，进一步的转变是周期性的。 

这意味着我们只需要进行模拟，直到达到 k 步或检测到重复状态。 由于最多有 10000 个状态，因此第一个重复状态必须出现在 10000 步以内。 之后，我们提取循环长度并直接使用模运算进行跳转。 

这将在预处理后将天文数字般大的 k 转换为恒定时间计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 每次测试 O(k) | O(1) | O(1) | 太慢了 |
 | 循环检测+跳跃| 每次测试 O(10000) | O(10000) | 已接受 |

 ## 算法演练

 我们将变换视为在 0000 到 9999 之间的整数上定义的函数 f(x)。

1. 通过应用一次数字排序规则，预先计算 [0, 9999] 中任意数字 x 的下一个状态。 这使得模拟期间的转换为 O(1)，因为我们避免了重复的字符串排序。 
2. 对于每个测试用例，从初始数字开始并模拟转换，同时记录每个值第一次出现的时间。 我们存储第一次看到每个数字的步骤索引。 
3. 如果在任何重复之前达到 k 步，我们直接返回当前值。 这处理 k 较小或序列不在观察部分内循环的情况。 
4. 如果我们重新访问之前看到的值，我们就检测到了一个循环。 令重复值的第一次出现索引为入口点t，当前步骤为s。 周期长度为 s - t。 
5. 为了计算 k 步后的最终状态，我们区分两个阶段。 如果 k < t，则答案位于循环开始之前。 否则，我们使用 (k - t) mod Cycle_length 计算进入循环的距离，并相应地对循环进行索引。 
6. 输出对应的存储值。 

重要的设计选择是将预循环和循环行为分开。 第一部分是线性链成循环，第二部分是周期性重复。 该算法依赖于显式存储序列，以便我们稍后可以对其进行索引。 

### 为什么它有效

 该变换定义了有限集上的确定性函数，因此每个无限轨迹最终都必须重复一个状态。 一旦一个状态重复，决定论就会迫使从该状态开始的整个未来演化都是相同的，从而形成一个循环。 记录的首次出现索引保证我们正确识别循环的入口点，而模块化算术确保我们落在循环中的正确位置。 由于每种可能的状态都在前缀或循环中得到考虑，因此模拟之外不存在看不见的行为。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def next_state(x: int) -> int:
    s = str(x).zfill(4)
    asc = "".join(sorted(s))
    desc = "".join(sorted(s, reverse=True))
    return int(desc) - int(asc)

def solve():
    t = int(input())
    
    # Precompute transitions for all states
    nxt = [0] * 10000
    for i in range(10000):
        nxt[i] = next_state(i)
    
    for _ in range(t):
        n, k = input().split()
        n = int(n)
        k = int(k)
        
        seen = {}
        seq = []
        
        cur = n
        step = 0
        
        while cur not in seen and step <= k:
            seen[cur] = step
            seq.append(cur)
            if step == k:
                break
            cur = nxt[cur]
            step += 1
        
        if step == k:
            print(cur)
            continue
        
        if cur not in seen:
            print(cur)
            continue
        
        start = seen[cur]
        cycle = step - start
        
        if k < len(seq):
            print(seq[k])
        else:
            idx = (k - start) % cycle
            print(seq[start + idx])

if __name__ == "__main__":
    solve()
```该实现首先构建一个转换表，以便在恒定时间内计算每个步骤。 这避免了模拟过程中的重复排序。 

对于每个测试用例，我们在字典中跟踪访问状态，将编号映射到首次出现索引。 该序列被存储，以便我们可以在检测到循环后重建答案。 

停止条件被仔细地分为三种情况。 如果我们在重复之前自然地到达步骤 k，我们会立即输出。 如果我们在没有达到 k 的情况下提前终止，但也没有循环检测（实践中很少见，但由于步骤限制而可能），我们仍然返回当前状态。 否则，我们应用循环算术。 

主要的微妙之处是确保之间的正确索引`seen`,`seq`和步数。 这`start`索引标记循环的入口点，并且`(k - start) % cycle`给出循环内的正确偏移量。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(10000 + t · L) | 预先计算所有转换一次，然后每个测试最多模拟前缀加循环条目，以状态数为界 |
 | 空间| O(10000) | 存储转换表和每次测试访问的序列 |

 固定的 4 位状态空间确保重复之前的步骤数 L 最多为 10000。当 t 达到 10^5 时，解决方案仍然有效，因为每个测试执行独立于 k 的有界工作。

 ## 边缘情况

 关键的边缘情况是 k = 0。该算法直接返回初始值，因为模拟循环会检查`step == k`在前进之前。 用于输入`n = 1234, k = 0`，序列永远不会前进，输出是`1234`。 

另一种情况是重复的数字，如 7770。转换很快将此类数字减少为稳定的循环。 循环检测机制捕获少量步骤内的重复并避免冗余计算。 

对于填充后带有前导零的数字，例如 21 变成 0021，使用`zfill(4)`确保一致的数字排序。 如果没有这个，转换就会错误地将 21 视为两位数，并产生完全不同的轨迹。
