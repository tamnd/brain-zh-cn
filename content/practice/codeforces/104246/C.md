 ## 解决方案
 ## 问题理解

 我们收到了几个独立的查询。 每个查询提供一个目标号码`x`和一个整数区间`[l, r]`。 在这个区间内，我们想知道是否可以选择三个不同的整数`a < b < c`，都躺在`[l, r]`，使得它们的乘积等于`x`。 

如果这样的三元组存在，我们可以输出任何一个有效的选择`(a, b, c)`。 如果不存在这样的三元组，我们输出`-1`。 

该间隔以一种非常具体的方式很小：尽管`l`和`r`最多可以为 1000，它们的差异最多为 100。这意味着每个查询最多对 101 个候选值进行操作。 该限制是关键的结构简化：尽管`x`可以大到 10^9，每个查询的搜索空间是严格限制的。 

一种幼稚的方法是尝试间隔中的每一个三重奏。 由于最多有 101 个数字可用，因此每个测试用例大约有 100^3 ≈ 10^6 种组合，最多有 100 个测试用例，虽然处于边缘状态，但在优化的 Python 中仍然可以接受。 然而，有一种更直接的减少方法可以完全消除一个循环。 

主要的边缘情况来自严格的不平等要求`a < b < c`。 即使三个数字相乘`x`，使用重复值，例如`a = b`无效。 另一个微妙的情况是当`x`是小或素数：区间内不会存在因式分解，但粗心的实现可能会在不验证第三个值的情况下错误地接受部分除数。 

天真的想法失败的例子：

 输入：`x = 12, l = 1, r = 5`三倍喜欢`(1, 2, 6)`乘法正确但是`6`超出了范围，因此即使部分推理表明有效性，也必须拒绝它。 

## 方法

 蛮力的想法很简单：迭代所有三元组`(a, b, c)`并检查它们的乘积是否等于`x`。 这是正确的，因为它详尽地检查了每种可能性，并且约束保证了间隔很小。 然而，其成本随着间隔大小呈三次方增长。 对于多达 101 个值，我们每个查询可以获得大约 171,700 个组合，并且在 100 个查询中，这可能会接近数千万次检查，一旦包含开销，这在 Python 约束下仍然处于边缘状态。 

关键的观察是我们不需要独立选择所有三个值。 如果我们修复`a`和`b`，值`c`完全确定为`c = x / (a * b)`，前提是划分准确。 这将搜索从三个嵌套循环减少到两个循环加上一个恒定时间验证步骤。 

因此，我们不是探索所有三元组，而是枚举所有有序对`(a, b)`和`a < b`，计算乘积`a * b`，并检查是否`x`可以被它整除。 如果是的话，我们计算`c`并验证是否在区间内且满足`b < c`。 

这将三次搜索变成了二次搜索，在给定最大间隔大小的情况下，速度相当快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（3 圈）| 每次测试 O(n³) | O(1) | O(1) | 最坏情况下太慢|
 | 配对固定 (a, b → c) | 每次测试 O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读`x`,`l`， 和`r`，并构造区间内的候选整数列表`[l, r]`。 

使用显式列表的原因是间隔很小并且每个查询都是固定的。 
2. 迭代所有可能的选择`a`从`l`到`r`。 

每个`a`表示三元组的第一个元素，强制递增顺序自然可以避免重复。 
3. 对于每个`a`, 迭代所有`b`这样`b > a`。 

这确保了始终保持严格的订购条件，无需额外检查。 
4. 计算`a * b`。 如果这个值超过`x`，我们仍然可以继续，因为更大`b`只会进一步增加乘积，但由于约束较小，不需要严格修剪。 
5. 如果`x % (a * b) == 0`, 计算`c = x / (a * b)`。 

此步骤通过导出唯一可能的候选者来完全取代第三个循环`c`。 
6. 检查是否`c`是一个整数并且位于`[l, r]`，并且还满足`c > b`。 

这保证了三元组的所有约束都得到满足。 
7. 如果有这样一个`c`存在，立即输出`(a, b, c)`并停止处理当前的测试用例。 
8. 如果没有配对`(a, b)`产生一个有效的`c`， 输出`-1`。 

### 为什么它有效

 每个有效的解决方案都对应于一个有序对`(a, b)`和`a < b`。 对于该对，第三个值`c`由产品约束唯一确定。 该算法检查区间中每个可能的有序对，因此如果存在有效的三元组，就会遇到其对应的对。 因为每一位候选人`c`根据间隔和排序约束进行验证，不会产生无效的三元组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, l, r = map(int, input().split())

        found = False

        for a in range(l, r + 1):
            for b in range(a + 1, r + 1):
                prod = a * b
                if prod > x:
                    continue
                if x % prod != 0:
                    continue

                c = x // prod
                if c > b and l <= c <= r:
                    print(a, b, c)
                    found = True
                    break
            if found:
                break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```该方案直接实现了pair-fixing的思想。 嵌套循环枚举`(a, b)`按递增顺序，确保`a < b`自动地。 乘法检查避免了不必要的除法工作`a * b`已经超过`x`。 一旦有效`c`导出后，算法会在打印之前立即验证排序和范围约束。 

尽早退出很重要：一旦找到任何有效的三元组，就无需继续搜索，因为该问题允许任何正确答案。

 ## 边缘情况

 当存在有效分解但其中一个因子位于区间之外时，就会出现一种微妙的情况。 例如，`x = 24, l = 2, r = 5`。 因式分解`2 * 3 * 4`工作完美并且由算法找到，但是像这样的分解`1 * 3 * 8`如果忽略范围限制，可能会被认为是心理上有效的。 该算法明确强制`l <= c <= r`，因此它会正确拒绝此类情况。 

另一种边缘情况是存在多重分解时。 由于算法在第一个有效对处停止`(a, b)`，它可能返回任何符合问题要求的有效三元组。
