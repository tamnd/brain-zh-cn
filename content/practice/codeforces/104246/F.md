 ## 解决方案
 ## 问题理解

 我们得到了一组编码器，每个编码器都从一些初始奖励值开始。 随着时间的推移，一系列更新到来，每次更新都针对一个编码器，并将该编码器的奖励增加某个整数，该整数可能是正数，也可能是负数。 

每次更新后，我们都被要求报告当时所有编码员中存在多少个不同的奖励值。 换句话说，在处理前 k 个更新后，我们在概念上有一个大小为 n 的更新数组，并且我们想要其中唯一值的数量。 

输入结构是多个独立的测试用例。 每个测试用例都会给出一个初始数组，然后是一系列点修改，并且我们必须在每个更新步骤输出一个答案。 

这些约束很重要，因为每个测试用例的 n 和 m 都可以高达 100000，而所有测试用例的总数最多为 200000。这立即排除了在每次更新后从头开始重新计算不同值数量的任何方法，因为这将导致每次查询的成本为 O(n)，并且在最坏的情况下会导致大约 10^10 次操作。 

一个微妙的问题是值在更新后可能会大量重复。 天真的直觉可能会尝试维护值的频率图，但盲目更新频率而不跟踪有多少元素共享一个值会导致不正确的不同计数。 

当多个编码器在不同的更新路径之后收敛到相同的值时，会出现另一种边缘情况。 例如，从 [1, 2] 开始，然后将 +1 添加到索引 1，将 -1 添加到索引 2，得到 [2, 1]，即使各个值更改了标识，它仍然具有两个不同的值。 任何解决方案都必须跟踪全局价值多重性，而不仅仅是每个索引的历史记录。 

## 方法

 直接强力解决方案会在每次更新后重新计算不同值的数量。 应用第 k 个操作后，我们扫描整个数组并将所有值插入到一个集合中以计算唯一值。 这是正确的，因为集合自然会删除重复值。 

然而，每次扫描的成本为 O(n)，而且我们执行了 m 次，因此每个测试用例的复杂度变为 O(nm)。 当n和m达到100000时，这远远超出了可行的极限。 

关键的观察结果是每次操作仅更改一个元素。 这意味着整个数组不需要重新计算； 我们只需要调整单个旧值和单个新值的贡献即可。 

如果我们维护所有编码器的值的频率图，则每次更新仅影响两个频率：更新编码器的旧值减少一次，新值增加一次。 不同值的数量正是该频率图中具有正计数的键的数量。 

因此，我们不是重建集合，而是增量地维护计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(n) | 太慢了 |
 | 频率图维护| O((n + m) log n) 或 O(n + m) 平均值 | O(n) | 已接受 |

 ## 算法演练

 我们维护两个结构：一个存储每个编码器当前值的数组，以及一个存储每个值在全局出现的次数的哈希图。 

### 步骤

 1.初始化一个数组`a`以及所有编码员的初始奖励。 
2. 构建频率图`freq`在哪里`freq[x]`目前有多少编码员具有价值`x`。 
3. 计算不同值的初始数量作为键的数量`freq`以非零频率。 
4. 每次更新`(p, r)`, 确定当前值`old = a[p]`。 
5. 减少`freq[old]`加一，因为编码器`p`将不再具有该值。 
6. 如果`freq[old]`变为零，将其从地图中删除或将其视为不存在，因为它不再对不同的值做出贡献。 
7. 计算新值`new = old + r`并将其分配给编码器`p`。 
8. 增加`freq[new]`按一位，如有必要，创建条目。 
9. 每次更新后，输出当前的key个数`freq`。 

每一步都是由每次操作仅更改一个元素这一事实驱动的，因此全局结构更新减少为两次计数器调整。 

### 为什么它有效

 关键的不变量是，在处理每次更新后，频率图准确地表示所有编码器的当前奖励值的多重集。 由于不同的值精确对应于频率大于零的值，因此对映射中的活动键进行计数即可得出正确的答案。 由于每次更新仅更改一个数组位置，因此调整两个计数可以保留这一不变性，而无需任何完整的重新计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out_lines = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        distinct = 0

        for x in a:
            if x not in freq:
                freq[x] = 0
            if freq[x] == 0:
                distinct += 1
            freq[x] += 1

        for _ in range(m):
            p, r = map(int, input().split())
            p -= 1

            old = a[p]

            freq[old] -= 1
            if freq[old] == 0:
                distinct -= 1

            new = old + r
            a[p] = new

            if new not in freq:
                freq[new] = 0
            if freq[new] == 0:
                distinct += 1
            freq[new] += 1

            out_lines.append(str(distinct))

    print("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```该实现直接反映了不变量。 数组`a`存储当前值，以便每次更新都可以在 O(1) 内访问旧值。 字典`freq`跟踪多重性。 变量`distinct`当计数在任一方向上过零时，通过增量维护来避免重新计算活动键的数量。 

处理转换时必须小心。 当递减一个值时，非重复计数器仅在其计数正好为零时才递减。 当增加一个值时，非重复计数器仅在从零转变为一时增加。 这可以避免重复计算已经存在的值。 

索引通过减一来调整`p`因为输入使用从 1 开始的索引。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每个测试用例的平均值为 O(n + m) | 每次更新都会执行恒定时间的哈希图操作 |

 ## 边缘情况

 一个重要的边缘情况是值完全消失。 假设除 1 之外所有编码器当前的值均为 5，并且最后一个编码器已更新。 5 的频率下降到零，并且必须将不同计数器恰好减少 1。 该算法处理这个问题是因为递减步骤检查`freq[old] == 0`减去后并减少`distinct`就在那一刻。 

另一种情况是引入一个已经存在的值。 如果编码器从 3 更改为 7，但 7 已经出现在其他地方，则非重复计数不得增加。 支票`if freq[new] == 0`确保我们仅在该值先前不存在时才增加 unique。 

第三种情况是对同一索引进行重复更新。 数组`a[p]`始终存储当前值，因此每次更新都会在应用下一个状态之前正确减去前一个状态。 这可以避免积累早期更新中的陈旧贡献。
