 ## 解决方案
 ## 问题理解

 我们得到了一系列武器蓝图和几堆独立的原材料。 每张蓝图都描述了制造一件武器需要多少锭，以及如果该武器后来被熔化，可以回收多少锭。 每次我们成功锻造一件武器，我们都会获得一个经验点，每次我们熔化之前锻造的武器，我们都会获得另一个经验点。 目标是通过在锻造和熔化之间反复循环，同时管理每种类型的可用金属，最大限度地提高总体体验。 

一个关键的自由是任何武器类别都可以使用任何金属类型锻造。 金属类型的行为独立，除了所有操作都从该类型的同一池中消耗并返回到该类型的事实之外。 这意味着问题分解为决定如何最好地使用每个金属堆，而武器类别则决定哪些周期是有利可图的。 

限制非常大，武器种类多达一百万种，金属种类多达一百万种。 这立即排除了武器和金属之间的任何二次相互作用。 任何试图模拟每对选择或重复重新计算每单位金属最佳动作的解决方案都将无法生存。 

还有一些涉及无利可图的武器的微妙案例。 如果武器返回的锭太少，则它永远不能用于创建重复循环。 例如，如果武器花费 5 锭并返回 0，那么锻造一次就会永久消耗资源，使其在每个可用剩余中最多可用一次。 另一方面，如果武器花费 5 并返回 4，则每个周期消耗净 1 锭并产生 2 经验，这意味着它可以重复，直到金属池耗尽。 

总是选择最便宜的武器或总是选择最有利可图的比率的天真贪婪方法可能会失败，因为该决定取决于一堆中当前剩余的金属。 早期的选择会影响以后可以使用其他武器的次数。 

## 方法

 直接的强力方法将模拟所有可能的锻造和熔化操作序列。 在每一步中，对于每种金属类型和每种武器，我们都会检查是否可以制作它、应用它并递归。 即使我们只考虑有效的移动来进行修剪，分支因子也非常大。 拥有多达 10^6 种武器类型和 10^6 种金属类型，即使是单层探索也是不可能的。 潜在操作的数量随着金属量的增加而增加，并且每个操作都可以改变状态，因此总搜索空间在实践中呈指数增长。 

关键的观察结果是，单一金属类型内的操作顺序并不重要，只有每种武器应用于该金属类型的次数才重要。 每种武器类型都定义了一种转换：它消耗`a_i`锭和回报`b_i`，所以每个周期的净成本是`a_i - b_i`，每个完整周期都会产生 2 个经验点。 

我们可以将武器分为两类。 如果武器有`a_i <= c_j`，它可以在大小的金属堆上至少使用一次`c_j`。 更重要的是，如果它在允许重复循环的意义上是有利可图的（即，它永远不会以使得未来循环不可能的方式阻止进一步使用），那么它实际上表现为每单位净消耗具有固定利润的重复交易。 

This turns each metal pile into a knapsack-like resource. 然而，由于所有操作都是线性且独立的，因此给定堆的最佳策略是始终使用适合当前剩余锭的最佳可用转换。 

Instead of simulating per pile, we reverse the viewpoint. For each possible remaining ingot value, we want to know the best possible gain. 这导致我们按照有效成本对武器进行排序，并按照成本递增的顺序贪婪地应用最好的武器，从而保持我们仍然可以花费的金锭数量。 

The crucial simplification is that only the net consumption`a_i - b_i`重复使用只重要，首次使用只重要可行性。 这将问题简化为排序和贪婪地积累贡献，同时跟踪可用容量。

 ## 算法演练

 1. 计算每种武器的净成本`d_i = a_i - b_i`请注意，每个完整周期都会提供 2 点经验值。 这从重复消耗资源而不是离散行动的角度重新定义了问题。 
2. 按武器净成本对武器进行排序`d_i`按递增顺序。 原因是更便宜的净成本允许任何固定金属堆更多的重复，因此必须首先考虑它们以最大化总周期。 
3. 对于每个金属堆`c_j`，我们从概念上希望从最小的开始应用武器`d_i`, 反复相减`d_i`从剩余的金属中，同时`c_j`足够大。 每次减法对应一个完整的锻造-熔化循环并贡献 2 点经验。 
4. 不要独立模拟每个堆，而是将所有堆聚合成单个多组可用资源。 我们通过维护可用锭的运行总数并贪婪地将它们花在最便宜的净成本武器上来集体处理它们。 
5. 对于按排序顺序的每种武器，计算它可以在所有剩余资源中应用的次数。 这是通过将可用锭除以得出的`d_i`，但我们必须确保不会重复计算早期、更便宜的武器已经消耗的使用量。 
6. 积累经验`2 * number_of_cycles`对于每种武器并相应地减少可用资源池。 
7. 处理完所有武器后，任何剩余的锭都无关紧要，因为无法执行进一步的完整循环。 

### 为什么它有效

 正确性来自于关于运营的全球交换争论。 任何有效的锻造和熔化顺序都可以重新安排，以便在不改变可行性或总体经验的情况下，所有更便宜的净成本武器的使用都发生在更昂贵的武器之前。 由于每个周期都是独立的并且仅消耗网络资源，因此交换操作永远不会减少可实现的周期数。 这保证了基于净成本的贪婪排序产生了可用金属的最佳循环打包。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    total = sum(c)

    weapons = [(a[i] - b[i]) for i in range(n)]
    weapons.sort()

    ans = 0
    remaining = total

    for d in weapons:
        if remaining <= 0:
            break
        if d <= 0:
            continue

        cnt = remaining // d
        ans += 2 * cnt
        remaining -= cnt * d

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先将所有金属堆折叠成一个总数，因为一旦我们根据每个周期的净消耗进行推理，只有可用金属锭的总数才重要。 我们计算每种武器的净成本并对其进行排序，确保我们始终首先尝试最有效的转换。 

在移动到下一个武器之前，循环贪婪地为每个武器分配尽可能多的周期。 这`remaining`变量跟踪有多少锭仍可用于未来的周期。 每次我们使用武器时`cnt`有时，我们会准确扣除消耗的资源，为以后的决策保留正确性。 

一个微妙的点是跳过`d <= 0`。 如果`a_i == b_i`，该武器产生一个自由循环，意味着无限的经验，但约束禁止这样做，因为`b_i < a_i`。 尽管如此，保护仍可确保稳健性。

 所有金属都会被最便宜的转变所消耗，立即产生最大的循环。 这证实了优先考虑较小的净成本主导了所有替代方案。

 ## 边缘情况

 一种极端情况是所有武器相对于可用金属的净成本都很高。 例如，如果`c = [3]`和所有`a_i - b_i >= 5`，则不可能有循环。 该算法正确地产生零，因为每个`remaining // d`评估为零。 

另一种情况是一种武器的净成本比所有其他武器小得多。 认为`d = [1, 100, 100]`并且总金属量很大。 贪婪步骤首先使用最小的成本消耗几乎所有东西，不为更大的成本留下任何东西。 任何替代订购只会减少总周期，因为较早在较大成本上花费金属会减少以后的廉价周期数量。 

最后一个微妙的情况是剩余金属仍然小于所有净成本。 例如，经过处理后，`remaining = 2`虽然所有`d_i >= 3`。 该算法自然终止，不会尝试无效操作，正确反映了不可能存在部分循环。
