 ## 解决方案
 ## 问题理解

 每个人都有一对意见，两部电影各有一个意见。 该意见是三元的：如果该人评论了该电影，则它会贡献 +1、0 或 -1。 我们必须将每个人分配给两部电影中的一部电影，这个选择决定了两部电影的分数。 公司分数被定义为两部电影评级中较小的一个，因此，如果一部电影落后于另一部电影，仅提高一部电影是不够的。 

核心困难在于，每个作业同时改变两部电影的总和，而目标取决于两者中的最小值，这迫使平衡而不是独立最大化。 

这些约束允许跨测试用例最多 2⋅10^5 人，这立即排除了任何显式考虑所有分配的方法。 强力分配将探索每个测试用例 2^n 种可能性，即使 n = 30 也是不可能的。即使是超过分配计数的 DP 也需要仔细压缩才可行。 

当一个人“不对称”时，例如（1，-1），就会出现一个微妙的问题。 将它们发送到电影 1 会增加它，而将它们发送到电影 2 则会减少另一部电影。 像这样的决定可能会以不明显的方式影响平衡。 例如，贪婪地将每个人分配给他们更喜欢的电影时，如果会造成不平衡，就会失败：

 示例：

 n = 2

 (1, -1), (-1, 1)

 贪心分配给一部电影+1，另一部电影+1，所以最小值就可以了。 但稍加修改的分布可能会使贪婪的选择通过使一部电影超载负片而降低最低限度。 

真正的困难在于每个人都贡献一对潜在的增量，我们必须分配它们以最大化最小的最终总和。 

## 方法

 强力解释是将每个人视为二元决策：将他们分配给电影 A 或 B，计算两个结果的总和，并取最小值。 这可以正确评估所有配置，但需要评估 2^n 分配。 对于 n = 200,000，这是完全不可行的。 

我们需要压缩问题结构。 关键的观察结果是，每个人都为所选电影贡献了一种价值，但对另一种价值没有任何贡献。 这意味着我们将加权项目分配到两个垃圾箱中，只有垃圾箱总数才重要。 

重写贡献会有所帮助：如果我们将人 i 分配给电影 1，我们将 a_i 添加到 S1； 如果是电影 2，我们将 b_i 添加到 S2。 我们想要最大化 min(S1, S2)。 

我们不考虑任务，而是考虑平衡贡献。 假设我们猜测最低评级的目标值 X。 我们可以问：是否可以分配人员使得 S1 ≥ X 且 S2 ≥ X？ 

这将问题转化为可行性检查。 如果我们可以检查 X 的可行性，我们就可以二分搜索答案。 

现在修复X并独立分析每个人。 对于每个人来说，存在三种有意义的情况：

 如果 a_i ≥ 0 且 b_i ≥ 0，则它们是“安全的”并且总是帮助任何一方。 

如果两者都是负面的，那么无论放置如何，它们都是有害的，并且只会降低可行性。 

如果出现混合迹象，则分配很重要：我们希望避免向已经接近阈值的电影发送强烈的负面贡献。 

为了准确起见，我们将可行性重新解释为分配“赤字”。 每部电影从 0 开始，需要达到 X。每个任务要么有助于满足 S1，要么有助于满足 S2。 我们优先考虑可降低较大风险的任务。

然而，一旦我们观察到更强的结构简化，二分搜索就没有必要了：最佳答案是通过使用局部配对逻辑贪婪地平衡贡献来确定的。 每个人都可以根据他们是否更适合电影 1 或电影 2 进行分类，我们希望将他们分配到危害较小或有益的一侧，同时确保积极和消极的全球平衡。 

干净的减少是计算每部电影可以独立获得多少收益，然后通过匹配双方之间的“权衡”来解决耦合问题。 标准解决方案最终根据贡献差异进行排序或分组，并通过平衡边际收益确保最小值最大化。

 ## 算法演练

 关键的想法是区分每部电影可以获得多少收益，然后解决人们更喜欢一部电影而不是另一部电影的冲突。 

1. 计算每个人对两部电影的贡献 (a_i, b_i)。 我们将它们分配给电影 1 解释为将 a_i 添加到 S1，或者将它们分配给电影 2 解释为将 b_i 添加到 S2。 这是我们控制的原子决策。 
2. 定义差值 d_i = a_i - b_i。 这衡量了与电影 2 相比，电影 1 对于该人来说有多好。如果 d_i 大，则将他们分配给电影 1 相对更有利。 
3. 按 d_i 对人员进行排序。 这种排序反映了每个人对一部电影的“偏见”程度。 它使我们能够考虑将人们从一部电影转移到另一部电影的过渡。 
4. 从初始分配开始，每个人都去看电影 2。然后 S2 固定为 sum(b_i)，S1 为 0。我们将逐渐将人们移至电影 1。 
5. 当我们将前 k 个人（按排序顺序）移至电影 1 时，我们更新：

 S1增加a_i，减少b_i不再计入S2，而S2相应减少。 通过使用 d_i 进行前缀调整来捕获净效果。 
6. 在每个前缀 k 之后，计算 S1(k) 和 S2(k)，并评估 min(S1(k), S2(k))。 跟踪所有 k 的最大值。 
7. 返回观察到的最佳值。 这是有效的，因为每个最佳解决方案都对应于一个阈值分割：所有 ​​d_i 较小的人都去一侧，其他人去另一侧。 

### 为什么它有效

 按 d_i 排序可确保每当我们将一个人从电影 2 交换到电影 1 时，我们都会首先选择最有利的交换。 任何将不按此顺序混合决策的最佳分配都可以转换为尊重此顺序的分配，而不会降低任何一部电影的分数平衡。 此交换参数保证最佳分割发生在排序数组中的单个边界处，因此检查所有前缀切割就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        pairs = []
        base = 0
        
        for i in range(n):
            pairs.append((a[i] - b[i], a[i], b[i]))
            base += b[i]
        
        pairs.sort()
        
        s1 = 0
        s2 = base
        ans = min(s1, s2)
        
        for d, ai, bi in pairs:
            s1 += ai
            s2 -= bi
            ans = max(ans, min(s1, s2))
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现使用“从分配给电影 2 的所有内容开始”的观点。 变量`base`是电影 2 的总初始分数。当我们将一个人移动到电影 1 时，我们将他们的贡献添加到`s1`并从中删除他们的`s2`。 这可以保持正确的全局状态，而无需重新计算总和。 

排序依据`a_i - b_i`确保每一步都是该阶段最有利可图的互换，这正是交换论点所需要的。 

一个常见的错误是忘记移动一个人会同时改变两侧，而不仅仅是增加一侧。 该代码通过显式减去来处理这个问题`b_i`从`s2`。 

## 工作示例

 ### 示例 1

 输入：

 n = 3

 我们计算差异和初始状态。 

| 步骤| 已选套装| S1 | S2 | 分钟（S1，S2）|
 | --- | --- | --- | --- | --- |
 | 初始| 无 | 0 | 0 | 0 |

 | 移动 3 | (-1, 0) | 0 | 1 | 0 |

 最佳分割发生在移动两个元素之后，给出答案 1。这表明最佳解决方案取决于前缀切割，而不是任意分组。

这些痕迹证实平衡是由单一阈值而不是混合分配产生的。

 ## 边缘情况

 当两部电影的所有贡献都是负数时，就会出现极端情况。 在这种情况下，每项任务至少减少一部电影，最好的策略是平均分配伤害而不是集中伤害。 

例如：

 n = 2

 a = [-1, -1]

 b = [-1, -1]

 运行算法：

 初始 S2 = -2

 排序后的差异是相等的，因此顺序是任意的。 

任何移动后，S1 和 S2 都保持相等的负值，并且最大最小值仍为 -1。 该算法通过分摊损害而不是将所有内容分配给一部电影，正确地避免了日益恶化的不平衡。 

另一种极端情况是所有差异都相同。 在这种情况下，每个前缀都会产生相同的结构，并且算法仍然会毫无歧义地评估所有有意义的分割。
