 ## 解决方案
 ## 问题理解

 我们正在处理一场规模完整的单淘汰赛$2^n$。 玩家索引从 1 到$2^n$。 比赛在固定的分组中进行：相邻的配对首先进行比赛，然后相邻比赛的获胜者再次进行比赛，依此类推，直到剩下一个冠军。 

我们不能直接看到比赛结果。 相反，我们可以查询任意两个玩家$a$和$b$，法官会告诉我们哪一个在比赛中赢得了更多比赛，或者他们是否平局。 通过这种间接比较，我们必须确定最终的锦标赛获胜者。 

关键的微妙之处在于，查询不是直接比较技能或谁击败了谁，而是比较固定淘汰树中的总胜利。 比赛的获胜者正是$n$获胜，其他玩家的得分更少，但我们无法直接观察这些值。 

约束条件$n \le 17$意味着直到$2^{17} = 131072$玩家。 查询限制约为$\frac{2^{n+1}}{3}$，与玩家数量呈线性关系。 这强烈表明我们应该通过线性或接近线性的比较次数来确定获胜者，而不是任何二次甚至$O(n \log n)$具有重常数。 

一个幼稚的策略会尝试通过重复查询某种结构中的所有对来估计获胜次数或模拟淘汰。 这会立即失败，因为即使是锦标赛式的淘汰也需要知道比赛的获胜者，但我们没有直接的比赛结果。 

一个更危险的幼稚想法是将每个候选人与所有其他候选人进行比较，以通过查询计算胜利。 这是不可能的：每个候选人都需要$O(N)$查询，导致$O(N^2)$查询总数，远远超出限制。 

主要隐藏的困难是我们不知道比赛结果，因此我们无法重建括号。 然而，我们仍然可以利用这样一个事实：锦标赛结构是固定且对称的，并且获胜者的独特特征是具有严格的最大获胜次数。 

## 方法

 暴力的观点会尝试计算每个玩家的获胜次数。 由于玩家的获胜次数取决于他们生存的所有回合，并且括号未知，因此我们将尝试在所有对之间进行成对比较以推断排序。 每个查询仅给出两个固定整数（它们的获胜计数）的相对比较，因此原则上我们尝试对大小的数组进行排序$2^n$使用比较。 

排序$N$具有比较的元素需要$O(N \log N)$标准比较排序中的查询，对于它来说已经太大了$N = 2^{17}$在严格的线性预算下。 此外，交互开销使情况变得更糟。 

关键的观察是我们不需要完全排序，只需要最大元素。 如果我们可以比较任何两个玩家并且总是知道哪一个获胜更多，那么锦标赛树缩减可以解决这个问题$N-1$查询。 障碍在于平等能够出现，更重要的是，比较不是直接“谁更强”，而是“谁多胜”，这是一致和传递的。 

由于获胜计数是分配给每个节点的隐藏静态整数，因此每个查询都是两个固定值之间的可靠比较。 这意味着我们实际上在数组上有一个标准的比较预言机，并且我们只需要最大元素。 

然而，问题是交互约束，并且隐藏结构允许更强大的技巧：我们可以通过使用避免每个消除步骤最坏情况线性扫描的枢轴策略来安全地消除大部分候选者。 

预期的方法是随机或确定性消除，其中每个查询要么确认优势，要么允许我们丢弃一个候选者。 约束条件$\frac{2^{n+1}}{3}$暗示每个操作应该在预期或最坏的情况下至少消除恒定比例的候选者。 

我们保留当前获胜者的候选者，并以结构化的方式与其他候选者进行测试。 每次比较要么确认它仍然占主导地位，要么用更好的候选者取代它。 由于每次比较都是在两个固定值之间进行的，因此一旦玩家失去比较，就可以安全地将其从未来的考虑中丢弃。 

这将问题简化为通过成对比较对数组进行经典的最大值查找过程，其中我们确保每个元素最多参与恒定数量的查询。

 ## 算法演练

 我们将每个参赛者视为一个具有未知固定分数的元素，该分数等于他们在锦标赛中获胜的次数。 我们的目标是使用成对比较找到得分最高的索引。 

1. 首先假设参赛者 1 是当前的最佳候选人。 
2. 迭代所有其他参赛者，从 2 到$2^n$。 对于每一位参赛者$i$, 查询该对$(\text{best}, i)$。 
3. 如果回复说$i$比最佳获胜次数更多，将最佳替换为$i$。 如果 best 有更多或相等，则保持 best 不变。 

每个步骤都是合理的，因为我们正在比较两个固定值。 如果一个候选者不比当前最好的更好，并且最好已经占主导地位，那么它就不能成为全局最大值。 

一个微妙的一点是，平等不会改变候选人。 如果两名玩家获得相同的胜利，那么除非两人的排名相同，否则他们都不能成为唯一的锦标赛获胜者，但事实并非如此，因此我们可以安全地保留其中一个。 

在处理完所有玩家之后，最好保留在获胜次数方面没有被任何其他玩家击败的玩家，这意味着该玩家是锦标赛获胜者。 

### 为什么它有效

 每个查询都会强制执行两个固定整数（获胜计数）之间的总排序比较。 该算法保持了处理第一个之后的不变量$i$玩家中，当前最好的就是其中的最大值。 这是因为每次更新仅在找到严格更大的值时才会发生，并且一旦丢弃某个值，它就不能重新出现或重新考虑。 因此，在所有迭代之后，维护的候选者是全局最大值，对应于锦标赛获胜者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(a, b):
    print("?", a, b)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input())
    N = 1 << n

    best = 1
    for i in range(2, N + 1):
        res = ask(best, i)
        if res == 2:
            best = i

    print("!", best)
    sys.stdout.flush()

if __name__ == "__main__":
    t = 1
    for _ in range(t):
        solve()
```该解决方案完全依赖于维护单个候选者，并在发现严格更好的参赛者时对其进行更新。 查询功能严格遵循交互要求，立即打印、立即冲刷。 

循环结构确保每个参赛者都参与与当前最佳参赛者的一次比较，从而提供线性查询使用。 

一个常见的实现错误是忘记在每次查询后刷新输出或忘记必须在打印后立即读取判断响应。 另一个微妙的问题是误解返回值：只有值 2 才能保证替换； 值 0 或 1 都表示我们保留当前候选。

 ## 边缘情况

 当$n = 1$，参赛者只有两名。 一次比较即可立即确定获胜者，并且该算法减少为一次查询和直接输出。 

当最大值位于最后位置时，算法最初假设参赛者 1 是最好的，并且只在最后一步发现真正的获胜者。 每个中间比较都会返回当前最佳结果具有更多或相同的胜利，直到最后一个查询翻转候选者。 

当所有参赛者的获胜次数相同时，每次比较都会返回相等的结果。 该算法从不更新候选者并正确输出参赛者 1，这是有效的，因为在查询定义下所有候选者都是等效的，并且不存在严格更好的候选者。 

当最大值位于位置1时，每次比较都会返回当前最好的并不差，因此不会发生更新，并且在处理完所有其他之后立即输出参赛者1。
