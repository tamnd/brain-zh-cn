 ## 解决方案
 ## 问题理解

 我们正在开发一个网格，允许在四个基本方向上移动，并且每一次移动都会花费一步。 该网格上放置了多个点，但有一个限制：每个点严格位于其中一个轴上，这意味着它的 x 坐标为零或 y 坐标为零。 我们的任务是从原点开始，以任意顺序访问所有这些点，然后返回原点，同时最小化总移动成本。 

重新构建任务的一个有用方法是每个点都位于穿过原点的水平或垂直线上。 x 轴上的点位于 y = 0 线上，y 轴上的点位于 x = 0 上。由于移动是曼哈顿距离，因此点之间的移动会沿着轴对齐线段进行累加。 

每个测试的输入大小很小，但测试用例的数量可能很大。 每个测试最多包含 100 个点，因此每个测试的二次或三次解已经是安全的，但我们应该瞄准基于线性或近线性观察的解。 测试中的总点数不受限制，这意味着每个测试解决方案的 O(n²) 仍然没问题，但每个测试用例结构的任何更糟糕的情况都是不必要的。 

一个天真的解释可能建议尝试访问点的所有排列来计算最短的闭合步行。 这会立即组合爆炸，因为有 n! 可能的订单。 对于 n ≤ 100，即使计算成对最短路径并进行旅行商动态规划解决方案也是大材小用。 

值得考虑的边缘情况来自点的简并分布：

 如果所有点都位于 (0, 0)，则不需要移动。 

如果所有点仅位于一个轴一侧，例如仅位于正 y 轴，则幼稚的策略可能仍会尝试在不必要的方向之间穿梭，但最佳路径只是走到最远的点并返回，收集途中的所有内容。 

## 方法

 蛮力的想法是将每个盒子视为一个节点，并考虑访问它们的每种可能的顺序，对连续点之间的曼哈顿距离求和并返回原点。 这是一个经典的旅行推销员公式。 正确性很简单，因为它会检查所有可能的旅行。 

失败纯粹是计算性的。 对于 n 个点，排列的数量为 n！，即使 n = 10，这也已经不可行，而这里 n 可以是 100。即使是子集上的动态规划也需要 O(n²·2ⁿ)，这远远超出了限制。 

关键的观察结果是几何形状受到严格限制。 每个点都位于与原点相交的两条直线之一上。 这意味着运动可以沿 x 轴和 y 轴方向独立分解。 在每个轴上，所有点都位于一条线上，因此访问这些点的最佳方式是减少从 0 到最远点并返回，同时扫过中间点。 

对于 x 轴，只有最大正 x 和最小负 x 很重要。 任何到达两个极端的路线都必须穿过它们之间的整个跨度，如果我们单调向外移动，中间点会自动覆盖。 相同的逻辑适用于 y 轴。 

因此，最佳策略只是计算我们必须在每个方向上走多远：最远的右、左、上、下点，并将这些距离加起来两倍，因为每个轴都需要往返。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（TSP 点数）| O(n!) | O(n) | 太慢了|
 | 最优（极值坐标）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 将点分成 x 轴和 y 轴上的贡献。 y = 0 的点导致水平移动，x = 0 的点导致垂直移动。 这种分离之所以有效，是因为一个轴上的运动不会影响另一轴。 
2. 跟踪x 轴上所有点中最大的正x 坐标。 
3. 跟踪 x 轴上所有点中的最小负 x 坐标。 
4. 跟踪 y 轴上所有点中的最大正 y 坐标。 
5. 跟踪 y 轴上所有点中的最小负 y 坐标。 
6. 计算所需的水平距离 max_x + abs(min_x)。 这代表从原点到达两个极端所需的总跨​​度。 
7. 出于同样的原因，将所需的垂直距离计算为 max_y + abs(min_y)。 
8. 返回这两个跨度总和的两倍，因为每次从原点到覆盖极值的偏移都必须返回。 

这些步骤背后的关键思想是访问一条线上的所有点不需要重新访问中间结构； 只有极端情况才能定义必要的旅行范围。 

### 为什么它有效

 x 轴上的所有点都位于一条直线 y = 0 上，因此访问最左边和最右边点的任何路线都必须遍历它们之间的整个间隔。 中间点位于该区间内，如果我们单调移动，则在遍历期间会自动访问中间点。 这同样适用于独立的 y 轴。 由于 x 轴和 y 轴上的运动在曼哈顿距离下是正交且相加的，因此总的最佳路径是每个轴的独立最佳遍历的总和，每个轴都需要从原点往返一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    
    max_x = 0
    min_x = 0
    max_y = 0
    min_y = 0
    
    for _ in range(n):
        x, y = map(int, input().split())
        if y == 0:
            max_x = max(max_x, x)
            min_x = min(min_x, x)
        else:
            max_y = max(max_y, y)
            min_y = min(min_y, y)
    
    ans = 2 * (max_x - min_x + max_y - min_y)
    print(ans)
```该实现保留了四个捕获所有点的几何包络线的运行值。 零初始化是有效的，因为原点始终是有效基线，并且任何仅轴点都会相应地调整正极值或负极值。 

最终的公式乘以2是因为我们必须在收集完所有点后返回原点，使得每个轴的遍历都是一个往返。 

## 工作示例

 ### 示例 1

 输入：```
n = 4
(0, -2), (1, 0), (-1, 0), (0, 2)
```我们追踪极端情况：

 | 步骤| 最大_x | 最小_x | 最大_y | 分钟_y |
 | --- | --- | --- | --- | --- |
 | (0,-2) | (0,-2) | 0 | 0 | 0 | -2 |
 | (1,0)| 1 | 0 | 0 | -2 |
 | (-1,0) | (-1,0) | 1 | -1 | 0 | -2 |
 | (0,2) | 1 | -1 | 2 | -2 |

 水平跨度 = 1 - (-1) = 2

 垂直跨度 = 2 - (-2) = 4

 合计 = 2 × (2 + 4) = 12

 该轨迹显示了无论订购如何，极端情况如何完全决定成本。

 ## 边缘情况

 当非原点位置只有一个点时，算法将一个轴跨度设置为零，另一个轴跨度设置为从原点到该点的距离。 例如，输入`(0, 5)`产生 max_y = 5 和 min_y = 0，产生垂直跨度 5 和最终答案 10。遍历对应于到达 (0,5) 并返回。 

当所有点都严格位于 x 轴上时，例如`(-2,0)`和`(3,0)`，y 跨度保持为零，而 x 跨度变为 5。该算法生成 10，对应于从原点到 -2，穿过原点到 3，然后返回。 

当点包含原点本身时，它不会影响任何极值。 (0,0) 处的点不提供任何运动要求，并且自然会被跨度逻辑忽略，因为所有极值保持不变。
