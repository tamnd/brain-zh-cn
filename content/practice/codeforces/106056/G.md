 ## 解决方案
 ## 问题理解

 我们有一个完整的图，其顶点从左到右编号。 通常，两个顶点之间的边的成本等于它们在这条线上的距离。 然而，少数对是特殊的：这些对有自己的给定边缘成本而不是正常距离。 任务是找到最小生成树的总权。 

困难来自于限制。 顶点的数量可以大到$10^9$，因此任何迭代顶点或构建图的解决方案都是不可能的。 同时，修改边的数量仅为$10^5$所有测试的总和，这告诉我们解决方案必须取决于特殊边而不是图的大小。 任何$O(n)$,$O(n \log n)$， 或者$O(n^2)$方法被排除时$n$很大。 

一个常见的错误是假设连续顶点之间的法线路径始终是 MST。 这会失败，因为一些连续的边可以被昂贵的特殊边替换。 例如，使用输入```
5 4
1 2 1000000000
1 3 1000000000
1 4 1000000000
1 5 1000000000
```正常的路径成本似乎是$4$，但离开顶点 1 的每条边都很昂贵。 最优答案是`1000000003`因为树必须付出一条昂贵的边来连接顶点1，而其余的顶点可以用正常的边连接。 

另一种边缘情况是没有特殊边缘时：```
5 0
```答案是`4`， 不是`0`而不是仅连接可见顶点的成本。 该解决方案必须考虑所有隐藏的普通顶点，即使我们从未明确存储它们。 

第三个棘手的情况是廉价的特殊长边：```
5 1
1 5 0
```答案是`3`。 特殊边连接两端，但仍需要附加中间三个顶点。 一种简单地用成本替换整个段的解决方案`0`是不正确的。 

## 方法

 暴力方法是在整个图上运行 Kruskal 算法。 该图有$n(n-1)/2$边缘，因此即使存储边缘也是不可能的。 什么时候$n$方法$10^9$，这个想法立刻就失败了。 

关键的观察结果是，只有出现在特殊边中的顶点才会表现出与法线不同的行为。 让我们称这些顶点为重要的。 最多有$2m$其中，所以只有$O(m)$相关职位。 

想象一下删除所有不重要的顶点。 它们位于重要顶点之间的连续线段中。 每个这样的段都是一条普通链。 线段的内部顶点总是需要相同数量的连接成本，并且我们可以在不存储它们的情况下考虑它们。 

假设两个连续的重要顶点是$a$和$b$。 如果$b-a>1$，它们之间有内部顶点。 这些内部顶点贡献$b-a-1$不可避免的单元边缘。 支付该费用后，两个重要顶点之间的剩余连接始终可以用一个单位边建立，除非顶点实际上是相邻的。 如果$a$和$b$相邻，没有隐藏顶点来帮助我们，因此必须使用真实的边成本。 

这让我们可以构建一个压缩图。 它的顶点只是重要的顶点。 答案是删除的普通顶点的数量加上该压缩图的 MST 成本。 我们在连续的重要顶点之间添加所有特殊边和必要的链边。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n²) | 太慢了 |
 | 压缩克鲁斯卡尔 | O(m log m) | O(米) | 已接受 |

 ## 算法演练

 1. 收集出现在特殊边中的每个顶点。 还包括顶点`1`和`n`，因为它们是线的边界。 对这些重要的顶点进行排序并删除重复的顶点。 这些顶点的数量很少，因为它受到特殊边数量的限制。 
2. 统计不重要的顶点数量。 它们永远不需要出现在压缩图中，但它们仍然为最终的树提供边。 他们的贡献是`n - important_count`。 
3. 在压缩图中为每个特殊边创建边。 这些边保留其原始权重，因为它们正是可以改善或恶化 MST 的不寻常选择。 
4. 按排序顺序连接每对连续的重要顶点。 如果它们在原始图中相邻，则如果存在这样的边，则使用特殊权重，否则使用权重`1`。 如果它们之间至少有一个法线顶点，则使用权重`1`因为剩余的连接始终可以通过链进行。 
5. 在压缩图上运行 Kruskal 算法。 将生成的 MST 成本添加到不重要顶点的贡献中。 

为什么它有效：每个不重要的顶点都属于一条简单的线段，没有特殊的边与之接触。 这些顶点无法创建新的有用的快捷方式，因此它们的唯一作用是添加固定数量的单位成本连接。 所有可能影响 MST 的选择都发生在重要顶点之间，并且压缩图会保留每个此类选择。 由于 Kruskal 找到了压缩图的最小生成树，因此添加固定段成本即可得到原始 MST。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, m, data):
    specials = {}
    important = {1, n}

    for u, v, w in data:
        specials[(u, v)] = w
        important.add(u)
        important.add(v)

    pts = sorted(important)
    idx = {x: i for i, x in enumerate(pts)}
    k = len(pts)

    edges = []

    for (u, v), w in specials.items():
        edges.append((w, idx[u], idx[v]))

    for i in range(k - 1):
        a = pts[i]
        b = pts[i + 1]
        if b - a == 1:
            w = specials.get((a, b), 1)
        else:
            w = 1
        edges.append((w, i, i + 1))

    edges.sort()

    parent = list(range(k))
    size = [1] * k

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return False
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]
        return True

    ans = n - k
    used = 0

    for w, a, b in edges:
        if union(a, b):
            ans += w
            used += 1
            if used == k - 1:
                break

    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        data = []
        for _ in range(m):
            u, v, w = map(int, input().split())
            data.append((u, v, w))
        out.append(str(solve_case(n, m, data)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```字典`specials`用于快速检查一对连续的重要顶点是否是修改边。 这避免了在构建压缩图时扫描所有特殊边。 

数组`pts`仅包含压缩顶点。 DSU 基于这些索引而不是原始顶点数，这是必要的，因为原始图最多可以有$10^9$顶点。 

价值`ans = n - k`考虑了压缩期间删除的普通顶点。 它们中的每一个都只需要一个单位成本连接。 剩余的成本来自压缩图上的 MST。 

一个微妙的细节就是条件`b - a == 1`。 只有在这种情况下，两个重要的顶点在原图中才真正相邻，因此特殊的边可以阻挡正常的单元边。 否则，隐藏的顶点允许我们保持单位连接。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m log m) | 对压缩边缘进行排序是工作的主导部分
 | 空间| O(米) | 仅存储特殊边和重要顶点 |

 压缩图最多有$2m+2$顶点和$O(m)$边，因此即使原始图有数十亿个顶点，它也很容易满足约束条件。

 ## 边缘情况

 对于特殊边覆盖整条线的情况：```
5 1
1 5 0
```压缩图只有顶点`1`和`5`。 三个不重要的顶点贡献`3`。 被压缩的边缘有重量`0`，所以最终的答案是`3`。 该算法保留了隐藏链成本，而不是错误地将捷径视为完整的解决方案。 

对于昂贵的相邻特殊边：```
5 4
1 2 1000000000
1 3 1000000000
1 4 1000000000
1 5 1000000000
```没有隐藏的顶点，因此答案完全来自压缩图。 Kruskal 避免了除了连接顶点 1 所需的边之外的所有昂贵边。 

对于空的情况：```
5 0
```该算法仅创建端点。 压缩边成本`1`，并且删除的中间顶点添加`3`，给出正确的 MST 成本`4`。
