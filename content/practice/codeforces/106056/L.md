 ## 解决方案
 ## 问题理解

 该网格描述了一个小社区，布局为 R by C 地图。 每个单元格要么是封闭的，要么是可自由步行的，要么是候选房屋位置，要么是学校，要么是公园。 只允许在正交相邻的可步行单元之间移动，并且每次移动只花费一步。 

该公司想知道哪些房屋实际上可以在限制条件下出售：只有当从房屋到学校和公园的距离最多为 D（以网格步数测量）时，买家才会接受该房屋。 仅当 D 步内至少存在一所学校且 D 步内至少存在一个公园且路径受封锁单元格限制时，房屋才有效。 

任务是计算有多少个房屋单元满足这两个可达性条件。 

网格大小最多为 30 x 30，因此最多有 900 个单元格。 即使距离限制高达 1000，状态空间也很小，这强烈表明来自多个源的最短路径计算是可行的。 

一个天真的想法是分别运行每个房屋的 BFS，然后搜索学校和公园。 这意味着在 900 个单元的网格上运行多达 900 个 BFS，每个成本为 O(RC)，这已经是临界值，但仍然合理。 然而，如果每个BFS也独立地搜索两个目标，或者重复地重新启动昂贵的工作，那么就变成了不必要的重复。 

当人们在找到任何学校或公园后试图尽早停止 BFS 时，就会出现幼稚本地搜索的一个微妙的失败案例。 例如，一栋房子可能会很快找到附近的学校，但最近的公园可能位于网格中完全不同的区域，需要全面探索。 如果不针对两种目标类型单独处理，基于部分发现的提前停止可能会导致错误修剪。 

当使用 DFS 独立计算每个房屋的距离而不进行记忆时，会发生另一个错误。 在带有走廊的网格中，这会多次重新计算相同的最短路径，并导致实践中出现冗余的指数探索模式。 

## 方法

 暴力方向将每个房子视为一个查询点。 从每栋房屋开始，我们在网格上进行最短路径搜索，直到到达学校和公园或耗尽所有可到达的单元格。 每个 BFS 都是 O(RC)，因此总复杂度变为 O(HRC)，其中 H 是房屋数量。 在最坏的情况下，H 接近 RC，这导致大约 O((RC)^2)。 当 RC 达到 900 时，这可以接近大约 810,000 次小区访问，这仍然是临界值，但包括重复扫描开销和每个 BFS 两次单独的目标搜索。 如果仔细实施，它可能会通过，但从概念上讲这是浪费，因为每个 BFS 都会从头开始重复相同的探索。 

关键的观察结果是所有房屋共享相同的环境，并且成本指标是统一的。 这建议扭转观点：不要计算从每所房屋到学校和公园的距离，而是计算从所有学校到每个单元格的距离，并分别计算从所有公园到每个单元格的距离。 这是一个经典的多源BFS思想。 一旦知道这两个距离场，就可以通过检查两个距离是否在 D 范围内，以 O(1) 的时间复杂度评估每个房屋。 

这种转换之所以有效，是因为未加权网格中的最短路径距离独立于起始查询集。 来自所有源的 BFS 同时生成到该类型的最近源的正确最小距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个房子的暴力 BFS | O((RC)^2) | O((RC)^2) | O(RC) | 可以接受但没有必要 |
 | 来自学校和公园的多源 BFS | O(RC) | O(RC) | 已接受 |

 ## 算法演练

 我们计算两张独立的距离图：一张用于学校，一张用于公园。

1. 收集所有学校单元并同时从所有单元开始运行 BFS。 将它们的距离初始化为零并将它们推入队列。 每次我们扩展一个单元格时，如果我们发现更短的距离，我们就会放松它的四个邻居。 这产生了每个单元到最近学校的最小距离。 
2. 对公园重复相同的过程，生成第二个距离网格，用于存储从每个单元格到最近公园的最小距离。 
3. 迭代网格中的所有单元格。 每当我们遇到一个房屋单元格时，我们都会检查它在两个距离网格中的值。 如果两个距离都小于或等于 D，我们就认为这栋房子是有效的。 
4. 输出有效房屋总数。 

BFS 扩展可以正确工作，因为队列的每一层都对应于距源集的不断增加的距离，并且一旦以尽可能小的距离访问单元，由于统一的边权重，任何未来到达该单元的路径只会更长。 

### 为什么它有效

 该算法保持不变式，即当从 BFS 队列中弹出一个单元时，其记录的距离等于距该类型的任何源（学校或公园）的最短可能距离。 由于所有边的成本相同，BFS 按距离递增的顺序进行探索，并且多源初始化不会改变正确性，因为所有源都从距离零开始并同时向外传播。 因此，计算出的距离网格分别准确地代表了到最近学校和最近公园的真实最短路径距离。 

当且仅当满足两个最短路径约束时，房屋才是有效的，并且由于两个约束都是使用正确的距离函数独立检查的，因此没有交互作用可以使结果无效。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(starts, grid, R, C):
    INF = 10**9
    dist = [[INF] * C for _ in range(R)]
    q = deque()

    for r, c in starts:
        dist[r][c] = 0
        q.append((r, c))

    dr = [1, -1, 0, 0]
    dc = [0, 0, 1, -1]

    while q:
        r, c = q.popleft()
        for k in range(4):
            nr, nc = r + dr[k], c + dc[k]
            if 0 <= nr < R and 0 <= nc < C:
                if grid[nr][nc] != '#':
                    if dist[nr][nc] > dist[r][c] + 1:
                        dist[nr][nc] = dist[r][c] + 1
                        q.append((nr, nc))

    return dist

R, C, D = map(int, input().split())
grid = [list(input().strip()) for _ in range(R)]

schools = []
parks = []
houses = []

for i in range(R):
    for j in range(C):
        if grid[i][j] == 'S':
            schools.append((i, j))
        elif grid[i][j] == 'P':
            parks.append((i, j))
        elif grid[i][j] == 'H':
            houses.append((i, j))

distS = bfs(schools, grid, R, C)
distP = bfs(parks, grid, R, C)

ans = 0
for r, c in houses:
    if distS[r][c] <= D and distP[r][c] <= D:
        ans += 1

print(ans)
```BFS 函数一般是为学校和公园编写的。 关键的实现细节是在启动队列之前初始化距离为零的所有源，这就是将其变成多源 BFS 的原因。 网格检查`grid[nr][nc] != '#'`确保我们永远不会遍历阻塞的单元格。 

一个常见的错误是忘记 BFS 必须将所有源视为同时启动。 如果相反，每个源单独运行 BFS，然后手动获取最小值，则该解决方案会变得更慢且冗余。 

另一个微妙之处是使用较大的哨兵值进行初始化。 这可以避免与未初始化数据的意外比较，并确保任何可到达的单元得到适当的放松。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(RC) | 每个 BFS 最多访问每个单元一次，我们运行两次 BFS 遍历 |
 | 空间| O(RC) | 两个距离网格加上最多 RC 单元上的队列 |

 网格最多有 900 个单元，因此即使开销系数恒定，该解决方案也能在限制内轻松快速。 即使对于最大距离约束，该方法仍然有效，因为 BFS 复杂性取决于结构，而不是 D。

 ## 边缘情况

 当一所房子被开放式牢房包围，但通过一堵薄墙与所有学校隔开时，就会出现一种边缘情况。 在这种情况下，来自学校的 BFS 永远不会到达房屋单元，因此它的距离仍然是无限的，并且最终检查正确地拒绝它。 

另一种情况是有多所学校或公园。 多源 BFS 自然地通过在距离零处初始化所有源来处理这个问题。 距离场成为所有可能源中的最小值，因此无论存在多少个设施，最近的设施始终占主导地位。 

最后一种边缘情况是 D 非常大时。 即使D超过网格直径，答案仍然只取决于可达性，而不取决于D本身的值。 该算法可以正确处理这个问题，因为距离是精确计算的，并且无论比例如何，阈值比较仍然有效。
