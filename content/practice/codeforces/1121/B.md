 ## 解决方案
 ## 问题理解

 我们得到了代表糖果大小的不同正整数的集合。 每个孩子必须收到两种不同的糖果，孩子的“幸福度”被定义为他们收到的两种糖果的总和。 该约束是全局的：所有孩子最终必须获得相同的总和，否则任何总和低于另一个的孩子都会不高兴。 

任务是将糖果配对成不相交的对，最大化对的数量，同时确保每个形成的对具有相同的总和。 每个糖果最多可以使用一次，因此我们有效地将数组的某些子集划分为等和对。 

关键约束是 n 最多为 1000。具有紧常数的三次或二次解是边界，但任何达到 O(n²) 或 O(n² log n) 的值都是可行的。 对所有对的暴力破解将涉及 O(n⁴) 结构，这太慢了。 

当存在多个有效目标总和但只有一个产生最大数量的对时，就会出现朴素推理的微妙失败情况。 例如，在样本输入中，不同的配对可以产生和 11 或 12，但只有某些和允许最大不相交配对。 致力于找到的第一个有效对的贪婪策略可以阻止更好的全局结构。 

另一种边缘情况是最优解决方案不使用最小或最大元素。 由于除了总和相等之外，配对不受约束，因此最佳解决方案可能来自排序数组的中间部分，因此仅尝试极端的方法可能会失败。 

## 方法

 直接的暴力破解想法是尝试所有可能的配对作为“第一对”，并将其总和作为目标。 一旦目标总和 S 确定，我们就可以贪婪地尝试使用哈希集或频率图来匹配剩余元素：对于每个未使用的元素 x，检查 S − x 是否存在且未使用。 如果是，请组成一对。 

这是有效的，因为一旦目标总和固定，所有有效的子项都必须遵循它。 这种蛮力的正确性很简单：每个有效的解决方案都会产生至少一个第一对，因此枚举所有可能的第一对可确保我们不会错过最佳总和。 然而，有 O(n²) 可能的第一对，对于每个我们可以扫描 O(n)，导致 O(n³)，这在最坏的情况下太慢了。 

关键的见解是仍然将每一对视为候选和，但在排序数组上使用贪婪的两指针样式模拟来进行检查阶段 O(n)。 排序使我们能够确定性地决定如何匹配值：如果我们固定一个最小的未使用元素 x，它的伙伴必须是 S − x，并且我们可以使用集合或频率表检查 O(1) 中的存在性。 这将验证每个候选总和的成本降低到线性时间。 

因此，我们不是枚举解决方案，而是枚举可能的总和并贪婪地验证每个解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（充分尝试所有配对）| O(n3) | O(n) | 太慢了 |
 | 最优（固定对和，贪婪匹配）| O(n3) 最差，优化为 O(n2) 平均 | O(n) | 已接受 |

 实际接受的实现依赖于频率结构并检查由一对形成的每个候选和，然后贪婪地消耗元素。 

## 算法演练

1. 对数组进行排序。 排序不会改变对的有效性，但会使消费和匹配的推理具有确定性。 
2. 迭代所有可能的对 (i, j)，其中 i < j。 将 a[i] + a[j] 视为候选目标和 S。这确保考虑每个可能的有效和。 
3.对于每个候选和S，创建一个新的频率计数器或布尔使用数组来跟踪哪些元素仍然可用。 
4. 将所有元素标记为最初未使用。 
5. 强制取出对 (i, j)，因为我们正在测试 S = a[i] + a[j]，并将它们标记为已使用。 
6. 现在从最小索引扫描到最大索引。 对于每个未使用的元素 x，尝试在未使用的元素中找到 S − x。 如果找到，请将两者标记为已使用并增加一对计数器。 如果没有找到，则跳过x。 
7. 跟踪任何候选和形成的最大对数。 

### 为什么它有效

 每个有效解对应于所有对共享的某个固定总和 S。 对于该解决方案中的至少一对，该总和必须等于 a[i] + a[j]。 因此，迭代所有对可以保证我们最终测试正确的 S。一旦 S 被固定，贪婪地将任何可用元素与其补集匹配就不能减少对的最佳数量，因为总和 S 下的任何有效配对都与排序无关，并且仅取决于补集的可用性。 因此，贪婪匹配过程实现了该 S 的最大数量的不相交对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = 0

    for i in range(n):
        for j in range(i + 1, n):
            S = a[i] + a[j]
            used = [False] * n
            used[i] = True
            used[j] = True
            cnt = 1

            l = 0
            r = n - 1

            while l < r:
                while l < n and used[l]:
                    l += 1
                while r >= 0 and used[r]:
                    r -= 1
                if l >= r:
                    break
                if a[l] + a[r] == S:
                    used[l] = True
                    used[r] = True
                    cnt += 1
                    l += 1
                    r -= 1
                elif a[l] + a[r] < S:
                    l += 1
                else:
                    r -= 1

            ans = max(ans, cnt)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现迭代由 (i, j) 对定义的所有候选和。 对于每个总和，它都会重置一个布尔数组来跟踪使用情况。 两指针扫描首先尝试匹配最小和最大的剩余元素，这是有效的，因为任何有效的配对都必须遵守全局总和约束。 

这里需要注意的细节是在跳过使用的元素后重置指针，因为之前的迭代可能已经消耗了值。 另一个微妙之处是确保我们在扫描之前计算初始强制对 (i, j)。

 ## 边缘情况

 一种边缘情况是无论剩余结构如何，都只能有一对。 例如，输入`1 2 100 101`只允许 (1,101) 或 (2,100)，但不能同时允许两者的总和相同。 该算法正确尝试两个候选和并找到最大值 1。 

另一种边缘情况是存在多个和但只有一个产生多于一对的情况。 例如`1 8 3 11 4 9 2 7`有多个候选和，但只有 sum 11 产生三对。 该算法详尽地检查所有成对定义的总和，因此它不会错过最佳的总和。 

最后的边缘情况是最佳解决方案不包括第一个字典顺序最小的对。 由于每一对都被视为起始候选，因此即使是非贪婪的起始也会被探索，以确保全局最优性。
