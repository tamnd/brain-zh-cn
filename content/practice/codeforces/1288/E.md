 ## 解决方案
 ## 问题理解

 我们正在维护一个动态的好友“最近聊天列表”，以 1 到 n 的数字排列表示。 该列表按从最近到最近的交互顺序排序。 每当朋友 x 收到消息时，该朋友就会移至列表的前面，而位于 x 前面的每个人都会向右移动一个位置。 

我们从身份顺序开始，这意味着朋友 i 最初位于位置 i。 在处理完所有 m 条消息后，每个朋友都被移动了多次，有时向前移动，有时由于其他朋友被拉到前面而间接向后移动。 在整个过程中，包括初始配置和每条消息后的每一个中间配置，每个好友都占据一个位置序列。 

任务是计算每个朋友在整个进化过程中占据的最小和最大位置。 

约束 n, m ≤ 3 · 10^5 立即排除任何在每次操作后显式维护完整排列的模拟。 在最坏的情况下，每条消息的数组的直接更新已经是 O(n)，这导致 O(nm)，远远超出了可行的限制。 

问题的一个微妙方面是立场不是独立的。 当一位朋友被移到前面时，它会影响所有其他朋友的位置，因此即使天真地跟踪一位朋友仍然需要全局更新。 

一些边缘案例揭示了天真的思维可能会出什么问题。 如果所有消息都来自同一个朋友，比如 1 重复 m 次，那么该朋友始终保持在位置 1，而其他消息只是最初被推回，然后稳定下来。 仅在消息时间重新计算位置的幼稚解决方案可能会错过位置变化，即使朋友没有直接参与也是如此。 

另一个边缘情况是当消息晚介绍朋友时，例如 n = 5 且消息为 [5, 4, 3, 2, 1]。 最终顺序颠倒，中间仓位波动较大； 早动的朋友的最高仓位往往发生在结束之前很久。 

关键的困难在于头寸取决于不断变化的全球秩序。 

## 方法

 蛮力方法是直接模拟。 我们维护一个表示排列的数组。 对于来自朋友 x 的每条消息，我们在数组中找到 x，将其之前的所有元素向右移动一步，并将 x 放在前面。 在此过程中，我们可以跟踪每个朋友每一步的位置并更新他们的最小值和最大值。 

除非我们维护额外的结构，否则定位 x 需要 O(n)，并且移位也需要 O(n)。 因此，每一次 m 操作都是 O(n)，从而导致 O(nm)，在最坏的情况下大约是 9 × 10^10 次操作。 这太慢了。 

关键的观察是我们实际上并不需要完整的排列演化。 对于每个朋友，我们只需要他们在特定离散时间出现的一组位置。 初始配置为朋友 i 贡献了已知位置 i。 此后，位置唯一发生变化的时间是在消息发出后立即，并且在每个这样的时刻，只有前缀结构很重要。 

我们可以跟踪每个朋友的最后一次访问时间，而不是跟踪完整的排列。 任何时刻的排序都是由新近度决定的：越新的消息对应越小的头寸。 最近见过的一个朋友离前面比较近。 

这导致了一个关键的重新表述：在任何时候，朋友的位置取决于有多少个不同的“活跃”朋友比它更近。 我们不是模拟交换，而是模拟时间戳。 每条消息都会分配一个时间索引，稍后我们会以结构化的方式处理这些时间以计算排名动态。

为了提取最小和最大位置，我们将初始位置视为固定的早期时间，然后将每条消息视为可能将好友推向位置 1，从而产生其最佳（最小）位置。 当它尽可能靠后时，就会出现最大位置，这发生在它第一次出现之前，或者当许多不同的朋友被移到它前面时。 

我们使用最后一次出现的排序来处理贡献，并随着时间的推移使用 Fenwick 树（或二叉索引树）来计算每个朋友的相关片段之前有多少“活动”事件。

 ## 算法演练

 我们将每个朋友的行为变成一个时间线问题。 

1.记录每个好友的所有留言时间。 对于好友 x，存储消息序列中 x 出现的索引列表。 这是必要的，因为每次出现都可能将 x 移动到前面，从而影响其最小位置。 
2. 为每个好友定义一个“有效最后激活时间”，作为该好友最后一次出现在消息列表中的时间。 在此之后，未来的操作将不会直接改善其地位。 
3. 计算每个朋友的最小位置。 当朋友在消息中进行处理时，它正好达到位置 1。 如果好友从未出现，则其最小位置仍为初始位置。 否则，其最小值为 1。这是根据每条消息都会将该朋友移动到前面的规则直接得出的。 
4. 较难的部分是计算最大位置。 我们按照朋友最后出现时间的升序来处理他们。 我们维护一棵 Fenwick 树，用于存储在给定时间或之前已经“激活”的好友数量。 
5. 对于朋友 x，考虑其初始位置 i。 在第一次激活之前，所有上次出现时间较早且不是 x 本身的朋友可能已经被移动到前面，因此可以将 x 向后移动。 我们计算在 x 第一次出现之前发生了多少次这样的激活，并将其添加到 i 来估计其最差位置。 
6. 我们将此值限制为 n，因为位置不能超过数组大小。 
7. 在处理每个朋友的最后一次出现时更新 Fenwick 树，以便将来的查询正确计算活动前缀。 

### 为什么它有效

 关键的不变量是，每当一个朋友出现在消息序列中时，它就严格地比按最后出现的顺序尚未处理的所有朋友更近。 因此，在任何时候，可以出现在给定好友之前的好友集合正是最后激活时间较早并且已经被考虑在内的好友集合。 这将动态排列问题简化为计算在给定阈值之前存在多少个此类“较早的最后活动”元素，这正是芬威克树所维护的。 

因为每次向前移动都对应于一个离散的激活事件，并且这些事件按时间形成总顺序，所以我们永远不会重复计算或错过对朋友最坏情况位移的任何贡献。

最终的最大值受 n 限制，因为即使在最坏的重新排列中，位置也不能超过列表大小。

 ## 边缘情况

 从未出现在消息中的朋友永远不会移动到前面，因此其最小值和最大值保持等于其初始位置。 该算法通过检查 last[x] = 0 并直接分配两个值来显式处理此问题。 例如，在输入 n = 4 和消息 [2, 3] 中，好友 1 永远不会被激活，因此它停留在位置 1。 

每条消息中出现的朋友都会立即达到最小位置 1。芬威克树确保其最大位置仍然是根据较早的激活而不是较晚的激活来计算的，因此它不会错误地累积未来的移位。 

当所有消息都相同时，例如 [1, 1, 1, 1]，芬威克树的结构仍然很简单：仅插入一个激活时间，所有其他朋友不受影响。 这可以防止实际不移动任何新元素的过度计数。
