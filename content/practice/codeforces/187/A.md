 ## 解决方案
 ## 问题理解

 我们给出了两个包含以下数字的排列`1`到`n`。 第一个排列是当前的排列，第二个排列是我们想要达到的目标排列。 

允许的操作不寻常。 在一次移动中，我们可能只取出当前排列的最后一个元素并将其插入数组中较早的任何位置，包括前面。 我们不能直接移动任意元素。 每次移动总是从当前的最后一个元素开始。 

任务是计算将第一个排列转换为第二个排列所需的此类操作的最少数量。 

约束足够大，以至于不可能采用大量模拟的解决方案。 和`n`最多`2 * 10^5`， 任何`O(n^2)`方法将围绕`4 * 10^10`最坏情况下的操作，远远超出了两秒的时间。 解决方案必须接近线性时间。 

棘手的部分是了解哪些元素可以保持固定。 由于每个操作都会删除最后一个元素，因此剩余前缀的相对顺序永远不会改变。 这意味着我们应该搜索目标排列的最大后缀，该后缀已经以正确的相对顺序出现在第一个排列中并且可以保持不变。 

一些边缘情况很容易打破天真的推理。 

考虑这个例子：```
4
1 2 3 4
1 2 3 4
```正确答案是`0`。 总是尝试从末尾开始匹配而不检查所有内容是否已对齐的粗心实现可能会错误地执行不必要的移动。 

现在考虑：```
3
3 2 1
1 2 3
```答案是`2`。 一些不正确的方法假设每个放错位置的元素都需要移动，从而产生`3`。 关键的观察是移动后`1`，顺序为`2`和`3`变得更容易恢复。 

另一个微妙的情况是：```
5
1 2 3 4 5
5 1 2 3 4
```答案是`1`。 我们只需移动`5`从结束到开始。 天真的从左到右的比较会错误地认为四个位置不同并多算。 

一种更重要的情况是只有后缀已匹配时：```
5
2 1 3 4 5
1 2 3 4 5
```答案是`2`。 后缀`[3, 4, 5]`已经是正确的并且永远不需要移动。 仅必须重建前两个元素。 

## 方法

 暴力方法将明确地模拟该过程。 在每一步中，我们都可以删除最后一个元素并尝试每个插入位置，直到出现目标排列。 这是正确的，因为它探索了所有可达状态，但排列的数量呈阶乘增长。 即使是贪婪的模拟也会变得昂贵，因为每次移动可能需要移动许多元素，从而导致`O(n^2)`行为。 

瓶颈来自于反复修改数组。 和`n = 2 * 10^5`，二次工作是不可能的。 

关键的见解是该操作仅影响最后一个元素。 任何从未被删除的元素将永远保留其相对顺序。 这意味着目标排列的某些后缀可以在整个过程中保持不变。 

假设我们从右到左扫描第一个排列，同时尝试从右到左匹配目标排列。 每当我们找到所需的目标元素时，我们都会保留它。 无法匹配的元素最终必须被移动。 

这将问题转化为寻找目标排列的最长后缀，该后缀作为第一个排列中的子序列出现。 

如果该后缀有长度`k`，那么剩下的`n - k`元素必须被移动，这个数量是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n²) 或更糟 | O(n) | 太慢了 |
 | 贪婪后缀匹配| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取两个排列`a`和`b`。 
2.从末尾开始排列`b`。 Let pointer`j = n - 1`。 该指针代表我们要保留而不移动的下一个目标值。 
3. 扫描排列`a`从右到左。 
4. 每当`a[i] == b[j]`, 递减`j`。 

这意味着我们发现了又一个可以留在原处的元素。 由于我们从末尾开始扫描，因此会自动保留相对顺序。 
5. 继续直至扫描完成。 
6. 处理完所有元素后，求出其中不匹配元素的个数`b`是`j + 1`。 

这些正是必须移动的元素。 
7. 输出`j + 1`。 

### 为什么它有效

 该操作仅删除末尾的元素。 任何从未被删除的元素都会保持其相对于所有其他未触及元素的顺序。 

当我们贪婪地匹配两个排列末尾的元素时，我们最大化可以保持固定的后缀。 每个匹配的元素都属于一个无需移动即可获得的后缀。 

任何不匹配的元素最终都必须成为最后一个元素并被移动到更早的地方。 由于贪心过程保留了最大可能的后缀，因此剩余计数就是所需操作的最小数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    j = n - 1

    for i in range(n - 1, -1, -1):
        if j >= 0 and a[i] == b[j]:
            j -= 1

    print(j + 1)

solve()
```该实现遵循演练中的精确贪婪论证。 

变量`j`跟踪目标排列中最右边的不匹配元素。 我们向后遍历第一个排列，因为只有后缀结构很重要。 每当我们遇到当前需要的值时`b[j]`，我们匹配它并移动`j`向左。 

一个微妙的细节是条件`j >= 0`。 如果没有此保护，代码可以在完全匹配目标排列后继续访问负索引。 

另一个容易犯的错误是返回`j`而不是`j + 1`。 自从`j`是一个索引，剩余不匹配元素的数量等于来自的位置数`0`通过`j`。 

该算法从不修改数组，从不模拟移动，并且只执行一次向后传递。

 ## 边缘情况

 考虑已经正确的排列：```
4
1 2 3 4
1 2 3 4
```扫描从右到左匹配每个元素：

 -`4`比赛
 -`3`比赛
 -`2`比赛
 -`1`比赛

 最终`j = -1`，所以答案就变成了`0`。 该算法正确地识别出不需要移动。 

现在检查循环移位情况：```
5
1 2 3 4 5
5 1 2 3 4
```向后扫描匹配`4`,`3`,`2`， 和`1`。 仅有的`5`仍然无与伦比。 自从`5`已经坐在最后面了，只要把它放在前面就可以解决问题。 算法输出`1`。 

最后，考虑一个几乎相反的排列：```
5
5 4 3 2 1
1 2 3 4 5
```扫描首先匹配`5`，但没有更早的元素可以匹配`4`同时维护秩序。 最大可保留后缀长度`1`，所以四个元素必须移动。 算法输出`4`，这是最优的。
