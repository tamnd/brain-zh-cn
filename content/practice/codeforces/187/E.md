 ## 解决方案
 ## 问题理解

 我们有`n`人们按照严格递增的坐标排成一行。 PMP从人开始`s`，立即算作已访问。 以后的每次移动都必须严格向左或严格向右，具体取决于该移动所使用的票证。 

左票允许从较大的索引移动到较小的索引。 正确的票证允许从较小的索引移动到较大的索引。 PMP 正好有`l`留下门票和`n - 1 - l`正确的门票，每个人都必须被拜访一次。 

任务是最小化总行驶距离并输出一个最佳访问顺序。 

第一个重要的观察结果是方向限制适用于每个单独的移动，而不是整个旅行。 只要票数匹配，PMP 就可以左右交替多次。 

坐标已排序，可以到达`10^9`，因此距离必须以 64 位整数存储。 人数最多可达`10^5`，这立即排除了任何二次方。 区间内的动态规划解决方案`O(n^2)`状态在内存和时间上都已经太大了。 我们需要一些接近线性或`O(n log n)`。 

问题的一个微妙部分是可行性。 不是每对`(l, s)`允许拜访所有人。 

认为`n = 5`,`s = 1`,`l = 2`。```
1 2 3 4 5
^
start
```从最左边的位置开始，再往左就没有人了。 留下的票永远不能使用。 正确的输出是`-1`。 

粗心的解决方案可能只检查票总数是否等于`n - 1`，这始终是正确的，但是忽略了位置约束。 

另一个容易犯的错误是假设最小化总体移动意味着总是拜访最近的未拜访过的人。 考虑：```
n = 5, s = 3, l = 2
x = [0, 1, 100, 101, 102]
```首先贪婪地去最近的一侧给出：```
100 -> 101 -> 102 -> 1 -> 0
distance = 1 + 1 + 101 + 1 = 104
```但更好的路线是：```
100 -> 1 -> 0 -> 101 -> 102
distance = 99 + 1 + 101 + 1 = 202
```实际上，这个例子展示了更深层次的东西：票证限制可能会迫使以后进行昂贵的跳跃。 局部贪婪决策不控制未来方向的可用性。 

当一侧的节点很少时，就会出现另一种危险的极端情况。```
n = 6, s = 2, l = 4
```左边只有一个节点`s`，因此在所有左侧节点耗尽之前最多可以发生一次左移。 任何有效的解决方案都必须在中间重新审视右侧并小心地花费门票。 简单的模拟经常会陷入困境，因为它们过早地消耗了一侧的所有可用动作。 

问题的真正结构来自于理解有效的方向序列是什么样的。 

## 方法

 蛮力的想法很简单。 我们可以尝试剩下的每一个排列`n - 1`人员，检查每个移动方向是否与可用票匹配，并计算总距离。 

这是可行的，因为约束在概念上很小：每个有效的游览只是顶点的排序。 问题是排列的数量。 即使是为了`n = 15`，我们已经大致有`10^12`的可能性。 

更精细的暴力破解在子集上使用 DP：```
dp[mask][last][left_used]
```它跟踪哪些人被访问过、我们当前在哪里以及消耗了多少张剩余门票。 

转换是正确的，因为每次移动仅取决于当前端点和移动方向。 但状态数量变得巨大：```
2^n * n * n
```甚至`n = 25`是不可能的，而真正的极限是`10^5`。 

所以我们需要利用线条的几何形状。 

关键的观察是每个方向类中的确切顺序几乎不重要。 重要的是我们有多少次换边。 

假设我们目前处于某个位置。 如果我们连续多次向右移动，最便宜的可能方法是按升序访问右侧节点。 任何跳过只会造成不必要的回溯。 

类似地，连续向左移动应按降序访问节点。 

这意味着每个最佳解决方案都有一个非常严格的形式。 该路径交替选取左侧最近的未访问节点和右侧最近的未访问节点。 唯一真正的选择是下一步该走哪个方向。 

现在考虑门票数量。 让：```
L = l
R = n - 1 - l
```每向左移动都会减少当前索引，每向右移动都会增加当前索引。 

开始于`s`，毕竟移动：```
final_position = s + R - L
```由于所有访问过的索引必须保持在`[1, n]`，我们得到可行性条件：```
1 <= s + R - L <= n
```替代`R = n - 1 - L`:```
1 <= s + (n - 1 - 2L) <= n
```简化为：```
s - 1 <= L <= n - s
```这个条件也足够了。 

一旦可行性成立，最优策略就会变得异常简单。 我们应该尽可能改变方向。 当我们从当前访问区间的一侧移动到另一侧时，就会发生长跳跃。 交替可以最大限度地减少这些跳跃，因为它使当前位置保持在剩余节点的中间附近。 

最优的构造是：```
left, right, left, right...
```或以右开头的对称版本，具体取决于门票数量和可用性。 

每次移动总是采用该方向上最近的未访问节点。 

这给出了线性时间结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 位掩码 DP | O(2^n · n^2) | O(2^n · n^2) | O(2^n·n) | O(2^n·n) | 太慢了 |
 | 贪婪的建设性 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`l`,`s`和坐标数组。 
2. 计算正确的票数：```
r = n - 1 - l
```1. 检查可行性。 

向左移动会减少当前索引。 由于只有`s - 1`人们离开了开始，我们不能使用超过`s - 1`留下了门票。 

类似地，也只有`n - s`人们在右边，所以我们不能使用更多的右边票。 

如果任一条件失败，则打印`-1`。 

1. 维护两个指针。`L`开始于`s - 1`，左边最近的未访问过的人。`R`开始于`s + 1`，右侧最近的未访问过的人。 

1. 贪婪地构建移动序列。 

只要有可能，请使用剩余票数较多的方向。 这可以保持旅行平衡并防止稍后滞留在一侧。 

如果我们向左移动，则追加`L`到答案并递减`L`。 

如果我们采取正确的行动，请附加`R`到答案并增加`R`。 

1. 继续直到所有`n - 1`动作被构建。 
2. 通过模拟产生的顺序来计算总距离。 

开始于`s`。 

为接下来的每一个人`v`:```
cost += abs(x[cur] - x[v])
cur = v
```1.输出总距离和访问顺序。 

### 为什么它有效

 每时每刻，向左移动可到达的最便宜的节点是左侧最近的未访问节点。 任何更远的选择都会跳过更近的节点并强制稍后进行额外的交叉，这只会增加总距离。 

同样的论点也适用于正确的行动。 

因此，唯一有意义的决定是方向的顺序。 在一个方向上使用过多的连续移动会将当前位置推向一个极端端点，从而使下一个相反方向的跳跃成本高昂。 尽可能交替地减少这些跨区间跳跃。 

可行性条件保证每次所需的定向移动始终可以执行，而不会耗尽该侧的节点。 

因为每次移动都是局部最优的，并且方向模式最小化了未来的穿越成本，所以最终的旅行是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, l, s = map(int, input().split())
    x = list(map(int, input().split()))

    r = n - 1 - l

    if l > s - 1 or r > n - s:
        print(-1)
        return

    left_ptr = s - 1
    right_ptr = s + 1

    left_rem = l
    right_rem = r

    ans = []

    while left_rem > 0 or right_rem > 0:
        if left_rem > right_rem:
            ans.append(left_ptr)
            left_ptr -= 1
            left_rem -= 1
        else:
            ans.append(right_ptr)
            right_ptr += 1
            right_rem -= 1

        if left_rem == 0:
            while right_rem > 0:
                ans.append(right_ptr)
                right_ptr += 1
                right_rem -= 1

        if right_rem == 0:
            while left_rem > 0:
                ans.append(left_ptr)
                left_ptr -= 1
                left_rem -= 1

    cur = s - 1
    total = 0

    for v in ans:
        total += abs(x[cur] - x[v - 1])
        cur = v - 1

    print(total)
    print(*ans)

solve()
```可行性检查是第一个微妙的部分。 左票需要当前位置左侧的实际节点。 由于指数在向左移动期间严格减少，因此我们永远不能使用超过`s - 1`总体而言是这样的举动。 

该结构在起始位置周围保留两个移动边界。 每次向左移动都会消耗最近的剩余左节点，每次右移动都会消耗最近的剩余右节点。 

该实现使用基于 1 的索引来存储节点号，因为输出格式需要它。 坐标数组本身仍然是从 0 开始的，因此每次访问都使用`v - 1`。 

另一个容易犯的错误是在施工过程中增量计算距离。 当前位置在每次移动后都会发生变化，因此最安全的方法是首先构建完整的订单，然后再模拟一次路径。 

所有涉及距离的算术都使用 Python 整数，它自然支持 64 位范围。

 ## 边缘情况

 考虑不可能的配置：```
5 2 1
0 1 2 3 4
```PMP 从最左边的节点开始。 左边没有顶点，所以即使是一张左边的票也无法使用。 

该算法检查：```
l > s - 1
2 > 0
```并立即打印`-1`。 

现在考虑相反的极端：```
4 3 4
0 5 10 20
```所有门票均为留票。 

该算法初始化：```
left_ptr = 3
right_ptr = 5
```由于没有右移动，它会重复消耗最近的左节点：```
4 -> 3 -> 2 -> 1
```距离：```
10 + 5 + 5 = 20
```不会发生不必要的跳转，因为连续的左移自然遵循排序顺序。 

另一个棘手的情况是严重不平衡的起始位置：```
6 1 5
0 1 2 3 100 101
```只有一张可用的右票和一个右侧节点。 

该算法仅使用一次正确的移动，并且永远不会尝试超出可用边界。 指针移动保证了每个产生的索引都是有效且唯一的。
