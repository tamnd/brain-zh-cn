 ## 解决方案
 ## 问题理解

 我们得到一条由边连接的点的线。 每条边的颜色为白色或黑色，编码为二进制字符串，其中每个字符描述连续点之间的边的颜色。 所以长度为 n 的字符串代表一行中的 n+1 个点。 

两名玩家轮流进行。 在一轮中，玩家选择一个连续的点段，其中至少有一个边缘，并且只允许选择内部边缘全部为对手禁止的一种颜色的段。 Bon Bon 只能选取内部边缘不包含黑色边缘的片段，这意味着所选片段必须完全位于白色边缘的区域中。 对称地，Lyra 只能选取没有白边的片段。 选择这样的线段后，所有选定的点以及任何关联边都将被删除，并且其余点必须作为单个块保持连接，这意味着删除不能将剩余结构分割为多个断开连接的组件。 

当玩家无法做出有效的动作时，他们就输了。 

问题在于，先下手的Bon Bon能否在最佳发挥下强行获胜。 

输入大小非常大：多达 100 万个测试用例，测试的总字符串长度高达 200 万。 这立即排除了任何每次测试的二次推理或任何移动模拟。 即使每次测试都是线性的，也需要仔细摊销或直接组合观察。 任何解决方案都必须将每个测试用例本质上减少为一次扫描或恒定时间推理。 

主要的陷阱是假设这是一场简单公正的分段游戏。 “移除后不分裂”约束是关键的微妙之处。 即使输入很小，简单地删除段并检查连通性的简单模拟也会失败，因为连通性取决于全局结构，而不仅仅是局部合法性。 

## 方法

 暴力方法会尝试模拟所有可能的动作。 从给定的配置中，枚举 Bon Bon 的每个有效段，然后对于 Lyra，递归地探索结果状态。 每次移动都需要检查一个线段是否仅包含白色边缘或仅包含黑色边缘，并验证删除它不会断开其余图形的连接。 

最坏情况下分支因子已经是 O(n)，深度也可以是 O(n)，导致指数复杂度。 即使记忆也没有帮助，因为状态空间取决于保留哪些点以及确切的邻接结构，该结构在删除后以非局部方式发生变化。 

关键的观察结果是，游戏实际上并不依赖于移除的完整几何形状，而仅依赖于在不破坏连接的情况下可以选择多少个“纯色块”。 移动有效地消除了单色区域内的连续间隔，但剩余图保持连接的约束迫使移动的行为就像将单个活动段分割成最多两个活动段一样，并且最佳游戏在相同颜色的运行上折叠成简单的类似奇偶校验的结构。 

如果我们将字符串压缩为相同字符的最大运行，则每个运行的行为就像一个可以提供独立选择的单元。 游戏简化为计算有多少次这样的跑动是“主动决策点”，玩家可以在其中强制执行至少一个动作。 获胜者仅取决于这些有效步数的总数是否为奇数。 

这将问题转化为具有运行压缩和奇偶校验计算的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 指数| O(n) | 太慢了 |
 | 基于跑步的减少| 每次测试 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们通过扫描二进制字符串并将其分组为相同字符的连续段来减少每个测试用例。

1. 从左到右遍历字符串，同时计算字符变化的次数。 相同位的每个最大段都是一次。 这将字符串划分为交替的块，例如 000…0111…1000…。 
2. 计算此类运行的次数。 该计数是决定结果的唯一重要数量。 
3. 根据运行次数的奇偶性决定获胜者。 如果跑的次数是奇数，Bon Bon 获胜。 如果是平局，则莱拉获胜。 

出现奇偶性的原因是，每一步都有效地删除了一个连续的结构，该结构对应于消耗颜色之间交替的一个“层”。 由于除了起始动作之外，玩家都是对称的，因此游戏简化为线性链段上的标准交替移除，其完全由链长度（以游程表示）是奇数还是偶数来表征。 

### 为什么它有效

 不变的是，在任何有效的移动之后，剩余的结构仍然可以表示为一系列交替颜色游程，并且每次移动都会将游程数量减少一倍。 任何移动都不能跳过这一减少，因为任何有效段都完全位于单色区域内，并且其删除恰好会破坏运行之间的一个边界。 由于玩家轮流进行，并且除了回合顺序外，双方都拥有相同的力量，因此游戏就相当于反复从一堆大小等于运行次数的单位中移除一个单位。 当堆大小为奇数时，第一个玩家获胜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        s = input().strip()
        if not s:
            out.append("NO")
            continue
        
        runs = 1
        for i in range(1, len(s)):
            if s[i] != s[i - 1]:
                runs += 1
        
        if runs % 2 == 1:
            out.append("YES")
        else:
            out.append("NO")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```代码独立处理每个测试用例。 键循环对连续字符之间的转换进行计数，这会直接生成运行次数，而无需显式存储它们。 空弦后卫是防御性的，尽管在限制下这并不是绝对必要的。 

然后做出的决定是奇偶校验。 不需要额外的数据结构，考虑到总输入大小的限制，这是必不可少的。 

## 工作示例

 考虑一个简单的输入`0011`。 

我们跟踪跑步和决策：

 | 我| s[i] | s[i-1] | s[i-1] 运行|
 | ---| ---| ---| ---|
 | 0 | 0 | - | 1 |
 | 1 | 0 | 0 | 1 |
 | 2 | 1 | 0 | 2 |
 | 3 | 1 | 1 | 2 |

 有 2 次运行，因此输出为 NO。 

这表明偶数长度交替结构有利于第二个玩家，因为游戏可以配对成对称响应。 

现在考虑`010`。 

| 我| s[i] | s[i-1] | s[i-1] 运行|
 | ---| ---| ---| ---|
 | 0 | 0 | - | 1 |
 | 1 | 1 | 0 | 2 |
 | 2 | 0 | 1 | 3 |

 有 3 次运行，因此输出为 YES。 

这表明额外的交替片段为第一个玩家提供了最终的无与伦比的移动，从而确认了奇偶规则。

 ## 边缘情况

 没有转换的字符串，例如`000000`恰好产生一次运行。 该算法返回 YES，因为运行计数为 1，这意味着第一个玩家有一个决定性的动作。 

完全交替的字符串，例如`0101010`产生许多运行。 每次角色翻转都会使运行计数增加一，最终的奇偶性直接决定获胜者。 该算法在一次扫描中处理这个问题，无需特殊的外壳。 

像这样的两块字符串`111000`产生两次运行。 第二个玩家获胜，因为每次移动都会移除一个有效边界层，并且偶数计数保证了第一次移动后的对称性。
