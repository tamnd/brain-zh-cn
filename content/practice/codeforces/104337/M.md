 ## 解决方案
 ## 问题理解

 我们参加了一场比赛，总共有$x$参赛队伍。 每个团队都属于三个类别之一，每个类别都会向主办方贡献固定金额的资金。 

第一类团队没有任何贡献。 第二类团队贡献正好1000美元。 第三组的队伍总共贡献2500美元，其中包括1000美元的后勤费和1500美元的报名费。 主办方所有队伍的总收入为$y$，但是三类的细分已经丢失。 

任务是重建任何有效的三元组$(A, B, C)$表示三种团队类型的计数，使得团队总数为$A + B + C = x$总收入是$1000B + 2500C = y$。 如果不存在这样的分解，我们必须输出$-1$。 

约束条件允许$x$最多$10^6$和$y$最多$10^9$。 这立即排除了任何试图枚举所有可能的三元组的方法，因为即使是二维搜索$B$和$C$最多需要$10^{12}$最坏情况下的状态。 有效的解决方案必须将问题减少到恒定数量的算术检查。 

当仅推理平均值或贪婪选择而不强制完整性时，会出现微妙的失败情况。 例如，如果$x = 3$和$y = 2500$，人们可能会尝试分配一个 C 型团队，将其余团队分配为 A 型团队，但这会产生$C=1, B=0, A=2$，给出总计$2500$，这是有效的。 然而，如果$y = 1500$，我们需要$B=1, C=0$，离开$A=2$，但如果$y = 2000$，不存在整数组合。 这强调了可行性取决于解决丢番图系统而不是近似。 

另一个边缘情况是当$y$相对于太小或太大$x$。 最小值为 0（均为 A 型），最大值为$2500x$（均为 C 型）。 任何超出该范围的值都是不可能的。 

## 方法

 蛮力策略是迭代所有可能的值$C$从 0 到$x$，并针对每个项目计算剩余预算并检查是否可以使用 B 类团队来填补。 对于固定的$C$，方程变为$1000B = y - 2500C$， 所以$B$如果余数能被 1000 整除，则唯一确定，然后$A$源自$x - B - C$。 这种方法是正确的，因为它直接测试所有组合$C$，但它执行$O(x)$迭代，即在$x = 10^6$是临界值，但在 Python 中仍然可以接受，只有经过严格的优化。 然而，方程的结构使我们能够完全避免迭代。 

关键的观察是一切都是线性的$B$和$C$，以及系数$B$是 1000 而系数$C$是 2500。将整个方程除以 500 可以将其简化为一个更小的系统，但即使没有缩放，我们也可以将其视为具有两个变量和一个总和约束的单个线性丢番图方程。 我们不进行搜索，而是直接消除一个变量。 

我们表达$B = x - A - C$并代入收入方程。 这产生了一个方程$A$和$C$，但更干净的方法是修复$C$隐式使用模 1000 的方程结构。由于 B 型恰好贡献了 1000，因此只有 C 型影响模 1000 的余数。这迫使$2500C \equiv 500C \pmod{1000}$， 所以$y \bmod 1000 = 500C \bmod 1000$。 这立即限制$C$最多两个残基类模 2，允许对最多两个候选进行恒定时间搜索。 

一次$C$是固定的，$B$精确地通过减去贡献来确定$C$，可行性简化为检查是否$B$是非负的并且是否$A = x - B - C$也是非负的。

 ## 算法演练

 我们从观察开始，B 类团队贡献了 1000，而 C 类团队贡献了 2500。这使得系统高度结构化，因为所有内容都按照 500 的倍数对齐。 

1.我们首先检查是否$y$位于 0 和 0 之间的可行范围内$2500x$。 如果没有，则根本没有分解。 此步骤消除了任何代数之前的不可能情况。 
2. 我们将方程以 1000 为模进行简化。$1000B$模 1000 消失，我们得到$2500C \equiv 500C \pmod{1000}$， 所以$y \bmod 1000$必须等于$500C \bmod 1000$。 这立即意味着$C$必须满足类似奇偶校验的条件：要么$C$是偶数还是奇数取决于是否$y \bmod 1000$是 0 或 500。 
3. 根据这个约束，我们最多尝试两个候选者$C$：满足留数条件的最小非负整数，并且该值加 2。这是唯一的可能性，因为同余每 2 步循环一次。 
4. 对于每位候选人$C$，我们计算剩余的贡献$y - 2500C$。 如果为负数或不能被 1000 整除，则该候选无效。 
5. 如果有效，我们计算$B = (y - 2500C) / 1000$。 然后$A = x - B - C$。 我们检查是否$A$是非负的。 
6. 如果任何候选产生有效的非负整数，我们输出$(A, B, C)$。 否则我们输出$-1$。 

### 为什么它有效

 该系统完全由两个独立的线性约束决定：团队数量和总收入。 一次$C$是固定的，$B$被整除性所迫，并且$A$是由总和约束强制的。 模块化条件确保我们只测试$C$可能满足收入方程，因此不会跳过任何有效解。 由于每个有效的解决方案都必须满足相同的同余性，因此它必须出现在已检查的候选方案中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())

    if y < 0 or y > 2500 * x:
        print(-1)
        return

    # 2500C ≡ 500C (mod 1000)
    r = y % 1000

    # we try C such that 500*C % 1000 == r
    candidates = []

    # since 500*C mod 1000 cycles with period 2:
    # C even -> 0 mod 1000
    # C odd  -> 500 mod 1000
    if r == 0:
        c0 = 0
        c1 = 2
    elif r == 500:
        c0 = 1
        c1 = 3
    else:
        print(-1)
        return

    for C in (c0, c1):
        if C > x:
            continue
        remaining = y - 2500 * C
        if remaining < 0 or remaining % 1000 != 0:
            continue
        B = remaining // 1000
        A = x - B - C
        if A >= 0:
            print(A, B, C)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```该代码首先拒绝不可能的总收入范围。 然后它使用 modulo-1000 结构来限制搜索$C$最多两个有意义的候选人。 对于每个候选者，它重建$B$精确地通过除法，并得出$A$从团队总数中。 

主要的微妙之处在于模数减少：由于 B 型贡献了 1000，所以它以 1000 为模消失，只留下 C 型控制剩余部分。 这就是为什么我们可以限制$C$如此积极而又不失正确性。

 ## 边缘情况

 一个关键的边缘情况是当$y = 0$。 算法检查$r = 0$, 尝试$C = 0$，并立即获得$B = 0$,$A = x$。 输出与所有 A 型团队一致。 

另一个边缘情况是当$y$接近最大值$2500x$。 例如，$x = 4, y = 10000$强制所有团队为 C 型。该算法评估$C = 4$，得到$B = 0$， 和$A = 0$，产生有效的分解。 

幼稚推理的失败案例是$x = 2, y = 2500$。 贪婪的方法可能会尝试分配一个 C 类团队，而将其余的保留为 A 类团队，但这只会产生 2500 人，并且没有剩余结构。 正确的推理强制执行精确的整除性，确保两个约束之间的一致性。
