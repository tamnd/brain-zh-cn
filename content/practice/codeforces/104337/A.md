 ## 问题理解

 我们给出了几个测试用例，每个测试用例都包含一个整数数组。 目标是使用特殊类型的操作将每个数组转换为非递减序列，并且我们希望使用尽可能少的操作来完成此操作。 

一个操作的工作原理如下：选择一个长度为奇素数的连续段，然后将 +1 或 −1 添加到该段中的每个元素。 您可以应用许多此类操作，但任何时候都不允许任何数组值变为负数。 

对于每个测试用例，输出是使数组不递减所需的这些段操作的最小数量。 

约束结构很重要。 所有测试用例的总长度最多为 2×10^4，这强烈表明我们应该针对每个测试的大致线性或近线性行为。 如果所有测试用例都很大，则数组大小的任何二次方都会太慢。 

幼稚的解释会尝试直接模拟操作或搜索应用段的所有方法。 这会立即失败，因为即使对于 n = 2000，可能的段数也是 O(n^2)，并且每个段都有两种符号选择，使得暴力破解完全不可行。 

一个微妙的问题还来自“过程中没有负值”的约束。 即使最终配置看起来不错，随意减去以修复未来结构的粗心贪婪策略也可能会意外地创建无效的中间状态。 例如，减少前缀来修复局部反转可能会在以后的校正之前暂时将值推至零以下。 

## 方法

 关键的困难是了解该操作实际上允许我们在全球范围内做什么。 尽管它被描述为长度有限的段更新，但重要的观察是，我们在表达能力方面并没有真正受到特定素数长度的限制，仅在成本方面受到限制。 

暴力的观点是将每个操作视为可以局部增加或减少块的工具。 如果我们尝试直接搜索此类操作的最佳序列，我们将需要探索指数级多个重叠片段的序列。 即使跨时间间隔的动态编程也会失败，因为转换取决于连续值的变化，而不仅仅是离散状态。 

结构洞察力来自于重新构建目标。 我们没有被要求达到特定的目标阵列； 我们被要求强制执行单调约束：每个位置最终必须至少与前一个位置一样大。 这将问题转化为消除阵列中的“滴”。 

假设我们从左到右扫描。 每当我们遇到一个位置`a[i] < a[i-1]`，我们需要增加位置的值`i`（可能还有附近的位置）足以使其不再比其前身小。 任何有效的操作序列都必须至少支付这个“赤字”，因为没有任何操作可以避免修复前缀减少的每个违规行为。 

现在考虑单个 +1 段操作的真正贡献。 即使它影响一个块，我们也可以选择重叠的片段，从而使净效果可以局部化：重复的重叠更新使我们能够模拟各个位置的单位增加，而每个校正单位只需支付一次操作。 对奇素数长度的限制不会渐进地改变这个结论，因为我们总是可以选择覆盖所需局部区域的有效段大小，并将它们重叠以隔离有效贡献。 

这导致了简化：成本恰好是从左到右扫描时删除阵列中所有向下步骤所需的增加总量。 每次序列下降时，我们都必须从该位置开始按照下降的大小“提升”后缀，每个提升单位对应于一次操作。 

因此，答案成为数组减少时所有正差值的总和。

 ## 算法演练

 我们独立处理每个测试用例并计算所需的单元校正的最小数量。 

1. 从数组的第二个元素开始，与前一个元素进行比较。 
2.如果当前值至少是先前值，则在这一步不需要校正，因为这里不违反非递减性质。 
3. 如果当前值小于前一个值，则计算差值`diff = a[i-1] - a[i]`。 这是当前位置必须增加的量才能恢复此时的单调性。 
4. 添加`diff`到答案。 这表示必须在覆盖位置的某处应用的单位 +1 贡献的最小数量`i`纠正违规行为。 
5. 从概念上讲，在考虑了这种修正之后，对待`a[i]`提高以匹配`a[i-1]`以便将来的比较正确传播。 
6. 继续直到数组末尾。 

### 为什么它有效

 连续元素之间的每次减少都表示强制的向上调整量，任何允许的操作序列都无法避免该向上调整量。 由于每个增加单位必须来自某些操作，因此所有减少的总和是一个下限。 

同时，我们可以实现这个下限，因为重叠段操作允许我们分配单位增加，而不会干扰数组中已经固定的部分。 这意味着不需要对已经有效的元素进行“浪费”更正，并且所需增加的每个单位都可以单独收费。 

因此，该算法计算必要且足够的操作量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        for i in range(1, n):
            if a[i] < a[i - 1]:
                ans += a[i - 1] - a[i]
                a[i] = a[i - 1]
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现直接遵循从左到右的扫描。 该数组会就地更新，以便每个位置都反映在考虑了早期缺陷后的校正值，这确保了以后的比较使用已经“固定”的前缀。 这可以避免当多次连续掉落累积时计数不足。 

这里一个常见的实施错误是忘记更新`a[i]`添加差异后。 如果没有该更新，则后面的差异将根据原始数组而不是校正后的级数进行测量，这会根据减少的模式导致重复计算或低估。

 ## 边缘情况

 一个有用的边缘情况是上下交替的序列，例如`[1, 10, 1, 10, 1]`。 该算法独立处理每个液滴，添加`9`每向下一步。 这符合直觉，即每次违规都会强制进行全面的本地更正，并且以后的增加不会取消之前所需的修复。 

另一种情况是长的严格递减前缀后跟递增，例如`[100, 90, 80, 90]`。 早期的大幅下跌会立即累积所有所需的修正，而后期的上涨并不会减少早期的成本。 扫描正确地将调整后的前缀保​​持在迄今为止看到的最大值，确保最后一步仅检查已经纠正的状态。 

最后，从下界附近开始的序列，例如`[1, 1, 1, 1]`确认没有引入或需要负值，并且算法自然地产生零操作而无需任何特殊处理。
