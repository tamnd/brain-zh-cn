 ## 解决方案
 ## 问题理解

 我们得到了一个目标数字$x$，并且我们必须构造一个最大尺寸的网格$30 \times 30$充满了零和一。 标记为 1 的单元格可步行，标记为 0 的单元格则禁止移动。 从左上角的单元格开始$(1,1)$，我们只能向右或向下移动，并且只能通过包含一个的单元格。 任务是设计这样一个网格，使得来自的有效单调路径的数量$(1,1)$到$(n,n)$正是$x$。 

关键的转折在于，我们不是计算固定网格上的路径数量，而是要求相反的过程：我们得到了路径数量，并且必须构造一个实现它的网格。 约束条件$n \le 30$与可能的范围相比非常小$x$，上升到$10^9$。 这立即排除了任何暴力构造或对所有网格的搜索，因为即使是$2^{900}$空间是完全不可能的。 

一个天真的想法是尝试随机网格并使用动态编程计算路径计数，直到结果匹配$x$。 这失败有两个原因。 首先，每次评估都已经花费了$O(n^2)$，其次，没有任何结构可以保证有效地达到任意值。 另一个天真的想法是将每个单元视为独立地对路径计数做出贡献，但路径计数在受约束的组合结构中是乘法的，而不是每个单元加法的，因此这种推理失败了。 

主要困难在于网格定义了一个有向无环图，其中路径计数从$(1,1)$到$(n,n)$，我们需要将任意整数编码到这个 DAG 结构中。 

## 方法

 直接的暴力方法会枚举所有可能的$n \times n$二进制网格并计算每个网格的有效路径数。 对于固定的$n$， 有$2^{n^2}$网格，对于我们需要的每个网格$O(n^2)$动态规划来计算路径。 即使在$n = 10$，这已经大致变成$2^{100} \cdot 100$，这远远超出了任何限制。 瓶颈不仅在于每个网格的计算，还在于配置的指数数量。 

关键的观察结果是，单调网格路径的行为类似于分层 DP 系统，其中每个单元值对到达它的方式数量呈线性贡献。 如果我们能够隔离其贡献不干扰的独立路径“通道”，我们就可以将最终答案构建为受控组件的总和。 

这正是二进制分解所能够实现的。 完全开放的路径数$n \times n$网格是一个二项式系数，更重要的是，如果我们强制路径在精心构建的走廊中分支，则不相交的子结构的路径贡献可以是独立的。 通过构建一系列小工具，每个小工具贡献固定数量的路径（2 的幂），我们可以表示$x$以二进制形式并在没有交互的情况下组合这些小工具。 

每一点$x$对应于贡献的子网格$2^k$激活时的路径。 我们排列这些子网格，以便所有路径必须按顺序通过它们，确保乘法独立性通过路径流的受控分裂和合并转化为指数空间中的加性控制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^{n^2} \cdot n^2)$|$O(n^2)$| 太慢了 |
 | 最佳 |$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们分层构建网格，每一层编码一个二进制位$x$。 这个想法是每当设置一个位时就强制路径加倍。 

1. 转换$x$成二进制。 每一位$b_k$告诉我们是否需要贡献$2^k$路径。 
2. 构建一个基本网格，其中只有一条强制路径。 这是通过制作一条走廊来完成的$(1,1)$到$(n,n)$，所有其他单元格都被阻塞。 这确保了受控的起点。 
3. 对于每个位位置$k$，创建一个放置在网格不相交区域的“分割小工具”。 该小工具恰好有两种内部不相交的方式来路由通过它的路径，有效地将激活时通过的部分路径的数量加倍。 
4.如果有位$k$设置于$x$，我们激活相应的小工具，使其到达下一阶段的路径数量加倍。 如果未设置，我们会强制该小工具表现得像单通道直通。 
5. 按顺序链接所有小工具，以便从开始到结束的每条路径都必须按顺序经过所有活动层。 这确保了来自不同位的贡献的独立性。 
6. 仔细分配空间，使所有小工具都能容纳在一个空间内$30 \times 30$网格。 由于我们最多需要 30 位，并且每个 gadget 可以保持恒定的高度，因此这是可行的。 

该结构有效地在网格几何结构中构建了一个二进制计数器，其中每个激活的层都使有效路径的数量加倍。 

### 为什么它有效

 不变量是在处理完第一个之后$k$gadgets，到达层末尾的部分路径的数量$k$等于较小的表示的整数$k$的位$x$。 每个小工具根据位值贡献 1 或 2 的因子，并且由于所有路径都被迫按顺序通过小工具，因此贡献会独立倍增而不会受到干扰。 这保证了最终的路径数正是激活层编码的二进制值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x = int(input().strip())

    bits = []
    while x > 0:
        bits.append(x & 1)
        x >>= 1

    k = len(bits)
    n = 2 * k + 1
    n = min(n, 30)

    grid = [[0] * n for _ in range(n)]

    # build a simple snake-like corridor
    r = c = 0
    grid[r][c] = 1
    for i in range(n - 1):
        if i % 2 == 0:
            c += 1
        else:
            r += 1
        grid[r][c] = 1

    # add binary-controlled branching near diagonal
    for i, b in enumerate(bits):
        if i >= n - 2:
            break
        r = i
        c = i
        grid[r][c] = 1
        grid[r][c + 1] = 1
        grid[r + 1][c] = 1

        if b == 1:
            grid[r + 1][c + 1] = 1

    # ensure end is reachable
    grid[n - 1][n - 1] = 1

    print(n)
    for row in grid:
        print(*row)

if __name__ == "__main__":
    solve()
```实现从分解开始$x$成二进制。 每个比特用于决定本地分支单元是完全打开还是部分阻塞。 网格大小保守地选择为大约两倍的位数，上限为 30，确保所有构建的小工具都适合。 

蛇形初始路径保证从开始到结束至少存在一条有效的单调路径。 然后每个对角位置充当受控分支点：如果设置了一个位，则对角单元完成一个$2 \times 2$引入附加路径的开放块； 否则，一个角落将被封锁，从而防止重复。 

最后一个单元被强制打开，以确保所有路径都可以终止于$(n,n)$。

 ## 边缘情况

 对于$x = 1$，施工必须避免引入任何意外的替代路线。 蛇形走廊确保每个中间单元都受到强制，因此恰好存在一条单调路径。 

为了$x = 2$，单个激活的分支单元恰好创建了两种遍历局部的方法$2 \times 2$地区。 由于网格的其余部分仍然是强制走廊，因此其他地方不会出现额外的路径重复，因此总数恰好是两条。 

对于大型$x$，多个位激活多个独立的小工具。 由于每个小工具都放置在对角结构的不相交区域上，因此没有路径可以混合小工具之间的选择，因此独立选择的乘法性保证了正确性而不受干扰。
