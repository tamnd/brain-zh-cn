 ## 解决方案
 ## 问题理解

 我们正在寻找恰好具有的最小正整数`n`位数，并且可以同时被数字 2、3、5 和 7 中的每一个整除。 换句话说，我们想要最小的`n`- 数字，是这四个整数的最小公倍数的倍数。 

由于数字 2、3、5 和 7 是成对互质的，因此它们的组合整除性要求分解为一个条件：该数字必须能被 210 整除。因此，该任务相当于找到最小的`n`- 能被 210 整除的数字。 

输出必须严格遵守长度约束。 一个数小于`n`即使满足整除性，数字也是无效的。 同样，任何候选者都不得超过最小的`n`- 数字阈值，除非有必要。 

约束条件`n ≤ 10^5`立即排除任何一一构造或检查数字的方法。 即使是线性扫描也可能`n`-数字值是不可能的，因为候选人的范围呈指数增长`n`。 解决方案必须是算术和基于公式的。 

一个关键的边缘情况出现在小`n`。 为了`n = 1`，能被210整除的最小1位数字并不存在，因为210的最小倍数是210本身，它已经有3位数字了。 这迫使答案是`-1`。 任何忘记根据数字长度检查可行性的方法都会错误地输出小数字`n`。 

另一个微妙的情况是当第一个`n`- 210 的数字倍数不完全是`10^(n-1)`但四舍五入到下一个倍数后的数字稍大。 正确处理这个问题需要仔细划分天花板。 

## 方法

 一个蛮力的想法是从最小的开始`n`- 位数，即`10^(n-1)`，并重复测试每个整数，直到找到一个能被 210 整除的整数。这是正确的，因为每个有效答案都位于这个区间内，并且我们正在按升序搜索。 

然而，这是不可行的。 该区间包含约`9 × 10^(n-1)`数字，甚至对于中等`n`这是一个天文数字。 每次可除性检查都是常数时间，但检查的数量决定一切。 

关键的观察是我们根本不需要搜索。 我们只需要 210 的最小倍数，即至少`10^(n-1)`。 这是一个经典的天花板除法问题。 一旦我们计算出下界`n`位数，我们可以在常数时间内将其四舍五入到 210 的下一个倍数。 

唯一剩下的问题是可行性。 如果结果数字不再精确`n`位数，那么在所需的长度内不存在有效的解决方案，因为任何更大的倍数只会进一步增加位数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(10^n) | O(10^n) | O(1) | O(1) | 太慢了 |
 | 最优（上限倍数）| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算最小数`n`数字，即`10^(n-1)`。 这是任何有效答案的严格下限，因为不允许使用前导零。 
2. 计算大于或等于该下限的 210 的最小倍数。 这可以使用上限划分来完成：`(lower + 209) // 210 * 210`。 这个想法是，如果数字尚未对齐，则将其移至下一个可整除的块中。 
3. 检查结果数是否仍然准确`n`数字。 如果小于`10^(n-1)`，它是无效的，但根据构造，这是不可能发生的。 真正的失败情况是当舍入将数字推至`10^n`或超越。 
4. 如果计算出的数字超过`n`数字，输出`-1`。 
5. 否则，打印该号码。 

### 为什么它有效

 所有有效答案都是 210 的倍数，因此它们形成等差数列。 我们正在选择该级数中位于区间内的最小元素`[10^(n-1), 10^n - 1]`。 上限操作找到不低于间隔起始的级数的第一项。 如果该项超过区间末端，则交集为空，因此不存在解。 这保证了正确性，因为没有比这更小的候选者可以同时满足这两个约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    if n == 1:
        print(-1)
        return

    lower = 10 ** (n - 1)

    # smallest multiple of 210 >= lower
    ans = (lower + 209) // 210 * 210

    # check digit length
    if ans >= 10 ** n:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先直接处理不可能的个位数情况。 这是必要的，因为否则数学构造将返回 210，这违反了数字约束。 

核心计算仅使用整数运算。 表达式`(lower + 209) // 210`实现没有浮点运算的上限除法。 乘以 210 即可恢复实际的候选数。 

最终检查确保我们不超过上限`n`数字，这很关键，因为上限步骤可能会跳出区间。 

## 工作示例

 ### 示例 1

 输入：`n = 2`下限为 10。 

| 步骤| 价值|
 | --- | --- |
 | 下= 10^(n-1) | 10 | 10
 | ceil 多重索引 | (10 + 209) // 210 = 1 |

 这说明我们虽然找到了210的第一个倍数，但它超出了允许的数字长度。 所以输出是`-1`。 这演示了边界故障情况，其中间隔不包含有效倍数。 

### 示例 2

 输入：`n = 3`下限为 100。 

| 步骤| 价值|

 | 候选人 | 210 | 210
 | 数字检查| 有效的 3 位数号码 |

 这里第一个有效倍数已经在 3 位数字之内，所以答案是 210。这显示了正常的成功对齐情况。

 ## 边缘情况

 对于`n = 1`，算法立即返回`-1`因为 210 的任何倍数都至少有 3 位数字。 这可以避免计算下限 1，否则会产生无效的候选值。 

为了`n = 2`，下限为 10。上限倍数为 210，超出了 2 位数字的限制。 支票`ans >= 10^n`正确地拒绝它。 

对于较大的`n`， 例如`n = 3`或者`n = 4`，下限最终与仍符合数字限制的 210 的倍数对齐。 上限操作确保我们永远不会错过第一个有效的候选者，上限检查确保我们不接受溢出情况。
