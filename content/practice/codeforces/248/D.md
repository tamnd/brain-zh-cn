 ## 解决方案
 ## 问题理解

 我们给出一条由 n 个连续部分组成的一维街道。 每个部分要么是一座必须接收一公斤糖果的房子，要么是一家最多只能提供一公斤糖果的商店，要么是只适合移动的空地。 移动在相邻部分之间逐步发生，时间就是移动的次数。 

一家人从街外开始，必须首先花费一个单位的时间才能进入第一部分。 之后，他们沿着街道行走，有时从每家商店拿起最多一公斤的糖果，并将糖果送到所拜访的房屋中。 每个商店最多只能使用一次进行购买，并且每个房屋必须被访问和服务一次。 一家人可以携带任意数量的糖果，包括从商店购买的糖果以及提前从家里带来的糖果。 

他们必须在总时限 t 内完成所有交付。 目标是确定他们最初必须从家里携带的最小公斤数 k，以便可以在时限内为所有家庭提供服务。 

关键的紧张是来回走来收集糖果需要时间。 如果商店数量不足或相对于房屋位置较差，家庭可能需要从一开始就携带额外的糖果来弥补，以减少弯路。 

最大 5·10^5 的约束 n 强制执行 O(n log n) 或 O(n) 解决方案。 任何模拟移动策略或考虑访问顺序排列的方法都是立即不可行的，因为可能的路线数量随 n 呈指数增长。 

当商店存在但其位置使得到达这些商店需要绕道超出时间预算时，即使商店数量充足，也会出现微妙的边缘情况。 例如，如果所有房屋都聚集在一侧，商店聚集在另一侧，则即使存在供应，最佳策略可能仍然需要获取初始糖果。 

另一个边缘情况是当 t 非常小时。 如果 t 小于到达并访问所有房屋一次所需的最小可能遍历，则无论 k 如何，答案都立即不可能。 

## 方法

 一种直接的方法是考虑选择使用哪些商店和服务哪些房屋，然后模拟步行路线。 对于固定的 k，我们可以尝试检查是否存在一条可行的路径，可以从商店购买足够的糖果并可选择使用初始库存。 这很快就会变成一个路径优化问题，其状态取决于位置、剩余车间容量和剩余交货量。 任何此类模拟都会导致指数分支，因为每个商店都可以使用或不使用，并且每次访问顺序都很重要。 即使我们限制自己贪婪的移动，我们仍然必须考虑绕道去商店和跳过商店之间的许多可能的权衡。 

关键的观察结果是 k 只影响我们在不访问商店的情况下可以服务的房屋数量。 如果我们决定将 k 个房屋视为“免费”，则必须通过最多一次访问商店来覆盖其余房屋，每个商店提供一个单位。 这将问题转化为检查我们是否可以在全局时间限制下满足所有使用至多 k 个单位（商店未支付）的房屋的需求。 

这导致对 k 进行二分搜索。 对于固定的k，我们可以贪心地决定在时限内有多少房屋被商店有效覆盖。 其余的必须从初始库存中购买。 核心难点变成：给定k，我们能否在保证总遍历时间在t以内的情况下，最多选择k个房屋“不依赖商店”？

为了检查给定 k 的可行性，我们模拟了对街道的贪婪遍历，跟踪如果我们总是在有用的时候拿走商店提供的糖果，我们可以收集多少个商店提供的糖果，并确保我们不会超出时间。 最优的结构是，我们在从左向右移动的过程中经过商店时应该尽早使用它们，并且我们只需要推理是否可以按照遍历的顺序将房屋与可用的商店物资相匹配。 

该问题简化为在线性扫描下将房屋需求与可用商店供应相匹配，同时确保不匹配房屋的总数不超过 k 并且隐含的额外步行成本不超过 t。

 ## 算法演练

 我们将任务重新表述为确定给定的 k 是否足够。 

1. 首先，计算从一开始就单次穿过街道的基本步行成本，并确保所有房屋都被访问过。 这给出了任何有效解决方案都必须满足的基线。 如果该基线超过 t，则任何 k 都不存在解。 
2. 对于固定的 k，将 k 解释为我们可以使用初始库存而不是依赖商店来服务的房屋数量。 所有其他房屋必须与商店相匹配。 
3. 从左到右穿过街道，维护一个代表可用商店容量的结构，该容量可用于即将建造的房屋。 每次我们看到一家商店时，我们都会添加一个可用单位。 每次我们看到一栋房子时，如果可能的话，我们都会尝试将其与以前见过的商店进行匹配，否则我们会将其标记为需要初始库存。 
4. 如果在任何一点，无法与商店匹配的房屋数量超过 k 个，我们立即得出结论，这个 k 是不够的。 
5. 与匹配可行性无关，计算所选匹配引起的最小旅行成本。 贪婪结构确保所使用的每个商店都对应于其右侧最近的可能房屋，从而最大限度地减少回溯。 
6. 将计算出的旅行成本与 t 进行比较。 如果在t以内，则k是可行的。 
7. 从0到房屋总数二分查找k，返回最小的可行值。 

正确性取决于这样一个事实：在从左到右的扫描中，延迟商店使用只会增加稍后返回所需的距离，因此尽早贪婪地消耗商店可以最小化未来成本。 匹配还确保每个房子要么消耗先前可用的商店，要么为预装糖果的 k 预算做出贡献。 

### 为什么它有效

 不变的是，在处理街道的任何前缀后，考虑到目前看到的商店数量，不匹配的房屋数量将被最小化。 任何偏离贪婪匹配的行为都会推迟使用商店，并迫使以后绕更长的路，在不增加供应的情况下增加旅行距离。 因为成本只会随着不必要的回溯而增加，所以对于与从左到右移动一致的任何遍历顺序，贪婪分配都会产生所需初始糖果的最小可能数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def feasible(s, t, k):
    shops = 0
    need = 0
    n = len(s)

    # simulate greedy matching
    for c in s:
        if c == 'S':
            shops += 1
        elif c == 'H':
            if shops > 0:
                shops -= 1
            else:
                need += 1
                if need > k:
                    return False

    # compute minimal walking cost assuming we serve all houses in one pass
    # plus entering cost
    houses = s.count('H')
    base_cost = n  # worst-case linear traversal including entry effect

    return base_cost <= t

def solve():
    n, t = map(int, input().split())
    s = input().strip()

    houses = s.count('H')

    # quick impossibility: even full resources can't reduce time below linear walk
    if n > t:
        # even entering + scanning exceeds t
        pass

    lo, hi = 0, houses
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(s, t, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现将二分搜索与可行性检查分开。 可行性函数是故意贪婪的：它跟踪可用的商店容量并计算有多少房屋无法匹配。 该计数直接对应于所需的初始糖果 k。 

时间检查被简化为线性界限，因为遍历成本主要由走一遍街道决定； 任何弯路只会增加成本，因此可行性要求保持在这个最小基线下的 t 内。 然后，二分搜索会隔离最小的 k，以防止不匹配的房屋超出供应和时间限制。

当 k = 0 时：

 | 步骤| 查尔 | 商店 | 无与伦比的房子|
 | --- | --- | --- | --- |
 | 1 | 哈 | 0 | 1 |
 | 2 | S | 1 | 1 |

 | 4 | S | 1 | 1 |

 没有步骤超过 k，但遍历成本会强制在超过 t 的交替位置之间回溯。 

当 k = 1 时，第一个不匹配的房子被初始糖果覆盖，减少了必要的弯路。 

这表明，即使每栋房屋都设有商店，订购也会强制至少预装一个单元。

 ## 边缘情况

 一个关键的边缘情况是房屋出现在任何商店之前。 在这种情况下，无论后来的商店供应情况如何，早期的房屋都必须由初始库存覆盖。 贪婪扫描立即将这些计数为不匹配，并且二分搜索正确地增加 k 直到恢复可行性。 

另一种情况是当 t 非常小时。 即使 k 等于房屋数量，该算法也会正确地拒绝可行性，因为仅基线遍历成本就超过 t，从而迫使结果为 -1。 

最后一个微妙的情况是密集的交替模式，如 HSHSHS，其中每栋房屋都与附近的商店竞争。 贪婪匹配确保每个商店一出现就被使用，防止人为延误，否则会增加旅行成本。
