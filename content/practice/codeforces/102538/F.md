 ## 解决方案
 ## 问题理解

 我们有一排怪物。 怪物`i`开始于`h[i]`健康点。 每回合，我们都可能击中任何活着的怪物并降低其生命值`a`，或者跳过我们的回合。 对手总是攻击最左边的活怪物并减少其生命值`b`。 每当我们的一次攻击杀死一只怪物时，我们就会获得一分。 我们的目标是最大化我们个人消灭的怪物数量。 

顺序很重要，因为对手不能自由选择目标。 指数较小的怪物会阻挡其后的所有怪物直至其死亡，因此怪物受到的对手攻击次数取决于之前怪物的决策。 思考该过程的有用方法不是将其视为回合的模拟，而是将其视为可用动作的平衡。 对手的每次攻击都让我们有时间准备未来的杀戮，而我们对怪物的每次攻击都会消耗一招。 

约束条件`n <= 300000`排除任何执行与匝数成比例的功的模拟。 健康值可达`10^9`，因此攻击总数可能非常巨大。 该算法必须仅处理每个怪物恒定或对数次数，这指向贪婪或基于数据结构的解决方案。 

一个常见的错误是独立对待怪物。 例如，具有相同的攻击力和三个怪物的生命值`1 1 1`，独立决定每个怪物的策略可能会认为所有三个怪物都可以被杀死。 事实上，在杀死一个怪物后，对手在我们的攻击之间仍然有轮流，而可用的先手优势是有限的。 正确答案是`2`。 

另一个错误是忘记了最初的移动优势。 有输入`3 1 1`和健康`2 2 2`，正确答案是`3`。 获胜策略是等到怪物只剩下一个生命值，然后在对手移除它之前完成它。 将第一步棋视为对手的正常回合就失去了这种可能性。 

## 方法

 直接的方法是模拟选择。 对于每个怪物，我们决定是用攻击杀死它还是把它留给对手。 每次选择后，我们都会模拟战斗并计算胜利。 这是正确的，因为每种可能的策略都被探索过，但是每个怪物都有两种选择，`2^n`的可能性。 即使在考虑模拟成本之前，这也是不可能的：`n`达到数十万。 

重要的观察是我们不需要知道攻击的确切顺序。 假设我们决定要杀死哪些怪物。 对于一个选定的怪物，没有理由击中它超过必要的次数。 让`r`是怪物达到再击中即可杀死它的状态之前的最小击中次数。 我们对这个怪物的最佳命中次数恰好是`r + 1`。 

公式为`r`来自查看剩余生命值对对手攻击周期的模数。 将所有健康值减一后，我们需要最小的`r`这样：```
(h - r * a) mod b < a
```其值为：```
r = floor(b * (h mod a) / a)
```在确定怪物是否被我们杀死后，我们可以将效果表示为可用移动次数的变化。 如果我们不杀掉它，对手就会花费`h`对它的攻击。 如果我们杀了它，对手的动作和我们的动作之间的差异是另一个值。 我们将这个选择与每个怪物都留给对手的基线进行比较。 

对于怪物`i`， 让`y[i]`是选择杀死它而不是忽略它所引起的变化。 我们需要选择尽可能多的`y[i]`值尽可能，同时保持每个前缀有效。 这成为一个经典的贪心选择问题。 我们从左到右扫描怪物，将所有选择的值保留在堆中，如果前缀变得不可能，则删除最差的选择怪物。 最坏的去除是最大的`y[i]`，因为删除较大的值可以修复约束，同时牺牲最少的选定怪物。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.将每个怪物的生命值减少1。 这改变了达到健康状态的杀戮条件`0`达到负值，这使得模计算更加清晰。 
2. 对于每个怪物，计算我们在最终击杀攻击之前的最少攻击次数。 其值为`r = (b * (h % a)) // a`。 
3. 计算我们自己杀死这个怪物的好处。 如果我们让它活着，它的贡献是`h`。 如果我们杀死它，它的贡献是：```
b * ((h - r * a) // b) - (r + 1)
```这两个值之间的差异是`y`。 

1. 维护所选的总和`y`从左到右扫描怪物时的值。 还保持所有原始的当前总和`h`该前缀中的值。 
2.添加当前`y`到最大堆。 如果所选的更改变得太大并且违反了前缀条件，则删除最大的`y`从堆中。 堆中总是包含我们最终决定杀死的怪物。 
3、堆中剩余元素的数量就是最大胜利数。 

不变的是，在处理每个前缀之后，堆包含该前缀中杀死的怪物的最大可能数量，同时保持前缀移动平衡有效。 当平衡失效时，移除最大的成本是最优的，因为每个移除的怪物都会减少其相同的约束`y`值，最大值给出最小的计数损失。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    h = list(map(int, input().split()))

    heap = []
    chosen_sum = 0
    prefix = 0

    for value in h:
        x = value - 1
        prefix += x

        r = (b * (x % a)) // a

        kill_value = b * ((x - r * a) // b) - (r + 1)
        y = kill_value - x

        heapq.heappush(heap, -y)
        chosen_sum += y

        if chosen_sum > prefix:
            removed = -heapq.heappop(heap)
            chosen_sum -= removed

    print(len(heap))

if __name__ == "__main__":
    solve()
```变量`prefix`如果我们让对手处理每个怪物，则存储保存的移动的基线数量。 变量`chosen_sum`存储当前选择用于攻击的怪物引入的总修改。 

Python 的堆是最小堆，因此存储负值来模拟最大堆。 当前缀条件不成立时，取最大的`y`被删除。 这是唯一发生贪婪选择的地方。 

表达式`(x % a)`是安全的，因为`a`可以大到`10^9`，但 Python 整数不会溢出。 开始时减一也是必要的。 如果没有它，一开始只有 1 点生命值的怪物会被错误地处理。

 ## 边缘情况

 一个只有 1 点生命值的怪物是最容易犯差一错误的地方。 为了：```
1 10 1
1
```答案是`1`。 将健康值转换为`h - 1`，怪物有价值`0`。 公式给出`r = 0`，意味着一次攻击就足够了。 

当所有怪物都具有相同的生命值时，算法仍然必须尊重对手施加的命令。 为了：```
3 1 1
1 1 1
```选择每个怪物都会违反前缀条件。 该堆删除了最无用的选择并留下了两个怪物。 

当攻击力差异很大时，直接模拟是不可能的。 为了：```
4 5 10
100 100 100 100
```匝数是巨大的，但是模块化计算立即决定了最佳选择。 堆仅跟踪决策，而不跟踪单独的攻击。
