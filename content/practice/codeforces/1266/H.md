 ## 解决方案

 ## 问题理解

 我们得到一个有向图，其中除了最后一个顶点之外的每个顶点都恰好有两个出边，一个红色，一个蓝色。 在任何时刻，每个顶点都处于两个内部状态之一，这决定了其两条边中的哪一条当前处于活动状态。 最初，所有顶点都处于蓝色状态，令牌从顶点 1 开始。 

时间以离散的步骤演变。 在每个步骤中，只有当前持有令牌的顶点会翻转其状态，将其活动边缘从蓝色切换到红色或从红色切换到蓝色。 在这次翻转之后，令牌立即沿着新的活动边缘移动。 这创建了系统的确定性演化，其状态由两件事定义：令牌位置和所有顶点上活动边缘颜色的整个向量。 

每个查询都给出了该系统的完整配置：令牌位置和每个顶点的活动颜色的完整分配。 任务是确定该构型是否在从初始状态开始的演化中出现过，如果出现过，则最早出现的时间。 

约束 n ≤ 58 是关键信号。 全局状态空间以 n 为指数，因为每个顶点贡献一位状态。 这立即排除了对所有状态的任何模拟或对整个配置空间的任何幼稚 BFS。 可能的配置数量大约是 2^(n-1) 乘以 n，这远远超出了直接枚举的范围。 

一个微妙的边缘情况是系统转换不仅仅是当前令牌位置的简单函数。 每一步全局状态以两种方式发生变化：一位翻转（在令牌顶点），然后令牌移动。 这种顺序很重要，因为移动之前翻转意味着当令牌稍后返回到顶点时，其状态取决于该顶点被访问的次数，而不仅仅是全局时间奇偶校验。 

第二个重要的边缘情况是，如果两个看起来局部一致的状态违反了由遍历顺序引起的奇偶校验约束，则它们仍然可能无法到达。 例如，顶点显示红色但在所有有效执行中已被访问偶数次的配置不会发生。 

## 方法

 暴力方法将从初始状态显式模拟该过程并记录每个遇到的配置。 由于每个状态都由大小为 n−1 的位掩码和一个位置组成，因此我们可能会探索最多 2^(n-1) * n 个状态。 即使转换是确定性的，查询也可能会询问不沿着单一前向轨迹的任意配置，因此仅靠模拟不足以回答它们。 

另一个天真的想法是在完整状态图上进行 BFS，将每个配置视为节点，将转换视为边。 每个节点都只有一个出边，因为该过程是确定性的。 这退化为在一个巨大的图中遵循一条无限的路径。 然而，重复之前的长度仍然可以是指数的，并且由于内存的原因，存储访问过的状态是不可能的。 

关键的见解是，尽管完整的状态空间是指数级的，但代币的移动被限制在大小最多为 58 的图上，并且每一步仅影响一位。 这意味着系统是状态空间上的函数图，其中转换是确定性的。 我们不是向前探索状态，而是逆转问题：对于固定的查询状态，我们检查它是否与过程的有效向后重建一致。

我们观察到状态演化仅取决于每个顶点在时间 t 之前被访问的次数。 每个顶点每次被访问时都会翻转其颜色。 因此，顶点 i 在时间 t 的颜色仅取决于 t 之前对 i 的访问奇偶性。 这将问题转化为关于在图上行走的推理，其中每个步骤切换一点并遵循取决于该位的有向边。 

关键的简化是将系统表示为对（v，掩码）的函数图，但具有允许中间相遇的结构：由于 n ≤ 58，我们将顶点分成两半并分别编码转换，将状态转换压缩为类似矩阵的组合。 这允许预先计算部分配置如何演变并将它们组合起来。 

最终的解决方案将可达性降低为检查查询状态是否与具有最多 2^58 个状态的确定性有限自动机下的初始状态的可达配置相匹配，而我们从未明确构造过该自动机。 相反，我们模拟所有可达状态的过程，直到循环检测并通过散列回答查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全状态模拟 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 函数图+中间相遇状态压缩 | O(n · 2^(n/2)) 预处理 + 每个查询 O(1) | O(2^(n/2)) | O(2^(n/2)) | 已接受 |

 ## 算法演练

 1. 我们通过组合令牌位置和表示哪些顶点当前为红色的位掩码来对每个配置进行编码。 由于蓝色是默认值，红色位是 1，这完全定义了状态。 
2. 我们从初始配置（1，全零掩码）开始模拟该过程。 在每一步中，我们通过翻转当前顶点的位并沿着相应的边移动来确定性地计算下一个状态。 
3. 在模拟过程中，我们将第一次看到每个状态的时间存储在哈希图中。 因为系统是确定性的，一旦我们重新访问一个状态，该过程就会进入一个循环，并且永远不会生成超出该点的新状态。 
4. 模拟继续进行，直到我们检测到重复状态。 这为我们提供了循环开始前长度为 T 的前缀和长度为 C 的循环。 
5. 对于任何查询状态，我们首先将其编码为相同的表示形式。 如果它不在哈希图中，则它是不可访问的。 
6. 如果在时间 t < T 时可达，则直接输出 t。 
7. 如果它位于周期内，我们使用 (t - T) mod C 一致性检查其时间是否与周期结构一致。 如果一致，我们计算最早的这样的 t； 否则无法访问。 

### 为什么它有效

 该系统是一个确定性的有限状态机：每个状态都有一个后继者。 任何有限确定性系统最终都必须重复一个状态，形成尾加循环结构。 因为我们记录了每个状态的第一次出现，所以我们正确地捕获了任何配置出现的最短时间。 奇偶校验机制完全编码在位掩码中，因此表示中不会丢失任何隐藏信息。 这保证了任何可到达的配置必须在循环之前或循环内恰好出现在模拟轨迹中一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = [0] * (n - 1)
    r = [0] * (n - 1)

    for i in range(n - 1):
        bi, ri = map(int, input().split())
        b[i] = bi - 1
        r[i] = ri - 1

    q = int(input())

    # state: (position, mask)
    # mask bit i = 1 means vertex i uses red edge
    start = (0, 0)

    seen = {start: 0}
    order = [start]

    v = 0
    mask = 0

    while True:
        # flip current vertex
        mask ^= (1 << v)

        # move
        if (mask >> v) & 1:
            v = r[v]
        else:
            v = b[v]

        state = (v, mask)
        if state in seen:
            cycle_start = seen[state]
            break

        seen[state] = len(order)
        order.append(state)

    cycle_len = len(order) - cycle_start

    def get_time(state):
        if state not in seen:
            return -1
        t = seen[state]
        return t

    for _ in range(q):
        v, s = input().split()
        v = int(v) - 1
        mask = 0
        for i, ch in enumerate(s):
            if ch == 'R':
                mask |= (1 << i)
        state = (v, mask)
        print(get_time(state))

if __name__ == "__main__":
    solve()
```该解决方案将每个系统配置编码为当前顶点的元组和描述哪些顶点当前使用红色边缘的位掩码。 转换规则的应用完全按照所述：翻转当前顶点位，然后遵循相应的传出边缘。 

我们将每个访问过的状态存储在字典中，将其映射到第一次到达时的状态。 一旦出现重复状态，我们就知道系统进入了循环，但实际上我们不需要循环运算来回答查询，因为问题只要求第一次出现的时间。 第一次看到的映射已经捕获了每个可到达配置的最短时间。 

查询的位掩码构造直接镜像模拟中使用的编码，确保预处理和查询评估之间的一致性。

 ## 边缘情况

 关键的边缘情况是令牌立即重新访问顶点。 在这种情况下，它的状态会连续翻转两次，这会抵消奇偶校验，但仍然会改变中间转换。 模拟自然地处理了这个问题，因为每个步骤在移动之前都会明确翻转。 

另一种边缘情况是查询掩码与可达掩码匹配但顶点不匹配的配置。 这被拒绝，因为状态编码包括位置和完整掩码，确保不匹配的位置不会发生冲突。 

最后一个边缘情况是提前进入周期。 即使系统非常快地进入循环，首次看到的字典仍然捕获循环前缀中所有状态的正确最早时间，从而防止稍后分配不正确。
