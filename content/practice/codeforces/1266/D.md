 ## 解决方案

 ## 问题理解

 我们得到一个有向加权图，其中每个顶点代表一个人，每个有向边代表一个人对另一个人的债务。 边缘的价值是源人欠目的地人多少钱。 任务不是最小化债务数量，而是使用两个允许的操作来转换这些债务的结构，以便所有边权重的总和变得尽可能小，同时保持有效的表示。 

第一个操作是两个独立债务的重新路由：如果一个人欠另一个人并且存在第二个不相关的债务，我们可以在交叉连接之间重新分配一些金额。 这有效地允许通过中间结构转移债务流。 第二项操作消除了自债，这意味着任何陷入某人欠自己债务的循环都可以完全消除。 

关键的解释是债务可以通过中间节点“重新路由”，并且可以免费丢弃自循环。 目标是找到相同净财务失衡的等效表示，但总有向边权重最小。 

约束很大，最多10万人，30万债务，每项最多10^9。 这立即排除了任何二次构造或边缘的重复成对合并。 任何解决方案在边数上都必须接近线性，可能为 O(n + m) 或 O(m log m)。 内存也足够紧张，我们必须避免构造密集的邻接矩阵或图的重复扩展。 

当循环存在时，就会出现一个微妙的问题。 一种幼稚的方法可能会尝试贪婪地取消相反的流或在本地合并路径，但是当多个周期交互时，这会失败。 另一个棘手的情况是当一个顶点是多个传入和传出债务的一部分时； 幼稚的成对消除可能会留下非最佳的剩余循环，而这些剩余循环仍然会带来不必要的总权重。 

例如，如果1→2有10个，2→3有10个，3→1有10个，天真的取消可能无法意识到整个循环可以重新路由和消除，在自循环消除后只剩下零净成本。 

核心挑战是认识到只有每个节点的网络不平衡才重要，而不是流的确切路由。 

## 方法

 强力解释将尝试重复应用这两个操作，直到无法改进为止。 这将涉及选择边缘对、模拟重新路由和跟踪自循环，可能会探索 O(m^2) 组合。 每个操作可能会改变多个边缘，因此收敛可能需要许多步骤。 考虑到 m 达到 300,000，这太慢了。 

关键的见解是，只要保留净流入和流出约束，这些操作就可以完全自由地重新分配流量。 这意味着问题简化为跟踪每个节点有多少是净债务人或债权人。 

如果我们计算每个节点的净余额（定义为流出减去流入），那么正节点必须发出资金，负节点必须接收资金。 中间边的结构是无关紧要的，因为操作类型 1 允许在边对之间任意重新路由流。 这实际上意味着我们可以将图压缩为盈余节点和赤字节点之间的二分转移问题。 

一旦按照净余额对节点进行了分类，我们只需要将剩余节点与赤字节点贪婪地连接起来即可。 自循环会自动消失，因为它们代表节点余额的内部取消。 

我们对所有正余额和负余额进行排序或收集，然后使用两指针策略对它们进行匹配。 这构造了一个最多有 n−1 条边的有效最小表示。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(m^2) | O(米) | 太慢了 |
 | 净余额+贪婪匹配| O(m + n) | O(n) | 已接受 |

 ## 算法演练

 1. 通过添加支出债务并减去收入债务来计算每个节点的净余额。 这捕获了在概念上应用所有本地取消之后节点总体上是债权人还是债务人。 
2. 将节点拆分为两个列表：余额为正的列表和余额为负的列表。 正节点代表应该付钱的人，负节点代表应该收钱的人。 
3. 在这些列表上使用两个指针。 在每一步中，将当前正节点与当前负节点进行匹配。 转账金额是其绝对余额中的最小值。 这确保其中之一在转移后成为中立。 
4. 将此传输记录为输出中的最终边沿。 相应地减少两个余额。 
5. 当节点余额为零时移动指针。 继续，直到所有余额用完。 
6.输出所有构造的边。 这些代表了总金额最小的有效合并债务体系。 

这种贪婪配对起作用的原因是任何有效的允许操作序列仅保留每个节点的净平衡。 因此，最终的配置完全由这些余额决定，并且对之间的任何重新分配都是可以互换的。 

### 为什么它有效

 允许的操作保留每个顶点的净流。 操作一仅重新路由流量，而不更改每个节点的总进出量，操作二删除不影响任何其他节点的内部自流。 这意味着每个节点都有一个不变的值：其净余额。 

任何有效的最终配置必须满足每个节点的输出减去输入等于其初始计算余额。 贪婪匹配构造了一个最小边缘集，它完全满足这些约束，而不引入额外的中间循环。 由于每个单位的流量都是直接匹配盈余和赤字的，因此不会形成多余的循环，最终的构建不会出现自环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    balance = [0] * (n + 1)

    for _ in range(m):
        u, v, d = map(int, input().split())
        balance[u] += d
        balance[v] -= d

    pos = []
    neg = []

    for i in range(1, n + 1):
        if balance[i] > 0:
            pos.append([i, balance[i]])
        elif balance[i] < 0:
            neg.append([i, -balance[i]])

    i = j = 0
    res = []

    while i < len(pos) and j < len(neg):
        u, a = pos[i]
        v, b = neg[j]

        x = min(a, b)
        res.append((u, v, x))

        pos[i][1] -= x
        neg[j][1] -= x

        if pos[i][1] == 0:
            i += 1
        if neg[j][1] == 0:
            j += 1

    print(len(res))
    for u, v, d in res:
        print(u, v, d)

if __name__ == "__main__":
    solve()
```该解决方案首先将所有债务压缩到一个余额数组中。 每条边都对债务人有积极贡献，对债权人有消极贡献。 这消除了图的所有结构复杂性。 

然后我们通过平衡符号来分离节点。 两指针循环是我们显式构建最终边集的构造阶段。 每一步都保证了进展，因为至少有一个节点已完全解决。 

最终输出直接编码最少的必要传输，而无需构建中间循环或自循环。

 ## 边缘情况

 纯两节点取消情况（如 1→2 with 10 和 2→1 with 10）测试算法是否正确产生零输出。 余额计算为两个节点提供零，因此两个列表都是空的并且没有发出任何边，这与消除所有债务的预期相匹配。 

诸如 1→2→3→…→k→1 之类的长循环测试内部循环是否错误地生存。 余额数组变为全零，算法不输出任何内容，确认周期不会对最终债务产生影响。 

一个节点具有较大的传出边缘和许多较小的传入边缘的倾斜星形测试指针稳定性。 贪婪匹配确保部分传输被正确分割，而无需创建额外的中间节点，从而保持线性复杂性和正确性。
