 ## 解决方案
 ## 问题理解

 我们给出了代表一行元素的数字序列，每个元素都有两个属性：值和移除成本。 该游戏允许我们重复选择两个相邻元素并删除较小值的元素，并支付相关的删除成本。 每次删除后，数组的结构都会发生变化，因为元素会靠近，因此邻接始终是动态的。 

该过程可以持续任意次，但我们必须始终在数组中保留至少一个元素。 我们也有固定的预算，每次删除都会消耗该预算的一部分。 目标是在预算约束下执行一些删除序列后最大化数组中剩余的最小值。 

从约束角度来看，数组大小可达100000，预算可达10^18。 这立即排除了任何逐步模拟操作或尝试枚举删除序列的解决方案。 任何在 n 甚至 n log n 上具有重常数的二次方法都可能是可接受的，但任何比 O(n log n) 更糟糕的方法都会太慢。 

关键的困难在于删除不是任意的：它们取决于邻接性，并且每个操作都会删除所选相邻对中较小的一个。 这意味着删除特定元素并不独立于其他元素； 相反，可行性取决于我们是否可以重复将该元素“暴露”为某些相邻对中较小的元素。 

一些微妙的边缘情况值得牢记。 如果所有元素都已经很大但成本为零，我们可以积极删除并留下非常高的最小值。 如果成本非常大，我们可能根本无法删除任何东西，所以答案就是数组的最小元素。 另一个极端情况是最优策略只留下一个元素； 由于问题需要至少保留一个元素，因此我们必须确保永远不会删除所有内容。 

一个简单的误导性例子是全球廉价元素位于中间但被昂贵元素包围的情况。 即使局部删除成本低廉，该结构也可能会阻止其删除，因为如果不首先删除邻居，它永远不可能成为有效相邻对中较小的一个。 

## 方法

 强力解释将尝试模拟所有可能的删除序列。 在每一步中，我们选择任何相邻的对，删除较小的，并从预算中减去其成本。 这形成了一个巨大的状态空间，因为数组在每次操作后都会改变形状，并且可能的序列数量随着 n 呈指数增长。 即使 n = 40，这也是不可行的。 

关键的观察是，我们实际上并没有被要求模拟该过程，而只是确定我们是否可以消除足够的元素以确保保留某个最小值。 这表明我们要扭转观点：我们不是模拟删除，而是测试候选答案 x 是否可以实现。 

固定一个值x。 我们想知道是否有可能在最多花费 s 的情况下删除所有值小于 x 的元素。 如果我们能做到这一点，那么所有剩余元素的值至少为 x，因此最小值至少为 x。 这将问题变成了一个可以针对每个 x 独立解决的决策问题，这自然会导致对答案进行二分搜索。 

重要的部分是确定固定 x 的可行性。 如果我们选择不删除值至少为 x 的元素，则永远无法删除它，因此我们将它们视为“受保护”。 值小于 x 的元素必须被删除。 每个这样的元素都有一个成本，但它是否真的可以被删除取决于它是否可以在这个过程中与某个邻居配对。

一个关键的结构简化是，任何可移动元素最终都可以被删除，只要我们始终确保它在被幸存元素阻止之前参与有效的相邻对。 这将问题简化为所有值小于 x 的元素的成本累积，因为我们总是可以按照一种顺序组织删除，使它们能够独立于彼此的确切位置而被删除，前提是在删除时至少存在一个邻居。 

因此，对于固定的x，可行性简化为将所有值小于x的元素的成本相加，并检查该总和是否在预算s内，同时还要确保并非所有元素都被删除（必须存在至少一个值≥x的元素）。 

这将问题转换为 x 上的单调谓词，从而实现二分搜索。

 | ---| ---| ---| ---|
 | 暴力模拟| 指数| O(n) | 太慢了 |
 | 二分查找+可行性检查| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对值进行排序或在概念上将其视为最终最小答案的候选值，因为答案必须等于某个现有元素值。 这将搜索空间减少到最多 n 个可能性。 
2. 对表示最终数组中允许的最小值的候选阈值 x 进行二分搜索。 
3. 对于固定的 x，迭代数组并识别值严格小于 x 的所有元素，因为这些是我们必须删除的元素。 
4. 累计移除这些元素的总成本。 这代表消除所有违反阈值的元素所需的最低可能支出。 
5. 检查总成本是否在预算之内。 如果它超过 s，则 x 不可行，因为我们无法消除所有违规元素。 
6. 确保至少存在一个值≥x 的元素。 如果不存在，那么即使有足够的预算，我们也无法留下满足阈值的有效最终元素。 
7. 如果两个条件都满足，则将x标记为可行，并尝试增加它； 否则减少它。 
8. 二分查找完成后，输出最大可行x。 

### 为什么它有效

 关键的不变量是，可行性仅取决于我们是否可以在不超出预算的情况下消除低于阈值的所有元素，而不取决于删除的确切顺序。 任何删除给定元素的有效删除序列总是只支付一次成本，并且邻接约束不会增加所需的总成本，它仅限制排序。 由于我们始终可以安排删除，以便每个可移动元素最终在被幸存的较高元素阻塞之前配对并消除，因此总成本恰好是低于阈值的所有元素的成本之和。 因此决策问题在x上是单调的，这保证了二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def feasible(a, c, s, x):
    total = 0
    has_good = False
    n = len(a)

    for i in range(n):
        if a[i] >= x:
            has_good = True
        else:
            total += c[i]

    return has_good and total <= s

def solve():
    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    c = list(map(int, input().split()))

    vals = sorted(set(a))
    
    lo, hi = 0, len(vals) - 1
    ans = vals[0]

    while lo <= hi:
        mid = (lo + hi) // 2
        x = vals[mid]

        if feasible(a, c, s, x):
            ans = x
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先读取数组和成本结构，然后将候选答案压缩为仅数组的不同值。 可行性函数计算删除低于阈值的所有元素的成本，并检查是否存在至少一个有效的幸存者。 

二分查找保持了所有值的不变量`ans`是可行的，只要当前中点有效，它就会向上扩展。 

一个微妙的实现细节是我们从不显式模拟邻接操作。 这是有意为之的，因为即使原始问题是动态表述的，总成本也与最佳调度下的删除顺序无关。

 ## 边缘情况

 当所有元素都低于候选阈值时，可行性检查立即失败，因为没有幸存元素来锚定最终最小值。 该算法正确地拒绝了此类阈值，因为`has_good`仍然是错误的，防止无效答案。 

当预算为零时，唯一可行的答案是最小元素，因为任何删除较低价值元素的尝试都会产生正成本。 检查自然会强制执行此操作，因为`total`每当需要清除时就会变为正值。 

当所有成本为零时，每个低于阈值的元素都可以被自由删除，因此答案成为最大可能的元素值。 该算法捕获了这一点，因为`total`永远不会超过`s`，可行性仅取决于幸存元素的存在。 

当值严格增加或减少时，二分搜索仍然有效，因为可行性仅取决于按阈值划分，而不是结构或邻接，使得顺序与成本计算无关。
