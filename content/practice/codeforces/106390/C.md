 ## 解决方案
 ## 问题理解

 问题在于烤面包时利润最大化。 面团的数量是固定的，馅料的种类也有多种。 某种馅料的包子消耗一定量的面团和一定量的该馅料，然后获得一定的利润。 一个普通的面包只消耗面团并产生自己的利润。 任务是决定制作每种可能类型的面包数量，以使总收入尽可能大。 

输入给出了面团总数、馅料类型数量以及原味包子的要求。 每种馅料类型都描述了该馅料的存在量、一个面包需要多少馅料、该面包消耗了多少面团以及它赚了多少钱。 产出是可以赚取的最大金额。 

馅料种类少，面皮量大。 由于填充类型的数量最多为 10 个，因此我们可以对填充类型提供指数或动态规划解决方案。 然而，面团数量可以达到 1000 个，因此在没有状态限制的情况下尝试所有可能数量的面包的解决方案会增长太多。 我们需要使用少量的馅类别来控制搜索和面团量作为DP维度。 

主要陷阱是处理选择包子后剩下的面团。 原味小圆面包充当任何未使用的面团的填充物，因此答案不仅仅是填充小圆面包的最佳组合。 例如：```
10 1 3 100
5 10 2 1
```正确答案是300个。我们不能做包子，因为一个需要10个包子，而只有5个，所以我们应该做三个包子。 只考虑馅料选择而忘记普通面包的解决方案将输出零。 

另一个棘手的情况是，当某种馅料类型每单位面团的利润较差，但由于它有效消耗有限的馅料而变得有用时。 例如：```
10 2 5 1
100 1 5 10
2 10 1 100
```正确答案是10。我们可以做两个第一种类型的面包。 总是选择每个面团最佳价值的贪婪方法会错误地选择第二种类型，因为它看起来更有利可图，但馅料限制阻止了这种情况的发生。 

## 方法

 直接的强力解决方案将尝试每种填充类型的所有可能计数。 对于每种类型，我们决定烤多少个面包，然后检查总馅料和面团用量是否有效。 该方法是正确的，因为每种可能的组合都会被检查，因此必须找到最有效的组合。 问题是每种填充类型最多可以有 1000 种可能的计数，而最多有 10 种类型，这会导致组合过多。 最坏的情况接近1000^10种可能性，这是不可能的。 

有用的观察结果是馅料类型的数量很少。 我们不必跟踪面包的每种可能的分布，而是可以逐一处理馅料类型，并仅存储每种使用的面团量可实现的最佳利润。 状态大小受面团数量限制，只有1000个。 

在加工馅料类型时，我们会尝试用它制作的所有可能数量的面包。 如果我们做k个这种类型的包子，我们就能准确地知道它们消耗了多少馅料和面团，以及它们增加了多少利润。 这是有界背包过渡。 当所有的馅料类型都处理完后，剩下的面团可以转化为原味包子，所以我们简单地将最好的原味包子利润添加到每个状态。 

蛮力之所以有效，是因为它会探索每个组合，但会失败，因为组合计数会爆炸。 DP之所以有效，是因为不同的馅料选择只与已经花费的面团数量和赚取的利润有关，而这正是国家储存的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(可能计数的乘积) | O(1) | O(1) | 太慢了|
 | 最佳| O(m * n * 100) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个动态规划数组，其中`dp[j]`代表准确使用后的最大利润`j`到目前为止加工的馅料类型的面团克数。 最初，使用零面团带来的利润为零。 
2. 对于每种馅料类型，计算可用馅料可以制作的最大面包数量。 我们不能超过这个数字，因为馅料是有限的资源。 
3. 对于每个可能的先前面团使用情况和当前类型的每个可能的面包数量，更新新状态。 制作`k`面包添加`k * d[i]`利润和消耗`k * c[i]`面团。 
4. 加工完所有类型的包子后，请考虑已使用的所有可能的面团量。 剩下的面团只能用来做普通包子，所以添加`(remaining dough / c0) * d0`到那个状态。 
5. 所有最终状态中的最大值就是答案，因为代表了使用馅料的所有有效方法，并且剩余的面团最适合用普通面包填充。 

为什么它有效：不变的是在处理填充类型的任何前缀之后，`dp[j]`在所有精确支出方式中存储尽可能最大的利润`j`仅使用那些加工类型的面团克数。 每个转换都会考虑添加当前填充类型任意可能的次数，因此它涵盖了每个新的有效组合。 由于普通面包除了面团之外没有有限的资源，因此最后处理它就完成了所有可能的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())
    items = []

    for _ in range(m):
        a, b, c, d = map(int, input().split())
        items.append((a // b, c, d))

    dp = [-1] * (n + 1)
    dp[0] = 0

    for limit, cost, value in items:
        ndp = [-1] * (n + 1)
        for used in range(n + 1):
            if dp[used] == -1:
                continue
            for cnt in range(limit + 1):
                new_used = used + cnt * cost
                if new_used > n:
                    break
                profit = dp[used] + cnt * value
                if profit > ndp[new_used]:
                    ndp[new_used] = profit
        dp = ndp

    ans = 0
    for used in range(n + 1):
        if dp[used] != -1:
            total = dp[used] + ((n - used) // c0) * d0
            if total > ans:
                ans = total

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将每种填充类型转换为可用限制。`a // b`是该类型面包的最大数量，因为每个面包都会消耗`b`填充单位并且仅`a`单位存在。 

为每种填充类型重建 DP 数组，以便过渡不会意外地多次使用相同的填充超出其限制。 对于每个可达到的面团量，内循环会尝试当前面包类型的所有可能计数。 

最后一个循环是处理普通面包的地方。 国家已经包含了包子的利润，剩下的面团则尽可能多地加工成素包子。 这避免了需要另一个 DP 维度。 

过渡的边界条件是`new_used > n`。 一旦超过面团限制，就不可能进行更大的计数，因此循环可以停止。 Python 整数对于最大利润范围来说足够大，因此不需要溢出处理。

## 复杂度分析

 | --- | --- | --- |
 | 时间 | O(m * n * 100) | 对于每种馅料类型，每个面团量都会尝试最多 100 个可能的面包计数，因为馅料量受 100 | 限制。

 ## 边缘情况

 当没有足够的馅料来制作哪怕一个包子时，算法就会使这些转换不可用。 对于这个案例：```
10 1 3 100
5 10 2 1
```填充限制变为零，因为`5 // 10 = 0`。 DP只保留空馅选择，最后一步制作三个素包子，利润为300。 

当看起来最有利可图的馅料不是最佳整体选择时，DP 仍然有效，因为它比较完整的组合。 在：```
10 2 5 1
100 1 5 10
2 10 1 100
```第二种不能充分使用，因为它的馅料有限。 转换包括第一种类型的选择，最终答案变为 10。 

当所有面团都应该用于普通面包时，最后的传递状态会自然地处理它。 面团消耗为零的 DP 状态仍然有效，剩余面团计算会产生最大的原味面包数。 这避免了需要特殊情况。
