 ## 解决方案
 ## 问题理解

 有几家公司排成一行，索引从 1 到 n。 存在许多投资组合，每个投资组合最初“属于”某个公司。 然而，它并没有被迫留在那里。 

每个封装都有一个由值 l 确定的灵活性范围。 源自公司 c 的包裹可以分配给任何公司 x，只要 x 离 c 不太远，特别是如果距离 |c − x| 至多为 l。 选择有效目的地后，包裹必须准确分配给一家公司。 

我们可以在有效的公司之间免费分发所有软件包。 我们关心的约束是最终分配的平衡程度：对于每个公司，计算其收到的包裹数量，并且我们希望使这些计数的最大值尽可能小。 任务是计算这个最小可能的最大负载。 

输入描述了多个独立的场景。 每个场景给出公司数量 n，包裹数量 m，然后是两个数组：一个代表每个包裹的原始所有者，另一个代表其灵活半径。 每个场景的输出都是一个整数，表示在最佳重新分配后分配给任何公司的最大数量的包裹中的最小可能值。 

关键的隐藏结构是每个包没有任意一组目的地。 相反，每个包 i 定义了从 c_i − l_i 到 c_i + l_i 的连续有效公司区间，并剪裁到范围 [1, n]。 因此，每个包都是一个区间请求，必须恰好分配给其区间内的一个整数点。 

从复杂性的角度来看，每个测试总数 n 和 m 都可以大到 2⋅10^5。 任何尝试以简单的方式模拟分配或独立检查每个 Z 值的可行性的解决方案都会太慢。 将每个包分配给某个有效公司的直接贪婪模拟也会失败，因为本地选择很容易阻止以后的分配，从而增加其他地方的拥塞。 

当所有包都高度灵活并且几乎到处重叠时，就会出现微妙的边缘情况。 在这种情况下，贪婪的“填充当前负载最小的有效公司”策略可能会产生不正确的分布，因为即使存在更全局平衡的分配，早期决策也可能以人为增加峰值负载的方式集中间隔。 

当间隔非常窄时会出现另一种边缘情况，例如对于所有 i，l_i = 0。 然后每个包都被强制发送到它原来的公司，答案就是任何 c_i 的最大频率。 任何忽略这种退化并假设重新分配是可能的解决方案都会高估可行性。 

## 方法

 直接的暴力方法会尝试一一分配每个包，探索所有有效的选择。 这是正确的，因为它尊重所有约束，但分支因子很大。 在最坏的情况下，每个包最多可以映射到 O(n) 个公司，因此状态空间呈指数级爆炸，即使对于小输入也是不可行的。 

稍微结构化一点的蛮力会固定候选值 Z 并检查是否可以分配包，以便没有公司收到超过 Z 的数据。这变成了一个类似于流的可行性问题：每个包必须分配到其间隔中的一个位置，并且每个位置都有容量 Z。直接的最大流构造可以工作，但是构建具有 O(n + m) 个节点和 O(mn) 边的完整流图太大，甚至优化的流对于在所有 Z 上重复检查也太慢。

关键的观察是我们实际上不需要显式地模拟分配。 我们只需要确定最小的容量Z，使得每个区间都可以被打包成整数点而不超过容量。 这是一个经典的“容量限制的区间分配”问题，如果我们按顺序处理头寸并在尊重可用性的同时始终尽可能晚地分配区间，则可以进行贪心检查。 该结构使我们能够思考从左到右扫描并维护当前处于活动状态的间隔。 

我们可以将问题转化为直接计算最小 Z，而不是重复尝试固定的 Z，通过跟踪在最佳排列中的任意点有多少个间隔被迫重叠。 每个包贡献一个范围，当所有间隔都被最佳分配时，答案就成为任何位置引起的最大负载。 最优策略相当于始终将每个包裹放置在其范围内尽可能靠右的位置，这样可以防止不必要的早期拥塞。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配搜索 | 指数| O(米) | 太慢了|
 | 按 Z 进行基于流程的可行性检查 | 每张支票的 O(flow) | O(n + m) | 太慢了|
 | 贪心区间放置+扫描| O((n + m) log m) | O((n + m) log m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 将每个包转换为区间 [L_i, R_i]，其中 L_i = max(1, c_i − l_i) 且 R_i = min(n, c_i + l_i)。 这将问题重新表述为将区间放置在整数点上。 
2. 按左端点对所有间隔进行排序。 这种排序确保我们按照间隔的放置顺序来考虑间隔，这对于保持一致的扫描是必要的。 
3. 扫描从1到n的位置，维护左端点≤当前位置但尚未分配的所有区间的数据结构。 
4. 在每个位置 x 处，将从 x 开始的所有间隔插入到由其右端点键入的优先级结构中。 正确的端点决定了紧迫性：必须尽早分配较早结束的间隔，以避免稍后失去可行性。 
5. 当当前分配给位置 x 的区间数量小于目标容量 Z 时，重复从活动结构中取出具有最小右端点的区间并将其分配给 x，只要 x ≤ 其右边界。 如果不存在这样的间隔，我们继续前进。 
6. 处理完所有位置后，检查是否所有区间都已分配。 如果是，则 Z 可行； 否则就不是。 
7. 要找到最小 Z，请在从 1 到 m 的答案范围内使用二分搜索，并使用上述扫描测试可行性。 

总是分配最早完成时间的区间的贪婪选择确保我们永远不会在可以生存更长时间的区间上“浪费”早期头寸，从而为以后更紧密的区间保留灵活性。 

### 为什么它有效

 在任何位置 x 处，唯一重要的约束是可以在那里分配多少个覆盖 x 的区间。 在仍然可以放置在 x 处的所有区间中，选择具有最小右端点的区间是安全的，因为它的未来灵活性最小。 任何分配较晚结束间隔的最佳解决方案都可以转换为将其与较早结束间隔交换的解决方案，而不会降低可行性。 此交换参数保留有效性并确保贪婪分配不会阻止任何可以实现相同或更小的最大负载的解决方案。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def can(Z, intervals, n):
    intervals = sorted(intervals)
    i = 0
    active = []
    used = 0

    for x in range(1, n + 1):
        while i < len(intervals) and intervals[i][0] == x:
            heapq.heappush(active, intervals[i][1])
            i += 1

        count = 0
        while active and count < Z:
            r = heapq.heappop(active)
            if r < x:
                continue
            count += 1
            used += 1

        # remove expired intervals
        while active and active[0] < x:
            heapq.heappop(active)

    return used == len(intervals)

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        c = list(map(int, input().split()))
        l = list(map(int, input().split()))

        intervals = []
        for i in range(m):
            L = max(1, c[i] - l[i])
            R = min(n, c[i] + l[i])
            intervals.append((L, R))

        lo, hi = 1, m
        ans = m

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, intervals, n):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个包转换为有效公司的有限区间。 可行性检查功能使用扫描线和按右端点排序的最小堆来模拟为每个位置分配最多 Z 间隔。 堆确保在所有当前可用的间隔中，我们总是分配那些如果不立即放置就会首先过期的间隔。 

二分搜索包含此可行性检查，以找到有效的最小 Z。 关键的实现细节是确保过期的间隔被删除并且永远不会计入分配，否则扫描将错误地允许无效的放置或超量容量。

 ### 示例 1

 输入：```
n = 3
packages: (1,0), (1,1), (2,1)
```间隔：

 转换后的 (1,1)、(1,2)、(1,3)

 我们测试 Z = 1。 

当 x = 1 时，所有三个间隔均处于活动状态。 我们指定具有最小右端点 (1,1) 的那个。 其余两个不能全部以容量 1 放置在位置 1 到 3 上，因为在 x = 1 和 x = 2 时，我们超出了容量。 

| x| 活动间隔| 分配于 x | 剩余|
 | --- | --- | --- | --- |
 | 1 | (1,1),(1,2),(1,3) | (1,1),(1,2),(1,3) | (1,1) | 2 |
 | 2 | (1,2),(1,3) | (1,2),(1,3) | (1,2) | 1 |
 | 3 | (1,3) | (1,3) | 0 |

 Z = 1 在此起作用，确认最小负载为 1。

 ## 边缘情况

 当所有包的 l_i = 0 时，每个区间都会折叠为一个点。 该算法简化为计算每个公司的频率。 扫描仍然有效，因为每个间隔仅进入一个位置，并且在容量允许的情况下立即分配。 

当所有区间覆盖整个范围[1,n]时，每个位置都会看到所有m个区间。 堆始终包含所有包，贪婪过程将它们均匀分布在各个位置，产生 Z = ⌈m / n⌉。 该算法自然地处理这个问题，因为每个位置在前进之前都已填充到 Z。 

当间隔像 [1,n]、[2,n]、[3,n] 一样嵌套时，贪婪选择始终首先分配较早结束的间隔，从而防止后期拥塞。 这保留了可行性并避免了过早分配长间隔会阻止放置选项较少的短间隔的陷阱。
