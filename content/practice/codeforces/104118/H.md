 ## 解决方案
 ## 问题理解

 我们得到了一系列练习。 对于每个练习，鲍勃都有三种可能的选择：跳过它、做简单版本或做强度版本。 每个选择的能量成本都是0，$a_i$， 或者$b_i$分别与$a_i < b_i$。 

鲍勃有一个总能量预算$x$，并且每次练习我们必须选择一个选项，以使总能量不超过$x$。 

在所有有效计划中，选择是根据三个标准按字典顺序进行判断的。 首先，我们必须避免超过能量限制，并且在所有有效的计划中，我们希望尽量减少跳过的练习次数。 确定最小跳过次数后，我们希望最大化选择的强烈版本数量。 

因此，决策结构并不是纯粹出于成本或利益的贪婪。 我们同时最小化跳跃（这相当于最大化我们采取的非零选择的数量），然后最大化其中的强度。 

约束条件很大：最多$2 \cdot 10^5$练习和非常大的能量预算高达$10^{15}$。 这排除了任何指数搜索或 DP 能量。 即使对物品进行二次 DP 也会太慢。 

关键的困难在于每次练习都有三种状态，但目标不是一个简单的背包：我们正在全球预算下按字典顺序对两个目标进行优化。 

如果我们尽可能地贪婪地选择强度，就会出现微妙的失败案例。 例如，假设一项练习有$a_i = 1, b_i = 100$，另一个有$a_j = 2, b_j = 3$，预算很少。 在第一个项目上采取强度可能会消耗太多预算并迫使跳过许多后续项目，这比采取允许更多总体参与的简单选择更糟糕。 所有项目之间的耦合使得局部决策不安全。 

如果我们首先尝试通过贪婪地在各处采用简单版本，然后在可能的情况下升级到密集版本来最大程度地减少跳过，则会出现另一种失败情况。 这可能会失败，因为升级不是独立的：将简单升级到强化会增加成本$b_i - a_i$，并且某些升级可能会阻止其他强制性简单选择的可行性，从而间接改变跳过计数。 

## 方法

 蛮力的想法是在每次练习时考虑所有三个选择并检查可行性。 这是$3^n$可能性，立即不可能。 

更结构化的蛮力是对项目和剩余能量的动态编程。 我们可以将 DP 状态定义为每种可能的能量使用的最小跳跃和最大强度计数。 然而，能量上升到$10^{15}$，所以这个状态空间太大了。 即使压缩，转换仍然需要迭代每个项目的所有状态，导致粗略$O(n \cdot x)$，这是不可行的。 

关键的观察结果是，最大限度地减少跳过次数相当于最大限度地增加练习次数，这意味着我们应该首先尝试尽可能地为每个项目分配简单或激烈的练习。 跳过某个项目的唯一原因是即使是简单版本也缺乏剩余能量。 

这表明了一个两级结构。 首先，我们尝试决定必须跳过哪些项目以使可能选择的总成本可行。 在所有避免跳过的方法中，只要我们能负担得起升级费用，我们就会更喜欢激烈的而不是简单的。 

这种转变是根据基线来思考，其中每个项目都以简单的成本获取。 这给出了总基线能量$S = \sum a_i$。 如果$S > x$，那么我们甚至无法获得简单级别的所有项目，因此必须跳过某些项目。 每次跳过都会消除成本$a_i$，并且我们希望最小化跳过，因此我们应该跳过最大的项目$a_i$第一的。 

如果$S \le x$，则无需跳过。 现在我们尝试将一些项目从简单升级到密集，每次升级都会增加成本$b_i - a_i$。 由于跳跃已经最小化，我们现在最大化升级数量，但受到剩余能量的限制。 

这将问题简化为经典的贪婪升级问题：从所有简单的开始，我们首先反复选择成本增加最小的升级。 

最终的结构变成：如果必要的话可能会删除一些项目，然后贪婪地升级剩余的项目。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举|$O(3^n)$|$O(n)$| 太慢了|
 | DP 比能量 |$O(n \cdot x)$|$O(x)$| 不可能|
 | 贪婪基线+升级|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们分两个阶段构建解决方案，首先以最小的跳跃确保可行性，然后最大化强度。 

## 算法演练

 1. 如果所有练习都以简单模式进行，请计算总成本。 这是$S = \sum a_i$。 这代表了最小化跳过的最佳情况，因为每次进行的锻炼对能量消耗的贡献最小。 
2.如果$S > x$，我们必须跳过一些练习。 每次跳过都准确保存$a_i$能量，因此为了以最少的跳过次数尽可能降低总成本，我们应该跳过最大的练习$a_i$第一的。 排序依据$a_i$下降确保每个跳跃都能最大限度地减少能量，从而最大限度地减少所需跳跃的数量。 
3. 在决定跳过哪些练习后，我们将剩余的练习固定为强制“至少完成简单级别”项目。 由此产生的基准成本现在保证为$\le x$。 
4. 计算剩余预算$R = x - \sum a_i$超过不可跳过的项目。 这是可用于升级的预算。 
5. 对于每个不可跳过的练习，定义升级成本$c_i = b_i - a_i$。 这是从简单到强度所需的额外能量。 我们的目标是在预算范围内选择尽可能多的升级$R$，因为每次升级都会增加剧烈练习的次数。 
6. 对剩余练习进行排序$c_i$上升。 按此顺序迭代并升级练习当且仅当$c_i \le R$，然后减去$c_i$从$R$。 首先选择最小的增量可确保我们最大化升级数量，因为每次升级都会独立消耗预算并同等地实现目标。 
7. 输出最终作业：跳过的项目标记为 0，升级的项目标记为 2，其他所有标记为 1。 

### 为什么它有效

 关键的不变量是，在步骤 3 之后，所有剩余的项目都是强制性的，因为跳过任何附加项目只会增加跳过计数超出可实现的最小值。 因此，问题完全简化为一个背包，其中每个物品都已包含在基本成本中，并且只有升级仍然是可选的。 由于每次升级具有相同的价值（一项密集的任务）但成本不同，因此最佳策略是首先进行最便宜的升级，这是标准的交换论点：任何采用更昂贵的升级而跳过更便宜的升级的解决方案都可以通过交换它们来改进，而不会影响可行性或客观价值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

idx = list(range(n))

# Phase 1: try to minimize skips
base = sum(a)

skip = [False] * n

if base > x:
    # need to skip some items
    idx.sort(key=lambda i: a[i], reverse=True)
    cur = base
    for i in idx:
        if cur <= x:
            break
        skip[i] = True
        cur -= a[i]
    base = cur

# remaining items
remaining = [i for i in range(n) if not skip[i]]

# Phase 2: maximize upgrades
gain = [(b[i] - a[i], i) for i in remaining]
gain.sort()

R = x - sum(a[i] for i in remaining)

upgrade = [False] * n
for c, i in gain:
    if c <= R:
        R -= c
        upgrade[i] = True

# build answer
ans = []
for i in range(n):
    if skip[i]:
        ans.append('0')
    elif upgrade[i]:
        ans.append('2')
    else:
        ans.append('1')

print(''.join(ans))
```该代码首先计算在简单模式下执行所有操作的基线成本。 如果超出预算，它会贪婪地删除高成本的简单项目，直到恢复可行性，这直接对应于最大限度地减少跳过练习的数量。 

之后，它将所有剩余项目视为按成本计算的强制性项目$a_i$，并使用剩余预算升级其中一些。 排序依据$b_i - a_i$确保每个单位的额外能量首先用于最有效的强度增益。 

跳跃处理和升级处理的分离至关重要，因为混合它们会错误地耦合两个不同的优化目标。 

## 工作示例

 我们追踪示例 1 的简化版本。 

假设：$n=4, x=6$

$a = [1,5,2,1]$

$b = [3,7,3,4]$基线成本是$1+5+2+1 = 9$，这超过了$x=6$。 所以我们必须跳过。 

我们排序依据$a_i$降序：索引按$a$是项目 2 (5)、项目 3 (2)，然后是项目 1 和 4 (1)。 

我们先跳过第 2 项，将成本降低到 4，这已经是$\le 6$。 因此只需要一个跳过。 

其余项目是具有基准成本的指数 1、3、4$1+2+1=4$。 剩余预算为$2$。 

现在升级成本为：

 第 1 项：2，第 3 项：1，第 4 项：3。 

我们按成本排序：项目 3、项目 1、项目 4。 

我们升级项目 3（成本 1），剩余预算 1，然后无法升级项目 1（成本 2），停止。 

最后：一跳，一激烈，轻松休息。 

现在是第二个构建的示例：$n=3, x=5$

$a=[2,2,2]$,$b=[5,5,5]$基线是 6，所以我们必须至少跳过一项。 跳过最大的一个$a_i$减少到4个，可行。 剩下的两件物品花费 4，预算剩余 1，所以不可能升级。 输出将有一个 0、两个 1。 

这些痕迹表明，决定跳过纯粹是为了以最少的数量满足可行性，而升级纯粹是事后的预算优化。

 ## 边缘情况

 一个关键的边缘情况是初始简易求和已经完全符合预算。 在这种情况下，不应触发任何跳过逻辑，并且算法应直接进行升级。 例如，如果$a=[2,3], x=5$，那么这两项都是必填项。 该算法不设置跳过，仅考虑升级成本。 由于升级可能超出预算，因此它会根据剩余容量正确生成 1 秒和 2 秒的混合。 

另一种边缘情况是，即使跳过除一个项目之外的所有项目，仍然超出预算。 由于限制，这不可能发生$a_i \ge 1$，但算法自然会处理它：它不断跳过直到可行，最终只剩下一项，保证终止和正确性。 

最后一个微妙的情况是多个项目共享相同的内容$a_i$或相同的升级成本。 排序不依赖于唯一性，因此关系不会影响正确性。 等成本项目之间的任何顺序都保留了可行性和最优性，因为互换不会改变总成本或目标价值。
