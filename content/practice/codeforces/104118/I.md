 ## 解决方案
 ## 问题理解

 我们得到了一大堆按照严格的依赖系统排列的项目。 有些物品是已经存在数量有限的基本资源，而所有其他物品都是通过消耗先前定义的物品的配方来生产的。 关键的结构属性是每个配方仅使用具有较大 ID 的项目，这保证了没有循环并强制从高 ID 到低 ID 的自然计算顺序。 

在所有项目中，前n个是特殊的。 这些是我们在最终答案中唯一关心的项目，它们不能作为任何其他食谱中的成分出现。 目标是确定有多少这些特殊物品可以至少生产一次，假设我们只从给定数量的原材料开始。 

每个手工制作的物品都会消耗其配方中每种成分的一个单位。 由于成分本身可能是由其他成分制成的，因此生产最终产品可以扩展为对原材料的全面要求。 核心难点在于配方形成多层DAG，因此每个最终产品都对应于原材料的需求向量而不是直接成本。 

这些限制迫使我们远离任何针对每个查询的制作模拟。 可能有多达二十万个项目和五十万个总配方边，因此任何重复重新计算每个最终项目的依赖关系的解决方案都会太慢。 但原材料的数量最多为十个，最终产品的数量最多为十五个。 这种分割是主要的结构提示：图很大，但实际资源约束的维度却极小。 

中间重用会产生微妙的边缘情况。 中间物品可能会在多个配方中使用，因此其成本必须计算一次并重复使用。 例如，如果两种不同的最终产品需要项目 A，则单独重新计算每个产品的原材料成本将会重复计算工作，并可能导致实施不一致。 正确的解释是，每个项目每单位都有一个固定的“原材料成本向量”，与以后如何使用无关。 

如果试图贪婪地按顺序生产产品，就会出现另一个问题。 即使一种产品单独来看很便宜，生产它也可能会消耗多种其他产品所需的稀有原材料。 这使得当地决策变得不可靠； 我们必须在全球范围内评估最终产品的子集。 

## 方法

 直接的强力策略是通过递归地将其配方扩展到原材料来模拟独立制作每个最终产品。 原则上这是可行的，因为依赖图是非循环的，所以我们可以通过 DFS 计算每个最终产品的成本向量。 获得这些向量后，我们可以尝试最终产品的所有子集，并检查其原材料需求的总和是否符合可用库存。 

这种蛮力已经包含了正确的分解，但如果不小心实施，其成本来自于重复递归。 如果没有记忆，每个产品都可以通过重叠的子图进行扩展，从而导致指数重复。 即使使用记忆化，真正的成本挑战也会转移到子集枚举，即 2^n，其中 n 最多为 15，因此该部分实际上是可以接受的。 

关键的观察结果是该结构自然地分为两个阶段。 首先，我们将整个大 DAG 压缩为一个小的固定维度表示：每个项目变成一个大小最多为 10 的向量，描述它消耗了多少单位的每种原材料。 其次，我们使用这些向量解决最多十五个项目的小型组合优化问题。

一旦每个项目被表示为 10 维成本向量，问题就变成：选择最多 15 个向量的最大子集，使得它们的坐标总和不超过固定容量向量。 这是针对小维度约束的经典子集可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个最终产品的天真的重复扩展| O(n·m) 最坏情况或更糟，无需记忆 | O(米) | 太慢/有风险|
 | 构建成本向量+子集枚举| O(m + 2^n · n · K) | O(m + 2^n · n · K) | O(m·K) | 已接受 |

 这里K是原材料的数量，最多十个。 

## 算法演练

 我们首先将整个依赖图压缩为每个项目的原材料成本，然后解决最终项目的子集选择问题。 

1. 识别所有原材料项目，并为每个原材料项目分配一个从 0 到 K−1 的索引。 每个这样的项目仅贡献其自身类型的一个单位，而不是其他。 
2. 为每个项目创建一个成本向量。 对于原材料项来说，这个向量是与其自身相对应的单位向量。 对于任何制作的物品，将其成本向量初始化为全零。 
3. 按 ID 升序处理项目。 由于每个配方仅使用具有较大 ID 的项目，因此保证项目的所有成分都已计算出其成本向量。 
4. 对于每个制作的物品，通过将其配方中所有物品的成本向量相加来计算其成本向量。 这是有效的，因为制作会消耗每种成分的一个单位，因此原材料需求会线性增加。 
5. 预处理后，提取前 n 个项目的成本向量。 这些是我们在最终选择中唯一可以选择的候选人。 
6. 使用位掩码枚举这 n 个项目的所有子集。 对于每个子集，通过对所包含项目的成本向量求和来计算总原材料消耗量。 
7. 通过验证每个原材料尺寸不超过可用供应来检查每个子集的可行性。 
8. 跟踪满足约束的最大子集大小。 

这种结构的关键点是，每个项目都有一个固定的原材料分解过程，与它最终形成的最终产品无关。 这使得子集评估具有一致性和可加性。 

### 为什么它有效

 该算法依赖于压缩不变量：在步骤 4 之后，每个项目 i 都由一个向量完全表征，该向量表示生产一个 i 单位所需的每种原材料的确切数量。 由于菜谱形成按 ID 递减排序的 DAG，因此该向量定义良好，并且每个项目只计算一次。 每个可行的最终产品集都对应于这些向量的一个子集，其坐标总和尊重资源限制，并且算法检查的每个子集都对应于有效的同步制作计划，因为只要原材料足够，中间物品就始终可以独立生产。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())

    ingredients = [[] for _ in range(m + 1)]
    raw_id = []
    raw_index = [-1] * (m + 1)

    for i in range(1, m + 1):
        tmp = list(map(int, input().split()))
        c = tmp[0]
        if c == 0:
            raw_id.append(i)
        else:
            ingredients[i] = tmp[1:]

    K = len(raw_id)
    for idx, rid in enumerate(raw_id):
        raw_index[rid] = idx

    p = [0] * K
    # second pass to read raw quantities
    # (we reparse lines implicitly is not possible; instead store earlier)
    # so we store separately
    sys.stdin.seek(0)
    input()
    raw_qty = [0] * (m + 1)
    parsed_ing = [[] for _ in range(m + 1)]

    for i in range(1, m + 1):
        tmp = list(map(int, input().split()))
        c = tmp[0]
        if c == 0:
            raw_qty[i] = tmp[1]
        else:
            parsed_ing[i] = tmp[1:]

    # rebuild ingredients correctly
    ingredients = parsed_ing

    cost = [[0] * K for _ in range(m + 1)]

    for i in range(1, m + 1):
        if raw_index[i] != -1:
            cost[i][raw_index[i]] = 1
        else:
            for v in ingredients[i]:
                for k in range(K):
                    cost[i][k] += cost[v][k]

    final = list(range(1, n + 1))

    best = 0
    size = len(final)

    for mask in range(1 << size):
        total = [0] * K
        ok = True
        cnt = 0

        for i in range(size):
            if mask & (1 << i):
                cnt += 1
                fi = final[i]
                for k in range(K):
                    total[k] += cost[fi][k]
                    if total[k] > raw_qty[raw_id[k]]:
                        ok = False
                        break
                if not ok:
                    break

        if ok:
            best = max(best, cnt)

    print(best)

if __name__ == "__main__":
    main()
```该解决方案首先将原材料与手工制品分开，并在紧凑的向量空间中为每种原材料分配一个固定索引。 然后，它构建一个反向依赖表示，以便每个项目都可以扩展到原材料需求。 

成本计算循环是关键的压缩步骤。 每个项目都会累积其成分的原材料向量，这是有效的，因为每个配方都会消耗每种成分的一个单位。 由于依赖项始终指向更高的 ID，因此在处理项目时已经计算了所有必需的值。 

最后，子集枚举检查最终产品的每个组合。 可行性检查是逐步进行的，一旦超过任何原材料限制，就会提前停止。

## 复杂度分析

 | 测量 | 复杂性 | 说明|

 | 空间| O(m·K) | 存储每个项目的成本向量|

 ## 边缘情况

 一种边缘情况是多个最终产品共享深度依赖链。 该算法可以正确处理此问题，因为每个中间项都作为共享向量计算一次。 例如，如果两个最终产品都依赖于同一个中间产品，则该中间产品对两个成本向量的贡献相同，因此会自动考虑重用。 

另一种极端情况是原材料不直接用于最终产品，而是仅通过长链使用。 预处理步骤仍然分配正确的向量，因为原材料向上传播到配方的每一层，确保不会遗漏任何隐藏的依赖关系。 

最后的边缘情况是，最佳解决方案需要跳过看似便宜的产品，以保留稀有的原材料用于另一种组合。 子集枚举显式地评估所有组合，因此可以自然地捕获此类权衡，而不需要贪心推理。
