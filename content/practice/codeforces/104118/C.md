 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，代表写在学生衬衫上的值。 每天，每个头寸都会根据全球统计数据同时更新其价值：一个值`v`变为出现的次数`v`当日整个阵中。 

所以该进程不是本地的。 每个元素都会查看整个数组，计算其当前值出现的次数，并用该计数替换自身。 重复这个操作`k`次，我们需要最终的数组。 

关键的难点在于`k`可以大到$10^9$，所以我们不能用直接的方式来模拟每一天。 

约束意味着数组长度最多为$2 \cdot 10^5$，因此任何解决方案在每个执行步骤中都必须接近线性或线性算数，并且执行步骤的数量必须非常小。 任何东西都成正比`k`立刻就不可能了。 

一个微妙的边缘情况来自这样一个事实：值可以大到$10^9$，但在第一次转换后，所有值都会崩溃到该范围内$[1, n]$，因为频率不能超过`n`。 这种崩溃是使问题易于处理的关键结构简化。 

一个天真的但重要的错误是假设值不断增长或随机行为。 例如，考虑：

 输入：```
5 2
100 100 100 200 300
```一天后：```
3 3 3 1 1
```第二天后：```
3 3 3 2 2
```尝试仅跟踪不同值或忽略多重性的粗心实现在这里会失败，因为转换完全取决于每一步的精确频率计数。 

另一种故障模式是假设该过程可能采用许多不同的配置。 实际上，系统很快就会崩溃到稳定或短周期状态。 

## 方法

 蛮力方法直接模拟了以下过程`k`迭代。 每次迭代都需要构建当前数组的频率图并使用该图重写每个元素。 每次迭代成本$O(n)$，所以总复杂度是$O(nk)$，当$k = 10^9$。 

关键的观察结果是，这种转变很快就会破坏大型结构。 第一步之后，所有值都变成频率，因此它们的边界为`n`。 此后，系统仅在较小的整数范围内演化并迅速稳定，因为重复应用频频无法在固定大小的数组上产生无限的新配置。 根据经验和结构，序列在很少的步骤之后就变得恒定（在这些约束下，最坏的情况是数十步）。 

这意味着我们只需要模拟少量步骤，特别是最多`k`，但由数组稳定的小常数边界限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(nk) | O(nk) | O(n) | 太慢了|
 | 迭代稳定（有界步骤）| O(n·分钟(k, 60)) | O(n) | 已接受 |

 ## 算法演练

 ### ## 算法演练

 1. 从初始数组开始。 

我们将每一天视为仅根据前一天的频率分布生成一个全新的数组。 
2. 重复变换直至`k`次，但如果数组停止变化，请尽早停止。 

如果在某些迭代中每个值`v`已经等于频率`v`，系统已达到固定点，进一步的操作不起作用。 
3. 要执行一次变换，请计算当前数组的频率表。 

这捕获每个值出现的次数，这是下一个状态所需的唯一信息。 
4. 通过替换每个元素来构建下一个数组`a[i]`和`freq[a[i]]`。 

此步骤同时应用于所有职位，因此我们始终基于上一个快照进行更新。 
5. 跟踪迭代过程中数组是否发生变化。 

如果值没有变化，我们就会提前中断，因为进一步的迭代将重复相同的结果。 
6. 为了避免最坏情况的迭代计数，请将模拟限制在一个小常数（大约 60 次迭代）。 

该系统无法有意义地发展超过这个深度，因为值受到以下限制：`n`并反复压缩成稳定的频率结构。 

### 为什么它有效

 变换总是将数组映射到由`[1, n]`第一步之后。 从那时起，系统的状态完全由固定有限范围内的多重集决定。 每次迭代仅基于该多重集应用确定性压缩，并且重复压缩可以快速消除结构变化。 最终，再次应用该操作会产生相同的数组，使系统成为一个不动点。 因为我们明确地模拟直到稳定或直到我们达到`k`，我们匹配当天的确切状态`k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def transform(a):
    n = len(a)
    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1
    return [freq[x] for x in a]

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    if k == 0:
        print(*a)
        return

    seen = 0
    while seen < k:
        b = transform(a)
        if b == a:
            break
        a = b
        seen += 1
        if seen >= 60:
            break

    # If k is larger than stabilization point, we already stabilized
    print(*a)

if __name__ == "__main__":
    solve()
```该解决方案为每次迭代计算频率字典，然后通过直接查找重建数组。 停止条件检查迭代是否改变任何内容，这表示固定点。 额外的迭代上限确保我们即使在病态推理情况下也不会过度模拟。 

关键的实现细节是每个转换必须基于先前的数组快照，而不是部分更新的值，这里通过构造新列表来保证这一点`b`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n \cdot \min(k, 60))$| 每次迭代都会重新计算阵列上的频率，但在稳定之前只需要少量迭代 |
 | 空间|$O(n)$| 频率图和下一个数组存储|

 约束允许最多$2 \cdot 10^5$元素，因此即使 60 次线性传递也能在时间限制内轻松完成。 内存使用量与数组大小保持线性关系。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        def transform(a):
            freq = defaultdict(int)
            for x in a:
                freq[x] += 1
            return [freq[x] for x in a]

        for _ in range(min(k, 60)):
            b = transform(a)
            if b == a:
                a = b
                break
            a = b

        print(*a)

    solve()
    return sys.stdout.getvalue().strip()

 ## 边缘情况

 一种边缘情况是所有元素都相同。 该值的频率是`n`，所以一步之后整个数组就变成常数`n`。 然后第二个应用程序映射`n`到它的频率，即`n`再次，因此系统立即稳定下来。 

另一种情况是所有值都不同。 每个值只出现一次，因此第一个转换将每个元素变成`1`。 之后，数组就已经统一了，进一步的步骤就不起作用了。 这说明了为什么即使对于对抗性输入，收敛速度也非常快。 

第三种情况是重复值和唯一值的混合。 例如`1 2 2 3 3 3`迅速塌缩成一小组频率，然后稳定下来。 该算法自然地处理了这个问题，因为每次迭代都会从头开始重新计算全局直方图，从而确保一致性，而不管先前的结构如何。
