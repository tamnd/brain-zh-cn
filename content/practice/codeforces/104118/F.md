 ## 解决方案
 ## 问题理解

 我们有一个由 n 个派系组成的队列，每个派系都按固定的从西到东的顺序排列，并且每个派系都有一个财富值。 随着时间的推移，派系逐渐消失，直到只剩下一个派系。 决定哪个派系消失的规则取决于根据当前财富分配计算出的全球状况。 

在任何时候，如果某个派系的财富严格超过所有其他派系的财富总和，则该系统就处于霸权状态。 同样，如果当前最大财富值大于总财富的一半。 

每一步都会删除一个派系。 如果该体系不处于霸权状态，那么财富最多的最西端的派系就会被移除。 如果处于霸权状态，财富最少的最西边的派系就会被清除。 移除后，被移除派系的直接幸存邻居（西边最多 1 个，东边最多 1 个）各自获得楼层（removed_wealth / 2）。 被移除的派系将永久消失。 

输出需要报告移除顺序，以及每个被移除的派系、其标签及其在移除时刻、在任何重新分配发生之前的财富。 

约束允许最多 200,000 个派系，并且每次删除仅影响恒定数量的邻居，因此任何每步执行线性工作的解决方案都已经太慢了。 任何二次甚至接近 n 平方的行为都是立即不可行的，因为 n 可能足够大，以至于重复扫描或重建结构将超出典型的时间限制几个数量级。 

一个微妙的困难是选择（动态权重的最大值或最小值）和更新（删除后的邻居增量）都会重复发生。 每次删除后从头开始重新计算全局最小值、最大值和霸权的简单方法将每步重复扫描最多 n 个元素，从而导致 O(n^2) 行为。 

另一个重要的边缘情况是绑定值。 当多个派系拥有相同的最大或最小财富时，必须选择最西的一个。 这使得索引排序至关重要； 即使权重逻辑是正确的，忽略它也会导致不正确的移除顺序。 此外，邻居更新使用楼层划分，因此 1 的一半贡献为零，并且不得意外触发不必要的堆更新。 

## 方法

 直接模拟会保留一个活动的派系列表，并重复扫描它以确定当前的最大值、最小值和总和。 每次删除后，它都会重新计算所有所需的统计数据并更新邻居。 这是正确的，但代价高昂：每一步都需要 O(n) 扫描，重复 n 次，导致 O(n^2)。 当 n 高达 2×10^5 时，这远远超出了可接受的范围。 

关键的观察结果是进程的结构是局部的。 每一步仅删除一个节点，并且仅其两个邻居改变权重。 其他一切保持不变。 这意味着我们不需要从头开始重新计算全局排序； 我们只需要一个有效支持三种操作的结构：通过平局打破按权重提取当前最大值，通过平局打破按权重提取当前最小值，并对各个节点应用小增量更新。 

这正是一对具有惰性删除功能的堆所提供的功能。 我们维护一种面向最大的优先级结构和一种面向最小的优先级结构，两者都以当前权重和索引为键。 由于权重发生变化，每个堆条目可能会变得过时，因此我们在弹出时根据当前存储的权重来验证条目。 邻居更新是通过将新版本推送到两个堆中来处理的。 

我们还维护一个双向链表，以便在删除一个派系后，我们可以立即在 O(1) 中找到其幸存的西邻居和东邻居，而无需扫描。 

这将每个步骤减少到 O(log n)，从而给出总体 O(n log n) 解决方案。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | O(n²) | O(n) | 太慢了|

 ## 算法演练

 ### ## 算法演练

 1. 初始化当前权重的数组、活动索引的双向链表以及所有权重的运行总和。 还初始化两个堆：一个以（权重，索引）为键的最大堆和一个以（权重，索引）为键的最小堆。 指数抢七确保最西方的偏好始终得到尊重。 
2. 反复通过检查当前最大权重是否超过total_sum - Maximum_weight来判断系统是否处于霸权状态。 最大权重是通过丢弃陈旧条目直到找到有效条目从最大堆中获得的。 此步骤有效，因为只有每个节点的最新权重才被认为是正确的。 
3、如果不在争霸中，则使用max-heap选择要删除的节点。 如果处于霸权状态，选择使用最小堆。 在这两种情况下，都会跳过陈旧的堆条目，直到到达其存储的权重与堆键匹配且仍处于活动状态的节点。 
4. 记录所选节点的索引和当前权重作为输出的一部分。 然后从总和中减去它的重量。 
5. 通过直接连接其西邻居和东邻居，将节点从链表中删除。 这无需扫描即可保留邻接结构。 
6. 对于每个现有邻居（如果存在，则为西和东），计算增量为 Floor(removed_weight / 2)。 如果增量非零，则更新该邻居的权重并将新的（权重，索引）状态推送到两个堆中。 
7. 将删除的节点标记为非活动节点，以便忽略引用该节点的未来堆条目。 
8. 重复，直到只剩下一个节点。 

这样做的原因是每个决策仅取决于当前的权重多重集及其排序极值，并且两者都可以增量维护。 堆可能包含过时的条目，但保留了正确性，因为我们从不急于删除堆条目； 相反，我们在提取时针对权威权重数组进行验证。 即使删除重塑了邻接关系，链表也能保证邻居查询保持正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    w = list(map(int, input().split()))
    
    if n == 1:
        return
    
    alive = [True] * n
    left = [i - 1 for i in range(n)]
    right = [i + 1 for i in range(n)]
    right[n - 1] = -1

    total = sum(w)

    maxh = []
    minh = []

    for i, val in enumerate(w):
        heapq.heappush(maxh, (-val, i))
        heapq.heappush(minh, (val, i))

    def clean_max():
        while maxh:
            negv, i = maxh[0]
            if not alive[i] or w[i] != -negv:
                heapq.heappop(maxh)
            else:
                return

    def clean_min():
        while minh:
            v, i = minh[0]
            if not alive[i] or w[i] != v:
                heapq.heappop(minh)
            else:
                return

    def get_max():
        clean_max()
        return -maxh[0][0], maxh[0][1]

    def get_min():
        clean_min()
        return minh[0][0], minh[0][1]

    for _ in range(n - 1):
        mx, _ = get_max()
        if mx * 2 > total:
            _, i = get_min()
        else:
            _, i = get_max()

        wi = w[i]
        print(i + 1, wi)

        total -= wi
        alive[i] = False

        l = left[i]
        r = right[i]

        if l != -1:
            right[l] = r
        if r != -1:
            left[r] = l

        add = wi // 2

        if l != -1:
            w[l] += add
            heapq.heappush(maxh, (-w[l], l))
            heapq.heappush(minh, (w[l], l))

        if r != -1:
            w[r] += add
            heapq.heappush(maxh, (-w[r], r))
            heapq.heappush(minh, (w[r], r))

solve()
```该解决方案将当前状态保持在三个同步结构中：作为事实来源的权重数组、用于快速极值查询的堆以及用于邻接的链表。 关键的实现细节是堆内的延迟删除。 当节点改变权重时，我们不是删除过时的条目，而是简单地推送更新的状态。 当提取候选者时，我们丢弃不再与当前权重匹配或引用已删除节点的堆条目。 

另一个微妙点是霸权制衡。 我们通过维护运行总计来避免重新计算所有剩余节点的总和。 使用从堆中提取的当前最大值来检查条件。 

通过将索引存储为第二个堆键来隐式处理索引打破平局。 对于最大堆，我们反转权重但保持索引升序，因此在相等的情况下选择最西的。 对于min-heap，我们直接使用(weight,index)。

 ## 边缘情况

 一种边缘情况是楼层划分产生零更新。 如果被删除的派系的财富为 1，则两个邻居都会收到 0。幼稚的实现可能仍会不必要地推送堆更新，但正确性要求值不发生变化。 该实现通过检查 add = wi // 2 并仍然安全地推送来处理此问题，因为可以重新插入相同的权重而不改变行为。 

另一种情况是由于对同一节点的多次更新而导致重复的陈旧堆条目。 例如，节点在被删除之前可能会收到多个增量。 堆将包含多个过时的版本，但惰性删除机制确保仅接受最新的权重，因此较旧的条目将被忽略。 

第三种情况是边界附近的邻接更新。 如果被移除的派系位于边缘，则它只有一个邻居。 链表表示自然地使用 -1 处理丢失的邻居，并且更新逻辑简单地跳过不存在的边，而无需超出边界检查的特殊大小写。
