 ## 解决方案
 ## 问题理解

 我们有一个小的矩形网格，其中每个单元格要么是空的，要么包含一头猪，要么包含一只狼。 狼可能会吃掉在四个基本方向之一上与其直接相邻的一头猪。 猪一旦被吃掉，它就会消失，不能再被吃掉。 

目标是最大化总共吃掉多少头猪。 

关键限制是不寻常且极其重要的：每头猪最多与一只狼相邻。 一只狼可能还有几只相邻的猪，但一头猪永远不会被多只狼争夺。 

该限制将问题从匹配问题转变为简单的贪婪模拟。 

网格尺寸最多为 10 × 10，因此整个板最多包含 100 个单元。 即使是低效的解决方案也可能会被通过。 尽管如此，这个问题的目的还是为了测试我们是否注意到消除了对重型图算法的需要的结构特性。 

谨慎的实施仍然很重要，因为董事会在狼吃猪的同时也在变化。 如果我们不小心让同一头猪被吃两次，答案就会变得不正确。 

一个容易犯的错误是，猪被吃掉后忘记将其移走。 考虑这个输入：```
1 3
WPW
```正确的输出是：```
1
```中间的猪与两只狼相邻，但这种配置实际上是语句所禁止的，因为每只猪最多只能有一只相邻的狼。 忽视保证的粗心实现可能会数猪两次。 

另一个微妙的情况是当一只狼有多只相邻的猪时：```
2 2
PW
PP
```正确的输出是：```
1
```即使两只猪相邻，狼也只能吃掉一只猪。 一个有缺陷的解决方案可能会计算每一个相邻的猪。 

边界处理是另一个常见的错误来源。 例如：```
1 2
WP
```正确的输出是：```
1
```狼只在网格内有邻居。 在没有检查的情况下访问板外的坐标会导致索引错误。 

## 方法

 最直接的暴力想法是为每只狼尝试每一个可能的决定。 每只狼可以选择一只相邻的猪，也可以不选择任何人。 我们可以递归地探索所有组合并保留最大答案。 

这是可行的，因为董事会很小。 在最坏的情况下，大约有100个细胞，其中许多可能是狼。 如果每只狼最多有四种选择，则搜索空间大致变为$4^k$， 在哪里$k$是狼的数量。 即使只有二十只狼，也已经拥有超过一万亿种可能性。 

发生这种爆炸的原因是狼通常会争夺猪。 为一只狼选择一头猪可能会阻止另一只狼。 

关键的观察是这个问题消除了几乎所有的竞争。 每头猪最多与一只狼相邻。 这意味着，如果一只狼看到一只猪，其他狼就无法接受它。 

一旦我们认识到这一点，问题就变得简单了。 我们迭代网格。 对于每只狼，我们检查它的四个相邻单元格。 如果任何邻居有一头猪，狼会立即吃掉它，我们增加答案，然后从棋盘上删除那只猪。 

这种贪婪的选择总是安全的，因为无论如何未来的狼都不可能使用那只猪。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(4^k) | O(4^k) | O(k) | 概念上太慢|
 | 最佳 | O(n × m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将网格读入二维数组，以便我们可以在猪被吃掉后修改单元格。 
2. 准备四个移动方向：上、下、左、右。 
3. 遍历网格中的每个单元格。 
4. 当当前单元格中有一只狼时，检查其四个相邻单元格。 
5. 对于每个邻居，首先检查坐标是否留在棋盘内。 这可以防止无效的数组访问。 
6. 如果相邻单元格中有猪，立即让狼吃掉它：

 1. 将答案加一。 
2. 将猪细胞替换为`.`这样以后狼就不能再吃它了。 
3. 停止检查其他邻居是否有这只狼。 

一只狼最多只能吃掉一头猪，所以在成功吃掉之后继续下去就不算数了。 
7. 处理完所有单元格后，打印吃掉的猪总数。 

### 为什么它有效

 正确性来自于保证每头猪最多与一只狼相邻。 假设一只狼发现了一只相邻的猪。 无论现在还是以后，没有其他狼可以使用那只猪。 立即吃掉它并不能减少任何未来的选择。 

由于该属性，每个成功的贪婪选择都独立于所有其他选择。 该算法对每只至少有一只相邻猪的狼精确地计数一头猪，并且不会对任何猪进行两次计数，因为吃掉的猪会从网格中移除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    ans = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'W':
                for dx, dy in directions:
                    ni = i + dx
                    nj = j + dy

                    if 0 <= ni < n and 0 <= nj < m:
                        if grid[ni][nj] == 'P':
                            ans += 1
                            grid[ni][nj] = '.'
                            break

    print(ans)

solve()
```该解决方案将棋盘存储为角色列表的可变列表，因为猪在被吃掉后就会消失。 Python 中的字符串是不可变的，因此使用原始字符串会使更新变得尴尬。 

外循环扫描每个单元一次。 每当我们遇到狼时，我们都会使用方向数组来测试四个相邻位置。 

边界检查发生在访问之前`grid[ni][nj]`。 颠倒此顺序将导致边缘单元出现索引错误。 

狼吃掉猪后，代码立即将猪替换为`.`。 这可以防止重复计算并准确地对问题陈述进行建模。 

这`break`声明是必不可少的。 一只狼只能吃掉一头猪。 如果没有这个突破，一只狼可能会错误地吃掉多只相邻的猪。

 ## 边缘情况

 考虑一下狼接触几只猪的情况：```
2 2
PW
PP
```该算法扫描狼的位置`(0,1)`。 它按顺序检查邻居并找到猪`(0,0)`。 答案变成1，猪被移除，循环立即中断。 剩下的猪被那只狼忽略，这符合每只狼最多吃一只猪的规则。 

现在考虑板边缘情况：```
1 2
WP
```狼坐在左上角。 一些相邻的坐标会落在棋盘之外，例如`(-1,0)`或者`(0,-1)`。 边界检查在数组访问之前拒绝这些位置。 有效邻居`(0,1)`包含一头猪，所以答案安全地变为 1。 

最后，考虑一个没有可能吃的情况：```
2 2
P.
.W
```狼在`(1,1)`检查所有四个方向。 每个有效的邻居要么是空的，要么是在棋盘之外。 答案永远不会增加，并且算法正确地打印 0。
