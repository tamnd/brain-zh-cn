 ## 解决方案
 ## 问题理解

 我们有格里沙的绳子`s`，以及由另一个字符串表示的字母卡的集合`t`。 的每一个角色`t`对应于一张实体卡，因此只有每封信的可用副本数量才重要。 的一个子串`s`如果对于每个字母，该子串使用的字母副本数量不超过卡片提供的数量，则可以构建。 

我们必须计算子字符串的出现次数，而不是不同的子字符串值。 例如，如果`s = "aaa"`有三个`a`卡，所有三个单字符子字符串单独计数。 

表示卡片的有用方法是使用数组`limit[26]`， 在哪里`limit[c]`是包含字母的卡片数量`c`。 当子串中每个字母出现的频率最多等于`limit`。 

两个字符串的长度最多`10^5`。 可以有大约`n(n+1)/2`，或者粗略地`5 * 10^9`，子字符串，因此枚举每个子字符串已经太昂贵了。 根据典型的竞争性编程时间预算，`O(n^2)`算法在这个规模下不可行，并且`O(n^3)`实施远远超出了极限。 我们需要在基本上线性的时间内处理字符串。 

有几种边缘情况可能会导致粗心的实施错误。 如果某个字符没有卡片，则该字符永远不可能属于有效的子字符串。 例如，```
1 1
a
b
```有答案`0`。 仅检查总子字符串长度的实现`m`会错误地计数`"a"`。 

当子字符串由于一个字符出现次数过多而变得无效时，就会出现另一种边界情况。 例如，```
3 2
aaa
aa
```有答案`5`。 有效的出现次数是长度为一的三个子字符串和长度为二的两个子字符串。 包含所有三个的窗口`a`字符无效，所以遇到第三个字符后`a`，左边界必须移动。 

可用的卡片可能包含某些字母的许多副本，但不包含其他字母。 例如，```
4 2
abca
aa
```有答案`2`，因为只有两个单字符出现`a`可以构建。 一种将卡片视为无序池但仅检查子字符串是否包含出现在卡片中某处的字母的方法`t`会错误地接受包含的子字符串`b`或者`c`。 

最后，答案可能比`10^5`。 如果```
100000 100000
aaaaaaaaaa...aaaaaaaa
aaaaaaaaaa...aaaaaaaa
```包含`100000`的副本`a`在这两个字符串中，每个子字符串都是有效的，答案是`100000 * 100001 / 2 = 5000050000`。 

实现必须使用能够存储该值的整数类型。 Python 整数具有任意精度，因此不需要在 Python 中进行特殊处理。 

## 方法

 最直接的解决方案考虑每对端点。 对于每个左端点，我们扩展右端点并保持当前子字符串中字母的频率。 只要所有频率都在卡限制范围内，我们就会在答案中加一。 这个增量版本需要`O(n^2)`操作，因为有`n(n+1)/2`端点对。 在`n = 100000`， 那是`5000050000`候选子串，已经太多了。 

更直接的暴力解决方案将构造每个子字符串并独立地计算其字母。 这需要`O(n^3)`时间。 如果逐个字符扫描每个子串，最坏情况下字符访问次数为`1 + 2 + ...`在所有子串长度上，即`n(n+1)(n+2)/6`。 

为了`n = 100000`，这大约是`1.6667 * 10^14`操作，因此该方法会更早失败。 

暴力方法之所以有效，是因为它准确地检查了我们需要的条件：每个字符频率必须保持在其可用限制内。 问题在于它会重复检查重叠的子字符串。 关键的观察是，当我们向右扩展子串时，有效性是单调的。 添加字符永远无法修复无效频率。 如果一个窗口已经有太多某个字母的副本，则包含该字母的每个较大窗口也无效。 

该属性使滑动窗口成为可能。 保留以当前正确位置结尾的最大有效子字符串。 当添加新字符使窗口无效时，将左端点向前移动，直到窗口再次有效。 对于固定的右端点，从当前左端点或更晚开始的每个后缀都是有效的。 如果左端点是`l`，正好有`r - l + 1`这样的后缀。 

因此，不是单独检查每个子字符串，而是每个字符进入窗口一次并最多离开窗口一次。 整个字符串可以被处理`O(n)`时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 增量计数为 O(n²)，新鲜计数为 O(n³) | O(26) | 太慢了|
 | 最优滑动窗口 | O(n) | O(26) | 已接受 |

 ## 算法演练

 1. 计算 26 个小写字母分别有多少张卡片。 将这些值存储在`limit`。 
2.初始化频率数组`cnt`为当前窗口，并设置左端点`l`为零。 右端点将从左向右移动`s`。 
3. 对于每个位置`r`， 添加`s[r]`通过增加其频率到当前窗口。 我们现在有了候选窗口`s[l:r+1]`。 
4.如果新添加的角色出现频率超过其卡牌限制，则移动`l`一次向右移一个位置，并从其中删除每个丢弃的字符`cnt`。 继续，直到当前窗口满足所有卡限制。 

只有新的最右边的字符才能使先前有效的窗口无效。 从左侧删除字符足以修复窗口，因为只有删除字符时频率才会降低。 
5.窗口生效后，添加`r - l + 1`到答案。 每个子串结束于`r`并从任意位置开始`l`通过`r`是这个有效窗口的后缀，所以它们都是有效的。 正好有`r - l + 1`这样开始。 
6. 继续，直到处理完所有字符。 累积的答案是有效子串出现的次数。 

### 为什么它有效

 每次迭代后，`[l, r]`是一个有效的窗口，并且`l`是窗口结束于的最小左端点`r`是有效的。 因此，每个以`r`并至少从一个位置开始`l`有效，而之前开始`l`将产生一个在移动左边界时已经无效的窗口。 因此`r - l + 1`精确计算所有以以下结尾的有效子字符串`r`，既没有遗漏，也没有重复。 由于每个字符都插入一次并最多删除一次，因此总工作量是线性的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()

    limit = [0] * 26
    for ch in t:
        limit[ord(ch) - ord('a')] += 1

    cnt = [0] * 26
    left = 0
    ans = 0

    for right, ch in enumerate(s):
        x = ord(ch) - ord('a')
        cnt[x] += 1

        while cnt[x] > limit[x]:
            y = ord(s[left]) - ord('a')
            cnt[y] -= 1
            left += 1

        ans += right - left + 1

    print(ans)

if __name__ == "__main__":
    solve()
```第一个循环将卡片字符串转换为`limit`大批。 没有理由保留顺序`t`，因为卡片是可以互换的，只有它们的多样性才重要。 

主循环向当前窗口的右侧添加一个字符。 如果其计数变得太大，`while`循环从左侧删除字符。 仅检查`cnt[x]`就足够了，因为在添加之前窗口是有效的`s[right]`，因此在此迭代期间没有其他字母会变得无效。 

条件使用`>`而不是`>=`。 如果正好有两个`a`卡和窗口恰好包含两个`a`字符，窗口有效。 只有当计数达到三时才失效。 

答案只有在窗户修好后才会更新。 那时，`right - left + 1`是结束于的有效子字符串的数量`right`。 左边界可以一直移动到`right + 1`在当前角色没有可用卡牌的情况下。 例如，如果`s[right] = 'a'`和`limit['a'] = 0`，循环删除当前窗口中的每个字符，包括新的字符`a`，和叶子`left = right + 1`。 那么贡献为零。 

Python 整数避免了最大可能答案的溢出，即`5000050000`。

 ## 边缘情况

 考虑不可用字符的情况```
1 1
a
b
```卡限额为`a`为零。 什么时候`a`进入窗口，`cnt[a]`合而为一，所以`while`条件立即为真。 唯一的字符被删除，`left`变成`1`，贡献是`1 - 1 + 1 = 0`。 算法正确返回`0`。 

对于重复的字母，```
3 2
aaa
aa
```第一个`a`做出贡献`1`，第二个给出贡献`2`，总计`3`。 在第三个位置，计数达到三，而限制为二。 删除第一个`a`离开窗户`"aa"`，所以第三个位置贡献`2`。 最终的答案是`5`。 

全部有效的案例```
3 3
abc
abc
```永远不会进入收缩循环。 贡献是`1`,`2`， 和`3`, 给予`6`，这正是三字符字符串的连续子串的数量。 

最大答案的情况完全由相同的字母组成，并且每次出现都有足够的卡片。 左边界在整个扫描过程中保持为零，因此贡献为`1, 2, ..., 100000`。 他们的总和是`5000050000`，演示了为什么结果不能存储在 32 位整数中。
