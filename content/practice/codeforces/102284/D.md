 ## 解决方案
 ## 问题理解

 我们有 (n) 个音符频率的数组。 我们可以选择任何非空子序列，因此所选位置必须保持其原始顺序，但位置可以被跳过。 当每两个相邻选定频率之间的绝对差为质数时，子序列是美丽的。 

任务不仅仅是计算这些子序列。 我们必须按照频率序列对所有美丽的子序列进行字典顺序排序，并输出第 (k) 个。 如果可以从几个不同的位置选择获得相同的频率序列，则每次出现这样的情况都会单独对排序做出贡献。 

这些限制使得直接枚举变得不可能。 对于 (n=1000)，可能有 (2^{1000}-1) 个非空子序列，因此即使生成它们也是没有希望的。 官方声明给出了2秒的时间限制和512MB的内存限制。 因此，有用的目标约为 (O(n^2))，在考虑素数预处理之前，这大约是一百万次数组级操作。 

(100000) 的值界足够大，以至于对每对独立测试素性将是浪费，但对于筛子来说又足够小。 最大可能的差异也低于 (100000)，因此一个筛子可以回答每个兼容性查询。 

有几种边缘情况可能会悄悄破坏原本合理的解决方案。 第一个是尽可能小的数组。 

为了```
1 1
5
```唯一漂亮的子序列是 ((5))，所以输出是```
1
5
```在计数中包含空子序列的解决方案将返回错误的排名，因为该问题仅考虑非空子序列。 

重复的值会造成另一个陷阱。 为了```
3 2
7 7 7
```唯一漂亮的子序列是三个单例出现，因为差值为零不是素数。 因此第二个是```
1
7
```如果粗心的实现将零视为有效的质数差，或者仅计算不同的频率序列而不是出现次数，则会给出不同的答案。 

重复前缀的字典顺序处理也很重要。 考虑```
3 4
1 3 1
```(1) 都可以形成一个单例，并且 (1) 和 (3) 之间的差是素数。 有序列表是

 [
 (1)、(1)、(1,3)、(1,3,1)、(3)、(3,1)。 
]

 因此第四个答案是```
3
1 3 1
```按第一次出现对相等的第一个值进行分组的解决方案将错误地将 ((1,3)) 放在第二个单例 ((1)) 之前。 

最后，不能接受一分之一的差异。 为了```
2 2
1 2
```这两对都不能扩展，所以答案是```
1
2
```这两个单例子序列是唯一美丽的。 这捕获了仅检查两个频率是否不同的实现。 

## 方法

 蛮力方法很简单。 生成数组的每个非空子序列，检查每个相邻差异是否为素数，存储漂亮的子序列，按字典顺序对它们进行排序，并取出第 (k) 个元素。 有 (2^n-1) 个子序列，检查一个子序列可能需要 (O(n))，因此最坏情况的工作是 (O(n2^n))。 对于 (n=1000)，这远远超出了任何实际限制。 

动态编程立即为我们提供了一个有用的计数原语。 对于每个位置 (i)，令 (ways[i]) 为其第一个选定位置恰好是 (i) 的漂亮子序列的数量。 仅由 (a_i) 组成的单例贡献一个。 每个具有素差的后续位置 (j) 都可以是下一个选定的位置，之后有 (ways[j]) 个可能的延续。 因此

 1+
 \sum_{\substack{j>i\ |a_i-a_j|\text{ 是质数}}}
 方式[j].
 ]

 可以在 (O(n^2)) 中从右到左评估此递归。 

剩下的困难是字典排序。 直接使用 (ways[i]) 并选择起始位置是很诱人的，但当多个位置包含相同频率时，这是错误的。 例如，在 ((1,3,1)) 中，两个单例 ((1)) 必须都出现在 ((1,3)) 之前。 词典顺序按频率分组，而不是按用于获取该频率的位置分组。 

关键的观察是，在我们固定了一个前缀之后，该前缀的每次嵌入都以相同的频率结束，即前缀的最后一个频率。 我们可以保留数组中每个位置结束的嵌入数量（权重）。 

假设当前前缀已固定，并且 (weight[i]) 是其在位置 (i) 结束的嵌入数。 那么前缀本身出现的次数就是

 [
 \sum_i 权重[i]。 
]

 由于序列按字典顺序小于其自身的任何适当扩展，因此在查看另一个下一个频率之前必须考虑整个块。 

现在考虑将前缀扩展值 (v)。 对于 (a_j=v) 的位置 (j)，以 (j) 结尾的扩展前缀的嵌入数量为

 \sum_{\substack{i<j\ |a_i-v|\text{ 是素数}}}
 重量[i]。 
]

 那么使用该位置作为新选择的元素的完整美丽子序列的数量为

 [
 newWeight[j]\cdot 方式[j]。 
]

 我们需要将这些计数按 (v) 分组，因为下一个频率相同的所有序列都属于一个字典块。 

有一个关键的简化。 所有非零 (weight[i]) 都属于具有当前前缀的最后频率 (c) 的位置。 因此，当从左到右扫描位置时，未来位置（j）所需的总和只是先前位置的累积权重，前提是（|c-a_j|）是质数。 因此，阵列的一次扫描会立即计算每个可能的下一个频率的计数。 

选择下一个频率后，相同的扫描已经计算出包含该频率的所有位置的新权重。 我们可以放弃所有其他立场并继续。 

暴力方法之所以有效，是因为每个子序列都被明确考虑，但会失败，因为它们的数量是指数级的。 当前前缀的所有嵌入都有一个共同的最后频率这一观察结果让我们将它们聚合到位置权重中，并在一次线性扫描中更新所有词典块。 由此产生的取消排序每个输出元素需要 (O(n))，并且最多可以有 (n) 个元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n2^n)) | (O(n2^n)) 如果所有子序列都被存储 | 太慢了|
 | 最佳 | (O(n^2)) | (O(n+V)) | 已接受 |

 这里 (V\le 100000) 是与筛子相关的最大频率差。 

## 算法演练

 1. 建立一个埃拉托色尼筛，频率差达到最大可能。 经过这样的预处理后，`prime[d]`在 (O(1)) 时间内告诉我们 (d) 是否是素数。 
2. 计算`ways[i]`从右到左。 最初每个位置都贡献它的单例，所以`ways[i]`从一开始。 对于后面的每个位置 (j)，添加`ways[j]`当频率差为素数时。 值的上限可以为 (k)，因为大于 (k) 的计数对于排名选择来说是无法区分的。 
3. 在构造任何前缀之前，将所有漂亮的子序列按其第一个频率进行分组。 每个位置 (i) 都有贡献`ways[i]`序列到第一个值为的块`a[i]`。 对不同频率进行排序并减去整个块，直到找到包含排名 (k) 的块。 
4. 设置`weight[i]`对于值为所选第一频率的每个位置为 1，在其他位置为零。 在此刻`weight[i]`准确地表示当前前缀在位置 (i) 处结束的嵌入数。 
5. 对于当前前缀，首先计算`exact = sum(weight)`。 这些都是前缀本身的出现。 如果 (k\le 精确)，则前缀是所需的答案，因为字符串按字典顺序小于其自身的每个正确扩展。 
6. 如果前缀本身不是答案，则减去`exact`来自(k)。 剩余的等级属于适当的扩展。 
7. 从左到右扫描阵列。 维持`pref`，当前仓位之前的仓位总权重。 对于每个位置（j），如果当前前缀值与`a[j]`是素数，那么`pref`正是当前前缀可以通过(j)扩展的嵌入数。 添加`pref * ways[j]`属于的词典块`a[j]`。 
8. 在同一次扫描期间，存储`pref`当转换有效时，作为位置 (j) 的新权重。 一旦选定的下一个值 (v) 已知，所有值不是 (v) 的位置都将被丢弃。 剩余的权重描述新前缀的每个嵌入。 
9. 重复前三个步骤，直到当前前缀本身包含所需的排名。 由于子序列使用严格递增的位置，因此其长度永远不会超过 (n)。 

### 为什么它有效

 不变量是构造前缀（P）后，`weight[i]`等于最后选择位置为 (i) 的 (P) 的嵌入数量。 因此，对这些权重求和会计算 (P) 的每次出现，包括不同位置产生的重复频率序列。 

对于任何可能的下一个位置 (j)，扫描精确计算可以到达 (j) 的 (P) 的嵌入数量。 将此乘以`ways[j]`从该选择开始的每一个美丽的完成都只计算一次。 将这些值分组为`a[j]`给出每个字典顺序下一个值块的确切大小.

 这些块按频率递增的顺序进行检查，因此跳过整个块可以保留所需序列的排名。 当选择一个块时，其对应的`newWeight`数组精确地表示该块内的所有嵌入。 因此，在每个选定的频率之后都会保留不变量，并且当排名落在精确前缀块内时，当前前缀正是所需的子序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, k, a):
    max_diff = max(a) - min(a)

    prime = bytearray(b'\x01') * (max_diff + 1)
    if max_diff >= 0:
        prime[0] = 0
    if max_diff >= 1:
        prime[1] = 0

    p = 2
    while p * p <= max_diff:
        if prime[p]:
            start = p * p
            cnt = (max_diff - start) // p + 1
            prime[start:max_diff + 1:p] = b'\x00' * cnt
        p += 1

    cap = k

    ways = [1] * n

    for i in range(n - 1, -1, -1):
        total = 1
        ai = a[i]

        for j in range(i + 1, n):
            if prime[abs(ai - a[j])]:
                total += ways[j]
                if total >= cap:
                    total = cap
                    break

        ways[i] = total

    values = sorted(set(a))

    first_count = {}
    for i, v in enumerate(a):
        old = first_count.get(v, 0)
        cur = old + ways[i]
        first_count[v] = cap if cur >= cap else cur

    for v in values:
        cnt = first_count.get(v, 0)
        if k > cnt:
            k -= cnt
        else:
            first_value = v
            break

    answer = [first_value]

    weight = [0] * n
    for i in range(n):
        if a[i] == first_value:
            weight[i] = 1

    current = first_value

    while True:
        exact = sum(weight)

        if k <= exact:
            break

        k -= exact

        group = {}
        new_weight = [0] * n
        pref = 0

        for j in range(n):
            aj = a[j]

            if pref and prime[abs(current - aj)]:
                new_weight[j] = pref

                add = pref * ways[j]
                old = group.get(aj, 0)
                cur = old + add
                group[aj] = cap if cur >= cap else cur

            if weight[j]:
                pref += weight[j]
                if pref >= cap:
                    pref = cap

        chosen = None

        for v in values:
            cnt = group.get(v, 0)
            if k > cnt:
                k -= cnt
            else:
                chosen = v
                break

        answer.append(chosen)
        current = chosen

        for i in range(n):
            if a[i] == chosen:
                weight[i] = new_weight[i]
            else:
                weight[i] = 0

    return answer

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    answer = solve_case(n, k, a)

    print(len(answer))
    print(*answer)

if __name__ == "__main__":
    main()
```筛子仅根据实际可能出现的最大差异而构建。 这`bytearray`表示使素性表保持紧凑，并使基于切片的筛选对于 Python 来说足够快。 

这`ways`递归遵循从右到左的动态规划步骤。 一旦计数达到则中断`k`是安全的，因为后来的所有添加都是非负的，因此确切的值对于取消排名不再重要。 

第一频率计算与主重建是分开的，因为根处没有先前频率。 每个位置都可以独立地成为第一个选定的位置，因此值 (v) 的块是`ways[i]`包含 (v) 的所有位置。 

一旦第一个值固定，`weight[i]`表示完整当前前缀的嵌入，而不仅仅是该前缀可能出现的位置。 这种区别可以正确处理重复的子序列。 

在重建扫描中，`pref`仅在处理位置 (j) 后更新。 子序列必须使用 (j) 之前的较早位置，因此包括`weight[j]`太早会引入无效的自转换。 出于完全相同的原因，在添加新权重之前会检查差异。 

表达式`pref * ways[j]`计算通过 (j) 的所有完成情况。`ways[j]`已经包含在 (j) 处停止的选项，这是必要的，因为当前前缀本身必须按字典顺序出现在其扩展名之前。 

Python 整数不会溢出。 上限计数为`k`此外，还可以防止不必要的增长，并让算法忽略已经足够大以包含所请求排名的计数之间的区别。

 ## 边缘情况

 对于单元素输入```
1 1
5
```值 (5) 的初始块的大小为 1，因为`ways[0] = 1`。 选择第一个值，`weight[0] = 1`，并且精确前缀计数为 1。 由于(k=1)，重建立即停止并输出((5))。 从来没有任何转换尝试，因此数组末尾的边界是自然处理的。 

为了```
3 2
7 7 7
```筛子将零标记为非素数。 最后`ways[i] = 1`在每个位置。 (7) 的第一个值块的大小为 3，因为每个位置给出一个单独的单例子序列。 选择(7)后，权重数组包含三个。 因此，精确前缀计数为 3，因此排名第二停在单例处。 任何差值为零的转换都是不被接受的。 

为了```
