 ## 解决方案
 ## 问题理解

 我们有一个最多包含 (10^5) 个正整数的数组，对于每个有序元素对 (a_i,a_j)，我们通过从最低有效侧交错它们的数字来形成一个新的十进制数。 如果一个数字有更多位数，则其剩余的最高有效数字保留在前面。 所需的答案是所有这些 (n^2) 个构造数字模 (998244353) 的总和。 

提示中的表述对应于 Codeforces 问题的硬版，正式列为 1195D2。 原问题有 2 秒时间限制和 256 MB 内存限制。 

主要约束是 (n\le 100000)。 在最坏的情况下，(O(n^2)) 算法已经执行 (10^{10}) 对运算，这远远超出了 2 秒竞争编程限制所允许的范围。 由于每个数字最多有 10 位数字，因此 (O(n\log a_i)) 或 (O(10n)) 解决方案很容易实现。 上限 (a_i\le10^9) 特别有用，因为它意味着只有 10 个可能的数字长度。 

在某些情况下，直接实现可能会悄无声息地出错。 如果两个数字的长度不同，则剩余前缀的处理方式必须与交替部分不同。 例如，使用输入```
2
9 10
```四个有序对产生 (f(9,9)=99)、(f(9,10)=190)、(f(10,9)=109) 和 (f(10,10)=1010)，因此答案是 (1408)。 始终假设长度相等的方法会错误地放置数字。 

第二个边缘情况是一位数。 用于输入```
1
1
```我们有 (f(1,1)=11)，所以答案是 (11)。 仅使用交替部分但忘记同一数字的两个角色占据不同小数位的公式会出错。 

第三个边缘情况是最大数字长度。 值 (10^9) 有十位数字，而 (10^9-1) 有九位数字。 例如，这对```
2
999999999 1000000000
```具有不同长度的数字，因此第二个数字的第十位数字是其不匹配前缀的一部分。 假设所有输入最多有九位数字也会导致预先计算的幂不足。 

## 方法

 蛮力方法很简单。 对于每个有序对 ((i,j))，将两个数字转换为十进制数字，构造 (f(a_i,a_j))，并将其添加到答案中。 这是正确的，因为所需的双和中的每一项都被明确评估。 问题是对的数量。 当(n=100000)时，有(10^{10})个有序对。 如果每个数字都有 10 位数字，则处理一对数字最多涉及 20 位数字的位置，在最坏的情况下大约给出 (2\cdot10^{11}) 位数字级操作。 这与可用时间相差甚远。 

(f) 的结构为我们提供了一种避免考虑个体合作伙伴的方法。 特定数字占据的位置仅取决于两件事：该数字从右侧算起的位置，以及另一个数字中的位数。 另一个数字的实际值对该数字的位置并不重要。 

考虑一个数字（x），并将其右起第（k）位数字设为（d）。 假设另一个数字有 (j) 位。 我们想知道这个单个数字对两个方向 (f(x,y)) 和 (f(y,x)) 的贡献有多大。 

如果(k\le j)，则该数字参与交替部分。 当(x)为第一个参数时，其数字占据小数点位置(2k-1)，而当(x)为第二个参数时，其数字占据小数点位置(2k-2)。 因此其组合系数为

 [
 10^{2k-1}+10^{2k-2}。 
]

 如果(k>j)，则该数字已经在较长数字的不匹配前缀中。 在任一方向上，另一个数字的 (j) 个数字占据其下方的 (2j) 个位置。 它原来的小数位置是(k-1)，所以它的最终位置是(k+j-1)。 两个方向给出相同的系数，

 [
 2\cdot10^{k+j-1}。 
]

 关键是这个系数只取决于(k)和(j)，而不取决于(y)的实际值。 我们可以计算每个数字长度有多少个数组元素，将这些计数组合成每个数字位置的一个系数，然后独立处理每个数字。 

这将二次对枚举变成每个十进制数字的恒定工作量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n^2\log A)) | (O(\log A)) | 太慢了|
 | 最佳 | (O(n\log A+(\log A)^2)) | (O(\log A)) | 已接受 |

 这里 (\log A\le10)，因此最优算法在 (n) 中实际上是线性的。 

## 算法演练

 1. 计算每个可能的数字长度有多少个数组元素。 由于 (a_i\le10^9)，只有从 1 到 10 的长度。让`cnt[j]`表示正好 (j) 位数字的元素数量。 
2. 预计算 (0\le e\le19) 的 (10^e\bmod998244353)。 我们需要的最大指数是 (2\cdot10-1=19)。 
3. 对于从右侧开始的每个数字位置 (k)，计算其在每个可能的伙伴长度上的总系数。 对于具有 (j) 位数字的合作伙伴，请使用

 [
 g(k,j)=
 \开始{案例}
 10^{2k-1}+10^{2k-2}, & k\le j,\
 2\cdot10^{k+j-1}，&k>j。 
\结束{案例}
 ]

 然后定义

 [
 w_k=\sum_{j=1}^{10}cnt[j]\cdot g(k,j)。 
]

 值 (w_k) 表示当在每个数组元素的两个可能方向上考虑该数字时，所选数字的第 (k) 位中的一个单位的总贡献。 

1. 从右到左逐位处理每个数字 (x)。 如果当前数字是 (d) 并且这是位置 (k)，则将 (d\cdot w_k) 添加到答案中。 (x) 除以 10 移动到下一个数字，因此不需要字符串转换。 
2. 将累加结果模（998244353）减少并打印。 

我们可以为每个选定的数字添加两个方向的原因是原始总和包含每个有序对。 对于不同的索引 (i,j)，项 (f(a_i,a_j)) 包含来自 (a_i) 的贡献和来自 (a_j) 的贡献。 处理 (a_i) 考虑了它作为第一个参数的贡献以及它作为 (f(a_j,a_i)) 中第二个参数的贡献。 在所有选定的数字中，每个有序对的每个数字贡献都只出现一次。 对于 (i=j)，两个方向只是 (f(a_i,a_i)) 内相同数字占据的两个位置，因此它们也只计算一次。 

**为什么有效。** 修复数组元素 (x) 及其数字之一。 它在 (f(x,y)) 中的位置完全由数字与右侧的距离以及 (y) 的长度决定。 当 (x) 作为第二个参数出现时也是如此。 系数 (g(k,j)) 准确捕获了这两个位置。 将其乘以长度 (j) 的伙伴数量即可一次性计算出所有此类伙伴。 对所有可能的 (j) 求和，然后对每个 (x) 的所有数字求和，说明完整有序对和中的每个数字贡献，因此得到的答案正是所需的双倍和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAX_DIGITS = 10

def solve(a):
    n = len(a)

    # cnt[j] = number of values having exactly j digits.
    cnt = [0] * (MAX_DIGITS + 1)
    for x in a:
        cnt[len(str(x))] += 1

    # pow10[e] = 10^e mod MOD.
    pow10 = [1] * (2 * MAX_DIGITS)
    for e in range(1, len(pow10)):
        pow10[e] = pow10[e - 1] * 10 % MOD

    # weight[k] is the total coefficient of the k-th digit
    # from the right, after considering every possible
    # partner in both orientations.
    weight = [0] * (MAX_DIGITS + 1)

    for k in range(1, MAX_DIGITS + 1):
        total = 0
        for j in range(1, MAX_DIGITS + 1):
            if cnt[j] == 0:
                continue

            if k <= j:
                g = pow10[2 * k - 1] + pow10[2 * k - 2]
            else:
                g = 2 * pow10[k + j - 1]

            total = (total + cnt[j] * g) % MOD

        weight[k] = total

    ans = 0

    # Process every number from its least significant digit.
    for x in a:
        k = 1
        while x:
            digit = x % 10
            ans = (ans + digit * weight[k]) % MOD
            x //= 10
            k += 1

    return ans

def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve(a))

if __name__ == "__main__":
    main()
```第一部分`solve`计算数字长度。 呼唤`len(str(x))`这里是安全的，因为每个值最多有十位数字，因此这仅贡献 (O(10n)) 工作。 

这`pow10`数组以 (10^0=1) 开头，这与某些从数组位置 1 处的 (10^0) 开始索引幂的实现不同。 保留传统的索引使得推导中的指数直接与代码匹配。 所需的最大指数为 19。 

的`weight`数组压缩所有可能的伙伴长度。 例如，如果 (k=2)，则每个两位数或更长的伙伴都使用交替系数 (10^3+10^2)，而一位数伙伴则使用 (2\cdot10^2)。 将这些系数乘以`cnt[j]`立即合并该长度的所有合作伙伴。 

最后的循环提取数字`% 10`并删除它们`// 10`。 第一个提取的数字正是从右边算起的第一个数字，所以`k`从 1 开始。对于前导零没有特殊处理，因为输入值本身没有前导零，并且在处理完最高有效数字后循环自然停止。 

Python 整数不会溢出，但每个大的中间系数都会模数减少`MOD`。 这使值保持较小并反映了问题所需的模运算。

 ## 边缘情况

 对于单个值`1`，唯一的对是 ((1,1))。 它唯一的数字有(k=1)，唯一的伙伴有(j=1)。 系数为(10^1+10^0=11)。 该算法添加 (1\cdot11)，产生`11`，完全按照要求。 

对于输入```
2
9 10
```长度计数是`cnt[1]=1`和`cnt[2]=1`。 对于数字`9`，(k=1)，除一位数情况下等式也成立外，双方长度均满足(k\le j)，因此其总系数为(11+11=22)，得到(198)。 为了`10`，最右边的数字有 (k=1) 并贡献 (0)，而其下一位数字有 (k=2)。 针对一位数伙伴 (k>j)，给出系数 (2\cdot10^2=200)，而针对两位数伙伴则给出 (10^3+10^2=1100)。 所得贡献为 (1300)，总计为 (198+1300=1498)。 等等，这揭示了为什么手工计算必须保留实际数字：`9`贡献 (9\cdot22=198)，而`10`贡献 (1\cdot1300=1300)，给出 (1498)，而不是`1408`。 

对于相同的输入，直接构造可确认 (f(9,9)=99)、(f(9,10)=190)、(f(10,9)=109) 和 (f(10,10)=1010)。 它们的总和是（99+190+109+1010=1408）。 上面的差异来自于分配 (k=2) 位`10`针对两位数伙伴的错误系数。 当(x=10)和(y=10)时，数字`1`不匹配的前缀是否仅相对于长度为一的交替后缀？ 两个数字实际上具有相同的长度，因此它参与交替部分，并且在两个方向上都有系数 (10^3+10^2=1100)，而反对`9`它在两个方向上都处于不匹配的前缀，系数为 (2\cdot10^2=200)。 因此它的总系数是 (1300)，给出 (1300)，并且`9`贡献（198），但缺失的贡献位于零位。 由于零没有任何贡献，因此直接总计应该是 (1498)，这与显式构造的对和相矛盾。 (f(10,9)) 的正确直接值为`109`，并且 (f(9,10)) 是`190`，而 (f(10,10)=1100)，则不是`1010`。 正确的总数是（99+190+109+1100=1498）。 因此，该算法和校正的边缘情况计算一致。 

对于最大值（10^9），该数字有十位，因此最高有效位在（k=10）处处理。 如果伙伴也有十位，则其系数为(10^{19}+10^{18})。 如果伙伴的数字较少，则公式切换为 (2\cdot10^{k+j-1})。 当一个数字具有较长前缀时，(k>j) 处的分支正是防止出现相差一错误的原因。 

对于（100000）个一位数字的副本`1`，每个有序对都会产生`11`。 有 (100000^2) 对，因此未简化的答案是 (110000000000)。 将其模 (998244353) 减少得到`193121170`。 该算法获得相同的结果，因为`cnt[1]=100000`，唯一的权重是 (100000\cdot11)，并且每个 (100000) 数字贡献该权重一次。
