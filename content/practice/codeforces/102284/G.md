 ## 解决方案
 ## 问题理解

 我们一一收到开关。 转变`i`有一个整数标签`a[i]`，如果两个带有标签的开关`x`和`y`连接起来，渠道成本`x XOR y`。 对于输入序列的每个前缀，我们需要精确包含已到达交换机的连接网络的最小可能总成本。 

由于任何连通的网络都可以在不增加其成本的情况下简化为生成树，因此每次插入后的任务正是完整图的最小生成树权值，该完整图的顶点是当前交换机，其边权值在`x`和`y`是`x XOR y`。 

最终的开关数量可以是`100000`，因此为每个前缀从头开始重建 MST 的成本太高了。 即使是大小前缀上的二次 Prim 实现`k`需要 θ(`k²`) 边缘比较。 对所有前缀求和，即为 θ(`n³`）， 关于`3.3 * 10^14`比较时`n = 100000`。 二次或三次算法无法满足正常的竞争性编程时间限制。 

值满足`0 <= a[i] <= 200000`。 自从`200000 < 2^18`，每个值只需要 18 个二进制位，从位 17 到位 0。这种小位宽是使二进制 trie 有用的结构属性。 比特数而不是可能的开关对的数量的算法多项式是可行的。 

有几种边缘情况很容易被错误处理。 首先，相同的值是不同的交换机，但它们的连接成本为零。 用于输入`3`有价值观`5 5 5`，答案是`0 0 0`。 将相等值视为重复顶点的实现仍然会碰巧在此处获得 MST 权重，但它可以通过假设每个新值都会创建一个新的 trie 叶子来轻松破坏其插入逻辑。 

一种更微妙的情况是，添加开关会更改两个二叉 trie 子树之间的最佳边，同时更改这些子树之一内的 MST。 例如，与`0 7 3`，答案是`0 7 7`。 插入后`3`，之间的最佳边`{0,3}`和`{7}`变成`3 XOR 7 = 4`，替换之前的成本交叉边`7`，但是子树`{0,3}`本身现在需要成本优势`3`。 这两个更改取消。 一个粗心的解决方案是简单地将新交换机的最近距离添加到之前的 MST 上，这样会得到`7 + 3 = 10`，这是错误的。 

允许的最高位是另一种边界情况。 用于输入`3`有价值观`0 131072 131073`，答案是`0 131072 131073`。 自从`131072 = 2^17`，必须包含位 17。 仅使用位 16 至 0 会默默地丢失最重要的贡献并产生不正确的结果。 

最后，第一个交换机根本没有边缘，因此它的 MST 成本为零。 为了`2`有价值观`0 1`，所需的输出是`0 1`。 在具有相反的 trie 分支之前更新答案的代码可能会意外地引入不存在的边。 

## 方法

 直接的方法是独立处理每个前缀。 对于包含的前缀`k`开关，我们可以隐式构造完整的图并运行 Prim 的算法。 对于每个新选择的顶点，我们扫描所有剩余的顶点并计算它们的 XOR 距离。 这是正确的，因为 Prim 始终生成 MST，并且完整的图包含每个可能的通道。 问题是重复工作。 一个前缀的成本为 θ(`k²`)，所以所有前缀都会花费`1² + 2² + ... + n² = Θ(n³)`。 

为了`n = 100000`，大致就是`3.33 * 10^14`配对检查，这根本不实用。 

关键的观察结果来自于通过其最高不同位来查看异或。 考虑共享某个固定前缀的所有值，并假设它们的下一个相关位是`b`。 将它们分成`L`，谁的位`b`为零，并且`R`，谁的位`b`是一。 里面的每一个边缘`L`以及里面的每一个边缘`R`有位`b`等于零。 之间的每条边`L`和`R`有位`b`等于一。 由于该 trie 节点内的所有高位都是相等的，因此每个内部边都比每个交叉边更便宜。 

这意味着克鲁斯卡尔将完全连接`L`和`R`在考虑它们之间的任何边缘之前先在内部进行。 两侧连接后，正好需要一个横边。 因此，最便宜的可能交叉边是以下值之间的最小异或：`L`和一个值`R`。 

这给出了基本递归`MST(node) = MST(left) + MST(right) + minimum_cross(node)`,

 如果两个子项之一为空，则最后一项为零。 

二进制 trie 准确地表示了这些递归分区。 剩下的问题是动态的：插入一个值后，只有该值的根到叶路径上的 trie 节点可以更改。 在每个这样的节点处，所选子节点的内部 MST 在 trie 中发生更深入的变化，并且唯一可能的新交叉边是从新插入的值到相对子节点的边。 

因此，我们为每个 trie 节点维护连接其两个子节点的当前最便宜的边。 当有新值时`x`插入后，我们就沿着它的真实路径走下去。 在bit对应的节点处`b`，如果相反的子节点已经存在，我们查询该子树的值最小化`x XOR y`。 这给出了唯一可以提高节点交叉边缘的新候选者。 我们通过新旧交叉边成本之间的差异来更新全局 MST 答案。 

最小 XOR 查询本身是标准的二进制 trie 贪婪行走。 在每个较低位，我们更喜欢包含相同位的分支`x`，因为它对 XOR 的贡献为零。 如果该分支不存在，我们就采用另一个分支并将相应的 2 的幂添加到查询结果中。 

暴力破解之所以有效，是因为它明确地重新计算了所有配对关系。 它失败了，因为几乎所有信息在连续前缀之间都没有变化。 MST 沿着二进制前缀分解的观察结果让我们只更新一条从根到叶的路径，并且每个跨边查询都是另一个 trie 遍历。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n^3)`总计 |`O(n)`| 太慢了 |
 | 最佳|`O(n log^2 A)`|`O(n log A)`| 已接受 |

 这里`A`是最大可能值，在这个问题中`log A <= 18`。 

## 算法演练

 1. 构建一个最初为空的二进制 trie，其中包含迄今为止插入的所有值。 每个 trie 节点存储其两个子节点以及连接这些子节点的当前最小 XOR 边。 

根代表所有插入的开关。 位 17 之后是位 16，依此类推，根据开关的二进制前缀对开关进行分区。 
2. 对于每个传入的值`x`，从根开始，沿着与`x`从位 17 向下到位 0。 

只有这条路径上的节点可以改变`x`已添加。 每个其他 trie 节点都包含与以前完全相同的一组旧开关。 
3.在bit对应的节点处`b`，识别包含相同位的子项`x`和对面的孩子。 

如果相对的子节点不存在，则插入前没有交叉边，插入后仍然没有交叉边。 我们只继续向下匹配的孩子。 
4. 如果存在相反的子树，则在该子树中查询最小异或`x`，仅考虑下面的位`b`。 

当前位的贡献正好`2^b`，因为两个孩子有点不同`b`。 低位trie查询确定边权重的剩余部分。 
5. 将该候选交叉边权重与为该节点存储的值进行比较。 

此插入引入的唯一新边是来自`x`到旧交换机。 在穿过该节点的两个子节点的边中，每对旧的边都已经存在。 因此旧的最小值只能保持不变或被来自的边缘取代`x`到相反子项中最接近的值。 
6. 如果候选值较小，则替换存储的交叉边值并将差值添加到全局 MST 答案中。 

这里的减少是可能的。 例如，当插入`3`进入`{0,7}`，根的交叉边缘改进为`7`到`4`。 同时，更深的节点获得内部边缘`0 XOR 3 = 3`。 全局答案记录了这两个变化，给出`7 - 3 + 3 = 7`。 
7. 如果匹配的子项尚不存在，则创建该子项，然后继续处理下一个较低位。 

创建 trie 路径是在检查相反的子树之后发生的，因此每个查询仅考虑当前插入之前存在的开关。 
8. 处理完所有 18 位后，将当前全局答案附加到输出中。 

对于一个开关来说，没有边缘，因此答案自然保持为零。 

### 为什么它有效

 对于每个 trie 节点，其子树中的所有值都具有相同的较高二进制前缀。 如果它的孩子有一点不同`b`，穿过两个孩子的每条边都有相同的更高贡献，并且有位`b`集，而留在一个孩子内部的每条边都有位`b`未设置。 因此，所有内部边缘比每个交叉边缘便宜。 在使用交叉边之前，克鲁斯卡尔必须完成两个子子问题，并且恰好一个最小交叉边足以连接它们。 这就证明了递归MST分解。 

在插入过程中，新值的 trie 路径之外的所有节点都包含完全相同的顶点，因此它们的 MST 成本和跨边最小值不会改变。 在路径节点处，唯一新可用的交叉边是那些与新值相关的交叉边。 trie 查询找到最便宜的这样的边。 因此，更新存储的跨边最小值是准确的，并且所有更改的节点贡献的总和正是新的 MST 权重。 通过插入归纳，每个报告的答案都是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX_BIT = 17

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # Each node has two children.
    # -1 means that the child does not exist.
    left = [-1]
    right = [-1]

    # cross[v] is the minimum XOR edge between the two
    # children of v. Zero means that one child is absent.
    cross = [0]

    answer = 0
    out = []

    for x in a:
        node = 0

        for b in range(MAX_BIT, -1, -1):
            bit = (x >> b) & 1

            if bit == 0:
                opposite = right[node]
            else:
                opposite = left[node]

            if opposite != -1:
                # Find the minimum XOR between x and a value
                # in the opposite subtree, using lower bits.
                cur = opposite
                lower_xor = 0
                k = b - 1

                while k >= 0:
                    xb = (x >> k) & 1

                    if xb == 0:
                        nxt = left[cur]
                        if nxt == -1:
                            nxt = right[cur]
                            lower_xor |= 1 << k
                    else:
                        nxt = right[cur]
                        if nxt == -1:
                            nxt = left[cur]
                            lower_xor |= 1 << k

                    cur = nxt
                    k -= 1

                candidate = (1 << b) + lower_xor
                old = cross[node]

                if old == 0 or candidate < old:
                    cross[node] = candidate
                    if old == 0:
                        answer += candidate
                    else:
                        answer += candidate - old

            # Move down the trie, creating the new path if necessary.
            if bit == 0:
                nxt = left[node]
                if nxt == -1:
                    nxt = len(left)
                    left.append(-1)
                    right.append(-1)
                    cross.append(0)
                    left[node] = nxt
            else:
                nxt = right[node]
                if nxt == -1:
                    nxt = len(left)
                    left.append(-1)
                    right.append(-1)
                    cross.append(0)
                    right[node] = nxt

            node = nxt

        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这三个数组代表二元特里树。`left[v]`和`right[v]`识别孩子的身份，同时`cross[v]`存储连接两个子子树的最便宜的边。 不需要将顶点本身存储在 trie 节点内。 

循环结束`b`遵循从最高相关位到最低相关位的新值。 最高相关位是 17，因为`200000 < 2^18`。 对于每个合法输入，使用 18 位就足够了，而从 18 位开始也可以，但会增加不必要的工作。 

在下降到匹配的子项之前，代码会检查相反的子项。 这个顺序很重要。 相反的子树必须只包含先前插入的开关，因为新的开关尚未附加到 trie。 否则查询可能会意外使用`x`自己作为自己的合作伙伴。 

查询直接从相反的子节点开始，而不是从根开始。 在当前位`b`，两个子前缀已经不同，因此该位的贡献已知为`2^b`。 仅需要优化较低位。 这就是为什么查询开始于`b - 1`。 

当首选 trie 分支丢失时，查询将采用另一个分支并设置相应的位`lower_xor`。 这恰好实现了最小异或搜索：匹配位总是更可取，因为它们贡献零。 

这`cross`value 使用零作为哨兵，因为两个不同子节点之间的任何实边都至少有一个不同的位，因此其 XOR 值为正。 相同的开关标签保留在同一个 trie 叶子中，并且永远不会创建正交叉边。 

Python 整数会自动处理可能较大的 MST 总和，因此不存在溢出问题。 无论如何，最大可能的答案完全在 Python 的整数能力范围内。 

## 工作示例

 ### 示例 1

 对于序列`4 0 2 2 9 4`，重要的变化如下所示。 

| 插入值| 更改特里结构级别 | 老十字架| 新十字| 达美航空 | 总答案 |
 | --- | --- | --- | --- | --- | --- |
 |`4`| 无 | 0 | 0 |`0`|`0`|
 |`0`| 位 2 | 0 | 4 |`+4`|`4`|
 |`2`| 位 1 | 0 | 2 |`+2`|`6`|
 |`2`| 无 | 不变| 不变|`0`|`6`|
 |`9`| 位 3 | 0 | 9 |`+9`|`15`|
 |`4`| 无 | 不变| 不变|`0`|`15`|

 插入后`0`，两个值在第 2 位第一次分开，因此唯一的边成本`4 XOR 0 = 4`。 

什么时候`2`到达，它属于相同的 bit-2 边`0`，但不同于`0`位 1。这创建了成本更便宜的内部连接`2`。 总计变为`6`。 

第二个`2`是一个重复值。 它创建另一个交换机，但从它到现有交换机的每个新边缘的成本与第一个交换机的相应边缘完全相同`2`，特别是它可以使用该交换机的零成本优势。 MST权重保持不变`6`。 

价值`9`首先与第 3 位的现有值不同。将新的第 3 位边连接到旧边的最便宜的边具有成本`9`，增加答案`15`。 决赛`4`已经由现有值表示`4`，因此零成本连接可用并且 MST 权重保持不变`15`。 

### 第二个例子

 考虑顺序`0 7 3 4`。 

| 插入值| 更改级别 | 老十字架| 新十字| 达美航空 | 总答案 |
 | --- | --- | --- | --- | --- | --- |
 |`0`| 无 | 0 | 0 |`0`|`0`|
 |`7`| 位 2 | 0 | 7 |`+7`|`7`|
 |`3`| 位 2 | 7 | 4 |`-3`|`4`|
 |`3`| 位 1 | 0 | 3 |`+3`|`7`|
 |`4`| 位 1 | 0 | 3 |`+3`|`10`|

 第三个插入展示了更新中最微妙的部分。 插入前`3`，根分开`{0}`从`{7}`，所以它的交叉成本是`7`。 插入后`3`，根分开`{0,3}`从`{7}`，最好的交叉边是`3 XOR 7 = 4`。 根贡献减少`3`。 

同时，子树包含`{0,3}`获得自己的 MST 成本优势`0 XOR 3 = 3`。 总的变化是`-3 + 3 = 0`，所以答案仍然是`7`。 

插入后`4`，子树包含`7`和`4`获得优势`4 XOR 7 = 3`。 生成的 MST 可以使用具有成本的边`3`,`3`， 和`4`，总共`10`。 

该跟踪特别有用，因为它说明了为什么仅维持新交换机到旧 MST 的距离是不够的。 多个特里结构级别可以同时更改，并且它们的贡献可以独立增加或减少。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log^2 A)`| 有`O(log A)`trie 级别，并且在每个级别，最小异或查询需要`O(log A)`|
 | 空间|`O(n log A)`| 最多`O(n log A)`创建 trie 节点 |

 这里`A <= 200000`，因此只有 18 个相关位。 每次插入最多执行 18 次最小异或搜索，低位步总数最多为`17 + 16 + ... + 0`，每次插入仅需 153 个 trie 步骤。 为了`100000`这大约需要 1530 万个内部查询步骤，加上普通的 trie 插入工作。 

内存使用情况也是可以管理的。 事实上，因为只有`2^18`可能的值，完整的二进制 trie 将包含少于`2^19`节点，尽管一般`O(n log A)`界足以进行分析。

 ## 边缘情况

 重复值的情况由 trie 自然处理。 用于输入`4`有价值观`123 123 123 123`，每个新值都遵循与第一个值完全相同的路径。 在任何级别上都不会创建相对的子级，因此跨边贡献不会发生变化。 输出是`0 0 0 0`。 开关仍然是不同的顶点，但连接相同的标签成本为零。 

第一个插入在任何地方都没有相反的子树，因为 trie 不包含以前的值。 用于输入`2`有价值观`0 1`，第一个答案是`0`。 什么时候`1`插入后，两个值首先在位 0 处不同，该位以下的查询为空，新的交叉边有成本`1`。 输出是`0 1`。 

最大值边界使用位 17。 对于输入`3`有价值观`0 131072 131073`, 插入`131072`在第 17 位创建分割并添加`2^17 = 131072`。 什么时候`131073`到达，它属于与以下相同的 bit-17 子树`131072`与它的区别仅在于位 0，因此 MST 具有成本优势`1`。 输出是`0 131072 131073`。 

最骗人的案例是`0 7 3`。 后`0`和`7`，唯一的优势是成本`7`。 什么时候`3`到达时，根的最佳交叉边从`7`到`3 XOR 7 = 4`，减少根贡献`3`。 在较低位处`0`和`3`分裂，新的内部成本优势`3`出现。 这两个更改取消，将答案保留为`7`。 这正是算法更新插入路径上的每个 trie 节点而不是将新交换机视为添加到先前 MST 的单个边缘的原因。 

最终示例还在构建了几个特里树级别后执行了重复插入。 在`4 0 2 2 9 4`，第二个`2`第二个`4`不改进任何存储的交叉边，因此答案在各自的插入处保持不变。 该算法不需要特殊的重复处理，因为 trie 结构和最小 XOR 查询已经考虑了零成本连接。
