 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 重要的隐藏结构是我们可以自由地重新排列元素，但只能以一种受限制的方式：我们可以选择任意两个位置并交换它们的值。 因此，我们可以有效地任意排列数组，因为任何排列都可以通过交换来实现。 

选择排列后，我们希望数组满足前缀条件：每个前缀和必须严格为正。 换句话说，当我们从左到右扫描时，运行总和在任何时候都不会降至零或更低。 

对于每个测试用例，任务是确定将数组重新排列成“有效前缀和正”顺序所需的最小交换次数。 如果没有重新排列可以实现这个属性，我们必须输出-1。 

输入约束意味着所有测试用例的元素总数很大，最多可达 10^5 左右。 这排除了任何尝试所有排列或显式模拟交换的方法。 在最坏的情况下，即使每个测试用例的 O(n^2) 也太慢了。 

关键的边缘情况是当数组的负值与正值相比过多时。 例如，如果数组包含的 -1 多于 1，即使是最好的排序也无法阻止前缀和最终变为非正数。 

当总和为正但勉强为正时，就会出现另一个微妙的情况。 例如，如果数组为[1, -1, -1, 1]，则总和为零，因此最后一个前缀和不能为正。 即使数组在本地看起来是平衡的，这也会立即使答案变得不可能。 

第二种类型的边缘情况是当安排存在但根本不需要交换时。 例如，[1, 1, -1] 已经有效，因此答案为零，即使天真的想法可能会考虑重新排序。 

## 方法

 暴力破解的想法很简单：生成数组的每个排列并检查其前缀和是否保持正数。 对于每个排列，以 O(n) 计算前缀和，并跟踪从原始数组到达它所需的最小交换次数。 然而，排列的数量是n！，即使忽略交换计数，简单地检查有效性也已经变得不可能超过非常小的n。 

思考这个问题的一个更有用的方法是分开两个问题：什么时候有效的安排是可能的，以及这种安排的结构是什么。 

前缀和条件强烈暗示贪婪构造。 如果我们希望所有前缀和保持正值，我们希望尽早获得大量的正贡献。 由于数组仅由 1 和 -1 组成，因此唯一真正的自由是我们如何交错它们。 

如果我们将 P 定义为 1 的数量，N 为 -1 的数量，那么任何有效的排列都必须在每个前缀中满足 P > N，特别是全局上 P 必须超过 N。 So a necessary condition is P > N.

Now consider constructing a valid ordering. 一个自然的策略是尽可能早地放置 1，并延迟 -1。 事实上，当 P > N 时，将所有 1 放在前面，然后将所有 -1 放在前面的贪婪顺序总是有效的，因为前缀和首先严格增加然后减少，但如果 P 足够大，则永远不会达到非正值。 

一旦我们知道有效性仅取决于计数，剩下的问题就变成需要多少次交换才能将原始数组转换为某种有效的排序。 

关键的观察是，任何有效的排列都必须对应于选择一个目标序列，其中所有 1 都出现在以受控方式引入足够的 -1 之前。 所需的最小交换相当于计算当前有多少个 -1 被放置在 1 应该在的位置，反之亦然，相对于规范的最佳排序。

形式化这一点的一种简洁方法是将目标排列视为所有 1 都放置在第一个 P 位置。 然后我们将原始数组与该目标进行比较并计算不匹配的数量。 每次交换可以修复两个放错位置的元素，因此，只要可行性成立，答案大约是不匹配数量的一半。

 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!) | O(n) | 太慢了|
 | 贪婪 + 不匹配计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 统计数组中有多少个1和-1。 这决定了是否可以进行任何有效的安排。 
2. 如果1的数量不严格大于-1的数量，则立即返回-1。 在任何排列中总和都将为非正数，因此某些前缀将失败。 
3. 通过首先放置所有 1，然后放置所有 -1 来修复规范的目标排列。 只要步骤 2 中的条件成立，这就是有效的，因为 1 中的每个前缀都有正和，并且 1 的盈余确保我们在添加 -1 后永远不会降至零。 
4. 扫描原始数组并逐个位置与目标位置进行比较，计算不匹配的情况。 当需要 1 的区域出现 -1 时，就会发生不匹配，反之亦然。 
5. 每次交换可以纠正两个不匹配，因为用错误的 1 与错误的 -1 交换可以同时修复两个位置。 因此计算不匹配除以 2 作为答案。 
6. 输出该值。 

### 为什么它有效

 核心不变量是任何有效的最终配置完全由 1 相对于 -1 的位置决定，并且前缀和约束强制在最佳排列中尽早使用所有 1。 由于交换在索引上不受限制，因此问题简化为将多集排列转换为固定的规范排列。 不匹配配对参数确保每次交换都能将错误放置的数量减少恰好两倍，并且没有任何交换可以做得更好，因此贪婪配对是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case():
    n = int(input())
    a = list(map(int, input().split()))

    ones = a.count(1)
    negs = n - ones

    if ones <= negs:
        return -1

    # target: all 1s then -1s
    target = [1] * ones + [-1] * negs

    mismatches = 0
    for i in range(n):
        if a[i] != target[i]:
            mismatches += 1

    return mismatches // 2

t = int(input())
for _ in range(t):
    print(solve_case())
```该代码首先使用简单的计数条件检查可行性。 这是对存在至关重要的唯一全球约束。 

然后，它构建概念目标排序，而不显式存储超出简单模式的任何大内容。 失配计数是在线性时间内计算的。 

除以 2 是关键的实现细节：每次交换恰好解决一个不正确的 1 位和一个不正确的 -1 位。

## 边缘情况

 如果数组中 1 和 -1 的数量相等，则可行性检查立即失败。 例如，[1, -1] 不能以任何顺序产生严格的正前缀和，因为最终和为零并且某些前缀必须降至零。 

如果数组已经排序为全 1 后跟全 -1，则不匹配计数为零，答案为零交换。 例如，[1, 1, 1, -1] 已经满足目标结构。 

如果数组混杂较多，比如[1, -1, 1, -1, 1, -1, 1]这样的交替值，错配计数会变大，但每次交换仍然可以解决两个错位，因此算法自然地将成本压缩为较小的整数交换次数，而不是无序地线性增长。
