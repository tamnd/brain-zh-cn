 ## 解决方案
 ## 问题理解

 我们正在模拟一个非常小的系统：一家酒店，正好有 10 个房间，索引从 0 到 9。每个房间可以是空的，也可以是有人的。 事件序列描述了客人如何随着时间的推移进入和离开，我们需要在按顺序处理所有事件后重建最终的入住状态。 

每个事件要么是从左入口到达，要么是从右入口到达，要么是从特定房间离开。 当有人从左边进入时，他们总是从 0 号房间开始向右移动最近的当前空房间。 当有人从右边进入时，他们会从9号房间开始向左移动最近的空房间。 当一个数字出现时，就意味着该房间的客人离开了，房间又空了。 

关键的困难不是模拟速度，而是重复更新下的正确性：到达总是取决于当前状态，因此早期的选择会限制未来的选择。 尽管结构很小，但事件数量可能很大，最多可达 100,000 个，因此我们必须确保每个事件都得到有效处理。 

一个幼稚的解释错误是假设到达者总是去固定位置，例如总是将左侧到达者分配给全局的第一个空闲时段，而不考虑先前出发的动态性质。 例如，如果我们忽略移除，我们可能会错误地将新左到达者放入当前占用的房间中。 

另一个微妙的边缘情况是重复切换同一个房间。 例如，一个房间可以被占用、释放和重新占用多次。 任何不能维持准确的实时状态阵列的解决方案都将偏离正确的配置。 

由于只有 10 个房间，因此最终输出是代表占用情况的 10 个字符的二进制字符串。 

约束 n ≤ 10^5 意味着我们必须在 O(1) 或 O(10) 时间内处理每个事件。 扫描每个事件的所有房间的任何方法仍然是可以接受的，但是每个房间使用 n 进行缩放的任何方法都会太慢。 

## 方法

 一个简单的模拟维护一个由 10 个布尔值组成的数组，表示每个房间是否被占用。 对于从左边开始的每个房间，我们从 0 开始扫描房间并选择第一个空房间。 对于从右侧到达的情况，我们从 9 向下扫描并选择第一个空的。 对于出发事件，我们只需将该房间标记为空即可。 

这种强力方法的状态大小已经非常小，因此每个事件的最坏情况成本最多为 10 次检查。 超过 10^5 个事件，这会导致大约 10^6 次操作，这完全在限制范围内。 不需要更复杂的数据结构，如堆或平衡树。 

关键的观察结果是，该问题不需要记住历史任务，只需要记住当前的占用情况。 每个决策仅取决于当前状态，并且状态空间很小且大小固定。 除了简单的线性扫描之外，这消除了任何优化的需要。 

我们可以将其视为维护大小为 10 的位掩码，并对每个事件应用贪婪选择规则。

 ## 算法演练

 1.初始化一个数组`rooms`大小为 10，所有值都设置为 0，这意味着所有房间都是空的。 这表示时间 0 时的当前酒店状态。 
2. 从左到右迭代输入字符串中的每个字符，将每个字符视为一个事件。 
3. 如果事件是`'L'`，从 0 号房间扫描到 9 号房间，找到第一个空房间。 将其标记为已占用。 这可确保使用距左入口最近的可用空间。 
4. 如果事件是`'R'`，从房间 9 向下扫描到房间 0，找到第一个空房间。 将其标记为已占用。 这可确保使用距右入口最近的可用房间。 
5. 如果事件是一个数字`'0'`到`'9'`，将其转换为整数索引并将该房间标记为空。 
6. 继续此过程，直到处理完所有事件。 
7. 将最终状态输出为长度为10的字符串，其中每个位置为`'1'`如果被占用并且`'0'`否则。 

### 为什么它有效

 该算法会在每次事件发生后维护所有房间的准确占用状态。 每个到达规则仅取决于当前的空置房间集合，而每次离开则直接将一个房间恢复到空置集合中。 由于我们总是根据最新状态重新计算选择，因此任何决定都不会违反“最近的可用房间”的约束。 正确性来自于以下不变量`rooms[i]`当且仅当房间为真`i`处理完事件前缀后被占用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    rooms = [0] * 10

    for c in s:
        if c == 'L':
            for i in range(10):
                if rooms[i] == 0:
                    rooms[i] = 1
                    break
        elif c == 'R':
            for i in range(9, -1, -1):
                if rooms[i] == 0:
                    rooms[i] = 1
                    break
        else:
            idx = ord(c) - ord('0')
            rooms[idx] = 0

    print("".join(map(str, rooms)))

if __name__ == "__main__":
    solve()
```该实现保留了酒店状态的直接表示。 循环为`'L'`和`'R'`故意简单，因为常数因子以 10 为界。转换数字字符使用 ASCII 算术，这可以避免解析速度变慢。 最终输出将整数标志连接成字符串。 

这里的一个常见错误是忘记离开总是成功的，因此数字事件可以安全地假设房间已被占用。 另一个是意外地在事件之间重用过时的循环索引，但由于每个事件都是独立的，因此扫描总是重新启动。

 ## 边缘情况

 一个重要的情况是释放后重复使用同一房间。 考虑输入`L0L0`。 后`L`，房间 0 被占用。 活动内容`0`释放它，然后下一个`L`再次选择房间 0，因为它又是最近的空槽位。 该算法可以正确处理这个问题，因为每个`'L'`扫描从房间 0 开始，因此先前释放的位置自然会重新考虑。 

另一种情况是除一个房间外的所有房间都被占用时。 如果房间 9 是唯一的空闲位置并且发生左到达，则从 0 向上扫描最终将到达 9 并将客人安置在那里。 即使离左入口较远，这也是正确的，因为严格的规则是“最近的空房间”，而不是“即使远也喜欢左边”。 

最后一个微妙的情况是交替使用边界房间的到达和离开。 例如，`L R 0 R L 0`重复切换房间 0 和 9。由于每个事件都会立即更新共享状态，因此扫描始终反映最新配置，从而防止分配过时。
