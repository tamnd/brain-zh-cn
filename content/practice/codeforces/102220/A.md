 ## 解决方案
 ## 问题理解

 农场是一棵按堆顺序编写的完全二叉树。 树 1 是根，每棵树`i > 1`有父母`i // 2`。 树`i`最初包含`a[i]`苹果。 

客户要求`(u, v, c, w)`很特别，因为`u`保证是的祖先`v`。 顾客最多可以购买`c`苹果，但卖给该客户的每个苹果都必须来自单一的下行路径`u`到`v`。 每个这样的苹果都会赚到`w`美元。 苹果可以分配给不同的客户，目标是选择根据每个请求销售多少苹果，同时尊重树木容量和客户限制。 

官方限制是`n,m <= 100000`每个测试用例，总计`n`和总计`m`跨越所有测试用例`10^6`。 时间限制为 6 秒，内存限制为 512 MB。 树节点只有深度`O(log n)`因为树是一个二叉堆，这是使对数深度动态规划成为可能的结构事实。 在`n = 100000`，执行二次数量的成对请求操作的算法已经太大了，而`O((n+m) log^2 n)`方法在预期范围内。 最初接受的实现正是使用了这种树-DP 思想。 

在许多情况下，看似自然的贪​​婪实现会失败。 首先，通过降低价格来处理请求是必要的，但仅仅沿着路径任意获取苹果是不够的。 考虑```
1
2 2
1 1
1 2 1 10
2 2 1 9
```正确答案是`19`。 第一个顾客可以拿走 1 号树上的苹果，将 2 号树上的苹果留给第二个顾客。 粗心的实现可能会使用树 2 来满足第一个请求，之后第二个请求什么也得不到，答案就变成了`10`。 

第二种边缘情况是两个端点相等的请求。 为了```
1
1 2
5
1 1 3 10
1 1 5 2
```答案是`34`。 两个请求都仅限于唯一的一棵树，因此第一个请求出售 3 个苹果，第二个请求出售剩余的 2 个。假设每条路径至少有一条边的实现可能会错误地处理这种情况。 

第三个问题是请求可能会要求比其路径包含的苹果更多的苹果。 为了```
1
3 1
1 1 1
2 3 10 7
```该路径仅包含树 2 和 3，因此只能出售 2 个苹果，答案为`14`。 使用要求的数量`c`直接不检查路径的可用容量会导致计算过多。 

## 方法

 一种直接的方法是将每个苹果视为单独的物品，并将每个请求视为可能的买家。 对于每个苹果，我们可以尝试路径包含其树的每个请求，并选择最高的可用价格。 如果分配被解决为最大权重二分匹配，那么这在概念上是正确的，但它是完全不可行的，因为`a[i]`可以大到`10^9`，所以单个苹果的总数可以达到`10^14`。 

相反，我们可以按树压缩苹果并构建最大成本流网络。 一棵树贡献它的苹果数量作为供应，而请求贡献它的容量和价格。 将请求连接到其路径上的每棵树会创建最多`O(m log n)`请求树发生率，因为每条路径都有对数长度。 该图已经很大，并且通用的最大成本流算法可能需要大量的增强，因为容量巨大。 这没有利用路径的特殊结构。 

有用的观察结果是，所有请求都是垂直路径，从祖先到后代。 这将分配问题转化为有根树上的霍尔型可行性问题。 对于一组固定的请求，当每个请求集合在其允许路径的并集中有足够的苹果时，它们就可以完全满足。 由于路径具有这种祖先-后代形式，因此潜在的紧霍尔集可以由有根子树和一条显着的向下路径来表示。 我们可以使用树 DP 来维护所有这些霍尔约束。 

第二个观察涉及利润。 按降序处理请求`w`。 假设所有更昂贵的请求都已被尽可能地满足。 对于当前的请求，我们希望添加尽可能多的需求，同时保持已构建的分配可行。 如果我们可以添加`C`苹果，利润增量正好是`C * w`，所以最大化`C`是最优的。 等价请求可以按任何顺序处理，因为只有已售出的苹果总数才重要。 

对于每一个可能的根`x`，我们维护子树的副本`x`，再次表示为堆。`v[x]`存储 Hall DP 使用的剩余容量值，同时`f[x]`存储当前的霍尔松弛。 对于相对节点`y`, 递推式为

 [
 f[y] = v[y] + \min(0,f[2y]) + \min(0,f[2y+1])。 
]

 失踪儿童的贡献为零。 负子值意味着其子树存在必须通过其父级提供的赤字，因此父级会继承该负数。 非负孩子内部已经有足够的能力，并且不会限制其父母。 

当请求来自`A`到`B`添加后，其端点`B`被视为每个祖先副本中的新需求单位，其根是`A`。 对于每个这样的副本，我们计算结束于的路径的霍尔松弛`B`，包括兄弟子树不可避免的缺陷。 这些松弛量的最小值正是在不违反任何霍尔条件的情况下可以添加的最大量。 

实施遵循原始竞赛解决方案`v`和`f`直接树DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解/个人苹果流 | 与苹果总数呈指数或成正比，最多`10^14`项目 | 潜力巨大| 太慢了 |
 | 最优霍尔树 DP |`O(n log n + m log² n)`|`O(n log n)`| 已接受 |

 ## 算法演练

 1. 阅读所有请求并按价格降序排序`w`。 价格较高的苹果必须始终先于价格较低的苹果进行分配，因为除了客户的价格之外，每个苹果对客户来说都具有相同的价值。 
2. 对于每棵树`x`，构建一个辅助堆，表示以`x`。 根`x`接收相对索引`1`，其子项接收索引`2`和`3`，他们的孩子收到`4`通过`7`， 等等。 这使得每个祖先-后代路径都可以通过相对索引上的普通父级和子级操作来表示。 
3. 对于每个辅助树，初始化`v`每个相关节点的苹果数量。 最初没有提出任何要求，所以`f`等于`v`。 
4. 对于每个请求`(A,B,C,W)`,首先确定相对指数`B`在每棵以祖先为根的辅助树中`x`的`A`。 如果深度差为`d`，则相对堆索引为`B`是通过保留最后一个来获得的`d`的二进制数字`B`并添加一个前导二进制文件`1`。 
5. 对于一根固定副根`x`, 开始于`dp = f[o]`， 在哪里`o`是相对位置`B`。 步行从`o`朝向副根。 每一个祖先`y`， 添加`v[y]`，因为实际路径可以使用苹果`y`。 然后检查路径孩子的兄弟姐妹。 如果该兄弟姐妹呈阴性`f`，其赤字对于相应的霍尔集合来说是不可避免的，因此将负值添加到`dp`。 
6. 取最小值`dp`遍及所有副根`x`在路径上从`A`到全局根。 该最小值是在不使某些霍尔约束成为不可能的情况下可以接受的该请求的最大附加量。 代替`C`如果它更小，则按此最小值。 
7. 如果结果`C`为零，当前请求不能出售任何东西，因此保持 DP 不变。 否则添加`C * W`到答案。 
8. 申请接受的金额`C`到每一个相关的辅助树。 减少`v[x][o]`和`f[x][o]`经过`C`，然后重新计算`f`在祖先上`o`使用相同的递归。 只有这些节点可以改变 Hall slack，因此没有理由重新计算整个辅助树。 

不变的是，在处理按价格递减排序的请求的任何前缀后，维护的`f`值描述了该前缀的可接受数量的可行分配，并且每个规范霍尔约束都由一些表示`f`值或通过下一次插入期间计算的路径松弛。 插入步骤选择最大可能的`C`对此，所有这些松弛仍然是非负的。 因此，只要可行性允许，每一个被接受的高价苹果都会被保留。 由于所有请求都是从较高价格到较低价格处理，因此没有可行的解决方案可以获得更好的总利润。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        a = [0] + list(map(int, input().split()))

        # v[x] and f[x] describe the subtree rooted at x.
        # Index 0 is unused.
        v = [None] * (n + 1)
        f = [None] * (n + 1)
        size = [0] * (n + 1)

        # Map a relative heap index z inside the subtree of x
        # to the original heap node.
        def actual_node(x, z):
            h = 1 << (z.bit_length() - 1)
            return x * h + (z - h)

        # Build the auxiliary heap for every x.
        for x in range(1, n + 1):
            lo, hi = 1, n + 1

            # Find the largest valid relative heap index.
            while lo + 1 < hi:
                mid = (lo + hi) >> 1
                y = actual_node(x, mid)
                if y <= n:
                    lo = mid
                else:
                    hi = mid

            mx = lo
            size[x] = mx

            vals = [0] * (mx + 1)
            for z in range(1, mx + 1):
                vals[z] = a[actual_node(x, z)]

            v[x] = vals
            f[x] = vals.copy()

        requests = []
        for _ in range(m):
            u, wv, c, w = map(int, input().split())
            requests.append((u, wv, c, w))

        requests.sort(key=lambda e: e[3], reverse=True)

        ans = 0

        def getid(x, y):
            d = y.bit_length() - x.bit_length()
            k = 1 << d
            return y - (x - 1) * k

        for A, B, C, W in requests:
            # First pass: find the largest feasible amount.
            x = A
            while x:
                o = getid(x, B)
                mx = size[x]
                vx = v[x]
                fx = f[x]

                dp = fx[o]
                y = o >> 1

                while y:
                    dp += vx[y]

                    t = y << 1
                    if t <= mx and t != o and fx[t] < 0:
                        dp += fx[t]

                    t = (y << 1) | 1
                    if t <= mx and t != o and fx[t] < 0:
                        dp += fx[t]

                    y >>= 1

                if dp < C:
                    C = dp

                x >>= 1

            if C <= 0:
                continue

            ans += C * W

            # Second pass: actually insert the accepted demand.
            x = A
            while x:
                o = getid(x, B)
                mx = size[x]
                vx = v[x]
                fx = f[x]

                vx[o] -= C
                fx[o] -= C

                y = o >> 1
                while y:
                    cur = vx[y]

                    t = y << 1
                    if t <= mx and fx[t] < 0:
                        cur += fx[t]

                    t = (y << 1) | 1
                    if t <= mx and fx[t] < 0:
                        cur += fx[t]

                    fx[y] = cur
                    y >>= 1

                x >>= 1

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```辅助树存储为按相对堆位置索引的列表。 表达式`actual_node(x, z)`重建由相对索引表示的原始节点`z`。 如果最高设置位`z`是`h`， 然后`z = h + r`对应的原始节点为`x * h + r`。 

已知后代的相对指数`B`可以更便宜地获得。 如果`d`是之间的深度差`x`和`B`， 然后`k = 2^d`，相对指数为`B - (x - 1)k`。 这相当于参考实现中使用的位操作。 

第一次传递请求仅确定其可行数量。 仅在知道该数量后，第二遍才会更改 DP。 混合这两个通道是不正确的，因为部分处理的请求可能会影响对其自身剩余数量的可行性检查。 

所有容量和答案都需要 C++ 中的 64 位整数。 Python 整数具有任意精度，因此不需要特殊的溢出处理。 这`C <= 0`检查也是必要的。 零松弛意味着当前请求不能增加任何需求，而对于可行的维护状态不能出现负值。 

## 工作示例

 对于官方样品，请求按价格顺序处理：`(2,4,2,4)`,`(2,5,2,3)`， 和`(1,2,3,1)`。 树上有苹果`[2,1,3,1,1]`。 官方输出是`13`。 

| 请求| 路径| 已请求`C`| 最大可行`C`| 价格| 增加利润| 总计 |
 | ---| ---| ---| ---| ---| ---| ---|
 |`(2,4,2,4)`|`2 -> 4`| 2 | 2 | 4 | 8 | 8 |
 |`(2,5,2,3)`|`2 -> 5`| 2 | 1 | 3 | 3 | 11 | 11
 |`(1,2,3,1)`|`1 -> 2`| 3 | 2 | 1 | 2 | 13 |

 第一个客户可以使用树 2 和 4 上的苹果。第二个客户与第一个客户共享树 2，而树 5 只提供一个额外的苹果，因此只能出售其请求的两个苹果中的一个。 之后，路径上仍然有两个苹果可用`1 -> 2`，给出最后的两美元。 霍尔松弛可防止第二个请求错误地从树的共享部分获取两个苹果。 

第二个例子说明了为什么路径上的苹果不能简单地以任意顺序被消耗。```
1
2 2
1 1
1 2 1 10
2 2 1 9
```| 请求| 路径| 已请求`C`| 可行的`C`| 价格| 增加利润| 总计 |
 | ---| ---| ---| ---| ---| ---| ---|
 |`(1,2,1,10)`|`1 -> 2`| 1 | 1 | 10 | 10 10 | 10 10 | 10
 |`(2,2,1,9)`|`2 -> 2`| 1 | 1 | 9 | 9 | 19 | 19

 第一个请求有两个可能的苹果。 Hall 表示记录第二个请求只能使用树 2，因此满足这两个请求需要保留树 2 可用。 该算法此时并未明确选择物理苹果。 相反，它保留了剩余的霍尔约束，这正是防止错误的任意选择的原因。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n log n + m log² n)`| 每个辅助子树包含`O(log n)`总体水平，每个请求都会检查`O(log n)`祖先与`O(log n)`DP为每个祖先工作。 |
 | 空间|`O(n log n + m)`| 辅助`v`和`f`数组为每个祖先-后代对存储一个条目，而请求列表存储`m`请求。 |

 为了`n,m <= 100000`，堆深度最多约为17，因此对数因子很小。 最初的竞赛使用 6 秒和 512 MB 的限制，并且接受的此 Hall 树 DP 的 C++ 实现符合这些限制。 Python 实现遵循相同的渐近方法，尽管 Python 具有更高的常数因子，并且与原始 C++ 实现相比不太适合最大可能的聚合输入。

 ## 边缘情况

 共享端点案例```
1
2 2
1 1
1 2 1 10
2 2 1 9
```是通过霍尔松弛来处理的，而不是通过选择特定的物理苹果来处理。 第一个请求被接受后，辅助DP记录下一个更严格的请求仍然需要树2。 因此，第二个请求仍然可行，产生`19`。 

等端点情况```
1
1 2
5
1 1 3 10
1 1 5 2
```根本没有路径边缘。 对于第一个请求，相对索引很简单`1`，所以第一遍看到松弛`5`并接受`3`。 该更新将根松弛从`5`到`2`。 然后第二个请求完全接受`2`, 给予`30 + 10 = 40`。 

请求超出其路径容量，```
1
3 1
1 1 1
2 3 10 7
```有相对路径`2 -> 3`。 初始霍尔松弛是两个可用苹果的总和，即`2`，所以要求的数量`10`减少为`2`。 因此利润为`2 * 7 = 14`。 

大堆边界```
1
100000 1
1 1 1 ... 1
1 100000 100000 1
```有一个包含二进制前缀链的路径`1`到`100000`。 自从`100000`二进制长度为 17，该路径包含 17 个节点。 该算法的相对索引转换遵循堆索引的二进制表示，因此它准确地计算出这 17 个可用的苹果并返回`17`，无需遍历树的不相关分支。
