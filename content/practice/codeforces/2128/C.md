 ## 解决方案
 ## 问题理解

 我们从一个长度的数组开始`n`，用零填充。 运算选择一个正整数`x`它严格大于数组中当前的最小值。 

该操作不允许我们选择哪个位置接收增量。 相反，它会自动查找其值仍然低于的最左边的索引`x`。 该职位收到`+x`。 

问题是给定的目标数组是否`b`可以在任意数量的此类操作之后从全零数组生成。 

输入包含许多测试用例。 在所有测试用例中，数组元素的总数最多为 200,000。 每个测试用例的任何比线性或接近线性慢的解决方案都会有风险。 二次算法大约需要$4 \cdot 10^{10}$在最坏的情况下进行操作，这是完全不可行的。 目标是一个$O(n)$或者$O(n \log n)$解决方案。 

有几种情况很容易误判。 

考虑：```
3
3 1 2
```正确答案是`NO`。 

一个常见的错误是只考虑每个元素是否可以表示为正增量之和。 这始终是事实。 困难来自于最左边位置规则，它施加了很强的排序约束。 

另一个棘手的情况是：```
2
1 1
```答案是`YES`。 

粗心的论证可能会声称每个增量必须大于当前最小值，并且由于第一个元素变为正数，因此不可能到达第二个位置。 实际上，在使第一个元素等于`1`，数组的最小值仍然是`0`，所以我们可以选择`x = 1`再次更新第二个元素。 

另一个有用的例子是：```
3
40 60 90
```答案是`NO`。 

虽然每一个数值都很大，但是第三个位置却无法积累足够的数值。 较早的位置对可能到达较晚位置的增量大小施加了上限。 

理解这个界限是关键的观察结果。 

## 方法

 暴力视图会尝试模拟所有可能的操作序列。 在每一步我们可以选择许多不同的值`x`，并且可达状态的数量呈爆炸式增长。 即使对于非常小的数组，搜索树也会变得巨大。 没有现实的方法可以枚举所有可能性。 

要找到结构，请专注于单一位置`i`。 

假设我们正在尝试构建`b[i]`。 到达位置的任何增量`i`必须满足两个条件。 

首先，它不能大于每个较早的元素。 否则位置`i`不会是下面最左边的值`x`。 如果尺寸增加`x`到达位置`i`，然后之前的每个位置`i`必须已经至少是`x`。 

二、什么时候定位`i`接收其第一个增量，其当前值为`0`。 由于增量本身是`x`，第一个增量永远不能超过最终目标`b[i]`。 

结合这些事实，每个增量都应用于位置`i`最多有尺寸$$\min(b_1,b_2,\ldots,b_{i-1}).$$让$$m_i=\min(b_1,\ldots,b_{i-1}).$$如果`b[i] > m_i`，那么唯一的方法就是到达`b[i]`是针对位置的第一个增量`i`确切地说`b[i]`。 任何较小增量的总和最多可达`m_i`。 

这意味着我们必须能够应用大小增量`b[i]`直接到位置`i`。 为此，每个较早的位置必须至少已经`b[i]`。 由于它们的最终值恰好是`b[1],...,b[i-1]`，这需要$$b[i] \le m_i.$$如果`b[i] > m_i`，达到`b[i]`是不可能的。 

相反，如果$$b[i] \le m_i$$对于第一个位置之后的每个位置都成立，那么构造总是可能的。 我们可以简单地给出位置`i`尺寸的单个增量`b[i]`一旦所有先前的位置都达到其最终值。 

整个问题简化为检查每个元素是否至多是所有早期元素的最小值。

 ## 算法演练

 1.读取目标数组`b`。 
2. 初始化`pref_min = b[0]`。 

这存储了迄今为止看到的所有元素中的最小值。 
3.从index开始从左到右处理位置`1`。 
4. 对于当前值`b[i]`，检查是否$$b[i] \le pref\_min.$$到达该位置的任何增量永远不能超过先前位置的最小最终值。 
5. 如果`b[i] > pref_min`，立即回答`NO`。 

位置`i`需要的增量大于先前位置可以支持的增量。 
6.否则更新$$pref\_min = \min(pref\_min, b[i]).$$这保持了所有已处理元素中的最小值。 
7. 如果每个位置都通过了检查，请回答`YES`。 

### 为什么它有效

 对于任何职位`i > 1`，到达它的每个增量必须不大于每个较早位置的最终值。 因此，每个这样的增量最多是$$m_i=\min(b_1,\ldots,b_{i-1}).$$如果`b[i] > m_i`，不允许的增量序列不能产生`b[i]`，因为第一个增量已经不能超过`m_i`。 

如果`b[i] \le m_i`，我们可以等到职位`1..i-1`已达到目标，然后应用单个大小增量`b[i]`定位`i`。 由于所有较早的位置至少`b[i]`，操作有效并立即完成该位置。 

因此，当第一个元素之后的每个元素不超过所有先前元素的最小值时，目标数组就可以到达。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

        pref_min = b[0]
        ok = True

        for i in range(1, n):
            if b[i] > pref_min:
                ok = False
                break
            pref_min = min(pref_min, b[i])

        ans.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(ans))

solve()
```该解决方案保持当前位置左侧所有元素中的最小值。 

加工时`b[i]`，变量`pref_min`正是$$\min(b_1,\ldots,b_{i-1}).$$可达性条件很简单`b[i] <= pref_min`。 如果条件失败一次，则后续处理无法修复它，因此我们可能会立即停止该测试用例。 

所有值都适合 32 位整数，但 Python 整数会自动处理它们。 该算法仅使用少数变量，无论`n`，因此内存使用量是恒定的。

 ## 边缘情况

 考虑：```
1
3
3 1 2
```该算法处理：

 | 位置 | 价值| 最小前缀 |
 | ---| ---| ---|
 | 1 | 3 | - |
 | 2 | 1 | 3 |
 | 3 | 2 | 1 |

 在位置 3，我们有`2 > 1`，所以答案是`NO`。 

位置 2 仅结束于`1`，意味着增量不大于`1`可以达到位置3.目标值`2`是遥不可及的。 

考虑：```
1
2
1 1
```扫描看到`1 <= 1`，所以答案是`YES`。 

如果一个人写出严格的不等式，那么平等的情况很容易处理不当。 条件是`<=`， 不是`<`。 

考虑：```
1
3
40 60 90
```该算法在位置 2 处立即停止，因为`60 > 40`。 

尽管值很大，但大小本身是无关紧要的。 重要的是每个元素是否超过最小的较早值。 一旦仓位大于该最小值，操作规则就会阻止创建该仓位。
