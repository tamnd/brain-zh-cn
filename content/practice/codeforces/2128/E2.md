 ## 解决方案
 ## 问题理解

 我们被要求识别数组中的子中位数。 更具体地说，对于数组范围中的每个整数$1$到$n$，我们要确定是否存在至少长度为的连续子数组$k$使得该整数是该子数组的中值。 中位数是将数组分成两半的元素：至少一半元素不大于，至少一半不小于。 对于偶数长度的数组，多个整数可以满足这个条件。 我们还需要提供任意一个以整数为中位数的子数组。 

输入由多个测试用例组成。 每个案例都有一个最多包含 300,000 个元素的数组，以及所有元素的总和$n$所有测试用例也高达300,000个。 时间限制为 3 秒，我们大致可以承受$O(n)$每个测试用例，或者$O(n \log n)$如果对数因子不太重的话。 二次方法立即不切实际，因为$n^2$可以达到$9 \times 10^{10}$。 

一种朴素的暴力方法将至少考虑所有长度的子数组$k$并计算它们的中位数。 这原则上是正确的，但需要$\Omega(n^2)$对于单个数组的操作，这太慢了。 不正确处理偶数长度子数组的粗心实现会错误识别多个中位数。 例如，在数组中$[1,2,3,2,1]$和$k=3$，子数组$[2,3,2]$有中位数$2$，但是仅查看中间元素的天真检查可能会错误地声明$3$。 

## 方法

 暴力法至少枚举所有长度的子数组$k$，对每个子数组进行排序，并计算所有中位数。 对长度的子数组进行排序$m$成本$O(m \log m)$，所以这种方法是$O(n^3 \log n)$在最坏的情况下——太慢了。 

关键的见解来自中位数的属性：整数$v$是子数组的中位数，如果当我们将数组转换为 +1 且元素 ≥$v$元素 < 则为 -1$v$，存在长度≥的连续线段$k$其总和为非负数。 这个数额反映了$v$它一侧的元件数量至少与另一侧的元件数量相同。 通过这种转换，问题简化为寻找长度≥的子数组$k$具有非负和，这可以在具有前缀和和运行最小值的线性时间内完成。 

而不是检查每个潜在的中位数$O(n)$分别时间，我们迭代从 1 到$n$，对于每个，我们使用前缀和技巧。 一旦找到有效的子数组，我们也可以停止搜索，保证每个子中值仅报告一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3 log n) | O(n3 log n) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个候选整数$v$从 1 到$n$，创建一个转换后的数组，其中每个元素都是+1，如果$a[i] ≥ v$否则为-1。 该变换编码是否$v$将支配子数组。 
2. 计算该变换后的数组的前缀和数组。 让$pref[i]$是第一个的总和$i$元素。 
3. 维护到position为止的最小前缀和$i - k$。 对于每个索引$i ≥ k$，检查是否$pref[i] - min\_prefix ≥ 0$。 这表明存在一个以$i$至少长度$k$在哪里$v$是一个中位数。 
4. 如果找到这样的索引，记录$v$作为子中位数并存储子数组索引$[l,r]$使用最小前缀和的位置。 
5. 继续处理下一个候选整数。 每个整数都是独立处理的，我们只需要每个整数的第一个有效子数组。 

为什么它有效：转换后的数组编码了主导权$v$+1/-1。 子数组和 ≥ 0 确保$v$至少与较小元素一样频繁，这正是成为中位数的条件。 具有运行最小值的前缀和技巧使我们能够有效地检查长度 ≥ 的所有子数组$k$在线性时间内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        result = []

        for v in range(1, n+1):
            transformed = [1 if x >= v else -1 for x in a]
            pref = [0]*(n+1)
            for i in range(n):
                pref[i+1] = pref[i] + transformed[i]

            min_pref = 0
            left_index = 0
            found = False
            for r in range(k, n+1):
                min_pref = min(min_pref, pref[r - k])
                if pref[r] - min_pref >= 0:
                    # find l corresponding to min_pref
                    for l_candidate in range(r - k + 1):
                        if pref[l_candidate] == min_pref:
                            result.append((v, l_candidate + 1, r))
                            found = True
                            break
                    if found:
                        break

        print(len(result))
        for v, l, r in result:
            print(v, l, r)

if __name__ == "__main__":
    solve()
```代码首先读取多个测试用例。 对于每个候选整数$v$，它转换数组并计算前缀和。 到位置的最小前缀和$i-k$帮助检测子数组$v$是一个中位数。 一旦找到有效的子数组，就会记录它并处理下一个候选整数。 

边界条件处理得很仔细：前缀和数组有长度$n+1$并且索引与从 1 开始的输出一致。 寻找$l$是线性的，但仅直到找到第一个有效子数组为止，因此整体复杂性仍然有效。 

## 工作示例

 考虑数组`[4, 1, 2, 4]`和`k=3`。 改造为`v=2`给出`[1, -1, 1, 1]`, 前缀和`[0,1,0,1,2]`。 索引的最小前缀`3`是`0`。 自从`pref[3] - min_pref = 1 >= 0`, 一个子数组`[1,3]`作品。 为了`v=4`，变换后的数组是`[1, -1, -1, 1]`, 前缀和`[0,1,0,-1,0]`。 指数`4`给出`pref[4]-min_pref = 0 - (-1) = 1 >= 0`，所以子数组`[2,4]`作品。 

| r | 首选项[r] | 最小偏好 | pref[r]-min_pref | 找到子数组了吗？ |
 | ---| ---| ---| ---| ---|
 | 3 | 1 | 0 | 1 | 是的 [1,3] |
 | 4 | 2 | 0 | 2 | 是的 [1,4] |

 这表明该算法正确识别了其中的子数组`v`是一个中位数，包括处理多个中位数。
