 ## 解决方案
 ## 问题理解

 我们给定一个数组和一个长度约束$k$。 从这个数组中，我们要选择至少一个连续的长度段$k$。 在任何选定的细分中，我们从广义上看待它的中位数：一个值$v$如果至少有一半的元素是，则被视为中位数$\ge v$并且至少有一半是$\le v$。 此定义允许偶数长度段有多个有效中位数。 

一个值$v$如果存在一些有效段（长度至少$k$） 在哪里$v$是中位数之一。 在所有这些值中，我们想要最大可能的值$v$，我们还需要输出任何使其有效的段。 

关键的困难不是计算固定段的中位数，而是判断是否存在某个特定值可以充当中位数的段。 由于我们必须最大化该值，因此该结构表明了值的单调可行性条件。 

约束很大：所有测试用例的数组总长度最多为 300,000。 这立即排除了任何二次甚至$O(n \sqrt{n})$方法。 每个测试用例的任何解决方案都必须接近线性或对数。 

当所有值都相同时，会出现微妙的边缘情况。 在这种情况下，每个段都有效，答案就是数组中的最大值。 另一个不平凡的情况出现在$k = 1$，其中每个元素形成一个有效的段，答案只是最大的数组元素，但逻辑仍然必须正确地生成一个段，并且不会由于中值处理假设而失败。 

更危险的陷阱是假设“中位数 ≥ v”与“至少一半元素≥ v”的含义相同，而没有仔细平衡不等式定义的两边。 对称性很重要，因为偶数长度的线段允许在中值条件下连接。 

## 方法

 直接方法至少尝试每个可能的长度段$k$，计算其中位数集，并检查所有显示为中位数的值。 这在概念上是正确的，但不可行：有$O(n^2)$段，并计算中值条件，即使在$O(1)$或者$O(\log n)$每个段仍然会导致太多的操作。 

关键的见解是确定候选值$v$并将数组转换为二进制序列：将元素标记为$+1$如果$a_i \ge v$， 和$-1$否则。 现在考虑一个片段。 条件是$v$是一个中位数，相当于该变换下具有非负“平衡”的段，这意味着至少有多个元素 ≥$v$作为元素 <$v$当缩放到中值阈值时。 通过对中值定义进行小幅调整，这可以减少到找到至少长度的子数组$k$其总和为非负数。 

这将问题变成了经典的可行性检查：对于固定的$v$，我们想知道是否存在至少长度为$k$转换后的数组中 sum ≥ 0。 这可以使用前缀和和有效起始位置上的滑动最小前缀在线性时间内解决。 

由于可行性是单调的$v$，如果一个值$v$有效，所有较小的值也有效。 这允许二分搜索$v$在$[1, n]$。 每张支票都是$O(n)$，因此总复杂度变为$O(n \log n)$，这就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们通过二分查找最大值来解决这个问题$v$这样就存在有效的段。 

1. 固定候选值$v$并将该数组转换为增益数组，其中每个位置贡献+1，如果$a_i \ge v$，否则为-1。 这编码是否$v$每个位置都受到“支撑”。 
2. 构建前缀和$p[i]$， 在哪里$p[i]$是从启动到索引的总增益$i$。 然后将子数组和计算为前缀和的差。 
3. 对于每个右端点$r \ge k$，我们想要一个左端点$l \le r-k+1$使得子数组和$p[r] - p[l-1]$是非负的。 这相当于在有效起始位置的滑动窗口上找到最小前缀。 
4. 维护索引间的最小前缀值$0 \dots r-k$。 对于每个$r$，我们检查是否$p[r] \ge \min p[l-1]$。 如果是，我们就找到了有效的段。 
5. 如果存在某个段，我们记录其端点并报告其可行性$v$。 
6.二分查找最大值$v$这是可行的，并输出$v$和录制的片段。 

这样做的原因是，转换将中值条件编码为相对于计数的平衡条件$v$。 任何有效段必须有足够的元素 ≥$v$“补偿”以下元素$v$，这正是非负子数组 sum 捕获的内容。 滑动最小值确保我们测试所有有效的段开始而无需重新计算总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(a, k, v):
    n = len(a)
    pref = [0] * (n + 1)
    
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (1 if a[i - 1] >= v else -1)

    min_pref = 0
    min_pos = 0

    for r in range(k, n + 1):
        if pref[r - k] < min_pref:
            min_pref = pref[r - k]
            min_pos = r - k

        if pref[r] - min_pref >= 0:
            l = min_pos + 1
            return True, l, r

    return False, -1, -1

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 1, n
    ans_l, ans_r = 1, k

    while lo <= hi:
        mid = (lo + hi) // 2
        ok, l, r = check(a, k, mid)
        if ok:
            ans_l, ans_r = l, r
            lo = mid + 1
        else:
            hi = mid - 1

    print(hi, ans_l, ans_r)

t = int(input())
for _ in range(t):
    solve()
```该代码将可行性检查与二分搜索分开。 这`check`函数对转换后的数组执行线性扫描，构建前缀和并维护有效起始位置中的最小前缀。 变量`min_pref`追踪迄今为止最好的起点，同时`min_pos`存储它发生的位置，以便我们可以重建该段。 

一个常见的实现陷阱是忘记有效的左端点依赖于$k$，这意味着我们只允许启动$r-k$。 另一个微妙的问题是在发现可行性后立即返回该片段； 这很好，因为二分搜索只需要存在，而不需要段的最优性。

```我们测试候选值$v = 3$。 变换后的数组变为：$$[-1, -1, +1, -1, -1]$$前缀和：

 | ---| ---|
 | 0 | 0 |
 | 1 | -1 |
 | 2 | -2 |

 我们扫描从$r = 2$。 在$r = 3$，我们比较$pref[3] = -1$有效开头中的最佳前缀。 最好的起始前缀是$pref[1] = -1$。 差值为0，所以分段$[2,3]$作品。 

这表明$v=3$是可行的，尽管它不是处​​处的绝对中位数。 

### 示例 2

 输入：```
n = 4, k = 3

```测试$v = 4$，变换后的数组：$$[+1, -1, -1, +1]$$前缀和：

 | ---| ---|
 | 0 | 0 |
 | 1 | 1 |

 在$r = 4$，我们可以取$l = 1$，因为总和是$0$。 该段$[1,4]$是有效的，确认了最大值的可行性。

 ## 边缘情况

 当$k = 1$，每个元素都是有效段。 该算法仍然有效，因为可行性检查减少为查找其中的任何位置$a_i \ge v$，并且二分查找正确收敛到最大数组元素。 

当所有值都相等时，每个变换都变成+1，因此每个前缀和都是严格递增的。 对于最大值，可行性检查始终成功，算法返回完整段$[1, n]$，因为每个位置都是有效的。 

什么时候$k = n$，仅考虑完整数组。 基于前缀的检查对每个候选者评估整个数组一次$v$，并且由于不存在滑动窗口歧义，因此保留了正确性。
