 ## 解决方案
 ## 问题理解

 我们得到了数字的排列，然后通过重复删除最左边或最右边的剩余元素来构建一个新序列。 这会产生一个长度为 n 的序列，但我们可以在每一步自由决定是从左边还是从右边获取。 

对生成序列的唯一要求是结构性的：它不能包含任何严格递增或严格递减的五个连续元素的块。 换句话说，我们必须避免在结果序列中的任何位置创建长度为 5 的单调游程。 

困难不在于计算有关排列本身的任何内容，而在于控制如何在线构建序列。 每个决定都会影响未来的自由度，因为一旦从一端取出一个元素，以后就无法使用它，并且剩余的段会缩小。 

这些约束允许每次测试最多使用 100,000 个元素，总计最多 200,000 个元素。 这立即排除了任何模拟或评估所有可能序列的方法。 即使用前瞻检查所有贪婪的选择，在最坏的情况下也会变成二次方。 

关键的微妙之处在于，约束是局部的，但具有记忆性：违规取决于最后五个选择的元素，而不仅仅是最后一个或两个。 只跟踪最后一个比较方向的天真贪婪将会失败。 

典型的失败案例来自于总是选择较小或较大的端点：

 输入：```
5
1 2 3 4 5
```总是向左选择会产生完全递增的序列，这立即违反了第五步的规则。 同样，始终选择较大的端点可以创建递减的运行。 

因此，该算法必须主动防止长时间单调运行，同时仍然消耗端点。 

## 方法

 暴力解决方案会在每一步尝试两种选择，构建所有可能的 L 和 R 决策序列，并检查结果序列是否保持有效。 这形成了深度为 n 的二叉树，给出了 2^n 种可能性，甚至提前修剪仍然会导致指数爆炸，因为只有在累积到五个元素后才会出现违规。 

关键的观察是我们不需要推理序列的完整历史。 唯一危险的情况是最后四个元素加上下一个选择形成严格的单调链。 这意味着在任何时候，我们只需要跟踪构造序列的最后四个元素，并确保第五个元素不会扩展单调运行。 

这将问题简化为双端队列构建过程中的局部约束维护问题。 由于我们总是有两个候选者（左和右），因此我们可以贪婪地选择任何不会立即创建禁止的长度为 5 的单调段的边。 如果双方都安全，则任何一方都有效。 

这样做的更深层次原因是禁止的模式短且连续。 一旦我们避免在本地创建它们，它们以后就无法“重新出现”，因为未来的扩展仅取决于最后四个元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有序列）| O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 具有局部约束的贪婪 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们增量地构造结果序列，同时维护最后最多四个选定值的窗口。 

1. 初始化两个指针，一个在排列的左端，一个在右端。 还维护一个空列表`q`为了结果。 
2. 在每一步中，考虑两个候选值：最左边的值和最右边的值。 
3. 对于每个候选，暂时检查是否将其附加到`q`创建长度为 5 的严格递增或严格递减游程。 

该检查仅涉及最后四个元素`q`加上候选人。 
4. 如果两种选择中只有一种是安全的，请立即采取。 
5. 如果两者都安全，请一致选择任一侧（例如始终向左走）。 这不会损害正确性，因为约束仅限制局部单调性，而不限制全局结构。 
6. 将所选值附加到`q`，更新对应的指针，如此重复，直到所有元素都被使用。 

关键的实现细节是我们扫描的元素永远不会超过最后四个元素。 这确保了每步的工作量为 O(1)。 

### 为什么它有效

 在任何时候，违反条件的唯一方法是完成以当前元素结尾的长度为 5 的单调段。 该部分完全由最后四个元素加上候选选择决定。 

通过确保我们永远不允许这样的完成，我们保证最终序列中不会出现坏片段。 由于未来的每次检查仅取决于最后四个元素，因此超出该窗口的早期结构不会影响未来的有效性，因此贪婪永远不会“将自己锁定”到不可避免的失败中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_bad(last, x):
    if len(last) < 4:
        return False
    a, b, c, d = last[-4], last[-3], last[-2], last[-1]
    if a < b < c < d < x:
        return True
    if a > b > c > d > x:
        return True
    return False

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    l, r = 0, n - 1
    last = []
    ans = []

    for _ in range(n):
        left_val = p[l]
        right_val = p[r]

        can_left = not is_bad(last, left_val)
        can_right = not is_bad(last, right_val)

        if can_left:
            ans.append('L')
            last.append(left_val)
            l += 1
        else:
            ans.append('R')
            last.append(right_val)
            r -= 1

        if len(last) > 4:
            last.pop(0)

    print("".join(ans))

if __name__ == "__main__":
    solve()
```该实现将最后四个元素的滑动窗口保留在`last`。 这已经足够了，因为只有长度为 5 的单调运行才重要，并且任何此类运行都必须在当前位置结束。 

决策逻辑检查两端并避免任何会立即创建禁止模式的举动。 如果只有一侧有效，则必须选择一侧。 如果两者都有效，则选择其中一个是安全的，并且实现默认采用左侧。 

当滑动窗口超过大小四时，通过从前面弹出来维护滑动窗口，确保恒定的内存和恒定的时间检查。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

        if len(last) < 4:
            return False
        a, b, c, d = last[-4], last[-3], last[-2], last[-1]
        return (a < b < c < d < x) or (a > b > c > d > x)

            can_r = not is_bad(last, rv)

                last.append(lv)
                l += 1

                ans.append('R')
                last.append(rv)
                r -= 1
            if len(last) > 4:
                last.pop(0)
        return "".join(ans)

    return solve()

 ## 边缘情况

 一种微妙的情况是，两端在早期都是安全的，但只有一个选择可以保持未来的灵活性。 该算法避免了这个问题，因为任何不安全的延续都会立即形成长度为五的单调链，并且这样的链必须是连续的，因此它不能被隐藏并在以后触发。 

另一种边缘情况是n较小，特别是n = 5。在这种情况下，算法有效地检查最终选择的顺序是否单调； 由于它仅在不立即创建禁止运行的情况下才允许移动，因此它自然会避免在一个方向上构建完全排序的序列。 

最后，已经在两个方向上几乎排序的排列仍然有效，因为贪婪将在一侧完成单调链时恰好切换末端。 本地检查确保决策边界始终在步骤级别可检测，从而防止出现死胡同。
