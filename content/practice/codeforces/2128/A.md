 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中都有一组袋子，每个袋子都有一个初始重量。 时间以离散秒为单位进行。 每一秒我们都被迫取出一个剩余的袋子。 取出行李有时是免费的，有时则需要花费硬币，具体取决于其当前重量是否超过阈值。 取出后，所有剩余的袋子重量都会增加一倍。 

关键的困难在于重量会随着时间的推移而增加，因此早期取出的便宜包可能会在以后变得昂贵。 我们不是选择是否移除行李，而是选择何时移除每个行李，而时间决定了我们是否付费。 

输入规模较小：每个测试用例最多 30 个袋子，最多 1000 个测试用例。 这立即排除了任何排列上的指数调度。 解决方案可以提供诸如排序、贪婪决策或每个测试用例的 O(n²) 模拟之类的功能，但不能提供随时间变化的子集上的阶乘或状态 DP。 

当所有值都已高于阈值时，就会出现微妙的边缘情况。 在这种情况下，无论顺序如何，每次移除的成本都是 1，因此答案就是 n。 相反的极端是当所有值长时间保持在阈值以下时，此时排序非常重要。 例如，如果延迟，一个小包可能会变大，因此不考虑时间的天真“先删除最大的”或“先删除最小的”都可能会失败。 

## 方法

 暴力方法会尝试所有可能的移除袋子的命令。 因为有 n! 排列，并且每个删除序列需要模拟最多 n 个步骤的权重更新，即使 n = 30，这也完全不可行。在最坏的情况下，总操作将超过 10^32。 

关键的观察结果是，每个袋子的最终成本仅取决于其被移除的时间步长。 如果一个包在时间 t（从 0 开始）被移除，它的重量就是它的初始值乘以 2^t。 所以我们只需要知道是否可以为每个包分配一个唯一的时隙，使得尽可能多的包满足条件a_i * 2^t ≤ c。 

重写这个条件，我们得到一个时间约束：每个包都有一个可以免费移除的最晚时间。 如果我们将截止日期 d_i 定义为最大 t，使得 a_i * 2^t ≤ c，那么每个包就成为必须在不同时间段 0 到 n-1 进行调度的作业。 任何指定时间超过截止时间的行李都会产生费用 1。 

这是一个经典的调度问题：最大化在截止日期之前完成的作业数量。 最优策略是贪婪的。 我们对截止日期进行排序，并为每个行李分配最早的空闲时段。 任何无法放入有效槽位的行李都必须付费。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（排列）| O(n!·n) | O(n!·n) | O(n) | 太慢了 |
 | 最优贪心调度 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个行李，计算其在变得太大而无法免费移除之前可以停留多长时间。 

这是保持 ≤ c 时允许的最大加倍次数。 我们在概念上重复加倍，计算在超过 c 之前可以乘以 2 的次数。 这定义了每个行李的截止日期。 
2. 将每个包转换为截止时间 t_i，这意味着只有在时间 ≤ t_i 时才能免费移除。 
3. 按升序对所有截止日期进行排序。 

分类确保我们首先优先考虑限制性最强的行李，因为它们的安全移除窗口最小。 
4. 浏览已排序的截止日期，同时维护指向当前时间段的指针。

开始时间为 0。 
5.对于每个deadline，如果当前时间≤deadline，则将包分配到该时间并增加时间。 否则，我们无法将其放入空闲槽中，因此必须稍后以成本 1 将其删除。 
6. 未分配行李的数量就是答案。 

### 为什么它有效

 每个袋子独立定义最大允许移除时间，零成本。 我们有效地将项目与整数时间段匹配。 任何最小化成本的分配都相当于最大化在允许的间隔内容纳的行李数量。 按最早的截止日期排序可确保我们不会在稍后放置的袋子上浪费宝贵的时间，从而保留了更严格限制的可行性。 这种贪婪的选择保持了不变性，即在每一步中我们都使用尽可能少的时隙数，同时保持所有分配有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))

        deadlines = []

        for x in a:
            if x > c:
                deadlines.append(-1)
                continue

            tlim = 0
            val = x
            while val <= c:
                val *= 2
                tlim += 1

            deadlines.append(tlim - 1)

        free_slots = sorted(deadlines)
        time = 0
        paid = 0

        for d in free_slots:
            if d >= time:
                time += 1
            else:
                paid += 1

        print(paid)

if __name__ == "__main__":
    solve()
```实现的核心是将每个权重转换为期限。 我们明确地模拟加倍，直到超过 c，这是安全的，因为值呈指数增长并且 n 很小，因此该循环以大约 30 次迭代为界限。 

我们将任何大于 c 的初始值视为截止日期为 -1，这意味着它永远不能免费删除。 除非非常早地匹配，否则这些都会自动计为已付款，贪婪循环自然会处理这种情况。 

最后，排序和贪婪地分配时隙可确保我们最大化免费移除。

 ## 边缘情况

 当每个元素都已经高于阈值时，所有截止日期都变为-1。 该算法仍然有效，因为每个元素都被立即强制放入付费桶中，并且不会创建虚假排序优势，因为只有在发生有效分配时时间才会增加。 

当所有元素都很小时，截止日期就会很大并且不断增加。 排序可确保它们全部按顺序分配而不会发生冲突，因此无需支付硬币。 

当值紧密聚集在阈值附近时，某些包仅在加倍一两次后就变得无效。 按截止日期排序可确保首先处理那些脆弱的案例，防止它们被推到稍后的时间，从而错误地获得报酬。
