 ## 解决方案
 ## 问题理解

 我们有一面矩形墙，分为瓷砖。 有些位置包含灯且无法涂漆。 每个其他位置必须收到以下之一`k`颜色。 

限制是局部的：取任何水平或垂直连续的瓷砖，其边界是墙壁边缘或两侧的灯。 在这样的作品中，每块彩绘瓷砖都必须具有不同的颜色。 换句话说，颜色不能在任何不间断的行段或列段内重复。 

任务是确定这种颜色是否存在。 如果是这样，我们需要打印一种有效的颜色，并将灯的位置保持为`0`。 

墙的尺寸最多为`100 × 100`，所有测试用例的单元总数最多为`100000`。 这排除了重复尝试所有颜色分配的算法。 可能的颜色数量是巨大的，所以我们需要直接构造。 小网格尺寸允许对细胞进行线性或近线性扫描。 

主要的边缘情况来自于灯创建的段。 当一个段长于可用颜色的数量时，适用于整个矩形的着色可能会失败，并且仅检查整行或整列是不够的。 

例如：```
1
5 1 3
1
1
1
1
1
```有一个长度为一列的段`5`，但仅`3`颜色存在。 正确的输出是：```
NO
```粗心的实现可能只查看行数或列数并假设构造始终存在。 

另一个例子：```
1
3 5 3
1 1 0 1 1
1 1 1 1 1
0 1 1 1 1
```最长的水平线段的长度`4`在第二排。 由于仅`3`颜色可用，正确的输出是：```
NO
```这些灯没有帮助，因为整行没有分隔符。 

一个有效的小案例是：```
1
2 4 3
1 1 0 1
1 1 1 0
```段具有最大长度`3`，所以答案是`YES`。 重复的对角图案可以为所有图块着色，而不会在任何段内重复。 

## 方法

 直接的暴力解决方案会将每个图块视为变量并尝试不同的颜色，直到找到有效的分配。 每次尝试后，可以通过扫描每行和每列段来检查条件。 这是正确的，因为它探索了每种可能的颜色，但作业的数量是`k`增加到瓷砖数量。 即使网格很小，其增长也远远超出了可以处理的范围。 

有用的观察来自于观察是什么使得一个片段变得不可能。 一个段包含`L`瓷砖需求`L`不同的颜色，因为其中没有两个位置可以共享一种颜色。 如果最长线段长度大于`k`，不存在任何着色。 

反方向是关键。 如果每个段的长度最多`k`，我们可以使用固定的重复模式。 为每个图块分配颜色`(row + column) mod k + 1`。 水平移动一步会使颜色增加 1，垂直移动一步效果相同。 长度最多为任意连续段`k`接收不同的残基，因此每个水平和垂直段都满足规则。 

灯只是中断这些顺序。 它们不需要颜色，并且在构建过程中被跳过。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k^细胞) | O（细胞）| 太慢了|
 | 最佳| O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 扫描每一行并找出每组连续瓷砖的长度。 如果任何组的长度大于`k`，墙壁无法着色，因为该组需要的颜色已经多于可用的颜色。 
2. 以同样的方式扫描每一列。 垂直线段长于`k`也使得答案变得不可能。 
3. 如果所有段都足够短，则使用以下方法为每个图块着色`(row + column) mod k + 1`。 让每盏灯都保持原样`0`。 
4. 打印构建的网格。 

最终图案起作用的原因是，相邻图块的每次移动都会以一个模数改变颜色`k`。 由于每个不间断的段最多包含`k`瓷砖，在序列环绕之前，任何颜色值都不能出现两次。 

### 为什么它有效

 如果一个段有超过`k`瓷砖，它需要的不仅仅是`k`不同的颜色，所以报告`NO`是不可避免的。 如果每个段的长度最多`k`，考虑任何水平或垂直线段。 其上分配的颜色形成一系列连续值模`k`。 最多有一个序列`k`连续的残基不能包含重复的残基，因此每个片段都满足要求。 由于每个可能的限制段要么是水平的，要么是垂直的，所以整面墙都是有效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m, k = map(int, input().split())
        wall = [list(map(int, input().split())) for _ in range(n)]

        ok = True

        for i in range(n):
            cur = 0
            for j in range(m):
                if wall[i][j] == 1:
                    cur += 1
                    if cur > k:
                        ok = False
                else:
                    cur = 0

        for j in range(m):
            cur = 0
            for i in range(n):
                if wall[i][j] == 1:
                    cur += 1
                    if cur > k:
                        ok = False
                else:
                    cur = 0

        if not ok:
            ans.append("NO")
            continue

        ans.append("YES")
        for i in range(n):
            row = []
            for j in range(m):
                if wall[i][j] == 0:
                    row.append("0")
                else:
                    row.append(str((i + j) % k + 1))
            ans.append(" ".join(row))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```首先存储输入，因为在检查线段长度和产生答案时都需要灯位置。 

行扫描和列扫描保持`cur`，当前不间断瓦片段的长度。 灯会重置该计数器，因为它分隔了两个独立的部分。 那一刻`cur`超过`k`，施工是不可能的。 

着色阶段使用从零开始的坐标。 表达式`(i + j) % k + 1`产生价值`1`到`k`，同时添加`1`避免使用`0`，这是为灯保留的。 小的不需要特殊处理`k`，因为可行性检查已经保证每个段都足够短。 

## 工作示例

 考虑：```
1
2 4 3
1 1 0 1
1 1 1 0
```扫描着色过程为：

 | 步骤| 职位| 行动| 当前检查结果 |
 | --- | --- | --- | --- |
 | 第 0 行 |`1 1 0 1`| 查找长度为 2 和 1 的线段 | 有效|
 | 第 1 行 |`1 1 1 0`| 查找长度为 3 的线段 | 有效|
 | 第 0 列 |`1 1`| 查找长度为 2 的线段 | 有效|
 | 第 1 栏 |`1 1`| 查找长度为 2 的线段 | 有效|
 | 第 2 栏 |`0 1`| 查找长度为 1 的线段 | 有效|
 | 第 3 栏 |`1 0`| 查找长度为 1 的线段 | 有效|
 | 着色|`(i+j)%3+1`| 产生颜色 | 有效|

 输出着色是一种可能的结果：```
YES
1 2 0 1
2 3 1 0
```每个段的最大长度`3`，因此循环模式永远不会在段内重复。 

现在考虑：```
1

1 1 1 1 1
```| 步骤| 职位| 行动| 当前检查结果 |
 | --- | --- | --- | --- |
 | 第 0 行 | 五个连续的瓷砖 | 段长度变为 4，然后变为 5 | 无效|

 该算法在检测到五个图块需要五种不同颜色（而只有三种颜色存在）后停止。

 ## 边缘情况

 对于不可能的列示例：```
1
5 1 3
1
1
1
1
1
```列扫描增加`cur`从`1`到`5`。 当它达到`4`，算法已经知道该段比可用颜色数长。 它输出`NO`无需尝试构建。 

对于由灯分割的行：```
1
1 5 3
1 1 0 1 1
```行扫描看到一段长度`2`，然后灯重置计数器，然后另一段长度`2`。 两者都是有效的，因为每个都只需要两种不同的颜色。 该结构通过相同的全局公式独立分配颜色，并且灯防止两个部分相互作用。 

对于仍然有效的最大可能部分：```
1
1 5 5
1 1 1 1 1
```扫描接受该行，因为它的长度等于`k`。 颜色变成：```
1 2 3 4 5
```没有值重复，因此墙壁的颜色正确。
