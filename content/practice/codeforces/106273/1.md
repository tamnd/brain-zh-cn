 ## 解决方案
 ## 问题理解

 我们得到了一个按整数天索引的温度时间线，其中第 0 天是今天。 输入提供过去 N 天、今天和接下来 N 天观测到的温度的连续序列。 在任意连续两天之间，温度不假定为恒定，而是线性变化，因此端点之间的每个中间实际值被认为在该时间间隔内是可实现的。 

除了这个连续温度函数之外，还有多个广告查询。 每个查询在两个维度上描述一个矩形条件：时间间隔和温度间隔。 如果在给定日期范围内存在至少一个时刻使得该时刻的温度位于给定温度范围内，则满足查询。 

任务是对于每个查询回答这样的时间是否存在。 

关键的困难在于“检查所有时刻”是不可能的，因为温度在整数天之间是连续的。 这将问题转化为线性段的推理：在第 i 天和第 i+1 天之间，温度呈线性变化，因此在每个段上，函数都是完全确定的。 

输入大小最多为 200,001 个温度点和 100,000 个查询。 对所有相关段进行简单的每次查询扫描会太慢，因为每个查询可能跨越整个范围，在最坏的情况下会产生 1010 次操作。 

线性插值产生了微妙的边缘情况。 一个常见的错误是只检查整日温度。 当几天之间达到有效温度范围时，这种情况就会失败。 

例如，假设我们有温度：```
day -1: 10
day 0: 0
day 1: 10
```如果查询询问 [-1, 1] 上的温度是否低于 5，答案是肯定的。 最小值出现在第 0 天，但如果查询改为询问间隔 [-1, 1] 上的温度 1，则即使在所有线段的端点处没有整数点等于 1，它也是正确的。 这说明了为什么段几何形状很重要。 

当间隔完全在一个段内时，会出现另一种失败情况：```
day 0: 0
day 1: 10
query: days [0, 1], temperature [9, 10]
```尽管端点可能不在范围内，但该线在第一天附近就与它相交。 

## 方法

 暴力解决方案独立处理每个查询。 对于查询，我们迭代 [dmin, dmax − 1] 内的每天间隔，并计算每个段上可达到的最低和最高温度。 由于每个段都是线性的，子段上的最小值和最大值出现在端点处，因此检查每个段的端点就足够了。 

然而，如果我们扫描每个查询的所有段，复杂度就会变成 O(NB)，最多需要 1010 次操作，而且速度太慢。 

关键的观察是我们不需要独立检查每个部分。 每个线段都提供一个简单的几何约束：它定义两个已知点之间的一条线。 该问题简化为检查任何线段是否与固定水平条带 [tmin, tmax] 相交。 这相当于询问许多线段中的任何一条是否与平面（时间、温度）中的矩形相交。 

我们不是在每次查询时一一检查段，而是对段进行预处理并支持对温度数组的快速范围最大和最小查询，此外还考虑相邻点之间的交叉行为。 如果任一端点位于带内或线段与温度带交叉，则线段与温度带相交，这可以通过端点比较进行检查。 

这将每个查询减少为检查少量范围极值查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对段的每个查询进行暴力破解 | O(NB) | O(1) | O(1) | 太慢了|
 | 具有最小/最大范围的段预处理（稀疏表或段树）| O((N + B) log N) | O((N + B) log N) | O(N log N) | O(N log N) | 已接受 |

 ## 算法演练

 1. 构建数组`a[i]`对于从 -N 天到 N 天的温度，进行索引，以便 0 对应于第 0 天。这给出了一个静态数组，我们可以通过它有效地查询范围。 
2. 预先计算该数组的范围最小和最大结构。 稀疏表效果很好，因为数组是静态的，我们只需要幂等范围查询。 这使我们能够在 O(1) 内查询任意区间内的最低和最高温度。 
3. 对于每个查询，读取时间间隔 [l, r] 和温度间隔 [tmin, tmax]。 将时间索引转换为数组索引。 
4. 使用稀疏表查询[l,r]上的最低和最高温度。 
5. 如果[minTemp, maxTemp]与[tmin, tmax]的交集非空，则至少有一个整数天满足条件。 然而，仅此还不够，因为有效值可能会在几天之间出现。 
6. 为了处理连续性，还要检查 [l, r] 内的相邻段。 对于每对 (i, i+1)，确定该段是否跨入带 [tmin, tmax]。 如果一个端点位于带的上方而另一个端点位于带的下方或内部，则线段相交。 
7. 如果任一端点位于带内或任何线段发生交叉，则输出“yes”，否则输出“no”。 

### 为什么它有效

 每个单位区间 [i, i+1] 定义一个连续线性函数，因此区间内任何可行的温度值都可以在端点处或通过端点之间的交叉来实现。 通过检查端点包含和相对于区间边界的符号变化来完全捕获线段与值范围相交的条件。 由于 [l, r] 中所有段的并集连续覆盖整个时间范围，因此任何有效时刻的存在等价于至少一个段上的存在，检查详尽地捕获了该段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N = int(input())
arr = list(map(int, input().split()))
B = int(input())

# build sparse table for min/max
n = len(arr)
LOG = (n).bit_length()

st_min = [[0]*n for _ in range(LOG)]
st_max = [[0]*n for _ in range(LOG)]

for i in range(n):
    st_min[0][i] = arr[i]
    st_max[0][i] = arr[i]

j = 1
while (1 << j) <= n:
    length = 1 << j
    half = length >> 1
    for i in range(n - length + 1):
        st_min[j][i] = min(st_min[j-1][i], st_min[j-1][i + half])
        st_max[j][i] = max(st_max[j-1][i], st_max[j-1][i + half])
    j += 1

log = [0] * (n + 1)
for i in range(2, n + 1):
    log[i] = log[i // 2] + 1

def query_min(l, r):
    k = log[r - l + 1]
    return min(st_min[k][l], st_min[k][r - (1 << k) + 1])

def query_max(l, r):
    k = log[r - l + 1]
    return max(st_max[k][l], st_max[k][r - (1 << k) + 1])

out = []

for _ in range(B):
    tmin, tmax, l, r = map(int, input().split())

    cur_min = query_min(l + N, r + N)
    cur_max = query_max(l + N, r + N)

    if cur_max < tmin or cur_min > tmax:
        out.append("no")
    else:
        out.append("yes")

print("\n".join(out))
```该实现以移动索引为中心，使第 -N 天变为索引 0，从而消除负索引复杂性。 稀疏表构建一次，然后重用于所有查询。 每个查询变成两个 O(1) 范围查询。 

一个常见的实现陷阱是忘记出于性能原因，此处未使用 Python 切片。 另一个问题是从日索引转换为数组索引时出现差一错误，因为两个端点都包含在内。

 ## 边缘情况

 关键的边缘情况是当有效温度范围正好在段的端点处达到时。 例如：```
temps: 0 10
query: [0,1], [10,10]
```第 1 天，温度正好为 10，所以答案是肯定的。 该算法捕获了这一点，因为范围最大值等于边界。 

另一种情况是仅在线段中间穿过的狭窄区间：```
temps: 0 10
query: [0,1], [4,6]
```线性插值会遍历 0 到 10 之间的每个值，因此答案是肯定的，即使两个端点都不位于带内。 范围检查确保不会错过这一点，因为最小值/最大值跨越了间隔。
