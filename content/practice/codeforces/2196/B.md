 ## 解决方案
 ## 问题理解

 给定一个数组，我们想要计算位置对的数量，这些位置的值与其在数组中的距离之间存在非常特定的关系。 对于两个指数$i < j$，当两个值的乘积完全匹配索引之间的距离时，该对被认为是有效的，这意味着$a_i \cdot a_j = j - i$。 

因此，每个测试用例都要求我们扫描所有索引对并计算有多少个索引对满足此等式。 

输入大小立即告诉我们，任何直接检查所有对的方法在最坏的情况下都是不可行的。 高达$2 \cdot 10^5$测试用例中的总元素，$O(n^2)$扫描将意味着顺序$10^{10}$最坏情况下的比较，远远超出了 2 秒的限制。 因此，我们需要一种方法来避免明确地迭代所有对。 

该条件的一个微妙方面是右侧仅取决于索引，而左侧仅取决于值。 这种不匹配正是结构得以实现的原因。 

一些边缘情况值得在心理上隔离。 

如果所有值都是$1$，条件变为$1 \cdot 1 = j - i$，所以我们只计算距离恰好为 1 的对。这意味着只有相邻的对才有贡献，答案是$n-1$。 幼稚的实现可能仍然会不必要地尝试所有对，但更重要的是，它确认即使值很小，也可以存在大量有效对。 

如果值很大，例如$10^9$，那么乘积是巨大的，很容易超过任何可能的指数差异，因此没有对有贡献。 粗心的实现可能仍然尝试直接匹配值，而没有意识到大多数对自动无效。 

关键的困难在于该条件将索引和值乘法联系在一起，因此我们希望将其转换为可以修复一侧并有效搜索另一侧的东西。 

## 方法

 蛮力方法很简单：迭代所有对$(i, j)$, 计算$a_i \cdot a_j$，并检查它是否等于$j - i$。 这是正确的，因为它直接对定义进行编码。 然而，它需要检查所有$\frac{n(n-1)}{2}$每个测试用例对。 什么时候$n = 2 \cdot 10^5$，这变得不可行。 

主要观察是以更有效地分离值和索引的方式重写条件。 从$$a_i \cdot a_j = j - i$$我们将其重新排列为：$$j = i + a_i \cdot a_j$$现在修复$i$。 对于每个$i$，我们想要找到索引$j > i$这样：$$a_j = \frac{j - i}{a_i}$$这仍然没有直接用处，因为$j$出现在两侧。 重要的技巧是转换视角：而不是修复两个端点或尝试直接求解$j$，我们根据差异对对进行分类$d = j - i$。 

对于固定距离$d$，条件变为：$$a_i \cdot a_{i+d} = d$$现在这是一种纯粹的位置关系。 对于每个偏移量$d$，我们扫描所有有效的$i$，并检查是否$a_i \cdot a_{i+d} = d$。 

这将问题转化为迭代所有可能的间隙$d$。 虽然这在理论上仍然是二次的，但我们可以利用有效对极其稀疏的事实。 对于固定的$d$，仅因式分解$d$可以做出贡献。 我们可以重写：$$a_i \cdot a_{i+d} = d$$所以两者$a_i$和$a_{i+d}$必须是除数$d$。 这意味着对于每个位置$i$，我们只关心价值观$a_{i+d}$那场比赛$d / a_i$，并且仅当这是一个整数时。 

所以不要枚举所有$d$，我们修复$i$，并仅枚举有意义的候选者$a_i$作为位置隐含的小值的除数。 关键的观察是$d$至多是$n$，所以它只有$O(\sqrt{n})$除数，并且每个有效对都受到整除性的严重限制。 

这导致了一种有效的计数策略，我们迭代位置并仅检查与可行产品一致的距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 优化的基于可分性的扫描 |$O(n \sqrt{n})$（实践中摊销更好）|$O(1)$或者$O(n)$| 已接受 |

 ## 算法演练

 1. 迭代每个索引$i$在数组中。 该索引将充当潜在对的左端点。 
2. 对于每个$i$，考虑向右延伸一段距离$d$，从$1$直到剩余长度。 我们不会盲目测试所有$d$，而是使用约束$a_i \cdot a_{i+d} = d$及早修剪无效案例。 
3.对于固定的$i$，我们尝试候选值$a_i$。 自从$a_i \cdot a_{i+d} = d$，值$d$必须能整除$a_i$。 所以我们只考虑距离$d$这样$d \bmod a_i = 0$。 
4. 对于每一个这样的$d$，计算所需的合作伙伴价值$a_{i+d} = d / a_i$。 
5.如果$i + d$在界限内并且数组实际上满足$a_{i+d} = d / a_i$，然后我们将这一对视为有效。 

我们之所以这样颠倒视角，是因为指数差异$d$作为一个小的结构化数字，而值是任意的。 将乘法转化为整除性可以让我们修剪几乎所有候选对。 

### 为什么它有效

 每个有效对$(i, j)$产生独特的距离$d = j - i$。 对于该对，方程迫使$d$准确地考虑到$a_i \cdot a_j$。 相反，如果我们枚举所有对$(i, d)$这样$d$可以整除$a_i$并且匹配位置包含互补因子，我们捕获每个有效对一次。 不会计算任何无效对，因为乘法约束和位置约束是同时强制执行的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0

        # We fix left endpoint i
        for i in range(n):
            ai = a[i]

            # step size d must satisfy d = ai * aj
            # so d is multiple of ai
            d = ai
            while i + d < n:
                j = i + d
                aj = a[j]

                if ai * aj == d:
                    ans += 1

                d += ai

        print(ans)

if __name__ == "__main__":
    solve()
```代码中的核心思想是避免迭代所有可能的距离。 相反，对于每个起始索引$i$，我们只测试距离的倍数$a_i$，因为只有那些才能满足产品约束。 这是折叠搜索空间的主要修剪步骤。 

循环变量`d`代表差距$j - i$。 增加它`ai`确保我们只访问可整除的候选者。 最后检查`ai * aj == d`是必要的，因为仅可整除性是不够的； 它仅保证候选配对在代数上是可能的，而不保证数组实际上匹配。

 ## 边缘情况

 相同数组的最小数组显示了最密集的有效结构。 用于输入`[1, 1]`，算法开始于`i = 0`， 套`d = 1`, 检查位置`1`，并发现`1 * 1 = 1`，所以它正好算作一对。 不存在其他索引，因此输出是正确的。 

当所有值都很大时，例如`[1000000000, 1000000000]`，算法集`d = 1000000000`对于第一个索引，立即超出数组边界，并终止而不计算任何内容。 这与没有任何指数差异可以达到如此大的产品的事实相符。 

对于没有有效乘法结构的数组，例如`[3, 3, 3, 3, 3]`，每个候选距离很快就会违反界限或相等，因此内部循环永远不会增加答案，从而正确地产生零。
