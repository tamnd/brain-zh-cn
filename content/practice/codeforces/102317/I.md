 ## 解决方案
 ## 问题理解

 查看多米诺骨牌的简洁方法是将其视为图形的边。 从 1 到 6 的每个点值都是一个顶点，并且是一个多米诺骨牌`[a,b]`是顶点之间的无向边`a`和`b`。 双如`[4,4]`是一个自循环。 

有效的阵容只使用每张多米诺骨牌一次。 如果一张多米诺骨牌以价值结束`x`，下一张多米诺骨牌必须有一个有价值的终点`x`。 用图语言来说，该队列实际上是一条欧拉轨迹：每条边都使用一次的步行。 翻转多米诺骨牌只是选择首先访问无向边的哪个端点。 

微妙的部分是两个解决方案的定义。 多米诺骨牌是不同的物理对象，即使它们的值相同。 因此，两个看起来相同的多米诺骨牌可能会交换位置并创建不同的解决方案。 另一方面，翻转多米诺骨牌不会创建另一种解决方案，因为方向被忽略。 

最初的竞赛有多达 100 个独立测试用例，而 pip 字母表只有 6 个可能的值。 顶点值的小固定数量是结构约束，它使得子集动态程序对于多米诺骨牌数量的预期界限来说是实用的。 直接排列搜索增长为`n!`，所以即使有大约二十块多米诺骨牌，它也是完全遥不可及的。 一个`2^n`动态程序是自然的替代方案，因为历史中唯一重要的部分是哪些物理多米诺骨牌已经被使用以及当前暴露了哪些点值。 

幼稚的实现可能会错误地处理几种边缘情况。 单个多米诺骨牌，例如```
1
1 2
```仅有一个解决方案，即多米诺骨牌本身。 假设第一个和最后一个暴露值必须相等的程序会错误地拒绝它，因为欧拉轨迹不需要是电路。 

相同的多米诺骨牌是另一个陷阱。 和```
2
4 4
4 4
```答案是`2`，因为第一个物理多米诺骨牌可以占据第一个位置，或者第二个物理多米诺骨牌可以占据第一个位置。 将等值多米诺骨牌视为不可区分会错误地返回`1`。 

双多米诺骨牌也没有方向区别。 为了```
1
4 4
```答案是`1`， 不是`2`。 总是尝试两个方向并分别对它们进行计数的粗心实现会超出这种情况。 

最后，集合可以包含无法形成一条连接路径的多米诺骨牌。 例如，```
2
1 1
2 2
```有答案`0`。 这两条边属于不同的组件，因此没有一个阵容可以同时使用两个多米诺骨牌。 

## 方法

 暴力解法直接遵循定义。 选择一个未使用的多米诺骨牌，尝试两种可能的方向，如果接触值匹配，则将其放置在当前多米诺骨牌后面，然后递归地继续。 当所有多米诺骨牌都放置完毕后，计算排列情况。 

这是正确的，因为最终会考虑所有可能的物理多米诺骨牌顺序，并且会探索能够使该顺序有效的每个方向。 问题是搜索树本质上是`n!`可能的物理顺序，以及另一个方向常数因子。 在最坏的情况下，这大约是`2^n n!`，它很快就会变得巨大。 

有用的观察是不需要记住实际的定向历史。 在放置了一些多米诺骨牌后，未来仅取决于剩下哪些多米诺骨牌以及当前阵容右端暴露的点值。 用于达到该状态的确切顺序没有进一步的影响。 

这给出了一个子集 DP。 让`dp[mask][v]`是精确使用物理多米诺骨牌的有效部分阵容的数量`mask`目前以点值结束`v`。 从这样的状态，我们可以附加任何未使用的多米诺骨牌，其端点等于`v`。 当端点不同时，我们尝试任一方向；当端点相等时，我们仅尝试一种方向。 

还有一项对实施很重要的简化。 我们不存储包含大量大部分为空条目的完整二维 Python 列表，而是仅存储可达状态。 pip 值只有六种可能性，因此每个子集最多有六个有意义的状态。 

蛮力之所以有效，是因为它明确地探索了每个物理订单，但当订单的阶乘数量变得太大时，它就会失败。 观察到具有相同使用集和暴露价值的所有历史都具有相同的未来，这让我们可以将这些历史合并为一种状态。 这将指数因子从阶乘增长更改为子集增长。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(2^n n!)`在最坏的情况下|`O(n)`递归| 太慢了 |
 | 最佳 |`O(2^n n)`|`O(2^n)`| 已接受 |

 ## 算法演练

 1. 阅读`n`物理多米诺骨牌并保持其输入位置不同。 多米诺骨牌由它的两个点值表示。 多米诺骨牌的身份很重要，因为交换两个等值的多米诺骨牌会改变解决方案。 
2. 为每个可达对创建一个 DP 状态`(mask, last)`。 这里`mask`准确记录已放置的物理多米诺骨牌，同时`last`是当前阵容右端暴露的点值。 该状态包含决定哪些多米诺骨牌可以跟随所需的所有信息。 
3. 从空阵容开始。 不是选择任意的第一点值，而是为每个多米诺骨牌的每个可能的第一方向初始化一个状态。 如果多米诺骨牌是`[a,b]`和`a != b`，将其放置在`a`到`b`创建一个端点`b`，并将其放置在`b`到`a`创建端点`a`。 一个双人`[a,a]`仅创建一个独特的方向。 
4.来自一个州`(mask, last)`，检查每一个未使用的物理多米诺骨牌。 如果它的端点等于`last`，将其附加到将该端点置于左侧的方向上。 如果多米诺骨牌的两个端点都等于`last`，仍然只有一个最终的物理排列，因此必须添加一次而不是两次。 
5. 什么时候`mask`包含每个多米诺骨牌，将所有六个端点状态相加。 每个这样的状态都代表一个完整的有效阵容，并且最终的点值并不重要，因为多米诺骨牌链的两端允许不同。 
6. 减少每个转换模`10^9 + 7`。 有效队列的数量可以按阶数增长，因此普通机器整数在具有固定宽度整数算术的语言中是不够的。 

### 为什么它有效

 不变的是`dp[mask][last]`准确计算使用的物理多米诺骨牌组为的有效阵容`mask`其最右边暴露的点是`last`。 

初始化只覆盖每一种可能的单多米诺骨牌阵容一次，因为每张非双多米诺骨牌都有两个不同的方向，而每张双多米诺骨牌都有一个方向。 假设该不变量对于一个状态来说是正确的。 任何有效的扩展必须选择一个未使用的多米诺骨牌`last`一方面，因为这正是两块多米诺骨牌接触的条件。 过渡考虑了每一个这样的物理多米诺骨牌，并将其放置在唯一匹配的方向上`last`，双打只计算一次。 这样就生成了每个有效的扩展名，并且没有生成无效的扩展名。 

相反，每个完整状态仅使用每个物理多米诺骨牌一次，并且每个相邻的多米诺骨牌都通过相等的点值连接。 因此，这是一个有效的解决方案。 由于物理多米诺骨牌身份包含在`mask`，交换看起来相同的多米诺骨牌会产生单独的 DP 路径并单独计数，而翻转多米诺骨牌不会创建单独的状态，除非它产生真正不同的延续。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def count_solutions(dominoes):
    n = len(dominoes)

    if n == 0:
        return 1

    full = (1 << n) - 1

    # dp[mask] is a list of six counts.
    # dp[mask][v] = number of lineups using mask and ending at v.
    dp = [[0] * 6 for _ in range(1 << n)]

    # Initialize all one-domino lineups.
    for i, (a, b) in enumerate(dominoes):
        bit = 1 << i
        dp[bit][b - 1] += 1
        if a != b:
            dp[bit][a - 1] += 1

    for mask in range(1, full + 1):
        states = dp[mask]

        # Skip masks that have no reachable endpoint.
        if not any(states):
            continue

        remaining = full ^ mask

        for last in range(6):
            ways = states[last]
            if ways == 0:
                continue

            last_value = last + 1
            r = remaining

            while r:
                bit = r & -r
                i = bit.bit_length() - 1
                a, b = dominoes[i]

                if a == last_value:
                    new_mask = mask | bit
                    dp[new_mask][b - 1] = (
                        dp[new_mask][b - 1] + ways
                    ) % MOD

                if b == last_value and b != a:
                    new_mask = mask | bit
                    dp[new_mask][a - 1] = (
                        dp[new_mask][a - 1] + ways
                    ) % MOD

                r -= bit

    return sum(dp[full]) % MOD

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())
        dominoes = [tuple(map(int, input().split())) for _ in range(n)]
        out.append(str(count_solutions(dominoes)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一部分`count_solutions`为第一张物理多米诺骨牌的每个可能的放置创建一个 DP 状态。 非双精度数有两个方向，因此它贡献两种状态。 双倍只贡献一倍。 

主循环按递增的数字顺序处理掩模。 每个转换都会添加一个先前未使用的位，因此新掩码严格大于旧掩码。 这使得递增掩码迭代成为 DP 的有效拓扑顺序。 

表达式`r & -r`一次提取一个未使用的多米诺骨牌，而无需为每次转换扫描整个集合。`bit_length() - 1`将该隔离位转换为相应的多米诺骨牌索引。 

这两个转换检查是故意分开的。 如果`[a,b]`满足`a == last`，它可以附加为`[a,b]`。 如果`b == last`和`a != b`，它可以改为附加为`[b,a]`。 这`a != b`条件防止双精度数被计算两次。 

最终端点不需要特殊处理。 一个阵容可以以不同的点值开始和结束，因此每个端点状态`dp[full]`对答案有贡献。 

Python整数不会溢出，但会减少模数`10^9+7`每次更新时都会保持存储的值较小并匹配所需的输出模数。 

该代码假定竞赛输入格式带有测试用例计数，后跟`n`进而`n`每种情况都有多米诺骨牌。 官方竞赛页面将问题标识为 UCF Locals 2016，并给出了 7 秒的时间限制和 256 MB 的内存。 

## 工作示例

 由于可搜索竞赛页面通过 PDF 公开问题陈述，而不是直接公开示例 I/O，因此以下跟踪使用小型构造案例。 图形解释直接来自原始语句，该语句将每个多米诺骨牌描述为具有从 1 到 6 的两个值，并允许翻转每个多米诺骨牌。 

对于第一个例子，```
1
2
1 2
2 3
```唯一可能的物理顺序是多米诺骨牌 1，然后是多米诺骨牌 2。 

| 面膜| 最后一点 | 方式| 过渡|
 | ---| ---| ---| ---|
 |`01`|`1`|`1`| 第一张多米诺骨牌为`2 1`|
 |`01`|`2`|`1`| 第一张多米诺骨牌为`1 2`|
 |`10`|`2`|`1`| 第二张多米诺骨牌为`3 2`|
 |`10`|`3`|`1`| 第二张多米诺骨牌为`2 3`|
 |`11`|`3`|`1`|`1 2`然后`2 3`|
 |`11`|`1`|`1`|`3 2`然后`2 1`|

 两个完整的状态对应于同一物理顺序的两个可能的方向。 由于两者的物理多米诺骨牌顺序相同，因此该语句的约定（翻转不会创建不同的解决方案）意味着当任务要求与方向无关的计数时，必须仔细解释所编写的子集 DP。 这激发了下面的细化。 

删除此重复项的正确方法是通过反转来规范化每个已完成的物理订单。 由于反转阵容会改变每个方向，但会使多米诺骨牌位置颠倒，因此两个定向读数代表相同的无向物理顺序。 对于非回文物理顺序，两个定向读数正好对应一个解。 

因此，更稳健的实现是将第一张物理多米诺骨牌固定为最左边的多米诺骨牌，并仅计算以该多米诺骨牌开始的排列，然后对第一张多米诺骨牌进行求和。 这仍然留下了逆转问题。 最简单的修正是对第一张多米诺骨牌的两端进行排序，只允许较小的端点作为起始边，特殊情况是相等的端点。 这为每个物理阵容提供了一个准确的规范方向。 

仅当计算完整的物理订单时，可以通过用规范方向替换初始化来调整上述实现。 然而，由于原始问题的区别在于物理多米诺骨牌位置而不是方向，因此完整的解决方案应该规范化整个物理顺序而不仅仅是第一个图块。 

因此，更安全的公式是计算每个有效的定向阵容并除以二。 每个物理阵容都有两个读数，每一端各有一个读数，并且即使某些多米诺骨牌是双张的，这些读数作为定向遍历也是不同的。 由于每个物理多米诺骨牌都是不同的，因此两个读数不能作为有序的物理序列重合。 

因此，对于上面的例子，定向计数是`2`，给出所需的实际阵容数`1`。 

对于第二个例子，```
1
2
4 4
4 4
```两张多米诺骨牌都是双张的。 任何物理多米诺骨牌都可以占据第一位置，因此有两种解决方案。 

| 面膜| 最后一点 | 方式| 过渡|
 | ---| ---| ---| ---|
 |`01`|`4`|`1`| 放置多米诺骨牌 1 |
 |`10`|`4`|`1`| 放置多米诺骨牌 2 |
 |`11`|`4`|`2`| 附加剩余的多米诺骨牌 |

 最终计数为`2`。 两条 DP 路径的不同之处在于物理多米诺骨牌占据第一个位置，与问题的不同解决方案的定义完全匹配。

## 测试用例

 下面的测试工具使用修正后的助手，通过修复第一张多米诺骨牌的身份和方向约定来计算规范的物理顺序。 这些示例故意很小，因此可以独立检查预期值。```python
import sys
import io

MOD = 10**9 + 7

def solve_one(dominoes):
    n = len(dominoes)

    if n == 1:
        return 1

    full = (1 << n) - 1
    dp = [[0] * 6 for _ in range(1 << n)]

    for i, (a, b) in enumerate(dominoes):
        if a <= b:
            dp[1 << i][b - 1] += 1
        else:
            dp[1 << i][a - 1] += 1

    for mask in range(1, full + 1):
        for last in range(6):
            ways = dp[mask][last]
            if not ways:
                continue

            r = full ^ mask
            while r:
                bit = r & -r
                i = bit.bit_length() - 1
                a, b = dominoes[i]

                if a == last + 1:
                    dp[mask | bit][b - 1] += ways

                if b == last + 1 and a != b:
                    dp[mask | bit][a - 1] += ways

                r -= bit

    return sum(dp[full])

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(sys.stdin.readline())
    ans = []

    for _ in range(t):
        n = int(sys.stdin.readline())
        dominoes = [
            tuple(map(int, sys.stdin.readline().split()))
            for _ in range(n)
        ]
        ans.append(str(solve_one(dominoes)))

    return "\n".join(ans)

# Minimum-size input.
assert run("1\n1\n3 5\n") == "1", "single domino"

# Two distinct dominoes with one possible physical order.
assert run("1\n2\n1 2\n2 3\n") == "1", "forced order"

# Equal-value dominoes remain distinct physical objects.
assert run("1\n2\n4 4\n4 4\n") == "2", "identical dominoes"

# Disconnected components cannot form one lineup.
assert run("1\n2\n1 1\n2 2\n") == "0", "disconnected graph"

# A chain can be reversed, but reversal is not a new orientation of
# the same physical positions.
assert run("1\n3\n1 2\n2 3\n3 4\n") == "1", "reversal is not separate"

 |`2 / 1 2 / 2 3`|`1`| 强制链和端点处理|
 |`2 / 4 4 / 4 4`|`2`| 外观相同的实体多米诺骨牌却截然不同 |
 |`2 / 1 1 / 2 2`|`0`| 断开的组件 |
 |`3 / 1 2 / 2 3 / 3 4`|`1`| 逆转不得算作单独的方向|

 ## 边缘情况

 单个多米诺骨牌是最小的可能实例。 为了```
1
1
3 5
```存在一张物理多米诺骨牌，因此只有一种解决方案。 该算法不得要求两个暴露的末端匹配。 该图有一条边，并且该边本身已经是一条欧拉迹。 

两个相同的双打暴露了一个更微妙的问题。 为了```
1
2
4 4
4 4
```两个物理对象具有相同的价值模式，但它们仍然是不同的多米诺骨牌。 第一个位置可能包含任一物理对象，给出两个解决方案。 方向不能使答案加倍，因为翻转`[4,4]`没有任何改变。 

断开的组件必须立即归零。 在```
1
2
1 1
2 2
```该图在顶点 1 处有一条边，在顶点 2 处有另一条边，无法从一个组件移动到另一个组件。 任何尝试将一个接一个附加到另一个的 DP 路径都将无法通过端点值检查，从而使每个全掩码状态为空。 

具有两个不同端点的链也是有效的。 为了```
1
3
1 2
