 ## 解决方案
 ## 问题理解

 我们有多项保护任务。 在一次任务中，一系列已知的爆能枪会在指定时间到达绝地。 有一两个绝地武士保护资产，每个绝地武士都有自己的反应时间。 绝地武士总能挡住分配给他的第一枪。 一次封盖后`t`，同一个绝地武士在时间到来之前无法阻挡另一次射击`t + reaction_time`。 

拍摄时间可以按任意顺序给出，因此第一步是按时间顺序对它们进行排序。 对于每一次射击，我们都想决定哪个绝地武士能够阻挡它（如果有的话）。 所需的输出是到达受保护资产的最小可能射击数量。 官方竞赛声明给出了每个任务最多 1000 次射击、一到两个绝地武士以及从 1 到 100 的反应时间。 

1000 次射击的小范围意味着即使是二次算法对于单个任务来说也是实用的，但问题的实际结构使我们能够做得更好。 对每个可能的任务进行强力搜索，每个镜头都会有三个选择，所以最坏的情况是`3^b`作业。 和`b = 1000`，这远远超出了任何比赛时间限制所能承受的范围。 有用的解决方案应该在排序后处理镜头，并且只对每个镜头进行恒定的工作。 

在几种边缘情况下，实现可能会默默地出错。 首先，相同的射击时间是不同的射击，不同的绝地武士可能会阻挡完全相同时间到达的不同射击。 例如，与```
1
2
5 5
2
1 10
```两名绝地武士都可以在时间 5 时挡住两枪中的一枪，所以答案是`0`。 删除重复时间的粗心实现会错误地报告`1`。 

第二个边缘情况是，当两者都可用时，绝地武士不必使​​用相同的策略。 考虑```
1
3
1 2 3
2
2 100
```反应时间为2的绝地武士可以挡住所有三枪，所以答案是`0`。 仅仅因为 Jedi 也可用而将第一个镜头分配给较慢的 Jedi 的实现仍然会碰巧在此输入上工作，但选择在更仔细构建的序列中很重要。 正确的规则是，只要两者都可用，就优先选择反应时间较短的绝地武士。 

第三种边界情况发生在绝地武士准备好时射击正好到达。 例如，```
1
3
1 3 5
1
2
```三个投篮都可以被封盖，因为一次投篮`3`一次射击后允许`1`，以及当时的镜头`5`时间过后同样允许`3`。 使用`>`而不是`>=`当检查可用性时，会错误地让射门畅通无阻。 

## 方法

 直接的暴力方法是考虑每个镜头的每个可能的决定。 对镜头进行排序后，每个镜头可以分配给绝地 1、分配给绝地 2，或者允许通过。 我们可以递归地枚举这些可能性，同时保持每个绝地武士阻止最后一枪，拒绝违反反应时间限制的任务。 该方法是正确的，因为每个合法的阻止策略都出现在递归中的某个位置，因此采用错过射击最少的策略给出了最佳结果。 

问题是可能的策略的数量。 和`b`镜头，最多可达`3^b`决策序列。 对于最多 1000 次拍摄，大约为`10^477`，因此即使检查单个策略的成本很低，暴力破解也是无法使用的。 

关键的观察是我们按时间顺序处理镜头。 假设两个绝地武士目前都能同时挡出一枪`t`。 设他们的反应时间为`a <= b`。 如果我们向有反应时间的绝地开枪`a`，绝地武士再次可用`t + a`，而其他绝地武士仍然可以在`t`。 因此，两个未来的可用时间是`{t, t + a}`。 

相反，如果我们给速度较慢的绝地武士机会，那么未来的可用时间就会变成`{t, t + b}`。 自从`a <= b`，第一对对于任何未来的拍摄来说都不会更差。 我们保留了一名绝地武士立即可用的状态，并在不晚于替代任务下的情况下提供另一名绝地武士。 

这给出了贪心规则。 每次射击时，如果只有一名绝地可用，则该绝地必须挡住射击。 如果两者都可用，请使用反应时间较小的绝地武士。 如果两者都不可用，则无法阻止射击并且必须到达资产。 

这种本地选择是安全的原因比简单地说绝地武士越快“越好”更有力。 当两者都空闲时使用较快的绝地武士会产生一个状态，其两个下一个可用时间在组件方面不晚于使用较慢的绝地武士产生的状态。 在较慢的绝地选择之后可以处理的任何未来序列也可以在较快的绝地选择之后处理。 因此，贪婪决策永远不会减少仍可被阻挡的最大射击次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(3^b)`|`O(b)`递归| 太慢了 |
 | 最佳|`O(b log b)`|`O(1)`除了排序| 已接受 |

 ## 算法演练

 1. 读取射击时间并按非降序对它们进行排序。 按时间顺序处理是必要的，因为绝地武士的可用性仅取决于他已经挡出的镜头。 
2. 存储每个绝地下次可以格挡的时间。 最初，这两个值都是负无穷大，或者等效地小于每个可能的射击时间的值，因为每个绝地都可以立即阻止他的第一次射击。 
3. 每次拍摄时间`t`，通过检查他们的下一次可用时间是否最多来确定哪些绝地当前可用`t`。 平等被视为可用，因为绝地武士可能会在他的反应时间结束时准确地阻挡射击。 
4. 如果两个 Jedi 都不可用，则增加到达资产的射击次数。 此镜头没有合法的分配，并且由于镜头是按时间顺序处理的，因此跳过它无法使不可用的绝地更快可用。 
5. 如果只有一名绝地武士可用，则将镜头分配给该绝地武士。 这个选择是被迫的，因为使用不可用的绝地武士会违反反应时间限制。 
6. 如果两个绝地武士都可用，则将射击分配给反应时间较短的绝地武士。 任务完成后，将该绝地武士的下一次可用时间设置为`t + reaction_time`。 
7. 处理完所有镜头后，以所需的任务格式打印无法阻挡的镜头数量。 

不变量是，在处理排序后的镜头序列的每个前缀之后，贪婪策略已经阻止了来自该前缀的最大可能数量的镜头，并且在达到该最大值的策略中，其两个下一个可用时间不比替代策略差。 当两名绝地武士都可用时，使用较快的绝地武士可以完全保留较慢的绝地武士，并使已使用的绝地武士比使用较慢的绝地武士更快准备好。 当只有一个可用时，分配是强制的。 当两者都不可用时，任何策略都无法阻止当前镜头。 这些事实保留了每次射击的不变性，因此最终错过的射击次数是最少的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    missions = int(input())
    out = []

    for mission in range(1, missions + 1):
        b = int(input())
        shots = list(map(int, input().split()))
        shots.sort()

        j = int(input())
        reaction = list(map(int, input().split()))

        # next_available[k] is the earliest time Jedi k can block again.
        # Negative infinity means that Jedi has not blocked anything yet.
        next_available = [-1] * j

        missed = 0

        for t in shots:
            available = [
                k for k in range(j)
                if next_available[k] <= t
            ]

            if not available:
                missed += 1
                continue

            if len(available) == 1:
                k = available[0]
            else:
                # Both are available. Use the Jedi who recovers sooner.
                if reaction[available[0]] <= reaction[available[1]]:
                    k = available[0]
                else:
                    k = available[1]

            next_available[k] = t + reaction[k]

        out.append(f"Mission #{mission}: {missed}")
        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入部分读取任务数量，然后是每个任务的射击次数和次数。 在做出任何调度决策之前对镜头列表进行排序，与算法的第一步相匹配。`next_available[k]`存储 Jedi 的最早时间`k`可能会阻挡另一次射击。 初始值`-1`就足够了，因为每次射击时间都是正数。 绝地武士阻挡射击后`t`，下一个合法时间正好是`t + reaction[k]`。 

名单`available`包含下一个可用时间不大于当前射击时间的 Jedi。 这`<=`比较处理边界情况，即反应间隔恰好在镜头到达时结束。 

当两个绝地武士都可用时，比较他们的反应时间就实现了贪婪交换论点。 如果他们的反应时间相等，则任一选择都是等效的，因此`<=`分支可以安全地选择第一个。 

重复拍摄时间不需要特殊处理。 它们一次处理一个，因此有两个可用的绝地武士，同时两次射击可以被不同的绝地武士阻挡。 绝地武士阻止其中一个后，他的下一次可用时间严格晚于，因为反应时间是积极的。 

Python 整数具有任意精度，因此`t + reaction[k]`计算不能溢出。

 ## 边缘情况

 对于重复的时间戳，请考虑确切的输入```
1
2
5 5
2
1 10
```排序后，留下的照片`5, 5`。 最初，两个绝地武士都可用，因此速度较快的绝地武士阻挡了第一个射击，并在时间 6 时可用。第二个绝地武士在时间 5 时仍然可用，因此他阻挡了第二个射击。 两个镜头都停止了，答案是`Mission #1: 0`。 该算法永远不会合并相等的值，因此两个镜头保持独立。 

对于确切的可用性边界，请考虑```
1
3
1 3 5
1
2
```唯一的绝地武士阻挡时间 1，使他的下一个可用时间为 3。时间 3 的射击满足`3 >= 3`，因此可以被阻止。 他的下一次可用时间变成了5，最后一投也被封堵。 输出是`Mission #1: 0`。 比较必须使用`<=`在确定可用性时。 

对于贪心选择，考虑```
1
5
1 2 3 4 5
2
2 100
```在时间 1 时，两个绝地武士都可用，因此选择反应 2 绝地武士。 他在 3 点就可以上场，而反应 100 绝地武士仍然可以上场。 在时间 2，速度较慢的绝地武士阻挡了射击。 在时间 3，更快的绝地武士再次准备好并阻止它，并且相同的模式继续。 在较慢的绝地武士的长冷却时间阻止进一步的帮助之前，可以阻止四次射击，只留下一枪未命中。 首先选择速度较慢的绝地武士会不必要地拖延能够快速恢复的绝地武士，这就是为什么需要贪婪的偏好。 

对于只有一名绝地武士的任务，例如```
1
5
10 5 5 10 5
1
100
```排序产生`5, 5, 5, 10, 10`。 绝地武士可以在 5 处阻挡第一枪，然后在 105 之前无法阻挡任何东西。剩下的四枪都在 105 之前到达，所以四枪都通过了。 输出是`Mission #1: 4`。 相同的实现可以处理一个和两个 Jedi，而不需要单独的算法。 

最大尺寸边界也很简单。 包含 1000 次射击的任务存储在一个列表中，排序为`O(1000 log 1000)`时间，然后扫描一次。 不需要递归搜索或二次状态，因此实现可以轻松地保持在预期限制内。
