 ## 解决方案
 ## 问题理解

 我们有一块大小为 (n × n) 的方板，最初填充有冰块。 策略包括 (m) 尝试敲除特定细胞。 如果该位置的方块已经消失，则尝试无效，无论是因为它之前被直接击倒，还是因为它作为级联的一部分掉落。 

如果块的整行仍然完好无损或它的整列仍然完好无损，则该块仍受支持。 一旦从一行中删除一个块，该行就不再完整。 同样，从列中删除块会使该列不完整。 任何行和列都不完整的方块都会掉落，掉落会导致更多方块消失。 所需的输出是每个板的无效尝试次数。 原始竞赛包含 (1 \le n \le 50) 和 (1 \le m \le 100)，具有请求的输出格式`Strategy #b: i`。 

约束的关键结果是，即使是简单的 (O(mn^2)) 模拟也很容易变得足够小，因为最大的棋盘只有 (2500) 个单元格，并且最多有 (100) 个移动。 然而，下降过程的结构使我们能够做得更好。 我们永远不需要单独维护所有 (n^2) 个单元。 

粗心的实施可能会错过一些边缘情况。 第一个是重复完全相同的动作。 例如，```
1
1 2
1 1
1 1
```有输出```
Strategy #1: 1
```第一次尝试删除唯一的块。 第二次尝试无效，因为该块已经消失。 只记住直接被剔除的单元的实现可以处理这种情况，但它也必须正确处理间接消失的块。 

一个更有趣的情况是行已经被破坏但列还没有。 例如，```
1
2 3
1 1
1 2
2 1
```有输出```
Strategy #1: 1
```移除后`(1,1)`，第 1 行和第 1 列不完整。 细胞`(1,2)`幸存下来是因为第 2 列仍然完整。 去除`(1,2)`然后打破第 2 列。最后的尝试`(2,1)`无效，因为第 2 行和第 1 列现在都不完整。 一个常见的错误是将整个触摸行视为不可用，这会错误地标记`(1,2)`无效的。 

边界情况（n=1）也值得关注。 为了```
1
1 1
1 1
```输出是```
Strategy #1: 0
```唯一的举动是有效的。 这里行和列没有区别，并且支持块，因为它的行和列最初都是完整的。 

## 方法

 直接模拟可以代表每个单元并在移动后重复检查棋盘。 当一个块丢失时，我们检查它的行是否完整或列是否完整。 如果两者都不完整，则该块会掉落，我们重复该过程，直到不再有块消失。 这是正确的，因为它确实遵循了棋盘的物理规则。 

该实施的问题是不必要的重复工作。 一种简单的实现是在每次移动后扫描所有 (n^2) 个单元格，并持续进行完整扫描，直到棋盘停止变化，一次移动需要 (O(n^2)) 次扫描，每次扫描需要 (O(n^2)) 次工作。 经过 (m) 次移动，这是 (O(mn^4))。 在最大约束下，这给出了 (100 \cdot 50^4 = 625{,}000{,}000) 个单元检查，这对于一秒竞赛问题来说是不必要的大。 

暴力方法之所以有效，是因为每个单元格的状态取决于其行和列是否完整。 这一观察结果让我们抛弃了大部分的棋盘状态。 

考虑一下成功迁移后立即发生的情况`(r,c)`。 (r) 行不再完整，(c) 列不再完整。 从此时起，两者都不再完整，因为块只会消失。 现在考虑任何细胞`(x,y)`。 当它的至少一个维度保持完整时，它就存活下来。 如果行 (x) 从未被破坏，则整行仍然存在。 如果列 (y) 从未被破坏，则整个列仍然存在。 如果两者都已经坏了，`(x,y)`一定是摔倒了。 

这意味着整个级联可以仅使用两个布尔数组来表示。`broken_row[r]`说那行`r`已变得不完整，并且`broken_col[c]`对于列来说也是如此`c`。 

请求的单元格`(r,c)`仍然存在恰好当`broken_row[r]`或者`broken_col[c]`是假的。 因此，当两个标志都已为真时，尝试的移动是无效的。 如果移动有效，我们将其行和列标记为损坏。 没有单独的级联模拟，因为已知两个破碎维度交叉处的每个单元都已经消失。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(mn^4)) | (O(n^2)) | 在最坏的情况下太慢|
 | 最佳| (O(m+n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 创建`broken_row`和`broken_col`，每行和每列最初为 false。 最初，每一行和每一列都包含所有的冰块，因此每个细胞都存在。 
2. 读取每个尝试的位置`(r,c)`并将其转换为从零开始的索引。 检查是否`broken_row[r]`和`broken_col[c]`都是真的。 
3. 如果两个标志都为真，则增加无效移动计数器。 该单元位于两个不完整维度的交叉点，因此它一定已经掉落了。 
4. 否则，块位于`(r,c)`仍然存在，因此移动有效。 标记`broken_row[r]`和`broken_col[c]`是真的。 这些尺寸永远不会再次变得完整，因为棋盘只会失去方块。 
5. 完成所有移动后，使用所需的策略编号打印无效尝试的次数。 

### 为什么它有效

 不变量是在处理任何移动前缀后，一个单元格`(r,c)`存在当且仅当行`r`仍然完整或列`c`仍然完整。 最初，这两个条件对于每个单元都成立。 当有效的移动移除时`(r,c)`，它的行和列变得不完整。 任何行和列都不完整的单元格都必须掉落，而每个具有至少一个完整维度的单元格仍然受到支持。 由于维度永远不会再次变得完整，因此两个布尔数组准确地描述了每次移动后的棋盘。 因此，当行和列都被标记为损坏时，移动是无效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())

        broken_row = [False] * n
        broken_col = [False] * n

        invalid = 0

        for _ in range(m):
            r, c = map(int, input().split())
            r -= 1
            c -= 1

            if broken_row[r] and broken_col[c]:
                invalid += 1
            else:
                broken_row[r] = True
                broken_col[c] = True

        out.append(f"Strategy #{case}: {invalid}")
        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入从板的数量开始。 对于每一块板，两个布尔数组记录哪些行和列丢失了至少一个块。 

对于每一步，代码首先检查两个标志，然后再修改它们。 这个顺序很重要。 如果行和列都已被破坏，则尝试的块已经落下，因此该移动必须被视为无效。 如果至少一维仍然完整，则该块仍然受到支持并且移动有效。 

有效移动后的分配故意简单。 我们不需要明确删除掉落的其他单元格。 一旦行或列被破坏，其标志将永远保持为真，并且任何两个被破坏的维度的交集将在下一步移动时自动被视为不存在。 

减一会将问题的从 1 开始的行和列编号转换为 Python 从 0 开始的数组索引。 Python 中不存在溢出问题，甚至答案本身最多也是 (m)。 

每个策略后面附加的空字符串会在输出之间生成所需的空行。 决赛`join`也避免了重复调用`print`，尽管对于这些限制来说，任何一种方法都足够快。

 第二盘是（4×4），有四步棋。

 | --- | --- | --- | --- | --- |

 |`(2,4)`| 假 | 假 | 是的 | 0 |

 ## 边缘情况

 对于重复移动的情况，```
1
3 4
1 1
1 1
1 1
1 1
```第一个`(1,1)`移动有效，因此第 1 行和第 1 列损坏。 在随后的每次尝试中，两个标志都已为 true。 该算法将答案增加三倍并产生`Strategy #1: 3`。 

对于行支撑情况，```
1
2 3
1 2
2 1
2 2
```第一个移动打破了第 1 行和第 2 列。第二个移动打破了第 2 行和第 1 列。第三个移动目标`(2,2)`，其第 2 行和第 2 列都已损坏，因此该块已经掉落。 输出是`Strategy #1: 1`。 这捕获了仅跟踪先前是否选择了确切坐标的常见错误。 

对于最小板，```
1
1 1
1 1
```唯一的行和唯一的列都开始完成。 第一步是有效的，答案仍然是零。 该实现不需要特殊的大小写，因为两个布尔数组的长度为一。 

对于最大尺寸的情况，前 50 次移动可以恰好接触每行和每列一次。 这些移动都是有效的，因为在每次对角移动之前，两个维度中至少有一个仍然是完整的。 一旦50行和列全部被打破，后续的每一步动作都无效。 再重复 50 次对角线移动，答案正好是 50。这也表明，即使棋盘已经经历了尽可能多的直接移动，算法的状态也是足够的。
