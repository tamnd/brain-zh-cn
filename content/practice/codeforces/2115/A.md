 ## 解决方案
 ## 问题理解

 我们从一系列正整数开始。 一步中，我们选择两个不同的位置，比如说$i$和$j$，然后我们覆盖$a_i$与其当前值的最大公约数和$a_j$。 第二个元素$a_j$保持不变。 我们重复这个过程，直到数组中的每个条目都变得相同，并且我们希望最大限度地减少所需的此类移动次数。 

关键的观察结果是最终值是强制的。 每个操作都会用数组中已存在的两个值的 gcd 替换一个元素，因此任何数字都不会增加，并且出现的每个值都是某个原始值的除数。 因此，在完全相等的数组中唯一可以保留的值是整个数组的 gcd。 

让$g = \gcd(a_1, a_2, \ldots, a_n)$。 该过程始终以每个元素等于$g$，任务是最小化将数组转换为所有数组所需的操作数$g$。 

约束以非常具体的方式很小：$n$所有测试用例最多为 5000，每个值最多为 5000。这立即表明解决方案具有大致$O(n^2)$每个测试用例都是可行的，但是任何立方体$n$会太慢。 

一个天真的但诱人的想法是贪婪地模拟该过程，甚至搜索操作序列。 但这会失败，因为状态空间是组合增长的。 如果没有关于 gcd 传播如何工作的全局信息，即使决定接下来应用哪对也无法实现局部最优。 

第二个常见的陷阱是假设一旦我们创建一个元素等于$g$，我们可以将其传播到所有其他位置$n-1$运营。 仅当我们已经知道创建第一个项目的成本时，这才是正确的$g$，这是困难的部分。 

例如，考虑$a = [6, 10, 15]$。 全局gcd为$1$。 我们无法得到$1$一步到位，因为没有对有 gcd$1$。 幼稚的策略可能会尝试重复组合对，并低估首先“制造”一个产品所需的步骤。$1$。 

## 方法

 一旦我们将任务分为两个阶段，这个过程就会变得更容易：首先创建至少一个等于$g$，然后将其传播到数组的其余部分。 

假设我们已经有一个位置包含$g$。 然后其他所有元素$x$可以变成$g$在一次操作中应用$x := \gcd(x, g)$。 所以第二阶段总是要花费$n-1$运营。 

真正的困难是第一阶段：需要多少次操作才能产生一个$g$使用 gcd 运算从原始数组中获取？ 

为了分析这一点，将每个元素除以$g$。 这种标准化将问题简化为$1$从数组中，因为$\gcd(a_1/g, \ldots, a_n/g) = 1$。 现在我们想要创建一个等于$1$使用操作$a_i := \gcd(a_i, a_j)$。 

如果某个元素已经存在$1$，那么我们立即完成第一阶段。 否则，我们需要组合元素，直到一个位置变成$1$。 每个操作只会减少值，因此我们有效地尝试构建一个子集，其 gcd 为$1$，并且我们必须显式地构造它。 

这导致了基于值而不是指数的动态规划公式。 让我们定义一个 DP，在其中跟踪从某些元素子集获取特定 gcd 值所需的最少操作数，同时通过连续合并“构建”它。 

然而，有一个重要的简化。 由于所有值最多为 5000，因此我们可以计算每个可能的值$x$，获得gcd所需的最少元素数$x$通过组合数组的前缀。 更直接地说，我们想要 gcd 为的最小数量的元素$1$，然后我们将其转换为操作计数。 

一个关键的结构事实是，如果大小的子集$k$有gcd$1$，那么我们可以将一个元素变成$1$准确地使用$k-1$通过对该子集中的剩余元素连续应用 gcd 运算来进行运算。 这给出了子集大小和操作成本之间的直接联系。 

所以第一阶段简化为寻找 gcd 等于的最小子集$1$。 如果它的大小是$k$，那么我们需要$k-1$操作以产生单个$1$。 之后，传播需要$n-1$，给出总计$k + n - 2$。 

我们使用 gcd 状态上的 DP 来计算这个最小子集大小：迭代元素并更新每个可能的 gcd 值的最佳子集大小。

 ## 算法演练

 1. 计算$g = \gcd(a_1, \ldots, a_n)$。 然后将每个元素除以$g$，将问题简化为使所有元素等于$1$。 这种标准化不会改变 gcd 传播的相对结构中所需的操作数量。 
2. 如果至少有一个元素已经存在$1$，稍后直接跳到第二阶段推理，因为不需要任何工作来创建第一个阶段$1$。 答案很简单$n - \text{count of ones}$。 
3. 否则，我们计算形成 gcd 所需的最小元素数$1$。 我们维护一个DP数组`dp[x]`表示 gcd 等于的最小子集大小$x$。 将所有条目初始化为无穷大。 
4. 迭代每个数组值$v$。 对于每个现有的 DP 状态$x$，我们可以形成一个新的gcd状态$g = \gcd(x, v)$，并更新`dp[g] = min(dp[g], dp[x] + 1)`。 我们还允许开始一个新的子集$v$， 所以`dp[v] = 1`。 
5. 处理完所有元素后，`dp[1]`给出最小子集大小，其 gcd 为$1$。 Call this value$k$。 
6. 创建单个的成本$1$是$k - 1$操作，因为每个操作都可以将一个附加元素合并到不断增长的 gcd 链中。 
7. 一旦一个元素被$1$，我们将它准确地传播到所有其他位置$n - 1$操作，每次用 gcd 覆盖一个位置$1$，除了强制它变成$1$。 
8. 返回$(k - 1) + (n - 1) = k + n - 2$。 

### 为什么它有效

 不变的是任何 gcd 操作序列都对应于逐步构建原始元素子集的 gcd。 任何操作都不能引入不是初始值某些子集的 gcd 的值。 因此，构建一个值$1$相当于选择一个gcd为的子集$1$，并且每个操作都可以将该子集的大小增加恰好一个贡献元素。 这在子集大小和实现其 gcd 所需的操作数之间建立了一对一的对应关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from math import gcd
from collections import defaultdict

INF = 10**9

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        g = 0
        for x in a:
            g = gcd(g, x)

        b = [x // g for x in a]

        ones = b.count(1)
        if ones:
            print(n - ones)
            continue

        dp = {}

        for v in b:
            ndp = dp.copy()

            ndp[v] = min(ndp.get(v, INF), 1)

            for x, val in dp.items():
                ng = gcd(x, v)
                ndp[ng] = min(ndp.get(ng, INF), val + 1)

            dp = ndp

        k = dp[1]
        print(k + n - 2)

if __name__ == "__main__":
    solve()
```实现直接遵循 DP 解释。 字典`dp`存储可达的 gcd 值以及实现这些值所需的最小子集大小。 每个新元素都会更新所有先前的状态，反映启动新子集或扩展现有子集的选择。 处理完所有元素后，gcd 的值等于 1，给出了临界子集大小。 

一个微妙的点是每次迭代使用复制的字典。 这避免了在同一迭代中覆盖状态，确保每个元素在子集构造中最多使用一次。 

## 工作示例

 ### 示例 1

 输入：```
3
12 20 30
```我们首先计算$g = 2$，所以我们标准化为$[6, 10, 15]$。 没有元素等于$1$，所以我们必须用 gcd 计算最小子集$1$。 

| 步骤| 加工价值| dp 状态（选定）|
 | ---| ---| ---|
 | 1 | 6 | {6:1} |
 | 2 | 10 | 10 {6:1, 10:1, 2:2} |
 | 3 | 15 | 15 包括产生尺寸为 3 的 1 的 gcd 组合 |

 最终$k = 3$，所以答案是$3 + 3 - 2 = 4$。 

该迹线表明，归一化后没有任何单个元素等于目标，因此我们必须将所有三个元素组合起来才能达到 gcd 1。 

### 示例 2

 输入：```
6
1 9 1 9 8 1
```这里$g = 1$，因此不需要标准化。 我们已经有了三个。 

最好的策略是使用单个操作来转换每个非一。 

| 步骤| 行动| 个数|
 | ---| ---| ---|
 | 初始| - | 3 |
 | 手术后| 转换 9,9,8 | 6 |

 我们需要转换 3 个非 1 元素，所以答案是$3$。 

这说明了不需要第一阶段的特殊情况。

 ## 边缘情况

 一种重要的边缘情况是数组已包含多个等于全局 gcd 的元素。 对于像这样的输入$[4, 6, 2, 8]$，最大公约数是$2$，并且至少一个元素可能已经等于$2$。 在这种情况下，第一阶段将被跳过，仅保留传播。 该算法通过以下方式正确检测到这一点：`ones`正常化后检查，立即返回$n - \text{count of ones}$。 

当最初没有元素等于 gcd，但两个元素已经直接产生它时，会出现另一种边缘情况。 例如$[6, 10]$有gcd$2$，但两个元素都不等于$2$。 DP阶段正确地发现构建需要两个元素$2$, 给予$k = 2$，因此需要一个操作来创建第一个$2$，然后再传播一个。
