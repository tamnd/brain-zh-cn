 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的几何对象进行交互：一个放置在非常大的方形网格内某处的圆。 正方形的两个轴的坐标范围为 0 到 100000，圆的中心坐标为整数，半径为整数。 半径保证至少为 100，并且圆完全包含在正方形内，这意味着它永远不会跨越边界。 

获取信息的唯一方法是在两个整数点之间画一条线段，并接收该线段有多少位于圆内。 换句话说，对于任何线段，法官计算该线段与圆盘相交的部分的总长度。 

任务是使用最多 1024 个此类查询来确定精确的中心坐标和半径。 

约束结构强烈地塑造了解决方案。 中心的搜索空间为 10^5 x 10^5，这对于任何试图一一细化坐标的网格搜索或随机采样方法来说都太大了。 每个查询在概念上都相对昂贵，因此我们必须从每个探针中提取尽可能多的几何信息。 关键的观察是，对固定水平或垂直线的每个查询不仅仅给出布尔答案，而是等于圆弦长度的连续值。 这将问题从离散搜索转变为连续几何。 

当探测线根本不与圆相交时，就会出现微妙的边缘情况。 在这种情况下，答案恰好为零。 如果选择一条远离圆的线，假设每个查询都返回有用的几何约束的幼稚策略可能会默默地失败。 例如，当圆心位于 y = 90000 附近且半径为 100 时查询 y = 0 将始终返回零，不会提供任何可用信息。 该解决方案必须避免依赖任意固定探针，而是主动定位存在交叉点的区域。 

## 方法

 蛮力策略会尝试探测网格上的许多线，逐渐缩小圆圈所在的位置。 例如，我们可以尝试所有水平线 y = 0, 1, 2, ...，并为每条线检测它是否与圆相交，然后从所有弦的集合重建圆。 这在理论上是合理的，因为每个弦都对中心和半径给出了限制，但成本却令人望而却步。 即使单次扫描超过 100000 行也已经太大了，如果我们想精确细化端点，每行可能需要多个探针。 

关键的结构见解是圆的水平切片的行为方式非常可预测。 如果我们固定一条水平线 y = Y，与圆（如果有的话）的交点是一条线段，其长度为

 2 * sqrt(r^2−(Y−cy)^2)。 

该函数仅取决于到中心的垂直距离。 它围绕 cy 对称，并在 y = cy 处达到最大值，此时弦长变为 2r。 这意味着我们可以通过找到该函数最大化的位置来恢复 cy，而不是从许多点重建圆。 一旦知道了 cy，最大弦长就可以直接得出 r。 

同样的想法使用垂直线 x = X 对称地应用于 x 方向，这允许恢复 cx。 

因此，问题简化为在整数域上找到单峰函数的峰值，然后评估其在峰值处的值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 彻底扫描所有线路 | O(10^5) 次查询 | O(1) | O(1) | 太慢了|
 | 使用弦长的单峰搜索 | O(log 10^5) 次查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

我们将水平探针视为函数 f(Y)，其中 f(Y) 返回圆与高度 Y 处的水平线相交的长度。该函数在圆的垂直跨度之外为零，向上增加到中心，然后对称地减小。 

我们在两阶段搜索中使用此结构。 

1. 我们通过使用查询 0 Y 100000 Y 形式的查询，在整个范围 [0, 100000] 内对 Y 执行三元式离散搜索来搜索 cy 的值。每个查询返回 f(Y)。 我们比较两个候选高度处的值并丢弃值较小的一侧。 这是可行的，因为 f(Y) 是单峰的，在 cy 处有一个最大值。 
2. 一旦搜索收敛，我们将最佳 Y 确定为 cy。 然后我们在 y = cy 处发出最后一个水平查询。 返回的值正好是 2r，因为该线穿过圆心。 由此我们计算 r。 
3. 我们在 x 方向上重复相同的过程。 我们将 g(X) 定义为 x = X 处从 (X, 0) 到 (X, 100000) 的垂直线段的交点长度。 该函数也是单峰的，最大值位于 cx 处。 我们使用相同的搜索策略找到 cx ，然后将其恢复为最大化器。 
4. 得到cx、cy、r后，输出答案。 

这样做的原因是圆与固定轴对齐线的交点完全由距中心的垂直距离决定。 该距离在平方根内形成凸二次关系，产生对称单峰曲线。 搜索过程仅依赖于函数值的比较，因此不需要超出允许的查询容差的任何数值精度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(x1, y1, x2, y2):
    print(f"query {x1} {y1} {x2} {y2}", flush=True)
    return float(input().strip())

def find_peak_horizontal():
    lo, hi = 0, 100000
    while hi - lo > 3:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3
        f1 = query(0, m1, 100000, m1)
        f2 = query(0, m2, 100000, m2)
        if f1 < f2:
            lo = m1
        else:
            hi = m2
    best_y = lo
    best_val = -1
    for y in range(lo, hi + 1):
        val = query(0, y, 100000, y)
        if val > best_val:
            best_val = val
            best_y = y
    return best_y, best_val

def find_peak_vertical():
    lo, hi = 0, 100000
    while hi - lo > 3:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3
        f1 = query(m1, 0, m1, 100000)
        f2 = query(m2, 0, m2, 100000)
        if f1 < f2:
            lo = m1
        else:
            hi = m2
    best_x = lo
    best_val = -1
    for x in range(lo, hi + 1):
        val = query(x, 0, x, 100000)
        if val > best_val:
            best_val = val
            best_x = x
    return best_x, best_val

def main():
    cy, max_h = find_peak_horizontal()
    r = int(round(max_h / 2))

    cx, _ = find_peak_vertical()

    print(f"answer {cx} {cy} {r}", flush=True)

if __name__ == "__main__":
    main()
```水平和垂直搜索功能在结构上是相同的，只是坐标是固定的。 每个查询都使用与轴对齐的全长线段，这保证返回的值与圆的单个弦完全对应。 

半径的舍入步骤是安全的，因为在理想模型中，返回的最大弦长在数学上恰好为 2r，并且该问题保证整数半径且数值误差范围较小。

 ## 边缘情况

 一种关键情况是当圆接近网格边界时。 例如，如果中心为 (100, 50000)，半径为 100，水平函数仍表现为单峰，但在大部分范围内变得高度不对称。 该算法仍然有效，因为保留了单峰性，即使大多数查询在有效间隔之外返回零。 

另一种情况是，由于整数采样，最大值在单个点上平坦。 即使两个相邻的 y 值产生几乎相同的弦长，三元搜索仍然会收敛到包含真实中心的小区间，并且对该区间的最终强力扫描会选择正确的整数坐标。 

最后一个微妙的情况是半径计算中的数值精度。 由于返回值可能包含最大10^-6的小误差，因此需要四舍五入。 由于 r 保证为整数且至少为 100，因此将恢复的 2r 值舍入到最接近的整数可以安全地恢复精确的半径，而不会产生歧义。
