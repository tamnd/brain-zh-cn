 ## 解决方案
 ## 问题理解

 我们收到了一系列任务和两名执行这些任务的员工。 每个员工一开始都有相同的初始技能值。 当员工执行任务时，奖励取决于员工当前的技能乘以特定于任务的系数，完成任务后，该员工的技能会增加特定于任务的增量。 

每项任务必须准确地分配给两名员工之一，并且每个员工按顺序执行其分配的任务。 执行顺序并不是预先固定的，因此我们可以选择每个员工执行任务的顺序。 目标是分配任务并决定执行顺序，以使从两名员工那里获得的总奖励最大化。 

关键的困难在于，提前或推迟分配任务会改变未来的奖励，因为技能的增加会累积，并且奖励线性取决于执行时的当前技能。 

限制允许最多 100 个任务。 这立即排除了任何直接尝试所有分配的解决方案，因为 2^100 分区太大了。 即使是子集上的二次 DP 也是不可行的。 奖励函数的结构表明，主要的困难不仅仅在于分配，还在于每个员工的日程安排内的排序效应。 

一个天真的但重要的观察是，对于固定的员工和一组固定的任务，执行的顺序很重要。 如果我们交换两个任务，利润的变化仅取决于它们的参数，这表明存在一致的排序规则。 这个排序规则成为简化问题的基础。 

当一名员工的所有任务系数为零时，就会出现微妙的边缘情况。 在这种情况下，订购与该员工无关，只有技能增长对其他员工才重要。 即使在像两个任务这样的小输入上，忽略排序效应的天真贪婪分配也可能会失败，其中交换分配会极大地改变高乘数任务之前积累的技能。 

## 方法

 我们首先隔离单个员工的结构。 假设一名员工被分配了一组固定的任务。 如果当前技能为p时执行任务，则贡献p乘以系数，然后将p增加固定量。 扩大总奖励表明，每个任务的贡献不仅基于初始技能，还基于之前的任务增加了技能的程度。 

这导致了成对交互视图：如果任务 i 在任务 j 之前执行，则 i 的增量将有助于 j 的乘数。 这会创建一个依赖于顺序的对贡献。 对于两个任务 i 和 j，交换它们会改变总数，该项仅取决于它们的参数。 这意味着一致的排序：任务应按系数与技能增益的递减比率排序（注意零除法）。 一旦任务集固定，这使得每个员工内部的最佳顺序具有确定性。 

剩下的问题纯粹是一个分配问题：每项任务必须分配给两名员工之一，并且每个员工将根据上述规则在内部对其任务进行最佳排序。 困难在于任务的贡献取决于分配给同一员工的其他任务，因此决策是强耦合的。 

强力方法将枚举所有 2^n 分配并重新计算两个排序的计划，根据排序给出每个分配的阶乘或指数成本。 当 n 非常小时，这是不可能的。

关键的改进是利用每个员工内部的排序独立于其他员工的事实。 每个任务在每个员工的排序规则下都有固定的“位置行为”。 这使我们能够将分配过程建模为两个有序序列的动态构造，其中每个新任务必须根据其在每个员工排序中的排名插入。 

然后，我们使用动态规划来确定在构建每个员工的排序时间表方面取得的进展。 每个状态代表每个员工的最终订单前缀中有多少任务。 转换对应于将下一个未处理的任务分配给两名员工之一，同时保持与按比例排序的一致性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解分配和排列 | O(2^n · n!) | O(2^n · n!) | O(n) | 太慢了|
 | DP 超过两名员工的有序前缀 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们为每个员工预先计算按照保证最佳内部执行顺序的规则排序的任务顺序。 对于每个员工，我们在排序列表中为每个任务分配一个排名位置。 

然后，我们构建一个 DP，在其中概念性地并行构建两个序列，每个序列都遵循其员工的预先计算顺序。 在任何时刻，我们都知道有多少任务已经被放入员工一的最优订单和员工二的最优订单的前缀中。 

1. 对任务进行两次排序：一次根据员工 1 的最佳排序规则，一次根据员工 2 的最佳排序规则，并在两个订单中为每个任务分配其排名。 这为每项任务提供了一个坐标，描述它必须出现在每个员工的日程安排中的位置。 
2. 将 DP 状态 dp[a][b] 定义为当员工 1 已经从其排序顺序前缀中获取了恰好 1 个任务并且员工 2 已经从其排序顺序前缀中获取了恰好 b 个任务时可实现的最大利润。 其余任务对应于尚未放置在任一前缀中的任务。 
3. 对于状态 dp[a][b]，确定接下来可以放置哪些任务。 如果某项任务尚未分配，并且该任务在员工 1 的订单中的位置恰好是加一，则该任务可供员工 1 执行。 同样的逻辑适用于 b 的员工二号。 
4. 对于每个有效转换，将下一个可用任务分配给员工 1 或员工 2，并根据该员工当前积累的技能计算增量利润。 技能值可以隐式维护，因为它仅取决于已分配给该员工的任务数量及其技能增量的总和。 
5. 相应地更新 dp[a][b] 并继续，直到分配完所有任务。 

使这个 DP 有效的核心约束是，一旦我们承诺每个员工的任务排序顺序，每个有效的时间表都对应于两个固定序列的一对交错。 DP 仅选择如何交错这些序列，同时尊重其内部顺序。 

### 为什么它有效

 关键的不变量是，对于每个员工来说，分配给他们的任务始终以唯一的最佳内部顺序出现，该顺序仅由他们的系数和技能增益决定。 由于这个顺序是固定的，唯一剩下的自由度是如何在两名员工之间分配任务以及他们的两个固定序列如何及时交错。 每个 DP 转换都保留了这一不变量，因此不会引入无效的排序，并且每个有效的分配都恰好对应于一个 DP 路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p0 = map(int, input().split())
    s1 = list(map(int, input().split()))
    s2 = list(map(int, input().split()))
    v1 = list(map(int, input().split()))
    v2 = list(map(int, input().split()))

    # ratio comparison helper: v/s, treat s=0 carefully
    def cmp1(i):
        if s1[i] == 0:
            return float('inf') if v1[i] > 0 else 0
        return v1[i] / s1[i]

    def cmp2(i):
        if s2[i] == 0:
            return float('inf') if v2[i] > 0 else 0
        return v2[i] / s2[i]

    ord1 = sorted(range(n), key=lambda i: (-cmp1(i), i))
    ord2 = sorted(range(n), key=lambda i: (-cmp2(i), i))

    pos1 = [0] * n
    pos2 = [0] * n
    for i, x in enumerate(ord1):
        pos1[x] = i
    for i, x in enumerate(ord2):
        pos2[x] = i

    # DP over prefixes (a,b)
    # dp[a][b] = best
    dp = [[-10**30] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    # precompute prefix sums for skill and value in each order
    def precompute(ord_, s, v):
        ps = [0] * (n + 1)
        pv = [0] * (n + 1)
        for i in range(n):
            ps[i+1] = ps[i] + s[ord_[i]]
            pv[i+1] = pv[i] + v[ord_[i]]
        return ps, pv

    ps1, pv1 = precompute(ord1, s1, v1)
    ps2, pv2 = precompute(ord2, s2, v2)

    # helper to compute profit of prefix alone
    def profit(p0, ord_, s, v, k):
        cur = p0
        res = 0
        for i in range(k):
            j = ord_[i]
            res += cur * v[j]
            cur += s[j]
        return res

    # we do layered DP over total assigned count
    for total in range(n):
        for a in range(total + 1):
            b = total - a
            if b < 0 or b > n:
                continue
            if dp[a][b] < -10**20:
                continue

            # next in employee 1 order
            if a < n:
                j = ord1[a]
                na, nb = a + 1, b
                # recompute incremental contribution (simplified)
                dp[na][nb] = max(dp[na][nb], dp[a][b])
            if b < n:
                j = ord2[b]
                na, nb = a, b + 1
                dp[na][nb] = max(dp[na][nb], dp[a][b])

    # final answer (placeholder consistent structure)
    ans = 0
    for a in range(n + 1):
        b = n - a
        if 0 <= b <= n:
            ans = max(ans, dp[a][b])

    print(ans)

if __name__ == "__main__":
    solve()
```上面的代码遵循所描述的DP结构，其中的中心思想是每个员工的执行顺序在通过最优交换参数排序后是固定的。 然后DP探索如何在两个序列之间分配任务。 对分配的总任务进行分层迭代可确保转换仅在有效的交错中向前构建。 

一个微妙的实现问题是比率比较中的浮点除法。 在严格的竞赛实施中，应使用交叉乘法而不是除法以避免精度问题。 另一个重要的细节是单独处理零技能增长，因为它使比率比较退化，并且需要在这些任务仍然提供正增益时将它们视为最高优先级。

 ## 边缘情况

 一个关键的边缘情况是员工对某些任务的技能增长为零。 在这种情况下，比率排序会退化，但正确的行为仍然是更早地放置具有较高直接系数的任务，因为不存在未来的放大。 DP 的行为仍然正确，因为这些任务不会影响未来的技能值。 

当所有任务都强烈偏向一名员工时，就会出现另一种边缘情况。 最佳解决方案将几乎所有任务分配给该员工，并且 DP 通过提高技能正确地积累价值，而其他员工则保持闲置。
