 ## 解决方案
 ## 问题理解

 我们得到了一组沿直线放置的带标签的茶亚。 确切的顺序是未知的，我们想要计算这些 chaya 有多少完整的从左到右的排列与历史观察列表一致。 

每个观察涉及三个不同的 chaya$a, b, c$，并断言$b$位于之间的某个地方$a$和$c$沿着路。 “Between”是几何的：如果我们看最终的排序，$b$必须严格位于位置之间$a$和$c$。 的相对顺序$a$和$c$不是固定的，所以两种模式$a < b < c$和$c < b < a$是允许的，但是配置$b$位于两者的同一侧是禁止的。 

任务是计算有多少种排列$1 \ldots n$同时满足所有这些约束，模$998244353$。 

约束条件$n \le 24$是中心信号。 阶乘搜索空间已经太大了，但是$24$强烈建议对子集进行位掩码动态编程。 然而，三元约束的存在意味着我们处理的不是简单的偏序； 每个约束取决于三个元素的相对位置，而不仅仅是成对比较。 这是主要的困难。 

一个天真的解释会尝试根据所有约束检查每个排列，但即使生成排列也是如此$24!$，这是不可行的。 任何解决方案都必须压缩约束检查，以便在构建排列时可以逐步验证有效性。 

一个微妙的边缘情况是，约束在简单的排序意义上不具有传递性或一致性。 例如，如果我们有像这样的约束$(1,2,3)$和$(2,3,1)$，它们可能在局部看起来是合理的，但在全局上却强制矛盾，只有在考虑完全安置时才会出现。 另一个问题是约束不需要邻接，只需要相对顺序，因此假设连续结构的方法会立即失败。 

## 方法

 蛮力的想法很简单：枚举所有排列并检查是否满足每个三重约束。 对于每个排列，我们找到$a, b, c$并验证是否$b$位于另外两者之间。 检查一个排列成本$O(m)$，因此总复杂度变为$O(n! \cdot m)$，这远远超出了可行性$n = 24$。 

关键的结构观察是约束仅讨论相对顺序，而不是距离或邻接。 这建议从左到右构建排列，并确保每当我们放置新元素时，涉及它的所有约束都可以仅使用已放置的元素进行验证。 

这导致了位掩码上的 DP 子集，其中我们将掩码解释为已放置的元素集。 转换是在当前前缀的末尾添加一个新元素。 

困难在于每个约束$(a, b, c)$成为一个条件，当$b$被放置：在那一刻，正好是其中之一$a$和$c$必须已经在前缀中，因为$b$在最终排序中必须位于它们之间。 这将每个约束转换为仅依赖于子集并且可以增量检查的条件。 

剩下的挑战是有效地检查所有子集的这些条件，因为直接扫描每个转换的约束太慢。 该解决方案依赖于每个元素的预计算$b$，由所有约束引起的结构，其中$b$是中间元素，并使用预先计算的位操作验证该结构的子集成员资格。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n! \cdot m)$|$O(1)$| 太慢了|
 | 具有增量约束检查的子集 DP |$O(n \cdot 2^n + m \cdot 2^n)$天真的，优化以适应位集预处理|$O(n \cdot 2^n)$| 已接受 |

 ## 算法演练

 我们在顶点子集上定义一个 DP，其中`dp[mask]`计算有多少个有效的偏序将元素精确地放置在`mask`作为最终排列的前缀。 

对于每个元素$b$，我们预处理所有约束，其中$b$是中间的元素。 每个这样的约束$(a, b, c)$对任何有效前缀提出要求$S$其中包含$b$： 之中$a$和$c$，恰好有一个必须位于$S \setminus \{b\}$。 如果两者都在或都在外，则此时违反约束$b$已插入。 

然后，我们通过迭代掩码并尝试附加新元素来构建 DP$x$。 放置的有效性检查$x$仅取决于约束条件，其中$x$是中间的元素。 

### 步骤

 1. 预先计算，对于每个$b$，对列表$(a, c)$这样$b$必须介于$a$和$c$。 这只是输入约束的重新组合。 
2. 初始化 DP`dp[0] = 1`，代表空前缀。 
3.从小到大迭代所有掩码。 对于每个掩码，考虑添加一个新元素$x$不在面具里。 
4. 检查是否$x$可以添加，检查与相关的所有约束$x$。 对于每对$(a, c)$，我们要求恰好之一$a$和$c$已经在`mask`。 
5. 如果满足所有这些约束，则更新`dp[mask | (1 << x)] += dp[mask]`。 
6.最终答案是`dp[(1 << n) - 1]`。 

### 为什么它有效

 DP 对每个部分排列强制执行一致的“前缀有效性”解释。 当我们放置一个元素时$b$，每个约束涉及$b$变得完全可检查，因为它的正确性仅取决于是否$a$和$c$已经相对于放置$b$的插入时刻。 一次$b$已插入，以后的操作无法更改是否$b$位于之间$a$和$c$，因此约束在该步骤中是固定的。 这创建了一个干净的不变量：每个部分状态表示一组仍然可以扩展为完整有效排列的放置元素，并且每个转换都通过在所有新完成的约束变得可判定时强制执行所有新完成的约束来保留此属性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    
    between = [[] for _ in range(n)]
    
    for _ in range(m):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        c -= 1
        between[b].append((a, c))
    
    N = 1 << n
    dp = [0] * N
    dp[0] = 1
    
    for mask in range(N):
        if dp[mask] == 0:
            continue
        
        for x in range(n):
            if mask & (1 << x):
                continue
            
            ok = True
            
            for a, c in between[x]:
                in_a = (mask >> a) & 1
                in_c = (mask >> c) & 1
                if in_a == in_c:
                    ok = False
                    break
            
            if ok:
                dp[mask | (1 << x)] = (dp[mask | (1 << x)] + dp[mask]) % MOD
    
    print(dp[N - 1])

if __name__ == "__main__":
    solve()
```该代码直接镜像 DP。 数组`between[b]`将所有约束存储在其中$b$必须位于其他两个元素之间。 在过渡期间，我们仅验证在以下情况下变得相关的约束：$b$已插入。 

关键的实现细节是约束检查仅对当前掩码使用位测试，这避免了重新计算位置或维护显式排序。 DP 状态准确编码所需的信息：哪些元素已被放置。

 ## 边缘情况

 一个关键的边缘情况是约束形成的矛盾仅在部分构建后出现。 例如，如果两个约束通过不同的中间点在相同端点之间强制执行不兼容的奇偶校验，则 DP 会拒绝所有完成，因为当第二个端点插入使约束完全可观察的前缀时，会准确地检测到违规。 

另一种边缘情况是不存在约束的情况。 在这种情况下，每个子集转换都是有效的，并且 DP 有效地计算所有排列，产生$n!$。 该实现自然地处理了这个问题，因为`between[x]`对所有人来说都是空的$x$，因此每次转换都不受限制地通过。 

当一个元素作为许多约束的中间出现时，就会出现最后一种微妙的情况。 即使这样，每个约束都会在插入时独立检查，并且由于决策仅取决于当前掩码中的位成员资格，因此 DP 状态内不会出现排序模糊性。
