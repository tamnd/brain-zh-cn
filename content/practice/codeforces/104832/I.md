 ## 解决方案
 ## 问题理解

 我们有一组源容器，每个容器包含两种液体 A 和 B 按固定比例的混合物。 我们可以从每个容器中取出其内容物的任何部分，并且该部分始终保留该容器内 A 与 B 的原始比例。 从任何容器中提取的所有部分都可以自由混合到新容器中。 

另一方面，有一组目标机构，每个机构都需要一个最终容器，其中包含指定数量的 A 和 B。所有来源的 A 总量等于所有目标所需的 A 总量，对于 B 也是如此。 

问题不是明确地构建分布，而是决定是否存在任何方法来拆分和混合源容器，以便每个机构准确地收到其所需的金额对。 

关键的限制是我们无法在瓶子内将 A 与 B 分开。 每个操作都会保留瓶子所选部分的局部比率，因此我们移动的每个部分都是固定二维向量的标量倍数。 

从计算的角度来看，我们有多达 500 个源瓶和 500 个目标机构。 这立即排除了各个无穷小分裂之间的流的任何三次或高二次构造。 如果直接实现，即使是所有成对传输的简单线性规划公式也会太大，因为它自然会建议具有 250000 个变量的 n × m 二分流。 

不平凡的困难在于我们使用相同的分配结构同时匹配两个线性约束（A 和 B）。 如果我们只关心总量，这将是一个标准的运输问题。 复杂的是，同一个流程必须同时满足 A 和 B，这迫使所有分配的比率保持一致。 

当总量匹配但聚合中的比率不兼容时，就会出现幼稚推理的微妙失败情况。 

考虑这样一种情况，两个源瓶具有非常不同的 A 与 B 比例，但目标机构要求混合物“交错”这些比例。 匹配任意交易量而不考虑比率排序的贪婪策略很容易产生 A 完美匹配但 B 不匹配的情况，即使总和是一致的。 

另一个失败案例是假设我们可以独立解决 A 和 B 作为两个独立的运输问题。 该方法忽略了两者必须由相同的分割矩阵满足。 

## 方法

 如果我们直接扩展问题，我们引入变量$x_{ij}$，代表源瓶的数量$i$被送往研究所$j$。 每个来源贡献固定的比例，因此发送$x_{ij}$瓶中毫升数$i$贡献$x_{ij} a_i$的 A 和$x_{ij} b_i$B 的约束变为线性：

 对于每个来源，发送的总分数为 1，对于每个机构，A 和 B 的总和必须与目标匹配。 

这是一个具有高度结构化约束矩阵的线性可行性问题。 强力求解器会将其视为一般线性程序或具有附加耦合约束的大型最大流。 当 n、m 达到 500 时，这很快就变得不可行。 

关键的结构洞察是每个流量单位都有一个固定的比率$a_i / b_i$。 这意味着每个源不仅仅是一个标量电源，而且是二维空间中线上的一个点。 任何混合都是这些点的凸组合。 每个目标也是同一空间中的一个点。 

因此，问题就变成了：我们能否将目标点分解为具有正确的总质量守恒的源点的凸组合。 

关键的观察是，如果我们按来源和目标的比率对它们进行排序$a_i / b_i$和$c_j / d_j$，那么最佳匹配必须遵守这个顺序。 直观地说，早期将高比率源与低比率目标混合将迫使随后进行破坏可行性的修正，因为无法“撤消”比率混合。 

这将问题转化为贪婪扫描，其中我们将最小比率边与最小比率边相匹配，始终推动流量直到一侧耗尽，然后前进。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | Naive LP /全流程配方| 指数或高多项式| 高| 太慢了|
 | 排序贪心比匹配 | O(n log n + m log m) | O(n log n + m log m) | O(n + m) | 已接受 |

 ## 算法演练

 我们将每个瓶子和每个机构解释为二维空间中具有固定比例的一段。 每个部分的总质量也等于$a_i + b_i$或者$c_j + d_j$。 该算法按照比率递增的顺序匹配这些片段。 

1. 计算每个源瓶的总质量$s_i = a_i + b_i$及其比例$r_i = a_i / (a_i + b_i)$。 对每个机构做同样的事情，获得$t_j = c_j + d_j$和$q_j = c_j / (c_j + d_j)$。 该比率是决定 A 和 B 在流量单位内如何分配的唯一信息。 
2. 按比例对源瓶进行排序$r_i$按递增顺序。 按比例对机构进行排序$q_j$按递增顺序。 这确保我们按照一致的顺序首先处理最“B 重”的混合物，最后处理最“A 重”的混合物。 
3. 维护两个指针，一个在源上，一个在机构上，并跟踪当前源和当前机构中的剩余质量。 
4. 通过在电流源和研究所之间转移尽可能多的质量来重复匹配电流源和研究所。 令转移量为剩余质量中的最小值。 转移后，相应减少两个剩余值。 
5. 当一个源耗尽时，移至下一个源。 当一个机构满意后，转移到下一个机构。 继续直到一侧完成。 
6. 如果最后双方都消耗完毕，则输出Yes。 否则输出No.

 这个过程有意义的原因是，在每一步中，我们都以单调顺序匹配最接近的可用比率，防止任何分配的“交叉”，从而导致以后出现不一致的凸组合。 

### 为什么它有效

 不变的是，在扫描中的任何点，所有已处理的源的比率不大于当前源，并且所有已处理的机构的比率不大于当前机构。 任何可行的解决方案都必须尊重这种顺序，因为否则较高比率的源将被部分分配给较低比率的研究所，而较低比率的源将被分配给较高比率的研究所，这会在所得混合物的凸分解中产生矛盾。 贪婪匹配强制不发生此类交叉，并且由于每次传输都在本地保留 A 和 B 比例，因此全局可行性降低为总质量是否可以在这种单调耦合下完美匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))
    d = list(map(int, input().split()))

    src = []
    dst = []

    for i in range(n):
        s = a[i] + b[i]
        src.append((a[i] / s, s))

    for j in range(m):
        t = c[j] + d[j]
        dst.append((c[j] / t, t))

    src.sort()
    dst.sort()

    i = j = 0
    rem_s = src[0][1] if n else 0
    rem_d = dst[0][1] if m else 0

    while i < n and j < m:
        r_i, _ = src[i]
        r_j, _ = dst[j]

        take = min(rem_s, rem_d)
        rem_s -= take
        rem_d -= take

        if rem_s == 0:
            i += 1
            if i < n:
                rem_s = src[i][1]

        if rem_d == 0:
            j += 1
            if j < m:
                rem_d = dst[j][1]

    print("Yes" if i == n and j == m else "No")

if __name__ == "__main__":
    solve()
```该实现将每个容器缩减为比率加权段，然后执行两指针扫描。 唯一的微妙之处是在切换段时正确保持剩余容量。 该算法永远不需要显式地分别跟踪 A 和 B，因为比率一致性是通过排序在结构上强制执行的。

 ### 示例 1

 我们按比率跟踪排序的源和目的地，然后模拟匹配。

 该过程干净利落地完成，这意味着所有质量都匹配，没有残留的不平衡。

 ## 边缘情况

 当所有源具有相同的比率时，就会出现关键的边缘情况。 在这种情况下，排序变得无关紧要，问题简化为简单的质量匹配，因为每次转移都保留相同的 A 到 B 比例。 该算法自然会处理这个问题，因为扫描永远不会产生不一致。 

另一种边缘情况是一侧的比率范围严格大于另一侧。 例如，如果所有来源都是低比率，但一个机构需要非常高比率的混合物，则排序可确保算法在达到高比率需求之前耗尽所有低比率供应，留下不匹配的需求并正确返回No。 

最后一种边缘情况是只有一个来源或一个机构时。 在这种情况下，解决方案简化为检查总质量相等，并且扫描会立即验证它，而不会产生中间歧义。
