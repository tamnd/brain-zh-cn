 ## 解决方案
 ## 问题理解

 我们会得到单个玩家的一系列测验结果，其中每个结果要么是正确的，要么是错误的。 玩家从零开始，等级只能增加。 

提高排名的规则基于回顾历史的最近部分。 在每次测验之后，我们尝试找到一些较早的起始位置，使得玩家在该起始位置之前已经处于当前排名，该段足够长，并且该段内的准确度足够高。 如果存在这样的段，则排名立即增加。 

以更可操作的方式重新表述，在处理完第 e 个测验后，我们想知道是否存在一个以 e 结尾的有效窗口，该窗口开始得足够晚（但不算太晚），长度至少为 c，并且其正确答案的比例至少为 p/q。 如果存在这样的窗口，则玩家的排名会增加一级，并且我们会继续检查同一时间位置的进一步晋升。 

输入大小最多允许 500,000 个测验。 参数 c 最多为 200，这强烈暗示任何依赖于扫描每个位置所有可能窗口的解决方案都太慢。 在最坏的情况下，尝试每个结束位置的所有起点的二次方法将需要大约 10^1 检查，这是不可行的。 

因此，正确的解决方案必须维护信息，让我们能够回答每个端点是否存在合格窗口，而无需重新扫描整个历史记录。 

当比率条件由于整数精度而几乎失败或几乎成功时，就会出现微妙的边缘情况。 例如，如果 p/q 为 1/2，则长度为 3、有 2 个正确答案的线段会通过，但长度为 2、有 1 个正确答案的线段恰好在边界上，也会通过。 任何使用浮点除法的解决方案都存在精度错误和对大输入的不正确提升的风险。 

另一个边缘情况是起始位置 s 必须尊重当前排名的约束：升级后，较早的有效开始变得无关紧要，因为玩家被认为已经在这些点之前离开了该排名。 

## 方法

 一种直接的方法是为每个结束索引模拟每个可能的起始索引。 对于每个 e，我们将尝试从 1 到 e 的所有 s，检查等级约束，检查长度约束，并计算该段上的比率。 即使我们预先计算前缀和，在最坏的情况下这仍然会退化为 O(n²) 检查，这对于 n 高达 5×10⁵ 来说太慢了。 

关键的观察是比率条件可以转化为线性不等式。 如果我们将正确答案映射到 1，将错误答案映射到 0，那么从 s 到 e 的段满足 sum / length ≥ p / q 当且仅当 q·sum ≥ p·(e − s + 1)。 重新排列给出了前缀和的条件：

 q·(前缀[e] − 前缀[s−1]) − p·(e − s + 1) ≥ 0。 

这可以重写为前缀比较：

 (prefix[e] 缩放) 减去 (prefix[s−1] 缩放) ≥ 0，其中每个位置为正确答案贡献 q，为长度的每个步骤贡献 -p。 这将问题转变为检查对于每个 e，在受限范围内是否存在索引 j = s−1，使得变换后的前缀差为非负。 

长度约束强制 s ≤ e − c + 1，即 j ≤ e − c。 排名约束将 s 限制为至少是当前排名开始的点，因此 j 也受到限制。 因此，对于每个e，我们需要知道在一个滑动区间内是否存在一个索引j使得前缀值足够小以满足prefix[e]≥prefix[j]。

该结构现在是针对前缀和的移动窗口最小查询。 由于 e 只增加，并且每个等级的左边界也只增加，因此我们可以为每个等级维护候选前缀索引的单调双端队列。 这允许在摊销 O(1) 中插入新索引和删除过时的索引，同时始终能够查询有效范围内的最小前缀。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 每个等级的单调前缀窗口 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们在转换后的序列上维护一个前缀数组和一个滑动结构，该结构始终允许我们查询当前排名的有效范围内的最小前缀值。 

1. 将输入字符串转换为一个数组，其中每个正确答案贡献 1，每个错误答案贡献 0，并在其上构建前缀和。 
2.对于当前排名，维护一个左边界L，它表示允许玩家开始分段的最早索引。 每当等级增加时，这个边界就会向前移动。 
3. 对于每个结束位置 e，计算是否存在有效的起始位置 s，使得 s ≥ L 且 s ≤ e − c + 1。这相当于检查 [L−1, e−c] 范围内的索引 j = s−1。 
4. 在前缀数组上维护索引 j 的双端队列，使得前缀值沿着双端队列递增。 这保证了双端队列的前面始终保存当前窗口中的最小前缀值。 
5. 随着 e 的增加，当新索引 e−c 符合条件时将其插入双端队列中，确保我们只考虑满足最小长度约束的开始。 
6. 如果索引落在 L−1 之前，则从双端队列的前面删除它们，因为它们由于等级限制而不再有效。 
7. 对于每个 e，将 prefix[e] 与存储在双端队列前面的最小前缀值进行比较。 如果 prefix[e] 大于或等于，则存在有效段并且发生提升。 
8. 当晋升时，提高等级并将L移动到e+1。 重新初始化或调整双端队列状态，因为较早的启动对于新排名不再有效。 

### 为什么它有效

 在任何固定端点 e 和等级处，以 e 结尾的每个有效段完全对应于受限区间内 j = s−1 的选择。 成功的条件仅取决于比较 prefix[e] 和 prefix[j]，因此我们只需要该区间内的最小 prefix[j]。 单调双端队列有效地维持这个最小值，同时间隔的两端随着时间的推移向前移动，从而在不重新扫描历史的情况下保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c, p, q = map(int, input().split())
    s = input().strip()

    # prefix sums of correct answers
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (1 if s[i - 1] == 'Y' else 0)

    rank = 0
    L = 1  # 1-based index of first quiz in current rank
    from collections import deque
    dq = deque()

    # we will maintain candidates j = s-1, so j in [0..n]
    # condition: pref[e] >= pref[j] + threshold transformation handled below

    # transform inequality:
    # q*(pref[e]-pref[s-1]) >= p*(e-s+1)
    # => q*pref[e] - p*e >= q*pref[s-1] - p*(s-1)
    # so we compare transformed prefix values

    trans = [0] * (n + 1)
    for i in range(0, n + 1):
        trans[i] = q * pref[i] - p * i

    # dq maintains indices with increasing trans value
    add_ptr = 0

    for e in range(1, n + 1):
        # add new candidate start index j = e-c
        j = e - c
        if j >= 0:
            while dq and trans[dq[-1]] >= trans[j]:
                dq.pop()
            dq.append(j)

        # remove out of range for rank
        while dq and dq[0] < L - 1:
            dq.popleft()

        # check promotion
        while dq and trans[e] >= trans[dq[0]]:
            rank += 1
            L = e + 1
            dq.clear()
            break

    print(rank)

if __name__ == "__main__":
    solve()
```该实现首先将问题压缩为前缀和，然后使用转换后的前缀表达式将比率条件转换为线性比较。 这完全避免了浮点运算。 

双端队列存储由变换后的前缀值索引的候选起始点，始终将最佳候选保持在前面。 有效开始的滑动性质是通过丢弃落在当前排名允许边界之前的索引来处理的。 当升级发生时，系统会重置允许的起始边界，这也会使所有先前存储的候选者无效，因此双端队列被清除。 

这里的一个常见错误是忘记条件取决于段长度，这就是变换包含项 -p·i 的原因。 没有它，不等式就不能简化为简单的前缀最小查询。

import sys, io

def run(inp: str) -> str:

    n, c, p, q = map(int, input().split())

            L = e + 1
            dq.clear()
            break

 ## 边缘情况

 当第一个可能的有效段恰好出现在长度 c 时，就会出现一种边缘情况。 该算法通过仅在候选起始索引有效后插入它们来处理此问题，确保不会过早评估。 

另一个边缘情况是，理论上同一端点可能会发生多次升级。 该实现在每次升级后清除双端队列并移动左边界，确保在后续检查中永远不会重复使用过时的起点。 

第三种边缘情况是严格下降的性能模式，其中没有段满足比率条件。 在这种情况下，双端队列可能仍然会积累候选者，但不会通过任何前缀比较，因此排名保持为零，并且不会触发无效提升。
