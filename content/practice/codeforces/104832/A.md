 ## 解决方案
 ## 问题理解

 我们有一个小的矩形网格，其中每个单元格包含六个字母之一：Y、O、K、O、H、A、M、A。从这个网格中，我们想要计算有多少种方式可以追踪长度为 8 的特定固定单词：Y 后面跟着 O、K、O、H、A、M、A。 

有效迹线是网格中八个单元格的序列。 第一个单元格必须包含 Y，第二个单元格必须包含 O，依此类推。 序列中的连续单元必须共享边缘，这意味着我们朝四个方向移动：上、下、左或右。 单元可能会被重新访问，因此路径不需要很简单。 

输出是准确拼写模式的不同有效单元序列的数量。 如果序列中的任何位置引用不同的网格单元，则即使字母序列相同，也认为两条迹线不同。 

网格最多为 10 x 10，因此最多有 100 个单元格。 这个小界限立即表明，只要我们使用固定模式长度积极修剪，指数搜索是可以接受的。 

一些边缘情况很重要：

 除非存在匹配 O K O H A M A 的完整 7 步邻接链，否则单个 Y 单元无法形成迹线。如果网格有许多 Y，但没有相邻的 Os，则答案为零。 

网格中重复的字母允许在路径中多次重新访问同一单元格，这意味着天真的“标记已访问并禁止重复使用”DFS 会错误地少计数。 

由于模式长度是固定的且很小，因此探索长度最多为 8 的部分路径的任何解决方案都是可行的。 

## 方法

 强力方法是将每个 Y 单元格视为起点，然后执行深度优先搜索，尝试长度为 7 的所有可能的移动，在每一步验证下一个单元格是否与序列中所需的字符匹配。 每一步最多分支到四个方向，因此在最坏的情况下，从一个起始 Y 开始的探索路径数量约为$4^7 = 16384$。 由于起始位置多达 100 个，这会产生大约 160 万条部分路径，这在 Python 中已经可以接受，但会浪费精力尽早探索无效分支。 

关键的观察是我们匹配的单词是固定的并且非常短。 我们可以将问题视为一个位置的状态空间，与我们在模式中的进展程度相匹配，而不是盲目探索。 每个状态由一个网格单元和字符串 YOKOHAMA 中的索引定义。 从每个状态，我们仅转换到与下一个所需字符匹配的邻居。 这会立即修剪几乎所有分支，因为不匹配的字母会立即被丢弃。 

这会将问题转换为分层动态规划或记忆 DFS，最多包含 100 个单元乘以 8 个模式位置，从而提供非常小的状态空间。 每个状态都计算一次，并且最多四个邻居的转换是恒定时间的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 来自每个 Y 的强力 DFS | O(nm·4^8) | O(8) 递归 | 太慢/临界|
 | DP / 记忆化 DFS（单元格、索引）| O(nm·8·4)| O(纳米·8)| 已接受 |

 ## 算法演练

 我们将网格重新解释为一个图表，其中每个单元与其四个相邻单元相连。 我们还将目标词视为位置 0 到 7 的序列。 

1. 定义一个函数，返回从模式中给定索引处的给定单元格开始存在多少个有效完成。 索引指示我们在这一步必须匹配哪个字符。 这使我们能够将问题分解为重叠的子问题。 
2. 如果当前单元格的字符与当前索引处的模式不匹配，则立即返回零。 这确保我们永远不会传播无效的部分路径。 
3. 如果索引为 7，意味着我们已成功匹配此单元格中的最后一个字符 A，则返回 1。 这表示完整的有效跟踪在此结束。 
4. 否则，迭代四个可能的相邻移动。 对于每个邻居，递归计算该邻居在索引 + 1 处存在多少个有效完成，并对所有结果求和。 
5. 将每个（单元格，索引）对的结果存储在备忘录表中，以便重复访问不会重新计算相同的子树。 这很重要，因为许多不同的路径可以到达相同的状态。 
6. 通过对索引 0 处包含 Y 的每个单元格启动 DFS 的结果求和来初始化最终答案。 

递归自然地强制执行邻接，因为我们只沿着边缘移动，并且它强制执行排序，因为我们仅在移动到有效的下一个字符时才推进索引。 

### 为什么它有效

 当我们需要匹配pattern[i:]时，状态(r,c,i)唯一地表示从单元格(r,c)开始的有效后缀路径的数量。 在此状态下计数的任何路径都必须从 (r, c) 开始，并遵循与其余字符严格匹配的有效邻接步骤。 因为每个递归转换都会将索引前进一倍，所以没有路径可以跳过或重新排序字符。 记忆化可确保我们计算每个状态一次而不改变其含义，从而在消除重复工作的同时保留正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

pattern = "YOKOHAMA"
dr = [1, -1, 0, 0]
dc = [0, 0, 1, -1]

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    
    from functools import lru_cache

    @lru_cache(None)
    def dfs(r, c, i):
        if grid[r][c] != pattern[i]:
            return 0
        if i == 7:
            return 1
        
        res = 0
        for k in range(4):
            nr, nc = r + dr[k], c + dc[k]
            if 0 <= nr < n and 0 <= nc < m:
                res += dfs(nr, nc, i + 1)
        return res

    ans = 0
    for r in range(n):
        for c in range(m):
            if grid[r][c] == 'Y':
                ans += dfs(r, c, 0)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接将状态 (r, c, i) 编码为记忆化 DFS 函数。 字符检查会立即发生，因此无效分支会提前终止。 

基本情况 i == 7 确保我们只计算以最终 A 结尾的完整匹配。递归仅在边界内进行，防止无效的网格访问。 

外循环将起始状态限制为 Y 单元，这减少了不必要的调用。 

## 工作示例

 ### 示例 1

 输入：```
2 4
YOHA
OKAM
```我们从每个 Y 开始跟踪 DFS 状态。 

| 开始 (r,c) | 下一步 | 有效完成 |
 | ---| ---| ---|
 | (0,0) | (0,0) | Y → O → K → O → H → A → M → A | 2 |
 | 其他 | 早期失配| 0 |

 两条有效轨迹对应于在小网格周围路由的不同方式，同时尊重邻接约束。 这证实了多个不同的路径可以共享相同的字母序列。

 输入：```

KHAM
```| 开始 (r,c) | 进展| 结果 |

 | (0,0) | (0,0) | YOKO...提前失败 | 0 |

        for c in range(m):
            if grid_lines[r][c] == 'Y':
                ans += dfs(r, c, 0)
    return str(ans)

 ## 边缘情况

 包含 YOKOHAMA 的单行网格应该恰好生成一条路径。 DFS 从 Y 开始，每一步都有一个与下一个字符匹配的有效邻居，因此除了线性进展之外，甚至不需要记忆。 

字母存在但断开连接的网格（例如被非 O 单元包围的 Y 单元）将导致在索引 1 处立即修剪。状态 (r,c,0) 存在，但所有转换都会失败，产生零。 

填充 Y 的网格除了其他地方的单个有效链之外仍然只计算有效的邻接链，因为递归在每一步强制执行精确的字符匹配，而不仅仅是字母的频率。 

每个单元格都是 Y 或 O 的密集网格会导致最大分支，但记忆化会折叠重复的子问题，以便每个（单元格，索引）对被评估一次，确保即使在最坏情况配置下运行时间也保持稳定。
