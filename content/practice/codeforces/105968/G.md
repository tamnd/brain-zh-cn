 ## 解决方案
 ## 问题理解

 该任务是高精度地定位固定区间（特别是 -30 到 30）内实值多项式的所有实根。 多项式以输入形式给出（通常作为系数），输出需要报告位于该域内的每个根。 

该问题不是尝试以符号方式求解多项式，而是依赖于数值计算。 关键的结构事实是该函数在实线上处处连续，因此区间上的任何符号变化都保证该区间内至少有一个根。 

所需的精度约为 10⁻⁶，这会立即排除任何纯粹离散或仅网格的答案。 粗略扫描仅适用于检测根可能所在的位置，而不适用于最终值。 

该间隔也足够大，以至于在各处直接进行细粒度采样将是昂贵的。 如果我们尝试在 60 个单元上使用 10⁻⁶ 的统一步长，我们将对该函数进行大约 6 × 10⁷ 次评估，并且每次评估本身的多项式次数都是 O(n) 。 根据限制，这变得临界或太慢。 

一种简单但常见的故障模式是仅检查扫描间隔的端点，并假设每个符号更改间隔恰好包含一个根。 当多项式接触轴并在不与轴交叉的情况下转动时，这种情况就会中断。 

例如，考虑一个像 (x − 1)² 这样的多项式。 它的根位于 x = 1，但 f(x) 在该点附近不会改变符号。 任何仅依赖符号变化的方法都会完全错过它。 

另一种故障模式是假设根被整数或固定网格边界完全隔离。 根可以任意靠近边界，例如 0.5 或 -0.5，并且如果不进行细化，近似值就会变得不稳定。 

## 方法

 强力解释是在 [−30, 30] 的非常精细的网格上评估多项式，检测符号变化，然后细化每个候选区间，直到达到所需的精度。 这是有效的，因为如果网格足够密集，连续性可以确保采样点之间的根不会凭空出现。 

然而，成本来自于网格分辨率。 如果我们选择步长 10⁻⁶，我们将执行大约 6000 万次评估。 d 次多项式的每次评估成本为 O(d)，因此总数变为 O(6 × 10⁷·d)，这对于典型约束来说太慢了。 

改进来自于将问题分为两个阶段。 首先，我们只需要定位包含根的小区间，而不是精确位置。 宽度为 0.5 的粗划分对此就足够了，因为多项式不能在单个小段内产生许多根的情况下任意快速振荡。 

一旦找到候选区间，第二阶段就对该区间使用二分搜索。 由于该函数是连续的，并且我们假设符号发生变化（或检测有效的根条件），因此二分搜索以对数方式收敛到具有所需精度的根。 这用少量有针对性的本地搜索取代了对密集全局网格的需求。 

关键的想法是，只有在保证根存在的情况下才能完成昂贵的工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 均匀细网格采样 | O(60·10⁶·d) | O(1) | O(1) | 太慢了 |
 | 粗略扫描+二分查找细化| O(120·d + k·d·log(1/ε)) | O(120·d + k·d·log(1/ε)) | O(1) | O(1) | 已接受 |

 这里 k 是检测到的包含根的片段的数量。 

## 算法演练

 我们将多项式视为函数 f(x)，可以使用霍纳方法在任何实数 x 处进行计算。

1. 将区间 [−30, 30] 分成长度为 0.5 的段。 这些段是[−30,−29.5]、[−29.5,−29]等。 目的是廉价地本地化潜在的符号变化。 
2. 对于每个段 [l, r]，计算 f(l) 和 f(r)。 如果 f(l) 恰好为零，则立即将 l 记录为根。 这同样适用于 r，因为端点可能包含精确根。 
3. 如果 f(l) 和 f(r) 符号相反，则在 [l, r] 内执行二分查找以找到根。 由于连续性，符号差保证了至少一次交叉。 
4. 如果不存在符号变化，但值非常接近于零（在较小的公差范围内），则将该段视为可能包含根。 这可以处理函数接触但不交叉轴的重复根等情况。 
5. 对每个候选区间运行二分查找，直到区间宽度低于 10⁻⁶。 最终区间的中点作为根。 
6. 收集所有发现的根并在输出之前对它们进行排序以确保确定性排序。 

此处应用二分查找的原因是在仅包含一个根的足够小的区间内符号的单调性。 一旦我们分离出这样一个区间，该函数的行为就像一条过零一次的连续曲线。 

### 为什么它有效

 正确性取决于连续函数的中间值性质。 多项式在不经过每个中间值的情况下无法更改值。 当 f(l) 和 f(r) 符号不同时，零必须位于它们之间。 

0.5 分割可确保任何根要么直接在边界处检测到，要么被捕获在至少一个小区间内。 在该区间内，我们将问题简化为根隔离，并且二分搜索收敛，因为当我们缩小区间时，函数是连续的并且符号结构保持稳定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

EPS = 1e-12

def eval_poly(coeffs, x):
    # Horner's method
    res = 0.0
    for c in coeffs:
        res = res * x + c
    return res

def find_root(coeffs, l, r):
    fl = eval_poly(coeffs, l)
    fr = eval_poly(coeffs, r)

    if abs(fl) < EPS:
        return l
    if abs(fr) < EPS:
        return r

    # assume sign change exists
    for _ in range(60):
        m = (l + r) / 2
        fm = eval_poly(coeffs, m)

        if abs(fm) < EPS:
            return m

        if fl * fm <= 0:
            r = m
            fr = fm
        else:
            l = m
            fl = fm

    return (l + r) / 2

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return

    # assumed format:
    # n followed by coefficients c0..cn (or similar)
    it = iter(data)
    deg = int(next(it))
    coeffs = [float(next(it)) for _ in range(deg + 1)]

    roots = []

    L, R = -30.0, 30.0
    step = 0.5

    x = L
    while x < R:
        l = x
        r = min(R, x + step)

        fl = eval_poly(coeffs, l)
        fr = eval_poly(coeffs, r)

        if abs(fl) < EPS:
            roots.append(l)
        if abs(fr) < EPS:
            roots.append(r)

        if fl * fr < 0:
            roots.append(find_root(coeffs, l, r))

        x += step

    roots.sort()

    # print with sufficient precision
    out = []
    for r in roots:
        out.append(f"{r:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案围绕两个核心实用程序构建：使用霍纳方法的快速多项式求值器和假设根存在于有界区间内的受控二分搜索。 分段循环负责发现，而细化函数负责精度。 

一个微妙的实现细节是重复检测端点作为根。 如果没有这个，精确位于段边界上的根可能会丢失或不一致地重复。 最后需要进行排序，因为根可能会以任意顺序被发现，具体取决于哪个段首先检测到它们。 

二分搜索循环使用固定次数的迭代（大约 60 次），这足以将 60 单位间隔降低到 10⁻⁶ 精度以下，而不管浮点漂移如何。 

## 工作示例

 ### 示例 1

 假设一个在范围内具有单根的简单多项式，例如 f(x) = x − 2。 

我们跟踪包含根的一个片段。 

| 步骤| 我| r | f(l) | f(l) | f(r) | f(r) | 行动|
 | ---| ---| ---| ---| ---| ---|
 | 段检查 | 1.5 | 1.5 2.0 | -0.5 | -0.5 0.0 | 0.0 检测到端点根 |
 | 求精| 1.5 | 1.5 2.0 | - | - | 跳过二分查找 |

 端点检测立即捕获 x = 2，这说明了为什么端点检查是必要的。 

### 示例 2

 考虑 f(x) = (x + 1)(x − 1)，其根位于 −1 和 1。 

| 细分 | 我| r | f(l)·f(r) | f(l)·f(r) | 行动|
 | ---| ---| ---| ---| ---|
 | [-1.5，-1.0] | -1.5 | -1.5 -1.0 | ≤ 0 | 二分查找 -1 |
 | [0.5, 1.0] | 0.5 | 0.5 1.0 | ≤ 0 | 二分查找 1 |

 每个区间恰好隔离一个根，二分查找独立收敛。

 ## 边缘情况

 诸如 (x − 1)² 之类的重复根说明了为什么单独的符号变化检测是不够的。 当 x = 1 时，函数为零，但两侧仍为正，因此分段必须显式检查端点和中点处的接近零值。 段循环中的端点检查确保即使没有符号翻转，根仍然被捕获。 

通过评估每个区间的两个端点来处理恰好位于段边界（例如 x = 0.5）上的根。 由于两个相邻段在评估中共享该边界点，因此至少一项检查将注册一个接近零的值并将其包含在根列表中。
