 ## 解决方案
 ## 问题理解

 该问题对一个图进行了建模，其中城市之间的旅行不仅在边权重方面成本高昂，而且还改变了称为声誉的次要状态。 系统的每个状态由节点和信誉值组成的对来描述。 从信誉为 0 的节点 1 开始，我们感兴趣的是在不同可能的信誉级别（最高上限 K）下到达每个节点的成本有多低。 

每次我们遍历一条边时，我们都会付出其成本，并且我们的声誉会增加一，除非它已经达到最大值 K。一旦我们达到 K，行为就会发生变化：声誉不会继续增长，而是有效地重置为 0。这使得状态空间在声誉维度上是循环的，而不是线性的。 

目标是计算当最终信誉为 K 时到达每个节点的最小成本。计算这些成本后，我们为每个节点给出值 v[i]，并且我们希望最大化净增益 v[i] 减去在状态 K 下到达节点 i 的最小旅行成本。只有正结果才重要，因为负值被忽略。 

这些约束意味着对所有路径的简单方法是不可能的，因为状态数量是 N 乘以 K，并且每个状态的每个边都存在转换。 即使在没有优先级队列的情况下存储或放松路径也会迅速降级到与 N 乘以 K 乘以 M 成比例的值，这远远超出了可行的限制。 由于所有边权重都是非负的，因此需要在扩展状态图上使用 Dijkstra 式的最短路径。 

在处理 K 处的声誉环绕时会出现一个微妙的问题。粗心的实现可能会将声誉视为简单地固定在 K 处，从而失去重置为零的行为。 例如，如果 K 等于 2 并且我们处于状态 (u, 2)，则在多一条边之后我们将移动到 (v, 0)，而不是 (v, 2)。 无法对该循环进行建模会破坏正确性，因为有意循环 K 的路径可能会重新启动该过程。 

另一个棘手的情况是假设通过单调增加到达具有信誉 K 的节点始终是最佳的。 由于重置行为，较早到达 K 然后循环的路径可能比小心避免过早到达 K 的路径更便宜。 

## 方法

 暴力解决方案将处理从节点 1 开始的每条可能路径，跟踪当前节点和当前声誉，并探索所有可能性。 每一步都沿着边缘分支，更新声誉并累积成本。 这实际上是在扩展图中枚举包含 N 倍 K 状态和每个状态 M 次转换的游走。 即使进行剪枝，探索的状态数量也会随着路径长度呈指数增长，因为不同的边序列可以以不同的成本产生相同的节点信誉对，需要重复探索。 

关键的结构观察是我们仍在处理具有非负权重的有向状态图上的最短路径。 每个状态都是一对 (u, r)，并且转换是确定性的：从 (u, r) 开始，每条边 (u, v, w) 精确地导向一个取决于 r 的下一个状态。 这意味着问题完全简化为 N 次 (K+1) 个节点上的最短路径计算，这可以使用 Dijkstra 算法来解决。 

唯一的复杂之处是正确定义状态转换。 如果 r 小于 K，则 r 加一。 如果 r 等于 K，则它重置为 0。这使得图非分层但仍然是静态的，因此标准 Dijkstra 无需修改即可应用。 

然后我们计算所有状态的 dist[u][r]，最后提取每个节点 i 的 dist[i][K] 来评估最终答案。

 | ---| ---| ---| ---|
 | 路径的暴力枚举| 指数| 指数| 太慢了 |
 | Dijkstra 论扩展状态图 | O((N + M) · K · log(NK)) | O((N + M) · K · log(NK)) | O(NK) | 已接受 |

## 算法演练

 我们将问题转换为扩展图上的最短路径，其节点是对 (u, r)，其中 u 是图节点，r 是当前声誉。 

1. 我们定义一个距离表 dist[u][r]，除了 dist[1][0] 被设置为 0 之外，所有状态都初始化为无穷大。这编码我们从节点 1 开始，成本为零，信誉为零。 
2. 我们使用按当前距离排序的优先级队列，并在这些扩展状态上运行 Dijkstra 算法。 队列中的每个条目代表一对 (current_cost, u, r)。 这确保我们始终首先扩展最便宜的已知状态，这是至关重要的，因为所有转换都保留非负权重。 
3. 当处理状态 (u, r) 时，我们迭代所有边 (u, v, w)。 遍历后我们计算下一个信誉：如果r小于K，则下一个信誉为r + 1，否则由于重置规则而变为0。 
4. 我们通过检查 dist[u][r] + w 是否改进了 dist[v][nr] 来放松边缘，其中 nr 是计算出的下一个信誉。 如果是，我们更新距离并将 (dist[v][nr], v, nr) 推入优先级队列。 这确保了探索到达相同状态的更好路径。 
5. 算法完成后，我们提取每个节点 i 的 dist[i][K]。 节点 i 的最终答案是 max(0, v[i] - dist[i][K])。 

它的工作原理与扩展状态图的结构有关。 原始问题中的每一次有效行走都恰好对应于状态图中的一条路径，并且每次转换都保留了声誉演化的正确性。 由于所有边权重都是非负的，Dijkstra 保证一旦以最小的成本处理一个状态，以后就不会出现更便宜的路径。 这确保了 dist[u][r] 对于每个状态始终是最优的，因此 dist[i][K] 是以最终信誉 K 到达节点 i 的真实最小成本。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
    
    INF = 10**30
    dist = [[INF] * (k + 1) for _ in range(n + 1)]
    dist[1][0] = 0
    
    pq = [(0, 1, 0)]
    
    while pq:
        d, u, r = heapq.heappop(pq)
        if d != dist[u][r]:
            continue
        
        for v, w in g[u]:
            if r < k:
                nr = r + 1
            else:
                nr = 0
            
            nd = d + w
            if nd < dist[v][nr]:
                dist[v][nr] = nd
                heapq.heappush(pq, (nd, v, nr))
    
    ans = []
    for i in range(1, n + 1):
        cost = dist[i][k]
        if cost < INF:
            ans.append(max(0, v[i] - cost))
        else:
            ans.append(0)
    
    print(*ans)

if __name__ == "__main__":
    solve()
```该实现直接反映了扩展状态 Dijkstra 公式。 距离表是二维的，因为声誉是国家的一部分。 优先级队列确保我们始终处理最便宜的未处理状态。 

一个微妙的实现细节是严格的相等性检查`if d != dist[u][r]`，这可以避免重新处理过时的堆条目。 如果没有这个，算法可能仍然是正确的，但性能会显着下降。 

另一个重要的细节是正确处理换行行为。 转换逻辑在决定是否重置为零之前显式检查 r 是否为 K。 放错这个条件将完全改变可达状态的结构。 

最后，答案提取仅使用 dist[i][K]，因为该问题专门要求结束信誉 K。 

## 工作示例

 ### 示例 1

 考虑一个小图，其中 K 等于 2，并且存在一条权重不断增加的路径 1 → 2 → 3。 

我们跟踪 Dijkstra 扩张期间的状态。 

| 步骤| State (u, r) | 距离 | Relaxed State | New Distance |
 | ---| ---| ---| ---| ---|
 | 1 | (1, 0) | (1, 0) | 0 | (2, 1) | w(1,2) |
 | 2 | (2, 1) | w12 | (3, 2) | w12 + w23 |

 这表明在两次转变后自然会达到声誉 K。 在状态 2 中到达节点 3 的最终成本正是路径成本，确认 dist[3][2] 捕获了预期的端点状态。 

### 示例 2

 现在考虑 K = 1，其中每个边沿在达到 K 后立即触发复位。 

| 步骤| 状态 (u, r) | 距离 | 下一个状态 | 新声誉|
 | ---| ---| ---| ---| ---|
 | 1 | (1, 0) | (1, 0) | 0 | (2, 1) | 1 |
 | 2 | (2, 1) | w12 | (3, 0) | (3, 0) | 重置|

 在这里我们清楚地看到了循环的本质。 继续行走的路径不会线性累积声誉，而是在 1 和 0 之间交替。这证实了为什么我们必须将 (u, 0) 和 (u, K) 视为根本不同的状态，即使两者都可以经常重新访问。

 ## 边缘情况

 一种边缘情况是 K 等于 0 或 1。如果 K 为 0，则每次遍历都会立即重置信誉，因此所有状态都会崩溃为频繁重置。 该算法仍然有效，因为状态空间包括 (u, 0) 并且转换始终返回到 0，从而有效地减少到标准最短路径。 

另一个边缘情况是当多个路径到达具有不同信誉历史的同一节点时。 该算法正确区分了它们，因为 dist[u][r] 与 dist[u][r’] 是分开的。 幼稚的单距离/节点方法在这里会失败，因为它会用更便宜但不太有用的中间状态路径覆盖更好的未来状态路径。 

最后一种情况是，最优路径故意循环通过 K 边界多次以正确调整声誉。 因为 Dijkstra 独立地探索所有状态，所以它自然地解释了这些循环，而不需要特殊处理。
