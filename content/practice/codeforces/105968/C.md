 ## 解决方案
 ## 问题理解

 我们有两个字符串序列。 第一个序列表示原始消息集合，第二个序列表示后来可能损坏的消息流。 已知第二序列中的某些字符串会使原始序列中的匹配字符串“无效”。 

任务是确定原始序列中的哪些字符串在处理第二个序列后仍然有效。 具体来说，如果某个字符串同时出现在原始列表和更改列表中，则删除原始列表中该字符串的每个出现位置。 输出是剩余的原始字符串，按原始顺序打印。 

结构的重要性有两个方面。 首先，成员资格检查必须很快，因为字符串会在两个列表中进行多次比较。 其次，输出必须保留原始顺序，这排除了任何纯粹通过排序或集合迭代重建答案的解决方案。 

尽管该语句暗示了排序和集合的使用，但真正的约束是对可能很大的列表进行重复的成员资格查询。 如果字符串总数达到 10^5 左右，则两个列表之间的任何二次比较都变得不可行，因为在最坏的情况下需要进行 10^10 次字符串比较。 这立即迫使我们转向基于哈希的结构，例如集合。 

当原始列表中存在重复项时，会出现微妙的边缘情况。 如果一个字符串出现多次，并且后来被第二个列表失效，则所有出现的字符串都必须消失，而不仅仅是一个。 例如，如果原始列表是`["a", "b", "a"]`更改后的列表包含`"a"`，正确的输出是一个空列表。 仅删除第一个匹配项的粗心实现将错误地输出`["b", "a"]`。 

当更改后的列表中没有字符串与原始列表相交时，会出现另一种边缘情况。 在这种情况下，输出必须与原始列表完全匹配，保留顺序和重复项。 任何错误地从集合重建的实现都会丢失重复项或重新排序元素。 

## 方法

 直接方法可以从字面上模拟该过程。 我们可以迭代更改列表中的每个字符串，并且对于每个字符串，扫描原始列表并删除匹配的元素。 这是简单且正确的，因为它直接强制执行“删除已更改列表中出现的每个原始字符串”的规则。 然而，每次删除都需要扫描原始列表，并且在最坏的情况下两个列表都包含 n 个元素。 这会导致 O(n^2) 次字符串比较，当 n 很大时，速度太慢。 

效率低下的原因在于对不断增长或缩小的名单进行重复的成员资格检查。 列表中的每次查找都是线性的，并且对每个更改的字符串重复查找会增加成本。 

关键的观察是我们不需要重复扫描。 我们只需要知道某个字符串是否出现在更改后的列表中。 如果我们将所有更改的字符串存储在哈希集中，则成员资格检查平均变为 O(1)。 然后，我们可以简单地在一次传递中过滤原始列表，仅保留更改集中不存在的字符串。 

原链表仍然必须按顺序处理，但遍历时不需要进行结构修改。 我们只决定是否将每个元素附加到输出中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 通过扫描暴力删除 | O(n²) | O(1) | O(1) | 太慢了 |
 | 哈希集过滤| O(n) 平均 | O(n) | 已接受 |

 ## 算法演练

 1. 读取原始字符串列表和更改后的字符串列表。 目标是确定哪些原始字符串被第二个列表“无效”。 
2. 将更改列表中的每个字符串插入到哈希集中。 这将成员资格检查转变为平均恒定时间的操作。 使用集合的原因是我们只关心存在性，而不关心频率。 
3.从左到右遍历原始链表。 对于每个字符串，检查它是否存在于更改集中。 
4. 如果该字符串不在更改集中，则将其附加到结果列表中。 如果存在，则完全跳过它，通过过滤有效地删除所有出现的情况。 
5. 按顺序输出结果列表，保留幸存元素中的重复项。 

### 为什么它有效

 该算法依赖于以下不变式：在扫描原始列表期间的任何点，更改的集合完全代表必须删除的所有字符串。 由于集合成员资格是静态的并且在过滤开始之前计算，因此每个决策都是独立的且最终的。 当且仅当未标记为删除时，每个原始字符串都会包含在输出中，并且因为我们从不重新排序或部分删除重复项，所以幸存元素的相对顺序与输入保持相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    
    # We assume format: n m, then n strings, then m strings
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    
    original = [next(it) for _ in range(n)]
    altered = {next(it) for _ in range(m)}
    
    res = []
    for s in original:
        if s not in altered:
            res.append(s)
    
    sys.stdout.write("\n".join(res))

if __name__ == "__main__":
    solve()
```该实现首先从更改的列表中构建一个集合，以便查找时间恒定。 原始列表存储为数组以保持顺序。 过滤循环是算法步骤的直接转换，我们根据集合中的成员资格决定包含内容。 

一个常见的错误是尝试在迭代时从原始列表中就地删除元素。 这会导致跳过元素或索引错误。 另一个问题是使用已更改集合的列表，这会由于线性成员资格检查而默默地降低性能。

 ## 边缘情况

 关键的边缘情况是原始列表中重复的字符串，如果更改后的列表中存在这些字符串，则必须将其全部删除。 对于像这样的输入`["a", "a", "b"]`与改变`["a"]`，算法处理每个`"a"`独立地删除两者，因为成员资格是按元素检查的，而不是按位置检查的。 该集合确保一旦`"a"`被标记为无效，每次出现都会被一致地过滤掉。 

另一个边缘情况是更改后的列表为空。 该集合变空，因此每次成员资格检查都会失败，并且原始列表按顺序原封不动地返回。 这证实了该算法不会引入意外的过滤。
