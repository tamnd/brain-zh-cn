 ## 解决方案
 ## 问题理解

 该任务呈现以文本形式而不是本机整数类型编写的单个数字。 该数字可能非常大，超出了大多数编程语言中的标准整数类型可以存储的范围，因此必须将其作为原始字符串进行处理。 

所需的输出仅取决于该数字是否为负数。 如果代表负值，则答案为一个值，否则为相反值。 实际上，我们正在评估 Heaviside 阶跃函数，它将所有负输入折叠到一个桶中，将所有非负输入折叠到另一个桶中。 

由于数字的大小可能超出内置的数字限制，因此任何尝试将其解析为整数类型的方法都会面临溢出或未定义行为的风险。 这迫使解决方案完全依赖于字符串检查而不是算术。 

这些约束隐式意味着每个测试用例的恒定时间处理，因为操作不依赖于数值本身，而仅依赖于其符号。 尽管读取整个字符串需要其长度的线性时间，但就数值大小而言，决策步骤必须是 O(1)。 

尝试直接整数转换时会发生简单的实现失败。 例如，像“-1000000000000000000000000000000”这样的值不能安全地存储在 32 位或 64 位整数类型中。 正确的输出仅取决于前导字符，因此不需要解析其余数字。 

另一个微妙的边缘情况是输入恰好为零，写为“0”或可能为“-0”。 粗心的数字解析器可能会将“-0”规范化为 0，但基于字符串的逻辑正确地将任何以“-”开头的字符串视为负数。 

## 方法

 暴力方法是使用内置解析将输入解释为完整整数，然后检查它是否小于零。 这在概念上很简单：将字符串转换为数字类型并与零进行比较。 正确性遵循标准算术规则。 

然而，这种方法在限制下会失败，因为数字可能具有任意长度。 将具有数百万位数字的字符串转换为整数需要成比例的内存分配和数字处理，这可能会超出时间和内存限制。 更关键的是，许多语言在尝试转换时会因溢出而彻底失败。 

关键的观察结果是，以标准十进制表示形式编写的数字的符号完全由其第一个字符确定。 如果第一个字符是减号，则数字为负数； 否则它是非负的。 无需进一步检查。 

这将问题从任意精度算术简化为单个字符检查，这是读取输入后的恒定时间。

 ## 算法演练

 1. 将输入数字作为字符串读取，而不是尝试进行数字转换，因为该值可能超出标准整数限制。 
2. 检查字符串的第一个字符。 
3. 如果第一个字符是“-”，则将该数字分类为负数，并输出负数输入的相应结果。 
4. 否则，将数字分类为非负数，并输出零或正输入的相应结果。 

### 为什么它有效

以标准形式编写的十进制整数将其符号显式编码为可选的前导“-”字符。 所有其余字符均表示大小，并且不影响该值是高于还是低于零。 由于输入格式中不存在替代符号表示，因此第一个字符完全确定分类。 因此，该算法根据单个确定性属性将所有有效输入恰好划分为两个不相交的集合，从而确保正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    if not s:
        return
    if s[0] == '-':
        sys.stdout.write("0")
    else:
        sys.stdout.write("1")

if __name__ == "__main__":
    solve()
```该解决方案将输入读取为原始字符串，以避免任何数字解析问题。 唯一的决定点是第一个字符检查。 如果它是负号，则输出是与负输入对应的值，否则假设非负情况。 

一个微妙的实现细节是使用`strip()`删除尾随换行符。 这确保了第一个字符检查是有效的。 不执行额外的解析，这避免了溢出或不必要的计算的风险。

 ## 边缘情况

 一种边缘情况是不带符号的零表示。 用于输入`"0"`，该算法将第一个字符读取为`'0'`，与负条件不匹配，因此它正确输出非负结果。 

另一个边缘情况是`"0000"`或其他填充表示。 由于不存在减号，因此无论格式如何，该函数都会将其分类为非负数。 

结构上的负零，例如`"-0"`处理正确，因为第一个字符是明确的`'-'`。 即使数值为零，该表示形式也会对问题所依赖的符号信息进行编码。 

一个非常长的整数，例如`"-1000000...000"`不会影响正确性，因为只检查第一个字符，因此无论长度如何，性能和正确性都保持稳定。
