 ## 解决方案
 ## 问题理解

 给定一个或多个非负整数序列。 对于每个序列，我们希望找到未出现在该序列中任何位置的最小非负整数。 该值称为 MEX，是“最小排除值”的缩写。 

将数组视为数轴上从零开始的标记整数的集合。 有些数字存在，有些则缺失。 任务是识别从 0 向上扫描时的第一个间隙。 

输入格式通常提供多个测试用例，并且对于每个测试用例，序列长度后跟序列本身。 每个测试用例的输出是一个整数，代表 MEX。 

这里没有明确说明约束，但预期的解决方案在每个测试用例的线性时间内运行。 这强烈表明测试用例中所有数组大小的总和最多约为 2 × 10^5 或 10^6。 如果总大小很大，任何针对每个测试用例重复扫描或排序数组的解决方案都会变得太慢。 

当从 0 到 N−1 的所有数字都存在时，就会出现微妙的边缘情况。 例如，如果数组是`[0, 1, 2, 3]`，那么答案就是`4`，因为这是第一个缺失的非负整数。 一种简单的方法，仅检查值`max(array)`如果不考虑 MEX 恰好是这样的可能性，这里就会失败`N`。 

当数组仅包含大值时会出现另一种边缘情况，例如`[10, 11, 12]`。 正确答案是`0`，因为零立即丢失。 从最小元素而不是零开始扫描的错误实现会错过这一点。 

最后，重复项不会影响正确性，但可能会误导尝试重复删除或排序元素的低效解决方案。 

## 方法

 计算 MEX 的一种强力方法是重复检查从 0 开始的每个整数是否出现在数组中。 对于每个候选值 x，我们扫描整个数组并检查 x 是否存在。 如果没有，我们立即返回 x。 

这种方法是正确的，因为它直接遵循 MEX 的定义。 问题在于它的成本。 在最坏的情况下，我们可能会检查从 0 到 N 的所有值，并为每个值扫描 N 个元素。 这导致每个测试用例需要 O(N^2) 次操作，当 N 很大时，这会变得太慢。 

关键的观察是我们不需要重复的全面扫描。 我们只关心 [0, N] 范围内的每个数字是否至少出现一次。 任何大于 N 的数字都不会影响答案，因为大小为 N 的数组的 MEX 始终最多为 N。这限制了搜索空间。 

因此，我们可以在输入的单次传递中使用布尔数组或哈希集来标记 [0, N] 中存在哪些值。 标记后，我们从 0 向上扫描并返回第一个未标记的索引。 这将问题简化为两次线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 读取数组大小N和数组值。 我们只会跟踪 [0, N] 范围内的值，因为任何更大的值都不能作为答案。 
2. 创建布尔数组`present`大小为 N+1 的值初始化为 False。 该数组中的每个索引 i 表示输入中是否存在值 i。 
3. 迭代输入数组中的每个元素 x。 如果 0 ≤ x ≤ N，则标记`present[x] = True`。 这一步将数组的所有相关信息压缩到一个紧凑的存在表中。 
4. 从 i = 0 到 N（含）扫描。 第一个索引我这样`present[i]`is False 是 MEX，所以我们立即返回它。 
5. 如果从 0 到 N 的所有值都存在，则返回 N。这涵盖了数组包含完整整数前缀的情况。 

### 为什么它有效

 正确性来自于以下事实：MEX 被定义为数组中不存在的最小非负整数。 布尔数组准确地表示可能是答案的所有候选人的成员资格。 由于大小为 N 的数组的任何 MEX 都不能超过 N，因此将注意力限制在 [0, N] 上不会丢失信息。 最终扫描按升序检查候选者，因此第一个缺失索引必须是真正的最小排除值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        present = [False] * (n + 1)

        for x in arr:
            if 0 <= x <= n:
                present[x] = True

        ans = n
        for i in range(n + 1):
            if not present[i]:
                ans = i
                break

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先读取测试用例的数量并对其进行迭代。 对于每种情况，它都会构建一个大小为的存在数组`n+1`涵盖所有潜在的相关值。 循环内的条件检查确保我们忽略有意义范围之外的值，从而避免不必要的写入并保持逻辑紧密。 

最终循环的结构是在找到第一个丢失的数字后立即停止。 这种早期退出很重要，因为它在实践中保留了线性行为，并且直接符合 MEX 的定义。

 ## 边缘情况

 一种重要的边缘情况是数组包含从 0 到 N−1 的所有整数。 例如：

 输入：```
1
4
0 1 2 3
```该算法将从 0 到 4 的所有位置标记为存在，但 4 除外，因为 4 永远不会被插入。 扫描发现`present[4]`为 False，因此返回 4。这与正确的 MEX 匹配，因为数组完全覆盖了前缀。 

另一种边缘情况是所有元素都超出有效范围时：

 输入：```
1
5
100 200 300 400 500
```在标记过程中，每个值都会被忽略，因为没有一个值位于 [0, 5] 中。 布尔数组仍然全为 False。 扫描立即返回 0，这是正确的，因为零是最小的缺失整数。 

第三种情况涉及重复：

 输入：```
1
5
0 0 0 1 1
```仅标记了 0 和 1。 扫描发现 2 作为第一个未标记的索引。 重复项不会改变存在数组的状态，因此保留了正确性。
