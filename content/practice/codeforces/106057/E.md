 ## 解决方案
 ## 问题理解

 我们得到一个长度为初始的数组$N$。 之后，一系列范围更新对其进行修改：每次更新都会选择一个段$[L, R]$并增加一个值$d$到该段内的每个元素。 一旦应用了所有更新，数组就被修复了。 然后我们收到询问$K$- 此最终数组中的第一个最大值。 

该任务基本上分为两个阶段。 首先，我们必须有效地将许多范围增量应用于静态数组。 其次，我们必须支持对最终转换后的数组进行顺序统计查询。 

典型 Codeforces 设置隐含的约束$N, Q, M$直到大约$2 \cdot 10^5$立即排除幼稚的模拟。 更新每个范围更新成本的每个元素的直接方法$O(NQ)$，这将是大约$10^{10}$在最坏的情况下运行并且不会在时限内运行。 同样，通过扫描数组来重新计算每个查询的答案会太慢，因为每个查询的排序或线性扫描会不必要地增加成本。 

边缘情况主要出现在索引和更新边界周围。 一个常见的错误是处理不当$R + 1$差异数组中的位置。 

如果$N = 5$，我们申请$(L=2, R=5, d=3)$，然后在位置处减去失败$R+1 = 6$或者错误地写入越界更新将导致增量泄漏到数组之外或导致逻辑崩溃。 另一个微妙的情况是多个更新重叠时； 简单的方法可能会重复应用或错误排序贡献，但正确的方法必须确保线性累积。 

最后，询问要求$K = 1$或者$K = N$排序后测试索引的边界正确性。 

## 方法

 一个简单的解决方案通过迭代来应用每个更新$L$到$R$并添加$d$直接地。 这是正确的，因为它反映了操作的定义。 然而，每次更新都可以触及$N$元素，并与$Q$更新，总复杂度变为$O(NQ)$。 对于大量输入，这是不可行的。 

关键的观察是每次更新都会在连续段上贡献一个恒定值。 我们可以使用差异数组对其效果进行编码，而不是逐个元素地应用它。 通过在位置标记+d$L$和 a -d 位置$R+1$，我们将范围更新转换为点更新。 该结构上的前缀和在线性时间内重建最终数组。 

一旦构建了最终数组，对其进行排序就可以直接访问订单统计信息。 这$K$按升序排序后，第一个最大的元素成为直接索引查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(NQ + M)$|$O(1)$| 太慢了 |
 | 最佳 |$O(N \log N + Q + M)$|$O(N)$| 已接受 |

 ## 算法演练

 我们将问题转换为两个独立的阶段：有效地应用范围更新，然后回答选择查询。 

1. 创建差异数组`df`尺寸的$N+1$，初始化为零。 该结构将表示连续位置之间的值如何变化，而不是直接存储实际值。 
2. 每次更新$(L, R, d)$， 添加$d$到`df[L]`。 这意味着所有位置从$L$应增加$d$。 
3. 减法$d$从`df[R+1]`如果$R+1 \le N$。 这消除了该段之外的影响，确保增量恰好停止在$R$。 这种边界处理使得表示相当于范围更新。 
4. 计算前缀和`df`重建每个位置的实际增量。 每个职位都会累积影响它的所有积极贡献。 
5. 将这些增量添加到原始数组中$A$，产生最终的转换数组。 
6. 按升序对结果数组进行排序。 排序对值进行组织，以便顺序统计数据成为直接索引访问。 
7. 对于每个查询$K$,输出索引处的元素$N - K$。 这对应于$K$- 自索引从零开始以来的第一个最大值。 

### 为什么它有效

 差异数组将每个范围更新编码为一对边界变化。 每个更新都会在连续段中贡献一个恒定的偏移量，并且前缀和确保每个位置准确地聚合其范围覆盖它的更新。 这保证了重建后，数组中的每个元素都反映了应用于它的所有有效更新的总和。 然后，排序将问题转换为静态顺序统计查询，其中每个查询都由确定性索引查找来回答。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q, m = map(int, input().split())
    a = list(map(int, input().split()))

    df = [0] * (n + 1)

    for _ in range(q):
        l, r, d = map(int, input().split())
        df[l - 1] += d
        if r < n:
            df[r] -= d

    cur = 0
    for i in range(n):
        cur += df[i]
        a[i] += cur

    a.sort()

    out = []
    for _ in range(m):
        k = int(input())
        out.append(str(a[n - k]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现完全遵循差异数组逻辑。 关键的微妙之处在于一致地转换为基于 0 的索引。 更新于$L$变成`df[l - 1] += d`，以及取消于$R+1$变成`df[r] -= d`因为移动一个索引可以正确对齐边界。 

前缀累加变量`cur`表示该位置的所有活动更新的运行总和$i$。 每个数组元素都会就地更新，避免额外的内存。 

排序后，使用从数组末尾开始的直接索引在恒定时间内回答查询。 

## 工作示例

 ### 示例 1

 输入：```
N=5, A=[1,2,3,4,5]
updates: (1,3,+2), (2,5,+1)
queries: K=1, K=3
```我们建造`df`一步一步：

 | 步骤| 运营| df 状态（压缩）|
 | ---| ---| ---|
 | 初始化| 全零| [0,0,0,0,0] |
 | 1 | +2 于 [1,3] | [2,0,0,-2,0] |
 | 2 | [2,5] +1 | [2,1,0,-2,0] |

 现在前缀总和：

 | 我| 当前| A[i] | 更新A |
 | ---| ---| ---| ---|
 | 1 | 2 | 1 | 3 |
 | 2 | 3 | 2 | 5 |
 | 3 | 3 | 3 | 6 |
 | 4 | 1 | 4 | 5 |
 | 5 | 1 | 5 | 6 |

 最终数组：`[3,5,6,5,6]`，排序：`[3,5,5,6,6]`查询：

 K=1 → 6

 K=3 → 5

 这证实了重叠更新已正确累积，并且排序查询仅取决于最终值。 

### 示例 2

 输入：```
N=4, A=[10,10,10,10]
update: (1,4,-5)
query: K=2
```| 步骤| df | 解读|
 | ---| ---| ---|
 | 更新后 | [-5,0,0,5] | 均匀减少|

 前缀和产生`[-5,-5,-5,-5]`，所以最终的数组是`[5,5,5,5]`。 

排序后的数组仍保留`[5,5,5,5]`，因此 K=2 返回 5。 

这表明该算法可以处理负更新并在统一变换下保持稳定性。

 ## 边缘情况

 一个重要的边缘情况是更新恰好在最后一个元素处结束。 例如，$N=4$有更新$(2,4,d)$。 正确的行为是在数组边界之外不会发生减法。 实现通过检查来处理这个问题`if r < n`申请之前`df[r] -= d`，确保没有访问无效索引并且效果精确地停止在边界处。 

另一种情况是当$K = N$，意味着需要最小的元素。 排序后，访问`a[n - k]`变成`a[0]`，这是正确的。 当在基于 1 的查询定义和基于 0 的数组之间进行转换时，此边界通常会导致相差一的错误，但索引公式始终将排名映射到位置。 

最后一种情况是所有更新抵消或产生相同的值。 排序仍然正确，并且重复的元素不会影响索引，因为顺序统计数据仅取决于位置，而不是唯一性。
