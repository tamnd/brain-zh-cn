 ## 解决方案
 ## 问题理解

 我们正在计算从 1 到 n 的标记顶点上的一个非常特定的有根树族。 该树以节点 1 为根，标签沿着任何根到节点的路径以单调方式运行：每当我们远离根时，标签必须严格增加。 

输入给出了跨测试用例的多个 n 值，对于每个值，我们需要计算在此约束下存在多少个有效的有根树。 每个有效结构都是 n 个标记节点上的一棵树，但并非所有标记树都是允许的，只有那些当我们远离根时标记永远不会减少的树。 

关键的结构约束是局部但全局限制的：除根之外的每个节点都必须有一个具有较小标签的父节点。 这立即迫使边缘的形成方式具有方向性，这就是整个计数论证的驱动力。 

约束足够小，阶乘增长不是问题，因此任何涉及每个测试用例 O(n) 甚至 O(n log n) 的解决方案都非常快。 这也表明答案可能具有封闭形式，而不需要组合枚举或树上的 DP。 

如果试图将其视为“计算所有有根树”，然后应用更正，则会出现微妙的失败情况。 例如，对于 n = 3，有根标记树的总数已经很重要，但其中许多违反了递增条件。 如果我们忽略排序约束并使用通用的凯莱公式计数，我们就会严重计算过多。 结构约束是整个问题，而不是次要的限制。 

## 方法

 暴力方法会尝试在 n 个节点上生成所有标记树，将它们的根设为 1，并检查每个根到节点的路径是否都在增加。 即使生成所有树也已经是不可行的，因为 n 个节点上标记树的数量为 n^(n−2)，对于 n = 10，这已经是数百万，而对于更大的 n，它会爆炸远远超出任何限制。 

即使我们避免完全枚举，而是尝试在强制约束的同时逐步构建树，我们仍然需要探索指数级的许多父分配并验证全局一致性。 

关键的观察是，从父代选择的角度来看，约束完全是局部的。 每个 i > 1 的节点必须有一个标签较小的父节点。 一旦我们为每个节点固定了父节点，生成的结构就会自动成为一个有效的有根树：不存在循环，因为边缘总是从较大的标签到较小的标签，并且由于父指针的重复跟随最终到达节点 1，因此保证了连接性。 

这将问题从计算树木转变为在简单限制下计算父母的独立选择。 

对于节点 i，父节点可以是 {1, 2, ..., i−1} 中的任意节点。 这些选择在节点之间是独立的，因此构造总数是所有 i > 1 的直积。 

该乘积变为 (1) × (2) × ... × (n−1)，这正是 (n−1)！

 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 将根固定为节点 1，因为它是给定的并且必须是所有路径的起点。 这锚定了结构并决定了所有父关系的方向。 
2. 对于从 2 到 n 的每个节点 i，选择其父节点。 唯一有效的选择是具有较小标签的节点，因为任何到较大标签的边都会立即违反从根开始的路径上的递增条件。 
3. 计算节点 i 存在多少个有效选择。 恰好有 i−1 个可能的父母。 
4. 将这些独立选择乘以所有节点。 由于每个节点的父节点选择不会限制其他节点超出本地标签条件的选择，因此总计数是所有 (i−1) 的乘积。 
5. 对于每个测试用例，迭代计算该乘积作为累积阶乘值，最多为 n−1。 

### 为什么它有效

 该构造定义了一种有向结构，其中每个节点恰好指向一个具有较小标签的父节点。 这保证了非循环性，因为标签在跟随父边时严格减少，因此循环是不可能的。 重复跟随父指针最终必须到达节点 1，这确保了连通性。 

因此，每个有效的父分配都恰好生成一棵有效的有根树，并且每个有效的树都对应于一个这样的分配。 树和独立父代选择之间的这种双射使得计数准确而不是高估。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ns = [int(input()) for _ in range(t)]
    
    max_n = max(ns)
    
    fact = [1] * (max_n + 1)
    for i in range(2, max_n + 1):
        fact[i] = fact[i - 1] * i
    
    out = []
    for n in ns:
        if n <= 1:
            out.append("1")
        else:
            out.append(str(fact[n - 1]))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现在所有测试用例中预先计算最大 n 的阶乘，以便可以在 O(1) 内回答每个查询。 数组fact[i]存储i!，因此n的答案是fact[n−1]。 

这里一个常见的差一陷阱是忘记了乘积是从 i = 2 开始的，而不是 i = 1 开始的。这会将阶乘索引精确移动 1，因此正确的映射是 (n−1)!，而不是 n!。 

特殊情况 n = 1 是单独处理的，因为否则阶乘表将返回fact[0] = 1，这已经是正确的，但显式分支使逻辑更清晰。 

## 工作示例

 ### 示例 1

 输入：

 n = 3

 我们计算有效的父分配。 

| 节点 i | 家长的选择 | 贡献 |
 | ---| ---| ---|
 | 2 | {1} | 1 |
 | 3 | {1, 2} | 2 |

 合计 = 1 × 2 = 2

 这就证实了公式(3−1)！ = 2。 

迹线表明，节点 3 比节点 2 具有更大的灵活性，并且乘法结构自然地由独立选择产生。 

### 示例 2

 输入：

 n = 4

 | 节点 i | 家长的选择 | 贡献 |
 | ---| ---| ---|
 | 2 | {1} | 1 |
 | 3 | {1, 2} | 2 |
 | 4 | {1,2,3}| 3 |

 总计 = 1 × 2 × 3 = 6

 这演示了选项数量如何随 i 线性增长，并且产品结构与阶乘增长完全匹配。

 ## 边缘情况

 对于 n = 1，只有一个顶点也是根，因此只有一棵有效树。 该算法使用fact[n−1]，它变成fact[0]，正确给出1。 

对于 n = 2，节点 2 只能选择父节点 1。该算法计算事实[1] = 1，匹配单个可能的树。 

对于较大的 n，请考虑 n = 3。该算法计算事实[2] = 2。这与两个有效的父配置完全对应：节点 2 必须附加到 1，而节点 3 可以附加到 1 或 2。该实现自然地捕获了这一点，而无需阶乘索引之外的特殊大小写。
