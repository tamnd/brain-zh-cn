 ## 解决方案
 ## 问题理解

 我们有一个矩形网格，其中每个单元格都包含一个非负整数。 我们必须从每一行中恰好选择一个元素。 每行选择一个数字后，我们计算所有选定值的按位与。 任务是确定是否存在至少一种方法来选择这些值，以便最终的 AND 结果严格为正。 

当至少有一个位位置每个选定的数字都有 1 时，按位 AND 为正。因此，问题实际上是问我们是否可以找到一个可以同时在所有选定的行元素中共用的位。 

网格可能足够大，以至于不可能尝试每行一个元素的所有组合。 如果有 N 行和 M 列，则暴力方法将需要检查 M^N 选择，这会呈指数增长，即使对于 N = 20、M = 20 等中等值也是不可行的。 

输入的结构表明我们只关心每行的位级可用性，而不关心确切的数字。 每行贡献一组位，这些位可能由该行中的至少一个元素提供。 

当某个位出现在每行中的某处但不在跨行的同一列索引中时，就会出现关键边缘情况。 例如，考虑：

 第 1 行：2 (010)、1 (001)

 第 2 行：4 (100)、1 (001)

 每行包含位 0（值 1），因此存在有效选择：从两行中选择 1。 答案是肯定的。 

但如果我们有：

 第 1 行：2 (010)

 第 2 行：4 (100)

 两行没有一个共同的位，因此无论选择如何，AND 都变为 0。 

这表明问题在于每行位可用性的交集而不是直接值比较。 

## 方法

 暴力破解的想法很简单：枚举每行一个元素，计算 AND，并检查它是否非零。 这是正确的，因为它探索了所有有效的选择。 然而，每行有 M 个选择，因此组合总数为 M^N。 即使对于 N = 10 和 M = 10，这也已经达到了 10^10 种可能性，这远远超出了任何可行的限制。 

关键的观察结果是 AND 结果完全取决于所有选定数字中存在的位位置。 我们可以重新构建问题，而不是推理单个选择：我们需要知道是否存在一个位，使得每行至少有一个数字包含该位。 

这将问题减少到每行位的可用性。 对于每一行，我们使用 OR 计算一个位掩码，表示该行中任何数字中出现的所有位。 然后，我们通过对这些掩码进行 AND 运算来检查所有行中哪些位是通用的。 如果最终的交集掩码非零，则每行中至少可以保留一位，这意味着我们可以选择在最终 AND 中保留该位的值。 

另一种观点是独立测试每个位。 对于每个位位置，检查每一行是否至少包含一个设置了该位的数字。 如果任何位满足此条件，我们立即知道存在有效的选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(M^N·N) | O(M^N·N) | O(N) | 太慢了 |
 | 行 OR + 全局 AND | O(NM) | O(N) | 已接受 |

 ## 算法演练

1. 初始化一个数组或变量来存储每行的位掩码。 每个掩码都从 0 开始，因为最初没有记录任何位。 
2. 对于每一行，扫描所有 M 值并使用按位或更新行掩码。 这捕获该行的至少一个元素中出现的每一位。 
3. 维护一个初始化为所有位集（或第一行掩码）的全局掩码。 处理完每一行后，使用按位与当前行掩码来更新它。 此步骤仅保留所有已处理行中仍然可能的位。 
4. 处理完所有行后，检查全局掩码是否非零。 如果非零，则输出YES； 否则输出NO。 

构建按行 OR 掩码的原因是我们只关心行中是否有某个位可用，而不关心哪个特定元素提供它。 跨行的 AND 确保我们只保留每行中幸存的位。 

### 为什么它有效

 对于任何位位置 b，当该行中至少存在一个设置了位 b 的元素时，算法将 b 保留在行掩码中。 对所有行进行 AND 运算后，当且仅当每行至少有一个元素包含该位时，最终掩码中才会保留一位。 这正是每行选取一个元素所需的条件，以便所有选定的元素共享该位，从而保证最终的 AND 为正。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    global_mask = (1 << 60) - 1  # large enough for constraints
    
    for _ in range(n):
        row_mask = 0
        row = list(map(int, input().split()))
        for x in row:
            row_mask |= x
        global_mask &= row_mask
    
    print("YES" if global_mask != 0 else "NO")

if __name__ == "__main__":
    solve()
```该解决方案读取每一行，将其压缩为单个位掩码，然后使用按位 AND 使所有行掩码相交。 的初始化`global_mask`设置所有位可确保第一行正确定义可能位的起始集。 

一个微妙的点是我们永远不需要跟踪实际选择的元素。 OR 步骤将每一行抽象到其可用位空间中，AND 步骤强制跨行的一致性。

 ## 边缘情况

 一种重要的边缘情况是行仅包含零。 例如：```
2 2
0 0
0 0
```每个行掩码变为 0，因此全局掩码立即变为 0。 该算法输出“否”，这是正确的，因为没有选择可以产生正“与”。 

另一种情况是单行：```
1 3
1 2 4
```行掩码非零，并且由于没有第二行来消除位，因此全局掩码保持非零。 答案是肯定的，因为我们可以选择任何正数，它与单个元素的“与”就是它本身。 

一个更微妙的情况是不相交的位分布：```
2 2
1 2
4 8
```行掩码为 3 和 12，它们的交集为 0。即使每行都包含有效位，但两行中都没有出现任何位，因此任何选择都无法在最终的 AND 中保留位。
