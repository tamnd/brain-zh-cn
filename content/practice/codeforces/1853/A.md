 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们重复应用一个操作，以一种非常结构化的方式将值从所选分割点的右侧移动到左侧。 每个操作都会选择一个索引，并将左侧的所有元素加一，同时将右侧的所有元素减一。 

目标不是使数组排序。 相反，我们从一个已排序的数组或一个未排序的数组开始，并想知道达到数组不再不减的状态所需的此类操作的最小数量。 

因此，该任务从根本上来说是“我们如何使用非常具体的全局转换来打破排序”。 

总量约束$n \le 500$跨测试用例意味着我们可以负担得起$O(n^2)$舒适地解决。 任何立方或更糟的东西都是不必要的，但在技术上仍然处于安全边缘； 然而，该结构表明每个测试用例的解决方案预计是线性或近线性的。 

一个关键的微妙之处是数组最初可能已经未排序，在这种情况下不需要任何操作。 另一个重要的情况是数组最初已排序但“勉强”排序，这意味着单个操作可能足够也可能不够，具体取决于我们是否可以在任何地方强制反转。 

一个天真的误解是认为我们必须模拟操作，直到出现违规为止。 但这会失败，因为每个操作都会影响全局的所有元素，并很快破坏幼稚的模拟假设。 另一个错误是假设答案仅取决于局部相邻差异； 实际上，该操作同时影响所有前缀后缀关系。 

## 方法

 暴力方法将模拟在所有可能的拆分序列中应用操作。 每个操作都由一个索引定义，因此有$n-1$每一步的选择。 尝试所有长度的序列$k$导致$(n-1)^k$的可能性，呈指数级增长。 如果我们对所有可能性重复执行，即使尝试逐步模拟并在每次操作后检查排序性仍然是昂贵的。 

然而，一个关键的观察使一切变得简单：我们并不是试图达到任意状态，我们只是试图打破单调性。 这意味着我们只关心存在某些情况的第一时刻$i$这样$a_i > a_{i+1}$。 

每个操作都会通过切口将质量从右向左移动，并且对前缀和后缀的相对影响是线性且均匀的。 这意味着重要的是我们可以多快地在数组中的某个位置创建下降。 

我们可以推断相邻元素之间的差异如何演变，而不是模拟所有操作。 每个操作位置$i$增加所有前缀元素并减少所有后缀元素，因此每个相邻对都会以可预测的方式受到影响，具体取决于拆分是在该对之前、之后还是内部。 

关键的简化是，最早可以强制违规的地方决定了答案。 我们只需要考虑需要多少次操作才能出现某种反转，这减少了分析对相邻元素之间最小间隙的最佳可能分割效果。 

最佳解决方案最终取决于使任何相邻对按顺序递减所需的最小操作数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | ---| ---| --- |
 | 暴力模拟| 指数| O(n) | 太慢了|
 | 最佳相邻间隙分析 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.首先检查数组是否已经未排序。 如果存在索引$i$这样$a_i > a_{i+1}$，则无需任何操作，答案为0。这就是目标条件的直接解释。 
2. 如果数组已排序，则计算相邻元素之间的最小间隙，定义为$a_{i+1} - a_i$为所有人$i$。 这衡量了数组“接近”未排序的程度。 
3. 确定应用强制反转操作的最佳位置。 每个操作都会影响所选拆分左侧和右侧的所有元素，因此创建违规的最有效方法是重复将一个前缀向上推并向下推一个后缀跨越最小的间隙。 
4. 一次分割操作的效果$i$就是增加$a_i$相对于$a_{i+1}$正好 2 个单位（因为$a_i$位于前缀中并且$a_{i+1}$位于后缀中）。 因此，之后$k$在同一拆分操作中，差距缩小了$2k$。 
5. 为了进行反演，我们需要$a_i + k > a_{i+1} - k$，这相当于$a_{i+1} - a_i < 2k$。 因此最小$k$对于一对是$\left\lfloor \frac{(a_{i+1} - a_i)}{2} \right\rfloor + 1$。 
6. 计算每个相邻对的该值，并取所有对中的最小值。 这给出了全局所需的最少操作次数。 

### 为什么它有效

 每个操作都完全以分割点为特征，并对一侧的所有元素应用统一的 +1 移位，对另一侧的所有元素应用统一的 -1。 这意味着只有跨边界的元素之间的相对差异发生变化，所有其他比较要么保持不变，要么朝相同方向移动。 因此，第一个反转必须出现在某个相邻对上，并且最佳策略始终将所有操作集中在最小化所需步骤数的分割上。 任何不同的分裂序列都无法胜过反复攻击最弱的相邻间隙，因为任何混合策略都会将效果分散到多个边界上，而不会加速第一次反转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # already unsorted
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                print(0)
                break
        else:
            ans = float('inf')
            for i in range(n - 1):
                diff = a[i + 1] - a[i]
                ans = min(ans, diff // 2 + 1)
            print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先扫描立即反转。 这是必要的，因为该问题允许零操作，并且不检查这种情况将错误地强制得到肯定答案。 

如果数组已排序，我们将计算打破任何相邻对所需的最少操作数。 表达式`diff // 2 + 1`直接编码在每个操作的±1对称更新效果下将非负间隙翻转为负间隙所需的最小操作数。 

循环结构确保我们只考虑相邻对，因为任何反转必须首先出现在本地，然后才能全局传播。

 ## 边缘情况

 一种边缘情况是数组一开始就未排序，例如`[3, 1, 2]`。 该算法在第一次扫描期间立即捕捉到这一点，因此它输出 0，而无需计算间隙。 这可以防止答案的错误膨胀。 

另一种边缘情况是当所有元素都相等时，例如`[5, 5, 5]`。 最小相邻差为零，则公式`diff // 2 + 1`给出 1。这与单个操作将在某处创建严格反转的事实相匹配，因为它将一侧向上移动，另一侧向下移动。 

最后的边缘情况是当数组以大间隙严格增加时，例如`[1, 100]`。 相差99，答案变成50。经过50次运算，左边的元素增加了50，右边的元素减少了50，产生`[51, 50]`，这是第一个可能的反转。
