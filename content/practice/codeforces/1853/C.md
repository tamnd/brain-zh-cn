 ## 解决方案
 ## 问题理解

 我们得到了一组抽象的巨大正整数，最初是从 1 到 1 的所有数字$10^{1000}$，对于计算目的而言，它实际上是无界的。 每天都有一份职位列表$a_1, a_2, \dots, a_n$提供了，并且要求我们从集合中删除当前按排序顺序占据这些位置的元素。 后$k$应用删除的天数，我们想知道集合中剩余的最小数字。 

关键输入参数是$n$、每天删除列表的长度，以及$k$，天数，两者都可能达到$2 \cdot 10^5$。 此外，删除列表中的值$a_i$可以大到$10^9$，以及测试用例总数$t$可能最多$10^5$。 这些约束排除了任何显式存储集合的简单方法$S$或通过索引迭代它，因为$S$太大，操作次数会超过$10^9$在单个测试用例中。 

当第一天删除的第一个元素为 1 时，或者当$a_1$重复为1。 例如，如果$a = [1, 2, 3]$和$k = 1$, 集合$S$一天后从 4 开始。假设头寸到值的静态映射而不考虑之前的删除，粗心的方法会产生错误的答案。 

另一个微妙的情况是当$a$包含从 1 开始的连续数字，并且$k$非常大，比如$a = [1, 2, 3]$和$k = 10^5$。 最小的剩余元素线性增长$k$乘以所产生的间隙$a_n$，而缺少这个增长因子很容易导致相差一倍的错误。 

## 方法

 暴力方法在概念上很简单：通过维护表示的动态数组来模拟删除过程$S$，每天删除指定位置的元素$a$。 这原则上是有效的，因为位置$a$严格增加，可以进行调整以反映前几天的清除量。 然而，这需要存储所有元素$S$，这是不可能的，或者在虚拟集上执行索引算术，这仍然涉及$O(n \cdot k)$运营。 在最坏的情况下，$n$和$k$都可以达到$2 \cdot 10^5$, 给予$O(4 \cdot 10^{10})$每个测试用例的操作，这太慢了。 

关键的见解是我们不需要整套$S$明确地。 我们只需要跟踪当我们删除数字时最小元素如何移动。 自从$a$是严格递增的，每天剩余元素的位置都会根据它们之前发生的删除次数而有效地移动。 这使我们能够计算最小元素的总移位$S$无需模拟整个集合。 具体来说，之后$k$天，最小的剩余元素只是 1 加上如果我们将每个删除映射到中就会发生的不同删除的总数$a$连续所有天。 这将问题简化为连续元素之间间隙的简单线性累积$a$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * k) | O(n * k) | 太慢了 |
 | 最佳 | 每个测试用例 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$,$k$，以及排序后的列表$a$。 排序是不必要的，因为$a$保证严格递增。 
2. 初始化变量`shift`到 0。这将累积从集合开始有效“删除”的位置数。 
3. 迭代每个元素$x$在$a$。 对于每个元素，计算`x - shift - 1`，它表示小于的数字的个数$x$尚未被删除。 如果该值大于0，则表示$x$仍在为这一转变做出贡献。 
4. 数一下里面有多少个数字$a$每天移除后仍保留，并重复此过程$k$次，更新`shift`因此。 从概念上讲，移位增加了删除的唯一位置的数量，这相当于最后一个元素$a$加上之前迭代的累积偏移。 
5.之后$k$天，剩余的最小元素是`1 + total_shift`。 

该算法之所以有效，是因为删除总是以可预测的线性方式移动剩余元素的位置。 中的每个元素$a$影响其后所有元素的位置，并且因为$a$是严格递增的，我们可以直接对这些影响求和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        shift = 0
        ans = 0
        for x in a:
            if x > shift:
                ans += 1
                shift += 1
        
        result = 1 + ans * k
        print(result)

if __name__ == "__main__":
    solve()
```该解决方案使用有效地读取输入`sys.stdin.readline`。 我们计算每个元素引起的有效位移`a`然后乘以`k`来计算所有的日子。 微妙的部分是正确计算的`x - shift`并递增`shift`以反映元素的删除如何影响后续位置。
