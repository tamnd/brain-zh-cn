 ## 解决方案
 ## 问题理解

 我们有两个整数，`n`和`k`。 我们想要计算有多少个类似斐波那契的序列长度`k`以价值结束`n`。 

类斐波那契序列的构建与斐波那契序列完全相同，只是前两个值是任意非负整数并且序列必须是非递减的。 对于每个职位`i > 2`,$$f_i = f_{i-1} + f_{i-2}.$$最后一个元素是固定的：$$f_k = n.$$我们的任务是计算前两个元素有多少个选择生成满足所有要求的有效序列。 

约束是第一个线索。 测试用例的数量可以大到`2 · 10^5`，以及所有的总和`n`值也最多是`2 · 10^5`。 执行与以下成比例的功的解决方案`n`每个测试用例是可以接受的，但是任何二次的`n`立刻就不可能了。 

不寻常的限制是`k`可以大到`10^9`。 任何显式构造长度序列的算法`k`是无望的。 该解决方案必须利用斐波那契数列增长极快的事实。 

一些边缘情况值得关注。 

什么时候`k`非常大并且`n`很小，可能根本没有解决方案。 例如：```
n = 3, k = 9
```相关系数`f_k`前两个元素在位置 9 之前就变大了，因此无法使用非负起始值来表示 3。 

什么时候`k = 3`，递归给出$$f_3 = f_1 + f_2.$$每对`(f1, f2)`与总和`n`作品，提供`f1 ≤ f2`。 为了`n = 1`， 仅有的`(0,1)`是有效的，所以答案是`1`。 

另一个微妙的情况是强制执行非递减条件。 一对可以满足递归并产生`f_k = n`，但失败了，因为`f_1 > f_2`。 例如，如果导出的解决方案给出`(3,1)`，即使所有后来的值都确定了，它也必须被拒绝。 

关键的观察是一旦`f_1`和`f_2`是非负的并且满足`f_1 ≤ f_2`，后面的每一项都自动不减。 

## 方法

 最直接的想法就是尝试每一种可能的配对`(f_1, f_2)`。 

由于所有项都是非负的，最终值为`n`，两个起始值最多为`n`。 我们可以枚举所有对并生成序列，直到位置`k`，检查最后一个值是否等于`n`。 

这是正确的，但太慢了。 有`O(n²)`候选对，每个候选对可能需要许多重复步骤。 和`n`最多`2 · 10^5`，这种做法是完全不可行的。 

下一个观察结果是，每个类斐波那契序列的前两个值都是线性的。 

让$$f_1=a,\qquad f_2=b.$$然后：$$f_3=a+b,$$

$$f_4=a+2b,$$

$$f_5=2a+3b,$$等等。 

系数本身遵循斐波那契数列。 一般来说，$$f_k = F_{k-2}a + F_{k-1}b,$$在哪里$F_1=1, F_2=1$。 

整个问题变成计算非负整数解$$F_{k-2}a + F_{k-1}b = n,$$受$$a \le b.$$现在这是一个线性丢番图方程。 

另一个重要的观察来自于对`n`。 斐波那契数列超过`200000`仅仅几十个学期之后。 自从`n ≤ 200000`，一旦任一系数变得大于`n`，至多有一种微不足道的可能性，而且通常没有。 

事实上，只有前 30 个斐波那契数列才重要。 对于较大的`k`，答案自动为零。 

对于每个测试用例，我们可以计算两个相关的斐波那契系数并计算所有整数对`(a,b)`满足方程并且`a ≤ b`。 

自从`n`很小，迭代所有可能的`b`值足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²·k) | O(1) | O(1) | 太慢了 |
 | 最佳 | 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 预先计算斐波那契数列，直到超过`200000`。 

既然所有`n`值最多为`200000`，较大的斐波那契数永远不能参与有效的表示。 
2. 对于测试用例`(n, k)`，确定系数。 

使用$$f_k = F_{k-2}a + F_{k-1}b,$$我们需要系数`A = F_{k-2}`和`B = F_{k-1}`。 
3.如果`k-1`超出预先计算的斐波那契数范围，立即返回`0`。 

那时`B > 200000 > n`，使得任何不平凡的表示都不可能。 
4. 枚举所有可能的值`b`。 

自从$$A a + B b = n,$$我们只需要考虑$$0 \le b \le \left\lfloor \frac n B \right\rfloor .$$5. 对于每位候选人`b`，计算剩余值：$$rem = n - B b.$$如果`rem`不能被整除`A`，没有整数`a`存在。 
6. 否则计算$$a = \frac{rem}{A}.$$计算解当且仅当`a ≤ b`。 
7. 输出总计数。 

### 为什么它有效

 每个类斐波那契数列都是由其前两个元素唯一确定的。 扩大重现性表明`k`- 第一项恰好是$$F_{k-2}a + F_{k-1}b.$$因此每个有效序列对应一个整数解`(a,b)`该方程的。 

相反，每个非负整数解`a ≤ b`生成有效的非递减类斐波那契序列。 递归保留了非负性，并且因为$$f_3=a+b \ge b,$$所有后续项至少与前一项一样大。 

该算法精确地计算这些对，而不计算其他任何东西，因此它是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# Fibonacci numbers with F1 = 1, F2 = 1
fib = [0, 1, 1]
while fib[-1] <= 200000:
    fib.append(fib[-1] + fib[-2])

t = int(input())

for _ in range(t):
    n, k = map(int, input().split())

    if k - 1 >= len(fib):
        print(0)
        continue

    A = fib[k - 2]
    B = fib[k - 1]

    ans = 0

    for b in range(n // B + 1):
        rem = n - B * b

        if rem % A != 0:
            continue

        a = rem // A

        if a <= b:
            ans += 1

    print(ans)
```第一部分预先计算斐波那契数，直到它们超过最大可能值`n`。 这已经足够了，因为较大的系数永远无法形成有效的表示。 

对于每个测试用例，我们获得系数`A = F_{k-2}`和`B = F_{k-1}`。 如果`k`太大以至于这些系数超出了预先计算的范围，答案立即为零。 

循环结束`b`检查解中可能出现的每个可能的非负值。 一次`b`是固定的，方程确定`a`独一无二。 可整除性检查该值是否为整数。 

条件`a <= b`正是不减要求。 不需要额外的序列验证，因为递归会自动产生递增的项。 

Python 整数是任意精度的，因此溢出从来不是问题。 最大的算术值仍然只有左右`200000`反正。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    fib = [0, 1, 1]
    while fib[-1] <= 200000:
        fib.append(fib[-1] + fib[-2])

    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())

        if k - 1 >= len(fib):
            ans.append("0")
            continue

        A = fib[k - 2]
        B = fib[k - 1]

        cur = 0
        for b in range(n // B + 1):
            rem = n - B * b
            if rem % A == 0 and rem // A <= b:
                cur += 1

        ans.append(str(cur))

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

 ## 边缘情况

 考虑：```
1
1 3
```等式是$$a+b=1.$$可能的非负对是`(0,1)`和`(1,0)`。 仅有的`(0,1)`满足`a ≤ b`，所以答案是`1`。 该算法通过枚举来检查两种可能性`b`并且正好数到一。 

现在考虑：```
1
1 4
```方程变为$$a+2b=1.$$唯一的整数解是`(1,0)`。 自从`a>b`，序列开始递减并且无效。 该算法找到了解决方案，但通过以下方式拒绝了它：`a <= b`条件、生产`0`。 

最后考虑：```
1
69 1434
```斐波那契系数`F_{1433}`极大地大于`69`。 不存在非负解。 该算法检测到`k`超出预先计算的斐波那契范围并立即返回`0`，避免任何不必要的工作。
