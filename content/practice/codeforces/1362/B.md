[CF 1362B - 约翰尼和他的爱好](https://codeforces.com/problemset/problem/1362/B)

 **评分：** 1200
 **标签：** 位掩码，暴力破解
 **求解时间：** 2m 2s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一组不同的整数。 约翰尼选择一个正整数`k`并替换每个值`s`在集合中`s XOR k`。 

该变换同时应用于每个元素。 转换后，我们希望结果集与原始集完全相同。 由于我们处理的是集合，因此元素的顺序并不重要。 

我们的任务是找到最小的正整数`k`为此$$\{s \oplus k \mid s \in S\} = S$$或报告不存在这样的正整数。 

限制异常小。 集合中的每个数字都小于`1024`，这意味着它最多使用 10 位。 测试用例中的元素数量最多为`1024`，所有测试用例的元素总数也最多为`1024`。 

这些限制立即表明尝试许多候选值`k`或许是完全可行的。 由于所有值都在范围内`[0, 1023]`，由两个这样的数字产生的任何 XOR 结果也位于该范围内。 对所有可能的 10 位掩码的搜索只需要大约一千次迭代。 

一些边缘情况很容易被忽略。 

考虑一个单元素集：```
1
1
5
```任何积极的`k`变化`5`成不同的值，因此该集合不能保持不变。 正确答案是：```
-1
```粗心的解决方案可能会假设每个集合都具有一定的对称性，并错误地返回一个值。 

另一个重要的情况是当答案很大时：```
1
2
0 1023
```使用`k = 1023`交换两个元素：```
0 XOR 1023 = 1023
1023 XOR 1023 = 0
```集合保持不变，所以答案是：```
1023
```仅检查元素本身中出现的掩码的解决方案会错过这一点。 

另一个微妙的情况是：```
1
3
1 2 3
```尝试不同的面具永远不会重现同一组面具。 正确答案是：```
-1
```人们很容易只寻找成对关系，但整个转换集必须完全匹配。 

## 方法

 最直接的想法就是测试每一个可能的正整数`k`。 

对于每个候选者，将集合中的每个元素与`k`，构建转换后的集合，并将其与原始集合进行比较。 如果它们匹配，我们就找到了有效的答案。 

这种强力方法是正确的，因为它从字面上检查语句中的条件。 问题是它是否足够快。 

关键观察来自值范围。 每个元素都小于`1024`，因此所有相关的 XOR 掩码也小于`1024`。 没有理由测试范围之外的任何内容`[1, 1023]`。 

对于每个候选掩码，我们最多处理`n ≤ 1024`元素。 每个测试用例的最坏情况工作是：$$1023 \times 1024 \approx 10^6$$运营。 

鉴于总和`n`所有测试用例仅`1024`，这在极限之内。 

所有数字都是 10 位值的观察结果将通常看起来巨大的搜索空间变成了一个很小的搜索空间。 我们只需要检查 1023 个可能的掩码，而不是搜索任意整数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有整数进行暴力破解 | 无界| O(n) | 不可能|
 | 枚举所有掩码 1..1023 | O(1024·n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取这组数字。 
2. 将原始元素存储在哈希集中，以进行 O(1) 成员资格和相等性检查。 
3. 迭代每个候选掩码`k`从`1`到`1023`。 
4. 对于当前掩码，计算所有值`x XOR k`对于每个元素`x`在集合中。 
5. 构建一个包含这些转换值的新集合。 
6. 将转换后的集合与原始集合进行比较。 

如果它们相同，则应用`k`准确地保留该集合。 
7. 由于掩码是按升序测试的，因此第一个有效掩码自动成为最小的有效答案。 立即输出。 
8. 如果检查所有值后没有掩码起作用`1`到`1023`， 输出`-1`。 

### 为什么它有效

 对于任何有效的答案，`k`必须是 10 位数字，因为所有集合元素都位于`[0,1023]`。 该算法检查整个范围内的每个正掩码。 

对于固定掩码，变换后的集合正是问题陈述中描述的集合。 将其与原始集合进行比较直接验证条件是否成立。 

由于会检查每个可能的候选掩码并返回第一个有效的掩码，因此该算法不会错过解决方案，并且当存在较小的解决方案时也无法返回较大的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        original = set(arr)

        answer = -1

        for k in range(1, 1024):
            transformed = {x ^ k for x in arr}

            if transformed == original:
                answer = k
                break

        answers.append(str(answer))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```实现几乎完全遵循算法。 

原始数字存储在Python中`set`，这允许有效的相等比较。 当且仅当两个集合包含完全相同的元素且与问题定义匹配时，它们才相等。 

对于每个候选掩码，集合推导式会生成转换后的值。 由于输入已经由不同的值组成，因此转换后的结果也仍然是一组不同的值。 比较两个集合直接检查变换是否使集合保持不变。 

掩码循环开始于`1`， 不是`0`。 该语句要求输入一个正整数`k`， 所以`0`不允许，即使它总是保留该集合。 

找到有效掩码后，搜索会立即停止，因为掩码是按升序处理的。 这保证了最小的有效答案。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(1024·n) | 检查1023个掩码，每个掩码处理n个元素 |
 | 空间| O(n) | 存储原始集和转换集 |

 ## 边缘情况

 单元素集没有有效答案：```
1
1
5
```该算法检查每个掩码`1`到`1023`。 每个转换都会产生不同的单例集：```
{5 XOR k}
```永远不能等于`{5}`因为`k > 0`。 搜索完成并输出：```
-1
```对于边界情况```
1
2
0 1023
```算法最终达到`k = 1023`并计算：```
0 XOR 1023 = 1023
1023 XOR 1023 = 0
```变换后的集合变为`{0,1023}`，与原件相符。 由于没有更小的掩码有效，因此输出为：```
1023
```对于没有对称性的集合，```
1
3
1 2 3
```每个候选掩码都会产生不同的集合。 每次相等测试都会失败，因此算法正确返回：```
-1
```直接集合比较可以防止仅检查元素之间的部分关系可能出现的误报。
