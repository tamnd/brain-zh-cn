 ## 解决方案
 ## 问题理解

 我们得到一个最初按非降序排序的数组。 在某些时候，要么什么也没发生，要么恰好一对元素可能已被交换。 

问题是是否可以使用最多任意两个位置的一次交换将当前数组转换为完全排序的数组。 如果答案是肯定的，我们打印`"YES"`。 否则我们打印`"NO"`。 

数组长度可以大到$10^5$。 任何尝试每种可能交换的算法都需要大约$n^2$尝试。 和$n = 10^5$，这意味着大约$10^{10}$可能性，在2秒的时间限制内是完全不可能的。 我们需要一些接近的东西$O(n \log n)$或者$O(n)$。 

问题的一个微妙方面是价值观不一定是不同的。 重复会使一些直观的方法失败。 

考虑：```
4
1 3 2 2
```排序后的数组为：```
1 2 2 3
```当前数组与排序后的数组仅在位置 2 和 4 处不同，因此一次交换即可修复该问题。 正确答案是：```
YES
```仅寻找反转的粗心解决方案可能会错误地得出需要做更多工作的结论。 

另一个重要的情况是当数组已经排序时：```
5
1 2 2 3 4
```答案依然是：```
YES
```因为零交换是允许的。 要求是“最多一次交换”，而不是“恰好一次交换”。 

当两个以上的位置与排序顺序不一致时，会出现第三种边缘情况：```
4
4 3 2 1
```排序后的版本是：```
1 2 3 4
```所有四个位置都不同。 没有一个交换可以解决所有问题，所以答案是：```
NO
```只检查反转次数是否很少的解决方案在这里会失败。 

## 方法

 一种简单的暴力方法是尝试所有可能的交换，包括不执行交换的可能性。 对于每个选择，我们检查结果数组是否已排序。 

有$O(n^2)$可能的互换。 检查数组是否已排序需要$O(n)$时间。 总复杂度变为$O(n^3)$。 

为了$n = 10^5$，这实在是太慢了。 甚至$O(n^2)$已经太大了。 

关键的观察结果来自于将当前数组与其完全排序版本进行比较。 

假设我们创建数组的排序副本。 当前数组和已排序数组已经匹配的任何位置都不需要更改。 一次掉期只能影响两个头寸。 因此，如果超过两个位置与排序数组不同，则一次交换永远无法使数组相同。 

这将问题变成了一个非常简单的检查。 

构造数组的排序版本。 计算原始数组和排序数组中有多少个索引包含不同的值。 

如果不匹配位置的数量为：

 - 0，数组已经排序。 
- 2，交换这两个位置修复数组。 
- 超过2个，1次交换不足。 

因为每次交换恰好改变两个位置，所以答案是`"YES"`恰好当不匹配计数最多为 2 时。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取数组。 
2. 创建数组的排序副本。 

排序后的副本代表我们想要达到的目标配置。 
3、逐个位置比较原数组和排序后的数组。 

计算有多少个索引包含不同的值。 
4. 如果不匹配的数量最多为2，则打印`"YES"`。 

一次交换恰好影响两个头寸。 零不匹配意味着数组已经排序，而两个不匹配对应于交换中涉及的两个位置。 
5. 否则，打印`"NO"`。 

### 为什么它有效

 令排序后的副本为$b$。 

如果原始数组最多可以使用一次交换进行排序，那么除了两个交换位置之外的所有位置都必须已经匹配$b$。 因此，原始数组和数组之间不匹配的数量$b$不能超过2。 

相反，如果正好有两个不匹配的位置，则交换这些位置处的值会使这两个位置同时与排序数组匹配。 如果存在零个不匹配，则数组已排序。 

因此，当且仅当不匹配计数最多为 2 时，数组最多可在一次交换中排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    b = sorted(a)

    mismatches = 0
    for x, y in zip(a, b):
        if x != y:
            mismatches += 1

    print("YES" if mismatches <= 2 else "NO")

if __name__ == "__main__":
    solve()
```实现直接遵循算法。 

排序后的副本`b`是目标安排。 然后，我们同时扫描两个数组并计算值不同的位置。 

关键的观察是我们计算的是不匹配的位置而不是反转。 重复会使基于反转的推理变得不可靠，而与排序数组的比较可以准确捕获哪些位置不正确。 

对于已经排序的数组不需要特殊处理。 在这种情况下，不匹配计数为零，并且条件`mismatches <= 2`自然回归`"YES"`。 

Python 整数可以轻松处理高达$10^9$，因此不存在溢出问题。

 ## 边缘情况

 考虑一个已经排序的数组：```
5
1 2 2 3 4
```排序后的副本是相同的。```
Original: 1 2 2 3 4
Sorted:   1 2 2 3 4
```不匹配计数为 0，因此算法打印：```
YES
```这符合允许零交换的要求。 

考虑重复：```
4
1 3 2 2
```排序后的副本是：```
1 2 2 3
```比较位置：```
1 = 1
3 ≠ 2
2 = 2
2 ≠ 3
```恰好有两个不匹配之处。 交换这两个位置会产生排序数组，因此算法输出：```
YES
```考虑需要多次交换的情况：```
4
4 3 2 1
```排序副本：```
1 2 3 4
```每个位置都不同，导致四个不匹配。 由于一次交换最多可以修复两个位置，因此算法输出：```
NO
```不匹配计数标准正确捕获所有此类情况。
