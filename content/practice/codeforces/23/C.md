 ## 解决方案
 ## 问题理解

 我们有`2N - 1`盒子。 每个盒子里都有两个数字，里面有苹果的数量和橘子的数量。 我们必须准确选择`N`使得所选的集合包含每个盒子中至少一半的苹果和至少一半的橙子。 

“至少一半”的措辞很重要，因为总数可能是奇数。 如果苹果总数是`S`，我们需要选择的盒子至少包含`ceil(S / 2)`苹果。 同样的条件独立地适用于橙子。 

输出不仅仅是这样的子集是否存在。 我们还需要打印一组有效的索引。 

最大的约束是`N`在所有测试用例中，最多是`10^5`。 由于每次测试都有`2N - 1`框，总输入大小是线性的。 这立即排除了任何子集枚举方法。 即使是为了`N = 30`，检查大小的所有子集`N`已经是天文数字了。 解决方案围绕`O(N log N)`或者`O(N)`每次测试都是现实的目标。 

棘手的部分是我们必须同时满足两个独立的平衡条件。 仅优化苹果的贪婪策略很容易在橙子上失败。 

考虑这个例子：```
N = 2

Box 1: (100, 1)
Box 2: (1, 100)
Box 3: (50, 50)
```选择苹果最多的两个盒子会得到盒子`1`和`3`，其中包含足够的苹果，但仅`51`橙子出`151`。 这还不够。 

另一个容易犯的错误是忘记了我们确切需要`N`盒子，而不是“最多`N`“。 例如：```
N = 2

(10, 10)
(1, 1)
(1, 1)
```第一个盒子已经包含了两种水果的一半以上，但我们仍然必须输出恰好两个索引。 

当总数为奇数时，会出现更微妙的边缘情况。```
N = 1

(3, 5)
```一半的苹果是`1.5`，所以我们至少需要`2`。 一半的橙子是`2.5`，所以我们至少需要`3`。 整数除法错误可能会错误地接受较小的值。 

这个问题的令人惊讶的部分是答案总是可能的。 这一挑战纯粹是建设性的。 

## 方法

 蛮力的想法很简单。 我们尝试尺寸的每个子集`N`，计算其中苹果和橙子的总数，并检查两个总和是否至少是全局总数的一半。 

这是可行的，因为一旦子集固定，条件就很容易验证。 问题是子集的数量。 我们需要检查：$$\binom{2N-1}{N}$$选择。 为了`N = 20`，这已经超过 350 亿个子集。 即使不断进行检查，这也是无望的。 

所以真正的问题是：什么隐藏结构保证有效子集始终存在？ 

关键的观察来自配对。 按差异对框进行排序：$$a_i - o_i$$苹果比橙子多的盒子放在一侧，橙子比苹果多的盒子放在另一侧。 

现在查看此排序中的相邻对。 对于每一对，一个盒子相对来说是苹果较多，另一个盒子相对来说是橙子较多。 如果我们从每一对中恰好选择一个盒子，那么不平衡往往会被抵消。 

由于有`2N - 1`盒子，分类后我们可以形成`N - 1`相邻的一对加上一个剩余的中间盒子。 然后我们从每一对中选择一个盒子，并包括剩下的盒子，准确给出`N`选定的盒子。 

美妙之处在于只有两种自然的方法可以做到这一点：

 第一选择：

 从每对中取出左边的元素加上剩下的盒子。 

第二选择：

 从每对中取出正确的元素加上剩下的盒子。 

这两组中的一组始终满足两种水果条件。 

为什么？ 因为这两个候选集一起划分了除剩余框之外的所有框。 他们的苹果之和加起来就是苹果的总数，橙子的数量也是如此。 如果一个候选人得到的苹果少于一半，另一位候选人自动得到一半以上的苹果。 排序依据`a_i - o_i`保证同样的方向也适用于橙子。 

这将不可能的组合搜索转变为简单的基于排序的构造。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\binom{2N-1}{N} \cdot N)$|$O(N)$| 太慢了 |
 | 最佳 |$O(N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 1. 阅读所有方框并计算苹果和橙子的总数。 
2. 对于每个框，计算值：$$a_i - o_i$$这可以衡量盒子中苹果含量更多还是橙子含量更多。 

1. 按此值对框进行排序。 

排序后，相邻的盒子相对于彼此平衡。 一方面出现较大的正差异，另一方面出现较大的负差异。 

1. 构建两个候选答案集。 

第一个候选人在以下位置拿箱子：```
0, 2, 4, ...
```第二位候选人在以下位置拿箱子：```
1, 3, 5, ...
```由于数组长度是奇数，因此这些候选者之一将恰好包含`N`盒子和另一个将包含`N - 1`。 将最后剩余的框附加到较小的组中。 

1. 计算一组候选集的水果总和。 

如果它已经包含至少一半的两种水果，请打印它。 

1. 否则打印其他候选集。 

该证明保证两者之一必须有效。 

### 为什么它有效

 排序后`a_i - o_i`, 每对`(2k, 2k+1)`满足：$$(a_{2k} - o_{2k}) \le (a_{2k+1} - o_{2k+1})$$重新排列给出：$$a_{2k} + o_{2k+1} \le a_{2k+1} + o_{2k}$$这意味着从一对元素的左侧元素切换到右侧元素，苹果的增加至少与橙子的减少一样多。 

现在考虑两个候选集。 他们一起分隔所有盒子。 他们的苹果总量增加了全球苹果总量，他们的橙子总量增加了全球橙子总量。 

如果第一个候选人拥有的苹果少于一半，则第二个候选人拥有一半以上的苹果。 上述不等式保证第二个也至少有一半的橙子。 对称地，如果第一个候选者有足够的苹果，那么它也有足够的橙子。 

因此，一名候选人必须满足这两个条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        boxes = []
        total_a = 0
        total_o = 0

        for i in range(1, 2 * n):
            a, o = map(int, input().split())
            boxes.append((a - o, a, o, i))
            total_a += a
            total_o += o

        boxes.sort()

        cand1 = []
        cand2 = []

        sum1_a = 0
        sum1_o = 0

        sum2_a = 0
        sum2_o = 0

        for i in range(2 * n - 1):
            _, a, o, idx = boxes[i]

            if i % 2 == 0:
                cand1.append(idx)
                sum1_a += a
                sum1_o += o
            else:
                cand2.append(idx)
                sum2_a += a
                sum2_o += o

        need_a = (total_a + 1) // 2
        need_o = (total_o + 1) // 2

        if sum1_a >= need_a and sum1_o >= need_o:
            out.append("YES")
            out.append(" ".join(map(str, cand1)))
        else:
            out.append("YES")
            out.append(" ".join(map(str, cand2)))

    sys.stdout.write("\n".join(out))

solve()
```实施直接跟随构造。 

每个盒子存储为：```
(a - o, a, o, index)
```第一个值是排序键，而原始计数和索引将被保留以供以后使用。 

排序后，我们按索引奇偶校验拆分数组。 由于盒子总数是奇数，偶数位置恰好包含`N`元素和奇数位置包含`N - 1`。 构造定理保证偶数索引集就足够了，否则如果我们选择相反的奇偶校验约定，奇数索引集就足够了。 因为排序后的长度是`2N - 1`，偶数索引位置包含`N`元素。 

一半要求使用上限除法计算：```
(total + 1) // 2
```当总数为奇数时，这一点至关重要。 

Python 整数安全地处理高达`10^9`甚至更远，所以溢出不是问题。
