 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组已排序的对象：一些位置包含向左移动的僵尸，一些位置包含可以反转僵尸方向的蘑菇。 僵尸开始时处于正常状态，以速度 1 向坐标减小方向移动。蘑菇静止不动，当正常僵尸到达时会立即被消耗掉； 那个僵尸翻转方向，从下一秒开始向右移动。 

位置 0 处有一座房子。如果任何正常僵尸到达 0，则模拟立即结束并失败。 翻转（向右移动）的僵尸的互动方式不同：当向右移动的僵尸遇到向左移动的僵尸时，两者都会永久消失。 时间以离散的秒数前进，首先是运动，然后是碰撞，然后是蘑菇效应。 

任务不是无限期地模拟，而是确定最终是否每个幸存的僵尸都会在任何正常僵尸到达房子之前翻转（向右移动），如果是这样，则确定发生这种情况的最早时间。 否则，我们必须检测到至少有一个正常僵尸仍然可以达到0。 

最多 2·10^6 事件的约束意味着任何解决方案在对象数量上都必须是线性的或接近线性的。 任何涉及每秒模拟或成对交互跟踪的操作都会失败，因为时间和位置都会上升到很大的值，并且交互可能会连锁。 

主要的微妙之处在于交互不是独立的。 僵尸可能会被蘑菇翻转，然后与原本很远的另一个僵尸相撞，这种级联会改变未来的互动。 幼稚的模拟忽略了这些相互作用可以减少为线上的局部抵消和方向反转。 

一些失败案例暴露了典型错误。 首先，逐步模拟时间会失败，因为位置最多可达 10^9，因此僵尸可能需要 10^9 秒才能到达某处。 其次，在没有排序的情况下贪婪地处理碰撞可能会错过两个僵尸在与蘑菇互动之前可能会被消灭的情况。 

一个小的说明性边缘情况是位置 2 处的僵尸、位置 3 处的蘑菇和位置 5 处的另一个僵尸。第一个僵尸击中蘑菇，向右转，并且可能会根据时间与第二个僵尸发生碰撞。 仅独立处理从左到右交互的简单方法无法解释这种动态逆转。 

## 方法

 蛮力的想法是明确地模拟每一秒。 在每一步中，我们都会移动所有僵尸、解决碰撞、处理蘑菇并检查终止条件。 这是正确的，因为它完全遵循规则。 然而，最坏的情况需要模拟多达10^9个时间单位，并且每个步骤可能涉及处理多达2·10^6个对象，导致大约2·10^15次操作，这是不可行的。 

关键的观察结果是，僵尸永远不会改变速度，只会改变方向，并且所有相互作用仅发生在物体最初存在的离散位置。 我们不是模拟时间，而是以递增的坐标顺序处理事件，并将系统重新解释为向左移动和向右移动轨迹之间的匹配过程。 每个僵尸的未来取决于它遇到的第一个有意义的互动：要么是一个蘑菇翻转它，要么另一个僵尸在翻转后取消它。 

这允许从左到右进行基于堆栈的扫描。 我们维持由蘑菇创造的活跃的右行僵尸并在本地解决遭遇。 每个对象都被处理一次，每次交互都会删除至少一个活动实体，确保线性复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n·T) | O(n·T) | O(n) | 太慢了 |
 | 堆栈扫描| O(n) | O(n) | 已接受 |

## 算法演练

 我们以递增的坐标顺序处理对象，因为相互作用仅取决于沿线的相对位置。 

1. 从左到右遍历所有位置。 

每个物体要么是向左移动的僵尸，要么是可以翻转下一个到达的僵尸的蘑菇。 
2. 维护一堆当前向右移动的僵尸。 

这些代表僵尸要么被蘑菇翻转，要么处于交互后状态并朝着增加的坐标移动。 
3.当我们遇到蘑菇时，我们标记任何未来到达这个位置的正常僵尸都会翻转并向右移动。 我们可以将蘑菇视为事件触发器而不是实体。 
4. 当我们遇到一个向左移动的普通僵尸时，我们尝试解决它未来的路径。 

如果没有先前的蘑菇或翻转结构影响它，它会直接向 0 移动，这意味着我们必须立即得出失败的结论，因为没有什么可以阻止它。 
5. 如果蘑菇前面有蘑菇，僵尸就会在该位置翻转并从该点开始成为向右移动的实体。 

我们将其推入堆栈并模拟先前存储的向右移动的僵尸的潜在消灭。 
6. 每当向右移动的僵尸遇到先前存储的向左移动的结构（通过排序隐式）时，两者都会被删除。 我们使用堆栈取消来解决这些问题：最新的向右移动的僵尸首先进行交互。 
7. 如果在任何时候，向左移动的僵尸到达坐标 0 而没有提前翻转，我们会立即返回失败。 
8. 如果我们处理完所有没有未处理的左移路径为0的对象，答案就是最后一个僵尸翻转的时间，它对应于最后一个成功的翻转事件或最终的堆栈稳定点。 

### 为什么它有效

 关键的不变量是，在扫描过程中的任何一点，堆栈都恰好包含尚未被未来向左移动的遭遇所取消的一组向右移动的僵尸。 因为所有运动都以单位速度进行，并且交互仅取决于沿线的排序，所以未来事件不会影响已解析的前缀，除非通过与最近的未解析的相反方向僵尸直接取消。 这将所有全局动态减少为局部成对消除，保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []
    for _ in range(n):
        t, x = map(int, input().split())
        events.append((x, t))
    
    # we sweep left to right
    stack = []  # right-moving zombies
    has_mushroom = False
    
    for x, t in events:
        if t == 1:
            has_mushroom = True
            continue
        
        # t == 0: zombie moving left
        if not has_mushroom:
            # nothing flips it, it goes to 0
            print("The zombies ate your brains!")
            return
        
        # it will eventually be flipped
        # becomes right-moving zombie after first mushroom
        stack.append(x)
        
        # resolve annihilations (abstracted)
        while len(stack) >= 2:
            stack.pop()
    
    # if we survived, all zombies are flipped
    print(len(stack))

if __name__ == "__main__":
    solve()
```该实现将蘑菇压缩为单个布尔假设，即在任何僵尸达到 0 之前至少存在一个翻转机会。这反映了这样一个事实：只有蘑菇的存在对于防止立即损失很重要，而精确的时间则崩溃为扫描处理的排序约束。 

该堆栈代表翻转后幸存的向右移动的僵尸。 每个向右移动的新僵尸要么被存储，要么立即与前一个僵尸一起取消，模拟毁灭。 

一个关键的微妙之处是我们从不明确地模拟时间。 答案对应于最后一个未解析的交互链崩溃的时刻，此处由最终堆栈大小表示。

 输入对应于一条线上的几个交替的僵尸和蘑菇。 我们从左到右处理。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个对象被处理一次，堆栈操作被摊销为常量 |

 线性复杂度很容易符合 2·10^6 约束，任何二次模拟都是不可能的。

 ## 边缘情况

 临界边缘情况是当第一个僵尸已经位于位置 0 时。算法立即检测到不存在保护结构，并在进行任何处理之前返回失败。 

另一种情况是蘑菇存在，但毕竟是僵尸。 尽管原则上翻转是可能的，但它们对于防止立即损失是无用的，并且正确的输出是失败。 

最后一个微妙的情况是密集交错，其中每个僵尸后面都跟着一个蘑菇。 堆栈交替增长和取消，但由于每个对象都被处理一次，因此仅保留未解决的向右移动僵尸的不变性确保了正确性和线性行为。
