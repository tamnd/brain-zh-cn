 ## 解决方案
 ## 问题理解

 城市是一个无向连通图，其中每栋房屋都是一个顶点，每条道路都是一条未加权的边。 邮政枢纽必须正好放置在一个顶点上。 此后，有几次计划的交付，每次交付都包括将包裹从源房屋移动到目的地房屋。 每次送货时，快递员首先从源地走到枢纽，然后从枢纽走到目的地，每经过一条路支付一个单位的成本。 

固定枢纽的总成本是所有交付的这些成本的总和。 任务是选择使总成本最小化的枢纽位置。 

输入大小表明该图的节点数量并不大，但在最坏的情况下可能具有密集的边数。 n 和 m 的乘积约束可防止同时出现大值，这通常表明 O(nm) 或 O(n(n+m)) 解在预期解空间中是可接受的，而 k 中的任何二次方或 n 中的三次方都将超出范围。 

一个天真的想法是尝试每个可能的中心，并通过从该中心运行最短路径搜索或重复重新计算距离来计算其总成本。 这立即变得昂贵，因为它需要重新计算每个候选中心的最短路径，导致重复遍历图。 

当没有交付时，会出现微妙的边缘情况。 在这种情况下，每个节点的成本为零，因此任何顶点都是有效的。 正确的解决方案不能假设至少存在一次交付。 

当多个集线器都追求最低成本时，就会出现另一个极端情况。 该问题允许返回其中任何一个，因此解决方案不得尝试强制执行超出正确性的确定性平局打破。 

## 方法

 直接的方法是独立评估每个可能的枢纽。 对于固定的中心 x，我们计算从 x 到所有节点的最短路径距离，然后对于每个交付 (c, d)，我们添加 dist(c, x) + dist(x, d)。 由于图是未加权的，因此每个最短路径计算都可以使用 BFS 来完成。 对每个候选集线器重复 BFS 意味着运行 n 次 BFS 遍历，每次成本为 O(n + m)。 这导致 O(n(n + m)) 次操作，在最坏的情况下接近约束 n · m ≤ 10^8 所暗示的允许工作的上限。 它在概念上是正确的，但浪费了重复的结构：每个 BFS 重新计算相同的距离信息。 

关键的观察结果是成本表达式在端点之间完全分离。 对于固定集线器 x，总成本变为请求中出现的所有端点的总和。 每次传递都会贡献 dist(x, c) 和 dist(x, d)，因此我们可以定义一个权重 w[u]，等于节点 u 作为源或目的地出现的次数。 集线器 x 的总成本变为 w[u] · dist(x, u) 的所有节点 u 的总和。 这完全消除了对对的依赖，并将问题转变为评估每个候选根的加权距离和。 

现在的任务变成计算未加权图中的所有对最短路径距离，或者至少有足够的结构来评估这些加权和。 由于在最坏的情况下每对节点之间都需要距离，因此从每个节点运行 BFS 是最直接的方法。 一旦知道了所有距离，计算每个候选中心的加权和就变成了直接聚合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重新计算每个集线器的 BFS | O(n(n + m)) | O(n(n + m)) | O(n) | 最坏情况下太慢 |
 | 全对 BFS + 聚合 | O(n(n + m)) | O(n(n + m)) | O(n^2) | O(n^2) | 在限制条件下接受|

 ## 算法演练

1. 阅读图形并构建邻接表。 该图是未加权的，因此 BFS 是计算最短路径的自然方法。 
2. 构建一个数组 w，其中 w[u] 计算节点 u 在所有交付端点中出现的次数。 每次交付都会为其来源贡献+1，为其目的地贡献+1。 这种重新表述用每个节点的权重取代了成对贡献。 
3. 对于从 1 到 n 的每个节点 s，运行 BFS 来计算 dist[s][*]，即从 s 到所有其他节点的最短距离。 此步骤是必要的，因为最终成本取决于从每个可能的集线器到所有加权节点的距离。 
4. 计算距固定源 s 的距离后，通过对所有节点 u 上的 w[u] · dist[s][u] 求和来计算其成本。 这表示集线器放置在 s 时的总成本。 
5. 跟踪计算成本最小的节点。 如果多个节点达到相同的最小值，则可以存储任何一个。 
6.输出最佳节点。 

BFS层结构保证了最短距离的正确性，因为每条边都有单位权值，所以BFS中第一次访问节点对应的是它的最小距离。 

### 为什么它有效

 从对贡献到节点权重的转换保留了总成本，因为每次交付恰好贡献了两个独立的最短路径项。 由于最短路径距离满足无向图中的对称性和求和的线性性，因此按端点重新分组项不会改变总值。 一旦进行分解，每个候选集线器都会根据相同的固定加权距离函数进行评估，因此选择所有节点上的最小值相当于解决原始优化问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj, n):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0

    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def main():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    k = int(input())
    w = [0] * (n + 1)

    for _ in range(k):
        c, d = map(int, input().split())
        w[c] += 1
        w[d] += 1

    # edge case: no deliveries
    if k == 0:
        print(1)
        return

    best_node = 1
    best_cost = float('inf')

    for s in range(1, n + 1):
        dist = bfs(s, adj, n)
        cost = 0
        for i in range(1, n + 1):
            cost += w[i] * dist[i]
        if cost < best_cost:
            best_cost = cost
            best_node = s

    print(best_node)

if __name__ == "__main__":
    main()
```BFS 函数使用队列计算单源最短路径。 外循环将每个节点评估为候选集线器。 对于每个候选者，我们重复使用相同的距离数组来计算线性时间内的加权和。 

一个微妙的实现细节是用 -1 初始化距离。 这可以避免重新访问节点并清楚地区分不可到达的状态，即使图是保证连接的。 另一个重要的点是将权重累加与 BFS 计算分开； 混合它们会导致 BFS 内部重复冗余求和并显着增加运行时间。 

## 工作示例

 考虑一个小图，其中的距离很容易理解。 假设我们将每个节点评估为潜在的中心，并根据端点频率计算加权和。 

对于简单跟踪，假设节点 1、2、3 形成一条线 1-2-3，并且有交付 (1,3) 和 (3,1)。 那么w[1] = 2，w[3] = 2，w[2] = 0。 

对于每个候选中心：

 | 枢纽| 距离 1 | 距离 2 | 距离 3 | 成本计算|
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 2 | 2·0 + 0·1 + 2·2 = 4 |
 | 2 | 1 | 0 | 1 | 2·1 + 0·0 + 2·1 = 4 |
 | 3 | 2 | 1 | 0 | 2·2 + 0·1 + 2·0 = 4 |

 所有节点都绑定，因此任何节点都是有效的。 这表明端点的对称性导致成本分布对称。 

现在考虑一种倾斜情况，其中大多数交付共享一个端点，假设许多对从节点 1 开始并转到不同的节点。 然后w[1]变大，并且最佳集线器向从节点1到其他节点的最短路径的中心移动，因为最小化加权距离有效地将集线器拉向高频节点。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n(n + m)) | O(n(n + m)) | BFS 从每个节点运行，每个 BFS 处理所有边一次 |
 | 空间| O(n^2) | O(n^2) | 距离矩阵根据源隐式存储或重新计算

 约束 n · m ≤ 10^8 确保运行 n 次 BFS 遍历是可行的，因为最坏情况的乘积仍然有界。 内存是可以接受的，因为 n 最多为 10^4，并且每个源的存储距离或重新计算都在限制范围内。

 ## 边缘情况

 当没有投递时，算法直接返回有效节点，不进行BFS。 这可以防止不必要的计算，并避免成本数组未使用时出现未定义的行为。 

对于所有交付端点都集中在一个节点（例如节点 1）的图表，权重数组严重偏向与候选集线器的距离，以最小化到节点 1 的距离。基于 BFS 的成本评估正确地反映了这一点，因为所有成本贡献都减少到 w[1]·dist(x, 1)，因此最佳节点成为一个最小化到节点 1 的距离的节点。 

在完全对称的图中，例如循环图或完整图，所有节点在统一的端点分布下产生相同的加权和。 该算法自然地通过评估候选者之间相同的成本值并接受遇到的第一个最小值来保留这一点。
