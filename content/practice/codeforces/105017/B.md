 ## 解决方案
 ## 问题理解

 我们正在模拟一个重复多次的非常简单的随机过程。 我们从一个大小的数组开始$n$，最初全为零。 然后我们执行$m$独立操作，每个操作选择其中之一$n$随机均匀定位并加一。 完成所有操作后，我们以随机分布结束$m$在数组中递增。 

重要的不是最终的确切数组，而是至少一个位置达到大于或等于给定阈值的值的事件$K$。 换句话说，扔完之后$m$相同的“单位增量”$n$bin 均匀随机，我们希望某个 bin 至少包含的概率$K$增量。 

约束足够小，使得涉及计数的状态的多项式时间动态规划解决方案是可行的。 两个都$n$和$m$最多 300，所以任何解决方案$O(nm^2)$或者$O(nmK)$会在时间限制内轻松通过。 这立即排除了所有的指数枚举$n^m$序列，这相当于直接模拟每个可能的选择序列。 

出现微妙的边缘情况时$K = 0$。 在这种情况下，每个元素至少自动$0$，所以答案始终是 1。另一个边缘情况是$K > m$，任何元素都不可能到达，因为没有一个位置可以接收超过$m$增量。 在这种情况下，答案是 0。在纯粹的组合公式中，这些情况很容易被忽视，但它们可以通过对过程的推理而自然地得出。 

## 方法

 直接方法将模拟所有$m$步骤并计算有多少选择序列产生有效的最终配置。 每一步都有$n$选择，所以有$n^m$总序列。 即使是为了$n = 300$和$m = 300$，这是一个天文数字，所以直接枚举是不可能的。 

关键的转变是停止考虑操作序列，而是考虑每个索引被选择的次数。 每个结果对应一个向量$(a_1, a_2, \dots, a_n)$使得总和为$m$，以及每个$a_i$是索引的次数$i$被选中。 任何此类配置的概率仅取决于多项系数。 

我们想要的活动是“所有$a_i \le K-1$”。因此，不要直接计算某些配置$a_i \ge K$，更容易计算所有配置$a_i \le K-1$，并从 1 中减去。 

为了计算有效配置，我们在 bin 上使用动态编程。 我们逐一处理索引，并维护到目前为止已分配的增量数量。 对于每个 bin，我们尝试从 0 到$K-1$，并累积由多项系数的阶乘项加权的贡献。 这将问题简化为超过 300 x 300 个状态的有界背包式 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 枚举所有序列 |$O(n^m)$|$O(1)$| 太慢了|
 | DP over bins 有界计数 |$O(n \cdot m \cdot K)$|$O(m)$| 已接受 |

 ## 算法演练

 我们计算补集事件的概率：每个元素最多接收$K-1$增量。 让$dp[i][j]$使用第一个表示有效分布的总加权和$i$指数使得恰好$j$到目前为止已经分配了增量，其中每个配置贡献一个因子$1 / (a_1! a_2! \dots a_i!)$。 

1. 初始化一个所有值都为零的表，并设置$dp[0][0] = 1$。 这表示在分配任何 bin 之前，恰好有一种空方法来分配零增量。 
2. 迭代每个索引$i$从 1 到$n$。 在每一步中，我们决定增量的数量$t$进入索引$i$， 但$t$被限制在范围内$0 \le t \le \min(K-1, m - j)$。 这确保我们尊重全局总和和每个容器的限制。 
3. 对于每个可能的总数$j$从 0 到$m$，通过添加之前状态的贡献来更新 DP：$$dp[i][j] += \frac{dp[i-1][j-t]}{t!}$$本次划分由$t!$考虑分配的内部排列$t$标记操作到同一个容器。 
4.处理完所有bin后，$dp[n][m]$包含数量的所有有效有界分布的总和$1 / (a_1! \dots a_n!)$。 
5. 将此值乘以$m!$恢复有效操作序列的数量。 所有可能序列的总数为$n^m$，因为每个$m$操作独立选择其中之一$n$指数。 
6. 最终概率为：$$\text{answer} = 1 - \frac{\text{valid sequences}}{n^m}$$正确性来自于这样的事实：每个操作序列唯一对应于一个多项式计数向量，并且DP在没有坐标超过的约束下枚举所有这样的向量$K-1$，同时正确考虑相同分配的排列数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, K = map(int, input().split())

    if K == 0:
        print(1.0)
        return
    if K > m:
        print(0.0)
        return

    # factorials up to m
    fact = [1.0] * (m + 1)
    for i in range(1, m + 1):
        fact[i] = fact[i - 1] * i

    dp = [[0.0] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = 1.0

    for i in range(1, n + 1):
        for j in range(m + 1):
            if dp[i - 1][j] == 0:
                continue
            max_add = min(K - 1, m - j)
            base = dp[i - 1][j]
            for t in range(max_add + 1):
                dp[i][j + t] += base / fact[t]

    good = fact[m] * dp[n][m]
    total = float(n) ** m
    ans = 1.0 - good / total
    print(ans)

if __name__ == "__main__":
    solve()
```代码直接遵循DP解释。 阶乘数组是预先计算的，以避免重复计算$t!$内部过渡。 DP 表累积了以下形式的贡献$1 / (a_i!)$，最后乘以$m!$重建真实的多项式计数。 

这里的一个常见错误是忘记阶乘出现的原因。 它们不是任意的权重，而是将“分配不可区分的计数”转换为“对标记的操作序列进行计数”的精确校正因子。 

另一个微妙之处是数值稳定性。 对于双精度来说，这些值仍然足够小，因为 DP 在最终缩放步骤之前累积归一化阶乘分数。 

## 工作示例

 考虑一个小例子，其中$n = 2$,$m = 3$,$K = 2$。 我们想要至少一个 bin 具有至少 2 个增量的概率。 补充是两个 bin 最多都有 1 增量。 

我们跟踪 DP 状态作为两个 bin 上的分布。 

| i（已使用的垃圾箱）| j（总分配）| dp 值概念上 |
 | ---| ---| ---|
 | 0 | 0 | 1 |

 处理第一个 bin 后，我们允许它获取 0 或 1 个项目。 

| 我| j | 过渡|
 | ---| ---| ---|
 | 1 | 0 | 1 |
 | 1 | 1 | 1 |

 处理完第二个垃圾箱后，我们在相同的约束下分配剩余的项目。 

| 我| j | DP |
 | ---| ---| ---|
 | 2 | 0 | 1 |
 | 2 | 1 | 2 |
 | 2 | 2 | 1 |
 | 2 | 3 | 0 |

 所以$dp[2][3] = 0$，意味着如果某个箱子的容量不超过容量 1，则无法分配 3 个增量。因此概率为 1，这与 3 个球和 2 个箱子的事实相符，某些箱子必须至少收到 2 个球。 

此跟踪演示了 DP 如何强制执行每个 bin 上限，同时仍然考虑标记操作的所有分布。

 ## 边缘情况

 当$K = 0$，条件“至少一个元素 ≥ K”始终为真。 该算法在 DP 之前立即处理此问题，返回 1，而不进入任何状态计算。 

什么时候$K > m$，没有索引可以积累足够的增量，因为只有$m$总操作。 提前返回避免了不必要的计算并正确输出0。 

当$n = 1$，所有增量都必须进入单个位置，因此结果成为确定性检查是否$m \ge K$。 DP 折叠成一条路径，最后乘以$m!$正确地重建准确的一个有效序列。 

什么时候$m = 0$，数组保持全零，所以答案仅取决于是否$K \le 0$。 DP 自然地仅用基态来表示这一点$dp[0][0]$，但早期的情况简化了处理并防止阶乘逻辑中被零除式的混乱。
