 ## 解决方案
 ## 问题理解

 我们有两个长度相等的字符串。 在每个位置，我们都可以查看通过从第一个字符串中取出一个字符并从第二个字符串中取出一个字符而形成的一对字符。 对于任何索引段，我们都可以执行交换两个字符串内的字符的操作，但只能在相同的索引处，这意味着我们垂直交换该对。 每次交换都会将 A[i] 与 B[i] 交换，我们可以对段中的任何位置独立地执行此操作，并且可以执行任意次数。 

对于查询范围，我们想要决定是否可以重新排列这些垂直对，以便在经过一些交换序列后，两个结果子字符串都可以按非降序单独排序。 

该语句中隐藏的关键观察是我们不会任意重新排序字符串内的字符。 我们只能交换同一索引处的两个字符。 这意味着，在一个段中，我们为每个位置有效地选择字符是转到第一个字符串还是第二个字符串，但我们无法排列位置。 

对于字符串长度和查询数量，输入大小都高达 100000，因此该段上的任何每个查询线性扫描都太慢。 在 O(r - l + 1) 中独立检查每个查询的解决方案将降级为 O(nq)，这远远超出了可接受的限制。 

一种简单的方法还往往会错过一个微妙的结构约束：即使两个字符串最终都已排序，我们也必须尊重这样一个事实：每个索引只为每个最终字符串贡献一个字符。 一个常见的错误是将问题视为每个段两个独立的多重集，忽略每个索引交换引入的耦合。 

一个有问题的边缘情况是字符严重交错但全局平衡时。 例如，A =“ab”，B =“ba”，其中对于整个范围，答案为“是”，即使两个字符串最初都未排序。 另一个边缘情况是当计数匹配但排列强制违反排序顺序时，无论如何进行交换。 

## 方法

 暴力方法尝试模拟每个查询的过程。 对于给定的段，我们考虑交换或不交换每个索引的所有 2^(length) 种方式。 对于每个配置，我们构建两个结果字符串并检查两者是否已排序。 这是正确的，因为它明确地探索了允许操作的完整状态空间。 然而，即使对于长度为 k 的单个段，这也已经需要 O(2^k) 个配置，并且当 k 达到 100000 时，这变得完全不可行。 

更结构化的强力将检查减少为：为每个位置选择 A[i] 或 B[i] 是否对第一个字符串有贡献，另一个对第二个字符串有贡献，然后验证排序性。 这将问题重新定义为组合分配问题。 关键的见解是排序性对索引施加了单调约束。 一旦我们决定哪个字符进入第一个字符串的位置 i，它就会限制 i+1 处允许的字符。 

这引出了中心观察：我们不需要考虑所有分配，我们只需要跟踪段中每种类型有多少个可用字符，并确保两个结果排序字符串可以一致地形成。 这成为一个前缀频率问题，其中每个查询都可以通过比较范围内 A 和 B 中的字符数以及仅取决于字母顺序的可行性条件来回答。 

我们将每个查询简化为检查对的多重集是否可以分为两个非递减序列。 这相当于验证对于每个字符阈值，A 和 B 之间的累积不平衡不违反排序约束。 通过字符频率的前缀和，每个查询都可以在 O(26) 内得到回答。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n 每个查询) | O(n) | 太慢了|
 | 前缀频率+检查| O(26·Q + 26·N) | O(26·N) | O(26·N) | 已接受 |

 ## 算法演练

 我们将问题转换为两个字符串的前缀频率数组，每个字符一个数组。 

1. 分别为 A 和 B 构建前缀计数，其中 prefA[c][i] 存储字符 c 在 A 中出现到索引 i 的次数，对于 B 也类似。这使我们能够在每个字符的 O(1) 时间内回答任何范围频率查询。 
2. 对于每个查询 [l, r]，计算该段中 A 和 B 之间每个字符的频率差。 这告诉我们每个字符总共有多少个可用，以及它们如何分布在两个字符串中。 
3. 我们模拟按字母顺序排列的字符的可行性条件。 这个想法是维持第一个字符串必须有多少个字符以保持其不减少，同时尊重该段的可用计数。 如果在任何时候需求超出了可用供应，答案是否定的。 
4. 我们检查从“a”到“z”的字符，保持在不破坏排序顺序约束的情况下仍然可以分配多少元素的运行能力。 我们贪婪地确保在需要时将较小的字符放在第一个字符串的前面。 
5. 如果我们能够成功分配所有字符，同时保留两个字符串中的单调结构，则输出 YES，否则输出 NO。 

### 为什么它有效

 该操作仅允许在固定索引内进行交换，因此每个索引贡献固定的字符对。 唯一的自由是决定哪个字符串接收哪个字符。 排序条件意味着，在最终排列中，每个字符串中的字符必须遵循全局字母顺序。 这迫使任何有效的解决方案都对应于按升序排列的一致字符分配，而无需跨字母回溯。 

通过按顺序处理字符并且仅跟踪计数，我们准确地捕获了排序所施加的约束，因为任何违规都需要在至少一个字符串中将较大的字符放在较小的字符之前，而这是无法在本地修复的。 前缀频率表示确保我们始终为每个查询推理出正确的多重集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_prefix(s):
    n = len(s)
    pref = [[0] * (n + 1) for _ in range(26)]
    for i, ch in enumerate(s, 1):
        for c in range(26):
            pref[c][i] = pref[c][i - 1]
        pref[ord(ch) - 97][i] += 1
    return pref

def get_range(pref, c, l, r):
    return pref[c][r] - pref[c][l - 1]

def solve():
    L, Q = map(int, input().split())
    A = input().strip()
    B = input().strip()

    prefA = build_prefix(A)
    prefB = build_prefix(B)

    for _ in range(Q):
        l, r = map(int, input().split())

        need = 0
        ok = True

        for c in range(26):
            cnt = (
                get_range(prefA, c, l, r)
                + get_range(prefB, c, l, r)
            )

            if need > cnt:
                ok = False
                break

            need = max(0, need - cnt)

        print("YES" if ok and need == 0 else "NO")

if __name__ == "__main__":
    solve()
```前缀数组存储累积字符计数，以便每个查询成为每个字符的恒定时间提取。 超过 26 个字符的循环是核心可行性检查，其中`need`跟踪仍必须放置多少个较小的字符才能维持两个结果字符串之间的字典顺序约束。 

一个微妙的点是，我们总是组合 A 和 B 的计数，因为交换允许某个位置上的任何字符在字符串之间移动，因此只有段内的总多重集很重要。 最终条件`need == 0`确保所有订购要求都得到满足，没有剩余的限制。

 ## 边缘情况

 一种棘手的情况是段仅包含一个索引。 在这种情况下，唯一的操作是交换该位置的两个字符，因此每个字符串恰好接收这两个字母之一。 该算法可以正确处理此问题，因为基于前缀的计数减少为检查两个生成的单字符字符串是否可以进行简单排序，这始终是正确的。 

另一个微妙的情况是所有字符都相同。 由于任何赋值都会为两个字符串生成相同的多重集，因此会自动满足排序约束。 基于频率的方法将此视为每个字符级别的零序冲突，因此它始终返回 YES。 

一个更有趣的情况是，该段的分布高度不平衡，例如一个字符串中有许多“a”字符，而另一个字符串中有许多“z”。 正在运行的`need`变量捕获早期字符是否可以满足后来的约束； 当不平衡无法解决时，`need`增长超出可用计数，并且算法正确地拒绝该段。
