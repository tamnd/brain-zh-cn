 ## 解决方案
 ## 问题理解

 给定一长串十进制数字，当解释为整数时，我们需要计算它有多少个连续子串表示能被 11 整除的数字。 

每个子字符串都是通过选择开始位置和结束位置并按顺序取出中间的所有数字而形成的，无需重新排序。 如果所得数字能被 11 整除，则它有助于答案。 

这些约束清楚地表明输入总量很大，而不是每个测试用例的输入量很大。 所有测试用例的总长度高达一百万，这迫使任何解决方案在总大小上基本上是线性的。 在最坏的情况下，任何尝试直接检查所有子串的方法都需要每个测试用例大约 n² 个子串，这远远超出了可行的限制。 

当尝试直接或什至使用滚动算术计算每个子字符串的数值时，会出现一种常见的失败模式。 即使对 11 进行运算，仍然有 O(n²) 个子串，并且常数因子太大。 

另一个微妙的问题源于对 11 整除性的解释。例如，“0”、“11”、“121”和“1111”等子字符串在简单的数字和启发式下表现不同。 天真的尝试可能会错误地假设整除性仅取决于数字和模 11，这是错误的。 例如，“121”可以被 11 整除，但“111”则不能被 11 整除，尽管它们的数字和很接近。 

关键的困难在于我们必须认识到一种结构，使我们能够避免独立评估每个子串。 

## 方法

 直接的方法是枚举每个子串，计算其值，并测试能否被 11 整除。即使我们保持滚动值以 11 为模，每个子串的成本仍然是 O(1)，但子串的数量为 O(n²)，导致时间为 O(n²)。 当 n 总共达到 10⁶ 时，这是不可行的。 

突破来自于 11 的算术性质：当且仅当一个数的各个数字的交替和能被 11 整除时，该数才能被 11 整除。更准确地说，如果我们从左到右取数字并计算 d₁ − d2 + d₃ − d₄ + …，结果是 11 的倍数，这就是可整除性。 

这将问题从对整数的推理转换为对数字上的线性函数的推理。 一旦我们有了线性函数，每个子串就变成了前缀值的差。 这是关键的简化：我们不是直接评估子字符串，而是将每个前缀映射到单个整数值，以便子字符串的有效性仅取决于前缀状态的相等性。 

我们定义一个前缀交替和。 每个位置根据其索引奇偶性来贡献其数字+或-符号。 对于任何子串，交替结构会导致子串的贡献分解为两个前缀值的有符号差。 符号取决于起始位置，但由于我们只关心结果是否为零，因此符号变得无关紧要。 

因此，问题简化为计算相等前缀值对。 每对相等的前缀和对应一个子串，其交替和为零，因此可被 11 整除。 

我们维护前缀值的频率图，并累计每个值到目前为止出现的次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 使用模算术暴力破解子串 | O(n²) | O(1) | O(1) | 太慢了|
 | 前缀交替和+频率计数| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。

1. 初始化设置为零的前缀累加器和零值出现一次的频率图。 这表示处理任何数字之前的空前缀。 
2. 从左到右迭代字符串，保持连续的交替和。 在位置 i，我们根据 i 是偶数还是奇数来添加或减去数字。 这将创建字符串到前缀状态的一致转换。 
3. 更新每个位置的前缀状态后，我们检查该前缀值之前出现过多少次。 之前的每个出现都定义了一个以当前位置结尾的子字符串，其转换后的值会抵消为零。 
4. 我们将该频率添加到答案中，然后增加当前前缀值的频率。 
5.处理完所有位置后，累加的答案包含所有有效子串。 

关键的推理步骤是每个前缀值都对到该点的数字交替结构进行编码，因此相等的前缀值意味着中间子串上的平衡交替和。 

### 为什么它有效

 交替求和变换将数字串联转换为位置上的线性函数。 对于任何子串，其交替和等于两个前缀和的差，可能乘以 -1，具体取决于起始奇偶校验。 由于能被 11 整除仅取决于是否等于 0，因此乘法符号不起作用。 因此，在此变换下，当两个相应的前缀状态相等时，子串恰好有效。 计算子串就相当于计算相等的前缀状态对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        freq = {0: 1}
        pref = 0
        ans = 0

        for i, ch in enumerate(s):
            d = ord(ch) - 48

            if i % 2 == 0:
                pref += d
            else:
                pref -= d

            ans += freq.get(pref, 0)
            freq[pref] = freq.get(pref, 0) + 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案维护单个运行前缀值和先前看到的值的哈希图。 基于奇偶校验的符号选择是对交替和结构进行编码的。 关键的实现细节是我们永远不会重新计算子字符串上的任何内容； 当我们重新访问前缀状态时，每个子字符串都会被隐式计数。 

一个常见的错误是忘记将频率从零初始化为一。 如果没有这个，从索引零开始的子字符串将永远不会被计算在内。

 ## 边缘情况

 最小的个位数输入，例如`"0"`恰好产生一个有效的子字符串。 前缀从零开始，并在处理数字后保持为零，因此频率查找立即将其视为有效。 

具有重复零的字符串的行为与重复的相同前缀类似。 例如，`"000"`产生一个恒定的前缀状态，这意味着每对位置都贡献一个有效的子串。 该算法正确计算所有 O(n²) 子串，而无需显式枚举它们。 

像这样的字符串`"1010"`以可预测的模式替换前缀值。 该算法通过重复地重新访问相同的前缀状态来处理这个问题，这以与每个位置结束的平衡子串的数量完全匹配的方式增加频率计数。
