 ## 解决方案
 ## 问题理解

 我们给定一个长度为的二进制字符串$n$，其中每个位置要么包含一个棋子，要么为空。 棋盘是一条线，棋子只能以非常受限的方式移动：棋子可以向左或向右“跳跃”两个单元格，但前提是中间单元格被占用且目标单元格为空。 

该限制使移动成为局部的并且依赖于相邻性，因此 pawn 不会独立移动。 相反，它们的行为就像必须在非常特定的意义上保持连接的群体：移动总是在三个连续单元格的小窗口中保留交替占用的模式。 

任务不是模拟移动，而是计算在任何有效移动序列下，从初始配置开始，可以出现多少种不同的棋子配置。 如果两个配置所占用的单元不同，则认为它们不同。 

约束足够严格，任何状态图探索都是不可能的。 总共有$n$最多$10^5$在测试用例中，即使每个测试用例的线性 BFS 也已经是临界值，并且 pawn 或配置数量呈指数增长的任何东西都是立即不可行的。 

一个微妙的点是，这些动作在弱意义上是可逆的：在对称配置中，左跳可以通过右跳来撤销，但并不总是直接的。 这会在配置图中创建高度结构化而非任意的连接组件。 

一个典型的错误是独立对待棋子或假设任何局部重新排列都是可能的。 例如，从`0110`，人们可能会错误地认为两个相邻排列的所有排列都是可达的，但实际上只有某些保留奇偶性的配置是有效的。 

第二个常见的失败是尝试贪婪地模拟动作，动态扩展状态。 即使对于小$n$，这很快就会爆炸，因为可达状态的数量在状态的聚集区域中组合增长。 

## 方法

 暴力方法将使用位掩码上的 BFS 或 DFS 显式模拟所有可到达的配置。 每个状态都是一个$n$位串，每个状态可以通过本地移动生成多个邻居。 在最坏的情况下，状态数量可能呈指数级增长$n$，因为每次移动都可以创建分支配置，并且不存在以简单方式限制增长的单调势函数。 即使每个状态只生成$O(n)$状态空间本身早就成为瓶颈$n=100$。 

关键的观察结果是，移动规则实际上并没有产生任意的重新排列。 棋子的移动仅取决于三个连续单元的局部模式，最重要的是，每次移动都保留了棋子的数量，并且还保留了隐藏的结构：该配置可以分解为用零分隔的独立片段，但不是简单意义上的连续块。 相反，相关结构基于连续段的最大段内的奇偶校验和配对。 

在连续片段的任何最大片段内，重要的是存在多少个不相交的相邻片段“对”。 每次移动都会有效地在这样的对上移动棋子，这意味着内部自由度对应于选择哪些对参与“移动”以及哪些保持固定。 这导致了组合计数问题，其中每个段根据其长度和内部结构贡献一个二项式因子。 

更准确地说，长度连续的每个最大块$L$贡献了许多可达配置，这些配置等于斐波那契式计数，该计数是通过选择哪些相邻对可以“激活”而不会重叠而产生的。 区块之间的独立性来自于充当硬分隔符的零：任何动作都不能跨越零，因此区块独立发展并且它们的贡献成倍增加。 

这减少了从状态上的图可达性到已知组合量的分段上的乘积的问题。

 ## 算法演练

 1. 扫描字符串并将其分成最大的连续段，仅包含`'1'`。 每个这样的段都是独立的，因为零阻止段之间的任何交互。 这将问题简化为单独解决每个部分。 
2.对于每段长度$L$，使用预先计算的动态递归计算其对答案的贡献。 这种递归性源于考虑前两个是否形成“固定对”，或者结构是否以由可能的移动引起的间隙状配置开始。 
3. 定义$dp[i]$作为一段长度内可达配置的数量$i$。 为了$i < 2$，该值微不足道，因为不可能进行任何移动。 对于较大的$i$，转换反映了最左边的结构要么锁定第一对，要么向前跳跃，具体取决于移动是否在边界有效使用。 这导致与斐波那契增长相同的线性递归。 
4. 预计算$dp[i]$达到最大$n$跨所有测试用例，以便可以在恒定时间内评估每个部分。 
5. 将所有段的贡献乘以模$998244353$以获得测试用例的最终答案。 

### 为什么它有效

 关键的不变量是移动永远不会混合不同的零分隔段，并且在一个段内，可达配置仅取决于以链式方式传播的局部邻接模式。 可以通过选择每个内部邻接是否参与交换链或保持固定来唯一地描述从段可达的每个配置。 这会导致可达状态和沿线性结构的有效二元决策之间的双射，这正是斐波那契递推所计算的。 

由于没有任何移动可以破坏一个段或合并两个段，因此分解在所有操作中都是稳定的，并且独立性确保了乘法性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def build_dp(n):
    if n == 0:
        return []
    dp = [0] * (n + 1)
    dp[0] = 1
    if n >= 1:
        dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD
    return dp

def solve():
    t = int(input())
    arr = []
    strings = []

    max_n = 0
    for _ in range(t):
        n = int(input())
        s = input().strip()
        strings.append(s)
        max_n = max(max_n, n)

    dp = build_dp(max_n)

    for s in strings:
        ans = 1
        n = len(s)
        i = 0
        while i < n:
            if s[i] == '0':
                i += 1
                continue
            j = i
            while j < n and s[j] == '1':
                j += 1
            length = j - i
            ans = (ans * dp[length]) % MOD
            i = j
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先构建一个达到最大输入大小的斐波那契式表，因为每个段都会查询它。 这避免了重新计算每个测试用例的动态值。 

然后，对于每个测试用例，它扫描字符串并提取连续字符串的最大块。 每个块都映射到一个预先计算的值，最终的答案是所有块贡献的乘积。 

关键的实现细节是正确的分割：零必须完全重置块边界，否则两个独立的结构将在计算中错误地交互。

 ### 示例 1：`0110`我们将字符串分解为单个块`11`长度为 2，被零包围。

这与以下事实相匹配：在两个相邻的棋子内，恰好有两个可达到的稳定配置：原始排列和由允许的移动约束引起的交换结构。 

### 示例 2：`01010`这分解为两个独立的单棋子片段：`"1"`和`"1"`。 

| 步骤| 细分 | 长度 | dp[长度] | 结果 |
 | --- | --- | --- | --- | --- |
 | 1 | “1”| 1 | 1 | 1 |

 最终答案是$1 \cdot 1 = 1$。 

由于没有相邻对，因此不可能移动，因此配置是固定的。 

这些示例证实了零分隔段之间的独立性和游程内的局部组合结构都被正确捕获。

 总计$n$所有测试用例最多$10^5$，因此线性扫描加上预计算很容易满足限制。 该解决方案避免了任何每个状态的探索，并将所有内容减少到对输入的一次传递。

 ## 边缘情况

 一个完全空的板，例如`0000`不会产生任何段，因此乘积保持为 1。该算法自然会处理此问题，因为扫描永远不会进入`'1'`块并返回初始答案不变。 

单个长块，例如`111111`直接测试复发率。 DP 在没有分割的情况下评估完整的斐波那契式增长，结果完全取自`dp[n]`。 扫描识别一段并恰好乘以一个因子。 

高度分散的输入，例如`1010101`确保保留段之间的独立性。 每个`'1'`变成长度为 1、值为 1 的段，因此乘法使结果保持不变。 该算法正确地避免了跨零的合并，因为每个零都会立即终止运行。 

这些案例证实，完全隔离和完全连接这两个极端都是由相同的分段机制统一处理的，无需特殊的外壳。
