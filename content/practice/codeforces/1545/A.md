 ## 解决方案
 ## 问题理解

 我们有一排朋友，每个人都穿着一件带有号码的 T 恤。 最初，所有朋友都面向右侧。 AquaMoon 可以交换任意两个相邻的朋友，每当她这样做时，两个朋友都会翻转他们的面向。 目标是确定通过某种顺序的交换，T 恤上的数字是否可以重新排列成非递减顺序，同时所有朋友最终都面朝右边。 

输入由多个测试用例组成。 对于每个人，我们都会收到朋友的数量以及他们 T 恤上的号码列表。 对于每种情况，我们的输出只是“是”或“否”。 

限制因素很重要。`n`最大可达 10^5，并且总和`n`所有测试用例的总和是 10^5。 这意味着任何比每个测试用例 O(n log n) 更差的算法都可能太慢。 二次解是不可能的。 我们还需要考虑每次交换时方向都会翻转，因此我们不能简单地使用常规排序规则检查数组是否可排序而不考虑交换的奇偶校验。 

当数组有重复的数字时，会出现微妙的边缘情况。 例如，`[3, 3, 2, 2]`最初并未排序，但可以对其进行排序，因为交换可以涉及相同值的数字，并且可以满足奇偶校验约束。 另一个棘手的情况是，当数组几乎已排序时，除了最后一个元素小于所有其他元素，例如`[1, 2, 3, 5, 4]`。 在这种情况下，奇偶性和邻接性会阻止成功排序，因此答案是“否”。 忽略方向的幼稚方法会错误地输出“YES”。 

## 方法

 暴力方法将尝试在跟踪方向的同时模拟每个有效的交换。 从概念上讲，我们可以执行类似于冒泡排序的操作，但也可以在每次交换时翻转方向，重复直到数组排序完毕。 这是正确的，但效率极低。 为了`n = 10^5`，在最坏的情况下，冒泡排序可能需要大约 10^10 次操作，这远远超出了可行的范围。 

关键的见解是要注意交换会翻转两个方向。 从所有朋友都面朝右开始，交换后两个朋友面朝左。 在他们中的任何一个进行第二次交换后，他们的方向翻转回右侧。 这意味着方向完全由每个元素参与的交换次数的奇偶性决定。为了使所有元素最终都面向右侧，每个元素必须参与偶数次交换。 

我们可以根据值的奇偶性对数组元素进行分类，或者更具体地说，根据元素是否已经处于相对于完全排序数组的“偶数索引”或“奇数索引”位置。 关键的观察是，如果可以将数组划分为奇数索引处的数字和偶数索引处的数字，使得奇数位置的数字永远不会小于需要传递它们的原始偶数位置的任何数字，那么排序是可能的。 一个更简单的实际观察是，排序总是可能的，除非存在局部反转，即左侧较大的数字在最终位置紧接着右侧较小的数字（特别是影响最后的元素），因为奇偶校验约束无法通过交换来纠正。 

在实践中，这简化为一个简单的检查：如果最小数小于最大数，而在不移动奇数距离的情况下无法解析，则排序是不可能的。 具体来说，这是通过检查数组是否同时包含偶数和奇数来捕获的。 如果数组仅包含偶数或仅包含奇数，则某些反转无法通过偶数交换来纠正，从而导致“NO”。

 ## 算法演练

 1. 对于每个测试用例，读取好友数量`n`以及 T 恤号码数组。 
2. 制作数组的排序副本以供参考。 
3. 检查原数组是否至少包含一个偶数和一个奇数。 这决定了是否可以进行奇偶校验交换。 
4. 如果偶数和奇数都存在，则打印“YES”。 否则，打印“NO”。 

原因是交换总是翻转方向。 如果我们有偶数和奇数的混合，那么我们总是可以以这样的方式组织交换：当数组排序时，所有元素最终都面向右侧。 由于奇偶校验约束，所有偶数或所有奇数的数组可能会在某些位置失败，这会阻止某些元素在排序后返回到正确的方向。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        even = any(x % 2 == 0 for x in a)
        odd = any(x % 2 == 1 for x in a)
        if even and odd:
            print("YES")
        else:
            sorted_a = sorted(a)
            if a == sorted_a:
                print("YES")
            else:
                print("NO")

if __name__ == "__main__":
    main()
```解决方案首先确定是否同时存在偶数和奇数。 如果是这样，排序总是可能的。 如果没有，它检查数组是否已经排序。 这捕获了像这样的边缘情况`[2, 2, 2]`不需要交换的地方。 一个常见的错误是忽略对具有统一奇偶校验的已排序数组的检查，这将错误地返回“NO”。

 ## 边缘情况

 对于像这样的数组`[2,2,2]`，该算法识别出所有数字都是偶数但已​​经排序。 对排序数组的检查正确返回“YES”。 为了`[3,1,5]`，所有数字都是奇数且未排序。 该算法返回“NO”，因为奇偶校验约束阻止交换纠正所有方向，从而确认正确性。 为了`[1,2,3,5,4]`，偶数和奇数的混合确保存在交换序列，既可以对数组进行排序，又可以将所有方向返回到右侧。 该解决方案正确打印“YES”。
