 ## 解决方案
 ## 问题理解

 我们有几台老虎机，每台老虎机在拉动时都会产生随机奖励。 每台机器在一小部分可能的奖励值上都有自己的固定概率分布。 你可以准确地执行`n`总共拉动，并且每个拉动可以分配给任何一台机器。 不同的拉取是独立的，一台机器的分布不会随着时间的推移而改变。 

目标是决定如何分配`n`拉动机器，使预期的总奖励尽可能大。 所有拉动完成后，我们只被要求提供最大可能的期望，而不是实际的结果顺序。 

限制很小：两者`n`和`k`最多 100 个，而每个分布最多可以包含 1000 个结果。 这已经暗示，即使是机器和拉动的二次或三次解也是可以接受的，但任何涉及每次拉动分布的组合分配都是不必要的。 仔细重新计算每台机器的期望的解决方案很容易足够快。 

许多错误方法中的一个微妙的失败模式是尝试对多次拉动中总奖励的完整概率分布进行建模。 例如，人们可能会在每次拉取后尝试对可能的总和进行动态编程。 这是不必要的，因为问题只要求期望，而不要求方差或分布形状。 另一个常见的错误是假设我们需要以巧妙的模式在机器之间交错拉动。 实际上，每次拉动都是独立的，并且在预期中做出附加贡献，因此排序没有效果。 

作为错误方向的具体示例，假设两台机器具有相同的预期值但不同的价差。 即使期望不依赖于方差，分布跟踪解决方案也可能错误地尝试选择“更安全”的机器。 正确答案仅取决于平均回报，而不取决于风险。 

## 方法

 对这个问题的一个天真的解释是我们必须分配`n`离散动作（拉动），每个动作选择其中之一`k`机器，每个动作都有一个随机结果。 人们可以想象一种暴力解决方案，枚举所有可能的分配`n`跨机器进行拉动并评估每项任务的预期价值。 

对于每个任务，如果我们正确地模拟期望，我们仍然需要从分布中计算每次拉动的预期奖励。 即使每台机器的期望是预先计算的，分配的数量也是`k^n`，因为每个`n`拉动可以独立选择其中之一`k`机器。 和`n = 100`，这变得天文数字般巨大并且完全不可行。 

关键的观察结果是期望是线性的。 多次独立拉动的预期总奖励只是每次拉动的预期奖励之和，而不考虑机器选择之间的依赖关系。 这意味着每个拉动仅根据其使用的机器进行独立贡献。 拉动之间不存在任何相互作用，无法使混合策略比反复选择最佳机器更好。 

一旦我们接受线性，结构就会崩溃：每台机器每次拉动都有固定的预期奖励，并且每次拉动都应该流向具有最大期望的机器。 不需要更复杂的分配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配拉| O(k^n) | O(k^n) | O(n) | 太慢了|
 | 计算期望并选择最大值 | O(k * m_i) | O(k * m_i) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每台机器的概率分布转换为一个数字，即每次拉动的预期奖励，然后选择最好的机器。 

1. 对于每台机器，阅读其可能奖励和相应概率的列表。 

这台机器的单次拉动的预期值是结果的加权和。 
2. 计算期望`E_i = sum(r_j * p_j)`对于每台机器`i`。 

这将整个分布折叠成一个代表长期平均收益的标量。 
3. 跟踪所有机器中的最大期望值。 
4. 将此最大期望乘以`n`，因为所有`n`拉力应分配给最好的机器。 

最终的答案是`n * max(E_i)`。 

### 为什么它有效

 每次拉动都会贡献一个独立的随机变量，其期望仅取决于所选机器。 总预期奖励是个人拉动的期望之和。 因为期望是相加的，所以重新安排机器之间的拉力不会产生任何交叉项或协同作用。 任何使用具有较小期望的机器的分配都可以通过将拉动转移到具有较大期望的机器来改进，严格增加总期望。 这意味着最佳解决方案始终将每次拉动分配给具有最大期望值的单台机器。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    best = 0.0
    
    for _ in range(k):
        m = int(input())
        rewards = list(map(int, input().split()))
        probs = list(map(float, input().split()))
        
        exp = 0.0
        for r, p in zip(rewards, probs):
            exp += r * p
        
        if exp > best:
            best = exp
    
    print(n * best)

if __name__ == "__main__":
    solve()
```实现直接遵循期望最大化的减少。 每台机器都是独立处理的，其期望值被计算为奖励和概率之间的点积。 唯一维持的全局状态是迄今为止看到的最大期望。 

一个常见的陷阱是尝试使用动态编程在多台机器上分配拉力。 这是不必要的，因为拉力之间不存在收益递减或依赖性。 

浮点精度就足够了，因为值是有界的，并且所需的精度是`1e-6`。 标准双精度可轻松处理每台机器最多 1000 个术语的累积。 

## 工作示例

 考虑一个具有两台机器和三个总拉力的小型实例。 

机器 1 以 0.5 的概率给出奖励 10，以 0.5 的概率给出奖励 0。 它的期望是5.0。 

机器 2 以 1.0 的概率给出奖励 3。 它的期望是3.0。 

| 机器| 预期值|
 | --- | --- |
 | 1 | 5.0 |
 | 2 | 3.0 |

 | 步骤| 迄今为止最好的 |
 | --- | --- |
 | 机器1后| 5.0 |
 | 机器2后| 5.0 |

 结果是`3 * 5.0 = 15.0`。 

现在考虑一种情况，机器有很多结果但平均值较低。 假设机器 A 有结果`[0, 100]`有概率`[0.99, 0.01]`，机器 B 总是返回 1。机器 A 的期望为 1.0，机器 B 的期望也为 1.0。 任何分配都会产生相同的预期值，因此将所有拉取分配给任一机器是最佳的。 

这证实了方差并不重要，只有平均值驱动解决方案。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k·m_i) | O(k·m_i) | 每台机器的期望都是通过对其分布进行单次计算来计算的 |
 | 空间| O(1) | O(1) | 仅存储少数标量超出输入缓冲 |

 这些约束允许最多 100 台机器，每台机器最多有 1000 个结果，因此最多执行 100,000 次乘法。 这很容易在限制范围内，并且除了输入存储之外，内存使用量是恒定的。

 ## 边缘情况

 一个关键的边缘情况是多台机器具有完全相同的期望值。 在这种情况下，它们之间的任何拉力分配都是最优的。 该算法自然地处理这个问题，因为它只跟踪最大期望，而不依赖于哪台机器实现它。 

另一种情况是所有机器的期望值为零。 即使这样，计算出的期望仍然为零，并乘以`n`保留正确性。 不需要特殊处理，因为最大值保持为零。 

最后一个微妙的情况是当概率非常小时或值接近上限时的数值精度。 由于所有奖励都以 100 为界，并且每台机器最多有 1000 个术语，因此累积浮点误差远低于要求的值`1e-6`宽容。
