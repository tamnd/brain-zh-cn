 ## 解决方案
 ## 问题理解

 我们得到了多个测试用例。 每个测试用例由一排站成一排的人组成，其中每个人属于两个组之一，编码为`U`或者`D`。 任务是选择该行的一个连续段，使得该段内的数量`U`字符数正好等于`D`字符，并且在所有此类有效段中，我们希望获得最大可能的长度。 

对于每个测试用例，我们仅输出一个数字，即最长平衡段的长度。 如果没有非空段可以满足条件，则答案为零。 

这些约束意味着我们可能会看到多达一万个测试用例，但所有字符串的总长度仅限于二十万。 这迫使任何解决方案平均在每个测试用例的线性时间内运行，因为当所有测试用例都很大时，每个字符串上的任何二次方都会立即超出时间限制。 

检查每个子数组的简单方法将检查每个测试用例的大约 n 个平方段。 总共n达到二十万，这是远远不可能的。 

当所有角色都属于一个组时，就会出现一个微妙的问题。 例如，`UUUUU`或者`DDDDD`。 在这些情况下，不存在正长度的有效段，因此答案必须为零。 任何假设至少存在一对有效值的方法都会错误地返回非零值。 

另一个极端情况是最佳片段跨越整个字符串。 例如`UDUD`是完全平衡的，正确答案是全长。 仅跟踪本地匹配或过于激进地重置的解决方案将错过此全局结构。 

## 方法

 暴力策略尝试每一个可能的起始索引并扩展到每个结束索引，计算有多少个`U`和`D`每个片段中都会出现字符。 每当计数匹配时，我们就会更新最佳答案。 这是正确的，因为它明确地检查每个可能的段。 

然而，如果重新计算，维护每对的计数仍然会花费每个段的线性时间，或者如果增量维护，则花费恒定时间。 即使在最好的实现中，我们仍然检查每个测试用例的 O(n^2) 段。 总输入大小高达 200,000，这在最坏的情况下会导致约 200 亿次操作，这是不可行的。 

关键的观察是我们实际上并不关心确切的数量`U`和`D`分别地。 我们只关心他们的差异。 如果我们解释`U`作为+1和`D`如果为 -1，则当段的总和为零时，该段恰好达到平衡。 

这将问题转化为寻找总和为零的最长子数组。 使用前缀和，这相当于在位置 i 和 j 处找到两个相等的前缀和。 如果 prefix[i] 等于 prefix[j]，则子数组（i+1 到 j）是平衡的。 

优化来自于我们只需要记住每个前缀和最早出现的时间。 当我们再次看到相同的前缀和时，出现次数之间的距离给出了有效的平衡段，我们通过保留第一次出现来最大化它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 太慢了|
 | 前缀和哈​​希 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 将字符串转换为动态平衡，其中`U`贡献+1并且`D`贡献-1。 我们跟踪代表每个位置的余额的前缀总和。 这使我们能够检测到相等`U`和`D`通过检查总和是否返回到之前的值。 
2. 初始化一个字典，存储每个前缀和值最早出现的索引。 在处理开始之前，我们还将前缀和 0 存储在索引 -1 处。 这会正确处理从索引 0 开始的段，因为从头开始的平衡前缀将匹配此基本状态。 
3. 迭代字符串，同时更新前缀和。 在每个位置，我们检查这个前缀和以前是否见过。 
4. 如果已经看到前缀和，则前一个索引和当前索引之间的子数组是平衡的。 我们计算它的长度并更新最大答案。 
5. 如果没有看到前缀和，我们将其索引记录为第一次出现。 我们永远不会覆盖较早的出现，因为较早的索引在稍后匹配时会产生更长的有效段。 
6. 处理完整个字符串后，输出找到的最大长度。 

### 为什么它有效

 位置 i 处的前缀和编码了计数之间的差异`U`和`D`到那时为止。 具有相同前缀和的两个位置意味着它们之间的净贡献为零，这意味着相同数量的`U`和`D`。 存储最早出现的事件可确保同一余额的每次重复都会产生在该位置结束的最长可能段。 不会丢失任何平衡段，因为每个有效段都对应于某对相等的前缀和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        first_pos = {0: -1}
        pref = 0
        best = 0
        
        for i, ch in enumerate(s):
            if ch == 'U':
                pref += 1
            else:
                pref -= 1
            
            if pref in first_pos:
                best = max(best, i - first_pos[pref])
            else:
                first_pos[pref] = i
        
        out.append(str(best))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```核心结构围绕着从左到右扫描时保持前缀平衡。 字典`first_pos`存储每个余额出现的最早索引。 初始化与`{0: -1}`很重要，因为它允许以索引结尾的前缀`i`净余额为零，可以正确生成一段长度`i + 1`。 

更新规则为`pref`将字符流转换为数字信号，这是简化问题的核心转换。 

这`best`变量跟踪重复前缀和之间的最大距离，它直接对应于最长的有效段。 

## 工作示例

 考虑一个简单的情况：

 输入字符串：`UUDD`我们跟踪前缀总和和首次出现的情况。 

| 我| 字符| 前缀 | 首次出现地图更新 | 最好的|
 | --- | --- | --- | --- | --- |
 | -1 | - | 0 | {0:-1} | 0 |
 | 0 | 你| 1 | {0:-1, 1:0} | 0 |
 | 1 | 你| 2 | {0:-1, 1:0, 2:1} | 0 |
 | 2 | d | 1 | 0 处的匹配给出长度 2 | 2 |
 | 3 | d | 0 | -1 处的匹配给出长度 4 | 4 |

 最终答案是4，说明整个字符串是平衡的。 

现在考虑`UDUUDD`。 

| 我| 字符| 前缀 | 第一次出现 | 最好的|
 | --- | --- | --- | --- | --- |
 | 0 | 你| 1 | 1:0 | 0 |
 | 1 | d | 0 | 0:-1 存在，更新 best=2 | 2 |
 | 2 | 你| 1 | 在 0 处看到得到 2 | 2 |
 | 3 | 你| 2 | 2:3 | 2 |

 这说明了重复的前缀值如何解锁多个有效段，以及为什么保留最早的位置对于最大化长度至关重要。

 | 测量| 复杂性 | 说明|

 | 时间 | O(n) | 每个字符处理一次，字典操作平均O(1) |
 | 空间| O(n) | 在最坏的情况下，所有前缀和都是不同的 |

 测试用例的总输入大小是有限的，因此每个测试用例的线性扫描足以保持在限制范围内。 哈希结构仅存储每个测试用例最多 n 个不同的前缀状态，可以轻松满足内存限制。

 ## 边缘情况

 当字符串仅包含一种字符类型时，每个前缀和都是严格单调的并且从不重复。 该算法仍然用以下方式初始化字典`{0: -1}`，但未来的前缀不会再次等于零，所以`best`始终保持为零。 这可以正确处理输入，例如`DDDDD`，其中不存在有效段。 

当整个弦平衡时，例如`UDUD`，前缀和在最后一个索引处返回为零。 由于最初将零存储在索引 -1 处，因此计算出的段跨越整个数组。 该算法自然地捕获了这一点，无需特殊的外壳。 

当平衡段存在但没有前缀对齐时，例如`UUDUD`，重复的前缀和出现在扫描中间。 每次重复都正确地形成一个候选段，并且最早存储的索引保证了该前缀值的最大扩展，确保找到最长的段，即使它在字符串的中间开始和结束。
