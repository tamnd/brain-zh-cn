 ## 解决方案
 ## 问题理解

 对于每个测试用例，我们都会得到一个小的整数数组。 我们可以从这个数组中选择任何元素子集，但明确禁止我们选择完整的数组。 该子集甚至可以为空。 

对于任何选定的子集$S$，我们计算一个组合了三个部分的值：子集的大小、取决于大小是偶数还是奇数的符号，以及所选元素的立方和。 具体来说，每个子集贡献的值等于其大小乘以$(-1)^{|S|}$乘以总和$x^3$覆盖子集中的所有元素。 

任务是在所有有效子集中找到该表达式的最小和最大可能值。 

关键的结构细节是数组长度最多为 15。这立即将视角从“组合数学优化”转变为“枚举所有内容”，因为子集总数最多为$2^{15} = 32768$。 即使有多达 1000 个测试用例，对子集的全面扫描仍然在限制范围内。 

一个微妙的边缘条件是空子集的作用。 对于空集，大小和总和都为零，因此该值完全为零。 另一个微妙之处是对选择全套的限制。 这意味着一个子集必须排除在考虑之外，即使它本来是完整枚举的一部分。 

表达式本身的表现也可能不直观，因为符号取决于子集大小的奇偶性，而幅度与大小成线性比例，也与立方和成线性比例。 这意味着子集组成的微小变化可以翻转符号并以非单调方式放大或缩小结果，从而排除了贪婪推理。 

## 方法

 一种直接的方法是迭代数组的每个子集。 对于每个子集，我们计算其大小及其元素的立方和，然后计算表达式。 我们跟踪所有有效子集的最小值和最大值。 

这是正确的，因为每个可能的元素选择都被明确考虑。 这种方法的成本完全来自枚举子集。 和$N = 15$，每个测试用例有 32768 个子集。 对于每个子集，我们最多可以扫描 15 个元素，在最坏的情况下，每个测试用例大约执行 500k 次操作。 对于多达 1000 个测试用例，如果在开销很大的紧密循环中天真地实现，这会变得太大，但在优化的 Python 中，它仍然是可以接受的。 更仔细的实现可以通过预先计算立方体值和使用位运算来避免重复工作。 

关键的观察是不需要更深的结构。 与子集交互或需要在连续域上进行优化的问题不同，这里的约束保证暴力枚举是预期的解决方案。 唯一需要的优化是将子集表示为位掩码和预计算$A_i^3$。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 预先计算每个数组元素的立方，这样我们就不会在子集求值时重复计算幂。 这减少了内循环内的重复算术。 
2.迭代从0到的所有位掩码$2^N - 1$。 每个位掩码代表一个子集，其中$i$-th 位表示元素是否$A_i$包括在内。 
3. 跳过与完整集合相对应的位掩码，因为该问题不允许选择所有元素。 
4. 对于每个剩余的位掩码，计算两个量：所选元素的数量以及这些所选元素的立方之和。 这是通过扫描位并累加计数和总和来完成的。 
5. 使用计算值评估表达式。 如果子集大小为零，则根据公式的定义，贡献为零。 
6. 维护所有评估子集的全局最小值和最大值。 
7.处理完所有子集后，输出最小值和最大值。 

这是正确结构的原因是每个子集都是独立的。 不存在将一个子集选择与另一个子集选择联系起来的约束，因此搜索空间完全可分为对减去一个元素的幂集的独立评估。 

### 为什么它有效

 除全集掩码外，每个有效子集恰好对应于一个位掩码，并且每个位掩码仅被评估一次。 由于每个掩码的计算与所需函数的定义完全匹配，因此该算法对解空间执行完整的枚举，没有遗漏或重复。 因此，在整个可行域中采用最小值和最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N = int(input())
        A = list(map(int, input().split()))
        
        cube = [x * x * x for x in A]
        
        full_mask = (1 << N) - 1
        
        INF = 10**30
        mn, mx = INF, -INF
        
        for mask in range(1 << N):
            if mask == full_mask:
                continue
            
            cnt = 0
            s = 0
            
            m = mask
            i = 0
            while m:
                if m & 1:
                    cnt += 1
                    s += cube[i]
                m >>= 1
                i += 1
            
            if cnt == 0:
                val = 0
            else:
                sign = -1 if cnt % 2 else 1
                val = cnt * sign * s
            
            if val < mn:
                mn = val
            if val > mx:
                mx = val
        
        print(mn, mx)

if __name__ == "__main__":
    solve()
```核心实现细节是位掩码循环。 每个掩码编码一个子集，并且我们显式地跳过完整掩码。 内部循环对位进行一位一位解码，同时维护立方体的计数和总和。 然后精确地按照指定计算表达式。 

一个常见的错误是忘记空子集是有效的并且必须予以考虑。 另一个是当子集大小为零时错误处理符号，但在这种情况下实现自然会产生零。 预计算立方体可避免子集循环内的重复求幂，这对于 1000 个测试用例的性能非常重要。

 ## 边缘情况

 空子集是最微妙的情况，因为即使表达式的两个分量都为零，它也会产生有效值。 该算法自然地将其包含在掩码 0 中，并且由于它与完整的掩码不匹配，因此它被正确地评估为 0。 

通过跳过掩码来显式处理全集排除$2^N - 1$。 如果没有这一条件，解决方案将错误地包含一个额外的候选者，该候选者可能会根据输入分布主导最大值或最小值。 

当所有元素都为零时，会出现另一种边缘行为。 然后，无论大小或符号如何，每个子集都计算为零，并且算法正确地为最小值和最大值返回零，因为所有计算值都崩溃为相同的常数。
