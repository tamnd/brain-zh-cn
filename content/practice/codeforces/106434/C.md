 ## 解决方案
 ## 问题理解

 我们得到了一张由双向道路连接的城市图。 每条路的成本正好是一步，但它也带有二元属性。 有些道路是正常的，而另一些则是昂贵的“桥梁”。 关键的限制是，从起始城市到博物馆城市时，我们总共最多只能穿过一条桥边。 

一部分城市设有博物馆。 对于每个城市，我们都想知道在沿途不能使用超过一座桥梁的限制下，到达任何博物馆的最短旅行距离（以边数来衡量）。 如果不存在这样的路径，则答案为-1。 

图尺寸很大，具有多达 200000 个节点和边，因此任何解决方案都必须接近线性或线性算数。 每个节点的直接最短路径搜索需要 O(nm) 或 O(nm log n) 之类的东西，这太大了。 即使是单个多状态 BFS，只有在避免重新计算的情况下才是可接受的。 

一个微妙的方面是，约束是每条路径的全局约束，而不是每条边或每条查询：一旦我们使用桥，我们就不能在同一路线的任何地方使用另一个桥。 这将标准的最短路径问题转变为分层状态问题。 

一些边缘情况很重要：

 如果一座城市本身就是一座博物馆，那么无论边缘如何，答案都是零。 例如，如果 n = 3 并且城市 2 是博物馆，则答案[2] = 0。 

如果一个城市仅通过两座或多座桥梁就可以到达博物馆，那么即使原始最短路径很小，也必须拒绝它。 例如，长度为 2 但使用两个网桥的路径是无效的。 

如果即使忽略约束也根本不存在路径，则答案为-1。 

## 方法

 一种简单的方法是使用 BFS 或 Dijkstra 计算从每个城市到任何博物馆的最短路径，并在遍历过程中跟踪使用了多少座桥梁。 每个状态都是 (node,used_bridge_count)，其中used_bridge_count 为 0 或 1。 

这已经提出了一个正确的公式：我们正在有效地在具有 2n 个节点的状态扩展图中进行搜索。 从每个状态，我们遍历所有相邻边，如果需要则增加桥计数，并拒绝超过 1 的转换。从每个源运行 BFS 的成本太高，因为它会重复相同的搜索结构 n 次。 

关键的观察是我们可以扭转思维的方向。 我们可以同时从所有博物馆开始，而不是从每个城市开始。 我们希望从任何节点到最近的有效博物馆路径的最小距离，因此多源 BFS 是自然的。 

然而，由于“至多一座桥”的限制，普通的 BFS 是不够的。 我们必须跟踪我们是否已经使用过一座桥。 这导致了分层 BFS，其中每个节点出现在两层中：一层是迄今为止我们使用零桥的层，另一层是我们使用单桥的层。 

然后，我们从两个州的所有博物馆运行一个 BFS。 每次我们遍历正常的边时，我们都会保持相同的状态。 每次我们遍历桥边时，我们只能从状态 0 移动到状态 1。状态 1 不能遍历更多的桥。 

因为 BFS 按距离递增的顺序处理节点，所以我们第一次达到某个状态时，它是最优的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 具有状态跟踪功能的每节点 BFS | O(n(m+n)) | O(n(m+n)) | O(n) | 太慢了|
 | 扩展状态上的多源 BFS | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们用两种状态对每个城市进行建模：状态 0 表示我们尚未使用桥梁，状态 1 表示我们已经使用过一座桥梁。 

我们从两个州的所有博物馆城市开始运行 BFS，距离为 0，因为在博物馆已经满足了目标。

我们在（节点，状态）上维护一个距离数组。 我们还维护一个要处理的状态队列。 

1. 将两种状态的所有距离初始化为无穷大。 
2. 对于每个博物馆城市 s，设置 dist[s][0] = 0 和 dist[s][1] = 0，并将这两个状态推入 BFS 队列。 这反映出我们已经处于有效端点并且可以开始向外传播。 
3. 当队列不为空时，pop(u,state)。 这表示使用给定数量的桥梁到达 u 的最短已知路径。 
4. 对于每条边 (u, v, t)，考虑过渡：

 如果 t = 0（正常道路），我们以成本 +1 移动到 (v, state)。 

如果 t = 1（桥），我们只能在状态 = 0 时进行转换。在这种情况下，我们以成本 +1 移动到 (v, 1)。 

任何无效的转换都会被忽略，因为它违反了至多一个桥的约束。 
5. 如果我们改进 dist[v][new_state]，则更新它并将新状态推入队列。 
6. BFS完成后，对于每个节点i，答案为min(dist[i][0], dist[i][1])。 如果两者都是无穷大，则输出−1。 

它之所以有效，是因为 BFS 运行在一个扩展图上，其顶点为 (city,used_bridge_count)。 原始图中的每条有效路径恰好对应于该扩展图中的一条路径，反之亦然，并且所有边都具有单位权重。 因此，BFS 保证了该状态图中的最短距离，并且最小化两个状态给出了最佳有效路线。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**18

def solve():
    n, m, k = map(int, input().split())
    museums = list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, t = map(int, input().split())
        g[u].append((v, t))
        g[v].append((u, t))

    dist = [[INF] * 2 for _ in range(n + 1)]
    q = deque()

    for s in museums:
        dist[s][0] = 0
        dist[s][1] = 0
        q.append((s, 0))
        q.append((s, 1))

    while q:
        u, state = q.popleft()
        d = dist[u][state]

        for v, t in g[u]:
            if t == 0:
                ns = state
            else:
                if state == 1:
                    continue
                ns = 1

            if dist[v][ns] > d + 1:
                dist[v][ns] = d + 1
                q.append((v, ns))

    out = []
    for i in range(1, n + 1):
        ans = min(dist[i][0], dist[i][1])
        out.append(str(-1 if ans == INF else ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码构建了一个保留边类型的图。 距离表每个节点有两列，对应于是否使用了网桥。 BFS 从所有博物馆状态开始，这确保我们计算到最近博物馆的距离，而不是从单一来源计算。 

一个关键的实现细节是将每个博物馆的两个状态初始化为零。 这允许一致地通过“尚未使用桥”或“已使用桥”状态进行传播，从而避免在反向推理中立即采用桥时对起始条件进行特殊处理。 

转换逻辑通过阻止任何来自状态 1 的桥遍历来小心地强制执行约束。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 每个状态（节点，bridge_used）在 BFS 中处理一次，并且每条边被松弛固定次数 |

 这些约束允许最多 200000 个节点和边，因此扩展状态图上的线性遍历很容易满足时间和内存限制。

 ## 边缘情况

 一个关键的边缘情况是，一座城市是一座博物馆，并且有一条直接向外的桥梁。 例如，如果博物馆节点仅通过桥链连接，我们仍然以零距离初始化两个状态。 BFS 将正确向外扩展，但在任何路径上都不允许有超过一座桥梁，因此距离仍然有效。 

另一种情况是同一节点之间有多个平行边，一个法线和一个桥。 该算法自然地处理这个问题，因为两条边都是独立处理的，并且正常边在可用时总是提供更便宜或相等的状态转换。 

最后一个微妙的情况是，最佳路径使用的桥不紧邻起点，而是位于中间的某个位置。 基于状态的 BFS 确保自然捕获这一点，因为消耗桥的决定被推迟，直到该边实际以最短扩展顺序遍历为止。
