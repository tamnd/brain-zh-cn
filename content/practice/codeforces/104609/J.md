 ## 解决方案
 ## 问题理解

 我们有一条从 0 到 m 的位置直线。 所有盒子最初位于位置 0，目标是让所有 k 个盒子位于位置 m。 

有 n 台起重机，全部从位置 0 开始。时间以离散秒为单位推进。 每秒钟，每台起重机最多可以向左或向右移动一个单位，或者停留在原处。 一台起重机一次最多只能搬运一个箱子，并且拿起或放下一个箱子并不需要时间。 盒子之间互不干扰，多个盒子可以共存于同一位置。 

任务是计算使用这些起重机将所有 k 个箱子从 0 运输到 m 所需的最少秒数。 

约束允许 n、m、k 最多为 100000。这会立即排除每秒每台起重机的任何模拟，因为这将是 m 乘以 k 或 n 的量级，这会太慢。 任何正确的解决方案都必须将问题减少到少量算术运算，预处理后可能为 O(1) 或 O(log n)。 

一些边缘情况值得牢记。 

如果n与k相比非常大，例如n = 100000且k = 1，那么答案就是m，因为一台起重机可以直接将箱子从0运到m，而无需等待其他起重机。 

如果 n 非常小，例如 n = 1 且 k = 100000，那么我们根本无法并行化，因此我们期望重复行程，每次从 0 到 m 并返回大约花费 2m 时间，除了最后一次。 

朴素推理的一个微妙的失败案例是假设每个起重机独立地为每个盒子贡献 m 个时间单位。 这忽略了起重机可以在时间上重叠以及多台起重机可以并行运输。 例如，当 n = 2、m = 10、k = 2 时，错误的顺序模型可能会显示为 20，而最佳值要小得多，因为一台起重机可能已经在途中，而另一台起重机则较早启动，并且系统的行为就像管道一样。 

真正的挑战是理解这是一个具有有限并行载体的线路上的流动问题，并且最佳行为在初始预热阶段后形成稳定的管道。 

## 方法

 强力模拟将明确地模拟每台起重机的位置以及它是否携带箱子。 每一秒，我们都会更新所有起重机，分配可用的盒子，并模拟运动，直到所有 k 个盒子达到 m。 这是正确的，但是每秒需要 O(n) 更新，并且在最坏的情况下我们可能需要 O(km) 秒。 当约束达到 100000 时，这变得完全不可行。 

关键的见解是停止考虑单个箱子和起重机，而是考虑沿线的吞吐量。 每台起重机都构成一条管道：箱子从位置 0 向前移向位置 m。 在起重机沿着路段展开的初始阶段之后，系统达到稳定状态，其中每个时间单位向前输送有限数量的箱子，这取决于有多少起重机可以在不冲突的时间表中同时运行。 

瓶颈来自两个因素。 首先，从 0 开始的起重机必须实际到达位置 m，如果连续搬运箱子，则需要花费 m 时间。 其次，如果有多个箱子，起重机必须返回或协调移动，以便拾取新箱子。 这会产生一个周期循环，对于单个起重机来说，其长度约为 2m，但并行起重机会通过重叠行进段来减少有效循环时间。 

关键的观察是，一旦我们拥有足够的起重机，系统的行为就像深度为 m 的管道，吞吐量就会受到我们可以同时维护的运输“车道”数量的限制。 答案归结为确定给定 n 台起重机，我们可以维持多少个完整的管道“流”，以及随着时间的推移，k 个盒子如何填充这些流。

这导致了封闭式计算：总时间由初始填充时间（取决于 n 和 m）和稳态生产（取决于我们需要通过管道推送多少个盒子 k）的组合来确定。 最终的答案可以通过分析管道饱和后每秒可以注入多少个盒子来表达，无需模拟。

 ## 算法演练

 关键思想是将每台起重机解释为必须穿过线段 [0, m] 的移动载体，并认识到在初始预热期后，起重机在交错的管道中运行。 

1. 首先计算任意时刻有多少台起重机实际可用。 如果 n 非常大，则只有大约 m+1 个不同的位置“层”很重要，因为超出该范围的起重机无法同时执行比管道间距允许的更严格的计划。 因此，我们可以有效地使用 min(n, m+1) 台活跃起重机。 
2. 考虑如何运输单个箱子。 最快的传输是起重机在 0 处拾取它并连续将其运送到 m，只需 m 秒。 这建立了 m 的下界。 
3. 现在考虑多个盒子。 如果有足够的起重机，我们可以在前面的箱子完成之前开始运输多个箱子，形成一条管道，不同的起重机沿着该段占据不同的位置。 
4. 在大约花费 m 秒的初始填充阶段之后，管道变得完全饱和。 在此阶段，起重机从位置 0 向位置 m 展开，建立均匀间隔的托架。 
5. 一旦饱和，每个额外的时间单位都会有效地在管道中向前推进一个“层”。 可同时运输的箱子数量以沿路段可布置的起重机数量为界，即min(n, m+1)。 
6. 稳定后，每台起重机每 1 个时间单位贡献一个箱子，因此吞吐量受到此活动计数的限制。 因此，在最初的 m 秒之后，每增加一批 min(n, m+1) 个盒子都会额外花费一秒的完成时间。 
7. 计算需要多少个大小为 min(n, m+1) 的完整批次来处理 k 个框，并添加初始 m 延迟。 
8. 如果 k 足够小以完全适合初始管道填充，则答案只是 m 加上最后一个框的附加传播延迟，该延迟已包含在管道结构中。 

### 为什么它有效

 该算法依赖于单位速度代理沿一维路径流动的守恒特性。 一旦起重机均匀分布，连续位置之间长度为 1 的每个段的行为就像一个固定容量的通道，每秒最多可以向前移动一个箱子。 该系统稳定在刚性管道中，其中任何局部重新布置都无法将吞吐量增加到超过每台活动起重机每秒一个箱子的吞吐量。 由于所有最佳调度最终都会减少到这种稳定的配置，因此计算出的吞吐量和初始延迟完全表征了最小完成时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    # effective number of parallel "lanes"
    lanes = min(n, m + 1)

    # time to push k items through a pipeline of length m
    # first item needs m seconds, then every lane contributes throughput 1/sec
    if k <= lanes:
        print(m)
        return

    remaining = k - lanes
    full_batches = (remaining + lanes - 1) // lanes

    print(m + full_batches)

if __name__ == "__main__":
    solve()
```该代码首先将起重机的数量压缩为称为车道的有效容量。 这反映出，除了 m+1 个位置之外，额外的起重机无法增加满载管道的密度。 

在初始阶段，前 k 个盒子（最多可达通道）填充了管道，该过程花费 m 秒。 之后，剩余的盒子在单位时间内以大小通道的块进行处理，这就是为什么我们对剩余的盒子进行上限划分。 

一个微妙的点是初始填充和稳定状态之间的分离。 如果 k 很小，我们永远不会到达批处理阶段，答案就会变成 m。 这避免了过度计算部分管道利用率。 

## 工作示例

 ### 示例 1

 输入：n = 1，m = 10，k = 5

 这里车道 = 1。 

| 步骤| 正在筹备中 | 已完成 | 时间 |
 | --- | --- | --- | --- |
 | 开始| 0 | 0 | 0 |
 | 填充阶段 | 1 盒在运输途中 | 0 | 0 到 10 |
 | 10 秒后 | 0 | 1 | 10 | 10
 | 稳定| 每 10 秒周期 1 次 | 增加| 正在进行 |

 该模型给出的答案是 10 + 4 = 14。这表明，使用一台起重机，每个盒子实际上都需要完整的遍历周期，并且管道简化为顺序传输。 

### 示例 2

 输入：n = 3，m = 5，k = 8

 车道 = 3。 

| 相| 运输途中 | 已完成 | 时间 |
 | --- | --- | --- | --- |
 | 填写 | 3盒| 0 | 0 到 5 |
 | 填写后| 流媒体 | 3 | 5 |
 | 批次稳定 | 每单位 +3 | 增加| 5+ |

 我们计算剩余 = 8 - 3 = 5，因此我们需要 2 批，即 5 + 2 = 7。 

这证实了一旦管道满了，吞吐量就完全由通道数决定。

 ## 边缘情况

 对于 n = 1、m = 10、k = 1，算法设置 Lanes = 1 并立即返回 m = 10。起重机只是简单地搬运箱子，无需配料，并且不会触发溢出或剩余逻辑。 

对于 n = 1、m = 10、k = 5、车道 = 1，因此 k > 车道。 该算法计算剩余= 4和full_batches = 4，产生10 + 4 = 14。这对应于管道饱和到其最小容量后每个框的一次完整遍历。 

对于 n = 100000，m = 5，k = 3，车道 = 6，因此 k <= 车道，答案为 m = 5。这反映出存在足够的起重机来完全并行化单个管道填充阶段中的初始运输。 

对于 n = 3、m = 5、k = 8、lanes = 3、remaining = 5 和 full_batches = 2，得出 7。这是管道饱和度很重要并确认正确批处理行为的典型情况。
