 ## 解决方案
 ## 问题理解

 我们得到一个排列成圆圈的序列，这意味着索引 1 与索引 N 相邻。每个位置都带有一个值，我们希望选择一个索引子集，使所选值的总和最大化。 

限制是几何的：如果我们选择两个索引，它们在圆上必须相距很远。 任意两个选定索引之间的圆形距离必须至少为 D + 1，这意味着沿着圆向任一方向行走，必须经过至少 D 个其他位置才能到达另一个选定索引。 

因此，该任务是循环图上的加权独立集问题，其中每个顶点不仅连接到直接邻居，而且还连接到两个方向上的下一个 D 顶点。 

输入大小 N 可以高达 100000，这会立即排除所有对上的任何指数子集枚举或二次 DP。 像 O(N^2) 这样的东西都会太慢，因为 10^10 次操作远远超出了限制。 该结构表明每个索引仅与大小约为 2D 的局部邻域交互，因此解决方案必须利用局部性或滑动结构。 

当 D 较小或较大时，会出现微妙的边缘情况。 当 D = 0 时，没有限制，我们取所有元素。 当 D 为 N − 1 时，我们最多可以选择一个元素，因此答案就是数组中的最大元素。 另一个重要的情况是当值是负值或混合值时，但由于语句中的值总是正值，因此决定纯粹是关于间距，而不是符号权衡。 

一种简单的方法可能会尝试考虑每个元素并递归地决定是接受它还是跳过其禁止的邻域。 这很快就会导致子问题重叠和指数分支。 

## 方法

 直接强力方法将考虑索引的所有子集并验证每个子集是否满足间距约束。 对于每个子集，我们将对所选索引进行排序并检查连续所选元素之间的圆形距离。 即使检查的时间复杂度为 O(N)，也有 2^N 个子集，即使对于 N = 40，这也是完全不可行的。 

稍微结构化一点的暴力是对位掩码的动态编程，其中每个状态代表已经选择的索引。 随着 2^N 状态的增加，它仍然会增长，并且转换需要检查距离 D 内的冲突，从而导致至少 O(N 2^N) 操作。 

关键的观察结果是，约束在循环顺序中纯粹是局部的。 如果我们决定在位置 i 处选择一个元素，那么下一个选择的元素必须位于从 i + D + 1 开始并向前延伸的线段中。 这将问题转化为选择一系列索引，这些索引沿着具有最小间隙约束的圆严格增加。 

然而，圆形结构阻止了直接线性 DP，因为第一个和最后一个元素相互作用。 处理这个问题的标准方法是打破循环：要么我们不选择位置 1，要么我们将位置 1 固定为所选位置并禁止环绕冲突。 在这两种情况下，问题都变成了线性“没有两个选定元素位于距离 D 内”优化。 

线性化后，我们可以将 DP[i] 定义为考虑到 i 之前的位置的最佳总和。 在每个 i 处，我们要么跳过它，要么跳回 i − (D + 1)。 这会产生一个干净的循环，类似于具有固定长度冲突的加权间隔调度。 

效率来自于每个状态仅依赖于单个先前状态的事实，因此我们完全避免了成对比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^N·N) | O(2^N·N) | O(N) | 太慢了 |
 | 最佳DP | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们将循环依赖关系转换为线性情况，然后运行遵守最小间距约束的标准 DP。

1. 将问题分为两种情况：一种是我们不选择索引 0，另一种是我们将圆在索引 0 处视为破损并仔细处理环绕。 这是必要的，因为否则根据圆形距离规则，靠近末尾的所选元素可能会与靠近开头的元素发生冲突。 
2. 对于固定线性排列，将 dp[i] 定义为我们可以使用从 0 到 i 的索引获得的最大总和，前提是所选索引至少相差 D + 1。 
3. 在位置 i，我们有两种可能性。 如果我们不取 A[i]，则 dp[i] = dp[i − 1]。 如果我们取 A[i]，那么之前的有效选择最多只能是 i − D − 1，因此该值变为 A[i] + dp[i − D − 1]。 
4. 当 i − D − 1 为负数时，我们将 dp 索引视为 0，这意味着我们可以不受任何先前限制地取 A[i]。 
5. 从左到右迭代计算 dp，存储每个前缀处可达到的最佳总和。 
6. 对于循环处理，请确保如果我们考虑采用索引 0 的情况，则不允许以违反环绕距离的方式采用最后 D 位置中的索引。 这是通过排除无效配置或通过移动起始位置并重新计算线性化数组上的 DP 来处理的。 

### 为什么它有效

 DP 保持了以下不变式：dp[i] 是仅使用最多 i 的索引中的有效选择即可实现的最大总和。 任何以 i 结尾的解要么排除已被 dp[i − 1] 覆盖的 i，要么包含 i，在这种情况下，必须排除 (i − D, i) 范围内的所有不兼容索引，强制最后一个先前选择的索引最多为 i − D − 1。这会穷尽所有有效的可能性而不会重叠，因此每个可行子集在递归中只表示一次。 

通过固定边界，确保没有选定的对穿过切割，将圆形情况简化为线性情况，这保留了正确性，因为每个有效的圆形子集在其循环表示中都避免了至少一条边。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(arr, D):
    n = len(arr)
    if n == 0:
        return 0

    # dp[i] = best up to i
    dp = [0] * n

    for i in range(n):
        take = arr[i]
        if i - D - 1 >= 0:
            take += dp[i - D - 1]
        skip = dp[i - 1] if i > 0 else 0
        dp[i] = max(skip, take)

    return dp[-1]

def solve():
    N, D = map(int, input().split())
    A = list(map(int, input().split()))

    if N == 1:
        print(A[0])
        return

    # Case 1: do not take index 0
    ans1 = solve_case(A[1:], D)

    # Case 2: take index 0, so we must forbid last D elements
    # effectively only consider A[0] + solve on middle part
    cut = N - D - 1
    if cut <= 0:
        ans2 = A[0]
    else:
        ans2 = A[0] + solve_case(A[1:cut], D)

    print(max(ans1, ans2))

if __name__ == "__main__":
    solve()
```该解决方案构建了一个前缀动态编程数组，其中每个状态代表一个位置的最佳可实现总和。 转换要么跳过当前元素，要么将其跳回 D + 1 个位置，这直接对间距约束进行编码。 

圆形约束通过分成两个线性情况来处理。 第一个例子中，索引 0 被排除，因此数组变成了简单的行。 在第二个中，包含索引 0，这强制排除索引 0 的距离 D 内的靠近末端的索引。 这就是为什么第二个DP只运行在中间段。 

这里的一个常见陷阱是忘记循环邻接将第一个和最后一个 D 元素耦合起来。 另一个错误是在没有适当处理的情况下错误地允许 dp[i - D - 1] 索引负位置，这就是代码显式检查边界的原因。

 ## 边缘情况

 当 D 接近 N − 1 时，就会出现临界边缘情况。在这种情况下，几乎所有索引都相互冲突，算法必须简化为选取最大元素。 用于输入`5 4 / 1 2 3 4 5`，DP 确保任何“take”转换都会跳过所有剩余元素，因此 dp 会折叠到最大单个值，正确生成 5。 

另一个边缘情况是当 D = 0 时。递推式变为 dp[i] = max(dp[i − 1], A[i] + dp[i − 1])，这简化为始终采用每个元素。 该实现自然地处理了这个问题，因为 i − D − 1 变成了 i − 1，所以 take 总是建立在 dp[i − 1] 上，产生所有元素的累积和。 

最后一个微妙的情况是圆形包裹交互。 为了`4 1 / 2 1 1 2`，在第二种情况下选择索引 0 会排除索引 3，而排除索引 0 则允许同时选择索引 1 和 3。 分箱处理可确保评估两种配置，并正确选择最大值为 3。
