 ## 解决方案
 ## 问题理解

 我们得到了三堆糖果：红、绿、蓝。 每堆有一定数量的糖果，用整数表示$r$,$g$， 和$b$。 塔尼娅每天只吃两颗糖果，但它们的颜色必须不同。 任务是确定她可以继续吃两种不同颜色的糖果的最大天数，直到至少一种颜色耗尽。 

输入由多个测试用例组成。 每个测试用例指定三种颜色糖果的初始数量。 每个测试用例的输出都是一个整数：Tanya 可以吃糖果的最大天数。 

约束告诉我们每堆最多可以有$10^8$糖果，最多可以有 1000 个测试用例。 这排除了任何逐一模拟每一天的方法，因为在最坏的情况下可能需要多达$10^8$每个测试用例的迭代次数，这对于 1 秒的时间限制来说远远超出了可行的范围。 我们需要一个$O(1)$或者$O(\log n)$每个测试用例的解决方案。 

当一堆比其他两堆的总和大得多时，就会出现不明显的边缘情况。 例如，如果桩是$r = 10$,$g = 2$,$b = 1$，我们不能简单地取平均值或总和的一半。 正确答案受到较小堆的总和的限制，因为一旦它们耗尽，即使最大堆还剩下糖果，也无法再吃掉更多的不同颜色对。 

## 方法

 蛮力方法是通过挑选两个非空堆并减少它们的计数来模拟每一天。 这工作正常，但对于大$r$,$g$,$b$太慢了。 例如，如果我们尝试模拟$10^8$天，即$O(r+g+b)$每个测试用例的操作数可以达到$3 \cdot 10^8$操作，并且有 1000 个测试用例，这显然是不切实际的。 

关键的见解是最大天数受到两个限制。 首先，每天消耗两颗糖果，所以绝对最大值是$(r+g+b) // 2$。 其次，你消耗的能量不能超过两个较小堆的总和，因为一旦它们耗尽，就不可能再进行配对。 因此，我们取一半糖果与两堆较小糖果的总和之间的最小值。 对堆进行排序使这变得更容易：如果$x \le y \le z$是排序后的计数，最大天数是$\min(x + y, (x + y + z) // 2)$。 

这一观察结果将模拟问题转化为每个测试用例的简单算术计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(r+g+b) | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取三堆糖果的计数：$r$,$g$,$b$。 
2. 对计数进行排序得到$x \le y \le z$。 排序可以确保我们知道哪堆是最小的、中间的和最大的，这简化了对消费的推理。 
3. 计算所有糖果的总和：$total = r + g + b$。 
4. 计算两个较小桩的总和：$pair_limit = x + y$。 
5. 最大天数是糖果总数的一半（整数除法）与两堆较小糖果堆之和中的最小值：$max_days = \min(total // 2, pair_limit)$。 
6. 输出$max_days$。 

为什么有效：每天只吃两颗糖果。 糖果总数的一半给出了可以消耗多少对的绝对上限。 两堆较小的一堆的总和保证我们永远不会尝试消耗超过两堆可用的量，因为一旦其中一堆耗尽，就不可能再有有效的日子了。 这两个约束充分抓住了问题的极限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    r, g, b = map(int, input().split())
    piles = sorted([r, g, b])
    x, y, z = piles
    total = x + y + z
    max_days = min(x + y, total // 2)
    print(max_days)
```该解决方案首先读取测试用例的数量。 对于每个测试用例，它解析三个整数并对它们进行排序。 排序可以确保$x$和$y$是最小的桩，这使得计算对限制变得简单。 然后我们计算糖果总数并应用之间的最小值$total // 2$和$x + y$找到最大天数。 使用整数除法可确保结果正确舍入。 对三个元素进行排序实际上是常数时间，因此不会影响整体复杂性。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    res = []
    for _ in range(t):
        r, g, b = map(int, input().split())
        x, y, z = sorted([r, g, b])
        res.append(str(min(x + y, (x + y + z) // 2)))
    return "\n".join(res)

 ## 边缘情况

 For an input like`0 5 5`，算法正确地识别出没有一天是可能的，因为一堆是空的。 排序给出 x=0、y=5、z=5、total=10、pair_limit=5 和 min(total//2,pair_limit) = min(5,5)=5。 但由于一堆有 0 颗糖果，我们实际上无法形成一对，因此正确的最大天数为 0。实际上，该算法有效，因为 x+y (0+5=5) 和total//2 (10//2=5) 的最小值为 5，但由于 x=0，不存在有效的对，模拟将确认为零。 这建议添加 x>0 的检查，但在问题约束 (1 ≤ r, g, b) 的情况下，这种情况不会发生。 因此，我们的解决方案是有效的。 

用于输入`1 1 100000000`，排序给出x=1, y=1, z=100000000,total=100000002,x+y=2,total//2=50000001,min=2。 只能消耗两天，因为两天后较小的堆就耗尽了，从而确认了两个较小堆的总和限制。
