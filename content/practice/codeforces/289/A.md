 ## 解决方案
 ## 问题理解

 我们在数轴上给出了几个整数区间。 每个区间代表一个连续的覆盖整数块，并且这些段不以任何方式重叠或接触。 所有段的并集形成一组覆盖的整数点，系统的“值”就是总共覆盖了多少个不同的整数。 

换句话说，如果我们想象绘制每个段内的所有整数，则该值就是绘制的整数点的总数。 

在一次操作中，我们可以获取任何单个段并将其向左或向右恰好扩展一个单位。 向左扩展将其左端点减少 1，向右扩展将其右端点增加 1。 每个操作都会将总覆盖长度恰好增加一，但根据段之间的间隙，扩展最终可能会合并相邻组件，这会改变覆盖范围的重叠方式。 

任务是确定所需的此类单元展开的最小数量，以便最终覆盖的整数点总数可以被 k 整除。 

这些限制促使我们寻求有效的解决方案。 由于分段数量多达 100,000 个，任何模拟每个扩展步骤的解决方案都是不可能的。 即使是尝试每个细分市场的所有扩展组合的策略也会出现组合爆炸。 关键是我们只关心总覆盖长度以及它如何随着每次扩展而变化，而不是每个中间配置的确切几何形状。 

当各段仅由一个间隙分隔时，会出现一种微妙的边缘情况。 例如，[1,2] 和 [3,4] 不相交但接近。 扩展任一片段最终可能会缩小间隙并将它们合并，这意味着总覆盖长度的增加不仅仅是合并后扩展的原始数量。 在这种情况下，假设每次操作总是将总值恰好增加 1 的天真的方法会错误计数。 

另一种边缘情况是当前总长度已经可以被 k 整除。 在这种情况下，答案是零，尽管任何扩展都会立即破坏可分性并需要进一步调整。 

## 方法

 一种直接的方法是模拟该过程：重复尝试所有可能的单一展开，重新计算并集长度，并跟踪何时实现整除。 如果我们合并间隔，则计算每次更改后的并集长度为 O(n)，并且对每个可能的操作序列执行此操作会导致指数搜索空间。 当 k 很大时，即使是最多 k 步的贪婪模拟也太慢。 

关键的观察结果是，唯一重要的数量是总覆盖长度，并且每次操作都会使总长度恰好增加一个单位。 即使段在扩展后合并，这种合并也不会减少计算或使计算复杂化：每次操作联合长度仍然增加一，因为我们总是添加一个先前未发现的新整数。 

所以这个问题就简化为一个纯粹的算术问题。 令 S 为总初始覆盖长度，计算为 (r_i - l_i + 1) 的所有段的总和。 我们想要最小的非负整数 x，使得 S + x 可以被 k 整除。 

这是一个简单的模调整问题。 我们计算 S mod k。 如果它已经为零，则答案为零。 否则我们需要 k - (S mod k) 运算。 

不相交线段的结构保证没有隐藏的相互作用影响总长度，因此我们永远不需要跟踪初始求和之外的几何形状。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(k·n) 或更差 | O(1) | O(1) | 太慢了 |
 | 算术归约| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 读取所有线段，并通过对每个线段求和 (r - l + 1) 来计算它们的总覆盖长度 S。 

这是可行的，因为不相交的段允许直接相加而无需重叠校正。 
2. 计算余数 rem = S mod k。 

这捕获了 S 与 k 的下一个倍数的距离。 
3. 如果rem == 0，则立即返回0。 

无需更改，因为条件已满足。 
4. 否则将答案计算为 k - rem。 

这是将 S 移动到 k 的下一个倍数的最小正增量。 

每个操作都对应于将覆盖范围增加一个整数，因此添加 k - rem 操作对于达到整除性来说既是必要的也是充分的。 

### 为什么它有效

 关键的不变量是，联合长度每次操作都会确定性地改变一个，无论选择哪个段或段后来如何交互。 由于段最初是不相交的，因此每个操作都将一个新的覆盖整数引入到联合中，直到重叠与总计数无关。 因此，该过程永远不会偏离 S 的简单线性增加，从而使最终条件纯粹模块化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    total = 0

    for _ in range(n):
        l, r = map(int, input().split())
        total += (r - l + 1)

    rem = total % k
    if rem == 0:
        print(0)
    else:
        print(k - rem)

if __name__ == "__main__":
    solve()
```该解决方案直接计算总覆盖长度，无需存储段。 每个段独立地贡献其长度，由于不重叠的保证，这是有效的。 模步决定了我们距离 k 的倍数有多远，最后的减法给出了所需的最小增量。 

## 工作示例

 ### 示例 1

 输入：```

```段总长度为 (2 - 1 + 1) + (4 - 3 + 1) = 2 + 2 = 4。

 我们需要 2 次运算才能达到 6，它可以被 3 整除。 

这证实了该算法正确地忽略了空间结构并仅关注总覆盖范围。

 ## 边缘情况

 一种边缘情况是总长度已经可以被 k 整除。 对于输入：```
1 4
1 4
```总数为 4，因此 rem 为 0，算法立即输出 0。 不需要任何操作，任何扩展只会使总数远离有效倍数。 

另一种边缘情况是所有段都是单点时：```
3 5
1 1
3 3
5 5
```总数为 3。余数为 3 mod 5 = 3，因此我们需要 2 次运算。 每个操作都会将覆盖计数恰好增加 1，因此达到 5 是最小且一致的。 

最后的边缘情况是大输入，其中 n 最大。 由于该算法从不存储段而仅累加总和，因此内存使用量保持恒定并且时间保持线性，从而避免了间隔处理的任何结构开销。
