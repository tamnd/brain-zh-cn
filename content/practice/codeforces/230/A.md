 ## 解决方案
 ## 问题理解

 桐人一开始就拥有一定的初始力量，必须击败关卡中的每条龙。 每条龙都有两个值：击败它所需的最低力量，以及桐人随后获得的额外力量。 

只有桐人当前的实力严格大于龙的实力，才有可能进行战斗。 同等实力是不够的。 获胜后，桐人立刻变得更强，之后或许能够击败更强悍的龙。 

战斗顺序不固定。 我们必须决定是否存在某种龙的排序，使得桐人能够在不失败的情况下击败所有龙。 

限制非常小。 最多有$10^3$龙，所以即使$O(n^2)$或者$O(n^3)$解决方案将轻松地符合限制。 这意味着真正的挑战不是优化，而是识别正确的贪婪策略。 

问题的危险部分是严格比较。 桐人的力量必须严格大于龙的力量。 粗心的实现使用`>=`而不是`>`默默地产生错误的答案。 

考虑这个输入：```
5 1
5 10
```正确的输出是：```
NO
```桐人的实力与龙的实力相当，所以他立刻就输了。 使用`>=`会错误地接受这个案例。 

另一个微妙的情况是以错误的顺序选择龙。```
3 2
2 1
4 100
```正确的输出是：```
YES
```如果桐人先与更强的龙战斗，他就会失败。 如果他先与较弱的龙战斗，他的力量就会变得$4$，这仍然不够，因为比较是严格的。 所以这个例子实际上是：```
NO
```稍微改变第一个奖金给出：```
3 2
2 2
4 100
```现在正确的输出是：```
YES
```击败第一条龙后，桐人的实力变为$5$，足以击败第二条龙。 

不仔细考虑战斗顺序的幼稚方法很容易在这些边界转换上失败。 

## 方法

 蛮力的想法是尝试所有可能的龙顺序。 对于每一种排列，我们都会模拟战斗并检查桐人是否能在所有排列中幸存下来。 

这是可行的，因为固定排序的结果很容易模拟。 我们只是按照这个顺序穿过龙，保持桐人现在的实力。 

问题是排列的数量。 和$n$龙，有$n!$可能的订单。 即使是为了$n = 15$，这已经是巨大的了。 和$n = 1000$，暴力破解是完全不可能的。 

关键的观察是，较早与较弱的龙战斗总是至少与较早与较强的龙战斗一样好。 

假设桐人可以击败两条龙，一条力量为3，另一条力量为10。如果他先击败较弱的一条，他会更快获得额外的力量，使未来的战斗变得更容易。 推迟简单的战斗没有任何优势，因为奖金是非负的。 

这将问题转化为一个简单的贪心策略：

 1.按照力量对龙进行排序。 
2.从弱到强与他们战斗。 
3.如果桐人无法击败现在的龙，那么答案就是不可能。 

为什么这个贪心顺序会起作用呢？ 因为每时每刻它都会最小化所需的电流强度。 如果桐人无法击败剩下的最弱的龙，那么他也无法击败剩下的任何更强的龙。 

排序完全消除了探索不同排列的需要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1.读取桐人的初始强度和龙列表。 
2. 将每条龙作为一对存储`(strength, bonus)`。 
3. 按照龙的力量从小到大的顺序对龙进行排序。 

最弱的龙总是最安全的战斗。 首先击败较容易的龙可以更早地获得力量加成。 
4. 一条一条地迭代排序后的龙。 
5.对于每条龙，将桐人当前的力量与该龙的力量进行比较。 

如果桐人的力量小于或等于龙的力量，他就会立即失败，答案是`"NO"`。 
6. 否则，桐人击败龙并获得额外力量。 

更新：$$s = s + bonus$$7. 如果所有龙都被成功击败，则打印`"YES"`。 

### 为什么它有效

 不变的是，在每次战斗之前，桐人都会在击败所有较弱的龙后获得最大可能的力量。 

假设剩下的最弱的龙无法被击败。 剩下的所有龙都至少同样强大，所以它们也都无法被击败。 这意味着无论顺序如何，游戏都已经输了。 

如果最弱的龙可以被击败，立即采取它总是安全的，因为奖金是非负的。 尽早战斗只会增加未来的实力，而不会阻止任何未来的选择。 

由于这个特性，按龙的强度排序会产生最佳顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s, n = map(int, input().split())

    dragons = []
    for _ in range(n):
        x, y = map(int, input().split())
        dragons.append((x, y))

    dragons.sort()

    for x, y in dragons:
        if s <= x:
            print("NO")
            return
        s += y

    print("YES")

solve()
```第一部分读取初始强度和所有龙。 每条龙都存储为一个元组，其中第一个值是龙的力量，第二个值是击败它后的奖励。 

致电给`sort()`是核心的贪婪步骤。 Python 按字典顺序对元组进行排序，因此龙会自动按照强度增加进行排序。 

该循环按该顺序模拟战斗。 条件`s <= x`很关键。 问题严格来说需要更大的力量，所以平等仍然意味着失败。 

赢得一场战斗后，奖金会立即添加。 这种更新的力量随后用于后来的龙。 

一旦桐人输掉一场战斗，解决方案就会提前退出。 失败后没有理由继续模拟。 

Python 整数是任意精度的，因此这里永远不用担心溢出。

 ## 边缘情况

 一个常见的错误是让同等力量获胜。 

输入：```
5 1
5 10
```龙已经排序了。 Kirito 从强度 5 开始。算法检查：```
5 <= 5
```这个条件成立，所以算法立即打印`"NO"`。 

这符合问题规则，因为桐人必须严格更强。 

另一个微妙的情况是排序改变结果。 

输入：```
3 2
4 100
2 2
```排序后：```
(2, 2), (4, 100)
```模拟：

 1.桐人击败力量2的龙，力量变为5。 
2.桐人击败力量4的龙。 

答案是`"YES"`。 

如果不排序的话，桐人会先和4级龙战斗，然后立刻就输了。 这说明了为什么贪婪排序很重要。 

最后一个边缘情况是较小的龙仍然无法提供足够的生长。 

输入：```
3 2
2 1
4 100
```排序后，顺序保持不变。 

1.桐人击败第一条龙，力量达到4。 
2.第二条龙的力量也为4。 

因为比较严格，桐人还是输了。 算法正确打印`"NO"`而不是错误地将平等视为成功。
