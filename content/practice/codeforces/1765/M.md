 ## 解决方案
 ## 问题理解

 我们被要求分割给定的整数`n`分成两个积极的部分`a`和`b`这样他们的总和就固定在`n`。 在所有这些分割中，我们想要使最小公倍数的对`a`和`b`尽可能小。 

因此输入只是一系列测试用例，每个测试用例提供一个数字`n`。 对于每个`n`，我们在概念上放置了一个断裂的切口`n`分成两个正整数，然后我们使用 LCM 来测量该对的“兼容性”程度。 目标是找到此兼容性度量最小化的拆分。 

约束条件`n ≤ 10^9`意味着我们不能以天真的方式尝试单个测试用例的所有可能的分割`n/2`如果我们每次拆分都做一些昂贵的事情，预计它会在最坏的情况下通过。 每个测试用例的线性扫描在多个情况下已经达到 10^9 的边界，但更重要的是，它表明解决方案必须将问题简化为分解或对数检查之类的问题。 

一个微妙的边缘情况是`n`很小，特别是`n = 2`。 在这种情况下，唯一的分割是`1 + 1`，因此任何依赖于除数或最大真除数的公式仍然必须处理“最佳除数”可能是这样的事实`1`。 另一个边缘情况是奇数，例如`n = 9`，直觉可能会建议平衡的分割，例如`4 + 5`，但这些在 LCM 下不一定是最优的； 事实上，更结构化的对，例如`3 + 6`表现更好。 这表明仅对称性并不是正确的启发式。 

## 方法

 直接的方法是尝试每一对`(a, b)`这样`a + b = n`, 计算`lcm(a, b)`，并取最小值。 由于大约有`n`选择`a`，这导致`O(n)`每个测试用例的工作。 和`n`最多`10^9`，这是完全不可行的。 

关键结构来自于重写LCM表达式。 对于任意一对`(a, b)`，我们可以表达`a = g x`和`b = g y`， 在哪里`g = gcd(a, b)`和`x`和`y`是互质的。 总和约束变为`g(x + y) = n`， 所以`g`必须划分`n`。 这将问题从搜索所有分割更改为搜索除数`n`。 

一旦总和确定为`x + y = n / g`，产品`x * y`将 LCM 确定为`lcm(a, b) = g * x * y`。 对于固定金额，产品`x * y`当一个值是最小化时`1`另一个是`k - 1`。 这推动 LCM`g * (k - 1)`这简化为`n - g`。 

现在目标变得极其简单：最大化`g`在这样的约束下`g`是一个真因数`n`。 最好的可能`g`是小于的最大除数`n`，通过除以得到`n`由其最小素因子。 

蛮力通过枚举所有分割来工作，但会失败，因为它忽略了除数结构。 LCM 依赖于 gcd 和 sum 的观察结果将问题简化为寻找单个素因子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(n) | O(1) | O(1) | 太慢了|
 | 基于素因数 | 每次测试 O(√n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们现在将推理转化为直接的过程。 

1. 对于每个测试用例，请阅读`n`。 目标是确定隐式 gcd 结构最大化的分割。 
2. 求最小质因数`p`的`n`。 这已经足够了，因为除法`n`经过`p`给出最大真因数`n`。 
3. 计算`g = n / p`。 该值代表有效对的最佳 gcd`(a, b)`。 
4. 将这对构造为`a = g`和`b = n - g`。 这保证了`a + b = n`并且 gcd 结构与最佳因式分解一致。 
5、输出`(a, b)`以任何顺序。 

这个结构起作用的原因是一旦我们修复了`g`作为除数`n`，剩余的总和分为`(1, k - 1)`在减少变量的水平上，这最小化了内积，从而最小化了 LCM。 

### 为什么它有效

 任何有效的对都可以写成`(g x, g y)`和`x + y = n / g`。 LCM 变为`g x y`。 对于固定`g`，最小化 LCM 可以减少到最小化`x y`，在极端不平衡时最小化`(1, k - 1)`。 剩下的自由就是选择`g`。 由于最终表达式简化为`n - g`, 最大化`g`给出最优解，以及最大真因数`n`正是`n`除以它的最小质因数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def smallest_prime_factor(n: int) -> int:
    if n % 2 == 0:
        return 2
    d = 3
    while d * d <= n:
        if n % d == 0:
            return d
        d += 2
    return n

t = int(input())
for _ in range(t):
    n = int(input())
    p = smallest_prime_factor(n)
    g = n // p
    a = g
    b = n - g
    print(a, b)
```辅助函数通过检查整除性来有效计算最小素因数`sqrt(n)`。 一旦我们找到它，我们立即推导出最佳 gcd 候选者`g`。 

施工`b = n - g`是有意为之的：它避免了互补结构的任何重新计算并直接强制执行总和约束。 

一个常见的错误是返回`(g, g)`，但这仅在以下情况下有效`n`是偶数并且`g = n/2`。 正确的公式总是通过减法保留求和条件。 

## 工作示例

 考虑`n = 9`。 

| 步骤| n | 最小质因数 p | g = n/p | 一个 | 乙|
 | --- | --- | --- | --- | --- | --- |
 | 初始化| 9 | - | - | - | - |
 | 因素| 9 | 3 | - | - | - |
 | 计算| 9 | 3 | 3 | 3 | 6 |

 这会产生`(3, 6)`。 其他分裂如`(4, 5)`或者`(1, 8)`产生更大的 LCM 值，因为它们对应于更小的有效 gcd 结构，从而增加了表达式`n - g`。 

现在考虑`n = 10`。 

| 步骤| n | 最小质因数 p | g = n/p | 一个 | 乙|
 | --- | --- | --- | --- | --- | --- |
 | 初始化| 10 | 10 - | - | - | - |
 | 因素| 10 | 10 2 | - | - | - |
 | 计算| 10 | 10 2 | 5 | 5 | 5 |

 这给出了对称分割，这是最佳的，因为最大真除数恰好是`5`。 

这些例子证实了算法自然地在对称和非对称分割之间切换，具体取决于是否`n`有一个小的质因数。

 ## 边缘情况

 对于`n = 2`，算法找到最小素因数`2`， 所以`g = 1`和输出`(1, 1)`，这是唯一有效的分割。 

对于素数`n`， 说`n = 7`，最小的质因数是`7`， 所以`g = 1`结果就变成了`(1, 6)`。 这与不存在非平凡除数结构的事实相匹配，因此解退化为极端不平衡。 

对于两个类似的幂`n = 16`，最小的质因数是`2`， 所以`g = 8`，生产`(8, 8)`。 这表明该算法自然地检测对称分割何时是最佳的，因为最大真除数恰好是`n`。
