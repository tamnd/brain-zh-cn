 ## 解决方案
 ## 问题理解

 我们有一个包含许多行和列的垂直网格，但除了每列中的一颗小行星之外，几乎所有单元格都是空的。 柱子$i$恰好包含一颗放置在行中的小行星$c_i$。 宇宙飞船从以下位置开始$(0, 0)$，并且可以在当前列内上下移动。 关键动作是它可以在任何时刻发射光束，该光束会摧毁与飞船当前位置位于同一排的每一颗小行星。 

列之间的移动隐含在语句中：由于小行星分布在列中，但射击会影响整行，因此实际结构是每个小行星对应一个目标点$(i, c_i)$。 该船可以在限制条件下无成本地垂直重新定位到任何行，但射击次数有限$K$，并且只有在包含至少一颗尚未被摧毁的小行星的行上发射时，每次射击才有用。 

所以任务最多减少为选择$K$行索引使得小行星位于这些行上的列总数最大化。 

每个选定的行“覆盖”小行星高度等于该行值的所有列，并且每列最多贡献一次，因为每列只有一个小行星。 

限制条件很大：$C$可以达到$10^5$。 任何尝试所有行子集甚至所有拍摄序列组合的解决方案都是不可行的。 甚至$O(C \log C)$或者$O(C)$每个查询是可以接受的，但是任何行或列的二次都会太慢。 

微妙的边缘情况来自于重复的高度。 如果多个列共享相同的$c_i$，该行中的一枪可清除所有这些。 独立处理列而不是按行聚合的幼稚方法会过多计算操作并低估效率。 

另一个边缘情况是当$K$超过不同高度的数量。 在这种情况下，应该选择至少有一颗小行星的每一行，但天真的逐列贪婪方法可能仍然会浪费镜头。 

例如，考虑：```
C = 5, K = 5
c = [1, 1, 2, 2, 3]
```正确答案是 5，因为使用 3 次射击即可清除所有小行星。 每列射击的幼稚方法可能会错误地假设需要更多射击或错误处理重复。 

## 方法

 一种蛮力的解释是根据镜头序列来思考。 由于飞船可以自由垂直移动，因此每次射击实际上都是选择一行，并且该行上的所有小行星都被移除。 一个天真的解决方案最多会尝试大小行的所有子集$K$，计算覆盖了多少列，并取最好的。 这是正确的，因为顺序并不重要，重要的是选择哪些行。 

然而，行的可能子集的数量与不同高度的数量呈指数关系。 在最坏的情况下，所有$c_i$是不同的，所以有$C$候选行。 尝试所有$K$-组合导致$\binom{C}{K}$，即使对于小规模来说也是不可行的$K$。 即使是回溯解决方案也会发生组合爆炸。 

关键的观察是行是独立的：选择一行精确地贡献了小行星所在的列的数量，并且除了预算之外，行之间没有相互作用$K$。 所以问题就变成了：我们有一组权重（每个行高的频率），并且我们最多想选择$K$具有最大总和的元素，其中选择一行会产生其频率。 

这立即减少到按降序排序频率并取顶部$K$。 每次射击都应该在给出最大边际增益的行上使用，并且由于增益是固定且独立的，因此贪婪选择是最佳的。 

我们计算所有的频率图$c_i$，对频率进行排序，并对最大的进行求和$K$价值观。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对行子集的暴力破解 |$O(2^C)$|$O(C)$| 太慢了 |
 | 频数统计+排序|$O(C \log C)$|$O(C)$| 已接受 |

 ## 算法演练

 1. 阅读小行星高度列表并计算每个高度出现的次数。 

此步骤将所有可以用一次射击摧毁的列分组，因为对一行进行射击会删除该行上的所有小行星。 
2. 将所有频率提取到一个数组中。 

每个频率代表选择该行一次的好处。 
3. 按频率降序排列。 

我们希望优先考虑每次拍摄去除最多小行星的行。 
4. 拿第一个$K$排序列表中的值并对它们求和。 

如果少于$K$不同的行，我们将它们全部拍摄，因为额外的镜头无法改善结果。 
5. 输出计算出的总和。 

### 为什么它有效

 每行贡献一个独立于其他行的固定值，因为每个小行星恰好属于一行，并且在第一次选择该行时被删除。 这创建了一组独立的奖励，并且每次射击都可以选择一个奖励。 由于不同行的奖励之间没有重叠，因此最大化总破坏减少为选择最大的可用奖励$K$。 任何偏离获得最大可用剩余奖励的行为都只能用较小的贡献来代替较大的贡献，而不能提高总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    R, C, K = map(int, input().split())
    c = list(map(int, input().split()))

    freq = {}
    for x in c:
        freq[x] = freq.get(x, 0) + 1

    vals = sorted(freq.values(), reverse=True)

    ans = 0
    for i in range(min(K, len(vals))):
        ans += vals[i]

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将网格结构压缩为行上的频率图。 这是至关重要的简化，消除了对运动或几何形状的任何依赖。 排序步骤确保我们始终首先考虑利润最高的行。 

该循环由两者仔细界定$K$以及不同行的数量，这可以避免索引错误$K$很大。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(C \log C)$| 计数频率是线性的，排序不同的高度占主导地位 |
 | 空间|$O(C)$| 频率图每个不同高度最多存储一个条目 |

 约束允许最多$10^5$值，因此线性算术解完全在限制范围内。 内存使用量也与不同小行星高度的数量成线性关系，大小正好在 256 MB 之内。

 ## 边缘情况

 一个常见的边缘情况是所有小行星位于同一行。 例如：```
3 3 10
5 5 5
```频率图仅包含一个条目 3。算法对 [3] 进行排序并取 min(K, 1)，生成 3。任何试图“每列使用多个镜头”的推理都是不正确的，因为该模型只允许每次镜头对每行进行一次破坏。 

另一个边缘情况是当$K = 0$。 频率列表可能非空，但算法正确返回 0，因为它在切片时从不选择任何行$K$。 在没有保护零次发射的情况下对频率进行简单的循环可能会错误地累积值。 

最后一个微妙的情况是多样性：```
C = 5, K = 2
c = [1, 2, 3, 4, 5]
```该算法对所有这些进行排序并选择两个，产生 2。任何尝试在列之间“移动船舶”而不是将行视为独立奖励的方法都可能错误地使移动过于复杂，但移动成本与评分无关，因此只有选择才重要。
