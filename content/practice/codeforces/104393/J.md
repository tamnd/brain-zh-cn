 ## 解决方案
 ## 问题理解

 我们有一个固定的食材储藏室，并且有一条规则，简必须准确挑选$K$形成沙拉的不同成分。 每个朋友都有一份他们拒绝吃的食材的个人清单。 仅当没有被选中时，朋友才会参加聚会$K$成分出现在他们不喜欢的列表中。 目标是选择$K$以便参加的朋友数量尽可能多。 

以更具结构性的方式重新表述，每种成分都是大小宇宙中的一个元素$N \le 50$。 每个朋友都定义了这个宇宙的一个禁止子集。 选定的沙拉是一个子集$S$尺寸的$K$。 朋友满意的时候正是$S$不与他们的禁止集相交。 我们想要选择$S$最大化同时满足这些约束的数量。 

约束大小很小，但以不对称方式排列：$N \le 50$,$F \le 20$， 和$K \le N$。 朋友数量少是关键的结构性信号。 即使成分空间足够大，可以直接枚举所有$K$-子集是不可能的，约束的数量足够小，我们可以对约束的子集而不是成分的子集进行推理。 

天真的尝试会尝试所有$\binom{50}{K}$成分集并与所有朋友进行检查。 即使是为了$K \approx 25$，这会爆炸到一个不可行的搜索空间。 

当尝试贪婪地选择成分时，会出现更微妙的失败案例。 选择对许多朋友来说单独看来安全的成分是行不通的，因为只有当多种成分组合在一起时才会出现冲突。 一个小例子说明了这一点：

 输入：```
3 2 2
1 1
1 2
```如果我们贪婪地选择成分 1（对第二个朋友安全），然后选择成分 2（对第一个朋友安全），那么两个朋友都会失去，因为每个人都不喜欢所选择的成分之一。 正确答案是 0，通过选择任意两种成分来实现，但没有贪心规则可以正确预测这种相互作用。 

这个问题从根本上讲是关于固定大小的约束子集的全局一致性，而不是单个成分的局部评分。 

## 方法

 蛮力视图是枚举大小成分的所有子集$K$，然后计算有多少朋友与该子集有零交集。 这是正确的，因为它直接遵循有效性的定义，但需要检查$\binom{50}{K}$子集，每个子​​集通过集合交叉测试与最多 20 个朋友进行检查。 即使是粗略的上限也远远超出了时间限制。 

关键的观察是翻转视角。 我们不是先选择食材，而是考虑选择我们想要满足哪些朋友。 假设我们修复了一组朋友$T$。 为了让所有人都参加，选择的沙拉$S$必须避免任何朋友中出现的每一种成分$T$的不喜欢名单。 这意味着$S$必须完全包含在其禁止集的补集的交集中。 

所以对于一个固定的$T$，条件变为：计算 中所有朋友所允许的成分集$T$，并检查该允许集合是否至少包含$K$元素。 如果是的话，我们总是可以选择任何一个$K$并让所有朋友满意$T$。 

这将问题转化为迭代朋友子集而不是成分子集。 自从$F \le 20$，只有$2^F \le 10^6$子集，这是可行的。 对于每个子集，我们计算最多 20 个大小为 50 的位掩码的交集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解成分|$O(\binom{N}{K} \cdot F \cdot N)$|$O(N)$| 太慢了 |
 | DP 超过朋友的子集 |$O(F \cdot 2^F + 2^F \cdot N/word)$|$O(2^F)$| 已接受 |

 ## 算法演练

 ### 1. 将成分集编码为位掩码

 每个朋友的不喜欢列表都会转换为 50 位掩码。 由此我们计算代表它们允许的成分的补体掩模。 

这种表示的原因是集合交集变成了快速的按位与运算。 

### 2. 将朋友的每个子集解释为约束组

 对于任何朋友子集$T$，我们希望他们所有人同时接受沙拉。 这意味着沙拉必须完全位于其允许的成分集的交集内。 

所以对于每一个$T$，我们定义：$$A_T = \bigcap_{i \in T} A_i$$在哪里$A_i$是朋友面膜允许的成分$i$。 

### 3. 使用 DP 计算每个朋友子集的交集

 我们计算$A_T$对于所有使用子集 DP 的子集。 如果$T$非空且包含最后添加的好友$i$， 然后：$$A_T = A_{T \setminus \{i\}} \ \& \ A_i$$这种递归使我们能够构建所有交叉点$O(F \cdot 2^F)$。 

### 4.评估每个朋友子集的可行性

 对于每个子集$T$，我们计算允许的成分数量$A_T$。 如果这个计数至少是$K$，那么可以选择$K$满足所有朋友的成分$T$。 

我们用这样一个子集的最大大小更新答案$T$。 

### 为什么它有效

 每个有效的沙拉都对应于它所满足的朋友的某个子集，即所有不喜欢集与沙拉不相交的朋友。 对于该子集$T$，沙拉必须包含在$A_T$。 相反，如果$A_T$至少有$K$元素，我们总能制作出有效的沙拉来满足这些朋友的需求。 这在可行沙拉和可行朋友子集之间建立了一对一的对应关系，并且最大化满意的朋友减少到在容量约束下最大化子集大小$|A_T| \ge K$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N, K, F = map(int, input().split())

dislike = []
for _ in range(F):
    arr = list(map(int, input().split()))
    f = arr[0]
    mask = 0
    for x in arr[1:]:
        mask |= 1 << (x - 1)
    dislike.append(mask)

ALL = (1 << N) - 1
allow = [(~d) & ALL for d in dislike]

size = 1 << F
inter = [0] * size

for mask in range(size):
    if mask == 0:
        inter[mask] = ALL
    else:
        lsb = mask & -mask
        i = (lsb.bit_length() - 1)
        prev = mask ^ lsb
        inter[mask] = inter[prev] & allow[i]

ans = 0

for mask in range(size):
    cnt = inter[mask].bit_count()
    if cnt >= K:
        ans = max(ans, mask.bit_count())

print(ans)
```该解决方案首先将每个朋友的不喜欢列表转换为位掩码，然后将其翻转为允许设置的掩码。 这使得兼容性检查纯粹按位。 

DP 阵列`inter[mask]`存储包含在其中的所有朋友允许的成分集的交集`mask`。 该转换删除了最低有效位以重用先前计算的交集，并使用一个附加约束对其进行细化。 

最后，通过检查每个子集的交集是否至少包含$K$原料。 如果是，则该子集大小将成为候选答案。 

一个微妙的点是 DP 依赖于最低设置位的一致索引来将子集映射到朋友。 这保证了每个子集仅构建一次，而不会重复或丢失转换。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = stdin.readline

    N, K, F = map(int, input().split())
    dislike = []
    for _ in range(F):
        arr = list(map(int, input().split()))
        f = arr[0]
        mask = 0
        for x in arr[1:]:
            mask |= 1 << (x - 1)
        dislike.append(mask)

    ALL = (1 << N) - 1
    allow = [(~d) & ALL for d in dislike]

    size = 1 << F
    inter = [0] * size

    for mask in range(size):
        if mask == 0:
            inter[mask] = ALL
        else:
            lsb = mask & -mask
            i = (lsb.bit_length() - 1)
            prev = mask ^ lsb
            inter[mask] = inter[prev] & allow[i]

    ans = 0
    for mask in range(size):
        if inter[mask].bit_count() >= K:
            ans = max(ans, mask.bit_count())

    return str(ans)

 ## 边缘情况

 当所有朋友都不喜欢共同覆盖整个成分宇宙的重叠集合时，就会出现一个关键的边缘情况。 在这种情况下，大多数朋友子集很快就会产生空交集，并且只有一小部分朋友子集仍然可行。 DP 正确地处理了这个问题，因为任何变为零的交集都会立即失败$K$-成分检查，防止多算。 

另一种情况是没有朋友不喜欢任何东西。 每个子集的交集仍然是完整的成分集，因此答案就变成了全部$F$朋友们，既然有$K$- 部分成分有效。 DP 自然地保留了这一点，因为 AND 运算永远不会减少掩码。
