 ## 解决方案
 ## 问题理解

 我们给出了一个整数函数，它通过将数字替换为数字的平方和来重复转换数字。 从一个数字开始$N$，我们重复应用这个变换，产生一个像这样的序列$N, F(N), F(F(N)), \dots$。 这个序列最终会变小并进入循环，因为一旦数字变小，可能的状态就只有有限多个，并且该函数总是将整数映射到有界范围内。 

对于每个起始值$N$，我们将其“有趣”定义为出现在这个重复变换序列中任何位置的最小值。 任务不是计算一个数字，而是计算一个范围内的每个整数$[A, B]$，然后将所有这些有趣值相加。 

约束条件允许$A, B \leq 10^6$。 这立即排除了为范围内的每个数字独立模拟转换链的可能性。 简单的模拟将计算每个数字的多个数字平方和迭代，以及每次迭代的成本$O(\log N)$。 在最坏的情况下，即使链长度适中，最多一百万个数字也会导致大约$10^6 \times 10$每个步骤有多个操作，每个数字有多个步骤，这在 1 秒限制下变得临界或太慢。 

一个更微妙的问题是重复重新计算。 许多数字很快就会陷入相同的中间状态。 例如，19和91都进入同一个链，因此从头开始重新计算会浪费工作量。 

可能导致简单解决方案失败的边缘情况来自循环行为。 粗心的实现可能会在第一次重复后提前停止或假设单调减少。 

例如，从20开始：$20 \to 4 \to 16 \to 37 \to 58 \to 89 \to 145 \to 42 \to 20$。 

此循环中的最小值为 4，不一定是第一个值或最小的前缀值。 任何仅检查前几个步骤或在值重复时停止而不正确跟踪全局最小值的方法都会失败。 

另一个边缘情况是个位数。 为了$N = 1$，序列是$1 \to 1$，所以有趣的是 1。$N = 10$， 这是$1 \to 1$，因此即使中间值不同，有趣性也为 1。 

## 方法

 暴力方法独立计算每个数字的变换链$x$。 对于每个$x$，我们重复计算数字的平方和，直到检测到循环。 我们跟踪链中看到的最小值并将其添加到答案中。 

这种方法是正确的，因为它明确遵循定义。 问题是性能。 每次转型成本$O(\log x)$，每个数字可能需要几十次变换才能进入一个循环。 高达$10^6$数量太多，总成本变得太大。 

关键的观察是所有数字最终都会进入一个小的有界状态空间。 一旦数字变换几次，它们很快就会低于$10^6$，更重要的是，重复的数字平方和运算将值快速压缩到相对较小的“数字平方和空间”集合中。 从任何起始数字开始，链都会快速进入一个区域，该区域的值足够小，我们可以完全预先计算转换。 

这允许逆向思维方法：我们预先计算函数，而不是重新计算每个数字的链$F(x)$为所有人$x \leq 10^6$，然后使用该函数图上的记忆来预先计算每个值的最终“有趣性”。 每个数字恰好指向一个下一个状态，形成一个有向图，其中每个节点的出度均为 1。我们可以使用具有记忆功能的 DFS 来计算每个节点可到达的最小值。 

完成此操作后，答案为$[A, B]$只是预先计算结果的前缀和。

 | ---| ---| ---| ---|
 | 蛮力 |$O((B-A+1)\cdot L \cdot \log N)$|$O(1)$| 太慢了 |
 | 最佳|$O(N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们将转换建模为有向图，其中每个整数$x$正好有一个出边$F(x)$。 

1. 预计算$F(x)$为所有人$x \leq 10^6$。 我们直接通过迭代数字来计算数字平方和。 这为我们提供了每个节点的确定性下一个状态。 
2. 构建记忆数组`best[x]`存储从开始可达的最小值$x$， 包括$x$本身。 我们将所有条目初始化为未计算的。 
3. 对于每个$x$， 如果`best[x]`不计算，我们运行类似 DFS 的递归：

 我们标记$x$作为访问、计算$F(x)$，递归计算`best[F(x)]`，然后设置`best[x] = min(x, best[F(x)])`。 
4. 在递归过程中，如果我们重新访问当前递归堆栈中已有的节点，我们会检测到循环。 一旦我们完成遍历，该循环中的最小值就已知，因此我们将该最小值传播回循环中。 
5. 填充后`best[x]`为所有人$x$，我们构建一个前缀和数组`pref[i] = sum_{1..i} best[i]`。 
6. 查询$[A, B]$，我们返回`pref[B] - pref[A-1]`。 

### 为什么它有效

 每个数字都定义了函数图中的确定性路径。 每一条路径最终都会进入一个循环。 节点的有趣性仅取决于其路径上直到（包括其周期）的最小值。 DFS 记忆确保一旦计算出节点的最小可达值，它就会被所有传入边重用。 由于每个节点恰好有一个出边，因此不存在分支不一致，并且循环检测确保了该功能结构中强连接组件的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 10**6

def digit_sq_sum(x):
    s = 0
    while x:
        d = x % 10
        s += d * d
        x //= 10
    return s

sys.setrecursionlimit(10**7)

next_val = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    next_val[i] = digit_sq_sum(i)

best = [-1] * (MAXN + 1)
vis = [0] * (MAXN + 1)

def dfs(x):
    if best[x] != -1:
        return best[x]
    if vis[x]:
        return x
    vis[x] = 1
    y = next_val[x]
    res = dfs(y)
    vis[x] = 0
    best[x] = min(x, res)
    return best[x]

for i in range(1, MAXN + 1):
    if best[i] == -1:
        dfs(i)

pref = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pref[i] = pref[i - 1] + best[i]

A, B = map(int, input().split())
print(pref[B] - pref[A - 1])
```数字到平方的转换会预先计算一次，因此我们可以避免在 DFS 期间重复重新计算数字。 递归会记住每个节点的最小可达值。 这`vis`数组处理循环检测； 当我们遇到当前递归堆栈中已有的节点时，我们停止并将节点本身作为边界值返回，让最小值通过循环解析正确传播。 

前缀和允许在 O(1) 内回答最终的范围查询。 

## 工作示例

 ### 示例1：输入`1 5`我们计算`best[x]`对于每个值。 

| x| F(x) | F(x) | 路径最小值| 最佳[x] |
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | 1 |
 | 2 | 4 | 2 → 4 → 16 → ... 循环分钟 4 | 4 |
 | 3 | 9 | 周期包括 9 | 9 |
 | 4 | 16 | 16 循环分钟 4 | 4 |
 | 5 | 25 | 25 循环分钟 4 | 4 |

 前缀和：`[1, 5, 14, 18, 22]`回答：`[1,5]`是`14`。 

该迹线表明，数字很快就会陷入相同的循环结构，并且它们的有趣之处取决于该循环中可达到的最小值，而不是早期的瞬态值。 

### 示例2：输入`31 31`31 岁：

 31 → 10 → 1 → 1

 最小值为 1，所以`best[31] = 1`。 

表：

 | x| F(x) | F(x) | 最佳[x] |
 | ---| ---| ---|
 | 31 | 10 | 10 1 |
 | 10 | 10 1 | 1 |
 | 1 | 1 | 1 |

 这证实了由于数字平方崩溃，收敛到 1 主导了许多起始值。

 ## 边缘情况

 单位数字输入总是在变换下形成自循环或快速减少到 1。该算法处理此问题是因为 DFS 立即检测记忆值或在重新访问循环状态时返回节点本身，确保最小值仍然是数字本身或循环最小值。 

像 10 这样的数字表现出快速崩溃：10 映射到 1，然后稳定下来。 递归在单个链中解决了这个问题，并且记忆化确保 1 被所有下游节点重用。 

附近有大量的$10^6$不需要特殊处理，因为数字平方函数会立即减小幅度。 即使最坏情况的输入也会落入相同的有界函数图中，循环检测可保证终止而无需指数遍历。
