 ## 问题理解

 我们给出了一系列的日子，每天我们都想计算从一组预定的贡献中累积了多少“额外的努力时间”。 

每个贡献都在某一天开始$x$然后影响从$x$到最后$n$。 贡献取决于其类型。 

对于类型 1，如果它从一天开始$x$，然后在这一天$x$它补充说$1$，当天$x+1$它补充说$2$，当天$x+2$它补充说$3$，等等，所以这一天$i$得到$i-x+1$只要$i \ge x$。 

对于类型 2，如果从白天开始$x$，然后在这一天$x$它补充说$1$，当天$x+1$它补充说$4$，当天$x+2$它补充说$9$，等等，所以这一天$i$得到$(i-x+1)^2$为所有人$i \ge x$。 

任务是处理许多这样的更新和输出，每天，总累计值模$10^9+7$。 

关键的困难在于，每次更新都会影响数组的后缀，并且每次更新都有一个不断增长的二次或线性模式，因此每天天真地应用它们将需要显式扩展每个范围，这太慢了。 

这些限制非常重要。 总和$n$和$m$所有测试用例最多$10^5$，所以一个$O(nm)$每个测试用例解决方案是不可能的。 甚至$O(n \sqrt{n})$会有风险。 预期的解决方案必须将每次更新减少为常数或对数工作，然后在线性时间内重建最终数组。 

一个微妙的问题是，贡献在类型 2 中呈二次方增长。许多不正确的解决方案使用前缀和正确处理类型 1，但无法将相同的想法扩展到二次增长，特别是当将多项式移动$x$。 

另一个陷阱是忘记了贡献是通过多次更新累积的，因此我们必须有效地组合许多移位序列，而不是从头开始重新计算。 

## 方法

 直接模拟独立处理每个操作。 对于每个查询$(op, x)$，我们迭代自$x$到$n$, computing the contribution for each day and adding it to an array. 类型 1 计算$i-x+1$，类型 2 计算$(i-x+1)^2$。 这是正确的，但会导致最坏的情况$O(nm)$，达到$10^{10}$在最坏的分布约束下运行显然是不可行的。 

这两个公式的结构表明了一个关键的观察结果：两者都是变量中的多项式$d = i-x+1$。 将它们扩展为$i$和$x$，我们得到线性组合$i^0, i^1, i^2$，加上取决于的条件$x$。 这意味着每次更新都可以表示为多项式$i$，但仅从位置激活$x$向前。 的“从$x$“继续”的情况才是真正的并发症。 

这正是差分数组变得强大的情况。 我们不是直接将值添加到每个位置，而是对多项式贡献如何开始进行编码$x$并继续前进。 对于线性项，一个差分数组就足够了。 对于二次项，我们需要一个差分数组的层次结构来跟踪$i^2$,$i$和常数部分。 

变换是将每个贡献重写为二次多项式$i$，然后使用多项式范围相加技巧：我们维护三个差异数组，以便在前缀求和之后，我们恢复多项式的系数$a i^2 + b i + c$每天。 

一旦所有更新都转换为位置处的系数更新$x$，我们进行最后一次扫描以重建每天的多项式值。

 | 多项式差分数组 |$O(n + m)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将每个更新转换为多项式贡献，并使用差异数组应用它。 

### 1. 将两种更新类型展开为多项式$i$让$d = i - x + 1$。 

对于类型 1：$$d = i - x + 1 = i + (1 - x)$$所以这是线性的$i$。 

对于类型 2：$$d^2 = (i - x + 1)^2 = i^2 + 2(1-x)i + (1-x)^2$$所以这是二次方$i$。 

这表明每次更新都会贡献一个二次多项式，从$x$。 

### 2. 将答案表示为每天的二次函数

 我们维护数组$A[i], B[i], C[i]$这样最终的答案是：$$A[i] \cdot i^2 + B[i] \cdot i + C[i]$$我们的目标是将范围更新应用于这些系数数组。 

### 3.使用差异数组进行范围激活

 每次更新开始影响$x$，这意味着我们在位置添加系数$x$以不同的形式，以便在前缀和之后，效果传播到所有$i \ge x$。 

我们维护三个差异数组$A, B, C$。 每次更新都会将多项式展开后的常量添加到这些数组的索引处$x$。 

关键思想是“从 x 开始”是通过前缀传播来处理的，而不是通过显式迭代来处理。 

### 4. 处理所有更新

 对于每个查询，计算多项式的系数并将它们添加到位置处的差异数组中$x$。 不需要对后缀进行迭代。 

### 5. 通过前缀和构建最终数组

 我们计算差异数组的前缀和来重建$A[i], B[i], C[i]$。 然后每天计算最终答案。 

### 为什么它有效

 每个贡献都是一个从固定索引开始的多项式。 差异数组将“从 x 开始并影响所有后续索引”转换为 x 处的本地更新。 由于多项式在加法下是封闭的，因此对系数空间中的贡献求和相当于逐日对实际值求和。 前缀累积确保每天准确接收所有活动更新的贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def add(diff, i, val):
    if i < len(diff):
        diff[i] = (diff[i] + val) % MOD

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())

        A = [0] * (n + 3)
        B = [0] * (n + 3)
        C = [0] * (n + 3)

        for _ in range(m):
            op, x = map(int, input().split())
            x -= 1  # use 0-based

            if op == 1:
                # (i - x + 1) = i + (1 - x)
                add(A, x, 0)
                add(B, x, 1)
                add(C, x, 1 - x)

            else:
                # (i - x + 1)^2 = i^2 + 2(1-x)i + (1-x)^2
                add(A, x, 1)
                add(B, x, 2 * (1 - x))
                add(C, x, (1 - x) * (1 - x))

        a = b = c = 0
        res = []

        for i in range(n):
            a = (a + A[i]) % MOD
            b = (b + B[i]) % MOD
            c = (c + C[i]) % MOD

            val = (a * i * i + b * i + c) % MOD
            res.append(str(val))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```该代码维护三个对应于系数的差异数组$i^2$,$i$和常数项。 每个查询都减少到索引处的更新次数恒定$x$。 最后的循环执行前缀累积，以便每个索引收集所有活跃贡献。 

最微妙的一点是确保周围的正确扩展$x$。 使用$1-x$始终避免差一错误。 另一个微妙之处是使用基于 0 的索引，以便$i$多项式中的值直接与循环变量匹配。

 ## 边缘情况

 一个关键的边缘情况是多个更新从同一位置开始。 由于所有更新都应用于相同的差异索引，因此它们的贡献自然累积。 例如，如果两个类型 2 更新都从$x=1$，系数数组在位置 1 处接收加倍的二次系数，并且前缀传播确保两者全天都处于活动状态。 

另一个边缘情况是当$x=n$。 在这种情况下，只有最后一天受到影响。 差异更新仍然有效，因为前缀传播仅影响等于或超出的索引$x$，因此不会发生意外溢出。 

最后一个微妙的情况是处理负中间系数，例如$1-x$。 这些是安全的，因为一切都取模$10^9+7$在每一步中，确保值保持在范围内，同时保持模算术下的正确性。
