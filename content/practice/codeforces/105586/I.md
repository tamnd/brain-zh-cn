 ## 解决方案
 ## 问题理解

 我们得到了一个隐藏在数组内的有向结构。 每个城市只有一个向外传送，并且每个传送都属于一个城市。 如果我们查看城市$i$作为节点并绘制一条边$i \to a_i$，整个系统变成一个函数图，其中每个节点的出度恰好为 1。 

从任何起始城市开始，你反复进行传送，最终陷入一个循环。 问题的要求是，在我们被允许交换分配给城市的传送点后，图应该成为强连通的。 交换交换两个节点的出边，这意味着我们交换数组中的两个值$a$。 

目标是计算所需的最小交换次数，以便从任何节点，每个其他节点都可以通过有向路径到达。 

约束允许最多$10^5$每个测试用例的节点总数$10^5$跨测试。 这排除了对所有交换或重复模拟变换的任何二次推理。 每个测试用例的任何解决方案都必须本质上是线性或接近线性的。 

一个微妙但重要的边缘情况是当图已经由长度的单个有向循环组成时$n$。 在这种情况下，它已经是强连接的，所以答案是零。 例如，$n=3$,$a=[2,3,1]$作品。 在不识别这种结构的情况下尝试“连接组件”的幼稚方法可能仍然会执行不必​​要的交换。 

另一个特殊情况是当结构是多个循环和通向它们的树的不相交联合时。 尽管图的出度始终为 1，但它可能有多个循环。 例如，$a=[2,1,4,3]$分裂成两个2循环。 这并不是强关联的，并且仅独立计算周期的天真的推理将会失败，除非它考虑交换如何合并周期。 

## 方法

 由数组导出的图是经典的函数图。 每个连接的组件都包含一个有向循环，可能有树进入其中。 然而，由于每个节点都有一个出边，因此可达性完全由这些循环的结构控制。 

一个蛮力的想法是模拟交换。 我们可以尝试所有位置对，交换它们，重建图，并通过从每个节点运行 DFS 来检查它是否变得强连接。 检查强连接性本身就是$O(n)$，并且有$O(n^2)$互换，导致$O(n^3)$每个测试用例。 这对于立即来说是不可能的$n=10^5$。 

即使我们减少检查，核心问题仍然存在：我们正在修改类似排列的结构并要求最小交换以达到目标全局结构。 关键的观察结果是，目标结构必须是覆盖所有节点的单个循环，因为在函数图中，强连通性意味着每个节点的入度也恰好为 1，从而迫使图成为单个有向循环。 

那么问题就变成了：我们要将当前数组转变成一个由一个周期长度组成的排列$n$，使用交换，其中每个交换交换数组中的两个值。 这相当于将数组重新排列成单循环排列，问题就变成了当前映射距离这样的循环结构还有多远。 

决定性的见解是将数组解释为目的地的排列。 由于每个值$a_i$仅使用一次作为出边源位置，该结构的行为就像在根据出边考虑节点后的排列。 函数图中的每个循环对应于该排列分解中的一个循环。 

交换两个值会以受控方式合并或拆分循环。 已知的结果是任何排列都可以使用交换合并到单个循环中，并且所需交换的最小数量由存在的循环数量确定。 每次交换最多可以减少一个周期数，因为它可以将两个周期连接为一个周期。 

如果图表有$c$周期，那么我们至少需要$c-1$交换将它们合并到一个循环中，这可以通过始终交换不同循环中的元素来贪婪地实现。 

因此，答案归结为计算函数图中有向循环的数量。

 ## 算法演练

 1. 从数组隐式构造函数图$a$，其中每个节点$i$指向$a_i$。 除了遍历之外，并不明确需要这种表示，因为我们可以直接跟踪边。 
2. 遍历所有节点并使用标准访问状态检测循环。 对于每个尚未访问过的节点，开始沿着传出边缘向前行走，直到到达已访问过的节点或返回到当前递归路径中的节点。 当我们重新进入当前路径中的节点时，我们就确定了一个循环。 
3. 计算存在多少个不同的循环。 每个节点恰好属于一个循环，或者是通向一个循环的链的一部分，但每个链最终都会进入一个唯一的循环，因此每个节点在遍历过程中都会被毫无歧义地分配。 
4. 如果循环次数为$c$， 输出$c - 1$。 

此步骤有效的原因是，每个交换可以通过重定向两个周期之间的一个传出边缘连接来合并恰好两个周期。 一旦两个循环合并，它们在可达性方面就表现为单个循环。 

### 为什么它有效

 功能图分解为不相交的循环，其中有树输入其中，但强连接性需要消除所有分支到单独的循环中。 任何有效的最终结构都必须是所有节点上的单个有向循环。 每次交换最多只能减少一个周期数，因为它可以连接两个先前不相交的周期，但不能同时合并两个以上的组件。 由于最初有$c$周期，至少$c-1$需要合并，并且存在建设性的交换序列，通过重复连接两个不同的周期来精确地实现此限制。 这给出了最优性和可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = [0] + list(map(int, input().split()))

        vis = [0] * (n + 1)
        cycles = 0

        for i in range(1, n + 1):
            if vis[i]:
                continue

            cur = i
            stack_index = {}
            path = []

            while True:
                if vis[cur]:
                    break
                if cur in stack_index:
                    cycles += 1
                    break

                stack_index[cur] = len(path)
                path.append(cur)
                cur = a[cur]

            for v in path:
                vis[v] = 1

        print(max(0, cycles - 1))

if __name__ == "__main__":
    solve()
```该实现从每个未访问的节点执行前向行走。 这`stack_index`字典用于检测当前路径中的后沿，这表示循环发现。 遍历完成后，该遍历中访问的所有节点都会被标记为已处理，因此永远不会重新访问它们。 

一个微妙的点是，每个节点都被分配给一次遍历，因此即使我们仅在重新访问当前路径时显式检测循环，但循环计数仍然正确，因为每个连接的功能组件都贡献了一次循环检测事件。

 ## 边缘情况

 像这样的单节点图$n=1, a=[1]$立即形成一个循环计数 1，产生答案 0。 遍历从节点1开始，检测到自循环，并标记其已访问。 

完全循环排列，例如$a=[2,3,4,1]$被处理为一次遍历和一个周期检测事件。 该算法永远不会错误地分割它，因为标记路径后不会留下新的未访问的起点。 

不相交的循环情况，例如$a=[2,1,4,3]$处理方法是从节点 1 开始检测一个周期，然后从节点 3 开始检测另一个周期。 每个组件恰好贡献一个周期检测，产生正确的周期计数两个并回答一个。 

进入循环的病态链仍然会折叠成单个检测到的循环，因为只有循环条目才会触发后沿条件； 树节点被简单地标记为已访问并且永远不会增加循环计数。
