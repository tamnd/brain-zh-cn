 ## 问题理解

 我们得到一个数字序列，每个数字都是 -1、0 或 1。在每对相邻元素之间，我们可以放置加号或乘号，并且我们还可以通过以通常的表达式求值方式选择求值顺序来隐式使用括号。 

运算符和分组的每个完整选择都会为整个表达式生成一个值。 任务是确定是否存在最终值恰好为 0 的此类结构。 

在此版本中，每个测试用例只有一个查询，并且测试中的所有输入大小之和最多为 10^6，因此任何解决方案在总输入大小上都必须是线性或接近线性的。 由于最坏的情况是许多长数组，因此每个测试用例的任何二次方都会立即失败。 

一个微妙的边缘情况来自乘法和零之间的相互作用。 如果将零放在乘法密集的子表达式内，则可以消除任何乘积，但如果将其隔离在加法内部，则它也可以被“中和”。 这使得“将所有东西结合起来”的天真贪婪推理变得不可靠。 

另一种常见的失败模式是假设表达式的行为类似于简单的分段。 一旦允许使用括号，这个假设就会被打破，因为现在我们正在使用完整的二叉树，而不是固定的从左到右的分组。 

## 方法

 直接的强力解决方案将尝试放置运算符和所有可能的括号的所有方法。 对于 n 个元素，有 2^{n−1} 个运算符选择，有效的完整括号的数量是加泰罗尼亚语数字大小。 即使n在20左右，这也已经变得不可行，而当n达到10^6时，这是完全遥不可及的。 

关键的简化来自于认识到该表达式可以被视为一棵二叉树，其中叶子是 {−1, 0, 1} 中的值，内部节点是加法或乘法。 由于乘以零会迫使整个子树变为零，因此任何可以通过包含零的子树“路由”所有贡献的构造都会立即实现目标。 

这将问题从结构枚举转移到询问由 + 和 * 在这三个值上生成的代数系统是否可以使用可用的数字多重集表示 0。 

两个观察结果使结构崩溃：

 如果至少有一个零，我们总是可以构建一个乘法节点，将其用作整个表达式的因子，强制结果为零。 

如果不存在零，则所有值要么为−1，要么为1。在这种情况下，只有当两个符号都存在时，加法才允许取消； 否则，无论括号如何，表达式都强制为严格正数或严格负数。 

这将问题简化为对数组的简单存在检查。

 ## 算法演练

 我们独立处理每个测试用例并扫描一次数组。

1. 扫描数组并检查是否有任何元素为 0。如果是，我们可以立即得出答案是“是”，因为我们可以构造一个表达式，将这个零与表达式的其余部分相乘，强制整个值为零。 
2. 如果没有零，记录我们是否看到至少一个 -1 和至少一个 1。这很重要，因为当在表达式树的不同部分组合时，这是唯一两个可能通过加法相互抵消的值。 
3. 如果-1和1同时存在，则输出yes。 原因是我们可以安排加法和乘法，以便正贡献和负贡献出现在单独的子树中并在顶层取消。 
4. 如果所有值都相同（全部为 1 或全部为 -1），则输出 no，因为每个可能的表达式都会计算为具有固定符号的非零值。 

正确性取决于乘法不能改变符号多样性的事实，并且没有两个符号或零，每个子树保持符号一致，防止任何取消为零。 

### 为什么它有效

 每个表达式的计算结果都是通过在仅包含 -1、0 和 1 的集合上重复应用加法和乘法而构建的值。将结果强制为零的唯一方法是在跨越整个表达式的乘法链中引入零，或者在正贡献和负贡献之间构造加法抵消。 如果零或两个符号都不存在，则每个可能的表达式都会计算为具有固定符号的非零值，因此不可能达到零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        x = int(input())  # always 0

        has0 = False
        has1 = False
        hasm1 = False

        for v in a:
            if v == 0:
                has0 = True
            elif v == 1:
                has1 = True
            else:
                hasm1 = True

        if has0:
            print("Yes")
        else:
            if has1 and hasm1:
                print("Yes")
            else:
                print("No")

if __name__ == "__main__":
    solve()
```该代码仅提取数组的全局属性，而不是模拟任何表达式构造。 这三个标志准确地捕获了与可行性相关的唯一信息：存在零、存在正值和存在负值。 

在此版本中查询值始终为零，因此可以读取但不会影响分支。

现在考虑`[1, -1, 1]`。 

| 步骤| 有0 | 有1 | 有-1 |
 | --- | --- | --- | --- |
 | 阅读 1 | F | T | F |

 | 阅读 1 | F | T | T |

 这里两个符号都存在并且不存在零，所以我们输出 yes。 这对应于在表达式树的不同子树中构建正贡献和负贡献之间的加性抵消。

 ## 边缘情况

 包含0的单元素数组是最直接的成功案例。 该算法通过 has0 标志立即检测到它并返回 yes，而不依赖于任何结构推理。 

包含 1 或 -1 的单元素数组会失败，因为无法应用任何操作，并且唯一可能的值非零。 在这两种情况下，标志逻辑都正确返回 no，因为这两个条件都不满足。 

同时包含 1 和 -1 但不包含 0 的数组由混合符号条件处理。 即使元素级别没有局部取消，表达式树也可以将贡献分离到不同的子树中，这些子树在根添加处取消，这正是条件捕获的内容。 

完全由 -1 或完全由 1 组成的数组会失败，因为没有通过零进行相反贡献或湮灭的来源，因此每个可能的表达式都保留非零大小和固定符号。
