 ## 解决方案
 ## 问题理解

 我们得到一个有向无环图，其中每个节点代表一个包含具有固定功率值的怪物的房间。 该图有一个特殊的结构：每个房间最终都可以到达最终编号的房间$n$，并且不存在有向循环。 有些房间没有传入边缘，这些是我们唯一被允许开始旅程的地方。 

玩家以初始正力量值开始$x$。 每当玩家进入房间时$i$，他们在那里与怪物战斗。 战斗的结果会改变当前的力量$x$取决于怪物的强度$a_i$。 如果当前功率至少为$a_i$，玩家轻松击败怪物并获得其力量，因此新的力量变为$x + a_i$。 否则，玩家仍然会打败它，但会挣扎，力量就会变成$2x - a_i$。 如果在任何时候功率变为零或负值，运行就会立即失败。 

玩家选择任何有效的起始房间（DAG 中的源），然后沿着有向边移动，直到最终到达房间$n$，与每个遇到的怪物战斗一次。 目标是最小化初始功率$x$这样就存在一些有效的起始房间和一些通往房间的路径$n$玩家永远不会死亡并成功击败房间里的怪物$n$。 

约束允许最多$10^5$节点和$2 \cdot 10^5$边缘。 这强烈建议在图的大小上采用线性或接近线性的解决方案，因为诸如显式检查所有路径之类的事情是不可能的。 即使对所有简单路径进行动态规划也是不可行的，因为 DAG 中的路径数量可能是指数级的。 

一个微妙的困难来自于这样一个事实：状态转换不是以简单的加法方式线性的。 下一个权力取决于是否$x$跨过门槛$a_i$，在低状态下，变换是仿射的，但有惩罚。 这意味着边上的贪婪推理或简单的最短路径解释不直接适用。 

一个天真的错误是假设我们必须访问所有节点，因为该语句提到了房间图。 例如，如果我们必须遍历每个节点，那么问题将成为 DAG 上的全局排序问题，但实际上我们只遵循一条路径。 

另一种失败模式是一如既往地对待过渡$x + a_i$。 例如，如果$x < a_i$，忽略惩罚会导致高估生存能力。 在小输入上，例如单边$a_1 = 10$，开始于$x = 5$在朴素的加法模型下会错误地看起来安全，但实际上会产生$x' = 2 \cdot 5 - 10 = 0$，立即失败。 

## 方法

 暴力解决方案将尝试每一个可能的起始源和每一个可能的路径$n$，逐步模拟每条路径的战斗并检查存活的最小初始功率。 即使我们固定起始节点，DAG 中的路径数量也会呈指数增长，并且每次模拟都会花费路径长度线性时间。 这很快就变得不可行，最坏情况的复杂性呈指数级增长$n$。 

关键的观察是，尽管有分支结构，玩家的目标总是减少到到达节点$n$，并且在每个节点我们只需要知道保证生存到最后所需的最小进入功率。 这提出了反向动态规划的观点：我们不问从一开始会发生什么，而是问每个节点的最小安全进入值是多少，以确保下游的成功。 

一旦我们为每个节点定义了这个值，就可以反转转换。 对于一个节点$v$，我们考虑每个传出邻居$u$，并计算最小值$x$在$v$确保战斗后$v$，结果值至少是所需的值$u$。 这将问题转化为以逆拓扑顺序计算 DAG 上的 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有路径+模拟）| 指数| O(n) | 太慢了|
 | DAG 上的反向 DP | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们定义$dp[v]$作为进入节点时所需的最小初始功率$v$这样玩家就可以安全到达节点$n$并沿着所选路径击败所有必要的怪物。 

1. 首先，我们按照逆拓扑顺序处理节点。 这确保了当我们计算时$dp[v]$， 全部$dp[u]$对于外出的邻居$u$是已知的。 
2. 我们在节点处初始化基本情况$n$。 在这个节点，击败怪物后没有任何要求，所以我们只需要保证战斗本身的生存即可。 如果我们带着力量进入$x$，结果是$x + a_n$什么时候$x \ge a_n$，这始终是安全的。 否则，我们得到$2x - a_n$，必须保持正值。 因此，最小可行进入值是两种制度中最好的：$x \ge a_n$, 给予$x = a_n$， 或者$x < a_n$, 给予$x > a_n/2$， 所以$x = \lfloor a_n/2 \rfloor + 1$。 我们设定$dp[n]$为这两个值中的最小值。 
3.对于每个节点$v \ne n$，我们计算$dp[v]$通过考虑每个出边$v \to u$。 我们必须找到最小进入功率$x$在$v$这样在战斗之后$v$，所得功率至少为$dp[u]$。 
4. 对于固定边$v \to u$，我们根据是否$x \ge a_v$或者$x < a_v$。 
5.如果$x \ge a_v$，那么战斗结束后我们有$x' = x + a_v$。 条件$x' \ge dp[u]$变成$x \ge dp[u] - a_v$，结合$x \ge a_v$。 这给了一个候选人$x = \max(a_v, dp[u] - a_v)$。 
6. 如果$x < a_v$， 然后$x' = 2x - a_v$。 条件$x' \ge dp[u]$变成$2x \ge dp[u] + a_v$， 所以$x \ge \left\lceil \frac{dp[u] + a_v}{2} \right\rceil$，带有附加约束$x < a_v$。 如果第二个候选者位于范围内，则会产生第二个候选者。 
7. 对于每条边，我们取最小有效候选边，然后$dp[v]$是所有传出边上的最小值。 
8. 最后，由于我们可以从任何源节点（没有入边的节点）开始，所以答案是$\min dp[v]$在所有这样的节点上。 

正确性依赖于以下事实：从源到源的每条可行路径$n$引入一系列必须满足这些局部约束的必要进入条件。 通过确保每次转换都保留已知有效后缀的可行性，我们保证了全局可行性。 

关键的不变量是$dp[v]$始终代表真正的最小进入功率，允许至少一个有效的延续$v$到$n$。 由于每个传出选择都根据其所需的延续进行精确评估，因此没有无效路径可以被视为可行，并且没有可行路径被排除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        indeg[v] += 1

    topo = []
    stack = [i for i in range(1, n + 1) if indeg[i] == 0]

    while stack:
        u = stack.pop()
        topo.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                stack.append(v)

    dp = [10**30] * (n + 1)

    av = a[n]
    dp_n = min(av, (av // 2) + 1)
    dp[n] = dp_n

    for u in reversed(topo):
        if u == n:
            continue
        if not g[u]:
            continue

        best = 10**30

        for v in g[u]:
            av = a[u]
            need = dp[v]

            cand1 = max(av, need - av)

            cand2 = 10**30
            low = (need + av + 1) // 2
            if low < av:
                cand2 = low

            best = min(best, cand1, cand2)

        dp[u] = best

    ans = 10**30
    for i in range(1, n + 1):
        if indeg[i] == 0:
            ans = min(ans, dp[i])

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先使用入度剪枝构建 DAG 的拓扑顺序。 这确保我们在计算时以反向依赖顺序处理节点$dp$。 

DP阵列存储每个节点的最小安全进入功率。 基本情况为$n$直接使用战斗公式的二态分析来计算。 

对于每个节点，我们迭代传出边缘并计算从转换函数的两种可能状态派生的两个候选进入要求。 注意强制执行约束$x < a_v$在第二种情况下，否则推导将允许无效转换。 

最后，我们只考虑源节点，因为玩家可以选择任何有效的入口点。 

## 工作示例

 考虑一个简单的链$1 \to 2 \to 3$有价值观$a = [2, 3, 4]$。 

| 节点| dp计算依据| dp值|
 | --- | --- | --- |
 | 3 | 分钟(4, 3) | 3 |
 | 2 | 必须达到 dp[3]=3 | 2 |
 | 1 | 必须达到 dp[2]=2 | 1 |

 该轨迹显示了当早期节点允许在到达更强节点之前进行累积时，所需功率如何减少。 

现在考虑一个分支情况，其中节点 1 通向节点 2 和 3，并且两者都通向 4。节点 1 处的 DP 将选择两个分支中更便宜的延续，这表明该解决方案自然会选择最佳路径，而无需显式枚举它们。

 ## 边缘情况

 一个关键的边缘情况是，生存节点的唯一有效方法是进入低状态$x < a_i$。 在这种情况下，错误地忽略了约束$x < a_i$导致选择不可行的候选人。 该算法在使用之前明确检查低机制的可行性，确保正确性。 

另一种边缘情况发生在最终节点，其中缺少传出边缘会改变 DP 的含义。 该解决方案通过仅计算节点战斗的生存来单独处理这个问题$n$，确保没有错误地应用下游约束。 

当节点非常大时，就会出现最后一个微妙的情况$a_i$和小$dp[u]$，使得最佳过渡来自于低政权，尽管高级政权看起来更简单。 两个候选人的比较保证了两种制度的评估是对称的，从而防止对一种过渡形式的偏见。
