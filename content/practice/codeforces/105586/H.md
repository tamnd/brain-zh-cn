 ## 解决方案
 ## 问题理解

 随着时间的推移，我们得到了一系列值，每个值要么是负一，要么是零，要么是加一。 每个值代表当天购买的一瓶酒的内在“效果”。 用户可以通过在相邻元素之间插入运算符以任何方式将序列划分为连续的组。 每个组都被解释为一个“饮料事件”，该事件的贡献是组内所有值的乘积。 最终得分是这些组产品的总和。 

同样，我们在相邻元素之间插入加法或乘法，在正常算术规则下评估表达式，并询问结果值是否可以等于目标 x。 

关键约束结构很重要。 测试和查询的总长度最多为 10^6，值仅为 -1、0 或 1。这会立即排除任何依赖于 n 乘以 x 的状态空间或任何天真地跟踪所有可能总和的 DP。 我们需要将每个测试简化为基本上线性预处理和恒定或对数查询回答。 

零的存在是主要的结构复杂性。 零按照乘法分割序列，因为任何包含零的乘积都会变为零，但也可以使用乘法来隔离零，或者使用加运算将零吸收到和中。 

一个幼稚的解释错误是假设这是一个标准分区 DP，我们在其中计算所有可能的段积和总和组合。 另一个微妙的问题是假设零总是有利于隔离。 实际上，零要么没有任何贡献，要么充当重置乘法结构的分隔符。 

打破朴素推理的一个小边缘情况是交替模式，如 1, -1, 1。分组为 (1 + -1 + 1) 给出 1，而分组为 (1 * -1 * 1) 给出 -1。 产品内部符号的相互作用使得局部贪婪分组不正确。 

## 方法

 直接强力方法考虑相邻元素之间加或乘的每种可能的放置。 每个位置有两个选择，给出 2^(n-1) 个表达式。 计算每个表达式的成本为 O(n)，因此变为 O(n · 2^n)，即使 n 约为 40，这也是不可能的。 

更加结构化的 DP 将尝试跟踪前缀的所有可能值。 然而，如果我们不利用 {-1,0,1} 上的约束，值的计数会组合增长。 关键的观察结果是，乘法不会创建超出 {-1,0,1} 的新量值，而加法仅聚合整数。 因此，唯一的增长发生在可实现的不同金额的数量上，而不是中间产品的数量上。 

关键的见解是将序列分成最大的非零值块。 在仅 ±1 的块内，乘法本质上是负数奇偶校验，而加法允许合并段。 该块内的每个分段乘积始终为±1。 因此，每个段贡献 +1 或 -1，具体取决于它包含偶数还是奇数个 -1 值。 

因此，问题简化为选择将数组划分为段，其中每个段贡献 +1、-1 或 0（如果它包含任何零），并且零充当强制分隔符或空贡献者。 总和成为所选段符号的总和，加上由零段引起的可选取消。 

一个更精确的公式出现了：删除作为分隔符的零，独立处理每个非零块，并计算可实现的和的范围，作为最小值和最大值之间的所有整数，由可以形成多少负乘积与可以创建多少正贡献决定。 由于每个块都会折叠为 ±1 的序列，因此可实现的总和集变得连续，并且只有其边界才是重要的。

最终的减少是，对于每个测试用例，我们计算可以最佳形成的非零元素的数量和负前缀段的数量。 可达到的总和间隔是对称的，并通过选择我们合并的段数来确定。 每次合并都会在加法和乘法选择之间翻转，但由于乘法永远不会增加幅度，因此极值是通过完全分裂或最佳分组来实现的。 

这导致预处理后每个查询检查的时间恒定。

 | 最佳| O(n + q) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们将问题压缩为计算数组的结构特征而不是枚举表达式。 

1. 首先，扫描数组并提取所有非零值，暂时忽略零，但单独计数。 这很重要，因为零充当分隔符，防止它们之间相乘。 
2. 将非零序列分割成最大连续段。 每个段仅包含+1和-1。 任何完全相乘的段的乘积仅由 -1 值的奇偶性确定。 
3. 对于每个线段，计算其总乘积符号。 如果我们将它完全相乘，它要么贡献+1，要么贡献-1。 如果我们使用加运算符进一步将其分割，我们可以将其分解为单个元素，每个元素贡献±1。 
4. 观察到，在长度为 k 的段内，我们可以通过分区选择将多少元素视为 +1 或 -1 贡献，从而以步长 2 实现 -k 和 k 之间的任意和。 这是因为每个元素在加法下都是单独的±1，而乘法只会将它们折叠成单个±1。 
5. 合并所有片段。 由于各个部分是独立的，因此它们的可实现范围相加。 这意味着最终答案仅取决于非零元素 Nnz 的总数和段 S 的总数。 
6. 全局最小总和是通过使每个细分贡献其最小价值来实现的，这对应于将每个细分完全合并成单个产品并选择使贡献最小化的标志。 通过将所有内容拆分为单个元素来实现最大总和。 
7. 因此，可达和形成一个完整的整数区间[minSum，maxSum]，因此每个查询x通过检查minSum≤x≤maxSum来回答。 

为什么它有效

 核心不变量是非零值的每个段都可以减少为单个 ±1 贡献或扩展为单独的 ±1 贡献，而不会创建除 1 之外的任何中间量值。零不会跨段交互，因此它们只影响分段，而不影响段内的算术范围。 由于所有操作都保持完整性并且不会引入 ±1 之外的值，因此每个段的可实现总和集是连续的。 对独立连续区间求和会产生另一个连续区间，因此整个解空间会压缩为单个区间 [minSum, maxSum]。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        # extract non-zero structure
        nonzero = []
        for v in a:
            if v != 0:
                nonzero.append(v)

        if not nonzero:
            # only zeros: every segment product is zero, total is always 0
            # queries ask x >= 1, so always No
            for _ in range(q):
                input()
                out.append("NO")
            continue

        # compute min/max achievable
        # max: split everything -> sum of +1 contributions for 1, -1 for -1 optimally
        # best is treating each element individually => sum of abs(v)=len(nonzero)
        max_sum = len(nonzero)

        # min: worst case is pairing to reduce positives; effectively we can make all segments
        # contribute -1 by grouping, so minimum is -len(nonzero)
        min_sum = -len(nonzero)

        for _ in range(q):
            x = int(input())
            if min_sum <= x <= max_sum:
                out.append("YES")
            else:
                out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码将数组减少到其非零投影，因为零仅贡献空乘积，并且无助于增加绝对和幅度。 根据忽略零后存在多少个 ±1 贡献，将可达总和区间计算为对称边界。 

每个查询都通过直接间隔检查来回答，这是有效的，因为构造保证了可实现总和的连续性。 

一个微妙的实现选择是读取所有查询，即使数组为空或微不足道，以避免输入解析不同步。 另一种方法是统一处理所有非零值，因为出于限制目的，-1 和 +1 仅符号不同，大小不同。 

## 工作示例

 ### 示例 1

 输入：

 n = 3，a = [1, 1, 0]，查询 = [2, 3]

 我们提取非零值 [1, 1]。 有 2 个元素。 

| 步骤| 非零数组 | 最小总和 | 最大和|
 | --- | --- | --- | --- |
 | 初始化| [1, 1] | -2 | 2 |

 查询 x = 2 位于 [-2, 2] 内，所以答案是 YES。 

查询 x = 3 位于外部，因此答案是否定的。 

这演示了如何在幅度计算中忽略零，而只考虑计数。 

### 示例 2

 输入：

 n = 3，a = [1, 0, -1]，查询 = [1]

 非零数组变为[1,-1]，长度为2。 

| 步骤| 非零数组 | 最小总和 | 最大和|
 | --- | --- | --- | --- |
 | 初始化| [1，-1] | -2 | 2 |

 查询 x = 1 位于区间内，因此输出为 YES。 

这表明数组内部的符号变化不会影响可行性界限，只有活动元素的数量才重要。

 ## 边缘情况

 对于像 [0, 0, 0] 这样的纯零数组，该算法将非零列表视为空。 这迫使每个分段乘积为零，因此唯一可实现的总数为 0。由于查询要求 x ≥ 1，因此每个答案都是“否”，这与区间 [-0, 0] 匹配。 

对于像 [1, 1, 1, 1] 这样的完全非零数组，该算法将其折叠为四个独立的 ±1 贡献，产生边界 [-4, 4]。 像 x = 4 这样的查询是 YES，而 x = 5 是 NO。 这符合这样的想法：分割每个元素对于最大化幅度来说是最佳的。 

对于交替符号，如 [1, -1, 1]，区间变为 [-3, 3]。 尽管乘法可以减少方差，但分裂的能力确保了中间整数的完全覆盖，从而确认即使在符号变化的情况下也能保持连续性。
