 ## 解决方案
 ## 问题理解

 我们沿着一条笔直的走廊移动，走廊分为从 0 到 n + 1 索引的垂直“车道”。时间是离散的。 每一秒，您要么留在当前车道上，要么向右移动一个车道。 你总是停留在水平轴 y = 0 上，所以唯一有意义的状态是你当前的车道索引和当前时间。 

除单个安全垂直路段外，从 1 到 n 的每个中间车道 i 均被交通堵塞。 该安全段最初跨越区间 [l_i, r_i] 中的 y，但每秒整个流量模式都会向下移动一个单位。 由于您始终站在 y = 0 处，因此唯一的问题是当您位于车道 i 时 y = 0 是否位于安全段内。 

在时间 t 时，车道 i 中的安全路段已转移到 [l_i − t, r_i − t]。 当 l_i ≤ t ≤ r_i 时，位置 y = 0 是安全的。 因此，每个车道 i 都有一个时间窗口：您只能在该时间间隔内的时间 t 进入车道 i。 

起始车道 0 和最终车道 n+1 始终是安全的，因此它们没有施加任何限制。 

任务是找到从车道 0 开始到达车道 n + 1 所需的最短时间，同时考虑到以下事实：在时间 t 时，您的车道必须在该时间内有效，并且您每秒最多只能将车道索引增加 1 个。 

约束 n ≤ 10^5 和 l_i、r_i 高达 10^12 意味着我们需要线性或近线性扫描。 任何尝试随时间探索状态或直接使用随时间值动态规划的方法都会太慢，因为时间可能会变长，并且转换会连续到 10^12 尺度值。 

随着时间的推移，简单的模拟也会失败，因为由于等待，时间可能远远超出 n，并且每个通道引入了一个全局约束窗口。 

当车道的有效间隔早于简单地向前行走可到达的间隔时，就会出现微妙的故障情况。 

例如，如果车道 i 的 r_i < i，那么即使不等待立即到达也已经违反了约束，使得整个路径不可能。 一个天真的贪婪者只在移动后检查可行性会错过这一点。 

另一个棘手的情况是需要等待以与未来的窗口对齐。 如果一个幼稚的解决方案总是在可能的情况下移动，那么它可能会太早到达有效窗口较晚开始的车道，从而导致稍后出现矛盾，即使早点等待本来是正确的。 

## 方法

 蛮力视角将每个状态视为一对（位置、时间）。 从每个状态，我们可以移动或等待，并且我们检查当前车道在当前时间是否有效。 这会生成一个具有时间相关约束的图。 此隐式图上的 BFS 或最短路径在概念上是正确的，因为每个操作花费一秒，但状态空间在时间上是无限的。 在最坏的情况下，时间值可以达到 10^12，并且可达状态的数量与该比例成比例增长，这使得这完全不可行。 

关键的观察是时间不需要明确地探索。 一旦我们确定了车道索引 i，唯一相关的信息就是我们可以到达那里的最早时间。 任何较晚的到达只会使约束变得更困难，而不是更容易，因为每个车道 i 要求 t 位于固定间隔 [l_i, r_i] 内。 这将问题转化为计算单个可行的递增时间序列 t_0, t_1, …, t_{n+1}。 

当从车道 i − 1 移动到 i 时，总会过去一秒，因此 t_i 必须至少为 t_{i−1} + 1。此外，我们无法在车道 i 在其时间窗口内到达之前到达，因此 t_i 也必须至少为 l_i。 最后，我们不能违反期限 r_i，因此 t_i 必须≤ r_i。

这将问题分解为贪婪的前向构造，我们总是在每一步中采用最早的可行时间。 如果最早可行时间超过 r_i，则不存在有效的时间表。

 | --- | --- | --- | --- |
 | （车道、时间）上的状态空间 BFS | O(非常大，最多 10^12 个状态) | O（状态）| 太慢了|
 | 每车道贪婪时间调度| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右建立每条车道的到达时间。 

1. 将通道 0 的时间初始化为 0。这表示在时间 0 从位置 0 开始。 
2. 对于从 1 到 n 的每个车道 i，计算最早可能到达时间。 由于我们必须花费至少一秒的时间从车道 i − 1 移动，因此时间不能小于 t_{i−1} + 1。 
3. 车道也有自己的有效窗口，所以我们必须确保我们不会在 l_i 之前到达。 因此，我们取 t_{i−1} + 1 和 l_i 中的最大值作为候选到达时间。 
4. 如果该候选超过 r_i，则该车道的安全窗口已经关闭，因此没有有效的运动序列可以通过该车道，并且该过程失败终止。 
5. 否则，我们将 t_i 设置为该候选者并继续。 
6.处理完第n个泳道后，我们移动到第n+1个泳道，该泳道没有任何限制。 我们仍然必须花一秒钟的时间来移动，所以最终的答案是 t_{n+1} = t_n + 1。 

为什么有效：在每个车道 i 上，由于时间进展，任何有效的调度都必须不早于 t_{i−1} + 1 到达，并且由于安全限制，任何有效的调度都必须不早于 l_i 到达。 任何较晚的到达只会增加所有后续时间，而无助于满足未来的下限，因此选择最小可行到达时间可以保留全局的可行性。 如果这个最小值已经违反了 r_i，那么每个可能的时间表也必须违反它，因为所有时间表至少都会迟到。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    l = [0] * (n + 2)
    r = [10**30] * (n + 2)

    for i in range(1, n + 1):
        li, ri = map(int, input().split())
        l[i], r[i] = li, ri

    t = 0
    for i in range(1, n + 1):
        t = max(t + 1, l[i])
        if t > r[i]:
            print(-1)
            return

    t = t + 1
    print(t)

if __name__ == "__main__":
    solve()
```该实现仅保留当前时间，因为每个通道仅依赖于前一个通道。 过渡`t = max(t + 1, l[i])`对强制时间进程和车道可用的最早时间进行编码。 可行性检查`r[i]`确保我们在安全窗关闭后永远不会进入车道。 

车道 n 之后的最终增量说明移至最后一个始终安全的车道 n + 1。

 ## 边缘情况

 一个边缘情况是第一个通道已经有一个在时间 1 之后开始的窗口。对于输入`1\n5 10\n`，算法设置 t = max(1, 5) = 5，这是有效的，然后在时间 6 移动到车道 2。 

另一种情况是车道过早关闭。 为了`1\n0 0\n`，我们必须在时间 0 到达车道 1，但移动至少需要时间 1，因此计算出的时间变为 1，这违反了 r_1 = 0 并正确返回不可能。 

最终的结构边缘情况是当所有间隔都非常大时，例如`n = 100000`与所有[0, 10^12]。 该算法只是将每个通道的时间增加 1，产生 t = n + 1，而不会遇到约束，这符合不需要等待的直觉。
