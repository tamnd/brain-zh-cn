 ## 解决方案
 ## 问题理解

 我们得到了一组不同的小写字符串。 从这些字符串中，我们可以选择任何非空子集并以任何顺序排列所选字符串。 对于每个有序选择，我们通过按顺序获取每个字符串的第一个字符来形成一个新字符串，并将其连接成一个短的“缩写”。 

两个不同的有序选择可以生成相同的缩写字符串，因此每个缩写都有一个“方案计数”，表示有多少个有序选择生成它。 该任务要求计算所有可能的缩写字符串的这些方案计数的总和。 

查看该过程的另一种方法是，每个有效的构造都是通过首先选择字符串的子集然后对其进行排列来确定的。 每个产生的排列对总数的贡献恰好为 1，但不同的排列可能会折叠成相同的缩写。 该问题要求的是所有缩写词的总贡献，而不是不同缩写词的数量。 

这些约束允许最多 100000 个字符串，总长度最多为 1e6，这立即表明任何依赖于实际字符或构建显式子集的解决方案都是不可能的。 枚举子集已经给出了 2^n 种可能性，甚至限制排列也会进一步爆炸。 唯一可行的解​​决方案是将问题简化为封闭形式的组合表达式或 n 上的线性扫描。 

一个微妙的点是，除了确保每个字符串是不同的之外，字符串的实际内容不会以任何结构方式影响计数。 天真的读者可能认为第一个字母对于分组很重要，但输出要求所有结构的总和，而不是按缩写标识分组。 

一个常见的错误是尝试模拟有多少子集产生每个缩写字符串，然后对唯一的缩写进行求和。 这种方法失败了，因为在最坏的情况下，不同缩写的数量本身就是指数级的。 另一个错误是假设需要仔细跟踪第一个字母之间的冲突。 例如，如果许多字符串以相同字符开头，则可能会尝试按字符频率进行分组，但这无关紧要，因为我们不会要求不同的缩写计数，而只会对所有选择进行总方案计数。 

举一个简单的例子，如果有 3 个字符串，则正确答案是 15。简单的按缩写分组方法可能会通过跟踪每个字母模式有多少个子集而使问题变得过于复杂，但正确的解释只是计算所有可能的任意大小的有序选择。 

## 方法

 蛮力解释很简单。 我们考虑 n 个字符串的每个非空子集，然后考虑该子集的每个排列。 每个排列都贡献一个有效的构造。 对于大小为 k 的固定子集，有 k! 排列，因此大小为 k 的所有子集的总贡献为 C(n, k) · k!。 对所有 k 求和得出最终答案。 虽然这在数学上是正确的，但显式生成这些对象是不可能的，因为项数呈指数增长。 

关键的观察是该结构根本不依赖于字符串中的实际字母。 缩写操作会丢弃除第一个字符之外的所有字符，但由于我们对所有排列求和，而不管生成的缩写如何，因此每个有序选择都同样有效，并且只贡献一个字符。 因此，问题简化为对所有可能的 k 计算 n 中 k 个不同项目的所有有序选择。

对于固定的 k，此类有序选择的数量恰好是下降阶乘 n·(n − 1)·...·(n − k + 1)，通常写为 nPk。 因此，答案就是从 k = 1 到 n 的所有下降阶乘的总和。 这可以通过维持当前乘积并减少每一步的乘数来以线性时间增量计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集和排列| O(n！聚合) | O(n) | 太慢了|
 | 阶乘累积下降 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将任务重新表述为对所有子集大小的排列计数求和。 

1. 从一个表示大小为 1 的有序选择数量的运行值开始。这就是 n，因为可以单独选择 n 个字符串中的任何一个。 
2. 保持一个递减的乘数，以反映随着子集大小的增长剩余的选择数量。 选择 k − 1 个元素后，下一个选择有 (n − (k − 1)) 种可能性。 
3. 对于从 1 到 n 的每个子集大小 k，通过将先前值乘以 (n − k + 1) 来计算大小为 k 的有序选择的数量。 这将构建下降阶乘序列，而无需从头开始重新计算。 
4. 将每个计算值添加到累加器中，该累加器存储模 1e9 + 7 的最终答案。 
5. 继续，直到所有尺寸均已处理完毕。 

实现永远不需要检查字符串本身，因为所有有效的构造仅依赖于选择和排序索引。 

### 为什么它有效

 每个有效的构造都唯一对应于不同字符串的有序序列。 对于每个 k，此类序列的数量恰好是从 n 个不同元素得出的长度 k 排列的数量。 对 k 求和对每个可能的构造恰好计数一次，因为每个构造都有唯一的大小 k 并且仅包含在总和的相应项中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    
    # We only need n, strings are irrelevant
    for _ in range(n):
        input()
    
    ans = 0
    cur = 1  # will build falling factorial incrementally
    
    for k in range(1, n + 1):
        cur = cur * (n - k + 1) % MOD
        ans = (ans + cur) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()
```关键的实现思路是`cur`表示当前 k 的 nPk。 每次迭代都会乘以下一个递减因子。 这可以避免重新计算并保持解的线性。 

输入字符串被立即读取并丢弃，因为它们不影响组合计数。 唯一重要的状态是 n。 

模运算应用于每个乘法和加法步骤，以防止溢出并将值保持在范围内。

 ## 边缘情况

 一种边缘情况是当 n 等于 1 时。唯一可能的构造是选择单个字符串，因此答案必须为 1。该算法从 k = 1 开始，给出 nPk = 1P1 = 1，这直接匹配。 

另一种情况是所有字符串共享相同的第一个字母。 幼稚的方法可能会尝试按该字母进行分组，并错误地过度计数或合并贡献。 例如，对于两个字符串“aaa”和“bbb”，算法仍然将它们视为不同的项目。 计算产生 2 + 2 = 4，对应于所有有序选择，并且相同的前缀不会产生歧义。 

最后的边缘情况是 n 很大，其中中间阶乘值快速增长。 如果每次乘法时没有模运算，就会发生溢出或错误的算术。 该实现在每一步都应用模数，即使值超过典型的整数限制也能确保正确性。
