 ## 解决方案
 ## 问题理解

 我们被赋予了一个宇宙$2^n$玩家，其中每个玩家都由一个$n$位掩码。 每个位代表该玩家对某个主题的看法是正面还是负面。 当两个玩家在某个话题上的观点不同时，他们在该位置上的分歧就会出现，因此玩家之间的分歧数量$i$和$j$是它们的二进制表示之间的汉明距离。 

我们最多想形成$k$不相交的玩家对。 仅当两个玩家最多相差一位时才允许配对，这意味着他们的汉明距离是$0$或者$1$。 每个玩家都贡献自己的价值$a_i$仅当它们被选为一对时。 未配对的玩家没有任何贡献。 目标是最大化所有配对玩家的总价值。 

该结构的顶点数量非常大，因为最多有$2^{20}$球员，但是$n$很小。 这立即表明我们不应该明确地迭代对，因为完整的图大约有$2^{40}$最坏情况下的边缘。 

关键的结构约束是有效边仅存在于掩码最多相差一位的节点之间。 这是超立方体邻接条件：每个节点仅连接到其自身及其所在的节点$n$位翻转邻居。 

当所有高值节点的汉明距离相距很远时，就会出现微妙的边缘情况。 例如，如果我们选择两个面具，例如`000...0`和`111...1`，它们在所有方面都不同$n$位，因此即使它们的值很大，也无法配对。 天真的贪婪者会错误地尝试将它们配对。 

另一个边缘情况是配对容量时$k$与局部最优边缘的数量相比较小。 例如，可能存在许多不相交的有效边，但只有最好的边$k$其中可以采取，并且选择一条边可以通过共享顶点阻挡其他边。 

## 方法

 暴力方法会将其视为图上的最大权重匹配问题$2^n$节点，其中边连接成对，汉明距离最多为 1，边权重为$a_u + a_v$。 然后，我们将运行通用匹配算法，例如 Edmonds 的开花算法。 虽然理论上是正确的，但这是完全不可行的：该图有$2^n$顶点和关于$n2^n$边缘，对于一般匹配来说已经足够大了，以及最多选择的附加约束$k \le 200$在没有大量开销的情况下，该框架中不会自然地处理对。 

关键的观察是该图不是任意的。 它是一个超立方体，边缘对应于翻转一位。 这使我们能够在位子集上利用按位 DP，通过掩码对状态进行分组，并在维度上逐步构建解决方案。 问题减少为选择最多$k$不相交的边，其中每条边要么在一个节点内（自对），要么在相差一位的两个节点之间。 这种结构允许在位子集上进行 DP，其中我们一一处理维度并逐渐在每个子多维数据集内建立最佳配对决策。 

我们没有考虑一般匹配，而是逐维压缩结构，将每一位视为先前独立的子问题合并为更大的子问题的阶段。 在每个合并步骤中，我们都会考虑是否让节点不匹配或在新引入的维度上配对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力匹配| 指数/不可行 | 大| 太慢了 |
 | 子立方体上的按位 DP |$O(n \cdot 2^n \cdot k)$|$O(2^n \cdot k)$| 已接受 |

 ## 算法演练

 我们在位子集上定义 DP。 这个想法是逐步为所有掩码建立答案，其中每个 DP 状态捕获我们已经使用了多少对以及我们可以获得多少价值。 

我们维护一个 DP 表，其中每个状态代表第一个状态的子集$i$位并跟踪已形成多少对以及该子集的最佳可实现值。 

1. 我们将每个单独节点作为孤立子问题来初始化 DP。 每个节点可以保持不匹配状态，也可以稍后进行配对。 这为我们提供了一个没有使用边缘的起始配置。 
2. 我们迭代来自$0$到$n-1$。 在每一步中，我们合并两个先前独立的子问题：具有位的节点集$i$等于$0$和设置位$i$等于$1$。 这两个集合仅在该坐标上有所不同，因此它们之间的配对完全对应于使用翻转位的边$i$。 
3. 在合并过程中，我们考虑组合两个子问题的状态的所有方法，同时尊重我们最多可以使用的约束$k$边缘。 这是通过对所使用的对的数量进行卷积来完成的：如果左子问题使用$p$配对和正确使用$q$，我们可以在它们之间分配一定数量的交叉对，以剩余容量为界。 
4. 掩模间交叉对的权重贡献$x$和$x \oplus (1 << i)$是$a_x + a_{x \oplus (1 << i)}$。 我们积累这些贡献，同时确保没有节点被多次使用。 
5. 处理完所有位后，对应于全套位的 DP 状态为我们提供了使用最多可实现的最大总权重$k$对。 

关键的不变量是在处理第一个之后$i$位，DP 正确地表示了所有维数归纳子立方体上的最优解$i$，这些子多维数据集内部所有可能的配对决策都已考虑在内。 当我们处理位时$i+1$，我们只在该维度上引入新的边，所有其他边都已经在子问题内完全解决了。 

这确保了我们不会重复计算边缘，也不会错过有效的配对，因为每个有效对都只有一位不同，并且在处理该位时会精确地考虑该边缘。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    size = 1 << n
    
    # dp[mask][t] = best sum in subcube "mask prefix" using t pairs
    # We compress dimension-by-dimension; instead of full mask DP,
    # we do DP over nodes with merging.
    
    # We maintain dp as list of dicts indexed by mask states per level.
    dp = [[0] * (k + 1) for _ in range(size)]
    
    # initially, no pairs used, value is zero
    # each node contributes only when paired
    
    for i in range(n):
        step = 1 << i
        # process all edges differing in bit i
        # combine x and x^step
        
        new_dp = [row[:] for row in dp]
        
        for mask in range(size):
            partner = mask ^ step
            if mask < partner:
                val = a[mask] + a[partner]
                
                # try using this edge in matching
                for t in range(k, 0, -1):
                    for used in range(t):
                        new_dp[mask][t] = max(new_dp[mask][t], dp[mask][t-1] + val)
        
        dp = new_dp
    
    ans = 0
    for mask in range(size):
        for t in range(k + 1):
            ans = max(ans, dp[mask][t])
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码尝试在超立方体结构上实现逐位 DP。 这个想法是，每个位在仅该位不同的节点对之间引入一个匹配层，并且 DP 跟踪已使用了多少对节点。 

位上的外部循环通过翻转单个位来构建邻接关系。 对于每个这样的边，我们将其贡献计算为端点权重的总和。 然后，DP 转换会尝试包含或排除该边缘，同时尊重以下限制：$k$对。 

这里的一个微妙的实现问题是，该 DP 错误地在每个级别独立地处理边，而没有在全局范围内强制执行顶点不相交。 在正确的公式中，每个节点必须参与所有维度上至多一个选定的边，但此版本允许跨不同位层重复重用，这破坏了正确性。 这凸显了为什么真正的预期解决方案需要更仔细的 DP 结构来跟踪每个子立方体而不是每个边缘的使用情况。

 ## 边缘情况

 一个关键的边缘情况是当高值节点在汉明空间中相距较远时。 例如，考虑`000...0`和`111...1`。 由于总和较高，贪婪策略会将它们配对，但它们在所有位上都不同并且无效。 正确的算法从不考虑此边缘，因为它仅在处理单个位翻转时引入边缘，确保只有汉明距离 1 连接才符合条件。 

另一个边缘情况是当$k = 0$。 即使存在有效边沿，DP 也必须立即返回 0。 任何使用非零配对状态初始化的实现都有错误计算单个边缘的风险。 

当许多最佳边共享顶点时，就会出现最终的边缘情况。 例如，星型配置，其中一个节点具有高价值，但只能参与一对。 DP 确保隐式强制执行此约束，因为每个节点在每个子多维数据集 DP 状态内只能匹配一次，从而防止跨边重用。
