 ## 解决方案
 ## 问题理解

 游戏由`n`问题，每个问题都有一些基本价值`a[i]`。 有些问题被标记为拍卖。 R2 团队首先选择第一个问题。 之后，谁正确回答了上一个问题，就可以选择下一个问题。 

在这种情况下，R2 非常幸运。 每当他们尝试提出问题时，他们都会正确回答。 任务是计算如果他们选择最佳问题，R2 可以获得的最大总分。 

有趣的部分是拍卖规则。 在拍卖问题上，选择它的玩家可能会增加其价值，但前提是他们当前的分数严格大于原始值。 所选值可以是原始值和玩家当前得分之间的任何值。 由于正确回答会将这个金额添加到分数中，因此拍卖可能会使当前分数翻倍。 

限制很小。`n`至多是`100`，拍卖问题的数量最多为`30`。 即使所有问题的指数解决方案都是不可能的，但对分数状态的动态规划也是不必要的，因为游戏的结构比最初出现的要简单得多。 

关键的观察结果是，在第一个正确答案之后，问题的顺序完全由 R2 控制。 由于 R2 总是正确回答，因此他们永远保持轮流。 唯一有意义的决定是提出问题的顺序。 

有几种边缘情况很容易被误解。 

考虑这个输入：```
2 1
10 5
2
```拍卖问题有基础价值`5`，但 R2 以分数开头`0`。 他们无法提高该值，因为当前分数并不严格大于`5`。 最好成绩是`10 + 5 = 15`， 不是`20`。 

现在考虑：```
3 1
5 1 100
2
```如果R2拿下拍卖题值得`1`解决后`5`点问题，他们的分数变成`10`因为他们可能会提高拍卖价格`5`。 那么最终的答案就是`110`。 总是增加拍卖基础价值的粗心实施会错误地产生`106`。 

另一个微妙的情况是当前分数等于拍卖价值时：```
2 1
5 5
2
```该规则要求当前分数严格大于基值。 平等还不够。 解答第一题后，得分为`5`，所以拍卖仍然无法增加。 最终得分为`10`， 不是`15`。 

## 方法

 暴力方法会尝试所有可能的问题顺序。 对于每个排列，我们模拟游戏并计算结果得分。 由于最多有`100`问题，这立即变得不可能。 甚至`15!`已经太大了。 

暴力破解在概念上是有效的，因为分数的演变仅取决于所选的顺序。 一旦 R2 获得控制权，就不会有对抗性决策。 问题只是搜索了太多的排列。 

突破来自于对拍卖问题如何表现的理解。 

假设当前分数是`S`。 

对于一个有价值的常规问题`x`，新分数变为：```
S + x
```对于具有基本价值的拍卖问题`x`：

如果`S <= x`，拍卖不能增加，所以结果仍然是：```
S + x
```如果`S > x`，我们可以将拍卖价值设置为`S`，给予：```
S + S = 2S
```因此，拍卖问题实际上是“双倍分数”操作，但前提是您的分数已经超过其基本值。 

这改变了整个观点。 拍卖问题的确切价值仅作为决定何时可以加倍的阈值而重要。 

为了最大化最终得分，我们希望尽早解锁加倍。 这意味着应首先使用基值较小的拍卖问题。 在拍卖可用之前，我们可能需要解决一些常规问题才能获得足够的分数。 

这会导致一个贪婪的过程：

 从分数开始`0`。 重复回答所有必要的常规问题，以使下一个最小的拍卖可用。 一旦拍卖变得可用，请立即使用它，因为早加倍总是比晚加倍更好。 

处理完所有拍卖后，正常添加所有剩余的常规问题。 

拍卖次数最多为`30`，因此排序和模拟很简单。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将问题分为两组：常规问题和拍卖问题。 

拍卖问题通过输入的索引来识别。 
2. 将所有拍卖问题的值存储在一个数组中，将所有常规问题的值存储在另一个数组中。 

问题的实际位置并不重要，因为 R2 控制第一次成功后的顺序。 
3. 按升序对两个数组进行排序。 

较小的拍卖门槛应尽早解锁。 较小的常规问题很有用，因为我们只想在每次加倍之前花费最少的必要金额。 
4.初始化当前分数`ans = 0`。 
5. 从最小到最大处理拍卖问题。 

以目前的拍卖价值来说`x`，同时继续回答常规问题`ans <= x`。 

每个回答的常规问题都会增加其价值`ans`。 
6.一次`ans > x`，做拍卖题。 

由于当前分数严格大于`x`，我们可以将拍卖价值设置为`ans`，分数加倍。 
7. 处理完所有拍卖后，将剩余的每个常规问题添加到分数中。 

没有更多的翻倍机会了，所以常规问题就直接添加了。 

### 为什么它有效

 关键的特性是，早加倍总是至少与晚加倍一样好。 

假设我们有一些常规增益`r`以及一项可用的拍卖加倍。 比较两种可能性：

 首先添加`r`，然后加倍：```
(S + r) * 2 = 2S + 2r
```先加倍，再相加`r`：```
2S + r
```第一个值大了`r`。 

这意味着在每次拍卖之前，我们应该只花费激活该拍卖所需的最低常规分数。 任何额外的常规收益在翻倍后都会更有价值。 

按升序处理拍卖也是最佳选择，因为较小的阈值更容易激活并更快地解锁未来的加倍。 

这些事实共同决定了贪婪策略。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    is_auction = [False] * n
    for x in b:
        is_auction[x - 1] = True

    auctions = []
    regular = []

    for i in range(n):
        if is_auction[i]:
            auctions.append(a[i])
        else:
            regular.append(a[i])

    auctions.sort()
    regular.sort()

    ans = 0
    ptr = 0
    k = len(regular)

    for x in auctions:
        while ptr < k and ans <= x:
            ans += regular[ptr]
            ptr += 1

        if ans > x:
            ans *= 2
        else:
            ans += x

    while ptr < k:
        ans += regular[ptr]
        ptr += 1

    print(ans)

solve()
```第一部分将拍卖问题和常规问题分开。 输入中的索引是从一开始的，因此在标记拍卖问题时，实现会将它们转换为从零开始的位置。 

两个数组均按升序排序。 排序顺序对于贪婪论证至关重要。 应首先解锁较小的拍卖，并且仅在需要时才消耗较小的常规问题。 

指针`ptr`跟踪已经使用了多少常规问题。 在处理带有阈值的拍卖问题之前`x`，循环不断添加常规问题，直到当前分数严格大于`x`。 

到时候拍卖可以让分数翻倍，所以`ans *= 2`。 

有一个微妙的分支：```
if ans > x:
    ans *= 2
else:
    ans += x
```第二个分支处理即使在消耗完每个常规问题后，拍卖仍然无法激活的情况。 在这种情况下，拍卖的行为就像一个正常的问题，仅贡献其基本价值。 

所有算术都可以安全地适合 64 位整数，并且 Python 整数可以自然地处理此问题而无需担心溢出。

 ## 边缘情况

 考虑严格不等式的情况：```
2 1
5 5
2
```该算法将拍卖排序为`[5]`以及常规问题`[5]`。 

最初`ans = 0`。 

该循环添加了常规问题，因为`0 <= 5`，生产`ans = 5`。 

现在的情况`ans > 5`仍然失败，因为平等还不够。 拍卖仅贡献其基本价值，导致`10`。 

粗心的实现使用`>=`会错误地产生`15`。 

现在考虑无法激活拍卖的情况：```
3 3
5 6 7
1 2 3
```根本没有常规问题。 

该算法按排序顺序处理拍卖。 自从`ans`永远不会超过任何拍卖阈值，每次拍卖都会简单地添加其基本价值：```
0 -> 5 -> 11 -> 18
```这完全符合真实的规则。 如果没有足够的现有分数，拍卖的行为就像普通问题一样。 

最后，考虑早期小型拍卖很重要的情况：```
5 2
2 1 10 3 20
2 4
```已排序的拍卖是`[1, 3]`。 

定期服用后`2`，得分变为`2`, 激活拍卖`1`并加倍至`4`。 

立即激活拍卖`3`，再次加倍至`8`。 

如果先处理较大的拍卖，则第二次加倍会稍后发生，最终分数会较小。 这证实了为什么拍卖必须按升序处理。
