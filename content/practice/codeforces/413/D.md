 ## 解决方案
 ## 问题理解

 我们处理一系列图块，每个图块要么是`2`或者`4`。 一块瓷砖从最右边开始并向左滑动。 当它触及相等的值时，两者合并成双倍的值，并且新的图块继续移动。 这是与普通 2048 的关键区别，合并可以在一次移动期间链接。 

我们给出了一个部分指定长度的序列`n`。 一些位置固定为`2`或者`4`，还有一些是`0`，这意味着我们可以选择`2`或者`4`那里。 我们必须计算有多少次完成至少产生了一块具有至少价值的图块`2^k`。 

这些约束完全决定了我们需要什么样的解决方案。 序列长度达到`2000`，所以任何指数`n`是不可能的。 对所有替代品的暴力破解已经达到`2^2000`。 即使维度过多的状态 DP 也会失败。 

有趣的是`k ≤ 11`。 目标图块最多为`2^11 = 2048`，这意味着仅合并级别达到`11`事情。 这个小界限建议将板状态压缩为位掩码或小 DP 状态。 

一个微妙的点是该条带是如何演变的。 由于合并的图块会继续移动，因此最终的条带始终表现得像二进制进位。 

例如：```
2 2 2
```不会变成：```
4 2
```反而：```
2 -> 4
4 + 2 -> 4 2
```最终状态是`4 2`。 

另一个容易犯的错误是假设具有相同功率的图块的顺序并不重要。 确实如此。 

例子：```
2 4 2 2
```的演变不同于：```
2 2 4 2
```因为合并发生在插入期间。 

当获胜牌仅在长进位链之后形成时，会出现另一种边缘情况。 

例子：```
2 2 2 2
```其过程是：```
2
4
4 2
8
```每次插入仅合并一次的幼稚模拟将错误地停止在`4 4`。 

输出要求有效替换数取模`10^9 + 7`，因此整个 DP 中必须在模运算下进行计数。 

## 方法

 最直接的解决办法就是暴力破解。 更换每个`0`与两者`2`和`4`，模拟整个游戏，检查是否至少有一个方块`2^k`出现。 

模拟本身很容易。 该条带的行为与二进制加法完全相同。 如果我们编码`2^1`作为水平`1`,`2^2`作为水平`2`，依此类推，然后插入一个级别就像向带进位的二进制计数器加一一样。 

例如，插入一个`2`表示在 level 添加一个 token`1`。 如果水平`1`已经存在，它们合并到关卡中`2`，并且继续进位。 

暴力破解是正确的，因为它确实遵循游戏规则。 问题在于复杂性。 至多有`2000`未知位置，我们需要检查`2^2000`序列。 

关键的观察结果是棋盘状态很小。 

任何时刻，对于以下每个级别`k`，只有奇偶性才重要。 两个相等的图块立即向上合并，因此一个级别最多可以包含一个图块。 这意味着整个相关板可以由大小的位掩码表示`k`。 

如果位`i`设置后，则该条带当前包含一个图块`2^i`。 

现在插入图块变成了这个掩码上的进位过程：```
while bit exists:
    remove bit
    carry upward
set first empty bit
```如果进位达到水平`k`或更高，我们已经赢了。 

这将问题转化为基于前缀和掩码的 DP 问题。 

让：```
dp[pos][mask]
```是处理第一个的方法的数量`pos`元素并以棋盘状态结束`mask`没有产生过`2^k`。 

口罩数量仅`2^k ≤ 2048`，并且每次转换成本最多`k`携带步骤。 

总复杂度变为：```
O(n * 2^k * k)
```这是周围`2000 * 2048 * 11 ≈ 4.5e7`原始操作，在经过仔细实现的优化 Python 中是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^z · n · k) | O(2^z · n · k) | O(k) | 太慢了 |
 | 最佳 | O(n·2^k·k) | O(n·2^k·k) | O(2^k) | O(2^k) | 已接受 |

 这里`z`是零的数量。 

## 算法演练

 1. 用指数代表每个图块。 

我们绘制地图：```
2 -> 1
4 -> 2
```目标正在达到指数`k`。 
2. 将条带状态表示为位掩码。 

少量`i`意思是一块瓷砖`2^i`存在。 我们只存储级别`0..k-1`。 任何超出这个范围的进展都意味着成功。 
3. 定义转换函数。 

假设我们插入级别`x`。 

从点滴开始`x`。 

虽然该位已经存在于掩码中：

 - 取下钻头，
 - 增量`x`,
 ——继续向上。 

当发现空位时：

 - 将钻头放在那里。 

如果`x >= k`，那么该序列已经获胜。 
4. 建立针对仓位的动态规划。 

让：```
dp[mask]
```存储处理某些前缀后到达此掩码的方法数，但仍然没有获胜。 
5. 从左到右处理序列。 

对于每个位置：

 - 如果该值固定为`2`, 只插入指数`1`,
 - 如果固定为`4`, 只插入指数`2`,
 - 如果是的话`0`，两者都尝试一下。 
6. 应用过渡。 

对于每个当前掩码和每个允许的插入：

 - 使用进位过程计算下一个掩码，
 - 如果进位达到指数`k`，将当前计数直接添加到答案中，
 - 否则更新下一个DP层。 
7. 对所有运算取模`10^9 + 7`。 

### 为什么它有效

 不变的是，假设没有级别的瓦片，每个 DP 状态在处理某些前缀后精确地表示唯一的条带配置`k`或更大的已经出现。 

携带过程与游戏机制完全匹配。 两个相等的方块合并并继续移动，这与带进位的二进制加法相同。 由于稳定后每个级别最多可以包含一个图块，因此位掩码表示是无损的。 

序列的每一个可能的完成都精确地遵循一个 DP 转换链，并且每个 DP 转换对应于一​​个合法的游戏演化。 该算法既不会遗漏序列，也不会对任何序列进行两次计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1 << k

    # trans[level][mask] = next_mask
    # if next_mask == -1, reaching >= 2^k occurs
    trans = [[0] * size for _ in range(3)]

    for level in (1, 2):
        for mask in range(size):
            x = level
            cur = mask

            while x < k and (cur >> x) & 1:
                cur ^= (1 << x)
                x += 1

            if x >= k:
                trans[level][mask] = -1
            else:
                trans[level][mask] = cur | (1 << x)

    dp = [0] * size
    dp[0] = 1

    ans = 0

    for val in a:
        ndp = [0] * size

        if val == 0:
            options = [1, 2]
        elif val == 2:
            options = [1]
        else:
            options = [2]

        for mask in range(size):
            ways = dp[mask]
            if not ways:
                continue

            for level in options:
                nxt = trans[level][mask]

                if nxt == -1:
                    ans = (ans + ways) % MOD
                else:
                    ndp[nxt] = (ndp[nxt] + ways) % MOD

        dp = ndp

    print(ans % MOD)

solve()
```实现中的第一个重要思想是将值转换为指数。 与...一起工作`1`和`2`而不是`2`和`4`使搬运处理变得自然。 

转换表是在 DP 启动之前预先计算的。 这消除了主循环内重复的进位模拟。 由于只有两种插入类型并且最多`2048`掩模，预处理很便宜。 

进位模拟修改临时掩码`cur`。 每当一个位已经存在时，我们就将其删除并向上携带。 这与游戏中的重复合并完全匹配。 

一个微妙的实现细节是处理获胜状态。 我们从不储存含有水平的面具`k`，因为一旦出现这样的图块，序列就已经成功了。 这些转变直接有助于`ans`。 

DP本身使用滚动阵列。 只有前一层很重要，因此保留两个数组就足够了。 

另一个容易出错的细节是位的索引。 少量`1`代表瓷砖`2`，和位`2`代表瓷砖`4`。 少量`0`未使用，这简化了幂和指数之间的映射。

 ## 边缘情况

 考虑：```
4 4
2 2 2 2
```每次插入仅合并一次的有缺陷的实现将停止在：```
4 4
```并错误地得出失败的结论。 

我们的转换模拟继续向上进行，直到出现空水平：```
2 + 2 -> 4
4 + 4 -> 8
8 + 8 -> 16
```因此 DP 正确地将这个序列视为获胜。 

现在考虑：```
3 3
2 4 2
```该过程变为：```
2
4
4 2
```不`8`出现。 

但：```
3 3
4 2 2
```变成：```
4
4 2
8
```尽管两者都包含两个，但答案不同`2`s 和一`4`。 由于 DP 严格按顺序处理插入，因此它正确地保留了这种区别。 

最后，考虑：```
2 3
4 4
```第一个`4`创建指数`2`。 第二次插入立即发生碰撞并进位到指数`3`，已经达到目标了。 

我们的转换表用以下方式标记此类转换`-1`，DP 直接将它们添加到最终答案中，而不是存储无效的掩码。
