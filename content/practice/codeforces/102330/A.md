 ## 解决方案
 ## 问题理解

 我们有一个数组`a`的`n`动物。 价值`a[i]`是 Aibolit 医生检查动物所需的时间`i`。 医生一次处理一只动物，因此动物会排成一队。 

对于选定的订单，第一只动物等待`0`时间单位。 第二个等待第一只动物的完整检查。 第三次等待前两次检查，依此类推。 我们需要选择数组元素的顺序，以使所有等待时间的总和尽可能小。 

例如，如果考试时间是`[5, 1, 2]`我们使用顺序`[1, 2, 5]`，等待时间为`0`,`1`， 和`3`，总共给出`4`。 

动物数量可达`10^6`，而每次考试时间最多为`10^5`。 诸如以下的算法`O(n^2)`已经需要大约`10^12`最坏情况下的操作，远远超出一秒的限制。 甚至`O(n log n)`必须相当有效地实现，因为输入本身包含一百万个数字，但它很容易实现。 答案可能比 32 位整数大得多：如果全部`10^6`考试时间相等`10^5`，答案是关于`5 * 10^16`。 Python 整数会自动处理这个问题。 

有几个小案例可以暴露错误。 例如，对于一只动物，输入是```
1
7
```答案是`0`，因为没有人等待。 在累积答案之前添加当前考试时间的实现会错误地产生`7`。 

在相同的检查时间下，每个订单都是等效的。 为了```
5
2 2 2 2 2
```等待时间是`0, 2, 4, 6, 8`，所以答案是`20`。 在这种情况下，意外按降序排序的解决方案不会失败，这使得相等的值可用于检查公式本身是否正确，而不是仅依赖于排序。 

另一个常见的边缘情况是，最短的动物必须首先处理，即使它出现在输入中较晚。 为了```
3
7 1 2
```最优顺序是`1, 2, 7`，给出等待时间`0, 1, 3`并回答`4`。 简单地按照输入顺序处理动物就可以得到`0 + 7 + 8 = 15`，因此从不对数组重新排序的实现会立即失败。 

## 方法

 直接的暴力方法会尝试动物的每一种可能的顺序。 对于每个排列，我们可以从左到右扫描它，保留已执行的总检查时间，并将该值添加到每只动物的答案中。 这是正确的，因为考虑了所有可能的时间表，并且我们可以选择等待时间总和最小的一个。 

问题是排列的数量。 有`n!`可能的订单，评估一个订单需要`O(n)`时间，所以总复杂度为`O(n · n!)`。 即使是为了`n = 20`，这已经是巨大的了。 为了`n = 10^6`，它不仅太慢，而且无法开始枚举时间表。 

等待时间的结构给了我们更强有力的观察。 假设两个连续的动物有检查时间`x`和`y`，而他们面前的一切都已被夺走`T`时间。 如果订单是`x, y`，他们对总等待时间的贡献是`T + (T + x) = 2T + x`。 

如果我们将它们交换为`y, x`，他们的贡献变成`T + (T + y) = 2T + y`。 

差异仅取决于`x`和`y`。 如果`x > y`, 投入`y`首先使总数变小。 因此，每当较长的考试紧接在较短的考试之前时，交换它们可以改善时间表。 

通过重复消除这种倒置，考试时间就按非降序排列。 由于每次反转只会使答案变得更糟，因此通过将数组从小到大排序来获得最佳调度。 

一旦知道顺序，就不需要显式存储每个等待时间。 维持`prefix`，已处理的所有动物的总检查时间。 当前动物正在等待`prefix`时间单位，所以加上`prefix`到答案然后增加`prefix`截至当前考试时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n · n!)`|`O(n)`| 太慢了 |
 | 最佳|`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 阅读`n`和`n`检查时间放入数组中。 原始位置并不重要，因为目标只是找到最佳排序。 
2. 按非降序对数组进行排序。 应尽早进行较短的检查，因为检查后的每只动物都会受益于较少的等待时间。 
3. 初始化`prefix = 0`和`answer = 0`。 这里`prefix`代表已经放置在当前动物之前的所有动物的总检查时间。 
4. 从左到右遍历排序后的数组。 目前考试时间`x`， 添加`prefix`到`answer`，因为正是`prefix`在该动物可以进入医生办公室之前已经经过了时间单位。 
5. 添加`x`到`prefix`。 当前的动物现已被处理，因此其检查时间成为后续每只动物的等待时间的一部分。 
6. 所有动物处理完毕后，输出`answer`。 第一只动物的贡献为零，因为`prefix`最初为零。 

### 为什么它有效

 考虑包含两个相邻考试时间的任何时间表`x`和`y`和`x > y`。 这两只动物之前的一切都需要一些固定的数量`T`。 按顺序`x, y`，他们的总贡献是`2T + x`，同时按顺序`y, x`这是`2T + y`。 自从`y < x`，交换它们严格减少了总等待时间。 

因此，最佳调度不能包含相邻的反转。 如果数组未排序，则它会发生反转，并且重复交换反转的相邻对最终会产生非递减顺序，而不会增加答案。 因此排序的顺序是最优的。 排序后，前缀总和恰好等于当前每个动物的等待时间，因此将其累加会产生最小可能的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    prefix = 0
    answer = 0

    for x in a:
        answer += prefix
        prefix += x

    print(answer)

if __name__ == "__main__":
    solve()
```前两行读取动物数量和检查时间。 此问题中只有一个测试用例，因此不需要外部测试用例循环。`a.sort()`将考试时间按照所需的最短优先顺序排列。 Python 的内置排序运行在`O(n log n)`时间并且对于一百万个整数来说足够有效地实现。 

循环故意添加`prefix`到`answer`在添加当前的之前`x`到`prefix`。 这个顺序是必要的。 当前的动物不等待它自己的检查，它只等待它之前的动物的检查。 对于数组`[1, 2, 3]`，用于答案的前缀序列是`0, 1, 3`， 不是`1, 3, 6`。 

Python 的整数类型也避免了溢出。 最大可能的答案大约是`5 * 10^16`，这将超过有符号的 32 位整数，但 Python 准确地表示了此类值。 

输入尺寸较大，因此解决方案使用`sys.stdin.readline`按要求。 内存使用主要是存储一百万个元素的数组。

import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    prefix = 0
    answer = 0

    for x in a:
        answer += prefix
        prefix += x

    print(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("5\n2 2 2 2 2\n") == "20", "sample 1"
assert run("5\n5 1 2 7 3\n") == "21", "sample 2"

# Minimum-size input
assert run("1\n7\n") == "0", "one animal waits zero time"

# Already sorted, checks that the prefix is added before the current duration
assert run("3\n1 2 3\n") == "4", "already sorted input"

# Reverse order, checks that sorting is actually performed
assert run("3\n7 2 1\n") == "4", "reverse order"

# All values at the maximum boundary
assert run("4\n100000 100000 100000 100000\n") == "600000", "maximum ai"

# Large n and large values, checks that the answer exceeds 32-bit range
assert run("1000000\n" + "100000 " * 1000000) == "49999950000000000", "maximum n"

## 边缘情况

 对于一只动物，输入```
1
7
```排序不变。 循环开始于`prefix = 0`，所以得到的答案是`0`。 然后`prefix`变成`7`，但没有下一个动物可以等待它。 输出是`0`。 

在考试时间相同的情况下，```
5
2 2 2 2 2
```每种可能的排序都有完全相同的结果。 该算法处理五个值并添加前缀`0, 2, 4, 6, 8`，生产`20`。 对于相等的值没有特殊处理，因为交换参数仅要求严格较长的检查不能先于较短的检查。 

对于最短的动物最后出现的输入，```
3
7 1 2
```排序将顺序更改为`1, 2, 7`。 前缀是`0, 1, 3`，所以答案是`4`。 原始订单将产生`15`，演示为什么保留输入顺序无效。 

为了获得最大的考试时间，```
4
100000 100000 100000 100000
```前缀是`0, 100000, 200000, 300000`, 给予`600000`。 这些值本身很适合普通整数范围，但累积的答案增长得更快。 

为了获得最大数量的动物和最长的检查时间，除了第一只动物之外的每只动物都等待增加的倍数`100000`。 结果总和是`100000 * (0 + 1 + 2 + ... + 999999) = 49999950000000000`。 

该实现直接使用前缀和不变量来计算，没有模拟单个时间单位，也没有二次行为。
