 ## 解决方案
 ## 问题理解

 我们得到一个写成十进制数字序列的任务编号。 分割会在数字之间选择多个剪切位置，因此每个结果片段都被解释为单独的任务编号。 一个有效的片段必须满足两个条件：它的十进制表示最多有`k`数字，其数值为质数。 禁止使用前导零，因此诸如`03`即使其数值为 3，也是无效的。 

目标是计算所有可能的切割方式，以便所有生成的片段都是有效的。 即使某些片段具有相同的数值，不同的剪切位置也会产生不同的分解。 答案以模数形式打印`10^9 + 7`。 

输入绑定`|n| <= 10^6`对于数字分区问题来说是非常有限制的。 绝对值最多有七位小数，而`k <= 6`。 这意味着最多有六个可能的剪切位置，因此最多有`2^6 = 64`完整的分区。 暴力解决方案对于这些限制来说已经足够小了。 尽管如此，相同的递归可以编写为动态程序，以避免重新计算相同的前缀状态，并且如果增加数字长度，则可以更好地扩展。 

构造数字字符串时使用绝对值。 减号不是数字，不能参与十进制任务编号，因此拆分的有意义的表示是`|n|`。 

在一些小情况下，粗心的实施可能会失败。 用于输入`2`和`k = 1`，答案是`1`，因为整个任务编号是素数 2。从 2 开始素数测试并意外需要除数的实现可能会拒绝这种情况。 

用于输入`11`和`k = 1`，答案是`0`。 每个一位数的部分是`1`，这不是素数。 将除零之外的每个数字都视为可能的素数的解决方案将错误地返回`1`。 

用于输入`103`和`k = 2`，答案是`0`。 唯一可能的两位数前缀是`10`，而剩下的数字是`3`;`10`不是素数。 另一种选择`1|03`被禁止是因为`03`有一个前导零。 在检查之前将每个子字符串直接转换为整数的解决方案将默默地接受这种无效的表示形式。 

用于输入`23`和`k = 2`，答案是`2`。 两个都`23`本身和`2|3`是有效的。 仅考虑长度精确的片段的解决方案`k`，或者忘记允许使用更短的最终片段，错过这些分解之一。 

## 方法

 直接的方法是枚举每一个可能的割集。 和`L`数字有`L - 1`间隙，并且每个间隙可以包含切口，也可以不包含切口，给出`2^(L-1)`分区。 对于每个分区，我们检查每个生产的工件，拒绝长度超过的工件`k`，拒绝前导零，并测试剩余值的素数。 这是正确的，因为每种可能的分解都恰好对应于间隙的一个子集，因此枚举既不会错过也不会重复分解。 

在实际约束下`L <= 7`，这种蛮力永远不会变得太慢。 完整分区最多有 64 个，每个分区最多有 7 个片，因此最多有 448 个片检查。 由于每个被检查的数字最多有六位数字，因此试除法每件需要的除数测试少于 1000 次。 由此产生的最坏情况上限约为 448,000 次基本除数检查，这很容易管理。 因此，暴力方法已经被接受来解决这个问题。 

更可重用的方法是观察可以从左到右构建分解。 假设第一个`i`数字已经被分割成有效的质数部分。 我们只需要决定下一个有效的棋子。 最多有`k`下一块的可能长度，这样我们就可以从位置过渡`i`到职位`i + 1`通过`i + k`。 这给出了一个一维动态程序。 

让`dp[i]`是第一个的有效分解的数量`i`数字。 最初`dp[0] = 1`，代表空前缀。 对于每个可达到的位置`i`，我们取下一个，两个，直到`k`数字。 如果生成的子字符串没有前导零并且表示素数，则它贡献`dp[i]`方法`dp[j]`， 在哪里`j`是紧接在该子字符串之后的位置。 

暴力方法之所以有效，是因为剪切位置的数量很少，但它会重复探索相同的有效前缀。 观察到每个分解都是数字位置之间的有效转换序列，这让我们可以将所有这些重复的前缀合并到单个 DP 状态中。 

这里的素性测试不需要大筛子。 最多有`7 * 6 = 42`DP考虑不同的子串候选，每个候选最多有六位数字。 试除平方根已经足够快了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^L * L * sqrt(10^k))`|`O(L)`| 接受为`L <= 7`|
 | 最佳|`O(L * k * sqrt(10^k))`|`O(L)`| 已接受 |

 这里`L`是数字的个数`|n|`。 DP 是更可取的，因为如果输入长度增加，其结构仍然有用，而实现仍然很小。 

## 算法演练

 1. 阅读`n`和`k`，并转换`abs(n)`到一个字符串`s`。 需要字符串表示形式，因为拆分是在十进制数字之间执行的，而不是根据数值算术执行的。 
2. 定义正整数的素性测试。 小于 2 的值将被拒绝。 对于至少为 2 的值，测试能否被整数整除到其平方根。 如果找不到约数，则该值为素数。 
3. 创建数组`dp`长度`len(s) + 1`并设置`dp[0] = 1`。 国家`dp[i]`意味着第一个`i`数字已经可以完全分成有效的部分`dp[i]`不同的方式。 
4. 从左到右处理位置。 如果`dp[i]`为零，没有有效的分解到达这个位置，所以没有什么可以从它延伸。 
5. 从位置`i`，尝试从 1 到`k`，停在字符串的末尾。 这涵盖了最大长度限制允许的每个可能的下一个片段。 
6. 当候选人的第一位数字为 时，立即拒绝该候选人`0`。 这样的子字符串将有一个前导零，并且不能表示有效的任务编号。 
7. 将候选子串转换为整数并测试其是否为素数。 如果是质数，则添加`dp[i]`到候选者末尾对应的状态。 这种转变意味着前缀的每个有效分解都可以通过这个特定的素数片段来扩展。 
8. 所有仓位处理完毕后，返回`dp[len(s)]`。 此状态精确计算消耗每个数字的分解，因此答案中不包含未完成的前缀。 

### 为什么它有效

 不变的是处理后的位置`i`,`dp[i]`恰好包含第一个的有效分解数`i`数字。 每一个这样的分解都有一个独特的最终作品。 删除最后一块会留下一些早期位置的有效分解`j`，并且被移除的部分正是从 的过渡考虑的子串之一`j`到`i`。 相反，算法接受的每个转换都会将有效的质数部分附加到已经有效的分解中。 因此，每个计数的分解都是有效的，并且每个有效的分解都只计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def is_prime(x):
    if x < 2:
        return False
    if x == 2:
        return True
    if x % 2 == 0:
        return False

    d = 3
    while d * d <= x:
        if x % d == 0:
            return False
        d += 2
    return True

def solve():
    n = int(input())
    k = int(input())

    s = str(abs(n))
    m = len(s)

    dp = [0] * (m + 1)
    dp[0] = 1

    for i in range(m):
        if dp[i] == 0:
            continue

        value = 0

        for length in range(1, k + 1):
            j = i + length
            if j > m:
                break

            if length > 1 and s[i] == '0':
                break

            value = value * 10 + (ord(s[j - 1]) - ord('0'))

            if is_prime(value):
                dp[j] = (dp[j] + dp[i]) % MOD

    print(dp[m])

if __name__ == "__main__":
    solve()
```这`is_prime`功能句柄`0`和`1`在测试可分性之前，并处理`2`分开，以便偶数捷径不会拒绝最小的素数。 之后，只需要考虑奇数除数。 

DP 使用`dp[0] = 1`作为空前缀基本情况。 如果没有这个值，有效的第一部分将没有状态来接收其贡献。 

候选值是增量构造的，而不是重复转换子字符串。 例如，当从位置延伸时`i`，值`3`,`37`， 和`377`相继获得。 这对于转换循环来说既简单又避免了不必要的字符串切片。 

在接受多位候选值之前，有意执行前导零检查。 一位数`0`也自然被拒绝`is_prime`， 所以`0`不需要单独的特殊情况。 如果`s[i] == '0'`，从那里开始的子字符串不再有效，因为每个更长的子字符串仍然会有前导零。 这就是循环可以立即停止的原因。 

最长的候选者最多有六位数字，所以`value`至多是`999999`。 Python 整数在这里不存在溢出问题，并且每个 DP 转换的模运算都遵循所需的输出约定，即使该问题的实际分解次数最多为 64。

 ## 边缘情况

 对于`2`和`k = 1`，DP 开始于`dp[0] = 1`。 它形成了候选人`2`， 和`is_prime(2)`返回 true，所以`dp[1]`变为1。最终答案是`1`。 素性测试中对 2 的特殊处理可防止将其错误地拒绝为偶数。 

为了`11`和`k = 1`，唯一的候选者是两个单独的数字`1`和`1`。 两者均未通过`x < 2`条件在`is_prime`，因此没有任何转换到达位置 1 或位置 2。最终答案是`0`。 

为了`103`和`k = 2`，第一个位置允许`1`和`10`，两者都不是素数。 从位置 1 开始的转换将从数字开始`0`，但由于它是多位候选，因此前导零检查会立即停止循环。 不能使用完整的数字，因为它的长度是三，而`k = 2`。 答案是`0`。 

为了`23`和`k = 2`，第一个位置产生两个`2`和`23`。 第一个转换给出`dp[1] = 1`，而第二个给出`dp[2] = 1`。 从位置1开始，剩余的`3`是素数，所以另一种方式达到`dp[2]`。 最终状态包含`2`，完全匹配两个有效的分解。 

为了`1000000`和`k = 6`，每个从第一个数字开始的候选者都是`1`,`10`,`100`， 等等。 仅有的`1`可能是有效分解的前缀，但它不是素数。 一旦DP达到零数字，从那里开始就没有有效的多数字部分，并且零本身不是素数。 没有过渡到达最终位置，所以答案是`0`。
