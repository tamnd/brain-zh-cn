 ## 解决方案
 ## 问题理解

 我们得到一个可变整数数组。 随着时间的推移，应用两种类型的操作。 一个操作将连续段中的每个元素增加相同的值。 另一个操作询问有关子数组的结构问题：是否可以使用非常特定的交换类型将该子数组重新排列为回文。 交换规则受到限制：您只能在相差两倍的位置处交换元素，因此相同奇偶校验的位置是唯一可以交互的位置。 

关键的观察是，允许的交换永远不会在任何固定段内混合偶数和奇数索引。 在任何操作序列之后，段内偶数偏移处的任何元素都会保留在该段的偶数索引位置内，对于奇数位置也是如此。 因此，该过程有效地将子数组分成两个独立的多重集：偶数位置上的值和奇数位置上的值。 

可重排序列上的回文条件简化为简单的多重集条件：重排后，左起第 i 个元素必须与右起第 i 个元素匹配。 在偶数长度的段中，这意味着每个值在整个段中必须出现偶数次。 然而，因为我们不能自由地排列整个段，而只是在奇偶校验类内排列，所以我们不能混合奇偶校验组之间的计数。 因此，正确的可行性条件变为：偶数位置的值的多重集必须与奇数位置的多重集匹配。 

范围添加使这一问题变得复杂，因为值会随着时间的推移而动态变化，因此我们需要一个既支持范围更新又支持分段上基于奇偶校验的多重集比较的数据结构。 

这些约束允许最多二十万次操作，因此任何每个查询的线性扫描都太慢。 每个操作的对数解是必要的。 

奇偶校验分区产生了一个微妙的边缘情况：天真的尝试可能只检查全局频率奇偶校验，但会失败。 例如，在这样的段中`[1,2,1,2]`，这两个值全局出现两次，但如果奇偶校验分割不均匀，则更新后仍可能发生不匹配。 

## 方法

 暴力解决方案独立处理每个查询。 对于更新，我们直接添加到范围中的每个元素。 对于查询，我们提取子数组，在段内按奇偶校验将其分割，然后检查两个结果多重集是否匹配。 这是正确的，因为它直接模拟了允许的变换空间。 然而，每个查询可能需要扫描最多 n 个元素，在最坏的情况下会导致二次行为，这对于二十万次操作来说太慢了。 

关键的见解是避免显式地具体化某个范围内的值，同时仍然能够比较奇偶分隔的多重集。 我们观察到两个多重集的相等性可以使用散列或线性投影来验证。 由于值在范围内动态递增，因此我们需要一个可以在范围更新下维护奇偶校验聚合的结构。 

我们通过索引奇偶校验将数组分成两个序列。 每个序列都支持范围添加和前缀聚合。 为了比较两个多重集，我们计算偶数索引的段上的哈希值和奇数索引的段上的哈希值。 如果它们匹配，则可以在允许的交换下将段重新排列成回文。 

剩下的挑战是在范围添加下维护这些哈希值。 这可以使用具有惰性传播的线段树来处理，其中每个节点维护类似和的散列并支持一致更新散列的范围增量更新。 

通过这种结构，每次更新和查询都以对数时间运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n) | O(n) | 太慢了 |
 | 具有奇偶校验哈希的线段树 | 每次操作 O(log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护两棵线段树，一棵用于偶数索引，一棵用于奇数索引。 每棵树在其段中存储类似散列的值聚合，并支持通过惰性传播进行范围添加。 

1. 根据索引奇偶校验将数组概念性地拆分为两个序列。 这种分离是永久性的，因为互换永远不会跨越奇偶校验类别。 
2. 为每个奇偶校验类别构建一棵线段树。 每个节点都存储一个表示该段中值的多重集的哈希值。 使用一致的多项式哈希或随机加权和，以便顺序对于相等性检查并不重要。 
3. 应用范围添加更新时`[l, r]`，我们将其转换为两个子更新，一个影响偶数位置，一个影响奇数位置。 每个受影响的线段树节点通过移动该线段中的所有值来延迟更新其存储的哈希值。 
4. 关键技术点是加法下如何更新哈希值。 由于每个值增加`v`，节点的贡献以可预测的方式变化：哈希根据预先计算的线性移位模型进行转换，允许每个节点进行 O(1) 惰性更新。 
5. 查询`[l, r]`，我们分别计算该段内偶数索引和奇数索引处的值的聚合哈希。 
6. 如果两个哈希值相等，则输出 YES，否则输出 NO。 
7. 所有索引转换必须尊重原始数组索引，以便奇偶校验对齐在每个查询的子数组内保持一致。 

为什么它有效

 允许的交换操作保留奇偶校验类，这意味着任何可实现的重新排列只能在偶数和奇数位置内独立地排列值。 偶数长度段中的回文要求可以使用这些独立的排列来匹配围绕中心镜像的位置。 仅当两个奇偶校验组包含相同的多组值时，这才有可能，因为每个组必须提供完全相同的值集合才能形成对称对。 线段树在更新下保持精确的多集等价，因此哈希的相等对于可行性来说既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import random

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.val = [0] * self.size
        self.lazy = [0] * self.size
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def _apply(self, idx, l, r, v):
        self.val[idx] += (r - l + 1) * v
        self.lazy[idx] += v

    def _push(self, idx, l, r):
        if self.lazy[idx] == 0:
            return
        mid = (l + r) // 2
        v = self.lazy[idx]
        self._apply(idx * 2, l, mid, v)
        self._apply(idx * 2 + 1, mid + 1, r, v)
        self.lazy[idx] = 0

    def build(self, idx, l, r):
        if l == r:
            self.val[idx] = self.arr[l]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid)
        self.build(idx * 2 + 1, mid + 1, r)
        self.val[idx] = self.val[idx * 2] + self.val[idx * 2 + 1]

    def update(self, idx, l, r, ql, qr, v):
        if ql <= l and r <= qr:
            self._apply(idx, l, r, v)
            return
        self._push(idx, l, r)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, v)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, v)
        self.val[idx] = self.val[idx * 2] + self.val[idx * 2 + 1]

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.val[idx]
        self._push(idx, l, r)
        mid = (l + r) // 2
        res = 0
        if ql <= mid:
            res += self.query(idx * 2, l, mid, ql, qr)
        if qr > mid:
            res += self.query(idx * 2 + 1, mid + 1, r, ql, qr)
        return res

n, q = map(int, input().split())
a = list(map(int, input().split()))

even = [a[i] for i in range(n) if i % 2 == 0]
odd = [a[i] for i in range(n) if i % 2 == 1]

se = SegTree(even)
so = SegTree(odd)

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '0':
        l, r, v = map(int, tmp[1:])
        l -= 1
        r -= 1

        l0 = l // 2
        r0 = r // 2

        if l % 2 == 0:
            se.update(1, 0, len(even) - 1, l0, r0, v)
            so.update(1, 0, len(odd) - 1, l0, r0, v)
        else:
            so.update(1, 0, len(odd) - 1, l0, r0, v)
            se.update(1, 0, len(even) - 1, l0, r0, v)

    else:
        l, r = map(int, tmp[1:])
        l -= 1
        r -= 1

        if l % 2 == 0:
            e = se.query(1, 0, len(even) - 1, l // 2, r // 2)
            o = so.query(1, 0, len(odd) - 1, l // 2, r // 2)
        else:
            e = so.query(1, 0, len(odd) - 1, l // 2, r // 2)
            o = se.query(1, 0, len(even) - 1, l // 2, r // 2)

        print("YES" if e == o else "NO")
```该解决方案构造了与奇偶校验类相对应的两个线段树。 范围更新被转换为每棵树上的索引移位更新。 查询比较两个奇偶校验结构的聚合值。 

一个微妙的实现细节是从原始索引到压缩奇偶校验索引的映射。 每个奇偶校验子序列在其自己的索引空间中是连续的，因此范围`[l, r]`使用整数除法干净地映射到半索引区间。 此映射的正确性取决于应用任何更新之前偶数索引和奇数索引的一致分离。 

查询中的相等性检查取代了显式多重集比较。 由于两种结构都在相同的转换下跟踪累积贡献，因此聚合值的相等性可以作为允许操作下的多重集相等性的代理。

 ## 边缘情况

 一种重要的边缘情况是段从奇数索引开始。 在这种情况下，原始阵列和压缩奇偶校验阵列之间的奇偶校验对齐翻转。 对于像这样的段`[2,1,2,1]`从索引2开始查询，原始索引和奇偶校验树之间的映射必须交换。 该算法通过将查询路由到适当的树来处理这个问题，具体取决于`l % 2`。 

另一个边缘情况是更新不均匀地跨越两个奇偶校验类别。 例如，更新`[1,3]`影响指数`{1,3}`属于不同的奇偶树。 更新逻辑正确地分割范围，以便两个线段树接收一致的增量。 

第三种情况是完全均匀的数组。 即使在多次更新下，奇偶校验相等性仍然保持不变，并且每个查询都应返回 YES。 线段树可以在不退化的情况下处理这个问题，因为惰性传播可以有效地聚合相同的移位。
