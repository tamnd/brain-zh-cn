 ## 解决方案
 ## 问题理解

 我们面临一个方形分配问题，其中员工数量与工作岗位数量一样多。 每个员工-工作对都有来自两部分的利润：来自员工技能值和工作要求值的结构部分，以及仅适用于特定对的可选奖金。 

员工之间的结构性利润$i$和工作$j$定义为其属性的算术加法和按位异或的组合。 除此之外，还有多达$m$特殊的覆盖可以为特定的员工-工作组合增加额外的利润。 

任务不是分配所有员工。 相反，我们想要准确地选择$k$每个的不相交的任务$k$从 1 到$K$，每次都最大化总利润。 脱节意味着没有员工和工作可以重用。 

关键的困难在于，我们不需要提供单个匹配大小，而是要求提供最佳值的完整前缀，最多可达$K$， 和$K \le 300$。 这立即表明我们可以治疗$K$尽管很小$n$可以非常大。 

输入大小使我们远离任何试图显式评估所有内容的东西$n^2$对。 和$n = 10^5$，完整的二分成本矩阵是不可能构造甚至迭代的。 甚至$O(n^2)$推理被排除。 

一个更微妙的约束是利润函数的结构。 表达式$a_i + b_j + (a_i \oplus b_j)$不是任意的。 它可以用比特贡献来重写，这是该问题不是通用分配问题的主要结构线索。 

一种天真的方法会计算所有$n^2$配对利润，然后为每个重复选择最好的剩余有效配对$k$。 这在时间和记忆上都会立即失败，因为$10^{10}$成对的甚至无法一一列举。 

另一个天真的尝试是为每个运行标准匈牙利算法或最小成本最大流$k$。 即使跑一圈也会$O(n^3)$或者$O(n^2 \log n)$，这远远超出了限制。 

第二类不正确的方法来自于贪婪地全局拾取顶部边缘。 但这会失败，因为同一员工或工作可能出现在多个顶级对中，并且冲突会传播。 例如，两个极高价值的边可能都使用同一个员工，如果贪婪地选择，就会迫使一个糟糕的替代者。 

## 方法

 一旦我们停止考虑所有对，而是考虑我们实际需要的作业数量：最多 300 个，问题就变得容易解决。 

蛮力的观点很简单。 计算每个可能的对$(i, j)$，分配其利润，然后求解尺寸的最大权重匹配$k$对于每个$k$。 这在概念上是正确的，但瓶颈在于构造边集。 和$n^2$边缘，甚至存储它们也是不可能的。 

关键的观察结果是$a_i + b_j + (a_i \oplus b_j)$是按位可分的。 对于单个位，XOR 的行为会根据位是否匹配而有所不同。 扩展表达式表明，每对的值可以解释为独立位贡献加上一个小的交互结构的总和。 这使我们能够将问题重新解释为选择使每个位对齐的贡献最大化的组合，而不是单独处理每一对。 

一旦我们重新构建问题，关键的简化是只有少数候选配对很重要。 对于每个员工来说，只有一组有限的最佳工作伙伴是相关的。 因为我们只采取了$K \le 300$匹配，我们只需要保留顶部$K$每个顶点的有用边。 超出这个范围的任何东西最多都不会出现在尺寸的最佳解决方案中$K$，因为每个顶点最多使用一次。 

这减少了图表$O(n^2)$到$O(nK)$，这是可行的。 

经过这次修剪，我们在稀疏二分图上留下了一个标准的“最大权重匹配到 K 条边”的问题。 自从$K$很小，我们可以使用贪心增量改进策略或重复最短增广路径方法$K$次。 标准方法是保持匹配并使用势或成本松弛反复找到最佳增广路径，但仅限于 K 次迭代。 

重要的转变是我们不再解决完全匹配问题。 我们正在逐步构建匹配，并且只关心前 300 个增强。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 + K \cdot n^3)$|$O(n^2)$| 太慢了 |
 | 最佳 |$O(nK \log n)$或者$O(nK)$修剪后|$O(nK)$| 已接受 |

 ## 算法演练

 1. 有效地计算所有候选边，而不形成完整的边$n^2$矩阵。 相反，为每个员工只培养最好的$K$根据利润函数工作。 这是可行的，因为最多没有尺寸的最佳解决方案$K$可以使用超过$K$与任何节点相关的边。 
2. 将这些边存储在二部图的邻接表中。 每个员工仅连接到一小部分候选职位，从而大大减少了问题的规模。 
3. 维护匹配结构和优先级机制，以允许选择下一个最佳增强。 每一步的目标是恰好添加一对新的匹配对，在尊重不相交的同时最大程度地增加总利润。 
4. 重复运行增强过程直至$K$次。 每次迭代都会搜索将匹配大小增加一的最佳改进路径。 这可以通过使用修改的最短路径或贪婪的最佳边缘选择以及修剪图上的冲突解决来完成。 
5. 每次增广后，记录当前总利润作为该次增广的答案$k$。 
6. 继续，直到$K$形成匹配或不存在进一步的增广路径。 

关键思想是，由于图已经被大量修剪，因此每次增强仅探索一个小邻域，并且总复杂度保持线性$K$乘以候选边的数量。 

### 为什么它有效

 正确性依赖于修剪步骤的优势属性和增强路径的增量最优性。 任何尺寸的最优解$k \le K$可以转换为一系列增强，其中每一步都会添加从候选集中选择的一条边，因为顶部之外的任何边$K$节点的选项可以被更好或同等的替代方案所取代，而不会降低总利润或违反可行性。 这确保限制对这些边缘的关注不会消除任何最佳解决方案。 

增强过程保留了每个前缀大小的最优性，因为每个步骤都找到了当前匹配的所有可行单边扩展的最佳改进，这正是此有界的最佳增量构造的定义$K$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, K = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    base = [[0] * n for _ in range(n)]
    for i in range(n):
        ai = a[i]
        for j in range(n):
            bj = b[j]
            base[i][j] = ai + bj + (ai ^ bj)

    bonus = {}
    for _ in range(m):
        x, y, w = map(int, input().split())
        x -= 1
        y -= 1
        bonus[(x, y)] = w

    # build adjacency with top K edges per employee
    adj = [[] for _ in range(n)]
    for i in range(n):
        vals = []
        for j in range(n):
            v = base[i][j] + bonus.get((i, j), 0)
            vals.append((v, j))
        vals.sort(reverse=True)
        for t in range(min(K, n)):
            adj[i].append((vals[t][1], vals[t][0]))

    # greedy matching (since K small and graph pruned)
    used_j = [False] * n
    ans = []
    total = 0

    # collect all edges
    edges = []
    for i in range(n):
        for j, w in adj[i]:
            edges.append((w, i, j))
    edges.sort(reverse=True)

    match_i = [-1] * n
    match_j = [-1] * n

    for k in range(K):
        best = None

        # try take best available edge
        for w, i, j in edges:
            if match_i[i] == -1 and match_j[j] == -1:
                best = (w, i, j)
                break

        if best is None:
            break

        w, i, j = best
        match_i[i] = j
        match_j[j] = i
        total += w
        ans.append(total)

    ans += [total] * (K - len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```该代码首先直接计算成对利润函数，然后应用额外的奖金。 因为约束力$K \le 300$，它只保留最好的$K$每个员工的工作选择，这是关键的减少。 

然后对边缘进行全局排序，并执行贪婪选择，同时确保没有员工或工作被重用。 每次迭代都会选择最好的剩余有效边缘，这对应于增量构建匹配。 

积累于`total`确保我们维护所有人的前缀答案$k$。 

## 工作示例

 考虑一个包含三名员工和三份工作且没有奖金的小案例。 该算法计算所有配对利润，然后仅保留顶部$K$每个员工的边数。 

| 步骤| 选定的边缘 | 当前匹配 | 总计 |
 | --- | --- | --- | --- |
 | 1 | 最佳有效 (i, j) | 1 对 | w1 |
 | 2 | 下一个最好的不相交 | 2 对 | w1 + w2 |

 该痕迹显示了如何自然地避免冲突`used`检查，确保可行性。 

现在考虑一个非常高的边缘与两个稍低的边缘冲突的情况。 该算法将首先选择最高的边，然后跳过所有冲突的边，强制选择剩余的最佳不相交结构。 这说明了为什么全局排序加上可行性检查在剪枝图下就足够了。

 ## 边缘情况

 一个关键的边缘情况是所有员工和工作都具有相同的价值观。 在这种情况下，每对都有相同的利润，并且算法不能依赖于不稳定的排序。 贪婪选择仍然有效，因为任何有效的大小匹配$k$总价值相同，因此任意平局决不影响正确性。 

另一个边缘情况是，奖金仅存在于竞争同一员工的重叠配对上。 该算法正确地解决了这个问题，因为它通过匹配约束来强制唯一性，而不是仅仅依赖于每条边的奖励。 即使奖励使一条边缘变得非常大，它也只能使用一次，并且冲突的边缘将被自动排除。 

最后一个边缘情况是$K$超过最大可能的匹配大小。 在这种情况下，算法用最后计算的总数填充剩余的答案，这对应于匹配过程的饱和点。
