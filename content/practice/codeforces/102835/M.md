 ## 解决方案
 ## 问题理解

 该问题模拟了一个有缺陷的数字键盘，其中四个按键排列为 2 x 2 网格。 每个键对应于数字 1 到 4 之一，按下一个键会产生一个包含其行索引和列索引的对。 当同时按下多个按键时，控制器会丢失行和列之间的配对。 它只接收出现的行集和出现的列集。 任务是计算有多少个不同的键子集可以生成观察到的行集和列集。 最初的问题将接收到的行和列集限制为最多两个大小，因为键盘只有两个可能的行值和两个可能的列值。 

输入包含多个测试用例。 对于每个测试用例，第一行给出收到的不同行和列的数量。 接下来的两行描述这些行值和列值。 输出是四个键盘按键中行和列的集合与接收到的信号完全匹配的子集的数量。 

限制非常小。 最多有10个测试用例，并且接收信号的每个维度仅包含一个或两个值。 这意味着该解决方案不需要任何高级优化。 恒定时间方法就足够了，即使检查四个键的每个可能子集，每次测试也只需 16 个案例。 任何涉及大型数据结构或复杂数学的解决方案都将解决比实际问题困难得多的问题。 

主要陷阱来自于不同的按键组合可以产生相同的信号。 例如，按下键 1 和 4 会得到与按下键 2 和 3 相同的接收行集和列集。尝试重建唯一按下集的解决方案将失败，因为信号不保留原始配对信息。 

对于输入```
1
1 1
0
0
```正确的输出是```
1
```只有键 1 产生行集`{0}`和列集`{0}`。 独立计算行和列选择的粗心方法可能会错误地将行和列视为不相关和过度计数。 

对于输入```
1
2 2
0 1
0 1
```正确的输出是```
7
```除空集之外的四个键的每个非空子集都会生成完整的行集`{0,1}`和列集`{0,1}`。 粗心的方法可能只返回一个，因为它假设接收到的信号识别一种组合。 

## 方法

 直接的暴力解决方案就足够了，因为键盘仅包含四个键。 自然的暴力破解思想是枚举每个可能的密钥子集，模拟该子集创建的信号，并将其与给定信号进行比较。 对于每个选定的键，我们收集其行和列。 如果两个收集的集合都等于接收到的行集和列集，我们就会增加答案。 

这种方法是正确的，因为它准确地检查有效击键组合的定义。 只有 (2^4 = 16) 个可能的子集，因此最坏的情况每个测试用例仅执行几十个操作。 小的限制使其成为预期的解决方案。 

关键的观察结果是键盘布局是固定的。 我们永远不需要搜索可能的布局或导出数学公式。 唯一未知的是按下了四个键中的哪一个，并且完整的搜索空间大小为 16。暴力方法已经将问题简化为检查少量固定数量的候选者。 

方法之间的比较是：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(16) | O(1) | O(1) | 已接受 |
 | 最佳 | O(16) | O(1) | O(1) | 已接受 |

 暴力解决方案也是这里的最佳实际解决方案，因为恒定的搜索空间无法有意义地减少。 

## 算法演练

 1. 存储四个按键及其对应的坐标。 键 1 有坐标`(0,0)`, 键 2 有坐标`(0,1)`，键3有坐标`(1,0)`，并且键 4 有坐标`(1,1)`。 
2. 读取接收到的行值和列值并将它们作为集合存储。 使用集合是因为​​接收值的顺序并不重要。 
3. 枚举从 0 到 15 的每个掩码。每一位代表按下的组合中是否包含四个键之一。 
4. 对于当前掩码，收集属于所选键的所有行和列。 生成的行集和列集准确地描述了控制器将从该组合中接收到的内容。 
5. 将生成的集与输入集进行比较。 如果两者相等，则将此掩码视为可能的击键组合。 
6.输出有效掩码的数量。 

为什么它有效：

 每个可能按下的组合恰好对应于四个键的一个子集，并且每个子集都通过枚举进行检查。 对于每个子集，算法计算控制器接收到的确切信号。 当且仅当子集的信号与给定信号匹配时，才会对子集进行计数，因此最终计数包含所有且仅有效的组合。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    t = int(input())
    keys = [(0, 0), (0, 1), (1, 0), (1, 1)]
    ans = []

    for _ in range(t):
        m, n = map(int, input().split())
        rows = set(map(int, input().split()))
        cols = set(map(int, input().split()))

        cur = 0

        for mask in range(1 << 4):
            r = set()
            c = set()

            for i in range(4):
                if mask & (1 << i):
                    r.add(keys[i][0])
                    c.add(keys[i][1])

            if r == rows and c == cols:
                cur += 1

        ans.append(str(cur))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```数组`keys`代表固定键盘布局。 元素的索引是键号减一，所以bit`i`掩码中的一个键直接对应于键盘上的一个键。 

掩码循环覆盖所有可能的子集。 有意包含空子集是因为在问题的更一般版本中接收到的信号理论上可能为空，尽管给定的约束总是提供至少一行和一列。 

套装`r`和`c`为每个面具重建。 这可以避免意外保留先前子集中的值，这是枚举问题中常见的实现错误。 

不存在索引边界问题，因为键盘恰好有四个已知位置。 整数溢出也是不可能的，因为答案最多是 16。

 ## 边缘情况

 对于由一个精确按键生成的信号，例如：```
1
1 1
0
0
```该算法检查所有 16 个子集。 仅包含键 1 的子集创建行集`{0}`和列集`{0}`，所以答案是 1。该解决方案不会将独立的行和列选择与实际键混淆。 

对于包含所有行和列的信号：```
1
2 2
0 1
0 1
```该算法找到七个匹配的子集。 空子集被拒绝，因为它不产生行和列，而除了缺少一个坐标的单行或单列组合之外的每个非空子集都被正确处理。 

对于不明确的信号，例如：```
1
2 2
0 1
0 1
```子集`{1,4}`和`{2,3}`两者产生相同的控制器信号。 枚举对两者都进行计数，因为它直接检查组合，而不是尝试从不完整的信息重建原始密钥。
