 ## 解决方案
 ## 问题理解

 拼图是一个圆盘，上面有`n`部门。 箭头从扇区开始`s`，并且每次按下按钮都会准确地移动它`k`顺时针扇区。 扇区环绕，所以扇区之后`n - 1`下一个部门是`0`。 任务是找到使箭头落在扇区上所需的最少按钮按下次数`x`。 如果没有任何移动序列可以达到`x`，答案是`-1`。 

输入由四个整数组成，描述圆的大小、每次单击后的固定移动、初始扇区和所需扇区。 输出是所需的最少点击次数。 

约束条件`n ≤ 20000`这意味着在许多情况下可以直接模拟所有部门，但我们需要小心。 模拟可能需要最多`n`移动，这在这里是可以接受的，但是预期的数学解决方案避免依赖扇区的数量并直接计算答案。 更重要的是，机芯的结构是模运算，因此同样的推理自然可以扩展到更大的极限。 

关键的边缘情况来自于重复添加`k`不一定要访问每个部门。 

例如，如果输入是：```
12 4 1 6
```箭头访问：```
1, 5, 9, 1, 5, 9, ...
```目标行业`6`永远不会达到，所以正确的输出是：```
-1
```假设每个扇区最终都会出现的粗心解决方案将给出错误的答案。 

另一个重要的情况是起点已经是循环的一部分但目标需要最小的正环绕计数。 例如：```
10 6 3 9
```职位是：```
3 -> 9
```点击一下后，答案是：```
1
```仅在完整周期后检查位置或错误处理模运算的解决方案可能会错过这一点。 

最后一种边缘情况是移动大小和扇区数量共享一个除数。 例如：```
8 6 0 5
```箭头仅到达偶数扇区：```
0, 6, 4, 2, 0, ...
```所以扇区`5`是不可能的，答案是：```
-1
```这些案例背后的可分性条件是解决方案的核心。 

## 方法

 最直接的方法是模拟点击。 开始于`s`,重复添加`k`并对结果取模`n`。 如果当前扇区变成`x`，我们找到了答案。 如果我们回到`s`没有找到`x`，循环完成，无法达到目标。 

这种方法是正确的，因为箭头的移动是确定性的。 一旦某个扇区重复，以后的每个位置也会重复，因此不会出现新的扇区。 问题在于它将数学循环视为一系列单独的动作。 在最坏的情况下它的表现几乎`n`迭代。 对于给定的约束，这仍然没问题，但它隐藏了底层结构并且无法扩展。 

重要的观察是，之后`t`点击，箭头位于：$$(s + t \cdot k) \bmod n$$我们需要这个值等于`x`，这给出：$$t \cdot k \equiv x - s \pmod n$$这是线性同余。 仅当最大公约数为`k`和`n`划分`x - s`。 当它出现时，我们可以将方程除以该 gcd 并使用模逆来找到最小的有效值`t`。 

蛮力解决方案之所以有效，是因为它精确地探索了由递归生成的状态。 数学解决方案运行速度更快，因为它使用模算术描述相同的可达状态，并直接求解所需的移动次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 接受这些限制，但不是一般想法 |
 | 最佳 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算从起始扇区到目标扇区所需的顺时针距离。 

我们定义：$$d = (x - s) \bmod n$$后`t`点击次数，我们需要：$$t \cdot k \equiv d \pmod n$$这将运动问题转化为求解模方程。 
2. 计算`g = gcd(k, n)`。 

反复相加得到的每个值`k`具有相同的模余数`g`。 这意味着目标距离也必须能被除以`g`。 
3.如果`d`不能被整除`g`， 返回`-1`。 

没有多少乘法`k`可以产生超出倍数的余数`g`，因此目标扇区无法到达。 
4. 通过将所有项除以来简化方程`g`。 

我们得到：$$\frac{k}{g}t \equiv \frac{d}{g} \pmod{\frac{n}{g}}$$现在系数为`t`与新模数互质。 
5. 求模逆`k / g`模数`n / g`。 

由于这两个值是互质的，因此存在倒数。 两边乘以这个倒数得到：$$t \equiv \frac{d}{g} \cdot (k/g)^{-1} \pmod{n/g}$$6. 返回最小非负值`t`。 

模运算自然会给出最小的有效点击次数。 

工作原理：可达扇区形成一个循环组，通过添加`k`模数`n`。 的最大公约数为`k`和`n`准确确定哪些残基属于该组。 如果目标距离属于该组，则减少同余会产生一个具有可逆系数的方程，并且模逆给出循环内的唯一答案。 如果它不属于，则任何点击序列都无法到达它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inverse(a, mod):
    _, x, _ = egcd(a, mod)
    return x % mod

def solve():
    n, k, s, x = map(int, input().split())

    d = (x - s) % n

    g = egcd(k, n)[0]

    if d % g != 0:
        print(-1)
        return

    k //= g
    d //= g
    mod = n // g

    answer = (d * mod_inverse(k, mod)) % mod
    print(answer)

if __name__ == "__main__":
    solve()
```使用扩展欧几里得算法是因为它提供了构造模逆所需的 gcd 和系数。 逆矩阵仅在除以之后才存在`g`， 因为`k / g`和`n / g`保证互质。 

即使在以下情况下，第一个模运算也能正确计算顺时针距离：`x`在数值上小于`s`。 整除性检查必须在简化方程之前进行，否则无法到达的情况会产生无意义的逆计算。 

Python 整数不会溢出，因此乘法`d * inverse`是安全的。 最终的模数将答案保持在所需的周期长度内。 

## 工作示例

 考虑：```
8 6 0 4
```变量的演变如下。 

| 步骤| 当前方程| gcd条件| 回答 |
 | ---| ---| ---| ---|
 | 初始|`d = (4 - 0) mod 8 = 4`|`gcd(6,8)=2`| 尚未决定|
 | 检查 |`4 % 2 = 0`| 可达 | 继续 |
 | 减少|`k=3, d=2, mod=4`| 解决`3t ≡ 2 mod 4`| 继续 |
 | 逆|`3^-1 mod 4 = 3`|`t = 2*3 mod 4`|`2`|

 顺序是：```
0 -> 6 -> 4
```所以答案是`2`。 这证实了模方程给出了与模拟移动相同的结果。 

考虑：```
12 8 1 6
```| 步骤| 当前方程| gcd条件| 回答 |
 | ---| ---| ---| ---|
 | 初始|`d = (6 - 1) mod 12 = 5`|`gcd(8,12)=4`| 尚未决定|
 | 检查 |`5 % 4 != 0`| 无法到达 |`-1`|

 运动总是以倍数改变扇区`4`，所以从扇区开始`1`仅具有相同余数模数的扇区`4`可以出现。 部门`6`位于该集合之外。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(log n) | 扩展欧几里得算法需要对数时间 |
 | 空间| O(log n) | 递归欧几里得调用使用对数堆栈空间 |

 约束足够小，甚至模拟也能通过，但模块化解决方案直接利用数学结构，并且对于更大的值仍然有效`n`。 

## 测试用例```python
import sys
import io

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inverse(a, mod):
    _, x, _ = egcd(a, mod)
    return x % mod

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k, s, x = map(int, sys.stdin.readline().split())

    d = (x - s) % n
    g = egcd(k, n)[0]

    if d % g:
        return "-1\n"

    k //= g
    d //= g
    mod = n // g
    return str((d * mod_inverse(k, mod)) % mod) + "\n"

assert solution("8 6 0 4\n") == "2\n", "reachable case"
assert solution("12 8 1 6\n") == "-1\n", "unreachable gcd case"
assert solution("2 1 0 1\n") == "1\n", "minimum size"
assert solution("20 5 3 18\n") == "-1\n", "same remainder restriction"
assert solution("17 4 10 5\n") == "3\n", "wrap-around movement"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`8 6 0 4`|`2`| 基本可达周期|
 |`12 8 1 6`|`-1`| GCD 不可能性检查 |
 |`2 1 0 1`|`1`| 尽可能小的圆|
 |`20 5 3 18`|`-1`| 运动仅达到一级残级|
 |`17 4 10 5`|`3`| 正确的模块化环绕 |

 ## 边缘情况

 对于：```
12 4 1 6
```该算法计算：```
d = (6 - 1) mod 12 = 5
g = gcd(4, 12) = 4
```自从`5`不能被整除`4`，算法立即返回`-1`。 这与每个可到达扇区具有相同的余数的事实相匹配`1`模数`4`。 

为了：```
8 6 0 5
```该算法发现：```
d = 5
g = gcd(6, 8) = 2
```距离不能被 gcd 整除，所以扇区`5`无法到达。 生成的序列证实了这一点：```
0 -> 6 -> 4 -> 2 -> 0
```为了：```
10 6 3 9
```算法得到：```
d = 6
g = gcd(6, 10) = 2
```减少后：```
3t ≡ 3 mod 5
```的逆`3`模数`5`是`2`， 所以：```
t = 3 * 2 mod 5 = 1
```答案是`1`，匹配单个动作：```
3 -> 9
```相同的推理可以处理所有其他情况，因为每个可能的运动序列都由模方程表示。
