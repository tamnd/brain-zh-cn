 ## 解决方案
 ## 问题理解

 我们从一个长度的数组开始$m$，最初用零填充。 每次操作$i$获取位置列表并用值覆盖所有这些位置$i$。 由于操作按从 1 到$n$，每个位置的最终值只是触及它的最后一个操作的索引。 

最终的数组$R$因此，由“最后写入获胜”规则决定：每个索引都会记住包含它的最大操作编号，并且该操作编号将成为其最终值。 

任务是重新排序操作。 我们可以任意排列操作，但是在按照新的顺序应用它们之后，每个位置都必须得到与原始过程中完全相同的最终值。 

约束允许最多$10^5$每次测试的操作和位置，总输入大小约为$2 \cdot 10^6$。 这迫使每个测试用例都有一个线性或近线性的解决方案。 任何操作位置发生次数的二次方都会立即失败，因为每个操作可能会触及许多位置。 

当两个操作在某些位置上重叠但这些位置的“获胜”操作在整个原始流程中不同时，就会出现微妙的失败情况。 例如，如果操作 1 触及位置 1 和 2，操作 2 触及位置 2 和 3，操作 3 触及位置 1 和 3，则不同的索引具有不同的最后写入者。 像按操作大小或按触及的最小索引排序这样的天真的想法会失败，因为它忽略了约束是特定于位置的而不是全局的。 

核心困难在于最终结果编码了操作之间的优先约束，并且必须仔细提取这些约束。 

## 方法

 如果我们忽略排序约束并简单地尝试所有排列，我们可以模拟每个排序并比较结果。 那将花费$n! \cdot m$，即使输入很小，这也是完全不可行的。 

一个稍微不那么幼稚的尝试是认识到每个位置的最终值仅取决于影响它的最后一个操作。 这建议为每个位置计算原始序列中最后一个操作。 打电话给这个$last[x]$。 如果我们确定相同的操作必须保留为每个位置的最后一个编写器，那么我们可以导出约束：对于每个位置$x$，每一个触及的操作$x$除了$last[x]$必须出现在之前$last[x]$。 

这将问题转化为操作的偏序问题。 每个位置都提供“操作”形式的定向约束$a$必须在手术前到达$b$一旦我们构建了所有这些约束，问题就变成了检查是否存在有效的拓扑排序。 

这正是该结构可以利用的地方。 我们不是推理数组，而是推理操作之间的依赖关系。 如果依赖图有环，则任何排列都无法保留所有“最后写入”关系。 如果它是非循环的，则任何拓扑排序都会产生有效的排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n! \cdot m)$|$O(m)$| 太慢了 |
 | 依赖图+拓扑排序|$O(n + \sum p_i)$|$O(n + \sum p_i)$| 已接受 |

 ## 算法演练

 我们将问题简化为构建和验证操作的有向图。 

1. 计算影响每个位置的最后一个操作。 我们按升序扫描操作并记录每个位置$x$最大索引$i$这样操作$i$包含$x$。 这个值是$last[x]$。 此步骤捕获阵列的最终状态。 
2. 对于每一个操作$i$，我们检查它触及的所有位置。 对于每个位置$x$， 如果$last[x] \neq i$，然后运行$i$必须在操​​作前出现$last[x]$在任何有效的订单中。 我们将其编码为有向边$i \rightarrow last[x]$。 
3. 我们使用邻接表构建完整的有向图并计算所有节点的入度。 该图对保留最终数组所需的每个约束进行了编码。 
4. 我们使用入度为零的节点队列执行拓扑排序。 每次我们从队列中删除一个操作时，我们都会将其附加到答案中并减少其邻居的入度。 
5. 如果我们设法输出所有$n$操作，订单有效。 否则，该图包含一个循环，并且任何排列都无法保留结果。 

关键思想是，每个位置都有一个“获胜者必须排在所有其他参与者之后”的约束，并且我们在全球范围内强制执行所有此类约束。 

### 为什么它有效

 各位置$x$在原始过程中通过独特的操作确定$last[x]$。 任何其他触及的操作$x$之后不得覆盖它$last[x]$在新的排序中，否则最终值将会改变。 因此，每个此类操作都必须先于$last[x]$。 这些约束正是图编码的内容。 

相反，如果满足所有这些约束，那么对于每个位置$x$，新顺序中触及它的最后一个操作仍然是$last[x]$，因为所有竞争操作都被强制提前。 这准确地保留了最终的数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    
    ops = [[] for _ in range(n + 1)]
    last = [0] * (m + 1)

    for i in range(1, n + 1):
        arr = list(map(int, input().split()))
        p = arr[0]
        for x in arr[1:]:
            ops[i].append(x)
            last[x] = i

    g = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    for i in range(1, n + 1):
        for x in ops[i]:
            j = last[x]
            if j != i:
                g[i].append(j)
                indeg[j] += 1

    q = deque([i for i in range(1, n + 1) if indeg[i] == 0])
    res = []

    while q:
        u = q.popleft()
        res.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    if len(res) != n:
        print("No")
    else:
        print("Yes")
        print(*res)

t = int(input())
for _ in range(t):
    solve()
```代码首先重建每个位置的“最后一次出现”，它完整地描述了目标数组。 然后，它构建一个有向图，其中每条边都强制要求某个位置的非获胜操作必须早于获胜操作出现。 

拓扑排序是使用双端队列来实现的。 如果存在任何循环，则某些操作永远不会达到零入度，这正确地表明了不可能。 

一个常见的陷阱是迭代边缘两次或错误地为操作本身是最后一个写入者的位置添加边缘。 必须跳过这些情况，因为它们没有施加任何限制。 

## 工作示例

 考虑一个操作重叠的小实例：

 输入：```
n = 3, m = 3
1: [1]
2: [1, 2]
3: [2]
```这里$last[1] = 2$,$last[2] = 3$,$last[3] = 0$。 

我们构造边：

 操作 1 贡献$1 \rightarrow 2$。 

操作2贡献$2 \rightarrow 3$。 

操作 3 没有任何贡献。 

拓扑排序产生排序$1, 2, 3$。 

| 步骤| 队列| 选择| 结果 | 入度变化|
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 1 | [1] | 2 减少 |
 | 1 | 2 | 2 | [1,2]| 3 减少 |
 | 2 | 3 | 3 | [1,2,3]| 完成 |

 这证实了依赖关系沿着重叠更新正确传播。 

第二个例子表明了不可能：```
1: [1]
2: [1]
```两个操作都触及相同的位置，但只有操作 2 是最后一个，所以我们得到边缘$1 \rightarrow 2$。 这仍然是非循环的，因此排序存在为$1,2$。 如果我们错误地反转依赖关系，我们将创建一个循环并错误地报告失败。 该结构确保方向始终是从非最后到最后，防止错误循环。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n + \sum p_i)$| 每个位置都会处理一次以进行最后出现计算，并处理一次以进行边缘生成 |
 | 空间|$O(n + \sum p_i)$| 存储邻接列表和操作成员列表 |

 总工作量与输入大小成线性比例，这正好符合所有工作总和的约束范围$p_i$取决于$10^6$。

 ## 边缘情况

 最小的情况是每个操作都涉及不相交的位置。 该图没有边，因此每个排列都是有效的。 该算法正确地生成初始入度为零的所有节点并输出任意顺序。 

更微妙的情况是当多个操作触及单个位置时。 只有原始序列中的最后一个成为边缘链的汇点，所有其他边缘都指向它。 该结构确保边缘不会反转，因此不会引入人工循环。 

如果我们错误地在共享位置的两个方向上添加边，就会出现失败情况。 即使存在有效的排序，这也会立即产生循环。 该算法通过将边缘严格定向到由原始过程确定的最终写入器来避免这种情况。
