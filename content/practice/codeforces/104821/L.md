 ## 解决方案
 ## 问题理解

 我们得到了一系列地块类型。 每种类型描述了存在多少个相同的包裹，其中每个包裹的重量为 1 或 2，并且必须交付到特定楼层。 我们可以考虑将每个组扩展为​​单独的包裹，每个包裹都有重量和目的地楼层。 

电梯每次乘坐的总重量是固定的。 每趟行程从底层出发，到达该行程所运包裹中最高的目的地楼层，然后返回。 乘车费用就是最高楼层的费用。 我们的任务是将所有地块划分为游乐设施，遵守重量限制，以便最大程度地减少这些最大楼层的总和。 

关键结构是我们在重量限制下将物品打包成组，但成本仅取决于每个组中的最大楼层，而不取决于其中有多少物品。 

约束很大：测试用例总共最多 3×10^5 组，每组最多 10^5 个地块。 这排除了任何单独扩展地块或尝试组合分组的方法。 任何解决方案都必须处理聚合计数，并且每个测试用例的行为大致为 O(n log n) 或更好。 

天真的解释可能会建议尝试所有包装或按楼层分类，并贪婪地填充没有结构的游乐设施。 这些方法失败了，因为重量 1 和重量 2 包裹之间的相互作用决定了包装的可行性，并且目标不是每件物品的累加，而是每组的最大楼层数。 

一些微妙的边缘情况说明了陷阱。 如果所有包裹的重量均为 2 并且 k 很小，则每个行程只能容纳 k/2 个包裹，因此按楼层分组非常重要。 如果所有地块都具有相同的楼层，则无论安排如何，答案都会减少为乘坐总数乘以该楼层。 如果忽略最佳混合重量，很容易浪费容量并创建不必要的额外游乐设施，从而增加总成本。 

## 方法

 蛮力的想法是模拟将包裹分组为有效游乐设施的所有可能方式。 每个游乐设施都是总重量不超过 k 的任何子集，我们支付该子集中最大楼层的费用。 这本质上是具有加权约束和非线性成本函数的多重集的划分问题。 即使是中等投入，划分方式的数量也是指数级的，因为每个地块都可以放置到任何现有或新的游乐设施中。 即使进行剪枝，状态空间也会与 n 组合增长，这使得这是不可行的。 

关键的观察结果是，成本仅取决于每次乘坐的最大楼层。 这建议按楼层降序对包裹进行排序。 一旦我们确定了一个游乐设施的最大楼层为f，我们只需要决定哪些楼层≤f的包裹可以装入其中。 这就把问题变成了：对于每个楼层，我们尝试将尽可能多的低层地块“附加”到其成本已经由高层地块决定的游乐设施中。 

这创建了一个自然的贪婪结构。 我们按照从最高到最低的顺序处理楼层。 每次我们在新楼层遇到包裹时，我们都必须启动足够的游乐设施来覆盖它们，因为这些包裹无法放置在已经敲定的较高楼层游乐设施中。 开放这些游乐设施后，我们尝试使用以前见过的较低楼层的包裹来填补剩余的容量，首先优先考虑较重的物品，因为它们消耗容量的速度更快。 

k 的奇偶性和均匀性很重要：由于重量只有 1 和 2，我们可以使用重量为 2 的物品和重量为 1 的物品的贪婪配对来减少每次骑行内的包装问题，以最大限度地利用容量。

我们根据活跃游乐设施中剩余的权重 1 插槽数量来维护可用的“剩余容量”，并单独跟踪权重 2 的使用情况。 当我们向下移动楼层时，我们不断尝试重新利用较高楼层的剩余容量，确保没有浪费槽位。

 ## 算法演练

 我们首先按楼层和重量聚合包裹，以便每个楼层都有重量为 1 和重量为 2 的物品计数。 

1. 按降序对所有不同楼层进行排序。 我们按照从最高到最低的顺序处理楼层，这样一旦我们将成本分配给行程，该成本就是固定的并且永远不会重新审视。 这是必要的，因为乘车成本由该乘车的最大楼层决定。 
2. 维护两个来自先前创建的游乐设施的未使用容量的全局池：一个代表重量为 1 单位的可用槽位，另一个代表可以在重量为 2 块中消耗的可用容量。 
3. 在给定的楼层 f，我们首先决定强制执行多少次新游乐设施。 f 层的每个包裹都必须交付，因此如果现有容量无法容纳它们，我们会以成本 f 创建新的游乐设施。 每个新游乐设施都会贡献 k 个单位的承重能力。 
4. 在f层分配地块时，我们首先尝试使用现有容量。 我们贪婪地使用剩余的满容量放置重量为 2 的包裹，因为它们以后更难容纳。 之后，我们将重量为 1 的包裹放入剩余的单个单元槽中。 
5. 放置当前楼层地块后的任何剩余容量将结转至较低楼层。 这很重要，因为它允许高成本的乘车服务稍后吸收更便宜的包裹，而不会增加总成本。 
6. 对所有楼层重复此过程，通过添加 f 乘以在该楼层创建的新游乐设施数量来累积总成本。 

正确性取决于这样一个事实：一旦为某个游乐设施分配了最大楼层 f，它就可以安全地吸收任何剩余的较低楼层包裹，而不会增加成本。 

### 为什么它有效

 在任何时候，游乐设施实际上都是固定成本等于其已包含的最高楼层的桶。 将较低楼层的地块引入现有游乐设施不会改变其成本，因此唯一重要的决定是是否需要新的游乐设施来容纳当前楼层的地块。 通过始终从最高楼层到最低楼层进行处理，我们确保每次乘车的成本都被准确确定一次，并且我们绝不会将强制性的高楼层包裹推迟到未来的决策中，因为这可能会人为地增加成本。 在重量 1 之前贪婪地打包重量 2 可确保最大程度地利用容量，防止不必要的额外行程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        groups = {}
        
        for _ in range(n):
            c, w, f = map(int, input().split())
            if f not in groups:
                groups[f] = [0, 0]  # [w1, w2]
            if w == 1:
                groups[f][0] += c
            else:
                groups[f][1] += c
        
        floors = sorted(groups.keys(), reverse=True)
        
        carry_w1 = 0
        carry_w2 = 0
        total_cost = 0
        
        for f in floors:
            w1, w2 = groups[f]
            
            cap = carry_w2 * 2 + carry_w1
            
            use2 = min(w2, cap // 2)
            cap -= use2 * 2
            w2 -= use2
            
            use1 = min(w1, cap)
            cap -= use1
            w1 -= use1
            
            remaining = w1 + 2 * w2
            need = (remaining + k - 1) // k
            
            total_cost += need * f
            
            total_cap = need * k
            
            total_cap += cap
            
            carry_w2 = total_cap // 2
            carry_w1 = total_cap % 2
        
        print(total_cost)

if __name__ == "__main__":
    solve()
```该解决方案将每个楼层压缩为重量 1 和重量 2 地块的聚合计数。 它不是跟踪单个包裹，而是跟踪以前创建的游乐设施已有多少可用容量。 

变量`cap`代表较高楼层游乐设施的未使用容量，以重量单位表示。 我们首先尝试容纳重量为 2 的包裹，因为它们更难容纳分散的容量。 然后我们放置重量为 1 的包裹。 

使用完所有可用容量后，我们计算该楼层剩余地块需要多少次全新游乐设施。 每一次这样的骑行都会做出贡献`k`能力，也贡献`f`到总成本。 

满足当前楼层需求后的剩余容量将向下结转。 我们将其转换为同等数量的权重 2 和剩余的权重 1 槽位，以便将来的楼层可以重复使用它。 

关键的微妙之处在于我们从未明确地模拟游乐设施； 我们只跟踪跨楼层的容量传播，确保正确性而不构建实际的组。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    input = sys.stdin.readline
    T = int(input())
    out = []

    def solve():
        for _ in range(T):
            n, k = map(int, input().split())
            groups = {}
            for _ in range(n):
                c, w, f = map(int, input().split())
                groups.setdefault(f, [0, 0])
                groups[f][0 if w == 1 else 1] += c

            floors = sorted(groups.keys(), reverse=True)
            carry_w1 = carry_w2 = 0
            total_cost = 0

            for f in floors:
                w1, w2 = groups[f]
                cap = carry_w2 * 2 + carry_w1

                use2 = min(w2, cap // 2)
                cap -= use2 * 2
                w2 -= use2

                use1 = min(w1, cap)
                cap -= use1
                w1 -= use1

                remaining = w1 + 2 * w2
                need = (remaining + k - 1) // k

                total_cost += need * f
                total_cap = need * k + cap

                carry_w2 = total_cap // 2
                carry_w1 = total_cap % 2

            out.append(str(total_cost))

    solve()
    return "\n".join(out)

 ## 边缘情况

 一种边缘情况是，所有包裹的重量均为 2，且 k 略大于 2。在这种情况下，每次骑行只能运载少量物品，对剩余容量的贪婪重用至关重要。 该算法通过始终首先从可用容量中消耗重量为 2 的包裹来解决此问题，从而防止碎片化，否则会产生额外的乘车次数。 

另一个边缘情况是所有地块共享同一楼层。 在这里，没有机会跨楼层重复使用，因此解决方案在重量限制下减少为纯粹的垃圾箱包装。 该算法自然地计算该楼层所需的所有游乐设施，并且不会向下传递任何有意义的容量，从而与预期行为相匹配。 

当存在许多低层重量为 1 的地块和少量高层重量为 2 的地块时，会出现第三种边缘情况。 如果不按降序处理，人们可能会错误地首先分配低楼层地块，并浪费本应为较高楼层保留的容量。 降序扫描可确保首先确定高成本决策，并将所有较低的项目视为填充材料。
