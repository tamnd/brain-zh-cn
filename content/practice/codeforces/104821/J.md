 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中每条边都带有一个非常大的字母表中的标签。 如果我们从根走到任何节点，沿该路径的边标签序列就会形成一个字符串。 我们将此字符串称为节点的路径字符串。 

除了树之外，我们还有一个序列`t`。 我们逐步处理它：一步一步`j`，我们考虑前缀`t[1..j]`。 对于每个树节点`i`，我们将其路径字符串与此前缀连接起来并获得一个新字符串。 

现在，对于每个这样构造的字符串，我们在树中查找作为其后缀出现的所有字符串。 在这些匹配的节点路径字符串中，我们选取​​深度最大的一个，该深度定义为`f(i, j)`。 直观上，我们问的是：在将一些字符附加到根到节点的字符串后，我们可以在树上“向后匹配”多远作为后缀。 

最后，对于每个前缀长度`j`，我们求和`f(i, j)`在所有节点上`i`。 这笔钱就是答案`g_j`。 

约束很大：树的大小和长度`t`所有测试用例最多可达 200,000 个。 任何关于节点和时间步长的二次方法都是不可能的。 甚至像重新计算每个匹配项之类的事情`(i, j)`在最坏的情况下，pair 明确需要最多 4e10 次操作，这远远超出了限制。 

正确的解决方案必须重用状态之间的结构。 关键的结构是我们比较的所有字符串都来自前缀字符串树，这强烈建议使用类似 trie 或基于自动机的视图，而后缀匹配建议反转视角或使用失败链接。 

打破朴素推理的边缘情况包括以下情况：

 一个节点的路径字符串已经是另一个节点的路径字符串的后缀，因此附加字符不会更改最佳匹配。 

例如，如果树包含字符串`("a")`,`("ba")`，然后我们附加`"a"`到`"b"`，根据结构，最佳后缀匹配可能会从较深的节点跳转到较短的节点。 天真的“总是扩展当前匹配”的想法失败了，因为后缀对齐在树中不是单调的。 

另一个极端情况是空字符串行为。 由于空字符串始终是有效的后缀，因此每个节点始终至少贡献深度 0，因此算法必须正确初始化该基线。 

## 方法

 蛮力解释很简单。 对于每个节点`i`和每个前缀`j`，我们明确地形成字符串`s_i + t[1..j]`。 然后我们枚举所有树节点`x`，检查是否`s_x`是这个构造字符串的后缀，并取有效匹配中的最大深度。 这需要每次检查比较长度最多 2e5 的字符串，导致最坏的解释大约为 O(n * m * n * L)，其中`L`是字符串长度。 即使我们优化比较，我们仍然有 O(n * m * L) 的行为，这是不可行的。 

关键的观察是我们总是匹配从根到节点路径派生的一组固定字符串。 这正是一个 trie 结构。 如果我们反转字符串，后缀查询就会变成前缀查询，并且一组字符串上的前缀查询自然会由自动机处理，就像带有失败链接的 trie 一样。 

现在重新解释一下这个过程。 而不是考虑后缀`s_i + t[1..j]`，我们考虑从这个连接字符串的末尾到 trie 可以向后匹配多远。 这与在由所有根到节点字符串构建的 Aho-Corasick 自动机中行走相同。 

自动机中的每个节点对应于特里树中的一个状态，并且每个转换对应于附加一个字符。 功能`f(i, j)`变为：从状态开始`i`, 处理后`j`字符，我们可以到达的对应于某些后缀匹配的最深节点是什么。 答案仅取决于自动机转换。 

主要困难是每个节点的所有节点的聚合`j`。 而不是更新每个`(i, j)`我们独立地在自动机状态上传播计数。 每一步`j`，我们维护当前每个状态有多少个起始节点。 然后我们使用转换`t[j]`，然后进行故障链接传播以确保后缀闭合。 每个节点贡献其深度权重，并且我们累积每一步的贡献。 

这减少了从成对匹配到在具有线性过渡的固定自动机上重复分配质量的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²·米) | O(n) | 太慢了 |
 | 树串上的自动机 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 我们首先从树中构建一个 trie 结构。 树中的每个节点对应于表示其根到节点路径字符串的特里树状态。 因为给出了父指针，所以我们可以在遍历树时为每个节点分配一个唯一的 trie 节点。 

接下来，我们使用 BFS 为该 trie 构建故障链接，就像 Aho-Corasick 一样。 这些链接允许我们从一个节点移动到最长的正确后缀，这也是一个有效的 trie 状态。 

然后我们在 trie 状态上维护一个频率数组。 最初，每个树节点在其相应的特里状态下贡献一个质量单位。 

我们还维护一个数组`depth[state]`，这是该树节点的深度。 

对于中的每个字符`t`，我们对所有状态执行全局转换。 我们不是独立移动每个节点，而是计算一个新的频率数组`nf`。 对于每个州`v`随频率`f[v]`，我们使用当前角色的自动机边缘进行过渡。 如果边缘不存在，我们将遵循失败链接，直到到达有效的转换或根。 我们将得到的频率累积到新的数组中。 

计算新位置后，每个状态将其频率乘以其深度贡献给当前答案`g_j`。 这是有效的，因为每个活动状态代表处理后其最佳后缀匹配的所有起始节点`j`字符在该状态结束。 

最后，我们对所有字符重复`t`。 

### 为什么它有效

 在任何一步，每个起始节点`i`恰好由一个活动自动机状态表示，这是最深的后缀匹配`s_i + t[1..j]`在特里树中。 故障链接结构保证每个可能的后缀对应都由某种可达状态表示。 因为转换总是保持后缀一致性，所以不会跳过任何有效匹配，并且因为我们总是遵循失败链接，所以不会计算无效匹配。 深度之和直接聚合`f(i, j)`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))
    c = list(map(int, input().split()))
    t = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        adj[p[i - 1]].append((i, c[i - 1]))

    nxt = [{} for _ in range(n + 1)]
    depth = [0] * (n + 1)

    q = deque([0])
    order = [0]

    while q:
        u = q.popleft()
        for v, ch in adj[u]:
            depth[v] = depth[u] + 1
            nxt[u][ch] = v
            q.append(v)
            order.append(v)

    fail = [0] * (n + 1)
    q = deque()

    for ch, v in nxt[0].items():
        fail[v] = 0
        q.append(v)

    while q:
        v = q.popleft()
        for ch, u in nxt[v].items():
            f = fail[v]
            while f and ch not in nxt[f]:
                f = fail[f]
            if ch in nxt[f]:
                fail[u] = nxt[f][ch]
            else:
                fail[u] = 0
            q.append(u)

    freq = [0] * (n + 1)
    for i in range(1, n + 1):
        freq[i] = 1

    def step(freq, ch):
        nf = [0] * (n + 1)
        for v in range(n + 1):
            if freq[v] == 0:
                continue
            u = v
            while u and ch not in nxt[u]:
                u = fail[u]
            if ch in nxt[u]:
                u = nxt[u][ch]
            else:
                u = 0
            nf[u] += freq[v]
        return nf

    res = []
    for ch in t:
        freq = step(freq, ch)
        ans = 0
        for i in range(n + 1):
            ans += freq[i] * depth[i]
        res.append(str(ans))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该实现根据父指针构建 trie，然后按 BFS 顺序计算故障链接。 这`step`函数在所有活动状态之间执行一次全自动转换。 关键的微妙之处在于，我们反复攀爬失败链接，直到找到有效的转换，这确保了当前路径无法直接延伸时后缀的正确性。 

深度数组很关键：它对值进行编码`d(x)`定义中需要`f(i, j)`。 求和`freq[state] * depth[state]`每一步都会产生所需的聚合。 

一个常见的陷阱是忘记该状态`0`表示空字符串，必须始终包含在内，否则短字符串的后缀匹配将会丢失。 

## 工作示例

 考虑一棵小树，其中根连接到形成字符串的节点`"a"`,`"ab"`,`"b"`， 和`t = "ba"`。 

开始时，每个节点都处于活动状态一次。 加工后`'b'`, 可以匹配后缀的节点`"b"`集中在对应的状态`"b"`和根回退。 加工后`'a'`，转变再次转移质量，并且我们积累当前状态的深度。 

| 步骤| 处理后的字符 | 活动状态（概念）| 贡献|
 | ---| ---| ---| ---|
 | 0 | - | 所有节点均处于初始状态| 所有节点的深度总和 |
 | 1 | 乙| 匹配以 b | 结尾的后缀的节点 更新深度总和 |
 | 2 | 一个 | 匹配以 ba | 结尾的后缀的节点 更新深度总和 |

 该跟踪显示了质量如何在 trie 状态之间移动，而不是从头开始重新计算匹配。 

现在考虑一个退化链树：`0 -> 1 -> 2 -> 3`与标签形成`"aab"`， 和`t = "b"`。 读完后`"b"`，所有后缀匹配都折叠到代表的节点`"b"`如果存在，否则回退到 root。 这确认故障链接正确处理丢失的转换。

 ## 边缘情况

 一个关键的边缘情况是所有节点都是共享前缀的深链。 在这种情况下，失败链接会重复重定向到根，并且如果没有适当的回退处理，转换将错误地丢弃贡献。 该算法通过显式遍历故障链接直到找到有效边缘来处理此问题，确保考虑到每个后缀可能性。 

另一种情况是当`t`包含从未出现在 trie 中的字符。 然后每次转换都必须回落到状态`0`。 频率质量塌陷到根，答案变成`n * depth[0] = 0`，这是正确的，因为只有空字符串匹配。
