 ## 解决方案
 ## 问题理解

 我们正在模拟一个非常受限的纸牌游戏，其中玩家有两个有序结构：初始手牌和抽牌堆。 手牌包含一张特殊的获胜牌，抽牌堆包含实用卡，可以通过抽更多牌暂时增加手牌大小。 玩家只能按顺序打牌，每张打出的牌都会在选择下一张牌之前完全解决。 

关键限制是手牌大小限制`k`。 每当从牌堆中抽出一张牌时，仅当当前手牌大小严格小于时，才会将其添加到手牌中`k`。 如果手牌已经满了，抽到的牌就会被丢弃。 抽签堆严格从上到下消耗。 

只有一张牌对胜利至关重要：独一无二`G`卡片。 只有当抽牌堆完全空的时候才能玩。 所以整个过程就是决定我们是否可以在管理手牌大小的同时耗尽牌堆，这样我们就不会陷入有用的抽奖效果被阻止的状态。 

输入给出两个字符串。 第一个描述了第一手牌，包括一手牌`G`。 第二个描述了从上到下的抽签堆。 每堆牌要么是单抽牌，要么是双抽牌，要么是不能打出的死牌。 

输出要求最小整数`k`（至少是初始手牌大小），这样存在一些扑克牌序列可以保证抽牌堆完全耗尽，从而允许`G`被播放。 如果没有这样的`k`存在，我们输出不可能性。 

所有测试用例的约束总和对于每个测试用例的粗略线性或近线性解决方案来说足够小。 自从`n, m ≤ 2500`， 一个`O((n+m)^2)`或者`O(nm)`方法是可以接受的，但是任何状态上的三次或指数都不会。 

当贪婪地消耗抽牌而不考虑手牌容量是所有抽牌的共享全局约束时，就会出现幼稚的失败情况。 例如，如果我们总是“立即拿走尽可能多的牌”，我们可能会尽早用无用的牌填满手牌，并阻止以后必要的抽牌链，即使不同的游戏顺序可以避免饱和。 

另一个微妙的失败发生在`W`牌。 由于它们无法玩，它们仍然占据手部空间，但对进度没有贡献。 忽略它们或假设可以随意跳过它们的幼稚模拟将低估所需容量或错误地得出可行性结论。 

## 方法

 直接模拟方法会尝试对整个游戏状态进行建模：当前手中有哪些牌、牌堆中的哪些位置以及牌的确切顺序。 每次我们考虑打出手中任何可用的牌时，我们都会模拟它的效果并递归。 这很快就变得不可行，因为手牌不仅仅是一个集合，它是一个多重集合，对桩交互有顺序约束，并且每次抽牌分支都取决于手牌是否满了。 

即使我们忽略分支并贪婪地模拟，真正的问题仍然存在：唯一有意义的资源是随着时间的推移我们必须在手牌中保留多少个槽位，这样我们就不会浪费潜在的平局。 每张抽牌都试图通过将新牌插入手牌来有效地增加未来的容量压力。 

关键的观察是我们实际上并不需要确切的比赛顺序。 手上所有可玩的牌，除了`G`可以被视为可用的“绘制源”，只要它们存在，就可以随时使用。 播放它们的顺序对于可行性并不重要； 重要的是我们是否能够确保，在从上到下处理该堆时，我们始终有足够的空闲槽位来接受有用的抽奖而不是丢弃它们。 

这将问题转化为确定给定容量是否`k`允许我们处理这堆卡片，同时保持足够的“可用空间预算”，以避免丢失必要的卡片。 如果我们可以检查固定的可行性`k`，我们可以二分查找最小值`k`。 但是，如果我们意识到可行性是单调的，那么即使二分搜索也是不必要的，并且我们可以通过跟踪由抽卡的最佳使用所产生的最大同时压力来直接计算最小值。 

关键的减少是我们模拟了堆，每当我们遇到一个`Q`或者`B`，我们将其视为产生未来的工作负载：`Q`生成一个潜在的槽消耗事件，`B`生成两个。 问题是我们是否可以安排初始手牌的使用来满足所有产生的需求而不超出容量。 这相当于跟踪最严重的前缀过载。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 状态的全面模拟 | 指数| 指数| 太慢了 |
 | 二分查找+模拟| O((n+m) log(n+m)) | O((n+m) log(n+m)) | O(n+m) | 已接受 |
 | 直接贪婪容量跟踪| O(n+m) | O(n+m) | 已接受 |

 ## 算法演练

 我们从上到下处理这堆纸堆，并在尊重手容量的同时维持必须满足的“主动抽奖请求”数量。 手最初有尺寸`n`，容量为`k`，所以最初我们有`k - n`免费插槽。 

我们将这个过程解释如下。 

1. 开始于`used = n`，表示所有初始手牌都占用槽位，包括`G`并且全部无法使用`W`牌。 可用空间是`free = k - n`。 
2. 按顺序遍历抽签堆。 
3、遇到时`Q`，我们模拟必须抽一张牌。 如果有空闲空间，我们就减少`free`并增加`used`因为这张牌已经到手了。 如果没有可用空间，该卡将被丢弃，我们什么也不做。 
4、遇到时`B`，我们重复相同的逻辑两次，因为它会顺序尝试两次绘制。 第二次抽签会看到第一次抽签后的更新状态。 
5、遇到时`W`，我们什么都不做，因为它不是绘制效果。 
6. 在任何时候，如果`free`变为负值，电流`k`无效。 
7. 如果我们在不违反约束的情况下完成了桩的处理，那么这`k`就足够了。 

重要的是我们永远不需要明确地模拟手牌。 这手牌的唯一作用是确定是否接受或放弃即将到来的听牌。 

最终答案是最小的`k`上述模拟成功。 由于可行性是单调的`k`，我们可以通过二分查找找到它`n`和`n + m`。 

### 为什么它有效

 在任何时候，系统变得不可能的唯一原因是我们被迫接受超过可用容量所允许的卡。 因为`Q`和`B`效果是连续的，并且与手中的特定卡牌触发它们无关，我们可以重新排序所有手牌，而不会影响抽奖事件的总数。 这样一次打桩过程就完全确定了`k`是固定的，任何有效的策略都对应于一些不会改变总需求的绘制触发器的调度。 该算法准确跟踪容量是否低于零，这是防止达到空堆的唯一条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(k, n, pile):
    free = k - n
    if free < 0:
        return False

    for c in pile:
        if c == 'Q':
            if free > 0:
                free -= 1
            else:
                return False
        elif c == 'B':
            for _ in range(2):
                if free > 0:
                    free -= 1
                else:
                    return False
        else:
            continue

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        SH = input().strip()
        SP = input().strip()

        # k must be at least n
        lo, hi = n, n + m

        ans = None
        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, n, SP):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        if ans is None:
            print("IMPOSSIBLE")
        else:
            print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将可行性检查分离为单调谓词。 辅助函数模拟固定容量下的桩`k`。 二分搜索范围是安全的，因为最坏的情况下我们可能需要持有所有牌，其范围为`n + m`。 

一个微妙的实现细节正在处理`B`作为两个连续的`Q`运营，因为当产能紧张时，订购很重要。 另一个是我们从未真正模拟过`G`牌或游戏逻辑，因为成功仅取决于清空牌堆，而不取决于手动排序。

 ## 边缘情况

 一个关键的边缘情况是当手已经充满了`W`牌。 在这种情况下，如果容量太小，即使是一大堆有用的抽牌也无济于事，因为每次尝试抽牌都会立即被丢弃。 该算法可以正确处理这个问题，因为`free`开始为`k - n`，所以如果`n`已消耗大部分容量，不接受抽奖。 

另一种边缘情况是连续的`B`牌堆中较早的牌。 由于每个`B`扩展为两次连续的绘制尝试，顺序在微步级别很重要。 模拟通过立即处理两次抽签来处理这个问题，确保部分接受不会错误地假设两者都成功。 

最后，情况`k = n`很关键。 这里不能添加新牌，因此所有抽牌都将被丢弃。 仅当堆与到达终止无关时，算法才能正确识别可行性，这符合游戏规则。
