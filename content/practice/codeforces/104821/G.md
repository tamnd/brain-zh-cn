 ## 解决方案
 ## 问题理解

 我们得到了一系列宝石，每颗宝石都有价格和美丽价值。 我们从固定金额开始，希望最大限度地提高最终获得的宝石的整体美感。 不同之处在于，在花钱之前，我们可以选择$k$免费宝石，这意味着它们有助于美丽，但不会减少预算。 使用此免费限额后，必须在预算范围内购买任何剩余的所选宝石$W$。 

决定的不仅是选择哪些宝石，还包括哪个子集应该被分配为免费还是付费。 一颗免费获取的宝石仍然占据着其中之一$k$插槽，因此在昂贵的物品上使用免费津贴可能是有益的，因为它节省了可以重定向到其他购买的预算。 

输入大小对于二次或$n \log n$风格的动态规划解决方案。 和$n \le 5000$和$W \le 10000$，按预算确定尺寸的标准背包是可行的，但额外的自由选择尺寸会阻止简单的一维背包捕获所有状态。 尝试免费项目的所有子集或所有分配的幼稚方法将是指数级的并且立即不可行。 

当一件高颜值的商品价格昂贵时，就会出现贪婪直觉的微妙失败案例。 一个幼稚的策略可能会选择$k$最高的美容物品是免费的，但这可能会将免费插槽浪费在已经值得便宜购买或根本不值得选择的物品上。 

例如，如果$k = 1$，我们有以下项目：```
(10 cost, 100 beauty), (1 cost, 90 beauty), (1 cost, 1 beauty)
```贪婪的选择可能会免费获得 100 种美容产品，但如果预算紧张，我们就无法负担其他能产生更高总体美容效果的组合。 最佳策略可能是购买昂贵的物品，并根据预算结构使用免费插槽购买更便宜但仍然有用的物品。 预算决策和自由分配之间的这种耦合使得问题变得非同小可。 

## 方法

 蛮力视图是针对每个项目子集决定采用哪些项目，然后分配最多$k$其中免费。 对于每个子集，我们将计算付费项目的总成本并检查它是否适合$W$，同时最大化整体美感。 这大致探讨了$2^n$子集，甚至计算每个子集中自由项目的最佳分配也不会减少指数爆炸。 和$n = 5000$，这是不可能的。 

关键的观察结果是自由选择与背包结构局部相互作用。 我们可以将自由选择直接纳入动态规划状态，而不是全局首先或最后决定自由项目。 诀窍是通过添加一个维度来扩展经典的背包 DP，该维度可跟踪到目前为止已使用了多少免费物品。 

我们根据项目、预算和使用的免费选择数量定义 DP。 每个项目要么被忽略，要么免费获取（如果仍有配额），要么通过支付其成本来获取。 这将组合分配问题转化为分层背包问题，其中每一层对应于已使用的免费物品数量。 

这是有效的，因为问题引入的唯一耦合是极限$k$，并且该约束纯粹基于基数，不依赖于权重或值。 这使得它适合额外的 DP 维度，而不需要更复杂的结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 3D DP（项目×预算×免费计数）|$O(n \cdot W \cdot k)$|$O(W \cdot k)$| 已接受 |

 ## 算法演练

 我们构建了一个动态编程表，其中每个状态代表在考虑项目前缀、花费一定数量的金钱和使用一定数量的空闲槽位后可实现的最佳美感。 

1. 初始化一个DP数组，其中$dp[w][f]$代表了总支付成本可实现的最大美感$w$确切地说$f$使用的免费物品。 所有状态一开始都是无效的，除了$dp[0][0] = 0$。 这相当于不选择任何内容。 
2. 一颗一颗地处理每颗宝石。 对于每个项目，我们创建一个新的 DP 层，以便转换不会覆盖同一迭代中稍后所需的状态。 
3. 对于每个当前状态$(w, f)$，我们考虑三种可能性。 首先，我们跳过该项目，保持状态不变。 这会保留所有先前的选择。 
4. 其次，如果我们还有剩余空位（$f < k$），我们免费拿走该物品并过渡到$(w, f+1)$同时增添它的美丽。 这体现了我们可以花免费老虎机而不是金钱的想法。 
5. 第三，如果我们负担得起（$w + w_i \le W$），我们购买该商品，过渡到$(w + w_i, f)$并增添它的美丽。 这代表标准背包行为。 
6. 处理完所有项目后，我们使用以下命令扫描所有状态$w \le W$和$f \le k$，取最大的美感。 

我们使用完整的 2D DP 而不是压缩维度的原因是免费物品和付费成本独立发展，并且必须跟踪两者以避免状态的无效混合。 

### 为什么它有效

 在处理项目的任何时刻，每个 DP 状态都会对已处理项目的有效子集进行编码，并在付费和免费选择之间进行精确区分。 每次转变都保留可行性：付费尊重预算约束，自由选择尊重限制$k$。 由于每个项目仅被考虑一次并被分配三个互斥角色之一，因此项目的每个有效配置恰好对应于一个 DP 路径。 配置和 DP 状态之间的这种双射确保所有最终状态的最大值是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, W, k = map(int, input().split())
    items = [tuple(map(int, input().split())) for _ in range(n)]

    NEG = -10**30

    dp = [[NEG] * (k + 1) for _ in range(W + 1)]
    dp[0][0] = 0

    for w_i, v_i in items:
        ndp = [[NEG] * (k + 1) for _ in range(W + 1)]

        for w in range(W + 1):
            for f in range(k + 1):
                if dp[w][f] == NEG:
                    continue

                val = dp[w][f]

                ndp[w][f] = max(ndp[w][f], val)

                if f < k:
                    ndp[w][f + 1] = max(ndp[w][f + 1], val + v_i)

                if w + w_i <= W:
                    ndp[w + w_i][f] = max(ndp[w + w_i][f], val + v_i)

        dp = ndp

    ans = 0
    for w in range(W + 1):
        for f in range(k + 1):
            ans = max(ans, dp[w][f])

    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接镜像 DP 定义。 使用新鲜的`ndp`数组确保给定项目的转换不会相互干扰。 每个项目恰好贡献三种过渡之一：跳过、免费观看或付费观看。 

一个常见的陷阱是尝试进行就地更新$w$和$f$，这会错误地允许在一次迭代中多次使用同一项目。 分层DP通过分离新旧状态来避免这种情况。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n \cdot W \cdot k)$| 每个项目都放宽了所有州的预算和免费计数网格|
 | 空间|$O(W \cdot k)$| 我们只存储两个 DP 层的大小$W \times k$|

 和$n \le 5000$,$W \le 10000$，并且通常很小$k$，这符合优化 Python 的时间限制，特别是因为转换是简单的整数更新。

 ## 边缘情况

 一个极端情况是当$k = 0$。 该算法仍然有效，因为自由转换永远不会被触发，并且 DP 仅在超出预算时退化为标准 0/1 背包。 例如：```
3 5 0
2 10
3 20
4 30
```DP 从不使用自由维度，并且仅选择第三项，最佳可实现值变为 30。 

另一个边缘情况是当$k \ge n$，所有物品都可以免费拿走。 DP 更喜欢每个项目的自由转换，因为它们从不违反约束。 例如：```
3 5 10
1 10
2 20
3 30
```所有物品自由拿取，结果是60。DP正确积累美貌，不消耗预算。 

第三种情况是预算紧张且占主导地位的项目。 考虑：```
2 3 1
2 10
2 100
```最佳策略是免费获取 100 个美容物品，或者根据 DP 转换购买。 DP 探索两者并正确选择 100。总是选择最高美丽作为免费的贪婪策略可能会在其他配置中失败，但这里 DP 确保两个分配的评估一致。
