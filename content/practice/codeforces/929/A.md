 ## 解决方案
 ## 问题理解

 我们沿着直线获得了自行车站所在的一系列位置。 第一站是阿尔卡迪的出发点（学校），最后一站是他的目的地（家）。 它们之间是中间站，他可以将其用作强制停车点。 

阿尔卡迪只骑自行车出行，但他每次租自行车最多只能骑固定距离`k`。 当他到达车站时，他必须归还当前的自行车，也可以选择换一辆新自行车，然后继续。 他只能在这些车站换自行车。 目标是确定他是否可以到达终点站，如果可以的话，他必须租用的最少自行车数量（算上第一辆）。 

关键的观察结果是，移动仅限于车站之间的跳跃，并且每次骑行必须覆盖长度不超过`k`。 

限制因素`n ≤ 1000`和坐标高达`100000`意味着 O(n²) 的解决方案已经可以接受。 不过结构更简单，所以线性贪婪扫描就足够了。 我们有效地选择覆盖从左到右路径的最少数量的线段。 

当有人尝试始终选择最远的可到达站点而不仔细从正确的当前位置进行更新时，就会出现幼稚的失败情况。 例如，如果车站是`0, 3, 6`和`k = 4`，贪婪必须走 0 → 3 → 6。从错误的原点错误地重新计算可达性的有缺陷的方法可能会跳过有效的转换。 

另一个微妙的情况是当连续站点之间的距离超过`k`。 例如，`0, 5, 6`和`k = 4`即使后面的路段足够小，也使旅行变得不可能。 任何正确的解决方案都必须立即检测到这一点。 

## 方法

 强力解释是将每个站视为一个节点并尝试所有可能的有效移动序列。 从车站出发`i`，我们可以移动到任何车站`j > i`这样`x[j] - x[i] ≤ k`。 然后，我们递归地尝试最小化到达最后车站所需的租赁数量。 

这是可行的，因为问题是有向无环图中的最短路径，但探索所有路径在最坏的情况下会导致指数分支。 和`n = 1000`，这变得完全不可行。 

关键的结构见解是图是有序的并且边仅向前移动。 这意味着一旦我们决定从车站骑自行车`i`，最好的下一站是可到达的最远的站，因为任何较早的选择只会减少未来的到达范围。 这就把问题变成了贪婪行走：在距离内尽可能向右重复跳跃`k`。 

我们只需要维护一个指向距离当前位置最远可达站点的指针，然后移动到那里，计算我们使用了多少个路段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们按从左到右的顺序处理电台。 

1. 从站 0（索引 0）开始，使用当前位置指针。 
2. 从当前车站开始，向前扫描寻找距离当前车站最远的车站`k`。 
3. 如果不存在这样的车站，则行程无法进行，我们会立即停车。 
4. 移动到最远的车站并将自行车数量增加 1。 
5. 重复直到到达终点站。 

我们总是选择最远的可达站的原因是，任何更近的选择都会严格减少或保留与下一个位置相同的剩余可达集，而不会扩展它。 由于所有未来的决策仅取决于当前的位置，因此最大化即时进展是最佳的。 

### 为什么它有效

 在任何车站`i`，将可达站点集合定义为所有`j > i`这样`x[j] - x[i] ≤ k`。 任何有效的解决方案都必须从该集合中选择其下一个站点。 如果我们选择最远的`j`，那么从任何较小的选择可到达的每个站点也可以从`j`， 因为`x[j]`是最大的。 这保留了可达性并最大限度地减少了换乘次数，这直接对应于最大限度地减少自行车租赁。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    x = list(map(int, input().split()))
    
    i = 0
    ans = 0
    
    while i < n - 1:
        j = i
        while j + 1 < n and x[j + 1] - x[i] <= k:
            j += 1
        
        if j == i:
            print(-1)
            return
        
        ans += 1
        i = j
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现保留一个指针`i`对于当前电台。 内循环前进`j`尽可能地保持距离`k`从`x[i]`。 如果`j`不动，说明连下一站都无法到达，所以答案是`-1`。 

每次成功的移动都会增加自行车租赁的数量，并直接跳转到最远的可达车站，确保最少的转换。

 ## 边缘情况

 当两个连续站点相距较远时`k`，内循环立即失败，因为`j`无法超越`i`。 用于输入`2 3`有职位`0 10`，算法开始于`i = 0`，看不到有效的`j`，并返回`-1`直接地。 这符合阿尔卡季从不走路的要求。 

当所有站点都在一段长度内时`k`， 例如`0 2 4 6`和`k = 10`，内循环总是一步到达最后一站。 算法增量`ans`一旦完成，正确地减少租金。 

当贪婪的选择显得不明确时，例如`0 3 5 7 10`和`k = 5`，算法总是推送到最远的可达站，产生`0 → 5 → 10`，这避免了不必要的中间租金，并确认局部最大跳跃保持了全局最优性。
