 ## 解决方案

 ## 问题理解

 我们拥有三组独立的球员：守门员、后卫和前锋。 每个球员都有一个独特的球衣号码。 我们必须组建一支由一名守门员、两名后卫和三名前锋组成的球队。 

仅当六名选定的球员满足球衣号码的全局限制时，选择才有效：对于任何一对选定的球员，较大号码最多只能是较小号码的两倍。 同样，如果我们取所选集合中的最小和最大数字，则最大值不能超过最小值的两倍。 

任务是计算在这些角色约束和数值约束下可以组建多少个有效团队。 

玩家总数最多为 1000，这立即排除了任何试图枚举跨组的所有六人组的方法。 即使是天真的组合计数$\binom{1000}{6}$远远超出了可行的限度。 然而，1000 个元素已经足够小了$O(n^2)$或者$O(n^2 \log n)$方法是可行的。 

一个微妙的边缘情况来自不同组中看起来重复的值：即使数字在全球范围内不同，但不同的角色组可能包含重叠范围内的数字。 另一个边缘情况是当有效窗口非常小时，例如，当只有少数数字满足比率约束时，如果不仔细处理计数，这可能会使简单的滑动窗口推理失败。 

## 方法

 直接的强力方法是选择一名守门员，然后选择所有后卫，然后选择所有三人前锋，并检查每个组合的状况。 这已经给出了$O(g \cdot d^2 \cdot f^3)$在最坏的解释中，如果我们显式扩展组合，即使对于最小的约束，组合也太大了。 

即使我们仔细对待组合，单独迭代所有三元组也是如此$O(f^3)$，并且自从$f \le 1000$，这已经是$10^9$，这是不可接受的。 

关键的观察结果是约束仅取决于所选六个数字的最小值和最大值。 一旦我们确定了候选最小值和最大值，所有有效选择都必须完全位于该数字区间内，并且每个选定的玩家必须属于三个组之一。 这将问题从枚举子集转移到对排序数组上受限滑动窗口内的组合进行计数。 

如果我们将所有玩家排序在一起，那么对于每个可能的左边界，我们可以扩展右边界，同时保持端点之间的比率最多为二的条件。 在这样一个窗口内，我们只需要计算有多少种选择1个守门员、2个后卫和3个前锋的方法。 由于各组是独立的，因此这成为组合计数的乘积：$C(g_i, 1) \cdot C(d_i, 2) \cdot C(f_i, 3)$窗内，在哪里$g_i, d_i, f_i$是窗口中每个角色的计数。 

剩下的问题是在我们滑动窗口时有效地维护这些计数。 由于玩家总数最多为 1000 人，因此具有角色计数前缀累积的两指针方法在线性时间内有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力战胜所有团队|$O(g \cdot d^2 \cdot f^3)$|$O(1)$| 太慢了 |
 | 排序+两个指针+组合|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们对所有球员按角色进行标记后统一对待，然后按球衣号码对他们进行排序。 

1. 按号码对所有球员进行排序，记录每个球员是守门员、后卫还是前锋。 需要进行排序，以便任何有效的团队在值范围方面都对应于连续的窗口。 
2. 保持两个指针，左、右。 当条件 max ≤ 2 * min 成立时，右指针扩展。 由于数组已排序，min 位于左侧，max 位于右侧。 
3. 对于每个左侧位置，确保右侧指针在仍然有效的情况下尽可能位于右侧。 这保证了从左侧开始的每个有效间隔都被仅考虑一次。 
4. 在当前窗口内，维护每个角色的计数：g_count、d_count、f_count。 
5. 如果窗口满足 g_count ≥ 1、d_count ≥ 2、f_count ≥ 3，则在该窗口中选择有效团队的方法数为：$g\_count \cdot \binom{d\_count}{2} \cdot \binom{f\_count}{3}$。 
6. 将此贡献添加到答案中。 
7. 向左向前移动时，从计数中删除最左边的元素，然后再继续。 

关键的实现细节是必须使用预先计算的方法有效地计算组合值$nC2$和$nC3$公式：$nC2 = n(n-1)/2$,$nC3 = n(n-1)(n-2)/6$。 

### 为什么它有效

 任何有效的球队都有明确定义的最小和最大球衣号码。 因为条件仅取决于这些极端值，所以所有六名玩家都必须位于由最小值和最大值定义的区间内。 我们的滑动窗口一次性枚举了所有此类间隔。 在每个间隔内，每个有效团队都是通过独立于该间隔内的计数选择角色来唯一确定的，因此计算每个窗口内的组合只会对每个有效团队计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def c2(x):
    return x * (x - 1) // 2

def c3(x):
    return x * (x - 1) * (x - 2) // 6

def solve():
    g, d, f = map(int, input().split())
    
    arr = []
    
    for x in map(int, input().split()):
        arr.append((x, 0))  # goalie
    
    for x in map(int, input().split()):
        arr.append((x, 1))  # defender
    
    for x in map(int, input().split()):
        arr.append((x, 2))  # forward
    
    arr.sort()
    
    n = len(arr)
    ans = 0
    
    dg = dd = df = 0
    r = 0
    
    for l in range(n):
        while r < n and arr[r][0] <= 2 * arr[l][0]:
            if arr[r][1] == 0:
                dg += 1
            elif arr[r][1] == 1:
                dd += 1
            else:
                df += 1
            r += 1
        
        if dg >= 1 and dd >= 2 and df >= 3:
            ans += dg * c2(dd) * c3(df)
        
        # remove left element
        if arr[l][1] == 0:
            dg -= 1
        elif arr[l][1] == 1:
            dd -= 1
        else:
            df -= 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将所有玩家合并到带有角色标签的单个列表中。 排序可确保任何有效团队都被限制在连续的数字段中。 两指针扩展保持每个左端点的最大有效范围。 

组合部分是本地化的：一旦窗口固定，我们只计算有多少种选择角色的方式，而不关心位置。 公式为$C(n,2)$和$C(n,3)$避免重复的嵌套循环。 

一个微妙的点是，当左指针向前移动时，右指针永远不会重置。 这是有效的，因为数组已排序并且约束是单调的：缩小左边界只能增加未来右扩展的有效性。

 ## 边缘情况

 当数值约束极其严格时，就会出现一种边缘情况。 例如：```
1 2 3
100
1 2
3 4 5
```这里任何有效的团队都必须位于一个狭窄的区间内，但该区间内的角色计数仍然可以满足组合数学的要求。 该算法仅正确扩展最多 2 * 分钟，因此 100 左右的窗口排除了所有较小的值并贡献为零。 

另一种情况是有效范围内有很多玩家但角色分配不充分。 例如：```
1 5 0
10
1 2 3 4 5
```尽管有很多后卫，但缺少前锋会导致贡献为零。 该算法在应用组合公式之前显式检查计数阈值，以防止无效贡献。 

最后一个微妙的情况是当窗口有效但缩小左边界会显着增加右边界扩展时。 单调指针行为确保不会跳过任何有效间隔，因为每个左位置都以其最大可到达右边界精确处理一次。
