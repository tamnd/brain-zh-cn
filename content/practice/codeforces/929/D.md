 ## 解决方案

 ## 问题理解

 该问题描述了一个由以下组成的一维世界$n$区域排列成一条线。 移动只能在相邻区域之间进行，因此从区域$i$你可以去$i-1$或者$i+1$如果它们存在的话。 相邻区域之间的每个边界都有一种颜色，该颜色决定是否允许您穿过它。 

限制是跨越颜色边界$c$仅当您之前访问过至少一个包含授予颜色钥匙的神社的区域时才可能$c$。 每个区域都包含一个神殿，每个神殿都为您提供一个颜色键。 一旦获得钥匙，该颜色的所有边界都可以自由跨越任意次数，并且每次跨越需要花费一步。 参拜神社本身并不消耗招式。 

我们被要求计算从区域出发所需的最少过境次数$a$到区域$b$，从根本没有钥匙开始。 如果无法到达$b$，答案是$-1$。 

该结构看似简单：一个折线图，但遍历边缘的能力取决于一组动态增长的“解锁颜色”，解锁颜色的唯一方法是通过物理方式到达如果不提前解锁就无法访问的区域。 

限制因素$n \le 100{,}000$排除任何在从头开始重新计算可访问性的同时重复模拟最短路径的方法。 对形式状态的朴素 BFS$(position, key set)$这是不可能的，因为密钥集很大并且以组合方式增长。 即使在解锁每种新颜色后重复 Dijkstra 运行也会太慢。 

当贪婪运动假设“应立即获取最近的有用颜色的神殿”时，就会出现微妙的失败情况。 例如，假设您需要颜色 1 向左移动，但最近的颜色 1 神殿位于颜色 2 的墙后面，这本身就需要在行中更深的地方有一个不同的神殿。 即使存在绕道解锁序列，总是朝着目标前进而不计划获取密钥的天真的贪婪行走可能会过早地陷入困境。 

## 方法

 关键的观察结果是，一旦已知一组颜色，线路结构就会使可达性区间结构良好。 

如果我们暂时假设我们已经知道哪些颜色可用，那么问题就会简化为图中的最短路径，其中仅存在允许的颜色的边。 在一条线上，最短路径只是可达区域之间边缘的距离。 

困难在于可用颜色的集合取决于我们已经可以到达的区域，因为按键位于区域本身。 

暴力策略会尝试直接模拟这种依赖关系。 可以从以下位置运行 BFS：$a$，但是每当我们进入一个新区域时，我们都会将其颜色添加到可用的集合中，然后重新启动 BFS 来传播新解锁的边。 在最坏的情况下，每个$n$颜色会触发整个可到达区域的重新扩展，从而导致$O(n^2)$行为。 

关键的见解是我们永远不需要以有意义的方式重新访问同一个区域。 我们不再考虑包含键的状态，而是翻转视角：将每种颜色视为“激活”沿该颜色所有边缘的运动，并询问该激活何时变得有用。 

这表明了一个两层结构：我们需要知道，对于每种颜色，它的神殿出现在哪里，对于每种颜色，我们是否至少到达过其中一个神殿。 一旦我们到达色彩的神殿$c$， 颜色$c$变得全球可用，我们可以自由地遍历该颜色的所有边缘，有可能解锁更多的神殿。 

这自然地被建模为同时针对颜色和位置的 BFS，但通过扩展线路上的可达段来有效实现。 

我们从一开始就维持当前的可达间隔，并在解锁新颜色时扩展它。 每次我们在可到达区域内或附近发现神殿时，我们都会解锁其颜色，然后尝试使用该颜色的所有边缘再次扩展。 由于每个区域和每种颜色仅处理一次，因此总工作量保持线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 BFS（位置、键集）| 指数| 指数| 太慢了 |
 | 最佳间隔 + BFS 颜色 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题重新定义为从以下位置发现可达区域的过程：$a$，而一旦遇到该颜色的神社，就会逐渐解锁颜色。 

1.我们预处理邻接信息：对于每种颜色，存储包含该神社颜色的所有区域的位置。 这使我们能够在第一次到达颜色的任何区域时快速激活颜色。 
2.我们还按颜色对边进行分组，因为遍历颜色的边$c$一旦成为可能$c$已解锁。 
3.我们从区域开始$a$，将其标记为已访问，并用它初始化 BFS 队列。 我们还维护一组未锁定的颜色，最初是空的。 
4. 处理区域时$x$，我们立即解锁它的神社颜色$k[x]$如果尚未解锁。 这是获得新的遍历能力的唯一方法。 
5.当有新颜色时$c$解锁后，我们扫描所有颜色边缘$c$。 这些已经可达的边缘的任何端点现在都可以通过这些边缘进一步传播，从而有效地沿着通过颜色连接的所有组件扩展我们的可达区域$c$。 
6. 我们在区域上执行 BFS，但我们只将邻居入队$y$如果之间的边缘$x$和$y$具有已解锁的颜色。 这确保我们只穿越合法的边缘。 
7. 当我们第一次到达区域时我们停下来$b$，因为 BFS 保证了遍历边的最少数量。 

### 为什么它有效

 在每一步中，解锁颜色组与当前可到达区域中已到达圣地的颜色组完全匹配。 由于移动只能沿着已解锁的颜色进行，因此任何新可到达的区域都必须通过一系列已有效的边缘来到达。 BFS 确保我们按照边交叉的递增顺序探索所有此类序列。 

不变的是，BFS 边界始终表示使用最小交叉数的当前解锁颜色集可到达的所有区域，并且解锁新颜色只会扩展该集，而不会使之前计算的距离无效。 访问任何区域的成本都不会高于必要的成本，因为 BFS 按距离递增顺序处理状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque, defaultdict

n, a, b = map(int, input().split())
a -= 1
b -= 1

g = list(map(int, input().split()))
k = list(map(int, input().split()))

edges = defaultdict(list)
for i, c in enumerate(g):
    edges[c].append(i)

pos_of_color = defaultdict(list)
for i, c in enumerate(k):
    pos_of_color[c].append(i)

adj = [[] for _ in range(n)]
for i, c in enumerate(g):
    adj[i].append((i + 1, c))
    adj[i + 1].append((i, c))

unlocked = set()
dist = [-1] * n
dist[a] = 0

q = deque([a])

while q:
    x = q.popleft()

    c = k[x]
    if c not in unlocked:
        unlocked.add(c)

    for y, col in adj[x]:
        if dist[y] == -1 and col in unlocked:
            dist[y] = dist[x] + 1
            q.append(y)

print(dist[b])
```该实现为线构造一个标准邻接列表，存储每条边的颜色。 BFS 是从起始区域开始运行的，我们只遍历颜色已经解锁的边。 

每次我们访问一个节点时，我们都会解锁它的神社颜色。 这确保了一旦某个区域变得可访问，其颜色立即可用于未来的扩展。 

一个常见的微妙之处是，当新颜色被解锁时，我们不会重新启动 BFS。 相反，BFS 自然会继续，因为新允许的边会根据更新的边进行动态检查`unlocked`放。

 ## 边缘情况

 关键的边缘情况是起始区域已经包含有用的颜色，但其边缘在 BFS 到达相邻区域之前尚不可用。 该算法自然地处理这个问题，因为解锁只影响遍历条件，而不影响立即移动。 

另一个微妙的情况是当一种颜色需要到达它自己的圣地时。 这是不可能发生的：神社已经在一个区域中，因此解锁永远不需要预先存在对相同颜色的访问，从而防止颜色级别的循环依赖。 

最后一种情况是长链，其中每个区域准确地解锁下一个所需的颜色。 在这样的配置中，BFS 一次增长一步，但每一步都会触发新的颜色解锁，并且队列单调扩展而无需重新访问，始终保持线性行为。
