 ## 解决方案
 ## 问题理解

 该问题描述了一条从起点 Ruby 坐标处延伸的线`0`朝正门方向。 守卫站在固定的坐标上，每个守卫仅在一定的时间间隔内处于活动状态。 情侣们在不同的整数开始时间从 Ruby 开始步行，每秒移动一个单位的距离。 对于每对夫妇，我们需要确定他们在遇到第一个警卫之前走过的距离，或者报告`-1`如果他们到达终点而没有遇到任何人。 

坐标处的守卫`X`间隔期间处于活动状态`[L-z, R-z]`， 在哪里`z`是一个小于的小正值`0.1`。 一对夫妇同时开始`T`恰好在到达这名守卫之后`X`秒，一次`T + X`。 被抓的条件是：`L - z <= T + X <= R - z`重新排列：`L - X - z <= T <= R - X - z`输入值是整数，而`z`是一个很小的正分数。 这改变了整数边界。 最小有效整数`T`是`L - X`， 因为`L - X`仍然大于`L - X - z`。 最大有效整数`T`是`R - X - 1`， 因为`R - X`分数已经太大了`z`。 

所以每个守卫都可以被视为创建一个时间间隔：`[L - X, R - X - 1]`在此间隔内的每个整数开始时间内，该警卫都可以抓住这对夫妇。 

限制最多允许`200000`警卫和`200000`情侣。 任何检查每对夫妇对抗每名警卫的方法都需要大约`4 * 10^10`操作，这远远超出了几秒钟允许的范围。 我们需要一个接近的解决方案`O((M+N) log M)`。 

一个常见的错误是忘记分数的影响`z`。 例如：```
1 1
0 1 5
5
```守卫活跃于`-0.1`到`0.9`。 夫妻俩到达坐标`5`在某个时间`10`，所以答案是`-1`。 使用的错误转换`[L-X, R-X]`会错误地包含开始时间`-5`仅在其他情况下并且可以将边界移动一倍。 

另一个棘手的情况是一个守卫在没有小数移位的情况下精确到达了右端点：```
1 1
10 20 5
15
```这对夫妇及时到达了警卫处`20`。 原始活动间隔结束于`19.9`，所以守卫不再存在。 正确的输出是：```
-1
```将间隔视为整数端点封闭会错误地输出`5`。 

## 方法

 直接的方法是独立模拟每对夫妇。 对于每个开始时间，我们都会检查每个守卫，并查看这对夫妇是否在该守卫处于活动状态时到达该守卫。 如果多个守卫匹配，我们保留最小的坐标，因为这对守卫停在遇到的第一个守卫处。 这是正确的，因为它直接模拟运动，但最坏的情况执行`M * N`检查。 两个值都等于`200000`，这大约变成四百亿次比较。 

有用的观察结果是查询已经按开始时间排序。 我们不必向每个警卫询问每对情侣的情况，而是可以扫过一次时间。 每个守卫在某个时间变得活跃`L-X`并在一段时间后停止活动`R-X-1`。 在按升序处理对时`T`，我们只需要知道当前活跃守卫中的最小坐标。 

一个优先级队列就足够了。 当守卫开始活动时，我们插入它的坐标和结束时间。 在回答查询之前，我们删除所有结束时间小于当前开始时间的守卫。 堆中剩余的最小坐标是这对夫妇将遇到的第一个守卫。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(明尼苏达) | O(1) | O(1) | 太慢了|
 | 最佳| O((M+N) log M) | O(M)| 已接受 |

 ## 算法演练

 1. 将每个守卫转换为一个时间间隔。 对于坐标处的守卫`X`，存储它在开始时间处于活动状态`L-X`到`R-X-1`。 坐标`X`与间隔一起存储，因为它是我们需要输出的值。 
2. 将所有转换后的保护间隔按照起始时间排序。 排序很有用，因为情侣也按递增的顺序到达，因此可以在它们变得相关时准确添加守卫。 
3. 从最小开始时间到最大开始时间处理对。 在回答几个之前，添加转换间隔开始时间不晚于当前时间的每个警卫。 这些是唯一可能影响这对夫妇或后来的夫妇的新守卫。 
4. 当守卫的结束时间小于当前守卫的开始时间时，将其从优先级队列中移除。 这样的守卫已经不再活跃了。 
5. 如果堆为空，则没有守卫可以捕获这对情侣，因此输出`-1`。 否则，堆中的最小坐标是遇到的第一个守卫。 

为什么它有效：

 任何查询时间`T`，堆恰好包含变换间隔包括的守卫`T`。 不在堆中的每个守卫要么稍后启动，要么已经过期。 在所有活跃的守卫中，这对夫妇首先到达物理上最小的坐标，因此取最小值`X`给出正确答案。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    data = input().split()
    if not data:
        return

    M, N = map(int, data)

    guards = []
    for _ in range(M):
        L, R, X = map(int, input().split())
        guards.append((L - X, R - X - 1, X))

    guards.sort()

    queries = []
    for _ in range(N):
        queries.append(int(input()))

    heap = []
    ans = []
    idx = 0

    for t in queries:
        while idx < M and guards[idx][0] <= t:
            start, end, x = guards[idx]
            heapq.heappush(heap, (x, end))
            idx += 1

        while heap and heap[0][1] < t:
            heapq.heappop(heap)

        if heap:
            ans.append(str(heap[0][0]))
        else:
            ans.append("-1")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```守卫转换是实现中最微妙的部分。 结束时间必须是`R-X-1`， 不是`R-X`，因为由于正值，原始间隔稍早于该整数时间结束`z`。 

堆存储`(coordinate, ending_time)`。 坐标是首要任务，因为我们需要最近的守卫。 保留结束时间，以便稍后可以删除过期的防护装置。 

查询已在输入中排序，因此不需要额外排序。 指针`idx`只向前移动，这意味着每个守卫进入堆一次，最多离开堆一次。

 ## 边缘情况

 当一对夫妇到达时恰好结束的警卫不得抓住他们。 输入：```
1 1
10 20 5
15
```给出变换后的区间`[5,14]`。 查询时间为`15`，它在间隔之外，因此堆在应答并返回之前移除了防护`-1`。 

必须包括在一对夫妇到达时恰好开始的守卫。 为了：```
1 1
3 4 2
1
```变换后的区间为`[1,1]`。 在处理时间之前插入防护装置`1`，保持活跃，答案是`2`。 

同一坐标多个守卫也自然处理。 堆可能包含多个具有相同坐标的条目，并且返回最小值仍然给出正确的停止距离。 输入保证同一坐标处的间隔不重叠，以防止冲突的同时状态导致歧义。
