 ## 解决方案
 ## 问题理解

 我们有两个长度相等的字符串。 第一个字符串是起始排列，第二个字符串是我们想要达到的目标排列。 仅当两个相邻字符属于不同组时才允许移动：一组包含类似的字母`a`,`c`,`e`，其中字母表中的位置是奇数，另一个包含类似的字母`b`,`d`,`f`，其中字母表中的位置是偶数。 这样的相邻字符可以被交换。 

问题是某些有效交换序列是否可以将第一个字符串转换为第二个字符串。 

每个字符串的长度可以达到$10^5$。 这立即排除了尝试模拟可能的交换序列或探索状态的方法，因为即使每个位置的线性数量的选择也会创建巨大的搜索空间。 有效的解决方案需要检查字符串少量次，这意味着$O(n)$或者$O(n \log n)$方法是合适的。 

主要陷阱来自假设字符的每种排列都是可能的。 例如：```
Special:  ab
Elegant:  ba
```答案是`Yes`， 因为`a`和`b`来自不同组，可以直接交换。 

一个更微妙的情况是：```
Special:  abc
Elegant:  cba
```答案是`No`。 字母`a`和`c`属于同一组，因此它们永远不能相互交叉。 仅检查两个字符串是否包含相同字母的粗心解决方案将错误地接受这种情况。 

另一种边缘情况是当字符串已经具有相同的组顺序但组的位置不同时：```
Special:  abcde
Elegant:  baced
```答案是`Yes`。 奇数位置字母的相对顺序为`ace`在两个字符串中，偶数位置字母的相对顺序是`bd`在两个字符串中。 允许的交换可以重新安排这两个组的交错方式。 

## 方法

 暴力解决方案将尝试执行有效的交换并搜索可以创建的所有可能的字符串。 这是正确的，因为每个可到达的状态最终都会被探索，但状态的数量增长得非常快。 一个长度的字符串$10^5$有太多可能的安排，因此这种方法不可用。 

一个更简单但仍然低效的想法是重复查找当前位于错误位置的角色，并使用相邻交换将其移向目的地。 每个动作都可以采取$O(n)$时间，并且对许多角色执行此操作可能会导致$O(n^2)$运营。 和$10^5$人物，那将是周围$10^{10}$最坏情况下的操作。 

关键的观察结果是该操作仅交换来自不同组的字符。 来自同一组的角色永远不会互相超越。 如果我们从两个字符串中删除所有偶数字母位置字母，则它们的剩余顺序必须相同。 删除所有奇数字母位置字母后也必须如此。 

这两个子序列是唯一不能改变的信息。 一旦匹配，这两个字符串就只是相同两个序列的不同交织。 任何此类交错都可以通过重复交换来自不同组的相邻字符来获得，因为该操作恰好是将一个组元素移动到另一组的元素之间。 

蛮力之所以有效，是因为它遵循每一个合法的举动，但它失败了，因为有太多可能的举动。 对保留子序列的观察将整个问题简化为检查两个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 重复相邻运动| O(n²) | O(1) | O(1) | 太慢了|
 | 保留的子序列 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将两个字符串分成两个子序列。 第一个子序列包含具有奇数字母位置的字母，第二个子序列包含具有偶数字母位置的字母。 对起始字符串和目标字符串都执行此操作。 
2. 将第一个字符串中的奇数位置字母子序列与第二个字符串中的奇数位置字母子序列进行比较。 

这些字符永远不能改变它们的相对顺序，因为有效的交换只能将它们移动到另一组的字符周围。 
3. 以同样的方式比较偶数位置的字母子序列。 

同样的推理也适用：两个偶数位置的字母永远不能互换。 
4. 如果两对子序列相同，则打印`Yes`。 否则，打印`No`。 

匹配子序列意味着两个字符串在两个组中包含相同的固定顺序。 剩下的区别只是这两个组如何混合在一起，而这些更改正是允许的交换可以创建的。 

为什么它有效：

 每个有效的交换将一个奇数位置的字母与一个偶数位置的字母交换。 因此，任何一个组织都不能改变其内部秩序。 任何可到达的目标都必须保留两个子序列。 

相反的方向也成立。 假设两个子序列匹配。 将奇数和偶数字母视为必须合并到目标顺序的两个队列。 从原始字符串开始，相邻交换可以将下一个所需的字母从任一队列移动到另一个队列的字母之间，直到到达所需位置。 由于所有交叉的字母都属于相反的组，因此每次这样的交换都是有效的。 重复此过程即可构造目标字符串，因此匹配子序列也足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    s_odd = []
    s_even = []
    t_odd = []
    t_even = []

    for c in s:
        if (ord(c) - ord('a') + 1) % 2 == 1:
            s_odd.append(c)
        else:
            s_even.append(c)

    for c in t:
        if (ord(c) - ord('a') + 1) % 2 == 1:
            t_odd.append(c)
        else:
            t_even.append(c)

    if s_odd == t_odd and s_even == t_even:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```该代码构建了四个列表。 前两个存储按组分隔的起始字符串中的字符，另外两个对目标字符串执行相同的操作。 

字母位置计算使用`ord(c) - ord('a') + 1`因为`ord`从零开始计数`a`，而问题的分组从 1 开始。 这里错误的奇偶校验计算会交换两组，并使每个答案都不正确。 

最终的比较就足够了，因为字符串的其他属性都不会影响可达性。 每个组内的相对顺序是在所有有效操作中幸存下来的唯一信息。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符串被扫描一次并比较子序列 |
 | 空间| O(n) | 分开的子序列一起包含所有字符 |

 最大长度为$10^5$，因此线性扫描很容易满足时间限制。 内存使用量也完全在 256 MB 限制之内。

import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    s = sys.stdin.readline().strip()
    t = sys.stdin.readline().strip()

    s_odd = []
    s_even = []
    t_odd = []
    t_even = []

            s_odd.append(c)

            s_even.append(c)

            t_odd.append(c)
        else:
            t_even.append(c)

    ans = "Yes" if s_odd == t_odd and s_even == t_even else "No"

    sys.stdin = old_stdin
    return ans + "\n"

assert solve_case("potha\nopath\n") == "Yes\n", "sample 2"

 ## 边缘情况

 对于这个案例：```
Special:
abc

Elegant:
cba
```该算法将两个字符串分为奇数组和偶数组。 的奇数子序列`abc`是`ac`，而奇数子序列`cba`是`ca`。 由于它们不同，算法返回`No`。 失败的原因是试图颠倒两个永远无法交换的字母。 

对于这个案例：```
Special:
ab

Elegant:
ba
```奇数子序列都是`a`，偶数子序列都是`b`。 算法返回`Yes`。 角色可以交换位置，因为他们来自相反的群体。 

对于这个案例：```
Special:
aaaa

Elegant:
aaaa
```两个子序列是相同的，因为每个字符都是同一组。 算法返回`Yes`立即地。 这可以处理重复的字符，而不会意外地需要唯一的位置。 

对于这个案例：```
Special:
potha

Elegant:
opath
```奇数组是`oah`在两个字符串中，偶数组是`pt`在两个字符串中。 该算法接受这种转换，因为唯一需要的改变是一组通过另一组的移动。
