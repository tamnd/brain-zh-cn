 ## 解决方案
 ## 问题理解

 令牌机存储一组插入的整数。 有效的令牌编号不是直接插入的值之一。 相反，它是可以通过选择存储数字的某个子集（包括其 XOR 为零的空子集）来获得的任何 XOR 值。 每次插入后，客户都会在所有不同的可能 XOR 值的排序列表中的某个位置请求令牌。 任务是在继续插入的同时回答这些订单统计查询。 引用turn0搜索0

 输入最多包含\(10^6\)运营。 一次插入最多给出一个整数\(10^9\)，并且查询要求所有生成的 XOR 值中有效的单索引位置处的值。 由于操作数量非常大，即使每个查询需要 O(\sqrt{q})\) 的方法也会太慢。 我们需要一个接近每位操作恒定时间的解决方案。 这些值适合 30 位，因为\(10^9 < 2^{30}\)，所以自然是空子集。 答案是：```text
0
```假设至少有一个存储的数字的粗心解决方案在这里会失败。 

另一个重要的情况是重复插入：```text
3
1 5
1 5
2 2
```可能的 XOR 值只有`0`和`5`，所以第二个标记是：```text
5
```如果我们计算插入的数字而不是独立的异或方向，我们会错误地认为有四个可能的子集异或。 

最后一个棘手的情况是插入的数字是线性相关的：```text
3
1 1
1 2
1 3
```第三个数字没有添加新信息，因为`1 XOR 2 = 3`。 生成的值仍然存在`{0,1,2,3}`。 每次插入后盲目地将值的数量加倍的方法会导致计数过多。 

## 方法

 直接方法将存储每个生成的 XOR 值。 如果有\(k\)机器中独立的编号，有\(2^k\)不同子集异或结果。 我们可以枚举每个子集，计算其异或，删除重复项，对结果进行排序，并按索引回答查询。 这是正确的，因为每个可能的标记都恰好来自一个子集 XOR。 问题是，即使\(k=60\)已经创建了不可能的数据量，并且独立值的数量会随着插入的数量而增加。 最坏情况的工作是指数级的，大约\(O(2^k)\)，这对于\(10^6\)运营。 

关键的观察结果是，XOR 的行为类似于二进制向量空间中的加法。 插入的数字不会创建任意的值集。 它们在位上创建线性跨度。 二元线性基存储该跨度的独立方向。 如果基础尺寸是\(k\)，正好有\(2^k\)独特的异或结果。 

剩下的挑战是找到\(n\)- 此有序范围中的第一个最小值，而不生成所有值。 一旦基被简化为一种特殊的有序形式，每个基向量独立地控制一个二进制位置。 我们可以贪心地从最高位到最低位决定答案的位。 对于每一位，我们都知道有多少生成的值该位为零。 如果请求的位置位于该组内，则答案将该位保持为零。 否则，我们跳过该组，从位置中减去其大小，并将该位设置为 1。 

蛮力之所以有效，是因为它明确地表示向量空间，但当空间变大时就会失败。 空间具有紧基的观察结果使我们可以直接在该基上执行相同的排序逻辑。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | \(O(2^k)\) | \(O(2^k)\) | 太慢了|
 | 最佳| 每次查询或插入 \(O(30)\) | \(O(30)\) | 已接受 |

 ## 算法演练

 1. 保持插入数字的二进制线性基础。 对于每个插入的值，尝试使用现有的基向量删除其最高设置位。 如果该值变为零，则它已经由之前的数字表示，并且不会增加可能的令牌数量。 否则，将其存储为新的独立基向量。 

2. 每次成功插入后，将基础重建为简化形式。 对于从高到低的每个位位置，从所有较低的基向量中删除该位。 这使得每个基向量负责一个唯一的位，这使我们能够计算有多少生成的值的某个位等于零。 

3. 回答职位查询\(n\)，从高到低处理位。 假设有\(cnt\)剩余的基向量可以影响较低位。 在剩余的可能性中，恰好有一半当前位等于 0，一半当前位等于 1。 零组有大小\(2^{cnt-1}\)。 

4. 如果\(n\)位于零组内，则保持当前应答位为零。 否则，通过从零组的大小中减去零组的大小来移动到第一组\(n\)，将当前答案位设置为 1，然后继续。 

5.如果\(n=1\)，该算法自然返回零，因为空子集是排序顺序中的第一个值。 

不变的是，简化的基表示与所有插入的数字完全相同的异或空间，但每个基向量贡献唯一的最高位。 在查询过程中，每个决策都会根据当前位将剩余的 XOR 值分为两个大小相等的组。 在每个位上选择正确的一半遵循排序顺序，因此在处理所有位之后，构造的值正是所请求的令牌号。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX_BIT = 30

basis = [0] * MAX_BIT
changed = True

def rebuild():
    for i in range(MAX_BIT - 1, -1, -1):
        if basis[i]:
            for j in range(i - 1, -1, -1):
                if (basis[i] >> j) & 1:
                    basis[i] ^= basis[j]

def insert(x):
    global changed
    for i in range(MAX_BIT - 1, -1, -1):
        if ((x >> i) & 1) == 0:
            continue
        if basis[i]:
            x ^= basis[i]
        else:
            basis[i] = x
            changed = True
            return

def kth(x):
    if changed:
        rebuild()
        changed = False

    ans = 0
    cnt = sum(1 for v in basis if v)

    for i in range(MAX_BIT - 1, -1, -1):
        if basis[i]:
            half = 1 << (cnt - 1)
            if x > half:
                x -= half
                ans |= basis[i]
            cnt -= 1

    return ans

def solve():
    global changed
    q = int(input())
    out = []

    for _ in range(q):
        p, n = map(int, input().split())
        if p == 1:
            insert(n)
        else:
            out.append(str(kth(n)))

    sys.stdout.write("\n".join(out))

solve()
```这`basis`数组为每个可能的最高位存储一个向量。 在插入过程中，当前数字会被现有向量减少，就像对二进制值进行高斯消除一样。 如果每一位都消失，则该数字是相关的并且不会改变可能的标记集。 

重建操作将正常基础转换为缩减基础。 此步骤被延迟到查询时，因为可以发生许多插入而无需检查顺序。 这`changed`标志可防止不必要的重复减少。 

查询函数从高位到低位遍历缩减基。 变量`cnt`跟踪剩余多少个独立向量来决定当前零组的大小。 Python 整数处理此处使用的 2 的幂而不会溢出，尽管所需的最大值仅为\(2^{30}\)。 

索引是基于一的。 第一个生成的令牌为零，因此除了直接在减半逻辑中使用给定位置之外不需要特殊处理。 归约和查询顺序是最有可能导致错误的部分，因为使用非归约基础进行查询不会保留排序顺序。

 ## 边缘情况

 对于空机箱：```text
1
2 1
```基数仍然全是零。 该查询没有要分割的向量，因此唯一可能的值是空子集 XOR，它为零。 该算法返回零，因为查询循环没有可供选择的位。 

对于重复值：```text
3
1 5
1 5
2 2
```第一次插入创建一个用于位表示的基本向量`5`。 第二次插入完全减少到零，因为相同的向量已经存在。 该查询仅看到一个独立向量，产生有序值`0, 5`。 

对于依赖值：```text
3
1 1
1 2
1 3
```第三个插入被现有基础消除，因为`3`已经表示为 XOR`1`和`2`。 基础秩仍然是二，所以生成的序列仍然是`0, 1, 2, 3`。 

对于大值：```text
5
1 1000000000
2 1
2 2
2 1
2 2
```最高使用位接近 30 位限制。 该算法仍然只检查固定位位置，因此不需要特殊情况。 即使在最高位，简化的基也能正确区分零和非零选择。
