 ## 解决方案
 ## 问题理解

 我们有一系列分数代表每个科目的当前分数。 有多个操作按固定顺序执行。 操作期间`j`，我们最多可以选择`B_j`主题并用值覆盖他们的分数`C_j`。 一个主题可以被多次选择，但只有最后一次选择它的操作才会影响其最终分数。 

目标是为每次操作选择科目，以便所有分数的最终总和尽可能大。 

的价值观`N`和`M`都可以达到`100000`。 这排除了模拟受试者选择或尝试所有可能的操作任务的方法。 甚至一个`O(NM)`方法将执行周围`10^10`最坏情况下的操作，远远超出了1秒的限制。 我们需要一个接近的解决方案`O((N+M) log N)`。 

主要陷阱来自于操作的顺序和无用的操作。 例如，某个操作可以用较低的值覆盖高分，因此盲目应用每个操作是不正确的。 

考虑这种情况：```
1 1
100
1 50
```正确答案是`100`。 总是执行操作的粗心解决方案将标记更改为`50`并失去价值。 

另一种情况是：```
3 2
5 1 4
2 3
1 5
```正确答案是`14`。 应忽略第一个操作，因为将两个主题更改为`3`是有害的。 第二次操作应该用标记改变主题`1`到`5`。 从一开始就贪婪地处理操作的解决方案可能会在第一个操作上花费主体，并阻止使用更好的后续操作。 

## 方法

 直接方法将尝试为每个操作决定替换哪些对象。 由于每个操作都可以选择许多不同的主题子集，因此可能的选择数量呈指数级增长。 即使是更合理的模拟（为每个操作检查许多候选对象）也会变得太慢。 在最坏的情况下，检查所有操作的所有主题已经花费了成本`10^10`比较。 

蛮力是正确的，因为它探索了对受试者的所有可能的操作分配，但问题的结构允许我们避免明确地做出这些选择。 

重要的观察是影响对象的最后一个操作完全决定了它的最终值。 这意味着我们可以按相反的顺序查看操作。 当向后处理操作时，后面的操作已经选择的每个主题都是固定的，不能再次触及。 其余科目仍保留原来的标记。 

对于有值的反向操作`C`，我们应该只对当前分数小于的科目使用它`C`。 如果我们决定使用该操作，则最好的受试者是得分最小的受试者，因为它们获得相同的替换值。 这将问题转化为重复从数据结构中获取最小值并在出现更好的操作时增加它们。 

最小堆存储仍然可用的主题。 向后处理操作让我们贪婪地提取最小的标记，将它们替换为`C`，然后插入新值。 每个主题只有在操作可以增加它时才会得到改进，并且堆总是暴露出最好的候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(N) | 太慢了|
 | 最佳| O((N + M) log N) | O((N + M) log N) | O(N) | 已接受 |

 ## 算法演练

 1. 将所有初始标记插入最小堆并计算它们的初始总和。 堆代表其最终值尚未由后续操作确定的主题。 
2. 按相反顺序遍历操作。 对于一次手术`(B, C)`，反复查看堆中当前的最小值。 如果它小于`C`，将其替换为`C`，通过添加改进来更新总和，并把`C`回到堆中。 

选择最小值是最佳的，因为每个选定的主题都会收到相同的新值。 最大的改进总是来自于替换最小的当前标记。 
3. 当出现以下任一情况时，停止使用当前操作：`B`科目已得到改善或最小可用值已至少`C`。 

如果最小值不小于`C`，每个其他可用值也不小于，因此使用该操作不能增加答案。 
4. 处理完所有逆运算后，输出维护的和。 

为什么它有效：

 向后处理时考虑任何操作。 后面的操作已经选择的主题是固定的，因为前面的操作不会影响它们的最终值。 剩下的科目中，目前的操作最多只能改善`B`价值观`C`。 最优的选择永远是`B`以下最小值`C`，因为替换任何较大的值都会带来较小的增加。 堆准确地维护了这些候选者，因此每个反向步骤都会做出最佳的本地决策。 由于每个操作都是在所有可以覆盖它的操作之后处理的，因此这些局部选择组合成全局最优分配。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    operations = []
    for _ in range(m):
        b, c = map(int, input().split())
        operations.append((b, c))

    heap = a[:]
    heapq.heapify(heap)

    ans = sum(a)

    for b, c in reversed(operations):
        used = 0
        while used < b and heap[0] < c:
            x = heapq.heappop(heap)
            ans += c - x
            heapq.heappush(heap, c)
            used += 1

    print(ans)

if __name__ == "__main__":
    solve()
```堆包含尚未按原始顺序分配给后续操作的所有标记。 反向遍历使得这种解释成为可能。 

当替换发生时，总和会立即更新，避免了每次操作后重建数组的需要。 Python 整数可以安全地处理可能的大总和，因为总和可以达到`10^14`。 

循环条件检查`heap[0] < c`在替换值之前。 这可以防止有害的替换，也可以避免删除超过可用的有用主题。 堆永远不会变空，因为每个删除的值都会用新标记插回。

 ## 边缘情况

 第一个边缘情况是当操作减少标记时。 为了：```
1 1
100
1 50
```堆开始于`[100]`。 操作处理完毕且最小堆值不小于`50`，所以算法什么也不做，并将答案保持为`100`。 

第二种边缘情况是早期操作可能会阻止更好的后期操作：```
3 2
5 1 4
2 3
1 5
```该算法首先处理`(1,5)`以相反的顺序和变化`1`到`5`。 剩余的值是`4,5,5`， 所以`(2,3)`无法改善任何事情。 最终的答案是`14`，匹配最优选择。 

第三种边缘情况是每个操作的替换值等于或小于当前标记：```
3 2
100 100 100
3 99
3 99
```堆最小值始终为`100`，它不小于`99`。 两个操作都被忽略，答案仍然存在`300`。
