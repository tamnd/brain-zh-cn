 ## 解决方案
 # 问题理解

 我们第一天开始收费 1。 接下来的每一天，新的费用必须通过以下三种操作之一从前一天的费用中获得：加倍、三倍或增加一。 给定目标电荷`D`，我们需要找到所需的最小天数，以便最后一天的费用恰好是`D`。 我们还必须打印一组有效的每日费用序列，以在最短天数内达到目标。 

输入包含多个独立的目标。 由于最大目标仅`10^6`，预期的解决方案可以对所有可能的值进行预处理，直到出现的最大目标。 尝试与每个查询分开搜索的解决方案会浪费工作，因为可能存在`10^5`查询。 在这个规模上，`O(D)`或者`O(maxD)`预处理方法是合适的，而为每个查询独立探索许多路径的算法很容易变得太慢。 

主要边缘情况出现在非常小的值和最佳路线不立即使用最大乘法的值周围。 例如，对于`D = 1`，答案是有一天，顺序就是`1`。 从一步棋开始搜索而不考虑起始状态的实现可能会错误地返回更长的答案。 

为了`D = 5`，最优序列为：```
1 3 4 5
```输出是`4`天。 在可能的情况下总是乘法的贪婪策略可能会选择`1 2 4 5`，有效但这里还有四天，隐藏了问题。 对于较大的值，盲目地选择乘法可能会错过较短的路径，因为达到有用的中间值`+1`可以启用稍后的乘法链。 

为了`D = 10`，一个最短序列是：```
1 2 3 9 10
```答案是`5`天。 仅存储距离而不存储父选择的方法将找到正确的最小长度，但无法重建所需的电荷序列。 

# 方法

 直接的强力解决方案可以对每个可能的操作序列进行建模。 开始于`1`，它会尝试所有组合`+1`,`*2`， 和`*3`直到达到`D`。 这是正确的，因为每个合法序列都被探索过，所以找到的第一个最短序列给出了答案。 问题在于可能性的数量。 后`k`天数最多可达`3^k`不同的操作序列，因此这会呈指数增长，即使对于中等大的目标也是不可能的。 

问题的结构给出了更清晰的视图。 每个电荷值都是图中的一个节点。 从一个值`x`，有边`x + 1`,`2x`， 和`3x`每当这些值不大于我们需要的最大目标时。 每个有效的电荷序列正是该图中的一条路径。 由于每次操作花费一天，因此最短序列是从节点开始的最短路径`1`到节点`D`。 由于所有边的成本相等，因此广度优先搜索会找到最小天数。 

暴力搜索会失败，因为它反复探索相似的部分序列。 BFS 合并所有达到相同电荷值的路径，对每个状态求解一次。 通过为每个访问过的值存储一个父值，我们可以在找到目标后重建精确的序列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3^k) | O(3^k) | O(k) | 太慢了|
 | 最佳| O(最大D) | O(最大D) | 已接受 |

 # 算法演练

 1.读取所有目标值并找到最大的目标`M`。 我们只需要将状态建立到`M`因为在这个问题中，任何有用的中间值都不能超过最终目的地。 所有操作只会增加费用。 
2. 从充电开始运行BFS`1`。 存储每次到达充电的距离以及之前到达该充电所用的距离。 BFS 队列保证在不断增加的天数内处理值。 
3. 对于每次当前充电`x`，尝试接下来三种可能的收费：`x + 1`,`2x`， 和`3x`。 忽略大于的值`M`或已经访问过的值。 第一次访问一个值是通过最短路径，因此它的父值可以永久固定。 
4. 对于每个查询`D`，从`D`并反复跟踪存储的父母，直到达到`1`。 反转此收集的列表以获得按正序排列的每日充电序列。 

工作原理：BFS 会先探索一天内可到达的所有状态，然后再探索两天内可到达的所有状态，然后再探索三天内可到达的所有状态，依此类推。 因此，第一次达到收费值时，所使用的路径具有尽可能少的操作次数。 父指针准确地存储了到每个可到达电荷的一条最短路径，因此从`D`回到`1`重建最优序列。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    t = data[0]
    queries = data[1:1 + t]
    limit = max(queries)

    parent = [-1] * (limit + 1)
    parent[1] = 0

    from collections import deque
    q = deque([1])

    while q:
        x = q.popleft()

        for y in (x + 1, x * 2, x * 3):
            if y <= limit and parent[y] == -1:
                parent[y] = x
                q.append(y)

    ans = []
    for d in queries:
        path = []
        cur = d
        while cur != 0:
            path.append(cur)
            if cur == 1:
                break
            cur = parent[cur]
        path.reverse()

        ans.append(str(len(path)))
        ans.append(" ".join(map(str, path)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```预处理部分构建一次最短路径树。 这`parent`数组有两个用途：`parent[x] == -1`表示尚未达到该值，否则将之前的费用存储在最短路径中。 

BFS 转换顺序不会影响正确性，因为所有操作的成本相同。 唯一需要的条件是每个新发现的状态都添加一次。 高于最大查询的值将被忽略，因为它们永远不能成为以较小目标结束的路径的一部分。 

在重建过程中，路径是从`D`到`1`。 颠倒它就可以得到每日费用的顺序。 天数是序列中值的数量，而不是操作的数量，因为第一天已经包含初始费用`1`。 

# 工作示例

 对于`D = 5`，BFS通过以下最短路径到达目标。 

| 当前电量| 运营| 新收费| 父存储 |
 | --- | --- | --- | --- |
 | 1 | *3 | 3 | 1 |
 | 3 | +1 | 4 | 3 |
 | 4 | +1 | 5 | 4 |

 关注家长来自`5`给出`5 -> 4 -> 3 -> 1`，这反过来为：```
1 3 4 5
```这个例子表明，包含较小增量的序列可以击败仅关注乘法的策略。 

为了`D = 10`，一种可能的 BFS 重建是：

 | 当前电量| 运营| 新收费| 父存储 |
 | --- | --- | --- | --- |
 | 1 | *2 | 2 | 1 |
 | 2 | +1 | 3 | 2 |
 | 3 | *3 | 9 | 3 |
 | 9 | +1 | 10 | 10 9 |

 重构后的序列为：```
1 2 3 9 10
```这说明了为什么必须考虑所有三种转变。 删除`+1`操作会导致某些最佳路径无法到达。 

# 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(最大D) | 每个费用值被访问一次并具有三个传出转换。 |
 | 空间| O(最大D) | 父数组和 BFS 队列存储每个可到达费用的信息。 |

 最大目标是`10^6`，因此预处理最多访问一百万个状态。 这很容易在限制范围内，并且可以避免重复工作`10^5`查询。

import sys
import io
from collections import deque

def solution(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        sys.stdin = old
        return ""

    queries = data[1:1+t]

    parent[1] = 0

        for y in (x + 1, x * 2, x * 3):
            if y <= limit and parent[y] == -1:
                parent[y] = x
                q.append(y)

    out = []
    for d in queries:
        path = []
        while d:
            path.append(d)
            if d == 1:
                break
            d = parent[d]
        path.reverse()
        out.append(str(len(path)))
        out.append(" ".join(map(str, path)))

    sys.stdin = old
    return "\n".join(out)

 # 边缘情况

 对于`D = 1`，BFS 从已经发现的答案开始。 重建循环立即停止并返回单个电荷`1`。 这避免了假设至少需要一项操作的常见错误。 

对于诸如`D = 5`，该算法不强制乘法路径。 BFS 探索每个值的所有三个选择，并保留到达每个状态的第一条最短路径。 The stored parent chain reaches`5`通过`1 -> 3 -> 4 -> 5`，给出最小天数。 

为了最大目标`D = 1000000`，算法不会创建超出该值的状态。 BFS 仍然覆盖整个有用的搜索空间一次，并且父数组允许重建而无需再次搜索。 生成的序列具有最小可能的长度，因为每个状态在 BFS 期间都被分配了其距离。
