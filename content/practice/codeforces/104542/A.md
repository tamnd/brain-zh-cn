 ## 解决方案
 ## 问题理解

 给定一个数组，我们可以选择它的任何子序列作为候选序列$b$。 问题在于我们没有检查$b$单独针对原始数组，但针对派生数组系列。 

对于任何职位$i$，我们删除$a_i$从数组中提取，然后我们在概念上多次重复这个缩短的数组，具体来说$n$副本连接在一起。 这会创建一个长序列$c$长度$n(n-1)$。 要求是必须至少存在一个子序列$b$原始数组的一些选择$i$,$b$无法在此重复结构中找到子序列$c$。 

所以任务不是构建$b$，而是决定是否存在这样的“区分子序列”。 

约束条件很大，总共$n$跨测试用例最多$2 \cdot 10^5$。 任何试图测试所有子序列的解决方案都是不可能的，因为子序列的数量是指数级的。 甚至检查单个候选子序列与所有$i$如果天真地进行选择，成本仍然太高，因为子序列检查本身与数组大小呈线性关系。 

这推动我们进行结构观察：子序列无法出现的唯一方法$c$是如果有某个值$b$在修改后的数组中太“罕见”，或者如果排序约束强制在重复副本之间进行不可能的对齐。 

一些微妙的边缘情况自然会出现。 

例如，如果所有元素都相同$a = [1,1,1]$，然后删除任何一个元素仍然留下一个常量数组。 任意子序列$b$只是一个 1 的序列，并且它总是以重复的副本出现。 这表明结果是“否”。 

如果存在一个只出现一次的值，比如$a = [1,2,3]$，删除唯一元素可以极大地改变符号的可用性，通常使得不可能同时在所有副本中嵌入某些子序列。 

关键的难点在于$c$重复相同的多重集$n$次，因此具有巨大的冗余度。 唯一有意义的限制来自于重复之前删除一个位置这一事实。 

## 方法

 暴力方法会尝试每个子序列$b$，那么对于每个$i$， 建造$c$并检查是否$b$是一个子序列$c$。 甚至忽略指数子序列，构建和扫描$c$成本$O(n^2)$，太大了。 

我们需要重新解释什么是“$b$是一个子序列$c$” 真正的意思是。自从$c$只是$n$删除一个元素的数组的重复，任何子序列嵌入$b$可以跨副本分发。 这意味着重复有助于匹配过程而不是限制它。 

关键的洞察力是扭转观点。 而不是问是否有一些$b$在某些方面失败$c$，我们问什么时候$a$仍然可以嵌入到每一个这样的重复结构中。 当删除任何单个元素不会降低序列的表达能力足以阻止子序列模式时，就会发生这种情况。 

这将问题分解为检查是否存在任何“关键结构”$a$，而该结构完全取决于所有元素是否相同。 如果至少存在两个不同的值，我们总是可以构造一个子序列，在删除任何索引时强制不匹配。 如果所有值都相同，则重复可以保证每个子序列在任何地方都保持有效。

 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 扫描数组并判断所有元素是否相等。 

如果至少有两个不同的值，我们立即知道存在有效的子序列。 
2. 如果所有元素都相同，则得出结论：不存在这样的区分子序列。 

第 1 步背后的原因是，值的多样性使我们能够构建一个取决于不同符号的相对顺序或可用性的子序列，可以通过删除精心选择的索引来破坏该子序列。 

接下来是第 2 步，因为常量数组在删除和重复下保持不变，因此每个子序列在每个构造的$c$。 

### 为什么它有效

 如果数组包含至少两个不同的值，请选择两个具有不同值的位置。 任何对这两个值之间的转换进行编码的子序列都可以对精心选择的索引的删除敏感，因为删除一个元素可能会破坏数组重复副本之间的必要对齐。 中的重复$c$并不能消除此漏洞，因为除了缺失的位置之外，所有副本都是相同的，因此不能总是嵌入精心选择的子序列。 

如果所有值都相同，则每个子序列只是一串相同元素。 删除任何一个位置都不会改变每个符号都是相同的事实，重复只会增加可用性。 因此，每一个子序列$a$仍然是所有可能的子序列$c$，所以没有有效的$b$存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # check if all elements are the same
        first = a[0]
        ok = False
        for x in a:
            if x != first:
                ok = True
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该实现直接对归约进行编码以检查是否存在至少两个不同的值。 一旦发现不匹配，循环就会提前退出，从而确保每个测试用例的线性时间。 

这里的一个常见错误是通过尝试模拟子序列匹配而使逻辑过于复杂。 关键是结构$c$使唯一有意义的属性是元素的多样性，而不是它们的排列。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        first = a[0]
        ok = any(x != first for x in a)
        out.append("YES" if ok else "NO")
    return "\n".join(out)

 ## 边缘情况

 完全均匀的数组，例如$a = [4,4,4,4]$总是导致NO。 该算法将第一个值读取为 4 并且从未发现不匹配，因此`ok`仍然是错误的，正确地产生NO。 

接近均匀的数组，例如$a = [10,10,10,11,10]$在第四个元素处触发提前退出。 该标志立即变为真，确保“是”，无需检查进一步的结构。 

length-2 数组也能正确处理。 为了$a = [3,3]$，不存在差异，所以答案是否定的。 为了$a = [3,5]$，第一次比较已经检测到独特性并返回 YES。
