 ## 解决方案
 ## 问题理解

 我们得到一串小写英文字母。 每个操作都允许我们选择两个不同的位置，并同时将两个字符在字母表中向后移动一步，其中移动意味着`b`变成`a`,`c`变成`b`，依此类推，循环往复，使得`a`变成`z`。 

目标是将字符串中的每个字符转换为`a`使用尽可能少的操作。 每个操作总是影响两个索引，并且每个受影响的字符向更接近的方向移动一步`a`在循环字母表中。 

关键的难点是我们不可以单独对单个角色进行操作。 每个减量必须与字符串中其他位置的另一个减量配对，这会在所有所需的转换之间创建全局耦合。 

所有测试用例的输入大小均达到 200,000 个字符，这排除了任何对字符进行逐步模拟操作的解决方案。 任何正确的解决方案都必须将问题简化为每个测试用例的线性时间内的计数和奇偶校验推理。 

当所需减量总量为奇数时，会出现微妙的边缘情况。 由于每个操作恰好执行两次递减，因此无法满足奇数的总需求。 例如，如果字符串是`"ab"`，我们需要对每个字符减一，所以总工作量是 2，这很好。 但如果字符串是`"aab"`，我们需要 0 + 0 + 1 = 1 总减量，它不能配对，所以答案一定是`-1`。 

另一个不明显的情况是，总体上可以进行配对，但分布使得不可能避免浪费操作，但在这个问题中，跨索引允许任何配对，因此只有总体可行性才重要。 

## 方法

 暴力策略将直接模拟该过程。 在每一步中，我们选择两个尚未确定的索引`a`并减少两个字符。 我们重复直到所有字符都变成`a`。 这是正确的，因为它准确地反映了操作定义，但它很快就变得不可行。 

如果一个字符最初是`k`距离`a`，那么它必须精确地递减`k`次。 对所有字符求和得出所需减量的总数。 每个操作恰好贡献两个减量，因此操作数量大约是总数的一半。 蛮力方法有效地显式地执行这种配对，导致最坏情况的复杂性与每次操作所需的减量总数成正比，这在病理模拟中可能是二次的。 

关键的观察结果是，问题不在于字符的位置，而在于总共需要多少个减量单位。 由于每个操作恰好提供两个减量单位，因此唯一的障碍是总要求是否为偶数。 一旦这一点成立，我们就可以在头寸之间任意配对递减，因为可以一起选择哪些指数没有限制。 

所以问题归结为计算所有字符到的总距离`a`按循环顺序，检查可行性，然后除以二。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(总操作 × n) | O(n) | 太慢了 |
 | 总和 + 奇偶校验约简 | 每次测试 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个角色，计算需要多少步才能到达`a`。 这是`(ord(c) - ord('a')) mod 26`。 

这测量了字符所需的确切减量数。 
2. 对整个字符串的这些值求和。 

该总和表示所有字符所需的单位递减操作的总数。 
3. 检查总和是否为偶数。 

每个操作恰好贡献两个减量，因此奇数总数无法完美匹配。 
4. 如果和为奇数，则返回`-1`立即地。 

没有办法将运算配对来匹配奇数个所需的减量。 
5. 否则，将总和除以 2 并将其作为答案输出。 

每个操作恰好删除两个需求单元，因此这是最小操作数。 

### 为什么它有效

 每次操作总是减少所需的总“距离”`a`” 精确地为 2，无论选择哪个索引。这意味着总和是一个不变的 mod 2，并且每个有效的操作序列都对应于将总所需减量划分为对。由于对配对索引没有限制，因此任何两个剩余的非零要求始终可以一起减少，直到所有要求消失。这使得总和成为唯一重要的状态变量，并且该过程完全由其值决定。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        total = 0
        for c in s:
            total += (ord(c) - ord('a'))

        if total % 2 == 1:
            print(-1)
        else:
            print(total // 2)

if __name__ == "__main__":
    solve()
```该代码独立处理每个测试用例，并计算将每个字符转换为所需的向后移位总数`a`。 每个字符贡献其字母距离`a`。 

奇偶校验是核心正确性条件。 如果总和是奇数，则不可能配对，因为每次操作都会消耗两个单位。 如果是偶数，则除以二即可得到所需的确切运算次数。 

不需要模拟或贪婪配对，因为该操作在索引之间是完全对称的。 

## 工作示例

 ### 示例 1

 输入：```
n = 3
s = "amo"
```我们计算每个字符的距离：

 | 步骤| 人物 | 到“a”的距离 | 运行总和 |
 | --- | --- | --- | --- |
 | 1 | 一个 | 0 | 0 |
 | 2 | 米 | 12 | 12 12 | 12
 | 3 | 哦| 14 | 14 26 | 26

 总和是 26，是偶数，所以答案是 13 次运算。 

这证实了所有必需的减量都可以跨索引任意配对，即使字符具有不同的初始值。 

### 示例 2

 输入：```
n = 3
s = "abc"
```| 步骤| 人物 | 到“a”的距离 | 运行总和 |
 | --- | --- | --- | --- |
 | 1 | 一个 | 0 | 0 |
 | 2 | 乙| 1 | 1 |
 | 3 | c | 2 | 3 |

 总和是 3，是奇数，所以答案是`-1`。 

这证明了关键的不可能性条件：即使每个角色单独可以达到`a`，操作总是成对消耗工作，使得最终状态无法到达。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每个测试用例 O(n) | 每个字符都会被处理一次以计算其距离 |
 | 空间| O(1) | O(1) | 仅存储运行总和 |

 该解决方案很容易满足限制，因为所有测试用例的字符总数最多为 200,000，使得单个线性传递就足够了。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        total = sum(ord(c) - ord('a') for c in s)
        if total % 2 == 1:
            out.append("-1")
        else:
            out.append(str(total // 2))

    return "\n".join(out)

# provided samples
assert run("5\n2\naa\n2\nab\n2\ncc\n3\namo\n4\negzx\n") == "0\n-1\n2\n13\n29"

# custom cases
assert run("1\n2\naz\n") == "25", "simple single pair"
assert run("1\n3\nabc\n") == "-1", "odd total requirement"
assert run("1\n4\nbbbb\n") == "4", "uniform distance case"
assert run("1\n5\naaaaa\n") == "0", "already done"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`az`| 25 | 25 单远距离配对|
 |`abc`| -1 | 奇怪的是完全不可能|
 |`bbbb`| 4 | 均匀非零距离 |
 |`aaaaa`| 0 | 已经满足的状态|

 ## 边缘情况

 一个最小但棘手的情况是`"ab"`。 这里总距离是1，所以答案是`-1`。 该算法正确地将总和计算为 1，并由于奇偶校验而立即拒绝，这与单个所需减量无法配对的事实相匹配。 

第二种情况是`"ba"`，其总距离也为 1。即使一个字符已经接近`a`，相同的奇偶校验约束阻碍了进展，算法再次返回`-1`。 

像这样的案例`"cc"`产生总距离 4。算法输出 2，这对应于重复配对两个字符，直到它们达到`a`。 每个操作都会同时减少两者，并且每一步都保持总工作减少 2 的不变式，直到完成。
