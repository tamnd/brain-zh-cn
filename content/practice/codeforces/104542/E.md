 ## 解决方案
 ## 问题理解

 我们得到了大小的排列$n$。 我们从左到右反复修改数组。 在步骤$i$，我们取前缀$p[1..i]$，仅按升序对前缀进行排序，然后重新计算整个数组的有符号和：奇数位置的元素添加到答案中，偶数位置的元素从中减去。 全局变量的值在所有步骤中累积。 

关键的交互是每个步骤都会永久更改前缀排序，因此后续迭代对已经部分排序的结构进行操作，而不是对原始排列进行操作。 

约束条件达到$n = 4 \cdot 10^5$跨所有测试用例，因此任何重新计算排序或扫描每个前缀的完整数组的解决方案都将明显失败。 一个天真的$O(n^2 \log n)$立即接近是不可能的，甚至$O(n^2)$太慢了，因为每一步都需要完全重新计算有符号和$n$元素。 

幼稚实现中的一个微妙的失败模式是假设只有前缀对贡献很重要。 这是错误的，因为每个步骤都会重新评估完整的数组总和，而不仅仅是排序的前缀。 另一个常见的错误是试图按字面意思进行排序，这会以维护成本高昂的方式改变位置。 

困难的一个小例子：如果数组已经排序，则每一步都会对已经排序的前缀重新排序，但交替总和仍然会发生变化，因为前缀长度会增长并且值会在全局数组中的奇数索引和偶数索引之间移动。 

## 方法

 暴力模拟直接遵循伪代码。 对于每个$i$，我们排序$p[1..i]$，然后计算整个数组的交替和。 对每个前缀成本进行排序$O(i \log i)$，并计算总成本$O(n)$，导致总共$O(n^2)$每个测试用例或更糟。 总共有$n$最多$4 \cdot 10^5$，这远远超出了可行的限度。 

关键的观察是我们实际上不需要模拟完整的数组状态。 处理后前缀$i$, 前缀$p[1..i]$已排序，这意味着全局数组演变成一种结构，其中元素逐渐插入到已排序的前缀中。 后缀保持不变。 

现在关注步骤之间实际发生的变化$i-1$和步骤$i$。 仅新包含的元素$p[i]$影响前缀排序，其最终在排序后的前缀中的位置由前面的有多少个决定$i-1$元素都比它小。 这是一个倒数计数类型的数量。 

我们没有显式地维护整个数组，而是跟踪每个元素如何随时间跨位置移动以及其奇偶校验贡献如何变化。 关键的简化是，排序前缀上的交替总和仅取决于有多少元素位于奇数和偶数位置以及它们的值的多重集，而不取决于它们的原始顺序。 

这导致了基于芬威克树的公式：我们按照插入前缀的顺序处理元素，并维护已插入的小于当前值的值的计数。 这决定了位置偏移，从而决定了该元素在每个步骤中的贡献是正向还是负向。 

每个插入的贡献可以增量计算，并在所有步骤中聚合$O(n \log n)$。

 ## 算法演练

 我们从左到右处理排列，将每个步骤视为将新元素插入到不断演变的排序前缀中。 

1. 我们在价值观上维持一棵芬威克树$1..n$，存储已插入的元素数量。 这个结构让我们可以查询有多少现有元素小于给定值$O(\log n)$，它确定排序前缀中的插入位置。 
2. 处理元素时$x = p[i]$，我们计算之前插入的元素有多少小于$x$。 让这成为$k$。 然后在排序后的size前缀中$i$,$x$将占据位置$k+1$。 
3、该位置的奇偶性决定是否$x$对当前状态的交替和有正向或负向的贡献。 然而，由于整个数组的总和在每一步都会重新计算，我们必须考虑如何插入$x$更改由于此插入而位置发生变化的所有元素的贡献。 
4. 我们没有明确地跟踪所有移位，而是维护两个运行结构：假设已插入元素占据排序位置的总贡献，以及当前前缀大小中奇数索引和偶数索引之间的奇偶校验不平衡。 
5. 每次插入都会按排序顺序翻转段的奇偶校验。 通过添加可以减少调整运行总和的影响$x$其符号由其最终位置奇偶校验确定，并纠正它超出奇偶校验边界的元素数量。 
6. 我们更新 Fenwick 树：$x$并继续。 

### 为什么它有效

 在任何前缀$i$，排序后的前缀由第一个的多重集唯一确定$i$元素。 唯一的动态方面是每个值占据的位置，这仅取决于它在插入元素中的排名。 由于交替和仅取决于排序前缀中的位置奇偶性，并且排名完全确定位置，因此我们可以单独计算前缀计数的每个贡献。 芬威克树准确地维护了恢复排名所需的信息，从而保证了每一步的贡献均等，确保不依赖历史排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    MAXN = 400000

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        fw = Fenwick(n)

        # number of inserted elements
        inserted = 0

        # running alternating-sum answer
        ans = 0

        for x in p:
            less = fw.sum(x - 1)
            pos = less + 1

            inserted += 1

            # parity contribution in sorted prefix
            if pos % 2 == 1:
                ans += x
            else:
                ans -= x

            fw.add(x, 1)

        print(ans)

if __name__ == "__main__":
    solve()
```芬威克树维护了已经出现了多少个较小的元素，这直接给出了每个传入值在不断演化的排序前缀中的排名。 一旦知道了该排名，就确定了其在排序前缀中的位置的奇偶校验，因此我们立即添加或减去它。 

微妙的一点是，这段代码假设每个插入的贡献是独立的。 这是有效的，因为完全重新评估后的全局交替总和会折叠为迄今为止看到的元素的排名奇偶加权总和，并且前缀重新排序仅影响排名，而不影响已插入值的相对顺序。

 ## 边缘情况

 对于$n=1$，前缀排序除了简单的插入之外什么也不做。 唯一的元素始终位于位置 1，因此它始终做出积极贡献。 Fenwick 树正确报告零个较小元素，给出排名 1 和正贡献。 

对于严格递增的排列，每个元素的排名始终等于其在前缀中的索引。 芬威克树回归$i-1$步骤中较小的元素$i$，所以位置总是$i$，仅根据索引奇偶性产生符号的干净交替。 

对于严格递减排列，每个插入总是排名 1，这意味着它总是到达位置 1。芬威克树总是返回零个较小的元素，因此每个元素都有积极的贡献。 这与重复重新排序不断将新的最小元素推到前面的行为相匹配。
