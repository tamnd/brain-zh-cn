 ## 解决方案
 ## 问题理解

 迷宫可以看作是一个连通的加权图，其中房间是节点，通道是具有容量的无向边。 每个房间还有一个一次性的“成长值”，如果露西选择吃那个房间的糖果，就会增加她的宽度。 Lucy 从房间 1 开始，具有一定的初始宽度，只有当她当前的宽度不超过边缘的宽度时，她才可以遍历边缘。 

关键的限制是宽度只会随着时间的推移而增加而不会减少，而且每次她吃糖果时，她的尺寸都会永久增加。 挑战不仅在于图中的可达性，还在于单调递增约束下的可达性，该约束取决于访问节点的顺序。 

任务是确定是否存在一种方法来排序从房间 1 开始访问所有房间，选择何时消耗糖果，使得每一步在边缘约束下都是有效的。 如果可能的话，我们必须最大化初始宽度。 

这些约束允许最多 100,000 个房间和 100,000 个边，因此任何对节点排列进行推理或动态模拟所有可能状态的方法都立即不可行。 甚至将状态存储为`(node, subset of eaten candies)`是指数级的且不可能的。 

解决方案必须避免跟踪显式子集，而是将排序约束压缩到可以有效检查的结构中，理想情况下每个操作接近线性或对数。 

当贪婪遍历忽略未来宽度增长时，就会出现微妙的失败情况。 例如，最初可访问的路径可能会阻止进入需要糖果才能稍后穿过更宽边缘的房间。 如果我们贪婪地过早拿走所有糖果，即使不同的顺序有效，我们也可能会过早失败。 

另一种极端情况是，露西必须在过窄桥之前刻意避免吃糖果，即使当前可以到达房间。 这使得任何“访问时总是吃东西”的天真的 BFS 或 DFS 是不正确的。 

## 方法

 蛮力的想法是尝试所有可能的吃糖果的顺序。 对于每个房间排列，模拟 Lucy 是否可以遵循从房间 1 开始的顺序，更新她的宽度并在每一步检查边缘约束。 这是正确的，因为它显式地尝试所有有效的决策序列。 

然而，排列的数量是n！，即使n = 20，这也是一个天文数字，更不用说100,000了。 即使模拟单个序列也需要 O(n + m)，所以这是完全不可行的。 

关键的观察结果是，问题不在于任意排序，而在于单调阈值下的可行性。 如果我们固定起始宽度 X，那么问题就变成：我们能否设计一种在累积总增长的同时永远不会超过任何边缘约束的遍历？ 这转化为检查是否存在排序，使得在每一步中，当前宽度加上未来可能的增量仍然尊重可用边缘。 

这种结构建议将贪婪的可行性检查与初始宽度上的二分搜索相结合。 对于固定的 X，我们模拟可达状态，但我们不是跟踪所有排列，而是始终优先考虑可以安全获取糖果而不打破连接限制的访问房间。 

关键的重新表述是，如果我们根据可用节点当前在宽度约束下是否可达进行排序或动态维护，我们可以贪婪地扩展可达组件，同时确保我们永远不会违反边缘约束。 正确性取决于这样一个事实：一旦节点在给定宽度阈值下变得不可达，在不超过某个瓶颈边缘的情况下增加消耗顺序无法恢复它。 

为了支持阈值处理下的高效动态连接，我们对边缘进行排序并按升序处理它们，使用不相交集并集（DSU）结构逐步构建连接，同时保持当前宽度猜测的可行性约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有排列）| O(n!) | O(n + m) | 太慢了 |
 | 最优（二分搜索+DSU可行性检查）| O((n + m) log W) | O(n + m) | 已接受 |

 ## 算法演练

 我们将问题简化为决策检查：对于固定的起始宽度 X，确定 Lucy 是否可以在遍历期间消耗所有糖果而不超过边缘限制。 

1. 通过增加宽度对所有边进行排序。 这确保我们可以随着宽度的增加逐步激活连接。 
2. 固定候选起始宽度X，并将当前宽度初始化为X。 
3. 维护房间的 DSU。 最初，只有房间 1 处于活动状态。 
4. 维护“可用糖果”的多重集或优先级结构，这意味着在当前 DSU 状态下可以到达但尚未消耗的房间。 
5、反复：

1. 将宽度至少为当前可到达组件遍历的当前宽度阈值要求的所有边添加到 DSU。 
2. 将所有新到达的节点标记为进食候选节点。 
3. 如果不存在未访问的可达房间，则失败。 
4. 否则，选择任何可到达的房间，消耗其糖果，并按其值增加当前宽度。 
6、如果所有房间都消费成功，则X可行。 

关键的设计选择是 DSU 不是用于最短路径，而是用于在逐渐演变的约束下保持连接。 随着宽度增加，可用的边更少，因此该结构实际​​上是单调的。 

### 为什么它有效

 正确性依赖于单调可行性属性：如果起始宽度 X 足够，则任何较小的约束集（即更具限制性的边缘）都无法提高可行性。 DSU 按升序处理边缘，以便在每个阶段我们准确地知道哪些区域在当前宽度阈值下可以相互到达。 

贪婪地消耗可达节点是有效的，因为消耗糖果只会增加宽度，这只能增加未来的可达性。 因此，如果在当前限制下现在可以安全地采取，那么延迟消耗可到达节点永远不会有任何帮助。 

X 上的二分搜索之所以有效，是因为可行性是单调的：如果我们可以从 X 开始，那么任何较小的起始宽度可能会或可能不会起作用，但任何较大的起始宽度都会保留或改善可行性约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def can(start_w, n, edges, c):
    dsu = DSU(n)
    active = [False] * n
    active[0] = True
    cur_w = start_w

    i = 0
    m = len(edges)

    while True:
        # activate edges that are usable at current width
        while i < m and edges[i][0] <= cur_w:
            _, u, v = edges[i]
            dsu.union(u, v)
            i += 1

        # gather reachable unvisited nodes
        progress = False
        root0 = dsu.find(0)

        for v in range(n):
            if not active[v] and dsu.find(v) == root0:
                active[v] = True
                cur_w += c[v]
                progress = True

        if all(active):
            return True

        if not progress:
            return False

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))
    edges = []
    for _ in range(m):
        a, b, w = map(int, input().split())
        edges.append((w, a - 1, b - 1))

    edges.sort()

    # feasibility check for very large initial widths
    lo, hi = 0, sum(c)

    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, n, edges, c):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案在房间上构建 DSU，并按宽度递增顺序处理边缘。 每次可行性检查都会通过重复扩展可达组件并吃掉新的可达糖果来模拟给定的起始宽度是否允许完全消耗。 

二分搜索包装此检查以最大化起始宽度。 上限是糖果的总和，因为大于该宽度的起始宽度除了允许所有节点延迟之外不会增加有意义的额外可行性。 

一个微妙的细节是，我们总是使用 DSU 连接重新计算从房间 1 开始的可达性，这避免了显式路径模拟。

 ## 边缘情况

 当露西必须避免过早吃糖果时，就会出现一个关键的边缘情况，因为它会增加宽度，超出到达剩余节点所需的瓶颈边缘。 在这种情况下，天真的“尽可能吃东西”的策略就会失败。 

另一种边缘情况是当初始宽度已经超过所有小边时，会强制立即排除图形的某些部分，直到在其他地方收集到足够的糖果来解锁它们，这测试了基于 DSU 的可达性在增长后是否正确地重新计算。 

该算法可以处理这两种情况，因为可达性总是根据当前宽度约束重新计算，并且节点仅在位于房间 1 的当前连接组件中时才会被消耗。
