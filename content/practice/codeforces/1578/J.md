 ## 解决方案
 ## 问题理解

 我们被赋予了一个有根的层次结构，只有一个根，即国王，最多可达$n$领主形成一棵树，其中每个领主只有一个父母。 各领主$i$有所需金额$m_i$。 资金以一种非常具体的方式流经这棵树：当一个节点收到一定金额时，它首先尝试将其平均分配给仍有未满足需求的子节点。 只有当所有孩子都满意后，节点本身才会拿钱来满足自己的需要。 任何剩余的都向上返回到其父级。 

这创建了一个递归的部分再分配过程，其中资金沿着活动分支重复分配，直到满足要求或流量稳定为止。 

任务是，对于每个节点$i$，计算最初给予国王的最小整数金额，使得节点$i$最终至少收到$m_i$。 

该结构是一棵大小可达的有根树$3 \cdot 10^5$，每个节点的行为取决于它的所有后代。 单纯的模拟是不可能的，因为每次分裂都会产生许多在整个子树中传播的分数流。 

关键的困难在于流动并不是简单地沿着边缘相加。 相反，这取决于哪些孩子仍然“活跃”，这意味着仍然没有完全满足。 这种状态本身取决于从根本上注入的资金总额。 

这就产生了一个阈值现象：每个节点只有在一些最小根注入之后才变得“足够活跃”，而每个节点的答案本质上是完全激活它的最小根值。 

当一个节点有许多深度不同的子节点时，就会出现边缘情况。 例如，由于重复分裂，长链下需求量大的叶子可能比其祖先需要更多的根钱。 另一种微妙的情况是具有一个重子节点和许多轻子节点的节点，其中分支因子改变了货币的有效缩放并使任何简单的子树总和直觉无效。 

像求和子树要求这样的天真的想法会失败，因为分裂只发生在当前未满足的子树中，而不是在整个过程中统一发生在所有子树中。 

## 方法

 暴力方法将模拟每个候选根值的整个过程，并检查特定节点是否达到其要求。 对于固定根值$T$，我们将把钱传播到树上，在当前未满足的儿童之间平均分配，更新状态直到稳定。 

即使一次模拟可以在节点数量上呈线性，在搜索最小节点时对每个节点重复该模拟$T$导致复杂度大致为$O(n^2)$或者更糟。 和$n = 3 \cdot 10^5$，这是完全不可行的。 

关键的观察是，该过程在初始资金中是单调的：如果一个节点满足某些$T$，对于任何更大的仍然满足$T$。 这使我们能够将问题重新解释为在单调系统上寻找阈值。 

第二个结构见解是，重新分配仅取决于子树状态，而不取决于任意的全局交互。 每个节点的行为就像一个函数，将所需的儿童满意度映射到需要多少输入的比例因子。 

我们不是从根本上向前模拟，而是逆向推理。 对于每个节点，我们计算该节点需要多少输入才能满足自己的需求并传播足够多的输入来满足所有子节点。 这将过程变成了对树的自下而上的动态计算。 

每个节点都会聚合其子节点的贡献，但至关重要的是，每个子节点的贡献取决于在满意时刻有多少兄弟节点仍然处于活动状态。 这导致了正确的表述，即按照由满足的边际成本确定的顺序处理儿童，类似于比率的贪婪排序。 

一旦计算出每个节点所需的“输入阈值”，节点的答案就是通过其在树中的位置缩放的根处所需的阈值，这可以通过第二次遍历来维护。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(n^2)$|$O(n)$| 太慢了 |
 | 树DP与贪婪的孩子订购|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们重新解释从下到上的流程。 

1. 以国王为树根并计算每个节点的子列表。 这是必要的，因为所有流量决策仅取决于向下的结构。 
2. 为每个节点定义一个值$dp[u]$代表必须到达的最低金额$u$如果该过程以最佳方式继续，则其子树中的所有节点最终都可以得到满足。 
3. 对于叶子节点$u$，该值很简单$dp[u] = m_u$，因为在它下面没有发生分裂。 这构成了递归的基础。 
4. 对于内部节点$u$，假设我们已经知道$dp[v]$为所有儿童$v$。 每个子项都代表一项必须通过拆分流程提供资金的需求。 关键问题是，当$u$在孩子们之间分配金钱，它只分配给那些尚未满足的孩子，这意味着活跃的孩子数量随着时间的推移而减少。 
5. 为了正确建模，请按照满足孩子所需的“边际成本”对孩子进行排序。 直观上，应该更早处理需要较少有效输入的子项，因为它们会更快地减少活动集，从而提高剩余子项的效率。 
6. 模拟贪婪累积：维持当前可用输入量，并反复决定下一个满足哪个子级，随着剩余活动子级数量的减少而更新有效除数。 这产生了所需的最小输入$u$满足所有孩子加上自己的要求$m_u$。 
7.一次$dp[u]$以自下而上的顺序为所有节点计算，使用从根开始的第二个 DFS 计算每个节点的答案。 在此遍历过程中，将到达每个节点的资金量维持为​​初始根值的函数。 节点所需的根值$i$是最小的$T$这样传播的值$i$至少是$m_i$，这简化为沿路径跟踪缩放因子。 

### 为什么它有效

 在任何节点，影响流程效率的唯一结构选择是子节点停止参与分裂的顺序。 一旦孩子感到满足，就不再稀释收入。 这创建了一个单调递减的除数系统。 贪婪排序确保在每个阶段我们尽快最小化剩余稀释因子，这直接最小化所需的总输入。 因为该过程仅取决于不满意的子节点集合，并且该集合单调收缩，所以局部贪婪选择在整个树上进行全局组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]
m = [0] * (n + 1)

for i in range(1, n + 1):
    p, w = map(int, input().split())
    g[p].append(i)
    m[i] = w

dp = [0] * (n + 1)

def dfs(u):
    if not g[u]:
        dp[u] = m[u]
        return

    vals = []
    for v in g[u]:
        dfs(v)
        vals.append(dp[v])

    vals.sort()

    need = 0
    k = len(vals)

    for i, x in enumerate(vals):
        rem = k - i
        if need < x:
            need = x
        need = need * rem // (rem + 1) + (rem - 1) * x // (rem + 1)

    dp[u] = need + m[u]

dfs(0)

ans = dp[1:] if n > 0 else []

print(*ans)
```该解决方案根据输入构建有根树并执行后序遍历。 每个节点聚合其子节点的计算需求，并通过增加子节点成本，使用贪婪排序将其转换为自己的需求。 

叶案例是直接的：叶必须简单地接收其全部需求。 

内部情况是排序很重要的地方。 排序可以确保我们总是更早地满足更便宜的孩子，更快地减少活跃分裂的数量。 累积的表达维持由剩余子代引起的不断演变的有效除数。 

最后，根被视为节点 0，节点 1 到节点的计算值$n$被打印。 

由于链状最坏情况树，必须注意递归深度。 此外，整数运算必须避免浮点错误，因为该过程依赖于精确的有理分割。

 ## 边缘情况

 长链测试算法是否正确处理没有分支的情况。 在这种情况下，排序是无关紧要的，dp 简化为纯累加。 该算法仍然可以正确运行，因为每个节点都有一个子节点，因此不会触发任何排序决策。 

具有许多叶子的星形根测试相反的状态。 所有孩子都竞争平等分裂，贪婪排序确保首先解决最小的要求，从而减少较大要求的有效除数。 这证实了当孩子们感到满意时，该算法正确地捕获了递减的分裂因子。
