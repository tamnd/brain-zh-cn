 ## 解决方案
 ## 问题理解

 每个具有整数角的单位正方形恰好与四个无限龙曲线之一的一段相交。 对于具有对角的查询正方形$(x,y)$和$(x+1,y+1)$，我们必须确定两件事。 

第一个是四条曲线中哪一条包含穿过该正方形的线段。 

第二个是沿曲线的该段的索引，其中每条曲线的第一段都有索引$1$。 

坐标大为$10^9$，并且最多有$2 \cdot 10^5$查询。 任何明确生成曲线的方法都是没有希望的。 即使生成一条足够大以达到该量级坐标的有限龙曲线也需要指数级数量的线段。 我们需要每个查询的对数解。 

困难之处在于龙曲线是自相似的。 距离原点很远的正方形仍然属于递归地看起来像更小的龙曲线的结构。 预期的解决方案重复地将查询方块从分形的一个尺度映射到下一个较小的尺度，直到到达原点。 每个步骤将坐标大致除以二，因此坐标最多只需要大约 31 次迭代$10^9$。 

一个常见的错误是假设按比例缩小后，段顺序会保留。 有时是这样，但有时相应的较大段内的顺序是相反的。 例如，属于同一大尺度段的两个相邻方块在一次递归归约后可能会以相反的顺序出现。 解决方案必须明确跟踪这些逆转。 

另一个微妙的情况是处理负坐标。 递归坐标变换依赖于算术移位和精心选择的公式。 用朴素除法替换它们可能会破坏负象限中正方形的映射。 

## 方法

 暴力方法将逐段生成龙曲线，直到到达目标方块。 这在概念上很简单，因为每个线段恰好穿过一个正方形。 不幸的是，线段的数量随着曲线的阶数呈指数增长。 坐标近$10^9$对应于 30 左右的递归深度，这已经意味着数十亿个段。 该方法是完全不可行的。 

关键的观察是自相似性。 

考虑龙曲线的两个版本。 致电原一订单$n+1$，以及通过旋转它获得的另一个$45^\circ$逆时针并缩放$1/\sqrt2$， 命令$n$。 较小曲线的每一段都恰好扩展为较大曲线的两段。 这给出了平面中的正方形和下一个较小比例的正方形之间的直接递归关系。 

平面可分为$2 \times 2$块。 根据奇偶校验，这样的块要么是“垂直的”，要么是“水平的”。 从块类型中，我们可以导出确定性变换，将当前方块映射到较小龙曲线中的相应方块。 重复这个操作不断缩小坐标。 

在收缩的同时，我们还保持该段在递归扩展段内的位置。 每次减少都会使表示的段长度加倍。 有时本地的顺序是相反的，所以我们替换$$pos \leftarrow (2^k-1)-pos.$$当该方格最终成为与原点相邻的四个方格之一时，曲线编号立即得知，累加的位置即为答案。

 ## 算法演练

 1、从查询的方坐标开始$(x,y)$。 
2. 维持两个价值观：`bit`，当前递归段表示的原始段数。`pos`，该段内的位置，最初为零。 
3. 当该正方形不是与原点相邻的四个正方形之一时，执行一次递归归约。 
4.双人间`bit`因为较小曲线的一段对应于较大曲线的两段。 后$k$减少，表示的段长度是$2^k$。 
5. 检查此减少是否颠倒了本地排序。 所需条件是```
(x ^ y ^ ((x ^ y) >> 1)) & 1
```如果属实，则更换```
pos = bit - 1 - pos
```这反映了当前段内的位置。 
6.判断当前是否$2 \times 2$块是水平的或垂直的。 

如果```
((x ^ y) >> 1) & 1
```为真，则使用水平变换：```
x, y =
    (x >> 1) + ((y + 1) >> 1),
    ((y + 1) >> 1) - (x >> 1) - 1
```否则使用垂直变换：```
x, y =
    ((x + 1) >> 1) + (y >> 1),
    (y >> 1) - ((x + 1) >> 1)
```These formulas map the square to the corresponding square in the next smaller dragon curve.
 7. 继续直到$(x,y)$属于$2 \times 2$原点周围的邻域，即```
-1 <= x <= 0 and -1 <= y <= 0
```8. 根据最终坐标确定曲线编号：```
curve = (x & 1 ^ y & 3) + 1
```9. 段索引为`pos + 1`因为输出是从 1 开始的。 

### 为什么它有效

 每次缩减都会将查询的方块从龙曲线的一个比例映射到下一个较小的比例。 龙曲线的几何结构保证了每个方格恰好对应于简化表示中的一个方格。 坐标变换保留了这种对应关系。 同时，`bit`记录有多少原始段已合并到当前递归段中，以及`pos`记录哪些段包含查询。 每当递归构造反转方向时，镜像变换就会更新`pos`因此。 经过足够的缩减后，查询到达与原点相邻的四个基本段之一。 此时，曲线标识和确切的线段位置都是唯一确定的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dragon_curve(x, y):
    bit = 1
    pos = 0

    while not (-1 <= x <= 0 and -1 <= y <= 0):
        bit <<= 1

        if (x ^ y ^ ((x ^ y) >> 1)) & 1:
            pos = bit - 1 - pos

        if ((x ^ y) >> 1) & 1:
            x, y = (
                (x >> 1) + ((y + 1) >> 1),
                ((y + 1) >> 1) - (x >> 1) - 1
            )
        else:
            x, y = (
                ((x + 1) >> 1) + (y >> 1),
                (y >> 1) - ((x + 1) >> 1)
            )

    curve = ((x & 1) ^ (y & 3)) + 1
    return curve, pos + 1

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        x, y = map(int, input().split())
        c, p = dragon_curve(x, y)
        ans.append(f"{c} {p}")

    sys.stdout.write("\n".join(ans))

solve()
```其实现实际上遵循递归归约。 

循环是解决方案的核心。 每次迭代都会将坐标大致缩小两倍，因此即使是最大的坐标也只需要大约三十次迭代。 

变量`bit`始终等于在原始段中测量的当前递归段的长度。 这就是为什么在处理电流减少之前​​它会加倍。 

反转更新很容易出错。 该公式使用新值`bit`，不是旧的。 如果顺序在一段长度内翻转$L$， 位置$p$变成$L-1-p$。 

坐标变换必须使用算术右移，如图所示。 Python 的移位对于负整数可以正确工作，符合预期的行为。

 ## 边缘情况

 考虑正方形`(0,0)`。 

循环条件立即失败，因为该正方形已经属于基邻域。 不需要递归归约。 该算法直接计算曲线`1`和位置`1`。 始终执行至少一次缩减的解决方案将错误地偏离基本配置。 

考虑正方形`(-2,0)`。 

第一次减量翻倍`bit`从`1`到`2`。 奇偶校验测试表明本地顺序颠倒了，所以`pos`变化自`0`到`1`。 坐标变换后正方形变为`(-1,-1)`，这是一个基正方形。 最终的答案是`2 2`。 任何忽略反转的实现都会返回位置`1`，这是错误的。 

考虑一个大的负坐标，例如`(-10^9,-10^9)`。 

递归公式重复对负值应用算术移位。 Python 在右移期间保留符号，与预期的几何简化相匹配。 更换`>> 1`使用普通的除法和向零截断会产生不同的中间坐标，并最终产生错误的曲线。 该算法通过使用从分形结构导出的精确变换来避免这个问题。
