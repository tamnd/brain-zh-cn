 ## 解决方案
 ## 问题理解

 我们得到一个字符串，它表示由三个构造构建的类型表达式：基本单元类型写为`()`，将类型分组而不改变其含义的括号，以及写为的函数构造函数`->`连接两种类型。 语法是完全有效的，因此我们永远不需要处理格式错误的输入。 

任务是计算整个类型的“顺序”。 顺序的行为类似于函数嵌套深度的度量。 单位类型的阶数为 0。括号根本不会改变顺序。 函数类型`T1 -> T2`以一种非常具体的方式增加复杂性：结果顺序是结果类型的顺序与参数类型的顺序相加的最大值。 

所以结构并不是简单地计算箭头或括号。 嵌套和右关联性之间的相互作用意味着相同的子字符串可以表示非常不同的函数结构，具体取决于它的分组方式。 

输入大小最多为 10^4 个字符，这会立即排除任何指数解析或子字符串的重复重新评估。 任何多次重新计算同一细分市场订单的解决方案都会面临二次行为的风险。 目标必须是线性或近线性时间。 

关联性出现了一个微妙的问题。 表达式`()->()->()`被解析为`()->(()->())`， 不是`(()->())->()`。 这会影响函数嵌套对顺序贡献 +1 的位置。 不尊重右关联性的简单的从左到右的简化将在这种情况下计算出错误的结果。 

另一个常见的失败是将问题视为简单的括号深度解析。 例如，`(()->())`比仅仅计算括号具有更深的结构，因为即使括号看起来平衡，箭头也会改变顺序。 

## 方法

 直接的强力解释会将字符串解析为显式的抽象语法树。 每次我们遇到一个`->`，我们将递归计算两边的顺序，尊重括号结构，然后应用规则`max(order(left)+1, order(right))`。 

这种方法是正确的，但如果在字符串上简单地实现，则效率低下，因为识别子表达式需要重复扫描或切片。 在最坏的情况下，每个函数应用程序都会强制重新扫描字符串的大部分，从而为嵌套表达式提供二次或更差的行为，例如`(()->(()->(...)))`。 

关键的观察结果是，语法完全用括号括起来，允许我们使用堆栈处理它，同时保留部分结果。 复杂性的唯一真正来源是`->`运算符，它必须合并两个已计算的订单。 

如果我们将表达式解释为标记序列，则可以使用表示部分计算的类型顺序的整数堆栈来评估它。 每当我们完成解析`()`块，我们推 0。每当我们看到`->`，我们不立即计算； 相反，我们等到得到右侧后再应用规则。 括号仅控制分组，而不控制计算。 

关键的简化是每个完整的类型片段都简化为一个整数：它的顺序。 因此，我们不是构建树，而是将字符串减少为基于堆栈的评估，其中每次减少都是常数时间。

 ## 算法演练

 我们从左到右处理字符串，维护表示部分评估的类型顺序的整数堆栈，并且我们还跟踪是否已看到待处理的函数箭头。 

1. 逐一扫描字符。 当我们看到`"("`，我们什么都不做。 它只影响分组，并不直接影响顺序。 
2.当我们检测子串时`"()"`，我们立即将 0 压入堆栈。 这表示订单为 0 的完整单元类型。 
3. 当我们遇到右括号时`")"`，我们就完成了一个分组类型。 此时，堆栈顶部表示该组内表达式的顺序。 我们将其保留为完整值。 
4.当我们遇到一个`"-"`其次是`">"`，我们将其视为函数构造函数分隔符。 我们不立即计算。 相反，我们标记下一个完成的类型是函数应用程序的右侧。 
5. 一旦我们完成了右侧类型（解析后堆栈值变得可用），我们使用以下规则将其与先前的左侧类型组合：`order = max(left + 1, right)`。 

合并后，我们将两者替换为结果顺序。 
6. 继续，直到字符串完全处理完毕。 最终的答案是剩下的单个值。 

这样做的原因是每个语法完整的子表达式都简化为一个整数，而函数应用程序是合并两个此类值的唯一操作。 通过确保每次合并在双方都完成时恰好发生一次，我们可以避免重新计算并保持正确性。 

### 为什么它有效

 在扫描中的任何一点，堆栈都表示一系列已完全求值的子表达式，其内部结构已被消耗。 每个值都对应于有效类型片段的确切顺序。 不变的是堆栈上的任何值都不依赖于未解析的未来字符。 这`->`运算符仅组合两个已经最终确定的值，因此每种组合都准确地反映一种语法产生式。 因为每个产生式都被评估一次且仅一次，所以最终的堆栈元素等于整个类型的顺序。

```该实现首先将字符串压缩为有意义的标记：单元类型和函数箭头。 括号被忽略，因为它们仅强制分组并且不影响计算顺序。 标记化之后，求值就变成了一个由整数组成的小表达式的归约问题`->`。 

这`reduce`函数反复折叠表单的模式`value -> value`成单个计算顺序。 重复的减少确保尊重右关联性：像这样的链`a -> b -> c`变得`a -> (b -> c)`当然，因为只有当右侧完全形成时才会发生还原。 

一个常见的陷阱是试图在看到后立即进行评估`->`。 这会失败，因为右侧可能尚未完成。 延迟归约直到两个操作数都存在可以避免此问题。

 ## 边缘情况

 一个重要的边缘情况是当括号包裹函数类型时，例如`(()->())`。 内心的表达`()->()`计算结果为 1，括号将其保留而不进行修改。 该算法正确标记`()`作为 0，形式`0 -> 0 = 1`，并将外括号视为无操作，保持结果不变。 

另一个边缘情况是长右关联链，例如`()->()->()->...`。 堆栈永远不会增长超过线性大小，并且每次归约都会崩溃一个运算符，确保最终结果反映重复应用`max(order(left)+1, order(right))`无需重新处理较早的片段。
