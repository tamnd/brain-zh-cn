 ## 解决方案
 ## 问题理解

 尼基塔有一座一开始是空的塔，他每次移动都可以执行两种操作之一：要么在顶部放置一个立方体，要么从顶部移除一个立方体。 问题问的是，在执行完之后是否`n`移动时，塔可以精确地`m`立方体。 每个测试用例提供移动次数`n`和所需的高度`m`。 如果可能，则输出为“Yes”，否则输出为“No”。 

限制很小：两者`n`和`m`最多 100 个，并且最多有 100 个测试用例。 这意味着任何具有大致复杂性的算法`O(n)`每个测试用例将在时间限制内顺利运行。 问题本质上是关于奇偶性和可达性，而不是详尽的模拟。 

不明显的边缘情况发生时`m`大于`n`或当`m`和`n`有不同的奇偶性。 例如，如果`n = 2`和`m = 3`，不可能只用两步就能到达三个立方体。 同样，如果`n = 3`和`m = 2`，经过 3 次操作后，移动必须在高度 2 处离开塔，但由于每次移动都会将高度恰好改变 1，因此`n`和`m`必须匹配它才可能。 

## 方法

 暴力方法将尝试模拟添加和删除立方体的所有序列。 对于每次移动，您可以递归地尝试添加或删除立方体并检查最终高度是否匹配`m`。 这适用于非常小的输入，但具有指数复杂性：每个`n`移动有两种选择，所以有`2^n`可能的序列。 即使与`n = 100`，这是不可行的。 

关键的见解是限制最终塔高度的唯一因素是移动总数`n`和奇偶性`m`。 每一次移动都会使塔的高度恰好改变一，所以之后`n`移动时，与起点（零）的高度差必须是与以下奇偶校验相同的数字`n`。 此外，可达到的最大高度为`n`如果尼基塔只添加立方体。 因此，准确达到的条件`m`立方体是`m`至多是`n`和`m`具有相同的奇偶性`n`。 这将问题简化为无需模拟的简单检查。

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取整数`n`和`m`。 
3. 检查是否`m`小于或等于`n`。 如果不是，则输出“No”并继续。 
4. 检查奇偶校验是否`n`和`m`匹配，意义`(n - m) % 2 == 0`。 如果是，则输出“Yes”； 否则，输出“No”。 

这样做的原因是每次移动都会将塔的高度精确地改变 1，因此两者之间的差异`n`和`m`必须是偶数才能精确到达`m`后`n`移动。 条件`m <= n`确保尼基塔不需要比允许的更多的动作来达到所需的高度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    if m <= n and (n - m) % 2 == 0:
        print("Yes")
    else:
        print("No")
```该代码使用有效地读取输入`sys.stdin.readline`。 对于每个测试用例，它立即检查两个条件：`m <= n`确保我们有足够的动作来达到高度，并且`(n - m) % 2 == 0`确保上下移动的次数可以安排准确到达`m`。 这可以避免不必要的循环或递归。 

## 工作示例

 **示例1：**`n = 3, m = 3`| n | 米 | n - 米 | 奇偶校验| 结果 |
 | --- | --- | --- | --- | --- |
 | 3 | 3 | 0 | 0 % 2 == 0 | 是的 |

 差异为零、偶数且`m <= n`，因此每次移动添加一个立方体就可以达到 3 个立方体。 

**示例2：**`n = 2, m = 4`| n | 米 | n - 米 | 奇偶校验| 结果 |
 | --- | --- | --- | --- | --- |
 | 2 | 4 | -2 | -2 % 2 == 0 | 没有 |

 虽然奇偶校验满意，`m > n`使得仅 2 步就不可能达到高度 4。 

这些痕迹表明这两个条件都是必要且充分的。

 ## 边缘情况

 当`m = 0`和`n`是偶数时，算法会正确输出“是”，因为尼基塔可以交替添加和删除立方体以得到空塔。 例如，`n = 4, m = 0`结果`(n - m) % 2 = 0`和`m <= n`，因此输出为“是”。 

什么时候`m > n`，算法立即输出“否”，避免对负面移动的错误假设。 例如，`n = 3, m = 5`即使奇偶校验匹配，也会产生“否”，因为高度无法到达。 

什么时候`n`和`m`奇偶校验不同时，算法输出“否”，捕获由于奇偶校验不匹配而导致 ±1 移动序列无法到达目标的微妙情况，例如`n = 5, m = 2`。
