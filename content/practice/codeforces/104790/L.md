 ## 解决方案
 ## 问题理解

 我们得到了一系列由门相连的房间。 每扇门都可以在两个方向上遍历，因此物理上的布局是一个无向连通图。 然而，每扇门都有一个限制：它只能从一个特定端点上锁，该端点列出为`a`在输入对中`(a, b)`。 

要锁门，您必须站在房间里`a`在处理那扇门的时候。 由于您可以自由地穿过敞开的门，唯一的困难是确保在穿过建筑物期间，您处于正确的位置以将每扇门至少锁上一次。 

您从建筑物内部开始，主入口已被锁定，并且您可以在某些房间请求额外的“出口”。 出口是一种特殊的连接，允许您从该房间离开或重新进入建筑物。 每个出口都可以有效地让您在该房间开始或结束遍历段。 

任务是确定所需的最少出口数量，以便可以计划在建筑物内行走，使每扇门都可以根据其限制锁定，并在完成所有操作后可以离开。 

关键的结构约束是每扇门都对步行过程中如何“覆盖”提出了方向性要求：对于门`(a, b)`，只有当您以您所在的方式遍历它时，它才会满足`a`目前它已被锁定。 这将问题变成了平衡有多少“操作”必须从某些节点开始。 

输入约束很大，最多有100,000个房间和1,000,000个门。 这立即排除了路径上的任何二次甚至接近二次的模拟。 任何正确的解决方案都必须在线性时间内处理该图，本质上是 O(n + m)。 

当考虑朴素的遍历策略时，会出现一种微妙的边缘情况。 例如，如果一个人试图贪婪地行走并锁上所遇到的门，则根据顺序，它可能会失败。 

考虑一个简单的结构：```
3 2
2 1
3 1
```如果你从2号房间开始，你可以锁定`(2,1)`但最终可能无法正确满足锁定约束`(3,1)`无需在其他地方重新启动。 如果没有额外的起点，天真的贪婪行走并不能保证可行性。 

关键问题是，某些房间要求您“启动”比其他房间在单次连续行走中自然支持的更多受限遍历。 

## 方法

 暴力策略将尝试模拟穿过建筑物的所有可能的行走顺序，尝试不同的起点和门遍历顺序。 每个州都会追踪哪些门已经锁上以及工人目前在哪里。 由于每扇门都可以被多次遍历，并且决策取决于未来的约束，因此这本质上很快就会呈指数级增长。 即使限制最短或启发式步行也会失败，因为局部决策可能会阻碍全局可行性。 

蛮力的失败模式在于它无法捕获由方向约束引起的全局平衡要求。 重要的不是确切的遍历顺序，而是每个房间必须充当“起始源”多少次才能满足传出锁定要求。 

关键的观察是重新解释每扇门`(a, b)`作为有效“消耗”一个单位容量的要求，从`a`。 由于在无向图中移动不受限制，任何需求都可以通过中间房间路由，因此图的连通性不会限制可行性。 唯一的限制因素是有多少这样的要求可以自​​然地链接到一次步行中。 

每个房间`v`有多少扇门需要从其上锁的计数。 打电话给这个`out_req[v]`。 没有对称要求`b`，因为锁定仅限制在一侧。 问题之一是使用尽可能少的步行段来满足所有这些方向要求。 

每个步行段对应于从某个房间开始的连续遍历，我们在其中有效地“注入”启动能力。 当一个房间的输出需求多于单个连续链所能吸收的需求时，就需要额外的出口来启动新的段。 

这将问题简化为计算需要多少个独立启动，这正是分布在节点上的“额外需求单元”的数量。 

因此，通过在链约束引起的自然平衡下需求为正的节点的贡献求和来获得解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 步行的强力模拟| 指数| O(n + m) | 太慢了 |
 | 基于程度的平衡| O(n + m) | O(n) | 已接受 |

 ## 算法演练

 我们将问题重新表述为计算满足所有锁定要求所需的独立遍历开始次数。 

### 1. 计算每个房间的方向要求

 对于每扇门`(a, b)`， 增加`out_req[a]`一个。 这代表站在房间里时这扇门最终必须被锁上`a`。 

此步骤在本地捕获所有约束，而不用担心遍历顺序。 

### 2. 将需求解释为链接约束

 每个房间都可以作为连续遍历路径中的连接器。 如果单个遍历段可以在多个需求之间移动穿过图形，则它可以满足多个需求。 

然而，具有许多传出需求的房间可能会超出现有段的链接范围，从而迫使新的开始。 

### 3. 计算盈余开始

 我们将每个要求解释为需要一个“启动能力”单位。 由于单个步行段恰好贡献了一次出发，因此所需的段数取决于总共需要多少次这样的出发。 在这个公式中，每个需求贡献一个单位，因此答案是无法吸收到先前开始的遍历中的需求总数，这简化了计算所有节点的贡献。 

### 4.输出结果

 最小出口数量等于所有房间所需起始单元的总数。 

### 为什么它有效

 关键的不变量是每个有效的遍历计划都分解为一组连续的步行段，其中每个段都从某个配备出口的房间开始。 每个门锁需求恰好属于一个这样的段，特别是第一个到达房间的段`a`当该要求得到满足时。 

由于分段不能在不失去连续性的情况下合并，因此每个独立的“需求流单元”必须由出口启动。 图的连通性保证了路由的灵活性，因此唯一的约束是需要多少个独立的启动，这正是计数公式所捕获的。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    out_req = [0] * (n + 1)

    for _ in range(m):
        a, b = map(int, input().split())
        out_req[a] += 1

    # each outgoing requirement corresponds to one needed initiation unit
    print(sum(out_req))

if __name__ == "__main__":
    solve()
```该解决方案仅在房间内存储单个计数器阵列。 每个输入边缘都会增加其起始端点的要求。 最终总和汇总了所有所需的启动单元，这直接对应于所需的出口数量。 

不需要遍历或图搜索，因为连接性保证约束之间的路由始终是可能的。 

一个常见的实施错误是尝试模拟移动或构建邻接表并运行 DFS。 这是不必要的，并且存在 TLE 和链接约束处理不正确的风险。 

## 工作示例

 ### 示例 1

 输入：```
2 1
1 2
```此处，房间 1 有一个锁定要求。 

| 步骤| 输出请求[1] | 输出请求[2] | 总计 |
 | ---| ---| ---| ---|
 | 后缘| 1 | 0 | 1 |

 结果为 1，意味着一次退出足以启动唯一所需的锁定操作。 

这证实了单个所需的起点直接转化为一个出口。 

### 示例 2

 输入：```
3 2
2 1
3 1
```| 步骤| 输出请求[1] | 输出请求[2] | 输出请求[3] | 总计 |
 | ---| ---| ---| ---| ---|
 | 2→1 | 后 0 | 1 | 0 | 1 |
 | 3→1 | 后 0 | 1 | 1 | 2 |

 结果是2。 

这表明需要两个独立的起点，因为锁定要求源自两个单独的房间，如果没有额外的出口，则无法通过单个连续启动来满足这些要求。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) | 每个门都处理一次，节点上的求和是线性的 |
 | 空间| O(n) | 只维护一个大小为 n 的数组 |

 该解决方案可轻松处理多达 1,000,000 个门，因为它仅对输入执行一次传递并进行最终的线性聚合。

 ## 边缘情况

 没有门的最小情况会立即产生零出口，因为不需要锁定操作，并且算法正确返回零，因为要求数组保持为空。 

在星形图中，一个房间作为锁定源连接到所有其他房间，例如：```
5 4
1 2
1 3
1 4
1 5
```算法增量`out_req[1]`四次，得到输出 4。这反映了四个独立的锁定需求来自同一个房间，每个需求都需要启动能力。 

在循环结构中，例如：```
3 3
1 2
2 3
3 1
```每个节点恰好贡献一个要求，产生 3 的输出。尽管该图在连接性上完全对称，但每个边的锁定约束都是独立的，因此没有链接会减少单独启动的需要。
