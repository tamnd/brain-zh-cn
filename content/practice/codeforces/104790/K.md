 ## 解决方案
 ## 问题理解

 我们得到了一个未知大小的网格$n \times n$，其中每个单元格包含不同的整数高度。 网格不直接可见。 相反，我们只能查询单个坐标并接收该位置的高度。 我们的任务是确定全局最大单元的坐标，但是一旦我们有效地确定了它的位置，问题就被定义为找到它的值。 

一个关键的结构保证改变了搜索的性质：恰好有一个单元严格高于其所有正交邻居。 因为所有值都是不同的，这意味着这个单个“峰值”也是整个网格的全局最大值。 其他地方没有其他局部最大值，这排除了多个竞争峰值的常见复杂情况。 

就每行预算而言，交互限制最多是严格的$10n + 100$查询。 和$n$最多$10^4$，对网格进行全面扫描是不可能的，因为这需要$n^2$最坏情况下的查询。 即使扫描网格的恒定部分也太昂贵。 这迫使任何解决方案都积极减少每个查询的搜索空间。 

一个幼稚的错误是将其视为通过随机采样或逐行扫描的标准矩阵最大搜索。 例如，在像这样的网格上```
1 2 3
4 5 6
7 8 9
```逐行扫描可以工作，但即使是也要花费 9 个查询$n=3$，并且对于大的$n$它变成二次方。 更重要的是，随机性可能会在峰值的对抗性放置下失败，因为单个最大值可能会始终避免采样位置，直到为时已晚。 

微妙的边缘情况来自于只有一个局部最大值的承诺。 移动到更好的邻居的天真的爬山方法在这里是安全的，但前提是我们确保我们永远不会陷入平面逻辑或低效地重新访问已经查询的区域。 如果没有仔细的结构，很容易超出查询限制。 

## 方法

 暴力方法很简单：查询每个单元格并跟踪看到的最大值。 这是正确的，因为所有查询值的最大值必须是网格的全局最大值。 然而，它执行$n^2$查询，即使对于中等程度的人来说也是不可能的$n$。 为了$n = 10^4$，这需要$10^8$查询，远远超出允许的范围$10n + 100$。 

关键的观察是我们不需要检查每个单元格来找到全局最大值。 由于网格具有唯一的峰值，没有其他局部最大值，因此任何始终向更高邻居移动的局部搜索都无法循环或陷入次优区域。 这使我们能够将网格视为一种地形，其中每个非峰值单元至少有一个严格更高的邻居，并且遵循这些改进可以确定地导致全局峰值。 

我们不使用扫描，而是使用查询来模拟梯度上升的形式。 我们维持当前的候选位置并反复将其与其邻居进行比较。 每一步都会移动到一个严格更高的相邻单元格。 由于价值观不同，每一步都严格增加高度，保证进步。 由于网格是有限的并且高度严格增加，因此该过程必须在全局最大值处终止。 

这减少了问题$O(n^2)$查询沿上升路径的有限数量的步数。 每个步骤使用恒定数量的查询，路径长度受到网格结构和峰值的唯一性的限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$查询 |$O(1)$| 太慢了 |
 | 通过查询爬山 |$O(n)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 我们使用查询模拟在隐式网格上上坡。 

1.从任意固定位置开始，例如$(1, 1)$。 这给出了有效的起始高度并确保了确定性行为。 我们查询这个单元格一次。 
2. 在当前位置$(x, y)$，查询其最多四个邻居：$(x-1, y)$,$(x+1, y)$,$(x, y-1)$,$(x, y+1)$，忽略网格之外的那些。 
3. 将查询到的邻居值与当前单元格值进行比较。 如果没有邻居具有严格更大的值，则当前单元格是局部最大值。 
4. 如果存在严格更大的邻居，则移动到其中具有最大值的邻居。 这确保了尽可能陡峭的上升并减少了所需的步数。 
5. 从新位置重复该过程。 

每次移动都会严格增加值，因此我们永远不会重新访问单元格。 这保证了终止。 

### 为什么它有效

 网格定义了一种有向结构，其中每个非最大单元都至少有一个到严格更高邻居的传出边缘。 遵循这些边保证会导致该有向图的唯一汇，这是全局最大值。 由于值是不同的，因此该结构是非循环的，因此遍历不能循环。 因此，该算法保证恰好在峰值处结束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = None
cache = {}

def ask(x, y):
    if (x, y) in cache:
        return cache[(x, y)]
    print("?", x, y)
    sys.stdout.flush()
    v = int(input().strip())
    cache[(x, y)] = v
    return v

def inb(x, y):
    return 1 <= x <= n and 1 <= y <= n

def solve():
    global n
    n = int(input().strip())

    x, y = 1, 1
    cur = ask(x, y)

    while True:
        best_x, best_y = x, y
        best_val = cur

        for dx, dy in ((1,0), (-1,0), (0,1), (0,-1)):
            nx, ny = x + dx, y + dy
            if not inb(nx, ny):
                continue
            val = ask(nx, ny)
            if val > best_val:
                best_val = val
                best_x, best_y = nx, ny

        if (best_x, best_y) == (x, y):
            print("!", cur)
            sys.stdout.flush()
            return

        x, y = best_x, best_y
        cur = best_val

if __name__ == "__main__":
    solve()
```该解决方案依赖于记忆`cache`以避免重复查询，这很重要，因为通过不同的邻居检查可以多次遇到相同的小区。 每次迭代仅在找到严格更高的邻居时才移动，确保单调上升。 

边界处理是明确的`inb`，防止网格外的无效查询。 仅当没有邻居改善当前值时，循环才会终止，当前值恰好对应于唯一的全局峰值。 

## 工作示例

 考虑一个小网格：```
1 2 3
4 9 5
6 7 8
```开始于$(1,1)$。 

| 步骤| 位置 | 当前值| 邻居价值观 | 移动|
 | ---| ---| ---| ---| ---|
 | 1 | (1,1) | 1 | (2,1)=4, (1,2)=2 | (2,1) |
 | 2 | (2,1) | 4 | (1,1)=1, (3,1)=6, (2,2)=9 | (2,2) |
 | 3 | (2,2) | 9 | 所有邻居都较小| 停止|

 该算法直接爬到 (2,2) 处的峰值。 

现在考虑一个“山脊”样式的网格：```
10 1  2
9  3  4
8  7  6
```| 步骤| 位置 | 当前值| 邻居价值观 | 移动|
 | ---| ---| ---| ---| ---|
 | 1 | (1,1) | 10 | 10 (2,1)=9, (1,2)=1 | (2,1)=9, (1,2)=1 | 停止|

 这里的开始已经是全局最大值，并且算法立即终止，确认对也是全局最大值的局部最大值的正确处理。

 ## 边缘情况

 最小尺寸网格$1 \times 1$立即满足停止条件。 算法查询$(1,1)$，找不到邻居，直接输出值，正确处理退化情况。 

边界峰值情况，例如```
5 4
3 2
```开始于$(1,1)$值为 5。由于两个邻居都较小，因此算法立即停止，确认无需移动即可处理角最大值。 

单调增加的结构迫使重复向上移动，直到到达右下角的单元格。 每一步都严格增加价值，确保无循环终止，并证明算法不依赖于几何对称性，而只依赖于严格的改进。
