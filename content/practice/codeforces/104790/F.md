 ## 解决方案
 ## 问题理解

 缆车前有一个排队系统，白天运行固定的分钟数。 每分钟，都有已知数量的人到达并加入队列，在处理完这些到达后，一辆马车立即出发，并从队列前面移除固定数量的人。 

您可以选择操作窗口内的一分钟到达。 如果您在第 i 分钟到达，那么您会排在所有同一分钟到达的人之后，这意味着您被放置在该分钟所有新到达者和所有已经等待的人后面。 从那一刻起，您就等待系统最终为您服务。 您的等待时间是指您到达的分钟与您登上车厢的分钟之间的分钟数。 

目标是选择最短等待时间的到达时间。 如果多个分钟给出相同的最短等待时间，则应选择最早的分钟。 如果白天没有一分钟你最终可以登上马车，那么答案是不可能的。 

这些限制允许最多 100,000 分钟以及每分钟非常大的到达计数。 这排除了针对每个可能的到达时间从头开始重新计算队列状态的任何模拟。 在最坏的情况下，对每候选分钟的队列演化进行简单的 O(n^2) 模拟将执行大约 10^10 次操作，并且不会及时完成。 

一些边缘情况对于正确性很重要。 如果到达人数如此之多，以至于即使在每分钟 n 分钟的服务容量 c 后，队列也永远不会清空，那么到达时间就无效。 例如，如果n = 5，c = 1，a = [5, 0, 0, 0, 0]，系统总共只能服务5人，但包括你在内出现了6人，所以你永远无法登机。 

另一个微妙的情况是，即使队列更大，晚一点到达有时也可以减少等待时间，因为早几分钟可能会让您落后于大量突发事件，从而产生较长的剩余等待间隔。 这使得有必要在一致的公式下评估所有候选到达时间，而不是依赖贪婪的直觉。 

## 方法

 蛮力方法独立考虑每个可能的到达分钟 i。 对于每个 i，我们从一天开始模拟队列，重建直到 i 分钟的完整状态，插入我们自己，并继续一分钟一分钟地模拟，直到我们得到服务或一天结束。 这正确地模拟了该过程，但它对每个 i 重复了几乎整个模拟。 如果每次模拟需要 n 分钟且工作时间为 O(n)，则这将变为 O(n^2)，当 n 为 100,000 时，这太慢了。 

关键的观察是，一旦我们知道加入时有多少人领先于我们，我们就不再需要一步一步地模拟。 在我们到达后，系统总是每分钟移除 c 个人，因此我们的位置每分钟确定性地减少 c 人。 这将问题变成了一个简单的算术问题：在我们的位置达到零之前需要多少次完整的“服务轮”。 

对于固定到达分钟 i，令 prefix[i] 为截至第 i 分钟（包括第 i 分钟）到达的总人数。 由于我们在第 i 分钟到达 a 个人之后，因此我们在队列中的位置变为 prefix[i] + 1。从那一刻起，每分钟都会从前面删除 c 个人，因此到达我们所需的分钟数是最小的 k，使得 k · c ≥ prefix[i] + 1。这给出了等待时间的封闭形式表达式。 

在前缀预处理之后，我们在 O(1) 中计算每个 i 的值，然后选择最佳候选。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n^2) | O(n^2) | O(1) 或 O(n) | 太慢了 |
 | 前缀+闭合形式 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ## 算法演练

1. 计算到达的前缀总和，使 prefix[i] 表示从第 0 分钟到第 i 分钟到达的人数。 这使我们能够在到达之前随时了解确切的队列大小，而无需重新模拟。 
2. 对于每个候选到达分钟 i，确定到达 i 后系统中已有多少人。 这是 prefix[i]，由于我们在同一分钟到达后加入，因此我们的位置变为 prefix[i] + 1。 
3. 将此队列位置转换为需要多少趟整车出发才能到达我们。 每次出发会删除 c 人，因此我们需要 k = ceil((prefix[i] + 1) / c) 次出发。 
4. 将所需出发次数换算为等待时间。 由于到达第 i 分钟后第一次可能的出发发生在同一分钟，因此我们等待的分钟数为 k − 1。 
5. 跟踪所有 i 的最短等待时间。 如果多个 i 产生相同的值，则保留最小的 i。 
6. 检查可行性。 即使候选者看起来是最佳的，也只有在服务窗口足够长以实际到达我们手中时才有效。 如果没有 i 允许我们在 n 分钟结束之前得到服务，则输出“不可能”。 

### 为什么它有效

 关键的不变量是，在确定到达分钟 i 后，我们在队列中的相对位置在每分钟后确定性地减少 c，与所有未来的到达无关。 所有未来的到达只会影响我们后面的人，而不影响我们从队列中删除的速度。 这将系统简化为单变量过程，其中只有我们的初始位置很重要。 因为等待时间仅取决于 prefix[i]，所以比较候选对象减少为评估 i 上的封闭式函数，从而保证所有 i 中的最小值是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))

    pref = 0
    best = None
    best_i = 0

    total = 0
    for x in a:
        total += x

    # If even all capacity cannot serve everyone + us
    if total + 1 > n * c:
        print("impossible")
        return

    for i in range(n):
        pref += a[i]
        pos = pref + 1

        # ceil(pos / c)
        k = (pos + c - 1) // c
        wait = k - 1

        if best is None or wait < best or (wait == best and i < best_i):
            best = wait
            best_i = i

    print(best_i)

if __name__ == "__main__":
    solve()
```该解决方案维护一个运行的前缀和，以便在恒定时间内评估每个候选分钟。 位置计算`pref + 1`编码同一分钟到达的规则比您早。 天花板部门计算需要多少满载车厢才能清除前面的每个人。 可行性检查可确保即使在最佳情况下，所有分钟内的总服务容量也足以容纳您； 否则，任何候选人都无法成功。 

最终的选择保留了最短等待时间和最早的索引，通过直接比较索引来解决平局。

 ## 边缘情况

 对于到达量超过总容量的完全饱和系统，前缀和可行性检查会立即触发。 例如，在`n=3, c=1, a=[2,2,2]`，总到达次数为 6，而容量为 3，因此算法在没有模拟任何分钟的情况下输出“不可能”。 

如果到达时间严重偏向早几分钟，例如`a=[100,0,0,...]`，第 0 分钟的前缀已经将您排在一个大队列后面。 该算法正确地计算了提前到达的较长等待时间，并且可能更喜欢前缀不变的较晚几分钟，但可行性仍然仅取决于总容量，该算法独立于每分钟评估进行检查。
