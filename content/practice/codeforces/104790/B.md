 ## 解决方案
 ## 问题理解

 我们得到一个数字$n$，表示如果仅依靠爪子，需要多少次单单元爪子操作才能完全拆除对手机器人。 每一次爪子操作都会去除一个结构单元，但机器人在概念上很大，我们只知道它的总尺寸。 

除了爪术之外，我们还有剑术。 剑切割不会直接去除材料。 相反，它将当前活动的机器人分成两部分，并且只有其中一部分继续移动，因为电机正好位于一半内部。 我们不知道哪一半包含电机，因此从我们的角度来看，最坏的情况是较大或更麻烦的一半总是幸存下来。 这意味着用剑切割一段尺寸后$x$，下一个状态实际上是一个大小的段$\lceil x/2 \rceil$。 

目标是完全摧毁机器人，这意味着将活动段的大小减少到零。 我们希望机器人在每次剑砍后的最坏情况演化中的操作次数最少。 

微妙之处在于我们无法控制随机性。 每一次剑砍都会迫使我们进入最糟糕的生存一半，因此每个决定都必须针对该结果进行稳健。 天真的解释可能会认为剑砍总是以乐观的方式将尺寸缩小一半，但在这里，天花板行为才是重要的，而且它是复杂的。 

约束条件$n \le 10^{18}$立即排除任何超过值的动态编程$n$，甚至线性或二次推理也是不可能的。 任何解决方案都必须乘法减小问题大小或使用以对数时间计算的封闭递归。 

当将剑视为“大致减半，因此它总是比抓握更好”时，出现了一个常见的错误。 对于小值来说，情况并不总是如此。 例如，当$n = 2$，一把剑减少到 1，但仍然需要多一步，匹配爪效率。 什么时候$n = 1$，剑没有任何用处，爪是强制性的。 这种边界行为打破了过度贪婪的假设。 

另一个陷阱是假设答案与$\log n$直接地。 仅在线性抓握占主导地位或与剑的使用相关的小前缀之后，该序列才开始以对数方式表现。 

## 方法

 蛮力策略将模拟每个可能的操作序列，保持当前的段大小并在每一步探索两种选择：要么应用爪减少$x \to x-1$，或应用剑减少$x \to \lceil x/2 \rceil$。 这形成了状态的搜索树。 即使我们记住结果，状态空间仍然是从 1 到$n$，每个状态取决于两个转换。 

直接 DP 的递推式为$$f(x) = 1 + \min(x-1, f(\lceil x/2 \rceil)).$$虽然正确，但对所有人都天真地评估这一点$x \le n$是不可能的，当$n$达到$10^{18}$。 

关键的观察结果是，一旦爪子操作变得严格劣质$x$足够大，因为反复减半很快就主导了线性减量。 在一个小阈值之后，最佳策略始终是使用剑，因为它以指数方式减小问题的大小，并且单个额外步骤的开销可以通过快速收缩来补偿。 

这将问题转化为重复应用递归$$f(x) = 1 + f(\lceil x/2 \rceil),$$直到到达已知直接值的小基区。 这将整个过程简化为计算我们可以重复取上限一半直到达到 1 的次数，并仔细处理小值。

 ## 算法演练

 我们想要计算减少当前大小所需的最小操作数$n$到 0，其中每一步要么减一，要么用上限一半替换该数字。 

1. 首先观察对于任何电流大小$x$，结果仅取决于两个选择：减少到$x-1$，或减少到$\lceil x/2 \rceil$。 答案总是这两个延续中较好的一个加一。 
2. 定义函数$f(x)$作为销毁大小的段所需的最少操作$x$。 为了$x = 0$，无需任何操作。 
3.为了$x = 1$，只有爪子才有意义，所以$f(1) = 1$。 这建立了减半毫无用处的基本情况。 
4. 对于$x > 1$，比较两种策略。 爪子给出成本$x$。 剑付出代价$1 + f(\lceil x/2 \rceil)$。 
5.观察一次$x \ge 4$，重复使用剑占主导地位，因为它会成倍地降低状态，使得重复爪的线性成本总是更差。 
6. 因此，对于所有有意义的较大值，我们使用递归$f(x) = 1 + f(\lceil x/2 \rceil)$。 
7. 从以下位置开始重复应用此变换$n$，计算我们应用它的次数，直到达到 1。 

为什么它有效

 核心不变量是，在每次剑操作之后，问题都会简化为相同形式的严格较小的实例，并且最优决策结构不依赖于除当前大小之外的任何隐藏状态。 递归保证了我们在每一步都选择全局最优操作，因为任何较早使用爪子的替代序列都可以通过用后面的剑替换该爪子来转换为具有至少相同步骤的序列，而不增加最优性。 该问题分解为单个确定性约简链。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    # base cases
    if n <= 1:
        print(1)
        return
    
    # f(1)=1, f(2)=2, f(3)=3 are special small values
    # but recurrence f(x)=1+f((x+1)//2) works for all x>=2
    res = 0
    x = n
    
    while x > 0:
        res += 1
        if x == 1:
            break
        x = (x + 1) // 2
    
    print(res)

if __name__ == "__main__":
    solve()
```该实现直接遵循先前导出的递归。 循环重复应用变换$x \to \lceil x/2 \rceil$，其实现为$(x+1)//2$，同时计算所采取的步数。 每次迭代完全对应于最优策略中的一个操作。 

一个微妙的点是终止条件的处理。 一次$x$变为 1 时，我们仍然计算销毁它的最终操作，因此循环确保正确包含此步骤。

 ## 边缘情况

 对于$n = 1$，算法立即返回 1，因为没有减半可以减少状态。 任何应用重复的尝试仍必须考虑强制最终销毁步骤。 

对于像这样的小值$n = 2$和$n = 3$，递归转换仍然正确，但尚未表现出渐近减半行为。 该算法通过同一个循环统一处理它们，确保没有特殊的大小写错误。 

对于略高于 2 的幂的值，例如$n = 2^k + 1$，上限除法确保第一次归约不会表现得像完美的二元分割。 使用$(x+1)//2$正确地保留了这种不对称性，并且迹线遵循相同的确定性收缩序列而没有偏差。
