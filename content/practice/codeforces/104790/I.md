 ## 解决方案
 ## 问题理解

 我们得到了一组国家/地区，每个国家/地区的感染分数均呈非递减趋势。 在任何两个国家之间旅行总是需要一天的时间，但抵达后可能会引发额外的检疫处罚，具体取决于前一个国家与目的地相比的情况。 

更准确地说，当从 i 国移动到 j 国时，旅行者总是在移动过程中花费一天的时间。 如果出发地的感染分数明显高于目的地，特别是如果 r[i] 超过 r[j] m 以上，则在到达 j 时会产生额外的隔离时间 t[j]。 否则，除了单个旅行日外，不会增加额外的延误。 

每个查询询问从出发国家 x 到目的地国家 y 所需的最小可能总时间，其中允许旅行者以任意顺序访问中间国家，并且旅行图是完整的。 

关键的困难在于，虽然每对国家都是直接相连的，但边缘的成本取决于 r 的相对值，并在目的地引入与国家相关的惩罚。 这使得该问题成为具有非均匀边权重的密集图上的最短路径问题。 

最大 100000 的约束 n 和 q 排除任何全对最短路径计算或每个查询图搜索。 即使每个查询只有一个 Dijkstra 也会太慢，因为如果简单地实现，每次运行的时间复杂度为 O(n^2)，如果优化的话，每次运行的时间复杂度为 O(n log n)，在最坏的情况下会导致大约 10^10 次操作。 

因此，正确的解决方案必须避免重新计算路径，而是利用排序的 r 数组中的结构。 

当最佳路线不是直达时，即使直达旅行没有隔离，也会出现微妙的边缘情况。 例如，直接转移可能会产生较大的 t[j]，而通过中间国家可以减少或消除惩罚。 相反，采取额外的跳数也会引入不必要的 t 惩罚，因此最优路径不仅仅是 r 或索引顺序中的单调。 

## 方法

 暴力解决方案会将其视为完整有向图上的最短路径问题。 对于每个查询，我们将从 x 开始运行 Dijkstra，考虑到所有其他节点的所有可能转换，边权重为 1 加上可选的隔离惩罚，具体取决于 r 值之间的条件。 这是正确的，因为它显式地探索所有有效的行进序列，但在密集实现中每个查询的成本为 O(n^2)，或者使用优先级队列和邻接扫描的每个查询的成本为 O(n log n)，这对于 10^5 查询来说变得太慢。 

主要观察结果是 r 值已经排序，这对惩罚发生时施加了强大的结构。 隔离条件仅取决于我们是否在 r 中“向下”移动超过 m。 这将相对于源的目的地分为两组：不支付惩罚的安全目的地和我们支付 t[j] 的不安全目的地。 

这种结构意味着对于任何国家 i，传出边的成本行为仅取决于 j 在排序的 r 数组中的位置。 我们可以将转换压缩成更小的结构，而不是将图视为完全任意的。 关键的结果是，任何最佳路线都不会从 r 中的“之字形”中获得不必要的好处，因为每一跳的成本要么是 1，要么是 1 加上目的地惩罚，并且中间绕道不会创造超出相邻 r 级别已经提供的新的无惩罚机会。

这使我们能够按照 r 的排序顺序将有效图简化为邻国之间的转换。 一旦这种减少被接受，问题就变成了折线图上的最短路径问题，其中每个相邻对都有一个派生的转移成本，代表它们之间的最佳可能的直接或绕道移动。 

一旦图形成为一条线，最短路径就变成了前缀和，因此每个查询在预处理后都可以在 O(1) 内得到回答。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的蛮力 Dijkstra | O(q·n²) | O(q·n²) | O(n) | 太慢了 |
 | 简化折线图+前缀预处理 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们首先按照 r 值对国家进行排序，r 值已经保证是非递减的，因此指数已经定义了这个顺序。 

然后，我们计算此排序中每个相邻对之间的有效成本。 这个想法是，任何较长距离的移动都可以通过链接相邻的移动来进行最佳模拟，因此我们只需要了解邻居之间的转换。 

对于每个相邻对 i 和 i+1，我们计算在它们之间沿任一方向移动的最佳可能成本。 这包括强制旅行日和任何检疫处罚，具体取决于方向和间隙情况。 我们将其存储为无向有效边权重 w[i]。 

此后，整个国家系统的行为就像索引 1 到 n 上的路径图一样，其中从 i 移动到 j 相当于将它们之间的唯一路径的边权重相加。 

我们在这些相邻权重上构建一个前缀和数组，以便我们可以在恒定时间内回答路径成本。 

最后，对于每个查询 (x, y)，我们确保 x 和 y 被解释为排序顺序中的位置，并返回前缀和的绝对差。 

### 为什么它有效

 关键的不变量是，最优路径永远不会因跳过按 r 顺序排序的中间国家而受益。 任何可以降低成本的直接跳跃都已在相邻转换中表示，因为非线性的唯一来源是隔离条件，它仅取决于 r 中的相对顺序。 一旦我们将注意力限制在 r 空间中的最小步转换上，所有较长的边都会分解为这些转换的等效或更差的序列，而不会引入新的机会来避免惩罚。 这保证了原始图中的最短路径与导出路径图中的最短路径匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q, m = map(int, input().split())
r = list(map(int, input().split()))
t = list(map(int, input().split()))

# We assume indices already correspond to sorted r.

# compute effective edge cost between i and i+1
w = [0] * (n - 1)

for i in range(n - 1):
    # cost i -> i+1
    cost1 = 1
    if r[i] > r[i + 1] + m:
        cost1 += t[i + 1]

    # cost i+1 -> i
    cost2 = 1
    if r[i + 1] > r[i] + m:
        cost2 += t[i]

    w[i] = min(cost1, cost2)

# prefix sums over path edges
pref = [0] * n
for i in range(1, n):
    pref[i] = pref[i - 1] + w[i - 1]

out = []
for _ in range(q):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    if x < y:
        out.append(str(pref[y] - pref[x]))
    else:
        out.append(str(pref[x] - pref[y]))

print("\n".join(out))
```该实现首先通过为每个相邻对分配有效的转换成本，将问题压缩为单个链。 它仔细考虑了两个方向，因为隔离不对称地取决于行进方向。 

然后，前缀数组充当该链上的距离累加器，允许在不遍历图形的情况下回答每个查询。 

主要的微妙之处在于我们从未明确构建完整的图。 相反，我们依赖这样一个事实：所有有意义的结构都会按排序的 r 顺序折叠成相邻的转换。

 ## 边缘情况

 当隔离因为 m 非常大而永远不会触发时，就会出现一种边缘情况。 在这种情况下，每条边的成本恰好为 1，并且算法简化为简单的索引距离。 前缀和构造自然会产生这种行为，因为所有 w[i] 都变为 1。 

当 m 为零并且 r 值差异很大时，会出现另一种边缘情况。 在这种情况下，r 的每一次向下移动都会受到惩罚。 邻接减少仍然有效，因为每个步骤都正确捕获惩罚是否适用于每个方向，并且前缀结构沿着路径一致地累积这些惩罚。 

第三种边缘情况是 x 和 y 在原始排序中相邻。 该算法直接处理这个问题，因为它们的答案正是单个预先计算的边权重，并且前缀减法正确地退化为该值。
