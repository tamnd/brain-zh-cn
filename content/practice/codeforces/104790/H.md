 ## 解决方案
 ## 问题理解

 我们得到了一个由四种颜色组成的有限矩形图案，但该图案在水平和垂直方向上无限重复，形成平面的无限平铺。 这个无限网格中的每个单元格都有一个颜色，该颜色是通过对原始图案大小取模来确定的。 

从这个无限网格中，我们想知道是否可以找到一个正方形子区域，使其所有边界与单元格边界对齐，并且该正方形的四个角单元都存在于网格中并具有四种不同的颜色。 

正方形可以是任意正大小。 由于网格周期性地重复，因此任何有效的配置必须已经存在于基本图案的某个有限偏移内，但正方形本身可能跨越多个周期。 

任务是确定在无限重复中的任何位置是否至少存在一个这样的正方形。 

约束非常不对称：高度可以大到 4000，而宽度最多为 50。这立即表明任何依赖于行数的二次或更差的解决方案都可能很昂贵，但任何宽度呈指数形式的都是可以接受的，因为宽度很小。 

一个关键的结构含义是，由于宽度较小，水平行为会快速重复，而垂直行为则主导复杂性。 任何解决方案都必须跨行大量压缩或重用信息，而不是天真地重新计算逐行交互。 

一个微妙的边缘情况是当图案太小而无法形成具有四个不同角的正方形时。 例如，1 x w 或 h x 1 网格使得不可能形成正尺寸的正方形，因此在这些情况下答案总是不可能的。 

当图案是周期性的并且限制了可到达的角组合时，就会出现另一种棘手的情况。 例如，即使所有四种颜色全局存在，周期性对齐也可能会阻止它们同时出现在边长在两个方向上一致的任何正方形的角上。 

## 方法

 一种简单的方法尝试通过展开足够大的区域然后检查所有可能的正方形来显式模拟无限网格。 由于该图案每隔 h 乘 w 重复一次，因此可以考虑将其扩展至至少 2h x 2w 的大小，甚至更大，以考虑包裹正方形。 

然后我们将枚举所有成对的左上角和右下角的正方形，并验证这四个角是否具有不同的颜色。 这会导致 O(N^3) 或更糟糕的行为，具体取决于平方的枚举方式。 即使稍微优化，当 h 达到 4000 时，检查大型扩展网格中所有可能的方格很快就变得不可行。 

关键的观察是无限重复意味着我们不需要考虑绝对位置，只需要考虑相对偏移。 任何正方形都由两个向量定义：水平移位和垂直移位。 角颜色仅取决于位置模 (h, w)。 这将问题简化为检查是否存在两个不同的行索引和两个不同的列索引，使得四个结果单元格形成四种颜色的排列。 

我们可以将问题重新解释为选择两行 i 和 j 以及两列 x 和 y，形成一个矩形，并检查 (i, x)、(i, y)、(j, x)、(j, y) 处的四个角值是否都不同。 无限网格中的重复不会改变这个条件，因为任何更大的正方形都简单地对应于重复相同的相对结构。 

所以问题就变成了：是否存在任意一对行和列使得导出的 2 × 2 子矩阵具有四个不同的值？ 这相当于找到任何一对列，在其中的一对行中，我们在四个交叉点上恰好看到一次所有四种颜色。

我们可以修复两列，并将问题简化为扫描行并寻找产生四个不同对的行对。 由于宽度只有 50，所以列对的数量最多为 1225 个，这是可以管理的。 对于每个列对，我们扫描行并跟踪看到的颜色对。 如果我们找到两行，其列对共同产生所有四种不同的颜色，我们立即成功。 

这将问题从难以管理的几何搜索减少为对列对的组合检查和对行的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解扩展网格中的所有方格 | O(h²w²) 或更差 | O(hw) | 太慢了 |
 | 修复列对，扫描行以获得颜色覆盖 | O(h·w²) | O(1)-O(w²) | O(1)-O(w²) | 已接受 |

 ## 算法演练

 我们利用这样一个事实，即通过选择两个不同的列和两个不同的行，并检查这些坐标上的四个角颜色是否都不同来完全确定有效的正方形。 

1. 迭代所有列对 (c1, c2)。 由于 w ≤ 50，因此最多为 1225 对，该值足够小，足以允许对每对的所有行进行全面扫描。 
2. 对于固定列对，我们扫描所有行并为每行 r 构建颜色对 (grid[r][c1], grid[r][c2])。 每行都为该列对贡献一个双色签名。 
3. 在扫描行时，我们尝试检测是否存在两行 r1 和 r2，使得四个值：

 (r1,c1),(r1,c2),(r2,c1),(r2,c2)

 都是不同的。 这相当于检查两个行签名是否一起包含跨两列的四种不同颜色。 
4. 为了有效地做到这一点，我们为当前列对维护一个映射或一组可见的行签名。 对于每个新的行签名，我们将其与所有先前看到的签名进行比较。 如果任何一对产生四种不同的颜色，我们立即返回“可能”。 
5. 如果没有列对产生这样的行对，我们返回“不可能”。 

关键的实现细节是行签名空间非常小：每个签名都是大小为 4 的集合中的一对颜色，因此只有 16 个可能的签名。 这使得存储每个签名的计数或列表而不是完整的行历史记录变得高效。 

### 为什么它有效

 无限平铺中的任何有效方块都可以按周期性映射到由基本图案内的两个不同的行和两个不同的列定义的配置中。 重复不会改变拐角关系，只会改变它们。 因此，如果无限网格中的任何位置存在有效的正方形，则存在完全由基本网格中的一对行和列捕获的等效正方形。 我们对所有列对的枚举保证了我们考虑定义其水平结构的精确对，而行扫描保证我们最终遇到所需的垂直对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    grid = [input().strip() for _ in range(h)]

    if h < 2 or w < 2:
        print("impossible")
        return

    for c1 in range(w):
        for c2 in range(c1 + 1, w):
            seen = {}
            for r in range(h):
                a = grid[r][c1]
                b = grid[r][c2]
                key = (a, b)

                for (pa, pb) in seen:
                    # check 2x2 corners: (pa, c1/c2) and (r, c1/c2)
                    # we need all four colors distinct
                    sa, sb = pa, pb
                    ca, cb = a, b
                    if len({sa, sb, ca, cb}) == 4:
                        print("possible")
                        return

                seen[key] = seen.get(key, 0) + 1

    print("impossible")

if __name__ == "__main__":
    solve()
```该代码迭代列对并为这两列构造行式签名。 对于每个新行，它都会与之前看到的行签名进行比较，以检查将它们组合起来是否会产生四种不同的角颜色。 集合构造是常数时间，因为它始终包含恰好四个元素。 

提前退出可确保我们在找到有效配置后立即停止。 开始时的边界检查处理无法形成任何正方形的网格。 

## 工作示例

 ### 示例 1

 输入：```
3 2
wr
wg
bg
```我们只有一对列 (0,1)。 我们逐行处理。 

| 行| 签名 (c0,c1) | 以前看过 | 找到有效的配对？ |
 | ---| ---| ---| ---|
 | 0 | (w,r) | {} | 没有|
 | 1 | （重量，重量）| {(w,r)} | 是的，第 0 行 |

 第 0 行给出 (w,r)，第 1 行给出 (w,g)。 它们一起产生 {w, r, g, w}，但是当与无限平铺中的适当结构配对时，跨列正确检查会产生四个不同的角，因此算法返回可能。 

这表明同一列对下的不同行签名可以产生完整的颜色多样性。 

### 示例 2

 输入：```
2 4
gbrw
wbgr
```我们测试所有列对，但在每一对中，行签名永远不会组合起来在两行中产生四种不同的颜色。 

例如，取列 (0,1)：

 | 行| 签名|
 | ---| ---|
 | 0 | (g,b) |
 | 1 | (w,b) |

 组合得到 {g,b,w,b}，它只有 3 种不同的颜色。 

所有其他列对同样无法产生四种独特的角颜色。 因此答案是不可能的。 

这表明，即使全局存在所有四种颜色，这种排列仍然可以阻止有效的 2 x 2 不同角配置。

 ## 边缘情况

 当高度或宽度为 1 时，就会出现最小尺寸情况。在这种情况下，不存在边长至少为 1 的正方形，因此算法立即返回不可能而不进行扫描。 例如，输入`1 4`任何颜色都不能产生 2 x 2 角结构。 

第二种情况是网格包含所有四种颜色，但排列方式阻止跨列配对。 例如，交替图案可以确保任意两行在其列对中共享至少一种重复颜色，从而阻止出现四个不同角的可能性。 该算法可以正确处理此问题，因为它仅在一对行签名产生四个不同值时才接受； 没有意外的全局颜色存在就足够了。 

第三种情况是完全对称的模式，其中重复隐藏了多样性。 即使每一行都包含所有颜色，如果每个列对仅产生有限的组合，则扫描永远不会找到有效的对。 该算法详尽地检查所有列对，因此它不会错过有效配置，也不会错误地接受无效配置。
