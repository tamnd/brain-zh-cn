 ## 解决方案
 ## 问题理解

 我们给定一个整数数组，并希望减少其总和，直到它不大于目标值。 唯一允许的操作是将单个元素减少一个单位，或者将一个元素的值复制到另一个位置。 

关键的困难在于，复制并不是一个无成本的操作，尽管它不会直接减少总和。 它可以战略性地用于创造额外的减少“机会”，因为它会覆盖价值。 由于允许值变为负数，因此没有什么可以阻止我们重复减少元素或在数组中传播非常小的值。 

目标是最小化操作数量，而不是最终配置。 

这些约束立即排除了任何二次或三次模拟。 所有测试用例的元素总数最多为 2⋅10^5，因此每个测试用例的任何解决方案都必须接近 O(n log n) 或 O(n)。 尝试所有复制和递减操作序列的天真的想法是不可能的，因为分支因子随着操作和位置的增加而增长。 

一个微妙的边缘情况来自复制和减少之间的相互作用。 一种只执行递减的粗心贪婪策略忽略了将小值复制到大值可以“免费”减少总和（覆盖成本除外）。 例如，通过复制将大元素转换为小值可能比多次递减它更好，但前提是我们已经有一个可用的小值。 

另一种边缘情况是所有元素的总和都已低于 k。 在这种情况下，就需要零操作，任何“进一步优化”的尝试都不能意外地引入不必要的操作。 

## 方法

 从最直接的想法开始。 如果不允许复制，问题就会很简单：答案将是总和减去 k，因为每次减量都会使总和恰好减少一个单位，并且没有其他方法可以减少它。 

一旦引入复制，我们就获得了第二种机制：我们可以将任何元素转换为另一个元素的值。 重要的观察是，如果我们用大值替换大值，复制不会改变总和，但如果我们用小值覆盖大值，则复制会减少总和。 这表明最好的策略是首先决定我们想要传播的最终“小值”，然后使用副本将许多元素转换为该值，最后在需要时执行递减。 

关键的见解是考虑排序后的数组。 如果我们固定一个值作为“最小成本的来源”，假设我们选择某个元素作为基线，那么我们可以将该基线值复制到许多位置。 之后，任何仍然太大的元素都可以单独减少。 权衡变成：选择较小的基线需要更多的初始努力才能达到它，但会使复制更强大。 

看待问题的一种更系统的方法是假设我们最终会将某些后缀中的最小元素用作模板。 如果我们按降序对数组进行排序，则考虑将前 i 个元素“保持大”，并将所有剩余元素转换为第 i 个值。 这减少了不同值的数量，从而减少了我们需要通过递减来修复的总和结构。 

对于我们将多少个元素视为“特殊”的固定选择，我们可以计算需要多少次操作：在通过复制操作将许多元素设置为相等后，我们为减少超额总和付费，并且我们还为复制操作本身付费。 

关键的减少是，最佳策略仅取决于我们保留多少最大元素，因为其他所有内容都可以被迫匹配选定的值。

这将问题转变为检查保留元素的所有可能计数。 由于 n 很大，我们可以通过在排序数组上使用前缀和来避免从头开始重新计算和。

 | ---| ---| ---| ---|
 | 暴力破解（模拟操作）| O(指数运算) | O(n) | 太慢了 |
 | 最优（排序+前缀评估）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将数组按降序排序。 这使我们能够推断出保留大元素而不是转换较小元素。 
2. 计算前缀和，以便我们可以快速计算任何前缀和后缀的总和。 
3. 尝试每个可能的分割点 i，其中前 i 个元素被视为“初始保持不变”，其余 n − i 个元素是通过复制覆盖的候选者。 
4. 对于固定的 i，将该策略解释为选择前 i 个元素之一作为模板值。 最好的模板是其中最小的，因为复制较小的值可以最大限度地减少未来的缩减成本。 
5. 使用复制操作计算使后缀中的所有元素等于所选模板值后的总和是多少。 
6. 如果所得总和已经 ≤ k，则成本就是所需的复制操作数，即 n − i。 
7. 否则，我们必须使用减量运算额外减少多余的总和。 每次减量都会使总和减一，因此我们将 (current_sum − k) 添加到成本中。 
8. 取所有 i 中的最小值。 

### 为什么它有效

 该过程将数组划分为定义基线值的部分和使用复制操作强制匹配该基线的部分。 任何最佳解决方案都必须有效地决定哪些值可以保持“昂贵”，哪些值需要提前降低。 由于复制总是完全覆盖，因此不存在部分匹配策略，因此每个元素要么用作模板，要么被替换。 一旦这个二进制结构被固定，剩余的成本就与保持在 k 以上的总和的数量呈纯线性关系，并且递减是进一步减少它的唯一方法。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + a[i]
        
        total = prefix[n]
        ans = float('inf')
        
        for i in range(n + 1):
            if i == 0:
                # no templates chosen, everything becomes a[0]
                cost = total - k if total > k else 0
                ans = min(ans, cost)
                continue
            
            # choose first i elements as potential templates
            # best template is a[i-1]
            template = a[i - 1]
            
            # suffix becomes template
            suffix_sum = prefix[n] - prefix[i]
            new_sum = prefix[i] + template * (n - i)
            
            ops = (n - i)  # copy operations
            
            if new_sum > k:
                ops += new_sum - k
            
            ans = min(ans, ops)
        
        print(ans)

if __name__ == "__main__":
    solve()
```代码首先对每个测试用例进行排序，以便根据前缀决定哪些元素保持较大。 前缀和数组允许对保留和替换的段进行恒定时间计算。 

对于每个分割点 i，该算法假设从 i 开始的元素都被值 a[i−1] 覆盖。 复制操作的次数恰好是被覆盖元素的数量。 

如果经过此转换后总和仍然超过 k，则减少总和的唯一方法是递减元素，这会为每单位超出的总和花费一次操作。 这直接添加到操作计数中。 

最后，打印所有配置的最小值。 

一个微妙的点是处理 i = 0 的情况，其中没有选择模板。 这对应于退化策略，其中我们根本不使用复制，仅依赖于原始总和的递减。

 ## 边缘情况

 关键的边缘情况是总和已在限制范围内。 该算法仍然评估所有分割，但最小值自然变为零，因为在 i = n 时，不进行复制，也不需要递减。 

另一个重要的情况是复制永远不会带来好处。 例如，如果 k 非常小并且所有元素都很大，则将大值复制到其他位置无助于减少总和。 该算法处理此问题是因为递减成本占主导地位，并且所有拆分都会产生与直接缩减相似或更差的结果。 

最后，当一个元素明显小于所有其他元素时，它就成为最佳模板。 在这种情况下，该元素之前的拆分会产生最小的成本，因为它最大限度地减少了复制操作和最终的超额总和。
