 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列，放置在位置 1 到 n 上。 我们可以使用非常具体的移动来重新排列它：我们只能交换索引恰好相差 k 的元素。 这意味着仓位形成了一个受限的交换系统，您只能与相距 k 的仓位进行交互。 

最重要的是，在进行任何这些受限交换之前，我们最多可以在任意两个头寸之间执行一次任意交换。 在可选的交换之后，我们想知道是否可以将排列完全排序到恒等排列中，其中仅使用允许的距离 k 交换，值 i 最终位于位置 i 处。 

输出不是最终的排列，而是可行性的分类。 如果在受限交换规则下排列已经可排序，我们将打印 0。 如果只有在使用一次任意交换后才变得可排序，我们会打印 1，如果没有它就不可能排序。 如果即使一次任意交换也无法使其可排序，我们就会打印 -1。 

约束结构意味着 n 可以很大，在测试用例中总共可达约 2×10^5。 这立即排除了任何模拟交换或每个查询执行重复图形遍历的方法。 我们需要每个测试用例更接近线性时间，最好是 O(n)，因为像 O(n log n) 或更糟糕的每个测试用例重复的任何事情仍然会通过，但 O(n^2) 显然是不可能的。 

关键的隐藏结构是允许的交换不会将所有索引连接在一起。 相反，他们将头寸划分为独立的链。 

打破朴素推理的常见边缘情况是 k 大或等于 1 时。 

当 k = 1 时，允许每个相邻交换，因此排列始终是可排序的，不受限制。 如果一个仍检查模块化约束的幼稚实现忘记了连接已满，则可能会错误地拒绝有效的情况。 

当 k 不为 1 时，例如 n = 6、k = 3，位置会分成 (1,4)、(2,5)、(3,6) 等链。 如果应该在位置 1 处结束的值在不同的链中开始，例如位置 2 或 3，则它永远无法到达位置 1，并且任何允许的交换序列都无法修复该问题。 

当这些链中恰好有一个或两个元素“放错位置”时，就会出现微妙的失败情况。 贪婪的直觉可能表明多次交换可以解决这种情况，但我们最多只能进行一次免费交换，因此我们必须推断有多少组件不一致。 

## 方法

 蛮力视图是显式模拟交换图。 我们在索引上构建一个图，其中边连接 i 和 i + k（有效时），然后尝试查看是否可以使用沿边的交换将每个值从其起始位置路由到其目标位置。 由于每个连接的组件都是独立的，因此我们实际上需要模拟每个组件内部是否可以达到排列。 

直接模拟会沿着路径重复交换元素直到排序，但在最坏的情况下这可能会降级为 O(n^2) 行为，因为每个值可能多次遍历长链。 即使每个元素使用 BFS 也是不必要的开销，因为结构是静态的。 

关键的观察是交换保留了图的连接组件。 如果两个位置不在同一组件中，则任何允许的交换序列都不能交换其内容。 因此每个值都被限制在其起始位置的组成部分内。 

这将问题简化为标签约束：每个值 i 必须从属于与 i 本身相同的组件的位置开始。 如果这对于所有 i 来说都成立，则可以以 0 成本对排列进行排序。

唯一的灵活性来自可选的单个任意交换，它可以在组件之间精确移动两个值。 这意味着它最多可以修复两个组件违规。 如果两个以上的值位于错误的组件中，则一次交换无法全部修复它们。 如果恰好有两个错误，我们可以检查交换它们是否使两个同时落在正确的组件中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 掉期的图形模拟 | O(n²) | O(n) | 太慢了|
 | 组件+不匹配分析| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先计算每个值当前所在的位置。 我们构建一个数组 pos，使得 pos[x] 是值 x 出现的索引。 

接下来我们确定 k 施加的结构约束。 每个索引 i 都属于完全由 i mod k 确定的分量，因为重复 ±k 移动永远不会改变剩余类别。 所以组件成员资格是 i mod k。 

然后我们根据其所需的位置 i 检查每个值 i。 对于每个值，我们将 pos[i] mod k 与 i mod k 进行比较。 

我们按如下方式进行：

 1. 构建 pos 数组映射值到其当前索引。 这让我们可以在 O(1) 中查询位置。 
2. 对于从 1 到 n 的每个值 i，通过检查 pos[i] % k 是否等于 i % k 来计算其不匹配条件。 如果匹配，则该值已经位于其目的地的可到达组件中。 
3. 将不满足此条件的所有值收集到坏列表中。 
4. 如果 bad 为空，则排列已经可排序，因此输出 0。 
5. 如果 bad 的元素超过 2 个，则输出 -1，因为一次交换只能影响两个值，并且无法修复两个以上的组件违规。 
6. 如果 bad 恰好有 2 个元素，例如 a 和 b，请在概念上模拟交换它们。 交换后，a 将被放置在 pos[b] 处，b 将被放置在 pos[a] 处。 我们检查这是否同时修复了两个约束，即 pos[b] % k == a % k 和 pos[a] % k == b % k。 
7. 如果该条件成立，则输出 1，否则输出 -1。 

正确性取决于交换仅影响两个值，并且组件成员资格在允许的交换下保持不变。 

### 为什么它有效

 允许的操作定义了一个图，其连接组件是模 k 的固定残差类。 在每个组件内，交换允许任意排列，因此可达性仅取决于每个值是否在与其目标位置相同的组件中开始。 这个条件既是必要的，也是充分的。 

可选的交换是在组件之间移动值的唯一方法。 由于它只影响两个值，因此它最多可以纠正两个不匹配。 任何受约束的交换序列都不能更改组件成员资格，因此检查简化为验证一组不匹配的值是否可以以每个值同时移入其正确残基类的方式进行配对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p, start=1):
            pos[v] = i

        bad = []
        for v in range(1, n + 1):
            if (pos[v] - 1) % k != (v - 1) % k:
                bad.append(v)

        if not bad:
            print(0)
            continue

        if len(bad) != 2:
            print(-1)
            continue

        a, b = bad[0], bad[1]
        if ((pos[a] - 1) % k == (b - 1) % k and
            (pos[b] - 1) % k == (a - 1) % k):
            print(1)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先构建逆排列，以便我们可以根据价值头寸进行推理，而不是直接跟踪掉期。 模运算使用 (i - 1)，因为问题自然是 1 索引的，但 0 索引形式的组件结构更清晰。 

关键的实现细节是我们从不模拟交换。 我们只对残差类别进行推理。 这可以避免性能问题和不正确的交换顺序带来的细微错误。

 ## 边缘情况

 当 k = 1 时，每个索引都属于其自己的组件，这意味着实际上不可能进行交换。 该算法处理这个问题是因为每个值 i 必须已经满足 pos[i] = i。 如果不是，则 bad 会变大，并且我们会正确返回 -1，除非已经排序或通过交换进行了简单修复，但交换也没有帮助，因为组件是单例的。 

当k很大时，例如k≥n/2，组件变成非常小的链。 残差检查仍然正确捕获可达性，因为每个链保持隔离，并且不匹配检测降低到局部一致性。 

仅有一个不匹配的情况无法通过一次交换来修复，因为交换需要两个端点。 算法自然会拒绝它，因为错误的大小是 1，我们立即输出 -1。 

具有两个以上不匹配的案例也会被提前拒绝。 这避免了对部分修复进行更深入推理的需要，因为一次交换无法跨组件修复两个以上的值。
