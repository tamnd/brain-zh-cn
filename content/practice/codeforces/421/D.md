 ## 解决方案
 ## 问题理解

 我们有一个编码员网络，每个编码员在会议期间提出一个主张：他们指向另外两名编码员并断言罪魁祸首是这两个人之一。 然后我们必须选择两名编码员作为嫌疑人。 

如果我们选择的两个人中至少有一个出现在他们提到的对中，则编码器“支持”我们选择的对。 换句话说，每当我们选择的候选对与他们声明的嫌疑人对相交时，每个编码器都会向候选嫌疑人对投出同意票。 

任务是计算我们可以选择多少个无序编码器对，使得至少`p`程序员同意这个选择。 

限制很大：多达 300,000 名编码员。 对所有对进行二次枚举是不可能的，因为在最坏的情况下需要大约 4.5 × 10^10 检查，这远远超出了 1 秒的限制。 这迫使我们寻求一种解决方案，将配对评估减少到更接近线性或近线性时间。 

一个微妙的点是，从“计算边缘”的意义上来说，一致性并不是对称的。 如果任一端点匹配，编码器就会做出贡献，因此一对端点的贡献是基于重叠，而不是完全匹配。 仅计算精确匹配或将问题视为简单的配对频率的简单方法会错误计数。 

当多个编码员选择同一对时，会出现常见的失败情况。 例如，如果许多编码员报告`(1, 2)`，那么这对`(1, 2)`得到额外的修正，超出了单独计算的程度所建议的范围。 忽略这一点会导致有效对的计数过多。 

## 方法

 暴力解决方案尝试每一个无序对`(u, v)`并扫描所有编码器以计算他们选择的对中有多少相交`{u, v}`。 每次检查都是恒定时间，因此在最坏情况推理中总复杂度为 O(n3)，或者至少 O(n2) 对乘以 O(n) 扫描，这是完全不可行的。 

We need a way to compute the agreement score for a pair without scanning all coders. 关键的观察是，编码员的贡献仅取决于是否`u`或者`v`出现在他们的配对中`(x_i, y_i)`。 这可以用度数重写。 

如果我们定义`deg[x]`作为编码器的数量，其对包括`x`，那么对于候选对`(u, v)`总的朴素贡献是`deg[u] + deg[v]`。 然而，准确选择的程序员`(u, v)`在该总额中被计算两次，而他们只应贡献一次。 通过减去其对恰好是的编码器的数量来修复此过量计数。`(u, v)`，我们称之为`cnt[u][v]`。 

所以真实分数就变成了：`score(u, v) = deg[u] + deg[v] - cnt[u][v]`。 

这个公式很强大，因为`deg`可以在 O(n) 中预先计算，并且所有`(u, v)`实际出现在输入中的对可以存储在哈希映射中，以进行 O(1) 校正查找。 

剩下的挑战是计算有多少对满足`score(u, v) ≥ p`遍历所有 O(n²) 种可能性，无需枚举它们。 我们把问题分开。 首先，忽略更正并计算所有对`deg[u] + deg[v] ≥ p`。 由于度数仅取决于顶点，因此我们可以按度数对顶点进行排序，并使用两个指针扫描来计算 O(n) 中的有效对。 

这会导致计数过高，因为某些通过程度阈值的对在减去后可能会失败`cnt[u][v]`。 这些有问题的情况仅发生在输入中实际出现的对中，因为只有那些对具有非零校正。 因此，我们再次迭代输入对并减去这些对，其中：`deg[u] + deg[v] ≥ p`但`deg[u] + deg[v] - cnt[u][v] < p`。 

这将校正阶段减少到 O(n)，由于排序而使整个解决方案保持线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²·n) | O(n²·n) | O(n) | 太慢了 |
 | 度数+校正分解| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算`deg[i]`对于每个编码器索引`i`通过扫描所有输入对一次。 这捕获了每个节点在所有语句中被提及的次数。 
2. 构建频率图`cnt`超过对`(x_i, y_i)`, 治疗`(a, b)`和`(b, a)`通过始终存储排序的端点来作为相同的键。 这允许快速查找有多少编码器准确地选择了给定的对。 
3. 创建所有节点的数组，按其度值排序。 这种排序将让我们计算有多少对具有足够大的度数和，而无需显式检查每对。 
4. 数一下有多少对`(u, v)`满足`deg[u] + deg[v] ≥ p`使用两指针扫描。 这个想法是，随着一个端点度数的增加，另一端点所需的最小度数单调减少。 
5. 迭代每个输入对`(u, v)`并使用计算其准确分数`deg[u] + deg[v] - cnt[u][v]`。 
6. 如果这对之前在仅学位步骤中被视为有效，但其校正分数低于`p`，从答案中减去它。 这仅删除由于计数过多而错误包含的对。 

### 为什么它有效

 每对对协议的贡献都清晰地分为两部分：来自端点的独立贡献和仅依赖于相同对碰撞的修正。 基于度的计数正确地解释了全局所有基于端点的贡献，而校正项仅影响输入中明确存在的对。 由于没有其他对可以进行非零校正，因此从基于度数的集合中删除无效的对会产生准确的最终计数，而不会丢失或重复计算任何有效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, p = map(int, input().split())

pairs = []
deg = [0] * (n + 1)
cnt = {}

for _ in range(n):
    x, y = map(int, input().split())
    pairs.append((x, y))
    deg[x] += 1
    deg[y] += 1
    if x > y:
        x, y = y, x
    cnt[(x, y)] = cnt.get((x, y), 0) + 1

nodes = list(range(1, n + 1))
nodes.sort(key=lambda x: deg[x])

ans = 0
j = n - 1

for i in range(n):
    while j >= 0 and deg[nodes[i]] + deg[nodes[j]] >= p:
        j -= 1
    ans += (n - 1 - j)

for x, y in pairs:
    u, v = (x, y) if x < y else (y, x)
    s = deg[x] + deg[y]
    c = cnt[(u, v)]
    if s >= p and s - c < p:
        ans -= 1

print(ans)
```该代码首先将所有编码器意见压缩为度数和配对频率。 排序步骤启用两指针扫描，仅根据度数来计算有多少对满足松弛条件。 第二个循环通过仅检查冲突重要的输入定义对来修复过度计数。 

一个微妙的实现细节正在维护`j`扫描时单调`i`。 这依赖于这样一个事实：增加`i`移动到更小的角度，因此阈值条件只会变得更困难，允许重用指针而不是重置它。

 输入：```
4 2

```我们计算度数：

 节点1出现3次，节点2出现2次，节点3出现1次，节点4出现2次。 

我们还存储配对频率：`(2,3)=1`,`(1,4)=2`,`(1,2)=1`。 

| 步骤| 行动| 结果 |
 | --- | --- | --- |
 | 1 | 构建度| [-, 3, 2, 1, 2] |
 | 2 | 计数有效度对 | 度数总和 ≥ 2 的对 |
 | 3 | 初步回答 | 6 |
 | 4 | 修正检查`(1,4)`| deg sum = 5，cnt = 2，score = 3 ≥ 2 无变化 |
 | 5 | 修正检查`(1,2)`| deg sum = 5，cnt = 1，score = 4 ≥ 2 无变化 |

 最终答案仍然是6。 

该轨迹表明，大多数对在度数限制下已经有效，并且更正不会使它们失效。

 ## 边缘情况

 当所有编码器命名同一对时，就会出现一种边缘情况。 在这种情况下，两个节点的度都变得非常大，并且基于度的计数严重高估。 然而，`cnt[u][v]`exactly matches the overcount, and the correction step removes precisely the invalid extra inclusion so that only the true contribution remains.

 另一种情况是当`p = 0`。 无论编码员的意见如何，每一对都是有效的。 基于度数的计数仍然可以正确计算值，但即使修正处理不当，也不需要排除任何对，因为阈值是空洞地满足的。 

当所有对都不同时，就会出现最终的边缘情况。 然后`cnt[u][v]`对于现有对始终为 1，否则为 0，这意味着修正只会稍微调整分数。 该算法仍然有效，因为校正仅涉及现有边缘，而不会影响大部分 O(n²) 非边缘对。
