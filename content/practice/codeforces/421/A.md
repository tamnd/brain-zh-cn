 ## 解决方案
 ## 问题理解

 我们得到一排苹果，编号从 1 到 n。 每个苹果都可以送给两只仓鼠中的一只，亚瑟或亚历山大。 唯一的限制是亚瑟必须只收到他喜欢的苹果，而亚历山大必须只收到他喜欢的苹果。 有些苹果可能是两只仓鼠都喜欢的，这些苹果可以送给任何一只仓鼠，但仍然只有其中一只。 

我们的任务是将每个苹果分配给一只仓鼠，同时尊重两个偏好列表。 输入给出 n，然后是 Arthur 喜欢的索引列表，以及 Alexander 喜欢的索引列表。 我们必须输出一个长度为 n 的由 1 和 2 组成的字符串，表示所有权。 

约束很小：n 最多为 100。这立即告诉我们，即使是 O(n²) 或暴力分配策略也很容易足够快。 不需要高级的数据结构或优化技巧。 问题的根本在于如何一致地解决重叠问题。 

一个关键的微妙之处是苹果不属于这两个列表。 该声明保证存在解决方案，但天真的实现可能会忽略这些情况或无法确定地分配它们。 

第二个微妙的情况是偏好之间的重叠。 如果两只仓鼠都喜欢一个苹果，任意分配它仍然有效，但如果我们不小心尝试“平衡”或“优化”，我们可能会意外地留下一些未分配的苹果。 

## 方法

 蛮力的观点是尝试将 n 个苹果分配给两只仓鼠的所有可能分配并检查有效性。 每个苹果有 2 个选择，因此有 2^n 次分配。 对于每项作业，我们都会验证不会给不喜欢苹果的仓鼠提供苹果。 验证成本为 O(n)，因此总工作量为 O(n·2^n)，即使 n = 100 也没有必要。 

问题的结构使得暴力破解变得过分，因为除了个体兼容性之外，不存在全局约束交互。 每个苹果都是独立的。 这意味着我们根本不需要搜索； 我们只需要为每个苹果进行本地分配。 

关键的观察结果是，每个苹果都属于三类之一：仅亚瑟喜欢，仅亚历山大喜欢，或者两者都喜欢（或者可能都不喜欢）。 由于该声明保证了解决方案的存在，因此双方都不喜欢的苹果一定不会以有问题的方式存在，或者可以在不破坏有效性的情况下任意分配它们。 所以每个位置都可以独立决定。 

这将问题简化为简单的扫描：对于每个苹果，将其分配给任何喜欢它的仓鼠。 如果双方都喜欢，可以一致选择，也可以任意选择。

 | --- | --- | --- | --- |
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了 |
 | 贪心赋值| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取n、a、b 和两个偏好列表。 

我们将把偏好列表转换成快速查找结构，这样我们就可以在恒定的时间内测试成员资格。 
2. 构建两个布尔数组或集合：一个用于 Arthur 喜欢的苹果，一个用于 Alexander 喜欢的苹果。 

这确保了每个苹果的 O(1) 成员资格检查。 
3. 初始化一个长度为n的答案数组。 
4. 迭代从 1 到 n 的所有苹果。 

对于每个苹果，仅根据喜好决定其所有者。 
5. 如果这个苹果是 Arthur 喜欢的并且不一定受到限制，则将其分配给 Arthur（输出 1）。 

这种选择在重叠情况下是任意的，但一致且安全。 
6. 否则，将其分配给 Alexander（输出 2）。 

由于输入保证了可行性，因此每个苹果必须至少被一只仓鼠喜欢，所以这个后备总是有效的。 
7. 打印结果作业。 

### 为什么它有效

正确性来自于决策的独立性。 每个苹果都不依赖于任何其他苹果。 唯一的限制是局部有效性：分配给亚瑟的苹果必须在亚瑟的集合中，对于亚历山大也是如此。 因为我们只将苹果分配给喜欢它们的仓鼠，所以每个约束都得到满足。 重叠不会产生冲突，因为我们永远不会将苹果分配给不喜欢它的仓鼠。 由于每个苹果只被处理一次并立即分配，因此不存在以后矛盾的可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, a, b = map(int, input().split())

arthur = set(map(int, input().split()))
alex = set(map(int, input().split()))

res = []

for i in range(1, n + 1):
    if i in arthur:
        res.append("1")
    else:
        res.append("2")

print(" ".join(res))
```### 实施说明

 我们使用集合进行成员资格检查，因为它们提供平均 O(1) 查找，这使解决方案保持线性。 

决策规则尽可能优先考虑 Arthur。 这是任意的； 只要我们尊重成员资格限制，首先选择亚历山大也是可行的。 

我们按照语句格式的要求打印空格分隔的字符。
