 ## 解决方案

 ## 问题理解

 我们得到了一系列按时间顺序排列的视频持续时间。 任务是将这个序列准确地分割成`k`连续的组，其中每个组代表一个帖子，并且每个视频必须完全属于一个组。 

关键约束不仅在于分区本身，还在于每个组必须具有相同的持续时间总和。 换句话说，如果我们计算每个段内的持续时间总和，所有`k`段总和必须相同。 

输出不是段本身，而是这些段的长度（按顺序排列）。 如果我们表示为`s_j`中的视频数量`j`在第一篇文章中，我们必须输出一个正整数序列，将数组划分为连续的块。 

约束条件`n ≤ 100000`排除尝试所有分区的任何方法。 即使是对分割位置的天真回溯也会呈指数增长，因为有`n-1`潜在的削减位置和选择`k-1`其中导致组合爆炸。 同样，重复重新计算段和甚至会使二次解超出范围。 

当所有视频时长的总和不能被整除时，就会出现一个微妙的问题`k`。 在这种情况下，根本不存在平等的划分。 当有效的段边界存在但由于重复的值而不是立即明显时，就会出现第二种边缘情况。 例如，像这样的数组`1 1 1 1 1`和`k = 2`允许多个有效的分割，但问题保证答案的唯一性（如果存在），这意味着一旦找到有效的贪婪边界，它就会被强制。 

## 方法

 蛮力策略会尝试选择`k-1`之间削减职位`n-1`间隙，并为每个候选分区计算段总和并验证相等性。 即使使用前缀和优化求和计算，每次检查仍然需要花费`O(k)`，分区数为`C(n-1, k-1)`，即使对于中等投入，它也会变得天文数字般大。 这使得暴力破解完全不可行。 

关键的观察是我们不能自由选择分段：一旦我们知道总和，分段总和就固定了。 如果总和`S`可以整除`k`，那么每个段的总和必须为`S / k`。 这将问题从“尝试所有分区”转变为“找到达到精确目标总和的边界”。 

一旦知道目标总和，我们就可以从左到右扫描数组，累积值。 每当运行总和恰好达到目标时，我们就切割一段。 如果超过目标，则尝试无效。 这种贪婪扫描之所以有效，是因为所有数字都是正数，因此部分总和会严格增加，并且以后无法“自行修复”。 

因此，问题的结构简化为具有运行累加器和强制切割点的线性扫描。

 ## 算法演练

 1. 计算所有视频时长的总和。 如果这个总和不能被整除`k`，立即断定不存在有效分区。 这是必要的，因为相等的段总和必须恰好等于总数。 
2. 计算所需的段和`target = total / k`。 每个帖子的总和必须等于该值。 
3. 从左到右遍历数组，同时维护当前段的运行总和。 此运行总和表示分配给当前帖子的总持续时间。 
4. 每当运行总和等于`target`，关闭当前段并记录其长度。 重置运行总和并继续构建下一个段。 这是有效的，因为我们被迫匹配精确的段总和，并且积极性确保我们永远不会在没有检测到的情况下超调。 
5. 如果在任何时候运行总和超过`target`，构建失败。 这意味着我们无法在给定的约束下形成有效的分区。 
6. 处理完所有元素后，验证是否准确`k`形成段并消耗整个数组。 如果是，则输出线段长度； 否则输出“否”。 

### 为什么它有效

 正确性取决于每个完成的段的总和完全等于的不变量`target`，并且运行总和永远不会超过`target`。 由于所有元素都是严格正数，一旦运行总和达到`target`，任何进一步的添加都会违反约束，因此剪切必须发生在该点。 只要存在解决方案，这就会强制每个段边界都是唯一的，从而与问题的唯一性保证相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

total = sum(a)

if total % k != 0:
    print("No")
    sys.exit()

target = total // k

res = []
curr = 0
length = 0

for x in a:
    curr += x
    length += 1

    if curr == target:
        res.append(length)
        curr = 0
        length = 0
    elif curr > target:
        print("No")
        sys.exit()

if len(res) == k:
    print("Yes")
    print(*res)
else:
    print("No")
```实施首先是强制执行可分割性条件，这是可行性的硬性先决条件。 然后扫描同时累加当前段的总和和长度，确保我们可以直接输出段大小而无需额外的簿记。 

关键的实现细节是立即终止`curr > target`。 如果没有此检查，无效分区可能会默默地继续并产生不正确的段计数。 另一个微妙之处是重置两者`curr`和`length`恰好在一个段关闭时，因为未能重置长度会扭曲输出结构。

 ## 边缘情况

 当总和不能被整除时，就会出现第一种边缘情况`k`。 用于输入`n = 3, k = 2, a = [1, 2, 3]`，总数为 6，因此目标为 3。扫描生成段`[1,2]`和`[3]`，两者总和正确，表明仅整除性是不够的，但它是必要的。 

第二种情况涉及早期超调。 用于输入`n = 4, k = 2, a = [5,1,1,1]`，目标为 4。第一个元素已经超过目标，因此算法立即终止。 由于积极性，任何推迟削减的尝试都只会进一步增加总金额，从而证实了不可能。 

第三种情况是最大碎片，比如`n = 5, k = 5, a = [1,1,1,1,1]`。 每个元素单独匹配目标，产生五个长度为 1 的片段。 该算法在每个元素之后自然重置，即使在极端的分区密度下也证明了正确性。
