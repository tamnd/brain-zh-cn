 ## 解决方案
 ## 问题理解

 游戏围绕两根弦展开。 克莱尔有一个较长的字符串，鲍勃选择另一个字符串作为目标单词。 鲍勃选择的字符串可能包含错误，因此任务是通过从克莱尔的字符串中删除一些字符，同时保持剩余字符的顺序，检查仍然可以形成多少种不同的方式。 

形成目标字符串的一种方法是子序列匹配。 例如，从`eeettt`, 字符串`et`可以通过选择三个中的任何一个来形成`e`字符和三个中的任何一个`t`它后面的字符，给出九个可能的匹配。 所需的输出是此类选择的总数模 (10^9+7)。 

第一个字符串的长度可达 5000，而目标字符串的长度可达 1000。对于最大输入，二次解通常约为 2500 万次运算，这在 Python 中很合适。 尝试每个可能的位置子集的解决方案需要检查最多 (2^{5000}) 个选择，这是不可能的。 这些约束表明目标字符串的位置必须通过动态编程而不是显式枚举来处理。 

有几个细节可以打破简单的实现。 如果目标字符串比原始字符串长，则不能存在子序列。 对于输入：```
abc
abcd
```正确答案是`0`。 仅计算匹配字符而不考虑顺序和长度的方法可能会错误地产生正值。 

重复的字符会造成另一个常见错误。 为了：```
ee
e
```答案是`2`，因为要么`e`可以选择第一个字符串。 仅计算不同的结果字符串将错误地返回`1`。 

字符的顺序也很重要。 为了：```
abc
ba
```答案是`0`，因为虽然两个字符都出现了，`b`出现在`a`位于源字符串中，并且不能在其之前选择。 仅基于字符频率的方法在这里会失败。 

## 方法

 直接的方法是为 Bob 字符串中的每个字符选择 Clair 字符串中的位置。 对于每个可能的位置选择，我们验证所选字符是否按顺序与目标字符串匹配。 这是正确的，因为每个有效子序列恰好对应于一组选定的位置。 

问题在于选择的数量。 如果 Clair 的字符串长度为 5000，则可能的子序列数为 (2^{5000})。 即使生成其中的一小部分也远远超出了时间限制，因此不能使用蛮力的想法。 

有用的观察是每个部分匹配都具有相同的结构。 当从左到右扫描 Clair 的字符串时，我们只需要知道 Bob 的字符串的每个前缀已经形成了多少种方式。 未来仅取决于这些计数，而不取决于之前使用的确切位置。 

假设我们已经处理了 Clair 字符串的一些前缀。 让`dp[j]`代表创建第一个的方法数`j`来自已处理前缀的 Bob 字符串的字符。 当从 Clair 读取新字符时，它可以扩展每个已存在的匹配项，其下一个所需字符相同。 它还可以开始匹配 Bob 字符串的第一个字符。 

这将指数搜索变成了动态规划过程。 Clair 中的每个字符都会更新 Bob 字符串中所有可能的前缀长度一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳| O(纳米) | O(米) | 已接受 |

 这里，`n`是克莱尔弦的长度，`m`是鲍勃的绳子的长度。 

## 算法演练

 1. 创建一个动态规划数组，其中`dp[j]`存储形成第一个的方法数`j`Bob 的字符串中的字符使用 Clair 的字符串中到目前为止已处理的部分。 最初，`dp[0] = 1`因为形成空字符串的方法只有一种：什么都不选择。 
2. 逐个字符扫描 Clair 的字符串。 对于当前字符，从末尾到开头检查 Bob 的字符串位置。 
3. 如果Clair当前的角色与`j`Bob的第-个字符，添加`dp[j-1]`进入`dp[j]`。 这表示将当前字符作为新形成的子序列的最终字符。 反向是必要的，因为当前字符在当前更新中只能使用一次。 
4. 处理完克莱尔的所有字符后，`dp[m]`包含形成 Bob 整个字符串的完整方法的数量。 输出该值模 (10^9+7)。 

为什么它有效：不变量是在处理完 Clair 字符串的任何前缀后，`dp[j]`正是形成第一个的方法的数量`j`Bob 的字符串中来自该前缀的字符。 当考虑新字符时，每个现有子序列要么忽略它，要么使用它作为下一个匹配字符。 向后更新对第二种情况进行计数，同时将第一种情况保留在现有值中。 由于每个有效的子序列都有一个唯一的最后选择的字符，因此每种可能性都只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    s = input().strip()
    t = input().strip()

    m = len(t)
    dp = [0] * (m + 1)
    dp[0] = 1

    for ch in s:
        for j in range(m, 0, -1):
            if ch == t[j - 1]:
                dp[j] += dp[j - 1]
                if dp[j] >= MOD:
                    dp[j] -= MOD

    print(dp[m])

if __name__ == "__main__":
    solve()
```数组`dp`表示 Bob 字符串的所有前缀长度。 它的大小只是目标字符串的长度，因为克莱尔字符串的处理部分不需要存储。 

外循环按照与构建子序列相同的顺序处理 Clair 的字符串。 内部循环向后遍历 Bob 的字符串，以便 Clair 中的字符出现一次，在此步骤中仅贡献一次。 如果循环继续进行，则可以立即重用更新后的值，并且同一字符可能会错误地填充 Bob 字符串中的多个位置。 

由于子序列的数量增长非常快，因此每次加法后都会应用模运算。 Python 整数不会溢出，但保持值减少可以避免不必要的增长并匹配所需的输出。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(纳米) | Clair 字符串的每个字符都会更新 Bob 字符串的每个可能的前缀长度一次。 |
 | 空间| O(米) | 仅存储 Bob 前缀的计数。 |

 和`n = 5000`和`m = 1000`，该算法执行大约五百万次状态更新，这完全符合限制。 

## 测试用例```python
import sys
import io

MOD = 10 ** 9 + 7

def solve():
    s = input().strip()
    t = input().strip()

    dp = [0] * (len(t) + 1)
    dp[0] = 1

    for ch in s:
        for j in range(len(t), 0, -1):
            if ch == t[j - 1]:
                dp[j] = (dp[j] + dp[j - 1]) % MOD

    print(dp[-1])

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

assert run("eeettt\net\n") == "9\n", "sample 1"
assert run("eeettt\nte\n") == "0\n", "sample 2"

assert run("a\na\n") == "1\n", "single matching character"
assert run("abc\nabcd\n") == "0\n", "target longer than source"
assert run("aaaa\naa\n") == "6\n", "all equal characters"
assert run("abab\nab\n") == "4\n", "multiple ordered matches"
```| 测试输入| 预期产出 | 它验证了什么 |

 ## 边缘情况

 对于目标比源长的情况：```
abc
abcd
```该算法创建一个长度为 5 的动态编程数组。 在扫描过程中，只有前三个目标位置可以接收贡献，因为第四个目标字符永远不会有匹配的源字符。 最终值保持不变`0`，这是正确的。 

对于重复字符：```
ee
e
```初始状态是`[1, 0]`。 第一个`e`将其更改为`[1, 1]`，第二个`e`将其更改为`[1, 2]`。 最终的答案是`2`，计算两种可能的位置选择。 

订购须知：```
abc
ba
```第一个字符`a`没有帮助，因为第一个必需的目标字符是`b`。 加工后`b`，有一种方法可以形成`b`，但是当`a`已处理，它无法扩展该匹配，因为目标需要`a`后`b`。 最终的答案是`0`。 

该算法可以处理这些情况，因为状态存储目标字符串的前缀，而不仅仅是字符计数。 仅当字符出现在相对于已匹配前缀的正确位置时，该字符才起作用。
