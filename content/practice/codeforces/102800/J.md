 ## 解决方案
 ## 问题理解

 我们有一个部分填充的 3 × 3 井字棋盘。 爱丽丝使用`O`，鲍勃使用`X`，并且某些单元格可能仍然是空的。 与普通的井字游戏不同，当有人完成一行时，游戏永远不会停止。 每个空单元格最终都会被填满。 最后，我们计算每一行、每一列和两条对角线。 每行完全由`O`贡献`+1`，每行完全由`X`贡献`-1`，混合线贡献`0`。 所需的答案是假设两名球员始终发挥最佳状态的最终得分。 Alice 尝试最大化分数，而 Bob 尝试最小化分数。 

每个测试用例指定下一个轮到谁以及当前的板配置。 我们必须计算每个测试用例的最佳最终分数。 

测试用例的数量高达 40,000 个，因此即使电路板很小，每个测​​试用例的工作量也必须非常小。 从头开始对每个测试用例进行完整的极小极大搜索将重复解决相同的游戏状态数千次。 整个游戏仅包含九个单元格，因此不同棋盘位置的数量是有限的。 这强烈建议预先计算每个可达状态一次，然后通过简单的查找来回答每个查询。 

有几种情况很容易产生不正确的实现。 

一条完整的线**不会**停止游戏。 例如，```
1
OOO
...
...
```爱丽丝已经有一排获胜的棋子，但两位玩家必须继续下棋，直到棋盘填满。 立即评估电路板的解决方案`+1`是不正确的，因为其他已完成的行、列或对角线可能会稍后出现。 

移动的玩家是由输入决定的，而不是通过计算棋子来决定的。 例如，```
0
...
...
...
```尽管空棋盘通常属于 Alice，但此输入明确表示 Bob 接下来要移动。 忽略转弯值会产生错误的极小极大决策。 

另一个容易犯的错误是每次移动后仅评估最新完成的行。 考虑```
1
OO.
OO.
...
```最后一步可能会同时完成一行和一列。 分数始终取决于最后的棋盘，而不是中间的事件。 

## 方法

 最直接的解决方案是递归极小极大搜索。 从当前位置开始，尝试每一个合法的动作，递归地解决剩下的游戏，让Alice选择最大值，Bob选择最小值。 当棋盘填满时，计算完成的行、列和对角线以获得最终分数。 

这个搜索是正确的，因为它明确地探索了每一个可能的延续。 问题是重复。 可以通过许多不同的移动顺序到达相同的部分填充的棋盘，从而导致相同的子树被重复地重新计算。 尽管单个游戏最多包含 9 个动作，但解决多达 40,000 个独立测试用例使得这种不必要的重复成本高昂。 

关键的观察是，游戏状态完全由棋盘配置和轮到的玩家决定。 板卡配置总数仅为$3^9 = 19,683$，因为每个单元格要么是空的，`O`， 或者`X`。 乘以两个可能的玩家得出的不同状态少于 40,000 个。 

我们不是独立地解决每个查询，而是使用记忆的极小极大值精确地解决每个状态一次。 每当递归达到先前计算的状态时，我们立即重用它的答案。 由于每个状态最多评估一次，因此总工作量受不同状态数量而不是递归路径数量的限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(b!)$， 在哪里$b$是空单元格的数量 |$O(b)$| 对于许多测试用例来说速度太慢|
 | 最佳|$O(3^9 \times 9)$预处理,$O(1)$每个查询|$O(3^9)$| 已接受 |

 ## 算法演练

 1. 将每个板表示为九个字符的字符串。 这唯一地标识了游戏状态并且可以用作记忆密钥。 
2. 编写一个函数，通过检查所有三行、所有三列和两条对角线来评估整个棋盘。 每一个都——`O`行加一，每行都-`X`行减一。 
3. 创建一个递归极小极大函数，使当前棋盘和玩家移动。 
4. 如果棋盘上没有空单元格，则返回第 2 步的评估结果。这是该已完成游戏的最终得分。 
5. 如果已经计算出该状态，则立即返回存储的答案。 这可以避免多次求解同一位置。 
6. 否则，通过将当前玩家的标记放入一个空单元格来生成每一个合法的移动。 
7. 与对方玩家递归地求解结果状态。 
8. 如果Alice移动了，保留最大返回值，因为她想要最大的最终分数。 如果鲍勃移动了，则保留最小返回值，因为他想要最小的最终得分。 
9. 在返回计算值之前将其存储在存储表中。 
10. 对于每个测试用例，将棋盘转换为所选的表示形式，读取要移动的玩家，调用记忆的 minimax 函数，并打印返回的值。 

### 为什么它有效

 每一次递归调用都代表一个合法的游戏位置。 递归探索从该位置开始的所有可能的延续。 最终评估与问题中定义的分数完全匹配，因为它仅在棋盘已满后才计算已完成的行。 由于 Alice 总是选择得分最大的延续，而 Bob 总是选择得分最小的延续，因此递归正是最优游戏的定义。 记忆化仅更改状态解决的频率，而不更改其接收的值，因此返回的值保持正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LINES = [
    (0, 1, 2),
    (3, 4, 5),
    (6, 7, 8),
    (0, 3, 6),
    (1, 4, 7),
    (2, 5, 8),
    (0, 4, 8),
    (2, 4, 6),
]

memo = {}

def score(board):
    res = 0
    for a, b, c in LINES:
        if board[a] == board[b] == board[c]:
            if board[a] == 'O':
                res += 1
            elif board[a] == 'X':
                res -= 1
    return res

def dfs(board, alice_turn):
    key = (board, alice_turn)
    if key in memo:
        return memo[key]

    if '.' not in board:
        val = score(board)
        memo[key] = val
        return val

    if alice_turn:
        best = -10
        mark = 'O'
        for i, ch in enumerate(board):
            if ch == '.':
                nxt = board[:i] + mark + board[i + 1:]
                best = max(best, dfs(nxt, False))
    else:
        best = 10
        mark = 'X'
        for i, ch in enumerate(board):
            if ch == '.':
                nxt = board[:i] + mark + board[i + 1:]
                best = min(best, dfs(nxt, True))

    memo[key] = best
    return best

t = int(input())
for _ in range(t):
    turn = int(input())
    board = "".join(input().strip() for _ in range(3))
    print(dfs(board, turn == 1))
```这`LINES`数组将每条评分线存储一次，从而避免在整个程序中重复进行索引计算。 

这`score`仅对完全填充的板调用该函数。 它检查八个可能获胜的行中的每一个，并计算爱丽丝和鲍勃完成的行之间所需的差异。 

递归`dfs`函数实现极小极大和记忆化。 记忆键包含棋盘和当前玩家，因为相同的棋盘可能根据轮到谁而具有不同的最佳值。 

仅当棋盘上没有空单元格时，递归才会终止。 这符合修改后的游戏规则，即游戏过程中完成的行不会结束游戏。 

初始值`-10`和`10`是安全的，因为分数总是在`-8`和`8`，因为板上只有八条可能的线。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(3^9 \times 9)$总预处理，$O(1)$每次查询的平均值 | 每个不同的状态都会解决一次，每个状态最多考虑九个动作 |
 | 空间|$O(3^9)$| 记忆化为每个可到达的状态存储一个值|

 由于存在的不同状态少于 40,000 个，因此整个状态空间很容易装入内存。 填充记忆后，每个测试用例都变成一个简单的哈希表查找，使 40,000 个查询轻松满足限制。

 ## 边缘情况

 考虑这样的情况：获胜线已经存在，但棋盘未满。```
1
1
OOO
...
...
```观察完成的行后，算法不会停止。 由于仍然存在空单元格，因此递归将继续，直到每个方格都被占据。 只有这样，评估函数才会计算所有已完成的行。 这完全符合修改后的游戏规则。 

现在考虑一个棋盘，其轮次与现有棋子的数量不一致。```
0
...
...
...
```记忆键包括棋盘和要移动的玩家。 搜索从 Bob 最小化结果开始，尽管这个位置在正常游戏中永远不会出现。 该算法遵循输入，而不是根据件数做出假设。 

最后，考虑一个移动同时创建多条线的位置。```
1
OO.
OO.
...
```递归搜索最终到达完全填满的棋盘，评估函数独立检查所有八个可能的行。 如果一次移动同时完成了一行和一列，则两者都会被计算在内，因为每条得分线都会被单独检查。 这可以避免在多个同时连接的情况下低估位置。
