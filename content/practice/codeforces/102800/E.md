 ## 解决方案
 ## 问题理解

 我们通过选择两个相邻的正值来重复缩短数组。 这两个值被删除并替换为`a % b`或者`b % a`，为该操作自由选择。 由于两个元素变成了一个，因此每次操作都会将数组长度恰好减少一。 

问题不在于最终值变成什么，而在于可以删除多少元素。 一旦不存在相邻的正数对，就不可能进行更多的操作。 我们必须计算可达到的最小最终长度。 

数组长度可以大到`10^6`在单个测试用例中，最多`10`测试用例。 任何探索不同操作顺序或模拟多种可能性的算法都会立即被排除。 即使是二次方时间也需要大约`10^12`对最大的输入进行操作，这是完全不可行的。 该解决方案必须在线性时间内处理每个数组。 

棘手的部分是我们可以选择其余的任何一个。 这种自由意味着实际的价值观远没有它们最初看起来那么重要。 

考虑数组`[1, 1, 1]`。 我们可以将前两个元素替换为`1 % 1 = 0`，得到`[0, 1]`。 由于剩余的一对并非都是正数，因此该过程随着长度而停止`2`。 尽可能合并的贪婪尝试无法达到长度`1`。 

现在考虑`[2, 3]`。 自从`2 % 3 = 2`和`3 % 2 = 1`，两种选择都不会产生零。 数组总是变成单个正值，所以答案是`1`。 

另一个重要案例是`[5, 5, 5, 5]`。 相同的值可以立即产生零，因为`5 % 5 = 0`。 重复这个想法留下两个零，所以最小长度是`2`， 不是`1`。 将每个正块视为完全可还原会给出错误的答案。 

## 方法

 强力解决方案将探索每个有效操作、每个可能的相邻对以及两个余数选择。 由于每个操作都会改变未来的可能性，因此搜索呈指数级分支。 即使是记忆也是无效的，因为可到达的数组数量巨大。 这种方法是正确的，因为它检查每个合法序列，但即使对于几十个元素的数组，它也变得毫无希望。 

关键的观察结果是零永久阻止未来的合并。 由于只能合并相邻的正数，因此每个最大连续正值块的行为都是独立的。 一个块内的操作永远不会与另一个块交互，因为零永远不会消失。 

剩下的问题是单个正块可以减少到什么程度。 

假设块内的每个值都是相同的。 每次合并都会产生零，因为`x % x = 0`。 每次合并都会创建一个分隔符，防止该零再次参与。 从一个长度块开始`k`，每次合并恰好消耗两个正数并创建一个零。 最终只剩下零，加上可能一个未触及的正数，如果`k`很奇怪。 该块的最终长度是`ceil(k / 2)`。 

现在假设该块至少包含两个不同的值。 那么在重复应用欧几里得算法时，块的最大公约数总是可以被保留。 由于不相等的数字最终会产生严格较小的正余数，因此我们可以避免创建阻塞零，直到只剩下一个正值。 整个块折叠成单个元素。 

这完全体现了每个积极块的特征。

 ## 算法演练

 1. 从左到右扫描阵列。 
2. 每当遇到零时，请跳过它，因为它已经分隔了独立区域。 
3. 当找到正值时，识别整个最大连续正块。 
4. 扫描该块时，检查每个元素是否等于第一个元素。 同时，记录块长度。 
5. 如果块中的每个值都相同，则添加`(length + 1) // 2`到答案。 这正是`ceil(length / 2)`。 
6. 否则，添加`1`答案是因为整个块可以简化为单个元素。 
7. 在块末尾后继续扫描，直到处理完整个数组。 

### 为什么它有效

 零是永久的障碍，因为只有相邻的正数可以参与运算。 每个操作都保留在一个正块内，因此不同的块不会相互影响。 

在包含至少两个不同值的块内，重复应用欧几里德算法可将整个块减少为一个正值，而不会引入不可避免的零。 在每个值都相同的块内，每个可能的合并都会立即创建一个零，将剩余的正值分成更小的独立部分。 该过程正好离开`ceil(length / 2)`幸存的元素。 由于每个块都是独立的，因此将这些贡献相加即可得出最小的最终数组长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0
        i = 0

        while i < n:
            if a[i] == 0:
                i += 1
                continue

            first = a[i]
            same = True
            j = i

            while j < n and a[j] > 0:
                if a[j] != first:
                    same = False
                j += 1

            length = j - i

            if same:
                ans += (length + 1) // 2
            else:
                ans += 1

            i = j

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```外循环独立处理每个测试用例。 指针`i`扫描数组一次，并且每个正块都被检查一次。 

对于每个块，代码会记住第一个值并检查后面的每个值是否与其匹配。 这避免了在确定块是否统一时存储任何额外的数据结构。 

表达式`(length + 1) // 2`计算`ceil(length / 2)`使用整数运算。 这是统一块所需的唯一特殊情况。 

完成一个块后，扫描直接跳到末尾。 没有重新访问任何元素，这就是实现保持线性的原因。

 ## 边缘情况

 考虑输入：```
1
3
1 1 1
```该算法找到一个长度为正的块`3`，观察到每个值都是相同的，并且贡献`(3 + 1) // 2 = 2`。 输出是`2`，匹配最佳操作顺序。 

现在考虑：```
1
2
2 3
```块长度为`2`，但值并不相同。 该算法贡献`1`，正确认识到不相等的数字始终可以合并为单个剩余值。 

最后，考虑：```
1
5
4 4 0 6 7
```扫描检测到两个独立的块。 第一个是统一与贡献`1`。 第二个包含具有贡献的独特价值观`1`。 他们的总和是`2`。 在处理过程中，零永远不会交叉，完全符合操作不能涉及非正邻居的限制。
