 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组。 数组中的每个值最多`m`。 对于每个查询值`x`，我们必须计算有多少个有序对`(ai, aj)`满足`gcd(ai, aj) = x`。 有序对的意思是`(i, j)`和`(j, i)`分别计算时`i ≠ j`， 和`(i, i)`也是一个有效的对。 

简单的解释是计算每对索引的最大公约数，并根据这些结果回答查询。 这是正确的，但输入大小使其不可能。 两个都`n`和`m`可以达到`10^5`，并且可能有`10^5`查询。 计算全部`n²`对需要最多`10^10`GCD 计算，远远超出一秒的计算范围。 即使存储每一对的信息也是不可能的。 

值的上限是真正的机会。 每个数组元素最多`m`，因此我们可以推理值及其除数，而不是推理单个指数。 迭代每个整数的倍数的算法大致运行`m log m`时间因为$$\sum_{i=1}^{m}\frac{m}{i}=m\log m.$$这完全在限制范围之内`m = 10^5`。 

一个容易犯的错误是忘记了问题需要有序对而不是无序对。 

例如，```
n = 2
array = [2, 4]
query = 2
```正确答案是`4`因为有效的对是`(2,2)`,`(2,4)`,`(4,2)`， 和`(4,4)`。 除以二就好像这些对无序一样会产生错误的答案。 

另一个微妙的情况是查询的 GCD 从未作为数组值出现。```
array = [6, 12]
query = 3
```没有一对的 GCD 等于`3`，即使每个数字都可以被`3`。 简单地计算可以被整除的数字`3`会错误地返回`4`。 

第三个常见错误是计算 GCD 是查询的倍数而不是查询的整数对。```
array = [4, 8]
query = 2
```两个数字都可以被`2`，但实际上每对都有 GCD`4`。 正确答案是`0`。 这正是需要包含-排除步骤的原因。 

## 方法

 蛮力方法检查每个有序的索引对，计算`gcd(ai, aj)`，并增加相应的答案。 它的正确性是直接的，因为它直接实现了问题的定义。 不幸的是，与`n = 10^5`，它执行`10^10`配对检查，使其完全不切实际。 

关键的观察结果是 GCD 是通过整除性来定义的。 不要一一检查对，而是计算有多少个数组元素可以被每个可能的值整除。 

让`cnt[v]`是值的频率`v`在数组中。 

对于每个除数`d`, 计算$$f[d]=\text{number of array elements divisible by }d.$$这是通过迭代多个来有效完成的`d`。 

如果`f[d]=c`，那么有`c²`其两个值均可被整除的有序对`d`。 这些对的 GCD 等于`d`或某个倍数`d`。 

剩下的任务是分离 GCD 恰好为的对`d`。 从大到小处理除数使这成为可能。 让`ans[d]`用 GCD 精确表示有序对的数量`d`。 最初，$$ans[d]=f[d]^2.$$这里计算的每一对实际上的 GCD 都是`2d`,`3d`，或者已经计算出另一个倍数，因为首先处理较大的除数。 减去所有这些贡献：$$ans[d]=f[d]^2-\sum_{k\ge2}ans[kd].$$这是倍数上的经典包含排除原理，通常被描述为莫比乌斯反演，无需显式计算莫比乌斯函数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n² log m) | O(n² log m) | O(米) | 太慢了|
 | 最佳| O(m log m + k) | O(m log m + k) | O(米) | 已接受 |

 ## 算法演练

 1.读取数组并构建频率数组`cnt`， 在哪里`cnt[v]`是值出现的次数`v`。 
2. 对于每个整数`d`从`1`到`m`，计算有多少个数组元素可以被整除`d`。 迭代`d, 2d, 3d, ...`并将它们的频率累积成`divisible[d]`。 
3. 创建答案数组。 
4. 处理除数`m`下降到`1`。 
5. 设置`ans[d] = divisible[d] * divisible[d]`。 这会计算两个值可被整除的每个有序对`d`。 
6. 迭代倍数`2d, 3d, ...`并减去`ans[multiple]`从`ans[d]`。 这些对在上一步中已计算在内，但实际上具有更大的 GCD。 
7. 预处理完成后，通过打印回答每个查询`ans[x]`。 

### 为什么它有效

 对于每个除数`d`,`divisible[d]²`计算所有 GCD 为以下倍数的有序对的数量`d`。 每一个这样的对都属于一个值，即它的精确 GCD。 从较大的除数到较小的除数的处理保证了所有较大的 GCD 贡献都已被计算。 减去这些贡献就精确地留下了 GCD 等于的对`d`。 由于每一对都恰好有一个最大公约数，因此每一对都被计算一次且仅一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m, k = map(int, input().split())

        cnt = [0] * (m + 1)
        for v in map(int, input().split()):
            cnt[v] += 1

        divisible = [0] * (m + 1)
        for d in range(1, m + 1):
            s = 0
            for x in range(d, m + 1, d):
                s += cnt[x]
            divisible[d] = s

        ans = [0] * (m + 1)
        for d in range(m, 0, -1):
            cur = divisible[d] * divisible[d]
            for x in range(d * 2, m + 1, d):
                cur -= ans[x]
            ans[d] = cur

        for _ in range(k):
            x = int(input())
            out.append(str(ans[x]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```频率数组将输入压缩为值计数而不是位置。 这就是预处理依赖于的原因`m`而不是`n²`。 

第二个循环计算有多少个数字可以被每个除数整除。 迭代倍数是高效的，因为每个整数仅显示为其除数的倍数。 

反向循环是该算法的核心。 减法必须在处理完较大的除数之后进行，这就是迭代从`m`下降到`1`。 颠倒此顺序将减去尚未计算的值。 

广场`divisible[d] * divisible[d]`已经正确计算了有序对。 不需要因子二，因为问题需要有序对。 

所有中间值都适合 Python 整数。 在具有固定宽度整数的语言中，需要 64 位类型，因为最大可能的答案是`n²`，达到`10^10`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m log m + k) | O(m log m + k) | 倍数上的两个谐波级数循环，然后每个查询的时间恒定 |
 | 空间| O(米) | 频率、可除计数和答案数组 |

 ## 边缘情况

 考虑数组```
1
2 4 1
2 4
2
```可整除的计数是`divisible[4] = 1`和`divisible[2] = 2`。 该算法首先计算`ans[4] = 1`。 对于除数`2`，它开始于`2² = 4`有序对并用 GCD 减去一对`4`，离开`4`。 这匹配四个有序对，其 GCD 恰好为`2`。 

现在考虑```
1
2 12 1
6 12
3
```两个值都可以整除`3`， 所以`divisible[3] = 2`初始计数是`4`。 处理较大的除数会减去 GCD 为的四对`6`，离开`0`。 该算法正确区分整除性和精确 GCD。 

最后，```
1
2 8 1
4 8
2
```再次`divisible[2] = 2`，给出初始计数`4`。 计算减去`ans[4] = 3`和`ans[8] = 1`，留零。 每个候选对都属于一个更大的精确 GCD，因此没有剩余的可作为除数`2`。 这说明了为什么从大除数到小除数的处理是必要的。
