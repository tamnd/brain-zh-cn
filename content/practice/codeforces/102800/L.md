 ## 解决方案
 ## 问题理解

 每个游泳者在一条长度的泳道中来回移动`m`。 每个游泳运动员从指定位置开始`0`，游向位置`m`，到达后立即转身，并永远重复这个动作。 游泳者的速度`i`是固定的并且等于`x[i]`米每秒。 每个查询都会询问一位特定游泳者在给定秒数后的位置。 

游泳者从不相互交互，因此每个查询都是完全独立的。 查询所需的唯一信息是游泳者的速度、泳道长度和经过的时间。 

限制才是真正的挑战。 最多可以有`10^6`游泳运动员和`10^6`查询。 任何每秒模拟运动的算法都是不可能的，因为单个查询可能涉及多达`10^9`秒。 即使模拟每个转弯也会失败，因为游得快的人可能会完成数亿次行程。 对于一百万个查询，每个查询只有恒定的时间工作才是实用的。 单独读取输入已经花费了输入大小的线性时间，因此算法应该只花费`O(1)`每个查询的额外工作。 

一些边缘情况很容易被错误处理。 

考虑准确到达墙壁。```
Input
1 5 1
1
5 1
```游泳者已经准确地游过`5`米，所以正确答案是```
5
```总是在取余数后反映的粗心实现可能会错误地返回`0`。 

现在考虑正好在一个完整的来回循环结束时着陆。```
Input
1 5 1
1
10 1
```游泳者已经离开`0`到`5`并回到`0`，所以正确答案是```
0
```将周期长度与`m`而不是`2m`会错误地返回`5`。 

另一个常见的错误是忘记游泳者在到达远处的墙壁后改变方向。```
Input
1 3 1
2
2 1
```游泳者去旅行`4`总共米。 到达位置后`3`，返回时还剩下一米的移动，所以答案是```
2
```简单计算`(speed × time) % m`会错误地返回`1`。 

## 方法

 最直接的解决办法就是模拟游泳者的动作。 从位置开始`0`，反复使游泳者前进，直到到达其中一堵墙，反转方向，然后继续前进，直到经过所要求的时间。 这与物理过程完全吻合，因此显然是正确的。 不幸的是，它太慢了。 单个查询可能涉及数十亿秒或数亿轮，使得最坏的情况完全不可行。 

关键的观察结果是游泳者的运动是完全周期性的。 想象一下将车道延伸成一条无限直线，而不是在墙壁上反射。 行驶总距离后```
distance = speed × time
```游泳者距离起点就只是这个距离。 

可以通过每隔一段时间折叠这条无限线来建模反射`2m`米。 一个完整的周期包括游泳`0`到`m`然后从`m`到`0`，给定周期长度`2m`。 

让```
r = (speed × time) mod (2m)
```如果`r ≤ m`，游泳者仍在向外的行程中，所以位置很简单`r`。 

否则，游泳者将返程。 距远墙的剩余距离为`r - m`，所以位置是```
2m - r
```现在，每个查询仅需要一次乘法、一次模运算和一次比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 不可能有效地绑定，最多`O(speed × time)`模拟|`O(1)`| 太慢了|
 | 最佳|`O(1)`每个查询|`O(n)`| 已接受 |

 ## 算法演练

 1.读取游泳人数、泳道长度、查询次数。 
2. 将所有游泳者的速度读入数组，以便每个查询都可以在恒定时间内访问其游泳者的速度。 
3. 计算周期长度为`cycle = 2 × m`，因为每次完整的去程和回程行程恰好涵盖`2m`米。 
4. 对于每个查询，检索游泳者的速度并计算总行程距离：`speed × time`。 
5. 将此距离取模减小`cycle`。 最后一个不完整循环之前的所有内容都会精确重复，因此只有余数会影响当前位置。 
6.如果余数最多为`m`，游泳者正在远离起点，因此输出余数。 
7. 否则，游泳者将返回起点。 通过输出将剩余部分反射到远处的墙上`cycle - remainder`。 

### 为什么它有效

 游泳者的位置仅取决于他们在水流中的位置`2m`米周期。 每个完整循环的结束位置和方向与开始时完全相同，因此使用模运算删除完整循环可以保留答案。 在一个周期内，路径是从`0`到`m`接下来是一段直线`m`回到`0`。 这两个公式与这两半完全对应，因此每个可能的余数都映射到正确的物理位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    speeds = list(map(int, input().split()))

    cycle = 2 * m
    out = []

    for _ in range(q):
        p, k = map(int, input().split())
        r = (speeds[k - 1] * p) % cycle
        if r <= m:
            out.append(str(r))
        else:
            out.append(str(cycle - r))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该程序首先存储每个游泳者的速度，以便每个查询都可以通过直接索引访问它。 由于游泳者从 1 开始编号，而 Python 列表的索引为零，因此代码使用`k - 1`。 

周期长度只计算一次，因为它永远不会改变。 每个查询执行相同的算术运算序列。 Python 整数可以安全地处理大到的值`10^9 × 10^9 = 10^18`，所以溢出不是问题。 

比较使用`<= m`而不是`< m`。 当余数正好是`m`，游泳者刚刚到达远处的墙壁并且仍然位于位置`m`。 使用严格的比较只会巧合地错误地反映这一点，并且在其他语言中使用不同的公式可能会引入微妙的错误。 

取模`2m`， 不是`m`。 使用`m`将完全丢失有关游泳者是向外移动还是返回的信息。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n + q)`| 读取速度需要线性时间，每个查询都是恒定时间。 |
 | 空间|`O(n)`| 速度数组存储一次。 |

 输入本身已经包含`n`速度和`q`查询，因此线性预处理是不可避免的。 每个查询的持续工作很容易满足约束，即使两者都存在`n`和`q`是一百万。 

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n, m, q = map(int, input().split())
    speeds = list(map(int, input().split()))
    cycle = 2 * m
    ans = []
    for _ in range(q):
        p, k = map(int, input().split())
        r = (speeds[k - 1] * p) % cycle
        if r <= m:
            ans.append(str(r))
        else:
            ans.append(str(cycle - r))
    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

# provided sample
assert run("1 3 2\n5\n1 1\n7 1\n") == "1\n1"

# minimum input
assert run("1 1 1\n1\n0 1\n") == "0"

# exact turning point
assert run("1 5 1\n1\n5 1\n") == "5"

# complete cycle
assert run("1 5 1\n1\n10 1\n") == "0"

# reflection
assert run("1 3 1\n2\n2 1\n") == "2"

# multiple swimmers
assert run("2 5 2\n2 3\n2 1\n2 2\n") == "4\n4"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 | 单人游泳者，零时间|`0`| 最小输入且无移动 |
 | 到达位置`m`正是|`5`| 正确处理转折点|
 | 完整周期|`0`| 正确的模周期`2m`|
 | Reflection example |`2`| 返回半个周期|
 | 多名游泳者 |`4`,`4`| 正确索引速度数组 |

 ## 边缘情况

 当游泳者准确到达远处的墙壁时，余数等于`m`。```
Input
1 5 1
1
5 1
```该算法计算`r = 5 mod 10 = 5`。 自从`5 ≤ 5`，它返回`5`，与游泳者在墙上的实际位置相匹配。 

当游泳者完成整个往返时，余数变为零。```
Input
1 5 1
1
10 1
```该算法计算`r = 10 mod 10 = 0`。 第一个分支返回`0`，这正是一个完整循环后的起始位置。 

当游泳者已经转身时，需要进行反射。```
Input
1 3 1
2
2 1
```总距离为`4`。 该算法计算`r = 4 mod 6 = 4`。 自从`4 > 3`，它返回`6 - 4 = 2`。 身体上，游泳者达到了位置`3`后`1.5`秒，然后再游回一米，最终到达位置`2`，与计算结果完全匹配。
