 ## 解决方案
 ## 问题理解

 我们给出了一系列的日子，每天都有一个购买一份冰淇淋的价格。 每天还有一些限制，描述坦尼娅当天可以吃多少份。 整个夏天她必须吃得恰到好处$k$总计部分，同时遵守每天的最低和最高消费限制。 

关键的决定是如何分配$k$跨天的份量，因为每份必须在食用当天购买，并且成本取决于当天的价格。 有些日子比较便宜，所以我们想在那里分配更多的部分，但我们不能超过上限或违反下限。 

输出是精确购买的最小可能总成本$k$部分同时尊重所有每日限制，或$-1$如果不存在有效的分布。 

这些约束推动了贪婪或基于排序的方法。 和$n$最多$2 \cdot 10^5$和$k$最多$10^9$，任何尝试按单元动态分配部分或使用按部分模拟的解决方案都是不可能的。 甚至一个$O(nk)$策略立即不可行。 

当可行性本身失败时，就会出现边缘情况。 如果所有最低要求的总和超过$k$，或者所有最大容量的总和小于$k$，不存在解。 另一个微妙的情况是，贪婪分配忽略了强制性的最低要求：天真的“总是选择最便宜的日子”策略破坏了可行性，因为它可能会违反仍必须收到一些部分的昂贵日子的下限。 

## 方法

 蛮力方法会尝试决定每天分配多少部分，同时遵守界限，并计算成本。 这相当于枚举所有整数向量$(d_1, \dots, d_n)$这样$a_i \le d_i \le b_i$总和是$k$，然后评估总成本。 这种分布的数量以组合方式增长，即使是粗略的界限也表明它是指数增长的$n$，因为每天都会贡献一系列可能的值。 在非常小的情况下，这几乎立即变得不可行$n$。 

关键的观察结果是，每天的成本结构是线性的：每天的每个部分$i$费用相同$c_i$。 这意味着我们不关心一天内的订单，只关心每天订购多少份。 问题变成了分布$k$将相同的单元放入具有下限和上限的箱中，其中箱中的每个单元具有相同的成本。 

如果我们将约束与优化分开，就会出现自然的贪婪想法。 首先，我们必须满足所有最低要求。 这给出了基线分配。 之后我们还需要分配剩余的部分。 此时，每天都有剩余容量，当天每增加一份$i$有成本$c_i$。 因此，我们应该始终首先将额外的部分分配给最便宜的可用日期。 

这将问题变成了按成本对天数进行排序，并在尊重上限的同时贪婪地填充剩余容量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举| 指数| O(n) | 太慢了 |
 | 贪心排序 |$O(n \log n)$| O(n) | 已接受 |

 ## 算法演练

 1. 通过对所有部分求和来计算所需的最小部分总和$a_i$。 如果这超过$k$，不存在解。 这增强了下限的可行性。 
2. 通过对所有的求和来计算总的最大可能总和$b_i$。 如果这个值小于$k$，不存在解。 这增强了上限的可行性。 
3. 分配每天的最低限度$a_i$部分。 这是每个有效解决方案都必须包含的强制基线。 
4. 将剩余部分计算为$k - \sum a_i$。 这些是灵活的单元，可以在剩余容量内分配到任何地方。 
5. 对于每一天，计算其剩余容量为$b_i - a_i$。 这些表示当天仍可以分配多少额外部分。 
6. 按成本增加对所有日期进行排序$c_i$。 这确保我们在分配灵活的部分时始终首先考虑便宜的日子。 
7. 按排序顺序遍历日期。 对于每一天，分配尽可能多的剩余部分，受其剩余容量和剩余全局需求的限制。 
8. 累计总成本作为基准成本$\sum a_i \cdot c_i$加上额外分配部分的增量成本。 
9. 当所有剩余部分都已分配完毕后停止。 

### 为什么它有效

 在确定强制性的最低分配后，除了在特定日期放置其的成本之外，每个剩余部分都是独立且相同的。 每天提供数量有限、成本相同的相同“时段”。 这减少了选择最便宜的可用插槽的问题，直到配额被填满。 任何与按成本排序的偏差都可以通过将更昂贵的分配槽与更便宜的未使用槽交换来改善，因此通过交换参数，贪心选择是最优的。 最小约束仅影响基线； 它们不会干扰可选作业的排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    days = []
    
    min_sum = 0
    max_sum = 0
    
    for _ in range(n):
        a, b, c = map(int, input().split())
        min_sum += a
        max_sum += b
        days.append((c, a, b))
    
    if k < min_sum or k > max_sum:
        print(-1)
        return
    
    remaining = k - min_sum
    
    total_cost = 0
    
    for c, a, b in days:
        total_cost += a * c
    
    days.sort()
    
    for c, a, b in days:
        if remaining == 0:
            break
        capacity = b - a
        take = min(capacity, remaining)
        total_cost += take * c
        remaining -= take
    
    print(total_cost)

if __name__ == "__main__":
    solve()
```实施过程首先使用最小总和和最大总和检查可行性。 这可以防止在不可能的配置上浪费工作。 基线成本是根据强制分配立即计算的，确保我们清楚地区分强制决策和可选决策。 

按成本排序是关键步骤：一旦对日期进行排序，我们就会按该顺序贪婪地消耗剩余容量。 这`remaining`变量跟踪有多少灵活部分仍未分配。 每次迭代都会消耗当前最便宜的一天中尽可能多的资源。 

一个常见的实施错误是忘记在排序之前必须包括基线成本； 排序不会影响强制分配，只会影响灵活分配。 另一个微妙的问题是其他语言中的整数溢出，但 Python 可以安全地处理大整数。 

## 工作示例

 ### 示例 1

 输入：```
3 7
3 5 6
0 3 4
3 3 3
```我们计算最小和最大总数：

 | 日 | 一个 | 乙| c | 基线a | 剩余上限 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 3 | 5 | 6 | 3 | 2 |
 | 2 | 0 | 3 | 4 | 0 | 3 |
 | 3 | 3 | 3 | 3 | 3 | 0 |

 最小总和是 6，所以我们需要额外一份。 

我们按成本排序：第 3 天 (3)、第 2 天 (4)、第 1 天 (6)。 

我们将额外的部分分配给第 3 天？ 没有容量，所以第二天就可以了。 

| 步骤| 日 | 剩余| 拍摄 | 成本增加 |
 | ---| ---| ---| ---| ---|
 | 开始 | - | 1 | - | 基线 = 3_6 + 0_4 + 3*3 = 27 |
 | 1 | 第二天| 1 | 1 | +4 |

 最终成本是31。 

该跟踪表明，强制约束强制采用不平凡的基线，而贪婪仅适用于剩余容量。 

### 示例 2

 输入：```
2 5
1 3 10
1 4 1
```Baseline is 2, so remaining is 3.

 | 日 | c | 帽 |
 | ---| ---| ---|
 | 2 | 1 | 3 |
 | 1 | 10 | 10 2 |

 我们从第二天起就把剩下的 3 个都拿走了，因为它最便宜。 

最终成本 = 基线 (1_10 + 1_1 = 11) + 3*1 = 14。 

这证实了贪婪排序正确地避免了昂贵的分配，即使存在更受限制的昂贵的一天。

 ## 边缘情况

 一个关键的边缘情况是最低要求已经超过$k$。 在这种情况下，即使在考虑成本之前，答案也必须是$-1$。 该算法通过总和立即检测到这一点$a_i$，确保不会发生不必要的排序或分配。 

另一种情况是最大容量不足时。 即使成本有利，也无法实现分销$k$，并且早期的可行性检查可以防止错误的部分分配。 

最后一个微妙的情况是，所有灵活产能都属于较昂贵的日子，而较便宜的日子已经被最低限度饱和。 该算法仍然表现正确，因为它将强制分配和可选分配分开，确保贪婪选择仅适用于实际可用的灵活性，而不是强制不可行的重新分配。
