 ## 解决方案
 ## 问题理解

 我们被要求为沿着城市固定循环路线旅行的游客规划最少的访问次数。 城市编号从1到n，循环排列，旅行者总是向前移动：从城市i到i+1，从城市n回到城市1。每个城市i都有一个目标自拍数量$a_i$必须拍照，并且旅行者每次访问只能拍一张自拍照。 他从城市 1 开始并且不能跳过城市。 目标是找出满足所有自拍要求所需的城市访问总数。 

输入由城市数量组成$n$和数组$a$长度$n$。 每个$a_i$可以达到$10^9$和$n$可以达到$2 \cdot 10^5$。 这意味着逐一访问城市的暴力模拟会太慢，因为访问总数可能非常大。 相反，我们需要一种在线性时间内工作的方法$n$。 

一个天真的解决方案可能会尝试模拟游客自拍，直到所有计数都满足，逐个城市移动并循环循环。 例如，使用输入`3 1 0 0`，模拟将在 1 次访问后停止，这很好。 但对于`3 3 1 2`，幼稚的模拟可能会不必要地重复循环，无法有效地找到最小访问次数。 挑战在于，由于周期的原因，每个城市都可以多次访问，并且周期的次数并不是预先固定的。 

非明显的边缘情况包括要求零自拍的城市、与其他城市相比自拍次数非常高的城市以及要求低于前一个城市的城市。 例如，输入`3 0 100 0`应该返回`101`，因为第一个城市贡献了 0 次访问，但第二个城市需要 100 次访问，这是跨周期分布的。 如果忽略循环依赖性的累积效应，粗心的方法可能会低估访问次数。 

## 方法

 蛮力解决方案很简单：从城市 1 开始，自拍，直到每个城市达到所需的数量，逐个城市移动并循环。 每次访问时，减少当前城市的剩余自拍照。 这在逻辑上是正确的，但可能需要总结$10^9$单个城市的步骤，这是不可行的。 

关键的观察是，对于每个城市 i（第一个城市之后），我们可以根据从前一个城市继承的“多余自拍”来思考。 由于游客的流动是周期性的，因此城市i的最少访问次数受到前一城市的自拍次数与其要求之间的差异的影响。 更正式地说，对于每个城市 i，城市 i 所需的访问次数至少为$\max(0, a_i - a_{i-1})$。 第一城总是贡献自己的全部$a_1$到访问计数。 然后，以这种增量方式对所有城市的贡献进行求和，得出最小的总访问量。 这是有效的，因为一个城市的每一次超额只能减少下一个城市所需的额外访问次数。 

最优解决方案利用了环是循环的和不能跳过自拍的特性：每个城市所需的最小额外访问次数是与前一个城市的非负差异。 通过对这些调整后的差异求和并添加第一个城市的自拍照，我们实现了 O(n) 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(总和(a_i)) | O(n) | 对于大 a_i 来说太慢 |
 | 基于差异的最小值 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取城市数量$n$和数组$a$代表每个城市所需的自拍。 
2. 初始化总访问次数为$total = a_1$因为旅程从城市 1 开始，所有的自拍照都必须拍。 
3. 从 2 到 n 迭代城市。 对于每个城市 i，计算$extra = \max(0, a_i - a_{i-1})$。 这表示除了访问前一个城市已经“覆盖”的范围外，城市 i 还需要额外的访问。 
4. 添加$extra$到$total$。 
5. 打印最终结果$total$。 

为什么有效：基于差异的方法准确地捕获了由于循环排序而不可避免的额外访问次数。 对于任何城市，如果前一个城市所需的自拍次数更高或相等，则当前城市可以使用相同的访问次数，而无需额外的周期。 只有当当前城市的需求超过之前的需求时才会强制增加访问量，$\max(0, a_i - a_{i-1})$公式捕获。 循环闭合（从城市 n 到 1）是隐式处理的，因为第一个城市已完全计数，确保不会少算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = a[0]
for i in range(1, n):
    total += max(0, a[i] - a[i-1])

print(total)
```该代码读取城市的数量和所需的自拍照。 它初始化`total`与第一个城市的自拍照。 对于每个后续城市，它都会添加与前一个城市的非负差异。 这确保我们只计算最少的必要访问。 不存在相差一的错误，因为我们从第二个城市开始迭代并单独处理第一个城市。 Python 的整数可以处理非常大的计数而不会溢出。
