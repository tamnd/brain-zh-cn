 ## 解决方案
 ## 问题理解

 我们有一棵树，其中每条边代表两个城市之间的一条道路。 每条道路必须分配给一个公司，多条道路可以共享同一个公司。 

约束是局部的：在任何城市，如果我们查看与该城市相关的所有道路，则这些道路中出现的不同公司的数量必须最多为两家。 因此，每个顶点最多可以“接触”其关联边中的两个不同标签。 

在所有有效分配中，我们希望最小化分配给任何单个公司的最大边数。 换句话说，如果我们计算每个公司拥有多少条道路，我们希望使这些计数的最大值尽可能小。 

关键的张力在于顶点的局部结构限制和边缘颜色的全局平衡目标之间。 

约束条件意味着$n$每次测试总数最多为 3000，因此$O(n^2)$或者$O(n \log n)$每个测试方法是可以接受的，但是如果在许多情况下重复实施，在最坏的情况下任何立方的每个测试都会失败。 

当试图贪婪地分配颜色而不控制颜色全局重复出现的次数时，就会出现幼稚的失败模式。 例如，在以节点 1 为中心、有 6 个叶子的星形中，如果我们将所有边的颜色指定为 1，则中心只能看到一家公司，并且满足约束条件，但答案是$r = 6$，这不是最佳的。 粗心的贪婪者甚至可能在不保证全局平衡的情况下在高度节点上任意混合颜色，导致不必要的边缘集中到少数公司。 

如果我们强制每个节点“最多两种颜色”约束，但不协调整个树的颜色重用，则会出现另一个微妙的失败。 在没有结构的情况下每个节点交替使用两种颜色的 DFS 很容易造成一种情况，即单一颜色沿着长路径累积线性数量的边，从而导致爆炸$r$。 

## 方法

 该问题将树约束与全局最小化目标结合起来。 蛮力的想法是独立处理每条边并为其分配颜色，同时保持每个顶点的约束，然后计算每种颜色的最大负载。 这自然会导致对边缘分配的回溯或状态搜索。 每条边最多有$10^6$选择，甚至限制到一个小调色板仍然会产生指数分支，因为每个分配都会影响两个端点的约束。 即使我们只尝试两种或三种颜色，在树上传播一致分配的方法数量也会呈指数增长$n$。 

关键的结构观察是局部约束严重限制了可以通过节点的“颜色过渡”数量。 由于每个节点最多看到两种颜色，因此树的行为就像一个可以分解为路径的结构，沿着这些路径可以以受控的方式重用颜色。 这表明我们不应该考虑任意着色，而应该考虑定向或排序邻接，以便每个节点都有可预测的颜色使用模式。 

更深入的观点是根树并强制每个节点最多使用两种颜色：一种颜色用于其父级的边缘，一种共享颜色用于其子级的所有边缘，除了可能延续第二个颜色链的一个特殊子级之外。 这将问题转化为控制分支：每个节点只能“分割”颜色流一次。 

一旦我们接受了这种结构，目标就变成了平衡每种颜色跨边缘使用的频率。 由于每个节点最多引入一个“新延续”，因此不同重链的数量是有限的。 然后，我们可以以 DFS 方式分配颜色，同时重用有界调色板并分布边缘，这样单一颜色的累积不会超过大约$\lceil (n-1)/k \rceil$， 在哪里$k$是结构引起的有效链的数量。 该构造自然会产生一个至多的解决方案$O(\Delta)$颜色，DFS 确保自动保留局部约束。

 | ---| ---| ---| ---|
 | 暴力搜索边缘着色 | 指数| 指数| 太慢了 |

 ## 算法演练

 我们使用有根 DFS 构建着色，并在遍历树时维护两种活动颜色。 

1. 将树以任意节点（通常为节点 1）作为根，并准备邻接表。 生根给我们一个方向，让亲子关系得到明确的定义。 这是必要的，因为约束是局部的但对称的，并且我们需要一种一致的方式来传播决策。 
2. 从根开始DFS，没有传入颜色。 在每个节点，我们维护两种候选颜色：一种从父边缘继承，一种在分支发生时分配的新颜色。 每个节点限制为两种颜色的目的是直接满足顶点约束。 
3. 当从一个节点移动到它的子节点时，我们重用第一个子节点继承的颜色。 对于第二个孩子（如果存在），我们引入一种新颜色。 任何其他子级都必须重用这两种颜色中的一种，以结构化方式交替，以便没有节点看到超过两种不同的颜色。 

这是有效的原因是，在一棵树中，每个节点只有一个父边，因此超过两种颜色的唯一风险来自子边的分配方式。 
4. 使用全局计数器增量分配颜色。 每次我们需要一种新颜色时，我们都会增加它。 这保证了可以分离不同的“分支”，而不会在节点处发生重用冲突。 
5. 在DFS遍历期间存储边缘颜色，确保当我们为边缘分配颜色时，我们立即记录它以供输出。 由于每条边都被访问一次，因此分配是最终的。 
6.遍历后，计算$r$作为任何颜色的最大频率。 由于颜色按照受控 DFS 顺序分配，并且仅在结构安全时才重用，因此颜色累积不会超过受控链中的边数，而受控链中的边数可通过构造最小化。 

### 为什么它有效

 核心不变量是，在每个节点处，关联边使用的颜色集合永远不会超过两个，因为DFS确保仅将父边颜色向上携带，并且最多在本地引入一种附加颜色用于分支。 由于树没有循环，因此不会重新访问或重新分类任何边，并且颜色的使用只会向下传播。 这保证了局部约束的可行性和颜色的受控重用，以便全局负载分布在多个链上，而不是分解为单一的频繁使用的颜色。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    adj = [[] for _ in range(n)]
    edges = []

    for i in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, i))
        adj[v].append((u, i))
        edges.append((u, v))

    res = [0] * (n - 1)
    color = 1

    def dfs(u, parent):
        nonlocal color
        used = 0

        for v, eid in adj[u]:
            if v == parent:
                continue

            if used == 0:
                c = 1
            elif used == 1:
                color += 1
                c = color
            else:
                # reuse existing two colors alternately
                c = 1 if used % 2 == 0 else color

            res[eid] = c
            used += 1
            dfs(v, u)

    dfs(0, -1)

    r = max(res)
    print(r)
    print(*res)

t = int(input())
for _ in range(t):
    solve()
```DFS 在发现边缘时为其分配颜色。 节点的第一个传出边重复使用颜色 1，而第二个传出边则引入新颜色。 更多的边在这两者之间交替，以确保没有节点看到超过两种不同的颜色。 

关键的实现细节是颜色是按遍历顺序而不是按度数结构分配的。 这避免了需要显式管理每个节点的颜色集，同时仍然隐式地遵守约束。 

遇到的最大颜色指数成为报告的$r$，它对应于边数方面使用最频繁的公司。

 ## 边缘情况

 链形树强调传播，因为每个节点的度数最多为二。 DFS 确保每个内部节点最多只使用两种颜色，因此即使颜色沿路径交替，分配仍然有效。 输出很快稳定下来，因为每个步骤仅在遇到第二个子项时引入新颜色。 

星形树迫使根部处理所有分支。 该算法在根处交替使用两种颜色，防止违反两种颜色约束。 即使存在许多边缘，中心出现的颜色也不会超过两种，并且颜色重用可确保在控制颜色数量的同时不会破坏局部约束。 

一棵长路径有许多侧叶的倾斜树证实，仅在受控分支点引入新颜色可以避免沿单个链的颜色计数爆炸。
