 ## 解决方案
 ## 问题理解

 我们得到了一个问题难度列表，其中每个问题都有一个索引和一个数字复杂度值。 任务是选择三个不同的索引$a$,$b$， 和$c$使得相应的值形成严格递增的链：$r_a < r_b < r_c$。 

输出不是值本身，而是任何有效三元组的索引。 如果不存在这样的三元组，我们必须输出`-1 -1 -1`。 

约束允许最多$n = 3000$。 这个尺寸足够小，可以$O(n^2)$甚至精心管理$O(n^3)$方法在某些语言中可能会通过，但在 Python 中，任何接近的方法都可以通过$O(n^3)$存在超时风险。 二次扫描是可以接受的，但根据常数，每次最坏情况超过 2700 万次操作的三次扫描已经处于临界状态。 

关键的困难不在于计算，而在于结构。 我们没有被要求优化数值函数或计数三元组，而是找到长度为三且保留索引的递增子序列的存在性。 

当值重复或未排序时，就会出现天真的陷阱。 例如，在像这样的数组中`[5, 1, 5, 1, 5]`，粗心的尝试可能会选择相同的值，认为它们形成了一个级数。 但这会失败，因为需要严格的不平等。 另一个微妙的问题是，以正确的索引顺序选择值是无关紧要的，因为只要值满足排序，索引就可以是任意的。 

暴力方法可能会忽略有效的三元组可能是分散的而不是相邻的，因此如果只检查邻居，贪婪的本地检查可能会失败。 

## 方法

 最直接的想法是尝试所有的指数三元组。 我们挑选$i < j < k$并检查是否$r_i < r_j < r_k$。 这是正确的，因为它明确地测试了条件。 然而，这检查$\binom{n}{3}$三倍，在最坏的情况下约为 45 亿张支票$n = 3000$。 这在 Python 中太慢了。 

我们需要避免枚举所有三元组，同时仍然保留有效检测有效中间元素的能力。 

关键的观察是对于任何固定的中间位置$j$，我们不需要搜索所有可能的对$(i, k)$独立。 相反，我们只需要知道是否存在小于$r_j$在其左侧并且某个值大于$r_j$在它的右边。 如果两者都存在，$j$作为有效三元组的中间。 

这将问题转化为维护两个辅助结构：前缀扫描跟踪迄今为止看到的最小元素（或其索引），后缀扫描跟踪大于每个元素的最小可能候选者或简单地检查右侧是否存在任何更大的元素。 由于值是任意的，因此我们可以针对每个位置预先计算右侧是否存在较大值，以及类似地左侧是否存在较小值。 

一旦计算出这些数组，扫描有效的中间索引就变得简单了。 对于任何$j$，如果存在$i < j$和$r_i < r_j$和$k > j$和$r_k > r_j$，我们立即输出该三元组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 前缀/后缀预计算 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们围绕每个有效三元组都有一个明确的中间元素的想法构建解决方案。 

1. 预先计算一个数组`left_min_index`存储每个位置$j$, 前缀中看到的最小值的索引$1..j$。 这给了我们一个候选人$i$这样$r_i < r_j$可以通过比较值来快速测试。 
2. 预计算数组`right_max_index`存储每个位置$j$，后缀中看到的最大值的索引$j..n$。 这给了我们一个候选人$k$这样$r_k > r_j$。 
3. 迭代每个索引$j$将其视为潜在的中间元素。 
4. 对于每个$j$，检查最佳候选前缀是否确实满足$r_{left[j]} < r_j$。 如果不是，则没有有效的左元素$j$。 
5. 同样，检查最佳后缀候选是否满足$r_{right[j]} > r_j$。 如果不是，则没有有效的正确元素$j$。 
6. 如果两个条件都成立，则立即输出索引的三元组。 

### 为什么它有效

 每个有效的解决方案都有一些中间元素$b$。 如果存在这样的三元组，则在其左侧的所有元素中$b$，至少有一个较小，并且在 右侧的所有元素中$b$，至少有一个更大。 前缀和后缀预计算保证我们不会错过这些候选者。 由于我们测试了每一个可能的中间位置，所以我们必须遇到正确的$b$，此时两个必需的同伴已经编码在预先计算的数组中。 无法跳过任何有效配置，因为每个候选中间索引都会被显式检查。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
r = list(map(int, input().split()))

left_min_index = [0] * n
min_idx = 0
for i in range(n):
    if r[i] < r[min_idx]:
        min_idx = i
    left_min_index[i] = min_idx

right_max_index = [0] * n
max_idx = n - 1
for i in range(n - 1, -1, -1):
    if r[i] > r[max_idx]:
        max_idx = i
    right_max_index[i] = max_idx

for j in range(n):
    i = left_min_index[j]
    k = right_max_index[j]
    if r[i] < r[j] and r[k] > r[j]:
        print(i + 1, j + 1, k + 1)
        sys.exit()

print(-1, -1, -1)
```前缀扫描为左侧最小值构建运行最佳候选，确保对于每个位置，我们都有较小元素的最强可能选择。 

对于较大的元素，后缀扫描的作用相反。 使用极值而不是完整列表就足够了，因为任何有效的中间元素只需要存在至少一个较小值和一个较大值。 

最后的循环只是将每个索引作为潜在的中间点进行测试，并验证双方是否都满意。

 ## 边缘情况

 一个棘手的情况是最小的有效左侧元素与中间候选元素不相邻。 考虑`3 1 4 1 5 9`。 在索引 2（值 4）处，正确的左候选是索引 1（值 1），而不是索引 0 或 3。前缀最小数组确保我们仍然选择索引 1，因为它全局跟踪最佳可用左值，而不管位置如何。 

另一个边缘情况是重复值。 在`2 2 2 3 3`，简单的扫描可能会为双方选择相同的值，但严格的不平等会阻止这种情况发生。 后缀最大值和前缀最小值保证正确性，因为它们始终验证实际值比较而不是依赖位置假设。 

最后一种情况是有效三元组相距很远，例如`1 100 2 3 4`。 中间元素不一定是局部增长趋势的一部分。 该算法仍然有效，因为它将每个索引检查为潜在的中间索引，并且不依赖于邻接性，仅依赖于全局前缀和后缀的存在。
