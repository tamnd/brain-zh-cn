 ## 解决方案
 ## 问题理解

 我们得到一个最多有 500 个顶点的无向图。 众所周知，该图来自一个非常具体的隐藏标记过程：每个顶点最初都有一个 0 到 15 之间的数字，并且当且仅当两个顶点的标签恰好有一个二进制位不同时，两个顶点之间才存在一条边。 换句话说，当两个顶点的值相差 XOR 形式的 2 的幂时，它们是相邻的。 

任务是为所有顶点重建 0 到 15 范围内数字的任何有效分配，这样，如果我们使用相同的 XOR 规则重建图，我们就可以准确地恢复给定的输入图。 

关键的限制是值只能是 4 位数字。 这意味着我们试图解释的图存在于 4 维超立方体结构中，但我们不知道哪个顶点对应于哪个立方体顶点。 我们只看到邻接结构。 

输入大小足够小，我们可以对边或顶点进行二次推理，但不能像尝试所有 16^n 分配那样。 任何在不强制执行全局一致性的情况下独立处理每个顶点标签的解决方案都会失败，因为边缘会施加强耦合约束：一旦一个顶点固定，其邻居就会受到部分约束，并且这些约束会传播。 

朴素方法的一个微妙的失败案例是根据每个顶点的度数独立处理每个顶点。 例如，人们可能会尝试贪婪地分配标签，以便每个顶点在可能的位翻转中具有正确数量的邻居。 这会失败，因为多个顶点必须同时在共享边上达成一致，并且局部度信息不能唯一确定 4 位值。 

## 方法

 关键的观察结果是，该图恰好是 4 维超立方体的子图，但可以任意重新标记。 每个标签都是一个 4 位向量，每个边对应翻转一位。 

这意味着该图必须是四个完美匹配的并集，每个匹配对应一个位位置。 每个顶点最多连接到四个邻居，每一位翻转一个。 因此，该图是 4-正则图或更少，并且每条边都根据位的不同进行“着色”。 

蛮力的想法是为每个顶点分配一个 0 到 15 之间的值并检查一致性。 这给出了 16^n 种可能性，完全不可行。 

一种更结构化的强力方法会将一个顶点固定为 0，然后传播约束：每个邻居必须恰好相差一位，因此它必须是四个候选者之一。 这成为小状态空间上的约束传播问题。 关键的困难在于，多个分配在本地仍然是可能的，但跨周期的一致性迫使一个独特的结构。 

重要的见解是我们不需要猜测绝对标签。 相反，我们可以使用 BFS 增量重建标签，将边缘约束视为变换。 如果我们为一个顶点分配一个值，则每条边都会强制其邻居为该值 XOR 2^k 对于某个未知的 k。 由于 k 最初未知，因此我们尝试与邻接结构一致的所有可能性并保持全局一致性。 

我们通过注意到一个更简单的结构来解决这个问题：由于标签是从 0 到 15，我们可以将每个顶点视为 4 位向量，并尝试通过强制沿边的一致性来直接分配位表示。 我们认为，沿着每条边 (u, v)，a[u] 和 a[v] 之间的异或必须是 2 的幂，这意味着恰好有一位不同。 

这成为二进制向量的约束系统。 该图保证是可解的，因此如果我们强制执行局部一致性，则从任意开始的任何一致传播都将成功。

我们选择一个任意顶点，为其分配 0。然后我们进行 BFS。 对于每条边，我们尝试通过恰好翻转与已分配的约束一致的一位来分配邻居。 由于每个顶点的度数都很小，因此我们可以通过已分配的所有邻居施加的相交约束来唯一确定其值。 

这减少了迭代地细化每个顶点的候选标签，直到所有顶点都被修复。

 | ---| ---| ---| ---|
 | 暴力破解分配| O(16^n·n) | O(16^n·n) | O(n) | 太慢了 |
 | 4 位状态的约束传播 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个顶点，将其可能的值初始化为完整集合 {0, 1, ..., 15}。 这代表在考虑约束之前可能采用的所有潜在 4 位标签。 
2. 对于每条边 (u, v)，强制执行 a[u] XOR a[v] 必须恰好为一位集的约束。 这意味着对于 u 域中的每个值 x，v 必须有一个值 y，使得 x XOR y 是 2 的幂。 我们相应地限制域名。 这一步直接对结构规则进行编码。 
3. 使用队列重复传播约束。 每当顶点的域缩小时，我们都会重新检查其所有邻居，因为它们的允许值也可能会缩小。 这是必要的，因为约束不是独立的； 对一个顶点的限制可能会使其邻居的多种可能性失效。 
4. 当一个顶点的域变成单个值时，我们将其视为固定的。 该固定值进一步将所有邻居限制为仅相差一位的值。 这会产生类似于约束满足问题的级联效应。 
5. 继续传播，直到域不再发生变化。 由于保证图是可解的，因此该过程必须以每个顶点至少具有一个有效值（并且实际上只有一个）结束。 
6. 输出每个顶点的最终分配值。 

这样做的原因是每条边在两个 4 位变量之间强制执行严格的代数约束。 约束系统是全局一致的并且完全对称。 由于我们从不分配违反任何边缘约束的值，并且每个限制仅源自有效的可能性，因此我们永远不会消除所有有效的全局解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def is_pow2(x):
    return x and (x & (x - 1)) == 0

def ok(x, y):
    return is_pow2(x ^ y)

n, m = map(int, input().split())
g = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

all_vals = (1 << 16) - 1

cand = [all_vals] * n
dq = deque()

# initialize
for i in range(n):
    dq.append(i)

while dq:
    u = dq.popleft()
    new_mask = 0

    for val in range(16):
        if not (cand[u] >> val) & 1:
            continue

        valid = True
        for v in g[u]:
            ok_v = False
            for nv in range(16):
                if (cand[v] >> nv) & 1 and ok(val, nv):
                    ok_v = True
                    break
            if not ok_v:
                valid = False
                break

        if valid:
            new_mask |= (1 << val)

    if new_mask != cand[u]:
        cand[u] = new_mask
        for v in g[u]:
            dq.append(v)

ans = [0] * n
for i in range(n):
    ans[i] = (cand[i] & -cand[i]).bit_length() - 1

print(*ans)
```该解决方案维护每个顶点的可能值的位掩码。 每个更新步骤都会过滤掉无法与 XOR 一位规则下的任何兼容邻居值匹配的值。 BFS 队列确保每当一个顶点的可能性缩小时，就会重新考虑其邻居，从而使约束传播稳定。 

最终分配为每个顶点选择最低的剩余有效值。 因为该问题保证了有效标签的存在，所以每个掩码最终都非空，并且一致性确保任何剩余的选择都有效。 

一个微妙的点是内部验证循环：对于顶点的每个候选值，我们必须验证每个邻居仍然具有至少一个兼容值。 这就是强制全球一致性而不仅仅是局部可行性的原因。

 ## 边缘情况

 关键边缘情况是度数较高的顶点，其值几乎完全由邻居决定。 在星图中，中心必须有一个同时与所有叶子兼容的标签。 该算法通过重复交叉允许的掩码来处理此问题，直到只剩下兼容的值。 

另一个边缘情况是断开的组件。 由于传播在所有顶点上都是全局的，因此每个组件都独立演化。 所有顶点的队列初始化确保每个组件都得到处理。 

最后一个微妙的情况是对称解决方案，其中多个分配是有效的。 该算法并不试图区分它们；而是尝试区分它们。 它仅保持可行性。 最后选择最低的剩余位是安全的，因为任何剩余的选择都属于问题陈述所保证的至少一个有效的全局解决方案。
