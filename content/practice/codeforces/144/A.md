 ## 解决方案
 ## 问题理解

 我们有一排士兵，每个人都有身高。 将军只关心阵容中的两个位置。 最高的士兵必须站在最前面，最矮的士兵必须站在最后。 其他人的顺序无关紧要。 

一秒钟之内，我们可能会交换两个相邻的士兵。 任务是计算实现所需排列所需的最小交换次数。 

输入给出了当前顺序的士兵数量和身高。 输出是一个整数，即所需的相邻交换的最小数量。 

限制很小，最多只有100名士兵。 即使是二次模拟也能在时间限制内轻松完成。 尽管如此，该问题仍然具有更清晰的线性时间观察，真正的挑战是正确处理重复的最大和最小高度。 

棘手的部分是决定移动最高和最矮的士兵中的哪一个。 如果多个士兵共享最大高度，我们应该将最左边的一个移到前面，因为它需要的交换最少。 如果多个士兵共享最小高度，我们应该将最右边的一个移到后面，再次最大限度地减少交换。 

当移动过程中所选的最大值与所选的最小值相交时，粗心的实施通常会失败。 

考虑这个输入：```
5
2 1 2 1 2
```正确答案是：```
3
```我们移动到最左边`2`在索引处`0`，它已经坐在前面，成本`0`互换。 然后我们移动最右边`1`在索引处`3`到最后，成本`1`交换。 总成本为`1`。 

如果我们错误地选择了第一个最小值而不是最后一个最小值，我们将需要更多的交换。 

当最大士兵站在最小士兵的右侧时，会出现另一个微妙的情况。```
5
1 3 2 4 5
```最高的士兵`5`位于索引处`4`，以及最矮的士兵`1`位于索引处`0`。 

移动`5`到前面需要`4`互换。 在此过程中，最矮的士兵向右移动一个位置。 这意味着将最小值移至末尾现在需要比以前少一次的交换。 忘记这一调整会产生太大的答案。 

## 方法

 暴力解决方案实际上是模拟交换。 我们可以反复将最高的士兵引向前方，然后将最矮的士兵引向后方。 由于每次交换都会改变相邻位置，因此这可以直接对问题陈述进行建模并且很容易推理。 

为了`n = 100`，甚至一个`O(n^2)`模拟是完全可以接受的。 在最坏的情况下，我们的表现大致如下`100 * 100 = 10,000`操作，规模很小。 

一旦我们注意到我们永远不需要显式地模拟交换，问题就会变得简单得多。 将元素移动到前面所需的交换次数正是其索引。 将元素移到后面所需的交换次数恰好是`(n - 1 - index)`。 

这将问题转化为选择最大和最小高度的正确出现。 

我们选择：

 1. 最大高度最左边出现的位置。 
2. 最小高度最右边出现的位置。 

最左边的最大值最大限度地减少了将其置于前面所需的交换。 最右边的最小值最大限度地减少了将其放到后面所需的交换。 

这两个运动之间存在一种相互作用。 如果最大值从最小值的右侧开始，则将最大值移到前面将使最小值向右移动一步。 这意味着最小值现在距离终点更近了一步，因此我们从总数中减去一。 

这一观察结果将整个问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取士兵人数和身高列表。 
2. 找到最左边出现的最大高度。 

该士兵需要最少的交换才能到达前线。 
3. 找到最右边出现的最小高度。 

这位士兵需要最少的交换才能到达终点。 
4. 计算将最大士兵移动到前线所需的交换。 

如果最大值位于索引处`max_pos`，成本很简单`max_pos`。 
5. 计算将最少的士兵移动到最后所需的交换次数。 

如果最小值位于索引处`min_pos`，成本为`(n - 1 - min_pos)`。 
6. 检查是否`max_pos > min_pos`。 

如果为 true，则在向左移动时最大值会越过最小值。 这会将最小的位置向右移动，将其到末尾的剩余距离减少一次交换。 
7. 在这种情况下减一。 
8. 打印最终总计。 

### 为什么它有效

 相邻的交换每次只能改变一步，因此移动一名士兵所需的交换次数等于移动的距离。 

选择最左边的最大值可以保证所有身高最高的士兵中与前方的距离尽可能最小。 选择最右边的最小值可以保证所有身高最小的士兵到后面的距离尽可能小。 

当最大值开始于最小值的右侧时，两个操作之间的唯一依赖关系发生。 在这种情况下，向左移动最大一步会自动向右移动最小一步。 考虑到这种单一重叠会产生确切的最小交换次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

max_height = max(a)
min_height = min(a)

max_pos = a.index(max_height)

min_pos = -1
for i in range(n):
    if a[i] == min_height:
        min_pos = i

answer = max_pos + (n - 1 - min_pos)

if max_pos > min_pos:
    answer -= 1

print(answer)
```该解决方案首先使用 Python 的内置函数识别最高和最矮的高度`max`和`min`。 

对于最大位置，`a.index(max_height)`自动返回第一个出现的位置，这正是我们想要的。 

对于最小位置，我们不能使用`index`，因为这会给出第一次出现而不是最后一次出现。 相反，我们扫描数组并不断覆盖`min_pos`每当我们看到最小值时。 循环结束后，`min_pos`存储最右边的出现。 

公式：```
max_pos + (n - 1 - min_pos)
```独立计算掉期。 

调整：```
if max_pos > min_pos:
    answer -= 1
```处理由于首先移动最大士兵而导致的重叠。 

这个条件很容易出错。 仅当最大值最初位于最小值的右侧时，我们才进行减法。 如果最大值已经位于最小值的左侧，则这两个运动不会干扰。

import sys, io

def solve():
    input = sys.stdin.readline

 ## 边缘情况

 考虑所有士兵身高相同的情况。 

输入：```
5
7 7 7 7 7
```最左边的最大值位于索引处`0`，最右边的最小值位于索引处`4`。 

计算变为：```
0 + (4 - 4) = 0
```不需要交换，因为第一个士兵已经是最大高度的士兵，而最后一个士兵已经是最小高度的士兵。 

现在考虑重复的最小值。 

输入：```
5
2 1 2 1 2
```正确的选择就是最正确的`1`在索引处`3`。 

该算法计算：```
max_pos = 0
min_pos = 3
answer = 0 + (4 - 3) = 1
```如果我们错误地使用了第一个`1`，我们会得到：```
0 + (4 - 1) = 3
```这并不是最小的。 

最后，考虑重叠的情况。 

输入：```
5
1 3 2 4 5
```最高的士兵`5`从索引开始`4`，以及最矮的士兵`1`从索引开始`0`。 

原始交换计数为：```
4 + 4 = 8
```但移动`5`向左移动`1`自动向右一次。 真正的最小值是：```
8 - 1 = 7
```该算法使用以下条件检测这一点：```
if max_pos > min_pos:
    answer -= 1
```它正确地处理了两个运动之间的相互作用。
