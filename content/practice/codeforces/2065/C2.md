 ## 解决方案
 ## 问题理解

 我们得到一个数组`a`和另一个数组`b`。 对于每个位置`a`，我们有一个类似二元的选择：我们可以离开`a[i]`不变或将其替换为通过选择某个元素获得的转换值`b[j]`和计算`b[j] - a[i]`。 每个索引在这个决策上都是独立的，但是所有选择后的最终序列必须按非降序排序。 

关键的困难在于每个位置不仅仅只有一种选择，它有多达`m + 1`可能性：原始值，以及`m`转变的价值观。 既然两者`n`和`m`可以达到`2⋅10^5`在测试用例中，枚举每个位置的所有可能性是不可能的。 即使考虑所有对也会导致二次行为，这远远超出了限制。 

当转换后的值变为负值或明显小于原始值时，会出现微妙的边缘情况。 天真的贪婪策略（例如总是在每个位置选择最小的可能值）会破坏排序约束，因为局部最优选择可能会破坏未来的可行性。 

例如，如果`a = [5, 4]`和`b = [10, 1]`，那么对于`a[1] = 5`，选择`1 - 5 = -4`看起来很有吸引力，但它可能会阻止有效的转换`a[2]`。 依赖性是全局的，而不是局部的。 

核心挑战是决定对于每个位置，是选择原始值还是变换后的值，使得结果序列可以是非递减的。 

## 方法

 暴力方法将对待每个`a[i]`作为有`m + 1`候选值并尝试所有组合。 即使忽略指数性质，生成所有候选者也已经花费了成本`O(nm)`时间，并且检查所有组合是不可能的。 

需要更结构化的观察：转换后的值具有以下形式`b[j] - a[i]`，这线性取决于`a[i]`并按以下元素移动`b`。 我们不应该考虑每个指数的选择，而应该考虑保持先前选择的值的可行性。 

假设我们从左到右处理数组并跟踪可以分配给当前位置的最小可能值，同时保持序列不递减。 对于每个`a[i]`，我们需要知道是否可以选择一个值`>= prev`。 

在位置`i`，我们有两类候选人：

 1.原值`a[i]`如果至少是`prev`。 
2. 价值的转变`b[j] - a[i]`，这也必须至少是`prev`， 意义`b[j] >= prev + a[i]`。 

这将问题简化为查找是否存在`b[j]`足够大以满足不等式。 如果我们排序`b`，我们可以二分查找最小的有效值`b[j]`。 

在每个位置，我们选择两个选项中最小的可行值。 这种贪婪的选择之所以有效，是因为保持运行值尽可能小可以最大限度地提高满足未来约束的机会。

 ## 算法演练

 1. 数组排序`b`。 排序是必要的，这样我们才能有效地查询是否有合适的`b[j]`对于给定的阈值存在。 
2. 初始化变量`prev`到一个非常小的值，表示结果序列中最后选择的最小值。 
3. 迭代每个元素`a[i]`从左到右。 
4. 尽量保持`a[i]`如果满足则不变`a[i] >= prev`。 这保留了原始值并避免了不必要的转换。 
5.检查是否可以转型`a[i]`。 我们需要一个`b[j]`这样`b[j] - a[i] >= prev`，这相当于`b[j] >= prev + a[i]`。 
6. 使用二分查找`b`找到最小索引，其中`b[j] >= prev + a[i]`。 如果存在这样的索引，则计算转换后的值`b[j] - a[i]`。 
7. 如果两个选项都存在，请选择较小的结果值，因为它为将来的元素留下了更多空间。 
8. 如果两个选项都无效，则立即返回失败，因为没有延续可以满足排序约束。 
9. 更新`prev`到所选值并继续。 

关键的想法是，在每一步中，我们都维护尽可能小的有效前缀结束值。 

### 为什么它有效

 在任意索引处`i`，算法保持不变式`prev`是前缀有效转换可实现的最小可能值`a[1..i-1]`。 在任何步骤选择较大的值只会限制未来的可行性，因为所有约束都是“下一个值必须至少是前一个值”的形式。 因此，如果存在有效的解决方案，则总有一个可以保持`prev`每一步都最小化。 这使得贪婪选择成为最优：任何增加的替代选择`prev`只能减少或消除未来的选择，而永远不会扩大它们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        b.sort()
        prev = -10**30
        
        ok = True
        
        for x in a:
            best = None
            
            # option 1: keep original
            if x >= prev:
                best = x
            
            # option 2: transform
            # need b[j] >= prev + x
            import bisect
            idx = bisect.bisect_left(b, prev + x)
            if idx < m:
                cand = b[idx] - x
                if best is None or cand < best:
                    best = cand
            
            if best is None:
                ok = False
                break
            
            prev = best
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```实现从排序开始`b`启用二分搜索。 变量`prev`跟踪构造序列中最后选择的值。 对于中的每个元素`a`，我们评估形成有效值的两种可能方式：保持不变或使用最小可行值对其进行转换`b[j]`。 

二分搜索步骤是关键的优化。 它确保我们不会扫描所有元素`b`对于每个职位。 选择较小的有效候选者可以为后面的元素保留灵活性。 

一个微妙的实现细节是初始化`prev`到一个非常小的数字，以便始终不受限制地考虑第一个元素。 另一个是仔细处理不存在有效转换的情况，必须立即终止测试用例。

 ## 边缘情况

 第一个边缘情况是当`a`已经排序了。 在这种情况下，算法总是倾向于保留原始值，因为它保证在每一步都是有效的。 自从`prev`仅增加或保持相等，不会触发不必要的转换。 

当所有元素都必须转换时，会出现另一种边缘情况。 For instance, when`a`严格递减并且`b`包含足够大的值，可行性完全取决于二分查找的正确性。 该算法通过始终选择最小的有效变换值来处理此问题，确保单调构造。 

最后一个重要的情况是当没有`b[j]`满足某些指标所需的阈值。 在这种情况下，二分查找返回的位置等于`m`，并且算法正确地提前终止。 这可以防止错误的继续，尽管前缀已经不可能，但后面的元素仍将被处理。
