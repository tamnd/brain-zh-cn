 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个位置最初包含一个固定值。 对于每个位置，我们都可以进行一种可选的转换：我们可以用从单个固定数字中减去该位置的值来替换该位置的值。 因为这是简单版本，所以该固定数字是第二个数组中的唯一元素，因此每个转换后的值都来自独立应用于每个位置的相同公式。 

任务是决定在为每个索引选择是保留原始值还是用转换后的对应值替换它之后，是否可以排列结果数组，使其从左到右不递减。 

关键是每个索引都有两个可能的最终值，并且我们可以为每个索引独立选择，但这些选择通过排序要求进行交互。 因此，该结构不是关于重新排列元素，而是关于在阵列中选择一致的配置。 

输入大小很大，测试用例的总数组长度高达 200,000。 这排除了尝试所有组合或重复检查每个部分分配的可行性的任何二次方法。 即使每个测试用例对多个候选数组进行排序也可以，但是对这两个选择的任何指数或每个元素回溯都会失败。 

当局部“好的”选择阻碍了未来的灵活性时，就会出现微妙的失败案例。 例如，在某个索引处选择两个值中较小的一个可能会在以后强制执行不可能的约束。 

考虑这样的情况：```
a = [5, 1, 4], b = [10]
```每个元素要么变成它自己，要么变成`10 - a[i]`。 索引 0 处的贪婪选择可能会选择 5 或 5，但稍后的选择可能会使序列变得不可能，即使不同的早期选择会成功。 这表明我们不能纯粹通过局部最小化或最大化来决定每个位置，而不跟踪与先前决策的兼容性。 

## 方法

 暴力解决方案会尝试所有$2^n$选择是否变换每个元素的方法。 对于每个配置，我们将检查结果数组是否已排序。 这显然是正确的，因为它列举了所有可能性，但它呈指数爆炸，即使对于$n = 30$。 

关键的观察是每个元素只有两个候选值，我们只关心维护全局顺序约束。 这将问题变成了一个顺序可行性过程：在每个索引处，我们必须选择一个至少与之前选择的值一样大的值。 

由于每个位置最多提供两个选项，因此我们可以贪婪地维持每一步可以放置的最小有效值。 在索引处$i$，我们考虑两个候选者，对它们进行排序，并选择仍然 ≥ 先前选择的值的最小者。 如果两者都不起作用，则配置失败。 

这是有效的，因为延迟选择只会增加对未来元素的限制，并且总是选择最小的可行值，为以后的位置留下最大的空间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 贪心选择| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个元素$a_i$，计算它的两个可能值：原始值$a_i$，以及变换后的值$b_1 - a_i$。 

这给出了每个位置的大小为 2 的局部选择集。 
2. 对这两个值进行排序，以便我们始终可以先尝试较小的选项。 

这种排序很重要，因为我们希望为以后的索引保留灵活性。 
3. 维护一个变量`prev`，表示为最终数组中的前一个索引选择的值。 将其初始化为一个非常小的数字。 
4. 从左到右迭代数组。 在每个索引处，按升序检查两个候选值。 
5. 选择 ≥ 的最小候选者`prev`。 

原因是，任何在此使用较大值的有效解决方案都可以替换为较小的可行解决方案，而不会损害未来的可行性。 
6. 如果两个候选者都不≥`prev`，那么就不可能维持非递减顺序，所以我们停止并返回失败。 
7. 如果我们成功地为每个索引分配一个值，则该数组可以在允许的操作下进行排序。 

### 为什么它有效

 在每一步，算法都保持不变式：`prev`是在保持前缀有效的情况下在该位置可实现的最小可能值。 由于每个位置仅通过单个不等式约束来限制下一个位置，因此选择最小的可行值永远不会减少未来指数的解空间。 任何在某个位置选择较大有效值的解决方案只会使以后的约束变得更困难或相等，而绝不会更容易，因此用较小的有效选择替换它可以保留可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        x = b[0]

        prev = -10**30
        ok = True

        for v in a:
            c1 = v
            c2 = x - v

            if c1 > c2:
                c1, c2 = c2, c1

            if c1 >= prev:
                prev = c1
            elif c2 >= prev:
                prev = c2
            else:
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案独立处理每个测试用例，始终读取单个值`b`作为变换常数。 对于每个元素，它计算两种可能的结果，并使用运行中的方法强制执行非递减条件`prev`临界点。 

一个微妙的实现细节是初始化`prev`到一个非常小的数字而不是零，因为转换后的值可能会变成负数。 另一个重要的细节是始终对两个候选值进行排序，确保我们首先尝试最小的可行值。

 ## 边缘情况

 一种边缘情况是所有转换后的值都小于原始值。 例如，如果$b_1$很小并且$a_i$很大，那么很多变换后的值都是负数。 该算法仍然可以处理这个问题，因为它总是与`prev`，经过早期步骤后可能已经为负值。 

另一种情况是，早期选择较小的值会导致稍后失败。 例如，如果早期索引具有非常小的变换值和稍大的原始值，则选择较小的索引可能不会留下有效的延续。 贪心规则避免了这种情况，因为它只在仍然可行时选择较小的值，而不会在阻止未来约束时选择较小的值。 

最后一个边缘情况是两个选择相同。 在这种情况下，任一分支都是有效的，并且算法自然会以相同的方式对待它们，因为排序对于可行性并不重要。
