 ## 解决方案
 ## 问题理解

 我们有一个有向图`n`顶点和`m`边缘。 原始图保证是强连接的，这意味着每个顶点都可以使用给定的边到达每个其他顶点。 我们必须准确地保留`k`删除这些边缘并删除其余部分。 目标是使剩余的图具有尽可能多的强连通分量。 输出是组件的最大数量和一组有效的`k`实现它的边缘索引。 

关键的限制是`k`小于`n`。 由于每个顶点都已经是一个可能的独立强连通分量，因此绝对最大答案是`n`。 问题是我们是否总是可以选择`k`边，而不会意外地创建有向循环。 

和`n`最多`100000`和`m`最多`200000`，任何尝试许多边子集或重复重新计算 SCC 的解决方案都会太慢。 需要一种在图表大小上接近线性的解决方案，因为在典型的竞赛设置中只有几百万个可用操作。 

一个常见的错误是选择任意边。 例如：```
3 3 2
1 2
2 3
3 1
```正确的输出是：```
3
1 2
```因为边缘`1 -> 2`和`2 -> 3`形成一个有向链，所以每个顶点都是它自己的SCC。 边缘的不小心选择`1`和`3`创建循环`1 -> 2 -> 3 -> 1`在这里不可能，因为边缘`2`缺失，但选择所有三个边显然会形成一个 SCC。 重要的细节是所选择的边必须避免循环。 

另一个边缘情况是`k = 0`。```
5 5 0
1 2
2 3
3 4
4 5
5 1
```正确的输出是：```
5
```空图在不同顶点之间没有路径，因此每个顶点都是一个单独的 SCC。 总是尝试输出至少一个边缘的实现将会失败。 

最后的边缘情况是当图很密集并且每个顶点都有许多传入和传出边缘时。 例如：```
4 6 3
1 2
2 3
3 4
4 1
1 3
2 4
```正确答案仍然是`4`。 密度并不重要。 我们只需要一个小的非循环边子集，而不是稀疏图。 

## 方法

 直接方法会尝试不同的组`k`边并计算每个选择的 SCC 计数。 这是正确的，因为检查每个可能的子集可以保证找到最好的子集。 然而，选择的数量是`C(m, k)`，即使对于小图来说，它也会变得巨大。 每次选择后都运行 SCC 算法是不可能的。 

有用的观察来自于原始图是强连通的这一事实。 从任何顶点开始，DFS 都可以到达其他所有顶点。 DFS 树恰好包含`n - 1`边，并且这些边总是形成从父级到子级的有向树。 树没有有向循环，因此该树中的每个顶点都是其自己的 SCC。 

自从`k < n`，我们可以取任何`k`此 DFS 树的边。 结果图仍然是非循环的，这意味着它恰好具有`n`强连通分量。 这已经是理论上的最大值，因此不需要更复杂的优化。 

蛮力之所以有效，是因为它探索了所有可能的剩余图，但由于搜索空间巨大而失败。 DFS 树观察将问题从在所有边子集之间搜索简化为构造一个有保证的最优子集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(m, k) * (n + m)) | O(C(m, k) * (n + m)) | O(n + m) | 太慢了|
 | 最佳| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1.从任意顶点运行DFS，例如vertex`1`。 每当 DFS 通过边访问新顶点时，将该边记录为 DFS 树的一部分。 该图是强连通的，因此该过程将访问所有顶点。 
2. 采取第一个`k`记录DFS树的边并输出它们的索引。 这些是必需的边，因为它们来自非循环结构。 
3.如果`k`为零时，输出零所选边缘。 空图已经给出了 SCC 的最大数量。 

为什么它有效：

 选定的边是 DFS 树的子集。 该树中的每条边都从父顶点指向子顶点。 跟随选定的边只能沿着树向下移动，因此返回到已经访问过的顶点是不可能的。 所选图是 DAG。 在 DAG 中，没有两个不同的顶点可以相互可达，因此每个顶点都形成自己的 SCC。 因此答案是`n`，这是 SCC 的最大可能数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    graph = [[] for _ in range(n)]

    for i in range(1, m + 1):
        u, v = map(int, input().split())
        graph[u - 1].append((v - 1, i))

    ans = []
    seen = [False] * n

    sys.setrecursionlimit(300000)

    def dfs(u):
        seen[u] = True
        for v, idx in graph[u]:
            if not seen[v]:
                ans.append(idx)
                if len(ans) == k:
                    return True
                if dfs(v):
                    return True
        return False

    if k > 0:
        dfs(0)

    print(n)
    if k:
        print(*ans)

if __name__ == "__main__":
    solve()
```邻接列表存储目标顶点和原始边索引，因为输出需要边编号而不是端点。 

DFS 在第一次发现新顶点时准确地记录一条边。 这使得记录的边成为图的可达部分的生成树。 因为图是强连通的，从顶点开始`0`到达每个顶点。 

一旦递归停止`k`收集边缘。 这是安全的，因为唯一的目标是输出任何有效的最优子集，而不一定是整个树。 条件`k < n`保证 DFS 树始终包含足够的边。 

施工后无需进行SCC计算。 该证明已经保证所选边形成 DAG，从而获得最大可能的答案。 

## 工作示例

 对于第一个样本：```
4 5 1
1 2
2 3
1 4
4 3
3 1
```一种可能的 DFS 遍历从顶点开始`1`。 

| 步骤| 当前顶点 | 选定的边缘 | 选定的边 |
 | ---| ---| ---| ---|
 | 1 | 1 | 1 -> 2 | 1 -> 2 1 |

 算法停止是因为`k = 1`。 

所选图形仅包含边`1 -> 2`。 不存在循环，因此所有四个顶点都是单独的 SCC。 答案是`4`。 

对于自定义示例：```
5 5 3
1 2
2 3
3 4
4 5
5 1
```DFS 树遵循循环，直到发现所有顶点。 

| 步骤| 当前顶点 | 选定的边缘 | 选定的边 |
 | ---| ---| ---| ---|
 | 1 | 1 | 1 -> 2 | 1 -> 2 1 |
 | 2 | 2 | 2 -> 3 | 2 -> 3 | 1 2 |
 | 3 | 3 | 3 -> 4 | 3 -> 4 1 2 3 | 1 2 3

 选定的边创建链`1 -> 2 -> 3 -> 4`。 顶点`5`与所选子集断开连接，但这是允许的。 没有循环，所以每个顶点仍然是一个独立的 SCC，答案是`5`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) | 每个顶点和边在 DFS 期间最多处理一次 |
 | 空间| O(n + m) | 邻接表和 DFS 状态数组存储图 |

 这些限制允许线性遍历，因为`n`和`m`两者最多都是几十万。 该算法只存储输入图和少量的DFS状态。

 ## 边缘情况

 当`k = 0`，算法跳过 DFS 选择并仅打印`n`。 这与空有向图没有非平凡 SCC 的事实相匹配。 对于具有五个顶点且没有选定边的示例，答案是`5`。 

什么时候`k`接近于`n`，DFS 树仍然提供足够的边，因为每个生成树都恰好有`n - 1`边缘。 对于一个图表`n = 5`和`k = 4`，算法可以输出所有四个树边，并且所选图仍然是非循环的。 

当原始图包含许多循环时，这些循环将被忽略。 例如，在包含以下内容的图中`1 -> 2 -> 3 -> 1`，DFS树可能只选择`1 -> 2`和`2 -> 3`。 删除的后边缘正是将顶点合并到一个 SCC 中的边缘，因此排除它即可得到最佳结果。
