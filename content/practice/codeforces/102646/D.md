 ## 解决方案
 ## 问题理解

 该问题模拟了篮球队的选择过程。 有`n`玩家按固定顺序站立，并且玩家`i`有技能值`a[i]`。 我们必须准确选择`k`玩家同时保留原来的顺序。 第一个选择的玩家将获得乘数`b[1]`，第二个接收`b[2]`， 等等。 目标是最大化总贡献，即所选玩家的技能乘以分配的乘数的总和。 

输入为玩家提供了阵容顺序和`k`乘数描述团队中每个选定位置的价值。 输出是选择最佳玩家子序列后可能的最大总价值。 

主要限制是`n <= 1000`。 这个值足够小，二次动态规划是可行的。 解决方案围绕`O(n^2)`很舒服，但尝试每一种可能的设置`k`玩家是不可能的，因为子序列的数量是组合增长的。 的价值观`a[i]`和`b[i]`可以达到`100000`，所以答案可以是`10^13`，这意味着实现必须使用 64 位整数。 Python integers already handle this range.

 微妙之处在于，最好的玩家不一定是技能值最大的。 A player with a large skill value may be more valuable when assigned to a larger multiplier later, while a smaller player may need to be kept for an earlier position. 排序约束阻止简单地对玩家进行排序。 

例如：```
Input:
3 2
10 1 10
1 100

Output:
1010
```按技能对玩家进行排序的粗心解决方案可能会选择两名具有技能的玩家`10`，这恰好在这里起作用，但推理不完整。 重要的部分是将第二个乘数分配给第一个选定玩家之后的选定玩家。 有效的选择是子序列，而不是任意组。 

当乘数相差很大时，会出现另一种边缘情况：```
Input:
3 2
100 50 1
1 100

Output:
5100
```选择前两名球员给出`100 * 1 + 50 * 100 = 5100`。 将最大技能与最大乘数配对并忽略位置的贪婪方法可能会尝试使用第一和第三玩家，给出`100 * 1 + 1 * 100 = 200`，这更糟。 

最小可能的情况也需要注意：```
Input:
1 1
7
9

Output:
63
```只有一种可能的选择。 任何假设至少有一名跳过玩家的 DP 初始化都可能在此处失败。 

## 方法

 直接的暴力方法是枚举每一个可能的组`k`玩家同时保持原来的顺序。 对于每个选定的子序列，我们通过将第一个选定的技能乘以来计算贡献`b[1]`，第二个由`b[2]`， 等等。 这是正确的，因为它会检查每个有效的团队。 

问题是可能的团队数量。 从`n`玩家，有多种方式可供选择`k`是`C(n, k)`。 什么时候`n = 1000`，这可能是一个天文数字。 即使评估一支球队只需要`k`算起来，总的工作量仍然远远超出了限制。 

关键的观察结果是，从左到右扫描玩家时唯一重要的信息是已经选择了多少名玩家。 如果我们已经处理了阵容的一些前缀并选择了`j`球员，这些选定球员的确切身份不再重要，除非通过实现的最佳总价值。 这种重叠的子问题结构自然会导致动态规划。 

蛮力方法之所以有效，是因为考虑了每一个可能的决定，但它多次重复几乎相同的部分选择。 观察到具有相同处理前缀和相同数量选定球员的两支球队只需要更好的分数，让我们将所有这些可能性压缩到一个小状态。 

我们定义`dp[j]`作为处理某些玩家前缀并准确选择后可能的最高分数`j`玩家。 当考虑新玩家时，我们要么忽略他们，要么将他们用作`(j+1)`-th 选择的玩家。 向后更新状态允许我们只存储一个数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n,k) * k) | O(C(n,k) * k) | O(k) | 太慢了|
 | 最佳| O(nk) | O(nk) | O(k) | 已接受 |

 ## 算法演练

 1. 初始化`dp[0] = 0`而其他所有状态都是不可能的。 国家`dp[j]`代表准确选择后的最佳分数`j`到目前为止处理过的玩家中的玩家。 
2. 从左到右对玩家进行一一处理。 对于当前有技能值的玩家`x`，尝试将他们指定为下一个选定的玩家。 
3. 更新选择计数`k-1`下降到`0`。 如果`j`球员已经被选择，选择当前球员会给出新的值`dp[j] + x * b[j+1]`。 

相反的顺序是必要的，因为当前玩家只能被选择一次。 从小事开始更新`j`到大`j`将允许同一玩家在一次迭代中多次贡献。 
4、处理完所有玩家后，答案是`dp[k]`，因为这种状态代表恰好选择了所需数量的玩家。 

不变量是在处理阵容的任何前缀之后，`dp[j]`包含所有精确选择方式中可能的最佳值`j`来自该前缀的玩家。 忽略当前玩家会使所有旧状态保持有效。 选择当前玩家可以扩展每个有效状态`j`选择的玩家进入有效状态`j+1`选定的球员。 由于这是仅有的两个可能的决定，因此会考虑每个有效的团队并保留最好的分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    neg = -10**30
    dp = [neg] * (k + 1)
    dp[0] = 0

    for x in a:
        for j in range(k - 1, -1, -1):
            if dp[j] != neg:
                dp[j + 1] = max(dp[j + 1], dp[j] + x * b[j])

    print(dp[k])

if __name__ == "__main__":
    solve()
```数组`dp`仅存储每个可能数量的所选玩家的当前最佳值。 不可能状态从非常小的数字开始，因此它们永远不会成为有效的最大值。 

当处理一个玩家时，循环开始于`k - 1`并向下移动。 已选择后选择当前玩家的乘数`j`玩家是`b[j]`因为Python使用从零开始的索引，所以`b[0]`是第一个选择的玩家的乘数。 

案件无需单独办理`n = k`。 DP 自然会迫使答案使用每个玩家，因为最终状态必须准确包含`k`选择。 

答案可能会超出 32 位整数限制，因为最大贡献可能约为`1000 * 100000 * 100000`，即`10^13`。 Python 整数避免了溢出问题。

 最终状态是`dp[2] = 7`，通过选择球员来实现`2`和`3`。 这展示了 DP 如何保留不同的可能选择，而不是立即致力于最大的单一技能。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(nk) | O(nk) | 每个`n`玩家最多更新`k`民主党指出。 |
 | 空间| O(k) | 仅存储当前选定玩家的数量。 |

 和`n <= 1000`和`k <= n`，最大转换次数约为一百万。 这很容易符合典型的比赛限制，但队伍的暴力数量太大。

 ## 边缘情况

 处理乘数大小差异很大的情况是因为 DP 不会立即决定玩家的角色。 为了：```
3 2
100 50 1
1 100
```处理前两个玩家后的状态包含接受两个玩家的可能性，给出`100 * 1 + 50 * 100 = 5100`。 该算法保持这种状态，而不是用仅基于技能的贪婪选择替换它。 

单人游戏的情况：```
1 1
7
9
```开始于`dp[0] = 0`。 唯一的转变创造`dp[1] = 63`，这是所需的答案。 不存在无效访问，因为更新循环正确地停止在`k - 1`。 

等值情况：```
4 3
5 5 5 5
2 2 2
```拥有众多最优团队。 DP 处理这个问题是因为它存储的是最佳分数而不是确切选择的索引。 任意三名玩家的总分相同`30`，所以最终状态仍然正确。
