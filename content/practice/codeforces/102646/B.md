 ## 解决方案
 ## 问题理解

 任务是将两个数字队列合并到一个数组中。 唯一允许的操作是从任一队列中取出当前的第一个元素并将其附加到答案中。 每个原始数组的内部顺序不能改变。 在所有可能的合并数组中，我们需要字典序最小的一个。 两个输入数组一起包含来自`1`到`2n`恰好一次，这意味着每个值都是唯一的。 

主要困难在于局部较小的第一个元素并不总是足够的。 如果两个数组当前都公开较大的值，则正确的选择取决于比较两个数组的剩余后缀。 例如，选择`5`超过`6`如果数组以以下开头，则不一定是最佳的`6`继续使用更小的值。 

每个数组的长度可以达到`100000`，所以元素总数为`200000`。 尝试所有可能合并的方法是不可能的，因为有效交错的数量是指数级的。 即使每次都逐个字符地比较后缀也会降级为二次行为，这对于这种输入大小来说太慢了。 

重要的边缘情况来自后缀比较。 如果一个数组用完，则必须复制剩余的数组，因为不再有选择。 例如：```
1
A = [3]
B = [1]
```答案是：```
1 3
```仅检查第一个元素的贪婪解决方案在这里有效，但在更复杂的情况下会失败。 

另一种情况是普通字符串问题中第一个元素相等。 这里，排列属性防止两个数组中的值相等，但假设它始终只能比较一个元素的解决方案将失败：```
n = 3
A = [6, 10, 4]
B = [9, 8, 11]
```正确答案开始于`6`，因为后缀`[6,10,4]`小于`[9,8,11]`。 选择错误后，不能通过查看后面的要素来做出决定。 

## 方法

 蛮力的想法是生成所有可能的选择序列。 每时每刻我们都可以从中汲取`A`或来自`B`，所以可能的合并数量为：$$\binom{2n}{n}$$为了`n = 100000`，这远远超出了任何实际限制。 即使存储这些可能性的一小部分也是不可能的。 

更合理的贪心想法是始终选择当前较小的前部元素。 这还不够。 考虑剩余数组所在的决策点：```
A = [4, 100]
B = [5, 1]
```服用`4`首先看起来是正确的，但如果我们有：```
A = [4, 100]
B = [4?]
```我们需要比较较长的零件。 在这个问题中，不可能出现相等的值，但是相同的原则仍然存在：下一个选择取决于整个剩余的后缀。 

关键的观察是，在任何时候，最佳移动都是采用字典顺序较小的剩余后缀。 如果`A[i:] < B[j:]`，取自`A`总是安全的，因为每一个未来的元素`A`停留在其余元素的前面`B`直到我们另有决定为止。 如果我们首先从较大的后缀中获取，则两个后缀不同的第一个位置立即给出更糟糕的答案。 

剩下的挑战是有效地比较后缀。 我们使用小于每个元素的分隔符值连接两个数组，并为所有后缀建立排名。 前缀加倍使这些排名在`O(n log n)`时间。 那么每次后缀比较就变成了恒定时间的排名比较。 前缀加倍构建越来越长的前缀的字典顺序，直到每个后缀都有唯一的排名。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(2n,n)) | O(C(2n,n)) | O(2n) | O(2n) | 太慢了|
 | 直接比较后缀 | O(n²) | O(1) | O(1) | 太慢了|
 | 后缀排名+贪婪合并| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建一个组合数组`S = A + [0] + B`。 价值`0`充当分隔符，因为所有实数值都是正数。 我们仅使用该数组来比较后缀，而不是创建答案。 
2. 计算每个后缀的字典顺序`S`使用前缀加倍。 每个等级告诉我们哪个后缀更小。 
3. 保留两个指针，`i`对于当前位置`A`和`j`对于当前位置`B`。 
4. 当两个数组仍然有元素时，比较从以下位置开始的后缀的排名`i`在`A`和`j`在`B`。 附加较小后缀的第一个元素并将其指针向前移动。 
5. 当一个数组为空时，直接追加另一个数组的剩余元素。 没有更多的决定需要做出。 

贪婪选择起作用的原因是两个候选后缀之间的第一个不同位置决定了以这些后缀开头的每个合并的字典顺序。 选择较小的后缀可以保留最佳的第一个未确定位置，并且在删除一个元素后重复此参数可以证明每个选定的元素都是最佳合并的一部分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_ranks(arr):
    n = len(arr)
    vals = {v: i for i, v in enumerate(sorted(set(arr)))}
    rank = [vals[x] for x in arr]
    k = 1

    while k < n:
        order = list(range(n))
        order.sort(key=lambda x: (rank[x], rank[x + k] if x + k < n else -1))

        new_rank = [0] * n
        for idx in range(1, n):
            a = order[idx - 1]
            b = order[idx]
            if (rank[a], rank[a + k] if a + k < n else -1) != (
                rank[b],
                rank[b + k] if b + k < n else -1,
            ):
                new_rank[b] = new_rank[a] + 1
            else:
                new_rank[b] = new_rank[a]

        rank = new_rank
        k <<= 1

    return rank

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    combined = A + [0] + B
    rank = build_ranks(combined)

    ans = []
    i = 0
    j = n + 1

    while i < n and j < 2 * n + 1:
        if rank[i] < rank[j]:
            ans.append(A[i])
            i += 1
        else:
            ans.append(B[j - n - 1])
            j += 1

    while i < n:
        ans.append(A[i])
        i += 1

    while j < 2 * n + 1:
        ans.append(B[j - n - 1])
        j += 1

    print(*ans)

if __name__ == "__main__":
    solve()
```这`build_ranks`函数是后缀比较引擎。 最初，每个后缀仅按其第一个值进行排名。 每个加倍步骤使用当前块的排名和下一个块的排名对后缀进行排序。 经过足够的迭代后，Rank 数组完全代表了后缀顺序。 

分隔符值`0`小于每个实数，因此它可以安全地分离两个数组。 因为原始数组中的所有数字都是不同的，所以后缀来自`A`不能是后缀的前缀`B`，因此分隔符不会创建不正确的比较。 

合并循环维护两个指针。 指针为`B`开始于`n + 1`因为第二个数组在组合数组中的分隔符之后开始。 比较使用预先计算的排名而不是扫描值，避免重复工作。 

Python 整数不会溢出，并且代码永远不会创建指数数量的可能合并。 唯一微妙的部分是保持分隔符索引以及组合数组索引和`B`指数正确。

import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    n = int(sys.stdin.readline())
    A = list(map(int, sys.stdin.readline().split()))
    B = list(map(int, sys.stdin.readline().split()))

    combined = A + [0] + B

    def build_ranks(arr):
        n = len(arr)
        rank = [x for x in arr]
        k = 1
        while k < n:
            order = sorted(range(n), key=lambda x: (rank[x], rank[x+k] if x+k < n else -1))
            nr = [0] * n
            for a, b in zip(order, order[1:]):
                nr[b] = nr[a] + ((rank[a], rank[a+k] if a+k < n else -1) != (rank[b], rank[b+k] if b+k < n else -1))
            rank = nr
            k *= 2
        return rank

    r = build_ranks(combined)
    ans = []
    i, j = 0, n + 1

    while i < n and j < 2*n + 1:
        if r[i] < r[j]:
            ans.append(A[i])
            i += 1
        else:
            ans.append(B[j-n-1])
            j += 1

    ans += A[i:]
    ans += B[j-n-1:]

    sys.stdin = old
    return " ".join(map(str, ans)) + "\n"

 ## 边缘情况

 当一个数组变空时，该算法不会尝试另一次比较。 为了：```
n = 1
A = [3]
B = [1]
```后缀排名比较选择`B`，生产`1 3`。 在那之后，`B`为空，剩余`3`已附加。 

一个常见的错误是仅比较当前元素。 案例：```
A = [6,10,4]
B = [9,8,11]
```开始于`6 < 9`， 所以`A`被选中。 后来比较发生了变化，因为剩余的后缀发生了变化。 该算法通过使用存储的后缀排名在每次删除后重新计算选择来处理此问题。 

分隔符位置是另一个容易发生错误的地方。 组合数组的索引为：```
A + [0] + B
```所以第一个元素`B`位于索引处`n + 1`。 该实现保留组合索引以进行比较并转换回`B`仅在添加答案元素时才索引。
