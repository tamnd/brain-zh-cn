 ## 解决方案
 ## 问题理解

 我们正在看一堵由`n × n`瓷砖网格。 每块瓷砖都有两种颜色之一：金色或银色。 一家人想要保留一平方大小的区域`k × k`可见并使该可见区域由单一颜色组成。 所选方块内的图块可以用其他颜色替换，目标是选择需要最少替换的方块。 

输入描述了墙的大小、所需的可见正方形大小以及所有图块的当前颜色。 输出是必须更改的最小图块数量，以便某些`k × k`部分墙壁变得均匀。 

约束条件是选择算法的关键。 墙最多可以有`1000 × 1000`瓦片，这意味着可以有一百万个单元。 尝试每个可能的正方形并扫描其所有单元格大约需要`n² * k²`在最坏的情况下工作。 如果有 100 万个单元，则可能需要进行约 1 万亿次操作，远远超出了正常时间限制所允许的范围。 我们需要一种方法来评估每个可能的方块，而无需重新检查每个图块。 

棘手的情况大多与接触边界的方块和已经统一的方块有关。 如果整个可见方块已经具有相同的颜色，则答案必须为零。 

例如：```
Input
3 2
GGG
GGG
SSS

Output
0
```顶部两行包含制服`2 × 2`正方形。 始终假设至少需要更换一次的解决方案将会失败。 

另一种情况是最佳方格不是第一个或最后一个可能的位置：```
Input
5 3
GGGGG
SSSSS
GGGGG
SSSSS
GGGGG

Output
3
```中间`3 × 3`正方形有六块金牌和三块银牌，因此更换三块银牌是最佳选择。 仅检查角落会错过这个答案。 

## 方法

 一个直接的解决方案是尝试每个可能的左上角`k × k`正方形。 For each position, we count how many gold and silver tiles it contains. 如果有`g`金砖和`s`银色瓷砖，使其全部为黄金成本`s`改变并使其全部变成白银成本`g`变化。 该方格的成本是两个值中较小的一个。 

这种方法是正确的，因为它检查每个可能的可见区域。 问题在于重复工作量。 有大约`(n-k+1)²`可能的方格，每个方格包含`k²`瓷砖。 在最坏的情况下，这会变成`O(n²k²)`，这对于`n = 1000`。 

重要的观察结果是相邻的方块严重重叠。 将正方形一列向右移动会删除一列`k`平铺并添加另一列`k`瓷砖。 没有理由重新计算整个广场。 

二维前缀和准确地给出了我们需要的信息。 我们构建一个矩阵，其中每个单元格告诉从原点到该单元格的矩形中存在多少个金块。 然后可以使用四个前缀值在恒定时间内找到任何矩形和。 之后，可以对每个候选方格进行评估`O(1)`时间，制定完整的解决方案`O(n²)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²k²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n²) | O(n²) | 已接受 |

 ## 算法演练

 1. 读取网格并为金块构建前缀和数组。 值在`(i, j)`存储矩形中金块的数量`(1, 1)`到`(i, j)`。 这让我们可以回答任何矩形查询，而无需扫描其单元格。 
2. 迭代每个可能的左上角`k × k`正方形。 右下角是根据左上角位置确定的`k`。 
3. 使用前缀和公式求出当前方格内的金块数量。 银牌的数量是`k * k - gold`。 
4. 计算制作这个方形金币和银币的成本。 较小的值是该方格所需的替换次数。 
5. 保留所有方格中成本最小的并打印出来。 

为什么有效：前缀和不会改变网格的含义，它只存储累积的信息。 检查每个可能的可见方块，并且对于每个方块，我们准确计算其包含每种颜色的图块数量。 由于方块的最小变化数是较小的颜色计数，因此所有检查的方块的最小值是全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n):
        row_sum = 0
        for j in range(n):
            if grid[i][j] == 'G':
                row_sum += 1
            pref[i + 1][j + 1] = pref[i][j + 1] + row_sum

    ans = k * k

    for i in range(n - k + 1):
        for j in range(n - k + 1):
            x1, y1 = i, j
            x2, y2 = i + k, j + k

            gold = (
                pref[x2][y2]
                - pref[x1][y2]
                - pref[x2][y1]
                + pref[x1][y1]
            )

            silver = k * k - gold
            ans = min(ans, gold, silver)

    print(ans)

if __name__ == "__main__":
    solve()
```前缀构造内部使用基于 1 的索引。 这可以避免矩形从第一行或第一列开始的特殊情况，因为网格之前的行和列都用零填充。 

矩形查询减去目标正方形之外的两个矩形，并添加回重叠部分。 这是二维前缀和的标准包含-排除公式。 

循环停止于`n - k + 1`因为正方形不能从其底部或右边缘超出墙外的位置开始。 最终答案开始为`k * k`因为最坏的可能方块需要更换每一块瓷砖。

import io

def solve():

    old = sys.stdin

    return out

 ## 边缘情况

 对于已经统一的情况：```
Input
3 2
GGG
GGG
SSS
```前缀总和报告左上角`2 × 2`正方形包含四个金块和零个银块。 该算法计算`min(0, 4)`作为重置成本，所以答案为零。 

对于最佳方块接触边界的情况：```
Input
4 2
GGSS
GGSS
SSGG
SSGG
```广场起始于`(0,0)`仅包含金色瓷砖，无需更改。 由于额外的零边框，前缀和查询正确包含第一行和第一列，因此无需任何特殊处理即可找到答案。 

对于唯一有效的正方形是整个网格的情况：```
Input
3 3
GSS
SGS
SSG
```只有一名候选人。 前缀总和返回 3 个金块，因此更改为全银需要 3 块，而更改为全金需要 6 块。 该算法输出三个，这是正确的最小值。
