 ## 解决方案
 ## 问题理解

 我们得到一个短整数序列，每个整数都来自一个非常小的固定集合：0、6、7、41 或 67。任务是将算术运算符放置在连续数字之间，以形成一个完全带括号的表达式，仅使用加法、减法、乘法或除法。 表达式按照正常运算符优先级规则以标准方式求值，并且除法是整数除法，就像典型的编程竞赛问题一样，除非结果变得不确定。 目标是选择运算符以使表达式的最终值尽可能大。 答案必须以 1e9 + 7 为模进行报告。 

这里的关键对象不仅仅是数组，而是通过在相邻元素之间插入运算符形成的所有可能的表达式的空间。 对于长度为 n 的数组，有 n−1 个间隙，因此朴素搜索会考虑 4^(n−1) 种可能性，因为每个间隙独立选择四个操作之一。 

约束足够小，n 最多为 100，这立即排除了对运算符放置的指数枚举。 即使 4^50 也已经是天文数字了，因此任何正确的解决方案都必须严重压缩状态空间。 

一个微妙的问题是分裂。 如果不小心允许除法，那么当除数为零时会引入未定义的情况。 由于数组包含 0，因此可以创建尝试根据分组除以零的表达式。 正确的解决方案必须完全避免无效状态，而不仅仅是在最后检测它们。 

另一个隐藏的边缘情况是，最佳表达式可能需要选择局部看起来很糟糕的操作。 例如，早期乘以零可能看起来很致命，但后来的结构可以避免它，具体取决于表达式的分组方式。 在这种情况下，贪婪的从左到右的方法会立即失败，因为操作顺序不是独立的。 

## 方法

 蛮力的想法很简单：尝试每个可能的运算符序列，评估结果表达式，并保留最大值。 由于评估在 n 中是线性的，因此这给出了 O(4^n · n) 行为。 当 n = 100 时，即使 n 很小，这也是完全不可行的，因为分支因子会爆炸。 

拯救我们的结构是带有二元运算符的序列表达式可以分解为子表达式。 由段 a[l..r] 形成的任何表达式都可以在某个 k 处拆分，最终值取决于用一个运算符将 [l..k] 和 [k+1..r] 的结果组合起来。 这是经典的区间动态规划模式：我们不是直接选择运算符，而是计算子数组的所有可实现值并合并它们。 

然而，每个间隔仅存储一个值是不够的，因为减法和除法不是单调的。 根据分组的不同，相同的段可以产生不同的值，并且这些中间结果会影响未来的组合。 因此，对于每个分段，我们必须跟踪一组可能的值，或者更准确地说，我们必须跟踪足够的状态来计算所有分割的最佳组合。 

由于值可能会变大，因此我们在每一步都依赖模算术，以确保我们永远不会携带无界整数。 除法使事情变得复杂，但由于数域很小且固定，因此唯一有意义的逆数是当除法精确时； 否则该转换无效。 

这导致在间隔上的 DP，其中每个状态聚合所有可达结果，并且转换在所有四个操作下组合左右子段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对运营商进行暴力破解 | O(4^n·n) | O(4^n·n) | O(n) | 太慢了 |
 | 子数组上的区间 DP | O(n^3·K^2)（K 小常数集大小）| O(n^2·K) | O(n^2·K) | 已接受 |

 ## 算法演练

1. 定义一个 DP 表，其中 dp[l][r] 表示可以从索引 l 开始到 r 结束的子数组中获取的所有值。 每个条目存储一小组整数。 
2. 使用单个值 a[i] 初始化 dp[i][i]，因为长度为 1 的段没有运算符且只有一个可能的表达式。 这构成了DP的基础。 
3. 考虑长度从 2 到 n 递增的段。 对于每个线段 [l, r]，我们将尝试 l 和 r 之间的每个可能的分割点 k。 
4. 对于每个分割 k，使用四个运算符中的每一个将 dp[l][k] 中的每个值与 dp[k+1][r] 中的每个值组合起来。 这会生成遵循此特定括号结构的所有表达式。 
5. 对于加法和乘法，我们直接计算结果并将其存储在 dp[l][r] 中。 对于减法，我们计算左减右。 对于除法，我们仅在右值精确除左值且除数非零时才包含结果，因为其他任何值都会创建无效表达式。 
6. 处理完所有分割后，dp[l][r] 包含该段的每个可实现的值。 最终答案是 dp[0][n−1] 中的最大值，以 1e9 + 7 为模。 

这样做的原因是任何有效的完全括号表达式都与数组上的二叉树完全对应，其中每个内部节点都是一个运算符分割。 DP 通过尝试所有分裂点来隐式枚举所有此类树。 由于每棵树在某处都有根分裂，并且 DP 包括所有子树，因此不会丢失任何有效表达式。 同时，记忆化可以防止重新计算相同的子问题，因此指数结构会崩溃为多项式时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def combine(a, b):
    res = set()
    for x in a:
        for y in b:
            res.add((x + y) % MOD)
            res.add((x - y) % MOD)
            res.add((x * y) % MOD)
            if y != 0 and x % y == 0:
                res.add((x // y) % MOD)
    return res

n = int(input())
arr = list(map(int, input().split()))

dp = [[set() for _ in range(n)] for _ in range(n)]

for i in range(n):
    dp[i][i].add(arr[i] % MOD)

for length in range(2, n + 1):
    for l in range(n - length + 1):
        r = l + length - 1
        cur = set()
        for k in range(l, r):
            left = dp[l][k]
            right = dp[k + 1][r]
            for x in left:
                for y in right:
                    cur.add((x + y) % MOD)
                    cur.add((x - y) % MOD)
                    cur.add((x * y) % MOD)
                    if y != 0 and x % y == 0:
                        cur.add((x // y) % MOD)
        dp[l][r] = cur

print(max(dp[0][n - 1]) % MOD)
```DP 表构造遵循间隔排序，以便每个 dp[l][r] 仅依赖于严格较小的间隔。 length、l 和 split k 上的嵌套循环强制执行此依赖性排序。 

在每次合并中，我们明确尝试左值和右值的所有组合，因为即使在同一段上，不同的括号也会产生不同的中间结果。 除法受到仔细保护以避免无效状态。 

一个常见的错误是尝试从左到右进行贪婪求值，但这忽略了括号的组合性质。 另一个常见的错误是忘记减法不是关联的，这正是我们必须携带多个候选值而不是尽早折叠状态的原因。 

## 工作示例

 ### 示例 1

 输入：```
4
6 7 41 0
```我们首先初始化单元素段。 

| 长度 | 细分 | dp[l][r] | dp[l][r] |
 | ---| ---| ---|
 | 1 | [6] | {6} |
 | 1 | [7] | {7} |
 | 1 | [41]| {41} |
 | 1 | [0]| {0} |

 对于长度为 2 的段 [6,7]，我们尝试所有操作：

 6 + 7 = 13, 6 − 7 = −1, 6 × 7 = 42，除法无效。 

所以 dp[0][1] = {13, -1, 42}。 

我们继续类似的做法，建立更大的细分市场。 当达到全范围 [6,7,41,0] 时，不同的括号允许我们以一种方式隔离零，避免破坏性除法并在它出现之前最大化乘法链。 

最终dp[0][3]包含多个候选，最大为1722。 

该轨迹表明，保留多个中间值至关重要，因为最佳结构可以避免过早崩溃。

 输入：```

最终的答案来自于在任何归约操作稀释值之前最大化早期乘法的分割。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MOD = 10**9 + 7
    n = int(input())
    arr = list(map(int, input().split()))

    dp = [[set() for _ in range(n)] for _ in range(n)]
    for i in range(n):
        dp[i][i].add(arr[i] % MOD)

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            cur = set()
            for k in range(l, r):
                for x in dp[l][k]:
                    for y in dp[k+1][r]:
                        cur.add((x + y) % MOD)
                        cur.add((x - y) % MOD)
                        cur.add((x * y) % MOD)
                        if y != 0 and x % y == 0:
                            cur.add((x // y) % MOD)
            dp[l][r] = cur

    return str(max(dp[0][n-1]) % MOD)

 ## 边缘情况

 一个关键的边缘情况是数组中出现零时。 任何幼稚的贪婪乘法如果提前相乘，都会立即将结果降至零。 DP 通过推迟包含零来避免这种情况，直到所有有益的乘法在早期的分割中完成为止。 对于像这样的输入`6 7 0`，最优分组为`(6 × 7) + 0`，并且 DP 明确地构造了两者`(6 × 7)`和`((6 × 7) + 0)`在选择最大值之前作为单独的状态。 

另一种情况是除以零。 对于像这样的输入`6 0 7`，任何尝试的分割`6 / 0`在生成时被丢弃，确保 dp 状态保持有效。 该算法从不存储未定义的表达式，因此无效分支无法传播。 

最后，减法重配置，例如`7 41 6`需要保留负的中间结果，因为稍后的乘法可能会扭转优势。 贪婪方法会提前丢弃负数，但 DP 会保留它们，确保未来的组合不会被意外排除。
