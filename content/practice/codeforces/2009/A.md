[CF 2009A - 最小化！](https://codeforces.com/problemset/problem/2009/A)

 **求解时间：** 1m 5s

 ## 解决方案
 ## 问题理解

 我们得到了多个独立的查询。 每个查询提供两个整数`a`和`b`，我们可以选择任何整数`c`在它们之间的包含范围内。 对于每一个选择`c`，我们计算一个成本，定义为距离`a`到`c`加上距离`c`到`b`。 

从几何角度来说，这就像放置一个点`c`数轴上的某处`a`和`b`，并测量我们距离`a`到`b`通过`c`。 任务是选择`c`使总旅行成本最小化，并输出该最小值。 

约束条件非常小：`a`和`b`最多 10 个，因此即使对所有可能的情况进行强力检查`c`价值观将是微不足道的。 然而，在这里，识别结构比计算更重要。 

天真的推理中一个微妙的陷阱是假设最好的`c`取决于其位置或需要搜索。 另一种方法是尝试通过测试中点或特殊值来“优化”。 因为表达式隐藏了取消，所以这种启发法可能会使实际上恒定的东西变得过于复杂。 

## 方法

 暴力解决方案会迭代所有可能的方法`c`之间`a`和`b`, 计算`(c - a) + (b - c)`，并取最小值。 这是有效的，因为范围很小，但它掩盖了关键的观察结果。 

展开表达式揭示其结构：`(c - a) + (b - c) = c - a + b - c = b - a`变量`c`完全消失。 这意味着每一个有效的选择`c`产生完全相同的值。 无需执行优化，因为成本不取决于决策。 

蛮力之所以有效，是因为它评估了冗余案例，但它无法揭示所有案例都是相同的。 中间项取消的观察使我们能够将问题简化为直接减法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(b - a + 1) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 简化公式可直接得出最佳解决方案。 

1. 读取整数`a`和`b`对于每个测试用例。 这些定义了线段的端点。 
2. 计算差异`b - a`。 这表示端点之间的总距离。 
3. 立即输出该值。 不依赖于`c`化简后仍保留。 

关键思想是每一个可能的选择`c`引起相同的代数抵消，因此除了读取输入之外没有任何决策步骤。 

### 为什么它有效

 表达式`(c - a) + (b - c)`总是简化为`b - a`因为`+c`和`-c`条款完全取消。 由于该恒等式适用于所有整数`c`，所有有效值的最小值`c`也是`b - a`，并且没有替代配置可以改善或恶化结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    print(b - a)
```实现直接反映了推导过程。 每个测试用例都是独立的，因此我们循环处理它们。 减法`b - a`是目标函数的完全简化形式，因此不需要搜索或分支。 除了简单的情况之外，没有边缘情况`a == b`，它正确地产生零。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = []

        a, b = map(int, input().split())
        out.append(str(b - a))

 ## 边缘情况

 唯一不明显的边缘情况是`a == b`。 在这种情况下，范围`c`折叠为单个值，并且表达式的计算结果为零。 公式`b - a`自然地处理这个问题，因为它变成了`0`，匹配正确的结果，无需任何特殊分支。
