 ## 解决方案
 ## 问题理解

 一个楼梯与$n$columns 包含高度列$1,2,\dots,n$。 这样一个楼梯中的单元总数是$$1+2+\cdots+n=\frac{n(n+1)}2.$$问题只关心_nice_楼梯。 一个关键的几何事实是，一个漂亮的楼梯总是有非常特定的楼梯数量。 如果我们从最小的漂亮楼梯开始，重复建造更大的楼梯，楼梯的数量如下$$1,\ 3,\ 7,\ 15,\dots$$这是$$2^k-1.$$对于带有$2^k-1$楼梯，单元格数量为$$1+2+\cdots+(2^k-1) = \frac{(2^k-1)2^k}{2}.$$让$$c_k=\frac{(2^k-1)2^k}{2}.$$可用的单元格$x$可以用来建造几个不同的漂亮楼梯。 每种楼梯类型最多只能建造一次，因为问题需要不同的漂亮楼梯。 我们希望楼梯类型的最大数量其总成本不超过$x$。 

的价值$x$可以大到$10^{18}$。 任何迭代所有数字直到$x$是不可能的。 甚至$O(\sqrt{x})$会太大。 我们需要一个解决方案，其工作仅取决于可能的漂亮楼梯的数量，而不取决于$x$本身。 

一个微妙的一点是，首先建造最大的楼梯并不总是最佳的。 例如：```
x = 8
```楼梯费用为：```
1, 6, 28, ...
```采取成本$6$第一片叶子$2$，允许多一个成本阶梯$1$，总共有两个楼梯。 试图最大化消耗细胞而不是楼梯数量的策略很容易做出错误的选择。 

另一个容易犯的错误是假设有许多楼梯尺寸需要考虑。 成本增长大致如下$4^k$，所以对于$x \le 10^{18}$只有大约三十种有效的楼梯类型。 利用这种增长就是整个解决方案。 

## 方法

 最直接的想法是生成每一个好的楼梯成本，然后尝试所有子集，找到总成本不超过的最大数字$x$。 这是正确的，因为每种楼梯类型都可以选择或不选择。 

问题是，即使有三十种楼梯类型也会导致大约$2^{30}$子集，超过十亿种可能性。 那是完全不可行的。 

关键的观察是楼梯成本增长极快：$$1,\ 6,\ 28,\ 120,\ 496,\dots$$每一项成本都远大于之前所有成本的总和。 例如，$$28 > 1+6,$$

$$120 > 1+6+28.$$事实上，对于每一个$k$,$$c_k > \sum_{i<k} c_i.$$这意味着序列是超增的。 

假设我们想要最大数量的楼梯。 如果适合的最大楼梯需要花费$c_k$，然后跳过任何解决方案$c_k$无法通过采用较小的楼梯来弥补，因为所有较小的成本加起来仍然低于$c_k$。 服用$c_k$只要合适，永远是最好的选择。 

这立即给出了一个贪心算法：

 继续减去不超过剩余单元格的最大楼梯成本。 数一数这可能发生多少次。 

由于只有大约三十个楼梯，成本高达$10^{18}$，该算法很小而且速度非常快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 |$O(2^m)$|$O(m)$| 太慢了 |
 | 预先计算成本的贪婪 |$O(m)$|$O(m)$| 已接受 |

 这里$m \approx 30$。 

## 算法演练

 1. 预先计算所有漂亮的楼梯成本$$c_k=\frac{(2^k-1)2^k}{2}$$尽管$c_k \le 10^{18}$。 
2. 对于每个测试用例，从给定数量的单元格开始$x$。 
3.找到不超过当前的最大楼梯成本$x$。 
4. 减去该成本$x$并将答案加一。 

这是正确的选择，因为每项成本都大于所有较小成本的总和。 
5. 当一些楼梯成本仍适合剩余单元格时重复此操作。 
6. 输出所选楼梯的数量。 

### 为什么它有效

 楼梯成本形成一个超级递增序列：$$c_k > \sum_{i<k} c_i.$$考虑最大的成本$c_k$符合当前预算。 任何不使用的解决方案$c_k$最多可以花费$$\sum_{i<k} c_i,$$它严格小于$c_k$。 更换$c_k$任何较小楼梯的集合都不会提供更好的机会来增加未来选择的数量。 

选择后$c_k$，剩余的问题在较小的预算下是相同的。 递归地重复相同的论证证明贪心选择总是最优的。 

## Python 解决方案```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

# precompute staircase costs
costs = []
k = 1
LIMIT = 10 ** 18

while True:
    p = 1 << k
    cost = (p - 1) * p // 2
    if cost > LIMIT:
        break
    costs.append(cost)
    k += 1

t = int(input())
ans = []

for _ in range(t):
    x = int(input())
    cnt = 0

    while True:
        idx = bisect_right(costs, x) - 1
        if idx < 0:
            break
        x -= costs[idx]
        cnt += 1

    ans.append(str(cnt))

sys.stdout.write("\n".join(ans))
```预计算阶段生成所有可能相关的良好楼梯成本。 由于成本呈指数增长，因此仅存储大约三十个值。 

对于每个测试用例，`bisect_right`找出不超过当前预算的最大成本。 减去该成本，然后重复该过程。 

使用二分搜索并不是绝对必要的，因为列表很小，但它可以保持实现干净并使意图明确。 

所有算术都使用Python整数，因此即使接近也不存在溢出风险$10^{18}$。
