 ## 解决方案
 ## 问题理解

 我们被赋予了一个秘密词`S`长度`n`，其中所有字符都是不同的，并且颜色图案`P`描述如何猜出另一个未知单词`T`被评估针对`S`使用 Wordle 规则。 

评估工作逐个进行。 如果`T[i]`等于`S[i]`，结果是绿色的。 如果`T[i]`与位置不匹配`i`但这封信存在于某处`S`，它变成黄色。 否则它是白色的。 

我们的任务反过来了。 我们被给予`S`以及由此产生的图案`P`，我们必须重建任何可能猜测的单词`T`长度`n`这样所有的字母都在`T`是不同的，Wordle 评估针对`S`准确地产生`P`。 如果不存在这样的词，我们必须报告不可能。 

关键的结构性限制是`n`非常小，最多 10。这立即告诉我们，位置上的指数结构是可以接受的，而任何依赖于整个字母表排列的东西都是不可接受的。 解决方案可以自由地探索字母子集上的分配或使用回溯，而不会带来崩溃的风险。 

一个微妙的约束来自于猜测单词中的“所有字母不同”规则。 这意味着我们不仅仅是为每个位置独立匹配颜色。 每个字母只能在全局范围内使用一次，因此一个位置的选择会限制所有其他位置。 

一个常见的陷阱是独立对待每个位置。 例如，如果`S = ABC`并且图案全是黄色，可以尝试分配`BCA`，但对于更复杂的绿色和黄色混合，贪婪的局部决策很容易阻碍全局一致性。 

当存在白色位置时，会出现另一种失败情况。 白色位置必须使用不存在于`S`。 如果有人错误地重复使用了剩下的信件`S`，评估会错误地产生黄色而不是白色。 例如，如果`S = ABC`位置是白色的，使用`A`这是无效的，因为它会变黄。 

## 方法

 一个蛮力的想法是生成所有可能猜测的单词`T`组成`n`区分字母表中的字母，并检查每个字母是否产生所需的颜色图案。 对于每个位置，我们计算成员资格和平等性`S`。 候选词的数量大致是取26个字母的排列`n`一次，其顺序为$26 \cdot 25 \cdot \dots$，即使对于`n = 10`。 这使得暴力破解变得不可行。 

问题的结构表明按位置类型划分约束。 绿色位置完全固定：如果`P[i] = G`， 然后`T[i]`必须等于`S[i]`。 黄色职位更有趣：他们必须接受来自`S`但不是他们自己立场的信件。 白色位置必须将字母放在外面`S`。 

一旦绿色分配被修复，剩下的任务就变成分配未使用字母的子集`S`到黄色位置，避免位置字母相等。 这是一个带有禁止对角线的约束匹配问题，并且由于大小最多为 10，因此回溯分配就足够了。 

当所有的绿色和黄色都放置完毕后，可以从不在其中的字母中任意填充白色位置`S`，因为这些字母除了不同之外不会与任何约束相互作用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力战胜一切语言| O(26!/(26-n)!) | O(26!/(26-n)!) | O(n) | 太慢了 |
 | 带约束的回溯 | O(n!) 最坏情况 (n ≤ 10) | O(n) | 已接受 |

 ## 算法演练

 我们一步步构建答案，同时尊重强制放置和全球唯一性。 

1. 根据模式将指数分为三组：绿色位置、黄色位置和白色位置。 绿色位置立即固定了字母及其位置。 
2. 对于每个绿色位置`i`， 放`T[i] = S[i]`并将该字母标记为已使用。 这降低了灵活性，但消除了不确定性。 
3. 建立剩余信件池`S`这不是由绿色位置固定的。 这些是唯一可以在黄色位置使用的字母。 
4. 对于每个黄色位置`i`，我们知道`T[i]`必须从其余字母中选择`S`，但不可能是`S[i]`。 这将为每个职位创建一组有效的候选人。 
5. 对黄色位置运行深度优先搜索，一次分配一个未使用的字母。 在每一步中，我们都会选择一个尚未使用且不违反位置限制的候选字母。 搜索继续进行，直到分配了所有黄色位置或发现矛盾。 
6. 如果我们成功分配所有黄色位置，则继续分配白色位置。 对于每个白色位置，选择不在其中的任何字母`S`并且尚未使用。 由于字母大小为 26 并且`n ≤ 10`，总是有足够的字母，除非早期的约束已经使配置变得不可能。 
7. 如果任何阶段失败，则报告不存在有效单词。 

### 为什么它有效

 该构造通过绿色分配立即强制执行所有确定性约束，然后将剩下的问题减少到在单射性约束和禁止的固定点下从固定集中分配字母子集。 回溯探索黄色位置和剩余秘密字母之间所有可能的一致双射，因此如果存在有效的分配，就会找到它。 一旦将字母的使用分为“来自S”和“外部S”，白色位置就是独立的，因此不会影响黄色阶段之后的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    p = input().strip()

    used = [False] * 26
    ans = [''] * n

    idx_s = {c: i for i, c in enumerate(s)}

    greens = []
    yellows = []
    whites = []

    for i in range(n):
        if p[i] == 'G':
            ans[i] = s[i]
            used[ord(s[i]) - 65] = True
        elif p[i] == 'Y':
            yellows.append(i)
        else:
            whites.append(i)

    # remaining letters from S for Y positions
    rem_letters = []
    for c in s:
        if not used[ord(c) - 65]:
            rem_letters.append(c)

    m = len(yellows)
    used_y = set()

    sys.setrecursionlimit(10000)

    def dfs(pos):
        if pos == m:
            return True

        i = yellows[pos]
        for c in rem_letters:
            if c in used_y:
                continue
            if c == s[i]:
                continue
            used_y.add(c)
            ans[i] = c
            if dfs(pos + 1):
                return True
            used_y.remove(c)
        return False

    if not dfs(0):
        print("No")
        return

    # fill whites with letters not in S
    available = []
    in_s = set(s)
    for i in range(26):
        c = chr(65 + i)
        if c not in in_s:
            available.append(c)

    ptr = 0
    for i in whites:
        ans[i] = available[ptr]
        ptr += 1

    print("Yes")
    print("".join(ans))

if __name__ == "__main__":
    solve()
```代码首先立即修复所有绿色位置，将它们的字母标记为已使用。 然后，它将剩余的索引分为黄色组和白色组。 对于黄色位置，它构建一个递归搜索，从秘密单词的未使用子集中分配不同的字母，同时遵守黄色位置不能采用其原始秘密字母的约束。 

成功分配黄色后，剩余位置为白色，并从秘密单词之外的字母贪婪地填充，保证存在足够的数量。 

一个微妙的一点是，黄色分配必须强制全局唯一性，而不仅仅是局部有效性。 这就是为什么共享`used_y`设置是必要的。

 ### 示例 1

| 步骤| 绿色| 黄色作业| 白色填充 |

 ## 边缘情况

 一种重要的边缘情况是所有位置都是绿色的。 在这种情况下，算法永远不会进入回溯并直接输出秘密词，因为每个位置都是固定的。 例如，与`S = ABC`和`P = GGG`，分配步骤立即设置所有位置并终止。 

另一种情况是所有位置都是黄色的。 这里，算法必须确保秘密字母的完全排列，没有固定点。 DFS 自然会通过拒绝以下情况来强制执行此操作：`T[i] = S[i]`，这保证了在受限集合上的类似混乱的行为。 

白色重质投入也很重要。 如果大多数位置都是白色，算法仍然会成功，因为非秘密字母池足够大。 由于字母表有 26 个字母，`n ≤ 10`，总是有足够的供应，除非早期的约束已经错误地消耗了它们，该结构通过干净地分离 S 字母和非 S 字母来避免这种情况。
