 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，然后我们查看它的每个可能的连续段。 每个段本身包含许多子段，我们只对那些 0 的数量等于 1 的数量的子段感兴趣。 

对于字符串中较大间隔的每个选择，我们都会计算它包含多少个平衡子段。 然后我们将所有可能的间隔的值相加。 另一种看待它的方式是，每个平衡子段都会对许多封闭区间做出贡献，并且我们正在有效地将所有这些贡献相加。 

直接的解释已经表明大量的重复计数。 每个子串都被视为潜在的候选者，并且每个封闭区间都会再次添加它。 由于外部间隔和内部子串的数量均按二次方缩放，因此当字符串长度达到 200000 时，任何显式枚举它们的解决方案都会太慢。 

一个天真的想法会尝试修复一个段并扫描其中的所有子段，但这会导致立方行为。 即使使用前缀和优化内部检查也不能拯救我们，因为段本身的数量仍然是二次的。 问题的结构迫使我们重新解释计数顺序。 

例如，当字符串是统一的时，就会出现朴素推理的微妙失败情况`"0000"`。 根本不存在平衡子串，所以答案为零。 然而，尝试错误地处理计数差异的粗心实现（例如，错误计算前缀相等性而不减去每个外部间隔的贡献）仍然可能由于重复计算空条件而累积非零值。 

关键的困难在于，每个有效子数组的贡献不是一次，而是与包含它的外部区间的数量成比例，并且必须解开两个区间层之间的这种耦合。 

## 方法

 暴力方法会枚举每个区间$(l, r)$，然后枚举每个子区间$(x, y)$在它里面，并检查它是否有相同的零和一。 使用前缀和，检查本身是恒定时间，但间隔对的数量仍然是$O(n^3)$。 和$n$最多$2 \cdot 10^5$，这是完全不可行的。 

为了改进，我们扭转了观点。 我们不是固定外部间隔并计算内部间隔，而是固定候选子数组并计算有多少个外部间隔包含它。 一个子数组$(x, y)$包含在所有$(l, r)$这样$l \le x$和$r \ge y$。 这种外部间隔的数量仅取决于位置$x$和$y$，并且等于$x \cdot (n - y + 1)$。 

所以问题简化为对所有平衡子数组求和：$$\sum_{x \le y, \; s[x..y]\text{ balanced}} x \cdot (n - y + 1).$$现在剩下的任务是有效地枚举所有平衡子数组。 这是经典的前缀和重构：map`0 → -1`和`1 → +1`。 当子数组的前缀和差为零时，子数组恰好是平衡的。 因此我们需要考虑前缀和匹配的所有位置对。 

让$p[i]$是前缀和。 对于每个值$v$，假设它出现在索引处$i_1 < i_2 < \dots < i_k$。 任意一对$(i_a, i_b)$和$a < b$定义平衡子数组$(i_a + 1, i_b)$。 每个这样的子数组贡献：$$(i_a + 1) \cdot (n - i_b + 1).$$因此，我们独立处理每个前缀和值，并使用前缀聚合在每组的线性时间内计算所有对的总和。 

关键的观察是，对于固定的右端点，我们可以维护左端点的累积和以避免二次枚举。

 ## 算法演练

 1. 将二进制字符串转换为前缀和数组，其中`0`变为-1并且`1`变为+1。 这将条件“零和一的数量相等”转换为“两个位置的前缀和相等”。 
2. 计算所有前缀和$p[0], p[1], \dots, p[n]$，开始于$p[0] = 0$。 
3. 相等前缀和值的组索引。 每组对应于运行余额相同的所有位置。 
4. 对于每组索引$i_1, i_2, \dots, i_k$，处理所有对的贡献$(i_a, i_b)$， 在哪里$a < b$，而不明确枚举它们。 
5. 按升序扫描索引，维护两个运行值：左端点的总和以及迄今为止出现的次数。 对于被视为右端点的每个新索引，使用之前看到的前缀索引添加其贡献。 
6. 对于右端点$i_b$，每个先前的索引$i_a$贡献$(i_a + 1) \cdot (n - i_b + 1)$。 分解因素$(n - i_b + 1)$，所以我们只需要总和$(i_a + 1)$超过组前缀。 
7. 对结果求模累加$10^9+7$。 

### 为什么它有效

 该转换将平衡子串减少为相等的前缀和。 每个有效子串唯一对应于一对相等的前缀和位置。 贡献函数清楚地分成仅取决于左端点的项和仅取决于右端点的项的乘积。 这种可分离性允许增量累积：在处理右端点时，所有有效的左端点都是已知的，并且可以对它们的贡献进行求和，而无需重新访问它们。 这保证了每个有效子数组都被精确计数一次，并且仅计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        # prefix sum positions grouped by value
        groups = {}

        cur = 0
        groups.setdefault(0, []).append(0)

        for i, ch in enumerate(s, start=1):
            cur += 1 if ch == '1' else -1
            groups.setdefault(cur, []).append(i)

        ans = 0

        for pos in groups.values():
            if len(pos) < 2:
                continue

            pref_sum_left = 0
            count = 0

            for i in pos:
                if count > 0:
                    right_factor = (n - i + 1)
                    ans = (ans + pref_sum_left * right_factor) % MOD

                pref_sum_left += (i + 1)
                count += 1

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```该实现构建前缀和，其中每个前缀和值收集它出现的所有索引。 对于每个组，我们从左到右扫描。 在被视为右端点的每个位置，我们将左端点的累积和（移位 +1 以匹配子串起始贡献）乘以右边界的可能扩展数量。 这直接匹配算法中导出的因式分解贡献。 

索引时需要小心。 为了方便起见，前缀数组使用从 0 开始的位置，但子字符串端点依赖于将前缀索引转换为实际的段边界，这就是为什么`(i + 1)`出现左端点并且`(n - i + 1)`用于右侧扩展计数。 

## 工作示例

 ### 示例 1：`010`前缀和为：

 | 索引我| 前缀和|
 | --- | --- |
 | 0 | 0 |
 | 1 | -1 |
 | 2 | 0 |
 | 3 | -1 |

 我们对职位进行分组：

 0 → [0, 2]

 -1 → [1, 3]

 对于组 0：

 | 对我| pref_sum_left | pref_sum_left | 贡献 |
 | --- | --- | --- |
 | 2 | 1 | (1 * (3 - 2 + 1)) = 2 |

 对于组-1：

 | 对我| pref_sum_left | pref_sum_left | 贡献 |
 | --- | --- | --- |
 | 3 | 2 | (2 * 1) = 2 |

 总计 = 4。 

这演示了每个组是如何独立的，并且贡献是如何通过前缀和而不是对枚举来聚合的。 

### 示例 2：`1100`前缀和：

 | 我| p[i] | p[i]
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 1 |
 | 4 | 0 |

 团体：

 0 → [0, 4]

 1 → [1, 3]

 2 → [2]

 第 0 组贡献：

 (0,4) → (1 * 1) = 1

 第 1 组贡献：

 (1,3) → (2 * 2) = 4

 总计 = 5。 

这显示了如何捕获多个平衡子字符串，即使它们严重重叠，以及如何按前缀和进行分组以避免丢失或重复计算它们。

 ## 边缘情况

 完全统一的字符串，例如`"0000"`除了简单匹配之外，不会产生前缀和冲突，因此除了初始状态之外，每个组的大小均为一。 该算法会跳过单例组，因此不会添加任何贡献，并且结果保持为零，与正确的行为相匹配。 

完全交替的字符串，例如`"0101"`创建许多重复的前缀和。 分组机制确保捕获所有相等的前缀对，并且每对根据其左右位置做出贡献。 扫描累积保证重叠的平衡子串不会被重复计算，因为每个右端点仅处理先前看到的左端点一次。
