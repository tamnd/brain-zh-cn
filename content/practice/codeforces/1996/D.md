 ## 解决方案
 ## 问题理解

 我们需要计算正整数的有序三元组$(a,b,c)$满足两个独立的限制。 

第一个限制限制了成对乘积：$$ab + ac + bc \le n$$第二个限制限制总和：$$a + b + c \le x$$“有序”这个词很重要。 如果$(1,1,2)$是有效的，那么$(1,2,1)$和$(2,1,1)$是分开计算的。 

输入包含多个测试用例。 对于我们收到的每个测试用例$n$和$x$，并且必须输出有效三元组的数量。 

约束才是真正的线索。 一次测试可以有$n,x$一样大$10^6$，但是所有的总和$n$整个输入的值最多是$10^6$，以及所有的总和$x$值也至多$10^6$。 

对所有可能值的三次搜索$a,b,c$是完全不可能的。 甚至对所有值进行二次搜索$10^6$会太大。 我们需要利用的结构$$ab + ac + bc$$极大地限制搜索空间。 

一个容易犯的错误是忘记变量必须严格为正。 例如：```
n = 1, x = 10
```不存在有效的三元组，因为 的最小可能值$$ab+ac+bc$$正整数是$1+1+1=3$。 

当总和界限很大并且实际上不相关时，就会出现另一种微妙的情况：```
n = 7, x = 1000
```答案不是由$x$。 每个有效的三元组仅来自乘积不等式。 迭代值最多的解决方案$x$会浪费大量时间。 

第三个常见错误是将排列视为相同。 为了```
n = 7, x = 4
```有效的三元组是$$(1,1,1), (1,1,2), (1,2,1), (2,1,1)$$这给出了答案$4$， 不是$2$。 

## 方法

 最直接的想法就是暴力。 列举每一个积极的一面$a$, 每个正数$b$, 每个正数$c$，检查两个不等式，并计算有效的三元组。 

这显然是正确的，因为每个候选人都只接受一次考试。 

不幸的是，即使我们只考虑高达$10^6$，搜索空间的顺序为$$10^{18}$$三倍。 这是根本不可能的。 

关键的观察是一旦$a$和$b$是固定的，两个约束都变成简单的上限$c$。 

从$$ab + ac + bc \le n$$我们得到$$c(a+b) \le n-ab$$因此$$c \le \frac{n-ab}{a+b}.$$自从$c$必须是整数，$$c \le \left\lfloor \frac{n-ab}{a+b} \right\rfloor.$$总和限制给出$$c \le x-a-b.$$所以对于固定对$(a,b)$，有效值的数量$c$简直就是$$\min\!\left( \left\lfloor \frac{n-ab}{a+b} \right\rfloor, x-a-b \right)$$前提是这个数量是正数。 

现在问题变成了对数$(a,b)$。 

我们仍然需要避免迭代所有$10^{12}$可能的对。 产品不平等本身就给出了很强的界限。 自从$c\ge1$,$$ab+a+b \le n.$$重新排列，$$b(a+1) \le n-a.$$因此$$b \le \frac{n-a}{a+1}.$$对于大型$a$，这个上限很快就会变小。 检查对的总数约为$$\sum_{a=1}^{n} \frac{n}{a} = O(n\log n).$$因为所有的总和$n$输入的值仅$10^6$，这种调和级数的复杂性很容易足够快。

 ## 算法演练

 1. 将答案初始化为零。 
2. 迭代所有正值$a$。 
3.对于当前$a$，计算最大可能的$b$这仍然可以带来一些积极的影响$c$。 

从$ab+a+b\le n$,$$b \le \left\lfloor \frac{n-a}{a+1} \right\rfloor.$$从$a+b+c\le x$和$c\ge1$,$$b \le x-a-1.$$取这两个界限的最小值。 
4. 迭代$b$从$1$到那个最大值。 
5. 计算基于产品的限制$c$：$$c_1= \left\lfloor \frac{n-ab}{a+b} \right\rfloor.$$6. 计算基于总和的限制$c$：$$c_2=x-a-b.$$7. 每个整数$c$在范围内$$1 \le c \le \min(c_1,c_2)$$是有效的，所以添加$$\min(c_1,c_2)$$到答案。 
8.毕竟成双成对$(a,b)$处理完毕，输出累计答案。 

### 为什么它有效

 对于固定对$(a,b)$，两个原始不等式独立地产生上限$c$。 值为$c$当它同时满足两个界限时恰好有效。 最大允许$c$因此是两个极限中的最小值。 

每个有效的三元组恰好对应一对$(a,b)$和一个计数值$c$。 每个计数值$c$通过构造满足两个原始不等式。 这在计数对象和有效三元组之间建立了一一对应关系，因此算法计数既不会太多也不会太少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, x = map(int, input().split())

        total = 0

        a = 1
        while True:
            b1 = (n - a) // (a + 1)
            b2 = x - a - 1
            bmax = min(b1, b2)

            if bmax < 1:
                if b1 < 1:
                    break
                a += 1
                continue

            for b in range(1, bmax + 1):
                c1 = (n - a * b) // (a + b)
                c2 = x - a - b
                total += min(c1, c2)

            a += 1

        ans.append(str(total))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```外循环迭代可能的值$a$。 表达式```
(n - a) // (a + 1)
```直接来自必要条件$ab+a+b\le n$，这保证了至少一个正值$c$可以存在。 

第二个界限```
x - a - 1
```来自于需要积极的空间$c$在总和约束中。 

对于每个有效对$(a,b)$，代码计算两个独立的上限$c$。 允许值的数量恰好是两个界限中较小的一个。 

一个常见的差一错误是忘记了$c$必须是积极的。 的界限为$b$推导假设$c\ge1$，这就是为什么公式包含额外的$+a+b$术语而不仅仅是$ab$。 

Python 整数会自动处理较大的答案，该答案可能会超过$2^{31}$。

 ## 边缘情况

 考虑：```
1
1 1
```的最小可能值$ab+ac+bc$正整数是$3$。 循环计算$$b_{\max}=\left\lfloor\frac{1-1}{2}\right\rfloor=0,$$所以没有对$(a,b)$已处理，答案仍然存在$0$。 

现在考虑：```
1
7 1000
```总和约束实际上是不相关的。 为了$(a,b)=(1,1)$，产品绑定给出$c\le2$，而总和给出$c\le998$。 该算法正确地取较小的值并仅计算可行的值$c$的。 

最后考虑：```
1
7 4
```三元组$(1,1,2)$,$(1,2,1)$， 和$(2,1,1)$都是不同的，因为循环迭代有序对$(a,b)$。 不执行对称性约简，因此有序三元组将按照要求精确计数。
