 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一个值`h`。 每对元素贡献一个值，具体取决于这两个元素是否放置在同一组或不同组中。 

如果有两个数`a[i]`和`a[j]`属于同一个子序列，它们的pair值为：$$a[i] + a[j]$$如果它们属于不同的子序列，则该对值变为：$$a[i] + a[j] + h$$对于选定的分区，我们查看每个无序对并收集所有这些值。 分区的优度是最大和最小对值之间的差异。 我们必须最小化这种差异并输出一个有效的分区。 

数组大小达到`10^5`，因此任何显式检查所有对的算法都是不可能的。 配对数量大致为：$$\frac{n(n-1)}{2}$$这是关于`5 * 10^9`在最坏的情况下。 即使存储所有对值也会超出内存限制。 

输入值和`h`可以达到`10^8`，因此总和可以安全地容纳在 32 位有符号整数内，但 Python 整数无论如何都消除了溢出问题。 

棘手的部分是分区通过添加来更改对值`0`或添加`h`。 粗心的实现可能会假设最佳答案总是使用这两个组，但这是错误的。 

考虑：```
2 100
1 1000
```如果我们拆分数字，唯一的对值将变为：```
1 + 1000 + 100 = 1101
```最大值和最小值相等，所以善良是`0`。 

但如果我们把一切放在一起：```
1 + 1000 = 1001
```美好还在`0`。 

两者都是最佳的。 该问题允许空子序列，这很重要，因为有时将所有内容放入一组是最好的。 

另一个微妙的情况出现时`h = 0`。```
4 0
1 5 7 10
```每对值很简单`a[i] + a[j]`无论分区如何，因此答案仅取决于数组本身。 任何分区都是最佳的。 尝试强制有意义的拆分逻辑的解决方案可能会意外地使这种情况变得过于复杂。 

最重要的边缘情况是最小和最大元素相互作用不良时。 

例子：```
3 2
1 2 100
```如果我们分开`100`独自一人，然后跨组配对获得`+2`，这可能会使最大值增加太多。 最优策略完全取决于控制全局最小和全局最大对和。 

这一观察推动了整个解决方案的发展。 

## 方法

 蛮力的想法很简单。 每个元素都可以属于两个组之一，因此有`2^n`可能的分区。 对于每个分区，我们可以计算所有对值并测量最大值和最小值之间的差异。 

正确性是显而易见的，因为我们检查了每一个可能的答案。 运行时间是灾难性的。 即使是为了`n = 30`，分区数量已经超过十亿。 和`n = 10^5`，穷举搜索是没有希望的。 

下一步是了解真正决定最小和最大对值的因素。 

假设数组已排序：$$b_1 \le b_2 \le \dots \le b_n$$在没有任何分配效应的情况下，最小可能的对和为：$$b_1 + b_2$$最大的是：$$b_{n-1} + b_n$$分区仅决定特定对是否接收额外的`h`。 

这意味着每个对值都属于以下两种形式之一：$$a_i + a_j$$或者$$a_i + a_j + h$$因此全局最小值必须是：$$b_1 + b_2$$或稍大的值（如果该对跨越组）。 

同样，全局最大值是：$$b_{n-1} + b_n$$或更大`h`。 

关键的见解是只有极端的对才重要。 我们不需要单独推理所有对。 

只有两个有意义的策略。 

第一个策略将每个元素保留在同一组中。 那么每对值都不变，所以：$$\text{goodness} = (b_{n-1} + b_n) - (b_1 + b_2)$$第二种策略试图通过强制最小的一对接收来改善传播`+h`同时防止最大的一对接收`+h`。 

为了使最小对交叉组，必须将两个最小的元素分开。 

为了将最大的一对保留在一个组中，两个最大的元素必须保持在一起。 

排序后，具有此属性的唯一可能的切割是：$$\{b_1\} \quad \text{and} \quad \{b_2, b_3, \dots, b_n\}$$或其对称等价物。 

在此分区下：

 最小对变为：$$b_1 + b_2 + h$$因为两个最小的元素是分开的。 

剩余的最大对：$$b_{n-1} + b_n$$因为两个最大的元素呆在一起。 

所以善良就变成了：$$(b_{n-1} + b_n) - (b_1 + b_2 + h)$$如果这个值变成负数，那就意味着最小和最大交换角色，所以实际的差价是绝对值。 

最终的答案是这两种可能性中较小的一个。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n^2)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取数组并记住每个元素的原始索引。 
2. 按值对元素进行排序。 
3. 计算所有元素都位于同一组中的优度。$$d_1 = (b_{n-1} + b_n) - (b_1 + b_2)$$这一分区始终有效，因为一个子序列可能为空。 

1. 计算仅隔离最小元素的特殊分割的优度。$$d_2 = |(b_{n-1} + b_n) - (b_1 + b_2 + h)|$$绝对值是必要的，因为将最小对增加`h`可以将其推至先前的最大值之上。 

1. 比较`d_1`和`d_2`。 
2.如果`d_1 <= d_2`，将每个元素放入组中`1`。 
3. 否则，将最小的元素放入组中`1`和所有其他元素到组中`2`。 
4. 按原来的输入顺序恢复答案并打印所选择的选项和分区。 

### 为什么它有效

 整个数组中最小的对和总是由排序后最小的两个元素组成。 类似地，最大的对和总是由两个最大的元素形成。 

分区只能添加`h`到选定的对。 任何改进答案的尝试都必须增加最小对值，同时不增加最大对值。 

增加最小值的唯一方法是将两个最小的元素分开。 避免增加最大值的唯一方法是将两个最大的元素保持在一起。 

一旦数组排序完毕，这两个要求就唯一地确定了最佳的非平凡分区。 任何其他分区要么保持最小值不变，要么不必要地增加最大值。 

因此，最优方案必须恰好是两个候选者之一：全部为一组或孤立最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, h = map(int, input().split())
a = list(map(int, input().split()))

arr = [(a[i], i) for i in range(n)]
arr.sort()

same_group = (arr[-1][0] + arr[-2][0]) - (arr[0][0] + arr[1][0])
split_group = abs(
    (arr[-1][0] + arr[-2][0]) -
    (arr[0][0] + arr[1][0] + h)
)

if same_group <= split_group:
    ans = [1] * n
    print(same_group)
    print(*ans)
else:
    ans = [2] * n
    ans[arr[0][1]] = 1
    print(split_group)
    print(*ans)
```第一部分存储值和原始索引，因为排序会更改顺序，但输出必须与原始输入顺序匹配。 

排序后，最小的两个元素在位置`0`和`1`，而最大的两个位于位置`n-2`和`n-1`。 

变量`same_group`对应于每个元素属于同一子序列的分区。 没有配对收到`+h`。 

变量`split_group`对应于隔离最小元素。 最小的一对现在跨组并接收`+h`，而最大的一对保持不变。 

绝对值是微妙的部分。 认为：```
h = 100
array = [1, 2, 3]
```然后：```
largest pair = 5
smallest cross pair = 103
```价差变为：```
103 - 5 = 98
```不是`5 - 103`。 

最后，我们重建分区。 如果平凡分区是最优的，则每个元素都会获得标签`1`。 否则，只有全局最小的元素才会收到标签`1`。 

## 工作示例

 ### 示例 1

 输入：```
3 2
1 2 3
```排序后：

 | 位置 | 价值| 原始索引 |
 | --- | --- | --- |
 | 0 | 1 | 0 |
 | 1 | 2 | 1 |
 | 2 | 3 | 2 |

 计算两个候选人：

 | 数量 | 价值|
 | --- | --- |
 | 最大的一对 | 2 + 3 = 5 | 2 + 3 = 5
 | 最小的一对 | 1 + 2 = 3 |
 | 相同组 | 5 - 3 = 2 | 5 - 3 = 2
 | 分割组 | \|5 - (3 + 2)\| = 0 |

 自从`0 < 2`，我们分离出最小的元素。 

分区：

 | 元素| 集团|
 | --- | --- |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 2 |

 该对值变为：

 | 配对| 价值|
 | --- | --- |
 | (1,2) | 5 |
 | (1,3) | 6 |
 | (2,3) | 5 |

 价差为`6 - 5 = 1`。 

该迹线说明了为什么仅更改最小的对就可以显着减小范围。 

### 示例 2

 输入：```
4 100
1 2 3 4
```排序数组：

 | 位置 | 价值|
 | --- | --- |
 | 0 | 1 |
 | 1 | 2 |
 | 2 | 3 |
 | 3 | 4 |

 候选值：

 | 数量 | 价值|
 | --- | --- |
 | 最大的一对 | 7 |
 | 最小的一对 | 3 |
 | 相同组 | 4 |

 现在额外的`h`太大了。 增加最小对会严重超调。 

最佳分区：

 | 元素| 集团|

 这个例子表明分裂并不总是有益的。

 ## 边缘情况

 考虑所有数字都相等的情况。 

输入：```
5 3
7 7 7 7 7
```没有分裂，每对值等于`14`，所以善良是`0`。 

如果我们隔离一个元素，跨组对就变成`17`，而同组对仍然存在`14`。 价差变为`3`。 

该算法正确比较：```
same_group = 0
split_group = 3
```并将所有内容放在一起。 

现在考虑一个分裂有很大帮助的情况。 

输入：```
3 2
1 2 3
```原始对范围是：```
5 - 3 = 2
```分离最小的元素会将最小值向上移动：```
1 + 2 + 2 = 5
```而剩下的最大值`5`。 

价差崩溃至`0`。 

最后，考虑危险的超调情况。 

输入：```
4 100
1 2 3 4
```分离最小的一对会改变最小值`3`到`103`，它变得大于旧的最大值`7`。 

该算法使用：```
abs(7 - 103)
```计算真实价差`96`。 

如果没有绝对值，实现将错误地产生否定答案。
