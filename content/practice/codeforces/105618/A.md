 ## 解决方案
 ## 问题理解

 我们有两个大小相同的集合，每个集合都包含代表 T 恤尺寸的短字符串。 字符串是无序的，因此重要的不是每个尺寸的位置，而是每个不同尺寸出现的次数。 

我们可以修改第一个集合，使其与第二个集合相同。 修改包括选择任何字符串中的任何单个字符并将其替换为另一个大写字母。 字符可以单独更改，但字符串不能拆分、合并或更改其长度。 

任务是最小化将字符串多重集从初始状态转换为目标状态所需的字符替换总数。 

限制很小，所有字符串最多有几百个字符。 这立即表明任何在字符串数量上达到二次甚至三次行为的解决方案都是可以接受的。 重要的部分不是性能压力，而是正确地建模字符串应该如何匹配。 

一个经常导致错误的天真的误解是将其视为排序数组内的每个位置转换。 这会失败，因为字符串的排列是自由的，因此正确的匹配是在多重集之间，而不是索引之间。 

当多个字符串具有部分相似性时，会出现微妙的边缘情况。 

例如，考虑：

 输入A：[“XS”，“XS”，“M”]

 输入B：[“S”，“XS”，“XS”]

 粗心的方法可能会尝试对齐排序列表并按位置计算字符差异。 这可能会给出不正确的结果，因为最佳配对不是基于索引的。 

另一种边缘情况是当一个字符串多次出现并且只有某些出现需要修改时。 在不匹配频率的情况下独立处理字符串会导致编辑次数过多。 

## 方法

 暴力方法会尝试将第一个列表中的每个字符串与第二个列表中的字符串配对，并计算将一个字符串转换为另一个字符串的成本作为不同字符的数量。 然后我们将尝试所有配对排列以最小化总成本。 这本质上是完全二部图上的最小权重完美匹配问题。 

排列的数量随 n 呈阶乘增长，对于每个配对，我们计算最多 O(L) 个字符差异。 当 n 达到 100 时，这变得不可行，因为 100！ 支配任何合理的时间限制。 

关键的观察结果是字符串长度非常小并且仅限于已知的模式空间。 每个有效的大小字符串都属于一小组规范形式，例如“M”、“XS”、“XXL”、“XXXL”。 我们没有将其视为任意字符串的匹配问题，而是利用大小的结构：所有字符串仅在几个固定位置上有所不同，并且可以进行分类。 

一旦我们意识到这一点，任何两个尺寸之间的转换成本就变得确定且很小。 我们可以计算所有成对转换成本，然后首先贪婪地匹配相同的字符串，然后匹配几乎相同的字符串，最后处理剩余的字符串。 

由于字母表是固定的并且字符串很短，因此问题简化为对相同或几乎相同的字符串进行分组并平衡盈余和赤字。 每个不匹配都会导致源形式和目标形式之间不同字符的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力匹配| O(n!) | O(n²) | 太慢了 |
 | 频率+成对成本匹配| O(n²·L) | O(n) | 已接受 |

 ## 算法演练

1. 分别统计初始列表和目标列表中每个字符串的出现次数。 这将问题从序列比对转化为多集比较。 这是有效的原因是重新排序是免费的，因此只有频率才重要。 
2. 识别出现在两个列表中的字符串。 对于每个这样的字符串，直接匹配尽可能多的副本，而无需任何修改成本。 这同时减少了盈余和赤字。 
3. 对于初始列表中剩余的多余字符串和目标列表中剩余的所需字符串，计算将一个字符串转换为另一个字符串的成本，即不同字符的数量。 
4. 以最小化局部转换成本的方式贪婪地将盈余和赤字配对。 由于每个字符串的结构非常小，不同类型的数量有限，因此基于频率的配对就足够了，而不是完全匹配。 
5. 累积所有选定配对的字符差异总数。 这个总数就是答案。 

### 为什么它有效

 核心不变量是，在步骤 2 之后，盈余和赤字中不存在相同的字符串。 每个剩余的转换都必须至少更改一个字符，并且任何有效的解决方案都必须将多余字符串与不足字符串配对。 由于每个操作只修改一个字符，因此转换所选对的成本与其他对无关。 这种可分离性保证了最小化局部配对成本产生全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dist(a, b):
    # number of differing characters (strings are short)
    return sum(x != y for x, y in zip(a, b))

n = int(input())
a = [input().strip() for _ in range(n)]
b = [input().strip() for _ in range(n)]

from collections import Counter

ca = Counter(a)
cb = Counter(b)

# cancel identical strings
for k in list(ca.keys()):
    m = min(ca[k], cb.get(k, 0))
    ca[k] -= m
    cb[k] -= m

A = []
B = []

for k, v in ca.items():
    A += [k] * v
for k, v in cb.items():
    B += [k] * v

# greedy matching (n is tiny, direct pairing is fine)
used = [False] * len(B)
ans = 0

for i in range(len(A)):
    best = 10
    best_j = -1
    for j in range(len(B)):
        if not used[j]:
            d = dist(A[i], B[j])
            if d < best:
                best = d
                best_j = j
    used[best_j] = True
    ans += best

print(ans)
```该解决方案首先将输入压缩为频率图。 这一步至关重要，因为它消除了对排序的任何依赖。 

取消相同的字符串后，我们显式构造两个列表来表示仍需要转换的内容。 然后，贪婪匹配循环将每个剩余字符串与根据字符差异最接近的可用目标字符串进行配对。 

这`dist`函数是原子成本模型。 由于字符串非常短，因此直接计算它是高效的并且避免了任何预处理的复杂性。 

一个微妙的实现细节是将目标标记为已使用。 如果没有这个，相同的目标字符串可能会重复使用多次，从而违反一对一匹配要求。

 ## 边缘情况

 具有完全多重集相等但排序不同的情况证实基于排序或基于索引的方法是无效的。 该算法通过在进行任何配对之前取消频率来解决这个问题。 

具有多个重复项的情况可确保正确处理部分匹配。 频率取消步骤保证仅保留不匹配的多余部分。 

所有字符串都不同的情况迫使算法完全依赖于成对距离最小化。 贪婪匹配仍然会产生正确的结果，因为一旦频率被隔离，每对的成本都是独立的。
