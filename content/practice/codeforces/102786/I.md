 # 问题理解

 我们有一排`n`货物，由一系列权重表示。 该行随着时间的推移而变化：每个查询都会交换两个位置的元素。 每次交换后，我们必须确定整个数组是否按非降序排序。 

答案并不取决于数组如何变成当前状态。 对于交换后的每个时刻，我们只需要知道每个元素是否不大于紧随其后的元素。 

这些限制迫使我们避免在每次查询后检查整个数组。 和`n`和`q`均达到`100000`，扫描所有的解决方案`n`每个交换的头寸最多执行`10^10`比较，这远远超出了 2 秒所允许的范围。 我们需要一个解决方案，其中每个查询仅更改少量维护的信息。 

主要的边缘情况来自这样一个事实：交换并不总是只影响两个交换的位置。 它还可以改变与相邻元素的关系。 例如：```
Input
3 1
1 3 2
2 3
```交换后，数组变为`[1, 2, 3]`，所以输出是：```
Sorted!
```仅检查交换值本身的顺序是否正确的解决方案会忽略以下事实：位置处的邻居关系`1`也改变了。 

另一个重要的情况是相等的值：```
Input
3 1
5 5 5
1 3
```输出是：```
Sorted!
```严格比较例如`a[i] < a[i+1]`会错误地将此数组标记为未排序，因为允许相等的相邻值。 

最后一个棘手的情况是当数组在后续查询之前进行排序时：```
Input
4 2
1 3 2 4
2 3
1 4
```第一次交换后，数组已排序，但第二次交换再次破坏了它。 我们必须独立于当前状态回答每个查询，而不是在第一个成功时刻之后停止。 

# 方法

 一种简单的方法是模拟每次交换，然后扫描整个数组以检查每个相邻对是否已排序。 这是正确的，因为非递减数组正是所有相邻比较都满足的数组`a[i] <= a[i+1]`。 

问题是成本。 每个`q`查询最多需要`n-1`比较，得出`O(nq)`工作。 在最坏的情况下，这大约是`10^10`操作，速度太慢。 

问题的结构给了我们一个更小的目标。 交换仅更改两个位置的值，因此大多数相邻对保持完全相同的顺序。 如果我们维护当前错误的相邻对的数量，则一次交换仅需要更新接触交换位置的对。 

当该计数为零时，数组将被精确排序。 在交换之前，我们删除受影响的相邻对的贡献，执行交换，然后添加它们的新贡献。 由于每个位置只有两个邻居，因此每个查询都会更改恒定数量的对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了|
 | 最佳| O(n+q) | O(n) | 已接受 |

 # 算法演练

 1. 建立一个不良相邻对的计数器。 对于每个索引`i`，检查是否`a[i] > a[i+1]`。 如果这是真的，则该对违反排序顺序并增加计数器。 
2. 对于每个交换查询，确定正在交换的两个头寸。 唯一可以更改的相邻对是涉及交换位置的对，因此在进行任何修改之前收集这些索引。 
3. 从计数器中删除每个受影响的相邻对的旧贡献。 需要执行此步骤，因为当前值即将从这些位置消失。 
4. 交换两个数组值。 
5. 添加交换后每个受影响的相邻对的新贡献。 计数器现在再次描述当前数组。 
6. 如果计数器为零，则打印`Sorted!`。 否则，打印`Unsorted!`。 

这样做的原因是非递减数组中每一个可能的无序都表现为坏的相邻对。 如果没有相邻对递减，则每个元素至多是下一个元素，这意味着整个数组已排序。 交换操作无法更改与交换位置之一不相邻的任何对，因此仅更新这些对可以保留违规的确切计数。 

# Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    bad = 0
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            bad += 1

    ans = []

    def value_bad(i):
        return i >= 0 and i + 1 < n and a[i] > a[i + 1]

    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        y -= 1

        affected = set()

        for pos in (x, y):
            affected.add(pos - 1)
            affected.add(pos)

        for pos in affected:
            if value_bad(pos):
                bad -= 1

        a[x], a[y] = a[y], a[x]

        for pos in affected:
            if value_bad(pos):
                bad += 1

        if bad == 0:
            ans.append("Sorted!")
        else:
            ans.append("Unsorted!")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```变量`bad`存储相邻反转的数量。 辅助函数检查特定的相邻对是否无效，同时还处理边界，因为永远不应该计算数组外部的位置。 

当交换的位置彼此相邻时，受影响的集合可能包含重复项。 使用集合可以避免两次删除或添加相同的相邻对。 这对于像头寸这样的掉期交易很重要`2`和`3`，其中两个位置共享相邻对。 

该代码从输入格式转换位置，该格式从`1`，进入Python索引，从`0`。 交换仅在旧的贡献被删除后才会发生，因为在不删除先前状态的情况下对修改后的数组进行计数会混合该数组的两个不同版本。

 # 边缘情况

 对于相等的值，该算法使用`>`而不是`>=`计算坏对时。 有输入：```
3 1
5 5 5
1 3
```交换后检查受影响的相邻对，但两次比较仍然有效，因为`5 <= 5`。 计数器保持为零，答案是`Sorted!`。 

对于修复整个数组的交换，算法会在交换之前删除旧的坏对，然后添加新的。 和：```
3 1
1 3 2
2 3
```最初的坏对是`(3,2)`。 它被删除，交换创建`[1,2,3]`，并且不会添加坏对。 计数器变为零，因此输出为`Sorted!`。 

对于更改两个相邻位置的交换，重复的受影响索引不得处理两次。 在：```
4 1
1 4 2 3
2 3
```这些位置共享它们周围的相邻对。 受影响的边集仅将该对保留一次，从而防止计数器发生错误更改。 

对于相互撤销的重复查询，该算法始终适用于当前数组。 在：```
2 2
1 2
1 2
1 2
```第一个查询创建一个坏对，第二个查询将其删除。 输出是：```
Unsorted!
Sorted!
```维护的计数器描述了每次操作后的当前状态，这正是每个答案所需的信息。```
