 # 问题理解

 我们有一个无向的道路网络。 每栋房子都是一个顶点，每条路都是一条边，每条路都有一个整数标签。 我们需要从一处指定的房屋前往另一处，但一条路线的成本并不是道路长度的总和。 成本是该路线上使用的所有道路值的按位或。 任务是在所有路径中找到尽可能小的这个值，或者报告两栋房子是断开的。 

输入描述了最多具有 100000 个顶点和 100000 个边的图。 权重可以大到 10^9，因此只能出现大约 30 个二进制位置。 这种大小的图会立即排除枚举路径或对所有可能的路线组合进行搜索的算法。 即使是普通的最短路径算法（例如 Dijkstra）也不能直接应用，因为 OR 不具备它们所需的加性性质。 

关键的困难在于，具有许多边的路线可能比具有较少边的路线更好。 例如，权重为 8 和 1 的路径的值为 9，而权重为 10 的单个边的值为 10。边的数量无关紧要，只有路由中出现的比特集才重要。 

有几种边缘情况会破坏简单的实现。 如果图形是断开的，则答案必须是 -1，而不是某个较大的初始值。 例如：```
3 1
1 2 7
1 3
```正确的输出是：```
-1
```将答案初始化为零或仅检查现有边缘的粗心解决方案可能会错误地返回值，即使无法到达房屋 3。 

第二个陷阱是假设道路数量最少的路径是最佳的。 考虑：```
3 3
1 2 6
2 3 1
1 3 7
1 3
```正确的输出是：```
7
```直达道路给出7，两条道路给出6 OR 1，也是7。基于边计数的方法并不能解决实际的优化问题。 

另一个常见错误是以错误的方向处理位。 由于高位的二进制值支配所有低位，因此只有在检查没有高位的情况下是否仍然可以连接之后才能删除高位。 例如，如果一个解决方案意外地保留了本来可以删除的位，那么以后进行再多的低位优化也无法修复结果。 

# 方法

 直接的强力方法将尝试探索两个顶点之间的所有可能路径并计算每条路径的“或”。 这是正确的，因为每个可能的答案都来自某个路径，但密集图中的路径数量可能是指数级的。 即使具有 100000 条边的图也可能包含大量不同的路线，从而使枚举变得不可能。 

一个稍微结构化的想法是使用最短路径算法并存储迄今为止为每个顶点找到的最佳 OR 值。 从顶点到邻居的过渡将是：```
new_value = current_value | edge_weight
```问题在于，可以到达某个顶点的不同 OR 值的数量自然不受 1 限制。 通常的 Dijkstra 论点依赖于将路径长度与加法相结合，而 OR 可以使之前看起来更糟糕的状态在以后变得有用。 正常的最短路径框架不利用 OR 值的特殊结构。 

重要的观察结果是“或”结果仅包含出现在所选路由的至少一个边缘上的位。 我们可以一点一点地构建答案，而不是尝试直接构建路线。 

假设我们当前有一组仍允许出现在答案中的位。 如果我们删除一位并且两个目标顶点仍然仅使用适合剩余掩模的边连接，那么该位是不必要的并且可以永久丢弃。 如果删除它会断开图的连接，那么每个有效的路由都需要该位，因此我们必须保留它。 

这将问题变成了重复的连接检查。 由于边权重只有大约 30 个相关位，因此我们只需要大约 30 个检查。 每个检查都可以使用不相交的集合并结构来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 路径数量呈指数增长 | O(n + m) | 太慢了|
 | 最佳| O(B(n + m) α(n)) 其中 B 是位数 | O(n) | 已接受 |

 # 算法演练

 1. 计算包含图中每个边权重的 OR 的掩码。 任何有效的路由只能包含此掩码中存在的位，因此这是最大可能的答案。 
2. 从最高位到最低位处理位。 对于当前位，暂时将其从掩码中删除，并仅使用其设置位全部包含在这个较小掩码中的边来测试起始顶点是否仍然可以到达目的地。 
3. 在连接测试期间，构建不相交集并集结构。 对于每条边，如果其权重满足，则合并其端点`(weight & mask) == weight`。 该条件意味着边沿不引入任何禁止位。 
4. 如果移除位后两个顶点位于同一组件中，则保持移除位。 如果它们断开连接，请恢复该位，因为每个可能的路线都需要它。 
5. 处理完所有位后，剩余的掩码是最小可能的 OR 值。 如果原始图从未允许连接，则最终掩码不足以区分这种情况，因此执行最终连接检查并在目标无法到达时输出 -1。 

这个贪婪过程正确的原因是二进制数是按其最高不同位按字典顺序排序的。 当考虑到一点时，如果没有它的有效路由仍然存在，则删除它总是比保留它更好。 任何后来的决定仅影响较低位，并且不能补偿不必要地保留较高位。 不变的是，在处理位前缀之后，当前掩码是已考虑的仍允许有效路由的高位的最小可能集合。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    edges = []
    mask = 0

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, w))
        mask |= w

    a, b = map(int, input().split())
    a -= 1
    b -= 1

    def connected(cur_mask):
        parent = list(range(n))
        size = [1] * n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(x, y):
            x = find(x)
            y = find(y)
            if x == y:
                return
            if size[x] < size[y]:
                x, y = y, x
            parent[y] = x
            size[x] += size[y]

        for u, v, w in edges:
            if (w & cur_mask) == w:
                union(u, v)

        return find(a) == find(b)

    if not connected(mask):
        print(-1)
        return

    for bit in range(30, -1, -1):
        candidate = mask & ~(1 << bit)
        if connected(candidate):
            mask = candidate

    print(mask)

if __name__ == "__main__":
    solve()
```变量`mask`表示删除不必要的位后仍然可能的最佳答案。 它以所有边的“或”开始，因为任何路径都不能包含未出现在图中任何位置的位。 

这`connected`函数执行重复图测试。 它不需要构建新的图。 相反，它精确地连接那些权重与当前掩码兼容的边。 表达式`(w & cur_mask) == w`检查边缘使用的每个位是否都被允许。 

不相交集并集实现使用路径压缩和按大小并集，使每个连接检查接近线性时间。 权重最多为 10^9，因此检查第 30 位到 0 涵盖了每个可能的设置位。 

初始连接检查是必要的，因为最终掩码本身无法代表不可达图和答案为零的可达图之间的差异。 仅包含零权重边的路径是有效的并且必须返回零。

 最终答案是5。顶点1和2之间唯一可能的路线使用权重为5的道路，因此OR值不能更小。

3 5 6
1 4 7
2 4 6
1 3
```初始掩码是`6 | 7 | 6 = 7`。 顶点 1 和 3 已断开连接。 

| 步骤| 当前掩码| 连接性| 结果 |

 # 边缘情况

 在任何位删除开始之前，会处理断开连接的图形情况。 对于输入：```
3 1
1 2 7
1 3
```初始掩码为 7。第一次连接检查发现顶点 3 与顶点 1 不在同一 DSU 组件中，因此算法立即返回 -1。 它从不尝试最小化不存在的路线。 

该算法还可以正确处理具有零权重边的路线。 为了：```
2 1
1 2 0
1 2
```初始掩码为零。 连接性检查接受唯一的边，因为`(0 & 0) == 0`。 无法删除任何位，答案仍然为零。 

具有许多边的路线可能比直接边更好，并且该算法不喜欢任何一种。 为了：```
4 4
1 2 8
2 3 4
3 4 2
1 4 15
1 4
```直接边缘给出 15。较长的路径给出`8 | 4 | 2 = 14`。 贪婪移除检查每个高位，发现位 0 可以消失，同时顶点保持连接，留下 14 作为最小值。 

最后的边缘情况涉及高位。 由于该算法处理从 30 到 0 的所有可能位，因此可以处理诸如 1073741823 之类的权重，而不会溢出或丢失重要位置。
