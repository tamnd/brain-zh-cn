 ## 解决方案
 ## 问题理解

 输入描述了资产价格的每日百分比变化。 每个值均以基点给出，因此值为`100`意味着改变`1%`,`-250`意味着减少`2.5%`， 等等。 价格变化是一个接一个地应用的，这意味着它们是相乘而不是相加。 一连串的变化`+10%`， 然后`-10%`不会返回到原始价格，因为第二次更改会影响已修改的值。 

我们需要选择连续的天数范围。 范围的开始是我们购买资产的日期，结束是我们出售资产的日期。 目标是在应用此范围内的所有更改后最大化最终值。 如果多个范围给出完全相同的回报，则优先选择起始日最晚的范围。 如果起始天数相同，则优先选择较长的范围。 

变化次数可达30万次。 在最坏的情况下，二次解需要检查大约 450 亿个间隔，这远远超出了典型的竞争性编程所允许的时间限制。 该解决方案必须在线性或近线性时间内处理数组。 内存量还必须与输入大小保持成正比，因此存储大型区间结果表是不切实际的。 

在一些边缘情况下，直接实现可能会失败。 首先，将百分比相加而不是相乘会给出错误的答案。 例如：```
4
5000 -4000 100 100
```正确答案是`1 4`，因为乘数是`1.5 * 0.6 * 1.01 * 1.01`，这大于任何个人收益。 总结变化的解决方案看到`50 - 40 + 1 + 1 = 12%`并且可能会错误地将其与个别日期进行比较。 

另一个问题是处理负面变化。 大幅下降可能会使扩展段变得更糟，但稍后增加可以使整个段达到最佳状态。 例如：```
5
-1000 5000 -1000 5000 -1000
```最好的区间是全范围`1 5`，因为两个强增加通过乘法补偿了损失。 仅搜索连续正值的解决方案会忽略这一点。 

打破平局是另一个微妙之处。 考虑：```
4
100 0 100 0
```间隔`1 4`和`3 4`具有相同的回报，因为零变化不影响价格。 正确答案是`3 4`，因为它开始较晚。 保留找到的第一个最大值的实现将会失败。 

## 方法

 一种直接的方法是尝试每一个可能的起始日，并一次延长一天的间隔。 对于每个区间，我们可以维护当前乘数并将其与迄今为止找到的最佳乘数进行比较。 这是正确的，因为每个可能的周期都会被检查。 

然而，有`N * (N + 1) / 2`可能的间隔。 和`N = 300000`，即大约 450 亿个间隔。 即使使用恒定时间更新，这也太慢了。 

关键的观察结果是，每个每日乘数都是正数。 的改变`p`基点对应于以下乘数：```
1 + p / 10000
```因为所有乘数都是正数，所以最大化乘积相当于最大化它们的对数之和：```
log(a * b * c) = log(a) + log(b) + log(c)
```该问题变成了变换值的最大子数组和问题。 这正是 Kadane 算法处理的结构。 

蛮力方法之所以有效，是因为它明确地评估了每个产品，但它失败了，因为间隔太多。 将乘法转换为加法可以让我们在从左到右扫描时仅保留可能最好的先前状态。 

方法之间的比较是：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了|
 | 最佳| O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将每天的变化换算成对数值。 为了改变`p`， 店铺：```
log(1 + p / 10000)
```这些值在一段时间内的总和代表总回报的对数，因此比较总和与比较实际回报相同。 

1. 维护转换值的前缀和。 如果`pref[i]`是第一个的总和`i`变换后的值，然后是区间值`(l, r)`是：```
pref[r] - pref[l - 1]
```1. 扫描结束位置时`r`,保留之前所有位置中最小的前缀和`r`。 减去先前的最小前缀给出结束于的最大可能间隔`r`。 
2. 当多个前缀位置的最小值相同时，保留最新的一个。 根据问题的平局规则，较晚的起始位置是首选。 
3. 将当前区间与迄今为止找到的最佳答案进行比较。 如果返回值更大，则替换答案。 如果收益相等，则选择起始索引较大的区间，如果也相等，则选择较长的区间。 
4、后加工位置`r`， 插入`pref[r]`到存储的最小前缀信息中，以便将来的间隔可以在之后开始`r`。 

为什么它有效：

 前缀和表示意味着每个间隔值都是通过选择一个较早的前缀从当前前缀中减去来确定的。 对于固定结束位置，最佳间隔必须紧接在最小的先前前缀值之后开始。 该算法始终准确存储这些必要的信息，包括相等前缀值之间的正确平局选择。 由于检查了每个可能的结束位置，并考虑了每个结束位置的最佳起点，因此找到了全局最优值。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    logs = [math.log1p(x / 10000.0) for x in p]

    eps = 1e-12

    pref = 0.0
    min_pref = 0.0
    min_pos = 0

    best_value = -float("inf")
    best_l = 1
    best_r = 1

    for i, value in enumerate(logs, start=1):
        pref += value

        current = pref - min_pref
        l = min_pos + 1
        r = i

        length = r - l + 1
        best_length = best_r - best_l + 1

        if (
            current > best_value + eps
            or (
                abs(current - best_value) <= eps
                and (l > best_l or (l == best_l and length > best_length))
            )
        ):
            best_value = current
            best_l = l
            best_r = r

        if pref < min_pref - eps or (abs(pref - min_pref) <= eps and i > min_pos):
            min_pref = pref
            min_pos = i

    print(best_l, best_r)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个百分比变化转换为对数。`log1p`使用而不是直接计算`log(1 + x)`因为它对于接近零的值更准确。 

变量`pref`存储当前的前缀和。`min_pref`是当前位置之前看到的最小前缀和，并且`min_pos`是该前缀的索引。 当当前位置用作句点的结尾时，减去此最小前缀会产生在此结束的最佳可能间隔。 

答案比较包含决胜逻辑。 对数回报越大越好。 如果两个返回值在浮点精度内相等，则选择左端点较大的区间。 如果两个左端点都匹配，则较晚的右端点给出较长的间隔。 

的更新为`min_pref`在检查当前答案后发生，因为当天不能用作前缀公式中同一天结束的间隔的起点。 保持顺序正确可以避免差一错误。 

Python 浮点数在这里就足够了，因为只需要比较累积对数之间的情况。 原始产品可能变得非常小或非常大，但对数形式使所有值保持在可管理的范围内。

 ## 边缘情况

 包含非常大的损失和随后的增益的序列由最小前缀逻辑处理。 为了：```
3
-9999 5000 5000
```第一个乘数是`0.0001`，因此包含它几乎会破坏投资。 第一天之后的前缀总和变得非常负，使其成为最小前缀。 当处理第二天时，从第 2 天开始变得更好，并且算法从那里继续。 最终的答案是：```
2 3
```间隔之间的平局必须优先选择最晚开始的。 为了：```
5
100 0 100 0 0
```零变化不会修改回报。 间隔`1 5`和`3 5`有相同的产品。 该算法存储相等的最小前缀中的最新位置，这会导致从第 3 天开始的候选前缀替换较早的前缀。 输出是：```
3 5
```一天可能就是最好的答案。 为了：```
4
1000 2000 -3000 4000
```前三天在一起的情况比最后一天单独的情况要弱。 第四天之前的最小前缀在丢失后更新，允许算法仅考虑第四天。输出变为：```
4 4
```这些情况正是基于增加百分比、假设积极连续性是最佳的或忽略打破平局规则的方法往往会失败的地方。
