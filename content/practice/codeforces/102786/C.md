 ## 解决方案
 ## 问题理解

 该任务是一个交互式图重建问题。 我们从大厅开始`0`，并在开始的大厅`0`通过`N`已经可达。 此后，无人机不断发送已发现隧道的碎片。 每个片段在大厅编号之间包含多个无向边。 在收到每个片段后，我们必须立即决定收集到的信息是否足以构建一条从我们当前可达区域到大厅的路径`9999`。 如果是，我们打印`ATTACK`; 否则我们打印`WAIT`并允许无人机继续飞行。 

该输入不寻常，因为它是在线到达的。 第一行给出了最初可用集的大小，然后接下来的每一行都是已发现边缘的新部分。 输出不是固定输入的最终答案，而是每次更新后的一系列决策。 

几乎可以有`100000`大厅。 这立即排除了在每条无人机消息后从头开始重建图形搜索的可能性。 每次更新后对所有已知边进行完整的 BFS 或 DFS 可能会处理相同的边数千次，这在 5 秒限制下过于昂贵。 我们需要一个可以增量更新连接的结构。 

关键的边缘情况是由输入的在线性质引起的。 路径可能会在处理新片段后恰好出现，因此仅在读取片段之前进行检查会错过所需的攻击时刻。 

例如，假设初始行是：```
0
```唯一的无人机消息是：```
1 0 9999
```正确的输出是：```
ATTACK
```打印的解决方案`WAIT`在应用新边缘之前，仅检查是否已经错过了允许的攻击时刻。 

另一个微妙的情况是女王是间接连接的。```
0
2 0 5 5 9999
```正确的输出是：```
ATTACK
```边缘`0-5`不直接包含大厅`9999`，但是两条边一起形成一条路线。 仅检查直接邻居`0`会失败的。 

第三个常见错误是忘记最初的大厅已经可以进入。 如果输入以以下内容开头：```
3
```然后大厅`0`,`1`,`2`， 和`3`在第一次无人机响应之前全部可用。 正确的解决方案必须从一开始就将它们视为一个可访问的组件。 

## 方法

 一个简单的解决方案是存储每个发现的隧道，并在每条无人机消息后从当前可到达的大厅运行图形搜索。 这是正确的，因为我们需要回答的唯一问题是：`9999`属于包含我们起始位置的组件。 然而，相同的旧边缘会被一遍又一遍地扫描。 高达`100000`大厅和许多更新，反复遍历整个图可以达到数十亿次边缘检查。 

问题的结构给了我们一个更简单的视角。 我们永远不需要确切的路线、距离或树结构。 我们只需要知道两个大厅是否在同一个连通分量中。 添加隧道只会合并两个组件，而不会分离它们。 这正是不相交集并集结构所适合的情况。 

最初，所有大厅`0`通过`N`属于可达组件。 对于每条无人机消息，我们将每个接收到的边的两个端点合并。 处理完消息中的所有边后，我们检查 Hall 是否`9999`与hall有相同的代表`0`。 如果是，则该路径存在。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(U * (V + E)) | O(V + E) | 太慢了 |
 | 最佳 | O((V + E) α(V)) | O((V + E) α(V)) | O(V) | 已接受 |

 这里`U`是无人机​​更新的数量，`α(V)`是阿克曼反函数，它增长得非常缓慢，以至于实际上是恒定的。 

## 算法演练

 1. 为所有可能的大厅创建一个不相交的并集结构。 由于大厅号码最多可达`99999`，我们为每个可能的顶点准备足够的空间。 

最初可到达的大厅是`0`通过`N`，所以它们必须已经连接到我们的起始位置。 我们将它们中的每一个与大厅合并`0`。 
2. 阅读下一条无人机消息。 第一个数字是已发现的过渡数量，后面是许多对大厅编号。 

每对代表一条无向隧道。 由于隧道意味着两个大厅都可以相互到达，因此我们合并了它们的组件。 
3.处理完整个消息后，比较hall的组成部分`0`和大厅`9999`。 

如果它们相等，则收集到的信息已经包含通往女王的路线，因此我们打印`ATTACK`并终止。 否则我们打印`WAIT`，刷新输出，并等待下一个片段。 

为什么它有效：

 不变量是，在处理任意数量的无人机消息后，当发现的隧道证明两个大厅之间存在路线时，它们恰好位于同一个不相交集并集组件中。 最初这是真的，因为起始的无障碍大厅合并在一起。 每个新隧道仅在两个组件之间创建可能的连接，而并集操作恰好执行该合并。 如果所有边都没有连接相应的组件，则不存在有效的路线，因此检查 Hall 是否`9999`与 Hall 属于同一组件`0`相当于检查是否存在攻击路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

def main():
    n = int(input())
    dsu = DSU(100000)

    for i in range(1, n + 1):
        dsu.union(0, i)

    for line in sys.stdin:
        if not line.strip():
            continue

        data = list(map(int, line.split()))
        k = data[0]

        idx = 1
        for _ in range(k):
            u = data[idx]
            v = data[idx + 1]
            idx += 2
            dsu.union(u, v)

        if dsu.find(0) == dsu.find(9999):
            print("ATTACK")
            sys.stdout.flush()
            return
        else:
            print("WAIT")
            sys.stdout.flush()

if __name__ == "__main__":
    main()
```这`DSU`类存储代表每个大厅的连接组件。 路径压缩在`find`使未来的查找速度非常快，而按大小并集使内部树保持浅层。 

初始化循环将每个最初可用的大厅连接到大厅`0`。 这是很容易被忽略的部分，因为输入没有明确列出这些边。 无人机仅在项目开始后提供额外的隧道。 

对于每个传入片段，代码首先应用所有新隧道，然后才检查答案。 顺序很重要，因为所需的攻击时刻可能恰好在最新片段到达之后。 

每次响应后的刷新是必要的，因为这是一项交互式任务。 如果没有它，法官可能不会发送下一个片段，因为它正在等待程序的决定。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O((N + E) α(100000)) | 每次初始合并和每个发现的边缘都执行几乎恒定的摊销工作 |
 | 空间| O(100000) | DSU 为每个可能的大厅存储一个父项和一个尺寸值 |

 对于固定 DSU 阵列来说，大厅的最大数量足够小。 该解决方案在收到所有边缘后不再扫描所有边缘，因此即使进行多次无人机更新，它仍然保持高效。

import sys
import io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))

        def find(self, x):
            if self.p[x] != x:
                self.p[x] = self.find(self.p[x])
            return self.p[x]

        def union(self, a, b):
            a = self.find(a)
            b = self.find(b)
            if a != b:
                self.p[b] = a

    out = []
    n = int(input())
    dsu = DSU(100000)

    for i in range(1, n + 1):
        dsu.union(0, i)

    for line in sys.stdin:
        if not line.strip():
            continue
        a = list(map(int, line.split()))
        k = a[0]
        ptr = 1
        for _ in range(k):
            dsu.union(a[ptr], a[ptr + 1])
            ptr += 2
        if dsu.find(0) == dsu.find(9999):
            out.append("ATTACK")
            break
        out.append("WAIT")

    return "\n".join(out)

 ## 边缘情况

 当女王通过第一条无人机消息连接时，该算法仍然有效，因为它在检查之前处理所有接收到的边。 为了：```
0
1 0 9999
```联合操作合并`0`和`9999`，所以代表匹配，答案是`ATTACK`。 

当线路有多个中间大厅时，无需特殊处理。 为了：```
0
2 0 5 5 9999
```第一个联合创建组件`{0,5}`第二个将其扩展为`{0,5,9999}`。 最终比较正确检测到路线。 

当起始可达区域除大厅外还包含大厅时`0`，这些大厅必须首先合并。 为了：```
3
1 3 8
1 8 9999
```大厅`3`已经可达，因此发现的链在第二次更新后到达女王。 仅从顶点开始的解决方案`0`无需初始化大厅`1`通过`N`会错误地延迟或错过攻击。
