 ## 解决方案
 ## 问题理解

 谢苗通过简单的日历规则选择跑步日期。 他的第一次训练是在某个月的奇数日进行的，之后他就在每个奇数日继续跑步。 当他连续两个日历日跑步时，他将在这两次跑步后的第一个偶数日立即退出。 

任务是找到戒烟日期。 输入的格式为一个有效日期`DD.MM.YYYY`，代表第一次运行。 这一天肯定是奇数，因此第一个训练日始终是一个有效的起点。 输出是连续运行天中第二次运行之后的第一个偶数日期。 

年份范围很小，从 1900 年到 2100 年，因此不需要高级日期库或复杂的日历结构。 重要的部分是正确处理月份长度和闰年。 每天移动的模拟只需要恒定数量的步骤，因为我们正在寻找奇数日时间表和日历之间的第一次冲突。 扫描多年或构建大型日期表的解决方案仍然适用于这些界限，但它会忽略问题的更小的结构。 

棘手的部分来自月份转换和闰年。 当第二天属于另一个月份时，仅增加天数的简单实现可能会失败。 例如，输入`31.01.2019`不可能，因为第一天保证有效且奇数，但接近月末的日期正是不正确的日历处理通常会中断的地方。 一个粗心的程序可能会改变`31.01.2019`进入`32.01.2019`而不是`01.02.2019`。 

闰年是错误的另一个来源。 用于输入`01.01.2020`，运行发生在奇数日期。 第二次连续运行出现在`01.02.2020`和`02.02.2020`，所以答案是`02.02.2020`。 将每年能被 4 整除的年份视为闰年的程序可能会在 1900 年等非闰年的年份失败。 

一个常见的差一错误是返回连续的第二个运行日而不是接下来的偶数日。 用于输入`01.01.2019`，连续运行是`01.01.2019`和`02.01.2019`，但答案是`02.01.2019`因为那是第二次运行后的第一个偶数天。 退出日期和第二次运行日期相同。 

## 方法

 直接的方法是一次模拟日历。 从第一次运行日期开始，我们可以继续检查每个日期。 如果当前日期是奇数，Semyon 就会运行。 如果前一个日期也是运行日，则当前日期是连续第二次运行，因此答案是第二天。 这种方法是正确的，因为它完全遵循语句中的规则。 

仅当不使用日期结构来实现时，强力方法才会变得不必要的复杂。 跨越多年的大型模拟需要迭代数十万天，但实际上可以在仅检查下一个偶数日期周围的天数后找到答案。 原因是 Semyon 的日程安排创建了一个可预测的模式：他在所有奇数日期运行，因此奇数日期之后第一次出现偶数日期时，每当日历到达偶数日之后紧接着的下一个奇数日时，第二天就会开始关键对。 

关键的观察结果是，只有当两个相邻日期具有奇数时，才会发生连续运行。 在一个月内，这种情况永远不会发生，因为奇数日后面总是跟着偶数日。 当奇数日是一个月的最后一天并且下个月的第一天也是奇数时，唯一可能的对出现。 由于月份结束日期只能为 28、29、30 或 31，因此我们只需找到上个月以奇数日结束的下个月边界。 下个月的第一天是第二次跑步，同一天是退出日期，因为它是偶数？ 这个观察需要细化：只有当上个月有 31 天时，第二次运行才是该月的奇数第一天，并且退出日期是第二天，即该月的第二天。 

因此，最佳解决方案是逐月移动，直到到达起点后 31 天的月份。 下个月的第一天是连续第二次运行，答案是该月的第二天。 这是有效的，因为每个有 31 天的月份如果第一天是奇数，则以奇数结束，并且搜索的开始日期始终是奇数。 跟踪月份转换可以避免不必要的日常模拟。

 ## 算法演练

 1. 将输入日期解析为日、月、年值。 起始日是奇数，因此它代表连续日，并且是查找下一个连续对的参考点。 
2. 重复移至下一个日历日，直至到达第一个偶数日。 这一天不可能是第二次运行，因为谢苗只在奇数日期运行，但它是可能的连续运行之间的一天。 
3.再向前推一天。 如果新的一天是奇数，则它是紧接奇数日之后的连续运行日，这意味着前两天是连续运行的。 答案是第二天。 
4. 如果新的一天不是所需模式的一部分，请继续前进，同时保留正确的月份长度和闰年规则。 

不变的是，在每个模拟日之后，当前日期是日历中的下一个可能的点，并且所有更早的日期都已被检查。 由于每对可能的连续运行日都必须按时间顺序出现，因此检测到的第一个对准确地给出了 Semyon 退出的日期。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_leap(year):
    return year % 400 == 0 or (year % 4 == 0 and year % 100 != 0)

def days_in_month(month, year):
    if month == 2:
        return 29 if is_leap(year) else 28
    if month in (4, 6, 9, 11):
        return 30
    return 31

def next_day(day, month, year):
    day += 1
    if day > days_in_month(month, year):
        day = 1
        month += 1
        if month == 13:
            month = 1
            year += 1
    return day, month, year

def solve():
    s = input().strip()
    day, month, year = map(int, s.split("."))

    while True:
        nd, nm, ny = next_day(day, month, year)

        if day % 2 == 1 and nd % 2 == 1:
            ans_day, ans_month, ans_year = next_day(nd, nm, ny)
            print(f"{ans_day:02d}.{ans_month:02d}.{ans_year:04d}")
            return

        day, month, year = nd, nm, ny

solve()
```闰年函数遵循问题所需的确切日历规则。 能被 400 整除的年份是闰年，能被 100 整除的年份不是闰年，其余所有能被 4 整除的年份都是闰年。 

这`days_in_month`函数隔离了唯一可能影响正确性的日历细节。 二月取决于年份，而其他月份有固定的长度。 

这`next_day`函数在一处处理所有转换。 这可以防止从月末或年末移动时出现错误。 

主循环不断检查相邻日期。 如果当前日期和下一个日期均为奇数，则为连续两个训练日。 输出是通过再次前进获得的，因为所需的日期是第二次运行后的第一个偶数日。

 ## 边缘情况

 31 天的月份过渡是核心边界情况。 用于输入`01.01.2019`，算法检查日期直到达到`31.01.2019`其次是`01.02.2019`。 这两个日期都是奇数，所以第二次运行发生在`01.02.2019`，输出变为`02.02.2019`。 仅检查同一个月内的日期的解决方案将错过此转换。 

闰年边界必须使用完整的闰年规则。 用于输入`29.02.2000`，日期算术认为 2000 可以被 400 整除，因此 2 月有 29 天。 该算法正确地持续到三月，并找到导致`02.04.2000`。 

第二次运行后第二天的输出是另一个常见的错误来源。 用于输入`31.05.2019`，连续运行是`31.05.2019`和`01.06.2019`。 正确答案是`02.06.2019`， 不是`01.06.2019`，因为谢苗只有在连续第二天训练后才退出。
