 ## 解决方案
 ## 问题理解

 我们正在处理一个矩形竞技场，其中心包含一个较小的矩形草地。 在这片草地的周围，分布着多条同心圆的矩形“车道”。 泳道 1 是紧邻草地的矩形，泳道 2 是较远的一个单位，依此类推。 每条车道都是一个闭环，跑步者以逆时针循环连续绕着他的车道行走，每秒移动一个网格单元。 

草地里面，一个固定的牢房里站着一名摄影师。 在某个时刻，他想用一台可以同时捕捉两个相反方向的特殊相机拍一张照片。 如果在那个时间，每个跑步者要么与摄影师在同一行，要么与摄影师在同一列，那么一张照片就被认为是好的。 重要的是，所有跑步者必须同时满足相同的条件，这意味着要么每个人都躺在 Rp 行上，要么每个人都躺在 Cp 列上。 

任务是计算这种情况发生的最早时间，或者确定这种情况永远不会发生。 

从结构意义上而不是数字意义上来说，约束很小。 最多有 18 个跑步者，这立即表明对跑步者子集的任何指数推理都是可能可接受的。 网格大小以大约 100 为界，因此每个车道的周长都很小，大约有几百个单元格。 这使得显式模拟或预先计算每个车道的运动周期变得可行。 

最重要的隐藏结构是每个跑步者沿着固定的周期周期性地移动。 一旦我们将车道上的位置映射到周期上的索引，每个条件（例如“跑步者在 Rp 行上”）就变成了一组以周期长度为模的时间同余式。 

一些边缘情况很重要：

 一个问题是一条车道可能与摄影师的行或列多次相交。 例如，跑步者可能在单个周期内的同一行上有两个不同的位置，从而产生多个有效时间残差。 

另一个问题是，对于某些通道，所需的行或列上可能没有位置。 在这种情况下，只有当我们选择不同类型的约束时才能满足该车道，否则整个配置是不可能的。 

最后，所有跑步者的组合条件是全局的：我们不需要每个跑步者分别位于行和列上，但我们需要每个跑步者有一致的选择，以便所有约束同时对齐。 

## 方法

 思考问题的一种天真的方法是逐步模拟时间。 每一秒，我们都会沿着其车道移动每个跑步者，然后检查所有跑步者是否都位于 Rp 行或全部位于 Cp 列。 由于每个车道的周期长度最多为几百个，并且我们可能需要模拟多个周期的最小公倍数，因此这种方法很快就变得不可行。 即使我们以合理的界限（例如 10^6 秒）截断，也不能保证答案会提前出现。 

关键的观察是每个跑步者都按照确定的循环移动。 我们不再考虑随时间变化的绝对网格位置，而是将每个车道重新参数化为圆形阵列。 通道上的每个单元都分配有一个索引，时间 t 对应于简单的模块化移位。 一旦完成，条件“跑步者在特定行或列上”就变成了循环上的一组特定索引，从而成为一组形式为 t ≠ a (mod L) 的同余式。 

因此，对于每个跑步者，我们获得一小组描述有效时间的算术级数。 每个跑步者都可以通过行对齐或列对齐来满足摄影师的要求，因此每个跑步者都贡献了多种可能的模块化约束。

全局要求是我们为每个跑步者选择一个有效条件，以便所有选择的同余都一致。 一旦形成一致的同余系统，它就定义了以联合循环结构为模的唯一时间。 我们可以使用广义 CRT 合并来检查一致性，因为模数不能保证互质。 

由于 n ≤ 18，我们可以使用深度优先搜索或迭代 DP 探索每个跑步者的选择组合，尽早修剪不一致的部分合并。 每个状态都保留代表所有先前选择的合并同余。 

这将问题从时间模拟转变为约束模块化方程合并，其中复杂性由跑步者的数量而不是时间范围决定。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力模拟 | O(T·n) | O(T·n) | O(1) | O(1) | 太慢了|
 | 模块化约束合并选择 | O(4^n · n) 最差，严重修剪 | O(n) | 已接受 |

 ## 算法演练

 ### 1. 将每个车道建模为一个循环

 每条车道都是一个从草地向外扩展的矩形。 我们按逆时针顺序枚举所有边界单元，并为它们分配从 0 到 Li − 1 的索引，其中 Li 是车道 i 的周长。 

跑步者的运动变成了一个简单的规则：如果他的起始位置对应于索引 si，那么 t 秒后他位于索引 (si + t) mod Li。 

这消除了几何形状并将运动简化为模运算。 

### 2. 将行和列条件转换为模块化集

 对于固定车道，我们扫描其周期的所有索引。 每当一个位置位于 Rp 行上时，我们就记录它的索引。 每个这样的索引 x 都会产生一个同余：

 t = (x − si) mod Li。 

我们对 Cp 列执行相同的操作。 

因此，每个通道最多产生四个算术级数，每个算术级数都由余数和模数完全描述。 

### 3. 将每条车道视为约束条件中的一个选择

 对于每个跑步者，我们可以通过他的任何一个有效同余来满足他的要求。 因此，每个车道都贡献一小组候选模方程。 

我们必须为每个通道选择一个方程，并且所有选择的方程必须同时满足。 

### 4. 使用通用 CRT 增量合并约束

 我们维护一个由 (mod, rem) 描述的当前系统，意思是：

 t = rem (mod mod)。 

最初，没有任何限制。 

当我们选择一个新的同余 t ≡ a (mod m) 时，我们将其与当前系统合并。 如果存在矛盾，我们就丢弃这个分支。 

否则，我们更新到组合同余。 

该合并使用标准扩展欧几里得方法来求解：

 rem + k·mod = a + t·m。 

### 5. 通过剪枝搜索选择

 我们逐条迭代车道。 对于每个通道，我们尝试每个候选同余，并尝试将其合并到当前状态。 无效的合并将被立即跳过。 

当所有车道都被处理后，我们获得了一个同时描述所有跑步者的有效系统。 

答案是最终合并同余的最小非负解。 

### 为什么它有效

 每条车道的运动都是完全周期性的，并且每个空间条件都精确地映射到以该周期为模的时间残差。 任何有效的照片时刻都对应于每个泳道一致选择的一个残基类别。 相反，任何一致的选择都会产生所有选择的条件同时成立的时间。 合并过程保留了部分选择和可行时间集之间的等价性，因此不会遗漏有效配置，也不会保留无效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from math import gcd

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def merge(a1, m1, a2, m2):
    g, x, y = egcd(m1, m2)
    diff = a2 - a1
    if diff % g != 0:
        return None
    lcm = m1 // g * m2
    k = (diff // g * x) % (m2 // g)
    res = (a1 + m1 * k) % lcm
    return res, lcm

def build_cycle(RL, CL, RR, CR, i):
    r1, c1 = RL - i, CL - i
    r2, c2 = RR + i, CR + i
    cells = []

    r, c = r1, c1
    for j in range(c1, c2):
        cells.append((r, j))
    for i2 in range(r1, r2):
        cells.append((i2, c2))
    for j in range(c2, c1, -1):
        cells.append((r2, j))
    for i2 in range(r2, r1, -1):
        cells.append((i2, c1))
    return cells

n = int(input())
RL, CL, RR, CR, Rp, Cp = map(int, input().split())

lanes = []
for i in range(1, n + 1):
    ri, ci = map(int, input().split())
    cycle = build_cycle(RL, CL, RR, CR, i)
    pos_index = {cycle[k]: k for k in range(len(cycle))}
    si = pos_index[(ri, ci)]
    L = len(cycle)

    options = []

    for k, (r, c) in enumerate(cycle):
        if r == Rp:
            a = (k - si) % L
            options.append((a, L))
        if c == Cp:
            a = (k - si) % L
            options.append((a, L))

    lanes.append(options)

ans = None

def dfs(i, cur_a, cur_m):
    global ans
    if i == n:
        if ans is None or cur_a < ans:
            ans = cur_a
        return
    for a, m in lanes[i]:
        if cur_m == 0:
            dfs(i + 1, a % m, m)
        else:
            merged = merge(cur_a, cur_m, a % m, m)
            if merged is None:
                continue
            na, nm = merged
            dfs(i + 1, na, nm)

dfs(0, 0, 0)

print(ans if ans is not None else -1)
```该解决方案首先将每个车道显式构建为坐标循环。 从坐标到索引的映射是必要的，以便移动成为简单的模块化移位。 

对于每个泳道，我们计算跑步者位于摄影师的行或列上的所有有效时间残差。 每个这样的残基都成为候选同余。 

然后，深度优先搜索在每个泳道中精确选择一个同余，并逐步合并它们。 合并功能使用扩展 gcd 确保一致性，并尽早拒绝不兼容的组合。 

最后，报告所有一致系统的最小有效时间。 

## 工作示例

 ### 示例 1

 考虑一个具有少量车道的简化场景，其中早期就存在有效的路线。 DFS 将探索每个泳道的候选同余式并快速找到一致的集合。 

| 步骤| 处理巷 | 选择同余| 当前（mod，rem）|
 | --- | --- | --- | --- |
 | 1 | 1 | 行约束| （L1，r1）|
 | 2 | 2 | 列约束 | 合并系统|
 | 3 | 3 | 行约束| 最终系统|

 该跟踪显示了每个通道如何独立地贡献模块化约束，并且系统逐渐锁定到单个一致时间。 

### 示例 2

 现在考虑一种情况，其中一条车道与先前选择的约束发生矛盾。 

| 步骤| 处理巷 | 尝试约束| 结果 |
 | --- | --- | --- | --- |
 | 1 | 1 | 行约束| 已接受 |
 | 2 | 2 | 列约束 | 已接受 |
 | 3 | 3 | 冲突约束| 被拒绝 |

 这里，合并函数通过 gcd 检查检测到不一致，并立即修剪分支，防止无效的全局分配。 

这些例子表明，正确性完全取决于模块一致性传播而不是几何模拟。

 ## 边缘情况

 当车道从未与摄影师所在的行或列相交时，就会出现一种边缘情况。 在这种情况下，该通道的 DFS 分支没有有效的选择，整个配置立即失败。 这是自然处理的，因为如果不选择同余，递归就无法继续。 

当车道在一个周期内多次与同一行或列相交时，就会出现另一种边缘情况。 例如，矩形可以在左侧和右侧都与Rp交叉。 这会产生多个有效残基，并且算法正确地将它们视为单独的选择，其中任何一个都可能导致全局解决方案。 

最后一个微妙的情况是所有通道已在零时间对齐。 在这种情况下，每个通道都贡献与余数为零的同余，并且合并的系统立即解析为 t = 0，这被正确地返回为最小可能时间。
