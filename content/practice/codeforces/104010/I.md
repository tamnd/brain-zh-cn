 ## 解决方案
 ## 问题理解

 我们有一个杂技演员的集合，每个杂技演员都由两个属性描述：一个类似高度的值$a_i$和一个类似重量的值$b_i$。 我们需要将所有杂技演员排成一行，产生索引的排列。 

控制有效性的约束是局部的：最终排序中的任何三个连续的杂技演员都必须满足涉及在三元组上定义的“效率”函数的条件。 对于三人房$(i, j, k)$，效率为$$a_i b_j + a_j b_k + a_k b_i.$$条件表示对于阵容中的每个连续三元组，前向顺序的效率$(i, j, k)$至少与相反顺序的效率一样大$(k, j, i)$。 展开这两个表达式，比较仅取决于三个元素的成对相互作用。 

任务是构造所有索引的任意排列，使得这个不等式对于每个长度为 3 的窗口都成立。 

输入尺寸$n \le 1000$排除对所有排列进行三次或更差的检查，因为即使验证单个排列也会天真地花费$O(n)$三元组，尝试排列是阶乘。 我们应该期望基于排序或带有成对键的贪婪排序的构造。 

一个微妙的点是，条件并不像按一个参数排序这样简单的方式对称。 该表达式混合了两者$a$和$b$跨位置，所以天真的排序$a_i$,$b_i$， 或者$a_i/b_i$即使看起来合理，也可能会失败。 

朴素排序的一个小故障场景是当两个杂技演员有很大的$a$但很小$b$，另一个有小$a$但很大$b$。 任何单参数排序都可能错误地放置它们，从而破坏局部三重约束，即使成对比较表明情况并非如此。 

## 方法

 蛮力的观点是尝试逐步构建排列，并在每一步中确保每个新形成的三元组都满足不等式。 这会导致回溯或检查所有排列。 即使尽早修剪，搜索空间仍然是指数级的，并且每次部分验证都需要扫描相邻的三元组，这使得它不可行。 

关键的观察是，条件仅取决于三元组，但是一旦我们修复了点的一致变换，每个三元组比较就可以重写为相邻元素之间的成对排序规则。 表达式$$a_i b_j + a_j b_k + a_k b_i \ge a_k b_j + a_j b_i + a_i b_k$$可以重新排列以隔离涉及索引对的项。 简化后，不等式等效于基于导出标量的一致排序条件：$$a_i b_j - a_j b_i + a_j b_k - a_k b_j + a_k b_i - a_i b_k \ge 0.$$这种望远镜的结构表明每个元素在变换的空间中线性贡献，并且三重条件在该空间中强制执行单调排序。 

解释这种情况的标准方法是为每个 acrobat 分配一个类似斜率的值$a_i / b_i$。 然而，按斜率直接排序是不够的，因为不等式涉及三个位置上的循环交互，而不仅仅是相邻比较。 

正确的见解是，该条件强制要求对于任何连续的三元组，中间元素的行为就像一个枢轴，与点之间的叉积方向排序一致$(b_i, a_i)$。 这将问题简化为按几何角度排序或等效地按叉积符号排序：$$(b_i, a_i) \times (b_j, a_j) = b_i a_j - a_i b_j.$$因此，通过增加比率来排序杂技演员$a_i / b_i$（或等效地排序$a_i b_j$比较）确保所有相邻三元组的一致性。 

这将全局三重约束转换为简单的全序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n!)$|$O(n)$| 太慢了|
 | 最优（按比例排序）|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将每个杂技演员转换为 2D 平面中的一个点，并根据它们的相对斜率施加排序。 

1. 代表每位杂技演员$i$作为一对$(a_i, b_i)$。 这允许使用交叉乘法来比较两个 acrobat，而无需除法。 
2. 定义两个 acrobat 之间的排序规则$i$和$j$:$i$应该先来$j$如果$$a_i b_j < a_j b_i.$$这比较了它们的比率，没有浮点错误。 

1. 使用此比较器对所有索引进行排序。 这产生了与增加一致的总订单$a_i / b_i$。 
2. 将排序后的索引输出为所需的阵容。 

不明显的部分是为什么当约束是关于三元组时纯粹的成对排序就足够了。 原因是，一旦顺序与增加的斜率一致，任何三个连续元素的比率都保持单调关系，这迫使正向和反向三元组之间的效率差异具有固定的符号。 

### 为什么它有效

 排序后，对于任意连续的三元组$i < j < k$，我们有$$\frac{a_i}{b_i} \le \frac{a_j}{b_j} \le \frac{a_k}{b_k}.$$这种单调性确保效率表达式中的交叉项对齐，以便交换三元组可以反转一致伸缩表达式的符号。 因此，正向排列总是支配或匹配反向排列，满足每个连续三元组所需的不等式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
arr = []
for i in range(n):
    a, b = map(int, input().split())
    arr.append((a, b, i + 1))

arr.sort(key=lambda x: (x[0] / x[1], x[0]))

print(*[x[2] for x in arr])
```该解决方案构建了一个杂技演员列表并按比例对他们进行排序$a_i / b_i$。 抢七局由$a_i$当比率相等时确保确定性排序。 

排序步骤是唯一重要的操作。 使用浮点除法在概念上很简单，但可以用叉积比较器代替以避免精度问题。 输出是原始索引的排列。

 ## 边缘情况

 当许多杂技演员具有相同的比率时，就会出现一种边缘情况$a_i / b_i$。 在这种情况下，比较器退化，并且它们之间的任何顺序都是可接受的，因为交换等比元素不会改变叉积比较。 该算法仍然会产生有效的排列，因为所有比较的计算结果都是相等的，从而使任意的平局打破变得无害。 

另一个边缘情况是当$b_i$非常大或非常小，这可能会破坏浮点除法的稳定性。 使用整数交叉乘法可以完全避免这种情况，因为比较仅依赖于整数的乘积，在给定的约束下，整数乘积保持在 64 位范围内$10^9$。
