 ## 解决方案
 ## 问题理解

 我们给定一个字符串，想要删除最少数量的字符，以便结果字符串不再包含`"pie"`或者`"map"`作为子串。 

关键细节是删除可以发生在任意位置。 我们不会重新排列角色，只是删除其中一些角色。 每次出现`"pie"`或者`"map"`必须以某种方式被打破。 

所有测试用例的字符串长度可以达到`10^6`，这立即排除了任何二次方。 一个`O(n^2)`解决方案将执行大约`10^12`operations in the worst case, far beyond the limit. 我们需要接近线性时间的东西。 

A first instinct might be to repeatedly search for`"pie"`和`"map"`并从每次出现的位置删除一个字符。 这在很大程度上是有效的，但是重叠的模式会产生棘手的情况，其中一次删除可能会同时破坏两个坏的子字符串。 

经典的例子是：```
mapie
```该字符串包含两个`"map"`和`"pie"`:```
mapie
^^^
  ^^^
```粗心的贪婪解决方案可能会分别计算并回答`2`。 但是删除中间的字符`'p'`同时销毁两个子字符串，所以正确答案是`1`。 

当多个坏子串仅部分重叠时，会出现另一种边缘情况。 考虑：```
mapmap
```两人`"map"`事件的发生是独立的：```
mapmap
^^^
   ^^^
```一次删除不能破坏两次出现的情况，所以答案是`2`。 

非常短的字符串也很重要。 对于输入：```
p
```不可能存在长度为 的子串`3`，所以答案是`0`。 盲目检查的实现`s[i:i+3]`无边界处理可能会在这里出错。 

最后一个微妙的情况是重复重叠：```
pppiepieeee
```出现的情况有：```
pppiepieeee
  ^^^
     ^^^
```它们不会以有用的方式重叠，因此我们确实需要删除两次。 

## 方法

 暴力策略是尝试每组可能的删除，并检查结果字符串是否变得漂亮。 这显然是正确的，因为它探索了所有的可能性，但却是完全不可行的。 甚至决定每个角色是保留还是删除它也会产生`2^n`的可能性。 

更合理的暴力改进是重复扫描字符串`"pie"`和`"map"`，只要找到一个字符就删除一个字符。 由于每个坏子串都有长度`3`，删除其中的任何一个字符都会破坏该事件。 

问题在于重叠处理。 如果我们贪心地处理`"map"`首先里面`"mapie"`，我们可以删除`'m'`或者`'a'`，那么还有`"pie"`其余的。 我们最终使用了两次删除而不是一次删除。 

关键的见解是，两者之间唯一有用的重叠`"map"`和`"pie"`是特殊图案：```
mapie
```在这种模式中，一次删除就足以销毁两个坏子串。 具体来说，去掉中央`'p'`作品。 

在这种情况之外，每次发生`"map"`或者`"pie"`必须独立贡献至少一项删除。 

所以最优策略变为：

 1. 从左到右扫描字符串。 
2.首先检查是否`"mapie"`从当前位置开始。 
3. 如果是，则计算一次删除并跳过整个模式。 
4. 否则，检查是否`"map"`或者`"pie"`从那里开始。 
5. 如果是，则计数一次删除并跳过该子串。 

这有效是因为`"mapie"`与单独处理两个模式相比，这是唯一的重叠，一次删除可以节省工作量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 贪婪线性扫描| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将应答计数器初始化为`0`。 

该变量存储所需的最小删除次数。 
2. 使用索引从左到右扫描字符串`i`。 

我们检查从每个位置开始的子字符串。 
3.首先检查子串是否开始于`i`是`"mapie"`。 

这是关键的重叠情况。 如果我们处理`"map"`或者`"pie"`首先，我们可能会不小心使用两个删除而不是一个。 
4. 如果`"mapie"`找到后，将答案增加`1`并移动`i`转发通过`5`。 

一次删除会破坏两个坏子字符串，并且该块内的任何字符都不需要重新考虑。 
5. 否则，检查子串是否以`i`是`"map"`或者`"pie"`。 

每次出现此类情况都需要删除一次。 
6. 如果找到任一子字符串，则将答案增加`1`并移动`i`转发通过`3`。 

从该子字符串中删除一个字符后，整个事件就变得无害了。 
7. 如果没有坏子串开始于`i`，移至下一个字符。 
8. 扫描完成后，输出答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        if i + 4 < n and s[i:i + 5] == "mapie":
            ans += 1
            i += 5
        elif i + 2 < n and (s[i:i + 3] == "map" or s[i:i + 3] == "pie"):
            ans += 1
            i += 3
        else:
            i += 1

    print(ans)
```该实现直接遵循前面描述的贪婪扫描。 

第一个条件检查`"mapie"`在做其他事情之前。 这个顺序很重要。 如果我们检查`"map"`首先，然后`"mapie"`将被错误地计为两次删除。 

边界检查也很重要：```
i + 4 < n
```保证`s[i:i+5]`检查有效`"mapie"`。 

相似地：```
i + 2 < n
```保护长度为 3 的子字符串检查。 

向前跳过`5`或者`3`避免重新处理已经属于已处理的错误子字符串的字符。

## 边缘情况

 第一个棘手的情况是重叠模式：```
mapie
```算法检查`"mapie"`前`"map"`或者`"pie"`。 在索引处`0`，它会检测到完全重叠并仅添加一个删除。 然后它会跳过所有五个字符。 最终答案变成`1`，这是最优的。 

现在考虑独立事件：```
mapmap
```在索引处`0`，算法发现`"map"`并将答案增加到`1`。 它跳过三个位置并落在第二个位置`"map"`，这需要再次删除。 结果是`2`。 

对于非常短的字符串：```
p
```条件：```
i + 4 < n
i + 2 < n
```两者都会立即失败，因此不会发生子字符串检查。 答案依然存在`0`。 

最后，检查重复模式：```
pppiepieeee
```扫描到达第一个`"pie"`并计算一次删除。 向前跳转后，到达第二个`"pie"`并数另一个。 由于这些事件不重叠，所以正确答案是`2`。
