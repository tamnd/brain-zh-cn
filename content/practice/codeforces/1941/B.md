 ## 解决方案
 # 问题理解

 我们得到一个非负整数数组。 在一次操作中，我们选择一个索引$i$这样$2 \le i \le n-1$，并按以下方式减少三个连续元素：$$a_{i-1} \mathrel{-}= 1,\quad a_i \mathrel{-}= 2,\quad a_{i+1} \mathrel{-}= 1$$该操作可以在任何有效索引上使用任意次数。 目标是确定是否可以将整个数组减少到全零。 

重要的细节是每个操作仅减去值。 我们永远不允许增加一个元素。 因此，一旦某个元素变为负数，则该过程无效。 正确的解决方案必须确定是否存在某种将数组转换为全零而不需要负值的操作序列。 

约束足够大，效率很重要：

 | 约束| 寓意 |
 | --- | --- |
 |$t \le 10^4$| 我们必须有效地处理许多测试用例。 |
 |$\sum n \le 2 \cdot 10^5$| 一个$O(n)$或者$O(n \log n)$每个测试用例的解决方案都是安全的。 |
 |$a_i \le 10^9$| 如果操作数量很大，我们就无法一一模拟。 |
 | 时间限制：2秒| 所有测试用例的总工作量应保持接近线性。 |
 | 内存限制：256 MB | 存储数组和一些辅助变量是完全没问题的。 |

 重复应用操作的简单模拟将会失败，因为元素可能大到$10^9$，导致数十亿次操作。 

一些边缘情况很容易被错误处理。 

### 数组已经等于零

 如果每个元素都已为零，则答案应立即为“是”。 粗心的实现可能仍会尝试执行操作并意外地拒绝该案例。 

### 小数组

 最小尺寸为$n=3$。 在这种情况下，只能选择中间的索引。 该解决方案必须正确处理仅存在一个操作位置的数组。 

### 贪婪处理期间的负值

 假设我们尝试从左到右消除值。 如果在某个时刻所需的操作计数超过了相邻元素中的可用数量，则其中一个变为负数。 这立即证明配置是不可能的。 

例如：$$[1,1,1,1]$$尝试消除第一个元素需要在索引 2 处执行一次操作，但这会将第二个元素减少 2 并使其变为负值。 

### 非零尾部元素

 即使左侧成功变为零，最后两个元素也可能保持非零。 由于操作会影响三个连续位置，因此一旦我们处理完左侧，就无法独立修复尾部。 正确的算法必须显式验证最终数组。 

# 方法

 ## 蛮力

 一个简单的想法是重复搜索有效的操作并应用它，直到无法进行更多操作为止。 例如，我们可以选择任何索引$i$在哪里：$$a_{i-1} \ge 1,\quad a_i \ge 2,\quad a_{i+1} \ge 1$$并不断减法。 

这种做法在逻辑上是正确的，因为每次操作都严格减少数组的总和，因此该过程最终终止。 如果我们全部为零，答案就是“是”。 否则，为“否”。 

问题是效率。 考虑一个包含附近值的数组$10^9$。 手术数量也可能接近$10^9$，使得在时限内无法进行直接模拟。 

因此，蛮力太慢了。 

## 最佳方法

 关键的观察结果是，操作结构强制采用自然的从左到右的贪婪策略。 

假设我们当前正在检查位置$i$。 唯一可以减少的操作$a_i$虽然仍影响其右侧的元素，但操作集中于$i+1$。 

这意味着一旦我们超过索引$i$，我们将永远无法再修改它。 因此，如果$a_i$此时不为零，唯一有效的选择是应用以下操作：$i+1$确切地$a_i$次。 

这创建了一个确定性过程。 

如果我们应用操作$x=a_i$中心时间$i+1$:$$a_i \mathrel{-}= x$$

$$a_{i+1} \mathrel{-}= 2x$$

$$a_{i+2} \mathrel{-}= x$$自从$x=a_i$，当前元素立即变为零。 

如果任一相邻值变为负值，则不存在有效序列。 

通过从左到右的处理，当每个元素永久固定时，我们贪婪地消除它。 最后，如果所有元素都为零，则可以进行转换。

 # 算法演练

 1. 读取数组。 
2. 从左到右处理索引，具体是从$0$到$n-3$。 
3. 各位置$i$， 让：$$x = a_i$$由于以后的操作无法修改$a_i$除非通过以中心为中心的操作$i+1$，我们现在就必须消除它。 
4.应用操作$x$时间概念上：$$a_i \mathrel{-}= x$$

$$a_{i+1} \mathrel{-}= 2x$$

$$a_{i+2} \mathrel{-}= x$$5. 更新后，检查是否：$$a_{i+1} < 0 \quad \text{or} \quad a_{i+2} < 0$$如果是，则输出“NO”。 
6.继续处理直到索引$n-3$。 
7. 完成所有操作后，验证每个元素是否为零。 
8. 如果整个数组为零，则输出“YES”。 否则，输出“NO”。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    possible = True

    for i in range(n - 2):
        x = a[i]

        a[i] -= x
        a[i + 1] -= 2 * x
        a[i + 2] -= x

        if a[i + 1] < 0 or a[i + 2] < 0:
            possible = False
            break

    if possible and all(v == 0 for v in a):
        print("YES")
    else:
        print("NO")
```该程序以快速 I/O 开始，因为总输入大小可以达到$2 \cdot 10^5$。 

对于每个测试用例，我们从左到右迭代。 在位置`i`，当前值`a[i]`准确确定必须应用多少个操作。 我们将此值存储在`x`。 

更新内容：```
a[i + 1] -= 2 * x
a[i + 2] -= x
```模拟执行操作`x`次。 

如果任一更新值变为负数，则配置不可能，因此我们提前终止。 

最后，我们验证每个元素都恰好为零。 最后的检查至关重要，因为即使没有更多操作可用，最后两个元素也可能保持为正。
