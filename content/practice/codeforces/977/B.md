 ## 解决方案
 ## 问题理解

 我们得到一串大写英文字母，并要求我们查看其中每对相邻的字符。 每个这样的相邻对形成“双字母模式”，例如字符串“ABAC”包含“AB”、“BA”和“AC”。 

任务是找出这两个字母模式中哪一个最常作为连续子字符串出现。 由于子字符串是由连续位置定义的，因此自然允许重叠，因此像“AAA”这样的模式包含两次“AA”。 

输出不是计数本身，而是达到最大频率的任何模式。 如果多个模式并列，则其中任何一种都可以接受。 

输入大小较小，最多 100 个字符。 这立即表明，即使二次推理也足够了，因为相邻对的总数只有 n−1，最多 99 个。 

一个微妙的点是，我们并不是独立搜索所有可能的 26×26 模式。 我们只关心那些实际出现在字符串中的相邻子串。 这消除了输入中根本不存在的“ZZ”等模式的任何歧义。 

边缘情况主要与短字符串有关。 当n = 2时，正好有一个二元组，必须返回它。 当所有字符都相同时，例如“AAAAA”，正确答案是“AA”，并且由于重叠而出现多次。 粗心的实现可能会尝试消除重复的事件或将它们视为不重叠，这是不正确的。 

## 方法

 一个蛮力的想法是采用每对可能的位置 (i, j) 并检查 s[i:i+2] 是否与所有其他子字符串匹配。 这将导致 O(n²) 个候选者，并且对于每个候选者进行另一次 O(n) 扫描，从而产生 O(n³)。 尽管 n 很小，但这对于这种直接计数任务来说是不必要的，而且在概念上很笨拙。 

更自然的暴力方法是生成所有长度为 2 的子字符串并使用字典对它们进行计数。 这将问题简化为 n−1 个元素的频率计数。 每个子串的提取都是 O(1)，因此总复杂度与 n 呈线性关系。 

关键的观察是，我们没有构建任何全局的或依赖于远程结构的东西。 每个有效答案完全由本地邻接决定，因此一次通过就足够了。 这将问题简化为计算固定大小的对流中的频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举+重新比较 | O(n3) | O(1) | O(1) | 太慢了 |
 | 相邻对的滑动计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从左到右扫描字符串，考虑从 0 到 n−2 的每个索引 i，并提取两个字母的子串 s[i]s[i+1]。 此步骤将问题转换为重叠观察流。 
2. 维护一个频率图，记录到目前为止每个两个字母模式出现的次数。 每个新的子字符串都会增加其计数器。 
3. 扫描时跟踪当前最佳模式及其频率。 当模式的频率超过迄今为止的最佳频率时，更新最佳模式和最佳计数。 
4. 处理完所有相邻对后，输出存储的最佳模式。 

我们可以在扫描期间安全地贪婪地更新答案的原因是，未来的更新仅取决于未来的对，并且计数只会增加。 以前的最佳配对不会变得无效或频率降低。 

### 为什么它有效

 每个 2-gram 的出现都是独立的，并且仅由大小为 2 的固定窗口决定。 该算法对每个此类窗口精确计数一次。 由于频率图存储精确的计数，并且我们始终保持所有可见值的最大值，因此最终存储的对必须是全局最大值之一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    freq = {}
    best = ""
    best_cnt = 0

    for i in range(n - 1):
        pair = s[i:i+2]
        freq[pair] = freq.get(pair, 0) + 1

        if freq[pair] > best_cnt:
            best_cnt = freq[pair]
            best = pair

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案使用对字符串的单次传递。 子串提取`s[i:i+2]`是常数时间，因为切片长度是固定的。 字典维护准确的频率，并且仅当观察到严格更大的计数时才更新最佳对，从而确保确定性行为，而无需第二次通过。 

一个常见的错误是迭代到 n 而不是 n−1，这会尝试访问超出范围的子字符串。 另一个是忘记重叠对是有效的，这在这里自然得到处理，因为每个索引恰好贡献从它开始的一对。

 ## 边缘情况

 对于长度为 2 的字符串（例如“XY”），循环只运行一次。 唯一的一对是“XY”，因此它立即成为频率为 1 的答案。 

对于像“AAAAA”这样的重复字符，每个索引贡献“AA”，因此计数累加到 4。该算法从不尝试消除重复的出现； 它只是增加每个观察到的窗口。 

对于像“ABABAB”这样的交替字符串，“AB”和“BA”都会出现多次。 每当发生严格增加时，算法都会更新最佳值，因此达到最大值的第一对仍然是有效输出。
