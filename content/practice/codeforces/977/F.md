 ## 解决方案
 ## 问题理解

 我们按照出现的顺序给出了一个整数序列。 我们希望从这个序列中挑选一些元素，同时保留顺序，但我们只允许保留一个看起来像一串连续整数的子序列，每一步只增加一个，例如$x, x+1, x+2, \dots$。 The task is to find the longest such subsequence and output both its length and the original positions of the chosen elements.

 关键的困难在于值不一定是唯一的，并且它们没有排序，因此我们无法直接扫描值空间中的连续段。 We must respect the original ordering, which turns this into a dynamic programming problem over indices with value-based transitions.

 The input size goes up to$2 \cdot 10^5$，这排除了任何元素的二次配对。 任何比较所有对或尝试天真地扩展子序列的解决方案都将涉及以下顺序：$n^2$在最坏的情况下，操作速度太慢了。 这迫使我们采用使用散列或映射的线性或近线性方法。 

当值重复多次时，会出现微妙的边缘情况。 例如，如果数组是$[5, 5, 5, 5]$，任何有效子序列的长度只能为 1，因为无法形成连续的结构。 在这种情况下，尝试链接相等值或未能强制执行严格的 +1 转换的天真贪婪方法会错误地过度计数。 

另一个棘手的情况是当存在多个具有相同价值结构但不同索引选择的有效链时。 例如，在$[3, 3, 4, 4]$, 链条$3 \to 4$可以使用不同的出现来形成，并且我们仍然必须恢复有效的索引子序列，而不仅仅是计算长度。 

## 方法

 强力策略是考虑每个起始位置，并尝试通过扫描所有后续元素寻找下一个所需值来向前延伸链。 对于每次开始，我们都会重复搜索下一个值$x+1$， 然后$x+2$， 等等。 即使我们使用线性扫描，每个起点也可能触发数组的另一次全扫描，从而导致$O(n^2)$最坏情况下的行为。 和$2 \cdot 10^5$元素，这是完全不可行的。 

关键的观察是，当我们处于某个值时$v$，延长一条链所需的唯一有用信息是以价值结尾的最佳链$v-1$。 这建议为每个值维护以该值结尾的最佳子序列长度。 如果我们从左到右处理数组，则每次出现$a[i]$可以延长一条终止于$a[i]-1$，因此我们可以计算结束于的最佳链$a[i]$使用哈希映射在恒定时间内。 

我们为每个值存储两条信息：以该值结束的链的最佳长度，以及该链最后出现的索引，以便我们可以重建解决方案。 当我们迭代时，我们更新这些地图并跟踪迄今为止看到的最佳端点。 

这将问题简化为通过字典查找对数组进行单次传递，从而将对比较的二次依赖转变为线性时间散列。

 ## 算法演练

 我们维护三个哈希映射：一个用于以某个值结束的最佳长度，一个用于重建链的前驱索引，一个用于跟踪每个值的最佳出现的索引。 

1.从左到右遍历数组，处理position处的每个元素$i$。 在每一步我们都会考虑价值$v = a[i]$。 
2. 计算可以结束于的最佳链$v$。 这是通过查看结束于的最佳链获得的$v-1$。 如果不存在这样的链，我们将开始一条长度为 1 的新链。此步骤之所以有效，是因为任何有效的连续子序列在每一步都必须恰好增加 1。 
3. 如果从$v-1$给出比任何先前记录的结束于的链更长的链$v$，我们更新最佳长度$v$并记录下来$i$是最好的结束索引$v$。 我们还存储一个来自$i$返回到获得最佳链的索引$v-1$。 
4. 处理完所有元素后，我们扫描所有值以找到链长度最大的值。 
5. 从存储的最佳值的结束索引开始，我们通过重复遵循前驱索引来重建子序列，直到到达开头。 

重建步骤是必要的，因为我们在扫描期间优化长度，但仍然需要以正确的顺序恢复实际位置。 

### 为什么它有效

 核心不变量是对于每个值$v$，我们始终保持结束于的最佳子序列$v$在迄今为止处理的所有前缀中。 当我们处理一个事件的发生时$v$，任何最优子序列结束于$v$必须来自于结束于的最优子序列$v-1$，因为任何有效的链都必须在每一步精确地递增 1 并且不能跳过值。 由于我们总是存储最好的此类子序列，因此我们永远不会错过更好的扩展。 这确保了在扫描结束时，最佳全局子序列被完全捕获在值条目之一中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

best_len = {}
prev_idx = {}
best_end_idx = {}

ans_val = 0
ans_end = -1

for i, v in enumerate(a):
    prev_len = best_len.get(v - 1, 0)
    cand_len = prev_len + 1

    if cand_len > best_len.get(v, 0):
        best_len[v] = cand_len
        best_end_idx[v] = i
        if v - 1 in best_end_idx:
            prev_idx[i] = best_end_idx[v - 1]
        else:
            prev_idx[i] = -1

        if cand_len > ans_val:
            ans_val = cand_len
            ans_end = i

res = []
cur = ans_end

while cur != -1:
    res.append(cur + 1)
    cur = prev_idx.get(cur, -1)

res.reverse()

print(ans_val)
print(*res)
```代码的主要结构是对数组的单次传递，其中每个元素尝试从值扩展链$v-1$。 这`best_len`字典存储每个值的最佳子序列长度，而`best_end_idx`记住最佳子序列的结束位置。 这`prev_idx`字典仅用于重建，将索引映射到链中的前一个索引。 

一个微妙的实现细节是，我们仅在改进某个值的最著名链时才更新状态。 这避免了用次优中间状态破坏重建指针。 另一个重要的一点是，我们在扫描期间跟踪全局最佳结束索引，因此我们不需要第二遍来找到端点。

 ## 边缘情况

 一种重要的边缘情况是在有用链已经形成之后出现的重复值。 例如，在像这样的数组中$[1, 2, 3, 2, 3]$，后来的$2, 3$对不应覆盖以较早索引结束的较长链。 该算法会处理此问题，因为更新仅在找到严格更好的长度时才会发生，因此会忽略较短或相等的链。 

另一种情况是当值很大且稀疏时，例如$[100, 1, 2, 3]$。 基于地图的转换确保只有$v-1$很重要，因此缺少中间值会正确地中断链并以长度 1 重新启动它们，而无需任何特殊的外壳。 

最后一种情况是存在多个最佳答案。 由于我们只需要任何有效的子序列，因此存储的前驱指针可以表示任何最佳路径，并且重建仍然会产生正确的索引序列。
