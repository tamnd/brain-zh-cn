 ## 解决方案

 ## 问题理解

 给定一个无向图，任务是计算有多少个连通分量形成一个简单的循环。 当一个组件的所有顶点都可以排列在一个环中，使得每个顶点在该组件内恰好有两个邻居，并且除了形成环的边之外没有额外的边时，该组件被认为是一个循环。 

用图术语来说，这意味着我们正在寻找连接的组件，其中每个顶点在该组件内的度数恰好为 2。 具有额外分支或内部和弦的组件是不合格的，即使它内部某处包含循环。 像三角形或正方形这样的孤立循环是有效的，但任何“循环加尾部”结构都是无效的。 

约束允许最多 200,000 个顶点和边。 这会立即排除任何尝试重复检查所有子集或重新计算连接的行为。 任何解决方案都必须在线性或近线性时间内运行，因此图遍历（例如 DFS、BFS 或基于 DSU 的分组）是必要的。 

一些微妙的边缘情况自然会出现。 

具有恰好一个周期但有额外边的单个连接组件会破坏该条件。 例如，附加了额外叶节点的三角形是相连的并且包含环，但不是环分量。 正确答案贡献为零。 

纯循环必须至少具有三个顶点。 即使两个顶点的度数均为 1，具有单边的尺寸为 2 的分量也是无效的，因为它无法形成闭环。 

最后，孤立的顶点或树总是无效的，因为它们不包含每个顶点都具有二度的循环。 

## 方法

 一种强力的想法是计算连接的组件，并针对每个组件明确验证它是否形成循环。 我们可以通过收集组件中的所有顶点，然后检查两个条件来做到这一点：每个顶点在组件内的度数正好为 2，并且边的数量等于顶点的数量。 这是有效的，因为在任何简单的循环中，边和顶点在闭环中一对一匹配。 

幼稚方法的问题仅出现在实施效率低下，而不是正确性。 如果我们反复扫描邻接列表或低效地重新计算组件成员资格，我们可能会转向二次行为。 然而，即使是一次收集组件并检查度数的简单 DFS 仍然是线性的。 

关键的观察是，当且仅当连接组件中的每个顶点在组件内的度数恰好为 2 时，连接组件才是循环。 这消除了边缘计数或结构重建的需要。 在遍历过程中，我们可以计算组件大小和内部度数之和，或者简单地验证组件中所有节点的度数条件。 

我们使用 DFS 或 BFS 来探索每个组件一次，标记访问过的节点。 对于每个组件，我们检查所有顶点是否满足度数等于 2。 如果是，则该组件是一个循环。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（反复重新检查结构）| O(n²) | O(n) | 太慢了 |
 | 带学位验证的 DFS/BFS | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

1. 构建图的邻接列表表示。 这允许在遍历期间对每个顶点的邻居进行恒定时间迭代。 
2. 维护一个所有顶点都初始化为 false 的已访问数组。 这确保了每个节点在所有组件中只被处理一次。 
3. 迭代从 1 到 n 的每个顶点。 如果某个顶点未被访问，它将成为新的连通分量的起点。 
4. 从该顶点运行 DFS 或 BFS，将所有可到达的节点标记为同一组件的一部分。 在遍历过程中，将属于该组件的所有顶点收集到一个列表中。 
5. 遍历完一个组件后，检查该组件中的每个顶点，并验证其邻接表大小是否恰好为 2。此条件强制每个顶点恰好参与该组件内的两条边，这是循环所必需的。 
6. 如果组件中的所有顶点都满足此条件并且组件至少有 3 个顶点，则增加答案。 
7. 继续，直到处理完所有顶点，然后输出最终计数。 

### 为什么它有效

 在任何连接的组件中，如果每个顶点的度数恰好为 2，则该结构不能分支或终止。 从任何顶点开始，后续的边最终必须返回起点，不重复，形成一个简单的循环。 相反，任何简单的循环图的每个顶点的度数恰好为 2。 因此，次数条件对于识别无向图中的循环分量既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

visited = [False] * (n + 1)

def dfs(start):
    stack = [start]
    comp = []
    visited[start] = True

    while stack:
        u = stack.pop()
        comp.append(u)
        for v in g[u]:
            if not visited[v]:
                visited[v] = True
                stack.append(v)

    return comp

ans = 0

for i in range(1, n + 1):
    if not visited[i]:
        comp = dfs(i)

        ok = True
        if len(comp) < 3:
            ok = False
        else:
            for u in comp:
                if len(g[u]) != 2:
                    ok = False
                    break

        if ok:
            ans += 1

print(ans)
```该解决方案构建邻接列表并从每个未访问的节点运行 DFS，确保每个连接的组件仅提取一次。 DFS 收集组件中的所有节点。 

提取组件后，代码首先检查其大小。 一个循环必须至少包含三个顶点，因此较小的组件会立即被拒绝。 然后它验证了循环图的定义属性：每个顶点在完整图中必须恰好有两个邻居，这在简单的连通组件中意味着它位于单个循环上。 

一个常见的错误是尝试计算组件内部的边数并与顶点进行比较，而没有仔细处理重复项或遍历状态。 使用全局邻接表度可以避免重新计算并避免微妙的簿记错误。 

DFS 是迭代的，以避免递归深度问题（给定上限为 200,000 个节点）。

 ## 边缘情况

 单个边缘组件，例如`1 - 2`处理正确，因为它的大小为 2，这不符合循环的最小大小要求。 DFS收集两个节点，检查立即拒绝它。 

一个三角形，例如`1 - 2 - 3 - 1`通过，因为所有节点的邻接表大小均为 2。DFS 将所有三个节点收集在一个组件中，并且每个节点的条件都成立。 

像这样的星图`1 connected to all others`失败，因为中心节点的度数大于 2，即使图是连通的，也违反了循环条件。
