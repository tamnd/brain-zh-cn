 ## 解决方案
 ## 问题理解

 我们得到一个整数列表并要求构造一个值$x$介于 1 和$10^9$这样正好$k$列表的元素小于或等于$x$。 如果不存在这样的值，我们必须输出$-1$。 

思考这个问题的一个有用的方法是$x$定义数轴上的阈值。 作为$x$增加，元素数量$\le x$只会增加，不会减少。 我们正在尝试找到一个点，使该计数恰好变为$k$。 

输入大小最多允许$2 \cdot 10^5$数字。 任何检查每个候选人的方法$x$直接在范围内$[1, 10^9]$是不可能的，因为这需要最多$10^9$运营。 即使以天真的方式重复检查每个数组元素也会导致大约$O(n^2)$在最坏的情况下工作，远远超出了时间限制。 

当数组中的多个值在边界周围相等时，就会出现关键边缘情况。 如果我们选择一个$x$等于数组中的某个值，元素的数量$\le x$可能会同时跳跃不止一个。 例如，如果数组是$[3, 3, 3]$和$k = 2$，没有$x$恰好产生两个元素$\le x$，因为计数从 0 跳起（对于$x < 3$) 直接到 3 (对于$x \ge 3$）。 

另一个微妙的情况是$k = 0$。 这需要一个$x$小于所有元素。 自从$x \ge 1$，只有当所有数组值都大于 1 时，这才有可能，即使这样$x = 1$可能有效也可能无效取决于任何元素是否等于 1。 

## 方法

 蛮力的想法是尝试每一个可能的整数$x$从 1 到$10^9$，并为每个计数有多少个数组元素$\le x$。 这是正确的，因为它直接符合我们想要的条件，但它执行$10^9$候选人检查，每次成本计算$O(n)$，导致$O(n \cdot 10^9)$，这是完全不可行的。 

关键的观察结果是函数“元素数量$\le x$”仅在数组中存在的值处发生变化。在两个连续的不同数组值之间，计数保持不变。这意味着我们只需要考虑数组排序值附近的阈值。

 对数组进行排序后，我们可以计算前缀长度等于的位置$k$。 如果存在这样的前缀，则任何值$x$之间的$k$-第一个最小值并且略低于$(k+1)$-th 最小值将起作用。 清洁施工是采取$k$-th 最小的元素并确保它不会意外地包含$(k+1)$-第一个。 

唯一的失败情况是当$k$-th 和$(k+1)$-th 元素相等，因为任何$x$其中一个包含所有相同的副本，因此无法准确隔离$k$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot 10^9)$|$O(1)$| 太慢了 |
 | 最优（排序）|$O(n \log n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对数组进行非降序排序。 这让我们可以直接推断前缀计数。 
2.如果$k = 0$，我们想要一个严格小于所有元素的值。 我们检查最小的元素。 如果为1，则无效$x \ge 1$存在，所以我们输出$-1$。 否则我们输出 1，因为它确保零元素$\le x$。 
3.如果$k = n$，我们希望所有元素都是$\le x$。 最大的元素总是有效，因此我们输出最大的数组值。 
4. 否则，请考虑$k$-第一个最小元素（索引$k-1$从 0 开始的索引）。 
5. 检查$(k+1)$-第一个最小元素（索引$k$）。 如果它等于$k$-th 元素，然后是任何$x$其中包括$k$-th 还包括$(k+1)$-th，所以我们无法准确实现$k$。 在这种情况下，输出$-1$。 
6. 如果不同，输出$k$-th 元素作为答案。 这准确地保证了$k$元素是$\le x$。 

### 为什么它有效

 排序后，元素个数$\le x$是一个阶跃函数，仅在不同的数组值处增加。 选择$x$等于$k$-第一个最小值确保至少$k$元素都包含在内。 如果下一个不同值严格更大，则在该间隙之后不会输入任何其他元素，因此计数保持精确$k$。 如果重复项会缩小间隙，则步长会变得太大，从而不可能完全相等。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

if k == 0:
    if a[0] == 1:
        print(-1)
    else:
        print(1)
elif k == n:
    print(a[-1])
else:
    x = a[k - 1]
    if a[k] == x:
        print(-1)
    else:
        print(x)
```排序步骤组织值，使得前缀位置对应于小于或等于阈值的元素计数。 的处理$k = 0$是分开的，因为我们无法选择$x = 0$，因此我们必须确保所选值保持在允许的范围内。 

关键检查是比较$a[k-1]$和$a[k]$。 如果它们相等，则任何包含$k$-th 元素必然包含多于$k$元素，违反了要求。 

## 工作示例

 ### 示例 1

 输入：```
7 4
3 7 5 1 10 3 20
```排序数组：$[1, 3, 3, 5, 7, 10, 20]$我们想要$k = 4$，所以我们看第四个元素（索引 3），即 5。 

| 步骤| 第 k 个值 | 第 (k+1) 个值 | 决定|
 | --- | --- | --- | --- |
 | 排序后 | 5 | 7 | 有效间隙|

 由于 5 和 7 不同，因此我们输出 5。5 到 6 之间的任何值都可以，因此 5 是有效的。 

这证实了算法正确地找到了恰好包含四个元素的阈值。 

### 示例 2

 输入：```
5 2
1 2 2 2 3
```排序数组：$[1, 2, 2, 2, 3]$我们取第二个元素（索引 1），即 2。第三个元素也是 2。 

| 步骤| 第 k 个值 | 第 (k+1) 个值 | 决定|
 | --- | --- | --- | --- |
 | 排序后 | 2 | 2 | 无效|

 由于它们相等，所以任意$x \ge 2$至少包含 3 个元素，因此恰好达到 2 个元素是不可能的。 输出是$-1$。 

这显示了重复块失败的情况。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    if k == 0:
        if a[0] == 1:
            return "-1"
        return "1"
    elif k == n:
        return str(a[-1])

 ## 边缘情况

 当所有元素都相等并且$k$不是 0 或 n，算法正确地拒绝这种情况，因为之间的相等性检查$a[k-1]$和$a[k]$立即失败。 例如，输入$[5, 5, 5]$和$k = 1$导致$a[0] = 5$和$a[1] = 5$，因此不存在有效阈值。 

为了$k = 0$，该算法确保我们永远不会选择低于 1 的值。如果最小元素是 3，则输出 1 产生零个元素$\le x$。 如果最小元素为1，则无效$x$存在于允许的范围内，所以我们正确输出$-1$。 

对于边界$k = n$，排序保证最后一个元素是最大值，因此选择它包括所有元素而不会过度计数，即使有重复项。
