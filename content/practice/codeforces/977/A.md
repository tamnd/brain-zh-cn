 ## 解决方案
 ## 问题理解

 该任务描述了一种非常具体的重复减少正整数的方法。 该运算不是简单地进行通常算术意义上的减一，而是取决于数字的最后一位数字。 如果数字以非零数字结尾，则该数字将正常运行并减一。 如果以零结尾，则该数字的值不会直接减少，而是完全删除最后一位数字，这相当于除以十。 

我们给出一个初始整数 n 和一些操作 k。 每个操作都会根据上述规则对数字进行转换，目标是在应用恰好 k 个这样的转换后确定最终值。 

约束 n ≤ 10^9 意味着该数字最多有 10 位数字。 操作数k最多为50，这是非常小的。 这立即排除了除了直接模拟之外的任何优化需求，因为即使是 k 个步骤的线性扫描也是微不足道的。 

一个幼稚的错误是将运算解释为总是减一。 例如，从 100 开始，简单的方法在一步后会生成 99，但正确的操作会删除尾随的零，生成 10。另一个微妙的错误是错误地在字符串和整数之间重复转换，或者忘记删除数字会完全改变数字的大小，从而影响后续步骤。 

当数字包含多个尾随零时，就会出现边缘情况。 例如，从 1000 开始应用一次运算得到 100，而不是 999。另一种边缘情况是重复删除零会快速减少位数，从而显着改变未来运算的行为。 

## 方法

 暴力方法直接应用规则 k 次。 每一步都会检查最后一位数字，然后减一或除以十。 由于 k 至多为 50，因此这种方法在实践中已经是最优的，不需要进一步优化。 

关键的观察结果是，除了本地数字操作之外，没有隐藏的结构。 每个操作仅取决于当前的最后一位数字，并且每次转换后数字都会以保留下一步正确性的方式发生变化。 不需要预先计算或数学捷径，因为过程本身已经受到一个小 k 的限制。 

因此，最佳解决方案就是完全按照所描述的过程进行模拟。

 ## 算法演练

 1. 从输入中读取整数 n 和 k。 n 的值是当前的工作数，k 是要应用的转换次数。 
2. 精确重复以下过程 k 次，因为每次迭代代表 Tanya 运算的一次应用。 
3. 使用 n % 10 检查 n 的最后一位。这会隔离个位，而不影响数字的其余部分。 
4. 如果最后一位非零，则从 n 中减一。 这对应于十进制表示形式的正常递减。 
5. 如果最后一位数字为零，则使用整数除法将 n 除以 10。 这会完全删除最后一位数字，从而减少位数。 
6. 完成所有 k 次迭代后，输出 n 的结果值。 

### 为什么它有效

在每一步，算法都会反映应用于数字当前状态的精确转换规则。 该操作仅取决于最后一位数字，每次转换后，所得数字将成为下一次操作的新有效状态。 由于每个步骤都是独立的并且完全由当前值决定，因此不需要额外的历史记录。 转换的顺序是确定性的，因此按顺序模拟它们可以保证最终值与所需的过程相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

for _ in range(k):
    if n % 10 == 0:
        n //= 10
    else:
        n -= 1

print(n)
```该解决方案读取初始数字并迭代应用 k 次变换。 条件`n % 10 == 0`直接实现尾随零的规则。 整数除法`//= 10`在这种情况下删除最后一位数字，而减法则处理所有其他情况。 

循环恰好运行 k 次，确保正确性而不会过度处理。 由于 k 很小，因此不需要额外的优化。

## 测试用例```python
import sys, io

def solve():
    n, k = map(int, sys.stdin.readline().split())
    for _ in range(k):
        if n % 10 == 0:
            n //= 10
        else:
            n -= 1
    print(n)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# provided sample
assert run("512 4\n") == "50\n", "sample 1"

# minimum case
assert run("10 1\n") == "1\n", "single division"

# all non-zero digits
assert run("999 3\n") == "996\n", "simple decrements"

# multiple trailing zeros
assert run("1000 2\n") == "10\n", "repeated digit removal"

# boundary small number
assert run("2 1\n") == "1\n", "small decrement"
```| 测试输入| 预期产出 | 它验证了什么 |

 ## 边缘情况

 当数字以多个零结尾时，就会出现一种边缘情况。 用于输入`1000`当 k = 2 时，第一个运算通过除法将其减少到 100，第二个运算通过另一个除法将其减少到 10。 该算法自然地处理这个问题，因为每次迭代都会在结构更改后重新评估最后一位数字。 

另一个边缘情况是数字在此过程的早期变成一位数。 例如，从 10 开始，第一次运算产生 1，后续运算继续安全地进行减法或除法。 该循环不假定固定的数字长度，因此当数字动态缩小时它仍然保持正确。 

最后的边缘情况是当 n 刚好高于 10 的幂边界时，例如 1001。减法序列快速创建一个尾随零，然后进行除法。 由于每个步骤始终检查当前状态，因此始终可以正确处理减法和除法之间的转换，而无需特殊情况逻辑。
