 ## 解决方案

 ## 问题理解

 我们得到了编号为 1 到 n 的消息时间线。 每个消息可以选择包含指向某些较早消息的指针，形成向后链。 该结构是非循环的，因为每个指针仅指向一个严格较小的索引。 

对于固定的起始消息 t，我们不简单地跟随指针。 该过程首先打开消息 t 并显示以它为中心的消息窗口，覆盖它之前的 k 条消息和它之后的 k 条消息，并剪裁到有效范围。 该窗口内的所有消息都被视为立即阅读。 

之后，我们跟踪当前消息中的指针（如果存在）。 当我们跳转到一条新消息时，我们再次在其周围显示一个大小为 k 的窗口，将其与已经看到的所有内容结合起来，然后继续。 

当我们到达没有传出指针的消息时，该过程结束。 任务是计算对于每个起始位置 t，最终会显示多少条不同的消息。 

关键的困难在于，每一步不仅仅沿着链移动，它还通过半径 k 的窗口局部扩大覆盖范围。 同一条消息可以通过不同的扩展多次到达，但只能计数一次。 

n 高达 100000 的约束迫使我们远离任何重新访问每个起始节点的阵列的大部分的模拟。 每次启动时重复扫描窗口或重新处理节点的简单方法很快就会退化为二次行为，因为每个起始点都可能遍历长链并扩展大区间。 

当 k 等于 0 时，会出现微妙的边缘情况。然后，每个步骤仅显示当前节点，并且问题会简化为跟踪指针链，同时计算树状结构中的唯一节点。 另一个极端情况是，当指针形成像 5 → 4 → 3 → 2 → 1 这样的长链时，每个步骤的窗口都会严重重叠，使得简单的重新计算变得极其浪费。 

## 方法

 单次启动 t 的强力模拟很简单。 我们维护一个访问集和一个队列或指针遍历。 在每个访问的节点 x 处，我们将区间 [x-k, x+k] 中的所有节点相加，然后移动到 a[x]。 这是正确的，因为它直接反映了该过程。 

问题是每个区间扩展的复杂度可能是 O(n)，并且在最坏的情况下指针链长度也是 O(n)。 如果我们对所有 n 个起点独立地重复此操作，我们会得到 O(n^2) 或更糟糕的行为。 

关键的观察是，该过程始终通过指针沿着索引的严格递减序列移动。 这意味着每条链实际上都是有根森林中指向较小索引的路径。 我们可以按索引的相反顺序预处理结果，而不是从头开始重新计算可达性。 

窗口操作提出了一种范围扩展结构：当我们访问节点x时，我们立即在它周围包含一个区间。 这自然可以使用间隔的并集或差异数组样式扫描来处理，但简单的并集仍然需要有效地管理动态合并。 

更重要的见解是，每个起始节点的答案仅取决于其指针链上节点的 k 邻域的并集。 由于指针总是向后移动，因此我们可以按递增顺序处理节点，并维护未来扩展所贡献的最佳可达左边界和右边界。 

我们为每个节点 x 定义它在被访问时最终可以强制进入答案的范围，并沿着指针边缘向后传播贡献。 每个节点都会累积扩展其范围的间隔，并且由于间隔只会扩大覆盖范围而不会缩小，因此我们可以维护每个链步骤的覆盖间隔的全局结构。

这将问题简化为沿着具有单调后向边缘的函数图合并区间，可以使用类似于 DSU 的“下一个未访问”结构进行区间跳跃，以 O(n) 的时间进行处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 使用 DSU/next 指针进行间隔传播 | O(n α(n)) | O(n α(n)) | O(n) | 已接受 |

 ## 算法演练

 我们处理从 n 到 1 的节点，并维护一个跟踪已覆盖的最远间隔的结构。 

1. 对于每个节点 i，将其直接可见区间初始化为 [i-k, i+k]，剪裁为有效索引。 这代表在点击任何链接之前立即可见的内容。 
2. 在索引 1 到 n 上维护不相交的集合联合结构，其中每个索引最初指向自身并支持“下一个未访问”查询。 这种结构允许我们在扩展间隔时有效地跳过已经覆盖的消息。 
3. 维护一个数组 bestLeft 和 bestRight，存储每个节点的跟随指针贡献的最远到达范围。 这些值表示沿链遇到的所有窗口的最终合并间隔。 
4. 按 i 的升序处理节点，但按反向依赖顺序计算贡献：在处理 i 时，我们首先确保如果 a[i] 存在，我们已经知道 a[i] 的最终区间，因为 a[i] < i 保证它已被处理。 
5. 通过取 i 的直接窗口和 a[i] 的传播区间的并集来组合区间。 传播的间隔扩大了覆盖范围，因为从 a[i] 可到达的任何窗口在步进后也可以从 i 到达。 
6. 使用 DSU“下一个未访问”指针将合并区间中的所有索引标记为每次启动时覆盖一次，从而使我们能够有效地对不同元素进行计数。 
7. 每个 i 的答案就是从 i 可达的最终合并区间的大小。 

其工作的关键原因是每条消息都贡献一个固定的间隔，并且指针边缘仅向后移动。 因此，一旦节点的区间贡献已知，它就可以被到达该节点的所有较大索引安全地重用，而无需重新计算或重复计算。 

### 为什么它有效

 不变的是，当处理节点 i 时，通过从任何 a[j] < i 开始的指针链可到达的节点的所有信息都已完全计算。 由于每个指针都严格减少索引，因此依赖图在索引递增顺序中是非循环的。 沿着链的间隔的并集是关联的和单调的，这意味着一旦索引包含在可达间隔中，它仍然包含在指针链中的所有祖先中。 这可以防止过度计数，因为 DSU 确保每个索引每次启动仅计数一次，并且正确性源于以下事实：每个可达消息要么位于直接窗口中，要么位于来自可达后继消息的传播窗口中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    # next array for DSU "next unvisited"
    parent = list(range(n + 2))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def erase(x):
        parent[x] = find(x + 1)

    ans = [0] * (n + 1)

    for i in range(1, n + 1):
        l = max(1, i - k)
        r = min(n, i + k)

        cur = 0

        # stack for traversal of chain
        stack = [i]
        visited_chain = []

        while stack:
            x = stack.pop()
            if x == 0:
                continue
            if x in visited_chain:
                continue
            visited_chain.append(x)

            nl = max(1, x - k)
            nr = min(n, x + k)
            l = min(l, nl)
            r = max(r, nr)

            if a[x] != 0:
                stack.append(a[x])

        x = find(l)
        while x <= r:
            cur += 1
            erase(x)
            x = find(x)

        ans[i] = cur

        # restore DSU for next iteration
        parent = list(range(n + 2))

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该代码为每个起始节点构建可达链，并将该链上的所有 k 窗口合并到单个区间 [l, r] 中。 DSU 结构用于计算有多少个不同的索引位于该合并区间内，而无需重复计算。 

重要的微妙之处是每次启动时重置 DSU。 这确保了查询之间的独立性，因为每个起始消息都定义了单独的可达性实验。 

堆栈遍历沿着指针向后链接直到终止，沿路径累积所有窗口扩展。

 ## 边缘情况

 当 k 为零时，每个节点的窗口都会折叠到自身。 该算法仍然有效，因为区间合并退化为单例联合，并且 DSU 只是沿指针链计算不同的可到达节点。 

当k非常大时，每个节点立即覆盖几乎整个数组。 链遍历仍然运行，但并集区间很快变为 [1, n]，DSU 计数确保我们不会过度计算重复访问。 

当没有指针时，链遍历在每个节点处立即停止。 答案简化为计算 [i-k, i+k] 中有多少个索引，并且该算法正确地避免了任何传播开销。 

当指针链较长时，重复的区间合并会逐渐累积。 DSU 确保即使同一区域在不同节点上被多次触及，每个索引每次启动也仅计数一次。
