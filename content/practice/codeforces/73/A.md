 ## 解决方案
 ## 问题理解

 我们有一个由具有尺寸的单位立方体组成的矩形块`x × y × z`。 始终沿着网格线进行一次切割，并且必须平行于盒子的一个面。 由于切口无限长，并且碎片永远不会离开其原始位置，因此一次切口可以同时穿过许多已创建的碎片。 

目标是在制作最多之后使最终件的数量最大化`k`削减。 

关键细节是剪切的行为方式。 如果我们做`a`垂直于`x`轴，盒子被分成`a + 1`沿着那个方向分层。 相似地，`b`顺着`y`生产`b + 1`那里的部分，以及`c`顺着`z`生产`c + 1`部分。 如果`a + b + c = k`，总件数变为：$(a+1)(b+1)(c+1)$尺寸限制了每个方向上可以进行的切割次数。 沿长度`x`，只有`x - 1`有效的网格平面，所以：$0 \le a \le x-1$对于其他两个维度也是如此。 

这些约束立即排除了任何切割模拟。 尺寸可达`10^6`， 尽管`k`可以达到`10^9`。 任何与状态或切割数量成正比的算法都会太慢。 甚至迭代所有三元组`(a,b,c)`天真地需要周围`10^{18}`最坏情况下的组合，这是不可能的。 

该问题实际上是三个整数的优化问题。 由于只有三个维度，因此可以通过数学观察大大减少搜索空间。 

一些边缘情况很容易被错误处理。 

假设输入是：```
1 1 1 100
```不可能进行任何切割，因为每个维度都已经有尺寸`1`。 正确答案是`1`，不涉及`k`。 

另一个微妙的情况是当`k`超过可用切割平面的总数：```
2 2 2 10
```每个维度只允许一次切割，因此最多可以使用三次切割。 最大件数仍为`8`。 

一个常见的错误是假设削减应该始终均匀分布。 考虑：```
10 1 1 5
```只能切割第一维。 答案是`6`，不是像这样平衡的东西`2 × 2 × 2`。 

另一个危险的实现错误来自 32 位整数语言中的整数溢出。 答案可以达到：$10^6 \cdot 10^6 \cdot 10^6 = 10^{18}$Python 会自动处理这个问题，但 C++ 解决方案需要`long long`。 

## 方法

 暴力解决方案会在每个方向上尝试所有可能的切割次数。 我们可以迭代所有三元组`(a,b,c)`满意：$a+b+c \le k$并检查每个值是否保持在尺寸限制内。 对于每个有效的三元组，我们计算：$(a+1)(b+1)(c+1)$并保持最大值。 

这是合乎逻辑的，因为每个有效的切削策略都是通过分配给每个轴的切削次数来唯一描述的。 问题在于搜索空间的大小。 即使我们只迭代到`10^6`，三重循环变得完全不可行。 

关键的观察结果是，答案仅取决于每个轴的切削次数，而不取决于切削顺序。 一旦我们决定`a`,`b`， 和`c`，件数是固定的。 

这将问题转化为在约束下最大化产品。 

如果没有维度上限，当值尽可能平衡时，乘积最大。 这是标准算术平均数和几何平均数的直觉。 但尺寸限制了每个方向可以接受的切割次数，因此最佳分布可能会达到边界。 

由于只有三个变量，我们可以迭代其中两个并导出第三个。 进一步的优化使这变得可行。 尺寸是对称的，因此我们对它们进行排序。 然后我们迭代最小两个维度的可行割，而第三个维度则自动确定。 

迭代总数保持可控，因为较小的维度极大地限制了循环。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k³) | O(1) | O(1) | 太慢了|
 | 最佳 | 排序后的 O(xy) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`x`,`y`,`z`， 和`k`。 
2. 对三个维度进行排序。 这不会改变答案，因为轴是可以互换的。 排序有助于保持嵌套循环较小。 
3. 迭代所有可能的切割次数`a`沿着第一维度。 

有效范围是：$0 \le a \le \min(k, x-1)$4. 对于每个`a`，迭代每个可能的切割次数`b`沿着第二个维度。 

有效范围是：$0 \le b \le \min(k-a, y-1)$5. 剩余的剪切进入三维：$c = \min(k-a-b, z-1)$我们使用尽可能多的剩余削减，因为增加`c`总是增加产品。 
6. 计算最终的件数：$(a+1)(b+1)(c+1)$7. 跟踪所有迭代中的最大值。 
8. 打印最大值。 

### 为什么它有效

 每次垂直于轴的切割都会使沿该轴的截面数恰好增加一个。 由于最终的碎片形成 3D 网格，因此碎片总数是每个维度中部分计数的乘积。 

该算法枚举每个可行对`(a,b)`。 一旦这些问题得到解决，最好的办法就是`c`始终是允许的最大剩余价值，因为产品单调增长`c`。 

由于每个有效的切割分布都被考虑一次，并且为每个分布计算正确的件数，因此算法找到的最大值是真正的最佳值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y, z, k = map(int, input().split())

    dims = sorted([x, y, z])
    x, y, z = dims

    ans = 1

    max_a = min(k, x - 1)

    for a in range(max_a + 1):
        max_b = min(k - a, y - 1)

        for b in range(max_b + 1):
            c = min(k - a - b, z - 1)

            pieces = (a + 1) * (b + 1) * (c + 1)
            ans = max(ans, pieces)

    print(ans)

solve()
```第一步对维度进行排序，以便最小的边界控制外循环。 这使得运行时易于管理。 

外循环选择沿第一个轴进行的切割次数。 由于只有`x - 1`有效平面，循环永远不需要超过该值。 

对于每一个`a`，第二个循环选择第二个轴的切割。 同样，我们不能超过剩余的切割或可用的平面。 

第三个值不需要另一个循环。 一次`a`和`b`是固定的，沿第三轴的任何额外切割都会严格增加乘积。 最好的选择就是最大的可行值。 

乘法使用`(a + 1)`,`(b + 1)`， 和`(c + 1)`因为`n`削减创造`n + 1`段。 

一个常见的差一错误是允许`x`削减而不是`x - 1`。 长度尺寸`x`恰好包含`x - 1`内部切割平面。 

另一个微妙的点是使用`min(k - a - b, z - 1)`为了`c`。 超出可用平面的额外削减是无用的，不得计算在内。

 ## 边缘情况

 考虑输入：```
1 1 1 100
```排序后，保留所有尺寸`1`。 

循环变成：```
a from 0 to 0
b from 0 to 0
c = 0
```计算出的乘积为：$1 \times 1 \times 1 = 1$因为没有内部平面，所以不可能进行切割。 该算法自然地通过以下方式处理这个问题`x - 1`界限。 

现在考虑：```
2 2 2 10
```每个维度只允许一次切割。 该算法探索所有可行的分配，但每个变量的上限为`1`。 

最大乘积变为：$2 \times 2 \times 2 = 8$其余七个切割将被忽略，因为它们无法对应于真实的切割平面。 

最后，考虑：```
10 1 1 5
```第二维和第三维的有效剖切面为零。 

算法迭代：```
a = 0..5
b = 0
c = 0
```最佳值出现在`a = 5`：$6 \times 1 \times 1 = 6$这证实了将所有切削集中在一个轴上有时是最佳选择。
