 ## 解决方案
 ## 问题理解

 我们在 2D 平面上有偶数个点。 任务是将所有点精确划分为$n/2$不相交的对。 

对于一对点$(x_1,y_1)$和$(x_2,y_2)$，它的贡献是曼哈顿距离$$|x_1-x_2| + |y_1-y_2|.$$在所有可能的完美匹配中，我们必须输出任何使曼哈顿距离总和最大化的配对。 

所有测试用例的点数最多为$2 \cdot 10^5$，因此任何检查所有配对的解决方案都是不可能的。 即使是为了$n=20$，完美匹配的数量已经非常巨大了。 和$n$达到$2 \cdot 10^5$，我们应该期望接近的东西$O(n \log n)$。 

棘手的部分是曼哈顿距离包含两个独立的坐标。 仅在 x 坐标上看起来最佳的配对可能与在 y 坐标上看起来最佳的配对不兼容。 关键的观察是这两种优化实际上可以同时进行。 

一个常见的错误是贪婪地配对最远的剩余点。 考虑：```
4
(0,0)
(1,100)
(100,1)
(101,101)
```局部贪婪选择很容易过早消耗一个极值点并阻止全局最优匹配。 正确的解决方案必须立即推理出所有点的结构。 

当许多点共享相同的 x 或 y 坐标时，会出现另一种微妙的情况。 例如：```
4
(0,0)
(0,1)
(0,2)
(0,3)
```该问题不需要唯一匹配。 存在多个最佳答案，并且无论关系如何，算法都必须有效。 

## 方法

 强力解决方案将生成每一个完美匹配，计算其总曼哈顿距离，并保留最佳匹配。 

这是正确的，因为它明确检查每个有效答案。 不幸的是，完美匹配的数量$n$顶点是$$(n-1)(n-3)(n-5)\cdots 1,$$它呈超指数增长。 甚至$n=20$已经远远超出了实际的极限。 

要找到更快的解决方案，首先忘记 y 坐标，只查看 x。 

假设我们有数字$x_1,x_2,\dots,x_n$并想要最大化$$\sum |x_a-x_b|$$在所有配对中。 

排序后，最优策略很明显：将最小的一半与最大的一半配对。 一维的每个最佳解决方案都将下半部元素与上半部元素相匹配。 

令人惊讶的是，相同的想法可以同时应用于两个坐标。 

按 x 对点排序。 标记第一个$n/2$点为$X_L$和最后一个$n/2$作为$X_R$。 

按 y 对点排序。 标记第一个$n/2$点为$Y_L$和最后一个$n/2$作为$Y_R$。 

每个点恰好属于四组之一：$$A=X_L\cap Y_L$$

$$B=X_R\cap Y_L$$

$$C=X_L\cap Y_R$$

$$D=X_R\cap Y_R$$如果我们可以将每个点配对$A$一点来自$D$，以及来自的每个点$B$一点来自$C$，那么每对都穿过 x 分割，也穿过 y 分割。 

跨越 x 分割保证了最大可能的 x 贡献。 

跨越 y 分割可保证最大可能的 y 贡献。 

计数论证表明$$|A|=|D|$$和$$|B|=|C|.$$因此这样的配对总是存在的。 这意味着独立最优的 x 和 y 结构实际上是兼容的。

 ## 算法演练

 1. 阅读所有点及其原始索引。 
2. 按 x 坐标对点进行排序。 
3.标记第一个$n/2$点属于下 x 半部分，其余点属于上 x 半部分。 
4. 按 y 坐标对点进行排序。 
5.标记第一个$n/2$点属于 y 下半部分，其余点属于 y 上半部分。 
6. 对于每个点，确定它属于四个组中的哪一个：$A$,$B$,$C$， 或者$D$。 
7. 配对点来自$A$积分来自$D$任意地。 
8. 配对点来自$B$积分来自$C$任意地。 
9. 输出所有生成的对。 

每个组内的任意配对之所以有效，是因为只有组成员身份才重要。 一旦一对在两个坐标中连接相对的一半，全局最优性论证就已经得到满足。 

### 为什么它有效

 对于一个维度，只有当每对将下半部元素与上半部元素连接起来时，才能实现最大可能的贡献。 

我们的构造保证每个生成的对都穿过 x 分区。 因此总的 x 贡献是最大的。 

相同的结构还保证每个生成的对都穿过 y 分区。 因此，总 y 贡献最大。 

由于曼哈顿距离是 x 贡献和 y 贡献之和，因此独立地最大化两者会给出全局最大曼哈顿和。 等式$|A|=|D|$和$|B|=|C|$确保始终能够完成所需的配对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())

        pts = []
        for i in range(n):
            x, y = map(int, input().split())
            pts.append([x, y, i + 1])

        x_side = [0] * n
        y_side = [0] * n

        order_x = sorted(range(n), key=lambda i: (pts[i][0], pts[i][1]))
        for pos, idx in enumerate(order_x):
            if pos < n // 2:
                x_side[idx] = 0
            else:
                x_side[idx] = 1

        order_y = sorted(range(n), key=lambda i: (pts[i][1], pts[i][0]))
        for pos, idx in enumerate(order_y):
            if pos < n // 2:
                y_side[idx] = 0
            else:
                y_side[idx] = 1

        A, B, C, D = [], [], [], []

        for i in range(n):
            if x_side[i] == 0 and y_side[i] == 0:
                A.append(pts[i][2])
            elif x_side[i] == 1 and y_side[i] == 0:
                B.append(pts[i][2])
            elif x_side[i] == 0 and y_side[i] == 1:
                C.append(pts[i][2])
            else:
                D.append(pts[i][2])

        for a, d in zip(A, D):
            out.append(f"{a} {d}")

        for b, c in zip(B, C):
            out.append(f"{b} {c}")

    sys.stdout.write("\n".join(out))

solve()
```第一个排序确定每个点相对于 x 属于下半部分还是上半部分。 第二次排序对 y 执行相同的分类。 

之后，每个点都被分配到四个桶之一。 证明表明桶的大小满足完美匹配所需的等式，因此将相应的元素与`zip`是安全的。 

使用原始索引至关重要，因为输出需要输入顺序中的点标识符，而不是排序后的位置。 

该实现从不计算曼哈顿距离。 数学结构本身就决定了最佳匹配。

 ## 边缘情况

 考虑重复点的情况：```
1
4
1 1
1 1
1 1
1 1
```按 x 和 y 排序后，任何平局顺序都是可接受的。 每个维度中有两个点进入下半部分，两个点进入上半部分。 这四个组的形成是一致的，并且计数证明仍然保证有效配对。 不同实现之间的输出可能有所不同，但每个生成的匹配都是最佳的，因为所有曼哈顿距离都为零。 

考虑共线情况：```
1
4
0 0
0 1
0 2
0 3
```x 坐标没有任何贡献。 该算法仍然将点分为下半部分和上半部分，并在该分割上成对。 由此产生的匹配最大化了总 y 贡献，这是这里的整个曼哈顿目标。 

考虑中位数周围的紧密联系：```
1
6
0 0
0 0
0 0
10 10
10 10
10 10
```由于坐标相等，存在多个有效的下半部和上半部分配。 通过排序生成的任何分配就足够了。 证明仅取决于每一半的点数，而不取决于分割的唯一性，因此算法保持正确。
