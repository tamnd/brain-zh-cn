 ## 解决方案
 ## 问题理解

 我们得到一个偶数长度的数组。 我们想要将其切割成连续的子数组，每个子数组必须具有奇数长度，并且所有这些子数组必须具有完全相同的中位数。 

这里的中位数是奇数长度数组的通常中位数，即排序后的中间元素。 

输入由单个数组组成。 输出只是这样的分区是否存在。 

数组长度可以达到$2 \cdot 10^5$。 任何显式检查所有奇数长度子数组的方法都将立即被排除。 有$O(n^2)$子数组，甚至计算一个子数组的中位数也不是常数时间。 我们需要一些接近的东西$O(n \log n)$。 

第一个微妙点是共同中位数不是任意的。 

考虑一个有效分区，其公共中位数是$x$。 每个具有中位数的奇数长度段$x$至少包含$\lfloor len/2 \rfloor + 1$元素是$\le x$，并且也至少$\lfloor len/2 \rfloor + 1$元素是$\ge x$。 

当几个这样的奇数段合并在一起时，这些保证就会加起来。 因此，所有段共享的中值也必须是通过合并它们获得的整个集合的中值。 这一观察结果是问题的关键结构属性。 

第二个容易被忽视的细节来自奇偶校验。 总长度是偶数，而每段长度是奇数。 因此，段数必须是偶数。 

例如：```
n = 2
a = [1, 2]
```唯一可能的分区是`[1] | [2]`。 他们的中位数不同，所以答案是`No`。 

另一个有用的例子是：```
n = 6
a = [1, 2, 3, 3, 2, 1]
```分裂成`[1,2,3]`和`[3,2,1]`给出中位数`2`在这两个部分中，所以答案是`Yes`。 

击败天真的推理的一个例子是：```
n = 6
a = [1, 2, 1, 3, 2, 3]
```价值`2`看起来很有希望，因为它位于排序顺序的中间，但不存在有效的分区。 答案是`No`。 

## 方法

 强力解决方案将枚举每个奇数分割位置和每个可能的分区，然后计算所有结果片段的中值并检查它们是否匹配。 

即使我们只尝试将每个分区分成两个奇数段，我们仍然需要在许多范围上进行中值查询。 通过对每个范围进行排序来计算中位数将花费$O(n \log n)$每个分割，导致大约$O(n^2 \log n)$工作。 

突破来自于理解任何有效分区的结构。 

假设存在一个有效的分区并且每个段都有中位数$x$。 

由于段数是偶数，因此将第一个段作为一组，并将所有剩余段合并为第二组。 第二组是奇数个有效段的合并，因此它也有中位数$x$。 第一组显然有中位数$x$。 

这意味着：

 当且仅当存在奇数索引时，有效分区才存在$k$这样```
median(a[1..k])     = x
median(a[k+1..n])   = x
```在哪里$x$是整个数组结构强制的中值。 

对于偶数长度数组，该值是全局排序数组中较低的中间元素，即位于位置的元素$n/2$在基于 1 的索引中。 这正是公认的解决方案中使用的值。 

现在问题被简化为：

 对于每个奇数分割位置$k$，确定前缀的中位数和后缀的中位数。 

这成为一个范围k阶统计问题。 通过坐标压缩和持久线段树，我们可以获得任意范围的中值$O(\log n)$。 

只有$O(n)$候选分割位置，因此完整的复杂性变为$O(n \log n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 \log n)$或者更糟|$O(n)$| 太慢了|
 | 持久线段树|$O(n \log n)$|$O(n \log n)$| 已接受 |

 ## 算法演练

 1. 读取数组并创建一个排序副本。 
2.让$X$是位置上的元素$n/2$在使用从 1 开始的索引的排序数组中。 这是唯一可能的共同中值。 
3. 对数组值进行坐标压缩，使其位于范围内$[1, m]$。 
4. 在前缀上构建持久段树。 

位置的根$i$存储前缀中值的频率$a[1..i]$。 
5. 实现范围第k个统计查询。 

使用与前缀相对应的根$r$和前缀$l-1$，我们可以得到第k个最小值$a[l..r]$。 
6. 对于每个奇数分割位置$k$:

 计算中位数$a[1..k]$。 

计算中位数$a[k+1..n]$。 

如果两个中位数相等$X$， 输出`"Yes"`。 
7. 如果没有分割成功，则输出`"No"`。 

### 为什么它有效

 每个有效分区都有偶数个奇数长度段，因为总长度是偶数。 

如果所有段都有中位数$X$，然后合并任意奇数个连续有效段仍然会产生具有中位数的段$X$。 将其应用于除第一个之外的所有段，可以将其划分为正好两个奇数长度部分，两个部分都有中值$X$。 

相反的情况是立即发生的。 如果存在分裂成两个奇数长度部分，其中位数都是$X$，该分割本身已经是一个有效的分区。 

因此检查所有奇数分割位置既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

tmp = sorted(a)
target = tmp[n // 2 - 1]

vals = sorted(set(a))
comp = {v: i + 1 for i, v in enumerate(vals)}
m = len(vals)

left = [0]
right = [0]
cnt = [0]
roots = [0] * (n + 1)

def update(prev, l, r, pos):
    node = len(cnt)
    left.append(left[prev])
    right.append(right[prev])
    cnt.append(cnt[prev] + 1)

    if l != r:
        mid = (l + r) // 2
        if pos <= mid:
            left[node] = update(left[prev], l, mid, pos)
        else:
            right[node] = update(right[prev], mid + 1, r, pos)
    return node

for i in range(1, n + 1):
    roots[i] = update(roots[i - 1], 1, m, comp[a[i - 1]])

def kth(u, v, l, r, k):
    if l == r:
        return l

    mid = (l + r) // 2
    left_count = cnt[left[v]] - cnt[left[u]]

    if k <= left_count:
        return kth(left[u], left[v], l, mid, k)
    return kth(right[u], right[v], mid + 1, r, k - left_count)

def median_value(l, r):
    length = r - l + 1
    k = (length + 1) // 2
    idx = kth(roots[l - 1], roots[r], 1, m, k)
    return vals[idx - 1]

for split in range(1, n, 2):
    if median_value(1, split) == target and median_value(split + 1, n) == target:
        print("Yes")
        sys.exit()

print("No")
```坐标压缩步骤允许持久线段树在紧凑的值范围上工作。 

树的每个版本对应一个前缀。 为了获得某个范围内的频率，我们减去两个版本中存储的计数。 这是范围顺序统计的标准持久段树技巧。 

中位数查询要求$(len+1)/2$-th 最小元素，因为我们检查的每个范围都有奇数长度。 

错误的常见来源是目标中位数。 由于整个数组长度是偶数，因此我们使用全局排序数组的中下元素，该元素对应于位置$n/2$在基于 1 的索引中。

 ## 边缘情况

 考虑：```
2
1 2
```唯一的奇数分割是在第一个元素之后。 

前缀中位数是`1`，后缀中位数为`2`。 

没有任何分割满足条件，因此算法输出`No`。 

现在考虑：```
2
5 5
```目标中位数是`5`。 

位置后的分割`1`给出中位数`5`和`5`，所以算法输出`Yes`。 

最后，考虑：```
8
7 7 7 7 7 7 7 7
```每个奇数长度范围都有中位数`7`。 

第一个检查的分割已经成功，算法立即返回`Yes`。 

这些案例验证奇偶校验参数、重复值的处理以及中值查询的正确性。
