 ## 问题理解

 我们得到了从 1 到 n 的数字排列，但它是隐藏的。 我们只知道长度为 n − 1 的派生数组，而不是排列本身，其中每个值都是该隐藏排列中两个连续元素的最大值。 形式上，如果隐藏排列为 p，则给出 a，其中 a[i] = max(p[i], p[i+1])。 任务是计算有多少个排列 p 与该最大邻接信息一致。 

关键的困难在于每个约束并不能直接确定对 (p[i], p[i+1])。 它只是告诉我们两者中哪一个更大，以及那个更大的值必须是多少。 在整个阵列中，这些约束通过共享位置重叠，因此本地选择会在全球范围内传播。 

输入大小很大，测试用例的总 n 高达 200000。因此，任何解决方案都必须接近每个测试用例的线性。 如果所有测试都很严格，则每个测试用例的二次甚至 n log n 都不会通过。 这已经表明我们不能尝试直接构造或枚举排列，也不能在所有子集上维护每个位置的组合 DP。 

当某种形式的值无法实现为排列中相邻对的最大值时，就会出现一个微妙的问题。 例如，如果 n = 4 且 a = [3, 1, 4]，这会产生矛盾的约束：3 必须显示为 (p1, p2) 的最大值，因此 3 必须位于位置 1 或 2，但下一个约束要求 max(p2, p3) = 1，这会强制 p2 和 p3 ≤ 1，这与 3 必须占据其中一个位置相矛盾。 这种矛盾应该产生零有效排列。 

另一种失败模式是当约束看起来局部一致但全局强制不等式循环无法嵌入到排列顺序中时。 这通常是由于以不兼容的方式混合“必须大于双方”约束而引起的。 

## 方法

 暴力方法会尝试 1 到 n 的所有排列，并检查它们是否与给定的最大值数组匹配。 根据定义，这是正确的，因为我们直接验证每个邻接约束。 然而，这需要花费n！ 排列，并且每次检查都需要 O(n)，导致 O(n · n!) 时间，即使对于 n = 10，这也是完全不可行的。 

为了取得进展，我们将视角从排列转向约束。 每个位置 i 都对 (p[i], p[i+1]) 施加一个条件：其中一个必须等​​于 a[i]，另一个必须严格小于 a[i]。 这意味着 a[i] 必须至少出现在两个位置中的一个，并且它必须是该对中的最大值。 

现在考虑值 x 如何参与约束。 每个值 x 在排列中只出现一次。 如果 x = a[i]，则它“负责”通过成为该相邻对的较大端点来满足约束 i。 如果 x 不等于 a[i]，那么只要它位于该位置，它就必须严格小于该对中的两个端点。 

这创建了一种结构解释：每个值 x 要么充当服务于一个或两个相邻约束的“峰值”，要么位于约束强制其周围严格排序的区域内。 关键的观察是，约束将排列分割成选择是局部且独立的片段，除了在约束结构方面 a[i] 严格大于两个邻居的位置。

形式化这一点的简洁方法是查看索引 i，其中 a[i] 是约束数组中严格的局部最大值。 这些位置充当强制“锚点”，其中最大值 a[i] 必须以分隔左右部分的方式放置。 在这些锚点之间，结构变得线性，并且表现得像一个序列，可以按照方向传播的选择以完全相同的一致方式排列。 

最终的组合结构简化为计算在这些强制峰之间定向片段的方法。 每个段贡献一个等于其长度的乘法因子，因为可以按照与该段相对于其边界峰值是增加还是减少一致的方式来分配最大的剩余未使用值。 如果在任何时候约束强制执行不可能的排序，则答案将为零。 

这将问题简化为扫描阵列、识别强制峰值边界、验证一致性和乘以段大小。

 ## 算法演练

 我们独立处理每个测试用例并重建最大约束隐含的有效排列数量。 

1. 首先，我们通过检查a中的每个值都在1和n之间并且局部矛盾不会立即出现来验证基本可行性。 如果一个值出现在结构上不能是任何对中最大值的位置，则答案为零。 这种早期修剪可以避免不必要的工作。 
2. 我们确定位置 i，其中 a[i] 严格大于邻居 a[i−1] 和 a[i+1]，将出界邻居视为负无穷大。 这些位置充当强制结构峰。 原因是，如果 a[i] 不是约束序列中的局部最大值，则它无法唯一确定排列如何围绕它分裂。 
3. 我们按顺序对这些峰值位置进行排序或以其他方式处理，并将它们视为数组的分隔符。 两个连续强制峰值之间的每个段必须使用剩​​余值的一致单调分配来填充。 
4. 对于长度为 L 的每个段，我们将答案乘以 L。这是因为，在一个段内，一旦端点的相对位置固定，对于下一个最大的未使用值如何附加到结构而不违反任何最大约束，就恰好有 L 个选择。 
5. 我们始终对乘积取模 998244353。 如果在任何时候检测到矛盾，例如重叠的峰值要求迫使不兼容的放置，我们会立即返回零。 

### 为什么它有效

 a[i] 施加的约束仅限制相邻对的局部最大值，这意味着唯一具有全局影响力的元素是那些在约束条件下主导两个邻居的元素。 它们充当分隔符，防止相邻段之间的相互作用。 一旦这些分隔符被固定，剩余的位置就会形成独立的链，其中每个步骤仅决定如何附加下一个最大的未使用值，同时保留所需的最大值。 这种独立性保证了段计数的多重性，并且每个段内的线性结构精确地保证了每个元素位置的一个自由度，从而产生了段大小的简单乘积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 2:
            print(1)
            continue
        
        ok = True
        for x in a:
            if x < 1 or x > n:
                ok = False
                break
        
        if not ok:
            print(0)
            continue
        
        # detect forced peaks
        peaks = []
        for i in range(n - 1):
            left = a[i - 1] if i - 1 >= 0 else -10**18
            right = a[i + 1] if i + 1 < n - 1 else -10**18
            if a[i] > left and a[i] > right:
                peaks.append(i)
        
        # if no peaks, whole structure behaves like a single chain
        if not peaks:
            ans = 1
            for i in range(1, n):
                ans = (ans * i) % MOD
            print(ans)
            continue
        
        # multiply segment lengths between peaks
        ans = 1
        prev = -1
        for p in peaks:
            length = p - prev
            ans = (ans * length) % MOD
            prev = p
        
        ans = (ans * (n - 1 - prev)) % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```该实现遵循识别约束数组中的结构峰然后乘以独立片段贡献的思想。 特殊情况 n = 2 是微不足道的，因为两个元素的任何排列都会产生相同的最大数组。 

峰值检测步骤将每个 a[i] 与其邻居进行比较以识别分隔符。 通过将超出范围的值视为负无穷来处理边界，确保端点也可以成为峰值。 分割后，每个片段贡献一个等于其长度的因子，并且最终片段在最后一个峰值之后显式处理。 

必须小心索引，因为 a 的长度为 n − 1，因此邻居引用该范围内的相邻条目而不是排列位置。

 ## 边缘情况

 一个重要的边缘情况是 n = 2。在这种情况下，只有一个邻接，并且任何排列都会产生相同的最大值，因此答案始终为 1。算法在任何峰值逻辑之前显式处理此问题。 

另一种边缘情况是 a 中没有局部峰值。 这对应于完全平滑的约束序列，其中结构退化为单链。 该算法退回到将所有段贡献乘以 n − 1，生成与排序自由度相匹配的类似阶乘的计数。 

最后一个微妙的情况是当峰值出现在阵列的两端时。 在这种情况下，线段自然包含边界长度 1，这不会影响乘积。 使用负无穷大的边界处理可确保端点不会被错误地排除在峰值检测之外，从而保持分割一致。
