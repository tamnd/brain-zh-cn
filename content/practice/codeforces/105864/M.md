 ## 解决方案
 ## 问题理解

 我们得到了一组神奇宝贝，每个神奇宝贝都由两个数字描述：其初始强度和价格。 在比赛开始前，我们可以选择一只神奇宝贝作为冠军。 选择它后，我们必须按照我们选择的顺序与所有其他神奇宝贝进行战斗。 

战斗是确定性的：如果我们当前的力量严格大于对手的力量，我们就赢了。 否则我们会立即失败并且过程结束。 每一场胜利都会使我们目前的实力增加一倍。 如果我们能够击败所有对手，那么首发神奇宝贝就被认为有能力赢得比赛。 

任务是确定可以被选为初始冠军的所有神奇宝贝中的最低成本，以便存在某种允许全面横扫对手的顺序。 如果没有神奇宝贝能够实现这一点，我们输出-1。 

关键的困难在于我们可以自由选择战斗顺序，这意味着可行性不仅取决于所选神奇宝贝的实力，还取决于我们如何根据比赛期间不断增强的实力来安排对手。 

这些约束允许最多 100,000 个神奇宝贝，这排除了任何在二次时间内模拟所有排列甚至每个候选者的贪婪尝试的解决方案。 任何试图通过模拟所有对手来独立测试每个神奇宝贝的方法都会降低到大约 O(n^2)，这太慢了。 

当多个神奇宝贝具有相同的力量时，就会出现微妙的失败情况。 如果起始神奇宝贝的所有可用选择都具有最小的力量，则没有人可以击败任何同等强度的对手，因为获胜条件严格来说更大。 例如，如果所有 ai 都相等，则无论成本如何，答案都必须为 -1。 

另一个不明显的情况是，如果我们不能组织战斗，使其不断增加的力量跟上更强大对手的顺序，那么即使是强大的起始神奇宝贝也可能会失败。 像“总是与最弱的剩余对手战斗”这样的天真贪婪是不够的，因为成本与排序无关，并且可行性取决于全局排序条件。 

## 方法

 暴力解决方案将选择每个神奇宝贝作为候选起始者，然后尝试确定是否存在允许其获胜的所有其他神奇宝贝的排序。 对于固定的起始神奇宝贝，我们可以通过重复选择当前可击败的下一个对手并更新强度来进行模拟。 以这种方式检查可行性已经需要排序或重复扫描，并且对每个候选者执行此操作至少会导致 O(n^2) 或 O(n^2 log n)，这远远超出了限制。 

结构洞察是停止动态模拟方面的思考，而是将问题转化为起始强度的可行性条件。 假设我们固定一个初始强度为 s 的候选者。 当我们赢得战斗时，在 k 次胜利后我们的力量变为 s + k。 为了击败所有对手，我们需要对他们进行安排，使得在每一步中，所选对手的实力都严格小于当前值。 

这意味着我们想要对所有其他神奇宝贝进行排序，其中每个 ai 都小于其位置索引阈值。 这相当于检查我们是否可以将每个对手的力量与不同的“时间段”相匹配，其中时间段索引贡献额外的允许强度。

关键的观察是，如果我们按强度对所有其他神奇宝贝进行排序，则在可行性检查中应首先考虑最难放置的神奇宝贝。 如果我们按强度递增顺序处理，则在步骤 i（0 索引）处，当前可用强度必须至少为 ai ≤ s + i。 重新排列给出了 s 的条件：对于排序列表中的每个 i，s ≥ ai − i。 因此，对于固定的起始神奇宝贝，我们可以计算所有其他神奇宝贝中的 (ai − i) 的最大值，并确保 s 严格超过它。 

由于排序，这将每个候选检查减少到 O(n log n)，但我们可以全球化这个想法。 如果我们观察到唯一相关的起始神奇宝贝是那些强度足以满足从所有其他神奇宝贝得出的全局约束的神奇宝贝，那么我们不需要尝试所有候选神奇宝贝。 

因此，我们按强度对神奇宝贝进行一次排序，计算所需的最小起始强度阈值，然后在强度满足该阈值的所有神奇宝贝中，选择最小成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 log n) | O(n^2 log n) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.将所有神奇宝贝按照实力非降序排列。 这为推理战斗安排提供了固定的顺序，因为我们只关心对手的相对大小。 
2. 遍历排序列表并计算通过跟踪 (ai − i) 的最大值定义的运行约束值，其中 i 是排序数组中的位置。 当我们试图尽早安排他们时，这可以捕捉到每个对手引入的“赤字”程度。 
3. 将此约束转换为所需的最小起始强度。 由于我们需要严格胜利，所以起始力量必须超过最大赤字，而不仅仅是等于它。 
4. 现在再次迭代所有神奇宝贝并检查哪些神奇宝贝可以作为起始候选者，这意味着它们的初始强度高于或等于所需的阈值。 
5. 在所有有效候选者中，取最小成本bi。 
6. 如果没有候选满足要求，则输出-1。 

### 为什么它有效

 一旦神奇宝贝按强度排序，任何可行的战斗顺序都可以转化为尊重该顺序的顺序，而不会降低可行性，因为在严格增加强度的过程中，较弱的对手永远不会比早期更难击败。 表达式 ai − i 捕捉了对手实力和可用进度槽之间最坏情况的差距。 如果初始强度足够高以覆盖最差的差距，那么按强度递增顺序进行战斗的贪婪计划将始终保持有效性，因为在步骤 i 中，我们已经积累了恰好 i 个胜利，因此 i 个强度增益。 这就产生了一个紧不变量：i获胜后，当前强度恰好是s + i，并且位置i上剩余的每个对手都必须满足ai < s + i，这是通过构造保证的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    pokes = list(zip(a, b))
    pokes.sort()
    
    # compute minimum required starting strength threshold
    need = -10**30
    for i, (ai, bi) in enumerate(pokes):
        need = max(need, ai - i)
    
    ans = float('inf')
    for ai, bi in pokes:
        if ai >= need:
            ans = min(ans, bi)
    
    print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将力量和成本配对，然后按力量排序，以便我们可以推断当我们“花费”每次胜利的一次收益时，力量需求如何演变。 变量`need`追踪调度压力方面最严格的对手。 

第二遍过滤有效的起始神奇宝贝。 条件`ai >= need`反映出只有初始强度已经满足全球要求的神奇宝贝才可以使用。 最后，我们在可行的选择中最小化成本。 

一个微妙的点是索引`i`排序数组中隐含地表示我们假设在以最佳时间表面对对手之前已经发生了多少场胜利。 这是转型成功的核心。

 ## 边缘情况

 当所有优势都相等时，每个 ai − i 计算都会很快揭示出一个很高的所需阈值，但没有任何候选者能够有意义地帮助超越该阈值，因为严格的比较会阻止任何与相等的进展。 例如，输入`a = [3, 3, 3]`产生在任何计划中都无法满足的要求，并且算法正确地产生 -1，因为没有元素通过可行性过滤器。 

当只有一只具有强大统治力的神奇宝贝时，例如`a = [1, 2, 100]`，阈值由排序顺序早期的最大间隙驱动。 该算法根据所有位置计算需求，只有最强的候选者能够通过检查，并正确选择其成本作为答案。 

当成本高度不均匀但强度相似时，该算法可确保可行性与优化分开。 它从不喜欢廉价但不可行的候选方案，因为在成本最小化之前严格执行可行性过滤器。
