 ## 解决方案

 ## 问题理解

 我们得到一个大小的数组$2n$，代表学生的技能水平。 任务是将这些学生分成两组，每组包含奇数个学生，每个学生都分配到一组。 

对于任何群体，我们将其“阶级强度”定义为对该群体进行排序后其成员的中位数。 由于两个组的大小都必须为奇数，因此每个中位数都被明确定义为单个中间元素。 

目标是将数组划分为两个奇数大小的组，以使它们中位数之间的绝对差尽可能小。 

约束允许最多$10^5$测试用例总数，总和$n$还高达$10^5$。 这强烈表明$O(n \log n)$或者每个测试用例需要更好的解决方案，因为排序是主要允许的操作，并且每个测试用例的任何二次都会立即超时。 

尝试所有分区的简单方法$2n$将元素分成两个奇数组是不可能的，因为分区的数量呈指数增长。 即使限制为有效的奇数分割也会导致组合爆炸。 

贪婪直觉的一个微妙的失败案例是假设将数组按排序顺序分成两个连续的两半总是有效的。 例如，即使值已排序，选择中点分割也会忽略中位数仅取决于每个组内的奇偶位置，而不取决于原始数组中的绝对位置。 

## 方法

 暴力解决方案将枚举所有分裂方法$2n$元素分为两组奇数大小。 对于每个分组，我们将对两个组进行排序并计算它们的中位数。 此类分区的数量约为$\binom{2n}{n}$，即使对于小物体来说，这也是一个天文数字$n$，使其完全不可行。 

关键的观察结果是，只有元素的相对顺序很重要，因为中位数取决于顺序，而不是身份。 一旦我们对数组进行排序，我们想要选择两个中位数，然后验证我们是否可以围绕它们构造有效的奇数大小的组。 

如果我们确定第一组的中位数位于位置$i$，则必须选择该元素作为奇数长度子集的中间。 第二组也是如此。 该结构强制两个中位数都对应于排序数组中的元素，并且最佳解决方案将来自选择排序顺序尽可能接近但具有奇偶校验约束的两个中位数。 

关键的改进是，排序后，有效中位数必须来自两侧都存在足够元素以形成奇数大小的组的位置。 事实证明，最佳答案是通过采用两个元素来实现的：$n$在排序数组中分开。 

这是有效的，因为当我们在位置选择一个中值候选人时$i$，我们必须确保我们可以组成一个小组$i$使用其周围的元素作为中位数，其余元素自动形成另一个奇数组。 第二个中位数必须来自结构上兼容的位置，并且最佳配对是围绕分裂对称的。 

因此，排序后，我们只需要比较对$(a[i], a[i+n])$对于所有有效的$i$，并取最小差值。

 ## 算法演练

 1. 对数组进行排序$2n$元素。 这给了我们一个结构，其中中位数对应于固定位置。 
2. 观察到，任何有效划分为两个奇数大小的组都对应于选择两个“中心”元素作为两个组的中位数。 
3. 迭代所有有效的起始位置$i$从$0$到$n-1$, 配对$a[i]$和$a[i+n]$。 原因是这些对代表了将数组分成两个奇数大小的组且中值位置不重叠的唯一结构一致的方法。 
4. 对于每一对，计算绝对差$|a[i] - a[i+n]|$。 
5. 跟踪所有对之间的最小差异并将其输出。 

我们只考虑完全分开的对的原因$n$位置是在大小的排序数组中$2n$，任何有效的二分到两个奇数大小的集合必须将一个中位数放在下半部分，另一个放在上半部分，并且可行中位数放置之间的边界恰好位于此偏移处。 

### 为什么它有效

 一旦数组被排序，任何中位数都对应于可以成为奇数大小子集的中心的位置。 选择下半部分的中位数会强制另一个中位数位于上半部分，因为其余元素也必须形成奇数大小的组。 配对距离$n$确保两组可以平衡，以便每个中位数成为其各自子集的中间元素。 由于所有有效配置都映射到某些此类配对，因此这些对的最小值是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        
        ans = float('inf')
        for i in range(n):
            ans = min(ans, abs(a[i] - a[i + n]))
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序，使中值关系成为位置关系而不是组合关系。 然后循环仅检查$n$结构上有效的中值配对。 每个配对对应一个可行的分区，其中两个组的大小都为奇数。 

一个常见的实现陷阱是迭代最多$2n$或错误地将指数混合在两半之间。 正确的不变量是我们总是精确地比较元素$n$按排序顺序分开。

 ## 边缘情况

 当所有元素都相同时，就会出现微妙的边缘情况。 该算法在排序后仍然对对称位置进行配对，但每个差异为零，这与任何分区产生相等中位数的事实相匹配。 

对于最小情况$n = 1$，该数组恰好有两个元素。 排序会产生两个位置，唯一的比较是在它们之间，这正确地反映了唯一可能的分区。 

在簇之间间隙较大的情况下，最佳配对始终来自排序后最接近的跨半对齐。 该算法自然地捕获了这一点，因为它评估了所有有效的$i, i+n$配对并选择其中的最小值，确保不会遗漏任何倾斜的分区。
