 ## 解决方案
 ## 问题理解

 给定一个整数数组，并希望两个属性同时为真：元素之和不得为零，并且元素的乘积不得为零。 唯一允许的操作是将单个元素加一。 任务是找到满足这两个属性的此类增量操作的最小数量。 

输入由多个测试用例组成。 每个测试用例都以数组的大小开始，然后是数组元素。 界限很小：每个数组最多 100 个元素，每个元素在 -100 到 100 之间，最多 1000 个测试用例。 这意味着$O(n)$每个测试用例的解决方案将足够快。 

当数组中有零时，就会出现边缘情况。 数组中的零使得乘积为零，必须通过每零至少一个增量来固定该乘积。 如果修复所有零后数组的总和为零，则会出现另一种微妙的情况。 例如，像 [0, -1, 1] 这样的数组的和为零，积为零。 如果我们将 0 增加到 1，乘积将变为非零，但总和现在为 1，因此两个条件都满足。 一般来说，处理零后，我们必须检查总和本身是否为零，因为增加零可能不会自动修复总和。 

## 方法

 暴力方法将模拟单独递增每个零，然后测试附加增量的每个组合以固定总和。 这是正确的但没有必要，因为这个问题可以用数学来推理。 和$n \le 100$并且值有界，操作计数可能看起来很小，但模拟每次总和调整可能需要指数工作，考虑到可用的更简单的见解，这是不合理的。 

关键的见解是将这两个约束分开。 数组中的任何零都必须递增才能修复乘积。 让`zeros`是零的数量； 我们至少需要`zeros`运营。 增加所有零后，我们可以计算结果数组的总和。 如果这个总和为零，我们需要在任何地方增加一个增量来使总和从零开始。 如果总和已经非零，则不需要进一步的操作。 这减少了计算零和检查调整后的总和的解决方案。

 | 暴力模拟| O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 计数零+调整总和| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`steps`为零。 这将跟踪所需的总增量。 
2. 计算数组中零的数量。 每个零需要增加一个增量才能使乘积非零，因此将此计数添加到`steps`。 
3. 假设将所有零加一后计算数组的总和。 让`sum_after`是这个总数。 
4.如果`sum_after`为零，增量`steps`一个。 这说明了修复产品导致总和为零的情况。 
5. 打印`steps`作为此测试用例的结果。 

为什么有效：每个零都必须递增才能获得非零乘积，这是算法所保证的。 一旦处理了零，总和保持为零的唯一方法是非零元素完美抵消。 在任何地方再添加一个增量就会打破这一点，保证总和和乘积都不为零。 该算法精确计算所需的最小增量数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    zeros = a.count(0)
    steps = zeros
    
    sum_after = sum(a) + zeros
    if sum_after == 0:
        steps += 1
    
    print(steps)
