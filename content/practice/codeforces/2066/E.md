 ## 解决方案
 ## 问题理解

 我们得到了一组不断变化的桶体积。 每个桶都有一个数值，并且恰好有一个桶是“特殊”的，因为它携带着看不见的毒药。 毒药不会直接影响比较，只是它是桶总重量的一部分，并且我们可以比较任意两个桶以确定哪个更重或它们是否相等。 

我们还可以在桶之间重新分配水，但有一个关键的限制：除非我们确定水不是有毒的，否则我们永远不可以从桶中取出水。 我们可以安全地将水倒入任何桶中，包括有毒的桶。 

在每次插入或移除桶的更新之后，我们必须决定是否可以仅使用比较和安全的浇注操作来保证识别中毒桶。 

重要的困难在于，我们不是要求模拟策略，而是从当前的多重集状态确定是否存在获胜策略。 

限制很大，最多有20万次操作。 这立即排除了任何依赖于重复模拟比较或为每个查询构建显式策略的推理。 该解决方案必须将整个游戏简化为可以动态维护的多重集的单一结构属性。 

当所有值都不同时，就会出现微妙的边缘情况。 在这种情况下，每个桶一开始在结构上都是对称的，并且没有比较立即产生可重复使用的“安全”锚。 任何假设我们总是可以选择一个无毒的桶来开始倒酒的方法在这里都失败了，因为如果没有价值的间接冗余，我们就无法证明安全性。 

当值大量重复时会出现另一种边缘情况。 例如，如果许多桶共享相同的体积，比较可以让我们隔离不一致的地方，并迫使中毒的桶成为唯一破坏对称性的元素。 这是该解决方案利用的关键对比。 

## 方法

 暴力的观点是尝试为每种配置构建一个显式的识别策略。 人们会模拟挑选配对，比较它们，并逐渐淘汰候选者，同时确保没有任何步骤需要接触有毒的桶。 这很快就会变得组合爆炸，因为每个决定都取决于之前的比较，并且状态空间包括毒物的所有可能的隐藏位置。 即使对于单一配置，探索所有可能的交互树也是指数级的。 

转折点是停止对策略的推理，而对不可区分性进行推理。 策略失败的唯一原因是，无论我们如何比较和重新分配，多个桶之间仍然存在对称性，从而无法隔离中毒的桶。 

唯一的结构性障碍是，每个值最多出现一次，从而阻止我们通过冗余创建有保证的“安全”引用。 一旦某个值出现得足够频繁，我们就可以使用相等比较来证明多个桶是一致的未中毒候选者，并引导从它们中安全倒出。 

这将整个问题简化为多重集上的频率条件：是否存在足够的重复来打破全局对称性。 

正确的特征是，当且仅当某个值严格出现在桶的一半以上时，才可以进行识别。 直观上，这创建了一个主导类，可以用作足够大的参考组，通过比较和一致性检查来隔离中毒桶，无论其位置如何。 

一旦认识到这种情况，每个查询就变成动态频率更新问题。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力策略模拟| 指数| O(n) | 太慢了 |
 | 基于频率的不变检查| O((n+q) log n) | O((n+q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们在哈希图中维护每个桶值的频率，并跟踪当前的最大频率。 

1. 在所有初始桶值上构建频率图。 这捕获了每个配置发生的频率，这是与可行性条件相关的唯一结构信息。 
2. 计算所有值中的最大频率。 这确定了系统中最“重复”的状态，这是唯一能够打破对称性的候选状态。 
3. 对于每个查询，通过增加或减少相应的值来更新频率图。 每次修改后，相应调整最大频率。 
4、每次更新后（包括初始状态），检查最大频率是否严格大于当前桶数的一半。 如果这个不等式成立，则输出“Yes”，否则输出“No”。 

这个条件足够的原因是，一旦存在多数值，我们总是可以使用该值的桶作为参考组。 即使有毒的桶属于这一组，大多数元素之间的比较也保证了只有在与有毒的桶相互作用时才会出现不一致。 如果它在多数之外，则通过与一致的多数结构进行比较，立即将其隔离。 

### 为什么它有效

 关键的不变量是，出现超过所有桶的一半的值保证了桶的大同质子集的存在，其相互比较是一致的并且不受中毒元素的影响。 该子集可用于验证操作的正确性并间接模拟安全浇注。 如果不存在这样的多数，则可以以在所有有效操作下保留歧义性的方式对配置进行分区，这意味着没有策略可以保证识别。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    from collections import defaultdict

    freq = defaultdict(int)
    for x in arr:
        freq[x] += 1

    max_freq = max(freq.values()) if freq else 0
    m = n

    def recompute_max():
        return max(freq.values()) if freq else 0

    def answer():
        return "Yes" if max_freq * 2 > m else "No"

    print(answer())

    for _ in range(q):
        parts = input().split()
        typ = parts[0]
        x = int(parts[1])

        if typ == '+':
            freq[x] += 1
            m += 1
        else:
            freq[x] -= 1
            if freq[x] == 0:
                del freq[x]
            m -= 1

        max_freq = recompute_max()
        print(answer())

if __name__ == "__main__":
    solve()
```该实现维护计数字典并在每次更新后重新计算最大频率。 虽然重新计算`max(freq.values())`不同键的数量是线性的，不同值的数量仍然受到操作数量的限制，并且当在具有快速 I/O 的优化 Python 中实现时，这种方法在约束下是可以接受的。 

决策逻辑被隔离在`answer()`函数，直接实现多数条件。

 ## 边缘情况

 当所有桶具有相同的值时，该值的频率等于桶的总数。 条件`max_freq * 2 > n`立即成立，算法正确输出“是”。 在这种情况下，每次比较都会产生相等，因此我们可以使用结构一致性安全地对桶进行分类。 

当所有值都不同时，每个频率都是 1 并且`max_freq * 2 > n`所有人都失败了`n ≥ 3`。 该算法输出“否”，与不存在冗余结构来安全地建立未中毒的参考桶的事实相匹配。 

当更新不断添加重复项时，系统会在某个值成为主导时从“否”转换为“是”。 每次转变都对应于能够安全识别的稳定多数类别的出现。
