 ## 解决方案
 ## 问题理解

 给定一个非负整数数组，我们可以从中选择一个子序列。 从该子序列中，我们希望保留尽可能多的元素，同时确保每个分割点都满足非常特定的前缀后缀条件。 

如果我们查看所选子序列的任何前缀，则该前缀中的最小值必须始终至少与剩余后缀的 mex 一样大。 集合的 mex 是集合中未出现的最小非负整数，因此它捕获后缀相对于从零向上的起始值的“完整”程度。 

该条件在左侧（由最小值控制）和右侧（由缺失的小整数控制）之间产生张力。 如果后缀缺少像 0 或 1 这样的小数字，则其 mex 会变小甚至为 0，从而使条件变得更容易。 但如果后缀包含许多连续的小整数，则其 mex 会增长，迫使前缀最小值也很大。 

测试用例的输入大小很大，总元素数高达 2·10^5，因此任何尝试所有子序列或每次拆分重复重新计算 mex 的解决方案都是立即不可行的。 即使每个测试用例的 O(n^2) 也太慢，如果涉及重复的重新计算，即使每个元素的 O(n log n) 也会有风险。 这促使我们采用线性或近线性结构，并仔细记录频率或缺失计数。 

当数组包含许多大值但很少有小值时，就会出现微妙的边缘情况。 例如，`[1000000000, 1000000000, 1000000000]`只允许一个简单的子序列，因为除非出现 0，否则后缀的 mex 始终为 0。 另一种边缘情况是 0 完全缺失：则任何后缀的 mex 始终为 0，使得条件变得微不足道并允许整个子序列。 尝试为每个后缀分割显式维护 mex 的简单方法会重复重新计算缺失值并在约束下失败。 

## 方法

 暴力策略会枚举所有子序列并检查每个子序列是否神奇。 对于每个子序列，我们需要测试所有分割点，重新计算前缀的最小值和后缀的 mex。 即使我们在 O(1) 中保持前缀最小值，mex 计算仍占主导地位：每个后缀 mex 计算都是 O(k)，其中 k 是子序列长度，并且子序列的数量呈指数级增长。 This is completely infeasible.

 更结构化的观察来自于重写条件实际执行的内容。 修复有效的子序列。 对于位置 i 处的分割，后缀 mex 仅由后缀中出现的小数字确定。 当我们扩展前缀时，前缀最小值是单调递减的。 因此，保持不等式对于长子序列有效的唯一方法是仔细控制我们包含的小整数的数量，因为每次出现小数字都会降低 mex 复杂性并限制未来的选择。 

关键的见解是扭转观点。 我们不考虑前缀，而是跟踪后缀要求：剩余部分的 mex 仅取决于我们是否已经包含某些值。 在最佳构造中，我们希望尽可能延迟“破坏”小整数的存在，同时确保保留足够的大元素来支持前缀最小值约束。 

这导致了一种贪婪的构造，在这种构造中，我们试图通过跟踪在不可能保持 mex 有界之前我们仍然可以包含每个值的次数来保持可行性。 我们有效地模拟构建子序列，同时确保后缀始终具有足够的缺失结构，以便 mex 不会超过当前前缀最小阈值。 

核心缩减是仅值 0, 1, 2, ... 直到当前的 mex 边界物质。 大于当前 mex 阈值的值表现为 mex 的中性元素，但可能影响前缀最小值。 因此，问题归结为平衡我们包含多少小数字与维持稳定的递减前缀最小值，这可以通过计算频率并模拟从左到右的贪婪选择来处理。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们计算数组中所有值的频率，但我们只明确关心最多 n 的值，因为对于长度为 n 的结构，mex 永远不会超过 n。 大于 n 的值可以被视为“无限”，并且仅影响前缀最小行为。 
2. 我们计算从 0 开始的每个值出现的次数。 这使我们能够模拟当我们假设删除元素时后缀的 mex 将如何演变。 
3. 我们通过模拟在保持 mex 条件的可行性的同时可以保留多少元素来构建答案。 我们维持一个运行的概念，即有多少不同的小值仍然“可”出现在后缀中。 
4. 我们贪婪地按照保持有效性的能力降序排列元素。 小值至关重要，因为它们决定了 mex； 大值是灵活的，只要不违反前缀最小约束，就可以包含它们。 
5. 该结构有效地减少了确定数组完全支持的整数 0,1,2,... 的最大前缀，同时还计算了不干扰该结构的所有元素。

微妙的一点是，一旦我们决定了可以维持的最大墨西哥水平，每个大于或等于该水平的元素都可以自由地包含在内，而低于该水平的元素必须根据可用性限制仔细匹配。 

### 为什么它有效

 后缀的 mex 仅取决于该后缀中是否存在从 0 开始的所有整数。 该算法隐式确保我们永远不会创建 mex 超出前缀最小值可以支持的后缀。 通过跟踪小整数的可用性并限制该链可以延伸的距离，我们强制每个分裂都满足所需的不等式。 

贪婪选择是正确的，因为一旦某个值被排除在支持 mex 进展之外，稍后重新引入它就无法提高早期分裂的可行性。 这种单调性确保全局确定最大可行 mex 阈值会产生最佳子序列长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cnt = [0] * (n + 2)
        for x in a:
            if x <= n:
                cnt[x] += 1
        
        mex = 0
        while mex <= n and cnt[mex] > 0:
            cnt[mex] -= 1
            mex += 1
        
        # all elements >= mex can be taken freely
        ans = mex
        for x in a:
            if x >= mex:
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先仅计算最多 n 的出现次数，因为较大的值不会影响 mex 级数。 然后，它从 0 开始构建最大连续前缀，消耗每个值的一次出现来确定 mex 链可以延伸多远。 该值成为子序列的结构支柱。 

一旦这个 mex 边界被固定，每个大于或等于它的元素都可以安全地包含在内，因为它们不会在后缀中引入丢失的低整数，并且它们不会破坏 mex 级数。 最终答案是这个最大链的大小加上所有这些大元素。 

一个常见的陷阱是忘记每个小数字只需要一个副本来扩展 mex 链，而额外的副本可以在以后自由使用。 另一个微妙之处是大于 n 的值实际上是等效的，不应在 mex 循环中处理。

 ## 边缘情况

 当数组不包含零时，mex 链甚至无法启动。 在这种情况下，算法立即将 mex 设置为 0，并且所有元素都被视为可自由包含，因为它们都 ≥ mex。 例如，输入`[5, 6, 7]`产生 mex = 0，答案变为 3，这与任何子序列都满足条件的事实相匹配。 

当数组恰好包含小整数的完整前缀但没有较大的桥接值时，例如`[0,1,2,3]`，mex 链完全延伸，没有其他元素贡献。 该算法使用每个值一次并在 mex = 4 处停止，给出答案 4。 

当存在重复项时，例如`[0,0,1,1,2,2]`，每个值仅使用一个副本来扩展 mex，而一旦链固定，剩余的重复项将被计为自由元素。 该算法正确地计算链的每个级别以及之后所有剩余出现的次数，从而保持最优性。
