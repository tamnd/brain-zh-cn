 ## 解决方案
 ## 问题理解

 我们从一个非负整数开始`n`。 

在一个操作中，我们查看当前数字的十进制表示形式，选择其中出现的任何数字，然后从该数字中减去该数字。 所选数字可以为零，但减零毫无帮助，因此有用的移动总是减去当前数字中出现的正数字。 

目标是使用尽可能少的操作精确地达到零。 

例如，如果当前值为`24`，可用的数字是`2`和`4`。 我们可以减去其中任何一个。 一种最佳序列是：`24 → 20 → 18 → 10 → 9 → 0`它使用五个操作。 

对于C1版本的问题，`n ≤ 10^6`。 这个界限足够小，可以考虑其中的每个值`0`到`n`。 每个数字一个状态的动态编程解决方案大约需要一百万个状态，这在时间和内存限制内很容易管理。 重复探索所有可能的减法序列的方法将呈指数增长，并且在达到上限之前很久就变得不可行。 

有几种边缘情况值得关注。 

如果`n = 0`，根本不需要任何操作。 

输入：```
0
```输出：```
0
```将所有答案初始化为一个大值并且从不正确处理起始状态的粗心实现可能会错误地报告其他内容。 

包含零的数字是另一个常见的错误来源。 

输入：```
10
```可用的数字是`1`和`0`。 减法`0`保持数字不变并创建无用的自转换。 正确的最优顺序是：`10 → 9 → 0`所以答案是：```
2
```一种盲目处理数字的实现`0`如果不小心，可能会意外地在递归解决方案中创建无限循环。 

个位数的数字可以立即得到答案。 

输入：```
7
```输出：```
1
```由于数字`7`出现在数字中，我们可以直接减去它，一举归零。 

## 方法

 最直接的想法就是把每一个减法序列看成一条路径。 来自一个数字`x`，我们可以移动到`x - d`对于每个数字`d`出现在`x`。 如果我们递归地尝试所有可能性并采取最少的步骤，我们最终会得到正确的答案。 

问题是相同的中间值重复出现。 例如，许多不同的路径可能到达该号码`137`，并且每次重新计算其答案都会导致工作量激增。 可能的减法序列的数量呈指数增长。 

关键的观察是，一个数字的答案仅取决于较小数字的答案。 如果我们已经知道以下每个值所需的最少操作`x`，然后我们可以计算答案`x`通过尝试出现在的每个数字`x`。 

让`dp[x]`表示减少所需的最小操作数`x`为零。 

假设数字`d`出现在`x`和`d > 0`。 减去后`d`，我们到达`x - d`。 第一步需要花费一次操作，然后我们需要`dp[x - d]`更多操作。 这给出了过渡`dp[x] = min(dp[x], dp[x - d] + 1)`。 

由于每次转换都会变成较小的数字，因此我们可以按升序处理值`1`到`n`。 计算时`dp[x]`，所有必需的状态都已计算完毕。 

这将问题转化为一个简单的动态规划解决方案，每个整数一个状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数递归树| 太慢了 |
 | 最佳DP | O(n log n) | O(n log n) | O(n) | 已接受 |

 这`log n`因子来自提取每个数字的数字。 

## 算法演练

 1.读取输入值`n`。 
2. 创建数组`dp`尺寸的`n + 1`。 
3. 设置`dp[0] = 0`因为零已经不需要任何操作。 
4. 对于每个数字`x`从`1`到`n`, 初始化`dp[x]`到一个很大的值。 
5. 提取所有数字`x`通过反复采取`x % 10`并除以`10`。 
6. 对于每个非零数字`d`出现在`x`，考虑将减法作为第一步。 
7. 更新`dp[x] = min(dp[x], dp[x - d] + 1)`。 

价值`dp[x - d]`已经知道，因为`x - d < x`。 
8. 处理完所有数字后`x`,`dp[x]`存储该数字的最佳答案。 
9. 输出`dp[n]`。 

### 为什么它有效

 动态编程状态表示从给定值达到零所需的真实最小操作数。 

每个有效的第一步从`x`必须减去它的一位数字。 选择数字后`d`，剩下的工作正是最优解`x - d`。 因此，每一个有效的策略都是有成本的`1 + dp[x - d]`对于某些数字`d`出现在`x`。 

该算法会检查所有此类第一步并保留最小值。 由于所有较小的状态都已正确计算，因此所选的最小值等于真正的最佳状态`x`。 通过对增加的值进行归纳`x`，每个状态都被正确计算，包括`dp[n]`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    dp = [0] * (n + 1)

    for x in range(1, n + 1):
        dp[x] = 10**9

        t = x
        while t > 0:
            d = t % 10
            if d != 0:
                dp[x] = min(dp[x], dp[x - d] + 1)
            t //= 10

    print(dp[n])

if __name__ == "__main__":
    solve()
```数组`dp`存储每个值的最小操作数，最多`n`。 

外循环按升序处理数字。 这种顺序很重要，因为每个转换都来自`x`到`x - d`，每当`d > 0`。 当我们计算时`dp[x]`，所有必需的前驱状态都已经可用。 

通过重复取模和除法直接进行数字提取。 这避免了将每个数字转换为字符串并保持实现简单高效。 

忽略数字`0`很重要。 减零不会改变数字，并且会创建从状态到自身的转换。 这样的举动永远无法改善答案。 

基本情况`dp[0] = 0`锚定整个复发。 单位数字自然有效，因为其中一位数字等于数字本身，允许直接过渡到零。

 ## 边缘情况

 考虑输入：```
0
```算法初始化`dp[0] = 0`并且不执行任何转换。 输出立即`0`。 这与数字已经为零的事实相符。 

考虑输入：```
10
```加工时`10`，提取的数字是`1`和`0`。 该算法忽略了`0`并仅使用通过数字的转换`1`：`dp[10] = dp[9] + 1 = 2`。 

结果序列是`10 → 9 → 0`，这是最优的。 

考虑输入：```
7
```唯一的非零数字是`7`。 过渡变为：`dp[7] = dp[0] + 1 = 1`。 

该算法正确地识别出单次减法达到零。 

考虑输入：```
100
```数字是`1`,`0`， 和`0`。 该算法忽略两个零并仅考虑相减`1`，产生过渡到`99`。 没有引入无效的自转换，DP 正常继续。 这正是问题所要求的行为。
