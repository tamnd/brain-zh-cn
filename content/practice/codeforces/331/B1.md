 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列，但排列不仅仅是数据，它定义了“海狸排成一行”的固定顺序。 每个数字只出现一次，但每个值的位置由于交换而随着时间而变化。 

类型 1 的查询询问值区间 [x, y]。 我们想知道需要多少次连续的“剃须会话”才能覆盖从 x 到 y 的所有值。 如果在排列内部，x、x+1、x+2、...、y 的位置在限制为该组时以递增的索引顺序出现，则单个会话可以处理一组值，这意味着它们形成一个尊重值顺序的子序列。 如果全局失败，我们将值范围分成多个连续的段，以便每个段在排列中变得“顺序一致”。 

类型 2 的查询会交换排列中的两个位置，因此它会动态更改我们查询的结构。 

核心隐藏结构是，我们并不是真正检查通常意义上的子序列，而是计算从 x 到 y 的值的位置序列“打破单调性”的次数。 

这些约束推动每次操作的更新为对数或接近恒定。 对于最多 10^5 个查询和 n 最多 3×10^5，任何每次查询扫描 [x, y] 的解决方案都会立即变得太慢，因为最坏情况下的总工作量将为 O(nq)，大约是 10^10 次操作。 

当排列已经完全有序或接近有序时，就会出现微妙的边缘情况。 例如，如果数组为 [1, 2, 3, 4, 5]，则每个查询都会返回 1。简单的实现可能仍然会扫描间隔并不必要地重新计算位置，从而通过小型测试但未通过完整约束。 

当交换创建局部反转时，会出现另一种故障模式，该局部反转不会立即影响全局结构，但仍会增加段的数量。 例如，交换 [1,2,3,4,5] 中的 2 和 3 会在位置序列中创建一个中断，这会更改涵盖这两个值的所有范围的答案。 任何尝试“本地修复”而不维护全局结构的解决方案都会错过这种传播。 

## 方法

 蛮力方法很简单。 对于每个查询 [x, y]，我们按值的递增顺序收集 x 到 y 值的位置，并计算从 x 移动到 x+1 时位置序列减少了多少次。 每次减少都表明需要一个新的段。 这是正确的，因为段完全对应于位置不断增加的最大连续值块。 

然而，这需要对每个查询迭代最多 O(n) 个值，在最坏的情况下导致总复杂度为 O(nq)。 对于 10^5 次查询，这太慢了。 

关键的见解是，答案仅取决于范围内的相邻值是否在排列顺序中被“破坏”。 将 pos[v] 定义为值 v 在排列中的位置。 那么对于固定间隔[x,y]，会话数为：

 1 + [x, y-1] 中索引 i 的计数，使得 pos[i] > pos[i+1]。 

因此，问题不再是推理任意子序列，而是减少到计算值空间中相邻值的反转，但使用动态数组 pos[v]。 

我们需要支持两种操作：位置上的点更新（交换元素时），以及计算值区间中有多少个相邻对（i，i+1）满足条件的范围查询。 这是值轴上线段树的经典设置，存储每个相邻对是否“坏”。 

每个叶子代表一个值 i 并存储一个 0/​​1 指示符来指示 pos[i] > pos[i+1] 是否。 交换两个元素仅影响交换值周围的本地比较，因此我们更新 O(1) 或 O(log n) 位置。 范围总和查询然后给出中断的数量。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了 |
 | 相邻比较的线段树 | O(q log n) | O(q log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护两个数组：pos[v]（值 v 在排列中的位置）和 arr[p]（位置 p 处的值）。 

我们还维护一个索引 1 到 n-1 的线段树，其中每个索引 i 存储是否 pos[i] > pos[i+1]。 

1. 根据输入排列构建初始数组 pos 和 arr。 在此过程中，计算 i 从 1 到 n-1 的每个比较指标。 此步骤初始化捕获所有未来查询答案的结构。 
2. 根据这些指标构建线段树。 每个节点存储其段的总和，该总和表示该值区间内“中断”的数量。 
3. 要回答类型 1 查询 [x, y]，请在线段树中查询索引 [x, y-1] 的总和。 结果是中断次数，因此答案是总和加一。 这是有效的，因为每次突破都会将连续增加的价值链分割成一个新的部分。 
4. 要处理位置 x 和 y 处的交换，令涉及的值为 a = arr[x] 和 b = arr[y]。 交换arr[x]和arr[y]后，更新pos[a]、pos[b]和arr[x]、arr[y]。 
5. 交换后，只有涉及a 或b 的比较可以改变。 这会影响索引 a-1、a、b-1 和 b（在范围内时）。 对于每个受影响的索引 i，重新计算是否 pos[i] > pos[i+1] 并更新该点的线段树。 
6. 继续按顺序处理所有查询。 

正确性依赖于这样一个事实：只有值空间中的邻接关系才重要，并且交换只会改变两个值的位置，因此只有涉及这些值的比较才会改变。 

## 为什么它有效

 关键的不变量是，对于每个相邻对 (i, i+1)，线段树准确存储这两个值在排列中的相对顺序是否反转。 每个有效的剃须段对应于不发生此类反转的最大连续值范围。 因此，对段进行计数简化为对这个二进制数组中的运行之间的边界进行计数。 由于交换仅影响两个值的位置，因此只有涉及这些值的比较才能更改，从而保持结构一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v*2, l, m, arr)
        self.build(v*2+1, m+1, r, arr)
        self.t[v] = self.t[v*2] + self.t[v*2+1]

    def update(self, v, l, r, i, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v*2, l, m, i, val)
        else:
            self.update(v*2+1, m+1, r, i, val)
        self.t[v] = self.t[v*2] + self.t[v*2+1]

    def query(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return 0
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        return self.query(v*2, l, m, ql, qr) + self.query(v*2+1, m+1, r, ql, qr)

n = int(input())
arr = [0] + list(map(int, input().split()))

pos = [0] * (n + 1)
for i in range(1, n + 1):
    pos[arr[i]] = i

if n == 1:
    q = int(input())
    for _ in range(q):
        input()
        print(1)
    sys.exit()

diff = [0] * (n)  # 1..n-1 used
for i in range(1, n):
    diff[i] = 1 if pos[i] > pos[i+1] else 0

st = SegTree(n-1)
st.build(1, 1, n-1, diff)

q = int(input())
for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        x, y = tmp[1], tmp[2]
        if x == y:
            print(1)
            continue
        res = st.query(1, 1, n-1, x, y-1)
        print(res + 1)
    else:
        x, y = tmp[1], tmp[2]
        a, b = arr[x], arr[y]

        if a == b:
            continue

        # swap in array
        arr[x], arr[y] = arr[y], arr[x]
        pos[a], pos[b] = y, x

        def fix(i):
            if 1 <= i <= n-1:
                val = 1 if pos[i] > pos[i+1] else 0
                st.update(1, 1, n-1, i, val)

        fix(a-1)
        fix(a)
        fix(b-1)
        fix(b)
```该实现将值空间结构与位置更新分开。 线段树从不存储原始位置，只存储值顺序的邻接关系，这使得查询独立于范围大小。 

一个常见的陷阱是试图通过头寸而不是价值来维护细分结构。 这会导致复杂的区间合并在交换下中断。 正确的观点是，价值定义了稳定轴，而不是位置。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(q log n) | O(q log n) | 每次交换都会更新 O(1) 个线段树点，每次查询都是一个范围和 |
 | 空间| O(n) | 数组加线段树存储 |

 约束允许最多 10^5 次操作，其中 n 最多为 3×10^5，因此每次操作对数就足够了。 线段树确保我们永远不会显式扫描大区间。

 ## 边缘情况

 当数组完全排序时，会出现关键的边缘情况。 在这种情况下，所有 diff 值都为零，并且每个查询都返回 1。该算法自然地处理此问题，因为线段树始终返回总和 0，因此输出为 1。 

另一种情况是交换涉及价值空间中的相邻值。 例如，交换值 i 和 i+1 的位置会根据它们的新位置直接切换 diff[i]，并且如果位置重叠，还会影响相邻的比较。 更新逻辑显式地重新计算两个交换值周围的 i-1 和 i+1 边界，以确保正确性。 

最后，同一对的重复交换测试过时的线段树值是否仍然存在。 由于每次交换都会重新计算 pos[] 中所有受影响的比较，因此不会保留任何历史依赖性，并且无论操作历史如何，结构都保持一致。
