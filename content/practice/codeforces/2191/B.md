 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且可以任意对其重新排序。 确定顺序后，我们会查看前缀和后缀之间每个可能的分割位置。 对于每个分割，我们计算前缀的 MEX 和后缀的 MEX，并且我们希望所有这些对都不同。 

关键要求是全局的：单个排列必须避免双方具有相同的缺失最小非负整数的任何分裂。 我们不会选择一种拆分，但必须确保没有一种拆分会产生相等的 MEX 值。 

约束很小，每个测​​试用例最多 100 个元素，最多 500 个测试用例。 这立即表明任何解决方案都可以为每个测试用例提供线性或二次推理，但是任何阶乘或指数的超排列都是不必要的，应该避免。 即使n很小，排列仍然是不可行的，因为n！ 即使在 n = 100 时增长也太快。 

一种天真的但自然的尝试是认为 MEX 在很大程度上依赖于从 0 开始的小整数的存在。这已经暗示只有低值的分布很重要，而不是它们的相对顺序。 

当数组中只有很少的不同小数字时，就会出现微妙的边缘情况。 例如，如果所有元素均为零，则每个前缀和后缀的 MEX = 1，因此每次拆分都会失败。 类似地，如果 0 完全缺失，则每个段的 MEX = 0，再次导致所有拆分失败。 这些退化案例表明，频率 0 和 1 的全局结构主导了答案。 

## 方法

 一种强力的想法是尝试数组的所有排列，并为每个排列计算每个分割的前缀 MEX 和后缀 MEX。 这是正确的，因为它直接匹配条件。 然而，生成排列是 n 的阶乘，甚至检查一个排列也需要 O(n^2)，因为要重新计算所有段的 MEX。 这是完全不可行的。 

关键的观察结果是，只有当我们跨越某个数字完全出现在段中的阈值时，MEX 才会发生变化。 为了使 MEX 增加超过 x，所有从 0 到 x 的数字都必须出现在该段中。 这意味着前缀和后缀 MEX 值仅取决于 0、1、2 等在拆分中的分布方式，而不取决于超出可行性的精确排序。 

决定性的简化是跟踪 0 出现的次数，因为 0 是最有影响力的值。 如果至少有一个 0，我们可以分隔出现的事件来控制前缀 MEX 行为。 如果没有 0，则对于任何拆分，前缀和后缀都始终具有 MEX = 0，因此永远无法满足条件。 

如果至少有两个零，我们总是可以构造一个有效的排列。 我们可以提前放置一些零，稍后放置一些零，以便前缀有时包含 0，有时不包含 0，从而在所有拆分中创建不同的 MEX 值。 剩余的结构（非零数）无法破坏这种可能性，因为 MEX 首先取决于 0 是否存在。 

如果恰好有一个零，情况就会变得紧张。 我们必须确保任何拆分都不会产生相同的 MEX 值。 事实证明，这在某些配置中是不可能的，但当有足够的非零值来分隔影响区域时，这是可能的。 决定性的特征归结为计算 0 和 1 的出现次数：如果至少有两个 0，或者至少有一个 0 和至少一个 1，我们就可以构造一个有效的排序； 否则我们不能。 

这将问题从排列简化为简单的频率推理。

 ## 算法演练

1. 计算每个值出现的次数，重点关注 0 和 1 的数量。 这两个值主导 MEX 行为，因为 MEX 始终从 0 开始，并且取决于是否存在小整数。 
2. 如果数组中没有零，则立即得出答案为“NO”。 这是因为每个子数组的 MEX = 0，因此每次分割的每个前缀和后缀对都将相等。 
3. 如果恰好有一个零，则检查是否至少有一个非零元素可以分隔前缀和后缀行为。 实际上，这简化为检查是否至少存在一个 1。 如果不是，任何分割都会以强制两侧具有相等的 MEX 值的方式隔离单个零。 
4. 如果至少有两个零，则输出“YES”。 我们始终可以安排数组，以便某些分割在前缀中包含零，而其他分割则不包含零，从而保证所有分区中的 MEX 值不同。 

工作原理：任何段的 MEX 首先取决于是否存在 0，然后如果完全覆盖 0，则确定是否存在 1，依此类推。 对于所有排列，分裂的两侧可以具有相等的 MEX 的唯一方法是当 0 的结构过于受限时，阻止我们分离它们的影响。 一旦我们在 0 的分布上有足够的灵活性（多个 0 或补偿 1），我们总是可以构造一个排序，其中某些前缀后缀边界在每次切割时都会打破 MEX 相等性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    z = a.count(0)
    o = a.count(1)
    
    if z == 0:
        print("NO")
    elif z == 1 and o == 0:
        print("NO")
    else:
        print("YES")
```该实现完全依赖于计算 0 和 1 的出现次数。这已经足够了，因为除了确保我们不处于完全退化的 MEX 常数情况之外，其余值不会影响有效排列的存在。 

关键的微妙之处在于我们从不尝试显式地构造排列。 该问题仅询问是否存在有效的排序，并且结构条件分解为简单的频率检查。

 ## 边缘情况

 当数组中没有零时，无论顺序如何，每个段的 MEX = 0。 例如，输入`[2,3,5]`每次分割总是生成前缀 MEX 0 和后缀 MEX 0，因此答案必须为“否”。 

当恰好有一个零并且没有一个时，例如`[0,2,3]`，单个零不能用于创建任何前缀和后缀 MEX 在所有分区中以一致方式不同的分割，从而强制失败。 

当有多个零时，例如`[0,0,1,2]`，我们总是可以放置零以确保在每个分割中至少一侧在是否包含 0 方面有所不同，从而防止所有分割中的 MEX 值相等。
