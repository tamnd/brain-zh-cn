 ## 解决方案
 ## 问题理解

 我们得到一个数字序列，并重复应用仅取决于当前序列的最后一个元素的转换。 每个转换将数组分成两个子序列：不大于最后一个元素的元素位于前面，严格大于最后一个元素的元素位于后面，同时保留其在每个组内的原始相对顺序。 然后该数组将被此串联替换。 

系统会询问我们需要应用此操作多少次，直到数组停止更改。 一旦应用变换不再改变数组，进一步的应用将保持它不变，并且我们在稳定发生的第一时刻输出。 

这些约束允许跨测试用例最多有 2·10^5 个总元素，这会立即排除最坏情况下的任何二次模拟。 当数组演化缓慢时，重复重建数组并扫描每个操作的完整序列的简单方法可能会降级为 O(n^2)，这在限制下太慢了。 

当数组已经位于固定点时，会出现微妙的边缘情况。 例如，如果所有元素都相等，例如 [7, 7, 7, 7]，则最后一个元素将所有元素划分到左侧，并且没有任何元素向右移动，因此数组永远不会改变。 正确答案是 0。粗心的模拟可能仍会执行一次完整的迭代，并错误地将其视为有意义的更改。 

另一个重要的情况是数组严格递增。 对于 [1, 2, 3, 4]，最后一个元素始终是最大值，因此同样没有任何移动，答案为 0。这表明该过程不一定“排序”，仅当枢轴之前出现更大的元素时才重新组织。 

## 方法

 直接模拟很简单：对于每一步，获取最后一个元素，扫描数组，根据元素是否≤或>这个主元将其分成两个列表，然后将它们连接起来。 每一步的成本为 O(n)。 问题是，在最坏的情况下，我们可能需要模拟最多 O(n) 个步骤，因为每个操作只能部分改善排序。 这导致 O(n^2)，对于 2·10^5 的总元素来说太大了。 

关键的观察是该过程是由大于当前主元的元素的位置驱动的。 每个操作都有效地“推动”已经相对于最终排序结构正确放置的元素之间的边界。 我们可以推断后缀中已有多少元素在所有未来操作下都是稳定的，而不是模拟变化。 

如果我们从末尾开始扫描，我们可以保持到目前为止看到的最大值。 每当我们遇到一个大于此运行最大值的元素时，这意味着该元素最终将迫使至少再发生一次非平凡的翻转，然后才能进入正确的区域。 每一个这样的“后缀优势的中断”都对应于一个所需的操作。 

具体来说，我们计算从右向左遍历时看到新最大值的次数，不包括最终的最大元素本身。 该计数直接对应于稳定之前有效变化的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 带最大跟踪的反向扫描 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 从数组的最后一个元素开始，将其视为当前最大值。 该元素在任何操作中都不会超出自身，因此它形成了初始的稳定后缀。 
2. 从右向左遍历数组，保持该方向迄今为止看到的最大值。 该最大值表示定义较早元素是否已与最终排序“兼容”的阈值。 
3. 每次遇到严格大于当前最大值的元素时，我们都会更新最大值并递增计数器。 此事件代表后缀排序中的结构性违规，如果没有至少一个外翻步骤，就无法解决该问题。 
4. 遍历完成后，计数器表示在到达固定点之前数组的结构必须被纠正多少次。 
5. 返回此计数器作为答案。 

### 为什么它有效

 每个版本都使用最后一个元素作为基准，并根据该值分隔元素。 最终的稳定配置对应于这样的情况：从右侧看，没有更早的元素超过最大后缀元素。 从右侧扫描时每次出现新的最大值，都标志着一个点，在阵列稳定之前，该点最终必须成为某些操作的枢轴。 由于这些最大值的遇到顺序与通过翻转解决它们的顺序相反，因此对它们进行计数可以准确地给出必要操作的数量，直到无法进一步重新排列为止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = 0
        ans = 0
        
        for i in range(n - 1, -1, -1):
            if a[i] > mx:
                mx = a[i]
                ans += 1
        
        out.append(str(max(0, ans - 1)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```代码独立处理每个测试用例。 反向扫描保持运行最大值。 每次出现新的最大值时，它都会增加一个计数器。 最终答案通过减一进行调整，因为最后看到的最大值对应于已经稳定的后缀，不需要进行操作。 这种微妙的减法是确保正确性的主要实现细节：没有它，完全排序的数组将错误地返回 1 而不是 0。

 我们得到 counter = 2，减去 1 后得到 1。这符合这样的事实：在一次有意义的翻转之后，数组变得稳定。 

### 示例 2：[5, 3, 2, 4, 1]

 | 索引（右→左）| 价值| 电流最大值 | 新麦克斯？ | 专柜|
 | ---| ---| ---| ---| ---|

 计数器 = 3，最终答案 = 2。这与声明中显示的两步稳定过程相匹配。 

这些痕迹表明，每次较大的元素出现在当前后缀最大值的左侧，它对应于外翻序列中所需的结构校正。

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()
