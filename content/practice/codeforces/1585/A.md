 ## 解决方案
 ## 问题理解

 我们获得了一朵花几天的浇水历史。 数组的每个元素代表一天。 值为`1`意味着花被浇过水，而`0`意味着它被忽视了。 

花从高度开始`1`。 每一天浇水都会增加高度，但数量取决于前一天发生的情况。 如果连续两天都浇水，则当天贡献`5`厘米。 否则一天浇水只会有贡献`1`。 干燥的一天没有任何贡献。 如果连续两天出现干旱，花会立即死亡，答案为`-1`。 

测试用例数量最多为`100`，每个测试用例最多包含`100`天。 即使每天一一检查的算法也只能执行一万次左右的运算，这是很小的。 不需要比线性扫描更复杂的东西。 

有几种情况很容易处理不当。 

一种情况是第一天干燥时。 例如：```
1
1
0
```答案是`1`， 不是`0`。 花已经有高度了`1`在任何一天开始之前。 

另一种情况是连续两天干燥。```
1
4
1 0 0 1
```正确答案是`-1`。 粗心的实施可能会简单地跳过干燥的日子并继续处理，从而产生不正确的正高度。 

连续浇水的日子也需要注意。```
1
3
0 1 1
```答案是`7`。 第二天贡献`1`，第三个贡献`5`，所以最终高度变为`1 + 1 + 5 = 7`。 将每天浇水视为添加`1`会给出错误的结果。 

## 方法

 最直接的想法就是完全按照描述来模拟花的生命。 我们从左到右处理这些天，保持当前的高度，并在需要确定当天产生多少增长时检查前一天。 由于每天访问一次，最坏的情况只需要`100`每个测试用例的操作。 

暴力模拟已经完全符合限制。 不需要动态编程或预处理，因为每天的效果仅取决于前一天。 规则的局部性质意味着我们可以在扫描数组时立即决定一切。 

关键的观察结果是只有三种模式很重要。 一对`0 0`杀死花。 一对`1 1`添加`5`第二天。 单个隔离`1`添加`1`。 由于这些条件仅取决于相邻元素，因此遍历数组一次就足够了。

 ## 算法演练

 1. 初始化花的高度为`1`，因为这是处理任何一天之前的起始高度。 
2. 从左到右遍历数组。 
3. 如果当天和前一天都是`0`，立即停止并将答案标记为`-1`。 一旦连续两天出现干旱，花就会枯死。 
4. 如果当天浇水且前一天也浇水，则添加`5`到高度。 规则规定当天贡献`5`而不是`1`。 
5. 如果当天浇水但前一天干燥，则添加`1`到高度。 
6. 如果当天干燥，则不添加任何物质。 
7. 处理完所有天数后，输出高度，除非花较早死亡。 

### 为什么它有效

 处理日后`i`，存储的高度等于之后花朵的实际高度`i`天，只要花还活着。 每对可能的连续天都根据规则进行处理。 一个`0 0`一对会导致立即终止，而每个浇水的日子都会精确地贡献问题指定的数量。 由于算法按时间顺序再现每天的效果，因此最终结果必须与花朵的真实高度相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        height = 1
        alive = True

        for i in range(n):
            if a[i] == 1:
                if i > 0 and a[i - 1] == 1:
                    height += 5
                else:
                    height += 1
            else:
                if i > 0 and a[i - 1] == 0:
                    alive = False
                    break

        if alive:
            ans.append(str(height))
        else:
            ans.append("-1")

    sys.stdout.write("\n".join(ans))

solve()
```变量`height`开始于`1`，匹配花的初始状态。 该循环按时间顺序处理天。 对于浇水的一天，我们回顾一个位置来决定贡献是否是`1`或者`5`。 

条件`i > 0`阻止访问`a[-1]`处理第一天的时候。 这种边界情况很容易被忽视。 

一旦找到一对连续的零，循环就会停止。 再继续下去就没有意义了，因为花已经死了。 

由于高度永远不会超过几百，所以普通整数就足够了。

 ## 边缘情况

 考虑输入```
1
1
0
```算法从高度开始`1`。 唯一一天是干燥的，所以不会生长。 由于没有前一天，因此无法触发死亡条件。 输出变为`1`。 从高度开始`0`会产生错误的答案。 

考虑```
1
4
1 0 0 1
```第一天后，高度变为`2`。 第二天没有任何贡献。 在第三天，算法注意到当前和前几天都是`0`，将花标记为死亡，然后停止。 输出是`-1`。 

考虑```
1
3
0 1 1
```第一天没有任何贡献。 第二天添加`1`，将高度增加到`2`。 第三天的先前值为`1`，所以它添加了`5`，产生最终高度`7`。 该算法正确区分单独浇水和连续浇水。
