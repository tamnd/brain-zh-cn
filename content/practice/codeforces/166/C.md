 ## 解决方案
 ## 问题理解

 我们从一个整数数组和一个目标值开始`x`。 我们可以将任意数量的额外整数附加到数组中，并且我们希望最终数组的中位数恰好变为`x`。 任务是计算实现这一目标所需的最少添加元素数。 

这里中位数的定义遵循 Codeforces 约定。 对数组进行排序后，中位数就是位置处的元素`⌊(n + 1) / 2⌋`使用从 1 开始的索引。 对于偶数长度的数组，这意味着选择左侧中间的元素。 

约束足够小，重复排序是完全可以承受的。 原数组长度最多为`500`，并且每个添加的元素只会稍微增加大小。 甚至一个`O(n^2 log n)`解决方案会很顺利地通过。 挑战不在于性能，而在于准确理解条件是什么`x`中位数以及如何用最少的插入来实现它们。 

第一个微妙的情况出现在`x`数组中根本不存在。 

例子：```
n = 3, x = 10
array = [20, 30, 40]
```答案不是`0`，尽管我们可以想象以某种方式改变位置。 如果`10`不存在，中位数永远不可能成为`10`，因为中位数必须是排序后的实际数组元素。 我们必须插入至少一个`10`。 

另一个容易犯的错误来自于误解哪个中间元件用于均匀长度。 

例子：```
n = 4, x = 4
array = [1, 4, 5, 6]
```排序顺序为：```
[1, 4, 5, 6]
```中位位置是`⌊(4 + 1) / 2⌋ = 2`，所以中位数是`4`， 不是`5`。 使用正确的中间元素的粗心实现会产生错误的答案。 

更微妙的边缘情况发生在`x`已经存在，但在它之前有太多更小的元素。 

例子：```
n = 5, x = 4
array = [1, 2, 3, 4, 100]
```排序后的数组为：```
[1, 2, 3, 4, 100]
```中位数是`3`， 不是`4`。 我们不能通过插入小于的数字来解决这个问题`4`，因为这只会推动`4`甚至更右边。 唯一有用的添加是大于或等于的数字`4`，这将中位位置向出现的方向移动`4`。 

相反的情况也很重要。 

例子：```
n = 5, x = 10
array = [10, 20, 30, 40, 50]
```中位数已经是`30`。 在这里，插入大量数字并没有帮助。 我们需要较小的数字来将中间位置向左拉，直到它落在`10`。 

这些方向效应是解决方案背后的关键观察结果。 

## 方法

 在这里，暴力方法出奇地自然。 我们可以反复测试当前中位数是否等于`x`。 如果没有，我们会插入一个精心挑选的数字，然后重试。 

最简单的版本是这样的。 对数组进行排序。 如果中位数小于`x`，插入另一个`x`。 如果中位数大于`x`，还插入另一个`x`。 继续下去，直到中位数变为`x`。 

这是正确的，因为每次插入`x`增加出现次数`x`并逐渐将中线拉向它。 由于约束很小，即使在每次插入后重复排序也足够快。 

这种蛮力想法的弱点在于概念性而非计算性。 它没有解释为什么这个过程有效或者什么条件真正定义了成功。 我们需要更清晰的表征。 

重要的观察是，排序后，出现了一些`x`必须占据中间位置。 假设我们对数组进行排序并查看第一次出现的`x`。 

如果该出现位于中间位置的左侧，则存在太多大于的元素`x`。 我们必须添加较小的数字来将中位数索引相对于`x`。 

如果该出现位于中间位置的右侧，则存在太多小于`x`。 我们必须添加更大的数字来相对于中值索引右移`x`。 

实现这一点的更干净的方法甚至更简单。 我们不断插入`x`本身，直到中位数变为`x`。 

为什么这有效？ 添加`x`永远不会改变较小值和较大值之间的相对顺序。 它只会增加相同值的块。 最终，中值指数必须落在该块内。 

由于最多需要几百次插入，重复排序是完全可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k·n log n) | O(k·n log n) | O(n) | 已接受 |
 | 最佳 | O(k·n log n) | O(k·n log n) | O(n) | 已接受 |

 这里，`k`是插入元素的数量。 在给定的约束条件下，`k`仍然很小。 

## 算法演练

 1.读取数组并插入一份`x`如果数组尚不包含它，则立即执行。 

此步骤是强制性的，因为中位数必须等于实际的数组元素。 
2. 对数组进行排序。 

中位数仅取决于排序顺序，因此每次检查都必须在排序后进行。 
3. 计算中位数指数为`(len(array) - 1) // 2`。 

这是问题定义的从零开始的版本。 
4. 检查中位数元素是否等于`x`。 

如果有，请立即停止。 当前插入的数量很少，因为我们只在必要时插入。 
5. 如果中位数小于`x`，追加另一个`x`。 

这会增加大于或等于的元素数量`x`，将中值向上推。 
6. 如果中位数大于`x`，还附加另一个`x`。 

这会增加小于或等于的元素数量`x`，将中值向下推。 
7. 重复步骤 2，直到中位数变为`x`。 

### 为什么它有效

 每次插入都会添加另一个副本`x`，扩展连续块`x`按排序顺序排列的值。 中值位置随着数组的增长而变化，但是块`x`价值观也随之增长。 最终，中值指数落在该区块内。 

由于每次操作都会增加`x`正好是一，没有更小的操作序列可以使中位数变成`x`早些时候。 中位数等于的第一个时刻`x`必然是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
arr = list(map(int, input().split()))

added = 0

while True:
    arr.sort()

    median = arr[(len(arr) - 1) // 2]

    if median == x:
        print(added)
        break

    arr.append(x)
    added += 1
```由于基本思想很简单，所以有意使其实现紧凑。 

循环始终从对数组进行排序开始。 由于中位数取决于排序顺序，因此在排序之前进行检查是没有意义的。 

中位数指数使用：```
(len(arr) - 1) // 2
```这与问题的偶数长度的左中定义相匹配。 使用`len(arr) // 2`会错误地选择正确的中间元素并在许多情况下失败。 

每当中位数不是`x`，我们附加另一个`x`。 无需区分中位数是太小还是太大。 添加`x`在两个方向上都有帮助，因为它扩大了等值的块。 

变量`added`跟踪我们插入了多少个数字。 由于每次循环迭代都只插入一个值，因此第一个成功状态自动为最小状态。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k·n log n) | O(k·n log n) | 每次插入后都会对数组进行排序 |
 | 空间| O(n) | 数组本身存储所有元素 |

 和`n ≤ 500`，重复排序很容易足够快。 即使我们插入了数百个元素，与 2 秒的限制相比，总工作量仍然很小。
