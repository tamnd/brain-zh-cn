 ## 解决方案
 ## 问题理解

 我们得到了编程竞赛的最终结果。 每个团队都有两个附加值：它解决了多少问题以及它的总罚时。 

排名规则是标准的 ICPC 式排序。 如果团队解决的问题越多，排名就越高。 如果两队解决了相同数量的问题，则罚分较小的一方排名较高。 拥有完全相同配对的球队`(solved, penalty)`积分榜上的位置相同。 

任务是确定有多少团队共享`k`-第一个地方。 

关键细节是不保证输入已按排名排序。 我们首先要根据比赛规则重建积分榜，然后确定坐在位置上的队伍`k`，最后统计有多少支球队的结果相同。 

限制非常小。 最多有 50 个团队，因此即使是二次算法也很容易足够快。 50 个元素的排序基本上是瞬时的。 这意味着问题不在于优化压力，而在于正确执行排名规则，没有细微的错误。 

最常见的错误是误解“共享第 k 个位置”的含义。 问题不在于询问当前存储在索引处的团队`k`。 它要求所有成绩与占据该位置的球队相同的球队`k`排序后的第 - 个位置。 

考虑这个例子：```
5 4
5 1
4 10
4 10
4 10
3 1
```排序后，积分榜变为：```
1st: (5,1)
2nd-4th: (4,10)
5th: (3,1)
```第4名属于`(4,10)`组，所以答案是`3`。 

粗心的实现可能只检查确切的索引`k-1`和输出`1`。 

当所有团队都相同时，会出现另一个微妙的情况：```
4 2
3 20
3 20
3 20
3 20
```每个队共享从 1 到 4 的每个位置。正确答案是`4`。 

尝试手动分配唯一排名的错误实现可能会意外地将相等的团队分开。 

还有一个潜在的差一错误，因为 Codeforces 位置的索引为 1，而 Python 列表的索引为 0。 如果`k = 1`，相关团队位于索引处`0`排序后。 

## 方法

 蛮力的想法很简单。 我们可以将每个团队与其他团队进行比较并手动确定排名组。 对于每个团队，我们可以计算有多少团队严格更好，然后确定哪些团队属于同一位置组。 

这是有效的，因为排名规则完全由成对比较确定。 和`n ≤ 50`，甚至一个`O(n²)`在最坏的情况下，该解决方案仅执行 2500 次比较。 

这种方法的弱点不是运行时，而是实现的复杂性。 手动重建排名会带来不必要的簿记，并使关联组周围的边缘情况更容易被错误处理。 

更清晰的观察是，比赛排名实际上是一种排序顺序。 团队排序依据：

 1. 首先解决较大的计数。 
2.先处罚较小的。 

团队排序后，索引处的团队`k-1`定义整个等级组`k`-第一个地方。 每个团队都有相同的`(solved, penalty)`两人共用那个地方。 

这将问题转化为两个简单的操作：

 1. 正确对团队进行排序。 
2. 计算有多少支队伍与当前位置的队伍相等`k-1`。 

排序规则的结构使得排序成为自然的解决方案，因为相同的结果按排序顺序形成连续的块。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n log n) | O(n log n) | O(1) 排除排序空间 | 已接受 |

 ## 算法演练

 1.读取队伍数量`n`和目标地点`k`。 
2. 将每个团队存储为一对`(problems_solved, penalty)`。 
3. 根据比赛排名规则对队伍进行排序。 

解决问题较多的团队必须排在第一位，因此我们按降序对该值进行排序。 对于相同的解决计数，较小的惩罚必须先出现，因此我们按升序对惩罚进行排序。 
4. 将竞赛排名转换为Python索引。 

由于比赛名额的索引为 1，因此代表`k`-th 位置存储在索引处`k-1`。 
5. 将配对保存在索引处`k-1`。 

这对唯一地标识了共享的整个绑定组`k`-第一个地方。 
6. 遍历排序后的列表并统计有多少支球队拥有完全相同的对。 
7. 打印计数。 

### 为什么它有效

 排序后，结果相同的团队会变得相邻，因为排序仅取决于`(solved, penalty)`。 团队所在位置`k-1`代表与相关的确切性能`k`-第一个地方。 具有相同对的每支球队共享位置，而具有不同对的每支球队则属于另一个排名组。 计算相等的对即可得出正确答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

teams = []

for _ in range(n):
    p, t = map(int, input().split())
    teams.append((p, t))

teams.sort(key=lambda x: (-x[0], x[1]))

target = teams[k - 1]

answer = 0

for team in teams:
    if team == target:
        answer += 1

print(answer)
```第一部分读取输入并将每个团队存储为一个元组。 使用元组很方便，因为相等检查变得自动且可靠。 

分拣线是解决方案的核心：```
teams.sort(key=lambda x: (-x[0], x[1]))
```负号打开`x[0]`为已解决的问题创建降序排列。 惩罚仍然是积极的，因为较小的惩罚应该排名较高。 

排序后，`teams[k - 1]`识别对应的性能`k`-第一个地方。 减一是必要的，因为 Python 使用从零开始的索引。 

最后的循环计算该确切元组的每次出现。 由于并列球队是通过两个值相等来定义的，因此元组比较完全符合比赛规则。 

一个常见的实施错误是也按降序对惩罚进行排序。 这会错误地将较大的处罚排在较小的处罚之前。 

另一个常见的错误是只计算索引周围连续的相等球队`k-1`。 虽然这也有效，因为排序后平等的团队是连续的，但完整的遍历更简单且不易出错。

import io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())

        p, t = map(int, input().split())

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

 ## 边缘情况

 一个棘手的情况是当请求的位置位于平局组的中间时。 

输入：```
5 4
5 1
4 10
4 10
4 10
3 1
```排序后：```
(5,1)
(4,10)
(4,10)
(4,10)
(3,1)
```第4位对应索引`3`，仍然属于`(4,10)`。 该算法将该元组存储为目标并对所有相同的元组进行计数，从而产生`3`。 

另一个微妙的情况是每个团队都相同。 

输入：```
4 2
3 20
3 20
3 20
3 20
```排序不会改变任何事情。 目标元组是`(3,20)`，并且每个团队都匹配它。 算法正确返回`4`。 

当出现相差一边界情况时`k = 1`。 

输入：```
3 1
5 10
4 1
3 1
```排序后，目标位于索引处`0`，即`(5,10)`。 只有一支球队与之匹配，所以答案是`1`。 

使用`teams[k]`而不是`teams[k - 1]`会错误地选择排名第二的球队。
