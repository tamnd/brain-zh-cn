 ## 解决方案
 ## 问题理解

 我们得到一排瓷砖，最初每个瓷砖的高度为 1。随着时间的推移，高度只会增加。 每个操作都会选择一个连续的段，并将相同的值添加到该段中的每个图块。 每次操作之后，我们必须评估遍历从图块 1 到图块 k 的整条线有多困难。 

在相邻图块之间局部评估遍历。 当从图块 i 移动到图块 i+1 时，所需的跳跃高度仅取决于图块 i+1 比图块 i 高多少。 如果图块 i+1 不更高，则该步骤没有困难。 如果更高，则所需的跳跃等于高度差。 如果员工的跳跃能力至少是路径上任意位置的最大向上台阶，则该员工在一轮中成功。 

因此，每一轮都减少为计算一个数字：应用到目前为止的所有更新后，所有连续图块对之间的最大正相邻差。 一旦知道该值，我们就会计算有多少员工的跳跃高度至少为该值。 

这些约束使得简单的重新计算变得不可能。 最多有 100,000 个图块和 100,000 个更新，每个更新都会更改一个范围。 每次更新后重新计算所有图块高度并扫描相邻差异将花费 O(nm)，这太大了。 除非仔细优化，否则即使每个查询的 O(n log n) 也会很紧张。 

关键的困难在于更新是范围添加，但查询取决于相邻差异，而不是原始值。 

一些边缘情况很容易被忽略。 如果 k 等于 1，则图块之间没有跳跃，因此无论更新如何，每个员工总是成功。 如果所有更新都平衡，从而没有相邻的增长变得积极，那么答案应该是所有员工。 如果早期出现较大的正峰值，则后续更新可能会通过以不同方式增加左侧或右侧来间接减少它，因此我们必须精确跟踪差异，而不是从头开始重新计算高度。 

## 方法

 直接模拟会在每次更新后重新计算所有图块高度，然后扫描所有相邻对以查找最大向上差异。 这是可行的，因为定义很简单：构建数组、计算差异并取最大值。 问题在于，每次更新都会修改 O(k) 个图块，并且每个查询都需要另一次 O(k) 扫描，导致总工作量为 O(mk)，这远远超出了限制。 

关键的观察是我们实际上从来不需要完整的瓷砖高度。 我们只需要邻居之间的差异。 如果我们定义 d[i] = h[i+1] - h[i]，那么答案仅取决于该差值数组中的最大正值。 

h 上的范围添加仅影响 d 中的两个位置。 将所有 h[l..r] 增加 x 会使 d[l-1] 增加 x（如果存在），并将 d[r] 减少 x（如果存在）。 其他一切都抵消了。 这将每次更新变成对 d 的 O(1) 修改，并且任务变成维护支持点更新和最大查询的动态数组。 

我们还需要回答有多少员工可以满足当前的最大要求，这是使用排序和二分搜索的标准阈值计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每轮重新计算高度 | O(纳米) | O(n) | 太慢了 |
 | 轨迹差分数组+线段树| O((n + m) log n) | O((n + m) log n) | O(n) | 已接受 |

 ## 算法演练

 我们将问题从跟踪高度转变为跟踪相邻差异。

1. 初始化一个大小为 k-1 且全为零的数组 d。 这表示初始差异，因为所有高度都相等。 
2. 对于每次更新 (l, r, x)，更新差值数组而不是高度数组。 如果 l > 1，则将 d[l-2] 增加 x，因为 h[l] 增加，但 h[l-1] 不增加。 如果 r < k，则将 d[r-1] 减少 x，因为 h[r] 增加，但 h[r+1] 不增加。 这两个调整充分捕捉了范围更新对所有相邻差异的影响。 
3、在d上维护一棵线段树，支持点更新，并且可以查询数组中的最大值。 每次更新后，将两点更改应用于线段树。 
4、本轮所需跳跃难度为最大正相邻差值。 这是 max(0, max(d))。 如果所有差异均为非正，则要求为零。 
5.对员工的跳跃能力进行一次排序。 对于每一轮，使用二分查找来查找有多少员工 j_i ≥ 要求的值。 
6. 输出计数。 

唯一的微妙之处是正确处理边界。 当l = 1时，没有d[l-2]。 当r = k时，不存在d[r-1]。 这些情况必须被跳过。 

### 为什么它有效

 该算法依赖于以下不变量：在任何更新序列之后，每个相邻差值 d[i] 始终等于真实差值 h[i+1] - h[i]。 每个范围更新仅影响两个边界，因为减去相邻高度时内部贡献会抵消。 由于遍历难度仅取决于这些差异，因此保持它们的最大值就足够了。 线段树确保我们在所有 d[i] 上始终具有正确的最大值，因此每轮之后计算的阈值都是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.seg = [0] * (2 * self.n)

    def update(self, i, v):
        i += self.n
        self.seg[i] += v
        i //= 2
        while i:
            self.seg[i] = max(self.seg[2 * i], self.seg[2 * i + 1])
            i //= 2

    def query_max(self):
        return self.seg[1]

def solve():
    n, m, k = map(int, input().split())
    jumps = list(map(int, input().split()))
    jumps.sort()

    if k == 1:
        for _ in range(m):
            input()
            print(n)
        return

    seg = SegTree(k - 1)

    for _ in range(m):
        l, r, x = map(int, input().split())

        if l > 1:
            seg.update(l - 2, x)
        if r < k:
            seg.update(r - 1, -x)

        mx = seg.query_max()
        if mx < 0:
            mx = 0

        import bisect
        ans = n - bisect.bisect_left(jumps, mx)
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先预处理员工跳跃能力，以便每个查询变成单个二分搜索。 线段树存储不断变化的相邻差异，每次更新仅涉及两个索引，从而保持了效率。 最大值被钳位为零，因为负斜率不会导致任何所需的跳跃。 

一个常见的陷阱是忘记只有积极的增长才重要。 另一种方法是试图保持完整的高度，这是不必要的，而且速度太慢。

 ## 边缘情况

 当 k 等于 1 时，没有相邻的转换，因此所需的跳转始终为零。 线段树从不存储任何值，每次查询都直接返回员工数量。 这符合规则，因为不需要移动。 

当更新完全抵消时，例如在一侧添加，然后通过相反的更新在同一边界上减去，差值数组可以返回全零。 然后线段树报告零，确保每个员工都符合资格，无论他们的跳跃能力如何。 

当较大的更新影响第一个或最后一个图块时，仅应用一个边界更新。 这可以避免无效的索引更新并保持正确性，因为在数组边界之外没有丢失的邻居。
