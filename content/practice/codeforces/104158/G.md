 ## 解决方案
 ## 问题理解

 我们有一个员工队列，每个员工都有一个固定的打字时间。 有$N$员工按顺序站好，我们就可以安排$M$电脑在他们面前。 在零时间，第一个$M$员工每人占用一台电脑并开始打字。 每当一台计算机空闲时，排队的下一位员工就会立即拿起该计算机并开始测试。 这一直持续到所有员工都完成为止。 整个流程的结束时间是最后一个员工完成打字的时刻。 

任务是确定最少的计算机数量$M$使得整个队列在给定的期限内完成$D$。 

关键在于分配是严格先进先出的：计算机不会选择最短的剩余作业，它总是为队列中的下一个人服务。 每台机器独立运行并重复处理一系列作业。 

限制因素$N \le 10^5$和$t_i \le 10^4$表明任何模拟每个候选人完整流程的解决方案$M$必须是高效的。 反复逐步推进时间或以低效方式扫描队列的简单模拟会太慢。 即使在没有堆的情况下模拟每个员工完成事件也可能会降级为$O(N^2)$在最坏的情况下，这是不可行的。 

当出现微妙的边缘情况时$M = 1$。 那么完成时间就是所有时间的总和$t_i$，任何贪婪的调度直觉都必须符合这个边界。 另一个边缘情况是当$M \ge N$，每个员工都有一台专用计算机，答案就变成了$\max(t_i)$。 任何未明确处理或自然包含这些情况的实现都会面临不正确的边界行为的风险。 

## 方法

 直接的方法是测试固定数量的计算机$M$并模拟整个过程。 我们分配第一个$M$作业，然后重复选择最早空闲的机器，为其分配下一个作业，并更新其可用性。 使用优先级队列，每个作业分配成本$O(\log M)$，所以模拟所有$N$就业成本$O(N \log M)$。 这是正确的，因为它忠实地模拟了流程，但每个候选人仅有用一次$M$。 

为了解决实际问题，我们需要找到最小的$M$满足截止日期条件。 关键的观察是，如果配置$M$机器在规定时间内完成$D$，那么任何更多的机器数量只能减少等待时间。 当我们添加更多并行服务器时，没有作业会变慢，因此可行性是单调的$M$。 

这种单调结构允许二分搜索$M$。 对于固定的$M$，我们使用机器可用时间的最小堆来模拟该过程。 每项工作都分配给最早的精加工机器，我们跟踪最长完成时间。 二分搜索将模拟次数减少到$O(\log N)$，给出总复杂度$O(N \log N \log N)$，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个 M 的强力模拟 |$O(N^2 \log N)$|$O(N)$| 太慢了 |
 | 二分查找+堆模拟|$O(N \log N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们将问题视为决策问题：给定$M$，我们能在规定时间内完成吗$D$？ 

1. 确定候选人$M$并使用大小的最小堆模拟调度过程$M$。 每个堆元素代表计算机空闲的时间。 最初，所有$M$计算机在时间 0 空闲。 
2. 按顺序迭代员工。 对于每位员工$i$，从堆中提取最小值，它代表最早可用的计算机。 这是将首先完成当前负载的机器。 
3. 分配员工$i$通过添加到该计算机$t_i$到其可用时间并将其推回堆中。 这保持了堆始终包含每台机器的下一个空闲时间的不变性。 
4.处理完所有员工后，该配置的最终答案是所有堆元素中的最大值，代表最后完成时间。 
5. 如果这个完成时间最多为$D$， 然后$M$是可行的。 
6. 二分查找结束$M$从 1 到$N$，使用可行性检查来指导搜索更小的有效值。 

它的工作原理基于单调负载分布特性。 增加$M$只能减少或维持每台机器的负载，因为以前在繁忙机器后面排队的作业现在可以获得更早的执行机会。 堆模拟总是将每个作业分配给最早可用的机器，这是唯一符合 FIFO 约束的局部最优选择。 由于每个任务仅取决于可用时间而不是未来的决策，因此模拟完全确定给定的时间表$M$，可行性定义明确且单调。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def can(M, t, D):
    # initialize M machines, all free at time 0
    heap = [0] * M
    heapq.heapify(heap)

    for x in t:
        cur = heapq.heappop(heap)
        cur += x
        heapq.heappush(heap, cur)
        if cur > D:
            # optional early exit
            pass

    return max(heap) <= D

def solve():
    N, D = map(int, input().split())
    t = list(map(int, input().split()))

    lo, hi = 1, N

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, t, D):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```核心模拟使用最小堆，其中每个值跟踪机器何时可用。 贪婪分配是由模型强制执行的：下一个员工总是占用最早空闲的机器。 

二分查找缩小最小可行范围$M$。 检查函数计算实际完成时间； 我们将其与$D$。 

一个微妙的实现细节是我们在最后跟踪最大堆值，而不是尝试仔细维护运行完成时间。 这避免了关于中间状态的部分推理中的错误。 另一个细节是，我们不能在不仔细维护正确性的情况下依赖循环内部的提前停止，因此干净版本只是简单地完成了模拟。

 ## 边缘情况

 对于$N = 1$，堆只有一台机器，算法立即返回 1，因为唯一的完成时间是$t_1$，符合要求。 

当所有$t_i$由于堆相等且小，因此堆将任务均匀地分布在机器上。 例如，与$N = 4$,$t = [2,2,2,2]$，和大$D$，模拟表明，一台机器就足够了，如果$D \ge 8$，但二分查找正确找到最小的有效值$M$无需高估。 

当一项任务比其他任务大得多时，例如$t = [100,1,1,1]$，堆确保长任务尽早占用一台机器，而短任务则填充其他机器。 与小$M$，长任务成为瓶颈，除非存在足够的机器，否则可行性失败。
