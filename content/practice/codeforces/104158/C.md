 ## 解决方案
 ## 问题理解

 我们在 2D 平面上有一个圆形目标和一组表示员工扔物体的位置的点。 任务是计算有多少个点落在圆的内部或正好落在圆的边界上。 

每次投掷只是平面上的一个坐标。 目标由其中心定义$(c_x, c_y)$和半径$r$。 如果到圆心的距离小于或等于，则投掷成功$r$。 

我们需要的主要量是每个点到中心之间的欧氏距离。 然而，计算平方根高达$10^5$点是不必要的，并且可能会引入浮点精度问题。 可以使用平方距离来做出决定。 

约束足够严格，以至于$O(n)$预计有解决方案。 自从$n \leq 10^5$，任何在恒定时间内处理每个点的方法就足够了。 任何涉及排序或成对比较的事情都是多余的。 

当点正好位于圆的边界上时，就会出现微妙的边缘情况。 例如，如果中心是$(0, 0)$，半径为$5$，并且一个点是$(3, 4)$，距离正好是$5$，所以必须算成功。 如果使用严格的不平等而不是包容性比较，这很容易处理不当。 

另一个潜在的陷阱是具有固定宽度整数的语言中的整数溢出，因为坐标可以大到$10^9$。 差值平方可达$10^{18}$，因此需要 64 位整数。 在 Python 中这是安全的，但推理对于翻译仍然很重要。 

## 方法

 最直接的方法是计算每个点的欧几里德距离，取平方根，并检查它是否小于或等于$r$。 这是正确的，因为它直接实现了圆的几何定义。 然而，它为每个员工执行昂贵的平方根运算，导致$O(n)$平方根调用。 虽然仍然是线性的，但这比必要的要慢，并且在比较边界附近的浮点值时存在精度问题。 

关键的观察结果是平方根是单调的。 比较距离相当于比较距离的平方。 而不是检查$$\sqrt{(x - c_x)^2 + (y - c_y)^2} \le r$$我们可以安全地对两边进行平方：$$(x - c_x)^2 + (y - c_y)^2 \le r^2$$这完全消除了浮点运算，并将每个点的运算减少到几个整数减法和乘法。 问题变成了具有恒定时间检查的简单线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（使用 sqrt）| O(n) | O(1) | O(1) | 已被接受，但速度较慢且风险较大 |
 | 平方距离检查 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取投掷次数和圈参数$c_x, c_y, r$。 这定义了所有计算的固定参考点和阈值。 
2. 预计算$r^2$。 这避免了对每个点重新计算，并确保所有比较都保持在整数算术中。 
3. 将计数器初始化为零。 这将跟踪有多少投掷落在圆内或圆的边界上。 
4. 对于每个员工的投入$(x_i, y_i)$，计算距中心的水平和垂直偏移：$dx = x_i - c_x$,$dy = y_i - c_y$。 这将问题转化为测量移动坐标系中距原点的距离。 
5. 计算平方距离$d = dx^2 + dy^2$。 这表示距中心的精确平方欧几里得距离。 
6. 比较$d$和$r^2$。 如果$d \le r^2$，递增计数器。 包含相等的情况是因为边界上的点被认为是成功的。 
7. 处理完所有点后，输出计数器。 

### 为什么它有效

 该算法依赖于这样一个事实：平方对于非负值是严格单调的。 由于平方距离和$r^2$是非负数，比较平方值会保留实际距离的顺序。 每个点都根据等效条件进行分类，因此不会发生错误分类的几何情况。 从欧几里德距离到平方距离的转换保留了正确性，同时完全消除了浮点计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, cx, cy, r = map(int, input().split())
    r2 = r * r
    ans = 0

    for _ in range(n):
        x, y = map(int, input().split())
        dx = x - cx
        dy = y - cy
        if dx * dx + dy * dy <= r2:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先以恒定的时间读取每行的所有输入。 半径平方计算一次，这避免了循环内的重复乘法。 每个点都是独立处理的，在评估平方距离条件之前计算其相对于中心的偏移量。 

比较使用`<=`而不是`<`，这很重要，因为边界点是有效命中。 所有算术都是使用 Python 整数执行的，它自然可以处理大值而不会溢出。

 ## 边缘情况

 一种边缘情况是当一个点恰好位于距离处时$r$。 例如，中心$(0,0)$， 半径$5$， 观点$(3,4)$。 该算法计算$dx^2 + dy^2 = 25$，等于$r^2$，所以计算正确。 这证实了包含边界条件。 

另一种边缘情况是坐标非常大时，例如$(10^9, -10^9)$。 距离的平方变为约$2 \cdot 10^{18}$，它仍然可以安全地适合 Python 整数。 该算法仍然正确，因为它从不依赖于浮点精度。 

最后一种情况是所有点都与中心重合。 每一个$dx$和$dy$变为零，因此所有点都被计算在内，匹配包含其中心的圆的几何定义。
