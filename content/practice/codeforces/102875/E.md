 ## 解决方案
 ## 问题理解

 我们有一个最多 16 个节点的无向网络。 每个节点都开始被感染。 在每一秒开始时，防病毒软件可能会清理一些当前受感染的节点，但最多可以清理`k`一次操作中的节点。 清理后，剩余的受感染节点将病毒传播给所有邻居，然后自行消失。 目标是输出一系列清理操作，最终使整个网络没有病毒，或者确定不存在这样的序列。 

表示这种情况的一种便捷方法是使用位掩码。 少量`i`当节点被设置`i`目前已被感染。 选择清除部分受感染节点后，只有未清除的节点才能传播。 下一个状态正是这些剩余节点的邻居的并集。 

的小值`n`是关键限制。 由于只有`2^n`可能的感染状态和`n <= 16`，最多有 65536 个状态。 状态数为多项式的解决方案是可能的。 另一方面，不使用状态压缩直接模拟图将无法有效地捕获重复配置。 

主要的边缘情况来自于混淆“现在清洁”和“永远清洁”。 如果相邻的受感染节点扩散到一轮中清理过的节点，则该节点可能会再次受到感染。 例如：```
2 1 1
1 2
```答案不是通过一项操作清理两个节点，因为`k=1`。 清理节点 1 首先使节点 2 受到感染，然后传播回节点 1。有效答案是：```
2
1
1
```另一个重要的情况是何时可以清理所有当前受感染的节点。 如果`k=n`，初始状态可以通过清理每个节点一次来立即解决。 总是在清洁后强制传播的模拟会错误地拒绝这种情况。 

## 方法

 蛮力的想法是尝试每一种可能的策略。 对于当前受感染的集合，我们可以枚举要清理的受感染节点的每个子集，模拟一次传播，然后递归地继续。 这是正确的，因为考虑了所有可能的有效策略。 问题在于选择的数量。 在所有状态中，枚举所有可能的清理子集可以粗略得出`3^n`转换，因为每个节点都可以属于以下三个类别之一：未受感染、受感染并已清理、或已受感染但未清理。 为了`n=16`，在考虑重复工作和存储搜索树之前，这已经是大约 4300 万种可能性。 

有用的观察是，当前的感染模式完全描述了未来。 我们不需要记住之前的操作。 这将问题转化为状态图上的最短路径搜索。 每个掩模都是一个顶点，有向边代表一次可能的清洁操作，然后是一次病毒传播。 

广度优先搜索就足够了，因为每个操作都有相同的成本。 剩下的优化是仔细生成转换。 不要直接选择已清理的节点，而是选择幸存下来并传播的受感染节点。 如果当前掩码是`S`幸存的受感染节点是`T`， 然后`T`必须是一个子集`S`，清理后的节点数为`popcount(S)-popcount(T)`。 我们只考虑该值最多的子集`k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3^n) | O(3^n) | O(2^n) | O(2^n) | 一般情况下太慢 |
 | 最佳| O(3^n) 最坏情况，常数较小 | O(2^n) | O(2^n) | 已接受 |

 最坏情况的转换计数仍然基于子集枚举，但状态图只有 65536 个顶点，并且实现使用整数位运算。 和`n=16`，这很舒服。 

## 算法演练

 1. 将每个感染状态编码为整数掩码。 初始状态是`(1 << n) - 1`，目标状态是`0`。 
2. 为每个掩码预先计算一种病毒传播的结果。 如果掩码代表在清理后幸存下来的受感染节点，则其下一个状态是所有设置位的邻接掩码的或。 
3. 从初始掩码开始运行 BFS。 存储先前的状态以及用于达到每个发现状态的清理操作。 
4. 处理状态时`S`，枚举每个子集`T`的`S`。 对待`T`作为清洁后仍受感染的节点。 如果`S`比`T`，清洁操作将超过`k`，所以跳过它。 
5. 清理后的节点为`S ^ T`。 下一个状态是预先计算的扩展结果`T`。 如果这个状态还没有被访问过，记录它的父状态和使用的操作。 
6. 当状态`0`到达后，通过向后跟踪父指针来重建答案。 

为什么它有效：BFS 在越来越多的操作中探索每个可到达的感染状态。 对于每个状态，都会考虑每个合法的清理选择，因此每个可能的策略都对应于该搜索图中的某个路径。 到达面罩`0`意味着病毒已经消失，而无法到达病毒则意味着不存在有效的策略。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    adj = [0] * n
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    total = 1 << n

    spread = [0] * total
    for mask in range(total):
        x = mask
        res = 0
        while x:
            b = x & -x
            i = b.bit_length() - 1
            res |= adj[i]
            x -= b
        spread[mask] = res

    parent = [-1] * total
    move = [0] * total

    start = total - 1
    parent[start] = start

    q = deque([start])

    while q:
        cur = q.popleft()
        if cur == 0:
            break

        bits = cur
        while True:
            remain = bits
            cleaned = cur ^ remain
            if cleaned.bit_count() <= k:
                nxt = spread[remain]
                if parent[nxt] == -1:
                    parent[nxt] = cur
                    move[nxt] = cleaned
                    q.append(nxt)

            if bits == 0:
                break
            bits = (bits - 1) & cur

    if parent[0] == -1:
        print(-1)
        return

    ans = []
    cur = 0
    while cur != start:
        mask = move[cur]
        s = ""
        for i in range(n):
            if mask >> i & 1:
                s += chr(ord('a') + i)
        ans.append(s)
        cur = parent[cur]

    ans.reverse()
    print(len(ans))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```邻接掩码使得传播速度非常快，因为每个节点的邻居都存储为单个整数。 这`spread`array 避免了 BFS 期间重新计算相同的图操作。 

子集循环使用标准子掩码迭代：```
bits = (bits - 1) & cur
```它访问每个子集`cur`正好一次。 变量`remain`表示在清理中幸存下来的受感染节点，因此清理后的集合是`cur ^ remain`。 这可以避免意外地允许防病毒软件清理已经清理过的节点。 

BFS 数组使用`-1`作为未访问的标记。 父指针以相反的顺序重建序列，因为 BFS 从进程的一开始就自然地发现目标。

 ## 边缘情况

 对于具有一个清洁槽的二节点图：```
2 1 1
1 2
```BFS 从 mask 开始`11`。 它尝试清理一个节点，达到掩码`01`或者`10`，然后发现清理剩余节点达到`00`。 该算法并不假设已清理的节点保持干净，因为每个转换始终应用扩展步骤。 

对于一个图表，其中`k=n`，初始状态正好包含所有可以被清理的节点。 BFS 找到具有幸存集的转换`0`，其扩散结果也是`0`。 这可以防止在完全清理后强制进行不必要的回合的常见错误。 

对于有环的图，例如：```
5 5 2
1 2
2 3
3 4
4 5
5 1
```贪婪的方法可能会重复清理再次被感染的节点。 BFS 避免了这种情况，因为它对完整状态进行推理，并且只关心状态是否已经被探索过。
