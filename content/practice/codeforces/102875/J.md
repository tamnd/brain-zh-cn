 ## 解决方案
 ## 问题理解

 该问题中的函数是计算模逆的递归方法，但请求的值不是逆本身。 该问题询问当函数以每个可能的起始值启动时函数调用的平均次数`1`到`p - 1`， 在哪里`p`是一个素数。 

当参数变为时，递归函数立即停止`1`。 否则，它会从当前值移动`x`到`p mod x`并再打一个电话。 用于构建逆函数的乘法和模运算在这里无关紧要，因为只有调用次数很重要。 例如，当`p = 7`，链为`x = 5`是`5 -> 2 -> 1`，所以它贡献了`3`调用平均值。 

输入最多包含 100 个素数值，每个素数最多为`10^6`。 这个界限是主要的算法线索。 试图独立地遵循每个递归链的解决方案可以多次重复相同的子问题，并且每个链的直接模拟将接近二次行为。 对于大约的值`10^6`，二次方法需要大约`10^12`的操作，远远超出了正常的时间限制。 我们需要利用这样一个事实：每个状态仅依赖于较小的余数。 

微妙的情况大多是在边界周围。 什么时候`p = 2`，只有一个可能的起始值，`x = 1`。 答案是`1`，以及假设循环始终包含来自的值的实现`2`到`p - 1`可能会意外除以零，因为起始值的数量是`p - 1`。 

对于输入：```
1
2
```正确的输出是：```
1.0000000000
```没有递归转换，因为唯一的调用是`F(1, 2)`。 

另一个容易犯的错误是将返回的模值视为答案。 例如，与`p = 7`和`x = 5`，函数返回模逆值，但贡献的是调用次数：```
F(5, 7) -> F(2, 7) -> F(1, 7)
```贡献是`3`，不是倒数`5`模数`7`。 

## 方法

 一种简单的方法是模拟每个可能的起始值的递归函数。 对于每个`x`从`1`到`p - 1`,我们反复替换`x`和`p mod x`直到达到`1`，计算呼叫次数。 这给出了正确的结果，因为递归准确地描述了我们需要测量的过程。 

问题是许多不同的起始值访问相同的中间值。 如果我们单独计算每个链，则可以一次又一次地评估相同的余数。 在最坏的情况下，对所有起始值独立执行此操作可能会变成二次值。 和`p`附近`10^6`，这意味着大约一万亿次跃迁。 

关键的观察结果是依赖图已经排序。 对于任何`x > 1`，下一个值是`p mod x`，并且这个值总是小于`x`。 这意味着如果我们按升序计算答案`x`，每个转变的答案都是已知的。 

让`dp[x]`是函数从以下位置开始的调用次数`x`。 基本情况是`dp[1] = 1`。 对于每个其他值：$$dp[x] = 1 + dp[p \bmod x]$$额外的`1`代表当前调用，其余调用正是来自递归子级的调用。 

最终答案是所有答案的平均值`dp[x]`值来自`1`到`p - 1`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(p²) | O(1) | O(1) | 太慢了 |
 | 最佳| O(p) | O(p) | 已接受 |

 ## 算法演练

 1. 创建数组`dp`在哪里`dp[x]`存储函数启动时所需的调用次数`x`。 放`dp[1] = 1`因为该函数立即返回此状态。 这直接给了我们唯一的停止条件。 
2. 迭代`x`从`2`到`p - 1`。 对于每个值，计算下一个递归状态`p mod x`。 由于该值小于`x`，它的答案已经计算出来了。 
3. 设置`dp[x] = 1 + dp[p mod x]`。 当前调用贡献了一个，链的其余部分已经存储在动态编程表中。 
4. 添加每个`dp[x]`值并将总计除以`p - 1`。 每个起始值从`1`到`p - 1`具有相同的概率，因此所需的期望是算术平均值。 

为什么它有效：重要的不变量是在处理每个值之后`x`,`dp[i]`对于每个都是正确的`i <= x`。 递归过渡自`x`总是移动到一个较小的数字，因此所需的子问题已经被不变量所覆盖。 由于每个可能的起始值在最终总和中只包含一次，因此计算出的平均值与预期的调用次数相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(p):
    if p == 2:
        return 1.0

    dp = [0] * p
    dp[1] = 1

    total = 1
    for x in range(2, p):
        dp[x] = 1 + dp[p % x]
        total += dp[x]

    return total / (p - 1)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        p = int(input())
        ans.append(f"{solve_case(p):.10f}")
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```特殊情况`p = 2`避免创建无效的平均计算。 只有一个可能的起始值，所以答案是直接`1`。 

对于较大的素数，`dp`有尺寸`p`因为每个可能的起始值都小于`p`。 循环顺序递增是核心实现细节。 计算时`dp[x]`, 索引`p % x`保证小于`x`，因此不需要递归或额外的排序。 

变量`total`在求和时保持为整数。 到浮点的转换仅在最后的除法期间发生，这避免了累加期间不必要的精度损失。 

## 工作示例

 对于`p = 7`，计算值是：

 | x| p 模 x | dp[x] | dp[x] | 运行总和 |
 | --- | --- | --- | --- |
 | 1 | - | 1 | 1 |
 | 2 | 1 | 2 | 3 |
 | 3 | 1 | 2 | 5 |
 | 4 | 3 | 3 | 8 |
 | 5 | 2 | 3 | 11 | 11
 | 6 | 1 | 2 | 13 |

 平均值是：$$13 / 6 = 2.1666666667$$此示例展示了如何重用重复的子问题。 链条用于`4`和`5`不需要独立重新计算路径`3`和`2`。 

为了`p = 5`:

 | x| p 模 x | dp[x] | dp[x] | 运行总和 |
 | --- | --- | --- | --- |
 | 1 | - | 1 | 1 |
 | 2 | 1 | 2 | 3 |
 | 3 | 2 | 3 | 6 |
 | 4 | 1 | 2 | 8 |

 最终结果是：$$8 / 4 = 2.0$$这种情况表明，一个状态可以依赖于另一个非紧邻的先前值。`dp[3]`取决于`dp[2]`，它已经可用，因为迭代遵循递增顺序。

 ## 边缘情况

 对于`p = 2`，算法立即返回`1.0`。 循环从`2`到`p - 1`是空的，但这是正确的，因为唯一的起点是`x = 1`。 

对于输入：```
1
2
```执行是：

 | 步骤| 状态|
 | --- | --- |
 | 开始| 唯一的价值是`x = 1`|
 | 函数调用 | 一通电话 |
 | 平均 |`1 / 1 = 1`|

 对于起始值达到另一个计算状态的情况，DP 排序会自然地处理它。 和`p = 7`，计算时`dp[5]`，转变为：```
5 -> 2
```价值`dp[2]`已知：```
dp[2] = 1 + dp[1] = 2
```所以：```
dp[5] = 1 + dp[2] = 3
```该算法永远不会重新计算链`2 -> 1`，这是线性解决方案起作用的主要原因。
