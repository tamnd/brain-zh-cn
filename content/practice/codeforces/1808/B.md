 ## 解决方案
 ## 问题理解

 每个玩家都会收到一张卡片，其中包含`m`整数。 对于每对玩家来说，他们在游戏中赢得的金额是他们牌上相应位置之间的绝对差之和。 

如果玩家`i`有卡值`c[i][1...m]`和玩家`j`有卡值`c[j][1...m]`，他们的贡献是：$$\sum_{k=1}^{m} |c[i][k] - c[j][k]|$$我们需要所有无序玩家对的总贡献。 

直接解释建议比较每对牌以及牌内的每个位置。 和`n`球员和`m`每张卡的值，这需要检查所有`n(n-1)/2`对和全部`m`每对的列。 

重要的约束是所有测试用例的矩阵条目总数：$$\sum (n \cdot m) \le 3 \cdot 10^5$$这对于周围的算法来说足够小`O(nm log n)`，但对于`O(n^2 m)`什么时候`n`很大。 例如，如果`n = 3 \cdot 10^5`和`m = 1`，然后一个`O(n^2)`方法大致需要$9 \times 10^{10}$运营。 

隐藏结构是绝对差之和可按列分开。 每列都独立地贡献最终答案。 

一些边缘情况很容易导致错误。 

考虑：```
2 1
5
5
```只有一对，它的贡献是`|5-5| = 0`。 任何假设排序后值严格增加的公式都会错误地添加正值。 

考虑：```
3 1
1
10
100
```答案是：```
|1-10| + |1-100| + |10-100|
= 9 + 99 + 90
= 198
```一个粗心的实现，在排序后只查看相邻的差异将会得到`9 + 90 = 99`，这只是所需金额的一半。 

考虑：```
1 4
7 8 9 10
```根本没有成对的玩家。 答案一定是`0`。 任何盲目应用配对公式而不考虑的解决方案`n = 1`可能会产生垃圾值。 

## 方法

 蛮力的想法很简单。 对于每对玩家，逐个坐标比较他们的牌，计算绝对差之和，并将其添加到答案中。 

这是有效的，因为它直接匹配奖金的定义。 问题是运行时间：$$O(n^2 m)$$如果`n = 3 \cdot 10^5`和`m = 1`，这变得完全不可行。 

关键的观察结果是每列的贡献是独立的。 

假设我们关注单个列并收集该列中的所有值：$$x_1, x_2, \dots, x_n$$本专栏的总贡献为：$$\sum_{i<j} |x_i - x_j|$$这是一个经典的表达方式。 排序后：$$x_1 \le x_2 \le \cdots \le x_n$$绝对值消失：$$|x_j-x_i| = x_j-x_i \quad (j>i)$$现在考虑每个排序值出现正值和负值的频率。 

对于职位`i`:$$x_i$$恰好显示为较大的元素`i`次并作为较小的元素`n-1-i`次（使用基于 0 的索引）。 

其净系数变为：$$i - (n-1-i)$$计算相同总和的另一种方法是使用前缀总和。 扫描排序数组时，对于每个值`x[i]`，所有先前的值都是已知的。 

它相对于之前元素的贡献是：$$i \cdot x[i] - \text{prefix}$$在哪里`prefix`是所有早期值的总和。 

这让我们可以在排序后的线性时间内计算整个列的贡献。 

由于每一列都是独立处理的，因此复杂性变为：$$O(m \cdot n \log n)$$这很容易满足约束条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²m) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(m·n log n) | O(m·n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取代表所有卡片的矩阵。 
2. 对于每一列，收集其`n`值放入数组中。 
3. 对列值进行排序。 

排序后，每对贡献变成简单的减法，而不是绝对值。 
4. 初始化`prefix = 0`。 
5. 从左到右扫描已排序的列。 

对于当前值`x[i]`，所有先前的值都小于或等于。 
6. 添加$$i \cdot x[i] - prefix$$到答案。 

这等于以下各项的总和：$$x[i]-x[0],\ x[i]-x[1],\ \dots,\ x[i]-x[i-1]$$这正是的贡献`x[i]`与所有早期元素。 
7. 更新$$prefix += x[i]$$所以未来的元素可以使用它。 
8. 对每一列重复此操作。 
9. 输出累计答案。 

### 为什么它有效

 对一列进行排序后，每对`(i,j)`和`i < j`贡献`x[j] - x[i]`。 加工时`x[j]`, 数量$$j \cdot x[j] - \text{prefix}$$准确地添加$$(x[j]-x[0]) + (x[j]-x[1]) + \cdots + (x[j]-x[j-1])$$这是所有以位置结束的对的总贡献`j`。 

每个无序对都只出现一次，即在处理其较大的排序端点时。 没有一对被省略，没有一对被计算两次。 将所有头寸和所有列的该值相加即可得出所需的总奖金。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, m = map(int, input().split())

    a = [list(map(int, input().split())) for _ in range(n)]

    ans = 0

    for col in range(m):
        vals = [a[row][col] for row in range(n)]
        vals.sort()

        prefix = 0

        for i, x in enumerate(vals):
            ans += i * x - prefix
            prefix += x

    print(ans)
```矩阵仅被读取一次。 对于每一列，我们提取其值，对它们进行排序，并使用运行前缀和计算成对差异的总和。 

表达式：```
ans += i * x - prefix
```是临界线。 在索引处`i`，正好有`i`之前的元素。 他们的总贡献`x`是：```
(x - v1) + (x - v2) + ... + (x - vi)
```简化为：```
i * x - (v1 + v2 + ... + vi)
```该总和存储在`prefix`。 

Python 整数自动处理大值，因此不存在溢出风险。 在 C++ 等语言中，需要 64 位整数。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m·n log n) | O(m·n log n) | 每列大小`n`排序一次 |
 | 空间| O(n) | 存储一列的临时数组 |

 所有测试用例的矩阵条目总数最多为`3·10^5`。 对每列进行排序可以使总复杂度在限制范围内，并且额外的内存只是单个列数组。

import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

        a = [list(map(int, input().split())) for _ in range(n)]
