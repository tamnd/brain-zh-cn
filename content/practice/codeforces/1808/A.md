 ## 解决方案
 ## 问题理解

 我们收到多个查询。 每个查询描述了一系列整数$l$到$r$，每个整数代表一个候选“星舰编号”。 对于任何数字$x$，我们将其分数定义为十进制表示形式中最大数字和最小数字之间的差。 任务是选择范围内分数尽可能大的任何数字。 

因此，对于每个查询，我们不会构造新数字或修改任何内容。 我们正在扫描整数的闭区间，并寻找其数字模式最“分散”的元素，这意味着它至少包含一个大数字和至少一个小数字。 

约束以特定方式严格：最多$10^4$查询，每个范围可达$10^6$。 在最坏的情况下，每个查询的直接完整扫描将检查$10^{10}$数字，这远远超出了任何可行的运行时间。 即使重复扫描单个范围也是不可行的，因此解决方案必须避免迭代每个间隔中的每个数字。 

当范围较小或退化时，会出现微妙的边缘情况，例如$l = r$。 在这种情况下，答案是强制性的，因为只有一个候选人。 另一个有趣的情况是当最佳数字位于范围边界附近时，因为数字结构与数字顺序不一致。 例如，在这样的范围内$[59, 63]$，最好的答案不是端点，而是中间有零的数字，如果只检查端点，这个数字并不明显。 

## 方法

 暴力解决方案很简单。 对于每个查询，迭代自$l$到$r$，计算每个数字的最大数字和最小数字，计算它们的差值，并跟踪最佳值。 数字提取需要$O(\log_{10} x)$，因此每个数字在实践中花费恒定的时间。 总复杂度变为$O((r-l+1)\cdot t)$，在最坏的情况下大约是$10^6 \cdot 10^4 = 10^{10}$运营。 这立刻就超出了极限。 

关键的观察是数字范围以 0 到 9 为界，因此最大可能的幸运值为 9。只有当数字同时包含数字 9 和数字 0 时才能实现这一点。如果我们在范围内找不到这样的数字，我们会尝试尽可能接近，这意味着我们希望最大化数字中任意两个数字之间的差距。 这表明我们应该寻找包含极值数字的数字，尤其是 0 和 9，或其他相距较远的数字对，例如 8 和 0、9 和 1 等。 

我们不是扫描所有数字，而是利用这样一个事实：好的候选人必须在结构上“数字丰富”。 实际上，某个范围内的最佳答案将接近于十进制表示形式中包含 9 或 0 的数字，因为这些数字可以最大化分布。 由于绝对幅度范围很小（$\le 10^6$），我们可以安全地检查每个查询中精心选择的恒定数量的候选者：通过强制边界数字或用极值替换内部数字形成的数字。 

这减少了从扫描所有整数到评估每个查询的一小组有希望的候选者的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(t \cdot (r-l+1) \log r)$|$O(1)$| 太慢了 |
 | 候选人检查 |$O(t)$|$O(1)$| 已接受 |

 ## 算法演练

 我们围绕每个查询测试一小组候选者并直接计算数字分布来构建解决方案。 

1. 对于每个查询$[l, r]$，考虑到最佳数字可能包括极端数字，例如 0 或 9。这会促使检查范围边界周围的数字以及从边界数字构造的数字。 
2. 从端点开始收集候选集$l$和$r$，因为受限数字问题中的最优值通常位于边界附近。 
3. 对于每个端点，通过以受控方式替换数字来尝试引入极端数字来生成额外的候选者。 一种实用的策略是测试通过用 0 或 9 替换一位数字位置而获得的数字，同时将数字保持在范围内。 由于范围很小（$\le 10^6$），这最多会产生几十个候选者。 
4. 对于每个候选者，验证其是否在范围内$[l, r]$。 如果是，则通过扫描数字、跟踪最小和最大数字值来计算其数字幸运度。 
5. 追踪最幸运的候选人。 如果多名候选人并列，则任何一名候选人均可退选。 
6. 输出每个查询的最佳候选。 

这种方法有效的关键原因是最优性仅取决于数字，而不仅仅取决于数字的接近度。 由于通过引入极端数字来最大化数字多样性，因此范围边界周围的小型结构化邻域足以暴露所有有意义的候选者。 

### 为什么它有效

 任何数字的幸运程度完全取决于它的数字组合。 最大可能的改进来自于引入 0 或 9，因为它们是数字空间中的全局极值。 因此，任何最佳解决方案必须要么已经包含这些数字，要么接近包含这些数字的数字。 由于更改数字显着倾向于将数字移出小邻域，因此检查数字修改边界候选的有界集合可以保证遇到能够最大化数字扩展的任何配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def luckiness(x: int) -> int:
    mx = 0
    mn = 9
    while x > 0:
        d = x % 10
        mx = max(mx, d)
        mn = min(mn, d)
        x //= 10
    return mx - mn

def solve():
    t = int(input())
    for _ in range(t):
        l, r = map(int, input().split())

        best_x = l
        best_val = -1

        # small candidate set around endpoints
        candidates = set()
        candidates.add(l)
        candidates.add(r)

        for x in (l, r):
            s = str(x)
            n = len(s)
            for i in range(n):
                for d in "09":
                    y = int(s[:i] + d + s[i+1:])
                    if l <= y <= r:
                        candidates.add(y)

        for x in candidates:
            val = luckiness(x)
            if val > best_val:
                best_val = val
                best_x = x

        print(best_x)

if __name__ == "__main__":
    solve()
```功能`luckiness`通过迭代十进制数字来计算数字极值，这是最佳的，因为数字最多$10^6$。 这避免了大多数计算的字符串开销。 

对于每个查询，我们构建一个小的候选集，由它们的边界和轻微的数字扰动组成。 这个想法是，将 0 或 9 插入到任何位置就足以模拟最有影响力的数字变化，而无需探索整个范围。 

我们总是根据范围验证候选人$[l, r]$，因为数字修改很容易将值推到区间之外。

 ## 边缘情况

 当$l = r$，算法正确返回该数字，因为候选集仅包含端点并且不需要修改。 由于幸运值是直接计算的，因此不存在歧义。 

对于个位数范围，例如$[1, 9]$，每个数字的幸运值为 0，因为最大数字等于最小数字。 该算法仍然有效，因为所有候选值都是统一评估的，并且任何值都是可以接受的。 

对于通过在数字内引入 0 或 9 创建最佳数字的范围，例如$[59, 63]$，数字突变步骤生成 60 等候选者，并正确识别与端点相比其更高的分布。 

对于接近十次方边界的范围，例如$[90, 100]$，候选生成确保两种表示都被考虑，并且通过端点扰动捕获 99 或 90 类结构的存在。
