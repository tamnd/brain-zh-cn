 ## 解决方案
 ## 问题理解

 我们得到一个数组，它表示不同项目的打乱顺序，并且我们最多可以执行一个操作：选择两个位置并交换它们的值。 任务是确定是否可以使用此单个交换将数组转换为排序顺序，如果可以，则根据问题所需的输出精确地描述这种可能性。 

从算法的角度来看，输入是一个长度的序列$n$目标配置是按非降序排序的相同序列。 唯一允许的修改是任意两个索引之间的一次全局交换。 输出通常是此约束下的决策或可行性的最小表征。 

约束机制（最大尺寸的数组，通常$10^5$或更多这种形式的 Codeforces 问题）立即排除任何尝试所有可能交换的方法。 尝试每一对都需要$O(n^2)$的操作，远远超出了可行的限度。 任何有效的解决方案都必须在线性或近线性时间内推理数组及其排序版本之间的不匹配结构。 

当数组已经排序时，会出现一种微妙的情况。 在这种情况下，不需要交换，并且任何盲目尝试“修复不匹配”的逻辑都可能错误地得出仍然需要交换的结论。 另一个重要的情况是，当恰好有两个元素不合适时，但交换它们实际上并不能修复顺序，因为它们的位置与其他位置相互作用。 例如，考虑一个接近排序的数组，其中多个元素在超过两个的周期中被替换。 只考虑极端情况的幼稚方法可能会错误地认为一次交换就足够了。 

作为一个具体的例子，以数组为例$[1, 4, 3, 2, 5]$。 排序后的数组是$[1, 2, 3, 4, 5]$。 有多个不匹配的位置，虽然交换$4$和$2$改善了这种情况，它没有对数组进行完全排序，这表明并非每个不匹配模式都可以通过一次交换来解决。 

## 方法

 蛮力的想法很简单：尝试每对索引$(i, j)$，交换它们，并检查结果数组是否已排序。 对于每次交换，验证排序需要花费$O(n)$时间，并且有$O(n^2)$可能的交换，导致$O(n^3)$如果天真地完成或解决方案$O(n^2)$如果我们更巧妙地重复使用检查。 当以下情况时，这变得不可行$n$变大，因为即使$10^5$会导致周围$10^{10}$运营。 

关键的观察是一次交换只能影响两个头寸。 这意味着如果数组可以完全固定，那么几乎所有位置都必须已经匹配其排序目标。 唯一的偏差必须严格定位。 我们不模拟交换，而是将数组与其排序版本进行比较，并仅关注它们不同的索引。 

一旦我们隔离了不匹配的位置，有效解决方案的结构就会变得僵化。 如果存在零个不匹配，则数组已排序。 如果恰好有两个不匹配，则交换这两个值可能会修复数组，但前提是它们在排序配置中彼此对应。 如果存在两个以上的不匹配，则一次交换无法修复两个以上的位置，因此答案立即是否定的。 

这将整个问题简化为与排序的基线进行比较并分析不匹配集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（尝试所有交换）|$O(n^3)$或者$O(n^2)$|$O(1)$到$O(n)$| 太慢了|
 | 与排序数组比较 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 构造数组的排序副本。 这代表了我们想要达到的最终目标状态。 与该数组的比较可以准确地告诉我们哪些位置不正确。 
2. 迭代所有索引并收集原始数组与排序数组不同的索引。 这些指数代表了互换可以解决的唯一问题。 
3. 如果不匹配的位置数为零，则数组已排序，无需进行任何操作。 我们可以立即返回成功。 
4. 如果不匹配位置的数量正好是两个，则提取这两个索引并测试交换它们的值是否会使两个位置与排序数组对齐。 这确保了交换在结构上是有效的，而不仅仅是局部改进。 
5. 如果不匹配位置的数量不是零或两个，则得出结论，没有单个交换可以修复阵列，因为一个交换最多只能纠正两个位置。 

### 为什么它有效

 关键的不变量是交换操作恰好影响两个索引，并且它仅交换它们的值而不改变其他地方的元素的多重集。 任何已经与其排序位置匹配的索引必须保持正确，除非涉及交换，并且最多可以涉及两个索引。 因此，任何可解的配置必须与排序数组最多有两个位置不同，并且这两个位置必须是互补的，因为交换它们的值可以恢复两者的正确性。 这种结构限制充分描述了所有有效案例的特征。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    b = sorted(a)
    
    diff = []
    for i in range(n):
        if a[i] != b[i]:
            diff.append(i)
    
    if len(diff) == 0:
        print("YES")
        return
    
    if len(diff) == 2:
        i, j = diff
        if a[i] == b[j] and a[j] == b[i]:
            print("YES")
        else:
            print("NO")
        return
    
    print("NO")

if __name__ == "__main__":
    solve()
```该解决方案首先读取数组并构建其排序版本。 这是参考配置。 收集不匹配索引的循环精确隔离了数组中违反排序顺序的部分。 然后逻辑严格按照该不匹配集的大小进行分支。 

最微妙的部分是两个不匹配的情况。 仅仅有两个不匹配是不够的； 交换的值必须完全匹配彼此的排序位置。 此检查可确保交换不是部分正确，而是完全解决两个不正确的位置。 

## 工作示例

 考虑数组$[1, 3, 2, 4]$。 排序后的版本是$[1, 2, 3, 4]$。 

我们跟踪不匹配情况：

 | 我| 一个[我] | b[i] | 不匹配|
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 没有|
 | 1 | 3 | 2 | 是的 |
 | 2 | 2 | 3 | 是的 |
 | 3 | 4 | 4 | 没有|

 失配指数为$[1, 2]$。 交换这些给出$[1, 2, 3, 4]$，所以答案是肯定的。 

现在考虑$[1, 4, 3, 2, 5]$。 排序后的数组是$[1, 2, 3, 4, 5]$。 

| 我| 一个[我] | b[i] | 不匹配|
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 没有|
 | 1 | 4 | 2 | 是的 |
 | 2 | 3 | 3 | 没有|
 | 3 | 2 | 4 | 是的 |
 | 4 | 5 | 5 | 没有|

 失配指数为$[1, 3]$。 检查交换：$a[1]=4$应该等于$b[3]=4$和$a[3]=2$应该等于$b[1]=2$，因此交换有效并且数组已排序。 这证实了两个不匹配情况的正确性条件。

 ## 边缘情况

 对于已经排序的数组，例如$[1, 2, 3]$，不匹配列表为空，算法立即返回 YES，而不尝试任何交换逻辑。 这避免了即使不需要也强制交换的常见错误。 

对于像这样的情况$[2, 1, 3]$，位置上恰好有两个不匹配$0$和$1$。 排序后的数组是$[1, 2, 3]$，并且交换不匹配的元素可以正确对齐两个位置，算法通过交叉检查条件确认了这一点。 

对于循环位移，例如$[3, 1, 2]$，所有三个位置都不匹配已排序的数组。 尽管数组“接近”排序，但没有单个交换可以解决 3 周期问题，并且算法通过检测到两个以上不匹配正确地拒绝它
