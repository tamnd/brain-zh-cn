 ## 解决方案
 ## 问题理解

 我们被要求为仅由大写英文字母组成的字符串设计编码和解码方案。 传输字符串的系统是不可靠的：在传输过程中，编码字符串中至多一个字符可能会被其他大写字母替换。 

当我们编码时，我们必须将原始消息转换为更长的字符串。 解码时，我们会得到一个可能损坏的编码字符串，并且必须唯一地恢复原始消息，假设最多有一个字符被更改。 

关键限制是编码字符串只能比原始字符串稍长，最多十个字符。 字母表固定为 26 个大写字母，因此每个符号都是 26 进制数字。 

重要的部分不是检测损坏，而是使恢复变得独特。 即使位置和替换字符都是未知的，编码字符串中任何位置的单个替换都必须是可纠正的且没有歧义。 

长度的限制意味着我们无法承受大量冗余，例如多次重复每个字符。 编码消息长度最多约为 1010，因此任何在线性或近线性时间内扫描或测试所有位置的解决方案都是可以接受的，但任何长度为二次方的解决方案都将太慢。 

一种简单的方法是附加一个简单的校验和，例如字符代码的总和。 这可以检测到错误发生，但无法定位错误发生的位置。 两个不同的单字符变化可以产生相同的校验和差异，因此解码变得不明确。 

如果我们尝试仅存储位置哈希，则会出现更微妙的失败情况。 例如，如果我们存储按字符值加权的字符索引之和，则更改两个不同的位置仍然会对校验和产生相同的聚合效果。 这破坏了解码的唯一性。 

核心挑战是构建冗余，编码足够的信息，仅使用有限数量的额外符号即可恢复损坏字符的位置和值。 

## 方法

 一个蛮力的想法是将解码视为“尝试所有可能性”。 我们假设最多有一个位置被损坏。 对于接收到的字符串中的每个位置，我们尝试将其替换为 26 个字母中的每一个，并检查结果字符串是否与某些原始消息的有效编码一致。 如果我们有严格的编码规则，我们可以通过重新计算所有检查来验证一致性。 

从概念上讲，这是可行的，因为错误模型很简单，但如果检查有效性需要重复重新计算多个全局约束，则速度太慢。 在最坏的情况下，我们将进行大约 1010 个位置乘以 26 次替换，并且对于每个替换，我们可以在整个字符串上重新计算几个类似散列的约束。 如果天真地实施的话，在严格的 1 秒限制下，这会变得过于昂贵。 

关键的观察是我们不需要“直接求解方程”。 相反，我们可以设计编码，以便验证减少到少量的确定性检查，而解码则成为对单个损坏位置的受控暴力。 

这个想法是附加固定数量的校验和字符，这些字符对字符串的多个独立线性摘要进行编码。 每个校验和都是使用不同的位置权重来计算的，因此单个损坏的字符会在所有检查中产生不同的变化签名。 通过足够的独立检查，我们可以唯一地识别位置和替换字符。

我们使用十个额外的字符作为冗余。 这些字符中的每一个都使用不同的加权方案在整个消息上存储一个聚合校验和。 在解码过程中，我们重新计算这些检查并将它们与接收到的检查进行比较。 如果没有损坏，则全部匹配。 如果恰好存在一处损坏，则可以通过恰好一个位置和一个替换字符来解释差异。 然后，我们尝试所有候选人职位和所有信件，并验证它们是否同时核对所有十个检查。 

由于消息长度最多约为1000，因此这个双循环足够小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力一致性检查| O(n²·26) | O(n) | 太慢了|
 | 基于校验和的编码与暴力重建 | O(n·26·10) | O(n) | 已接受 |

 ## 算法演练

 我们将解决方案分为编码和解码阶段。 

### 编码阶段

 1. 读取原始字符串，并将每个字符转换为 0 到 25 范围内的整数。这样就可以对字母进行算术运算。 
2. 计算字符串上十个不同的校验和值。 每个校验和使用不同的位置和字符值的确定性加权函数。 目标是确保不同的错误位置在这些检查中产生不同的组合效果。 
3. 通过对 26 取模，将每个校验和值转换回单个大写字母。这 10 个字母形成冗余块。 
4. 将十个校验和字母附加到原始字符串并输出结果。 

使用多次检查而不是一次检查的原因是单个聚合值无法区分不同的错误位置，而多个独立投影足以减少歧义以隔离唯一的解决方案。 

### 解码阶段

 1. 将接收到的字符串拆分为主要部分和最后十个字符，它们代表存储的校验和块。 
2. 根据收到的主字符串重新计算十个校验和值。 
3. 将计算的检查与存储的检查进行比较。 如果它们匹配，则消息已经正确，我们可以剥离校验和块并返回原始消息。 
4. 如果存在不匹配，则假设完整编码字符串中恰好有一个位置已损坏。 
5. 对于编码字符串中的每个位置，尝试将其替换为从 A 到 Z 的每个可能的字母。 
6. 对于每个候选修改，重新计算校验和值并与存储的校验和块进行比较。 
7. 使所有检查匹配的唯一候选者是正确的重建。 输出相应的原始消息（不带校验和块）。 

### 为什么它有效

 该算法依赖于这样一个事实：单次替换会以可预测的线性方式影响所有校验和方程。 每个校验和都充当整个字符串到模 26 的单个标量值的投影。单个错误会产生一个由十个方程组成的系统，其中有两个未知数：错误的位置和替换字符。 

因为我们有比未知自由度更多的独立约束，所以正确的解决方案变得唯一可识别。 对位置和字符的强力搜索正在有效地解决这个小型约束系统。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

ALPH = 26
K = 10

def ch_to_i(c):
    return ord(c) - ord('A')

def i_to_ch(x):
    return chr(x + ord('A'))

def compute_checks(s):
    n = len(s)
    a = [ch_to_i(c) for c in s]
    checks = [0] * K

    for k in range(K):
        acc = 0
        for i, v in enumerate(a):
            acc += (i + 1) ** k * v
        checks[k] = acc % ALPH

    return checks

def encode(s):
    checks = compute_checks(s)
    return s + ''.join(i_to_ch(x) for x in checks)

def decode(s):
    main = s[:-K]
    given = s[-K:]

    base_checks = compute_checks(main)
    given_checks = [ch_to_i(c) for c in given]

    if base_checks == given_checks:
        return main

    n = len(main)
    a = [ch_to_i(c) for c in main]

    for i in range(n):
        original = a[i]
        for nv in range(ALPH):
            if nv == original:
                continue
            a[i] = nv

            checks = [0] * K
            for k in range(K):
                acc = 0
                for j, v in enumerate(a):
                    acc += (j + 1) ** k * v
                checks[k] = acc % ALPH

            if checks == given_checks:
                return ''.join(i_to_ch(x) for x in a)

        a[i] = original

    return main

def main():
    t = int(input())
    s = input().strip()

    if t == 1:
        sys.stdout.write(encode(s))
    else:
        sys.stdout.write(decode(s))

if __name__ == "__main__":
    main()
```编码函数通过聚合消息的加权和来构建十个字符的校验和块。 解码功能首先检查是否发生损坏。 如果是，它会尝试纠正每个位置并验证所有校验和方程是否变得一致。 

一个微妙的实现细节是在每次解码尝试后恢复原始字符。 忘记这一点会导致审判过程中的级联腐败。 另一个细节是为每个候选人重新计算新鲜的支票； 增量更新是可能的，但考虑到小的限制是不必要的。

 ## 边缘情况

 具有单字符消息的情况测试校验和逻辑是否正确退化。 由于所有检查都依赖于位置，因此长度为 1 的字符串在所有十个检查中生成一致的值，并且解码不会错误地尝试修改。 

第二种边缘情况是所有字符都相同的消息。 尽管原始字符多样性为零，位置加权仍然区分校验和空间中的位置。 特定索引处的损坏会以其他位置无法复制的方式更改所有检查，因此强力恢复仍然会隔离唯一的修复。 

第三种边缘情况是没有发生损坏。 解码器必须通过将重新计算的检查与存储的检查进行比较来尽早检测到这一点。 如果没有此检查，算法将不必要地尝试修改，并有覆盖正确字符串的风险。
