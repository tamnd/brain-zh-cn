 ## 解决方案
 ## 问题理解

 我们被要求构造任何整数数组，使其前缀和和后缀和同时满足四个极值条件。 

对于选定的数组，请考虑从零开始并从左到右累加元素的运行前缀和序列。 该序列具有最高值和最低值。 我们被告知这两个值必须是什么：前缀和必须达到最大值`a`和至少`b`。 

同时，如果我们从右侧看，将后缀和定义为从每个位置到末尾的元素之和，那么后缀和序列也有一个最大值和一个最小值。 这些必须是`c`和`d`。 

因此，任务不是计算这些值，而是构建任何恰好产生这四个极值约束的数组，或者报告不可能性。 

约束的大小很大，但输出数组大小足够小（最多 1000）。 这强烈暗示了一种建设性的解决方案，我们明确地构建前缀和的路径，而不是尝试任何组合或搜索。 任何试图暴力破解数组的解决方案都是立即不可行的，因为即使检查一个候选者也需要线性前缀和后缀计算，并且数组的空间原则上是无限的。 

一个微妙但重要的困难是前缀和后缀条件不是独立的。 一种幼稚的方法可能会尝试单独构造前缀和路径匹配`(a, b)`和另一个匹配的`(c, d)`然后将它们连接起来，但后缀总和取决于全局总数，因此任意连接会破坏一致性。 

当所需的极值不兼容时，就会出现边缘情况。 例如，如果前缀和应该保持在不包含零的范围内，则构造变得不可能，因为前缀和总是从零开始。 因此任何有效的解决方案都必须至少尊重这一点`0`位于之间`b`和`a`。 

## 方法

 一个蛮力的想法是尝试逐步构建数组并同时维护前缀和后缀约束。 在每个位置，我们将选择一个值并重新计算前缀和后缀极值。 这很快就会变成指数，因为每个位置都会分支许多整数选择，并且约束取决于未来不可局部确定的后缀行为。 即使按界限修剪仍然会留下指数状态空间。 

关键的简化来自于仅根据前缀和重写所有内容。 让`S[i]`是前缀和`S[0] = 0`和`S[n]`等于总和。 每个后缀和可以写成`total - S[i]`。 这意味着后缀极值完全由前缀极值和最终总数决定。 

从这个观察来看，后缀约束不会引入新的结构自由度，它们只会修复之间的关系`a, b, c, d`和总金额。 一旦这些一致，任务就减少到构建任何从`0`到保持在固定区间内的最终总和`[b, a]`并且实际上达到了两个终点。 

这将问题转化为构建具有有限高度的一维晶格路径，这可以确定性地完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | ---| ---| ---|
 | 暴力建设| 指数| O(n) | 太慢了|
 | 前缀和约简+构造路径| O(a - b + c) | O(n) | 已接受 |

 ## 算法演练

 我们将前缀和表示为`S`， 和`S[0] = 0`。 

### 步骤1：将后缀约束转换为前缀形式

 我们使用总和来表示后缀和`T = S[n]`。 位置处的后缀和`i`等于`T - S[i-1]`。 因此，当前缀最小时，后缀值最大，而当前缀最大时，后缀值最小。 这产生关系：`c = T - b`和`d = T - a`两个方程描述相同的总数，所以我们必须有`T = a + d = b + c`。 这是一致性要求； 如果失败，则任何数组都不能存在。 

### 步骤 2：推导前缀和的可行性条件

 由于前缀和总是从零开始，因此间隔`[b, a]`必须包含零。 还有最后的总金额`T`必须位于这个区间内，否则前缀和序列不能结束于`T`不违反界限。 

所以我们必须有`b ≤ 0 ≤ a`和`b ≤ T ≤ a`。 

替代`T = b + c`，我们得到`0 ≤ c ≤ a - b`。 如果失败，则无法进行施工。 

### 步骤 3：将任务重新表述为受限行走

 我们现在需要一系列步骤`+1`和`-1`（或者更一般的整数步）开始于`0`，结束于`T`，永不离开`[b, a]`，并达到两个端点`a`和`b`在某个时刻。 

保证这一点的最简单方法是明确强制访问两个边界。 

### 步骤 4：构建路径

 我们分三个阶段构建前缀和轨迹。 

我们首先从`0`最多`a`使用`+1`步骤。 这始终有效，因为`0 ≤ a`。 

然后我们从`a`下降到`b`使用`-1`步骤。 这保持在界限内，因为我们永远不会低于界限`b`。 

最后，我们从`b`最多`T`使用`+1`步骤。 这是有效的，因为`T ≤ a`。 

结果路径是连续的，保持在`[b, a]`，并以正确的总数结束。 

### 为什么它有效

 构造的前缀和序列在每个阶段内是单调的，但全局是非单调的，这对于实现最小值和最大值至关重要。 每个阶段都明确保证访问一个极值，因此最终序列同时满足`a`和`b`。 由于后缀总和仅由前缀总和和最终总计确定，因此匹配前缀约束并强制执行正确的总计会自动强制后缀极值匹配`c`和`d`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c, d = map(int, input().split())

        T1 = a + d
        T2 = b + c

        if T1 != T2:
            print(-1)
            continue

        T = T1

        if not (b <= 0 <= a):
            print(-1)
            continue

        if not (b <= T <= a):
            print(-1)
            continue

        res = []

        # 0 -> a
        res.extend([1] * a)

        # a -> b
        res.extend([-1] * (a - b))

        # b -> T
        res.extend([1] * (T - b))

        print(len(res))
        print(*res)

if __name__ == "__main__":
    solve()
```该解决方案首先验证两种计算总和的方法是否一致。 如果没有这个，前缀和后缀约束就会相互矛盾。 

之后，它确保前缀总和间隔在零附近有效，并且在该间隔内可以达到目标总和。 

该结构本身是前缀和轨迹的直接翻译：每个`+1`或者`-1`对应于运行总和的受控变化，并且选择步数，以便路径在达到所需总数之前达到两个边界。 

一个常见的陷阱是忘记前缀和必须包含零作为起点。 另一种假设是任何路段的顺序都有效，而实际上顺序是经过精心选择的，以保持步行在内部`[b, a]`步步。 

## 工作示例

 考虑一个一致的情况：

 输入：```
1
3 -2 4 -1
```我们计算`T = a + d = 3 + (-1) = 2`，还有`b + c = -2 + 4 = 2`，所以该实例是可行的。 间隔为`[-2, 3]`。 

| 相| 行动| 前缀和范围| 当前总和|
 | ---| ---| ---| ---|
 | 开始| 0 | [0]| 0 |
 | 0 → 一个 | +1 三次 | [0,3]| 3 |
 | a → b | -1 五次 | [3，-2] | -2 |
 | b → T | +1 四次 | [-2,2] | 2 |

 这证实了两个极值`3`和`-2`达到并且最终的总和匹配`T`。 

现在考虑一个无效的情况：

 输入：```
1
2 1 3 0
```这里`a + d = 2 + 0 = 2`但`b + c = 1 + 3 = 4`。 这种不一致立即表明没有任何构造可以同时满足前缀和后缀约束。

 ## 边缘情况

 当出现一种边缘情况时`a = 0`或者`b = 0`，这意味着前缀和间隔恰好在一个边界处触及起点。 在这种情况下，第一阶段可能会完全消失，但施工仍然有效，因为从`0`到`a`需要零步时`a = 0`。 

另一种情况是当目标总数`T`equals one of the boundaries. 如果`T = a`，最后一个阶段变空，并且构造仍然正确地以最大前缀值结束，而不违反约束。 

最后一个微妙的情况是`b`为负且幅度较大。 第二阶段会变得很长，但每一步仍然有效，因为路径永远不会低于`b`，并且我们明确地停止在`b`在再次向上移动之前。
