 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$网格和放置在不同单元格上的几辆车。 车控制其行中的每个单元格和列中的每个单元格。 仅当没有车共享其行或列时，单元格才被视为“安全”。 

允许的操作是将车从棋盘上移除。 我们的目标不是最大限度地提高各处的安全性，而只是保证拆除后至少存在一个安全单元。 我们希望尽量减少为了使这样一个单元存在而移除的车数量。 

换句话说，我们希望最终得到至少一个单元格$(i, j)$这样删除后，行$i$不包含车和列$j$不包含车。 

限制很小：$n \le 50$和$k \le n^2 \le 2500$。 这立即排除了粗略之外的任何情况$O(n^3)$如果仔细实施的话，每个测试用例都会这样做，但即使这样也是不必要的。 对网格单元的直接枚举已经是可行的。 

一个天真的错误是认为我们需要模拟删除车的子集。 例如，如果我们尝试选择要删除的车，则子集的数量为$2^k$，即使在$k = 2500$。 另一个错误的方向是假设我们只独立关心空行或空列，但条件取决于一对$(row, column)$，不仅仅是一个维度。 

当根本没有车时，就会出现微妙的边缘情况。 答案是零，因为每个细胞都已经安全了。 另一种情况是车的分布使得每一行和每一列至少被占用一次； 即便如此，从精心选择的行和列交叉点中删除车仍然可以产生安全的单元格，但前提是进行有针对性的删除。 

## 方法

 一个蛮力的想法是尝试删除所有可能的车子集，然后检查是否存在安全单元。 对于每个子集，我们将扫描所有行和列以验证是否存在一对$(i, j)$其行和列都没有剩余的车。 检查一个子集成本$O(n^2 + k)$，并且有$2^k$即使对于最小的非平凡输入，这也远远超出了可行的限制。 

关键的简化来自于视角的转变：我们首先修复目标安全单元，而不是决定删除哪些车。 假设我们决定安全单元必须是$(i, j)$。 为此，行$i$必须以空和列结束$j$最终必须是空的。 这意味着我们被迫移除行中的每一辆车$i$和列中的每个车$j$。 没有其他方法可以确保该单元的安全。 

这将问题转化为直接成本计算。 对于每个候选单元格$(i, j)$，我们计算其行或列中有多少车。 删除这些车可以保证$(i, j)$变得安全，并且该成本正是该选择所需的移除数量。 然后我们选择所有单元格中的最小值。 

这是有效的，因为每个有效的最终配置必须对应于至少一个行和列被完全清除的单元格，而实现这一点的唯一方法是删除与这些线相交的所有车。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^k \cdot n^2)$|$O(k)$| 太慢了|
 | 尝试对所有单元格进行计数 |$O(n^2 + k)$|$O(n^2)$| 已接受 |

 ## 算法演练

 1. 计算每行每列有多少辆车。 这使我们能够稍后计算移除成本，而无需重复扫描所有车。 
2. 使用布尔网格或集合记录每个单元格中是否存在车。 当车位于所选行和列的交叉点时，需要这样做以避免重复计数。 
3. 对于每个细胞$(i, j)$，计算使其安全的成本。 成本是排中车的数量$i$加上列中车的数量$j$，如果已经有车在，则减一$(i, j)$。 
4. 跟踪所有单元的最小成本。 这代表在电路板上的任何位置创建至少一个安全单元所需的最少移除次数。 
5. 输出每个测试用例的最小值。 

### 为什么它有效

 修复目标细胞$(i, j)$强制提出严格要求：移除后，其行和列都必须没有车。 这些线之外的任何车都不会影响该特定单元的安全，而内部的任何车必须被移除。 因此，每个候选单元的成本是完全确定的并且独立于其他地方的决策。 由于每个有效的解决方案必须对应于至少一个这样的安全单元，因此最小化所有候选单元涵盖了所有可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        row = [0] * (n + 1)
        col = [0] * (n + 1)
        has = [[0] * (n + 1) for _ in range(n + 1)]
        
        for _ in range(k):
            x, y = map(int, input().split())
            row[x] += 1
            col[y] += 1
            has[x][y] = 1
        
        ans = k
        
        for i in range(1, n + 1):
            for j in range(1, n + 1):
                cost = row[i] + col[j] - has[i][j]
                if cost < ans:
                    ans = cost
        
        print(ans)

if __name__ == "__main__":
    solve()
```实现直接反映了推理。 行和列数组存储计数，以便可以在恒定时间内评估每个候选单元格。 网格`has`当车恰好位于交叉点时，可以防止双重减法。 答案开始于$k$因为删除所有车总是可以保证有效的配置。 

所有单元格上的双循环是安全的，因为$n \le 50$，每个测试用例最多给出 2500 个评估。

 ## 边缘情况

 当没有车时，行数和列数到处都保持为零，因此每个单元格的成本计算为零，并且最小值为零。 该算法无需特殊处理，自然会返回零。 

当所有车都位于同一行时，该行中的每个候选单元格都会产生较高的成本，而其他行中的单元格仅取决于列数。 最小值正确地移动到占用行之外的一行，无需删除。 

当车几乎覆盖每一行和每一列时，相交校正`-has[i][j]`变得至关重要。 没有它，车就被放置在$(i, j)$会被计算两次，从而增加了移除成本并产生错误的答案。
