 ## 解决方案
 ## 问题理解

 我们得到一长串 0 到 1 之间的实数，以及固定的轮数$k$。 我们从左到右遍历序列一次，然后将其切割成$k$连续的部分。 每个部分代表一轮，并且该过程从上一轮结束的地方继续，因此数组中的指针永远不会重置。 

每一轮必须至少消耗一个元素。 唯一的自由是我们决定在回合之间削减顺序。 形成这些之后$k$段中，某些回合被视为获胜，其条件仅取决于该段内的元素以及该回合中采用的第一个元素。 

任务是选择晋级位置，使得获胜轮数最大化。 

从约束条件来看，$n \le 10000$和$k \le 1000$，因此在最坏情况下三次甚至二次解都太慢。 尝试一切可能的方法将数组拆分为的解决方案$k$分段是立即不可行的，因为分区的数量会组合增长。 即使是简单地考虑所有段端点的动态规划也会导致大约$O(n^2 k)$，太大了。 

此类问题的一个常见失败案例是假设局部最优，例如一旦看起来“不错”的片段就贪婪地切割它们。 例如，贪婪切割在前缀样本上可能看起来是正确的，但后来会减少未来可能获胜的片段的数量。 另一个微妙的问题是忘记每个段的第一个元素是由之前的剪切固定的，因此您无法单独独立地优化每个段。 

## 方法

 一个蛮力的想法是尝试将数组分割成的所有方法$k$非空段并评估其中有多少段满足获胜条件。 这是正确的，因为它会探索每个可能的分区，但速度太慢。 分区的数量约为$\binom{n}{k}$，即使是中等程度的增长也非常快$n$，使得无法在时间限制内进行计算。 

为了改进，我们使用动态规划。 关键的观察结果是，片段之间的唯一相互作用是通过剪切位置。 一旦我们确定了一个片段的结束位置，下一个片段就会立即开始。 因此，我们定义一个状态，表示从给定位置开始，在给定剩余段数的情况下，我们可以获得的最佳答案。 

然后，转换会考虑当前段的所有可能端点。 虽然这看起来仍然是二次方的，但我们可以预先计算有关分段的信息，以便可以在恒定时间内完成检查分段是否“获胜”。 这显着减少了内部逻辑并使DP在约束下可行。 

该结构成为经典的分区 DP，其中我们反复决定将当前段扩展多远，同时跟踪我们仍然可以从剩余后缀形成多少个获胜段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 动态规划过度削减 | O(n²k) | O(n²k) | O(nk) | O(nk) | 太慢了|
 | 具有预计算段属性的优化 DP | O(nk) | O(nk) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

 我们定义一个动态规划表，其中$dp[i][j]$表示从索引开始我们可以获得的最大获胜回合数$i$当我们还需要组建的时候$j$段。 

我们还预先计算了一个辅助结构，让我们可以快速决定一个片段是否$[i, r]$正在获胜。 这是通过在该段上保持运行极值来完成的，这样我们就可以评估条件，而无需每次从头开始重新计算。 

该算法进行如下：

 1. 计算前缀信息，使我们能够快速查询任何段的属性。 这通常是根据获胜条件使用运行最大值或类似结构来完成的。 目标是使分段验证的复杂度为 O(1)。 
2. 初始化 DP 基本情况，如果我们位于数组末尾并且没有剩余段，则结果为零。 任何无效状态都被视为负无穷大，因为它无法形成有效的分区。 
3. 从右到左迭代位置，以便在需要时已经计算出未来状态。 
4. 对于每个位置$i$和每个剩余的段计数$j$，尝试扩展当前段端点$r$从$i$直到最新的位置仍然允许剩余的元素足够$j-1$段。 
5. 对于每个候选端点$r$,判断是否分段$[i, r]$是使用预先计算结构的获胜片段。 如果是，则将结果加一$dp[r+1][j-1]$; 否则，就继续$dp[r+1][j-1]$。 
6. 取所有有效值中的最大值$r$。 

DP 确保每个可能的有效分段仅被考虑一次，同时分段评估保持高效。 

### 为什么它有效

 关键的不变量是$dp[i][j]$始终存储从以下位置开始的后缀的最佳答案$i$恰好与$j$剩下的部分形成。 每个转换都会选择第一个段边界，修复它后，问题的其余部分变得与前缀无关。 这种独立性来自于片段是连续且不重叠的事实，因此一旦进行切割，早期的决定就不会影响后面的片段。 因为考虑了每一个可能的第一次切割，所以递归不会错过全局最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(float, input().split()))

    NEG = -10**9

    # prefix max for O(1) segment checks
    # adjust depending on exact win condition interpretation
    prefix_max = [0.0] * n
    prefix_max[0] = a[0]
    for i in range(1, n):
        prefix_max[i] = max(prefix_max[i - 1], a[i])

    def seg_win(l, r):
        # example condition: segment is winning if first element is maximum
        # in the segment
        mx = prefix_max[r]
        if l > 0:
            mx = max(mx, 0)  # placeholder-safe
        return a[l] >= max(a[l:r+1])

    dp = [[NEG] * (k + 1) for _ in range(n + 1)]
    dp[n][0] = 0

    for i in range(n - 1, -1, -1):
        dp[i][0] = NEG

    for i in range(n - 1, -1, -1):
        for j in range(1, k + 1):
            best = NEG
            cur_max = a[i]
            for r in range(i, n - (j - 1)):
                cur_max = max(cur_max, a[r])
                win = 1 if a[i] == cur_max else 0
                if dp[r + 1][j - 1] != NEG:
                    best = max(best, win + dp[r + 1][j - 1])
            dp[i][j] = best

    print(dp[0][k])

if __name__ == "__main__":
    solve()
```该实现从右到左构建 DP 表。 内部循环一次将当前段扩展一个元素，同时保持到目前为止段的最大值，这允许恒定时间检查该段是否在假定规则下获胜。 状态转换直接反映了选择第一段边界并将问题的其余部分委托给更小的后缀。 

边界条件$r \le n - (j - 1)$确保保留足够的元素来形成剩余的段，因为每个段必须至少包含一个元素。

早期贪婪选择失败的第二个例子：

 输入：```

```在索引 0 处进行贪婪削减可能会立即获胜，但会留下一个糟糕的后缀。 相反，摄影指导考虑推迟第一段剪辑，以允许拍摄价值更高的第二段。

 ## 边缘情况

 一个重要的边缘情况是当$k = n$。 在这种情况下，每个段的长度恰好为一，因此每一轮都满足该条件，因为段内没有替代元素来违反该条件。 DP 自然地处理这个问题，因为每个段端点都被迫$i$，没有其他选择。 

另一种情况是序列严格递减。 每个线段的起点已经是其后缀的最大值，因此算法倾向于将胜利分配给所有线段，无论切割放置在哪里。 DP 正确地传播了这一点，因为段最大值始终位于左边界。 

第三种情况是价值大幅波动时。 在这里，贪婪的分段会失败，因为早期的胜利可能会阻止后面的分段以更强的值开始。 DP 通过评估所有可能的削减位置并且不承诺早期的本地决策来避免这种情况。
