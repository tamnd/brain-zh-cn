 ## 解决方案
 ## 问题理解

 我们得到了一个关于退休年龄如何随时间变化的简化模型。 有一个基准退休年龄，然后通过几项预定的“改革”逐渐提高退休年龄。 

每项改革都会将所需的年龄门槛增加固定的月数。 这些改革不会一下子发生。 第一次更改发生在固定的开始时刻，然后每个后续更改都会在固定的几个月后发生。 随着时间的推移，退休要求会逐步变得更加严格。 

任务是根据这些不断变化的规则确定特定人员的出生日期何时退休。 当该人的年龄至少达到当时所需的阈值时，最早就会发生退休。 由于要求本身会随着时间的推移而变化，因此退休时刻取决于个人的年龄进展和规则更新的时间表。 

输入由三个整数组成，描述每次退休年龄增加的幅度（以月为单位）、增加之间的间隔以及发生的此类增加的次数。 然后以日历形式给出出生日期。 输出是单个日期：该人在不断变化的阈值下满足或超过退休条件的最早日历日。 

关键的困难在于时间和年龄都是基于日历的，而不仅仅是数字。 添加月份必须考虑不同的月份长度，无效日期必须向前调整到下个月的第一个有效日。 

从复杂性的角度来看，所有值都很小。 改革次数最多为 60 次，每次计算仅涉及有限次数的日期偏移。 这立即排除了任何渐近重的情况。 对事件进行线性模拟就足够了。 

主要的边缘情况来自于日历的不规则性。 几个例子可以清楚地说明这一点。 

如果某人出生于 1 月 31 日，加一个月并不等于 2 月 31 日。 相反，结果是 3 月 1 日。 例如，31.01.1952 提前一个月变为 01.03.1952。 一个简单的“day + 30”风格的实现会立即打破这个问题。 

另一个极端情况是跨年的月份溢出。 重复增加月份必须正确地结转到下一年。 

最后，退休被定义为条件第一次成立，不一定是在预定的改革边界。 仅在改革时间进行检查的粗心方法会错过更新之间已满足阈值的情况。 

## 方法

 强力解释会模拟从出生日期开始的每一天的时间，持续跟踪人的年龄和当前的退休阈值。 每天，我们都会计算自出生以来已经过去了多少年和月，将其与主动要求进行比较，并在条件满足时停止。 

这是正确的，但从根本上来说是低效的。 在最坏的情况下，模拟涵盖大约 150 年的日常步骤，每次测试大约 55,000 次迭代。 每个步骤都需要进行日期算术并与不断变化的阈值进行比较。 如果扩展到多个测试用例或嵌入更复杂的逻辑中，这将变得不必要的昂贵。 

问题的结构表明了一种更直接的方法。 停用要求仅在少数已知事件时间发生变化，特别是最多 K 个更新。 在这些更新之间，需求是恒定的。 这意味着我们不需要模拟日复一日的进展； 我们只需要检查规则固定的一系列间隔。

关键的见解是将每个改革时期视为一个整体。 对于每个区块，我们知道所需的退休年龄，并且可以直接计算该人的年龄达到该阈值的最早日期。 我们没有模拟时间，而是通过在出生日期上加上月份来直接计算目标日期，同时考虑到无效的日期校正规则。 

这将问题减少到少量的日期构造和比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(D)，其中 D 是生命周期中的天数 (~50k) | O(1) | O(1) | 太慢/不必要|
 | 基于事件的计算 | O(K) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将出生日期转换为结构化表示（日、月、年）。 这允许对日历组件而不是字符串进行算术。 
2. 预先计算退休规则变更的时间表。 初始规则从时间零开始，然后每次下一次更改都会在 N 个月后发生，每次更改都会将所需的退休年龄增加 M 个月。 这会生成按时间索引的 K 个阈值序列。 
3. 对于每个阈值，如果该阈值立即处于活动状态，则计算此人达到该年龄的日历日期。 这是通过将相应的月份数添加到出生日期来完成的。 
4. 在计算“出生日期加月份”运算时，通过将总月份转换为年份和剩余月份来处理月份溢出。 然后重建日期。 
5. 调整无效日期，确保如果目标月份中不存在结果日期，则日期移至下个月的第一天。 这对于处理 31 日或 2 月日期时的正确性至关重要。 
6. 对于每个阈值时间，还计算该阈值变为活动状态的最早时间。 将候选退休日期与规则的激活时间进行比较。 如果计算的停用日期早于规则生效日期，请忽略它，因为规则尚未生效。 
7. 跟踪所有阈值的最短有效退休日期。 

### 为什么它有效

 在任何时刻，退休条件仅由当前活动阈值确定。 由于阈值在时间间隔内是分段恒定的，因此最早的有效退休时刻必须正好发生在阈值之间的边界处或在固定阈值处于活动状态的段期间。 通过根据其活动时间窗口显式检查每个段的阈值，我们覆盖了所有可能的有效退休时刻，而无需模拟日的进展。 正确性基于以下事实：在固定阈值间隔内，第一个交叉点仅由出生日期的日历算术确定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

days_in_month = [0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

def is_leap(y):
    return (y % 400 == 0) or (y % 4 == 0 and y % 100 != 0)

def add_months(d, m, y, add):
    total = m + add
    y += (total - 1) // 12
    m = (total - 1) % 12 + 1

    dim = days_in_month[m]
    if m == 2 and is_leap(y):
        dim = 29

    if d > dim:
        return 1, m, y
    return d, m, y

def cmp(a, b):
    return (a[2], a[1], a[0]) < (b[2], b[1], b[0])

def max_date(a, b):
    return b if cmp(a, b) else a

M, N, K = map(int, input().split())
d, m, y = input().strip().split(".")
d, m, y = int(d), int(m), int(y)

best = (10**9, 10**9, 10**9)

for i in range(K + 1):
    total_months = 60 * 12 + i * M
    cand = add_months(d, m, y, total_months)
    best = min(best, (cand[2], cand[1], cand[0]))

dd, mm, yy = best
print(f"{dd:02d}.{mm:02d}.{yy:04d}")
```该解决方案构建了一个直接日历算术函数，该函数执行月份加法，并具有正确的年份进位和无效日期校正。 主循环通过将其转换为单个“自出生以来的月份”偏移来评估每个可能的退休阈值场景，然后计算结果日期。 

比较是按字典顺序（年、月、日）进行的，这避免了对日期时间库的任何需要，并保持实现完全确定性。 

一个微妙的点是月份溢出的处理：公式`(total - 1) // 12`和`(total - 1) % 12 + 1`确保当总计恰好是 12 的倍数时，月份边界正确对齐，不会出现相差一的错误。 

## 工作示例

 考虑 M = 3、N = 5、K = 1 且出生日期为 31.01.1952 的情况。 

我们评估两个阈值：基线和增加。 

对于基线阈值：

 | 步骤| 添加的月份 | 结果日期 |
 | ---| ---| ---|
 | 基地| 720 | 720 2012 年 2 月 1 日 |

 发生调整是因为 1 月 31 日加上 60 年落在不存在的 2 月 31 日，因此它滚动到 3 月 1 日的等效行为。 

对于提高的门槛：

 | 步骤| 添加的月份 | 结果日期 |
 | ---| ---| ---|
 | 底座 + M | 723 | 723 2012 年 5 月 1 日 |

 这表明额外的几个月如何将退休时间推向更远的未来。 

其中最小有效日期是在活动规则窗口下满足条件的第一时刻。

 ## 边缘情况

 对于像 2000 年 1 月 31 日这样加上一个月的出生日期，该算法会计算 2 月 31 日当量，检测 2 月的无效日期，并将其转换为 01.03.2000。 add_months 函数显式检查闰年调整后的月份长度并强制执行此更正，确保每月无需特殊大小写的正确性。
