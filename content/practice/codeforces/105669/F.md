 ## 解决方案
 ## 问题理解

 我们被要求计算有多少种不同的方式可以将一个正整数分解为多个正整数之和，其中顺序并不重要。 如果两个表示由相同的被加数多重集组成，即使以不同的顺序编写，也被认为是相同的。 

例如，对于像 4 这样的小数字，有效分解为 4、3+1、2+2、2+1+1 和 1+1+1+1。 其中每一个都对应于一种不同的整数划分方式。 

输入给出单个整数 n，输出是 n 的此类分区的数量，以 1e9+7 为模计算。 

约束达到 1e6，这会立即排除任何尝试显式枚举分区或构建组合的方法。 即使对子集或背包式构造的动态编程也会失败，因为它们通常依赖于 n^2 转换或更糟。 

微妙的边缘情况是最小的输入。 当 n = 1 时，答案为 1，因为只有一种方法可以表示 1。任何假设至少有两个部分或尝试在没有初始化的情况下从较小的正索引构建的错误实现都可能很容易在此处崩溃。 

当实现错误地将不同的订单视为不同的订单时，就会出现另一种故障模式。 例如，对于 n = 4，计算分区的排列会错误地将 3+1 和 1+3 视为不同的，这会夸大结果。 正确的解释完全忽略了顺序。 

## 方法

 蛮力的想法是递归地尝试从剩余的总和中减去每个可能的第一部分。 对于数字 n，我们从 1 到 n 选择第一个被加数 k，并递归地划分 n-k，约束下一部分最多为 k，以避免过度计数排列。 这种递归是正确的，因为它强制执行规范的非递增分区结构。 

然而，这种方法扩展到一个大的递归树。 即使使用记忆化，在最坏的情况下状态的数量仍然是 n^2 / 2 个转换的数量级，因为每个状态都会尝试所有可能的下一个部分。 对于 n = 1e6，这远远超出了可行的限制。 

关键的观察结果是整数分区具有从欧拉五边形数定理导出的众所周知的递推。 我们不是根据下一个被加数的选择来构建分区，而是用早期值 p(n - k(3k−1)/2) 来表达 p(n)，其中广义五边形数自然地编码分区结构的包含和排除。 这将问题转化为 n 上的单个线性 DP，其中每个状态取决于由结构化偏移序列索引的少量早期状态。 

该结构很重要，因为偏移量会像 O(k^2) 一样增长，因此对于每个 n 来说，只有大约 O(√n) 个有效贡献。 这将计算量减少到大约 n√n 算术运算，这在 C++ 中是可以接受的，并且通过仔细实现仍然可以管理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 带有记忆化的强力递归 | O(exp(n)) | O(exp(n)) | O(n) | 太慢了 |
 | DP 与欧拉五边形定理 | O(n√n) | O(n√n) | O(n) | 已接受 |

 ## 算法演练

 我们预先计算从 0 到 n 的所有 i 的分区值 p[i]，其中 p[i] 表示 i 的整数分区数。 我们设置 p[0] = 1，因为只有一种方法可以划分零，即不选择任何内容。 

对于从 1 到 n 的每个值 i，我们使用广义五边形数的贡献来计算 p[i]。 这些数字来自 k(3k−1)/2 和 k(3k+1)/2（k = 1、2、3 等）。 每个这样的偏移对应于扩展或收缩分区的结构化方式，同时保留分区形状上的包含-排除的正确性。

我们以两个贡献为一组交替使用符号。 具体来说，对于 k = 1, 2, 3, …，我们采用两个偏移量：t1 = k(3k−1)/2 和 t2 = k(3k+1)/2。 p[i − t] 的贡献根据 k 的奇偶性进行添加或减去，当 t 超过 i 时我们停止。 

对所有有效贡献求和后，我们将结果以 1e9+7 为模进行归一化。 

其原理在于，分区数的生成函数 1 / Product(1 − x^i) 具有对数结构，其展开会导致由广义五边形数精确索引的取消。 循环中的每一项都会纠正前一项引入的过度计数，并且交替符号模式可确保准确取消无效配置。 DP 有效地以 i 的递增顺序迭代评估递归，保证所有需要的子问题都已计算出来。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())
    
    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        total = 0
        k = 1
        while True:
            a = k * (3 * k - 1) // 2
            b = k * (3 * k + 1) // 2

            if a > i:
                break

            sign = 1 if k % 2 == 1 else -1

            total += sign * dp[i - a]
            if b <= i:
                total += sign * dp[i - b]

            k += 1

        dp[i] = total % MOD

    print(dp[n] % MOD)

if __name__ == "__main__":
    solve()
```DP 数组是自下而上构建的，因此每个 dp[i] 仅取决于已计算的较小索引。 k 上的循环生成五边形偏移。 符号每两项交替一次，这与递推式的结构相匹配。 

一个常见的实现陷阱是忘记偏移量 k(3k−1)/2 和 k(3k+1)/2 必须包含在同一符号组中。 另一个微妙的问题是在累加之后而不是在每次加法期间处理模算术，因为中间值可能会变成负数。 

## 工作示例

 考虑 n = 5。该算法按顺序计算 dp[1] 到 dp[5]。 

对于 dp[1]，只有 k = 1 通过偏移量 1 做出贡献，因此 dp[1] = 1。 

对于 dp[2]，贡献来自 dp[1] 和 dp[0] 通过五边形偏移，产生 dp[2] = 2。 

对于dp[5]，计算涉及多个k值，我们可以跟踪更新。 

| k | t1 = k(3k−1)/2 | t2 = k(3k+1)/2 | 标志| 贡献|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 2 | + | +dp[4], +dp[3] |
 | 2 | 5 | 7 | - | -dp[0]，跳过 dp[-2] |

 求和后：

 dp[5] = dp[4] + dp[3] − dp[0] = 5 + 3 − 1 = 7

 这与已知的分区值 5 匹配。 

该迹线显示了较高的指数如何仅依赖于先前计算的状态以及如何通过减法消除无效的过度计数。

 ## 边缘情况

 对于 n = 1，该算法初始化 dp[0] = 1 并跳过所有五边形贡献，因为第一个偏移量已经超过索引。 这会正确生成 dp[1] = 1，而不依赖于任何递归深度。 

对于像 n = 2 或 n = 3 这样的小值，只有最小的五边形数才起作用。 k 上的循环很快停止，因此不会发生越界访问，并且 dp 值纯粹由 dp[0] 和 dp[1] 构建。 

对于较大的值，例如 n = 10，多个 k 级别会起作用，但每个 dp[i] 保证仅使用先前计算的 dp[j]（其中 j < i）。 这确保了没有未初始化的访问并在整个迭代构建过程中保持正确性。
