 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 每个场景中都有$n$区，每个区属于某个由整数标签标识的帮派。 我们的任务是构建一组精确的$n-1$无向道路，使所有地区作为一个连接的组成部分连接起来，这意味着任何地区都可以通过这些道路到达任何其他地区。 

这个限制是结构性的：如果两个区属于同一帮派，我们就不能直接连接它们。 最终图中的每条边都必须连接具有不同标签的两个顶点。 我们可以自由选择任何树结构，只要它跨越所有顶点并遵守此约束即可。 如果不存在这样的树，我们必须报告不可能性。 

约束条件$\sum n \le 5000$意味着在所有测试用例中，我们可以提供每个测试用例大致线性或接近线性的解决方案。 每个测试用例在最坏情况下的任何二次方仍然会通过，但如果在许多测试中重复，任何三次方或涉及重复昂贵的重新计算的东西都会变得不安全。 这促使我们采用基于构造的解决方案，而不是搜索或回溯。 

当所有地区都属于同一帮派时，就会出现一个关键的边缘情况。 在这种情况下，每个可能的对都违反了约束，因此即使是第一条边也无法添加。 

另一种微妙的情况发生在恰好有两个帮派但一个帮派只有一个节点时。 例如，如果我们尝试在单一颜色簇内贪婪地连接节点，我们可能会隔离该单例，并且只有仔细的交叉连接策略才能保留连接性。 

## 方法

 暴力方法会尝试通过检查所有可能的树或在验证连通性和颜色约束的同时逐渐构建边缘来构建有效的生成树。 从概念上讲，我们可以在遵守规则的所有边上尝试 DFS 或 BFS，看看是否可以到达所有节点，但这忽略了我们必须准确输出的要求$n-1$边形成一棵树。 枚举候选树是指数级的$n$，因为标记树的数量是$n^{n-2}$，甚至通过颜色限制来过滤它们也是不可行的。 

关键的结构洞察力是我们不需要搜索一棵树；我们需要寻找一棵树。 我们只需要构建一个。 唯一的障碍是边缘必须始终连接不同的帮派。 如果存在至少一个与所选根不同的组的节点，则该根可以充当中心：每个其他节点都可以附加到它或仔细选择的代表节点，以确保连接而不违反约束。 

唯一失败的时候是当所有节点都属于同一个组时，因为那时根本不存在有效的边。 

这提出了一种简单的建设性策略：选择一个节点作为参考，最好是从多数节点或简单的索引 1 中选择，然后将不同帮派的每个节点连接到它。 然而，仅靠这一点并不能保证同一帮派结构的节点之间的连通性，因此我们改进了想法：我们从一个帮派中选择一个枢轴节点，并确保所有连接都是从该枢轴或不同帮派的节点建立的，有效地构建了星形或近星形结构。 

然后，我们确保对于颜色与枢轴匹配的每个节点，我们避免将其直接连接到枢轴，而是通过某个不同颜色的节点将其连接。

 | ---| ---| ---| ---|
 | 蛮力（树搜索）| 指数| O(n) | 太慢了 |
 | 建设性的支点战略| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们使用固定的代表结构构建有效的生成树。 

1. 选择任意节点作为参考，通常为节点1，并记录其帮派标签$c$。 
2. 将所有节点分为两组：带标签的节点$c$，以及那些标签不等于$c$。 这种分割至关重要，因为至少在涉及参考节点时，每个有效边都必须穿过此边界。 
3. 如果没有节点的标签与$c$，立即输出NO。 这对应于每条边都会违反约束的情况。 
4. 选择一个节点$j$使其标签不同于$c$。 该节点充当通用连接器。 
5. 将节点1连接到节点$j$。 这保证了两组之间至少有一个有效的桥梁。 
6. 对于每个剩余节点$i > 1$，如果其标签不同于节点 1，则将其连接到节点 1$c$。 否则，将其连接到节点$j$。 

拆分附件规则的原因是节点1无法安全地连接到自己颜色的节点，但是节点1$j$可以充当该颜色组的替代锚点。 

### 为什么它有效

 该结构保证每个节点都由一条边连接，除了连接在一起的两个锚点之外，形成一棵树$n-1$边缘。 连接性随之而来，因为每个节点都直接连接到节点 1 或节点$j$，并且这两个锚点是相连的。 每条边都是有效的，因为我们只通过构造连接不同颜色的节点。 该结构是非循环的，因为除了两个锚点之外的每个节点都只有一个父节点，并且两个锚点形成唯一的交叉链接。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        root_color = a[0]
        other = -1

        for i in range(n):
            if a[i] != root_color:
                other = i
                break

        if other == -1:
            print("NO")
            continue

        print("YES")

        # connect root (0) with first different color node
        print(1, other + 1)

        # attach remaining nodes
        for i in range(1, n):
            if i == other:
                continue
            if a[i] == root_color:
                print(other + 1, i + 1)
            else:
                print(1, i + 1)

if __name__ == "__main__":
    solve()
```该代码首先确定是否存在第二个团伙。 变量`other`使用与第一个节点不同的标签存储第一个索引。 如果还剩下`-1`，所有节点共享同一个组，并且不存在解决方案。 

然后，边缘构造将节点 1 固定为主要枢纽。 第一个跨帮节点成为次要枢纽。 每个节点要么连接到节点 1，要么连接到该辅助集线器，具体取决于它是否与节点 1 的组匹配。 这避免了创建同组边缘，同时确保所有节点通过最多两个中心顶点连接。 

一个微妙的细节是跳过`other`循环期间的节点，因为它已经参与了初始连接边。 如果没有这个跳过，我们将创建一个重复的或自引用的结构。 

## 工作示例

 ### 示例 1

 输入：```
n = 5
a = [1, 2, 2, 1, 3]
```我们选择节点 1 作为颜色 1 的根。第一个不同的节点是索引 2（颜色 2）。 

| 步骤| 行动| 到目前为止的边缘|
 | ---| ---| ---|
 | 1 | 连接 1 和 2 | (1,2) |
 | 2 | 节点 3 的颜色为 2，附加到 1 | (1,2), (1,3) | (1,2), (1,3) |
 | 3 | 节点 4 的颜色为 1，附加到 2 | (1,2), (1,3), (2,4) | (1,2), (1,3), (2,4) |
 | 4 | 节点 5 的颜色为 3，附加到 1 | (1,2)、(1,3)、(2,4)、(1,5) |

 这形成了一个有效的树，其中所有边都连接不同的组，并且所有节点都可以通过节点 1 或节点 2 到达。

 ## 边缘情况

 当所有区都属于同一个帮派时，扫描永远找不到有效的辅助节点，因此算法立即输出“否”。 对于像这样的输入`1 1 1 1`，这正确地反映了根本不存在法律优势。 

当恰好存在两个帮派但其中一个仅出现一次时，辅助节点就成为关键桥梁。 例如，`1 1 1 2`，节点 2 成为所有颜色为 1 的节点的唯一安全连接器。该构造通过相反颜色的节点路由所有相同颜色的节点，确保在仍然生成连接树的同时不会创建无效边。
