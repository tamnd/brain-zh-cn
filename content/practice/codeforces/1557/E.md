 ## 解决方案
 ## 问题理解

 我们正在 8 × 8 的棋盘上玩互动游戏。 有一个由我们控制的女王和一个由法官控制的国王。 国王从一个与女王的起始单元不同的未知单元开始。 我们选择初始的皇后位置，然后游戏开始，国王先移动。 每次国王移动后，我们只知道它移动的方向，而不是它的目的地。 然后我们移动女王。 

国王像国际象棋国王一样移动，向八个方向中的任何一个方向迈出一步，但有一个额外的限制：他不允许踏上与当前皇后在同一行、同一列或对角线上的任何方格。 这意味着女王定义了限制国王活动范围的禁线。 

我们的目标是迫使国王处于没有合法步数的位置，最多 130 步后步。 每个动作都是完全互动的，我们必须在每次国王动作之后仅根据我们被告知的方向来决定我们的皇后动作。 

关键的困难是我们从来没有观察到国王的确切位置。 我们只维护他可能所在的一组可能的单元格，并且随着我们模拟两个玩家动作的约束，这组单元格会不断演变。 

该板很小，只有 64 个单元，但交互约束和移动限制使其成为动态状态跟踪问题，而不是最短路径问题。 

一个天真的误解是试图像确定性棋子一样“追逐”国王。 这会立即失败，因为我们永远不知道它的确切位置。 正确的观点是我们正在缩小信念集。 

当信念集断开连接或崩溃为所有位于禁止皇后线上的单元格时，就会出现边缘情况。 只跟踪边界框而不考虑皇后攻击线的粗心方法将产生几何上合理但实际上对国王来说非法的状态。 

## 方法

 蛮力视角是明确追踪每一个可能的国王位置。 最初，除了蚁后的起始单元之外的每个单元都是可能的。 在每个国王移动方向后，每个候选位置都会朝该方向移动一步，但前提是最终位置留在棋盘内并且不会受到当前皇后的攻击。 这给出了可能的国王位置的更新集。 

这种简单的模拟已经很小了，因为电路板只有 64 个单元，因此维护该组的成本很低。 真正的挑战是选择皇后动作。 如果我们尝试所有可能的王后目的地并模拟它们对集合的影响，我们可以测量移动后还有多少个可能的王位置。 皇后移动进一步限制了国王，因为任何与新皇后位于同一行、列或对角线上的单元格对于国王来说都是不可能的。 

这导致了一种自然的贪婪的想法。 对于每个有效的王后移动，我们模拟下一个状态并选择最小化剩余可能王组大小的移动。 直觉是，由于状态空间如此之小，因此在每一步中积极缩小不确定性足以迫使收敛在移动限制内。 

显式尝试所有皇后动作并模拟所有位置的强力版本足够快，因为总工作量大约为 130 乘以 64 乘以 64 次操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 所有状态的暴力模拟+贪婪皇后选择 | O(130 × 64²) | 奥(64) | 已接受 |
 | 没有完整状态跟踪的任何几何启发式 | O(130 × 1) | O(1) | O(1) | 失败|

 重要的转变是认识到我们唯一需要的信息是可行的国王位置集合，并且该集合仍然很小，足以完全暴力破解。 

## 算法演练

我们维护一个集合 S，其中包含国王当前可能所在的所有单元格。 我们还追踪皇后位置 Q。 

1. 将 S 初始化为除 Q 之外的所有 64 个单元格。这代表所有可能的隐藏王放置。 
2. 当我们收到一个王移动方向时，我们通过将 S 中的每个位置朝该方向移动一步来计算新的候选集 S'。 任何超出棋盘的移动位置都将被丢弃。 
3. 从S'中，我们删除所有被当前皇后Q攻击的位置。这些位置是不可能的，因为国王不允许进入皇后控制的线。 
4. 现在我们选择下一个皇后位置Q′。 我们枚举从 Q 开始的合法皇后移动可到达的所有单元格，这意味着同一行、列或对角线上但不等于 Q 的任何单元格。 
5. 对于每个候选 Q′，我们模拟如果将皇后移到那里 S 会变成什么。 我们从 S' 中删除所有受到 Q' 攻击的位置，因为一旦皇后移动，这些方格对于国王来说就变得非法。 
6. 在所有候选 Q' 中，我们选择一个能够最小化结果集大小的一个。 我们将 Q 更新到该位置并用模拟结果替换 S。 
7. 如果 S 在任何时候变空，国王就会被困住，交互结束。 

关键的不变量是 S 始终准确地表示与所有观察到的国王方向和所有皇后约束一致的位置集。 每个更新步骤都反向应用真正的转换规则，因此不会错误地添加或删除可能的国王位置。 

因为 S 永远不会高估或低估真正可到达的位置，而且因为每个皇后的举动都会贪婪地最小化其规模，所以不确定性会稳步崩溃，直到国王没有剩下合法的举动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

DIRS = {
    "Right": (0, 1),
    "Left": (0, -1),
    "Up": (-1, 0),
    "Down": (1, 0),
    "Up-Right": (-1, 1),
    "Up-Left": (-1, -1),
    "Down-Right": (1, 1),
    "Down-Left": (1, -1),
}

def inside(x, y):
    return 1 <= x <= 8 and 1 <= y <= 8

def attacked(x, y, qx, qy):
    return x == qx or y == qy or abs(x - qx) == abs(y - qy)

def apply_shift(S, dx, dy, qx, qy):
    ns = []
    for x, y in S:
        nx, ny = x + dx, y + dy
        if inside(nx, ny) and not attacked(nx, ny, qx, qy):
            ns.append((nx, ny))
    return ns

def queen_moves(qx, qy):
    res = []
    for i in range(1, 9):
        for j in range(1, 9):
            if (i, j) == (qx, qy):
                continue
            if i == qx or j == qy or abs(i - qx) == abs(j - qy):
                res.append((i, j))
    return res

def main():
    t = int(input())
    for _ in range(t):
        # initial placement
        qx, qy = 1, 1
        print(qx, qy, flush=True)

        # initial S (unknown king position)
        S = [(i, j) for i in range(1, 9) for j in range(1, 9) if (i, j) != (qx, qy)]

        for _ in range(130):
            s = input().strip()
            if s == "Done":
                break

            dx, dy = DIRS[s]

            # king moves
            S = apply_shift(S, dx, dy, qx, qy)

            # try all queen moves
            best = None
            bestS = None

            for nq in queen_moves(qx, qy):
                nx, ny = nq
                cand = []
                for x, y in S:
                    if not attacked(x, y, nx, ny):
                        cand.append((x, y))
                if bestS is None or len(cand) < len(bestS):
                    bestS = cand
                    best = nq

            qx, qy = best
            S = bestS

            print(qx, qy, flush=True)

            if not S:
                break

if __name__ == "__main__":
    main()
```该解决方案是围绕明确维护不确定性集而构建的。 这`apply_shift`函数实现国王的移动，同时尊重棋盘边界和皇后当前的攻击线。 这`queen_moves`函数通过直接检查车和主教的移动规则来枚举所有合法的皇后目的地。 

主循环首先处理王方向，更新置信集，然后通过模拟其剪枝效果来评估每个可能的后移动。 所选择的棋步是最小化剩余候选王位置的棋步，这直接对应于最大化信息增益。 

一个微妙的点是，我们在每次皇后移动后重新计算国王位置的合法性，而不是尝试逐步维持多个状态。 由于电路板很小，重新计算更简单且不易出错。

 ## 边缘情况

 当所有剩余的国王位置都位于当前女王攻击的线上时，就会发生严重的边缘情况。 在这种情况下，应用皇后限制后，集合立即变空。 该算法正确地处理了这个问题，因为每次皇后移动后的过滤步骤都会删除所有受攻击的方格，并且空集是有效的终止条件，表明国王没有与历史一致的合法位置。 

另一种情况是当国王反复击中棋盘边界时，例如从顶行连续“向上”移动。 移位步骤自然会丢弃无效位置，从而防止信念集错误地环绕或停滞。 收缩是纯粹几何形状的并且保持一致。 

最后，如果国王已经被迫进入单个单元格，则每个候选皇后的移动要么保留该单例，要么消除它。 如果可能的话，贪婪的选择总是会选择导致空集的一步，立即结束交互。
