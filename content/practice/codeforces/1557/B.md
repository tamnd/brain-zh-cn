 ## 解决方案
 ## 问题理解

 我们得到一个不同整数的数组，并允许执行一次非常具体的转换。 首先，我们将数组切分成 k 个连续的块，每块都非​​空。 然后我们可以任意排列这些片段，最后我们按照新的顺序将它们重新粘在一起。 

目标是确定是否存在某种方法来选择 k 段，以便在对它们重新排序后，最终合并的数组以非降序完全排序。 

关键的困难是我们不允许重新排列单个元素，只能重新排列整个连续的块。 因此，原始数组的结构对哪些元素可以组合在一起施加了限制，而不会破坏重新排序为排序序列的能力。 

约束足够大，任何解决方案对于每个测试用例都必须是线性的。 当 n 总数达到 3e5 时，每个测试用例方法的 O(n log n) 就可以了，但是分段探索中的任何二次方都是不可能的。 对所有可能的 k 分区进行暴力破解会导致组合爆炸，因为有 O(n 选择 k) 种分割方式。 

当 k 等于 1 时，会出现微妙的边缘情况。然后我们无法对任何内容重新排序，因此数组必须已经排序。 另一个边缘情况是 k 等于 n，其中每个元素都是其自己的段，并且我们始终可以通过排列单例进行排序，因此答案始终是“是”。 

重要的情况是当 1 < k < n 时，分段以有意义的方式与数组的内部顺序交互。 

## 方法

 暴力方法会尝试一切可能的方法将数组分割成 k 个连续的段，然后尝试这些段的每种排列，并检查是否有任何排序产生排序数组。 即使我们固定一个分区，也有k个！ 排列，并且分区的数量是组合的。 即使对于 n = 30，这也太大了。 

关键的见解是停止考虑任意段，而是考虑数组“已经与排序顺序一致”的位置。 让我们对数组的副本进行排序并比较位置。 由于所有元素都是不同的，因此每个值在排序数组中都有唯一的正确位置。 

现在观察有效的解决方案真正需要什么：当我们排列段时，我们有效地将元素分组为 k 个块，并且每个块必须是可移动的，而不会破坏全局排序顺序。 当我们可以将数组分割成 k 个连续的段时，这就成为可能，这样每个段在内部考虑时都不会违反排序数组所需的相对顺序。 

决定性的观察是，每次在原始数组中按排序顺序的连续元素之间的邻接被“破坏”时，我们都被迫进行切割。 如果按排序顺序的两个连续元素在原始数组中不相邻，那么如果我们想保留全局可重新排序性，它们就不能属于同一段。 

因此，我们计算映射到排序位置时原始数组中存在多少个“排序相邻断点”。 将该数字设为所需削减量。 如果我们需要超过 k−1 次切割，我们就无法实现遵循排序结构的 k 个段。 如果我们需要更少或相等，我们总是可以进一步分割段以恰好达到 k。 

这将问题简化为排序引起的排列中的转换的简单计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力分区+置换| 指数| O(n) | 太慢了|
 | 排序 + 计算必要的削减 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将数组转换为其排序顺序并记录每个值的位置。

1. 构建从值到排序数组中索引的映射。 这告诉我们元素的预期顺序。 
2. 用这些位置替换原始数组，将问题转化为分析从 0 到 n−1 的排列。 
3. 从左到右扫描转换后的数组，并计算下一个元素不完全是按排序顺序排列的当前元素的后继元素的次数。 每个这样的不连续性意味着如果我们想要可以自由地重新排列成排序顺序的段，则需要一个新的段边界。 
4. 设该数为c。 这些是保留排序邻接性所需的最小段。 
5. 如果 c + 1 ≤ k，那么我们可以通过任意破坏现有分段来进一步拆分以达到恰好 k 个分段，因为额外的切割不会损害有效性。 
6. 否则，如果 c + 1 > k，我们无法创建足够的灵活性来重新排序为排序序列。 

该决策简化为检查 k 是否至少是由排序邻接引起的单调游程的数量。 

### 为什么它有效

 扫描识别最大连续块，其中元素以连续排序顺序出现。 在这样的块中，所有元素已经形成一条链，在任何有效的重新排序中都必须保持在一起，因为破坏它会强制排序邻接关系的反转，而这无法仅通过块排列来修复。 每次这条链条断裂时，我们都会引入强制削减。 任何有效的分割都必须尊重这些削减，任何额外的削减都是可选的细化。 因此，可实现的最小段数正是这些运行的次数，可行性相当于让 k 不小于该最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        b = sorted(a)
        pos = {v: i for i, v in enumerate(b)}
        
        cnt = 1
        for i in range(1, n):
            if pos[a[i]] != pos[a[i-1]] + 1:
                cnt += 1
        
        if cnt <= k:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序以确定每个元素的目标顺序。 字典`pos`按此排序顺序存储每个值的排名，将问题转换为从 0 到 n−1 的整数序列。 

变量`cnt`计算原始顺序中存在多少个单调排序的相邻段。 每当连续元素按排序顺序不连续时，就必须开始一个新段。 

最后，我们将这个最小所需段数与 k 进行比较。 如果 k 足够大，我们总是可以进一步分割以恰好达到 k 个段。 

一个常见的错误是认为我们必须直接形成恰好 k 个“好”片段。 正确的观点是，我们只需要保证最多k个段是结构上必要的即可； 额外的分裂总是可能的。

 ### 示例 1

 输入：```
5 4

```排序后的数组是`[1, 2, 3, 4, 6]`，位置将原始值映射到排名。 

| 我| 一个[我] | 位置[a[i]] | 连续的？ | 碳纳米管|

 我们得到 cnt = 4。由于 k = 4，条件成立，答案为“是”。 

这表明排序邻接中的每次中断都会强制生成一个新段，并且精确匹配 k 就足够了。 

### 示例 2

 输入：```
4 2
1 -4 0 -2
```排序后的数组是`[-4, -2, 0, 1]`。 

| 我| 一个[我] | 位置[a[i]] | 连续的？ | 碳纳米管|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 3 | - | 1 |
 | 1 | -4 | 0 | 没有| 2 |

 | 3 | -2 | 1 | 没有| 4 |

 这里 cnt = 4 但 k = 2，因此不可能将结构压缩为仅 2 个可重新排序的段。 

这表明，即使允许重新排序，但太多损坏的邻接会迫使太多独立块。

 ## 边缘情况

 对于 k = 1 的完全排序数组，算法正确输出 YES，因为不存在邻接中断并且 cnt 保持为 1，这与不需要重新排序的事实相匹配。 

对于 k = n，即使数组高度无序，cnt 也始终至多为 n，因此条件 cnt ≤ k 始终成立。 这反映出我们可以隔离每个元素并自由地重新排序单例段。 

对于在长时间连续运行中出现排序顺序的数组，cnt 变小，并且算法正确地识别出很少的段就足够了。 任何额外的 k 仅仅意味着我们可以进一步分割这些运行而不影响正确性，因为分割永远不会引入新的排序约束。
