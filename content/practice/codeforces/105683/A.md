 ## 解决方案
 ## 问题理解

 我们在一条线上得到了两个有序的目标点集合：一组严格位于原点的右侧，另一组严格位于原点的左侧。 机器人从位置 0 开始，必须访问两组中的每个点。 

机器人以单位速度移动，因此时间等于行进的距离。 不同之处在于访问的结构方式：每当机器人到达一侧的某个点时，就需要先返回原点，然后再到达另一侧的点。 每边访问点的顺序是任意的，我们也可以自由选择是从左侧开始还是从右侧开始。 

一个关键的微妙之处是，在最终访问点之后不需要返回原点，因此最后的移动可以在任何地方结束。 

输入给出两个长度为 n 的数组：右侧点距零的距离和左侧点距零的距离。 我们必须找到在交替约束下访问所有点所需的最小总时间。 

当 n 高达 100000 且距离高达 10^9 时，任何显式尝试所有排列或模拟调度选择的解决方案都会太慢。 即使 O(n^2) 也变得不可用，并且任何阶乘都会立即消失。 

主要困难在于访问点的顺序在每边内部并不重要，但交替约束通过重复返回零将两侧耦合起来。 

当一侧有许多小点而另一侧有一个非常大的点时，就会出现常见的故障情况。 总是去最近的下一个点的贪婪方法可能会因支付过高的回程费用而陷入困境。 

例如，如果右侧点为 [10]，左侧点为 [1, 2, 3]，则朴素贪婪策略可能会交替不佳并重复返回，而最佳解决方案会分组访问以最大程度地减少昂贵的长途旅行。 

另一种失败模式是忘记只有最后一段不需要归零。 许多错误的解决方案都会计算出额外的回报。 

## 方法

 暴力解释是考虑访问左点和右点的每种可能的顺序，同时尊重连续访问必须交替进行。 对于左点和右点的每个排序以及起始边的每次选择，我们模拟行进成本：到一个点的每次移动都会贡献其距离，并且边之间的每次切换都会强制返回到零，从而增加该段行进距离的两倍。 

这是正确的，因为它明确地探索了所有有效的调度，但交错的数量以组合方式增长。 即使固定内部顺序，每一步都有 2 个选择，导致 O(2^n) 模式，如果我们还考虑每边内部的排列，它就会变成阶乘。 这远远超出了任何可行的限度。 

关键的观察结果是，在每一方内部，访问顺序并不影响回程次数。 如果我们对每一侧的点进行排序，唯一有意义的决定是我们换边的次数，而不是我们使用哪种确切的排列。 

每次我们访问一侧的一个点时，我们都会支付其距离。 此外，每次我们换边时，我们都会产生等于刚刚访问点的距离的归零成本。 由于我们可以自由地对访问进行重新排序，因此我们希望构建顺序，以便最大限度地减少昂贵的回报。 

这将问题简化为在两个排序列表上确定最佳交替序列。 事实证明，最优结构对排序值是贪婪的：当选择一侧时，我们总是按距离降序处理每侧内的点，因为较大的距离应与较少的开关配对。

最后的简化是，最优策略相当于按降序合并两个排序列表并模拟交替行走，仔细考虑一侧何时用完。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 将两个数组按降序排序。 这确保了我们总是首先考虑每边最远的剩余点，从而避免了以后支付不必要的重复长途旅行。 
2. 维护两个指针，每个数组一个，代表该侧的下一个未访问点。 
3. 通过隐式评估两种可能性来决定起始方，但我们不是重复模拟，而是计算两种结果。 
4. 模拟贪心过程：在每一步，比较两侧下一个可用点，选择距离较大的一个。 这一选择确保我们在换边之前始终扩大当前的“昂贵范围”。 
5. 当移动到距离 d 的点时，将 d 添加到总成本中。 如果这不是第一次移动并且我们要换边，请添加一个额外的 d 来表示在到达新点之前返回到零。 
6. 继续，直到访问完所有点，确保最后的移动不会触发归零成本。 
7. 取两个可能的起始边的最小结果。 

### 为什么它有效

 成本的结构仅取决于每次返回之前访问的最大距离的顺序。 每当我们选择一个较小的点而另一侧保留较大的点时，我们都会冒着稍后在很远的距离处引入不必要的额外重置的风险。 通过始终优先考虑最远的可用点，我们确保每个归零事件都与局部最大段相关联，这是最优的，因为返回是不可逆的成本事件。 

这会产生单调结构：一旦跳过大距离，就只能在以后更差或相同的条件下使用。 因此，贪婪排序保留了长移动与最小重置的最佳配对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_once(R, L):
    R.sort(reverse=True)
    L.sort(reverse=True)

    i = j = 0
    cur_side = None
    ans = 0

    # pick first side based on larger starting point
    if i < len(R) and (j == len(L) or R[i] >= L[j]):
        cur_side = 0
    else:
        cur_side = 1

    first = True

    while i < len(R) or j < len(L):
        if cur_side == 0:
            d = R[i]
            i += 1
        else:
            d = L[j]
            j += 1

        ans += d

        if first:
            first = False
        else:
            ans += d  # return to origin before switching

        # switch side
        if i == len(R):
            cur_side = 1
        elif j == len(L):
            cur_side = 0
        else:
            if R[i] >= L[j]:
                cur_side = 0
            else:
                cur_side = 1

    return ans

def solve():
    n = int(input())
    R = list(map(int, input().split()))
    L = list(map(int, input().split()))

    # try both starting choices
    res1 = solve_once(R, L)
    res2 = solve_once(L, R)

    print(min(res1, res2))

if __name__ == "__main__":
    solve()
```该解决方案是围绕单个模拟例程构建的，该例程假设固定的起始侧。 两个数组按降序排序，以便每一侧的下一个候选始终是最大的剩余距离。 

指针逻辑确保我们永远不会重新访问元素。 这`first`标志至关重要：初始移动不需要返回到零，因此我们只在第一段之后开始添加往返惩罚。 

侧面切换逻辑是通过比较下一个可用元素来驱动的。 这是贪婪决策点，可确保较早处理大距离，防止它们被迫进入多个返回周期。 

最后，我们运行模拟两次，因为第一个选择的一方可以改变回报成本的结构。

 ## 边缘情况

 一种边缘情况是每侧只有一个点。 该算法从两个距离中较大的一个开始，并且由于可能只发生一次切换，也可能不会发生，因此它正确地避免了不必要的返回成本。 

例如，右[5]，左[10]。 该算法从左侧开始，取 10，不返回，然后转到 5，加上 5 + 5 作为切换成本，得到 20。任何替代的起始侧都会更糟，并且代码的第二次模拟涵盖了这两种选择。 

另一种边缘情况是一侧明显较大但有许多小点。 排序确保大点总是首先被消耗，因此它们不会因为早期的小动作而被迫陷入重复的返回循环。 

例如，右[100,1,1]，左[2]。 从正确的一侧开始可以防止大 100 被中间返回分割，并且贪婪比较确保它在较小的中断之前得到处理。
