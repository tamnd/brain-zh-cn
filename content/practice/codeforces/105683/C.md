 ## 解决方案
 ## 问题理解

 我们给定一个长度的字符串$n$，代表一张已经填满大写拉丁字母的海报。 任务是修改该字符串，使子字符串“NEIMARK”出现尽可能多的次数，同时平衡成本模型：更改任何字符都会花费 1 个单位的惩罚，而子字符串“NEIMARK”作为 7 个字符的连续块的每次出现都会给予 5 的奖励。 

关键细节是，出现次数是通过长度为 7 的固定子字符串进行计数的，这意味着每个位置$i$从$0$到$n-7$定义候选段。 如果我们决定将该段转换为“NEIMARK”，我们将获得 5，但我们必须支付当前子字符串和“NEIMARK”之间的汉明距离。 

最终得分是所有奖励减去所有修改成本的总和，并且我们可以自由地全局修改角色，这意味着所选事件之间的重叠通过共享角色进行交互。 这从根本上解决了选择一组长度为 7 的间隔并一致地分配字符以最大化净收益的问题。 

自从$n \le 2 \cdot 10^5$，任何涉及枚举子串子集的解决方案都是不可能的。 即使对所有子串对进行二次方法也会太慢。 该结构强烈建议对位置进行动态规划或最短路径公式，因为决策仅取决于固定长度的局部段。 

当重叠出现的选择不一致时，就会出现微妙的边缘情况。 例如，如果我们尝试同时从位置 0 和 1 开始形成“NEIMARK”，我们会强制进行矛盾的字符分配。 独立评估每个窗口的天真贪婪方法会高估奖励并低估修改冲突。 

## 方法

 一种强力方法是考虑放置“NEIMARK”的起始位置的每个子集。 对于每个子集，我们将尝试分配字符以满足所有选定的段并计算转换原始字符串的成本。 这很快就变得不可行，因为有$2^{n}$最坏情况下的子集。 

即使限制我们自己独立检查所有子字符串也会失败。 如果我们计算，对于每个位置$i$, 转换成本$s[i:i+7]$进入“NEIMARK”，然后贪婪地选择所有有利可图的，我们立即遇到不一致的情况。 两个重叠的盈利部分可能共享特征，修复一个部分可能会增加或减少另一个部分的成本。 

关键的观察是目标单词的长度固定为 7，因此任何有效的配置都可以视为从左到右移动，在每个位置决定是否开始一个单词或跳过它。 如果我们在位置开始一个单词$i$，然后位置$i+1$到$i+6$被该决定有效地消耗了。 这自然会导致对索引的动态规划。 

在每个位置$i$，我们比较两种可能性：跳过它并移至$i+1$，或将“NEIMARK”置于$i$，支付错配成本并跳转到$i+7$。 可以为每个起始位置预先计算失配成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 |$O(2^n)$|$O(n)$| 太慢了 |
 | 每个窗口贪婪 |$O(n)$|$O(n)$| 错误|
 | DP 超过头寸 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们定义一个动态规划数组，其中$dp[i]$是仅考虑到位置的前缀的最大可达到的分数$i$， 在哪里$i$是我们尚未处理的第一个索引。 

1.初始化一个大小为DP的数组$n+1$具有非常小的值，并设置$dp[0] = 0$。 这表示在处理任何字符之前，我们的得分为零。 
2. 预先计算每个起始位置的成本数组$i \le n-7$，我们计算之间有多少个字符不同$s[i:i+7]$和字符串“NEIMARK”。 如果我们决定放置一个从以下位置开始的单词，这会给出修改成本$i$。 
3. 从左到右迭代位置。 在每个位置$i$，通过设置传播跳过当前字符的选项$dp[i+1] = \max(dp[i+1], dp[i])$。 这模拟了不在位置开始单词的决定$i$。 
4. 如果$i \le n-7$，考虑将“NEIMARK”从$i$。 我们更新$dp[i+7] = \max(dp[i+7], dp[i] + 5 - cost[i])$。 这个转变同时捕获了 5 的奖励和角色变化的惩罚。 
5. 继续，直到处理完所有位置。 答案是$dp[n]$，它反映了整个字符串中可达到的最佳分数。 

关键点是每个转换都在索引中向前移动，因此不会以产生循环或不一致的方式重新访问任何状态。 

### 为什么它有效

 DP 保持不变式$dp[i]$是仅使用严格影响之前位置的决策可获得的最佳得分$i$。 “NEIMARK”出现的任何有效构造都可以分解为不相交的片段，这些片段要么从某个位置开始，要么被跳过。 由于每个放置恰好消耗 7 个连续字符，因此 DP 状态空间中的转换在时间上永远不会重叠。 这保证了任何全局最优排列恰好对应于 DP 图的一条路径，并且递归探索所有此类路径而不会重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    target = "NEIMARK"

    INF = -10**18
    dp = [INF] * (n + 1)
    dp[0] = 0

    cost = [0] * n

    for i in range(n - 6):
        c = 0
        for j in range(7):
            if s[i + j] != target[j]:
                c += 1
        cost[i] = c

    for i in range(n):
        if dp[i] == INF:
            continue

        if i + 1 <= n:
            dp[i + 1] = max(dp[i + 1], dp[i])

        if i <= n - 7:
            dp[i + 7] = max(dp[i + 7], dp[i] + 5 - cost[i])

    print(dp[n])

if __name__ == "__main__":
    solve()
```实现直接遵循DP。 成本计算显式地计算每个可能窗口的不匹配字符。 DP 循环小心地确保跳过前进一个位置，同时将单词前进七个位置，从而保留不重叠的结构。 

一个微妙的实现细节是，更新的应用方式必须不会覆盖同一迭代中同一索引的决策。 使用前向 DP 数组可以避免此问题，因为每个状态仅从较早的索引写入。

 ## 边缘情况

 一种重要的边缘情况是当字符串长度恰好为 7 时。该算法要么采用整个段，要么跳过它。 由于 DP 明确允许从 0 到 7 的单次转换，因此它可以正确评估全部成本与不执行任何操作。 

另一种情况是重叠的潜在匹配，例如“NEIMNEIMARK”之类的字符串。 贪婪方法可能会尝试从位置 0 和 2 开始，但 DP 会阻止这种情况，因为一旦选择了从 0 开始的段，状态就会跳转到索引 7 并跳过任何冲突的重叠。 

最后一个微妙的情况是失配率极高。 即使窗口在结构上相似，如果满足以下条件，DP 也会正确地避免它：$5 - cost[i]$是负面的，因为这样的转变会降低总分，并且永远不会被选择，除非它对更大的全球结构有利。
