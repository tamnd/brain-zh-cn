 ## 解决方案
 ## 问题理解

 我们给出了长度的排列$n$，这意味着从 1 到$n$只出现一次，但它们沿着位置线以任意顺序排列$1 \dots n$。 价值$a_i$告诉我们哪个标签位于该位置$i$，并且因为它是一种排列，所以每个标签恰好对应一个位置。 

现在假设我们必须按升序访问标签：首先是值 1 所在的位置，然后是值 2 所在的位置，依此类推，直到值$n$。 行程成本是连续访问位置之间的绝对差之和。 如果值的位置$x$是$p_x$，那么成本就是$|p_{x+1} - p_x|$。 

我们最多可以执行一项操作来交换两个标签的访问顺序。 同样，我们选择两个值$x$和$y$，并且按顺序$1,2,\dots,n$我们交换它们的位置，而所有其他值保持其自然顺序。 

任务是尽量减少由此产生的差旅成本。 

约束条件达到$n \le 5000$。 一个天真的$O(n^2)$或者$O(n^3)$解决方案是边界性的，但仍然可能可行，但是像重新计算每个交换候选者的完整路径之类的任何事情都会导致粗略的结果$O(n^3)$，这太慢了。 成本函数的结构是我们必须利用的。 

一些边缘情况很重要。 

如果排列已经排序，则意味着$a_i = i$，那么头寸已经按升序排列，并且成本恰好是$n-1$。 任何交换只会恶化或保留邻接结构，因此答案应该保留$n-1$。 粗心的解决方案可能仍然会尝试交换，并由于不处理未更改的结构而错误地降低成本。 

如果颠倒排列，所有位置都最大限度地分散，交换两个中心元素可以显着改变几个相邻的差异。 强力重新计算必须仅正确考虑局部变化； 否则它可能会过度计算未受影响的边缘。 

一个微妙的情况是，当交换的元素按值顺序相邻时，例如交换 5 和 6。成本变化是其邻居周围的局部变化，但仅调整两条边的简单重新计算可能会忽略交换后两个元素对不同邻接边都有贡献的事实。 

## 方法

 蛮力的想法很简单：计算初始成本，然后尝试每对值$(x,y)$，模拟按访问顺序交换它们，从头开始重新计算全部成本，并取最小值。 

从头开始计算成本需要$O(n)$，并且有$O(n^2)$交换、给予$O(n^3)$。 和$n = 5000$，这的顺序是$1.25 \times 10^{11}$操作，远远超出了限制。 

关键的观察是交换两个值只会影响这两个元素在位置序列中的位置$p_1, p_2, \dots, p_n$。 所有其他相邻差异保持不变。 因此，我们不需要重新计算整个总和，而只需重新计算涉及交换元素的边的贡献。 

对于任何值$x$，只有两条边将其包含在原始总和中：$|p_x - p_{x-1}|$和$|p_{x+1} - p_x|$。 交换后$x$和$y$，这四个边发生局部变化，而其他一切保持不变。 这将每次交换的评估减少到$O(1)$。 

我们还有$O(n^2)$交换，但现在每个都是恒定时间，这很合适。 

进一步的改进是我们不需要显式地构建新序列。 我们只操作位置数组并直接计算受影响的差异。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（重新计算每次交换的完整路径）|$O(n^3)$|$O(n)$| 太慢了|
 | 与本地增量更新交换 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先将排列转换为逆数组$p$， 在哪里$p[x]$是值的位置$x$。 这很重要，因为访问顺序是按值而不是按索引。 

1. 计算数组$p$这样我们就可以立即找到排列中的每个值。 这避免了重复扫描阵列。 
2. 通过求和计算基线成本$|p[i] - p[i-1]|$为所有人$i \ge 2$。 这代表任何交换之前的原始行驶距离。 
3. 使用该基线值初始化答案，因为允许执行零交换。 
4. 迭代所有值对$(x, y)$和$x < y$。 每对代表交换他们的访问顺序。 
5. 对于每一对，计算交换引起的成本变化$x$和$y$。 不要重建完整路径，而是删除涉及的旧贡献$x$和$y$，然后在交换位置后添加他们的新贡献。 

关键细节是值序列中的邻接性才是重要的，因此只有邻居$x-1, x+1, y-1, y+1$都参与其中。 我们小心地减去旧边缘并使用位置的绝对差添加新边缘。 

1. 用获得的最小值更新答案。 

### 为什么它有效

 成本函数是值排序中相邻对的总和。 交换仅更改两个值的位置，因此任何不涉及其中任何一个的项都保持相同。 由于总和是相加的并且边是独立的，因此正确性降低到正确更新那些受影响的项。 除了这些邻接关系之外不存在隐藏的依赖关系，因此仅跟踪本地贡献可以准确地保留总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # p[v] = position of value v
    p = [0] * (n + 1)
    for i, v in enumerate(a):
        p[v] = i

    def cost_at(i, j):
        return abs(p[i] - p[j])

    base = 0
    for i in range(2, n + 1):
        base += abs(p[i] - p[i - 1])

    ans = base

    for x in range(1, n + 1):
        for y in range(x + 1, n + 1):
            px, py = p[x], p[y]

            # remove old contributions around x and y
            old = 0
            if x > 1:
                old += abs(p[x] - p[x - 1])
            if x < n:
                old += abs(p[x] - p[x + 1])
            if y > 1:
                old += abs(p[y] - p[y - 1])
            if y < n:
                old += abs(p[y] - p[y + 1])

            # avoid double counting if adjacent in value
            if abs(x - y) == 1:
                # one edge counted twice in above, adjust carefully
                old = 0
                for i in range(2, n + 1):
                    old += abs(p[i] - p[i - 1])

            # swap positions
            p[x], p[y] = p[y], p[x]

            new = 0
            if x > 1:
                new += abs(p[x] - p[x - 1])
            if x < n:
                new += abs(p[x] - p[x + 1])
            if y > 1:
                new += abs(p[y] - p[y - 1])
            if y < n:
                new += abs(p[y] - p[y + 1])

            if abs(x - y) == 1:
                new = 0
                for i in range(2, n + 1):
                    new += abs(p[i] - p[i - 1])

            ans = min(ans, base - old + new)

            # revert swap
            p[x], p[y] = p[y], p[x]

    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于维护逆位置数组，以便每个值的位置都是 O(1)。 交换循环临时交换两个值的位置，计算邻接和中的增量，然后恢复数组。 

最微妙的部分是处理值空间中的邻接，当$x$和$y$相差 1。在这种情况下，本地贡献的朴素减法会重复计算共享边，因此使用完整的重新计算回退来确保正确性。

 ## 边缘情况

 一个关键的边缘情况是排列已经排序。 该算法正确计算基线成本为$n-1$，并且每次交换评估仅重新计算受影响的贡献，而不会产生错误的改进，因为邻接结构已经很小。 

另一种边缘情况发生在按值顺序交换相邻值时，例如交换$x$和$x+1$。 在这种情况下，两个值在成本定义中共享直接邻接关系，因此简单的局部减法有重复计算的风险。 该算法通过回退到该交换的完全重新计算来处理此问题，即使发生依赖项重叠也能确保正确性。 

最后一个微妙的情况是当交换的元素位于边界附近时，例如值 1 或值$n$。 在这些情况下，一个或两个邻接项都不存在。 实现显式检查边界$x>1, x<n$，因此它可以避免访问无效的邻居，同时仍然正确更新部分成本。
