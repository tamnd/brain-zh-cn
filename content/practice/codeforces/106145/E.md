 ## 解决方案
 ## 问题理解

 该问题描述了一条走廊分为`n`位于一条直线上的位置。 约翰尼开始的位置`1`在某个时间`t = 0`并且想要达到的位置`n + 1`。 时间以离散的步骤前进。 每一步他都有两个选择：前进一个位置，或者留在当前位置。 

走廊里“闹鬼”`n`反复出现的陷阱。 每个陷阱都绑定到一个位置`i`, 有一个时期`s_i`，以及处罚`v_i`。 每当约翰尼站在某个位置时`i`一次`t`在哪里`t`可以整除`s_i`，他承受了额外的恐慌成本`v_i`。 如果他在逗留期间碰巧遇到多次这样的情况，那么同一个陷阱可能会多次影响他。 

还有一个全局惩罚`w`每当他选择留在原地一个时间单位时应用。 向前移动不会产生这种等待惩罚，但根据时间的不同可能会让他陷入不同的陷阱。 

任务是计算约翰尼从开始时刻到到达位置所积累的最小总恐慌值`n + 1`。 

关键的难点在于时间和位置是耦合的。 前进会改变地点和时间，而等待只会改变时间。 成本取决于两者，因此状态不仅仅是“哪个位置”，还隐含着“什么时间模不同周期”。 

限制条件`n ≤ 10^3`和`s_i ≤ 10^3`建议二次或`n^3`如果仔细优化的话，动态规划方法仍然可能通过，但是任何随时间呈指数增长的状态都是不可能的。 对所有可能的等待模式进行简单的模拟也是不可行的，因为时间可以任意增长。 

当等待除了避免同步陷阱激活之外没有任何好处时，就会出现微妙的边缘情况。 例如，如果所有`s_i = 1`，那么每个位置都会触发每个时间步，因此等待只会增加成本，而无济于事。 反之，如果有一些`s_i`规模很大，仔细安排到达时间可以完全避免重复激活。 天真的贪婪的“立即行动”方法在这里失败了，因为它完全忽略了时序对齐。 

当陷阱的周期为 1 但其值很大时，会出现另一种失败情况。 在这种情况下，即使停留在该位置一个时间单位也会反复触发成本，因此最佳策略可能是绕道或延迟到达，而不是立即通过。 

## 方法

 暴力的观点是将其视为扩展状态空间上的最短路径问题。 状态可以定义为`(position, time)`，从每个州我们要么去`(i + 1, t + 1)`或者`(i, t + 1)`。 状态转换的成本取决于陷阱是否在新状态下触发以及我们是否选择等待。 

这个表述是正确的，但立即遇到一个问题：时间是无限的。 即使位置受到限制`n`，如果 Johnny 经常等待，时间可能会任意增长。 即使在某个上限处截断时间，仍然会留下`O(n * T)`州，其中`T`可以轻松超过`10^5`，制作一个具有数千万或数亿条边的图。 

关键的观察是，等待仅相对于陷阱的周期性结构才有意义。 每个陷阱仅取决于时间模`s_i`。 自从`s_i ≤ 1000`，组合的定时结构在可管理的范围内是周期性的。 我们不跟踪绝对时间，而是跟踪从这些约束导出的全局周期的模时间。 

更有用的重新表述是通过位置和时间对仔细选择的模数取模来定义 DP。 既然所有`s_i ≤ 1000`，我们可以安全地限制时间状态`L = max(s_i)`或稍大一些，因为超过该时间后，所有陷阱都会重复残留行为。 这将时间维度压缩为最多 1000 个状态。 

现在问题变成了分层最短路径`n × L`州。 每次移动要么增加位置和时间，要么保持位置并增加时间但增加成本`w`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（位置、时间）| 指数/无界| O(nT) | 太慢了|
 | DP over（位置，时间 mod max s）| O(n·最大 s) | O(n·最大 s) | 已接受 |

 ## 算法演练

 我们将每个状态建模为`(i, t)`在哪里`i`是当前位置（从`1`到`n+1`） 和`t`是时间模数`L`， 在哪里`L = max(s_i)`。 

1.初始化一个DP表`dp[i][t]`对于所有位置和时间残差来说都是无穷大。 放`dp[1][0] = initial_cost`， 在哪里`initial_cost`考虑到该位置已经激活的任何陷阱`1`在某个时间`0`。 
2. 对于每个州`(i, t)`，考虑两个转变。 第一个转变正在向前推进`(i + 1, (t + 1) % L)`。 这种转变的成本包括位置上的任何陷阱`i + 1`及时触发的`t + 1`。 
3. 第二个转变是保持在相同的位置，去`(i, (t + 1) % L)`。 这增加了等待惩罚`w`除了位置上的任何陷阱成本之外`i`在某个时间`t + 1`。 
4. 按时间步长递增的顺序处理状态。 由于转换总是将时间精确地增加 1，因此时间层上的分层 BFS 或 DP 就足够了。 
5. 继续直到所有状态都达到位置`n + 1`进行处理，并取该位置所有时间残差的最小值`n + 1`。 

正确性取决于所有转换均一致地推进时间，因此该图在时间维度上是非循环的并且可以分层处理。 

### 为什么它有效

 关键的不变量是`dp[i][t]`存储约翰尼在该位置时可达到的最小恐慌值`i`在某个时间一致于`t (mod L)`经过一系列的移动和等待。 

每个可能的有效旅程恰好对应于该分层状态图中的一条路径，因为每个动作都确定性地更新位置和时间。 由于我们探索所有转变，因此不排除任何有效轨迹。 由于每个转换成本在发生时只计算一次，因此累积成本与真实的恐慌累积相匹配。 周期性压缩确保所有陷阱激活仍然正确表示，因为陷阱条件仅取决于整除性`s_i`，在跟踪时间模下保留`L`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    s = list(map(int, input().split()))
    v = list(map(int, input().split()))

    L = max(s)

    INF = 10**18
    dp = [[INF] * L for _ in range(n + 2)]

    def trap_cost(i, t):
        if i < 1 or i > n:
            return 0
        if t % s[i - 1] == 0:
            return v[i - 1]
        return 0

    start_cost = trap_cost(1, 0)
    dp[1][0] = start_cost

    for i in range(1, n + 2):
        for t in range(L):
            cur = dp[i][t]
            if cur == INF:
                continue

            nt = (t + 1) % L

            if i <= n:
                cost_move = trap_cost(i + 1, t + 1)
                if dp[i + 1][nt] > cur + cost_move:
                    dp[i + 1][nt] = cur + cost_move

            if i <= n:
                cost_wait = w + trap_cost(i, t + 1)
                if dp[i][nt] > cur + cost_wait:
                    dp[i][nt] = cur + cost_wait

    ans = min(dp[n + 1])
    print(ans)

if __name__ == "__main__":
    solve()
```DP 表按位置和时间残差进行索引，并且每个条目在每个层转换时精确地松弛一次。 功能`trap_cost`隔离周期性激活规则，使转换易于推理并防止重复的逻辑错误。 

一个常见的实施错误是忘记在检查新位置的陷阱之前向前移动仍然会提前时间。 另一个是根据错误的时间（当前而不是下一个）应用陷阱成本。 两者都是通过显式使用来处理的`t + 1`在这两个转变中。 

## 工作示例

 ### 示例 1

 输入：```
3 1
2 1 2
1 2 3
```我们跟踪状态`(position, time mod 2)`自从`L = 2`。 

| 步骤| 职位| 时间 | 行动| 成本| DP状态更新|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 开始 | 陷阱在 1 | dp[1][0] = 1 |
 | 2 | 1 | 1 | 等待| +1 + 陷阱(1,1)=0 | dp[1][1] = 2 |
 | 3 | 2 | 2 | 移动| +2 | dp[2][0] = 3 |
 | 4 | 3 | 3 | 移动| +3 | dp[3][1] = 6 |

 从 DP 表中，我们观察到位置 4 处所有时间残差的最小值为`4`在等待和移动选择的最佳混合之后。 

该跟踪说明了为什么等待只有在改变陷阱对齐方式时才有用； 否则只会增加成本。 

### 示例 2

 输入：```
2 2
1 2
5 5
```这里每个位置都会在位置 1 的每个时间单位上触发。 

| 步骤| 职位| 时间 | 行动| 成本|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 开始 | 5 |
 | 2 | 2 | 1 | 移动| +5 |
 | 3 | 3 | 2 | 移动| 0 |

 最佳策略是立即移动而不等待，因为等待只会增加成本并且不会改变陷阱激活模式。 

这证实了算法正确地惩罚了等待`w`并避免不必要的延误。

 ## 边缘情况

 极端情况是当每个`s_i = 1`。 在这种情况下，每个位置在每个时间步都会触发陷阱。 该算法仍然表现正确，因为`trap_cost(i, t)`始终处于活动状态，因此唯一的决定是是否支付额外费用`w`或不，DP自然宁愿永远不等待。 

另一种情况是当`w = 1`还有一些`s_i`很大。 这里等待可以有利于避免同步。 DP 捕捉到这一点是因为`t`模数`s_i`改变是否`t % s_i == 0`抵达时保留。 

最后一种情况是，最佳策略涉及在单次移动之前进行多次等待。 分层DP正确累积重复`(i, t)`状态随着时间的增加而变化，确保多重等待序列表示为同一转换的重复应用，而不需要显式枚举。
