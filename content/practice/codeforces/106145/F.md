 ## 解决方案
 ## 问题理解

 该问题给出了两个字符串，仅由`L`和`R`。 第一根弦描述了击鼓的实际顺序。 每次点击都会在录制的声音中创建一个可见字符或两个相同的可见字符。 第二根弦是我们听到的录音。 我们需要决定第一个字符串中的每个命中是否可以扩展为同一字符的一个或两个副本以形成第二个字符串。 

例如，命中序列`LR`可以成为`LR`,`LLR`,`LRR`， 或者`LLRR`。 每个原始字符的扩展都是独立的，因此唯一允许的更改是每个字符可以重复一次。 

这些限制使得对每种可能的扩展的直接模拟变得不可能。 如果一个字符串有长度`n`，每个角色都有两个选择，因此尝试所有可能的录音需要检查`2^n`的可能性。 即使对于几十个字符，这也是不可行的。 预期的解决方案必须处理每个字符恒定的次数，给出`O(n)`算法。 

棘手的部分不是大字符串，而是相等字符组之间的边界。 一个常见的错误是只检查两个字符串是否具有相同的压缩形式。 仅压缩是不够的，因为组的长度很重要。 

例如：```
Input:
p = "L"
s = "LLL"
```正确的输出是：```
NO
```粗心的解决方案可能会发现两个字符串都只包含`L`并接受它们。 然而，一首原创歌曲最多只能产生两首`L`字符，所以三个字符是不可能的。 

另一个边缘情况是组的顺序发生变化时：```
Input:
p = "LR"
s = "LLL"
```正确的输出是：```
NO
```第二个字符串只有一组`L`，而原始序列有两个不同的命中。 失踪者`R`不能通过扩展来创建`L`。 

最后的边界情况是记录的字符串较短时：```
Input:
p = "LL"
s = "L"
```正确的输出是：```
NO
```每个原始字符必须至少贡献一个字符，因此两次命中不能消失在一个记录字符中。 

## 方法

 蛮力方法会尝试一切可能的方法来扩展第一个字符串。 对于每个字符，我们选择是保留一个字符还是变成两个副本，然后将生成的结果与录音进行比较。 这是正确的，因为它检查了对命中的所有可能的解释。 问题是一个长度的字符串`n`有`2^n`可能的扩张，很快就会变得太大。 

有用的观察结果是，原始字符串中的每个字符对应于记录中相同字符的连续块。 一个`L`只能创建`L`字符，并且它必须创建其中的一个或两个。 这同样适用于`R`。 

这意味着我们不需要构造可能的扩展字符串。 我们只需要遍历两个字符串并比较匹配组。 如果原字符串有一组`k`相同的字符，记录的字符串必须有一组长度相同的字符`k`和`2k`。 在这个问题中，由于原始字符串的每个字符都是单独的命中，因此直接计算每个原始组的长度。 这减少了比较游程长度的问题。 

蛮力之所以有效，是因为每个有效的扩展都遵循命中规则，但会失败，因为它探索可以在本地检查的选择。 观察到每次命中仅影响其自己的连续块，这让我们可以用线性扫描代替指数探索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 在原始字符串和录制字符串的开头设置两个指针。 指针代表下一个未处理的敲击和声音。 
2. 对于原字符串中的当前字符，统计它有多少个连续的相等字符。 对录制字符串中的相应组执行相同的操作。 这些组必须以相同的字符开始，因为命中不能从`L`到`R`或者反之亦然。 
3. 检查两个组长度之间的关系。 录制的组长度必须至少是原始组长度，因为每次击中都会产生一个声音，并且它最多必须是原始组长度的两倍，因为每次击中最多可以产生两个声音。 
4. 将两个指针移至下一组并重复，直到其中一个字符串用完。 
5. 扫描完成后，仅当两个字符串都已完全消耗时才接受。 任何剩余的字符都意味着一个字符串包含不匹配的命中或声音。 

为什么它有效：

 原始字符串中每个最大的相同字符块代表同一鼓上的连续敲击序列。 这些命中不能与录音中的其他字符混合，因此它们必须恰好对应于录制字符串中的一个块。 唯一可能的区别是该块的长度，因为每次命中都会贡献一个或两个字符。 该算法精确地检查每个块的这个条件，因此它准确地接受有效的记录。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        p = input().strip()
        s = input().strip()

        i = 0
        j = 0
        ok = True

        while i < len(p) and j < len(s):
            if p[i] != s[j]:
                ok = False
                break

            pi = i
            while i < len(p) and p[i] == p[pi]:
                i += 1

            sj = j
            while j < len(s) and s[j] == s[sj]:
                j += 1

            p_len = i - pi
            s_len = j - sj

            if s_len < p_len or s_len > 2 * p_len:
                ok = False
                break

        if i != len(p) or j != len(s):
            ok = False

        ans.append("YES" if ok else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```主循环保留两个索引，每个索引对应一个字符串。 它永远不会向后移动，这就是为什么总工作是线性的。 

内部循环查找当前块的末尾。 他们完成后，`p_len`是产生该块的命中数`s_len`是录音中的声音数量。 唯一有效的范围是从`p_len`到`2 * p_len`。 

最终比较`i`和`j`之所以需要，是因为主循环可以在一根字符串结束后停止。 如果没有此检查，实现可能会错误地接受前缀匹配，同时忽略额外的字符。 

Python 整数在这里不是问题，因为该算法仅存储长度和索引。 最大值受输入大小限制。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 两个字符串中的每个字符都会被访问一次。 |
 | 空间| O(1) | O(1) | 仅存储指针、计数器和答案状态。 |

 所有字符串的总长度通过单遍处理。 这很容易符合典型的竞争性编程限制，因为该算法仅对每个字符执行恒定的工作。

 ## 边缘情况

 对于这个案例：```
p = "L"
s = "LLL"
```该算法比较唯一的组。 原始群长度为`1`记录的组长度为`3`。 自从`3`大于`2 * 1`，条件不成立，答案为`NO`。 

对于这个案例：```
p = "LR"
s = "LLL"
```第一组对比看到`L`反对`LLL`。 记录组有长度`3`，这已经超过了一次命中的最大可能扩展。 算法停止而不尝试匹配剩余的`R`，正确返回`NO`。 

对于这个案例：```
p = "LL"
s = "L"
```原始组需要两个声音，因为有两个命中。 记录组仅包含一个字符，因此其长度小于所需的最小长度。 该算法拒绝输入。 

对于这个案例：```
p = "LLLL"
s = "LLLLLLLL"
```该算法将整个字符串视为一组。 原始群长度为`4`记录的组长度为`8`，这正是最大允许值。 输入被接受。
