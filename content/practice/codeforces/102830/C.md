 ## 解决方案
 ## 问题理解

 凯文用他自己的一个反应启动了一条模因反应链。 每天晚上，当前的反应数量都会自动加倍。 他还可以在任何早晨自己添加反应，这些手动反应会立即发生。 目标是准确达到`n`反应，同时执行尽可能少的手动反应，计算启动链的第一个反应。 

输入是单个整数`n`，代表所需反应的最终数量。 输出是 Kevin 必须做出的最少手动反应。 

极限允许`n`一样大`10^9`。 这排除了依赖于天数或尝试许多可能的时间表的模拟。 解决方案应该在恒定时间或最多对数时间内工作，因为`10^9`只有大约 30 位二进制数字。 

关键的困难是认识到手动反应并不总是在最终计数中只贡献一个反应。 如果凯文反应早，反应会加倍很多倍。 如果他反应晚一些，次数就会少一倍。 每个手动反应都可以被视为选择对最终总数有贡献的二的一个幂。 

一些边缘情况暴露了实现中的错误。 

为了`n = 1`，答案是`1`。 凯文必须做出第一反应，不这样做就不可能获得第一反应。 

对于输入：```
8
```正确的输出是：```
1
```粗心的方法可能会认为凯文需要几个反应，因为数量会在多天内增长，但第一个反应就变成了`2`,`4`， 进而`8`。 

对于输入：```
5
```正确的输出是：```
2
```一种反应可以发展成`4`，然后再创建一个手动反应`5`。 尝试计算天数而不是手动操作会给出错误的数量。 

## 方法

 直接的暴力方法可以模拟该过程。 我们可以从一个反应开始，每天重复将计数加倍，并尝试在不同时刻添加反应，直到达到`n`。 这是有效的，因为可以通过决定每个手动反应发生的时间来描述每个可能的时间表。 

问题在于，这探索了大量可能的时间表。 对于设置了多个位的数字，何时添加反应可以有多种选择。 搜索空间呈指数级增长，尽管`n`它本身只有大约 30 位。 这是不必要的，因为加倍过程具有简单的数学结构。 

有用的观察是，每个手动反应都会为最终答案贡献 2 的幂。 一开始的反应有助于`2^k`后`k`夜晚。 一天后做出的反应有贡献`2^(k-1)`， 等等。 最终的数字正是凯文反应时刻对应的2的幂之和。 

数字的二进制表示是将其写为 2 的幂和的独特方式。 由于每个设置位都意味着需要一个手动反应，因此答案很简单：`1`二进制表示中的位`n`。 

暴力破解之所以有效，是因为每个调度都对应于 2 的有效幂和，但会失败，因为它会搜索二进制表示已经直接描述的调度。 对设置位进行计数可以消除整个搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 可能的反应时间数量呈指数增长 | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取目标反应数`n`。 

的价值`n`包含所需的所有信息，因为反应的时间仅影响两个的幂相加。 
2.看二进制表示`n`。 

每个二进制数字表示最终和中是否需要特定的 2 的幂。 一个数字等于`1`意味着凯文需要一个手动反应作为该贡献而幸存下来。 
3. 计算有多少个二进制位等于`1`。 

该计数是手动反应的最小数量，因为二进制表示使用尽可能少的二的幂来创建数字。 
4. 输出计数。 

该计数包括初始反应，因为最低二进制位对应于任何倍增之前进行的反应。 

为什么它有效：

 每个手动反应的最终贡献恰好是二的一次方。 如果凯文在某个时刻做出反应并且有`k`剩下的夜晚，这种反应有助于`2^k`最后的反应。 因此，任何有效的策略都是两个幂的集合，其总和为`n`。 二进制表示给出了唯一的分解`n`成 2 的幂，并且使用每个设置位一次可以最大限度地减少项数。 设置位数恰好是手动反应的最小数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    print(n.bit_count())

if __name__ == "__main__":
    solve()
```该解决方案使用Python的内置`bit_count()`方法来计算整数表示中设置的位数。 这直接符合算法的数学观察。 

输入仅包含一个整数，因此对于性能而言，快速输入并不是必需的，但使用了标准的竞争性编程输入样式。 输出是所需手动反应的数量。 

不存在边界问题，因为`bit_count()`直接处理所有正整数。 最小的输入，`1`，产生一组位。 最大允许输入，`10^9`，仍然很容易适合 Python 的整数类型，并且只有很少的位数。

def solve(inp: str) -> str:

 ## 边缘情况

 对于`n = 1`:```
1
```二进制表示是`1`。 该算法计算一组位并输出`1`。 这与过程相匹配，因为凯文必须自己做出第一反应。 

为了`n = 8`:```
8
```二进制表示是`1000`。 该算法仅看到一组位并输出`1`。 单个初始反应加倍三倍，恰好产生八个反应，无需任何额外的手动操作。 

为了`n = 5`:```
5
```二进制表示是`101`。 该算法计算两个设置位并输出`2`。 这些对应于以下贡献`4`和`1`，匹配一个时间表，其中一个反应提前发生，一个反应稍后添加。 

对于设置了每个低位的值，例如：```
1023
```二进制表示是`1111111111`。 算法输出`10`。 2 的 10 次方中的每一个都是必需的，没有任何策略可以使用更少的手动反应，因为每个手动操作仅贡献 2 的 1 次方。
