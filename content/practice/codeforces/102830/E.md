 ## 解决方案
 ## 问题理解

 凯文有几种类型的炸玉米饼可供选择。 每种类型都有正常的购买价格，并且玉米卷类型之间也存在单向交换。 通过交换，他可以通过支付额外费用将一种类型的炸玉米饼变成另一种类型的炸玉米饼。 每次交换可以执行任意次数。 

输入描述了炸玉米饼类型的数量、购买每种类型的一份炸玉米饼的直接价格、所有可能的交换，以及最后凯文想要多少每种类型的炸玉米饼。 目标是找到完成所要求的炸玉米饼分配所需的最低金额。 

核心问题不是购买炸玉米饼后如何进行兑换。 相反，它是每种最终玉米卷类型的生产成本。 炸玉米饼类型`i`可以直接购买，也可以通过购买另一种类型并进行一系列交换来获得。 一旦知道了每种类型的最便宜的生产成本，每个请求的炸玉米饼就可以独立处理。 

这些约束强烈建议采用图形解决方案。 最多可以有 10,000 个 taco 类型和 100,000 个交换。 检查每个目的地的每个可能的起始 taco 的方法仅用于图形处理就需要大约 10^8 或更多操作，并且重复探索路径会太慢。 我们需要一种有效处理稀疏图的最短路径算法。 边缘权重是非负的，因此 Dijkstra 算法是合适的。 

在一些边缘情况下，粗心的实施可能会失败。 第一种情况是，炸玉米饼只能通过多次交换才能获得。 例如：```
Input

10

100

1 2 4

```正确的输出是：```
17
```购买0型并使两次交换成本`10 + 3 + 4 = 17`。 仅考虑直接购买的解决方案将错误地回答`100`。 

另一个棘手的情况是，交换比直接购买源炸玉米饼便宜，但交换路径从不同类型开始。 例如：```
Input
2 1
100
5
1 0 2
0
1
```正确的输出是：```
5
```Type 1 已经足够便宜，并且不需要转换。 假设每个炸玉米饼必须使用至少一个交换的解决方案可能会产生更大的成本。 

最后一个常见的错误是忽略了许多炸玉米饼类型可能共享相同的最便宜的来源。 例如：```

3 2
1
50

0 1 1

```正确的输出是：```

```每个炸玉米饼都可以用 0 型制成。答案是`3 * 1 + 3 * 2 + 3 * 3 = 18`？ 等等，本例中请求的计数都是三个，所以实际输出是：```
18
```仅计算一个最佳转换目标或贪婪地分配源而不独立考虑每个目标的解决方案将会失败。 

## 方法

 蛮力方法是将每种炸玉米饼类型视为可能的起点，然后从该类型运行最短路径搜索以确定它可以生成哪些其他炸玉米饼类型。 之后，我们可以将购买起始炸玉米饼并将其转换为每个目的地的当前最佳答案的成本进行比较。 

这种方法是正确的，因为考虑了所有可能的炸玉米饼来源。 如果创建炸玉米饼类型的最便宜方法从购买炸玉米饼开始`s`，从运行`s`就会发现相应的交换路径。 

问题在于重复工作量。 运行 Dijkstra 一次需要花费`O((t + e) log t)`。 从每种炸玉米饼类型运行它的成本`O(t(t + e) log t)`。 10,000 种 taco 类型和 100,000 次交换，这远远超出了时间限制。 

关键的观察结果是，所有类型的炸玉米饼都在问同一个问题：“我能找到的最便宜的来源是什么？” 我们可以反转观点，而不是分别从每个源运行最短路径。 想象一下，创建一个与每种 taco 类型距离为零的虚拟源，但在运行 Dijkstra 之前，我们用其直接购买成本初始化每种 taco 类型的距离。 然后，多源 Dijkstra 将通过交换图分散这些初始成本。 

当 Dijkstra 放松类型交换时`i`键入`j`，它检查是否获得`i`便宜且支付兑换费比目前的获取方式更好`j`。 这与原始问题完全匹配，因为每个可能的起始购买都已经存在于初始距离中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(t(t + e) log t) | O(t(t + e) log t) | O(t + e) | 太慢了 |
 | 最佳 | O((t + e) log t) | O(t + e) | 已接受 |

 ## 算法演练

 1. 阅读 taco 类型、直接购买价格、兑换和所需数量。 将每个交换存储为有向图边，因为交换来自类型`i`键入`j`并不意味着反向交换存在。 
2. 用其直接购买价格初始化每种 taco 类型的最短距离。 这代表了无需使用任何交易所即可立即购买炸玉米饼的可能性。 
3. 将每个 taco 类型及其当前距离插入优先级队列。 这会同时从所有可能的来源启动 Dijkstra。 
4. 反复删除已知成本最小的 taco 类型。 对于每次出站兑换，首先获取当前的taco类型，然后支付兑换费用，计算到达目的地的成本。 如果该值较小，则更新目的地并将新值推入优先级队列。 
5. 最短路径过程完成后，将每种炸玉米饼类型的最便宜成本乘以该类型所需的炸玉米饼数量。 将这些值加在一起即可得到最低总价。 

这样做的原因是，获得炸玉米饼的每一种有效方法都包括选择一些起始炸玉米饼来购买，然后遵循交换路径。 初始距离代表所有可能的起始购买，每次放松都代表延长其中一条路径。 Dijkstra 始终保留到达每个节点的最便宜的已知路径，因为所有交换成本都是非负的。 当算法完成时，每种 taco 类型的距离恰好是创建该类型的 taco 的最便宜的可能成本。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t, e = map(int, input().split())

    dist = []
    for _ in range(t):
        dist.append(int(input()))

    graph = [[] for _ in range(t)]

    for _ in range(e):
        i, j, p = map(int, input().split())
        graph[i].append((j, p))

    need = []
    for _ in range(t):
        need.append(int(input()))

    pq = []
    for i, cost in enumerate(dist):
        heapq.heappush(pq, (cost, i))

    while pq:
        cost, node = heapq.heappop(pq)

        if cost != dist[node]:
            continue

        for nxt, price in graph[node]:
            new_cost = cost + price
            if new_cost < dist[nxt]:
                dist[nxt] = new_cost
                heapq.heappush(pq, (new_cost, nxt))

    answer = 0
    for i in range(t):
        answer += dist[i] * need[i]

    print(answer)

if __name__ == "__main__":
    solve()
```这`dist`数组以直接的炸玉米饼价格开始，而不是无穷大。 这是将普通 Dijkstra 转变为多源 Dijkstra 的主要实现细节。 

优先级队列在开始时包含每种 taco 类型。 当找到更便宜的路径时，旧队列条目不会被删除。 相反，会插入一个新条目，并且`if cost != dist[node]`检查会跳过过时的条目。 这是在 Python 中高效实现 Dijkstra 的标准方法。 

该图是有向的，因为交换仅在指定方向上进行。 将其视为无向会错误地允许不可能的转换。 

最终的乘法是安全的，因为 taco 类型的数量和值非常适合 Python 整数。 Python 整数不会溢出，因此代码不需要对大和进行特殊处理。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O((t + e) log t) | 每种taco类型可以多次进入优先级队列，并且在Dijkstra期间每次交换都比较宽松。 |
 | 空间| O(t + e) | 图表存储每次交换，数组存储每种 taco 类型的一个值。 |

 拥有 10,000 种 taco 类型和 100,000 种交换，这种复杂性很容易达到极限。 该算法执行一次图遍历，而不是从每个可能的起始炸玉米饼重复最短路径计算。

        graph[i].append((j, p))

 ## 边缘情况

 当一个 taco 需要经过多次交换才能到达时，算法自然会通过重复的松弛来处理它。 在价格为 10、100、100 和交易所的示例中`0 -> 1`成本 3 和`1 -> 2`花费 4，Dijkstra 从距离开始`[10, 100, 100]`。 它首先将类型 1 改进为 13，然后将类型 2 改进为 17。最终答案使用 17，因为最便宜的路径包含两个交换。 

当炸玉米饼已经是最便宜的可能来源时，算法会保持其初始距离。 对于价格为 100 和 5 的输入以及从类型 1 到类型 0 的交换，初始距离为`[100, 5]`。 处理类型 1 尝试将类型 0 改进到类型 7，但这仅影响类型 0。所请求的类型 1 炸玉米饼每个仍花费 5。 

当许多 taco 类型共享相同的最便宜源时，每个目的地都会收到自己的最短路径值。 对于类型 0 的交换链，距离值一次向外扩展一个边缘。 最终乘以请求的计数，然后正确地组合这些独立的最小成本。
