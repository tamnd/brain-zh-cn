 ## 解决方案
 ## 问题理解

 我们得到一个无向图，其中顶点 0 是安全团队的起点，顶点 N − 1 是包含关键目标的目标位置。 团队希望尽快从 0 到 N − 1，其中每条边的遍历通常需要一个单位时间。 

在旅程开始之前，我们最多可以选择 K 个顶点来“阻挡”。 进入被阻挡的顶点会为该顶点访问增加一个额外的时间单位。 守卫完全知道哪些顶点受到阻碍，因此将始终在这些修改后的顶点成本下选择最短的可能路径。 

任务是选择被遮挡的顶点，使得该修改图中从 0 到 N − 1 的最短路径距离变得尽可能大。 

该图的 N 量很小，最多 100 个顶点，但由于 M 可以接近 N²，因此可能很稠密。 这强烈表明 O(N3) 甚至 O(N2 log N) 解决方案是可接受的，而子集或路径上的任何指数解决方案则不可接受。 

一个关键的微妙之处在于，我们不是选择一条路径，而是修改图形，以便影响每条可能的路径，然后对手选择剩余的最佳路径。 这排除了仅在单个最短路径上的贪婪推理。 

一个常见的失败案例来自于尝试仅阻碍原始最短路径上的顶点。 这还不够，因为增加一条路径可能只是将最佳路由转移到另一条路径。 

例如，假设从 0 到 N − 1 有两条不相交的最短路径。仅在一条路径上阻塞顶点会使另一条路径保持不变，因此即使直觉表明我们正在“延迟进度”，答案也不会增加。 

正确的解决方案必须在全局意义上推理距离，而不仅仅是单个路径。 

## 方法

 蛮力的想法是尝试所有大小最大为 K 的顶点子集，将它们标记为阻塞，并每次重新计算从 0 到 N − 1 的最短路径。 每个最短路径计算都可以使用 BFS 完成，因为所有基边的权重均为 1，但顶点惩罚会破坏纯 BFS 结构，除非我们对状态进行编码。 即使我们简化，枚举子集的成本也已经是 O(2^N)，并且重新计算每个子集的最短路径使其完全不可行。 

瓶颈在于障碍集以非线性方式直接改变最短路径结构，因此朴素枚举会爆炸。 

关键的见解是将顶点阻塞重新解释为图的变换。 每个顶点 v 的成本可以为 1（正常）或 2（如果选择）。 这表明我们要考虑扩展状态空间上的最短路径问题，我们跟踪到目前为止已使用了多少障碍物。 

一旦我们这样做了，问题就变成了分层图上的最短路径：状态是（node，k_used），并且转换消耗 0 或 1 个阻塞，具体取决于我们是否选择将 v 作为阻塞输入。 然而，我们并没有预先在状态空间中选择一个固定的子集； 相反，我们正在寻找沿路径最多 K 个障碍物的最佳可能分配，以在对抗性路由下最大化最短路径距离。 

这自然成为一个极小极大问题：我们选择权重（通过放置障碍物），而对手选择最短路径。 处理这种类型的“修改最多 K 个节点以最大化最短路径”的标准方法是，对于每个可能使用的障碍物数量，计算到每个节点的最佳可实现距离。

我们在层上维护一个距离数组，其中每一层代表我们在通往该节点的路径上使用了多少障碍物。 每个转换要么在不花费一个障碍的情况下移动到邻居，要么在花费一个障碍并为正在进入的节点增加额外成本的情况下移动。 在这个分层状态空间上运行类似 Dijkstra 的松弛可以得到最佳结果。 

该结构本质上是具有扩展状态的图中的最短路径，其中边缘成本取决于我们是否已经使用了障碍预算。 这将组合选择问题简化为确定性最短路径计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(2^N·N²) | O(2^N·N²) | O(N²) | 太慢了|
 | 分层最短路径（K 状态）| O(K·M log (K·N)) | O(K·M log (K·N)) | O(K·N) | 已接受 |

 ## 算法演练

 我们将问题转换为扩展状态图上的最短路径，其中每个状态表示位于一个顶点并使用了一定数量的障碍物。 

1. 构造一个状态定义，其中状态为 (v, c)，这意味着我们目前处于顶点 v 并使用了 c 个障碍物。 这捕获了所有相关历史，因为只有障碍物的数量对未来的选择重要，而不是它们的位置。 
2. 将除 (0, 0) 之外的所有距离初始化为无穷大，该距离设置为 0。我们从没有使用任何障碍物的入口处开始。 
3. 使用优先级队列在状态上运行 Dijkstra。 每次我们提取最小距离状态 (v, c) 时，我们都会尝试放松所有邻居 u。 
4. 当从 v 移动到 u 时，考虑两种可能性。 如果我们不阻碍 u，我们将以成本 +1 移动并留在 c 层。 如果我们确实阻碍了 u 并且 c < K，则我们以成本 +2 移动并将层数增加到 c + 1。我们在 u 处添加成本的原因是阻碍会影响顶点遍历时间，因此在进入 u 时适用。 
5. 每当我们为状态 (u, c) 或 (u, c + 1) 找到更好的距离时，我们就把它推入优先级队列。 
6. 处理完所有状态后，答案是 c 从 0 到 K 的所有状态 (N − 1, c) 之间的最小距离，因为我们最多允许使用 K 个障碍物。 

正确性取决于以下事实：每个可能的有效障碍配置对应于该扩展状态图中的某个路径，并且该状态图中的每个路径对应于有效的障碍配置。 Dijkstra 保证了所有此类配置之间的最佳距离，因为所有边权重都是非负的，并且所有选择都在转换中显式编码。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, M, K = map(int, input().split())
        g = [[] for _ in range(N)]
        for _ in range(M):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        INF = 10**18
        dist = [[INF] * (K + 1) for _ in range(N)]
        dist[0][0] = 0

        pq = [(0, 0, 0)]

        while pq:
            d, v, c = heapq.heappop(pq)
            if d != dist[v][c]:
                continue

            for u in g[v]:
                nd = d + 1
                if nd < dist[u][c]:
                    dist[u][c] = nd
                    heapq.heappush(pq, (nd, u, c))

                if c < K:
                    nd2 = d + 2
                    if nd2 < dist[u][c + 1]:
                        dist[u][c + 1] = nd2
                        heapq.heappush(pq, (nd2, u, c + 1))

        ans = min(dist[N - 1])
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```核心结构是产品状态空间上的标准 Dijkstra。 每条边的两个转换实现是否在目标顶点花费障碍预算的决定。 

距离表是二维的，这很重要，因为在不跟踪障碍物计数的情况下合并状态会错误地混合具有不同未来灵活性的路径。 优先级队列确保我们始终扩展当前最著名的部分路径，从而保持正确性。 

一个微妙的实现细节是，两个转换都是独立允许的，即使它们导致相同的邻居。 这就是在不枚举子集的情况下对障碍物放置的组合选择进行编码的内容。 

## 工作示例

 考虑一个简单的线图 0 − 1 − 2，其中 K = 1。 

我们从 dist[0][0] = 0 开始。从 (0,0)，我们可以以成本 1 到达 (1,0)，或者以成本 2 到达 (1,1)。从 (1,0)，我们以成本 2 到达 (2,0)。从 (1,1)，我们以成本 4 到达 (2,1)。 

| 步骤| 状态| 距离 | 行动|
 | ---| ---| ---| ---|
 | 1 | (0,0) | (0,0) | 0 | 开始 |
 | 2 | (1,0)| 1 | 无障碍 |
 | 3 | (1,1) | 2 | 阻碍节点 1 |
 | 4 | (2,0) | 2 | 继续畅通无阻 |
 | 5 | (2,1) | 4 | 继续受阻 |

 最好的答案是 min(dist[2][0], dist[2][1]) = 2？ 实际上我们仔细比较一下：dist[2][0]=2，dist[2][1]=4，所以我们取2。这表明，阻碍节点1只有在影响所选路径时才是有益的；否则，阻碍节点1只有在影响所选路径的情况下才是有利的； 否则可能无法使用。 

现在考虑一个图，其中 0 同时连接到 1 和 2，并且都连接到 3，且 K = 1。通过任一中间节点的最短路径的长度始终为 2。 如果我们只阻塞一个中间节点，另一条路径仍然给出距离 2，所以答案保持不变。 

| 步骤| dist[3][0] 通过 1 | dist[3][0] 通过 2 | 最佳|
 | ---| ---| ---| ---|
 | 无障碍 | 2 | 2 | 2 |
 | 区块 1 | 3 | 2 | 2 |
 | 区块 2 | 2 | 3 | 2 |

 这证实了该算法正确捕获了对抗性重新路由。

    out = []
    import heapq

        g = [[] for _ in range(N)]
        for _ in range(M):

            g[u].append(v)
            g[v].append(u)

        dist[0][0] = 0

        while pq:

            if d != dist[v][c]:
                continue
            for u in g[v]:

    return "\n".join(out)

 ## 边缘情况

 一个关键的边缘情况是当 K = 0 时。在这种情况下，状态空间在未加权图上崩溃为标准 BFS/Dijkstra。 该算法自然地处理它，因为只允许 c = 0 的转换，因此不会引入膨胀边缘。 

另一个边缘情况是阻塞入口（节点 0）是最佳选择。 从状态 (0,0) 开始，如果我们花费一个阻塞，则每次到邻居 u 的传出转换都可以选择立即增加成本。 该算法在第一步正确考虑了成本为 2 的 (u,1)，这意味着入口惩罚已完全建模。 

第三种边缘情况是最优策略使用少于 K 个障碍物。 由于在所有 c ≤ K 上答案被视为 min(dist[N−1][c])，因此自动允许未使用的预算，而不会造成不必要的障碍。
