 ## 解决方案
 ## 问题理解

 我们被要求计算填充的结构化方法$N \times N$带有“帐篷”的网格，其中每个选定的单元格恰好包含一个帐篷，每个帐篷容纳一个大小为 1、2 或 3 的家庭。关键约束不是单个单元格的本地约束，而是每行和每列的全局约束：每行和每列总共必须恰好贡献 3 个人。 此外，任何行或列都不允许包含超过两个已占用的单元格，这意味着每一行或列可以将所有 3 个人放入一个单元格中，或者将他们分成正好两个单元格。 

在所有有效的填充物中，我们只对那些至少包含$X$单元格携带值 3，意味着至少$X$行和列，其中单个单元格贡献 3 的总和。 

输出是此类有效网格的数量模$10^9+7$。 

约束条件达到$N \le 10^6$跨多个测试用例，这会立即排除任何遍历网格甚至行和列对的解决方案。 任何超出线性或接近线性的预处理$N$太慢了。 这促使我们采用仅依赖于阶乘式预计算和前缀和的公式。 

一种简单的方法是尝试在跟踪行和列总和的同时逐个单元格分配值。 即使我们积极修剪，每一行也会通过列约束与每一列交互，从而产生一个组合增长的状态空间。 为了$N=20$，这已经远远超出了回溯的可行范围。 

更微妙的故障模式来自于忽略列对称性。 例如，如果我们决定第 1 行在第 2 列中使用单个 3，则必须立即确保第 2 列也与正好有一个或两个占用单元格总和为 3 一致。任何仅行构造都会过多计算无效配置。 

## 方法

 如果我们不再考虑“帐篷”，而是考虑每行如何在各列之间分配值 3，那么结构就会变得更加清晰。 

每行只有两种可能的形状。 它将单个 3 放置在一列中，或者放置两个非零条目，其值必须按某种顺序为 1 和 2。 同样的限制对称地应用于列。 

这立即建议根据使用“single 3”模式的行数来拆分解决方案。 假设我们将该数字固定为$k$。 

如果某行的列中只有一个 3$j$，然后列$j$已经从该单元获得了 3 的全部配额。 它不能参与任何其他非零单元，否则其总和或度数约束将被打破。 这迫使每个这样的行-列对表现得像直接匹配：单 3 个单元格的集合形成行和列之间的部分双射。 

所以选择这些职位就等于选择$k$行，$k$列，并将它们双射配对。 

去掉这些之后$k$行和列，我们剩下一个$(N-k)\times(N-k)$现在，每行和每列必须使用两个单元格来分配其剩余总和 3 的子问题。 这意味着剩余的每一行都会选择两个不同的列，并且每个剩余的列也总共使用两次。 

该结构相当于对剩余的部分进行两个独立的排列$N-k$索引：一个排列确定“第一边缘”的位置，另一个排列确定“第二边缘”。 每行正好收到两个传出分配，每列正好收到两个传入分配。 

最后，该结构中的每个连接组件都是一个循环，并且沿着每个循环，恰好有两种有效的方法来分配哪个排列贡献值 1，哪个排列贡献值 2。 

通过这个计数可以得到一个干净的封闭形式。 固定贡献$k$大大简化为：$$\frac{(N!)^2}{k!}$$我们只需要对所有的求和$k \ge X$。

 ## 算法演练

 我们将组合结果转化为可计算的公式。 

1. 预先计算阶乘直至最大值$N$跨测试用例。 这是必需的，因为最终表达式取决于$N!$。 
2. 预先计算逆阶乘，以便我们可以得到$1/k!$模数$10^9+7$在恒定时间内每$k$。 
3. 对于每个测试用例，请阅读$N$和$X$。 
4. 计算逆阶乘的后缀和：$$S = \sum_{k=X}^{N} \frac{1}{k!}$$这代表了使用单个 3 的行数的所有有效选择。 
5. 将结果乘以$(N!)^2$，它考虑了选择哪些行和列参与以及如何在剩余结构中形成排列。 
6. 输出结果取模$10^9+7$。 

### 为什么它有效

 关键的不变量是，每个有效的配置都唯一地分解为两个独立的部分：由单 3 个单元形成的匹配部分，以及由剩余行和列形成的 2-正则二分结构。 匹配贡献的因素仅取决于$k$，一旦大小固定，其余结构就会贡献一个与特定匹配无关的项。 这种分离可确保不会对任何配置进行两次计数，并且不会遗漏任何有效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    T = int(input().strip())
    tests = []
    max_n = 0

    for _ in range(T):
        n, x = map(int, input().split())
        tests.append((n, x))
        max_n = max(max_n, n)

    fact = [1] * (max_n + 1)
    invfact = [1] * (max_n + 1)

    for i in range(1, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[max_n] = modinv(fact[max_n])
    for i in range(max_n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    for tc, (n, x) in enumerate(tests, 1):
        suf = 0
        for k in range(x, n + 1):
            suf = (suf + invfact[k]) % MOD

        ans = fact[n] * fact[n] % MOD
        ans = ans * suf % MOD

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```该实现依赖于将预处理与每次测试计算分开。 阶乘和逆阶乘一次建立到最大$N$，这是必要的，因为每次测试重新计算它们会太慢。 

逆阶乘的后缀和是根据测试用例直接计算的，因为$T$足够小并且总和$N$跨案例在预期的限制下保持可控。 

一个常见的陷阱是忘记最终的表达式涉及$(N!)^2$，不仅仅是一个阶乘。 这来自于在分解中独立选择行和列结构。 

## 工作示例

 考虑$N=2, X=0$。 我们总结一下$k=0,1,2$。 

| k | 1/k！ | 贡献 |
 | ---| ---| ---|
 | 0 | 1 | 1 |
 | 1 | 1 | 1 |
 | 2 | 1/2 | 1/2 1/2 | 1/2

 所以总数是$N!^2 \cdot (2.5)$。 自从$N!=2$，我们得到$4 \cdot 2.5 = 10$，匹配公式隐含的结构化赋值的数量。 

现在考虑$N=3, X=1$。 我们只总结$k=1,2,3$。 

| k | 1/k！ |
 | ---| ---|
 | 1 | 1 |
 | 2 | 1/2 | 1/2
 | 3 | 1/6 | 1/6

 该结构显示了增加单 3 行的最小数量如何减少可用配置，同时仍然保留结构的阶乘比例主干。 

这些痕迹强调，组合权重仅取决于有多少行折叠成单 3 个单元格，而不取决于它们的具体位置。

 ## 边缘情况

 当$X=0$，允许每种可能的分解，因此后缀和包括所有逆阶乘项。 该算法无需特殊外壳即可正确累加所有贡献，因为求和范围自然会扩展到整个区间。 

什么时候$X=N$，仅计算每行使用单个 3 的配置。 在这种情况下，后缀和减少为$1/N!$，最终的表达式变为$(N!)^2 / N! = N!$，这与为 3 个单元格选择行和列之间的完全双射完全对应。
