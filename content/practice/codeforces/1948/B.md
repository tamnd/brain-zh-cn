 ## 解决方案
 ## 问题理解

 给定一个 0 到 99 之间的整数数组，我们的目标是决定是否可以通过重复将两位数字“拆分”为各个数字来将其转换为非递减数组。 具体来说，对于任何至少 10 的元素，我们可以按顺序将其替换为数字。 例如，12 变为 [1, 2]，45 变为 [4, 5]。 我们可以对任何符合条件的元素执行此操作任意次。 任务是确定是否存在使整个数组按非降序排序的操作序列。 

这些约束为我们提供了长度最多为 50 个且最多 1000 个测试用例的数组。 因为最大的数组很小，所以数组长度呈二次方的算法是可行的，但元素数量呈指数的算法是不切实际的。 每个元素最多 99 个，因此“拆分”操作最多生成两个新元素，这限制了任何转换后的数组的大小。 

当数字已经是个位数、数组包含重复项或必须拆分较大的数字以适应顺序时，就会出现边缘情况。 例如，输入`[12, 3]`可以转化为`[1, 2, 3]`，已排序。 如果粗心的实现只检查原始数字而不考虑拆分，则会错误地报告“NO”。 另一种边缘情况是当所有数字都为零或一位数时，例如`[0, 0]`; 算法应该将其识别为已排序。 

## 方法

 暴力方法是通过以每种可能的顺序执行分割来生成所有可能的数组。 对于每个数组，我们将检查它是否是非递减的。 这在原则上是正确的，因为它会详尽地尝试每种组合，但可能性的数量随着多位数的数量呈指数增长。 即使最大数组长度为 50，我们也可以粗略地得到`2^50`最坏情况下的可能性太大了。 

实现最佳解决方案的关键见解是，拆分数字对于排序绝对有利，因为它永远不会降低数字的相对顺序。 每个号码`x`两位数字只能分成其第一位和第二位数字，并且这些数字始终是非递减的（`x//10 <= x%10`）。 因此，我们可以采取贪心的方法，而不是探索所有组合：我们立即将每个两位数字转换为其组成数字，然后检查结果数组是否已排序。 延迟分割没有任何好处，因为提前分割只能使数组更容易排序。 

通过应用这种见解，我们将问题简化为简单地传递转换后的数组以验证非递减顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 贪婪分割| 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空列表`b`它将保存转换后的数组。 我们将迭代原始数组并将每个两位数替换为其数字。 
2. 对于每个元素`x`在数组中`a`，检查是否至少为10。如果是，则追加`x // 10`其次是`x % 10`到`b`。 否则，附加`x`直接地。 这立即模拟将数字拆分为数字。 
3. 一旦所有元素都被处理成`b`, 迭代`b`并检查每个元素是否大于或等于前一个元素。 如果任何元素违反了这个条件，我们就得出结论，不可能使用分割对数组进行排序并输出“NO”。 
4. 如果整个数组`b`通过非递减检查，输出“YES”。 

为什么它有效：在每一点上，数组`b`包含分割后可能的最小表示，并且任何进一步的分割都不会减少第一个数字或创建更小的数字。 因此，如果`b`是非递减的，有一系列操作可以使原始数组排序。 相反，如果`b`不是非减的，没有任何分割序列可以修复它，因为我们已经分割了所有数字，任何额外的分割只会增加元素的数量，但永远不会减少一个数字来改善顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = []
        for x in a:
            if x >= 10:
                b.append(x // 10)
                b.append(x % 10)
            else:
                b.append(x)
        ok = True
        for i in range(1, len(b)):
            if b[i] < b[i - 1]:
                ok = False
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    main()
```在解决方案中，我们读取测试用例的数量，然后为每个测试用例读取数组。 变换后的数组`b`是通过立即拆分数字来构建的。 检查非递减顺序是一次性完成的。 这种方法避免了不必要的分割，并确保我们只跟踪相关序列来确定是否可以排序。

 ## 边缘情况

 对于像这样的数组`[12, 3]`，该算法将 12 分为`[1, 2]`并附加 3 得到`[1, 2, 3]`。 检查确认数组已排序，生成“YES”。 为了`[28, 5]`，分裂产生`[2, 8, 5]`。 最后一个元素 5 小于 8，因此检查失败，生成“NO”。 这证实了该算法可以处理需要分割但分割不够的数组，以及已经排序或可简单排序的数组。
