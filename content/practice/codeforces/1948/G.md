 ## 解决方案
 ## 问题理解

 给定一个最多有 20 个顶点的无向连通加权图。 我们必须选择一棵生成树。 该树的成本有两部分。 

第一部分是标准部分，即所选边权重的总和。 

第二部分取决于树的结构。 对于所选的生成树，我们计算其最大匹配大小，这意味着可以从树中选择的成对顶点不相交边的最大数量。 如果匹配的尺寸是$k$，我们额外支付$k \cdot c$。 

我们的目标是找到总成本最小的生成树。 

该图的顶点很小，$n \le 20$，但可能很密集，因为每对顶点都可能有一条边。 一棵生成树有$n-1$边，但可能的生成树数量是巨大的。 即使对于完整的图，凯莱公式也给出$n^{n-2}$跨越树木。 为了$n=20$，那已经是$2.6 \times 10^{23}$，完全无法一一列举。 

的小值$n$强烈建议该解决方案应使用位掩码。 周围的复杂性$O(2^n \cdot \text{poly}(n))$是现实的，因为$2^{20}\approx 10^6$。 像这样的东西$O(2^n n^2)$大致是$4\times 10^8$原始操作在最差的理论计数中，但通过非常小的常数和仔细的实现，它在 6 秒的限制内变得可以接受。 任何涉及所有树的枚举或所有树内的所有匹配的事情都是没有希望的。 

问题的危险部分是匹配项。 一个天真的想法是生成候选生成树并计算它们的最大匹配。 匹配大小取决于整个树结构，因此如何与 MST 构建一起优化它并不明显。 

有几种容易被忽略的情况。 

考虑四个顶点上的路径：```
1 - 2 - 3 - 4
```最大匹配大小是 2，因为我们可以取边$(1,2)$和$(3,4)$。 

输入：```
4 100
0 1 0 0
1 0 1 0
0 1 0 1
0 0 1 0
```仅最小化边权重的解决方案将选择这棵树并获得边和$3$，但实际成本是$3+2\cdot100=203$。 

另一个微妙的情况是明星：```
    2
    |
3 - 1 - 4
```最大匹配尺寸仅为 1，因为每条边都接触中心。 

输入：```
4 100
0 1 1 1
1 0 0 0
1 0 0 0
1 0 0 0
```树权重为3，匹配惩罚仅为$100$，因此总成本为 103。假设“顶点周围的边越多意味着匹配越大”的解决方案是完全错误的。 

最重要的结构陷阱是树中的最大匹配大小不是局部属性。 具有相同边权重和的不同树可能具有不同的匹配惩罚。 优化必须同时处理这两项。 

## 方法

 蛮力的想法很简单。 枚举图的每个生成树，计算其边权重和，计算其最大匹配大小，并保留最小答案。 

这是可行的，因为目标是直接在生成树上定义的。 如果我们能够检查每棵树，正确性就会立即显现。 

问题是生成树的数量。 在有 20 个顶点的完全图中，有$$20^{18}$$不同的生成树。 即使每秒检查一百万棵树也不会影响搜索空间。 

所以我们需要更深入地理解匹配项。 

关键的观察来自一个经典定理。 

每棵树都是二分的。 

对于二部图，$$\text{maximum matching} = \text{minimum vertex cover}.$$这就是柯尼希定理。 

不要考虑匹配，而要考虑顶点覆盖。 

假设最终树的最大匹配大小为$k$。 那么树的顶点覆盖大小为$k$。 

令该顶点覆盖为$S$。 

由于树的每条边都必须被覆盖，因此每条树边内部必须至少有一个端点$S$。 

这意味着树只使用端点不都在外面的边$S$。 

这彻底改变了问题。 

修复一些子集$S$。 认为$S$将是最终树的顶点覆盖。 

那么每个允许的树边必须满足：$$u\in S \quad\text{or}\quad v\in S.$$换句话说，外部两个顶点之间的边$S$被禁止。 

在所有仅使用此类边的生成树中，我们只需要权重最小的一棵。 这只是受限图上的 MST 问题。 

如果该受限图是断开连接的，则不存在用于此选择的生成树$S$。 

如果限制图是连通的，则兼容的最便宜的生成树$S$正是它的 MST。 

其总成本变为$$\text{MST weight} + |S|\cdot c.$$为什么这就足够了？ 

因为如果一棵树有最大匹配大小$k$，然后它有一些大小的顶点覆盖$k$。 当我们枚举该覆盖时，该树在相应的受限图中变得可行。 该受限图的 MST 只能比该树便宜。 因此考虑每个子集$S$永远不会错过最佳时机。 

现在问题变成：

 枚举每个子集$S$，构建仅包含边接触的图$S$，计算其 MST 权重，并最小化$$\text{MST weight}+|S|c.$$自从$n\le 20$， 有$2^n$子集。 对于每个子集，我们可以运行 Prim 的算法$O(n^2)$。 

这产生$O(2^n n^2)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解跨树 | 树木数量呈指数增长 | 巨大 | 太慢了 |
 | 枚举顶点覆盖 + MST |$O(2^n n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取图形并用无穷大值替换每个缺失的边。 
2. 枚举每个位掩码$mask$从$0$到$2^n-1$。 
3. 解释设置位$mask$作为候选顶点覆盖$S$。 
4. 构造隐式限制图，其中边$(u,v)$仅当至少一个端点属于$S$。 

端点均在外侧的边$S$不能出现在被覆盖的树中$S$。 
5. 在此受限图上运行 Prim 算法。 

松弛边时，忽略两个端点都在外面的每条边$S$。 
6. 如果Prim无法到达所有顶点，则限制图断开。 

在这种情况下这个子集$S$无法生成生成树，因此丢弃它。 
7. 否则获取MST权重$W$。 
8. 计算$$W + c \cdot \text{popcount}(mask).$$1. 最小化所有掩码的答案。 

### 为什么它有效

 对于任意生成树$T$， 让$k$为其最大匹配尺寸。 

由于每棵树都是二分树，Kőnig 定理给出了顶点覆盖$S$尺寸的$k$。 

每一个边缘$T$至少有一个端点$S$， 所以$T$完全包含在由以下定义的受限图中$S$。 

该受限图的 MST 的权重最多为$T$， 因为$T$是同一图的一棵有效生成树。 

因此对于这个特定的子集$S$,$$\text{MST}(S)+|S|c \le \text{weight}(T)+kc.$$因此，最优树的成本至少是我们的枚举所考虑的一个值。 

相反，对于每个子集$S$，受限图的任何生成树的所有边都被$S$。 所以$S$是该树的顶点覆盖，因此它的最大匹配大小最多为$|S|$。 我们计算的成本，$$\text{MST}(S)+|S|c,$$MST 本身就可以实现，并且永远不会低估真正的目标。 

这两个方向一起表明所有子集的最小值正是答案。 

从匹配到顶点覆盖的减少是关键的桥梁。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10 ** 18

def prim(mask, n, g):
    dist = [INF] * n
    used = [False] * n
    dist[0] = 0

    total = 0

    for _ in range(n):
        v = -1

        for i in range(n):
            if not used[i] and dist[i] < INF:
                if v == -1 or dist[i] < dist[v]:
                    v = i

        if v == -1:
            return INF

        used[v] = True
        total += dist[v]

        for to in range(n):
            if used[to]:
                continue

            if ((mask >> v) & 1) == 0 and ((mask >> to) & 1) == 0:
                continue

            w = g[v][to]
            if w < dist[to]:
                dist[to] = w

    return total

def solve():
    n, c = map(int, input().split())

    g = [[INF] * n for _ in range(n)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j in range(n):
            if i == j:
                g[i][j] = INF
            elif row[j] != 0:
                g[i][j] = row[j]

    ans = INF

    for mask in range(1 << n):
        mst_cost = prim(mask, n, g)
        if mst_cost == INF:
            continue

        cur = mst_cost + c * mask.bit_count()
        if cur < ans:
            ans = cur

    print(ans)

solve()
```实现几乎完全遵循证明。 

功能`prim`计算与掩码对应的受限图中的 MST 权重。 它不是为每个子集显式构建新图，而是在松弛期间检查限制。 如果至少一个端点属于掩模，则边缘可用。 

返回`INF`当不存在未访问的可到达顶点时很重要。 这就是我们检测受限图是否断开的方式。 

该图使用`INF`对于不存在的边缘。 这让 Prim 自然地忽略它们，因为这些值永远不会改善距离。 

表达式```
((mask >> v) & 1) == 0 and ((mask >> to) & 1) == 0
```检查两个端点是否位于候选顶点覆盖范围之外。 这样的边缘是被禁止和跳过的。 

蟒蛇的`bit_count()`给出子集的大小，它与顶点覆盖惩罚完​​全对应。 

一个微妙的问题是允许使用空掩码。 它只是意味着没有选择任何顶点。 通常受限图会变得断开连接，但在非常小的图中，统一测试它仍然有效。

 ## 边缘情况

 考虑星图：```
4 100
0 1 1 1
1 0 0 0
1 0 0 0
1 0 0 0
```一个常见的错误是假设匹配惩罚随着中心度的增加而增加。 实际上，每条边都共享相同的顶点，因此只有一条边可以属于匹配。 

该算法通过顶点覆盖公式来处理这个问题。 单独选择中心作为覆盖层给出掩模大小 1。受限图已经包含所有树边，因此 Prim 返回权重 3，答案变为$$3 + 1\cdot100 = 103.$$现在考虑路径：```
4 100
0 1 0 0
1 0 1 0
0 1 0 1
0 0 1 0
```最大匹配尺寸为2。最小顶点覆盖尺寸也为2，即顶点2和3。 

当算法枚举该掩码时，每个路径边缘都是允许的。 Prim 获得树权重 3，产生$$3 + 2\cdot100 = 203.$$大小为 1 的掩码无法覆盖所有三个边缘，因此算法正确地拒绝了匹配惩罚可能为 100 的不可能假设。 

最后，考虑一个断开图形的掩码。```
4 1
0 1 1 1
1 0 1 1
1 1 0 1
1 1 1 0
```拿面膜`{1}`。 

顶点之间的边`{2,3,4}`被禁止，因为两个端点都不属于封面。 受限图变成以顶点 1 为中心的星形，该星形仍然是连通的。 

如果我们采用空掩码，则每条边都将被禁止。 Prim 无法到达所有顶点并返回`INF`。 该算法会自动丢弃该子集。 

此连接检查至关重要。 许多掩码不对应于任何有效的生成树，将它们视为有效会产生错误的答案。
