 ## 解决方案
 ## 问题理解

 我们得到了一个代表城市地图的有向图，其中每条道路都有一个方向和与反转它相关的成本。 市长的目标是修改某些道路的方向，以便最终的有向图不包含有向环，即在沿着有向道路至少移动一次后不能重新访问起始交叉路口。 换句话说，改变之后，图在有向意义上必须是无环的，这相当于可以为所有顶点分配拓扑排序。 

每条边可以保持其原始方向，也可以反转，但反转边会产生等于其给定权重的成本。 我们必须选择一组边进行反转，使得生成的有向图是非循环的，同时最小化总反转成本。 此外，我们必须输出哪些边是反转的，并且我们可以输出任何有效的反转边集，即使它们的数量不是最少的。 

这些约束迫使我们采取线性或近线性行为。 对于多达 100,000 个顶点和 100,000 条边，任何试图在每次修改后检查所有边子集或重新计算循环结构的解决方案都是不可能的。 即使是算法$O(m \log m)$或者$O(m \alpha(n))$是可以接受的，但是任何根据决策重复执行 DFS 的操作都会失败。 

一个关键的微妙之处是图不需要成为树，甚至不需要连接。 我们只需要全局消除有向循环即可。 这意味着我们正在有效地寻找一种最小成本的方法来定向每条边，以便最终的方向允许拓扑排序。 

打破朴素推理的边缘情况通常来自局部循环直觉：

 一个简单的循环示例：```
1 -> 2 -> 3 -> 1
```具有不同的逆转成本。 尝试独立打破每个周期中最便宜边缘的贪婪方法会失败，因为周期重叠。 

另一个失败案例：```
1 -> 2 -> 3 -> 4 -> 2
```这里循环共享边。 删除一个边缘可能会部分破坏多个周期，因此局部决策会产生误导。 

第三种微妙的情况是，反转边缘成本高昂，但对于保持全局一致性是必要的。 在局部看来，它可能是可以避免的，但在全球范围内，由于可达性限制，它变得不可避免。 

## 方法

 暴力策略会尝试为每条边（原始或反向）分配一个方向，并检查生成的图是否是非循环的。 这立即表明$2^m$的可能性，这显然是不可能的$m = 10^5$。 即使在构建过程中通过检测周期进行修剪，在最坏的情况下仍然会导致指数行为。 

更结构化的想法来自于将问题视为强制拓扑顺序。 如果我们有固定的顶点顺序，则每条边都按该顺序向前或向后移动。 如果有优势，我们就保留它； 如果它倒退，我们就必须扭转它，并付出代价。 因此，对于固定排序，成本只是后向边缘成本的总和。 

这将问题转化为寻找一个顶点排序，使与该顺序相反的边的成本总和最小化。 这是在类似锦标赛的加权有向图中设置的经典最小反馈弧，但这里的图是任意的。 

关键的见解是我们不需要直接猜测顺序。 相反，我们可以使用带有边缘分类的基于 DFS 的拓扑构造来贪婪地构造它。 在DFS过程中，当我们遍历一条边到达未访问过的节点时，我们将其视为前向边； 当我们遇到与排序约束相矛盾的边时，我们将其解释为反转的候选者。 通过仔细构建遍历，我们确保选择用于反转的边与违反基于 DFS 的拓扑标记的边完全对应。 

标准技巧是在有向图上执行 DFS，同时记录整理顺序。 每当我们遍历通向当前递归堆栈中已有节点的边时，我们都会检测到后边，这正是促成循环的原因。 这些后边形成一个集合，我们希望将其总成本最小化，但我们必须确保只选择实际上破坏所有循环的边。 

改进是按原样对待图并依赖于 DFS 完成时间：当且仅当我们可以通过反向后序分配排序时，有向图才是非循环的。 DFS 树结构中从较晚完成节点到较早完成节点的任何边都是后边，必须在最优解中反转。 令人惊讶的事实是，选择所有此类边会产生消除所有循环所需的最小成本集，因为 DFS 以尊重循环结构的方式将边划分为树、前向边和后向边。

 | --- | --- | --- | --- |
 | 蛮力 |$O(2^m)$|$O(m)$| 太慢了|
 | DFS分类|$O(n + m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 我们构建基于 DFS 的排序，并同时识别哪些边违反该排序。 

1. 为有向图构建邻接表，跟踪边索引和成本。 这是必要的，因为我们必须输出边 ID，而不仅仅是成本。 
2. 从每个未访问的节点运行 DFS。 这确保我们处理所有组件，因为图可能会断开连接。 
3. 维护节点的状态数组：未访问、在递归堆栈中、已完成。 这种区别很重要，因为只有递归堆栈中节点的边对应于循环。 
4. 在从节点 u 进行 DFS 期间，当我们检查边 u -> v 时：

 如果 v 未被访问，我们递归到 v。这保留了 DFS 树结构。 

如果 v 当前位于递归堆栈中，则我们找到了后边，这意味着该边参与有向循环。 我们将这条边标记为反向并添加其成本。 

如果 v 已经完成，我们会忽略它，因为它无法参与 DFS 排序中的循环。 
5. 探索完 u 的所有出边后，我们将 u 标记为完成并将其附加到表示反向拓扑顺序的列表中。 
6. DFS 完成后，所有标记的边正是那些与 DFS 导出的非循环方向相反的边。 我们输出他们的指数和累计成本。 

为什么它有效：

 DFS 完成顺序定义了顶点的部分排序。 从一个节点到仍在递归堆栈中的另一个节点的任何边都必然会关闭活动探索路径中的有向循环。 这些边正是阻止 DFS 排序成为有效拓扑排序的边。 准确地删除（反转）这些边会破坏每个循环，因为每个有向循环在任何 DFS 遍历中都必须包含至少一个后边沿。 成本被最小化，因为每个后沿仅被识别一次，并且没有前向或交叉沿被不必要地反转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for i in range(1, m + 1):
        u, v, c = map(int, input().split())
        g[u].append((v, c, i))
    
    state = [0] * (n + 1)
    # 0 = unvisited, 1 = in stack, 2 = done
    bad_edges = []
    total_cost = 0
    
    def dfs(u):
        nonlocal total_cost
        state[u] = 1
        for v, c, idx in g[u]:
            if state[v] == 0:
                dfs(v)
            elif state[v] == 1:
                bad_edges.append(idx)
                total_cost += c
        state[u] = 2
    
    for i in range(1, n + 1):
        if state[i] == 0:
            dfs(i)
    
    print(total_cost, len(bad_edges))
    print(*bad_edges)

if __name__ == "__main__":
    solve()
```邻接表存储边索引，因此我们可以直接输出所需的标识符。 DFS 状态数组至关重要：如果没有栈内标记，我们将无法区分后边和交叉边，这完全改变了正确性。 

增加递归限制是必要的，因为图可以形成多达 100,000 个节点的长链。 

一个微妙的实现点是我们只将状态 1 中的节点的边视为可逆的。 状态 2 节点的边将被忽略，即使它们看起来可以以其他遍历顺序形成循环； DFS 保证它们不会关闭活动递归路径中的循环。

 ## 边缘情况

 第一个重要的边缘情况是已经是 DAG 的图。 在这种情况下，递归堆栈中不会重新访问任何节点，因此算法永远不会记录坏边。 输出成本为零，边列表为空，这是最优的。 

第二种情况是单个大循环，其中所有节点形成一个循环。 DFS 将遍历循环，直到再次遇到递归堆栈中的第一个节点，将恰好一条边标记为坏。 这已经足够了，因为打破简单有向循环中的任何一条边都会删除所有循环。 

第三种情况是周期重叠。 在此类图中，在遍历过程中可能会发现多个后边缘，但每个后边缘在关闭递归路径时都会被准确检测到。 尽管循环在结构上重叠，但 DFS 堆栈确保每个闭包都是独立考虑的，并且每个循环必须至少包含这些边之一，因此反转后不会保留任何循环。
