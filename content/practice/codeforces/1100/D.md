 ## 解决方案
 ## 问题理解

 我们正在模拟 999 x 999 网格上与单个白王和许多黑车的交互。 国王首先移动，可以走到八个相邻单元格中的任何一个。 每次国王移动后，对手都会将一辆车移动到任何空方格，但有一个重要的限制：永远不允许车移动到与国王位于同一行或同一列的方格上。 

只有当国王踏入与某个车位于同一行或同一列的方格时，国王才会输。 目标是保证无论车如何移动，2000 次王移动都不会发生这种情况。 

关键的困难在于，车可以自适应地移动，并且可以尝试占据靠近国王想去的地方的危险位置。 然而，它们相对于国王的行和列的移动限制产生了可以利用的结构约束。 

对棋盘尺寸的限制足够大，以至于任何每次移动扫描或车影响力的全局重新计算都将是不必要的开销。 由于交互仅运行 2000 步，因此预计每次移动策略的时间恒定。 

如果我们假设车以一种动态的方式逐渐“包围”国王，就会出现一个微妙的问题。 这种直觉是具有误导性的，因为车不允许进入国王当前的行或列，这会永久地将整条线从其可到达的空间中删除。 

例如，如果王从位置 (x, y) 开始，车就不能再次占据 x 行或 y 列。 这立即使任何假设车最终能够以对称方式阻挡国王周围所有方向的策略失效。 

一个幼稚的错误是尝试通过扫描棋盘或在本地对车的移动做出反应来动态避开车。 但这会失败，因为车可以在其他任何地方重新定位，并且状态空间太大，无法在交互式设置中有效地维护影响图。 

## 方法

 一个蛮力的想法是将每一步棋都视为寻路问题：在每一步，考虑所有 8 个可能的王棋步，并模拟在每次假设的棋步后是否可能进行车攻击。 这需要维护车位置的动态结构，并重复检查每个候选移动的行和列冲突。 由于这种情况会发生 2000 次，并且每次检查可能涉及扫描多达 666 个车，因此在交互式环境中，这很快就会变得不必要的沉重和脆弱。 

关键的观察是国王为车创建了一个永久的禁区。 一旦王位于 (x, y)，车就不能再移动到 x 行或 y 列。 这意味着在剩下的比赛中，整条队伍将永远没有车。 这种结构极其严格：我们可以将国王锁定在一个通过构建而全局安全的区域，而不是考虑局部回避。 

一旦我们意识到国王的固定行或列永远完全没有车，问题就崩溃了。 国王可以限制自己只沿着该行（或列）移动，确保每个访问的方格永远不会与任何车位于同一行或同一列。 

蛮力之所以有效，是因为它试图直接适应车，但它失败了，因为交互是对抗性的，而且太大而无法精确跟踪。 对永久阻塞行和列的观察消除了对车的任何动态推理的需要。

 ## 算法演练

我们利用了这样一个事实：车被禁止进入国王当前的行和列，因此这些行永远没有车。 

1. 读取国王的初始位置。 让它成为（r，c）。 这一行和一列将定义一条永久安全的走廊。 
2. 决定将所有未来的王移动仅限于 r 行。 我们再也不会离开这一排了。 
3. 由于没有车可以占据第 r 行，因此保证每个单元格 (r, y) 始终没有车。 这也消除了基于列的攻击的任何危险，因为 rook 攻击需要共享行或列，并且 r 行全局禁止 rook。 
4. 沿着 r 行构造一个简单的确定性运动模式，例如向右移动一步直到到达边界，然后反转方向。 只要尊重网格边界，任何一维行走都可以工作。 
5. 每转一圈，输出该水平行走的下一个位置。 由于 r 行中的所有单元格都是安全的，并且相邻的移动保留在 r 行中，因此每个移动都是有效的并且不会触发丢失条件。 
6. 完全忽略所有车更新。 它们不会影响不变量，因为它们永远不允许进入 r 行。 

### 为什么它有效

 不变的是，国王总是排成一排，在整个游戏过程中车完全无法接近。 因为明确禁止车移动进入王当前的行或列，所以一旦选择了一行或列，它就永久没有车。 通过永远不离开该行，国王确保未来的车配置不会与其位置产生行或列重叠。 由于检查仅取决于与车共享行或列，因此这个不变量保证了每一步的安全。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    r, c = map(int, input().split())
    for _ in range(666):
        input()

    left, right = 1, 999
    cur = c
    direction = 1

    for _ in range(2000):
        if cur == right:
            direction = -1
        elif cur == left:
            direction = 1

        cur += direction
        print(r, cur)
        sys.stdout.flush()

        line = input().strip()
        if line == "-1 -1 -1":
            return

if __name__ == "__main__":
    main()
```该解决方案首先修复国王的初始行，然后完全忽略车的位置，因为它们不再影响该行。 移动逻辑是沿着该行在板的左边缘和右边缘之间进行简单的弹跳。 唯一的微妙之处是在边界处保持方向变化以避免离开网格。 

在交互问题中，每次移动后的同花至关重要； 如果没有它，法官将停止等待输出。 

## 工作示例

 考虑初始国王位置 (5, 5)。 国王承诺第 5 行。 

| 步骤| 专栏 | 移动|
 | --- | --- | --- |
 | 1 | 6 | (5, 6) |
 | 2 | 7 | (5, 7) |
 | 3 | 8 | (5, 8) |

 这一直持续到第 999 列，然后反转方向。 每走一步，国王都留在第 5 排，该排永远没有车。 

这表明一旦建立了不变量，车的运动就与安全无关。 

作为第二种情况，假设国王从边界附近开始，例如 (5, 999)。 该算法立即反转方向并向左行走：

 | 步骤| 专栏 | 移动|
 | --- | --- | --- |
 | 1 | 998 | (5, 998) |
 | 2 | 997 | 997 (5, 997) |
 | 3 | 996 | (5, 996) |

 即使在这种情况下，边界处理也确保不会发生无效移动。

 ## 边缘情况

 如果国王从第 1 列开始，算法会立即强制移动到第 2 列，确保不会尝试无效的左移动。 在更新位置之前，通过方向翻转来处理边界条件。 

如果王从第 999 列开始，则第一步正确地转到 998，因为到达边界时方向相反。 

如果车在棋盘上任意聚集，它们永远不会影响所选行，因为游戏规则阻止它们进入该行，因此不变量在整个交互过程中保持不变。
