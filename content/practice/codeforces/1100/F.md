 ## 解决方案
 ## 问题理解

 我们在一条线上得到了一系列值，其中每个位置代表一家汉堡店，该位置的值是那里最昂贵的汉堡的成本。 对于每个查询，我们都会获得该数组的一个段，并且允许我们选择该段内索引的任何子集。 选择子集的效果是，我们从一个非常大的初始数开始，并重复对所选值应用异或。 我们关心的量是值相对初始状态减少了多少，相当于最大化所选子集的异或结果。 

一个关键的简化来自于所有位都已设置的初始值。 如果我们从每个相关位都是 1 的形式的数字开始，那么与一个值进行异或会有效地翻转位。 “花费的钱”仅取决于所有异或运算后的结果值，因此任务简化为最大化给定段的某些子集的异或。 

因此，每个查询都会询问：给定一个子数组，通过选择其中的任何元素子集可以获得的最大 XOR 值是多少。 

约束很大，最多有 500,000 个元素和 500,000 个查询。 这立即排除了在该段上的线性时间内重新计算每个查询的任何内容，因为这会导致大致$2.5 \times 10^{11}$最坏情况下的操作。 甚至$O(n \log n)$每个查询太慢。 我们需要一个支持 XOR 子集快速范围查询的结构。 

一种简单的方法是构建一个范围的所有子集，或者为每个查询重新计算贪婪的 XOR 基础。 这会失败，因为子集枚举是指数级的，甚至在重复多次时从头开始维护每个查询的运行基础也太慢。 

当段中的所有值都为零时，会出现微妙的边缘情况。 正确的答案是零，任何在没有适当标准化的情况下假设至少一个非零基向量的方法都可能在查询空基时错误地返回非零值或崩溃。 另一个边缘情况是值重复时； 重复项不得错误地扩展基础。 

## 方法

 蛮力的想法很简单。 对于每个查询，我们收集段中的所有值并尝试每个子集，计算 XOR 并跟踪最大值。 这是正确的，因为它直接评估问题的定义。 然而，每段长度$k$有$2^k$子集，即使对于$k = 30$，更不用说$k = 500000$。 

我们需要认识到，XOR 子集优化并不是直接涉及子集，而是涉及它们在 GF(2) 上形成的线性结构。 任何一组数字在 XOR 下都会生成一个向量空间，任何子集 XOR 都对应于这些向量的线性组合。 可获得的最大 XOR 是从该集合的线性基础可获得的最大值。 

这将问题转化为维持数组各段的线性基础。 关键的观察是，一个段的完整行为完全由其基础描述，其大小最多为 20，因为值最多可达$10^6$，因此最多 20 个相关位。 

然后，我们需要一个可以有效返回任何段的组合基础的数据结构。 线段树的工作原理很自然：每个节点存储其区间的一个基，合并两个节点意味着将两个基合并为一个简化基。 

一旦我们获得了查询段的基础，我们就通过贪婪地尝试从最高位向下改进结果来计算最大异或。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 |$O(2^n)$每个查询 |$O(1)$| 太慢了|
 | 具有异或基础的线段树 |$O((n + q)\log n \cdot B^2)$|$O(n \log n \cdot B)$| 已接受 |

 这里$B$是位数，大约20。 

## 算法演练

 我们构建一棵线段树，其中每个节点存储其线段中所有值的线性基础。 

1. 使用仅包含该位置处的单个值的基础来初始化每个叶节点。 该基础表示从该单个元素可实现的所有异或，这些异或只是零和元素本身。 
2. 定义两个基之间的合并操作。 我们从第二个基中获取所有向量，并使用标准线性基插入将它们插入到第一个基中。 每次插入都会尝试使用现有的基向量消除最高设置位，以确保结构保持独立。 
3. 通过合并子节点自下而上构建线段树。 每个内部节点存储其左右子段的合并基础。 这确保了每个片段都由其基础完全代表。 
4. 对于每个查询$[l, r]$，我们遍历线段树并收集完全覆盖查询范围的所有线段的基数。 这些被合并到一个临时的基础上。 
5. 一旦我们有了查询的最终基础，我们就计算最大 XOR 值。 我们从零开始，从最高到最低迭代位，尝试通过与增加该值的基向量进行异或来提高该值。 
6. 输出每个查询的最大值。 

合并起作用的原因是不相交段上的异或组合是独立的。 全范围的任何子集都可以分为左部分和右部分的子集，并且它们的异或线性组合。 因此，合并基数保留了所有可实现的异或。 

### 为什么它有效

 在每个线段树节点上，我们维护一个恰好涵盖该区间的可异或表示值集的基。 合并操作保留了跨度，因为两个集合的异或组合对应于它们向量空间的并集。 由于每个查询都分解为不相交的段，这些段的并集形成了整个范围，因此合并它们的基会生成一个跨越查询间隔的所有可能子集 XOR 的基。 然后，贪婪提取步骤找到该空间中的最大可表示值，这是最佳的，因为线性基保证可以通过确定性按位构造来构造任何可到达的异或。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

B = 20

class Basis:
    __slots__ = ("b",)
    def __init__(self):
        self.b = [0] * B

    def insert(self, x):
        for i in reversed(range(B)):
            if (x >> i) & 1:
                if self.b[i]:
                    x ^= self.b[i]
                else:
                    self.b[i] = x
                    return

    def merge(self, other):
        for x in other.b:
            if x:
                self.insert(x)

    def max_xor(self):
        res = 0
        for i in reversed(range(B)):
            res = max(res, res ^ self.b[i])
        return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [Basis() for _ in range(4 * self.n)]
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.t[v].insert(self.arr[l])
        else:
            m = (l + r) // 2
            self.build(v * 2, l, m)
            self.build(v * 2 + 1, m + 1, r)
            self.t[v].merge(self.t[v * 2])
            self.t[v].merge(self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr, res):
        if ql <= l and r <= qr:
            res.merge(self.t[v])
            return
        m = (l + r) // 2
        if ql <= m:
            self.query(v * 2, l, m, ql, qr, res)
        if qr > m:
            self.query(v * 2 + 1, m + 1, r, ql, qr, res)

def main():
    n = int(input())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    q = int(input())
    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        res = Basis()
        st.query(1, 0, n - 1, l - 1, r - 1, res)
        out.append(str(res.max_xor()))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```线段树在数组上构建一次，每个节点存储其区间内所有 XOR 贡献的压缩表示。 查询函数仅收集相关节点并将它们的基础合并到临时结构中。 最后一步计算可实现的最佳异或。 

实施中的微妙之处在于，合并基地必须保持独立性； 将一个基础的每个元素插入到另一个基础中是必要的，而不是天真的串联。 另一个细节是确保基础使用固定的位限制，因为值的边界是$10^6$。 

## 工作示例

 ### 示例 1

 输入：```
n = 4
arr = [7, 2, 3, 4]
query = [1, 4]
```| 步骤| 当前基础| 行动|
 | --- | --- | --- |
 | 1 | {} | 插入 7 |
 | 2 | {7} | 插入 2 |
 | 3 | {7, 2} | 插入 3 |
 | 4 | {7,2,3}| 插入 4 |

 建立基础后，我们通过贪婪选择计算最大异或。 可实现的最佳 XOR 是 7。 

这表明，即使所有元素都可用，最佳子集只是选择一个强大的贡献者。 

### 示例 2

 输入：```
n = 3
arr = [12, 14, 23]
query = [1, 3]
```| 步骤| 基础| 说明|
 | --- | --- | --- |
 | 开始| {} | 空 |
 | 插入 12 | {12} | 添加第一个向量 |
 | 插入 14 | {12, 14} | 独立|
 | 插入 23 | {12, 14, 23} | 完整基础 |

 现在计算最大异或。 贪心构造从 12 XOR 23 得到 27。 

这证实了即使单个值不是最大值，最优子集也可能涉及多个元素。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O((n + q)\log n \cdot B^2)$| 每次合并最多插入 B 个向量，每次插入成本 B |
 | 空间|$O(n \log n \cdot B)$| 每个线段树节点存储一个大小为 B | 的基

 复杂度足够了，因为$B \approx 20$，使所有操作有效地成为小常数。 即使有 500,000 个查询，线段树操作在限制内仍然足够快。

 ## 边缘情况

 对于仅包含零的段，每次插入基础都会使其为空，因此最终的贪婪异或保持为零。 线段树正确地存储此类节点的空基，并且合并空基没有任何效果，从而保持了正确性。 

对于重复值，插入相同的数字两次不会改变基础，因为它会被现有向量消除。 这确保了重复项不会人为地扩大可表示空间。 

对于单元素查询，叶子节点已经包含了正确的基础，所以不需要合并。 查询只是返回该节点的基础，贪婪步骤返回与正确答案匹配的元素本身。
