 ## 解决方案
 ## 问题理解

 我们收到一系列问题，每个问题都标记有从 1 到 n 的难度。 Arkady 保留了一系列已创建的问题，并且在任何时候，如果他能够从 1 到 n 的每个难度中恰好选出一个未使用的问题，则他可以随时参加竞赛。 一旦竞赛形成，那些选定的问题就会从池中删除。 

该过程是在线的。 每个新问题出现后，我们必须决定池中是否已经出现了所有 n 个困难的完整集合。 如果是，阿尔卡迪立即使用每个难度中的一个进行比赛，并且池子相应减少。 我们在那一刻输出 1，否则输出 0。 

关键难点在于，问题会随着时间的推移而积累，只有自上次比赛以来每个难度至少出现一次才能形成比赛，但每次比赛每个难度只消耗一份副本。 

约束允许最多 100,000 个事件，n 也最多为 100,000 个。 任何在每次插入后从头开始重新计算可用性的解决方案都会太慢，因为它需要每一步扫描最多 n 个元素，导致最坏情况下的 O(nm) 行为，对于 1 秒来说太大了。 

一个微妙的边缘情况是重复触发。 例如，如果 n = 3 并且流是 1 2 3 1 2 3，那么天真的方法可能会认为第二个 1 2 3 不应该触发，因为池没有显式“重置”，但实际上第一个竞赛消耗了每个三元组中的一个，第二个三元组再次可用。 

另一个常见的错误是忘记了相同难度的多个副本除了“每次比赛至少一份未使用的副本”之外没有任何帮助。 如果难度2出现10次，它仍然只为在任何时刻组成新的比赛贡献一个名额。 

## 方法

 暴力解释保留了所有产生的问题的多重集。 每次插入后，它都会检查从 1 到 n 的每个难度是否在池中至少存在一次。 如果是，则通过删除每个难度的一次出现来形成竞赛并输出 1。 

这是正确的，因为它直接模拟了规则。 然而，检查可行性需要每次扫描所有 n 个困难，每个事件的复杂度为 O(n)。 对于 m 个事件，这变为 O(nm)，在最坏的情况下是 10^10 次操作，远远超出了限制。 

关键的观察是，唯一重要的是我们目前是否每个难度都至少有一个未使用的实例。 如果我们维护当前“可用正数量”的不同难度的计数器，则不需要重复扫描所有值。 每次添加问题时，我们都会更新其频率。 每当频率变为 1 时，我们就会获得一个新的“覆盖难度”。 每次我们在比赛期间删除一个事件时，一些频率就会降至零，从而减少覆盖范围。 

因此，我们不是重复验证所有 n 种类型，而是跟踪当前至少出现一次的不同困难。 当该计数达到 n 时，就会触发一场竞赛，并且我们将针对这 n 个难度的所有频率恰好减一。 这保证了我们无需完全重新扫描即可正确重置覆盖范围。 

核心效率来自于这样一个事实：每个问题在每个比赛周期最多递增和递减一次，从而给出线性的总工作量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描| O(纳米) | O(n) | 太慢了|
 | 频率+独特计数器| O(米) | O(n) | 已接受 |

 ## 算法演练

 我们维护两个结构：频率数组`cnt[d]`存储池中存在多少未使用的难度 d 副本，以及一个计数器`have`存储当前有多少不同的困难`cnt[d] > 0`。 

我们还维护一个列表或简单的循环机制，用于在比赛形成时清除每个难度的一个实例。 

### 步骤

 1.初始化一个数组`cnt`大小为 n+1，带有零和集合`have = 0`。 

该数组表示每个事件后的当前池状态。 
2. 迭代每个传入的难度 x。 

我们将其视为向池中插入一个新问题。 
3.如果`cnt[x] == 0`插入前，递增`have`因为这个困难是新出现的。 
4. 增加`cnt[x]`1.
 5. 插入后，检查是否`have == n`。 

此条件意味着从 1 到 n 的每个难度在池中至少出现一次，因此可以进行比赛。 
6. 如果可以进行竞赛，则对该位置输出 1，然后模拟消除从 1 到 n 的每个难度的一个问题。 

对于从 1 到 n 的每个 i，递减`cnt[i]`1.如果有的话`cnt[i]`变为零，递减`have`。 
7. 如果没有形成比赛，则输出0。 

### 为什么它有效

 不变的是`cnt[d]`始终反映在所有先前执行的比赛之后未使用的难度 d 问题的数量。 变量`have`精确计算有多少个索引满足`cnt[d] > 0`。 当且仅当每个难度都至少有一个可用问题时，才有可能进行一场竞赛，这相当于`have == n`。 

当我们组织一场竞赛时，我们会准确地删除每个难度的一个实例，这样可以保留正确性，因为每个难度都为竞赛贡献了一个问题。 该系统保持一致，因为任何困难都不会被消除到零以下，因为前提条件是所有`cnt[i] > 0`触发时。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    cnt = [0] * (n + 1)
    have = 0
    res = []

    for x in a:
        if cnt[x] == 0:
            have += 1
        cnt[x] += 1

        if have == n:
            res.append('1')
            for i in range(1, n + 1):
                cnt[i] -= 1
                if cnt[i] == 0:
                    have -= 1
        else:
            res.append('0')

    print(''.join(res))

if __name__ == "__main__":
    solve()
```实现直接反映了算法。 关键细节正在更新`have`仅当频率在零和正之间转换时，确保它仍然是不同可用困难的真实计数。 

竞赛形成循环从每个难度中减去一，这是安全的，因为我们只有在所有频率都为正时才进入该块。

 ## 边缘情况

 一个关键的边缘情况是比赛在第一时间立即发生。 该算法处理这个问题是因为`have`达到`n`正好在第一次全面覆盖时。 

另一个边缘情况是单一难度的重复频率。 即使一种困难出现多次，也只能贡献一次`have`，因此额外的副本不会过早触发竞争。 

最后一个边缘情况是连续的比赛触发因素。 比赛结束后，频率会减少一，但如果流中已经包含重复项，系统可能会立即再次符合资格。 递减循环通过更新来确保正确性`have`始终如一，因此不存在陈旧的“完全覆盖”状态。
