 ## 解决方案
 ## 问题理解

 花园被表示为`n × m`网格。 每个单元格要么包含一棵树，要么是空的。 我们需要放置一个矩形建筑区域，其边沿网格线。 矩形有尺寸`a × b`，但也可以旋转为`b × a`。 选择位置的成本是该矩形内的树木数量，因为未来建筑工地上的每棵树都必须被移除。 任务是找到所有有效展示位置中可能的最小成本。 

网格尺寸最多为 50 x 50，因此单元格总数仅为 2500。这足够小，我们可以检查许多可能的矩形，但我们仍然需要避免不必要的工作。 尝试每个可能的矩形并扫描其所有单元格的解决方案在这里是可以接受的，因为搜索空间是有限的，而如果网格增长到如下值，相同的想法会变得太慢`10^5`，即使是二次枚举也已经太昂贵了。 

主要的边缘情况来自于正确处理矩形方向和确切的边界。 

第一种情况是矩形仅在旋转后才适合。 例如：```
2 3
0 0 0
1 1 0
2 1
```答案是：```
0
```一个粗心的实现，只检查一个矩形的大小`a × b`和`a`与行对齐会失败，因为有效的位置实际上是`b × a`。 

另一种情况是当矩形覆盖整个花园时：```
2 2
1 0
0 1
2 2
```答案是：```
2
```一个意外地迭代直到`n - a`而不是`n - a + 1`会错过唯一可能的位置。 

第三种情况是没有树木的空矩形区域：```
1 3
0 0 0
1 2
```答案是：```
0
```将最小答案初始化为零而不是大值的解决方案在这些输入上仍然可以显示正确，但当每个可能的矩形都包含树时会失败。 

## 方法

 直接的方法是尝试建筑工地的所有可能的左上角。 对于每个角，我们计算所选矩形内有多少棵树，并保留最小的计数。 这种方法是正确的，因为每个有效的建筑工地都只有一个左上角，因此检查所有角会检查每个可能的答案。 

对于大小为 50 x 50 的网格，可能的位置数量最多约为 2500 个。扫描一个矩形也最多需要 2500 次操作，大约进行 625 万个单元格检查。 对于给定的限制来说，这个值足够小。 

蛮力之所以有效，是因为输入很小。 网格很小的观察结果让我们可以将问题简化为穷举搜索，而不需要高级数据结构。 前缀和也可以工作，并且对于较大的网格来说是一种有用的通用技术，但这里更简单的方法已经足够快并且更容易验证。 

两个可能的方向是唯一的额外细节。 我们进行相同的搜索`a × b`并为`b × a`当两者都是有效展示位置时。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m × a × b) | O(n × m × a × b) | O(1) | O(1) | 接受这些限制 |
 | 前缀和优化| O(n × m) | O(n × m) | 已接受 |

 ## 算法演练

 1. 读取花园网格和所需的矩形尺寸。 存储网格值，以便在搜索过程中检查每棵树。 
2. 定义接收矩形尺寸的过程`h`和`w`。 它会尝试所有可能的左上角，其中该大小的矩形仍然适合花园内。 
3. 对于每个可能的位置，通过访问所选行和列边界之间的所有单元格来计算矩形内的树数。 这直接匹配我们需要最小化的成本。 
4. 当某个放置包含的树少于所有先前放置的树时，更新当前最小值。 
5. 运行程序`a × b`。 如果旋转后的矩形`b × a`也适合，再次运行并获得更好的结果。 

必须检查两个方向的原因是该问题允许旋转施工区域。 矩形尺寸描述边长，而不是固定的行列方向。 

为什么有效：每个有效的建筑工地都对应于算法考虑的位置之一。 对于每个考虑的位置，算法都会准确计算其中的树木数量。 由于最小值是针对所有可能的位置和两个方向而取的，因此最终值是可实现的最小可移除树木数量。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    a, b = map(int, input().split())

    def check(h, w):
        if h > n or w > m:
            return 10**9

        ans = 10**9

        for i in range(n - h + 1):
            for j in range(m - w + 1):
                trees = 0
                for x in range(i, i + h):
                    for y in range(j, j + w):
                        trees += grid[x][y]
                ans = min(ans, trees)

        return ans

    answer = check(a, b)
    answer = min(answer, check(b, a))

    print(answer)

if __name__ == "__main__":
    solve()
```这`check`函数执行对一个方向的完整搜索。 第一个条件拒绝无法容纳的矩形，这可以防止无效的循环范围，并且还可以干净地处理旋转情况。 

循环结束`i`和`j`枚举每个可能的左上角。 限制使用`n - h + 1`和`m - w + 1`因为最后一个有效的起始位置正是矩形接触花园底部或右边缘的位置。 

内部循环对当前矩形内的单元格进行计数。 由于网格尺寸很小，这种重复计数比维护额外的前缀数组更简单。 

最后两个调用处理两个允许的方向。 维度可能相等，在这种情况下，第二次调用会重复相同的搜索，但成本仍然远低于限制。

 ## 边缘情况

 当只有旋转才能放置时，算法会单独尝试第二个方向。 为了：```
2 3
0 0 0
1 1 0
2 1
```第一次搜索被拒绝`2 × 1`仅当它不适合所需的方向时，而旋转的`1 × 2`搜索找到一个空白区域并返回`0`。 

当矩形接触到边框时，`+1`在循环限制中允许检查最后一个有效的左上角。 为了：```
2 2
1 0
0 1
2 2
```只有一种可能的放置位置。 该算法访问它并对两棵树进行计数。 

当所有单元都包含树时，最小值不能为零。 答案从一个大值开始，并且仅在评估实际放置后才被替换，因此该算法返回真正的最小树数而不是默认值。
