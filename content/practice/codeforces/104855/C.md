 ## 解决方案
 ## 问题理解

 我们得到了一个圆形排列的盒子，每个盒子都包含一些相同的物品。 一个人从第一个盒子开始，重复执行固定的例程：如果当前盒子仍然有物品，则她恰好删除一个物品并增加运行计数器，然后移动到下一个盒子。 如果当前的盒子已经是空的，她只需跳过移除步骤并继续前进。 这会无限期地持续下去，直到所有盒子都变空。 

我们必须计算的关键数量不是最终吃掉的物品总数（它只是所有值的总和），而是更动态的东西：对于每个盒子索引，我们想知道在特定盒子第一次变空的确切时刻吃掉的物品总数。 

这些约束意味着所有测试用例中的框总数最多为 200,000 个，而单个值可以大到 10^9。 这会立即排除任何每步减少一项的模拟。 一个简单的过程可能需要每个完整周期的所有 a_i 操作的总和，并且由于行走是循环的，因此访问次数很容易达到 O(n * max(a_i))，这是完全不可行的。 

打破天真的方法的一个微妙问题是，空虚时间并不是独立的。 例如，如果一个盒子具有非常大的值，那么在较小的盒子完成后很长时间内，它会继续为循环做出贡献，这会改变这些较小的盒子变空的时间。 任何尝试独立处理框或假设单遍的解决方案都是不正确的。 

作为具体的失败案例，请考虑 n = 3、a = [100, 1, 1]。 框 2 和框 3 很快就会被清空，但框 1 会在很长一段时间内主导该过程。 一种幼稚的“单独处理每个盒子”的方法可能会假设每个盒子按照其自身价值的比例完成，忽略了盒子 1 保持循环活动并夸大系统稳定之前发生的完整旋转次数的事实。 

## 方法

 直接模拟遵循字面上的规则。 我们让指针在索引中循环，尽可能递减，并记录每个框达到零的时刻。 这是正确的，但代价高昂：每一步都从某个盒子中精确减少一个单位，因此我们总共执行 sum(a_i) 操作。 值高达 10^9，这远远超出了任何限制。 

如果我们将时间视为离散的全局步骤而不是每个框的操作，则过程的结构更容易理解。 每个步骤对应于按循环顺序对某个框的一次访问。 在长度为 n 的一个完整循环中，每个非空框恰好贡献一个减量。 这意味着在一个完整的循环中，每个框都会减一，直到达到零，并且当至少一个框不为零时，该过程会继续。 

关键的观察是反转视角：我们不是模拟时间向前，而是根据它存活的完整周期和部分周期来确定每个盒子在哪个全局时间完成。 如果一个盒子的值为 a_i，则它在 a_i 对其自身的完整“访问”期间保持活动状态，但这些访问分布在整个周期中。 每个完整周期都会将每个活动盒子减少 1，因此在 k 个完整周期之后，每个盒子都会丢失 k 个单位。 因此，一个盒子在a_i循环后变空，但具体的时刻取决于其他盒子如何提前终止并缩短过程。 

该问题相当于以 a_i 的降序处理框，同时跟踪每个框消失之前有效需要多少个完整周期。 一旦考虑了一个盒子，我们就可以计算它还需要多少次完整旋转才能达到零，因为一些较早的盒子可能已经被删除并且不再参与未来的循环。

这导致了一个经典的离线排序策略：我们从最高的 a_i 向下处理盒子，维持循环中有多少元素仍然“活着”。 每次处理新值时，我们都会计算之前的完整周期加上剩余的部分周期所贡献的总步数，直到该框完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(a_i 总和) | O(n) | 太慢了 |
 | 排序+循环核算| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将这个过程重新解释为在当前一组活动框上重复完整的循环。 

1. 将每个框与其索引和初始值相关联，并按 a_i 的降序对框进行排序。 这种排序让我们可以推断盒子何时“退出”流程。 
2. 维护一个变量cnt，表示有多少个盒子在循环中仍然处于活动状态。 最初 cnt = n，因为所有盒子都参与。 
3. 维护一个运行指针时间，该时间表示迄今为止在所有组合的盒子上执行的项目移除总数。 这实际上是全球时间表。 
4. 按照 a_i 的降序处理框。 当我们到达值为 x 的框时，我们将其解释为在当前活动集清空之前恰好存活了 x 个完整周期。 每个完整周期都会贡献一次影响此框的 cnt 操作。 
5. 因此，该框完成的时刻是 time + x * cnt。 我们将此记录为答案。 
6.处理完这个box后，我们将cnt减1，因为这个box不再参与以后的循环。 由于周期缩短，剩余的盒子现在将更快完成。 
7. 继续，直到处理完所有框，然后将结果映射回原始索引。 

关键的微妙之处在于，排序确保我们始终按照盒子从系统中消失的顺序对其进行处理。 一旦考虑到较大的盒子，它就会有效地减少所有剩余盒子的周期长度，这正是实际过程中发生的情况。 

### 为什么它有效

 在任何时刻，所有活动框都以固定的循环顺序被访问，并且每个完整周期都会将每个活动框减少一个单位。 这意味着系统分阶段演化，每个阶段对应于当前活动集的一次完整遍历。 按值排序可以保证我们以正确的顺序模拟这些阶段结束：最大值在大多数阶段中存活下来，因此它们定义了周期大小的最早的结构变化。 因为每个盒子在每个周期只贡献一个单位，直到它消失，所以将其值乘以当前周期大小即可捕获其在全局时间中的总贡献，并且删除它会减少与真实动态一致的未来周期长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        arr = [(a[i], i) for i in range(n)]
        arr.sort(reverse=True)
        
        ans = [0] * n
        cnt = n
        cur_time = 0
        
        for val, idx in arr:
            ans[idx] = cur_time + val * cnt
            cur_time += val
            cnt -= 1
        
        print(*ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个值与其原始索引配对，以便在排序后可以恢复结果。 按降序排序可确保我们按照盒子有效停止对循环做出贡献的顺序处理盒子。 

变量 cnt 跟踪有多少个框仍然处于活动状态，这直接对应于在一个完整周期中访问了多少个位置。 变量 cur_time 累积已完成阶段的贡献。 当我们分配 ans[idx] 时，我们通过组合已完成的周期及其自身的剩余贡献（按当前周期长度缩放）来计算此框完成时的确切全局步骤。 

一个常见的错误是忘记 cnt 在处理每个框后发生变化，这会错误地假设静态循环长度。 减少 cnt 至关重要，因为一旦盒子空了，未来的循环就不再包含它，从而减少了所有剩余盒子所需的时间。

 ## 边缘情况

 当 n = 1 时，系统没有循环效应。 单个盒子被重复访问，但没有其他位置，因此每个单元被顺序消耗，完成时间正好是a_1。 该算法处理此问题是因为 cnt 从 1 开始，并且在赋值之前不会改变，因此 ans[0] 变为 0 + a_1 * 1。 

对于相同的值，例如 [k, k, k]，所有框都按某种顺序处理，但每个框都会看到递减的循环长度 3、2、1。根据索引，输出按某种顺序变为 k·3、k·2、k·1。 该算法正确地反映了这一点，因为每次删除都会均匀地减少 cnt 并将相同的公式结构应用于每个元素。
