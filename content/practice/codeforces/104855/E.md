 ## 解决方案
 ## 问题理解

 给定三个长度相等的数组，我们的任务是构建从 1 到 n 的索引排列。 对于每个位置 i，排列中分配给该位置的值决定了我们在 i 处收集三个奖励中的哪一个。 如果选择的数字 p[i] 小于 i，我们就得到 a[i]。 如果它等于 i，我们就得到 b[i]。 如果它大于 i，我们就得到 c[i]。 目标是为每个数字分配一次，以便使所有位置收集的总奖励最大化。 

关键的困难在于，每个索引都根据其使用方式提供奖励，同时消耗排列中的唯一值。 这就产生了一种全局耦合：选择尽早放置一个大值可能有助于一个位置，但会限制其他地方的未来选择。 

约束很大：每个测试用例 n 最多可达 200000，所有测试用例的总和也是 200000。这立即排除了任何尝试所有排列的解决方案，甚至排除了任何二次方的解决方案，例如尝试所有交换或每个测试用例运行一个流程。 我们被迫采用每个测试用例 O(n log n) 或 O(n) 的方法。 

三种奖励类型之间的对称性产生了微妙的边缘情况。 一个幼稚的贪心算法在本地决定是将 i 分配给自己、更小还是更大的东西，可能会失败，因为它忽略了每个分配都有一个匹配的对应项。 例如，如果一个位置使用“大于”分配，则其他某个位置必须将该大值用作“小于”分配。 忽略这种配对会导致不一致的结构，看起来局部最优，但全局不可行。 

## 方法

 暴力方法会尝试 1 到 n 的所有排列并计算每个排列的分数。 这是正确的，因为它直接评估定义，但这是不可行的，因为有 n！ 排列，即使 n 小到 20，这也是不可能的。 

一个稍微聪明一点的粗暴想法是尝试根据局部增益贪婪地分配值：对于每个位置 i，通过选择最佳的可用未使用数字来选择是否使 p[i] < i、p[i] = i 或 p[i] > i。 这会失败，因为一个索引的选择改变了所有剩余索引的可用性结构。 例如，尽早选择一个较大的数字来满足“p[i] > i”偏好可能会阻止另一个索引从其自己的分配中实现更高的增益。 

关键的观察是每个索引 i 可以被认为具有三个选项，但可行性约束完全来自排列结构。 如果我们想象固定哪些索引被分配固定点，则其余元素必须在“较小侧”和“较大侧”位置之间形成双射。 这表明我们应该将决策分成结构化的匹配过程，而不是独立的贪婪选择。 

解决此类问题的标准方法是按优先级对索引进行排序，然后首先贪婪地匹配最“昂贵”的机会，确保保留高价值的交互。 在这里，结构进一步简化：我们可以将问题视为通过确定相对方向和按排序顺序配对元素来构建排列，从而将其简化为受控分配问题。

 | 蛮力 | O(n!) | O(n) | 太慢了 |

 ## 算法演练

 其核心思想是根据指数是否最好被视为“偏好小值”、“偏好定点”或“偏好大值”将指数分为三组，但我们不是硬分类，而是根据选择之间的潜在增益差异对指数进行排序来构建排列。

1. 对于每个索引 i，计算偏好 a[i] 和 c[i] 之间的增益差异。 具体来说，定义一个优先级值，该值捕获 i 是否因位于排列的“左侧”或“右侧”而受益更多。 
2. 按此优先级对所有索引进行排序。 排序顺序决定哪些位置应先被视为“小消耗”，哪些位置应稍后被视为“大生产”。 这种排序确保首先处理对一侧具有更强偏好的索引，从而避免以后发生冲突。 
3. 维护两个指针，一个从排列范围内的最小可用值开始，一个从排列范围内的最大可用值开始。 
4. 按排序顺序遍历索引。 对于每个索引 i，决定是从左指针、右指针分配一个值，还是分配 i 本身。 
5. 如果与将 i 强制分配到任一侧相比，分配 i 本身会产生最高的直接贡献 b[i]，并且如果 i 仍然可用，则分配 p[i] = i 并将 i 从可用池中删除。 
6. 否则，比较放置较小的值（左指针）或较大的值（右指针）是否会为该索引带来更好的增益。 如果 a[i] 优于 c[i]，则分配最小的可用值； 否则分配最大的可用值。 
7. 赋值后移动相应的指针并继续，直到处理完所有索引。 

关键的想法是，只要固定点明显有利，就会贪婪地处理它们，而剩余的指数则分为两个单调组，从值范围的两端填充。 

### 为什么它有效

 排列约束强制每个值只能使用一次，因此任何策略都必须在全局范围内将“小分配”与“大分配”配对。 按偏好对指数进行排序可确保尽早满足各方最强烈的需求，此时灵活性最高。 一旦索引被承诺位于左侧或右侧，它仅消耗边界值，保持单调结构。 这保证了后面的分配不会阻止更好的早期选择，因为所有决策都是按照全局一致的偏好强度顺序做出的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        c = list(map(int, input().split()))

        idx = list(range(n))

        # priority: how much we prefer left (a) vs right (c)
        idx.sort(key=lambda i: a[i] - c[i])

        p = [0] * n
        used = [False] * (n + 1)

        l, r = 1, n

        for i in idx:
            # try fixed point if possible
            if not used[i + 1] and b[i] >= max(a[i], c[i]):
                p[i] = i + 1
                used[i + 1] = True
                continue

            # otherwise assign to better side
            if a[i] >= c[i]:
                while used[l]:
                    l += 1
                p[i] = l
                used[l] = True
                l += 1
            else:
                while used[r]:
                    r -= 1
                p[i] = r
                used[r] = True
                r -= 1

        print(*p)

if __name__ == "__main__":
    solve()
```该实现首先根据 a[i] - c[i] 的差值对索引进行排序，这会使早期处理偏向于更喜欢较小分配的索引。 这使得从左到右的填充能够一致地工作，而不会出现以后的冲突。 

使用的数组跟踪已分配的排列值，包括固定点。 指针 l 和 r 维护最小和最大可用值，跳过已使用的值。 

定点条件检查 b[i] 是否足够强大以证明将 i 分配给自身是合理的。 如果是这样，我们立即锁定它。 这可以防止在保持固定更好的位置上浪费极端值。 

之后，根据 a[i] 或 c[i] 是否较大，将剩余索引贪婪地分配给左端或右端。 排序顺序确保这个贪婪决策不会与之前的分配相矛盾。

 ### 示例 1

 我们跟踪按 a[i] - c[i] 排序的索引，然后逐步赋值。

 | ---| ---| ---| ---| ---| ---|

 该轨迹显示了左指针和右指针如何逐渐向中心折叠，从而强制进行完全排列。 

### 示例 2

 取 n = 4，具有混合偏好，其中一个索引强烈偏好固定点，一个偏好小，而其他索引偏好大。 

| 步骤| 索引我| 决定| 我| r | p|
 | ---| ---| ---| ---| ---| ---|

 这证实了固定点不会干扰剩余元素的单调填充。

 ## 边缘情况

 一个重要的边缘情况是，所有值都强烈倾向于固定点，这意味着对于每个 i，b[i] 都大于 a[i] 和 c[i]。 在这种情况下，算法会将所有位置分配为排序通道中的固定点，立即消耗所有索引。 指针逻辑永远不会被触发，这是正确的，因为任何偏离固定点的行为都会严格降低总分。 

当所有 a[i] 远大于 c[i] 时，会发生另一种边缘情况，导致所有索引更喜欢左侧。 排序顺序确保了索引的处理方式越来越优先于左赋值，并且 l 指针从 1 干净利落地前进到 n，而不会发生冲突。 没有索引会尝试获取已经使用过的值，因为使用过的跟踪可以保证一致性。 

第三种边缘情况正好相反，其中所有 c[i] 支配 a[i]。 然后 r 指针从 n 向下移动到 1，再次产生没有重叠的有效排列。 两侧之间的对称性确保算法即使在极端倾斜的情况下也能表现一致。
