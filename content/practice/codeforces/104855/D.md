 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每条边都带有一个称为颜色的标签。 从节点 1 开始，我们可以沿着有向边行走任意多次，并且可以重新访问节点并重用边。 唯一的限制是，当我们遍历一条路径时，我们不允许取两条具有相同颜色的连续边。 我们的任务是确定在此约束下从节点 1 可以到达哪些节点。 

因此图本身是静态的，但游走的有效性取决于最后使用的边的历史记录。 这意味着可达性不仅是节点的属性，而且是由节点和用于到达那里的最后一条边颜色组成的对的属性。 

限制很大：所有测试用例的节点和边的总数可以达到一百万。 这立即排除了任何尝试显式模拟路径或探索边缘序列而无需记忆的解决方案。 路径上的任何幼稚 DFS 或 BFS 都会爆炸，因为路径可能由于循环而任意长，并且可以在不同的最后颜色上下文下重新访问同一节点。 

当相同颜色的多个边缘形成循环时，会出现微妙的边缘情况。 例如，如果节点 1 具有 1 -> 2（红色）、2 -> 3（红色）、3 -> 1（红色）这样的自循环结构，那么虽然在普通图意义上所有节点在结构上都是可达的，但在彩色约束下只有节点 2 是可达的，因为在取出一条红边后，不能立即使用第二条红边。 

当可以通过两种不同颜色到达节点，但只有其中一种允许进一步前进时，就会出现另一种极端情况。 例如，如果通过红色边缘到达节点会阻塞所有传出边缘，因为它们也是红色的，而通过蓝色边缘到达节点允许继续，则天真的访问[节点]方法将错误地合并这些状态，并且高估或低估可达性。 

## 方法

 暴力方法会尝试探索从节点 1 开始的所有可能的路径，同时跟踪最后使用的边缘颜色。 我们可以将其建模为状态（节点、last_color）上的 DFS 或 BFS。 在每个状态中，我们尝试颜色与 last_color 不同的所有传出边缘。 

这种方法是正确的，因为它直接强制执行约束，但它会遭受状态空间的根本性爆炸。 在最坏的情况下，每个节点都可以通过许多不同的最后颜色到达，并且每个边缘转换都会生成另一个状态。 如果我们将 m 表示为边数，则可能的颜色数也可以达到 m，因此在病理情况下状态图可以接近 O(nm)。 这对于 10^6 的总输入大小来说太大了。 

关键的观察是，虽然最后一个颜色对于正确性很重要，但我们只需要知道在任何有效的最后一个颜色下是否可以到达节点，而不是所有可能的最后一个颜色。 这表明，如果我们能够有效地表示转换并避免重新审视等效情况，则状态上的 BFS 仍然可行。 

因此，我们将图扩展为分层状态图，其中每个状态都是（节点，last_color），但我们通过隐式存储访问过的转换来避免显式存储每个节点的所有颜色。 每当 c_prev != c_i 时，每个有向边都会成为从 (u, c_prev) 到 (v, c_i) 的过渡。 诀窍是从 (1, 0) 开始运行 BFS，其中 0 表示“没有先前的颜色”，并将状态标记为已访问以防止重复。 

因为每个状态最多处理一次，并且每个边缘最多引起恒定数量的跨状态转换，所以总复杂度与实际发现的有效状态转换的数量成线性关系，其边界为 O(n + m)。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（颜色上的路径 DFS）| 最坏情况下呈指数增长 | O(纳米) | 太慢了 |
 | 状态 BFS（节点，最后一种颜色）| O(n + m) 摊销 | O(n + m) | 已接受 |

 ## 算法演练

 我们将问题重新表述为在扩展的状态空间中搜索，其中每个状态都会记住最后使用的边缘颜色。 

1. 我们从状态 (1, 0) 开始，其中 0 表示尚未获取边。 这允许使用来自节点 1 的任何传出边。 此初始化是必要的，因为第一步没有颜色限制。 
2. 我们构建一个邻接列表，其中每个条目存储对（邻居、颜色）。 这使我们能够有效地枚举节点的所有传出转换。 
3. 我们使用状态队列（节点、last_color）运行 BFS。 每次我们将状态 (u, c_prev) 出队时，我们都会探索所有传出边缘 (u -> v, c_i)。 如果 c_i 与 c_prev 不同，则转换有效。 
4. 对于每个有效的转换，我们移动到状态 (v, c_i)。 如果之前没有访问过该状态，我们将其标记为已访问并将其推入队列。 这确保我们不会重新处理相同的情况，从而防止指数爆炸。 
5. 我们维护一个单独的数组reachable[node]，记录某个节点在任何状态下是否曾经被访问过。 每次我们到达一个新的状态 (v, c_i) 时，我们将reachable[v] 标记为 true。 
6. BFS完成后，我们输出reachable[node]为true的所有节点。 

正确性取决于仅一次探索所有可能的有效最后颜色上下文，确保不会错过任何有效的行走，同时防止循环引起的无限重访。 

### 为什么它有效

 核心不变量是，每当处理状态 (u, c_prev) 时，BFS 就已经发现了以 u 结尾且最后边缘颜色为 c_prev 的所有有效彩色路径。 有效路径的任何扩展都必须来自这样的状态，并且每个有效扩展完全对应于具有不同颜色的传出边缘。 由于每个状态最多被访问一次，并且所有有效的扩展都被探索，因此不会错过任何可到达的节点。 相反，每个访问的状态都对应于一条有效的彩色路径，因此没有错误的节点被标记为可达。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, c = map(int, input().split())
            g[u].append((v, c))

        # visited states: (node, last_color)
        # since colors are up to m, we store dict per node
        visited = [set() for _ in range(n + 1)]

        q = deque()
        q.append((1, 0))
        visited[1].add(0)

        reachable = [False] * (n + 1)
        reachable[1] = True

        while q:
            u, last_c = q.popleft()

            for v, c in g[u]:
                if c == last_c:
                    continue
                if c in visited[v]:
                    continue
                visited[v].add(c)
                reachable[v] = True
                q.append((v, c))

        res = [str(i) for i in range(1, n + 1) if reachable[i]]
        print(" ".join(res))

if __name__ == "__main__":
    solve()
```该实现准确地反映了状态 BFS。 邻接列表存储端点和边缘颜色，以便可以在每个边缘的恒定时间内检查转换。 每个节点都维护所访问的结构，并以上次使用的颜色为键控，这可以防止重新访问相同的状态对。 

一个关键细节是用颜色 0 初始化 BFS。该哨兵确保始终可以获取第一个边缘，无论其颜色如何。 另一个微妙之处是在我们发现新状态时标记reachable[v]，而不是在我们将其出队时标记，这避免了丢失在新发现的状态中首先到达的节点。 

## 工作示例

 ### 示例 1

 输入图：1 -> 2（红色）、2 -> 3（蓝色）、1 -> 3（红色）

 我们模拟状态上的 BFS。 

| 步骤| 状态（节点，颜色）| 过渡| 新州 |
 | ---| ---| ---| ---|
 | 1 | (1, 0) | (1, 0) | 从1取红到2，红到3 | （2，红色），（3，红色）|
 | 2 | （2，红色）| 红色 -> 蓝色边缘允许为 3 | （3，蓝色）|
 | 3 | （3，红色）| 没有传出有效分机 | 无 |
 | 4 | （3，蓝色）| 没有传出边缘 | 无 |

 所有节点 1、2、3 变得可达。 

这表明可以在多个颜色上下文中到达同一节点 (3)，并且必须跟踪两者。 

### 示例 2

 输入图：1 -> 2（红色）、2 -> 3（红色）、3 -> 4（红色）、2 -> 4（蓝色）

 | 步骤| 状态| 过渡| 新州 |
 | ---| ---| ---| ---|
 | 1 | (1, 0) | (1, 0) | 1 -> 2（红色）| （2，红色）|
 | 2 | （2，红色）| 不能对 3 使用红边，可以对 4 使用蓝边 | （4，蓝色）|
 | 3 | （4，蓝色）| 终端| 无 |

 节点 3 永远不会到达，因为到它的所有路径都会强制使用连续的红色边缘。 节点 4 可通过颜色更改到达。 

这表明可达性取决于颜色过渡，而不仅仅是图形连接性。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) 摊销 | 每个状态（节点，last_color）都会被访问一次，并且每个边在每个有效的颜色转换中最多被处理一次 |
 | 空间| O(n + m) | 邻接列表加上每个节点的访问状态跟踪

 测试用例的总输入大小以一百万个节点和边为界，并且每个状态转换都是恒定时间。 这确保了解决方案在限制范围内舒适地运行。

 ## 边缘情况

 当一个节点可以通过多种传入颜色到达，但只有一种可以进一步遍历时，就会出现一种微妙的情况。 考虑从节点 1 通过红色到达节点 2，从节点 1 通过蓝色到达节点 2。如果从 2 出发的所有出边都是红色，则只有状态 (2，蓝色) 可以继续，而 (2，红色) 是死胡同。 该算法正确地分离了这些状态，因为访问是按节点和颜色进行跟踪的，因此这两个状态都是独立探索的。 

另一种情况是第一次发现节点处于“死”颜色状态时。 即使第一个发现不会导致任何结果，reachable[node] 仍然设置为 true，并且稍后有效的颜色状态也可能到达它。 这确保了正确性，因为节点级可达性独立于特定状态是否可以继续。
