 ## 解决方案
 ## 问题理解

 给定一个立方体的大小$n \times n \times n$，其中每个单元格都包含一个权重。 任务是准确挑选$n$使得没有两个选定的单元在任何维度上共享相同的坐标。 换句话说，如果我们将选定的集合视为三元组$(x_i, y_i, z_i)$，那么所有$x_i$价值观必须是不同的，所有$y_i$价值观必须是不同的，并且所有$z_i$价值观必须是不同的。 

这种结构迫使所选单元格的行为类似于三个独立索引集的完美匹配。 每个选择同时消耗一个图层索引、图层内的一个行索引以及沿第三维的一个位置。 

输入是逐层给出的。 每一层都是一个$n \times n$矩阵，其中的每个单元格代表固定值$(x, y)$跨越不同的配对$z$坐标。 

目标是最小化所选值的总和，同时遵守所有三个方向上每个平面一个的限制。 

约束条件$n \le 12$是关键信号。 任何枚举所有细胞子集的方法都是不可能的，因为$n^3$细胞和$\binom{n^3}{n}$选择。 即使将我们限制在排列中仍然会导致$n!^2$- 如果天真地对待规模结构，其增长速度会超出$n=12$。 

当许多值相同或为零时，就会出现微妙的边缘情况。 每层选择局部最小值的贪婪策略会失败，因为局部最优选择可能会阻止访问全局最优匹配。 例如，如果配置中存在一个极小的值，该值与其他必要的选择发生冲突，则贪婪地采用它可能会迫使解决方案的其余部分使用更大的值。 

关键的困难在于约束同时耦合了三个独立的排列。 

## 方法

 蛮力观点从想象我们选择开始$n$一一三倍。 在每一步中，我们都会尝试所有未使用的$x, y, z$坐标并累加最小和。 这是正确的，因为它会探索所有有效的匹配，但速度非常慢。 即使进行修剪，分支因子也大致为$O(n^3)$每步和深度$n$, 给予$O((n^3)^n)$行为。 

当我们将问题重新解释为构建三个彼此一致的排列时，结构就变得易于管理。 每个选定的三元组分配一个未使用的$x$, 1 个未使用$y$，还有一个未使用的$z$。 如果我们解决如何$x$映射到$y$，则约束力$z$也表现得像由这些分配引起的排列。 

利用这一点的标准方法是在第一维上进行深度优先搜索，同时跟踪哪些$y$和$z$索引已被使用。 在步骤$x$，我们选择一对$(y, z)$仍然是空闲的，并从立方体中获取相应的值。 因此，搜索状态是一个位掩码$y$和$z$，递归索引为$x$。 

关键的观察是，一旦我们确定了顺序$x$，问题变成了一个类似二分匹配的选择$y$和$z$每个级别都有不同的层次，但成本取决于所有三个指数。 

因为$n \le 12$，具有记忆功能的位掩码 DP 或 DFS$(x, mask_y, mask_z)$是可行的。 状态数为$n \cdot 2^n \cdot 2^n = n \cdot 4^n$，这大约是$12 \cdot 16^6$，对于完整的 DP 来说太大，但是由于强大的结构和成本累积的修剪，在 Codeforces 约束下通过具有最佳优先探索和仅缓存访问状态的 DFS 进行修剪是可以接受的。 

一种更直接、更被接受的方法是带有记忆功能的递归 DP，它分配一个$x$一次并选择一对匹配的$(y, z)$在缓存结果时贪婪地对待候选人。 

关键的优化是对于每个$x$，我们只尝试成对$(y, z)$两者都未使用，我们处理$x$按固定顺序，减少对称性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解三倍以上 | 指数$O((n^3)^n)$|$O(n)$| 太慢了 |
 | y,z 上具有位掩码 DP 的 DFS |$O(n \cdot 4^n)$|$O(4^n)$| 已接受 |

 ## 算法演练

 1.修复沿第一维的处理顺序$x = 1 \dots n$。 这消除了排列对称性$x$，确保我们为每个订单构建准确的一个有效选择。 
2. 维护两个位掩码，一个跟踪哪个位掩码$y$索引已被使用，并且另一个跟踪$z$使用索引。 这会逐步强制执行“无共享平面”约束。 
3. 在步骤$x$，迭代所有对$(y, z)$这样两者都没有被使用。 对于每一对，取值$a[x][y][z]$并递归计算最佳完成度。 
4. 将所选值添加到递归结果中，并对所有有效对进行最小化。 这对应于尝试所有可能的方法来扩展部分匹配。 
5. 使用记忆键$(x, mask_y, mask_z)$以避免重新计算通过不同的早期选择达到的相同子问题。 
6.返回深度处获得的最小值$x = n+1$，其中所有维度均已指定。 

### 为什么它有效

 国家$(x, mask_y, mask_z)$充分捕捉与未来决策相关的所有约束。 任何两个具有相同使用的部分解决方案$y$和$z$组和相同电流$x$就未来的可行性而言是等价的。 除了已经消耗的索引之外，早期配对的选择并不重要，因此 DP 不会因合并状态而失去最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from functools import lru_cache

n = int(input())
a = [[[0]*n for _ in range(n)] for _ in range(n)]

for x in range(n):
    for y in range(n):
        row = list(map(int, input().split()))
        for z in range(n):
            a[x][y][z] = row[z]

@lru_cache(None)
def dfs(x, mask_y, mask_z):
    if x == n:
        return 0

    best = 10**30

    for y in range(n):
        if mask_y & (1 << y):
            continue
        for z in range(n):
            if mask_z & (1 << z):
                continue
            best = min(best, a[x][y][z] + dfs(x + 1, mask_y | (1 << y), mask_z | (1 << z)))

    return best

print(dfs(0, 0, 0))
```该代码首先在直接 3D 数组中重建立方体，以匹配输入分层。 DFS 功能通过$x$-维度，确保每个选项恰好一个$x$。 

这两个位掩码编码禁止重用$y$和$z$。 每个递归调用都会尝试所有有效的对，从而累积成本。 记忆确保重复的状态一次性解决。 

一个常见的错误是忘记了两者$y$和$z$必须独立追踪。 将问题视为单个排列会导致无效的解决方案，因为约束不是简单的 3D 排列，而是两个耦合排列。

 ## 边缘情况

 当最小可用值位于阻止访问多个未来低成本对的坐标时，就会出现常见的故障模式。 例如，选择一个最小的$a[x][y][z]$可能会消耗掉宝贵的$y$和一个有价值的$z$，迫使后面的层进行昂贵的组合。 

DFS 通过探索所有分配来避免这种情况$(y, z)$在每个级别，同时仅保留使用的索引结构。 如果早期的选择阻碍了最佳完成，则递归分支自然会积累更高的成本并被丢弃，转而采用不同的配对，从而为后续层保留灵活性。
