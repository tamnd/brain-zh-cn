 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们希望将其转换为非递减序列。 唯一允许的工具是一个特殊的排序例程，其行为类似于选择排序变体：它重复将固定位置与所有后续位置进行比较，并在发现较小值时进行交换。 该例程的成本与段长度的平方成正比，因此对长度的段进行排序$i$成本$i^2$。 

我们总共最多可以调用该例程两次。 每次调用必须对数组的前缀或后缀进行操作，并且我们可以每次选择长度。 一次调用即可对第一个进行排序$i$元素，一次调用即可对最后一个元素进行排序$i$元素，按任何顺序。 

任务是选择最多两个这样的操作，以便最终的数组排序，同时最小化总成本。 

约束条件$n \le 10^6$立即排除任何模拟排序或尝试所有成对操作的方法。 即使是单个$O(n^2)$扫描是不可能的。 该解决方案必须依赖于关于阵列结构的线性或近线性推理。 

一个关键的微妙之处在于，该操作的行为并不像对孤立的任意子数组进行完全排序。 它创建了一个非常具体的“部分纠正”结构：在前缀操作之后，只有第一个段保证排序，但它也可能包含最初属于其他地方的元素，从而影响第二个操作的可行性。 

当数组已经排序时，当除了开头或结尾处的单个错位块之外几乎排序时，以及当需要在两个方向上进行交错校正时，会出现边缘情况。 一种假设“如果数组未排序，一个前缀排序 + 一个后缀排序总是足够的”的简单方法在反转分布在边界上的模式上失败，例如像这样的数组$[2,1,3,4,5]$，其中单独的后缀修复无济于事，单独的前缀修复会过度纠正。 

## 方法

 如果我们忽略成本限制，我们可以尝试所有可能的操作选择。 这意味着选择前缀长度$i$（或跳过它），选择后缀长度$j$（或跳过它），按两个顺序应用它们，并模拟结果数组。 每次模拟费用$O(n)$，并且有$O(n^2)$成对、给予$O(n^3)$总的复杂性。 这远远超出了任何可行的限度。 

即使我们尝试更聪明地一次修复一个端点，主要困难仍然存在：在一次操作之后，数组没有全局排序，第二次操作的效果取决于第一个操作如何重新分配值。 

关键的观察结果是，该操作对于排序的前缀和后缀而言是单调的。 在前缀长度排序之后$i$，第一个$i$元素恰好变成$i$按排序顺序的前缀的最小元素。 同样，在后缀排序长度之后$i$，最后一个$i$元素在内部进行排序，但它们不一定是全局正确的后缀，除非它们已经包含正确的多重集。 

这导致了一种简化：最终的排序数组可以通过使前缀正确和后缀正确来实现，并且它们之间的相互作用仅取决于数组从“已经正确”过渡到“需要更正”的单个边界点。 

该问题简化为识别数组中已与排序版本匹配的位置，然后决定是否需要一次操作或两次操作来修复剩余的未排序区域。 每个操作的成本仅取决于其选择的长度，因此我们需要覆盖所有无序的最小片段。 

我们计算数组的排序版本并将其与原始版本进行比较。 让$l$是它们不同的第一个索引，并且$r$它们不同的最后一个索引。 外面的一切$[l, r]$已经是正确的了。 

从这里开始，只有一些有意义的策略：

 我们可以使用 size 的一个前缀操作对整个数组进行排序$n$。 这总是有效的。 

如果无序排列在一侧，我们可以尝试用一个前缀或一个后缀来修复数组。 

否则，我们使用两种操作：一种前缀覆盖部分区间，另一种后缀覆盖其余部分。 最佳分割始终与边界对齐$l$或者$r$，因为严格在失配区间之外应用操作不会改变正确性，但会增加成本。 

这将问题减少到检查源自的恒定数量的候选配置$l$和$r$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(n^3)$|$O(n)$| 太慢了|
 | 边界分析|$O(n \log n)$或者$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 构建数组的排序副本。 这给出了我们必须达到的目标配置。 我们仅将其用于比较，而不是模拟。 
2.找到最左边的索引$l$其中原始数组与排序数组不同。 这标志着正确性首先被打破的地方。 
3.找到最右边的索引$r$其中原始数组与排序数组不同。 这标志着正确性的结束。 
4. 如果不存在这样的索引，则数组已排序，因此答案为零。 
5.考虑使用单个长度前缀操作对整个数组进行排序的成本$n$，即$n^2$。 
6、检查单个前缀操作是否为length$r+1$就足够了。 这个想法是，如果之后的一切$r$已经正确并且前缀固定到$r$恢复全局顺序，则其余后缀不受影响且有效。 
7、同样检查是否有长度的单个后缀操作$n-l$就足够了。 
8. 最后，考虑两种操作的分割：一个前缀覆盖$[0, l + k]$和一个后缀覆盖$[l + k, n-1]$对于一些边界选择。 当前缀和后缀操作恰好在候选边界处对齐时，就会发生最佳分割$l$和$r$，因为超出此范围的任何操作只会增加成本，而不会提高正确性。 
9. 评估由边界引起的少数候选组合，并取最小成本。 

### 为什么它有效

 不匹配区间$[l, r]$是顺序与目标不同的唯一区域。 任何完全超出这个区间的操作都不能减少混乱。 任何部分覆盖它但进一步扩展的操作只会增加成本而不会提高正确性。 由于允许的操作是单调的（前缀和后缀排序仅在其段内重新排序为排序状态），因此最佳解决方案必须将操作边界与$l$和$r$。 这将对分段选择的指数搜索折叠成恒定数量的有意义的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    b = sorted(a)
    
    if a == b:
        print(0)
        return
    
    l = 0
    while l < n and a[l] == b[l]:
        l += 1
    
    r = n - 1
    while r >= 0 and a[r] == b[r]:
        r -= 1
    
    ans = n * n
    
    # full prefix sort
    ans = min(ans, n * n)
    
    # prefix up to r
    # cost: (r+1)^2, but only valid if prefix fix makes whole array sorted
    def check_prefix(k):
        arr = a[:]
        i = k
        for x in range(i):
            for y in range(x + 1, i):
                if arr[x] > arr[y]:
                    arr[x], arr[y] = arr[y], arr[x]
        return arr == b
    
    def check_suffix(k):
        arr = a[:]
        start = n - k
        for x in range(start, n):
            for y in range(x + 1, n):
                if arr[x] > arr[y]:
                    arr[x], arr[x] = arr[y], arr[x]
        return arr == b
    
    for i in range(1, n + 1):
        # prefix only
        if check_prefix(i):
            ans = min(ans, i * i)
        # suffix only
        if check_suffix(i):
            ans = min(ans, i * i)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接测试候选前缀和后缀长度。 辅助例程精确地模拟 Alice 在某个段上的操作，以验证排序目标的正确性。 虽然这不是最优化的形式，但它反映了问题的结构：我们只关心一个段是否在本地被排序到正确的多重集中，以及这是否足以在全局范围内满足要求。 

关键的实现细节是忠实地再现所选段上的类似选择排序的行为。 任何偏差，例如假设简单的 sort() 调用，都会歪曲中间状态并导致不正确的可行性检查。 

## 工作示例

 ### 示例 1

 输入：```
6
3 2 5 5 4 1
```我们计算：

 已排序 = [1, 2, 3, 4, 5, 5]

 失配区间是从 l = 0 到 r = 5，因为一切都不同。 

我们评估候选人的策略。 

| 运营| 线段长度| 成本| 结果 |
 | --- | --- | --- | --- |
 | 仅前缀 | 6 | 36 | 36 未排序 |
 | 仅后缀 | 6 | 36 | 36 未排序 |
 | 前缀+后缀分割| 3 + 4（最佳对齐）| 9+16| 已排序 |

 最好的有效分解是长度为 4 的后缀，然后是长度为 3 的前缀，产生成本 25。 

这证实了最佳解决方案通常取决于中心无序块周围的重叠校正。 

### 示例 2

 输入：```
4

```已排序 = [1, 2, 3, 4]

 这里整个数组被反转，所以 l = 0 且 r = 3。 

| 运营| 线段长度| 成本| 结果 |
 | --- | --- | --- | --- |
 | 前缀(4) | 4 | 16 | 16 已排序 |

 一次操作就足够了，这表明极端无序仍然可以通过一次全局前缀校正来解决。

 ## 边缘情况

 大小为 1 的最小数组总是产生零成本，因为它已经排序并且不需要任何操作。 

已经排序的数组表明该算法必须正确检测零不匹配间隔； 任何不必要的操作都会错误地增加成本。 

完全反转的数组显示了识别单个前缀操作何时全局足够的重要性，即使数组是最大程度无序的。 

边界处的单个反转，例如$[2,1,3,4,5]$，表明局部无序通常可以用非常小的前缀来修复，而尝试更大的操作只会增加成本。 

中间反转就像$[1,3,2,4,5]$强调最佳片段必须与无序间隔精确对齐，而不是不必要地扩展到完整的前缀或后缀。
