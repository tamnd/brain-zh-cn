 ## 解决方案
 ## 问题理解

 传输的消息是汉明编码块。 一个块有`2^k`位，并且这些位的索引来自`0`到`2^k - 1`。 接收到的块可能已通过改变至多两位而被修改。 任务是确定接收到的块是否仍然有效，是否恰好有一位被损坏并识别其索引，或者是否有两位被更改且错误无法纠正。 

输入包含几个独立的块，直到文件末尾。 对于每个块，我们收到`k`然后是代表接收到的位的完整二进制字符串。 输出描述该块的状态：有效的代码字、单个损坏的位置或不可纠正的两位损坏。 

约束告诉我们需要什么样的解决方案。 自从`k`可以大到`16`，一个块可以包含`2^16 = 65536`位。 所有测试用例的总位数限制为大约一百万，因此对每个块的线性传递是预期的方法。 任何尝试可能的错误位置或与所有有效代码字进行比较的方法都是不可能的，因为搜索空间呈指数增长。 

有几种容易错过的情况，因为索引处的位`0`与其他位置的行为不同。 它是额外的奇偶校验位，因此，如果我们仅检查索引奇偶校验位，则那里的单个错误具有零位置综合症，并且可能被误认为是有效块。 

例如，这个接收到的块代表只有第一位错误的情况：```
3
10000000
```正确答案是：```
d(0) is changed
```仅计算设置位索引的异或的解决方案将计算零并错误地打印`good`。 

另一个微妙的情况是两个错误，其中一个是奇偶校验位：```
3
11000000
```正确的输出是：```
broken
```位置异或指向位置`1`，但总体奇偶校验表明有两个翻转位。 将综合症视为保证的单一错误会错误地报告`d(1) is changed`。 

## 方法

 直接的方法会尝试修复每一个可能的位。 我们可以翻转每一个`2^k`位置，检查结果块是否满足所有汉明奇偶校验条件，并确定该位置是否已损坏。 这是正确的，因为当恰好存在一个错误时，原始码字必须距接收块一位。 但是，它需要检查`2^k`候选人，以及每张支票的费用`O(k)`或者`O(2^k)`取决于实施。 为了`k = 16`，即使是更简单的版本也可以在大量输入上执行数十亿次操作。 

汉明码的结构为我们提供了一种更小的定位错误的方法。 每个非零索引都有一个二进制表示形式，每个奇偶校验条件对应于该表示形式的一位。 如果我们对包含的所有位置的索引进行异或`1`，结果是所有损坏位置的异或。 该值称为综合症。 

索引处的整体奇偶校验位`0`告诉我们有多少位被模二改变。 如果接收块中设置的比特总数具有正确的奇偶校验，则不存在奇数个变化。 将综合症与整体奇偶性结合起来给出所有可能的情况：

 如果校正子为零且整体奇偶校验正确，则该块有效。 

如果校正子非零并且整体奇偶校验不正确，则恰好改变了一位。 该综合症本身就是损坏的索引。 

如果校正子为零且整体奇偶校验不正确，则仅位`0`改变了。 

如果校正子非零并且整体奇偶校验正确，则恰好有两位发生变化，因此块被破坏。 

暴力解决方案之所以有效，是因为它搜索附近的有效代码字，但当块很大时会失败。 汉明奇偶校验已经对错误位置进行了编码，这一观察结果使我们能够将整个过程简化为一次输入扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^k * k) | O(2^k * k) | O(1) | O(1) | 太慢了|
 | 最佳 | O(2^k) | O(2^k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`k`和接收到的位串。 字符串的长度就是块的大小，`2^k`。 
2. 通过异或所有位置的索引来计算综合症`1`到`2^k - 1`包含一个`1`。 位置`0`被跳过，因为它是整体奇偶校验位并且没有索引信息。 
3. 数一下数量`1`整个接收块中的位。 该计数的奇偶校验表明是否满足整体奇偶校验条件。 
4. 使用校正子和奇偶校验结果对错误进行分类。 

如果校正子为零并且奇偶校验有效，则输出`good`。 

如果校正子非零并且奇偶校验无效，则输出校正子作为改变的位置。 

如果校正子为零并且奇偶校验无效，则输出该位置`0`改变了。 

否则，输出`broken`。 

这样做的原因是该综合症正是所有改变的位置的异或。 单个位置的改变会留下自己的索引作为综合症。 两个改变的位置产生两个不同索引的异或，奇偶校验位让我们将其与单错误情况区分开来。 

为什么有效：汉明奇偶校验方程对于有效块来说是不变的，因此包含的所有位置的异或`1`必须为零。 翻转位将其索引贡献给异或，这意味着校正子准确地包含所有错误的组合位置信息。 额外的奇偶校验位将奇数个错误与偶数个错误分开，使我们能够区分一位损坏和两位损坏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(k, s):
    n = 1 << k

    syndrome = 0
    ones = 0

    for i, ch in enumerate(s):
        if ch == '1':
            ones += 1
            if i != 0:
                syndrome ^= i

    if ones % 2 == 0:
        parity_ok = True
    else:
        parity_ok = False

    if syndrome == 0 and parity_ok:
        return "good"

    if syndrome != 0 and not parity_ok:
        return f"d({syndrome}) is changed"

    if syndrome == 0 and not parity_ok:
        return "d(0) is changed"

    return "broken"

def main():
    ans = []
    while True:
        line = input()
        if not line:
            break
        if not line.strip():
            continue
        k = int(line)
        s = input().strip()
        ans.append(solve_case(k, s))

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```实施直接遵循演练中的四个案例。 变量`syndrome`存储包含的所有非奇偶位置的异或`1`。 循环跳过索引很重要`0`，因为包含它会破坏奇偶校验位错误和正常位置错误之间的区别。 

变量`ones`计算所有设置位，包括位置`0`。 总奇偶校验确定改变的位数是奇数还是偶数。 由于该问题最多保证两次更改，因此无效的整体奇偶校验意味着恰好更改了一位。 

不需要阵列或额外的存储。 字符串被处理一次，并且所有计算都可以轻松地放入 Python 整数中，因为最大索引仅是`65535`。

 对于第一个样本：```

 ## 边缘情况

 第一种特殊情况是奇偶校验位本身存在错误。 考虑：```
3
10000000
```扫描没有发现有值的非零位置`1`，所以综合症仍然存在`0`。 然而，总个数是奇数，这意味着整体奇偶校验失败。 由于没有位置信息，唯一可能的单一错误是在索引处`0`，算法打印：```
d(0) is changed
```第二种特殊情况是两个改变的位，其中之一是奇偶校验位：```
3
11000000
```该综合症是`1`因为位置`1`对异或有贡献。 总个数是偶数，这意味着改变的位数是偶数。 由于校正子不为零，因此在问题约束下唯一可能的情况是两个损坏的位，因此算法输出：```
broken
```这正是为什么奇偶校验必须与综合症结合起来而不是单独使用综合症的原因。
