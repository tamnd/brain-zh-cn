 ## 解决方案
 ## 问题理解

 我们有一棵带有节点的有根树`1`作为根。 在无限序列的随机操作中，每次都会统一选择一个节点。 访问从根到该节点的路径，并且该路径上的每条边都将成为其父节点的首选边（如果它还不是首选边）。 任务是找出每次操作的首选子更改的长期平均数量。 答案需要模数`998244353`。 最初的说法将这些操作描述为LCT访问操作，但该解决方案不需要任何Link-Cut Tree知识。 

关键的困难在于这个过程是随机的并且永远持续下去。 我们不模拟操作。 相反，我们计算流程达到稳定行为后每个节点引起的预期变化数量。 

对于一棵树来说，最多`100000`对于每个可能的状态，任何重复模拟操作或执行与树高成比例的工作的方法都太昂贵了。 二次方法已经可以执行`10^10`最坏情况下的操作，远远超出了典型的 1 秒限制所允许的。 我们需要对树进行线性或近线性计算。 

第一个边缘情况是单节点树。 没有首选的孩子，也没有可能的改变，所以答案是`0`。```
Input
1

Output
0
```粗心的实现，假设每个节点都有父边或尝试反转`subtree_size - 1`如果不检查就会在这里失败。 

另一种边缘情况是只有一个子节点的节点。 一旦通过该节点访问了该子节点，以后通过该节点的访问就永远不会更改首选子节点。 例如：```
Input
2
1

Output
0
```根总是更喜欢它唯一的子节点，因此预期的更改次数为零。 将每次访问孩子都算作变化的公式会错误地输出正值。 

第三种边缘情况是一个节点的子节点具有非常不同的子树大小。 例如：```
Input
5
1 1 1 1

Output
0
```根有四个叶子孩子。 它的首选孩子只是被访问的四个孩子中的最后一个。 从一个孩子变为另一个孩子的概率取决于之前访问的分布，而不仅仅是孩子的数量。 同等对待所有儿童会带来错误的期望。 

## 方法

 直接的方法是模拟首选子状态。 对于每个操作，选择一个节点，从根走到该节点，并沿路径更新首选子节点。 这是正确的，因为它完全遵循流程。 然而，随着操作次数接近无穷大，所请求的值是极限。 模拟无法提供精确的模块化答案，即使在一棵深树上进行一百万次操作也可能已经太慢了。 在一连串的`100000`节点，一次操作即可触及`100000`边缘，给出大约`10^11`边缘更新`10^6`模拟操作。 

有用的观察是每个节点都可以独立分析。 考虑一个节点`u`带孩子`c1, c2, ...`。 的首选孩子`u`仅当所选节点位于这些子子树之一时才会更改。 如果选择的节点在外部`u`的子树，不涉及`u`变化。 

经过多次操作，得到了首选孩子`u`是包含下面最近访问的子子树`u`。 孩子的概率`c`当前首选与其子树的大小成正比。 如果以下子节点的节点总数`u`是`s`， 然后：$$P(c\text{ is preferred})=\frac{size[c]}{s}$$在下一次手术中，孩子`c`被选择的概率为：$$\frac{size[c]}{n}$$当新子项与当前首选子项不同时，就会发生更改。 的贡献`u`是：$$\sum_c \frac{size[c]}{n}
\left(1-\frac{size[c]}{s}\right)$$在哪里：$$s = subtree[u]-1$$这简化为：$$\frac{1}{n}
\left(
s-\frac{\sum size[c]^2}{s}
\right)$$现在问题变成了树DP问题。 我们只需要每个节点的子树大小以及子树大小的平方和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(操作 × 树高) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从父数组构建有根树。 存储每个节点的子节点，以便我们稍后可以检查每个子子树。 
2. 使用后序遍历计算每个子树的大小。 节点的子树大小是必需的，因为它告诉我们每个子节点成为首选子节点的频率。 
3. 对于每个非叶子节点`u`， 让`s = subtree[u] - 1`。 这是包含在所有子子树中的节点数`u`。 计算值：$$\frac{s-\frac{\sum size[child]^2}{s}}{n}$$并将其添加到答案中。 

1. 执行所有除法`998244353`。 由于模数是素数，因此每个非零分母都有一个使用模幂的倒数。 
2. 输出累加值取模`998244353`。 

为什么它有效：

 对于每个节点`u`，首选子树仅由进入其子树之一的最新访问确定。 独立于树的其余部分，这创建了一个稳定的概率分布，其中每个子项根据其子树大小被优先选择。 该公式精确计算下一次访问选择不同孩子的概率。 将所有节点上的这些独立预期贡献相加即可得出一次操作中首选子更改的预期数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    children = [[] for _ in range(n)]
    if n > 1:
        parents = list(map(int, input().split()))
        for i, p in enumerate(parents, start=1):
            children[p - 1].append(i)

    size = [1] * n
    order = [0]
    for u in order:
        for v in children[u]:
            order.append(v)

    for u in reversed(order):
        for v in children[u]:
            size[u] += size[v]

    inv_n = pow(n, MOD - 2, MOD)
    ans = 0

    for u in range(n):
        if not children[u]:
            continue

        s = size[u] - 1
        sq = 0
        for v in children[u]:
            sq += size[v] * size[v]
            sq %= MOD

        cur = (s % MOD - sq * pow(s, MOD - 2, MOD)) % MOD
        cur = cur * inv_n % MOD
        ans += cur
        ans %= MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该树存储为子列表，因为每个节点只需要来自其直接子节点的信息。 遍历顺序是迭代构建的，以避免链形树上的 Python 递归深度问题。 

子树大小按反向遍历顺序计算。 当一个节点被处理时，它的所有子节点都已经收到了它们的最终子树大小，因此添加它们会产生父节点的正确大小。 

该公式仅适用于具有子节点的节点。 对于叶子来说，`subtree[u] - 1`为零，并且不可能发生首选子更改，因此跳过它们也可以避免被零除。 

所有算术都是模数完成的`998244353`。 的逆`s`存在是因为`s`总是介于`1`和`n-1`对于已处理的节点。

 ## 边缘情况

 对于单节点树：```
Input
1
```该算法创建一个没有子节点的节点。 它跳过贡献循环，因为没有可能的首选子代，将答案保留为零。 

对于有一个子节点的节点：```
Input
2
1
```根有`s = 1`唯一的孩子有子树大小`1`。 贡献变为：$$1-\frac{1^2}{1}=0$$所以答案仍然是零。 该公式反映了这样一个事实：选择相同的独生子不能创建重新分配。 

对于平等孩子的情况：```
Input
5
1 1 1 1
```根有四个大小为 1 的子节点。 下一次访问更改首选子项的概率为：$$4 \times \frac{1}{5}\times\frac{3}{4}=\frac{3}{5}$$子状态通过其子树大小进行处理，因此算法不会意外地假设每次访问都会更改首选边缘。 

对于不平衡树（例如链），该算法正确地生成零，因为每个内部节点只有一个可能的首选子节点。 无需特殊处理，实现即可得出相同的结论，因为通用公式自然会崩溃到零。
