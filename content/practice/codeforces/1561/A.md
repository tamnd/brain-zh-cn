 ## 解决方案
 ## 问题理解

 我们得到了一个排列，这意味着一个数组包含从 1 到 n 的每个整数恰好一次。 该过程重复应用确定性的“奇怪的气泡传递”操作，但有一个变化：奇数轮比较从索引 1、3、5 开始的相邻对，偶数轮从索引 2、4、6 开始比较。 

每次比较仅在它们无序时交换该对。 完整一轮包括按顺序扫描所选奇偶校验的所有有效对。 

任务是确定需要多少整轮，直到数组第一次按升序完全排序。 如果最初已经排序，则答案为零。 

约束足够小，甚至直接模拟也是可行的。 所有测试用例的 n 总和最多为 999，每个模拟步骤每轮最多执行 n 次比较。 这将一个简单的解决方案限制为总共大约 10^6 次操作，这在 Python 中很容易足够快。 

当数组已经排序或接近排序时，会出现微妙的边缘情况。 仅在完成一轮后进行检查的简单实现必须确保在任何迭代开始之前不会错过“已排序”条件。 另一个潜在的陷阱是在一轮期间检测到排序状态后停止，而不是在完成完整迭代后停止，因为该问题将完整迭代定义为计数单位。 

## 方法

 天真的想法是直接模拟所描述的过程。 在每次迭代中，我们根据奇偶校验循环适当的索引并执行条件交换。 每次完整迭代后，我们检查数组是否已排序。 我们重复直到它被排序。 

这是有效的，因为该操作准确地定义了排列的演变，并且我们第一次被要求达到排序顺序，因此模拟是忠实的。 

效率低下的问题是重复的全通是否太昂贵。 每次传递的时间复杂度为 O(n)，在最坏的情况下我们可能需要 O(n) 次传递，但这里 n ≤ 999 并且总和很小，因此每个测试用例的最坏情况 O(n²) 仍然是可以接受的。 

关键的观察结果是，不需要先进的数据结构或排序理论，因为该过程对于排序顺序是明确有界和单调的。 每轮都是确定性的，并以结构化的方式减少反演，因此直接模拟就足够了。

 ## 算法演练

 我们完全按照定义模拟该过程并计算轮次。 

1. 读取排列并检查它是否已排序。 如果是，则立即输出0。 当答案很简单时，这可以避免不必要的模拟。 
2. 初始化执行迭代次数的计数器。 
3. 重复直到数组排序完毕：

 1. 如果当前迭代次数为奇数，则扫描索引 1, 3, 5, ..., n−2，并在需要时交换相邻元素。 
2. 如果迭代次数为偶数，则扫描索引 2, 4, 6, ..., n−1，并在需要时交换相邻元素。 

每次完整扫描代表过程的一次迭代，扫描内的部分进度是同一迭代的一部分。 
4. 每次完整迭代后，增加计数器并检查数组现在是否已排序。 
5. 排序后，返回完成的迭代次数。

这样做的原因是该算法定义了排列的确定性状态转换。 每次迭代都是一个完整的转换步骤，问题要求系统达到固定点（排序顺序）时的第一个时间步骤。 由于状态空间是有限的，并且每一步都严格减少无序直到收敛，因此模拟将始终终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_sorted(a):
    for i in range(len(a) - 1):
        if a[i] > a[i + 1]:
            return False
    return True

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if is_sorted(a):
            out.append("0")
            continue
        
        steps = 0
        
        while True:
            steps += 1
            
            if steps % 2 == 1:
                start = 0
            else:
                start = 1
            
            for i in range(start, n - 1, 2):
                if a[i] > a[i + 1]:
                    a[i], a[i + 1] = a[i + 1], a[i]
            
            if is_sorted(a):
                out.append(str(steps))
                break
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实施直接遵循流程定义。 迭代的奇偶性决定我们是从索引 0 还是 1 开始比较。循环步进 2 确保我们只对正确的对应用交换。 

排序检查放置在每次完整迭代之后，符合我们计算完整轮次的要求，而不是轮次内的部分进度。 仿真前的早期检查可以有效地处理零情况。

 ## 边缘情况

 完全排序的数组，例如`[1, 2, 3, 4, 5]`立即返回 0，因为初始检查在任何迭代开始之前没有检测到反转。 

反向排列如`[3, 2, 1]`演示小 n 的最大工作量。 第一遍修复局部反转，但不会对数组进行全局排序，因此在达到固定点之前需要多次完整迭代。 

像这样的交替模式`[2, 1, 4, 3, 5]`显示独立局部反演如何并行求解。 奇数和偶数传递分别解析不同的邻接集，并且阵列在少量完整迭代后稳定，确认收敛是由局部校正而不是全局重组驱动的。
