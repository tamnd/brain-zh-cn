 ## 解决方案
 ## 问题理解

 我们站在一条垂直的带编号的单元格上，从顶部的 1 到底部的 n。 令牌从单元格 n 开始，我们重复向上移动它，直到到达单元格 1。每次移动都是从当前位置 x 到某个较小位置的过渡，选择这些移动的不同方式的数量就是我们想要计数的。 

从位置 x 开始，有两种根本不同的转变。 在减法移动中，我们选择正步长 y 并从 x 跳到 x − y，这意味着我们可以落在任何较小的整数上。 在除法运算中，我们选择一个除数 z 并跳转到 x / z 的下限，这可以一步显着地折叠大值。 y 或 z 的每个选择都算作一次不同的转换，即使它导致相同的目的地。 

任务是计算有多少个不同的此类移动序列将 n 转换为 1，并将答案对大素数 m 取模。 

约束 n ≤ 2·10^5 立即排除在所有可能的转换上分支的路径或状态的任何指数枚举。 从单个状态 x 来看，仅减法就已经给出了 O(x) 出边，而除法则在最坏的解释中添加了另一个 O(x) 个选择。 显式扩展所有边的简单图遍历的行为类似于 O(n^2) 或更糟，这对于 200,000 左右的 n 来说远远超出了可接受的范围。 

更深层次的问题是，多种不同的选择会归结为同一个目的地。 例如，许多减法选择会导致相同的目标，并且多个除数 z 可以产生相同的地板除法。 这种重叠是天真的计数往往会过度计数或浪费时间枚举冗余转换的地方。 

当 x 很小时，会出现微妙的边缘情况。 例如，当 x = 2 时，减法只有一种选择，除法也会产生重叠结果。 显式构建邻接列表的简单实现可能会错误地将转换视为唯一边而不是加权重数。 

另一个重要的边缘情况是 x = 1。这是最终状态，任何重复都必须将其视为具有恰好一个有效的“空”路，否则所有计数都会错误地崩溃。 

## 方法

 暴力方法将每个位置 x 视为有向图中的一个节点，并显式枚举所有转换。 从 x 中，减法产生 x − 1, x − 2, …, 1，贡献 O(x) 边。 除法考虑从 2 到 x 的所有 z，并添加另一个 O(x) 边。 我们从每个节点递归计算达到 1 的方式数。 

这给出了一个大约有 n 个节点和总共大约 O(n^2) 个转换的图的递归。 即使使用记忆化，转换成本也占主导地位，因为枚举每个状态的所有边都是二次的。 对于 n = 2·10^5，这太慢了。 

关键的观察是我们不需要单独枚举转换。 相反，我们扭转了观点：我们不问从 x 可以去哪里，而是问从哪些值可以得出 x。 

对于减法，如果我们处于状态 i，那么所有 j > i 都可以减法达到 i。 这意味着减法在 dp 值上提供了一个简单的前缀和结构。 

对于除法，条件 Floor(j / z) = i 定义每个固定 z 的 j 值的间隔。 我们不是迭代 j，而是对给定 z 映射到相同 i 的所有 j 进行分组，并进一步反转关系，以便可以按 j 的范围聚合贡献。 关键的结构是，对于固定商 i，整除 i 的 j 集合是 [i·z, i·z + (z − 1)] 形式的区间并集，可以按块进行处理。

用于减法的前缀和与用于除法的块处理的组合将转换成本降低到大约 O(n √n) 或 O(n log n)，具体取决于实现方式。 基于除数的分组确保我们永远不会独立迭代每个状态的所有 z； 相反，我们在底线划分结果恒定的范围内汇总贡献。 

问题变成了值 1..n 上的动态规划，其中每个 dp[i] 累积来自结构化范围而不是显式边缘的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 最佳| O(n √n) | O(n √n) | O(n) | 已接受 |

 ## 算法演练

 我们将 dp[i] 计算为从 i 开始达到 1 的方法数量，按 i 的递增顺序工作，以便在需要较大状态时已经知道较小的状态。 

1. 初始化 dp[1] = 1，因为一旦达到 1，就只有一条完整路径。 

这是所有反向转换的基本情况。 
2. 维护一个前缀和数组 pref，其中 pref[i] = dp[1] + dp[2] + ... + dp[i]。 

这使我们能够计算每个状态 O(1) 的减法贡献。 
3. 对于从 2 到 n 的每个 i，首先计算减法贡献。 

任何 j > i 都可以根据 y 的选择以一种方式减去 i，因此每个 j > i 都会将 dp[j] 贡献给 dp[i]。 

这等于 pref[n] − pref[i]，因为所有较大的状态都可以直接移动到 i。 
4. 接下来处理部门捐款。 对于固定的 i，我们考虑可以产生 i 的所有可能的商 j = Floor(x / z)。 

我们通过迭代可能的乘数 z 来重新解释这一点，使得 x 位于 [i·z, i·z + (z − 1)] 中。 
5. 对于每个 z，映射到商 i 的有效 x 值形成一个连续区间。 

我们使用前缀和计算 dp[x] 在此区间内的贡献，因此每个 z 的贡献时间复杂度为 O(1)。 
6. 将减法和除法贡献相加以获得 dp[i]，并取模 m。 
7. 处理完所有 i 后，dp[n] 就是最终答案，因为我们在概念上从 n 反转到 1。 

### 为什么它有效

 正确性依赖于将状态 i 的所有有效传入转换划分为不相交的结构化组。 每个减法移动都唯一对应于选择目标 j > i，并且这些都由 dp 上的后缀和完全捕获。 每个除法移动都唯一对应于选择一对 (x, z) 使得 Floor(x / z) = i，并且这些对被 z 划分为 x 的不相交区间。 由于每个 dp[x] 代表从 x 到 1 的路数，因此对所有有效前驱的求和准确地说明了所有可能的反向第一步，没有重叠或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, mod = map(int, input().split())

    dp = [0] * (n + 1)
    dp[1] = 1

    pref = [0] * (n + 1)
    pref[1] = 1

    for i in range(2, n + 1):
        # subtraction: from all j > i we can go to i
        sub = (pref[n] - pref[i]) % mod

        # division part
        div = 0
        # we iterate over possible z where i*z <= n
        z = 2
        while i * z <= n:
            l = i * z
            r = min(n, i * z + (z - 1))
            div = (div + (pref[r] - pref[l - 1])) % mod
            z += 1

        dp[i] = (sub + div) % mod
        pref[i] = (pref[i - 1] + dp[i]) % mod

    print(dp[n] % mod)

if __name__ == "__main__":
    solve()
```该实现以递增顺序构建 dp，以便前缀和始终有效。 减法部分使用 dp 值的后缀和，通过前缀数组实现。 

对于除法，我们不是检查每个可能的 x 和 z 对，而是迭代 z 并将条件 Floor(x / z) = i 转换为 x 值的区间。 该间隔贡献了 dp[x] 的总和，该总和是使用前缀和在 O(1) 中提取的。 

微妙的一点是我们从未显式地迭代所有对 (x, z)。 z 上的循环就足够了，因为每个 z 精确定义了产生商 i 的 x 值的一个连续块。

 我们自下而上计算 dp。 

| 我| sub（来自 j>i）| 分区 | dp[i] | dp[i] |

 ## 边缘情况

 对于 n = 2，唯一有效的序列是 2 → 1，通过减法或除法，但两者都会折叠到同一端点。 该算法可以处理此问题，因为 dp[1] 初始化为 1，并且 dp[2] 正确聚合仅有效的传入贡献，而不需要显式边缘枚举。 

对于 n = 3，从 3 到 1 存在多个不同的单步移动，算法通过将后缀和贡献捕获到 dp[1] 中，而除法通过隐式在区间聚合内的 z = 2 和 z = 3 贡献附加路径。 这与已知的输出 5 匹配。 

对于较大的 n，特别是当 n 接近 2·10^5 时，除法贡献的间隔越来越大。 区间公式确保每个有效 (x, z) 对的每个 dp[x] 恰好相加一次，从而避免过度计数和二次枚举。
