 ## 解决方案
 ## 问题理解

 在“黑色方块”中，每当黑色方块出现时，陪审团必须按下四个垂直条之一。 每条条都有固定的压制能量成本（以卡路里为单位）。 我们得到四个整数，代表按下第一条到第四条时消耗的卡路里。 游戏的进展由一个字符串来描述，其中每个字符都是从“1”到“4”的数字，指示哪条带在该时刻有一个正方形。 任务是通过遵循此顺序并按下相应的条来计算陪审团消耗的总卡路里。 

输入保证最多 105 游戏秒，因此我们的解决方案必须高效地处理每个角色，最好是线性时间。 每个卡路里消耗可以为零，这意味着按压条带可能不会消耗能量。 边缘情况包括字符串完全是一种类型的条带、交替的条带或最大长度为 105。重复搜索或对每个字符执行复杂操作的简单解决方案可能会超出时间限制。 

当所有卡路里成本为零时，就会出现微妙的边缘情况。 例如，如果输入是`0 0 0 0`和`s = "12341"`，正确的输出是`0`，但是粗心的方法，例如假设每台压力机至少贡献一卡路里，就会得到错误的结果。 

## 方法

 强力方法是迭代字符串，对于每个字符，将其映射到相应的卡路里成本并将其添加到运行总计中。 这是有效的，因为每一秒都是独立的； 我们只需要知道该特定条带的成本。 从技术上讲，暴力破解已经是最佳选择，因为必须检查每个字符，从而给出与字符串长度成正比的最坏情况复杂性。 

确认这种方法足够的关键观察是条带之间没有相互作用； 卡路里是累加的。 不需要优化或复杂的数据结构，因为每次查找都是恒定时间操作。 通过将字符“1”-“4”直接映射到卡路里数组中相应的索引，我们可以高效地累加总卡路里。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取代表第一条至第四条的卡路里的四个整数。 将它们存储在列表中`calories`用于直接索引。 
2.读取字符串`s`代表黑色方块的序列。 
3. 初始化变量`total`归零以累积卡路里计数。 
4. 迭代每个字符`c`在字符串中`s`。 转变`c`为整数并减一以匹配从零开始的索引，然后访问`calories`在该索引处并将值添加到`total`。 
5.处理完所有字符后，打印出的值`total`。 

为什么它有效：该算法保持了以下不变式：`total`始终等于所有加工条的卡路里总和。 由于每个角色都被处理一次并直接映射到其成本，因此不会遗漏或重复计算卡路里。 决赛`total`因此是所有秒数的总和，满足问题要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# read calorie costs for each strip
calories = list(map(int, input().split()))
s = input().strip()

total = 0
for c in s:
    total += calories[int(c) - 1]

print(total)
```第一行读取四个卡路里值并将它们存储在列表中。 从中减去一`int(c)`确保从“1”-“4”到从零开始的列表索引的映射是正确的。 循环直接将适当的卡路里值添加到`total`没有任何条件检查或分支。 这可以避免差一错误。 该字符串被删除了空格，以确保我们不会意外地处理换行符。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    calories = list(map(int, input().split()))
    s = input().strip()
    total = 0
    for c in s:
        total += calories[int(c) - 1]
    return str(total)

# provided sample
assert run("1 2 3 4\n123214\n") == "13", "sample 1"

# custom cases
assert run("0 0 0 0\n12341\n") == "0", "all zero calories"
assert run("1 1 1 1\n11111\n") == "5", "all same strip"
assert run("1 2 3 4\n4321\n") == "10", "descending order"
assert run("10 20 30 40\n444444\n") == "240", "repeated max strip"
assert run("5 5 5 5\n1\n") == "5", "single element"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 | 0 0 0 0 / 12341 | 0 | 处理零卡路里条|
 | 1 1 1 1 / 11111 | 5 | 重复按压同一条条|
 | 1 2 3 4 / 4321 | 10 | 10 降序序列的正确索引映射 |
 | 10 20 30 40 / 444444 | 240 | 240 对最后一条条进行多次按压 |
 | 5 5 5 5 / 1 | 5 5 5 5 / 1 5 | 最小输入尺寸 |

 ## 边缘情况

 当所有卡路里值为零时，`total`无论顺序如何，都保持为零。 例如，输入`0 0 0 0\n12341`产生`0`。 该算法正确处理长度为 1 的字符串，如下所示`5 5 5 5\n1`，它只是将第一个条带的成本添加一次。 用于重复按压单个条带，例如`11111`当所有卡路里为 1 时，算法会正确累加总和，从而确认多个相同字符之间的不变性成立。
