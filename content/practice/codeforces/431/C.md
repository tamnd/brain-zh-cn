 ## 解决方案
 ## 问题理解

 我们正在使用一棵有根无限树，其中每个节点总是精确地$k$儿童的传出边缘。 其中每一个$k$边具有固定权重：第一个为 1，第二个为 2，依此类推，直到$k$。 从根本上讲，我们考虑逐步通过子级的向下路径，每次我们选择其中之一$k$边缘。 

路径只是从根开始的一系列边选择，其总成本是沿该路线使用的边的权重之和。 我们只对总权重恰好为的路径感兴趣$n$。 其中，我们只计算至少包含一条边的路径，其权重至少为$d$，这意味着至少一个步骤使用标记为的边$d, d+1, \dots, k$。 

所以任务是计算受约束的组合$n$：每一步都贡献一个价值$[1, k]$，顺序很重要，而且我们还要求序列至少包含一个“大”步骤（至少$d$）。 由于每个选择也对应于一个不同的子项，因此即使不同的序列具有相同的权重，它们也是不同的。 

约束条件$n, k \le 100$清楚地表明，对于“到目前为止的总和”和“是否满足约束”等状态的二次或三次动态规划解决方案就足够了。 序列上的任何指数都是不可行的，因为序列的数量像$k^n$，即使对于中等强度来说，这也是一个天文数字$n$。 

天真的尝试可能会尝试枚举总重量的所有序列$n$。 即使我们按当前总和进行修剪，序列的数量也会表现得像广义的斐波那契爆炸。 例如，与$k=3$和$n=20$，部分路径的数量已经超过数百万。 这立即使得暴力破解变得不可能。 

出现微妙的边缘情况时$d = 1$。 那么每条边都是“大”的，所以每一个有效的分解$n$分成几部分$[1,k]$是可以接受的。 另一个边缘情况是$d = k$，其中只有重量步长$k$符合大条件，因此序列必须至少包含一个$k$。 如果一个粗心的解决方案忘记了“至少一个大边缘”条件，那么在这两种情况下都会出现计数过高的情况。 

## 方法

 该问题从根本上讲是关于计算由以下边界限制的正整数序列$k$总和为$n$，对是否出现大值有一个侧面约束。 蛮力视图很简单：增量构建序列，跟踪当前总和，并计算那些恰好结束的序列$n$并包含一个值$\ge d$。 这是正确的，因为它直接枚举了有效路径的定义。 

然而，从任何州总和$s$, 最多有$k$过渡，深度可以达到$n$。 这大约产生$O(k^n)$最坏情况下的序列，这是完全不可行的。 

关键的观察是，我们不需要记住整个序列，只需要记住两条信息：当前的总和以及我们是否已经使用了至少一个“大”边。 这立即表明对总和的前缀进行动态规划。 

我们在剩余总和或当前总和上定义一个 DP，以及指示条件是否已满足的二元状态。 转换很简单：从 sum$i$，我们尝试添加每个权重$w \in [1,k]$，根据是否更新总和和标志$w \ge d$。 

这将选择的指数树变成了分层图$n$州，其中每个州最多有$k$传出转换，给予$O(nk)$复杂。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 路径上的暴力 DFS |$O(k^n)$|$O(n)$| 太慢了|
 | DP 总和 + 标志 |$O(nk)$|$O(n)$| 已接受 |

 ## 算法演练

 我们构建一个动态规划表，其中维度是迄今为止实现的总和，并跟踪是否使用了“大边缘”。 

1.定义DP表$dp[i][0/1]$， 在哪里$i$是当前总和，第二个维度表示我们是否至少使用了一条带权重的边$\ge d$。 该结构将整个历史压缩为与最终条件相关的唯一信息。 
2. 初始化$dp[0][0] = 1$。 这表示在获取任何边之前根部的空路径。 由于尚未采用任何边，因此尚未使用大边。 
3. 迭代所有的和$0$到$n-1$。 每个状态代表已经具有一定总权重的部分路径。 
4. 来自各个州$(i, flag)$，尝试所有边权重$w$从 1 到$k$。 如果$i + w \le n$，我们可以将路径扩展一步。 这与在树中选择一个子边完全对应。 
5. 转换时，将新标志计算为$flag \lor (w \ge d)$。 这确保了一旦我们使用大边，该属性就会永久记住在状态中。 
6. 添加从当前状态进入下一个状态的路数：$dp[i + w][new\_flag] += dp[i][flag]$，取模$10^9 + 7$。 
7.填表后，答案为$dp[n][1]$，因为我们想要准确的总和$n$并且至少使用了一个大边缘。 

### 为什么它有效

 每个有效的根到节点路径唯一对应于一系列边选择，其权重总和为$n$。 DP 只枚举所有此类序列一次，因为每个转换都会附加一个有效的边缘选择。 状态压缩是安全的，因为未来的转换仅取决于剩余的总和以及是否已经满足约束，而不取决于早期小边的顺序。 因此，没有两个不同的有效序列被错误地合并，并且没有无效序列可以到达$dp[n][1]$因为该标志正确地强制执行了约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, k, d = map(int, input().split())

dp = [[0, 0] for _ in range(n + 1)]
dp[0][0] = 1

for i in range(n + 1):
    for used in range(2):
        if dp[i][used] == 0:
            continue
        cur = dp[i][used]
        for w in range(1, k + 1):
            if i + w > n:
                break
            nxt_used = used or (w >= d)
            dp[i + w][nxt_used] = (dp[i + w][nxt_used] + cur) % MOD

print(dp[n][1])
```DP 表存储使用或不使用大边缘达到每个总和的方式的计数。 外循环按递增顺序对总和进行处理，因此每次转换始终向前进行，并且不会重新访问之前的状态。 

权重从 1 到$k$准确地反映树结构，因为每个节点都有$k$具有这些边缘权重的孩子。 早间休息的时候$i + w > n$是安全的，因为重量正在增加，所以所有进一步的重量也会超过$n$。

## 测试用例```python
import sys, io

MOD = 10**9 + 7

def solve():
    n, k, d = map(int, sys.stdin.readline().split())
    dp = [[0, 0] for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(n + 1):
        for used in range(2):
            cur = dp[i][used]
            if not cur:
                continue
            for w in range(1, k + 1):
                if i + w > n:
                    break
                nd = used or (w >= d)
                dp[i + w][nd] = (dp[i + w][nd] + cur) % MOD

    print(dp[n][1])

def run(inp: str) -> str:
    global input
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old
    return out.getvalue().strip()

# provided sample
assert run("3 3 2\n") == "3"

# minimum case
assert run("1 1 1\n") == "1"

# no valid large edge possible
assert run("3 2 3\n") == "0"

# all edges are large
assert run("3 3 1\n") == "4"

# boundary k=n
assert run("4 4 3\n") >= "0"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 | 3 3 2 | 3 3 2 3 | 样本正确性 |
 | 1 1 1 | 1 1 1 1 | 最小非平凡路径|
 | 3 2 3 | 3 2 3 0 | 不可能满足大边缘条件|
 | 3 3 1 | 3 3 1 4 | 所有序列都有效，因为每条边都很大 |

 ## 边缘情况

 当$d = 1$，每条边都足够大，因此答案简化为计算$n$使用零件$1..k$。 DP 仍然有效，因为每当采用任何边沿时，每次转换都会立即将标志设置为 1，因此仅$dp[i][1]$在第一步之后变得相关。 

什么时候$d = k$，只有最大的边对约束有贡献。 DP 正确跟踪从未使用过的序列$k$在$dp[*][0]$，并且仅移动到$dp[*][1]$当一个$k$被选中。 这可以清楚地分离无效序列，即使它们达到总和$n$，确保它们不被计算在内，除非$k$至少出现一次。
