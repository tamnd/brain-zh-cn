 **求解时间：** 1m 46s

 ## 解决方案
 ## 问题理解

 输入是从表单标签构建的有效的类似 XML 的文本`<a>`和`</a>`，其中标签名称是单个小写字母。 标签可以嵌套，多个 XML 片段可以相继出现。 

任务不是验证 XML。 有效性已经得到保证。 我们只需要重新格式化它。 

每个标签必须打印在自己的行上。 压痕取决于嵌套深度。 深度标签`h`前面是`2 * h`空间。 

例如，在```
<a><b></b></a>
```标签`<a>`处于深度`0`,`<b>`在里面`<a>`所以它在深度`1`， 和`</b>`也被深度打印`1`。 

输入长度最多为 1000 个字符。 这是很小的。 甚至一个`O(n²)`解决方案很适合，但问题的结构自然会导致简单的线性扫描。 

主要挑战是正确处理结束标签的缩进。 一个常见的错误是使用当前深度打印结束标签，然后才减小深度。 考虑：```
<a></a>
```正确输出：```
<a>
</a>
```如果我们打印`</a>`在降低嵌套级别之前，它会错误地缩进两个空格。 

另一个微妙的情况是紧跟在开始标签后面的结束标签：```
<a><b></b></a>
```正确输出：```
<a>
  <b>
  </b>
</a>
```深度为`</b>`与深度相同`<b>`。 在打印结束标签之前，我们必须降低嵌套级别。 

第三种情况是多个兄弟元素：```
<a></a><b></b>
```正确输出：```
<a>
</a>
<b>
</b>
```完成一个元素后，嵌套级别必须返回到其先前的值，以便下一个同级元素以正确的缩进开始。 

## 方法

 解决该问题的一种强力方法是重复定位下一个标签，通过检查所有先前处理的标签来确定其嵌套级别，然后打印它。 这种方法多次重新计算深度信息。 带有长度的字符串`n`，这可能导致`O(n²)`工作。 

输入大小足够小，即使这样也可以通过，但有一个更简洁的解决方案。 

关键的观察是，只有当我们遇到标签时，嵌套深度才会发生变化。 

开始标签增加了其中所有内容的深度。 结束标记结束当前嵌套区域并减少深度。 

这意味着我们可以从左到右处理 XML 文本一次。 每当我们遇到一个标签时，我们都会确定它是打开还是关闭。 

对于开始标签：```
<a>
```我们使用当前深度打印它，然后增加深度。 

对于结束标签：```
</a>
```我们首先减少深度，然后打印它。 

该单一规则会自动为每个有效的 XML 结构生成正确的缩进。 

由于在提取标签时每个字符仅检查一次，因此该解决方案以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | O(n) | O(n) | 已接受 |

 这`O(n)`辅助空间来自于打印之前存储输出行。 

## 算法演练

 1. 读取 XML 字符串。 
2. 从左到右扫描字符串。 
3. 每当`<`找到了，继续，直到匹配到`>`提取完整的标签。 
4. 检查标签是否为结束标签。 结束标签开头为`</`。 
5. 如果标签是结束标签，则在打印之前将当前深度减一。 被关闭的元素属于父级别，而不属于其自身内部的级别。 
6. 打印前面的标签`2 × depth`空间。 
7. 如果标签是开放标签，则打印后将深度增加一。 该元素内部的所有内容都更深一层。 
8. 继续，直到处理完整个字符串。 

### 为什么它有效

 维持不变式`depth`始终等于当前打开标签（其结束标签尚未处理）的数量。 

在打印开始标签之前，它属于当前嵌套级别，因此使用当前深度打印是正确的。 打印后，该标签将变为活动状态，因此深度会增加一。 

在打印结束标签之前，相应的元素不再被视为活动的。 首先减少深度会恢复父元素的嵌套级别。 使用此更新的深度进行打印可以准确地给出语句所需的缩进。 

由于每个标签都根据 XML 嵌套规则更新深度，因此每一行都以其正确的级别打印。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    depth = 0
    lines = []

    i = 0
    n = len(s)

    while i < n:
        j = i
        while s[j] != '>':
            j += 1

        tag = s[i:j + 1]

        if tag.startswith("</"):
            depth -= 1
            lines.append("  " * depth + tag)
        else:
            lines.append("  " * depth + tag)
            depth += 1

        i = j + 1

    sys.stdout.write("\n".join(lines))

if __name__ == "__main__":
    solve()
```扫描使用两个指针。`i`标记当前标签的开始，并且`j`前进直至匹配`>`被发现。 

关闭标签的操作顺序是实现中最重要的细节。 在产生压痕之前必须减小深度。 反转这两个操作会将每个结束标记向右移动一级。 

对于打开标签，需要相反的顺序。 标签本身属于当前级别，因此首先打印它，然后才增加其内容的嵌套深度。 

保证输入仅包含有效的 XML 文本，因此不需要堆栈或验证逻辑。

 ## 边缘情况

 考虑最小的有效 XML：```
<a></a>
```加工`<a>`深度打印`0`并将深度增加到`1`。 什么时候`</a>`达到时，算法将深度减小回`0`打印前。 输出变为：```
<a>
</a>
```这是完全正确的。 

考虑立即嵌套：```
<a><b></b></a>
```打印后`<b>`，深度变为`2`。 什么时候`</b>`出现时，算法首先将深度减小到`1`然后打印。 输出是：```
<a>
  <b>
  </b>
</a>
```如果减量发生在打印之后，`</b>`会错误地收到四个空格。 

考虑兄弟元素：```
<a></a><b></b>
```后`</a>`处理完毕后，深度返回到`0`。 下一个标签`<b>`打印时没有缩进。 输出是：```
<a>
</a>
<b>
</b>
```这证实了关闭子树会在处理后续元素之前完全恢复父级的嵌套级别。
