 ## 解决方案
 ## 问题理解

 我们有`n`霍比特人想要创造尽可能多的聚会日。 

每天对应一个客人列表，这是霍比特人的一些非空子集。 

宾客名单必须满足两个条件。 

对于每一对不同的日子，必须至少有一个霍比特人被邀请参加这两天。 用既定术语来说，每两个宾客名单必须相交。 

对于每三个不同的日子，一定不存在被邀请参加所有三天的霍比特人。 霍比特人可能会出现一天或两天，但绝不会出现三天或更长时间。 

输入仅包含`n`，可用霍比特人的数量。 我们必须最大化天数`k`，然后每天输出一个有效的客人名单。 

约束条件`n ≤ 10000`足够小，输出大小成为真正的限制。 任何接受的建筑总共最多只能生产约一万名霍比特人。 解决方案与`O(n²)`记忆是不可能的，因为`10000² = 10^8`元素。 一个解决方案大致为`O(n)`工作和输出都非常好。 

棘手的部分是，该问题要求最大可能的天数，而不仅仅是有效的时间表。 

考虑`n = 3`。 粗心的构造可能只会造成两天的时间：```
1 2
2 3
```这满足了条件，但不是最大值。 正确答案有三天：```
1 2
1 3
2 3
```另一个容易犯的错误是三天内允许一名霍比特人出现。 例如：```
Day 1: {1,2}
Day 2: {1,3}
Day 3: {1,4}
```每一对日子都有交集，但霍比特人`1`属于全部三天，违反了第二个条件。 

另一个陷阱是忘记每一对日子都必须交叉。 例如：```
Day 1: {1,2}
Day 2: {2,3}
Day 3: {3,4}
```第 1 天和第 3 天是不相交的，因此构建无效。 

挑战在于了解天数的最大可能上限，然后制定一个实现该上限的时间表。 

## 方法

 暴力心态始于将每一天视为霍比特人的任意子集。 我们可以尝试不同的子集集合并检查这两个条件。 验证一个候选者需要检查所有的天数和三倍数。 即使我们以某种方式将自己限制在几百天，子集的搜索空间也是指数级的`n`，使得这完全不可行。 

关键的观察来自于对单个霍比特人的观察。 

因为没有霍比特人可以参加三个不同的日子，所以每个霍比特人最多可以属于两天。 

假设一个霍比特人正好属于两天，比如说几天`A`和`B`。 那么那个霍比特人可以被认为代表这对`(A,B)`。 

现在考虑第一个条件。 每双日子必定有一个共同的霍比特人。 由于霍比特人不能属于三天，因此一个霍比特人只能见证一对日子的交集。 它不能同时充当两个不同对的共同客人。 

如果有`k`天，天对的数量是$$\binom{k}{2}.$$每对至少需要一名专门的霍比特人。 由于只有`n`霍比特人,$$\binom{k}{2} \le n.$$这立即给出了一个上限`k`。 

下一个问题是这个界限是否可以实现。 

这是。 拿`k`天。 对于每一对日子`(i,j)`，创建一个霍比特人，邀请他确切地参加这两天。 然后每一对日子都会因为那个霍比特人而相交，并且没有霍比特人属于三天，因为每一天都被分配到恰好一对。 

该结构准确地使用了$$\binom{k}{2}$$霍比特人。 

如果`n`较大时，剩余的霍比特人未使用。 该声明仅要求宾客列表是居民的非空子集，而不是每个霍比特人都必须出现。 

因此整个问题就简化为寻找最大整数`k`满意的$$\binom{k}{2} \le n.$$| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳施工| O(k²) | O(k²) | 已接受 |

 自从`k`大致是`√(2n)`， 为了`n = 10000`我们得到`k ≤ 141`， 制作`k²`微小的。 

## 算法演练

 1. 求最大整数`k`这样`k(k-1)/2 ≤ n`。 
2. 创建`k`空的宾客名单。 
3. 霍比特人的编号从`1`。 
4. 每两天`(i,j)`和`i < j`，创建一个新的霍比特人并将其添加到这两天`i`和一天`j`。 

这位霍比特人成为这两天交叉的唯一见证人。 
5. 处理完所有对后，准确地`k(k-1)/2`霍比特人已被使用。 
6. 输出`k`。 
7. 输出每位宾客名单。 

### 为什么它有效

 有`k(k-1)/2`几天。 该结构为每一对分配了一个独特的霍比特人。 

取任意两个不同的日子。 他们对应的一对收到了一个霍比特人，正好在这两天出现，所以日子是交叉的。 

以任何霍比特人为例。 它是为特定的一天创建的，并恰好插入到这两个客人列表中。 因此，霍比特人在不同的三天里都不会出现。 

施工完全采用`k(k-1)/2`霍比特人。 自从`k`被选为满足的最大值`k(k-1)/2 ≤ n`，任何超过`k`天数将需要超过`n`霍比特人，与计数论点相矛盾。 因此天数是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    k = 1
    while (k + 1) * k // 2 <= n:
        k += 1

    groups = [[] for _ in range(k)]

    cur = 1
    for i in range(k):
        for j in range(i + 1, k):
            groups[i].append(cur)
            groups[j].append(cur)
            cur += 1

    print(k)
    for g in groups:
        print(*g)

solve()
```第一个循环找到最大可行天数。 自从`k`永远不会超过 141，即使是简单的线性搜索也足够了。 

数组`groups[i]`存储当天的客人名单`i`。 

嵌套循环在每一对无序的日子中迭代。 对于每一对，都会创建一个新的霍比特人标识符并将其插入两个相应的访客列表中。 任何标识符都不会被重复使用。 

一个常见的错误是继续分配霍比特人，直到完全到达`n`。 那是不必要的。 证明最多只需要`n`霍比特人。 允许未使用的霍比特人。 

另一个微妙的点是索引。 程序中的天数以从零开始的索引存储，但霍比特人标签从`1`因为该声明中的居民数量来自`1`到`n`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k²) | 每两天进行一次迭代 |
 | 空间| O(k²) | 将所有指定的霍比特人存储在来宾列表中 |
 | 输出尺寸| O(k²) | 确切地`k(k-1)`印刷嘉宾亮相|

 自从`k`是最大的整数`k(k-1)/2 ≤ n`，我们有`k = O(√n)`。 为了`n = 10000`,`k ≤ 141`，因此存储和打印的客座人数不到两万。 这很容易符合限制。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

            groups[i].append(cur)
            groups[j].append(cur)
            cur += 1

    out = [str(k)]

 ## 边缘情况

 考虑最小输入：```
3
```该算法发现`k = 3`因为`3·2/2 = 3`。 这三对日子接待霍比特人`1`,`2`， 和`3`。 每天正好有两位客人。 即使在最小的边界上，该结构仍然有效。 

考虑：```
5
```我们仍然得到`k = 3`因为`4·3/2 = 6 > 5`。 尽管存在五个霍比特人，但该算法仅使用三个霍比特人。 这表明未使用的霍比特人是无害的。 这个问题并不需要每个居民都出现。 

考虑一个完全等于三角数的值：```
10
```该算法发现`k = 5`因为`5·4/2 = 10`。 每个可用的霍比特人都会被使用，每两天一个。 这是精确达到计数上限的最严格的可能情况。 

考虑一个正好低于下一个三角形数的值：```
9
```一个常见的差一错误会错误地选择`k = 5`，但这需要十个结对证人霍比特人。 算法正确地保持了`k = 4`因为`10 > 9`。 极大性证明保证五天是不可能的。
