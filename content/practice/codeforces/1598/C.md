 ## 解决方案
 ## 问题理解

 我们给定一个数组，其平均值对于原始数组来说是固定的。 任务是恰好删除两个元素，并计算可以删除多少对索引，以使剩余元素的平均值不会改变。 

与其直接考虑平均值，不如将条件转化为总和约束更有用。 如果原数组有和$S$和尺寸$n$，那么平均值是$k = S/n$。 删除两个元素后$a_i$和$a_j$，剩余的金额变为$S - a_i - a_j$，剩余大小为$n - 2$。 我们要求：$$\frac{S - a_i - a_j}{n - 2} = \frac{S}{n}$$该方程充分描述了哪些对是有效的。 

约束允许最多$2 \cdot 10^5$所有测试用例的总元素，这排除了每个测试用例的任何二次解。 任何直接尝试所有对的方法都需要最多$O(n^2)$操作，这远远超出了两秒内可行的范围。 

处理平均值时会出现一个微妙的问题：因为$k$可能不是整数，如果尝试计算，简单的整数比较可能会破坏正确性$k$并比较浮点值。 另一个常见的错误是在循环内重复重新计算总和，这会意外地将$O(n)$想法进入$O(n^2)$。 

具体的边缘情况是所有元素都相等。 例如，在`[5, 5, 5, 5]`，每对都有效，但是假设某些“特殊结构”的错误推导可能会错误地拒绝有效对，因为它期望值的可变性。 

另一种情况是只有非常特定的互补对才起作用，例如`[50, 20, 10]`，其中删除任何对都会改变平均值，因此答案为零。 这捕获了错误地假设对称性或基于频率的启发式的解决方案，而没有得出确切的条件。 

## 方法

 暴力解决方案尝试每一对$(i, j)$，删除它们，重新计算总和，并检查所得平均值是否等于原始平均值。 每次移除成本后重新计算总和$O(n)$，并且有$O(n^2)$对，因此总数变为$O(n^3)$。 即使我们预先计算一次总和，每一对仍然需要检查派生条件，给出$O(n^2)$，它已经变得太大了$2 \cdot 10^5$总元素。 

关键的观察结果来自于用代数重写条件。 开始于：$$\frac{S - a_i - a_j}{n - 2} = \frac{S}{n}$$交叉相乘得出：$$n(S - a_i - a_j) = (n - 2)S$$扩展：$$nS - n(a_i + a_j) = nS - 2S$$取消$nS$:$$n(a_i + a_j) = 2S$$所以：$$a_i + a_j = \frac{2S}{n}$$这将整个问题简化为计算总和等于固定目标值的对。 这立即提出了一种基于频率的线性解决方案：我们扫描数组，同时跟踪每个值出现的次数，对于每个元素，我们检查有多少先前的元素形成所需的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 计算总和$S$数组并导出目标总和$T = \frac{2S}{n}$。 如果$2S$不能被整除$n$，不存在有效的对，因此答案为零。 此整除性检查可防止使用无法对应于整数数组元素的非整数目标。 
2. 创建一个哈希映射来存储迄今为止看到的值的频率。 这允许恒定时间查找补集。 
3. 从左到右迭代数组，处理每个元素$a[i]$作为潜在对的第二个元素。 
4. 对于每个元素，计算所需的补集$T - a[i]$。 以此索引结尾的有效对的数量正是该补码已经出现在前缀中的次数。 
5. 将此计数添加到答案中，然后增加当前元素的频率。 

关键思想是，当处理对的第二个元素时，每个有效对都只计算一次。 

### 为什么它有效

 该变换将条件简化为固定和配对问题。 每个有效对唯一对应于一对索引$(i, j)$和$i < j$和$a_i + a_j = T$。 频率图确保在处理索引时$j$，我们精确地计算那些$i < j$满足方程。 不会丢失任何对，因为每个索引都作为第二个端点处理一次，并且不会重复计算任何对，因为我们从不在数组中向前查找。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        S = sum(arr)
        if (2 * S) % n != 0:
            print(0)
            continue
        
        target = (2 * S) // n
        
        freq = {}
        ans = 0
        
        for x in arr:
            need = target - x
            if need in freq:
                ans += freq[need]
            freq[x] = freq.get(x, 0) + 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先计算总和并检查是否存在有效的整数目标对和。 如果不是，它立即返回零，因为没有一对整数可以满足小数要求。 

频率字典存储到目前为止每个值被看到的次数。 当我们扫描数组时，每个元素都会根据之前看到的补集对答案做出贡献，从而确保正确的排序$i < j$。 

使用前缀频率可以避免重复计算，并使每个测试用例的解决方案保持线性。

 ## 边缘情况

 对于所有值都相同的数组，例如`[10, 10, 10]`，算法计算出的目标等于该值的两倍。 每个元素都匹配补集条件，并且随着第二个索引的增加，频率累积对所有对恰好计数一次。 最终输出是$\binom{3}{2} = 3$，匹配预期的组合结果。 

对于所需总和不是整数的情况，例如`[1, 1, 2]`，计算出的目标变得非整数，因为$2S/n$是不可分割的。 该算法立即返回零，并且不进行频率处理。 这可以避免任何错误的配对尝试，否则将依赖于不可能的相等性。
