 ## 解决方案
 ## 问题理解

 我们有两个玩家，爱丽丝和鲍勃，每个人随着时间的推移构建一根绳子。 两者都从由单个字符组成的同一个简单字符串开始`"a"`。 

然后他们会收到一系列操作。 每个操作都以 Alice 或 Bob 为目标，并将给定字符串的多个副本附加到其当前字符串。 每次操作后，每个玩家都可以以任何他们想要的方式自由地重新排序整个字符串的字符，目标是产生他们当前拥有的字符的字典顺序最小的可能排列。 

由于重新排序不受限制并且仅字符数很重要，因此字符串的实际结构变得无关紧要。 每次操作后重要的是每个玩家积累了多少个角色。 

在两个玩家独立优化他们的排序后，我们按字典顺序比较他们得到的字符串，并输出哪个较小，或者它们是否相等。 

一个关键的含义是每个字符串始终是玩家拥有的已排序的字符多重集。 因此，问题简化为维护 Alice 和 Bob 的字母频率计数，并在每次更新后比较两个多重集。 

输入大小使得这种减少变得至关重要。 每个操作可以附加一个长度最多为 400,000 的字符串，重复最多 200,000 次，但总体而言，每个测试用例的所有操作的长度总和为 400,000。 这个约束是关键的观察：虽然 k 可能很大，但我们只需要乘以计数，并且处理的不同字符总数与输入大小呈线性关系。 

显式构造重复字符串的天真解释将立即失败，因为即使是单个操作也可能会扩展到巨大的长度。 

经常破坏简单解决方案的边缘情况是同一操作多次重复附加大字符串。 例如，附加`"zz"`重复 100000 次不应显式构造 200000 个字符的字符串； 这样做会超时甚至耗尽内存。 

另一个微妙的情况是 Alice 和 Bob 收到相同的操作序列。 正确的输出应该始终是`"Tie"`步步。 错误地比较原始字符串而不是字符计数的解决方案可能会错误地区分不同的内部顺序，即使两者始终在末尾排序。 

## 方法

 蛮力方法试图从字面上模拟问题。 对于每个操作，我们通过重复来扩展字符串`x`确切地`k`times 并将其附加到目标玩家的字符串中。 每次更新后，我们对整个字符串进行排序，并按字典顺序比较 Alice 和 Bob。 

这在原则上是正确的，因为它完全遵循规则：构建字符串，对其进行最佳重新排序，然后进行比较。 然而，排序的成本随着字符串总长度的增加而增加。 经过多次操作后，字符串的大小可能会增长到与所有附加字符的总和成正比。 由于多达 400,000 个字符并重复排序，在最坏的情况下，整个操作的总成本约为 O(n² log n)，这远远超出了限制。 

关键的见解是每次操作后都没有必要进行排序。 由于我们总是可以任意重新排序，因此每个玩家的字符串完全由大小为 26 的频率数组决定。`x`重复`k`时代只是添加`k * count_of_each_character_in_x`到玩家的频率向量。 Alice 和 Bob 之间的比较简化为按字典顺序比较两个 26 长度的向量，就像我们对字符串进行了排序一样。 

这将每个操作减少为计算字符数`x`一次并缩放`k`，然后更新固定大小的数组。 词典比较也是超过 26 个字符的恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（构建+排序字符串）| O(total_length log 每个查询的total_length) | O(总长度) | 太慢了 |
 | 每个操作的频率计数 | 每个测试用例 O(26 · q) | O(26) | 已接受 |

 ## 算法演练

 1.初始化两个数组`A[26]`和`B[26]`代表 Alice 和 Bob 每个字母的计数。 两者都以`A['a']=1`和`B['a']=1`，其他全部为零。 这对初始字符串进行编码而不显式存储它。 
2. 对于每个操作，请阅读`(op, x, k)`。 
3. 计算局部频率数组`cnt[26]`对于字符串`x`。 这需要单次扫描`x`，计算每个字符的出现次数。 
4. 将每个相乘`cnt[c]`经过`k`。 这代表重复字符串`k`次而不构建它。 
5.如果操作的目标是Alice，则添加`cnt`进入`A`。 否则添加到`B`。 每次更新都是字符数的直接累积。 
6. 要确定此操作后的输出，请比较`A`和`B`按字典顺序从`'a'`到`'z'`。 它们不同的第一个索引决定了获胜者：较小的计数意味着玩家的排序字符串按字典顺序较小。 
7. 如果所有计数都匹配，则输出`"Tie"`。 

它的工作原理取决于每次操作后，每个玩家的字符串始终按字符的非递减顺序排序的不变性。 由于重新排序不受限制，因此任何排列都会简化为相同的规范排序多重集。 因此，玩家之间的字典序比较相当于按字母顺序比较他们的频率向量。 字符串的隐藏结构并不重要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cmp(a, b):
    for i in range(26):
        if a[i] != b[i]:
            return "Alice" if a[i] < b[i] else "Bob"
    return "Tie"

def main():
    T = int(input())
    for _ in range(T):
        q = int(input())
        A = [0] * 26
        B = [0] * 26

        A[0] = 1
        B[0] = 1

        for _ in range(q):
            parts = input().split()
            op = int(parts[0])
            x = parts[1]
            k = int(parts[2])

            cnt = [0] * 26
            for ch in x:
                cnt[ord(ch) - 97] += 1

            for i in range(26):
                cnt[i] *= k

            if op == 1:
                for i in range(26):
                    A[i] += cnt[i]
            else:
                for i in range(26):
                    B[i] += cnt[i]

            print(cmp(A, B))

if __name__ == "__main__":
    main()
```关键的实现选择是避免任何扩展字符串的构造。 乘法步骤取代了 k 个串联。 另一个微妙的细节是保持频率数组固定在大小 26，这保证了恒定时间比较独立于总字符串增长。 

## 工作示例

 考虑一个简化的场景：

 输入：```
1
3
1 aa 2
2 ab 1
2 a 3
```我们从爱丽丝开始 =`{a:1}`, 鲍勃 =`{a:1}`。 

第一次操作后，爱丽丝添加`"aa"`两次，贡献`{a:4}`到目前为止总计`{a:5}`。 

第二次操作后，Bob 添加了`"ab"`一次，所以鲍勃变成`{a:2, b:1}`。 

第三次操作后，鲍勃添加`"a"`三次，所以鲍勃变成`{a:5, b:1}`。 

在每一步中，我们都按字典顺序进行比较：

 | 步骤| 爱丽丝A | 鲍勃·B | 结果 |
 | ---| ---| ---| ---|
 | 初始化| 一个：1 | 一个：1 | 领带|
 | 1 | 一个：5 | 一个：1 | 鲍勃 |
 | 2 | 一个：5 | a：2，b：1 | 爱丽丝|
 | 3 | 一个：5 | a：5，b：1 | 爱丽丝|

 该跟踪表明字典比较取决于第一个不同的字符，这里`'a'`然后`'b'`，而不是对原始字符串的任何排序。 

现在考虑第二个强调结构的例子：

 输入：```
1
2
1 cba 1
2 abc 1
```两次操作后：

 爱丽丝：`{a:1, b:1, c:1}`鲍勃：`{a:1, b:1, c:1}`即使输入不同，排序也会完全消除结构，因此结果始终是平局。

 ## 边缘情况

 第一个边缘情况是两个玩家在所有操作中都保持相同。 该算法保持相同的频率数组，因此比较循环总是在没有发现差异的情况下完成，正确输出`"Tie"`每次。 

另一种情况是大量重复，例如为 400,000 个字符的字符串附加一个大乘数。 该实现从不构造扩展字符串，因此内存使用量保持不变。 在 Python 中，乘法步骤可以正确缩放计数，而不会出现溢出问题。 

最后一种情况是仅在后期字母字符中出现差异。 由于比较扫描来自`'a'`到`'z'`，较早的相等前缀将被安全地跳过，并且第一个不同的字符完全按照字典顺序的要求确定结果。
