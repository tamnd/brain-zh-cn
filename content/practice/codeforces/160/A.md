 ## 解决方案
 ## 问题理解

 我们得到了一组硬币，每个硬币都有一个正整数值。 任务是选择这些硬币的子集，使得我们选择的硬币的总价值严格大于留给其他人的硬币的总价值。 我们还必须最大限度地减少实现这一目标所需的代币数量。 

输入提供硬币数量，$n$，以及作为整数序列的硬币的值。 输出是一个整数：超过剩余硬币总和所需的最小硬币数量。 由于每枚硬币的价值在 1 到 100 之间，并且$n$最多 100，所有计算都适合标准整数算术。 这意味着我们可以自由地对值求和或对数组进行排序，而不必担心溢出或昂贵的操作。 

可能会导致幼稚方法失败的边缘情况包括所有硬币价值相等的情况，或者单个硬币已经大于总金额一半的情况。 例如，使用输入`4\n1 1 1 1`，任何尝试拿取少于 3 个硬币的行为都会导致平局或输钱。 另一个微妙的情况是当一枚硬币的价值等于所有其他硬币的总和时，例如`2\n3 3`; 这里我们必须拿两枚硬币来满足严格的不平等。 

## 方法

 暴力方法是考虑所有可能的硬币子集，计算它们的总和，并检查每个子集的总和是否大于剩余硬币的总和。 这是正确的但效率低下：对于$n$硬币，有$2^n$子集。 即使在$n = 20$，这将需要超过一百万张支票，并且最多$n = 100$，这是不可行的。 

简化问题的关键观察是，我们挑选硬币的顺序很重要，较大的硬币对总和的贡献更快。 因此，我们可以将硬币按降序排序，并从最大的开始挑选硬币。 在每一步中，我们都会累积它们的总和，直到超过总和的一半。 这保证了所需的最少数量的硬币，因为首先取出较小的硬币将需要更多的硬币才能超过剩余的金额。 

最佳方法利用排序和简单的贪婪累积，避免了检查所有子集的需要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取硬币数量，$n$，以及硬币值的数组。 我们需要完整列表来计算总和并执行排序。 
2. 计算所有硬币价值的总和。 这是了解我们需要超过的阈值所必需的。 
3. 将硬币按降序排列。 这确保了我们挑选的每枚硬币都能贡献最大可能的价值，从而最大限度地减少所需的硬币数量。 
4. 初始化两个变量：一个用于跟踪所选硬币的累计总数，另一个用于计算我们拿走了多少硬币。 
5. 迭代已排序的硬币，将每个硬币的值添加到累计总和中并增加硬币计数。 
6. 添加每枚硬币后，检查累计金额是否超过总金额的一半。 如果是，则停止迭代并返回获取的硬币数量。 
7.输出最少数量的硬币。 这满足了我们的总和严格大于剩余硬币总和的条件。 

这里的不变量是，在迭代中的任何一点，累积的总和是用该数量的硬币可获得的最大可能总和。 通过首先挑选最大的硬币，我们可以保证，一旦累积的总和超过剩余的总和，没有更小的子集可以用更少的硬币实现这一目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
coins = list(map(int, input().split()))

total_sum = sum(coins)
coins.sort(reverse=True)

accum = 0
count = 0

for coin in coins:
    accum += coin
    count += 1
    if accum > total_sum - accum:
        print(count)
        break
```我们首先读取硬币的数量和值列表。 这`sum`函数有效地计算总和。 按降序排序可确保首先贪婪地选择最大的硬币。 在迭代过程中，我们同时累加总和并计数硬币。 停止条件`accum > total_sum - accum`直接执行严格的不平等要求。 使用`break`确保我们一旦达到条件就立即停止。 

## 工作示例

 **样品1：**`2\n3 3`| 硬币| 累积| 总和 - 累加 | 计数|
 | ---| ---| ---| ---|
 | 3 | 3 | 3 | 1 |
 | 3 | 6 | 0 | 2 |

 第一枚硬币不够，因为`3`不大于`3`。 拿走两枚硬币可以得到`6 > 0`，所以输出是`2`。 

**样本2：**`4\n1 2 2 2`| 硬币| 累积| 总和 - 累加 | 计数|
 | ---| ---| ---| ---|
 | 2 | 2 | 5 | 1 |
 | 2 | 4 | 3 | 2 |

 取两个最大的硬币给出`4 > 3`，所以输出是`2`。 这表明贪心方法保证了最少的硬币数量。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    coins = list(map(int, input().split()))
    total_sum = sum(coins)
    coins.sort(reverse=True)
    accum = 0
    count = 0
    for coin in coins:
        accum += coin
        count += 1
        if accum > total_sum - accum:
            return str(count)

# provided samples
assert run("2\n3 3\n") == "2", "sample 1"
assert run("4\n1 2 2 2\n") == "2", "sample 2"

 ## 边缘情况

 对于`2\n3 3`，迭代排序后的硬币得到的累积和为`3`第一枚硬币之后，不超过`3`。 添加第二枚硬币给出`6 > 0`，所以算法正确输出`2`。 为了`5\n1 1 1 1 1`，算法选择三个硬币来达到`3 > 2`，表明它可以正确处理所有相等的硬币。 停止条件保证始终满足严格的不等式，即使在平局或边界情况下也是如此。
