 ## 解决方案
 ## 问题理解

 我们得到了一行值，我们想要计算有多少连续段在非常具体的模拟规则下表现“良好”。 

当我们选择一个细分市场时$[l, r]$，我们从左到右处理它的元素，保持一个连续的总和$g$。 添加每个元素后，如果运行总和超过阈值$x$，总和重置为零。 否则，它会保持原样。 如果在处理整个段之后，该段的最终值被认为是好的$g$不为零。 任务是对多个测试用例中所有这些好的片段进行计数。 

这些约束迫使我们根据每个测试用例的线性或近线性解决方案进行思考。 所有测试用例的总长度最多为$2 \cdot 10^5$，它排除了任何二次方，例如显式检查所有段。 任何有效的解决方案本质上都必须维护一个滑动窗口或增量结构，其中每个元素都被处理恒定的次数。 

当值相对于$x$。 在这种情况下，每个元素都会单独重置总和，这意味着只有单元素段才有效。 另一个边缘情况是当数组不递减或全部为小值时，长段在许多步骤中都不会重置，并且仅跟踪前缀和的简单逻辑将过度计数。 

## 方法

 暴力解决方案尝试每个部分$[l, r]$，模拟该过程，并检查最终是否$g$是非零的。 每次模拟需要$O(n)$，导致$O(n^3)$在最坏的情况下总计，这太慢了。 

关键的观察结果是，该过程仅取决于自上次重置以来的当前累计总和。 一旦总和超过$x$，它被擦除为零，并且该过程在本地重新启动。 这会创建自然的“有效块”，其中运行总和永远不会超过$x$，并且块之间的边界行为独立。 

问题归结为跟踪在运行总和触发重置之前我们可以从每个位置开始将段延伸多远。 一旦我们知道了这些边界，我们就可以使用两指针或基于前缀的计数策略来计算有效段。 

暴力破解之所以有效，是因为它显式地模拟重置，但会失败，因为它重复地重新计算相同的前缀行为。 将数组重置为独立段的观察使我们能够重用计算结构并有效地计算贡献。

 ## 算法演练

 我们独立处理每个测试用例并在数组上维护一个滑动窗口。 

1.我们维护一个左指针$l$和一个运行总和$g$。 这个想法是保持最大段开始于$l$进程尚未重置的地方。 
2.我们迭代$r$从左到右依次添加$a[r]$到$g$。 这模拟了当前段的扩展。 
3.如果$g$超过$x$，我们通过设置来模拟重置$g = 0$和移动$l$到$r + 1$。 这反映了之前的片段$r$无法促成有效的延续。 
4. 各位置$r$， 如果$g \neq 0$，那么任意起点$l' \in [l, r]$产生一个有效的段结束于$r$，因为这些启动都不会在到达之前导致立即重置$r$。 我们添加$r - l + 1$到答案。 
5. 我们持续到最后，积累贡献。 

关键思想是重置将数组分割成独立的块，并且在每个块中我们计算在该过程中幸存下来的每个位置处结束的所有子数组。 

### 为什么它有效

 不变的是，在任何时刻，$l$始终指向当前活动块的第一个索引，此后未发生重置$l$。 运行总和$g$准确地表示已处理的段$[l, r]$根据游戏规则。 每次重置时，我们都会正确丢弃之前所有无法进一步扩展的贡献。 这确保了每个有效段都被精确计数一次，并且每个无效段都被排除在外，因为它必然在完成之前触发重置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        l = 0
        g = 0
        ans = 0
        
        for r in range(n):
            g += a[r]
            
            if g > x:
                g = 0
                l = r + 1
                continue
            
            ans += (r - l + 1)
        
        print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循滑动窗口逻辑。 指针$l$仅当发生重置时才更新，这对应于超过阈值。 贡献$r - l + 1$计算结束于的子数组的所有有效起始点$r$。 重置步骤至关重要，因为如果没有它，我们就会错误地将无效的部分和转移到未来的段中。 

## 工作示例

 考虑一个小案例，其中$x = 2$数组是$[1, 2, 1]$。 

在$r = 0$，我们有$g = 1$， 所以$l = 0$，贡献 1 段。 

在$r = 1$,$g = 3$超过$x$，所以我们重置并设置$l = 2$，贡献0。 

在$r = 2$,$g = 1$，贡献 1 段。 

总数为 2，符合预期行为。 

现在考虑$[1, 1, 1, 1]$和$x = 2$。 窗口不断增长，直到总和超过$x$，然后重置，我们重复计算每个安全块内的贡献。 跟踪显示有效块内的每个扩展都会线性贡献，并且重置可防止块之间的交叉污染。

 ## 边缘情况

 当所有元素都大于$x$，每一步都会触发立即重置，因此只有长度为 1 的段才有效。 该算法会处理这个问题，因为每次$g > x$，我们重置并移动$l$超过当前索引，确保没有无效段贡献。 

当所有元素都很小时并且总和永远不会超过$x$，窗口永远不会重置，答案成为所有子数组计数的总和，其中公式$(r - l + 1)$正确累积。 

当重置正好发生在该位置时$r$，该实现确保该步骤不计入任何贡献，因为$g$在添加任何答案之前会被清除，以防止错误地包含损坏的段。
