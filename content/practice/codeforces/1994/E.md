 ## 解决方案
 ## 问题理解

 我们有几个独立的森林，每个森林由多个有根树组成。 每棵树在顶点 1 处都有一个固定的根，每个顶点定义一个自然子树，该子树由自身以及该根结构中的所有后代组成。 

允许的操作是选取任意树中的任意顶点并删除其整个子树。 每次此类删除的成本等于删除的顶点数量，并且我们可以在所有树上自由执行任意数量的此类操作，直到所有内容都被删除。 顺序并不重要，但每个顶点只能删除一次，因为子树一旦删除就会消失。 

目标不是最小化操作，而是最大化我们删除的所有子树大小的按位或。 每次我们删除大小为 S 的子树时，我们都会将 S 包含在运行的 OR 累加器中。 我们想要选择一个不相交子树删除的集合，其大小最大化此 OR 值。 

规模上的限制非常严格：测试文件中所有树的顶点总数最多可达一百万个，而且树的数量也很大。 这迫使每个测试用例的任何解决方案都是线性或接近线性的，并排除了任何考虑删除组合或枚举顶点子集的方法。 

一个关键的微妙之处是子树大小不是任意数字。 它们来自树结构，因此每个节点恰好贡献一个子树大小，并且这些大小由输入固定。 然而，我们并没有被迫删除整棵树或只删除根； 任何节点的子树都是有效的可选择对象。 

一个天真的错误是假设我们必须选择不相交的子树来形成分区，或者我们应该模拟删除。 例如，在节点链中，在不同点重复删除子树可能看起来会改变可能的大小，但实际上每个节点仍然对应于固定的子树大小，无论其上方的删除如何。 

最重要的隐藏简化是每个顶点都对应一个值：它的子树大小。 一旦观察到这一点，问题就不再是树运算，而是选择数字子集（子树大小）以最大化其按位或。 

暴露错误推理的边缘情况包括：

 单节点树，其答案必须为 1，因为唯一的子树大小为 1。任何尝试错误组合或忽略叶节点的算法都可能输出 0。 

一棵星形树，其中根的大小为 n，叶子的大小为 1。错误的贪婪方法可能会假设只有最大的子树重要，从而产生 n，而正确的答案是 n OR 1，如果 n 已经包含位 0，则为 n，但如果结构在多个树之间发生变化，则通常可能会有所不同。 

具有多棵树的森林，其中最佳 OR 需要组合来自不同树的子树大小。 任何独立处理每棵树并仅采用根值的方法都会错过更深节点的贡献。 

## 方法

 暴力视图是考虑所有树上每个可能的顶点子集。 对于每个选定的子集，我们将计算其子树大小的 OR 并取最大值。 这是正确的，因为它直接遵循定义：每个删除序列对应于选择某些子树集合，并且 OR 是可交换的，因此顺序并不重要。 

然而，这种方法会立即失败，因为子集的数量与节点的数量呈指数关系。 对于多达一百万个顶点，即使存储所有子树大小也可以，但是枚举子集将需要 2^n 次操作，这是不可行的。

结构简化来自于认识到子树大小是节点的固定属性，并且不依赖于删除顺序。 更重要的是，可以独立选择任何节点作为候选删除，因为删除子树并不妨碍我们在序列中较早地概念性地选择其大小； OR 运算仅聚合值。 

因此，整个森林贡献了一组值，每个节点一个：该节点的子树大小。 问题变成选择这些值的任何子集以最大化它们的按位或。 

现在的关键观察是，在所有元素均可独立选择的按位或最大化问题中，最佳策略就是采用所有可用值。 添加更多数字永远不会减少 OR，并且不存在阻止选择所有节点的约束，因为即使删除在实际过程中重叠，但值集合在贡献方面不需要不相交。 每个节点的子树大小可以通过在被视为删除时选择该节点来包含一次。 

这将问题简化为计算所有树上所有节点的子树大小，然后将它们组合在一起。 

剩下的唯一任务是高效的子树大小计算，这可以通过每棵树使用单个 DFS 来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集的暴力破解 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 计算子树大小 + 或全部 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 根据父表示为每棵树构建邻接表。 这创建了一个有根结构，其中子节点可以从每个节点显式访问。 
2. 对于每棵树，从根（顶点 1）开始运行 DFS 来计算子树大小。 每个节点的子树大小定义为 1 加上其子节点的子树大小之和。 这是正确的，因为子树定义遵循有根树中的后代。 
3. 在 DFS 期间，将计算出的每个节点的子树大小存储在全局累加器列表中。 
4. 处理完所有树后，迭代所有存储的子树大小并将其按位或计算为单个结果变量。 
5. 输出测试用例的最终累加或值。 

关键的实现细节是DFS必须是迭代或递归安全的，因为跨测试用例的节点总数可以达到一百万，而Python的递归深度可能不够。 

### 为什么它有效

 每个节点恰好贡献一个子树大小，并且无论删除的任何顺序如何，该大小都是固定的。 由于该操作允许随时选择任何子树，因此每个节点的子树大小都可以作为 OR 集中的选定值独立实现。 由于按位“或”对于添加元素而言是单调的，因此最佳解决方案包括所有可用的子树大小，从而使最终答案成为所有节点子树大小的“或”。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def dfs(u, adj, sz, order):
    stack = [(u, 0)]
    parent = {u: -1}
    while stack:
        v, state = stack.pop()
        if state == 0:
            stack.append((v, 1))
            for to in adj[v]:
                parent[to] = v
                stack.append((to, 0))
        else:
            s = 1
            for to in adj[v]:
                s += sz[to]
            sz[v] = s
            order.append(v)

t = int(input())
for _ in range(t):
    k = int(input())
    total_nodes = 0
    trees = []
    nodes_list = []

    for _ in range(k):
        n = int(input())
        total_nodes += n
        adj = [[] for _ in range(n + 1)]
        p = list(map(int, input().split()))
        for i, par in enumerate(p, start=2):
            adj[par].append(i)
        sz = [0] * (n + 1)
        dfs(1, adj, sz, nodes_list)
        trees.append(sz)

    ans = 0
    for sz in trees:
        for i in range(1, len(sz)):
            ans |= sz[i]
    print(ans)
```实现的核心是子树大小计算。 每棵树都使用从父数组派生的邻接列表来表示。 DFS 按后序计算大小，以便子级先于其父级进行评估。 

计算完所有子树大小后，我们只需将每个值或到单个累加器中。 

一个微妙的点是内存局部性：在约束下存储每棵树的所有子树大小是安全的，因为跨测试用例的总 n 是有界的。 但是，我们避免存储不必要的遍历元数据。 该解决方案依赖于这样一个事实：子树大小可以在计算后立即处理，而无需重新访问结构。 

## 工作示例

 ### 示例 1

 考虑一个大小为 4 的单链树：1 → 2 → 3 → 4。 

| 节点| 子树大小|
 | ---| ---|
 | 4 | 1 |
 | 3 | 2 |
 | 2 | 3 |
 | 1 | 4 |

 我们计算 OR：4 OR 3 OR 2 OR 1 = 7。 

这符合预期的行为，因为每个节点独立地贡献自己的子树大小，并且将它们组合起来可以最大化位覆盖率。 

该跟踪证实，即使子树大小在结构上重叠，它们的值在 OR 计算中是独立的。 

### 示例 2

 考虑一棵星形树：1 是根，连接到 2、3、4、5。 

| 节点| 子树大小|
 | ---| ---|
 | 1 | 5 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 1 |
 | 5 | 1 |

 或结果为 5 OR 1 = 5。 

这表明重复的小贡献不会改变 OR，除了启用已经存在的低位之外。 该结构确认重复项不会影响正确性，因为 OR 是幂等的。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个节点在 DFS 中被访问一次，在最终 OR 累加中被访问一次 |
 | 空间| O(n) | 邻接表和子树数组为每个节点存储一个条目 |

 总复杂度与森林的大小成线性关系，森林的大小必须达到一百万个顶点。 时间和内存限制都得到了轻松满足。

 ## 边缘情况

 单节点树表明该算法正确处理最小结构。 DFS 分配子树大小为 1，OR 累加器立即变为 1。 

深链确保后序计算正确地向上传播大小。 每个节点都依赖于其子节点，迭代 DFS 保证正确的累积而不会出现递归问题。 

星形树测试许多相同大小的子树的行为。 所有叶子都贡献 1，但 OR 忽略重复，因此只有位 0 的存在才重要，从而确认操作的幂等性。
