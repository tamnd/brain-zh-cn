 ## 解决方案
 ## 问题理解

 我们得到一个由小写字母组成的字符串。 在一步操作中，我们可以精确地选择位置的一个子集，获取这些位置处的字符，并仅任意重新排列那些选定的字符，同时将所有其他字符固定在其原始位置。 

目标是在一次这样的操作之后使整个字符串按非降序字母顺序排序。 我们被要求最小化为此操作需要选择的字符数量。 

考虑该过程的一个有用方法是最终字符串必须与原始字符串的排序版本匹配。 我们不会插入或删除字符，只是在它们之间重新定位选定的子集，而其余的则充当固定锚点。 

限制很小：字符串长度最多为 40，并且最多有 1000 个测试用例。 这立即表明，每个测试用例达到大约 O(n²) 甚至 O(n³) 的解决方案是安全的，但除非仔细构建，否则任何 40 指数级的解决方案仍然是边缘的。 然而，问题的实际结构允许线性扫描解决方案。 

一个微妙的问题是，所选子集可以是任何位置，不一定是连续的。 这意味着像“本地修复反转”这样天真的贪婪选择可能会失败，因为单个放错位置的字符可以通过参与所选集的全局重新排列来纠正。 

另一个潜在的陷阱是假设我们必须将排序后的字符串逐个位置与不匹配项进行匹配。 这很接近事实，但还不够，除非我们证明为什么不匹配本身就是最佳选择的特征。 

## 方法

 暴力策略将尝试所有位置子集，模拟对所选字符进行重新排序，并检查结果字符串是否可以排序。 对于长度为 n 的字符串，这意味着迭代 2ⁿ 子集。 对于每个子集，我们将提取字符，对它们进行排序，然后将它们放回原处，然后验证最终的字符串是否已排序。 即使检查时间复杂度为 O(n log n)，子集爆炸仍占主导地位。 当n达到40时，2⁴⁰是完全不可行的。 

关键的观察是我们实际上不需要模拟子集。 最终的目标字符串是固定的：它是原始字符串的排序版本。 唯一的问题是哪些位置已经符合这个目标而没有被移动。 

如果位置 i 处的字符已经等于排序字符串中应该出现的字符，我们可以选择保持它不变。 任何不匹配的位置都必须包含在所选子集中，否则永远无法纠正，因为未更改的位置保留其字符。 

这将问题转化为原始字符串与其排序版本之间的比较。 所需的最少更改次数恰好是它们不同的位置数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2ⁿ·n log n) | O(2ⁿ·n log n) | O(n) | 太慢了|
 | 最佳| 每次测试 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构造字符串的排序版本。 这代表了我们手术后想要达到的确切目标安排。 
2. 将原始字符串与此排序后的版本逐个字符进行比较。 
3. 计算两个字符串之间有多少个位置不同。 
4. 输出这个计数作为答案。 

每个不同的位置代表一个尚未处于正确最终位置的字符。 由于未更改的位置保持固定并且不能间接更改，因此每个不匹配必须至少包含在所选子集中一次。 

## 为什么它有效

将排序后的字符串修复为最终配置。 任何原始字符串已经匹配此配置的位置都不需要参与操作。 这些位置可以安全地排除，因为保持它们不变可以保持正确性。 

现在考虑原始字符串和排序字符串不同的位置。 如果未选择该位置，则其字符保持固定并且无法移动到其他位置，因此最终的字符串无法与排序的目标匹配。 因此，每个不匹配的位置都被迫进入所选的集合。 

相反，选择所有不匹配的位置就足够了，因为剩余的字符已经按照相对于固定位置的正确的相对顺序排列，并且可以对所选字符进行排列以填充排序顺序中的剩余槽。 

这创建了精确的等价：所选字符的最小数量等于不匹配位置的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        target = ''.join(sorted(s))
        
        k = 0
        for i in range(n):
            if s[i] != target[i]:
                k += 1
        
        print(k)

if __name__ == "__main__":
    solve()
```该解决方案为每个测试用例构建一次字符串的排序版本，然后执行线性扫描以计算不匹配的数量。 关键的实现细节是排序产生我们必须达到的精确的最终排列，因此不需要模拟允许的操作。 

答案不是“交换数量”或“反转数量”，而是严格来说已经与最终排序配置不一致的位置数量。

 ## 边缘情况

 单字符字符串，例如`a`排序后产生相同的字符串。 该算法将排序版本计算为`a`，比较位置 0，发现没有不匹配，然后返回 0。这证实了当字符串已经是最佳时，没有进行不必要的选择。 

A fully reversed string like`dcba`映射到`abcd`。 每个索引都不同，因此所有位置都被计算在内。 该算法正确地强制 k = n，因为没有字符已与其最终位置对齐，并且没有字符可以在不妨碍排序的情况下保持固定。
