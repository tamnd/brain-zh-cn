 ## 解决方案
 ## 问题理解

 我们被要求计算在一组“组连续性”约束下有多少歌手的排列是有效的。 

每个歌手都是一个独特的元素$1$到$n$。 我们必须将它们全部排成一行。 每个朋友都会向我们提供他们关心的歌手的子集，只有在最后一行中，该子集中的所有歌手都出现在彼此旁边且没有外人插入的情况下，他们才会感到满意。 组内的顺序并不重要； 唯一重要的是它们占据了连续的段。 

输出是所有排列的数量$n$同时满足每个朋友的约束的歌手，取模$998244353$。 

约束条件很小：两者$n$和$m$至多是$100$，但这并不能立即简化问题。 存在阶乘大小的搜索空间 ($n! \approx 10^{158}$在$n=100$），因此任何试图直接构造排列的方法都是不可能的。 

约束的结构才是重要的。 每个子集要求都不是局部的位置，它对排列施加全局“间隔约束”。 多个子集之间的相互作用产生了依赖关系，将歌手合并成不可分割的群体。 

一些边缘情况值得牢记。 

如果有一个朋友的集合都是歌手，则每个排列都是有效的，因为整个序列作为一个块是简单连续的。 例如，与$n=5$还有一位朋友喜欢所有歌手，答案是$5!$。 

如果每个朋友都喜欢单例，则每个排列都是有效的，因为单个元素总是连续的。 这给出了$n!$。 

一个更微妙的情况是约束重叠不一致。 例如，与$n=3$, 如果一位朋友想要$\{1,2\}$连续的，另一个想要的$\{2,3\}$连续，那么$1,2,3$必须全部结束在一个块中，即使没有朋友明确请求这三个块。 独立处理约束的幼稚方法会错过这种强制合并。 

关键的困难在于约束通过重叠传播，形成比明确给出的更大的不可分离的结构。 

## 方法

 蛮力方法会尝试所有排列$n$歌手并检查每个子集是否显示为连续的片段。 检查单个排列需要扫描每个子集并验证其元素是否占据连续范围，这可以在$O(nm)$。 总成本变为$O(n! \cdot nm)$，这远远超出了任何可行的极限。 

中心观察是约束不能独立运作。 如果两个子集以强制防止交错的方式重叠，它们就会有效地将其元素粘合在一起形成更大的结构。 这一想法的重复应用产生了歌手的最大“不可分割的组件”：在这样的组件内，元素不能在不打破至少一个约束的情况下分割到不同的位置。 

这表明将问题视为在重叠引起的闭合下重复合并集合。 一旦这些组件被识别出来，全局排列就变成了这些组件的排序，并且每个组件在内部都受到相同规则的递归约束。 

该结构自然地变得递归：每个组件要么是微不足道的，要么可以使用相同的逻辑进一步分解。 递归终止是因为每次合并都会严格增加组件大小。 

直接实现避免显式枚举排列，而是通过扩展和递归来构建这些组件，确保每个约束仅在强制结构增长时应用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n! \cdot nm)$|$O(n)$| 太慢了 |
 | 递归闭包分解|$O(\text{amortized exponential with strong pruning})$|$O(nm)$| 已接受 |

 ## 算法演练

 我们通过重复提取最小的不可分离块来构建解决方案。 

1、从全套歌手入手。 选择尚未分配给块的最小索引歌手。 该锚确保确定性分解。 
2. 初始化工作集$C$仅包含这位歌手。 
3. 重复扫描所有好友的子集。 如果子集相交$C$但并未完全包含在其中，展开$C$通过添加该子集的所有元素。 此步骤强制执行以下规则：任何朋友的群组都不能部分位于区块内。 
4. 继续扩展直至$C$停止改变。 在此刻，$C$在完全包含每个相交子集的约束下是封闭的。 
5.递归解决里面的问题$C$，仅处理完全位于范围内的约束$C$。 
6. 删除$C$从剩余的歌手中重复相同的过程以获得其他块。 
7. 形成所有块后，通过乘以每个块的有效内部排列的数量，然后乘以这些块的排序方式的数量来计算答案。 

存在最终的块顺序乘法，因为没有约束跨越两个不同的块，因此块在最终的排列中是独立的段。 

### 为什么它有效

 扩展步骤计算超图下顶点的闭合，其中超边是友元子集。 任何有效的排列必须将每个超边完全放置在连续段内。 如果超边与候选块部分重叠，则其元素无法分割，从而强制包含整个超边。 重复此闭包可确保每个剩余的约束要么完全内部，要么完全外部。 

这保证了每个生成的块在约束引起的不可分离性方面是最小的，并且没有有效的排列可以在不违反至少一个约束的情况下分离其元素。 然后递归在每个块内应用相同的逻辑，确保分解的完整性。 

## Python 解决方案```python
import sys
sys.setrecursionlimit(1000000)
input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
sets = []
for _ in range(m):
    tmp = list(map(int, input().split()))
    k = tmp[0]
    s = set(tmp[1:])
    sets.append(s)

all_mask = (1 << n) - 1

# bit representation
set_bits = []
for s in sets:
    mask = 0
    for x in s:
        mask |= 1 << (x - 1)
    set_bits.append(mask)

from functools import lru_cache

@lru_cache(None)
def solve(mask):
    if mask == 0:
        return 1

    # pick smallest element in mask
    u = (mask & -mask).bit_length() - 1

    comp = (1 << u)

    changed = True
    while changed:
        changed = False
        for s in set_bits:
            if s & comp:
                new_comp = comp | s
                if new_comp != comp:
                    comp = new_comp
                    changed = True

    rest = mask & ~comp

    # recursively solve
    return (solve(comp) * solve(rest)) % MOD

print(solve(all_mask))
```该代码实现了基于闭包的分解。 每个子集都表示为位掩码，允许快速交叉检查。 

功能`solve(mask)`返回由 表示的歌手集的有效排列数`mask`。 它选择一个规范的起点，然后使用相交子集上的闭包来增长强制组件。 一旦组件稳定，其余元素就形成一个独立的子问题。 

记忆化至关重要，因为相同的子集结构在递归分裂过程中可能会出现多次。 如果没有缓存，递归将重复地重新计算相同的状态。 

正确性依赖于这样一个事实：一旦组件关闭，任何有效的排列都不能将其元素与外部元素混合，因此问题会干净地分裂。 

## 工作示例

 ### 示例 1

 输入：```
3 1
2 1 3
```我们使用位掩码：$\{1,3\}$是唯一的限制。 

从面膜开始$111$。 最小的元素是$1$。 从组件开始$C = \{1\}$。 

我们扩展因为设置$\{1,3\}$相交$C$，所以我们添加$3$, 给予$C = \{1,3\}$。 不会发生进一步的扩展。 

剩余元素为$\{2\}$。 

| 步骤| 面膜| 组件C | 剩余|
 | ---| ---| ---| ---|
 | 开始| 111 | 111 {1} | 2,3 |
 | 展开 | 111 | 111 {1,3} | 2 |
 | 分裂| - | {1,3} | {2} |

 现在我们递归地解决这两部分。 每个块分别有 2 和 1 个元素，贡献$2!\cdot 1!$内部的方式，并且可以对块进行排序$2!$方式。 这会产生 4 个有效排列。 

此跟踪显示单个约束如何强制合并到块中。 

### 示例 2

 约束被链接的情况：```
3 2
2 1 2
2 2 3
```这两个子集通过元素 2 重叠。 

| 步骤| 面膜| 组件C |
 | ---| ---| ---|
 | 开始| 111 | 111 {1} |
 | 第一组之后 | 111 | 111 {1,2} |
 | 第二盘后| 111 | 111 {1,2,3} |

 所有的东西都合并成一个组件，所以所有的东西$3!$排列是有效的。 

这证明了约束的传递闭包。

 ## 边缘情况

 一个没有限制的最小示例，例如$n=1$，立即返回 1，因为递归在空或单例掩码处停止，并且不会发生合并。 

在完全受限的示例中，每个歌手都出现在单个集合中，导致初始闭合步骤立即扩展整个掩模。 然后递归在一次调用中终止，结果为$n!$，匹配所有排列满足单个连续要求的事实。 

例如，链式重叠案例$\{1,2\}$和$\{2,3\}$，显示闭包如何通过中间元素传播。 从 1 开始，第一个集合强制包含 2，第二个集合强制包含 3。最后一个块成为整个集合，并且递归不会再出现进一步的分裂。 

不相交约束情况，例如$\{1,2\}$和$\{3,4\}$表明封闭并没有过度。 每个块保持独立，并且最终答案正确地计算了两个组以任意顺序显示为连续段的排列。
