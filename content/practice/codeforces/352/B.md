 ## 解决方案
 ## 问题理解

 我们得到了一个整数序列，对于每个不同的值，我们想要了解它在数组中的出现次数是如何分布的。 对于任何值$x$，我们查看所有索引，其中$x$出现。 如果这些索引形成一个具有恒定差异的序列，那么$x$被认为是有效的，我们也报告了这种差异。 如果$x$仅出现一次，差值定义为零。 

因此，任务不在于价值观本身，而在于他们的立场结构。 我们根据每个不同数字的出现模式是否均匀分布来有效地对其进行分类。 

输入大小可达$10^5$。 这会立即排除任何重复扫描每个值的整个数组的情况，因为天真的分组和检查方法会降级为$O(n^2)$在最坏的情况下，当许多值重复时。 我们需要一个能够以恒定次数处理每个元素的解决方案。 

当某个值恰好出现两次时，就会出现微妙的边缘情况。 两个位置总是形成等差级数，所以答案就是它们的差异。 另一个极端情况是出现的事件间隔不均匀但可能看起来几乎规则，例如位置$[1, 3, 4]$。 粗心的方法可能只在本地检查连续的差异，而错过了稍后模式中断的情况。 

## 方法

 强力策略是首先收集每个不同值的所有位置，然后验证连续位置之间的差异是否恒定。 这在逻辑上是正确的：如果所有间隙都相等，则位置形成等差级数。 

然而，成本取决于我们如何组织数据。 如果我们重复扫描整个数组中的每个不同值，我们最终会这样做$O(n)$每个值的工作量，变成$O(n^2)$在最坏的情况下，所有元素都是不同的。 即使我们首先对字典中的位置进行分组，构建列表的总成本是$O(n)$，但验证每个组仍然与其频率成正比，因此总检查仍然存在$O(n)$。 那部分很好。 

真正的问题是，我们必须避免每个值处理中不必要的开销，并确保我们不会引入按组排序，这会增加额外的开销$\log n$每个不同元素的因子。 

关键的观察是，除了单次传递之外，我们不需要任何花哨的东西来收集位置，因为输入已经按顺序排列。 如果我们在扫描时存储索引，则每个列表本质上都是排序的。 然后，可以通过检查其存储的索引之间的单个共同差异来验证每个值。 

这将问题简化为线性簿记：累积头寸，然后扫描每个列表一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 分组+重复扫描|$O(n^2)$|$O(n)$| 太慢了 |
 | 对每个值进行分组 + 验证一次 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护一个字典，将每个值映射到它出现的索引列表。 

1. 从左到右扫描数组，并将每个索引附加到相应值的列表中。 这确保了位置自动排序，无需额外工作。 
2. 对于每个不同的值$x$，检查其职位列表。 如果它仅包含一个元素，则该值的答案立即为零，因为不存在空格歧义。 
3. 如果至少出现两次，则使用前两个位置计算初始差。 
4. 遍历剩余的位置并验证每个连续的差异与第一个差异是否匹配。 如果发现不匹配，则完全丢弃该值。 
5. 收集所有有效值及其差异，然后按值本身排序输出。 仅对不同的键进行排序，而不是对整个数组进行排序。 

### 为什么它有效

 对于任何有效值$x$，条件“位置形成等差级数”等价于“所有连续差值都相等”。 由于索引已经按构造排序，因此检查相邻差异是充分且必要的。 即使只有一个间隙不同，就违反了级数性质。 相反，如果所有间隙都匹配，则满足算术级数的定义，从而保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pos = {}
    
    for i, x in enumerate(a, start=1):
        if x not in pos:
            pos[x] = []
        pos[x].append(i)
    
    res = []
    
    for x in pos:
        p = pos[x]
        if len(p) == 1:
            res.append((x, 0))
            continue
        
        d = p[1] - p[0]
        ok = True
        
        for i in range(2, len(p)):
            if p[i] - p[i - 1] != d:
                ok = False
                break
        
        if ok:
            res.append((x, d))
    
    res.sort()
    
    out = []
    out.append(str(len(res)))
    for x, d in res:
        out.append(f"{x} {d}")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案依赖于按值键控的字典，其中每个条目都存储不断增长的索引列表。 由于我们从左到右迭代，因此这些列表不需要排序。 算术级数的检查是在每个值的单个线性传递中完成的。 

一个常见的错误是重新计算差异而不尽早修复参考差异，这会导致不必要的比较或不正确的提前退出。 另一个微妙之处是确保显式处理单次出现的值，否则它们可能会被错误地跳过。

 ## 边缘情况

 值仅出现一次是最简单的情况，但如果实现在计算差异之前假设至少两个位置，则很容易处理不当。 在这种情况下，该算法在对相邻元素进行任何访问之前显式分配零，以防止超出范围的错误。 

另一种边缘情况是一个值出现两次。 例如输入：```
4
5 1 5 1
```对于值 5，位置为 [1, 3]，因此差值为 2。算法直接根据第一对计算并接受它，无需进一步验证。 

一个更微妙的情况是当序列以有效差异开始但后来中断时：```
5
2 1 2 2 1
```对于值 2，位置为 [1, 3, 4]。 第一个差异是 2，但下一个差异是 1，因此被拒绝。 扫描会在第一次不匹配时立即检测到这一点并丢弃该值，以确保不会错误地接受部分模式。
