 ## 解决方案
 ## 问题理解

 我们的键盘只有两个可能的键，`a`和`b`。 当按下某个键时，键盘不会打印一次该字符。 相反，它会打印该字符的两份或三份副本。 给定 Singhal 按下的按键顺序，我们需要计算可能出现多少个不同的最终字符串。 

输入包含几个原始字符串。 每个字符串只包含`a`和`b`，每个的输出是可以生成的不同字符串的数量，模`10^9 + 7`。 

主要困难在于不同的扩展选择可能会导致相同的最终字符串。 例如，按`a`两次可以产生`aaaa`,`aaaaa`， 或者`aaaaaa`。 结果`aaaaa`可以通过扩展第一个来创建`a`长度为二，第二个长度为三，反之亦然。 我们只对结果字符串进行一次计数。 

所有输入字符串的总长度最多为`10^5`。 这排除了生成所有可能的输出，因为组合的数量呈指数增长。 如果一个字符串有长度`n`, 已经有`2^n`可以选择每次按键是否变为两个或三个字符。 即使对于中等`n`，这远远超出了一秒解决方案的处理能力。 我们需要找到一个计数公式来处理每个字符恒定的次数。 

棘手的情况来自连续的相等字符。 一种幼稚的方法可能会独立处理每个按键，并为每个字符乘以两个选择。 这会导致计数过多，因为相邻的相同字符在最终字符串中形成一个连续的块。 

例如：```
Input:
aa

Correct output:
3
```可能的输出是`aaaa`,`aaaaa`， 和`aaaaaa`。 将两个独立的选择相乘会给出四种可能性，但是两个不同的扩展选择会产生相同的中间字符串。 

另一个重要的情况是所有角色都与其邻居不同。```
Input:
aba

Correct output:
8
```每个角色都会创建自己单独的块，因此每个选择都会改变最终的字符串。 可能的块长度独立选择为两个或三个，给出`2 * 2 * 2 = 8`结果。 

最后的边缘情况是单个字符。```
Input:
b

Correct output:
2
```唯一的可能性是`bb`和`bbb`。 该算法仍必须处理仅正确运行一次的字符串。 

## 方法

 暴力方法是模拟每一种可能的键盘行为。 对于每个字符，选择其长度是否扩展为 2 或 3，构建结果字符串，并将所有结果存储在一个集合中。 这是正确的，因为该集合会自动删除重复项。 

然而，对于一个长度的字符串`n`， 有`2^n`扩展选择。 一个长度的字符串`50`已经创造了超过千万亿的可能性，所以这种方法在限制下无法工作。 

有用的观察来自于观察相同字符的运行。 考虑长度相同的连续块`k`。 该块中的每个字符都会扩展为两个或三个副本，因此该块的总长度可以是以下任意值`2k`到`3k`。 此间隔中的每个长度都是可能的，因为每个字符贡献两个或两个加一个额外字符。 

该块可能的最终长度数为：```
3k - 2k + 1 = k + 1
```不同的字符块不会互相干扰，因为相邻的块包含不同的字母。 最终的字符串完全由每个块的扩展长度决定。 因此，可能的字符串数量是每次运行的选择数量的乘积。 

蛮力方法之所以有效，是因为每个扩展选择都是单独考虑的，但它会失败，因为许多选择会崩溃到相同的游程长度中。 将字符串压缩为游程可以消除这种重复，并将问题简化为简单的乘法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(2^n * n) | O(2^n * n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从左到右扫描字符串并识别连续的相同字符组。 一组代表一个块，该块在扩展后仍保留为单个字符块。 
2. 对于每个有长度的组`k`，将答案乘以`k + 1`。 该值代表该块所有可能的最终长度，从`2k`通过`3k`。 
3. 继续，直到每个组都已处理完毕。 保持乘法为模数`10^9 + 7`因为可能的字符串数量可能会变得非常大。 

为什么它有效：

 最终字符串可以通过原始游程的扩展长度来唯一地描述。 不同游戏中的角色会交替出现，因此了解每次游戏的长度可以准确地告诉我们每个角色发生的变化。 一段长度`k`正好有`k + 1`可能的扩展长度。 由于每次运行都可以独立选择其长度，因此将这些值相乘会将每个可能的最终字符串精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()

        result = 1
        current = 1

        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                current += 1
            else:
                result = (result * (current + 1)) % MOD
                current = 1

        result = (result * (current + 1)) % MOD
        ans.append(str(result))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```变量`current`存储当前运行的大小。 每当角色发生变化时，该运行就完成并贡献其因子`current + 1`。 

最终运行需要在循环后单独处理，因为没有下一个字符会触发乘法。 忘记这一步是导致错误答案的常见原因。 

每次乘法后都会应用模运算。 Python 整数不会溢出，但保持值减少可以防止不必要的增长并匹配所需的输出。 

该算法只计算运行次数，因此不需要存储扩展的字符串，甚至不需要存储运行结构。 除了输入和输出存储之外，它还使用恒定的额外内存。

 对于`S = "aba"`:

 | 步骤| 当前角色 | 当前运行长度| 结果 |
 | ---| ---| ---| ---|
 | 开始| 一个 | 1 | 1 |
 | 完成一个 | 一个 | 1 | 2 |
 | 完成b| 乙| 1 | 4 |
 | 完成一个 | 一个 | 1 | 8 |

 三个运行是独立的。 每次运行的长度可以是二或三，所以答案是`2 * 2 * 2 = 8`。 

为了`S = "aa"`:

 | 步骤| 当前角色 | 当前运行长度| 结果 |
 | ---| ---| ---| ---|
 | 开始| 一个 | 1 | 1 |
 | 字符串结尾 | 一个 | 2 | 3 |

 两次按键是一次运行的一部分。 游程长度可以变为四、五或六，从而给出三个不同的字符串。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个角色在形成运行时都会被访问一次。 |
 | 空间| O(1) | O(1) | 仅存储计数器和当前答案。 |

 所有字符串的总长度为`10^5`，因此线性扫描很容易符合限制。 该解决方案通过直接计算可能的游程长度来避免指数级的扩展选择。

import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        ans = 1
        run = 1

        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                run += 1
            else:
                ans = ans * (run + 1) % MOD
                run = 1

        ans = ans * (run + 1) % MOD
        out.append(str(ans))

    return "\n".join(out)

aba
aa
""") == """2

""") == "5", "single long run"

 ## 边缘情况

 对于输入：```
aa
```该算法看到一次游程长度`2`。 它将答案乘以`2 + 1`，生产`3`。 三个可能的最终字符串是`aaaa`,`aaaaa`， 和`aaaaaa`。 它不会单独计算不同的扩展顺序，因为只有总游程长度很重要。 

对于输入：```
aba
```该算法处理三个长度的游程`1`。 每个因素贡献一个因素`2 +?`修正：每次运行长度`1`贡献`1 + 1 = 2`，所以答案就变成了`2 * 2 * 2 = 8`。 由于运行包含不同的字符，因此任何两个选择都不能合并为相同的最终字符串。 

对于输入：```
b
```有一趟有长度`1`。 其可能的长度为`2`和`3`，给出因子`1 + 1 = 2`。 该算法可以处理这种情况，因为扫描结束后最后一次运行会相乘。
