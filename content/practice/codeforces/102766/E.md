 ## 解决方案
 ## 问题理解

 我们得到一个字符串，该字符串是通过将几个连续的整数相邻写入而创建的。 整数最初形成一个从某个起始值开始的范围`n`到最终值`m`，该范围内至少有三个数字。 在串联之前，正好跳过该范围中间的一个整数。 任务是恢复跳过的整数，如果多个范围可以解释该字符串，则返回可能的最小缺失值。 

例如，字符串`1314151718`可以拆分为`13, 14, 15, 17, 18`，来自连续范围`13`到`18`和`16`已删除。 答案是缺失的值，而不是剩余的序列。 

数字的上限很大，最多可达`10^9`，因此生成整个范围是不可能的。 范围可以包含大量整数，而输入字符串本身只有长度`10^5`。 总输入大小也限制为`10^5`字符，这意味着解决方案必须在每个字符串长度的大致线性时间内工作。 尝试所有可能的开始和结束数字的成本太高了。 

棘手的情况来自字符串开头的歧义。 第一个数字可能是实际的起始值，或者缺失的数字可能是范围的第一个值。 例如，输入`13`可以代表数字`1, 2, 3`和`2`缺失，所以答案是`2`。 始终将第一个数字序列视为第一个现有数字的解决方案将错过这种可能性。 

另一种边缘情况是缺失的数字位于范围的末尾。 例如，输入`123`可以代表`1,2,3,4`和`4`丢失的。 仅检查相邻已解析数字之间的跳转的解析器永远不会检测到缺失值，并且会错误地拒绝该序列。 

第三种情况是数字长度的变化。 例如，`899100101`代表`89,90,91,101`仅当分割选择不正确时，而有效的解释可能涉及从两位数到三位数的过渡期间缺少数字。 解析器必须比较整个预期数字，而不是假设固定数量的数字。 

## 方法

 一种直接的方法是猜测完整的连续序列。 我们可以尝试每个可能的第一个数字，重复地将字符串拆分为递增的整数，并检查是否恰好跳过了一个值。 这是正确的，因为任何有效答案都必须来自这样一个连续的序列。 问题在于搜索空间。 第一个数字可能很大，并且可能的分裂会快速增长。 探索长度字符串的所有分区`10^5`不现实。 

有用的观察是第一个现有数字必须出现在字符串的开头。 由于答案中的每个数字都小于`10^9`，第一个数字最多有九位数字。 我们只需要测试这几个可能的前缀作为第一个数字的候选。 

对于选定的起始数字，序列的其余部分是确定性的。 我们总是知道接下来应该是哪个数字。 如果字符串的下一部分与预期的数字匹配，我们就会使用它。 如果不匹配，唯一允许的解释是这个期望的数字是缺失的，并且字符串的当前部分必须是后面的数字。 此后，缺失值已被使用，因此后面的每个数字都必须完全匹配。 

这将问题从搜索多个分区转换为检查少量可能的启动，每个启动都是线性时间。

 | ---| ---| ---| ---|
 | 蛮力 | 可能的分裂数量呈指数增长 | O(1) | O(1) | 太慢了|
 | 最佳 | O(9 * | S | ) | O(9 * | S | ) |

 ## 算法演练

 1. 尝试所有可能的前缀长度`1`到`9`作为第一个数字。 超过九位数字的前缀不能表示有效数字，因为缺失值保证低于`10^9`。 
2. 对于每个候选起始数字，解析剩余的字符串，同时期望连续的整数。 第一个数字本身会立即被消耗，因为它定义了序列开始。 
3. 维护下一个预期整数和一个指示是否已找到丢失数字的标志。 当下一个字符与期望的整数匹配时，消耗它们并增加期望。 
4. 如果预期整数与字符串的当前部分不匹配，则将该预期整数视为缺失值。 当前部分必须与其后面的数字匹配。 如果此跳转发生多次，则候选起始无效。 
5. 消耗完整个字符串后，检查是否正好跳过了一个数字。 如果序列在最后一个现有数字之后立即结束，则缺失值是下一个预期数字。 
6. 在所有有效候选值中，返回最小的缺失值。 

为什么有效：对于固定的起始数字，应该出现的数字顺序是完全确定的。 在每个位置，要么出现预期数字，要么问题允许的唯一可能的差异是省略了该预期数字。 因为只允许省略一个，所以贪心解析无法跳过错误的数字。 测试所有可能的第一个数字涵盖了每个有效的结构，因为第一个现有数字要么是范围的真正开始，要么是紧接在缺失的第一个值之后的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(s):
    ans = 10**9

    def check(start):
        pos = 0
        cur = start
        missing = None

        first = str(start)
        if not s.startswith(first):
            return None
        pos += len(first)
        cur += 1

        while pos < len(s):
            expected = str(cur)
            if s.startswith(expected, pos):
                pos += len(expected)
                cur += 1
            else:
                if missing is not None:
                    return None
                nxt = str(cur + 1)
                if not s.startswith(nxt, pos):
                    return None
                missing = cur
                pos += len(nxt)
                cur += 2

        if missing is None:
            missing = cur

        return missing

    for length in range(1, min(9, len(s)) + 1):
        if length > 1 and s[0] == '0':
            continue
        start = int(s[:length])
        value = check(start)
        if value is not None:
            ans = min(ans, value)

    return str(ans)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_case(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案首先尝试第一个数字的所有可能长度。 只有九种可能性，因为有效数字如下`10^9`。 

这`check`函数执行贪婪扫描。 变量`cur`存储接下来应该出现的数字。 当字符串包含`cur`，扫描正常移动。 如果不存在，该函数会验证`cur + 1`而是出现并记录`cur`作为缺失的号码。 

最终条件处理缺失的最后一个数字。 如果扫描结束时没有找到间隙，则唯一剩下的可能性是下一个预期的数字从未被写入。 该实现避免了整数溢出，因为 Python 整数会自动增长，尽管此处的最大值对于标准 64 位整数来说也足够小。

 ## 边缘情况

 当缺失的数字是第一个值时，算法会处理它，因为第一个现有数字也可以是缺失的数字之后的数字。 用于输入`13`, 候选者开始`1`将序列解析为`1,3`，缺失值被检测为`2`。 候选人开始`13`无效或给出了更大的解释，因此保留最小答案`2`。 

当缺失的数字是最终值时，字符串内部不存在可见的跳转。 用于输入`123`，序列可以是`1,2,3,4`和`4`丢失的。 解析器读取完毕后完成`3`，看到没有记录间隙，并将下一个预期数字指定为缺失值。 

当序列跨越数字长度时，例如`1314151718`，解析器不依赖于固定宽度的块。 它在每一步都会比较预期数字的精确十进制表示形式，允许在两位数字和三位数字值之间进行转换，而无需特殊处理。
