 ## 解决方案
 ## 问题理解

 键盘只有两个键，`a`和`b`。 按一个键不会打印一个字符。 相反，每个按下的字符都会变成该字符的两个或三个副本的块。 输入字符串描述按键的顺序。 任务是计算所有按键完成后屏幕上会出现多少个不同的回文字符串。 

答案计算的是最终字符串，而不是生成它们的方法。 如果生成的屏幕字符串相同，则两次或三次按下的两种不同选择被认为是相同的。 

所有输入字符串的长度合计最多为 (10^5)，因此解决方案必须接近线性。 尝试每种可能的扩展是不可能的，因为长度为 (n) 的字符串有 (2^n) 个选择，每个按下的字符是否变为长度为 2 或 3。 

主要的边缘情况来自运行的结构。 如果原始字符串只有一个字符，则两种可能的输出都是有效的回文。 例如：```
a
```输出是：```
2
```因为可能的字符串是`aa`和`aaa`。 

第二个重要的情况是字符运行序列不对称。 例如：```
aab
```运行字符是`a`,`b`，所以每个最终字符串仍然以`a`并以`b`。 任何扩展都无法改变这一点，所以答案是：```
0
```仅检查可能的长度而忽略字符顺序的粗心解决方案可能会错误地计算某些字符串。 

另一个边界情况是具有单次运行的字符串：```
aaa
```可能的长度是从 6 到 9，因为三个中的每一个都按下`a`角色贡献两到三份。 每个结果都是回文，所以答案是：```
4
```有效的字符串是`aaaaaa`,`aaaaaaa`,`aaaaaaaa`， 和`aaaaaaaaa`。 

## 方法

 直接的方法是模拟每一种可能的键盘行为。 对于每个字符，我们选择两个或三个副本，构建结果字符串，检查它是否是回文，并将有效字符串存储在集合中。 这是正确的，因为它准确地检查了可能的结果。 然而，长度为 (100000) 的字符串可能有 (2^{100000}) 种扩展，因此这种方法不太可行。 

有用的观察结果是键盘仅改变行程长度。 考虑输入的压缩形式，其中连续的相等字符被分组在一起。 例如，`aaabbba`变成跑步`a(3), b(3), a(1)`。 由于相邻的运行包含不同的字符，因此扩展它们永远不会合并运行。 原始长度 (x) 的每次运行都可以变为 (2x) 到 (3x) 之间的任意长度。 

仅当最终字符串的游程字符被镜像并且每个镜像的游程对具有相同的长度时，它才是回文字符串。 字符条件仅取决于原始压缩字符串。 如果压缩字符序列本身不是回文，则答案为零。 

如果字符序列是对称的，则每对镜像游程都可以从其可能范围的交集中独立选择公共长度。 中间段（当存在时）可以从其自身范围中选择任意长度。 

问题从探索指数级数量的字符串减少到乘以每个镜像运行对的有效选择的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(2^n * n) | O(2^n * n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将输入字符串压缩为交替运行。 存储每次运行的字符及其原始长度。 
2. 比较镜像运行的特征。 如果第一个运行字符与最后一个运行字符不匹配，或者任何其他镜像对不同，则无法创建回文，因此返回零。 
3. 对于每个镜像运行对，计算两个运行的可能最终长度。 一段长度`x`可以产生长度`2*x`通过`3*x`，包含在内。 该对的选择数量是这两个范围的交集的大小。 
4. 将每个镜像对的选择数量相乘。 如果游程数为奇数，则再乘以中间游程的可能长度数。 
5. 打印模 (10^9+7) 的结果。 

这样做的原因是在验证字符顺序后，每个游程长度选择都是独立的。 回文需要每个镜像对之间满足一个条件：它们的长度必须匹配。 计算每个独立对的有效选择并将它们相乘，就将每个可能的回文恰好计数一次。 

## 为什么它有效

 压缩的运行序列完全决定了每个可能输出中的字符顺序。 扩展只能更改每次运行中重复字符的数量，而不能更改运行顺序。 回文在镜像位置必须具有相同的字符，这意味着游程字符必须彼此镜像，并且相应的游程长度必须相等。 

当运行字符对称时，为每个镜像对选择有效长度将恰好创建一个有效的回文。 每个可能的回文都对应于一组这样的选择，因为它的游程长度揭示了每次运行所做的选择。 乘法计算所有且仅有效的回文。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

MOD = 10**9 + 7

def solve_case(s):
    chars = []
    lens = []

    for c in s:
        if chars and chars[-1] == c:
            lens[-1] += 1
        else:
            chars.append(c)
            lens.append(1)

    m = len(chars)

    for i in range(m):
        if chars[i] != chars[m - 1 - i]:
            return 0

    ans = 1

    for i in range(m // 2):
        left_low = 2 * lens[i]
        left_high = 3 * lens[i]
        right_low = 2 * lens[m - 1 - i]
        right_high = 3 * lens[m - 1 - i]

        low = max(left_low, right_low)
        high = min(left_high, right_high)

        if low > high:
            return 0

        ans = ans * (high - low + 1) % MOD

    if m % 2 == 1:
        ans = ans * (lens[m // 2] + 1) % MOD

    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()
        out.append(str(solve_case(s)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```压缩循环一次性创建运行表示。 仅保留连续字符和长度可以避免存储每个可能的扩展字符串。 

在任何算术运算之前对运行字符执行回文检查。 当字符排序已经使回文不可能时，这可以避免不必要的计算。 

对于一个长度的运行`x`，可能的长度数是`x + 1`，因为最小长度是`2x`最大值是`3x`。 对于镜像运行，我们不能独立使用各个范围，因为两次运行必须以相同的长度结束。 交集计算直接处理这种情况。 

每次更新后，乘法都会使用模算术，因为即使运行次数很少，可能的字符串数量也会呈指数增长。 

## 工作示例

 对于输入：```
aba
```运行是三个单字符运行。 

| 步骤| 跑对 | 可用的常见长度 | 回答 |
 | ---| ---| ---| ---|
 | 1 | 第一的`a`， 最后的`a`| 2, 3 | 2 |
 | 2 | 中间`b`| 2, 3 | 4 |

 最终答案是4？ 实际上，中间的运行提供了两个选择，而该对提供了两个选择，给出（2 \times 2 = 4）。 可能的回文是`aabbaa`,`aabbba`,`aaabbbaa`， 和`aaabbbaaa`。 

对于输入：```
aaa
```有一个长度为 3 的游程。 

| 步骤| 跑对 | 可用长度 | 回答 |
 | ---| ---| ---| ---|
 | 1 | 中跑 | 6、7、8、9 | 4 |

 每个可能的输出都是一个块`a`，所以每个输出都自动是回文。

MOD = 10**9 + 7

def solution(inp):
    data = inp.strip().split()
    t = int(data[0])
    ans = []

    for s in data[1:]:
        chars = []
        lens = []
        for c in s:
            if chars and chars[-1] == c:
                lens[-1] += 1
            else:
                chars.append(c)
                lens.append(1)

        m = len(chars)
        ok = True
        for i in range(m):
            if chars[i] != chars[m - 1 - i]:
                ok = False

        if not ok:
            ans.append("0")
            continue

        cur = 1
        for i in range(m // 2):
            lo = max(2 * lens[i], 2 * lens[m - 1 - i])
            hi = min(3 * lens[i], 3 * lens[m - 1 - i])

        if m % 2:
            cur = cur * (lens[m // 2] + 1) % MOD

        ans.append(str(cur))

    return "\n".join(ans)

 ## 边缘情况

 对于`a`，该算法创建长度为一的一次游程。 没有镜像对，因此它只计算中间运行的可能长度。 从二到三的范围给出了两个答案。 

为了`aab`，压缩给出运行`a(2), b(1)`。 第一个和最后一个运行字符不同，因此算法立即返回零。 任何扩展长度的选择都不能将第一个字符块更改为最终字符块。 

为了`aaa`，压缩给出长度为三的一次游程。 由于没有配对可匹配，因此适用中游规则。 可能的长度为六到九，给出四个有效的回文。 

对于包含许多交替运行的大型输入，该算法从不扩展字符串。 它仅比较存储的运行信息并在每次运行时执行恒定的工作，避免出现指数数量的可能的键盘结果。
