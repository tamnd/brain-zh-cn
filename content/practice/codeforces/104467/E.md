 ## 解决方案
 ## 问题理解

 我们得到两个二进制字符串，并且允许我们通过选择任何相邻的字符对并用它们的 XOR 替换它们来重复压缩第一个字符串。 每个操作都会将字符串缩短一，因为两个符号变成了一个。 目标是确定在经过一些此类操作序列后，我们是否可以将初始字符串精确地缩减为第二个字符串。 

关键的心理模型是我们不是重新排列角色，而是反复将邻居合并成一行。 每次合并都会局部破坏位置信息，但全局保留线性结构。 由于每个操作都会将长度减少一，因此任何有效的转换$S$到$T$准确地要求$|S| - |T|$运营。 

约束条件达到$10^6$，这会立即排除任何合并模拟或子字符串上的任何动态编程。 任何解决方案都必须是线性或接近线性的，并且必须避免在重复修改下显式维护字符串。 

一个天真的误解是认为最终的字符串取决于任意的位配对，但邻接性被保留，因此该过程受到顺序的限制。 

当初始字符串有许多看起来可以以不同方式“合并”的零时，就会出现微妙的失败情况，但合并的结构实际上是严格的。 例如，在像这样的字符串中`1010`，看起来可能根据合并顺序创建不同的结果，但可达集比组合爆炸建议的要小得多。 

另一个边缘情况是当$T$具有不同的长度，但与本地 XOR 模式“看起来一致”$S$。 由于合并确定性地减少长度，任何不考虑长度差异的方法都将错误地接受不可能的转换。 

## 方法

 如果我们尝试直接模拟该过程，我们将重复扫描字符串，选择相邻的对，用异或替换它们，然后继续，直到长度匹配$T$。 每次合并成本$O(n)$在一个幼稚的实施中，因为我们需要重建或改变结构。 高达$10^6$角色和潜在的$10^6$操作，这变成了$O(n^2)$，这太慢了。 

不同的视角是逆向操作。 不要考虑合并，而是想象将最终的字符串拆分回原始字符串。 中的每个角色$T$代表一个连续的块$S$其 XOR 等于该字符。 问题变成了一个分割问题：我们可以分割吗$S$准确地进入$|T|$XOR 匹配的连续段$T$？ 

这种重新表述之所以有效，是因为每次合并仅组合相邻元素，因此任何最终值都对应于原始字符串中连续段的 XOR。 段的顺序被保留，并且每个段必须恰好贡献一个字符$T$。 

所以问题归结为检查是否存在分区$S$进入$|T|$连续的段，使得每个段异或匹配相应的字符$T$。 因为我们只需要存在，所以贪婪扫描就足够了：我们在遍历时累积异或$S$，每当当前前缀 XOR 与下一个目标位匹配时，我们就剪切一个段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n²) | O(n) | 太慢了|
 | 贪心段异或匹配 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们扫描$S$从左到右，同时保持当前段的运行异或。 我们还跟踪我们的位置$T$，指示我们当前正在尝试匹配的目标位。 

1. 初始化一个指针$j = 0$为了$T$，和一个变量`cur = 0`存储当前段的异或。 
2. 迭代每个字符$S[i]$, 更新`cur ^= S[i]`。 
3. 每当`cur`变得等于$T[j]$，我们完成这一部分并移动$j$前进、重置`cur`为零。 
4. 继续直到结束$S$。 
5.处理完所有字符后，检查所有字符是否在$T$被匹配，意思是$j = |T|$，并确保没有剩余的部分段（`cur = 0`）。 

关键思想是，每次关闭一个段时，它都准确对应一个输出字符。 我们绝不允许部分片段溢出到下一个目标位置。 

### 为什么它有效

 相邻 XOR 合并的任何序列都对应于在原始字符串的连续间隔上构建 XOR 值。 任何操作都不会混合不相邻的区域，因此最终的字符串必须表示原始字符串划分为连续的块。 相反，任何有效划分为 XOR 一致段的方法都可以通过在每个段内部进行合并直至其合并为单个位来实现。 这在有效合并序列和有效分段之间创建了一对一的对应关系，这证明了贪婪构造的合理性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    S = input().strip()
    T = input().strip()
    
    n, m = len(S), len(T)
    if n < m:
        print("No")
        return
    
    j = 0
    cur = 0
    
    for ch in S:
        cur ^= (ord(ch) - 48)
        
        if j < m and cur == (ord(T[j]) - 48):
            j += 1
            cur = 0
    
    if j == m and cur == 0:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```该实现使扫描保持完全流式传输，因此不会构建中间字符串。 每个字符被处理一次，XOR 被增量地维护。 唯一微妙的条件是确保在消耗完所有$S$，不存在未完成的段，因为这意味着额外的部分合并不能对应于中的任何字符$T$。

```我们尝试构建单个段：

 | 步骤| 查尔 | 当前| j | T[j] | 行动|

 到最后，我们还有`cur = 1`尽管$T$在第一个字符之后已经完全匹配。 剩下的部分无法消失，所以答案是否定的。

 ## 边缘情况

 一个最小的字符串，例如`S = 0, T = 0`确认算法正确接受简单的单段情况，因为初始 XOR 已经与目标匹配。 

像这样的案例`S = 10, T = 1`表明即使 XOR 模式看起来在本地兼容，分割也无法产生与目标匹配的单个干净块，因为如果没有额外的合并，剩余结构就无法消失。 

像这样的案例`S = 1111, T = 0`练习完整的累积行为：运行的 XOR 交替，但永远不会自然地对齐到一个干净的分区，该分区恰好以正确的段数结束，并且当最后一个段未关闭时，算法会正确地拒绝它。
