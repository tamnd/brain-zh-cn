 ## 解决方案
 ## 问题理解

 我们得到了一系列每日价格变化，其中每个值代表股票价格从一天到下一天的变动情况。 从这个序列中，我们重复查看在位置结束的滑动窗口`i`且最多跨度`M`元素。 对于每个职位`i`，我们只考虑段`A[max(1, i-M+1) ... i]`。 

在每个这样的窗口内，我们希望找到最差的连续下降部分。 下降段是任何连续的子数组，其总和尽可能为负，但我们只关心最严重的下降。 如果所有子数组都是非负的，则答案定义为零。 

因此，对于每个窗口，我们计算最小子数组和，如果该最小值为正或零，我们将其限制为零。 

这本质上是经典“最大子数组和”问题的滑动窗口版本，只不过我们最大化向下移动而不是向上增益。 

限制因素`N ≤ 100000`和`M ≤ N`这意味着任何从头开始重新计算每个位置答案的解决方案都太慢了。 对所有窗口的二次方法将尝试大约`10^10`在最坏的情况下进行操作，这远远超出了限制。 我们需要摊销线性或近线性结构。 

一些微妙的边缘情况很重要：

 必须输出具有所有非负值的窗口`0`。 例如，如果`A = [1, 2, 3]`和`M = 2`，每个窗口都不会产生有效的下降，因此每个答案都是`0`。 

一个窗口，其中最严重的下降不是完整的前缀或后缀，而是内部段，必须正确处理。 例如，在`[-3, -5, 2, -3]`，最严重的下降是`[-3, -5]`，不是完整的数组。 

一个天真的错误是假设最严重的下降总是后缀和或前缀和。 这在最佳段位于内部的混合符号数组上失败。 

## 方法

 蛮力的想法很简单。 对于每个索引`i`，我们取最后一个`M`结束于的元素`i`并尝试该窗口内所有可能的子数组。 对于每个子数组，我们计算其总和并跟踪最小值。 

这是正确的，因为它明确地检查每个可能的连续段。 然而，每个窗口内的大小可达`M`， 有`O(M^2)`子数组。 全面的`N`窗户，这变成`O(NM^2)`以最糟糕的解释，甚至`O(NM)`如果我们用前缀和来优化子数组和计算，但当两者都是时仍然太大`10^5`。 

关键的观察是每个窗口都要求最小子数组和，这相当于最大前缀差。 如果我们定义前缀和`S[i] = A[1] + ... + A[i]`，然后任意子数组和`A[l..r]`是`S[r] - S[l-1]`。 最小化这个相当于修复`r`并找到最大值`S[l-1]`在允许的范围内。 

因此，每个窗口减少为在前缀和上维持滑动窗口最大值，但有一个限制，即仅在最后一个内添加前缀索引`M`职位是允许的。 这就变成了一个数据结构问题：我们需要在滑动窗口中维护最大前缀和，并计算`S[i] - max_prefix`。 

然而，有一个微妙的复杂性：窗口是动态的`i`，因此前缀索引进入和离开有效范围。 这正是单调双端队列场景，我们以降序维护最大前缀和的候选者。 

最终答案为`i`是：`min_subarray_sum = S[i] - max_{j in window}(S[j-1])`，如果为正则钳位为零。 

我们维护前缀和索引的双端队列，确保它们的前缀值递减，并且我们还确保删除窗口外的索引。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N·M²) | O(1) | O(1) | 太慢了|
 | 最优（前缀+双端队列）| O(N) | O(N) | 已接受 |

 ## 算法演练

 我们将问题转化为前缀和，然后在前缀索引上维护滑动结构。 

### 步骤

 1. 构建前缀和`S`在哪里`S[0] = 0`和`S[i] = S[i-1] + A[i]`。 

这让我们可以使用差异在恒定时间内计算任何子数组的总和。 
2. 对于每个位置`i`，我们想要最小子数组和在最后一个内部的某个地方结束`M`元素，对应于选择`j`在`[i-M, i-1]`对于前缀索引`j`。 
3. 维护索引的双端队列`S`它们是当前窗口中最大前缀值的候选者。 

我们按升序存储索引，但按降序维护前缀值。 
4、加工前`i`，从双端队列前面删除超出范围的索引。 

具体来说，任何索引`< i-M`不再有效。 
5、插入新的前缀索引时`i-1`，我们从双端队列的后面删除任何前缀值小于或等于的索引`S[i-1]`。 

这些是无用的，因为更大的前缀在所有未来的查询中占据主导地位。 
6.清理后，追加`i-1`到双端队列。 
7. 窗口中最好（最大）的前缀位于双端队列的前面。 计算：`best = S[i] - S[deque[0]]`。 
8. 如果`best > 0`， 输出`0`，否则输出`best`。 

### 为什么它有效

 双端队列保持了不变式，即其前端始终存储当前窗口中所有有效索引中具有最大前缀和的索引。 任何前缀总和小于新索引的索引将永远不会再次成为最佳索引，因为它更差，而且位置约束也更旧或相等。 这保证了每个查询在恒定时间内得到答复，并且每个索引最多进入和离开双端队列一次，从而保持线性复杂性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # prefix sums
    ps = [0] * (n + 1)
    for i in range(n):
        ps[i + 1] = ps[i] + a[i]

    from collections import deque
    dq = deque()

    res = []

    for i in range(1, n + 1):
        # window for prefix indices: [i-m, i-1]
        left = i - m
        if left < 0:
            left = 0

        # remove out of range indices
        while dq and dq[0] < left:
            dq.popleft()

        # add prefix index i-1
        idx = i - 1
        while dq and ps[dq[-1]] <= ps[idx]:
            dq.pop()
        dq.append(idx)

        best_prefix = ps[dq[0]]
        best = ps[i] - best_prefix

        if best > 0:
            best = 0
        res.append(str(best))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```前缀和数组允许恒定时间子数组和计算。 双端队列维护结束于的负子数组的最佳起始点的候选者`i`。 关键细节是我们存储前缀索引，而不是数组索引，并且始终使用`i-1`作为最新候选前缀端点。 

删除外部索引`[i-m, i-1]`确保遵守窗口约束，同时单调去除确保仅保留潜在的最佳前缀和。

 ## 边缘情况

 当出现单元素窗口时`M = 1`。 该算法简化为检查元素是否为负，因为唯一的子数组就是它本身。 前缀/双端队列方法仍然有效，因为前缀索引的窗口变成了单个点，并且差异`S[i] - S[i-1]`正确地产生`A[i]`。 

当所有值都非负时，前缀和严格递增，因此每个窗口中的最大前缀始终是最早的有效索引。 计算出的子数组和变为非正数，因此钳位始终产生零。 双端队列仍会正确更新，但不会更改结果结构。 

当所有值均为负数时，最大前缀始终是最小负前缀，通常是窗口中最早的前缀。 这会产生与累积最差段相匹配的稳定递减的答案序列。 该算法可以处理此问题，因为双端队列保留递减的前缀顺序，但所有候选者仍然保持相关，直到它们滑出范围。
