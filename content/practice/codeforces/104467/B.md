 ## 解决方案
 ## 问题理解

 给定一个二进制字符串，我们需要回答对其子字符串的多个独立查询。 每个查询给出一个范围$[L, R]$。 在这个范围内，我们必须找到任何更小的子段$[a, b]$这样子串$S[a..b]$完美平衡，因为它恰好包含整个子串的一半零和一半$S[L..R]$。 

这个条件比最初看起来更严格。 如果查询范围有$c_0$零点和$c_1$，那么任何有效答案都必须是一个子数组，其计数恰好是$c_0/2$零点和$c_1/2$那些。 这立即意味着两者$c_0$和$c_1$必须是偶数，否则不存在答案。 

输出必须是任何有效的对$(a, b)$如果不可能，则为 -1。 我们不需要最短或最长的线段，只需要存在。 

限制因素$N, Q \le 10^5$意味着每个查询必须粗略地处理$O(1)$或者$O(\log N)$预处理后的时间。 在最坏的情况下，任何直接扫描每个范围的解决方案都会太慢，因为它需要$O(NQ)$运营。 

一个微妙的点是，答案不一定与对称性或前缀边界对齐。 天真的直觉可能会建议搜索中点分割或平衡前缀和，但有效段可以出现在查询间隔内的任何位置。 

朴素方法的一种失败案例是假设答案必须居中。 例如，在这样的范围内`0011`，存在有效答案，例如`[2,3]`，但如果仅检查中心周围，基于中点的猜测就会错过它。 

另一种失败模式是尝试在不进行预处理的情况下贪婪地扩展或缩小窗口。 如果没有前缀结构或奇偶校验推理，这就会退化为每个查询的二次扫描。 

## 方法

 暴力解决方案会尝试每一对$(a, b)$里面$[L, R]$，计算该子数组中的 0 和 1，并检查它是否与所需的半数匹配。 即使使用前缀和来加速计数，这仍然会检查$O(N^2)$最坏情况下每个查询的间隔。 和$10^5$查询，这会变得天文数字。 

关键的观察结果是，该条件仅取决于 0 和 1 的计数差异。 如果我们将字符串编码为$+1$为了`1`和$-1$为了`0`，那么平衡子串恰好是和为零的子串。 问题简化为：在每个查询范围内，找到一个非空子数组，其总和为零，并且其总和约束与均匀分割整个范围一致。 

这将问题转化为前缀和。 让$P[i]$是前缀总和$i$。 一个子串$[a, b]$总和为零当且仅当$P[b] = P[a-1]$。 因此，任务变成在查询范围内查找前缀和相等的两个索引。 

但是，我们必须遵守附加约束，即所选子数组恰好对应于整个范围中的一半零和一。 这导致了一个更强大的结构：总和超过$[L, R]$必须是偶数，我们本质上是在寻找一个中点，使前缀和正好达到总前缀差的一半。 

因此，我们计算前缀和，并针对每个查询将其简化为找到前缀和等于某个范围内的目标值的位置。 这成为一个经典的范围存在查询，可以使用前缀和的预处理位置和二分搜索来处理。 

对于每个前缀和值，我们存储它出现的所有索引。 对于查询，我们计算目标前缀总和值，然后检查有效索引区间中是否存在出现的情况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(N^2 Q)$|$O(1)$| 太慢了|
 | 前缀+哈希+二分查找|$O((N+Q)\log N)$|$O(N)$| 已接受 |

 ## 算法演练

 1. 将二进制字符串转换为前缀和数组，其中`0`贡献-1并且`1`贡献+1。 这允许任何子串平衡条件表示为前缀相等条件。 
2. 构建一个列表数组，将每个前缀和值映射到它出现的索引。 这是至关重要的，因为我们需要快速访问查询范围内的事件。 
3. 对于每个查询$[L, R]$，使用前缀和计算范围的总和。 如果这个和不偶数，则立即返回 -1，因为相等的分割是不可能的。 
4. 计算范围和的一半对应的目标前缀和值。 这表示必须发生有效剪切的前缀级别。 
5.我们现在需要在里面找到两个位置$[L-1, R]$其中前缀总和等于相同的值，因此它们的差异给出了完全包含在中的有效子段$[L, R]$。 在存储的位置列表上使用二分搜索查找该前缀值来查找范围内的候选者。 
6. 如果存在这样的位置，则输出对应的位置$(a, b)$。 否则输出-1。 

关键操作是将“在范围内查找平衡子数组”问题转换为“在范围内查找重复前缀和值”问题，由于出现列表已排序，因此效率很高。 

### 为什么它有效

 前缀和变换确保每个子数组和都表示为两个前缀值的差。 平衡子数组对应于两个端点处的前缀和相等。 子数组必须恰好代表原始范围的一半的约束强制唯一确定前缀目标。 由于所有出现的前缀都按排序顺序存储，因此可以使用二分搜索检测查询间隔内的任何有效对，并且由于枚举了所有出现的前缀，因此不会错过任何有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    # prefix sum: 1 -> +1, 0 -> -1
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (1 if s[i - 1] == '1' else -1)

    # map prefix value -> indices
    pos = {}
    for i, v in enumerate(pref):
        if v not in pos:
            pos[v] = []
        pos[v].append(i)

    out = []

    for _ in range(q):
        L, R = map(int, input().split())

        total = pref[R] - pref[L - 1]
        if total % 2 != 0:
            out.append("-1")
            continue

        target = pref[L - 1] + total // 2

        if target not in pos:
            out.append("-1")
            continue

        arr = pos[target]

        # find any index in [L-1, R]
        # binary search manually
        lo, hi = 0, len(arr) - 1
        left_idx = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if arr[mid] >= L - 1:
                left_idx = mid
                hi = mid - 1
            else:
                lo = mid + 1

        if left_idx == -1 or arr[left_idx] > R:
            out.append("-1")
            continue

        # second endpoint: we need another occurrence in range if possible
        start = left_idx
        if start + 1 < len(arr) and arr[start + 1] <= R:
            a = arr[start] + 1
            b = arr[start + 1]
            out.append(f"{a} {b}")
        else:
            out.append("-1")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码在线性时间内构造前缀和，然后按前缀值对索引进行分组。 每个查询都会计算所需的目标前缀总和级别，并使用二分搜索来查找查询窗口内的有效匹配项。 输出结构会小心地移动索引，因为前缀数组是从 0 开始的，而字符串是从 1 开始的。 

一个微妙的实现细节是在之间保持一致的索引$S$、前缀数组和存储的位置。 在之间转换时通常会出现相差一错误$S[a..b]$和前缀差异，因此代码一致使用前缀索引$i$代表处理后的状态$S[i]$。

 ## 边缘情况

 关键的边缘情况是前缀和目标存在，但仅在查询范围内一次。 在这种情况下，即使总和条件表明潜在的平衡，也无法形成有效的子数组。 该算法通过要求至少出现两次来处理这个问题$[L-1, R]$，确保存在真实的子数组而不是单个前缀匹配。 

另一个边缘情况是当查询范围具有奇数总不平衡时。 即使局部结构看起来部分平衡，全局要求也会强制立即拒绝，并且前缀奇偶校验会尽早过滤这些情况而不进行搜索。 

最后的边缘情况是查询范围之外的重复前缀值。 由于出现次数是全局存储的，二分搜索步骤确保我们只考虑查询窗口内的索引，从而防止远程匹配出现误报。
