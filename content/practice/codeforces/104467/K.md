 ## 解决方案
 ## 问题理解

 我们从`T`卡拉 OK 系统锁定前几秒。 歌曲必须从时间开始连续播放`0`，所以永远不会有空闲时间。 三首普通歌曲可供选择，长度`A`,`B`， 和`C`，并且每个都可以被选择任意多次。 还有一首特别的歌曲，金曲，长度固定为`768`秒。 

锁定恰好在时间发生`T`。 严格来说，在锁定之前的任何时刻仍可以开始一首新歌曲，但一旦时钟到达`T`，无法选择更多歌曲。 由于允许当前播放的歌曲结束，因此最后一首歌曲通常应该是金曲，因为它比其他歌曲长得多。 

任务是最大化歌唱时间总量。 这意味着我们要把普通歌曲安排在金曲之前，这样金曲的开始时间尽可能晚，但仍严格小于金曲的开始时间。`T`。 

的最大值`T`只是`18000`，而每首普通歌曲都在`180`和`300`秒长。 这立即排除了尝试所有可能的歌曲序列，因为序列的数量随着播放的歌曲数量呈指数增长。 另一方面，时间限制足够小，任何算法都与`T`很容易足够快。 

一个容易犯的错误就是忘记金曲可能会在某个时间开始播放`0`。 考虑```
3 200 190 180
```锁前不适合播放普通歌曲。 正确答案是`768`，因为金曲可以立即开始。 

另一个微妙的情况是剩余时间无法准确填满。 例如，```
400 180 200 300
```最好的普通前缀持续`200`秒。 金曲开始时间`200`，总共给出`968`。 等到时间`399`这是不可能的，因为空闲时间是被禁止的。 

差一错误的第三个来源是锁定规则。 认为```
600 300 200 180
```二`300`-第二首歌曲恰好在时间结束`600`。 此时无法启动金曲，因为屏幕已锁定。 最好的有效选择是`200`-第二首歌曲，后面跟着两首`180`-第二首歌曲，到达时间`560`，然后开始金曲。 答案是`1328`， 不是`1368`。 

## 方法

 直接强力搜索生成普通歌曲的所有可能序列，其总持续时间低于`T`。 当无法添加更多歌曲时，当前时长将被视为金曲的开始时间。 由于每个位置都有三个选择，因此序列数量的增长大致如下`3^k`， 在哪里`k`是播放的普通歌曲的数量。 歌曲长度大约`180`秒，`k`可以达到约`100`，使得搜索完全不可行。 

关键的观察是，只有累积时间才重要。 导致相同经过时间的歌曲顺序对未来的选择没有影响。 这意味着问题实际上是询问下面的时间`T`通过重复添加即可到达`A`,`B`， 或者`C`。 

这立即表明了对经过时间的动态规划。 让`dp[t]`表明是否可以准确支出`t`秒只使用普通歌曲。 我们从`dp[0] = True`。 每当一个时间可达时，添加三个歌曲长度中的任何一个都会产生另一个可达时间，前提是它仍然低于`T`。 

计算完所有可达时间后，我们只需找到严格小于的最大可达值`T`。 金曲从那里开始，答案就是时间加上`768`。

 ## 算法演练

 1.读取四个整数`T`,`A`,`B`， 和`C`。 
2. 创建布尔数组`dp`长度`T`。 指数`i`代表是否准确地`i`可以在锁定前播放几秒普通歌曲。 
3. 设置`dp[0] = True`因为使用不普通的歌曲总是可能的。 
4. Scan every reachable time from`0`到`T - 1`。 每当`dp[i]`是的，尝试添加三个普通歌曲长度中的每一个。 如果`i + song < T`，将新时间标记为可达。 
5. 处理完所有可达状态后，再次扫描数组，记录最大可达时间。 
6. 输出最大可达时间加上`768`，因为金曲是在普通歌曲之后立即开始的，并且总是完整播放。 

### 为什么它有效

 动态规划不变量是在处理完一个可达时间后`x`，每次通过用一首额外的普通歌曲扩展该时间表来获得的时间也被标记为可达。 由于每个序列都在时间开始`0`每个序列都是通过重复附加一首歌曲来构建的，下面每个有效的经过时间`T`最终被发现。 

相反，每个标记的状态都对应于实际的歌曲序列，因为状态只能通过将一个合法的歌曲长度添加到已经有效的状态来创建。 最大可达时间恰好是金曲可以合法开始的最晚时刻，因此加上其固定持续时间就得到了最大总演唱时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

T, A, B, C = map(int, input().split())

dp = [False] * T
dp[0] = True

songs = (A, B, C)

for t in range(T):
    if not dp[t]:
        continue
    for s in songs:
        nt = t + s
        if nt < T:
            dp[nt] = True

best = 0
for t in range(T):
    if dp[t]:
        best = t

print(best + 768)
```动态编程数组准确地存储了锁定之前可到达的经过时间。 由于每次转换至少都会增加时间`180`秒，循环是不可能的，简单的从左到右扫描就足够了。 

比较使用`nt < T`， 不是`<= T`。 准时开始金曲`T`被禁止，因为屏幕在那一刻锁定。 这是该问题中最常见的差一错误。 

最终扫描仅保留最大可达值。 如果普通歌曲根本不适合，只有`dp[0]`是真的，所以答案自然就变成了`768`。

## 测试用例```python
import sys, io

def solve():
    input = sys.stdin.readline

    T, A, B, C = map(int, input().split())

    dp = [False] * T
    dp[0] = True

    for t in range(T):
        if not dp[t]:
            continue
        for s in (A, B, C):
            if t + s < T:
                dp[t + s] = True

    best = 0
    for t in range(T):
        if dp[t]:
            best = t

    print(best + 768)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old
    return out.getvalue().strip()

# provided samples
assert run("601 180 210 300\n") == "1368", "sample 1"
assert run("3 200 190 180\n") == "768", "sample 2"

# custom cases
assert run("180 180 180 180\n") == "768", "cannot start ordinary song at T"
assert run("181 180 180 180\n") == "948", "ordinary song fits once"
assert run("540 180 180 180\n") == "1128", "exactly reaches T, not allowed"
assert run("18000 300 300 300\n") == "18768", "maximum input"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`180 180 180 180`|`768`| 普通歌曲完全相等的边界`T`|
 |`181 180 180 180`|`948`| 允许一首普通歌曲的最小价值 |
 |`540 180 180 180`|`1128`| 准确抵达`T`不得使用 |
 |`18000 300 300 300`|`18768`| 最大约束|

 ## 边缘情况

 考虑```
3 200 190 180
```动态规划表仅标记`0`之所以可达，是因为每首普通歌曲都超出了可用时间。 算法返回`0 + 768 = 768`，正确认识金曲必须立即开始。 

现在考虑```
400 180 200 300
```可达时间为`0`,`180`,`200`,`300`， 和`380`。 时间`400`不可到达，因为它不严格小于`T`。 该算法选择`380`, 生产`1148`，或者如果仅`200`在不同的歌曲长度下都可以访问，它正确地选择了它。 不会引入空闲等待，因为每个可达状态都对应于不间断播放。 

最后，考虑```
600 300 200 180
```动态规划数组标记`560`作为可达的，同时`600`被忽略，因为转换使用条件`next < T`。 该算法开始金曲`560`并返回`1328`，完全匹配锁定规则。
