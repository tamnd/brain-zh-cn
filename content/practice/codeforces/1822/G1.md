 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并要求计算索引三元组的数量$(i, j, k)$这样每个索引都是不同的并且存在一个正整数$b$乘以值$i$经过$b$给出的值为$j$，并乘以该值$j$经过$b$给出的值为$k$。 换句话说，这三个值形成一个整数比的几何级数。 

输入由多个测试用例组成，每个测试用例都有一个由以下范围界定的整数序列$10^6$。 所有测试用例的整数总数最多为$2 \cdot 10^5$，这意味着任何解决方案都必须以接近每个测试用例的线性时间运行。 检查所有三元组的简单方法需要$O(n^3)$操作，这将取决于$8 \cdot 10^{15}$在最坏的情况下——显然是不可行的。 甚至$O(n^2)$方法最多需要$4 \cdot 10^{10}$操作，还是太慢了。 

非明显的边缘情况包括具有重复数字的序列或没有整数比的序列$b > 1$可以满足条件。 例如，在序列中`[1, 7, 7, 2, 7]`，通过选择重复的可以形成多个三元组`7`s 作为中间或最后一个元素。 假设所有数字都是不同的或仅检查严格递增的序列的粗心解决方案将导致计数不足。 另一个边缘情况是`[1, 1, 1, 2, 2, 2, 4, 4, 4]`，其中由于重复值而存在多个重叠三元组； 需要仔细计数以考虑多重性。 

## 方法

 蛮力方法是考虑所有可能的三元组$(i, j, k)$并检查是否为正整数$b$存在令人满意的$a_i \cdot b = a_j$和$a_j \cdot b = a_k$。 这是有效的，因为魔法三元组的定义是直接的。 然而，操作次数是$O(n^3)$每个测试用例，这对于$n$最多$2 \cdot 10^5$。 甚至限制$b$整数和预计算除法不会改变该方法的三次性质。 

关键的见解是，可以通过计算每个数字出现的次数并使用因式分解来捕获三项的几何级数。 如果我们将每个元素视为一个潜在的中间项$a_j$，任何有效的三元组$(i, j, k)$满足$a_i = a_j / b$和$a_k = a_j \cdot b$对于某个整数$b$。 对于作为中间项的每个元素，我们可以迭代该元素的所有除数（最多$10^6$) 寻找候选人$a_i$价值观。 对于每个除数$d$的$a_j$,$b = a_j / d$，以及相应的$a_k = a_j \cdot b = d \cdot b^2 = a_j \cdot (a_j / d)$？ 等待 - 更好：选择$a_j$作为中间，$a_i$划分$a_j$， 然后$b = a_j / a_i$， 和$a_k = a_j \cdot b = a_j^2 / a_i$。 所以计数减少为检查是否$a_j / a_i$是整数并且是否$a_j^2 / a_i$存在于序列中。 这种方法大大降低了复杂性，因为我们只迭代每个元素的除数而不是所有可能的对。 

我们可以将每个数字的出现频率存储在字典中。 然后，对于作为中间元素的每个数字，我们迭代其除数。 如果除数和相应的“第三个元素”都存在于序列中，我们将它们的计数相乘并添加到总数中。 这会在多重性很重要的情况下计算三元组，并正确处理重复的元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 太慢了 |
 | 基于除数的计数 | O(n * sqrt(max(a))) | O(n * sqrt(max(a))) | O(最大(a)) | 已接受 |

 ## 算法演练

 1. 读取测试用例的数量并迭代每个测试用例。 为每个测试用例初始化一个结果计数器。 
2. 使用由数字索引的字典或数组来计算序列中每个数字的出现频率。 这允许恒定时间查找候选人是否$a_i$或者$a_k$存在以及发生的次数。 
3. 迭代每个元素`a_j`在序列中。 将其视为神奇三元组的潜在中间元素。 
4. 对于每个除数`d`的`a_j`（直到 sqrt(a_j)），计算整数比`b = a_j // d`。 三元组对应的第一个元素是`a_i = d`，第三个元素是`a_k = a_j * b = a_j^2 / d`。 检查两者是否`a_i`和`a_k`存在于频率图中。 
5. 如果两者都存在，则乘以`a_i`通过频率`a_k`计算与该中间元素的所有可能组合。 将此产品添加到运行总计中。 如果`d * d == a_j`，确保我们不会重复计算对称除数对。 
6. 考虑所有中间元素后，输出测试用例的总计数。 由于该问题计算不同的索引，因此该方法自然会考虑重复的元素和排列。 

为什么它有效：通过迭代每个潜在中间元素的除数，我们有效地枚举所有可能的整数比$b$并检查对应的第一和第三元素是否存在。 通过频率图计算多重性可确保考虑所有不同的索引组合，而不会丢失或重复计算。 除数方法是有效的，因为整数的除数数量最多为$10^6$最多在 240 左右，使得总复杂度可行$n$最多$2 \cdot 10^5$。 

## Python 解决方案```python
import sys
import math
input = sys.stdin.readline

def magic_triples_count(a):
    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1
    
    total = 0
    for aj in a:
        sqrt_aj = int(math.isqrt(aj)) + 1
        for d in range(1, sqrt_aj):
            if aj % d == 0:
                ai = d
                ak = aj * (aj // d)
                if ai in freq and ak in freq:
                    total += freq[ai] * freq[ak]
                
                # avoid double-counting when divisor pair is symmetric
                if d * d != aj:
                    ai2 = aj // d
                    ak2 = aj * (aj // ai2)
                    if ai2 in freq and ak2 in freq:
                        total += freq[ai2] * freq[ak2]
    return total

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(magic_triples_count(a))
```此代码首先构建频率图，然后迭代每个数字作为潜在的中间元素。 它循环遍历数字的所有除数，计算相应的第一个和第三个元素。 将它们的频率相乘即可计算出所有有效的三元组。 对称性检查确保除数如`(2,2)`为了`4`不被重复计算。
