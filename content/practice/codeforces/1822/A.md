 ## 解决方案
 ## 问题理解

 提要可以被认为是视频的线性列表，每个视频都有两个属性：观看需要多长时间以及观看的愉快程度。 蘑菇菲利波夫从第一个视频开始，可以在列表中向右移动，每一步花一秒跳到下一个项目。 他可以随时决定停止跳过并开始观看视频。 一旦他选择了某个位置的视频`i`，总消耗时间是从位置1跳到位置1所花费的时间`i`加上视频本身的时长。 

对于每个测试用例，我们必须确定他应该选择哪个视频，以便“到达时间”和“观看时间”的总和不超过可用的午餐总时间`t`。 在满足这个约束的所有视频中，我们选择一个具有最大娱乐价值的视频。 

该模型的重要部分是到达视频的成本`i`是固定且确定的：它正是`i - 1`秒。 选择之间没有分支或相互作用，因此每个指标都可以独立评估。 

限制很小：`n ≤ 50`和`q ≤ 1000`。 这意味着总共最多进行 50,000 次视频检查。 任何线性的解`n`每个测试用例都足够快，而任何涉及每个视频嵌套大量计算的内容仍然是可以接受的，但没有必要。 

一个常见的错误是忽略跳过成本而只比较`a[i] ≤ t`。 但这失败了，因为访问更深的视频会消耗时间。 例如，如果`t = 5`，位于位置 4、持续时间为 2 的视频无效，因为到达该视频已经花费了 3 秒，使总时间为 5。另一个错误是尝试动态模拟 feed； 这是不必要的，因为每个候选人都是独立的。 

边缘情况出现在以下情况：

 - 时间内无法访问任何视频。 例子：`n = 3, t = 1`, 持续时间`[10,10,10]`。 即使第一个视频至少需要1秒才能到达，再加上10秒的观看时间，超过`t`。 输出必须是`-1`。 
- 最好的娱乐视频并不是最早有效的视频，因此我们必须跟踪最大值`b[i]`在有效选择中，不要停在第一个有效索引处。 

## 方法

 蛮力方法是直接的：对于每个视频`i`，计算是否`i - 1 + a[i] ≤ t`。 如果有效，请考虑其娱乐价值`b[i]`。 保留所有有效指数中最好的。 这需要检查每个测试用例的每个视频，从而导致`O(n)`每个测试用例的工作。 

和`n ≤ 50`而最多1000个测试用例，这最多也就是50000个评估，这是非常小的。 即使是幼稚的实现也是安全的。 

不需要更深层次的优化结构，因为每个视频的可行性仅取决于其自身的索引和持续时间。 “跳过成本”是线性的并且每个位置都是独立的，因此前缀和、排序或贪婪重新排序没有任何好处。 

关键的观察结果是，问题简化为独立过滤：我们从由简单约束定义的集合中选择最佳元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(1) | O(1) | 已接受 |
 | 最佳 | O(nq) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读`n`,`t`，持续时间数组`a`、及娱乐阵列`b`。 我们让它们按索引对齐，因为每个视频都是配对的对象。 
2. 初始化变量`best_value = -1`和`best_index = -1`。 这些跟踪迄今为止看到的最佳有效视频。 哨兵`-1`表示不存在有效视频的情况。 
3. 迭代每个视频索引`i`从`1`到`n`。 
4. 计算选择视频所需的时间`i`，即`(i - 1) + a[i]`。 第一项表示从源开始的跳过时间，第二项是观看持续时间。 
5. 如果这个总时间小于或等于`t`，该视频在午餐限制内是可行的。 
6.如果可行，比较其娱乐价值`b[i]`和`best_value`。 如果更大，则更新两者`best_value`和`best_index`到这个视频。 
7.扫描所有视频后，输出`best_index`。 如果没有找到有效的视频，`best_index`遗迹`-1`。 

### 为什么它有效

 每个视频都在仅取决于其位置的固定确定性成本模型下进行评估。 选择之间没有相互作用，因此可行性是每个元素的属性。 该算法保持了处理第一个之后的不变量`i`视频、`best_index`是该前缀所有有效视频中娱乐价值最高的`[1..i]`。 因为每个视频都被检查一次，所以最终结果是整个数组中所有有效候选者中最好的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    n, t = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    best_val = -1
    best_idx = -1

    for i in range(n):
        time_needed = i + a[i]  # i == i-1 in 0-based indexing

        if time_needed <= t:
            if b[i] > best_val:
                best_val = b[i]
                best_idx = i + 1

    print(best_idx)
```该代码直接遵循以下观察结果：跳过时间恰好是从零开始的索引中的索引偏移量。 该循环检查可行性并贪婪地更新最佳答案。 

一个微妙的点是保持索引一致：在 Python 中我们使用`i`从0开始，所以到达视频`i`成本`i`秒，不`i-1`。 返回的索引被调整回从 1 开始的索引。

 ## 边缘情况

 当`t`非常小，唯一可能的候选者通常是第一个视频，因为后面的每个位置都会增加至少一秒的跳过成本。 该算法自然会处理这个问题，因为`i + a[i]`很快超过`t`为所有人`i > 0`。 

例如：```
n = 3, t = 2
a = [5, 1, 1]
b = [10, 20, 30]
```执行检查：

 - i=1:0+5=5>2，无效
 - i = 2：1 + 1 = 2 ≤ 2，有效 → 最佳 = 20
 - i = 3: 2 + 1 = 3 > 2，无效

 输出变为索引 2，表明跳过成本可以使后面的短视频更受欢迎，即使早期的视频较长。 

该算法独立地正确评估每个候选者，并且从不假设娱乐价值或持续时间的单调性。
