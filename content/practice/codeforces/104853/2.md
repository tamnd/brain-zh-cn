 ## 解决方案
 ## 问题理解

 我们得到一个字符串集合，每个字符串仅包含 0 到 9 之间的数字。对于任何有序的索引对$(i, j)$和$i < j$，我们连接两个字符串$s_i$和$s_j$。 任务是计算有多少个这样的串联产生了非递减的数字序列，这意味着每个数字都小于或等于下一个数字。 

关键对象是连接的字符串$s_i + s_j$。 该条件不要求对每个字符串单独进行排序。 相反，它询问之间的边界是否$s_i$和$s_j$，加上两者的内部结构，保留了整个合并字符串的单调性。 

限制很大：最多 100,000 个字符串，总长度为 100,000。 这立即排除了直接检查所有对，因为那将是$O(n^2)$，这远远超出了可行的范围。 即使简单地检查串联有效性也需要重复扫描字符串，这会太慢。 

串联边界处出现了一个微妙的问题。 即使两者$s_i$和$s_j$单独非递减，如果最后一位数字，它们的串联可能会失败$s_i$大于第一个数字$s_j$。 相反，即使一个字符串内部未排序，它可能仍然可以在某些受约束的配对中工作，但我们会看到内部结构大大减少。 

一个小的说明性失败案例：

 输入：```
2
21
123
```唯一的一对是$(1,2)$。 连接是`21123`，这不是非减的，因为在边界处 2 > 1。 所以答案是0。 

如果我们天真地只检查后到先兼容性，我们仍然会错过内部违规，例如`132`在单个字符串内，但那些已经使包含该字符串的任何串联无效，因此结构很重要。 

## 方法

 蛮力方法将迭代所有对$(i, j)$，连接字符串，并检查结果字符串是否是非递减的。 如果总长度是$m$，那么每次检查的成本$O(|s_i| + |s_j|)$，并且有$O(n^2)$对。 这会导致最坏的情况$O(n^2 \cdot \text{avg length})$，这对于$n = 10^5$。 

关键的观察结果是，在级联边界处非递减的条件极其严格。 一旦我们修复了两个字符串，唯一可能跨越边界的违规是第一个字符串的最后一位数字是否大于第二个字符串的第一个数字。 然而，只有当两个字符串本身内部不减时，这才有意义； 否则，内部违规行为就已经取消了他们的资格。 

因此，每个有效字符串首先必须是内部非递减的。 任何具有递减相邻对的字符串永远不能成为有效串联的一部分，因为该违规在最终串联中保持不变。 

现在每个字符串都可以用两个值来概括：它的第一个数字和最后一个数字。 这种减少之所以有效，是因为在每个字符串中，数字永远不会减少，因此出于兼容性目的，整个结构是在端点确定的。 

我们现在按第一个数字对字符串进行分类$f$和最后一位数字$l$。 一对$(i, j)$，串联有效当且仅当：

 1.$s_i$内部不减
 2.$s_j$内部不减
 3.$l_i \le f_j$这将问题简化为在小字母表（数字 0-9）上计数对，并具有简单的排序约束。 

我们预先计算每对有多少个有效字符串$(f, l)$。 然后我们聚合所有类别对。 由于数字很小，我们可以有效地计算第一个数字或最后一个数字的前缀和并计算兼容对。

 | 蛮力 |$O(n^2 \cdot L)$|$O(1)$| 太慢了 |
 | 优化分类 |$O(n + 100)$|$O(100)$| 已接受 |

 ## 算法演练

 1. 对于每个字符串，检查它是否从左到右非递减。 如果不是，请将其丢弃。 这是必要的，因为任何内部减少都会使每个串联无效。 
2. 对于每个有效字符串，提取其第一个数字$f$和最后一位数字$l$，并增加频率表`cnt[f][l]`。 
3. 在第一个数字上构建一个前缀结构：对于每个可能的最后一个数字$l$，我们希望快速访问有多少字符串的第一位数字至少或最多给定阈值。 相反，我们准备对第一位数字进行汇总计数。 
4. 迭代所有数字类别对$(f_i, l_i)$和$(f_j, l_j)$。 对于每一对，如果$l_i \le f_j$，那么这些组之间的所有组合都会贡献$cnt[f_i][l_i] \cdot cnt[f_j][l_j]$。 
5. 将所有有效贡献相加，注意与$i = j$只有通过跨组乘法才能正确处理并且排序$i < j$是通过计算组合而不是有序对来强制执行的。 

一旦保证内部单调性，正确性取决于将每个字符串减少到稳定的边界签名。 

### 为什么它有效

 一旦字符串内部不减，其内部数字之间的每次比较都与跨字符串有效性无关。 连接中唯一可能的失败点是两个字符串之间的单个边界。 因为每个字符串内的数字永远不会减少，所以边界条件$l_i \le f_j$既是必要的又是充分的。 这将问题转化为计算仅由端点定义的部分有序集中的兼容对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_good(s):
    for i in range(1, len(s)):
        if s[i] < s[i - 1]:
            return False
    return True

def main():
    n = int(input())
    
    cnt = [[0] * 10 for _ in range(10)]
    valid = []

    for _ in range(n):
        s = input().strip()
        if is_good(s):
            f = int(s[0])
            l = int(s[-1])
            cnt[f][l] += 1
            valid.append((f, l))

    # prefix sums over first digit
    pref = [[0] * 10 for _ in range(11)]
    for f in range(10):
        for l in range(10):
            pref[f + 1][l] = pref[f][l] + cnt[f][l]

    ans = 0

    # count ordered pairs i < j via aggregation
    for f1 in range(10):
        for l1 in range(10):
            c1 = cnt[f1][l1]
            if c1 == 0:
                continue
            for f2 in range(10):
                for l2 in range(10):
                    c2 = cnt[f2][l2]
                    if c2 == 0:
                        continue
                    if l1 <= f2:
                        if (f1, l1) == (f2, l2):
                            ans += c1 * (c1 - 1) // 2
                        else:
                            ans += c1 * c2

    print(ans)

if __name__ == "__main__":
    main()
```该解决方案首先过滤掉内部违反单调性的所有字符串。 该步骤至关重要，因为否则端点压缩将无效。 每个剩余的字符串都被简化为一对数字，表示其与其他字符串的交互。 

数字对上的双循环是安全的，因为字母表的大小只有 10，所以总共有 100 个状态。 唯一的微妙之处是正确处理自对：当两个字符串来自同一个桶时，我们必须计算组合$c(c-1)/2$而不是$c^2$，因为索引必须满足$i < j$。

 ## 边缘情况

 一个关键的边缘情况是存在许多相同的字符串。 例如，如果所有字符串都是`111`，每对都是有效的。 该算法将它们分组到一个桶 (1,1) 中，并正确计数$c(c-1)/2$，匹配对的数量。 

另一个边缘情况是字符串内部无效，但端点看起来兼容。 例如，`132`和`123`。 两者共享可能表明兼容性的端点，但是`132`被提前丢弃，因为它违反了内部的单调性。 这可以防止仅端点逻辑否则会引入的错误计数。
