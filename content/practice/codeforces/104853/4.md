 ## 解决方案
 ## 问题理解

 我们得到了几堆石头。 每堆石头都有一个固定的允许范围，即我们可以从中取出多少石头。 从堆$i$，我们必须选择一个整数$x_i$这样$l_i \le x_i \le r_i$。 从所有堆中选择后，所有选择值的总和必须恰好$s$。 

不同的是，我们没有被要求提供有效选择的单一全局计数。 相反，对于每一堆$i$，我们想知道有多少个值$x$在其允许的范围内是“安全的”，这意味着如果我们修复$x_i = x$，那么仍然可以为所有其他桩选择值，以使总和恰好变为$s$。 

因此，对于每一堆，我们都在有效地计算有多少本地选择与至少一个全局完成兼容。 

这些约束立即排除了任何试图枚举所有组合的方法。 和$n$最多$10^5$范围可达$10^9$，即使存储所有可能的和也是不可能的。 总金额$s$可以大到$10^{18}$，因此任何由 sum 索引的 DP 也是不可能的。 

一个天真的想法是：对于每一堆和每个候选值$x$，检查剩余的桩是否能形成和$s-x$。 但这重复了相同的可行性检查$O(n \cdot m)$次，这太慢了。 

例如，当一堆的范围非常窄时，就会出现微妙的边缘情况$l_i = r_i$。 在这种情况下，其固定值要么始终有效，要么永远无效，具体取决于其余部分能否形成所需的残差和。 粗心的解决方案可能会错误地假设桩之间是独立的，但可行性是全局的。 

## 方法

 关键的观察是，问题实际上是关于独立区间上求和的可行性。 每堆都贡献一个区间的选择$[l_i, r_i]$。 我们不计算作业； 我们正在测试部分分配是否可以扩展。 

让我们定义一下根本上发生了什么。 如果我们移除桩$i$，剩余的桩可以在一定的区间内形成任意的和$[L_i, R_i]$， 在哪里：$$L_i = \sum_{j \ne i} l_j, \quad R_i = \sum_{j \ne i} r_j$$这是因为每堆在其最小值和最大值之间独立贡献，因此总范围是相加的。 

现在修复桩$i$假设我们选择价值$x$。 剩余的牌堆必须形成总和$s - x$。 当且仅当：$$L_i \le s - x \le R_i$$重新排列：$$s - R_i \le x \le s - L_i$$所以对于桩$i$，有效值$x$正好是两个区间的交集：$$[l_i, r_i] \cap [s - R_i, s - L_i]$$在我们预先计算全局总和之后，这会将每个查询减少到区间交集。 

唯一昂贵的部分是计算$L_i, R_i$对于每一个$i$。 这可以通过总和来完成：$$\text{sumL} = \sum l_i, \quad \text{sumR} = \sum r_i$$然后：$$L_i = \text{sumL} - l_i, \quad R_i = \text{sumR} - r_i$$每个答案都变成了一个简单的算术交集$O(1)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（尝试每堆的所有选择）|$O(n \cdot \max r_i)$或者更糟糕的指数 |$O(1)$| 太慢了 |
 | 最优（间隔减少）|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 计算两个全局和：总和最小和`sumL`和总最大和`sumR`。 当所有桩都空闲时，这会捕获完整的可实现范围。 这样做的原因是桩贡献是独立的且可累加的。 
2. 对于每堆$i$，通过减去剩余桩的贡献来计算其可达到的范围：$L_i = sumL - l_i$,$R_i = sumR - r_i$。 

此步骤隔离堆$i$并将其余部分视为单个间隔系统。 
3. 将要求“剩余桩数总和”转换为$s - x$” 成为约束条件$x$:$s - R_i \le x \le s - L_i$。 

这来自于扭转定义可行性的不平等。 
4. 将此导出的区间与局部约束相交$[l_i, r_i]$。 的有效值$x$是：$$[\max(l_i, s - R_i), \min(r_i, s - L_i)]$$5.堆的答案$i$如果该交集非空，则为该交集的大小，否则为零。 

### 为什么它有效

 整个建设依赖于这样一个事实：剩余的$n-1$桩形成一个连续的总和区间，没有间隙。 由于每堆在固定范围内独立贡献，因此所有组合都填充最小和最大总和之间的整个范围。 这保证了可行性仅取决于区间重叠，而不取决于范围内的离散结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    l = [0] * n
    r = [0] * n

    sumL = 0
    sumR = 0

    for i in range(n):
        l[i], r[i] = map(int, input().split())
        sumL += l[i]
        sumR += r[i]

    out = []

    for i in range(n):
        L = sumL - l[i]
        R = sumR - r[i]

        low = max(l[i], s - R)
        high = min(r[i], s - L)

        if high < low:
            out.append("0")
        else:
            out.append(str(high - low + 1))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```该实现完全依赖于预先计算的总数。 重要的细节是在计算剩余范围时正确减去当前堆的贡献。 一个常见的错误是忘记下限总和和上限总和必须一致地排除同一堆。 

相交步骤是通常发生相差一错误的地方。 公式`high - low + 1`正确计算包含区间内的整数点。 

## 工作示例

 ### 示例 1

 假设我们有 3 堆：$$[1,3], [2,4], [1,2], \quad s = 6$$我们计算：$$sumL = 4, \quad sumR = 9$$现在分析第1堆：

 | 步骤| 价值|
 | --- | --- |
 | l₁，r₁ | 1, 3 |
 | 剩余 L、R | 4-1 = 3, 9-3 = 6 |
 | 总和约束的有效 x 范围 | [6-6, 6-3] = [0, 3] |
 | 交叉口| [1,3] ∩ [0,3] = [1,3] |
 | 答案| 3 |

 桩 2：

 | 步骤| 价值|
 | --- | --- |
 | l2，r2 | 2, 4 |
 | 剩余 L、R | 4-2 = 2, 9-4 = 5 |
 | 有效 x 范围 | [6-5, 6-2] = [1,4] |
 | 交叉口| [2,4]|
 | 答案| 3 |

 这显示了在固定全局范围后如何对称且独立地处理每个桩。

 ## 边缘情况

 一个微妙的情况是可行区间在相交后变空。 例如，如果全局要求强制使用超出堆允许范围的值。 

输入：```
2 10
0 3
0 3
```这里：

 sumL = 0，sumR = 6。对于任一堆，所需的贡献区间变为 [7,10]，它不与 [0,3] 相交，因此两个答案都为零。 该算法通过以下方式正确检测到这一点：`high < low`。 

另一种情况是可行区间完全包含桩的范围。 那么每个值都是有效的，答案很简单`r_i - l_i + 1`，它自然地脱离了交集公式，无需特殊的套管。
