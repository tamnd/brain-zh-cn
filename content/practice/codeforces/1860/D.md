 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并且允许我们使用任意两个位置之间的交换来重新排序。 每个操作的成本是一次交换，并且交换是不受限制的，因为我们可以选择任何一对索引。 

当 0 出现在 1 之前的索引对的数量等于 1 出现在 0 之前的索引对的数量时，该字符串称为平衡字符串。 换句话说，如果我们计算存在多少个类型 01 的反演和存在多少个类型 10 的反演，这两个数量必须匹配。 

由于我们可以自由交换字符，因此最终的字符串仅取决于我们在每个位置放置多少个 0 和 1。 重要的是重新排列后的字符串结构，而不是原始的邻接关系。 

约束很小，长度最多为 100。这立即排除了除了二次或三次状态探索之外的任何必要内容，但也表明该解决方案可能基于结构不变量而不是大量优化。 

一个关键的微妙之处在于，两个反转计数都取决于排序，但交换允许任意排列。 这意味着我们不受本地行动的限制； 我们正在选择多组字符的排列。 

一个常见的错误是假设问题在于使字符串按字典顺序排序或对称。 那不是必需的。 我们只需要从最终安排得出的两个全局计数之间相等。 

另一个陷阱是误解交换保留了多组字符。 任何解决方案都必须保留相同数量的 0 和 1，因此我们实际上是在选择放置这些固定计数的位置。 

## 方法

 如果我们进行暴力破解，我们将尝试保留 0 和 1 数量的字符串的所有可能排列，计算每个子序列的 01 和 10 数量，并选择达到任何平衡配置所需的最小交换数量。 即使对于 n = 100，这也是不可行的，因为不同排列的数量是 0 和 1 数量的组合，并且评估每个排列需要 O(n^2) 的对计数。 

重要的观察是条件“#01 等于#10”是极其严格的。 让我们看看这些计数代表什么。 

对于任何二进制字符串，每对索引根据顺序贡献为 01 或 10。 由不同字符组成的每一对都恰好对这两个计数之一做出贡献。 如果我们将 0 的数量表示为 Z，将 1 的数量表示为 O，则每个 0-1 对仅贡献一次，即 01 或 10，具体取决于顺序。 因此混合对的总数为 Z·O，并且这分为两个不相交的部分：#01 + #10 = Z·O。 

平衡条件要求#01 = #10，因此每个都必须等于Z·O / 2。这意味着Z·O 必须是偶数，但除非Z 和O 都是奇数，否则总是如此。 然而，更重要的是，该条件取决于零相对于一的分布方式。 

现在考虑交换操作。 交换可以在 1 块之间移动 0，反之亦然，并且每次交换都会以受控方式更改反转结构。 我们没有考虑排列，而是将问题重新定义为使字符串“尽可能接近”01 和 10 的贡献是对称的结构。 

核心的简化是，唯一重要的自由度是距离对称位置“多远”。 问题归结为对齐字符串，使其反转不平衡变为零。 

更直接的方法是计算当前差值 D = (#01 − #10)。 每次交换都可以在有限的范围内改变该值，并且任务变成最小化交换以使 D 为零。 当 n ≤ 100 时，我们可以使用动态规划或贪婪配对按位置和剩余不平衡对状态进行建模。

一个干净的解释是处理字符串并考虑每个字符对不平衡的贡献。 位置 i 处的零的贡献取决于其后出现的个数，而 1 的贡献取决于其后的零。 我们的目标是重新排列角色以消除这种全球不平衡。 

最佳策略是将最终字符串视为目标配置，并计算将原始字符串转换为任何零不平衡配置所需的最小交换。 我们可以尝试所有可能的分割点，以将零和一放置在交错模式中，并通过不匹配计数来计算交换成本。 因为 n 很小，我们可以有效地评估候选结构。 

我们比较：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!·n^2) | O(n!·n^2) | O(n) | 太慢了 |
 | 目标结构枚举+失配成本| O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们首先观察到任何最终字符串完全由零的位置决定，因为零填充了剩余的槽。 目标是选择一个平衡的最终安排，然后计算达到它所需的最小交换量。 

1. 计算零 Z 和一 O 的总数。这修复了任何有效重新排列的多重集。 
2. 通过选择零所在的位置集来隐式枚举所有候选最终字符串。 由于交换可以实现任何排列，因此我们只需要评估哪些零位置产生平衡字符串。 
3. 对于零位置的固定选择，计算该排列中 01 和 10 子序列的数量。 这可以通过扫描并计算每个零相对于后面的零的贡献来完成，反之亦然。 
4. 仅保留#01 等于#10 的配置。 这些是有效的目标状态。 
5. 对于每个有效目标，计算将原始字符串转换为该目标的交换成本。 具有固定计数的两个二进制字符串之间的最小交换次数可减少到原始位置和目标位置中零之间不匹配位置数量的一半。 
6. 取所有有效目标中的最小值并输出。 

关键步骤是交换两个位置同时纠正两个不匹配，因此两个二进制配置之间的交换距离恰好是零位置的汉明不匹配除以二。 

### 为什么它有效

 该算法隐式搜索字符串的所有可行的最终排列。 条件#01 = #10 将这些排列过滤为所有零一对的反转贡献均匀分布的排列。 由于交换保留了字符的多重集并且任何排列都是可到达的，因此最小化交换减少为寻找汉明距离中最接近的有效排列。 正确性来自于这样一个事实：排列之间的交换距离恰好是零位置集合中移位元素的数量除以二，因此最小化交换相当于最小化与有效平衡配置的位置不一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_inversions(s):
    # returns (#01, #10)
    ones = 0
    zeros_after = s.count('0')
    inv01 = 0
    inv10 = 0
    
    for c in s:
        if c == '0':
            zeros_after -= 1
        else:
            inv01 += zeros_after
    # compute 10 similarly
    zeros_before = 0
    ones_after = s.count('1')
    for c in s:
        if c == '1':
            ones_after -= 1
        else:
            inv10 += ones_after
    return inv01, inv10

def swaps_needed(a, b):
    # both strings same multiset
    mismatch = 0
    for x, y in zip(a, b):
        if x != y:
            mismatch += 1
    return mismatch // 2

def solve():
    s = input().strip()
    n = len(s)
    Z = s.count('0')

    # try all placements of zeros (n small)
    import itertools

    idx = list(range(n))
    best = 10**9

    for zeros_pos in itertools.combinations(idx, Z):
        t = ['1'] * n
        for i in zeros_pos:
            t[i] = '0'
        t = ''.join(t)

        inv01, inv10 = count_inversions(t)
        if inv01 == inv10:
            best = min(best, swaps_needed(s, t))

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案构造每个可能的零位置，构建相应的字符串，并检查它是否满足平衡条件。 反转计数是在每个候选者的线性时间内直接完成的。 交换成本是通过比较原始字符串和候选字符串之间的不匹配位置来计算的，利用每个交换修复两个不匹配位置的事实。 

一个微妙的点是我们从不显式生成交换序列。 我们只计算将一种二进制排列转换为另一种二进制排列所需的最小交换次数，这纯粹是不匹配索引的函数。 

## 工作示例

 考虑一个简短的示例字符串`101`。 

我们有 Z = 1，因此我们选择一个位置为零。 

| 零位| 目标字符串 | #01 | ＃10 | 平衡 | 与原来的互换|
 | --- | --- | --- | --- | --- | --- |
 | 0 | 011| 2 | 0 | 没有 | - |
 | 1 | 101 | 101 1 | 1 | 是的 | 0 |
 | 2 | 110 | 110 0 | 2 | 没有 | - |

 唯一平衡的配置是原始字符串本身，因此答案为零。 这表明该算法在考虑交换成本之前正确过滤了无效目标。 

现在考虑`1100`。 

Z = 2，因此我们选择任意两个位置作为零。 

一种有效的平衡安排是`1001`。 

| 零位 | 目标| #01 | ＃10 | 平衡 | 掉期 |
 | --- | --- | --- | --- | --- | --- |
 | (1,2) | 1001 | 1001 2 | 2 | 是的 | 1 |
 | (0,3) | 0110| 1 | 1 | 是的 | 1 |

 原来的`1100`是与任一平衡配置的一次交换，确认交换成本仅取决于位置不匹配，而不直接取决于反转结构。

 ## 边缘情况

 像这样的案例`000...0111...1`很有趣，因为所有零都在 1 之前，产生最大的不平衡。 该算法仅接受零交叉以均衡反转方向的重新排列，并且交换距离恰好对应于必须跨过多少个零。 

为了`n = 3`， 输入`110`，唯一平衡的配置是`101`或者`011`。 该算法正确地评估两者并选择最小交换距离 1，因为只需一次相邻交换即可将 0 移动到中心位置。 

完全统一的字符串，例如`0000`根本没有有效的反转不平衡。 每个候选排列都会产生零个混合对，因此所有的混合对都是平凡平衡的，并且算法返回零交换，与基于不匹配的距离度量一致。
