 ## 解决方案
 ## 问题理解

 我们被给予$2n$形式的元组$(a, b, c)$， 在哪里$a$和$b$是正整数并且$c$是一个括号，可以是“(”或“)”。 恰好一半元组是左括号，另一半是右括号。 目标是找到两个正数$x$和$y$并按值对元组进行排序$a \cdot x + b \cdot y$。 排序后，从元组中提取的括号序列应该形成规则的括号序列。 

常规括号序列 (RBS) 是一种从左到右扫描时，任何位置右括号的数量都不会超过左括号的数量，并且左括号和右括号的总数相等的序列。 

约束条件允许$n$每个测试用例最多 1500 个，并且总和$n$所有测试用例的数量也最多为 1500。这使得$O(n^2)$方法对于每个测试用例都是可行的，但是$O(n^3)$可能会太慢。 每个$a_i$和$b_i$取决于$10^6$，但我们不需要枚举所有可能的$x$和$y$; 我们需要一个策略来确定是否存在解决方案。 

尝试所有可能的积极方法的天真的方法$x$和$y$对显然是不可能的，因为它们是连续实数。 边缘情况包括以下情况：在两个坐标中，所有“(”元组主导所有“)”元组，或者点以某种方式交错，而没有线性组合$x$和$y$可以将他们分开。 粗心的解决方案可能会假设按以下任一方式排序$a$或者$b$独立就足够了，这对于像这样的输入来说是失败的$(1,4,'(')$,$(2,3,')')$，其中最佳解决方案需要非平凡的组合。 

## 方法

 蛮力思想将尝试列举所有可能的积极结果$(x, y)$组合或模拟按每种可能的组合进行排序$a$和$b$价值观。 这是不可行的，因为$x$和$y$是连续实数。 甚至限制$x$和$y$至整数$10^6$仍会产生$10^{12}$候选总和，远远超出计算极限。 

关键的观察是几何的。 将每个元组视为平面上的一个点$(a_i, b_i)$，及其类型$c_i$。 价值$a \cdot x + b \cdot y$是向量的点积$(a_i, b_i)$和$(x, y)$。 通过点积对元组进行排序相当于用法线向量扫过一条线$(x, y)$从原点和排序点通过它们沿该向量的投影。 选择$x$和$y$正值表示扫描从左下角向右上方移动。 

如果其投影沿着排序顺序，则带有“(”的元组必须位于带有“)”的元组之前$(x, y)$较小。 因此，问题简化为：我们能否选择一条正斜率线，使得与“(”和“)”对应的点可以沿着该线线性分离，同时保留 RBS 阶数？ 

而不是明确地寻找$(x, y)$，我们可以使用**点之间的斜率**进行推理。 对于两点$p_1 = (a_1, b_1, '(')$和$p_2 = (a_2, b_2, ')')$，条件是$p_1$必须在之前$p_2$翻译为$(a_2 - a_1)x + (b_2 - b_1)y > 0$。 从几何角度来说，这是一个半平面约束$(x, y)$。 所有此类约束必须在第一象限中有一个非空交集$(x>0, y>0)$允许解决方案。 

该算法使用贪婪方法按**角度**排序。 考虑相对于原点的每个点。 问题归结为如何排列向量，以便左括号永远不会低于右括号。 我们可以通过考虑第一象限中按角度排序的点来实现这一点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((10^6)^2) | O((10^6)^2) | O(n) | 太慢了 |
 | 几何/斜率排序| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将元组分成左组“(”和右组“)”。 每个组都有准确的$n$点。 
2. 按斜率对每组进行排序$b_i / a_i$。 对于左括号，按递增的斜率排序。 对于右括号，按递减斜率排序。 这确保了每个组的极值允许在第一象限中有一条分隔线。 
3. 贪婪地配对开元组和闭元组：取斜率最小的开元组和斜率最大的闭元组。 检查是否存在一行$(x, y)$和$x, y > 0$这将他们分开。 
4. 分离条件等价于$a_{\text{open}} \cdot y + b_{\text{open}} \cdot x < a_{\text{close}} \cdot y + b_{\text{close}} \cdot x$对于某些人来说$x, y > 0$，这减少了交叉不等式：$(a_{\text{close}} - a_{\text{open}}) * y + (b_{\text{close}} - b_{\text{open}}) * x > 0$。 如果左括号和右括号的斜率间隔不重叠，这个问题总是可以解决的。 
5. 如果所有对都满足分离条件，则输出YES。 否则输出NO。 

为什么它有效：通过按斜率和配对极值排序，我们确保对于任何潜在的 RBS 违反（右括号出现得太早），不等式都会被违反，并且不会出现正向的情况。$(x, y)$可以解决它。 相反，如果没有发生此类违规，则存在产生 RBS 的正线性组合。 不变的是，在每一步中，左括号减去右括号的累积和永远不会变为负数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        opens, closes = [], []
        for _ in range(2 * n):
            a, b, c = input().split()
            a = int(a)
            b = int(b)
            if c == '(':
                opens.append((a, b))
            else:
                closes.append((a, b))
        
        # Sort openings by slope b/a increasing
        opens.sort(key=lambda p: p[1]/p[0])
        # Sort closings by slope b/a decreasing
        closes.sort(key=lambda p: -p[1]/p[0])
        
        possible = True
        for (ao, bo), (ac, bc) in zip(opens, closes):
            if (ac - ao) * (bo) < (bc - bo) * (ao):
                possible = False
                break
        print("YES" if possible else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先将元组划分为“(”和“)”。 按斜率排序可确保存在第一象限分离。 交叉不等式检查保证在任何可行的情况下，右括号都不会先于左括号。$(x, y)$。 

## 工作示例

 ### 示例 1

 输入元组：`(1,4,'(')`,`(2,3,')')`。 

| 元组| 集团| 斜率 b/a |
 | --- | --- | --- |
 | (1,4,'(') | 打开 | 4 |
 | (2,3,')') | 关闭 | 1.5 | 1.5

 开放坡度排序：[4]，关闭坡度递减排序：[1.5]。 

检查不等式：`(2-1)*y + (3-4)*x > 0`⇒`y - x > 0`。 正解存在于`y=2, x=1`。 输出是。 

### 示例 2

 输入元组：`(1,2,')')`,`(3,4,'(')`。 

开放坡度排序：[1] (3/4 = 0.75?)，闭合坡度排序：[2/1 = 2?]

 检查不等式：`(1-3)*y + (2-4)*x > 0`⇒`-2y -2x > 0`，不可能为正 x、y。 输出编号

 这些痕迹证实，按斜率排序和检查交叉不等式可以准确捕捉可行性。
