[CF 474B - 蠕虫](https://codeforces.com/problemset/problem/474/B)

 **评分：** 1200
 **标签：** 二分查找，实现
 **求解时间：** 1m 36s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到了几堆按顺序排列的蠕虫。 所有堆中的蠕虫都被连续编号。 

如果桩尺寸为：```
2 7 3
```那么第一堆包含编号为 1 到 2 的蠕虫，第二堆包含编号为 3 到 9 的蠕虫，第三堆包含编号为 10 到 12 的蠕虫。 

对于每个查询，我们都会获得一个蠕虫标签，并且必须确定哪个堆包含该蠕虫。 

关键的挑战是堆的数量和查询的数量都可以大到$10^5$。 扫描每个查询的所有堆的解决方案的执行次数可达$10^{10}$最坏情况下的操作，远远超出了1秒的时间限制。 我们需要更接近的东西$O(n \log n)$或者$O((n+m)\log n)$。 

一个微妙的细节是，蠕虫标签通常恰好位于堆边界上。 考虑：```
2
2 3
2
2 3
```桩覆盖范围：```
Pile 1: [1, 2]
Pile 2: [3, 5]
```正确答案是：```
1
2
```如果粗心的二分搜索实现搜索第一个前缀和严格大于查询而不是大于或等于查询，则它可能会错误地将蠕虫 2 放入堆 2 中。 

另一个常见的错误来源是一堆蠕虫中的第一个。```
3
2 2 2
1
3
```范围是：```
Pile 1: [1, 2]
Pile 2: [3, 4]
Pile 3: [5, 6]
```蠕虫 3 属于桩 2。范围构造中的任何差一错误都会产生错误的结果。 

## 方法

 一种简单的解决方案是重建每个桩所覆盖的范围，然后对于每个查询，一个接一个地扫描桩，直到找到正确的范围。 

例如，构建后：```
Pile 1: [1, 2]
Pile 2: [3, 9]
Pile 3: [10, 12]
...
```我们可以按顺序检查每个间隔。 这是有效的，因为每条蠕虫都属于一堆。 问题是性能。 和$10^5$桩和$10^5$查询，我们可以执行$10^{10}$间隔检查。 

编号结构为我们提供了更好的选择。 如果我们计算桩大小的前缀和，我们得到：```
a = [2, 7, 3, 4, 9]

prefix = [2, 9, 12, 16, 25]
```每个前缀和代表该堆中包含的最大蠕虫标签。 

蠕虫属于第一堆，其结束标签至少是蠕虫编号。 例如，蠕虫 11 属于第 3 堆，因为：```
2  < 11
9  < 11
12 >= 11
```前缀和数组按升序排序，这使得二分搜索适用。 我们不是扫描所有堆，而是找到第一个前缀总和大于或等于查询的$O(\log n)$时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n + m log n) | O(n + m log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取堆的数量及其大小。 
2. 构建一个前缀和数组，其中`prefix[i]`等于堆中蠕虫的总数`1..i+1`。 

这会将堆大小转换为堆结束位置。 
3.对于每个查询蠕虫标签`q`，对前缀和数组执行二分查找。 
4.找到第一个前缀和大于等于的位置`q`。 

这标识了其结束标签到达或通过所查询的蠕虫的第一堆。 
5. 使用从 1 开始的编号输出堆索引。 

### 为什么它有效

 前缀和数组将所有蠕虫标签划分为连续的范围。 

如果：```
prefix[i-1] < q <= prefix[i]
```然后所有标签直到`prefix[i-1]`属于较早的桩，而桩`i+1`包含从以下位置开始的标签`prefix[i-1] + 1`并结束于`prefix[i]`。 找到第一个至少为的前缀和`q`因此唯一地确定了正确的桩。 二分搜索只是有效地定位这个边界。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    piles = list(map(int, input().split()))

    prefix = []
    total = 0

    for x in piles:
        total += x
        prefix.append(total)

    m = int(input())
    queries = list(map(int, input().split()))

    ans = []

    for q in queries:
        pile = bisect_left(prefix, q) + 1
        ans.append(str(pile))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```代码的第一部分构造前缀和数组。 每个元素存储属于该堆的最大蠕虫标签。 

关键的操作是：```
bisect_left(prefix, q)
```

`bisect_left`返回值大于或等于的第一个位置`q`。 这符合该问题所需的数学条件。 

这`+1`将从零开始的数组位置转换为语句所需的从一开始的堆编号。 

使用 Python 的内置二分搜索可以避免许多边界错误。 特别是，它正确处理等于桩端点的查询，这是此问题中最常见的逐一陷阱。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m log n) | O(n + m log n) | 构建前缀和需要 O(n)，每个查询都使用二分搜索，时间复杂度为 O(log n) |
 | 空间| O(n) | 前缀和数组每堆存储一个值 |

 和$n,m \le 10^5$，该解决方案的性能大致为$10^5$前缀和运算和$10^5$二分搜索。 这很容易符合时间限制，并存储$10^5$整数完全在内存限制之内。

 ## 边缘情况

 考虑一个完全等于堆端点的查询。```
2
2 3
1
2
```前缀和：```
[2, 5]
```二分查找`2`返回位置`0`因为`prefix[0] = 2`。 答案是一堆`1`，这是正确的。 搜索严格大于查询的第一个前缀总和将错误地返回一堆`2`。 

考虑一个新蠕虫中的第一个查询。```
2
2 3
1
3
```前缀和：```
[2, 5]
```二分查找`3`返回位置`1`因为`2 < 3 <= 5`。 答案变成一堆`2`。 这证实了堆的开头被正确处理，而无需显式存储间隔开头。 

考虑尽可能最小的输入。```
1
1
1
1
```前缀和：```
[1]
```二分查找`1`返回位置`0`, 给予堆`1`。 即使仅存在单个堆和单个蠕虫，该算法也能工作。 

考虑整个集合中的最后一个蠕虫。```
3
2 2 2
1
6
```前缀和：```
[2, 4, 6]
```二分查找至少找到第一个前缀和`6`，这是最后一个元素。 答案是一堆`3`，确认编号方案的上限处理正确。
