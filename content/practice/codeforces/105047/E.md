 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们重复应用单个破坏性操作：选择两个不同的位置，并将第一个位置的当前值与第二个位置的值进行异或替换。 第二个位置永远不会被修改。 

任务是使用一系列此类操作将数组转换为非递减序列，并输出任何有效的操作序列。 我们没有被要求保留原始值，只是为了达到就地排序的顺序。 

关键的限制是我们没有交换或分配，只能通过异或将信息从一个位置注入到另一个位置。 这使得问题感觉像是在一个非常不寻常的原语下排序。 

数组长度最多为1000，值最多为20位整数。 操作限制足够大，二次或接近二次的行为仍然可以接受，但评分系统奖励短序列，特别是在 2500 次操作下。 

幼稚的解释会尝试直接模拟比较和交换，但这会立即失败，因为我们无法在没有大量操作的情况下以受控方式直接比较和有条件地重新排序。 更微妙的问题是，每次操作都会破坏目标位置的信息，因此粗心的序列很容易不可逆地破坏值。 

第二个隐藏的边缘情况是假设 XOR 的行为类似于算术赋值。 例如，尝试“移动”一个值而不仔细恢复中间体会导致静默损坏：

 输入：```
3
5 1 2
```如果我们尝试执行一种天真的“类似交换”序列，但忘记了恢复步骤，则一个位置最终将被永久更改，即使索引正确，排序也会失败。 

## 方法

 蛮力的想法是直接模拟排序。 我们按值计算索引的排序顺序，并尝试使用位置之间的交换将每个元素放置到正确的位置。 由于我们没有掉期，我们模拟仓位之间的掉期`i`和`j`使用异或：

 我们可以使用三个操作交换两个值：

 首先，使`i := i XOR j`， 然后`j := j XOR i`， 然后`i := i XOR j`。 经过这些步骤后，值`i`和`j`被交换。 

这将问题简化为通过任意交换进行排序，这意味着我们可以将索引的排列分解为循环并独立地修复每个循环。 每个周期的长度`k`需要`k - 1`互换。 

这种方法是正确的，因为交换让我们实现任何排列，而排序只是应用对值进行排序的排列。 

蛮力思维的失败点在于，如果没有结构，单独实现交换仍然太昂贵，并且天真的重复交换或冒泡排序会导致太多操作。 

循环分解观察将交换次数减少到最多`n - number_of_cycles`，这最多是`n - 1`，使其在互换中呈线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重复相邻交换| O(n² 交换) → O(3n² 操作) | O(1) | O(1) | 太慢了|
 | 循环分解+异或交换| O(n log n) 排序 + O(n) 交换 | O(n) | 已接受 |

 ## 算法演练

 我们将问题视为排序索引，同时使用异或交换操作沿位置携带值。 

1. 根据索引值的升序计算索引的排序顺序。 
2. 构建数组`pos`在哪里`pos[i]`指示元素当前所在的位置`i`应该按排序排列。 这定义了索引的排列。 
3. 将此排列分解为不相交的循环。 每个循环代表一个闭合的元素链，这些元素必须在它们之间旋转。 
4.对于每个周期长度`k`，选择一个元素作为枢轴。 然后使用 XOR 交换迭代地将主元与循环中的每个其他元素交换。 每个交换都是使用三个允许的操作来实现的：

 第一`x := x XOR y`， 然后`y := y XOR x`， 然后`x := x XOR y`。 

这会逐渐将每个元素移动到正确的位置，而不会影响已经固定的周期。 
5. 将每个原始 XOR 运算记录为输出。 

这样做的原因是每个循环都是独立解决的，修复一个循环后，其中的所有元素都被正确放置并且再也不会被触及。 

### 为什么它有效

 每次交换都是一次精确的价值交换，因此它保留了跨头寸的多重价值集。 循环分解保证沿循环边缘应用交换最终将每个索引映射到其排序的目的地。 由于每个循环都是不相交的，因此没有操作会干扰已经固定的元素。 不变的是，完成一个循环后，该循环中的所有位置都包含在目标排列中分配给它们的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def xor_swap_ops(a, b, ops):
    # performs swap between positions a and b using XOR operations
    # a != b
    ops.append((a, b))
    ops.append((b, a))
    ops.append((a, b))

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))

    # sorted order of indices
    order = sorted(range(n), key=lambda i: arr[i])

    # permutation: i -> where i goes in sorted array
    pos = [0] * n
    for new_idx, old_idx in enumerate(order):
        pos[old_idx] = new_idx

    vis = [False] * n
    ops = []

    for i in range(n):
        if vis[i] or pos[i] == i:
            vis[i] = True
            continue

        cycle = []
        cur = i
        while not vis[cur]:
            vis[cur] = True
            cycle.append(cur)
            cur = pos[cur]

        # fix cycle
        for j in range(1, len(cycle)):
            a = cycle[0]
            b = cycle[j]

            # XOR swap a and b via 3 operations
            ops.append((a + 1, b + 1))
            ops.append((a + 1, b + 1))
            ops.append((a + 1, b + 1))

    print(len(ops))
    for x, y in ops:
        print(x, y)

if __name__ == "__main__":
    solve()
```该实现首先计算排序顺序中每个元素的目标位置。 然后它将排列分解为循环，以便每个元素确切地知道它必须结束的位置。 

对于每个循环，它重复地在循环代表和循环中的每个其他元素之间应用交换。 每个交换都扩展为三个 XOR 操作，因为这是唯一允许的原语。 

一个微妙的点是索引必须小心处理：输出是从 1 开始的，而内部数组是从 0 开始的。 另一个微妙的问题是确保我们在进入循环时立即标记已访问的节点以避免双重处理。 

## 工作示例

 ### 示例 1

 输入：```
4
3 2 1 0
```排序顺序是索引`[3, 2, 1, 0]`。 

排列周期：`(0 3)(1 2)`。 

| 步骤| 循环 | 运营| 阵列效果|
 | --- | --- | --- | --- |
 | 1 | (0,3) | 交换(0,3) | 0 和 3 交换 |
 | 2 | (1,2) | 交换(1,2) | 1 和 2 交换 |

 解决两个循环后，数组变为`[0,1,2,3]`。 

这证实了不相交的循环是独立的并且可以单独处理。 

### 示例 2

 输入：```
5
2 4 3 1 0
```排序索引：`[4, 3, 0, 2, 1]`。 

周期：`(0 2 3 1 4)`。 

| 步骤| 枢轴| 交换目标| 效果|
 | --- | --- | --- | --- |
 | 1 | 0 | 2 | 部分旋转|
 | 2 | 0 | 3 | 继续循环修复|
 | 3 | 0 | 1 | 继续 |
 | 4 | 0 | 4 | 完成周期 |

 最终数组变成`[0,1,2,3,4]`。 

这表明单个长循环可以通过反复锚定在一个枢轴上来解决。

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 对于已经排序的数组，每个元素都已经处于长度为一的正确循环中，因此不会生成任何操作。 该算法立即将每个索引标记为已访问并跳过交换生成。 

对于具有重复值的数组，排序仍然定义有效的索引排列。 由于交换是在位置上进行的，因此重复不会破坏正确性，并且循环分解仍然会产生有效的独立循环。 

对于单个长周期，算法重复固定相对于第一个主元的元素。 即使值不断移动，枢轴最终到达其最终位置的不变量仍然保持不变，并且循环在 k − 1 次交换后结束。
