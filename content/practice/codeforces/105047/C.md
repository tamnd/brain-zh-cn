 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的轴对齐矩形交互，其边长是两个未知整数$a$和$b$，都最多 100。我们无法直接看到这些值。 相反，我们可以通过提出另一个有边的矩形来探测该矩形$c$和$d$，法官告诉我们这是否$c \times d$矩形可以完全放置在隐藏的内部$a \times b$长方形。 

响应是确定性的：当两者都满足时，响应就是肯定的$c \le a$和$d \le b$，或者当方向交换时$c \le b$和$d \le a$。 我们最多允许进行 20 个这样的查询，每个查询最多使用 200 个维度，并且我们最终必须以任意顺序输出两条边的长度。 

关键的困难在于我们不知道哪一边对应哪个维度，并且我们只能得到一个二元可行性预言机。 这使得该问题成为两个变量中单调谓词的重构任务。 

一种简单的方法是尝试测试所有对$(a, b)$在允许的范围内并检查与答案的一致性，但这已经暗示了交互式设置中的低效率，其中每个查询的成本都很高。 更重要的是，幼稚的推理存在歧义的风险，因为谓词是对称的：交换两边会产生相同的答案。 

主要的微妙边缘情况是对称性。 例如，如果隐藏矩形是$6 \times 4$，然后查询$4 \times 6$和$6 \times 4$两者都返回成功，因此任何重建策略都必须将方向视为无关紧要，并且仅恢复多重集$\{a, b\}$。 

## 方法

 交互作用定义了一个单调条件：如果一个矩形$c \times d$适合，然后任意$c' \le c$,$d' \le d$也适合。 这表明我们可以使用逐渐接近真实维度的查询来恢复边界信息。 

暴力策略将尝试测试所有对$(c, d)$在范围内$1 \le c, d \le 200$。 对于每一对，我们都会询问法官是否适合并收集所有有效的候选人。 然而，这并没有利用结构。 在最坏的情况下，需要多达 40,000 次查询，这远远超出了 20 次的限制。即使我们限制自己在逻辑上检查每个候选对的可行性，我们仍然需要太多的查询来消除正确矩形的歧义。 

关键的观察是我们可以将两个维度解耦。 假设我们可以确定仍然适合固定探头的一个方向的最大可能边长。 如果我们修复一侧，说$c = 200$，并进行二分查找$d$，我们可以找到最大的$d$这样$200 \times d$适合。 该值必须是$\min(a, b)$或者至少受到较小一侧的限制。 一旦我们确定了一侧的长度，我们就可以类似地推导出另一侧的长度。 

更清晰的观点是，我们只需要将两个维度恢复为无序对。 我们可以首先确定适合正方形的最大边长，这给出$\min(a, b)$。 然后我们使用该值修复探针并搜索最大兼容的第二面，这揭示了$\max(a, b)$。 

这将问题从二维搜索减少为两个一维单调搜索，每个搜索都可以通过最多 8 个查询中的二分搜索来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(200^2)$查询 |$O(1)$| 太慢了|
 | 最佳|$O(\log 200)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 我们依赖这样一个事实：可行性在两个维度上都是单调的，并且在方向上是对称的。 

1. 首先，我们通过探测正方形来确定矩形的较小边$k \times k$。 我们二分查找最大的$k$使得答案是肯定的。 这是有效的，因为任何适合的正方形都必须满足$k \le \min(a, b)$，并且该属性是单调的$k$。 
2. 令该值为$s = \min(a, b)$。 我们现在知道了一个维度，但我们仍然需要更大的一面。 
3. 为了找到第二条边，我们使用以下方法固定探针$s$。 我们现在最大的二分查找$x$这样$s \times x$适合。 如果$s$匹配较小的一侧，然后$x$将扩展到$\max(a, b)$。 如果我们不小心先匹配了较大的一边，对称性确保相同的推理仍然成立。 
4.找到后$x$，我们输出$(s, x)$。 

关键的推理步骤是，一旦一侧固定在较小的维度上，可行性谓词就会崩溃为另一个变量中的一维单调函数。 

### 为什么它有效

 正确性依赖于两个单调性。 首先，如果一个正方形的大小$k$适合，则所有较小的正方形都适合，这使得二分搜索有效。 其次，一旦我们将一侧固定为不超过两侧的值$a$和$b$，另一个维度的可行性仍然单调且与方向无关。 这保证了二分搜索毫无歧义地隔离了真实的边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(c, d):
    print("?", c, d)
    sys.stdout.flush()
    res = input().strip()
    if res == "-1":
        sys.exit(0)
    return int(res)

def solve():
    lo, hi = 1, 200
    best = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if ask(mid, mid):
            best = mid
            lo = mid + 1
        else:
            hi = mid - 1

    s = best

    lo, hi = 1, 200
    best2 = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if ask(s, mid):
            best2 = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print("!", s, best2)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该解决方案围绕单个查询助手构建，该查询助手强制刷新并处理终止条件。 第一个二分搜索仅探测正方形，这完全避免了处理方向。 第二次搜索依赖于包含的单调性，固定一侧并扩展另一侧。 

一个微妙的实现细节是，即使在成功查询之后，我们也总是更新最已知的值。 即使二分查找在边界附近超出，这也确保了正确性。 另一个重要的细节是 -1 时立即终止，因为继续将被判断为无效交互。

 ## 边缘情况

 一个关键的边缘情况是当一侧为 1 时。在这种情况下，每个大于 1 的平方都会立即失败，因此第一个二分搜索会快速崩溃为 1。然后第二阶段直接恢复另一侧而不会产生歧义，因为形式的查询$1 \times x$其行为与线性阈值测试完全相同。 

另一个边缘情况是当$a = b$。 这里每个有效的方格直到$a$第一阶段成功，因此算法干净地返回$s = a$。 然后，第二阶段所有人都会看到相同的行为$x \le a$，生产$x = a$以及。 对称性不会引入任何分支不确定性，因为两个维度一致，因此方向无关紧要。
