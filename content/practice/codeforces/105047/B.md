 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 目标是提高每个元素，使其至少达到阈值`k`。 修改数组的唯一方法是通过应用于所选索引的非常具体的操作`i`。 

当我们选择一个索引时`i`，该元素增加`m`，而其他所有元素都减少`r`。 该操作是全球性的，因为即使我们“瞄准”一个位置，所有其他位置都会受到负面影响。 我们可以以任何顺序对任何索引重复应用此操作，并且我们希望最小化所需的总操作次数，以便所有数组值最终至少`k`。 

关键的难点在于，每一项操作都对一个职位有帮助，但对其他所有职位都有损害。 这会在决策之间产生耦合：改进一个元素可能会暂时使其他元素变得更糟，从而需要在其他地方进行更多的未来操作。 

这些限制表明对操作进行二次或更差的模拟是不可能的。 跨测试用例的所有数组的总大小很小，但值可以很大，并且操作数量原则上是无限制的。 任何尝试逐步模拟操作或搜索序列的解决方案都会太慢。 

当某些元素已经接近时，就会出现一个微妙的问题`k`但被推到下面`k`通过针对其他指数的操作。 简单地重复修复最小元素而不考虑全局副作用的天真贪婪方法可能会失败。 

例如，如果一个元素刚好高于`k`，但许多操作是在其他地方执行的，它可能会降至阈值以下，从而强制执行更平衡的策略本可以避免的额外操作。 

## 方法

 蛮力视角是直接模拟该过程。 在每一步中，我们都会考虑对每个索引应用操作并计算结果数组，然后递归或迭代地继续，直到所有元素都达到`k`。 这是正确的，因为它探索了所有有效的操作序列，但分支因子是`n`每一步的深度也可能很大，因此状态数量呈指数级爆炸。 

关键的观察是，我们实际上并不关心顺序操作的身份，只关心每个索引被选择的次数。 让`x_i`是我们对索引应用操作的次数`i`。 然后我们可以纯粹用这些计数来表达每个元素的最终值。 

每次我们申请操作`i`， 元素`i`收益`m`所有其他元素都会丢失`r`。 所以对于固定索引`i`，其最终值为：```
a[i] + x_i * m - r * sum_{j != i} x_j
```让`S = sum x_j`。 然后我们重写：```
final[i] = a[i] + x_i * m - r * (S - x_i)
         = a[i] + x_i * (m + r) - r * S
```现在整个系统由`S`和每个`x_i`。 条件`final[i] >= k`变成：```
a[i] + x_i * (m + r) >= k + r * S
```重新排列：```
x_i >= (k + r*S - a[i]) / (m + r)
```这显示了循环依赖：`x_i`取决于`S`， 但`S`是所有的总和`x_i`。 

重要的结构简化是对于固定的`S`， 每个`x_i`独立确定为满足不等式的最小值。 这让我们可以计算所需的总和`S' = sum x_i`候选人暗示`S`。 如果`S' > S`，我们的业务分配不足； 如果`S' <= S`，配置可行。 

然后我们寻找最小的`S`稳定了这种一致性条件。

 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(n) | 太慢了|
 | S 上的定点 | O(n log A) | O(n log A) | O(n) | 已接受 |

 ## 算法演练

 我们将问题转化为寻找一致的操作总数`S`。 

1. 从初步猜测开始`S`， 通常`0`。 这表示假设全球经济衰退尚未产生交叉影响。 
2. 对于每个索引`i`，计算必须选择多少次才能至少达到`k`鉴于目前的假设`S`。 需求来自解决：```
a[i] + x_i*(m+r) >= k + r*S
```所以：```
x_i = max(0, ceil((k + r*S - a[i]) / (m + r)))
```我们将 max 设为零，因为我们从不需要负运算。 
3. 将所有计算结果相加`x_i`值以获得新的总计`S_new`。 
4. 如果`S_new`等于`S`，我们已经达到了稳定的配置，这`S`是可行的。 
5. 否则更换`S`和`S_new`并重复该过程。 

迭代背后的关键原因是增加`S`提高了所需的门槛`k + r*S`，这反过来可能会增加个人要求。 然而，有一次`S`足够大，重新计算将不再改变它。 

### 为什么它有效

 系统定义了一个单调自洽条件：递增`S`只能增加每个的右侧要求`x_i`，永远不要减少它。 因此映射从`S`到`S_new`是单调非减的。 开始于`0`，重复应用收敛到最小不动点，该点恰好对应于可行的操作分配。 任何较小的值`S`会违反至少一个约束，而任何更大的值都意味着不必要的额外操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k, m, r = map(int, input().split())
        a = list(map(int, input().split()))

        denom = m + r

        S = 0
        while True:
            newS = 0
            for x in a:
                need = k + r * S - x
                if need > 0:
                    newS += (need + denom - 1) // denom
            if newS == S:
                break
            S = newS

        print(S)

if __name__ == "__main__":
    solve()
```实现的核心是定点迭代`S`。 分母`m + r`是预先计算的，因为它被每个元素重用。 

表达式`need = k + r*S - x`编码在当前全局惩罚假设下元素距所需阈值的距离。 如果`need`是正数，我们计算需要多少完整操作来补偿赤字和持续的全球惩罚。 

循环收敛，因为每次迭代要么稳定，要么严格增加`S`，并且该值受到将最小元素从最坏可能状态提升所需的操作数的限制。 

## 工作示例

 考虑一个简单的情况：

 输入：```
n = 2, k = 5, m = 4, r = 1
a = [1, 3]
```我们追踪`S`:

 | 迭代| S | x1 的要求 | x2 的要求 | 新S |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 天花板((5-1)/5)=1 | 天花板((5-3)/5)=1 | 2 |
 | 1 | 2 | 天花板((5+2-1)/5)=2 | 天花板((5+2-3)/5)=1 | 3 |
 | 2 | 3 | 天花板((5+3-1)/5)=2 | 天花板((5+3-3)/5)=1 | 3 |

 我们稳定在`S = 3`。 

这表明全球惩罚如何迫使额外的行动超出幼稚的独立要求。 

现在考虑：

 输入：```
n = 3, k = 4, m = 10, r = 2
a = [0, 0, 0]
```| 迭代| S | 每个元素 x | 新S |
 | --- | --- | --- | --- |
 | 0 | 0 | 1, 1, 1 | 3 |
 | 1 | 3 | 2, 2, 2 | 6 |
 | 2 | 6 | 2, 2, 2 | 6 |

 我们汇聚于`S = 6`，表明对称性导致均匀分配。

 ## 边缘情况

 关键的边缘情况是所有元素都已满足阈值。 在那种情况下，`k - a[i] <= 0`为所有人`i`，所以计算出的`need`总是非正值`S = 0`。 该算法立即产生`newS = 0`，因此它收敛而不进入任何增长循环。 

另一个重要的情况是当一个元素明显小于其他元素时。 例如，如果`a = [1, 100, 100]`具有适度的`k`，第一个元素主导计算`S`。 在早期迭代中，大元素仍然需要零操作，但是一旦`S`增加后，他们开始“感受到”全局惩罚，并且可能需要自己进行额外的操作。 定点迭代正确地传播这种依赖性直到稳定。 

第三种情况是当`m`仅略大于`r*(n-1)`。 这是最糟糕的情况，因为与全球损失相比，每次行动只能带来很小的净收益。 该算法仍然收敛，因为分母`m + r`确保每笔操作都有严格的正向自身收益，防止振荡或发散。
