 ## 解决方案
 ## 问题理解

 我们给出从 1 到 n 的数字排列，我们将其“成本”定义为元素相对其自然位置的总位移，特别是 |p[i] − i| 的所有位置 i 的总和。 直观上，每个元素都会影响它远离其身份位置的距离。 

任务不仅是计算或优化这个值，而是枚举具有固定成本 b 的排列，并在其中选择按字典顺序排列的第 k 个排列。 

字典顺序以排列的标准方式定义：从第一个位置开始比较，第一个不同的值决定顺序。 

因此，输入对排列上的约束系统进行编码，并且输出是满足全局成本约束和所有有效排列中的等级约束的单个排列。 

从复杂性角度来看，社论叙述中隐含的限制非常大。 建议的动态规划已经达到 O(n^4)，并且对前缀的枚举使其进一步倍增。 这立即排除了任何尝试显式生成或排序所有有效排列的方法，因为排列空间是 n 的阶乘。 该解决方案必须依赖于同时聚合许多排列的计数结构。 

平衡与结构的相互作用产生了一个微妙的边缘情况。 例如，考虑像 n = 3 这样的小排列。如果我们尝试 p = [2, 3, 1]，平衡是 |2−1| + |3−2| + |1−3| = 1 + 1 + 2 = 4。另一种排列如 [3, 1, 2] 也会产生不同的平衡。 一个天真的想法可能会假设平衡的行为与字典顺序是单调的，但这是错误的。 字典顺序和位移成本是独立的，因此不计数的贪婪选择会导致第 k 个答案错误。 

当多个排列具有相同的平衡，但元素向左或向右移动的距离在结构上不同时，就会出现另一种失败情况。 在构造前缀时，尤其是在尝试继续部分排列时，仅跟踪总位移的朴素 DP 会丢失有关可行性的信息。 

## 方法

 蛮力的观点很简单。 我们可以生成 1 到 n 的所有排列，计算它们的平衡，过滤那些值恰好为 b 的排列，按字典顺序对它们进行排序，然后返回第 k 个排列。 这是正确的，因为它直接遵循问题的定义。 然而，它需要枚举n！ 排列，每次评估的成本为 O(n)，时间为 O(n!·n)，即使 n 约为 12，这也是不可行的。 

关键的观察是，如果我们将排列构造重新解释为配对位置和值，则平衡函数会自然分解。 我们不直接考虑 p[i]，而是考虑一条线上的匹配索引：一侧代表位置，另一侧代表值，两者都已排序。 每个作业对应于这两个集合的配对。 

这种配对观点允许我们将排列重新解释为一系列决策，其中每个新元素要么与先前不匹配的元素配对，要么推迟配对。 该结构类似于非交叉或部分有序的匹配，可以使用前缀和开放不匹配元素数量的动态编程来捕获。 

第一个 DP 忽略成本并计算所有有效配对。 令 DP[i][j] 表示处理前 i 个元素同时留下 j 个开放的不匹配端点的方法数。 转换会考虑新元素是关闭其中一个打开的元素还是启动一个新的打开的需求。 这已经捕获了排列的组合结构。

为了实现平衡，我们改进了状态。 关键是每个配对都对总位移贡献一个可测量的值，并且这种贡献仅取决于我们正在考虑配对的哪一侧。 如果我们跟踪配对中“右端点”的索引之和，则自动确定左端点之和，它们的差值给出了总余额。 这导致DP状态DP[i][j][s]，其中i是前缀长度，j是开对的数量，s是右端点的累加和。 

此 DP 在 O(n^4) 状态下运行，因为 i 的范围可达 n，j 的范围可达 n，s 的范围可达 O(n^2)，并且每个状态的转换时间均为常数。 

一旦我们能够计算出具有给定剩余余额要求的部分固定前缀存在多少个完成，我们就可以按字典顺序构造第 k 个排列。 在每个位置，我们尝试按升序放置可能未使用的值。 对于每个候选选择，我们临时修复该分配并查询 DP 来计算剩余的有效完成数量满足剩余余额约束。 如果计数小于 k，我们跳过它并进行减法； 否则，我们承诺并继续。 

这将问题从全局枚举减少到部分赋值下的重复计数查询，这正是 DP 支持的。

 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了 |
 | DP 重建 | O(n^6) | O(n^6) | O(n^4) | O(n^4) | 已接受 |

 ## 算法演练

 我们首先将排列重新解释为位置和值之间的匹配过程。 我们不是立即修复所有分配，而是逐步构建排列，同时保留足够的信息来评估有多少完整排列与当前的部分选择保持一致。 

我们定义一个动态编程表，其中每个状态代表到目前为止我们已经处理了多少个元素，有多少个当前保持不匹配，以及为最终平衡积累了多少部分贡献。 这种结构就足够了，因为一旦我们知道右端点如何贡献，左端点就被隐式确定，并且余额变得可计算。 

我们通过前缀自下而上地计算这个 DP。 在每一步中，当我们添加新元素时，我们都会考虑它是与现有的开放元素配对还是在将来的配对中保持不匹配。 这解释了排列构造的所有结构可能性。 

填写完这个 DP 后，我们开始构建答案排列。 我们维护一组未使用的值。 在每个位置 i，我们按升序迭代候选值。 对于每个候选值 x，我们暂时假设 p[i] = x 并将问题简化为计算在此约束下存在多少个完成。 这是通过使用反映此选择引起的强制配对的更新参数查询 DP 来完成的。 

如果完成的数量小于 k，我们从 k 中减去它并继续下一个候选。 否则，我们将 x 固定在位置 i 并继续到位置 i + 1。这确保了字典顺序的正确性，因为我们总是首先耗尽较小的选择。 

### 为什么它有效

 正确性依赖于这样一个事实：DP 状态完全捕获了扩展部分排列所需的所有信息而没有歧义。 前缀的每个有效延续恰好对应于一个 DP 路径，并且每个 DP 路径恰好对应于一个完成。 因此，对 DP 状态进行计数可以精确测量有多少有效排列扩展给定的前缀，从而通过减去计数来允许正确的词典选择。

 ## 边缘情况

 关键的边缘情况是平衡约束仅强制一小部分排列保持有效。 例如，当 n = 2 且 b = 2 时，只有排列 [2, 1] 满足约束。 DP 仍然必须正确报告导致此结构的前缀选择的一个完整结果。 任何超额计数都会错误地允许较早的词典编目选择。 

当 k 相对于有效排列的数量较大时，会出现另一种边缘情况。 在这种情况下，必须跳过前面位置的每个候选，并且算法必须在提交后面的选择之前正确耗尽所有 DP 计数。 如果 DP 计数不准确，k 可能会变为负数或无法正确终止。
