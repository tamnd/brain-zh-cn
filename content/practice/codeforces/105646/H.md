 ## 解决方案
 ## 问题理解

 我们给定了一个整数序列，我们希望将其精确地拆分为$k$连续的段。 每个段都有一个平均值，计算方法是其元素之和除以其长度。 在分区中的所有段中，我们查看最小的平均值，我们的目标是选择使这个最小平均值尽可能大的分区。 

换句话说，我们将数组切割成$k$间隔，我们关心平均值中最弱的间隔。 我们希望使最弱的区间尽可能强大。 

输入大小允许数组足够大，以至于每次检查任何解决方案都必须接近线性或近线性。 参数的存在$k$并且对分区的优化强烈建议采用贪婪或二分搜索结构，而不是对所有分区进行动态编程，这会引入$O(n^2)$或者更糟糕的依赖。 

当所有数字都是负数或当$k$很大。 试图贪婪地扩展细分市场直到其平均值良好的幼稚策略可能会失败，因为局部决策会影响未来细分市场的可行性。 

例如，假设数组是$[1, 2, 3, 4]$和$k = 2$。 一个天真的想法可能会尝试削减$3$，但根据平均值的计算方式，这可能不是最佳的。 正确的解决方案必须全局评估分区，而不是贪婪地评估。 

当值浮动或直接比较平均值时，会出现另一个问题。 浮点不稳定可能导致边界阈值的可行性检查不正确。 

## 方法

 蛮力方法会枚举所有可能的选择方式$k-1$之间切位置$n-1$差距。 对于每个分区，我们计算分段总和和分段平均值，然后取最小值并最大化。 这是正确的，但组合起来具有爆炸性，因为选择切割的方法数量是$\binom{n-1}{k-1}$，即使对于适度的人来说这也是不可行的$n$。 

关键的结构见解是停止直接考虑分区，而是提出一个决策问题：对于固定值$x$，我们可以将数组分成$k$使得每个段至少具有平均值$x$？ 如果我们能回答这个问题，我们就可以搜索最大可能的$x$使用二分查找，因为如果某个阈值$x$是可以实现的，任何更小的阈值也是可以实现的。 

检查固定方案的可行性$x$，我们将平均值条件转换为总和条件。 一段来自$l$到$r$满足$$\frac{a_l + \dots + a_r}{r-l+1} \ge x$$这相当于$$(a_l - x) + \dots + (a_r - x) \ge 0.$$所以我们减去$x$从每个元素开始，现在要求每个段具有非负和。 

对于前缀和，这变成了前缀值的选择问题：我们想要选择$k+1$索引（段边界），使得每个段对应于连续选择的前缀位置之间的非负和差。 这会导致贪婪的可行性检查，可以解释为选择有效的切割点，其中前缀和相对于上次切割不会减少。 

由此产生的结构简化为寻找我们是否可以选择$k$有效段，可以将其构建为变换后的前缀和上的最长非递减结构，或者更直接地构建为使用前缀最小约束的贪婪分段。 

二分查找包含了这个可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 二分查找+贪心检查 | O(n 对数精度) | O(n) | 已接受 |

 ## 算法演练

 我们将答案视为实际值，并使用二分搜索在安全包含最佳平均值的区间内进行搜索。 

1. 定义一个函数`check(x)`这决定了我们是否可以将数组至少划分为$k$每个段至少具有平均值的段$x$。 这是核心的可行性测试。 
2. 通过减法变换数组$x$从每一个元素。 这将条件“平均值≥x”转换为“段总和≥0”。 
3. 计算此变换后的数组的前缀和。 让$p[i]$是第一个的总和$i$变换后的元素。 
4. 从左到右贪婪地构建段。 我们保持最后的切割位置。 对于结束于位置的新段$i$，我们检查是否$p[i] - p[last]\ge 0$。 如果是的话，我们可以在这里关闭一个部分。 
5. 每次关闭一个片段时，我们都会将最后一个剪切移动到$i$and increment the segment count.
 6. 扫描数组后，我们检查是否至少获得了$k$段。 
7. 二分查找$x$使用这个`check`函数，收紧间隔，直到达到所需的精度。 

微妙的推理是，一旦可以实现非负部分，我们总是尽早削减。 推迟削减无助于未来的可行性，因为它只会降低剩余的灵活性。 

### 为什么它有效

 变换后的条件将每个段约束减少到对前缀差异的非负性要求。 贪婪分段确保每个选定的分段在约束下是最大的，同时仍然有效。 如果给定的分区存在有效分区$x$，这种贪婪策略将找到至少一个这样的分区，因为任何有效的分段都可以转换为最左边的贪婪分段，而不会破坏可行性。 这保留了到达的能力$k$尽可能准确地进行分段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(arr, k, x):
    cnt = 0
    cur = 0
    last = 0

    for v in arr:
        cur += v - x
        if cur - last >= 0:
            cnt += 1
            last = cur

    return cnt >= k

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    lo, hi = -1e5, 1e5

    for _ in range(60):
        mid = (lo + hi) / 2
        if can(arr, k, mid):
            lo = mid
        else:
            hi = mid

    print(lo)

if __name__ == "__main__":
    solve()
```这`can`函数对变换后的数组实现贪婪分割。 变量`cur`在减去候选平均值后维持运行前缀和。 变量`last`存储最后切割位置的前缀和，因此`cur - last`正好是当前段的总和。 当它变为非负数时，我们关闭一个段。 

二分搜索运行固定次数的迭代，这足以满足浮点收敛。 范围$[-10^5, 10^5]$安全地包含给定典型约束的任何合理平均值。 

## 工作示例

 考虑数组$[1, 2, 3, 4]$和$k = 2$。 

我们测试一个候选人$x = 2.5$。

 ## 边缘情况

 一种边缘情况是当$k = n$。 每个元素形成自己的段，因此答案必须等于最小数组元素。 该算法可以处理此问题，因为每个段检查都会简化为单个转换值$a_i - x \ge 0$，二分查找精确收敛到保持所有非负数的最小值。 

当所有值都相同时，会出现另一种边缘情况。 任何分区都会产生相同的段平均值，因此答案是常数。 可行性检查总是在该值处成功，而在该值之上则失败，因为所有转换后的值都变为负值。 

最后一种边缘情况是当值为负值且与正值混合时。 该转换确保了正确性，因为它将绝对比例转换为候选对象周围的相对偏移量$x$，因此分割仅取决于累积平衡而不是符号分布。
