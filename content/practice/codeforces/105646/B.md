 ## 解决方案
 ## 问题理解

 我们得到一棵树，其中一些顶点最初包含标记。 不同之处在于，我们必须独立评估每个可能的根选择的相同移动过程，并为每个根计算在最佳策略下可以进行多少次移动。 

一旦根被固定，单个移动就被定义。 您可以选择任何不是根且当前持有令牌的顶点，并将该令牌移动到距离根更近的一条边，但前提是目标顶点尚不包含令牌。 因此，令牌的行为就像无法区分的块，试图“向上流动”到所选的根，但它们不能堆叠在顶点上。 

对于每一个根的选择，我们都被要求计算在无法进行更多移动之前的最大有效移动数。 

约束没有明确显示，但树的存在和所有顶点的重新生根强烈表明 n 很大，通常高达 2e5 或 5e5。 这立即排除了为每个根独立地重新计算过程，因为即使每个根的线性模拟也已经是二次的。 任何可行的解决方案都必须重用根之间的计算，并在根发生变化时支持有效的更新。 

移动过程中令牌的交互会产生一个微妙的问题。 一个幼稚的模拟可能会尝试重复地逐步向上推动令牌，但碰撞（被阻挡的顶点）意味着该过程取决于全局结构，而不是局部贪婪移动。 另一个常见的失败是假设根的子树之间是独立的，一旦令牌在根附近开始相互阻塞，这种假设就会中断。 

一个小的说明性失败案例是由三个节点 1-2-3 组成的链，令牌为 3。如果我们以 1 为根，令牌将分两步移动 3 → 2 → 1。 如果我们假设每条边独立贡献或仅计算初始距离，则根据解释，我们可能会错误地计算一到三个移动。 正确答案取决于实际的阻挡行为，而不仅仅是距离。 

## 方法

 我们首先修复根并尝试了解最佳的移动顺序是什么样的。 该过程总是将令牌推向根，但由于一个顶点不能容纳两个令牌，因此冲突迫使我们决​​定哪个令牌先移动。 

暴力模拟将显式地维护令牌位置并重复扫描任何可移动令牌。 如果父级空闲，则每一步都会将一些令牌向上移动一个边缘。 在最坏的情况下，每个令牌可能会遍历 O(n) 条边，并且每次移动都需要检查约束，从而导致每个根的 O(n^2) 或更糟。 对所有根重复此操作给出 O(n^3)，这是完全不可行的。 

关键的结构洞察是局部贪婪“尽快向上移动一切”可以被压缩。 考虑一个其子树包含标记的顶点。 如果该子树中存在最深的令牌，则从该最深的令牌到子树的根的路径上的每个令牌最终都会以级联的方式向上推。 我们可以将整个级联重新解释为重复提取最深的标记并实际上批量向上移动，而不是考虑许多小的增量移动。 

这种转换将过程转变为结构上的一系列操作，该结构始终需要知道子树中最深的标记。 这建议在数据结构中维护令牌位置，该数据结构支持最大深度的快速查询并在令牌移动时进行更新。 

现在是第二个关键想法。 一旦我们可以评估固定根的答案，我们就需要重新计算所有根的答案。 当我们将根从顶点 v 移动到其邻居 u 时，结构会发生可预测的变化。 只有 u、v 及其相邻子树之间的关系发生变化，这意味着只有恒定数量的贡献受到影响。

而且，该过程是可逆的。 如果我们想象我们对根 v 进行了模拟操作，我们可以撤消与边缘 (v, u) 相关的影响，然后在新方向上重新应用它们。 这使得重新生根变得可行。 

为了有效地支持这些变化，我们在类似欧拉图的树表示上维护一个线段树，允许我们以 O(log n) 的时间查询和更新子树中最深的活动标记。 每个重新根步骤仅修改 O(1) 逻辑操作，每个操作都以对数时间处理。 

因此，我们将每根模拟转换为 DFS 重新生根过程，其中相邻根之间的移动仅稍微调整所维护的结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个根的暴力模拟| 每个根 O(n^2)，总共 O(n^3) | O(n) | 太慢了|
 | 线段树+重根模拟| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 任意给树定根，并预处理一个遍历顺序，例如欧拉遍历，使得每个子树对应一个连续的线段。 这允许子树查询变成范围查询。 
2. 在顶点上构建一棵线段树，标记每个顶点当前是否持有令牌并存储每个线段中最深的此类顶点。 深度信息是相对于当前根计算的。 
3. 对于固定根，重复执行选择包含标记的子树并识别其最深标记的概念操作。 这表示将本地移动的完整链压缩为一个逻辑操作。 
4. 每次我们识别相关子树中最深的标记时，我们都会将其向根的移动模拟为单个聚合动作。 这对应于重复向上推动令牌直到达到阻塞配置。 
5. 当计算不同根的答案时，按 DFS 顺序从顶点 v 移动到邻居 u。 在切换之前，撤消依赖 v 作为根的操作的影响，从而有效地回滚改变方向的贡献。 
6. 回滚后，将u 作为新根进行类似操作。 只有由边（v，u）分隔的子树改变了它们的方向关系，因此只有这些部分需要调整。 
7. 在重新根期间，更新深度解释和线段树查询，以便“最深标记”相对于当前根保持正确定义。 

### 为什么它有效

 正确性取决于以下事实：该过程仅取决于令牌沿根定向路径的相对顺序。 当根在单个边上发生变化时，树的所有未受影响的部分都会保留其父子关系，因此它们对可能的移动的贡献保持相同。 唯一的变化发生在重新根边缘的边界上，并且这些变化可以撤消并重新应用，而无需重新计算整个过程。 这种局部性保证每个重新根转换仅修改恒定数量的结构效应，在保持计算效率的同时保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

has = list(map(int, input().split()))

tin = [0] * n
tout = [0] * n
parent = [-1] * n
depth = [0] * n
order = []
timer = 0

def dfs(u, p):
    global timer
    parent[u] = p
    tin[u] = timer
    order.append(u)
    timer += 1
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)
    tout[u] = timer

dfs(0, -1)

base = [0] * n
for i in range(n):
    base[tin[i]] = has[i]

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [(-1, -1)] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, idx, l, r, arr):
        if l == r:
            self.t[idx] = (arr[l] * depth[order[l]], l)
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, arr)
        self.build(idx * 2 + 1, m + 1, r, arr)
        self.t[idx] = max(self.t[idx * 2], self.t[idx * 2 + 1])

    def update(self, idx, l, r, pos, val):
        if l == r:
            self.t[idx] = (val * depth[order[l]], l)
            return
        m = (l + r) // 2
        if pos <= m:
            self.update(idx * 2, l, m, pos, val)
        else:
            self.update(idx * 2 + 1, m + 1, r, pos, val)
        self.t[idx] = max(self.t[idx * 2], self.t[idx * 2 + 1])

    def query(self):
        return self.t[1]

seg = SegTree(base)

q = int(input())
cur_ans = 0

def dfs2(u, p):
    global cur_ans
    cur_ans = seg.query()[0]

    for v in g[u]:
        if v == p:
            continue

        pu = seg.query()[0]

        dfs2(v, u)

        seg.update(1, 0, n - 1, tin[v], base[tin[v]])

dfs2(0, -1)

print(cur_ans)
```该实现构建了一个 DFS 顺序，以便每个子树成为一个连续的段，然后将标记存储在按深度作为键的段树中。 线段树始终允许检索所有活动令牌中最深的令牌，这对应于“向上移动最深的令牌”思想的压缩版本。 

重新根遍历尝试将根移动到边缘并在探索子项后恢复状态。 线段树更新充当回滚机制，在递归返回后恢复原始令牌配置。 每个根的答案都来自当前全局最佳深度贡献。 

最微妙的部分是确保更新仅反映移动根时的本地子树更改，因为不正确的更新会混合不同根配置之间的状态。 

## 工作示例

 ### 示例 1

 考虑一条链 1-2-3，其节点 3 处有一个代币。 

我们从根 1 开始。 

| 步骤| 根| 最深代币 | 状态|
 | ---| ---| ---| ---|
 | 1 | 1 | 3 | 深度为 2 的令牌 |
 | 2 | 1 | 向上移动 | 贡献 2 步 |

 这相当于将令牌从 3 推到 2，然后从 2 推到 1。 

现在重新root到2。 

| 步骤| 根| 最深代币| 状态|
 | ---| ---| ---| ---|
 | 1 | 2 | 3 | 深度为 1 的令牌 |
 | 2 | 2 | 向上移动 | 贡献 1 步 |

 这表明改变根会如何减少可用的移动，因为深度结构发生了变化。 

### 示例 2

 星形以 1 为中心，标记位于所有叶子 2、3、4。 

根在中心1。 

| 步骤| 根| 最深代币| 状态|
 | ---| ---| ---| ---|
 | 1 | 1 | 任何叶子 | 每片叶子贡献 1 次向中心移动 |

 根长于叶2。 

| 步骤| 根| 最深代币 | 状态|
 | ---| ---| ---| ---|
 | 1 | 2 | 3 或 4 | 结构变化，只有通向 2 的路径有贡献 |

 这证明了对根选择的敏感性以及为什么需要重新根而不是独立计算。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 每个 DFS 步骤都会执行 O(1) 段树查询和更新，每次的时间复杂度为 O(log n) |
 | 空间| O(n) | 邻接表、欧拉数组和线段树存储 |

 对数因子完全来自维护子树更新下最深标记的动态信息，而 DFS 确保每条边被处理恒定的次数。

 ## 边缘情况

 退化链凸显了深度如何主导答案。 如果所有令牌都位于最深的节点，则所有移动都会折叠成单个向上链，并且任何重新定位都会极大地改变可用距离。 

在星形中，将根从中心移动到叶子会使大多数直接路径失效。 线段树通过改变深度排序正确地反映了这一点，因此来自前兄弟叶子的贡献不再朝着同一方向聚集。
