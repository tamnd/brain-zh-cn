 ## 解决方案
 ## 问题理解

 给定一个有向无环图，它具有固定的起始顶点 1 和固定的结束顶点 n。 任务不是找到单个路径，而是构建尽可能长的有效 1 到 n 路径序列，并带有一个约束，使每个新路径与所有先前选择的路径相比“带来新的东西”。 具体而言，序列中的每个下一条路径必须包含至少一个从未出现在序列中任何较早路径中的有向边。 

因此，我们本质上是将图的可用部分分解为一系列 1 到 n 的遍历，其中每次遍历必须贡献至少一个以前未使用的边。 一旦一条边出现在某个选定的路径上，它就会因为计算新颖性而被“消耗”。 

输入图是 DAG，它消除了对循环的担忧，但没有简化路径如何重叠的组合性质。 输出是一个整数：该序列的最大长度。 

Codeforces 图问题典型约束的第一个直接含义是，n 和 m 足够大，任何比 m 中的线性或近线性更差的解决方案都不会运行。 这已经表明我们不能显式地枚举路径或模拟贪婪构造，因为 DAG 中简单路径的数量可能是指数级的。 

一个关键的结构边缘情况是顶点 1 根本无法到达顶点 n。 在这种情况下，没有有效路径，因此答案必须为 0。当存在可达性但只能通过非常狭窄的走廊时，就会出现第二种微妙的情况。 例如，如果从 1 到 n 仅有一条路径，则答案为 1，因为使用该路径后，每条边都已被使用，并且没有第二条路径可以引入新边。 

一种简单的方法可能会尝试重复查找从 1 到 n 的路径，其中包含至少一个未使用的边，删除或标记该边，然后继续。 这是因为你选择“消耗”的边决定了未来的结构，而贪婪的路径选择并不能保持最优性。 

## 方法

 思考问题的一种强力方法是显式模拟该过程。 我们维护一组已使用的边，并重复搜索从 1 到 n 的路径，其中包含至少一个未使用的边。 每次我们找到这样的路径时，我们都会将其所有边标记为已使用并增加答案。 

即使我们使用 DFS 或 BFS 优化每次搜索，迭代次数也可以与边数成线性关系，并且每次迭代的成本为 O(n + m)。 更关键的是，路径的选择不是独立的：选择一条路径可能会“浪费”本来可以在多个未来路径中更有效地重用的边缘。 这使得暴力破解不仅缓慢而且难以正确推理。 

关键的见解是停止思考整个路径，而是推理边和顶点如何促成每条新路径所需的最小结构。 我们将注意力限制在实际相关的子图上：位于至少一个有效的 1 到 n 路径上的顶点。 这些正是反向图中从 1 可到达且可到达 n 的顶点。 设此类顶点的数量为 N，它们之间的边的数量为 M。 

在这个受限子图中，每条有效的 1 到 n 路径必须从 1 开始并以 n 结束，并且新路径中出现的每个中间顶点迫使该路径“消耗”至少一条超出已考虑范围的新边。 这在所有路径上可以引入多少个新顶点以及必须存在多少条边来支持它之间建立了紧密的关系。

如果我们用 p 表示最优序列中的路径数量，并令 v 为“每个路径结构的新顶点贡献”的总数，我们可以将每条路径视为强制比它引入的新顶点数量至少多一条边。 对所有路径求和可得出 M、N 和 p 之间的线性关系。 求解该会计恒等式可得出闭合形式 p = M − N + 2。 

这种转换是核心简化：我们不再探索组合路径序列，而是将所有内容简化为计算“有用”子图中的顶点和边。

 | ---| ---| ---| ---|
 | 暴力路径模拟| 最坏情况下呈指数 | O(n + m) | 太慢了|
 | 可达性+计数公式 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们首先隔离图中实际上可以参与从 1 到 n 的任何有效路径的部分。 该区域之外的所有内容都是无关紧要的，因为没有有效的序列可以包含这些顶点或边。 

1. 从顶点1开始进行图遍历，标记所有可到达的顶点。 这确保我们只考虑可能出现在某些有效路径段开头的顶点。 
2. 从顶点n开始遍历反转图，标记所有可以到达sink的顶点。 这确保我们只保留实际上可以完成有效路径的顶点。 
3. 使这两组顶点相交。 只有这些顶点才能出现在任何有效的 1 到 n 路径中，因为它们既可以从源到达，也可以到达汇点。 
4. 计算 N 作为该交点的顶点数。 此时，我们仅关注所有有效路径所在的图的“核心”。 
5. 将 M 计算为两个端点均位于该交点内的有向边的数量。 这些是唯一可能出现在任何有效路径中的边。 
6. 如果从顶点 1 无法到达顶点 n，则立即返回 0。 根本不存在有效路径，因此不存在任何序列。 
7. 否则将答案计算为 M − N + 2。 

该公式出现的原因是，除了第一条路径之外的每条附加路径都可以解释为强制包含至少一条新边，以补偿先前使用的顶点。 存在多少条边和必须遍历多少个顶点之间的平衡限制了此类“新鲜”增强的最大数量。 

### 为什么它有效

 在限制到有用子图之后，除了端点 1 和 n 之外的每个顶点都可以被认为需要至少一个传入边和一个传出边来参与任何有效的 1 到 n 遍历。 序列中的每条新路径必须引入至少一条先前未使用的边，并且 DAG 的结构确保这些引入不能在不引入新的顶点参与约束的情况下任意重用。 这创建了一种紧密的核算关系：边为新路径提供“供应”，而顶点则施加“结构开销”，从而降低了跨路径重用边的效率。 在考虑基本路径和端点约束后，派生表达式 M − N + 2 准确地捕获了此盈余。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    rg = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        rg[v].append(u)
        edges.append((u, v))

    # reachability from source
    vis1 = [False] * (n + 1)
    q = deque([1])
    vis1[1] = True
    while q:
        u = q.popleft()
        for v in g[u]:
            if not vis1[v]:
                vis1[v] = True
                q.append(v)

    # reachability to sink (reverse graph)
    vis2 = [False] * (n + 1)
    q = deque([n])
    vis2[n] = True
    while q:
        u = q.popleft()
        for v in rg[u]:
            if not vis2[v]:
                vis2[v] = True
                q.append(v)

    # check connectivity
    if not (vis1[n] and vis1[1]):
        print(0)
        return

    cnt_v = 0
    for i in range(1, n + 1):
        if vis1[i] and vis2[i]:
            cnt_v += 1

    cnt_e = 0
    for u, v in edges:
        if vis1[u] and vis2[u] and vis1[v] and vis2[v]:
            cnt_e += 1

    print(cnt_e - cnt_v + 2)

if __name__ == "__main__":
    solve()
```该解决方案首先构建前向和反向邻接列表，因为我们需要两个独立的可达性计算。 1 中的一个 BFS 标识可从源端使用的顶点，而反向图上 n 中的另一个 BFS 标识仍可通向接收器的顶点。 这两个集合的交集定义了有效子图。 

然后我们计算这个子图中的顶点和边。 边缘过滤很重要，因为接触不相关顶点的边缘不得包含在 M 中； 否则该公式就会中断，因为它假定完全一致的受限结构。 

最后，我们应用封闭式表达式 M − N + 2，它直接产生最大序列长度。 

## 工作示例

 ### 示例 1

 考虑一个简单的链：1 → 2 → 3 → n，没有额外的边。 

| 步骤| 从 1 开始 | 达到 n | 活动顶点| 活动边缘| 结果 |
 | ---| ---| ---| ---| ---| ---|
 | 开始| {1,2,3,n} | {1,2,3,n} | {1,2,3,n} | 3 | |
 | 计数 | 4 | 4 | 4 | 3 | |

 这里 M = 3，N = 4，所以答案是 3 − 4 + 2 = 1。 

这证实了单个简单路径只能贡献一个序列元素，因为每条边都会立即被消耗。 

### 示例 2

 考虑一个菱形结构：1 分裂成 2 和 3，都变成 4，然后 4 → n，还有一个额外的交叉边 2 → 3。 

活动顶点均为 5 个节点，因此 N = 5。活动边为 1→2、1→3、2→3、2→4、3→4、4→n，因此 M = 6。 

| 步骤| 尼 | 中号 | 结果 |
 | ---| ---| ---| ---|
 | 计算| 5 | 6 | 6 − 5 + 2 = 3 |

 这显示了额外的内部边如何增加序列中不同 1 到 n 路径的可能数量，而不仅仅是不相交的路由数量。

 ## 边缘情况

 一个关键的边缘情况是当无法从源到达接收器时。 例如，1→2和3→n，组件之间没有连接。 从1开始的BFS只标记{1,2}，而从n开始的反向BFS只标记{n,3}。 它们的交集是空的，所以N = 0并且M = 0，但是我们直接返回0，因为根本没有有效路径。 这避免了在简并状态下应用该公式。 

另一种情况是图是单个简单路径。 对于 1 → 2 → 3 → n，所有顶点都在交集中，因此 N = 4 且 M = 3。计算得出 1，这符合只有一个序列元素可能的直觉。 

一个更微妙的情况是，当存在额外的边不会改变可达性但会增加 M 时。这些边正确地增加了最终答案，因为它们为不同的路径提供了额外的“新鲜边机会”，并且公式线性地解释了它们，而不需要任何模拟。
