 ## 解决方案
 ## 问题理解

 我们有一棵树，其中每个节点代表一个持有一定数量黄金的营地。 我们可能会选择某些营地来“加强”。 强化一个营地并不会直接改变自己的金币，而是会减少其所有邻居的金币固定数量$c$。 所有强化决策做出后，只有强化阵营才能生存，最终得分为所有削减后幸存节点的金币值总和。 

因此，真正的决定是选择哪些节点，以便在考虑了邻居对它们造成的损害后，我们可以最大化所选节点的总贡献。 

每个选定的节点都会贡献其原始值，但每次选择其邻居之一时，其值都会减少$c$。 由于只有选定的节点对最终总和很重要，因此交互完全在选定的节点子集内。 问题变成根据节点权重和边交互来选择最大化值的节点子集。 

这些约束促使我们为每个测试用例提供线性或线性算术解决方案。 所有测试用例的节点总数为$2 \cdot 10^5$，所以任何解决方案的作用超过$O(n \log n)$每个测试用例总共或单个基于 DFS 的 DP 是可以接受的，但树结构中的任何二次方都会失败。 

天真的直觉的一个微妙的失败案例是假设独立性，例如选择所有正节点。 这失败了，因为由于惩罚，选择两个相邻的高值节点可能比只选择其中一个更糟糕$c$。 另一个失败是贪婪的叶子去除，它会破坏长链，而局部选择会减少未来的收益。 

## 方法

 如果我们忽略结构，我们可能会尝试节点的所有子集。 对于每个子集，我们通过对节点值求和并减去来计算其分数$c$对于选择两个端点的每个内部边缘。 这是正确的，但需要检查$2^n$子集，即使对于$n = 30$。 

关键的观察结果是，目标仅取决于所选集合内哪些边被“激活”。 每个选定的节点贡献其权重，每个选定的边贡献惩罚$c$。 这正是节点和边在本地交互的树上的最大权重子集问题。 

这种类型的结构自然是由树 DP 处理的。 节点的选择仅取决于该节点是否被选择以及其子节点的行为方式。 一旦我们为树建立根，我们就可以使用两种状态来表达每个子树的最优解：选择或不选择该子树的根。 

这将指数子集问题简化为树边上的线性DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 树DP |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们在任意节点（通常是节点 1）将树作为根。每个节点的 DP 计算两个值：选择该节点时和未选择该节点时其子树中可实现的最佳分数。 

1. 定义$dp[u][1]$作为子树中的最大分数$u$如果我们选择$u$。 定义$dp[u][0]$如果我们不选择，则作为最高分数$u$。 

这种分离是必要的，因为仅当选择两个端点时才适用边缘惩罚。 
2. 初始化$dp[u][1] = a_u$，自从选择$u$在考虑邻居之前给出其全部价值。 
3. 初始化$dp[u][0] = 0$，因为没有选择$u$没有直接贡献任何东西。 
4. 对于每个孩子$v$的$u$，我们将其贡献合并为$u$。 

如果$u$没有被选中，那么$v$可以选择或不选择，不会受到边缘惩罚$(u, v)$。 所以我们添加$\max(dp[v][0], dp[v][1])$。 

如果$u$被选中，然后选择$v$受到处罚$c$，因为边缘只贡献一次。 所以：

 - 如果我们不选择$v$，我们添加$dp[v][0]$- 如果我们选择$v$，我们添加$dp[v][1] - c$所以在这种情况下我们添加$\max(dp[v][0], dp[v][1] - c)$。 
5. 处理完所有子节点后，根的答案是$\max(dp[root][0], dp[root][1])$。 

这样做的原因是，从父级到子级的每条边都只被考虑一次，并且仅在选择两个端点时才应用惩罚。 一旦父级的状态固定，DP 可确保子树决策是独立的，因此不会遗漏或重复计算任何交互。 

## Python 解决方案```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)
        
        dp0 = [0] * n
        dp1 = [0] * n
        parent = [-1] * n
        
        order = []
        stack = [0]
        parent[0] = -2
        
        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if parent[v] == -1:
                    parent[v] = u
                    stack.append(v)
        
        for u in reversed(order):
            dp1[u] = a[u]
            dp0[u] = 0
            
            for v in g[u]:
                if v == parent[u]:
                    continue
                dp0[u] += max(dp0[v], dp1[v])
                dp1[u] += max(dp0[v], dp1[v] - c)
        
        print(max(dp0[0], dp1[0]))

if __name__ == "__main__":
    solve()
```在实现中，将DFS顺序转换为迭代遍历，以避免递归深度问题。 然后，我们以相反的顺序处理节点，以便子节点在其父节点之前进行评估，确保 DP 状态在需要时准备就绪。 关键的微妙之处在于区分每个节点的两种情况：选定的和未选定的，因为这使我们能够在每个选定的边上正确地收取一次惩罚。 

## 工作示例

 考虑具有值的三个节点的简单链$[2, 3, 1]$和$c = 1$。 

| 节点| dp0 | dp1 |
 | --- | --- | --- |
 | 3 | 0 | 1 |
 | 2 | 3 | 3 + 最大值(0,1-1)=3 |
 | 1 | 3 | 2 + 最大值(0,3-1)=4 |

 最终答案是 4，通过选择节点 1 和 2 而不是 3 来实现。 

这显示了如何仅在选择两端时才应用惩罚，以及跳过节点有时会如何增加下游价值。 

现在考虑一颗星，其中心具有较大的值，但叶子较小。 如果惩罚超过其贡献，DP 自然会避免选择太多叶子，这证明了节点增益和边缘成本之间的权衡。

 ## 边缘情况

 一个关键的边缘情况是当所有$a_i$是负面的。 DP 正确地避免选择大多数节点，因为$dp[u][1]$从负值开始，并且转换允许完全跳过选择。 另一种情况是当$c$非常大，使得任何相邻选择都是有害的； 然后 DP 就会崩溃，只选择孤立的高价值节点。 最后一种情况是交替选择是最佳的路径，这自然可以通过父子状态分割来捕获。
