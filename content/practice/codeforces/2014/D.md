 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 每个作业占用一定的天数间隔`[l, r]`。 访客停留时间正好`d`连续几天，因此选择开始日期`s`表示访问涵盖了时间间隔`[s, s + d - 1]`。 

如果工作至少与访问重叠一次，则该工作将被计数。 重叠的数量并不重要。 共享一天就足够了。 

对于每个可能的有效开始日，我们需要知道有多少工作与该长度相交 -`d`窗户。 在所有有效的开始中，我们希望：

 - 窗口与最大作业数相交的最早开始日。 
- 窗口与最小作业数相交的最早开始日。 

访问必须保留在日历内，因此有效的开始日期为`1`通过`n - d + 1`。 

约束是解决方案的驱动力。 单个测试最多可以有`10^5`天和`10^5`职位，以及所有职位的总和`n`整个输入的值最多是`2 · 10^5`。 这意味着`O(n)`或者`O(n log n)`每个测试用例的解决方案都很舒服。 一个`O(nk)`解决方案是不可能的，因为它可能需要大约`10^10`运营。 

棘手的部分是工作是间隔的，访问是间隔的。 对每对间隔进行简单的重叠检查成本太高。 

一些边缘情况值得关注。 

考虑：```
n = 5
d = 2
job = [2,3]
```此次访问`[1,2]`工作重叠，因为他们共享一天`2`。 此次访问`[3,4]`也重叠，因为他们共享一天`3`。 一个粗心的实现，如果只检查访问开始是否位于作业内部，就会错过这些重叠之一。 

考虑关系：```
n = 4
d = 1
jobs:
[1,1]
[4,4]
```计数为：

 | 开始| 工作重叠 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 0 |
 | 3 | 0 |
 | 4 | 1 |

 最大计数发生在天数`1`和`4`。 正确答案是日`1`，最早的一个。 同样的规则也适用于最小值。 

当工作时间长于访问时间时，会出现另一个微妙的情况：```
n = 10
d = 2
job = [2,8]
```每次访问从当天开始`1`通过一天`8`与这项工作重叠。 我们需要一种方法来有效地标记所有此类启动，而不是单独检查每个窗口。 

## 方法

 最直接的解决方案是检查每个有效的开始日并计算有多少个工作与其窗口相交。 

开始一天`s`，访问间隔为`[s, s+d-1]`。 一份工作`[l,r]`如果出现以下情况，则与本次访问重叠：```
l ≤ s+d-1
and
r ≥ s
```针对所有情况检查此条件`k`每个有效开始的作业给出的复杂性为：```
O((n-d+1) · k)
```在最坏的情况下，两个值都在`10^5`，大致产生`10^10`重叠测试。 这已经远远超出了极限。 

关键的观察是扭转视角。 

而不是问：

 > 对于开始日来说，哪些工作重叠？ 

问：

 > 对于一份工作，哪些开始日期有重叠呢？ 

让访问开始于`s`。 

重叠条件为：```
[s, s+d-1] intersects [l,r]
```这相当于：```
s ≤ r
s+d-1 ≥ l
```重新排列：```
s ≤ r
s ≥ l-d+1
```所以范围内的每个开始日```
[l-d+1, r]
```产生重叠访问。 

这非常有用，因为工作有助于`+1`到整个连续的开始日期范围。 

每当必须对数组应用许多间隔更新时，差异数组就是自然的工具。 

对于每项工作：```
add 1 to all starts in [l-d+1, r]
```将该范围限制在有效的开始日期之后`[1, n-d+1]`，我们执行范围更新`O(1)`使用差异数组。 

最终的前缀总和会为每个开始日重建重叠作业的确切数量。 

一旦知道这些计数，找到最早的最大值和最早的最小值就是一个简单的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n + k) | O(n) | 已接受 |

 ## 算法演练

 1.让`m = n - d + 1`，有效开始天数。 
2. 创建一个足够大的差异数组以支持索引的范围更新`1...m`。 
3. 对于每项工作`[l, r]`，确定哪些开始日期与其重叠。 

由重叠条件可知：```
l-d+1 ≤ s ≤ r
```4. 将此范围限制为有效开始日期：```
L = max(1, l-d+1)
R = min(m, r)
```任何外面的开始`1...m`不能代表有效的访问。 
5.如果`L ≤ R`，为所有开头加一`[L, R]`使用差异数组：```
diff[L] += 1
diff[R+1] -= 1
```6. 计算差值数组的前缀和。 

位置处的结果值`s`等于从当天开始与访问重叠的工作数量`s`。 
7. 从左到右扫描所有开始日期。 

跟踪迄今为止看到的最大计数以及最早实现该计数的日期。 
8. 在同一次扫描中，跟踪迄今为止看到的最小计数以及最早达到该计数的日期。 
9. 输出记录的两个开始日期。 

### 为什么它有效

 当访问开始满足以下条件时，工作恰好与访问重叠：```
l-d+1 ≤ s ≤ r
```每一个这样的开始都应该从该工作中获得一份贡献，而其他开始则不应该。 

差异数组精确地在该起始范围上加一。 由于不同工作的贡献是独立的，因此每个开始日的最终前缀总和等于重叠工作的总数。 

最大值和最小值的扫描是正确的，因为它按升序处理开始日期。 当稍后出现相同的计数时，它们将被忽略，保留最早出现的计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n, d, k = map(int, input().split())

        m = n - d + 1
        diff = [0] * (m + 3)

        for _ in range(k):
            l, r = map(int, input().split())

            L = max(1, l - d + 1)
            R = min(m, r)

            if L <= R:
                diff[L] += 1
                diff[R + 1] -= 1

        cur = 0

        max_cnt = -1
        max_day = 1

        min_cnt = 10**18
        min_day = 1

        for day in range(1, m + 1):
            cur += diff[day]

            if cur > max_cnt:
                max_cnt = cur
                max_day = day

            if cur < min_cnt:
                min_cnt = cur
                min_day = day

        ans.append(f"{max_day} {min_day}")

    sys.stdout.write("\n".join(ans))

solve()
```变量`m = n - d + 1`代表所有合法的起始位置。 每个计算都是在这个压缩域上而不是在原始日历上执行的。 

对于每项工作，关键导数为：```
s+d-1 ≥ l
⇒ s ≥ l-d+1
```连同`s ≤ r`，这给出了与作业重叠的确切启动间隔。 

夹紧步骤是必不可少的。 理论上，一份工作对开工的影响可能小于`1`或大于`m`，但这些开始并不对应于有效访问。 

扫描使用严格比较：```
if cur > max_cnt:
```和```
if cur < min_cnt:
```而不是`>=`或者`<=`。 

当多天达到相同计数时，这会保留最早的位置。 

差异数组分配了一些额外的单元格，因为更新可能会触及`R + 1`。 

## 工作示例

 ### 示例 1

 输入：```
n = 7
d = 2
jobs:
[1,2]
[1,3]
[6,7]
```有效的开始是`1..6`。 

对于每项工作：

 | 工作 | 原始范围 | 夹紧范围|
 | --- | --- | --- |
 | [1,2]| [0,2]| [1,2]|
 | [1,3]| [0,3]| [1,3]|
 | [6,7]| [5,7]| [5,6]|

 应用更新并获取前缀和后：

 | 开始日 | 重叠的工作 |
 | --- | --- |
 | 1 | 2 |
 | 2 | 2 |
 | 3 | 1 |
 | 4 | 0 |
 | 5 | 1 |
 | 6 | 1 |

 最大计数为`2`，在当天首次实现`1`。 

最小计数为`0`，在当天首次实现`4`。 

输出：```
1 4
```此示例显示了单个作业如何对整个开始日间隔（而不是一个职位）做出贡献。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + k) | 每个作业一次范围更新，所有有效开始日一次扫描 |
 | 空间| O(n) | 大小差异数组`n - d + 1`|

 由于所有的总和`n`输入值最多为`2 · 10^5`，所有测试用例的总工作量与输入大小呈线性关系。 这很容易满足 2 秒的限制，并且内存使用量仍然很小。

 ## 边缘情况

 考虑：```
1
5 2 1
2 3
```工作重叠开始：```
[2-2+1, 3] = [1,3]
```计数变为：

 | 开始| 计数|
 | --- | --- |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 0 |

 该算法准确标记了区间`[1,3]`在差异数组中并正确输出：```
1 4
```这验证了仅共享一个端点日仍然算作重叠。 

现在考虑领带的情况：```
1
4 1 2
1 1
4 4
```计数为：

 | 开始| 计数|
 | --- | --- |
 | 1 | 1 |
 | 2 | 0 |
 | 3 | 0 |
 | 4 | 1 |

 扫描期间，白天`1`成为记录的最大值。 当日`4`达到相同值时，严格比较防止替换。 答案仍然是最早的最大日。 

最后，考虑：```
1
10 2 1
2 8
```重叠范围为：```
[1,8]
```夹紧后。 

差异数组为每个起始位置加一`1`通过`8`，离开开始`9`有计数`0`。 该算法输出：```
1 9
```这证实了影响许多窗口的长作业是在恒定的更新时间内处理的，而不是重复的重叠检查。
