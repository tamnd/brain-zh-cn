 **求解时间：** 2m 2s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 对于每个查询，我们只查看子数组$a_l, a_{l+1}, \dots, a_r$。 

罗宾先动。 每回合，玩家选择任何剩余的目标，获得其价值，然后将其移除。 由于对选择哪个目标没有限制，因此游戏完全由查询段内的多个值集决定。 

两位球员都发挥得很完美。 对于每个查询，我们必须确定警长是否可以避免失败。 对于警长来说，平局算作成功，因为问题是问他是否**不**失败。 

所有测试用例的元素和查询总数最多为$2 \cdot 10^5$。 任何在线性时间内处理查询的解决方案都需要大约$4 \cdot 10^{10}$最坏情况下的操作，远远超出了极限。 预处理后，我们需要每个查询接近恒定或对数的工作。 

博弈论部分是第一个陷阱。 最佳游戏的简单模拟看起来很复杂，因为玩家交替轮流。 实际上，由于每个目标从一开始就可用，因此每个玩家只需获取当前最大的剩余值即可。 所选值的顺序是完全确定的。 

另一个容易犯的错误是认为只有总和才重要。 考虑：```
[1, 2]
```罗宾拿了 2，警长拿了 1，所以警长输了。 

总和是 3，但这本身并不能告诉我们什么。 

第二个陷阱是假设每个偶数长度的线段都会产生平局。```
[1, 1, 2, 3]
```罗宾得到$3+1=4$, 警长得到$2+1=3$。 警长输了。 

值的频率很重要。 

一个更微妙的情况是：```
[5, 5, 7]
```降序排序：```
7, 5, 5
```罗宾得到$7+5=12$, 警长得到$5$。 

尽管5出现了两次，但无与伦比的7决定了比赛。 

准确理解何时存在不匹配的值是关键的观察。 

## 方法

 让我们首先了解什么是最佳游戏。 

由于始终可以选择每个剩余的目标，因此当可以获得较大的值时，玩家永远不会从采用较小的值中受益。 如果还有较大的值，立即取走只能提高该玩家的最终得分。 

结果，游戏相当于将值按降序排序。 罗宾获得职位$1,3,5,\dots$警长获得职位$2,4,6,\dots$。 

假设我们对每个查询的段进行显式排序。 对于一段长度$m$，我们将对其值进行排序并计算交替总和。 这是正确的，因为它完全符合最佳玩法。 

问题在于复杂性。 查询可能包含$O(n)$元素，因此排序成本$O(m \log m)$。 高达$2 \cdot 10^5$查询，这是完全不可行的。 

突破来自于观察频率而不是分数。 

取任意值$x$。 如果出现偶数次，则在排序后，这些副本占据连续位置并在两个玩家之间平均分配。 他们的贡献被抵消了。 

只有具有奇数频率的值才重要。 将相等的值配对在一起后，每个奇数频率值恰好留下一个未配对的副本。 这些剩余的副本具有不同的价值。 排序后，他们在罗宾和警长之间轮流。 

现在观察一些值得注意的事情。 令剩余的不同值是$$b_1 > b_2 > \dots > b_k.$$罗宾收到$b_1, b_3, b_5,\dots$, 警长收到$b_2, b_4, b_6,\dots$。 

由于这些值严格递减，因此无论何时，罗宾的总数都大于警长的总数$k$很奇怪。 如果$k$是偶数，剩菜完美配对，总数相等。 

所以整个游戏就归结为一个问题：

 该段包含奇数个还是偶数个频率为奇数的值？ 

当计数为偶数时，警长会避免输掉比赛。 

我们现在需要一个数据结构来回答，对于任何子数组，每个值在取消后是否出现偶数次。 

这是一个经典的奇偶校验查询。 为每个不同值分配一个随机 64 位哈希值。 让$$pref[i] = h(a_1) \oplus h(a_2) \oplus \dots \oplus h(a_i).$$对于查询$[l,r]$,$$X = pref[r] \oplus pref[l-1].$$每个出现偶数次的值在 XOR 下都会被取消。 结果正是与奇数频率的值对应的哈希值的异或。 

如果不存在奇数频率值，则$X=0$。 

更一般地，奇数频率值的数量是偶数当且仅当它们的散列的 XOR 等于偶数大小的散列集的 XOR 时。 预期的解决方案使用随机散列：为值分配独立的随机数。 然后，当所有奇数频率值取消时，XOR 恰好为零，否则以压倒性的概率非零。 

官方的观察更加强烈。 当且仅当该段中的每个值频率都是偶数时，Sheriff 不会丢失。 该条件相当于段 XOR 哈希值为零。 

与 64 位随机数发生冲突的概率可以忽略不计。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(m \log m)$每个查询 |$O(m)$| 太慢了|
 | 最佳 |$O(n+q)$每个测试用例|$O(n)$| 已接受 |

 ## 算法演练

 ### 1. 为每个不同的值分配一个随机 64 位数字

 每当一个值第一次出现时，生成一个随机的 64 位整数并存储它。 

相同的值总是收到相同的哈希值。 

### 2.构建前缀异或数组

 定义$$pref[0]=0$$和$$pref[i]=pref[i-1]\oplus h(a_i).$$这使我们能够在恒定时间内获得任何段的异或哈希。 

### 3. 处理查询

 对于细分市场$[l,r]$, 计算$$cur=pref[r]\oplus pref[l-1].$$每个出现偶数次的值都会贡献其哈希偶数次并消失。 

结果是与段内频率为奇数的值精确对应的哈希值的异或。 

### 4. 确定答案

 如果$$cur=0,$$那么每个值的频率都是偶数，因此 Sheriff 可以避免丢失。 输出`"YES"`。 

否则输出`"NO"`。 

### 为什么它有效

 关键的不变量是 XOR 跟踪奇偶校验。 

对于任何值$x$，其哈希值每次出现时出现一次$x$。 自从$$h(x)\oplus h(x)=0,$$所有偶数事件都取消。 对段进行异或后，唯一幸存的哈希值属于奇数频率的值。 

如果每个频率都是偶数，则段 XOR 等于 0。 如果存在至少一个奇数频率值，则异或非零，除非随机散列的冲突概率可以忽略不计。 

游戏分析表明，当每个值都可以与另一个相等的值配对时，警长就可以避免失败。 因此，查询答案完全取决于段异或哈希是否为零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MASK = (1 << 64) - 1

def splitmix64(x):
    x = (x + 0x9e3779b97f4a7c15) & MASK
    x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9 & MASK
    x = (x ^ (x >> 27)) * 0x94d049bb133111eb & MASK
    x ^= x >> 31
    return x & MASK

def solve():
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        value_hash = {}
        pref = [0] * (n + 1)

        for i, x in enumerate(a, 1):
            if x not in value_hash:
                value_hash[x] = splitmix64(x)

            pref[i] = pref[i - 1] ^ value_hash[x]

        ans = []

        for _ in range(q):
            l, r = map(int, input().split())

            cur = pref[r] ^ pref[l - 1]

            if cur == 0:
                ans.append("YES")
            else:
                ans.append("NO")

        sys.stdout.write("\n".join(ans) + "\n")

solve()
```第一部分使用以下方法将确定性 64 位哈希分配给每个不同的值`splitmix64`。 使用确定性哈希可以避免对 Python 随机生成器的依赖，同时保留解决方案所需的抗碰撞性。 

前缀数组存储累积的 XOR 值。 由于 XOR 是其自身的逆，因此段 XOR 的获得方式为`pref[r] ^ pref[l - 1]`。 

唯一微妙的细节是索引。 前缀数组构建为基于 1 的结构，因此查询边界自然映射到标准范围公式。 

Python 整数是无界的，但所有哈希值都使用掩码保存在 64 位内。 这会重现无符号 64 位算术。

 ## 边缘情况

 考虑：```
1
1 1
10
1 1
```该段包含一次 10。它的哈希值在段 XOR 中仍然存在，所以答案是`"NO"`。 该算法正确地识别出仍然存在单个不匹配的值。 

考虑：```
1
1 1
4 4 9 9
1 4
```这两个值都出现两次。 段异或变为$$h(4)\oplus h(4)\oplus h(9)\oplus h(9)=0.$$算法输出`"YES"`因为每个频率都是偶数。 

考虑：```
1
1 1
5 5 7
1 3
```5 的两个副本取消，只留下 7 的哈希值。段 XOR 不为零，产生`"NO"`。 

最后，考虑一个触及数组边界的范围：```
1
2 1
1 2 1 2
1 4
```查询使用`pref[4] ^ pref[0]`。 前缀结构故意包括`pref[0]=0`，因此对于从位置 1 开始的范围没有特殊处理。答案是`"YES"`因为每个值都出现两次。
