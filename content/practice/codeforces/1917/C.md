 ## 解决方案
 ## 问题理解

 我们从一个数组开始`a`长度`n`。 

对于接下来的每一个`d`日子里我们必须选择一个行动。 

第一个操作增加前缀`[1..b_i]`乘一，其中序列`b`通过重复给定的数组生成`v`永远。 

第二个动作得分。 如果当前数组包含以下位置`a_j = j`，我们为每个这样的位置获得一分。 计分后，整个数组将重置为零。 

目标是在准确之后使总分最大化`d`天。 

最重要的观察结果是重置会破坏之前的所有进度。 重置后，无论之前发生了什么，数组都会固定为全零。 这意味着时间线自然地分成由评分操作分隔的独立片段。 

这些限制揭示了一些不寻常的事情。 天数可以大到`10^9`，所以任何模拟一整天的解决方案都是不可能的。 另一方面，所有的总和`n`整个输入的值仅`2000`。 这强烈表明预期的解决方案应该花费大约`O(n²)`每个测试用例工作并完全避免依赖`d`。 

一个微妙的点是，重置后，数组会变成全零。 由于位置编号为`1`，全零数组贡献零分。 连续执行两次得分操作总是没有用的，因为第二次得分为零并且使数组保持不变。 

另一个容易犯的错误是认为很多天都很重要。 考虑：```
n = 3
a = [0,0,0]
v = [3]
d = 10^9
```位置后`j`已经超过价值`j`，额外的增量永远不会使其等于`j`再次因为价值只会增加。 尽管阵列的有用演化非常短`d`是巨大的。 

第三个陷阱是忘记评分操作会消耗一天的时间。 认为：```
n = 1
a = [1]
v = [1]
d = 1
```答案是`1`，因为我们可以立即得分。 我们不能在同一天既增加又得分。 

## 方法

 强力解释是将每天视为决策点并在几天内执行动态规划。 该状态需要记住整个当前数组，因为未来的分数取决于其确切值。 自从`d`可能达到`10^9`，这是没有希望的。 

为了找到更小的东西，我们应该看看实际发生了什么变化。 

每个增量操作仅向前缀加一。 对于任何职位`j`，其值在两次重置之间的整个段内单调递增。 一次`a_j`变得大于`j`，它永远无法对该细分市场内的未来分数做出贡献。 

假设我们从未重置并执行第一个`t`增量操作。 让```
good(t) = number of positions j with current value exactly j
```在那些之后`t`增量。 

现在想象一下在当天选择分数运算`t + 1`。 

我们收获`good(t)`立即积分。 

剩下的日子怎么办？ 计分后，数组变为全零。 从零开始，在剩下的日子里获得的最佳分数出人意料地简单。 

从零数组开始，之后`x`未来，最多每两天可以获得一个分数：一天创造有用的东西，一天给它评分。 公认的解决方案中使用的官方观察是最大额外贡献等于```
floor((remaining_days) / 2)
```因为位置`1`总是可以被反复地重新创造和收获。 

因此，如果我们选择准确表现后得分`t`从原始数组开始递增操作，总可达到的分数是```
good(t) + floor((d - t - 1) / 2)
```在哪里`t + 1`是用于评分的日期。 

剩下的问题是有多少个值`t`必须检查。 

对于职位`j`，一旦其值超过`j`，则永久无用。 自从最初`0 ≤ a_j ≤ n`，每个位置只能在第一个过程中等于其索引`O(n)`增量。 大致之后`2n`每个位置的操作要么已经匹配，要么永久超出。 

官方解决方案利用了这一点并仅检查```
t = 0, 1, ..., min(d - 1, 2n)
```同时显式模拟这些前缀添加。 

因为所有的总和`n`只是`2000`，这个模拟很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 几天的暴力破解 | 指数 / 取决于`d`| 巨大 | 太慢了 |
 | 第一个优化模拟`2n`状态 |`O(n²)`每个测试用例|`O(n)`| 已接受 |

 ## 算法演练

 1. 让`cur`是初始数组的副本。 
2. 计算满足的位置数`cur[i] = i + 1`。 调用这个值`good`。 
3. 初始化答案```
good + floor((d - 1) / 2)
```这相当于第一天立即得分。 
4、一一模拟增量操作。 
5.让`lim = min(d - 1, 2n)`。 我们只需要检查第一个`lim`增量操作。 
6. 对于步骤`t`从`1`到`lim`:

 1. 使用以下命令应用下一个前缀增量`v[(t - 1) mod k]`。 
2.重新计算当前有多少个位置满足`cur[i] = i + 1`。 
3.如果还剩下至少一天进行评分操作，则更新```
answer = max(
    answer,
    good + floor((d - t - 1) / 2)
)
```这里`t`已使用增量天数，将再使用一天进行评分。 
7.输出找到的最大答案。 

### 为什么它有效

 考虑任何最佳策略。 关注它执行的第一个分数操作。 

假设这个分数正好发生在`t`对原始数组进行增量操作。 那一刻获得的分数正是`good(t)`。 

那天之后，数组就变成全零，过去就不再重要了。 剩下的优化问题只取决于还剩下多少天。 从零开始，每两天最多贡献一点，这个界限是可以达到的。 因此，未来最好的贡献正是`floor((remaining_days)/2)`。 

所以每个策略都对应于选择一些`t`并获得```
good(t) + floor((d - t - 1)/2).
```该算法评估所有相关值`t`。 

只有第一个`2n`价值很重要，因为每个头寸只有在永久超过其指数之前才能做出贡献。 在那之后`good(t)`永远不会增加，而第二项则减少`t`成长。 没有更大`t`可以改进答案。 

因此，算法检查的最大值等于最佳分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, k, d = map(int, input().split())
        a = list(map(int, input().split()))
        v = list(map(int, input().split()))

        def count_good(arr):
            cnt = 0
            for i, x in enumerate(arr, start=1):
                if x == i:
                    cnt += 1
            return cnt

        cur = a[:]

        ans = count_good(cur) + (d - 1) // 2

        lim = min(d - 1, 2 * n)

        for step in range(1, lim + 1):
            b = v[(step - 1) % k]

            for i in range(b):
                cur[i] += 1

            good = count_good(cur)
            ans = max(ans, good + (d - step - 1) // 2)

        print(ans)

if __name__ == "__main__":
    solve()
```数组`cur`表示从原始配置进行一定次数的增量操作后的状态。 

对于每个可能执行的增量数`t`，我们评估第一个评分操作紧随其后发生的场景。 表达式```
good + (d - step - 1) // 2
```与证明中推导的公式相符。 

界限```
lim = min(d - 1, 2 * n)
```是关键的优化。 模拟超过`2n`增量操作是不必要的，因为在该点之后没有位置可以重新变得有用。 

经常导致相差一错误的一个细节是`step`。 后`step`增加天数，计分操作需额外增加一天。 这就是为什么剩余的天数相等```
d - step - 1
```而不是`d - step`。

 | 测量| 复杂性 | 说明|

 自从`min(2n, d) ≤ 2n`，时间复杂度为`O(n²)`。 所有的总和`n`输入值最多为`2000`，因此总工作量明显低于限制。

 ## 边缘情况

 考虑：```
1
1 1 1
1
1
```该数组已经有一个匹配位置。 该算法评估`t=0`并获得```
1 + (1 - 1) // 2 = 1.
```由于没有剩余日期可供后续评分，因此无法进行增量操作。 输出正确`1`。 

现在考虑：```
1
3 1 3
0 0 0
3
```这些州是：```
t=0 : [0,0,0], good=0
t=1 : [1,1,1], good=1
t=2 : [2,2,2], good=1
```最佳值获得于`t=1`, 给出分数`1`。 这证实了该算法正确处理以没有匹配位置开始的数组。 

最后考虑：```
1
4 1 10
4 4 4 4
1
```位置`1`很快就会超出目标，并且永远无法再次发挥作用。 经过最初几天的模拟之后，`good(t)`永远不会增加。 由于未来奖金期限减少为`t`毛重，仅检查第一次`2n`状态就足够了。 该算法提前停止，无需检查所有十天，这正是使该解决方案适用于非常大的观察结果`d`。
