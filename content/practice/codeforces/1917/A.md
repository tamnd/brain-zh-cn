 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且能够将每个数字减少到零和当前值之间的任何整数。 对于正数，这意味着我们可以将它们减少到零； 对于负数，我们可以将它们增加到零。 目标是在执行任意数量的这些操作后最小化所有数组元素的乘积，然后报告所需的最小操作数以及实现该最小乘积的一个有效序列。 

数组长度最多可达 100，并且值的大小可能非常大。 自从$n$很小，我们可以单独检查每个元素并决定是否修改它。 然而，该产品可以快速溢出 64 位整数，因此在不计算的情况下推理精确值会更安全。 关键的见解是任何包含零的数组的乘积都为零，这是可能的最小乘积。 如果不存在零，则乘积由负数的奇偶性确定：奇数个负数给出负乘积，偶数个给出正乘积。 因此，要最小化乘积，首要任务就是创造一个零。 如果数组已包含零，则无需进行任何操作。 如果不是，将任何元素减少到零即可获得最小乘积。 

当数组已包含零或完全由负数组成时，会出现不明显的边缘情况。 例如，在数组中`[-1, -2]`，乘积为 2。将负数减少到零会将乘积减少到 0，这是严格更小的。 粗心的代码可能无法处理包含现有零的数组，或者假设所有负数必须保持负数。 

## 方法

 暴力方法会考虑数组中每个元素的所有可能选择并计算结果乘积，并跟踪最小值。 这原则上是正确的，但速度却呈指数级缓慢：对于$n = 100$甚至将每个元素限制为两个选项（原始或零）给出$2^{100}$的可能性。 

解锁线性解的观察结果是，如果数组包含零或者我们将任何元素减少到零，则最小乘积始终为零。 因此，我们只需要扫描数组，检查是否存在零，如果不存在，则执行一次操作将一个元素减为零。 无需检查归约或符号的组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，读取数组长度$n$和数组元素。 
2. 初始化一个标志来检测数组中是否已存在零。 如果不存在零，还跟踪第一个元素的索引。 
3. 迭代数组。 如果找到零，则标记该标志。 如果不是，请记住第一个元素的索引作为归约的候选元素。 
4. 扫描后，如果发现零，则已达到最小乘积，无需任何操作。 输出清零操作。 
5. 如果不存在零，则执行一项操作将存储索引处的元素减少到零。 输出指定索引（从 1 开始）和值 0 的一个操作。 

这是有效的，因为创建任何零都可以保证最小的乘积。 多个零不会进一步减少乘积，问题只要求最少的运算次数。 选择任何元素来归约就足够了，因此选择第一个非零元素可以简化实现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    zero_found = False
    idx_to_zero = -1
    
    for i in range(n):
        if a[i] == 0:
            zero_found = True
            break
        if idx_to_zero == -1:
            idx_to_zero = i
    
    if zero_found:
        print(0)
    else:
        print(1)
        print(idx_to_zero + 1, 0)
```该解决方案使用有效地读取输入`sys.stdin.readline`，处理多个测试用例，并正确输出基于 1 的操作索引。 我们仔细跟踪是否存在零以避免不必要的操作，并选择第一个非零元素进行约简。

 ## 边缘情况

 例如，对于大小为 1 且包含正整数的数组`[42]`，算法选择该元素并将其减少到零，从而产生一个操作。 如果单个元素已经为零，则算法会正确检测到它并输出零运算。 对于全负数组，该算法将第一个元素减少到零以最小化乘积，确保输出乘积为零。 任何地方包含零的数组都会被立即识别，并且不执行任何操作。 这证实了该算法可以处理所有可能的边缘情况，包括最小尺寸数组、包含零的数组、全负数组和全正数组。
