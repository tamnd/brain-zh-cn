 ## 解决方案
 ## 问题理解

 我们得到了一个括号字符串，但它并没有逐个字符明确地写入。 相反，它被压缩成块。 每个数字描述出现了多少个相同的连续括号，并且括号的类型交替：第一个块是左括号，第二个是右括号，然后再次打开，依此类推。 

展开序列给出完整的括号字符串。 从这个扩展的字符串中，我们考虑每个连续的子字符串，并计算其中有多少子字符串形成正确的括号序列。 正确的序列是指仅使用括号的结构就可以将其转换为有效的算术表达式的序列，这相当于通常的平衡括号的概念。 

输入大小最多为 1000 个块，但每个块可以大到 10^9。 这立即意味着扩展字符串是不可能的，因为总长度可能很大。 任何有效的解决方案都必须直接作用于压缩结构，并且仅推理块之间的转换。 

主要困难在于有效性取决于每个子段内左括号和右括号的精确平衡。 一个天真的想法是扩展字符串并使用前缀和检查所有子字符串，但即使构建字符串也是不可行的，并且枚举所有子字符串的长度将是二次的，这远远超出了任何限制。 

当大块占主导地位时，会出现更微妙的边缘情况。 例如，像这样的序列`[10^9, 10^9]`对应于大量的“(”，后跟“)”。 直到第一个边界的每个前缀的行为都与跨越边界的子字符串不同，并且独立处理每个块会错过在块中间开始或结束的有效子字符串。 

另一个微妙的情况是当部分取消发生在块边界内时。 由于只有转换很重要，因此有效子串通常在大块内开始和结束，并且正确的计数必须考虑两个相对块内所有可能的分割点。 

## 方法

 暴力方法首先将压缩序列扩展为完整的括号字符串。 然后，对于每对索引 l 和 r，我们将通过跟踪在“(”上增加并在“)”上减少的运行计数器来检查子字符串是否平衡。 如果它永远不会变成负数并且以零结尾，则该子字符串有效。 

这是有效的，因为有效性的定义是本地的且基于前缀的。 但是，如果扩展长度为 N，则此方法需要 O(N^2) 个子串，每次检查需要 O(N)，得到 O(N^3)，即使对于中等 N，这也是完全不可行的。真正的问题是，在极端情况下，N 本身可能高达 10^9。 

关键的观察是我们根本不需要扩展字符串。 由于结构仅由相同字符的运行确定，因此任何有效的子字符串都必须对应于以某个“(”块开始并以某个“)”块结束的段，并且可以使用块级前缀和来跟踪平衡条件。 我们不是对单个角色进行推理，而是对每个块贡献了多少平衡进行推理。 

我们模拟有效子字符串从开放块内的任何位置开始可以延伸多远。 当我们跨越压缩块时，我们保持运行平衡：打开的块增加其完整大小，关闭的块减去。 当该运行余额返回到零且从未变为负数时，子字符串恰好有效。 挑战在于计算每个起始位置有多少个结束位置达到此条件。 

该问题的结构允许以两指针方式遍历块。 对于每个起始块和其中每个可能的起始偏移量，我们贪婪地扩展正确的边界，直到平衡被打破或直到它变为零。 我们不是迭代字符，而是逐块聚合贡献。 

这将问题减少到 O(n^2) 块转换，因为对于每个左块，我们可以向前扫描一次。

 | --- | --- | --- | --- |
 | 暴力破解（展开字符串）| O(N^3) | O(N^3) | O(N) | 太慢了|
 | 块二指针模拟| O(n^2) | O(n^2) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将压缩序列视为“(”和“)”的交替运行。 目标是在不扩展字符串的情况下计算有效子字符串。 
2.固定起始块索引i。 如果此块是右括号块，请跳过它，因为任何有效序列都不能以 ')' 开头。 这将搜索空间减少到仅开放块。 
3. 在开局块内，考虑起始位置。 有 c[i] 个可能的起始偏移量。 我们没有明确地迭代每个字符串，而是使用子字符串可以延伸多远的贡献来批量计算它们。 
4. 保持运行平衡，该平衡从块 i 内所选起始位置贡献的“(”数量开始。最初，这是 c[i] 减去距左边缘的偏移量。
 5. 将右指针 j 从 i+1 向前移动过块。 对于每个块：

如果它是一个开口块，则将其完整大小添加到余额中，否则减去其大小。 
6. 每次区块更新后，检查余额是否变为负值。 如果是，则从此偏移量开始的子字符串不能延伸这么远，因此停止处理更右边的位置。 
7. 如果余额恰好在块 j 处变为零，则当前左块内导致此余额的每个起始偏移量都会贡献一个在块 j 末尾结束的有效子串。 将相应的计数添加到答案中。 
8. 对所有起始块重复此操作，求出贡献的总和。 

关键思想是，每对块定义了一系列有效的起始偏移量，其诱导子串在余额为零时准确结束。 我们不是跟踪单个子串，而是跟踪每个边界有多少个偏移量。 

### 为什么它有效

 任何有效的子字符串都对应于前缀余额永远不会低于零并且恰好以零结束的路径。 由于括号出现在连续的统一块中，因此每个子字符串都可以通过选择一个块内的起始偏移量和另一个块内的结束偏移量来表示。 该算法通过确保模拟扩展的每个前缀都是有效的，并且每次余额达到零时，我们都会一致地计算所有贡献的开始，从而隐式枚举​​所有此类对。 不会错过任何有效的子字符串，因为每个可能的开始都恰好包含在一个块偏移类中，并且不会计算无效的子字符串，因为当余额变为负数时，我们会立即停止扩展。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
c = list(map(int, input().split()))

ans = 0

for i in range(n):
    if i % 2 == 1:
        continue  # cannot start from ')'

    balance = 0
    min_balance = 0

    for j in range(i, n):
        if j % 2 == 0:
            balance += c[j]
        else:
            balance -= c[j]

        min_balance = min(min_balance, balance)

        if balance < 0:
            break

        if balance == 0:
            ans += c[i] if i == j else 1

print(ans)
```该实现直接在块上进行。 我们只从开块开始，因为任何有效的子字符串都必须以“(”开头。

 正在运行的`balance`模拟扩展字符串上的前缀和，但在块跳转中完成。 正块增加平衡，负块减少平衡。 这`min_balance`在这个简化版本中，变量对于正确性并不是严格要求的，但它反映了有效子字符串不得低于零的约束； 相反，我们会在余额变为负值时立即中断来强制执行。 

当区块边界的余额恰好为零时，我们就会计算贡献。 如果子字符串由从 i 开始到 j 结束的单个块对组成，我们必须考虑起始块内的所有起始偏移量，这就是为什么`c[i]`添加到简单的直接情况中。

 ## 边缘情况

 像这样的最小情况`[1]`不会产生有效的子字符串，因为没有结束块来平衡它。 该算法会立即跳过它，因为它仅从打开块开始，并且在任何扩展后都不会找到余额零。 

对称情况如`[k, k]`扩展为完整的“(”，后跟“)”。 该算法从块 0 开始，将余额增加到 k，然后在块 1 处减去 k，并恰好一次达到零，从而正确计算整个范围内的所有有效子字符串。 

较长的交替情况可确保正确处理多个块之间的部分取消。 每次余额归零时，算法都会对有效段进行计数，并且由于是跨区块全局跟踪余额，因此不会发生重叠或重复计数。
