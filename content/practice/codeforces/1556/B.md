 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们交换相邻元素。 目标是重新排列数组，以便没有两个相邻元素共享相同的奇偶校验，这意味着我们需要偶数和奇数的交替模式。 

每次交换仅交换两个相邻的元素，因此移动元素的成本取决于它移动的距离。 任务是找到达到任何有效的交替奇偶校验排列所需的此类相邻交换的最小数量，或确定无法形成此类排列。 

影响解决方案的关键约束是大小：所有测试用例的元素总数最多为 100,000 个。 这排除了任何明确模拟交换或尝试安排排列的方法。 即使每个测试用例的 O(n²) 也会太慢，因为使用类似气泡的逻辑移动元素可能会退化为二次行为。 

当偶数和奇数的计数相差太大时，就会出现一个微妙的问题。 要存在交替数组，计数最多只能相差 1。 如果违反这一点，则无论交换如何，任何安排都不起作用。 例如，在`[2, 4, 6, 8, 1]`，有 4 个偶数和 1 个奇数，任何排列都会迫使至少有两个偶数相邻。 

另一种边缘情况是数组已经有效。 在这种情况下，答案为零，任何盲目移动元素的贪婪交换方法都可能错误地引入不必要的交换。 

## 方法

 一个蛮力的想法是模拟交换：重复扫描数组，每当相邻元素违反奇偶校验交替时就交换它们，并继续直到不再存在违规为止。 这本质上是将数组冒泡排序为有效的奇偶校验模式。 虽然正确，但在最坏的情况下可能需要 O(n²) 次交换，因为每个元素可能需要遍历整个数组。 

关键的观察结果是，问题不在于值，而在于奇偶类别的位置。 一旦我们确定了目标交替模式，无论是从偶数开始还是从奇数开始，我们只需要测量每个奇偶校验元素必须移动多远才能到达其指定的位置。 

如果我们固定起始奇偶校验，甚至在索引 0 处，那么所有偶数元素都必须占用索引 0、2、4 等。 将一组项目移动到一行中的目标位置所需的最小相邻交换次数是当前位置和目标位置（当两者都排序时）之间的绝对差之和。 这将问题简化为两个候选模式和简单的成本计算。 

我们计算两种有效起始配置的成本（如果可行），并取最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 相邻交换模拟| O(n²) | O(1) | O(1) | 太慢了|
 | 贪心位置匹配 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将数组分为偶值元素和奇值元素的索引。 

1. 计算偶数和奇数。 如果`abs(evens - odds) > 1`，返回 -1，因为不存在交替排列。 这是一个独立于交换权力的结构性约束。 
2. 构建两个列表：原始数组中偶数的位置和奇数的位置。 
3. 考虑偶数从索引 0 开始的情况。 

我们检查可行性：这需要`evens >= odds`。 如果没有，这个配置是不可能的。 
4. 通过匹配计算此配置的成本：

 偶数位置 → 目标槽位`[0, 2, 4, ...]`每个偶数元素按顺序分配到其相应的槽，然后对绝对差求和。 
5. 假设奇数从索引 0 开始，即赔率占据偶数索引，重复相同的计算。 
6. 返回有效配置中的最小成本。 

### 为什么它有效

 一旦奇偶校验分配固定，具有相同奇偶校验的元素就可以互换。 重要的只是它们最终占用的索引。 最小化相邻交换的最佳策略相当于最小化排序配对下索引空间中的总位移。 这将问题简化为线上最优分配的实例，其中排序的贪婪配对是最优的，因为交叉分配只会增加总距离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cost(positions, start_index):
    res = 0
    for i, pos in enumerate(positions):
        res += abs(pos - (start_index + 2 * i))
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    even_pos = []
    odd_pos = []

    for i, v in enumerate(a):
        if v % 2 == 0:
            even_pos.append(i)
        else:
            odd_pos.append(i)

    ev = len(even_pos)
    od = len(odd_pos)

    if abs(ev - od) > 1:
        print(-1)
        continue

    ans = float('inf')

    # try even starts at 0
    if ev >= od:
        ans = min(ans, cost(even_pos, 0))

    # try odd starts at 0
    if od >= ev:
        ans = min(ans, cost(odd_pos, 0))

    print(ans)
```该解决方案分离奇偶校验位置并使用辅助函数来计算将奇偶校验组与其目标索引对齐所需的交换次数。 这`cost`函数对当前位置和理想交替槽之间的贪婪匹配进行编码。 

一个常见的实现错误是混淆了哪个奇偶校验列表对应于哪个起始模式。 另一个微妙的问题是忘记了当计数相等时必须检查两种配置。

 ## 边缘情况

 对于`n = 1`，该数组始终有效，因为没有相邻对。 该算法正确地返回零，因为其中一种奇偶校验配置是非常可行的。 

对于奇偶校验计数完全平衡的阵列，将检查两个起始模式。 这可以防止在两者都可能时错过最佳安排，例如`[1, 2, 3, 4]`，其中偶数开始和奇数开始配置都可以产生具有不同成本的有效交替阵列。 

对于不可能的分布，例如`[2, 2, 2, 1]`，条件`abs(evens - odds) > 1`在任何成本计算之前立即拒绝该案例，避免强制交替布局的错误尝试。
