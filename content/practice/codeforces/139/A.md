 ## 解决方案
 ## 问题理解

 彼得有一本书`n`页。 从周一开始，他每周每天都会阅读固定页数。 输入按周一到周日的顺序给出了这七个每日阅读能力。 

我们需要确定彼得在哪一天完成这本书。 答案不是总天数，而是从`1`到`7`， 在哪里`1`指星期一和`7`指星期日。 

限制非常小。 页数最多为`1000`，并且每个日值也最多为`1000`。 即使是日复一日的直接模拟也完全足够快。 在最坏的情况下，Petr 每周只读一页，因此模拟可以运行大约`1000`天。 对于 2 秒的限制来说，这仍然是微不足道的。 

棘手的部分不是性能，而是正确处理停止条件。 

一个常见的错误是仅在完成一周后才检查剩余页数是否恰好为零。 考虑这个输入：```
1
1 0 0 0 0 0 0
```正确答案是`1`因为 Petr 周一马上就结束了。 如果不小心实施，每周循环一次，可能会意外地持续到下一周。 

当某些日子的阅读能力为零时，会发生另一种微妙的情况。```
2
1 0 0 0 0 0 0
```正确答案仍然是`1`。 Petr 在第一个星期一读第 1 页，然后在第二个星期一读第 2 页。 页面为零的日子仍必须处理，因为 Petr 不会跳过它们。 

当 Petr 恰好在一天结束时完成任务时，就会出现最后一个差一的陷阱。```
10
5 5 1 1 1 1 1
```答案是`2`， 不是`3`。 周二之后，剩余页数变为零，因此周二是收尾日。 

## 方法

 最直接的方法是每天模拟 Petr 的阅读过程。 我们反复迭代七个工作日，从剩余页数中减去 Petr 在当天可以阅读的页数。 一旦剩余数字变为零或负数，我们就返回当前工作日。 

这是有效的，因为问题中描述的过程本身是连续的。 Petr 按时间顺序阅读，从不跳过几天，因此准确模拟发生的情况自然会产生正确的结果。 

由于这本书最多`1000`页数，即使是最慢的阅读计划在可管理的迭代次数后仍然可以完成。 例如，如果 Petr 每个星期一只读取一页，而在所有其他日子读取零页，则模拟执行大约`7000`每日检查。 那是很小的。 

还有一个稍微干净一点的观察。 我们不需要明确地计算完整的周数。 我们只关心累计阅读页数达到或超过的第一天`n`。 这意味着在工作日进行一次重复遍历就足够了。 

蛮力方法和最优方法最终看起来非常相似，因为约束很小。 最佳版本就是最干净的模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(模拟天数) | O(1) | O(1) | 已接受 |
 | 最佳 | O(模拟天数) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取总页数`n`。 
2. 读取七个整数组成的数组，表示 Petr 从星期一到星期日读了多少页。 
3. 在工作日开始无限循环，因为时间表每周都会重复。 
4. 对于索引中的每个工作日`0`到`6`，减去当天的阅读量`n`。 
5. 减去后，检查是否`n <= 0`。 
6. 如果条件为真，则使用返回当前工作日数`index + 1`因为该问题使用从 1 开始的编号。 

这有效的原因是那一刻`n`就在 Petr 完成最后一页的那一刻，结果变得非积极。 前一天仍有一些页面未读。 

### 为什么它有效

 该算法保持一个简单的不变量：在处理一天之前，`n`等于剩余未读页数。 减去当天的阅读量后，`n`成为当天结束后剩余的未读页面。 

第一天去哪里`n <= 0`正是累积阅读页数至少达到原书大小的那一天。 由于日期是按时间顺序处理的，所以不可能更早的一天完成这本书。 这保证了返回的工作日是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    days = list(map(int, input().split()))

    while True:
        for i in range(7):
            n -= days[i]

            if n <= 0:
                print(i + 1)
                return

solve()
```该程序直接遵循算法中描述的模拟。 

这`while True`循环代表重复周。 在其内部，`for`循环按顺序迭代周一到周日。 

减去当天的阅读量后，我们立即检查这本书是否读完。 顺序很重要。 如果我们在减法之前检查，我们就会错误地将答案延迟一天。 

条件使用`n <= 0`而不是`n == 0`。 在最后一天，彼得读的页数可能比书中剩余的页数还要多。 例如，如果`3`剩余页数，今天的容量是`10`，剩余值变为`-7`，但结束的日子还是今天。 

输出使用`i + 1`因为 Python 数组是从 0 索引的，而问题中的工作日是从`1`到`7`。

 ## 边缘情况

 考虑 Petr 在第一天立即完成的情况。 

输入：```
1
1 0 0 0 0 0 0
```该算法从中减去星期一的值`n`， 制作`n = 0`。 自从`n <= 0`，它立即返回`1`。 这可以避免继续到另一天或另一周的常见错误。 

现在考虑一个包含许多零读数日的时间表。 

输入：```
2
1 0 0 0 0 0 0
```第一个星期一过后，只剩下一页。 即使周二到周日减去零，该算法仍然会处理。 下周一，剩余值变为零，算法正确返回`1`。 

Finally, consider a case where Petr reads more pages than remain.

 输入：```
3
10 0 0 0 0 0 0
```周一之后，剩余页面变为`-7`。 该算法仍然接受这一点，因为它检查`n <= 0`而不是`n == 0`。 正确答案是`1`因为彼得在周一的阅读课上完成了。
