 ## 解决方案
 ## 问题理解

 我们有一张长方形的纸，上面有尺寸$n \times m$。 我们要从这张纸上剪下$k$相同的方形贴纸，其中每个贴纸都是边长为正方形的$x$。 正方形必须完全包含在纸张中，并且不允许重叠。 

任务是确定最大可能的整数或实数值$x$这样至少$k$大小的正方形$x \times x$可以放在矩形内。 

关键的观察是对于任何固定边长$x$，我们可以放置的方块数量取决于每个维度上适合的方块数量。 水平方向我们可以适应$\lfloor n / x \rfloor$正方形，并且垂直我们可以拟合$\lfloor m / x \rfloor$平方，所以总和就是它们的乘积。 

限制条件$n, m \le 10^3$足够小，对于固定的情况，评估此函数是微不足道的$x$， 但$k \le 10^9$使得无法直接枚举放置计数的可能性。 答案不一定是整数，因为最佳正方形大小可以是小数。 

一种天真的方法是尝试所有可能的正方形大小$1$降低到非常小的增量，但这会失败，因为答案的连续精度高达$10^{-6}$。 甚至离散化为$10^{-6}$分辨率需要大约$10^6$检查，并且每项检查都是$O(1)$，这是边界，但考虑到更清晰的结构是不必要的。 

边缘情况出现时$k$非常大，迫使正方形尺寸变小。 例如，如果$n = m = 2$和$k = 3$， 然后$x = 1$有效是因为$2$正方形适合每行和每列，给出$4$总计，但任意$x > 1$减少下面的计数$3$。 另一个边缘情况是当$k = 1$，答案很简单$\min(n, m)$，因为一个正方形可以占据尽可能大的边。 

## 方法

 蛮力的想法是尝试所有可能的正方形边长$x$，计算有多少个正方形适合，并跟踪最大的有效值。 如果我们离散化$x$分成小步骤，例如$10^{-6}$，每项检查都需要计算$\lfloor n/x \rfloor \cdot \lfloor m/x \rfloor$，这是常数时间。 然而，这种离散化导致大约$10^6$候选人，每次评估都涉及浮点除法和地板运算。 虽然在某些情况下这可能会通过，但它是不必要的，并且在精度上仍然很脆弱。 

关键的结构观察是，拟合的方格数量相对于$x$。 如果给定尺寸$x$有效，那么任何较小的尺寸也有效，因为减小正方形尺寸只会增加沿每个维度适合的数量。 相反，如果$x$太大，进一步增加只会降低可行性。 这种单调行为使我们能够将问题视为连续的二分搜索$x$。 

我们定义一个谓词$f(x)$检查是否$\lfloor n/x \rfloor \cdot \lfloor m/x \rfloor \ge k$。 这个谓词是单调的，所以我们可以二分查找最大值$x$对于这一点来说，它仍然是正确的。 

搜索空间来自$0$到$\max(n, m)$。 二分搜索的每一步都会在恒定时间内评估谓词，给出足以满足以下条件的对数迭代次数：$10^{-6}$精确。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(10^6)$|$O(1)$| 太慢/不精确|
 | 二分查找 |$O(\log(\text{precision}))$|$O(1)$| 已接受 |

 ## 算法演练

 我们将问题重新表述为寻找最大的$x$这样至少$k$边长为正方形$x$合身。 

1. 定义一个函数`can(x)`计算有多少个正方形适合：$(n // x) * (m // x)$。 如果这个值至少是$k$， 然后$x$是可行的。 楼层划分捕获沿每个轴有多少个完整的正方形。 
2. 设置二分查找间隔`left = 0`和`right = max(n, m)`。 答案一定在这个范围内，因为比矩形大的正方形一次也装不下。 
3. 反复计算`mid = (left + right) / 2`并测试`can(mid)`。 
4.如果`can(mid)`是的，我们可以尝试增加正方形的大小，所以我们移动`left = mid`。 否则，我们减小尺寸`right = mid`。 
5. 继续直到间隔宽度低于$10^{-7}$，保证了所需误差范围内的正确性。 
6. 输出`left`作为最佳可行的近似值。 

### 为什么它有效

 功能$can(x)$是单调递减的$x$。 一旦某个尺寸变得不可行，所有更大的尺寸仍然不可行，因为增加$x$只能减少或维持适合的方格数量。 这种单调性保证了二分搜索永远不会跳过最优边界，并且最终的收敛点逼近最大可行$x$在要求的精度范围内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(n, m, k, x):
    return (n // x) * (m // x) >= k

def solve():
    n, m, k = map(int, input().split())

    # handle edge case: no squares fit unless x <= min(n, m)
    left, right = 0.0, float(max(n, m))

    for _ in range(60):
        mid = (left + right) / 2
        if mid == 0:
            left = mid
            continue
        if (n // mid) * (m // mid) >= k:
            left = mid
        else:
            right = mid

    print(left)

if __name__ == "__main__":
    solve()
```实现的核心是`can`逻辑，它直接编码每个维度上有多少个正方形。 二分搜索运行固定的迭代次数 (60)，这对于双精度收敛来说绰绰有余。 

一个微妙的点是避免除以零`mid`变得非常小。 实际上，循环会在问题出现之前收敛，但检查可确保数值安全。 另一个微妙之处是使用 60 次迭代而不是 epsilon 条件，这可以避免浮点不稳定。

 ## 边缘情况

 当$k = 1$，算法自然地向最大可行平方扩展，变成$\min(n, m)$。 二分搜索从零开始，并快速确认大中间值的可行性，直到收敛到真正的最大值。 

什么时候$k$非常大，除了那些接近零的值之外，几乎所有中间值的可行性检查都会变得错误。 搜索会缩小间隔，直到正方形尺寸变得足够小，使得两个楼层划分仍然产生足够的放置。 

什么时候$n = m$，对称性并没有简化逻辑，但却让可行性边界更加清晰。 该算法仍然可以正确收敛，因为无论对称性如何，单调性都得以保留。
