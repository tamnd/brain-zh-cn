 ## 问题理解

 给定一个凸多边形$n$顶点。 唯一允许的操作是在两个现有顶点之间绘制对角线。 每条对角线将一个多边形区域分成两个较小的区域。 目标是继续添加对角线，直到每个结果区域都是三角形，并且我们希望最小化使用的对角线数量。 

重新表述该任务的一个有用方法是我们对凸多边形进行三角测量。 每次切割都会增加碎片的数量，我们希望用尽可能少的切割达到完全分解为三角形的目的。 

输入尺寸较小，$n \le 100$，因此任何关于顶点的二次或三次推理都是完全安全的。 这立即表明答案可能是已知的封闭形式或简单的组合属性，而不是依赖于几何形状的状态的动态规划。 

一个微妙的点是，“沿对角线切割”意味着每次切割都是两个顶点之间的一条直线，并且单个对角线是唯一的操作。 交叉对角线没有限制，但在凸多边形中，最佳三角剖分无论如何都不需要交叉。 

除了最小的有效多边形之外，不存在棘手的极端情况。 为了$n = 4$，我们有一个四边形，一条对角线正好产生两个三角形。 对于较大的$n$，结构有规律地缩放。 

## 方法

 一种直接但过于字面的方法是通过重复选择对角线来模拟将多边形切割成三角形的过程。 在每一步中，我们可以尝试所有有效的对角线，应用一条，递归地求解所得的子多边形，并最小化切割次数。 

这种蛮力视图很快就变成了枚举三角测量的问题。 凸多边形有$n$顶点有加泰罗尼亚数的许多三角剖分，其增长大致如下$O(4^n / n^{3/2})$。 即使是为了$n = 50$，这已经远远超出了任何计算极限，因此穷举搜索是不可能的。 

关键的观察是，我们没有被要求优化不同的三角剖分，而只是计算任何有效三角剖分中需要多少对角线。 这消除了所有组合复杂性：凸面的每个三角剖分$n$-gon 使用相同数量的对角线。 

要了解原因，请考虑三角测量产生的结果。 一个凸$n$-gon 被分割成三角形，每个三角形有三个边。 在三角剖分中，每条添加的对角线都贡献一条内部边，最终的结构是一个平面图，其中所有面都是三角形。 

有一个标准的结构事实：凸面的任何三角剖分$n$-gon 总是准确地产生$n - 2$三角形。 由于原始多边形有$n$顶点，三角剖分总是将其分成$n - 2$三角形的脸。 每条对角线都会使面数恰好增加一个。 从1个面（原始多边形）开始，到达$n - 2$面孔需要准确$n - 3$削减。 

这使得答案独立于几何或策略。 完全三角化多边形的任何有效对角线切割序列必须精确地使用$n - 3$对角线。

 ## 算法演练

 1.读取整数$n$，表示凸多边形的顶点数。 
2. 认识到每次对角线切割都会将一个区域分成两部分，从而将区域数量恰好增加一。 
3. 从一个区域（原始多边形）开始。 
4. 完整的三角测量产生$n - 2$三角形区域。 
5. 每次切割都会使区域计数增加一，因此切割次数恰好是我们需要从 1 个区域到$n - 2$地区。 
6. 将答案计算为$n - 3$并输出它。 

### 为什么它有效

 不变量是凸多边形的平面细分中的面和切口之间的关系。 最初只有一张脸。 每个对角线插入都会将一个现有面准确地分成两部分，从而将面数增加一。 由于每个有效的三角测量必须准确地以$n - 2$三角形面，所需分割总数固定为$n - 3$，与对角线的选择方式无关。 任何有效的对角线插入序列都不能更改此计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
print(n - 3)
```该解决方案读取顶点数并直接应用推导公式。 无需模拟几何或维护任何结构，因为最终计数仅取决于任何三角剖分中顶点、三角形和对角线之间的不变关系。 

唯一需要注意的实现细节是剥离输入行，因为竞争性编程输入通常包括尾随换行符。

 ## 边缘情况

 对于$n = 4$，算法计算$4 - 3 = 1$。 四边形已经几乎被三角化，并且需要正好一条对角线，以匹配几何现实。 

对于较大的$n$， 例如$n = 5$，算法返回 2。如果我们明确地在五边形中绘制对角线，则任何有效的三角剖分都会准确地生成三个三角形，从而准确地生成两条对角线。 该公式正确匹配该结构，而不依赖于选择哪些对角线。 

对于最大情况$n = 100$，计算保持稳定和直接。 不存在误差累积或状态依赖性，因为该公式纯粹是算术并且源自不变的面计数。
