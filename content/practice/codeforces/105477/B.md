 ## 解决方案
 ## 问题理解

 我们被要求计算固定数量的分段可以形成多少个有效的“过山车”，其中每个分段水平移动一个单位，垂直向上或向下移动一个单位。 完整的旅程包括`2l`段，从地面开始，回到地面结束，并且在路径的任何前缀处都不会低于地面。 在所有这些有效路径中，我们只想要那些最大高度恰好为`h`。 

对此进行建模的一种便捷方法是将每个段视为格子路径中的一个步骤：“向上”步骤将高度增加 1，“向下”步骤将高度减少 1。约束转换为经典的 Dyck 路径样式条件：路径具有长度`2l`，从高度 0 开始和结束，永远不会为负数，并且精确地具有最大高度`h`。 

所以任务变成了计算半长的戴克式路径`l`有界高度约束等于`h`。 

输入尺寸允许`l`和`h`最多 200 个和最多 40000 个测试用例。 这立即排除了任何基于查询的动态编程`O(l^2)`州。 甚至`O(l^2)`一次可以，但重复几万次不行。 正确的方法必须预先计算所有答案`l ≤ 200`和`h ≤ 200`，然后在 O(1) 内回答每个查询。 

出现微妙的边缘情况时`h`大于给定的可能值`l`。 任何长度有效路径中的最大可能高度`2l`是`l`，所以任何查询`h > l`除非仔细解释，否则应该返回 0：实际上我们计算最大值恰好为`h`，所以如果`h > l`，答案是 0。另一个边缘情况是`h = 0`，这对于任何正数都是不可能的`l`，因为非平凡戴克路径必须至少上升到 1。 

一个幼稚的错误是计算所有高度 ≤ h 的 Dyck 路径，而不是精确计算 h。 这多算了； 问题是要求精确的最大高度，而不是有界高度。 

## 方法

 蛮力的想法是生成所有长度有效的平衡路径`2l`使用递归，跟踪当前高度和达到的最大高度。 每一步我们要么向上要么向下，但我们必须确保高度永远不会变成负值。 当我们达到长度时`2l`，我们检查是否回到 0 以及最大高度是否等于`h`。 这是正确的，但探索了大约加泰罗尼亚大小的状态空间，它的增长就像`O(4^l / l^{3/2})`。 即使是为了`l = 200`，这是不可能的。 

关键的观察结果是，这是一个经典的戴克路径枚举，对最大高度有额外的限制。 此类问题通常通过位置和高度的动态规划来处理，或者通过传输 DP 来更有效地处理，该传输 DP 计算高度由`h`。 一旦我们可以计算`F(l, h)`= 长度有效路径的数量`2l`保持在 height ≤ h 范围内，然后我们可以使用边界包含来导出精确高度的答案：具有最大值的路径`h`等于`F(l, h) - F(l, h-1)`。 

这种减少至关重要，因为“最大精确度 h”很难直接强制执行，而“绝不超过 h”在 DP 中自然会强制执行。 

然后我们预先计算`F(l, h)`为所有人`l ≤ 200`和`h ≤ 200`使用 2D DP，其中状态为`(i, j)`意思是达到高度的方法数`j`后`i`步数不低于 0 或以上`h`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^{2l}) | O(2^{2l}) | O(l) | 太慢了 |
 | 最佳DP | O(l^2) 预计算 + O(1) 每次查询 | O(l^2) | O(l^2) | 已接受 |

 ## 算法演练

 我们定义一个 DP 表，其中`dp[i][j]`是长度有效序列的数量`i`那端在高处`j`并且永远不要超过当前的高度限制。 

我们针对每个可能的高度限制单独计算`H`从 0 到 200。 

1.对于固定的最大允许高度`H`, 初始化`dp[0][0] = 1`。 这代表从地面开始的空路径。 
2.对于每一步索引`i`从 1 到`2l_max`,更新所有高度`j`在`[0, H]`。 
3. 来自州`(i-1, j)`，我们可以移动到`(i, j+1)`如果`j+1 ≤ H`，对应于上一步。 
4. 来自州`(i-1, j)`，我们可以移动到`(i, j-1)`如果`j-1 ≥ 0`，对应于向下的步骤。 仅当我们尚未到达地面时，此移动才有效。 
5. 填写DP后的值`dp[2l][0]`给出长度有效路径的数量`2l`永远不会超过高度`H`。 
6. 获取最大高度恰好为的路径`h`, 计算`dp_exact[l][h] = dp_at_most[l][h] - dp_at_most[l][h-1]`。 

这种减法起作用的原因是每条有效路径都有明确定义的最大高度。 统计最大值≤h的所有路径，包括最大值严格小于h的路径； 减去最大值 ≤ h−1 的那些，就可以准确地分离出最大值为 h 的那些。 

### 为什么它有效

 DP 定义了有效的前缀相关路径和有界网格中的转换序列之间的双射。 每条有效路径恰好对应于一个 DP 转换序列，并且在每一步都在本地强制执行高度约束。 因为每条路径都被精确计算一次`dp_at_most`，并且最大高度将所有有效路径的集合划分为不相交的类`{max = 0, max = 1, ..., max = l}`，减法步骤提取没有重叠的单个类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAX_L = 200

# dp_at_most[h][i][j] = ways for length i ending at height j with max height <= h
dp = [[[0] * (MAX_L + 1) for _ in range(2 * MAX_L + 1)] for _ in range(MAX_L + 1)]

dp[0][0][0] = 1

for h in range(1, MAX_L + 1):
    for i in range(2 * MAX_L + 1):
        for j in range(h + 1):
            val = dp[h - 1][i][j]
            if not val:
                continue
            dp[h][i][j] = (dp[h][i][j] + val) % MOD
            if i + 1 <= 2 * MAX_L:
                if j + 1 <= h:
                    dp[h][i + 1][j + 1] = (dp[h][i + 1][j + 1] + val) % MOD
                if j - 1 >= 0:
                    dp[h][i + 1][j - 1] = (dp[h][i + 1][j - 1] + val) % MOD

t = int(input())
for _ in range(t):
    l, h = map(int, input().split())
    if h > l:
        print(0)
        continue
    if h == 0:
        print(0)
        continue

    ans = (dp[h][2 * l][0] - dp[h - 1][2 * l][0]) % MOD
    print(ans)
```该实现在最大高度上构建分层 DP。 每层`h`重复使用前一个`h-1`，因此我们有效地允许上限逐渐增加的路径。 最终答案使用两层之间的差异，隔离精确的最大高度。 

这里的一个常见错误是忘记 DP 必须同时执行两个边界条件：非负高度和上限`h`。 另一个是混合“长度维度”和“高度维度”更新，当路径多次重新访问中间高度时，这会默默地破坏正确性。 

## 工作示例

 考虑输入`l = 2, h = 2`。 我们正在计算长度为 4 的路径，这些路径从 0 开始和结束，永远不会变为负数，并且到达高度恰好为 2。有效路径只有一条：向上、向上、向下、向下。 

| 步骤| dp 高度 0 | dp 高度 1 | dp 高度 2 |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 0 | 1 | 0 |
 | 2 | 1 | 0 | 1 |
 | 3 | 0 | 2 | 0 |
 | 4 | 1 | 0 | 1 |

 由此看来，`dp_at_most[2][4][0] = 2`， 和`dp_at_most[1][4][0] = 1`，所以确切的高度 2 是`2 - 1 = 1`。 

现在考虑`l = 3, h = 2`。 我们计算长度为 6 的路径，最大值正好为 2。DP 包括所有小于 2 的路径，然后减去那些小于 1 的路径。 

这演示了约束的分离：DP 层控制上限，而减法则隔离确切的最大值。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(高 * 长 * 长) | 我们计算每个高度最多 200 的分层 DP，每个更新 O(L * H) 状态 |
 | 空间| O(高 * 长 * 长) | DP 层的高度、长度和位置存储 |

 这些约束允许预先计算大约 800 万个状态，这完全在限制范围内。 使用预先计算的表在恒定时间内回答每个查询。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7
    MAX_L = 10  # reduced for testing

    dp = [[[0] * (MAX_L + 1) for _ in range(2 * MAX_L + 1)] for _ in range(MAX_L + 1)]
    dp[0][0][0] = 1

    for h in range(1, MAX_L + 1):
        for i in range(2 * MAX_L + 1):
            for j in range(h + 1):
                val = dp[h - 1][i][j]
                if not val:
                    continue
                dp[h][i][j] = (dp[h][i][j] + val) % MOD
                if i + 1 <= 2 * MAX_L:
                    if j + 1 <= h:
                        dp[h][i + 1][j + 1] = (dp[h][i + 1][j + 1] + val) % MOD
                    if j - 1 >= 0:
                        dp[h][i + 1][j - 1] = (dp[h][i + 1][j - 1] + val) % MOD

    def solve_case(l, h):
        if h > l or h == 0:
            return 0
        return (dp[h][2 * l][0] - dp[h - 1][2 * l][0]) % MOD

    out = []
    for line in inp.getvalue().splitlines()[1:]:
        l, h = map(int, line.split())
        out.append(str(solve_case(l, h)))
    return "\n".join(out)

# provided samples

# custom cases
assert run("1\n1 1\n") == "1", "minimum valid mountain"
assert run("1\n1 2\n") == "0", "height impossible"
assert run("1\n2 1\n") == "1", "single peak case"
assert run("1\n3 3\n") == "0", "height too large for length"

 ## 边缘情况

 当`h > l`，该高度的 DP 层仍然存在于简单的实现中，但没有长度的路径`2l`可以在保持有效的情况下在物理上达到该高度。 该算法通过立即返回 0 来处理此问题，从而避免不必要的计算。 

什么时候`h = 1`，仅考虑从不超过高度 1 的路径，这意味着结构会塌陷为交替的上下模式。 DP 仅正确计算那些返回地面的序列，而无需堆叠两个连续的 up。 

什么时候`l = 1`，唯一可能的有效路径是“向上然后向下”，并且仅`h = 1`是有效的。 减法`dp[1] - dp[0]`干净地隔离这个单一配置，确认最大高度分解的正确性。
