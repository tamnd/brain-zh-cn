 ## 解决方案
 ## 问题理解

 每个测试用例给出一个非负整数，代表一个完整的 128 位 IPv6 地址。 IPv6 地址正好有 8 个 16 位部分，因此第一项工作是将整数写入正好 32 个十六进制数字，并将这些数字分成八组，每组四个。 然后写入每个组，不带前导零。 

在标准化之后，连续运行的零值组可以被替换为`::`，但前提是运行至少包含两个组。 压缩最多可以使用一次。 在所有法律表示中，我们首先想要留下最少明确部分的表示，然后是字典顺序上最小的表示。 官方问题指定最多 128 位输入、直到 EOF 的多个测试用例以及 1 秒、256 MB 的限制。 

128 位界限在这里特别友好，因为 IPv6 地址始终恰好是八组。 没有大小为 (n) 的依赖于输入的数组，也不需要复杂的数据结构。 即使检查每个可能的零间隔的方法也只需要考虑 (8 \cdot 9 / 2 = 36) 个间隔。 Python 的任意精度整数还消除了标准整数类型小于 128 位的语言中可能出现的溢出问题。 

第一个微妙的情况是单个零组。 例如，整数`340282366920938463463374607431768145920`代表`ffff:ffff:ffff:ffff:ffff:ffff:ffff:0`。 正确的输出是`ffff:ffff:ffff:ffff:ffff:ffff:ffff:0`。 粗心的实现可能会将最后的零压缩为`::`，生产`ffff:ffff:ffff:ffff:ffff:ffff:ffff::`，但明确禁止单个省略部分。 

第二种微妙的情况是根本不包含非零组的地址。 用于输入`0`, 八个归一化组都是`0`，正确的输出是`::`。 将全零地址视为普通前缀和后缀可能会意外生成空字符串或无效的单个冒号。 

第三种微妙情况是多个零游程具有相同的最大长度。 考虑八组`1:0:0:2:0:0:3:4`。 两个都`1::2:0:0:3:4`和`1:0:0:2::3:4`压缩两个零组并且对于剩余部分的数量同样好。 正确答案是`1:0:0:2::3:4`，因为它按字典顺序更小。 在这种情况下，简单地选择第一个最长运行的解决方案将失败。 

最后，开头或结尾的零运行需要特殊的字符串构造。 为了`1`，标准化组是`0:0:0:0:0:0:0:1`，所以答案是`::1`。 为了`0`，压缩运行的两边都是空的，所以答案正是`::`， 不是`:`。 

## 方法

 直接的暴力解决方案是可能的，因为只有八组。 将它们归一化后，我们可以考虑每个区间`[l, r]`其组均为零。 最多有36个间隔，长度为1的间隔被丢弃。 对于每个剩余的间隔，我们构造通过将该间隔替换为而获得的地址`::`，然后根据所需的顺序比较候选者。 如果没有有效间隔，则未压缩的标准化地址就是答案。 

对于实际问题来说，这种蛮力已经足够快了。 在最坏的情况下，有 36 个可能的间隔，并且构建一个候选最多涉及 8 个组，因此每个测试用例最多有 (36 × 8 = 288) 个组级操作，除了短字符串操作之外。 在给定的固定八组表示下，没有有意义的输入大小使得该方法变得太慢。 地址格式本身可以防止变长问题中常见的 (O(n^2)) 爆炸。 

我们可以通过观察第一个优化标准的含义来进一步简化搜索。 压缩长度 (k) 的零游程精确删除 (k) 个显式组并将其替换为 1`::`。 因此，通过选择最长的零游程，可以精确地最小化剩余部分的数量。 长度为 1 的游程永远不符合资格，因此只有长度至少为 2 的游程才重要。 

一旦知道最大游程长度，每个候选者都会使用相同数量的剩余组，并删除相同数量的字符。 唯一剩下的标准是字典顺序。 对于等长的零游程，选择后面的游程总是按字典顺序更小。 在两个候选者不同的第一个位置，压缩较早运行的候选者包含`:`，而留下该零组显式的候选者包含`0`。 自从`0`按字典顺序小于`:`，较晚的一方获胜。 我们可以直接使用这个事实，或者更稳健地为所有最大长度运行构建候选者并采用 Python`min`。 

最佳实现扫描八个组一次以找到最长的零游程，仅为该最大长度的游程构建候选者，并采用字典顺序最小的一个。 渐近复杂度仍然是(O(8))，简单来说就是(O(1))，但推理直接反映了优化准则，而不是枚举不相关的区间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(8²) | O(8) | 已接受 |
 | 最佳| O(8) | O(8) | 已接受 |

 ## 算法演练

 1. 将输入的整数转换为正好 32 位的十六进制。 填充是必要的，因为前导零位仍然是 128 位地址的一部分。 将结果分成八组，每组四个十六进制数字，并从每组中删除前导零，留下`"0"`当一个群完全为零时。 
2. 从左到右扫描八个标准化组。 每当找到零组时，继续直到零游程结束并记录其起始位置和长度。 保留找到的最大长度，忽略少于两组的运行，因为 RFC 式压缩无法表示单个省略的部分。 
3. 如果不存在长度至少为 2 的游程，则用冒号连接八个标准化组并返回该地址。 没有合法使用`::`在这种情况下。 
4. 对于长度等于最大长度的每个零游程，通过将该完整游程替换为`::`。 运行前和运行后的组保持不变。 仅考虑最大长度游程就足够了，因为每个较短的游程都会留下更明确的部分。 
5. 按字典顺序比较候选者并返回最小的一个。 这可以处理开始、中间和结束时的运行，而不需要单独的平局打破逻辑。 
6. 如果所选运行涵盖所有八组，则构造会产生`::`。 如果从第一组开始，结果的形式为`::suffix`; 如果它在最后一组结束，则具有以下形式`prefix::`。 这些情况在连接两侧时明确处理。 

为什么有效：标准化后，每个合法缩写的唯一区别在于连续的零游程被替换为`::`。 长度 (k) 的游程留下 (8-k) 个显式部分，因此每个最佳缩写必须使用最长的合法零游程。 在相同最大长度的游轮中，构建所有候选者并选择字典顺序最小的候选者精确地实现了最终的抢七规则。 每个构建的候选者都代表相同的原始八组，因为`::`正好代表省略的零组。 因此，所选候选满足所有三个要求：合法压缩、剩余部分的最小可能数量以及这些选择中的最小词典表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def make_candidate(groups, l, r):
    left = groups[:l]
    right = groups[r + 1:]

    # Two empty fields joined by ':' produce '::'.
    return ":".join(left + ["", ""] + right)

def abbreviate(x):
    # Exactly 32 hexadecimal digits correspond to eight 16-bit groups.
    h = f"{x:032x}"
    groups = []

    for i in range(0, 32, 4):
        part = h[i:i + 4]
        value = part.lstrip("0")
        groups.append(value if value else "0")

    best_len = 0
    runs = []

    i = 0
    while i < 8:
        if groups[i] != "0":
            i += 1
            continue

        j = i
        while j < 8 and groups[j] == "0":
            j += 1

        length = j - i

        if length >= 2:
            if length > best_len:
                best_len = length
                runs = [(i, j - 1)]
            elif length == best_len:
                runs.append((i, j - 1))

        i = j

    if best_len == 0:
        return ":".join(groups)

    answer = None

    for l, r in runs:
        candidate = make_candidate(groups, l, r)
        if answer is None or candidate < answer:
            answer = candidate

    return answer

def solve():
    out = []

    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue

        x = int(line)
        out.append(abbreviate(x))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```转换`f"{x:032x}"`是关键的表示步骤。 32 的宽度不是装饰性的：一个整数，例如`1`必须成为`00000000000000000000000000000001`，否则 8 个 16 位边界将会丢失。 

每个四字符块都转换为其规范化的十六进制形式`lstrip("0")`。 回退到`"0"`是必要的，因为从`"0000"`产生一个空字符串。 

零运行扫描使用`i`作为第一个未处理的组并前进`j`直到当前运行结束。 环境`i = j`跳过整个运行，因此八组中的每一组仅被检查恒定次数。 长度为 1 的游程被故意忽略。 

候选构建器使用两个空字符串，而不是尝试将前缀和后缀与特殊情况连接起来。 例如，`["1", "", "", "2"]`加入了`:`变成`1::2`， 尽管`["", "", "1"]`变成`::1`和`["1", "", ""]`变成`1::`。 如果所有组都被压缩，`["", ""]`变成`::`。 

Python 整数具有任意精度，因此读取小数输入`int`直接处理从零到 (2^{128}-1) 的整个范围。 不需要手动十进制到二进制转换或溢出处理。 

候选比较有意委托给 Python 的正常字符串排序。 由于此时考虑的所有候选者都具有相同的最佳零游程长度，因此没有候选者可以获胜，因为它在第一个优化标准中更短。 字符串比较只是解决最终的字典顺序问题。 

## 工作示例

 ### 示例 1

 第一个样本整数是`42540578239448488099419523072699400193`。 其标准化的十六进制组是`2001:470:f003:0:0:0:0:1`。 

| 我| 集团| 当前零运行| 最佳长度| 最佳跑步 |
 | ---| ---| ---| ---| ---|
 | 0 |`2001`| 无 | 0 | 无 |
 | 1 |`470`| 无 | 0 | 无 |
 | 2 |`f003`| 无 | 0 | 无 |
 | 3 |`0`| 3..6，长度 4 | 4 | 3..6 | 3..6
 | 7 |`1`| 无 | 4 | 3..6 | 3..6

 从组 3 到组 6 有一个最大游程。将这四个零组替换为`::`给出`2001:470:f003::1`。 

这个例子直接演示了主要的优化。 四个零组的运行仅留下四个显式组，而压缩任何较短的运行将留下更多部分。 

### 示例 2

 用于输入`1`，固定宽度的十六进制表示为`00000000000000000000000000000001`。 

| 我| 集团| 当前零运行| 最佳长度| 最佳跑步 |
 | ---| ---| ---| ---| ---|
 | 0 |`0`| 0..6，长度 7 | 7 | 0..6 | 0..6
 | 7 |`1`| 无 | 7 | 0..6 | 0..6

 零运行到达地址的开头并在最后一个之前立即结束`1`。 候选构建器看到左侧空并生成`::1`。 

该跟踪确认在搜索压缩间隔时前导零组必须保留为地址的一部分。 它们不会作为整个整数的数字前导零被丢弃。 

### 示例 3

 用于输入`0`，所有八个归一化组均为零。 

| 我| 集团| 当前零运行| 最佳长度| 最佳跑步 |
 | ---| ---| ---| ---| ---|
 | 0 |`0`| 0..7，长度 8 | 8 | 0..7 | 0..7

 最大游程覆盖整个地址，因此候选仅包含`::`。 

这种情况验证前缀和后缀都为空的边界。 在这种情况下，完整的 IPv6 地址由压缩标记表示，两边都没有任何内容。

import sys
import io

def make_candidate(groups, l, r):
    return ":".join(groups[:l] + ["", ""] + groups[r + 1:])

def abbreviate(x):
    h = f"{x:032x}"
    groups = []

    for i in range(0, 32, 4):
        part = h[i:i + 4]
        part = part.lstrip("0")
        groups.append(part if part else "0")

    best_len = 0
    runs = []

    i = 0
    while i < 8:
        if groups[i] != "0":
            i += 1
            continue

        j = i
        while j < 8 and groups[j] == "0":
            j += 1

        length = j - i

        if length >= 2:
            if length > best_len:
                best_len = length
                runs = [(i, j - 1)]
            elif length == best_len:
                runs.append((i, j - 1))

        i = j

    if best_len == 0:
        return ":".join(groups)

    return min(make_candidate(groups, l, r) for l, r in runs)

def solve():
    out = []
    for line in sys.stdin:
        line = line.strip()
        if line:
            out.append(abbreviate(int(line)))
    return "\n".join(out)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve() + "\n"
    finally:
        sys.stdin = old_stdin

# Provided samples
assert run("42540578239448488099419523072699400193\n") == \
       "2001:470:f003::1\n", "sample 1"

assert run("1\n") == "::1\n", "sample 2"

assert run("0\n") == "::\n", "sample 3"

# Maximum 128-bit value, containing no zero groups.
assert run("340282366920938463463374607431768211455\n") == \
       "ffff:ffff:ffff:ffff:ffff:ffff:ffff:ffff\n", \
       "maximum value"

# A single zero group must not be compressed.
assert run("340282366920938463463374607431768145920\n") == \
       "ffff:ffff:ffff:ffff:ffff:ffff:ffff:0\n", \
       "single zero group"

# Two equally long zero runs. The later one is lexicographically smaller.
tie_value = (
    (1 << 112) +
    (2 << 64) +
    (3 << 16) +
    4
)
assert run(str(tie_value) + "\n") == \
       "1:0:0:2::3:4\n", \
       "lexicographic tie"

# No compressible zero run.
no_run_value = (
    (1 << 112) +
    (2 << 96) +
    (3 << 80) +
    (4 << 64) +
    (5 << 48) +
    (6 << 32) +
    (7 << 16) +
    8
)

       "1:2:3:4:5:6:7:8\n", \

 ## 边缘情况

 对于全零地址，输入为`0`。 固定宽度转换产生八个`0000`组，标准化为八个`"0"`字符串。 扫描仪从位置 0 到 7 找到长度为 8 的一个运行，因此它严格优于所有其他可能的压缩。 候选人在任何一方都没有团体，并且成为`::`。 该算法永远不会产生`:`因为候选构建器在加入之前插入了两个空字段。 

对于末尾的单个零部分，输入`340282366920938463463374607431768145920`对应于`ffff:ffff:ffff:ffff:ffff:ffff:ffff:0`。 扫描仪看到七个非零组，后面跟着一个长度为 1 的零游程。 由于游程长度低于 2，因此被完全拒绝。 后备是标准化地址本身，给出`ffff:ffff:ffff:ffff:ffff:ffff:ffff:0`。 这是捕获压缩每个零游程而不检查其长度的实现的边界。 

对于相同的最大运行次数，测试中使用的值表示`1:0:0:2:0:0:3:4`。 扫描仪在位置 1 到 2 处记录长度为 2 的游程，并在位置 4 到 5 处记录另一个长度为 2 的游程。两者都满足主要优化标准。 生成的候选者是`1::2:0:0:3:4`和`1:0:0:2::3:4`。 比较它们到达公共前缀之后的第一个压缩位置`1:`。 第一个候选人有`:`，而第二个有`0`， 和`0`按字典顺序较小，因此选择第二个候选者。 

对于没有可压缩运行的地址，测试值表示`1:2:3:4:5:6:7:8`。 每个组都是非零的，因此扫描器永远不会记录有效的运行，并且`best_len`保持为零。 该算法跳过候选构建并简单地加入标准化组，产生`1:2:3:4:5:6:7:8`。 这也可以防止意外发生`::`当根本没有零部分时被插入。 

对于输入`1`，标准化地址包含七个零组，后跟`1`。 扫描仪将位置 0 到 6 记录为长度为 7 的游程，这是唯一的最佳值。 压缩的左边是空的，右边是`1`，所以构造的字符串是`::1`。 这验证了前导运行边界，并确认了为什么必须首先将原始整数填充到所有 32 个十六进制数字。
