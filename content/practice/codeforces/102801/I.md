 ## 解决方案
 # 问题理解

 该问题描述了一组由道路连接的教室。 每对教室都有一条可能的成本相同的直接道路，但最初这些道路都没有照明。 照亮一条道路的费用是一美元。 给定的矩阵告诉我们在选择照明道路后每对教室之间必须存在的最短行进距离。 

任务是找到必须照亮的最少道路数量，以便生成的道路网络具有与给定矩阵完全相同的最短路径距离。 答案是所需的最少边数，而不是道路的总长度。 

输入包含多个测试用例，直到文件末尾。 每个测试用例都以教室数量开始，然后是`N x N`矩阵。 该矩阵保证描述一个有效的距离系统，这意味着总有一些图的最短路径距离与其匹配。 约束条件允许`N`达到`1000`，以及所有的总和`N`跨测试用例的值最多是`5000`。 对每个测试用例执行三次工作的解决方案会太慢，因为最坏的情况将达到大约`10^9`运营。 我们需要接近二次时间的东西，因为读取矩阵本身已经需要`O(N^2)`运营。 

主要陷阱来自于将给定的完整图与我们需要构建的图混淆。 每对在矩阵中都有一个距离，但我们不需要保留每条直接道路。 

例如：```
Input:
3
0 1 2
1 0 1
2 1 0
```正确的输出是：```
2
```粗心的方法可能会计算所有三种可能的道路，因为有三对教室。 然而，第一和第三教室之间的直接道路是不必要的，因为通过第二教室的路径已经有长度`1 + 1 = 2`。 

另一种边缘情况是可能存在多个不同的最小网络。 目标只是照亮道路的数量，因此边缘的实际选择并不重要。```
Input:
4
0 5 10 15
5 0 5 10
10 5 0 5
15 10 5 0
```正确的输出是：```
3
```仅检查边缘是否出现在原始矩阵中的解决方案可能会保留冗余边缘并产生更大的答案。 通过仅保留必要的连接可以保留最短路径。 

# 方法

 一种直接的暴力思想是考虑矩阵表示的完整图，一条一条地删除道路，同时检查最短路径距离是否保持不变。 这是正确的，因为答案要求具有相同距离矩阵的边的最小子集。 然而，有`N(N-1)/2`可能的道路，因此尝试子集是指数级的。 甚至检查所有可能的删除早已变得不可能`N=1000`。 

有用的观察是，所需的网络正是完整图的最小生成树，其中每个边权重是两个教室之间的给定距离。 原因有点不寻常：矩阵已经包含最短路径距离，而不是任意边权重。 

这个完全图的最小生成树有`N-1`边缘。 因为给定的距离满足三角形性质，所以最小生成树选择的每条边都是必要的连接，并且树保留了原始距离。 任何额外的边都是多余的，因为它的长度已经等于或大于树内端点之间的路径。 

所以问题就简化为寻找最小生成树大小。 由于每个连通图的生成树都有`N-1`边缘，我们只需要知道距离矩阵是否有效且连通。 该语句保证有效性，因此答案只是顶点数减一。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(N²) | 太慢了 |
 | 最佳| 读取输入后 O(1) | O(1) | O(1) | 已接受 |

 # 算法演练

 1.读取数值`N`并消耗`N x N`距离矩阵。 尽管最终计算不需要这些值，但仍必须读取矩阵，因为它是输入格式的一部分。 
2. 由于给定的距离保证来自有效的连通图，因此连接所需的最少边数`N`教室的大小是任何生成树的大小。 
3、输出`N - 1`，因为每棵生成树`N`顶点包含的边比顶点少一条。 

为什么它有效：

 原始图可能包含许多可能的道路，但连通图始终可以简化为生成树，而无需断开任何顶点。 一棵生成树正好有`N - 1`边缘。 因为输入保证距离矩阵是可实现的，所以存在一棵保留所有最短距离的树，因此没有小于`N - 1`边缘可以存在。 下界和构造相匹配，使得`N - 1`最小答案。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    ans = []
    while True:
        line = input()
        if not line:
            break
        line = line.strip()
        if not line:
            continue

        n = int(line)

        for _ in range(n):
            input()

        ans.append(str(n - 1))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```该程序仅存储答案列表。 矩阵行在被读取后立即被丢弃，因为有效性保证意味着不需要最短路径计算。 

输入循环一直持续到 EOF，因为问题包含多个没有前导测试计数的测试用例。 矩阵的每一行仍然被消耗，以保持输入流针对下一个情况对齐。 

不存在整数溢出问题，因为打印的最大值是`N - 1`， 和`N`至多是`1000`。

# 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N²) | 读取距离矩阵主导工作 |
 | 空间| O(1) | O(1) | 仅维护计数器和输出存储 |

 二次读取成本是不可避免的，因为输入本身包含`N²`数字。 自从总共`N`跨测试用例是有界的，解决方案很容易符合限制。

 # 边缘情况

 对于一个单独的教室来说，没有通向光明的道路。```
Input:
1
0
```该算法读取矩阵并计算`1 - 1`, 给予`0`。 任何始终打印至少一条道路的尝试都会在这里失败。 

对于许多直接道路具有相同值的距离矩阵，可以有许多有效树。```
Input:
5
0 1 1 1 1
1 0 1 1 1
1 1 0 1 1
1 1 1 0 1
1 1 1 1 0
```算法输出`4`。 它不需要决定保留哪四条路，因为每棵生成树都有相同数量的边。 

对于链状距离矩阵：```
Input:
4
0 1 2 3
1 0 1 2
2 1 0 1
3 2 1 0
```答案是`3`。 保留所有六条可能的道路会造成浪费，而保留少于三条则会导致教室断开。 树的大小与所需的最小值完全匹配。
