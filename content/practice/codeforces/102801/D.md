 ## 解决方案
 ## 问题理解

 我们有一群玩家试图夺取移动的王冠。 表冠不会静止不动：它从高处开始`0`，向上移动直到高度`H`，然后向下移动直到高度`0`，并永远重复这个动作。 到达目的地后，如果皇冠高度最大，玩家可以立即抢到皇冠`h`。 否则，玩家需要等待，直到王冠降得足够远。 

输入通过两个值描述每个玩家。`x_i`是玩家到达目的地的时间，并且`c_i`是游戏系统额外添加的网络延迟。 如果一名球员当时实际摘取了桂冠`t`，游戏将玩家的抢夺时间记录为`t + c_i`。 获胜者是记录时间最短的玩家，如果多名玩家记录时间相同，则索引最小的玩家获胜。 

挑战并不在于模拟表冠运动的每一秒。 玩家人数可达`2 * 10^5`一个测试用例中，最多可以有 20 个测试用例。 检查每个玩家的许多未来时刻的算法可以轻松达到数十亿次操作。 我们需要对每个玩家的第一个可能的抓取时刻进行恒定的时间计算。 

表冠的运动周期非常小，因为`H`最多为 300。整个周期持续`2H`秒。 这一小界限意味着我们可以直接推理一个周期，而不是维持长时间的模拟。 

棘手的案件来自运动的确切边界。 

例如，如果玩家恰好在王冠达到最大高度时到达：```
1
1 2 5
5
10
```皇冠处于高度`5`在某个时间`5`，大于`h = 2`，所以玩家必须等待。 下一个可接受的时刻是当表冠下降到一定高度时`2`，在某个时间`8`。 记录的时间是`18`，所以答案是：```
1
```一个粗心的解决方案，只检查表冠是否在下方`h`向下移动后可能会错误地将峰值视为可接受的点。 

另一个边界情况是当玩家恰好到达皇冠处于可接受的高度时：```
1
1 2 5
2
10
```时`2`，冠高正好是`2`，并且允许相等。 玩家立即抓取，所以答案是：```
1
```使用严格比较的解决方案，例如`< h`会错误地延迟玩家。 

最后一个边缘情况是`h = H`:```
1
1 5 5
100
7
```皇冠永远不会高于`5`，所以每次到达都会立即成功。 答案是：```
1
```任何假设总是有等待期的方法在这里都会失败。 

## 方法

 直接的解决方案是模拟王冠的运动并询问每个玩家何时可以抓住它。 由于王冠不断变化，我们需要确定未来第一个时刻，其高度对于每个玩家来说都是可以接受的。 如果我们逐秒模拟，单个玩家可能需要最多`2H`检查，虽然很小，但是为每个玩家执行此操作仍然可以得到`O(nH)`运营。 和`n = 200000`和`H = 300`，每个测试用例大约需要 6000 万次检查，这在 Python 中已经很不舒服并且没有必要。 

关键的观察结果是冠部遵循重复的三角波。 我们只需要知道球员在一个时期内的位置即可。 周期长度为`2H`。 在每个周期中，表冠从时间上来说是可以接受的`0`到`h`当上升和从时间开始`2H-h`到`2H`跌倒时。 

到达时间`x`， 让`r = x mod (2H)`。 如果`r`已经处于这些可接受的间隔之一中，玩家立即抓住。 否则，玩家位于中间部分的某处，皇冠太高。 下一个可接受的时刻始终是高度下降点`h`，这发生在循环位置`2H-h`。 因此，等待时间就是距离`r`到`2H-h`。 

这将整个问题简化为计算每个玩家一个公式。 蛮力之所以有效，是因为王冠有一个可预测的周期，但会失败，因为它在许多玩家身上重复了太多次。 周期性结构让我们完全跳过模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nH) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个玩家，计算第一次物理抢夺时间。 让`period = 2H`和`r = x_i mod period`。 价值`r`告诉我们皇冠在当前周期内的位置。 
2. 检查表冠是否已够到。 发生这种情况时`r <= h`或者`r >= 2H - h`。 在这种情况下，玩家的物理抓取时间就是`x_i`。 
3.如果皇冠太高，玩家必须等到皇冠落到高度`h`。 下一个这样的时刻是在循环位置`2H - h`，因此物理抓取时间变为：```
x_i + (2H - h - r)
```1.添加播放器延迟`c_i`获取记录的抓取时间。 与当前最佳答案进行比较。 如果该玩家获胜较早，或者记录时间相等而该玩家的指数较小，则替换答案。 

### 为什么它有效

 表冠的运动会重复一次`2H`秒，因此每种可能的情况完全由到达时间在该周期内的余数决定。 唯一可以抓取的时间是冠高最大的两个区间`h`。 如果玩家在这些间隔之外，则下一个可到达时刻必须是下一个可接受间隔的第一个点，这正是高度的下降交叉点`h`。 由于该算法会计算每个玩家最早可能的抢夺时刻，然后应用精确的平局规则，因此所选玩家一定会成为获胜者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, h, H = map(int, input().split())
        x = list(map(int, input().split()))
        c = list(map(int, input().split()))

        period = 2 * H
        best_time = None
        best_id = None

        for i in range(n):
            r = x[i] % period

            if r <= h or r >= period - h:
                grab = x[i]
            else:
                grab = x[i] + (period - h - r)

            total = grab + c[i]

            if best_time is None or total < best_time or (total == best_time and i < best_id):
                best_time = total
                best_id = i

        ans.append(str(best_id + 1))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案独立处理玩家，因为一个玩家的等待时间不会影响另一玩家的皇冠交互。 变量`r`存储当前表冠周期内的位置，避免任何运动模拟。 

条件`r <= h or r >= period - h`包括两个端点，因为当冠高正好是时，玩家可以抓住`h`。 缺少相等性会在边界情况下产生错误的答案。 

当冠太高时，公式`period - h - r`总是积极的。 结果是下降侧到达高度的确切剩余时间`h`。 

该比较还仔细处理关系。 Python数组是从零索引的，但问题编号是从1开始的，因此仅在打印时存储的索引才会加1。

 ## 边缘情况

 当玩家恰好到达王冠运动的最高点时，剩余的就是`H`。 如果`h < H`，这是在不可到达的中间区间内。 例如：```
1
1 2 5
5
10
```余数为`5`，下一个可到达的位置是`8`，所以物理抓取时间是`8`。 该算法达到相同的结果，因为`5`至多都不是`2`也不至少`8`。 

当球员恰好到达皇冠高度时`h`，立即允许抓取。 为了：```
1
1 2 5
2
10
```余数是`2`，满足`r <= h`。 该算法保留了到达时间，而不是增加不必要的等待。 

什么时候`h = H`，任何可能的冠高都是可以接受的。 为了：```
1
1 5 5
100
7
```期间是`10`，并且条件总是成功，因为每个余数最多是`5`或者至少`5`。 玩家根据需要立即抓取。
