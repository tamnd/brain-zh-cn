 ## 解决方案
 ## 问题理解

 该问题定义了正整数的变换。 对于一个号码`x`，取其十进制表示形式的每个后缀，将所有这些后缀值相乘，并减少乘积模`x + 1`。 这个结果是`f(x)`。 然后我们反复申请`f`，任务是添加第一个`m`这个过程产生的价值。 

例如，当当前值为`1023`，后缀是`3`,`23`,`23`， 和`1023`，所以下一个值是这些数字模的乘积`1024`。 

输入值很大：起始数和迭代次数都可以大到`10^9`。 直接模拟`m`步骤是不可能的，因为单个测试用例可能需要十亿次函数评估。 该解决方案必须利用函数的属性而不是函数的大小`m`。 

关键的观察结果是`f(x)`始终在范围内`[0, x]`，因为它是模余数`x + 1`。 如果该值没有改变，则序列已达到固定点。 否则它会严格减少。 由于非负整数的严格递减序列不能永远持续下去，因此每个起始值最终都会达到一个固定点。 

在某些情况下，粗心的实施仍然可能会失败。 如果`x`是一位数字，唯一的后缀是数字本身，所以结果是`x % (x + 1) = x`。 对于输入：```
3 4
```序列是`3, 3, 3, 3`，所以答案是`12`。 不断尝试永远减少数量的实现将永远不会终止。 

以零结尾的值是另一个容易犯的错误。 例如：```
10 3
```后缀是`0`和`10`，所以产品为零并且`f(10)=0`。 顺序是`0, 0, 0`，给出答案`0`。 忽略零后缀的代码可能会产生不正确的非零值。 

第三种情况是起始值经过多次归约已经是固定点。 例如，第二个样本最终达到稳定值。 该算法必须停止模拟并将剩余计数乘以该固定值，而不是执行不必要的迭代。 

## 方法

 暴力解决方案遵循字面定义。 对于每一个`m`所请求的项，它计算小数后缀，将它们相乘，应用模运算，然后移至下一个值。 这是正确的，因为它完全遵循递归。 

然而，这种方法取决于`m`， 和`m`可以是`10^9`。 即使有一项评价`f`非常小，每个测​​试用例 10 亿次评估远远超出了允许的时间。 

有用的特性是生成的序列是单调的。 每一个应用`f`返回一个介于`0`和当前值。 该值无法减小的唯一原因是它已经是一个固定点。 这彻底改变了问题。 而不是执行所有`m`转换，我们只需要模拟直到序列稳定。 在那之后，每个剩余的项都是相同的，因此答案的其余部分可以通过乘法相加。 

蛮力法之所以有效，是因为递归很容易评估，但当迭代次数很大时，就会失败。 序列不可能永远减少的观察结果让我们用短收敛过程代替无界模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m * d) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(k * d) | O(1) | O(1) | 已接受 |

 这里`d`是当前值的位数，并且`k`是到达固定点之前递减的步数。 

## 算法演练

 1. 计算当前值`f(current)`并将新值添加到答案中。 第一个生成项是`f(n)`，不是原来的`n`，因此转换必须在添加之前发生。 
2. 当值发生变化并且仍然有请求的项时，继续应用该函数。 每个成功的更改都会移动到一个严格较小的整数，因此该过程最终必须停止。 
3. 当找到一个固定点时，剩余的每个生成值都是相同的数字。 将该值乘以剩余项数相加。 
4. 输出累加和。 

为什么它有效：

 生成值的顺序是`a1=f(n), a2=f(a1), ...`。 对于每一个积极的`x`,`f(x)`是一个模数`x+1`结果，所以`0 <= f(x) <= x`。 如果`f(x) != x`， 然后`f(x) < x`。 因此序列减少直到某个值`p`满足`f(p)=p`。 从那一刻起，申请`f`永远不会改变该值。 该算法精确计算递减前缀，然后计算常量后缀，因此所需总和中的每个项都包含一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def apply_f(x):
    if x == 0:
        return 0

    mod = x + 1
    prod = 1
    p = 10

    while p <= x * 10:
        prod = (prod * (x % p)) % mod
        p *= 10

    return prod

def solve_case(n, m):
    ans = 0
    cur = n

    while m > 0:
        nxt = apply_f(cur)
        ans += nxt
        m -= 1
        cur = nxt

        if cur == apply_f(cur):
            ans += cur * m
            break

    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(solve_case(n, m)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```这`apply_f`函数直接实现定义。 该循环生成 10 的幂并使用余数运算提取后缀。 乘法减少模数`x + 1`在每一步之后，因为只有余数很重要，这使得中间值很小。 

主循环不使用`m`作为迭代次数。 它只会遵循该序列，直到出现固定点。 在检测到下一个值相同后，它会立即添加所有剩余的副本。 

边界情况`x = 0`单独处理，因为原始定义以正整数开始，但迭代可以达到零。 立即归零可以防止不必要的发电。 

Python 整数不会溢出，这很有用，因为在某些情况下最终的总和可能大于 64 位有符号范围。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k * d) | 每个非固定转换都会对小数后缀求值一次。 |
 | 空间| O(1) | O(1) | 仅存储当前值和累积答案。 |

 重要的是，运行时间取决于减少的数量，而不是`m`。 由于序列严格递减直至稳定，因此对于给定的限制，迭代次数足够小。

 ## 边缘情况

 对于一位数，例如：```
3 4
```后缀列表仅包含`3`。 该产品是`3`，模数是`3 % 4`，这仍然是`3`。 该算法检测到下一个值等于当前值并立即添加剩余项。 

对于以零结尾的数字：```
10 3
```后缀是`0`和`10`。 他们的乘积为零，因此第一个生成的值是`0`。 后面的每个应用程序也会返回零，因为该函数接收到零。 对零的特殊处理使这种情况正确终止。 

对于大量迭代，该算法从不尝试执行所有迭代`m`运营。 一旦达到固定点，剩余的贡献将通过乘法计算。 这是取决于不可能界限的解决方案之间的差异`10^9`迭代和仅遵循短递减链的迭代。
