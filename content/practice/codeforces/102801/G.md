 ## 解决方案
 # 问题理解

 Halli Galli 是一个关于几个玩家一张一张地揭开水果牌的模拟问题。 玩家循环行动，因此在最后一个玩家轮流后，第一个玩家再次开始。 每个玩家只保留他们最新翻开的牌，因为新牌覆盖了前一张牌。 

每张亮出的牌后，我们都会检查所有可见的牌。 对于苹果、香蕉、葡萄和梨中的每种水果类型，我们计算当前可见的该类型水果的数量。 如果某种类型的水果恰好有五个，则该类型的铃声会被按下一次。 答案是所有回合中按铃的总数。 最初的声明定义了最多 100 个测试用例，每个用例最多 100 个回合，最多 6 个玩家。 

小限制表明这主要是一个实现和模拟问题。 即使在每次转动后从头开始检查每个水果的数量也是很便宜的。 水果类型只有四种，因此直接模拟每轮只需要恒定的工作量。 具有不必要的大型结构或复杂预处理的解决方案正在解决比给定问题更难的问题。 

错误的主要原因是正确处理替换规则。 玩家不会永远添加牌。 当他们亮出一张新卡时，他们的旧卡就会消失。 

例如：```
1
2 1
A 5
A 5
```正确的输出是：```
2
```第一轮后，可见的卡片包含五个苹果，因此铃响一次。 第二回合后，旧卡将被新苹果卡取代，而不是添加到其上面。 还有五个苹果，所以铃声再次响起。 如果不小心保留每张打出的牌，就会数出十个苹果并产生错误的结果。 

另一种极端情况是几种水果类型同时达到五种。```
1
3 3
A 5
B 5
G 5
```正确的输出是：```
3
```每种水果类型独立地贡献一次按铃。 仅检查是否有任何水果达到五个而不是计算所有匹配类型会失去这些额外的推动力。 

当玩家没有之前的牌时，就会出现最后的边界情况。```
1
1 6
P 1
```正确的输出是：```
0
```第一回合必须只添加新卡。 该球员的位置上没有任何东西可以移除。 

## 方法

 暴力方法是存储所有当前可见的卡片，模拟每个回合，并在每个回合后扫描每个玩家的卡片以重建四个水果总数。 这是正确的，因为游戏状态完全由当前可见的卡牌描述。 最多六名玩家，四种水果，即使是这种直接的方法在这里也足够快了。 

可以更普遍地看待同样的想法。 可见状态仅在轮到玩家的位置发生变化。 当该玩家亮出一张牌时，一张旧牌可能会消失并出现一张新牌。 每次移动后重新计算所有内容是不必要的，因为大部分状态保持不变。 

关键的观察是我们只需要当前可见的每个水果的总数。 当玩家更换牌时，我们可以从旧牌中减去水果，并添加新牌中的水果。 水果总数始终代表当前的棋盘状态，因此每回合后我们只需要进行四次比较即可决定铃响多少次。 

暴力破解之所以有效，是因为玩家数量很少，但增量更新方法直接匹配游戏的结构。 它减少了从重复扫描所有玩家到更新一张牌和检查四个计数器的工作。

 ## 算法演练

 1. 存储每个玩家当前的牌。 最初，每个玩家都没有牌。 
2. 保留四个计数器，代表每种类型可见水果的数量。 这些计数器是决定铃声是否响起所需的完整信息。 
3. 对于每个回合，通过使用回合索引对玩家数量取模来确定哪个玩家正在行动。 
4. 如果该玩家已经拥有一张牌，则从相应的水果计数器中删除其水果数量。 玩家翻开新卡后，旧卡将不再可见。 
5. 读取新卡牌，将其存储为玩家当前的卡牌，并将其水果数量添加到匹配的水果计数器中。 
6. 检查四个水果柜台。 每个等于 5 的计数器都会在答案中加一，因为每种水果类型都是独立计算的。 
7. 处理完所有回合后，输出累积的铃推力。 

为什么它有效：

 不变的是，在每个处理回合之后，四个水果计数器与所有玩家当前卡上显示的水果完全匹配。 最初两者都是空的。 当玩家更换牌时，移除旧牌并添加新牌会将计数器更新为新的可见状态。 由于铃声条件仅取决于这四个总数，因此每次更新后检查它们都会准确给出规则所需的推送次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    index = {'A': 0, 'B': 1, 'G': 2, 'P': 3}

    for _ in range(t):
        n, k = map(int, input().split())

        cards = [None] * k
        counts = [0] * 4
        total = 0

        for turn in range(n):
            ch, x = input().split()
            x = int(x)

            player = turn % k

            if cards[player] is not None:
                old_ch, old_x = cards[player]
                counts[index[old_ch]] -= old_x

            cards[player] = (ch, x)
            counts[index[ch]] += x

            for value in counts:
                if value == 5:
                    total += 1

        ans.append(str(total))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`cards`数组存储每个玩家最新的卡牌。 它的索引是玩家编号，因此在更新之前找到要删除的卡牌需要恒定的时间。 

这`counts`数组包含每个水果的当前可见数量。 从水果字符到数组索引的映射避免了重复的条件检查，并使每次更新保持恒定的时间。 

操作顺序很重要。 在添加新卡之前必须先删除之前的卡，因为新卡会取代旧卡。 检查响铃状态仅在两次操作之后发生，因为游戏会在回合结束后判断完整的可见状态。 

Python 中不存在整数溢出的风险，因为最大圈数很小。 答案是每轮最多按四次铃，所以它仍然很小。

 ## 边缘情况

 处理替换情况是因为算法只为每个玩家存储一张牌。 为了：```
1
2 1
A 5
A 5
```第一回合添加了五个苹果，答案就变成了一个。 第二回合移除旧的五个苹果，添加新的五个苹果，并再添加一次按铃。 最终答案是两个。 

多种水果的情况是通过检查所有四个计数器来处理的，而不是在找到一个匹配后停止。 为了：```
1
3 3
A 5
B 5
G 5
```苹果、香蕉和葡萄的柜台变成了五个。 每个计数器分别做出贡献，给出的答案为三。 

第一张牌的情况是通过在移除任何东西之前检查玩家是否已经拥有一张牌来处理的。 为了：```
1
1 6
P 1
```玩家之前没有牌，因此算法仅添加一个梨并正确报告零铃推送。
