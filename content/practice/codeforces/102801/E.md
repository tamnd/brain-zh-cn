 ## 解决方案
 ## 问题理解

 问题问向量是否`B`可以从初始向量得到`A`通过重复应用两个允许的移动：将当前矢量顺时针旋转 90 度，或添加固定矢量`C`到当前向量。 旋转和添加可以以任何顺序混合并使用任意次数。 任务是确定这样的操作序列是否存在。 

所有向量的坐标可以大到`10^8`以绝对值表示。 这排除了基于操作数量的任何模拟，因为所需的添加数量可能非常大，并且序列长度没有上限。 该解决方案必须使用运算的代数结构并在恒定时间内完成。 

主要隐藏的困难是轮换操作改变了未来添加的方向。 一个简单的方法，只检查是否`B - A`是的倍数`C`错过了旋转允许新的运动方向的情况。 

第一个边缘情况是当`C`是零向量。 例如：```
Input
0 0
1 1
0 0
```答案是：```
NO
```无论执行多少次旋转，零向量都保持为零，因此唯一可到达的向量是`A`。 一种除以长度的方法`C`在这里会失败，因为没有有效的除数。 

另一个边缘情况是目标可能需要在添加任何内容之前旋转起始向量。 例如：```
Input
1 0
0 -1
0 0
```答案是：```
YES
```旋转`(1, 0)`顺时针给出`(0, -1)`。 仅检查原始位置添加内容的方法会错误地拒绝此操作。 

第三种边缘情况是当所需的移动仅由于旋转的副本而成为可能时`C`取消或合并。 例如：```
Input
0 0
1 0
0 1
```答案是：```
YES
```向量`(1,0)`可以通过添加`(0,1)`在坐标系效果的三个顺时针旋转之后，因为旋转的加法创建了所有垂直方向。 仅检查原始的倍数`C`会失败的。 

## 方法

 直接的强力解决方案将尝试每种可能的旋转和添加顺序。 这个想法的问题在于没有有意义的停止点。 一个序列可以包含任意数量的加法，并且搜索所有可能的操作顺序呈指数增长。 即使将搜索限制为固定数量的操作也是不合理的。 

有用的观察是旋转是周期性的。 顺时针旋转四次将使矢量返回到其原始方向。 所有操作完成后，得到初始向量`A`只有四种可能的最终形式：```
A
R(A)
R^2(A)
R^3(A)
```在哪里`R`是顺时针旋转90度。 

考虑轮换后，添加的内容也更容易理解。 每添加一个`C`稍后可能会轮换，因此所有添加的总贡献是以下整数组合：```
C
R(C)
R^2(C)
R^3(C)
```后两个只是前两个的负数，因此这与由 生成的格子相同`C`和`R(C)`。 

对于每个可能的最终方向`A`，我们只需要检查之间的差异`B`该方向属于该晶格。 

让：```
C = (x, y)
R(C) = (y, -x)
```一个向量`(u, v)`如果存在整数则位于该格子内`p`和`q`这样：```
p * (x, y) + q * (y, -x) = (u, v)
```该系统的矩阵很特殊，因为它的平方是标量矩阵：```
[x  y] [x  y]   [x²+y²  0]
[y -x] [y -x] = [0      x²+y²]
```这给出了系数：```
p = (x*u + y*v) / (x² + y²)
q = (y*u - x*v) / (x² + y²)
```剩下的唯一一件事是检查两个分子是否可以被整除`x² + y²`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 无界、指数搜索 | O(1) | O(1) | 太慢了 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取三个向量`A`,`B`， 和`C`。 将坐标存储为整数，因为所有计算都可以精确完成，无需浮点运算。 
2.如果`C`是`(0, 0)`，检查四种可能的旋转`A`。 只能进行轮换，因为添加没有任何作用。 
3. 计算`x² + y²`为了`C = (x, y)`。 该值是两个晶格基向量的行列式幅值。 它也是用于恢复整数系数的分母。 
4. 尝试所有四种可能的最终旋转`A`。 对于每一个，计算差异向量`D = B - rotated_A`。 
5. 检查是否`D`可以写成以下的整数组合`C`及其顺时针旋转。 两个必需的可分性检查是：```
x*D.x + y*D.y
y*D.x - x*D.y
```两者都必须能被整除`x² + y²`。 

1. 如果任何旋转通过了点阵测试，则打印`YES`。 如果四个都失败，则打印`NO`。 

为什么它有效：每个有效的操作序列都可以在概念上重新排列为最终的循环`A`加上旋转版本的总和`C`。 旋转只有四种可能的状态，并且旋转的可能总和`C`向量恰好形成由下式生成的整数格`C`和`R(C)`。 该算法检查每个可能的旋转状态并使用该晶格的确切隶属条件，因此它接受每个可达向量并拒绝每个不可达向量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def rotate(v):
    x, y = v
    return (y, -x)

def possible(a, b, c):
    cx, cy = c

    if cx == 0 and cy == 0:
        cur = a
        for _ in range(4):
            if cur == b:
                return True
            cur = rotate(cur)
        return False

    den = cx * cx + cy * cy

    cur = a
    for _ in range(4):
        dx = b[0] - cur[0]
        dy = b[1] - cur[1]

        p_num = cx * dx + cy * dy
        q_num = cy * dx - cx * dy

        if p_num % den == 0 and q_num % den == 0:
            return True

        cur = rotate(cur)

    return False

def solve():
    a = tuple(map(int, input().split()))
    b = tuple(map(int, input().split()))
    c = tuple(map(int, input().split()))

    print("YES" if possible(a, b, c) else "NO")

if __name__ == "__main__":
    solve()
```这`rotate`函数直接实现顺时针四分之一圈。 应用四次将返回原始向量，这就是主循环只需要四次迭代的原因。 

零向量的情况是单独处理的，因为格子分母变为零。 什么时候`C`为零，唯一可用的操作是旋转，因此检查四个方向就足够了。 

对于非零`C`，变量`den`总是积极的。 可整除性检查避免了浮点精度问题，并且可以正确处理大坐标，因为 Python 整数具有任意精度。 

两种表达方式`p_num`和`q_num`来自求解二乘二线性系统。 它们必须均分，因为每个晶格方向的使用次数必须是整数。

 ## 边缘情况

 当`C`为零，算法永远不会进入点阵计算。 为了：```
0 0
1 1
0 0
```的四次旋转`(0,0)`都是`(0,0)`， 所以`(1,1)`无法到达，算法返回`NO`。 

当旋转一个`A`如果需要，四个状态检查直接处理它。 为了：```
1 0
0 -1
0 0
```第一次检查失败，因为向量不同，但第二次旋转产生`(0,-1)`，匹配`B`。 

当答案取决于组合旋转加法时，晶格测试可以捕获它。 为了：```
0 0
1 0
0 1
```生成的方向是`(0,1)`和`(1,0)`通过额外的轮换可以获得他们的底片。 所需的运动在晶格内部，因此算法返回`YES`。
