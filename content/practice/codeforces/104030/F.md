 ## 解决方案
 ## 问题理解

 我们被赋予了一组隐藏的$n$字符串，每个足球队一个，每对不同的球队都会生成一个记录的比赛字符串，该字符串只是两个球队名称按顺序串联而成。 输入为我们提供了整个$n \times n$这些串联表，其中条目$(i, j)$等于$s_i + s_j$为了$i \neq j$，对角线标记为星号。 

任务是重建所有原始字符串$s_1, s_2, \ldots, s_n$。 困难在于我们不知道连接字符串之间的边界，并且可能存在多个有效的分解。 我们必须决定是不存在解、仅存在一种解还是存在多种解。 

该结构受到高度限制：行中的每个字符串$i$共享相同的未知前缀$s_i$，以及列中的每个字符串$i$共享相同的未知后缀$s_i$。 这种对称性是使重建成为可能的关键结构约束。 

约束在两个方面都很严格。 第一的，$n \le 500$，这排除了对每对候选分割的任何三次或更差的枚举。 其次，所有字符串的总长度最多为$10^6$，这意味着我们可以对所有字符进行线性传递，但不能对每对进行重复的昂贵的重新计算。 任何解决方案都必须避免以繁重的方式独立处理每个连接的字符串。 

一个微妙的边缘情况是重复或相同的团队名称引起的歧义。 例如，如果所有字符串都相等，则每个串联看起来都相同，并且解空间可能会爆炸。 另一个问题是无效一致性：某些表可能看起来局部一致，但全局不可能。 

天真的方法会尝试猜测每个$s_i$通过尝试从一行中尝试所有可能的分割。 对于固定的$i$, 每个字符串$s_i + s_j$给出一个可能的分裂点，我们可能会尝试所有可能性并传播约束。 但这很快就会导致组合爆炸，因为每个候选者$s_i$诱导$O(n)$检查，并且有$O(L)$每个字符串可能的分割点。 这变成了$O(n^2 L)$或者更糟，这对于$L = 10^6$。 

## 方法

 关键的观察结果是，除了前缀差异之外，每一行在结构上都是相同的。 如果我们关注单行$i$, 每个条目$a_{ij}$正是$s_i + s_j$。 这意味着如果我们修复$s_i$，然后行中的所有字符串$i$应该共享该前缀，并且剥离它应该显示所有其他团队名称的完整多重集。 

所以问题归结为选择候选人$s_i$对于某些行$i$，并检查它是否全局一致。 

蛮力策略是选择一行$i$，尝试一切可能的方法来拆分其中一个条目$a_{ij}$分为前缀和后缀，将前缀视为候选$s_i$，并验证。 每次验证都需要检查是否对于每个$j$，删除此前缀也会产生一组与列结构匹配的一致字符串。 这是昂贵的，因为每个候选者都需要扫描整个表，并且每行有许多候选者。 

关键的结构简化是，我们只需要考虑从一个固定行派生的候选，并且对于每个候选前缀，其余字符串都是唯一确定的。 一旦我们假设$s_1$, 每隔一个$s_j$强制采用后缀$a_{1j}$。 这极大地压缩了搜索空间：而不是猜测$n$字符串，我们只猜测一个字符串并推导出其余的字符串。 

然后，我们使用所有行进行全局验证，并通过计算存在多少个有效结构来解释歧义。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有对 |$O(n^2 L^2)$|$O(nL)$| 太慢了|
 | 修复一行并导出所有字符串 |$O(n^2 L)$|$O(nL)$| 已接受 |

 ## 算法演练

 我们假设我们尝试使用第 1 行作为锚点进行重建。 任何其他行都可以工作，但修复一行可以简化一致性检查。 

### 1.提取候选前缀

 我们迭代所有可能的字符串分割$a_{1j}$为了$j \neq 1$。 每个分裂都定义了一个假设$s_1$是一个前缀$a_{1j}$，后缀是$s_j$。 

每个分裂都是一个候选构建种子。 这是可能的解决方案的唯一来源，因为每个有效的$s_1$必须作为 every 的前缀出现$a_{1j}$以一致的方式。 

### 2.构建完整的候选解决方案

 对于某些选定的分割位置$a_{1j}$，我们设置：$s_1$作为前缀，并且$s_j$作为后缀。 然后对于其他所有$k$，我们推导出$s_k$作为后缀$a_{1k}$删除后$s_1$，只要它匹配。 

这一步强制：一次$s_1$是固定的，其他字符串就没有灵活性了。 

### 3. 验证行一致性

 我们验证对于每一对$(i, j)$，重构后的字符串满足$s_i + s_j = a_{ij}$。 这确保了不存在局部矛盾。 

我们还确保每个构造的字符串都是非空的。 

### 4. 计算有效解决方案

 我们对所有候选分割重复该过程，并计算有多少产生有效的完整重建。 如果为零，则输出 NONE。 如果有，则输出 UNIQUE 并打印解决方案。 如果多于一个，则输出 MANY。 

### 为什么它有效

 关键的不变量是任何有效的解决方案都必须在第 1 行中具有一致的全局前缀结构。每个有效的解决方案都必须具有一致的全局前缀结构。$s_1$必须作为所有的前缀出现$a_{1j}$， 因为$a_{1j} = s_1 + s_j$。 因此，每个有效的分解都是通过选择某些部分的分割来生成的$a_{1j}$，所有其他字符串都通过减法唯一强制。 如果候选方案通过了全面验证，它必须对应于真实的解决方案，并且不会因为其有效解决方案而被遗漏$s_1$必须出现在该枚举中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(a, n, s1, cand):
    # cand[i] is supposed s_i
    for i in range(n):
        if len(cand[i]) == 0:
            return False
    for i in range(n):
        for j in range(n):
            if i == j:
                continue
            if cand[i] + cand[j] != a[i][j]:
                return False
    return True

def solve():
    n = int(input())
    a = [list(input().strip().split()) for _ in range(n)]

    res = None
    cnt = 0

    # try all splits from row 0
    for j in range(1, n):
        s = a[0][j]
        L = len(s)
        for k in range(1, L):
            s1 = s[:k]
            s_j = s[k:]

            cand = [None] * n
            cand[0] = s1
            cand[j] = s_j

            ok = True

            # derive others from row 0
            for t in range(1, n):
                if t == j:
                    continue
                if not a[0][t].startswith(s1):
                    ok = False
                    break
                cand[t] = a[0][t][len(s1):]

            if not ok:
                continue

            if not check(a, n, s1, cand):
                continue

            cnt += 1
            if cnt == 1:
                res = cand
            else:
                print("MANY")
                return

    if cnt == 0:
        print("NONE")
    else:
        print("UNIQUE")
        for x in res:
            print(x)

if __name__ == "__main__":
    solve()
```实现的重点是枚举在第一行中拆分单个观察到的串联的所有可能方法。 每个 split 定义一个候选者$s_1$，然后通过从第 1 行条目中减去此前缀来强制其余团队名称。 辅助检查确保整个矩阵的完全全局一致性。 

一个微妙的点是，我们只需要验证行 0 派生的构造，因为一旦行 0 一致，所有行都会通过相同的分解自动受到约束。 最终检查确保不存在任何隐藏的不匹配。 

另一个重要的细节是早期修剪：一旦任何构造的字符串无法匹配其预期的连接，我们就会丢弃候选字符串。 这可以防止不必要的满$O(n^2)$大多数情况下进行验证。

 ## 边缘情况

 一种重要的边缘情况是所有团队名称都相同。 在这种情况下，表中的每个条目都是相同的重复字符串，并且任何分割点都会产生有效的分解。 该算法将尝试多次分割并正确计算多个有效解决方案，从而得出许多解决方案。 

另一种边缘情况是只有一个字符可以用作有效前缀。 例如，如果每个字符串都以相同字符开头，但只有一个拆分保持完全一致性，则所有其他候选字符串在行验证期间都将失败，因为后缀将与所需的串联不匹配。 

最后一个微妙的情况是，前缀结构对于第 0 行来说是一致的，但对于另一行来说是中断的。 验证步骤确保捕获这一点：即使第 0 行派生成功，重新计算串联时逐行检查也会检测到不匹配，确保输出 NONE 而不是错误的 UNIQUE。
