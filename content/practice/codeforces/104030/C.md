 ## 解决方案
 ## 问题理解

 我们得到了一系列按顺序排列的 n 个讲座。 每个讲座要么有咖啡机，要么没有。 学生在第一堂课之前开始时没有咖啡杯，并且在每堂课期间她必须只喝一杯咖啡才能保持清醒。 

一个关键的限制是咖啡可以在讲座之间携带，但在任何时候她总共最多只能拿两杯。 在有机器的讲座中可以免费获得咖啡，并且只要不超过容量限制，任何未使用的杯子都可以带到以后的讲座中。 

任务是确定她可以按顺序参加的最大讲座数量，同时在她选择参加的每次讲座开始时仍然至少有一个可用的咖啡杯。 

输入是一个二进制字符串，其中每个字符描述该讲座位置是否存在咖啡机。 贪婪或调度解释是很自然的：我们正在选择类似前缀的进程，但如果可以更好地利用有限的承载能力，我们可能会策略性地跳过讲座。 

高达 100000 的约束立即排除了对每个位置携带的杯子的所有状态的任何指数子集模拟或动态编程。 任何解决方案都必须是线性或近线性的，因为预计 O(n log n) 或 O(n)。 

一些很容易被忽略的边缘情况：

 如果根本没有咖啡机，例如输入 0000，则答案为 1。只有当您认为没有咖啡就不可能在第一步之后开始时，您才能参加第一堂课，因此实际上您必须依赖于不满足的第一个位置，除非有机器存在。 

如果机器很密集，比如 111111，你可能会认为答案是 n，但这仍然受到每个讲座只需要一杯的事实的限制，额外的容量被浪费了。 

如果机器稀疏，比如 1000001，那么关键的困难是决定如何仅使用两个携带的杯子来弥补长的差距。 

尝试模拟每次讲座使用或存储咖啡杯的所有可能方式的简单方法将会失败，因为状态不仅取决于位置，还取决于携带的杯子数量，并且分支在 n 个位置上加倍。 

## 方法

 强力解释将模拟每次讲座中的每一个可能的决定：要么喝自带的咖啡，要么在机器旁喝咖啡并决定是否储存它。 每个州都会跟踪当前位置和持有的杯子数量，最多为 0、1 或 2。 

在每个状态中，转换分支基于我们是否在机器讲座中拿起咖啡以及我们是否消耗存储的杯子。 即使状态空间很小，如果直接模拟，n 个步骤的分支会导致指数数量的路径，因为有关何时消费或存储咖啡的决策会影响未来的可行性。 

关键的观察是我们永远不会从任意复杂的存储决策模式中受益。 该系统受到一个事实的限制：在不遇到机器的情况下最多可以支持两个未来的讲座。 这暗示了一种贪婪的解释：我们应该将咖啡机视为“补充缓冲容量”的机会，并利用该缓冲来弥补差距。 

我们可以将问题重新表述为维持最多两个可用消耗的小缓冲区。 每堂课消耗一个单元。 当我们访问一台机器时，我们可以增加可用缓冲区，但不能超过两个。 最优策略是线性扫描、贪婪消耗和受控补充。 

蛮力之所以有效，是因为它对所有可能的缓冲区管理决策进行了建模，但当 n 变大时，它就会失败。 只有当前缓冲区大小很重要的观察结果使我们能够将问题简化为跟踪每个位置的单个整数状态。

 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 太慢了|
 | 最优贪心模拟 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们模拟按顺序浏览讲座，同时跟踪我们当前有多少咖啡杯。 设该值为`cup`，根据是否可以开始第一讲进行初始化。 

我们还保持不变式`cup`始终在 0 和 2 之间（含 0 和 2）。 

1. 初始化`cup = 0`和一个柜台`ans = 0`。 计数器代表我们成功参加了多少次讲座。 
2. 在处理讲座之前，请检查我们是否至少有一个可用的杯子。 如果`cup == 0`，只有当当前的讲座有咖啡机时我们才能继续，因为否则我们无法生产一杯咖啡来度过本次讲座。 如果有一台机器，我们立即从中消耗一个隐含的杯子，因此我们将其视为在同一步骤中提供和消耗。 这允许我们继续并设置`cup = 0`消费后。 
3.如果`cup > 0`，我们只需消耗一杯来参加讲座并减量`cup`1.
 4. 消费后，如果当前讲座有咖啡机，我们将额外获得一杯咖啡。 然后我们盖帽`cup`2点，因为我们不能携带超过两个杯子。 
5. 增加`ans`因为我们顺利地参加了这次讲座。 
6. 继续这个过程，直到我们到达一个我们无法参加的讲座，这意味着`cup == 0`那个讲座上没有机器可用。 在那一点上，我们停下来。 

关键的想法是，我们总是尽早贪婪地使用可用的杯子，因为在硬容量上限为 2 的情况下，延迟消耗没有任何好处。任何延迟使用只会降低以后的灵活性。 

### 为什么它有效

 该算法认为，每次参加讲座后，该值`cup`代表在不遇到另一台机器的情况下可以持续的未来讲座的最大数量。 因为容量以 2 为界，所以除了接下来的两次所需消耗之外，“节省”杯子没有任何优势。 每台机器都充当重新填充点，将缓冲区恢复或增加到最大值。 由于我们总是立即消耗并立即补充，因此我们永远不会浪费机器机会，也不会过度积累无法使用的容量。 任何替代策略都可以转化为这种贪婪策略，而不会减少听课的数量，因为在有界缓冲系统下，尽早重新排序消耗永远不会降低可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    cup = 0
    ans = 0

    for i in range(n):
        if cup == 0:
            if s[i] == '0':
                break
            cup = 0
        else:
            cup -= 1

        if s[i] == '1':
            cup += 1
            if cup > 2:
                cup = 2

        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```代码直接实现了上面描述的贪心模拟。 变量`cup`每次讲座后跟踪可用的咖啡杯。 第一个条件处理我们必须依靠机器才能继续当前讲座的情况。 当我们已经存储了杯子时，第二个分支处理正常消耗。 

在消耗逻辑之后，如果机器存在，我们会处理补货，确保强制执行 2 台机器的上限。 

一个微妙的点是订购：消耗必须在补充之前发生，因为当前讲座使用的杯子不能来自同一讲座中的机器，除非我们明确地将其视为立即供应。 这种顺序确保了状态转换的正确性。

 ## 边缘情况

 对于输入`1\n0`，算法立即发现`cup == 0`并且没有机器存在，因此它在参加任何讲座之前停止，产生 0。这与不存在咖啡源的事实相匹配。 

为了`1\n1`，第一堂课提供了一个杯子，也消耗了它，所以可以只听一次。 

为了`0000`，该过程在第一节停止，因为没有机器可用于启用消费，正确地产生 0。 

对于`110000`，前两个讲座建立的缓冲区最多为 2 杯，但随后的四个零消耗该缓冲区直到耗尽，之后进度停止。
