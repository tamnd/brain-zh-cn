 ## 解决方案
 ## 问题理解

 我们得到了在均匀间隔位置采样的一长串地形高度。 从这个序列中，我们想要识别一种特殊的“峰值”，通过选择三个索引 i、j、k 来定义，其中 i < j < k，这样高度首先不会在 j 之前减小，然后在 j 之后不会增加。 换句话说，该序列形成以 j 为中心的山形，但两侧允许有平台。 

对于任何有效的三峰，其质量不是通过顶部的绝对高度来衡量的，而是通过峰与两侧相比高出多少来衡量的。 具体来说，我们查看峰高 hj 与左端点 hi 之间的差值，以及 hj 与右端点 hk 之间的差值，并取这两个值中较小的一个。 该值代表山的最弱一侧，我们希望在所有有效峰值上最大化它。 

输入大小最多可达 200000 个点，这会立即排除三元组的任何三次甚至二次枚举。 任何尝试显式测试所有 i、j、k 组合的解决方案都需要 N^3 或 N^2 次操作，这远远超出了可行的限制。 即使是 N log N 解决方案也必须仔细构建，以避免预处理或检查中隐藏的二次行为。 

当序列是单调或接近单调时，预先计算以每个 j 为中心的所有可能峰值，然后向外扫描所有 i 和 k 对的简单方法将严重失败，因为每个中心的有效 (i, k) 对数量变为 O(N)，再次导致总工作量为二次方。 

当数组恒定或接近恒定时，就会出现边缘情况。 例如，如果所有高度都相等，则每个三元组在技术上都是平峰，并且答案必须为零，因为 hj − hi 和 hj − hk 的差值都为零。 另一个极端情况是严格递增或严格递减序列。 在严格递增的数组中，唯一有效的峰值是右侧平坦或精心选择的峰值，粗心的解释可能会错误地假设不存在有效峰值或返回正值。 

## 方法

 对定义的直接解释建议固定中间索引 j 并尝试向左和右扩展以找到最佳的 i 和 k。 对于固定的 j，我们希望 i 尽可能靠左，使得 hi 很小，k 尽可能靠右，使得 hk 很小，同时仍然尊重 j 的单调约束。 这已经暗示双方的极端值比局部结构更重要。 

强力解决方案将枚举每个 j 周围的每个可能的对 (i, k)，并检查序列是否在 j 之前不递减并且在 j 之后不递增。 即使我们预先计算单调有效性检查，每个中心仍然可能需要扫描两侧的 O(N) 候选者。 这会导致 O(N^2) 或更糟的总复杂度。 

关键的结构观察是，条件 hi ≤ hj ≥ hk 迫使 hj 充当相对于所选端点的局部最大值，但排序约束意味着固定 j 的最佳 i 和 k 由左侧和右侧可达到的最小可能值确定，同时保持单调可行性。 我们不需要考虑所有端点，而只需要知道每个位置在单调结构中从左侧和右侧可实现的最佳“支撑”。

这变成了一个经典的转换：我们将数组分解为最大非递减游程和非递增游程。 在这些结构中，我们可以计算，对于每个位置 j，我们可以向左延伸多远，同时保持不减少到 j，同样，我们可以向右延伸多远，同时保持从 j 开始不增加。 一旦知道这些边界，每个 j 的最佳 i 和 k 就由这些单调区域的端点确定。 剩下的任务变成仅使用这些预先计算的边界值来评估每个 j 的候选值。 

蛮力会失败，因为它会在重叠的间隔上重复重新计算单调可行性，而优化方法将这些间隔压缩为记录可到达极值的线性时间扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（检查所有 i、j、k）| O(N^3) | O(N^3) | O(1) | O(1) | 太慢了|
 | 通过扫描进行中心扩展 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了|
 | 单调边界预处理 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们构建两个辅助数组来捕获单调约束从每个位置自然延伸的距离。 

1. 对于每个索引 j，计算非递减条件中断的最接近左侧的位置。 我们从左到右扫描，维护一个跟踪当前非递减段开始的指针。 这给了我们左边界，可以安全地选择与 j 相关的 hi 值。 
2. 对于每个索引 j，对称地计算非递增条件中断的最接近右侧的位置。 我们从右向左扫描，维护一个跟踪每个非增加段的开头的指针。 这给出了正确的边界，可以安全地选择与 j 相关的 hk 值。 
3. 对于每个候选峰中心 j，我们使用这些边界来识别满足相对于 j 的单调约束的最佳可能左端点 i 和右端点 k。 最佳选择始终位于有效单调段的最末端，因为向内移动只会增加 hi 或 hk 并使目标恶化。 
4. 对于每个 j，将候选峰值计算为 min(hj − h[left_best[j]], hj − h[right_best[j]])。 
5. 返回所有 j 的最大值。 

关键思想是，一旦强制执行单调有效性，最佳端点始终由极端可达位置确定，因此不需要内部扫描。 

### 为什么它有效

 该算法依赖于这样一个事实：任何有效的峰形都受到两侧单调性的约束。 在以 j 结尾的非递减前缀中，最小的可能 hi 出现在该段的开头。 任何其他更接近 j 的 i 选择都会产生更大或等于 hi，因此无法改进 hj − hi。 同样的逻辑对称地适用于右侧。 这将潜在的二次搜索空间减少为每个方向一次通过，并保证每个最佳配置都由边界配置表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    h = list(map(int, input().split()))

    # left[i] = start of non-decreasing segment ending at i
    left = [0] * n
    for i in range(1, n):
        if h[i] >= h[i - 1]:
            left[i] = left[i - 1]
        else:
            left[i] = i

    # right[i] = end of non-increasing segment starting at i
    right = [0] * n
    right[n - 1] = n - 1
    for i in range(n - 2, -1, -1):
        if h[i] >= h[i + 1]:
            right[i] = right[i + 1]
        else:
            right[i] = i

    ans = 0
    for j in range(n):
        l = left[j]
        r = right[j]
        # choose endpoints
        if l < j and j < r:
            ans = max(ans, min(h[j] - h[l], h[j] - h[r]))

    print(ans)

if __name__ == "__main__":
    solve()
```该实现构建了两个线性扫描。 这`left`array 将每个位置压缩到其当前非递减运行的开始处。 这确保了任何有效的左端点必须位于该段内，并且最佳候选者是该段的第一个元素。 

这`right`array 对于非递增运行执行相同的操作，存储每个索引的下降终止位置。 最后的循环在恒定时间内评估每个可能的中心 j。 

一个微妙的点是条件`l < j and j < r`。 这确保了该段实际上形成具有左侧和右侧的有效峰形状。 如果没有它，扁平或退化的段可能会错误地贡献无意义的值。

 ## 边缘情况

 对于严格单调序列，例如`1 2 3 4 5`，每个索引的左边界折叠到索引本身，而右边界延伸到末尾，直到第一次违规。 这可以防止任何有效的三元组形成峰值的两侧，并且该算法正确地产生零，因为没有 j 同时满足严格的左和右要求。 

对于常量数组，例如`7 7 7 7`，每个位置共享相同的左右边界。 计算出的差值到处都为零，并且最大值仍然为零。 单调段压缩确保我们不会错误地将每个三元组视为产生正高度增益。 

对于像这样的形状`1 3 2 4 3`，存在多个局部峰。 该算法独立评估每个候选中心，但边界压缩确保使用其真实的限制端点评估每个峰值，因此仍然可以正确识别全局最大值，而无需枚举重叠的子结构。
