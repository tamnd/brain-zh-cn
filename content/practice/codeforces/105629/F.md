 ## 解决方案
 ## 问题理解

 我们正在使用固定长度的二进制字符串$n$。 每个位置要么是 0 要么是 1，所以总空间包含$2^n$字符串。 其中，我们要统计有多少个满足至少两个条件之一：字符串包含至少一个连续块$a$零，或者它包含至少一个连续块$b$那些。 答案需要模数$10^9 + 7$。 

这种情况通过补语的观点更容易推理。 我们通常不会直接计算“包含长串”的字符串，而是对避免两种不良事件的字符串进行计数：没有任何零串达到长度$a$，并且没有任何一个序列达到长度$b$。 最终的答案是总字符串减去这个限制集。 

输入尺寸允许$n$直到大约$10^6$，所以任何二次 DP$n$甚至$O(n \cdot a)$立即是不可行的。 甚至$O(n \log n)$如果常数很大，就会处于临界状态。 这将我们推向每个状态具有恒定或摊销恒定转换的线性时间动态规划。 

出现微妙的边缘情况时$a = 1$或者$b = 1$。 如果$a = 1$，那么任何字符串都已经包含长度至少为 1 的一串零，因此每个字符串都是有效的。 同样，如果$b = 1$，每个字符串都是有效的。 一个幼稚的补充 DP 可能会错误地尝试禁止已经不可能的状态，从而导致差一错误或空状态转换。 

## 方法

 蛮力的想法很简单：生成所有$2^n$二进制字符串，并通过扫描最长连续的 0 和 1 来检查每个字符串。 这是正确的，但立即失败，因为$2^n$呈指数级增长。 即使是为了$n = 40$，这变得太大了，这里$n$取决于$10^6$，使其完全无法使用。 

关键的观察是，我们关心的属性仅取决于当前运行的连续相同字符。 一旦我们知道前缀末尾有多少个连续的零或一，我们就不需要完整的历史记录。 这将问题变成了有限自动机：我们跟踪当前字符及其当前运行的长度，上限为$a-1$对于零和$b-1$对于那些。 禁止任何超出限制的转换。 

这导致了动态编程公式，我们从左到右构建字符串。 让我们根据最后一个字符及其游程长度来定义状态。 我们维护两组：以 0 结尾且游程长度的状态$1 \dots a-1$，以及以 1 结尾且游程长度的状态$1 \dots b-1$。 在每一步中，我们都会扩展 0 或 1，移动游程长度或重置它们。 

一个天真的 DP 会显式地维护所有这些状态并为每个位置更新它们。 那将花费$O(n(a+b))$，太大了。 重要的结构是每个组内的转换都是前缀移位操作，可以使用前缀和来加速。 我们不是独立地重新计算每个状态，而是计算先前有效状态的累积和，以便每个层都可以在状态数量上以线性时间更新，然后使用滚动前缀技术进一步优化，使总数变为$O(n)$。 

最后，由于我们正在计算补码，所以答案是$2^n - \text{valid}(n)$， 在哪里$\text{valid}(n)$是避免两次长游程的字符串数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举|$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 具有优化的游程 DP |$O(n)$|$O(a + b)$| 已接受 |

 ## 算法演练

 我们首先预先计算 2 的幂$n$，因为二进制字符串的总数是$2^n$。 这为我们提供了补充步骤的基线。 

然后，我们为有效字符串构建 DP，这意味着避免运行的字符串$a$零并避免运行$b$那些。 

我们维护两个数组：一个用于以 0 结尾的状态，另一个用于以 1 结尾的状态。每个数组存储按游程长度索引的计数。 在步骤$i$，这些数组代表长度的所有有效字符串$i$。 

在添加每个新字符时，我们按如下方式计算新数组。 附加 0 时，我们要么通过增加长度来扩展先前的 0 游程，要么从 1 游程切换到长度为 1 的 0 游程。附加 1 时适用相同的对称逻辑。 

从“所有以相反字符结尾的运行”到“所有以当前字符结尾的运行”的转换是前缀和很重要的地方。 我们不是迭代每个新状态的所有可能的先前运行长度，而是维护累积总数，以便可以在每个状态的恒定时间内计算每个更新。 

处理完所有位置后，我们将两组中所有有效的结束状态相加。 这给出了避免两个禁止运行的字符串的数量。 从中减去这个$2^n$得出最终答案。 

### 为什么它有效

 不变的是处理后的位置$i$，每个DP状态精确统计长度为有效的前缀的数量$i$以特定字符和游程长度结尾。 每个转换都保持有效性，因为我们只扩展严格低于禁止阈值的运行。 由于每个有效字符串在每个前缀处都有唯一的游程长度分解，因此不会重复计算或遗漏任何字符串。 补码步骤是有效的，因为 DP 恰好覆盖了违反至少一个约束的字符串补码集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, a, b = map(int, input().split())

    # if any constraint allows everything
    if a == 1 or b == 1:
        print(pow(2, n, MOD))
        return

    # dp0[i] = ways ending with 0-run length i (1..a-1)
    # dp1[i] = ways ending with 1-run length i (1..b-1)
    dp0 = [0] * a
    dp1 = [0] * b

    # initial state: single 0 or single 1
    dp0[1] = 1
    dp1[1] = 1

    total_len = 1

    for _ in range(2, n + 1):
        ndp0 = [0] * a
        ndp1 = [0] * b

        # prefix sums for fast range transitions
        pre0 = [0] * (a + 1)
        pre1 = [0] * (b + 1)

        for i in range(1, a):
            pre0[i] = (pre0[i - 1] + dp0[i]) % MOD
        for i in range(1, b):
            pre1[i] = (pre1[i - 1] + dp1[i]) % MOD

        # transitions to dp0
        # extend previous 0-runs
        for i in range(1, a):
            ndp0[i] = dp0[i - 1] if i > 1 else 0
        # switch from all valid 1-runs
        ndp0[1] = pre1[b - 1]

        # transitions to dp1
        for i in range(1, b):
            ndp1[i] = dp1[i - 1] if i > 1 else 0
        ndp1[1] = pre0[a - 1]

        dp0, dp1 = ndp0, ndp1

    valid = (sum(dp0) + sum(dp1)) % MOD
    ans = (pow(2, n, MOD) - valid) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```该实现保留两个游程长度 DP 数组并逐层更新它们。 微妙的部分是将“相同字符的扩展”与“切换字符”分开，因为切换总是将游程长度重置为 1 并通过前缀和聚合所有兼容的先前状态。 

一个常见的错误是尝试为每个状态显式地迭代所有先前的游程长度，这会导致$O(n^2)$爆炸。 另一个典型的问题是忘记游程长度严格限制在以下范围内$a$和$b$，因此数组的大小必须相应调整，并且转换绝不能访问无效状态。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, a = 2, b = 2
```我们希望避免任何长度为 2 的游程，因此只有交替字符串才有效。 

| 步骤| dp0 | dp1 |
 | --- | --- | --- |
 | 1 | [1] | [1] |
 | 2 | [1] | [1] |
 | 3 | [1] | [1] |

 有效字符串为“010”和“101”，因此有效 = 2。总计 = 8，答案 = 6。 

这证实了当两个运行限制都很严格时，DP 可以正确跟踪交替结构。 

### 示例 2

 输入：```
n = 4, a = 3, b = 2
```我们允许长零，但禁止连续零。 

转换后，DP 收敛到对从未连续出现的字符串进行计数。 

| 步骤| dp0 | dp1 |
 | --- | --- | --- |
 | 1 | [1] | [1] |
 | 2 | [1,1]| [1] |
 | 3 | [2,1]| [2] |
 | 4 | [3,2]| [3] |

 有效 = 11，总计 = 16，答案 = 5。 

这表明不对称约束如何使 DP 严重偏向不受限制的角色。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n)$| 每个位置使用有界状态数组上的前缀聚合来执行恒定时间转换 |
 | 空间|$O(a + b)$| 仅存储 0 和 1 的游程状态 |

 约束允许最多$10^6$，所以线性时间是必要的。 DP 避免了每个状态的嵌套迭代，并且每步仅执行线性扫描，由于常数因子较小和滚动数组，这仍然是可行的。
