[CF 1631A - 最小最大交换](https://codeforces.com/problemset/problem/1631/A)

 **评分：** 800
 **标签：** 贪婪
 **求解时间：** 1m 5s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组，在每个位置我们可以决定两个值中的哪一个留在第一个数组中，哪个进入第二个数组。 具体来说，对于每个独立的索引，我们可以交换该对或保持原样。 当我们完成选择交换后，每个位置恰好向第一个数组贡献一个数字，向第二个数组贡献另一个数字。 

目标是安排这些选择，使第一个数组中的最大元素与第二个数组中的最大元素的乘积尽可能小。 

关键的困难在于每个局部决策同时影响两个全局量。 将大值移入一个数组可能会增加该数组的最大值，而将其保留在另一个数组中可能会增加另一个数组的最大值。 该决策在各个指数之间并不独立，因为最大值是全局摘要。 

约束很小：最多 100 个测试用例，数组大小最多 100。这立即排除了对分配的任何组合搜索，即使决策空间在概念上是$2^n$。 尝试每个测试用例的所有交换配置的解决方案最多需要$2^{100}$国家，这是远远不可能的。 

当两个数组已包含相同的大值时，会出现微妙的边缘情况。 在这种情况下，交换不会改变任何东西，答案是固定的。 例如，如果两个数组都是`[3, 3, 3]`，每个配置都会产生 3 和 3 的最大值，因此答案是 9。任何假设交换始终可以独立减少最大值的方法都会错误地尝试不必要的重新排列，但仍然无法改进产品。 

当大值在同一索引处“配对”时，会出现另一种边缘情况。 例如，如果在索引处$i$， 两个都$a_i$和$b_i$很大，那么其中一个必须成为一个阵列的最大贡献者，而另一个可能会也可能不会帮助相反的阵列，具体取决于交换。 这种耦合是中心结构约束。 

## 方法

 强力策略是将每个索引视为二元选择：要么将索引对保留为$(a_i, b_i)$或将其交换为$(b_i, a_i)$。 对于每个$2^n$配置中，我们计算结果第一个数组的最大值和第二个数组的最大值，然后将它们相乘并跟踪最小值。 这是正确的，因为它探索了每一个可能的任务。 

故障点在规模上是显而易见的。 为了$n = 100$， 这是$2^{100}$配置，甚至对于$n = 30$，它已经太大了。 因此，必须简化问题的结构。 

关键的观察是，重要的不是完整的赋值，而是哪些值最终成为每个数组的最大值。 如果我们固定第一个数组的候选最大值，我们可以对每个元素强制约束：对于每个索引，我们确保所选的位置不违反该最大值，对于第二个数组也是如此。 这将问题简化为在猜测的最大阈值下检查可行性。 

查看结构的一个有用方法是想象按较大值对所有对进行排序。 任一数组的最终最大值必须是这些值之一，因为最大值直接来自所有输入数字的集合。 一旦我们确定了第一个数组最大值的候选者，我们就会贪婪地分配每个索引，以便在该约束下最小化第二个数组的最大值。 

这导致对每个候选最大值进行简单的线性检查：我们强制放入第一个数组中的所有值不超过候选值，并且我们跟踪强制放入第二个数组中的最大值。 最佳乘积是候选最大值的所有选择中的最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n^2)$|$O(1)$| 已接受 |

 ## 算法演练

 我们迭代所有交换后第一个数组中的最大值可能是什么的可能选择。 

1. 将两个数组中的所有值收集到单个候选最大值列表中。 这些是唯一可能成为任一数组最大值的值。 
2. 对于每个候选值$X$，将其视为第一个数组的预期最大值。 我们现在决定每一对如何做出贡献。 
3. 对于每个索引$i$，如果其中之一$a_i$或者$b_i$大于$X$，该值必须进入第一个数组，除非它违反了约束。 由于我们强制第一个数组最大值最多为$X$，任何大于$X$不能放置在那里。 这立即决定了此类对的放置位置。 
4. 对于两个值均为的剩余对$\le X$，我们选择最小化第二个数组的最大值的位置。 自然的贪心规则是尽可能将较大的值放入第一个数组，将较小的值留在第二个数组。 
5. 处理完所有索引后，计算第二个数组的最大值，调用它$Y$。 候选人的答案是$X \cdot Y$。 
6. 对所有可能的情况重复此操作$X$并取最小乘积。 

### 为什么它有效

 关键的不变量是对于固定阈值$X$，我们永远不会放置任何大于$X$进入第一个数组。 这确保了第一个数组的最大值恰好由$X$。 在遵守此约束的所有有效分配中，将较大的剩余元素推入第一个数组可以减少对第二个数组的压力，因为它可以防止大值不必要地累积在那里。 任何偏离这种贪婪选择的行为都只会增加或保留第二个数组最大值，而不会减少它，因为交换仅重新分配值而不更改每对的多重集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        vals = set()
        for i in range(n):
            vals.add(a[i])
            vals.add(b[i])
        
        vals = list(vals)
        ans = float('inf')
        
        for X in vals:
            max_b = 0
            
            for i in range(n):
                x, y = a[i], b[i]
                
                if x > X and y > X:
                    max_b = float('inf')
                    break
                
                if x > X:
                    max_b = max(max_b, x)
                elif y > X:
                    max_b = max(max_b, y)
                else:
                    max_b = max(max_b, min(x, y))
            
            if max_b != float('inf'):
                ans = min(ans, X * max_b)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先提取所有可以充当第一个数组的最大值的候选值。 这已经足够了，因为任何最大值都必须来自现有元素。 对于每位候选人$X$，我们在第一个数组中没有任何内容超出的约束下模拟最佳可能的排列$X$。 

在仿真过程中，如果一对中的两个值都超过$X$，该候选者无效，因为两者都不能在不违反最大值结构的情况下放入第二个数组中。 否则，我们会贪婪地确保第二个数组接收尽可能小的贡献，并跟踪其最大值。 

一旦确定了两个最大值，最后的乘法就直接反映了目标函数。

 ## 边缘情况

 一种重要的边缘情况是两个数组包含相同的值。 例如：```
a = [3, 3, 3]
b = [3, 3, 3]
```每一位候选人$X = 3$导致相同的配置。 该算法处理每个索引并始终记录`max_b = 3`，产生产品 9。不存在替代配置，并且算法不会尝试不必要的交换，因为每次比较都落入 equal-case 分支。 

另一种边缘情况是每个索引已经最佳“对齐”：```
a = [2, 1]
b = [1, 2]
```为了$X = 2$, 每对贡献$1$到第二个数组最大值，给出乘积 2。模拟永远不会违反可行性，因为没有对的两个值都超过$X$。
