 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并允许执行任意次数的特定操作：选择一个偶数长度的子数组并用后半部分的值覆盖它的前半部分。 目标是使用最少的操作数使数组的所有元素相等。 每个测试用例都是独立的，我们要输出每个测试用例的最小操作数。 

这些约束告诉我们，数组可能非常大，单个测试用例中最多可以有 200,000 个元素，跨测试用例的所有数组大小的总和也以 200,000 为界。 这意味着任何在数组大小上具有二次复杂度的算法都会太慢。 我们必须针对每个测试用例采用 O(n) 或 O(n log n) 方法。 

需要注意的边缘情况包括已经统一的数组、大小为 1 的数组、仅最后一个元素与其余元素不同的数组以及每个元素都不同的数组。 尝试每个可能的子数组的简单方法在最后一种情况下会失败，因为操作数量随 n² 增长。 

例如，对于一个数组`[4, 4, 4, 2, 4]`，最佳解决方案是复制最后一个元素来修复不同的元素。 尝试顺序操作的粗心算法可能会选择从第一个元素开始的子数组，而忽略了复制最后一段可以在一次操作中解决它的事实。 

## 方法

 暴力方法是模拟所有可能的操作：对于每个偶数长度的子数组，应用该操作，然后递归地继续，直到所有元素匹配。 这是正确的，因为最终重复的应用程序将收敛到一个统一的数组，但它太慢了。 对于长度为 n 的数组，大约有 n²/2 个长度为 2, 4, 6, ... 的候选子数组，模拟每个操作总共会给出 O(n³)，这对于 n = 2·10⁵ 来说是不可接受的。 

关键的观察结果是该操作总是将所选子数组的后半部分复制到前半部分。 因此，第一个元素只能等于数组中后面出现的某个元素。 更一般地，对于任何与最后一个元素不同的元素，我们需要向后扩展最后一个元素的统一段，直到整个数组统一。 每个操作都可以使这个统一段的大小加倍，因为我们总是可以选择以最后一个元素结尾的偶数长度子数组。 这让人想起贪婪的向后加倍方法：我们修复最后一个元素，然后以指数方式扩展相同元素的块。 操作次数变成了我们需要将统一后缀加倍直到覆盖整个数组的次数。 

这将问题简化为计算将统一后缀从大小 1 增长到 n 需要多少次操作。 通过选择大小等于当前统一后缀两倍的子数组，可以保证每个操作至少使段大小加倍。 这种见解将潜在的二次模拟转换为相对于 n 的对数运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n3) | O(n) | 太慢了 |
 | 贪婪后缀加倍 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`ops`到 0。这将存储所需的最小操作数。 
2.从最后一个元素开始，确定大小`suffix_len`末尾的连续元素块已经相等。 最初，这是 1，因为最后一个元素与其自身基本一致。 
3.同时`suffix_len`小于n，执行以下操作：

 a. 如果当前后缀之前的元素与最后一个元素的值不同，则递增`ops`加 1，表示将统一块复制到不同元素上的操作。 

b. 更新`suffix_len`通过将其加倍，因为每个操作至少可以将统一后缀加倍。 这模拟了将均匀线段向前延伸。 
4.一次`suffix_len`达到或超过 n，所有元素都相等。 输出`ops`。 

为什么它有效：在每一步，操作都会复制大小统一的块`suffix_len`超过前面的元素。 即使前缀大于后缀，选择两倍后缀长度的子数组也能确保至少`suffix_len`元素是固定的。 重复此操作可保证在 O(log n) 次操作后，整个数组是均匀的。 总是从后缀扩展的贪心选择确保了最少的操作数，因为任何不扩展最后一个统一段的操作都无法减少所需的操作数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        target = a[-1]
        ops = 0
        suffix_len = 1
        while suffix_len < n:
            if a[n - suffix_len - 1] != target:
                ops += 1
            suffix_len *= 2
        print(ops)

if __name__ == "__main__":
    solve()
```该解决方案使用有效地读取输入`sys.stdin.readline`。 这`target`是最后一个元素，因为所有操作最终都会将后缀复制到开头。 这`suffix_len`变量跟踪末尾的统一块的大小。 在每次迭代中，如果当前后缀之前的元素不同，则算一次操作。 加倍`suffix_len`模拟一次操作可实现的最大延伸。 当后缀长度覆盖整个数组时循环结束，确保数组变得均匀。 

## 工作示例

 考虑数组`[4, 4, 4, 2, 4]`:

 | 步骤| 后缀长度 | a[n - suffix_len - 1] | a[n - suffix_len - 1] | 操作|
 | ---| ---| ---| ---|
 | 0 | 1 | 一个[3] = 2 | 1 |
 | 1 | 2 | a[1] = 4 | 1 |
 | 2 | 4 | suffix_len >= n | 后缀长度 1 |

 该表显示只需要一个操作，即向后复制最后一个元素以修复不同的 2。 

对于`[4, 2, 1, 3]`:

 | 步骤| 后缀长度 | a[n - suffix_len - 1] | a[n - suffix_len - 1] | 操作|
 | ---| ---| ---| ---|
 | 0 | 1 | a[2] = 1 | 1 |
 | 1 | 2 | a[0] = 4 | 2 |
 | 2 | 4 | suffix_len >= n | 后缀长度 2 |

 这里需要两次操作，因为末尾的uniform块必须扩展两次才能覆盖整个数组。
