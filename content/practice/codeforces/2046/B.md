 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并且允许我们重复执行非常具体的转换：选择任何元素，将其加一，然后将其移动到数组的末尾。 每次我们这样做时，所选元素都会从其位置消失，稍微增长，然后重新出现在后面。 

任务是应用此操作任意次数（可能为零），以便生成按字典顺序排列的最小可能的最终数组。 

关键的难点在于操作同时改变价值和仓位。 将元素及时向前移动（到末尾）的成本很高，因为它会按字典比较顺序延迟它，但如果它允许较早的位置变小，则可能是值得的。 

所有测试用例的总长度最多为 100000 的约束强烈表明我们需要 O(n log n) 或 O(n) 策略。 任何尝试所有操作序列或模拟每个元素重复调整的解决方案都会失败，因为即使是单个元素在最坏的情况下也可能被移动多次，从而导致二次或更糟糕的行为。 

一个天真的错误是假设局部贪婪选择总是安全的。 例如，当较大的元素阻塞较小的前缀时，总是立即移动它可能会失败，因为增加元素会以微妙的方式改变未来的比较。 

考虑这种微妙的失败模式：如果我们总是立即将大于下一个的任何元素推到后面，我们可能会过度修改在其他删除之后本来可以正常工作的元素。 另一个错误是将操作视为仅对元素进行重新排序。 增量打破了纯粹的排列直觉。 

主要的非平凡边缘情况是早期元素很小但后来的元素稍小，但如果移动则需要多次增量才能保持竞争力。 例如，像 1 这样的元素移动了几次就变成了 1 + k，这最终可能会超过其他未移动的元素，因此延迟它实际上可能会损害字典顺序。 

## 方法

 暴力方法将模拟所有可能的操作序列。 每一步都会选择一个索引，递增它，然后将其推到后面。 由于每个元素可以多次选择并且位置不断变化，因此状态空间呈指数增长。 即使通过 n 个操作限制每个元素也会导致 O(n^2) 或更糟糕的行为，这远远超出了限制。 

关键的观察是，从未移动的元素的最终相对顺序被保留，并且移动的元素总是积累等于它们在定居之前被推回的次数。 我们可以不考虑操作序列，而可以认为每个元素要么留在原地，要么在某个时刻被“推到最后”，之后它将永远不会再返回。 

一旦我们修复了将保持不变的元素的前缀，每个剩余的元素最终都必须移到该前缀后面，并且其最终值仅取决于处理时在其之前有多少个未触及的元素。 这就把问题变成了按照从左到右的顺序决定我们是应该现在保留一个元素还是将其推迟到最后，同时考虑到推迟的元素将以递增的成本顺序返回的事实。 

当我们处理元素并维护将形成后缀的“待移动元素”结构时，就会出现贪婪结构。 在每一步中，我们都会将当前元素与在考虑增量后可以从待处理池中提出的最小可用候选元素进行比较。 这可以使用跟踪所有推迟元素的多重集（或堆）来有效处理。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(n) | 太慢了|
 | 贪婪 + 多集维护 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，维护两个组件：不断增长的答案前缀和已“移动到后面”但尚未发送到最终结构中的元素池。 

1. 从推迟元素的空结构开始。 我们将其视为多重集，因为我们需要重复提取最小的调整值。 
2. 从第一个元素到最后一个元素迭代数组。 在每个索引处，我们决定当前元素是否应该直接放入答案中或移动到推迟池中。 
3. 对于每个元素 a[i]，我们将其与当前推迟池中的最小元素进行比较，但我们必须记住，每次较早的移动，池中的元素都会增加一次。 这创造了一种动态，随着时间的推移，推迟的元素的价值实际上“上升”。 
4. 如果当前元素小于或等于最佳可用推迟选项，我们立即将当前元素放入答案中。 否则，我们更愿意先从推迟池中取出一些东西，因为它会产生更小的字典前缀。 
5. 每当我们从延迟池中取出时，我们都会发出可用的最小调整元素，然后在必要时重新插入它，并使用其增量值来考虑另一次移动，或者如果它已完成，则将其删除。 
6. 如果我们选择不从推迟池中取出，则将当前元素添加到池中，表示它已被推到末尾并递增一次。 
7. 完成扫描后，按顺序提取任何剩余的推迟元素，每次应用它们的累积增量。 

微妙之处在于，每个推迟的元素的行为就像每次循环时都会增加 1 的值，因此我们从不显式模拟每个元素的多次移动。 我们只存储其当前的有效值。 

### 为什么它有效

 在任何步骤中，算法都会确保下一个发出的元素是在某些有效操作序列中可以合法出现在该位置的最小值。 不变的是，延迟池始终包含已延迟超过当前前缀的元素，每个元素都以其正确的累积增量状态表示。 由于字典顺序仅取决于最早的不同位置，因此始终发出最小的可用候选者可以保持局部最优性，从而保持全局最优性。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # min-heap of postponed elements
        heap = []

        res = []

        for x in a:
            if not heap or x <= heap[0]:
                # take current element
                res.append(x)
            else:
                # move current element to back (it gets incremented once)
                heapq.heappush(heap, x + 1)

                # take smallest postponed element
                smallest = heapq.heappop(heap)
                res.append(smallest)

        # flush remaining
        while heap:
            res.append(heapq.heappop(heap))

        print(*res)

if __name__ == "__main__":
    solve()
```该实现依赖于最小堆来始终访问 O(log n) 中的最小延迟元素。 决策点将当前元素与堆最小值进行比较，后者代表先前延迟元素中可能的最佳候选者。 

一个常见的陷阱是忘记，当我们推迟一个元素时，它会立即增加 1，并且每次进一步的推迟都会通过堆排序的重新处理来隐式表示。 堆从不存储原始值； 它存储已经为第一步调整过的值。 

需要最后的刷新步骤，因为任何剩余的推迟元素仍必须按照其有效值的升序放置到输出中。

 ## 边缘情况

 一个关键的边缘情况是数组严格递减。 在这种情况下，除了第一个元素之外的每个元素都会被推入堆中，并重复增加它们的值。 该算法仍然会产生平滑的递增序列，因为每个元素的延迟增量自然地按堆排序，从而防止后面的元素错误地超越较早的推迟元素。 

另一个边缘情况是所有元素都相等。 由于与保留元素相比，没有任何元素会通过推迟来严格改进，因此堆永远不会在比较中占主导地位，并且数组保持不变。 

第三种情况是非常小的元素出现较晚。 堆确保它不会丢失在较大的延迟元素后面，因为它始终会在适当的时候作为最小有效值出现，从而保留字典顺序上的最佳前缀。
