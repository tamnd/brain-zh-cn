 ## 解决方案
 ## 问题理解

 我们有`n`硬币有多种面额，每种面额都可以使用任意次数。 对于目标金额`m`，我们需要计算有多少种不同的多重硬币总和恰好等于`m`。 硬币的顺序并不重要，所以`2 + 3`和`3 + 2`代表同样的改变方式。 答案以模数形式报告`1,000,000,007`。 

例如，对于面额`2, 3, 5, 7`和目标`10`，有效的组合是`3 + 7`,`5 + 5`,`2 + 3 + 5`,`2 + 2 + 3 + 3`，以及五份`2`，给出答案`5`。 

目标最多是`10,000`，虽然最多可以有`100`教派。 这强烈建议围绕动态规划解决方案`n * m`，每个测试用例最多大约一百万个状态更新。 对于最多 10 个测试用例，这在具有紧凑一维 DP 的 Python 中仍然实用。 枚举所有可能组合的解决方案根本不可行，因为即使是单一面额也可以使用最多`m`随着更多面额的增加，组合的数量也迅速增长。 

面值也可以大到`10,000`。 任何大于`m`永远不能参与有效的组合，因此没有必要对其进行处理。 该语句将面额描述为不同的，但如果提供重复的值，则在实现中对它们进行重复数据删除将使算法变得稳健。 重复的相同面额不应产生不同的方式，因为方式是由硬币的价值和多重性决定的，而不是由提供硬币的输入位置决定的。 

在一些边缘情况下，粗心的实现可能会默默地计算出错误的结果。 和```
1
1 3
5
```答案是`0`，因为唯一可用的硬币已经大于目标。 盲目索引的复发`dp[amount - coin]`不检查边界就可以访问无效状态。 

和```
1
2 5
2 3
```答案是`1`， 从`2 + 3`。 一个常见的错误是以错误的顺序更新 DP 并意外地计算出相同硬币的不同排列。 两个序列`2 + 3`和`3 + 2`一定不能成为单独的答案。 

和```
1
2 4
2 2
```答案是`1`如果重复面额被解释为相同的硬币价值。 将两个输入条目视为独立的硬币类型将以多种方式计算相同的货币组合。 最初的问题承诺不同的面额，但重复数据删除避免了这种歧义。 

最后，与```
1
1 1
1
```答案是`1`。 空总和表示为`dp[0] = 1`，并添加面额`1`必须将其完全转变为形成金额的一种方式`1`。 将 DP 数组初始化为到处都为零将会失去这个基本的基本情况。 

## 方法

 直接的暴力方法是选择每个面额使用多少份，并测试所得的总和是否为`m`。 对于面额`c_i`，其计数范围可以从零到`floor(m / c_i)`，所以检查的组合数量是`product(floor(m / c_i) + 1)`。 

这是正确的，因为每一种可能的多组硬币都恰好对应于这些计数中的一种选择。 问题在于搜索空间的大小。 在最坏的情况下，如果所有教派都`1`，理论上有`10001^100`计数的选择，尽管原始声明不允许重复的面额。 即使是不同的小面额，搜索空间也会变得巨大。 因此，递归枚举在到达之前很久就失败了`n = 100`和`m = 10000`。 

更微妙的暴力策略生成每个有序的硬币序列，其总和不超过`m`，然后只保留序列完全达到`m`。 这更糟糕，因为相同的组合出现在许多排列中。 例如，`2 + 3 + 5`可以以六种不同的顺序生成。 实际问题要求该组合有一个答案，因此探索顺序会产生问题不需要的工作。 

关键的观察结果是目标金额的界限为`10,000`，所以我们不需要记住到目前为止选择的整个硬币集合。 我们只需要知道每个较小的量可以有多少种形成方式。 一旦按固定顺序处理了面额，我们就可以决定是否将当前面额附加到已计数的组合中。 

让`dp[x]`是形成金额的方式的数量`x`使用迄今为止处理过的面额。 处理有价硬币时`c`, 各种方式形成`x - c`可以延长一`c`硬币形成`x`。 因此我们添加`dp[x - c]`到`dp[x]`。 

循环的顺序决定了计数组合而不是排列。 我们在外循环中处理面额，在内循环中按升序处理金额。 一次面额`c`正在处理中，`dp[x - c]`已经包含了可以使用的方法`c`，允许无限复制。 同时，每种面额都是在一个固定的阶段引入的，因此相同的组合不能以不同的顺序再次生成。 

蛮力之所以有效，是因为它明确地考虑了每种硬币的所有可能的多重性，但当这样的选择太多时，它就会失败。 观察到具有相同当前量的两个部分解具有相同的未来可能性，我们可以将它们合并为一个 DP 状态。 这将问题减少到`O(nm)`过渡。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(product(m / c_i + 1))`在最坏的情况下|`O(n)`递归深度 | 太慢了 |
 | 最佳 |`O(nm)`|`O(m)`| 已接受 |

 ## 算法演练

 1. 读取面额并删除重复的值（如果有）。 面额代表硬币的价值，因此相同价值的重复副本不会创造不同的找零方式。 
2. 忽略每一个大于的面额`m`。 这样的硬币永远不可能以等于`m`，所以处理它不能改变答案。 
3. 创建一维数组`dp`长度`m + 1`并将每个条目初始化为零。 放`dp[0] = 1`。 使金额为零的方法只有一种，即不选择硬币。 这个基本情况允许第一个实际硬币开始组合。 
4. 处理各面额`c`一次一个。 对于当前面额，迭代`x`从`c`通过`m`按递增顺序并执行`dp[x] += dp[x - c]`模数`1,000,000,007`。 
5. 递增顺序`x`故意允许`dp[x - c]`已包含当前面额。 例如，在处理硬币时`2`，更新为`dp[4]`可以使用新更新的`dp[2]`，代表两个副本`2`。 如果按金额降序处理，则每种面额最多可以使用一次。 
6. 所有面额处理完毕后，`dp[m]`包含总价值恰好为的不同组合的数量`m`。 打印该值的模数`1,000,000,007`。 

### 为什么它有效

 不变量是在处理完第一个之后`k`教派,`dp[x]`等于完全形成的组合数`x`仅使用那些`k`教派。 处理新面额时`c`，每一个旧的组合形成`x`仍然可用，并且每个组合至少使用一个`c`可以通过删除一个来唯一获得`c`，留下一个由以下计数的组合`dp[x - c]`。 因此，更新准确地添加了由`c`。 

由于面额按固定顺序处理，因此组合具有引入其最大索引面额的独特点。 不能通过相同硬币的另一种排列来再次计数。 由于金额是从小到大处理的，当前面额可能会重复使用，因此包含所有有效的重数。 因此，该不变量在每个教派之后都成立，并且`dp[m]`是必需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        coins = list(map(int, input().split()))

        # The original statement has distinct denominations.
        # Deduplication also makes the implementation robust to repeated values.
        coins = sorted(set(c for c in coins if c <= m))

        dp = [0] * (m + 1)
        dp[0] = 1

        for coin in coins:
            for amount in range(coin, m + 1):
                dp[amount] += dp[amount - coin]
                if dp[amount] >= MOD:
                    dp[amount] -= MOD

        out.append(str(dp[m]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```每个测试用例都会读取一次输入，并在 DP 启动之前对面额进行过滤和重复数据删除。 排序并不是正确性所必需的，但可以为硬币组提供确定性的顺序，并且可以轻松一致地处理面额。 

DP数组有索引`0`通过`m`，所以它的大小正好是`m + 1`。`dp[0] = 1`代表唯一的空组合。 不应将其他初始状态设置为非零值。 

对于每个硬币，内循环开始于`coin`，因为低于硬币价值的金额不能使用该面额。 它结束于`m`，因为大于目标的金额无法贡献`dp[m]`。 

内环向上移动。 这是最重要的实施细节。 假设当前的硬币是`2`。 计算后`dp[2]`，稍后更新为`dp[4]`读取更新后的值，因此有两个副本`2`是允许的。 如果循环向下移动，则当前硬币在同一迭代中将不可见，从而将循环变成零或一使用转换。 

Python 整数不会溢出，但每次更新都会取模`MOD`保持存储的值很小并直接实现所需的模运算。 由于两个操作数都已经低于`MOD`，加法后一次减法足以将结果保持在范围内`[0, MOD)`。

 ## 边缘情况

 ### 面额大于目标

 考虑```
1
1 3
5
```硬币`5`被丢弃是因为`5 > 3`。 民主党仍保留`[1, 0, 0, 0]`， 所以`dp[3] = 0`。 该算法不会尝试访问`dp[3 - 5]`，避免了 Python 中的负索引错误。 

### 订单不得创建不同的组合

 考虑```
1
2 5
2 3
```最初`dp[0] = 1`。 加工硬币`2`产生一种金额方式`2`和`4`，对应于`2`和`2 + 2`。 加工硬币`3`然后使用这些状态，所以`dp[5]`收到一份贡献`dp[2]`，代表`2 + 3`。 没有对应的第二个贡献`3 + 2`，因为面额`2`之前已经处理过`3`。 输出正是`1`。 

### 重复面值

 考虑```
1
2 4
2 2
```去重后币单就只剩下`[2]`。 DP 生产`dp[4] = 1`，对应于`2 + 2`。 如果没有重复数据删除，将两个相等的值视为不同的硬币类型将使相同的货币组合通过不同的输入位置出现。 该声明保证不同的面额，因此这种情况不在官方输入模型之内，但实现可以安全地处理它。 

### 空组合作为 DP 基本情况

 对于```
1
1 1
1
```初始状态是`dp[0] = 1`。 加工硬币`1`更新`dp[1]`从`dp[0]`, 给予`dp[1] = 1`。 唯一的方法是单一的`1`硬币。 如果`dp[0]`如果被初始化为零，则任何数量都不会变得可访问，因为每个转换都取决于不可访问的状态。 

### 目标的精确边界

 考虑```
1
3 6
2 3 6
```加工`2`给出了一种制作方法`2`,`4`， 和`6`。 加工`3`添加`3`和`6`，而金额`6`也收到组合`3 + 3`。 最后，硬币`6`添加直接组合`[6]`。 这三种不同的组合是`2 + 2 + 2`,`3 + 3`， 和`6`，所以答案是`3`。 

循环`range(coin, m + 1)`包括`m`本身。 停在`m - 1`会错过最终更新直接创建目标的每个组合，包括单个硬币`6`在这个例子中。
