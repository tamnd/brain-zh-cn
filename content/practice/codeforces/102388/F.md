 ## 解决方案
 ## 问题理解

 我们有`n`硬币有多种面额，每种面额都可以使用任意次数。 对于目标金额`m`，找零的方式仅取决于每种面额的硬币的使用数量，而不是这些硬币的书写顺序。 例如，对于面额`2`和`3`， 量`6`有两种方式：`2 + 2 + 2`和`3 + 3`。 

对于每个测试用例，输入给出面额数量、目标金额以及面额值本身。 所需的输出是总价值恰好为的不同组合的数量`m`, 减少模数`10^9 + 7`。 

这些约束直接指向动态规划。 最多有`100`面额和目标最多`10000`，大致如此`n * m = 10^6`每个测试用例的状态转换是可以承受的。 最多十个测试用例，这大约是`10^7`简单的操作，这在编译语言中是合理的，并且在具有紧凑实现的Python中仍然实用。 任何指数级的东西`m`或者说硬币选择的数量完全是遥不可及的。 

第一个边缘情况是面额大于目标面额。 例如，```
1
2 3
4 5
```有输出`0`。 两种货币都不能参与有效的总和，因此 DP 实现一定不能意外地处理初始状态`dp[0] = 1`作为实现每个目标的一种方式。 

第二种边缘情况是面额完全等于目标面额。 例如，```
1
1 5
5
```有输出`1`。 内循环必须包含索引`m`; 使用停止于的范围`m - 1`默默地失去了这个解决方案。 

第三种边缘情况是无限地重复使用某个面额。 例如，```
1
2 6
2 3
```有输出`2`，对应于`2 + 2 + 2`和`3 + 3`。 将每个面额视为 0/1 项目会错过两种组合，因为两种面额都不能使用多次。 

第四种边缘情况是输入顺序不得影响答案。 例如，```
1
2 6
3 2
```也有输出`2`。 正确的硬币找零 DP 使用升序目标循环，以便在同一遍中可以重复使用当前面额。 下降的目标循环会将转换转变为 0/1 背包行为。 

正式声明将硬币的价值描述为不同。 如果仍然提供了重复的值，则将每个输入条目作为单独的硬币类型进行处理，从而分别对它们进行计数。 例如，三个值的条目`2`和目标`6`给`10`，因为这三种类型可以贡献计数总和`3`在`C(5,2) = 10`方式。 这样的输入超出了规定的限制，但实现对其有一致的解释。 

## 方法

 直接暴力方法可以递归地尝试每一个可能的下一个硬币并继续，直到运行总和达到或超过`m`。 为了避免将不同的订单计算为不同的找零组合，它可以保持所选硬币索引不减，或者等效地生成所有有序序列并在将其插入集合之前将每个序列规范化。 从概念上讲，这是可行的，因为可以生成每个有效的组合，并且每个无效的部分选择最终都可以被拒绝。 

问题在于候选人的数量。 即使只有两种面额的有序序列版本也会变得巨大。 对于教派`1`和`2`，其总和为的有序序列的数量`10000`正是斐波那契数`F_10001`，因为序列结尾为`1`来自序列求和`9999`，而结尾为`2`来自序列求和`9998`。`F_10001`大致有`2090`十进制数字，因此暴力搜索需要生成以下顺序`10^2089`在完成之前终止序列。 规范化这些序列并没有帮助，因为昂贵的一代已经发生了。 

蛮力之所以有效，是因为每种组合都可以通过选择硬币来构建，但它会重复解决相同的较小子问题。 例如，一旦我们知道有多少种方法可以赚钱`8`使用面额的某个前缀，每当另一个解决方案达到相同状态时，就再次需要该结果。 观察到这些重复的子问题完全由已经形成的数量和允许的面额集合来描述，这让我们可以存储答案而不是重新计算它们。 

这给出了标准的无界硬币找零动态规划公式。 让`dp[x]`代表赚钱方式的数量`x`仅使用迄今为止处理过的面额。 当面额`c`介绍一下，每一种老方法的制作方法`x - c`可以通过添加一个来扩展`c`硬币，提供了一种制作方法`x`。 因此，过渡是`dp[x] += dp[x - c]`。 

内循环的方向是关键细节。 我们处理`x`从`c`向上。 因为`dp[x - c]`可能已经使用相同的硬币进行了更新，则可以再次使用当前面额，这与每种类型有无限多个硬币的事实完全匹配。 

外层面额循环的顺序也为我们提供了关键的计数约定。 组合如`2 + 3 + 5`是根据固定面额顺序生成的，而不是每次排列一次生成，例如`3 + 5 + 2`。 每个组合在DP状态序列中只有一个表示，因此被计数一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数为`m`和选择的数量| 生成状态的数量呈指数增长 | 太慢了 |
 | 最佳 |`O(nm)`|`O(m)`| 已接受 |

 ## 算法演练

 1. 创建数组`dp`长度`m + 1`， 在哪里`dp[x]`最终意味着形成金额的方式数量`x`。 放`dp[0] = 1`和所有其他条目为零。 空选择正是使金额为零的一种方法，并且每个非零金额最初没有已知的表示。 
2. 一次处理一枚硬币面额。 处理完面额后，`dp[x]`仅使用目前看到的面额来计算组合。 这个不变量可以防止相同硬币的不同顺序成为单独的答案。 
3. 对于有价值的硬币`c`, 迭代`x`从`c`通过`m`按递增顺序。 对于每个这样的金额，添加`dp[x - c]`到`dp[x]`。 
4. 转换是正确的，因为每个组合都由`dp[x - c]`可以额外获得一份`c`硬币并成为组合`x`。 由于循环是上升的，`dp[x - c]`可能已经包含使用的组合`c`，因此当前面额的任意数量的副本都是允许的。 
5.减少每次更新模数`10^9 + 7`。 问题只需要余数，并且在计算过程中减少可以使存储的整数保持较小。 
6. 所有面额处理完毕后，输出`dp[m]`。 此时，不变量表示它恰好包含可用面额的所有组合，其总价值为`m`。 

### 为什么它有效

 不变量是在处理完第一个之后`k`教派,`dp[x]`等于形成的组合数`x`仅使用那些`k`教派。 最初，没有面额，只能形成金额为零，给出`dp[0] = 1`。 当面额`c`被处理后，每个新组合至少使用一个`c`使用已处理的面额加上一个最终的面额进行独特的分解`c`。 上升循环允许前面的组合包含任意数量的`c`硬币，因此每个有效组合仅添加一次。 现有组合不使用`c`保持原样。 因此，不变量在每个教派中都存在，并且`dp[m]`最后就是所需的计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        coins = list(map(int, input().split()))

        dp = [0] * (m + 1)
        dp[0] = 1

        for coin in coins:
            if coin > m:
                continue

            for amount in range(coin, m + 1):
                dp[amount] += dp[amount - coin]
                if dp[amount] >= MOD:
                    dp[amount] -= MOD

        print(dp[m])

if __name__ == "__main__":
    solve()
```第一部分读取每个测试用例并为其目标数量创建一个 DP 数组。 该数组有`m + 1`条目，因为金额零是真实状态并且目标`m`也必须有代表。 

环境`dp[0] = 1`是必不可少的。 当处理一枚硬币等于`x`，过渡使用`dp[x - coin] = dp[0]`，从而创建第一个完全由该硬币组成的解决方案。 如果没有这种初始化，每个状态都将永远保持为零。 

外循环处理面额而不是金额。 这就是 DP 计算组合而不是有序序列的原因。 一旦处理了一个面额，就可以添加后面的面额，但较早的面额永远不会以不同的顺序重新考虑。 

内循环开始于`coin`，因为较小的数量无法容纳该硬币。 它结束于`m`，包括在内，因为硬币本身可能就是完整的目标。 

内环必须向上移动。 考虑`coin = 2`和`amount = 6`。 到......的时候`dp[6]`计算得出，`dp[4]`已经合并了当前的硬币，允许`2 + 2`延伸至`2 + 2 + 2`。 下降循环只会读取当前硬币推出之前的状态，并且会错误地将每种面额限制为一种用途。 

Python整数不会溢出，但是模运算仍然是必要的，因为所需的答案是模`10^9 + 7`。 条件减法就足够了，因为两个操作数都已经低于模数，因此它们的总和小于`2 * MOD`。 

## 工作示例

 ### 示例测试用例 1

 考虑第一个测试用例：```
1 100
1
```只有一种面额，因此唯一可能的代表`100`是一百枚有价值的硬币`1`。 

| 加工硬币|`dp[0]`|`dp[1]`|`dp[100]`|
 | --- | --- | --- | --- |
 | 无 | 1 | 0 | 0 |
 | 1 | 1 | 1 | 1 |

 硬币加工后`1`，升序循环重复使用当前面额。 因此`dp[100] = 1`，输出是`1`。 

该跟踪说明了为什么该问题是无界背包问题而不是 0/1 背包问题。 同一面额必须可以使用一百次。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(nm)`| 每个`n`面额从其价值扫描金额`m`，最多有`m`过渡。 |
 | 空间|`O(m)`| 只有一维DP数组`m + 1`状态被存储。 |

 和`n <= 100`和`m <= 10000`，一个测试用例最多执行约一百万次 DP 更新。 即使在十个测试用例中，这也大约是一千万次更新，而内存使用量仅为大约一万个 Python 整数引用加上它们的整数对象。 该解决方案轻松地避免了暴力的指数搜索空间并符合规定的限制。

 ## 边缘情况

 大于目标的面额由条件处理`if coin > m: continue`。 对于输入```
1
2 3
4 5
```两种面额都被跳过，因此数组仍然存在`dp[0] = 1`和`dp[1..3] = 0`。 算法打印`0`，正确认识到无法形成正数。 

与目标精确相等的面额行使上限。 为了```
1
1 5
5
```循环运行`amount = 5`并执行`dp[5] += dp[0]`。 自从`dp[0] = 1`，由此产生的`dp[5]`是`1`。 包容性的`m + 1`端点在`range(coin, m + 1)`正是这个解决方案变得可见。 

无限重用由金额递增循环处理。 为了```
1
2 6
2 3
```加工硬币`2`产生`dp[2] = 1`， 然后`dp[4] = dp[2] = 1`， 然后`dp[6] = dp[4] = 1`，代表三个副本`2`。 加工硬币`3`随后创建`dp[6] += dp[3] = 1`，代表两个副本`3`。 最终的答案是`2`。 

最后，更改输入顺序不会更改组合。 为了```
1
2 6
3 2
```硬币`3`首先被处理并创建`3 + 3`解决方案。 硬币`2`然后被处理并创建`2 + 2 + 2`。 由于每种面额都在固定的外循环阶段进行处理，并且只能通过上升的内循环重复使用，因此两种解决方案都不会重复。 结果依然`2`。
