 ## 解决方案
 ## 问题理解

 对于每个测试用例，我们都会收到一个仅包含英文字母的非空字符串。 所需的编码按照问题描述的顺序应用三种转换：将每个字母更改为相反的大小写，反转整个字符串，并在保留字母大小写的同时应用 ROT13。 输出是生成的编码字符串。 

例如，从`HelloWorld`，改变大小写给出`hELLOwORLD`。 倒车给出`DLROwOLLEh`，ROT13 产生`QYEBjBYYRu`。 

最多有 100 个测试用例，每个字符串最多有 100 个字符。 因此，输入总量很小，因此即使对每个字符串进行多次完整传递，也很容易满足 1 秒的限制。 更重要的是，变换本身在字符串长度上是线性的，因此没有理由使用比直接模拟更复杂的东西。 花费二次时间的解决方案也将通过这些特定的约束，但解决问题会比必要的困难得多。 

第一个边缘情况是单字符字符串。 用于输入`A`，大小写交换给出`a`，反转没有任何改变，ROT13 给出`n`，所以正确的输出是`N`在其指定的组合中应用变换之后。 将反转视为需要至少两个字符的粗心实现可能会意外跳过或错误处理这种情况。 

第二个边缘情况是靠近字母表末尾的字符。 用于输入`Z`, ROT13 必须从`Z`到`M`，而不是移出字母表。 正确的输出是`M`。 小写字母也会出现同样的问题`z`，这变成`m`。 简单地将 13 添加到 ASCII 值而不换行的实现将产生无效字符。 

第三种边缘情况是情况和字母表边界的混合。 用于输入`AaZz`，首先反转给出`zZ aA`没有空格，即`zZaA`。 交换大小写后变成`ZzAa`，ROT13 给出`MmNn`。 粗心的解决方案是在更改大小写之前应用 ROT13，但随后使用了错误的大小写信息，很容易产生不正确的大小写。 

## 方法

 最直接的方法是分别模拟这三个操作。 我们可以扫描整个字符串并交换每个字符的大小写，执行反转，然后再次扫描整个字符串以查找 ROT13。 这直接反映了编码定义，因此正确性是立竿见影的。 带有长度的字符串`n`，这三遍执行`n`案例变化，`floor(n / 2)`逆转掉期，以及`n`ROT13 转换。 在这种直接实现下，即`2n + floor(n / 2)`字符级操作。 和`n <= 100`，最坏的情况是每个测试用例只有 250 个这样的操作，因此这种方法不会变得太慢。 明显的暴力基线已经被接受。 

通过观察大小写交换和 ROT13 都是按字符转换，我们可以使实现更加清晰。 这两种操作都不依赖于角色的位置，因此两者都可以反转。 我们可以从右向左遍历原始字符串并在生成答案时应用两个字符转换，而不是首先构造中间字符串然后反转它。 每个输入字符仅被处理一次。 

关键的观察是这三个操作不需要复杂的交互。 反转决定字符出现的顺序，而大小写交换和 ROT13 仅修改每个单独的字符。 因此，当我们从最后一个位置到第一个位置访问原始字符时，我们已经隐式地执行了反转。 我们只需要变换每个访问过的角色。 

这将实现减少为一次字符串遍历。 渐近复杂度仍然存在`O(n)`，这是最佳的，因为每个字符都必须至少检查一次才能确定输出。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 单独的模拟通道 | O(n) | O(n) | 已接受 |
 | 向后遍历时的一次变换 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取字符串`s`。 它的字符保证是英文字母，所以每个字符都可以通过检查它是大写还是小写来处理。 
2. 遍历`s`从最后一个字符到第一个字符。 沿此方向读取会执行所需的反转，而无需显式构造反转副本。 
3. 交换当前字符的大小写。 大写字符变为小写，小写字符变为大写。 
4. 将 ROT13 应用于角色，同时保留其当前大小写。 对于大写字母，减去`A`，加上 13 模 26，然后加上`A`后退。 对于小写字母，使用相同的方法`a`。 
5. 将转换后的字符附加到答案中。 由于字符是按反向输入顺序处理的，因此得到的答案已经具有所需的反向排列。 
6. 打印测试用例的完整答案。 

### 为什么它有效

 考虑任何原始角色`s[i]`。 最终的编码字符串必须包含该字符在位置的转换版本`n - 1 - i`，因为反转移动了位置`i`到那个位置。 通过遍历输入`n - 1`下降到`0`，算法将字符按照从左到右的顺序准确地放置到最终位置。 大小写交换和 ROT13 操作与角色的位置无关，因此在访问角色时应用它们会产生与反转之前或之后应用它们所产生的完全相同的字符。 因此，每个输出位置都包含正确的编码字符。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def transform(s):
    ans = []

    for c in reversed(s):
        if 'A' <= c <= 'Z':
            c = c.lower()
        else:
            c = c.upper()

        if 'A' <= c <= 'Z':
            c = chr((ord(c) - ord('A') + 13) % 26 + ord('A'))
        else:
            c = chr((ord(c) - ord('a') + 13) % 26 + ord('a'))

        ans.append(c)

    return ''.join(ans)

def main():
    t = int(input())

    for _ in range(t):
        s = input().strip()
        print(transform(s))

if __name__ == "__main__":
    main()
```这`transform`函数直接对应于算法演练。`reversed(s)`完全按照反转操作后所需的顺序给出字符，因此不需要单独的反转操作。 

第一个条件更改角色的大小写。 然后，第二个条件确定该字符属于哪个字母表并使用模算术执行 ROT13。 表达式`(ord(c) - ord('A') + 13) % 26`将字符转换为从零开始的字母位置，将其旋转 13 个位置，并在必要时回绕。 

模运算干净地处理字母表边界。 例如，`Z`从零开始的位置为 25，所以`(25 + 13) % 26`给出 12，对应于`M`。 小写分支的行为与`a`作为它的基础。 

没有涉及指数计算`len(s) - 1 - i`，因此该实现避免了最常见的逆转差一错误。 也不存在整数溢出问题，因为所有算术都是对 0 到 25 之间的值执行的。 

答案存储在列表中，因为重复连接字符串可能会创建不必要的中间字符串。 最后加入一次列表可以有效地构建最终结果。

 ## 边缘情况

 对于单字符输入`A`，遍历仅包含该字符。 大小写交换变化`A`到`a`和 ROT13 的变化`a`到`n`。 角色在反转过程中没有其他地方可以移动，所以最终的输出是`N`。 该算法不需要长度为一的特殊情况。 

对于字母边界输入`Z`，角色首先变成`z`因为案例交换。 ROT13 然后计算`(25 + 13) % 26 = 12`，生产`m`，所以输出是`M`。 模运算可防止计算脱离字母表。 

对于混合边界输入`AaZz`，反向遍历访问`z`,`Z`,`a`,`A`。 经过案例交换和 ROT13 后，这些变成`M`,`m`,`N`,`n`， 分别。 输出是`MmNn`，这证实了该算法在处理大写和小写环绕时保留了正确的大小写。 

对于由 100 个副本组成的最大尺寸全相等输入`A`，反转不会明显改变字符串，但每个字符仍然经历大小写交换和 ROT13 转换。 每个`A`变成`N`，因此结果包含 100 个副本`N`。 该算法正好处理 100 个字符，并且不需要对重复值进行特殊处理。
