 ## 解决方案
 ## 问题理解

 我们得到一个完全定向的完整图，这意味着每一对不同的顶点之间都恰好有一条有向边。 对于每个顶点$u$，输入准确地告诉我们它指向哪些顶点。 

一个顶点$u$如果它可以在最多两步内到达所有其他顶点，则被认为是好的。 换句话说，对于任何目标顶点$v$， 任何一个$u$有直接优势$v$，或者存在中间顶点$w$这样$u \to w$和$w \to v$。 

这是锦标赛图中深度二的可达性条件。 任务是找到满足该属性的任何三个不同的顶点。 如果存在的此类顶点少于三个，我们输出不存在解。 

约束条件$n \le 5000$立即排除任何尝试显式测试通过三元组顶点的所有路径的解决方案。 对单个顶点的简单检查已经需要扫描所有目标的所有中间顶点，从而导致$O(n^2)$每个顶点和$O(n^3)$全面的。 那太慢了。 

当很少的顶点是好的时，就会出现微妙的边缘情况。 例如，在循环锦标赛中，每个顶点在一个循环中恰好击败一个邻居，没有顶点可以在两步内到达所有其他顶点，因此答案必须是“未找到”。 另一方面，在传递锦标赛中（边从较低索引到较高索引），每个顶点都很好，因为每个顶点都可以直接到达所有内容，因此答案通常是任何三个顶点。 

困难在于，该条件是全局的，取决于邻居邻域的并集，因此仅局部度信息是不够的。 

## 方法

 直接方法检查每个顶点$u$并尝试验证每个顶点是否$v$要么在其传出集合中，要么可以通过一个中间步骤到达。 这需要迭代所有$w$可从 到达$u$然后标记所有可到达的顶点$w$。 从概念上讲，我们正在为每个顶点计算两步闭包。 

这可以正常工作，但瓶颈是邻接列表上的重复并集。 在最坏的情况下，每个顶点大约有$n/2$传出边，因此所有顶点上基于边的转换总数变为二次方，并且每个转换影响最多$n$顶点。 这导致立方行为。 

关键的观察是图结构是一个锦标赛，因此我们可以将可达性集表示为位集并执行快速的联合操作。 我们不是重复迭代各个顶点，而是将每个邻接列表压缩为位掩码并使用按位或运算计算两步可达性。 这显着减少了常数因子并避免了顶点上的 Python 级嵌套循环。 

我们只需要识别三个有效顶点，而不是全部。 一旦找到三个候选者，这允许提前停止，这在实践中很重要，因为随机或结构化锦标赛中的许多顶点在计算早期就已经满足条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个顶点的强力可达性 |$O(n^3)$|$O(n^2)$| 太慢了|
 | Bitset 两步关闭 | ～$O(n^3 / w)$最坏情况，实践中更快|$O(n^2)$| 已接受 |

 这里$w$是 Python 整数位运算对机器字大小的影响。 

## 算法演练

 我们将每个顶点的出边视为一个位集，其中位$v$被设置如果$u \to v$。 

1. 构建位掩码`out[u]`对于每个顶点$u$。 这对所有直接边进行编码$u$以紧凑的形式。 
2. 定义完整的位掩码`all_mask`与所有$n$位设置。 这代表到达每个顶点。 
3. 对于每个顶点$u$，从其直接邻居开始构造其两步可达集。 我们初始化`reach = out[u]`。 
4. 对于每个顶点$w$这样$u \to w$，我们合并`out[w]`进入`reach`使用按位或。 这模拟了通过两步添加所有可到达的顶点$w$。 
5.处理完所有这些之后$w$，我们检查是否`reach`覆盖除可能之外的所有顶点$u$。 如果是，那么$u$是有效的支配顶点。 
6. 我们收集这些顶点，直到找到三个，然后立即输出它们。 
7. 如果处理完所有顶点后发现少于三个，我们输出`NOT FOUND`。 

我们可以提前停止的原因是每个顶点的条件是独立的； 找到一个有效的顶点不会影响其他顶点。 

### 为什么它有效

 对于固定顶点$u$，最多两步可到达的任何顶点要么在其直接传出集中，要么在其直接到达的某个顶点的传出集中。 所有此类邻居的位集联合精确地构造了该集合。 因为每条可能的两步路径都必须经过$u$，不遗漏任何可达顶点，也不添加任何不可达顶点。 因此，计算集正是以下两步可达闭包：$u$，并且针对全套的检查是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = [0] * n
    
    # build bitsets
    for i in range(n):
        s = input().strip()
        mask = 0
        for j, ch in enumerate(s):
            if ch == '1':
                mask |= 1 << j
        out[i] = mask

    full = (1 << n) - 1
    res = []

    for u in range(n):
        reach = out[u]
        w = out[u]
        
        # iterate over outgoing neighbors of u
        while w:
            lsb = w & -w
            v = (lsb.bit_length() - 1)
            reach |= out[v]
            w -= lsb
        
        # remove self if present
        if reach | (1 << u) == full:
            res.append(u + 1)
            if len(res) == 3:
                print(*res)
                return

    print("NOT FOUND")

if __name__ == "__main__":
    solve()
```该解决方案将每个邻接行编码为 Python 整数位掩码。 迭代设置的位`out[u]`允许我们仅访问实际的传出边缘。 对于每个这样的邻居，我们使用按位或将其邻接位掩码合并到可达性集中。 

支票`reach | (1 << u) == full`确保我们忽略顶点是否到达自身，因为定义只涉及其他顶点。 

一个微妙的点是使用提取最低有效设置位`w & -w`。 这使迭代与传出边的数量成比例，而不是$n$。

 ## 边缘情况

 关键的边缘情况是一个顶点，它具有许多传出边缘，但仍然无法满足两步到达条件，因为它的所有邻居都以结构化方式指向内部。 对于这样的顶点，直接度数会产生误导，只有第二层闭包才能揭示失败。 该算法可以正确处理此问题，因为它显式联合二级邻接集而不是依赖度。 

另一种边缘情况是恰好三个顶点满足条件。 算法必须在找到三个后立即停止； 否则会面临不必要的计算风险。 提前终止逻辑可确保正确性，而无需更改检测到的顶点集。 

最后的边缘情况是没有顶点满足条件时。 在这种情况下，位集闭包永远不会完全覆盖任何$u$，结果列表保持为空，正确触发`NOT FOUND`。
