 ## 问题理解

 我们为每个测试用例提供了两个矩形，但它们的方向不是固定的。 每个矩形仅由两条边长来描述，并且任一值都可以表示宽度或高度。 任务是确定这两个矩形是否可能来自通过垂直或水平直线切割一次切割的单个正方形，从而准确地产生这两块。 

更具体地说，我们试图确定是否存在一个正方形，这样，在将其切成两个较小的矩形（其中一个直切与正方形的边对齐）之后，可以重新排列生成的一对矩形（通过独立旋转每个矩形）以匹配给定的尺寸。 

约束范围非常小：每条边长最多为 100，并且最多有 10^4 个测试用例。 这立即表明任何恒定时间或每次测试 O(1) 推理就足够了，甚至简单的条件检查也足够快。 任何涉及搜索或模拟的事情都是不必要的，因为状态空间很小并且完全由一些几何约束来表征。 

主要的微妙之处来自方向的模糊性以及方形切割产生非常结构化的输出这一事实。 一个幼稚的错误是尝试通过独立地猜测每个矩形的边长来重建正方形，而不强制两个矩形之间的一致性。 

一些经常打破错误推理的边缘情况：

 如果两个矩形都是 2 x 3 和 3 x 1，则天真的方法可能会错误地尝试在不检查对齐约束的情况下形成边长为 5 或 4 的正方形，但这些形状无法通过单次直切一致地平铺正方形。 

如果两个矩形相同，例如 2 x 2 和 2 x 2，则仅当它们在一个方向上对齐时，它们总是形成边长为 2+2=4 的正方形，这取决于方向。 

如果一个矩形为 3 x 3，另一个矩形为 1 x 3，则可能看起来很有希望，因为它们共享边长，但除非切割产生一致的完整边长，否则它们无法形成正方形。 

## 方法

 由一条直线切割成的正方形会产生非常特殊的结构。 只有两种可能性：垂直切割或水平切割。 

如果我们想象一个边长为 S 的正方形，垂直切割会产生两个尺寸为 S × x 和 S × (S − x) 的矩形。 两个矩形必须共享相同的高度 S。类似地，水平切割生成 x × S 和 (S − x) × S，这意味着两个矩形共享相同的宽度 S。 

这一观察将问题简化为检查我们是否可以为两个矩形指定方向，以便它们共享相同的高度且宽度总和为公共 S，或者共享相同的宽度且高度总和为 S。 

强力解释是尝试两个矩形的所有可能方向，然后尝试从每个配置推断出正方形边。 由于每个矩形有 2 个方向，因此总共只有 4 种组合，对于每一种组合，我们都可以测试它们是否形成有效的正方形分区。 这已经是一项持续的工作，因此蛮力实际上是最佳的。 

关键的见解是，我们不需要重建正方形，而只需要验证一致性：两个矩形要么水平堆叠形成一个正方形（相同高度），要么垂直堆叠（相同宽度）。 

蛮力“失败”只是因为它通过显式地构造 S 来思考，从而使推理变得过于复杂，而结构已经隐式地约束了 S。

 ## 算法演练

我们通过检查两个可能的切割方向来测试这两个矩形是否可以形成正方形。 

### 1. 标准化表示

 对于每个矩形，我们通过尝试（宽度，高度）的两个分配来隐式考虑两个方向。 这是必要的，因为输入顺序是任意的。 

### 2.尝试垂直切割条件

 我们假设两个矩形具有相同的高度。 在这个假设下，我们检查它们的高度是否可以相等，以及组合宽度是否等于相同的值，这将成为正方形的边。 

如果矩形 1 是 (w1, h1)，矩形 2 是 (w2, h2)，那么我们测试：

 如果 h1 == h2，则候选正方形边为 h1，我们检查 w1 + w2 == h1。 

我们还尝试交换两个矩形的方向。 

### 3.尝试水平切割条件

 现在我们假设两个矩形具有相同的宽度。 我们测试 w1 == w2 是否以及 h1 + h2 是否等于共享宽度。 

我们再次检查所有方向交换。 

### 4.返回结果

 如果任何配置满足任一条件，我们就得出结论，存在有效的正方形结构。 

### 为什么它有效

 一次直切将一个正方形精确地分成两个轴对齐的矩形，这两个矩形必须沿一个维度完美对齐。 这迫使一个维度在两个部分上保持不变，而另一个维度相加地分裂以形成正方形边。 由于矩形方向是灵活的，枚举所有旋转可以保证我们不会错过有效的对齐。 没有其他几何配置可以通过一次切割从一个正方形产生恰好两个矩形，因此这两个条件既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ok(a, b, c, d):
    # (a,b) and (c,d)
    # try vertical cut: same height
    if b == d and a + c == b:
        return True
    # try horizontal cut: same width
    if a == c and b + d == a:
        return True
    return False

t = int(input())
for _ in range(t):
    a1, b1 = map(int, input().split())
    a2, b2 = map(int, input().split())

    # try all orientations
    if (
        ok(a1, b1, a2, b2) or
        ok(a1, b1, b2, a2) or
        ok(b1, a1, a2, b2) or
        ok(b1, a1, b2, a2)
    ):
        print("YES")
    else:
        print("NO")
```核心功能`ok`编码两种结构可能性：两个矩形共享相同的高度，并且它们的宽度总和为该高度（正方形的垂直切割），或者它们共享相同的宽度，并且它们的高度总和为该宽度（水平切割）。 外循环只是枚举所有旋转，因为输入未指定方向。 

唯一微妙的实现细节是确保所有四个方向组合都经过测试。 即使缺少一次交换也会导致有效配置的错误拒绝。

 ## 边缘情况

 关键的边缘情况是两个矩形相同。 例如，输入 (2,2) 和 (2,2) 应返回 YES，因为它们可以通过垂直或水平分割形成 4 x 4 的正方形。 该算法检查两个方向，发现一个维度匹配，而另一个维度求和正确。 

另一种边缘情况是矩形共享一条边但无法正确求和。 对于 (3,3) 和 (1,3)，算法测试两个方向。 即使在一种配置中高度匹配，宽度之和也不会形成一致的正方形边，因此所有检查都会失败并且输出正确为“否”。 

最后一种边缘情况是方向至关重要。 对于 (2,3) 和 (3,1)，简单的检查可能会错过有效的配置 (2,3) 和 (1,3)。 详尽的方向枚举可确保正确处理此情况，并生成“是”。
