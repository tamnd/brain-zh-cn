 ## 问题理解

 该系统由三个同步流组成，它们仅通过一个活动的“加载位置”进行交互。 一条流是一排火车车厢，每个车厢都有固定的所需容量。 另外两条流是矿车的循环队列，一车在车站的左侧，一车在车站的右侧，每辆矿车在倾倒满载后不断地再次可用。 

在任何时刻，只有一节车厢处于活动状态。 该车一开始是空的，必须完全装满。 当它处于活动状态时，我们可以重复选择以下三个操作之一：从队列 A 中取出前面的推车并倾倒其满载货物，从队列 B 中取出前面的推车并倾倒其满载货物，或者将两个前面的推车放在一起并同时倾倒两批货物。 使用购物车后，它会立即循环到队列的末尾。 火车车厢只有在其容量完全匹配时才会出发，然后该过程会继续下一节车厢。 

任务是确定是否存在一系列这样的选择，使得每节火车车厢都能准确地按顺序装满。 

车数量限制较小，每个队列最多 50 辆车，火车车厢最多 100 节。 然而，容量很大，每节车厢可达 200 万辆，这立即排除了任何模拟单个矿石单元运输的方法。 任何正确的解决方案都必须根据购物车负载的组合进行推理，而不是增量模拟。 

一个微妙的边缘情况来自于推车是循环且可重复使用的事实。 将每个购物车视为只能使用一次的天真的解释会错误地得出许多可行序列是不可能的结论。 例如，如果火车车厢需要重复使用大车，正确性取决于识别周期，而不是消耗。 

另一个边缘情况是，每节车厢的配对决策并不是独立的。 对早期汽车所做的选择会影响所有后来的汽车中哪些车位于前面的对齐方式。 这意味着独立解决每辆车的贪婪策略可能会失败，即使每辆车看起来孤立可行。 

## 方法

 暴力方法将尝试显式模拟每节火车车厢的所有可能的动作序列。 对于给定的汽车，在每个步骤中，我们都会在三个选项中进行选择：使用 A、使用 B 或两者都使用。 由于购物车循环，状态不仅取决于剩余容量，还取决于两个队列的当前位置。 这创建了一个大致大小的状态空间$r \cdot s \cdot \text{capacity}$，并且每个步骤的转换分支最多为三种。 即使忽略容量大小，队列的重复循环也会导致可能的配置呈指数爆炸。 

关键的结构见解是，在单个火车车厢内，重要的不是操作顺序，而是每节车厢在车厢完成之前使用了多少次。 由于每个操作都会将剩余容量减少固定量，因此每个可行的完成都对应于选择 A 车、B 车和配对使用的非负计数，以便总和与目标容量匹配。 循环性质确保在遵循计数的任何使用序列之后，系统返回到相同的相对对准模循环移位。 这将每个火车车厢变成了重复多重权重集上的约束子集和问题，除了 A 和 B 流通过配对操作耦合之外。 

我们不是探索序列，而是跟踪由火车车厢结束时我们在每个队列中的距离定义的状态。 对于每种可能的对齐状态，我们计算火车车厢的前缀是否可以完成。 这自然会导致火车车厢和队列偏移量的动态规划公式。 

对于每辆火车车厢以及 A 和 B 中的每对位置，我们检查是否可以从该对齐开始达到精确的容量，如果可以，我们会以什么新的对齐结束。由于 r 和 s 很小，因此我们可以使用有界背包式探索采用 A、B 或两者的可能组合，通过暴力方式预先计算所有开始状态上的转换。 

关键的简化是，每节火车车厢在大小为 r × s 的有限状态空间上定义了一个确定性转换函数，而我们只需要在 n 节车厢之间组合这些转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数| 高| 太慢了 |
 | 队列对齐上的状态 DP | 每个状态有界搜索的 O(n · r · s · K) | O(r·s) | 已接受 |

 ## 算法演练

 我们将状态表示为队列 A 和队列 B 中当前的前索引。因为这两个队列都是循环的，所以索引取 r 和 s 的模。 对于固定的火车车厢容量，我们想知道，从每种可能的状态来看，是否有可能准确地装满该车厢以及完成后的结果状态。 

对于每个状态，我们使用有界搜索来预先计算一个转换，即在汽车装满之前我们采取这三个动作中的每一个的次数。 

1. 对于每对索引 (i, j)，将其视为填充火车车厢之前的起始对齐。 我们尝试确定是否可以从此配置精确达到容量 c。 
2. 我们在剩余容量上运行 BFS 或 DP，其中每次转换对应于消耗来自 A 的 ai、来自 B 的 bj 或来自两者的 ai + bj。 状态包括（剩余容量，i，j）。 每次应用操作时，我们都会更新 i 和 j 对其长度取模。 
3. 如果我们恰好达到零剩余容量，则记录成功并将结果 (i, j) 存储为完成该列车车厢后的下一个对齐状态。 
4. 在计算给定汽车的转换映射后，我们将其视为将每个 (i, j) 映射到新的 (i, j) 或故障的函数 T_k。 
5. 我们从第一节火车车厢之前的 (0, 0) 开始初始化该过程。 
6. 我们对每节车厢依次应用转换，更新可达状态集。 如果在任何时候都没有状态可到达，我们就得出不可能的结论。 
7. 处理完所有车厢后，如果至少有一个状态可达，则输出成功。 

不明显的部分是，我们永远不需要记住以前汽车内的确切操作顺序。 所有相关信息都被压缩到对齐状态中，因为队列是循环的并且购物车在各个周期中是相同的。

它之所以有效，是因为每节火车车厢都充当有限状态空间上的封闭变换。 一旦一辆车装满，与未来决策相关的唯一信息就是哪辆车位于每个队列的前面。 对于所有未来的汽车来说，以同一对指数结束的任何两个历史都是可以互换的，因为系统动态仅取决于当前的前沿，而不取决于它们是如何达到的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_fill_all(r, s, n, a, b, c):
    # dp[state] = possible after processing current cars
    # state is (i, j)
    from collections import deque

    states = {(0, 0)}

    for cap in c:
        new_states = set()

        # precompute transitions for this capacity
        # memo: (i, j) -> possible resulting states
        trans = {}

        for si in range(r):
            for sj in range(s):
                # BFS over (remaining, i, j)
                dq = deque()
                dq.append((cap, si, sj))
                seen = set()
                seen.add((cap, si, sj))
                success = None

                while dq:
                    rem, i, j = dq.popleft()
                    if rem == 0:
                        success = (i, j)
                        break

                    ni = (i + 1) % r
                    nj = (j + 1) % s

                    # take A
                    if rem >= a[i] and (rem - a[i], ni, j) not in seen:
                        seen.add((rem - a[i], ni, j))
                        dq.append((rem - a[i], ni, j))

                    # take B
                    if rem >= b[j] and (rem - b[j], i, nj) not in seen:
                        seen.add((rem - b[j], i, nj))
                        dq.append((rem - b[j], i, nj))

                    # take both
                    if rem >= a[i] + b[j] and (rem - a[i] - b[j], ni, nj) not in seen:
                        seen.add((rem - a[i] - b[j], ni, nj))
                        dq.append((rem - a[i] - b[i], ni, nj))

                if success is not None:
                    trans[(si, sj)] = success

        for st in states:
            if st in trans:
                new_states.add(trans[st])

        states = new_states
        if not states:
            return False

    return True

def main():
    r, s, n = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    print("Yes" if can_fill_all(r, s, n, a, b, c) else "No")

if __name__ == "__main__":
    main()
```该实现为每个火车车厢构建一个转换图，描述两个队列的给定起始对齐在完全装满该车厢后如何演变。 BFS 探索了使用仅 A、仅 B 或配对移动来减少剩余容量的所有方法，同时循环更新队列索引。 

一个关键的实现细节是 BFS 状态包括剩余容量和两个索引。 访问集是强制性的，因为如果没有它，搜索就会由于循环队列而无休止地重新访问相同的配置。 

另一个微妙之处是，每个起始状态的转换都是独立计算的。 考虑到 r 和 s 的界限较小，这是昂贵的，但也是必要的。 一旦计算出转换，火车车厢上的全局 DP 就变成了简单的状态传播。

 ## 边缘情况

 第一种边缘情况是，由于骑自行车，仅重复使用单个车厢即可填充火车车厢。 该算法可以处理此问题，因为 BFS 允许在模更新后重新访问相同的索引，因此重复的贡献会正确累积，直到达到容量。 

另一个边缘情况是唯一有效的解决方案需要在特定步骤同步使用两个队列。 由于 BFS 明确包含组合转换，因此此类路径与单队列移动一起探索，确保不会遗漏任何有效的分解。 

最后一个边缘情况是，早期的火车车厢强制进行特定的对齐，这使得后来的火车无法进行。 状态上的 DP 正确地捕获了这一点，因为无法到达的转换完全消除了这些状态，而不是允许不一致的历史持续存在。
