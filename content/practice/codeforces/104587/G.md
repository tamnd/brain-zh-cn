 ## 解决方案
 ## 问题理解

 我们保持不断变化的标记团队排名$T_1$通过$T_n$。 最初，排名固定为递增索引顺序，因此$T_1$是第一个并且$T_n$是最后一个。 然后我们处理一系列比赛结果，其中每个结果都表明一支球队击败了另一支球队。 

每场比赛仅在获胜球队当前排名比其击败的失败球队差时影响排名。 如果获胜者的排名已经较高，则不会发生任何变化。 如果获胜者排名较低，我们会将其从当前位置删除并将其重新插入对手的正上方，从而将其“提升”到被击败的球队之上，同时保留所有未受影响球队的相对顺序。 

因此，该过程是由当前位置比较驱动的一系列稳定列表插入，而不是原始索引。 输出是按时间顺序处理所有匹配后的最终排序。 

约束很小，有$n \le 100$和$m \le 100$。 这立即表明任何在团队数量上具有二次甚至三次行为的算法都是安全的。 我们可以自由地模拟数组上的重新排序操作，而不必担心性能瓶颈。 

当多场比赛涉及同一对球员或重复晋升累积时，就会出现微妙的边缘情况。 排名是动态的，因此球队在比赛时的位置而不是其初始位置很重要。 

例如，考虑最初由三个团队组成的场景$T_1, T_2, T_3$。 如果我们处理$T_3$节拍$T_2$， 然后$T_3$向上移动。 稍后如果$T_3$节拍$T_1$，第二个操作使用更新后的位置，而不是原始排序。 任何仅使用初始索引的解决方案都会在这里失败。 

另一个重要的边缘情况是赢家已经高于输家的情况。 例如，如果当前订单是$T_1, T_2, T_3$我们处理$T_1$节拍$T_3$，即使指数显示存在缺口，也没有任何变化。 这个条件纯粹是位置性的。 

## 方法

 直接模拟是很自然的。 我们将排名保留为数组或列表。 对于每场比赛，我们都会找到两支球队当前的指数。 如果赢家已经领先于输家，我们什么也不做。 否则，我们将获胜者从其当前位置删除并将其插入到失败者之前，将中间段向左移动一步。 

这是正确的，因为它完全遵循问题陈述。 唯一的挑战是干净地实施“逐段移动”操作。 

强力复杂性来自搜索位置和执行列表操作。 团队索引的每次查找成本$O(n)$，并且每次插入都需要移位到$O(n)$元素。 和$m$操作，总成本为$O(mn)$，这最多是$10^4$，很容易在限制内。 

不需要平衡树或链表等高级数据结构，因为$n$很小。 一个简单的数组加上一个将团队名称映射到索引的字典（或每次直接重新计算索引）就足够了。 

关键的见解是排名是本地剪切和插入操作下的排列。 由于每个操作仅影响连续的段并保留内部顺序，因此直接模拟在约束下已经是最佳的。

 ## 算法演练

 我们直接模拟排名。 

1. 初始化一个列表`order`包含以下形式的团队`T1, T2, ..., Tn`。 这始终代表当前的排名。 
2. 每场比赛的球队$A$击败团队$B$，找到他们当前的位置`order`。 我们扫描列表或使用映射（如果已维护）。 
3. 如果位置$A$小于 的位置$B$，什么也不做，因为排名已经与结果一致。 
4. 如果位置$A$大于的位置$B$， 消除$A$从目前的位置。 
5. 插入$A$在索引处$B$。 这有效地放置了$A$正上方$B$，将所有干预球队下移一位。 
6. 继续按顺序处理所有匹配项。 

微妙之处在于删除发生在插入之前，否则索引会错误地移动。 从概念上讲，该操作是剪切和粘贴，而不是交换或本地调整。 

### 为什么它有效

 排名始终是球队的排列，并且每次操作都强制执行一个新的约束：如果获胜者之前位于失败者下方，则获胜者必须出现在失败者的正上方。 所有其他相关顺序保持不变，因为问题明确指出不存在其他证据可以修改它们。 由于每个操作仅引入与规则一致的单个局部校正，因此随着时间的推移，重复应用可以保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    order = ["T" + str(i) for i in range(1, n + 1)]

    for _ in range(m):
        a, b = input().split()

        ia = order.index(a)
        ib = order.index(b)

        if ia > ib:
            order.pop(ia)
            order.insert(ib, a)

    print(" ".join(order))

if __name__ == "__main__":
    main()
```实现几乎逐字遵循该算法。 名单`order`存储当前排名。 每个查询都使用`.index()`找到职位，这是可以接受的，因为$n \le 100$。 条件`ia > ib`准确捕捉排名与比赛结果相矛盾的情况。 

关键的实现细节是在插入之前先删除获胜者。 如果先插入，索引就会发生变化，最终的位置也会不正确。 使用字符串标识符，例如`"T3"`直接匹配输入格式，避免任何解析开销。

 ## 边缘情况

 一个重要的边缘情况是一支球队屡次获胜并不断进步。 考虑输入：```
4 3
T4 T3
T4 T2
T4 T1
```执行开始于`T1 T2 T3 T4`。 

后`T4 beats T3`，顺序变为`T1 T2 T4 T3`。 后`T4 beats T2`，就变成`T1 T4 T2 T3`。 后`T4 beats T1`，就变成`T4 T1 T2 T3`。 

在每一步中，算法都会删除`T4`并将其重新插入到其对手上方，保留所有其他相对顺序。 这表明多个向上运动可以正确组合，无需任何全局重新计算。 

另一个边缘情况是胜利不会触发移动。 例如：```
3 1
T1 T3
```初始订单是`T1 T2 T3`。 自从`T1`已经在上面了`T3`，条件`ia > ib`失败并且列表保持不变。 该算法正确地避免了不必要的修改，从而保持了不相关片段的稳定性。
