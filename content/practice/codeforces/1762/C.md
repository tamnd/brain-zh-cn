 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串`s`。 For every prefix of`s`，我们定义一个值`f(prefix)`。 

计算`f(x)`，我们看看所有可能的扩展`x`。 如果`x`有长度`k`，扩展有长度`2k-1`。 的人物`x`固定在扩展的奇数位置，而每个偶数位置可以自由选择`0`或者`1`。 

在这些扩展中，我们计算有多少是“好的”。 

好的扩展具有特殊的属性。 对于每个奇数位置`i`, 位置处的字符`i`必须等于结束于的前缀的中位数`i`。 由于字母表是二进制的，因此中位数只是该奇数长度前缀中的多数值。 

对于每个测试用例，我们必须计算$$\sum_{i=1}^{n} f(s[1..i])$$模数`998244353`。 

所有测试用例的总长度最多为`2·10^5`。 任何独立处理每个前缀并枚举扩展名的解决方案都是不可能的。 即使是单个长度前缀`200000`有`2^{199999}`扩展。 每个测试用例我们需要一个线性或近线性的解决方案。 

错误的一个微妙来源是误解中值条件的含义。 

考虑：```
s = 11
```扩展名是：```
101
111
```两者都很好，所以`f(11)=2`。 

现在考虑：```
s = 01
```扩展名是：```
001
011
```仅有的`011`很好，所以`f(01)=1`。 

假设每个偶数位置始终是空闲的解决方案将会过度计数。 

当运行发生变化时，另一个容易出现的错误就会出现。 

考虑：```
s = 010
```答案是：```
f(0)=1
f(01)=1
f(010)=1
```全部的`3`。 

当相邻字符不同时，良好扩展的数量就不再增加一倍。 

## 方法

 蛮力解释很简单。 对于每个前缀，生成所有`2^{len-1}`扩展名，检查每个扩展名是否满足中值条件，并统计有效的扩展名。 

这是正确的，因为它直接遵循定义。 不幸的是，对于长度前缀`k`， 有`2^{k-1}`扩展。 和`k`一样大`200000`，这是没有希望的。 

关键的观察结果来自于检查中值条件实际施加的内容。 

假设我们已经处理了一个以奇数位置结尾的前缀`2i-1`。 当我们扩展到奇数位置时`2i+1`，我们在两个固定位之间恰好插入一个空闲位。 

设固定位为：```
a_i and a_{i+1}
```如果这两个比特不同，则插入的比特就完全确定了。 确实存在一种保留中值条件的选择。 

如果这两个位相等，则插入位有两个有效选择。 

这将看似全局的中值约束转换为原始字符串的连续字符之间的简单局部规则。 

让`dp[i]`表示前缀的良好扩展的数量`s[1..i]`。 

什么时候：```
s[i] != s[i-1]
```计数不变。 

什么时候：```
s[i] == s[i-1]
```计数加倍。 

更准确地说：```
dp[1] = 1

dp[i] =
dp[i-1]                  if s[i] != s[i-1]
2 * dp[i-1]             if s[i] == s[i-1]
```由于最终答案是所有答案的总和`dp[i]`，我们可以一次性计算出所有内容。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化`cur = 1`。 

这代表`f(s[1])`。 单个角色恰好有一个好的扩展。 
2. 初始化`answer = 1`。 

我们已经知道第一个前缀的贡献。 
3. 从位置开始迭代`2`定位`n`。 
4.如果`s[i] == s[i-1]`, 乘以`cur`经过`2`。 

对于新插入的偶数位置位，存在两种有效选择。 
5. 如果`s[i] != s[i-1]`， 离开`cur`不变。 

插入的位是强制的，因此良好扩展的数量不会增加。 
6. 添加`cur`到运行的答案。 
7. 执行所有模运算`998244353`。 
8. 输出最终答案。 

### 为什么它有效

 让`g_i`是前缀的良好扩展的数量`s[1..i]`。 

从前缀长度移动`i-1`到`i`在扩展中引入了一个新的空闲位置。 

如果新添加的固定字符等于先前的固定字符，则可以将任一值放置在插入位置，而不会违反中位条件。 每个先前的有效扩展都会生成两个新的有效扩展。 

如果新添加的固定字符与前一个不同，则可以插入恰好一个值，同时保持所需的中位关系。 每个先前的有效扩展都会生成一个新的有效扩展。 

因此：$$g_i = \begin{cases} 2g_{i-1} & s_i=s_{i-1}\\ g_{i-1} & s_i\ne s_{i-1} \end{cases}$$这个循环计算所有好的扩展并且只计算好的扩展。 总结所有`g_i`给出所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    cur = 1
    ans = 1

    for i in range(1, n):
        if s[i] == s[i - 1]:
            cur = (cur * 2) % MOD

        ans = (ans + cur) % MOD

    print(ans)
```变量`cur`存储当前前缀的良好扩展名的数量。 每当两个相邻字符相等时，每个现有扩展都会分成两个有效的延续，因此`cur`双打。 

当相邻字符不同时，不会发生新的分支。 计数保持不变。 

答案是`cur`覆盖所有前缀。 

唯一重要的实现细节是在乘法和加法之后立即应用模数。

 ## 边缘情况

 考虑：```
n = 1
s = 0
```只有一个前缀。 该算法开始于`cur = 1`并且永远不会进入循环。 答案是`1`，这是正确的。 

考虑：```
s = 0000
```的价值观`cur`变得：```
1, 2, 4, 8
```答案变成：```
1 + 2 + 4 + 8 = 15
```每个相邻对都是相等的，因此每一步都会使良好扩展的数量加倍。 

考虑：```
s = 010101
```每个相邻的对都不同。 的价值`cur`永远保留`1`。 答案很简单，就是前缀的数量：```
6
```这证实了相邻位之间的变化消除了所有分支并仅留下一个有效的扩展路径。
