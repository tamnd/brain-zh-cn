 ## 解决方案
 ## 问题理解

 我们有两个数组和一个固定整数$m$。 从第一个数组开始，我们可以重复分割一个可以整除的元素$m$进入$m$相等的部分，或合并$m$连续相等的元素合并为一个较大的元素。 

问题是这些操作是否允许我们将第一个数组转换为第二个数组。 

这些操作看起来很复杂，因为数组长度发生变化，并且可能有许多不同的移动顺序。 关键的观察结果是，这两种操作都不会更改隐藏在元素内的“原子值”。 

取一个元素$x$。 反复除以$m$虽然可能：$$x = base \cdot m^t$$在哪里$base$不再能被整除$m$。 

例如，当$m=2$,$$12 = 3 \cdot 2^2$$和$$8 = 1 \cdot 2^3.$$拆分操作仅移动权力$m$值和份数之间。 底层的$base$永远不会改变。 

这些约束强烈表明我们需要一个近线性的解决方案。 所有测试用例的所有数组长度之和最多为$2 \cdot 10^5$。 一个$O(n^2)$算法需要大约$4 \cdot 10^{10}$最坏情况下的操作，远远超出了极限。 解决方案围绕$O(n)$或者$O(n \log n)$每个测试用例都是必需的。 

一些边缘情况很容易被错误处理。 

考虑：```
m = 2
a = [8]
b = [4,4]
```正确答案是`Yes`。 仅逐个元素比较数组的解决方案会错误地拒绝它。 分叉转弯$8$一分为二$4$的。 

考虑：```
m = 2
a = [2,2]
b = [4]
```正确答案是`Yes`。 这里的转换需要合并而不是分裂。 

考虑：```
m = 2
a = [2,4]
b = [1,1,1,1,1,1]
```正确答案是`Yes`。 

全面展开后：$$2 \to (1,2),\quad 4 \to (1,4)$$提供六份基本价值$1$。 如果不小心实现将两个组分开，就会错过具有相同基数的相邻组可能合并的情况。 

考虑：```
m = 3
a = [3,3]
b = [9]
```正确答案是`No`。 

每个$3$贡献一份基础副本$1$。 他们一起贡献两个副本，但合并需要精确的组$m=3$。 我们无法创建一个单一的$9$。 

## 方法

 暴力方法会尝试模拟所有可能的拆分和合并序列。 这在原则上是正确的，因为每个可到达的数组最终都可以被探索。 

问题在于状态空间的大小。 即使是单个值，例如$$10^9 = 2^9 \cdot 1953125$$可以多次分割，创建指数级的中间数组。 可到达的配置数量增长得太快，无法进行详尽的搜索。 

突破来自于审视那些永远不会改变的东西。 

取一个元素$x$。 消除所有可能的因素$m$：$$x = base \cdot m^t.$$如果我们全面展开$x$，就变成$$base$$重复$m^t$次。 

例如，与$m=2$,$$12 = 3 \cdot 2^2$$其行为与四个副本完全相同$3$。 

这些基值的顺序永远不会改变。 运营仅重新分配权力$m$在对应于相同基值的连续块内。 

这意味着每个元素都可以表示为一对：$$(base,\ count)$$在哪里$$count = m^t.$$为了$12$和$m=2$，这对是$(3,4)$。 

具有相同碱基的相邻对可以合并，因为它们的展开形式是无法区分的。 以这种方式压缩整个数组后，转换问题变为：

 执行两个压缩序列$(base,count)$配对完全匹配吗？ 

如果是，则数组表示相同的完全展开的序列并且是相互可达的。 如果不匹配，则任何操作序列都无法修复不匹配的情况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳 |$O((n+k)\log_m V)$|$O(n+k)$| 已接受 |

 这里$V \le 10^9$是最大的元素值。 

## 算法演练

 1. 从左到右处理第一个数组。 
2. 对于每个值$x$, 反复除以$m$同时可分割。 设剩余值为`base`。 
3. 计算有多少个因数$m$被删除。 如果$x = base \cdot m^t$，那么这个元素贡献`cnt = m^t`的副本`base`。 
4. 存储该对`(base, cnt)`。 
5. 如果之前存储的对具有相同的`base`，将计数加在一起而不是创建一个新的对。 

这是有效的，因为具有相同基数的相邻块表示相同扩展值的连续副本。 
6. 对第二个阵列重复相同的压缩过程。 
7. 比较两个结果对序列。 
8. 如果序列相同，则打印`Yes`。 否则打印`No`。 

### 为什么它有效

 对于每个元素$x$，值$$base = \frac{x}{m^t}$$任何操作都无法更改。 

分裂皈依者$$(base,m^t)$$进入$m$的副本$$(base,m^{t-1}),$$而合并则执行相反的变换。 

因此，每个操作都保留扩展后的基值序列。 唯一的自由是如何将基值的总重数分组为元素。 

将相邻的相等碱基压缩为单个计数后，我们获得了规范表示。 当且仅当这些规范表示相同时，两个数组才可以相互访问。 该算法精确地计算该表示并比较结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def normalize(arr, m):
    res = []

    for x in arr:
        base = x
        cnt = 1

        while base % m == 0:
            base //= m
            cnt *= m

        if res and res[-1][0] == base:
            res[-1][1] += cnt
        else:
            res.append([base, cnt])

    return res

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        k = int(input())
        b = list(map(int, input().split()))

        na = normalize(a, m)
        nb = normalize(b, m)

        ans.append("Yes" if na == nb else "No")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`normalize`函数构建规范表示。 每个数字都减少到其不可分割的基值，并且去除的幂$m$被转换成多重计数。 

微妙的部分是将具有相同基础的相邻条目合并。 如果没有这一步，数组如`[2,4]`和`[1,1,1,1,1,1]`即使它们代表相同的扩展序列，也会以不同的方式标准化。 

计数直接存储为$m^t$。 由于每个原始值最多是$10^9$，重复乘法仍然安全地保持在 Python 的整数范围内。 

最终的比较只是两个对列表之间的相等性。 一旦规范形式匹配，每个必要的拆分或合并序列都会自动存在。

 ## 边缘情况

 考虑：```
m = 2
a = [8]
b = [4,4]
```标准化给出：```
a -> [(1,8)]
b -> [(1,8)]
```算法返回`Yes`。 实际的变换是通过分裂得到的$8$一次。 

考虑：```
m = 2
a = [2,2]
b = [4]
```标准化给出：```
a -> [(1,4)]
b -> [(1,4)]
```算法返回`Yes`。 相应的操作是将两个相等的值合并。 

考虑：```
m = 2
a = [2,4]
b = [1,1,1,1,1,1]
```标准化给出：```
a -> [(1,6)]
b -> [(1,6)]
```关键的一步是将相邻条目与基值组合起来$1$。 如果没有这种压缩，左侧将显示为`[(1,2),(1,4)]`并且比较会错误地失败。 

考虑：```
m = 3
a = [3,3]
b = [9]
```标准化给出：```
a -> [(1,6)]
b -> [(1,9)]
```计数不同，因此算法返回`No`。 即使所有基值都匹配，但没有足够的多重性来创建单个$9$。
