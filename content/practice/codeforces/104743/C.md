 ## 解决方案
 ## 问题理解

 我们得到一个非负整数数组。 我们可以修改元素，但是每次修改都有一个非常具体的规则：如果我们选择位置`i`，我们覆盖`a[i]`前缀的 MEX 严格位于其前面，表示未出现在中的最小非负整数`a[1..i-1]`。 对于第一个位置，前缀为空，因此 MEX 为`0`。 

目标不是应用固定数量的操作或最小化操作。 相反，我们希望达到字典顺序上最小的任何可到达的数组配置，这意味着我们关心尽可能积极地改进早期位置，即使这会迫使以后发生变化。 

关键的困难在于，更改较早的元素会更改所有未来的前缀 MEX 值，从而影响后面的位置。 所以问题是对一系列局部相关变换的全局优化。 

这些约束意味着所有测试用例的总长度最多为 5×10^5，因此每个测试用例的任何解决方案都必须接近线性。 具有大量每个索引重新计算的二次甚至 n log n 方法将会失败。 任何从头开始为每个位置重新计算 MEX 的方法都会立即变得太慢，因为除非仔细维护，否则 MEX 计算至少是线性的。 

一个微妙的边缘情况是早期元素很大或不相关。 例如，如果数组以大值开头，例如`[100, 200, 300]`，天真的想法可能表明不存在有用的操作。 但是替换第一个元素会迫使它变成`0`，然后重塑所有未来的 MEX 值。 

另一种边缘情况是当数组已经包含小的连续段时，例如`[0,1,2,...]`。 在这种情况下，将元素更改为 MEX 可能会暂时引入重复或破坏结构，但这样做仍然可以更早地改善字典顺序。 

## 方法

 暴力策略会模拟这个过程：在每个位置，决定是保留当前值还是用前一个前缀的 MEX 替换它，然后递归地探索所有可能性。 这形成了一个决策树，其中每个节点根据我们是否修改位置进行分支`i`或不。 前缀的 MEX 可以增量维护，但分支仍然会导致状态数量呈指数增长。 

即使是每次从左到右处理并重新计算 MEX 的贪婪模拟也需要维护频率结构并在每次操作时更新它。 如果我们对每个索引重新计算 MEX，则每次计算都是 O(n)，导致每个测试用例的 O(n^2)，这远远超出了限制。 

关键的结构见解是，我们引入的唯一有用的值是前缀的 MEX 值，并且这些值在受控方式下始终很小且单调。 一旦我们观察到 MEX 仅取决于哪些数字`0,1,2,...`到目前为止，我们可以在从左到右贪婪地构造答案的同时维护一个动态的“已见集”。 

然后我们重新解释问题：我们不选择任意操作，而是决定每个位置是否强制执行前缀历史允许的最小可能值。 由于字典顺序优先考虑较早的位置，因此考虑到较早的决策是固定的，我们总是希望每个索引处可实现的最小值。 

这导致了贪婪的构造，我们模拟构建有效前缀的过程，跟踪哪些数字已以影响未来 MEX 值的方式“消耗”，并为每个位置分配与可达性一致的最佳可能值。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 贪婪的 MEX 建设 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 我们从左到右处理数组，维护一个跟踪哪些小整数已经出现在构造的前缀中的结构。 该结构仅用于有效计算当前 MEX。 
2. 在每个索引处`i`，我们计算当前前缀状态的 MEX。 这代表我们可以在该位置强制的最小值`i`如果我们选择覆盖它。 
3.我们决定是否可以改进`a[i]`用这个 MEX 替换它。 由于字典顺序优先考虑较小的值，因此如果 MEX 小于当前值，我们将应用该操作。 
4. 当我们分配一个值（原始值或 MEX）时，我们会相应地更新“已看到”结构。 这可确保未来的 MEX 计算反映实际构造的前缀。 
5. 我们继续这个过程直到数组末尾，始终在每一步都承诺最小的可行值。 

微妙之处在于，我们不是模拟任意操作序列，而是通过确保每个前缀与 MEX 替换的某些有效序列一致来直接构建最佳可达结果。 

### 为什么它有效

 该算法在每个索引处都保持不变`i`，可以使用有效操作从原始数组访问构造的前缀。 MEX 的位置`i`仅取决于哪些值已被强制放入较早的位置，以及在该位置分配的任何值`i`正是可以通过该索引的合法操作生成的值。 由于字典顺序取决于第一个不同的位置，因此在可达性约束下最小化每个位置会产生全局最小序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # We only care about small values for mex tracking
        seen = set()
        mex = 0

        res = [0] * n

        for i in range(n):
            # update mex to current smallest missing
            while mex in seen:
                mex += 1

            # we may choose to overwrite with mex or keep original
            # but lexicographically we prefer smaller value if achievable
            if mex < a[i]:
                res[i] = mex
                seen.add(mex)
            else:
                res[i] = a[i]
                seen.add(a[i])

            while mex in seen:
                mex += 1

        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现保留了`seen`设置已固定到结果前缀中的值。 变量`mex`是增量维护的，因此每个整数最多前进一次，从而提供线性摊销行为。 

在每个索引处，我们将当前 MEX 与原始值进行比较。 如果 MEX 较小，则替换会立即改善字典顺序。 否则，保留原件是最佳选择，因为任何替换只会增加价值。 

第二次更新为`mex`插入后可确保一致性：添加值后，未来的 MEX 值会正确跳过它。

 ## 边缘情况

 对于像这样的输入`[0]`，算法初始化`mex = 0`，看到`0`已经相等，并保持不变。 该集合变为`{0}`输出是`0`，匹配正确性。 

为了`[5]`,`mex = 0`小于`5`，所以我们将其替换为`0`。 这是有效的，因为选择`i = 1`总是产生空前缀的 MEX，即`0`。 

为了`[0,1,2,3]`，每个值都会被保留，因为在每一步 MEX 都等于当前值，因此不可能进行改进。 不变量确保我们永远不会降级前缀，因此恒等变换被正确保留。
