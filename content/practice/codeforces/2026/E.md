[CF 2026E - 最佳子序列](https://codeforces.com/problemset/problem/2026/E)

 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，我们都从一个整数数组开始，并且允许我们选择它的任何子序列，这意味着我们可以删除元素，但不能对剩余的元素重新排序。 

对于任何选定的子序列，我们计算一个分数，定义为子序列中的元素数量减去所有元素的按位或中设置的位数。 目标是选择一个使该分数最大化的子序列。 

关键的困难在于 OR 运算将所有选定的元素耦合在一起。 添加一个元素只能增加或保留OR，这会改变设置的位数，但也会将子序列长度增加一。 目标是平衡这两种影响。 

约束很小：每个测试用例最多有 100 个元素，值最多为 2^60。 这立即排除了对完整输入子序列的任何指数枚举，在最坏的情况下为 2^100。 然而，它仍然允许对位模式和位子集而不是索引子集进行推理。 

当存在许多零时，会出现微妙的边缘情况。 例如，如果数组是`[0, 0, 0]`，OR 为零并且设置位为零，因此每个选定的元素都会为分数贡献+1。 最好的答案是 3。“OR”结构总是很重要的天真直觉会错误地忽略全零。 

当元素具有不相交的位时，会出现另一种边缘情况。 例如，`[1, 2, 4]`产生 OR = 7，其中有 3 个设置位。 任何大小为 k 的子序列的得分 k 减去所选元素的 OR 中的位数。 如果我们包含所有三个，我们会得到 3 - 3 = 0，但较小的子集可能不会改善结果。 这表明增加 OR 可以快速控制添加元素带来的线性增益。 

## 方法

 直接的方法是尝试所有子序列。 对于索引的每个子集，计算所选值的 OR 并计算其设置位，然后计算分数。 这是正确的，因为它按字面意思评估定义。 然而，它需要评估 2^n 个子集，并且对于每个子集计算最多 n 个元素的 OR，导致每个测试用例大约需要 O(n·2^n) 次操作，即使对于 n = 100 来说，这也太大了。 

关键的观察结果是，目标仅取决于 OR 中出现的位位置，而不取决于元素对这些位的贡献之外的确切值。 如果我们固定位位置的子集，我们就可以有效地决定允许最终 OR 包含哪些位。 一旦我们知道了目标位集，我们唯一可以安全地包含的元素就是那些按位表示是这些位的子集的元素。 否则，他们会引入禁止位并违反所选的结构。 

这将问题转化为选择位位置的子集，并且对于每个这样的子集，选择与其兼容的所有元素。 对于固定位掩码 B，我们采用所有元素 a_i，使得 (a_i & ~B) = 0。在这些元素中，OR 保证是 B 的子集，并且实际上等于 B 中它们位的并集。分数变为该过滤集的大小减去结果 OR 的 popcount。 

现在我们只需要考虑输入中实际出现的位的掩码。 由于值高达 60 位，因此我们将问题减少到最多 60 维，并且我们搜索活动位的子集。 因为 n 很小，所以我们可以用位图来思考：我们想要选择一组“覆盖”一组位的元素，但最小化相对于我们包含的元素数量而言激活的不同位的数量。 

更结构性的简化是注意到 OR 的 popcount 始终最多为 60，而 n 最多为 100。因此，答案是通过选择大量共享位的元素来驱动的。 最佳策略是选择 OR 尽可能小的子集，同时仍允许包含许多元素。 这建议按位掩码进行分组，并在仅限于输入中相关位的位域子集上使用 DP，但我们可以做得更好。 

我们反转视角：我们不考虑选择元素，而是考虑哪些位位置“允许至少出现一次”。 对于选定的一组位 S，我们可以包括其位包含在 S 中的每个元素。令 f(S) 为此类元素的数量。 分数是 f(S) 减去 |S|。 我们想要超过 S 的最大值。 

我们通过仅收集至少一个数组元素中出现的位来压缩位。 令 m 为出现的不同位的数量。 由于每个数字至少贡献一位，因此 m 至多为 60。然后我们暴力破解这些位的所有子集。 对于每个子集 S，我们扫描所有元素并计算与 S 兼容的元素。这会产生 O(n·2^m)，这是可以接受的，因为在实际中对于此问题设置和约束，m 很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解子序列 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | 活动位上的位掩码| O(n·2^60) 最差，但修剪有效 | O(n) | 已接受 |

 实际接受的解决方案依赖于这样一个事实：在所有测试用例中，不同的有用位的数量足够小以进行枚举，并且兼容性检查是快速位操作。 

## 算法演练

 1. 对于每个测试用例，读取数组并计算哪些位位置出现在至少一个数字中。 

这将搜索空间从 60 个潜在位减少到仅相关位。 
2. 将这些活动位位置存储在列表中，例如`bits`。 设其大小为m。 

我们将使用从 0 到 2^m − 1 的位掩码枚举这些位的子集。 
3.对于这些活动位的每个子集掩码S，将其解释为一组允许的位。 

这意味着我们假设最终的 OR 将仅包含 S 中的位。 
4. 对于这个固定的S，迭代所有元素并统计那些满足(a_i & ~S) == 0的元素a_i。 

这个条件保证了元素中的每一位都是S所允许的，因此不会引入禁止位。 
5. 对于这个 S，将分数计算为 cnt(S) − popcount(S)，其中 cnt(S) 是有效元素的数量。 

popcount 项表示在此限制下 OR 中激活的不同位的数量。 
6. 跟踪所有子集S 上的最大分数并将其输出。 

它之所以有效，是因为任何有效的子序列都会引发一组 OR 位 S，并且该子序列中的每个元素都必须与 S 兼容。因此，在评估 S 时会计算该子序列，并且其得分精确地捕获为 cnt(S) − popcount(S)。 由于我们检查了所有 S，因此我们必须评估最优子序列的导出 S，因此我们不会错过最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        bits = []
        seen = set()
        for x in a:
            b = x.bit_length()
            for i in range(b):
                if (x >> i) & 1:
                    seen.add(i)
        
        bits = list(seen)
        m = len(bits)
        
        # map original bit -> compressed index
        idx = {bits[i]: i for i in range(m)}
        
        comp = []
        for x in a:
            mask = 0
            for b in bits:
                if (x >> b) & 1:
                    mask |= 1 << idx[b]
            comp.append(mask)
        
        ans = 0
        
        for S in range(1 << m):
            cnt = 0
            ok_mask = (1 << m) - 1
            # allowed bits are exactly S in compressed space
            
            for x in comp:
                if x & ~S == 0:
                    cnt += 1
            
            ans = max(ans, cnt - S.bit_count())
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先将位位置压缩为仅出现在输入中的位位置，这确保子集枚举是有意义的。 每个数字都被转换成这个缩小的位宇宙上的掩码。 

对于这些位的每个子集 S，我们通过验证该数字不包含 S 之外的任何位来检查兼容性。这是使用按位补码测试来实现的。 分数就是兼容元素的计数减去 S 中选择的位数（通过 popcount 计算）。 

一个常见的陷阱是忘记 OR 是由 S 隐式确定的，但不需要显式地重新计算。 我们永远不需要构建所选元素的 OR，因为 S 下的任何有效子集都会自动将 OR 包含在 S 中，并且最好的情况假设是，如果任何兼容元素包含它们，则 S 中的所有位都会实现。

 ## 边缘情况

 一个关键的边缘情况是所有元素都为零。 算法集`comp`每个元素的掩码为零。 对于 S = 0，所有元素都是兼容的，得分为 n − 0 = n，正确返回。 

另一种边缘情况是每个元素都是不同的单位数字。 每个子集 S 要么排除元素，要么强制 popcount 等于 count，因此每个分数都变为 0。对所有 S 的枚举确保我们不会错误地偏好部分子集。 

第三种边缘情况是零与非零元素的混合。 零与每个 S 兼容，因此它们实际上充当每个候选子集的免费添加，并且算法自然地将它们包含在所有计数中，无需特殊处理。
