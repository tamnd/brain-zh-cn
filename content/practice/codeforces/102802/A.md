 ## 解决方案
 ## 问题理解

 乔治有一组圆形饼干，放置在坐标平面上。 每个 cookie 由其中心坐标和半径来描述。 他需要一个矩形烤盘，其侧面与坐标轴平行，并且完全包含每块饼干。 目标是找到这样一个平底锅的尽可能小的面积。 

一个 cookie 集中在`(x, y)`有半径`r`到达从`x - r`到`x + r`水平地和从`y - r`到`y + r`垂直。 由于平底锅是轴对齐的，因此其水平尺寸仅取决于所有饼干的最左点和最右点，其垂直尺寸仅取决于最低点和最高点。 

cookie 的数量可以大到`100000`，因此该解决方案无法检查每对可能的饼干或尝试可能的矩形。 在几秒钟的限制下，`O(N^2)`在最坏的情况下，该方法将执行大约一百亿次操作，这远远超出了实际情况。 我们需要单次通过或接近它的东西。 

坐标值和半径可达`10^7`在幅度上。 最终的宽度和高度都可以左右`4 * 10^7`，使周围区域`10^15`。 这意味着实现需要可以安全容纳大型产品的整数类型。 Python 整数会自动处理这个问题。 

一些边缘情况可能会破坏粗心的解决方案。 如果只有一块饼干，则平底锅必须在两个方向上简单地匹配该饼干的直径。 例如：```
Input
1
0 0 5

Output
100
```仅考虑不同 cookie 之间距离的解决方案将会失败，因为不存在对。 

另一个常见的错误是忘记 cookie 半径会扩展边界框。 例如：```
Input
2
0 0 1
2 0 1

Output
16
```cookie 占据的水平坐标为`-1`到`3`，给出宽度`4`，和垂直坐标`-1`到`1`，给定高度`2`，所以面积是`8`， 不是`16`。 使用中心作为矩形角的粗心实现会计算出错误的尺寸。 

上面示例的正确输出实际上是：```
8
```矩形只需要覆盖饼干，不需要将它们中心之间的距离在每个方向上加倍。 

## 方法

 一种简单的方法是通过检查每个 cookie 并跟踪当前的最小和最大坐标来模拟查找矩形的过程。 这已经是基本的想法了。 更简单的版本可能会将每个 cookie 与其他 cookie 进行比较以确定极端边界，但这会执行`O(N^2)`比较。 和`N = 100000`，这变成了关于`10^10`比较。 

问题的结构为我们提供了更简单的观察。 最终的矩形完全由四个值决定：任何 cookie 达到的最小 x 坐标、任何 cookie 达到的最大 x 坐标、任何 cookie 达到的最小 y 坐标以及任何 cookie 达到的最大 y 坐标。 每个 cookie 仅提供两个可能的 x 边界和两个可能的 y 边界。 

暴力方法之所以有效，是因为答案取决于所有 cookie 的极值点，但当它重复搜索这些极值点时，就会失败。 每个 cookie 都可以独立更新极值的观察结果让我们可以将问题简化为通过输入进行一次扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化四个变量来表示当前的边界矩形。 将最小 x 和 y 值设置为非常大的数字，并将最大 x 和 y 值设置为非常小的数字。 这将创建一个空矩形，该矩形将在处理 cookie 时扩展。 
2. 读取每个cookie并计算其四个极值点。 左边缘是`x - r`，右边缘是`x + r`，底边是`y - r`，并且顶边是`y + r`。 
3. 使用这四个边界更新存储的最小值和最大值。 直接更新的原因是最终的矩形只取决于最远到达的位置，而不取决于各个cookie的位置。 
4. 处理完每个 cookie 后，将矩形宽度计算为`max_x - min_x`和高度为`max_y - min_y`。 
5. 将宽度和高度相乘。 结果值是可能的最小平移区域，因为任何较小的矩形都无法包含极端 cookie 边界之一。 

为什么它有效：

 在扫描期间的每个点，存储的值描述包含迄今为止处理的所有cookie的最小轴对齐矩形。 添加新 cookie 时，其整个区域必须适合矩形，因此唯一可能的更改是扩展四个边中的一个或多个。 处理完所有 cookie 后，存储的矩形包含每个 cookie，并且每条边都受到至少一个 cookie 边界的强制，这意味着没有边可以向内移动。 以这种方式固定所有四个边的矩形是可能的最小平底锅。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    min_x = float("inf")
    max_x = float("-inf")
    min_y = float("inf")
    max_y = float("-inf")
    
    for _ in range(n):
        x, y, r = map(int, input().split())
        
        min_x = min(min_x, x - r)
        max_x = max(max_x, x + r)
        min_y = min(min_y, y - r)
        max_y = max(max_y, y + r)
    
    print((max_x - min_x) * (max_y - min_y))

if __name__ == "__main__":
    solve()
```该程序维护算法中描述的四个边界。 每个输入 cookie 都会立即贡献其左、右、下和上边缘。 

更新是在读取输入时发生的，而不是存储所有 cookie。 这可以保持内存使用恒定并避免不必要的工作。 仅在知道完整的边界矩形后才执行最终的乘法。 

尽管使用无穷大进行初始化，但没有浮点计算。 坐标和半径都是整数，因此每个边界和最终面积都是整数。 Python 的整数运算还避免了在具有固定大小整数类型的语言中可能出现的溢出问题。

 ## 边缘情况

 对于单个 cookie，该算法仅从该 cookie 初始化矩形。 有输入：```
1
0 0 5
```边界变为`-5`,`5`,`-5`， 和`5`。 宽度和高度都是`10`，所以输出是`100`。 

对于接触或重叠的 cookie，该算法不会尝试合并形状。 它只关心最外层占用的坐标。 有输入：```
2
0 0 1
2 0 1
```水平范围是从`-1`到`3`垂直范围是从`-1`到`1`。 答案是`8`，这表明重叠与计算无关。 

对于极值，该算法保持精确的整数边界。 有输入：```
2
10000000 10000000 10000000
-10000000 -10000000 10000000
```矩形从`-20000000`到`20000000`在两个轴上。 宽度和高度各为`40000000`，给出面积`1600000000000000`。 该实现无需特殊情况即可处理此问题，因为 Python 整数会根据需要增长。
