 ## 解决方案
 ## 问题理解

 两个用户在一段时间内进行交流$n$天。 我们给出了几个不相交或有序的间隔来描述用户何时$A$发送消息至$B$，并且类似地当$B$发送消息至$A$。 每个间隔意味着通信每天都会在该范围内发生，因此每个用户的总体活动可以被视为数轴上的段的并集。 

当天可获得友谊积分$i$当且仅当最后一个$m$天数结束于$i$双向通信完全覆盖。 换句话说，在窗口内$[i-m+1, i]$, 用户$A$必须在该窗口的每一天发送消息，并且用户$B$一定也做了同样的事。 此条件成立的每一天都会为最终答案贡献一个单位。 

任务是计算整个范围内存在多少这样的天$[1, n]$，即使当$n$与$10^9$。 描述通信的间隔很少，每个方向最多 100 个，并且已经排序且不重叠。 

关键的难点在于规模$n$。 日常模拟是不可能的，因为迭代$10^9$头寸将立即超出时间限制。 相反，我们必须根据片段和过渡进行推理。 

出现微妙的边缘情况时$m = 1$。 然后，两个用户发送消息的每一天都会立即计数，因为窗口就是这一天本身。 当用户的覆盖范围几乎完成但在很长的间隔内缺少一天时，就会出现另一种边缘情况，这会完全破坏跨越该间隙的任何有效窗口。 合并间隔但忽略准确的每日覆盖范围的幼稚方法会错误地将部分覆盖视为完全覆盖。 

## 方法

 暴力方法会明确标记每天从 1 到$n$对于两个用户，然后滑动一个长度的窗口$m$。 对于每一天，我们都会检查窗口中的所有日期是否对两个用户都处于活动状态。 即使使用前缀和，在以下情况下构建完整数组也是不可行的：$n = 10^9$，因为存储或迭代所有天是不可能的。 

关键的观察是我们永远不需要检查个别日子。 每个用户的活动是最多 100 个间隔的并集，因此我们可以首先将每个用户的日程安排转换为随时间变化的二元函数，然后计算其连续活动的位置。 我们想要的条件是两个用户每天的活跃时间长度是-$m$窗户。 这相当于说它们的活动集的交集也必须包含完整的长度区间$m$结束于一天$i$。 

因此，问题归结为计算两个区间并集的交集，然后计算有多少长度-$m$后缀窗口完全适合该交叉点。 我们不扩展时间线，而是直接计算相交线段。 一旦我们有了一个细分$[L, R]$，每个有效窗口结束于$i$对应于一个索引，其中$[i-m+1, i] \subseteq [L, R]$，这简化为$i \in [L+m-1, R]$。 每个交叉段都贡献一个简单的算术计数。 

因此，完整的任务变为：计算两个排序的不相交间隔列表的交集间隔，然后对每个结果段的贡献求和。

 ## 算法演练

 我们将两个用户的消息历史记录视为不相交间隔的排序列表。 然后我们使用两指针扫描计算它们的重叠。 

1.初始化两个指针，一个用于$A$的间隔和一个为$B$的间隔。 这个想法是始终比较每个用户的当前活动段并提取它们的重叠部分。 
2. 在每一步，计算当前间隔的交集。 如果$A = [l_a, r_a]$和$B = [l_b, r_b]$，它们的重叠部分是$[ \max(l_a, l_b), \min(r_a, r_b) ]$，但前提是左端点不超过右端点。 这会产生两个用户同时活跃的分段。 
3. 如果存在重叠段，我们不会立即计算其所有天数。 相反，我们将其转换为有效的窗口结束位置。 一个窗口在一天结束$i$需要全面覆盖$[i-m+1, i]$，所以有效的$i$重叠内的值$[L, R]$满足$i \ge L + m - 1$和$i \le R$。 如果$R \ge L + m - 1$，我们添加$R - (L + m - 1) + 1$到答案。 
4. 向前移动最先结束的区间的指针。 这确保了我们遍历所有片段而不会错过任何重叠的可能性。 我们总是丢弃不能进一步延伸的区间，因为它不能对未来的交叉点做出贡献。 
5. 重复此过程，直至用完一个列表。 

正确性依赖于所有相关结构都由区间边界捕获的事实。 有效窗口不能在至少一个用户处于非活动状态的间隙内开始或结束，因此所有贡献必须完全包含在交叉段内。 

### 为什么它有效

 在任何时间点，该算法都认为涉及先前间隔的所有可能重叠都已被处理。 每个交叉段对于两个用户的活动都是最大的，这意味着没有有效的窗口可以部分延伸到它之外而不破坏至少一个用户的连续性。 由于有效窗口完全对应于完全包含在交集中的连续范围，因此对每个段的窗口进行计数既是必要的也是充分的。 两指针级数确保每对重叠段都被恰好考虑一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, x, y = map(int, input().split())
        
        A = [tuple(map(int, input().split())) for _ in range(x)]
        B = [tuple(map(int, input().split())) for _ in range(y)]
        
        i = j = 0
        ans = 0
        
        while i < x and j < y:
            la, ra = A[i]
            lb, rb = B[j]
            
            L = max(la, lb)
            R = min(ra, rb)
            
            if L <= R:
                start = L + m - 1
                if start <= R:
                    ans += R - start + 1
            
            if ra < rb:
                i += 1
            else:
                j += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先读取每个测试用例的两个间隔列表。 由于间隔保证是不相交和排序的，因此线性两指针扫描就足够了。 

在循环内部，我们计算当前间隔的重叠。 如果不存在重叠，则不添加任何内容。 如果存在重叠，我们会将其转换为有效窗口端点的计数，而不是在几天内迭代。 

指针前进规则至关重要。 我们总是越过最先结束的间隔，因为它不能与超出其端点的其他列表中的任何未来间隔重叠。 

必须小心从重叠段到有效窗口的转换。 表达式$L + m - 1$定义第一天的完整窗口大小$m$可以在停留在重叠范围内时结束。 如果这超过$R$，该段没有任何贡献。

 ## 边缘情况

 一种重要的边缘情况是重叠存在但短于$m$。 例如，如果两个用户在第 10 到 12 天都处于活动状态并且$m = 5$，交集有效但没有任何贡献。 算法正确计算$L + m - 1 > R$，因此它完全跳过该段。 

另一种边缘情况是间隔接触但不重叠。 如果 A 在第 5 天结束，B 在第 6 天开始，则计算出的交集为$L > R$，因此没有添加贡献。 这确保了没有重叠的邻接不会被错误地视为连续性。 

最后一个微妙的情况是由交替间隔引起的多个不相交的重叠。 双指针扫描确保每个重叠只处理一次，因为前进较早结束间隔的指针可以保证不会跳过或重复计算交集段。
