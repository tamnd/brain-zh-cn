 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例都包含一个整数列表，表示为竞赛准备的编程问题的难度分数。 

对于每个列表，我们必须确定它是否满足一组定义有效竞赛集的结构规则。 这些规则限制了问题的数量、最小难度值的分布以及排序时难度增加的平滑程度。 

第一个限制纯粹是关于大小：只有具有较小固定大小范围的集合是可接受的，特别是 10 到 13 个问题之间（包括 10 到 13 个问题）。 任何超出此范围的设置都会立即无效，无论其值如何。 

第二个限制定义了最简单问题的身份。 如果我们查看集合中的最小难度，每次出现该最小值都必须恰好为值 1。这会强制将最简单的层锚定为 1，而不是允许任意低值。 结果是，如果最小值不为 1，则配置失败。 

第三个限制要求至少存在两个困难问题1。这可以防止仅存在一个最简单问题的退化情况。 

第四个限制在将难度按非降序排列后适用。 当我们扫描相邻元素时，相邻元素之间的绝对差值不得超过 2。唯一的例外是当两个相邻问题之一是唯一最难问题时，即数组中的最大值并且只出现一次。 任何涉及此最大值的邻接都会绕过差异限制。 

一个幼稚的错误是统一应用邻接约束，包括涉及最大值的边。 例如，考虑一个排序数组，如`[1, 1, 3, 4, 5, 6, 7, 13, 14, 15]`。 从 7 到 13 的跳跃很大，但仅当 13 是唯一最大值时才允许。 如果 15 是最大值，则该跳转无效。 忽略异常的解决方案将错误地拒绝有效案例。 

当最小值为 1 但只出现一次时，会发生另一个微妙的故障。 即使所有邻接差异都很小，该集合仍然必须被拒绝。 

约束很小：最多 10^4 个测试用例，每个数组最多有 100 个元素。 这意味着每个测试用例解决方案的 O(n log n) 就足够了，甚至 O(n^2) 也很有限，但没有必要。 排序后预期的解决方案是线性的。 

## 方法

 解释规则的一种强力方法是直接在每个测试用例上模拟每个条件，而不简化结构。 我们会一一检查所有属性，甚至可能重复重新计算最小值、最大值和计数，然后验证邻接约束，同时动态识别是否涉及最大值。 这是正确的，但从概念意义上来说效率很低，因为它可能会在邻接验证期间重复扫描数组以进行最大检查，从而导致冗余工作。 在最坏的情况下，如果我们重新计算每个邻接检查的最大值或计数，我们会朝着每个测试用例的 O(n^2) 方向漂移。 

关键的观察结果是，每个数组都可以预先计算一次所有必需的全局属性。 值的最小值、最大值和频率与邻接检查无关，排序后所需的唯一结构推理是单个线性扫描。 这将问题简化为对排序列表进行简单的验证，并通过恒定时间检查位置是否包含最大值。 

暴力破解之所以有效，是因为它直接执行规则，但它无法干净地扩展，因为它将全局查询混合到本地检查中。 预先计算汇总统计数据可以分离关注点，并通过排序将所有内容减少到 O(n log n)。

 | ---| ---| ---| ---|

 | 最佳| 每次测试 O(n log n) | O(1) 额外 | 已接受 |

 ## 算法演练

 ### 最优推理步骤

 1. 读取数组并立即检查其长度。 如果它超出了 10 到 13 的范围，则配置无效，因此我们可以拒绝它，而无需进一步处理。 这避免了对明显无效的情况进行不必要的排序。 
2. 按非降序对数组进行排序。 此步骤是必要的，因为邻接约束仅在排序后定义，并且如果不排序，我们就无法在本地推理平滑度。 
3. 计算排序数组的最小值和最大值。 还要计算最小值出现的次数。 这些值决定是否满足有关极端的结构要求。 
4. 验证最小值是否正好为 1。如果不是，则立即违反“最简单的问题是 1”规则。 
5. 检查1的数量至少为2。这确保有足够的最简单的问题。 
6. 确认最大值恰好出现一次。 这确定了规则所要求的独特的最难问题。 
7. 扫描排序数组中的相邻对。 对于每一对，检查它们的绝对差。 如果任一元素等于最大值，则跳过该对的约束。 否则，请确保差异最多为 2。如果任何对违反此规定，则配置无效。 

### 为什么它有效

排序后，除了有关最小值和最大值的全局条件外，所有结构约束都简化为局部一致性检查。 预先计算最小值、最大值和频率可隔离全局约束，以便邻接验证变得独立。 不变的是，每个非最大值元素必须位于一个序列中，其中值以步长最多为 2 逐渐增长。唯一允许的不连续性是在唯一最大值参与的边界处，这不会影响剩余链的连续性。 这种分离保证了任何违规都会出现在全局检查或单个相邻对比较中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n < 10 or n > 13:
            out.append("No")
            continue

        a.sort()

        mn = a[0]
        mx = a[-1]

        if mn != 1:
            out.append("No")
            continue

        cnt1 = 0
        for x in a:
            if x == 1:
                cnt1 += 1

        if cnt1 < 2:
            out.append("No")
            continue

        if a.count(mx) != 1:
            out.append("No")
            continue

        ok = True
        for i in range(n - 1):
            if a[i] == mx or a[i + 1] == mx:
                continue
            if abs(a[i + 1] - a[i]) > 2:
                ok = False
                break

        out.append("Yes" if ok else "No")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先使用大小约束过滤不可能的情况。 排序为所有后续推理建立正确的顺序。 对最小值和频率的检查强制执行对最简单问题的结构要求。 对最大值的唯一性检查可确保明确定义特殊例外规则。 

最后一个循环是核心验证步骤。 它仅在两个元素都不是最大值时才强制执行差异约束，这与异常规则完全匹配。 这可以避免最大元素产生较大跳跃时意外拒绝有效配置。

 ## 边缘情况

 一种棘手的情况是，当数组包含多个小值但只有一个 1 时。即使邻接差异很小，要求至少两个 1 的规则也会强制拒绝。 该算法可以正确处理这个问题，因为它在任何结构检查之前显式地计算 1 的出现次数。 

当最大值多次出现时，就会出现另一种边缘情况。 即使邻接约束会通过，例外规则也会变得不明确，因此算法会通过检查最大值的唯一性来提前拒绝它。 

第三种情况是当最大值附近出现大间隙时，但也会影响其他地方的非最大值转换。 该算法仅跳过涉及最大值的比较来确保正确性，因此所有其他对都经过严格验证，保证不会遗漏任何隐藏的违规行为。
