 ## 解决方案
 ## 问题理解

 我们得到一个数字序列`a_i`每个都标有类型`b_i`即 0 或 1。任务是确定是否可以通过仅交换不同类型的元素来按非降序对序列进行排序。 换句话说，仓位之间允许互换`i`和`j`仅当`b_i != b_j`。 输入由多个测试用例组成，每个测试用例都有数组长度、值数组和类型数组。 如果在这些约束下可以进行排序，则输出应为“是”，否则输出应为“否”。 

鉴于限制条件，`n`最多可以有 500 个，并且最多可以有 100 个测试用例。 直接对每个序列进行排序很快，但模拟所有可能的交换会太慢，因为潜在交换的数量会组合增长。 我们需要一种更具分析性的方法来确定排序是否可行，而无需实际执行所有交换。 

当所有元素都属于同一类型时，会出现微妙的边缘情况。 在这种情况下，不允许交换，因此只有当数组已经处于非降序时才可以将其视为可排序。 例如，如果`a = [3, 1, 2]`和`b = [0, 0, 0]`，正确的输出是“No”，因为不会发生交换。 粗心的方法可能会忽略类型约束，并在内部对数组进行排序后错误地回答“是”。 

## 方法

 暴力方法将尝试每个有效交换序列，直到数组已排序或所有可能性都用尽。 原则上这是正确的，因为规则允许的任何交换序列最终都可以对数组进行排序。 然而，交换数量呈指数增长`n`，使得该方法即使对于`n = 20`。 最坏的情况可能涉及检查交换的阶乘组合，远远超出允许的计算时间。 

关键的见解是要注意，唯一阻碍排序的因素是缺乏类型多样性。 如果至少有一个类型 0 的元素和一个类型 1 的元素，我们可以通过重复使用中间交换来有效地交换任意一对元素，这允许完全重新排序。 如果数组包含这两种类型，那么答案就是“是”。 如果所有元素都具有相同的类型，则仅当数组已排序时答案为“是”。 

这一观察将问题简化为一个简单的检查：要么数组已经排序，要么它包含两种类型。 不需要实际的交换模拟。

 ## 算法演练

 1. 对于每个测试用例，请阅读`n`，数组`a`，以及类型数组`b`。 
2. 检查数组是否`a`已经按非降序排序。 如果是，则打印“Yes”并移至下一个测试用例。 在这种情况下排序是完全可能的。 
3. 如果数组未排序，检查数组中是否同时存在类型0和类型1`b`。 如果两种类型都存在，则打印“Yes”，因为任何排列`a`可以通过不同类型之间的交换来实现。 
4. 如果仅存在一种类型并且数组尚未排序，则打印“No”。 排序是不可能的，因为不允许交换。 
5. 对所有测试用例重复此操作。 

为什么它有效：不变的是，拥有这两种类型允许任何元素通过一系列允许的交换与任何其他元素间接交换。 这保证了任何未排序的数组都可以转换为已排序的顺序。 如果只存在一种类型，则不允许交换，因此数组的有序性是唯一的标准。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        if a == sorted(a):
            print("Yes")
            continue
        
        has_zero = 0 in b
        has_one = 1 in b
        
        if has_zero and has_one:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```该解决方案首先检查数组是否已经排序，以快速处理简单的情况。 然后它扫描类型数组以查看这两种类型是否都存在。 支票`0 in b`和`1 in b`简单而充分，因为唯一重要的是两种类型的存在，而不是它们的计数。

 ## 边缘情况

 当所有元素都是同一类型时，不会发生交换。 例如，`a = [3, 1, 2]`和`b = [0, 0, 0]`。 该数组未排序，`0 in b`是真的，`1 in b`为 False，因此算法输出“No”。 如果数组已经排序，例如`a = [1, 2, 2]`和`b = [1, 1, 1]`，它打印“是”。 当两种类型都存在时，例如`a = [4, 3, 2]`和`b = [0, 1, 0]`，算法打印“是”，因为交换允许重新排序。 这些案例证实了所有细微输入配置的正确性。
