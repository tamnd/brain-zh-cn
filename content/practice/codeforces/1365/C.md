 ## 解决方案

 ## 问题理解

 我们得到了同一组数字从 1 到 n 的两种排列。 将它们视为相同标记瓷砖的两种不同的圆形排列。 我们可以将每个圆独立旋转任意多次，然后将它们对齐在固定位置。 如果该位置的两个数组中出现相同的值，则该位置对答案有贡献。 

所以真正的问题是：选择两次循环移位后，我们可以让多少个索引 i 满足 a[i] == b[i]？ 

由于两个数组包含完全相同的值，因此每个值 x 在 a 中都有一个固定位置，在 b 中也有一个固定位置。 数组的旋转只是均匀地移动所有这些位置，因此每个排列内的相对顺序保持不变，只有全局偏移量发生变化。 

约束 n 高达 2 × 10^5 迫使对所有移位进行任何二次比较都是不可能的。 尝试一个数组的所有 n 次移位与另一个数组的 n 次移位已经给出了 O(n^2)，这太慢了。 即使 O(n log n) 或 O(n sqrt n) 方法也是可以接受的，但我们应该期望基于位置的线性或近线性变换。 

当排列在旋转之前都相同时，就会出现微妙的边缘情况，在这种情况下，我们可以对齐所有位置并获得 n 个匹配。 在另一个极端，有些情况下每个比对只产生一个匹配，例如：

 a = [1,2,3,4]，b = [2,3,1,4]。 由于循环结构冲突，任何旋转都不能同时对齐两个以上的位置。 

另一个隐藏的细节是，旋转两个阵列相当于固定一个阵列并沿相反方向旋转另一个阵列。 这种对称性至关重要，因为它将问题从两个自由度减少到一个自由度。 

## 方法

 蛮力的想法很简单。 我们固定 a 的旋转，然后尝试 b 的每次旋转，计算有多少个索引匹配，并取最大值。 每次比较的成本为 O(n)，并且有 O(n^2) 个旋转对，如果天真地完成，则导致 O(n^3) 时间；如果我们仔细地预先计算比较，则导致 O(n^2) 时间。 无论哪种方式，对于 n = 2 × 10^5 来说都太大了。 

关键的观察是，驱动对齐的是价值，而不是位置。 每个值 x 出现在 a 中的某个位置 pos_a[x] 和 b 中的 pos_b[x] 处。 如果我们旋转 b 使得 b 的 x 位置落在 a 的 x 位置上，则 x 贡献一场比赛。 对于固定轮换，匹配的数量恰好是所需移位一致的值的数量。 

因此，每个值都会在 a 和 b 之间产生“所需的旋转偏移”。 如果我们计算每个 x 的偏移量，则最佳对齐方式就是最频繁的偏移量。 这将问题简化为计算 n 个计算差异的频率。 

这将问题从尝试所有对齐方式转变为根据值需要的旋转量对值进行分组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) 或 O(n^2) | O(1)-O(n) | O(1)-O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算第一个排列中每个值的位置。 对于每个值 x，存储它在 a 中出现的位置。 
2. 类似地计算第二个排列中每个值的位置。 这使我们能够快速查找每个值需要落地的位置。 
3. 对于每个值 x，计算将 b[x] 与 a[x] 对齐所需的旋转位移。 如果 pos_a[x] 为 i，pos_b[x] 为 j，则将 b 移位 (i - j) 模 n 即可正确对齐 x。 这将问题转化为确定哪个移位值最常见。 
4. 计算每个班次产生多少个值。 我们维护一个由移位值模 n 索引的频率数组或哈希图。 
5. 答案是所有班次中的最大频率。

这样做的原因是每次移位都定义了数组之间的全局对齐方式。 仅当该移位将其在 b 中的位置直接映射到其在 a 中的位置时，该值才会对移位做出贡献。 因此，任何有效的轮换都对应于这些移位桶之一，并且该轮换下的所有匹配正是落入该桶中的值。 

不变的是，对于任何选定的旋转，匹配值恰好是 a 和 b 之间的相对位移等于该旋转的值。 由于每个值都独立地影响一个位移，因此对所有值的频率进行计数可以详尽地捕获所有可能的对齐方式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

pos_a = [0] * (n + 1)
pos_b = [0] * (n + 1)

for i, x in enumerate(a):
    pos_a[x] = i

for i, x in enumerate(b):
    pos_b[x] = i

freq = [0] * n

for x in range(1, n + 1):
    shift = (pos_a[x] - pos_b[x]) % n
    freq[shift] += 1

print(max(freq))
```第一部分构建从值到索引的逆映射，这避免了重复扫描数组。 核心循环计算每个值所需的旋转。 模运算可确保负移位正确包含在 [0, n-1] 范围内。 

频率数组的大小为 n，因为恰好有 n 种可能的不同旋转。 最终的最大值直接对应于最佳对齐。 

一个常见的错误是反转移位方向； 只要保持一致性，这两种约定都有效。 另一个是忘记模归一化，这会将等效旋转分为负值和正值桶。

 所有值都会产生偏移 1，因此频率[1] = 5，答案为 5。 

这证实了一次旋转完美地对齐了两种排列的情况。

这表明可以存在多个最佳旋转，并且算法正确地识别出其中的最佳旋转。

 ## 边缘情况

 当 n = 1 时，两个排列仅包含一个元素。 唯一的移位是 0，并且频率数组折叠为单个存储桶，因此答案很简单就是 1。 

当数组相同时，每个值都有移位 0。移位 0 的频率变为 n，算法返回完全对齐，而不需要任何特殊的大小写。 

当排列彼此完美旋转时，每个值都会产生相同的移位值。 频率表完全集中在一个桶中，表明该方法可以正确捕获全局循环等价性，而无需显式模拟旋转。 

当除了一个小子集之外，没有任何一次旋转可以对齐大多数元素时，频率表自然地将值分布在不同的移位上，并且最大值仍然对应于可实现的最佳对齐。
