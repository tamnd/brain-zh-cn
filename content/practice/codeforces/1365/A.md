 ## 解决方案
 ## 问题理解

 我们得到一个网格，其中一些单元格已经被占用。 两名玩家轮流轮流，每次移动时，玩家必须在严格限制下选择一个以前未使用的单元格：不允许两个选定的单元格共享一行或一列。 

当玩家无法做出合法的动作时，游戏就结束了，我们需要决定如果双方都发挥最佳并且 Ashish 开始的话谁会获胜。 

关键的观察结果是，网格结构本身并不重要，除了行或列是否已被占用的单元“阻挡”之外。 一旦一行包含选定的单元格，该行就永远不能贡献另一次移动，这同样适用于列。 每一步实际上都会同时消耗一个未使用的行和一个未使用的列。 

每个测试用例和 50 个测试用例的约束最多为 50 x 50，直接模拟就可以了，但任何尝试搜索放置组合的行为都会很快爆炸。 该结构强烈建议减少计数而不是搜索问题。 

一个常见的失败案例来自于误解被阻塞的行和列如何交互。 例如，如果两个初始 1 位于同一行或同一列，则简单地独立计算行和列而不进行重复数据删除的简单实现可能会高估可用的移动。 

当网格完全为空时，会出现另一个微妙的问题。 人们可能会假设每个空单元格都是可玩的，但实际上选择一个单元格会立即阻止其整个行和列，将许多潜在的选择压缩为一个动作。 

## 方法

 暴力策略将尝试模拟所有有效的移动序列，在满足行和列约束的每个可用单元格上进行分支。 即使在 50 x 50 的网格中，有效序列的数量也可以组合增长，因为每次移动都会改变全局可用移动的结构。 这很快就变得不可行。 

关键的简化来自于根据结构而不是立场来重新定义问题。 每次移动都会选择一个先前未触及的行和一个先前未触及的列。 因此，游戏简化为重复地将空闲行与空闲列配对。 这种配对的数量完全取决于有多少行和列已经被初始行和列阻塞。 

我们观察到每个初始占用的单元格都会阻塞其行和列。 删除重复项后，自由选择的数量将缩减为剩余自由行和自由列的最小值。 游戏变成了一个简单的堆，每一步都会消除一个单位，获胜者仅取决于平价。 

暴力破解之所以有效，是因为它直接遵循规则，但失败是因为它没有压缩行和列之间的对称性。 观察到每次移动恰好消耗一行和一列，从而将问题简化为计算存在多少个这样的对。

 | 暴力模拟| 指数| 指数| 太慢了|
 | 减少行/列计数 | O(纳米) | O(n + m) | 已接受 |

 ## 算法演练

 我们首先确定哪些行和列已经被初始占用的单元格阻挡。 如果一行至少包含一个 1，则该行被阻止，列也类似。 

接下来，我们计算有多少行仍然完全空闲，有多少列仍然完全空闲。 这些代表仍然可以参与移动的资源。 

每次移动同时消耗一个空闲行和一个空闲列，因此可能的移动总数是这两个数量中的最小值。 

最后，由于玩家从 Ashish 开始交替移动，我们通过检查这个数字是奇数还是偶数来确定获胜者。 如果奇怪，阿什什会做出最后一步并获胜。 如果是的话，维韦克也会这么做。

关键的不变量是，每次移动后，恰好一行和一列会从未来的考虑中永久删除。 任何一步都不能重复使用任一维度，因此游戏状态始终在两个方向上单调减少，确保有效移动的计数完全决定结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        rows = [False] * n
        cols = [False] * m

        grid = [list(map(int, input().split())) for _ in range(n)]

        for i in range(n):
            for j in range(m):
                if grid[i][j] == 1:
                    rows[i] = True
                    cols[j] = True

        free_rows = sum(1 for i in range(n) if not rows[i])
        free_cols = sum(1 for j in range(m) if not cols[j])

        moves = min(free_rows, free_cols)

        if moves % 2 == 1:
            print("Ashish")
        else:
            print("Vivek")

solve()
```该解决方案扫描网格一次，标记哪些行和列已经不可用。 之后，它会计算剩余的可用行和列，并将游戏简化为奇偶校验。 唯一微妙的一点是，如果一行或一列包含至少一个占用的单元格，则该行或列被认为是阻塞的，而不是基于它包含多少个占用的单元格。 

## 工作示例

 ### 示例 1

 输入：```
2 2
0 0
0 0
```所有行和列最初都是免费的。 

| 步骤| 自由行| 免费专栏 | 移动|
 | --- | --- | --- | --- |
 | 开始| 2 | 2 | 0 |
 | 计算| 2 | 2 | 2 |

 移动次数为 2，因此 Vivek 获胜。 

这表明，即使在完全空的网格中，游戏也仅限于最多 min(n, m) 步，而不是单元格数量。 

### 示例 2

 输入：```
2 2
0 0
0 1
```第 1 行和第 1 列被单个占用的单元格挡住。 

| 步骤| 自由行| 免费专栏 | 移动|
 | --- | --- | --- | --- |
 | 开始| 1 | 1 | 0 |
 | 计算| 1 | 1 | 1 |

 一步可行，所以阿什什获胜。 

这证实了单个被阻止的行列对确定了单个强制移动。

 ## 边缘情况

 完全空的网格表明答案仅取决于 min(n, m)，而不取决于单元格总数。 一种网格，其中所有行都已被阻止，除了列约束占主导地位的测试之外。 除一列测试对称情况外，所有列均被封锁的网格。 这些情况中的每一种都干净地减少为剩余自由维度的单个奇偶校验计算，并且该算法统一处理它们，因为它从不假设单元之间的独立性。
