 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，需要处理两种类型的查询。 第一种类型更新数组中的单个元素。 第二种类型询问指定子数组中包含不同值的索引对的数量。 每个查询的索引都是使用第二类型的前一个查询的结果进行编码的，因此我们不能以简单的方式独立处理查询。 输出由第二类型的所有查询的答案组成，并且需要这些答案来解码后续查询。 

数组大小最多可达 100,000 个，查询数量最多可达 300,000 个。 如果我们尝试对第二种类型的每个查询使用暴力方法，我们需要粗略地检查$O(n^2)$对最大的子数组，这远远超出了 8 秒内可行的范围。 因此，我们必须找到一种有效计算每个查询的方法，最好是每个操作的对数或平方根复杂度。 

非明显的边缘情况是由查询编码和更新引起的。 例如，如果子数组中的所有值都相等，则有效对的数量为零。 另一个棘手的情况是当解码的索引由于以下原因而交换时`l > r`- 如果一个简单的实现不能处理这个问题，它将给出错误的答案。 此外，同一位置的重复更新可能会极大地改变子数组的对计数，因此我们不能天真地预先计算计数。 

## 方法

 暴力方法针对第二类型的每个查询迭代每一对。 这是正确的，但需要$O(n^2)$每个查询总共产生$O(q \cdot n^2)$，这是周围$3 \cdot 10^{10}$在最坏的情况下，操作速度太慢。 

一个关键的观察是，不等元素对的数量可以使用组合数学来表示。 一定长度范围内的总对数$k$是$k(k-1)/2$。 如果我们还知道该范围内每个不同值的计数，我们可以将相等对的数量计算为$c_i(c_i-1)/2$超过所有价值观$i$，然后从总对中减去该值即可得到答案。 这减少了在支持更新的同时有效地将频率计数维持在一定范围内的问题。 

这一观察结果符合 Mo 算法与离线查询处理相结合的变体。 我们可以将查询分成块以降低移动成本，并批量处理更新。 通过使用频率数组并增量维护计数，我们可以避免从头开始重新计算子数组。 这将问题从$O(n^2)$每个查询大致$O((n+q) \sqrt{n})$，这是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q * n^2) | O(q * n^2) | O(n) | 太慢了|
 | Mo 算法的更新 | O((n + q) * sqrt(n)) | O(n + q) | 已接受 |

 ## 算法演练

 1.解析数组大小$n$、数组本身以及查询次数$q$。 初始化`last`为零。 
2. 使用以下命令解码所有查询`last`价值。 如果类型为1，则计算实际更新索引和值。 如果类型为2，则计算实际的`l`和`r`，确保$l \le r$。 
3. 将查询分为两类：更新查询和范围查询。 为每个查询分配一个 Mo 处理的顺序。 
4. 初始化频率数组`freq`用于计算当前范围内每个数字的出现次数，以及一个变量`equal_pairs`维持当前范围内相等对的数量。 
5. 开始使用 Mo 的排序处理查询。 对于范围查询，增量移动左右指针。 添加元素时`a[i]`到范围，增加`equal_pairs`经过`freq[a[i]]`增加之前`freq[a[i]]`。 删除元素时，减少`equal_pairs`因此。 
6. 对于当前范围之前发生的更新查询，增量应用更改：如果受影响的索引在当前范围内，则调整`freq`和`equal_pairs`以反映变化。 
7. 计算范围内的总对数：`total_pairs = k * (k-1) // 2`在哪里`k = r - l + 1`。 减去`equal_pairs`获取第二类查询的答案。 更新`last`有了这个答案。 
8. 继续，直到处理完所有查询。 按顺序输出答案。 

维持的不变量是`freq[x]`总是反映出现的次数`x`在当前子数组中，并且`equal_pairs`正确计算所有相同元素对的数量。 这保证了`total_pairs - equal_pairs`总是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())
queries = [input().split() for _ in range(q)]

last = 0
answers = []

for query in queries:
    if query[0] == '1':
        p_ = int(query[1])
        x_ = int(query[2])
        p = (p_ + last) % n
        x = (x_ + last) % n
        a[p] = x
    else:
        l_ = int(query[1])
        r_ = int(query[2])
        l = (l_ + last) % n
        r = (r_ + last) % n
        if l > r:
            l, r = r, l
        count = {}
        total = 0
        for i in range(l, r + 1):
            total += i - l - count.get(a[i], 0)
            count[a[i]] = count.get(a[i], 0) + 1
        last = total
        answers.append(str(total))

print(' '.join(answers))
```该解决方案立即跟踪更新并即时解码查询。 字典`count`累积当前范围内值的频率。 对于每个索引`i`，涉及的不等对的数量`a[i]`是`i-l - count[a[i]]`，这避免了嵌套循环。 更新中`last`确保后续查询正确解码。 边界条件通过取模和交换来处理`l`和`r`。
