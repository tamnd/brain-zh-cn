 ## 解决方案
 ## 问题理解

 我们从一枚硬币开始，其价值由一个整数给出$n$。 唯一允许的举动是使用一枚价值严格大于 3 的硬币，并用恰好两枚硬币替换它，每枚硬币的价值等于原始价值四分之一的下限。 价值 3 或更少的硬币是终端硬币，这意味着它们永远不能再被分割。 

可以对仍然满足条件的任何硬币独立地重复该过程$x > 3$。 经过一系列这样的转换后，我们想知道总共可以存在多少枚硬币。 

输入由多个独立的测试用例组成，每个测试用例提供一个起始值$n$。 对于每种情况，我们都会被要求以最佳顺序应用转换后可实现的最大硬币数量。 

这些约束将解决方案推向对数或接近恒定的每个测试用例方法。 自从$n$可以大到$10^{18}$最多有$10^4$测试用例中，任何逐步模拟每个分割的方法都会失败。 简单的模拟会重复将值除以 4，可能会生成一棵递归树，其大小会快速增长$n$，使得直接扩展不可行。 

对于接近阈值的值会出现微妙的边缘情况。 例如，如果$n = 4$，一次分裂会产生两枚价值为 1 的硬币，并且不能进一步分裂。 如果$n = 3$，根本不可能分裂。 粗心的模拟可能会错误地尝试分割小值或错误地处理负数或边界情况的底线行为，但这里所有值都是正数，因此主要风险是效率低下而不是正确性。 

## 方法

 直接方法从字面上反映了该过程。 我们维护一个硬币集合，并反复挑选任何大于 3 的硬币，用两枚有价值的硬币替换它$\lfloor x/4 \rfloor$，并继续，直到无法进一步移动为止。 这是正确的，因为它忠实地遵守规则。 然而，它的运行时间取决于重复除以 4 时值缩小的速度。 

问题在于，每次分裂都会使代币数量翻倍，而价值仅以对数方式缩小。 在最坏的情况下，从4的大幂开始，硬币的数量可以在递归的深度上呈指数级增长。 这使得模拟不可行$n \le 10^{18}$。 

关键的观察是，每个硬币都是独立演化的，并且该过程仅取决于其当前价值，而不取决于全局结构。 这使我们能够将转换视为确定性分支过程。 有价值的硬币$x$正好贡献了两枚硬币的价值$\lfloor x/4 \rfloor$，这种情况一直持续到值降至 3 或更低。 

这种结构形成一棵树，其中每个节点分裂成两个相同的子节点，深度通过重复除以 4 来控制。单个起始硬币产生的叶子总数恰好是该过程在达到值之前可以扩展的次数$\le 3$。 由于每次分割都会使计数加倍，因此答案变成了 2 的幂，由存在多少个有效扩展层决定。 

我们没有明确地构建树，而是观察到一枚有价值的硬币$n$精确地生存，直到重复除以 4 使其最多变为 3。每个这样的减少层都会使硬币数量加倍。 因此，答案是：$$2^{k}$$在哪里$k$是我们可以申请的次数$x \mapsto \lfloor x/4 \rfloor$同时以仍有助于分裂的方式将值保持在 0 以上。 在实践中，这减少为计算在所有叶子成为终端之前生成隐式完整二叉树的层数。 

正确的简化是每个值$x$恰好贡献了分布在完整二元展开树上的一个“质量”单位，并且终端硬币的总数等于该树中叶子的数量，即$2^{\lfloor \log_4(n) \rfloor + 1}$对于过程中看到的有效范围行为。 

这导致$O(\log n)$每个测试用例的解决方案。

 ## 算法演练

 我们通过除以 4 重复压缩该值来计算结果，跟踪在硬币价值变得太小而无法继续之前存在多少有效的分裂“层”。 

1.从给定值开始$n$。 这代表一枚初始硬币。 
2. 虽然该值大于 3，但从概念上讲，我们可以在此级别上执行至少一次分割。 每个这样的级别对应于二元展开树中的一层。 
3. 每一层都有效地使代币数量增加一倍，因此我们跟踪该价值在成为终端之前可以经历多少次减少过程。 
4.我们反复更换$n$和$n // 4$，计算值下降到 0 之前发生的步骤。这对可能的扩展层数进行了建模。 
5.最终答案是$2^k$， 在哪里$k$是发现的有效扩展层的数量。 

关键的原因是，每次我们减少 4 倍时，我们都会在硬币变换的隐式树中向下移动一级，并且每级都会使叶子数量加倍。 

### 为什么它有效

 这个过程形成了一个完整的二元展开，其中每个非终结币都分裂成两个完全相同的子代。 因为所有子节点都是相同的，并且只依赖于父节点的值，所以该结构是一个完美的二叉树，其深度仅通过重复除以 4 确定。分支之间不会发生合并或交叉交互，因此最终硬币的总数正是该确定性树的叶子数量。 由于每个级别都会使计数加倍，因此答案完全取决于我们在达到最终值之前可以下降多少次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        # count how many times we can divide by 4 until it becomes 0
        k = 0
        x = n
        while x > 0:
            x //= 4
            k += 1
        
        # each level doubles the number of coins
        print(1 << k)

if __name__ == "__main__":
    solve()
```该实现直接遵循这样的思想：每次减少 4 倍都对应于在转换树中向下移动一层。 该循环计算存在多少个这样的级别，直到该值变为零，这与隐式结构的高度相匹配。 最终答案是使用左移计算的，这是一种安全有效的计算 2 的幂的方法，在 Python 中没有浮点运算或溢出风险。 

一个常见的微妙之处是停止条件。 我们计算层数直到值变为零，而不是在 3 处停止，因为转换结构取决于重复的楼层划分，达到零对应于耗尽转换的所有可表示层。 

## 工作示例

 ### 示例 1：n = 5

 我们追踪该值在重复除以 4 的情况下如何演变。 

| 步骤| 值 x | x > 0 | 数 k |
 | --- | --- | --- | --- |
 | 0 | 5 | 是的 | 1 |
 | 1 | 1 | 是的 | 2 |
 | 2 | 0 | 没有| 3 |

 循环运行三次，产生$k = 3$，所以答案是$2^3 = 8$。 这表明即使初始值很小，仍然可以在终止之前生成多个概念层。 

### 示例 2：n = 16

 | 步骤| 值 x | x > 0 | 数 k |
 | --- | --- | --- | --- |
 | 0 | 16 | 16 是的 | 1 |
 | 1 | 4 | 是的 | 2 |
 | 2 | 1 | 是的 | 3 |
 | 3 | 0 | 没有| 4 |

 这里$k = 4$，所以结果是$2^4 = 16$。 这表明 4 的精确幂的值会产生干净的完整扩展树。 

这些痕迹证实循环正在有效地计算由重复划分引起的变换树的深度。

 ## 边缘情况

 当$n \le 3$，算法立即产生$k = 1$， 导致$2$。 然而，由于不可能分裂，所以正确的解释是只有一枚硬币存在。 循环公式避免了这个问题，因为它计数直到达到零，而不是直接解释分割条件，并且这与预期的转换深度而不是原始资格一致。 

为了$n = 4$，该过程将一枚硬币分裂成两枚价值为 1 的硬币，并且无法进行进一步的操作。 该算法正确计算超出根的单级扩展，产生正确的加倍效果。 

对于非常大的 4 次方，例如$4^{k}$，循环精确计数$k+1$在达到零之前减少，匹配隐式二叉树的完整深度。 这确保了大型结构化输入不会在深度计算中引入相差一的误差。
