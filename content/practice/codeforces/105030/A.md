 ## 解决方案
 ## 问题理解

 每个香料单元都标有一个整数主题。 我们必须将所有单元分配给尽可能少的学生。 

一个学生可能会收到多个单元，但分配给该学生的任何两个主题的差异必须大于`k`。 如果两个主题编号最多相差`k`，它们被认为是相似的并且不能属于同一学生。 

任务是计算所需的最少学生人数。 

的价值`n`达到`2 · 10^5`，因此任何比较每对主题或尝试不同分配的算法都会立即变得过于昂贵。 二次算法需要大约`4 · 10^10`最坏情况下的操作，远远超出了实际极限。 我们应该瞄准`O(n log n)`或更好。 

有几种情况值得特别注意。 

什么时候`k = 0`，在一名学生的作业中禁止单独使用相同的主题。 例如，```
3 0
3 1 1
```正确答案是`2`。 一名学生可能会收到主题`1`和`3`，而第二个学生则收到剩余的`1`。 简单地计算不同的值会错误地产生`1`。 

价值观之间的巨大差距完全消除了冲突。 例如，```
4 5
1 10 20 30
```正确答案是`1`，因为每对的差异都超过`5`。 仅查看元素总数而不考虑距离的解决方案会高估答案。 

许多相等的值与邻近的值一起是另一个陷阱。 考虑```
5 2
5 5 5 6 7
```正确答案是`5`。 每份副本`5`与所有其他副本冲突，并且两者都`6`和`7`也与每个人发生冲突`5`。 仅跟踪一个学生序列中前一个值的贪婪作业如果忽略多重性，很容易变得不正确。 

## 方法

 一种直接的方法是尝试将每个主题分配给现有学生，并在没有人接受时创建一个新学生。 如果仔细实施，这最终会找到最低限度的作业，因为每个决定都会检查所有以前的学生。 不幸的是，每个`n`主题最多可扫描`n`学生，制作`O(n²)`工作。 

关键的观察结果是，对主题值进行排序后，每个冲突都变得局部化。 主题仅与长度区间内的值发生冲突`k`。 我们可以提出不同的问题，而不是单独考虑学生。 

假设我们查看每个值的区间，其最大值减去最小值最多为`k`。 该区间内的每一对都相互冲突，因此它们可能不属于同一学生。 如果一个区间包含`m`元素，至少`m`学生是必要的。 

令人惊讶的是，这个下限也足够了。 

排序后，冲突图是区间图。 区间图是完美图，这意味着色数等于最大集团的大小。 这里，团就是包含在某个长度区间中的一组值`k`。 因此，学生的最小数量等于满足以下条件的任何窗口中包含的排序元素的最大数量`a[r] - a[l] <= k`。 

找到这个最大窗口大小正是经典的两指针技术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(1) 额外，不包括排序 | 已接受 |

 ## 算法演练

 1. 读取输入并对所有主题值进行排序。 
2. 维护两个索引，`l`和`r`，描述排序数组中的当前窗口。 
3. 扩展`r`从左到右。 插入新值后，检查窗口是否仍然满足`a[r] - a[l] <= k`。 
4.虽然差异超过`k`， 移动`l`向前直到条件再次变为真。 

每次`l`移动，窗口变得更窄，所以最终情况恢复。 
5. 当前窗口现在包含以以下结尾的最大后缀`r`其值都在一定长度范围内`k`。 
6. 用当前窗口长度更新答案，`r - l + 1`。 
7.处理完每个位置后，输出最大窗口尺寸。 

### 为什么它有效

 在每一时刻，窗口都恰好包含其值适合一个长度区间的元素`k`。 该窗口内的每一对最多相差`k`，所以它们都互相冲突。 它们必须占据不同的学生，使窗口长度成为必要的下限。 

反之，由一条线上的区间构成的冲突图就是区间图。 区间图始终可以精确地使用其最大团的大小来着色。 由于每个派系对应一个这样的窗口，因此最大的窗口大小也足够了。 该算法精确地计算了这个量，因此答案是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    ans = 0
    l = 0

    for r in range(n):
        while a[r] - a[l] > k:
            l += 1
        ans = max(ans, r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```排序将值差异转换为连续的段，从而使滑动窗口能够正常工作。 

左指针只能向前移动，不能向后移动。 该属性保证了排序后的线性工作。 每个元素进入窗口一次并离开窗口一次。 

里面的对比`while`循环必须是`> k`。 Windows 完全不同`k`仍然有效，因为这些值被认为是相似的并且属于同一集团。 

恢复不变量后更新答案`a[r] - a[l] <= k`。 较早更新会计算无效窗口。

 ## 边缘情况

 当`k = 0`，只有相同的价值观才会发生冲突。 

输入：```
3 0
3 1 1
```排序后我们得到`[1, 1, 3]`。 最大有效窗口为`[1, 1]`，其大小为`2`。 算法输出`2`，匹配所需的学生人数。 

当所有值相距很远时，每个窗口都会快速缩小以包含所有已处理的元素，因为每个差异都超过`k`。 

输入：```
4 5
1 10 20 30
```每个有效窗口都有大小`1`，所以答案就变成了`1`。 一个学生可以接收每个香料单元，因为没有一对主题是相似的。 

当许多相等的值与附近的值一起出现时，自然会计算重复项，因为滑动窗口对元素而不是不同的值进行操作。 

输入：```
5 2
5 5 5 6 7
```整个数组适合一个窗口，因为`7 - 5 = 2`。 窗口大小为`5`，所以需要五名学生。 每份副本`5`与所有其他副本冲突，并且两者都`6`和`7`也与他们发生冲突，使得任何较小的任务都变得不可能。
