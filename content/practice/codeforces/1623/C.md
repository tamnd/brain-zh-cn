 ## 解决方案
 ## 问题理解

 我们得到了一系列石堆。 在从第三堆开始的单次从左到右的扫描中，我们可以将每堆石子以固定比例重新分配到前两堆：如果我们选择一个数量$d$，我们删除$3d$从当前堆中取出石头，添加$d$到前一堆，并添加$2d$到之前的那个。 

关键目标不是任意找到最终配置，而是在按顺序执行所有此类移动后最大化最小堆大小。 每堆都既作为源（当我们在扫描过程中到达它时）又作为接收者（来自后面的堆）。 

约束条件很大：最多$2 \cdot 10^5$测试用例总元素。 这排除了每个测试用例的任何二次方。 任何解决方案都必须基本上以线性或接近线性的时间处理每个数组，否则它将无法扩展。 

一个微妙的问题是重新分配不是对称的或可逆的。 一旦我们处理索引$i$，它的贡献被有效地“锁定”，因为较早的桩在扫描中不会被重新访问。 这会产生一种方向依赖性，天真的贪婪推理很容易错误处理。 

当早期的桩看起来太小并且我们错误地延迟补偿时，就会出现典型的失败案例。 例如，在大后缀可以大力支持早期桩的配置中，但前提是我们正确控制从每个后缀元素中提取的量。 

另一个常见的错误是假设每一步的局部平衡都是最优的。 例如，贪婪地最大化每个指数的当前最小值可能会降低未来的转移潜力，从而导致全球范围内更糟糕的结果。 

## 方法

 暴力方法会尝试模拟所有可能的选择$d$在每个索引处。 在每个堆上$i$，我们可以分支所有有效值$d$，递归地探索所有配置并跟踪生成的最小桩。 这显然是指数级的，因为每个堆最多可以贡献$O(h_i)$可能的选择，以及过程的跨度$n$职位。 

即使我们离散化选择，状态空间仍然是巨大的，因为每个决策都会以耦合的方式影响两个较早的位置。 堆之间的交互向后传播，因此无法独立评估局部决策。 

关键的观察是，我们实际上并不关心精确的重新分配，只关心是否有可能确保每堆至少达到某个阈值$x$。 这立即建议对答案进行二分搜索。 

对于固定候选人$x$，我们在一次从左到右的遍历中检查可行性。 关键的想法是将每个堆解释为携带“过剩供应”，可以向后推，但有严格的转换成本：向前发送 3 个单位将产生 1 个单位$i-1$和 2 个单位$i-2$。 

这种结构允许贪婪模拟：在每个索引处，我们累积可以达到它的所有可用供应，确保它满足所需的阈值$x$，并将任何剩余盈余以正确的比例转发至较早的指数。 

这种做法有效的原因是，所有转移在一个方向上（朝向较小的指数）都是单调的，因此早期的决策永远不会从未来的调整中受益，除非通过累计盈余。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 二分查找+贪心检查 | O(n log A) | O(n log A) | O(n) | 已接受 |

 这里$A$是最大桩尺寸。 

## 算法演练

 我们要测试是否有一个固定的最小值$x$所有桩都可以实现。 

1. 对答案进行二分查找$x$0 到$\max h_i$。 这是有效的，因为可行性是单调的：如果我们能够实现$x$，我们也可以得到任何更小的值。 
2. 对于给定的$x$，维护一个数组`cur`它代表我们模拟该过程时每个位置的有效可用棋子。 最初，`cur[i] = h[i]`。 
3. 从左向右扫动。 在索引处$i$，首先添加从索引传播的任何剩余贡献$i+1$和$i+2$在前面的步骤中。 从概念上讲，未来的每一堆都将剩余的向后贡献`cur`。 
4. 如果`cur[i] < x`，该配置是不可行的，因为未来的操作无法将该索引增加到超出已向后传播的索引。 
5. 如果`cur[i] >= x`，我们准确地保留$x$根据需要宝石，并将剩余盈余视为可转移到早期指数。 这笔盈余将转化为捐款$i-1$和$i-2$按照操作规定的固定比例。 
6. 对所有索引继续此过程。 最后，如果没有出现违规情况，候选人$x$是可行的。 

关键的微妙之处在于，盈余必须始终以正确的比例立即向后推。 推迟它会失去转型的结构，因为后来的指数取决于已经汇总的贡献。 

### 为什么它有效

 在每个索引处，我们强制当前堆至少有$x$在收到后缀所有可能的贡献后。 任何超出的额外$x$是最佳使用的，因为不使用它只会减少未来支持早期桩的容量。 由于每个剩余单位都有固定的确定性后向效应，贪婪传播保留了所有未来的可能性。 这创建了一个不变量：处理后索引$i$, 所有桩$j \ge i$至少固定在$x$，所有剩余的灵活性都以最有用的形式被保留。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(a, x):
    n = len(a)
    cur = [0] * (n + 2)
    
    for i in range(n):
        cur[i] += a[i]

    for i in range(n - 1, 1, -1):
        if cur[i] < x:
            return False

        extra = cur[i] - x

        # extra from i can be split:
        # 3 units -> +1 to i-1, +2 to i-2
        if i - 1 >= 0:
            cur[i - 1] += extra // 3
        if i - 2 >= 0:
            cur[i - 2] += 2 * (extra // 3)

    return cur[0] >= x and cur[1] >= x

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        lo, hi = 0, max(a)
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if check(a, mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```该代码将可行性检查与搜索分开。 二分搜索尝试候选最小值并依赖于`check`模拟是否可以在整个阵列中维持该目标。 

里面`check`，我们构建一个工作数组`cur`表示每堆在收到传播剩余后拥有多少有效资源。 后向循环至关重要：它确保在处理索引时$i$，后来的指数的所有贡献都已被考虑在内。 

传输步骤对操作的固定比率进行编码。 我们仅使用 3 个剩余单位的完整组，因为在问题的约束下部分使用无法产生有效的重新分配。 

一个常见的实施陷阱是更新方向错误。 如果我们内部从左到右处理`check`，我们会错误地认为未来的堆积可以弥补当前的赤字，这是不可能的。

 ## 边缘情况

 当最后几堆很小但前面的堆很大时，就会出现容易发生故障的情况。 在这种情况下，天真的前向模拟可能会错误地假设早期桩可以将支撑“推”到后缀中，但由于方向性，这是不可能的。 该算法避免了这种情况，因为可行性是从右到左严格检查的，确保首先强制执行后缀约束。 

另一种边缘情况是当剩余量很大但不能被 3 整除时。只能使用完整的 3 组，因此无法形成完整转移的剩余宝石必须保持未使用。 这是通过传播步骤中的整数除法正确处理的。 

最后，当所有桩都相同时，不需要重新分配。 支票立即通过$x = h_i$，并且二分搜索收敛而不触发任何传输，从而确认该算法不会过度应用不必要的操作。
