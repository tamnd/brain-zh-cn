 ## 解决方案
 ## 问题理解

 我们得到了一根仅由以下材料组成的字符串`(`和`)`。 在所有连续的子串中，我们需要找到构成有效括号序列的子串的最大长度。 我们还需要计算有多少子串达到了最大长度。 

有效的括号序列的行为与表达式中正确匹配的括号完全相同。 每个左括号最终都必须闭合，并且任何前缀都不能包含比左括号更多的右括号。 

输入长度可达`10^6`，这完全改变了可行的方法。 任何检查所有子串的算法都是不可能的。 大致有`n^2`子串，甚至每个子串花费恒定的时间也已经超出了实际限制。 在 2 秒的时间限制下，我们的目标应该是接近线性时间，或者最坏的情况`O(n log n)`。 

棘手的部分是最长的有效子串不一定是两个匹配括号之间的整个有效区域。 无效字符可以将字符串分割成独立的段。 例如：```
())(())
```正确答案是：```
4 1
```子串`(())`有效，但前缀`())(`打破了顺序。 仅计算匹配对的粗心实现可能会错误地返回长度`6`。 

当存在多个最长的子串时，会出现另一个简单的错误：```
()()(()())
```正确答案是：```
10 1
```整个字符串是有效的，即使其中也存在较小的有效片段。 独立计算每个有效段而不正确跟踪最大值可能会过度计数。 

一个特别重要的边缘情况是根本不存在有效的子字符串：```
))))
```输出必须是：```
0 1
```计数是`1`， 不是`0`。 该问题明确定义了这种特殊行为。 

一种更微妙的情况涉及相同大小的断开有效区域：```
()())()
```正确答案是：```
4 1
```子串`()()`有长度`4`，而最后的`()`只有长度`2`。 如果我们在无效括号后错误地重置状态，我们可能会错过较大的段。 

## 方法

 蛮力方法很简单。 我们生成每个子字符串并检查它是否形成有效的括号序列。 可以使用余额计数器来测试有效性：增量`(`, 递减`)`，并确保余额永远不会变为负值并最终为零。 

这在逻辑上是有效的，因为每个有效的括号序列都满足这些条件。 问题是成本。 有`O(n^2)`子串。 即使有效性检查被优化为`O(length)`，总复杂度变为`O(n^3)`。 和`n = 10^6`，这太慢了。 

我们可以使用前缀平衡来改进有效性测试，但我们仍然无法枚举所有子字符串。 甚至`O(n^2)`在这种规模上是不可能的。 

关键的观察结果是有效的括号子字符串在本地表现。 每当我们遇到一个右括号时，我们只关心它前面是否存在一个不匹配的左括号。 这自然意味着堆栈。 

堆栈存储不匹配的左括号的索引。 当我们看到`(`，我们推其索引。 当我们看到`)`，我们尝试将其与最新的未匹配的`(`。 

更深入的见解是如何有效地恢复子串长度。 假设位置`i`关闭一个有效的序列。 那么最长的有效子串结束于`i`紧接在其之前最近的不匹配括号之后开始。 如果我们保留堆栈上最近不匹配位置的索引，我们可以在常数时间内计算长度。 

这将问题从独立检查每个子字符串转换为从左到右处理一次字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了|
 | 最佳堆栈解决方案| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 用单个值初始化堆栈`-1`。 

这充当了哨兵的角色。 它表示字符串开始之前的位置，并允许从索引开始的有效子字符串`0`才能正确测量。 
2.维护两个变量：`best_len`，迄今为止找到的最大有效子串长度。`count`，达到该长度的子串数量。 
3. 从左到右遍历字符串。 
4. 如果当前字符是`(`，将其索引压入堆栈。 

这些索引代表不匹配的左括号，稍后可能形成有效的对。 
5. 如果当前字符是`)`，从堆栈中弹出一个元素。 

我们正在尝试将此右括号与最近的未匹配的左括号相匹配。 
6. 出栈后，检查栈是否变空。 

如果为空，则此`)`无法匹配。 将其索引压入堆栈作为新的无效边界。 

任何未来的有效子字符串都必须在此位置之后开始。 
7. 否则，堆栈仍然包含索引。 

设当前索引为`i`。 结束于的有效子字符串的长度`i`等于：```
i - stack[-1]
```堆栈顶部现在标记有效段之前最近的不匹配位置。 
8. 将此长度与`best_len`。 

如果较大则更新`best_len`并重置`count = 1`。 

如果相等则递增`count`。 
9. 处理完整个字符串后，处理特殊情况：`best_len == 0`。 

所需的输出变为`0 1`。 

### 为什么它有效

 堆栈始终存储不匹配括号的索引。 加工后位置`i`，堆栈顶部表示阻止扩展以结尾的有效子字符串的最近位置`i`。 

当形成匹配对时，删除匹配的`(`在当前有效块之前恰好留下一个边界索引。 从该边界到`i`给出结束于的最大有效子串`i`。 

每个有效子串在处理其右端点时都会被准确地发现，并且最长的子串会被正确测量，因为不匹配的位置将字符串划分为独立的有效区域。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

stack = [-1]

best_len = 0
count = 0

for i, ch in enumerate(s):
    if ch == '(':
        stack.append(i)
    else:
        stack.pop()

        if not stack:
            stack.append(i)
        else:
            length = i - stack[-1]

            if length > best_len:
                best_len = length
                count = 1
            elif length == best_len:
                count += 1

if best_len == 0:
    print("0 1")
else:
    print(best_len, count)
```堆栈开始于`-1`因为有效的子字符串可能从索引开始`0`。 如果没有这个哨兵，像这样的序列`()`会产生长度`1`而不是`2`。 

加工时`)`，我们立即弹出一次。 这对应于消耗一个匹配的`(`或当前无效边界。 如果之后堆栈变空，则当前`)`没有匹配的左括号。 然后我们将其索引存储为最新的无效边界。 

表达式：```
length = i - stack[-1]
```是算法的核心。 匹配成功后，栈顶指向当前有效块之前最近的未匹配索引。 减去得到精确的子串长度。 

操作顺序很重要。 在检查是否为空之前我们必须先弹出。 首先检查会错误地将匹配的括号视为不匹配。 

特殊输出`0 1`单独处理，因为没有有效的子字符串更新`count`。

 ## 边缘情况

 考虑输入：```
))))
```处理第一个字符会弹出哨兵`-1`，使堆栈为空。 该算法立即推送索引`0`作为新的无效边界。 剩下的每个角色都会发生同样的情况。 没有形成有效的子字符串，所以`best_len`停留`0`。 最终的特殊情况处理打印：```
0 1
```现在考虑：```
()())()
```该算法首先发现`()`与长度`2`， 然后`()()`与长度`4`。 在索引处`4`，无与伦比的`)`出现，因此堆栈会随着边界重置`4`。 决赛`()`有长度`2`，这并不影响答案。 输出变为：```
4 1
```这证实了无效的括号正确地分隔了区域。 

最后，考虑：```
(()(
```子串`()`即使额外的左括号仍然不匹配，字符串内部也是有效的。 匹配索引后`2`，堆栈仍然包含索引`0`，给出长度`2`。 决赛`(`保持不匹配，但不会删除较早的有效段。 算法正确输出：```
2 1
```
