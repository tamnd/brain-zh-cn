 ## 解决方案
 ## 问题理解

 我们给定一个长度的字符串$n$由小写英文字母和光标位置组成$p$可以以循环方式围绕字符串向左或向右移动。 使用箭头键，我们可以移动光标或增加/减少光标处的字母（也是循环的，因此“z”后面是“a”，反之亦然）。 目标是使用最少的按键次数将字符串转换为回文。 

输入提供字符串长度$n$, 起始光标位置$p$，以及字符串本身。 输出应该是最少的按键总数，包括光标移动和字母更改。 

和$n$最多$10^5$并且有1秒的时间限制，任何在恒定时间内处理每个字符的算法都是可行的。 尝试每一个可能的移动序列和字母变化的简单暴力方法是不可行的，因为序列的数量呈指数级增长。 我们必须利用回文的对称性和光标移动的结构。 

非明显的边缘情况包括已经是回文的字符串、光标从一端附近开始，以及由于循环移动而需要向左而不是向右移动最佳解决方案的情况。 例如，使用输入`"abca"`并且光标位于位置 4，天真的右移动策略可能会过多计算移动次数。 

## 方法

 蛮力方法很简单：考虑每种可能的按键序列，对其进行模拟，并检查它是否产生回文。 虽然正确，但这需要$O(26^{n/2})$仅针对字母更改的操作，这对于$n$最多$10^5$。 

高效解决方案的关键在于，问题自然分解为两个独立的部分：字母更改和光标移动。 要使字符串成为回文，只有不匹配的字符对$(s[i], s[n-i-1])$为了$i = 0$到$n//2-1$需要纠正。 使用循环字母距离计算每对向上/向下按下的最小次数是微不足道的。 剩下的挑战是最小化光标移动。 

由于光标可以循环左右移动，因此最佳的移动路径是从初始位置开始，转到相关半个字符串中最左边的不匹配和最右边的不匹配，然后以尽可能短的顺序在它们之间遍历。 如果光标从右半部分开始，我们将其镜像到左半部分，因为问题是围绕字符串中点对称的。 

因此，解决方案是：计算每个不匹配对的最小字母变化之和，然后计算覆盖所有不匹配位置的最小光标移动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(26^(n/2)) | O(26^(n/2)) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 如果光标位于字符串的右半部分，则将其镜像到左半部分以简化计算。 让$p$是从 0 开始的。 
2. 迭代第一个$n//2$字符并识别不匹配的位置$s[i] \neq s[n-i-1]$。 跟踪最左边和最右边的不匹配。 
3. 对于每个不匹配的位置，计算匹配镜像字符的向上/向下按下的最小次数。 这使用了循环距离$\min(|a-b|, 26 - |a-b|)$。 将这些相加即可得到总的字母更改成本。 
4. 如果不存在不匹配，则输出零，因为该字符串已经是回文。 
5. 计算光标移动。 有两种策略：首先移动到最左边的不匹配，然后移动到最右边，反之亦然。 两条路径都覆盖了所有不匹配的位置。 最小总移动量是这两个距离中较小的一个加上最左边和最右边不匹配之间的距离。 
6. 返回字母更改成本和光标移动成本之和。 

为什么它有效：我们只修改有助于使字符串成为回文的位置。 该算法涵盖连接所有相关位置的最小路径。 由于循环字母表距离，字母更改成本独立最小。 通过仅考虑不匹配位置的跨度，可以最大限度地减少光标移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, p = map(int, input().split())
s = input().strip()

p -= 1
half = n // 2

if p >= half:
    p = n - 1 - p

left, right = half, -1
letter_changes = 0

for i in range(half):
    if s[i] != s[n - 1 - i]:
        left = min(left, i)
        right = max(right, i)
        diff = abs(ord(s[i]) - ord(s[n - 1 - i]))
        letter_changes += min(diff, 26 - diff)

if right == -1:
    print(0)
    sys.exit(0)

move_cost = min(abs(p - left), abs(p - right)) + (right - left)
print(letter_changes + move_cost)
```为了简单起见，该解决方案首先将光标镜像到左半部分。 然后，它迭代前半部分以计算字母更改成本并找到最左边和最右边的不匹配。 光标移动成本考虑到从当前位置开始并最佳地遍历所有不匹配的位置。 

边界考虑因素包括正确处理从 1 到从 0 的转换、确保循环字母表计算以及当光标已位于不匹配范围的一端时正确计算移动。

 输入：`8 3 aeabcaez`| 我| s[i] | s[n-1-i] | s[n-1-i] 字母变化| 左| 对|
 | --- | --- | --- | --- | --- | --- |
 | 0 | 一个 | z | 1 | 0 | 0 |

 光标从位置 2 开始（从 0 开始：2）。 字母变化 = 1+0+0+1 = 2。最左边不匹配 = 0，最右边 = 3。光标移动 = min(abs(2-0), abs(2-3)) + (3-0) = 1 + 3 = 4。总计 = 2 + 4 = 6。

这些痕迹表明算法正确计算了最小的字母变化和光标移动。

 ## 边缘情况
