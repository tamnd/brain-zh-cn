 ## 解决方案
 ## 问题理解

 该问题要求我们计算事件对的数量，其中两个事件发生的时间足够接近并且具有相反的符号。 每条记录都给出一个时间戳和一个符号，其中`+`和`-`代表两个不同的方面。 如果时间戳相差最多，则一对有效`d`并且这两个标志是不同的。 事件已经按时间排序，因此任务是有效地计算所有此类交叉符号对。 

输入尺寸可以达到`3 * 10^5`，这会立即排除检查每对事件。 直接比较将围绕`n * (n - 1) / 2`检查，大约是`4.5 * 10^10`以最大尺寸进行操作。 即使是非常优化的实施也无法在典型的比赛时间限制内完成。 我们需要利用时间戳已排序的事实。 

在其他合理的解决方案中，一些细节会导致错误的答案。 相等的时间戳是一个常见的陷阱，因为差异可以为零，并且条件允许具有相同时间的对。 例如：```
3 0
5 5 5
+-+
```答案是`2`因为两个`+`事件与`-`同一时间戳的事件。 只寻找严格更小或更大时间的解决方案将会错过它们。 

另一个错误是忘记同一时间戳的多个事件是单独的事件。 例如：```
4 1
1 1 2 2
++--
```答案是`4`。 每一个`+`在某个时间`1`匹配每一个`-`在某个时间`2`。 仅计算不同的时间戳会产生`1`，这是错误的。 

最后一个棘手的情况是距离的边界`d`。 例如：```
2 3
10 13
+-
```答案是`1`因为距离正好是`3`。 使用严格比较而不是`<= d`丢失有效对。 

## 方法

 最简单的方法是将每个积极事件与每个消极事件进行比较。 对于每一对，我们计算它们时间之间的绝对差，如果最多则加一`d`。 这很容易推理，因为它直接遵循有效对的定义。 

问题在于比较的数量呈二次方增长。 和`n = 300000`，可能的对的数量大致为`45000000000`，这远远超出了我们的处理能力。 

有用的观察来自排序的时间戳。 我们可以维护一组与当前事件仍然足够接近的先前事件，而不是检查每个较早的事件是否与较晚的事件匹配。 当我们从左向右移动时，之前的每个事件要么保留在允许的时间窗口内，要么变得太旧并且永远无法再次匹配。 

对于每个当前事件，我们至少需要知道有多少个先前事件具有相反的符号和时间戳`current_time - d`。 由于输入已排序，我们可以使用移动指针删除过期事件。 我们只需要活跃的计数`+`和`-`事件，而不是他们的个人立场。 

当当前事件是`+`，它与所有活跃的形成一个有效的对`-`事件。 When it is`-`，它与所有活跃的形成一个有效的对`+`事件。 计数后，我们将当前事件插入到活动窗口中，以便将来的事件可以使用它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 滑动窗口计数| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将所有事件存储为`(time, sign)`对。 The events are already sorted, so we can process them in the given order without sorting again. Keep a left pointer representing the first event that is still inside the valid time window.
 2. 维护由符号分隔的活动事件的计数。 The active window contains exactly the previous events whose timestamps are at least`current_time - d`。 
3. 在处理当前事件之前，当左侧事件太旧时，将左指针向前移动。 从活动计数中删除其符号，因为它无法再与任何未来事件形成有效的对。 
4. 查看当前事件的标志。 如果是的话`+`, 添加活跃数`-`事件来给出答案。 如果是的话`-`, 添加活跃数`+`事件代替。 这些与之前的事件完全相同，具有相反的符号和有效距离。 
5. 通过增加相应的符号计数将当前事件插入到活动窗口中。 它可能会匹配以后的事件，因此它必须保持可用。 

为什么它有效：在扫描中的每个点，活动窗口包含所有且仅先前的事件，这些事件仍然可以与当前和未来的事件创建有效的对。 当处理该对中的较晚事件时，每对都只计数一次。 由于我们仅添加活动窗口中的相反符号事件，因此每个计数对都满足符号条件和时间条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    t = list(map(int, input().split()))
    s = input().strip()

    ans = 0
    left = 0
    plus = 0
    minus = 0

    for i in range(n):
        while left < i and t[left] < t[i] - d:
            if s[left] == '+':
                plus -= 1
            else:
                minus -= 1
            left += 1

        if s[i] == '+':
            ans += minus
            plus += 1
        else:
            ans += plus
            minus += 1

    print(ans)

if __name__ == "__main__":
    solve()
```主循环实现了演练中的滑动窗口。 指针`left`永远不会向后移动，因此每个事件最多被删除一次。 这就是使总工作保持线性的原因。 

去除条件使用`t[left] < t[i] - d`而不是`<=`因为时间戳完全不同`d`仍然有效。 当前事件在添加到存储的计数之前先进行计数，以防止事件与其自身配对。 

Python 整数在这里就足够了，因为答案可以与所有对的数量一样大，大约是`4.5 * 10^10`。

 ## 边缘情况

 对于时间戳相等的情况：```
3 0
5 5 5
+-+
```第一个事件被添加到活动中`+`数数。 第二个事件看到一个活跃的`+`，所以它添加了一个有效的`-`对并添加到`-`数数。 第三个事件看到一个活跃的`-`，添加另一对。 结果是`2`，这符合只有完全相同时间的事件才能配对的事实。 

对于许多事件的重复时间戳：```
4 1
1 1 2 2
++--
```两个事件同时发生`1`同时处理两个事件时保持活动状态`2`，因为它们的区别正是`1`。 每个负面事件计数两个正面事件，给出`4`总对。 该算法可以处理多重性，因为它存储的是事件计数，而不是唯一的时间戳。 

对于边界条件：```
2 3
10 13
+-
```第一个事件保留在窗口中，因为`10 < 13 - 3`是假的。 第二个事件看到一个相反符号的事件并将其添加到答案中。 结果是`1`，证明包含比较处理正确。
