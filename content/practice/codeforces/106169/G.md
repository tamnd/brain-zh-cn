 ## 解决方案
 ## 问题理解

 我们得到了一本秘密单词词典和一个文本字符串。 文本包含小写字母和特殊字符`?`。 

一个`?`可以代表任何单个小写字母。 任务是计算整个文本可以有多少种不同的方式分割成字典单词。 

如果字典单词具有相同的长度并且每个位置满足以下条件之一，则它们与文本片段匹配：

 - 文本字符等于单词字符；
 - 文本字符是`?`，这意味着它可以代表该单词字符。 

每个词典单词可以使用任意多次。 文本的每个字符必须完全属于一个选定的单词。 我们需要有效分解的模数`10^9 + 7`。 

限制很小，但很有启发性。 最多有 100 个单词，每个单词的长度最多为 10，文本长度最多为 100。解决方案`O(|T| * n * maxLen)`是完全安全的。 甚至`100 * 100 * 10 = 100000`人物比较很小。 

主要的微妙之处在于`?`不只创建一个匹配的单词。 它可能匹配几个不同的字典单词，并且每个匹配选择分别对答案做出贡献。 

考虑第一个样本：```
Words: a, b, c, d, ab, bc, cd
Text: ab?d
```第三个字符可以表现为`a`,`b`,`c`， 或者`d`，产生几个不同的分解。 答案是 11，而不是 4。 

另一个容易犯的错误是忘记相同长度的不同单词可以匹配相同的子字符串。 

例子：```
Words:
ab
ac

Text:
a?
```两个词都匹配。 答案是：```
2
```仅记录某个位置是否可达的布尔 DP 将错误地返回 1。 

第三种边缘情况是整个文本由问号组成。 

例子：```
Words:
a
b

Text:
??
```第一个位置有2个选择，第二个位置有2个选择，所以答案是：```
4
```这是官方样本之一。 

## 方法

 最直接的想法就是递归回溯。 从文本的开头开始，尝试与当前位置匹配的每个字典单词，并递归处理字符串的其余部分。 每一次成功的完成都会为答案贡献一份力量。 

这种方法是正确的，因为每个有效的分解都恰好对应于递归树中的一条路径。 问题在于相同的后缀被重新计算多次。 在最坏的情况下，例如文本充满`?`字符和许多匹配的单词，递归状态的数量呈指数增长。 

重复的工作表明动态规划。 

让`dp[i]`表示分解在位置之前结尾的前缀的方法数`i`。 然后，每个匹配的单词都会从较早的位置过渡到较晚的位置。 

假设一个单词的长度`L`匹配以位置结尾的子字符串`i`。 然后，该单词之前的前缀的每个有效分解都可以通过该单词进行扩展。 这给出：```
dp[i] += dp[i - L]
```剩下的唯一任务是有效检查单词是否与文本段匹配。 由于字长最多为 10，因此简单的逐个字符比较已经足够快了。 

蛮力直接探索分解。 动态编程解决方案对每个前缀的所有分解进行一次计数并重用这些结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(|T|
 | 最佳DP | O( | T | × n × maxLen) | O( | T | × n × maxLen) |

 ## 算法演练

 1. 阅读所有字典单词。 
2.让`m`是文本的长度并创建一个数组`dp`长度`m + 1`。 
3. 设置`dp[0] = 1`。 

这代表空前缀。 只有一种方法可以分解任何东西。 
4. 对于每个位置`i`从`0`到`m - 1`，检查每个字典单词。 
5.让当前单词有长度`L`。 

如果`i + L > m`，单词不能从位置开始`i`，所以跳过它。 
6. 将单词与文本段进行比较`T[i : i + L]`。 

对于每个职位`j`，如果满足以下任一条件，则匹配成功`T[i + j] == '?'`或者`T[i + j] == word[j]`。 
7. 如果整个单词匹配，则添加：```
dp[i + L] += dp[i]
```并对结果取模`10^9 + 7`。 

每次分解到达位置`i`可以用这个匹配词来扩展。 
8.处理完所有位置和单词后，输出`dp[m]`。 

### 为什么它有效

 不变的是`dp[i]`始终等于第一个的有效分解数`i`文本的字符。 

最初这是正确的，因为空前缀只有一次分解。 

每当一个单词从位置开始匹配时`i`，每次分解计算`dp[i]`可以通过该词进行扩展，产生长度的分解`i + L`。 该转换恰好添加了这些新的分解，仅添加了其他内容。 

每个有效的分解都有一个唯一的最后一个词。 当处理最后一个单词时，通过其前面的前缀将分解计数一次。 因为每个分解都生成一次并且每个生成的分解都是有效的，`dp[m]`等于想要的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

n = int(input())
words = [input().strip() for _ in range(n)]
text = input().strip()

m = len(text)

dp = [0] * (m + 1)
dp[0] = 1

for i in range(m):
    if dp[i] == 0:
        continue

    for word in words:
        L = len(word)

        if i + L > m:
            continue

        ok = True
        for j in range(L):
            if text[i + j] != '?' and text[i + j] != word[j]:
                ok = False
                break

        if ok:
            dp[i + L] = (dp[i + L] + dp[i]) % MOD

print(dp[m])
```DP 数组存储前缀的计数。 位置`i`代表第一个`i`文本的字符，这使得转换干净并避免差一错误。 

直接进行匹配测试。 由于每个单词长度最多为 10，因此无需进行哈希、尝试或字符串预处理。 

这`if dp[i] == 0`检查不是正确性所必需的，但它避免了来自不可到达状态的不必要的匹配尝试。 

每次加法之后都应用模运算，因为当许多运算时，分解的数量会增长得非常快。`?`字符存在。

 ## 边缘情况

 考虑：```
2
ab
ac
a?
```在位置 0 处，两个单词都匹配，因为`?`可以代表任一`b`或者`c`。 

该算法执行两种转换：```
dp[2] += dp[0]
dp[2] += dp[0]
```给予`dp[2] = 2`。 仅检查某个单词是否匹配的解决方案会错误地生成 1。 

考虑：```
2
a
b
??
```在第一个字符处，两个单词都匹配。 同样的情况也发生在第二个角色上。 

DP 演变为：```
dp = [1, 2, 4]
```并返回 4。这正确地计算了所选单词隐含的每个字母分配。 

考虑：```
1
ab
a
```该单词比其余文本长。 跳过转换是因为`i + L > m`。 没有状态到达终点，所以`dp[m]`仍然为 0，正确表明文本无法分解为字典单词。
