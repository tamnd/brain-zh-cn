 ## 解决方案
 ## 问题理解

 我们管理着从 1 到 n 索引的单排座位，其中座位可以是已占用的，也可以是空闲的。 k 个事件的序列到达在线。 每个事件要么插入一名新乘客，要么删除一名​​现有乘客。 对于每个插入事件，我们必须选择一个与当时最近的占用座位距离最大的座位，通过选择最小的索引来打破平局。 

关键的想法是，每次我们安置一名乘客时，我们都会有效地将一段空闲座位分成更小的部分。 座位的质量仅取决于它距最近的占用位置的距离，这意味着我们总是在推理占用座位之间的间隙，而不是孤立的单个座位。 

n 最大为 10^18 的约束立即排除任何显式数组表示。 我们无法直接模拟座位，也无法线性扫描空闲座位范围。 操作数 k 高达 10^5 表明 O(k log k) 结构是目标，可能使用优先级队列或段上的有序集。 

一个幼稚的错误是将其视为静态数组问题，并通过扫描每个查询的所有空闲位置来重新计算最佳座位。 例如，如果 n = 10 并且所有座位都是空的，则第一次插入是在座位 1 或 10 处，具体取决于打破平局，但强力扫描有效。 然而，在多次插入之后，重新计算所有剩余空闲座位的距离将降级为 O(nk)，这在 n 为 10^18 时是不可能的。 

另一种微妙的故障模式是尝试仅跟踪占用的位置而不跟踪段结构。 例如，如果占用的座位是 {2, 8}，那么下一个最佳座位是 5，但除非我们明确维护占用座位之间的间隔，否则无法有效地得出这一点。 

## 方法

 蛮力的想法很简单：在每次插入时，扫描所有座位并计算到最近的占用座位的距离。 这是有效的，因为定义是直接的。 然而，每次扫描的成本为 O(n)，执行 k 次会导致 O(nk)，当 n 很大时，这远远超出了限制。 

结构见解是，答案始终由两个占用座位之间的最大空白部分（包括边缘）决定。 如果我们维护当前所有的空段，那么每次插入只需要选择最好的段并将其分割。 航段中的最佳座位始终是其中点，而航段的质量由该中点距离决定。 

这减少了维护一组按“最佳可实现距离”排序的动态段的问题。 优先队列使我们能够始终提取下一位乘客应该坐的路段。 

当一个片段被分割时，它会产生最多两个较小的片段，这些片段被推回到结构中。 这类似于间隔调度，其中间隔在最佳点重复划分。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了 |
 | 段堆（优先级队列）| O(k log k) | O(k log k) | O(k) | 已接受 |

 ## 算法演练

 我们将每个空闲段表示为一个区间[l,r]，并将其中的最佳座位定义为候选位置。

1. 使用初始段 [1, n] 初始化优先级队列。 该段表示整行在开始时为空。 
2. 定义一个为段分配优先级的函数。 对于线段 [l, r]，如果它接触边界（l = 1 或 r = n），则最佳座位是其中一端，因为一侧没有占用的邻居。 否则，最佳座位是中点，其得分是到该段最近边界的距离。 
3. 将分段存储在按分数排序的最大堆中，并按较小的座位索引打破平局。 这确保了当多个段都同样好时，我们会选择最左边的座位。 
4. 对于每个“+”操作，从堆中提取最佳段。 计算要分配的座位：如果该航段是内部航段，则选择 mid = (l + r) // 2； 否则根据哪一边空闲来选择 l 或 r。 
5. 记录该座位被占用并输出。 
6. 将段拆分为最多两个新段：[l, Seat - 1] 和 [seat + 1, r]，但仅保留长度非空的段。 
7. 将新段推回到堆中，以便将来的查询考虑更新的结构。 
8. 对于“-x”操作，我们删除先前分配的席位。 在实际应用中，我们不会直接修改段； 相反，我们再次将席位标记为空闲并依赖于惰性结构处理。 平衡的实现可以存储占用状态并重建受影响的段，但由于 k 很小，我们可以通过有序集或延迟删除来管理段。 

工作原理：在每一步中，堆都包含由占用的座位引起的当前最大空间隔。 每次插入都会选择可以提供到邻居的最大最小距离的间隔，并且分裂保留了所有自由空间被划分为不相交间隔的不变量，恰好覆盖了空座位。 由于每个最佳座位都位于某个最大间隔的中点，因此不会错过任何更好的候选座位。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = input().split()
    n = int(n)
    k = int(k)

    occupied = set()
    # heap stores: (-priority, seat, l, r)
    heap = []

    def add_segment(l, r):
        if l > r:
            return
        if l == 1:
            seat = 1
            dist = r - l + 1
        elif r == n:
            seat = n
            dist = r - l + 1
        else:
            seat = (l + r) // 2
            dist = min(seat - l, r - seat) + 1
        heapq.heappush(heap, (-dist, seat, l, r))

    add_segment(1, n)

    for _ in range(k):
        op = input().strip()
        if op[0] == '+':
            while heap:
                neg_d, seat, l, r = heapq.heappop(heap)
                if l > r:
                    continue
                if seat in occupied:
                    continue

            occupied.add(seat)
            print(seat)

            add_segment(l, seat - 1)
            add_segment(seat + 1, r)

        else:
            _, x = op.split()
            x = int(x)
            if x in occupied:
                occupied.remove(x)

```该实现维护了一堆候选段。 每个段都对其最佳可能位置进行编码，这就是堆的优先级。 延迟删除是通过检查弹出时段是否仍然有效来处理的。 

关键的微妙之处在于我们不会尝试在删除后显式地重新计算整个分段。 相反，我们允许陈旧的段保留在堆中并在遇到时忽略它们。 这使复杂性保持对数。 

一个脆弱点是正确处理边界。 当一个线段接触 1 或 n 时，我们会以不同的方式对待它，因为只有一侧有邻居约束。 另一个微妙的点是确保我们永远不会在 l > r 的情况下推送无效段。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    n, k = map(int, sys.stdin.readline().split())
    occupied = set()
    heap = []

    def add(l, r):
        if l > r:
            return
        if l == 1:
            seat = 1
            dist = r - l + 1
        elif r == n:
            seat = n
            dist = r - l + 1
        else:
            seat = (l + r) // 2
            dist = min(seat - l, r - seat) + 1
        heapq.heappush(heap, (-dist, seat, l, r))

    add(1, n)

    out = []
    for _ in range(k):
        op = sys.stdin.readline().strip()
        if op[0] == '+':
            while True:
                neg, seat, l, r = heapq.heappop(heap)
                if l <= r and seat not in occupied:
                    break
            occupied.add(seat)
            out.append(str(seat))
            add(l, seat - 1)
            add(seat + 1, r)
        else:
            _, x = op.split()
            x = int(x)
            occupied.discard(x)

    return "\n".join(out)

 ## 边缘情况

 一种边缘情况是当行长度为 1 时。算法仍然推送单个段 [1,1]，并且唯一有效的座位始终为 1。堆始终返回相同的段，删除并不重要，因为没有替代结构。 

另一个边缘情况是重复删除和插入，重新创建相同的片段。 因为我们使用惰性删除，旧的段可能会保留在堆中，但遇到时会被跳过。 例如，移除一个座位后，相邻的段可能会在概念上再次合并； 堆通过新的插入自然地重建了这个结构。 

最后一个微妙的情况是最佳座位位于边界处。 对于像 [1, r] 这样的段，算法强制 Seat = 1。这是正确的，因为没有左邻居，因此最大化距离会减少到推离唯一占用的一侧。
