 ## 解决方案
 ## 问题理解

 我们从一系列任务开始，按照自然顺序从 1 到 n 编号。 随着时间的推移，Yurik 重复选择当前排序的连续片段，并使用从全局排列 p 导出的固定规则仅对该片段进行完全重新排序。 

规则如下：当选择长度为 m 的段时，我们暂时将值 p1 分配给该段左端的元素，分配给下一个元素 p2，依此类推，直到 pm。 然后，我们根据这些分配的值对段中的元素进行排序，并按排序顺序将它们写回。 在该段之外，没有任何变化。 

在应用 q 个这样的段重新排序操作后，我们只被问到一个问题：哪个任务最终位于位置 k。 

关键的难点在于，每个操作都取决于当前的排序，因此后面的每个操作都作用于修改后的数组，并且一个操作的效果不是简单的反转或旋转。 相反，每个段都按 p 确定的固定“模式”重新排序，但该模式适用于当前占据该段的任何元素。 

约束 n、q 高达 100000 意味着任何显式执行每个段排序的模拟都太慢。 单个排序的成本为 O(n log n)，并且在最坏的情况下执行 q 次会导致大约 10^10 次操作。 即使是线性的每次操作模拟也太慢，因为每个操作都可能涉及大段。 

打破天真的思维的微妙边缘情况是，段排序在值方面不是局部的，它取决于全局排列 p。 例如，如果 p = [3, 1, 2] 并且我们将其应用于段 [a, b, c]，则第二个元素将在第一个元素之前移动，即使 a、b、c 本身没有表明该顺序。 按段中的值或索引排序的幼稚实现会产生完全错误的行为。 

## 方法

 直接模拟通过获取段、分配键 p1 到 pm、排序和写回来应用每个操作。 这是正确的，但太慢了，因为每个操作在段大小上至少是线性的，在最坏的情况下会导致 O(nq) 行为。 

关键的观察是我们不需要向前模拟数组。 我们只需要知道所有变换后位置 k 最终在哪里。 这表明反转该过程：我们不是通过 q 操作将元素向前推，而是通过逆变换向后追踪位置 k。 

段上的每个操作都是该段内位置的排列。 由于按 p 排序是确定性的，因此该操作对应于长度为 m 的段的固定排列 πm。 因此，逆操作也是固定的：它将段内的一个位置映射到排序之前的原始位置。 

因此，我们不是构建整个数组，而是通过向后遍历操作来重复更新单个索引 k。 主要困难在于计算段 [l, r]，其中按 p 排序的顺序中的给定排名来自该段。 

要反转段上的操作，我们必须回答对数组 p 中索引 1 到 m 的顺序统计查询。 具体来说，当索引按 p[i] 排序时，我们需要找到给定排名的元素。 这可以简化为计算有多少个索引 i ≤ m 满足 p[i] ≤ x，然后使用它来二分搜索所需的元素。 

这会将每个反演步骤转换为对数或对数平方顺序统计查询，对于 q 高达 100000 来说速度足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | O(nq) | O(n) | 太慢了 |
 | 逆向遍历带顺序统计 | O(q log^2 n) | O(q log^2 n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

我们以相反的顺序处理运算，因为每个运算都是一个排列，因此是可逆的。 

1. 从最终数组中的目标位置k开始。 这就是我们想要通过转换向后追踪的位置。 
2. 迭代从 q 到 1 的操作。对于每个操作，令其段为 [l, r]，长度 m = r − l + 1。 
3. 如果当前位置k在[l,r]之外，则操作不影响它，我们继续。 
4. 如果 k 在 [l, r] 内部，则将其转换为局部索引 x = k − l + 1。这表示其在反转之前在段内的位置。 
5. 前向操作按 p[i] 对段进行排序，其中 i 从 1 到 m。 因此，为了反转它，我们必须确定段内的哪个原始索引对应于p[1..m]排序中的排名x。 
6. 为了计算这个，我们需要找到值 p[1..m] 中的第 x 个最小元素，但作为索引位置返回。 由于 p 是排列，我们可以使用从值到位置的逆映射。 
7. 我们定义一个辅助函数：给定 m 和阈值 v，我们计算有多少个索引 i ≤ m 满足 p[i] ≤ v。这允许我们二分搜索最小的 v，使得 p[1..m] 中至少 x 值 ≤ v。 
8. 一旦找到值 v，我们就将其转换回原始排列数组中的位置 i = pos[v]，其中 pos 是 p 的逆。 
9. 将 k 替换为 i，因为这是此操作之前数组的前一个状态中的位置。 

处理完所有操作后，k 指向最终位置 k 处的原始任务编号。 

正确性依赖于每一步中的不变量，k 表示在处理剩余后缀操作之前数组状态中的位置。 每个反转步骤都精确地反转一个排列对段的影响，并且由于所有操作都是双射，因此逆的组合唯一地重建了原始位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_pos(p):
    n = len(p)
    pos = [0] * (n + 1)
    for i, v in enumerate(p, 1):
        pos[v] = i
    return pos

def count_leq(p, m, v):
    cnt = 0
    for i in range(1, m + 1):
        if p[i] <= v:
            cnt += 1
    return cnt

def kth_index(p, pos, m, k):
    lo, hi = 1, len(p) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if count_leq(p, m, mid) >= k:
            hi = mid
        else:
            lo = mid + 1
    return pos[lo]

def solve():
    n, q, k = map(int, input().split())
    p = [0] + list(map(int, input().split()))
    pos = build_pos(p)

    ops = [tuple(map(int, input().split())) for _ in range(q)]

    for l, r in reversed(ops):
        if k < l or k > r:
            continue
        m = r - l + 1
        x = k - l + 1
        new_pos = kth_index(p, pos, m, x)
        k = new_pos

    print(k)

if __name__ == "__main__":
    solve()
```该解决方案将排列结构与动态数组演化分开。 除了跟踪单个索引之外，数组本身从未被显式维护。 

功能`kth_index`对可能的 p 值执行二分搜索，使用`count_leq`作为谓词。 这是核心简化：段重新排序被转换为对索引前缀的顺序统计查询，完全由固定排列 p 控制。 

反向循环至关重要，因为每个操作都被撤消一次。 正向模拟需要重建分段； 向后模拟仅需要将逆映射应用到单个位置。 

## 工作示例

 考虑一个小实例，其中 n = 5，p = [2, 3, 1, 5, 4]，我们应用两个操作：[1, 3]，然后是 [2, 5]。 假设我们跟踪 k = 3。 

### 反转操作后

 | 步骤| 运营| 段长m | k（之前）| 内段| 本地 x | 行动结果|
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [2, 5] | 4 | 3 | 是的 | 2 | 通过 p[1..4] | 的顺序映射
 | 2 | [1, 3] | 3 | 更新 | 是的 | ... | 最终索引 |

 在第一个反向步骤中，我们查看 p[1..4] = [2,3,1,5] 的顺序。 按 p 排序给出索引 [3,1,2,4]。 第二小的对应于索引 1，因此 k 在该操作之前成为数组状态中基于 1 的位置 1。 

第二步，我们在较小的段上重复相同的逻辑，最终恢复原始索引。 这显示了每个反转步骤如何“展开”一个排列层。 

该轨迹证实了关键不变量：在反向处理 i 个操作之后，k 始终引用那些 i 个操作之前的状态中的有效位置。

 ## 边缘情况

 当长度为 1 的段重复出现时，会出现一种微妙的情况。 在这种情况下，排列 π1 始终是恒等的，因为只有一个元素并且 p1 没有影响。 该算法自然地处理这个问题，因为订单统计查询总是返回相同的索引，因此 k 永远不会改变。 

另一种边缘情况是当 k 通过相反的操作重复进入和退出不同的段时。 该算法正确地将 k 保留在受影响的段之外，因为排列反转严格限于 [l, r]，并且检查 k < l 或 k > r 确保不会出现意外更新。 

最后的边缘情况是当 m 很大且 p 导致段内几乎相反的排序时。 即使在这种极端情况下，对 p 值的二分搜索仍然可以正确识别第 k 个元素，因为排序完全来自 p[i] 的比较，而不是来自数组中存储的值。
