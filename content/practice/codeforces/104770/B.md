 ## 解决方案
 ## 问题理解

 该任务与标准战舰网格有关，但被简化为单个查询。 您将获得一块方板，其中每个单元格要么是空水，要么包含船的一部分。 除了这个网格之外，您还会获得一个代表对手射击的坐标。 你的任务是确定射击是击中飞船单元还是落入水中。 

更具体地说，输入提供整数网格大小和一对坐标。 然后它给出一张 n × n 的字符图，其中一个符号标记船舶单元，另一个标记空海。 输出是基于指定坐标是否对应于船舶单元的简单是或否决策。 

约束足够小，任何 O(n²) 的网格扫描速度都非常快。 即使在解析网格后直接查找也是最佳的，因此除了读取矩阵之外不需要任何预处理。 问题的结构排除了任何算法复杂性问题，例如图遍历或优化。 

主要的微妙之处在于索引和输入格式。 坐标是以从零开始的索引给出的，而许多程序员本能地将网格视为从一开始的。 另一个常见的陷阱是假设网格的输入格式不同，例如空格分隔的字符而不是连续的字符串，这会改变每行的解析方式。 

当镜头位于边界或角落时，就会出现具体的边缘情况。 例如，如果 n = 1 并且网格是包含水的单个单元格，则在 (0, 0) 处的射击必须输出“是”。 粗心的实现会意外地交换行和列或将索引移动一位，从而错误地对这种情况进行分类。 

## 方法

 暴力解释是将每个查询视为对整个网格的扫描，以查找目标单元是否是一艘船。 对于每个查询，您将迭代所有 n² 单元格并比较坐标。 这是正确的，因为它直接检查命中的定义，但它浪费了工作，因为只有一个单元格很重要。 

关键的观察结果是整个网格是静态的，并且查询只询问一个位置。 这意味着我们不需要搜索； 我们只需要直接索引到预加载的二维结构中。 一旦网格存储在内存中，访问单个单元的时间复杂度为 O(1)，因此整个问题简化为读取输入并执行一次查找。 

从暴力到最优的转变来自于认识到静态矩阵上的空间查询不需要重复扫描。 网格本身已经编码了所有必要的信息，因此预处理只是解析。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的强力扫描 | O(n²) | O(n²) | 太慢（不必要的工作） |
 | 直接索引 | O(n²) 预处理，O(1) 查询 | O(n²) | 已接受 |

 ## 算法演练

 1. 读取整数n、r、c，它们定义网格大小和射击位置。 假定坐标是从零开始的，因此不需要调整。 
2. 读取网格的 n 行并将它们存储在允许直接索引的结构中。 每行都可以存储为字符串或字符列表，以便可以立即访问 grid[r][c]。 
3. 访问存储网格中位置 (r, c) 的单元格。 
4. 如果该单元格包含船舶标记，则输出“否”，因为射击是命中。 否则输出“Yes”，因为这是一个未命中。 

步骤 4 背后的推理直接来自问题定义：“否”对应于撞船，而“是”对应于水。 

### 为什么它有效

该算法保留输入网格单元和内存表示之间的一对一映射。 由于没有执行网格转换，因此每个查询坐标都精确对应于一个存储的字符。 这使得正确性仅取决于正确的解析和正确的索引，因此不需要组合或几何推理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, r, c = map(int, input().split())
    grid = [input().strip().replace(" ", "") for _ in range(n)]

    if grid[r][c] == 'S':
        print("No")
    else:
        print("Yes")

if __name__ == "__main__":
    main()
```关键的实现细节是处理以下事实：在语句的某些变体中，行可能在字符之间包含空格。 使用`replace(" ", "")`如果输入是空格分隔的，则确保鲁棒性。 

索引始终保持从零开始，直接匹配问题定义，这避免了网格问题中常见的差一错误。

 ## 边缘情况

 关键的边缘情况是 1 x 1 网格，其中行索引和列索引都必须正确解析，而无需假设任何周围结构。 在这种情况下，算法会简化为单个字符比较，任何索引错误都会立即变得可见。 

另一种边缘情况是输入的字符之间包含空格。 将每一行视为原始字符串而不删除空格会移动索引并产生不正确的结果。 该解决方案通过在索引之前标准化每行来避免这种情况，确保网格结构与预期的 2D 布局相匹配。
