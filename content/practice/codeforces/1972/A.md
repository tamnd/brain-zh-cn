 ## 解决方案
 ## 问题理解

 我们有一场比赛`n`问题，每个问题都有一个建议的难度`a_i`以及预期的最大难度`b_i`。 两个序列均按非降序排序。 目标是调整提出的困难，使每个问题都满足`a_i ≤ b_i`。 

唯一允许的操作是提出一个任何困难的新问题`w`。 提出后，将新问题插入到数组中`a`，对数组进行排序，并删除最大的元素。 实际上，我们正在用我们可以控制的新问题取代更困难的问题之一。 

输出是必须提出以满足的新问题的最少数量`a_i ≤ b_i`为所有人`i`。 

限制很小：`n`最多可以达到 100 个，并且最多有 100 个测试用例。 这意味着`O(n^2)`每个测试用例的解决方案是可以接受的，因为`100*100^2 = 10^6`操作一秒轻松搞定。 

非明显的边缘情况包括所有提出的困难超出预期的序列，例如`a = [5,6,7]`和`b = [1,2,3]`，要求我们为每个不匹配提出一个新问题。 另一个微妙的情况是，当只有前几个元素时`a`超过`b`但其余的都很好，因为贪婪方法必须首先针对最早的不匹配。 

## 方法

 一种朴素的暴力方法会模拟每一个可能的新问题插入，尝试每一种可能的方法`w`从`1`到`max(a_i,b_i)`直到满足条件。 这是有效的，因为每次插入后，最大的元素都会被删除，因此最终可以减少所有元素。 不过，候选人数`w`值是巨大的（`10^9`），使得暴力破解变得不切实际。 

关键的见解是数组是排序的。 我们不需要尝试任意值。 如果我们从最简单到最难处理问题，则提出的最小新问题只是违反条件的第一个问题的预期难度。 插入它将替换最大的元素并使数组更接近目标。 每个违规行为都可以通过这种方式贪婪地修复。 

因此，最佳方法是贪心两指针方法。 我们维护一个指针`a`和`b`从左到右。 每当`a[i] > b[i]`，我们将其视为一个必要的新问题。 新问题的数量就是此类违规行为的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 最大值(a_i,b_i)) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`ops = 0`跟踪所需的新问题的数量。 
2. 遍历两个数组`a`和`b`从第一个问题到最后一个问题。 
3. 对于每个索引`i`， 比较`a[i]`和`b[i]`。 
4. 如果`a[i] > b[i]`, 增量`ops`1. 这计算了我们必须提出的新问题的数量，以取代过于困难的问题。 
5.处理完所有索引后，输出`ops`。 

贪心选择是合理的，因为数组已排序。 什么时候`a[i] > b[i]`，右侧的任何元素都无法在不替换更大元素的情况下解决违规问题。 每个操作都会替换最大的元素，并确保我们可以首先减少最左边的违规。 不变的是之后`ops`操作，第一个`n - ops`的元素`a`已经 ≤ 的对应元素`b`，我们只需要替换剩下的`ops`元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    ops = 0
    for i in range(n):
        if a[i] > b[i]:
            ops += 1
    print(ops)
```该解决方案使用有效地读取多个测试用例`sys.stdin.readline`。 它遍历每个索引，计算违规次数。 不需要排序，因为输入数组已经排序。 比较很简单，可以避免任何相差一的错误。 递增`ops`直接对应于提出一个新问题。

 ## 边缘情况

 对于所有提出的问题都大于预期的边缘情况，`a = [10,20,30]`和`b = [1,2,3]`，算法正确计数`3`运营。 每次迭代都会识别`a[i] > b[i]`并增加计数器。 即使值很大（`10^9`)，比较不会溢出。
