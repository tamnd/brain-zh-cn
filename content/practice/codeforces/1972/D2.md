 ## 解决方案
 ## 问题理解

 我们被要求计算有序的正整数对`(a, b)`这样`1 ≤ a ≤ n`和`1 ≤ b ≤ m`，还有一个附加的整除条件：`b * gcd(a, b)`必须能整除`a + b`。 从概念上讲，`a`和`b`可以被认为是“卡片”上的两个数字，我们正在检查哪些对满足特定的数学关系。 

关键的挑战来自尺寸限制。 两个都`n`和`m`最多可达200​​万个，测试用例最多可达10000个。 尝试一切的天真的方法`(a, b)`在最坏的情况下，这对需要高达 4 万亿次操作，这远远超出了 2 秒时间限制的可行范围。 这立即排除了任何 O(n * m) 暴力策略。 

不明显的边缘情况是由小数和互质数引起的。 例如，`(1,1)`永远不满足条件，因为`1*1`不能被整除`2`。 同样，像这样的对`(2,1)`和`(1,2)`很微妙：粗心的实现可能会错误地假设对称性或错过 gcd 的作用。 案例中`a`等于`b`通常会简化整除条件，但不能假设始终有效。 

## 方法

 暴力解决方案会迭代所有可能的解决方案`a`在`[1,n]`和所有`b`在`[1,m]`，检查是否`b * gcd(a,b) % (a+b) == 0`。 虽然正确，但这种方法的复杂度为 O(n * m)，当 n 和 m 达到数百万时，这种方法很快就变得不可行。 

关键的见解来自于对 gcd 的因式分解。 让`g = gcd(a, b)`。 然后`a = g * x`和`b = g * y`在哪里`x`和`y`是互质的。 代入，条件变为`g * y * g % (g * x + g * y) == 0`或同等地`g * y % (x + y) == 0`。 现在问题只取决于`x`,`y`， 和`g`。 

我们可以将其重写为`(b / g)`可除以`(a + b)/g`这进一步简化为`y % (x + y) / g == 0`。 由此，您可以看到对于每个`a`, 候选人`b`值是以下的倍数`(a+b)/g`，它允许迭代可能的除数而不是所有`b`。 预先计算除数信息并利用整数运算将所有测试用例的复杂性从 O(n*m) 降低到大约 O(n log n)。 这种方法可以在给定的约束下轻松扩展。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 太慢了|
 | 最佳 | O(max(n, m) * log(max(n, m))) | O(max(n, m) * log(max(n, m))) | O(最大(n, m)) | 已接受 |

 ## 算法演练

 1. 预先计算最大整数的所有除数`n`或者`m`输入中遇到的。 每个除数列表都可以快速产生潜力`b`满足固定整除条件的值`a`。 
2. 迭代`a`从 1 到`n`。 对于每个`a`, 计算势`k`使用从 gcd 操作导出的公式得出的值：我们需要整数`b`这样`(a + b) / gcd(a, b)`划分`b`。 预先计算的除数使该枚举更加高效。 
3. 对于每位候选人`b`，检查是否`b <= m`。 如果是，则将其视为有效对。 
4. 将所有计数相加`a`以获得测试用例的答案。 
5. 对每个测试用例独立重复上述步骤。 

这是有效的，因为我们的除数预计算确保我们只考虑`b`可能满足的值`b * gcd(a, b) % (a+b) == 0`。 该算法永远不会错过有效的对，因为每个除数都只被考虑一次，无效的对会立即被过滤掉。`b <= m`查看。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX = 2 * 10**6 + 5

# Precompute divisors for all numbers up to MAX
divisors = [[] for _ in range(MAX)]
for i in range(1, MAX):
    for j in range(i, MAX, i):
        divisors[j].append(i)

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    ans = 0
    for a in range(1, n + 1):
        for d in divisors[a]:
            b = a * d // (d - 1)
            if b <= m and (a + b) % a == 0:
                ans += 1
    print(ans)
```该代码预先计算 200 万以内的所有除数，然后迭代`a`在`[1,n]`。 对于每个除数`d`的`a`，它计算候选人`b`使用导出公式得出的值。 支票`(a + b) % a == 0`确保整除条件成立。 

微妙的选择包括仔细使用整数除法并确保`b <= m`以避免计数超出允许范围的对。 通过启动可以避免差一错误`a`从 1.
