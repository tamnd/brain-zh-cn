 ## 解决方案
 ## 问题理解

 我们得到一个字符串$s$长度$n$，并且我们考虑它的所有后缀。 对于每个起始位置$k$，对应的子串是$s[k..n]$。 任务是独立分析每个后缀。 

对于固定后缀$T$，我们想要找到一个字符串$t$这既是前缀又是后缀$T$，严格短于$T$，其长度为奇数。 在所有这些候选者中，我们需要最大可能的长度。 如果不存在这样的字符串，我们输出$-1$。 

换句话说，对于每个后缀，我们正在搜索该后缀的最长边界，该边界的长度为奇数且不等于整个字符串。 

约束条件允许$n$最多$10^6$，它排除了任何在二次甚至接近二次的时间内独立地为每个后缀重新计算前缀函数或散列的方法。 甚至$O(n \sqrt{n})$已经不安全了。 任何正确的解决方案都必须跨后缀重用结构或在整个字符串上以线性时间计算边界信息。 

“奇数长度”约束产生了一个微妙的问题。 标准边界计算（如前缀函数或 Z 函数推理）给出所有边界，无论奇偶性如何。 如果我们按后缀重新计算，事后过滤是不够的，因为这已经太慢了。 

简单的实现可能会分别计算每个后缀的前缀函数。 如果不小心实现，那么在性能和正确性上都会失败：后缀上的前缀函数与完整字符串上的前缀函数不同，并且独立地重新计算它会忽略共享结构。 

另一个陷阱是假设整个字符串的最长边界可以通过简单的移位重新用于后缀。 边界依赖于绝对对齐，因此移动会改变匹配行为。 

## 方法

 蛮力的想法很简单：对于每个后缀$s[k..n]$，我们尝试所有可能的边界长度$n-k+1$降到1，检查该长度的前缀是否等于相同长度的后缀，以及长度是否为奇数。 每张支票都是$O(n)$在最坏的情况下，对所有后缀执行此操作会导致在最坏的情况下出现立方行为。 

即使我们使用散列优化比较，我们最终仍然会评估每个后缀的许多候选边界，从而导致大约$O(n^2)$哈希比较。 和$n = 10^6$，这是远远不可能的。 

关键的观察结果是后缀是嵌套的： suffix$k+1$是从后缀获得的$k$从前面删除一个字符。 这表明边界结构应该逐步发展。 我们动态维护边界信息，而不是从头开始重新计算。 

表示边界的标准方法是通过前缀函数（KMP 失败函数）。 然而，我们不需要每个后缀独立地使用它。 相反，我们为整个字符串计算一次前缀函数，然后重新解释它。 

关键的见解是后缀的任何边界都对应于原始字符串中的前缀函数链，但只有那些完全位于后缀内部的边界才是有效的。 因此，我们可以预先计算前缀函数$s$，然后为每个后缀维护一个指向该链的指针，在移动起始索引的同时调整它。 

为了有效地处理所有后缀，我们使用预先计算的故障链接并沿着前缀函数链跳跃来模拟移动开头的效果，同时保持最长的有效边界。 这将每个后缀的工作减少到摊销常数时间。 

最后，我们在遍历链时仅跟踪奇数长度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$到$O(n^3)$|$O(1)$| 太慢了 |
 | 最佳|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们依赖前缀函数数组$pi$， 在哪里$pi[i]$存储最长的适当前缀的长度$s[0..i]$这也是它的后缀。 

我们还构建了“下一个边界链”的解释：对于任何位置$i$，我们可以从$i$到$pi[i-1]$，重复枚举以结尾的前缀的所有边界$i$。 

我们从左到右处理后缀，为每个后缀维护在该后缀内有效的当前候选边界长度。 

1. 计算前缀函数数组$pi$对于整个字符串。 这为我们提供了前缀的所有边界关系$s$。 
2. 对于从位置开始的每个后缀$k$,初始化候选长度$cur$作为$n-k+1$，然后立即使用前缀函数链减少它，直到它是后缀的正确边界。 在实践中，我们从$pi[n-1]$并随着后缀的缩小而动态调整。 
3.从后缀移动时$k$到$k+1$，我们有效地删除了第一个字符。 任何比新后缀长度长的边框都是无效的，所以我们重复跳转$cur = pi[cur-1]$直到$cur \le n-k$。 
4. 确保有效性后，我们必须强制执行“奇数长度”约束。 尽管$cur > 0$和$cur$均匀后，我们继续沿着边界链跳跃。 
5.如果在这次减少之后$cur = 0$， 输出$-1$。 否则输出$cur$。 

其高效工作的原因是沿着前缀函数链的每次跳转都会严格减少候选边界长度。 在所有后缀中，每个值仅被访问固定次数的摊销，因此总工作量保持线性。 

### 为什么它有效

 字符串前缀的每个边界都可以通过重复的前缀函数链接到达。 当我们从一个后缀移动到下一个后缀时，我们只会使超出新长度的边界无效。 删除无效边界恰好对应于沿着前缀函数链向上移动，直到达到可行的长度。 

奇数长度过滤器不会破坏正确性，因为前缀函数链以严格降序枚举所有有效的边界长度。 跳过偶数长度并不会消除任何有效的奇数边界，因为任何较长的有效奇数边界都会出现在链中较短的偶数边界之前。 

该算法在处理后缀后保持了不变式$k$,$cur$是该后缀的最大有效奇数边框长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    pi = [0] * n
    for i in range(1, n):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j

    res = []
    cur = pi[-1]

    for k in range(n):
        limit = n - k

        while cur > limit:
            cur = pi[cur - 1]

        while cur > 0 and cur % 2 == 0:
            cur = pi[cur - 1]

        if cur == 0:
            res.append("-1")
        else:
            res.append(str(cur))

        if k < n - 1:
            nxt = pi[cur - 1] if cur > 0 else 0
            cur = nxt

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```前缀函数构建是标准 KMP 预处理，构建定义所有边界关系的故障链接。 变量`cur`跟踪当前后缀的最佳边框长度，我们增量更新它，而不是从头开始重新计算。 

关键的实现细节是减少的顺序：我们首先确保边界适合当前后缀，然后强制奇偶校验。 这避免了错误地丢弃仅由于边界移动而变得无效的有效候选者。 

过渡`cur = pi[cur - 1]`每一步之后都是基本的摊销技巧，确保我们永远不会从头开始扫描。

 ## 边缘情况

 对于没有重复结构的字符串，例如`abcde`，前缀函数数组全为零。 算法集`cur = 0`最初并且从未找到有效边界，因此每个后缀都会输出`-1`。 这符合这样的事实：除了完整字符串之外，任何地方都没有非空前缀等于后缀。 

对于像这样的高度周期性字符串`aaaaa`，前缀函数链变为`4 → 3 → 2 → 1 → 0`。 该算法从 4 开始，立即过滤偶数值，并正确输出每个后缀递减的奇数边界。 过渡步骤确保我们永远不会从头开始重新扫描，只会沿着链向下移动。 

对于长度为 2 的短字符串，唯一可能的边界长度为 1，并且仅在与长度为 2 的后缀进行比较时才有效。该算法可以正确处理此问题，因为前缀函数为相等字符给出 1，而奇偶校验过滤会保留它。
