 ## 解决方案

 ## 问题理解

 我们在整数网格上得到一组点，任务是决定是否可以使用最多两条无限直线覆盖所有这些点。 每个点必须至少位于其中一条线上，但两条线可以重叠甚至相同。 

思考这个问题的一个有用方法是，我们希望将点划分为最多两个共线组。 一组位于第一行，其余（如果有）必须位于第二行。 

输入大小最多可达100,000点。 任何尝试直接检查所有三元组或所有候选线对的解决方案都会太慢。 点上的三次或二次构造很快就变得不可行，因为即使$O(n^2)$在 Python 中已经处于临界状态，并且在最坏的情况下通常太慢。 

关键的困难是没有给出线路。 我们必须在不明确尝试所有可能性的情况下发现这样的一对是否存在。 

一些边缘案例揭示了天真的推理失败的原因：

 所有点都已共线的配置应立即返回 YES。 例如：```
3
0 0
1 1
2 2
```如果粗心的方法总是尝试构建两条不同的线，则如果假设线必须不同，则可能会错误地拒绝此操作。 

另一个棘手的情况是，必须仅在几个初始点中选择最佳第一行，但不一定是按输入顺序的前两个点：```
4
0 0
1 1
2 2
0 1
```这里正确的答案是“是”，使用穿过 (0,0)-(1,1)-(2,2) 的线和另一条垂直线 x = 0。如果前两个点定义“正确”线的贪婪假设可能会失败，如果这两个点与不代表全局结构的小子集共线。 

核心挑战是避免猜测任意线，同时仍然保证我们不会错过正确的线对。 

## 方法

 蛮力策略会尝试每一对点作为候选第一线。 对于每条这样的线，我们将收集其上的所有点，然后检查其余点是否共线。 这是有效的，因为任何有效的解决方案都必须包含定义第一条线的一对点。 

然而，这种方法检查$O(n^2)$候选线，对于每条线，我们可以扫描所有点，从而得到$O(n^3)$最坏情况下的行为。 和$n = 10^5$，这是完全不可行的。 

关键的观察是我们实际上不需要尝试所有对。 如果存在有效的解决方案，那么在选择不属于第二行的任意两个点之后，必须发生以下两种情况之一：要么它们已经位于正确的第一行，要么可以通过尝试涉及早期点的少量恒定数量的交换来纠正错误。 

这导致了建设性的贪婪归约：假设第一条线是由几个初始选择之一（具体来说，涉及前几个点）确定的，然后验证在删除已经拟合的点后是否可以使剩余的点共线。 

其作用的更深层次原因是几何刚性。 一旦两条线被固定，该结构就会迫使最早期的点至少位于其中一条上。 如果候选失败，则它一定会失败，因为前几个点之一位于并集结构之外，并且将该点交换到定义对中足以修复构造。 

这将搜索空间从二次候选减少到恒定候选。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有点对均作为第 1 行）| O(n3) | O(n) | 太慢了 |
 | 优化候选修复 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们依靠几何助手：使用叉积检查三个点是否共线。 

1. 首先假设第一条线由点 0 和 1 定义。 

如果所有点都位于这条线上，则答案立即为“是”。 这对应于一行就足够的情况。 
2. 否则，识别不在通过点 0 和 1 的直线上的点。将这些点称为“离线点”。 

如果最多有两个这样的点，我们总是可以将它们放在第二行，所以答案是肯定的。 
3. 如果至少有三个离线点，则第二条线（如果存在）必须经过其中任意两个点。 我们采用前两个离线点并尝试使用它们定义第二条线。 
4. 现在检查所有剩余的离线点是否都位于第二条线上。 如果是，请回答“是”。 
5. 如果此尝试失败，我们通过使用点 0 和 2 而不是 0 和 1 重新定义第一条线来重试，重复相同的过程。 
6. 如果所有尝试均失败，则返回 NO。 

我们只需要几次尝试的原因是，在任何有效的配置中，前三个点中至少有一个必须属于两条覆盖线中的每一条。 通过在前几个点中强制进行不同的选择，我们最终会与有效的分解（如果存在）保持一致。 

### 为什么它有效

 任何有效的解决方案都会将点分成两条线 L1 和 L2。 考虑前三点。 根据鸽巢原理，至少有两个位于同一条线上，即 L1。 如果我们选择这两个作为第一行的定义对，我们就可以正确识别 L1。 一旦 L1 固定，所有剩余点都必须位于 L2 上，并且算法会检测到这一点。 如果初始对不对应于 L1，则尝试前三个点之间的其他组合可以保证我们最终从同一条真实直线中选择两个点。 这确保了完整性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def collinear(a, b, c):
    return (b[0] - a[0]) * (c[1] - a[1]) == (b[1] - a[1]) * (c[0] - a[0])

def check(p0, p1, pts):
    bad = []
    for p in pts:
        if not collinear(p0, p1, p):
            bad.append(p)

    if len(bad) <= 2:
        return True

    p2 = bad[0]
    p3 = bad[1]

    for x in bad:
        if not collinear(p2, p3, x):
            return False
    return True

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    if n <= 4:
        print("YES")
        return

    candidates = [(0, 1), (0, 2), (1, 2)]

    for i, j in candidates:
        if check(pts[i], pts[j], pts):
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```该实现编码了仅需要测试三个候选基线的想法。 这`collinear`函数使用叉积来避免浮点精度问题，并且完全以整数运算工作。 

这`check`函数将点分为第一行上的点和第一行外的点。 如果离线集很小，那么它们很容易适合第二条线。 否则，它会尝试使用前两个违规点强制建立第二条线，并验证所有剩余的点。 

外循环尝试在前三个点中锚定第一条线的所有相关方法，这足以保证由于两条覆盖线上的鸽巢论证而导致的正确性。

 ## 边缘情况

 经典的故障模式是假设前两点始终定义正确的线。 例如：```
4
0 0
0 1
1 1
2 2
```如果我们选择 (0,0)-(0,1)，我们会将许多点分类为离线，并可能错误地得出不可能性的结论。 该算法通过重试前三个点中的替代对来解决此问题，确保最终选择来自真实底层线的一对。 

另一种微妙的情况是所有点都位于一条线上。 当第一次检查后离线集为空时，算法会立即检测到这一点，并返回 YES，而无需构造第二条线。 

当正好有两个点定义第二条线时，就会出现边界情况。 该实现明确允许`len(bad) <= 2`，因为任意两点始终定义一条有效线，从而防止在最小配置中出现不必要的拒绝。
