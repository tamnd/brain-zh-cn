 ## 解决方案

 ## 问题理解

 讲座持续几分钟，在每一分钟内讲师都会提出一定数量的定理。 如果米什卡在那一刻醒着，那些定理就会被记录下来； 如果他睡着了，他们就会迷路。 

不同的是，Mishka 有自己的睡眠模式，由二进制数组表示。 值为 1 表示他自然清醒并记录该分钟内的所有内容，而 0 表示他在睡觉且未记录任何内容。 您可以通过选择连续的长度块来干预一次`k`分钟并迫使米什卡在整个街区保持清醒，无论他的自然状态如何。 在那段时间里，他记录了所有定理，就像他醒着一样。 

目标是为这个强制唤醒片段选择尽可能最佳的起始位置，以使记录的定理总数最大化。 

输出是一个整数：在应用一次强制唤醒窗口后，Mishka 可以记录的最大定理总数。 

约束条件`n ≤ 100000`排除任何尝试每个可能的窗口并从头开始重新计算总和的解决方案。 一个幼稚的方法是 O(nk)，在最坏情况下大约 10^10 次操作会变得太慢。 这推动我们采用线性或近线性方法。 

当最佳片段与已经清醒的时间严重重叠时，就会出现一个微妙的问题。 如果不仔细分离基线和附加增益，则仅对强制段求和或仅对唤醒部分分别求和的简单实现可能会重复计算或错过贡献。 

例如，如果所有`t[i] = 1`，答案就是所有的总和`a[i]`，任何窗口选择都不应该改变任何东西。 如果一个幼稚的解决方案错误地再次添加窗口贡献而不减去重叠，则会过度计数。 

另一个边缘情况是当所有`t[i] = 0`。 那么答案就是长度的最大和子数组`k`，窗口处理中的任何错误都会直接表现为不正确的滑动行为。 

## 方法

 暴力解决方案会尝试强制唤醒段的每个可能的起始位置。 对于每个位置`i`，它重新计算总贡献：Mishka 自然记录的所有定理之和加上通过唤醒他获得的附加定理`[i, i+k-1]`。 

自然贡献是固定的并且可以计算一次。 困难在于有效计算每个窗口的增益。 在一个简单的版本中，对于我们扫描的每个窗口`k`元素，这导致 O(nk) 复杂度。 和`n = 10^5`，这变得太慢了。 

关键的观察结果是，基础贡献并不取决于强制窗口的放置位置。 改变的只是所选窗口内发生的事情。 窗内，任何时刻`t[i] = 0`变得新有用，贡献`a[i]`，同时分钟`t[i] = 1`不贡献任何额外的内容，因为它们已经计入基线中。 

这将问题转化为最大化派生数组上的滑动窗口总和，其中每个位置都有贡献`a[i]`仅当 Mishka 在那里睡着时才为 0，否则为 0。一旦进行此转换，任务就简化为查找任意长度子数组的最大和`k`，这可以通过 O(n) 的滑动窗口来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题分为 Mishka 已经获得的内容和我们可以额外解锁的内容。 

1. 计算 Mishka 已经醒来的所有分钟的定理基线总和，即所有索引`i`在哪里`t[i] = 1`。 无论我们选择什么窗口，这个值都不会改变。 
2. 从概念上构建“增益阵列”的想法，其中`gain[i] = a[i]`如果`t[i] = 0`， 否则`gain[i] = 0`。 这仅代表我们可以通过强制在分钟内醒来来解锁额外的定理`i`。 
3. 考虑任意长度的窗口`k`。 如果我们强迫米什卡在那里醒来，额外的好处恰好是`gain[i]`在那扇窗户里面。 这是有效的，因为他已经醒着的几分钟不会增加额外的价值。 
4. 计算第一个的总和`k`增益数组的元素。 这是初始窗口增益。 
5. 从左向右滑动窗口。 在每一步中，减去离开窗口的元素并添加进入窗口的新元素。 这会更新每个班次 O(1) 的增益。 
6. 跟踪在这个滑动过程中看到的最大窗口总和。 
7. 将此最大增益添加到基线总和中并输出结果。 

### 为什么它有效

 该算法依赖于这样一个事实：每个定理都只计算一次：无论是在基线（已经清醒的分钟）中还是在强制窗口的增益中。 增益变换仅隔离基线中缺失的那些贡献。 强制段的每个有效选择都与增益数组中的一个连续子数组和精确对应，因此最大化一个子数组会最大化另一个子数组。 除了转换之外不需要重叠调整，这保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))
t = list(map(int, input().split()))

base = 0
gain = [0] * n

for i in range(n):
    if t[i] == 1:
        base += a[i]
    else:
        gain[i] = a[i]

window = sum(gain[:k])
best = window

for i in range(k, n):
    window += gain[i] - gain[i - k]
    if window > best:
        best = window

print(base + best)
```该代码首先计算从已经清醒的分钟数中始终获得的贡献。 然后，它通过仅在 Mishka 睡觉的地方放置值来构造隐式增益数组。 初始窗口总和对应于在第一段上强制该技术。 滑动循环通过删除最左边的元素并添加下一个元素来有效地更新窗口，从而保持每个班次的 O(1) 更新。 最终答案在基线上添加了可实现的最佳额外增益。 

一个常见的实施陷阱是忘记强制窗口内的清醒分钟数不应重复计算。 通过分离基线和增益可以完全避免这种情况。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    t = list(map(int, input().split()))

    base = 0
    gain = [0] * n

    for i in range(n):
        if t[i] == 1:
            base += a[i]
        else:
            gain[i] = a[i]

    window = sum(gain[:k])
    best = window

    for i in range(k, n):
        window += gain[i] - gain[i - k]
        best = max(best, window)

    return str(base + best)

 ## 边缘情况

 当所有`t[i] = 1`，增益数组完全为零。 滑动窗口永远不会改善基线，因此算法正确返回`a`。 任何仍然增加窗口总和的错误实现都会使答案膨胀。 

当所有`t[i] = 0`，基线为零，答案简化为找到长度的最大和子数组`k`。 该算法直接通过增益窗口处理这个问题。 这里的错误通常来自于低效地重新计算每个窗口的总和或索引管理不善。 

什么时候`k = n`，窗口恰好覆盖整个数组一次。 增益成为所有增益的总和`a[i]`在哪里`t[i] = 0`，最终的答案成为所有元素的总和，正如预期的那样。 这会检查全范围边界的正确处理。
