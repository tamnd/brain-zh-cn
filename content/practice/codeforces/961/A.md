 ## 解决方案
 ## 问题理解

 我们正在模拟一个过程，其中方块一个接一个地到达并堆积成列。 有`n`列，每个传入的方块都会选择一列并落在已有的列的顶部，将该列的高度增加一倍。 

每当每列同时变为非空时，就会发生关键事件。 在那一刻，我们“清除”了一个完整的底层：每一列都损失了一个方格，而我们获得了一分。 移除后，所有剩余的堆栈实际上都会向下移动，但由于我们只关心高度，这相当于从每列的当前高度中减去一。 

因此，整个过程实际上是跟踪列高度，并计算所有列的最小高度至少达到 1 且所有列也不为零的次数。 

输入给出列数和接收方块的列序列。 输出是整行删除发生的次数。 

限制因素`n, m ≤ 1000`明确 O(mn) 模拟已经是安全的，但任何比这更糟糕的事情都是不必要的。 每次更新对所有列进行线性扫描仍然没问题，但结构表明我们可以通过维护增量状态来避免重复的全扫描。 

当一列较晚接收到其第一个方格时，会出现微妙的边缘情况。 在最后一个空列变为非空之前，无论其他列增长多大，都不会发生删除。 另一种边缘情况是当删除连续发生时：删除后，所有列都会减一，因此某些列可能会立即再次变空，从而阻止另一次删除，直到它们被重新填充。 

例如，如果`n = 2`序列是`[1, 2, 1, 2]`，两列在第 2 步都变为非空，并且我们删除了一个。 之后，高度重置为`[0, 0]`，接下来的两个插入再次同步，产生另一个删除。 忘记正确重置高度的幼稚方法会导致计算过多。 

## 方法

 直接模拟保留一个数组`h`尺寸的`n`，增加`h[c_i]`对于每个传入的方块，每次更新后都会检查所有条目是否至少为 1。如果是，则增加答案并从每个条目中减去 1。 

这是有效的，因为该过程实际上是根据全局检查和全局减量来定义的。 然而，昂贵的部分是重复对所有列进行全面扫描以检查是否有任何列为零，然后再进行一次全面扫描以递减所有值。 在最坏的情况下，这会变成 O(mn)，这在这里仍然可以接受，但在概念上是浪费的。 

关键的观察是我们不需要显式模拟高度。 当我们自最后一个删除点以来每列中积累了至少一个方块时，就会发生行删除。 每次移除后，每列都会减少一，这有效地将系统重置为仅跟踪“最后清除层之外的额外方块”。 这意味着我们只需要知道每一列在当前阶段是否至少收到了一个方块。 

我们维护一个布尔数组，指示自上次重置以来是否出现了列，以及当前“在此阶段填充”的列数的计数器。 每次在当前阶段中第一次填充列时，我们都会增加此计数器。 当它达到`n`，我们得分并重置所有标志和计数器。

 ## 算法演练

 我们跟踪当前周期中出现了哪些列以及当前填充了多少个不同的列。 

1.初始化一个数组`seen`尺寸的`n`所有值均为 false，并且有一个计数器`filled = 0`。 这表示自最后一行删除以来哪些列已接收至少一个方块。 
2. 迭代列中每个传入的方块`c`。 
3.如果`seen[c]`为 false，将其标记为 true 并递增`filled`。 此步骤仅计算当前周期中列的第一次出现，因为同一列中的其他方块无助于完成整行。 
4.如果`filled`变得等于`n`，我们已经达到了所有栏目的全覆盖。 这恰好对应于在当前状态下形成完整的底行。 
5. 发生这种情况时，将答案加一，重置`seen`全部为 false，并重置`filled`为零。 这模拟移除底层并将所有剩余的方块减一。 
6. 以同样的方式继续处理剩余的方块。 

它之所以起作用是基于过程的阶段分解。 每次我们清除一行时，所有列都会失去一个高度单位，这会从每一列中删除一个“保证层”。 该层之上剩余的内容与检测下一个整行完成无关； 唯一重要的是，自上次移除以来，每列是否至少收到了一个新方块。 因此，每个周期都是独立的，并且计算我们完成全套列的次数与删除的次数完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cols = list(map(int, input().split()))

    seen = [False] * n
    filled = 0
    ans = 0

    for c in cols:
        c -= 1
        if not seen[c]:
            seen[c] = True
            filled += 1

        if filled == n:
            ans += 1
            seen = [False] * n
            filled = 0

    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接反映了基于阶段的解释。 这`seen`数组跟踪每一列是否在当前周期中贡献了至少一个方块。 这`filled`计数器避免重复扫描数组以检查完整性。 

一个常见的实施陷阱是忘记重置两者`seen`和`filled`当形成一整行时。 如果只是`seen`已重置但是`filled`否则，算法将错误地继续计算完成情况。 

另一个微妙之处是减少列索引，因为输入列是从 1 开始的，而 Python 数组是从 0 开始的。

 ## 边缘情况

 最少的列数 (`n = 1`) 的行为有所不同，因为每个方块立即完成一整行。 该算法自然地处理这个问题：`filled`每次出现新列后都会变为 1，每次都会触发重置，因此答案等于`m`。 

一列在其他列出现之前收到许多方块的情况演示了相位行为。 用于输入`3 4: 1 1 1 2`，没有完成任何行，因为第 3 列从未被填充；`filled`永远不会达到 3，所以答案仍然为零。 

像这样的全周期边界情况`3 3: 1 2 3`在最后一步恰好完成一个周期，表明完成与第一次覆盖所有列有关，而不与更新频率有关。
