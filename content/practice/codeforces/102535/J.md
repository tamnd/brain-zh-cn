 ## 解决方案
 ## 问题理解

 任务是模拟非常大的电子填充过程，但只有最终填充的子壳层才重要。 具有原子序数的原子`a`正好有`a`电子。 电子被放入按值排序的子壳中`n + l`，并且关系可以通过较小的解决`n`。 带索引的子 shell`l`可以容纳`4l + 2`电子。 

对于每个查询，我们只需要接收电子的最后一个子 shell，而不是打印整个电子配置。 答案必须包含外壳号`n`、子壳层标签以及实际放置在那里的电子数量。 

的极限为`a`一样大`10^15`立即排除一一模拟电子的可能性。 即使为每个测试用例迭代所有填充的子 shell 也会太慢，因为跨域可能有数百万个相关位置`10^5`查询。 该解决方案需要在数学上跳过大量子 shell，并且仅检查对数数量的候选者。 

第一个棘手的情况是命令不是简单地增加炮弹数量。 例如，输入`19`产生`4s1`， 因为`4s`有较小的`n+l`比`3d`。 按顺序扫描 shell 的解决方案会给出错误的结果。 

另一个边缘情况是查询正好在子 shell 的边界处结束。 用于输入`2`，答案是`1s2`。 粗心的二分查找可能会错误地找到下一组而不是包含答案的第一组`2s`。 

最后一个微妙的情况是扩展子 shell 命名。 例如，最大的样本使用的标签长度​​超过一个字符。 一个解决方案假设`l`在单字母标签用完后，总是有一个字母会失败。 

## 方法

 直接方法将生成子壳层排序，从剩余电子数量中减去每个子壳层容量，并在剩余值适合当前子壳层时停止。 这是正确的，因为它完全遵循 Aufbau 顺序。 然而，对于`10^15`电子，子壳的数量太大，无法为每个查询单独生成。 

有用的观察是子壳自然地通过值形成对角线`k = n + l`。 每条对角线都可以整体跳过。 对于固定的`k`，所有可能的对满足`n + l = k`，并且该对角线上的电子总数可以用公式计算。 我们可以二分查找累计容量达到给定原子序数的第一个对角线。 

找到对角线后，里面的子壳数量大约只有一半。 我们没有遍历它们，而是使用另一种二分搜索，因为这些容量形成了算术级数。 这将整个问题简化为一些对数搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询的 O(子 shell 数量) | O(1) | O(1) | 太慢了|
 | 最佳 | 每个查询 O(log K) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 定义一个函数，返回所有子壳层中包含的电子总数`n + l <= K`。 

对于固定的子shell索引`l`，有效的 shell 满足`l + 1 <= n <= K - l`。 此类贝壳的数量为`K - 2l`，并且每个人都做出贡献`4l + 2`电子。 对这个算术表达式求和得到一个封闭公式，使我们能够跳过整个对角线。 
2.二分查找最小`K`使得总电子达到对角线`K`至少是给定的原子序数。 

前面的对角线已完全填满，因此减去它们的总数就剩下必须放置在对角线内的电子数量`K`。 
3. 找到对角线内的精确子壳`K`。 

在这条对角线上，壳的访问量不断增加`n`。 相应的`l`值减少。 它们的容量是一个算术序列，因此另一个二分查找找到第一个累积容量达到剩余电子数的子壳。 
4. 计算该子壳层中剩余的电子并将其转换为`l`值转换为所需的标签格式。 

之后的前 20 个子 shell 索引`s`和`p`有单字符标签。 之后，标签变成按字典顺序排列的字母组合。 

工作原理：该算法通过仅对原始序列的连续部分进行分组，从而保留与 Aufbau 规则相同的顺序。 第一个二分搜索确定包含答案的确切对角线，第二个二分搜索确定该对角线内的确切子 shell。 由于每个跳过的部分都是通过精确的容量公式计算的，因此任何电子位置都不能被跳过或计算两次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def prefix(k):
    if k <= 0:
        return 0
    m = (k - 1) // 2
    return 2 * k * (m + 1) * (m + 1) - (2 * m * (m + 1) * (4 * m + 5)) // 3

def inside_sum(largest_l, count):
    return count * (4 * largest_l + 2) - 2 * count * (count - 1)

def label(idx):
    if idx == 0:
        return "s"
    if idx == 1:
        return "p"

    singles = "dfghijklmnoqrtuvwxyz"
    idx -= 2

    if idx < len(singles):
        return singles[idx]

    idx -= len(singles)
    length = 2
    while True:
        block = 26 ** length
        if idx < block:
            chars = []
            for _ in range(length):
                chars.append(chr(ord('a') + idx % 26))
                idx //= 26
            return ''.join(reversed(chars))
        idx -= block
        length += 1

def solve_one(a):
    lo, hi = 1, 100000
    while lo < hi:
        mid = (lo + hi) // 2
        if prefix(mid) >= a:
            hi = mid
        else:
            lo = mid + 1

    k = lo
    rem = a - prefix(k - 1)

    start_n = k // 2 + 1
    max_l = k - start_n

    lo, hi = 0, max_l
    while lo < hi:
        mid = (lo + hi) // 2
        if inside_sum(max_l, mid + 1) >= rem:
            hi = mid
        else:
            lo = mid + 1

    skipped = lo
    l = max_l - skipped
    before = inside_sum(max_l, skipped)
    e = rem - before
    n = k - l

    return str(n) + label(l) + str(e)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_one(int(input())))
    print('\n'.join(ans))

main()
```这`prefix`功能是核心优化。 它计算完整的对角线而不是单个子壳。 变量`m`是最大可能的`l`对角线值`k`，该公式来自对该对角线上所有容量的求和。 

第二个帮手，`inside_sum`，给出第一个的容量`count`对角线内的子壳。 因为这些容量每次都会减少四倍，所以总和是一个算术级数。 

第一个二分搜索使用足够大的范围来容纳所有可能的输入。 需要的值`10^15`电子远小于`100000`，所以这个界限只是一个安全上限。 Python 整数避免了大型乘法期间的溢出。 

标签转换与数学分离。 这避免了将不寻常的命名规则与电子计数逻辑混合。

 ## 边缘情况

 对于原子序数`2`，算法发现`k = 1`因为第一条对角线已经包含足够的电子。 剩余计数为`2`，对角线中的第一个子壳有容量`2`，所以输出是`1s2`。 二分搜索不会移动到下一个对角线，因为它搜索第一个有效前缀。 

对于原子序数`19`，算法首先跳过之前的所有对角线`k = 5`。 在该对角线内，它按顺序比较容量`3d`,`4s`。 第一个子壳不能包含剩余的电子，所以答案变成`4s1`。 

对于非常大的值，例如`1000000000000000`，该算法永远不会构造完整的配置。 它仅评估完整对角线的公式并执行对数搜索，然后根据计算的子壳索引生成最终的多字母标签。 这处理扩展的命名规则，而无需对标签长度进行任何固定的上限假设。
