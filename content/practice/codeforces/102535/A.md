 ## 解决方案
 ## 问题理解

 我们有一小批五把钥匙和五把锁。 输入给出了佩里拥有的钥匙的号码和门上的锁的号码。 任务是确定该特定钥匙是否能够打开该特定锁。 如果密钥有效，我们将打印成功消息，否则将打印失败消息。 

钥匙和锁之间的关系是固定的。 钥匙 1 仅适用于锁 2，钥匙 2 适用于锁 1 和 3，钥匙 3 适用于锁 2 和 4，钥匙 4 适用于锁 3 和 5，钥匙 5 仅适用于锁 4。由于只有 5 个可能的钥匙和 5 个可能的锁，因此整个决策空间仅包含 25 种组合。 这些约束不需要任何高级数据结构或优化。 任何执行恒定工作量的解决方案都足够快。 

主要的边缘情况来自按键序列的末端以及假设附近的数字始终以相同的方向工作。 例如，输入```
1
4
```应该产生：```
CURSE YOU
```钥匙 1 只能打开锁 2，因此将钥匙视为可以打开一定距离内的所有锁会给出错误的结果。 

另一个边界情况是最后一个键：```
5
4
```正确的输出是：```
GOOD LUCK AGENT P
```密钥 5 只有一个有效的锁，该锁是 4。在检查相邻锁的同时尝试访问不存在的锁 6 的实现可能会失败。 

第三种情况是钥匙和锁的编号相同：```
3
3
```正确的输出是：```
CURSE YOU
```这些数字标识不同的对象。 钥匙号码与锁号码匹配并不意味着兼容性。 

## 方法

 一种简单的方法是存储每个密钥可能的锁，并检查给定的锁是否出现在该列表中。 这实际上是锁系统的直接模拟。 它是正确的，因为每个有效的钥匙锁对都根据确切的规则进行检查。 在这个问题中，最坏的情况仍然只需要检查一把钥匙的两个可能的锁，因此它最多执行几个操作。 

更一般的暴力解释是尝试每种可能的密钥和锁关系，直到找到给定的对。 有五把钥匙和五把锁，这意味着最多检查 25 对。 这在这里也很容易接受，但它忽略了这样一个事实：输入已经标识了我们唯一关心的对。 

关键的观察结果是锁系统是静态的。 答案不依赖于任何计算或搜索。 它仅取决于该对是否属于一小部分预定义的有效对。 表示这些对直接将问题转化为恒定时间的成员资格检查。 

蛮力方法之所以有效，是因为输入大小很小，但它并不能表达问题的实际结构。 通过观察有效关系是固定的，我们可以将解决方案简化为一次查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(25) | O(1) | O(1) | 已接受 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从输入中读取钥匙号码和锁号码。 这两个值完整地描述了我们需要评估的情况。 
2. 创建有效键锁对的表示。 该表示将每个钥匙映射到它可以打开的锁，与锁系统的规则相匹配。 
3. 检查给定的锁是否存在于给定的键可用的锁中。 查找成功意味着钥匙可以打开门。 
4. 打印`"GOOD LUCK AGENT P"`对于有效的对和`"CURSE YOU"`否则。 

为什么它有效：

 存储的映射恰好包含允许的每个键锁关系。 对于任何输入，算法都会检查与问题定义相同的条件：所提供的锁是否属于所提供的密钥打开的锁集合。 由于没有丢失有效对并且没有包含无效对，因此查找产生的答案始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    L = int(input())

    can_open = {
        1: {2},
        2: {1, 3},
        3: {2, 4},
        4: {3, 5},
        5: {4}
    }

    if L in can_open[k]:
        print("GOOD LUCK AGENT P")
    else:
        print("CURSE YOU")

if __name__ == "__main__":
    solve()
```字典存储了完整的锁系统。 每个钥匙号码都指向一组恰好包含它可以打开的锁号码的集合。 

成员资格检查使用给定的密钥来检索其可能的锁，然后检查输入锁是否在该集合内。 由于输入值保证在 1 到 5 之间，因此不需要额外的验证或边界处理。 

没有指数计算，因此不存在偏差一的风险。 该解决方案还避免了关于钥匙和锁编号之间关系的算术假设，这一点很重要，因为第一个和最后一个钥匙的行为与中间钥匙不同。

 ## 边缘情况

 对于第一个边界情况：```
1
4
```该算法检索集合`{2}`对于键 1。成员资格检查询问该集合中是否存在 4，这是错误的，因此它打印`CURSE YOU`。 这可以处理一把钥匙只有一个可能的锁的情况，并避免接受不相关的锁。 

对于最后一个键：```
5
4
```该算法检索`{4}`对于键 5。立即找到值 4，因此输出为`GOOD LUCK AGENT P`。 固定映射可防止任何超出可用键范围的尝试。 

对于匹配号码：```
3
3
```该算法检索`{2, 4}`对于键 3。由于 3 不存在，因此打印`CURSE YOU`。 这证实了该解决方案检查实际兼容性，而不是直接比较两个输入数字。
