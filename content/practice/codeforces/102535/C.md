 ## 解决方案
 ## 问题理解

 佩里拥有一组编号钥匙，每把钥匙只能打开紧邻其编号的锁。 这些锁形成一条从 1 到 1,000,000,000 的简单线。 对于出现在活动天数输入列表中的每一把锁，我们需要确定 Perry 的密钥集合中是否存在至少一个其相邻号码。 答案是可以打开的活动锁的数量。 

输入首先给出关键位置的集合。 第二个重要的集合是活跃期间出现的锁仓集合。 我们不需要处理所有可能的锁，因为可能有十亿个锁，只需处理输入中列出的特定锁即可。 

钥匙数量和查询锁数量都可以达到10万个。 在两秒的限制下，解决方案应保持接近线性时间。 检查每把钥匙和每把锁需要多达 10,000,000,000 次比较，这远远超出了实际情况。 O(k + L) 或 O((k + L) log k) 附近的解决方案是合适的。 

在几种极端情况下，实施很容易失败。 

位置 1 的锁只有一把可能的钥匙，即钥匙 2。将其视为钥匙 0 存在会给出错误的答案。 例如：```
1
0
1
1
```不是有效输入，因为键编号从 1 开始，但等效的有效情况是：```
1
3
1
1
```答案是 0，因为钥匙 3 无法打开锁 1。粗心的实现错误地检查边界周围的绝对差可能会产生错误的结果。 

中间的锁可以从任意一侧打开，并且有一个匹配的邻居就足够了。 例如：```
1
4
1
5
```答案是 1，因为钥匙 4 打开锁 5。要求两个相邻钥匙都存在的实现将错误地返回 0。 

钥匙不应与正在查询的锁混淆。 例如：```
1
10
1
10
```答案是 0，因为钥匙 10 不能打开锁 10。它只能打开锁 9。在这种情况下，对钥匙集中的锁进行直接成员资格检查将会失败。 

## 方法

 最简单的方法是检查每把锁并将其与每把钥匙进行比较。 对于每个查询的锁，我们将计算该锁与每个可用键之间的差异，如果差异恰好为 1，则对其进行计数。 这是正确的，因为解锁规则仅取决于该距离。 

然而，最坏的情况包含 100,000 个钥匙和 100,000 个锁。 蛮力方法执行大约 100 亿次比较。 即使操作速度非常快，如此大量的工作也无法在时限内完成。 

有用的观察是锁并不关心所有密钥。 它只关心两个可能的邻居：紧邻其之前的数字和紧邻其之后的数字。 我们可以将所有键存储在哈希集中，并直接询问其中一个邻居是否存在，而不是搜索整个键集合。 

暴力解决方案之所以有效，是因为它会检查钥匙和锁之间的所有可能关系，但它会重复大量不必要的工作。 每个锁只有两个候选者的观察结果将每个查询减少为两个恒定时间查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(kL) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(k + L) | O(k) | 已接受 |

 ## 算法演练

 1. 将每个键值存储在哈希集中。 使用集合是因为​​我们需要重复检查特定数字是否存在，而平均 O(1) 查找可以满足所需的速度。 
2. 一次读取每个活动锁。 我们不需要对锁进行排序或存储，因为每个锁都可以独立应答。 
3.对于当前的锁`x`，检查是否`x - 1`是否在键集中或者是否`x + 1`位于按键集中。 如果任一查找成功，则增加答案。 
4. 处理完所有锁后输出最终计数。 

为什么它有效：每一个可能的钥匙都可以打开锁`x`必须有一个比以下值小一或大一的数字`x`。 该算法仅检查这两种可能性，而不检查其他可能性。 如果其中之一存在，则对锁进行计数，如果都不存在，则不存在有效密钥。 由于每个查询的锁都是独立处理的，因此累计的计数正是成功的天数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    keys = set(map(int, input().split()))

    L = int(input())
    locks = list(map(int, input().split()))

    ans = 0

    for lock in locks:
        if lock - 1 in keys or lock + 1 in keys:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```首先构建密钥集，因为所有后续操作都是成员资格检查。 Python的set实现提供了平均恒定时间查找，这是核心优化。 

每个锁都会被处理一次。 该代码直接检查两个相邻的数字，而不是搜索所有键。 边界情况是自然处理的，因为查找不存在的数字只会返回 false。 例如，检查`lock - 1`什么时候`lock`为1测试0，不能出现在键集中。 

Python 整数在这里不会溢出，因为最大值仅为 1,000,000,000，这完全符合 Python 的整数表示形式。

 ## 边缘情况

 对于边界情况，请考虑：```
1
3
1
1
```密钥集仅包含 3。算法通过查看 0 和 2 来检查锁 1。两者都不存在，因此答案仍然是 0。它从不假设编号为 0 的密钥存在。 

对于单邻居情况：```
1
4
1
5
```该算法检查锁 5。在集合中找到左邻居 4，因此答案变为 1。它不需要右邻居存在。 

对于数量相等的情况：```
1
10
1
10
```该算法检查 9 和 11。这两个数字都不存在，因此答案为 0。锁号本身是无关紧要的，除非它也作为相邻钥匙出现，而这是不可能的。
