 ## 解决方案
 ## 问题理解

 每条加密消息都包含一个标记值。 对于每个标记，我们需要根据可分性确定三个代理中的哪一个应该接收它。 代理 003 接收标记可被 3 整除的消息，代理 005 接收可被 5 整除的标记，代理 007 接收可被 7 整除的标记。单个标记可能属于多个代理，因此输出可以按固定顺序包含多个代理名称。 处理每个标记后，输出必须包含分隔线。 

输入最多可包含 100000 个标记，每个标记最大可为 (10^{18})。 测试用例的数量是驱动算法选择的部分。 对每个标记尝试多次操作的解决方案将很快超出可用时间。 对于 (10^5) 种情况，预期的解决方案需要每个标记几乎持续不断的工作，这使得依赖于数字大小的方法变得不可能。 幸运的是，检查能否被三个固定小整数整除是一个常数时间操作。 

主要的边缘情况来自于多个条件可以同时成立的事实。 在找到第一个可整除的数字后停止的解决方案将错过有效的收件人。 例如：```
1
420
```正确的输出是：```
AGENT 003
AGENT 005
AGENT 007
---
```数字 420 可被所有三个值整除。 一个粗心的实现使用`if`,`elif`,`else`只会打印第一个匹配的代理。 

另一个边缘情况是一个与任何人都不匹配的标记：```
1
11
```正确的输出是：```
NONE
---
```假设每个标记都有至少一个接收者的程序可能不会打印任何内容或产生不完整的分隔符结构。 

最后一个案例是一个非常大的标记：```
1
1000000000000000000
```正确的输出是：```
AGENT 003
AGENT 005
AGENT 007
---
```该值远远超出了 32 位整数限制。 该算法必须处理大整数，Python 可以自然地处理这些整数。 

## 方法

 一种直接的方法是分别测试每种可能的接收条件。 对于每个标记，我们检查它是否能被3整除，是否能被5整除，是否能被7整除。这实际上是问题所需的完整逻辑，所以它是正确的。 每个测试用例的总工作量是 3 次模运算，为最大输入提供大约（3 × 10^5）次运算。 

如果有人试图通过搜索每个标记的约数来概括问题，那么成本会变得更大。 对于接近 (10^{18}) 的标记，检查所有可能的除数直至其平方根将需要对单个情况进行大约 (10^9) 次迭代，这是完全没有必要的。 唯一重要的除数是三个已知的收件人。 

关键的观察是，问题不在于要求我们发现除数。 可能的接收者是已知的。 我们只需要评估三个固定的整除性检查。 这将任务减少到每个标记的恒定时间算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力除数搜索 | 每个测试用例 O(sqrt(m)) | O(1) | O(1) | 太慢了|
 | 检查能被 3、5 和 7 整除 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例的数量并独立处理每个标记。 每个标记与其他标记没有交互，因此没有必要在案例之间保持状态。 
2. 为当前标记创建一个空的收件人列表。 我们存储名称而不是立即打印，以便明确控制最终顺序。 
3. 检查标记是否能被3整除。如果是，则追加`AGENT 003`。 该检查代表了第一个接收者的完整状况。 
4. 检查标记是否能被5整除。如果是，则追加`AGENT 005`。 
5. 检查标记是否能被7整除。如果是，则追加`AGENT 007`。 
6. 如果未添加收件人，请追加`NONE`。 否则，按照检查顺序打印所有收集的收件人。 
7. 在每个测试用例之后打印分隔线。 

为什么它有效：

 对于每个可能的收件人，该算法精确地执行定义该收件人是否应该接收消息的数学条件。 由于所有三项检查都是独立执行的，因此可以正确处理可被多个值整除的标记。 如果这三个条件都不成立，则收件人列表保持为空，这正是由下式表示的情况`NONE`。 最终的输出顺序是有保证的，因为检查总是按要求的顺序执行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        m = int(input())
        agents = []

        if m % 3 == 0:
            agents.append("AGENT 003")
        if m % 5 == 0:
            agents.append("AGENT 005")
        if m % 7 == 0:
            agents.append("AGENT 007")

        if not agents:
            ans.append("NONE")
        else:
            ans.extend(agents)

        ans.append("---")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```使用读取输入`sys.stdin.readline`因为可能有很多测试用例。 该解决方案将输出行存储在列表中并在末尾写入一次，从而避免重复打印开销。 

这`agents`为每个标记重建列表。 每个可分性测试都是独立的，因此分开`if`需要声明。 将它们替换为`elif`会引入一个错误，因为一个标记可以属于多个代理。 

Python 整数具有任意精度，因此高达 (10^{18}) 的值不需要特殊处理。 模运算直接作用于输入值，无需担心溢出。

 ## 边缘情况

 第一个边缘情况是重叠可分性。 对于输入：```
1
420
```该算法评估`420 % 3`,`420 % 5`， 和`420 % 7`。 所有三个结果均为零，因此列表变为：```
AGENT 003
AGENT 005
AGENT 007
```使用独立支票可以让所有收件人都出现。 

第二个边缘情况是没有接收者的标记：```
1
11
```三个模运算产生非零余数。 由于列表仍然为空，因此算法插入`NONE`在打印分隔符之前。 

第三个边缘情况是一个非常大的值：```
1
1000000000000000000
```该算法不会将数字转换为数字或执行重复除法。 它直接应用模检查，该检查在 Python 中保持恒定时间，并正确识别所有三个收件人号码的整除性。
