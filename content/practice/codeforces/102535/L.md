 ## 解决方案
 # 问题理解

 对手的线可以看作是一个二进制数组。 莫克是`1`因为它仍然需要战斗，而 MEEK 是`0`因为金免费通过它。 战斗开始前，我们可以正好交换两个位置`k`次。 我们的目标是合理安排队伍，使清除所有 MOOK 所需的分钟数尽可能短。 

战斗过程有一个隐藏的二进制计数器结构。 如果我们分配位置`i`价值`2^(i-1)`并将所有 MOOK 位置的值相加，一场战斗总是将这个总和减去 1。 第一个 MOOK 更改为`1`到`0`，并且之前的所有零都变成一，这正是二进制递减。 因此，最终的答案是交换后的二进制数组表示的数值。 

输入给出了线的长度、确切的掉期次数，以及每个仓位的当前状态。 输出是执行这些交换后的最小可能二进制值，模`10^9`。 

约束条件`n <= 100000`是主要的困难。 战斗过程的模拟可能需要长达`2^n`分钟，这是不可能的。 即使尝试所有可能的交换选择也远远超出了 2 秒的限制所允许的范围，因为可能的对的数量是二次方的，并且交换序列呈指数增长。 该解决方案必须仅检查线路固定次数，从而导致`O(n)`方法。 

有几种边缘情况会破坏更简单的解决方案。 如果没有 MOOK，则答案始终为零。 例如：```
2 5
MEEK
MEEK
```正确的输出是`0`。 总是试图移动 MOOK 的方法可能会错误地假设至少存在一场战斗。 

第二个陷阱是必须准确使用掉期的要求`k`次。 例如：```
2 1
MOOK
MEEK
```唯一的交换将状态更改为`MEEK, MOOK`，赋予价值`2`。 仅尝试达到完全优化排列的解决方案将错误地输出`1`。 

最后一个特殊情况是两个不同类型的对手。 没有可用于交换的相等元素作为无意义的额外操作。 例如：```
2 2
MEEK
MOOK
```两次交换后，数组返回到其初始状态，所以答案是`2`，不是排序后的值`1`。 

## 方法

 直接方法将模拟每一种可能的互换选择。 对于每个交换序列，我们可以计算生成的二进制值并保留最小的值。 这是正确的，因为它考虑了所有合法的最终安排。 然而，即使是一次交换`O(n^2)`选择，并重复此操作最多`n`交换提供了不可能的搜索空间。 

更好的起点是了解交换可以改进什么。 将所有 MOOK 放在行首即可获得具有相同 MOOK 数量的最小二进制值，因为较早的位置具有较小的 2 的幂。 例如，对于三个 MOOK，理想的形式是`111000...`。 

第一个块中包含 MEEK 的每个位置都是一个错误。 将其与右侧的 MOOK 交换就可以解决这样一个错误。 为了最大化改进，我们应该使用块外最左边的错误位置和最右边的 MOOK。 

剩下的难点就是“恰好”二字。 如果我们需要的交换次数少于错误数量，那么每次交换都应该是有用的。 如果我们有足够的交换来达到排序的安排，唯一的问题是剩余的交换是否可以被浪费。 在每种情况下，除了包含一个 MOOK 和一个 MEEK 的长度为 2 的行之外，可以在相等的对手之间进行额外的交换，或者通过撤消先前的交换来进行。 特殊情况可以单独处理，因为唯一可能的操作是重复交换两个位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将行转换为二进制数组，其中 MOOK 为`1`MEEK 是`0`。 统计MOOK的数量，调用它`m`。 最好的最终安排是有位置的`1`通过`m`。 
2.特殊情况处理`n = 2`正好有一个 MOOK 和一个 MEEK。 由于每次交换都会交换两个元素，因此只有奇偶校验`k`很重要。 偶数次交换恢复原始状态，奇数次交换两个位置。 
3. 找到第一个中所有不正确的零位置`m`位置和第一个之后的所有位置`m`职位。 在这些位置上，有用的掉期可以提高价值。 
4. 如果少于`k`存在错误，使用每个错误修复交换。 剩余的交换不需要改变最终的二进制值，因为它们可以被浪费而不影响排列。 
5.如果`k`小于错误数，准确执行`k`有用的交换。 将最小的错误位置与目标前缀之外的最大 MOOK 位置配对。 这给出了二进制值的最大减少。 
6. 通过相加计算得到的二进制值`2^i`对于每个剩余的 MOOK 位置。 答案取模`10^9`。 

为什么它有效：

 二进制值解释将战斗过程转化为简单的数字问题。 最小化战斗时间与最小化交换后的二进制值相同。 每个有用的交换都会移动一个`1`到较早的位置和`0`到稍后的位置。 将最早可用的零与最新可用的零配对会产生该交换的最大可能减少。 一旦所有可能的错误都被修复，该安排已经是最小可能的安排，并且任何剩余的交换都可以被抵消，除了单独处理的二元混合情况之外。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9

def solve_case(n, k, arr):
    ones = sum(arr)

    if ones == 0:
        return 0

    if n == 2 and ones == 1:
        if k % 2 == 1:
            return (2 if arr[0] == 1 else 1)
        return (1 if arr[0] == 1 else 2)

    bad = []
    extra = []

    for i in range(ones):
        if arr[i] == 0:
            bad.append(i)

    for i in range(ones, n):
        if arr[i] == 1:
            extra.append(i)

    use = min(k, len(bad))

    extra.sort(reverse=True)

    for i in range(use):
        a = bad[i]
        b = extra[i]
        arr[a], arr[b] = arr[b], arr[a]

    ans = 0
    power = 1
    for x in arr:
        if x == 1:
            ans += power
            if ans >= MOD:
                ans -= MOD
        power = (power * 2) % MOD

    return ans % MOD

def main():
    n, k = map(int, input().split())
    arr = []
    for _ in range(n):
        arr.append(1 if input().strip() == "MOOK" else 0)

    print(solve_case(n, k, arr))

if __name__ == "__main__":
    main()
```该代码首先计算 MOOK 的数量，因为这决定了目标前缀长度。 目标排列不单独存储，因为可以直接找到需要改变的位置。 

这`bad`数组存储应在最佳前缀中包含 MOOK 的 MEEK 位置。 这`extra`数组存储当前在该前缀之外的 MOOK。 交换这两个组首先执行最有价值的可能更改。 

在贪婪交换之前处理特殊的二元素情况。 这避免了假设额外交换总是可以被忽略的错误。 对于较大的数组，可以吸收额外的交换而不改变最终的二进制值。 

最后一个循环使用两个模数的幂来计算二进制数`10^9`。 Python 整数不会溢出，但在累加过程中取模可保持计算量较小并镜像所需的输出。

 ## 边缘情况

 处理全 MEEK 情况是因为 MOOK 的数量为零，因此二进制值为零，并且没有交换可以创建 MOOK。 

确切的交换条件由二元素混合情况处理。 为了：```
2 2
MEEK
MOOK
```第一次交换创建`MOOK, MEEK`，第二次交换返回到`MEEK, MOOK`。 该算法检测偶数个交换并返回原始值。 

对于只有一种有用的交换可用的示例：```
3 1
MEEK
MOOK
MEEK
```第一个位置位于目标 MOOK 前缀内，目前是错误的。 该算法将其与前缀之外的唯一 MOOK 交换，产生`MOOK, MEEK, MEEK`，其值为`1`。 

对于以下情况`k`大于错误数，一旦达到最优排列，算法就会停止进行价值变化的交换。 剩下的交换可以无害地进行，因为除了已经处理的二元混合线之外，至少存在一对相等的对手。
