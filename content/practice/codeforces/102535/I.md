 ## 解决方案
 ## 问题理解

 网格代表一个图，其顶点是允许骑士站立的单元格。 起始顶点是标记的单元格`K`，目标顶点是标记的单元格`F`，并标记被阻止的单元格`X`从图表中删除。 当合法的骑士跳跃连接两个单元时，两个顶点之间存在移动。 任务是确定目标是否可达，如果可达，则打印最短的骑士移动标签序列。 在所有最短的序列中，需要字典顺序最小的一个。 

网格最多可以包含一百万个单元，因为两个维度都可以达到 1000。最多有 10 个测试用例，输入总量仍然足够大，以至于访问每个单元的算法应该接近可接受工作的极限。 任何单独探索许多可能路径的方法都会失败，因为可能的骑士路径数量呈指数增长。 我们需要一种方法来处理每个单元格恒定的次数。 

答案还需要精确的最短路径，而不仅仅是可达性。 一个常见的错误是运行深度优先搜索并在第一次找到目标时停止。 DFS 不保证第一个发现的路径是最短的，并且它自然也不尊重字典顺序要求。 

有几个细节可能会导致错误的实现。 只包含开始的单单元格网格是不可能的，因为输入总是有一个单独的结束，但非常小的尺寸仍然很重要，因为许多骑士的动作离开了棋盘。 例如：```
1
2 3
KOO
OOF
```正确的输出是：```
Neigh
```假设每个正常的骑士移动都存在而不检查边界的粗心实现可能会访问无效位置或声称路径存在。 

另一种极端情况是可以通过多种方式到达终点。 例如：```
1
3 3
KOO
OOO
OOF
```该算法必须首先选择最短路线，然后选择该长度的路线中最小的字符串。 返回任何可达路径都会给出错误的答案。 

被阻挡的单元格仅影响着陆位置，而不影响中间的方块。 例如：```
1
2 3
KXF
OOO
```骑士可以直接跳到`F`如果移动到达那个方格。 治疗`X`细胞作为阻碍整个跳跃的障碍会错误地输出`Neigh`。 

## 方法

 暴力解决方案可以递归地尝试从以下位置开始的每个可能的骑士序列`K`。 它是正确的，因为每条合法路径最终都会被探索，因此当路径存在时，就准确地找到了目标。 问题在于路径的数量。 在一个大的开放网格中，每个位置最多可以分支出八个新动作。 搜索所有可能的序列直至答案长度可能需要探索指数数量的状态，这远远超出了两秒的限制所允许的范围。 

问题的结构给了我们更好的方向。 马的每一步移动都有相同的成本：答案字符串中的一次移动。 每当图中的每条边具有相等的权重时，就可以通过广度优先搜索找到最短路径。 BFS 探索一次移动可到达的所有位置，然后探索两次移动可到达的所有位置，依此类推。 第一次到达时`F`，距离最小。 

剩下的挑战是字典顺序。 如果邻居处理正确，BFS 已经保证了最短长度。 如果按字母顺序考虑八种可能的动作`A`到`H`，发现的第一条最短路径也是字典顺序上最小的路径。 这是可行的，因为 BFS 逐级处理路径，并且在一个级别内它保留了先前路径扩展的顺序。 

蛮力方法之所以有效，是因为它会检查每种可能性，但当可能性数量爆炸时就会失败。 观察到这是一个未加权的最短路径问题，我们可以用线性图遍历代替路径枚举。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(8^L)，其中 L 是路径长度 | O(L) | 太慢了|
 | 最佳 | O(RC) | O(RC) | 已接受 |

 ## 算法演练

 1. 存储网格并找到起始单元格和结束单元格。 每个非阻塞单元都是可能的图顶点，因此我们只需要记住坐标。 
2. 从起始单元运行 BFS。 队列中始终包含距离不减的单元`K`，这意味着第一次从队列中删除一个单元格时，我们找到了向该单元格移动的最短数量。 
3.按顺序尝试八个骑士动作`A`通过`H`。 对于每次移动，计算目标坐标，如果移动离开网格或落在某个位置，则忽略该移动`X`细胞。 按照这个顺序处理移动是赋予最终答案其字典属性的原因。 
4. 当找到未访问的有效单元格时，标记其前任单元格以及用于到达它的移动字符。 存储父项可以避免将整个字符串复制到每个队列条目中，这会浪费内存。 
5. 继续 BFS 直到`F`已达到或队列变空。 如果队列结束但未到达`F`，没有有效的路线。 
6.如果`F`已达到，通过向后跟踪父指针来重建答案`F`到`K`。 收集的字符是相反的，因为它们是从目的地向后存储到开头的。 

工作原理：BFS 在路径长度不断增加的层中探索图，因此第一条路径到达`F`具有尽可能少的移动次数。 在每一层中，动作按字母顺序展开。 由于较早的层已经按字典顺序排序，因此第一个发现的最短路径是所有最短路径中最小的字符串。 父指针只记录这条已经证明的最优路径，因此重建不能改变结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    moves = [
        (-2, -1, 'A'),
        (-2, 1, 'B'),
        (-1, -2, 'C'),
        (1, -2, 'D'),
        (2, -1, 'E'),
        (2, 1, 'F'),
        (-1, 2, 'G'),
        (1, 2, 'H')
    ]

    out = []

    for _ in range(t):
        r, c = map(int, input().split())
        grid = []
        start = finish = None

        for i in range(r):
            row = input().strip()
            grid.append(row)
            for j, ch in enumerate(row):
                if ch == 'K':
                    start = (i, j)
                elif ch == 'F':
                    finish = (i, j)

        parent = [[None] * c for _ in range(r)]
        move_used = [[''] * c for _ in range(r)]
        queue = [start]
        head = 0
        parent[start[0]][start[1]] = start

        while head < len(queue):
            x, y = queue[head]
            head += 1

            if (x, y) == finish:
                break

            for dx, dy, ch in moves:
                nx = x + dx
                ny = y + dy

                if nx < 0 or nx >= r or ny < 0 or ny >= c:
                    continue
                if grid[nx][ny] == 'X':
                    continue
                if parent[nx][ny] is not None:
                    continue

                parent[nx][ny] = (x, y)
                move_used[nx][ny] = ch
                queue.append((nx, ny))

        if parent[finish[0]][finish[1]] is None:
            out.append("Neigh")
            continue

        ans = []
        cur = finish
        while cur != start:
            x, y = cur
            ans.append(move_used[x][y])
            cur = parent[x][y]

        ans.reverse()
        out.append("Whinny")
        out.append(''.join(ans))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```这`moves`数组定义图的边。 它的顺序不是任意的：字符已经排序，因此 BFS 扩展会自动遵守所需的平局规则。 

这`parent`矩阵有两个目的。 一个非`None`value 表示该单元已经被访问过，防止重复工作，并且存储的坐标让我们可以在 BFS 完成后重建路线。 起始单元格指向自身，以便可以将其与未访问过的单元格区分开来。 

队列使用具有移动索引的数组，而不是重复删除第一个元素。 从 Python 列表的前面删除会移动所有剩余元素并使遍历变慢。 

边界检查在访问网格之前进行。 这可以防止当骑士跳跃离开棋盘时无效索引。 该代码仅拒绝骑士降落的单元格`X`; 跳跃过程中穿过的单元格是无关紧要的。

 | 步骤| 当前单元格 | 移动| 目的地 | 状态 |

 ## 边缘情况

 对于无法到达的小板：```
1
2 3
KOO
OOF
```BFS 开始于`(0,0)`。 它只插入有效的骑士跳跃可以到达的单元格。 由于每个可能的目的地要么在棋盘外，要么无法到达终点，因此终点单元永远不会收到父单元。 算法输出`Neigh`。 

对于字典顺序平局的情况：```
1
3 3
KOO
OOO
OOF
```可能存在几条最短路径。 因为移动列表是从`A`到`H`，为每个单元存储的第一条路径是到达该单元的所有最短路径中的最小路径。 重建遵循那些存储的选择并产生所需的最小字符串。 

对于障碍物解释情况：```
1
2 3
KXF
OOO
```搬迁自`K`到`F`跳过`X`细胞。 BFS 仅检查目标方格，发现`F`被允许，并记录该移动。 这证实了只有着陆细胞才重要。
