[CF 146B - 幸运面具](https://codeforces.com/problemset/problem/146/B)

 **评分：** 1300
 **标签：** 暴力破解、实施
 **求解时间：** 1m 30s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有两个整数。 第一个数字，`a`，是任意的。 第二个数字，`b`，保证是幸运的，意味着每一个数字`b`是`4`或者`7`。 

对于任何正整数，它的“掩码”是通过仅取数字来形成的`4`和`7`从左到右并将它们连接起来。 For example, the mask of`72174994`是`7744`因为这些是按顺序出现的幸运数字。 

任务是找到最小的整数`c`这样`c > a`和面具`c`等于`b`。 

限制很小。 两个数最多都是`100000`，因此即使对许多候选数进行直接模拟也是完全现实的。 两秒限制，数值约为`10^5`通常可以轻松地进行数百万次简单操作。 这意味着，如果每张支票都很便宜，那么即使一一核对数字也是可以接受的。 

棘手的部分不是性能，而是正确提取掩模。 

一个简单的错误是忘记忽略非幸运数字而不是停止该过程。 

例如：

 输入：```
1 47
```正确答案是：```
47
```粗心的解决方案可能会被拒绝`47`因为它在一些后来的候选者中的幸运数字之前或之后包含其他数字，但掩码仅取决于幸运数字的子序列。 

当数字本身是幸运的时候，就会发生另一种微妙的情况。 

输入：```
1 7
```正确答案是：```
7
```的面具`7`仍然是`7`。 首先删除所有数字并意外地将掩码视为空的有缺陷的实现将在此处失败。 

还有一个涉及根本没有幸运数字的数字的边界条件。 

输入：```
40 4
```正确答案是：```
44
```数量`41`有面具`4`，所以实际上最小的有效答案是：```
41
```仅检查完全幸运数字的粗心实现会错误地跳过许多有效答案。 

## 方法

 最直接的方法就是暴力破解。 开始于`a + 1`，计算每个数字的掩码，当掩码等于时停止`b`。 

要计算掩码，请从左到右扫描数字并仅保留`4`和`7`。 如果结果序列匹配`b`，我们找到了答案。 

这是可行的，因为约束很小。 即使我们检查数万或数十万个数字，每个掩码计算也只涉及几个数字。 一个数字最多`10^5`最多有六位数字，因此总工作量仍然很小。 

蛮力方法已经可以顺利通过了。 

关键的观察是搜索空间自然是有限的。 自从`b`它本身最多有六位数字，只有幸运数字才重要，我们不需要任何高级组合或动态规划。 最简单的模拟已经足够优化了。 

有些人尝试逐位构建答案，但这会造成不必要的复杂性。 直接测试掩码条件非常便宜，因此顺序搜索是最干净的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k·d) | O(d) | 已接受 |
 | 最佳 | O(k·d) | O(d) | 已接受 |

 这里，`k`是检查的整数的数量，`d`是每个整数的位数。 自从`d ≤ 6`，运行时间在搜索范围内实际上是线性的。 

## 算法演练

 1. 读取整数`a`和`b`。 
2. 转换`b`到字符串，因为掩码最容易作为字符串进行比较。 
3. 开始迭代`a + 1`向上。 
4. 对于每个候选数字，将其转换为字符串并构建其掩码。 

从左到右扫描每个数字。 每当数字为`4`或者`7`，将其附加到掩码上。 
5. 将构建的掩模与`b`。 

如果它们相等，则该候选值是最小的有效答案，因为我们正在按升序检查数字。 
6. 打印候选并终止。 

### 为什么它有效

 该算法检查每个大于的整数`a`按严格递增的顺序。 对于每个整数，它通过仅按顺序保留幸运数字来精确计算掩码的定义。 

掩码等于的第一个数字`b`必须是最小有效答案，因为不存在更小的未经检查的数字。 由于每个候选者都根据掩码定义进行了正确测试，因此算法不会错过答案或返回无效数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = input().split()
    a = int(a)

    x = a + 1

    while True:
        mask = []

        for ch in str(x):
            if ch == '4' or ch == '7':
                mask.append(ch)

        if ''.join(mask) == b:
            print(x)
            return

        x += 1

solve()
```解决方案直接遵循算法。 

输入被分成两个字符串，因为`b`作为文本进行比较是最自然的。 我们只转换`a`为整数，因为我们需要对其进行算术运算。 

循环开始于`a + 1`因为答案必须严格大于`a`。 

对于每个候选人编号`x`，我们逐个字符地扫描它的十进制表示形式。 每当我们遇到`4`或者`7`，我们将其附加到掩码列表中。 连接列表会产生精确的掩码字符串。 

使用字符串可以避免前导连接逻辑或整数算术的错误。 由于数字很小，因此这种方法既简单又完全有效。 

检查的顺序很重要。 我们按顺序测试候选人，因此第一个成功的候选人自动是最小的。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k·d) | 我们检查`k`候选数，每个最多有`d`数字|
 | 空间| O(d) | 掩码最多存储一个数字的所有数字 |

 这里，`d`最多为 6，因为所有数字都很小。 即使我们扫描了许多候选者，与时间限制相比，数字运算的总数仍然很小。 内存使用量可以忽略不计。

    input = sys.stdin.readline

    sys.stdin = io.StringIO(inp)

    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue()

 ## 边缘情况

 考虑输入：```
40 4
```该算法开始于`41`。 

为了`41`，从左到右扫描数字：

 -`4`运气好，所以添加到面膜中。 
-`1`被忽略。 

构建的掩码变为`"4"`，它立即与目标匹配。 算法打印`41`。 

这个案例证实了幸运数字之间的任意数字并不重要。 

现在考虑：```
1 7
```该算法按顺序检查数字：

 -`2`,`3`,`5`， 和`6`生产空口罩。 
-`4`生产口罩`"4"`。 
-`7`生产口罩`"7"`。 

第一场比赛是`7`，所以输出是正确的。 

这验证了单个幸运数字是否正确工作以及空掩码是否得到安全处理。 

最后，考虑：```
99999 4
```该算法将五位数继续为六位数。 

第一位戴口罩的候选人`"4"`是：```
100004
```它的数字恰好包含一位幸运数字，`4`，所以掩模是`"4"`。 

这证实了该实现可以正确处理数字长度扩展并且不依赖于固定宽度假设。
