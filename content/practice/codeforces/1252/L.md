 ## 解决方案
 ## 问题理解

 我们给出了一组城市，其中每个城市都提出了一条可能的道路。 城市$i$想要连接到特定的其他城市$A_i$，所以每个提案都是一条无向边$(i, A_i)$。 如果我们忽略关于工人的所有约束，这些提议的边已经形成一个连通图，因此至少有一种方式可以使用所有提议在任何两个城市之间旅行。 

每个提议的边都不能自由构建。 它只能使用列出的某些允许的材料来建造$B_i$。 另一方面，每个工人都非常专业：只有当材料与他们自己的材料完全匹配时，他们才能建造一条道路$C_j$，每个工人最多可以建造一条路。 工人也可能什么都不做。 

任务是将工作人员分配到一些建议的边缘，尊重材料兼容性和唯一性约束，以便由所选边缘形成的图在所有城市之间保持连接。 我们可以跳过边或让工人不使用，但最终选择的边必须连接所有城市。 

核心困难在于我们没有被要求最大化边缘或使用所有工人。 我们被迫选择边缘的子集，并以保留连接性的方式将工作人员分配给它们。 

这些约束强烈地塑造了解决方案。 和$N, K \le 2000$和总计$\sum M_i \le 10000$，我们处于一个政权中$O(NK)$或者$O(M \log N)$类型的解决方案是可以接受的，但任何接近城市立方体或重复流构建的方法都会太慢。 所有材质列表的稀疏总大小表明我们应该明确地处理边缘材质关系，而不是重复扫描大型数组。 

一个微妙的问题是连接必须仅使用选定的边缘来保持。 一种幼稚的方法可能会贪婪地将任何可用的工作人员分配到任何边缘，但这很容易断开图的连接。 另一种失败模式是从图中的一个区域选择太多边，而使另一个区域孤立，即使所有建议都连接在一起。 

隐藏的结构是由提案形成的图恰好具有$N$节点和$N$边，因为每个节点恰好提出一条边。 这意味着该结构是一个连接的伪森林，每个组件只有一个循环，但由于该图是整体连接的，因此它在整个结构推理上下文中恰好包含一个循环。 这很关键：我们只需要选择$N-1$边来保持连接性，如果我们可以使用工作器实现它，提案图的任何生成树就足够了。 

## 方法

 一个蛮力的想法是将每个提议的边视为候选边，并尝试选择形成生成树的子集，同时分配与每个边允许的材料相匹配的工作人员。 人们可以尝试大小边的所有子集$N-1$，检查是否形成生成树，然后验证worker是否可以匹配。 这立即变得不可行，因为边缘子集的数量是指数级的$N$，甚至检查分配的可行性也需要重复解决二分匹配问题。 

一种更结构化的方法是观察我们不需要提前选择生成树。 相反，我们可以考虑在构建生成树的同时分配工作人员。 我们决定包含的每条边都必须由兼容材料的可用工作人员支持，并且每个工作人员只能使用一次。 这成为边和工人之间的匹配问题，但附加的约束是所选边必须形成连接的结构。 

关键的见解是使用不相交集并集 (DSU) 处理边缘，同时保持连接性。 我们尝试在提案图上构建生成树，但仅激活我们可以为其分配工作人员的边。 对于每条边，我们需要知道是否存在尚未使用的工人，其材料在边的允许集中。 自总计$M_i$很小，我们可以按材料预先索引边缘，按材料预先索引工人。 

然后，我们贪婪地尝试连接组件：每当一条边连接两个不同的 DSU 组件并且有可用的工作线程时，我们就会使用它。 这让人想起 Kruskal 的算法，只不过没有权重，并且可行性取决于每种材料的工人可用性。 正确性依赖于任何生成树都足够的事实，因此我们只需要确保我们可以实现一个。 

微妙的一点是，物质限制可能会阻碍天真的贪婪选择。 正确的策略是以任何顺序处理边缘，但如果可能的话，始终尝试使用它们来合并组件，并仔细分配有效材料的未使用工作人员。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（子集+匹配）| 指数| O(NK) | 太慢了|
 | 最优（DSU + 贪婪分配）| O((N + M) log K) | O((N + M) log K) | O(N + K + M) | 已接受 |

 ## 算法演练

 我们通过在城市图上逐步构建生成树来构建解决方案，同时将工作人员分配到我们承诺的边缘。 

1. 初始化 DSU 结构，每个城市都有自己的组件。 这代表哪些城市已经通过选定的道路连接起来。 
2. 按材料对工人进行分组$C_j$，为每种材质存储多重集或队列。 这允许快速检索可以构建给定材料的未使用的工人。 
3. 对于每条边$i$，存储端点对$(i, A_i)$及其允许材料清单$B_i$。 我们还准备了“每种材料可用的工人”的邻接。 
4. 以任意顺序处理边，尝试使用每个边连接两个不同的 DSU 组件。 如果端点已经连接，我们会跳过它，因为它会创建一个循环并且对于连接来说是不必要的。 
5.为了边缘$(u, v)$，我们尝试在其中找到任何材料$B_i$仍然有一个未使用的工人。 如果不存在，我们就不能使用这条边，所以我们继续前进。 
6. 如果存在这样的材料，我们选择该材料的一名工人，分配该工人来构造边缘$(u, v)$，并将该工人标记为已使用。 
7. 我们将 DSU 组件联合起来$u$和$v$。 这反映出修建的道路现已连接这两个地区。 
8. 继续下去，直到所有城市都在一个连通分量中或所有边都已处理完毕。 

处理后，如果 DSU 没有显示单个连接组件，或者我们没有分配足够的边来连接所有节点，我们输出 -1。 否则，我们输出每个工人分配的边，未使用的工人产生“0 0”。 

它之所以有效，源于连通性的结构。 我们只添加连接两个先前断开的组件的边，因此永远不需要循环。 由于原始图是连通的，因此始终存在由提议边组成的生成树。 唯一的问题是我们是否可以将工作人员分配到这些边缘。 因为每条边只需要一个资源单位（有效材料的一个worker），并且我们在提交边时只消耗一个worker，所以该过程简化为在本地容量约束下选择可行的生成树。 贪婪的 DSU 结构确保我们永远不会浪费原本可以用于连接组件的边缘，因为跳过有用的边缘将迫使我们使用在工作人员可用性方面可能不太可行的较晚的边缘。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

def solve():
    N, K = map(int, input().split())
    edges = []
    for i in range(N):
        arr = list(map(int, input().split()))
        a = arr[0] - 1
        m = arr[1]
        B = arr[2:]
        edges.append((i, a, B))

    workers = list(map(int, input().split()))

    mat_to_workers = {}
    for idx, c in enumerate(workers):
        mat_to_workers.setdefault(c, []).append(idx)

    ans = [(-1, -1)] * K

    dsu = DSU(N)

    for u, v, B in edges:
        if dsu.find(u) == dsu.find(v):
            continue

        chosen_worker = -1
        chosen_mat = -1

        for c in B:
            if c in mat_to_workers and mat_to_workers[c]:
                chosen_worker = mat_to_workers[c].pop()
                chosen_mat = c
                break

        if chosen_worker == -1:
            continue

        dsu.union(u, v)
        ans[chosen_worker] = (u + 1, v + 1)

    root = dsu.find(0)
    if any(dsu.find(i) != root for i in range(N)):
        print(-1)
        return

    for u, v in ans:
        if u == -1:
            print("0 0")
        else:
            print(u, v)

if __name__ == "__main__":
    solve()
```DSU 用于确保我们只接受有助于连接的边缘。 工作池按材料索引，以便检查边缘的可行性减少到扫描其小的允许列表$B_i$。 每次我们接受一条边时，我们都会立即消耗一个工作线程并合并组件，以确保我们维护一个有效的部分森林。 

一个微妙的实现细节是，当我们接受边缘时，我们立即分配工作人员。 延迟分配将需要稍后回溯或匹配，这使正确性变得非常复杂。

 ## 边缘情况

 一种重要的边缘情况是图结构允许连接但材料分布阻挡了关键的桥接边缘。 在这种情况下，基于 DSU 的贪婪方法会按顺序尝试边缘，如果桥边缘出现较晚且其所需材料已被消耗，则会跳过该边缘，从而使组件断开连接。 这反映出这样一个事实：可行性并非纯粹是结构性的，而且还受到资源的限制。 

另一种情况是当许多边连接已经连接的组件时。 DSU 检查可确保忽略这些内容，从而防止在不必要的周期上浪费工作人员，否则会降低基本连接的可用性。
