 ## 解决方案

 ## 问题理解

 我们得到了代表旋律的原始整数序列。 我们不可以直接保留； 相反，我们必须构建一个相同长度的新序列，仅保留原始序列的“形状”：上升、保持相等或下降的每一步都必须精确地反映在新序列中。 最重要的是，新序列中的连续值不能变化得太快，它们的绝对差受给定常量的限制$K$，并且每个值必须保持在固定区间内$[L, R]$。 

任务不仅仅是找到任何有效的变换旋律，而是找到字典顺序上最小的旋律。 这意味着我们希望使最早的位置尽可能小，只有在受到约束时才增加后来的位置。 

输入尺寸$N \le 10^5$排除任何二次策略。 任何尝试所有可能的有效序列或在每个位置执行重复间隔传播的方法都会太慢。 我们需要一个线性或近线性的结构，其中每个位置被决定一次或几次。 

一个微妙的困难是约束不是以微不足道的方式局部化的。 方向约束向前传播信息，而有界差异约束将相邻元素紧密耦合。 像“总是选择最小的允许值”这样天真的贪婪选择可能会失败，因为太小的值可能会使未来的位置变得不可能。 

一种常见的失败案例是局部贪婪浸入：

 如果我们选择$B_i$非常小以最小化字典顺序，但是$A_{i} < A_{i+1}$力量$B_{i+1} > B_i$并且仍在之内$K$，由于范围限制，我们稍后可能会用完可行值。 

因此，真正的挑战是保持未来的可行性，同时仍然最小化当前值。 

## 方法

 暴力解释是尝试构建$B$从左到右，在每个位置尝试所有可能的值$[L, R]$，检查剩余的后缀是否仍然可以完成。 这将需要对于每个选择，将约束向前传播到所有剩余位置，从而有效地解决可行性问题$O(N)$每个位置的次数。 这导致$O(N^2)$或者更糟，这远远超出了限制$N = 10^5$。 

关键的观察是后缀约束的可行性可以使用区间传播来维持。 我们没有承诺单个值，而是为每个位置维护一系列可能的值，这些值仍然允许完成后缀。 当我们从右向左移动时，这个范围会缩小。 

然而，仅后缀可行性不足以实现词典编目最小化。 我们还需要构建实际的序列。 关键思想是将后向可行性范围与前向贪婪结构结合起来：在每个位置，选择仍然保持后缀可行的最小值。 

为了计算可行性，我们向后传播间隔。 让$S_i$是所有值的集合$B_i$可以采取这样的立场$i..N$保持有效。 对于职位$N$,$S_N = [L, R]$。 对于较早的位置，我们交叉三个约束：范围限制、斜率约束$A$，并且要求存在兼容值$S_{i+1}$距离内$K$。 

这将问题转化为具有移动区间的区间交集：

 取决于是否$A_i < A_{i+1}$,$=$， 或者$>$，我们强制执行严格递增、相等或严格递减行为，并结合有界步长。 

一旦向后计算这些间隔，我们就可以重建$B$从左到右，始终选择使下一个状态保持在其可行区间内的最小有效值。 

这避免了指数分支，同时保持了正确性。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(N) | 太慢了|
 | 区间DP+贪心重构 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们定义一个后向DP，其中每个位置存储一个区间$[L_i, R_i]$的有效值$B_i$。 

### 1.最后初始化

 我们将最后一个位置设置为$[L, R]$，因为范围内的任何值最初都是可能的。 

这是唯一没有前向限制的位置。 

### 2. 向后传播约束

 对于每个位置$i$从$N-1$下降到$1$，我们确定给定哪些值是可能的$S_{i+1}$。 

我们首先将关系翻译为$A$：

- 如果$A_i < A_{i+1}$， 然后$B_i < B_{i+1}$- 如果相等，则$B_i = B_{i+1}$- 如果更大，则$B_i > B_{i+1}$我们还要求$|B_i - B_{i+1}| \le K$， 意义$B_{i+1}$必须位于$[B_i-K, B_i+K]$。 

我们不是向前推理，而是反转关系：对于固定的$B_{i+1}$，我们得出允许的范围$B_i$。 

这会产生一个区间$B_i$取决于间隔$[L_{i+1}, R_{i+1}]$。 我们计算在方向约束和步长限制下可以转换到该区间的所有可能值，然后与$[L, R]$。 

### 3. 检查可行性

 如果在任何时候间隔变空，则不存在有效的旋律，我们输出 -1。 

### 4. 构造字典顺序最小的序列

 我们从位置 1 开始。在每一步，我们选择中的最小值$[L, R]$这样它就可以过渡到某个值$S_{i+1}$。 我们通过检查存储间隔内是否存在兼容的下一个值来确保可行性。 

这种贪婪的选择之所以有效，是因为后缀区间已经编码了所有可行性约束。 

### 为什么它有效

 核心不变量是后向传播后，$S_i$准确地代表了所有值$B_i$可以扩展到有效的后缀$B_{i+1..N}$。 因为该集合完全被表征为一个区间，所以它之外的任何值都被证明是不可能的，并且它内部的任何值都至少有一个有效的延续。 

因此，当我们在位置选择最小可行值时$i$，我们不会冒未来失败的风险，因为已经预先计算了所有后缀的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def intersect(a1, a2, b1, b2):
    return max(a1, b1), min(a2, b2)

def solve():
    N, L, R, K = map(int, input().split())
    A = list(map(int, input().split()))
    
    INF = 10**30
    
    lo = [0] * N
    hi = [0] * N
    
    lo[-1], hi[-1] = L, R
    
    for i in range(N - 2, -1, -1):
        low_next, high_next = lo[i + 1], hi[i + 1]

        if A[i] < A[i + 1]:
            # B[i] < B[i+1]
            # so B[i] in [L, R], and must have some b_{i+1} in next interval > b_i
            # feasible b_i must be < high_next
            lo_i = L
            hi_i = min(R, high_next - 1)

        elif A[i] > A[i + 1]:
            # B[i] > B[i+1]
            lo_i = max(L, low_next + 1)
            hi_i = R

        else:
            # equal
            lo_i = max(L, low_next)
            hi_i = min(R, high_next)

        if lo_i > hi_i:
            print(-1)
            return

        lo[i], hi[i] = lo_i, hi_i

    res = [0] * N
    res[0] = lo[0]

    for i in range(1, N):
        prev = res[i - 1]
        low_next, high_next = lo[i], hi[i]

        if A[i - 1] < A[i]:
            # must increase
            cand = max(low_next, prev + 1)
            if cand > high_next:
                print(-1)
                return
            res[i] = cand

        elif A[i - 1] > A[i]:
            # must decrease
            cand = min(high_next, prev - 1)
            if cand < low_next:
                print(-1)
                return
            res[i] = cand

        else:
            # equal
            if low_next <= prev <= high_next:
                res[i] = prev
            else:
                print(-1)
                return

        if abs(res[i] - res[i - 1]) > K:
            print(-1)
            return

    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先向后计算可行性区间。 每个位置存储仍然允许有效后缀的最小和最大可能值。 转换逻辑直接编码我们是否需要严格增加、减少或相等，同时尊重全局边界。 

第二阶段通过贪婪地选择与预先计算的间隔和方向约束一致的最小可行值来构造字典序最小的序列。 最终检查强制执行$|B_i - B_{i+1}| \le K$约束。 

一个常见的实施陷阱是忘记了可行性区间本身并不能强制执行$K$-全局差异约束。 必须在重建过程中进行检查，因为这里的区间传播仅保证存在，而不是所选贪婪路径的精确步长一致性。

 ## 边缘情况

 一个脆弱的情况是当后向间隔仍然很大但前向贪婪选择破坏了可行性时。 例如：

 输入：```
3 1 5 1
1 2 1
```向后间隔允许在位置 1 处进行多个选择，但选择 1 可能会阻止增加到有效中间值的能力。 重建步骤通过始终选择仍允许预先计算的间隔内的有效后继者的最小值来避免这种情况。 

另一个边缘情况是平等链。 如果有一段相等的长线段$A_i$存在，每一个$B_i$必须相同。 向后 DP 将所有间隔折叠到后缀范围的交集中，并且重建只是传播单个值，防止意外漂移。 

最后的边缘情况发生在以下情况：$K$很大但是$[L, R]$很紧。 尽管步骤限制很宽松，但范围限制本身就可以迫使早期持仓进入狭窄的区间。 向后计算可确保在做出任何贪婪决策之前应用此限制，从而防止后期失败。
