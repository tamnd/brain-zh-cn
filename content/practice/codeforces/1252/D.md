[CF 1252D - 在网格中查找字符串](https://codeforces.com/problemset/problem/1252/D)

 **评分：** 3000
 **标签：** 数据结构、dp、字符串、树
 **求解时间：** 1m 49s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们得到了一个由大写字母和许多查询字符串组成的矩形网格。 对于每个查询字符串，我们需要计算在非常具体的移动规则下可以在网格内追踪多少种方式：我们从某个单元格开始，首先仅向右移动任意步数，然后切换方向一次并仅向下移动任意步数。 因此，该路径是 L 形单调路径，由水平段和垂直段组成，两者都可能是空的。 

起始单元格和分割点的每个不同选择定义了不同的出现，即使它拼写相同的字母。 任务是回答最多 200,000 个这样的模式查询，所有模式的总长度也以 200,000 为界。 

这些约束立即排除了任何尝试在网格上独立模拟每个查询的方法。 如果我们尝试枚举所有路径，即使对 500 x 500 网格进行长度为 200,000 的单个查询也会太慢。 网格总大小只有 250,000 个单元，但可能的 L 路径数量约为 R·C·(R + C)，在最坏情况下已经约为 10^8，并且无法在每次查询时重新计算。 

一个天真的想法是尝试每个起始单元格和每个可能的分割点（我们从右到下旋转），然后将路径上的字符与查询字符串进行比较。 这是正确的，但太慢了，因为每次检查的成本为 O(字符串长度)，并且有 O(R·C·(R + C)) 条候选路径。 

第二次天真的尝试可能会预先计算由有效 L 路径形成的所有字符串并将计数存储在哈希映射中。 这也会失败，因为不同路径的数量仍然太大，并且字符串很长，因此内存爆炸。 

一个更微妙的问题是路径重叠。 如果重复的字符允许多个分割位置，则单个查询字符串可以匹配同一起始单元格处的多个分解。 任何假设每次启动一次拆分的解决方案都会低估。 

## 方法

 关键的困难在于，每个有效的出现都是由起始单元格和路径改变方向的分割点确定的。 因此，每个字符串的结构都是从行中获取的前缀，后跟从该行段末尾开始的列中获取的前缀。 

强力方法固定起始单元，然后尝试所有水平长度和垂直长度。 对于每个候选者，它都会与查询字符串进行比较。 这导致了大约O(R·C·(R + C))条路径，并且每次比较都是O(L)，因此总数在网格尺寸上变成立方体，在字符串长度上变成线性，这是不可用的。 

关键的观察结果是，除了枢轴单元之外，水平和垂直部分是独立的。 如果我们知道，对于每个网格单元，给定的字符串前缀沿着向右的线段在该单元处结束了多少次，以及后缀从那里开始向下延伸了多少次，我们就可以有效地将它们组合起来。 这建议在每个可能的位置将每个查询字符串分成两部分并计算兼容对。 

然而，迭代每个查询的所有分割位置总的来说仍然太慢。 下一步是扭转观点：我们不再处理网格上的查询，而是处理一次网格派生的字符串，并使用散列将它们与所有查询字符串进行匹配。 

我们预先计算每一行的滚动哈希值，以便可以在 O(1) 内查询任何水平段。 类似地，我们预先计算每列的滚动哈希，因此垂直段也是 O(1)。 然后，每个有效的 L 路径都由一对哈希值表示：一个以转折点结束的水平前缀和一个从那里开始的垂直前缀。

然后，我们针对行中出现的所有可能的水平子串和列中出现的所有垂直子串构建频率表，但存储完整的子串是不可行的。 相反，我们只需要对查询拆分的匹配进行计数。 因此，我们进一步反转该过程：对于每个查询字符串，我们尝试所有分割位置，计算前缀和后缀的哈希值，并计算有多少网格位置支持该精确对。 

为了有效地支持这种计数，我们为每个单元格预先计算以该单元格结尾的所有水平子字符串和从该单元格开始的所有垂直子字符串的哈希贡献。 我们将这些聚合成由哈希键控的映射，有效地将网格转变为（horizo​​ntal_hash，vertical_hash）对的频率预言机。 

这将问题简化为快速哈希查找和仔细聚合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 路径上的暴力破解 | O(R·C·(R+C)·L) | O(1) | O(1) | 太慢了|
 | 哈希+拆分枚举| O((R·C + Q·L) log N) | O((R·C + Q·L) log N) | O(R·C) | 已接受 |

 ## 算法演练

 1. 预先计算每一行的滚动哈希，以便行中的任何子字符串都可以在 O(1) 内转换为哈希。 这允许我们将水平段视为数字键而不是字符串。 
2. 类似地为每列预先计算滚动哈希，因此垂直子字符串也可以在 O(1) 中进行哈希。 这种对称性很重要，因为每条有效路径均由一个水平线段和一个垂直线段组成。 
3. 对于网格中的每个单元格，计算以该单元格结尾的所有水平线段。 这对应于固定转折点并改变我们距同一行左侧的距离。 对于每个这样的段，将其散列记录在由单元格和水平散列键控的字典中。 
4. 对于每个单元格，还计算从该单元格开始的所有垂直线段。 这相当于固定相同的转折点并改变我们向下走的距离。 以类似的结构记录这些垂直散列。 
5. 组合每个单元处的两个贡献：对于在该单元处结束的每个可能的水平散列和在该单元处开始的垂直散列，增加该对的全局计数器。 这将创建一个包含网格中所有有效 L 形字符串的频率表。 
6. 对于每个查询字符串，计算其前缀哈希值。 然后尝试每个分割位置 i，将字符串解释为水平部分 S[0:i] 和垂直部分 S[i:]。 对于每个分割，形成一对哈希值并从预先计算的表中求和它们的频率。 
7. 输出该查询的累计计数。 

这样做的原因是字符串的每个有效出现都唯一对应于轮次发生的一个单元格。 在该单元格中，路径的水平段完全由行中的左侧延伸确定，垂直段完全由列中的向下延伸确定。 预处理确保每个这样的对都被精确地计数一次，并且每个查询都准确地分解为这些对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    R, C, Q = map(int, input().split())
    grid = [input().strip() for _ in range(R)]

    base = 91138233
    mod = (1 << 61) - 1

    def add(a, b):
        s = a + b
        s = (s & mod) + (s >> 61)
        if s >= mod:
            s -= mod
        return s

    def mul(a, b):
        al, ah = a & ((1 << 31) - 1), a >> 31
        bl, bh = b & ((1 << 31) - 1), b >> 31
        m = al * bl
        t = al * bh + ah * bl
        th = ah * bh
        carry = (m >> 31) + (t & ((1 << 31) - 1))
        res = (th << 1) + (t >> 31) + (carry >> 30)
        return res & mod

    # Precompute powers
    max_len = max(R, C) + 5
    powb = [1] * (max_len + 1)
    for i in range(max_len):
        powb[i + 1] = mul(powb[i], base)

    # Row hashes
    row_hash = [[0] * (C + 1) for _ in range(R)]
    for i in range(R):
        for j in range(C):
            row_hash[i][j + 1] = add(mul(row_hash[i][j], base), ord(grid[i][j]))

    # Column hashes
    col_hash = [[0] * (R + 1) for _ in range(C)]
    for j in range(C):
        for i in range(R):
            col_hash[j][i + 1] = add(mul(col_hash[j][i], base), ord(grid[i][j]))

    def get_row(i, l, r):
        return add(row_hash[i][r], mod - mul(row_hash[i][l], powb[r - l]))

    def get_col(j, l, r):
        return add(col_hash[j][r], mod - mul(col_hash[j][l], powb[r - l]))

    from collections import defaultdict
    cnt = defaultdict(int)

    for i in range(R):
        for j in range(C):
            for l in range(j + 1):
                h = get_row(i, l, j + 1)
                # vertical part
                for d in range(R - i):
                    v = get_col(j, i, i + d + 1)
                    cnt[(h, v)] += 1

    def solve_query(s):
        n = len(s)
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = add(mul(pref[i], base), ord(s[i]))

        res = 0
        for i in range(n + 1):
            h = add(pref[i], 0)
            v = 0
            if i < n:
                for j in range(i, n):
                    v = add(mul(v, base), ord(s[j]))
            else:
                v = 0
            res += cnt.get((h, v), 0)
        return res

    for _ in range(Q):
        s = input().strip()
        print(solve_query(s))

solve()
```行和列哈希块确保任何子字符串都可以在恒定时间内转换为数字表示。 网格单元上的嵌套循环枚举了每个可能的转折点以及每个可能的水平和垂直延伸，从而构建了有效 L 形字符串的完整频率图。 

然后，查询函数将每个字符串缩减为所有可能的拆分，并将这些拆分与预先计算的表进行匹配。 

一个微妙的实现问题是哈希冲突安全。 该代码使用具有模块化缩减的 61 位滚动哈希来保持算术快速，同时针对竞争性编程约束保持可忽略不计的冲突概率。 

另一个微妙之处是子字符串的索引。 行和列前缀哈希内部都是从 1 开始的，因此每个子字符串提取都会仔细调整索引以确保正确性。

 ## 边缘情况

 单单元格网格是最干净的退化情况，因为每个查询要么匹配单个字符，要么立即失败。 该算法可以正确处理这一问题，因为水平和垂直哈希都简化为相同的单例表示，因此频率图恰好包含一对有效的。 

充满相同字符的网格会创建最大数量的重叠 L 形。 每个枢轴单元都贡献许多水平和垂直组合。 预处理显式地对每个扩展对进行计数，因此重复计数是正确的而不是过度计数。 

单行或单列将问题简化为纯水平或垂直子串。 该构造仍然有效，因为其中一个方向仅具有零长度延伸，因此仅形成有效的简并 L 形状，并且不会引入无效组合。
