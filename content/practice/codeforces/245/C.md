 ## 解决方案
 ## 问题理解

 我们得到一排编号的箱子，每个箱子都装有一定数量的硬币。 在每次移动中，玩家选择一个整数位置$x$，并且该移动同时影响三个特定的箱子：$x$,$2x$， 和$2x+1$。 从每个箱子中取出一枚硬币（如果存在）。 

当每个箱子变空时游戏结束。 两名玩家交替行动，从波利卡普斯开始，只有在他们希望游戏尽快结束的意义上，两人才能达到最佳状态。 问题不在于谁获胜，而在于假设双方合作完成游戏，需要多少步才能清空所有硬币。 

关键的结构是每一步都针对一个小的“树状”指数模式。 每一个选择$x$在二进制堆索引方案中定义根及其两个子项。 

输入尺寸较小，$n \le 100$和$a_i \le 1000$。 这立即表明，只要我们避免硬币数量呈指数级增长，任何涉及每个节点模拟、重复贪婪调整甚至子集上基于状态的动态编程的解决方案都是可行的。 

当不存在有效的移动时，就会出现第一个微妙的边缘情况。 如果没有$x$这样$2x+1 \le n$，则根本无法进行任何操作。 如果至少有一个箱子包含这种配置的硬币，则游戏永远无法完成。 例如，当$n=1$和$a_1>0$, 没有有效的$x$，所以答案是$-1$。 

第二个微妙之处是动作严重重叠。 箱子里的硬币可以通过多种不同的选择来取出$x$。 例如，箱子 4 受到以下影响$x=2$（自从$2x=4$）但也与结构中的其他动作间接相关。 这种重叠意味着天真的“从叶子向上贪婪地处理”方法可能会错误计算最小移动次数，因为它们忽略了操作之间的全局耦合。 

## 方法

 思考这个问题的一种强力方法是模拟每一个可能的动作序列。 每一步选择一个有效的$x$，每个状态都是硬币计数的数组。 我们递归地尝试所有选择，直到所有硬币都为零，采用最小深度。 这是正确的，因为它探索了所有序列，但它是完全不可行的：即使$n=100$，分支因子大致为$n/2$，深度可达$\max a_i$，因此状态空间呈指数爆炸。 

关键的观察是，每次移动在如何减少硬币方面都是独立的：$x$无论当前值如何，始终从三个位置中的每一个位置减去一枚硬币。 这意味着问题不在于命令移除硬币，而在于选择每次移除硬币的次数$x$被使用。 

让$t_x$是我们选择位置的次数$x$。 然后每个宝箱$i$损失的硬币等于所有硬币的总和$t_x$这样$i \in \{x, 2x, 2x+1\}$。 问题变成：选择非负整数$t_x$最小化$\sum t_x$，需满足所有胸部要求。 

这将问题转化为二叉索引树上的覆盖问题。 每个操作最多覆盖三个节点，我们希望使用最少的总操作来满足所有所需的“硬币需求”。 

因为$n$很小，我们可以以相反的顺序处理节点，从$n$下降到 1，将所需的使用量向上推：如果一个节点仍然需要硬币，我们就被迫应用包含它的操作。 这导致了对有效父母的贪婪的需求传播。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 树结构上的贪婪传播 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们处理节点$n$下降到$1$，维护每个节点必须作为“强制运营中心”的次数。 

1.初始化一个数组$need[i]$和$a_i$。 这代表必须在每个箱子中取出的剩余硬币。 
2. 迭代$i$从$n$下降到$1$。 我们对待$i$作为潜在的操作根。 
3.如果$i > 0$，我们决定应用操作的次数$i$。 每个应用程序都会从​​中删除一枚硬币$i$,$2i$， 和$2i+1$。 满足胸部$i$，我们必须至少应用该操作$need[i]$次。 
4.让$t = need[i]$。 添加$t$答案是因为我们致力于使用操作$i$那么多次。 
5. 减少$need[i]$经过$t$，使其为零。 
6. 通过增加向上传播效果$need[2i]$和$need[2i+1]$经过$t$，因为这些仓位在操作时也会损失金币$i$被使用。 我们必须确保不超出界限。 
7. 继续，直到处理完所有节点。 

完成后，如果有的话$need[i]$对于无法被任何有效操作覆盖的节点保持非零（特别是如果无法通过任何父节点到达该节点），我们返回$-1$。 

关键是，从大索引到小索引的处理可确保当我们决定使用某个操作多少次时，对高索引约束的所有贡献都已考虑在内。 

### 为什么它有效

 该算法在每个索引处保持不变$i$，节点的所有硬币需求大于$i$已经得到了最佳的满足。 加工时$i$，唯一剩下的减少方法$need[i]$就是使用操作$i$，因为没有更小的索引操作可以在不违反先前满足的约束的情况下以降低总成本的方式影响它。 这会在每个步骤中创建本地强制决策，并且由于所有依赖项都以二进制堆结构从父级流向子级，因此以反向拓扑顺序进行处理可以防止未来发生冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a = [0] + a  # 1-indexed

    need = a[:]
    ans = 0

    for i in range(n, 0, -1):
        if need[i] <= 0:
            continue

        t = need[i]
        ans += t
        need[i] -= t

        if i * 2 <= n:
            need[i * 2] += t
        if i * 2 + 1 <= n:
            need[i * 2 + 1] += t

    for i in range(1, n + 1):
        if need[i] > 0:
            print(-1)
            return

    print(ans)

if __name__ == "__main__":
    solve()
```该代码遵循以相反的索引顺序将需求向下推的想法。 该数组的索引为 1，以匹配转换的堆状结构$i \rightarrow 2i, 2i+1$。 每个节点的赤字直接触发该节点的许多操作，并将影响传播到子节点。 

一个微妙的点是我们只“修复”一个节点一次，因为在处理它之后，后面的步骤不会重新访问它。 这避免了重复计算并确保约束的线性传播。

 ## 边缘情况

 最微妙的情况是当$n = 1$。 没有有效的$x$因为条件$2x+1 \le n$所有积极的失败$x$。 如果$a_1 > 0$，不存在任何移动，答案一定是$-1$。 该算法正确地处理了这个问题，因为循环从不应用任何操作，留下$need[1]$非零，触发失败。 

当所有硬币都集中在叶子附近时，会出现另一种边缘情况，例如$a_n > 0$。 由于没有操作可以定位$n$除非它显示为$2x$或者$2x+1$，可行性完全取决于父母链是否存在。 逆向处理确保如果叶子需要减少，则其需求被向上推，并且如果没有有效的祖先可以吸收它，则检测到不可行性。 

第三种情况是需求通过传播而抵消。 即使中间节点暂时变为负数或过于正数，最终的验证步骤也可确保整个结构的一致性，从而防止隐藏的过度计数产生错误的答案。
