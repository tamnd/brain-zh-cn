 ## 解决方案
 ## 方法

 暴力方法来自于直接解释书面规则：对于每个守卫，我们检查其他每个守卫并计算他们如何交互，累积他们对最终答案的贡献。 这很容易实现和纠正，因为它准确地反映了定义。 然而，如果有 n 个守卫，每个守卫都需要 O(n) 次比较，则总工作量为 O(n²)。 对于 2·10⁵ 左右的 n，这相当于 4·10^10 次运算，这远远超出了任何实际限制。 

这种改进来自于认识到相互作用不是独立的成对事件，而是对共享结构的重复贡献。 我们没有单独处理每一对，而是重新组织计算，以便每个守卫只对全局状态做出一次贡献。 这通常意味着用“更新已经编码所有先前效果的共享结构”来替换“与所有其他效果进行比较”。 

核心观点是，最终值取决于聚合属性，例如计数、前缀关系或不变保持转换，而不是显式的成对关系。 一旦我们以这种形式表达问题，我们就可以一次性处理整个配置，或者使用简单的数据结构（例如前缀和或频率图）。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 太慢了 |
 | 最佳| O(n) 或 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 最优方法重构了问题，这样我们就不会显式地逐对比较元素。 

1. 我们首先读取整个配置并将每个保护位置转换为允许聚合的结构化表示。 这通常是标准化步骤，例如映射坐标或对相同位置进行分组。 目的是使重复的贡献易于组合。 
2. 我们在相关维度上构建频率结构，例如位置、行、列或从它们派生的值。 这个结构告诉我们有多少守卫为每个局部区域做出贡献，而无需重复扫描整个列表。 
3. 我们在一次传递中处理该结构，维护迄今为止在每个相关类别中看到的守卫数量的运行累积。 每个新警卫都根据以前积累的信息做出贡献，而不是检查所有其他信息。 
4. 对于每个元素，我们仅使用聚合状态来计算其贡献。 我们不是迭代所有先前的元素，而是查询当前的摘要结构。 这将每次更新减少到 O(1) 或 O(log n)，具体取决于实现。 
5. 我们在处理每个守卫时逐步更新全局答案，确保每次交互都被精确计算一次。 

### 为什么它有效

 正确性来自于这样的事实：在处理第二个防护时，两个防护之间的每次交互都被精确地表示一次。 此时，数据结构已经包含了可以与其交互的所有先前守卫的完整摘要。 由于贡献函数与该累加相关联，因此将其拆分为“先前状态+当前元素”可以保留总和，而不会重复计算或遗漏。 这将成对定义转变为前缀封闭状态上的顺序构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = {}
    ans = 0

    for x in arr:
        # all previous occurrences of x contribute in a uniform way
        if x in freq:
            ans += freq[x]
            freq[x] += 1
        else:
            freq[x] = 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现遵循维护先前看到的状态的频率图的结构。 每个新的防护都会根据已经出现的兼容元素数量做出贡献，从而消除了嵌套循环的需要。 关键的微妙之处在于更新必须在计算贡献之后发生； 否则当前元素将错误地计算自身。 

## 工作示例

 考虑一个简单的配置，其中防护被放置在位置 [1, 2, 1]。 

对于这个输入，我们逐步跟踪频率图和贡献。 

| 步骤| 当前 x | 之前的频率图| 贡献已添加 | | 之后的频率图 总计 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | {} | 0 | {1:1} | 0 |
 | 2 | 2 | {1:1} | 0 | {1:1, 2:1} | 0 |
 | 3 | 1 | {1:1, 2:1} | 1 | {1:2, 2:1} | 1 |

 唯一的贡献发生在第二次出现 1 时，因为它与之前的 1 相互作用。 

现在考虑所有值都相同的情况，[3, 3, 3, 3]。 

| 步骤| 当前 x | 之前的频率图| 贡献已添加 | | 之后的频率图 总计 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | {} | 0 | {3:1} | 0 |
 | 2 | 3 | {3:1} | 1 | {3:2} | 1 |
 | 3 | 3 | {3:2} | 2 | {3:3} | 3 |
 | 4 | 3 | {3:3} | 3 | {3:4} | 6 |

 这表明所有成对相互作用都是自然累积的，无需显式枚举对。

 ## 边缘情况

 当只有一个保护时，算法立即输出零，因为在处理第一个元素之前频率图是空的。 贡献步骤永远不会触发任何添加，这与不存在交互的事实相匹配。 

当所有守卫共享相同位置时，频率图稳定增长，并且每个新元素准确地贡献了先前出现的次数。 这确保了通过增量累积而不是重复扫描，所有成对相互作用都被精确计数一次。 

当所有位置都不同时，频率图中的每次查找都会返回零贡献。 该算法仍然以线性时间运行，但没有积累任何内容，正确反映了配置中不存在交互的情况。
