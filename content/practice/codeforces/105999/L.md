 ## 解决方案
 ## 方法

 蛮力策略是尝试每一个可能的中心$p$。 对于每个$p$，计算需要翻转多少次才能使剩下的所有内容$p$变成$R$一切正确的事情都变成了$L$。 这很简单：对于一个固定的$p$，我们扫描所有位置并计算相对于所需方向的不匹配。 每次评估费用$O(n)$，并且有$O(n)$的选择$p$，导致$O(n^2)$总工作量。 和$n = 2000$，这大约是 400 万个字符检查，这很好。 

关键的观察是每个位置以结构化的方式独立地为每个候选中心做出贡献。 索引处的一个字符$i$对所有中心来说都是错误的$p > i$如果是的话$L$，并且对于所有中心都是错误的$p < i$如果是的话$R$。 这使我们能够预先计算当中心移动时贡献如何变化。 而不是从头开始重新计算每个$p$，我们可以维护前缀计数$L$和后缀数$R$，并导出每项成本$O(1)$。 

从暴力解决方案到最优​​解决方案的转变是认识到每个分割点仅改变每个索引属于哪一侧，因此成本只是两个前缀/后缀统计数据的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（尝试所有中心，每次重新计算）|$O(n^2)$|$O(1)$| 已接受 |
 | 前缀/后缀预计算 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题重写为选择分割点$p$使得成本为：

 1. 统计位置中有多少个字符$[0, p-1]$不是$R$，因为它们最终必须是$R$。 
2. 计算位置中有多少个字符$[p+1, n-1]$不是$L$，因为它们最终必须是$L$。 
3.忽略位置$p$。 

我们计算前缀和$R$和后缀总和$L$。 

1. 构建数组`prefR`在哪里`prefR[i]`商店有多少家`R`字符出现在`s[0..i-1]`。 这样可以快速计算任何分割的左侧已经存在多少个正确位置。 
2. 构建数组`sufL`在哪里`sufL[i]`商店有多少家`L`字符出现在`s[i..n-1]`。 这捕获了任何分割右侧存在多少个正确位置。 
3.对于每个候选分割位置$p$，计算左侧所需的翻转次数为$p - \text{prefR}[p]$，因为一切都还没有$R$必须翻转。 
4. 计算右侧所需的翻转次数：$(n - p - 1) - \text{sufL}[p+1]$，因为一切都还没有$L$必须翻转。 
5. 取所有的最小总和$p$。 

它之所以有效，是因为对于固定中心，最优策略永远不需要考虑不同指数之间的相互作用。 每个索引要么已经与该侧所需的方向匹配，要么必须翻转。 一个索引的翻转选择不会影响其他索引的正确性，因此成本可以干净地分解为独立的贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    prefR = [0] * (n + 1)
    for i in range(n):
        prefR[i + 1] = prefR[i] + (1 if s[i] == 'R' else 0)

    sufL = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        sufL[i] = sufL[i + 1] + (1 if s[i] == 'L' else 0)

    ans = n
    for p in range(n):
        left_cost = p - prefR[p]
        right_cost = (n - p - 1) - sufL[p + 1]
        ans = min(ans, left_cost + right_cost)

    print(ans)

if __name__ == "__main__":
    solve()
```如果在它们之后放置分割，则前缀数组会跟踪有多少位置已经满足左侧要求。 后缀数组起到右侧对称的作用。 所有分割点上的循环直接评估目标位置的每种可能选择，循环内的公式正是将不匹配分解为独立的段。 

一个常见的错误是忘记排除枢轴索引$p$从两侧。 另一个是混淆左侧是否想要$R$或者$L$，它翻转了前缀和的解释。 最安全的实施方法是明确写下每一侧必须成为的内容，然后计算不匹配而不是匹配的数量。

 ## 边缘情况

 对于像这样的单向字符串`LLLL`，每次分割至少在一侧产生零成本，并且该算法正确评估所有分割，因为前缀和后缀数组捕获完全同质性。 在任何分裂$p$,`prefR[p] = 0`和`sufL[p] = n-p`，导致一致的最小值为零。 

对于交替字符串，例如`LRLRLR`，贪婪的方法往往会影响决策，但基于分割的公式独立地隔离了每个候选中心。 评估中$p = 3$直接产生平衡的错配计数，并且算法正确识别最小校正成本，而不受早期位置的影响。 

对于边界分割$p = 0$和$p = n-1$，一侧是空的。 由于前缀或后缀贡献消失，公式可以正确归约，从而确认不需要对边缘进行特殊处理。
