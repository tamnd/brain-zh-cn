[CF 436A - 用糖果喂食](https://codeforces.com/problemset/problem/436/A)

 **评分：** 1500
 **标签：** 贪婪
 **求解时间：** 1m 36s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们最多有2000颗糖果。 每个糖果都有一个类型（0 或 1）、所需的跳跃高度和质量。 

Om Nom 以跳跃力开始`x`。 他可以吃任何未吃掉的糖果，其高度最多为他当前的跳跃力。 吃完一块有质量的糖果后`m`，他的跳跃力增加`m`。 

还有一项附加限制：连续的糖果必须具有不同的类型。 如果最后吃的糖果是类型 0，那么下一颗糖果一定是类型 1，反之亦然。 

目标是最大化吃掉的糖果总数。 

限制小得惊人。 和`n ≤ 2000`， 一个`O(n²)`解决方案是完全安全的，因为它执行大约四百万次操作。 另一方面，对所有有效的饮食订单进行指数搜索是不可能的，因为订单数量呈阶乘增长。 

棘手的部分是吃糖果会改变未来的可达性。 在当地看起来不错的选择可能会在以后解锁更多糖果。 

一个容易犯的错误就是总是拿走可触及的高度最小的糖果。 

例子：```
3 3
0 2 10
1 3 1
1 20 1
```正确输出：```
2
```如果我们先吃0型糖果，跳跃力就会变成13，我们仍然可以吃1型糖果。 如果我们关注的是高度而不是增加的质量，我们可能无法最大化未来的可达性。 

另一个微妙的情况是，最佳序列可以从任一类型开始。```
2 1
0 1 1
1 100 100
```正确输出：```
1
```从类型 0 开始给出一颗糖果。 从类型 1 开始给出零。 任何假设固定起始类型的解决方案都会失败。 

第三个陷阱是假设在所需类型的可获得的糖果中，任何选择都同样好。```
3 5
0 5 1
0 5 10
1 15 1
```正确输出：```
2
```当首先选择 0 型糖果时，选择质量 10 绝对比选择质量 1 好，因为它会立即解锁 1 型糖果。 

## 方法

 蛮力的想法很简单。 在每一步中，尝试所需类型的每种可到达的糖果，递归并获得最佳结果。 这探索了所有有效的饮食顺序。 

暴力破解是正确的，因为它明确地检查每个合法序列。 不幸的是，序列的数量是巨大的。 即使是几十块糖果也是不可行的，`n = 2000`这是完全不可能的。 

为了更快地获得某些东西，我们需要了解真正重要的东西。 

假设下一个糖果必须具有类型 0。在所有可到达的未使用的类型 0 糖果中，想象一下选择一个具有质量的糖果`a`而另一个可达的选择具有更大的质量`b`。 

吃下较大质量的糖果后，跳跃力会比吃下较小质量的糖果后更大。 获得后可获得的每一颗糖果`a`获得后也可到达`b`。 更大的收益永远不会消除可能性。 

这个观察结果是关键的贪婪属性。 每当我们必须选择某种类型的糖果时，最好的选择就是该类型中可到达且质量最大的糖果。 

唯一剩下的不确定性是起始类型。 由于只有两种类型，我们可以模拟两次贪婪过程。 

在一次模拟中，我们坚持认为第一个糖果是类型 0。 

在另一个模拟中，我们坚持认为第一个糖果是类型 1。 

对于每个模拟：

 1. 反复寻找所需类型且质量最大且未使用的可达糖果。 
2. 吃掉它。 
3.增加跳跃力。 
4. 切换所需类型。 

当不存在所需类型的可到达糖果时，模拟结束。 

答案是两次模拟的较大结果。 这种贪婪策略是该问题的标准公认解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优贪心模拟 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 读取所有糖果并存储它们的类型、高度和质量。 
2. 运行模拟，假设第一个吃的糖果必须是类型 0。 
3. 创建一个`used`数组标记哪些糖果已经被吃掉。 
4. 设置当前跳跃功率为`x`。 
5.让`need_type`是接下来必须吃的类型。 
6. 扫描所有糖果，找到一颗未使用的糖果，其类型为`need_type`，其高度最多为当前跳跃能力，且其质量是所有此类候选者中最大的。 
7. 如果不存在候选者，则停止本次模拟。 

此时，没有可用的合法移动，因为下一个糖果必须具有所需的类型。 
8. 吃掉选择的糖果。 

通过其质量增加跳跃力，将其标记为已使用，增加此模拟的答案，然后翻转`need_type`。 
9. 重复步骤 6。 
10. 再次执行相同的过程，这次从类型 1 开始。 
11. 输出两个结果中较大的一个。 

### 为什么它有效

 考虑下一个糖果必须具有某种固定类型的任何步骤。 

在该类型的所有可到达的糖果中，令`A`是质量最大的糖果。 假设另一个可到达的糖果`B`被选择。 

吃完后`A`，跳跃力至少变得和进食后一样大`B`。 选择后可获得的每颗糖果`B`选择后仍然可达`A`。 由于类型交替要求仅取决于糖果类型而不取决于质量，因此选择`A`不能减少未来有效移动的集合。 

用可达到的最大质量代替任何较小质量的选择永远不会有坏处。 在每一步应用这个论点证明贪婪选择对于固定的起始类型始终是最佳的。 

由于每个有效序列必须以类型 0 或类型 1 开始，因此检查两种起始类型可确保找到全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def simulate(start_type, candies, x):
    n = len(candies)
    used = [False] * n

    cur_jump = x
    need_type = start_type
    eaten = 0

    while True:
        best_idx = -1
        best_mass = -1

        for i, (t, h, m) in enumerate(candies):
            if not used[i] and t == need_type and h <= cur_jump:
                if m > best_mass:
                    best_mass = m
                    best_idx = i

        if best_idx == -1:
            break

        used[best_idx] = True
        cur_jump += candies[best_idx][2]
        eaten += 1
        need_type ^= 1

    return eaten

def solve():
    n, x = map(int, input().split())

    candies = []
    for _ in range(n):
        t, h, m = map(int, input().split())
        candies.append((t, h, m))

    ans = max(
        simulate(0, candies, x),
        simulate(1, candies, x)
    )

    print(ans)

solve()
```模拟函数直接实现贪心过程。 这`used`数组可防止重复使用糖果。 在每一步中，我们都会搜索所有糖果并选择具有最大质量的所需类型的可到达糖果。 

该比较使用质量而不是高度，因为证明依赖于最大化未来的跳跃能力。 选择可达的最高糖果并不能保留贪婪财产。 

更新的顺序很重要。 我们首先将糖果标记为已使用，然后将其质量添加到跳跃功率中，然后切换所需的类型。 这与问题的事件顺序完全匹配。 

所有值都很容易适合 Python 整数。 即使在极端情况下，总获得的质量最多为`2000 × 2000 = 4,000,000`。

import io

def solve():
    n, x = map(int, input().split())

    candies = [tuple(map(int, input().split())) for _ in range(n)]

    def simulate(start_type):
        used = [False] * n
        cur = x
        need = start_type
        ans = 0

        while True:
            best = -1
            best_mass = -1

            for i, (t, h, m) in enumerate(candies):
                if not used[i] and t == need and h <= cur and m > best_mass:
                    best_mass = m
                    best = i

            if best == -1:
                break

            used[best] = True
            cur += candies[best][2]
            ans += 1
            need ^= 1

        return ans

    print(max(simulate(0), simulate(1)))

 ## 边缘情况

 ### 只有一种起始类型有效

 输入：```
2 1
0 1 1
1 100 100
```从类型 0 开始，Om Nom 吃一颗糖果并达到跳跃力 2。 

从类型 1 开始，没有可到达的糖果。 

该算法显式模拟两种起始类型并返回更好的结果，即 1。 

### 更大的质量不是可选的

 输入：```
3 5
0 5 1
0 5 10
1 15 1
```当跳跃力为 5 时，两种 0 型糖果都可以到达。 

该算法选择质量 10，将跳跃力提高到 15 并解锁 1 类糖果。 

如果它选择质量 1，则跳跃力将仅为 6，答案将从 2 降至 1。 

### 可获得的糖果，但类型错误

 输入：```
3 10
0 1 1
0 2 1
1 20 1
```吃完一颗 0 类糖果后，下一个需要的类型是 1。 

即使可以到达另一个 0 类糖果，但由于交替规则，它不能立即被吃掉。 

当不存在所需类型的可到达糖果时，模拟会正确停止。 这与问题陈述完全一致。
