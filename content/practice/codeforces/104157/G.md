 ## 解决方案
 ## 问题理解

 我们得到一系列按固定顺序站立的员工，其中每个员工都有已知的打字持续时间。 有 M 台相同的计算机，这些计算机就像并行处理器一样，不断地接收队列中的下一个可用人员。 

在零时间，前 M 名员工立即开始打字，每台计算机一个。 每台计算机的行为都是独立的：当用户完成操作后，同一台计算机会立即引导下一个排队等候的人。 这个过程一直持续到所有员工都完成了测试，当最后一名员工完成测试时比赛结束。 

任务是确定最小数量的计算机M，使得整个队列的总完成时间不超过最后期限D。 

如果天真地完成这些约束，那么对所有可能的 M 进行直接模拟是不可行的。 N 最大可达 100000，D 最大可达 10^9。 在最坏的情况下，为每个候选 M 重新计算完整调度的天真尝试将花费 O(N^2)，这对于极限来说太慢了。 如果对 M 进行线性测试，即使每次检查的 O(N log N) 也会变得昂贵。 

当单个员工的时间已经大于 D 时，就会出现微妙的边缘情况。在这种情况下，即使有无限的计算机，答案仍然受到最大个人运行时间的限制，因为该员工无法并行化。 例如，如果 N = 3、D = 5 且 t = [10, 1, 1]，则答案不存在，除非问题保证可行性（事实确实如此）。 这告诉我们必须假设预期的解空间始终包含有效的 M。 

当所有处理时间相等时，会出现另一种边缘情况。 在这种情况下，完成时间几乎线性地取决于 ceil(N / M)，天真的贪婪直觉可能会误导人们认为 M = N 总是需要的，但队列重用可确保在 D 足够大的情况下，较小的 M 仍然可以满足约束。 

## 方法

 一个蛮力的想法是尝试从 1 到 N 的所有可能数量的计算机 M。对于每个 M，我们使用优先级队列或跟踪每台计算机何时空闲的最小堆来模拟整个调度过程。 我们推送前M个任务，然后重复弹出最早完成的机器，分配下一个任务，一直持续到所有任务都处理完毕。 总运行时间是该模拟产生的最大完成时间。 

这是有效的，因为它准确地再现了真实的系统。 问题是每次模拟的成本为 O(N log M)，并且在最坏的情况下对所有 M 进行模拟会导致 O(N^2 log N)，这远远超出了限制。 

关键的观察是给定 M 的可行性是单调的。 如果M台计算机可以在时间D内完成，那么任何M'>M也可以在D内完成，因为添加机器只能减少等待时间或保持等待时间不变。 这将问题转化为 M 上的单调谓词，这立即表明二分搜索。 

剩下的就是检查固定 M 的可行性的有效方法。使用堆的自然模拟在 O(N log M) 中已经可以接受，但由于二分搜索，我们只需要 O(log N) 检查，因此整体复杂度变为 O(N log N log N)，这已经足够了。 

我们有效地结合了两种想法：相同机器上的负载平衡和满足全局时间约束所需的机器数量的二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(N^2 log N) | O(N^2 log N) | O(N) | 太慢了 |
 | 二分查找+堆模拟| O(N log N log N) | O(N log N log N) | O(N) | 已接受 |

 ## 算法演练

 我们通过寻找通过可行性测试的最小 M 来解决这个问题。

1. 定义一个函数 can(M)，用于确定 M 台计算机是否足以在时间 D 内完成所有任务。我们使用完成时间的优先级队列完全按照问题中描述的过程进行模拟。 
2. 在can(M)中，我们首先将前M个任务分配给M台计算机。 堆中的每个条目代表计算机空闲的时间，因此我们使用 t[i] 对其进行初始化，其中 i 从 0 到 M−1。 这反映了这些任务中的每一个都在零时间开始。 
3. 对于每个剩余任务，我们重复从堆中取出最早可用的计算机。 该机器在 current_time 时间完成，我们将下一个任务分配给它，并将其新的完成时间更新为 current_time + t[i]。 我们将这个更新后的值推回到堆中。 
4. 一旦分配了所有任务，这个 M 的答案就是堆中看到的最大值。 由于堆始终存储完成时间，因此最大值表示最后一个员工完成的时间。 
5. 如果该最大值小于或等于 D，则 M 就足够了。 
6. 我们使用 can(M) 作为谓词，对 M 从 1 到 N 进行二分搜索。 如果can(M)为真，我们尝试更小的M； 否则，我们增加M。 

二分查找有效的关键原因是 can(M) 是单调的。 如果增加机器数量不能恶化完成时间，那么一旦 M 的值有效，所有较大的值仍然有效。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def can(M, t, D):
    if M >= len(t):
        return max(t) <= D

    heap = t[:M]
    heapq.heapify(heap)

    for i in range(M, len(t)):
        earliest = heapq.heappop(heap)
        finish = earliest + t[i]
        heapq.heappush(heap, finish)

    return max(heap) <= D

def solve():
    N, D = map(int, input().split())
    t = list(map(int, input().split()))

    lo, hi = 1, N
    ans = N

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, t, D):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```函数can(M)将系统精确地模拟为多机调度过程。 堆存储当前的完成时间，因此我们总是重用最早的可用机器。 这种贪婪分配是必要的，因为延迟分配只会增加完成时间。 

二分搜索确保我们不会显式测试所有 M 值。 相反，我们依靠单调性以对数方式减少搜索空间。 

一个微妙的点是用前 M 个任务初始化堆。 该模型在零时间同时启动，这一点至关重要； 将机器视为最初空闲会错误地改变所有完成时间。 

## 工作示例

 ### 示例 1

 输入：```
N = 6, D = 151
t = [56, 94, 95, 33, 62, 28]
```我们通过二分搜索测试候选 M 值。 

| 中号 | 堆演变（完成时间）| 最终最大| 可行|
 | --- | --- | --- | --- |
 | 1 | [56] → [150] → [245] → ... | >151 | 没有 |
 | 2 | [56, 94] → [56, 127] → [150, 127] → ... | >151 | 没有 |
 | 3 | [56, 94, 95] → 更新 → 最大 ≤ 151 | 151 | 151 是的 |

 当 M = 3 时，调度会平衡足够的负载，以便没有机器超过最后期限。 

这证实了增加 M 可以减少单个机器的压力，并且阈值严格为 3。

 ## 边缘情况

 关键的边缘情况是 M 等于 1。在这种情况下，算法退化为简单的前缀和，因为每个任务都在一台机器上顺序运行。 堆逻辑仍然可以正常工作，但这实际上是不必要的开销。 用于输入`[5, 5, 5]`当 D = 10 时，模拟产生完成时间 15，正确拒绝 M = 1。 

另一个重要的情况是当 M 大于或等于 N 时。这里每个任务都有自己的机器，所以答案就是 t 中的最大值。 代码显式地处理这个问题，确保不会浪费任何堆操作并保持正确性。 

第三种情况涉及许多小任务中的一项极其大的任务。 堆确保这个大任务总是尽早占用一台机器，二分查找确保我们找到最小的 M，足以隔离其影响以满足 D。
