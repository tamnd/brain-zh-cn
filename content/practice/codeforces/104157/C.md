 ## 解决方案
 ## 问题理解

 我们在 2D 平面上得到一个圆形目标，以及代表不同员工投掷物体的位置的一系列点。 任务是计算有多少个抛出的点落在圆内或恰好落在其边界上。 

每次抛出只是一个坐标对。 圆由其圆心和半径定义。 如果距中心的欧氏距离小于或等于半径，则抛出成功。 

约束足够大，任何解决方案都必须在恒定时间内处理每个点。 投掷次数高达 100,000 次，$O(n)$预计有解决方案。 任何涉及排序或成对比较的事情都是不必要的，而且速度太慢。 

在此类问题中经常出现的一个微妙问题是计算距离时的数值安全性。 简单的公式涉及平方根，浮点比较可能会引入精度误差。 另一个常见的陷阱是在对坐标进行平方时使用 32 位整数$10^9$，立即溢出。 

一些边缘情况很重要：

 恰好位于边界上的点应视为成功。 例如，如果中心是$(0,0)$半径是$5$, 点$(3,4)$必须计算在内，因为$3^2 + 4^2 = 25$。 

第二个微妙的情况是大坐标。 如果我们计算$(x - c_x)^2$使用 32 位整数，值接近$10^9$生产周围$10^{18}$，这需要 64 位算术。 使用错误的类型会默默地产生错误的结果。 

## 方法

 解决该问题的直接方法是独立处理每个投掷并计算其到圆心的距离。 对于每个点，我们使用以下公式计算欧几里德距离$\sqrt{(x_i - c_x)^2 + (y_i - c_y)^2}$，并检查它是否小于或等于$r$。 这是正确的，因为“圆内”的定义正是距离条件。 

然而，这涉及每个点的平方根。 尽管$O(n)$就渐近复杂度而言很好，平方根运算相对昂贵且不必要。 更重要的是，浮点比较可能会在边界附近引入精度误差，其中应该包含一个点，但可能会因舍入而被排除。 

关键的观察是我们永远不需要实际距离。 我们只需要将它与半径进行比较。 由于两边都是非负的，我们可以安全地对不等式两边进行平方：$$(x_i - c_x)^2 + (y_i - c_y)^2 \le r^2$$这完全消除了平方根并将问题转换为简单的整数算术。 现在每个点只需要几次整数运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（每点开方）| O(n) | O(1) | O(1) | 被接受但脆弱|
 | 平方距离检查 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取点数、圆心坐标和半径。 我们立即计算$r^2$所以我们在处理过程中永远不需要重新计算它。 这避免了重复乘法并保持比较的统一。 
2. 将计数器初始化为零。 这将跟踪有多少点满足圆条件。 
3. 每次投掷$(x_i, y_i)$，计算距中心的水平和垂直偏移：$dx = x_i - c_x$,$dy = y_i - c_y$。 这些偏移表示从中心到该点的位移矢量。 
4. 计算平方距离$dx^2 + dy^2$。 这是距中心的精确平方欧几里得距离。 我们有意避免平方根，因为它们不需要进行比较。 
5. 将平方距离与$r^2$。 如果小于或等于，则增加计数器。 这直接对应于在圆的内部或边界上的定义。 
6. 处理完所有点后，输出计数器。 

### 为什么它有效

 正确性取决于平方对于非负值是单调的这一事实。 由于平方距离和$r^2$总是非负的，比较它们会保留原始距离的顺序。 这意味着平方后的不等式相当于原始几何条件。 每个点都按照真正的欧几里德距离进行精确分类，但不引入浮点计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, cx, cy, r = map(int, input().split())
    r2 = r * r

    cnt = 0
    for _ in range(n):
        x, y = map(int, input().split())
        dx = x - cx
        dy = y - cy
        if dx * dx + dy * dy <= r2:
            cnt += 1

    print(cnt)

if __name__ == "__main__":
    solve()
```实现直接遵循算法。 预处理步骤存储$r^2$，确保每个查询只执行固定数量的算术运算。 

减法步骤很重要，因为它将坐标减少到以圆原点为中心的局部框架中。 这避免了对绝对位置的任何需要。 

所有算术都是使用Python整数完成的，它天然支持大值，因此不存在溢出风险。

 ## 边缘情况

 一个重要的边缘情况是当一个点恰好位于圆边界上时。 考虑输入：```
1 0 0 5
3 4
```该算法计算$dx = 3$,$dy = 4$， 和$dx^2 + dy^2 = 25$。 自从$r^2 = 25$，条件满足，得分。 这确认了边界点的正确包含，而不需要浮点容差。 

另一个边缘情况是大坐标值：```
1 1000000000 -1000000000 1
1000000000 -999999999
```这里$dx = 0$,$dy = 1$，因此平方距离为 1。即使中间坐标值很大，Python 的整数算术也可以安全地处理它们，并且比较仍然正确。
