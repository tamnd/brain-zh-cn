 ## 解决方案
 ## 问题理解

 每个测试用例给我们两个大整数，表示两个互补部分的可用计数。 根据这些计数，托马斯有效地生成了许多等于两个值的最大公约数的完整对。 那个gcd值，称之为$g$，是我们真正关心的唯一数量，因为它代表可以从两种供应中一致地形成多少完整项目。 

对于每个测试用例，一次$g$确定了，任务不是输出$g$本身，而是以质因数形式表达。 我们需要所有不同的素数相除$g$，递增排序，对于每个这样的素数，我们必须输出它在因式分解中出现的次数。 

约束的测试用例数量很少，但值本身很大，最多可达$10^{12}$。 这立即排除了任何重复列举候选人的方法$g$或执行试除直至$g$。 即使是简单的因式分解$10^{12}$如果重复最坏情况 100 次，每个测试用例就会太慢。 

因此，主要的计算结构很清楚：我们需要有效地计算 gcd，然后将一个数分解为$10^{12}$高效。 

一些边缘情况很重要。 如果$b$和$l$是互质的，那么$g = 1$，并且我们必须只打印该测试用例的终止标记，前面没有素数。 如果$g$是素数，我们必须准确地输出包含重数为 1 的素数的一行。一个常见的错误是忘记重数是指因式分解中的指数$g$，不是原始输入。 

## 方法

 朴素的方法计算$g = \gcd(b, l)$，然后通过检查从 2 到 的所有整数来分解它$\sqrt{g}$并反复分割。 这是正确的，因为每个合数至少有一个质因数至多其平方根。 然而，在最坏的情况下$g \approx 10^{12}$， 所以$\sqrt{g} \approx 10^6$。 对每个测试用例进行多达 100 万次试验划分，并对多达 100 个案例重复此操作，得出的粗略结果是$10^8$运算，并且每个除法步骤在 Python 中都不是微不足道的。 这接近边界并存在 TLE 风险。 

关键的改进来自于注意到分解只需要素数，而不是所有整数。 我们可以预先计算所有素数$10^6$一旦使用筛子，然后将每个因子分解$g$仅除以这些素数。 由于任意合数最多可达$10^{12}$至少有一个质因数 ≤$10^6$，这就足够了。 去掉小素数后，如果剩余的值大于1，那么它本身就是素数。 

这减少了每个测试用例$O(\sqrt{g})$检查大致$O(\pi(\sqrt{g}))$，大约有 78,000 个素数，但实际上由于早期归约，要少得多。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力审判司|$O(T \sqrt{g})$|$O(1)$| 太慢了 |
 | 筛选 + 质因数分解 |$O(\sqrt{N} + T \cdot \pi(\sqrt{g}))$|$O(\sqrt{N})$| 已接受 |

 ## 算法演练

 ### 1. 预先计算素数$10^6$我们建立了埃拉托色尼筛。 这为我们提供了将任何数字分解为因式分解所需的所有素数$10^{12}$，因为该范围内的任何合数最多必须有一个质因数$10^6$。 

### 2. 处理每个测试用例

 对于每对$(b, l)$, 计算$g = \gcd(b, l)$。 这一步很快，$O(\log \min(b,l))$，并且不支配任何东西。 

### 3.因素$g$使用预先计算的素数

 我们按升序迭代素数。 对于每个素数$p$，我们划分$g$只要$p \mid g$，计算这种情况发生了多少次。 

每一次成功的分裂都会缩小$g$，所以以后的支票会变得更便宜。 这就是为什么我们早早停下来$p^2 > g$。 

### 4. 处理剩余价值

 如果处理完所有素数后$\sqrt{g}$， 其余$g > 1$，则它是质数，并贡献一个指数为 1 的最终因子。 

### 5.输出格式

 我们按升序打印每个质因数及其指数。 完成测试用例后，我们打印一行包含 0 的内容。 

### 为什么它有效

 正确性取决于质因数分解的唯一性以及每个合数都有一个不超过其平方根的质因数这一事实。 筛子保证我们按顺序测试所有可能的素数，因此每个因子都被完全提取一次。 由于每次除法在继续之前都会删除所有出现的素数，因此可以精确计算重数，并且通过按升序迭代素数来保留顺序。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

MAX = 10**6

is_prime = [True] * (MAX + 1)
is_prime[0] = is_prime[1] = False
primes = []

for i in range(2, MAX + 1):
    if is_prime[i]:
        primes.append(i)
        for j in range(i * i, MAX + 1, i):
            is_prime[j] = False

def factorize(n):
    res = []
    for p in primes:
        if p * p > n:
            break
        if n % p == 0:
            cnt = 0
            while n % p == 0:
                n //= p
                cnt += 1
            res.append((p, cnt))
    if n > 1:
        res.append((n, 1))
    return res

t = int(input())
out = []

for _ in range(t):
    b, l = map(int, input().split())
    g = math.gcd(b, l)

    if g == 1:
        out.append("0")
        continue

    factors = factorize(g)
    for p, c in factors:
        out.append(f"{p} {c}")
    out.append("0")

sys.stdout.write("\n".join(out))
```该筛子在开始时构建一次，并在所有测试用例中重复使用。 因式分解例程小心地停止一次$p^2 > n$，一旦剩余数字已经是素数，就可以防止不必要的迭代。 

gcd 计算确保我们只对每个测试用例分解一个减少的数字，而不是两个大的输入。 

输出累积在一个列表中，以避免循环内重复的 I/O 开销，这在时间有限的 Python 中非常重要。

 ## 边缘情况

 一种重要的边缘情况是 gcd 为 1 时。例如，输入`83 24`产生$g = 1$。 完全跳过因式分解循环，唯一需要的输出是单个`0`。 该算法自然地处理这个问题，因为分解函数返回一个空列表，并且调用者直接附加终止符。 

另一个边缘情况是当 gcd 是素数幂时，例如`49 49`， 在哪里$g = 49 = 7^2$。 该循环检测能被 7 整除，计算两次除法，然后追加`(7, 2)`。 由于减少后的值变为 1，因此不会附加剩余部分，从而防止重复输出。 

最后一个微妙的情况是当 gcd 本身是一个大于的大素数时$10^6$， 例如`1000000000039 1000000000039`。 在这种情况下，没有素数筛将其除以，因此循环结束，剩下的`n > 1`作为指数 1 的单个质因数附加。即使超出筛子范围，这也能确保正确性。
