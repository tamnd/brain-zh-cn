 ## 解决方案
 ## 问题理解

 我们得到一系列排列成行的箱子，每个箱子都带有一个可以是正值或负值的值。 玩家在第一个宝箱之前开始，并且拥有有限数量的代币。 玩家严格从左向右移动，但移动并不是简单的一步一步。 相反，每个动作都包括选择跳跃长度，根据该跳跃支付费用，然后打开该跳跃到达的箱子。 

如果玩家选择长度为 1 的跳跃，则需要支付 1 个代币并打开下一个宝箱。 如果他们选择长度为 2 的跳跃，则需要支付 1 + 2 个代币并降落在前面的第二个箱子上，恰好跳过中间的一个箱子。 更一般地，选择跳跃长度 k 会花费第 k 个三角形数，即 1 + 2 + ... + k 个代币，并将玩家向前移动 k 个位置，沿途跳过 k − 1 个箱子。 每次跳跃后，玩家可以随时停止。 

目标是选择一系列此类跳跃，以便总成本不超过可用代币，同时最大化打开的箱子的价值总和。 

这些限制使得结构变得重要。 箱子的数量最多为 100 个，而代币的数量最多为 1000 个。这立即表明我们可以负担得起动态编程解决方案，该解决方案可以探索位置和剩余预算的状态，但任何试图天真地模拟所有跳跃序列的东西都会爆炸，因为即使 m 达到 100，将运动划分为跳跃的方法数量也会呈指数级增长。 

当使用贪婪直觉时，会出现微妙的失败情况。 例如，考虑具有较小正值的早期箱子和具有较大值的较晚箱子。 总是采取最便宜的跳跃来收集早期收益的贪婪策略可能会浪费代币，而这些代币本来可以在以后进行更大的跳跃。 相反，总是为大幅跳跃而储蓄可能会错过完全符合预算的廉价增量收益。 这种结构迫使我们在全球范围内评估权衡。 

另一个边缘情况来自负值。 即使可以到达，最好跳过许多宝箱，因为打开它们会降低总分数。 这打破了任何假设我们应该始终消耗移动直到代币耗尽的方法。 

## 方法

 暴力方法会尝试所有可能的跳跃长度序列。 每个跳跃长度 k 的成本等于一个三角数，并将位置前进 k。 从起点开始，我们可以递归地尝试所有有效的 k 值，当我们降落在箱子上时减去成本并累积分数。 这是正确的，因为它完全按照规则定义的方式枚举了所有有效策略。 

然而，分支因子很大。 从任何位置来看，在令牌限制内最多有大约 40 种可能的跳跃大小，因为三角形数呈二次方增长。 超过 100 个位置，这将创建一个巨大的递归树。 即使进行了修剪，相同的子问题也会频繁重复：通过许多不同的跳转序列可能会出现具有相同剩余标记的相同索引。 这种冗余是效率低下的关键。 

重要的观察是，问题状态完全由两个参数决定：当前宝箱索引和剩余代币。 一旦我们达到给定的预算和给定的指数，无论我们如何到达那里，未来的选择都是相同的。 这使我们能够将指数树折叠成动态规划表。 

从每个状态，我们尝试所有可能的跳跃长度 k，使得三角成本不超过剩余预算并且目的地索引不超过 m。 我们在所有过渡中都采取最好的方式。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有跳转序列进行暴力递归 | 指数| O(m) 递归深度 | 太慢了|
 | DP 头寸和剩余代币 | O(m·n·sqrt(n)) | O(m·n·sqrt(n)) | O(m·n) | 已接受 |

 ## 算法演练

 我们将状态 dp[i][t] 定义为当我们当前处于宝箱索引 i（意味着我们可以打开的下一个宝箱是 i+1）且剩余 t 个代币时可达到的最大分数。 

1. 我们用一个非常小的值初始化所有 dp 状态，并定义到达或超过最后一个宝箱会产生零额外增益，因为没有进一步的开口。 这创建了一个自然停止条件，我们可以随时选择结束该过程。 
2. 我们预先计算跳跃长度的三角成本。 对于每个 k，成本为 k(k+1)/2，我们只保留不超过最大代币预算的值。 这限制了每个状态的转换数量。 
3. 从状态 (i, t) 开始，我们总是考虑立即停止的选项，这会导致进一步的分数为零。 
4. 我们尝试从 1 开始向上的每个跳跃长度 k。 对于每个 k，如果 i + k 不超过 m，我们可以降落在箱子 i + k 上。 我们检查成本 T_k 是否在剩余令牌之内。 如果是，我们转换到 dp[i + k][t − T_k] 并将 a[i + k] 添加到结果中。 
5. 我们取停止和所有有效跳跃转换中的最大值。 
6. 最终答案为 dp[0][n]，代表从第一个具有完整代币预算的宝箱之前开始。 

关键思想是每个有效的游戏序列都对应于该 DP 图中的一条路径，并且每个 DP 转换代表游戏中合法允许的移动。 

### 为什么它有效

 正确性依赖于状态 (i, t) 完全捕获所有相关历史的事实。 未来移动获得的分数仅取决于我们所在的箱子以及剩余的代币数量，而不取决于我们如何到达那里。 每个有效的跳转序列都准确地映射到通过状态的一条路径，并且每个 DP 转换都保留合法性，因为它尊重移动约束和代币支出。 由于考虑了所有可能的转换，DP 会探索整个可行解空间，而不会重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # 1-index the array for convenience
    a = [0] + a

    # precompute triangular costs
    tri = []
    k = 1
    while k * (k + 1) // 2 <= n:
        tri.append(k * (k + 1) // 2)
        k += 1
    maxk = len(tri)

    NEG = -10**18

    # dp[i][t] = best score starting at position i with t tokens left
    dp = [[NEG] * (n + 1) for _ in range(m + 2)]

    # base: at or beyond last chest, score is 0
    for t in range(n + 1):
        dp[m][t] = 0
        dp[m + 1][t] = 0

    for i in range(m - 1, -1, -1):
        for t in range(n + 1):
            best = 0  # option: stop immediately

            for k in range(maxk):
                cost = tri[k]
                j = i + (k + 1)
                if j > m:
                    break
                if cost > t:
                    break
                best = max(best, a[j] + dp[j][t - cost])

            dp[i][t] = best

    print(dp[0][n])

if __name__ == "__main__":
    solve()
```该实现直接反映了状态定义。 DP 表是通过从右到左迭代头寸而自下而上构建的，以便已经计算出到未来指数的转换。 每个状态都考虑立即停止，这很重要，因为某些路径有意避免因负值而进一步开放。 

三角成本预先计算一次，以避免在 DP 循环内重新计算算术，并且当成本超过剩余预算或位置超出范围时，k 上的循环自然会提前终止。

| 状态 (i, t) | 最佳选择| 说明|
 | --- | --- | --- |
 | (0, 4) | (0, 4) | 跳 1 | 拿走宝箱 1 会得到 +1 并留下 3 个代币 |
 | (1, 3) | 跳 1 | 拿走宝箱 2 可获得 +2 |

跟踪显示，即使预算很小，连续的廉价跳跃仍占主导地位，因为所有值都是正数，并且成本与简单的单位跳跃一致。

 ## 边缘情况

 当所有早期的箱子都是阴性但后来的箱子都是高度阳性时，就会出现一个关键的边缘情况。 DP 处理这个问题是因为它总是允许在任何状态下停止，从而防止负值的强制累积。 

另一种情况是，最佳策略需要通过大跳跃跳过多个箱子。 由于转换包括所有 k 值，因此该算法正确地考虑了支付较大的三角成本来直接到达远处的高价值宝箱，而逐步贪婪方法会错过这一点。 

最后，当预算较小时，只有k=1可行。 DP 自然地退化为带有可选停止的简单前缀累积，无需特殊的大小写即可保持正确性。
