 ## 解决方案
 ## 问题理解

 我们得到一系列按固定顺序排列的卡片。 每张卡都带有 1 到 m 之间的整数值。 我们可以删除卡片的任何子集，但不能对剩余的卡片重新排序。 删除后，我们希望剩余的序列形成严格递增一的链，这意味着每个相邻的对都精确地相差一。 

因此，任务是选择一个看起来像 x、x+1、x+2 等的子序列，同时保留原始顺序，并最大化剩余的卡片数量。 

关键点是我们不是选择任意卡，而是选择一个表现得像连续整数运行的子序列。 

约束 n ≤ 100000 排除了尝试所有子序列甚至尝试每个起点并通过嵌套扫描贪婪地扩展它的任何解决方案。 任何二次或更糟糕的事情都会超时。 我们需要接近线性或 n log n 的东西。 

当值重复或多个候选链重叠时，会出现微妙的边缘情况。 例如，如果数组是 1 2 1 2 3，我们可能会认为我们可以扩展许多链，但只有尊重顺序和精确 +1 转换的子序列才重要，因此我们必须仔细跟踪可行性而不仅仅是频率。 

另一个棘手的情况是最佳链未与其起始值的第一次出现对齐。 例如，在 2 3 2 1 4 中，从前 2 个开始比从后 2 个开始更糟糕，无法构建更长的连续运行。 

## 方法

 暴力解释是尝试每个起始位置 i，将 a[i] 视为链的开头，并贪婪地向右扫描，收集 a[i]、a[i]+1、a[i]+2 等。 对于每次开始，我们都会维护一个指针并重复向前扫描以查找下一个所需的值。 这是正确的，因为任何有效的子序列都必须按顺序选择元素，并且贪婪地采用最早可能出现的元素可以保留可行性。 

然而，这种方法会重复扫描数组。 在最坏的情况下，对于 n 个起始位置中的每一个，我们可以扫描最多 n 个元素，给出 O(n²)。 当 n 达到 100000 时，这大约是 10^10 次操作，这是不可行的。 

结构观察是，一旦我们确定了起始值 x，问题就简化为在选定位置后重复查找下一个出现的 x+1。 如果我们能够快速回答“索引 p 之后值 v 的下一次出现”，我们就可以有效地模拟每条链。 这建议预处理每个值的位置并使用二分搜索。 

我们为每个值存储它出现的索引的排序列表。 然后，对于值为 x 的给定起始位置 i，我们通过重复跳转到当前索引之后出现的第一个 x+1 来向前行走。 通过二分搜索，每次跳转的成本为 O(log k)，我们最多执行 m 步，但实际上仅沿着现有的连续值执行。 

这将问题简化为仅扫描可行的链，而不是重复扫描整个数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 位置列表+二分查找 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建从每个值 v 到 v 出现在数组中的索引列表的映射。 

这使我们能够快速定位按排序顺序出现的任何值。 
2. 迭代数组中的每个索引 i 并将其视为潜在的起点。 

我们尝试构建从 a[i] 开始的最长有效连续子序列。 
3. 设当前值为a[i]，当前位置为i。 初始化长度为1。 
4. 反复尝试将链条延伸至当前值+1。

我们在位置列表中搜索该值，并使用二分搜索找到严格大于当前位置的最小索引。 
5. 如果存在这样的索引，则移至该索引，增加链长度，然后继续。 

如果不存在，则链停止。 
6. 跟踪所有起始位置的最大链条长度。 

每个步骤都确保我们始终尊重原始顺序，同时仅选择严格连续的值。 

### 为什么它有效

 对于任何有效的解决方案，子序列必须锚定在值 v 的某个起始出现位置。从该点开始，每个下一个元素必须是上一个选择之后 v+1 的第一个可用出现位置； 稍后选择任何事情只会减少未来的选择。 因此，贪婪跳转到最早有效的下一个事件不会降低最优性。 由于考虑了每个起始索引，因此我们不会错过任何可能的链。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from bisect import bisect_right

n, m = map(int, input().split())
a = list(map(int, input().split()))

pos = [[] for _ in range(m + 2)]
for i, v in enumerate(a):
    pos[v].append(i)

ans = 1

for i in range(n):
    v = a[i]
    cur_idx = i
    length = 1

    while v + 1 <= m:
        lst = pos[v + 1]
        if not lst:
            break
        j = bisect_right(lst, cur_idx)
        if j == len(lst):
            break
        cur_idx = lst[j]
        v += 1
        length += 1

    if length > ans:
        ans = length

print(ans)
```该解决方案依赖于预处理位置，以便每个“下一步”查询都变成二分搜索。 外循环尝试每个可能的起始索引，因为最佳链可能从任何值的任何出现处开始。 内部循环向前遍历连续值，始终跳转到最早的可行出现。 

bisect_right 的使用至关重要，因为我们必须确保索引严格向前移动； 不允许相等，因为我们不能重复使用同一张卡。

## 测试用例```python
import sys, io
from bisect import bisect_right

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    pos = [[] for _ in range(m + 2)]
    for i, v in enumerate(a):
        pos[v].append(i)

    ans = 1

    for i in range(n):
        v = a[i]
        cur = i
        length = 1
        while v + 1 <= m:
            lst = pos[v + 1]
            if not lst:
                break
            j = bisect_right(lst, cur)
            if j == len(lst):
                break
            cur = lst[j]
            v += 1
            length += 1
        ans = max(ans, length)

    return str(ans)

# provided samples
assert solve("5 4\n2 3 2 1 4\n") == "3"
assert solve("7 10\n1 2 3 4 7 8 9\n") == "4"
assert solve("3 8\n3 2 1\n") == "1"

# custom cases
assert solve("1 5\n3\n") == "1", "single element"
assert solve("5 5\n1 1 1 1 1\n") == "1", "all equal"
assert solve("6 6\n1 3 2 4 5 6\n") == "4", "interleaving but valid chain"
assert solve("8 8\n8 7 6 5 4 3 2 1\n") == "1", "strictly decreasing"

 ## 边缘情况

 关键的边缘情况是所需值多次出现，但只有后面的值允许继续。 例如，在 1 2 1 2 3 中，从第一个 2 开始可能会导致死胡同，而从第二个 2 开始则可以达到 3。该算法会处理此问题，因为每次出现都被视为起点，并且二分查找始终选择当前位置之后第一个有效的下一个出现。 

另一种情况是序列中间缺少值。 如果 1 和 3 存在，但 2 不存在，则无法形成比 1 长的链。 在这种情况下，2 的位置列表为空，算法立即停止扩展，从而正确防止通过间隙的错误链接。 

最后一个微妙的情况是按顺序聚集的重复值，例如 1 1 1 2 2 3。该算法始终在索引空间中向前跳跃，因此它避免重复使用早期的重复项，并且仍然找到长度为 3 的最大可实现链 1 → 2 → 3。
