 ## 解决方案
 ## 问题理解

 我们得到一个大小为 n × m 的网格，其中每个单元格包含一个字母或一个点，表示一个空单元格。 在这个网格上，我们想要确定给定的单词 s 是否已经作为有效的“蛇”路径出现。 

有效的外观意味着我们可以选择一个起始单元格，然后在四个基本方向上逐步移动，以便每一步都到达相邻的单元格，我们永远不会重复使用单元格，并且访问单元格的顺序完全按顺序拼出 s 。 只有已经包含字母的单元格才可用，并且每个访问的单元格中的字母必须与 s 的相应字符匹配。 

单词 s 还有一个附加属性，即它的所有字符都是不同的。 此限制至关重要，因为它将任何成功路径的长度限制为最多 26 个，并且它可以防止重新访问单词中的相同字母位置，尽管除非我们强制执行路径规则，否则它不会直接阻止重新访问网格单元。 

网格本身的总大小可能很大，最多可达 10^6 个单元格，因此任何尝试在网格结构上以朴素 DFS 方式搜索所有路径的解决方案都有可能探索指数数量的路径，并且无法及时完成。 

经常打破简单解决方案的一个微妙点是分支和路径有效性之间的相互作用。 即使单词很短，单个字符也可能出现在网格中的多个位置，并且从每次出现的天真回溯可以重复探索重叠区域。 另一种常见的故障模式是忘记“禁止重复使用单元”约束，如果没有正确跟踪，可能会意外地允许无效周期。 

例如，如果网格是一个大的开放区域，填充了与 s 的转换相匹配的相同字母分布，则简单的 DFS 可能会通过不同的路径重新访问同一区域，并以组合方式爆炸，即使单词长度很小。 

因此，任务不是在网格中任意搜索，而是有效检查是否存在有效的位置链（s 的每个字符一个），使得连续位置在网格中相邻。 

## 方法

 最直接的想法是从第一个字符的每次出现开始，执行 DFS 或 BFS 尝试逐步构建单词。 从每个当前单元格，我们探索其四个邻居，如果下一个字符匹配则继续。 

这在逻辑上是正确的，因为它枚举了拼写该单词的所有可能路径。 然而，其复杂性取决于每一步的分支选择数量。 在密集网格中，每个步骤可能分支到四个方向，并且多个起始位置可以倍增搜索空间。 即使单词长度最多为 26，搜索树仍然可以扩展到非常大量的部分路径，特别是当许多网格单元匹配中间字符时。 

简化问题的关键观察是字长非常小，而网格很大。 我们可以考虑逐层传播，而不是考虑任意路径探索。 单词中的每个字符位置形成一个层，我们只需要知道哪些网格单元可以在某些有效的部分路径中表示该位置。 

我们从与第一个字符匹配的所有单元格开始。 然后，对于每个下一个字符，我们计算与前一层中至少一个可到达单元相邻并包含所需字符的所有网格单元。 由于每个单元转换都是局部的并且每层仅检查一次，因此该过程在每层网格单元的数量上保持线性。 

这将问题转化为最多 26 层的受控动态传播，完全避免了指数分支。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | DFS 从始至终 | 最坏情况下呈指数 | O(k) 递归 | 太慢了|
 | 分层传播 DP | O(nm·|s|)|

 ## 算法演练

 1. 读取网格并找到与单词的第一个字符匹配的所有单元格。 这些形成了初始的一组可到达位置，因为任何有效路径都必须从其中一个开始。 
2. 维护一个布尔网格或访问标记，用于跟踪在当前字符索引处可以访问哪些单元格。 这可以防止在一层内重复处理同一单元。 
3. 对于单词中的每个下一个字符，通过扫描所有当前可到达的单元格并检查其四个邻居来构建一组新的可到达位置。 如果邻居包含所需的下一个字符，则它在下一层中变得可达。 
4. 用新构造的集合替换当前可达集合，并继续处理下一个字符。 
5. 如果在任何阶段可达集变空，则该单词无法形成有效路径，我们会提前停止。 
6. 处理完所有字符后，如果最后一个字符至少有一个单元格可达，则该单词存在于棋盘上。 

### 为什么它有效

 该算法保持了这样一个不变式：在处理单词的第 i 个字符后，活动单元格的集合完全对应于拼写前缀 s[0..i] 的有效路径的所有端点。 每个转换步骤仅将有效路径扩展一个与下一个字符匹配的邻接移动。 由于每条有效路径都必须通过相邻步骤逐步构建，并且我们永远不会丢弃任何有效扩展，因此不会丢失任何解决方案。 同时，每个记录的状态都对应一个真实的路径段，因此不会引入无效路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    s = input().strip()
    k = len(s)

    # current reachable cells
    cur = set()

    # initialize with positions of first character
    for i in range(n):
        row = grid[i]
        for j in range(m):
            if row[j] == s[0]:
                cur.add((i, j))

    if not cur:
        print("NO")
        return

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for idx in range(1, k):
        nxt_char = s[idx]
        nxt = set()

        for x, y in cur:
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if 0 <= nx < n and 0 <= ny < m:
                    if grid[nx][ny] == nxt_char:
                        nxt.add((nx, ny))

        cur = nxt
        if not cur:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```实现直接遵循分层传播思想。 初始扫描收集所有有效的起点。 每次迭代仅通过有效的网格邻接扩展来向前推进一个字符。 使用集合可确保每个单元每层最多处理一次，从而防止多条路径到达同一位置时出现冗余传播。 

关键的实现细节是我们从不尝试跟踪完整路径。 我们只跟踪每个前缀长度的可达端点，这已经足够了，因为单词本身唯一地确定了所需字符的序列。

 ## 边缘情况

 当第一个字符在网格中多次出现但这些出现都不能真正连接到第二个字符时，就会出现临界边缘情况。 该算法自然地处理这个问题，因为初始集可能很大，但第一个传播步骤立即根据邻接性对其进行过滤，从而在一次迭代中折叠边界。 

另一种情况是字符出现在形成循环的簇中。 即使许多路径在本地循环，基于集合的传播也可以防止同一层内的重复扩展，因此循环不会使状态空间膨胀。 

最后，当单词长度为 1 时，当且仅当该字符存在于网格中的任何位置时，算法才会正确返回 YES，因为初始集合本身已经是最终答案。
