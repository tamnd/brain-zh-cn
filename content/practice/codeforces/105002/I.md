 ## 解决方案
 ## 问题理解

 每个测试用例都会给出一个单词，对于该单词，我们需要决定在插入一个字符后它是否可以被视为某个较短字符串的“扩展”版本。 

更准确地说，我们正在寻找一个字符串`t`这样如果我们在任意位置插入一个字符`t`，我们得到给定的单词`s`。 在所有可能的方法中删除一个字符`s`，我们需要至少一个删除位置，在该位置，通过以相同的方式删除任何其他位置都无法生成结果较短的字符串。 如果存在这样的位置，我们输出结果字符串； 否则我们输出`-1`。 

输入的字数非常小，最多十个，但每个字可以很长，最多十万个字符。 这种不平衡很重要：任何试图重新计算每个字长的二次方的解决方案都会立即失败，而每个字的线性扫描就足够了。 

当单词仅包含重复字符时，会出现微妙的失败情况。 例如，考虑`"aaaa"`。 删除任何一个位置总是会产生`"aaa"`，但是有多个有效的删除位置会产生相同的结果，因此“插入位置”不会是唯一的。 在这种情况下，正确答案是`-1`，即使存在更短的字符串。 

另一个边缘情况是这样的词`"abca"`。 删除第一个`'a'`和最后一个`'a'`两者都产生`"bca"`，因此结果是不明确且无效的。 简单地删除任何位置的幼稚方法会错误地接受此类情况。 

## 方法

 思考该问题的直接方法是尝试单词中每个可能的位置，删除该字符，并将结果视为候选任务字符串。 原则上这是正确的：每个有效的任务字符串都必须来自恰好删除一个字符。 

然而，仅有正确性是不够的；还需要正确性。 我们还需要删除是唯一的。 如果两个不同的位置产生相同的缩短的字符串，则将删除的字符插入回该字符串将无法确定唯一的位置，这违反了要求。 

直接的暴力实现将为每个索引构造缩短的字符串并将其与所有其他删除进行比较以确保唯一性。 这导致$O(n^2)$每个单词的构造，因为每次删除都会创建一个新的长度字符串$O(n)$，并且比较也$O(n)$。 字长可达$10^5$，这种方法变得完全不可行。 

关键的观察是，只有当删除的字符相同并且所有周围结构都相同时，两个不同的删除位置才能产生相同的结果，这只有当删除的字符在单词中多次出现时才有可能。 这将唯一性条件简化为简单的频率检查：当且仅当该位置处的字符在整个单词中恰好出现一次时，删除位置才有效。 

这将问题从组合搜索转变为每个单词的单一频率扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个单词的最坏情况为 O(n³) | O(n) | 太慢了|
 | 基于频率的扫描 | 每个单词 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个单词。 

1. 统计单词中每个字符的出现频率。 这告诉我们哪些字符是独特的，哪些是重复的。 我们首先这样做的原因是删除的唯一性完全取决于它的字符是否可以与其他地方的另一个相同字符匹配。 
2. 从左到右扫描单词，查找该字符在整个字符串中恰好出现一次的位置。 这个位置是安全的，因为没有其他删除可以删除相同的字符并产生相同的结果。 
3. 如果找到这样的位置，则通过删除该字符来构造答案字符串并立即输出。 我们可以提前停止，因为任何有效的任务字符串都是可接受的，并且该问题不需要按字典顺序排列的最小或最大结果。 
4. 如果扫描完成后没有找到唯一出现的字符，则输出`-1`。 这意味着单词中的每个字符至少出现两次，因此每个可能的删除都是不明确的。 

正确性背后的核心思想是删除出现过一次的字符会在结果字符串和原始位置之间创建一对一的映射。 没有其他索引可以生成相同的缩短字符串，因为单词中的其他位置不存在其他相同的字符。 相反，如果每个字符出现多次，任何删除都可以镜像到具有相同字符的另一个位置，从而破坏唯一性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    if not s:
        return

    from collections import Counter
    cnt = Counter(s)

    for i, ch in enumerate(s):
        if cnt[ch] == 1:
            print(s[:i] + s[i+1:])
            return

    print(-1)

if __name__ == "__main__":
    solve()
```实施直接遵循频率优先策略。 这`Counter`计算线性时间内的字符频率。 然后扫描检查每个位置并立即输出第一个有效删除。 

一个常见的实现陷阱是尝试通过实际构造所有可能的删除并比较字符串来验证唯一性，这会悄悄地变成二次的。 另一个错误是只检查局部条件，例如相邻字符是否不同，这与全局唯一性要求无关。 

## 工作示例

 考虑输入单词`"junior"`。

 第一个角色已经可以工作了，因为它是独一无二的。 结果字符串立即被接受，确认唯一性仅取决于全局频率，而不取决于位置。 

现在考虑`"tracktor"`。 

| 步骤| 索引 | 人物 | 频率| 行动| 结果 |

 这里是角色`'a'`是唯一的，因此删除它会产生有效的任务字符串。 尽管其他角色重复，但只有独特的角色才重要。

## 测试用例```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    n = int(input())
    for _ in range(n):
        s = input().strip()
        cnt = Counter(s)
        ans = -1
        for i, ch in enumerate(s):
            if cnt[ch] == 1:
                ans = s[:i] + s[i+1:]
                break
        out.append(str(ans))
    return "\n".join(out)

# provided sample
assert run("4\naaab\nzzz\njunior\ntracktor\n") == "-1\n-1\nunior\ntrcktor"

# all equal characters
assert run("1\naaaa\n") == "-1"

# single unique middle character
assert run("1\naabaaa\n") == "aabaaa".replace("b","")

# unique only at end
assert run("1\nxxxy\n") == "xxx"

# already valid mixed
assert run("1\nabca\n") == "-1"

 ## 边缘情况

 所有字符都相同的单词，例如`"bbbbbb"`，证明任何天真的删除策略都是失败的。 每次删除都会产生`"bbbbb"`，但每个结果可以从多个位置获得，因此不存在有效的任务字符串，并且输出必须是`-1`。 

用一句话来说就是`"abca"`，删除任一`'a'`产生相同的缩短字符串`"bca"`。 即使存在较短的字符串，它也不对应于唯一的插入位置，因此算法正确地拒绝它，因为没有字符的频率恰好为 1。
