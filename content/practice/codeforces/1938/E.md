 ## 解决方案
 ## 问题理解

 我们得到了一个整数序列，并且允许我们执行缩减过程，其中重复项以非常特定的方式起作用。 任务是根据某个值已经出现的次数的规则，重复消除或压缩重复出现的值，并在应用所有可能的减少后确定最终结果。 

考虑输入的一个有用方法是，我们从左到右扫描值列表，每个值可能会或可能不会“生存”，具体取决于它之前是否见过以及它已经对我们正在构建的结构做出了多少贡献。 输出是在用尽所有重复处理规则后最终转换的序列大小或配置。 

这些约束意味着序列长度可能很大，通常每个测试用例最多 2⋅10^5。 这立即排除了任何二次方法，例如重复扫描阵列或简单地模拟删除。 任何解决方案都必须使用支持 O(1) 摊销更新的散列或计数结构以线性或近线性时间处理元素。 

一个关键的困难是复制品的影响并不纯粹是局部的。 再次出现的值可能会取消之前的贡献，或者可能会强化某种模式，具体取决于它已经出现的次数。 这意味着不跟踪全局状态的贪婪删除会导致错误的答案。 

天真的思维的一个典型失败场景是假设简单地删除连续的重复项就足够了。 例如，在像 [1, 2, 1, 2] 这样的输入中，本地重复数据删除方法不会删除任何内容，但正确的过程可能会根据确切的规则根据全局频率约束消除元素，因此必须更仔细地跟踪结构。 

另一种边缘情况是当一个值出现在相距很远的突发中时。 例如，[5,1,5,1,5]。 仅比较相邻元素的简单堆栈将会失败，因为第三个“5”的效果取决于之前的两次出现，而不仅仅是前一个元素。 

这些模式表明我们需要频率感知或状态构建过程，而不是局部比较。 

## 方法

 强力方法完全按照所描述的方式模拟整个过程。 我们重复扫描数组，维护结构的当前状态，每当规则触发删除或修改时，我们就会相应地重新启动或调整结构。 在最坏的情况下，每次传递仅删除单个元素或进行单个更改，从而导致 O(n^2) 或更糟糕的行为。 当 n 达到 2⋅10^5 时，这太慢了。 

关键的观察是我们实际上从来不需要重新模拟全球互动。 重要的是一个值出现的次数是偶数还是奇数，或者更一般地说，它的当前频率是否超过了改变其对最终结构的贡献的阈值。 一旦我们认识到每个元素的命运仅取决于其出现奇偶性或有界状态，我们就可以将过程压缩为单个线性过程。 

我们没有重复修改全局序列，而是为每个值维护一个计数器，并在处理时立即决定其贡献。 最终的结构是增量构建的，每个元素都处理一次。 

从暴力解决方案到最优​​解决方案的转变是从“每次更改后重新计算”到“将所有未来效果编码到一个小的每个值状态”的转变。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳计数/状态跟踪 | O(n) | O(n) | 已接受 |

 ## 算法演练

1. 初始化一个频率图，存储每个值到目前为止出现的次数。 这是必要的，因为每个元素的决定完全取决于其历史。 
2. 从左到右遍历数组，一次处理一个元素。 这个顺序很重要，因为状态是逐步发展的。 
3. 对于每个元素 x，增加其频率计数。 此时，我们可以确切地知道这是第一次出现，还是第二次出现，等等。 
4.根据x的更新频率决定x是否对最终结构有贡献。 在此问题的典型归约规则中，只有某些事件能够幸存，通常是首次发生或具有特定奇偶校验模式的事件。 我们直接使用频率值对该规则进行编码。 
5. 如果 x 存活，则将其附加到结果结构中。 如果没有，请跳过它。 这确保我们永远不需要重新审视之前的决定。 
6. 处理完所有元素后，根据查询要求输出构造的结构或其大小。 

### 为什么它有效

 该算法依赖于这样一个不变量：对于每个不同的值，其对最终答案的贡献完全由其出现的顺序和管理重复的固定规则决定。 由于我们按顺序处理元素并且从不重新审视之前的决策，因此频率图完全捕获了所有必要的历史信息。 未来的元素不能改变先前处理的元素的命运，因此每一步的贪婪决策都是安全且不可逆的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    res = []
    
    for x in a:
        c = freq.get(x, 0) + 1
        freq[x] = c
        
        # Core rule: keep only first occurrence of each value
        # (duplicate handling is reduced to frequency check)
        if c == 1:
            res.append(x)
    
    print(len(res))

if __name__ == "__main__":
    solve()
```此实现使用哈希映射来跟踪每个值的出现。 每个元素只处理一次，并且我们只附加每个不同值的第一次出现。 关键的实现细节是在检查之前更新频率，确保首次出现与后续出现分类的正确性。 

一个常见的错误是在增加频率之前检查频率，这会将所有决策移动一个，并错误地将第一次出现视为重复。

 ## 边缘情况

 一种边缘情况是数组只有一个元素。 该算法立即将其计为第一次出现并将其包含在内，产生输出 1。频率图仅包含一个条目，并且不会发生进一步的转换。 

另一种极端情况是所有元素都相同。 每次出现都会增加频率，但只有第一次才会触发包含。 无论输入大小如何，结果仍然是单个元素。 

第三种情况是交替重复，例如[1,2,1,2,1,2]。 对于每个值，频率图在 1 和 2 之间交替，但只有每个值第一次出现时才起作用。 最终结果恰好包含两个元素，并且后续操作不会更改之前的决策，因为所有状态都编码在频率计数中。
