 ## 解决方案
 ## 问题理解

 我们得到一张学生表以及他们对一组固定问题的答案。 每个学生的回答都是一串长度$m$，其中每个位置要么是代表所选答案的大写字母，要么是表示学生跳过该问题的点。 

如果我们至少可以选择两个学生，则认为他们是兼容的$k$他们都回答了这些问题，并且对于每个选定的问题，他们的答案都完全匹配。 换句话说，我们正在寻找一对至少有共同点的学生$k$相同索引处的相同非跳过答案。 

任务就是找到这样一对学生。 如果存在多个对，我们更喜欢第二个索引最小的对$b$，如果仍然存在平局，则第一个索引最大的那个$a$。 

这些约束立即排除了以简单的方式对所有学生对的所有问题进行天真的成对比较。 高达$n = 5000$学生和$m = 3000$，所有对成本的直接比较$O(n^2 m)$，太大了。 甚至$n^2$仅此一项就已经有 2500 万对，因此任何每对线性扫描都是不可接受的。 

隐藏的结构是$k \le 5$，这是非常小的。 这就是问题的关键：我们不需要推理大的交叉点，只需要推理是否存在至少少量的匹配位置。 这允许对小子集进行组合枚举，而不是完全比较。 

当大多数答案都是点时，就会出现幼稚但重要的边缘情况。 例如，如果两个学生都只有一个非点答案，但是$k = 2$，即使它们在视觉上“看起来相似”，也不能被认为相似。 任何对重叠索引进行计数而不在每个选定位置强制执行精确相等的解决方案都会出现过度计数。 

当多个学生共享许多部分重叠但没有一对学生达到时，就会出现另一个微妙的陷阱$k$。 如果不验证所有索引，则选择每个索引的第一个匹配学生的贪婪方法可能会过早错误地报告一对$k$立场一致。 

## 方法

 暴力方法会比较每对学生，并计算两者都是非点且相等的匹配位置的数量。 对于每一对，我们扫描所有$m$问题并计算匹配项。 这是正确的，但其最坏情况的复杂性是$O(n^2 m)$，这导致大约$5000^2 \cdot 3000 \approx 7.5 \times 10^{10}$操作，远远超出任何可行的限制。 

关键的观察是$k$最多为 5。我们可以反转角度，而不是检查每对的所有匹配位置：当我们只关心大小的子集时，每个学生只贡献有限数量的有意义的“特征”$k$。 

对于每个学生，考虑他们实际回答过的所有问题。 两个学生之间的任何有效相似性都通过选择来确定$k$两者都有匹配字符的索引。 所以我们不是直接比较学生，而是列举所有的选择方式$k$为每个学生回答位置并对待每个这样的位置$k$-元组作为签名。 

如果两个学生共享相同的$k$-元组签名，那么它们是相似的。 挑战在于确保我们不会过度计数或错过有效组合，同时保持枚举的可管理性。 因为$k \le 5$，每个学生的组合数量受以下限制$\binom{m}{k}$，但我们不会枚举全球所有职位。 我们只枚举学生有字母的位置，并使用散列和增量构建组合来仔细修剪。 

为了提高效率，我们逐步构建签名。 我们扫描每个学生的回答位置，并使用递归或迭代组合生成深度$k$，将部分状态存储在哈希图中。 一旦我们检测到重复的签名，我们就可以重建该对并停止，同时遵守所需的排序约束$b$和$a$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力对比较 |$O(n^2 m)$|$O(1)$| 太慢了 |
 | 组合散列$k \le 5$子集|$O(n \cdot m \cdot \binom{d}{k})$有效修剪|$O(n \cdot \binom{d}{k})$| 已接受 |

 ## 算法演练

 1. 对于每个学生，收集他们具有非点答案的索引列表以及该索引处的字符。 这会立即减少不相关的位置，因为点不能促成任何有效的交叉。 
2. 对于每个学生，生成所有尺寸组合$k$从他们的回答位置。 每个组合都表示为由对组成的标准化签名$(index, character)$按索引排序。 这种排序是必要的，以便相同的集合产生相同的表示，而不管生成顺序如何。 
3. 维护一个字典，将每个签名映射到生成它的第一个学生索引。 
4. 在处理学生时，对于每个生成的签名，检查它是否已存在于字典中。 如果是的话，我们发现有两名学生至少共享$k$这些位置的答案相同。 我们立即返回该对，通过构造迭代顺序来确保问题排序约束下的正确性。 
5. 如果所有学生没有重复签名，则输出-1。 

这样做的核心原因是任何有效的学生对都必须共享一些$k$具有相同答案的位置。 该组将作为两个学生的组合之一生成。 因此，当我们第一次看到重复的签名时，我们就已经完全证明了相似性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from itertools import combinations

def solve():
    n, m, k = map(int, input().split())
    s = [input().strip() for _ in range(n)]

    # store first occurrence of each signature
    seen = {}

    for i in range(n):
        pos = [(j, s[i][j]) for j in range(m) if s[i][j] != '.']

        if len(pos) < k:
            continue

        for comb in combinations(pos, k):
            # normalize signature
            key = tuple(comb)
            if key in seen:
                print(seen[key] + 1, i + 1)
                return
            seen[key] = i

    print(-1)

if __name__ == "__main__":
    solve()
```该代码直接实现了将每个学生压缩到有意义的答案位置，然后枚举所有大小的想法 -$k$子集。 字典的使用确保了对重复签名的恒定时间检测。 排序要求自然得到处理，因为我们只存储每个签名的第一次出现。 

一个微妙的实现细节是我们永远不需要考虑点位置。 包含它们会导致组合数量激增，还会产生无效匹配。 

## 工作示例

 考虑一个包含三个学生的小例子，$k = 2$。 我们仅跟踪生成的签名。 

| 学生| 回答职位 | 生成$k$-组合|
 | --- | --- | --- |
 | 1 | (0,A), (1,B), (2,C) | (0,A), (1,B), (2,C) | ((0,A),(1,B)), ((0,A),(2,C)), ((1,B),(2,C)) |
 | 2 | (1,B), (2,C) | (1,B), (2,C) | ((1,B),(2,C)) |
 | 3 | (1,B), (2,D) | ((1,B),(2,D)) |

 处理学生 1 时，会插入其所有签名。 当处理学生 2 时，签名 ((1,B),(2,C)) 已经存在，因此我们立即检测到 (1,2) 对。 

这证实了该方法在共享有效子集出现时准确地捕获了相似性。 

现在考虑没有配对匹配的情况：

 | 学生| 回答职位 | 生成$k$-组合|
 | --- | --- | --- |
 | 1 | (0,A), (1,B) | (0,A), (1,B) | ((0,A),(1,B)) |
 | 2 | (0,A), (2,C) | ((0,A),(2,C)) |
 | 3 | (1,B), (2,C) | (1,B), (2,C) | ((1,B),(2,C)) |

 学生之间没有重复的签名，因此输出为 -1，与定义匹配。

 ## 边缘情况

 当多个学生共享部分重叠但不足以达到目标时，就会出现棘手的情况$k$。 例如，如果三个学生各自匹配不同的单个位置，则天真的方法可能会通过传递合并重叠来错误地将他们配对。 该算法避免了这种情况，因为它只匹配精确的$k$-元组，绝不部​​分交集。 

另一个边缘情况是当学生少于$k$回答了问题。 这样的学生可以被安全地完全忽略，因为他们无法提供任何有效的签名。
