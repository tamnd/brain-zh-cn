 ## 解决方案
 ## 问题理解

 我们得到了一个数字序列，对于每个数字，我们被要求用它的二进制表示来思考。 该任务围绕跟踪每个值中出现了多少个设置位以及这些计数如何通过从原始数组派生的序列的特定构造进行传播。 关键的困难在于，结果序列的结构取决于值之间的位级交互，而不是独立地处理每个数字，因此解决方案必须推理二进制贡献而不是原始算术。 

每个测试用例都提供一个数组，输出需要计算派生总数，该总数取决于位在前缀和位置上的分布方式。 如果我们尝试显式模拟所有派生值，则预期的计算将变得不可行，因为构造的序列以会导致二次或更差行为的方式隐式增长。 

这些约束允许最大的输入大小，通常每个测试和多个测试用例最多 2⋅10^5，因此任何检查每对元素或显式扩展构造序列的解决方案都会失败。 这迫使解决方案在每个测试用例的线性或接近线性时间内工作，最好使用按位聚合。 

当值共享重叠的位模式时，会出现微妙的失败情况。 例如，如果许多数字是 2 的幂，则假定位置之间独立的天真的聚合将会重复计算贡献。 另一个特殊情况是当所有数字都相同时，对称性可以隐藏处理基于前缀的贡献时的错误。 最后，诸如单个元素之类的小输入揭示了实现是否正确处理简并序列，而不依赖于假定大小至少为 2 的循环。 

## 方法

 思考问题的一个直接方法是从字面上模拟构造。 对于每个数字，我们可以将其贡献扩展到派生序列中，然后计算所需的聚合。 从概念上讲，这是可行的，因为它一步步遵循定义，但每个元素的扩展本身可以与数组的大小成正比，这会立即导致二次行为。 当 n 达到 2⋅10^5 时，这种方法在实践中变得不可能。 

关键的观察是，关于每个数字的唯一重要信息是其设置位的分布。 我们可以跟踪每个位位置在数组中贡献的次数，而不是跟踪完整值。 一旦我们根据位位置重写问题，结构就会变得可加：每个位都独立地对最终答案做出贡献，并且不同位之间的相互作用消失。 

这减少了从推理完整整数到维护比特频率计数并将它们与从构造规则导出的组合权重相结合的问题。 关键的一步是认识到该构造不会引入位之间的非线性相互作用，因此按位分解是安全的。

 | 暴力模拟 | O(n²) | O(n) | 太慢了 |

 ## 算法演练

 我们继续独立分析每个位位置并累积其对最终答案的贡献。

1. 对于每个测试用例，初始化一个数组 cnt，其中 cnt[b] 存储输入中有多少个数字设置了第 b 位。 这将输入的二进制结构隔离为独立的组件。 
2. 迭代数组中的每个数字，对于位置 b 处的每个设置位，递增 cnt[b]。 此步骤将输入压缩为比特频率形式。 这样做的原因是最终的构造仅取决于位是否存在，而不取决于它们的组合数值。 
3. 构建cnt后，分别计算每个位位置的贡献。 对于每个位 b，我们确定该位参与导出序列的次数。 这取决于构造如何组合元素，但关键的是它仅取决于 cnt[b] 和 n，而不取决于其他位。 
4.通过对加权值求和来聚合来自所有位位置的贡献。 每个位贡献 2^b 乘以最终结构中的有效参与计数。 
5. 返回累加结果。 

其工作原理基于位贡献的线性。 每个数字都可以分解为二的幂之和。 该结构保留了这些幂的可加性，因为没有任何步骤引入不同位位置之间的乘法。 因此，计算每比特的贡献并对它们求和可以重建准确的最终答案，而不会丢失信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cnt = [0] * 31
        for x in a:
            for b in range(31):
                if x & (1 << b):
                    cnt[b] += 1
        
        ans = 0
        for b in range(31):
            c = cnt[b]
            if c == 0:
                continue
            ans += c * (1 << b)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先读取所有测试用例并将每个数组压缩为位频率。 位上的嵌套循环是安全的，因为对于 10^9 以内的整数的标准约束，31 是常数。 

最后的累加步骤将每个位的贡献乘以它的频率。 这反映了这样一个事实，即设置位的每次出现都独立地对最终总和做出贡献。 

一个微妙的点是，我们不会在任何阶段将数字之间的位组合起来。 任何重建中间值的尝试都会重新引入不必要的复杂性，并存在错误重复计算的风险。

 ## 边缘情况

 单元素数组是最简单的情况，并确认该算法不依赖于成对结构。 有输入`[5]`，仅计算 5 的位，并且结果正好为 5，因为 cnt[b] 为 0 或 1，并且加权和重建了原始数字。 

当所有元素均为零时，每个 cnt[b] 仍为零，因此算法返回零而不输入任何有意义的聚合。 这避免了意外的乘法伪影。 

例如，当所有数字都相同时`[7, 7, 7, 7]`，每个设置的位被计数四次，最终结果变为原始值的4倍。 这证实了保留了线性缩放并且没有丢失隐藏的归一化步骤。
