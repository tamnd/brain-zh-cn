 ## 解决方案
 ## 问题理解

 我们被要求计算给定范围内有多少个整数$[l, r]$满足基于数字的递归约束。 如果从十进制表示开始，前两位之后的每个数字完全由前两位数字使用下一位数字等于前两位数字之和模 10 的规则确定，则该数字被称为有效数字。 

这意味着一旦您修复了数字的前两位数字，整个数字序列就会被强制。 例如，选择前导数字$1$和$2$强制下一个数字为$3$， 然后$5$， 然后$8$，依此类推，以 10 为模进行循环。在任何位置任何偏离此规则的情况都会导致该数字不合格。 

此外，从 1 到 99 的每个数字都自动有效，因为在第三位数字之前没有任何可以违反的限制。 

任务是有效地回答许多查询，其中每个查询询问一个大区间内有多少个有效数字。 界限上升到$10^{18}$，所以我们不能单独检查每个数字。 有效数字的结构仅取决于数字转换，这表明问题从根本上讲是关于数字动态而不是数字本身的算术属性。 

关键的约束含义是任何按号码检查的方法都是不可能的。 即使通过模拟数字来检查单个数字也很好，但对某个范围内的所有数字执行此操作就太慢了。 最多约$7 \cdot 10^5$查询，我们大致需要$O(1)$或者$O(\log N)$预处理后按查询分摊。 

一个微妙的边缘情况是小数字的处理。 从 1 到 99 的所有数字始终有效，即使它们违反了严格意义上的递归思想。 例如，根据定义，47 是有效的，无论递归是否一致延伸。 任何忘记此异常的解决方案都会低估小范围，例如$[1, 50]$。 

当一个数字满足局部递归但全局失败时，就会出现另一种边缘情况。 例如，2169 是无效的，因为在某些时候规则被打破：数字 9 不等于$(1+6) \bmod 10 = 7$。 这表明仅检查部分一致性是不够的； 整个数字链必须遵守该规则。 

## 方法

 暴力方法会检查中的每个数字$[l, r]$，转为字符串，逐位验证递归条件。 这可以正常工作，因为它直接强制执行定义。 然而，最坏情况的间隔长度可以是$10^{18}$，甚至使单个查询变得不可行，并且对于数十万个查询，这会变得非常慢。 

关键的观察是有效数字完全由其前两位数字及其长度决定。 一旦选择了前两位数字，剩下的数字就会确定地生成。 这将问题从检查所有整数转变为计算有效数字序列。 

因此，我们可以预先计算长度不超过 18 的所有有效序列（因为数字可达$10^{18}$）。 每个序列都是通过选择从 00 到 99 的前两位数字，然后重复应用递归来生成完整数字而形成的。 这给出了一组固定的有限有效数字。 

生成此列表后，我们对其进行排序。 每个查询$[l, r]$然后可以通过二分查找来回答有多少预先计算的值落在该区间内。 

从蛮力到最优解决方案的转变本质上是认识到约束定义了数字上的确定性自动机，产生有限的可预计算集而不是隐含的无限条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O((r-l+1) \cdot d)$|$O(1)$| 太慢了 |
 | 预计算 + 二分查找 |$O(100 \cdot 18 + t \log N)$|$O(100 \cdot 18)$| 已接受 |

 ## 算法演练

 1. 枚举从 00 到 99 的每一个可能的起始数字对。每对代表候选序列的前两位数字。 这已经足够了，因为递归修复了接下来的一切。 
2. 对于每个起始对，模拟最多 18 个步骤的数字生成。 在每一步中，附加$(a + b) \bmod 10$到序列，其中$a$和$b$是最后两位数字。 我们停在 18 位数字，因为任何在限制范围内的有效数字都不能超过这个长度。 
3. 将生成的每个数字序列转换为整数，并将其存储在全局列表中。 该列表代表了定义下所有可能的有效“dibonacci”数字。 
4. 对列表进行排序。 排序是必需的，因为查询将使用二分搜索来回答，这需要有序的结构。 
5. 对于每个查询$[l, r]$，计算小于或等于的有效值的数量$r$，并减去严格小于的有效值的数量$l$。 这个差异给出了区间的答案。 

步骤 2 背后的主要原因是递归是确定性的，因此在固定前两位数字后不存在分支。 这会将指数搜索空间折叠成恒定数量的生成序列。 

### 为什么它有效

 每个有效数字都唯一对应于其前两位数字。 从这一点开始，每个数字都受到递归规则的强制，因此每个起始对恰好有一个延续。 由于最大长度受到输入约束的限制，因此通过枚举所有起始对并生成其完整序列来覆盖所有可能的有效数字。 这保证了完整性，没有超出相同数值的重复，这些重复在排序后自然处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

vals = []

def build():
    for a in range(10):
        for b in range(10):
            digits = [a, b]
            for _ in range(2, 18):
                digits.append((digits[-1] + digits[-2]) % 10)

            # convert to number, skip leading zeros entirely
            for i in range(len(digits)):
                if digits[i] != 0:
                    break
            else:
                continue

            num = 0
            for x in digits[i:]:
                num = num * 10 + x
            vals.append(num)

build()
vals.sort()

def count_le(x):
    lo, hi = 0, len(vals)
    while lo < hi:
        mid = (lo + hi) // 2
        if vals[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    print(count_le(r) - count_le(l - 1))
```预处理步骤通过仅暴力破解数字对来构建所有候选数字，这是可行的，因为只有 100 个起始状态，并且每个状态都会生成一个固定长度的序列。 转换步骤会小心地跳过前导零，以便将 000123 这样的数字视为 123，而不是无效表示。 

二分查找函数`count_le`是核心查询引擎。 它返回最多有多少个预先计算的值是给定阈值，从而启用每个查询的对数时间范围计数。 

一个微妙的实现细节是处理前导零。 如果序列以零开头，则有效数字可能更短，并且未能跳过它们会人为地夸大存储的值或创建与不同整数不对应的重复项。

 ## 边缘情况

 一种边缘情况是当范围完全在$[1, 99]$。 在这种情况下，根据定义，每个数字都是有效的，因此答案应该只是间隔长度。 该算法仍然有效，因为所有这些数字都出现在预先计算的列表中，因此二分搜索自然可以正确计算它们。 

另一种边缘情况是生成的序列中包含许多前导零的数字。 对于像 0, 0 这样的起始对，序列保持全零，这不能产生无效的重复项。 该实现会丢弃纯零序列并在转换前对前导零进行标准化，以确保不会插入人为值。 

最后的边缘情况是附近的大范围$10^{18}$。 例如$[10^{18}-100, 10^{18}]$。 生成的列表已包含长度不超过 18 位的所有有效序列，因此二分搜索仅正确捕获此高范围内的序列，而无需任何特殊处理。
