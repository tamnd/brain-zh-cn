 ## 解决方案
 ## 问题理解

 超级计算机可以表示以下每个整数`0`通过`2^m - 1`。 然而，这位年轻人只想与以下范围的工作`1`通过`10^k`。 我们需要最大的`k`该十进制范围内的每个数字都可以表示。 

由于年轻人使用的最大数字是`10^k`，整个范围恰好适合`10^k <= 2^m - 1`。 

所以每个测试用例给出`m`，输出为最大整数`k`满足这个不等式。 还必须打印案件编号，从`1`。 官方声明确认了最多约`10^5`测试用例与`1 <= m <= 10^5`。 

测试用例的数量足够大，解决方案的工作量与`m`对于每种情况都已经太昂贵了。 和`10^5`案例和`m`一样大`10^5`，可以到达周围`10^10`迭代。 我们需要将每个测试用例减少到恒定时间。 

有两个边界细节通常会导致错误。 首先，当`m = 1`，机器仅代表`0`和`1`， 所以`10^0 = 1`适合但是`10^1 = 10`没有。 答案是`0`， 不是`1`。```
Input:
1

Output:
Case #1: 0
```计算小数位数的粗心实现`2^m`可能会回来`1`，但机器的最大值是`2^m - 1`， 不是`2^m`。 

第二个边界是之间的严格区别`2^m`和`2^m - 1`。 为了`m = 10`，机器通过以下方式支持值`1023`。 自从`1000 <= 1023`,`k = 3`是有效的。```
Input:
10

Output:
Case #1: 3
```错误要求的解决方案`10^k < 2^m - 1`会碰巧拒绝一些精确的边界情况。 解决这个问题的简洁方法是利用两边都是整数的事实，并将条件转换为严格的不等式，其中涉及`2^m`。 

## 方法

 直接的解决方案可以尝试以下值`k`从零开始并测试是否`10^k <= 2^m - 1`。 这是正确的，因为有效值`k`形成从零开始的连续范围，因此第一个失败的值比答案大一个。 为了`m = 100000`然而，答案就在附近`30102`，所以一个测试用例需要大约`30103`候选人检查。 和`10^5`这样的情况，也就是关于`3,010,300,000`在考虑操作越来越大的整数的成本之前进行检查。 这远远超出了一秒的限制所能支持的范围。 

有用的观察是，不等式包含二和十的幂，因此对数立即消除两个指数。 开始于`10^k <= 2^m - 1`,

 我们有，因为两边都是整数，`10^k < 2^m`。 

取以 10 为底的对数可得出`k < m * log10(2)`。 

最大整数严格小于`m * log10(2)`是它的下限，前提是该值本身不是整数。 它不能是正整数`m`。 如果`m * log10(2) = r`， 然后`2^m = 10^r`， 但`10^r`包含一个因子`5`尽管`2^m`不，这是不可能的。 

因此答案的形式非常简单`answer = floor(m * log10(2))`。 

这将问题从每个测试用例可能进行数万次迭代改为一次浮点乘法和一层运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个案例 O(m) | O(1) | O(1) | 太慢了 |
 | 最佳| 每个案例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取号码`m`对于当前的测试用例。 我们只需要这个值，因为最大可用的十进制幂直接取决于机器的位宽度。 
2. 计算`m * log10(2)`。 这是通过取以 10 为底的对数获得的实​​值边界`2^m`。 
3. 取该值的下限。 自从`m * log10(2)`不能为正整数`m`，这正是最大的整数`k`满意的`k < m * log10(2)`。 
4. 使用所需的打印结果`Case #x: y`格式。 

为什么它有效可以表达为一系列等效条件。 值为`k`恰好在以下时间有效`10^k <= 2^m - 1`。 由于两个数量都是整数，因此这相当于`10^k < 2^m`。 取对数可得`k < m log10(2)`。 满足该不等式的最大整数是`floor(m log10(2))`。 代码精确计算该数量，因此每个打印的答案都是最大且有效的。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

LOG10_2 = math.log10(2.0)

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        m = int(input())
        ans = int(m * LOG10_2)
        out.append(f"Case #{case}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

`LOG10_2`计算一次而不是每个测试用例计算一次。 然后，每个测试用例仅执行一次乘法和一次整数转换，这是算法中的常数时间公式。 

转换`int(m * LOG10_2)`此处执行所需的下限，因为该值为正数。 蟒蛇的`int`向零截断，这与取正数相同。 

这`2^m - 1`边界不需要显式构造`2^m`或者`10^k`。 对数求导已经处理了该边界。 Python 整数也具有任意精度，但避免巨大的整数构造使得实现更简单、更快。 

对于给定的约束`m <= 100000`，最大的结果仅约为`30102`。 双精度的精度远高于此范围所需的精度，并且`m * log10(2)`不是任何正整数的整数`m`，因此不存在精确的整数对数边界来混淆取整操作。 

官方样本有`m = 1`生产`0`和`m = 64`生产`19`，匹配公式。

## 测试用例```python
import sys
import io
import math

LOG10_2 = math.log10(2.0)

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for case in range(1, t + 1):
        m = int(input())
        ans = int(m * LOG10_2)
        out.append(f"Case #{case}: {ans}")

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("2\n1\n64\n") == (
    "Case #1: 0\n"
    "Case #2: 19"
), "provided sample"

# Minimum input
assert run("1\n1\n") == "Case #1: 0", "m = 1"

# Boundary where 10^3 first becomes possible
assert run("2\n9\n10\n") == (
    "Case #1: 2\n"
    "Case #2: 3"
), "boundary around k = 3"

# Several equal values, checking case numbering as well
assert run("4\n10\n10\n10\n10\n") == (
    "Case #1: 3\n"
    "Case #2: 3\n"
    "Case #3: 3\n"
    "Case #4: 3"
), "repeated values"

# Maximum allowed m
assert run("1\n100000\n") == "Case #1: 30102", "maximum m"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1\n1\n`|`Case #1: 0`| 最低限度`m`和`2^m - 1`边界|
 |`2\n9\n10\n`|`Case #1: 2`,`Case #2: 3`| 相差一跃迁，其中`1000`变得有代表性|
 |`4\n10\n10\n10\n`| 四个案例及答案`3`| 重复输入和正确的案例编号 |

 ## 边缘情况

 对于`m = 1`，公式给出`floor(log10(2)) = 0`。 该算法从不尝试构造`10^1`，因此它自然可以处理尽可能小的机器。 确切的输入是`1`，输出是`Case #1: 0`。 

周围的转变`m = 10`捕获最有可能的相差一错误。 为了`m = 9`，最大机器值为`511`， 所以`100`适合但是`1000`不，给予`2`。 为了`m = 10`，最大值为`1023`， 所以`1000`适合，答案就变成了`3`。 对数值约为`2.7093`和`3.0103`，准确生产这些地板。 

对于重复值，例如四个测试用例都包含`10`，每个答案都必须是`3`，但病例数仍必须从`1`通过`4`。 由于每个输入行都是独立处理的，并且案例计数器在每次迭代时都会递增，因此该实现保留了这两个属性。 

对于最大输入`m = 100000`，公式给出`floor(100000 * log10(2)) = 30102`。 该算法不构造`2^100000`，这将是一个大整数，并且不会迭代三万个 10 的候选幂。 它执行与以下相同的恒定时间计算`m = 1`，这是解决方案扩展到整个输入范围的关键原因。
