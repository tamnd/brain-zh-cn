 ## 解决方案
 ## 问题理解

 我们从一个正整数（n>1）开始。 在一项操作中，我们均匀地随机选择其正除数之一，并用该除数替换当前数字。 当数字首先变为 (1) 时，该过程停止。 任务是找到预期的操作次数。 

输入给出 (n)、不同质因数的数量 (m) 以及这些质因数。 关键的细节是 (n) 可以大到 (10^{24})，因此将 (n) 之前的每个整数都视为一个状态是不可能的。 提供的素数因子让我们可以恢复 (n) 因式分解中每个素数的指数。 

期望值是一个有理数。 我们不打印分子和分母，而是打印分子乘以分母模 (10^9+7) 的模逆。 

原始社论推导了相同的递归，然后将状态空间从实际整数减少到素数指数的多重集。 

界限 (n\le 10^{24}) 是标准除数 DP 不够的原因。 此范围内的数字可以有超过一百万个除数，并且可以有大约 (2\times10^5) 个测试用例。 枚举每个测试用例的每个除数将需要远远超过可用时间。 不同素数因子的数量要少得多，最多为 (18)，因为前 (18) 个素数的乘积已经约为 (10^{23})。 这使得基于素数指数的状态表示变得可行。 

有几种边缘情况很容易被错误处理。 对于(n=2)，除数为(1)和(2)，可以再次选择当前状态。 期望满足

 [
 f(2)=1+\frac{f(1)+f(2)}2,
 ]

 所以 (f(2)=2)，给出`Case #1: 2`。 仅平均真除数的递归将错误地获得 (1)。 

对于 (n=4)，正确值为 (5/2)，即`500000006`模 (10^9+7)。 通过除数 (4) 的自转移必须保留在递归中。 

对于 (n=6)，正确的除数期望为 (f(1)=0)、(f(2)=2) 和 (f(3)=2)。 由于 (6) 有四个约数，

 [
 f(6)=1+\frac{0+2+2+f(6)}4=\frac83。 
]

 其模块化表示为`666666674`。 一个常见的错误是使用 (f(p)=1) 作为素数 (p)，而忘记选择 (p) 本身会创建一个自循环。 

最后，相等的指数必须被视为多重集而不是可区分的位置。 数字 (12=2^2\cdot3) 和 (18=2\cdot3^2) 具有相同的指数多重集 ({1,2})，并且它们的期望相等。 由有序素数列表键控的状态将失去这种对称性。 

## 方法

 直接方法遵循期望重现。 令 (f(n)) 表示 (n) 的预期剩余操作数，其中 (f(1)=0)。 如果 (\tau(n)) 是正除数的数量，则选择一个除数统一给出

 [
 f(n)=1+\frac1{\tau(n)}\sum_{d\mid n}f(d)。 
]

 项 (f(n)) 出现在总和中，因为选择 (d=n) 会使数字保持不变。 重新排列给出

 [
 f(n)=
 \frac{\tau(n)+\sum_{d\mid n,\ d<n}f(d)}
 {\tau(n)-1}。 
]

 暴力实现可以生成每个除数 (d\mid n)，递归计算 (f(d))，并记住结果。 这是正确的，因为每个除数恰好是一个可能的下一个状态。 问题是除数计数。 对于 (n\le10^{24})，单个数字可以有 (1,290,240) 个除数，所有相关状态的除数总数约为 (1.5\times10^{10})。 如此多的操作无法适应三秒的比赛限制。 

第一个有用的观察是实际的素数并不重要。 假设

 [
 x=\prod_i p_i^{e_i}
 ]

 和

 [
 y=\prod_i q_i^{e'_i}
 ]

 具有相同的多重指数集。 它们的除数是通过独立选择 (0) 和每个 (e_i) 之间的指数获得的。 由于每个结果除数的期望仅取决于其自身的指数多重集，因此对数字值的归纳表明 (f(x)=f(y))。 因此，状态可以仅由其正质数指数的无序多重集来表示。 

例如，(12)和(18)的指数状态都是((2,1))，因此它们共享一个记忆值。 通过将最大指数分配给最小素数，将下一个最大指数分配给下一个最小素数，依此类推，获得具有最小可能整数的代表。 这给出了规范的排序。 

我们仍然无法枚举代表的每一个约数。 第二个观察是将除数和计算为多维前缀和。 定义

 [
 h(n,k)=
 \sum_{d\mid\prod_{i=1}^k p_i^{e_i}}
 f\左(
 d\frac{n}{\prod_{i=1}^k p_i^{e_i}}
 \右）
 ]

 并令 (g(n,k)) 与限制为前缀的真约数的总和相同。 那么(h(n,k)=f(n)+g(n,k))。 

不要枚举第 (k) 个指数的所有选择，而是将它们分为使用其完整指数的情况和至少删除一个副本的情况。 后一部分正是 (n/p_k) 的部分除数和。 这给出了每个维度仅需要一个较小状态的转变。 计算结果与相关指数多重集的数量乘以不同素数的数量成正比，而不是与除数的数量成正比。 官方分析报告了 (172513) 个可能的指数多重集和 (n\le10^{24}) 的大约 (1.17) 万个状态维度转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(\sum \tau(n))) 所有状态 | (O(\text{状态数})) | 太慢了 |
 | 最佳| (O( | S | \omega(n)+T\log n)) | (O( | S | omega(n))) | 已接受 |

 这里 (S) 是可能的指数多重集的集合，(\omega(n)) 是不同质因数的数量。 每个输入数字的因式分解仅需要 (O(m\log n)) 重复除法。 

## 算法演练

1. 使用提供的不同质因数对给定 (n) 进行因式分解。 对于每个提供的素数 (p)，重复将 (n) 除以 (p) 并计算其指数。 生成的指数列表是完整的素因数分解。 
2. 按非升序对正指数进行排序。 这从状态中删除了素数的身份。 具有相同指数多重集的两个整数现在使用完全相同的 DP 状态。 
3. 将 (F(E)) 定义为指数多重集 (E) 的期望值，并将 (G(A,B)) 定义为仅改变多重集 (A) 表示的素因子而获得的所有真因数 (F) 的总和，同时多重集 (B) 保持固定。 
4. 如果(A)为空，则没有通过改变空前缀生成真除数，因此(G(\varnothing,B)=0)。 这是前缀和递归的基本情况。 
5. 从 (A) 中选择一个指数 (a)，最好是最大的指数，因为所有多重集均按规范存储。 令 (A_0) 为 (A)，并删除该指数；令 (A_1) 为 (A)，且 (a) 减一，如果指数变为零则将其删除。 
6. 根据为此特定素数选择的指数来划分约数。 如果该指数仍然等于 (a)，则除数必须在剩余前缀中正确，给出 (G(A_0,B\cup{a}))。 如果它小于 (a)，则每个结果除数都已是真值，其总和为 (F(A_1\cup B)+G(A_1,B))。 
7. 结合这两种情况：

 [
 G(A,B)=
 G(A_0,B\cup{a})
 +
 F(A_1\B杯)
 +
 G(A_1,B)。 
]

 第一个递归调用减少了活动前缀因子的数量。 第二个分支减少总指数和，因此递归是非循环的。 

1. 对于完全指数多重集 (E)，值 (G(E,\varnothing)) 恰好是 (F(d)) 在所有真因数 (d<E) 上的总和。 让

 [
 \tau(E)=\prod_{e\in E}(e+1)。 
]

 期望重现变为

 [
 F(E)=
 \frac{\tau(E)+G(E,\varnothing)}
 {\tau(E)-1}。 
]

 所有算术均以模 (10^9+7) 执行，用模逆乘法代替除法。 

1. 记住 (F(E)) 和 (G(A,B))。 由于 (F) 仅取决于排序的指数多重集，因此具有相同指数模式的所有测试用例都会立即重用结果。 (A) 和 (B) 的规范排序还合并了仅因等价素因子的排列而不同的状态。 

### 为什么它有效

 递归精确地保留了被求和的真因数集合。 对于 (G(A,B))，每个除数为可区分素数选择一个指数。 该指数要么是原始 (a)，在这种情况下，剩余的前缀本身必须是真除数，要么最多是 (a-1)，在这种情况下，除数自动是真除数。 这些情况是不相交的，并且只覆盖每个真因数一次。 递归调用会减少活动前缀因子的数量或总指数和，因此每个所需的值最终都会达到基本情况。 最后，期望方程直接根据均匀选择的除数条件得出，因此计算出的 (F(E)) 正是所需的期望值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000007

# f_cache[E] = expected value for the exponent multiset E.
# E is always a tuple sorted in non-increasing order.
f_cache = {(): 0}

# g_cache[(A, B)] = sum of F over proper divisors generated by A,
# with the exponents in B fixed.
g_cache = {}

def get_f(e):
    e = tuple(sorted((x for x in e if x), reverse=True))
    if not e:
        return 0

    cached = f_cache.get(e)
    if cached is not None:
        return cached

    proper = get_g(e, ())
    tau = 1
    for x in e:
        tau = tau * (x + 1) % MOD

    ans = (tau + proper) % MOD
    ans = ans * pow(tau - 1, MOD - 2, MOD) % MOD

    f_cache[e] = ans
    return ans

def get_g(A, B):
    A = tuple(A)
    B = tuple(B)

    key = (A, B)
    cached = g_cache.get(key)
    if cached is not None:
        return cached

    if not A:
        return 0

    # A and B are stored in non-increasing order.
    # We take the largest exponent from A.
    a = A[0]
    A0 = A[1:]

    # Case 1: the chosen prime keeps its full exponent a.
    B0 = tuple(sorted(B + (a,), reverse=True))
    part_full = get_g(A0, B0)

    # Case 2: its exponent is smaller than a.
    if a == 1:
        A1 = A0
    else:
        A1 = tuple(sorted((a - 1,) + A0, reverse=True))

    combined = tuple(sorted(A1 + B, reverse=True))
    part_reduced = (get_f(combined) + get_g(A1, B)) % MOD

    ans = (part_full + part_reduced) % MOD
    g_cache[key] = ans
    return ans

def solve_case(n, primes):
    exponents = []

    for p in primes:
        e = 0
        while n % p == 0:
            n //= p
            e += 1
        exponents.append(e)

    exponents.sort(reverse=True)
    return get_f(tuple(exponents))

def main():
    t = int(input())
    out = []

    for case_id in range(1, t + 1):
        n, m = map(int, input().split())
        primes = list(map(int, input().split()))

        ans = solve_case(n, primes)
        out.append(f"Case #{case_id}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```因式分解循环使用提供的素数而不是试除法。 由于每个提供的质数都可以除以原始 (n)，因此重复除以它可以恢复其精确的指数。 在处理完所有提供的素数后，(n) 的剩余值变为 (1)。`get_f`在查找它的参数之前将其规范化。 例如，这就是使 (12) 和 (18) 共享相同状态 ((2,1)) 的对称性约简。`get_g`实现前缀递归中的两种情况。 服用`A[0]`是安全的，因为 (A) 内的顺序无关。 修改指数后，生成的多重集在存储之前再次排序。 排序不仅仅是装饰性的，它还可以识别仅因素因数的排列而不同的状态。 

表达式为`tau`是 (\prod(e_i+1))，除数的数量。 分母是`tau - 1`因为原始状态本身对除数平均值有贡献 (f(n))。 模逆是用费马定理计算的，因为 (10^9+7) 是素数，并且该语句保证所需的分母可逆模模。 

Python 整数安全地保存输入界限 (10^{24})，因此不需要特殊的大整数表示。 每次转换后模值本身都保持在模数以下，以防止不必要的增长。 

递归是被记忆的，而不是对每个除数进行评估。 这是核心实现选择，它将实际复杂性从依赖于除数计数改为依赖于更小的指数状态空间。 状态缩减和前缀和思想与官方解决方案使用的结构简化相同。

## 边缘情况

 对于 (n=2)，指数状态为`(1)`。 真因数和为零，因为唯一的真因数是 (1)，其期望为零。 除数计数为 (2)，因此公式得出 (F=(2+0)/(2-1)=2)。 该算法立即到达空前缀并返回正确的结果。 

对于 (n=4)，指数状态为`(2)`。 递归前缀计算得到(F(1)=2)，因此(4)的真因数和为(2)。 使用三个除数 (F(4)=(3+2)/2=5/2)，产生`500000006`。 自跃迁由分母 (\tau-1) 计算。 

对于 (n=6)，指数状态为`(1,1)`。 两个素数状态都有期望(2)，真因数和为(0+2+2=4)。 由于 (\tau(6)=4)，

 [
 F(6)=\frac{4+4}{3}=\frac83,
 ]

 这变成`666666674`。 这捕获了假设素数总是进行一次操作的常见错误。 

对于 (n=12)，指数状态为`(2,1)`。 实际的质数名称在因式分解后消失，因此状态与 (18=2\cdot3^2) 相同。 因此，两个输入都会检索相同的记忆值 (91/30)，表示为`233333338`。 

对于 (n=36)，指数状态为`(2,2)`。 相等的指数保留为重复条目，而不是折叠成一个集合，因为两个素因数仍然代表两个独立的选择。 结果期望为 (147/40)，算法输出`675000013`。 

对于最大输入 (n=10^{24}=2^{24}5^{24})，指数状态很简单`(24,24)`。 Python 可以直接表示输入整数，而 DP 从不尝试为每个测试用例重复枚举其 (1,625) 个除数。 更一般地说，该算法使用指数结构，这就是 (10^{24}) 界限易于管理的原因。 官方解决方案同样将问题简化为可能的指数多重集的相对较小的集合，而不是单个整数的巨大集合。
