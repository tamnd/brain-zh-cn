 ## 解决方案
 ## 问题理解

 给定一个数组，我们可以将其切成连续的段，从左到右覆盖整个数组。 每个段都被汇总为一个值，即其元素的异或。 一旦数组被压缩为这些段异或，我们就对所有这些段值进行按位或。 任务是选择最大段数，使得最终的 OR 不超过给定的限制$x$。 如果无法进行哪怕一个有效的分割，我们会输出$-1$。 

该结构强制将数组划分为连续的块，因此真正的决定是在哪里放置切割点。 每次剪切都会改变 XOR 聚合的方式，然后这些 XOR 结果通过 OR 进行交互，这与 XOR 的行为非常不同。 XOR 是本地且可逆的，而 OR 只累积位并且从不删除它们，因此每个段都可能永远“锁定”某些位。 

约束是解决方案形状的主要信号。 总共有$n \le 10^5$在所有测试用例中，任何尝试所有分段甚至端点上的二次 DP 的方法都会失败。 每个测试用例需要线性或近线性方法，可能涉及贪婪构造或按位推理。 

一些边缘案例暴露了天真的思维的突破：

 如果所有元素都为零并且$x = 0$，每个分割都是有效的，答案应该是$n$。 任何在看到零 OR 贡献时提前停止的贪婪都会在这里失败。 

如果$x = 0$但任何数组元素都是非零的，不存在有效的分段，因为即使是覆盖整个数组的单个分段也会产生非零 XOR，这会立即违反 OR 界限。 

如果$x$由于设置位很少，如果任何段异或引入了禁止位，则即使是单个段也可能是不可能的。 仅跟踪整个数组的总异或的简单方法会错过这一点。 

关键的困难在于拆分会增加 OR，因为每个部分都是独立贡献的。 这会产生一种张力：更多的段会增加 OR 的潜力，但也可能有助于隔离位。 

## 方法

 暴力策略会尝试一切可能的方法将数组分割成段。 对于每个分区，计算每个段的 XOR，然后计算所有段结果的 OR。 这是正确的，但不可行。 数组的分区数是指数级的$n$， 具体来说$2^{n-1}$，即使有效地计算异或也不能减少组合爆炸。 

更结构化的蛮力可以修复段的数量$k$，并尝试检查可行性。 即便如此，将分割点分配给$n$位置导致$\binom{n-1}{k-1}$的可能性，在最坏的情况下仍然是指数级的。 

关键的见解是扭转观点。 我们不尝试构建段并计算 OR，而是专注于$x$。 任何段 XOR 都会为 OR 贡献位，并且一旦某个位出现在任何段 XOR 中，它就会被永久包含在内。 这意味着我们只能使用分段，其中每个分段 XOR 都是位掩码的子集$x$。 否则，OR 超过$x$。 

那么问题就变成了：将数组分割成尽可能多的段，使得每个段异或时不会引入外部的位$x$。 由于我们想要最大化段的数量，所以我们应该尽早切割，但只有当当前段异或仍然有效时$x$。 

这将问题转化为贪婪扫描：从左侧累积异或，并且每当当前前缀段异或与“兼容”时$x$，我们关闭一个段。 然而，除非我们仔细推理有效性和最大切割，否则仅靠贪婪是不够的。 

最佳方法是观察任何有效分段对应于前缀 XOR 边界序列，其中每个分段 XOR 保持在位约束内。 只要我们能够在不违反约束的情况下安全地完成一个段，就可以通过切割来实现最大段数，同时确保我们不会不必要地推迟切割。 

这将问题简化为具有正在运行的 XOR 的单遍，以及当前 XOR 是否可以被接受为段结束的条件。

 ## 算法演练

 我们在从左到右扫描数组的同时保持运行的异或。 这个正在运行的 XOR 代表当前正在构建的段的 XOR。 

1. 初始化变量`cur_xor = 0`和一个柜台`segments = 0`。 还要保留一个正在运行的 OR 累加器`or_acc = 0`。 
2. 迭代数组。 对于每个元素，更新`cur_xor ^= a[i]`。 这扩展了当前段。 
3. 更新后，检查添加该段值是否会违反约束。 仅当该段不向外部引入位时，该段才是“安全”的$x$，通过验证来检查`cur_xor | or_acc`仍≤$x$。 直觉是，完成的段 XOR 中出现的任何位都会永久地影响最终的 OR。 
4. 如果条件成立，我们完成此段：increment`segments`， 更新`or_acc |= cur_xor`，并重置`cur_xor = 0`。 这意味着我们在保持有效的同时尽早贪婪地关闭该段。 
5.如果在数组末尾`cur_xor`不为零，我们必须将其视为最终段并以相同的方式验证它。 如果违反约束，则返回$-1$。 
6. 返回`segments`。 

一旦段有效就关闭段的贪婪选择是正确的，因为延迟切割只会合并段，这会减少段的数量，并且无助于约束，因为 OR 只会随着段的增加而增长。 

### 为什么它有效

 每个段都为最终的 OR 贡献一个固定的 XOR 值，并且这些贡献是独立的。 一旦某个位出现在任何段 XOR 中，它就永远保留在 OR 结果中。 该算法确保我们仅在不引入无效位且这样做不会降低可行性的情况下提交段。 由于合并段不能减少 OR，只能减少段的数量，因此最早的安全切割始终保持最大值。 

不变量是在任意点，`or_acc`恰好包含所有最终段的或，并且`cur_xor`代表尚未决定完成的候选段。 仅当进一步扩展该段不会增加答案或违反可行性时才进行每次切割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    or_acc = 0
    cur_xor = 0
    segments = 0

    for v in a:
        cur_xor ^= v

        # if current segment XOR already exceeds allowed bits, we must stop
        if (cur_xor | or_acc) <= x:
            # greedily cut here
            segments += 1
            or_acc |= cur_xor
            cur_xor = 0

    # leftover segment
    if cur_xor:
        if (cur_xor | or_acc) <= x:
            segments += 1
        else:
            print(-1)
            return

    print(segments)

t = int(input())
for _ in range(t):
    solve()
```该实现直接镜像贪婪扫描。 XOR 累加定义了当前段。 OR 累加器存储先前段已提交的所有位。 关键条件`(cur_xor | or_acc) <= x`确保不会引入任何禁止位。 

最后的剩余检查是必要的，因为最后一个段可能尚未在循环内关闭，并且忽略它会默默地接受无效分区。

 ## 边缘情况

 一个关键的边缘情况是当$x = 0$。 在这种情况下，每个段异或必须为零，否则即使是单个位也会违反约束。 该算法处理这个问题是因为任何非零`cur_xor`立即引起`(cur_xor | or_acc)`超过$x$，防止无效削减并强制返回$-1$除非整个数组异或结构允许所有段都为零。 

当数组仅包含零时，会出现另一种边缘情况。 这里`cur_xor`始终为零，并且每个位置都会触发有效的切割。 该算法产生$n$因为每个元素都可以被隔离而不影响 OR 约束。 

第三种情况是当数组具有在 XOR 中取消但仍引入中间非零前缀的交替位时。 贪婪结构确保我们仅在安全时进行切割，并且由于 OR 仅跟踪最终确定的段，因此不会发生过早的约束冲突。
