 ## 解决方案
 ## 问题理解

 输入描述了由垂直堆叠的单位宽度砖块组成的几个独立的“景观”。 每个景观都是一个数组，其中位置的值`i`代表此时墙的高度。 

下雨时，水会积聚在较高墙壁之间的间隙中。 只有当某个位置的左右两侧都有较高或相同的墙壁时，水才会被困住，否则水就会流出。 

对于每个测试用例，任务是计算雨后整个结构中残留的水总量。 

这些限制意味着最多 10,000 个测试用例，但所有用例的职位总数最多为 20,000 个。 这个单一界限是关键：任何接近每个测试用例线性的解决方案都已经太慢了，但总体上每个元素的线性扫描是可以接受的。 每个测试用例的任何二次方都将远远超出限制。 

一些边缘情况对于正确性很重要。 

严格递增的数组，例如`[1, 2, 3, 4]`不会积水，因为每个位置都没有比其自身高的左边界。 答案一定是0。 

严格递减数组，例如`[4, 3, 2, 1]`出于同样的原因，也不会捕获水，但是如果不小心实施，仅查看一侧最大值而不进行适当配对的简单算法可能会错误地计算负值或部分贡献。 

平面数组如`[2, 2, 2, 2]`也没有积水。 一些不正确的实现如果使用严格的不等式而不是包含最大值，则会意外地将相等边界视为陷阱空间。 

最后，单元素或类似空结构的情况，例如`[5]`必须返回 0，因为无法形成容器。 

## 方法

 计算滞留水的直接方法是独立检查每个位置并确定其上方有多少水。 对于给定的索引`i`，水位受到左侧最高墙和右侧最高墙的限制。 如果我们将它们表示为`L[i]`和`R[i]`，然后水位以上`i`是`max(0, min(L[i], R[i]) - h[i])`。 

暴力实现计算`L[i]`和`R[i]`通过左右扫描每个索引。 这是正确的，因为它明确地重建了每个位置的约束。 然而，每个索引都需要 O(n) 工作来重新计算其边界，从而导致每个测试用例的时间复杂度为 O(n²)。 总共有`n`如果测试用例呈对抗性分布，则在 2×10⁴ 以内，这种最坏情况的行为在严格的 1 秒限制内会变得太慢。 

关键的观察是左右最大值不需要重复重新计算。 它们可以预先计算一次。 一旦我们有了前缀最大值和后缀最大值数组，就可以在 O(1) 内评估每个位置，从而将问题简化为线性扫描。 进一步的优化通过使用双指针技术完全删除辅助数组，该技术保持两端的运行最大值，确保每个元素都被处理一次。 

双指针方法之所以有效，是因为任何位置处滞留水的限制因素始终是迄今为止从两侧看到的最佳边界中较小的一个。 通过始终推进边界较小的一方，我们保证该步骤的决定是最终的，以后无法改进。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 前缀/后缀数组 | O(n) | O(n) | 已接受 |
 | 两个指针| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用带有运行最大值的两指针策略。 

1.初始化两个指针`l = 0`和`r = n - 1`，和两个变量`left_max = 0`和`right_max = 0`。 这些代表了迄今为止从每一侧看到的最佳边界。 
2. 虽然`l < r`， 比较`h[l]`和`h[r]`。 高度较小的一侧决定下一步的计算。 
3.如果`h[l] <= h[r]`，我们处理位置`l`。 原因是右边界已经保证至少是`h[l]`，所以限制因素是`left_max`。 如果`h[l] >= left_max`，我们更新`left_max`。 否则，水会积聚在`left_max - h[l]`。 然后递增`l`。 
4. 否则，我们处理位置`r`对称地。 如果`h[r] >= right_max`， 更新`right_max`。 否则，添加`right_max - h[r]`。 然后递减`r`。 
5. 累积扫荡期间的所有贡献。 

在每一步中，我们总是最终确定一个边界的水贡献，而不需要未来的信息，因为保证另一侧足够高以形成该指数的上限。 

### 为什么它有效

 不变的是，在任何时刻，所有位置都严格位于当前位置之外`[l, r]`窗口已经使用正确的边界约束进行了完全处理。 处理较小一侧的决定可确保对于所选索引，相对边界至少与正在处理的高度一样大，因此唯一未知的限制因素是已处理一侧的运行最大值。 这可以防止任何后续调整改变计算出的水位。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))

        l, r = 0, n - 1
        left_max, right_max = 0, 0
        water = 0

        while l < r:
            if h[l] <= h[r]:
                if h[l] >= left_max:
                    left_max = h[l]
                else:
                    water += left_max - h[l]
                l += 1
            else:
                if h[r] >= right_max:
                    right_max = h[r]
                else:
                    water += right_max - h[r]
                r -= 1

        out.append(str(water))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码维护两个向中心收缩的指针。 在每一步中，它都会首先处理较小的边界，因为该侧的水位已经完全由迄今为止看到的最佳边界确定。 运行的最大值确保我们永远不会重新计算对数组的扫描，并且累积的`water`变量立即收集贡献。 

一个常见的实施错误是比较`h[l]`和`h[r]`但忘记保持单独的最大值，这会导致出现内部峰值时计数不足。 另一个问题是在使用当前高度之前更新指针，这会将逻辑移动一个索引并默默地破坏结果。

 ## 边缘情况

 对于单个元素输入，例如`[7]`，算法将两个指针设置为相同的索引，并立即终止而不进行处理，产生 0。没有形成边界，因此无法计算水。 

对于像这样的扁平结构`[4, 4, 4, 4]`， 两个都`left_max`和`right_max`立即更新为 4，并且每次比较都没有发现低于边界的间隙。 累积水量始终保持为 0，符合预期的物理解释。 

对于严格递增的序列，左指针一侧总是更新`left_max`在检测到任何缺陷之前的每一步。 由于没有任何元素低于其运行最大值，因此不添加水。 相同的逻辑对称地适用于严格递减序列，其中右指针占主导地位并防止该侧的累积。
