 ## 解决方案
 ## 问题理解

 我们给定一个整数$m$和一个数组$a$。 任务是查看每个除数$d$的$m$，并决定是否$d$是“安全”还是“坏”。 除数$d$如果至少存在一个数组元素，则被认为是坏的$a_i$这样$d$划分$a_i$。 否则，$d$是安全的。 目标是计算有多少个约数$m$是安全的。 

查看条件的另一种方法是我们过滤$m$通过排除那些作为至少一个数组元素的除数出现的元素。 我们不关心哪个元素触发排除，只关心它是否至少发生一次。 

这些限制促使我们进行仔细的因式分解推理。 总和$n$所有测试用例可以达到$10^6$， 和$m$取决于$10^9$。 这立即排除了任何试图检查每个除数的解决方案$m$直接针对每个数组元素。 即使迭代所有对也会太慢。 

第二个微妙的问题是，同一个除数$m$可能出现在许多数组元素中。 重新计算每个除数的每个元素的整除性的简单方法会反复浪费工作。 

典型的陷阱出现在以下情况：$m$很小但是数组很大。 例如，如果$m = 1$，唯一的除数是$1$，答案仅取决于是否存在$a_i$等于$0$或者$1$在可分性方面。 粗心的实现假设有多个除数或忘记了特殊结构$m$很容易算错。 

当许多数组元素是一个小除数的倍数时，会出现另一种边缘情况$m$。 例如，如果$m = 12$并且该数组包含许多倍数$2$，然后除数$2$即使它从未明确出现在数组中，也应将其排除。 逻辑取决于可除性传播，而不是相等性。 

## 方法

 蛮力视角自然地从枚举所有因数开始$m$。 自从$m \le 10^9$，约数的数量最多在几千左右。 对于每个除数$d$，然后我们扫描整个数组并检查是否存在任何$a_i$这样$a_i \bmod d = 0$。 如果不存在，我们就计算它。 

这是有效的，因为直接检查定义。 然而，其成本是$O(n \cdot \tau(m))$每个测试用例，其中$\tau(m)$是除数的数量。 和$n$最多$10^6$，即使$\tau(m)$在最差的配置中只有 1000，这变成$10^9$每个测试用例的操作，这是不可行的。 

关键的观察是，我们实际上并不关心除数是否整除某个元素，而是它是否整除至少一个元素。 这相当于标记出现在数组元素的除数集中的除数。 我们不是迭代每个查询的除数，而是反转视角：对于每个数组元素$a_i$，我们枚举所有的约数$a_i$并将它们标记为“坏”。 处理完数组后，我们只需要计算出哪些因数即可$m$从未被标记。 

这翻转了复杂性。 现在每个$a_i$贡献$O(\sqrt{a_i})$工作，并且自从$\sum n \le 10^6$，总工作量仍处于可控范围内。 我们仍然需要确保快速除数生成和高效的成员标记。 

我们还依赖这样一个事实：$a_i$和$m$达到$10^9$，因此整数分解到平方根是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot \tau(m))$|$O(\tau(m))$| 太慢了 |
 | 最佳 |$O(\sum \sqrt{a_i} + \sqrt{m})$|$O(\tau(m))$| 已接受 |

 ## 算法演练

 我们维护一个集合或哈希结构，用于存储我们观察到的“坏”数组元素的所有除数。 

1.读取数组并计算每个元素的所有除数$a_i$。 对于每个除数$x$，将其插入到哈希集中。 该集合表示除至少一个数组元素的所有数字。 我们这样做是因为可分性是唯一与排除相关的属性。 
2. 计算所有除数$m$。 这是在$O(\sqrt{m})$通过测试最多$\sqrt{m}$和配对因素。 每个除数都被收集到一个列表中。 
3. 迭代除数$m$。 对于每个除数$d$，检查是否$d$存在于“坏”集中。 如果不存在，则意味着没有数组元素可以被整除$d$，所以我们算一下。 
4. 输出最终计数。 

正确性依赖于这样一个事实：每次除数出现在集合中时，都保证至少有一个数组元素可被它整除。 因此，排除是精确的：没有因数$m$被删除，除非它真正划分了一些$a_i$。 

### 为什么它有效

 中心不变量是，在处理数组之后，该集合恰好包含整除至少一个数组元素的整数集合。 这不是一个近似值，因为我们明确枚举了每个的所有约数$a_i$，因此没有遗漏除数。 

一旦这个不变量成立，最后一步纯粹是对除数的过滤$m$。 除数$d \mid m$当且仅当它不在集合中时，答案才有效。 该条件与问题陈述完全匹配，因此计数是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_divisors(x):
    divs = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            divs.append(i)
            if i * i != x:
                divs.append(x // i)
        i += 1
    return divs

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    bad = set()

    for v in a:
        i = 1
        while i * i <= v:
            if v % i == 0:
                bad.add(i)
                bad.add(v // i)
            i += 1

    divs_m = get_divisors(m)

    ans = 0
    for d in divs_m:
        if d not in bad:
            ans += 1

    print(ans)
```该解决方案首先构建出现在任何数组元素中的所有除数的全局集合。 这是关键的压缩步骤：我们只关心存在性，而不是跟踪哪个元素触发除数。 

辅助函数为$m$干净地枚举所有除数$\sqrt{m}$，给定约束就足够了$m \le 10^9$。 

最后一个循环是对除数的直接过滤$m$。 不需要额外的状态。 

一个微妙的实现细节是$i$和$v // i$必须插入时$i \mid v$，否则一半的除数将会丢失，并且过滤将变得不正确。 

## 工作示例

 考虑一个小例子，其中$m = 12$和$a = [3, 10]$。 

3 的约数贡献$\{1, 3\}$，和 10 的约数贡献$\{1, 2, 5, 10\}$。 坏因数的并集变为$\{1, 2, 3, 5, 10\}$。 

12 的约数是$\{1, 2, 3, 4, 6, 12\}$。 

| 步骤| a[i] | 的除数 步骤后设置错误 |
 | --- | --- | --- |
 | 3 后 | 1, 3 | {1, 3} |
 | 10点后| 1、2、5、10 | {1,2,3,5,10}|

 检查 12 的约数，只有 4、6 和 12 不在坏集合中，所以答案是 3。 

该轨迹表明该算法不依赖于频率，只依赖于存在性，这正是所需的属性。 

现在考虑第二种情况$m = 6$和$a = [4, 9]$。 

4 的约数是$\{1, 2, 4\}$，9 的约数是$\{1, 3, 9\}$。 坏集合变成$\{1, 2, 3, 4, 9\}$。 

6 的约数是$\{1, 2, 3, 6\}$。 只有 6 个不在坏集合中。 

| 步骤| a[i] | 的除数 步骤后设置错误 |
 | --- | --- | --- |
 | 4 后 | 1, 2, 4 | {1,2,4}|
 | 9点后| 1、3、9 | {1,2,3,4,9}|

 结果证实，即使除数从未明确显示为数组元素，只要存在任何倍数，它就会被排除。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(\sum \sqrt{a_i} + \sqrt{m})$| 每个数字都通过试除进行因式分解； 每个数字枚举一次除数 |
 | 空间|$O(\tau(m) + \sum \tau(a_i))$| 哈希集中存储的除数加上临时列表 |

 时间限制由除数枚举驱动，在约束下这是有效的，因为测试用例的总输入大小是有限的。 内存使用量仍然与遇到的不同除数的数量成正比，这很好地限制在典型的限制范围内$10^6$总元素。

 ## 边缘情况

 当$m = 1$，唯一的除数是 1。如果任何数组元素可被 1 整除（这始终为真），则坏集合立即包含 1。 该算法正确返回 0，因为最终循环检查单个值并发现它存在于集合中。 

当所有数组元素相同且等于$m$, 的每个除数$m$被插入到坏集合中，因为每个除数$m$也分$m$本身。 因此，最终循环排除了所有候选者，产生 0。 

当数组元素是与无关的大素数时$m$，坏集合大多只包含 1 和素数本身。 的除数$m$复合且不相关的保持不变，因此答案等于$m$减去与 1 的任何重叠部分。
