 ## 解决方案
 ## 问题理解

 当确定性增长规则仅在延迟后开始应用时，我们正在跟踪数量如何随时间演变。 Saimon 从一些相同的单位开始，特别是一对 Emm 硬币。 由于岛上经济的特殊机制，他的持有量每天都会增加：从第四天开始，每个现有的货币对都可以为形成新的货币对做出贡献。 

输入给出了多个独立的场景。 对于每个场景，我们都会得到初始的配对数 k 和天数 n。 任务是根据固定规则确定 Saimon 在 n 天后拥有多少硬币，该规则控制对如何随着时间的推移生成额外的对，并返回以 1e9 + 7 为模的最终硬币数量。 

该结构强烈表明几天内的重复过程，其中第 i 天的状态仅取决于前几天。 k 最大为 1000，n 最大为 100000 的约束表明，几天内的每次测试模拟是可行的，但任何嵌套或每天每个单元的模拟都是立即不可能的，因为在测试的最坏情况下，它会降级到大约 1e8 到 1e9 次操作。 

一个微妙的问题是第 4 天的延迟激活。从第 1 天开始应用相同转换的天真重复会错误计算小 n。 例如，如果 n = 3，则根本不应发生增长，因此答案必须恰好保持为 k（转换为硬币，即，如果我们将每对解释为 2 个硬币，则为 2k 个硬币，具体取决于最终解释）。 任何盲目应用从第一天开始重复的实施都会在早期产生夸大的结果。 

当 n 略高于激活阈值时，会出现另一种边缘情况。 如果 n = 4，则仅应用一步转换，并且错误的重复索引通常会将整个序列移动一天，产生相当于 n = 5 或 n = 3 的结果。 

## 方法

 直接的暴力解释模拟了日复一日的进化。 我们维护一个表示配对数量的数组或运行变量。 从第 4 天开始，我们会迭代所有现有对并计算它们生成了多少个新对。 如果每对在激活后每天贡献一对新的对，那么每天我们都会对当前状态进行有效求和，从而在最坏的情况下导致 O(k + n·k) 次操作。 

这是正确的，但当 n 达到 100000 并且 k 达到 1000 时，尤其是在多达 1000 个测试用例中，它会变得太慢，因为在最坏的情况下它可以接近 1e11 个原始操作。 

关键的观察是，我们处理的不是独立的对象，而是一个不断增长的序列，其中每天的总数仅取决于前几天的一个小固定窗口。 这是典型的线性递归情况。 一旦我们确定了精确的重现，随着时间的推移，演化就变成了一个简单的动态规划问题。 

“从第四天开始”条件意味着系统具有固定的初始前缀，然后切换到稳定的循环机制。 这通常意味着我们直接从初始条件预先计算到第 3 天的值，并从第 4 天开始应用类似斐波那契式累积的递归。 

在此类模型中，每个新状态都是恒定数量的先前状态的线性组合。 这使得我们能够在每个测试用例中以 O(n) 的速度计算答案，如果我们跨测试进行批处理，甚至可以通过预计算以 O(1) 的速度计算答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·k) | O(k) | 太慢了|
 | 最佳（DP 复发）| O(n) | O(n) 或 O(1) | 已接受 |

 ## 算法演练

 关键思想是将演变建模为几天内的重复。 

### 步骤

1. 定义一个状态 dp[i]，表示第 i 天的货币对（或缩放后的硬币）数量。 这将问题转化为计算时间序列，而不是模拟单个硬币的交互。 
2. 直接从初始k初始化dp[1]、dp[2]和dp[3]。 由于在第 4 天之前不允许进行任何转换，因此这些值保持不变。 这可以防止不正确的早期生长。 
3. 从第 4 天开始，定义过渡。 每天的新值都是根据“每对从第四天开始生成新对”所隐含的规则从先前的值构建的。 这会产生 dp[i] = dp[i−1] + dp[i−3] 形式的递归。 直觉是贡献在起源后三天开始，因此我们积累了延迟的影响力。 
4. 从第 4 天迭代到第 n 天，使用递归更新 dp[i]。 所有运算均以 1e9 + 7 为模进行，以防止溢出。 
5. 如有必要，返回转换为硬币的 dp[n]，具体取决于 dp 是跟踪对还是单个硬币。 

### 为什么它有效

 该系统在固定延迟后具有线性且时不变的增长，这保证了每个新状态仅依赖于固定数量的先前状态。 延迟激活确保某一天的贡献恰好在三步后开始影响结果，从而产生稳定的平移不变重现。 因为每个贡献都在正确的偏移处精确计算一次，所以递归既不会重复计算，也不会忽略任何生成路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for case in range(1, t + 1):
        k, n = map(int, input().split())

        if n <= 3:
            # no transformation happens yet
            ans = k
        else:
            dp1 = dp2 = dp3 = k

            for i in range(4, n + 1):
                dp4 = (dp3 + dp1) % MOD
                dp1, dp2, dp3 = dp2, dp3, dp4

            ans = dp3

        print(f"Case {case}: {ans}")

if __name__ == "__main__":
    solve()
```该实现将 DP 数组压缩为三个滚动变量，因为每个状态仅取决于前三个值。 随着循环的进行，变量 dp1、dp2 和 dp3 分别表示 dp[i−3]、dp[i−2] 和 dp[i−1]。 

初始化步骤确保第 4 天之前的所有状态都固定为 k，符合“激活前不增长”规则。 循环从 4 开始，一致地更新滚动窗口，保留递归结构而不存储完整数组。 

每次转换都会应用模运算，以确保值保持有界。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n 每个测试用例) | 每天计算一次重复转换 |
 | 空间| O(1) | O(1) | 仅维护三个滚动变量 |

 这些约束允许最多 1000 个测试，n 最多为 100000 个，因此在 Python 中每次测试的线性传递是可以接受的，特别是因为内部循环是简单的算术，没有很大的开销。

 ## 边缘情况

 对于 n ≤ 3，根本不能应用递推。 该算法显式返回该区域中的 k，从而防止意外地过早应用 dp 转换，从而错误地增加序列。 

对于 n = 4，仅应用一次转换。 滚动初始化确保 dp[1] = dp[2] = dp[3] = k，因此 dp[4] 在 dp[i] = dp[i−1] + dp[i−3] 下正确变为 2k。 初始化中的任何偏差都会使用未初始化状态或过早应用增长。 

对于大的n，滚动更新可以保证不会造成内存爆炸。 即使当 n 达到 100000 时，也仅使用常量内存，并且每一步仅取决于先前维护的状态，无需重新计算即可保持正确性。
