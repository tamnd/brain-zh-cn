 ## 解决方案
 ## 问题理解

 我们得到了几个“能力字符串”，其中每个能力都由不同的字符组成，并且没有字符出现在多个能力中。 根据这些能力，我们通过在当前字符串中的任何位置插入整个能力字符串作为连续块来重复构造从空开始的最终字符串。 每次插入都会保留该能力字符串的内部顺序，但它可以放置在中间、末端或先前插入的部分内。 

经过多次这样的插入后，我们会看到一个最终的字符串，并询问它是否可以通过这些操作的某些序列生成。 如果可能的话，我们还必须报告总共使用了多少插入。 

重要的结构约束是角色按能力进行全局划分。 每个字母都属于一种能力，因此可以通过跟踪每个字符来自哪个能力来分解最终的字符串。 这立即限制了不同能力之间的相互作用：它们从不竞争相同的角色位置，并且任何全局交错都必须尊重每个能力的顺序约束。 

就结构而言，约束很小，但就最终字符串长度而言，约束很大。 所有测试用例的总长度最多为100000，因此任何解决方案都必须与输入字符串的长度呈线性或近线性。 能力最多有13个，而且每个能力都很短。 这强烈表明我们应该在单次传递或每种能力的少量传递中处理最终字符串。 

一个微妙的问题是插入可能发生在先前插入的块内。 这意味着能力字符串不一定在最终结果中显示为连续的子字符串。 尝试直接匹配整个子字符串的幼稚方法会在有效构造（例如将一种能力插入到另一种能力的中间）上失败。 

另一个陷阱是假设某个能力的出现必须在最终字符串中显示为连续的段。 他们没有。 较早插入的能力可以通过稍后插入进行分割，因此其字符可以与其他字符交错，同时仍保留内部顺序。 

## 方法

 考虑该过程的一种直接的暴力方法是模拟所有可能的插入序列。 从空字符串中，每一步我们选择一种能力并将其插入到任意位置。 这产生了一个巨大的分支因子：在步骤 k，有 O(n) 个能力选择和 O(L) 个插入位置，其中 L 随着每一步而增长。 即使最终长度适中，状态数量也会以组合方式爆炸，使得这种方法不可行。 

关键的简化来自于观察到不同能力的角色永远不会混合在一个能力中，并且每个能力在内部都是刚性的。 因此，我们可以忘记插入的几何结构，而是在最终字符串中独立跟踪每个能力。 

如果我们将最终字符串仅投影到属于给定能力的字符上，我们将获得仅由该能力的字符组成的子序列。 任何有效的构造都必须通过按顺序重复写入能力字符串的副本来产生此子序列。 其他地方的插入不会干扰此投影，因为它们只插入其他字符，这些字符在我们过滤时会消失。 

这将全局构建问题减少为每个能力的独立检查。 对于每种能力，我们验证其过滤后的子序列是否恰好是其自身字符串重复一定次数的串联。 如果这适用于所有能力，那么我们可以通过以与观察到的计数一致的任何顺序交错这些插入来实现整个构造。

迭代总数就是每种能力在其自己的预计子序列中出现的次数之和。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们首先读取所有能力字符串，并将每个字符分配给其相应的能力索引。 这种映射是独一无二的，因为没有一个角色出现在多个能力中。 这允许我们将最终字符串压缩为能力标识符序列而不是原始字符。 
2.我们将最终的字符串S转换为数组A，其中每个位置存储拥有该角色的能力的索引。 这将问题减少到最多处理 13 个符号。 
3. 对于每个能力 i，我们提取仅由 i 的出现组成的 A 子序列。 该子序列表示该能力的字符在最终字符串中出现的确切顺序。 
4. 我们将此子序列与能力字符串 si 的重复副本进行比较。 我们模拟循环地遍历 si：每次我们在 A 中看到能力 i 的角色时，它都必须与 si 中的下一个预期角色匹配。 如果我们不匹配，那么建造就不可能。 
5. 在进行匹配时，我们计算完成 si 完整遍历的次数。 每个完成对应于该能力字符串的一次插入。 
6. 如果所有能力都通过了此检查，我们输出“是”以及所有能力的已完成循环总数。 否则，我们输出“No”。 

### 为什么它有效

 由于每个角色都属于一种能力，因此从 S 中删除所有其他角色不会影响该能力内角色的相对顺序。 每个有效的构造都会为每个能力生成一个与其定义字符串完全相同的序列，因为插入仅复制整个能力字符串而不改变内部顺序。 相反，如果每个投影子序列都与重复模式匹配，我们可以按照 S 中出现的顺序交错相应的插入，而不会在能力之间产生冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        abilities = []
        owner = {}

        for i in range(n):
            s = input().strip()
            abilities.append(s)
            for ch in s:
                owner[ch] = i

        S = input().strip()

        # compress S into ability ids
        A = [owner[ch] for ch in S]

        # for each ability, extract its subsequence
        pos = [[] for _ in range(n)]
        for x in A:
            pos[x].append(x)

        total_ops = 0
        ok = True

        for i in range(n):
            if not pos[i]:
                continue

            pattern = abilities[i]
            m = len(pattern)

            j = 0
            cnt = 0

            for x in pos[i]:
                # since x identifies ability i, we only need to track cycle
                if pattern[j] != pattern[j]:
                    pass

            # rebuild properly: we need actual characters, not ids
            seq = [ch for ch in S if owner[ch] == i]

            j = 0
            cnt = 0
            for ch in seq:
                if ch != pattern[j]:
                    ok = False
                    break
                j += 1
                if j == m:
                    j = 0
                    cnt += 1
            if not ok:
                break

            total_ops += cnt

        if ok:
            print("Yes")
            print(total_ops)
        else:
            print("No")

if __name__ == "__main__":
    solve()
```实现的核心是按能力扫描。 对于每个能力，我们重建其在 S 中出现的字符序列，然后检查该序列是否是通过重复能力字符串形成的。 指针`j`跟踪能力字符串的一份副本内的进度，每次它重置为零时，我们就完成了一次插入。 

一个微妙的点是我们必须使用原始字符而不是压缩标识符来重建每个能力序列。 这使得比较与能力定义直接相关。

 ## 边缘情况

 一种边缘情况是某项能力从未出现在最终字符串中。 在这种情况下，它的子序列是空的并且没有任何贡献，这是有效的，因为该能力根本就从未被使用过。 

另一种情况是，某项能力看似部分匹配，但在周期中结束。 例如，如果模式是`abc`投影是`abca`，最后的`a`开始一个新的循环但从未完成它，这在有效插入下不会发生，因为每次插入都会贡献该能力的完整副本。 

第三种情况是多种能力严重交织时。 由于投影消除了所有干扰，每个能力仍然独立地形成自己的循环结构，并且算法单独验证它们而不受交织的影响。
