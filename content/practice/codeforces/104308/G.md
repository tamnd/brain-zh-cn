 ## 解决方案
 ## 问题理解

 我们得到了多个测试用例。 每个测试用例都包含一个小写字符串，表示 Roshid 想要输入的文本。 然而，他的键盘出现了硬件故障：对应于标准键盘布局的底行的特定字母组不再起作用。 每当输入字符串中出现任何这些损坏的字符时，就无法键入它，因此它永远不会出现在最终输出中。 

任务是为每个测试用例独立模拟这个过滤过程，并在删除所有不可用的字符后打印结果字符串。 

所有测试用例的总长度最多为 1e6 的约束意味着任何解决方案都必须在完整输入上以线性时间运行。 只要我们只为每个字符做持续的工作，每个测试用例的 O(n) 方法就可以了。 任何二次方的操作，例如重复的字符串连接或每次删除时的重复扫描，都不会通过。 

一个微妙的边缘情况是整个字符串仅由损坏的字符组成。 例如，如果输入是像“mcc”这样的字符串，其中所有字符均不可用，则正确的输出是空行。 另一个边缘情况是混合字符串，其中仅删除了一些字符，例如“mist”，其中仅过滤了损坏的字母，而其余字母完全保留了它们的顺序。 

## 方法

 思考问题最直接的方法就是从字面上模拟键盘行为。 对于每个测试用例，我们从左到右扫描字符串并决定是否可以键入每个字符。 如果可以，我们将其附加到结果中，否则我们跳过它。 

简单的方法可能会尝试使用替换操作或多次过滤来重复从字符串中删除字符。 例如，可以扫描每个损坏的字符并将其从字符串中全局删除。 从概念上讲，这是可行的，但每次全局替换都是 O(n)，并且对多个字符执行此操作会导致重复的完整扫描。 在最坏的情况下，每个测试用例的复杂度为 O(26 · n) 或更糟，具体取决于实现开销，这在严格的约束下是不必要的且存在风险。 

关键的观察结果是，可以使用集合或布尔查找表中的成员资格测试在恒定时间内独立检查每个字符。 这将整个过程减少为每个测试用例一次线性传递，仅累积有效字符。 

暴力破解之所以有效，是因为每个字符的过滤都是独立的，但如果我们重复重建字符串，它就无法扩展。 优化的方法将所有内容简化为流过滤器。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（重复删除）| 每次测试 O(26 · n) 或更差 | O(n) | 太慢了|
 | 最佳（单通道过滤）| 总共 O(n) | O(1) 辅助 | 已接受 |

 ## 算法演练

 我们将损坏的按键集定义为在 Roshid 键盘上不起作用的字母。 然后我们独立处理每个测试用例。 

### 步骤

 1. 预定义一个包含所有损坏字符的集合。 

这允许在扫描字符串时进行恒定时间的成员资格检查。 
2. 对于每个测试用例，初始化一个空的输出缓冲区。 

我们使用字符列表而不是重复的字符串连接，因为循环内的连接会产生二次行为。 
3. 迭代输入字符串中的每个字符。 

对于每个字符，检查它是否在损坏集中。 
4. 如果字符未损坏，则将其附加到输出缓冲区。 

如果它损坏了，请完全跳过它。 
5. 处理完整字符串后，将缓冲区连接成最终字符串并打印。 

### 为什么它有效

在扫描过程中的任何时刻，输出缓冲区都准确地包含迄今为止所看到的并且没有被破坏的字符。 由于每个字符都是独立处理的并且永远不会重新访问，因此保留了有效字符的相对顺序。 未来的决定不依赖于早期过滤超出破碎集的成员资格，因此贪婪扫描就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    broken = set("zxcvbnm")  # broken keyboard row

    t = int(input())
    for _ in range(t):
        s = input().strip()
        res = []

        for ch in s:
            if ch not in broken:
                res.append(ch)

        print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案一次性构建一组固定的损坏字符，并将其用于所有测试用例。 每个字符串都被逐个字符地处理，并将有效字符累积到一个列表中。 最终的连接操作与字符串大小成线性关系。 

重要的实现细节是使用列表而不是重复的字符串连接。 在Python中，字符串是不可变的，所以重复`+=`会显着降低性能。

 ## 边缘情况

 一种重要的情况是整个字符串由损坏的字符组成，例如`mcc`。 该算法处理每个字符，在损坏的集合中找到每个字符，并且不向缓冲区添加任何内容。 结果是一个空字符串，仍应打印为空行。 

另一种情况是字符串不包含损坏的字符。 例如，`abcdef`逐个字符扫描，每个成员资格测试都会失败，并且每个字符都会被附加。 输出与输入完全匹配。 

第三种情况是有效字符和无效字符交错时。 例如，`mist`仅删除`m`，离开`ist`。 该算法可以干净地处理这个问题，因为每个字符都是独立处理的，不依赖于周围的上下文。
