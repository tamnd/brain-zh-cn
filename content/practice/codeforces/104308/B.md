 ## 解决方案
 ## 问题理解

 每个测试用例都描述了填写相同表格的过程，其中每个表格都需要从多个办公室收集签名。 对于每个办公室 i，一份表格需要该办公室的 ai 签名。 同时，对于您可以从该办公室获得的所有表格的签名总数有一个硬性上限。 

除了办公室签名之外，还有一个特殊的来源，即老板，他可以提供最多k个灵活的签名。 其中每一个都可以替换任何办公室缺少的所需签名。 目标是确定将有限的办公能力与这些通用替代品相结合时可以填写多少份完整表格。 

关键的困难在于，每个额外的表格都会同时消耗所有办事处的资源，因此每个办事处的可行性并不是独立的。 相反，我们必须找到最大数量的表格 x，使得每个办公室 i 的总需求 x·ai 不超过可以从该办公室实际获得的内容加上可以使用有限的 k 个灵活签名替换的内容。 

这些约束足够大，以至于任何一种方法都无法一一模拟表单构造。 每个测试用例最多有 10^5 个办公室，最多有 10^4 个测试用例，在两个值都很大的最坏情况下，O(n·答案) 策略将立即崩溃。 

将老板签名独立分配给最受限制的办公室的天真贪婪方法也失败了。 原因是每一种附加形式都会改变所有办事处的赤字分配，因此局部优化并不能体现全局可行性。 

当一个办事处的容量稍有不足，但许多其他办事处的容量却严重不足时，就会出现微妙的失败案例。 如果我们贪婪地独立分配每个办公室的老板签名，我们可能会过早地浪费灵活性，并错误地得出可能的表格比实际可行的表格少的结论。 

## 方法

 蛮力的想法是尝试构建 x 形式并验证可行性。 对于固定的x，每个办公室i必须提供x·ai签名，但最多只能贡献bi。 任何短缺都由老板签名弥补。 因此，我们计算所有办事处的总赤字，并检查它是否最多为 k。 

这种检查是正确且简单的，但是如果我们尝试从 0 向上尝试所有 x，则每次检查的时间复杂度为 O(n)，从而导致 O(n · max forms)。 由于最大形式可以大到 10^9，因此这种方法不可行。 

关键的观察结果是可行性在 x 中是单调的。 如果可以完成 x 个表格，则任何较小数量的表格也是可能的，因为所有要求都线性向下扩展。 这允许我们将 x 视为二分搜索的搜索空间。 

对于固定的 x，可行性检查简化为计算所有办事处的总和：max(0, x · ai − bi)。 这准确地代表了老板需要多少换人。 如果这个总数在 k 之内，则 x 是可行的。 

这将问题转化为对 x 的二分搜索，每次检查都需要 O(n)，从而产生有效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| O(n·X) | O(n·X) | O(1) | O(1) | 太慢了 |
 | 二分查找+可行性检查| O(n log X) | O(n log X) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取 n、k 以及数组 a 和 b。 这些定义了每个表格的线性扩展要求和每个办公室的限制。 
2. 定义一个函数can(x)，用于检查x 形式是否可以完成。 此函数计算所需替换的总数：

对于每个办公室 i，计算所需 = x·ai。 如果需求量超过bi，超出部分将导致全球赤字。 
3. 在 can(x) 内，维持运行总和赤字 = 0。对于每个 i，计算赤字 += max(0, x · ai − bi)。 如果在任何时候赤字超过 k，我们可以提前停止，因为可行性已经被打破。 
4. 对 x 执行二分查找。 搜索范围从 0 开始到安全上限。 自然界限是 max(bi) + k，但更简单且安全的界限是 10^18 或从 min(bi // ai) 导出。 
5. 对于每个中点mid，计算can(mid)。 如果可行，则将下限上移； 否则，减小上限。 
6. 二分查找结束后，最佳可行的x就是答案。 

### 为什么它有效

 对于任何固定的x，可行性条件仅取决于k是否可以弥补所有办事处的总缺口。 该不足是随 x 线性增加的独立非负贡献之和。 因此，如果 x 可行，则所有较小的值也必须可行，而如果 x 不可行，则所有较大的值仍然不可行。 这种单调结构保证了二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        def can(x):
            need = 0
            for i in range(n):
                req = x * a[i]
                if req > b[i]:
                    need += req - b[i]
                    if need > k:
                        return False
            return need <= k

        lo, hi = 0, 10**18

        while lo < hi:
            mid = (lo + hi + 1) // 2
            if can(mid):
                lo = mid
            else:
                hi = mid - 1

        print(lo)

if __name__ == "__main__":
    solve()
```实现的核心是可行性函数。 它将每个候选表格数量转换为确定性的资源需求检查。 循环内的早期停止条件很重要，因为一旦赤字已经超过 k，它可以防止不必要的求和。 

二分搜索使用上中偏差，以便当 lo 和 hi 相差 1 时收敛可以正常工作。 如果没有这种偏差，循环可能会在边界情况下停止。

 ### 示例 1

 考虑 n = 2、k = 3、a = [2, 1]、b = [3, 1]。 

我们测试不同 x 值的可行性：

这显示了各个办事处的赤字如何累积，以及为什么需要进行全局求和而不是每个办事处的决策。

 ## 边缘情况

 当所有 bi 相对 ai 都非常大时，就会出现一种边缘情况。 在这种情况下，不需要老板签名，答案纯粹由min(bi // ai)决定。 该算法自然地处理这个问题，因为对于所有 x 直到该界限，赤字保持为零。 

当 k 非常大时，会出现另一种边缘情况。 那么限制因素就变成只有bi，可行性就减少到检查对于所有i 是否x·ai ≤ bi。 二分搜索仍然有效，但可以收敛到办公室之间的最小比率附近。 

最后一个微妙的情况是，一个办公室的 bi 很小，但 ai 很大。 例如，ai = 10^9，bi = 1。当 x ≥ 1 时，该办公室立即主导可行性，但算法正确地将其贡献汇总到赤字总和中，而不是过早拒绝，从而允许其他办公室用剩余产能和老板签名进行补偿。
