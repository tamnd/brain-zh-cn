 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 在每个测试用例中，都有一个偶数长度的数组。 我们必须将数组划分为不相交的对，以便每个元素恰好属于一对。 对于每一对，它对答案的贡献是该对内两个值中较大的一个。 目标是选择使这些成对最大值的总和最小化的配对策略。 

因此，任务不是找到单个最佳匹配，而是决定如何对值进行分组，以便大型元素不会不必要地增加许多配对成本。 

约束允许最多$10^5$所有测试用例的总元素，值高达$10^9$。 这立即排除了尝试所有配对的任何方法。 分区方式的数量$n$成对的元素以超指数增长，所以即使对于$n = 20$蛮力已经行不通了。 有效的解决方案必须大致运行$O(n \log n)$或每个测试用例更好，因为排序$10^5$elements 已经接近 Python 中速度的极限。 

一些边缘情况值得牢记。 

如果所有元素都相等，则每个配对都有相同的成本，因此任何正确的算法都必须保持这种不变性。 

如果数组已经按降序排序，像第一个与第二个、第三个与第四个配对这样的天真贪婪实际上是最佳的，但第一个与最后一个配对是灾难性的，因为它迫使最大元素进入通过结构间接涉及它的每一对中。 

例如，当值交错时，就会出现不正确的贪婪策略的微妙失败案例`[1, 100, 2, 99]`。 极端配对`(1,100)`和`(2,99)`产量成本`100 + 99 = 199`，同时最佳配对`(1,2)`和`(99,100)`产量`2 + 100 = 102`。 任何不明确控制排序的策略都可能会错过这种结构。 

## 方法

 蛮力的想法很简单。 我们尝试将数组的每一种可能的配对$n/2$对，计算每个配置的最大值之和，并取最小值。 这是正确的，因为它直接评估每个有效结构的目标。 问题是完美匹配的数量$n$元素是$(n-1)!!$，它已经从小到大$n$。 为了$n = 20$，这就结束了$10^7$可能性，以及每次评估成本$O(n)$，所以这种方法立即崩溃。 

关键的观察是一对的成本仅取决于较大的元素。 这意味着每个元素要么作为其对中的“赢家”做出贡献，要么隐藏在更大的合作伙伴之下。 为了最小化总和，我们希望尽可能少地使用大元素。 这表明将大元素与尽可能小的元素配对，但这种直觉必须在全球范围内保持一致。 

一旦数组排序完毕，我们就可以推断局部结构。 考虑任意四个元素$a \le b \le c \le d$。 如果我们将它们配对为$(a, d)$和$(b, c)$，成本为$d + c$。 如果我们将它们配对为$(a, b)$和$(c, d)$，成本为$b + d$。 自从$c \ge b$，除非值相等，否则第二种配置永远不会增加成本，并且绝对更好。 这种交换论证表明，小元素和大元素之间的交叉是有害的，并且最佳结构在排序后会塌陷为相邻配对。 

因此，解决方案变成对数组进行排序并将连续元素配对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优（排序+贪婪配对）| O(n log n) | O(n log n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 读取当前测试用例的数组。 问题的结构完全包含在每个测试用例中，因此不存在跨用例交互。 
2. 按非降序对数组进行排序。 此步骤揭示了元素的自然排序，以便我们可以在本地推理最佳对形成。 
3. 以两步遍历已排序的数组，将连续元素配对。 每对形成为`(a[i], a[i+1])`。 这种配对确保每个较小的元素都与最接近的可能的较大元素匹配，从而防止大元素浪费在多个对上。 
4. 对于每一对，将第二个元素（排序后较大的元素）添加到答案中。 由于数组是有序的，`a[i+1]`保证是该对中的最大值。 
5. 输出测试用例的累计和。 

### 为什么它有效

 排序后，任何引入“交叉”结构的配对（其中较小的元素与非常大的元素配对，而另一对包含中间值）都可以通过交换端点进行局部改进。 每次交换都会减少或保留总成本，因为它可以防止更大的元素不必要地被掩盖。 重复应用此交换会消除所有非相邻配对，仅留下连续配对作为稳定配置。 这种结构确保除了偶数位置的元素之外的每个元素作为最大值只贡献一次，并且这些最大值是在其配对阶段可用的最小可能选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        ans = 0
        for i in range(1, n, 2):
            ans += a[i]
        out.append(str(ans))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案的结构围绕排序和线性扫描。 关键的实现细节是，我们在排序后对从索引 1 开始的每隔一个元素求和，因为这些元素是每个最佳对中充当最大值的元素。 使用快速 I/O 是必要的，因为总输入大小可以达到$10^5$跨测试用例的整数。

 ### 示例 1

 输入：`[1, 100, 2, 99]`排序后，数组变为`[1, 2, 99, 100]`。

 | --- | --- | --- | --- | --- |
 | 1 | [1, 2, 99, 100] | (1,2) | 2 | 2 |
 | 2 | [1, 2, 99, 100] | (99,100) | 100 | 100 102 | 102

 总数为 102，表明相邻配对避免了在不同对之间浪费大量值。

import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        ans = 0
        for i in range(1, n, 2):
            ans += a[i]

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

        from contextlib import redirect_stdout
        import io as sio
        out = sio.StringIO()
        with redirect_stdout(out):
            solve()
        return out.getvalue().strip()
    finally:
        sys.stdin = old_stdin

 ## 边缘情况

 对于交错输入，例如`[1, 100, 2, 99]`，算法排序为`[1, 2, 99, 100]`并形成对`(1,2)`和`(99,100)`。 第二个要素`2`和`100`被累加，得到 102。任何不排序的配对尝试都会产生交叉对，从而将至少一个大元素膨胀到成本更高的位置。 

对于重复较多的输入，例如`[5, 5, 5, 5, 1, 1]`，排序会产生稳定的邻接关系，其中交换对不会改变结果。 该算法始终将每对的一个副本分配为最大值，并且由于所有大元素都相等，因此任何重新排列都不会减少总数。
