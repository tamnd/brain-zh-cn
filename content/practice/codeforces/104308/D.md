 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，然后是一个查询序列。 对于每个查询值$b$，我们对所有正因数感兴趣$b$。 在这些除数中，有些可能出现在给定数组内部，有些则可能不会。 每个查询的任务是计算有多少个除数$b$数组中不存在。 

对于每个测试用例，数组本身都是静态的，因此在处理所有查询时可以将其视为固定参考集。 

这些约束意味着数组大小和查询数量最多可以达到$10^5$，数组和查询中的值也受$10^5$。 这立即排除了每个查询天真地重新计算除数的情况，也排除了通过扫描数组直接针对每个查询元素检查数组的整除性的情况。 每个查询涉及所有数组元素的解决方案将导致大约$10^{10}$在最坏的情况下进行操作，远远超出了时间限制。 

当考虑独立地重新计算每个查询的除数时，会出现一个微妙的陷阱。 对于像 100000 这样的数字，迭代至$\sqrt{b}$每个查询都可以，但是这样做$10^5$如果不仔细优化，时间仍然有超时的风险，尤其是在严格限制下的 Python 中。 

另一个边缘情况来自数组中的重复项。 如果一个值出现多次，它仍然只能算作“当前除数”一次，因此有必要将数组视为一个集合。 例如，如果数组是$[2, 2, 3]$和$b = 6$，除数是$1,2,3,6$。 两个都$2$和$3$存在，所以答案是$2$，不受重复2的影响。 

## 方法

 每个查询的直接方法是枚举从 1 到$b$并检查哪些划分$b$，然后验证数组中的成员资格。 这是正确的，但立即太慢了，因为每个查询都会花费$O(b)$，导致高达$10^{10}$运营。 

更好的观察是，除数是成对出现的，并且可以有效地生成到$\sqrt{b}$。 这将每次查询的成本降低到$O(\sqrt{b})$，但仍然留给我们最多$10^5$查询，这可能会使总数接近极限。 

关键的结构改进来自于认识到所有数字都受以下限制$10^5$。 我们可以预先计算从 1 到 1 之间的每个数字的除数列表，而不是重复地重新计算除数$10^5$一旦使用类似筛子的结构。 之后，每个查询都变成对预先计算的列表的简单扫描，并且可以在中完成成员资格检查$O(1)$使用布尔数组或哈希集。 

这将问题从重复算术因式分解转变为查找问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的暴力破解 |$O(q \cdot b)$|$O(1)$| 太慢了 |
 | 每个查询的 sqrt 分解 |$O(q \sqrt{b})$|$O(1)$| 边界|
 | 预计算除数+集合查找|$O(N \log N + q \cdot d(b))$|$O(N)$| 已接受 |

 ## 算法演练

 ## 算法演练

 1. 读取数组并将其转换为按值索引的布尔存在表。 这允许恒定时间检查数组中是否存在数字。 使用表而不是集合的原因是值范围小且固定。 
2. 预先计算 1 到 100000 之间每个数字的除数列表。对于每个整数$i$，迭代其倍数并追加$i$作为除数。 这以类似筛子的方式构建所有除数列表。 
3.对于每个查询值$b$，检索其预先计算的除数列表。 
4. 迭代所有因数$b$，并计算数组布尔表中未标记的那些。 
5. 输出每个查询的计数。 

关键思想是除数生成完全移出查询循环，因此每个查询都成为对小型预计算结构的线性扫描。 

### 为什么它有效

 数字的每个除数都保证只包含在预先计算的除数列表中一次。 存在表独立跟踪该除数是否存在于数组中。 由于这两个组件都是所需集合的精确表示，因此计算不匹配次数会直接产生正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 100000

# precompute divisors for all numbers up to MAXV
divs = [[] for _ in range(MAXV + 1)]
for i in range(1, MAXV + 1):
    for j in range(i, MAXV + 1, i):
        divs[j].append(i)

def solve():
    t = int(input())
    out_lines = []

    for _ in range(t):
        n, q = map(int, input().split())
        arr = list(map(int, input().split()))
        queries = list(map(int, input().split()))

        present = [False] * (MAXV + 1)
        for x in arr:
            present[x] = True

        for b in queries:
            cnt = 0
            for d in divs[b]:
                if not present[d]:
                    cnt += 1
            out_lines.append(str(cnt))

    return "\n".join(out_lines)

print(solve())
```预处理步骤为每个整数构建一次除数列表，因此没有查询执行任何算术分解。 该数组被转换为布尔查找表，这保证了恒定时间的成员资格检查。 

在每个查询中，我们仅迭代实际除数$b$，所以工作与除数计数成正比，而不是与大小成正比$b$。 

这里的一个常见错误是重复使用 Python 设置每个数字的除数，这会重新引入每个查询的开销。 预计算完全避免了重复分配。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(N \log N + \sum d(b))$| 除数筛加上每个查询的扫描除数 |
 | 空间|$O(N)$| 除数列表加上存在数组 |

 ## 边缘情况

 当数组包含重复值时，例如$[2, 2, 2]$，布尔存在数组确保重复项不会影响结果。 对于查询$b = 6$, 除数$1,2,3,6$每个都针对存在表检查一次，因此重复不会增加计数。 

对于像这样的小值$b = 1$，除数列表仅包含$[1]$。 如果数组不包含 1，则答案为 1； 否则为 0。该算法自然会处理此问题，因为预先计算的 1 的除数列表是正确且最小的。 

对于附近的最大值$10^5$，除数列表仍然足够小，因此每个查询迭代它都是有效的。 即使在最坏的情况下，例如高度复合的数字，除数计数仍然有限，不会威胁到时间限制。
