 ## 解决方案
 ## 问题理解

 每个候选人站在垂直轴上的位置`(0, a_i)`并发射一支箭，沿直线向着陆点行进`(x_i, y_i)`。 任务是保留尽可能多的候选者，以便两个选定的箭头轨迹不会相交。 

查看轨迹的一种有用方法是将其视为具有起始高度和斜率的线。 起始高度为`a_i`，斜率是`(y_i - a_i) / x_i`。 输入给出起始高度和着陆点，输出是可以共存且无交叉点的最大轨迹数。 

所有测试用例的候选数可以达到`500000`，因此比较每一对的算法是不可能的。 二次方法的执行情况约为`250000000000`最大情况下的比较，远远超出了正常竞技编程所允许的时间限制。 我们需要一个解决方案`O(N log N)`每总输入。 

坐标非常大，达到了大约`2^52`，所以浮点运算是不安全的。 比较两个斜率时的微小精度误差可能会改变答案。 所有斜率比较都必须使用整数交叉乘法来完成。 

在某些情况下，实施可能会悄无声息地失败。 等斜率就是其中之一。 例如：```
1
3
0 5 5
10 5 15
20 5 25
```斜坡都是`1`，所以答案是`3`。 严格递增的子序列实现将错误地返回`1`，因为允许相等的斜率。 

另一种情况是负斜率：```
1
2
0 2 -2
10 2 8
```斜坡是`-1`和`-1`，所以两条轨迹是平行的，答案是`2`。 将分子视为普通整数而不考虑分母符号很容易产生错误的排序。 

第三种危险情况是大值：```
1
2
0 4503599627370496 4503599627370496
1 4503599627370496 0
```斜坡是`1`大约`-1`，答案是`1`。 将这些值转换为`float`可能会失去足够的精度来错误地比较斜率。 

## 方法

 直接的解决方案是检查每对轨迹并确定它们是否相交。 由于当两条轨迹的斜率相对于起始高度的顺序不正确时，两条轨迹就会相交，因此我们可以按起始高度排序并比较每对斜率。 这是正确的，因为排序后`a_i`，只有当其斜率不较大时，较低的轨迹才能保持在较高的轨迹之下。 问题在于比较的次数。 和`N = 100000`，暴力法需要大约`N * (N - 1) / 2`，或者大约五十亿次比较，这太慢了。 

关键的观察是，在按垂直轴上的位置对候选者进行排序后，我们只需要永不减小的最长斜率序列。 假设候选人`i`从候选人下方开始`j`。 如果坡度为`i`越大，下面的线最终会追上上面的线，并且轨迹相交。 如果斜率较小或相等，则两条线之间的距离永远不会为零，因此它们都可以被选择。 

几何问题变成有理数上的最长非减子序列问题。 标准耐心排序技术解决了这个问题`O(N log N)`。 唯一的额外挑战是精确比较分数，这是通过交叉乘法处理的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 最佳| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 1. 按照起始身高对所有候选人进行排序`a_i`按递增顺序。 这固定了轨迹离开垂直轴的顺序。 任何有效选择的集合都必须遵守此顺序。 
2. 将每条轨迹转换为斜率值：$$s_i = \frac{y_i-a_i}{x_i}$$分母始终为正，因此比较斜率只需要比较分子和分母的叉积。 

1. 按排序顺序处理斜率并维护耐心排序数组。 位置处的值`k`表示长度非递减子序列的最小可能结束斜率`k + 1`。 
2. 对于当前斜率，找到第一个严格大于它的存储斜率。 将该值替换为当前斜率。 如果没有存储的斜率更大，则附加斜率。 

搜索使用第一个较大值而不是第一个大于或等于值，因为相等的斜率可以一起出现在答案中。 我们需要最长的非递减子序列，而不是最长的严格递增子序列。 

1、耐心排序数组的长度是不相交轨迹的最大数量。 

为什么它有效：

 按起始高度排序后，每个选定的轨迹都会从下到上显示。 对于两个连续选择的轨迹，较低的轨迹的斜率必须不大于较高的轨迹。 否则，由于它开始较低但上升较快，它最终必须达到较高的轨迹。 如果斜率按非递减顺序排列，则连续轨迹之间的垂直差开始为正，并且永远不会降低到零以下。 因此，每个有效答案都准确对应于斜率的非递减子序列。 耐心排序算法找到最长的这样的子序列，因此它的长度就是所需的最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def greater_frac(a, b):
    return a[0] * b[1] > b[0] * a[1]

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        arr = []

        for _ in range(n):
            a, x, y = map(int, input().split())
            arr.append((a, y - a, x))

        arr.sort()

        tails = []

        for _, num, den in arr:
            cur = (num, den)

            left = 0
            right = len(tails)

            while left < right:
                mid = (left + right) // 2
                if greater_frac(tails[mid], cur):
                    right = mid
                else:
                    left = mid + 1

            if left == len(tails):
                tails.append(cur)
            else:
                tails[left] = cur

        ans.append(str(len(tails)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```输入首先被转换为`(starting height, slope numerator, slope denominator)`。 将斜率存储为`(y_i - a_i, x_i)`避免任何浮点运算。 

排序步骤仅基于起始坐标，因为偏离轴的顺序决定了必须考虑轨迹的顺序。 

这`tails`数组是最长非递减子序列的常用耐心排序结构。 二分查找查找严格大于当前分数的第一个分数。 分数比较使用乘法而不是除法，这使得即使对于最大坐标，所有计算也保持精确。 

Python 整数自动处理大型中间产品。 在具有固定宽度整数的语言中，需要更宽的类型，因为乘法可能会超出 64 位限制。

 ## 边缘情况

 相等的斜率由二分搜索选择处理。 对于输入：```
1
3
0 5 5
10 5 15
20 5 25
```每个轨迹都有斜率`1`。 二分搜索永远不会用更短的子序列位置替换相等的斜率，因为它只搜索严格大于当前值的值。 数组增长到一定长度`3`，这是正确的。 

负斜率不需要特殊处理。 考虑：```
1
2
0 2 -2
10 2 8
```坡度都是`-1`，表示为`(-2, 2)`和`(-2, 2)`。 叉乘将它们精确地进行比较，因此两者被认为是兼容的，答案是`2`。 

非常大的坐标也是安全的。 为了：```
1
2
0 4503599627370496 4503599627370496
1 4503599627370496 0
```第一个斜率是`1`，而第二个是`-1`。 耐心数组用较小的斜率替换第一个值，留下长度`1`。 该算法从不将这些值转换为浮点数，因此不会发生精度损失。
