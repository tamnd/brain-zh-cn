 ## 解决方案
 ## 问题理解

 我们得到了一根仅由以下材料组成的字符串`'0'`和`'1'`。 每个角色代表排队的足球运动员的球队。 如果至少有七名连续的球员属于同一支球队，就会出现危险的情况。 

任务只是检查字符串是否包含七个连续的`'0'`字符或连续七个字符`'1'`人物。 如果存在这样的段，我们打印`"YES"`。 否则，我们打印`"NO"`。 

输入的大小非常小，最多 100 个字符。 即使是低效的解决方案也很容易满足限制。 在最坏的情况下，二次算法将执行大约 10,000 次运算，这对于 2 秒的限制来说是微不足道的。 不过，这个问题自然承认线性扫描，它更简单、更干净。 

棘手的部分不是性能，而是正确处理连续运行。 

一个简单的错误是当角色改变时错误地重置计数器。 

考虑：```
1111110
```正确答案是`"NO"`因为最长的相等字符长度为 6。粗心的实现仅检查字符总数`'1'`字符会被错误打印`"YES"`。 

另一个常见错误是仅检查七个字符而不是至少七个。 

例子：```
11111111
```正确答案是`"YES"`因为长度为 8 的游程仍然满足条件。 如果代码仅检查等于 7 的游程，则此处会失败。 

当危险序列从字符串的开头开始或在字符串的末尾结束时，就会出现第三种边缘情况。 

例子：```
0000001
```正确答案是`"NO"`因为最长的行程只有6。 

示例：```
10000000
```正确答案是`"YES"`因为最后的七个字符都是`'0'`。 

仅比较中间位置的实现可能会意外错过边界运行。 

## 方法

 暴力破解的想法是检查每个长度为 7 的子字符串，并检查其中的所有字符是否相同。 

对于每个起始位置，我们可以检查接下来的七个字符并验证它们是否都是`'0'`或全部`'1'`。 由于字符串长度最多为 100，因此这种方法完全足够快。 在最坏的情况下，我们检查大约 100 个窗口，每个窗口大小为 7，因此工作大约是 700 个字符比较。 

暴力破解之所以有效，是因为危险情况仅取决于局部连续的段。 如果存在任何有效的运行，则至少一个长度为 7 的窗口必须包含相同的字符。 

更清晰的观察进一步简化了实施。 我们可以在跟踪当前条纹长度的同时扫描一次字符串，而不是重复检查窗口。 

如果当前字符与前一个字符匹配，我们就延长连胜。 否则，我们将连胜重置为 1，因为新的运行已经开始。 当连胜数达到 7 的那一刻，我们就已经知道答案了`"YES"`。 

这将问题转化为具有恒定内存的简单线性遍历。

 | --- | --- | --- | --- |
 | 蛮力 | O(n × 7) | O(1) | O(1) | 已接受 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取输入字符串。 
2. 初始化计数器`count = 1`因为第一个字符已经形成长度为 1 的条纹。 
3. 从索引1开始遍历字符串。 
4. 对于每个位置，将当前字符与前一个字符进行比较。 
5. 如果相等，则递增`count`因为连续运行仍在继续。 
6. 否则，重置`count = 1`因为新的连胜是从当前角色开始的。 
7. 更新计数器后，检查是否`count >= 7`。 
8. 如果是，则打印`"YES"`并因发现危险情况立即停止。 
9. 如果循环结束时没有找到这样的条纹，则打印`"NO"`。 

### 为什么它有效

 该算法保持不变式`count`始终等于在当前位置结束的当前连续运行的长度。 

当两个相邻字符匹配时，游程自然延长一。 当它们不同时，前一次运行结束，新的长度为 1 的运行开始。 

由于字符串中的每个连续段都被处理一次，任何长度至少为 7 的游程最终都会导致`count`达到 7。如果算法从未达到该值，则不存在危险段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

count = 1

for i in range(1, len(s)):
    if s[i] == s[i - 1]:
        count += 1
    else:
        count = 1

    if count >= 7:
        print("YES")
        break
else:
    print("NO")
```该程序首先读取字符串并删除尾随的换行符`strip()`。 

变量`count`存储当前连续序列的长度。 它从 1 开始，因为单个字符已经形成长度为 1 的有效游程。 

循环从索引 1 开始，因为每次比较都使用`s[i - 1]`。 从索引 0 开始将导致无效访问。 

当相邻字符相等时，条纹加一。 否则，由于连续性已被破坏，该条纹将重置。 

这`if count >= 7`检查在更新条纹长度后立即放置在循环内。 一旦它们变得危险，它就会立即逃跑。 

这`for ... else`结构在这里很有用。 这`else`仅当循环从未遇到过时才执行块`break`。 这意味着我们打印`"NO"`仅当未发现危险段时。

 ## 边缘情况

 考虑输入：```
1111110
```该算法连续处理六个`'1'`字符，所以`count`达到 6. 最后一个字符`'0'`，连胜次数重置为 1。`count`永远不会变成 7，输出是`"NO"`。 

现在考虑：```
11111111
```条纹增长如下：```
1 → 2 → 3 → 4 → 5 → 6 → 7
```只要连续第七次`'1'`达到时，算法打印`"YES"`。 第八个字符永远不会引起问题，因为条件会检查`>= 7`，不完全是 7。 

最后，考虑：```
10000000
```第一个字符创建长度为 1 的条纹。从第二个字符开始，算法不断扩展`'0'`字符，直到计数器在最终位置达到 7。 输出变为`"YES"`。 

这证实了字符串边界处的序列被正确处理。
