 **标签：** 二分查找、位掩码、暴力破解
 **求解时间：** 4m 51s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们需要找到大于或等于给定整数的最小数字，使得：

 1. 每个数字都可以是`4`或者`7`。 
2. 计数`4`s 等于计数`7`s。 

这些数字被称为超级幸运数字。 

例如，`47`有效，因为它包含一个`4`和一个`7`。 数量`7744`也是有效的，因为它的每个数字有两个。 数量`4447`无效，因为计数不同。 

输入包含单个整数`n`, 直至`10^9`。 我们必须输出最小的超级幸运数，至少是`n`。 

上的界限`n`是关键观察。 自从`10^9`最多有 10 位数字，任何答案也只有少量数字。 对普通整数进行强力搜索仍然很糟糕，因为幸运数字很少。 检查每个数字`n`向上可能需要数百万或数十亿次迭代。 

幸运数字的结构彻底改变了问题。 有效号码只能包含`4`和`7`，并且长度必须是偶数，因为计数必须匹配。 最多10位数字，候选人总数很少。 

对于一个长度`2k`，我们只需要选择哪个`k`职位包含`4`。 其余位置变为`7`。 此类字符串的数量为：$$\binom{2k}{k}$$对于长度不超过 10 位数字：$$\binom{2}{1} + \binom{4}{2} + \binom{6}{3} + \binom{8}{4} + \binom{10}{5} = 2 + 6 + 20 + 70 + 252 = 350$$总共只有 350 名候选人。 它足够小，可以直接产生所有可能性。 

一些边缘情况可能会悄悄破坏粗心的解决方案。 

如果`n = 1`，答案是`47`。 试图保持相同位数的贪心方法可能会失败，因为不存在一位数的超级幸运数字。 

如果`n = 999999999`，答案就变成了`4444477777`，其位数多于`n`。 任何仅限于原始数字计数的解决方案都会错过这一点。 

如果`n`本身就已经超级幸运了，比如`4477`，我们必须将其原样返回。 使用严格的`>`比较而不是`>=`会错误地跳过它。 

另一个微妙的例子是字典顺序。 认为`n = 4500`。 有效的 4 位数候选人是：`4477, 4747, 4774, 7447, 7474, 7744`答案是`4747`。 如果错误地选择了前面的数字，天真的贪婪结构可能会陷入困境。 

## 方法

 最直接的暴力想法是从`n`并一一测试每个整数。 

对于每个数字，我们都会检查其数字并检查是否：

 1. 每个数字都是`4`或者`7`。 
2. 计数`4`和`7`匹配。 

这在逻辑上是可行的，但性能却是灾难性的。 幸运数字极其稀少。 大约`10^9`，我们可能需要扫描数百万个普通整数才能找到下一个有效整数。 由于可能的值多达十亿，这种方法并不现实。 

重要的观察是答案空间本身很小。 

超级幸运数字：

 1. 仅使用数字`4`和`7`。 
2. 长度均匀。 
3. 正好包含一半`4`半个`7`s。 

我们可以直接生成每个有效的候选者，而不是搜索所有整数。 

对于每个偶数长度：

 1. 选择职位`4`s。 
2. 将剩余位置填充为`7`s。 
3. 将得到的数字序列转换为数字。 

由于我们需要的最大长度仅为 10 位数字，因此有效候选者的总数仅为 350。 

生成它们后：

 1. 对列表进行排序。 
2. 找到第一个至少为`n`。 

这将问题从搜索巨大的数字范围转变为搜索微小的预先计算的集合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(答案 - n) | O(1) | O(1) | 太慢了 |
 | 最佳| O(350 对数 350) | O(350) | 已接受 |

 ## 算法演练

 1.读取整数`n`。 
2.生成所有带长度的超级幸运数字`2, 4, 6, 8, 10`。 

我们永远不需要更长的长度，因为`n ≤ 10^9`，下一个可能的答案在 10 位数字以内。 
3.对于每个偶数长度`L`，生成所有二进制掩码`0`到`(1 << L) - 1`。 

每一位决定一个位置是否包含`4`或者`7`。 
4. 计算掩码中设置了多少位。 

有效的超级幸运号码必须准确包含`L / 2`数字等于`4`。 
5. 逐位构建数字。 

如果设置了一个位，则放置`4`。 否则放置`7`。 
6. 将构造的字符串转换为整数并存储。 
7. 对所有生成的候选者进行排序。 

排序保证数字顺序递增。 
8. 扫描排序后的列表并输出第一个数字`x`这样`x >= n`。 

### 为什么它有效

 每个超级幸运数字都有：

 1、长度均匀。 
2. 恰好一半的数字等于`4`。 
3. 所有剩余数字等于`7`。 

该算法生成满足所有相关长度的这些条件的每个字符串。 没有跳过任何有效的候选人。 

排序后，第一个大于或等于的值`n`正是最小的有效答案。 由于候选列表是完整且有序的，因此算法不会错过较小的有效数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    lucky = []

    for length in range(2, 11, 2):
        half = length // 2

        for mask in range(1 << length):
            if bin(mask).count("1") != half:
                continue

            s = []

            for i in range(length):
                if (mask >> i) & 1:
                    s.append('4')
                else:
                    s.append('7')

            lucky.append(int("".join(s)))

    lucky.sort()

    for x in lucky:
        if x >= n:
            print(x)
            return

solve()
```该方案直接实现了生成策略。 

外循环迭代从 2 到 10 的所有偶数长度。这些是此问题中超级幸运数字的唯一可能长度。 

每个位掩码代表一个数字分配。 一组位表示数字`4`，而未设置的位表示数字`7`。 支票：```
bin(mask).count("1") != half
```过滤掉不正好包含一半的掩码`4`s。 

首先将数字构建为字符串，因为数字连接更简单且不易出错。 

排序至关重要，因为掩码不会自然地按数字顺序生成数字。 

一个微妙的细节是比较：```
if x >= n:
```平等很重要。 如果`n`已经超级幸运了，必须立刻归还。 

另一个微妙之处是答案的位数可能多于`n`。 例如：```
999999999 -> 4444477777
```生成最多 10 个长度可确保正确处理这种情况。

 ## 边缘情况

 考虑输入：```
1
```该算法首先生成所有2位超级幸运数字：`47`和`74`。 

排序后，`47`是第一个满足的值`x >= 1`，所以答案是：```
47
```This case confirms that the algorithm correctly handles situations where the answer has more digits than the input.

 现在考虑：```
999999999
```No 8-digit or 9-digit super lucky number can satisfy the condition because:

 1.超级幸运数字要求长度为偶数。 
2. 所有 8 位候选数字都小于`999999999`。 

该算法继续生成 10 位候选数字。 最小的一个是：```
4444477777
```由于它是第一个大于或等于输入的有效候选者，因此它成为答案。 

最后，考虑：```
4477
```生成的候选者包括`4477`确切地。 扫描期间：

 | 候选人 | 状况 |
 | --- | --- |
 | 4477 | 4477`4477 >= 4477`是真的 |

 算法打印`4477`立即地。 这证实了比较是包容性的，完全符合问题要求。
