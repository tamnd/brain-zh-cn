 ## 解决方案
 ## 问题理解

 我们正在研究一个有根树，其中每个节点都可能受到不遵循“仅子树”或“仅路径”等单一简单模式的更新的影响。 相反，更新将其效果分为两个结构不同的区域：节点的完整子树，以及节点的直接子节点。 查询要求在多次此类更新后所有节点上的最大累积值。 

更具体地说，每个操作要么向某个节点的子树中的每个节点添加一个值，要么仅向节点的直接子节点添加一个值。 经过一系列的修改后，我们需要计算所有节点中的最大值。 

困难不在于更新本身，而在于重叠结构。 从 DFS 意义上来说，子树更新会影响大的连续区域，而“仅限子树”更新不是子树，也不对应于标准欧拉区间。 这个问题变成了树上的数据结构问题，我们必须将两种不同的结构关系映射成线性且可查询的关系。 

这些约束意味着节点和操作的数量都足够大，以至于子树的任何每次更新遍历都是不可能的。 在星形树中，为每个子树更新遍历所有后代的简单方法会降低到二次时间，因为根处的单个更新会重复触及几乎每个节点。 

当节点有许多子节点但深度较浅时，就会出现微妙的边缘情况。 例如，如果节点 1 连接到所有其他节点，则节点 1 上的“子更新”几乎会影响除节点 1 本身之外的整棵树。 一个简单的实现会将其误解为子树更新或重复重新计算邻接关系，从而会高估或低估这些贡献。 

另一个棘手的情况是重叠更新。 如果我们首先添加到以 x 为根的子树，然后添加到 x 的子树，则 x 下深度为 2 的节点仅接收子树更新，而直接子树则接收两者。 任何将这两种效应合并到单个欧拉区间的不正确展平都会产生不正确的最大值。 

## 方法

 蛮力方法很简单。 对于每次更新，我们都会显式遍历受影响的节点。 子树更新从节点执行 DFS 并将值添加到每个访问的顶点。 子更新迭代节点的邻接列表并更新每个邻居。 

这是正确的，因为它直接匹配每个操作的定义。 然而，成本变得令人望而却步。 在最坏的情况下，子树可以包含 O(n) 个节点，我们可能会重复此类操作 O(n) 次，从而导致 O(n²)。 更糟糕的是，在星形树中，子树和子树更新都会退化为 O(n) 工作，使得总运行时间显然不可行。 

关键的见解是子树更新自然是由欧拉巡演间隔处理的，但子树更新不是。 解决方案是改变遍历排序的角度，以便节点的子节点在特殊构造的 DFS 顺序中形成连续区域，即使它们在标准欧拉遍历中并不连续。 

我们使用 DFS 排序，首先记录节点本身，然后立即列出其子节点，然后再进一步深入。 这将创建一个序列，其中不包括该节点的子树分裂成一个块，其中所有子节点都出现在连续的段中。 这是关键的结构转换：我们用标准 DFS 间隔属性换取支持两种所需更新类型的自定义排序。

一旦树在此自定义顺序下线性化，这两个操作都会成为段上的范围更新。 子树更新对应于不包括某些前缀结构的大区间，而子树更新对应于局部连续的段。 这允许我们使用具有惰性传播的线段树来维护值并回答最大查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | DFS顺序+线段树 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们构建了一个基于 DFS 的排序，该排序尊重父子局部性，使两种更新类型都可以表示为间隔。 

1. 以节点 1 为树根，开始 DFS 遍历。 

我们首先在访问每个节点时添加该节点，然后按顺序处理其子节点。 这种排序确保每个节点的直接子节点紧接在该节点之后显示为连续块。 
2. 构建一个代表该遍历顺序的数组。 

每个节点接收该数组中的一个位置。 关键思想是树中的结构关系现在表示为该数组中的间隔。 
3. 确定此顺序中的两种更新模式。 

节点 x 的子树更新对应于 x 的所有后代出现的范围，但 x 本身及其直接子节点在此排序中的行为不同。 节点 x 的子节点更新对应于一个连续段，该段完全由 DFS 顺序中的子节点组成。 
4. 在线性化数组上构建线段树。 

每个位置存储该节点的累积值。 线段树支持范围添加和范围最大查询。 
5. 对于节点 x 处的子树更新，对表示子树中除直接子边界结构之外的所有节点的段应用范围加法。 

这是可行的，因为更深的后代完全包含在连续的 DFS 块中。 
6. 对于节点 x 处的子更新，对与 DFS 顺序中 x 的子块完全对应的连续段应用范围加法。 

这避免了迭代邻接列表并利用了排序属性。 
7. 处理完所有更新后，在线段树中查询所有位置的最大值。 

正确性依赖于维护树结构和 DFS 订单段之间的一致映射。 每次更新都会转换为最多一两个连续的范围，因此所有操作都保持对数。 

### 为什么它有效

 DFS 排序的构造是为了使父子关系保留局部性：每个节点的子节点在更深层次的递归将它们分开之前被分组在一起。 这保证了任何限制为“x 的所有子级”的操作都成为一个连续的区间。 同时，子树关系在DFS顺序中保持自然连续，因此子树更新也减少为间隔操作。 线段树维护可累加的可组合更新，确保重叠操作正确累积，不会重复计算或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    order = []
    parent = [0] * (n + 1)
    tin = [0] * (n + 1)
    tout = [0] * (n + 1)

    def dfs(u, p):
        parent[u] = p
        tin[u] = len(order)
        order.append(u)
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)
        tout[u] = len(order) - 1

    dfs(1, 0)

    pos = [0] * (n + 1)
    for i, v in enumerate(order):
        pos[v] = i

    size = 1
    while size < n:
        size <<= 1

    seg = [0] * (2 * size)
    lazy = [0] * (2 * size)

    def push(i):
        if lazy[i] != 0:
            seg[i * 2] += lazy[i]
            seg[i * 2 + 1] += lazy[i]
            lazy[i * 2] += lazy[i]
            lazy[i * 2 + 1] += lazy[i]
            lazy[i] = 0

    def add(l, r, val, i=1, lx=0, rx=None):
        if rx is None:
            rx = size
        if l >= rx or r <= lx:
            return
        if l <= lx and rx <= r:
            seg[i] += val
            lazy[i] += val
            return
        push(i)
        m = (lx + rx) // 2
        add(l, r, val, i * 2, lx, m)
        add(l, r, val, i * 2 + 1, m, rx)
        seg[i] = max(seg[i * 2], seg[i * 2 + 1])

    def query():
        return seg[1]

    for _ in range(q):
        t, x, v = map(int, input().split())
        if t == 1:
            add(tin[x], tout[x] + 1, v)
        else:
            if len(g[x]) == 1 and x != 1:
                continue
            l = pos[x] + 1
            r = l
            for y in g[x]:
                if y != parent[x]:
                    r = max(r, pos[y] + 1)
            add(l, r, v)

    print(query())

def main():
    solve()

if __name__ == "__main__":
    main()
```DFS 构建节点的线性顺序，并将子树边界存储在tin 和tout 中。 这些索引允许子树更新直接映射到段范围。 

线段树使用延迟传播进行范围添加，并在根处维护最大值。 推送功能确保惰性值在部分更新之前正确传播。 

子树更新使用间隔`[tin[x], tout[x]]`，这是标准的欧拉行为。 子级更新使用 DFS 顺序中直接子级的位置。 由于在这次遍历中子节点在节点之后连续出现，因此我们可以将范围从第一个子节点扩展到最后一个子节点。 

## 工作示例

 ### 示例 1

 考虑一棵简单的树：1 连接到 2 和 3，2 连接到 4 和 5。 

我们处理：

 将 1 的子树更新为 +10，然后将 2 的子树更新为 +5。 

| 步骤| 运营| 受影响的节点 | 按键间隔 |
 | --- | --- | --- | --- |
 | 1 | 儿童(1) +10 | 2,3 | [2,3]|
 | 2 | 子树(2) +5 | 2,4,5 | 子树间隔为 2 |

 步骤1后，节点2和3为+10，节点1为0。步骤2后，节点2变为+15，节点4和5变为+5，节点3仍为+10。 最大值为 15。 

这显示了子更新和子树更新之间的分离。 

### 示例 2

 树是一条链：1-2-3-4。 

操作：

 子树(2) +3，子树(1) +2，子树(1) +1。 

| 步骤| 运营| 受影响的节点 | 结果效果|
 | --- | --- | --- | --- |
 | 1 | 子树(2)+3 | 2,3,4 | 全部+3 |
 | 2 | 儿童(1)+2 | 2 | 仅节点 2 +2 |
 | 3 | 子树(1)+1 | 1,2,3,4 | 全部+1 |

 最终值变为：

 节点1=1，节点2=6，节点3=4，节点4=4。 最大值为 6。 

这确认了重叠更新正确累积。

 ## 边缘情况

 一种边缘情况是星形树，其中节点 1 连接到所有其他节点。 节点 1 上的子节点更新应该只影响直接子节点，而不影响节点 1 本身。 DFS 排序确保节点 1 被放置在第一位，并且其子节点占据下一个连续段，因此更新正确地应用于该间隔。 

另一个边缘情况是深链。 在这种情况下，子树更新变成大的连续段，但子树更新仅触及单个位置。 该算法处理这个问题是因为每个节点的子块退化为单个元素区间，无需特殊的大小写即可保持正确性。 

最后的边缘情况是具有单个子节点的节点。 在这种情况下，子间隔会折叠到一个位置。 线段树仍将其视为有效的范围更新，并且相邻不相关节点不会发生错误合并，因为 DFS 排序将兄弟组隔离为不同的线段。
