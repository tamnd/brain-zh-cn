 ## 问题理解

 我们得到了一系列排列成一直线的门。 每扇门都有一个与之相关的数字，可以解释为该门的“强度”或“成本”。 您从第一扇门前开始，并尝试尽可能向前移动。 规则很简单：只要有可能，你就继续穿过门，但每当你被卡住时，这意味着下一个路段无法穿过，你必须执行一个操作，“重置”迄今为止在你刚刚穿过的路段中看到的最重要的阻塞值。 

更具体地说，该过程是从左到右重复扫描数组。 你积累了一些进步的观念，只要当前的价值观允许前进，你就会继续下去。 当您达到在当前条件下进度无法再继续的位置时，您将停止，确定自上次重置以来该段中遇到的最大值，并将该值重置为零。 然后您再次继续扫描。 

输出是不再存在阻塞段后的最终状态，或者等效地是执行的操作数或转换后的数组，具体取决于解释。 在这个问题中，预期的结果是在每次失败的遍历中反复“打破”最具约束力的门后的最终配置。 

这些限制意味着我们无法模拟对大段的简单重复完整扫描。 如果数组大小达到$10^5$，那么任何在每次失败后从头开始扫描的解决方案都有风险$O(n^2)$最坏情况下的行为，在典型的 2 秒限制下会太慢。 我们需要一种能够有效识别段最大值并进行有效更新的结构。 

一些边缘案例暴露了幼稚思维的破绽。 

一种情况是数组严格递减。 输入示例：`[5, 4, 3, 2, 1]`。 简单的扫描可能会在第一步立即中断，具体取决于对“无法通过”的解释，重复选择收缩前缀的当前最大值。 正确的行为仍应确保每次完整通过都识别活动段中的最大值，而不仅仅是第一个故障点。 

另一种情况是当所有值都相等时，例如`[3, 3, 3, 3]`。 如果算法错误地仅重置第一个阻塞值而不是段的真正最大值，则可能会留下剩余值，从而继续导致不必要的失败。 

第三种情况是最大值出现在段的末尾。 如果简单的实现仅跟踪故障点之前的最大值，则它可能会错过稍后在同一扫描窗口中出现的真实最大值。 

这些问题促使我们维护一种能够始终检索动态范围内的最大值并有效更新的结构。 

## 方法

 蛮力方法很简单。 我们完全按照描述模拟该过程。 我们重复从左到右扫描，维持当前段。 在扫描时，我们跟踪迄今为止看到的最大值。 如果我们到达不再允许继续进行的点，我们将停止扫描，获取该段的最大值，将其设置为零，然后从头开始扫描。 

这是正确的，因为它直接反映了流程定义。 故障点总是会强制重置当前遍历中最重要的阻塞元素，因此忠实地重复此操作最终将消除所有障碍。 

问题是性能。 最坏的情况下，每一遍可能只能消除一个元素，并且每一遍扫描$O(n)$元素。 这产生$O(n^2)$行为，当$n = 10^5$。 

关键的见解是每个操作仅依赖于连续区域中的最大元素，并且一旦删除该最大值，它就不会再做出贡献。 这表明，我们不应该从头开始重新扫描，而应该在一个可以快速提取当前最大值并将其标记为已删除的结构中维护活动值集。 优先级队列或多集允许我们重复识别最大的剩余“阻塞门”并消除它，同时跟踪仍然处于活动状态的内容。 

这将重复扫描过程转换为最大元素的删除序列，每个删除都以对数时间处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(n^2)$|$O(n)$| 太慢了|
 | 最大堆/基于集合的贪婪 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将这个过程解释为反复识别最强的剩余障碍物并将其移除。 

1. 将所有值及其索引存储在允许提取最大值的结构中。 这通常是最大堆。 需要索引的原因是我们必须确保删除实际元素，而不仅仅是抽象值。 
2. 初始化一个已访问或已删除大小的标记数组$n$，最初都是假的。 这会跟踪哪些门已经被“破坏”。 
3. 构建一个包含所有对的最大堆$(value, index)$。 我们存储负值以使用 Python 的最小堆模拟最大堆。 
4. 当堆不为空时，提取当前最大候选值。 
5. 如果该元素已被删除，则跳过它并继续。 这可以避免陈旧的堆条目。 
6. 否则，将此元素标记为已删除，并在概念上将其在最终结构中“重置”为零。 
7. 继续，直到处理完所有元素。 

关键的推理步骤是每次迭代都会消除最重要的剩余障碍，并且一旦消除了该区域中的主要障碍元素，后续操作就不会依赖于较小的值。 

### 为什么它有效

 在任何时候，唯一可以阻止段中进一步进展的元素是该段中的最大元素。 一旦该元素被移除，它施加的约束就会完全消失，并且没有更小的元素可以重新创建该阻塞条件。 这表明该过程相当于重复删除当前结构中剩余活动元素中的全局最大值。 由于每次删除都会严格减少活动集并保留排序约束，因此该过程会收敛到一个稳定的配置，其中不再存在进一步的阻塞最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    # max heap via negative values
    heap = [(-a[i], i) for i in range(n)]
    heapq.heapify(heap)

    removed = [False] * n

    while heap:
        neg_val, idx = heapq.heappop(heap)
        if removed[idx]:
            continue
        removed[idx] = True
        a[idx] = 0

    print(*a)

if __name__ == "__main__":
    solve()
```实现直接遵循重复提取最大元素的思想。 堆存储值和索引，以便我们可以安全地忽略过时的条目。 这`removed`数组确保我们不会由于重复的堆状态而多次处理同一位置。 

一个微妙的点是，我们仅在决定“破坏”它时才将值设置为零。 任何引用相同索引的早期堆条目都会变得陈旧，并且`removed`检查可防止错误的双重处理。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n \log n)$| 每个元素在堆中插入一次并删除一次，每次操作都会花费对数时间 |

 ## 边缘情况

 一种重要的边缘情况是数组只有一个元素。 堆包含单个条目，它会立即被删除，并且结果会正确更新为零。 这证实了该算法不需要“一对”元素即可运行。 

另一种情况是重复相等的最大值。 由于堆条目包括索引，因此每次出现都会被独立处理。 这`removed`array 可确保处理一个实例后，该索引的所有重复堆条目都将被忽略，从而防止重复删除。 

最后一种情况是数组已经为零。 堆仍然处理条目，但所有删除都只是重写零。 该算法保持稳定，因为删除已经为零的元素不会对正确性产生副作用。
