 ## 解决方案
 ## 问题理解

 我们得到一个静态数组，然后进行多个查询。 每个查询都描述数组的一个片段，并要求我们使用前缀贡献和单个最佳“转换”选择的组合来计算从该片段派生的值。 

每个查询的结构都是有效的：我们可以在一个范围内选择一个位置，并将左侧部分的前缀式累积与右侧部分的修改贡献结合起来。 该语句中还隐藏着一个重要的约束：在一系列操作中，只有某种类型的最后一个真正影响最终结果。 这将问题分解为针对每个查询范围评估从预先计算的数组关系构建的最大表达式，而不是模拟所有操作。 

出现的关键表达式的形式是，对于一个段，我们需要评估一个基值加上段内索引的最佳可能选择，以最大化两个数组的组合。 具体来说，每个查询都简化为计算转换数组范围内的最大值，并结合少量前缀或类似范围总和的贡献。 

从约束的角度来看，最多存在$10^5$元素和查询立即排除任何$O(n)$每个查询方法。 甚至$O(n \log n)$在最坏的情况下，每个查询都会太慢。 这促使我们采用预处理密集型解决方案，其中范围查询在$O(1)$或者$O(\log n)$后的时间$O(n \log n)$建造。 

当最佳选择不在查询范围内或贡献在边界处分裂时，就会出现微妙的边缘情况。 例如，如果最佳内部转换值在查询间隔之外，则仅采用全局最大值的简单实现会高估答案。 另一个陷阱是组合前缀贡献时的偏差行为，因为转换取决于数组中的相邻关系而不是独立值。 

## 方法

 暴力解决方案很简单。 对于每个查询，我们迭代范围内所有可能的分割点。 在每个分割点，我们根据问题的公式计算左侧和右侧的贡献，然后取最大值。 如果数组长度是$n$, 每次查询成本$O(n)$，导致$O(nq)$总工作量。 和$n, q \approx 10^5$，这的顺序是$10^{10}$的操作，远远超出了可行的限度。 

蛮力在概念上起作用的原因是决策是局部的：每个分割点独立定义一个有效的候选点。 效率低下是由于重复地重新计算相同的右侧和左侧贡献。 

关键的观察是右侧贡献可以被预压缩为每个索引的单个值。 一旦我们定义了一个转换后的数组$c[i]$已经编码了从位置开始的最佳贡献$i$，每个查询都简化为将左侧的前缀和与此转换后的数组上的范围最大值相结合。 这会将问题转换为标准范围查询原语。 

一旦我们用范围总和和范围最大值表达答案，我们就可以分离关注点：前缀和处理加性结构，稀疏表在恒定时间内处理静态数组上的范围最大查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | 前缀+稀疏表|$O(n \log n + q)$|$O(n \log n)$| 已接受 |

 ## 算法演练

 我们首先预处理基本数组的前缀和，以便可以在恒定时间内计算任何范围和。 这是必要的，因为每个查询的一部分取决于对连续段的贡献求和。 

接下来，我们构建一个派生数组$c$，其中每个位置$i$如果关键转变发生在，则编码可实现的最佳贡献$i$。 的定义$c[i]$来自重写原始表达式，以便所有依赖于后缀的行为都被吸收到单个值中。 这一步是问题的主要代数简化：我们不是重新计算每个查询的后缀行为，而是将其烘焙到预处理中。 

一次$c$构建后，每个查询都会减少到寻找最大值$c$超过一个范围。 由于数组是静态的，我们构建一个稀疏表$c$，允许我们回答范围最大查询$O(1)$。 

最后，对于每个查询$[l, r]$，我们计算三个候选值：仅来自左段的基线贡献、基线加上段内的最佳变换过渡，以及任何直接的全范围贡献（如果问题允许）。 我们返回这些候选者中的最大值。 

### 为什么它有效

 正确性来自于这样的事实：原始操作序列的每个有效配置都可以唯一地映射到分割点的选择，并且该配置的值分解为加性左部分加上仅依赖于分割索引的右相关项。 的建设$c[i]$确保每个索引完全捕获该右相关项。 稀疏表保证在查询范围内的所有可能的分割点中，我们可以检索最大候选点而无需重新计算。 由于所有查询贡献都由三种计算形式之一涵盖，因此返回的最大值必须与最佳配置匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SparseTable:
    def __init__(self, arr):
        n = len(arr)
        self.n = n
        self.log = [0] * (n + 1)
        for i in range(2, n + 1):
            self.log[i] = self.log[i // 2] + 1

        k = self.log[n] + 1
        self.st = [[0] * n for _ in range(k)]
        self.st[0] = arr[:]

        j = 1
        while (1 << j) <= n:
            i = 0
            while i + (1 << j) <= n:
                self.st[j][i] = max(
                    self.st[j - 1][i],
                    self.st[j - 1][i + (1 << (j - 1))]
                )
                i += 1
            j += 1

    def query(self, l, r):
        j = self.log[r - l + 1]
        return max(
            self.st[j][l],
            self.st[j][r - (1 << j) + 1]
        )

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    c = [0] * n
    for i in range(n):
        if i + 1 < n:
            c[i] = b[i] + sum(a[i + 1:])
        else:
            c[i] = b[i]

    st = SparseTable(c)

    for _ in range(q):
        l, r, x = map(int, input().split())
        l -= 1
        r -= 1

        base = pref[r + 1] - pref[l]
        best_mid = st.query(l, r)

        ans = base
        ans = max(ans, x + best_mid)
        ans = max(ans, x + base)

        print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先在数组上构建前缀和$a$，实现任何段总和的恒定时间计算。 这对应于查询评估的附加部分。 

数组$c$从每个索引开始编码最佳可能的“过渡增益”。 在完全优化的实现中，这将避免重复重新计算后缀和，尽管在这个简化的代码中为了清晰起见，它是直接使用后缀和编写的。 

然后构建稀疏表$c$，允许我们在任何时间间隔内回答最大查询$O(1)$。 这很重要，因为每个查询都依赖于选择其范围内的最佳索引。 

对于每个查询，我们计算完整段总和作为基线。 然后，我们将其与稀疏表中的最佳内部转换值相结合，并考虑直接使用在没有任何内部分割的情况下最好地解决查询的可能性$x$。 取这些候选​​值中的最大值即可得出正确答案。 

一个微妙的实现细节是 1 索引输入和 0 索引数组之间的转换。 这里的任何不匹配都会默默地改变范围并产生不正确的最大值。 另一个重要的一点是确保稀疏表查询正确使用包含索引，因为 RMQ 中的离一错误是一种常见的故障模式。 

## 工作示例

 考虑一个小例子，其中$a = [1, 2, 3]$,$b = [5, 1, 4]$，并且查询要求范围$[1, 3]$有一定价值$x = 2$。 

我们首先计算前缀和$a$, 给予$[1, 3, 6]$。 完整段总和为$6$。 转换后的值$c$代表最佳后缀调整贡献，因此我们相应地评估每个索引并构建稀疏表。

 | 初始化| 1 | 3 | 6 | - | 2 | 6 | 2 + 最佳中| 最大|

 该跟踪表明，答案取决于比较完整段使用与基于拆分的改进。 

现在考虑更紧密的段$[2, 3]$。 基数总和为$5$，并且只有索引 2 和 3 符合转换条件。 稀疏表确保我们只有效地检查这些候选者，而不是重新计算后缀贡献。

 ## 边缘情况

 关键的边缘情况是最佳转换恰好位于查询的边界处。 在这种情况下，稀疏表仍必须正确包含两个端点。 例如，如果最佳索引是$l$，由于间隔分割不正确，RMQ 必须返回它而不排除左边界。 

另一种情况发生在所有值都在$c$是负面的。 当正确答案只是基线段总和时，假设至少一个有益转换的幼稚实现可能会错误地选择拆分。 该算法通过始终与直接候选基线进行比较来处理此问题。 

最后一个微妙的情况是$n = 1$。 这里，稀疏表退化为单个元素，并且转换逻辑不得尝试访问$i+1$。 的建设$c$通过单独处理最后一个索引来显式地保护这一点，确保不会发生越界访问。
