 ## 解决方案
 ## 问题理解

 我们正在处理二进制字符串，其中重要的结构不是单个字符，而是相等字符的连续段。 连续的每个最大段`0`s 或连续`1`s 形成一个块。 例如，字符串`0001110011`由四个块组成：`000`,`111`,`00`， 和`11`。 

允许的转换规则是用这些块来描述的。 区块不允许完全消失，但其长度是灵活的。 块可以任意拉伸或收缩，这意味着我们可以更改它包含的字符数量，但我们不能删除块或将其与其邻居合并。 重要的是块的顺序及其起始值。 

字符串转换的条件`a`成字符串`b`简化为比较它们的块结构。 如果两个字符串具有相同数量的块并且第一个块具有相同的值，则可以将一个字符串转换为另一个字符串。 

因此，每个测试用例的输入由两个二进制字符串组成，输出是在块保留规则下是否可以进行转换的决定。 

语句片段中未明确给出约束，但这种形式的问题通常允许每个测试用例使用最多 10^5 左右的字符串或更多。 这立即排除了任何模拟转换或尝试构造中间字符串的解决方案。 任何方法都必须将每个字符串减少为线性扫描以及每个测试用例的常数或对数比较。 

一个幼稚的错误是直接比较字符串或仅比较字符串的数量`0`沙`1`s。 两者都失败了，因为结构很重要。 例如，`0011`和`0101`具有相同数量的零和一，但块结构不同，并且没有允许的操作序列可以协调交替结构。 

另一个微妙的边缘情况是单字符字符串。 例如，`0`可以转换为`0000`， 但`0`无法转换为`1`即使两者的长度都是一，因为起始块不同。 

## 方法

 考虑这个问题的强力方法是模拟调整字符串中块大小的所有可能方法`a`并尝试匹配字符串`b`。 由于每个块可以自由增长或缩小，但必须保持在原位，因此唯一有意义的状态是将字符串划分为块。 暴力模拟将尝试为每个块分配长度`a`匹配`b`。 在最坏的情况下，如果两个字符串都有 n 个字符，则存在 O(n) 个块，并且由于相邻块之间的依赖性，尝试所有分配或对齐会退化为指数或至少二次匹配逻辑。 即使 n 约为 10^4，这也很快变得不可行。 

关键的观察是块边界永远不会改变。 由于块无法被破坏或合并，因此每个有效的转换都会保留块类型的确切顺序。 唯一的自由度是在每个块的长度内。 这意味着整个转换问题归结为两个游程编码之间的结构等效性检查：比较交替字符的序列是否相同。 

这将问题简化为计算两个字符串的游程编码并检查两个序列在​​长度和字符方面是否完全匹配。

 | --- | --- | --- | --- |
 | 蛮力 | 指数 / O(n²) | O(n) | 太慢了|
 | 最优（RLE 比较）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们通过将每个字符串压缩成块序列来处理它。 

1. 扫描字符串`a`从左到右并构造其游程编码。 每当当前字符与前一个字符不同时，我们就会关闭一个块并开始一个新的块。 我们只存储每个块的字符，而不存储其长度，因为长度与转换无关。 
2. 对字符串重复相同的过程`b`，产生其块序列。 
3. 比较两个序列中的块数。 如果它们不同，则无法在不合并或分裂的情况下对齐块结构，这是禁止的。 
4. 比较两个字符串的起始字符。 由于第一个块的值必须匹配，因此此处的不匹配会立即导致转换无法进行。 
5. 按位置比较每个块。 位置 i 的每个块`a`必须与相应块具有相同的字符`b`。 如果发生任何不匹配，则转换是不可能的。 
6. 如果所有检查均通过，则断定转型是可能的。 

这样做的原因是，一旦块边界固定，每个块的行为都是独立的。 由于我们可以任意扩展或缩小块，因此只要序列模式匹配，我们总是可以匹配相应块的长度。 

### 为什么它有效

 不变性是二进制串划分为最大均匀段是唯一确定的，并且在允许的操作下不能改变。 由于操作永远不会合并或破坏块，因此任何有效的转换都必须保留块标识的精确序列。 因此，当且仅当两个字符串的游程编码字符序列相同时，两个字符串在操作规则下是等效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def rle(s: str):
    blocks = []
    n = len(s)
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        blocks.append(s[i])
        i = j
    return blocks

def solve():
    t = int(input())
    for _ in range(t):
        a = input().strip()
        b = input().strip()

        ra = rle(a)
        rb = rle(b)

        if ra == rb:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该解决方案直接构造每个字符串的游程长度签名。 辅助函数扫描每个字符串一次，生成一系列块标识符。 然后比较被简化为简单的列表相等性检查。 

一个微妙的实现细节是我们根本不存储块长度。 这是安全的，因为该问题明确允许块任意增长或缩小。 存储长度只会增加噪音并带来不正确比较的风险。 

正确性完全取决于邻接结构不变的事实，而不是每个块内的实际计数。 

## 工作示例

 ### 示例 1

 考虑`a = 0001110`和`b = 001110`。 

为了`a`，块是：

 | 步骤| 指数范围| 块|
 | --- | --- | --- |
 | 1 | 0-2 | 0 |
 | 2 | 3-5 | 3-5 1 |
 | 3 | 6-6 | 0 |

 所以`ra = [0, 1, 0]`。 

为了`b`，块是：

 | 步骤| 指数范围| 块|
 | --- | --- | --- |
 | 1 | 0-1 | 0 |
 | 2 | 2-4 | 2-4 1 |
 | 3 | 5-5 | 5-5 0 |

 所以`rb = [0, 1, 0]`。 

由于序列匹配，因此输出为`YES`。 

这证实了不同的块长度并不重要。 

### 示例 2

 让`a = 010`和`b = 001`。 

为了`a`，块是`[0, 1, 0]`。 

为了`b`，块是`[0, 1]`。 

| 字符串 | 块序列|
 | --- | --- |
 | 一个 | [0, 1, 0] |
 | 乙| [0, 1] |

 由于块数不同，无法转换，因此输出为`NO`。 

这表明即使总计数相似，不匹配的交替也会破坏可行性。

 ## 边缘情况

 一种重要的边缘情况是两个字符串都包含单个重复字符。 例如，`a = 0000`和`b = 0`。 该算法将两者压缩成一个块`[0]`，所以输出是`YES`。 这反映了块长度无关紧要的事实。 

另一个边缘情况是当字符串具有相同的计数时`0`和`1`但不同的交替模式，例如`0011`和`0101`。 第一个产生`[0, 1]`而第二个产生`[0, 1, 0, 1]`，立即拒绝转换。 该算法正确地捕获了这一点，因为它在压缩过程中永远不会丢失边界信息。 

最后的边缘情况是交替单字符字符串，例如`010101`相对`0101010`。 尽管两者看起来相似，但块计数相差一，并且算法在比较步骤中拒绝它，匹配块结构必须相同的不变量。
