 ## 解决方案
 ## 问题理解

 我们得到一个整数区间的集合。 每个区间代表一个允许值的范围，我们试图确定是否存在一个整数，它在类似 GCD 的约束下在所有区间内表现一致。 

该问题分为两种不同的情况，具体取决于所有区间是否都是“严格的”，或者是否至少有一个区间崩溃为单个固定值。 如果每个间隔都有正长度，意味着其左端点严格小于右端点，则不存在单个强制值。 在这种情况下，输出只是全偶数，这意味着问题的结构退化为独立于输入细节的统一答案。 

当至少一个区间退化为单个点时，就会出现有趣的情况，这意味着对于某些 i，li 等于 ri。 在这种情况下，该值成为锚点 X。我们将 X 分解为其素数因子，对于每个这样的素数 p，我们必须确保一致性条件：每个区间必须至少包含 p 的倍数。 如果这对于任何素数都是不可能的，那么该素数的构造就会失败。 

从计算的角度来看，区间的数量可能很大，因此任何解决方案都必须避免区间和因子检查之间的二次交互。 主要运算必须与 n 加上单个数字的因式分解成本呈线性。 这排除了显式检查每个区间内的每个候选值的情况。 

当存在多个固定间隔时，会出现微妙的边缘情况。 如果有多个 i 使得 li 等于 ri，那么它们必须都代表同一个 X，否则根本没有一致的锚点。 例如，如果一个区间强制 X = 12，而另一个区间强制 X = 18，则问题会立即变得不一致，因为没有共享的基值可供分解。 

当间隔不固定但输出规则为“全偶数”时，会出现另一种边缘情况。 一个幼稚的实现可能会尝试从间隔中计算一些东西并产生不一致的结果，但正确的行为完全独立于该分支中的输入结构。 

## 方法

 直接的暴力方法将尝试测试间隔隐含的所有可能的候选整数。 人们可能会尝试迭代任何区间端点中出现的所有值，或固定区间内的所有值，然后检查每个候选值是否满足以下条件：对于每个区间 [li, ri]，其内部存在每个所需素数的倍数。 

这立即变得不可行，因为即使是大小为 10^9 的单个区间也会引入太多候选者。 即使我们将自己限制在端点上，我们仍然需要根据所有间隔验证每个候选者，在最坏的情况下导致 O(n^2) 检查。 

关键的观察结果是，当单个强制值 X 存在时，整个结构就会崩溃。 我们不需要探索所有候选者，而只需要考虑除 X 的素数。问题简化为验证，对于每个这样的素数 p，每个区间是否至少包含 p 的一个倍数。 这将问题从搜索值转移到检查整除覆盖率。 

对于区间[l,r]，检查其是否包含p的倍数相当于检查p不小于l的最小倍数是否仍在r内。 每个时间间隔可以在 O(1) 内完成。 因此，一旦 X 固定，整个验证就变得与 n 呈线性关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力对待候选人| O(n·R) 或更糟 | O(1) | O(1) | 太慢了|
 | 检查固定 X + 质因数 | O(n + sqrt(X)) | O(n + sqrt(X)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 1.检测是否有强制值

我们扫描所有间隔。 如果每个区间都满足 li < ri，则没有区间可以确定特定值，因此我们立即根据需要输出所有偶数。 

如果至少一个区间满足 li = ri，我们记录该值。 如果存在多个这样的区间，它们必须全部一致； 否则答案是不可能的，因为单个 X 不能满足两个不同的固定约束。 

### 2.提取锚点值X

 一旦我们知道存在有效的固定区间，我们就将 X 设置为其值。 如果存在多个固定区间，我们通过将所有这些区间与 X 进行比较来验证一致性。 

此步骤是必要的，因为所有后续推理都取决于 X 的明确定义。 如果没有一致的锚点，因式分解就没有意义。 

### 3. 将 X 分解为素因数

 我们计算 X 的素数分解并收集除 X 的所有不同素数 p。这些素数代表了问题其余部分中唯一重要的约束。 

我们只关心不同素数的原因是，如果 p 除 X，确保每个区间中存在 p 的倍数就足够了，无论指数如何。 

### 4. 验证每个素数跨区间的覆盖范围

 对于每个素数 p，我们检查每个区间 [l, r]。 我们计算 p 的第一个不小于 l 的倍数，即 ((l + p - 1) // p) * p。 如果该值超过r，则该区间不包含p的倍数，并且p无效。 

如果任何素数未通过此检查，则该 X 的构造将失败。 

### 5. 汇总结果

 如果所有素数都通过了区间覆盖测试，我们接受配置； 否则，我们将拒绝它。 

### 为什么它有效

 该算法将问题简化为验证由素数除 X 定义的算术级数的覆盖范围。关键的不变量是任何有效的解决方案都必须遵守由 X 引起的整除性约束，并且这些约束在素数之间是独立的。 由于 X 的每个整数倍同时也是每个素数因子的倍数，因此确保每个素数的覆盖范围相当于确保 X 本身的覆盖范围。 区间检查保证没有区间排除所需质数的所有倍数，否则会破坏可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def factorize(x):
    primes = []
    d = 2
    while d * d <= x:
        if x % d == 0:
            primes.append(d)
            while x % d == 0:
                x //= d
        d += 1
    if x > 1:
        primes.append(x)
    return primes

def ok(intervals, p):
    for l, r in intervals:
        first = ((l + p - 1) // p) * p
        if first > r:
            return False
    return True

def solve():
    n = int(input())
    intervals = []
    fixed = None

    for _ in range(n):
        l, r = map(int, input().split())
        intervals.append((l, r))
        if l == r:
            if fixed is None:
                fixed = l
            elif fixed != l:
                print("NO")
                return

    if fixed is None:
        print("EVEN")
        return

    X = fixed
    primes = factorize(X)

    for p in primes:
        if not ok(intervals, p):
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```该解决方案首先解析所有区间并识别是否存在固定点。 立即处理多个固定间隔的一致性检查，以避免将矛盾传播到后续阶段。 

因式分解例程是高达 sqrt(X) 的标准试除法。 由于 X 直接从输入端点导出，因此它在典型约束下仍然有效。 

关键的验证步骤封装在`ok`函数，它计算每个区间内每个素数的第一个可达倍数。 这避免了显式地迭代所有倍数。 

最终决策清晰地分为三种情况：没有固定间隔导致偶数输出，不一致的固定间隔导致拒绝，有效的 X 导致逐个素数验证。

 ## 边缘情况

 一种重要的边缘情况是多个固定间隔不一致时。 假设输入包含 [5,5] 和 [7,7]。 该算法首先检测到fixed = 5，然后在遇到7时立即拒绝，以防止任何无效的因式分解步骤。 这避免了构建不可能的锚点。 

另一种情况是当 X 是素数时。 例如，X = 13 导致素数 = [13]。 该算法检查每个区间是否至少包含 13 的倍数。如果有一个区间完全位于 1 和 12 之间或位于 13 的非倍数之间，则检查会立即失败。 这表明单素数分解将问题简化为周期序列的纯区间覆盖。
