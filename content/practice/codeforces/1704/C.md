 ## 解决方案
 ## 问题理解

 我们得到了一个圆形排列的房屋，其中一些位置最初被感染。 每天由两个阶段组成：首先，我们永久保护一个当前安全的房屋，然后感染从每个受感染的房屋传播到所有相邻的未受保护和未受感染的房屋。 

目标是选择保护顺序，以便在感染不再传播后，受感染房屋的总数尽可能少。 

看待这一过程的一个有用方法是将受感染的房屋想象成沿着圆圈向外扩展的“源头”，而我们的保护措施则充当阻止这种扩展的障碍。 一旦房屋受到保护，它就成为永久的墙，不能被感染或被用于进一步传播。 

输入大小使得解决方案的结构变得很重要。 尽管房屋数量 n 可能非常大，高达 10^9，但在所有测试用例中，受感染房屋的总数很小。 这立即表明我们无法模拟整个循环的过程。 任何跟踪单个房屋或模拟逐日扩张的方法都太慢了。 

关键的隐藏结构是只有受感染位置之间的间隙才重要。 该圆圈被有效地分成受感染房屋之间的健康房屋的各个部分，只有这些部分才能决定感染如何传播以及设置保护措施的有用性。 

当只有一所受感染的房屋时，就会出现一种微妙的边缘情况。 在这种情况下，感染会沿着圆圈向两个方向对称传播，答案完全取决于我们能够以多快的速度阻止单一来源的传播。 将其视为多个片段的天真的贪婪策略将会失败，因为感染之间没有内部边界。 

另一个棘手的情况是受感染的位置均匀分布。 在这里，所有差距都是平等的，贪婪的选择必须正确地优先考虑首先打破更大的有效价差，即使局部一切看起来都是对称的。 

## 方法

 暴力模拟会尝试每天对过程进行建模。 每天我们都会选择一个安全屋，将其标记为受保护，然后扩大所有当前受感染细胞的感染范围。 由于每次扩展都可能触及许多新房屋，因此最坏的情况会退化为重复扫描圆圈的大部分区域。 当 n 达到 10^9 时，甚至存储状态也是不可能的，而且即使我们压缩状态，跨段的重复传播仍然与每天受影响的间隔大小呈线性关系，导致最多 m 步的爆炸。 

关键的观察结果是，感染在圆圈上最初感染的房屋之间的每个间隙内独立传播。 如果我们对受感染的位置进行排序，圆圈就会变成一系列间隙。 每个间隙的行为就像由两个受感染端点（或环绕情况下的一个端点）界定的线性段。 感染从两侧向内扩展，我们的防护措施可以花费数天时间来阻止这种扩展。 

贪婪策略来自于比较每个间隙被感染“吃掉”的速度与我们放置保护块的速度。 每天我们都可以有效地推迟一个单位的扩建，因此最好的策略是始终优先考虑保存最大的剩余健康房屋部分。 

形式上，对于每个大小为 x 的间隙，感染将从两侧消耗它，并且可以保存的房屋数量取决于我们多久开始阻止它。 对这些差距进行排序并按降序处理它们可以实现保护天数的最佳分配。 

直觉是，大的间隙是有价值的，因为它们需要更长的时间才能完全感染，因此它们提供了更多机会在其中放置防护墙。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n·m) 或更糟 | O(n) | 太慢了|
 | 间隙+贪婪排序| O(m log m) | O(米) | 已接受 |

 ## 算法演练

 1. 沿圆圈对感染位置进行排序。 这对于正确计算连续受感染房屋之间的间隙是必要的。 
2. 按循环顺序计算相邻感染位置之间的所有间隙。 对于两个连续的受感染房屋 a 和 b，间隙为 b - a - 1，对于环绕间隙，其为 n - 最后 + 第一个 - 1。这些间隙代表最初安全屋的独立延伸。 
3. 按降序对间隙进行排序。 这种排序反映了优先考虑感染压力最高或干预措施能挽救最多房屋的地区。 
4. 初始化一个表示过去天数的变量。 这可以跟踪保护措施有效阻止了多少层感染。 
5. 迭代已排序的间隙。 对于每个间隙，从其大小中减去已使用天数的两倍，因为感染从两端向内推进，而保护会消耗时间。 如果结果值为正，请将其添加到答案中并适当增加日计数器。 
6. 累积受感染房屋的总数作为间隙内所有保存的部分的补充。 

### 为什么它有效

 每个间隙的行为都是独立的，因为感染不能越过最初感染的房屋。 在间隙内，感染从两端对称进行，除非被堵塞，否则每天将有效可用空间减少两个单位。 由于每种保护措施都会通过有效消耗一天的生长来延迟扩张，因此将较早的日子分配到较大的间隙总是比延迟它们保留更多的细胞。 这创建了一个单调的收益结构，其中按间隙大小进行贪婪排序是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    if m == n:
        print(n)
        continue
    
    a.sort()
    
    gaps = []
    for i in range(m - 1):
        gaps.append(a[i + 1] - a[i] - 1)
    gaps.append(n - a[-1] + a[0] - 1)
    
    gaps.sort(reverse=True)
    
    saved = 0
    days = 0
    
    for g in gaps:
        effective = g - 2 * days
        if effective <= 0:
            continue
        effective -= 1
        if effective > 0:
            saved += effective
            days += 2
    
    print(n - saved)
```该代码首先标准化受感染的位置并构造所有圆形间隙。 排序确保我们始终首先处理最有价值的区域。 

变量`days`模拟已经积累了多少感染压力，代表双方有多少层已经被早期的保护所抵消。 每个间隙都相应减小。 减法为`2 * days`捕捉感染从两端传播的对称性质。 

最终答案的计算方式为总房屋数减去可避免感染的房屋数。 

## 工作示例

 ### 示例 1

 输入：

 n = 10，感染者 = [3,6,8]

 感染者排序：[3,6,8]

 差距是：

 | 步骤| 计算间隙 |
 | --- | --- |
 | 3 → 6 | 2 |
 | 6 → 8 | 1 |
 | 8 → 3（换行）| 4 |

 已排序的间隙：[4,2,1]

 我们首先处理最大的差距。 

| 差距| 天| 有效| 已保存 |
 | --- | --- | --- | --- |
 | 4 | 0 | 4 | 3 |
 | 2 | 2 | 0 | 0 |
 | 1 | 2 | 0 | 0 |

 总共获救 = 3，因此被感染 = 10 - 3 = 7。 

这表明只有最大的细分市场才有意义，因为较小的细分市场被先前的传播压力压垮了。 

### 示例 2

 输入：

 n = 10，感染者 = [2, 5]

 已排序感染者：[2, 5]

 差距：

 | 步骤| 差距|
 | --- | --- |
 | 2 → 5 | 2 |
 | 5 → 2 | 5 |

 排序：[5, 2]

 | 差距| 天| 有效| 已保存 |
 | --- | --- | --- | --- |
 | 5 | 0 | 5 | 4 |
 | 2 | 2 | 0 | 0 |

 获救总数 = 4，感染者 = 6。 

这证实了环绕段受到同等对待，并且在较大时主导该过程。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m log m) | 对受感染位置和间隙进行排序占主导地位，采用线性间隙处理 |
 | 空间| O(米) | 只存储感染位置和间隙数组 |

 这些约束允许测试用例中总共最多有 10^5 个受感染位置，因此每个测试用例的排序就足够了。 该解决方案很容易满足限制，因为所有操作都是线性的或接近线性的（以 m 为单位）。

 ## 边缘情况

 单个受感染的房屋将问题简化为单个圆形扩展区域。 该算法创建一个大的环绕间隙并正确评估它，而不依赖于多个感染点之间的任何邻接结构。 

当所有房屋都被感染时，间隙构造到处都会产生零，并且算法立即返回 n，因为没有空间可以保存。 

当受感染的房屋均匀分布时，所有间隙都是相等的，并且排序会保持任意顺序。 贪婪仍然有效，因为每个间隙都通过相同的感染压力项统一减少，确保没有间隙被错误地优先排序。 

在所有情况下，行为仅取决于相对间隙大小和由日进展引起的线性衰减，这与过程的实际对称扩散动态相匹配。
