 ## 解决方案
 ## 问题理解

 我们得到一个字符串`s`长度`n`和目标长度`k`。 我们的目标是构造一个长度精确的字符串`k`通过执行任意次数的两个操作：删除当前字符串的最后一个字符，或者通过将字符串与其自身连接来复制字符串。 最终的字符串应该是这些操作的所有可能结果中按字典顺序最小的。 

实际上，我们可以将字符串缩小到任何前缀`s`然后反复加倍，直到超过或达到长度`k`。 之后，我们可以修剪多余的部分以达到精确的长度`k`。 词典比较是标准的：字符串逐个字符进行比较，如果所有比较的字符都匹配，则较短的前缀较小。 

简易版本的限制限制`n`和`k`最多 5000。这使我们能够使用具有二次或接近二次复杂度的算法。 生成所有可能的删除和重复序列的简单蛮力将呈指数级增长`n`，甚至构建所有长度的前缀`k`如果不优化的话，重复会太慢。 

一个微妙的边缘情况是初始前缀已经最小。 例如，给定`s = "abc"`和`k = 5`，最优结果为`"aaaaa"`，通过取前缀得到`"a"`并反复加倍。 如果一个简单的算法总是以完整的字符串开始，它可能会错误地产生`"abcab"`，按字典顺序排列更大。 

当最佳前缀长于 1 但不是完整字符串时，会出现另一种边缘情况。 为了`s = "dbcadabc"`和`k = 16`，从完整字符串开始并重复给出`"dbcadabcdbcadabc"`，这恰好是最优的。 因此，该算法必须检查所有可能的前缀。 

## 方法

 蛮力方法是考虑每个前缀`s`，然后重复复制该前缀，直到其长度至少为`k`，最后精确截断为`k`。 然后我们将比较所有结果以按字典顺序找到最小的结果。 这是正确的，因为任何可实现的字符串都必须从某个前缀派生，但如果简单地实现，它可能会很慢。 为了`n = 5000`和`k = 5000`，简单的字符串连接可能需要最多`5000 * 5000`字符操作，这接近 Python 中可接受的性能极限。 

关键的观察结果是，这些操作将我们限制在前缀和重复加倍上。 一旦选择了前缀，结果字符串就被唯一确定：不断加倍直到达到长度`k`然后截断。 这将问题简化为迭代所有前缀、使用字符串乘法有效地生成扩展字符串并比较结果。 由于字符串乘法在大多数语言中都得到了优化，因此这种方法可以在以下环境中轻松运行：`O(n * k)`时间。 

这一观察使我们能够避免组合爆炸。 我们永远不需要考虑任意的​​删除和重复序列，只需要考虑`n`可能的前缀`s`。

 | --- | --- | --- | --- |
 | 蛮力 | O(n * k) | O(k) | 已接受 |
 | 优化前缀加倍 | O(n * k) | O(k) | 已接受 |

 ## 算法演练

 1. 初始化变量`best`到完整的字符串`s`乘以或截断长度`k`。 这将存储迄今为止找到的最小字符串。 
2. 迭代所有可能的前缀`s`。 对于索引`i`从`0`到`n-1`， 让`prefix = s[0:i+1]`。 
3. 对于每个前缀，计算重复扩展长度`k`。 这是通过将前缀乘以足够多的次数来完成的`k`然后精确截断为`k`。 
4. 将生成的字符串与`best`。 如果按字典顺序更小，则更新`best`。 
5. 考虑完所有前缀后，打印`best`。 

为什么它有效：通过允许的操作可获得的任何字符串都必须以以下前缀开头`s`。 一旦前缀被固定，重复加倍然后截断就生成一个长度的候选字符串`k`。 比较所有这些候选者可以保证选择最少的一个。 不变的是`best`始终保存迄今为止考虑的前缀中按字典顺序最小的字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
s = input().strip()

best = s[0] * k  # initialize with the minimal possible string using only first character

for i in range(n):
    prefix = s[:i+1]
    repeat_times = (k + len(prefix) - 1) // len(prefix)
    candidate = (prefix * repeat_times)[:k]
    if candidate < best:
        best = candidate

print(best)
```每个部分直接对应于算法步骤。 关键细节是计算`repeat_times`确保相乘的前缀覆盖长度`k`。 这里的相差一错误可以通过以下方式避免`(k + len(prefix) - 1) // len(prefix)`。 我们初始化`best`用尽可能小的字符串，`s[0] * k`，以避免与未初始化的值进行比较。

 ## 边缘情况

 对于`s = "zxy", k = 6`，该算法考虑前缀`"z"`,`"zx"`,`"zxy"`。 仅有的`"z"`重复给予`"zzzzzz"`。 虽然`"zx"`更长，`"zzzzzz" < "zxzxzx"`。 前缀迭代保证始终找到最小的词典前缀，从而正确处理这种边缘情况。 

为了`s = "aaaa", k = 10`，所有前缀生成`"aaaaaaaaaa"`，所以算法自然会选择`"a"*10`。 不会发生不必要的重复或比较错误，因为重复的字符串乘法和截断会产生精确的长度`k`。
