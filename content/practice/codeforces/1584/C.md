 ## 解决方案
 ## 问题理解

 我们有两个长度相等的整数数组。 第一个数组上允许的操作非常具体：我们可以选择位置的一些子集，并将每个选定的元素恰好增加 1。 之后，我们就可以自由地对数组进行重新排序。 

问题是我们是否可以使用一个这样的操作阶段将第一个数组转换为第二个数组。 

重新排序步骤至关重要，因为它消除了任何位置限制。 在增量步骤之后，只有值的多重集很重要，而不是它们来自哪里。 这意味着问题从根本上讲是关于我们是否可以通过向第一个多重集的某些元素添加一个来将一个整数多重集转换为另一个整数多重集。 

约束很小，数组大小最多 100 个，测试用例最多 100 个。 对于单个测试来说，对元素子集的直接指数搜索在原始形式中已经是可以接受的，但在所有情况下进行清晰推理时则不然。 尽管如此，小的限制表明排序和线性检查可能就足够了，并且任何涉及子集组合枚举的解决方案都是不必要的。 

过度思考排列步骤会产生一个微妙的陷阱。 例如，人们可能会尝试直接匹配索引并贪婪地决定每个位置。 这会失败，因为最终的排列允许任意重新分配。 

另一个常见的错误是假设我们可以根据固定的顺序独立决定每个位置是否必须递增。 由于排列发生在增量之后，因此正确的观点是比较排序结构，而不是原始索引。 

考虑这种失败模式：如果我们尝试按原始顺序匹配元素，即使增量后存在有效排列，我们也可能错误地得出不可能性的结论。 重新排序完全破坏了位置意义。 

## 方法

 暴力方法会尝试增加索引的每个子集。 对于每个子集，我们将应用增量，然后排序并与目标数组进行比较。 有 2^n 个子集，每次检查的成本为 O(n log n)，即使 n 只有 100，这也很快变得不可行，因为常数因子巨大并且结构是不必要的。 

关键的观察结果是该操作仅将值更改 +1，并且不会引入任何其他转换。 这意味着最终数组中的每个元素必须来自原始数组中的元素，要么保持不变，要么增加一次。 对两个数组进行排序后，我们实际上尝试确定目标数组的每个元素是否可以与源数组的元素匹配（差异为 0 或 1），并且每个 +1 操作对于每个选定元素仅使用一次。 

一旦两个数组都排序完毕，自然配对就成为测试可行性的最佳结构。 最小的元素必须与最小的目标对齐； 否则，低端的不匹配无法通过稍后重新排序来修复。 这将问题简化为排序后的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（子集枚举）| O(2^n · n log n) | O(2^n · n log n) | O(n) | 太慢了 |
 | 排序+贪心匹配| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个测试用例简化为两个排序数组之间的比较。

1. 按非降序对两个数组进行排序。 这消除了最终排列步骤引入的所有位置歧义。 
2. 计算数组总和之间的总差。 该值表示必须增加多少个元素，因为每个操作都会将总和恰好增加 1。 
3. 从左到右比较排序数组的对应元素。 对于每个位置，检查目标值是否至少等于源值。 如果任何目标值较小，则任何 +1 操作序列都无法解决此问题。 
4. 对于每一对，计算差异。 每个差值必须为 0 或 1，因为每个元素最多只能递增一次。 
5. 验证 +1 差异的总数是否与之前计算的差异总和相符。 

该决定取决于局部可行性（每个元素只能增加一）和全局可行性（总增量必须与所需的增量总和相匹配）之间的一致性。 

### 为什么它有效

 排序后，我们将最小的可用值配对在一起。 如果目标数组中的较小元素与源中的较大元素配对，则交换伙伴无法修复不匹配，因为所有较大的源元素只会使未来的配对恶化。 这种贪婪对齐确保如果存在任何有效的转换，它将出现在排序顺序配对下。 每个元素只能递增 1 的限制强制排序配对中每个位置的二进制选择，这充分描述了转换的特征。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort()
        
        diff_sum = 0
        ok = True
        
        for i in range(n):
            if b[i] < a[i]:
                ok = False
            diff_sum += (b[i] - a[i])
            if b[i] - a[i] > 1:
                ok = False
        
        print("YES" if ok and diff_sum == sum(b) - sum(a) else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先对两个数组进行排序，以便我们可以将它们作为多重集进行推理。 然后，循环同时检查两个约束：是否有任何目标值小于其配对的源值，以及是否有任何元素需要多个增量才能达到其目标。 如果我们遵循这种配对，累积的差异将跟踪需要多少次 +1 操作。 

最终的比较确保了局部约束与全局要求之间的一致性`sum(b) - sum(a)`必须执行增量。

 ## 边缘情况

 一种常见的边缘情况是总和差与元素数量匹配，但一个元素需要多个增量。 例如，改造`[0, 0]`进入`[2, 0]`其总和差为 2，但仍然失败，因为单个元素需要两次增量。 排序使这种失败立即可见，因为一对变成`(0, 2)`。 

当值总体相等但局部不匹配时，会出现另一种边缘情况。 例如，`[1, 3]`到`[2, 2]`保留总和，但排序配对产生`(1, 2)`和`(3, 2)`，揭示了目标小于源的违规，无法通过排列修复。 

该算法正确地拒绝了这两种情况，因为它通过总和跟踪强制执行每个元素的局部可行性和全局一致性。
