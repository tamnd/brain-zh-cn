 ## 解决方案
 ## 问题理解

 我们得到一个表示一行单元格的二进制目标字符串，最初都是白色的。 唯一允许的操作作用于两个相邻的单元格：当我们选择一个索引时$i$，我们强制设置单元格$i$白色和细胞$i+1$变为黑色，无论其之前的状态如何。 

目标是确定此类局部操作的某些序列是否可以将全白线转换为所需的黑白图案，如果可以，则输出任何有效的移动序列。 

每个操作只触及两个相邻位置，并且总是以固定的不对称方式覆盖它们：左侧单元格变为白色，右侧单元格变为黑色。 这种不对称性是问题结构的全部根源。 

约束条件$n \le 100$意味着构建不需要高级优化。 每个测试用例的工作量为二次方，甚至在一个小的恒定范围内为三次方的任何解决方案都可以顺利通过。 操作的数量也被限制在一个适度的值，因此我们期望显式地构造一个序列，而不仅仅是决定可行性。 

一个微妙的边缘情况是目标字符串已经全白。 在这种情况下，不需要任何操作，任何“修复”单元的尝试都只能引入不需要的黑色单元，因此答案必须是空序列。 

另一个重要的边缘情况是当黑色单元格出现在最后一个位置时。 由于创建黑色单元的每个操作总是将其创建为某个选定对的右端点，并且右侧没有单元$n$，最后一个位置只有作为索引的右端点配对时才会变黑$n-1$。 这已经暗示该结构本质上是关于放置正确的操作端点。 

更具欺骗性的情况是交替模式，例如$1010$。 尝试从左到右修复而不重新考虑早期选择的天真贪婪可能会失败，因为每个操作都会覆盖两个位置，因此局部修正可能会破坏早期的正确性。 

## 方法

 蛮力的想法是将过程视为所有状态图$2^n$二进制字符串并从空配置运行 BFS。 每个州最多有$n-1$过渡，所以边的数量是$O(n 2^n)$。 即使对于$n=100$，但更重要的是它忽略了结构：大多数状态都是无关紧要的，因为操作总是以非常特定的方式引入黑色单元，并且不能任意删除它们。 

关键的观察结果是黑细胞不是独立的。 每次操作都会在位置创建一个黑色单元格$i+1$，同时强制位置$i$至白色。 这意味着黑色单元始终由某些操作“拥有”，其右端点正是该位置。 反过来思考，每个黑色单元格必须由至少一个针对其左邻居的操作来解释。 

这建议从右向左扫描。 当我们在位置看到需要的黑色时$i$，创建它的唯一方法是在$i-1$。 一旦我们决定使用操作$i-1$，我们立即知道对阵列的局部影响。 这消除了全局搜索的需要：每个黑色单元强制执行确定性的局部操作。 

剩下的问题是相邻强制操作之间的相互作用是否可以相互矛盾。 该结构解决了这个问题，因为操作总是强制将右侧单元格设置为黑色。 如果我们从右向左处理，我们可以确保一旦某个位置被固定为黑色，后面的操作就不会以冲突的方式再次触及它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 |$O(n 2^n)$|$O(2^n)$| 太慢了|
 | 从右到左的构造 |$O(n)$每次测试|$O(n)$| 已接受 |

 ## 算法演练

 1. 从最终阵列开始，最初全部为白色，因为这与起始配置匹配。 
2.从右向左扫描目标字符串，从index开始$n$下降到$2$。 从右到左的原因是每个在位置创建黑色单元格的操作$i$仅取决于位置$i-1$，因此从末尾开始处理可以防止以后的修改干扰已经解析的位置。 
3. 当目标处于位置时$i$是黑色的，我们通过在索引处应用操作来强制它$i-1$。 此操作保证位置$i$变成黑色，符合要求。 
4. 应用操作后，显式更新工作数组：设置位置$i-1$到白色并定位$i$至黑色。 这使模拟与操作的覆盖行为保持一致。 
5. 如果目标在位置$i$是白色的，什么也不做。 任何影响的操作$i$会迫使它变黑，所以保持不变是唯一有效的选择。 
6. 扫描完成后，检查位置$1$。 如果目标中是黑色的，则无法创建它，因为没有操作写入位置$1$作为右端点。 在这种情况下输出NO。 
7. 否则输出 YES 以及记录的操作。 

正确性取决于单调性：一旦一个位置$i$已处理，选择的所有操作仅影响位置$\ge i$，并且以后都不需要更改$i$再次。 从右到左的排序确保每个黑色单元都通过其独特的可能的生成器操作“支付”一次，并且早期的决定不会在以后失效，因为所有未来的操作都严格位于左侧。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s = list(input().strip())
        
        ops = []
        cur = ['0'] + s[:]  # 1-indexed
        
        possible = True
        
        for i in range(n, 1, -1):
            if s[i - 1] == '1':
                ops.append(i - 1)
                cur[i - 1] = '0'
                cur[i] = '1'
        
        if s[0] == '1':
            possible = False
        
        if not possible:
            out.append("NO")
        else:
            out.append("YES")
            out.append(str(len(ops)))
            if ops:
                out.append(" ".join(map(str, ops)))
            else:
                out.append("")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现保留了一个简单的模拟数组来反映每个操作的效果。 该数组是 1 索引的，以匹配问题的操作定义，这避免了应用时出现差一错误$i-1$运营。 

主循环处理索引$n$下降到$2$。 每当需要黑色单元时，我们立即附加相应的操作并更新模拟状态。 这确保了如果多个操作影响重叠对，则最新的强制约束始终支配早期的假设。 

对第一个单元格的最终检查至关重要，因为没有任何操作可以在位置 1 处生成黑色单元格。由于操作的固定方向，任何间接导出它的尝试都会失败。

 ## 边缘情况

 当字符串已经全为零时，扫描不会产生任何操作，因为不需要创建黑色单元。 该算法自然会返回一个空的操作列表，与恒等变换有效的事实相匹配。 

当黑色出现在位置 1 时，算法会立即拒绝，因为没有任何操作可以将位置 1 设置为黑色作为右端点。 尽管位置 1 可以重复地被覆盖为白色，但没有机制在那里引入黑色，因此任何试图强制它的构造都会失败。 

当字符串为全黑时，算法在从 1 到 n-1 的每个位置上进行操作。 每个步骤都确保满足右端点，并且重复覆盖较早的位置以保持与后面的约束的一致性，这是可以接受的，因为始终仅通过向左操作重新访问较早的位置。
