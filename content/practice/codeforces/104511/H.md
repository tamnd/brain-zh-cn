 ## 解决方案
 ## 问题理解

 我们有一个网格，其中一些单元格包含树木，其他单元格是空地。 目标是为每个树单元分配一个“天数”，以便最终删除所有树，并且计划遵循一个关键约束：只有当前可以通过空单元从网格边界到达树时，才能在某一天删除树。 

工人每天的工作量是有限的，因此即使有很多树木有资格被移除，最多也只能$k$其中可以在同一天进行切割。 树木会在几天内被移除，一旦树木被移除，它就会变成空的，可以帮助其他树木变得可到达。 

输出是每个树单元的标签及其被砍伐的日期，形成一个有效的计划，在尊重可达性条件和每日工人限制的同时删除所有树木。 我们可以自由选择任何有效的时间表，但我们希望尽量减少天数。 

关键的结构约束是“可移除”取决于通过空白空间到边界的连接，随着树木的移除，边界会动态变化。 这使得天真的贪婪策略变得不可靠，除非它们明确地模拟可访问性如何演变。 

约束很大，许多测试用例的网格多达 500 x 500。 这意味着我们无法从头开始重新计算每天或每棵树的可达性。 任何每步重复运行洪水填充或 BFS 的解决方案都会太慢。 

当一棵树被其他树包围但只有在多次删除后才能到达时，就会出现微妙的边缘情况。 根据初始可达性提前分配它的幼稚策略将会失败，因为可达性不是静态的。 

## 方法

 暴力策略会日复一日地模拟这个过程。 每天，我们扫描所有树，从边界到空单元格运行 BFS，标记所有当前可到达的树，并分配最多$k$其中直到今天。 然后我们删除它们并重复。 

这是正确的，因为它直接遵循规则。 然而，每个 BFS 都是$O(n^2)$，我们可以重复直到$O(n^2 / k)$在最坏的情况下，会导致整体二次或更糟糕的复杂性。 

关键的见解是扭转观点。 我们没有考虑“树何时可达”，而是根据每棵树嵌套在障碍物内的深度来为其分配优先级。 较难到达的树应稍后安排。 这建议计算距边界的类似距离的值，但在图表中不允许穿过树木移动，除非它们已经被移除。 

我们可以将其建模为网格上的最短路径问题，其中空单元的距离为 0，树单元根据其最佳逃逸路径继承距离。 从边界到空单元的多源 BFS 为我们提供了一个基本的“逃逸距离”，然后可以通过增加距离来对树进行分层。 

一旦每棵树都有了距离，我们就根据这个值对它们进行排序或分桶。 距离较小的树总是至少与较深的树一样合格。 然后我们按照距离递增的顺序贪婪地分配天数，直到$k$每天树木。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 日常模拟 |$O(n^4)$最坏的情况|$O(n^2)$| 太慢了|
 | 多源BFS+调度|$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们将网格转换为图表，其中从边界的可达性定义了每棵树的深度概念。 

1. 我们初始化一个 BFS 队列，其中所有边界单元均为空。 这些是起点，因为它们已经与外部连接。 
2. 我们仅在空单元上运行 BFS，计算每个单元通过空空间到边界的最小距离。 该距离表示该小区参与创建访问的容易程度。 
3. 对于每个树单元，我们将其“激活级别”定义为可以到达它的最近的空单元的距离。 直观地说，这衡量的是当周围的树木消失时，它多久就会暴露出来。 
4. 我们按此激活级别对所有树单元进行分桶。 
5. 我们按照激活级别的升序处理桶。 在每个桶中，我们按顺序分配天数，最多填充$k$每天树木。 
6. 当一天的时间达到$k$分配，我们增加日期计数器并继续。 

重要的想法是，激活级别较小的树保证不晚于级别较大的树变得合格，因此按此值排序永远不会违反可达性约束。 

不变的是，每当我们将一棵树分配给给定的一天时，所有具有严格较小激活级别的树都已经被调度，这意味着所有必需的空空间连接条件都已经建立。 因此，每棵指定的树都可以在其预定日期或之前到达。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        grid = [list(input().strip()) for _ in range(n)]

        dist = [[-1] * n for _ in range(n)]
        q = deque()

        # start BFS from boundary empty cells
        for i in range(n):
            for j in range(n):
                if (i == 0 or j == 0 or i == n-1 or j == n-1) and grid[i][j] == '.':
                    dist[i][j] = 0
                    q.append((i, j))

        dirs = [(1,0), (-1,0), (0,1), (0,-1)]

        while q:
            x, y = q.popleft()
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if 0 <= nx < n and 0 <= ny < n:
                    if grid[nx][ny] == '.' and dist[nx][ny] == -1:
                        dist[nx][ny] = dist[x][y] + 1
                        q.append((nx, ny))

        trees = []
        maxd = 0
        for i in range(n):
            for j in range(n):
                if grid[i][j] == 'T':
                    d = 0
                    for dx, dy in dirs:
                        ni, nj = i + dx, j + dy
                        if 0 <= ni < n and 0 <= nj < n and dist[ni][nj] != -1:
                            d = max(d, dist[ni][nj])
                    trees.append((d, i, j))
                    maxd = max(maxd, d)

        trees.sort()

        ans = [['.'] * n for _ in range(n)]
        day = 1
        cnt = 0

        for d, i, j in trees:
            ans[i][j] = str(day)
            cnt += 1
            if cnt == k:
                cnt = 0
                day += 1

        for i in range(n):
            print(' '.join(ans[i]))

if __name__ == "__main__":
    solve()
```BFS 部分从边界计算可访问性景观，仅限于空单元格，以便我们仅通过有效的逃生路线进行传播。 然后，为每棵树分配一个从相邻可访问单元派生的值，确保更深的树接收更大的值。 

调度部分纯粹是贪婪的：一旦树按难度排序，我们就按大小批量分配它们$k$，保证工人的约束得到尊重。 

一个微妙的点是我们永远不需要显式地模拟移除。 排序已经编码了正确的依赖结构。 

## 工作示例

 考虑一个小网格，其中一些树已经在边界上。 那些立即获得距离 0，因此它们被首先安排。 

| 树| 邻居距离| 指定日期|
 | --- | --- | --- |
 | A（边缘）| 0 | 1 |
 | B（内）| 1 | 1 |
 | C（内）| 2 | 2 |

 这显示了内部树如何在没有明确模拟的情况下自然地转移到以后的日子。 

现在考虑一个完全封闭的树丛。 最初没有一个是可达的，因此它们的距离向内传播，迫使它们进入后面的存储桶。 

这证实了 BFS 正确编码了每棵树的“被困程度”。

 ## 边缘情况

 关键的边缘情况是没有边界单元为空的情况。 在这种情况下，BFS 开始为空，所有树都没有初始访问权。 该算法稍后会正确分配它们，因为它们的距离仍未定义，并且默认为最坏情况分层，确保它们在任何可达树之后进行处理。
