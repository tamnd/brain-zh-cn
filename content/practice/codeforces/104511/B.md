 ## 解决方案
 ## 问题理解

 我们正在尝试将硬币分配给六头不同的奶牛，以便每头牛都收到一枚硬币，并且所有分配的硬币的总价值等于目标总和$n$。 可用硬币受面额限制：对于从 1 到 5 的每个值，Farmer John 都有一个固定数量$a_x$有价硬币$x$。 任务不是单独决定可行性，而是计算存在多少个不同的分配，其中如果至少一头牛收到不同价值的硬币，则两个分配是不同的。 

该结构本质上是一个受约束的分配问题：我们从一组有限的资源中恰好选择了 6 个硬币，排序很重要，因为奶牛是不同的。 即使两个分配使用相同的多组硬币值，交换哪头牛获得哪只硬币也会创建不同的有效配置。 

限制很小：$n \le 30$，以及每个$a_x \le 6$。 这立即表明，对所有分配进行暴力破解是合理的，因为奶牛的数量和硬币的数量都很小。 任何通过有界分支枚举超过六个位置的分配的方法都会很快终止。 期望涉及指数组合或小状态空间上的动态规划的解决方案。 

一些微妙的边缘情况很重要：

 如果硬币总数太少，即使忽略价值，也不可能分配六枚硬币。 例如，如果所有$a_x = 0$，那么无论怎样都不存在赋值$n$，答案必须为零。 

如果有足够的硬币，但它们的值太小或太大，总和约束仍然可能失败。 例如，如果所有硬币的价值都是 1，那么唯一可实现的总数是 6，因此任何$n \ne 6$产生零路。 

最后，多重性约束很重要。 即使存在六个值的有效多重集，其总和为$n$，我们必须确保不会超出可用硬币数量。 忽略有限供应的天真的组合计数是不正确的。 

## 方法

 最直接的想法就是给每头牛一一分配一枚硬币。 对于每头牛，我们选择任何可用的硬币类型，降低其可用性，然后递归地继续。 这正确地对问题进行了建模，因为它同时考虑了总和约束和有限供应约束。 结果只是有效叶子分配的数量，其总数等于$n$。 

然而，分支因子是每头牛最多有五个选择，而我们有六头牛。 在最坏的情况下，这会导致$5^6 = 15625$分配的数量已经很小了，但我们还必须考虑根据硬币的可用性进行修剪。 即使我们忽略修剪，这在计算上也是微不足道的。 

我们可以通过注意到这个问题相当于用以下值填充六个标记槽来使结构更清晰：$[1,5]$，受到每个值可以使用多少次以及总和条件的全局约束。 这自然是在非常小的状态空间上的有界深度搜索。 

稍微结构化的视图是对奶牛和剩余金额的动态编程，同时跟踪剩余的硬币数量。 但自从每个$a_x \le 6$，带有记忆化甚至不带有记忆化的直接 DFS 就足够了。 

关键的见解是状态空间很小，因为只有六个决策，每个决策有五个选择，因此带有有效性检查的暴力破解已经是最佳选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力 DFS 超过 6 头牛 |$O(5^6)$|$O(1)$或者$O(6)$递归| 已接受 |
 | DP 与硬币计数 |$O(6 \cdot n \cdot \prod a_x)$|$O(n \cdot \prod a_x)$| 已接受但没有必要 |

 ## 算法演练

 我们一一处理奶牛，维护每个值还有多少枚硬币可用以及我们需要达到的剩余金额。 

1. 从所有硬币数开始$a_1 \ldots a_5$，和目标总和$n$，我们的奶牛索引为 0。剩余的总和最初是$n$。 这定义了搜索的初始状态。 
2. 对于当前的牛，尝试为每个硬币分配 1 到 5 的值，前提是我们至少还有一枚该值的硬币可用。 此步骤在本地强制实施供应限制。 
3. 如果我们分配一枚有价值的硬币$v$，我们递减$a_v$并将剩余金额减少$v$，然后递归到下一头牛。 这确保部分分配始终反映真实的剩余资源。 
4. 如果在任何时候剩余的总和变为负数，我们立即停止探索该分支。 由于所有剩余硬币都是正数，因此无法恢复。 
5. 当我们到达第六头牛时，我们检查剩余的总和是否正好为零。 如果是，我们将其视为一项有效作业。 

正确性依赖于这样一个事实：每一次分配给奶牛的硬币都恰好对应于该搜索树中的一条路径。 每个级别都会选择一头牛的硬币，每个选择都由硬币的价值和可用性唯一决定。 因此，我们既不会错过有效的分配，也不会在相同的状态演化下重复计算相同的分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    cows = 6
    values = [1, 2, 3, 4, 5]
    
    sys.setrecursionlimit(10000)
    
    from functools import lru_cache
    
    @lru_cache(None)
    def dfs(i, c1, c2, c3, c4, c5, rem):
        if rem < 0:
            return 0
        if i == cows:
            return 1 if rem == 0 else 0
        
        res = 0
        counts = [c1, c2, c3, c4, c5]
        
        for v in range(5):
            if counts[v] > 0:
                nxt = counts[:]
                nxt[v] -= 1
                res += dfs(i + 1, nxt[0], nxt[1], nxt[2], nxt[3], nxt[4], rem - (v + 1))
        
        return res
    
    print(dfs(0, a[0], a[1], a[2], a[3], a[4], n))

if __name__ == "__main__":
    solve()
```该实现直接反映了前面描述的递归构造。 该状态包括奶牛指数和剩余硬币数量，因为硬币的可用性会影响未来的选择。 剩余的总和作为参数携带以尽早强制执行目标约束。 

记忆化确保不会重新计算重复状态，当不同的选择序列导致相同的剩余多重集和奶牛索引时可能会发生重复状态。 即使原始递归已经很小，这也可以保持快速执行。 

一个常见的陷阱是忘记奶牛是不同的，这会导致除以阶乘或错误地使用组合计数。 在这里，我们明确地将每头牛的位置视为有序的，因此不需要标准化。

 ## 边缘情况

 一种极端情况是硬币总数不足。 用于输入`n = 6, a = (0,0,0,0,0)`，DFS 立即发现在奶牛 0 处不可能移动，因此递归返回 0。这证实了资源的缺乏正确地阻塞了所有路径。 

另一种情况是硬币存在但无法匹配所需的金额。 例如，`n = 7, a = (6,0,0,0,0)`强制所有奶牛获取价值 1 的硬币，在叶层产生总和 6，但永远不会达到 7。算法达到深度 6，剩余总和为 1，并拒绝所有路径。 

最后一个微妙的情况是存在多种组合的硬币过多。 由于每个分配都被视为奶牛的不同有序序列，因此 DFS 自然会计算每个排列，而无需额外的组合校正，从而匹配独特性的预期定义。
