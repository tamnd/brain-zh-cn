 ## 解决方案
 ## 问题理解

 我们在数轴上有一排粉丝俱乐部。 每个粉丝俱乐部都位于一个不同的坐标，并包含一名或两名成员。 Ian 在一个特殊的起始粉丝俱乐部中从位置 0 开始，该粉丝俱乐部贡献了大量固定数量的成员，并且他只能移动到严格位于右侧的粉丝俱乐部。 

运动规则是主要的转折。 只要他还没有访问过任何有两名成员的粉丝俱乐部，他就可以按照位置递增的顺序访问任何粉丝俱乐部。 然而，一旦他访问了一个有两名成员的粉丝俱乐部，那么他之后访问的每个粉丝俱乐部也必须恰好有两名成员。 这会产生一种单向约束切换：选择 2 名成员的粉丝俱乐部后，所有 1 名成员的粉丝俱乐部都将被禁止。 

任务是按照递增的坐标顺序选择粉丝俱乐部的子集，该子集尊重此规则并最大化收集的成员总数。 

约束 n ≤ 1000 意味着 O(n²) 动态规划解决方案是可行的。 如果简单地实现的话，任何三次或更糟的东西在 Python 中都会太慢，不到 2 秒，但排序位置上的二次转换是安全的。 这也强烈暗示了排序点或前缀结构上的 DP。 

当需要跳过早期的 2 名成员粉丝俱乐部以随后收集许多 1 名成员粉丝俱乐部时，就会出现一个微妙的失败案例。 另一个例子是过早加入 2 名粉丝俱乐部会阻碍以后达到更高的总数。 

例如，考虑：

 输入：```
4
1 2
2 1
3 1
4 1
```如果一个人贪婪地获取位置 1 处的第一个 2 成员粉丝俱乐部，则根据规则，剩余的最佳序列为空，仅给出 2。但是跳过它可以收集三个 1 成员粉丝俱乐部，总共 3 个。正确答案是 3，这表明早期的大值并不总是最优的。 

另一个极端情况是，最好的策略是根本不接受任何 2 名成员的粉丝俱乐部，即使它们存在。 

## 方法

 暴力方法会尝试粉丝俱乐部的每个子集，按位置对它们进行排序，并检查该顺序在规则下是否有效。 对于每个子集，我们将模拟从左到右行走，并验证一旦包含 2 名成员的粉丝俱乐部，之后就不会出现 1 名成员的粉丝俱乐部。 这已经需要检查 O(2ⁿ) 个子集，甚至验证每个子集也需要 O(n)，导致 O(n·2ⁿ)，这远远超出了可行的范围。 

约束的结构表明，基于我们第一次选择 2 名成员的粉丝俱乐部，进行了彻底的分离。 在此之前，我们处于允许两种类型的自由状态。 在那之后，我们就处于限制状态，只允许 2 名成员的粉丝俱乐部。 

这立即建议按位置排序并使用动态编程，我们跟踪两种状态：当我们仍然允许选择任一类型时达到前缀的最佳结果，以及当我们已经切换到受限模式时的最佳结果。 当我们决定组建一个由 2 名成员组成的粉丝俱乐部时，这种转变就发生了。 

关键的想法是，一旦我们确定了我们采用的第一个 2 成员粉丝俱乐部的索引，它之前的所有内容都可以自由地包含这两种类型，而它之后的所有内容都受到限制。 这将问题简化为尝试所有可能的“切换点”并以最佳方式组合前缀和后缀。 当 n ≤ 1000 时，预先计算两种类型的前缀最佳值足以在 O(n²) 甚至 O(n) 中评估所有切换点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(n·2ⁿ) | O(n) | 太慢了 |
 | 具有前缀/后缀分割的 DP | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 按坐标递增对所有粉丝俱乐部进行排序。 这是必要的，因为移动是严格向右的，因此任何有效路径都必须遵守排序顺序。 按排序顺序工作可消除 DP 状态中的位置推理。 
2. 构建两个前缀DP数组。 让 dp0[i] 代表我们可以使用索引 i 之前的粉丝俱乐部收集的最大成员数量，同时从未选择 2 名成员的粉丝俱乐部。 这意味着我们只能接受 1 名成员的粉丝俱乐部。 类似地，如果我们允许这两种类型但尚未承诺“2 后限制”制度，则让 dp1[i] 代表我们在 i 之前可以做的最好的事情。 

实际上，dp1[i] 是我们使用直至 i 的所有粉丝俱乐部可以实现的最佳总和，没有任何限制，因为在第一个 2 成员粉丝俱乐部之前，一切都是允许的。 

1. 仅计算 1 名成员粉丝俱乐部的前缀总和。 这直接给出了 dp0[i]，因为我们被迫忽略这个状态下的所有 2 人粉丝俱乐部。 
2. 对于我们确定粉丝俱乐部 j 是我们采用的第一个 2 名粉丝俱乐部的每个位置 j，计算最佳总数如下。 我们从 j 之前的所有索引中获取最佳无限制增益，然后添加 2 来选择 j，然后在 j 之后严格使用仅 2 名成员的粉丝俱乐部添加可能的最佳后缀总和。 这种分割是有效的，因为约束恰好在 j 处变为活动状态。 
3. 为了有效地计算后缀贡献，构建一个后缀 DP，其中 suf2[i] 是索引 i..n-1 中所有 2 名成员粉丝俱乐部的成员总数（如果我们将所有成员都取的话）。 由于选定第一个 2 人后就没有进一步的限制，因此我们只需将所有 2 人粉丝俱乐部作为后缀即可。 
4、最终答案是三种情况中最大的一个：只选择1人粉丝俱乐部，从不切换； 选择某个索引 j 作为第一个 2 人粉丝俱乐部； 或者直接从一开始就只有 2 名成员的粉丝俱乐部开始。

它之所以有效，是因为状态转换仅取决于之前是否选择了 2 名粉丝俱乐部。 任何最优解中都存在一个单调切换点：在它之前，两种类型都是允许的； 之后，只允许使用 2 种类型。 任何最佳解决方案都可以转换为具有单个开关的解决方案，而不会降低结果，因为延迟第一个 2 选择只会增加灵活性，而不会降低灵活性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    clubs = [tuple(map(int, input().split())) for _ in range(n)]
    clubs.sort()

    x = [c[0] for c in clubs]
    y = [c[1] for c in clubs]

    prefix_one = [0] * (n + 1)
    prefix_all = [0] * (n + 1)

    for i in range(n):
        prefix_one[i + 1] = prefix_one[i] + (1 if y[i] == 1 else 0)
        prefix_all[i + 1] = prefix_all[i] + y[i]

    suffix_two = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_two[i] = suffix_two[i + 1] + (2 if y[i] == 2 else 0)

    ans = 10**18

    ans = max(ans, prefix_one[n])

    for j in range(n):
        best_before = prefix_all[j]
        best_after = suffix_two[j + 1]
        ans = max(ans, best_before + y[j] + best_after)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先对粉丝俱乐部进行排序，以便任何有效的选择都对应于前缀一致的遍历。 然后构建前缀数组：如果我们只选择安全的粉丝俱乐部，一个会跟踪有多少个 1 成员粉丝俱乐部可用；如果我们在切换之前自由选择所有内容，另一个会跟踪总会员资格。 

后缀数组汇总了所有 2 名粉丝俱乐部的贡献，因为切换后，约束迫使我们专门进入该类别，但对于跳过或超出位置的排序没有限制。 

j 上的循环评估每个可能的前 2 名粉丝俱乐部。 对于每个 j，其之前的所有内容均以不受限制的方式获取，j 直接贡献，并且仅当它是 2 名粉丝俱乐部时，其后的所有内容才贡献。 

一个常见的陷阱是忘记转换是不可逆的。 这就是为什么我们在 j 之后从不混合 1 名成员的粉丝俱乐部。

 ## 边缘情况

 一个关键的边缘情况是最佳策略避免所有 2 名成员的粉丝俱乐部。 该算法通过仅前缀的情况来处理此问题，该情况只是将所有 1 名成员的粉丝俱乐部相加，并且从不触发切换逻辑。 

另一个极端情况是，最佳解决方案在第一个 2 名粉丝俱乐部中立即切换。 在这种情况下，索引 0 之前的 prefix_all 为零，并且 suffix 正确聚合了所有剩余的 2 名粉丝俱乐部。 

最后，通过评估每个可能的切换索引，可以自然地处理 2 名成员粉丝俱乐部稀疏但强大的情况，确保永远不会错过最佳分配。
