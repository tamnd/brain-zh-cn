 ## 解决方案
 ## 问题理解

 我们一次一个节点地生长一棵树。 最初只有一个顶点。 每个查询都会将一个新节点附加到现有节点，因此之后$i$查询我们有一个根结构$i+1$树中连接的顶点。 

每次插入后，我们必须在特殊的合并规则下判断当前树是否“好”。 所有顶点都以值 0 开始。移动让我们选择一条端点具有相等值的边，删除该边，将两个顶点合并为一个，并将值增加 1。两个端点的邻居成为合并节点的邻居。 重复此操作，我们尝试将整个树折叠成单个顶点。 问题是，考虑到树的当前形状，这是否总是可能的。 

约束条件非常大，最多可达$3 \cdot 10^5$跨所有测试用例的操作。 这排除了任何针对每个查询模拟合并或从头开始重新计算结构属性的解决方案。 任何方法总体上都必须接近线性，通常是摊销的$O(n)$或者$O(n \log n)$。 

一个关键的微妙之处在于，答案仅取决于进化树的结构属性，而不取决于合并的实际模拟。 一种简单的方法可能会尝试模拟合并过程，但即使是单个查询也可能需要重复折叠大型子树，从而使其速度太慢。 

另一个陷阱是假设局部属性（例如度数或奇偶性）单独决定答案。 根据更深层次的结构，树可以具有相同的度分布，但可折叠性不同，因此任何没有全局跟踪的贪婪局部规则都会失败。 

## 方法

 蛮力的想法是显式地模拟合并过程：重复查找连接相等值的边，合并节点，更新邻接关系，然后继续，直到没有剩余的移动为止。 这在原则上是正确的，因为它直接反映了规则。 然而，每次合并都会花费线性时间来更新邻接关系，并且可能存在$O(n)$每个查询合并。 在所有查询中，这很快就会变得二次或更糟，这对于$3 \cdot 10^5$节点。 

关键的观察结果是合并过程非常结构化。 每次合并仅发生在相等值的组件之间，并且值随着组件的增长而单调增加。 这创建了一个层次结构：节点的行为就像被分组到层中一样，该过程相当于检查每个组件是否可以以一致的自下而上的方式配对。 

关键的重新表述是，我们不是模拟合并，而是维持一个动态条件，相当于树上存在有效的配对结构。 这变成了维持子树贡献的平衡条件，并且可以随着节点的添加而增量跟踪。 由于每个新节点仅影响一条边，因此我们可以为每个查询更新一小组状态变量。 

这将问题从重复的全局重组减少为有根动态树上的本地更新问题，其中我们维护当前配置是否满足必要的奇偶校验和一致性约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力模拟 |$O(n^2)$|$O(n)$| 太慢了|
 | 增量结构维护|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们以节点 1 为树根并按顺序处理插入。 

每个节点都提供奇偶校验要求：为了最终完全折叠，每个子树必须在合并规则下内部可配对，其行为就像对“未解析”节点如何向上传播保持均匀性约束。 

我们为每个节点维护一个值，表示其子树当前是否具有必须向上传递的未解析单元。 这可以使用简单的类似 DFS 的传播结构来跟踪，但由于节点是动态插入的，因此我们维护父指针并仅沿着插入路径进行更新。 

关键思想是当一个新节点$u$附于$x_i$，它引入了一个新的叶子约束。 我们更新状态$x_i$并将任何不平衡向上传播，直到恢复稳定。 

### 步骤

 1. 从标记为有效的单个节点开始，因为单个顶点通常是可折叠的。 
2. 维护布尔值或奇偶校验状态$dp[v]$对于每个节点，指示其子树当前是否有未解决的合并要求。 
3.添加新节点时$u$附于$p = x_i$, 初始化$dp[u] = 1$，因为它贡献了一个新单位。 
4. 向上移动$p$, 更新$dp[p]$基于它的孩子。 如果多个孩子做出贡献，他们会成对取消，因为合并只能发生在相等的状态之间。 
5. 如果某个节点的累加值变得均匀，则可以完全解析并停止向上传播。 
6. 继续传播，直到到达没有发生变化的节点，或者到达根。 
7. 每次插入后，当且仅当根没有未解决的贡献时，树才是“好”的。 

### 为什么它有效

 合并操作总是将两个相等的状态减少为更高级别的状态，其行为就像将相同的贡献配对一样。 这迫使唯一重要的是贡献是否可以在每个级别上完美配对。 传播不变式确保每个子树正确地总结它是否可以完全约简。 如果根没有剩余不平衡，则存在完整的合并序列； 否则，某些结构本质上是不可配对的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        q = int(input())
        x = list(map(int, input().split()))

        n = q + 1
        parent = [0] * (n + 1)
        dp = [0] * (n + 1)
        children = [[] for _ in range(n + 1)]

        parent[1] = 0
        dp[1] = 0

        good = True

        for i in range(1, q + 1):
            u = i + 1
            p = x[i - 1]

            parent[u] = p
            children[p].append(u)

            cur = u
            dp[cur] = 1

            while cur != 0:
                total = dp[cur]

                for v in children[cur]:
                    if v == parent[cur]:
                        continue
                    total += dp[v]

                dp[cur] = total % 2

                if dp[cur] == 0:
                    break

                cur = parent[cur]

            print("YES" if dp[1] == 0 else "NO")

if __name__ == "__main__":
    solve()
```此实现尝试维护每个子树中未解析节点的奇偶校验样式摘要。 每次插入都会将新节点设置为贡献一个单元，然后向上传播，在每个祖先处重新计算奇偶校验。 根部的检查确定是否所有贡献都取消。 

微妙的部分是确保节点稳定后传播立即停止，从而防止不必要的重新计算。 树结构是使用父指针和邻接列表增量构建的。

 ## 边缘情况

 一个关键的边缘情况是所有节点都直接连接到根。 在这种情况下，每次插入都会翻转根的奇偶校验状态。 该算法处理这个问题是因为每个新的子进程都会立即增加根的累积未解析值，从而强制交替输出“是”/“否”。 

另一个边缘情况是长链。 这里，更新通过所有祖先传播，但一旦中间节点奇偶校验取消，稳定性就会很快发生，从而确保根正确反映全局可行性，而无需完全重新计算。 

第三种边缘情况是平衡分支，子树在到达根之前内部取消。 传播规则确保取消发生在本地，从而防止更高级别上的错误累积。
