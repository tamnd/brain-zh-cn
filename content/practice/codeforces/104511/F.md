 ## 解决方案
 ## 问题理解

 我们有几种类型的咖啡，但最终只有第一种是有价值的。 该过程有两个阶段。 

首先，我们可以从Sumika那里得到一些初始咖啡。 她可以提供任何非负实际量的咖啡，但仅限于标有`1`在二进制字符串中。 唯一的限制是我们从她身上拿走的总体积不能超过`v`。 这意味着我们可以分配一定规模的预算`v`涵盖咖啡类型的一个子集。 

之后我们就可以重复进行交易了。 每笔交易涉及两种输入咖啡类型并生产一种输出类型。 交易由系数描述：按规模进行交易`k`，我们必须给`k * a`一种类型的单位和`k * b`另一种类型的单位，我们收到`k`第三类单位。 价值`k`是任何非负实数，因此每笔交易都是完美线性的并且可以连续缩放。 

我们的目标是在任意顺序的此类交易之后，最大限度地增加我们最终可以获得的 1 类咖啡的数量。 

关键的结构性限制是`n`最多为 50，而交易数量最多可达 1000。这立即表明解决方案可以对所有交易进行重复松弛，但无法模拟连续流或尝试对交易序列进行组合搜索。 实值缩放的存在也强烈表明该问题本质上是线性的而不是离散的。 

Sumika 提供了多种可能的起始类型，这是一个微妙的边缘情况。 我们并不被迫按固定比例接受一切； 我们可以选择总预算的任意分配`v`。 另一个边缘情况是，交易还可以产生中间类型，这些中间类型后来在其他交易中变得有用，这意味着简单的一步转换是不够的。 

## 方法

 直接模拟将尝试跟踪所有咖啡类型的数量并以任意顺序重复应用交易。 问题在于交易是连续的并且可以以无限多种方式组成，因此简单的状态模拟很快就会变得难以管理。 

相反，我们将问题重新解释为线性转换成本系统。 将每种咖啡类型视为都有一个“价格”，这意味着生产一单位该类型的咖啡需要多少 Sumika 预算。 如果我们知道生产每种类型的最低成本，那么最好的策略就是将所有预算花在最便宜的方法上来生成类型 1。 

最初，我们可以直接从 Sumika 获取的每种源类型的每单位成本为 1，因为我们可以花费 1 单位的预算来获取 1 单位的该类型。 所有其他类型一开始都是不可能的。 

现在考虑一项交易。 如果我们可以生产一种类型`x`按成本`cost[x]`和一个类型单位`y`按成本`cost[y]`，然后产生`k * a`和`k * b`成本`k * (a * cost[x] + b * cost[y])`，它产生`k`类型单位`z`。 因此，每单位类型的隐含成本`z`是：```
cost[z] = a * cost[x] + b * cost[y]
```这给出了类似于最短路径的松弛规则，除了每条边依赖于两个先前已知的节点。 自从`n`很小，重复应用这些松弛直到没有改善就足够了。 

一旦所有最低成本稳定下来，答案很简单`v / cost[1]`，因为我们通过最便宜的转换链将整个预算转换为类型 1。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟交易 | 指数/无界| 高| 太慢了|
 | 贸易成本放宽| O(n·m·迭代) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个数组`cost`尺寸的`n`。 放`cost[i] = 1`Sumika是否可以直接提供类型`i`，否则将其设置为无穷大。 该模型模拟了这样的事实：最初只有这些类型可以以单位成本获得。 
2. 对所有交易重复放松，直到价值没有变化。 每笔交易更新`cost[z]`使用公式`a * cost[x] + b * cost[y]`。 如果该值小于当前值`cost[z]`，更新一下。 
3. 继续放松过程，直到所有交易的全面通过都不会产生任何改进。 由于每次更新都会严格降低一些成本，因此该过程会收敛。 
4. 收敛后，计算最终答案为`v / cost[1]`。 这意味着将所有可用预算转化为类型 1 的最有效生产路线。 

### 为什么它有效

 成本定义形成了一个单调的不平等系统。 每笔交易都对可实现的成本施加线性约束，任何有效的交易序列都对应于重复应用这些约束。 松弛过程实际上是从直接来源开始，有效地计算满足自下而上的所有贸易约束的最大固定点。 由于每次更新只会降低成本，并且成本限制为零以下，因此该过程会收敛到每种类型的最小可行生产成本。 一旦知道类型 1 的成本，将整个预算按其倒数缩放即可得出可实现的最大金额。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    t = int(input())
    for _ in range(t):
        n, m, v = map(int, input().split())
        s = input().strip()

        cost = [INF] * n
        for i, ch in enumerate(s):
            if ch == '1':
                cost[i] = 1.0

        edges = []
        for _ in range(m):
            a, x, b, y, c, z = map(int, input().split())
            x -= 1
            y -= 1
            z -= 1
            edges.append((a, x, b, y, z))

        changed = True
        for _ in range(n * n):
            changed = False
            for a, x, b, y, z in edges:
                if cost[x] < INF and cost[y] < INF:
                    val = a * cost[x] + b * cost[y]
                    if val < cost[z]:
                        cost[z] = val
                        changed = True
            if not changed:
                break

        if cost[0] >= INF / 2:
            print(0.0)
        else:
            print(v / cost[0])

if __name__ == "__main__":
    solve()
```该实现反映了问题的松弛观点。 这`cost`数组存储创建每种类型的一个单元所需的最小初始预算。 我们仅初始化允许的 Sumika 类型，成本为 1。 

每次迭代都会扫描所有交易并应用双线性松弛规则。 收敛检查确保我们在没有交易改善任何成本时尽早停止。 

最后，类型1的成本换算总预算`v`成可达到的最大金额。 

一个常见的陷阱是忘记在应用放宽之前，交易的两种投入类型必须已经具有有限成本。 另一个假设是单次传递就足够了，而实际上改进可以通过交易链传播。 

## 工作示例

 考虑一个小型系统，Sumika 提供类型 2 和类型 3，并且存在将它们转换为类型 1 的交易。 

我们从成本开始：

 | 类型 | 初始成本|
 | --- | --- |
 | 1 | 信息 |
 | 2 | 1 |
 | 3 | 1 |

 应用交易后，假设我们可以使用以下方法生产类型 1`2 + 3`，所以：

 | 迭代| 成本[1] | 成本[2] | 成本[3] | 更新原因 |
 | --- | --- | --- | --- | --- |
 | 0 | 信息 | 1 | 1 | 初始化|
 | 1 | 2 + 1 = 3 | 1 | 1 | 贸易应用|
 | 2 | 稳定 | 1 | 1 | 收敛|

 最终答案是`v / 3`。 

现在考虑一个链式情况，其中类型 4 无法直接访问但变得有用：

 | 类型 | 初始成本|
 | --- | --- |
 | 1 | 信息 |
 | 2 | 1 |
 | 3 | 信息 |
 | 4 | 信息 |

 贸易 1 从 2 和 2 生产 3，贸易 2 从 3 和 2 生产 1。 

| 步骤| 更新 |
 | --- | --- |
 | 1 | 成本[3] 变为 2 |
 | 2 | 成本[1] 变为 3 |
 | 3 | 稳定 |

 这表明中间生产路径的重要性以及为什么需要反复放松。

 ## 边缘情况

 一种重要的边缘情况是类型 1 根本无法到达。 在这种情况下，其成本仍然是无限的，除以它是无效的。 实现显式检查这一点并输出零。 

另一种情况是 Sumika 提供多种可用的起始类型。 初始化将所有这些成本分配为 1，并且松弛自然地选择其中最有效的，而不需要显式分配逻辑。 

第三种情况是长依赖链，其中类型 1 仅在几次中间改进后才可到达。 重复的松弛循环确保这些改进在计算最终答案之前完全传播。
