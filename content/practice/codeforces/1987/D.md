 ## 解决方案
 ## 问题理解

 我们有一个两人游戏，爱丽丝和鲍勃玩一组蛋糕，每个蛋糕都有一个整数的美味。 爱丽丝先走。 轮到她时，她只能拿走味道严格高于她之前吃过的任何蛋糕的蛋糕，而鲍勃可以不受限制地拿走任何剩余的蛋糕。 当玩家无法做出有效的动作时，游戏结束。 爱丽丝想要最大化她吃的蛋糕数量，而鲍勃想要最小化这个数量。 任务是计算在双方最佳玩法下爱丽丝吃了多少块蛋糕。 

输入由多个测试用例组成。 对于每个测试用例，我们收到一个整数$n$和一个数组$a$的$n$美味值。 每个测试用例的输出是一个整数：爱丽丝将消耗的蛋糕数量。 

限制条件适中：$n$最多可达 5000，总和$n$所有测试用例不超过 5000。这意味着$O(n^2)$每个测试用例的解决方案都是可行的。 每个蛋糕的美味程度都受到限制$n$，这允许我们在需要时使用频率数组或直接索引。 

不明显的边缘情况包括所有蛋糕都具有相同味道的情况。 在这种情况下，爱丽丝只能吃第一个蛋糕，因为她无法选择与她之前选择的蛋糕相同的蛋糕。 另一个微妙的情况是，当数组严格增加或减少时，这可能会根据鲍勃的最佳对策改变爱丽丝可以吃的蛋糕数量。 

## 方法

 暴力方法将直接模拟游戏。 对于爱丽丝可能的第一步行动，我们可以尝试鲍勃的每一个反击行动序列，并递归地继续，直到游戏结束。 这种方法原则上是正确的，但分支因子是巨大的：在每个 Alice 或 Bob 回合中，可能有多达$n$选择。 在最坏的情况下，这会产生类似的结果$O(n!)$，这对于$n = 5000$。 

关键的见解是根据美味值的频率计数来思考，而不是模拟每个序列。 爱丽丝的行动受到限制：她只能选择严格增加的美味值。 鲍勃的策略不受限制； 如果最小的可用值阻止了爱丽丝增加序列，他总是会首先删除它们。 因此，我们可以将问题简化为对每个潜在长度进行计数$x$Alice 的序列，Bob 是否可以阻止它。 

对此进行建模的一种更简单的方法是对美味数组进行排序，计算每个美味值的频率，并尝试构建最长的严格递增子序列，其中鲍勃删除尽可能多的小元素。 鲍勃的最佳游戏后剩余的不同味道值的数量决定了爱丽丝的最大序列长度。 形式上，爱丽丝的结果是最大的$x$使得存在长度严格递增的序列$x$使用鲍勃阻挡后剩余的蛋糕。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n!) | O(n) | 太慢了 |
 | 频率+计数| 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 统计每个味道值出现的频率。 由于美味值在 [1, n] 中，我们可以使用大小为$n+1$存储计数。 这使我们能够知道每个值存在多少个蛋糕$O(n)$时间。 
2. 初始化变量`alice_count`为零。 这将跟踪爱丽丝可以吃的蛋糕数量。 
3. 按升序迭代美味值。 对于每一种美味`t`，如果还剩下至少一块这种口味的蛋糕，爱丽丝就可以吃一块蛋糕。 增量`alice_count`对于每一个成功的选择。 
4.爱丽丝挑选了一块美味的蛋糕后`t`，减少该美味的计数。 鲍勃将尽可能多地移走蛋糕，以防止爱丽丝吃下一个更高口味的蛋糕。 在实践中，对于最优策略，我们只需要确保阻止Alice重复相同的味道或跳过必要的值，这是由频率计数自动处理的。 
5. 继续，直到爱丽丝没有剩下更高的美味值。 变量`alice_count`现在爱丽丝在最佳游戏下可以消耗的最大蛋糕数量。 

核心不变量是，在任何一步中，爱丽丝的下一个蛋糕都必须严格大于她之前的所有蛋糕。 通过按排序顺序迭代并计算频率，我们确保构建尊重此约束的最长序列。 鲍勃的最佳删除是隐式处理的，因为唯一可以阻止爱丽丝扩展序列的是耗尽下一个所需的美味。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        freq = [0] * (n + 2)
        for v in a:
            freq[v] += 1
        
        alice_count = 0
        for tastiness in range(1, n + 1):
            if freq[tastiness] > 0:
                alice_count += 1
                freq[tastiness] -= 1
        print(alice_count)

if __name__ == "__main__":
    solve()
```该解决方案首先读取测试用例的数量。 对于每种情况，它都会读取美味值数组并构造一个频率数组。 然后它迭代可能的美味值，计算爱丽丝可以消耗多少，同时确保她只接受严格递增的值。 频率递减确保每个蛋糕仅使用一次。 该循环保证 Alice 的序列是最大的，因为它按升序处理值。
