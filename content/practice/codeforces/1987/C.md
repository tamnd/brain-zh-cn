 ## 解决方案
 ## 问题理解

 我们被要求模拟一个排列成直线的花园，其中每朵花都有一个初始高度。 风每秒从左边吹来，并根据严格的规则降低一些花的高度：如果一朵花是该行中的最后一朵花，或者它比紧邻其右侧的花高，那么该花就会收缩。 每次减少正好一个单位，并且没有花可以低于零。 任务是确定所有花朵达到零高度需要多少秒。 

输入由多个测试用例组成，每个测试用例给出花朵的数量及其初始高度。 输出是直到所有高度为零为止的秒数。 约束很重要：每个测试用例的花数最多可达 10^5，并且测试用例之间的总和也最多可达 10^5。 这意味着对每朵花每秒进行简单模拟会太慢，因为如果高度很大，在最坏的情况下可能需要多达 10^9 次操作。 

当高度从左到右严格增加时，就会出现一个重要的边缘情况，例如 [1, 2, 3]。 简单的模拟会首先减少最后一朵花，然后逐渐减少前面的花。 粗心的实现可能会尝试同时减少所有花或忽略从左到右的顺序，从而导致错误的结果。 另一个微妙的情况是所有的花都是平等的。 例如，[2, 2, 2] 只需要与最大高度一样多的秒数，因为每朵花都可以同时减小，但与下一朵花进行比较的规则意味着只有最后一朵花最初会递减，然后递减向左传播。 

## 方法

 暴力方法将通过迭代所有花并应用规则来模拟每一秒。 虽然概念上简单且正确，但这需要每个测试用例进行 O(n * max(h_i)) 次操作，这对于 n 高达 10^5 且高度高达 10^9 来说是不可行的。 

关键的见解是，位置 i 处的花朵到达零所需的秒数由从右向左移动时遇到的最大高度决定，但有传播约束：如果一朵花不高于下一朵花，则其递减会延迟，直到下一朵更高的花降低为止。 实际上，我们可以将“风效应”建模为从右到左的高度差传播。 这一观察使我们能够通过从右向左扫描并在考虑传播后跟踪每朵花的有效高度来计算总时间。 最佳解决方案将模拟减少到每个测试用例一次 O(n) 次，完全避免了每秒迭代。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n * 最大(h_i)) | O(n) | 太慢了 |
 | 从右到左传播 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化变量`seconds`为零，这将存储所需的总秒数。 
2. 开始从右向左扫描花高，存储`current_max`代表花朵对总持续时间贡献的有效最大高度。 初始化`current_max = 0`。 
3. 对于位置 i 处的每一朵花（从最后一朵向左移动的花开始），更新`current_max`作为其自身高度的最大值和`current_max + 1`。 这`+1`解释了这样一个事实：在右侧传播允许之前，左侧的花无法开始减少。 
4.更新后`current_max`对于每朵花，更新`seconds`作为之间的最大值`seconds`和`current_max`。 这确保了`seconds`始终反映迄今为止处理的所有花朵达到零所需的时间。 
5. 所有鲜花处理完毕后，`seconds`包含所需的总秒数。 

**为什么起作用**：传播逻辑捕捉到这样的规则：在风导致较高或最后的花朵开始减少之前，花朵不会减少。 通过从右向左扫描，每朵花的有效高度要么是它自己的，要么比其右侧花的最大有效高度延迟一倍。 这个不变量保证了所有有效高度中的最大值正确反映了所有花达到零之前的总时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))
        seconds = 0
        current_max = 0
        # Process flowers from right to left
        for height in reversed(h):
            current_max = max(height, current_max + 1)
            seconds = max(seconds, current_max)
        print(seconds)

if __name__ == "__main__":
    solve()
```该代码读取测试用例的数量并独立处理每个测试用例。 它反转高度列表以在单次传递中应用从右到左的传播。`current_max`累积传播的效果，并且`seconds`跟踪最大持续时间。 这种方法避免了每秒模拟并有效地处理非常大的高度。 

## 工作示例

 对于第一个样本输入`[1, 1, 2]`，我们从右向左扫描：

 | 我| 高度| 当前最大| 秒|
 | --- | --- | --- | --- |
 | 2 | 2 | 最大(2, 0+1)=2 | 2 |
 | 1 | 1 | 最大(1, 2+1)=3 | 3 |
 | 0 | 1 | 最大(1, 3+1)=4 | 4 |

 结果是`4`，匹配示例输出。 

对于输入`[7, 4, 4, 3, 2]`：

 | 我| 高度| 当前最大| 秒|
 | --- | --- | --- | --- |
 | 4 | 2 | 最大(2,0+1)=2 | 2 |
 | 3 | 3 | 最大(3,2+1)=3 | 3 |
 | 2 | 4 | 最大(4,3+1)=4 | 4 |
 | 1 | 4 | 最大(4,4+1)=5 | 5 |
 | 0 | 7 | 最大(7,5+1)=7 | 7 |

 结果是`7`，匹配示例输出。

 ## 边缘情况

 对于一朵花来说`[5]`，算法集`current_max = max(5,0+1)=5`,`seconds=max(0,5)=5`,正确输出`5`。 对于所有相同的高度`[2,2,2]`，反向扫描更新`current_max`为 2, 3, 4，结果为`seconds = 4`。 这正确捕获了延迟传播。 该算法自然可以处理大高度，因为它从不每秒模拟，仅传播有效最大值。
