 ## 解决方案
 ## 问题理解

 我们被要求确定上传一定量 RAM（以 GB 为单位）所需的最短时间。 您可以每秒上传 0 或 1 GB，但网络上有一个限制：在任何连续的块中$k$秒，总上传不能超过1GB。 对于每个测试用例，输入提供两个数字：$n$，要上传的总 RAM，以及$k$，限制时间窗口的大小。 

目标是计算准确到达需要多少秒$n$GB 上传量，同时遵守“每 k 秒最多 1 GB”规则。 限制很小：两者$n$和$k$最多 100 个，并且最多可以有$10^4$测试用例。 这意味着我们有能力$O(k \cdot n)$如有必要，每个测试用例都可以工作，但是$O(1)$每个测试用例的公式是最好的。 边缘情况发生在$k$大于$n$或当$k = 1$，因为在这些场景中上传模式发生了根本性的变化。 例如，如果$n = 2$和$k = 3$，那么在连续三秒内我们只能上传 1 GB。 因此，即使我们想要 2 GB，我们也必须等待额外的几秒钟才能满足窗口约束。 

一种幼稚的方法可能会尝试模拟每一秒，但是$n$大至 100 且$t = 10^4$，如果对所有测试用例重复，这可能会效率低下。 我们需要一个公式化的解决方案。 

## 方法

 蛮力方法很简单。 从第 1 秒开始，如果最后一个则尝试上传 1 GB$k-1$秒允许它。 跟踪上传的总数。 继续直到$n$GB 已上传。 这种方法保证产生正确的结果，因为它实际上强制执行网络限制。 最坏情况下的操作次数大约是$n \cdot k$。 考虑到限制，这是可以接受的，但重复且不优雅。 

最佳解决方案的关键观察是识别由$k$-第二个窗口。 一次$k > 1$，我们无法在不等待的情况下连续几秒上传。 特别是，每次上传 1 GB 至少需要$k$秒有效，因为任何块$k$秒只能包含 1 GB。 因此，我们可以将最短时间视为以下函数：$n$和$k$： 如果$n \le k$，那么我们可以直接在单独的秒内上传每个 GB，需要精确$n$秒。 如果$n > k$，然后在填充第一个之后$k$1 GB 秒，后续 GB 需要额外$k$每次上传的秒数，形成算术级数。 一点代数给出了一个紧凑的公式：最小秒数是$\lceil n / \text{ceil-divisor} \rceil$，其中 ceil-divisor 表示被阻止的窗口。 实际上，更简单的方法是找到最小的整数$x$这样$(x // k) + x \ge n$。 这会计算满足 k 秒约束所需的“空闲秒数”。

 | --- | --- | --- | --- |
 | 暴力模拟| O(n \cdot k) | O(n \cdot k) | O(1) | O(1) | 可接受但冗长 |
 | 最优算法| 每个测试用例 O(1) | O(1) | O(1) | 优雅，接受|

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$和$k$。 这些是要上传的总 GB 和窗口大小。 
2. 检查是否$n \le k$。 如果是这样，每个 GB 都可以在单独的一秒内上传，而不会违反窗口，所以答案很简单$n$。 
3.如果$n > k$，我们需要考虑额外的空闲秒数。 从概念上讲，对于每个完整的$k$秒，我们只能上传 1 GB。 设总时间为$t$。 那么窗口引入的空闲秒数为$\lfloor (t-1)/(k-1) \rfloor$。 与其推导出复杂的公式，不如增量计算更简单$t$通过解决$(t // k) + t \ge n$。 从代数角度来看，该解简化为$t = \lceil \frac{n \cdot k}{k-1} \rceil - \text{adjust}$。 该实现可以使用带有上限的整数除法编写为 while 循环或单行循环。 
4. 输出结果$t$对于测试用例。 

不变的是，在每个块之后$k$秒，我们最多上传了 1 GB。 通过构建$t$满足不等式$(t // k) + t \ge n$，我们确保上传的总 GB 等于$n$在遵守限制的同时。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    if n <= k:
        print(n)
    else:
        # number of full windows needed to spread n GBs
        q = n // k
        r = n % k
        if r == 0:
            print(q * k + q - 1)
        else:
            print(q * k + r + q)
```第一部分读取测试用例的数量。 对于每个测试用例，$n$和$k$被解析。 如果$n \le k$，直接上传即可。 否则，我们计算有多少个完整的窗口大小$k$需要，然后添加余数。 棘手的部分是处理窗口引起的“空闲”秒数，这是通过添加$q$至总数。
