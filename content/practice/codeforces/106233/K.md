 ## 解决方案
 ## 问题理解

 该过程从放置在板上的单个整数开始。 您可以重复取出棋盘上当前的任何数字，将其擦除，然后用两个总和等于擦除值的正整数替换它。 每个这样的分割的成本等于两个结果数字的乘积。 

随着时间的推移，这将构建由重复分割派生的多重数字集。 每个查询的目标是确定是否可以从初始值开始获得目标数字集合，如果可以，则所有拆分的最小总成本必须是多少。 

一个关键的微妙之处是最终的板不需要完全包含所需的数字。 所有必需的值出现在最终多重集中的某个位置就足够了； 允许使用额外的数字，如果有帮助的话可以进一步拆分。 

每个查询给出一个数组段，表示所需的值，以及一个起始值 S。我们必须决定 S 是否可以分解为包含该段中所有值的多重集，如果可以，则计算所有拆分操作的最小成本。 

这些约束意味着大量的查询和数组大小，因此任何独立地重新计算每个查询的任何解决方案都会太慢。 对分裂的简单模拟会呈指数增长，因为每次分裂都会增加节点数量，并且每个节点都可以再次分裂。 

隐藏的结构是分裂不是任意分支，它总是保留总和，并且成本函数在二叉分解树上的行为是可预测的。 

由于粗心的做法，一些失败案例会立即出现。 

如果S小于要求值的总和，例如S=5，要求的数字是2、3、4，那么即使允许分裂，也无法增加总和，所以答案一定是不可能的。 

如果 S 等于总和但忽略分割的结构，人们可能会假设可行性始终成立。 例如，S = 7，所需值 [2, 2, 3] 有效，但 [3, 3, 3] 无效，即使总和为 9，因为 S 不足。 

另一个微妙的例子是成本行为。 对于S = 4，分裂成(1,3)的成本为3，而分裂成(2,2)的成本为4。在构造多个目标值时，“平衡分裂”的贪婪选择并不是全局最优的，因为中间值可能需要进一步分裂。 

## 方法

 直接暴力方法将过程建模为以 S 为根的二叉树。每个节点代表当前数字，将节点 y 扩展为 a 和 b 会增加成本 a·b。 我们递归地尝试所有可能的分割，直到所有需要的值都出现在多重集中。 

这是正确的，因为每个有效的操作序列都完全对应于一个二叉树，其叶子是最终的数字。 然而，可能的树木数量呈爆炸式增长。 即使对于中等的 S，每个值 y 也有 O(y) 可能的分裂，并且递归分支很多。 这会导致指数时间，并使其无法用于大 S 或许多查询。 

关键的观察结果是，将数字 y 拆分为 a 和 b 的成本恰好是 a·b = (a+b)^2/4 - (a^2 + b^2)/4 结构，但更重要的是，将 S 完全分解为叶子的总成本仅取决于最终叶子的成对相互作用，而不取决于拆分的顺序。 

如果我们将 S 扩展为叶子 x1, x2, ..., xk，则总成本变为 xi·xj 的所有无序叶子对的总和。 这是由于反复应用拆分合并交叉项贡献的恒等式。 这将问题转化为选择叶子的多重集，其中包括所有所需的 xi 和可能的额外正整数，同时在固定总和 S 下最小化成对交互成本。

额外的数字不是免费的，但它们可以用来“填补 S 中的空白”。最佳策略最终是将缺失的和视为大小为 S - sum（必需）的附加叶子，然后将成本计算为所选段上前缀和的函数。 

这将每个查询减少为计算段上的两个量：值的总和以及成对乘积的总和，这可以通过前缀预处理来维护。

 ## 算法演练

 1. 预先计算所需值数组的前缀和。 这允许快速计算任何查询范围的段总和。 
2. 预先计算前缀平方和或等效贡献，这将允许计算线段上的成对交互项。 这是必要的，因为成本取决于所有选定值之间的相互作用。 
3. 对于查询 (l, r, S)，计算该段所需的总和 T。 
4. 如果T > S，则立即返回-1，因为分裂不能增加总和，因此可行性失败。 
5. 定义剩余值 L = S - T。这表示分配所需叶子后剩余的“额外质量”。 
6. 使用从成对扩展导出的公式计算所需元素贡献的成本：所有对 xi·xj 的总和加上与 L 的交互（如果将其视为附加叶子）。 
7. 返回计算出的成本。 

不明显的步骤是用最终叶子上的封闭形式表达式替换整个分裂过程。 每个分割都保留总和，因此任何有效的过程都对应于总和为 S 的最终多重集。成本的累积与叶子之间的叉积完全相同，因为每个分割都以在整个树上伸缩的方式将交互成本分配给其子级。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# We assume preprocessing arrays exist after reading input:
# a is the array of values
# prefix sums and prefix square sums are computed

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
        pref2[i + 1] = pref2[i] + a[i] * a[i]

    out = []

    for _ in range(q):
        l, r, S = map(int, input().split())
        l -= 1

        sum_seg = pref[r] - pref[l]

        if sum_seg > S:
            out.append("-1")
            continue

        # leftover mass
        L = S - sum_seg

        # total pairwise contribution among segment elements
        # using identity: sum_{i<j} a_i a_j = (sum^2 - sumsq)/2
        sumsq = pref2[r] - pref2[l]
        pair_cost = (sum_seg * sum_seg - sumsq) // 2

        # interaction with leftover treated as an extra leaf
        extra_cost = L * sum_seg

        out.append(str(pair_cost + extra_cost))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码依赖于将贡献分成两个独立的部分。 第一个是所需元素之间的内部交互，使用从前缀和和前缀平方导出的成对和的标准恒等式进行计算。 第二个是剩余值 L 和每个所需元素之间的交互作用，它是线性的，因为每个所需元素都贡献 L·xi。 

最微妙的部分是认识到，一旦我们切换到叶子表示，分裂过程的进一步结构就不再重要。 这是许多不正确的解决方案要么使过程过于复杂，要么尝试贪婪分裂的地方，但由于局部平衡选择不能保持全局最优性而失败。

 ## 边缘情况

 当段总和已经超过 S 时，就会出现临界边缘情况。在这种情况下，没有任何分割序列可以修复缺陷，因为分割可以准确地保留总和。 该算法在任何成本计算之前通过前缀和比较立即处理这个问题。 

当 S 等于段总和时，会出现另一种边缘情况。 这里 L 变为零，所有剩余的相互作用项消失。 该解决方案正确地减少了段元素之间的纯成对成本，避免了任何人为的成本膨胀。 

最后一个微妙的情况是段只有一个元素。 成对项为零，答案只是 L 乘以该元素，反映出所有额外质量必须与单个叶子相互作用。
