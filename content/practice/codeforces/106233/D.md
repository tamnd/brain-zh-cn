 ## 问题理解

 我们正在处理一个看起来像斐波那契的序列，只不过用于组合先前值的操作是按位异或而不是算术加法。 给出了两个起始值，并且每个下一个值仅由前两个值确定。 任务是在基于 XOR 的递归下计算该序列的后续项，通常是非常大的索引项。 

具体而言，该序列的行为就像一个确定性自动机：一旦前两个值固定，后面的所有值都会被强制。 每个新元素都是通过对前两个元素进行按位异或来形成的。 输出要求沿该生成序列远的某个位置的值。 

这里最重要的约束是索引的大小。 当请求的项可能非常大时，任何逐步模拟序列的操作都变得不可能，因为每一步都依赖于前一步。 直接模拟需要索引中的线性时间，对于较大的值（例如 10^9 或更高），该时间会立即中断。 这迫使我们寻找序列演变的结构。 

当思考“只是模拟直到达到索引”时，就会出现一个微妙的失败案例。 例如，如果索引是 10^9 并且每个步骤都是恒定时间 XOR，则即使每个操作都很便宜，实现仍然太慢。 另一个常见的陷阱是假设序列的行为类似于正常的斐波那契数，并尝试直接应用算术公式，这不会结转，因为异或不保留进位，并且行为类似于不同代数系统中的加法。 

## 方法

 暴力方法很简单：从两个初始值开始，使用 XOR 迭代计算每个下一个值，直到达到所需的索引。 这是正确的，因为它完全遵循定义。 然而，其成本随指数线性增长。 如果索引为 n，则此方法执行 n 次转换，每次转换涉及常数时间 XOR。 当 n 非常大时，这变得不可行。 

关键的观察结果是，递归在具有两个元素的域上是线性的。 XOR 的行为类似于每个位独立地模 2 加法，这意味着每个位位置在相同的斐波那契递推下独立演化。 这将问题转化为分析线性递推系统，可以使用矩阵求幂来加速。 

我们可以将从状态 (F[i], F[i+1]) 到 (F[i+1], F[i] XOR F[i+1]) 的转换编码为线性变换。 重复应用此变换相当于将 2×2 矩阵求幂。 一旦我们能够在对数时间内计算这个矩阵幂，我们就可以直接获得第 n 项，而无需迭代所有中间状态。 

暴力破解之所以有效，是因为它忠实地模拟了递归过程。 它失败了，因为它将序列视为本质上连续的，而转换结构实际上允许我们通过对转换求幂来一次“跳跃”多个步骤。

 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 太慢了|
 | 矩阵求幂| O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将序列视为状态转换问题，其中每个状态包含两个连续值。 目标是使用重复加倍从初始状态跳转到位置 n 的状态。 

1. 将步骤 i 处的状态表示为包含 (F[i], F[i+1]) 对的向量。 这是必要的，因为重复依赖于两个先前的值，因此跟踪单个值是不够的。 
2. 将从一种状态到下一种状态的转变表示为线性变换：

(F[i], F[i+1]) 变换为 (F[i+1], F[i] XOR F[i+1])。 这准确地捕捉了序列如何演变。 
3. 将此变换编码为 GF(2) 上的 2×2 矩阵，其中乘法对应于 XOR，加法也对应于 XOR。 这使我们能够应用标准的快速求幂技术。 
4. 使用二进制求幂将转移矩阵求 (n-1) 次幂。 每个平方步骤将多个递归步骤压缩为一个操作，这是对朴素迭代的关键优化。 
5. 将得到的矩阵乘以初始向量(F[0], F[1])以获得位置n处的状态。 该结果向量的第一个分量就是答案。 

这样做的原因是递归定义了 GF(2) 上二维向量空间的线性变换。 重复应用递归正好对应于重复应用该变换。 矩阵求幂计算重复应用，无需显式模拟中间状态，线性度保证在压缩过程中不会丢失任何信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def mat_mul(a, b):
    # 2x2 matrix multiplication over GF(2) with XOR as addition
    return [
        [
            a[0][0] ^ (a[0][1] & b[1][0]) ^ (a[0][1] & b[1][0]),
            a[0][0] ^ a[0][1]
        ]
    ]
```
