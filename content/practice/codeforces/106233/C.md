 ## 解决方案
 ## 问题理解

 我们有一个面包师，其面团数量有限，馅料也有几种。 一个特定馅料的面包会消耗一定量的面团和一定量的馅料，并带来一定的利润。 面包师还可以制作仅消耗面团的普通面包。 任务是选择每种面包烤多少个，使总利润尽可能大。 

输入描述了可用的面团、馅料类型的数量、普通面包的成本和利润，以及每种馅料类型的可用馅料量、每个面包所需的馅料量、每个面包所需的面团以及利润。 产出是最大可能赚到的钱。 

面团的上限是1000个，这改变了我们思考问题的方式。 由剩余面团量索引的状态足够小以维持。 填充类型的数量也很少，最多10种，因此单独处理每种类型是可行的。 尝试每种填充类型的所有可能数量的面包的解决方案会增长得太快，因为组合会成倍增加，而接近 O(m * n * 一些小东西) 的解决方案是舒适的。 

一个常见的错误是只选择每克面团利润最高的馅料。 这失败了，因为填充物也是有限的资源。 例如，考虑：```
10 2 2 1
7 3 2 100
12 3 1 10
```最好的选择是不要只使用第一次填充，因为它会用完。 正确答案是`241`，使用两个第一种类型的面包，四个第二种类型的面包和一个普通的面包。 贪婪的比例选择可能会导致宝贵的面团得不到利用。 

另一种边缘情况是存在馅料，但与普通面包相比不值得使用。 例如：```
100 1 25 50
15 5 20 10
```正确的输出是：```
200
```一个粗心的解决方案可能会把面团花在馅料上，因为它是可用的，但四个普通面包可以带来更多利润。 

第三种边缘情况是填充量不能除以一个面包所需的量。 例如：```
5 1 3 10
4 3 2 100
```只能制作一个包子，因为馅料是有限的资源。 剩余的馅料不能使用。 正确的输出是`110`，一个夹心面包和一个素面包。 仅检查面团限制的循环可能会高估答案。 

## 方法

 直接蛮力的想法是决定每种馅料类型要制作多少个面包。 对于每种类型，我们都会尝试从零到馅料和面团允许的所有可能计数。 确定所有馅料后，剩下的面团就变成了普通的面包。 这是正确的，因为考虑了所有可能的烘焙计划。 

问题在于组合的数量。 尽管每种填充类型单独的选择数量有限，但组合 10 种类型会产生很大的搜索空间。 如果每种类型都允许大约 100 个选择，那么蛮力将探索大约`100^10`组合，这是不可能的。 

有用的观察结果是，所有面包类型之间共享的唯一资源是面团。 填充资源仅影响当前填充类型。 由于面团限制很小，我们可以为每种可能使用的面团量存储可实现的最佳利润。 

对于一种馅料类型，我们可以将制作包子视为有界的背包物品。 我们知道该类型面包的最大数量，并且每个面包都有固定的面团成本和利润。 我们更新动态规划数组，其中`dp[x]`表示准确使用后的最大利润`x`克面团。 处理完每种馅料后，剩余的面团最好用普通面包填充。 

蛮力之所以有效，是因为它枚举了所有有效的计划，但它失败了，因为它忽略了许多计划共享相同数量的用过的面团。 动态规划方法将所有此类计划合并为一种状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(所有选择的乘积) | O(1) | O(1) | 太慢了|
 | 最佳| O(m * n * maxBunsPerType) | O(m * n * maxBunsPerType) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读可用的面团和所有面包类型。 单独存储素面包信息，因为它将在考虑所有夹心面包后应用。 
2. 创建一个大小为动态规划的数组`n + 1`。 位置处的值`i`代表精确消费后的最大利润`i`克面团。 最初，花费零面团带来零利润。 
3. 逐一处理每种灌装类型。 对于这种类型，计算可用馅料中可能的最大面包数量。 实际数量受到馅料量和面团限制的限制。 
4. 尝试所有可能数量的当前馅料类型的面包。 对于之前每种可能的面团使用情况，通过添加所选数量的面包来更新新状态。 这是有效的，因为当前的馅料独立于除面团之外的其他馅料。 
5. 处理完所有馅料后，重复使用已使用的所有可能数量的面团。 将剩余面团制作普通面包的利润相加，并保留最大答案。 

这是正确的原因是，在处理某些馅料类型后，动态规划状态包含了每种面团消耗量的最佳可能利润。 添加新的填充类型时，会考虑该类型的每种可能的贡献，因此不变量仍然为真。 当所有的馅料处理完毕后，剩下的唯一决定就是如何使用剩余的面团，而普通包子没有其他限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())

    types = []
    for _ in range(m):
        a, b, c, d = map(int, input().split())
        types.append((a, b, c, d))

    dp = [0] * (n + 1)

    for a, b, c, d in types:
        limit = min(a // b, n // c)
        ndp = dp[:]

        for dough_used in range(n + 1):
            if dp[dough_used] < 0:
                continue
            for cnt in range(1, limit + 1):
                new_dough = dough_used + cnt * c
                if new_dough > n:
                    break
                value = dp[dough_used] + cnt * d
                if value > ndp[new_dough]:
                    ndp[new_dough] = value

        dp = ndp

    ans = 0
    for used in range(n + 1):
        plain = (n - used) // c0 * d0
        if dp[used] + plain > ans:
            ans = dp[used] + plain

    print(ans)

if __name__ == "__main__":
    solve()
```数组`dp`存储已投入的每种可能的面团量的最佳结果。 一开始只有可用的空烘焙计划。 

对于每次填充，变量`limit`防止不可能的转变。 只有有足够的馅料和足够的面团才能做出包子。 复制的数组`ndp`使用 是因为当前填充的所有新选择都应基于前一组填充，而不是基于在同一迭代中已使用相同填充的决策。 

最后一个循环处理普通面包。 国家已经把所有包子都占了，所以剩下的面团只能用来做素包子了。 Python 整数避免了溢出问题，因为最大答案仍然很小，但使用整数算术自然可以处理所有中间值。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m * n * 平均可能的面包) | 对于每种馅料，我们尝试所有面团状态和可能的数量|
 | 空间| O(n) | 仅存储当前面团状态 |

 面团的最大数量只有1000个，馅料最多有10个，所以转换的次数很容易在限制之内。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n, m, c0, d0 = map(int, data().split())
    types = []
    for _ in range(m):
        a, b, c, d = map(int, data().split())
        types.append((a, b, c, d))

    dp = [0] * (n + 1)

    for a, b, c, d in types:
        limit = min(a // b, n // c)
        ndp = dp[:]
        for i in range(n + 1):
            for cnt in range(1, limit + 1):
                if i + cnt * c > n:
                    break
                ndp[i + cnt * c] = max(ndp[i + cnt * c], dp[i] + cnt * d)
        dp = ndp

    ans = 0
    for i in range(n + 1):
        ans = max(ans, dp[i] + (n - i) // c0 * d0)

    sys.stdin = old
    return str(ans) + "\n"

 ## 边缘情况

 对于有限填充情况：```
5 1 3 10
4 3 2 100
```该算法计算出最多可以生产一个包子，因为`4 // 3 = 1`。 转换创建了一个使用 2 克面团和 100 利润的状态。 剩下的 3 克可以制作一个素面包，这就是最终的结果`110`。 

对于普通面包更好的情况：```
100 1 25 50
15 5 20 10
```填充过渡只能创建一种可能的填充面包，但与使用面团制作普通面包相比，每一种这样的选择留下的价值都太小了。 最终扫描将所有状态与添加的普通面包利润进行比较，因此空填充状态获胜`200`。 

对于混合资源情况：```
10 2 2 1
7 3 2 100
12 3 1 10
```动态编程状态结合了两种填充类型，而不需要记住早期类型还剩下多少填充。 每个填充都会处理一次，有其自己的限制，因此最终状态代表每个有效组合。
