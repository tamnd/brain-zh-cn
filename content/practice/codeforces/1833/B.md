 ## 解决方案
 ## 问题理解

 我们有两个长度相同的数组。 一个数组表示每天的预测温度，另一个数组包含实际温度，但实际值会被打乱并且顺序会丢失。 我们必须重建实际温度的有效排序，以便每天的分配值与预测一致：预测值和分配值之间的差异不得超过给定阈值$k$。 

关键约束是始终保证存在有效的分配，这消除了回溯或失败处理的需要。 该任务纯粹是建设性的：生成满足所有局部约束的第二个数组的任何排列。 

输入大小很大：所有测试用例的元素总数高达$10^5$。 这立即排除了二次或更高的匹配策略。 任何解决方案本质上都必须在每个测试用例的线性时间内进行排序和匹配。 

当价值观紧密聚集时，就会出现一个微妙的问题。 如果多个预测值接近且多个实际值接近，则无序的天真贪婪分配很容易失败。 例如，将每个配对$a_i$与最近的可用$b_j$即使存在全局有效匹配，也可以阻止将来的分配。 这正是必须用全局排序策略取代局部贪婪决策的结构。 

## 方法

 蛮力的想法是将其视为索引之间的二分匹配问题$a$和$b$, 连接$i$到$j$如果$|a_i - b_j| \le k$。 然后我们尝试找到完美的匹配。 这是正确的，但太慢了：即使构建边缘也会花费成本$O(n^2)$，并且通过流或匈牙利式方法进行匹配在以下位置是不可行的$n = 10^5$。 

关键的观察结果是约束在值上是单调的，而不是在位置上。 如果我们对两个数组进行排序，我们可以利用以下事实：$a$只能匹配较小的值$b$在允许的公差范围内，对于大值也类似。 排序将问题转化为一维对齐问题。 

一旦两个数组都排序完毕，存在保证意味着按排序顺序将它们配对始终是安全的。 任何偏离单调配对的尝试都可以在不破坏可行性的情况下转换回单调配对，因为交换反转仅在绝对差约束下提高或保持有效性。 

这将问题简化为排序后的简单贪婪扫描。

 | --- | --- | --- | --- |
 | 暴力匹配|$O(n^2)$或者更糟|$O(n^2)$| 太慢了 |
 | 排序+贪心匹配|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们在单个测试用例中工作。 

1. 对数组进行排序$a$按非递减顺序。 这会按照从最冷预报到最热预报的顺序排列日期，从而创建一致的分配结构。 
2. 对数组进行排序$b$按非递减顺序。 这将实际温度从最冷到最热进行组织，以便我们可以匹配可比的幅度。 
3.构造一个新数组$c$通过分配$c[i] = b[i]$为所有人$i$。 该配对对应于匹配$i$- 最小的预测$i$-最小的实际温度。 
4. 输出$c$。 

正确性取决于这样一个事实：任何有效的赋值都可以在不违反约束的情况下转换为排序的赋值。 直观上，如果两个分配交叉，交换它们不会使绝对差值超出允许的阈值，因为两个序列都按相同方向排序。 

### 为什么它有效

 假设存在一个有效排列$b$匹配$a$。 考虑配对中的任何反转：$a_i \le a_j$但$b_i > b_j$。 交换$b_i$和$b_j$不能增加最大值$|a_i - b_i|$和$|a_j - b_j|$因为将较大的值移动到较大的目标，将较小的值移动到较小的目标，可以减少绝对差异下两个方向的不匹配。 重复此消除操作会删除所有反转，从而产生单调匹配。 这种单调匹配正是排序配对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    
    print(*b)
```实现直接遵循派生结构。 对两个数组进行排序是唯一需要的转换。 最终的配对不需要显式检查，因为问题保证了可行性，并且单调重排保留了有效性。 

一个常见的陷阱是试图贪婪地匹配每个$a_i$具有本地有效的$b_j$使用两个带有条件检查的指针。 这种方法可能会陷入死胡同，因为早期的选择可能会阻碍以后可行的匹配。 对两个数组进行排序完全消除了这种依赖性。

 ## 边缘情况

 当所有值都在$a$是相同的，任意排列$b$只要值在范围内就有效。 排序仍然会产生有效的分配并避免歧义。 

什么时候$k = 0$，约束强制完全相等。 排序可确保相同的值在位置上对齐，因此无需额外的逻辑即可保留可行性。 

当值为负或分布广泛时，绝对差对称性可确保排序保持有效； 不需要基于符号的调整，因为排序纯粹基于幅度一致性而不是算术结构。
