 ## 解决方案
 ## 问题理解

 我们给定了一系列学生技能水平，我们想计算一下我们可以准确选择多少种方式`m`学生在两个同时约束下形成一个小组。 

首先，所选择的学生必须具有成对不同的技能值，这意味着我们不能选择两个具有相同水平的学生，即使他们是输入中的不同人。 其次，如果我们对所选值进行排序，则任何最小和最大所选值之间的差必须严格小于`m`，这相当于说所选值必须适合大小小于的窗口`m`。 

一个关键的微妙之处在于我们不是在选择值，而是在选择指数。 如果某个值在数组中多次出现，则每次出现都可以独立选择，只要它是该组中所选值的唯一出现即可。 

输出是大小精确的有效索引子集的数量`m`满足这两个条件。 

这些约束迫使我们为每个测试用例提供大致线性或近线性的解决方案。 自从总共`n`所有测试用例最多`2 \cdot 10^5`，任何超过的解决方案`O(n log n)`每个测试或对所有子集使用嵌套枚举是不可能的。 尝试所有大小子集的简单组合方法`m`是立即指数的，不能被考虑。 

有一些边缘情况打破了天真的推理。 

如果所有值都相等，例如`a = [5,5,5]`和`m = 2`，则不存在有效组，因为不可能存在两两不同的值，因此答案为零。 

如果`m = 1`，每个学生都形成一个有效的群体，因为这两个约束都得到了满足。 

如果所有值都不同，则第二个约束减少为选择任何值`m`取值范围小于的元素`m`，这强烈建议在排序值上使用滑动窗口。 

一个常见的错误是将重复项视为可自由使用，但它们实际上表现为压缩值结构内的独立选择，而不是组合的多重性。 

## 方法

 暴力方法会枚举大小的每个子集`m`，检查所有值是否不同，然后验证范围条件。 这立即导致$\binom{n}{m}$子集，即使对于`n = 40`。 

通过首先对值进行排序并检查每个子集的有效性，更加结构化的暴力破解会略有改进`O(m)`时间，但这仍然使子集计数呈指数增长。 

关键的结构简化是停止用指数来思考，而是用不同的值来思考。 如果我们选择`m`不同的值，那么我们必须恰好选择每个所选值的一次出现。 如果出现一个值`f`次，它贡献了一个乘法因子`f`我们可以在子集中实现该值的方式数量。 

那么问题就变成了：选择`m`不同的值，使得它们的最大值减去最小值小于`m`，并且对于每个这样的值集，乘以频率。 

现在我们对唯一值进行排序并在它们上使用滑动窗口。 对于每个右端点，我们找到满足范围约束的最小左端点。 在该窗口内，我们需要计算有多少种方法可以准确选择`m`与按多重性加权的频率不同的值。 

这成为窗口上经典的“选择具有权重的 k 个元素”，可以使用组合前缀乘积技巧来维护：维护窗口中频率的总乘积以及减去无效大小的方法。 这里的标准技巧是计算每个窗口选择任何大小子集的方法数量`m`通过维持二项式累积，但由于`m`每次测试都是固定的，我们可以在窗口扩展上维护一个正在运行的 DP。 

然而，有一个更简单的观察可以完全解决这个结构：因为我们准确地要求`m`不同的值，并且窗口仅在其长度至少为时才有效`m`，每个有效集对应于选择一个具有不同大小值的窗口`m`也满足范围约束。 一旦我们修复了一个窗口`m`不同的值，方式的数量是它们的频率的乘积。 

因此，我们在排序的不同值上滑动一个窗口，最多保持其大小`m`，并且每当大小等于`m`并满足`max - min < m`，我们添加频率的乘积。 

这将问题简化为排序、滑动窗口和乘法聚合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^m) | O(n^m) | O(米) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将数组压缩为值的频率图。 每个不同的值代表学生的“类型”，其频率代表如果选择该值，我们有多少个选择。 
2. 将不同的值排序到一个递增的数组中`vals`，并保持它们的频率平行。 
3.维护滑动窗口`[l, r]`超过`vals`使得窗口始终代表不同值的候选集。 
4. 展开`r`步步。 添加后`vals[r]`，检查条件是否满足`vals[r] - vals[l] < m`被侵犯。 如果是，请移动`l`转发直至其再次有效。 
5. 如果窗口大小恰好等于`m`，计算该窗口的贡献作为其中所有值的频率的乘积。 
6. 累加所有贡献模数`10^9 + 7`。 

最重要的部分是第 4 步，我们在其中强制执行范围约束。 这是有效的，因为一旦对值进行排序，任何窗口中的最大值和最小值始终位于其末尾，因此可以在 O(1) 内检查有效性。 

### 为什么它有效

 每个有效的学生选择都唯一对应于选择一组`m`范围小于的不同值`m`。 排序可确保任何此类集合在已排序的不同列表中显示为连续块。 滑动窗口将所有此类块枚举一次。 频率的乘积考虑了选择每个值的出现次数的独立选择，并且由于每个值最多被选择一次，因此不会发生过度计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        vals = sorted(freq.keys())
        f = [freq[v] for v in vals]

        k = len(vals)
        l = 0
        prod = 1
        ans = 0

        for r in range(k):
            prod = (prod * f[r]) % MOD

            while vals[r] - vals[l] >= m:
                prod = (prod * pow(f[l], MOD - 2, MOD)) % MOD
                l += 1

            if r - l + 1 == m:
                ans = (ans + prod) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先构建频率计数，因为重复项是乘法处理的，而不是在子集中组合处理的。 对唯一值进行排序后，滑动窗口确保我们只考虑有效范围。 

变量`prod`保持当前窗口内频率的乘积。 当左指针移动时，我们通过费马定理使用模逆进行除法。 这是安全的，因为 MOD 是素数。 

条件`r - l + 1 == m`确保我们只计算全尺寸的选择，避免部分窗口少计数或多计数子集。 

一个微妙的点是，我们从不显式枚举子集，因为一旦窗口固定，每个值都会独立贡献，因此乘法捕获所有组合。

 ## 边缘情况

 当所有学生共享相同的值时，算法会将所有内容压缩为单个不同的值。 如果`m > 1`，滑动窗口永远不会达到大小`m`，因此没有添加贡献。 如果`m = 1`，窗口立即贡献总频率，与单个学生选择的数量相匹配。 

当值全部不同但分布广泛时，许多窗口不符合范围约束。 指针`l`积极推进，确保无效的跨度永远不会被计算在内。 例如，使用值`[1, 100, 200]`和`m = 2`， 仅有的`[1,100]`有效，如果`99 < 2`失败，因此没有人做出贡献，并且算法正确地返回零。 

当重复项集中在有效窗口内时，例如`[2,2,2,3]`和`m = 2`, 窗户`[2,3]`贡献`3 × 1 = 3`，正确反映了从三个相同学生中挑选一个具有价值的三种方法`2`与单个相结合`3`。
