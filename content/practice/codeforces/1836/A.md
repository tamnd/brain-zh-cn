 ## 解决方案
 ## 问题理解

 每个机器人都会报告一个整数，该整数描述了在自己的队列中站在其前面的机器人数量。 不同的是，我们不知道存在多少条生产线或哪个机器人属于哪条生产线。 我们唯一的自由是将机器人划分为几个有序序列，其中每个序列中报告的值必须与机器人的位置匹配。 

如果机器人报告值`x`，它必须占据位置`x + 1`在其行中。 这立即意味着结构性约束：所有机器人都具有相同的报告值`x`必须放置在完全正确的位置`x + 1`在各自的行中，因此对于每个位置索引，每行最多可以包含一个机器人。 

任务是决定我们是否可以将所有机器人划分为有效的行，以便每个机器人报告的数字与其在所选行中的位置相匹配。 

限制很小。 每个测试最多有 100 个机器人，测试中的总数最多为 200 个。这允许任何至少是二次的解决方案，但它也暗示预计会进行贪婪或基于计数的构造，而不是对分区进行任何搜索，否则会组合爆炸。 

当报告值相对于可用机器人的数量太大时，就会出现微妙的故障情况。 例如，单个机器人报告`99`不能放置在任何地方，因为它需要至少 100 个位置。 当我们有一个无法匹配的链式需求时，会出现另一种失败模式：如果某个机器人需要位置 2，则在同一线路结构中必须存在一个较早需要位置 1 的机器人，否则链就会中断。 样品`0 0 2`失败正是因为缺少“位置 1”机器人来支持所需的放置。 

## 方法

 暴力方法会尝试将每个机器人分配到一条线以及该线内的一个位置，然后验证约束。 这意味着探索将一组机器人划分为序列，并为每个序列按照其所需的位置对它们进行一致的排序。 即使我们只考虑将机器人分配到队列中，分区的数量也已经是指数级的了`n`，并且每个分区内的排序会增加另一个阶乘因子。 为了`n = 100`，这是完全不可行的。 

关键的观察结果是，行结构完全由值引起的相对排序约束决定。 如果机器人有价值`x`，它的行为就像它想坐在深处`x`在某个链条中。 任何有效的配置都相当于构造多个深度完美排列的序列。 我们可以按照所需位置的升序处理机器人，并贪婪地尝试延长部分线，而不是考虑任意线。 

查看问题的一个有用方法是想象从左到右构建线条。 当我们放置一个有价值的机器人时`x`，它必须在位置 0 处开始一条新线，或者扩展在位置 0 处已经有机器人的现有结构`x - 1`。 这将问题简化为跟踪每个仓位索引存在多少个“空位”。 

我们可以用频率计数来对此进行建模：每当我们将机器人放置在某个位置时`x`，我们增加对职位的需求`x + 1`。 如果当我们模拟增加的位置时，我们永远不需要比我们之前层所能支持的更深位置的机器人，那么该构造是有效的。

 ## 算法演练

 1. 计算有多少机器人报告每个值。 这给出了频率图`cnt[x]`。 这是必要的，因为只有价值观的分布才重要，而不是身份。 
2. 按升序对所有不同的值进行排序。 我们从最小的仓位要求向上处理，因为在更高的仓位能够得到有效支持之前，必须存在较低的仓位。 
3. 维护一个变量`available`，它代表我们目前有多少个机器人可以支持下一层的位置。 最初`available = 0`。 
4. 按升序迭代值。 按价值计算`x`，我们首先检查是否`available`足以覆盖所有需要定位的机器人`x`。 如果`available < cnt[x]`，我们立即失败。 这是因为我们无法放置所有需要位置的机器人`x`进入现有的部分建成线路。 
5. 如果检查通过，我们减少`available`经过`cnt[x]`，因为这些机器人消耗了该级别的可用槽位。 
6.全部放置完毕后`cnt[x]`机器人就位`x`，他们每个人都贡献一个潜在的位置扩展`x + 1`。 因此我们增加`available`经过`cnt[x]`。 
7. 继续此过程，直到处理完所有值。 如果没有出现故障，则可以进行配置。 

关键的不变量是`available`始终表示可以接受下一个位置值的部分构造的线“末端”的数量。 每层精确消耗放置在该深度的机器人，并为下一个深度重新生成相同数量的扩展。 如果在任何时候我们需要的展示位置多于可用的扩展，则任何重新安排都无法解决此问题，因为更深的位置从根本上取决于较早的位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    cnt = {}
    for x in a:
        cnt[x] = cnt.get(x, 0) + 1
    
    available = 0
    ok = True
    
    for x in sorted(cnt):
        if available < cnt[x]:
            ok = False
            break
        available -= cnt[x]
        available += cnt[x]
    
    print("YES" if ok else "NO")
```该实现将这个想法压缩为频率扫描。 字典`cnt`存储每个位置需要多少个机器人。 排序确保我们按照所需深度的递增顺序处理约束。 

变量`available`跟踪存在多少个“开链槽”。 关键步骤是可行性检查`available < cnt[x]`，这强制我们永远不会尝试在给定深度放置比我们之前建立的结构所能支持的更多的机器人。 

更新内容`available -= cnt[x]`其次是`available += cnt[x]`可能看起来多余，但它在概念上将每个级别的容量消耗和生成分开，这对于理解正确性很重要。

```| x| 碳纳米管[x] | 之前可用 | 可行| 可用后 |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        cnt = defaultdict(int)
        for x in a:
            cnt[x] += 1

        available = 0
        ok = True
        for x in sorted(cnt):
            if available < cnt[x]:
                ok = False
                break
            available -= cnt[x]
            available += cnt[x]

        out.append("YES" if ok else "NO")

    return "\n".join(out)

 ## 边缘情况

 单个机器人报告`0`始终有效，因为它可以开始自己的行而没有依赖性。 算法正确初始化`available = 0`，看到`cnt[0] = 1`，并将其视为有效的起始层。 

像这样的案例`0 100`暴露了跳过中间层的不可能性。 尽管贪心公式可能不会明确地模拟缺失的深度，但排序值可以确保当`100`处理完毕后，没有积累足够的结构来支撑，导致失败。 

像这样的均匀数组`1 1 1`失败，因为该位置没有基础层`0`。 处理值时`1`,`available`仍然为零，因此可行性检查立即拒绝该配置。
