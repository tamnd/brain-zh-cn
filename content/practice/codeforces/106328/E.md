 ## 解决方案
 ## 问题理解

 我们得到了从 0 到 n 减 1 的数字排列。 对于每个位置 i，我们要严格向右查找并找到值小于 i 处的值的第一个位置 j。 如果不存在这样的位置，则 i 的答案为 n。 

因此，任务本质上是为每个索引计算排列中下一个较小的元素索引，但仅限于严格较小的值并且严格位于右侧。 

约束很小，n 最大为 1000，这可以立即进行二次推理，而无需考虑性能。 然而，这种扭曲不在于效率，而在于解释：我们不仅仅是找到一个值，而是找到一个严格较小的值出现的第一个位置。 

常见的失败情况是将“下一个较小的值”与“下一个较小或等于”混淆，或者错误地向左扫描而不是向右扫描。 另一个微妙的情况是最小的元素提前出现。 例如，在 [1, 0, 2] 这样的排列中，索引 1 的答案是 n，因为它的右侧不存在更小的值。 任何未显式处理缺少有效 j 的实现都将返回无效索引或留下垃圾值。 

## 方法

 最直接的方法就是从字面上模拟定义。 对于每个索引 i，我们扫描所有大于 i 的位置 j 并跟踪 p[j] 小于 p[i] 的第一个 j。 这是正确的，因为它完全遵循定义。 在最坏的情况下，对于像 [9, 8, 7, ..., 0] 这样的递减排列，每个位置 i 都会扫描几乎所有剩余位置，导致两次比较大约为 n 平方，当 n 等于 1000 时，这大约是 50 万次操作。 这很容易足够快。 

关键的观察结果是，问题中没有任何内容需要更高级的预处理，因为我们不需要范围查询或重复更新。 每个答案都是独立的，仅取决于数组的后缀。 

尽管可以使用单调堆栈在线性时间内解决下一个较小的元素问题，但这在这里是不必要的。 约束的简单性使得暴力解决方案既足够又最容易正确实现。

 ## 算法演练

 我们独立计算每个指数的答案。 

1. 对于从0到n减1的每个位置i，将答案初始化为n。 这表示未找到有效 j 的情况。 
2. 从 i 加 1 到 n 减 1 扫描 j。对于每个 j，将 p[j] 与 p[i] 进行比较。 如果 p[j] 较小，我们就找到了右侧的第一个有效位置，因此我们将 j 存储为 i 的答案并停止进一步扫描。 
3. 如果扫描完成后没有找到任何更小的值，则答案仍为 n，这正确地编码了有效位置的缺失。 

正确性来自于我们按升序扫描j，因此第一次遇到较小的值时自动是满足条件的最小有效索引j。 一旦发生这种情况，就无需再检查头寸。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    if not data:
        return
    
    n = data[0]
    p = data[1:1+n]
    
    res = [n] * n
    
    for i in range(n):
        for j in range(i + 1, n):
            if p[j] < p[i]:
                res[i] = j
                break
    
    print(*res)

if __name__ == "__main__":
    solve()
```该实现紧密地反映了该算法。 我们首先解析 n 和排列。 结果数组用 n 初始化以表示后备情况。 嵌套循环实现后缀扫描。 内部循环在找到有效的较小元素后立即中断，确保我们捕获第一次出现的元素。 

这里的一个常见陷阱是在找到第一个有效的 j 后忘记中断，这会用后面的索引覆盖答案并违反定义。 另一个错误是用零错误地初始化结果数组，这会错误地表明索引零有效，即使不存在这样的 j 。

 ## 边缘情况

 像 [0] 这样的单元素排列不会产生有效的 j，因此答案是 [1]。 该算法将 res[0] 初始化为 n，并且从未找到更小的元素，因此它正确地输出 1。 

对于像 [0, 1, 2, 3] 这样的严格递增排列，每个元素仅当它存在于右侧时才会看到较小的值，但没有一个元素存在。 每次扫描都会运行到最后，并将所有索引的结果保留为 n。 

对于像 [3, 2, 1, 0] 这样的严格递减排列，每个元素都会立即发现下一个元素更小。 内部循环在 j = i + 1 处中断，因此输出变为 [1, 2, 3, 4]，完全匹配第一个有效的较小索引规则。
