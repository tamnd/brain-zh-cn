 ## 解决方案
 ## 问题理解

 我们正在处理一个有 n 个顶点的有向图，但该图没有明确给出。 相反，我们只能通过询问任意有序的不同顶点对之间是否存在有向边来探测它。 我们的任务是确定是否存在一个特殊顶点，该顶点具有来自所有其他顶点的传入边，并且根本没有传出边。 如果存在这样的顶点，我们必须输出它们中的任何一个，否则我们输出-1。 交互限制我们每个测试用例最多 3n 个查询。 

关键的困难在于，该图是自适应的，因为答案与可能取决于我们的查询的某些隐藏图一致。 这消除了基于固定结构假设的概率捷径的任何可能性，因此每个决策在与过去答案一致的任何图表下都必须保持有效。 

每个测试用例 n 最多为 1000，总和为 1000，这表明 O(n^2) 查询处于临界状态，但如果每个测试都仔细控制，则可能可以接受。 然而，3n 个查询迫使我们采用线性查询策略，因此任何比较所有对的方法都立即不可能。 

当多个顶点几乎都是候选点时，就会出现微妙的边缘情况。 例如，在 3 个节点上的有向循环中，每个顶点的入度为 1，出度为 1，因此不存在答案。 “高入度顶点可能是候选者”的天真的想法失败了，因为我们无法在每个顶点没有 O(n) 查询的情况下直接计算度数。 

另一种故障模式出现在星形图中，其中一个顶点几乎是水槽，但有一个出边。 任何边的部分采样都可能错误地表明它是候选者，除非我们系统地消除非候选者。 

## 方法

 暴力策略将使用 n(n−1) 个查询计算完整的邻接矩阵，然后计算每个顶点的入度和出度。 这是正确的，因为它完全重建了图形并直接验证条件。 然而，它每个测试用例使用 Θ(n^2) 个查询，这远远超出了允许的 3n 限制。 当 n = 1000 时，每个测试大约有一百万个查询，这是不可行的。 

关键的观察是我们不需要图的完整结构知识。 我们只需要确定是否存在通用接收器，如果存在，则找到它。 此类问题通常需要线性消除过程：我们不确定所有度，而是维护单个候选点并使用成对比较来丢弃不可能的顶点。 

决定性的性质是，如果顶点 u 不是汇点，那么要么它具有到某个顶点的出边，要么存在另一个不能成为汇点的顶点，因为它错过了来自 u 的传入边。 这使我们能够以类似锦标赛的方式比较顶点，每个查询至少消除一个候选点。 

我们可以维护一个候选顶点。 对于每个其他顶点，我们在一个方向上查询候选顶点和该顶点之间的边。 根据答案，我们可以安全地消除候选顶点或其他顶点。 经过线性扫描后，我们最多只剩下一个候选者。 第二次验证通过最多使用 2(n−1) 次查询来检查它是否真正满足接收器条件，将总数保持在 3n 以内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) 次查询 | O(1) | O(1) | 太慢了|
 | 候选人淘汰 | O(n) 次查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 首先假设顶点 1 是候选汇。 这是任意的，因为在我们检查边之前任何顶点都可能满足条件。 
2. 迭代从 2 到 n 的顶点。 对于每个顶点 i，查询是否存在从候选点到 i 的边。 
3. 如果存在候选边 → i，则该候选边不能是接收器，因为接收器没有出边。 将候选者替换为 i。 
4. 如果不存在边候选 → i，则顶点 i 不能再成为接收器候选。 这是因为接收器必须从每个其他顶点接收一条边，但候选者没有到 i 的边，因此当 i 被取消资格时，候选者可能仍然有效。 
5. 在此通过之后，我们就有了一位在所有淘汰中幸存下来的潜在候选人。 
6. 执行验证过程：对于每个顶点 i ≠ 候选，使用查询检查两个条件。 首先，候选 → i 必须为假。 其次，i→candidate必须为真。 如果任何一项检查失败，则该候选人无效。 
7. 如果所有检查都通过，则输出候选者； 否则输出-1。 

这样做的原因是，消除过程中的每个查询都会删除至少一个不能成为接收器的顶点。 最终候选者是唯一没有因与接收器属性的任何矛盾而被消除的顶点，并且验证通过确保不存在自适应不一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    def ask(u, v):
        print("?", u, v)
        sys.stdout.flush()
        return int(input())
    
    cand = 1
    
    for i in range(2, n + 1):
        res = ask(cand, i)
        if res == 1:
            cand = i
    
    for i in range(1, n + 1):
        if i == cand:
            continue
        if ask(cand, i) == 1:
            print("! -1")
            sys.stdout.flush()
            return
        if ask(i, cand) == 0:
            print("! -1")
            sys.stdout.flush()
            return
    
    print("! {}".format(cand))
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve()
```实施直接遵循消除策略。 功能`ask`封装了交互和刷新，这在交互问题中是强制性的，以避免空闲错误。 

第一个循环维护单个候选者。 每次比较只需要一次查询，因为足以确定当前候选是否具有到另一个顶点的出边。 如果是的话，它不可能是水槽，所以我们立即切换。 

验证阶段更加严格。 我们确保候选人对任何人都没有外向优势，并且每个人都对候选人有优势。 这两个条件对于目标顶点都是必要且充分的。 

## 工作示例

 考虑一个 n = 4 的小图，其中顶点 3 是汇点。 假设边是这样的，除了 3 之外的每个顶点都指向 3，并且 3 没有出边。 

### 淘汰阶段

 | 步骤| 候选人 | 我| 查询 cand → i | 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 1 | 可以变成 2 |
 | 2 | 2 | 3 | 0 | 坎德停留2 |
 | 3 | 2 | 4 | 1 | 坎德变成4 |

 排除后，候选项为 4，在这个构建的场景中这是不正确的，这说明了为什么需要验证。 

### 验证阶段

 | 我| 坎 → 我 | 我 → 坎 | 结果 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 好的 |
 | 2 | 1 | 1 | 好的 |
 | 3 | 1 | 1 | 好的 |

 这里如果违反任何条件，验证就会失败； 在有效的接收器情况下，所有操作都会通过并且正确的顶点将得到确认。 

该迹线表明，在任意图下仅靠消除是不够的，第二阶段对于正确性至关重要。

 ## 边缘情况

 一个关键的边缘情况是多个顶点形成近汇结构但没有一个是有效的。 例如，在大小为 n 的有向循环中，每个顶点都有传入边和传出边，因此算法将在消除过程中不断替换候选点。 最终候选者将无法通过验证，因为它要么具有传出边，要么缺少来自某个顶点的传入边，从而触发正确的 -1 输出。 

另一种边缘情况是真实接收器存在但从未以消除它的方式进行直接比较。 消除步骤保证了这一点，因为接收器永远不会有出边，因此与任何顶点比较时它永远不会被丢弃； 它总是能在所有比较中幸存下来并不变地达到验证。
