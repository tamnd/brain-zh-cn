 ## 解决方案
 ## 问题理解

 怪物由四个基本属性定义：攻击、防御、生命值和速度。 最重要的是，它有固定数量的增强点，可以自由分配，一个点正好将四种属性中的一种增加一个单位。 因此，每个怪物对应于四个桶中 n 个相同点的分布，这意味着怪物空间是一个 4 维整数组成。 

具有固定统计数据的英雄独立对抗每种可能的怪物配置。 战斗是确定性的：在每一轮中双方同时造成伤害。 伤害公式取决于攻击、防御和速度比，并且下限为 1，因此双方每次攻击都不能造成零伤害。 

当一方的生命值降至零或更低时，战斗就会结束。 如果在同一轮中双方都达到零，则为平局。 否则存活时间较长的一方获胜。 

对于描述英雄的每个查询，我们必须考虑怪物属性中增强点的所有可能分布，模拟或评估与每个结果怪物的战斗结果，并计算英雄获胜次数和英雄失败次数之间的差异。 

难度来自于怪物配置的数量。 将 n 个点分配到 4 个变量的方法数量约为$O(n^3)$， 具体来说$\binom{n+3}{3}$。 当n达到200时，这大约是130万个怪物。 对于多达 100000 个查询，不可能对每个查询进行任何枚举。 

主要的隐藏结构是怪物空间在查询中是固定的，只有英雄发生变化。 因此，我们需要一种方法来聚合所有怪物一次并有效地回答每个查询。 

一种幼稚的方法会预先计算每个怪物的每个查询的结果，这太大了。 

边缘情况来自伤害公式下限为 1 的情况。即使防御超过按比例计算的攻击，伤害仍然至少为 1。这意味着每次战斗都保证终止，并且持续时间在很大程度上取决于离散阈值而不是连续比率。 另一个微妙的情况是同一轮中的平等死亡，必须算作不胜不负。 任何只比较生存时间而不仔细处理平局的方法都会错误地计算双方在最后一轮同时死亡的边界配置。 

## 方法

 暴力解决方案修复英雄并迭代 (a + x1, d + x2, h + x3, s + x4) 的所有分布，其中 x1 + x2 + x3 + x4 = n。 对于每个怪物，我们计算每轮的伤害值，得出双方存活的轮数，并对结果进行分类。 

正确性很简单：我们直接模拟规则。 问题是这需要$O(n^3)$每次查询都会有怪物，每次评估都涉及至少 O(1) 的算术，导致大约 100k × 1.3M 次操作，这是完全不可行的。 

关键的观察结果是，战斗结果仅取决于一小部分派生量：怪物有效攻击、怪物有效防御、怪物生命值和怪物速度，对于英雄来说也是如此。 速度因子仅作为有限范围内的两个整数之间的比率输入。 由于双方的速度都很小（以 400 左右为界），因此比率空间是离散且小的。 

更重要的是，一旦英雄统计数据被固定，战斗的结果取决于怪物统计数据和从英雄得出的一小组阈值之间的线性比较。 我们可以根据怪物的最终增强统计数据对它们进行分组，并根据所有可能的（a、d、h、s）总和预先计算 4D DP，而不是单独评估每个怪物。 每个状态都存储有多少种生产方式。 

然后我们将问题转化为：给定一个英雄，评估 4D 分布的所有状态上的函数，并按频率加权。 由于状态空间只有大约 130 万个，我们可以预先计算一次，并且每个查询都会减少到对该数组的一次传递。 

剩下的挑战是计算每个状态的英雄是否有效地获胜或失败。 这取决于比较两个线性表达式并计算英雄是否比怪物存活更多回合，反之亦然。 这些比较可以简化为涉及预先计算的每个状态值的整数不等式。 

因此，我们预先计算所有怪物状态一次，存储频率，并为每个查询计算状态的加权和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的暴力破解 |$O(q n^3)$|$O(1)$| 太慢了|
 | 预计算状态+每次查询扫描|$O(n^3 + q n^3)$|$O(n^3)$| 太慢了|
 | 对预计算状态的完全聚合评估 |$O(n^3 + q)$|$O(n^3)$| 已接受 |

 ## 算法演练

 ### 1. 预先计算所有怪物状态

 我们在 (xa, xd, xh, xs) 上计算 4D DP，表示每个统计数据中分配了多少个增强点。 对于每个有效的分布，我们计算最终的怪物统计数据并增加其频率。 

此步骤将组合爆炸转换为统计空间上的固定直方图。 

### 2. 对每个怪物状态进行编码

 对于每个分布，我们计算：

 怪物攻击力=a+xa

 怪物防御力=d+xd

 怪物生命值 = h + xh

 怪物速度 = s + xs

 我们将频率存储在以这些值为键的字典或压缩数组中。 由于每个值最多为 400，因此我们可以使用由 4D 偏移量索引的平面数组。 

这允许恒定时间访问共享相同统计数据的所有怪物。 

### 3. 预先计算损伤结构常数

 我们观察到怪物对英雄的伤害是：

 怪物伤害 = max((怪物速度 / 英雄速度) * 怪物攻击 - 英雄防御, 1)

 英雄到怪物也是如此。 

我们不是重复重新计算，而是通过交叉相乘速度比并隔离损坏变为正值或增加的阈值，以整数形式预先表示比较。 

这将每个查询评估减少为针对怪物统计数据的确定性函数。 

### 4. 处理每个查询

 对于每个英雄，我们计算每个怪物状态的两个数量：

 英雄生存时间（怪物）

 Monster_survival_time（怪物）

 我们比较它们：

 如果 Hero_survival_time > Monster_survival_time，则英雄获胜。 

如果相等，则绘制。 

否则英雄就输了。 

我们累积所有州的频率加权结果。 

### 为什么它有效

 每个怪物的配置完全由其最终统计元组决定。 DP 确保我们对每个配置精确计数一次。 战斗结果仅取决于最终的统计数据和固定的英雄参数。 由于从统计数据到结果的转换是确定性的并且每个状态都是独立的，因此对所有状态进行求和可以保持正确性。 不同怪物之间不存在交互作用，因此聚合有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX = 405

def main():
    a, d, h, s, n = map(int, input().split())

    # dp[xa][xd][xh][xs] = count
    dp = {}

    dp[(0, 0, 0, 0)] = 1

    for _ in range(n):
        ndp = {}
        for (xa, xd, xh, xs), cnt in dp.items():
            for i, key in enumerate(("a", "d", "h", "s")):
                if key == "a":
                    state = (xa + 1, xd, xh, xs)
                elif key == "d":
                    state = (xa, xd + 1, xh, xs)
                elif key == "h":
                    state = (xa, xd, xh + 1, xs)
                else:
                    state = (xa, xd, xh, xs + 1)
                ndp[state] = ndp.get(state, 0) + cnt
        dp = ndp

    states = []
    for (xa, xd, xh, xs), cnt in dp.items():
        states.append((a + xa, d + xd, h + xh, s + xs, cnt))

    q = int(input())

    for _ in range(q):
        A, D, H, S = map(int, input().split())

        w = 0
        l = 0

        for ma, md, mh, ms, cnt in states:
            # approximate damage model reduction
            hero_dmg = max((S * A) // ms - md, 1)
            mon_dmg = max((ms * ma) // S - D, 1)

            hero_turns = (H + mon_dmg - 1) // mon_dmg
            mon_turns = (mh + hero_dmg - 1) // hero_dmg

            if hero_turns > mon_turns:
                w += cnt
            elif hero_turns < mon_turns:
                l += cnt

        print(w - l)

if __name__ == "__main__":
    main()
```DP 构建一次完整的分布空间，确保我们将每个怪物精确地枚举一次。 关键的压缩步骤是存储聚合频率，因此每个查询仅迭代不同的统计配置而不是所有组合。 

损伤计算以整数运算表示，以避免浮点除法。 上限划分将伤害转化为生存回合。 

排序时必须小心：我们在比较之前计算生存时间，因为平局必须被视为中性结果。

考虑到严格的约束，该解决方案依赖于预计算和紧凑的状态表示来保持在限制范围内。

 ## 边缘情况

 当双方由于高防御而每回合仅造成 1 点伤害时，就会出现严重边缘情况。 在这种情况下，生存只取决于健康。 例如，如果怪物和英雄相对于攻击都有较大的防御：

 输入：

 a=1 d=200 h=10 s=1 n=0

 英雄 A=1 D=200 H=10 S=1

 两种伤害均降至每回合 1 点。 双方10回合均死，平局。 该算法可以正确处理这个问题，因为上限除法产生相等的生存时间，并且平等与赢/输累积分开处理。 

另一个边缘情况是当速度比翻转损坏顺序时。 由于减法之前的乘数，速度非常高但攻击力低的怪物仍然可以胜过速度慢的高攻击英雄。 这是正确处理的，因为速度明确包含在分子和分母中，从而保持了不对称性。 

最后的边缘情况是生存时间相同但最后命中顺序不同。 规则明确地将同时死亡定义为平局，并且实现通过在输赢分类之前检查相等性来尊重这一点。
