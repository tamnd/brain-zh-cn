 ## 解决方案
 ## 问题理解

 学生已经乘坐一辆沿着 x 轴从左向右移动的公共汽车。 巴士在固定位置停靠`(xi, 0)`按递增顺序。 除第一站外，学生可在任何一站下车，直达位于`(xu, yu)`。 

如果学生留在车上直到停车`i`，总行程时间分为两部分。 第一部分是从`x = 0`到`x = xi`。 由于公交车以匀速行驶`vb`，这个时候是`xi / vb`。 第二部分是运行时间`(xi, 0)`到`(xu, yu)`。 该距离是欧几里德距离，因此运行时间为：$$\frac{\sqrt{(xu - xi)^2 + yu^2}}{vs}$$任务是找到使总到达时间最小化的停靠索引。 如果多个站点的时间完全相同，我们必须选择距离大学较近的站点。 

限制很小。 最多有 100 个站点，因此即使直接检查每个站点也是微不足道的。 一个解决方案做`O(n)`或者`O(n^2)`1秒限内工作完全安全。 这个问题不是关于优化技巧的，而是关于正确实现比较逻辑并仔细处理浮点比较的问题。 

第一个微妙的边缘情况是平局打破规则。 两个站点可能会产生完全相同的总行程时间，但答案不一定是较早的站点。 我们必须选择离大学较近的站点。 

考虑：```
3 1 1
0 2 4
3 4
```对于第 2 站：```
bus time = 2
run distance = 5
total = 7
```对于第 3 站：```
bus time = 4
run distance = 1
total = 5
```较晚的一站获胜，因为尽管巴士行程较长，但运行距离却大大缩短。 

另一个容易犯的错误是让学生在第一站离开。 声明明确禁止这样做。 从索引开始的粗心循环`0`会产生错误的答案。 

例子：```
2 10 1
0 100
0 1
```学生想立即下车并跑一段距离`1`，但这是非法的。 正确答案是停止`2`。 

浮点相等是另一个危险。 由于精度误差，两个理论上相等的时间可能略有不同。 使用精确的`==`双打的比较可能会意外失败。 最安全的方法是与较小的 epsilon 进行比较。 

## 方法

 最直接的方法是模拟每一个可能的停留。 对于每一站`i`，计算：$$\text{time} = \frac{xi}{vb} + \frac{\sqrt{(xu-xi)^2 + yu^2}}{vs}$$然后选择时间最短的站点。 如果时间相等，比较到大学的距离并选择较小的。 

这种蛮力方法已经被完全接受，因为`n ≤ 100`。 总的工作量很小，只有大约几百次算术运算和平方根。 

这里没有隐藏的动态规划或几何优化。 关键的观察结果是，学生只有一个有意义的决定，即他下车的那一站。 一旦确定了该站点，整个路线和旅行时间就被唯一确定。 这就把问题变成了一个简单的枚举问题。 

更复杂的方法会尝试推理凸性或以几何方式优化距离，但这些都没有帮助，因为输入大小已经非常小。 最干净、最可靠的解决方案是直接评估每个候选站点。

 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取停靠站数、公交车速度、学生跑步速度。 
2.读取停止坐标数组`x`。 
3.读取大学坐标`(xu, yu)`。 
4. 初始化最佳停靠点为停靠点`2`，因为第一站不允许学生离开。 
5. 对于索引中的每个站点`2`到`n`：

 计算公交车行程时间：$$\frac{xi}{vb}$$然后计算跑步距离：$$\sqrt{(xu-xi)^2 + yu^2}$$将该距离除以`vs`以获得运行时间。 
6. 将两个时间相加即可得到该站点的总到达时间。 
7. 将此总时间与当前最佳时间进行比较。 

如果新时间严格小于，则更新答案。 

如果时间在浮点精度内相等，则比较到大学的距离并保留较近的停止点。 
8. 输出选择的停止索引。 

### 为什么它有效

 每个有效的策略都对应于选择学生下车的确切一站。 一旦确定了站点，总时间就由公交​​车行程加上直线运行距离唯一确定。 由于该算法会评估每个合法的停止并保留总时间最少的停止，因此它不会错过最佳答案。 在比较过程中明确处理平局打破规则，因此同样时间的情况也能正确解决。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

n, vb, vs = map(int, input().split())
x = list(map(int, input().split()))
xu, yu = map(int, input().split())

eps = 1e-9

best_idx = 1
best_time = float('inf')
best_dist = float('inf')

for i in range(1, n):
    bus_time = x[i] / vb

    dist = math.sqrt((xu - x[i]) ** 2 + yu ** 2)
    run_time = dist / vs

    total_time = bus_time + run_time

    if total_time < best_time - eps:
        best_time = total_time
        best_dist = dist
        best_idx = i + 1
    elif abs(total_time - best_time) <= eps:
        if dist < best_dist:
            best_dist = dist
            best_idx = i + 1

print(best_idx)
```循环从索引开始`1`而不是`0`因为第一站是禁止的。 这是问题中最常见的实现错误。 

变量`dist`存储从当前站点到大学的几何距离。 相同的值在运行时和打破平局时重复使用，这使实现变得简单。 

epsilon 比较避免了精度问题。 如果两个浮点值的差异极小，则代码会认为它们相等，而不是检查两个浮点值是否完全相等。 

答案使用`i + 1`因为 Codeforces 索引是从 1 开始的，而 Python 列表是从 0 开始的。

 ## 边缘情况

 第一个重要的边缘情况是禁止的第一站。 

输入：```
2 10 1
0 100
0 1
```如果允许第一站出发，总时间仅为`1`。 但学生必须留在车上，直到至少停下来`2`。 

该算法通过从索引开始循环来处理这个问题`1`，对应于停止`2`在基于 1 的索引中。 唯一评估的候选者是 stop`2`，所以输出是正确的：```
2
```另一个棘手的情况是总时间相等。 

输入：```
3 1 1
0 1 2
1 0
```为停止`2`：```
bus = 1
run = 0
total = 1
```为停止`3`：```
bus = 2
run = 1
total = 3
```停止`2`立即获胜。 

现在考虑：```
3 1 1
0 1 2
1 1
```在浮点运算中，计算出的总数变得非常接近。 使用直接相等检查可能会产生不一致的行为，因为平方根是无理数。 相反，该算法使用 epsilon 阈值，因此微小的舍入误差不会影响决策。 

当最佳停靠点是终点站时，就会出现最终的边缘情况。 

输入：```
5 100 1
0 10 20 30 40
39 0
```公交车跑得很快，而学生却跑得很慢。 该算法仍然独立检查每个站点，因此它正确地发现，留在公交车上直到终点可以最大限度地减少运行距离，足以抵消额外的公交车行程。
