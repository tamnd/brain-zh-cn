 ## 解决方案
 ## 问题理解

 我们被要求计算从 1 到 _n_ 有多少个数字在十进制表示中仅包含数字 0 和 1。 换句话说，十六进制的内存仅存储以 10 为基数写入时不包含除 0 或 1 以外的数字的数字。例如，1、10、11 是有效的，但 2、12、20 则不是。 

输入是单个整数 _n_，可以大到 10^9。 这意味着显式迭代从 1 到 _n_ 的每个数字的解决方案可能会执行多达十亿次检查，这对于 1 秒的时间限制来说太慢了。 与我们实际需要存储的少量数据相比，64 MB 的内存限制已经足够了。 

边缘情况在这里很微妙。 如果 _n_ = 1，则答案应为 1，因为存储了 1。 如果 _n_ = 2，答案仍然是 1，因为 2 无效。 如果 _n_ = 11，则数字 1、10 和 11 有效。 不检查上限而逐位生成数字的粗心解决方案可能会包含大于 _n_ 的数字，从而产生不正确的计数。 同样，将“二进制数”视为实际的以 2 为基数的数字也是错误的 - 这些数字是只有 0 和 1 位的十进制数。 

## 方法

 蛮力方法是迭代从 1 到 _n_ 的每个数字，检查每个数字，并计算仅包含 0 和 1 的数字。这工作正常，但对于 _n_ ≈ 10^9，它执行多达十亿次迭代，这太慢了。 操作计数大致是 _n_ 之前所有数字的位数之和，仍然约为 10^9 或更多。 内存使用量可以忽略不计，因为我们只需要一个计数器。 

关键的见解是，仅由 0 和 1 数字组成的数字形成了一个非常结构化的序列：它们正是可以表示为系数为 0 或 1 的 10 次幂之和的数字。这相当于以“十进制二进制”顺序生成数字：1、10、11、100、101、110、111、1000 等。 按升序生成它们可以让我们在超过 _n_ 时立即停止。 这将问题从迭代到 _n_ 减少到仅迭代 O(log_10(n)) 个数字组合，对于 n ≤ 10^9，这大约是 2^10 = 1024，这是一个巨大的加速。 

蛮力方法之所以有效，是因为检查每个数字中是否有数字 0 和 1 很简单。 当 n 很大时它会失败，因为我们做了不必要的工作。 观察到只有数字 0 和 1 的数字是相关的，让我们可以直接按升序生成它们，从而产生快速的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(1) | O(1) | 太慢了|
 | 最佳 | O(2^d) 其中 d ≈ n | 中的位数 O(2^d) | O(2^d) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`count`归零和队列`q`仅包含数字 1。这将设置从最小的数字开始生成有效数字。 
2. 当队列不为空时，删除第一个元素，调用它`x`。 如果`x`大于_n_，停止处理。 这确保我们永远不会计算超出允许范围的数字。 
3. 增量`count`减一是因为`x`是仅由数字 0 和 1 组成且不超过 _n_ 的有效数字。 
4. 通过在末尾附加 0 和 1 生成下一个数字`x`以十进制表示。 从数学上来说，计算`x * 10`和`x * 10 + 1`。 将这些号码添加到队列中。 这保证了我们按升序探索所有有效数字而不会遗漏任何数字。 
5. 重复直到队列为空或所有数字超过_n_。 

工作原理：队列中始终包含数字只有 0 或 1 且按升序排列的数字。 通过处理每个数字并生成其“小数子代”，我们一次性探索所有有效数字。 不变的是，小于 _n_ 且只有 0 和 1 位的数字不会被跳过，大于 _n_ 的数字不会被计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def main():
    n = int(input())
    count = 0
    q = deque([1])
    
    while q:
        x = q.popleft()
        if x > n:
            continue
        count += 1
        q.append(x * 10)
        q.append(x * 10 + 1)
    
    print(count)

if __name__ == "__main__":
    main()
```该代码首先读取输入并初始化计数器和队列。 我们使用双端队列来有效地从前面弹出并在后面追加。 在计数之前，每个数字都会根据_n_进行检查。 生成`x * 10`和`x * 10 + 1`确保我们按顺序考虑所有数字为 0 和 1 的数字。 一个微妙之处是使用`continue`超过 _n_ 之后而不是打破循环，因为队列中较大的数字可能仍然有效。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(2^d) | O(2^d) | 大约有 2^d 个数字，其中 d 位由 0 和 1 组成。对于 n ≤ 10^9，d ≤ 10，因此最多处理 1024 个数字。 |
 | 空间| O(2^d) | O(2^d) | 队列存储所有要处理的数字，其边界相同为 O(2^d)。 |

 考虑到这些限制，处理最多 1024 个数字的速度相当快，并且使用的内存可以忽略不计。
