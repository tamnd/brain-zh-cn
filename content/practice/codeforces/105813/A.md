 ## 解决方案
 ## 问题理解

 我们被要求构造一个固定长度的二进制字符串的大集合$n$，对任意两个所选字符串的不同程度有一个限制。 

每个字符串都由零和一组成。 禁止的情况是两个不同的字符串在一个位置上不同，这意味着您可以通过翻转一位而无需其他任何操作来将一个字符串转换为另一个字符串。 同样，它们的汉明距离绝不能恰好为 1。 

任务不是优化值或回答查询，而是显式输出满足此约束的任何最大可能集合。 

约束条件$n \le 15$表明整个空间$2^n$字符串足够小，可以进行结构推理而不是模拟成对检查。 比较所有字符串对的简单方法将涉及大约$2^n$候选人和$O(2^{2n})$配对检查，这已经是边界$n=15$因为这意味着大约十亿次比较。 

出现微妙的边缘情况时$n=1$。 只有两个字符串：“0”和“1”，并且它们只有一个位置不同。 这意味着我们不能同时采用两者，任何正确的解决方案都必须只输出其中之一。 在不检查这种情况的情况下假设对称或奇偶校验模式的粗心构造可能会错误地输出两个字符串。 

对于较大的$n$，小例子阐明结构。 为了$n=2$，最优答案是$\{00, 11\}$。 这对$\{01, 10\}$同样有效，但混合任何这些对都会违反规则，因为 00 与 01 有一位不同。 

这暗示二进制字符串的超立方图中的邻接是真正的约束：我们正在选择最大的顶点集，并且该集中没有边。 

## 方法

 暴力的观点是将每个二进制字符串视为一个节点$n$维超立方图，其中边连接恰好一位不同的字符串。 问题变成选择没有内部边缘的最大顶点子集，这是该图上经典的最大独立集问题。 

直接的暴力破解会枚举所有顶点子集并检查有效性。 和$2^n$顶点，子集的数量为$2^{2^n}$，即使对于$n=5$。 即使限制于检查所选子集中的成对冲突也会导致指数爆炸。 

关键的结构观察是超立方体是二分的。 任何二进制串都可以通过其位数的奇偶校验来分类。 翻转一位总是会改变奇偶校验，因此每条边都将偶校验字符串连接到奇校验字符串。 这将整个图分成两个独立的分区，其中分区内不存在边。 

一旦认识到这一点，最大独立集就是两个分区中较大的一个，这两个分区在超立方体中大小相等。 因此，要么所有偶校验字符串要么所有奇校验字符串形成有效的最优解，并且两者都有大小$2^{n-1}$。 

这将任务从子集上的组合搜索减少为基于奇偶校验的确定性构造。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^{2^n} \cdot n)$|$O(2^n)$| 太慢了 |
 | 基于奇偶校验的构建 |$O(n 2^n)$|$O(2^n)$| 已接受 |

 ## 算法演练

 最佳构造依赖于根据所有二进制字符串是否包含偶数或奇数个数对它们进行分组，然后完全选择一组。 

1. 迭代从0到的所有整数$2^n - 1$。 每个整数代表一个长度的二进制字符串$n$。 这种编码允许直接位操作而无需字符串操作。 
2. 对于每个数字，计算有多少位设置为 1。此计数确定该字符串属于偶数还是奇数奇偶校验类别。 
3. 选择一个奇偶类别作为答案集。 自然的选择是所有字符串都具有偶校验，因为它包含全零字符串并保持实现简单。 
4. 对于每个奇偶校验与所选类别匹配的数字，将其转换为长度为二进制的字符串$n$并存储它。 
5. 输出该集合的大小，后跟所有字符串。 

不明显的部分是为什么奇偶校验就足够了。 原因是翻转单个位总是会切换奇偶校验，因此同一奇偶校验类中的任何两个字符串必须在至少两个位置上不同。 这保证了自动满足约束而无需显式检查。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    res = []
    for mask in range(1 << n):
        if bin(mask).count("1") % 2 == 0:
            res.append(mask)

    print(len(res))
    for mask in res:
        s = format(mask, f"0{n}b")
        print(s)

if __name__ == "__main__":
    solve()
```该解决方案迭代所有位掩码并按奇偶校验过滤它们。 转换步骤使用固定宽度的二进制格式来保留前导零，这是必要的，因为较短的字符串会被错误地解释。 

一个微妙的实现细节是通过`bin(mask).count("1")`足以$n \le 15$，但在更高的约束下，更快的内置函数如`bit_count()`会更好。 这里它不是性能关键的。 

另一个重要的细节是准确保留字符串长度$n$，因为省略前导零会将不同的顶点折叠成不明确的表示。

 ## 边缘情况

 对于$n = 1$，仅存在两个字符串：“0”和“1”。 奇偶校验结构仅选择其中之一，因为“1”具有奇校验而“0”具有偶校验。 该算法恰好输出一个字符串，符合任何一对字符串在一个位置上不能不同的约束。 

为了$n = 2$，整个集合干净地分成两个部分。 该算法恰好选择 {00, 11}。 如果一个幼稚的实现试图在不检查全局结构的情况下贪婪地包含字符串，它可能会意外地将 01 和 00 包含在一起，从而违反规则，因为它们相差一位。 

为了$n = 3$，邻接变得更密集，但奇偶校验仍然保证分离。 所选集合中的每个字符串至少在两个位位置上与其他字符串不同，这可以通过直接比较 000 和 011 等代表性对来验证。 

该构造避免了所有此类陷阱，因为它从不局部推理对，仅推理超立方体的全局奇偶结构。
