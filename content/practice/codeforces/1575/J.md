 ## 解决方案
 ## 问题理解

 我们有一个`n × m`网格。 每个单元存储三个方向之一。 

值为`1`表示球向右移动一个单元格。 值为`2`表示球向下移动一个单元格。 值为`3`表示球向左移动一个单元格。 

球从第一排开始一个接一个地落下。 当球访问某个单元格并离开它时，该单元格的值将永久更改为`2`。 换句话说，任何球使用一个单元后，未来到达该单元的球将立即从该单元向下移动。 

对于每个球，我们必须确定它退出网格的列。 由于移动只能向左、向右或向下，因此球最终会从底行离开，答案就是它离开的列。 

网格尺寸最多为`1000 × 1000`，因此最多可以有一百万个单元。 球数可达`100000`。 

直接模拟每个球的成本太高了。 一个球可以访问许多单元格。 由于有多达`100000`球，反复走过已经处理过的区域将产生数亿甚至数十亿次操作。 

关键的观察结果是，一个单元仅在第一次被访问时才会表现出特殊的行为。 在那一刻之后它的价值变成`2`永远。 一旦处理完一个单元格，未来的球应该能够立即跳过它。 

当许多球从同一列开始时，就会出现一种微妙的情况。```
1 1 3
1
1 1 1
```第一个球向右移动并将单元格更改为`2`。 第二个球现在立即向下移动。 第三个球也立即向下移动。 

始终遵循原始网格的模拟将错误地为所有球生成相同的路径。 

另一个容易犯的错误是忘记水平移动可能会在向下移动之前继续跨越多个单元格。```
1 3
1 1 2
1
```球从第 1 列移动到第 2 列，然后从第 2 列移动到第 3 列，最后穿过第 3 列向下离开。 

仅查看起始单元格的解决方案将错误地回答第 1 列。 

一个更重要的情况是当一个单元格已经转换为`2`。```
2 2 2
1 1
2 2
1
```第一个单元格已经指向下方。 球应立即进入下一行。 任何在处理单元格后重新应用原始水平行为的尝试都是错误的。 

## 方法

 蛮力的想法很简单。 对于每个球，从其入口栏开始并重复遵循当前方向。 每当球离开一个单元格时，将该单元格更改为`2`。 

这个模拟是正确的，因为它完全遵循规则。 问题是它的运行时间。 

不同的球可以多次访问一个单元格。 在最坏的情况下，球可能会穿过`O(nm)`细胞。 高达`10^5`球，总工作量变得巨大。 

关键的观察结果是每个细胞最多改变一次。 

假设一个球访问了一个单元格，其值为`1`或者`3`。 离开后，细胞变成`2`。 任何未来到达该单元格的球将立即继续向下。 不再需要该单元昂贵的水平行为。 

这表明将处理过的细胞从未来的搜索中“删除”。 当一个球到达一个已经变成的单元格时`2`，我们希望直接跳转到其下方的下一个未处理的单元格，而不是遍历一长串已处理的单元格。 

这正是不相交集并集结构可以做到的。 

对于每一列，我们在行上维护一个 DSU。 当一个单元格被永久处理时，我们将其与下面的行合并。 然后，将来的查询可以立即找到该列中尚未处理的第一行。 

每个单元最多处理一次，并且由于路径压缩，每个 DSU 操作几乎是恒定的时间。 总功与单元数量加上球数量成正比。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下的 O(knm) | O(1) 超出网格 | 太慢了 |
 | 最佳 | O(nm α(n) + k α(n)) | O(纳米) | 已接受 |

 ## 算法演练

 ### 数据结构

 对于每一列，在行上创建一个 DSU`1..n+1`。 

排`n+1`是一个哨兵，意思是“网格之外”。 

如果行`r`在列中`c`已经处理完毕，我们联合`r`和`r+1`。 然后查找操作返回等于或低于的第一行`r`那仍然是活跃的。 

### 步骤

 1. 存储网格。 
2. 创建DSU阵列`parent[row][column]`。 
3. 对于每个球，从位置开始`(1, start_column)`。 
4. 当当前行位于网格内时，使用 DSU find 跳转到当前列中第一个未处理的行。 
5. 如果返回的行是`n + 1`，球已通过当前列离开网格。 将该列记录为答案。 
6. 否则检查该单元中存储的方向。 
7. 通过将单元格的行与同一列中的下一行合并起来，将单元格标记为已处理。 

该单元将永远不会再进行水平运动，因此未来的球应该跳过它。 
8. 如果值为`1`，移动到右侧的列。 
9. 如果值为`3`，移至左侧的列。 
10.如果值为`2`，保持在同一列。 
11. 在每种情况下，都从已处理单元格正下方的行继续。 

使用单元格后，它的行为将永久类似于向下的箭头。 从该位置开始的未来运动从其下方开始。 
12. 重复直到球离开网格。 

### 为什么它有效

 不变量是列的 DSU 始终准确地跳过其单元格已被处理的行。 

当球第一次访问某个单元格时，我们执行该单元格的原始方向，然后通过将该单元格与下一行合并，将该单元格从将来的考虑中永久删除。 

任何后来到达同一列和行的球都会使用 DSU 跳过该单元格，这相当于该单元格已经成为`2`并立即将球向下发送。 

由于每个单元格都被删除一次，并且所有未来的访问都正确地绕过它，所以模拟的行为与问题规则完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    a = [list(map(int, input().split())) for _ in range(n)]
    starts = list(map(int, input().split()))

    parent = [[r for _ in range(m)] for r in range(n + 2)]

    def find(r, c):
        while parent[r][c] != r:
            parent[r][c] = parent[parent[r][c]][c]
            r = parent[r][c]
        return r

    ans = []

    for start_col in starts:
        r = 1
        c = start_col - 1

        while True:
            r = find(r, c)

            if r == n + 1:
                ans.append(str(c + 1))
                break

            direction = a[r - 1][c]

            parent[r][c] = find(r + 1, c)

            if direction == 1:
                c += 1
            elif direction == 3:
                c -= 1

            r += 1

    print(" ".join(ans))

solve()
```网格使用从零开始的列索引存储，而 DSU 行使用从一开始的索引。 这反映了问题陈述并使哨兵行`n + 1`容易代表。 

每个列的 DSU 都是独立维护的。`parent[r][c]`告诉我们列中的下一个候选行`c`。 处理单元格时，我们通过将其行链接到其下方的第一个可用行来删除它。 

最微妙的部分是更新顺序。 在移除单元之前，我们必须读取单元的原始方向。 之后，该单元将被永久视为已处理，因此我们立即更新 DSU。 

行增量在执行指令后发生。 球总是离开一个单元格并从下一行继续。 水平移动仅改变列。
