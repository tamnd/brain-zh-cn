[CF 1575D - 可被二十五整除](https://codeforces.com/problemset/problem/1575/D)

 **评分：** 1800
 **标签：** 暴力破解、dfs 和类似、dp
 **求解时间：** 2m 1s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一个非常短的字符串，最多长度为 8，它表示一个部分未知的整数。 有些位置包含固定数字，有些包含通配符下划线，表示“此处允许任何数字”，有些包含字符 X，表示所有 X 位置必须共享相同的数字选择。 

任务是计算有多少个完整的数字分配产生可被 25 整除的有效整数，同时还要遵守最终数字不能有前导零的通常规则，除非它恰好为零。 X 引入的耦合是主要的复杂性，因为它全局地将多个位置联系在一起，这与每个位置独立的下划线不同。 

约束的长度非常小，这立即排除了渐近高效字符串处理的任何需要。 即使尝试所有数字分配的解决方案也是合理的，因为最坏的情况最多涉及共享数字的 9 个选择和每个通配符位置的 10 个选择，从而形成可管理的搜索空间。 

微妙的困难不在于复杂性，而在于正确性。 有两种常见的故障模式。 

一种是忽略 X 的全局约束。例如，在像这样的字符串中`1X2X`，独立处理每个 X 会超出无效分配的计数，例如分配不同的数字。 

另一个是前导零处理不当。 天真的替换可能允许像这样的字符串`0X`变成`00`，除非整个数为零，否则无效。 

最后，能否被 25 整除完全由最后两位数字决定。 检查部分构造的整除性或忘记强制后缀约束的粗心方法将错误地计算有效完成。 

## 方法

 自然而然就会出现暴力方法。 我们可以为每个通配符位置独立分配数字，也可以为 X 选择一个数字，然后测试每个结果数字。 由于长度最多为 8，因此我们可以枚举所有分配的可能性并计算满足两个约束的分配。 

然而，该结构比纯 10^8 枚举稍微受到更多限制。 每个下划线最多贡献 10 个因子，而 X 在全局范围内仅贡献 10 个选择。 在 8 个下划线加 X 的最坏情况下，这仍然是大约 10^9 种可能性，如果对每个候选字符串天真地实现的话，这个可能性太大了。 

关键的观察结果是，能否被 25 整除仅取决于最后两位数字。 这将全局条件折叠为对长度为 2 的后缀的约束。 我们可以专注于构建有效的结尾并计算前缀可以一致填充的方式，而不是生成完整的数字和检查整除性。 

第二个关键观察结果是，前导零约束仅取决于第一个非固定或指定的数字位置，并且一旦我们知道 X 使用哪个数字，就可以独立处理。 

这导致了受控枚举：选择 X 的数字，然后填充所有下划线位置，并在本地验证约束，特别是后缀有效性和前导零有效性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 所有作业的暴力枚举 | O(10^k) | O(10^k) | O(1) | O(1) | 太慢了 |
 | 修复X位+约束枚举| O(10 * 10^k)，有效修剪 O(10^6) | O(1) | O(1) | 已接受 |

 这里 k ≤ 8，因此优化的枚举完全在限制范围内。 

## 算法演练

 我们继续将 X 和独立通配符的角色分开。 

1. 首先，收集字符串中X的所有位置。 如果没有，我们将 X 视为没有贡献任何额外的约束。 
2. 尝试从 0 到 9 中每一个可能的数字 d 作为 X 的值。这是必要的，因为所有 X 字符必须共享一个值，而我们事先并不知道。 
3. 对于 d 的每个选择，构建字符串的工作版本，其中每个 X 都替换为 d。 这会将问题转换为仅包含数字和下划线的问题。 
4. 现在我们填写下划线。 每个下划线独立地采用 0 到 9 之间的任何数字，因此我们从概念上枚举了所有分配。 但是，除非必要，我们不会显式构建完整的字符串； 相反，我们在实施约束的同时计算配置。 
5. 对于每项已完成的作业，检查最后两位数字。 如果它们组成的数字能被 25 整除，则该数字有效。 由于长度很小，因此该检查是恒定时间。 
6. 还强制执行前导零有效性。 我们找到第一个非零数字。 如果所有数字都为零，则仅当整个字符串都为零时该数字才有效。 否则，第一个非零数字之前的任何前导零都是允许的，但我们必须确保该数字不是类似的`0000`受到不一致的对待。 
7. 将 X 位数字的所有选择的贡献相加。 

### 为什么它有效

 正确性来自于通过分配给 X 的值对解空间进行分区。每个有效的完成都恰好对应于 X 数字的一个选择，因此我们既不会重复计算也不会错过任何配置。 一旦 X 被修复，所有剩余的选择对于每个下划线都是独立的。 整除性约束仅取决于最后两位数字，这在分配后完全确定，因此最后检查就足够了。 前导零约束仅取决于全局前缀结构，该结构在完全赋值的情况下保留，确保不计算无效数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def valid_num(s):
    # leading zero rule
    if len(s) > 1 and s[0] == '0':
        # check if all zeros
        return any(c != '0' for c in s) == False

    # divisible by 25 check
    return int(s[-2:]) % 25 == 0 if len(s) >= 2 else int(s) % 25 == 0

def solve():
    s = input().strip()
    n = len(s)

    x_positions = [i for i, c in enumerate(s) if c == 'X']
    underscore_positions = [i for i, c in enumerate(s) if c == '_']

    ans = 0

    # all X must share same digit
    for xd in range(10):
        base = list(s)
        for i in x_positions:
            base[i] = str(xd)

        # enumerate all underscore assignments
        # since n <= 8, brute is acceptable with recursion
        def dfs(idx):
            nonlocal ans
            if idx == len(underscore_positions):
                cand = ''.join(base)
                if valid_num(cand):
                    ans += 1
                return

            pos = underscore_positions[idx]
            for d in range(10):
                base[pos] = str(d)
                dfs(idx + 1)

        dfs(0)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先识别所有 X 位置并尝试为它们尝试所有 10 个可能的数字分配。 对于每个这样的分配，它都会对下划线位置执行深度优先搜索。 每个递归步骤都会将一个数字分配给一个下划线。 一旦字符串被完全实例化，它就会被验证。 

关键的实现细节是改变共享列表`base`，这避免了递归期间重复的字符串复制。 即使在如此小的限制下，这对于性能也很重要。 

仅在最终构造的字符串上检查整除性，依赖于 Python 对最后两位数字的模运算。 前导零有效性在辅助函数内处理，该函数显式检查整个字符串是否为零。 

## 工作示例

 考虑输入`25`。 

这里没有通配符或 X 字符，因此 DFS 很简单。 

| 步骤| X 数字 | 下划线作业 | 构造字符串 | 有效后缀 | 有效 |

现在考虑输入`_5`。 

我们必须计算所有以 5 结尾且能被 25 整除的数字，这意味着最后两位数字必须是 25 或 75。 

| 步骤| X 数字 | 下划线| 字符串| 最后两位数字 | 有效 |

 ## 边缘情况

 一种重要的边缘情况是字符串在赋值后变为全零。 例如，输入`X_`其中 X 选择为 0 并且下划线也为 0 产生`00`。 这是有效的，因为整个数字为零并且前导零规则允许这样做。 该算法处理此问题是因为验证函数显式检查所有字符是否为零并允许这样做。 

另一种边缘情况是前导零后跟有效后缀，例如`_25`。 将下划线指定为 0 会产生`025`，这是无效的，因为它有前导零并且不是数字零。 检查正确地拒绝它，因为该字符串并非全零并且以零开头。 

最后一个微妙的情况是多个 X 位置，例如`X_X`。 DFS 并不独立分配它们； 相反，在计数开始之前，它们都固定为一位数字，以确保各个位置的一致性并防止计数过多。
