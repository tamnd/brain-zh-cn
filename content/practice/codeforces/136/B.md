 ## 解决方案
 ## 问题理解

 我们有两个十进制整数，`a`和`c`。 此问题中的计算机不使用二进制异或。 相反，它使用称为三元运算`tor`。 

申请`tor`，两个数字都以基数 3 书写。如果一个数字的位数较少，我们会用前导零填充它，以便两个长度匹配。 然后我们对每个位置独立地添加相应的数字模 3。 数字之间没有进位。 

例如，在基数 3 中：

 -`14 = 112`-`50 = 1212`填充后：

 -`0112`-`1212`逐位模 3 加法给出：

 -`(0+1)%3 = 1`-`(1+2)%3 = 0`-`(1+1)%3 = 2`-`(2+2)%3 = 1`所以结果是`1021₃ = 34`。 

任务是相反的。 我们知道`a`和`c`，并且我们必须构造最小的十进制整数`b`这样：```
a tor b = c
```约束在数值上非常小，两个值最多都是`10^9`。 以 3 为底的表示形式`10^9`只有大约 20 位数字，因为：```
3^20 ≈ 3.4 × 10^9
```这意味着我们可以安全地以三进制形式逐位处理数字。 任何相对于三进制位数以线性时间工作的算法对于这些约束来说都是有效的恒定时间。 

这个问题的危险部分是正确处理模 3 的减法。 粗心的实现可能会计算：```
b_digit = c_digit - a_digit
```并忘记结果必须保持在范围内`[0, 2]`。 

考虑：```
a = 2
c = 0
```三元形式：```
2 tor 1 = 0
```因为：```
(2 + 1) % 3 = 0
```正确答案是`1`， 不是`-2`。 正确的公式是：```
b_digit = (c_digit - a_digit + 3) % 3
```另一个容易犯的错误是在一个数字变为零后忘记处理剩余的数字。 

例子：```
a = 0
c = 5
```自从`5`三元形式是`12`，我们需要：```
0 tor b = b
```所以答案一定是`5`。 

如果我们尽快停下来`a == 0`，我们会错误地忽略更高的三进制数字`c`。 

前导零在概念上也很重要。 认为：```
a = 14
c = 34
```三元形式有不同的长度：```
14 = 112
34 = 1021
```我们必须将它们解释为：```
0112
1021
```否则数字对齐会中断并产生错误的答案。 

## 方法

 最直接的暴力解决方案是尝试所有可能的值`b`, 计算`a tor b`，并检查它是否等于`c`。 

计算`tor`，我们将两个数字都转换为基数 3 并模拟数字模 3 加法。 这个运算本身很便宜，大约20位运算。 问题在于搜索空间。 自从`b`可能大到大约`10^9`，暴力方法可能需要数十亿次检查。 即使每秒进行几百万次操作，这也是完全不可行的。 

暴力破解之所以能在逻辑上发挥作用，是因为该操作是确定性的。 对于每一位候选人`b`， 任何一个：```
a tor b = c
```或者它没有。 

关键的观察是`tor`对每个三进制数字的行为都是独立的。 位置之间不存在进位传播。 这将问题从全局搜索转变为局部重建问题。 

假设我们正在查看一个三进制数字位置：```
(a_digit + b_digit) % 3 = c_digit
```我们知道`a_digit`和`c_digit`，所以我们可以直接求解`b_digit`：```
b_digit = (c_digit - a_digit + 3) % 3
```每个三元位置都可以独立重建。 恢复所有数字后，我们将三进制结果转换回十进制。 

这是有效的，因为模算术给出了唯一的答案`{0,1,2}`对于每对`(a_digit, c_digit)`。

 | ---| ---| ---| ---|
 | 蛮力 | O(10^9 × log₃10^9) | O(10^9 × log₃10^9) | O(log₃10^9) | 太慢了 |
 | 最佳 | O(log₃10^9) | O(log₃10^9) | 已接受 |

 ## 算法演练

 1. 读取整数`a`和`c`。 
2.初始化：

 -`power = 1`-`b = 0`变量`power`表示当前的三进制位值：`1, 3, 9, 27, ...`。 
3. 同时`a`或者`c`仍有剩余的三进制数字：

 - 提取当前的三进制数字：```
da = a % 3
dc = c % 3
```- 计算所需的数字`b`：```
db = (dc - da + 3) % 3
```- 将这个数字添加到答案中：```
b += db * power
```这将重建满足以下条件的唯一三进制数字：```
(da + db) % 3 = dc
```4、去掉处理后的三进制数字：```
a //= 3
c //= 3
```5. 移至下一个三进制位置：```
power *= 3
```6. 处理完所有数字后，打印`b`。 

### 为什么它有效

 操作`tor`独立处理每个三进制数字，因为位置之间没有进位。 对于每个位置，我们解决：```
(a_digit + b_digit) % 3 = c_digit
```模运算保证恰好一位有效数字`b_digit`在`{0,1,2}`：```
b_digit = (c_digit - a_digit) mod 3
```由于每个位置都被正确重建并且位置不相互作用，所以完整的数量`b`是正确的。 

该解决方案也是自动最小化的。 每个三进制数字都是唯一确定的，因此只有一种可能`b`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a, c = map(int, input().split())

b = 0
power = 1

while a > 0 or c > 0:
    da = a % 3
    dc = c % 3

    db = (dc - da + 3) % 3

    b += db * power

    a //= 3
    c //= 3
    power *= 3

print(b)
```该解决方案直接以三进制处理数字，无需显式构建字符串或数字数组。 

表达式：```
da = a % 3
```提取最低有效的三进制数字。 整数除以 3 后会删除该数字。 

微妙的部分是：```
db = (dc - da + 3) % 3
```额外的`+3`防止负中间值。 没有它，情况如下：```
dc = 0
da = 2
```会错误地产生`-2`而不是`1`。 

变量`power`跟踪当前的三进制位值。 当我们计算一个数字时`db`，我们使用以下方法将其放入最终十进制答案中的正确位置：```
b += db * power
```当任一数字仍有剩余的三进制数字时，循环将继续。 这可以正确处理以下情况`a`和`c`具有不同的三元长度。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    a, c = map(int, input().split())

    b = 0
    power = 1

    while a > 0 or c > 0:
        da = a % 3
        dc = c % 3

        db = (dc - da + 3) % 3

        b += db * power

        a //= 3
        c //= 3
        power *= 3

    print(b)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("14 34\n") == "50\n", "sample 1"

# minimum values
assert run("0 0\n") == "0\n", "both zero"

# modulo wraparound
assert run("2 0\n") == "1\n", "requires modulo subtraction"

# different ternary lengths
assert run("0 5\n") == "5\n", "remaining digits must be processed"

# large values

 ## 边缘情况

 考虑：```
0 0
```循环永远不会执行，因为两个数字都已经为零。 初始化的答案`b = 0`是直接打印的。 这是正确的，因为：```
0 tor 0 = 0
```现在考虑：```
2 0
```三元形式：```
2 tor 1 = 0
```该算法计算：```
db = (0 - 2 + 3) % 3 = 1
```并返回`1`。 这证实了模校正可以正确处理负差异。 

考虑不同的数字长度：```
0 5
```三元表示：```
0 = 0
5 = 12
```算法继续运行，同时`c > 0`，产生三进制数字`2`和`1`。 重构后的数字正好是`12₃ = 5`。 

最后，考虑：```
8 0
```三元形式：```
8 = 22
```我们逐位求解：```
(2 + 1) % 3 = 0
(2 + 1) % 3 = 0
```所以：```
b = 11₃ = 4
```这个例子证实了位置之间不存在进位相互作用。 每个数字都是独立求解的。
