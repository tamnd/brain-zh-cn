 ## 解决方案

 ## 问题理解

 我们有两个长度相等的整数数组。 一个数组表示加密值，另一个数组表示顺序已丢失的一组密钥值。 每个原始消息值都使用按位异或与一个密钥值组合，但我们不再知道哪个密钥与哪个加密位置配对。 

我们的任务是重建任何原始消息，当与密钥数组的排列进行异或时，可以生成给定的加密数组，但在所有有效的可能性中，我们必须输出字典顺序上最小的可能消息。 

关键的难点在于配对：消息中的每个元素都必须与不同的键值匹配，并且为一个位置选择配对会限制未来的选择，因为键无法重复使用。 

这些约束将我们推向 O(n log n) 或 O(n) 类型的解决方案。 对于多达 300,000 个元素，任何尝试所有配对或重复重新计算每个位置最佳匹配的方法都会太慢。 排序和贪婪选择是必要的，但幼稚的贪婪策略可能会失败，因为异或的局部最小化不能保证全局字典序最优性。 

当为当前位置选择最小的异或伙伴时，会出现微妙的失败情况，从而阻止以后更好的配置。 

例如，假设我们贪婪地在索引 1 处选择最小的可能结果，但这会消耗一个本来可以在索引 2 处实现更小的结果的键。由于字典顺序在很大程度上取决于早期位置，因此正确的策略必须全局优先考虑较早的位置，而不仅仅是局部最小的 XOR 选择。 

## 方法

 暴力解决方案将尝试键数组的所有排列，计算每个排列的结果消息，并采用字典顺序最小的结果。 这是正确的，因为它直接模拟了问题的定义。 然而，它需要 n! 可能的分配，并且每个分配的评估成本为 O(n)，这使得它在 n 非常小时之外完全不可行。 

关键的观察结果是，我们重复执行相同类型的操作：对于每个加密值 Ai，我们希望选择一个密钥值 Pj，使得 Ai XOR Pj 变得尽可能小，但取决于密钥的剩余可用性。 这是按位值的经典贪婪匹配问题。 

XOR 结构表示二叉树（前缀树）。 每个键都可以按位插入到字典树中。 对于给定的 Ai，最好的可能伙伴是产生最小 XOR 结果的密钥，可以通过遍历与 Ai 位匹配的 trie 优先分支来找到该结果。 

然而，每个位置的纯粹贪婪是不够的，因为我们必须在整个输出中保留字典顺序。 按顺序处理 Ai 的正确方法仍然是贪婪的，但每个步骤都必须独立地为该 Ai 选择最佳可用密钥，因为较早的位置主导字典顺序，并且我们必须尽早最小化每个输出值。 

更深层的理由是，一旦我们将 Ai 固定在位置 i，后面位置的任何改进都无法弥补更差的 Ai。 因此，在给定剩余密钥的情况下，我们始终希望每一步都获得尽可能小的 Ai XOR 密钥。 trie 保证我们始终能够有效地找到最小的 XOR 伙伴，同时尊重删除。 

所以问题就简化为重复：

 选择最小化 Ai XOR Pj 的密钥 Pj，将其删除，然后继续。 

这正是一个带有删除的动态最小异或问题，使用带有计数的二进制 trie 来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!) | O(n) | 太慢了|
 | Trie 贪心匹配 | O(n·30) | O(n·30) | 已接受 |

 ## 算法演练

我们构建一个二进制特里树，其中每个节点存储有多少个数字通过它。 每个密钥都是根据其 30 位二进制表示形式插入的。 

然后我们按顺序处理加密的数组。 对于每个值 Ai，我们查询 trie 以找到最小化 Ai XOR 键的键。 该查询从最高位逐位贪婪地向下到 0，如果可能，总是更愿意将 XOR 位保持为 0。 

找到最佳键后，我们通过减少沿其路径的计数将其从特里树中删除。 

### 步骤

 1. 将所有键值插入到二进制 trie 中，在每个节点中存储计数，以便支持删除。 计数表示该子树中剩余多少未使用的键。 
2. 对于按顺序排列的每个 Ai，从 trie 的根开始并构造最佳匹配键。 从 29 到 0 的每一位，我们尝试遵循与 Ai 当前位匹配的分支。 如果该分支存在（计数为正），我们就采用它，因为它对该位的异或贡献为 0。 否则，我们必须采用相反的分支，这会在 XOR 结果中引入 1。 
3. 在遍历时，我们累积我们选择的重构键值，因为之后我们需要删除该键。 
4. 完成对 Ai 的遍历后，我们沿着所选键的路径递减计数，以将其从将来的考虑中删除。 
5.计算Ai异或choose_key并将其存储为位置i处的输出消息值。 

### 为什么它有效

 在每个位置，我们总是在所有可用密钥中选择最小化 Ai XOR 密钥的密钥。 trie 确保此选择对该步骤来说是全局最优的，因为它按位顺序探索所有有效密钥，并且始终倾向于将 XOR 的较高位保持尽可能小。 

最终消息的字典顺序与按顺序独立地最小化每个位置相一致：一旦在位置 i 处获得较小的值，以后的重新排列就无法改善字典顺序。 因此，每个位置的贪婪选择与全局目标是一致的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("ch", "cnt")
    def __init__(self):
        self.ch = [-1, -1]
        self.cnt = 0

class Trie:
    def __init__(self):
        self.nodes = [Node()]

    def insert(self, x):
        v = 0
        self.nodes[v].cnt += 1
        for b in range(29, -1, -1):
            bit = (x >> b) & 1
            if self.nodes[v].ch[bit] == -1:
                self.nodes[v].ch[bit] = len(self.nodes)
                self.nodes.append(Node())
            v = self.nodes[v].ch[bit]
            self.nodes[v].cnt += 1

    def erase_and_get_best(self, x):
        v = 0
        self.nodes[v].cnt -= 1
        res = 0
        path = []

        for b in range(29, -1, -1):
            bit = (x >> b) & 1
            preferred = bit
            other = bit ^ 1

            if self.nodes[v].ch[preferred] != -1:
                nxt = self.nodes[v].ch[preferred]
                if self.nodes[nxt].cnt > 0:
                    v = nxt
                    res = (res << 1) | preferred
                    path.append((v, preferred))
                    continue

            nxt = self.nodes[v].ch[other]
            v = nxt
            res = (res << 1) | other
            path.append((v, other))

        # erase along path
        v = 0
        self.nodes[v].cnt -= 1
        for b in range(29, -1, -1):
            bit = (res >> b) & 1
            v = self.nodes[v].ch[bit]
            self.nodes[v].cnt -= 1

        return res

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    P = list(map(int, input().split()))

    t = Trie()
    for x in P:
        t.insert(x)

    out = []
    for a in A:
        best_key = t.erase_and_get_best(a)
        out.append(str(a ^ best_key))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```该实现依赖于维护子树计数，以便特里树中的每个决策都尊重密钥的剩余可用性。 遍历总是倾向于将位与 Ai 匹配以最小化 XOR，并且仅在必要时偏离。 

一个微妙的实现细节是删除：所选路径上的每个节点都必须减少其计数，以便将来的查询不会使用已删除的键。 如果没有正确的计数，算法可能会重复使用密钥或进入无效分支。 

## 工作示例

 ### 示例 1

 输入：```
3
8 4 13
17 2 7
```我们将键 17、2、7 插入到 trie 中。 

对于 A1 = 8，我们查询最佳密钥。 假设 trie 返回 17，则 8 XOR 17 = 25。 

对于 A2 = 4，剩余的密钥是 2 和 7。最佳匹配是 2，给出 4 XOR 2 = 6。 

对于 A3 = 13，剩余密钥为 7，得到 13 XOR 7 = 10。 

输出变为：```
25 6 10
```这匹配有效的最佳排列之一，并且较早位置的任何偏差都会增加字典顺序。

 ## 边缘情况

 一种边缘情况是多个键对给定 Ai 产生相同的最小 XOR 值。 特里树将根据结构确定性地选择一个，但只要尊重计数，任何有效的抢七都是可以接受的。 该算法自然地处理这个问题，因为它总是更喜欢相同的结构路径。 

另一种情况是许多键共享长前缀。 例如，如果所有键仅在低位不同，则早期特里树决策始终遵循相同的高位路径。 该算法仍然表现正确，因为分支仅发生在第一个不同的位，并且计数确保有效的可用性。 

第三种情况是许多位置的 Ai 为零。 然后，trie 总是尝试直接选择最小的可用密钥，因为 XOR 等于密钥本身。 删除逻辑确保没有密钥被重用，并且即使在重复相同的查询下结果也保持正确。
