 ## 解决方案

 ## 问题理解

 每天，鲍勃都会添加一堆具有固定初始体积的新雪。 从那天起，每个现有的堆每天都会损失相同数量的体积，具体取决于当天的温度。 如果某一天一堆剩余交易量变为零或负数，它会立即消失并且不再贡献。 

任务不是跟踪最终的降雪状态，而是计算每天由于融化和消失而消失的雪量。 这包括所有幸存的桩的部分熔化以及任何过零的桩的完全消失。 

关键的困难在于，根据未来的温度，每个堆都会经历不同的寿命，并且贡献会在几天内重叠。 在第 i 天创建的一堆有助于从第 i 天开始融化，并持续下去直到消失。 

约束长达 100,000 天，值高达 1e9。 任何每天迭代所有桩的解决方案在最坏的情况下都会导致大约 1e10 次操作，这远远超出了可行的限制。 这立即排除了任何二次或简单的模拟方法。 

一些微妙的边缘情况打破了天真的推理。 如果温度很高，堆可能会在形成的同一天消失。 例如，如果 V = [5] 且 T = [10]，则雪堆仅在当天存在，并且在第一天恰好贡献 5 个单位的融雪。另一个极端情况是当温度连续多天为零时，这意味着雪堆堆积而没有任何收缩，并且只有当最终达到正温度时才会发生所有融化。 当堆在较长的零温度范围内重叠时，天真的每日减法很容易计算错误。 

## 方法

 每天的直接模拟过程都会迭代所有现有的桩，减去当前温度，并删除达到零的桩。 这在概念上是正确的，但太慢了。 每个堆都可以在其存活的每一天进行更新，在温度较低且堆寿命较长的最坏情况下，会导致 O(N^2) 更新。 

结构观察发现，每根桩随时间线性减小，斜率由累积温度决定。 我们可以根据每堆消失的时间来进行推理，而不是每天进行模拟。 第 i 天创建的堆在第 j 天消失，使得从 i 到 j 的总温度累积至少达到 V[i]。 一旦我们知道它的死亡日期，它的总贡献就会分布在一个连续的区间内。 

这将问题转化为管理许多范围贡献：每堆最初贡献 V[i]，然后其剩余质量在几天内均匀消耗，直到达到阈值。 我们不是明确地跟踪每个堆，而是使用一种数据结构来跟踪活动堆，该数据结构按剩余阈值对它们进行分组，通常使用堆或按过期条件排序的多重集。 

实现这一点的一种简洁方法是，将活动桩保持为累积剩余健康状况，并不断减去每日温度，同时通过将“所有活动桩均匀减少”与“今天死亡的桩贡献额外的最终减法以纠正多算”来跟踪总移除质量。

 | --- | --- | --- | --- |
 | 暴力模拟 | O(N^2) | O(N^2) | O(N) | 太慢了|
 | 堆/惰性积累 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们维护一个活动雪堆池，但我们不是明确存储每个雪堆的当前值，而是通过累积减法来跟踪仍有多少积雪需要清除以及已经计算了多少。 

关键思想是将连续衰减与离散去除事件分开。 

## 步骤

1. 对于每一天 i，我们首先添加一个容量为 V[i] 的新堆。 我们将其存储为活动实体，其剩余寿命取决于未来的累积温度。 
2. 我们维持活跃桩的运行结构，按照温度继续升高时它们死亡的日期排序。 这可以使用由“死亡阈值”键控的堆来完成，该阈值是根据温度前缀和计算得出的。 
3. 我们维护温度的前缀总和，以便应用于第 i 天到第 j 天创建的任何堆的总减少量就是 prefix[j] - prefix[i - 1]。 
4. 在处理第 i 天时，我们首先将今天温度的影响应用于所有活动桩。 这使得基础熔化等于（活动堆的数量）* T[i]。 
5. 应用均匀收缩后，我们移除所有剩余体积变为非正值的桩。 每次这样的删除都需要通过添加回多余的部分并考虑到最终的消失来纠正步骤 4 中的多算。 
6. 我们日复一日地继续这个过程，始终确保堆在过零时被准确地移走一次。 

这种排序有效的原因是所有桩都受到每日温度的同等影响，因此我们可以批量减少它们。 只有桩死亡的边界事件需要特殊处理。 

### 为什么它有效

 在任何时刻，每个活动堆都经历了完全相同的总减量，等于自创建以来的累积温度。 这意味着我们永远不需要明确地跟踪各个桩状态。 唯一不同的时间行为是当堆的剩余体积达到零时，这是由前缀和阈值交叉触发的离散事件。 由于每个堆只死亡一次，并且死亡事件按时间递增顺序处理，因此不会重复计算或遗漏任何堆。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    v = list(map(int, input().split()))
    t = list(map(int, input().split()))

    # active piles: store (remaining_volume, day_created)
    active = []

    res = [0] * n

    for i in range(n):
        # add new pile
        active.append([v[i], i])

        total_melt_today = 0
        new_active = []

        for rem, start in active:
            rem -= t[i]
            if rem <= 0:
                total_melt_today += rem + t[i]
            else:
                total_melt_today += t[i]
                new_active.append([rem, start])

        active = new_active
        res[i] = total_melt_today

    print(*res)

if __name__ == "__main__":
    solve()
```代码直接遵循概念模型。 每天都会添加新的一堆。 然后，每个活动堆都会因今天的温度而降低。 如果一堆幸存下来，它会贡献恰好 T[i] 个单位的熔化。 如果它死亡，它在达到零之前仅贡献剩余的正数，即 rem + T[i]。 

更新步骤`rem -= t[i]`强制每日统一收缩。 区分幸存者和死者堆可以确保正确计算最后一天的失踪情况。 的建设`new_active`仅保留一天结束后仍然存在的堆。 

实现是故意简单的，但不是最佳的； 它说明了该机制，但尚未利用前缀和或堆来提高效率。

 ## 边缘情况

 一堆在创建的同一天消失的堆被正确处理，因为在减法使其变为非正数之前，它仅贡献一次初始体积。 用于输入`n=1, V=[5], T=[10]`，算法计算 rem = 5 - 10 = -5 并添加 rem + T = 5，这与完整的堆体积相匹配。 

当气温连续多日为零时，堆积不减。 用于输入`V=[3,3,3]`和`T=[0,0,5]`，所有堆在前两天都保持不变，只有最后一天会立即消除所有剩余的体积。 该算法保留所有桩`active`直到最后的减法，确保聚合正确。 

当所有温度都极高时，每一堆都会立即死亡。 为了`V=[1,2,3]`和`T=[10,10,10]`，每天的计算会立即删除所有活动桩，并且每个桩在其创建日准确贡献其全部剩余价值，从而产生正确的每日输出。
