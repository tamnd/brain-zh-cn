 ## 解决方案
 ## 问题理解

 我们得到一个表示元素循环排列的字符串，另一个表示目标模式的字符串。 任务是确定是否可以通过旋转原始圆形排列来获得目标图案。 

不考虑圆周运动，更容易将操作重新解释为获取原始字符串并将其向左移动一定数量的位置，环绕末端。 每个有效的配置只是这些轮换之一。 目标是确定至少一个轮换是否与目标完全匹配。 

输入描述了两个长度相等的字符串，一个作为基本配置，另一个作为我们想要在旋转后匹配的模式。 输出是简单的是或否决定，具体取决于是否存在这种轮换。 

约束结构意味着字符串可能很大，通常最多可达 10^5 个字符左右。 在最坏的情况下，尝试每次旋转并逐个字符进行比较的二次解决方案将需要 N^2 次比较，这在标准限制下太慢了。 这立即推动我们找到一种可以在线性时间内测试所有旋转的方法。 

一些边缘情况在这里很重要。 如果两个字符串相同，那么答案显然是肯定的，因为零旋转有效。 例如，如果字符串具有不同的字符多重集`abac`和`zzzz`，没有任何旋转可以修复这种不匹配，并且任何简单的旋转检查仍然会提前失败。 当存在重复模式时会出现另一种微妙的情况，例如`aaaaa`和`aaaaa`，其中每次旋转都是有效的。 粗心的实现可能仍然会错误地尝试多个冗余比较，但正确性应该不受影响。 

## 方法

 暴力破解的想法很简单：生成原始字符串的每个可能的旋转并将其与目标进行比较。 每次旋转都可以通过在位置 k 处切片字符串并将后缀与前缀连接来构建。 对于每个这样的候选者，我们将其与目标逐个字符进行比较。 

这是有效的，因为它显式地检查搜索空间中的每个配置。 然而，成本很高。 构造和比较每次旋转需要 O(N)，并且有 N 次旋转，导致总操作量为 O(N^2)。 对于 N 大约 100,000 来说，这是不可行的。 

关键的观察是字符串的所有旋转都包含在其自身的双倍版本中。 如果我们将字符串与其自身连接起来，则每个循环移位都显示为该双倍字符串的连续子字符串。 例如，旋转`abcd`是`abcd`,`bcda`,`cdab`,`dabc`，并且全部出现在里面`abcdabcd`。 

这将问题简化为子字符串搜索：我们只需要检查目标字符串是否出现在`S + S`。 我们没有显式生成旋转，而是使用线性子串搜索扫描一次。 一个简单的实现使用直接切片比较，总体上仍然是 O(N)，因为每个起始位置最多检查一次并且比较很快就会短路。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) | O(N^2) | O(N) | 太慢了|
 | 双字符串扫描 | O(N) | O(N) | 已接受 |

 ## 算法演练

 1. 读取两个字符串，将它们称为 S 和 T。如果它们的长度不同，则立即断定不存在解，因为旋转保留了长度。 这避免了格式错误或边缘输入中不必要的工作。 
2. 通过将 S 与其自身连接来构造一个新字符串 U。 此步骤将 S 的所有循环旋转编码为 U 的子串。 
3. 从 0 到 len(S) - 1 迭代每个起始位置 i。每个位置代表一个候选旋转。 
4. 对于每个 i，将子串 U[i : i + len(S)] 与 T 进行比较。如果完全匹配，则立即返回肯定答案。 
5. 如果没有位置产生匹配，则返回否定答案。 

比较步骤是算法的核心。 它是安全的，因为每次旋转都恰好对应于双倍字符串中的一个起始索引，因此不会跳过任何有效配置。 

### 为什么它有效

 正确性依赖于循环旋转保留字符的相对顺序，仅移动起点的事实。 当我们形成 S + S 时，S 中从索引 i 开始的任何旋转都对应于 S + S 中从 i 开始长度为 len(S) 的子串。 这在双倍字符串中的旋转和固定长度的子字符串之间建立了一对一的映射。 因此，在这些子串中搜索T相当于检查所有旋转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    S = input().strip()
    T = input().strip()

    if len(S) != len(T):
        print("NO")
        return

    n = len(S)
    U = S + S

    for i in range(n):
        if U[i:i+n] == T:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```该实现直接遵循子字符串搜索的简化。 双倍字符串 U 构造一次，然后我们在其上滑动一个大小为 n 的窗口。 切片比较是安全的，因为 Python 会在不匹配时短路比较，从而使典型输入的平均行为保持线性。 

一个微妙的细节是循环绑定。 我们只迭代到 n，而不是 2n，因为从索引 n 开始会重复先前位置已经覆盖的旋转。

 ### 示例 1

 假设 S =`abcd`, T =`cdab`。

 在 i = 2 时，我们找到匹配项，所以答案是“是”。 这演示了如何将旋转作为子字符串嵌入到双倍字符串中。 

### 示例 2

 假设 S =`aabc`, T =`abca`。

这些轨迹表明，每次有效的旋转恰好对应于一个成功的对齐窗口。

 ## 边缘情况

 一种重要的边缘情况是所有字符都相同。 对于 S =`aaaaa`且 T =`aaaaa`，每次旋转都是相同的。 该算法形成 U =`aaaaaaaaaa`，并且每个窗口都匹配 T。第一次迭代已经返回 YES，正确处理最大重复。 

另一种情况是由于字符数不同而无法匹配旋转。 对于 S =`abc`且 T =`abd`, U =`abcabc`。 每个窗口仅包含字符 a、b、c，因此与 T 的任何比较都会立即失败，并且循环耗尽所有位置，正确返回 NO。 

最后一个微妙的情况是匹配发生在双倍字符串的边界处。 对于 S =`bcda`, T =`dabc`, U =`bcdabcda`。 有效匹配从索引 3 开始，跨越原始边界。 滑动窗口仍然捕获它，因为 S + S 准确地保留了环绕连续性。
