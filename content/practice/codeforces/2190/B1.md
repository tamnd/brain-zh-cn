 ## 解决方案
 ## 问题理解

 我们给出了一个规则的括号序列`s`。 常规括号序列 (RBS) 是每个前缀至少包含同样数量的前缀的序列`'('`作为`')'`，并且左括号和右括号的总数相等。 

我们可以删除任意字符`s`，保持剩余字符的原始顺序。 得到的字符串`t`也必须是非空的常规括号序列。 

在所有这样的子序列中`t`，我们想要最大可能的长度，使得`t`_更好_于`s`。 

排序是按字典顺序排列的，有一个额外的规则：如果较短的字符串是其前缀，则较长的字符串被认为较大。 自从`'(' < ')'`在问题的排序中，字符串不同的第一个位置必须是`'('`在`t`和`')'`在`s`。 

输入保证`s`本身已经是苏格兰皇家银行了。 所有测试用例的总长度最多为`2 · 10^5`，这意味着我们需要接近线性时间的东西。 任何显式检查许多子序列的解决方案都是立即不可能的，因为子序列的数量是指数级的。 

主要的微妙之处在于，子序列和词典编排上更大的序列以一种不明显的方式相互作用。 

考虑`s = "()"`。 

唯一非空的 RBS 子序列是`"()"`本身。 因为它等于`s`，这还不是更好。 答案是`-1`。 

考虑`s = "(())()"`。 

一个诱人的想法是删除一些字符并使序列按字典顺序变大。 然而，每个真 RBS 子序列的长度最多为`4`，并且没有一个比原来更好。 正确答案是`-1`。 

另一个容易犯的错误是认为任何删除都会产生不同的 RBS。 例如：```
s = (()(()))
```子序列`"((()))"`是有效的。 在第一个不同的位置，原件有`')'`而子序列有`'('`，所以比较好。 答案是`6`。 

挑战在于准确识别这样的子序列何时存在并最大化其长度。 

## 方法

 暴力方法将枚举所有子序列`s`，检查哪些是常规括号序列，并将它们进行比较`s`，并保留最长的有效答案。 

这是正确的，因为它确实测试了每个候选人。 不幸的是，一串长度`n`有`2^n`子序列。 即使是为了`n = 60`这是没有希望的，而问题允许总长度`200000`。 

我们需要利用常规括号序列的结构。 

自从`t`是一个子序列`s`，它永远不能长于`s`。 唯一的办法是`t`比`s`是在他们首先不同的某个位置，`t`包含`'('`尽管`s`包含`')'`。 

这在操作上意味着什么？ 

假设我们从左到右读取两个字符串。 在第一个差异之前，字符必须相同。 在第一个差异处，下一个未使用的字符`s`是`')'`，但我们跳过它，稍后再采取一些`'('`。 

所以关键的问题就变成了：

 我们能找到一个`')'`在稍后某处跟随的序列中`'('`？ 

如果存在这样的模式，那么在该位置我们可以删除它`')'`并继续。 生成的子序列按字典顺序变得更大。 

现在回想一下常规括号序列的经典属性。 每个 RBS 都可以唯一地分解为原始块。 原始块是一个 RBS，其余额仅在结束时返回零。 

示例：```
()()()      -> () + () + ()
(())()      -> (()) + ()
(()(()))    -> one primitive block
```如果序列至少由两个基元块组成，则它们之间存在边界：```
... ) ( ...
```一个块的右括号后面紧接着（稍后）是下一个块的左括号。 

在这种情况下，我们可以恰好删除一个匹配的原始块边界对并获得长度为 RBS 的子序列`n - 2`那比`s`。 

如果序列仅由一个原始块组成，则每个`'('`出现在完成该块所需的每个无与伦比的关闭动作之前。 无法在保留 RBS 子序列的同时创建所需的一阶差分。 不存在有效答案。 

所以问题归结为计算原始块。 

如果只有一个原始块，则回答`-1`。 

如果至少有两个原始块，则回答`n - 2`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 扫描括号序列，同时保持当前平衡。 
2. 增加余额`'('`并减少它`')'`。 
3. 每当余额变为零时，一个原始块就结束了。 
4. 计算扫描期间余额达到零的次数。 该计数等于原始块的数量。 
5. 如果计数正好为1，则输出`-1`。 

单个基元块无法产生更好的正则括号子序列。 
6.否则输出`n - 2`。 

至少有两个原始块，我们可以从后面块的开头删除一个左括号和一个匹配的右括号，从而获得长度为 RBS 的子序列`n - 2`按字典顺序，它比原始版本大。 

### 为什么它有效

 正则括号序列的每个正则括号子序列都是通过删除匹配对获得的。 

如果序列至少有两个基元块，则存在一个块结束而另一个块开始的边界。 删除后面块的外部匹配对会在比较中将左括号移到前面，从而创建子序列包含的第一个不同位置`'('`和原来包含`')'`。 生成的序列保持规则并且具有长度`n - 2`。 

子序列不再存在，因为任何正确的正则括号子序列必须删除至少一对匹配的，从而将长度减少至少两倍。 

当序列是单个基元块时，每个真正则括号子序列按字典顺序变得比原始序列小。 所需的第一不同位置永远不可能有`'('`在后续和`')'`在原作中。 因此不存在有效的子序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        bal = 0
        blocks = 0

        for ch in s:
            if ch == '(':
                bal += 1
            else:
                bal -= 1

            if bal == 0:
                blocks += 1

        if blocks == 1:
            ans.append("-1")
        else:
            ans.append(str(n - 2))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```实现直接遵循结构观察。 

变量`bal`存储当前的括号余额。 每当它返回到零时，我们就完成了一个原始块。 由于输入保证为 RBS，因此余额永远不会变为负数并最终为零。 

关键的实现细节是我们将每次返回都计数为零，而不仅仅是最后一次。 例如：```
(())()
```余额两次为零，因此有两个原始块。 缺少中间零会错误地对序列进行分类。 

一旦知道了块的数量，答案就立即出来了。 单个块给出`-1`，而多个块给出`n - 2`。
