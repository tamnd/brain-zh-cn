 ## 解决方案
 ## 问题理解

 我们从一片森林开始。 我们可以在其连接的组件之间添加边，直到整个图变成一棵树。 

对于每棵生成的树，运行标准 Prüfer 代码删除过程：重复删除编号最小的叶子，直到只剩下两个顶点。 这些顶点之一始终是顶点$n$。 另一个幸存的顶点称为 Prüfer 顶点$P(T)$。 

任务不是计算所有完成树。 相反，对于每一个$v<n$，我们必须计算有多少种连接森林的方式产生了普吕弗顶点等于的树$v$。 

所有测试用例的顶点总数最多为$2\cdot 10^5$。 任何执行与完成树数量成正比的工作的解决方案都是无望的，因为即使是空森林$n$顶点有$n^{n-2}$可能的树。 我们需要 Prüfer 顶点的结构特征，然后需要一个仅取决于组件大小和一些子树大小的计数公式。 

一个令人惊讶的危险边缘情况是$n$和$n-1$已经属于同一个连通分量。```
4 3
1 2
2 3
3 4
```森林已经是一棵树了。 恰好有一个完成。 答案集中在单个顶点上，即路径上的第二个顶点$4$到$3$。 任何假设的计数公式$n$和$n-1$最初断开连接将在此处失败。 

另一个微妙的情况是森林仅由孤立的顶点组成。```
3 0
```共有三个完成树。 答案并不对称。 顶点$2$大于顶点$1$，因此叶子移除顺序很重要。 任何仅基于未标记树的论证都会给出错误的分布。 

第三个陷阱是包含以下内容的组件：$n$。 该组件内部的顶点成为答案的可能性并不相同。 重要的是挂在孩子下面的有根子树的大小$n$，而不仅仅是组件尺寸。 

## 方法

 蛮力的想法很简单。 枚举将森林连接成树的各种方法，模拟普吕弗过程，并递增相应的答案。 

这是正确的，因为它直接遵循定义。 不幸的是，完成树的数量是$$n^{k-2}\prod s_i,$$在最坏的情况下是指数级的。 即使对于适度的值$n$，树木的数量是天文数字。 

关键的观察结果来自于对普吕弗流程本身的理解。 

考虑最后幸存的一对。 顶点$n$始终存在。 什么时候可以顶点$n-1$结束前消失？ 

一棵至少有两个顶点的树总是至少有两片叶子。 因此$n-1$如果靠近末端的唯一叶子是，则只能生存到末端$n-1$和$n$。 这意味着从$n$到$n-1$包含所有剩余的顶点。 该路径上的第二个顶点正是与$n$。 这完全体现了普吕弗顶点的特征。 

一旦知道了这个特征，问题就变成了连接组件的计数问题。 经典公式$$n^{k-2}\prod s_i$$计算连接组件的方式可以与组件内的每个顶点都是对称的事实相结合。 结果计数仅取决于组件大小，并且对于组件内的顶点$n$，关于有根子树的大小。

 ## 算法演练

 ### 1. 查找连通分量

 在林上运行 DFS 或 DSU。 

对于每个顶点，存储其组件 ID 和该组件的大小。 

将每个组件的最大编号顶点作为根。 特别地，该组件包含$n$扎根于$n$。 

### 2. 计算组件内的子树大小$n$在DFS期间，计算$$dp[v]=1+\sum dp[\text{child}].$$对于一个孩子$v$的$n$，这个值正好是下面悬挂的树枝的大小$v$。 

### 3. 处理以下情况$n$和$n-1$已经连接

 Prüfer 顶点随后永久固定。 

步行从$n-1$向上直到到达子项$n$躺在路上从$n$到$n-1$。 

称这个顶点为$x$。 

每个完成树都有$P(T)=x$， 所以$$ans[x] = \Big(\prod s_i\Big)\, n^{k-2}.$$所有其他答案都是零。 

### 4. 考虑候选顶点$v$认为$n$和$n-1$位于不同的组件中。 

有三种情况。 

#### 4.1$v$在于组成部分$n$然后$v$必须是直接子代$n$。 

在连接其余组件的所有方式中，包含的组件$n-1$必须最终在 的分支内$v$。 

因为 的组件的顶点$n$是对称的，落在该分支的概率是$$\frac{dp[v]}{|C_n|}.$$乘以完成树的总数即可得出答案。 

#### 4.2$v$在于组成部分$n-1$我们首先连接组件$n$和$n-1$。 

然后所需的分支大小变为$$|C_n|+|C_{n-1}|.$$代入计数公式即可得出贡献度。 

#### 4.3$v$位于任何其他组件中

 该组件必须首先附加到$n$。 

组件内的所有顶点都是对称的，因此只有组件的大小很重要。 

### 5. 预先计算模逆和幂

 所有公式都包含按组件大小划分。 由于模数是素数，因此使用模逆。 

还预先计算$$n^0,n^1,\dots,n^k.$$### 为什么它有效

 关键的属性是 Prüfer 顶点恰好是路径上的第二个顶点$n$到$n-1$。 一旦知道这一点，问题就不再依赖于详细的删除顺序。 

对于固定候选人$v$，我们只需要计算完成树，其中包含的组件$n-1$最终在 的分支内$v$当树的根位于$n$。 在经典的组件连接计数公式中，同一连接组件内的顶点是无法区分的，因此计数与相关分支的大​​小成正比。 该算法使用的每个公式恰好是完成树的总数乘以完成放置的分数$n-1$在那个分支。 因此，对于一个顶点，每个完成都会被计算一次$v$，所得答案是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())

    inv = [0] * 200001
    inv[1] = 1
    for i in range(2, 200001):
        inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

    for _ in range(t):
        n, m = map(int, input().split())

        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        comp = [-1] * (n + 1)
        parent = [0] * (n + 1)
        sub = [1] * (n + 1)
        sizes = []

        sys.setrecursionlimit(1 << 20)

        def dfs(v, p, cid):
            comp[v] = cid
            sizes[cid] += 1
            parent[v] = p

            for to in g[v]:
                if to == p:
                    continue
                dfs(to, v, cid)
                sub[v] += sub[to]

        cid = 0
        for v in range(n, 0, -1):
            if comp[v] == -1:
                sizes.append(0)
                dfs(v, 0, cid)
                cid += 1

        k = cid

        sz = [0] * (n + 1)
        for v in range(1, n + 1):
            sz[v] = sizes[comp[v]]

        p = 1
        for s in sizes:
            p = p * s % MOD

        pw = [1] * (k + 1)
        for i in range(1, k + 1):
            pw[i] = pw[i - 1] * n % MOD

        def npow(e):
            if e >= 0:
                return pw[e]
            return inv[n]

        ans = [0] * n

        if comp[n] == comp[n - 1]:
            v = n - 1
            while parent[v] != n:
                v = parent[v]

            ans[v] = p * npow(k - 2) % MOD
        else:
            comp_n = comp[n]
            comp_nm1 = comp[n - 1]

            for v in range(1, n):
                if comp[v] == comp_n:
                    if parent[v] != n:
                        continue

                    ans[v] = (
                        sub[v]
                        * p
                        % MOD
                        * inv[sz[n]]
                        % MOD
                        * npow(k - 2)
                    ) % MOD

                elif comp[v] == comp_nm1:
                    ans[v] = (
                        p
                        * inv[sz[n]]
                        % MOD
                        * inv[sz[n - 1]]
                        % MOD
                        * (sz[n] + sz[n - 1])
                        % MOD
                        * npow(k - 3)
                    ) % MOD

                else:
                    ans[v] = (
                        sz[v]
                        * p
                        % MOD
                        * inv[sz[n]]
                        % MOD
                        * inv[sz[v]]
                        % MOD
                        * npow(k - 3)
                    ) % MOD

        print(*ans[1:])

solve()
```DFS 同时计算组件 ID、组件大小、父指针和子树大小。 将每个组件的最大顶点作为根与计数证明中使用的参数相匹配。 该组件包含$n$自动植根于$n$，这使得每个相关分支的大​​小等于子树的大小。 

功能`npow`处理特殊指数$-1$。 出现这种情况时$k=1$或者$k=2$，并将编辑公式替换为$n^{-1}$通过模逆$n$。 

最常见的实现错误是忘记只有直接子代$n$可以是答案时$v$属于的组成部分$n$。 支票`parent[v] == n`是必不可少的。

 ## 边缘情况

 ###$n$和$n-1$已经连接

 输入：```
4 3
1 2
2 3
3 4
```路径从$4$到$3$从顶点开始$3$， 所以$P(T)=3$。 不可能添加边缘。 该算法检测到两个顶点属于同一组件，并直接输出一个非零答案。 

### 所有顶点被隔离

 输入：```
3 0
```共有三个完成树。 该算法仅使用组件大小，因此它自然会计算所有完成情况而不枚举它们。 

### 组件内的候选顶点$n$输入：```
6 3
1 6
6 4
2 1
```顶点$4$是的直接子代$6$，而顶点$1$其下方悬挂着一个更大的子树。 该算法使用子树大小，而不仅仅是组件大小，这正是区分它们的答案计数的原因。
