 ## 解决方案
 ## 问题理解

 我们得到两个整数，描述一群人玩简化的剪刀石头布设置的聚合信息。 我们不跟踪个人互动，只关心有多少人选择每只手：石头、剪刀和布。 让这些计数成为$R$,$S$， 和$P$。 它们的总和必须等于玩家总数$N$，并且它们还必须满足涉及剪刀和布的第二个线性约束：剪刀数量的两倍加上布玩家数量的五倍等于给定值$M$。 

任务不是构造一个实际的配置，而只是确定是否有任何非负整数三元组$(R, S, P)$存在满足两个方程。 此外，我们还需要确定是否存在游戏有获胜者的有效配置。 该语句将此条件编码为结构属性：当并非所有三种牌型同时出现时，获胜者就存在，这意味着最多有两种牌型$R, S, P$是积极的。 

尽管问题是用游戏的形式表达的，但其核心结构是在具有非负整数变量的线性约束小型系统上的纯粹算术可行性。 

这些约束意味着自由度方面的搜索空间非常小。 一次$S$和$P$被选择，$R$是被迫的，因此系统有效地减少了检查一维或二维晶格上的整数解，具体取决于我们如何消除变量。 这强烈表明，将两个变量强行强制达到$N$对于大型来说已经太慢了$N$，因为在最坏的情况下这将是二次的。 

主要的微妙之处在于可行性取决于整数一致性，而不仅仅是实值解决方案。 一个常见的错误是求解实数上的线性系统并假设可行性延续，但整除性约束可以消除大多数候选。 

当解决方案位于边界上时，就会出现边缘情况，其中一个或多个$R, S, P$变为零。 例如，如果$P = 0$，方程简化为$2S = M$，这可能是偶数，也可能不是偶数。 同样，如果$S = 0$，我们得到$5P = M$，强制被 5 整除。这些边界情况对于可行性和“获胜者存在”条件都很重要。 

## 方法

 暴力方法将枚举所有对$(S, P)$这样$2S + 5P = M$, 计算$R = N - S - P$，并检查所有变量是否都是非负的。 该方程本身已经显着限制了搜索空间：$P$范围可达$M/5$，对于每个选择我们计算$S = (M - 5P)/2$如果它是一个整数。 这已经是线性的$M$，这对于小的约束是可以接受的，但是当$M$很大，尤其是存在多个测试用例时。 

关键的观察结果是该系统并不是真正的二维系统。 第二个方程确定了之间的关系$S$和$P$，所以一次$P$被选择，$S$如果有效则唯一确定。 然后$R$是被迫的。 所以问题就变成了检查是否存在非负整数$P$从而满足整除性和范围约束。 

第二部分是关于胜利者是否存在的问题，结构上比较简单。 当三个条件不全时，就存在赢家$R, S, P$是积极的。 因此，一旦我们找到任何有效的解决方案，我们就会另外检查是否至少有一个变量为零。 如果存在所有均为正值的解决方案，则对应于完全混合状态，因此在给定条件下没有赢家。 如果所有有效的解决方案都必须强制为零，那么就有可能获胜。 

这减少了扫描小范围的问题$P$，计算对应的$S$，推导$R$，并检查约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 (S, P) | O(M)| O(1) | O(1) | 对于大M来说太慢|
 | 仅迭代 P | 最坏情况 O(M)，有效 O(M/5) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 迭代所有可能的值$P$从 0 到$\lfloor M/5 \rfloor$。 这已经足够了，因为每篇论文为第二个方程贡献了 5 个单位，任何更大的值都会立即超过$M$。 
2. 对于每个$P$，计算剪刀的剩余贡献为$M - 5P$。 该数量必须是偶数，否则不是整数$S$存在。 
3. 如果是偶数，则计算$S = (M - 5P)/2$。 此步骤强制执行第二个方程的精确满足，无需浮点运算，从而避免了精度问题。 
4. 计算$R = N - S - P$。 这直接来自总人口限制。 
5. 检查是否$R, S, P$都是非负的。 如果有任何结果为负，则丢弃该候选者，因为它违反了计数解释的可行性。 
6. 如果找到有效的三元组，记录可行性。 另外跟踪是否存在至少一个有效的三元组，其中至少一个变量等于零，因为这决定了是否存在获胜者配置。 

为什么它起作用是基于第二个方程定义了整数点的一维格子$(S, P)$飞机。 每个有效的解决方案都必须位于这个格子上，并且每个候选方案都完全通过选择来确定$P$。 然后，第一个方程充当过滤器，仅选择那些正确投影到的格点$N$。 因为这两个约束都是线性的，并且我们在每一步都强制执行完整性，所以不会跳过任何有效的解决方案，也不接受无效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())

    possible = False
    has_winner = False

    for P in range(M // 5 + 1):
        rem = M - 5 * P
        if rem < 0:
            break
        if rem % 2 != 0:
            continue

        S = rem // 2
        R = N - S - P

        if R < 0:
            continue

        possible = True
        if R == 0 or S == 0 or P == 0:
            has_winner = True

    if not possible:
        print("NO")
    else:
        print("YES" if has_winner else "NO")

if __name__ == "__main__":
    solve()
```代码后面直接枚举过来$P$。 奇偶校验确保$S$保持整数，避免无效的半值。 一次$S$推导出来，$R$是由第一个方程强制的。 

一个微妙的实现细节是早期中断$M - 5P < 0$，这在技术上是不必要的，但可以防止病理输入中的额外迭代。 另一个重要的细节是计算后检查非负性$R$，因为即使满足第二个方程，第一个约束仍然会使候选无效。 

获胜者的条件在枚举期间被跟踪，因为它仅取决于是否有任何有效的解决方案将至少一个变量置于零。

 ## 边缘情况

 一种边缘情况是当$M$很奇怪。 在这种情况下，每个候选人$P$产生奇数余数$M - 5P$每当$5P$偶数或奇数不一致，但实际上奇偶校验立即消除了所有候选者$S$不会是整数。 例如，$N = 10, M = 3$没有产生有效的解决方案，因为$2S = 3 - 5P$对于任何整数都不能为偶数$P$。 

另一个边缘情况是当$P = 0$，这将系统减少到$2S = M$和$R = N - S$。 例如，$N = 7, M = 4$给出$S = 2, R = 5$，一种有效的解决方案，其中一个变量为零，保证获胜者配置。 

第三种边缘情况是所有变量都严格为正，但仍然满足两个方程。 例如，$N = 8, M = 13$产生$(R, S, P) = (3, 4, 1)$。 该算法正确地标记了可行性，但没有标记获胜者，因为在唯一有效的解决方案空间中没有变量为零。
