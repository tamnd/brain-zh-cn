 ## 解决方案
 ## 问题理解

 我们正在对一系列独立试验进行建模，其中每个试验要么成功，要么以已知的概率失败。 任务不是模拟该过程，而是计算随时间变化的概率：具体来说，一个非常特殊的模式第一次恰好出现在该位置的概率$X$。 

该图案具有固定在位置周围的刚性结构$X$。 向后看从$X$，我们需要一个块$K$连续成功结束于$X$，紧接在位置失败之前$X-K$，并且在此之前该模式不得已在序列中较早出现。 

因此，输入表示每次试验的成功概率列表，以及描述模式长度的参数$K$和目标位置$X$。 输出是单个概率值：此“失败然后 K 成功”模式的第一次有效出现恰好在位置结束的概率$X$。 

没有明确说明约束条件，但有关于使用累积乘积的提示$O(1)$每个查询意味着试验次数可能很大，通常最多可达$10^5$或更多。 这立即排除了对所有子阵列的任何二次推理或对每个子阵列的重复扫描$X$。 任何有效的解决方案都必须对信息进行预处理，以便可以在恒定时间内查询分段概率。 

当天真的方法忽略“第一次”条件时，就会出现微妙的失败案例。 例如，假设$K = 2$我们取得了一系列成功，例如：

 输入概率：```
0.5 0.5 0.5 0.5
```如果我们只检查位置是否$X-2, X-1, X$本地匹配模式，我们可能会错误地计算该模式之前已经出现的配置，例如在位置$2$到$4$，即使第一次出现的位置是$3$到$5$在一个较长的序列中。 正确的解决方案必须强制执行前缀条件，确保不存在较早的有效窗口。 

另一个常见的错误是在边界处理时出现的$X-K-1 \le 0$。 在这种情况下，条件“之前不满足”$X-K-1$” 变得空洞，幼稚的实现常常错误地乘以不应该存在的前缀术语。

 ## 方法

 暴力方法将显式枚举整个序列中所有可能的成功和失败配置，并检查第一个有效发生是否结束于$X$。 这很快就会呈指数增长$N$，因为每个试验都会分为两个结果。 即使我们试图限制自己只检查以$X$，我们仍然需要验证没有较早的窗口满足相同的结构，这在最坏的情况下需要扫描每个候选端点的所有较早的位置。 这导致$O(N^2)$行为。 

关键的观察结果是，条件仅取决于三个独立的段：前缀高达$X-K-1$，单一故障$X-K$，以及块$K$连续成功从$X-K+1$到$X$。 这些在模型下是独立的，因此它们的概率成倍增加。 唯一的复杂之处是强制该模式不会更早出现，但可以通过维持“直到 i 为止不出现”的运行概率来处理该条件。 

一旦我们认识到该结构简化为前缀概率和固定长度窗口概率，我们就可以预先计算成功和失败概率的前缀乘积。 然后可以在恒定时间内评估每个候选端点，并且我们可以构建一个 DP 样式的前缀数组来跟踪该模式是否曾经出现在给定索引之前。

 | ---| ---| ---| ---|
 | 蛮力 |$O(N^2)$或指数|$O(1)$| 太慢了|
 | 最佳|$O(N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们假设一系列成功概率$p[i]$，失败概率$q[i] = 1 - p[i]$。 我们还假设我们需要连续段的概率，因此我们依赖于前缀乘积。 

1. 以允许快速范围乘法的方式预先计算成功概率和组合段概率的前缀乘积。 这允许任何段$[l, r]$在恒定时间内计算的独立试验次数作为前缀值比率的乘积。 
2. 维护数组`pref_ok[i]`表示该模式未出现在以 结尾的前缀中的任何位置的概率$i$。 这是必要的，因为该事件是“第一次发生”。 
3. 对于每个位置$i$，将其视为潜在终点$X$。 计算位置的概率$i-K+1$到$i$都是使用前缀产品结构的成功。 
4. 乘以该位置的概率$i-K$是一个失败。 
5. 乘以`pref_ok[i-K-1]`，这强制不存在较早的有效事件。 
6.将此贡献添加到答案并更新`pref_ok[i]`通过减去新事件结束的概率$i$，确保它仍然是“到目前为止没有发生”的概率。 
7. 继续此过程直至$N$，仅在有效端点累积贡献$i \ge K+1$。 

关键的设计选择是我们从不明确搜索更早的事件。 相反，我们将该约束折叠到前缀 DP 状态中，以便增量地维持“第一次出现”条件。 

### 为什么它有效

 在每个索引处$i$，定义有效首次出现的所有事件仅依赖于不相交的段：之前的前缀$i-K-1$，单一故障$i-K$，以及长度的后缀窗口$K$。 这些部分涉及独立试验，因此概率成倍增加。 DP状态`pref_ok[i]`保持不变式，即它等于没有有效模式在 或之前结束的概率$i$。 由于每个新出现的情况仅在其端点处引入，并立即从未来的前缀中排除，因此不会对任何配置进行重复计算，并且每个有效的首次出现都只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, x = map(int, input().split())
    p = list(map(float, input().split()))

    # prefix product of success probabilities
    pref = [1.0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] * p[i - 1]

    def range_prod(l, r):
        if l > r:
            return 1.0
        return pref[r] / pref[l - 1]

    # dp[i]: probability no pattern ends at or before i
    dp = [1.0] * (n + 1)
    ans = 0.0

    for i in range(1, n + 1):
        dp[i] = dp[i - 1]

        if i >= k + 1:
            l = i - k + 1
            r = i

            success_block = range_prod(l, r)
            failure = 1.0 - p[i - k - 1]

            contrib = dp[i - k - 1] * failure * success_block
            ans += contrib

            dp[i] -= contrib

    print(ans)

if __name__ == "__main__":
    solve()
```前缀产品数组`pref`允许在恒定时间内计算任何连续的成功块。 帮手`range_prod`干净地处理空或无效范围，这在以下情况下至关重要$k = 0$或者当索引在数组开头附近对齐时。 

数组`dp`不是经典的 DP 状态转换，而是一个运行概率质量，用于跟踪早期模式完成已经“消耗”了多少概率质量。 减法`contrib`确保一旦配置被计为在位置结束`i`，它不能对后面的位置做出贡献，从而保留“第一次出现”约束。 

索引时需要仔细注意：故障位置是`i - k - 1`，只有当`i >= k + 1`。 这个边界是差一错误的最常见来源。 

## 工作示例

 考虑一个小案例$n = 4$,$k = 1$，和概率：```
p = [0.5, 0.5, 0.5, 0.5]
```我们计算每个端点的贡献。 

| 我| 失效指数（i-k）| 成功块 | dp[i-k-1] | dp[i-k-1] | 贡献 |
 | ---| ---| ---| ---| ---|
 | 2 | 1 | p[2] | p[2] | dp[0]=1 | dp[0]=1 | 0.5 * 0.5 * 1 = 0.25 |
 | 3 | 2 | p[3] | p[3] | dp[1] | dp[1] | 0.5 * 0.5 * dp[1] | 0.5 * 0.5 * dp[1] |
 | 4 | 3 | p[4] | p[4] | dp[2] | dp[2] | 0.5 * 0.5 * dp[2] | 0.5 * 0.5 * dp[2] |

 该表显示每个端点如何依赖于早期的前缀状态。 这`dp`随着早期事件的积累，术语会减少贡献，从而强制执行“第一次”约束。 

该跟踪表明该算法从不重新计算过去的段，而仅使用累积的前缀概率。

 ## 边缘情况

 一种重要的边缘情况是故障位置索引变为零或负值。 认为$k = 2$和$i = 2$。 然后$i-k-1 = -1$，这是无效的。 该算法通过仅在以下情况下才开始贡献来明确避免这种情况：$i \ge k+1$，确保每个引用的前缀状态都存在。 对于这样的输入，不执行任何计算，并且答案保持为零，这是正确的，因为没有先前的失败就不可能存在有效的模式。 

当所有概率均为 1 时，会出现另一种边缘情况。在这种情况下，故障条件的概率到处都为零，因此无法形成有效的模式。 该算法正确地乘以`(1 - p[i-k-1])`，它变为零并消除所有贡献。 

第三种情况是当$k = 0$，其中“成功块”为空。 范围乘积函数对于空间隔返回 1，因此该事件减少为“在位置 i-1 处失败且之前没有发生过”，这仍然可以由前缀 DP 结构正确处理而无需修改。
