 ## 解决方案
 ## 问题理解

 给定一个由大写字母组成的字符串，我们感兴趣的是提取“U 后面是 P 后面是 C”形式的加权结构，甚至更晚还会出现一个附加的 C。 每次我们成功选取四个指数$i < j < k < l$形成有效的配置，我们获得的值等于它们位置的乘积$i \cdot j \cdot k \cdot l$。 每个索引最多可以在所有选定的四元组中使用一次。 

任务是在遵守排序约束的所有可能的不相交四元组上最大化这些乘积的总和。 

这些约束足够大，以至于任何涉及检查所有四元组或对所有子序列进行动态规划的方法都立即不可行。 天真地列举了所有$O(n^4)$即使进行修剪，四倍体也将远远超出以下情况下的可能性：$n$达到典型的 Codeforces 限制，例如$10^5$。 甚至$O(n^2)$如果没有仔细的结构来实现交互将会太慢，因为每个元素都参与多个潜在的配对。 

当尝试按从左到右的顺序匹配字符时，就会出现贪婪推理的一种微妙的失败情况。 例如，贪婪地将最早可能的 U 与最早可能的 P 配对可能会阻止稍后的配置，该配置由于较大的索引而产生更大的乘积。 考虑一个像这样的字符串

 UP CUP C C C

 简单的前向匹配可能会尽早配对小索引，并以次优的方式留下大索引。 关键的困难在于，其价值乘法取决于仓位，因此后来的指数的价值要高得多。 

## 方法

 蛮力观点是考虑选择不相交四元组的所有方法$(i, j, k, l)$这样$S_i = U$,$S_j = P$,$S_k = C$,$S_l = C$随着指数的增加。 对于每个有效的选择，我们计算乘积并求和。 这立即导致指数或至少组合爆炸，因为我们选择多个不相交的递增链。 

蛮力的失败点不仅仅是选择的数量，而是选择之间的依赖关系。 选择一个四元组会删除稍后可能成为更好四元组一部分的索引，因此我们需要一种全局排序原则。 

关键的见解是，每个索引中的值函数都是单调的并且是乘法的，这允许重新排列参数。 如果我们进行任意两个操作并以坐标排序方式交换它们选择的索引，则总值不会减少。 这是一个经典的交换论证，表明可以假设最佳解决方案具有结构：所选索引以单调方式对齐，这意味着我们可以安全地选择首先采用最大的可用有效索引。 

这将问题从全局组合问题转变为贪婪构造问题。 我们不是搜索所有有效的四元组，而是从右到左处理，并始终尝试完成最右边的可能链。 每次我们看到一个字符时，我们都会尝试尽可能地扩展部分形成的链，始终消耗最大的可用索引。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从右到左处理字符串，维护代表“C ← P ← U ← C”构造到目前为止已经完成了多少阶段的部分链。 

1. 我们扫描索引$n$下降到$1$，将后面的位置视为更有价值，因为它们贡献更大的乘数因子。 这种排序与交换论点一致，即最优结构可以在指数中变得单调。 
2. 我们维护三个与部分构造相对应的队列。 一种存储可用的 C 位置，一种存储完整的“PC”值，一种存储完整的“UPC”值。 每个队列元素代表我们仍然可以扩展的最佳部分链。 
3.当我们遇到C时，如果可能的话，我们会尝试立即完成完整的链条。 如果存在完整的 UPC 链，我们将选择最好的一条，乘以当前索引，然后将其添加到答案中。 如果没有，我们将这个 C 存储为未来 P 匹配的潜在起点。 
4.当我们遇到P时，我们尝试将现有的C扩展到PC链中。 如果有可用的 C，我们将其与当前索引配对，相乘形成 PC 值，并将其存储以供以后扩展。 
5.当我们遇到U时，我们尝试将现有的PC链扩展为UPC链。 如果有可用的 PC，我们会将其相乘并存储为 UPC。 

每个步骤都会贪婪地使用最近可用的组件，这些组件对应于由于从右到左处理而产生的最大索引。 

每个操作都是局部最优的原因是任何早期的选择只会减少未来扩展的乘数效应。 通过始终使用最佳可用的部分链，我们确保当存在较大的延续时，不会在较小的延续上浪费大索引。 

### 为什么它有效

 交换参数保证在所有最优解决方案中，存在一个在早期步骤中使用的索引永远不会小于稍后在同一角色中使用的索引。 这使我们能够强制执行单调结构：每个部分链都是从右到左构建的，而不会损失最优性。 队列通过始终将当前索引与最佳可用延续配对来模拟这种结构，从而在每个阶段保留最大可能的贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    c = []
    pc = []
    upc = []

    ans = 0

    for i in range(n, 0, -1):
        ch = s[i - 1]

        if ch == 'C':
            if upc:
                val = upc.pop()
                ans += val * i
            else:
                c.append(i)

        elif ch == 'P':
            if c:
                j = c.pop()
                pc.append(j * i)

        elif ch == 'U':
            if pc:
                val = pc.pop()
                upc.append(val * i)

    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循从右到左的扫描。 每个列表充当堆栈而不是严格的队列，这已经足够了，因为由于处理顺序相反，我们总是希望首先使用最近添加的（最大索引）元素。 关键的微妙之处在于，当扩展部分结构时，乘法会立即发生，从而保留累积的乘积，而无需存储完整的元组。 

一个常见的错误是尝试匹配给定字符的所有可能的早期状态。 这是不必要的，也是有害的，因为它破坏了交换论证所保证的单调结构。 贪婪堆栈行为确保每个索引仅使用一次，并且始终在最有价值的可用扩展中使用。

 ## 边缘情况

 一种边缘情况是所有有用的字符都聚集在字符串的末尾。 例如，在“UUUPPPCCC”中，算法从右向左处理并确保始终首先使用最大的索引。 天真的从左到右的贪婪者会错误地过早消耗小指数，从而阻止更高价值链的形成。 

另一种边缘情况是同一阶段有多个部分链可用。 基于堆栈的方法通过始终扩展最近形成的部分链自然地解决了这个问题，这对应于由于反向扫描而产生的最大可用贡献。
