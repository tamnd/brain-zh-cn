 ## 解决方案
 ## 问题理解

 我们得到一个字符串序列和目标长度$M$。 我们通过完整获取第一个字符串来开始构建一个新字符串，然后对于每个下一个字符串，我们可以附加它的任何前缀，可能是空的。 处理完所有字符串后，我们丢弃除最后一个之外的所有内容$M$最终连接的字符，以及最终的长度-$M$字符串才是最重要的。 

关键的困难在于，最后的切割使得结构的早期部分变得无关紧要，除了它们如何影响最后的部分$M$人物。 这会产生一种依赖关系，其中关于从每个字符串中获取多少内容的决策必须进行全局优化，而不是本地优化。 

输入约束意味着如果总长度很大，我们无法显式模拟完整的串联。 在总长度可达的典型限制下，任何构建整个字符串然后进行切片的方法都会立即失败$10^5$或更多，因为内存和时间都会随着构造大小线性增长，并且子串的比较在实践中会变成二次方。 

当贪婪地独立思考每根弦时，就会出现一个微妙的陷阱。 例如，尽早选择字典顺序较小的前缀可能会阻止稍后的字符串访问更好的后缀贡献，因为只有最后一个$M$角色得以生存。 类似地，如果不正确统一，将第一个字符串的后缀选择与后面的子字符串贡献分开处理会导致重复计算或丢失候选者。 

当一个字符串既是后缀贡献者的候选者，又影响后面字符串的前缀 DP 时，就会出现另一个重要的失败情况。 一个简单的解决方案可能会独立考虑所有子字符串，但其中许多子字符串都由单个最佳代表性后缀主导。 

## 方法

 蛮力方法是明确考虑从每个字符串中选择前缀的所有可能方法，构建完整的串联，然后采用最后一个$M$人物。 这是正确的，因为它直接符合构造规则。 然而，方式的数量呈指数增长，因为每个字符串都贡献一定范围的前缀长度，并且即使有界，枚举所有组合也会导致粗略的结果$O(\prod |S_i|)$可能性，这是不可行的。 

更结构化的暴力通过固定每个字符串的候选剪切位置并计算结果后缀来改善这一点，但即便如此，提取并比较结果长度 -$M$字符串需要$O(M)$每个候选人的工作量，仍然有$O(NM)$或者$O(NM^2)$状态取决于如何处理前缀长度。 这导致朴素 DP 公式中出现立方行为。 

关键的观察是我们实际上从来不需要完整的中间字符串。 我们只关心字典顺序上最小的可实现的固定长度后缀$M$。 这允许我们定义一个仅传播最佳长度的 DP——$M$从后缀到前缀的字符串。 

第二个重要的结构见解是，对于前缀串联，较短的最优结构始终是较长最优结构的前缀。 这种单调性将潜在的二维 DP 压缩为每个索引的单个状态。 

最后，对于子字符串选择，所有子字符串都可以简化为每个字符串的单个最佳后缀候选。 任何不是后缀的子字符串要么由较长的后缀主导，要么由字典顺序较小的竞争后缀主导，因此无需显式考虑所有子字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 前缀选择的完整枚举 | 指数| O(1) | O(1) | 太慢了|
 | 所有前缀长度和子串上的朴素 DP | O(NM^3) | O(NM^3) | O(NM) | 太慢了|
 | 通过后缀减少和 LCP 优化 DP | O(NM) | O(N) | 已接受 |

 ## 算法演练

 我们从右到左处理字符串，保持最佳的字符串长度$M$可以由从位置开始的后缀组成$i$。 

1. 定义$dp[i]$作为长度按字典顺序最小的字符串$M$可以使用字符串获得$S_i, S_{i+1}, \dots, S_N$，其中每个字符串贡献一个前缀。 

这将所有下游决策压缩为单个目标对象。 
2. 初始化$dp[N]$作为最佳长度-$M$的前缀$S_N$，这就是简单的$S_N[0:M]$如果足够长，否则所有$S_N$。 
3. 对于每个$i$从$N-1$下降到$1$，计算仅根据前缀构建的候选：

 我们尝试将最终答案分开$S_i$和$dp[i+1]$。 对于每个分割位置$j$，我们形成$S_i[0:j] + dp[i+1][0:M-j]$。 

这涵盖了所有基于前缀的结构的原因是，$S_i$最终的字符串完全取决于我们在移动到后面的字符串之前从中取出的字符数。 
4. 避免检查所有$j$天真地，我们有效地比较两个分裂选择。 比较分割$s < t$减少到比较$T[0:M-s)$和$S[s:t] + T[0:M-t)$， 在哪里$T = dp[i+1]$。 

此比较简化为后缀之间的 LCP 查询$S_i$和$dp[i+1]$，我们使用 Z 算法对以下形式的串联进行计算$dp[i+1] + \# + S_i$。 
5. 接下来，我们处理索引的子串贡献$i \ge 2$。 而不是考虑所有子串$S_i$，我们观察到只有字典顺序最小的后缀$S_i$很重要。 设这个后缀为$Z$。 

任何不是这个后缀的子字符串要么在字典顺序上更大，要么在随着未来的贡献扩展时由它主导。 因此，我们只考虑以下形式的字符串$Z[0:k] + dp[i+1][0:M-k]$。 
6. 对于$S_1$，后缀处理略有不同，因为它显示为第一次剪切之前的初始段。 我们找到长度按字典顺序最小的子串$M$在$S_1 + dp[2]$，这再次减少了对组合结构的后缀扫描。 
7. 维护$dp[i]$作为前缀分割和后缀派生结构的最佳候选者，并继续向后直到$i=1$。 

### 为什么它有效

 在每个索引处$i$，DP状态代表从后缀可实现的后缀结果的完整集合$i$。 任何有效的构造都可以分解为关于多少的第一个决定$S_i$为决赛做出贡献$M$-length 窗口，然后是最佳完成$i+1$。 字典序比较的单调结构确保在所有分解中，只有边界对齐的分裂才是重要的，因为任何内部变化都会扩展或截断已经在字典序中占主导地位的前缀。 后缀缩减参数保证所有非极端子串都由规范后缀主导，从而防止丢失最佳候选。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    return z

def lex_min_suffix(s):
    best = 0
    for i in range(1, len(s)):
        a, b = i, best
        while a < len(s) and b < len(s) and s[a] == s[b]:
            a += 1
            b += 1
        if a < len(s) and (b == len(s) or s[a] < s[b]):
            best = i
    return s[best:]

def best_prefix_combine(S, T, M):
    n, m = len(S), len(T)
    best = None

    def take(j):
        return S[:j] + T[:M-j]

    for j in range(min(n, M) + 1):
        cand = take(j)
        if best is None or cand < best:
            best = cand
    return best

def solve():
    N, M = map(int, input().split())
    S = [input().strip() for _ in range(N)]

    dp = [""] * N

    dp[N-1] = S[N-1][:M]

    for i in range(N-2, -1, -1):
        best = None

        for j in range(min(len(S[i]), M) + 1):
            cand = S[i][:j] + dp[i+1][:M-j]
            if best is None or cand < best:
                best = cand

        if i >= 1:
            Z = lex_min_suffix(S[i])
            for j in range(min(len(Z), M) + 1):
                cand = Z[:j] + dp[i+1][:M-j]
                if best is None or cand < best:
                    best = cand

        dp[i] = best

    # suffix of S1 + dp[1]
    ans = None
    A = S[0] + dp[1]
    for i in range(len(A) - M + 1):
        cand = A[i:i+M]
        if ans is None or cand < ans:
            ans = cand

    print(ans)

if __name__ == "__main__":
    solve()
```该代码反映了上述 DP 结构。 主循环构建$dp[i]$从$dp[i+1]$通过枚举取前缀之间的分割点$S_i$并来自后缀 DP。 字典顺序上最小的后缀计算是通过直接扫描实现的，即使存在更快的实现，这也足以使概念清晰。 

最后一步通过扫描所有长度来处理第一个字符串的特殊角色 -$M$之间合并边界的子串$S_1$和$dp[2]$。 

一个微妙的点是长度的一致截断$M$在每个候选构建中。 忽略这一点会导致不正确的词典比较，因为即使前缀更差，较长的字符串也会错误地占主导地位。

 考虑一个具有三个字符串的小实例，其中多个分割竞争。

| 我| S[i] | dp[i+1] | dp[i+1] 候选分割结果 |
 | ---| ---| ---| ---|

 | 2 | “巴”| “c”| “bc”，“bac”，“c...”最好=“bc”|

 此跟踪显示了早期选择如何受到下游最优字符串的约束，以及 DP 如何确保针对固定后缀状态评估本地分割决策。 

第二个例子强调了子串的优势。 

| 我| S[i] | Z（最佳后缀）| dp[i+1] | dp[i+1] 最好的|
 | ---| ---| ---| ---| ---|

 这表明只有字典顺序最小的后缀才有意义； 其他子串永远不会被选择。

 ## 边缘情况

 一个关键的边缘情况是，第一个字符串本身已经包含一个子字符串，该子字符串击败了后面字符串的任何组合。 在这种情况下，算法的最终扫描步骤将结束$S_1 + dp[2]$确保不会丢失第一个字符串的纯内部子字符串。 

另一种情况发生在字符串比剩余所需长度短时，迫使 DP 完全消耗它。 split 枚举自然地处理这个问题，因为循环$j$上限为字符串长度，使得所有剩余字符都来自$dp[i+1]$。 

当两个分割策略针对长前缀长度产生相同的前缀但随后出现分歧时，就会出现第三种情况。 基于 LCP 的比较可确保长前缀上的相等性不会错误地使决策产生偏差，因为分歧在第一个不匹配字符处得到了准确解决。
