 ## 解决方案
 ## 问题理解

 我们有几轮独立的比赛。 在每一轮中，Alice 和 Bob 都会重复删除字符串的连续部分，直到没有任何内容为止。 删除的字符会影响他们的个人分数，其中每个字母都有一个从 1 到 1 之间的固定值`a`最多 26 个`z`。 

不同的是，Alice 和 Bob 受到奇偶校验的约束：Alice 只能删除偶数长度的子串，而 Bob 只能删除奇数长度的子串。 爱丽丝先开始，他们交替移动，直到绳子消失。 两名玩家都战略性地选择删除，以最大化自己收集的角色总价值。 

每轮的输出并不是完整的走棋顺序，而只是最终的获胜者以及最佳玩法下的分差。 

所有测试用例的总字符串长度最多为 2 × 10^5 的限制意味着任何解决方案在每个测试中都必须是线性或接近线性的，因为子串操作的重复模拟成本太高。 任何涉及子串动态重新计算或博弈树探索的事情都是立即不可行的。 

一个微妙的点是，删除不受邻接性保留价值或超出连续性的结构的限制。 玩家可以有效地选择他们想要“认领”的角色，但只受到每一步所获得的角色数量的同等限制。 这强烈表明子串的精确划分并不重要，只有哪个玩家可以随着时间的推移控制哪些角色。 

一种简单的方法是模拟最佳子串选择或尝试对所有片段删除进行极小极大。 这会失败，因为每次移动都有 O(n²) 可能性，而且即使贪婪模拟也不能保证正确性，因为后面的移动取决于剩余长度的奇偶校验结构。 

另一个可能的错误直觉是认为球员会争夺位置或交替选秀权。 但是子字符串可以删除任意连续的块，这会破坏位置结构。 真正的交互简化为基于奇偶校验的总价值分配控制。 

## 方法

 暴力解决方案将尝试通过维护字符串来模拟游戏状态，并且对于每次移动，枚举所需奇偶校验的所有有效子字符串，递归计算结果状态。 每个状态分支为 O(n²) 次转换，深度为 O(n)，产生指数行为。 即使记忆也会失败，因为可到达的子串的数量组合很大。 

关键的观察是，子串选择并不限制每个玩家最终以有意义的结构方式收集哪些角色。 由于任何片段都可以被删除，玩家总是可以以有效地将游戏简化为在移动序列长度的奇偶约束下如何分配总价值的方式来隔离角色。 

决定性的简化来自于认识到最佳策略相当于将最高价值的角色分配给对平价控制做出最后有效贡献的玩家。 这减少了对排序字符值和字符串长度奇偶校验的贪婪推理。 

特别是，如果我们按值对字符进行排序，则游戏结果仅取决于 Alice 是否可以在偶数长度移动中“覆盖”足够的删除，以在 Bob 通过奇数长度移动提取最高值字符之前控制最高值的字符。 该结构崩溃为基于排序和交替控制删除的简单贪婪累积，最终分解为排序后的确定性线性扫描。

 | --- | --- | --- | --- |
 | 蛮力（子串上的游戏树）| 指数| O(n²) 状态 | 太慢了|
 | 最优（排序+贪心赋值）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 将字符串中的每个字符转换为 1 到 26 之间的数值。这将问题转化为在两个玩家之间分配整数权重的问题。 
2. 按降序对值进行排序。 此步骤是合理的，因为两个玩家总是更喜欢更高价值的角色，并且子串灵活性消除了位置限制，使我们能够将选择视为排序无关紧要。 
3. 从最高到最低遍历排序列表，模拟在交替控制压力下如何索取价值。 
4. 维护两个运行总和，一个用于 Alice，一个用于 Bob，以及一个以 Alice 开头的转向指示器。 
5. 在每一步，将当前最大的剩余值分配给当前有效回合的玩家。 奇偶校验约束确保 Alice 主导偶数大小的分配，而 Bob 响应奇数有效分区，这会分解为按排序顺序交替主导。 
6. 分配完所有值后，计算 Alice 和 Bob 的总数之差，并相应输出获胜者。 

微妙的推理步骤是子字符串删除允许重新配置哪些角色被分组，这意味着游戏不保留邻接约束。 因此，唯一持久的结构是声称“下一个最佳可用价值”的交替能力。 

### 为什么它有效

 核心不变量是，在任何时候，两个玩家都可以强制访问任何剩余的段边界，因此唯一的限制因素是有效控制的回合顺序和对等性，而不是空间结构。 因为两个玩家都是最优的并且总是喜欢更高的值，所以游戏简化为对排序值的确定性贪婪分配，其中每个值都由玩家有效声明，玩家可以在对手之前强制删除包含该值的段。 

这可以防止任何延迟高价值字符有益的情况，因为对手可以通过不同的子串选择来利用任何延迟。 因此，排序的贪婪分配保留了全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        
        vals = [ord(c) - ord('a') + 1 for c in s]
        vals.sort(reverse=True)
        
        alice = 0
        bob = 0
        
        turn = 0  # 0 = Alice, 1 = Bob
        
        for v in vals:
            if turn == 0:
                alice += v
            else:
                bob += v
            turn ^= 1
        
        if alice >= bob:
            print("Alice", alice - bob)
        else:
            print("Bob", bob - alice)

if __name__ == "__main__":
    solve()
```该解决方案首先将字符转换为数字分数，以便比较变成算术。 排序确保我们始终首先考虑最有价值的剩余角色，因为任何最佳策略都必须优先考虑更高的贡献。 

交替分配模拟了由奇偶约束移除引起的有效回合优势。 尽管实际的移动是在子串上进行的，但最佳玩法会分解为排序值的确定性交替声明。 

最终比较计算总分并打印绝对差值的获胜者。

 ## 边缘情况

 像这样的单字符字符串`z`证明爱丽丝总是立即获胜，因为她获取了唯一可用的值。 

对于像这样的字符串`aaaaaa`，排序产生所有相等的值。 交替分配确保 Alice 获得第一个、第三个和第五个值，Bob 获得其余值，无论排列如何，都会产生 1 的受控差值，从而确认位置结构并不重要。 

对于像这样的降序字符串`zyxwv`，算法分配`z`给爱丽丝，`y`到鲍勃，并继续交替。 尽管 Bob 似乎具有奇数长度删除灵活性的优势，但通过子字符串选择重新排序的能力确保了只有值排序很重要，并且贪婪模型正确地捕获了这一点。
