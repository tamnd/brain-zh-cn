 ## 解决方案
 ## 问题理解

 我们在数轴上给出了几个区间。 每个间隔代表覆盖点的连续段。 如果多个间隔重叠或接触，则当我们进行并集时，它们组合的覆盖区域会合并为一个连续的部分。 

任务不是直接计算整个集合的并集，而是精确删除一个区间，然后计算剩余区间的并集中剩余多少个不相交的连续段。 我们希望选择移除的区间，使得连接分量的数量尽可能大。 

因此，问题在于了解每个间隔如何有助于合并先前单独的覆盖区域。 删除一个间隔可能会将一个合并区域分割成多个部分，但如果该间隔是多余的，它也不会执行任何操作。 

限制很严格：所有测试用例总共最多有 200,000 个间隔。 这立即排除了任何为每次删除重新计算完整联合的解决方案。 删除每个间隔后重新计算合并的简单方法将需要对 n 个删除中的每一个进行排序和扫描，导致每个测试用例大约为 O(n^2 log n)，这太慢了。 

一个微妙的方面是，间隔可以是完全多余的，也可以是完全关键的。 例如，如果一个间隔完全被其他间隔覆盖，则删除它不会改变任何情况。 相反，作为两个部分之间唯一桥梁的间隔至关重要。 

打破天真的思维的边缘情况包括这样的情况：所有间隔都相同，删除任何一个都不起作用，或者每个间隔仅轻微重叠的链，因此删除单个间隔会将长连接组件分成两部分。 一个小例子：

 输入：```
3
1 3
3 5
5 7
```这里所有的区间形成一条链，产生一个连通分量。 删除中间间隔将链分成两个部分，将答案从 1 增加到 2。每个索引的天真“计数删除后合并的组件”仍然太慢，而且天真的贪婪想法（例如删除最小或最大间隔）也会失败，因为结构取决于重叠连接性，而不是长度。 

## 方法

 蛮力策略很简单：对于每个间隔，将其删除，重建剩余间隔的并集，并计算存在多少个不相交的合并段。 构建并集需要按左端点对间隔进行排序并扫描一次，合并重叠。 每个测试用例的成本为 O(n log n)。 执行 n 次会导致 O(n^2 log n)，这在 2e5 总间隔中是完全不可行的。 

关键的观察结果是，联合结构仅取决于按端点排序时间隔如何重叠。 当间隔按左端点排序时，只要间隔重叠或触及当前活动的右边界，就会通过贪婪地扩展当前段来形成并集。 每次扩展失败时，都会启动一个新组件。 

现在我们问当我们删除一个间隔时会发生什么。 仅当该间隔负责扩展合并的组件或连接两个部分时，删除该间隔才有意义。 在按左端点排序的扫描中，有时当前活动覆盖范围由活动间隔中的最大右端点确定。 唯一重要的间隔是那些在扫描中的某个时刻成为“最大右端点贡献者”的间隔。 

这导致了一个经典的转换：我们不是为每个删除重新计算并集，而是为每个间隔计算它需要多少个“并集段”。 如果删除它会导致合并或拆分，则可以使用它唯一确定活动最大覆盖范围的次数来表达该效果。 

为了使这一点更加精确，我们处理按左端点排序的间隔，但不仅维护一个活动的右端点，而且跟踪当前有多少间隔对最大右端点有贡献。 如果最大值是唯一的，则删除该间隔会减少覆盖范围扩展，并可能在联合中产生分裂。 如果最大值不唯一，则删除一份副本不会更改联合边界。 

这将问题简化为跟踪每个间隔是否唯一负责在某些段转换处扩展联合。 使用坐标压缩和具有多重集或堆状结构的扫描，我们可以维护当前最佳和第二最佳的右端点，并检测最佳端点何时是唯一的。 

每次并集延伸到新的右边界时，该延伸都会归因于至少一个区间。 如果恰好有一个间隔负责，则删除它会破坏该扩展并使组件数量增加 1。 

最后，答案是联合段的基线数量减 1 加上通过删除唯一关键间隔获得的最佳改进。

 ## 算法演练

 我们首先计算所有区间并集中的连通分量的数量。 这是通过按左端点对间隔进行排序并在下一个间隔与当前间隔重叠时贪婪地合并来完成的。 每次我们开始一个新的非重叠区域时，我们都会增加组件计数。 

接下来，我们模拟相同的扫描，但用有关哪个间隔负责扩展当前最远右端点的信息来丰富它。

1. 按左端点对间隔进行排序，如果相等，则按右端点降序排列。 这确保了在从同一点开始的间隔中，首先处理进一步延伸的间隔。 
2. 在当前合并区域中维护“活动候选者”右端点的多重集（或两个堆）。 目标是始终知道最大值以及它是否是唯一的。 
3. 扫过间隔。 对于每个间隔，我们将其右端点插入到活动结构中。 
4. 当当前间隔在当前合并段结束后开始时，我们完成前一个组件。 这是我们记录新联合段开始的地方。 
5. 在扩展线段时，每当最大右端点增加时，我们将这种扩展归因于达到该最大值的间隔。 
6. 如果在任何一点恰好通过一个间隔达到了最大右端点，我们将该间隔标记为“在此边界处关键”，这意味着删除它会阻止这种扩展并拆分组件。 
7. 处理完所有区间后，我们计算移除一个区间可以获得多少个分量。 如果每个间隔唯一负责原本不会发生的合并，则每个间隔最多可以贡献 +1 的改进。 
8. 最终答案是原始分量数加上删除后所有区间的最佳改进。 

### 为什么它有效

 并集结构仅在活动最大右端点跨组件之间的间隙发生变化的点处发生变化。 当没有间隔桥接间隙以扩展覆盖范围时，组件边界恰好存在。 只有唯一定义边界最大范围的间隔才能影响该边界在移除后是否消失。 由于重叠是由扫描的最大跟踪完全捕获的，因此每个合并或拆分事件仅由当时达到最大右端点的间隔的标识确定，这使得每个间隔的影响独立且可聚合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i))

    segs.sort()

    import heapq

    # active max-heap by (-r, id)
    heap = []
    contrib = [0] * n

    i = 0
    ans = 0
    cur_l = None
    cur_r = None

    while i < n:
        l = segs[i][0]

        if cur_l is None:
            cur_l, cur_r = segs[i][0], segs[i][1]

        if l > cur_r:
            ans += 1
            heap.clear()
            cur_l, cur_r = segs[i][0], segs[i][1]
            heapq.heappush(heap, (-segs[i][1], segs[i][2]))
            i += 1
            continue

        while i < n and segs[i][0] <= cur_r:
            l, r, idx = segs[i]
            heapq.heappush(heap, (-r, idx))
            cur_r = max(cur_r, r)
            i += 1

        # collect candidates with max r
        best_r = -heap[0][0]
        best_ids = []

        while heap and -heap[0][0] == best_r:
            best_r2, idx = heapq.heappop(heap)
            best_ids.append(idx)

        if len(best_ids) == 1:
            contrib[best_ids[0]] += 1

        for idx in best_ids:
            heapq.heappush(heap, (-best_r, idx))

    ans += 1
    print(ans + max(contrib) - 1)

t = int(input())
for _ in range(t):
    solve()
```该代码首先通过扫描排序间隔并检测间隙后新段何时开始来计算存在多少个联合组件。 它维护一堆活动右端点来识别当前覆盖边界何时由单个间隔唯一确定。 

这`contrib`array 跟踪每个间隔唯一负责扩展联合段的次数。 如果某个区间唯一负责至少一个此类扩展，则删除它可以使并集组件的数量恰好增加 1。 

最终公式添加了删除单个区间的最佳可能增益。

 ## 边缘情况

 关键的边缘情况是存在多个相同的区间。 在这种情况下，删除一个副本根本不会改变并集，因为另一个相同的间隔仍然保留相同的覆盖范围。 该算法处理此问题是因为最大右端点永远不会唯一地归因于单个区间； 多个指数共享相同的最佳值，因此不记录贡献。 

另一种边缘情况是一系列重叠间隔，其中每次重叠都是连接两个遥远区域所必需的。 在这种情况下，删除单个桥间隔会使联合组件的数量恰好增加 1。 扫描检测到负责在合并边界处扩展当前最大右端点的唯一间隔，以便该间隔被记入。 

最后一种微妙的情况是，一个区间完全包含在一个较大的区间内。 删除它永远不会影响联合结构。 由于它在任何扫描步骤中都不会成为唯一的最大右端点，因此它不会对增益计数做出贡献，因此最终答案正确地忽略它。
