 ## 解决方案
 ## 问题理解

 我们得到一棵树和一组固定的顶点，这些顶点由原始树中的所有叶子组成。 这些叶子从初始结构中确定一次，并且在此过程中不会改变。 

然后，我们重复选取两个不同的未使用的叶子，添加它们之间的唯一路径的长度，并将它们标记为已使用。 这个过程一直持续到最多一片叶子未被使用为止。 我们的目标是以最小化所有选定路径长度总和的方式选择配对顺序。 

这里重要的是，每个操作只能配对叶子，并且每个叶子最多只能参与一对。 如果叶子的数量是奇数，则恰好有一个叶子将保持不配对，但它的选择也是优化的一部分，因为它会影响支付的距离。 

约束条件很大：所有测试用例最多有二十万个顶点。 尝试所有配对甚至直接在所有叶子上运行匹配算法的任何解决方案都太慢。 即使叶子数量的二次行为也被立即排除，因为在最坏的情况下，树可以有 θ(n) 个叶子，就像一颗星一样。 

一个微妙的点是我们不允许选择任意顶点，只能选择原始树的叶子。 这种固定的结构使得问题适合奇偶校验上的树 DP 而不是一般的匹配算法。 

一个天真的但诱人的错误是认为我们可以自由地在本地贪婪地配对附近的叶子。 这对于简单的结构（例如具有许多分支的路径）来说是失败的，其中局部最优配对可能会迫使以后绕很远的路并增加总成本。 

例如，考虑一条路径，两端都有叶子，并且有许多小分支产生额外的叶子。 首先配对最近的叶子可能看起来是最佳的，但它可能会留下剩余叶子相距很远的配置，与全局平衡配对策略相比，增加了成本。 

## 方法

 该问题的直接表述是叶子集合上的最小权重完美匹配问题，其中两个叶子之间的距离是它们的树距离。 这是正确的，但如果直接接近，计算量会很大，因为不需要通用匹配技术，并且会过度破坏结构。 

关键的观察结果是树距离在边缘上清晰地分解。 每对叶子精确地沿着其独特路径的边缘贡献总成本。 如果我们修复配对，我们可以将答案重新解释为边上的总和：每条边对端点位于通过删除该边形成的不同组件中的每对贡献一次。 

这将问题从全局配对叶子转移到控制有多少对穿过每条边。 

现在考虑任何边缘。 删除它会将树分成两个部分。 令 k 为一个组件中的叶子数量，L − k 为另一组件中的叶子数量，其中 L 是叶子总数。 在每个组件内部，我们可以尽可能地在本地配对叶子。 组件中任何剩余的未配对叶子必须与另一侧的叶子配对，从而创建使用该边缘的交叉对。 

关键的结构事实是，在子树中，叶子可以完全配对，如果计数为奇数，则可能只剩下一个叶子。 剩下的部分是被迫杂交的唯一原因。 因此，当且仅当一侧的叶子数量为奇数时，一条边才会被一对交叉对使用。 

这将整个问题简化为针对每条边计算其下方的子树是否包含奇数个原始叶子。 

暴力尝试将重新计算每条边的叶子计数或尝试所有配对。 这将花费 O(n²) 或更糟。 优化后的解决方案只需要一个 DFS 来计算每个子树中有多少个原始叶子。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力配对/匹配 | 指数或至少 O(L²) | O(L) | 太慢了 |
 | 通过子树叶奇偶校验的树DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们任意给树建立根，为了方便起见，假设在节点 1 处。我们为每个节点定义一个值：其子树中存在多少个原始叶子。 

1. 从根运行 DFS 并计算每个子树中原始叶子的数量。 
2. 对于每个节点，如果它是原始叶子，则将其子树叶子计数初始化为 1，否则初始化为 0。 
3. 在 DFS 遍历期间，将子项的计数累加到父项中。 这给出了每个子树中叶子的总数。 
4. 从子 v 返回到其父 u 时，考虑边 (u, v)。 如果 v 的子树包含奇数个叶子，则该边对答案的贡献为 1。 
5. 将所有边上的所有此类贡献相加。 

我们只检查奇偶性的原因是子树内的配对会取消两个两个的叶子。 只有奇数余数迫使一片叶子向上逃逸，并且该逃逸恰好对应于穿过父边缘的一次交叉。 

### 为什么它有效

 每片叶子最终只参与一次配对，或者保持不匹配。 将每个配对视为定义两个叶子之间的路径，并且当该对的两个端点位于边缘的相对侧时，每条边缘都会对总成本产生影响。 

在任何子树内，只要叶子的数量是偶数，叶子就可以在内部配对。 当计数为奇数时，一颗叶子必须通过其连接边退出子树。 该出口恰好对应于任何有效的最佳构造中穿过该边缘的一次交叉。 

由于子树内部没有其他结构可以减少或增加此奇偶校验约束，因此叶子数量的奇偶校验是确定是否必须使用边缘所需的唯一信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    is_leaf = [False] * (n + 1)
    for i in range(1, n + 1):
        if len(g[i]) <= 1:
            is_leaf[i] = True

    visited = [False] * (n + 1)
    ans = 0

    def dfs(u, p):
        nonlocal ans
        visited[u] = True
        cnt = 1 if is_leaf[u] else 0

        for v in g[u]:
            if v == p:
                continue
            sub = dfs(v, u)
            if sub % 2 == 1:
                ans += 1
            cnt += sub

        return cnt

    dfs(1, -1)
    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该实现首先识别哪些顶点是原始树中的叶子。 这很重要，因为叶子根据定义是固定的，并且在 DFS 遍历期间不会改变。 

DFS 计算子树叶子计数。 当从子树返回时，其子树的奇偶性决定了父树和子树之间的边是否必须计入答案中。 累加器`ans`对所有这些边求和。 

根的选择不会影响正确性，因为只有子树分区很重要，而不是绝对方向。 

## 工作示例

 ### 示例 1

 考虑一棵小树，其中根连接到两个子树，每个子树包含一个叶子。 

| 节点| 子树叶子计数 | 边缘贡献|
 | --- | --- | --- |
 | 左孩子 | 1 | 边到根贡献 1 |
 | 右孩子| 1 | 边到根贡献 1 |

 DFS 发现两个子项都返回奇数计数，因此两条边都被计数一次。 这对应于每个叶子必须通过根连接才能到达其伙伴的事实。 

该跟踪证实，每当子树有不成对的叶子时，就会强制强制交叉一个边。 

### 示例 2

 在中心为 1、叶子为 2、3、4、5 的星形树中：

 | 节点| 子树叶子计数 | 边缘贡献|
 | --- | --- | --- |
 | 2 | 1 | 1 |
 | 3 | 1 | 1 |
 | 4 | 1 | 1 |
 | 5 | 1 | 1 |

 每片叶子直接连接到中心，因此每条边都承载一个贡献单位。 这反映出任何配对都必须经过中心。 

该跟踪强调了答案完全取决于子树叶奇偶性，而不取决于任何配对顺序。

 ## 边缘情况

 一个关键的边缘情况是叶子数量为奇数时。 在这种情况下，恰好有一个叶子保持不匹配，但算法不需要显式选择它。 奇偶传播自然地解释了这一点，因为恰好一条从根到叶的路径将以一种不配对的奇怪贡献模式结束。 

另一种边缘情况是一棵树，其中除两个之外的所有节点都是叶子，例如长路径。 在这种情况下，每个内部边缘在一侧都会看到奇数个叶子，因此每个边缘只贡献一次。 DFS 正确地累积了每个这样的边的贡献，因为每个子树在每一步都会分裂出一个叶子，产生交替的奇数计数。 

最后，在星图中，每个叶子都直接连接到中心。 每个叶子子树的大小为 1，因此每条边都会被计算在内。 该算法无需特殊大小写即可处理此问题，因为每个子项独立返回奇偶校验 1 并递增答案。
