 ## 解决方案
 ## 问题理解

 给定一个无向图，最初我们只知道顶点的数量和每个顶点的度数。 任务是为每个顶点分配一种颜色，以便满足两个条件。 首先，共享颜色的顶点必须在图中形成连通分量。 其次，对于每个颜色组，其顶点的度数之和不能超过该组中顶点数的平方。 交互允许我们查询每个顶点的邻居，但每个顶点最多只能查询一次，并且查询总数不能超过顶点数。 

约束很严格但易于管理：每个测试用例的顶点数量最多为 1000 个，所有测试用例的顶点总数不超过 1000。这表明任何总体复杂度约为 1000 个的算法$O(n^2)$每个测试用例都是可以接受的，但是任何超出此范围的嵌套查询都可能会达到查询限制。 因为我们只能查询每个顶点一次，所以我们必须在探索边时具有策略性。 尝试在不考虑查询限制的情况下重建完整邻接列表的简单方法将会失败，尤其是在度数较高的情况下。 

当顶点被隔离、具有最大度数或形成如果简单着色则可能违反度数和条件的组件时，就会出现边缘情况。 例如，如果一个顶点以零度孤立，则它必须成为单一颜色。 如果所有顶点都有度数$n-1$，颜色分配必须仔细分割它们以满足$s_c \le n_c^2$健康）状况。 粗心的方法可能会将高度顶点合并为单一颜色，从而违反度数总和条件。 

## 方法

 暴力方法会尝试通过查询每个顶点的每个邻居来构建完整的邻接列表。 这在技术上是正确的，因为一旦我们知道了图形，就可以对连接的组件进行着色以满足$s_c \le n_c^2$很简单。 然而，我们被限制为每个顶点最多一个查询，因此这种方法立即失败。 即使我们尝试多次查询顶点并缓存邻居，我们也会超出非平凡图的查询限制。 

关键的见解来自度和约束。 每个颜色组最多只能累积度数$n_c^2$。 如果我们以度数递减的顺序处理顶点，并且始终通过连接当前顶点的无色邻居来扩展组，则可以保证永远不会违反约束。 高度数的顶点自然形成颜色组的主干，并且添加较小度数的邻居不会超出界限。 这种贪婪方法之所以有效，是因为我们可以查询一个顶点一次，然后立即将其颜色分配给所有发现的邻居。 通过始终首先处理最高度数的无色顶点，我们可以最大限度地减少创建度数和边界空间不足的组的机会。 

这种策略自动确保连通性条件，因为我们总是从顶点沿着边扩展，从不跳过连接。 度和界限得到满足，因为从最大度的顶点开始并贪婪地添加顶点永远不会累积大于组大小的平方的度和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) 次查询 | O(n^2) | O(n^2) | 超出查询限制，失败 |
 | 贪婪程度| O(n log n + n) | O(n log n + n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取顶点的数量及其度数。 保留按度数降序排序的未着色顶点列表。 排序确保我们始终从具有最多邻居的顶点开始，从而最大限度地提高在度和约束内对连接组进行着色的能力。 
2. 从 1 开始初始化颜色计数器。这将为我们创建的每个组分配唯一的颜色。 
3. 当存在未着色顶点时，选择度数最高的未着色顶点。 仅查询一次以检索其邻居之一（根据交互规则）。 将此顶点指定为当前颜色。 
4. 对于查询返回的每个无色邻居，立即分配相同的颜色。 由于我们以度数递减的顺序处理顶点，因此添加邻居不会违反度数和条件，因为每个邻居的度数都小于或等于起始顶点。 
5. 增加颜色计数器并继续按降序处理下一个未着色的顶点。 重复此操作，直到所有顶点都着色。 
6. 输出着色。 每个组都是相连的，因为算法在同一步骤中为顶点及其邻居分配相同的颜色。 度数总和条件成立，因为最大的度数首先被分组，并且每个添加的顶点不会使总和超出组大小的平方。 

为什么有效：不变的是，在每一步中，当前颜色组的度数总和永远不会超过该组中顶点数的平方。 从最高度顶点开始可确保邻居的贪婪添加不会违反此界限。 由于着色从初始顶点沿着实际边缘传播，因此保证了连通性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
print_flush = lambda x: (print(x), sys.stdout.flush())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        degrees = list(map(int, input().split()))
        uncolored = set(range(1, n+1))
        colors = [0] * n
        color_id = 1
        degree_order = sorted([(deg, i+1) for i, deg in enumerate(degrees)], reverse=True)

        for deg, u in degree_order:
            if colors[u-1] != 0:
                continue
            colors[u-1] = color_id
            print_flush(f"? {u}")
            neighbor = int(input())
            if neighbor != -1 and colors[neighbor-1] == 0:
                colors[neighbor-1] = color_id
            color_id += 1
        print_flush("! " + " ".join(map(str, colors)))

if __name__ == "__main__":
    solve()
```我们首先按度数对顶点进行排序，首先处理度数最大的顶点。 当我们查询一个顶点时，我们立即为其邻居分配相同的颜色（如果未着色）。 我们仅在每组完成后才增加颜色计数器。 一个微妙的点是确保我们不会多次查询一个顶点； 我们通过在处理过程中只查询一次来维护这一点。 另一种方法是处理零度的孤立顶点，这些顶点会自动分配唯一的颜色。
