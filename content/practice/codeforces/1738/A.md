 ## 解决方案
 ## 问题理解

 我们获得了一系列战斗技能，每个技能都有两个属性：类型（火或霜）和伤害值。 英雄必须按某种顺序执行所有技能一次。 连续技能之间的唯一相互作用是，如果技能的类型与前一个技能不同，则该技能的伤害会加倍。 

目标是在应用此加倍规则后对技能进行排列以最大化总累积伤害。 

重要的结构点是只有不同类型之间的转换才重要。 在同一类型的连续方块内，所有技能都不受加成的影响，但每当我们在火和霜之间切换时，切换后的第一个技能就会加倍。 

这些约束允许所有测试中每个测试用例最多包含 100,000 个技能。 任何尝试所有排列甚至维持排序动态规划的解决方案都是不可行的，因为阶乘增长甚至二次转换都会超出限制。 每个测试用例我们都需要一个线性或线性算术方法。 

一个微妙的陷阱是假设将一种类型的所有技能分组是最佳的。 一般来说，这是错误的，因为切换类型会创造加倍的机会，并且这些乘数应尽可能应用于较大的伤害值。 

第二个微妙的问题是忽略了每个技能最多可以加倍一次。 即使我们多次交替类型，一项技能也只能从之前的过渡中受益，因此结构简化为控制技能的哪个子集加倍，而不是重复放大。 

## 方法

 暴力方法会尝试每种技能的排列，并通过模拟序列来计算所产生的伤害。 这是正确的，因为它直接评估目标函数，但它是完全不可行的。 有n个技能，就有n个！ 排列，每次评估的成本为 O(n)，导致远远超出 10^5 限制的爆炸。 

关键的观察是，影响技能贡献的唯一因素是它是否位于不同类型之间的边界。 这表明我们应该考虑安排火和霜这两个组，并决定我们创建多少个过渡。 

如果我们固定起始类型，序列就会变成交替块。 每次我们切换类型时，我们都会“花费”一次转换，使新块的第一个元素加倍。 因此，我们希望将最大值分配给它们加倍的位置。 

由于每个开关在新段中恰好贡献了一个双倍元素，因此该结构有效地简化为选择一种排列，其中我们最大化某些值子集乘以 2 的总和，而其余部分保持为 1×。 

事实证明，最佳策略仅取决于按伤害对所有技能进行排序，并确定哪一方对“非加倍基线”有贡献。 一种简洁的看待方式是：在所有可能的交替排列中，两种类型计数中的最小值决定了存在多少“强制配对”，并且我们可以进行安排，以便主导类型的最小元素不加倍，而较大的元素位于边界处以获得加倍。 

这导致了一种贪婪的解决方案，该解决方案基于对每种类型内的值进行排序，并仔细计算有多少元素可以避免加倍。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们根据类型将所有技能分为两个数组：火和霜，仅存储它们的伤害值。

1. 将两个数组按降序排序。 这确保我们始终考虑首先将最大值分配给最有利的位置。 
2. 计算两个数组的前缀和。 这允许快速评估从任一类型中获取前 k 个元素。 
3. 对于每个可能的转换数量，我们隐式确定每一侧有多少元素将被加倍或不加倍。 任何有效序列的结构都意味着最多一种类型可以在交替平衡之外贡献额外的不加倍元素。 
4. 我们通过尝试一种类型主导交替模式的分割点来评估可实现的最佳配置。 具体来说，我们考虑两种情况：着火序列和霜启动序列。 
5. 对于每种情况，我们将总贡献计算为所有元素的总和加上类型切换后立即落地的元素的额外增益。 由于每个开关恰好加倍一个元素，因此我们将加倍分配给与转换相对应的位置中最大的可用元素。 
6. 取两个起始选择中的最大值。 

中心思想是，最佳安排总是将高价值技能与过渡职位结合起来，因为这些是唯一可能加倍的职位。 

### 为什么它有效

 任何有效的排序都会引发一系列类型运行。 每个运行边界在下一次运行中恰好创建一个加倍的元素，并且所有其他元素都取消加倍。 由于可以在内部重新排列游程而不影响转换结构，因此只有边界位置的值分配很重要。 排序可确保最大值占据这些边界位置，从而最大化加倍的边际收益。 没有任何配置可以创建比转换数量更多的加倍事件，并且任何远离贪婪分配的重新分配只能用较小的值替换较大的加倍值，从而减少总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        fire = []
        frost = []
        
        for i in range(n):
            if a[i] == 0:
                fire.append(b[i])
            else:
                frost.append(b[i])
        
        fire.sort(reverse=True)
        frost.sort(reverse=True)
        
        def best(start_fire):
            # simulate optimal greedy placement idea
            f = fire[:]
            r = frost[:]
            
            if start_fire:
                first, second = f, r
            else:
                first, second = r, f
            
            i = j = 0
            turn = 0
            total = 0
            
            # take alternation greedily
            while i < len(first) or j < len(second):
                if turn % 2 == 0:
                    if i < len(first):
                        total += first[i]
                        i += 1
                    else:
                        total += second[j]
                        j += 1
                else:
                    if j < len(second):
                        total += 2 * second[j]
                        j += 1
                    else:
                        total += first[i]
                        i += 1
                turn += 1
            
            return total
        
        ans = max(best(True), best(False))
        print(ans)

if __name__ == "__main__":
    solve()
```该代码按类型拆分技能并对两组进行排序，以便我们总是更早地消耗更大的值。 然后它评估两种结构选择：从火开始或从霜开始。 对于每一种，它都模拟一种交替消耗模式，其中类型更改后立即获取的元素加倍，这与产生额外伤害的唯一机制相匹配。 

贪婪模拟之所以有效，是因为一旦两个列表都排序完毕，转换的最佳用途始终是将其应用于传入类型的最大剩余值。 基于指针的模拟强制执行该规则，而不需要对所有排列进行显式组合。 

一个微妙的实现细节是处理一种类型的耗尽。 当一个列表为空时，算法自然会回退到不加倍的消耗，这与不存在进一步转换的事实相匹配。

 ## 边缘情况

 最小的边缘情况是只有一项技能。 该算法立即返回其值，因为不存在转换，因此不可能加倍。 

第二种情况是所有技能都属于同一类型。 在这种情况下，每个技能都会在一次运行中处理，因此不会发生相邻类型的变化。 模拟永远不会触发加倍分支，这与每个乘数应保持为 1 的事实相符。 

第三种情况是一种类型占主导地位。 该算法仍然交替进行，直到较小的列表用完，然后沿直线继续。 此时，不会发生进一步的加倍，这正确地反映了一旦一侧耗尽，就不再可能进行跃迁。
