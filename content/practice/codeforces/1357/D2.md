 ## 问题理解

 我们在一组项目上获得了一个隐藏结构，其中每个项目属于两个类别之一，但我们不允许直接观察标签。 相反，获取信息的唯一方法是通过预言机来响应精心选择的有关数据集的查询。 

每个查询都与数据的底层“量子”表示交互，并返回间接依赖于隐藏分类的聚合信息。 任务是在交互式或查询受限环境的约束下，使用尽可能少的查询来恢复所有项目的完整分类。 

从算法的角度来看，这是一个受限访问下的重建问题：我们无法检查单个元素，也不能假设对标签的随机访问。 每条信息都必须通过结构化查询来提取，以揭示隐藏状态的线性或组合属性。 

这些约束意味着诸如单独查询每个元素或详尽地测试所有子集之类的幼稚策略是不可行的。 如果项目数量约为 10^5，则任何对每个元素执行 O(n) 昂贵的交互操作的方法都将面临超出时间和查询预算的风险。 任何隐式枚举子集的解决方案都会立即被排除，因为子集的数量呈指数增长，并且在不利用预言机中的结构的情况下无法进行修剪。 

朴素推理的一个常见失败案例是假设本地查询揭示本地信息。 例如，如果假设查询一小部分子集会隔离单个元素的标签，那么解决方案就会崩溃，因为预言机响应通常会纠缠在所有查询的元素上。 另一个微妙的陷阱是试图贪婪地重建答案：早期的错误推论会污染后来的推理，因为查询不是对单个变量的独立观察。 

错误方法的一个具体示例是重复查询单例集并假设响应直接对标签进行编码。 在这种情况下，输出可能会反映全局奇偶校验或聚合转换，从而使解释无效并导致整个数据集出现一致的错误分类。 

## 方法

 暴力策略很简单：对于每个元素，设计一个将其与所有其他元素隔离的查询，然后从响应中推断其类别。 在最坏的情况下，这需要 O(n) 次查询，每个查询都涉及与系统的完全交互。 如果每个查询本身由于子集构建或评估而花费 O(n) 处理，则总复杂度变为 O(n^2)，这对于大型数据集来说太慢并且超出了典型的交互约束。 

关键的见解是预言机在隐藏结构上呈线性行为。 我们没有尝试隔离单个元素，而是将每个查询视为未知标签向量上的线性方程。 一旦以这种方式解释问题，重构就成为标准的线性代数任务：我们收集足够的独立方程来确定所有未知数。 

这将问题从“独立识别每个元素”转变为“从线性测量中恢复未知的二进制向量”。 从这个角度来看，最佳策略是选择构成空间基础的查询，确保每个未知数对至少一个测量有独特的贡献。

在数据集 4 中，结构更加有利：查询响应表现得足够好，我们可以使用精心选择的对数或线性数量的查询构建满秩系统，然后使用 GF(2) 上的高斯消去法来解决它。 这完全避免了自适应每个元素查询。

 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 线性重建 | O(n^3) 最坏情况（高斯消除），O(n^2) 优化 | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们将隐藏标签建模为二进制向量，其中每个位置对应于未知分类。 每个查询都会返回这些值在模 2 算术下的线性组合，有效地为我们提供了一个方程组。 

1. 我们构建一组查询向量，形成线性独立系统。 每个查询的设计都使其响应给出涉及未知变量的不同子集的不同方程。 这样做的原因是为了确保没有多余的查询，否则会浪费有价值的信息。 
2. 我们将每个查询结果存储为增广矩阵中的一行。 每一行对应一个线性方程，每一列对应隐藏向量中的一个变量。 这将交互过程转换为静态线性系统。 
3. 我们对构造的矩阵进行 GF(2) 的高斯消去。 这一步系统地将系统简化为行梯形形式，将变量一一隔离。 系统的二进制性质将算术简化为异或运算。 
4. 矩阵缩减后，我们执行回代来恢复每个变量。 每个求解的变量都会立即用于解决早期方程中的依赖性，从而确保整个系统的一致性。 
5. 最后，我们输出所有元素的重建分类。 

这样做的原因是构造的查询集保证了系统的满等级。 每个隐藏变量至少对一个独立方程有贡献，高斯消去法保留了原始系统和简化形式之间的等价性。 由于我们永远不会在不保留线性约束的情况下丢弃信息，因此最终解决方案必须满足所有原始预言机响应，使其成为唯一的一致分类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def gauss_xor(mat, n, m):
    row = 0
    for col in range(m):
        pivot = -1
        for i in range(row, n):
            if mat[i][col]:
                pivot = i
                break
        if pivot == -1:
            continue
        mat[row], mat[pivot] = mat[pivot], mat[row]

        for i in range(n):
            if i != row and mat[i][col]:
                for j in range(col, m + 1):
                    mat[i][j] ^= mat[row][j]

        row += 1
        if row == n:
            break

def main():
    n = int(input().strip())
    mat = []

    for _ in range(n):
        row = list(map(int, input().split()))
        mat.append(row)

    m = n

    gauss_xor(mat, n, m)

    ans = [0] * n
    for i in range(n):
        for j in range(n):
            if mat[i][j]:
                ans[j] = mat[i][n]
                break

    print(*ans)

if __name__ == "__main__":
    main()
```该实现构建了查询系统的二进制矩阵表示，并使用基于异或的高斯消除来简化它。 每行都被视为一个方程，并且对称地执行消去以保持 GF(2) 中的正确性。 最后一步从简化的系统中提取变量分配。 

一个常见的实现陷阱是忘记消除必须应用于所有行，而不仅仅是枢轴下方的行。 由于我们在 GF(2) 中工作，对称消除确保系统最终保持一致且直接可读。 

另一个微妙之处是正确索引增强列。 最后一列存储每个方程的结果，这里的任何差一错误都会立即破坏重建。

 ## 边缘情况

 一种重要的边缘情况是系统包含冗余或重复的方程。 在这种情况下，消除会产生零行。 例如，如果两个查询产生相同的响应，则第二个查询在异或消除后将变为全零。 该算法自然会忽略它，因为它没有贡献任何主元，从而使解决方案保持不变。 

另一种边缘情况是当变量出现在每个方程中时，使系统变得密集。 即使在这里，高斯消除仍然在进行，因为主元选择确保每一步至少消除一个变量，从而防止停顿。
