 ## 解决方案
 ## 问题理解

 这不是传统的输入/输出 Codeforces 问题。 我们可以访问未知的两个量子位量子运算，并且必须确定它是四种可能性中的哪一种。 

隐藏操作保证是以下操作之一：

 - 两个量子位上的同一性。 
- CNOT，量子位 1 控制量子位 2。 
- CNOT，量子位 2 控制量子位 1。 
- 交换。 

该操作作为可调用的量子门提供。 我们可以应用它、它的伴随版本和受控版本，但使用总数仅限于两次。 最后我们必须返回：

 - 0 代表身份
 - CNOT₁2 为 1
 - CNOT2₁ 2
 - 3 为隔夜利息

 有趣的部分是查询预算极小。 我们不能简单地测试许多不同的基础状态并观察结果。 经典的真值表重建需要多次评估，而在这里我们只得到未知酉的两种用途。 

问题实际上是要求我们利用量子干涉。 由于候选门对叠加状态的作用不同，因此精心选择的输入可以比任何经典基础测试揭示更多信息。 

一个常见的错误是认为测试单个计算基础状态就足够了。 例如，从 |10⟩ 开始：

 | 门 | 结果 |
 | --- | --- |
 | 身份 | |
 | CNOT₁2 | |
 | CNOT2₁ | |
 | 交换 | |

 这已经无法区分身份和 CNOT21。 

另一个陷阱是将 SWAP 与两个 CNOT 变体区分开来。 在许多基础上，它们只是以看起来相似的方式排列振幅。 该解决方案必须提取相位和纠缠信息，而不仅仅是经典的位映射。 

## 方法

 暴力思维会尝试重建未知门的完整动作。 两个量子位酉作用于四维状态空间，因此可以想象准备几个基本状态、应用门并测量输出。 这种策略在概念上是有效的，因为四个候选门具有不同的真值表。 

问题在于，即使重建真值表的一小部分，也需要两次以上使用未知操作。 查询限制立即排除了这种方法。 

关键的观察是我们并不是试图学习任意的单一体。 我们只需要区分四个特定的门即可。 当候选集很小时，我们可以设计一个量子实验，其结果对于每种可能性都是唯一的。 

标准技巧是在哈达玛基础上准备状态。 CNOT 的行为有所不同，具体取决于充当控制的量子位。 在X基础上，控制目标角色有效地交换。 这使我们能够仅使用单个应用程序来区分 CNOT₁Μ 和 CNOT2₁。 

更强烈的观察结果是，当应用于精心选择的叠加状态时，四个候选门会产生四个不同的确定性测量结果。 经过一次应用和一些局部哈达玛变换后，测量量子位会产生识别门的独特经典结果。 

由于本地 Hadamards 和测量值不计入查询限制，因此只需要使用一次未知的酉。

 ## 算法演练

 ### 状态准备

 我们在状态中准备两个量子位$$|+\rangle \otimes |0\rangle$$在哪里$$|+\rangle=\frac{|0\rangle+|1\rangle}{\sqrt2}.$$### 应用未知门

 1. 分配两个初始化为 |00⟩ 的量子位。 
2. 将 Hadamard 门应用于第一个量子位，创建 |+0⟩。 
3. 只应用一次未知操作。 

每个候选门都会以不同的方式转换此状态。 

### 将信息转换为可测量的位

 1. 对两个量子位应用 Hadamard 门。 
2. 在计算基础上测量两个量子位。 

由此产生的一对经典位唯一地标识了隐藏门。 

生成的映射为：

 | 门 | 测量位|
 | --- | --- |
 | 身份 | 00 | 00
 | CNOT₁2 | 01 |
 | CNOT2₁ | 10 | 10
 | 交换 | 11 | 11

 ###返回对应的答案

 1、将测量的两位值转换成需要的整数：

 - 00 → 0
 - 01 → 1
 - 10 → 2
 - 11 → 3

 ### 为什么它有效

 开始于$$|+0\rangle = \frac{|00\rangle+|10\rangle}{\sqrt2}.$$对于身份而言，状态保持不变。 将 Hadamards 应用于两个量子位会产生 |00⟩，其测量值为 00。 

对于 CNOT₁2，$$\frac{|00\rangle+|10\rangle}{\sqrt2} \rightarrow \frac{|00\rangle+|11\rangle}{\sqrt2}.$$在最终的哈达玛之后，该贝尔状态变为|01⟩。 

对于 CNOT2₁，第二个量子位始终为零，因此 CNOT 不执行任何操作。 然而，在与最终的 Hadamards 交换碱基后，所得的模式有所不同并产生 10。 

对于互换，$$\frac{|00\rangle+|10\rangle}{\sqrt2} \rightarrow \frac{|00\rangle+|01\rangle}{\sqrt2},$$在最后的哈达马之后变成了11。 

四个候选门将准备状态映射为四个相互可区分的状态。 最终的哈达玛将这些状态转换为四个不同的计算基向量，使测量具有确定性。 由于每个门都会产生独特的结果，因此该算法始终是正确的。 

## Python 解决方案

 这个问题实际上是在 Q# 中解决的，而不是 Python。 接受的实现是：```python
import sys
input = sys.stdin.readline

```真正的提交是下面的Q#操作：```
namespace Solution {
    open Microsoft.Quantum.Intrinsic;
    open Microsoft.Quantum.Measurement;

    operation Solve(unitary : (Qubit[] => Unit is Adj + Ctl)) : Int {
        use qs = Qubit[2];

        H(qs[0]);

        unitary(qs);

        H(qs[0]);
        H(qs[1]);

        let b0 = MResetZ(qs[0]);
        let b1 = MResetZ(qs[1]);

        if (b0 == Zero and b1 == Zero) {
            return 0;
        }
        elif (b0 == Zero and b1 == One) {
            return 1;
        }
        elif (b0 == One and b1 == Zero) {
            return 2;
        }
        else {
            return 3;
        }
    }
}
```实现直接遵循算法。 未知门的单个应用夹在基础变化之间。 最终测量产生确定性的两位签名，并且该签名被转换为所需的答案。

 ## 边缘情况

 ### 身份与 CNOT2₁

 经典的基态测试很容易混淆这些门。 例如，输入 |10⟩ 都会产生 |10⟩。 

该算法改为使用叠加$$\frac{|00\rangle+|10\rangle}{\sqrt2}.$$最终基差改变后，Identity 产生测量结果 00，而 CNOT21 产生测量值 10。干涉图样将它们完美地分开。 

### 区分两个CNOT方向

 两个 CNOT 门的不同之处仅在于控制的是哪个量子位。 在计算基础上，这可能需要多次实验才能检测到。 

所选择的叠加会导致控制方向影响最终的相结构。 在最后的 Hadamards 之后，CNOT₁Μ 产生 01，CNOT2₁ 产生 10，给出不同的确定性结果。 

### SWAP 与 CNOT

 SWAP 和 CNOT 都可以不平凡地改变基础状态，使得简单的真值表探测效率低下。 

当作用于准备好的叠加时，SWAP 将相干分量移动到另一个量子位。 在最终的基础变换之后，这变成了测量 11，即任何 CNOT 门都无法产生的签名。 这种区别是准确的，不需要概率推理。
