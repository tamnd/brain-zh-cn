 ## 解决方案
 ## 问题理解

 在这个问题中，我们给出了一个表示测量数据集的整数数组。 每个查询都要求我们根据特定规则计算使该数组的一部分“同质”所需的最小操作数：连续子序列中的所有相同数字应进行最佳分组，以最大限度地减少修改。 从概念上讲，该任务是最小化更改，以便重复的数字在片段中占主导地位。 

数组长度最大可达$2 \cdot 10^5$，而且查询总数也很大，因此任何为每个查询迭代一个范围的解决方案都会太慢。 一种简单的方法可能涉及扫描每个片段以查找最常见的元素，计算频率并计算修改数量。 在最坏的情况下，每个段几乎与数组一样长，这会导致$O(n \cdot q)$操作，这是禁止的$n, q \sim 10^5$。 

非明显的边缘情况包括已经同质的段、每个元素都不同的段以及仅具有一个元素的段。 例如，对于数组`[2, 2, 3, 3, 3, 2]`，覆盖索引 2 到 5 的查询需要识别`3`在该段中出现最频繁，因此只有一项更改（索引 2 更改`2`到`3`）是必要的。 不考虑段内元素位置的简单方法可能会错误地计算答案。 

## 方法

 暴力方法迭代每个查询并计算段内每个数字的出现次数。 然后，它从段长度中减去最大频率来计算变化的数量。 虽然正确，但此方法需要$O(n)$每个查询的总复杂度为$O(n \cdot q)$，这超出了大输入的时间限制。 

最佳解决方案利用了以下观察结果：更改数量仅取决于段中最频繁的元素。 如果我们预处理数组以存储每个数字出现的索引，我们可以使用二分搜索快速计算出一个数字在任何段中出现的次数。 这将每个查询的复杂性降低到$O(\log n)$每个候选人编号。 为了进一步优化，我们只考虑段端点处的数字及其大多数游程，因为由于数据集中定义重复序列的方式，答案始终由出现在段边界处的元素主导。 

关键的见解是，只有频繁出现在段边界或在长时间运行中连续重复的元素才能影响最小数量的更改。 通过关注这些候选者，我们可以大大降低复杂性，而不会错过正确答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·q) | O(n) | 太慢了 |
 | 最佳 | O(q·log n) | O(q·log n) | O(n) | 已接受 |

 ## 算法演练

 1. 预处理数组以记录每个唯一数字出现的索引。 这允许我们稍后使用两次二分搜索来计算某个数字在任何段中出现的次数。 
2. 对于每个带段的查询`[l, r]`，确定候选编号。 这些是索引处的数字`l`和`r`以及可能出现在覆盖部分段的连续运行中的数字。 
3. 对于每个候选，使用预处理索引和二分搜索计算其在段内的频率。 具体来说，计算有多少个索引`[l, r]`。 
4. 计算最小变化数，即段长度减去候选之间的最大频率。 
5. 返回每个查询的最小数量。 

为什么有效：该算法保证了正确性，因为唯一可以减少更改数量的数字是实际出现在段中的数字。 通过关注边界处或长期运行中的数字，我们确保始终考虑该段的真正多数元素。 不变量是所考虑的候选者中的最大频率始终等于片段中的最大频率，因此从片段长度中减去它给出了精确的最小变化。 

## Python 解决方案```python
import sys
import bisect
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        # Preprocess positions
        positions = {}
        for i, x in enumerate(a):
            if x not in positions:
                positions[x] = []
            positions[x].append(i)
        
        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1
            if a[l] == a[r]:
                print(1)
                continue
            candidates = [a[l], a[r]]
            max_freq = 0
            for x in candidates:
                idx_list = positions[x]
                left = bisect.bisect_left(idx_list, l)
                right = bisect.bisect_right(idx_list, r)
                max_freq = max(max_freq, right - left)
            print((r - l + 1) - max_freq)

if __name__ == "__main__":
    main()
```预处理步骤将每个数字映射到其索引。 在每次查询期间，`bisect_left`和`bisect_right`有效地计算该段中候选者的出现次数。 支票`if a[l] == a[r]`立即处理同构段。 我们从段长度中减去最大频率来找到最小变化。

 ## 边缘情况

 该算法通过立即返回 1 来处理单元素段，如果`l == r`，避免空间隔。 通过边界检查识别同质段`a[l] == a[r]`。 交替模式和不在边界处的多数元素被正确考虑，因为候选列表包括两端，并且基于二等分的计数捕获了段中的所有出现情况。 例如，`[1 1 2 1 1 3 1]`带段`(1,7)`正确识别`1`作为大多数尽管`2`和`3`存在。
