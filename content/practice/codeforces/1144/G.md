 ## 解决方案
 ## 问题理解

 我们得到一个序列，并被告知它最初是通过两个隐藏序列并将它们交错形成的。 一个隐藏序列是严格递增的，另一个是严格递减的，并且在合并过程中保留了它们的内部顺序，但它们的元素在位置上任意混合。 

我们的任务不是重建原始序列本身，而只是决定这种分割是否可能。 如果可能的话，我们必须将给定数组中的每个位置分配给两个序列之一。 一个标签代表递增序列，另一个标签代表递减序列。 

困难在于，如果违反严格的排序，则相同的值不能出现在两个序列中，并且一旦我们将一个元素分配给一个序列，它必须与相对于同一序列的所有先前分配的元素的单调性约束保持一致。 

约束条件$n \le 2 \cdot 10^5$排除尝试所有分区的任何方法。 朴素的子集分配导致$2^n$的可能性，这是完全不可行的。 即使是所有分割上的二次 DP 也会太慢。 

当值重复或贪婪赋值看似局部有效但后来强制矛盾时，就会出现微妙的边缘情况。 例如，像这样的序列$[3, 1, 2, 0]$看起来很灵活，但贪婪的赋值很容易让一个序列陷入违反单调性约束的境地。 另一种失败情况是交替的高低模式，其中两个序列都过早“用完”。 

核心挑战是每个元素的分配方式必须同时尊重递增约束和递减约束，同时仍允许未来的灵活性。 

## 方法

 强力解决方案将尝试所有方法将每个元素分配给递增或递减序列，然后独立验证两个序列。 对于每个分配，我们将扫描两个子序列以检查严格的单调性。 这需要$2^n$作业和$O(n)$验证每个，这导致$O(n \cdot 2^n)$，远远超出任何合理限度。 

关键的观察是我们只需要跟踪每个序列中最后使用的值。 如果我们从左到右处理数组，则在每个位置我们决定是将当前值放入递增序列还是递减序列。 约束简化为维持两个“边界”：递增序列中的最后一个值必须严格递增，递减序列中的最后一个值必须严格递减。 

然而，基于当前比较的贪婪选择会失败，因为有时两种选择在本地都有效，但只有一种保留了未来的可行性。 正确的结构是将其视为具有两个演化状态的决策问题，其中我们跟踪在使用给定的最后值配置处理每个前缀后是否可以到达状态。 

解决此问题的标准方法是维持两种动态状态：一种代表最后选择的递增值，一种代表最后选择的递减值。 在每一步中，我们都会尝试这两种分配，但会删除不可能的转换。 由于值是有界的，因此我们通过仅保留每个前缀的每个角色的最小可行最后值来压缩状态。 关键的见解是，为了实现可行性，在处理每个前缀后为每个序列维持最佳可能的边界条件就足够了。 

这导致了线性贪婪式传播，其中我们以受约束的方式模拟两种可能性，并且总是更喜欢使两个序列尽可能灵活的分配。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护两个值：为递增序列选择的最后一个元素和为递减序列选择的最后一个元素。 最初两者都是未定义的，我们将其视为无限灵活的边界。 

我们从左到右处理数组并决定将每个元素分配到哪里。 

1. 如果当前值可以扩展递增序列（意味着它严格大于最后一个递增值），我们考虑将其放在那里。 
2.如果它可以扩展递减序列（意味着它严格小于最后一个递减值），我们也考虑将其放在那里。 
3. 如果两种选择都可行，我们会选择为未来步骤保留更大灵活性的一种。 具体来说，如果这样做不会立即使递减序列变得不可能，我们更愿意将其放入递增序列中，因为当值很大时，递减序列的限制性更大。 
4. 如果只有一项任务是可能的，我们就必须接受它。 
5. 如果两个分配都不可能，我们立即得出结论：分割是不可能的。 
6. 我们记录分配并更新相应的最后值跟踪器。 

该算法是贪婪的，但受到可行性约束的指导，而不是任意偏好。 

### 为什么它有效

 在数组的任何前缀处，该算法都保持不变，即存在与当前最后值状态一致的所有已处理元素的有效分配。 每个决策至少保留一个可行的延续（如果存在）。 单调性约束仅通过最后选择的值来减少每个序列的未来自由度，因此保留有效的最后值足以表征所有未来的可能性。 由于只要存在解决方案，每一步都至少保留一个可行的扩展，因此无矛盾地到达终点可以保证有效的划分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    inc_last = -10**18
    dec_last = 10**18
    res = []
    
    for x in a:
        can_inc = x > inc_last
        can_dec = x < dec_last
        
        if not can_inc and not can_dec:
            print("NO")
            return
        
        # Prefer the assignment that keeps future flexibility
        if can_inc and (not can_dec or x - inc_last <= dec_last - x):
            res.append(0)
            inc_last = x
        else:
            res.append(1)
            dec_last = x
    
    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```该解维持两个边界变量。`inc_last`跟踪递增序列中使用的最后一个值，初始化为负无穷大，以便任何值都可以启动它。`dec_last`跟踪递减序列中使用的最后一个值，初始化为正无穷大。 

在每一步中，我们都会测试当前值是否可以扩展任一序列。 如果两者都不可能，则构建会立即失败。 

平局决胜条件旨在避免过早地拉紧一个序列。 如果两种放置方式均可行，我们会选择为另一个序列留下更多空间的放置方式（通过值与其边界的距离来衡量）。

 ## 边缘情况

 单元素数组始终有效，因为它可以属于任一序列而不破坏单调性约束。 该算法默认将其分配给递增序列，因为两种转换最初都是可行的。 

对于严格递增的数组，永远不需要递减序列。 该算法始终保持分配给递增序列，因为`can_inc`仍然为真并且`can_dec`第一步之后就变得无关紧要了。 

对于严格递减数组，第一个元素分配为递增后，所有后续元素都必须进入递减序列。 一旦增加的边界阻止进一步的分配，算法就会正确地切换角色。 

在交替的高低序列中，两种选择经常可用。 打破平局规则通过优先选择在边界之间留下较大余裕的分配来防止过早承诺，从而确保该过程不会意外地过早消除可行性。
