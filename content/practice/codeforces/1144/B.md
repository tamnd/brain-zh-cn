 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并且允许我们在奇偶校验约束下逐个删除元素，该奇偶校验约束取决于先前的删除。 第一个删除的元素可以是任何元素。 之后，每次删除都必须相对于最后删除的元素交替奇偶校验：如果我们刚刚删除了偶数，则下一个必须是奇数，反之亦然。 一旦不存在满足此交替规则的有效元素，该过程就会停止。 

我们的目标不是最大化我们删除的元素数量，而是最小化当我们陷入困境时保留在数组中的元素的总和。 由于所有删除都是免费的，并且分数是剩余的总和，因此我们希望删除尽可能大且尽可能有价值的元素子集，同时尊重奇偶校验交替约束。 

关键的约束是每次移动仅取决于最后删除的元素的奇偶校验，而不是其值或位置。 这显着减少了问题结构：我们正在有效地构建奇偶校验交替的删除序列，并且我们希望最大化删除的总权重。 

数组大小最多为2000，这排除了所有删除顺序的指数模拟。 三次或更差的方法可能会失败。 然而，O(n^2) 或 O(n^2 log n) 解决方案是可行的。 这强烈表明了贪婪或基于排序的结构，因为我们可能可以推理每个奇偶校验组的最佳选择，而不是探索所有序列。 

当最佳策略不是最大化删除数量而是仔细选择从哪个奇偶校验链开始时，就会出现微妙的失败情况。 例如，选择一个非常小的起始元素可能会解锁一个更好的交替链，该链稍后会删除较大的元素。 任何假设“总是从最好的直接选择开始”的方法都是不安全的。 

## 方法

 暴力解释是模拟所有可能的删除序列。 从任何状态，我们选择一个有效的下一个具有相反奇偶性的元素并继续，直到卡住。 每条路径都会产生一个候选剩余总和。 然而，在最坏的情况下，可能的序列数量是阶乘，因为在每一步我们都可以在许多有效元素中进行选择。 即使通过奇偶校验进行修剪也没有足够的帮助，因为排序仍然很重要，并且可以通过许多顺序达到相同的子集。 

关键的观察是，元素的实际身份并不比它们的奇偶性和价值更重要。 由于我们正在最小化剩余总和，因此我们希望最大化已删除总和。 该约束仅强制交替，这意味着任何有效的删除序列只是所选元素的交替序列。 只要奇偶校验交替，我们就可以任意重新排序删除，因此我们只需要决定取多少个偶数和奇数元素以及采用什么交替结构即可。 

一个关键的简化是考虑对所有元素进行排序。 如果我们决定以交替方式获取一定数量的偶数和奇数，我们应该始终获取每个奇偶校验中最大的可用元素，因为将所选元素与较小的元素交换不会破坏可行性，而是会提高目标。 

这将问题简化为选择起始奇偶校验，然后贪婪地交替，始终消耗所需奇偶校验的最大剩余元素，直到一侧耗尽。 我们尝试两种起始平价并取得最好的结果。

 | ---| ---| ---| ---|
 | 所有序列的暴力模拟 | 指数| O(n) | 太慢了 |
 | 贪婪排序奇偶校验列表 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将数字分为偶数和奇数，然后按降序对两组进行排序，以便我们始终首先考虑最有价值的删除。

1. 根据奇偶校验、偶数和奇数将数组拆分为两个列表。 这是必要的，因为游戏规则仅取决于奇偶校验转换，而不取决于位置。 
2. 按降序对两个列表进行排序。 这确保了每当我们从奇偶校验类中进行选择时，我们总是选取最大的剩余元素，这使得本地已删除元素的总和最大化。 
3. 模拟从偶数元素开始的贪婪删除过程。 我们保留两个指向偶数和奇数列表的指针。 我们交替选择：在选择偶数后，我们选择奇数，反之亦然。 
4. 继续交替，直到用完一个列表。 此时，不存在进一步的有效移动，因此该过程结束。 计算此模拟中采用的所有元素的总和。 
5. 首先从奇数元素开始重复相同的过程。 这解释了这样一个事实：第一步没有限制，并且对整个链条有强烈的影响。 
6. 答案是所有元素的总和减去两次模拟得到的最大和。 

为什么它有效：一旦起始奇偶性固定，该过程就被迫进入确定性交替行走，其中每一步唯一的自由是采用该奇偶性的哪个元素。 由于我们总是选择所需奇偶校验的最大可用元素，因此任何偏差都会用较小的元素替换所选元素，而不会影响可行性。 这在严格改进或维持目标的同时保留了有效性，因此贪婪选择在每个固定的起始奇偶性内是最优的。 取两个起始奇偶校验的最大值涵盖所有有效序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def simulate(evens, odds, start_even):
    i = j = 0
    take_even = start_even
    total = 0

    while True:
        if take_even:
            if i >= len(evens):
                break
            total += evens[i]
            i += 1
        else:
            if j >= len(odds):
                break
            total += odds[j]
            j += 1
        take_even = not take_even

    return total

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    evens = sorted([x for x in a if x % 2 == 0], reverse=True)
    odds = sorted([x for x in a if x % 2 == 1], reverse=True)

    total_sum = sum(a)

    best_take = max(
        simulate(evens, odds, True),
        simulate(evens, odds, False)
    )

    print(total_sum - best_take)

if __name__ == "__main__":
    solve()
```该解决方案的工作原理是将问题简化为两个确定性贪婪模拟。 排序后的奇偶校验列表确保每次我们从奇偶校验类中进行选择时，我们都能最大化本地贡献。 这两次运行说明了不受约束的第一步。 

一个常见的微妙之处是忘记了第一步是不受限制的，这就是为什么我们必须评估两个起始平价而不是任意固定一个。

 ## 边缘情况

 单元素数组很简单：不进行任何移动或先删除元素，游戏立即结束，剩余总和为零。 

所有具有相同奇偶校验的元素是另一个极端情况。 例如，`[2, 4, 6]`只允许删除一次，因为删除第一个元素后没有相反的奇偶校验可以继续。 该算法正确地处理了这一问题，因为其中一个奇偶校验列表立即变空，因此模拟在一步后停止，其余部分保持不变。 

高度不平衡的奇偶校验计数说明了为什么起始奇偶校验很重要。 如果偶数很多而赔率很少，那么从偶数开始可能会很快耗尽赔率，而从赔率开始可能会更早浪费结构。 双模拟方法确保评估两种可能性，并选择最大删除和。
