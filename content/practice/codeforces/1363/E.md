 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中每个节点携带两位信息：初始二进制数字和所需的最终二进制数字。 任务是使用特殊操作将初始配置转换为目标配置，该操作允许我们采用任何子树，选择其中的任何节点子集，并自由排列这些所选节点之间的位。 这种操作的成本仅取决于子树根和所选节点的数量，具体来说，它与所选子集的大小乘以该子树根的成本成正比。 

操作的关键效果是在子树内选定的子集中，我们可以任意重新分配值。 这意味着我们不是一步步沿着边缘移动，而是创建灵活的“混合区域”，这些区域变得更便宜或更昂贵，具体取决于我们选择哪个祖先作为操作的根。 

该约束足够大，任何尝试显式模拟操作的解决方案都是不可能的。 对于多达 200,000 个节点，任何对节点子集或成对传输进行推理的方法都会立即变得二次或更糟。 这将我们推向树 DP 视角，其中每个节点总结了必须向上发送或从下面吸收的内容。 

一个微妙的困难来自于可行性。 如果初始配置中的总数量与目标配置中的总数量不匹配，则任何洗牌序列都无法解决此问题，因为洗牌会全局保留多重集。 忽略此全局约束的简单实现将错误地尝试构建成本。 

当子树仅包含一种类型的数字但需要在转换后产生两种类型时，会出现另一种失败情况。 例如，如果一棵子树仅包含 0，但目标需要 1，并且其他地方不存在可移动的子树，则答案必定是不可能的。 这不是每个节点本地的，它取决于赤字如何通过树传播。 

## 方法

 暴力视图将尝试将每个操作建模为在选定的子树内移动令牌，从而有效地模拟所有可能的子集和排列。 即使我们限制自己选择最佳子集，每个节点的可能性数量也是子树大小的指数，因为每个子集都是有效的并且每个排列都是允许的。 这很快就会变得棘手。 

关键的观察结果是，该操作并不真正依赖于节点的身份，仅依赖于 0 和 1 的计数。 在任何子树操作中，我们都在有效地重新分配位的供应和需求，并且成本取决于我们选择执行操作的位置。 如果我们选择更高的祖先，与在树中执行多个本地操作相比，我们支付的每个节点成本更小。 

这导致了一个贪婪的想法：在每个节点，我们想要决定其子树中的初始配置和目标配置之间有多少不匹配必须通过该节点“解决”。 每个节点的行为就像一个潜在的“输送机”，可以匹配其子节点的盈余和赤字。 最佳策略是自下而上组合不匹配，始终考虑可以发生配对的最便宜的位置。 

这将问题简化为树 DP，其中每个节点计算其子树中剩余多少多余的 0→1 和 1→0 转换，以及本地解析内部对的最小成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（子集模拟）| 指数| O(n) | 太慢了 |
 | 最优树DP（后序失配平衡）| O(n) | O(n) | 已接受 |

 ## 算法演练

我们以节点 1 为树根并执行后序 DFS。 对于每个节点，我们跟踪其子树中每种类型有多少未解决的不匹配。 

我们为每个节点定义两个数量：其子树中有多少节点需要当前具有 1 的 0，以及有多少节点需要当前具有 0 的 1。 

1. 从根执行 DFS，以便每个节点在处理自身之前聚合来自其子节点的信息。 这确保了我们在决定如何在当前节点解决子树之前始终知道子树的完整不匹配结构。 
2. 对于每个节点，根据其自身的初始位和目标位计算其本地失配。 如果是 0→1，则贡献 1 个 1 的需求。如果是 1→0，则贡献 1 个 0 的需求。这将节点的需求与子树结构隔离。 
3. 通过对子结果的不匹配计数求和，将子结果合并到当前节点。 在此阶段，我们对子树中所有未解决的需求有了完整的了解。 
4. 在节点 u 处，我们尝试“匹配”来自子节点的相反不匹配。 0→1 不匹配可以取消 1→0 不匹配，因为在子树内我们可以任意打乱值。 此类取消的数量是两个计数中的最小值。 
5. 每个取消代表一对可以使用以 u 为根的操作来修复的节点。 仅当我们显式模拟配对时，固定这样一个对的成本才为 2 * a_u，但最佳解释是通过 u 的每个单位的流量贡献与 a_u 成比例的成本。 因此，我们根据本地取消后通过 u 的不匹配数量来累积成本。 
6. 取消后，剩余的不匹配将传递给父级，因为它们无法在此子树中完全解决，并且必须在操作可能更便宜的树中更高层进行处理。 

一个重要的认识是，每个不匹配都必须向上移动，直到找到可以配对的位置。 最便宜的此类位置是路径上仍包含两种类型的不匹配的最高可能节点。 这就是 DFS 中聚合起作用的原因。 

### 为什么它有效

 该算法保持了不变式，即在处理节点 u 后，其子树中的所有不匹配仅表示为一种类型的净剩余，这意味着当它们可以在本地配对时，我们永远不会同时向上携带两种类型。 由于操作允许在子树内进行任意排列，因此可以在本地完成的任何配对总是至少与向上延迟它一样好，并且延迟只会增加成本，因为祖先成本通常并不小。 这确保了每次取消都是在最高效益点执行，从而产生全局最小成本，同时通过确保不匹配的需求不会在根本上得到解决来增强可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = [0] * (n + 1)
    b = [0] * (n + 1)
    c = [0] * (n + 1)

    for i in range(1, n + 1):
        ai, bi, ci = map(int, input().split())
        a[i] = ai
        b[i] = bi
        c[i] = ci

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    INF = 10**30

    def dfs(u, p):
        zero = 0
        one = 0
        cost = 0

        if b[u] == 0 and c[u] == 1:
            one += 1
        elif b[u] == 1 and c[u] == 0:
            zero += 1

        for v in g[u]:
            if v == p:
                continue
            z, o, cst = dfs(v, u)
            cost += cst

            # match opposite demands
            m = min(zero, o)
            zero -= m
            o -= m

            m = min(one, z)
            one -= m
            z -= m

            zero += z
            one += o

        # if both remain, they must be paired at this node
        m = min(zero, one)
        zero -= m
        one -= m

        # each remaining pair contributes cost at this node
        cost += (zero + one) * a[u]

        return zero, one, cost

    z, o, ans = dfs(1, -1)

    if z != 0 or o != 0:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```DFS 计算每个子树在最大本地配对后剩余多少不匹配的需求。 变量`zero`和`one`分别表示类型 1→0 和 0→1 的不匹配。 当我们合并子节点时，我们立即取消相反的不匹配，因为任何这样的对都可以在当前节点的子树上解析，而不需要将它们向上推。 

合并后，我们再次取消当前节点剩余的配对，剩余的不匹配数量将被收取成本`a[u]`，表示这些不匹配必须在任何有效的操作序列中至少经过节点 u 一次。 

最终检查确保没有不匹配的需求逃脱根源； 否则转型是不可能的。

 ## 边缘情况

 关键的边缘情况是存在不匹配但无法在树中的任何位置相遇，因为它们都具有相同的类型。 例如，如果每个节点都有 b[i] = 0 且 c[i] = 1，则该算法仅累积一种不匹配类型，并以非零余数到达根。 最终检查正确返回-1。 

另一种边缘情况是子树中的不匹配在到达根之前完全取消。 在这种情况下，两个计数器在中间节点都变为零，并且在取消点之外不会添加任何成本。 该算法通过在传播之前始终执行局部取消来确保这一点，因此不会引入人为的向上成本。 

第三种情况是长链，其中交替错配仅在根处相遇。 DFS 确保它们在收敛之前保持分离，并且在最顶层的有效交汇点仅收取一次成本，这符合将昂贵的解决方案延迟到必要时的最佳策略。
