 ## 解决方案
 ## 问题理解

 我们得到一个数组$A$长度$n$，但我们无法直接看到它。 相反，我们可以提出查询：选择索引的任何子集，然后判断返回最大值$A$超过这些指数。 

除了这个隐藏数组之外，我们还得到了$k$特殊索引集$S_1, S_2, \dots, S_k$。 这些集合是不相交的，但它们一般不涵盖所有索引。 我们需要恢复的实际“密码”是另一个数组$P$长度$k$，其中每个值都是从隐藏数组和这些集合之一间接定义的。 

对于每个$i$，我们删除所有索引$S_i$，查看剩余索引，并取最大值$A$那里。 该值变为$P_i$。 因此，每个密码条目都是已知禁止集的补集的最大值。 

挑战在于我们最多只能向法官提出 12 个查询，因此我们必须提取有关全局最大值及其位置的足够信息，以有效地重建所有这些补集最大值。 

关键的困难在于，只有当全局最大值为$A$位于该集合内。 如果我们能够识别最大值并了解哪些子集包含该最大值的所有出现，我们就可以确定每个子集如何$P_i$与全局最大值不同。 

约束条件$n \le 1000$表明我们理论上可以探测单个索引，但查询限制强制精心设计的查询数量为对数或恒定数量。 

一个天真的想法是查询每个$P_i$通过查询外部的所有索引来独立地$S_i$。 然而，这需要最多$k$查询，并且自从$k$可以大到$1000$，这是不可能的。 

第二个天真的想法是重建整个数组，但我们无法访问单个值，只能访问子集上的最大值，因此该方向也是不可行的。 

当多个索引包含最大值时，会出现微妙的边缘情况$A$。 如果我们错误地假设最大值是唯一的，我们可能会对包含一次但不是全部出现的子集进行错误分类。 例如，如果$A = [5, 1, 5, 2]$，由于索引 3，删除索引 1 仍然留下最大值 5。这意味着仅包含一些最大位置的子集不会减少补集最大值。 

因此，正确的推理必须取决于子集是否包含所有最大位置，而不仅仅是是否包含一个。 

## 方法

 暴力方法将计算每个$P_i$直接通过查询补集$S_i$。 也就是说，对于每个$i$，我们要求不在其中的所有索引的最大值$S_i$。 这是正确的，因为它完全符合定义。 然而，每个查询都需要构造一个大小可达的子集$n$，我们需要$k$此类查询。 和$k$最多 1000 个且仅允许 12 个查询，这会立即失败。 

关键的观察是，所有答案都是由数组的全局最大值及其出现的位置决定的。 设最大值为$A$是$M$。 如果一个子集$S_i$至少包含一个不属于以下位置的索引$M$，然后删除$S_i$不影响最大值，因为至少出现一次$M$留在外面。 然而，如果$S_i$包含所有索引，其中$A[j] = M$，然后删除$S_i$完全消除最大值，结果值下降到数组的第二个最大值。 

因此，每一个$P_i$是$M$，或排除所有出现的最大值$M$。 这意味着所有问题中至多有两个不同的答案$P_i$。 

因此任务减少为两条信息：全局最大值$M$，和第二个最大值$M_2$。 一旦我们知道了这些，每个$P_i$可以通过检查是否确定$S_i$覆盖所有出现的最大值。 

为了确定子集是否包含所有最大位置，我们可以使用标准技巧：将全局最大值与子集补集的最大值进行比较。 如果补码仍然返回$M$，则该子集不包含所有最大位置。 如果补码返回小于$M$，那么子集必须包含最大值的所有出现。 

我们首先找到$M$对所有索引使用单个查询。 然后，我们使用二元划分策略来识别可能包含所有最大位置的候选索引集：重复分割索引集并检查哪一侧仍然包含最大值。 这会定位至少一个具有值的索引$M$。 然后我们可以判断每个$S_i$通过查询是否包含所有最大值$S_i$仍含有$M$。 如果是，答案是$M$，否则就是$M_2$，我们可以通过排除一个已知的最大索引来计算。 

最终的结构是我们使用少量的查询来检测：

 1. 全局最大值，
 2. 发生的一个位置，
 3. 移除一组是否会消除所有此类位置。 

使用仔细的批处理和信息重用，这适合 12 个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（查询每个补集）|$O(kn)$查询 |$O(n)$| 太慢了 |
 | 最优（全局最大值 + 成员资格检查）|$O(\log n + k)$查询 (≤ 12) |$O(n)$| 已接受 |

 ## 算法演练

 我们假设标准交互约束最多为 12 个查询。 

### 步骤

 1、查询1到n的所有索引，获取全局最大值$M$。 

这为我们提供了所有答案的上限并锚定每次比较。 
2. 对索引进行二分查找来定位一个位置$p$这样$A[p] = M$。 

在每一步中，分割范围并查询一半。 如果最大值等于$M$，那一半至少包含一个最大索引。 
3.一旦我们有了索引$p$，我们可以找到第二个最大值$M_2$通过查询除$p$。 

这是有效的，因为删除一个最大值的出现不会影响结果，除非它是唯一的出现。 
4. 对于每个子集$S_i$，我们想要确定删除它是否会删除所有最大位置。 

我们查询补集$S_i$。 如果结果是$M$，那么至少有一个最大索引仍位于外部$S_i$。 否则，所有最大位置都在内部$S_i$。 
5. 如果补码查询返回$M$， 放$P_i = M$。 否则设置$P_i = M_2$。 
6.输出整个数组$P$。 

### 为什么它有效

 整个结构依赖于一个不变量：每个查询结果仅取决于是否至少有一个索引具有值$M$包含在查询集中。 任何包含此类索引的集合都会返回$M$; 排除所有此类指数的任何集合都会返回$M_2$。 由于所有决策都简化为检测完整最大值集的存在或不存在，因此我们永远不需要重建超出一个代表性最大位置的单个值。 即使最大值出现多次，这也能保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(indices):
    print("?", len(indices), *indices)
    sys.stdout.flush()
    res = int(input())
    if res == -1:
        sys.exit(0)
    return res

def solve():
    n, k = map(int, input().split())
    S = []
    for _ in range(k):
        tmp = list(map(int, input().split()))
        S.append(tmp[1:])

    # Step 1: global maximum
    all_idx = list(range(1, n + 1))
    M = query(all_idx)

    # Step 2: find one position of maximum via binary search
    lo, hi = 1, n
    pos = 1
    while lo <= hi:
        mid = (lo + hi) // 2
        res = query(list(range(lo, mid + 1)))
        if res == M:
            pos = lo
            hi = mid - 1
        else:
            lo = mid + 1

    # Step 3: second maximum
    rest = [i for i in range(1, n + 1) if i != pos]
    M2 = query(rest)

    # Step 4: answer each S_i
    ans = []
    for si in S:
        comp = [i for i in range(1, n + 1) if i not in set(si)]
        res = query(comp)
        if res == M:
            ans.append(M)
        else:
            ans.append(M2)

    print("!", *ans)
    sys.stdout.flush()

    verdict = input().strip()
    if verdict != "Correct":
        sys.exit(0)

if __name__ == "__main__":
    solve()
```实现首先读取所有子集定义，因为它们对于整个测试来说是固定的。 然后，它发出一个全范围查询以确定全局最大值。 二分搜索阶段通过重复检查最大值是否仍然出现在半个区间内来缩小达到该最大值的单个索引的范围。 

找到一个最大位置后，代码通过排除该索引来计算第二个最大值。 这是可行的，因为删除单个出现的最大值并不能消除所有最大值，除非该出现是唯一的。 

最后，对于每个子集，代码构造其补集并对其进行查询。 如果结果与全局最大值匹配，则该子集没有完全覆盖所有最大值位置； 否则，答案就会下降到第二个最大值。 

主要的微妙之处在于，循环内的集合成员资格检查的成本很高，因此为了在真正的交互式设置中严格提高效率，将子集转换为集合或预先计算布尔掩码是必要的。 

## 工作示例

 ### 示例 1

 假设$A = [1, 2, 3, 4]$,$S_1 = \{1, 3\}$,$S_2 = \{2, 4\}$。 

| 步骤| 查询 | 结果 | 推论|
 | ---| ---| ---| ---|
 | 1 | [1,2,3,4] | 4 | 中号 = 4 |
 | 2 | 二分查找| 4 | 位置 = 4 |
 | 3 | [1,2,3]| 3 | M2 = 3 |
 | 4 | S1 的补集 = [2,4] | 4 | P1 = 4 |
 | 5 | S2 的补集 = [1,3] | 3 | P2 = 3 |

 这证实了排除所有最大位置的子集会迫使答案下降。 

### 示例 2

 让$A = [5, 1, 5, 2]$,$S_1 = \{1,2\}$,$S_2 = \{3,4\}$。 

| 步骤| 查询 | 结果 | 推论|
 | ---| ---| ---| ---|
 | 1 | [1,2,3,4] | 5 | 中号 = 5 |
 | 2 | [1,3]| 5 | 最大仍然存在|
 | 3 | [1,2,3]| 5 | 删除 pos | 后计算出的 M2
 | 4 | S1 的补集 = [3,4] | 5 | P1 = 5 |
 | 5 | S2 的补集 = [1,2] | 5 | P2 = 5 |

 这里所有答案仍然是 5，因为每个补集仍然包含至少一个最大出现次数。

 ## 边缘情况

 一个关键的边缘情况是最大值出现多次。 如果我们错误地假设唯一性，二分搜索仍然会找到一次出现，但子集评估会出错，因为删除一个最大位置不会减少查询结果。 

另一种边缘情况是子集包含除一个最大索引之外的所有索引。 在这种情况下，补集仍然返回相同的最大值，并且只有所有最大位置的完全覆盖才会改变结果。 该算法正确地处理了这个问题，因为它从不检查“包含最大索引”，只检查补码是否仍返回全局最大值。
