 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，必须准确选择`x`其中的元素。 所选元素可以来自数组中的任何位置。 问题是是否存在精确的选择`x`和为奇数的元素。 

这些数字的实际值除了其奇偶性外并不重要。 每个整数要么是奇数，要么是偶数，和的奇偶校验仅取决于包含多少个奇数。 当且仅当它包含奇数个奇数元素时，和才是奇数。 

限制很小。 每个测试用例最多包含1000个数字，测试用例最多有100个。 甚至一个`O(n²)`解决方案是可以接受的，但奇偶观察允许更简单的线性解决方案。 不需要动态编程或子集枚举。 

一些边缘情况很容易被忽略。 

考虑一个仅包含偶数的数组：```
1
4 3
2 4 6 8
```正确答案是`No`。 任何偶数之和仍为偶数。 一个粗心的解决方案，只检查是否`x`很奇怪会在这里失败。 

考虑一个仅包含奇数的数组：```
1
4 2
1 3 5 7
```正确答案是`No`。 选择两个奇数会产生偶数和。 一些实现错误地假设奇数可用总是足够的。 

考虑我们必须获取所有元素的情况：```
1
3 3
1 2 3
```总和是`6`，它是偶数，所以答案是`No`。 什么时候`x = n`，只有一种可能的选择。 

当有足够的奇数使总和为奇数，但没有足够的总元素以有效奇偶校验填充剩余槽时，会发生另一种微妙的情况：```
1
3 3
1 2 2
```我们必须掌握所有三个要素。 总和是`5`，所以答案是`Yes`。 可行性取决于奇数元素的数量和精确选择的要求`x`元素。 

## 方法

 暴力方法将枚举大小的所有子集`x`并检查其中是否有奇数之和。 这是正确的，因为它检查了每一个可能的选择。 问题在于此类子集的数量。 在最坏的情况下，我们需要检查$$\binom{1000}{500}$$不同的选择，这是一个天文数字，在时间限制内是完全不可能的。 

关键的观察是只有平等才重要。 让`odd`是数组中奇数元素的数量并且`even`是偶数元素的数量。 

当所选奇数元素的数量为奇数时，所选和恰好为奇数。 假设我们选择`k`奇数元素。 然后：$$k + \text{chosen even elements} = x$$由于剩余的选定元素必须是偶数元素，因此我们需要：$$x - k \le even$$还有$$k \le odd$$价值`k`必须是奇数，因为最终的总和必须是奇数。 

问题变成：是否存在奇数`k`这样：$$1 \le k \le odd$$和$$x-k \le even$$和$$k \le x$$最多有`x`的可能值`k`，因此检查所有奇数值很简单。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n,x)) | O(C(n,x)) | O(x) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算数组中有多少个元素是奇数，有多少个元素是偶数。 
2.尝试每一个奇数`k`从`1`最多`min(odd, x)`。 
3. 治疗`k`作为我们要选择的奇数元素的数量。 自从`k`是奇数，任何有效的选择都使用精确的`k`奇数元素将有奇数和。 
4. 计算`need_even = x - k`。 这些是必须用偶数元素填充的剩余位置。 
5. 检查是否`need_even`是非负的并且是否`need_even <= even`。 如果这两个条件都成立，我们可以建立一个精确的选择`x`元素。 
6.如有异常`k`满足条件，打印`Yes`。 
7. 如果没有候选人工作，则打印`No`。 

### 为什么它有效

 和的奇偶性仅取决于所包含的奇数的数量。 当计数为奇数时，总和就是奇数。 

该算法检查每个可能的奇数计数`k`可能会出现在有效的选择中。 对于每一个这样的`k`，它验证是否存在足够的奇数元素来提供这些`k`存在数字和足够的偶数元素来填充剩余的`x-k`职位。 

如果算法找到一个可行的`k`，可以直接根据这些计数构建实际选择。 如果每一个奇数`k`失败，则没有选择可以同时具有所需的大小和奇数奇偶校验。 由于每个有效的解决方案都必须对应于某个奇数`k`，算法完整，不会漏掉任何一个解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        odd = sum(v % 2 for v in a)
        even = n - odd

        possible = False

        for k in range(1, min(odd, x) + 1, 2):
            need_even = x - k
            if need_even <= even:
                possible = True
                break

        ans.append("Yes" if possible else "No")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```解决方案的第一部分计算奇数和偶数元素。 关于价值观的其他事情都不重要。 

循环结束`k`检查所选奇数的每个可能的奇数。 步长为`2`，这保证了每个候选人`k`很奇怪。 

条件`need_even <= even`验证是否存在足够的偶数来完成选择。 我们不需要单独检查`need_even >= 0`因为循环只考虑`k <= x`。 

一旦找到一种可行的配置，答案就是`Yes`，因此循环提前终止。 

对于大值不需要特殊处理，因为只操作计数。 Python 中不可能出现整数溢出，并且计数永远不会超过 1000。

 ## 边缘情况

 ### 所有元素都是偶数

 输入：```
1
4 3
2 4 6 8
```算法算数`odd = 0`和`even = 4`。 由于不存在奇数值`k`尝试一下，循环永远找不到有效的配置。 输出是`No`。 

这符合数学事实：任何偶数之和都是偶数。 

### 所有元素都是奇数，选择大小是偶数

 输入：```
1
4 2
1 3 5 7
```算法算数`odd = 4`和`even = 0`。 

它尝试`k = 1`，它需要一个偶数元素，但不存在。 

没有更大的奇数`k`是允许的，因为`k > x`。 

输出是`No`。 

每次选择恰好两个奇数时，总和为偶数，因此结果是正确的。 

### 必须选择每个元素

 输入：```
1
3 3
1 2 3
```算法算数`odd = 2`和`even = 1`。 

尝试`k = 1`需要两个偶数元素，但只有一个存在。 

不可能有其他奇数。 

输出是`No`。 

由于必须选择所有三个元素，它们的总和为`6`，偶数，不存在有效选择。

```算法算数`odd = 1`和`even = 4`。
