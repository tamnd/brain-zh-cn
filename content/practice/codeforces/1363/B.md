 ## 解决方案

 ## 问题理解

 我们得到一个二进制字符串，并允许翻转任何字符任意次数。 每次翻转都会将一位从 0 更改为 1 或从 1 更改为 0。目标是转换字符串，使其变得“好”，这意味着如果我们尝试按升序选择三个索引，则永远无法形成子序列 0, 1, 0 或子序列 1, 0, 1。 

重要的细节是这里的子序列不需要邻接。 角色按顺序出现就足够了，即使它们相距很远。 所以条件是全局的，而不是局部的。 我们不仅避免将 010 这样的模式作为子字符串，而且还避免将其作为字符串中任何位置的子序列。 

长度限制很小，每个字符串最多 1000 个，最多 100 个测试用例。 这立即排除了对每个测试用例进行二次或更糟的重度优化的需要，但也表明每个字符串的 O(n) 或 O(n log n) 解决方案很容易就足够了。 即使 O(n^2) 也可能通过，但条件的结构表明我们不需要它。 

即使字符不相邻也可以形成子序列模式，这一事实引起了微妙的边缘情况。 例如，在像 1001 这样的字符串中，不存在子字符串 101，但存在子序列 1（第一个字符）、0（第二个）、1（最后一个）。 仅检查子字符串或本地模式的简单方法在这里会失败。 另一个陷阱是认为删除所有交替就足够了，因为即使不相邻的交替仍然可以形成禁止的子序列。 

核心困难在于，翻转一个字符会影响全局的许多潜在子序列，而不仅仅是局部结构，因此我们需要对“好”字符串的外观进行全局表征。 

## 方法

 我们首先询问什么样的二进制字符串不能包含 010 或 101 作为子序列。 考虑它的一种蛮力方法是尝试所有可能的翻转集，生成所有可到达的字符串，并测试每个字符串是否有禁止的子序列。 检查字符串是否为 010 或 101 作为子序列可以在 O(n) 内完成，并且存在 2^n 种可能的翻转配置，因此即使对于 n = 1000，这种方法也是完全不可行的。 

相反，我们尝试了解是什么结构属性阻止了这两种模式。 如果一个字符串同时包含 0 和 1，并且它们以灵活的方式交错，则可以选择一个 0，然后是 1，然后是另一个 0，反之亦然。 关键的观察结果是，任何具有 0 和 1 之间多次转换的“混合”结构都会为这些交替子序列创造空间。 

考虑它的一个有用方法是考虑最终的字符串。 如果它是好的，则它不能同时具有模式 010 和 101 作为子序列。 这迫使字符串变成一种非常受限制的形状：它最多只能有一个 0 和 1 之间的“转换”。否则，多个不同位的块将允许构造交替的子序列。 

因此，任何好的字符串都必须采用全 0 后跟全 1 的形式，或者全 1 后跟全 0 的形式，或者完全统一的形式。 这些正是符号之间最多有一个边界的单调二进制串。 

这将问题简化为一个简单的转换任务：给定原始字符串，我们希望以最少的翻转将其转换为 000…0111…1 或 111…1000…0。 现在，对所有分割点的暴力破解很容易：对于每个位置，计算需要翻转多少次才能使左边的所有内容等于一个值，右边的所有内容等于另一个值，并在两个方向上取最小值。 

这将问题从推理子序列减少到使用前缀计数的线性扫描。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（尝试所有翻转子集）| O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最佳（尝试拆分+前缀计数）| 每个字符串 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将构建 0 和 1 的前缀计数来快速评估任何分割。 

1. 对于每个测试用例，计算前缀数组，我们可以在其中查询字符串的任何前缀中出现了多少个零和一。 这允许对任何段进行恒定的时间计数。 
2. 考虑将最终字符串设为 000…0111…1 的形式。 对于每个可能的分割位置 i，我们假设位置 [0, i) 变为全 0，位置 [i, n) 变为全 1。 
3. 对于固定分割 i，计算成本为左侧部分中 1 的数量（它们必须翻转为 0）加上右侧部分中 0 的数量（它们必须翻转为 1）。 这直接计算与目标结构的不匹配。 
4. 对反转模式 111…1000…0 重复相同的过程，其中左侧变为全 1，右侧变为全 0。成本为左侧的 0 加上右侧的 1。 
5. 对所有分割和两种模式取最小成本。 这就是测试用例的答案。 

我们可以将自己限制为单个拆分结构的关键原因是任何有效的最终字符串都不能有两个单独的替换。 如果确实如此，它将立即允许通过从每个区域选择代表来构建 010 或 101 作为子序列。 因此，所有有效字符串都会折叠成这个简单的两块形式。 

### 为什么它有效

 任何在 0 和 1 之间具有多个转换的字符串都必然包含模式 010 和 101 作为子序列，因为我们总是可以从交替的段中选取字符。 因此，每个有效目标必须最多有一次转换。 我们的算法通过尝试所有分割点和两个可能的方向来隐式枚举所有此类有效目标。 由于我们计算到每个候选结构的精确汉明距离（所需的翻转次数），因此所有候选结构的最小值就是最佳操作数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    n = len(s)

    pref0 = [0] * (n + 1)
    pref1 = [0] * (n + 1)

    for i, ch in enumerate(s):
        pref0[i + 1] = pref0[i] + (ch == '0')
        pref1[i + 1] = pref1[i] + (ch == '1')

    ans = n

    for i in range(n + 1):
        left_ones = pref1[i]
        right_zeros = pref0[n] - pref0[i]
        cost01 = left_ones + right_zeros

        left_zeros = pref0[i]
        right_ones = pref1[n] - pref1[i]
        cost10 = left_zeros + right_ones

        ans = min(ans, cost01, cost10)

    print(ans)
```该实现依赖于前缀和来计算 O(1) 内的段计数。 分割点上的循环确保我们考虑单个允许转换的每个可能位置。 这两个成本公式完全对应于翻转每一半中不匹配的位。 不会出现差一问题，因为分割被定义为前缀边界 [0, i) 和后缀 [i, n)。

def run(inp: str) -> str:

        s = input().strip()

 ## 边缘情况

 对于像这样的字符串`010`，该算法考虑所有分割。 在分割 i = 1 时，000→111 的成本为 1（翻转中间），111→000 的成本也是 1，给出答案 1。这符合直觉，即一次翻转足以消​​除交替结构。 

对于像这样的字符串`111000`，最佳分割位于块之间的边界处，成本为 0。前缀和正确反映了与正确方向对齐时不存在不匹配，从而确认该算法无需特殊处理即可自然检测到已经好的字符串。
