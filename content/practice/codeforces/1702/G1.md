 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一棵树和几个查询。 每个查询指定一组顶点。 对于每个查询，我们必须确定所有选定的顶点是否可以位于树的单个简单路径上。 

一棵树只包含任意两个顶点之间的一条简单路径。 如果存在一些简单路径，使得每个查询的顶点都属于该路径，则认为查询是可以通过的。 该路径允许包含不属于查询的其他顶点。 

该树最多包含$2 \cdot 10^5$顶点，而所有查询中查询的顶点总数也最多为$2 \cdot 10^5$。 这立即排除了任何重复遍历每对查询顶点的整个路径的方法。 一个$O(n)$每个查询顶点的操作已经变得太昂贵了。 我们需要对树进行预处理，然后对每个查询的大小进行近线性处理。 

有几种情况很容易被误解。 

考虑一棵星形树：```
    2
    |
3 - 1 - 4
    |
    5
```询问：```
{2,3,4}
```答案是`NO`。 

每对查询的顶点之间都有一条路径，但不存在包含所有三个叶子的单一简单路径。 两片叶子之间的任何路径都会穿过中心并仅到达那两片叶子。 

另一个例子：```
1 - 2 - 3 - 4 - 5
```询问：```
{2,4}
```答案是`YES`。 

路径不需要在查询的顶点处开始或结束。 从 1 到 5 的路径同时包含 2 和 4。 

一个更微妙的情况：```
    2
    |
1 - 3 - 4 - 5
```询问：```
{1,2,5}
```答案是`YES`。 

从1到5的路径经过顶点3，但不经过顶点2。包含所有查询到的顶点的实际路径是2-3-4-5，其中还包含1？ 不，所以答案实际上是`NO`。 这说明了为什么仅检查成对距离或成对连通性是不够的。 我们需要验证每个查询的顶点都属于一条公共路径。 

## 方法

 一个蛮力的想法是尝试将所有查询的顶点对作为所需路径的可能端点。 对于每一对，构建它们的路径并检查每个查询的顶点是否位于其上。 

在树中，有一个顶点$x$位于之间的路径上$a$和$b$恰好在什么时候$$dist(a,x)+dist(x,b)=dist(a,b).$$因此我们可以测试每个端点对并验证所有查询的顶点。 

这是正确的，但太慢了。 如果查询包含$k$顶点，有$O(k^2)$端点对，每对都需要检查$k$顶点。 那就变成了$O(k^3)$。 和$k$达到$2 \cdot 10^5$，这是没有希望的。 

关键的观察来自于树木的几何形状。 

假设所有查询的顶点都位于一条简单路径上。 那么在这些顶点中必须有两个顶点是该路径的端点。 每个其他查询的顶点都位于连接这两个极端的唯一路径上。 

因此，我们不需要尝试所有端点对，而只需要找到一个可能是极端的候选对。 

一个标准的树技巧是，如果我们选择任何查询的顶点$s$，那么距离最远的查询顶点$s$是查询集的直径的一个端点。 如果我们从该端点开始并再次找到最远的查询顶点，我们就获得了另一个端点。 

称这些顶点为$a$和$b$。 

如果查询的顶点确实位于一条路径上，则每个查询的顶点都必须属于该路径$a \leftrightarrow b$。 相反，如果每个查询的顶点都属于该路径，则该集合是可以通过的。 

剩下的任务是有效的距离计算。 我们使用 DFS 和二元提升对树进行预处理。 然后每个距离查询都可以在$O(\log n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(k^3)$每个查询|$O(1)$| 太慢了|
 | 最佳 |$O(n\log n + k\log n)$总计 |$O(n\log n)$| 已接受 |

 ## 算法演练

 ### 预处理

 构建树并从根运行 DFS。 

存储每个顶点及其二进制提升祖先的深度。 这允许最低公共祖先查询$O(\log n)$。 

使用 LCA，将距离计算为：$$dist(u,v)=depth[u]+depth[v]-2\cdot depth[lca(u,v)].$$### 查询处理

 1、以任意查询到的顶点为起始顶点$s$。 
2. 计算距离$s$到每个查询的顶点并找到最远的顶点。 叫它$a$。 

如果查询的顶点位于路径上，则其跨度的一个端点必须距离任何选定的顶点最远。 
3. 计算距离$a$到每个查询的顶点并找到最远的顶点。 叫它$b$。 

这对$(a,b)$是查询的顶点的直径。 
4. 对于每个查询的顶点$v$，检查是否$$dist(a,v)+dist(v,b)=dist(a,b).$$5. 如果每个查询的顶点都成立，则输出`YES`。 
6.否则输出`NO`。 

### 为什么它有效

 让$a$和$b$是查询的顶点之间的直径端点。 

如果所有查询的顶点位于单个路径上，则该路径必须包含两个直径端点。 每个查询的顶点都位于它们之间，因此距离相等适用于所有顶点。 

对于相反方向，假设每个查询的顶点满足$$dist(a,v)+dist(v,b)=dist(a,b).$$在树中，这个条件恰好在以下情况下成立：$v$位于独特的道路上$a$到$b$。 因此每个查询的顶点都属于同一个简单路径$a \leftrightarrow b$。 套餐还过得去。 

该算法完全接受可通过的集合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = (n + 1).bit_length()

up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

stack = [(1, 0)]

while stack:
    v, p = stack.pop()
    up[0][v] = p

    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        stack.append((to, v))

for j in range(1, LOG):
    prev = up[j - 1]
    cur = up[j]
    for v in range(1, n + 1):
        cur[v] = prev[prev[v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a

    diff = depth[a] - depth[b]

    bit = 0
    while diff:
        if diff & 1:
            a = up[bit][a]
        diff >>= 1
        bit += 1

    if a == b:
        return a

    for j in range(LOG - 1, -1, -1):
        if up[j][a] != up[j][b]:
            a = up[j][a]
            b = up[j][b]

    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

q = int(input())

ans = []

for _ in range(q):
    k = int(input())
    nodes = list(map(int, input().split()))

    start = nodes[0]

    a = start
    best = -1

    for v in nodes:
        d = dist(start, v)
        if d > best:
            best = d
            a = v

    b = a
    best = -1

    for v in nodes:
        d = dist(a, v)
        if d > best:
            best = d
            b = v

    diameter = dist(a, b)

    ok = True

    for v in nodes:
        if dist(a, v) + dist(v, b) != diameter:
            ok = False
            break

    ans.append("YES" if ok else "NO")

sys.stdout.write("\n".join(ans))
```经过预处理后，每次距离查询只需要一次LCA计算。 对于每个查询，我们执行两次扫描以查找直径端点，并执行一次最终扫描以进行验证。 

DFS 是迭代实现的，以避免树上的 Python 递归深度问题$2 \cdot 10^5$顶点。 

一个常见的错误是假设整个树的直径端点。 我们只关心查询的顶点之间的直径。 两个最远点搜索专门针对查询中出现的顶点执行。 

另一个微妙的点是路径成员测试。 仅检查顶点是否靠近直径路径是不够的。 确切的平等$$dist(a,v)+dist(v,b)=dist(a,b)$$必须持有。

```直径端点是同一顶点。 距离为零，验证立即成功。 算法输出`YES`。

```该算法选择 2 和 4 作为直径端点。 两者都满足路径条件，所以答案是`YES`。 这证实了路径可以延伸到查询的顶点之外。
