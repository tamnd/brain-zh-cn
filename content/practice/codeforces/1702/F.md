 ## 解决方案
 ## 问题理解

 我们有两个相同大小的整数集合。 将它们视为两袋代币，其中顺序并不重要，但多样性很重要。 目标是确定我们是否可以使用独立应用于第二个包的元素的操作将第二个包转换为第一个包。 

第二个包中的每个元素可以通过两种方式重复修改：可以加倍，或者可以用其整数的一半替换。 重复这些操作可以从任何起始数字创建一组可到达的值。 任务是决定在为第二个多重集的每个元素选择一系列此类操作后，我们是否可以使两个多重集相同。 

关键的困难在于转换不是对称的并且不能以干净的方式可逆。 减半引入了舍入，这会破坏结构，而加倍会无限制地扩展值。 许多元素之间的相互作用迫使我们推理规范形式而不是显式转换。 

这些约束允许所有测试用例最多使用 200,000 个数字，值最多为 10^9。 任何尝试模拟每个值的变换或探索变换图的解决方案都会失败，因为单个数字可以通过重复加倍和减半生成一条长链，并且对所有元素独立执行此操作会导致二次或更糟糕的行为。 

天真的思维的一个微妙的失败案例是假设我们可以贪婪地匹配中的每个值`a`有一定的价值`b`并在本地修复它。 例如，如果我们尝试匹配`a = [8]`和`b = [3]`，我们可能认为 3 通过加倍可以达到 8，但我们还必须确保其他数字的剩余结构在多重集中保持一致，这会破坏贪婪匹配。 

减半会产生另一个误导性的场景：像 7 这样的数字可以变成 3，然后变成 1，但这些中间值可能会干扰匹配其他所需目标。 一个不控制值如何“吸收”的天真的贪婪分配将会陷入矛盾。 

问题本质上是关于分配每个`b`对某些目标的价值`a`通过结构化的转换空间，同时确保所有任务的一致性。 

## 方法

 如果我们专注于单个值`b`，我们可以通过反复减半直到 0 并反复加倍来探索所有可达到的值。 这形成了可能性的树状结构。 对于其中的每个元素，暴力方法将`b`，尝试将其与中的某个元素匹配`a`通过探索所有转换并标记使用的元素。 在实践中，这很快就会变成指数，因为每个数字都可以生成一个与 log（最大值）成比例的长度链，并且我们仍然需要考虑所有元素的分配，从而有效地导致这些链上的阶乘匹配。 

关键的观察结果是，变换图具有强大的结构：每个数字最终都会通过重复减半而崩溃为 0，并且每个数字在减半下都有一个独特的祖先链。 这表明，与其向前思考（从`b`到`a`），我们应该通过反复减半来标准化值，直到它们成为“稳定候选者”，然后控制重数。 

解释该过程的一个有用方法是，中的每个数字`b`可以减少到许多可能的更小的值，但是减少是单调的并且总是终止。 我们没有扩大可能性，而是反复压缩数字`b`向下直到它们匹配目标`a`或变得无效。 一旦我们引入排序，我们总是可以首先优先考虑较大的数字，因为较大的值具有较少的有效减少，但仍然可以匹配较大的目标。 

这导致了贪婪策略：对两个数组进行排序并尝试从最大到最小匹配，不断减少`b`值，直到它们匹配或变得不可用。 如果存在匹配，我们就消耗它； 否则我们就会失败。

 ## 算法演练

 1. 对两个多重集进行排序`a`和`b`按降序排列。 这确保了我们总是首先尝试满足最大的要求值，因为它们是最难用较小的数字构造的。 
2. 维护值的多集结构（概念上是频率图或计数器）`b`。 这允许在元素匹配后有效地删除它们。 
3. 迭代每个值`x`在`a`从最大到最小。 在每一步中，我们都会尝试找到一个合适的值`b`可以精确地减少到`x`。 
4. 如果最大剩余值`b`正是`x`，我们直接匹配并删除它。 
5. 否则，如果中的最大值`b`大于`x`，我们反复将其减半，直到它小于或等于`x`。 此步骤是合理的，因为减半是唯一减少幅度的操作，任何超出的值都必须减少才能匹配。 
6. 减半后，如果该值正好变为`x`，我们匹配并删除它。 如果它变得小于`x`， 这`b`元素不能贡献于`x`，所以我们丢弃它并尝试下一个候选`b`。 
7. 如果在任何时候我们找不到有效的`b`一些元素`x`，我们立即得出结论，匹配是不可能的。 

### 为什么它有效

 按降序处理可确保当我们分配`b`对大目标的价值`a[i]`，我们以后再也不需要那个`b`值以满足更大的要求。 减半过程保留了单调减少路径，这意味着每个`b`value 具有向下可达状态的确定性序列。 因为我们总是消耗最大的可用量`b`首先，我们避免出现大量元素的情况`b`过早地减少到超过另一个大所需的中间值`a`。 这种贪婪的稳定性使得匹配在整个多重集中保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort(reverse=True)
        b.sort(reverse=True)
        
        i = 0
        
        for x in a:
            if i >= n:
                break
            
            while i < n and b[i] > x:
                b[i] //= 2
                if b[i] == 0:
                    i += 1
            
            if i < n and b[i] == x:
                i += 1
            else:
                print("NO")
                break
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```该实现直接反映了贪婪过程。 对两个数组进行排序可确保我们始终首先尝试满足最大的目标。 指针`i`跟踪当前候选人`b`。 当一个值太大时，它会被反复减半，直到它匹配或变得不可用。 一旦匹配发生，我们就会消耗它并继续前进。 

一个微妙的点是我们永远不会将减少的值推回到堆或结构中。 这是安全的，因为中的每个元素`b`遵循单一的向下转型路径； 作为一个新的候选人重新审视它是没有必要的。 单调指针确保线性处理。

 ## 边缘情况

 一个关键的边缘情况是当多个大值`b`必须小心地减少而不破坏中间匹配。 例如，如果`a = [8, 8]`和`b = [1, 16]`，天真的贪婪可能会减少`16`在意识到它可以产生一个之前错误地`8`，但适当的降序处理可确保`16 → 8`首先被消耗掉，留下`1`无关紧要。 

另一种情况是重复减半会跳过有效值。 为了`a = [3]`和`b = [7]`，我们有`7 → 3 → 1`。 如果我们早点停在`1`或者中间处理不当`3`，我们可能会错误地拒绝有效的匹配。 该算法通过不断减半直到准确地通过或击中目标来避免这种情况，确保不会跳过任何有效的中间部分。
