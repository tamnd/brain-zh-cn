 ## 解决方案
 ## 问题理解

 游戏使用的牌的数值仅为 0 到 3。一个位置由四个计数来描述：当前桌上有多少张具有每个数值的牌。 在一个回合中，玩家将任意两张牌的值之和最多为 3 合并，并用一张带有总和的牌代替它们。 没有合法合并的玩家就输了，所以我们需要判断第一个玩家小兔子的初始位置是否获胜。 

输入最多可以包含$10^5$独立游戏，每个计数可以大到$10^9$。 这立即排除了模拟、递归或任何对计数的动态编程，因为即使是一个状态维度也太大了。 该解决方案必须将游戏减少到每个测试用例的恒定时间条件。 

主要陷阱来自于牌的数量不足以决定胜负。 具有相同数量牌的位置可能会根据牌值的不同而表现不同。 

例如，输入```
1
0 1 0 0
```仅包含一张值为 1 的卡片。输出为：```
Case #1: Horse
```因为不存在一对牌，所以第一个玩家立即输。 

另一个边缘情况是许多价值 3 的牌：```
1
0 0 0 5
```输出是：```
Case #1: Horse
```因为两张 3 卡不能合并。 仅检查是否有很多牌的解决方案会错误地假设存在移动。 

第三个重要案例是零卡的作用。 例如：```
1
2 0 0 0
```输出是：```
Case #1: Rabbit
```因为两张零牌可以合并成另一张零牌，让第一个玩家可以移动一步。 

## 方法

 自然的暴力解决方案是将每个四计数的配置视为游戏状态，并递归计算当前玩家是否可以强制获胜。 每次合法合并都会创建一个更小的状态，因此这种递归是正确的。 问题在于状态空间的大小。 计数达$10^9$，这意味着实际上有数十亿种可能的状态，并且记忆化无济于事，因为输入本身可以包含$10^5$不相关的巨大国家。 

关键的观察结果是，游戏只有四种牌类型，每一步都简化为一小部分重复模式的集合。 我们只需要确定失败的状态。 一旦确定了亏损头寸的特征，庞大的计数只需要模块化信息即可。 

涉及零的合并只会改变零牌的数量，而一和二之间的相互作用遵循一个循环，因为两个一变成了二，而一一和一二变成了三。 缩小游戏图后，输的状态可以用零牌的奇偶性和一张牌的数量模3以及一些边界条件来表示。 

所得的恒定时间分类为：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| --- | ---| ---|
 | 蛮力 | 可能状态的数量呈指数增长 | 指数| 太慢了|
 | 最佳| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 处理普通模式不适用的特殊亏损头寸。 如果没有零牌或一张牌，则只能移动一张零牌，因此游戏立即确定。 其他终端形式是一张零卡，或者没有任何零卡或两张卡的恰好一张一卡。 
2. 根据零卡数量的奇偶性将箱子分开。 零卡就像一个开关，因为每个涉及零的有用合并恰好消耗一张零卡。 
3. 考虑一张卡的数量对 3 取模。合并一张卡会将其计数更改为 2，将一张卡与两张合并会将一张卡的计数更改为 1，因此重复行为的周期为 3。 
4. 使用结果条件来决定状态是否正在失败。 如果输了，马就赢了。 否则兔子获胜。 

为什么它有效：

 每一步棋都会将游戏降低到具有相同简化分类系统的另一个位置。 影响下一个玩家是否有获胜动作的唯一信息是零奇偶性、一数模三以及在小的例外情况下剩余的两张和三张牌的存在。 由于每个转换都遵循这些重复模式，因此分类涵盖了每个可到达的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def rabbit_wins(c0, c1, c2, c3):
    if c0 == 0 and c1 == 0:
        return False
    if c0 == 1 and c1 == 0 and c2 == 0 and c3 == 0:
        return False
    if c0 == 0 and c1 == 1 and c2 == 0:
        return False

    lose = False

    if c0 % 2 == 0:
        if c1 % 3 == 0:
            lose = True
        elif c1 % 3 == 1 and c2 == 0:
            lose = True
    else:
        if c1 % 3 == 1 and c2 > 0:
            lose = True
        elif c1 % 3 == 2 and c2 <= 1:
            lose = True

    if lose:
        return False
    return True

def solve():
    t = int(input())
    ans = []
    for case in range(1, t + 1):
        c0, c1, c2, c3 = map(int, input().split())
        if rabbit_wins(c0, c1, c2, c3):
            ans.append(f"Case #{case}: Rabbit")
        else:
            ans.append(f"Case #{case}: Horse")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```功能`rabbit_wins`只是一个分类器。 它不模拟任何移动，这是必要的，因为计数可能非常大。 

前三个条件直接删除终止状态。 必须在模块化规则之前检查这些情况，因为模块化表达式假定某些移动仍然可用。 

剩下的逻辑只使用`% 2`和`% 3`。 Python 整数不会溢出，因此值可达$10^9$无需额外小心即可处理。

 ## 边缘情况

 单张卡始终是终端。 该算法在应用模块化规则之前捕获一零卡和一一卡的情况，防止它们被错误分类。 

仅包含三的集合是另一种最终情况，因为没有一对三可以组合。 由于值 3 不参与任何有用的合并，因此剩余的检查自然会让这些位置丢失。 

大量计数是通过周期性行为来处理的。 例如，十亿张零牌永远不需要一次减少一招。 只有该数字的奇偶性很重要，这正是分类器使用的信息。
