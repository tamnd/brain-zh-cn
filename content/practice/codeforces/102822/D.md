 ## 解决方案
 # 问题理解

 该问题描述了一系列炸弹，其中每个炸弹都有一个倒计时值。 在一次行动中，我们可以选择一颗炸弹并将其时钟增加一。 紧接着，每颗炸弹的时钟都会丢失一个。 如果在此减少之后任何时钟变为负值，则该过程结束。 目标是在爆炸发生之前最大限度地增加选择动作的数量。 

输入包含多个测试用例。 每个测试用例都会给出炸弹的数量以及每个炸弹的初始时钟值。 输出是我们可以选择炸弹的最大次数，格式为案例答案。 

炸弹数量可达$10^5$，所有测试用例的炸弹总数最多为$3 \times 10^5$。 尝试所有可能的选择序列的解决方案是不可能的，因为可能的序列数量呈指数增长。 即使尝试在每个时刻找到最佳选择的模拟也会太慢，因为当时钟值很大时，答案可能会非常大。 时钟的值可以达到$10^9$，因此算法必须取决于炸弹的数量而不是答案的大小。 

棘手的部分是，即使最后一个动作可能立即导致爆炸，也要计算在内。 一个常见的错误是只计算已完成的安全回合。 

例如：```
1
2
1 1
```正确的输出是：```
Case #1: 3
```粗心的模拟可能会说 2，因为在两轮完整的回合后，两颗炸弹都空了。 不过，还有时间再进行一次选择动作，只有在接下来的减少之后才会发生爆炸。 

另一个边缘情况是一些炸弹从零开始：```
1
3
0 5 5
```第一个炸弹无法在一轮中幸存，除非每次都选择它。 仅考虑时钟总数的解决方案可能会忽略单个炸弹需要足够的保护。 

## 方法

 直接的方法是尝试模拟该过程并决定每次增加哪种炸弹。 由于选择炸弹可以保护其免受该回合的减少，因此自然贪婪的想法是始终选择当前值最小的炸弹。 这可以适用于小情况，但它并不能揭示问题的实际结构。 答案可能与所有时钟的总和一样大，从而使模拟速度太慢。 

关键的观察来自于固定数量的安全回合而不是个人选择。 

假设我们想生存$x$完成回合。 炸弹$i$如果没有被选择，则每轮都会输掉一个。 如果选择的话$c_i$次，这些之后的最终值$x$回合数为：$$a_i - (x - c_i)$$为了让炸弹保持活力，我们需要：$$c_i \geq x-a_i$$如果$x-a_i$为负数，炸弹不需要任何特殊保护，所以真正的要求是：$$c_i \geq \max(0, x-a_i)$$可用选项总数$x$轮数正是$x$。 因此，$x$如果满足以下条件，则可以进行安全回合：$$\sum_i \max(0, x-a_i) \leq x$$这个条件是单调的。 如果我们能活下来$x$回合，那么我们可以生存更少的回合。 如果我们无法生存$x$轮，更大的值是不可能的。 这允许二分搜索。 

我们需要的答案是比完整安全回合的最大数量多一，因为在爆炸发生之前仍然会计算下一个选择动作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(答案 × n) | O(n) | 太慢了|
 | 轮次二分查找 | O(n log(sum(a))) | O(n log(sum(a))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算所有初始炸弹时钟的总和。 这给出了我们需要考虑的完整轮数的上限，因为每一轮都会减少时钟值的总量$n-1$，而二分查找只需要一个安全上限。 
2.二分查找最大完整安全轮数$x$。 对于候选人$x$，计算弱炸弹迫使多少种选择。 炸弹$i$需要$\max(0, x-a_i)$选择。 
3. 如果所需选项总数最多为$x$，将此值标记为尽可能，并搜索更大的轮数。 否则，搜索较小的值。 
4. 找到最大可能的完整轮数后$x$， 输出$x+1$。 多出来的一个代表的是后面导致爆炸的最终选择动作。 

为什么它有效：

 二分搜索条件准确地描述了可用的选择是否可以使每个炸弹都存活。 任何时钟太小的炸弹都需要经常被选择，以补偿其收到的时钟减少。 这些最低要求的总和就是所需的最少选择数。 如果这适合在$x$可用轮数，存在有效的时间表。 由于条件是单调的，二分查找找到最大可能的$x$，并添加 1 作为最终计数的动作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(a):
    total = sum(a)

    def possible(x):
        need = 0
        for v in a:
            if x > v:
                need += x - v
                if need > x:
                    return False
        return True

    lo, hi = 0, total + 1
    while lo + 1 < hi:
        mid = (lo + hi) // 2
        if possible(mid):
            lo = mid
        else:
            hi = mid

    return lo + 1

def main():
    t = int(input())
    ans = []

    for case in range(1, t + 1):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append(f"Case #{case}: {solve_case(a)}")

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```这`possible`函数检查上面导出的数学条件。 它只计算炸弹需要的额外选择，因为炸弹至少具有价值`x`能够生存`x`无需保护即可进行回合。 

二分查找使用半开上限。`total + 1`是安全的，因为完整回合的答案永远不会超过所有时钟的总和。 最终答案加一，因为问题要求的是选择动作的数量，而不是完全完成的回合数。 

提早返回室内`possible`避免不必要的工作。 一旦所需的选择超过了可用的轮次，候选值就已经不可能了。

这些痕迹表明了为什么该解决方案不需要决定选择炸弹的确切顺序。 不等式仅询问是否存在某种选择分布。

 ## 边缘情况

 对于这个案例：```
1
2
1 1
```二分查找检查完整的轮次。 两轮比赛是可能的，因为每个炸弹只能选择一次。 三轮是不可能的，因为每颗炸弹都需要两种保护，需要四种选择。 算法返回`2 + 1 = 3`，正确计算导致爆炸的最终动作。 

对于这个案例：```
1
3
0 5 5
```第一颗炸弹从零开始。 为了生存完整一轮，必须选择它，否则它会变成负值。 条件要求：$$\max(0,1-0)+\max(0,1-5)+\max(0,1-5)=1$$有一个选择，所以一轮是可能的。 对于较大的值，所需的保护最终会超出可用的选择，并且二分搜索会在正确的点停止。 

对于这个案例：```
1
3
0 0 0
```每颗炸弹都需要被选择，否则就会失去价值。 完成零轮后，仍然可能有一个最终选择动作，因此答案为 1。算法会处理此问题，因为最终的选择动作是`+1`与安全轮计算分开。
