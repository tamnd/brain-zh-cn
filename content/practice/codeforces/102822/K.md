 ## 问题理解

 问题给出了一个数`x`并要求一个整数集合，其总和恰好为`x`。 每个选定的整数必须大于 1，必须至少有两个整数，并且集合中的每对整数必须互质。 在所有有效集合中，我们需要最小化最大和最小选择值之间的差异。 

输入最多包含`10^5`的独立值`x`，每个都大到`10^9`。 这排除了搜索可能的集合，甚至排除了对每个测试用例进行昂贵的因式分解。 预期的解决方案必须使用直接的数学特征并在恒定时间内回答每个查询。 

棘手的部分是，最好的答案不是通过简单的分裂得到的`x`分成两个接近的数字。 两个接近的数字仍然可以共享一个因子。 例如，对于`x = 6`, 分裂`{3, 3}`具有最小的可能范围，但无效，因为相等的数字不是互质的。 正确的输出是`-1`。 

另一种边界情况是奇值。 为了`x = 5`, 集合`{2, 3}`有效且有范围`1`，所以答案是`1`。 只搜索偶数分割的粗心实现会错过这一点。 

第三个重要的情况是当`x`能被四整除。 为了`x = 8`, 集合`{3, 5}`作品。 区别在于`2`， 不是`1`，因为两个连续整数的和将为奇数。 缺少两个相隔的数字之间的互质条件可能会导致错误的答案。 

## 方法

 强力解决方案将尝试可能的最小元素并围绕它们构建候选集。 对于每个可能的范围，它将枚举该区间的子集并检查总和是否为`x`以及是否所有对都是互质的。 这是正确的，因为它检查了每个可能的候选答案，但在这里这是不可能的。 区间和子集的数量远远超出了`10^5`测试用例可以处理。 

有用的观察是只有非常小的范围才能达到最佳。 一系列`1`当我们可以使用两个连续的数字时，这就是可能的。 它们的和是奇数，所以每个奇数`x`有答案`1`。 

对于甚至`x`， 范围`1`无法工作。 然后我们看看范围`2`。 两个数有差异`2`有形式`a`和`a + 2`。 他们的gcd是`gcd(a, 2)`，所以它们恰好互质`a`很奇怪。 他们的总和是`2a + 2`，可除以`4`。 因此每一个`x`可除以`4`有答案`2`。 

剩余的偶数值为`x ≡ 2 (mod 4)`。 一系列`2`不可能，所以我们需要更大的间隔。 施工`{a, a+1, a+3}`给出范围`3`。 其总和为`3a+4`。 通过选择`a`适当地，可以表示此类中所有足够大的值。 唯一失败的偶数值是`x = 6`。 

整个问题归结为检查奇偶性和整除性。

 ## 算法演练

 1.如果`x`为奇数，输出`1`。 两个连续整数`(x-1)/2`和`(x+1)/2`具有所需的总和并且始终互质。 
2.如果`x`是偶数并且可被`4`， 输出`2`。 这对`x/2 - 1`和`x/2 + 1`有总和`x`， 不同之处`2`，并且较小的数字是奇数，因此该对是互质的。 
3.如果`x`等于`6`， 输出`-1`。 不存在有效的集合，因为唯一可能的划分为大于 1 的数字，要么重复数字，要么包含公因数。 
4. 对于每个其他偶数值，输出`3`。 在四元素窗口内使用三个数字的构造证明了一系列`3`总是足够的。 

为什么它有效：

 下限来自奇偶校验和 gcd 限制。 范围`0`不可能，因为重复的数字不是互质的。 范围`1`只允许两个连续的数字，其和必须是奇数。 对于不能被四整除的偶数，范围`2`无法产生有效的对，因为两个相隔的数字将具有错误的互质奇偶性。 上面的结构符合这些下限，除了`x = 6`，其中不存在任何构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []
    for case in range(1, t + 1):
        x = int(input())

        if x & 1:
            res = 1
        elif x % 4 == 0:
            res = 2
        elif x == 6:
            res = -1
        else:
            res = 3

        ans.append(f"Case #{case}: {res}")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该程序仅执行算术检查，因此它从不依赖于`x`。 奇偶校验测试处理范围`1`建设第一。 接下来是被四整除的检查，因为这些情况的范围更窄`2`回答。 特殊情况`6`必须在最终回退之前进行检查，因为它是唯一不可能的偶数值。 

输出格式完全按照要求包含案例编号。 Python 整数就足够了，因为所有计算都保持在几十亿以下。

 ## 边缘情况

 对于`x = 6`，算法达到显式不可能的情况。 一系列`1`需要两个连续的整数之和为偶数，这是不可能发生的。 一系列`2`需要一对像`{2,4}`，但他们的gcd不是`1`。 较大的范围无法超过所需的最小值，并且不存在有效的集合。 

为了`x = 5`，奇数分支立即返回`1`。 数字`2`和`3`总和为`5`，他们的 gcd 是`1`，证明最小可能范围是可以实现的。 

为了`x = 8`，算法返回`2`因为`8`能被四整除。 套装`{3,5}`有总和`8`，两个值都大于一，并且`gcd(3,5)=1`。 范围不能是`1`因为连续的数字总和总是奇数。 

对于较大的值，例如`x = 1000000000`，程序不会尝试构建或迭代。 它只检查整除性，发现该值可以被四整除，然后返回`2`立即地。 这证实了解决方案的扩展与数值大小无关`x`。
