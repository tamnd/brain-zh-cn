 ## 解决方案
 ## 问题理解

 我们得到了一个四位数的年份序列。 每一年都可能有错误，但我们最多可以修改一位数字。 在所有修复之后，序列必须变为非递减，并且每个结果年份必须保持在 1000 到 2011 之间（包括 1000 和 2011）。 

任务不是最小化全局变化的数量。 每年独立地可能与原始值最多相差一位数，并且任何有效的最终序列都是可接受的。 

思考这个问题的最自然的方式是：对于每个原始年份，只有一小部分可能的修复年份。 我们必须为每个位置选择一个候选者，以便对最终序列进行排序。 

约束足够小，可以进行积极的枚举。 最多有1000年，每一年只能修改四个位置。 对于每个职位，我们可以尝试十位数字，因此每年最多有 1 + 4 × 9 = 37 个有效候选人，加上一些重复的候选人。 即使我们将每个候选者与之前的每个可能性进行比较，总的工作量仍然很小。 

问题的危险部分不是性能，而是正确性。 一些边缘情况可能会悄无声息地破坏粗心的实现。 

一个常见的错误是忘记了 2011 年的上限。请考虑：```
2
2009
9999
```一个幼稚的解决方案可能会变成`9999`进入`2099`，仍然大于 2011 年并且无效。 正确答案在这里是不可能的。 

另一个陷阱是允许前导零。 例如：```
1
1000
```将第一位数字更改为`0`会创造`0000`，但年份必须保留 1000 到 2011 之间的四位数。 

当贪婪地选择最小的有效候选者时，会出现一个更微妙的问题。 考虑：```
2
1999
1000
```第二年，有效的一位数变化包括`1000`,`1009`,`1090`， 等等。 至少没有一个是`1999`，所以答案是不可能的。 直到为时已晚才忽略先前选择的值的贪婪算法可能会错误地接受无效序列。 

还有一个相反的问题，即选择的候选人规模太大，不必要地阻碍了未来的职位。 假设我们有：```
3
1888
1880
1881
```如果我们不必要地将第二个值提高太多，我们可能会使第三个值变得不可能。 最安全的策略是在保持可行性的同时使每个选择的年份尽可能小。 

## 方法

 蛮力的想法很简单。 对于每个职位，生成最多有一位数变化的所有可用年份。 然后递归地尝试每个组合并检查结果序列是否是非递减的。 

这是有效的，因为每年的候选人很少。 四位数字可以保持所有数字不变，也可以将四个位置之一修改为九个替代数字之一。 每年大约有 37 名候选人。 

问题在于，将这些可能性结合起来会呈指数级增长。 在最坏的情况下，我们会探索$37^n$序列。 即使是为了$n = 1000$，这是完全不可能的。 

关键的观察结果是序列约束是局部的。 候选人是否有效仅取决于之前选择的年份。 我们不需要记住整个前缀。 

一旦我们看到这一点，问题就变得贪婪了。 假设我们已经将前一年固定为某个值`prev`。 对于当前职位，任何小于`prev`是永远无法使用的。 在所有剩余候选者中，选择最小的始终是最佳选择。 

为什么？ 因为较小的值为未来几年留下了更多的空间。 选择一个更大的有效候选人对后来的职位毫无帮助，只会进一步限制他们。 

这将问题转换为一个简单的从左到右的过程：

 1. 生成当年所有有效候选人。 
2. 仅保留至少与上一所选年份一样大的候选者。 
3. 选择其中最小的一个。 
4. 如果不存在，则答案是不可能的。 

由于每年只有大约 37 名候选人，因此总复杂度呈线性关系`n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(37^n)$|$O(n)$| 太慢了|
 | 最佳 |$O(n \cdot 40)$|$O(40)$| 已接受 |

 ## 算法演练

 1. 将所有年份读取为字符串，以便数字替换变得容易。 
2. 维护一个变量`prev`，代表最后选择的修复年份。 最初将其设置为`1000`，因为每个有效年份必须至少为该值。 
3. 对于当年，生成最多有一位数变化的所有可用数字。 

首先包含原始号码本身。 然后尝试将四个位置分别替换为数字`0`通过`9`。 
4.拒绝无效的生成年份。 

如果出现以下情况，候选人无效：

 - 它有一个前导零，
 - 它掉到外面`[1000, 2011]`。 
5. 将所有有效候选者存储在一个集合中以避免重复。 

不同的数字替换有时会产生相同的数字。 
6. 在所有候选者中大于或等于`prev`，选择最小值。 

这就是贪心的一步。 保持当前值尽可能小可以最大限度地提高以后位置的灵活性。 
7. 如果没有候选人满足条件，则打印`"No solution"`并终止。 
8. 否则将所选值附加到答案列表并更新`prev`。 
9. 处理完所有年份后，打印结果序列。 

### 为什么它有效

 该算法保持了这个不变性：

 加工后位置`i`，所选前缀是字典顺序上最小的有效非递减前缀。 

假设在某个步骤我们选择一个候选人`x`即使另一个有效的候选人`y < x`也存在。 选择后任何有效的未来序列`x`选择后也可以工作`y`，因为未来值只需至少是前一个值。 降低先前的值永远不会删除未来的选项。 

因此，选择最小有效候选者总是安全的，并且不会损害未来的可行性。 通过归纳，如果存在解，贪心算法就会找到一个。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def candidates(s):
    res = set()

    original = int(s)
    if 1000 <= original <= 2011:
        res.add(original)

    arr = list(s)

    for i in range(4):
        old = arr[i]

        for d in "0123456789":
            if d == old:
                continue

            arr[i] = d

            if arr[0] != '0':
                val = int("".join(arr))

                if 1000 <= val <= 2011:
                    res.add(val)

        arr[i] = old

    return sorted(res)

def solve():
    n = int(input())
    years = [input().strip() for _ in range(n)]

    ans = []
    prev = 1000

    for s in years:
        cand = candidates(s)

        chosen = None

        for x in cand:
            if x >= prev:
                chosen = x
                break

        if chosen is None:
            print("No solution")
            return

        ans.append(chosen)
        prev = chosen

    print("\n".join(map(str, ans)))

solve()
```辅助函数生成每年可达最多一位数字修改。 使用字符串使数字替换变得简单并避免算术技巧。 

首先插入原始值，因为允许零更改。 然后每个位置都独立修改。 更改一位数字后，代码检查第一位数字是否为零以及结果年份是否保持在允许的间隔内。 

集合会自动删除重复项。 例如，会跳过用数字本身替换数字，但即使不同的编辑有时也会产生相同的整数。 

候选列表已排序，因为贪婪步骤需要最小的有效值至少与`prev`。 由于列表很小，排序几乎不需要任何成本。 

里面`solve`，算法从左到右处理年份。 对于每一年，它都会扫描排序后的候选列表并选择第一个满足要求的候选`x >= prev`。 

初始化`prev = 1000`是故意的。 每个有效年份都必须已经满足这个下限，因此第一个选择的值只需要遵守原始问题约束即可。 

最常见的实现错误是在测试替换后忘记恢复修改后的数字。 该行：```
arr[i] = old
```是必不可少的。 如果没有它，以后的修改会意外地将多个数字更改堆叠在一起。

 ## 边缘情况

 考虑以下情况：```
2
2009
9999
```为了`2009`，算法可以选择`1009`。 然后它处理`9999`。 任何一位数的修改仍然会留下大于 2011 的值，因此候选集变空。 该算法立即打印`"No solution"`。 

这证实了上限限制是在候选生成期间而不是之后强制执行的。 

现在检查前导零的危险：```
1
1000
```当修改第一个数字时，算法可能会临时创建字符串，例如`"0000"`或者`"9000"`。 条件：```
if arr[0] != '0':
```在转换之前过滤掉无效的前导零数字。 有效候选人`1000`仍然存在，因此输出是正确的。 

最后，考虑一个贪婪极简很重要的序列：```
3
1888
1880
1881
```在第一年，算法选择最小的有效候选者，例如`1088`。 那么第二个就可以变成`1080`，第三个`1081`。 

如果我们为第一个位置选择一个大的修复值，那么以后的几年可能变得不可能。 贪心规则通过始终保留后缀的最大灵活性来避免这种情况。
