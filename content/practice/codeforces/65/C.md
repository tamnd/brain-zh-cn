[CF 65C - 哈利·波特与金色飞贼](https://codeforces.com/problemset/problem/65/C)

 **评分：** 2100
 **标签：** 二分查找，几何
 **求解时间：** 2m 11s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 告密者在 3D 空间中沿着固定的折线移动。 它从第一个顶点开始，以恒定速度逐段行进`vs`。 哈利从另一点开始，可以以恒定速度向任何方向移动`vp`， 在哪里`vp >= vs`。 

我们需要哈利和飞贼能够最早占据同一点的时间。 如果在告密者完成折线之前这种情况从未发生，我们会打印`"NO"`。 

几何形状是连续的。 飞贼不会在顶点之间跳跃，它会沿着每个部分平滑地移动。 哈利还可以自由地在太空中连续移动。 挑战是找到告密者轨迹上的第一个可到达点。 

该路径最多包含`10000`段，这立即排除了任何极其细粒度的模拟。 具有微小增量的简单时间步进方法要么会因为浮点精度而错过答案，要么需要数十亿次迭代才能达到足够的精度。 

每个坐标最多`10^4`，因此距离可以用数字来管理。 双精度浮点运算就足够了。 

棘手的部分是告密者轨迹是分段线性的。 最早的捕获点可能严格出现在线段内，而不是出现在顶点处。 仅检查顶点的解决方案是错误的。 

考虑这个例子：```
1
0 0 0
10 0 0
2 1
5 0 0
```飞贼从`(0,0,0)`到`(10,0,0)`与速度`1`。 哈利开始于`(5,0,0)`与速度`2`。 

哈利及时抓住了飞贼`5/3`，在点`(5/3,0,0)`。 仅检查端点将完全错过这一点。 

另一个容易犯的错误是假设哈利总能抓住飞贼，因为`vp >= vs`。 

例子：```
1
0 0 0
10 0 0
1 1
100 0 0
```告密者按时完成`10`。 哈利需要`90`几秒钟就到达终点。 当飞贼移动时，不可能捕捉到，所以正确答案是`"NO"`。 

段边界附近还存在精度缺陷。 假设接球时刻恰好发生在告密者到达顶点时。 在段内独立进行二进制搜索而没有仔细的间隔处理可能会意外地跳过确切的端点。 

## 方法

 蛮力的想法很简单。 按时间参数化告密者位置，然后按时间进行全局二分搜索，找到哈利到达告密者位置的第一个时刻。 

对于给定的时间`t`，我们可以计算沿着折线的告密者位置。 哈利能够达到这一点，如果$$\text{distance}(P, S(t)) \le vp \cdot t$$在哪里`P`是 Harry 的起始位置并且`S(t)`是当时告密者的位置`t`。 

这个条件是单调的。 一旦哈利有能力接近金色飞贼，他就可以在以后的所有时间里保持这种能力，因为他可以简单地等待。 

因此，随着时间的推移，全局二分搜索是有效的。 

难点在于评估`S(t)`。 飞贼移动到`10000`段。 如果我们扫描每次二分搜索迭代的所有段，复杂度大致变为：$$O(n \cdot \log(\text{precision}))$$这在这里已经可以接受，但是我们可以通过利用每个段的结构来进一步简化推理。 

在单个分段内，告密者位置随时间线性变化。 可行性条件在该区间内也是单调的。 这意味着我们可以逐个处理段，并仅在第一个段内进行二分搜索，从而可以进行捕获。 

关键的观察是：

 如果哈利在片段结束时无法抓住飞贼，那么最早的捕捉时间必须晚一些。 

对于细分市场`i`， 让：

-`t0`是告密者进入该段的时间
 -`t1`是它离开该段的时间

 如果哈利无法按时间到达路段终点`t1`，那么未来片段中的早期内容还不重要。 

一旦我们找到了可以及时到达端点的第一个路段，最早的捕获时刻一定位于该路段内的某个位置。 然后对时间里面进行二分查找`[t0, t1]`给出了确切的答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 使用段扫描进行暴力全局二分搜索 | O(n 对数精度) | O(n) | 已接受 |
 | 分段二分查找 | O(n + 对数精度) | O(n) | 已接受 |

 ## 算法演练

 1. 读取所有折线顶点并预先计算每段线段的长度。 

告密者以恒定速度移动，因此一段的遍历时间很简单：$$\frac{\text{segment length}}{vs}$$2. 维护当前累计时间`cur_t`。 

这表示告密者到达当前片段开始的时间。 
3. 按顺序处理段。 

假设当前段来自`A`到`B`。 
4. 计算路段遍历时间。 

如果段长度为`d`， 然后：$$\Delta t = \frac{d}{vs}$$告密者到达`B`时间：$$t_1 = cur_t + \Delta t$$5. 检查Harry是否可以到达终点`B`按时间`t1`。 

哈利需要：$$\frac{\text{distance}(P, B)}{vp}$$秒到达那里。 

如果这超过`t1`，那么哈利在这个端点之前的任何地方都无法抓住金色飞贼，所以继续下一段。 
6. 一旦某个端点及时变得可达，最早的捕获就位于该段内。 

在比赛开始时，追赶是不可能的。 在段末端，这是可能的。 条件单调变化，因此只有一个转变点。 
7. 在当前段区间内按时间二分查找。 

设搜索范围为`[cur_t, t1]`。 
8. 候选人时间`mid`，计算分段上的告密者位置。 

如果段参数为：$$r = \frac{mid - cur_t}{\Delta t}$$那么位置就是线性插值：$$S(mid) = A + r(B - A)$$9. 检查可行性。 

哈利有时能抓住飞贼`mid`如果：$$\text{distance}(P, S(mid)) \le vp \cdot mid$$如果可行，将二分查找向左移动。 否则向右移动。 
10.经过足够的迭代后，输出最终的时间和位置。 

### 为什么它有效

 关键属性是单调性。 

定义：$$f(t) = \text{distance}(P, S(t)) - vp \cdot t$$哈利可以准确地抓住飞贼`f(t) <= 0`。 

随着时间的增加，哈利的可达半径线性增长。 飞贼连续移动的速度最多等于哈利的速度。 一旦飞贼进入哈利的可接触区域，它就永远无法逃脱。 

这意味着可行性只会改变一次，从不可能变为可能。 二分查找有效。 

按顺序处理段可以保证我们找到包含有效时间的最早段，并且该段内的二分搜索可以恢复最早的可行时刻。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def dist(a, b):
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    dz = a[2] - b[2]
    return math.sqrt(dx * dx + dy * dy + dz * dz)

def solve():
    n = int(input())

    pts = [tuple(map(float, input().split())) for _ in range(n + 1)]

    vp, vs = map(float, input().split())
    P = tuple(map(float, input().split()))

    cur_t = 0.0

    for i in range(n):
        A = pts[i]
        B = pts[i + 1]

        seg_len = dist(A, B)
        seg_time = seg_len / vs

        end_t = cur_t + seg_time

        if dist(P, B) > vp * end_t + 1e-12:
            cur_t = end_t
            continue

        lo = cur_t
        hi = end_t

        for _ in range(100):
            mid = (lo + hi) / 2.0

            ratio = (mid - cur_t) / seg_time

            x = A[0] + (B[0] - A[0]) * ratio
            y = A[1] + (B[1] - A[1]) * ratio
            z = A[2] + (B[2] - A[2]) * ratio

            snitch = (x, y, z)

            if dist(P, snitch) <= vp * mid:
                hi = mid
            else:
                lo = mid

        t = hi
        ratio = (t - cur_t) / seg_time

        x = A[0] + (B[0] - A[0]) * ratio
        y = A[1] + (B[1] - A[1]) * ratio
        z = A[2] + (B[2] - A[2]) * ratio

        print("YES")
        print(f"{t:.10f}")
        print(f"{x:.10f} {y:.10f} {z:.10f}")
        return

    print("NO")

solve()
```第一个辅助函数计算 3D 空间中的欧几里得距离。 问题中的一切都是几何的，所以这个操作会重复出现。 

主循环一次处理一个段。`cur_t`当告密者到达分段开始时存储。 根据段长度和告密速度，我们计算遍历需要多长时间。 

端点可达性检查是关键的修剪步骤。 如果在告密者到达那里时哈利仍然无法到达片段终点，那么该片段中的早期点也不起作用。 这让我们可以跳过整个部分。 

一旦找到可行的端点，答案就必须位于该段内。 二分搜索使用时间作为搜索变量。 将时间转换为线段上的点需要带参数的线性插值`ratio`。 

二分查找运行的时间为`100`迭代。 这对于`1e-6`精度，因为每次迭代都会将间隔减半。 

小 epsilon 为：```
dist(P, B) > vp * end_t + 1e-12
```当值极其接近时避免浮点不稳定。 

一个微妙的细节正在使用`hi`作为二分查找后的最终答案。`hi`总是存储一个可行的时间，而`lo`存储一个不可行的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + 对数精度) | 每个段被处理一次，并且恰好执行一次二分查找 |
 | 空间| O(n) | 存储所有折线顶点 |

 和`n <= 10000`，这很容易符合限制。 二分搜索执行恒定次数的迭代，因此运行时间主要由对段的线性扫描决定。

 ## 边缘情况

 考虑捕获恰好发生在顶点的情况。 

输入：```
1
0 0 0
10 0 0
2 1
20 0 0
```告密者到达`(10,0,0)`在某个时间`10`。 哈利也确实需要`10`秒到达该点。 

该算法处理段并检查端点可行性：$$\text{distance} = 10,\quad vp \cdot t = 20$$所以该段是可行的。 

二分查找收敛到端点本身。 由于可行性已通过`<=`，完全相等的情况被正确接受。 

现在考虑一个内部捕获。 

输入：```
1
0 0 0
10 0 0
2 1
5 0 0
```时`0`，告密者太左了。 时`10`，哈利一定能到达终点。 

二分查找逐渐向第一个可行时间收缩：

 | 时间 | 告密者位置| 哈利可达半径 | 可行|
 | ---| ---| ---| ---|
 | 1 | 1 | 2 | 没有 |
 | 2 | 2 | 4 | 是的 |

 确切的转换发生在：$$t = \frac{5}{3}$$这证实了算法正确地严格处理段内的答案。 

最后，考虑一个完全不可能的情况。 

输入：```
1
0 0 0
10 0 0
1 1
100 0 0
```到达段终点的时间`10`，但哈利需要`90`秒到达那里。 

端点可行性检查失败，因此算法永远不会进入二分搜索并打印`"NO"`。 

这可以防止由于假设相同的速度意味着最终拦截而导致误报。
