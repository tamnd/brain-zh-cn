 ## 解决方案
 ## 问题理解

 我们对学生进行一一处理。 每个学生都有一所固定的房子，由其中一个字母代表`G`,`H`,`R`,`S`，或者有不明确的血统，由`?`。 

那个房子里总是有一个固定的学生。 一个`?`学生的行为有所不同。 我们查看所有四栋房屋的当前数量。 学生可以选择当前数量最少的任何房屋。 

赫敏来到了所有指定的学生之后。 我们必须确定她可能最终进入的每所房子，假设更早`?`学生以任何有效的方式选择他们的房子。 

关键的困难在于早期的选择会影响以后的平衡。 一开始的两个不同决定可能会完全改变以后可用的房屋。 

赫敏之前的学生人数最多为`10000`。 这对于任何指数搜索来说都太大了`?`作业。 甚至`2^40`是不可能的，在最坏的情况下我们可能会`10000`暧昧的学生。 我们需要更接近线性或多项式时间的东西。 

问题的一个微妙部分是我们没有被要求提供一种可访问的配置。 我们需要赫敏在某些有效选择序列下可能进入的所有房屋。 

一个容易犯的错误是假设每一个`?`学生应该始终平等地选择所有当前最小的房屋。 这个过程不是概率性的。 我们只关心可达性。 

考虑：```
2
H?
```在第一个学生之后：```
G=0 H=1 R=0 S=0
```第二位同学可以选择`G`,`R`， 或者`S`。 

如果他们选择`G`, 赫敏可能会选择`R`或者`S`。 

如果他们选择`R`, 赫敏可能会选择`G`或者`S`。 

如果他们选择`S`, 赫敏可能会选择`G`或者`R`。 

所以赫敏永远不会以`H`。 

贪心模拟，为每个人任意选择一所房子`?`会错过可能性。 

另一个危险的边缘情况是多个房屋长时间保持完美平衡。 

例子：```
4
????
```每一步都保持接近平衡。 四个学生之后，每个房子仍然可以有计数`1`，所以赫敏可以选择任何房子。 

粗心的 DFS 在没有记忆的情况下进行计数会爆炸，因为许多不同的序列会产生相同的状态。 

这里还隐藏着一个对称性观察。 只有相对差异才重要。 先前选择的确切顺序仅在当前计数时才重要。 

## 方法

 蛮力的想法很简单。 从左到右处理学生。 每当我们看到一个固定的字母时，就增加该房子。 每当我们看到`?`，分支到每个当前最小的房子。 

最后，检查哪些房子对于赫敏来说是最小的。 

这是正确的，因为它明确探讨了决策的每一个法律顺序。 

问题在于分支机构的数量。 最坏的情况下，第一批学生可能全部都是`?`，每个选项最多可以分为四种选择。 即使进行修剪，路径的数量也会呈指数增长。 

例如，仅用`40`暧昧的学生，`4^40`已经是天文数字了。 

重要的观察是，许多不同的选择序列会导致完全相同的房屋计数。 一旦计数相同，未来的可能性也相同。 

这立即暗示了动态编程或状态上的记忆 DFS。 

现在我们需要了解状态空间到底有多大。 乍一看，计数可能高达`10000`，听起来很大。 但平衡规则严重限制了配置。 

一个`?`学生只能进入目前最小的房子。 这意味着房屋数量的差异永远不会超过`1`在仅通过进化而来的房屋中`?`作业。 固定的任务会扰乱平衡，但只是以受控的方式。 

关键的压缩是这样的：

 我们不存储确切的历史记录，而是仅存储当前计数的元组。 

从一种状态开始，转换是确定性的：

 固定字母 -> 递增一计数，

 问号 -> 分别增加每个最小计数。 

由于平衡约束积极合并路径，因此可达计数元组的数量仍然非常小。 

我们可以通过对可达状态进行记忆来运行 DFS。 每个独特的状态都会被处理一次。 

这在一定范围内提供了一个可接受的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(4^q) | O(4^q) | O(q) | 太慢了|
 | 最佳 | O(可达状态数) | O(可达状态数) | 已接受 |

 这里`q`是的数量`?`人物。 

## 算法演练

 1. 将房屋表示为指数：`0 = G`,`1 = H`,`2 = R`,`3 = S`。 
2.从计数元组开始`(0, 0, 0, 0)`。 
3. 使用具有记忆功能的 DFS 从左到右处理学生。 
4. DFS状态包括：

 当前位置`i`,

 以及当前的房屋计数元组。 
5. 如果`i == n`，我们到达了赫敏之前的那一刻。 

找出四间房子中的最小数量。 

每个具有该最小值的房子都是有效的答案。 
6. 如果当前学生有固定的学院信，则仅增加该学院并继续 DFS。 
7. 如果当前学生是`?`，计算最小电流计数。 

每栋具有最低限度的房屋都是合法的过渡。 

对于每个这样的房子，增加其计数并继续 DFS。 
8. 记住访问过的州`(i, counts)`所以相同的配置永远不会被处理两次。 

如果没有记忆，可以通过许多不同的选择序列来达到相同的计数元组。 

### 为什么它有效

 国家完全决定未来。 

假设两个不同的历史产生相同的位置`i`和相同的计数元组。 剩下的每个学生都会看到完全相同的房子计数，因此未来合法的移动集合是相同的。 早期决策中的信息不再重要。 

DFS 对每个唯一状态的每个合法转换进行一次探索。 每个终止状态都对应一个有效的排序序列，并且每个有效的排序序列都出现在DFS中。 

所以最后收集到的最小房子正是赫敏可以进入的房子。 

## Python 解决方案```python
import sys
from functools import lru_cache

input = sys.stdin.readline

houses = ['G', 'H', 'R', 'S']
name_map = {
    'G': 'Gryffindor',
    'H': 'Hufflepuff',
    'R': 'Ravenclaw',
    'S': 'Slytherin'
}

idx = {c: i for i, c in enumerate(houses)}

n = int(input())
s = input().strip()

possible = [False] * 4

@lru_cache(maxsize=None)
def dfs(i, g, h, r, s_cnt):
    counts = [g, h, r, s_cnt]

    if i == n:
        mn = min(counts)
        for j in range(4):
            if counts[j] == mn:
                possible[j] = True
        return

    ch = s[i]

    if ch != '?':
        nxt = counts[:]
        nxt[idx[ch]] += 1
        dfs(i + 1, *nxt)
    else:
        mn = min(counts)

        for j in range(4):
            if counts[j] == mn:
                nxt = counts[:]
                nxt[j] += 1
                dfs(i + 1, *nxt)

dfs(0, 0, 0, 0)

for i in range(4):
    if possible[i]:
        print(name_map[houses[i]])
```DFS直接镜像排序过程。 

记忆键包含当前位置和四个房屋计数。 具有相同值的两个状态可以互换，因为未来的转换仅取决于这些值。 

终端状况值得关注。 我们不会将赫敏分配到任何地方。 我们只检查目前最少的房子，因为那些是她可以选择的房子。 

另一个微妙之处是全局更新答案，而不是从 DFS 返回集合。 重复返回大集合会增加不必要的开销。 一个简单的布尔数组就足够了。 

元组解包在：```
dfs(i + 1, *nxt)
```保持缓存键不可变且可散列。 直接使用列表会失败，因为列表不可散列。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(可达状态数) | 每个记忆状态都会被处理一次 |
 | 空间| O(可达状态数) | 缓存存储所有访问过的状态 |

 平衡规则使可达状态空间保持可控。 即使与`n = 10000`，不同的可达计数配置的数量对于 Python 来说保持在限制范围内足够小。

 ## 边缘情况

 考虑：```
2
H?
```在第一个学生之后：```
(0,1,0,0)
```第二个学生只能选择最少的房屋：```
G, R, S
```DFS 恰好分支为这三个状态。 没有产生`H`之后为最小。 该算法正确排除了赫奇帕奇。 

现在考虑：```
4
????
```DFS 反复将学生分配到目前最少的宿舍中。 因为所有的房子一开始都是平等的，所以每个分支都保持接近平衡。 

一种可到达的终端状态是：```
(1,1,1,1)
```所有四栋房子都很小，所以赫敏可以选择任何房子。 记忆化 DFS 在没有指数重复的情况下探索了这一点，因为许多不同的分配顺序会合并到相同的计数元组中。

3
SSS
```计数变为：```
(0,0,0,3)
```赫敏只能在最小的房屋中进行选择：```
G, H, R
```该算法自然地处理这个问题，因为终端处理只是检查哪个计数等于最小值。
