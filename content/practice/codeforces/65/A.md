 ## 解决方案
 ## 问题理解

 我们有三个转化咒语，可以将一种材料转化为另一种材料。 

第一个咒语转`a`克沙子放入`b`克铅。 

第二个咒语转`c`克铅进入`d`克黄金。 

第三个咒语转`e`克金成`f`克沙子。 

只要我们当前拥有足够的材料来施展我们想要施放的法术，我们就可以以任何顺序应用这些法术任意次数。 问题是是否存在一些有限的起始沙子数量，以便我们最终可以生产任意大量的黄金。 

关键词是“大于任何预先分配的数字”。 我们没有被要求提供具体的最高金额。 我们必须确定黄金产量是否可以无限增长。 

限制很小。 每个数字都介于`0`和`1000`。 这意味着我们可以自由地使用直接数学推理，而不必担心性能。 即使是中等范围内的强力状态探索也能在时间限制内完成。 真正的挑战不是效率，而是正确处理所有涉及零的退化情况。 

危险的案例都来自于“从无到有”创造物质的咒语。 

考虑这个输入：```
1 1 0 1 1 1
```第二个咒语转换`0`引入`1`金子。 我们可以立即无限多次地施放它。 答案是`"Ron"`。 

如果不小心实现，只检查全周期乘法比，就会错过这一点。 

另一个微妙的情况：```
1 1 1 1 0 1
```第三个咒语转换`0`金成`1`沙。 从零沙子开始，我们可以免费生成无限沙子，然后使用第一和第二个法术来创建无限金子。 答案是`"Ron"`。 

假设我们总是需要正初始资源的解决方案在这里会失败。 

在某些情况下，每个咒语都会保存或破坏物质：```
100 50 100 50 100 50
```每次转变都会损失一半的材料。 重复循环只会减少资源，所以答案是`"Hermione"`。 

另一个边缘情况：```
0 0 0 0 0 0
```所有咒语都不起作用。 无限金币是不可能的。 

问题最难的部分是正确区分真正的放大和无害的循环。 

## 方法

 一个自然的暴力想法是模拟可达状态。 我们可以从一定数量的沙子开始，重复应用所有可能的咒语，标记每个可到达的三元组`(sand, lead, gold)`。 

这在概念上是有效的，因为系统是确定性的并且状态转换很简单。 如果存在无限增长，我们预计资源价值将持续增加。 

问题在于状态空间没有明显的上限。 如果答案是`"Ron"`，数量可以永远增长。 即使我们将所有资源限制在某个限制之内，例如`10^6`，我们仍然无法证明正确性。 一个盈利周期可能需要暂时积累大量资金才能可持续。 

法术的结构提供了一条更清晰的路线。 

观察材料形成定向循环：```
sand -> lead -> gold -> sand
```如果我们从一定量的沙子开始并经历一次整个循环，则沙子总量会按乘法因子变化：```
(b / a) * (d / c) * (f / e)
```如果这个系数大于`1`，那么一个完整的循环就会增加沙子。 重复这个循环，资源就会呈指数增长，我们可以提取无限的黄金。 

重新排列可以避免分数：```
b * d * f > a * c * e
```这处理的是所有分母均为正数的普通情况。 

剩下的挑战是零处理。 零输入的咒语可以从无到有创造物质。 这样的咒语完全绕过了乘法论证。 

例如，如果`c = 0`和`d > 0`，第二个咒语免费创造金币。 无限金币变得立即。 

同样，如果`e = 0`和`f > 0`，我们可以从无到有产生无限的沙子。 如果前两个咒语最终可以将沙子变成金子，那么无限的金子就会随之而来。 

整个解决方案变成逻辑检查的一小部分集合。

 ## 算法演练

 1. 检查第二个咒语是否从无到有创造出黄金。 

如果`c == 0`和`d > 0`，那么每次铸造都会产生金而不消耗铅。 我们可以立即无限次地施放它，所以答案是`"Ron"`。 
2. 检查第三个咒语是否从无到有产生沙子。 

如果`e == 0`和`f > 0`，那么我们就可以免费生成无限的沙子。 要将沙子变成金子，我们还需要第一个咒语来实际生产铅，第二个咒语实际生产金子。 

具体来说，我们需要：`a > 0`,`b > 0`,`c > 0`， 和`d > 0`。 

如果全部成立，则答案是`"Ron"`。 
3. 处理涉及零分母的不可能循环。 

如果其中有任何分母`a`,`c`， 或者`e`为零时，乘法循环公式无效。 

至此，所有免产案件均已处理完毕。 任何剩余的零分母都无法产生无限的黄金，所以答案是`"Hermione"`。 
4. 比较全周期放大倍数。 

计算是否：```
b * d * f > a * c * e
```如果属实，则一个完整周期会严格增加沙子。 无限次地重复这个循环会产生无限的资源，从而产生无限的黄金。 
5.否则，输出`"Hermione"`。 

### 为什么它有效

 系统只包含一个资源循环：```
sand -> lead -> gold -> sand
```任何可持续的无限增长战略都必须反复经历这个循环。 一次遍历的净效果是将沙子乘以：```
(b/a) * (d/c) * (f/e)
```如果该产品超过`1`，反复循环无限增长资源。 如果最多是`1`，每个完整的循环都会保留或减少可用材料总量，因此不可能无限增长。 

唯一的例外是咒语消耗零输入时。 在这种情况下，物质可以从无到有，我们必须明确地分别处理这些情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a, b, c, d, e, f = map(int, input().split())

# Free gold
if c == 0 and d > 0:
    print("Ron")
    sys.exit()

# Free sand
if e == 0 and f > 0:
    if a > 0 and b > 0 and c > 0 and d > 0:
        print("Ron")
    else:
        print("Hermione")
    sys.exit()

# Invalid cycle denominators
if a == 0 or c == 0 or e == 0:
    print("Hermione")
    sys.exit()

# Profitable cycle
if b * d * f > a * c * e:
    print("Ron")
else:
    print("Hermione")
```前两项检查隔离了危险的零输入咒语。 这些很特别，因为它们打破了通常的保护式推理。 消耗零材料的法术可以永远重复。 

第二个条件需要格外小心。 仅有免费沙子是不够的。 我们仍然必须能够使用前两个咒语将沙变成金。 这就是代码验证这些转换的正输入和输出的原因。 

分母检查可防止除零逻辑错误。 一旦所有自由生产情况被消除，任何剩余的零分母都意味着该循环无法盈利。 

最终比较仅使用整数运算。 两边相乘完全避免了浮点精度问题。 

Python 整数自动安全地处理大型产品，尽管这里的最大值仅为：```
1000 * 1000 * 1000 = 10^9
```它已经很适合标准整数范围。

    out = io.StringIO()

 ## 边缘情况

 考虑免费黄金的情况：```
1 1 0 5 1 1
```该算法首先检查：```
c == 0 and d > 0
```变成：```
0 == 0 and 5 > 0
```这是真的，所以答案立即`"Ron"`。 

这是正确的，因为第二个咒语创造了`5`克黄金而不消耗任何铅。 我们可以无限多次地施放它。 

现在考虑没有可用转换的自由沙：```
0 0 1 1 0 10
```第三个咒语免费创造沙子，但第一个咒语不能将沙子转化为铅，因为两者`a`和`b`为零。 

算法进入自由沙分支：```
e == 0 and f > 0
```然后它检查前两个咒语是否形成有效的黄金管道：```
a > 0 and b > 0 and c > 0 and d > 0
```这失败了，所以答案变成了`"Hermione"`。 

最后，考虑精确守恒：```
1 1 1 1 1 1
```乘法比较变为：```
1 * 1 * 1 > 1 * 1 * 1
```这是错误的。 

每个循环都会返回完全相同数量的沙子。 资源永远不会增长，因此黄金不可能变得任意大。 算法正确打印`"Hermione"`。
