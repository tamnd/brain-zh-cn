 ## 解决方案
 ## 问题理解

 我们得到一个无向连通图，其中所有人都从顶点 1 开始。每个朋友都有一个他们最终必须到达的目的地顶点。 在这些朋友中，有一些最多 6 人的子集是“特殊”的，因为他们没有汽车。 其他人可能都有车。 

有车的朋友可以接送任意数量的无车朋友，但前提是有严格的约束：车主沿着从顶点 1 到自己目的地的最短路径行驶，并且他们接送的每个无车朋友必须以兼容的方式位于该确切的最短路径路线上。 换句话说，汽车定义了一条从 1 到目的地的最短路线，并且所有乘客都必须位于汽车在该路线上经过的顶点上。 

我们的任务是尽量减少没有汽车的朋友被迫独自行走的数量。 同样，我们希望最大化k个特殊朋友中可以分配给车主的数量，使得每个车主的最短路径可以“覆盖”所有分配的乘客。 

问题的结构变得紧凑，因为 k 至多为 6。这立即意味着特殊朋友子集上的指数解决方案是可行的，因为 2^6 只有 64。然而，图本身和朋友 f 的数量可能很大，每个测试用例最多 10^4，因此任何解决方案都必须严重压缩图信息并避免每对最短路径重新计算。 

当我们试图贪婪地将每个无车朋友分配给最近的车主时，就会出现幼稚的失败案例。 当两个无车朋友分别与不同的汽车兼容但由于最短路径分歧而无法一起提供服务时，这种情况就会被打破。 例如，如果两个所需的顶点位于到给定汽车目的地的每条最短路径的不同分支上，贪婪分配可能会错误地假设两者可以一起行驶。 

另一个微妙的问题是假设“处于从 1 到 h_i 的最短路径上”相当于简单的距离比较。 两个顶点可以独立地满足距离约束，但不能一起位于单个最短路径树路由上，这会使分组无效。 

## 方法

 蛮力观点首先只关注 k 个特殊的朋友。 对于每个特殊的朋友，我们尝试将他们分配给有车的朋友。 对于固定车主来说，我们必须决定他们可以携带哪些特殊朋友。 这取决于所有选定的特殊顶点是否位于从 1 到该车目的地的单个最短路径上。 

如果我们预先计算距每个相关汽车目的地的最短距离，我们可以使用标准条件检查顶点是否位于到该目的地的最短路径上：当且仅当 dist1[v] + dist[v][h] 等于 dist1[h] 时，顶点 v 位于从 1 到 h 的某个最短路径上。 然而，图很大，计算所有对的 dist[v][h] 是不可能的。 

关键的观察结果是 k 非常小，因此我们可以反转视角。 我们不是在大型状态空间中独立地检查每辆车与乘客子集，而是预先计算与每个潜在汽车目的地相关的 k 个特殊顶点之间的所有成对关系。 

对于每个朋友（潜在的车主），我们预先计算从他们的目的地到所有顶点的最短距离。 然后，对于每个特殊顶点，我们可以使用一次比较来测试它是否位于从 1 到该目的地的最短路径上。 这将问题转化为兼容性掩码：对于每个车主，我们计算一个 k 位掩码来描述他们可以携带哪些特殊朋友。

现在的问题变成了选择一部分车主，使每个特殊的朋友都至少被一个选定的面具覆盖，从而最大限度地减少未被覆盖的元素。 这是大小为 k 的子集上的经典 DP。 

我们将 dp[mask] 定义为精确覆盖特殊朋友的子集 mask 所需的最少车主数量。 每辆车贡献一个掩模，我们在最多 2^k 个状态上执行子集 DP。 

暴力的想法将尝试直接为每辆车分配子集，而不需要预处理掩码，从而导致重复的图形检查。 这导致大约 O(f * 2^k * (n + m)) 太慢了。 优化版本通过 BFS 将图形工作减少到 O(f * (n + m))，然后将选择压缩为 O(f * 2^k)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解每个子集重复检查路径 | O(f·2^k·(n + m)) | O(f·2^k·(n + m)) | O(n + m) | 太慢了|
 | 汽车上的 BFS + 位掩码 DP | O(f·(n + m) + f·2^k) | O(f·(n + m) + f·2^k) | O(n + m + 2^k) | O(n + m + 2^k) | 已接受 |

 ## 算法演练

 我们首先修复 k 个特殊朋友并将它们视为索引 0 到 k-1。 

1. 从顶点 1 运行 BFS 来计算所有顶点的 dist1[v]。 这给出了从起点到每个节点的最短距离。 
2. 对于输入列表中的每个朋友 i，我们需要从 h_i 到所有顶点的最短距离。 我们不是单独对所有 f 执行此操作并存储完整数组，而是在需要时使用 BFS 处理每个友元。 
3. 对于每个朋友 i，我们确定 k 个特殊朋友的位掩码。 对于位于顶点 x_j 的每个特殊好友 p_j，我们通过验证来检查 x_j 是否位于从 1 到 h_i 的某个最短路径上：

 dist1[x_j] + dist_i[x_j] == dist1[h_i]。 

如果为真，我们在好友 i 的掩码中设置位 j。 
4.我们只关心有车朋友的口罩。 对于没有车的朋友来说，他们的贡献是无关紧要的，因为他们无法为他人服务。 
5. 现在，我们求解一个子集 DP，我们希望使用最少数量的掩码覆盖所有 k 位。 我们初始化 dp[0] = 0 并将所有其他状态初始化为无穷大。 
6. 对于每个车主掩码 m，我们以逆子集顺序更新 dp：对于每个状态 s，我们设置 dp[s | m] = min(dp[s | m], dp[s] + 1)。 
7、答案是dp[(1 << k) - 1]，代表全覆盖所有无车朋友。 

这种方法起作用的关键结构原因是每辆车都对应于 k 个特殊顶点上的单个固定覆盖模式。 一旦知道了这些模式，图就会消失，问题就变成了大小最多为 6 的宇宙上的纯集合覆盖优化。 

## 为什么它有效

 最短路径结构保证可以使用距离可加性独立测试到目的地的有效路线上的顶点的成员资格。 这将每辆车转换为可用乘客的确定性子集。 由于 k 很小，特殊朋友之间的所有交互都被子集掩码完全捕获，并且 DP 探索了组合这些独立覆盖的所有方法，而不会丢失任何交互模式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, g, n):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        v = q.popleft()
        for to in g[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        f = int(input())
        h = list(map(int, input().split()))
        k = int(input())
        p = list(map(int, input().split()))
        special_idx = [x - 1 for x in p]
        special_vertices = [h[i] for i in special_idx]

        dist1 = bfs(1, g, n)

        masks = []

        for i in range(f):
            dist_i = bfs(h[i], g, n)
            mask = 0
            for j in range(k):
                v = special_vertices[j]
                if dist1[v] + dist_i[v] == dist1[h[i]]:
                    mask |= (1 << j)
            masks.append(mask)

        dp = [10**9] * (1 << k)
        dp[0] = 0

        for mask in masks:
            if mask == 0:
                continue
            for s in range((1 << k) - 1, -1, -1):
                if dp[s] == 10**9:
                    continue
                ns = s | mask
                if dp[ns] > dp[s] + 1:
                    dp[ns] = dp[s] + 1

        print(dp[(1 << k) - 1])

if __name__ == "__main__":
    solve()
```每个测试用例计算一次来自顶点 1 的 BFS，因为所有最短路径有效性检查都依赖于 dist1。 每个朋友从他们的目的地触发另一个 BFS 来构建其覆盖掩码，这是可以接受的，因为总的 f 和 n 总体上以 10^4 为界。 

DP 循环迭代 2^k 个状态，k 最多为 6，因此这是常数因子工作。 唯一微妙的实现细节是向后迭代 DP 状态，以避免在单个转换步骤中多次重复使用掩码。 

## 工作示例

 考虑一个小的概念案例，其中 k = 3 个特殊朋友对应于顶点 A、B、C。 

### 示例 1

 假设我们有三个车主生产口罩：

 | 汽车 | 面膜|
 | --- | --- |
 | 1 | 110 | 110
 | 2 | 011|

 我们初始化 dp[000] = 0。 

处理完汽车 1 后，dp 更新为覆盖 110。处理完汽车 2 后，组合转换使用两辆汽车产生 111 的覆盖。 

这说明了为什么组合面罩是必要的：没有任何一辆车可以覆盖所有的情况，但它们的联合可以。 

### 示例 2

 如果所有汽车掩码都是相同的，假设都是 100，那么 dp 永远无法达到完全覆盖，除非我们冗余地使用多辆车，这表明重复没有帮助，并且 DP 正确地避免了不必要的选择。

 ## 边缘情况

 一个关键的边缘情况是多个朋友共享相同的目标顶点。 基于 BFS 的掩码结构自然会为它们分配相同的掩码，并且 DP 将它们视为可互换的，从而避免了计数过多。 

另一种边缘情况是汽车的最短路径包含一个特殊顶点，但与另一个特殊顶点不一致。 距离相等检查正确地拒绝不兼容的分组，确保掩模不会夸大覆盖范围。 

最后，当一个特殊的朋友不能被任何汽车覆盖的情况下，除了零状态转换之外，dp 保持无限，正确地得出这些朋友必须步行。
