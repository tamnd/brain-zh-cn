 ## 解决方案
 ## 问题理解

 我们被要求构建一个数字排列$1$到$n$从而同时满足两个约束。 首先，每个值必须至少与一个值与其相差一倍的邻居相邻。 其次，任何号码都不允许留在原来的位置上。 

第一个条件强制局部结构：每个值必须是链的一部分，其中相邻数字的值相差一个，这意味着邻居的行为必须像某种顺序的连续整数。 第二个条件删除了固定点，从而排除了琐碎的类似身份的安排。 

输入给出多个独立值$n$。 对于每一个，我们要么构建这样的排列，要么确定不存在。 

总量约束$n$跨越所有测试用例意味着任何解决方案的总大小都必须是线性的。 一个$O(n \log n)$方法已经是安全的，但是任何二次方都会失败，因为最坏的情况达到$2 \cdot 10^5$元素。 

最精致的边缘情况是小$n$。 为了$n = 2$，不存在有效的排列，因为交换给出$[2,1]$，这违反了末端元素的邻接条件，因为两个元素都没有不同的邻居$1$两侧。 为了$n = 3$，每个排列要么创建一个不动点，要么打破邻接约束，因此它也会失败。 These cases must be explicitly excluded.

 ## 方法

 蛮力会尝试所有排列并检查两个约束。 有$n!$排列，以及每次检查成本$O(n)$，所以即使对于$n = 10$。 

关键的观察结果是，邻接约束强制数字出现在连续的值块中。 如果我们将数字放置在连续整数的小反向段中，那么在每个段内，每个元素都与一个恰好相差 1 的数字相邻。 这建议将排列分组为大小的块$2$或者$3$结构在当地得以保留。 

然后，定点约束确定哪些块大小是安全的。 简单的对交替交换可以干净地工作：交换每个相邻对可确保没有元素停留在其原始位置，并且每个元素都与其连续的邻居相邻。 

什么时候$n$是奇数且大于$3$，我们可以通过形成一个大小的块来处理剩余的结构$3$一开始，然后继续交换对。 

这导致了具有线性时间的建设性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了|
 | 建设性配对|$O(n)$|$O(n)$| 已接受 |

 对于每个测试用例，我们直接构建排列。 

## 构建思路

 我们处理的数字来自$1$到$n$并将它们分组。 

1.如果$n = 2$或者$n = 3$， 输出$-1$因为没有任何安排可以同时满足这两个约束。 这是通过枚举小案例的可能性来验证的。 

2. 对于$n \ge 4$，开始以块的形式构建排列。 

3.如果$n$是奇怪的，首先放置$3, 1, 2$。 这避免了固定点并确保块内连续值之间的相邻性。 

4.然后对于从下一个未使用的索引开始的剩余数字，处理对$(i, i+1)$并按交换顺序输出它们$(i+1, i)$。 这保证没有固定点。 

5. 继续，直到使用完所有数字。 

## 为什么它有效

 在每对交换的内部$(i, i+1)$，两个数都与其连续值相邻，满足邻接条件。 逆转并不能保证$i$也不$i+1$被放置在其原始索引处。 最初的$3$-cycle块在不破坏邻接性的情况下处理奇偶校验，之后结构是统一的。 由于每个数字要么位于交换对中，要么位于初始块中，因此全局满足所有约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        if n == 2:
            print("1 2")
            continue
        if n == 3:
            print("-1")
            continue

        res = []

        i = 1
        if n % 2 == 1:
            res.extend([3, 1, 2])
            used = {1, 2, 3}
            i = 4
        else:
            used = set()

        i = 1
        res = []
        if n % 2 == 1:
            res.extend([3, 1, 2])
            i = 4
        else:
            i = 1

        while i <= n:
            if i + 1 <= n:
                res.append(i + 1)
                res.append(i)
                i += 2
            else:
                break

        print(*res)

if __name__ == "__main__":
    solve()
```该构造完全是贪婪的，并且仅依赖于固定的本地交换。 奇怪的情况是通过破坏对称性的一个小的初始排列来处理的，之后配对是安全的。 

一个微妙的点是，我们永远不会将数字放在其原始索引处，因为每个块要么交换位置，要么在循环中排列。 该实现确保线性遍历而无需回溯。
