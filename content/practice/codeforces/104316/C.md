 ## 解决方案
 ## 问题理解

 给定一个二进制字符串，并构建一个方阵，其行都是该字符串的循环移位。 零行是字符串本身，第一行右移一位，第二行右移两位，依此类推，直到第 n 行减一。 

这种构造产生了一个非常结构化的矩阵：每一行都包含相同的字符，只是旋转了。 任务是找到该矩阵内最大的轴对齐矩形，使得矩形中的每个单元格都是 1。 

这里的矩形是任何连续的行块和连续的列块。 所以我们正在寻找一个完全由 1 组成的子矩阵，使其面积最大化。 

约束足够大，任何尝试显式构建 n × n 矩阵的解决方案都立即不可行。 当所有测试用例的总长度达到 200 万时，即使存储它也已经太昂贵了。 这迫使我们直接对循环移位的结构进行推理，而不是具体化网格。 

当字符串中只有很少或根本没有时，就会出现关键边缘情况。 如果没有，答案为零，因为不存在矩形。 如果字符串全为 1，则整个矩阵都被 1 填充，答案为 n 乘以 n。 

当形成多个块时，会出现更微妙的情况。 例如，在像这样的字符串中`110011`，最长的连续块的长度为二，但这样的块有多个。 只计算总数量的天真想法会错误地高估答案，因为跨班次的数量并不是全局一致的。 

天真的思维的另一个失败案例是假设每一行独立贡献。 即使每一行都有很长的一段，由于循环移位，这些段可能不会跨不同行排列，这正是问题变得不平凡的原因。 

## 方法

 暴力方法将构造完整的 n × n 矩阵，然后在二进制矩阵算法中运行最大矩形。 构造矩阵的成本已经是 O(n²)，而在测试中 n 总共达到 2·10⁶ 是不可能的。 即使 n = 200000 的单个测试也会远远超出内存限制。 

即使我们避免显式构造，我们仍然需要评估所有 O(n²) 矩形，这基本上太大了。 

关键的观察来自于理解循环移位对结构的影响。 每行在旋转之前都是相同的，这意味着行的模式被保留但被移动。 这意味着任何好的矩形都不是由网格中的任意局部结构创建的，而是由单个图案沿着一致的偏移量重复对齐创建的。 

关键的简化是限制因素是原始循环字符串中最长的连续块。 如果我们确定循环意义上连续块的最大长度，称之为 L，那么我们总是可以通过跨连续移位对齐这些块来构造矩阵中的 L × L 正方形。 同时，任何矩形在任一维度上都不能超过 L，因为任何长于 L 的行或列段都需要在字符串的某些移位版本中进行更长的运行，而这并不存在。 

这将问题简化为找到字符串中最长的循环运行并返回其平方。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 构建矩阵+暴力矩形| O(n²) | O(n²) | 太慢了 |
 | 最佳循环运行减少| 每次测试 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 ## 1. 扩展字符串以进行循环处理

 我们将字符串与其自身连接起来以线性模拟循环行为。 这允许原始字符串的任何环绕段显示为普通子字符串。 

此步骤是必要的，因为最长的一串可能会环绕字符串的末尾。 

## 2. 找到双倍字符串中最长的连续段

 我们在跟踪连续字符串的同时扫描双倍字符串，但我们只考虑长度为 n 的游程，因为循环游程不能超过原始长度。 

每当我们遇到零时，我们都会重置当前的游程长度。 遇到的最大值是最长的循环游程 L。 

该值表示经过适当旋转后可以在矩阵的任何行中一致对齐的 1 块的最大长度。 

## 3.方阵推理

 一旦 L 已知，我们就会观察到在任何行中，在某个循环位置上都存在 L 个连续的段。 因为行是循环移位，所以我们可以将这些段跨 L 个连续行对齐，以便它们在一组一致的列中重叠。 

这会产生一个 L × L 全 1 矩形。 

## 4.输出L平方

 答案就是这个最大正方形的面积。 

### 为什么它有效

 每行都是相同二进制模式的旋转，因此维护矩形的唯一方法是为每个选定的行选择完全位于一系列 1 内部的列间隔。 任何循环对齐中的最大此类游程恰好是 L。在任何对齐中，没有行可以贡献超过 L 个连续行，因此有效矩形的尺寸都不能超过 L。由于我们可以通过对齐最大游程来构造 L by L 块，因此 L² 既是可实现的，也是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        if n == 0:
            print(0)
            continue
        
        # double string for circular handling
        ss = s + s
        
        best = 0
        cur = 0
        
        # we only need to scan at most 2n characters
        for i, ch in enumerate(ss):
            if ch == '1':
                cur += 1
                # cap because cyclic window cannot exceed n
                if cur > n:
                    cur = n
            else:
                cur = 0
            best = max(best, cur)
        
        print(best * best)

if __name__ == "__main__":
    solve()
```该解决方案依赖于扫描双倍字符串来捕获循环运行。 n 处的上限很重要，因为如果没有它，双倍字符串中类似“111...111”的运行可能会错误地超出有效的循环解释。 

最后的平方步骤直接对应于形成跨行和列的最大对齐块。 

## 工作示例

 ### 示例 1

 考虑`s = 00111`。 

我们建造`s + s = 0011100111`。 

我们扫描运行的：

 - 最长的连续是`111`，所以 L = 3。 

我们输出9。 

这对应于选择出现的三个连续列并将它们跨三个适当移动的行对齐。

### 示例 2

 考虑`s = 10101`。 

然后`s + s = 1010110101`。 

最长的连续数是 1，因为它们是孤立的。 

所以L = 1，答案是1。 

这表明，即使有很多矩形，缺乏邻接也会阻止任何更大的矩形。

 ## 边缘情况

 仅包含零的字符串不会产生有效的运行，因此扫描永远不会增加当前计数器，并且最佳值保持为零。 该算法正确地输出零，这与不存在由 1 组成的矩形的事实相匹配。 

包裹跨越边界的字符串，例如`1100011`，通过加倍字符串可以正确处理。 奔跑`11`最后连接到`11`在双倍表示的开头，产生正确的循环最大值。 

在实现中，全一字符串的上限为 n，确保双倍表示不会错误地产生比实际循环结构更长的游程。 这将产生 L = n 和一个 n × n 的矩形。
