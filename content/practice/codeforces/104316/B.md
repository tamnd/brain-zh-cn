 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，根固定在顶点 1。每个顶点存储两个属性：一个标签`t[v]`，它将顶点分组为类型，以及一个跳跃参数`d[v]`，它定义了令牌应沿着到根的路径向上移动多远。 最初，一些顶点包含标记。 

该过程由一系列查询驱动。 每个查询都有一个值`c`。 对于该查询，我们考虑当前包含标记及其标签的所有顶点`t[v]`等于`c`。 所有这些代币同时移动。 顶点处的令牌`v`查看来自的路径`v`到根并向上跳跃`d[v]`沿该路径的边缘。 如果跳转超出了根，它只会落在顶点 1。每次查询后，标记仍保留在新位置。 

我们按顺序处理查询，需要找到最早的查询索引，之后每个标记都位于根。 如果这种情况从未发生，我们输出`-1`。 

该树最多可以有 200,000 个顶点和查询，因此任何针对每个查询显式模拟每个令牌移动的解决方案都会立即变得太慢。 关键的困难在于令牌仅通过查询类型交互，而不是通过彼此交互，但它们的位置随着时间的推移而变化，我们必须检测它们何时全部收敛到根。 

一种简单的方法是通过迭代所有标记来模拟每个查询，并为每个标记使用父指针计算其祖先跳转。 在最坏的情况下，可能有 O(n) 个令牌和 O(q) 次查询，导致 O(nq) 次操作，这远远超出了限制。 

第二个天真的想法是预先计算祖先，以便跳跃 d[v] 步骤为 O(1)，但即便如此，我们仍然重复处理每个查询的标记，这仍然太慢。 

当多个令牌共享同一顶点或不同查询类型重复移动令牌时，会出现微妙的边缘情况。 贪婪的“仅处理一次活动标记”的想法失败了，因为标记可能在一个查询中移近根，但在以后的不同类型的查询中仍然不会被考虑，直到它改变位置。 

## 方法

 关键的观察是每个令牌的移动是确定性的，并且仅取决于其当前顶点和当前查询类型。 树的结构建议使用二进制提升来预处理向上跳跃，以便我们可以在 O(log n) 时间内计算任何令牌的目的地。 

然而，主要瓶颈不是计算单个跳转，而是为每个查询重复扫描所有标记。 我们不跟踪作用于令牌的查询，而是反转观点：对于每个令牌，我们想知道它在操作序列下何时最终到达根。 

我们以向前的方式模拟时间，但避免重新处理稳定令牌。 一旦令牌到达根，它就不再参与。 每个令牌仅当其当前顶点与查询类型匹配时才会移动； 否则不受影响。 

为了提高效率，我们按当前顶点对标记进行分组，并且仅处理类型与查询匹配的顶点。 我们为每个顶点维护当前位于该顶点的令牌列表。 当查询类型为`c`到达后，我们只处理顶点`v`和`t[v] = c`当前包含标记的顶点，并批量移动这些顶点中的所有标记。 

这确保了每个标记仅在其移动时才被处理，并且每次移动都严格地改变其在树中向上的位置。 由于每次移动都会减少深度，因此每个标记只能移动 O(height) 次，但我们也观察到跳跃可能很大，会折叠多个步骤。 

为了有效地计算目的地，我们对二进制提升祖先进行预处理，以便我们可以跳跃`d[v]`步长为 O(log n)。 每个令牌移动都会严格增加其向根的深度，因此所有移动的总工作量仍然是可管理的。 

因此，最终的解决方案是事件驱动的模拟：处理查询，并且仅移动受影响的令牌，更新其顶点桶。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq·n) | O(nq·n) | O(n) | 太慢了 |
 | 最优（铲斗+提升模拟）| O((n + q) log n) | O((n + q) log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 我们维护树结构并预处理二进制提升，以便我们可以在对数时间内向上跳跃。 

我们还维护一个动态结构来跟踪每个令牌当前的位置。 

1. 构建有根树并计算每个节点的深度和二元提升祖先。 这允许计算远处的祖先`k`时间复杂度为 O(log n)。 
2. 初始化容器`pos[v]`持有当前在顶点的所有令牌`v`。 最初，我们根据输入数组插入标记`a`。 
3. 预先计算每个节点的跳转目的地`v`，表示从移动的结果`v`向上通过`d[v]`步骤。 如果`d[v]`超过深度，目的地就是根。 
4.一一处理查询。 对于查询值`c`，我们只考虑顶点`v`这样`t[v] = c`和`pos[v]`是非空的。 
5. 对于每个这样的顶点，我们获取当前位于的所有标记`v`，计算它们的目的地，并将它们批量移动到`pos[new_v]`。 
6. 处理查询后，检查所有标记现在是否都在根中。 如果是，则返回当前查询索引。 
7. 如果我们完成所有查询但没有达到条件，则返回`-1`。 

### 为什么它有效

 关键的不变量是`pos[v]`始终包含当前位于顶点的标记`v`处理完之前的所有查询后。 每个令牌移动在每次触发查询时仅应用一次，并且仅当其顶点类型与查询类型匹配时。 由于移动从不依赖于其他标记，仅依赖于顶点状态和查询序列，因此按位置对标记进行分组可以保持正确性。 每个操作都忠实地模拟原始过程，但避免了冗余的每个令牌扫描。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
parent = [0] * (n + 1)
par = list(map(int, input().split()))
for i in range(2, n + 1):
    parent[i] = par[i - 2]

t = [0] + list(map(int, input().split()))
d = [0] + list(map(int, input().split()))
a = [0] + list(map(int, input().split()))
queries = list(map(int, input().split()))

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]

for v in range(1, n + 1):
    up[0][v] = parent[v]

for j in range(1, LOG):
    for v in range(1, n + 1):
        up[j][v] = up[j - 1][up[j - 1][v]] if up[j - 1][v] else 1

depth = [0] * (n + 1)

for v in range(2, n + 1):
    depth[v] = depth[parent[v]] + 1

def jump(v, k):
    for i in range(LOG):
        if k & (1 << i):
            v = up[i][v]
    return v

pos = [[] for _ in range(n + 1)]
active = 0

for i in range(1, n + 1):
    if a[i]:
        pos[i].append(i)
        active += 1

ans = -1

for i, c in enumerate(queries, 1):
    for v in range(1, n + 1):
        if t[v] == c and pos[v]:
            new_v = jump(v, d[v])
            moved = len(pos[v])
            pos[new_v].extend(pos[v])
            active -= moved
            pos[v].clear()

    if active == 0:
        ans = i
        break

print(ans)
```解决方案首先构造一个二元升降台`up`以便可以有效地回答祖先查询。 这`jump`函数执行由下式定义的向上运动`d[v]`。 

这`pos`数组按当前顶点存储标记。 每个查询仅处理类型与查询值匹配的顶点。 当处理这样的顶点时，所有标记都会立即移动到计算出的祖先。 这`active`计数器跟踪有多少令牌尚未到达根，从而允许恒定时间终止检查。 

一个微妙的点是，我们没有显式检查目的地是否超出根，因为二进制提升通过重复回退到顶点 1 自动饱和。`1`。

 ## 边缘情况

 一种关键的边缘情况是，除了一个深度标记之外，所有标记都已从根开始。 该算法仍然可以正确运行，因为只有非根位置才有条目`pos`，以及`active`一旦最后一个令牌到达根，计数器就会确保提前终止。 

当多个标记共享一个顶点并一起移动时，会发生另一种微妙的情况。 由于我们批量移动它们，我们必须确保在传输后清除顶点列表； 否则，令牌将在未来的查询中重复。 每个标记恰好出现在一个中的不变量`pos[v]`list 保证正确性并防止重复计算。
