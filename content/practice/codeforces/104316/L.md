 ## 解决方案
 ## 问题理解

 我们得到一个仅由两个字符组成的字符串：脱字符号和下划线。 我们可以在字符串中的任何位置插入其他字符，但不允许删除或重新排序现有字符。 在所有插入之后，生成的字符串必须满足覆盖规则：最终字符串的每个位置必须至少属于两个允许模式之一的出现，即由两个插入符组成的两字符模式或三字符模式插入符下划线插入符。 这些事件允许重叠。 

目标是使原始字符串在此规则下“安全”，同时添加尽可能少的字符。 

解释这一点的一种有用方法是，最终字符串必须完全被图块覆盖，其中每个图块要么是“^^”，要么是“^_^”，并且每个字符位置至少包含在一个图块中。 我们正在尝试插入字符，以便原始字符串成为某个完全可平铺覆盖的字符串的子序列。 

约束很小，字符串长度最多为 100，测试用例最多为 100 个。 这立即排除了任何立方或更糟糕的字符串构造以及严重的状态扩展。 二次或三次动态程序是安全的，但子串上的任何指数都是不必要的。 

微妙的困难在于，就单个字符修复而言，插入不是本地的。 固定一个下划线可能会强制周围的结构，并且插入符可以以多种方式参与重叠的图块。 对局部违规的天真贪婪修复将会失败，因为有关字符串一部分的决定可能会强制稍后进行额外的插入。 

当下划线间隔开时，会出现一种常见的失败情况，因此局部修复下划线会在其他地方产生间隙。 例如，在像“_^_”这样的字符串中，人们可能会尝试独立修复每个下划线，但覆盖所需的共享插入符结构将两端耦合起来，因此天真的本地修复了计数过多或计数不足的插入。 

## 方法

 一个暴力的想法是尝试通过以所有可能的方式插入字符来构建最终的字符串，并检查结果是否可以被有效的图块完全覆盖。 对于每个候选最终字符串，我们将通过扫描所有位置并检查每个位置是否属于有效的“^^”或“^_^”出现来验证覆盖条件。 然而，插入字符的方式数量随着字符串长度的增加而组合增长，甚至将最终长度限制在一个适度的范围内，搜索空间也会变得巨大。 

关键的观察是我们不需要在全局范围内明确地推理图块。 相反，最终字符串的有效性可以在本地强制执行：每次我们确定一个字符是“^_^”模式的中心时，它的邻居必须强制为插入符，并且任何一对连续的插入符都可以支持“^^”图块。 这使得问题可以简化为从左到右构建字符串，同时强制执行本地一致性。 

我们模拟构建最终字符串，同时将原始字符串作为子序列嵌入。 在每一步中，我们决定是从原始字符串中取出下一个字符还是插入一个字符。 每次追加一个字符时，我们都会确保新形成的长度为 3 的窗口不会违反下划线两侧必须有插入符号的规则。 这将全局覆盖约束转换为滚动局部检查。 

这将问题转化为对原始字符串中的位置和构造字符串的最后两个字符的动态编程过程，因为只需要最后两个字符来验证添加新字符是否会创建无效中心。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力插入+验证| 指数| 指数| 太慢了 |
 | DP 前缀和最后两个字符 | O(n·4·2) | O(n·4) | 已接受 |

 ## 算法演练

 我们逐步构建最终字符串，并跟踪我们已经消耗了多少原始字符串。 

1. 我们定义一个由原始字符串中的索引和构造字符串的最后两个字符组成的状态。 最后两个字符足以检测添加新字符是否会创建以后面一位为中心的禁止配置。 
2. 在任何状态下，我们都会考虑将插入符号或下划线附加到构造的字符串中。 该附加字符要么是插入，要么与原始字符串中的下一个未使用的字符匹配，在这种情况下，我们将指针在原始字符串中前进。 该模型都允许以统一的方式进行操作。 
3. 当我们追加一个字符时，我们立即验证唯一可能的新约束。 如果前面两个位置的字符是下划线，则当前字符和前一个字符都必须是插入符号，因为它们在该下划线周围形成所需的“^_^”模式。 如果违反此条件，则放弃转换。 
4. 每次我们选择追加一个字符而不消耗原始字符串中的一个字符，我们的成本就会增加一。 如果我们从原始字符串中消费，成本不会增加。 我们始终致力于最大限度地降低这一成本。 
5. 我们继续，直到我们消耗了整个原始字符串并构建了有效的最终配置。 所有有效完成的最小成本就是答案。 

### 为什么它有效

 核心不变量是，当且仅当潜在“^_^”模式的完整“中心位置”在完全确定时没有被违反时，任何部分构造的字符串仍然可扩展为有效的完全覆盖字符串。 问题中的每个约束都是长度为 3 的窗口的局部约束，一旦某个位置成为此类窗口的中心，其两个邻居此时在 DP 转换中就已经固定。 这意味着未来的插入无法修复已经暴露的违规，并且在这些窗口之外不存在隐藏的远程条件。 因此，修剪无效转换不会消除任何全局有效的构造，并且每个有效的最终字符串都可以通过某些转换序列到达。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**9

def solve():
    t = int(input())
    
    for _ in range(t):
        s = input().strip()
        n = len(s)
        
        # dp[i][a][b] = minimum insertions after consuming i chars of s
        # and ending with last two characters (a, b)
        # encode: 0 = '^', 1 = '_'
        
        dp = [[[INF] * 2 for _ in range(2)] for _ in range(n + 1)]
        dp[0][0][0] = 0  # dummy start state
        
        for i in range(n + 1):
            for a in range(2):
                for b in range(2):
                    cur = dp[i][a][b]
                    if cur == INF:
                        continue
                    
                    for c in range(2):
                        # check constraint for window (prev2, prev1, c)
                        # prev2 is unknown here; we simulate by storing last two only,
                        # so we interpret (a,b) as last two, c new => window is (a,b,c)
                        
                        # if b is '_' (1), then a and c must be '^' (0)
                        if b == 1:
                            if not (a == 0 and c == 0):
                                continue
                        
                        # determine next state
                        ni = i
                        cost = cur + 1
                        
                        if i < n:
                            if s[i] == ('^' if c == 0 else '_') and i < n:
                                # match original character
                                ni = i + 1
                                cost = cur
                        
                        # if we didn't consume s[i], we still keep i unchanged
                        
                        if ni <= n:
                            dp[ni][b][c] = min(dp[ni][b][c], cost)
        
        ans = min(dp[n][a][b] for a in range(2) for b in range(2))
        print(ans)

if __name__ == "__main__":
    solve()
```该实现将构造字符串的最后两个字符存储为两位状态。 这已经足够了，因为约束变得可执行的唯一时间是附加第三个字符时，这完成了长度为 3 的窗口。 

每个转换都会尝试添加插入符号或下划线。 如果添加的字符与原始字符串的下一个未使用的字符匹配，我们将其视为来自原始字符串的消耗； 否则，插入会增加答案。 

关键的检查是窗口验证：如果最后三个字符的中间是下划线，则两个相邻字符都必须是插入符。 当附加第三个字符时，这会立即强制执行。 

DP 跟踪每个可能的前缀消耗和最后两个字符配置的最佳成本。 

## 工作示例

 考虑字符串“^_”。 DP 从一个空的构造状态开始，并逐渐尝试放置角色。 一种最佳路径是在末尾插入额外的插入符号以完成“^_^”，这满足覆盖规则。 

| 步骤| 我在 s | 最后两 | 行动| 成本|
 | ---| ---| ---| ---| ---|
 | 0 | 0 | （开始）| 插入“^”| 1 |
 | 1 | 0 | ^ | 匹配 s | 中的 '^' 1 |
 | 2 | 1 | ^^ | 插入“^”| 2 |
 | 3 | 1 | ^^ | 匹配 '_' | 2 |
 | 4 | 2 | ^_^ | 完成 | 2 |

 这表明下划线不能单独存在，必须嵌入到“^_^”结构中，强制至少插入一次。 

现在考虑“^^”。 这已经是兼容的，因为两个插入符可以形成一个“^^”图块。 

| 步骤| 我在 s | 最后两 | 行动| 成本|
 | ---| ---| ---| ---| ---|
 | 0 | 0 | （开始）| 匹配 '^' | 0 |
 | 1 | 1 | ^ | 匹配 '^' | 0 |
 | 2 | 2 | ^^ | 完成 | 0 |

 这证实了算法自然更喜欢在可能的情况下配对插入符而不进行插入。

 ## 边缘情况

 单个下划线输入突出显示最强的约束。 DP 必须强制插入周围的插入符以允许有效的“^_^”模式，并且任何试图使其不被覆盖的解决方案在检查窗口约束时都会立即失败。 

诸如“^_^_^”之类的长交替字符串强调重叠行为。 每个下划线已经具有部分结构，并且 DP 确保插入符号在相邻模式中有效地重用，而不是不必要地重复插入。
