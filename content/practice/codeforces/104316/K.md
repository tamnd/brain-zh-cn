 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，都有 n 个按顺序访问的商店，并且有 m 个可能的苹果类型。 每个商店可能包含一些苹果类型的子集。 当丹尼亚参观一家商店时，他会拿那里出售的每种类型的苹果，然后将它们放入背包中。 

不同的是，背包有取消规则。 每当离开商店后背包中出现两个相同类型的苹果时，背包中的所有苹果都会立即消失。 这意味着到目前为止，只有每种类型添加的次数的奇偶校验很重要，并且当一种类型出现两次时，所有内容都会重置为零。 

有些店不知名。 对于这些商店，我们可以任意选择它们的内容，包括将它们设为空或使其包含苹果类型的任何子集。 我们的目标是选择这些未知的商店，以最大化最终商店后背包中剩余的苹果数量。 

每个场景的输出是在给定未知商店的最佳选择的情况下，所有 n 个商店之后苹果的最大可能最终数量。 

这些约束意味着所有测试用例中的商店条目总数最多为 200000 个。这排除了任何尝试枚举未知商店的所有子集或彻底模拟选择的解决方案。 每个测试用例我们需要一种线性或接近线性的方法，理想情况下用 O(1) 或摊销的 O(1) 工作处理每个商店一次。 

当天真的方法假设我们可以独立优化每个未知商店时，就会出现微妙的失败案例。 例如，如果我们贪婪地尝试避免本地碰撞，我们仍然可能强制未来重置。 交互是全局的，因为一旦某个类型重复，无论何时发生，所有内容都会丢失。 

另一个微妙的情况是所有商店都是未知的。 一个天真的想法是包括所有地方的所有类型，但这会在第二家商店之后立即倒闭。 相反，最佳策略是精确控制碰撞发生的时间，理想情况下尽可能长时间地延迟任何重复类型或完全避免重复。 

## 方法

 如果我们忽略未知商店的灵活性，则该过程是确定性的。 我们简单地模拟每个商店，维护一组活动苹果类型或位掩码，并在出现重复项时应用取消规则。 这在 O(total apples) 中有效，但它不能帮助我们选择未知的商店。 

困难在于，未知的商店使我们能够完全控制子集，但取消规则会在第一次重复时破坏所有内容。 这表明任何类型在最终构造中任何地方出现两次本质上都是有害的，因为它会消除所有积累的进度。 

关键的观察是，在任何成功的构建中，每种苹果类型最多可以在我们实际选择“激活”的所有商店中出现一次。 如果一个类型在我们选择的两个不同的商店中出现两次，那么整个结构在第二次出现后就变得毫无用处，所以最终的答案在那一刻会崩溃到零。 

这减少了选择一组商店出现的问题，使得没有苹果类型在所选商店中被使用两次。 每个商店都贡献一组类型，因此我们希望包含尽可能多的商店，但前提是它们的类型集在使用的类型方面不相交。 由于未知的商店可以任意制作，因此它们总是可以调整以避免冲突，除非我们选择刻意引入新类型。

最优策略变得对商店贪婪：我们维护哪些类型已经被使用过。 对于每个商店，如果已知，我们就被迫考虑其固定集。 如果未知，我们可以最佳地选择它的集合：如果我们想增加答案，我们应该恰好选择一种新的未使用类型，否则将其留空。 任何在未知商店中挑选一种以上新类型的尝试都是毫无意义的，因为它会消耗多种新鲜资源，但仍然只能按顺序贡献一个商店步骤。 

因此，该过程简化为跟踪有多少商店可以贡献至少一种以前未使用的类型，然后再耗尽所有 m 类型或遇到强制冲突。 

更精确的解释是，唯一重要的是我们可以在时间轴上引入某种类型“第一次出现”多少次。 每次我们分配一个以前没有出现过的类型时，我们都会在最终计数中获得一个苹果，除非强制重复会提前触发崩溃。 由于崩溃是灾难性的，我们永远不希望任何类型出现两次。 

因此，答案变成了我们可以实现的不同苹果引入的最大数量，它受到 m 和我们能够在不冲突的情况下引入新类型的商店位置数量的限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（选择未知商店的子集）| 指数| O(米) | 太慢了 |
 | 最优（贪婪地跟踪第一次出现）| O(n + 总 ki) | O(米) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们维护一个布尔数组used[1..m]，用于跟踪苹果类型是否已在任何加工商店中引入。 这代表再次添加是否会立即触发全局崩溃规则。 
2. 我们将计数器答案初始化为0，代表最后有多少个苹果可以安全地存在于背包中而不触发重置。 
3. 我们按顺序从 1 到 n 迭代商店。 对于每家商店，我们都会检查其已知类型列表。 
4. 如果商店未知（ki = 0），我们将其视为引入新苹果类型（如果存在）的机会。 我们扫描任何尚未使用的类型。 如果我们找到一个，我们将其标记为已使用，并将答案增加 1。我们不会引入超过一种类型，因为引入多种只会冒未来不可避免的重复风险，而不会增加最终的安全计数。 
5. 如果该商店已知，我们会检查其类型。 如果该商店中的任何类型已被标记为已使用，那么完全引入该商店将导致重复冲突，从而破坏所有进度。 在这种情况下，最好的策略是跳过从这家商店拿走任何苹果，实际上贡献 0。否则，如果所有类型都未使用，我们可以安全地拿走所有苹果：我们将每种类型标记为已使用，并根据商店的大小增加答案。 
6. 我们继续这个过程，直到处理完所有商店，累积最大数量的安全介绍。 

关键的微妙之处在于我们永远不允许重复使用类型。 一旦使用某种类型，它将被永久禁止将来包含。 

### 为什么它有效

 在任何时间点，如果一种类型在背包历史记录中出现两次，一切都会重置，使得之前的所有收益都变得无关紧要。 这迫使任何旨在最大化最终剩余苹果的有效构造，以确保每种类型在所选添加的整个序列中最多全局引入一次。 

该算法严格维护这一不变性：类型在第一次引入时被标记为已使用，并且不再引入。 任何违反此不变量的商店都会被部分忽略或跳过。 因为未知的商店可以自由选择，所以我们永远不会因为将它们限制为最多一种新类型而失去最优性，因为就未来的冲突而言，其他类型要么是多余的，要么是立即危险的。

因此，该算法总是按时间顺序构建最大的非重复类型引入集合，这直接对应于最大可能的最终存活苹果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        used = [False] * (m + 1)
        ans = 0

        for _ in range(n):
            arr = list(map(int, input().split()))
            k = arr[0]
            if k == 0:
                # unknown shop: try to introduce one new type if possible
                added = False
                for x in range(1, m + 1):
                    if not used[x]:
                        used[x] = True
                        ans += 1
                        added = True
                        break
                continue

            types = arr[1:]
            conflict = False
            for x in types:
                if used[x]:
                    conflict = True
                    break

            if conflict:
                continue

            for x in types:
                if not used[x]:
                    used[x] = True
                    ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```实现遵循每个类型只能贡献一次的不变量。 对于已知的商店，我们首先检查它们是否会通过重用类型来违反规则。 只有在安全的情况下，我们才会食用该店的所有新鲜品种。 对于不知名的店铺，我们贪婪地推出一种新的类型。 

一个微妙的点是，未知的商店在 m 上线性扫描以找到自由类型，只有当 m 很小时才可以接受； 在更严格的优化设置中，这将被替换为指向下一个未使用类型或优先级结构的指针。 

## 工作示例

 ### 示例 1

 考虑 m = 3 种类型和 3 家商店的情况：

 商店 1：{1, 2}

 商店 2：{3}

 店铺3：未知

 我们从没有使用过的类型开始。 

| 店铺 | 行动| 二手类型 | 回答 |
 | ---| ---| ---| ---|
 | 1 | 取 1,2 | {1,2} | 2 |
 | 2 | 拿3 | {1,2,3} | 3 |
 | 3 | 不选择新类型（没有留下或避免风险）| {1,2,3} | 3 |

 这表明，一旦所有类型都用尽，不知名的商店就无法改善结果。 

### 示例 2

 m = 4，商店：

 商店 1：{1,2}

 店铺2：未知

 商店 3：{1,3}

 | 店铺 | 行动| 二手类型 | 回答 |
 | ---| ---| ---| ---|
 | 1 | 取 1,2 | {1,2} | 2 |
 | 2 | 分配 3 | {1,2,3} | 3 |
 | 3 | 冲突 1 | {1,2,3} | 3 |

 这表明，一旦使用一种类型，它就会永久地限制未来的商店。 商店 3 不能安全使用，因为它会重复类型 1，因此必须完全跳过。

 ## 边缘情况

 当所有商店都是未知的时，算法会贪婪地为每个商店分配一种新类型，直到类型用完。 由于每种类型只能使用一次，因此答案以 m 为界，算法自然会在该值处饱和，而不会触发任何冲突。 

当已知商店包含之前已经使用过的类型时，算法会完全跳过它。 这模拟了这样一个事实：包含它会强制重复并破坏最优性。 跳过是安全的，因为一旦存在重复，已知商店内的部分选择就无法避免重复。 

当商店是空的或未知的并且没有未使用的类型时，它就没有任何贡献。 这正确地捕捉到了在用尽所有可用的不同类型之后，在不违反不重复约束的情况下不可能有进一步的增益。
