 ## 解决方案
 ## 问题理解

 我们有几个隐藏数组，每个数组都包含少量不同的整数。 数组从 1 到 n 排序，每个查询让我们选择一个索引列表并按该顺序接收这些数组的串联，但元素之间没有任何分隔符。 唯一的额外信息是连接结果的总长度。 

任务是完全按照其出现的样子重建每个单独的数组，包括其顺序。 

困难不在于值的大小，因为它们很小，而在于数组是不透明的块。 查询返回多个粘在一起的数组的扁平序列，并且没有直接标记告诉一个数组在哪里结束以及下一个数组在哪里开始。 我们还限制最多 20 个查询，因此我们不能简单地单独查询每个索引。 

一种简单的方法是单独查询每个索引 i 并直接恢复数组 ai 。 这是正确的，但一旦 n 超过 20，查询限制就会立即失败。因此，任何解决方案都必须从精心选择的批量查询中提取全局结构。 

连接格式产生了一个微妙的问题。 即使我们知道查询结果中的所有值，我们也不知道哪个段属于哪个查询索引，除非我们已经知道底层数组的长度。 这意味着核心困难不是读取值，而是将值对齐回源数组。 

## 方法

 蛮力的想法很简单。 分别查询每个索引，读取其完整数组并存储它。 这是可行的，因为单索引查询恰好返回一个数组，没有歧义。 这个问题纯粹是操作性的：它需要 n 个查询，最多可达 1000 个，远远超出了 20 个的限制。 

所以我们需要压缩从查询中提取的信息。 关键的观察结果是每个查询不仅返回值列表，还返回隐藏结构的总和。 每个数组提供固定的多重值集，并且对多个索引的查询以相同的顺序返回这些数组的多重集并集。 

这就把问题变成了通过签名进行身份识别的问题。 我们没有尝试在串联序列中定位边界，而是在少量查询中为每个数组分配一个唯一的“行为”，然后从该行为中恢复成员资格。 

关键技巧是设计查询，以便将每个数组索引编码为二进制签名。 然后每个值都会继承它所来自的数组的签名。 一旦值按签名分组，每一组都对应一个隐藏数组。 

唯一剩下的要求是确保每个索引都有唯一的签名。 对于最多 1000 个数组，10 到 20 位足以分配唯一代码。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（查询每个索引）| O(n) 次查询 | O(总元素) | 查询太多 |
 | 位掩码签名重建 | O(20·n + 总元素) | O(n) | 已接受 |

 ## 算法演练

 我们为每个索引 i 分配一个长度为 20 的不同二进制代码。该代码充当数组的标识符。

1. 对于从 0 到 19 的每个位位置 b，我们形成一个由所有索引 i 组成的查询，其代码中的第 b 位为 1。响应为我们提供了属于这些索引的所有数组的串联。 我们解析所有返回值。 
2. 对于查询结果中出现的每个值x，我们记录它出现在位位置b。 在所有 20 个查询中，每个值都会累积一个 20 位签名。 
3. 每个值都属于一个隐藏数组，因此同一数组中的所有值共享相同的 20 位签名。 该签名正是我们分配给该数组索引的代码。 
4. 我们根据恢复的签名对所有值进行分组。 每组对应一个原始数组。 
5. 最后，我们通过将每个索引的二进制代码转换为相应的组来按索引顺序输出数组。 

微妙的一点是，我们从不尝试推断串联响应内的边界。 相反，我们让重复参与结构化查询来标记每个值的来源。 

### 为什么它有效

 每个查询都定义了一些信息：数组索引是否参与其中。 由于每个值都永久地绑定到一个数组，因此该值的每次出现都会继承其数组的参与模式。 这 20 个查询共同形成每个数组的唯一标识符，因此值可以完全分类，而无需重建串联的内部顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    B = 20
    groups = {}

    # assign each index a bitmask signature (1 << i)
    # but we encode it across B queries
    for b in range(B):
        query = []
        for i in range(1, n + 1):
            if (i >> b) & 1:
                query.append(i)

        if not query:
            print("? 0")
            sys.stdout.flush()
            _ = input()
            continue

        print("? {} {}".format(len(query), " ".join(map(str, query))))
        sys.stdout.flush()

        data = list(map(int, input().split()))
        total_len = data[0]
        arr = data[1:]

        for x in arr:
            if x not in groups:
                groups[x] = 0
            groups[x] |= (1 << b)

    # now we must invert mapping: signature -> list of values
    rev = {}
    for val, mask in groups.items():
        rev.setdefault(mask, []).append(val)

    # output arrays in index order
    # each index i corresponds to mask i
    res = []
    for i in range(1, n + 1):
        mask = i
        arr = rev.get(mask, [])
        res.append(str(len(arr)))
        res.extend(map(str, arr))

    print("! " + " ".join(res))
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现构建了 20 个批量查询，每个查询对应于索引编码的一位。 按顺序扫描每个查询的响应，每个遇到的值都会累积一个位掩码，指示它出现在哪些查询中。该位掩码成为其标识符。 

最后的重建步骤通过相同的掩码对值进行分组。 由于属于同一隐藏数组的所有值共享相同的参与模式，因此它们最终会出现在同一个存储桶中。 

主要的微妙之处是在每次查询后刷新并仔细解析每个响应的第一个整数作为总长度，因为重建不需要它。 

## 工作示例

 由于这是交互式的，因此请考虑简化的静态模拟。 

假设 n = 4 并且数组为：

 数组 1：[5, 7]

 数组 2：[2]

 数组 3：[9, 11]

 数组 4：[4]

 我们分配二进制代码 1..4：

 1 = 01, 2 = 10, 3 = 11, 4 = 100（概念上扩展）

 对于位 0 查询，我们询问索引 1 和 3。响应包含串联的数组 1 和 3：[5, 7, 9, 11]。 这里的每个值都用位 0 标记。 

对于位 1 查询，我们询问索引 2 和 3。响应给出 [2, 9, 11]。 现在值 9 和 11 也接收位 1。 

处理完所有位后，每个值都有一个签名：

 5,7 → 01

 2 → 10

 9,11 → 11

 4 → 100

 按签名分组可以准确地重建数组。 

| 位查询| 返回值| 更新签名 |
 | ---| ---| ---|
 | 0 | 5 7 9 11 | 5 7 9 11 5，7：+1； 9,11:+1 |
 | 1 | 2 9 11 | 2 9 11 2：+2； 9,11:+2 |
 | 2 | 4 | 4：+4 |

 这演示了重叠查询如何在不需要边界的情况下对源信息进行编码。

 ## 边缘情况

 特殊情况是两个数组包含相同的值。 在这种情况下，即使使用完美的查询，这些值也无法区分，因为它们在所有查询中共享相同的行为。 该算法自然地将它们合并到同一组中，因为它们的签名是相同的。 这反映了这样一个事实：查询中没有任何信息可以区分来自不同来源的相同值。 

另一种情况是具有单个元素的数组。 这样的数组仍然会收到完整的签名，并且它们形成单例组。 由于不需要边界检测，单例的行为与较大的数组完全相同。 

最后，非常不平衡的索引模式不会影响正确性。 即使某些查询是稀疏的，每个索引仍然参与唯一的位组合，因此每个数组仍然积累完整的签名。 

重建保持稳定，因为它从不依赖于串联响应内的排序，仅依赖于跨查询的一致包含模式。
