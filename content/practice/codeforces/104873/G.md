 ## 解决方案
 ## 问题理解

 我们得到一个仅由两种引用标记组成的序列。 每个标记都是左侧样式，写为`<<`或正确的风格写为`>>`。 任务不是将它们解释为固定的左括号或右括号。 相反，每个标记都是不明确的：根据周围的结构，它可以充当起始引用或结束引用。 

有效的结构是递归定义的。 空字符串有效。 两个有效的结构可以连接起来。 有效的结构可以包装为`<< A >>`或作为`>> A <<`， 在哪里`A`本身是有效的。 这意味着有两种对称的括号系统：一种的行为类似于普通括号，另一种则相反，并且两者都允许任意嵌套。 

构建这样的结构后，我们删除除报价标记之外的所有内容。 输入正是这样一个“扁平化”序列，我们必须确定它是否来自有效的结构。 如果可以的话，我们还需要通过将每个标记标记为起始引用或结束引用来重建一种有效的解释。 如果存在多种解释，任何一种都可以接受。 

输入长度最多约为 254 个字符，但由于标记是两个字符的字符串，因此有效序列长度最多约为 127。这个长度足够小，O(n) 或 O(n log n) 贪婪或基于堆栈的解析就足够了，而任何解释的指数枚举都是不必要且不安全的。 

一个微妙的问题是歧义：像这样的令牌`<<`可以在一种配对类型中充当开场白，在另一种配对类型中充当结束语。 天真的固定括号解释会立即失败。 例如，字符串`<<>>`在多种方面可能是有效的，但治疗`<<`总是像开放和`>>`总是因为关闭会错误地拒绝类似的情况`>><<`，在反向配对下有效。 

另一个边缘情况是，由于嵌套约束，结构强制通常作为开启器的令牌充当关闭器。 如果我们不仔细考虑兼容性，贪婪的选择可能会失败。 

## 方法

 一个强力的想法是尝试将每个标记作为“开始引用”或“结束引用”的所有可能解释，并另外考虑在每个嵌套级别使用哪种配对系统。 这会导致指数级增长，因为每个位置都会分支为多个角色，并且解释的数量会像加泰罗尼亚结构乘以配对方向分配一样增长。 即使长度为 100，这也是不可行的。 

关键的观察是我们实际上不需要全局决定配对类型。 我们只需要确保当我们关闭之前打开的段时，关闭令牌与打开令牌兼容。 每个开盘选择完全决定了匹配的结束符号必须是什么，反之亦然。 

这将问题简化为堆栈过程，但有一个转折：令牌可以解释为打开或关闭，但合法性取决于它是否可以匹配当前的打开结构。 当我们看到一个令牌时，如果它与堆栈顶部兼容，我们会尝试将其视为关闭令牌。 如果不兼容，就必须成为开放令牌。 

这种贪婪的决定就足够了，因为推迟强制关闭永远不会有好处：一旦无法关闭前缀，未来的重新解释就无法在不违反早期结构的情况下修复不匹配。

 ## 算法演练

 我们从左到右处理代币，同时维护一堆当前未平仓的报价。 每个堆栈条目存储开盘报价的类型。 

1. 将输入字符串解析为长度为 2 的标记 (`<<`或者`>>`）。 这简化了推理，因为每个决策都是针对每个标记，而不是针对每个字符。 
2. 维护一个空栈和一个数组`ans`存储每个令牌是否被分配为开盘（`[`) 或关闭 (`]`）。 
3. 对于每个token，检查它是否可以关闭当前的栈顶。 如果堆栈不为空并且顶部元素与当前令牌的类型不同，则令牌兼容作为关闭令牌。 这反映了配对必须在相反符号之间的规则。 
4. 如果令牌可以关闭栈顶，我们弹出栈并将该位置标记为`]`。 
5. 否则，我们将其视为打开标记，将其类型压入堆栈，并将其标记为`[`。 
6. 处理完所有令牌后，如果堆栈不为空，则不存在有效结构，我们输出失败。 

### 为什么它有效

 堆栈不变式是它始终表示当前打开的报价序列，但仍需要以相反的顺序匹配结束报价。 每次我们关闭时，我们都被迫匹配最近的未匹配的开局。 如果一个令牌不能合法地关闭顶部，那么它也不能关闭任何较早的开启器，因为所有较早的开启器都在堆栈中更深的位置，并且需要更多的嵌套违规。 因此开放是唯一一致的解释。 这个局部决策保留了全局一致性，因为嵌套约束是严格的后进先出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    # parse into tokens: "<<", ">>"
    tokens = []
    i = 0
    while i < len(s):
        tokens.append(s[i:i+2])
        i += 2
    
    stack = []
    ans = []
    
    for tok in tokens:
        if stack and stack[-1] != tok:
            # treat as closing
            stack.pop()
            ans.append(']')
        else:
            # treat as opening
            stack.append(tok)
            ans.append('[')
    
    if stack:
        print("Keine Loesung")
    else:
        print("".join(ans))

if __name__ == "__main__":
    solve()
```该实现首先将原始字符串压缩为逻辑标记，因为每个决策都以标记粒度进行操作。 堆栈存储每个未平仓报价的实际令牌类型。 关键的决定是比较`stack[-1] != tok`，它编码了有效对必须由不同符号组成的规则。 如果这个条件失败或者堆栈为空，我们必须打开一个新段。 

一个常见的错误是允许在堆栈顶部与当前标记匹配时关闭。 这将违反配对规则，因为相同的符号无法在该系统中形成有效的封闭对。

 ## 边缘情况

 一种边缘情况是字符串以通常期望关闭某些内容的标记开头，例如`>><<`。 该算法正确地处理了这个问题，因为堆栈在开始时是空的，强制第一个令牌被视为打开，无论其身份如何。 

另一个边缘情况是完全对称的字符串，例如`<<<<>>>>`，如果我们假设方向性，天真的固定解释就会失败。 该堆栈确保每个关闭决策仅由可用的开放结构驱动。 

第三种边缘情况是看起来计数平衡但结构上不可能的序列，例如`<<>>><<`。 堆栈将尝试在可能的情况下关闭，但最终会遇到无法关闭任何内容的令牌
