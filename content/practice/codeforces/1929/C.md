 ## 解决方案
 ## 问题理解

 萨沙玩重复投注游戏，每次投注要么使他的赌注乘以一个系数，要么完全输掉。 他唯一能控制的是每次赌注的大小，并且他可以根据过去的结果进行调整。 然而，赌场有一个安全限制：他输的钱永远不能超过$x$连续多次。 

问题不在于最大化预期利润或找到概率意义上的最佳投注策略。 相反，它是关于最坏情况的保证。 我们必须决定萨沙是否可以设计一种投注策略，无论结果如何（只要遵守连续亏损的规则），他的资本都可以在某个时间点任意增加。 

输入描述了多个独立的场景。 每个场景都会给出乘数$k$, 允许的最大连续损失$x$，以及初始资本$a$。 输出是一个简单的可行性决策。 

约束足够小，每个测​​试用例必须在恒定的时间内处理。 这立即排除了任何模拟或策略搜索。 答案必须来自损失和收益如何相互作用的结构特性。 

出现微妙的边缘情况时$x = 1$。 在这种情况下，萨沙永远不会被允许连续输掉两次，这极大地改变了动态。 另一个边缘情况是当$k$接近 2，因为每场胜利的增长是最小的，并且必须补偿被迫损失的区块。 

## 方法

 蛮力想法会尝试模拟投注策略和对抗性结果。 人们可以想象探索所有可能的赌注大小并跟踪每个对抗序列是否仍然允许无限增长。 这很快就变得不可能了，因为即使对于小$x$，结果序列的数量呈指数增长，并且策略空间在赌注大小的选择上是连续的。 

关键的见解是停止考虑个人投注，而是将过程压缩为先输后赢的循环。 因为萨沙不能失去超过$x$连续多次，任何最坏情况的比赛片段最多由$x$必须在获胜之前连续失败。 问题归结为，精心选择的单个获胜赌注的收益是否可以主导此类区块的累积最坏情况损失。 

这将问题转化为确定性不等式，涉及$k$,$x$， 和$a$。 唯一重要的是是否存在一种策略可以防止资本崩溃，同时确保最终的倍数增长。 该条件简化为阈值比较$k$相对$x + 1$。 

什么时候$k \ge x + 2$，胜利带来的增长足以超过最坏情况下的损失序列，萨沙总是可以无限期地恢复和放大资本。 什么时候$k \le x + 1$，任何策略都可以通过在阻止净指数增长的区块中安排损失来抵消。

 ## 算法演练

 我们独立分析每个测试用例。 

1. 阅读$k$,$x$， 和$a$。 初始资本$a$不影响最终决定，因为条件仅取决于无限制增长在结构上是否可能。 
2. 比较$k$和$x + 1$。 这种比较体现了获胜的乘数优势是否可以克服最糟糕的连败。 
3.如果$k \ge x + 2$，输出“是”。 这对应于即使在之后$x$连续亏损，单次获胜投注可以增加资本，足以抵消累计亏损并恢复增长潜力。 
4.否则输出“NO”。 在这种制度下，对抗性损失模式可能会阻止系统实现无限增长。 

### 为什么它有效

 该过程自然分解为最多长度的损失块$x$，每场比赛都以胜利告终。 这种块的净效应仅取决于是否乘以$k$大于减法$x$步骤。 门槛$k = x + 1$将每个周期增长为正的制度与非正的制度区分开来。 一旦每个周期的增长为正，重复应用就会产生无限的资本； 否则，无论策略如何，流程都是有限的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k, x, a = map(int, input().split())
    if k >= x + 2:
        print("YES")
    else:
        print("NO")
```该实现直接遵循导出的阈值条件。 每个测试用例在恒定时间内独立处理。 变量$a$被读取但未在决策中使用，因为无限增长的可能性仅取决于之间的关系$k$和$x$，而不是起始资金。 

一个常见的错误是试图合并$a$进入条件或模拟投注序列。 两者都是不必要的，并且会导致错误的推理或低效率。 

## 工作示例

 考虑案例$k = 2, x = 1, a = 7$。 自从$k = 2$和$x + 1 = 2$，我们有$k \le x + 1$，所以答案是“否”。 该系统无法保证增长，因为任何损失都会立即阻碍进一步的恢复模式。 

现在考虑$k = 5, x = 4, a = 7$。 这里$k = 5$和$x + 1 = 5$，所以再一次$k \le x + 1$，给出“否”。 尽管胜利很强大，但对手可以强制执行损失封锁，从而抵消随着时间的推移的增长。 

最后，采取$k = 88, x = 4, a = 10^9$。 这里$k \ge x + 2$，所以答案是“是”。 任何最多 4 次损失的序列都会通过足够强大的获胜乘数来补偿，从而允许资本无限制地增长。

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        k, x, a = map(int, input().split())
        out.append("YES" if k >= x + 2 else "NO")
    return "\n".join(out)

 ## 边缘情况

 当$x = 1$，系统变得极其严格，因为每次失败后都必须立即获胜。 在这种情况下，即使是中等值$k$除非超过阈值，否则可能不够$x + 1 = 2$。 该算法通过相同的比较直接处理这个问题，无需特殊的外壳即可产生正确的决策。 

什么时候$k = x + 1$，系统正好处于盈亏平衡的边界。 该算法将其分类为“NO”，反映每个周期没有净正增长，因此无法保证无限增长。
