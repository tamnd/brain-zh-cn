 ## 解决方案
 ## 问题理解

 我们有`n`按定向循环排列的站点。 从车站出发`i`，火车总是开往`i + 1`，以及从车站出发`n`它绕回车站`1`。 相邻站点之间的每次移动只花费一秒钟。 

每颗糖果都从某个车站开始`a`并且最终必须到达车站`b`。 火车可以一次装载任意数量的糖果，但有一个限制：每当火车到达一个车站时，在出发前最多只能从该车站装载一颗糖果。 

对于每个可能的起始站，我们必须计算所有糖果到达目的地所需的最短时间。 

关键困难不是运输能力。 瓶颈在于加载。 如果一个站点包含许多糖果，则在第一次访问时无法将它们全部加载。 火车必须不断绕行并多次往返，每次装载一颗糖果。 

限制很小。 最多有100个车站和200个糖果。 甚至一个$O(n^2)$或者$O(n^3)$解决方案是完全可以接受的。 重要的是发现流程的正确模型。 

一个常见的错误是专注于单个糖果并模拟加载决策。 火车可以运载无限多的糖果，因此一旦装载了糖果，其运送完全取决于到达目的地的循环距离。 真正的挑战是决定应该首先加载车站中的哪种糖果。 

另一种微妙的情况是，当多个糖果来自同一站时。 

例子：```
n = 4

1 -> 2
1 -> 3
1 -> 4
```车站有三颗糖果。 火车在第一次访问期间只能装载一个，在第二个循环期间只能装载一个，在第三个循环期间只能装载一个。 任何假设所有三个都可以立即加载的解决方案都会低估答案。 

第二个容易忽略的情况是环绕距离。 

例如：```
n = 5
5 -> 2
```距离不是`2 - 5 = -3`。 沿着循环：```
5 -> 1 -> 2
```所以距离等于`2`。 

循环距离错误会破坏整个计算。 

## 方法

 一个蛮力的想法是模拟火车在每个出发站的运动，同时做出最佳的装载选择。 由于一个车站可能包含多个糖果，并且火车多次重访车站，因此状态空间变得混乱。 即使限制很小，推理正确性也变得很困难。 

突破来自于独立观察单个站。 

假设站`u`包含`k`糖果。 

每当火车来访时`u`，它可能恰好加载其中之一。 由于访问发生在每个完整周期，因此加载时间为：```
0, n, 2n, ..., (k-1)n
```相对于第一次访问该站。 

糖果中原产地为`u`， 定义```
dist(u, v)
```作为顺时针距离`u`到`v`。 

如果我们想要所有糖果`u`尽可能早地运送，运送距离最小的糖果应先装载，其次是次小的，依此类推。 

假设糖果之间的最小距离为`u`是：```
best[u]
```糖果的数量为：```
cnt[u]
```最后一颗糖果从车站装载`u`之后离开```
(cnt[u] - 1) * n
```额外的秒数。 

为了最大限度地提高效率，最后装载的糖果应该是目的地距离最短的糖果。 那么站的完成时间贡献`u`变成```
(cnt[u] - 1) * n + best[u]
```从火车首次到达车站的那一刻开始计算`u`。 

现在考虑一个起始站`s`。 

车站前`u`可以开始加工糖果，火车必须首先到达`u`。 

让```
reach(s, u)
```是从 的顺时针距离`s`到`u`。 

然后站`u`可以强制整体完成时间为```
reach(s, u) + (cnt[u] - 1) * n + best[u]
```当最慢的站结束时整个过程结束，所以起始站的答案`s`只是所有包含糖果的站点中该数量的最大值。 

这完全消除了模拟的需要。

 | ---| ---| ---| ---|
 | 暴力模拟 | 很难干净地装订| 大状态追踪| 不必要|
 | 基于观测的最优解决方案 | O(n² + m) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个站点，计算有多少糖果源自该站点。 
2. 每一颗糖果`(a, b)`，计算其顺时针距离：```
dist = (b - a + n) % n
```自从`a != b`，这个距离总是正的。 
3. 各站`a`，存储从那里开始的所有糖果之间的最小目的地距离。 叫它`best[a]`。 
4. 对于每个起始站`s`，将答案初始化为零。 
5. 迭代每个站点`u`。 
6.如果`u`不含糖果，没有任何贡献，可以跳过。 
7. 计算到站所需时间`u`：```
reach = (u - s + n) % n

finish =
    reach
    + (cnt[u] - 1) * n
    + best[u]
```8.取最大值`finish`超过所有含有糖果的车站。 
9. 输出每个起始站的最大值。 

### 为什么它有效

 一个车站有`k`糖果每次访问只能释放一颗糖果，连续访问之间精确间隔`n`秒。 任何策略都无法避免延迟`(k - 1) * n`在该站的最后一颗糖果装完之前。 

在同一站的所有糖果中，目的地距离最小的是最后交付的最佳候选者。 任何其他选择都会增加该站的完成时间。 因此，车站的最小可能完成时间`u`，从第一次访问开始测量，正好是```
(cnt[u] - 1) * n + best[u].
```火车到达车站`u`后`reach(s,u)`秒，所以所有糖果最早可能的时刻`u`交付的是```
reach(s,u) + (cnt[u]-1)n + best[u].
```一旦确定了首次访问时间，每个站点就独立运行。 仅当最慢的站点完成时，整个过程才会结束，这就是为什么对所有站点取最大值给出最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())

    cnt = [0] * n
    best = [10**9] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        cnt[a] += 1

        dist = (b - a + n) % n
        best[a] = min(best[a], dist)

    ans = []

    for s in range(n):
        cur = 0

        for u in range(n):
            if cnt[u] == 0:
                continue

            reach = (u - s + n) % n
            finish = reach + (cnt[u] - 1) * n + best[u]
            cur = max(cur, finish)

        ans.append(str(cur))

    print(" ".join(ans))

if __name__ == "__main__":
    main()
```数组`cnt`存储每个车站有多少糖果。 数组`best`存储这些糖果中最小的顺时针目的地距离。 

表达式```
(b - a + n) % n
```计算循环上的顺时针距离。 添加`n`当目标索引在数值上小于源索引时，在取模之前避免出现负值。 

对于每个出发站`s`，我们评估每个站`u`独立。 数量```
(cnt[u] - 1) * n + best[u]
```是所有糖果的最短完成时间`u`，从第一次访问到`u`。 

添加```
(u - s + n) % n
```考虑到达所需的时间`u`从选定的起始站出发。 

最终的答案是该值的最大值，因为在整个过程完成之前必须完成每个站的工作量。

def solve():

    n, m = map(int, input().split())

    cnt = [0] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        cnt[a] += 1
        best[a] = min(best[a], (b - a + n) % n)

    for s in range(n):
        cur = 0

        for u in range(n):

 ## 边缘情况

 ### 一站多糖果

 输入：```
4 3
1 2
1 3
1 4
```目的地距离为`1`,`2`， 和`3`。 该站包含三颗糖果，因此最后一颗糖果要在两个完整周期后才能装载。 

该站的贡献为```
(3 - 1) * 4 + 1 = 9
```假设所有糖果都可以立即加载的模拟将错误地返回`3`。 

该算法存储`cnt[1] = 3`和`best[1] = 1`，产生正确的结果。 

### 环绕目的地

 输入：```
5 1
5 2
```真正的顺时针路线是：```
5 -> 1 -> 2
```所以距离等于`2`。 

该算法计算：```
(2 - 5 + 5) % 5 = 2
```与实际行驶距离相符。 

任何使用普通减法的实现都会得到`-3`并产生废话。 

### 没有糖果的车站

 输入：```
4 1
2 4
```车站`1`,`3`， 和`4`不含糖果。 

该算法完全跳过它们：```
if cnt[u] == 0:
    continue
```没有糖果的电台没有规定截止日期，并且永远不会影响最大值。 忽略这些站点可以使计算既正确又简单。
