 ## 解决方案
 ## 问题理解

 我们最多有 10 个时间段，每个时间段对应于 Yolanda 可能访问商店的一天。 商店中最多有 100 件商品，并且每件商品都在这 10 天内的某些天内有货。 对于每个项目，我们不直接选择它被“收集”的次数； 相反，这个数字是由约兰达选择访问的日期隐式决定的。 

如果 Yolanda 决定在这 10 天中的一部分进行访问，那么对于每个商品，我们都会计算所选日期中有多少天与该商品有库存的天数一致。 这给出了一个值$c_i$每个项目的值介于 0 到 10 之间。 

每个项目贡献的值仅由以下因素决定$c_i$。 具体来说，有一个全局数组$P$，以及项目的贡献$i$是所有整数的异或$P_1$到$P_{c_i}$，包含在内。 如果$c_i = 0$，此贡献成为空范围或简并范围上的 XOR，我们将其解释为 0，因为对于零计数情况，没有以有意义的方式定义有效端点。 

目标是选择 Yolanda 访问的 10 天中的哪一天，以使所有项目贡献的总和最大化。 

关键结构是决策完全在 10 天的时间内完成，这意味着最多有$2^{10} = 1024$的可能性。 每个选择都会产生一个确定性向量$(c_1, \dots, c_N)$，因此是确定性分数。 

主要的微妙之处在于每个$c_i$取决于所选天数子集和每个项目的固定 0-1 模式之间的重叠，因此天真地重新计算每个子集的所有内容仍然没问题，但粗心的实现通常会低效地重新计算计数或错误处理 XOR 范围端点，特别是当$P_{c_i}$用作值而不是索引。 

当出现以下情况时会出现常见的边缘情况：$c_i = 0$。 如果处理不当，可能仍然会计算 XOR_range(P1, P0)，这是没有意义的。 正确的行为是将贡献视为 0，因为该问题仅定义由正计数引起的有效范围的贡献。 

另一个问题是索引的异或和值的异或之间的混淆。 函数 XOR_range(a, b) 的整数值来自$a$到$b$，不超过数组位置。 

## 方法

 从蛮力视角开始，我们唯一的自由是选择 Yolanda 访问的 10 天中的哪一天。 这是最多 10 个二元决策的子集选择问题，因此可以直接枚举所有可能性。 

对于访问天数的固定子集，每个项目的计数$c_i$只是该商品可用的所选天数。 一旦全部$c_i$已知，通过对每个项目应用 XOR 范围函数，总分是立即的。 

重新计算的直接实现$c_i$从头开始每个子集将花费$O(2^{10} \cdot N \cdot 10)$，这已经很小了，但是我们可以通过预先计算每个项目的 10 位可用性掩码并使用位运算来计算来进一步简化$c_i$在$O(1)$每个项目。 

关键的观察结果是，该结构在子集之间是完全静态的：唯一的动态组件是子集交集大小，这正是一个位计数操作。 这将每个子集的评估减少到$O(N)$，制定完整的解决方案$O(2^{10} \cdot N)$，这对于$N \le 100$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力重新计算每个子集的计数 |$O(2^{10} \cdot N \cdot 10)$|$O(N)$| 已接受 |

 ## 算法演练

 1. 预先计算一个辅助函数，该函数返回某个范围内所有整数的 XOR$[a, b]$。 这是使用前缀 XOR 完成的，因为可以在常数时间内计算从 1 到 x 的 XOR。 
2. 读取可用性矩阵，并将每个商品的 10 天可用性压缩为长度为 10 的位掩码。每个位代表该商品当天是否有库存。 
3. 预先计算每个项目和每个可能计数的值表$k \in [0, 10]$。 该表存储该项目的贡献（如果它被准确地看到）$k$次。 
4. 迭代 10 天的所有子集，从 0 到$2^{10} - 1$。 
5. 对于每个子集，使用按位 AND 后跟人口计数计算每个项目可用的选定天数。 
6. 使用该项目的预先计算贡献求和$c_i$，累积子集的总分。 
7. 跟踪所有子集的最高分数。 

其高效工作的原因是，一旦子集固定，项目之间的所有依赖关系都是独立的。 除了共享相同的选定日期子集之外，项目之间没有任何交互。 

### 为什么它有效

 对于任何固定的天数子集$S$, 每一项$i$贡献的价值仅取决于$|S \cap A_i|$， 在哪里$A_i$是项目的天数集合$i$有库存。 这将全局优化问题简化为评估 10 元素宇宙的所有子集上的函数。 由于枚举了所有子集，因此交叉点大小的每种可能配置都被考虑一次，确保找到最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def xor_upto(x):
    # XOR from 1 to x
    # pattern: x % 4
    if x % 4 == 0:
        return x
    if x % 4 == 1:
        return 1
    if x % 4 == 2:
        return x + 1
    return 0

def xor_range(a, b):
    if a > b:
        a, b = b, a
    return xor_upto(b) ^ xor_upto(a - 1)

def main():
    N = int(input())
    mask = []
    for _ in range(N):
        row = list(map(int, input().split()))
        m = 0
        for j in range(10):
            if row[j]:
                m |= (1 << j)
        mask.append(m)

    P = list(map(int, input().split()))
    # ensure enough indexing safety
    # P[1..10] used, we ignore P[0] unless needed
    max_c = min(10, len(P) - 1)

    # precompute item contribution for each possible c
    val = [[0] * 11 for _ in range(N)]
    for i in range(N):
        for c in range(11):
            if c == 0:
                val[i][c] = 0
            else:
                val[i][c] = xor_range(P[1], P[c])

    best = 0

    for s in range(1 << 10):
        total = 0
        for i in range(N):
            c = (mask[i] & s).bit_count()
            total += val[i][c]
        if total > best:
            best = total

    print(best)

if __name__ == "__main__":
    main()
```该实现将每个项目的可用性压缩为 10 位整数，因此交集计数变成了位运算。 预先计算的表`val[i][c]`消除子集循环内重复的 XOR 范围计算，从而使解决方案在时间限制内轻松完成。 

一个微妙的点是处理$c = 0$。 该代码明确地在那里分配零贡献，避免意外评估无效范围端点。 

子集循环枚举所有$2^{10}$掩码，对于每个掩码，我们只执行简单的位操作和表查找，使得实际运行时间非常小。

 ## 边缘情况

 一个关键的边缘情况是某件商品在任何选定的一天都不可用。 在那种情况下，$c_i = 0$，并且实现不得尝试使用无效端点计算 XOR_range。 该算法明确分配零贡献，因此此类项目不会影响分数。 

当选择全部 10 天时，会出现另一种边缘情况。 在这种情况下，每个$c_i$变成其行中的总数，并且解决方案简化为评估单个确定性配置。 子集枚举仍然包含这种情况，确保正确性。 

最后，自然处理多个子集产生相同计数但不同项目分布的情况，因为该算法直接比较总和，而不假设从子集到分数的映射的唯一性。
