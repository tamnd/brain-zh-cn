 ## 解决方案
 ## 问题理解

 我们在隧道中看到一小段灯光序列，每个灯光要么关闭（0），要么打开（1）。 目标是将这个序列转换成完美的交替图案，其中相邻的灯光总是不同的。 恰好有两种有效的目标模式：一种以 0 开头并交替为 0101...，另一种以 1 开头并交替为 1010...。 

单个操作包括翻转灯，将其从 0 更改为 1 或从 1 更改为 0。我们需要确定将给定配置转变为两种交替模式之一所需的最小翻转次数。 

输入大小很小，n 最大为 100。这立即表明，即使是检查每个位置并与多个模式进行比较的解决方案也很容易足够快。 每个候选模式的线性扫描最多可以进行几百次操作，因此任何 O(n) 甚至 O(n²) 的操作都是安全的。 

主要的边缘情况来自非常小的输入和已经交替或几乎交替的输入。 例如，如果输入为“0”，则两个目标模式都会减少为“0”或“1”，因此根据比较，答案为 0 或 1。 如果字符串已经像“010101”一样交替出现，则答案必须为 0，并且任何错误地假设只有一种起始模式的解决方案仍然可以工作，但在其他情况下可能会错过最佳对齐。 

当只考虑一种目标模式时，就会出现一个微妙的错误。 例如，如果输入是“1010”，它已经匹配以 1 开头的模式，但与以 0 开头的模式完全不同。仅检查其中之一通常会给出错误的答案。 

## 方法

 直接的暴力方法将显式构造长度为 n 的两个目标字符串，然后通过计算不匹配次数将它们与输入进行比较。 对于每个可能的起始位，我们生成完整的交替字符串并计算汉明距离。 这是正确的，因为每个有效的解决方案都必须与这两个固定模式之一完全匹配。 

蛮力成本很微不足道：生成两个长度为 n 的字符串并比较它们每个模式的成本为 O(n)，因此 O(2n)。 当 n ≤ 100 时，这个值可以忽略不计。 即使我们更加天真并反复切换每个位置来模拟变换，我们仍然会保持在限制之内，但这是不必要的。 

关键的观察结果是目标的结构是完全固定的。 只有两个候选者，每个位置独立地为不匹配计数贡献 0 或 1。 这消除了任何模拟或贪婪决策的需要。 我们可以通过扫描一次并累积两种模式的不匹配来直接计算成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力构建 + 比较 | O(n) | O(n) | 已接受 |
 | 单次扫描失配计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 读取输入字符串并将其视为字符数组。 我们将其与两个概念交替模式进行比较，而不显式存储它们。 
2. 初始化两个计数器：一个用于匹配以 0 开头的模式的成本，另一个用于以 1 开头的模式。这些计数器表示每个目标需要翻转多少次。 
3. 从 0 到 n - 1 迭代每个索引 i。在每个位置，确定两种模式中正确的字符应该是什么。 对于以 0 开头的模式，预期值为 i % 2。对于以 1 开头的模式，预期值为 1 - (i % 2)。 
4. 将当前字符与两个预期值进行比较。 如果不同，则增加相应的计数器。 这一步直接测量如果我们选择该模式需要翻转多少次。 
5. 处理完所有位置后，取两个计数器的最小值并输出。 这代表了最佳的交替模式。 

### 为什么它有效

 灯串中的每个位置相对于最终成本都是独立的，因为翻转一盏灯不会影响任何其他位置。 固定目标模式所需的翻转总数恰好是输入与该模式之间不匹配索引的数量。 由于只有两种有效模式，并且每个有效交替配置必须与其中之一精确匹配，因此这两个不匹配计数中的最小值必然是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

cost0 = 0  # pattern 0101...
cost1 = 0  # pattern 1010...

for i, ch in enumerate(s):
    bit = ord(ch) - 48  # convert '0'/'1' to int

    expected0 = i % 2
    expected1 = 1 - (i % 2)

    if bit != expected0:
        cost0 += 1
    if bit != expected1:
        cost1 += 1

print(min(cost0, cost1))
```该实现保留两个运行的不匹配计数，而不是构造目标字符串。 转换`ord(ch) - 48`避免重复的字符串比较。 每个索引对两个计数器都有独立的贡献，这就是为什么两个检查在同一个循环中完成而不会相互干扰。 

一个常见的错误是根据发现的第一个不匹配仅更新一个计数器。 必须对两者进行评估，因为每个模式都是关于最终配置的单独假设。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()

    cost0 = 0
    cost1 = 0

    for i, ch in enumerate(s):
        bit = ord(ch) - 48

        if bit != (i % 2):
            cost0 += 1
        if bit != (1 - i % 2):

 ## 边缘情况

 一个重要的边缘情况是最小输入大小 n = 1。对于输入“0”，两个交替模式都是长度为 1 的有效候选者，因此不匹配计数分别为 0 和 1，给出答案 0。该算法可以正确处理此问题，因为两个计数器都是独立计算的，并且取最小值。 

另一种情况是完全统一的字符串，如“0000”。 该算法将其与两种模式进行比较。 与 0101 相比，它在索引 1 和 3 处不匹配，给出成本 2。与 1010 相比，它在索引 0 和 2 处不匹配，也给出成本 2。因此输出为 2，与必须翻转一半位置的事实相匹配。 

最后一种情况是字符串已经与一个模式完全匹配，例如“1010”。 该模式的不匹配计数器在整个扫描过程中保持为零，而其他模式则累积错误。 由于我们取最小值，因此输出正确为 0。
