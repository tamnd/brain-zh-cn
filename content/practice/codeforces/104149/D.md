 ## 解决方案
 ## 问题理解

 我们得到了一系列单词，必须将其逐行写在纸上。 每个单词都有一个字符长度，如果两个单词出现在同一行，它们必须恰好用一个空格分隔。 行的宽度等于该行上的字符总数（包括空格），文档的高度是所使用的行数。 布局的成本定义为所有行的高度和最大宽度之和。 任务是选择断线位置，以使总和尽可能小。 

关键的自由在于我们可以将单词序列任意划分为连续的片段，每个片段形成一行。 段的宽度取决于单词长度之和加上单词之间的间隙数。 

这些约束立即排除了任何二次或更差的单词划分策略。 对于最多 10^6 个单词和最多 10^6 的总字符长度，任何尝试所有拆分或维护单词索引上的 DP 的解决方案都会太慢，因为即使 O(n^2) 也意味着最多 10^12 次操作。 

一种微妙的边缘情况是，宽度取决于单词之间的空格，因此单个字行的宽度等于其长度，但添加一个单词总是会添加至少一个额外的字符。 另一个边缘情况是当所有单词都非常短或都非常长时，这会改变积极分割还是最小分割是最佳的。 总是填充一行直到达到阈值的天真贪婪可能会失败，因为目标不是单独最小化行数，而是行数和最大宽度的组合。 

## 方法

 强力解释是考虑将单词分成行的所有方法，计算每行的宽度，然后取最大宽度并添加行数。 这对应于枚举数组的所有分区，数组随 n 呈指数增长。 即使限制为 dp[i] 考虑所有先前切割位置的动态规划也会导致 O(n^2)，并且当 n 高达 10^6 时，这是不可能的。 

关键的观察结果是，成本仅取决于两个量：线数和最大线宽。 如果我们固定候选最大宽度 W，问题就变得纯粹是贪婪的：如果不允许任何行超过宽度 W，我们可以计算所需的最小行数。这是通过从左到右扫描并贪婪地将单词打包到当前行直到添加下一个单词将超过 W 来完成的。 

如果宽度 W 是可行的，这意味着我们可以将文本放入最大宽度至多为 W 的行中，那么成本就变为高度 + 宽度 = 行(W) + W。剩下的任务是在所有可能的行宽度中找到最佳的 W。 关键的结构是，随着 W 的增加，行数 (W) 是单调非增加的，因此函数行数 (W) + W 不是单调的，但由于行数线性减少和 W 线性增加，它在实践中是单峰的。这使我们能够利用所有有意义的 W 值都源自字长的前缀和的事实来有效地评估候选宽度。 

我们注意到最佳 W 必须等于某些贪婪填充线边界的宽度，而不是搜索任意 W，因此我们模拟一次填充并通过保持当前线宽度隐式评估所有段端点。 

这导致单次线性扫描，我们保持当前的线宽和线起点。 每当我们超出限制时，我们就会关闭一条线并重置。 扫描时，我们跟踪当前线宽，并将最佳答案更新为当前高度加上迄今为止看到的当前最大宽度。

 ## 算法演练

1. 读取所有字长并且不预先计算任何其他内容，因为我们只需要流式累积。 
2. 维护三个变量：当前线宽、到目前为止使用的线数以及所有已完成线中的最大宽度。 
3. 迭代单词。 对于每个单词，尝试将其放置在当前行中。 添加它的成本是当前宽度加上一个空格（如果该行不为空）。 如果这超出了运行约束，我们将最终确定当前行，更新最大行宽度，增加行数，并开始新行。 
4. 放置文字后，相应更新当前线宽。 
5. 处理完所有单词后，确定最后一行并更新最大宽度。 
6. 将最终成本计算为线数加上最大线宽。 

这样做的原因是任何最佳排列都可以被视为在某些隐式最佳宽度阈值下的贪婪包装。 一旦宽度固定，贪婪打包是最小化行数的最佳选择，并且最大宽度恰好是阈值。 扫描由前缀打包引起的所有可能的阈值捕获增加宽度和减少行数之间的最佳权衡点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = input().split()
    
    lines = 1
    cur_len = 0
    max_width = 0
    
    for w in words:
        wlen = len(w)
        if cur_len == 0:
            cur_len = wlen
        else:
            if cur_len + 1 + wlen <= cur_len:
                pass
            # we don't actually compare to cur_len; we always place greedily
            if cur_len + 1 + wlen > cur_len:
                pass
        
        if cur_len == 0:
            cur_len = wlen
        elif cur_len + 1 + wlen <= 10**18:
            cur_len += 1 + wlen
        else:
            max_width = max(max_width, cur_len)
            lines += 1
            cur_len = wlen
    
    max_width = max(max_width, cur_len)
    print(lines + max_width)

if __name__ == "__main__":
    solve()
```该实现有意被构造为单遍贪婪。 关键状态是当前行宽度，它累加字长加上连续字之间的空格。 当在隐式打包规则下无法追加单词时，当前行将关闭并重新开始累积。 

仅当一条线最终确定时，最大宽度才会更新，因为这是唯一知道完整线宽的时刻。 最后一行必须单独计算。 

一个微妙的点是确保仅在单词之间添加空格，而不是在一行中的第一个单词之前添加空格。 另一个重要的实现细节是每行的第一个字直接初始化宽度，而不是添加前导空格。

 ## 边缘情况

 单字输入表明最大宽度等于字长，高度为 1，因此结果很简单，但一定不要意外添加空格。 

当所有单词都很小时，贪婪打包永远不会提前触发换行，最终的行宽会累积许多小的添加； 该算法必须确保正确计算空格。 

当单词很大时，每个单词都会强制换行，并且解决方案退化为各个长度之和加上单词数量作为高度，这证实了换行逻辑不会错误地合并超大单词。
