 ## 解决方案
 ## 问题理解

 我们得到一个代表长楼梯的二进制字符串。 每个字符对应一个步骤，只有标有的位置`1`已损坏并需要修复。 所有损坏的台阶必须通过一次操作进行修复，并且该操作必须适用于楼梯的一个连续部分。 

我们使用的咒语总是固定一个完整的连续区间，但它的可用范围取决于它的书写方式。 在最简单的形式中，它最多可以覆盖 32 个连续步骤。 我们可以通过在其前面重复添加“long”一词来扩展它的范围，并且每添加一个“long”，它可以处理的最大步数就会增加一倍。 所以该法术的能力形成了几何级数。 

任务是确定可以涵盖所有内容的最短有效咒语形式`1`在具有单个连续段的字符串中。 

输入字符串可以长达 10^6 个字符，因此任何解决方案都必须在线性时间内扫描它。 任何涉及对子串进行重复模拟或范围重新计算的操作都会太慢。 

一个关键的结构观察是只有第一次和最后一次出现`1`事情。 一旦我们选择覆盖所有破碎步骤的单个连续段，其所需的最小长度完全由这两个极端之间的距离决定。 

一个天真的错误是认为我们需要考虑多个不相交的组`1`s 或计算有多少段`1`存在。 例如，在像这样的字符串中`100010001`，有人可能会错误地认为需要多个咒语。 实际上，由于该咒语覆盖了一个连续的区间，因此我们无论如何都被迫在其之间包含零，因此只有边界区间很重要。 

另一个潜在的错误是误解咒语的缩放比例。 增长与“long”前面的次数成指数关系，因此将其视为线性增长会导致大跨度的错误答案。 

## 方法

 蛮力的想法是尝试包含所有内容的段的所有可能的开始和结束位置`1`s，计算其长度，然后确定需要多少个“长”前缀来覆盖该长度。 一旦我们注意到任何有效段必须在第一个段或之前开始，这立即变得不必要`1`并在最后一个或之后结束`1`，并且选择更大的值只会使要求变得更糟。 尝试所有端点对会导致长度高达 10^6 的字符串出现二次行为，这远远超出了可行的限制。 

关键的见解是问题分解为一个区间：包含所有内容的最小段`1`s 是从第一个开始的间隔`1`到最后`1`。 设其长度为`L`。 该咒语必须至少支持`L`步骤。 

现在我们只需要确定“长”前缀的最小数量：```
32 * 2^(k-1) >= L
```这是因为基本形式已经对应于容量 32，并且每个额外的“长”都会使该容量增加一倍。 我们正在有效地求解使容量超过所需跨度的最小指数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有细分市场进行蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 使用第一个/最后一个`1`和对数缩放 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 扫描一次字符串，找到第一个的索引`1`和最后一个`1`。 这定义了必须覆盖的最小段。 任何较小的部分都会错过至少一个损坏的步骤。 
2. 计算所需长度`L = last_one_index - first_one_index + 1`。 这是包含所有中断步骤的最小连续间隔。 
3、从基础容量32开始，对应单个“长”。 
4. 反复将容量加倍，同时计算我们在概念上应用“长”的次数。 我们正在有效地找到最小的`k >= 1`这样`32 * 2^(k-1) >= L`。 
5.输出重复的“长”字`k`次，以空格分隔。 

### 为什么它有效

 该咒语始终在连续的间隔上运行，因此任何有效的解决方案都必须至少涵盖第一个和最后一个之间的间隔`1`。 超出该区间的扩展只会增加所需的容量。 由于每个“长”容量都会增加一倍，因此问题就简化为找到适合固定目标长度的最小二次幂缩放。 单调增长保证了一旦容量超过`L`，不能使用更少数量的前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    n = len(s)
    first = -1
    last = -1
    
    for i, ch in enumerate(s):
        if ch == '1':
            if first == -1:
                first = i
            last = i
    
    L = last - first + 1
    
    k = 1
    cap = 32
    
    while cap < L:
        cap *= 2
        k += 1
    
    print(" ".join(["long"] * k))

if __name__ == "__main__":
    solve()
```实现首先确定边界区间`1`一次通过。 然后它计算所需的跨度长度。 之后，它会模拟法术容量从32开始的指数增长，增加“长”前缀的数量，直到容量足够。 循环在所需长度上是对数的，这在约束下是安全的。 

一个微妙的点是我们开始`k`为 1 而不是 0，因为即使是最小的咒语也已经包含一个“长”。 这与最短有效形式从不为空的示例输出相匹配。

 ## 边缘情况

 一个棘手的情况是当`1`已经挤得很紧了。 例如，在`11111`，第一个和最后一个位置接近，因此所需的长度较小。 该算法正确计算出最小间隔并立即保持在基本容量，产生单个“长”。 

另一种情况是当`1`s 出现在一个非常大的字符串的最末端。 尽管中间可能有数百万个零，但只有第一个和最后一个之间的距离`1`很重要。 扫描在 O(n) 时间内正确捕获了这一点，并且加倍循环仍然很小，因为增长是指数级的。 

最终的边缘情况是一个`1`。 在这种情况下，`L = 1`，并且基础容量已经涵盖了它，因此输出再次只是一个“长”，这符合即使是最短的咒语也至少有一个前缀的定义。
