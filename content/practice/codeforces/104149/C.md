 ## 解决方案
 ## 问题理解

 地下城被描述为一个由一些原始走廊构建而成的系统，然后反复组合。 每条原始走廊都连接入口和出口，其行为就像从一个端点到另一个端点的单个无向通道。 更复杂的系统是通过两种方式组合更小的系统而形成的。 在顺序合成中，第一个系统的出口粘在第二个系统的入口上，因此运动必须先经过一个系统，然后才能到达另一个系统。 在并行组合中，两个系统共享入口和出口，因此旅行者可以选择任一分支。 

任务不是模拟运动。 相反，我们被要求在地牢中放置最少数量的“老师”，以便保证从全局入口到全局出口的每条可能的路线都被至少一名老师拦截。 每个老师都会沿着他们占据的路线阻止通行，目标是确保从入口到出口的所有路径都没有完全无人看守。 

输入是一个完全带括号的表达式，描述如何使用两个二元运算符构建地牢。 一个运算符对应于顺序组合，另一个对应于并行组合。 该表达总是简化为具有唯一入口和出口的单个系统。 

输出是一个整数，表示保证拦截每个入口到出口路径所需的最少教师数量。 

由于表达式长度可以达到一百万个字符，因此任何解决方案本质上都必须是线性的。 任何将结构扩展为显式图或枚举路径的尝试都会立即爆炸，因为即使是中等的嵌套深度也已经产生了指数级的许多路径。 表示本身是我们可以利用的唯一结构。 

当将结构视为局部决策是独立的时，会出现常见的故障模式。 例如，假设每个走廊独立贡献会导致顺序组合中的计数过多，因为串联的两个路段共享一个瓶颈。 

第二个微妙的陷阱是将并行组合视为最小值而不是总和。 例如，在像 ( () * () ) 这样的结构中，有两条不相交的路线，并且都必须被阻塞，因此答案必须增加，而不是减少。 

最后，像 (((() + ()) * ())) 这样的表达式深度混合了这两种操作。 任何尝试贪婪求值而不考虑完整括号结构的解决方案都将在减少顺序很重要的嵌套组合上失败。 

## 方法

 暴力方法将显式构造表达式所隐含的图，然后计算全局入口和出口之间的最小割。 每个原始走廊都成为一条边，并且组合规则扩展到图形合并。 构建图后，具有单位容量的最大流或最小割算法将解决该问题。 

这在概念上是正确的，但完全不可行。 该表达式可以描述在最坏情况下，特别是在重复并行组合的情况下，其大小呈指数增长的图。 即使避免了构造并且我们直接运行流程，我们仍然需要一个具有多达数百万个节点的结构，这充其量是边界，并且在Python限制下是不可能的。

关键的观察结果是该图属于串并网络类别。 在此类图中，为了断开源和汇而必须移除的边的最小数量遵循简单的代数结构。 每个原始走廊贡献的基值为 1。 当两个系统串联时，每条有效路径都必须经过两个系统，因此瓶颈是两个系统中较弱的一个，这意味着值通过最小值合并。 当两个系统并联时，路径会分开，所有分支都必须被阻塞，因此贡献会增加。 

这将整个问题转化为计算一个表达式，其中叶子为 1，一个运算符充当加法，另一个运算符充当最小值。 该表达式完全用括号括起来，因此可以使用堆栈在一次从左到右的扫描中对其进行求值，类似于算术表达式求值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 显式图+最大流量| O(N^2) 到指数 | O(N^2) | O(N^2) | 太慢了|
 | 串并联表达式的堆栈求值 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们逐个字符地处理表达式，并维护一个存储部分结果或结构标记的堆栈。 

1. 从左到右扫描表达式，忽略仅指示分组的结构左括号。 当遇到一对空括号表示的原始走廊时，将其视为值1并将其压入堆栈。 
2. 当遇到两个子表达式之间的运算符时，将其存储在堆栈中，以便稍后在两个操作数都可用时应用它。 该运算符可以是顺序组合规则，也可以是并行组合规则。 
3. 当我们到达右括号时，它表明 (A op B) 形式的完整子表达式已经完成。 此时，我们从堆栈中弹出右操作数，然后是运算符，然后是左操作数。 
4. 我们计算子表达式的结果。 如果运算符对应于顺序组合，则我们取两个值中的最小值，因为任何有效路径都必须经过两个组件，并且瓶颈占主导地位。 如果运算符对应于并行组合，我们将这两个值相加，因为所有分支都必须独立阻塞。 
5. 将计算结果推回堆栈，以便它可以参与更高级别的组合。 
6. 处理完整个字符串后，堆栈中包含一个值，这是整个地下城的答案。 

正确性取决于每个堆栈条目都代表完全简化的子表达式的正确答案的不变量。 每次我们减少括号内的块时，我们都会将其折叠成一个等效的“边缘切割值”，忠实地总结了所有内部结构。 由于表达式完全用括号括起来，因此归约不会干扰不完整的子表达式。 

这保证了当执行最终减少时，每个可能的路径组合都已经被计算一次，并且最终值代表了真正需要的最少教师数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    stack = []

    for ch in s:
        if ch == '(':
            continue
        if ch == ')':
            right = stack.pop()
            op = stack.pop()
            left = stack.pop()

            if op == '+':
                stack.append(min(left, right))
            else:  # '*'
                stack.append(left + right)
        else:
            if ch == '1':
                stack.append(1)
            else:
                stack.append(ch)

    print(stack[0])

if __name__ == "__main__":
    solve()
```该实现依赖于这样一个事实：每个完整的子表达式总是在遇到其右括号时精确地减少。 堆栈在值和运算符之间交替。 当出现右括号时，堆栈顶部必须是右操作数，后面是运算符，最后是左操作数。 这种顺序是由输入的严格结构保证的。 

一个微妙的细节是，原始走廊由空括号表示，因此它们贡献恒定值 1。 在解析过程中，只要遇到叶结构，它们就会作为基值推送。 

## 工作示例

 考虑表达式`(()+(()*(()+())))`。 我们只追踪减少量。 

在最底层，每个`()`贡献1.最里面的结构`(()+())`变成`min(1,1)=1`。 然后`(()*1)`变成`1+1=2`。 最后顶层组合`1 + 2`作为顺序组合，给出`min(1,2)=1`。 

| 步骤| 堆栈| 行动|
 | --- | --- | --- |
 | 推| [1, 1] | 两个基地走廊|
 | 减少 + | [1] | 分钟(1,1) |
 | 推 * 分支 | [1, 1] | 并行扩展|
 | 减少* | [1, 2] | 总和|
 | 最终减少+ | [1] | 分钟|

 该跟踪显示了并行分支如何累积成本，同时顺序结构崩溃到瓶颈。 

现在考虑一个纯粹的并行结构`( () * () * () )`解释为嵌套二进制文件。 每个叶子都是 1，重复应用加法会得到 3。该算法正确地累积了所有独立路径。 

| 步骤| 堆栈| 行动|
 | --- | --- | --- |
 | 推| [1, 1, 1] | 三片叶子|
 | 减少* | [2, 1] | 第一次合并 |
 | 减少* | [3] | 第二次合并 |

 这表明每个独立分支必须单独核算。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符处理一次，每次缩减都是常数时间 |
 | 空间| O(n) | 堆栈最多存储线性数量的部分结果和运算符 |

 线性复杂度是必要的，因为输入大小达到一百万个字符。 任何二次行为都会立即超出时间限制。 基于堆栈的评估确保每个符号恰好参与一次压入和一次弹出序列。

 ## 边缘情况

 由单个组成的最小输入`()`确保叶子解析正确地用值 1 初始化堆栈，并且不会过早触发归约。 

对于像这样深度嵌套的系列`((((() + ()) + ()) + ()))`，算法重复应用最小缩减。 每次归约都会将两个单位值合并为一个，最终答案仍然是一个，这表明顺序链正确地传播了瓶颈行为。 

对于深度嵌套的平行链，例如`((((() * ()) * ()) * ()))`，每次减少都会增加累积的总和。 堆栈可预测地增长和缩小，从而确认在重复缩减过程中不会丢失任何分支。 

在混合结构中，例如`((() + ()) * (() + ()))`，左子树和右子树在组合之前独立地减少到一棵，最后的加法产生两棵，这表明分支的独立性在层次组合中得以保留。
