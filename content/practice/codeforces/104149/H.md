 ## 解决方案
 ## 问题理解

 哈利正试图到达一个沙漠中心，而这个中心正是$d$如果他一个人走的话，还有几天的时间。 每人每天消耗一单位水。 每个人，包括哈利和每个朋友，最多可以携带$c$水的总量单位，并且当他们在一起时，水可以在群体之间自由地重新分配。 

朋友们可以陪伴哈利一段旅程，然后沿着同一条路返回起点。 回国的朋友必须有足够的水来度过回程，回程所需的天数与他们返回时已经走过的向外距离完全相同。 哈利的目标只是自己到达目的地，而不是返回。 

关键的难点在于，朋友不仅仅是固定行程的额外承载能力。 它们是临时承运人，如果被送回，必须在前段和回程段中存活下来。 这就产生了一种权衡：更多的朋友增加了总水容量，但也带来了额外的用水义务，因为回程的旅行者必须为回程做好充分准备。 

输入给出$d$，到达目的地的天数，以及$c$，每个人可以携带的最大水量。 输出是哈利能够活着到达目的地所需的最小朋友数量，或者即使有任意数量的朋友也无法满足约束条件，这是不可能的。 

第一个边缘情况出现时$c = 1$。 每个人只能携带一单位的水，每天消耗一单位的水，这意味着没有人能够生存哪怕是一天的旅行。 如果$d \ge 1$，哈利一个人已经失败了，添加朋友也无济于事，因为他们的行为都相同。 正确的输出是不可能的。 

另一种微妙的情况发生在$c$很小但是$d$很大。 天真的直觉可能表明，有足够多的朋友总能解决问题，但返回的朋友变得极其昂贵，因为他们必须在与他们已经出去的时间成比例的长返回路径上运水。 

一个更结构化的失败案例是$c$略高于 1。例如，$c = 2$,$d = 10$。 除了日常生存之外，每个人只有一个额外的单位，这严重限制了帮助者在需要返回之前可以走多远。 

## 方法

 直接的暴力方法会尝试所有可能数量的朋友$k$，并模拟哈利是否有可能到达距离$d$和$k$帮手。 对于每种配置，我们都会跟踪小组每天可以前进多远、消耗多少水以及朋友何时必须返回。 即使我们仔细优化模拟，每次可行性检查都取决于模拟最多$d$天或至少多个转折点，以及$k$可以达到$d$以最坏的推理。 这导致大约$O(d^2)$或更糟糕的行为，这是不可能的$d \le 10^9$。 

关键的观察是我们永远不需要模拟日常运动。 相反，我们只需要推断有效策略所需的总水预算以及需要多少人来供应它。 

重新思考这个问题的一个有用方法是将每个朋友想象成一个可重复使用的“水容器”，在场时可以提供容量，但在返回时却成为一种负担，因为他们必须携带足够的水用于回程。 关键的限制是，在任何时候，团队都必须能够同时支持所有活跃的前行旅行者和所有回程旅行者。 

这导致单调结构：如果$k$朋友就足够了，然后任何$k' > k$也足够了。 这种单调性允许对答案进行二分搜索。 剩下的任务是可行性检查：给定$k$，确定是否可以支持哈利。 

可行性检查简化为关于朋友在返回之前可以停留多长时间的贪婪推理。 如果朋友回来后$x$天，他们必须至少携带$x$返还的单位，加上返还期间每天 1 单位，已算对称； 主要的限制是它们携带的水必须在容量范围内覆盖双腿$c$。 这意味着每个朋友的最大有效旅行长度，因此限制了每个朋友可以为哈利的前进进步贡献多少“覆盖范围”。 

计算每个好友可以提供多少有效的“额外支持天数”并累积贡献，得出最优解，直至达到$d$。

 ## 算法演练

 我们对待朋友的数量$k$作为猜测并检查它是否足够。 

1.对于固定的$k$，考虑整个系统$k+1$人，各有能力$c$，给出总水量$(k+1)c$。 这是零时刻的总可用资源池。 
2.整个活动组每天的生存消耗正好是当前前进的人数。 复杂的是，有些朋友可能会回归，但回归只是将他们的消费转移到了回归阶段。 
3. 中心思想是计算可以“支持”的最大可能前向距离$k$朋友们在不违反退货限制的情况下。 每个朋友都可以转发几天$t$，但必须保留足够的水以返回$t$天，所以他们的前向参与受到限制$c = t + t_{\text{return}} + \text{ongoing consumption}$，这会分解为关于它们可以保持有用时间的线性约束。 
4.我们得出有效贡献：一个朋友最多可以贡献$c - 1$在需要保留水以供返回之前，需要净额外的天数，因为每天至少必须花费 1 单位的水才能在存在时生存。 
5. 我们从概念上对贡献进行排序或累积：$k$朋友们，总的额外支持是$k \cdot (c - 1)$。 哈利本人仅做出贡献$c$无需回报限制的生存天数。 
6. 检查总有效支持是否$c + k(c - 1)$至少达到$d$。 如果是，$k$就足够了。 
7.我们二分查找最小的$k$在$[0, d]$满足这个条件。 
8. 即使非常大$k$不满足不等式，我们输出不可能。 

### 为什么它有效

 不变的是，每向前推进一单位，就消耗一个积极参与者的一单位水，而任何回头的朋友都必须支付等于他们向前参与的对称成本。 这种对称性迫使采用线性计算模型：每个额外的朋友都会贡献固定的边际可用前向耐力，与调度无关。 由于没有任何策略可以重复利用超出容量的水$c$每人的线性界限是紧的，任何可行的时间表都对应于一个分区$d$贡献的范围为$c$和$c-1$增量。 因此，检验不等式准确表征了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(k, d, c):
    # Harry + k friends
    # total effective forward capacity
    return c + k * (c - 1) >= d

def solve():
    d, c = map(int, input().split())

    if c == 1:
        print("impossible" if d > 0 else 0)
        return

    lo, hi = 0, d
    ans = None

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, d, c):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    if ans is None:
        print("impossible")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```功能`can(k, d, c)`编码导出的可行性不等式。 二分搜索探索好友计数的单调空间。 特殊情况`c == 1`之所以单独处理，是因为不平等恶化了：没有参与者能够生存哪怕一天，从而使得任何正距离都不可能。 

主要的微妙之处是确保我们不模拟任何运动。 前进和返回的所有动态都被压缩为单个线性容量表达式。 

## 工作示例

 考虑$d = 4, c = 3$。 

我们评价越来越多的朋友。 

| k | c + k(c-1) | c + k(c-1) | 可行|
 | --- | --- | --- |
 | 0 | 3 | 没有 |
 | 1 | 5 | 是的 |

 最小值是$k = 1$。 这符合这样的想法：一位朋友可以有效地将哈利的耐力延长 2 天，超出他自己的能力。 

该迹线表明可行性随着以下因素单调增长：$k$，这证明了二分搜索的合理性。 

现在考虑$d = 5, c = 3$。 

| k | c + k(c-1) | c + k(c-1) | 可行|
 | --- | --- | --- |
 | 0 | 3 | 没有 |
 | 1 | 5 | 是的 |

 同样，一个朋友就足够了，并且当总容量与所需距离匹配时，边界情况就会发生。 

这些例子表明，每个朋友都会贡献固定的加性增益$c-1$，哈利贡献了基础$c$，形成一个简单的线性增长模型。

 ## 边缘情况

 当$c = 1$，每个人每天消耗的都是他们能携带的量，所以即使是哈利一个人也无法走出第一步。 该算法立即返回不可能，无需进入二分搜索，匹配约束$c + k(c-1)$永远不会超过 1。 

对于$d = 1, c = 2$，支票给出$2 + 0 = 2 \ge 1$，所以零个朋友就足够了。 该算法正确地输出 0，因为 Harry 一个人就有足够一天的容量。 

对于大型$d$和小$c$， 例如$d = 10^9, c = 2$，所需的好友数量就变得非常大。 二分查找探索最多$d$，但仍然很快收敛，因为可行性随斜率线性增长$c-1 = 1$，所以答案大约是$d - c$，这与不等式检查一致。
