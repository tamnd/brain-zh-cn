 ## 解决方案
 ## 问题理解

 我们正在使用一个带权无向连通图，我们需要从节点 1 移动到节点 n。 每条路径都可以重新访问顶点和边，因此允许循环。 

任何选定路径的成本仅由沿该路径出现的最小和最大边权重决定。 如果路径使用边权重$w_1, w_2, \dots, w_k$，那么成本就是这些权重中最小值和最大值的总和。 任务是找到从 1 到 n 的任何路径来最小化这个数量。 

这种情况的不同寻常之处在于，路径本身不是通过总权重或边数来评分的，而是通过其边上的极值函数来评分的。 这打破了通常的最短路径结构：添加边不会线性累积成本，它仅可能改变迄今为止看到的最小值或最大值。 

约束很严格：所有测试用例的顶点和边的总数为$2 \cdot 10^5$。 这排除了任何重新计算每个候选间隔的最短路径或以简单的方式尝试所有边缘对作为边界的方法。 任何比接近线性或接近线性更糟糕的情况$m \log m$每个测试用例都会很困难。 

一个微妙的问题来自于路径可能会重新访问边缘这一事实。 天真的读者可能会认为我们正在寻找一条简单的路径，但允许重复意味着一旦连接的子图中存在“良好范围”的边权重，我们就可以在其中任意遍历以调整连接性。 

一些故障模式自然会出现：

 如果我们在跟踪当前最小和最大边权重的同时在顶点上尝试标准最短路径，则状态空间变为$(node, minEdge, maxEdge)$，太大了。 例如，即使在一个小图中，到达同一节点的不同方式（最小值略有不同）也会产生完全不同的未来成本。 

另一个不正确的直觉是假设答案对应于单个 MST 或最短路径树内的某个最佳路径。 那是失败的，因为我们没有优化加法结构； 如果添加稍差的边可以改善连接性，那么它仍然是有益的，这样我们以后就可以避免更差的最大值。 

## 方法

 关键的观察是将视角从“路径定义最小值和最大值”转变为“通过选择允许的边权重来定义可行的答案”。 

假设我们固定一个下界$L$和上限$R$。 如果存在仅使用权重位于的边的从 1 到 n 的路径$[L, R]$，那么我们可以实现一条成本至多的路径$L + R$，因为该路径上的最小边至少是$L$且最大值最多为$R$，并且我们始终可以通过该过滤图中的连接来确保两个端点都出现在路径中。 

所以问题就变成了：找到一对$(L, R)$这样 1 和 n 仅使用该范围内的边连接，从而最小化$L + R$。 

现在我们扭转思路。 我们不是固定两端，而是按权重对边进行排序，并尝试在解决方案中锚定最小边。 假设我们选择一条有权重的边$w$作为路径中允许的最小边缘。 那么答案一定是$w + \text{(some maximum reachable weight while keeping connectivity)}$。 

定影$w$，我们只允许至少有权重的边$w$。 在这个子图中，我们需要知道仍然连接 1 和 n 的最小可能的最大边权重。 相当于找到最小阈值$R$使得边缘$[w, R]$连接 1 和 n。 

这自然可以通过 DSU 扫描来处理：按权重对边进行排序，并在增加上限时保持连接性。 对于每个候选下界$w$，我们在概念上重置，然后向上增长，但是对每个边执行此操作会太慢。 

最终的优化是实现我们不需要“根据下限重置”。 相反，我们以递增的顺序处理边，并通过使用与持久或增量连接逻辑相结合的两指针技术来维持 DSU 连接上的滑动窗口思想。 更直接和标准的解决方案是对边进行排序并使用 DSU，同时将每条边视为最小端点并维护连接 1 和 n 的最小最大值。 

实际上，我们通过从小到大扫描来固定最大边缘，并维护 1 和 n 是否连通。 微妙的部分是提取最佳对应的最小值，这是通过在每个连接时间跟踪可以作为同一连接间隔内的有效最小值的最小边权重来实现的。 

避免陷阱的干净的重新表述是：

 我们按权重对边缘进行排序。 我们维护 DSU，因为我们按升序包含边。 在任意点，当 1 和 n 第一次以边权连接时$R$，当前组件已使用边缘构建$R$。 在该组件内部，首先连接 1 和 n 的连接结构上使用的最小边权重实际上是该最大值的最佳可能最小值$R$。 因此，对于每个 DSU 组件，我们维护用于形成它的最小边权重，并且当 1 和 n 联合时，我们评估候选答案。 

这会产生对排序边缘的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 使用 BFS 对所有 (L, R) 对进行暴力破解 | O(m^2 (n + m)) | O(m^2 (n + m)) | O(n + m) | 太慢了 |
 | DSU 扫描已排序的边 | O(m α(n)) | O(m α(n)) | O(n) | 已接受 |

 ## 算法演练

 1. 按权重升序对所有边进行排序。 这确保了当我们添加边缘时，它只能增加任何考虑的区间的当前最大边界。 
2. 初始化 DSU，其中每个节点都是其自己的组件。 在每个组件旁边，存储用于将其合并到当前结构的最小边权重。 最初这是未定义的。 
3. 按权重排序迭代边$w$。 对于每条边（u、v、w），尝试合并它们的分量。 合并两个组件时，将结果组件存储的最小边权重更新为两个组件存储值中的最小值，并且$w$。 
4. 每次合并时，检查节点 1 和 n 现在是否在同一组件中。 如果是的话，我们可以形成一条路径，其最大边是当前的$w$，因为到目前为止使用的所有边都 ≤$w$。 
5. 当 1 和 n 连接时，计算候选答案为$w + \text{minEdge}[component(1)]$，因为该组件中存储的最小边代表参与连接它们的结构的最小边权重。 
6. 继续处理边，因为稍后的合并可能会创建具有较大最大值但明显较小最小值的替代结构，从而有可能提高总和。 

### 为什么它有效

 在扫描中的任何点，每个 DSU 组件仅使用达到当前最大权重的边来表示连接$w$。 从 1 到 n 的任何使用边 ≤ 的路径$w$完全包含在这个结构中。 第一个时刻 1 和 n 连接对应于仅使用达到该阈值的边的任何有效路径的最小可能最大边。 在相同的构建历史中，跟踪联合过程中包含的最小边权重捕获与该连接机制兼容的最小可实现下限。 由于每个候选最优路径必须对应于引入其最大边缘的某个阈值，因此扫描保证我们对每个相关最大值精确评估一次，并与该约束下可实现的最佳最小值配对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.min_edge = [10**18] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b, w):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        self.min_edge[a] = min(self.min_edge[a], self.min_edge[b], w)
        return True

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    dsu = DSU(n)

    ans = 10**18

    for w, u, v in edges:
        dsu.union(u, v, w)

        if dsu.find(0) == dsu.find(n - 1):
            root = dsu.find(0)
            ans = min(ans, dsu.min_edge[root] + w)

    print(ans)
```当我们逐渐增加允许的边权重时，DSU 结构保持连接的组件。 并集操作不仅合并连通性，而且还跟踪每个组件内部出现的最小边权重，这对于重建最小可能的路径成本至关重要。 

当节点 1 和 n 在某个边权重下首次连接时$w$， 那$w$充当候选最大值。 该组件中存储的最小边提供了与该连接状态兼容的最佳可能最小值，并且它们的总和被评估为候选答案。 

一个微妙的点是，在 1 和 n 已经连接之后，同一个组件可能会进一步演化。 这就是为什么我们不提前停下来； 稍后的合并可能会在保持连接性的同时引入较小的最小边，这可以减少总和。

 ## 边缘情况

 关键的边缘情况是，最佳路径不是边缘方面的最短路径，而是使用绕道来减少最终成本中的最小边缘。 例如，如果 1 和 n 之间存在直接的重边缘，但也存在包含非常小的边缘的较长路径，则算法正确地首选较长的结构，因为它减少了最小项，同时通过扫描控制最大值。 

另一个微妙的情况是，当 1 和 n 第一次连接时不会产生最佳答案。 由于稍后的合并可以将更小的最小边缘引入到同一组件中，而不会过于激进地增加当前的最大值，因此继续扫描可确保捕获这些改进。
