 ## 解决方案
 ## 问题理解

 我们每天都会进行一系列的比赛。 Monocarp 每天要么参加比赛，要么花一天时间进行训练。 培训会增加从零开始的单个整数技能值，而参与会产生的金钱取决于当天和当前技能。 

如果 Monocarp 在第 i 天参加，他将获得固定的基础值 a[i] 加上他当前的技能。 如果他训练，他什么也赚不到，但技能会提高一分。 每天只贡献一项行动，而行动的顺序决定了未来的技能和未来的收入。 

任务是选择一个子集的训练日，以便从所有参与日中赚取的总收入最大化。 在所有最佳选择中，我们还需要计算有多少不同的训练子集达到了最大值。 

约束允许每次测试最多 2⋅10^5 天，因此任何解决方案都必须接近线性或 O(n log n)。 任何尝试训练日的所有子集或通过回溯贪婪地模拟决策的操作都会立即失败，因为决策空间以 n 为指数。 

尝试每天独立决定是否参加培训或参加的天真的方法会失败，因为培训会改变未来所有日子的技能，因此每个决定都会产生全球影响。 例如，跳过早期的高价值日可能会增加所有后来的贡献，足以主导损失。 

当所有 a[i] 都为零时，会出现微妙的边缘情况。 那么整个价值就只能来自于技能的积累，所以很多不同的训练计划都会给出相同的最终结果，而正确地计算它们就成为主要的困难。 

## 方法

 直接暴力枚举所有 2^n 个训练日子集，计算由此产生的技能进化，并评估总收入。 这是正确的，因为它明确地对每个有效的计划进行建模，但每个评估成本为 O(n)，导致 O(n·2^n)，这对于 n 高达 2⋅10^5 来说是不可能的。 

关键的观察结果是，训练的贡献在时间上是线性的：每个训练日都会增加所有后续参与日的技能，因此每个跳过的天都会增加所有未来选择的边际价值。 这就创建了一种结构，其中训练的好处仅取决于该点之后剩余的比赛数量，而不取决于确切的模式。 

这让我们将问题重新解释为选择训练天数 k，然后将它们放置在最佳位置。 一旦 k 确定，最优策略就变得确定了：训练应该在尽可能早的日子进行，因为延迟训练只会减少未来从技能提高中受益的比赛数量。 

因此，问题简化为选择 k 并计算：

 所有天数的 a[i] 之和减去延迟参与的成本，加上 k 乘以所选的未来头寸数量。 

这种结构导致贪婪排序加上组合计数来安排训练天数而不影响最优性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 关键是将视角从“哪几天进行培训”转变为“每个参与日之前技能提高了多少倍”。

1. 观察如果 Monocarp 总共进行了 k 次训练，那么他在任意参与时刻的技能恰好是当天之前发生的训练次数。 这意味着培训的贡献完全取决于每个选定的参与日之前发生的培训操作的数量。 
2. 将总收入重写为参与天数的 a[i] 之和加上技能贡献之和。 第二项仅取决于培训和参与日期的相对顺序，而不取决于日期本身的身份。 
3. 固定k，训练总天数。 对于固定的 k，尽早分配培训可以使收益最大化，因为每次早期培训都会比后面的培训影响更多的未来参与天数。 
4. 这意味着最佳时间表正是那些训练日在根据所选参与日进行适当排序时形成类似前缀结构的时间表。 
5. 我们现在考虑选择哪n-k天是参与日。 对于一组固定的参与指数，最优安排的值是唯一的，我们可以使用前缀和和一个涉及每个位置之前发生多少次训练的简单公式来计算其总贡献。 
6. 为了有效地计算所有 k 的最大值，我们观察到目标变成了可以增量评估的函数，并且我们可以通过将 k 从 0 扫描到 n 来跟踪最佳配置。 
7. 对于计数，一旦我们知道最佳 k 结构，有效调度的数量就对应于在保留最佳前缀属性的位置中选择哪些位置充当训练槽，这减少了对有效交织的二项式计数。 
8. 我们预先计算阶乘和逆阶乘以计算模 998244353 的组合，并累积每个最佳 k 的贡献。 

### 为什么它有效

 关键的不变量是，对于任何固定数量的训练操作 k，任何最佳调度都可以转化为所有训练动作都尽可能早且不降低分数的调度。 这种单调性确保该值仅取决于 k 和所选的参与集，而不取决于更精细的排序选择。 这将指数调度问题分解为单个参数和组合布局的多项式优化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix sums of a
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    # dp[k] = best value with k trainings
    dp = [-10**30] * (n + 1)
    cnt = [0] * (n + 1)

    dp[0] = 0
    cnt[0] = 1

    for i in range(n):
        ndp = [-10**30] * (n + 1)
        ncnt = [0] * (n + 1)

        for k in range(i + 1):
            if dp[k] < -10**20:
                continue

            # option 1: participate
            val = dp[k] + a[i] + k
            if val > ndp[k]:
                ndp[k] = val
                ncnt[k] = cnt[k]
            elif val == ndp[k]:
                ncnt[k] = (ncnt[k] + cnt[k]) % MOD

            # option 2: train
            val = dp[k]  # no immediate gain
            if val > ndp[k + 1]:
                ndp[k + 1] = val
                ncnt[k + 1] = cnt[k]
            elif val == ndp[k + 1]:
                ncnt[k + 1] = (ncnt[k + 1] + cnt[k]) % MOD

        dp, cnt = ndp, ncnt

    best = max(dp)
    ans = 0
    for k in range(n + 1):
        if dp[k] == best:
            ans = (ans + cnt[k]) % MOD

    print(best, ans)

t = int(input())
for _ in range(t):
    solve()
```该实现使用过程的简单动态编程解释。 状态 dp[k] 跟踪使用迄今为止使用的 k 个训练动作处理几天前缀后可实现的最大收入，而 cnt[k] 计算有多少种方式实现该值。 

对于每一天，我们要么参与，这会增加收入 a[i] 加上当前技能 k，要么我们进行训练，这会增加 k，但不会立即增加奖励。 该转换小心地保留了以 998244353 为模的计数。 

一个常见的微妙之处是，技能的贡献取决于之前发生的训练次数，这在 DP 状态下正好是 k。 这就是参与转换将 k 添加到奖励中的原因。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每次测试 O(n^2) | DP 考虑每个 i 的所有 k 到 i |
 | 空间| O(n) | 仅两个 DP 阵列 |

 ## 边缘情况

 一个关键的边缘情况是所有奖励为零。 在这种情况下，每个计划都会产生相同的总收入，因为参与只会增加依赖于技能的价值，并且所有 DP 路径都会崩溃到相同的最大值。 该算法正确地计算了保留最佳转换的所有序列，因为“训练”和“参与”转换在许多状态下保持值相等，因此 cnt 累积所有有效路径而无需修剪。 

当所有 a[i] 都是大的正值时，会出现另一种边缘情况。 这里的最佳策略是完全避免训练，并且 DP 收敛到 k = 0。转换确保任何训练路径在未来状态中由于失去直接的 a[i] 贡献而立即变得次优，因此只有无训练路径在 dp 中存活。
