 ## 解决方案
 ## 问题理解

 我们得到一个由三个可能的字符组成的字符串，每个位置代表某种类型的硬币。 对于该字符串的任何子段，两个玩家玩确定性挑选游戏，其中每次移动都包括选择一种类型，然后从该段中取出该类型的所有剩余硬币。 一旦选择了一种类型，它就会在游戏的其余部分中消失。 玩家交替移动，并且都以最佳方式进行游戏，以最大化他们个人收集的硬币数量。 

对于每个查询段，我们需要计算第一个玩家在这种最佳玩法下最终收集了多少硬币。 

限制很大：最多 100,000 个字符和 100,000 个查询。 任何独立地重新计算每个查询计数的解决方案都会超时，因为它需要每个查询的线性工作，从而在最坏的情况下导致二次行为。 

关键的困难不在于分段计数本身，而是在我们知道分段内每种硬币类型的计数后，理解游戏如何简化为固定的确定性结果。 

直接模拟游戏是一个幼稚的错误。 对于单个查询，这似乎是可以管理的，但每次移动都会删除整个类别，并且动态推理最佳选择很快就会变得容易出错。 另一个错误的方向是认为顺序比频率更重要，例如尝试跟踪位置或模拟交替的贪婪选择。 示例行为表明，只有每种类型的计数很重要，而不是它们的排列。 

## 方法

 如果我们关注单个查询，我们可以统计该段中存在多少个 G、S 和 B 币。 然后，暴力方法将模拟游戏：每个回合选择最佳类型，将其删除，然后继续。 由于只有三种类型，因此这种模拟是每个查询的持续工作。 

然而，将这个想法扩展到所有查询需要重新计算每个段的计数。 每个查询的成本为 O(n)，这导致 O(nq)，对于输入限制来说太慢了。 

关键的观察是整个游戏仅取决于片段中的三个频率。 一旦我们知道每种类型存在多少，最佳移动的顺序就完全确定了。 每个玩家总是会选择剩下的类型中的一个，并且由于只有三个类别，因此结构会分解为固定的结果：第一个玩家在最佳游戏后最终获得最大和最小的堆，而第二个玩家则获得中间的堆。 

在预处理前缀和之后，这将每个查询减少为常数时间计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的强力模拟 | O(nq) | O(1) | O(1) | 太慢了 |
 | 前缀和+公式 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们预处理三个字符中每个字符的前缀计数，以便我们可以在恒定时间内回答范围频率查询。 

1. 构建三个前缀数组，跟踪每个索引中出现的 G、S 和 B 字符数。 这使我们能够使用减法来计算任何段中的计数。 
2. 对于每个查询段 [l, r]，使用前缀数组计算该段中 G、S 和 B 硬币的数量。 这给了我们三个代表游戏完整状态的整数。 
3. 通过识别这三个计数的最大值、最小值和中间值对这三个计数进行逻辑排序，而无需显式排序。 
4. 硬币总数就是三个计数的总和。 第一个玩家的最终收益是最大堆和最小堆的总和，相当于从总数中减去中间的值。 

此步骤有效的原因是，最佳游戏总是分解为两个玩家有效控制三个类别中的两个，而剩下的类别则由第一个玩家最后收集。 

### 为什么它有效

一旦这三种类型的计数固定下来，游戏就没有位置结构了。 每一步都会删除整个类别，并且两个玩家总是选择剩余的类别。 这意味着结果仅取决于两个玩家在三个动作中如何分配三个堆大小。 最佳游戏迫使第二个玩家拿走中等大小的堆，因为第一个玩家总是可以通过适当选择顺序来确保最大和最小的堆。 因此，第一个玩家的结果是确定性的，等于总数减去中值频率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pref_g = [0] * (n + 1)
    pref_s = [0] * (n + 1)
    pref_b = [0] * (n + 1)

    for i, ch in enumerate(s, 1):
        pref_g[i] = pref_g[i - 1]
        pref_s[i] = pref_s[i - 1]
        pref_b[i] = pref_b[i - 1]

        if ch == 'G':
            pref_g[i] += 1
        elif ch == 'S':
            pref_s[i] += 1
        else:
            pref_b[i] += 1

    q = int(input())
    out = []

    for _ in range(q):
        l, r = map(int, input().split())

        g = pref_g[r] - pref_g[l - 1]
        s = pref_s[r] - pref_s[l - 1]
        b = pref_b[r] - pref_b[l - 1]

        total = g + s + b

        mx = max(g, s, b)
        mn = min(g, s, b)

        # first player gets largest + smallest
        out.append(str(total - (total - mx - mn)))  # total - median = mx + mn

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现使用前缀和来使每个查询独立于字符串长度。 每个字符恰好更新三个前缀计数器之一。 对于查询，减法可在 O(1) 内给出准确的频率计数。 

最终公式通过使用三个数字的中位数等于总计减去最大值减去最小值的恒等式来避免排序，并且第一个玩家的答案是总计减去该中位数。 

一个常见的实施陷阱是混淆了第一个玩家是否获得最大或最小的牌堆。 正确的不变量是，在最佳玩法下，中间堆总是分配给第二个玩家。 

## 工作示例

 考虑完整的示例字符串`BGSSBGB`。 我们为像 [1, 7] 这样的查询建立计数。 假设我们计算频率并得到 G = 2、S = 2、B = 3。 

| 步骤| G | S | 乙| 总计 | 最大| 最小| 回答 |
 | ---| ---| ---| ---| ---| ---| ---| ---|
 | 查询 | 2 | 2 | 3 | 7 | 3 | 2 | 5 |

 该表显示结果完全由频率决定，而不是顺序。 答案匹配 3 + 2。 

现在考虑一个较小的段，例如单个字符，例如仅包含 S 的 [3, 3]。 

| 步骤| G | S | 乙| 总计 | 最大| 最小| 回答 |
 | ---| ---| ---| ---| ---| ---| ---| ---|
 | 查询 | 0 | 1 | 0 | 1 | 1 | 0 | 1 |

 这证实了当只有一种类型存在时，第一个玩家总是立即采取它。 

这些例子表明，减少频率统计可以充分捕捉游戏行为。

 ## 边缘情况

 关键的边缘情况是段中的所有字符都相同。 在这种情况下，除了一个之外的所有三个计数都为零，并且中位数也为零，因此答案变为完整的段长度。 该算法自然地处理这个问题，因为最大值等于总计，最小值等于零。 

另一种情况是计数平衡时，例如 G = S = B。这里，中位数等于所有值，因此第一个玩家仅以合计形式收到三分之二的硬币，但公式仍然正确地隔离了 max + min，确保所有分布的一致性。
