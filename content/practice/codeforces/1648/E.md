 ## 解决方案
 ## 问题理解

 我们从一个连通的无向图开始。 该图代表 Berlaflot 航班，每条边都有一个价格。 

两个城市之间的旅行费用不寻常。 一条航线可能包含很多航班，但其成本并不是边权重之和。 相反，它是该路线上出现的最大边权重。 在两个城市之间的所有可能路线中，我们取最小值。 

对于加权图，这个量是经典的**最小最大距离**。 

现在构造补图。 每对未由 Berlaflot 边连接的城市都成为 S8 边。 S8 Edge 的重量`(u,v)`正是之间的最小最大距离`u`和`v`在原始图表中。 

补图保证是连通的。 

最后，对于每个原始边缘`(u,v)`，我们必须计算之间的最小最大距离`u`和`v`S8 图表内。 这些值成为新的 Berlaflot 价格。 

输入是一个连通图，所有测试用例中最多有 200000 个顶点和 200000 个边。 输出要求每个原始边有一个答案。 

约束立即排除任何接近全对最短路径的情况。 即使存储所有成对距离也需要 θ(n²) 内存，这对于`n = 200000`。 任何解决方案都必须利用最小最大距离和图补集的强大结构特性。 

一个危险的错误是将极小极大距离视为普通的最短路径问题。 

考虑：```
1 --(1)-- 2 --(100)-- 3
1 --(50)-- 3
```最短路径从`1`到`3`是权重的直接边`50`，但最小最大距离也是`50`，因为替代路径具有最大边缘`100`。 最短路径的算术在这里无关紧要。 

另一个简单的陷阱是显式构建补图。 和`n = 200000`，补体几乎可以包含`n²/2`边缘。 即使迭代所有补边也是不可能的。 

第三个微妙点是图中的极小极大距离完全由最小生成树确定。 忽略这一事实会导致算法重复解决原始图中的路径问题并且变得太慢。 

## 方法

 让我们首先想象一下暴力解决方案。 

对于每对顶点，计算 Berlaflot 图中的极小极大距离。 使用这些值将权重分配给所有补边。 然后，对于每个原始边，再次计算补图内的极小极大距离。 

这在概念上很简单。 不幸的是，补图可能包含 θ(n²) 条边。 甚至建造它也是不可能的。 计算所有对之间的极小极大距离至少需要二次内存和三次式工作。 

关键的观察来自最小最大距离的经典属性。 

取加权图的最小生成树。 对于任意两个顶点`u`和`v`，它们之间的最小最大距离等于它们之间唯一 MST 路径上的最大边。 

为什么这在这里有用？ 

让`T`是原始图的 MST。 每个补边`(u,v)`接收的权重等于之间路径上的最大边`u`和`v`在`T`。 

假设我们按升序处理 MST 边。 当 MST 边缘权重`w`连接两个组件`A`和`B`, 每对`(a,b)`和`a∈A`,`b∈B`精确地具有极小极大距离`w`。 

在这些对中，一些是原始图边，一些是补边。 

此时创建的所有补边都接收权重`w`。 

这意味着整个 S8 图可以通过 MST 中的组件合并来描述，而无需具体化所有补边。 

下一个问题是如何计算补图内的极小极大距离。 

我们再次使用 MST 原则。 如果我们可以构造补图的 MST，那么原始边的答案就是该 MST 内相应路径上的最大边。 

美妙之处在于补图 MST 也可以在相同的组件合并过程中构建。 组件分而治之的结构自然而然地出现了。 生成的图只有 O(n log n) 辅助边，并且基于 DSU 的 Kruskal 过程可以有效地构建所需的树。 

整个解决方案变成一系列 MST 构造和树查询，全部接近线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 |---|------|---|

 | 蛮力 | O(n²) 到 O(n³)，具体取决于实施 | O(n²) | 太慢了 |

 | 最佳 | O((n + m) log² n) | O((n + m) log² n) | O((n + m) log n) | O((n + m) log n) | 已接受 |

 ## 算法演练

 ### 步骤 1

 构建最小生成树`T`使用 Kruskal 绘制原始图。 

对于最小最大距离，原始图现在可以完全替换为`T`。 

### 步骤 2

 按权重递增的顺序处理 MST 边。 

当 MST 边缘权重`w`连接组件`A`和`B`，每对端点位于不同边的顶点都获得极小极大距离`w`。 

这正是 Kruskal 重建树中的 LCA 是代表此合并的节点的对的集合。 

### 步骤 3

 构建原始图的 Kruskal 重建树。 

每次合并都会创建一个新节点，其值等于用于合并的 MST 边的权重。 

对于任何两个原始顶点，原始图中的最小最大距离是存储在该重建树中的 LCA 处的值。 

### 步骤 4

 我们需要表示所有补边而不枚举它们。 

对于每个具有与组件对应的子节点的合并节点`A`和`B`, 所有对`(a,b)`和`a∈A`,`b∈B`将收到等于合并值的补边权重，除了已经是原始图边的对之外。 

使用 DSU-on-tree 样式集合并，维护哪些原始图边与每次合并相交。 这让我们能够准确地识别缺失的对，即补边。 

### 步骤 5

 为补图 MST 生成一组稀疏候选边。 

经典的分而治之的论证表明，只需要 O(n log n) 这样的候选边。 每个补边都属于重建树的合并节点，并且我们连接适当子集之间的代表。 

生成的边权重就是合并值。 

### 步骤 6

 在这些候选边上再次运行 Kruskal。 

这构建了 S8 图的 MST，而无需构建完整的补图。 

令这个 MST 为`T₂`。 

### 步骤 7

 构建 Kruskal 重建树`T₂`。 

现在，对于任何一对顶点，S8 图中的最小最大距离等于第二个重建树中这些顶点的 LCA 中存储的值。 

### 步骤 8

 对于每个原始边缘`(u,v)`，查询LCA`u`和`v`在第二个重建树中。 

该 LCA 的存储值正是该报表所要求的新价格。 

### 为什么它有效

 第一个重建树对原始图中的所有最小最大距离进行编码，因为最小最大距离等于 MST 路径上的最大边缘，并且 Kruskal 重建树将这些最大值精确存储为 LCA 值。 

每个补边权重都是由这样的最小最大距离定义的，因此每个补边对应于第一重建树中的某个合并节点。 

稀疏候选生成保留了可以参与补图的最小生成树的所有边。 因此，这些候选者的 Kruskal 会产生与从完整补图获得的相同的 MST。 

然后，第二个重建树对 S8 图中的所有极小极大距离进行编码。 查询每个原始边缘端点对的 LCA 会精确返回它们之间任何路线上的最小可能最大 S8 边缘，这是所需的改革价格。

input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

 ## 边缘情况

 考虑一棵树。```
4 3
1 2 1
2 3 2
3 4 3
```原始图已经等于其 MST。 尝试使用最短路径逻辑而不是极小极大逻辑的解决方案将得出不正确的补边权重。 重建树正确赋值`2`,`3`， 和`3`到补边。 

考虑相等的边权重。```
4 4
1 2 5
2 3 5
3 4 5
1 4 5
```每个最小最大距离等于`5`。 Kruskal重建节点均带有值`5`，每个补边都接收权重`5`，并且每个答案都是`5`。 在组件合并过程中错误地处理相等的权重很容易打破这种情况。 

考虑一个缺少许多对的图表。```
5 4
1 2 1
2 3 2
3 4 3
4 5 4
```补图比原始图密集得多。 在较大的实例中，显式构造已经需要 θ(n²) 工作。 公认的解决方案永远不会枚举所有缺失的对，它仅从组件合并中导出与 MST 相关的结构。
