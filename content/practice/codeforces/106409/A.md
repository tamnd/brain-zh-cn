 ## 解决方案
 ## 问题理解

 该问题描述了高度的满二叉树`h`。 每个节点都是一个任务。 最初只有根任务可用。 在每个时刻，最多`p`处理器可以完成可用的任务，并且完成任务可以使其两个子任务在下一刻可用。 变得可用的任务将保持可用状态，直到处理器处理它。 

对于每个测试用例，我们需要找到完成所有任务所需的最小时刻。 

输入给出了几个独立的场景。 每个场景都包含树的高度和处理器的数量。 输出是该场景的最小计划长度。 

主要困难来自于处理过程不是强制逐级进行的。 缓慢的解决方案可能会在考虑下一个深度之前完成一个深度的所有节点，但处理器可以保留较早深度的一些未完成的节点，并稍后将它们与新创建的任务组合。 

高度足够小，层数才是重要因素，而不是节点总数。 有高度的满二叉树`h`有`2^h - 1`节点，因此直接模拟每个节点变得不可能`h`很大。 该解决方案必须仅使用每个深度可用的任务数量。 由于处理器的数量也可能很大，因此每个级别的每个操作都应该接近恒定时间。 一个`O(2^h)`方法很快就会变得太慢，而`O(h)`方法可以轻松处理限制。 

常见的边缘情况是处理器足以立即完成整个关卡，但不足以完成所有未来的工作。 例如：```
1
3 2
```该树有 7 个节点。 根在时刻 1 完成，两个节点在时刻 2 完成，剩下的四个节点无法再多一个时刻完成，因为只有两个处理器存在。 正确答案是：```
4
```不将未完成的工作向前推进的逐级实现可能会意外地产生更大的值，因为它在空级别上浪费了处理器。 

另一个棘手的情况是可用任务的数量不能被处理器数量整除。 例如：```
1
4 3
```在某个时刻可能有 5 个就绪任务。 其中三个已处理，其余两个应与稍后创建的任务合并。 将这两项任务视为属于一个孤立的级别会给出错误的答案。 

## 方法

 最直接的方法是模拟树级别。 在深度`0`深度只有一项任务`1`有两个任务，然后是四个，依此类推。 对于每个深度，我们可以计算处理该深度的所有任务需要多少时刻。 这适用于小树，因为结构很简单。 

问题在于，该模拟假设一个深度的任务独立于下一深度的任务。 事实上，剩余的任务仍然可用。 如果三个处理器正在处理一棵树，并且一个级别有四个任务，那么最后一个任务在那一刻之后不会消失。 它等待并可以与下一级的任务一起处理。 

每个节点上的强力模拟也太昂贵。 一棵树的高度`h`包含`2^h - 1`节点，即使对于中等大的高度，这也会变得巨大。 

关键的观察是我们不需要了解单个任务。 我们只需要知道在处理每个级别之前有多少任务正在等待。 让`remaining`代表之前级别中未完成的任务。 当新级别包含`2^i`任务，总可用工作变为`2^i + remaining`。 我们可以完成尽可能多的完整处理器组，剩下的就成为新的`remaining`。 

这将问题从模拟树转变为对高度的简单贪婪过程。 贪婪选择是最优的，因为每个处理器插槽都应该尽快使用。 推迟已准备好的任务永远不会创造额外的未来能力，而提前完成任务只会暴露更多的孩子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^h) | O(2^h) | O(2^h) | O(2^h) | 太慢了|
 | 最佳| O(h) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 开始于`remaining = 0`和`answer = 0`。 这`remaining`值存储已准备好但之前未处理的任务。 
2. 从根向下处理树级别。 处于水平`i`，新的可用任务数为`2^i`。 此阶段可处理的总任务为`2^i + remaining`。 

我们添加的原因`remaining`这里是未完成的任务不属于固定的级别。 它们只是等待任务，可以与新任务一起处理。 
3. 将可用任务除以处理器数量。 商告诉我们可以花费多少个完整的时刻来处理如此大量的工作。 将该值添加到`answer`。 
4. 存储完成后剩余的任务。 它们是等待下一个级别创建更多可用工作的任务。 
5. 完成所有关卡后，如果有些任务仍在等待，则需要最后一刻来完成它们。 将这最后一刻添加到答案中。 

为什么它有效：

 在每个级别，算法都会准确保留当前可用但未完成的任务集。 除非处理器处理任务，否则不会删除任何任务。 立即使用所有可能的处理器容量的贪婪步骤是安全的，因为较早处理任务只能揭示更多的子任务，而永远不会减少未来的选项。 存储的余数保留所有未完成的工作，因此下一个级别从正确的状态开始。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        h, p = map(int, input().split())

        remaining = 0
        moments = 0

        for level in range(h):
            tasks = (1 << level) + remaining
            moments += tasks // p
            remaining = tasks % p

        if remaining:
            moments += 1

        ans.append(str(moments))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该循环遍历树的每个深度。 表达式`1 << level`计算`2^level`，这避免了浮点运算并保持计算精确。 

除法步骤计算有多少个完整的处理器批次适合当前可用的任务。 余数分配是实现的关键部分。 如果忘记了，解决方案会错误地假设必须完成每个深度才能继续前进。 

最终检查处理最后一个级别之后未完成的任务。 叶子不会创建更多任务，因此唯一剩下的工作就是再花一点时间完成它们。

 ## 边缘情况

 对于处理器与级别大小完全匹配的情况，例如：```
1
3 4
```根在第一刻就完成了。 下一个级别有两个任务，并且都立即完成。 最终关卡有四个任务，也立即完成。 答案是`3`。 该算法会处理这个问题，因为每个级别都会贡献一批并且不会留下任何剩余部分。 

对于有剩菜的情况：```
1
4 3
```0 级给出了第一时刻之后剩余的任务。 在第 1 级，可用工作为`2 + 1 = 3`，所以一瞬间就完成了，没有留下任何剩余。 在第 2 级，出现四个新任务。 处理了三个，剩下一个。 3 级开始于`8 + 1 = 9`任务，需要三个时刻。 总计变为`5`。 结果取决于使等待任务保持活动状态，而不是在每个级别重置。 

对于单个处理器：```
1
10 1
```每项任务都需要它自己的时刻。 该树包含`2^10 - 1 = 1023`任务，所以输出是`1023`。 该算法很自然地达到了这一点，因为每次除以`1`每个可用任务仅消耗一分钟。
