 ## 解决方案
 ## 问题理解

 我们给出一个简单的无向图，最多可达$2 \cdot 10^5$顶点和最多$3 \cdot 10^5$边缘。 任务是确定是否存在由四个不同顶点组成的链$a, b, c, d$这样沿着链的每个连续对都由一条边连接，形成长度为三的简单路径。 如果存在这样的路径，我们必须按顺序输出任何有效的四元组顶点； 否则我们输出-1。 

我们正在搜索的结构不是循环或一般的子图模式，而是具有三个边的简单路径。 这很重要，因为重复的顶点是被禁止的，所以即使存在多条边，我们也不能重用节点。 

这些限制强烈表明$O(N^2)$或者$O(NM)$方法是不可能的。 和$N, M$甚至有数十万的量级$10^8$操作是边界，任何立方体都完全超出范围。 任何解决方案本质上都必须以线性或近线性时间扫描图，很可能$O(N + M)$。 

当图形包含许多三角形或密集邻域时，就会出现微妙的失败情况。 例如，大小为 4 的派系确实包含有效答案，但尝试所有三元组或邻居的邻居的幼稚方法将发生组合爆炸。 另一个极端情况是当图是星形时：一个中心连接到许多叶子。 即使边的数量很大，那里也不存在长度为三的路径，因此假设“许多边意味着长路径”的算法将是不正确的。 

## 方法

 直接的暴力方法是尝试每对有序的边并尝试将它们延伸到一条路径中。 具体来说，我们可以迭代每条边$b\!-\!c$，然后尝试所有邻居$a$的$b$和所有邻居$d$的$c$，检查是否$a, b, c, d$是不同的。 这是正确的，因为它枚举了每个可能的中间边缘并尝试在两侧扩展它。 

问题是，这在人口稠密的地区变得极其昂贵。 在完整图的最坏情况下，每个顶点都有度$O(N)$，因此检查每条边的所有扩展会导致$O(N^3)$行为。 和$3 \cdot 10^5$边缘，这是不可行的。 

关键的观察是我们不需要探索所有的扩展。 我们只需要知道一条边的每个端点除了相对端点之外是否至少有一个邻居。 一旦我们选择了有效的中间边缘$b-c$,任意邻居$a \neq c$的$b$和任何邻居$d \neq b$的$c$立即形成有效路径$a-b-c-d$。 因此，问题简化为找到任意边，其中两个端点在图中的度数至少为 2，这是通过从考虑中删除相对端点而得出的。 

利用这一点的一种简洁方法是预处理邻接表和度。 然后我们迭代边缘并尝试贪婪地构造路径。 允许两个扩展的第一个边立即产生有效答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有扩展进行暴力破解 |$O(N^3)$|$O(N + M)$| 太慢了|
 | 基于度的贪婪边缘扩展 |$O(N + M)$|$O(N + M)$| 已接受 |

 ## 算法演练

 1. 构建图的邻接表并计算每个顶点的度数。 这允许恒定时间访问邻居并快速检查是否可以扩展。 
2.迭代每条边$(b, c)$。 该边缘将作为路径的潜在中间。 
3. 对于当前边，搜索邻居$a$的$b$这样$a \neq c$。 如果不存在这样的邻居，则该边不能是有效路径的中间，因此继续前进。 
4.同样，搜索邻居$d$的$c$这样$d \neq b$。 如果这也存在，我们立即就有一个有效的路径$a - b - c - d$，我们就可以输出它了。 
5. 如果在步骤 3 和 4 中没有边成功，则图中不存在有效的长度为 3 的路径，因此输出 -1。 

关键思想是我们永远不需要在每边探索多个候选邻居。 一旦我们找到一条边两端的有效延伸，我们就停止。 

### 为什么它有效

 任何有效的解决方案都必须包含一些中间边缘$(b, c)$。 如果一条路径$a - b - c - d$存在，那么根据定义$a$是一个邻居$b$不同于$c$， 和$d$是一个邻居$c$不同于$b$。 因此，当我们检查边缘时$(b, c)$，正确的端点$a$和$d$保证存在于邻接表中。 该算法不依赖于超出此存在条件的排序或结构，因此它不会错过有效的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        edges.append((u, v))

    for b, c in edges:
        a = -1
        d = -1

        for x in adj[b]:
            if x != c:
                a = x
                break

        if a == -1:
            continue

        for x in adj[c]:
            if x != b:
                d = x
                break

        if d == -1:
            continue

        print(a)
        print(b)
        print(c)
        print(d)
        return

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案构建一次邻接列表，然后扫描边缘。 内部循环仅扫描邻居，直到找到第一个有效候选者为止，因此每次成功尝试处理的顶点不会超过其度数。 关键的实现细节是在选择邻居时避免重用相反的端点，因为这会违反唯一性。 

该算法依赖于提前终止：一旦找到有效路径，我们就停止进一步的工作。 

## 工作示例

 ### 示例 1

 输入：```
4 1
3 4
```只有一条边，因此没有顶点的度数至少为 2。算法检查边 (3, 4)，为任一端点找到替代邻居，并以 -1 终止。 

### 示例 2

 输入：```
6 7
1 3
1 5
2 3
2 5
2 6
4 5
4 6
```我们逐边追踪：

 | 边 (b,c) | b 的邻居，不包括 c | c 的邻居，不包括 b | 结果 |
 | --- | --- | --- | --- |
 | (1,3) | 5 | 2 | 找到有效路径 |

 对于边 (1, 3)，顶点 1 除了 3 之外还有邻居 5，顶点 3 除了 1 之外还有邻居 2。这给出了路径$5 - 1 - 3 - 2$。 该算法立即打印它并停止。 

这表明我们只需要一个成功的边缘； 不需要全局结构搜索。

 | 测量 | 复杂性 | 说明|

 | 时间 |$O(N + M)$| 构建邻接列表需要线性时间，并且平均每条边都通过恒定时间邻居扫描检查一次。 |

 ## 边缘情况

 星形图显示了存在边但没有顶点可以充当长度为 3 的路径的中间的故障模式。 当算法检查任何边缘时，一个端点的度数始终为 1，因此邻居排除步骤立即失败，并且算法正确返回 -1。 

具有额外尾部边缘的完全连接的三角形表明密集的局部结构不会混淆算法。 当它处理尾部边缘时，连接到三角形的端点仍然有一个替代邻居，从而允许构建有效路径而无需探索所有三角形边缘。 

纯路径图是最干净的正例。 每个内部边缘都具有所需的结构，并且算法一旦遇到任何中间边缘就会成功，从而确认提前终止不会跳过有效答案。
