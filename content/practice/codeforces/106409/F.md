 ## 解决方案
 # 问题理解

 该问题描述了放置在一条线上的多个信标。 每个信标都有一个位置和当前功率。 在正常步骤中，每个仍然可以扩展的信标都会将其功率增加一。 充满力量的灯塔`p`覆盖区间从`x - p`到`x + p`。 一旦一个信标的覆盖区间触及另一个信标的覆盖区间，它就会停止扩展，因为它不再能够独立增长。 

任务是在这个重复过程完成后找到最终覆盖头寸的总数。 

输入给出了信标的数量，后跟每个信标的坐标和初始功率。 输出是所有可能的扩展发生后覆盖的整数位置的数量。 

这些限制要求避免直接模拟。 如果有`n`每个信标都可能扩展很多次，模拟每一轮所花费的时间远远超过线性时间。 对于大输入，重复扫描所有信标的方法太慢，因为轮数取决于坐标距离，而不仅仅是取决于`n`。 

棘手的部分是同步增长很重要。 在一次部分更新后出现阻塞的信标可能仍会在实际过程中增长，因为其他信标也在同一轮中增长。 

例如，两个信标：```
2
0 1
5 1
```双方都开始覆盖`[ -1, 1 ]`和`[4, 6]`。 两人最终在成长后相遇。 仅增长左侧信标直到其停止的模拟会错误地过早地冻结它。 

另一个边缘情况是初始范围重叠：```
2
0 5
3 1
```第一个信标已经覆盖了第二个信标。 将第二个信标视为独立并分别添加两个范围将会对位置进行两次计数。 

# 方法

 一个简单的解决方案是模拟完整的步骤。 在每一轮中，找到每个可以扩展的信标，增加其功率，然后重复，直到没有变化发生。 这是正确的，因为它完全遵循流程。 问题是一个信标在到达另一个信标之前可能需要多次扩展。 如果坐标很大，则轮数可以与坐标距离成正比，使得最坏的情况远远超出可接受的限度。 

有用的观察是各个扩展的顺序并不重要。 想象一下执行较小的操作，一次只有一个信标扩展一个单位，而不是一起增加所有可扩展的信标。 最终的稳定状态是相同的。 这使我们能够将扩展处理为覆盖区间之间的合并。 

按位置对信标排序后，维护当前不相交的覆盖段。 当新的段与前一个段重叠时，两者属于同一个最终组。 它们的最大范围成为合并段的范围。 每个原始段仅参与恒定数量的合并，因此排序后的总工作是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(轮数 × n) | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 # 算法演练

 1. 按位置对所有信标进行排序。 从左到右的顺序就足够了，因为交互只能发生在相邻的覆盖区间之间。 
2. 将当前每个组表示为一个段`[left, right]`连同它的扩展能力。 最初，每个信标都是它自己的段。 
3. 按排序顺序一一添加信标。 插入新段后，将其与之前的段进行比较。 
4. 如果两个线段不重叠，则保留两个线段。 他们永远分开，因为一个群体内部未来的扩张无法跨越未覆盖的鸿沟。 
5. 如果片段重叠，请将它们合并。 新段具有左段的左边界和合并的覆盖范围的右边界。 它的力量是两个力量中较大的一个，因为那个信标可以继续扩张到最远的地方。 
6. 继续向后合并，同时最新的段与前一个段重叠。 
7. 所有合并完成后，剩余的每个段都是最终的连通覆盖组件。 具有左端点的线段`l`, 右端点`r`，和功率`p`贡献`r - l + 2 * p + 1`职位。 

为什么它有效：不变的是每个存储的段恰好代表覆盖范围中无法再分离的一个连接组件。 当两个组件接触时，未来的过程会将它们视为一个组件，因为任何一侧的扩展都可以继续，直到达到组件内部的最远距离。 由于每次合并都保留了最大可能的范围，因此最终的片段与重复应用原始完整步骤所产生的片段完全相同。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    beacons = []
    for _ in range(n):
        x, p = map(int, input().split())
        beacons.append((x, p))

    beacons.sort()

    stack = []

    for x, p in beacons:
        stack.append([x - p, x + p, p])

        while len(stack) >= 2:
            a = stack[-2]
            b = stack[-1]

            if a[1] < b[0]:
                break

            stack.pop()
            stack.pop()

            stack.append([
                a[0],
                max(a[1], b[1]),
                max(a[2], b[2])
            ])

    ans = 0
    for l, r, p in stack:
        ans += r - l + 2 * p + 1

    print(ans)

solve()
```首先对输入进行排序，因为合并过程取决于相邻间隔。 堆栈仅存储当前独立的间隔。 

合并循环是算法的核心。 当两个区间相交时，将它们分开会违反所有存储的区间不相交的不变量。 新的力量是两个原始力量中的最大值，因为在它们连接后，只有最强的剩余扩展能力才重要。 

最后的循环计算每个独立组件覆盖的位置。 该公式包括初始间隔长度和两侧可用的额外增长。 

Python 整数不会溢出，因此实现不需要对大答案进行特殊处理。 

# 工作示例

 考虑：```
3
0 1
5 1
10 1
```处理过程如下所示：

 | 步骤| 添加了信标 | 堆栈状态 |
 | ---| ---| ---|
 | 1 |`(0,1)`|`[-1,1]`|
 | 2 |`(5,1)`|`[-1,1], [4,6]`|
 | 3 |`(10,1)`|`[-1,1], [4,6], [9,11]`|

 没有间隔重叠，所以最终答案是：`3 + 3 + 3 = 9`该示例显示独立组件保持分离。 

另一个例子：```
3
0 2
5 2
10 2
```| 步骤| 添加了信标 | 堆栈状态 |
 | ---| ---| ---|
 | 1 |`(0,2)`|`[-2,2]`|
 | 2 |`(5,2)`|`[-2,2], [3,7]`|
 | 3 |`(10,2)`|`[-2,2], [3,7], [8,12]`|

 中间间隔最初不接触任何一侧，因此组件保持分离。 该算法不会仅仅因为间隔接近而合并间隔，仅当它们覆盖的位置相交时才合并。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 排序占主导地位，每个区间合并固定次数 |
 | 空间| O(n) | 堆栈存储当前不相交的分量 |

 该解决方案很合适，因为它避免了模拟各个扩展轮次。 即使坐标非常大，排序后堆栈操作的数量仍保持线性。

 # 边缘情况

 对于单个信标：```
1
7 0
```堆栈包含一个区间`[7,7]`。 不发生合并，贡献为`1`，这是正确的，因为一个位置被覆盖。 

对于最初重叠的信标：```
2
0 5
3 1
```第一个信标覆盖`[-5,5]`第二个封面`[2,4]`。 由于间隔重叠，算法会立即合并它们。 合并后的间隔保留较大的功率，因此最终的覆盖范围仅由第一个信标决定，避免重复计算。 

对于分离的信标：```
2
0 1
100 1
```间隔`[-1,1]`和`[99,101]`永远不会相交。 堆栈保留两个分量，答案是两个长度的总和。 

对于重叠链：```
3
0 2
4 2
8 2
```前两个音程接触，因此它们合并。 生成的组件到达足够远以与第三个间隔重叠，从而导致第二次合并。 重复的合并循环可以处理这种情况，因为每次合并后都会根据前一个组件再次检查新的间隔。
