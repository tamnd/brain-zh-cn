 ## 解决方案
 ## 问题理解

 我们得到了一个正整数数组以及一种非常具体的减少它的方法。 每个操作都会选择一个前缀或后缀，并将所选段中的每个元素恰好减一。 目标是确定我们是否可以使用任意数量的此类操作将所有值减少到零。 

思考该过程的一个有用方法是，每个操作都是从左侧或从右侧绘制的“层”。 前缀操作绘制从索引 1 开始的连续块，而后缀操作绘制以索引 n 结束的连续块。 每个元素都会通过覆盖其位置的操作累积绘制层，并且每个位置的最终高度必须与其初始值完全匹配。 

这些约束很重要，因为所有测试用例的总大小最多为 30000。这排除了对所有操作或端点的任何二次模拟。 任何显式模拟逐步应用操作或尝试 k 值的所有组合的解决方案都会爆炸，因为每个操作都是 O(n) 并且操作数量是无限的。 

微妙的困难在于操作严重重叠，局部贪婪决策可能会失败。 例如，始终使用尽可能大的前缀或后缀递减量会产生误导，因为它可能会消耗内部元素所需的覆盖范围。 

一种简单的方法可能会尝试显式地构造操作序列或将其视为具有任意重数的区间覆盖。 这很快就会失败，因为前缀和后缀操作的可能序列呈指数级增长。 

一个关键的边缘情况是当数组在中间增加但无法通过重叠的前缀和后缀贡献来解释时。 例如，在像这样的数组中`[5, 2, 1, 10]`，最后一个元素强制执行许多后缀操作，然后这些操作会溢出到较早的位置，并且可能会过度减少它们，除非仔细平衡。 

## 方法

 蛮力的想法是模拟所有可能的操作序列。 每个操作选择一个 k 以及它是前缀还是后缀操作。 这创建了一个分支过程，其中每个步骤都会修改数组，并且我们搜索通向全零的路径。 

这在理论上是正确的，因为它直接遵循流程的规则。 然而，每个步骤有 2n 个选择，并且深度可以与数组中的最大值一样大。 即使对于较小的 n，分支因子也会使其变得不可行。 

关键的观察是，我们可以考虑每个位置必须被前缀操作“覆盖”多少以及后缀操作“覆盖”多少，而不是根据操作来思考。 每个职位 i 都收到来自以下机构的贡献：

 至少扩展到 i 的前缀操作，以及从 i 或之前开始的后缀操作。 

这将问题转化为检查我们是否可以将数组分解为两个单调的“配置文件”：一个从左侧构建，一个从右侧构建。 关键的结构约束是，前缀的有效贡献不能随着我们向右移动而增加，而后缀的有效贡献不能随着我们向左移动而增加。 

这导致了建设性的一致性检查：我们模拟需要多少“左容量”和需要多少“右容量”，确保在每个位置可行的前缀和后缀贡献之和可以匹配给定值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们从左到右扫描并保持来自前缀操作的最小可能贡献。 在位置 i 处，如果该值相对于 i−1 增加，则该增加不能用来自右侧的后缀操作来解释，因此必须由附加前缀结构支持。 这对需要多少前缀“预算”施加了非递减的约束。 
2. 我们从右向左对称扫描，计算支持每个位置所需的最小后缀贡献。 任何从右到左的增加都必须由较早开始的后缀操作来解释。 
3. 对于每个位置，我们结合所需的前缀和后缀贡献。 总数不得超过原始值，因为每个单位减量必须恰好来自覆盖该位置的一次操作。 
4. 我们检查整个阵列的一致性。 如果在任何时候所需的组合结构超出了元素可以支持的范围，那么答案是不可能的。 

关键思想是每个元素的高度都分为两个单调部分：一个来自前缀覆盖，一个来自后缀覆盖。 前缀分量只能随着向右移动而减小，后缀分量只能随着向左移动而减小。 

### 为什么它有效

 每个有效的操作序列都会产生两个单调覆盖范围。 前缀操作贡献左锚定堆栈，后缀操作贡献右锚定堆栈。 这些堆栈是独立单调的，因为扩展前缀不能增加后面索引右侧的覆盖范围，而扩展后缀不能增加早期索引的覆盖范围。 

相反，如果我们可以构造两个这样的单调配置文件，其总和与数组完全匹配，那么我们可以通过在每一层执行相应数量的前缀和后缀操作来直接实现它们。 有效操作序列和有效分解之间的双射保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # prefix feasibility
        left = [0] * n
        left[0] = a[0]
        for i in range(1, n):
            left[i] = min(a[i], left[i-1] + 1)
        
        # suffix feasibility
        right = [0] * n
        right[-1] = a[-1]
        for i in range(n-2, -1, -1):
            right[i] = min(a[i], right[i+1] + 1)
        
        ok = True
        for i in range(n):
            if left[i] + right[i] < a[i]:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```左边的数组强制每个位置的值有多少可以纯粹由前缀增长约束支持。 它在向右移动时绝不允许大于 1 的跳转，因为进一步向右扩展的前缀操作是唯一可以逐渐增加覆盖范围的机制。 

右侧的阵列反映了另一侧的相同逻辑。 最终检查确保两个结构组件一起可以充分解释每个元素的高度而不超过它。 

一个常见的实现错误是忘记“+1 传播限制”，它编码了前缀或后缀范围不能在相邻位置之间产生任意急剧增加的事实。 

## 工作示例

 我们追踪第一个样本数组`[1, 2, 1]`。 

我们计算左右贡献。

 | 0 | 1 | 1 | 1 | 2 | 是（本地）|
 | 1 | 2 | 1 | 1 | 2 | 是的 |

 这里所有的位置都满足约束，所以答案是YES。 该结构表明中间峰受到前缀和后缀重叠的支持。 

现在考虑`[5, 2, 1, 10]`。 

| 我| 一个[我] | 左[i] | 右[i] | 左+右| 有效 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 5 | 5 | 1 | 6 | 是的 |

 ## 边缘情况

 单元素数组总是会成功，因为长度为 1 的一个前缀或后缀操作可以将其精确地减少到零所需的次数。 

严格递减数组总是有效的，因为我们可以纯粹通过从右端开始的后缀操作来实现它们，这自然会产生与约束兼容的单调递减结构。 

尖峰如`[1, 10, 1]`失败是因为前缀和后缀操作都不能独立生成一个大的孤立中心而不超出相邻位置。 该算法通过中间索引处左右传播限制之间的不匹配来检测这一点，其中组合容量无法达到所需的高度。
