 ## 解决方案
 ## 问题理解

 我们给出了几个序列，每个序列都已按非降序排序。 我们重复执行一个操作，选择一个序列，获取其当前的第一个元素，将其添加到总数中，然后从序列中删除该元素。 我们精确地执行了 k 次，目标是最大化收集到的总和。 

查看该过程的另一种方式是，每个数组的行为就像一个队列，在每一步中，我们都会选择一个队列并从其前面弹出。 由于数组按递增顺序排序，因此数组中前面的元素最小，后面的元素较大。 

关键结构是我们不限于在移动到另一个数组之前完全消耗一个数组。 我们可以自由地在数组之间交错选择，但是每次我们回到数组时，我们都会有效地沿着它前进一个指针。 

这些约束立即排除了任何考虑所有选择序列的方法。 由于多达 3000 个数组和多达 3000 个操作，每个操作对数组选择的任何强力分支都会呈指数增长。 即使对所有指针的所有状态进行 DP 也会涉及跟踪 3000 维状态，这是不可能的。 

一个更微妙的问题是，总是采用当前最大可用前端元素的天真贪婪策略是正确的，但前提是我们能够有效地维护它。 隐藏的挑战是，每次我们从数组中进行选择时，它的前面都会发生变化，因此候选值会动态变化。 

天真的思维的一个典型失败案例是独立处理每个数组，取其最大的前缀和，然后贪婪地组合结果。 例如，如果一个数组开始时很小，但结束时非常大，延迟它可能是最佳选择，但天真的前缀聚合会错过这种交错。 

正确的解决方案需要一种方法来始终了解所有数组中最佳可用的“下一个元素”，同时在每次选择后仅有效更新受影响的数组。 

## 方法

 蛮力的想法是逐步模拟该过程。 在每次操作中，我们都会尝试所有 n 个数组，选择一个，然后递归地继续。 这正确地探索了所有可能的选择序列，但每 k 个步骤的分支因子都是 n，导致 O(n^k)，这是完全不可行的。 

第二个强力改进是注意每个数组都是单调的，因此对于每个数组我们只消耗前缀。 我们可以通过从每个数组中取出多少元素来定义状态。 即使如此，状态空间仍然是巨大的，因为每个数组最多可以贡献 3000 个元素，从而产生组合爆炸。 

关键的观察结果是，在任何时刻，每个数组都为决策过程贡献了一个候选值：其当前的前面元素。 选择后，该数组中的下一个候选者向前移动一个位置。 这意味着整个问题简化为在 n 个变化的前值中重复选择最大值。 

这正是针对一组候选者的动态选择问题，其中每次选择都会导致一个候选者被固定列表中的后继者取代。 优先级队列就足够了：我们维护每个数组的当前前面，并且每次提取都将其替换为同一数组中的下一个元素。 

这是有效的，因为在每个数组中，顺序是固定的且不递减，因此一旦我们向前移动，我们就不需要重新考虑较早的元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^k) | O(n^k) | O(k) | 太慢了 |
 | 最优（堆模拟）| O((n + k) log n) | O((n + k) log n) | O(n) | 已接受 |

 ## 算法演练

1. 初始化一个最大优先级结构，该结构存储每个数组的一个条目，特别是其当前的第一个元素以及数组索引和位置。 我们反转值来模拟最大堆，因为标准堆在 Python 中是面向最小的。 这确保我们始终在所有数组中提取最佳的可用候选者。 
2. 将每个非空数组的第一个元素插入堆中。 如果我们决定从该数组中进行选择，则每个条目都代表最佳的下一个选择。 
3. 为答案初始化一个累加器，它将存储 k 次操作中所有选定元素的总和。 
4. 重复k次：

 1. 从堆中提取最大的可用元素。 
2. 将其值添加到累加器中。 
3. 在相应数组内前进一位。 
4. 如果数组仍有剩余元素，则将其新的前部元素插入堆中。 

此步骤起作用的原因是，在删除当前前面之后，该数组中的下一个有效候选者是唯一确定的。 

### 为什么它有效

 在任何时刻，堆中的每个数组都包含一个候选者：尚未消耗的最小索引。 每一个可能的合法举动都对应于选择这些候选人之一。 由于除了堆中的竞争之外，数组是独立的，因此选择当前最大候选者始终是当前步骤的最佳选择。 该问题具有交换属性：如果最优解决方案在某个步骤中没有选择最大可用元素，则将其与所选元素交换不能减少总和，因为所有值都是非负的，并且替换仅影响同一排序序列中的未来访问。 这确保了贪婪选择是全局一致的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

n, k = map(int, input().split())

arrays = []
for _ in range(n):
    tmp = list(map(int, input().split()))
    t = tmp[0]
    arrays.append(tmp[1:])

heap = []
for i in range(n):
    if arrays[i]:
        heapq.heappush(heap, (-arrays[i][0], i, 0))

ans = 0

for _ in range(k):
    val, i, j = heapq.heappop(heap)
    val = -val
    ans += val

    if j + 1 < len(arrays[i]):
        heapq.heappush(heap, (-arrays[i][j + 1], i, j + 1))

print(ans)
```该解决方案维护了一堆活跃的前端元素。 每个堆条目都对值及其位置进行编码，以便我们可以在其数组中正确前进。 负号是必要的，因为 Python 只提供了最小堆。 

一个微妙的实现细节是我们从不推送过时的元素。 每个堆条目对应于数组中的一个特定索引，因此当我们弹出它时，我们确定性地知道下一个要推送的索引。 这避免了延迟删除的需要。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O((n + k) log n) | O((n + k) log n) | 每个堆操作花费 log n，我们执行 k 次提取和最多 k 次插入 |
 | 空间| O(n) | 堆中每个数组最多存储一个活动指针 |

 边界 n, k ≤ 3000 使其速度相当快。 即使在 6000 次堆操作的最坏情况下，对数因子也可以忽略不计。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    n, k = map(int, sys.stdin.readline().split())
    arrays = []
    for _ in range(n):
        tmp = list(map(int, sys.stdin.readline().split()))
        arrays.append(tmp[1:])

    for i in range(n):
        if arrays[i]:
            heapq.heappush(heap, (-arrays[i][0], i, 0))

        val = -val
        ans += val
        if j + 1 < len(arrays[i]):
            heapq.heappush(heap, (-arrays[i][j + 1], i, j + 1))

    return str(ans)

 ## 边缘情况

 一种边缘情况是单个数组主导后期值。 对于输入：```
2 3
2 1 2
3 1 1 100
```堆从 1, 1 开始。该算法采用 1，然后再次采用 1，但在推进第二个数组之后，它最终达到 100，这成为主导选择。 堆正确地延迟访问，直到指针到达它。 

另一个边缘情况是所有数组都包含相同的值。 堆有很多平局，但由于值是非负且独立的，因此任何打破平局的顺序都是有效的。 该结构确保准确无偏地进行 k 个选择。 

最后的边缘情况是当 k 等于元素总数时。 在耗尽所有数组后，堆恰好变空，并且该算法从不尝试推送无效索引，因为每次推送都受到数组长度界限的保护。
