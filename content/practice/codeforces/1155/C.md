 ## 解决方案
 ## 问题理解

 我们给出了几个事件时间，已经按升序排列。 Ivan 想要配置一个定期响起的闹钟。 一旦第一声响铃在几分钟内响起`y`，时钟有时会继续响：`y, y + p, y + 2p, y + 3p, ...`开始时间`y`可以是任何整数，但句点`p`必须从给定的允许期间列表中选择。 

我们的任务是确定是否存在某个允许的时间段，使得每个事件时间都属于振铃序列。 如果存在这样的时间段，我们必须输出有效的起始分钟和所选时间段的索引。 

这些约束立即表明该解必须接近线性。 两个都`n`和`m`可以达到`3·10^5`，因此任何针对每个时期检查每个事件的算法都需要大约`9·10^10`在最坏的情况下进行操作，这是完全不可行的。 

事件时间和周期可以长达`10^18`。 这排除了任何依赖于按值索引的数组或任何振铃过程模拟的方法。 我们必须纯粹使用算术属性。 

一个微妙的问题是，警报可能会在事件时间之外的其他时间响起。 我们只要求每个活动时间都在响铃时刻之中。 这种区别至关重要。 

考虑：```
x = [3, 12, 18]
p = 3
```响铃顺序开始于`3`是：```
3, 6, 9, 12, 15, 18, ...
```额外的响铃位于`6`,`9`， 和`15`是完全可以接受的。 

另一个容易犯的错误是只关注连续的差异。 

例子：```
x = [1, 7, 13]
```差异是：```
6, 6
```一段时期`6`作品。 

但对于：```
x = [1, 7, 19]
```差异是：```
6, 12
```一段时期`6`仍然有效，因为所有事件时间都是全等模数`6`。 

关键的对象不是个体差异，而是最大公约数。 

当没有允许的周期划分所需的结构时，就会出现最后的边缘情况。 

例子：```
x = [1, 7, 13]
allowed periods = [4, 5]
```所有事件时间的模数一致`6`，但两者都没有`4`也不`5`可以全部生成，所以答案是`NO`。 

## 方法

 The most direct idea is to try every allowed period. For a chosen period`p`，我们可以检查所有事件时间是否属于同一个残差类模`p`。 

如果每个事件都满足：```
xi ≡ x1 (mod p)
```然后选择`y = x1`作品。 

该测试是正确的，因为每个振铃时间都由`x1`有时期`p`具有相同的模余数`p`。 

问题是成本。 最多有`3·10^5`候选期直至`3·10^5`活动时间。 测试每对都需要：```
O(nm)
```操作，规模太大了。 

关键的观察来自重写同余条件。 

如果所有事件时间必须满足：```
xi ≡ x1 (mod p)
```然后：```
p | (xi - x1)
```对于每一个`i`。 

一个数字若能整除集合中的每个值，则必须整除它们的最大公约数。 让```
g = gcd(x2 - x1, x3 - x1, ..., xn - x1)
```那么任何有效期限必须划分`g`。 

这彻底改变了问题。 

我们首先计算单个数字，而不是针对每个时期测试每个事件`g`。 那么我们只需要检查是否有一些允许的时期划分`g`。 

如果在允许的期限内`pj`满足：```
g % pj == 0
```那么每一个差异`(xi - x1)`可以整除`pj`，意味着所有事件时间的模数一致`pj`。 选择：```
y = x1
```立即生效。 

这将问题简化为一次 gcd 计算后的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读活动时间和允许的时间段。 
2. 计算：```
g = gcd(x2 - x1, x3 - x1, ..., xn - x1)
```这捕获了事件时间施加的每个可分性约束。 
3. 按输入顺序迭代允许的句点。 
4. 每个时期`pj`，检查是否：```
g % pj == 0
```如果这成立，那么`pj`划分每一个差异`(xi - x1)`。 
5. 一旦找到这样的周期，就输出：```
YES
x1 j
```在哪里`j`是该期间从 1 开始的索引。 
6. 如果不允许期间划分`g`， 输出：```
NO
```### 为什么它有效

 让```
g = gcd(x2 - x1, ..., xn - x1).
```如果一个时期`p`有效，则每个事件时间必须满足：```
xi ≡ x1 (mod p).
```等价地，```
p | (xi - x1)
```对于每一个`i`。 

自从`p`除以每一个差异，它必须除以他们的gcd`g`。 

反之，如果在允许的时间内`p`划分`g`，然后除以每个差值`(xi - x1)`。 因此：```
xi ≡ x1 (mod p)
```为所有人`i`。 

选择`y = x1`生成包含每个事件时间的响铃序列。 因此条件`p | g`既是必要的又是充分的。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x = list(map(int, input().split()))
    p = list(map(int, input().split()))

    g = 0
    for i in range(1, n):
        g = gcd(g, x[i] - x[0])

    for idx, period in enumerate(p, start=1):
        if g % period == 0:
            print("YES")
            print(x[0], idx)
            return

    print("NO")

solve()
```第一部分计算相对于第一个事件的所有差异的 gcd。 正在初始化`g`用零很方便，因为：```
gcd(0, a) = a
```因此第一个差值自动成为起始值。 

第二个循环扫描允许的周期。 除数时刻`g`找到了，答案就已知了，我们可以立即终止。 

使用`x[0]`因为开始时间就足够了，因为每个事件时间都具有与所选周期相同的余数。 没有搜索`y`是必要的。 

Python 整数处理的值可达`10^18`无需担心溢出。

 ## 边缘情况

 考虑：```
3 2
1 7 19
6 12
```差异是`6`和`18`，给予：```
g = 6
```算法检查周期`6`并接受它。 一个常见的错误是要求所有连续差值等于所选周期。 这里的差异并不相等，但有一段时期`6`完全有效，因为所有事件时间共享相同的余数模`6`。 

考虑：```
3 2
1 7 13
4 5
```我们得到：```
g = 6
```两者都不`4`也不`5`划分`6`，所以算法输出`NO`。 这可以处理事件结构承认有效期限但没有允许的选项提供有效期限的情况。 

考虑：```
2 3
10 25
3 5 15
```最大公约数为：```
g = 15
```算法发现`3`划分`15`和输出：```
YES
10 1
```一些解决方案错误地搜索精确的差异匹配，并且只接受`15`。 gcd 的任何除数都是有效的，因为所有事件时间对该除数的模数保持一致。
