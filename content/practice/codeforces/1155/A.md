 ## 解决方案
 ## 问题理解

 我们得到一个由小写英文字母组成的字符串。 我们可以在该字符串中选择一个连续的段，并将该段反转一次。 执行此单一反转后，我们获得一个新字符串。 任务是确定是否存在任何此类反转，使结果字符串按字典顺序小于原始字符串。 如果存在，我们必须输出任何有效的段； 否则我们报告这是不可能的。 

这里的字典顺序的行为类似于字典比较：两个字符串不同的第一个位置确定哪个较小。 这意味着改进必须尽早出现在字符串中，一旦实现较小的前缀，以后发生的任何事情都无关紧要。 

字符串长度可达 300,000，因此任何尝试所有子字符串或模拟每次反转的解决方案都太慢。 在最坏的情况下，对子串进行二次或三次扫描将需要大约 10^10 次操作，这在两秒内是不可行的。 这立即排除了对所有端点对的暴力破解。 

一个微妙的限制是，我们不需要最小化结果，只需要找到任何可以改善字典顺序的逆转即可。 这强烈表明我们正在寻找一种局部结构，该结构可以在字符串前面附近创建有益的不匹配。 

一个天真的错误是假设我们应该总是反转包含字符串中最小字符的段。 但这会失败，因为反转的效果取决于位置，而不仅仅是角色值。 另一种故障模式是反转一个段，该段改善了后面的位置但损害了前面的位置，这在字典顺序上没有帮助。 

更具体的边缘情况是当字符串已经在某种意义上不减少而阻止了改进时。 例如，像这样的字符串`aaaa`或者`abcde`不能通过任何反转来改进，因为反转任何子字符串要么使字符串保持不变，要么使早期字符更大。 

## 方法

 蛮力的想法很简单：尝试每对索引$l$和$r$，反转该子字符串，并将结果与​​原始字符串进行比较。 这是正确的，因为它探索了所有允许的操作，并且字典比较是确定性的。 然而，反转子字符串需要$O(n)$时间并且有$O(n^2)$选择、给予$O(n^3)$总的复杂性。 即使我们使用切片技巧优化反转，我们仍然面临$O(n^2)$比较对于 300,000 个字符来说太大了。 

关键的观察是，词典编序的改进是在我们设法减少字符的最早索引处确定的。 由于只允许一次反转，因此更改较早位置的唯一方法是将字符串中较后位置的较小字符移至较早位置。 

现在考虑一下反转的实际作用：它采用所选段的一些后缀并将其移动到该段的前面。 所以如果我们选择位置$l$和$r$, 位置处的字符$r$移动到位置$l$。 这是右侧字符影响段中最早位置的唯一方法。 

所以问题归结为寻找索引$l < r$这样$s[r] < s[l]$。 如果我们逆转$s[l..r]$, 字符$s[r]$移动到位$l$，使该位置更小并保证索引处的词典编排立即改进$l$，因为所有先前的位置保持不变。 

我们甚至不需要考虑第一个改进点之外的任何事情：一旦我们找到这样的一对，答案就是有效的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n^2)$|$O(1)$| 已接受 |

 ## 算法演练

 核心任务是找到两个索引，其中后一个较小的字符可以通过反转来替换较早的较大字符。 

1. 扫描所有可能的索引对$(l, r)$和$l < r$。 对于每一对，检查是否$s[r] < s[l]$。 这个条件保证了反转子串后$[l, r]$, 位置处的字符$l$变得比以前严格地变小。 
2. 一旦找到这样的一对，就将其输出并停止。 原始字符串按字典顺序发生变化的第一个位置将立即改进，因此不需要进一步验证。 
3. 如果扫描完所有可能性后不存在这样的对，则输出“NO”。 

正确性取决于词典编排改进需要减少第一个不同位置的事实。 降低仓位的唯一方法$l$使用单个反转是将较小的字符从后面的位置带入$l$，这恰好发生在$s[r] < s[l]$。 

### 为什么它有效

 任何反转都会通过反转顺序影响段，但不会引入新字符。 提高字典顺序的唯一方法是减少字符串可以更改的最早索引。 对于固定位置$l$，唯一可以替换的字符$s[l]$通过一次逆转是那些处于位置$r > l$，可以移动到$l$通过选择细分$[l, r]$。 如果没有这样的$r$存在于任何$l$，那么每个后缀字符都大于或等于前面位置的每个前缀字符，这意味着字符串是非递减的，任何逆转都无法改善。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

for l in range(n):
    for r in range(l + 1, n):
        if s[r] < s[l]:
            print("YES")
            print(l + 1, r + 1)
            sys.exit()

print("NO")
```该解决方案对所有线对执行直接扫描。 嵌套循环就足够了，因为我们只需要任何有效的改进，而不是最优的改进。 条件`s[r] < s[l]`精确编码反转将放置较小字符到位的要求`l`。 

在输出中使用基于 1 的索引是通过向两个索引添加 1 来处理的，因为问题陈述需要它。 程序在找到第一个有效对后立即退出，确保不会继续进行不必要的计算。

 ## 边缘情况

 一种重要的边缘情况是字符串包含重复字符但不包含严格较小的后续字符。 例如，`aabbaa`。 该算法会扫描所有字符对，虽然存在相同的字符对，但它们会被忽略，因为相等不会改善字典顺序。 由于在任何有帮助的位置之后都没有出现严格较小的字符，因此输出正确地变为“NO”。 

另一种情况是像这样的递减字符串`dcba`。 这里第一个有效对立即出现在$l = 1, r = 2$， 因为`c < d`。 反转任何较长的段也可以，但算法可以正确找到最小见证人，而不需要全局推理。 

最后一个微妙的情况是，改进是可能的，但不是相邻的，例如`abdc`。 有效的移动是$l = 2, r = 3$， 自从`b > d`是假的但是`d > b`相反的方向会带来改善。 扫描最终会发现`b`配对`d`，确认检查的局部性足以捕获第一个改进机会。
