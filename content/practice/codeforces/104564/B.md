 ## 解决方案
 ## 问题理解

 我们得到两个等长的数字字符串，代表两个记分牌值，但有些位置未知并显示为问号。 每个问号都可以替换为 0 到 9 之间的任何数字。填写完所有未知数后，每个字符串都成为一个具体的非负整数（允许有前导零，因为显示是固定宽度的）。 

任务是为所有问号选择替换，以使两个结果整数之间的绝对差尽可能小。 如果多次分配达到相同的最小差异，我们更喜欢第一个数字较小的分配。 如果仍然平局，我们最小化第二个数字。 

字符串的长度可达 18，因此不可能对赋值进行任何指数枚举。 即使每个字符有 10 个选择，在最坏的情况下也会给出 10^18 种可能性，这远远超出了任何可行的搜索。 

天真的贪婪方法会失败，因为有关数字的本地决策可能会让您陷入更糟糕的全局差异。 关键的困难在于，两个数字之间的比较具有字典顺序的意义：较早的数字支配后面的数字，但最佳选择取决于我们是否已经知道某个前缀处哪个数字更大。 

典型的失败情况是早期数字相等或未知，并且贪婪填充提交得太早。 例如，为一个字符串提前选择较小的数字可能会在以后产生巨大的后缀差异，即使稍大的早期数字可以更好地平衡总体数字。 

## 方法

 暴力解决方案将尝试将数字分配给问号并计算结果对。 这是正确的，但需要检查最多 10^k 种可能性，其中 k 是未知数的数量。 最坏情况下 k 高达 36，这是不可行的。 

关键的观察是该问题具有前缀结构：两个数字之间的最终比较是在它们不同的第一个位置确定的。 在此之前，前缀是相等的，我们处于中立状态。 一旦出现差异，剩下的选择就不再对称：一个数字已经更大，所以我们应该根据打破平局的规则最小化或最大化未来的贡献。 

这表明对具有三种状态的位置采用动态编程方法：到目前为止前缀是否相等，或者已经决定第一个数字更大，或者已经决定第二个数字更大。 在每个位置，我们尝试与输入约束一致的所有数字分配以及基于所选数字的比较的状态之间的转换。 

因为只有 18 个位置和 3 个状态，每个位置最多有 100 个数字对组合，所以总复杂度足够小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有任务 | O(10^k) | O(10^k) | O(k) | 太慢了 |
 | DP过位及比较状态| O(n·100·3) | O(n·3) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，维护一个 DP，存储每个位置每个状态的最佳可实现结果。

1. 我们定义三种比较状态：到目前为止相等，第一个已经更大，或者第二个已经更大。 这捕获了未来决策所需的所有信息，因为只有相对顺序很重要，而不是确切的数字差异。 
2. 在每个位置，我们考虑可以在两个字符串中放置哪些数字。 如果字符是固定的，我们只使用该数字。 如果是问号，我们会尝试从 0 到 9 的所有数字。 
3. 对于当前位置的每个数字组合，我们计算它如何改变比较状态。 如果先前的状态相等，则新状态取决于比较所选数字。 如果已经决定，则状态保持不变。 
4. 我们通过使用字典比较键保留每个状态的最佳结果来更新 DP。 关键是一个由完整构造的字符串组成的元组，它自动执行平局打破规则：首先最小化绝对差，然后最小化第一个字符串，然后最小化第二个字符串。 
5. 处理完所有位置后，我们选择所有状态中的最佳结果，因为最优解可能以任何比较状态结束。 

一个微妙的点是我们从不显式计算 DP 转换期间的数值差异。 相反，我们依靠比较状态来编码一个数字是否已经更大，这隐式地决定了后面的选择如何影响最终的差异。 

### 为什么它有效

 在任何位置，有关未来决策的所有相关信息都由当前索引和比较状态完全捕获。 除了确定一个前缀是否更大之外，确切的数字历史记录并不重要。 这将指数分配问题简化为每个状态具有恒定分支的线性扫描，同时保留正确排序所需的所有约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = (10**30, "", "")

def cmp(a):
    return a

def better(x, y):
    return x < y

def solve_case(C, J):
    n = len(C)

    dp = {
        (0, ""): (0, "", "")
    }

    for i in range(n):
        ndp = {}
        for (state, _), (_, c_str, j_str) in dp.items():
            c_choices = [int(C[i])] if C[i] != '?' else list(range(10))
            j_choices = [int(J[i])] if J[i] != '?' else list(range(10))

            for cd in c_choices:
                for jd in j_choices:
                    nc = c_str + str(cd)
                    nj = j_str + str(jd)

                    if state == 0:
                        if cd < jd:
                            nstate = -1
                        elif cd > jd:
                            nstate = 1
                        else:
                            nstate = 0
                    else:
                        nstate = state

                    key = (nc, nj)
                    val = (abs(int(nc) - int(nj)), nc, nj)

                    if (nstate, key) not in ndp or val < ndp[(nstate, key)]:
                        ndp[(nstate, key)] = val

        dp = ndp

    best = min(dp.values())
    return best[1], best[2]

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        C, J = input().split()
        c, j = solve_case(C, J)
        print(f"Case #{tc}: {c} {j}")

if __name__ == "__main__":
    solve()
```该代码逐个位置增量地构建解决方案。 DP 状态对比较关系和部分构造的字符串进行编码。 每个步骤都会尝试与约束一致的所有数字分配，并仅保留按字典顺序排列的最佳结果。 

一个关键的实现细节是将完整的字符串存储在 DP 状态中。 虽然这看起来很重，但长度以 18 为界，因此操作在实践中保持恒定时间。 另一个重要的细节是使用元组比较在单个操作中强制执行所有平局打破规则，避免手动条件逻辑。 

## 工作示例

 ### 示例 1：`1? 2?`在位置 0 处，可能的数字是 (1,2)。 这立即建立状态第一<第二。 在位置 1，两个数字都是自由的，但状态已经限制了最佳行为：我们尝试在尊重平局决胜的同时保持数字接近。 

| 步骤| C 前缀 | J 前缀 | 状态|
 | --- | --- | --- | --- |
 | 0 | 1 | 2 | J 较大 |
 | 1 | 19 | 19 20 | J 较大 |

 最终结果是 19 和 20，在约束条件下将差异最小化。 

### 示例 2：`?5 ?0`在位置 0 处，存在多种选择，但最好的对齐方式是 0 和 0，以延迟发散。 在位置 1，我们匹配剩余的约束。 

| 步骤| C 前缀 | J 前缀 | 状态|
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 等于|
 | 1 | 05 | 00 | 00 C 较大 |

 这会产生 05 和 00，最大限度地减少差异并尊重平局决胜局。 

这些痕迹显示了早期决策如何保持中立或强制一个方向，以及该方向如何控制所有后来的最佳选择。

 ## 边缘情况

 关键的边缘情况是两个字符串完全未知并且所有数字都是对称的。 该算法必须在任何地方都选择 0，因为任何非零数字都会增加幅度并可能增加差异。 

另一个边缘情况是第一个不同的位置出现较晚。 在这种情况下，早期的 DP 状态在许多步骤中保持相等，并且不正确的修剪将消除未来的最佳分裂。 状态机通过保持相等状态直到发生分歧来避免这种情况。 

最后，当一个字符串过早变得严格更大时，所有剩余的决策都应相应地一致最小化或最大化。 DP 状态确保一旦发生分歧，未来的转换就无法恢复它，这与数字比较的单调性质相匹配。
