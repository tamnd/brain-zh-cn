 ## 解决方案
 ## 问题理解

 我们有三枚硬币贴有标签`A`,`B`， 和`C`。 每对硬币都已经使用天平进行过一次比较，每次比较都会告诉我们哪枚硬币更重。 

一行像`A>B`意思是硬币`A`比硬币重`B`。 由于假设较重的硬币具有较大的面额，因此任务实际上是恢复三种硬币从最轻到最重的完整顺序。 

输入始终包含恰好三个比较，三个硬币中的每一对都有一个比较。 输出应该是一个长度为 3 的字符串，代表从最小重量到最大重量的硬币。 如果比较相互矛盾并且不存在有效的排序，我们打印`Impossible`。 

限制很小，因为只有三个硬币。 任何合理的算法都可以轻松地满足限制。 即使检查每个可能的顺序也是有效的恒定时间，因为只有`3! = 6`排列。 挑战不在于性能，而在于正确检测矛盾。 

棘手的部分是一些比较集形成循环。 例如：```
A>B
B>C
C>A
```这说`A`重于`B`,`B`重于`C`， 和`C`重于`A`。 没有排序可以同时满足所有三个条件。 只计算赢或输的粗心实现可能会意外地产生无效订单，而不是检测到矛盾。 

另一个微妙的情况是当比较已经在混合方向上给出时：```
A<B
C<B
A<C
```正确的顺序是`ACB`。 如果我们只跟踪直接关系而不考虑完整的顺序，我们可能会错误地放置`B`太早了，因为它出现在比较的双方。 

第三种边缘情况是当两个硬币受到同等约束时：```
A>B
A>C
B<C
```正确的顺序是`BCA`。 最强的硬币很容易识别，但剩下的两枚仍然需要仔细订购。 仅按“胜利次数”排序在这里有效，但这只是因为该图是非循环的。 如果没有矛盾检查，相同的逻辑就会在循环输入上中断。 

## 方法

 最直接的暴力解决方案是生成三种硬币的所有六种可能的排序，并根据比较来测试每一种。 

假设我们尝试排列`CAB`。 这意味着`C < A < B`。 对于每个输入关系，我们验证它是否与排列内的位置一致。 如果所有三个比较都匹配，我们就找到了答案。 

这种方法是正确的，因为每个有效的总排序必须出现在六个排列中。 该算法只是检查所有候选者，直到其中一个满足每个条件。 

只有六种排列，运行时间实际上是恒定的。 尽管暴力在这里是完全可以接受的，但思考它为何有效仍然有用。 我们直接验证全局一致性，而不是尝试逐步推断顺序。 

还有一种更干净的基于观察的解决方案。 

每次比较都会给出硬币之间的一种直接关系。 如果我们计算每枚硬币比另一枚硬币重多少次，假设比较一致，最轻的硬币将赢得零次，中间的硬币将赢得一次，而最重的硬币将赢得两次。 

例如：```
A>B
C<B
A>C
```硬币`A`两次获胜，`C`赢一次，并且`B`获胜次数为零。 按获胜次数排序给出`BCA`，但这是从最弱到最强的胜利来计算的。 由于胜利对应于较重的硬币，因此我们反转解释并得到`CBA`作为重量的递增顺序。 

有用的见解是，只要有三个不同的元素，有效的排序就会形成严格的链条。 除非存在矛盾，否则出度计数唯一地确定每个硬币的位置。 

矛盾的情况自然就出现了。 在这样的循环中：```
A>B
B>C
C>A
```每一枚硬币都只有一次胜利。 不存在唯一的排序，因为所有计数都是相同的。 检测重复计数会立即揭示不一致之处。

 ## 算法演练

 1. 创建一个字典，存储每个硬币的获胜次数：`A`,`B`， 和`C`。 
2.一一阅读三个比较。 
3. 对于每次比较：

 如果关系是`X>Y`，增加获胜次数`X`。 

如果关系是`X<Y`，增加获胜次数`Y`。 

较重的硬币获得一场胜利，因为它压倒了较轻的硬币。 
4. 处理完所有比较后，检查三个获胜计数。 
5. 在有效的订购中，计数必须准确无误`0`,`1`， 和`2`按某种顺序。 

如果两个硬币的数量相同，则关系是矛盾的，因此打印`Impossible`。 
6. 否则，按照获胜次数的增加对硬币进行排序。 

获胜次数较少的硬币较轻，因为它比其他较少的硬币重。 
7. 将排序后的序列输出为字符串。 

### 为什么它有效

 三种不同硬币的每一个有效排序都会形成严格的排名。 最轻的硬币比任何人都重，所以它得到`0`获胜。 中间的硬币比一枚硬币重，所以它得到`1`赢。 最重的硬币比其他硬币都重，所以它得到`2`获胜。 

矛盾会产生循环，从而阻止这些计数成为唯一的。 在一个周期内，没有任何一个币种能够始终在排名中占据独特的位置。 由于该算法仅接受不同的模式`0,1,2`，它拒绝所有矛盾的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

wins = {'A': 0, 'B': 0, 'C': 0}

for _ in range(3):
    s = input().strip()

    if s[1] == '>':
        wins[s[0]] += 1
    else:
        wins[s[2]] += 1

values = list(wins.values())

if len(set(values)) < 3:
    print("Impossible")
else:
    order = sorted(wins.keys(), key=lambda x: wins[x])
    print(''.join(order))
```字典`wins`存储每个硬币作为较重硬币出现的次数。 

每个比较的长度为三，所以`s[0]`和`s[2]`是硬币标签，而`s[1]`是`<`或者`>`。 

当关系是`A>B`, 硬币`A`因为它更重，所以赢得一胜。 当关系是`A<B`, 硬币`B`反而获得一场胜利。 

处理完所有比较后，解决方案会检查所有计数是否不同。 由三个元素组成的有效链必须产生计数`{0,1,2}`。 任何重复的值都表示循环或矛盾。 

排序步骤很微妙。 我们按照获胜次数递增的顺序进行排序，因为获胜次数越少意味着重量越轻。 如果我们不小心按降序排序，输出将变成从最重到最轻，而不是所需的从最轻到最重。 

不需要额外的图结构，因为只有三个节点，并且出度计数完全确定顺序。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    wins = {'A': 0, 'B': 0, 'C': 0}

    for _ in range(3):
        s = input().strip()

        if s[1] == '>':
            wins[s[0]] += 1
        else:
            wins[s[2]] += 1

    if len(set(wins.values())) < 3:
        print("Impossible")
    else:
        order = sorted(wins.keys(), key=lambda x: wins[x])
        print(''.join(order))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("A>B\nC<B\nA>C\n") == "CBA", "sample 1"

# cyclic contradiction
assert run("A>B\nB>C\nC>A\n") == "Impossible", "cycle detection"

# already increasing
assert run("A<B\nB<C\nA<C\n") == "ABC", "simple sorted order"

# reverse order
assert run("A>B\nA>C\nB>C\n") == "CBA", "fully descending"

# mixed relations
assert run("A<C\nB>A\nB<C\n") == "ABC", "mixed direction comparisons"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |

 |`A<B, B<C, A<C`|`ABC`| 处理已经排序的订单 |
 |`A>B, A>C, B>C`|`CBA`| 处理完全逆转的排名|

 ## 边缘情况

 考虑矛盾循环：```
A>B
B>C
C>A
```该算法计算获胜：```
A = 1
B = 1
C = 1
```由于计数不唯一，算法立即打印`Impossible`。 这正确地拒绝了不可能的排序。 

现在考虑一种以混合方向编写比较的情况：```
A<B
C<B
A<C
```处理比较给出：```
A = 0
C = 1
B = 2
```按胜利排序产生`ACB`，它符合真正的从轻到重的顺序。 该算法不关心输入方向，因为它总是增加较重的硬币。 

最后，考虑：```
A>B
A>C
B<C
```胜利计数变为：```
C = 0
B = 1
A = 2
```输出是`CBA`。 该案例证实，即使最强的硬币从一开始就很明显，中间的硬币也能被正确确定。
