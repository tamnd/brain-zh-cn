 ## 解决方案
 ## 问题理解

 我们正在尝试重建一个隐藏的二进制字符串长度`n`。 Vasya 所做的每一个猜测都是另一个相同长度的二进制字符串，以及一个数字，说明有多少位置与真实代码完全匹配。 

例如，如果隐藏代码是`101011`猜测是`111001`，答案是`3`因为字符串在三个位置一致。 

我们最多有十个这样的猜测。 每个答案最多是`5`，事实证明这是关键的限制。 任务是统计有多少个二进制字符串同时与所有答案一致。 

最直接的解释是：`2^n`二进制字符串，有多少个满足$$\text{matches}(x, s_i) = c_i$$对于每一次尝试`i`。 

这些约束完全排除了枚举每个可能的代码。 自从`n`可以达到`35`，搜索空间包含$$2^{35} \approx 3.4 \times 10^{10}$$字符串。 即使每秒检查十亿个字符串仍然太慢。 

尝试次数很少，最多只有`10`。 这表明解决方案必须利用猜测之间的关系，而不是强制所有候选人。 

不寻常的限制`c_i ≤ 5`才是真正的开口。 每个猜测与真实答案至少有一定的差异`n - 5`职位。 这意味着隐藏的代码与每个给定的字符串相距甚远，并且相对于任何一个猜测所需的更正数量很小。 

一些边缘情况很容易被错误处理。 

假设两个猜测相同但需要不同的匹配计数：```
6 2
000000 2
000000 3
```没有二进制字符串可以满足这两个条件，所以正确答案是`0`。 独立处理约束的粗心实现可能会意外地计算出不可能的状态。 

当约束要求零匹配时，会出现另一种微妙的情况：```
6 1
000000 0
```唯一有效的代码是`111111`。 任何考虑“改变一些位”的实现都必须允许在必要时翻转每个位置。 

还存在许多不同的更正产生相同的最终字符串的情况。 例如：```
6 2
000000 1
111111 5
```这两个约束都描述完全相同的一组字符串，即所有字符串都恰好有一个零。 简单的递归搜索可能会重复计数，除非它存储完整的分配而不是路径。 

## 方法

 蛮力的想法很简单。 枚举每个长度的二进制字符串`n`，将其与所有比较`m`猜测，并计算有多少满足所有匹配计数。 

检查一名候选人的成本`O(mn)`因为我们会逐个字符地比较每个猜测。 总复杂度变为$$O(2^n \cdot m \cdot n)$$这是无望的`n = 35`。 

约束的结构提出了不同的观点。 选择一个猜测作为参考字符串，比如第一个。 其所需的匹配数为`c`。 

由于隐藏字符串恰好具有`c`与此参考匹配的位置，它的不同之处在于$$n - c$$职位。 

乍一看这仍然很大，因为`n - c`可能在附近`30`。 但翻转视角会有所帮助。 

不要直接构造隐藏字符串，而是考虑哪些位置仍然等于参考字符串。 自从`c ≤ 5`，这样的位置最多有五个。 

这极大地改变了搜索空间。 我们只需要选择最多五个相对于第一个猜测保持不变的位置。 其他所有位置都会自动成为相反的位。 

这样的子集的数量是$$\sum_{k=0}^{5} \binom{35}{k}$$这是在`400000`。 对于每个子集，我们可以准确地重建一个候选字符串并验证所有约束。 

这是可行的，因为二进制字符串在每个位置只有两个可能的值。 一旦我们确定某个位置是否与参考字符串匹配，它的值就固定了。 

暴力破解之所以成功，是因为可以独立检查每个有效代码。 优化解决方案成功是因为第一个约束将候选空间压缩为`2^35`减少到大小最多为五个的所有子集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot m \cdot n)$|$O(1)$| 太慢了|
 | 最佳|$O\left(mn \sum_{k=0}^{5}\binom{n}{k}\right)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 阅读所有猜测及其所需的匹配计数。 
2. 选择第一个猜测作为参考字符串。 
3. 假设第一个猜测有匹配数`c`。 隐藏代码必须与该字符串完全不同`n - c`职位。 
4. 不要选择不同的位置，而是选择与参考字符串保持相同的位置。 他们的计数正好是`c`，并且自从`c ≤ 5`，可能性的数量很小。 
5. 枚举大小位置的每个子集`c`。 

这些位置被声明等于第一个猜测。 所有其他位置都翻转。 
6. 构造该子集隐含的候选字符串。 

对于每个索引：

 - 如果索引属于所选子集，则复制参考位
 - 否则，反转它

 因为字母表是二进制的，所以这唯一地确定了整个字符串。 
7. 检查候选人的每一个猜测。 

计算有多少个位置匹配。 如果每个计数都等于所需值，则候选者有效。 
8. 统计所有有效候选人并打印总数。 

### 为什么它有效

 第一个约束将所有位置分为两组：隐藏字符串等于参考猜测的位置和不同的位置。 

由于字符串是二进制的，“不同”意味着相反的位，而不是任意的第三个值。 一旦选择了相等的位置，隐藏字符串就完全确定了。 

每个有效的隐藏字符串恰好对应于大小相同的位置的一个子集`c`，并且每个这样的子集恰好生成一个候选字符串。 该算法枚举所有这些子集并过滤掉那些违反其他约束的子集，因此每个有效的解决方案都只计算一次。 

## Python 解决方案```python
import sys
from itertools import combinations

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    strings = []
    counts = []

    for _ in range(m):
        s, c = input().split()
        strings.append(s)
        counts.append(int(c))

    base = strings[0]
    keep = counts[0]

    ans = 0
    positions = list(range(n))

    for same_positions in combinations(positions, keep):
        same_set = set(same_positions)

        candidate = []

        for i in range(n):
            if i in same_set:
                candidate.append(base[i])
            else:
                candidate.append('1' if base[i] == '0' else '0')

        candidate = ''.join(candidate)

        ok = True

        for s, need in zip(strings, counts):
            match = 0

            for a, b in zip(candidate, s):
                if a == b:
                    match += 1

            if match != need:
                ok = False
                break

        if ok:
            ans += 1

    print(ans)

solve()
```实现直接遵循数学简化。 

第一个重要的观察出现在以下几行中：```
base = strings[0]
keep = counts[0]
```我们使用第一个猜测作为参考字符串。 任何有效答案都必须完全匹配`keep`职位。 

循环```
for same_positions in combinations(positions, keep):
```枚举隐藏代码等于参考字符串的每个可能的位置集。 自从`keep ≤ 5`，这个枚举保持足够小。 

候选人的结构很微妙。 对于所选子集之外的位置，我们必须翻转该位：```
'1' if base[i] == '0' else '0'
```这只有效，因为字母表是二进制的。 在较大的字母表中，与参考不同不会唯一地确定该值。 

验证步骤将候选者与每个猜测进行比较，并计算完全匹配的数量。 发现矛盾后立即退出循环，避免了不必要的工作。 

一个常见的错误是尝试在迭代子集时增量地改变引用字符串。 从头开始重建候选者更简单，并且可以避免陈旧的状态错误。 

另一个微妙之处是独特性。 不同的子集总是生成不同的候选字符串，因为等于参考的位置是唯一确定的。

 考虑矛盾约束情况：```
