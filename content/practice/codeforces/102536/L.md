 ## 解决方案
 ## 问题理解

 任务是找到几个不同的多项式，这些多项式将给定整数序列中的每个值作为根。 序列中的值不被视为普通整数。 相反，它们被转换为模数为 999983 的有限域元素，因此相差 999983 倍数的两个数字表示相同的值。 

对于每个序列，我们需要输出最多`n`次数不超过的不同非零多项式`k`。 如果少于`n`这样的多项式是存在的，每一个可能的多项式都必须被打印出来。 

在程度和序列长度方面的约束很小，但测试用例的数量很大。 由于可能有 2500 个案例，因此重复执行昂贵的多项式运算的解决方案会太慢。 度数限制和序列长度最多为 50 告诉我们，周围的操作`O(k^2)`或者`O(ell * k)`是合适的，而枚举所有可能的多项式是不可能的，因为即使是 10 次也已经在大小为 999983 的字段上给出了大量候选多项式。 

有一些细节很容易被忽略。 首先，重复的序列值不会产生额外的根要求。 例如，序列`1 1 1`具有与完全相同的限制`1`，因为多项式只需在该场元素处为零一次。 

其次，在构建多项式之前，必须以 999983 为模减少值。 一个序列包含`1`和`999984`不需要两个根。 它们代表了该领域的同一点。 

第三，多项式不能是零多项式。 对于空度范围来说，这很重要，因为将有效的根多项式乘以零会创建另一个不允许的多项式。 

例如，考虑：```
1
2 3 3
1 1 1
```唯一需要的根是`1`。 多项式`(x - 1)`有效，将其乘以任何次数最多为 2 的非零多项式也有效。 将重复值视为单独根的粗心解决方案可能会认为所需多项式的次数为 3，并错误地打印零答案。 

另一个例子是：```
1
1 1 2
1 999984
```两个序列值均以 999983 为模。多项式`x - 1`是有效的。 将这些值视为普通整数会错误地得出需要两个不同根的结论。 

## 方法

 直接方法将尝试最多生成每个次数的多项式`k`，对每个序列值进行评估，并保留成功的值。 这是正确的，因为它完全检查了所需的条件，但它是完全不可行的。 即使阶数只有 10，可能的系数组​​合数量也大致为`999983^11`，所以生成是不可能的。 

有用的观察来自于观察所有有效多项式的共同点。 如果不同的序列值是`a1, a2, ..., am`在现场，每个有效多项式必须包含所有因子`(x - ai)`。 满足条件的最小多项式为：`g(x) = (x - a1)(x - a2)...(x - am)`每个其他有效多项式都恰好是`g(x) * h(x)`对于某些多项式`h(x)`。 这将问题从搜索多项式转变为选择不同的乘数。 

程度`g`是不同根的数量。 如果它大于`k`，即使是最小的可能有效多项式也太大，因此不存在答案。 否则，`h`最多可以有学位`k - degree(g)`。 

几乎在每种情况下，可能的非零乘数的数量都足够大，但我们只需要 50 个答案。 我们可以简单地生成简单的乘数，例如常数和幂`x`，因为它们保证是不同的多项式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 不可能，大约`O(999983^(k+1))`候选人 | 巨大 | 太慢了 |
 | 最佳 |`O(ell * k + k^2)`每个测试用例|`O(k)`| 已接受 |

 ## 算法演练

 1. 以 999983 为模减少每个序列值并仅保留不同的值。 剩余值的数量就是我们需要构造的最小多项式的次数。 重复的根不会改变所需的因式分解。 
2. 构建多项式`g(x) = product(x - root)`一次将当前系数数组乘以一个线性因子。 多项式乘法很小，因为最大次数仅为 50。 
3.如果程度`g`大于`k`，输出零，因为每个拟合多项式都必须包含`g`作为一个因素，并且已经太大了。 
4. 否则，令剩余度容量为`r = k - degree(g)`。 构建不同度数最多的乘数`r`。 最简单的选择是`1, x, x^2, ...`，给出候选多项式`g, xg, x^2g, ...`。 
5. 继续创建答案，直到`n`多项式已产生或所有可能的乘数已用尽。 

可能的乘数的数量是`999983^(r+1) - 1`，因为乘法器的每个系数都可以独立选择，并且排除全零乘法器。 自从`n`最多50，只需要几个简单的乘数就可以达到目标。 
6. 将系数从场表示转换为整数`0`和`999982`，并按降序打印度数和系数。 

为什么它有效：

 每个拟合多项式在每个不同的序列值处都必须为零，因此它必须可被所有相应线性因子的乘积整除。 该算法精确地构造了这个最小的可能多项式，并且仅将其乘以其他非零多项式，因此每个生成的答案仍然有效。 由于选择的乘数不同并且该域具有唯一的多项式表示，因此得到的多项式是不同的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 999983

def multiply_linear(poly, root):
    res = [0] * (len(poly) + 1)
    for i, c in enumerate(poly):
        res[i] = (res[i] - c * root) % MOD
        res[i + 1] = (res[i + 1] + c) % MOD
    return res

def solve_case(n, k, seq):
    roots = set(x % MOD for x in seq)

    poly = [1]
    for x in roots:
        poly = multiply_linear(poly, x)

    if len(poly) - 1 > k:
        return ["0"]

    ans = []
    max_extra = k - (len(poly) - 1)

    for power in range(max_extra + 1):
        cur = [0] * power + poly[:]
        while len(cur) > 1 and cur[-1] == 0:
            cur.pop()
        ans.append([len(cur) - 1] + cur[::-1])
        if len(ans) == n:
            break

    possible = pow(MOD, max_extra + 1) - 1
    if possible < n:
        return [str(len(ans))] + [" ".join(map(str, x)) for x in ans]

    return [str(n)] + [" ".join(map(str, x)) for x in ans[:n]]

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n, k, l = map(int, input().split())
        seq = list(map(int, input().split()))
        out.extend(solve_case(n, k, seq))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```多项式在内部以指数递增顺序存储。 例如，`[3, 5, 7]`代表`3 + 5x + 7x^2`。 该表示法乘以`(x - root)`很简单，因为每个旧系数都对两个相邻位置有贡献。 

这`multiply_linear`函数每次执行一个根的最小多项式的构造。 乘法期间应用模运算，因为所有计算都发生在有限域中。 

生成的答案使用`x^i * g(x)`作为乘数。 将系数数组移动`i`位置代表乘以`x^i`。 由于学位从未超过`k`，每个生成的多项式都满足所需的限制。 

Python 整数不会溢出，但代码仍然保持所有系数以 999983 为模减少。这使值保持较小并符合多项式等式问题的定义。

```最小多项式的次数仍为 4。 

| 步骤| 所需学位 | 最大度数| 结果 |

 ## 边缘情况

 对于重根，该算法在乘以因子之前将值存储在一组中。 对于输入：```
1
2 3 3
1 1 1
```根集变为`{1}`。 多项式`x - 1`是用 1 度构建的，还剩下两个额外的度数可用。 算法输出`g(x)`和`xg(x)`，两者均有效。 

对于等于模 999983 的值，减少发生在根收集之前。 为了：```
1
1 1 2
1 999984
```第二个值变成`1`，所以最小多项式仍然存在`x - 1`。 针对普通整数的解决方案将构造一个不必要的大多项式。 

对于不可能的度数限制，算法会检查最小可能答案的度数。 和：```
1
1 3 4
1 2 3 5
```最小多项式的次数为 4，已经大于允许的次数 3。由于每个有效多项式都必须包含该因子，因此不存在有效输出且答案为零。
