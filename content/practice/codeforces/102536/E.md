 ## 解决方案
 ## 问题理解

 我们有一个由网格表示的矩形地板。 有些牢房是正常的步行空间，有些是墙壁，有些是门。 代理从标记的单元格开始`A`并且需要到达标记的单元格`B`。 

移动到相邻的可步行单元需要一秒钟的时间。 门禁单元在关闭时不可行走。 打开邻近的门需要一秒钟，一旦打开，特工就可以通过它。 任何时刻，不超过`k`门可能保持打开状态。 任务是找到到达炸弹的最短可能时间，或者报告无法到达。 

对于图算法来说，约束足够小，但对于重复探索网格的大部分的算法来说却不够。 单个网格最多包含 5000 个单元格，而所有测试用例总共最多包含 300000 个单元格。 这意味着每个单元需要一个近似线性或线性算数的解决方案。 尝试所有可能的打开门组合的解决方案是不可能的，因为门子集的数量呈指数增长。 即使对许多不同的门配置进行全面搜索也会很快超出时间限制。 

关键的困难在于打开门的数量很重要，而不仅仅是代理的位置。 忽略门限制的最短路径可能会低估答案，因为它可能会留下太多门打开。 

考虑一个小案例：```
1
1 3 1
ABD
```输出是：```
HAHAHUHU
```特工无法进门，因为门实际上就在炸弹后面？ 这个例子是无效的，因为`B`必须是一个空单元，因此将所有非壁单元视为可互换的粗心实现可能已经在格式错误的假设上失败。 一个有效的小例子是：```
1
1 4 1
AD.B
```输出是：```
HAHAHUHU
```门挡住了唯一的路，没有办法绕过去。 将门视为开放单元的普通 BFS 会错误地报告路径。 

另一个重要的情况是当路线使用的门多于`k`。```
1
1 5 1
ADDB.
```特工必须穿过两扇门，但只有一扇门可以保持打开状态。 第一扇门可以保持打开状态，而第二扇门必须在通过后关闭。 只计算打开的门数量而忘记关闭成本的解决方案会低估答案。 

## 方法

 直接的暴力方法将保持地板的完整状态：当前位置以及哪些门打开。 这是正确的，因为未来取决于这两条信息。 然而，如果有`m`门，这创造了`r*c*2^m`州。 即使是有几十扇门的网格也让这成为不可能。 

有用的观察是我们不需要知道打开的门的身份。 对于选定的路线，代理穿过的每扇门都必须打开一次。 唯一的决定是最后哪扇门保持打开。 最多`k`其中可以避免成交成本。 

假设一条路径交叉`d`门细胞并包含`s`细胞之间的运动。 运动本身的成本`s`。 打开所有门需要花费`d`。 这些门之中，最多`k`避免被关闭。 剩下的每扇门都会增加关闭时间。 总成本为：`s + d + max(0, d - k)`这意味着我们只需要知道已经穿过了多少扇门，上限为`k`。 一旦我们已经穿越`k`门，每扇额外的门的行为都是相同的：它增加了额外的打开和关闭成本。 

现在可以展开该图。 一个状态是`(cell, x)`， 在哪里`x`交叉门的数量上限为`k`。 移动到空单元格会保留`x`不变，成本为 1。 通过一扇门会增加`x`如果低于`k`; 第一次的成本是两秒`k`门，三秒钟后。 

由于所有边权重都是小的正值，因此 Dijkstra 算法可以找到最小距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解打开的门组 | O(rc * 2^m) | O(rc * 2^m) | 太慢了 |
 | 带门数的扩展图 | O(rc * k log(rc*k)) | O(rc * k log(rc*k)) | O(rc * k) | 已接受 |

 ## 算法演练

 1.找到起始单元格`A`和目标单元格`B`。 创建一个最短路径状态图，其中每个网格单元都有`k + 1`可能的状态。 状态`x`意味着正是`x`门已被跨过，在那里`x = k`也代表每个大于或等于的值`k`。 
2. 从以下位置开始 Dijkstra 算法`(A, 0)`。 代理在开始时没有穿过任何门，因此初始门数为零。 
3. 扩展状态时，尝试移动到四个相邻单元格中的每一个。 墙被忽略，因为它们永远无法进入。 
4. 如果邻居是空单元格或炸弹单元格，则新状态保持相同的门数并收到一秒的额外成本。 这只是正常的运动。 
5.如果邻居是一扇门，如果门数状态仍然低于，则增加门数状态`k`。 输入第一个`k`门需要两秒：打开门需要一秒，穿过门需要一秒。 进入一扇门后`k`已经穿过的门需要花费三秒的时间，因为该门最终必须关闭。 
6. 答案是所有以炸弹单元为终点的状态之间的最小距离。 不同的门数可能会以不同的成本到达炸弹。 

为什么它有效：

 对于任何路线，影响门额外成本的唯一信息是进入每扇门之前经过了多少扇门。 门的确切身份并不重要，因为代理可以选择任何门`k`门保持打开状态。 该状态准确地存储了确定下一扇门是否需要花费两秒或三秒所需的信息。 由于 Dijkstra 探索的状态不断增加，并且每条可能的有效路线都对应于该展开图中的一条路径，因此找到的最小距离就是真正的最短到达时间。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        r, c, k = map(int, input().split())
        grid = []
        start = -1
        target = -1

        for i in range(r):
            row = list(input().strip())
            for j, ch in enumerate(row):
                if ch == 'A':
                    start = i * c + j
                elif ch == 'B':
                    target = i * c + j
            grid.extend(row)

        n = r * c
        states = k + 1
        total = n * states
        INF = 10**18

        dist = [INF] * total
        dist[start * states] = 0

        heap = [(0, start, 0)]

        while heap:
            d, pos, used = heapq.heappop(heap)
            idx = pos * states + used
            if d != dist[idx]:
                continue

            if pos == target:
                ans.append(str(d))
                break

            x = pos // c
            y = pos % c

            for nx, ny in ((x - 1, y), (x + 1, y), (x, y - 1), (x, y + 1)):
                if nx < 0 or nx >= r or ny < 0 or ny >= c:
                    continue

                npos = nx * c + ny
                cell = grid[npos]

                if cell == '#':
                    continue

                if cell == 'D':
                    if used < k:
                        nused = used + 1
                        cost = 2
                    else:
                        nused = k
                        cost = 3
                else:
                    nused = used
                    cost = 1

                nd = d + cost
                nidx = npos * states + nused

                if nd < dist[nidx]:
                    dist[nidx] = nd
                    heapq.heappush(heap, (nd, npos, nused))
        else:
            ans.append("HAHAHUHU")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```距离数组为每个扩展图状态存储一个值。 指数`cell * (k + 1) + used`唯一地标识网格位置以及已经穿过的门的数量。 

堆包含`(current distance, cell, used doors)`条目。 当旧条目的距离不再与存储的最短距离匹配时，旧条目将被忽略，这是 Dijkstra 的标准延迟删除技术。 

门的过渡成本是核心实施细节。 到达之前`k`越过门，进入另一扇门需要两秒。 在那之后，每扇新门都必须稍后关闭，因此成本变为三秒。 门数上限为`k`，这使得状态数量易于管理。 

无需显式模拟关闭门。 过渡背后的公式已经解释了哪些门保持开放的最佳选择。

 ## 边缘情况

 没有门的路线由国家管理`(cell, 0)`仅有的。 该算法简化为空单元格上的普通最短路径，因为每次移动只花费一秒钟。 

当最优路径上的门数超过`k`，该算法不会因为仅存储而丢失信息`k`。 一次`k`门已经可以保持打开状态，后面的每扇门都有相同的额外费用。 例如，在`ADDB.`和`k = 1`，第一扇门使用空闲槽，第二扇门增加关闭惩罚。 

如果将门像普通单元一样对待，则看似可能的路线将被拒绝，因为门单元只能通过门过渡进入。 转换逻辑是唯一可以穿过门的地方，因此墙壁和关闭的门不会意外地成为正常的移动单元。
