 ## 解决方案
 # 问题理解

 该火山包含`n`陨石坑，每个陨石坑要么被填满（`1`) 或空 (`0`）。 每天罗罗必须准时来访`m`陨石坑。 访问会翻转所选的火山口：空的火山口会被填满，而已填充的火山口会变成空的。 我们需要选择每日访问集的序列，以便最多之后`n`每一天，每个火山口都被填满。 

输出不仅仅要求最终状态。 我们必须打印准确的日常命令，其中每个命令都是一个二进制字符串，并且精确地`m`那些。 1 表示当天访问了火山口。 

约束足够小`n`虽然只有 80 个，但是日常可能执行的命令数量却是巨大的。 直接搜索可能的几天将大致有`C(n, m)`每天的选择，即使对于很小的值来说也已经太大了`n`。 80 的限制表明预期的解决方案应该使用线性代数或其他复杂度接近的方法`O(n^3)`而不是探索状态。 

棘手的部分是，访问陨石坑两次会被抵消，因为该操作是翻转。 天数的顺序在数学上并不重要，只有所有选定的每日掩码的异或才重要。 贪婪地尝试填充当前空坑的粗心解决方案可能会失败，因为稍后的访问可能会重新打开它们。 

考虑以下情况：```
1
1 1
0
```正确的输出是有一天访问唯一的火山口：```
1
1
```如果解决方案假设已经填满的弹坑是唯一有用的目标，那么就会忽略一次翻转就可以解决问题。 

另一个边缘情况是必须每天访问每个陨石坑：```
1
3 3
101
```唯一可能的操作是`111`，翻转所有陨石坑。 一次操作后状态变为`010`，没有全部填满，重复只是交替。 正确的输出是：```
CATACLYSM IMMINENT - TIME TO HOARD FACE MASKS
```仅检查是否可以减少空坑数量的解决方案将错误地接受这种情况。 

## 方法

 暴力方法是将每个可能的日常命令视为一个动作，并对所有可能的状态执行图形搜索。 状态是一个长度为二进制的字符串`n`，所以有`2^n`州。 从每个州我们都可以尝试`C(n, m)`可能的命令。 在最坏的情况下，这会探索不可能数量的转换，远远超出允许的限制。 

有用的观察是每个操作都只是异或。 如果当前状态是`S`，最终状态必须全为 1，因此所有命令的总异或必须等于：`S XOR 111...111`问题变成了找到权重的集合-`m`其 XOR 等于目标向量的二进制向量。 

为了`m < n`，所有重量-`m`向量几乎跨越整个向量空间。 如果`m`是偶数，每个可能的 XOR 都具有偶奇偶校验，因此只有具有偶数个设置位的目标才能到达。 如果`m`是奇数，跨度是整个空间，所以每个目标都是可达的。 

我们可以使用 GF(2) 上的高斯消元法构建有效的日常命令的基础。 我们不是生成所有可能的命令，而是生成足够的结构化命令来跨越空间。 从包含第一个的掩码开始`m`职位。 将一个选定的位置与一个未选择的位置交换会产生另一个有效的掩模，并且这些交换提供了坐标之间必要的差异。 

蛮力之所以有效，是因为考虑了所有可能的路径，但当状态空间爆炸时就会失败。 XOR 结构让我们用寻找基向量的线性组合来代替路径寻找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * C(n,m)) | O(2^n * C(n,m)) | O(2^n) | O(2^n) | 太慢了 |
 | 最佳| O(n^3) | O(n^3) | O(n) | 已接受 |

 ## 算法演练

 1. 将问题转换为 XOR 目标。 目前的陨石坑`0`需要翻转奇数次，而已经形成的陨石坑`1`需要翻转偶数次。 目标向量是初始状态的补集。 
2.特殊情况处理`m = n`。 唯一可能的命令是访问每个陨石坑。 该命令只是翻转整个向量，因此只有通过重复翻转所有向量才能到达所有向量的状态才是可能的。 
3.为了`m < n`，创建候选命令。 从访问第一个的命令开始`m`陨石坑。 然后通过将这些位置之一替换为该组之外的位置来创建命令。 每个生成的命令仍然准确包含`m`访问。 
4. 将这些命令插入到 GF(2) 上的线性基中。 在插入期间，保持原始命令与每个基向量相关联。 我们只需要独立的向量，因为任何目标都可以使用每个基向量最多表示一次。 
5. 使用基础减少目标向量。 每当使用基向量时，请将其原始命令添加到答案中。 如果目标不能减少到零，则目标超出范围，答案是不可能的。 
6. 输出选定的命令。 选取的基向量的个数最多为`n`，因此天数始终满足限制。 

为什么它有效：生成的命令构成了所有可到达的更改空间的基础。 高斯消除保留了跨度，同时删除了冗余命令。 当目标完全减少时，所选原始命令的异或正是所需的更改。 应用这些命令会将最初为空的每个火山口翻转奇数次，并将最初填充的每个火山口翻转偶数次，使所有火山口都被填充。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

BAD = "CATACLYSM IMMINENT - TIME TO HOARD FACE MASKS"

def solve_case(n, m, s):
    if s == "1" * n:
        return []

    if m == n:
        if s == "0" * n:
            return ["1" * n]
        return None

    target = 0
    for i, c in enumerate(s):
        if c == '0':
            target |= 1 << i

    base = (1 << m) - 1
    candidates = [base]

    for a in range(m):
        for b in range(m, n):
            candidates.append(base ^ (1 << a) ^ (1 << b))

    basis = [0] * n
    original = [0] * n

    for mask in candidates:
        x = mask
        for bit in range(n - 1, -1, -1):
            if (x >> bit) & 1:
                if basis[bit]:
                    x ^= basis[bit]
                else:
                    basis[bit] = x
                    original[bit] = mask
                    break

    ans = []
    x = target
    for bit in range(n - 1, -1, -1):
        if (x >> bit) & 1:
            if basis[bit] == 0:
                return None
            ans.append(original[bit])
            x ^= basis[bit]

    res = []
    for mask in ans:
        cur = []
        for i in range(n):
            cur.append('1' if (mask >> i) & 1 else '0')
        res.append(''.join(cur))

    return res

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()
        ans = solve_case(n, m, s)
        if ans is None:
            out.append(BAD)
        else:
            out.append(str(len(ans)))
            out.extend(ans)
    print('\n'.join(out))

if __name__ == "__main__":
    main()
```实现的第一部分处理可能的操作受到限制的情况。 什么时候`m = n`，只有一个可能的向量，因此不需要一般的线性代数。 

对于正常情况，目标掩模是通过标记每个需要改变的凹坑来构建的。 基础构造使用整数作为位集，这使得 XOR 运算非常快，并且避免为每个向量维护长度为 80 的数组。 

消除过程中，`basis[bit]`存储最高设置位为的向量`bit`。 平行的`original`数组存储生成该基本向量的实际日常命令。 这种区别很重要，因为转换后的基向量仅用于计算，而输出必须包含正确的有效命令`m`参观了陨石坑。 

缩减阶段收集基础使用的原始命令。 最终名单已经保证最多有`n`元素，因为线性基础超过`n`位最多包含`n`向量。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^3) | O(n^3) | 生成的候选数为 O(n^2) 个，每次插入/归约都使用 O(n) XOR 运算。 |
 | 空间| O(n) | 基础为每个位位置最多存储一个向量。 |

 和`n <= 80`，即使立方界也很小。 生成的候选数最多约为 6400 个，并且每次运算都只是整数 XOR，因此该解决方案很容易满足限制。

 ## 边缘情况

 对于已经解决的状态：```
1
2 1
11
```目标向量为零，因此不需要翻转。 该算法立即返回一个空序列，而不是尝试会干扰答案的不必要的操作。 

对于不可能完全访问的情况：```
1
3 3
101
```唯一可能的命令是`111`。 目标是`010`，但唯一可到达的状态是通过重复异或来获得的`111`，这之间交替`101`和`010`。 由于这两个状态都不是全 1，因此算法正确地拒绝了它。 

对于甚至`m`平价：```
1
4 2
1000
```所需的更改具有三个设置位。 每个命令恰好更改两位，因此命令的任何 XOR 必须包含偶数个更改的位。 基差减少不能消除最终的奇数平价目标并报告不可能。
