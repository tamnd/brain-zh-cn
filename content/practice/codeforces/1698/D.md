 ## 解决方案
 ## 问题理解

 我们从 1 到 n 的数字排列开始，但排列不是任意的。 它是通过选择不相交的位置对并交换每对内的值来根据恒等排列创建的。 由于 n 是奇数，因此这些交换恰好有一个位置未受影响，并且位于该位置的值也是该索引的原始值。 

我们的任务是确定哪些值保留在其原始位置。 我们无法直接看到数组。 相反，我们可以查询任何段 [l, r]，并且判断器返回按升序排序的该段中的值。 这意味着我们丢失了查询范围内的位置信息，但我们仍然了解该区间内的多重值集。 

15 个查询的交互约束强烈表明我们必须使用少量精心选择的比较来提取全局结构，而不是在本地重建任何内容。 

关键的结构属性是每个值要么保持固定，要么恰好属于一个交换，因此对于 i < j 的每一对 (i, j)，值 i 和 j 都会交换，这意味着 i 出现在 j 处，j 出现在 i 处。 这意味着对称性：每个不正确的位置都会产生位移，唯一的固定点是位置与其值相匹配的唯一值。 

一个天真的想法是通过查询单个元素来重建整个数组，但每个单元素查询只给出该位置的值，这是可能的，但已经花费了n次查询。 由于 n 可能很大并且我们只有 15 个查询，所以这是不可能的。 

另一个诱人的想法是尝试从小段进行随机采样或局部推理，但排序会破坏排序信息，因此局部推理无法可靠地确定位移方向。 

真正的约束压力是我们需要一个全局属性，当我们包含或排除固定点时，该属性会单调变化。 这表明前缀或后缀行为的二分搜索风格参数。 

## 方法

 暴力方法将使用 [i, i] 单独查询每个位置，恢复整个数组，然后检查哪个索引 i 满足 a[i] = i。 这是正确的，因为固定点保证是唯一的。 但是，这会花费 n 个查询，一旦 n > 15，就会超出限制。 

关键的观察是我们不需要完全重建。 我们只需要检测中点的哪一侧包含固定点。 如果我们将一个段中的值的总和与预期身份段的总和进行比较，我们可以检测到由于交换跨越边界而导致的不平衡。 然而，金额并不能直接获得； 相反，我们收到排序值，它仍然准确地保留多重集总和。 

因此，对于任何查询 [l, r]，我们可以计算返回值的总和。 同一性的预期总和将为 (l + r)(r - l + 1) / 2。实际总和与预期总和之间的任何差异都表明该段包含跨越其边界的移位元素。 至关重要的是，如果一个段不包含固定点，则交换在内部或外部完美配对，并且总偏差表现一致。 这允许我们对固定点的位置进行二分搜索。 

在每一步中，我们都会测试中点前缀 [1, mid]。 如果总和与预期不同，则不动点位于其中； 否则它位于后缀中。

 | --- | --- | --- | --- |
 | 蛮力 | O(n) 次查询 | O(1) | O(1) | 太慢了|
 | 最佳 | O(log n) 次查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护一个搜索范围 [l, r]，其中必须包含固定点。

1. 初始化 l = 1 且 r = n。 固定点保证位于该区间内。 
2. 当 l < r 时，计算 mid = (l + r) // 2。 
3. 查询段[l, mid]，并接收该范围内的排序值。 计算它们的总和S。 
4. 计算恒等段 [l, mid] 的期望和，即 ((l + mid) * (mid - l + 1)) // 2。 
5. 将 S 与预期总和进行比较。 如果它们相等，则跨越边界的交换不会影响该段，因此固定点必须位于 [mid + 1, r] 中。 否则，它位于 [l, mid] 中。 
6. 相应地更新 l 或 r 并重复。 
7. 当l == r时，输出l作为不动点的位置。 

### 为什么它有效

 每个交换要么完全留在测试段内，要么跨越其边界。 如果一个段不包含不动点，则影响它的所有交换都是完全内部或外部的，因此总和与恒等和完全匹配。 在前缀和中创建持久不平衡从而改变二分搜索决策的唯一方法是该段是否包含唯一的未配对元素（即固定点）。 这使得前缀和测试成为索引空间上的有效单调谓词，从而实现二分搜索。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(l, r):
    print("?", l, r)
    sys.stdout.flush()
    arr = list(map(int, input().split()))
    if arr and arr[0] == -1:
        sys.exit(0)
    return arr

def segment_sum(arr):
    return sum(arr)

def expected_sum(l, r):
    cnt = r - l + 1
    return (l + r) * cnt // 2

def solve_case(n):
    l, r = 1, n

    while l < r:
        mid = (l + r) // 2
        res = query(l, mid)
        s = segment_sum(res)

        if s == expected_sum(l, mid):
            l = mid + 1
        else:
            r = mid

    print("!", l)
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```通过发出查询并立即刷新输出来处理交互。 每个查询都会返回排序后的段，并且我们仅依赖于值的总和，忽略顺序，因为排序无论如何都会删除位置结构。 二分搜索边界更新完全取决于前缀是否表现得像未触及的身份段。 

一个微妙的点是我们永远不需要查询单个元素。 每个查询都会将搜索空间减少大约一半，从而使查询总数远低于限制。

 ## 边缘情况

 像 n = 3 这样的最小情况突出表明固定点可能位于端点。 例如，[1,3,2] 使 1 保持固定。 二分搜索立即区分前缀 [1,1] 和 [1,2]，因为只有后者显示出与预期总和行为的偏差。 

完全平衡的交换结构（例如 n = 7），其中交换许多元素，但除了固定点附近之外没有任何元素跨越前缀边界，确保不正确的段始终在内部取消，从而确认总和相等是排除目标段的稳定指标。 

这些案例证实，无论交换配置如何，决策谓词都保持单调，这使得二分搜索能够保持一致的行为。
