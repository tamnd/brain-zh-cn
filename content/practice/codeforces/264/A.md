 ## 解决方案
 ## 问题理解

 我们得到一个由字符组成的字符串`l`和`r`。 人物描述了当石头一颗一颗落下时，松鼠如何移动。 

石头`i`落在石头后面`1...i-1`已经被放置了。 如果对应的字符是`l`，松鼠移动到当前区间的左半部分。 如果是的话`r`，她移动到右半边。 所有动作完成后，棋子最终排列成一条线。 我们必须从最左到最右输出石头编号。 

几何描述听起来很复杂，但实际任务是确定宝石索引最终从左到右的顺序。 

字符串的长度可以达到一百万。 任何重复插入数组中间或显式模拟位置的算法都会太慢。 和$n = 10^6$， 甚至$O(n^2)$行为大致需要$10^{12}$的操作，这是完全不可行的。 我们需要一个线性时间的解决方案。 

一个微妙的点是，顺序不是由石头的物理坐标决定的。 几何形状仅暗示相对排序规则。 

考虑输入：```
r
```只有一颗石头，所以输出是：```
1
```假设每个解决方案`r`应该放在其他可能错误处理这个最小情况之后。 

另一个有趣的案例是：```
lll
```正确的输出是：```
3
2
1
```每颗新宝石最终都位于所有先前加工过的宝石的左侧。 一个粗心的实现，在读取字符串时简单地附加索引会产生`1 2 3`，这是不正确的。 

相似地：```
rrr
```产生```
1
2
3
```现在，每块石头都出现在所有早期石头的右侧。 

混合情况```
llrlr
```给出```
3
5
4
2
1
```这表明无论是颠倒答案还是保持原始顺序都是不够的。 

## 方法

 直接模拟是可能的。 我们可以维持当前的从左到右的棋子顺序。 当石头`i`到达后，我们确定它相对于现有石头的所属位置，并相应地插入它。 

问题在于，插入动态数组的前面或中间会花费线性时间。 在最坏的情况下我们执行$n$插入，每次成本计算$O(n)$，导致$O(n^2)$复杂。 对于一百万颗石头来说，这实在是太慢了。 

关键的观察结果是几何形状产生了非常简单的排序规则。 

Suppose we process stones in order. 当石头`i`对应于`l`，松鼠向左逃走。 这意味着该区间内的每个未来位置都位于石头的左侧`i`。 在最后的安排中，石头`i`应该尽早出现在剩余的未加工宝石中。 

当石头`i`对应于`r`，松鼠向右逃走。 石头`i`必须出现在所有随后放置在正确区间内的棋子之后。 

这导致了建设性的解释。 

对于每一个`l`，对应的石子编号属于最终序列的前面。 

对于每一个`r`，对应的石子编号属于最终序列的后面。 

如果我们从左到右读取字符串，我们可以将石头数字与`l`进入前部和石数`r`进入后部。 

如果我们直接考虑输出顺序，就会出现一个更简单的公式。 

所有宝石均已标记`r`应按原始顺序打印。 

所有宝石均已标记`l`应在它们之后以相反的顺序打印。 

双端队列自然地代表了这个过程。 石材用`i`：

如果`s[i] == 'l'`， 推`i+1`到前面。 

如果`s[i] == 'r'`， 推`i+1`到后面。 

最后，从前到后读取双端队列给出了所需的顺序。 

由于双端队列上的每个操作都是恒定时间，因此整个算法是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取输入字符串。 
2. 创建一个空双端队列。 
3. 从左到右处理字符。 设当前石头数为`i + 1`。 
4. 如果当前字符是`l`，将石号插入双端队列的前面。 

这反映了这样一个事实：该棋子必须出现在所有将被放置在向左移动所到达的区间内的棋子之前。 
5. 如果当前字符是`r`，将石号插入双端队列的后面。 

这反映了这样一个事实：该棋子必须出现在稍后将放置在正确间隔中的棋子之后。 
6、处理完所有字符后，从前往后遍历双端队列，打印每一个存储的石数。 

### 为什么它有效

 处理第一个之后保持不变量`i`字符，双端队列恰好包含石头的最终相对顺序`1...i`。 

当一个角色是`l`，从所选间隔生成的每个未来棋子必须位于最终排列中当前棋子的右侧。 将当前石头放在前面可以保留正确的相对顺序。 

当一个角色是`r`，从所选间隔生成的每个未来棋子都必须位于当前棋子的左侧。 将当前的石头放在后面可以保留正确的相对顺序。 

由于每次插入都会将新石头放置在与该步骤中选择的间隔一致的唯一位置，因此在整个处理过程中不变式保持不变。 在最后一个石头之后，双端队列包含完整的从左到右的排序。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    s = input().strip()

    dq = deque()

    for i, ch in enumerate(s, start=1):
        if ch == 'l':
            dq.appendleft(i)
        else:
            dq.append(i)

    sys.stdout.write('\n'.join(map(str, dq)))

if __name__ == "__main__":
    solve()
```该解决方案使用双端队列，因为它支持在恒定时间内在两端插入。 

循环按照自然顺序处理宝石，从`1`到`n`。 石头数直接从循环索引中获得。 

对于一个`l`，我们使用`appendleft`，将石头放置在当前排序的开头。 对于一个`r`，我们使用`append`，将其放在最后。 

不需要坐标计算。 整个几何过程归结为维持正确的相对顺序。 

最终输出是通过遍历双端队列一次并将数字与换行符连接起来产生的。 这避免了许多单独的打印调用，这在输入长度达到一百万时很重要。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|

 输入长度可以大到一百万。 线性时间意味着只有几百万个原始操作，很容易满足时间限制。 存储一百万个整数也完全在内存限制之内。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    s = sys.stdin.readline().strip()
    dq = deque()

    for i, ch in enumerate(s, start=1):
        if ch == 'l':
            dq.appendleft(i)
        else:
            dq.append(i)

    return "\n".join(map(str, dq))

# sample from statement
assert run("llrlr\n") == "4\n2\n1\n3\n5", "sample"

# minimum size
assert run("r\n") == "1", "single stone"

# all left
assert run("lll\n") == "3\n2\n1", "all left moves"

# all right
assert run("rrrr\n") == "1\n2\n3\n4", "all right moves"

# alternating pattern
assert run("lrlr\n") == "4\n2\n1\n3", "mixed ordering"

# boundary style case
assert run("lr\n") == "1\n2", "small mixed case"

 ## 边缘情况

 考虑输入：```
lll
```处理过程如下：`[1] → [2,1] → [3,2,1]`输出变为：```
3
2
1
```每块石头都是从前面插入的，因此最终的顺序与到达顺序正好相反。 

考虑输入：```
rrr
```处理过程如下：`[1] → [1,2] → [1,2,3]`输出是：```
1
2
3
```每颗宝石都插入后面，因此最终顺序与到货顺序一致。 

考虑尽可能最小的输入：```
l
```双端队列变成`[1]`，输出为：```
1
```该算法不需要对这种情况进行特殊处理，因为`appendleft`和`append`当双端队列为空时可以正常工作。 

考虑一个混合模式：```
lrl
```处理给出：`[1] → [1,2] → [3,1,2]`输出是：```
3
1
2
```这证实了后来的`l`正确地跳到所有先前处理过的宝石之前，同时保留其他宝石已建立的相对顺序。
