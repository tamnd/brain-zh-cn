 ## 解决方案
 ## 问题理解

 我们得到了一系列按固定顺序排列的球。 每个球都带有两条信息：颜色和数值。 我们可以从这个序列中选择一个子序列，同时保留原始顺序，或者什么都不选择。 

一旦选择了子序列，就可以通过从左到右扫描来计算其分数。 每个选定的球都会贡献其价值乘以一个系数，该系数取决于其颜色是继续运行还是开始新的运行。 如果一个球与之前选择的球具有相同的颜色，则将其视为延续并贡献其值乘以`a`。 如果颜色不同，它将开始一个新段并贡献其值乘以`b`。 

对于每个查询，该对`(a, b)`改变，但值和颜色的数组保持不变。 任务是独立计算每个查询的所有子序列的最大可能得分。 

约束条件`n ≤ 10^5`和`q ≤ 500`立即排除任何在二次时间内根据查询从头开始重新计算完整动态程序的解决方案。 子序列上的朴素 DP 将涉及所有先前位置之间的转换，给出`O(n^2)`每个查询，在这种规模下速度太慢了。 

一个更微妙的问题来自负值。 由于值可能为负且系数也可能为负，因此拿更多的球并不总是有益的。 像“总是选择积极贡献”或“总是扩展相同颜色运行”这样天真的贪婪策略会失败，因为该决定取决于未来切换颜色或重用高价值片段的机会。 

一个常见的失败案例是，保持颜色的存活在本地成本很高，但以后可以获得更大的增益。 例如，如果某种颜色的一个小负值球允许稍后将该颜色的大块乘以，则可能值得包括在内`a`而不是重新开始`b`。 

## 方法

 一个直接的表述是定义`dp[i]`使用前缀作为最佳分数`i`，结束于`i`或者根本就没有结束。 过渡考虑跳过球或将其附加到子序列，可能会继续颜色段或开始新的颜色段。 然而，每个状态都可能取决于之前所有匹配或不同颜色的状态。 这自然会导致`O(n^2)`过渡。 

关键的结构观察是，扩展子序列时唯一重要的是最后选择的颜色，而不是完整的历史记录。 如果我们知道对于每种颜色，以该颜色结尾的最佳子序列，我们就可以有效地进行转换。 

让`best[c]`表示最后选择的球有颜色的子序列的最大分数`c`。 加工新球时`(c_i, v_i)`，我们要么用它开始一个新的子序列，要么扩展相同颜色的现有子序列。 从色彩延伸`c_i`受益于`best[c_i] + v_i * a`，而从任何其他颜色切换都会有助于`max(best all colors) + v_i * b`。 

这将每次更新减少为恒定数量的聚合值，前提是我们保持所有的全局最大值`best[c]`。 困难在于`a`和`b`每个查询都会更改，因此我们无法预先计算单个 DP。 相反，我们重新计算每个查询的 DP`O(n)`使用相同的结构。 

我们维护一个数组`dp[c]`对于当前查询和全局最大值`mx`。 我们还跟踪运行的答案，因为子序列可以在任何位置重新开始。 

对于每个查询，我们重置数组并扫描一次序列，使用上面导出的递归更新状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子序列的暴力 DP | 每个查询 O(n^2) | O(n) | 太慢了 |
 | 每个查询优化的颜色 DP | O(nq) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个查询，因为系数`(a, b)`每次都不同。 

1.初始化一个数组`dp[c]`对于所有颜色都是非常负的值，这意味着当前没有子序列以该颜色结尾。 我们还维护`ans = 0`，因为允许空子序列。 这确保我们始终可以选择放弃一切。 
2.维护一个全局变量`mx`，所有值中的最大值`dp[c]`在当前步骤中。 这代表了迄今为止最好的子序列结局。 
3. 从左到右遍历这些球。 
4. 对于当前球`(color c, value v)`，计算两个候选转移。 第一个是在这个球上重新开始，赋予价值`v * b`。 第二个是扩展之前以不同颜色结尾的子序列，给出`mx * b + v * b`，但这已经通过捕获`mx`。 
5. 我们还考虑扩展已经以相同颜色结尾的子序列`c`, 给予`dp[c] + v * a`。 这就是连续性的情况。 
6. 以颜色结尾的最佳子序列`c`处理后，该球成为在该球处开始新的或扩展先前的相同颜色子序列的最大值。 我们更新`dp[c]`因此。 
7.更新后`dp[c]`，我们刷新`mx`如果这个值改善了它。 
8.我们更新`ans`与其中最好的`ans`,`dp[c]`，以及在该球处开始新子序列的值。 这捕获从任意位置开始的子序列。 

### 为什么它有效

 在每一步中，对于每种颜色，我们将所有可能的子序列历史压缩为以该颜色结尾的单个最佳值。 任何以位置结束的最优子序列`i`必须扩展以相同颜色结尾的最佳子序列，或者从之前以不同颜色结尾的最佳子序列开始。 国家`dp[c]`is sufficient because the future only depends on the last color, and all earlier structure is irrelevant once its contribution is summarized into the best achievable score.

 全局最大值`mx`确保跨颜色过渡始终在恒定时间内可用，从而无需每一步扫描所有颜色。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    v = list(map(int, input().split()))
    c = list(map(int, input().split()))

    colors = set(c)

    for _ in range(q):
        a, b = map(int, input().split())

        dp = {}
        mx = 0
        ans = 0

        for i in range(n):
            col = c[i]
            val = v[i]

            prev_same = dp.get(col, 0)

            # extend same color
            extend_same = prev_same + val * a

            # start new segment here
            start_new = mx + val * b

            best = max(0, extend_same, start_new)

            if best > dp.get(col, 0):
                dp[col] = best

            mx = max(mx, dp[col])
            ans = max(ans, dp[col])

        print(ans)

if __name__ == "__main__":
    solve()
```该实现保留了一个字典`dp`对于颜色状态，因为只有出现的颜色在实践中才重要。`mx`是迄今为止以任何颜色结尾的最佳子序列值。 对于每个球，我们计算是否扩展相同颜色的子序列更好，或者从最佳的先前端点开始新的段更好。 

一个微妙的点是`ans`是分开维护的`mx`。 这可以避免丢失在正确传播之前以中间状态结束的子序列。

 ## 边缘情况

 一个关键的边缘情况是所有值都为负时。 在这种情况下，最佳策略是不选择任何内容，产量为零。 该算法处理这个问题是因为每个转换都包含一个`max(0, ...)`-通过初始化隐式选择样式`ans = 0`并与之前的最佳值进行比较。 

另一个微妙的情况是交替出现较晚出现较大正值的颜色。 简单的方法可能会丢弃早期的低值，但 DP 保留每种颜色的最佳前缀状态，确保切换回之前看到的颜色仍然受益于其累积的最佳子序列。 

最后，由不同颜色的长段分隔的重复颜色需要正确使用`mx`。 如果没有全局最大值，不同颜色之间的转换将需要扫描所有状态，这会破坏效率并在实践中经常导致不正确的部分更新。
