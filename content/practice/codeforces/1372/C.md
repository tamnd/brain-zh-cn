 ## 解决方案

 ## 问题理解

 我们给出了从 1 到 n 的数字排列，我们希望使用受限操作将其转换为排序的恒等排列。 该操作允许我们选择任何连续的段并任意排列它，但有一个重要的限制：操作后不允许任何元素保留在该段内的原始位置。 

因此，每次移动都是子数组的一次受约束的“重新洗牌”，其中所选段中的每个元素都必须移动到同一段内的其他位置。 

任务是计算将排列转变为排序顺序所需的此类操作的最少数量。 

所有测试用例的输入大小达到 2 · 10^5，因此每个测试用例的任何解决方案都必须是线性或接近线性的。 O(n^2) 策略立刻就太慢了，因为即使是 n = 2 · 10^5 的单个测试也已经需要大约 10^10 次操作。 

这个问题的一个微妙点是，该操作比交换更强，但比整个数组的任意重新排列弱。 它允许对段进行完全排列，但禁止该段内的固定点。 只要我们能够避免将元素放回其开始的位置，此约束对于长度至少为 2 的段就变得无关紧要，除非段已经正确对齐，否则这总是可能的。 

打破朴素推理的边缘情况通常涉及误解“段的有效排列”的含义。 例如，如果数组已经排序，则不需要进行任何操作。 如果数组中的元素已经位于正确的位置，则一次修复一个元素的天真贪婪可能会低估在单个段中修复多个错位元素的好处。 

## 方法

 蛮力视角会尝试模拟这个过程。 在每一步中，我们都可以搜索一个段，应用该段的所有有效排列，然后递归地继续，直到数组排序。 这会很快组合爆炸，因为长度为 k 的每个段都有许多有效的排列，并且检查所有可能的操作序列会导致指数行为。 即使尝试对排列进行 BFS 也是不可能的，因为状态空间是 n!。 

关键的结构观察是，我们实际上不受所选段的内部排列的限制，仅受该段中的元素是否已正确放置的限制。 该操作可以“修复”任何片段，只要它尚未与该区间内的恒等排列完美对齐即可。 这将问题转化为计算排列如何分解为最大的已正确前缀后缀结构。 

我们从左到右扫描排列，同时跟踪“正确前缀”可以延伸多远。 在安全执行包含所有当前丢失元素的操作之前，我们保持必须到达的最远位置。 每当我们遇到一个前缀段，其中直到某个边界的所有位置都已经正确时，该段就不需要任何操作。 每当我们遇到这种结构的破坏时，我们就被迫执行一项操作来覆盖最大的无序区域。 

这导致了一种贪婪的分割思想：将数组分割成最大的块，使得每个块包含至少一个错放的元素，强制执行校正步骤，并且每个操作最佳地修复一个这样的块。

 ## 算法演练

1. 从左到右扫描阵列，同时跟踪当前的无序区域。 我们维护一个变量，该变量表示当前正在考虑的段中必须包含的最大索引。 
2、对于每个位置i，如果i处的值已经是i+1，则已经是正确的，不会扩大当前区域。 
3. 如果 i 处的值不在正确的位置，我们将扩展当前段边界以包含该值应该去的位置，因为修复它需要触及该位置。 
4. 我们继续扩展这个边界，直到属于这个“依赖闭包”的所有元素都被包括在内。 
5. 一旦扫描索引到达当前边界，我们就确定了可以在单个操作中修复的最小段，因此我们计算一次操作并从下一个索引开始一个新段。 
6. 重复直到数组末尾。 

关键思想是，每个操作对应于解析由“错位依赖”形成的一个连接组件，其中索引 i 取决于位置 a[i]。 

为什么有效：每个不合适的元素都会强制任何有效的修复都包含其当前位置和目标位置。 这会创建依赖链，并且当将其视为位置到目标链接的图形时，最小操作数正是排列中不相交依赖组件的数量。 每个特殊的交换可以完全解决一个这样的组件，但不能合并两个断开的组件，除非不必要地将段扩展到超出需要的范围。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ops = 0
        i = 0

        while i < n:
            if a[i] == i + 1:
                i += 1
                continue

            ops += 1

            max_reach = i
            j = i
            while j <= max_reach:
                if a[j] - 1 > max_reach:
                    max_reach = a[j] - 1
                j += 1

            i = max_reach + 1

        print(ops)

if __name__ == "__main__":
    solve()
```该实现依赖于贪婪扫描。 外循环会跳过已经正确的位置，因为它们不需要任何操作。 当我们发现一个放错位置的元素时，我们开始扩展一个段。 内部循环使用其中元素的目标位置来增长段边界。 这有效地构建了必须包含在一项操作中的索引的闭合。 

微妙之处在于使用`a[j] - 1`作为位置索引，因为排列是从 1 开始的，而 Python 数组是从 0 开始的。 当没有新的依赖项进一步扩展该段时，该段结束。

 ## 边缘情况

 干净的边界情况是排列已经排序的情况。 该算法立即跳过每个索引，因为`a[i] == i + 1`，因此不会创建任何段并且输出保持为零。 

另一个重要的情况是单个大循环，例如`[2,3,4,5,1]`。 这里每个索引都依赖于另一个索引，因此依赖闭包一次性扩展到整个数组。 该算法从索引 0 开始，展开`max_reach`直到它到达末尾，并且只计算一次操作，这与整个数组可以固定在单个有效交换中的事实相匹配。
