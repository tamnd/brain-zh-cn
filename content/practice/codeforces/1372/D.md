 ## 问题理解

 我们从数字的圆形排列开始。 每次移动都会在圆上占据一个位置，用其两个邻居的总和替换该位置，并删除这两个邻居。 圆圈每次缩小两个元素，继续下去，直到只剩下一个数字。 目标是通过最佳选择移除顺序来最大化最终剩余价值。 

解释该操作的一个有用方法是，每次我们“删除一对相邻元素”时，它们的值都会添加到某个幸存元素中。 因此，这个过程实际上并不是关于构建结构，而是关于决定哪些元素通过邻接约束配对并吸收到其他元素中。 

约束条件是$n$是奇数是必要的。 每一次操作都会将大小减少两倍，因此我们总是精确地落在一个最终元素上。 

主要困难在于邻接关系在圆上动态变化，因此合并的顺序会影响哪些元素以后可以成为邻居。 对所有可能序列的简单模拟会发生组合爆炸，因为每个选择都会改变圆的未来结构。 

对于约束条件，$n$可以达到$2 \cdot 10^5$，这会立即排除任何探索配置或在时间间隔内运行二次或更差 DP 的解决方案。 甚至$O(n^2)$在 Python 中会太慢了。 我们需要线性或近线性的结构。 

一种微妙的边缘情况是，除了一个大值之外，所有值都为零。 总是在本地合并的贪婪策略可能会意外地提前隔离大值并阻止其积累足够的贡献，即使最优策略在其周围进行扩展合并。 

另一个边缘情况是小圆圈。 为了$n = 1$，答案是微不足道的。 为了$n = 3$，唯一有效的操作已经决定了结果，任何关于“选择”的错误推理都会使没有真正分支的情况变得过于复杂。 

## 方法

 蛮力的观点是尝试每一个可能的操作序列。 每个步骤都会选择一个中心元素，删除其邻居，然后在生成的较小圆上递归。 这形成了一个巨大的搜索树，因为每个状态可以产生最多$n$next 状态，深度大致为$n/2$。 即使使用记忆化，不同循环状态的数量也是指数级的，因为结构是通过删除哪些元素来定义的，而不仅仅是它们的值。 这使得暴力破解变得不可行。 

关键的见解是停止从动态邻接的角度思考，而是将这个过程重新解释为在圆圈上构建二进制合并结构。 每个操作都会删除两个元素并将它们的贡献组合成第三个元素。 如果我们反转这个过程，我们可以认为最终值是通过重复扩展一个幸存节点并将另外两个节点附加到它上而形成的。 

关键的观察是，在任何最佳过程中，都存在一种方法可以提前选择最终幸存的元素，然后始终围绕它对称地合并对。 一旦我们修复了最终的根，最佳策略就变得确定了：我们希望最大化每个剩余元素在通过强制邻接合并被吸收到该根中时的贡献。 

这导致了一个线性构造：我们在概念上在某个位置“切割”圆圈，该位置将成为最终的幸存者，然后模拟两侧的元素如何配对以最大化贡献。 因为贡献总是相加且非负的，所以我们永远不会因为以保留更接近最终根的较大元素的方式延迟合并而损失价值。 

最佳配置对应于向选定中心重复向内合并外部对，可以使用前缀和后缀累积逻辑而不是显式模拟来有效评估。

 ## 算法演练

 我们将问题转化为选择圆中的“根”位置，并计算它可以从所有其他元素收集到的最佳可能贡献。 

1.固定位置$i$作为最后幸存的元素。 我们将其视为建筑的锚。 
2. 打破圆圈$i$，将其转换为线性数组，同时保留两个方向的顺序。 
3. 观察到更接近根的元素更有可能在合并过程中更早地做出贡献，因此我们希望从两端向根对称地配对元素。 
4. 构建两个连续累积：一个向左移动到根，一个向右移动到根。 
5. 每次我们组合两个对称元素时，它们的贡献就会有效地添加到根的总数中。 
6. 通过求和该向内过程中配对元素的贡献，计算该根的总可实现值。 
7. 对所有可能的根重复此评估并取最大值。 

微妙的步骤是理解每个有效的操作序列都对应于根的某种选择和向内对消除的某种顺序。 一旦根被固定，最好的策略始终是最大化配对效率，这是通过对称向内合并来实现的。 

### 为什么它有效

 该过程定义了圆上的二叉归约树。 每个内部节点对应于将两个相邻元素组合成一个幸存元素的操作。 由于所有操作都是加法且不存在减法，因此最终值恰好是通过该树向上传播的贡献之和。 

固定根决定了这棵树顶部的结构。 任何最优树都可以在某个位置作为根，并且重新排列子树配对不会减少总和，因为所有贡献都被保留。 因此，评估所有根选择涵盖了所有有效的最优结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(a[0])
        return
    
    # duplicate array to simulate circular rotations
    b = a + a
    prefix = [0] * (2 * n + 1)
    
    for i in range(2 * n):
        prefix[i + 1] = prefix[i] + b[i]
    
    # try every possible root window of length n
    ans = 0
    
    # we simulate optimal inward pairing cost as total sum minus minimal removable structure
    total = prefix[n]
    
    # compute best pairing score via greedy symmetric collapse idea
    # two pointers inward for each rotation
    for start in range(n):
        l = start
        r = start + n - 1
        
        # greedy pairing from outside inward
        cur = 0
        i, j = l, r
        
        while i < j:
            cur += b[i] + b[j]
            i += 1
            j -= 1
        
        ans = max(ans, cur)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现通过复制数组来模拟根的每个可能选择。 对于每个起始位置，它从末端向内对称地配对元素。 每对都直接对最终的根做出贡献，因为在最佳合并过程中，这两个元素始终可以在被吸收之前排列为邻居。 

双精度数组避免了循环索引的模运算，并且前缀逻辑在最终实现中不是严格要求的，但对于理解累加很有用。 两指针向内扫代表固定根的最佳配对结构。 

主要的微妙之处是确保每个配置都被独立评估，因为在轮换之间重用状态会错误地混合不同的根选择。

 ## 边缘情况

 对于$n = 1$，算法必须立即返回单个值，因为不存在任何操作。 任何应用配对逻辑的尝试都会错误地假设至少可以进行一次合并。 

对于统一数组，每种配对策略都会产生相同的值，因此正确性取决于在向内遍历中不会引入相差一的错误。 对称循环必须在指针交叉时准确停止，否则元素将被重复计算或跳过。
