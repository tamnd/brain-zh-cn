 ## 解决方案
 ## 问题理解

 我们被要求构造一个长度的整数数组`n`其中每个元素都是正数，不超过 1000，并且满足总和的全局限制：如果我们选择任意三个位置（它们可能重合），则两个选定元素的总和永远不会等于数组中的任何元素。 

更具体地说，数组中的任何值都不允许表示为数组中两个值的总和，包括将单个元素加倍的可能性。 所以如果`a[i] + a[j]`出现在数组中的任何位置，甚至出现在其他索引处`k`，数组无效。 

输入给出了多个测试用例，每个测试用例仅提供`n`，对于每个我们必须输出该长度的任何有效数组。 

限制很小。 全部的总和`n`跨测试用例最多 1000 个，每个测试用例`n`最多为 1000。这立即告诉我们，我们没有处理性能压力。 任何解大约可达`O(n^2)`或者甚至每个测试用例稍差一些都会轻松通过，但条件的结构表明我们应该完全避免不必要的成对检查。 

朴素构造的非明显失败案例是递增序列。 如果我们尝试`[1, 2, 3, 4, 5]`，我们立即得到`1 + 2 = 3`，这违反了条件。 更微妙的失败尝试是任何密集的小数字集，因为小值自然地组合到也存在的其他小值中。 

第二个微妙的陷阱是试图随机化没有结构的值。 即使值在界限内，随机选择也会经常造成意外的总和冲突，例如`a[i] + a[j] = a[k]`，特别是当数字很小或重复时。 

## 方法

 暴力方法会尝试逐步构建数组。 对于每个新元素，我们可以测试来自的所有候选值`1`到`1000`并检查添加它是否违反了任何先前选择的对的条件。 这需要检查当前前缀中的所有对，因此对于每个位置，我们最多可以执行`O(n^2)`检查，导致`O(n^3)`最坏情况下每个测试用例的总工作量。 这是不必要的，因为条件是全局的并且不需要动态地维护精确的组合结构。 

关键的观察是我们不需要使用不同的值或最大化多样性。 我们只需要避免和冲突。 保证这一点的一个简单方法是使所有元素等于常量值。 如果每个元素都是相同的数字`x`，那么两个元素的每个和都是`2x`，只要满足以下条件，数组中就不存在`x != 2x`。 自从`x > 0`，这始终是正确的。 

我们还需要尊重 1000 的上限，但是选择`x = 1`已经满足所有约束条件。 那么数组完全由 1 组成，唯一可能的和是`2`，它不在数组中。 

这使得这个问题本质上是一个持续的构建任务。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力增量检查 | O(n^3) | O(n^3) | O(n) | 太慢了 |
 | 常量数组构造 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们为每个测试用例独立构建数组。 

1. 阅读`n`对于测试用例。 我们只需要确定输出多少个元素，而不需要确定超出满足条件的结构。 
2. 选择固定值`1`对于所有职位。 这可确保每个元素均为正数且在所需的 1000 范围内。 
3. 填充数组`n`的副本`1`。 不需要额外的检查，因为结构保证了有效性。 
4. 输出数组。 

### 为什么它有效

 由数组形成的唯一可能的和的形式为`1 + 1 = 2`。 由于每个数组元素都是`1`， 和`2`从未出现在数组中，不存在这样的索引三元组`a[x] + a[y] = a[z]`。 由于所有元素都相同，因此每个可能的对和都相同，并且保证位于数组中使用的值集之外。 无论什么情况，这个不变量都成立`n`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(" ".join(["1"] * n))

if __name__ == "__main__":
    solve()
```实施直接反映了构造。 唯一的微妙之处是处理多个测试用例并确保使用快速 I/O`sys.stdin.readline`。 

表达式`["1"] * n`将所需的数组高效地构建为字符串，避免循环内整数到字符串的转换。 由于输出大小是限制因素，因此这在实践中是最佳的。

 ## 边缘情况

 唯一有意义的边缘情况是当`n = 1`。 施工仍输出`[1]`。 没有任何对可以形成总和，因此条件是空洞地满足的。 

为了`n = 1000`，我们输出 1000 个。 即使有很多对，每一笔钱仍然存在`2`，它不存在于数组中，因此不会发生违规。 

重复测试用例的情况不会改变行为，因为每个测试用例都是独立的并且使用相同的构造逻辑。
