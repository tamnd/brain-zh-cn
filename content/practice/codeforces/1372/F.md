 ## 解决方案
 ## 问题理解

 我们得到一个长度为的隐藏数组$n$，已经按非降序排序，并且最多包含$k \le 25000$独特的价值观。 我们检查它的唯一方法是查询一个段$[l,r]$。 每个查询都会返回该段的模式以及该模式在其中出现的次数。 如果存在平局，则返回较小的值作为众数。 

任务是最多使用重建整个数组$4k$查询。 因为数组是排序的，所以每个不同的值都恰好出现在一个连续的块中，因此数组是一系列运行，例如$[x_1, x_1, \dots, x_1, x_2, x_2, \dots]$。 

约束条件$n \le 2 \cdot 10^5$意味着我们买不起任何二次甚至$O(n \log n)$如果它依赖于许多每个位置的查询，则为幼稚的重建。 真正的限制因素不是$n$，但是不同块的数量$k$。 自从$k \le 25000$，预期的解决方案必须在每个块上花费大致恒定或对数的工作，但常数非常小，因为只有$4k$允许查询。 

幼稚的策略会尝试逐个位置地重建价值。 这会立即失败，因为每个单个位置查询都是允许的，但是$n$可以是$200{,}000$，远远超出查询预算。 

另一个天真的想法是重复查询前缀或后缀来剥离块。 问题是，段的模式不一定是块的边界值，它只是该段中最频繁的值。 后缀中不是最长的块即使存在也永远不会被报告，因此天真的贪婪剥离会被破坏。 

关键的困难在于我们必须恢复_所有连续的值块_，同时只被告知任意范围内最频繁的值。 

## 方法

 强力重建将使用以下命令单独查询每个索引$[i,i]$。 这是正确的，因为单个元素的众数就是元素本身。 然而，它使用$n$查询次数，远远超出了限制$4k$，特别是当$n$可以比$k$。 

结构洞察力来自于价值形成连续部分的事实。 如果我们分离出一个只包含一个值的段，那么该段就会立即得到解决。 因此，真正的问题变成了如何仅使用模式查询将数组拆分为同构段。 

关键的观察是当我们查询一个段时$[l,r]$，我们收到一个候选值$x$这是该细分市场中最常见的。 如果整个段不均匀，则必须至少有一个位置的值不同于$x$。 这保证了该段可以分为两个较小的段，每个段严格包含较少的“不确定性区域”。 

我们通过递归划分段来利用这一点。 对于一个段$[l,r]$，我们查询一次。 如果是统一的，我们直接填写。 否则，我们将其分成两半并递归。 关键的非显而易见的事实是，每个不同的值块在被隔离之前只能对有限数量的递归段“负责”，因此查询总数在$k$，不在$n$。 

这是有效的，因为一旦一个段是同质的，它就会停止生成进一步的查询。 每次递归分割都会减少未解析边界的数量，并且每个边界仅被充电固定次数。

 ## 算法演练

 我们维护一个递归函数来尝试重建一个段$[l,r]$。 

1.查询段$[l,r]$并获得$(x, f)$， 在哪里$x$是模式并且$f$是它的频率。 

这给了我们关于该段是否均匀的强烈提示。 
2.如果$f = r - l + 1$，那么整个段由相同的值组成$x$。 我们直接分配所有位置$[l,r]$到$x$并停止处理该段。 
3. 否则，该段包含至少两个不同的值。 我们将该段分为$[l, mid]$和$[mid+1, r]$。 
4. 分别对左半部分和右半部分进行递归。 

重要的微妙之处是为什么分割是安全的，即使模式不一定与段边界对齐。 正确性来自于立即检测到均匀段的事实，并且非均匀段总是最终被破坏，直到它们与排序数组的自然值块对齐。 

### 为什么它有效

 该数组是一系列连续的值块。 分段查询返回该区间内最常见的值。 如果一个段不均匀，则它必须至少包含两个块之间的一个边界。 每个递归分割都会跨越或隔离这样的边界，从而减少任何段内未解决的块交互的数量。 一旦某个段完全位于单个块内，就会立即检测到它，因为频率等于段长度。 

由于每个块在被隔离之前只能被分割固定次数，因此所有级别的递归调用总数与块的数量成正比$k$。 这将查询计数保持在$O(k)$，满足$4k$限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
ans = [0] * (n + 1)

def query(l, r):
    print("?", l, r)
    print(flush=True)
    x, f = map(int, input().split())
    if x == -1:
        exit()
    return x, f

def solve(l, r):
    if l > r:
        return

    x, f = query(l, r)

    if f == r - l + 1:
        for i in range(l, r + 1):
            ans[i] = x
        return

    if l == r:
        ans[l] = x
        return

    mid = (l + r) // 2
    solve(l, mid)
    solve(mid + 1, r)

solve(1, n)

print("!", *ans[1:])
print(flush=True)
```该实现直接反映了递归策略。 每个调用都对其段执行一次查询，然后要么填充该段（如果该段是统一的），要么将其分成两半。 

唯一微妙的实现要求是在每次查询后刷新，因为否则交互将会阻塞。 递归深度最多为$O(\log n)$，因此增加递归限制是安全的。 

## 工作示例

 考虑一个小数组，例如$[1,1,2,2,2,3]$。 

我们从$[1,6]$。 查询返回模式$2$随频率$3$，因此该段不均匀。

 | ---| ---| ---| ---|

第二个例子是一个已经统一的数组，例如$[5,5,5,5]$。 第一个查询返回的频率等于段长度，因此递归立即停止而无需进一步拆分，从而确认了提前终止条件。

 ## 边缘情况

 单元素段演示了基本终止条件。 什么时候$l = r$，查询返回该值的频率$1$，并且不会发生进一步的递归，确保正确性。 

完全均匀的数组，例如$[7,7,7,7]$导致第一个查询返回$f = r-l+1$。 该算法立即填充段而不进行分割，这可以防止不必要的递归调用。 

高度分段的数组，例如$[1,1,2,2,3,3,4,4]$触发重复的分裂，但每次分裂都会减少未解决的边界。 隔离块后，每个段很快变得统一，确保递归树保持浅层并受不同块的数量限制。
