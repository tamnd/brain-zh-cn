[CF 1903D1 - 最大值和查询（简单版）](https://codeforces.com/problemset/problem/1903/D1)

 **评分：** 1700
 **标签：** 二分查找、位掩码、暴力破解、贪婪
 **求解时间：** 2m 15s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一个操作预算，其中每个操作允许将单个元素增加 1。对于提供不同预算的每个查询，我们希望在使用最多那么多操作后通过对所有数组元素进行按位 AND 来实现可实现的最大值。 数组本身在查询之间不会改变，因此每个查询都是独立的。 

输入大小很大：数组最多可以有 100,000 个元素，并且最多可以有 100,000 个查询。 总产品为`n * q`上限为 100,000，这意味着我们无法提供一种算法来检查嵌套循环中每个查询的所有元素。 每个元素可以大到 10^6，因此按位表示最多有 20 位。 这表明位级操作是可行的并且可能是必要的。 操作次数`k`可能很大，最多 10^18，因此我们无法单独模拟每个增量。 

幼稚的方法可能会尝试尝试所有可能的方式来执行操作，甚至尝试所有可能的结果数组。 例如，如果数组是`[1, 2, 3]`和`k=3`，人们可以尝试将元素中总计 3 个单位相加的所有组合。 这会发生组合爆炸，即使对于小的情况也是不可行的`n`。 

一个重要的微妙之处是，某些元素可能已经设置了高位，而其他元素则需要显着增加才能匹配。 例如，考虑`[1, 2, 7]`和`k=1`。 最大与为`0`，因为任何单个元素加 1 都不能使所有元素共享一个共同的高位。 粗心的解决方案只是对增量求和或尝试从左到右进行贪婪加法，可能会报告错误的 AND。 我们必须仔细评估在给定预算下可以在所有元素中“打开”哪些位。 

## 方法

 暴力解决方案将尝试分布的每一种组合`k`最大化 AND 的操作。 这在原则上是正确的，因为如果我们能够尝试所有的可能性，我们最终会找到最好的。 但对于`n=10^5`和`k`最多10^18，这是不可能的。 即使在没有巧妙逻辑的情况下迭代每个查询的所有数组元素，在最坏的情况下也会产生 O(n*q) = 10^10 操作。 

关键的见解是用位而不是绝对数字来思考。 数字的按位与由**所有**元素中设置的最高位的位置决定。 如果我们想让 AND 尽可能大，我们可以从最高位向下检查位，看看是否可以使用可用的操作增加元素来设置该位。 对于每一位，我们计算提高所有尚未将该位设置为至少该值的数字的总成本。 如果成本在当前查询的范围内`k`，我们将该位保留在最后的 AND 中。 

这一观察将问题从跟踪精确数字简化为贪婪的、从高到低的逐位检查。 总位数很少（对于 10^6 以内的数字为 20 位），因此对于每个查询，我们只需要评估所有元素中最多 20 位。 这会产生每个查询的可行 O(n * 20) 时间，考虑到 n*q ≤ 10^5 约束，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k * n) | O(n) | 太慢了 |
 | 按位贪心 | 每个查询 O(n * 20) | O(n) | 已接受 |

 ## 算法演练

 1. 从任何元素中可能的最高位开始（对于 ≤10^6 的数字为第 20 位），按降序对感兴趣的位进行排序。 我们从最高有效位到最低有效位一次处理一位，因为较高的位对 AND 的贡献更大。 
2. 将答案初始化为 0。该变量将存储我们可以使用当前预算实现的 AND。 
3. 对于每一位，计算在所有元素中设置该位的成本。 对于尚未设置该位的每个元素，计算需要添加多少才能打开该位而不更改已设置的较高位。 这是`(1 << bit) - (a[i] & (1 << bit - 1))`简化为到达该位为 1 的下一个数字所需的数量。 
4. 如果当前位的总成本小于或等于`k`，从中扣除这笔费用`k`并使用按位或将该位包含在答案中。 
5. 继续处理下一个较低位并重复该过程，直到所有位都已被评估。 
6. 输出查询的最终答案。 

工作原理：算法在每一步都保持不变，当前答案代表使用迄今为止所花费的操作可实现的最高 AND 值。 通过从最高位开始并且仅提交可以为所有元素打开的位，我们确保不会错过任何机会，并且当不能应用于所有元素时不会设置任何位。 这保证了结果是给定预算下真正的最大值和可实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

queries = [int(input()) for _ in range(q)]

max_bit = 0
for num in a:
    max_bit = max(max_bit, num.bit_length())

for k in queries:
    ans = 0
    remaining = k
    for bit in reversed(range(max_bit + 1)):
        cost = 0
        mask = 1 << bit
        for num in a:
            if not (num & mask):
                increment = mask - (num & (mask - 1))
                cost += increment
        if cost <= remaining:
            remaining -= cost
            ans |= mask
    print(ans)
```该解决方案首先计算所有元素的最高相关位。 然后，对于每个查询，它从高位到低位进行迭代，计算为所有元素打开该位所需的成本。 仅当总成本符合查询预算时`k`我们更新答案吗？ 一个微妙的点是为已经设置了较低位的数字正确计算增量，这可以避免意外的超调。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * max_bit * q) ≈ O(n * 20 * q) | 每个查询都会迭代所有位和所有元素。 |
 | 空间| O(n + q) | 存储数组和查询。 |

 自从`n * q ≤ 10^5`并且 max_bit ≤ 20，该算法很容易满足 2 秒的时间限制并使用适度的内存。
