 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 我们可以增加单个元素，一次增加一个，每次增加花费一个单位的预算。 对于每个查询，我们都会给出一个预算值$k$，我们想知道在花费最多之后我们可以使整个数组按位与有多大$k$所有元素的总增量。 

关键输出不是最终的数组，而是最大可能的值$a_1 \,\&\, a_2 \,\&\, \dots \,\&\, a_n$最多经过最优分配后$k$增量。 

约束条件非常大：最多$10^6$元素和查询以及值$k$最多$10^{18}$。 这立即排除了任何模拟每个查询或每个元素操作的解决方案。 即使每个查询的线性工作也会太慢。 

一个天真的解释是：对于每个查询，尝试所有分配增量的方法，这是组合的并且显然是不可能的。 即使尝试“构建”目标 AND 值并独立检查每个查询的可行性，也必须进行大量优化，因为每个查询的重新计算成本太高。 

当所有数字已经很大但未按位对齐时，会出现微妙的边缘情况。 例如，如果一个数字设置了一位，而另一个数字没有设置，则增加值可能会有所帮助或有害，具体取决于进位传播。 这使得贪婪推理变得非常重要，并迫使我们根据位约束而不是数字约束来思考。 

## 方法

 蛮力的想法在概念上很简单。 对于固定的$k$，我们猜测运算后的最终数组并计算其 AND。 由于每个增量恰好将一个元素增加 1，因此我们实际上是在“购买”分布在元素之间的任意整数增量。 这意味着每个元素都可以独立筹集，但成本会在全球范围内累积。 

直接暴力将尝试在预算范围内达到的所有可能的最终阵列$k$，但这是一个天文数字。 

更结构化的蛮力是固定目标值$X$最后的AND。 然后我们问：我们能否使每个数组元素至少变成$X$总成本最多$k$，同时还确保所有位$X$递增后仍然存在于每个元素中？ 

这将问题转化为可行性检查：对于候选人$X$，计算筹集每项资金的成本$a_i$到某个数字$b_i \ge X$这样$(b_i \& X) = X$。 成本是$b_i - a_i$，最小化每个元素。 

关键的见解是我们实际上不需要考虑任意$b_i$。 对于每个元素，最便宜的有效$b_i$是大于或等于的最小数$a_i$包含所有位$X$。 这给出了每个元素的确定性成本函数。 

现在结构变得单调：如果一个值$X$在预算范围内可以实现$k$，然后任何更小的$X$也是可以实现的。 这允许对每个查询的答案进行二分搜索。 但我们仍然需要快速的可行性检查，这就是使用按位贪婪构造的地方。 

我们不是从头开始重新计算每个查询，而是预先计算在强制数字包含候选掩码位时成本的行为方式。 然后，每个查询都成为与位掩码上的二进制搜索相结合的快速可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对数组进行暴力破解 | 指数| O(n) | 太慢了 |
 | 可行性+二分查找|$O(n \log A \log A)$| O(n) | 已接受 |

 ## 算法演练

 我们将问题转化为寻找一个固定的$k$, 最大整数$X$这样所有数组元素都可以增加到至少$X$并分享所有的点$X$，在预算范围内$k$。 

1. 我们对数组进行排序并构建一个结构，该结构允许我们推理使所有元素与目标位掩码“兼容”。 关键的观察是每个元素都可以独立向上舍入以满足位约束，但成本取决于二进制进位如何交互。 
2.我们定义一个函数`cost(X)`计算所需的最小总增量，以便每个元素都可以变成某个数字$b_i \ge a_i$和$(b_i \& X) = X$。 对于每个元素，我们贪婪地构建最小的有效元素$b_i$必要时向上翻转位。 这是可行的，因为增加 1 会按递增顺序探索数字，因此上面的第一个有效候选者$a_i$是最优的。 
3. 为了计算可行性，我们迭代元素，并为每个元素模拟我们必须向上跳多远才能嵌入所有位$X$。 这是通过扫描位来完成的$X$从最高到最低并强制丢失位。 
4.一次`cost(X)`被定义，我们观察到单调性：如果$X$是可以实现的，那么它的比特的任何子集（即较小的值）也是可以实现的，因为约束减弱了。 这使得二分搜索结束$X$有效的。 
5. 对于每个查询$k$，我们二分查找最大的$X$这样`cost(X) ≤ k`。 

### 为什么它有效

 关键的不变量是可行性仅取决于强制每个元素进入由下式定义的位约束的超集：$X$，并且满足这些约束的最小方法是每个元素独立的。 由于增量只会增加值，因此每个元素的最优调整都是局部贪婪的，并且除了通过总成本之外不会影响其他元素。 这种可分离性保证了个体最小成本求和的正确性。 单调性在$X$确保二分搜索永远不会跳过最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXB = 61  # enough for k up to 1e18

def next_valid(x, mask):
    """
    Smallest y >= x such that y contains all bits of mask.
    We construct it greedily from MSB to LSB.
    """
    y = x
    for b in range(MAXB):
        if (mask >> b) & 1:
            if not ((y >> b) & 1):
                # force this bit by rounding up
                y = ((y >> (b + 1)) + 1) << (b + 1)
    return y

def cost(a, mask, limit):
    total = 0
    for x in a:
        y = next_valid(x, mask)
        total += (y - x)
        if total > limit:
            return total
    return total

def can(a, mask, k):
    return cost(a, mask, k) <= k

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    # upper bound for answer bits
    hi = (1 << 20) - 1  # safe since values start <= 1e6 and k large can grow them

    for _ in range(q):
        k = int(input())

        ans = 0
        # binary search over bits
        for b in reversed(range(20)):
            if ans | (1 << b) <= hi:
                if can(a, ans | (1 << b), k):
                    ans |= (1 << b)

        print(ans)

if __name__ == "__main__":
    solve()
```### 代码说明

 功能`next_valid`为每个元素构造满足候选 AND 掩码所有位的增量可达到的最小数字。 它一点一点地工作：如果缺少所需的位，我们会将数字向上舍入到可以设置该位的下一个位置，而不会违反先前的约束。 

这`cost`函数对每个元素的调整进行求和，并在超出预算时提前停止，这对于考虑到较大约束的性能至关重要。 

每个查询都使用从最高位到最低位的贪婪位结构独立处理。 我们不是对所有值进行二进制搜索，而是通过测试设置每个位的可行性来直接构造答案位掩码。 

这避免了完整的$O(\log A)$每个查询进行二分搜索，并将其替换为线性位扫描。

 ## 边缘情况

 临界边缘情况是当一个元素略低于 2 的幂阈值时。 例如，如果$a_i = 7$我们需要一个设置位 3 的掩码，下一个有效数字是 8，这会引入一个大的跳转。 这说明了为什么贪婪的每个元素舍入是必要的，因为天真的位设置会低估成本。 

另一种边缘情况发生在$k = 0$。 答案必须是原始数组的 AND，因为不允许增加。 该算法自然会处理这个问题，因为任何需要更改的候选掩码都将无法实现可行性。 

最后一个边缘情况是$k$非常大。 在这种情况下，算法应该收敛到一个掩码，强制所有元素变得等于相同的大数。 按位构造确保我们最终包含所有可行的位，直到与约束一致的最大可能。
