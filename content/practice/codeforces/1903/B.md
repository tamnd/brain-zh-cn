 ## 解决方案
 ## 问题理解

 我们得到一个对称矩阵，据称该矩阵通过按位构造规则来自隐藏数组。 隐藏数组有$n$非负整数，每个都小于$2^{30}$。 对于每对不同的索引$i$和$j$，矩阵项$M_{i,j}$等于隐藏值的按位或$a_i$和$a_j$。 对角线项始终为零。 

任务是重建任何有效的数组$a$可以生成给定的矩阵，或者确定不存在这样的数组。 

关键的困难是我们没有得到直接值，只有成对的“或”结果。 每个约束耦合两个未知数，矩阵中的每个位都对两个端点的位的部分信息进行编码。 

这些约束意味着严格的重建问题而不是搜索问题。 自从$n$每次测试最多可达 1000，测试的总和也是 1000，$O(n^3)$或者任何涉及对所有三元组重复按位一致性检查的事情仍然是边缘性的，但只有在小常数的情况下才可以接受。 然而，预期的解决方案必须避免三重嵌套推理。 

如果我们尝试简单的重建，一些失败案例自然会出现。 

一个常见的错误是假设$a_i = \bigwedge_{j \ne i} M_{i,j}$。 这是错误的，因为 OR 不会以这种方式分解。 例如，如果$a_i = 1$和$a_j = 2$， 然后$M_{i,j} = 3$，并且没有单个交集可以恢复原始位。 

另一个微妙的问题是三元组之间的不一致。 例如，如果$M_{1,2} = 3$,$M_{1,3} = 3$,$M_{2,3} = 0$，则不存在有效的分配。 最后一个值意味着 2 和 3 不相交的位集，但两者必须与 1 共享位，这在 OR 结构下变得矛盾。 

真正的结构必须来自将每个矩阵行解释为隐藏位集的“联合签名”。 

## 方法

 一个蛮力的想法是尝试所有可能的数组$a$，但每个元素都有$2^{30}$的可能性，所以这是不可能的。 即使基于成对约束来限制值仍然会留下指数搜索空间。 

一种更结构化的粗暴方法是对待每个$a_i$作为未知位掩码并成对强制执行约束。 我们可以迭代并反复调整值直到收敛，但每次更新都依赖于所有其他更新，并且最坏情况的传播$n^2$约束导致多项式成本较高。 

关键的观察是反转 OR 关系。 如果$M_{i,j} = a_i \mid a_j$，那么所有涉及的成对 OR 中每个为零的位$i$必须缺席$a_i$。 相反，如果某个位出现在某些$M_{i,j}$，它必须至少属于以下之一$a_i$或者$a_j$。 

利用这一点的干净方法是贪婪地构建候选值：从每个$a_i$必须与所有 OR 约束一致。 对于固定的$i$，考虑如果位$b$每个都缺失$M_{i,j}$， 然后$a_i$不能包含位$b$。 这给出了一个上限$a_i$。 

然后我们检查一致性：一旦构建了候选数组，我们就验证所有成对 OR 是否与矩阵匹配。 否则，施工无效。 

存在更直接的构造性简化：对于有效的 OR 矩阵，该矩阵必须满足任何三元组的要求$i, j, k$,$$M_{i,j} \mid M_{i,k} = M_{j,k} \mid M_{i,k}$$结构间接地强制一致性，但如果我们仔细重建，我们不需要显式的三重检查。 

标准接受的方法出奇地简单：设置$$a_i = M_{i,1} \& M_{i,2} \& \cdots \& M_{i,n}$$是错误的，但正确的建设性技巧是：$$a_i = M_{i,1} \& M_{i,2} \& \cdots \& M_{i,n} \text{ is not valid}$$所以我们使用补充推理：

 对于每个位位置，请考虑哪些行可以安全地包含该位。 允许有一点$a_i$仅当对于每个$j$， 任何一个$M_{i,j}$已经设置了该位，或者我们可以将其一致地分配给一个端点。 该问题的已知简化可简化为：

 套装$$a_i = \bigwedge_{j \ne i} M_{i,j}$$作为候选人是不够的，但正确的结构是：$$a_i = \bigwedge_{j \ne i} (M_{i,j})$$然后验证。 如果存在有效的解决方案，则该构造将匹配其中之一，因为 OR 矩阵结构确保强制位的一致性。 

剩下的步骤是验证：重新计算所有$a_i \mid a_j$并与$M$。 如果全部匹配，则输出； 否则，不存在解决方案。 

这是有效的，因为在任何有效的 OR 分解中，任何位都被迫出现在涉及的所有成对交互中$i$必须属于$a_i$。 任何无关位都会违反至少一对约束。

 ## 算法演练

 1. 对于每个测试用例，读取矩阵$M$。 我们保持它不变，因为我们将验证它的一致性。 
2. 对于每个索引$i$，计算候选值$a_i$通过对所有内容进行按位与$M_{i,j}$为了$j \ne i$。 这会提取所有涉及的关系中一致存在的位$i$，这是唯一可以安全属于的位$a_i$不打破任何 OR 约束。 
3. 构建所有候选值后，根据矩阵验证它们。 对于每对$i, j$, 计算$a_i \mid a_j$并检查它是否等于$M_{i,j}$。 如果发生任何不匹配，该构造就无法表示给定的矩阵。 
4. 如果所有对都匹配，则输出 YES 后跟数组$a$。 否则输出NO。 

### 为什么它有效

 AND 行中幸存下来的每一位$i$存在于每一个$M_{i,j}$。 在任何有效的分解中，这样的位都不能丢失$a_i$，否则会存在一些$j$OR 需要该位来自哪里$a_j$，与它在所有对中的存在相矛盾。 相反，任何不一致的位都不能安全地分配给$a_i$，因为这可能会导致与某些伙伴行产生 OR 不匹配的风险。 这使得构建的$a_i$每个索引的最大安全分配，以及最终的验证步骤确保没有不正确地接受不明确的位分布。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        M = [list(map(int, input().split())) for _ in range(n)]

        a = [0] * n

        for i in range(n):
            val = (1 << 30) - 1
            for j in range(n):
                if i != j:
                    val &= M[i][j]
            a[i] = val

        ok = True
        for i in range(n):
            for j in range(n):
                if i == j:
                    if M[i][j] != 0:
                        ok = False
                        break
                else:
                    if (a[i] | a[j]) != M[i][j]:
                        ok = False
                        break
            if not ok:
                break

        if not ok:
            print("NO")
        else:
            print("YES")
            print(*a)

if __name__ == "__main__":
    solve()
```构建阶段计算每个$a_i$通过交叉涉及该索引的所有约束。 使用所有位集进行初始化可确保只有在所有成对 OR 中一致支持的位才能生存。 

验证步骤至关重要，因为构建是必要的，但在不检查全局一致性的情况下并不总是足够的。 所有对的双循环确保不存在隐藏的矛盾。

 ## 边缘情况

 关键的边缘情况是所有非对角线条目均为零时。 在这种情况下，每个成对 OR 都为零，因此每个$a_i$必须为零。 该结构对零进行 AND 计算，正确生成零，并且验证立即通过。 

另一种情况是具有相同值的全连接矩阵，例如所有非对角线项都等于 7。每行的 AND 得到 7，因此每个$a_i = 7$，并且 OR 一致性不重要，因为$7 \mid 7 = 7$。 

一个更微妙的情况是三元组之间的位分布不一致。 例如，如果一行表明某个位必须存在，而另一行禁止该位，则 AND 构造将从至少一个端点删除该位，并且验证将在重新计算 OR 值期间检测矛盾。
