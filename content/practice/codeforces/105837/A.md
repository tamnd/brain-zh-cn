 ## 解决方案
 ## 问题理解

 我们得到了一些垃圾箱。 每个垃圾箱都以一定数量的球开始，并具有最大容量。 该过程中的关键操作是，每当垃圾箱变满时，就会将其从主动考虑中删除，并将其全部内容转移到共享储备中。 储备中的球随后可以分配到其他垃圾箱中，帮助它们也达到满容量。 

根本问题是，从初始配置开始，是否有可能最终触发这个级联过程，使得所有箱子都可以仅使用最初可用的或储备中积累的球来完全处理。 

查看系统的另一种方式是，每个箱子在激活之前都需要有额外数量的球。 一旦激活，它将其全部容量贡献到全局池中，这可能使其他容器达到其激活阈值。 只要可以使用当前可用的储备来完成某些仓，该过程就会继续。 

这些约束意味着当箱的数量很大时，直接模拟激活箱的所有可能顺序是不可行的。 如果我们尝试探索激活序列的所有排列，可能性的数量会呈阶乘增长，即使对于几十个箱来说，这也是完全不可行的。 这立即表明该问题必须具有贪婪或基于排序的结构，使我们能够避免对所有可能的选择进行分支。 

当多个垃圾箱接近满时，会出现微妙的故障情况，但首先选择错误的垃圾箱会导致流程停滞。 

例如，假设我们有两个垃圾箱：

 输入：

 3 5

 4 6

 Bin 1 还需要 2 个球，而 Bin 2 也需要 2 个球，但完成后 Bin 2 会产生更多容量。 如果我们错误地优先考虑较大或任意的垃圾箱，我们最终可能会处于一种状态，即使存在有效的序列，储备也不足以完成剩余的垃圾箱。 这表明关于首先激活哪个垃圾箱的本地决策至关重要。 

核心困难在于，完成一个 bin 不仅仅是一个局部事件，它改变了全局资源池，从而影响了所有未来的可行性决策。 

## 方法

 暴力方法将尝试模拟完成垃圾箱的所有可能的顺序。 在每一步中，我们都会选择当前储备可以满足剩余所需空间的任何垃圾箱，递归地探索所有选择。 在最坏的情况下，如果所有 bin 最终可以通过多种方式完成，这会导致 N 个 bin 上的阶乘分支，从而导致 O(N!) 状态。 即使修剪无效路径也不能从根本上改善这种最坏情况的行为，因为许多中间状态仍然有效并导致进一步分支。 

关键的结构见解是，垃圾箱唯一有意义的属性是它需要多少额外空间才能被激活。 一旦我们抽象出确切的分配过程，我们就会发现，所需空间较小的垃圾箱更容易激活，并且永远不应该为了需要较大需求的垃圾箱而推迟。 

解锁解决方案的转换是将每个容器视为贡献一个需求值，定义为其剩余容量。 我们不是推理任意激活顺序，而是根据此要求对 bin 进行排序，并始终尝试处理当前可行的最受约束的 bin。 这是有效的，因为如果存在一种解决方案，可以延迟小需求容器以支持较大需求容器，我们总是可以交换它们的顺序，而不会使过程变得更加困难。 声明中提供的保留论点形式化了这种交换论点：优先考虑更紧密的垃圾箱永远不会降低可行性，只能改进或保留它。

这将问题简化为维护多组剩余容量并按递增顺序贪婪地消耗它们。

 | --- | --- | --- | --- |
 | 蛮力 | O(N!) | O(N) | 太慢了|
 | 最优（空间贪婪）| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们将每个垃圾箱的剩余所需空间定义为容量与当前内容之间的差值。 该值表示激活该垃圾箱的难度。 

### 步骤

 1. 计算每个箱子的剩余空间，即容量减去当前球数。 这捕获了激活它所需的确切额外资源。 
2. 按剩余空间以非递减顺序对所有垃圾箱进行排序。 这个想法是始终首先考虑最受限制的垃圾箱，因为如果延迟，它们最有可能阻碍进度。 
3. 初始化一个代表可用备用球的变量。 最初，该值为零，因为尚未激活任何垃圾箱。 
4. 按排序顺序迭代 bin。 对于每个箱，检查当前的储备是否足以满足其所需的空间。 如果不是，则该过程停止，因为也无法完成具有相同或更大要求的其他箱。 
5. 如果储备充足，则激活垃圾箱并将其全部容量添加到储备中。 这模拟了这样一个事实：一旦一个垃圾箱完成，它的所有球都可以重新分配。 
6. 继续此过程，直到处理完所有垃圾箱或直到无法激活垃圾箱。 

### 为什么它有效

 正确性取决于激活顺序的交换论证。 假设存在一个有效序列，该序列在具有较小需求的容器之前激活具有较大剩余需求的容器。 因为较小的 bin 更容易满足，所以交换它们的顺序永远不会减少在较大 bin 仍然可行的任何步骤中的可用储备。 因此，任何有效的解决方案都可以转换为按所需空间的非递减顺序处理容器的解决方案。 这意味着，如果存在任何解决方案，贪婪排序顺序也将成功，并且如果贪婪过程在某个 bin 失败，则任何替代排序也不会成功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    bins = []
    for _ in range(n):
        a, s = map(int, input().split())
        bins.append((s - a, s))
    
    bins.sort()
    
    reserve = 0
    
    for need, cap in bins:
        if reserve < need:
            print("NO")
            return
        reserve += cap
    
    print("YES")

if __name__ == "__main__":
    solve()
```实现直接遵循贪婪排序。 每个箱由一对表示，由其所需的额外空间及其容量贡献组成。 排序确保我们始终首先处理最严格的约束。 保留检查可防止无效转换，即无法使用当前可用资源激活容器的情况。 

一个常见的实施陷阱是忘记激活后添加的贡献是全部容量，而不仅仅是差异。 另一个微妙之处是确保排序键恰好是剩余空间，因为按容量排序会破坏逻辑。

 ## 边缘情况

 一种重要的边缘情况是所有仓都要求严格的正初始储备。 例如：

 输入：```
2
3 5
4 6
```两个箱子都需要至少 2 个储备单位，但系统从零开始。 该算法按要求对它们进行排序，并立即检测到第一个 bin 无法激活，正确返回 NO。 任何首先激活较大垃圾箱的尝试也会失败，因此不存在隐藏的有效排序。 

另一种边缘情况是当一个容器的需求为零时：

 输入：```
3
0 10
5 6
6 7
```在这里，第一个垃圾箱始终可以被激活并产生大量储备。 由于排序，该算法首先对其进行处理，确保系统在处理更紧密的垃圾箱之前变得可行。 跟踪显示储备增长足以解锁所有后续箱，确认贪婪顺序正确地模拟了依赖结构。
