 ## 解决方案
 ## 问题理解

 我们得到一个长序列，其中每个元素都保证是六个固定值之一：4、8、15、16、23、42。任务不是重新排序或修改值，只是删除元素，以便将剩余的元素划分为长度为 6 的完整有序链。 每个有效链必须遵循严格的顺序 4 → 8 → 15 → 16 → 23 → 42，并且剩余数组中的每个元素必须恰好属于一个这样的链位置。 

目标是最大化我们可以从原始顺序形成多少个完整链，因为每个六个完整链都会对保留的元素做出贡献，并且必须删除这些链之外的所有内容。 一旦我们知道完整链的最大数量，答案就是总元素减去该数量的六倍。 

约束很大，元素多达 500,000 个。 这立即排除了任何二次甚至$O(n \log n)$每个元素具有重状态的方法。 该解决方案必须是线性的或非常接近线性的，在单次传递或少量恒定次数的传递中处理数组。 

当贪婪策略仅独立跟踪每个数字的频率时，就会出现微妙的失败情况。 例如，如果我们在任何 4 之前看到许多 8，或者在足够的 16 之前看到许多 23，则简单计数会高估可能的链。 顺序依赖性是严格的，因此我们必须尊重顺序，而不仅仅是总数。 另一个棘手的情况是交织多个部分序列； 相同的值可能在不同的链中可用，具体取决于早期元素的消耗方式。 

## 方法

 一个蛮力的想法是模拟构建每一个可能的链。 我们可以尝试贪婪地将每个元素分配给一个序列，维护所有部分构建的序列。 每个新数字都会尝试扩展任何兼容的部分链，或者如果它是 4，则开始一个新的链。这很快就会变得复杂，因为我们必须跟踪潜在的许多不完整的链。 在最坏的情况下，元素以对抗模式交替出现，我们最终可能会得到$O(n)$活跃的部分链，每次更新可能会扫描其中许多链，从而导致$O(n^2)$行为。 

关键的观察结果是所有链都是相同的并且严格排序。 我们不需要跟踪各个链，只需要跟踪当前有多少条链正在等待每个阶段的完成。 我们不跟踪序列，而是跟踪有多少部分链到达每个前缀：有多少个看到了 4，有多少个看到了 4→8，有多少个看到了 4→8→15，等等。 

这将问题变成了管道。 每个数字要么从舞台上推进一条链$i$到$i+1$，或者如果该阶段没有可用的链，则被忽略。 贪心规则变成：总是延长最早可能的阶段。 

这将问题简化为固定的 6 级类似 DP 的模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（明确跟踪链）| O(n²) | O(n) | 太慢了 |
 | 阶段数贪婪模拟| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个值映射到其在序列中的位置：4 是阶段 0，8 是阶段 1，15 是阶段 2，16 是阶段 3，23 是阶段 4，42 是阶段 5。 

我们维护一个数组`cnt[6]`， 在哪里`cnt[i]`是当前阶段等待值的部分序列的数量`i`。 

我们还维护我们已经完成了多少条完整的链条。 

1. 将所有计数初始化为零。 我们将从左到右处理数字，自然地保留顺序约束。 
2. 当我们读取一个值时，确定它的阶段索引。 
3.如果值为4（阶段0），我们总是通过增加来开始一个新的部分链`cnt[0]`。 这是可以开始一条链的唯一值。 
4. 对于任何其他阶段的值`i > 0`，我们尝试延长当前正在等待该值的链。 如果`cnt[i-1] > 0`，我们递减`cnt[i-1]`并增加`cnt[i]`。 这代表消耗先前启动的部分链并推进它。 
5. 如果值为 42（第 5 阶段），那么当我们将一条链延伸到第 5 阶段后，我们立即完成它。 所以递减后`cnt[4]`，我们增加已完成链的数量，而不是存储第 5 阶段的链。 
6. 如果没有链可供扩展，我们将不执行任何操作，隐式丢弃该元素。 这对应于它是最佳解决方案中被删除的元素之一。 

重要的想法是我们从不拖延任务。 如果可能，每个元素都会立即使用，并且始终在最早的兼容阶段。 

### 为什么它有效

 在任何时刻，部分链的结构都可以通过等待每个下一个所需值的数量来完全捕获。 由于所有链都具有相同的结构，并且所有元素都按顺序处理，因此在早期阶段可用时为后期阶段分配值的任何决策只会降低未来的灵活性。 贪婪地延长最早可能的阶段可以保留稍后完成完整序列的最大能力。 这保持了一个不变量`cnt[i]`始终是可以到达 stage 的部分序列的最大可能数量`i`使用已处理的前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    order = {4: 0, 8: 1, 15: 2, 16: 3, 23: 4, 42: 5}
    cnt = [0] * 6
    completed = 0
    
    for x in a:
        i = order[x]
        
        if i == 0:
            cnt[0] += 1
        else:
            if cnt[i - 1] > 0:
                cnt[i - 1] -= 1
                if i == 5:
                    completed += 1
                else:
                    cnt[i] += 1
    
    print(n - completed * 6)

if __name__ == "__main__":
    solve()
```该解决方案对每个元素只处理一次。 字典将每个值映射到其阶段索引，因此转换是恒定时间。 这`cnt`array 跟踪每个阶段有多少个部分链正在等待。 当我们达到 42 时，我们只计算完成情况，不会进一步存储它，因为完成的链不再参与未来的转换。 

一个常见的实现陷阱是错误地允许 42 创建新状态而不是终止链。 另一个是忘记确保每个元素最多只推进一条链。

 ## 边缘情况

 一个关键的边缘情况是元素以部分正确的顺序到达但在完成之前被“破坏”。 对于像这样的输入`4 8 15 16 42 23`，算法将成功前进到阶段 3，在 42 处无法完成一条链，然后将 23 视为无用。 最终完成的计数仍然为零，这与不存在完整链的事实相匹配。 

另一个边缘情况是过多的早期中间元素，例如在任何 4 之前有许多 8。 该算法只是丢弃不匹配的 8，因为`cnt[0]`为零。 这可以防止无效的链构建并确保不会过早推进。 

最后一个边缘情况是多个链的严重交错。 该算法自然地将可用阶段分布在多个部分链上，因为每个阶段计数器代表独立的链容量。 这避免了显式链跟踪的需要，同时保留了最佳匹配。
