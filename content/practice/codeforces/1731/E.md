 ## 解决方案
 ## 问题理解

 我们从一个图表开始$n$标记顶点且无边。 目标是准确地结束$m$无向边。 顶点之间的每条边$u$和$v$不是自由选择的：它的权重是固定的并且等于$\gcd(u, v)$。 然而，构建边的实际成本并不直接取决于各个边。 相反，我们可以重复执行批量创建边的操作。 

在一次操作中，我们选择一个数字$k \ge 1$。 如果可以选择的话$k$目前缺少边，我们将它们全部添加并支付总成本$k + 1$，无论其个人身份如何。 这意味着批次中每条边的成本仅取决于批次大小，而不取决于端点。 该约束纯粹是组合性的：我们只能包含尚不存在且不违反自循环或复制规则的有效边。 

关键的困难在于我们不是一一选择边。 相反，我们必须对最终的集合进行划分$m$边分成组，其中一组的大小$k$成本$k + 1$。 图的结构（通过 gcd 约束）仅与可行性有关：是否存在足够的有效边来形成所需的批次。 

约束条件很大，总共$n$跨测试用例最多$10^6$。 任何尝试显式构造或枚举所有对之间的边的解决方案都是立即不可能的，因为完整的图具有$O(n^2)$边缘。 即使每个测试用例存储邻接结构也会超出内存和时间限制。 该解决方案必须在每个测试用例的线性或接近线性时间内工作。 

当在不了解 gcd 结构施加的可行性限制的情况下尝试贪婪批处理时，会出现微妙的失败情况。 例如，在小$n$，并非所有批量大小都是可以实现的，因为具有所需属性的有效边可能太少。 另一个常见的错误是假设任何分区$m$成批量大小是可能的，这忽略了由于有限的兼容边缘而无法形成某些批量大小。 

## 方法

 蛮力观点是考虑所有$\binom{n}{2}$可能的边缘，标记哪些是有效的，然后尝试划分选定的大小子集$m$分批进行。 每批尺寸$k$成本$k + 1$，所以我们将搜索所有分区$m$以及使用有效边实现这些分区的所有方法。 这是组合爆炸性的：即使在分区之前，枚举边也是如此$O(n^2)$，以及分区的数量$m$呈指数级增长。 

关键的观察是，边的实际身份与成本无关，只与我们在每批中获取多少条边有关。 因此，图的结构仅在决定哪些批量大小可行时才重要。 这减少了确定哪些整数的问题$k$可以通过批量大小来实现，然后最小化分区上的成本表达式$m$。 

更深层次的结构来自于 gcd 边。 对于任意顶点$x$，它连接到多个$x$，因此顶点可以按整除性进行分组。 这会创建一个层次结构，其中较大的 gcd 值对应于更受约束的边集。 最佳构造有效地使用这种可分结构来决定每个“级别”可以形成多少条边以及如何将它们分组为批次。 

一旦我们根据除数层重新解释可行性，​​问题就会简化为结构化容量函数上的贪婪成本最小化：在给定的最小 gcd 贡献下有多少条边可用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数|$O(n^2)$| 太慢了|
 | 基于除数的贪婪 DP |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 关键思想是计算我们可以使用 gcd 至少给定值形成多少条边，然后使用此能力贪婪地从最便宜到最昂贵的批次进行组装。 

1. 对于每个整数$d$，计算有多少个顶点是 的倍数$d$。 这给了我们在水平上对 gcd 结构有贡献的顶点组的大小$d$。 

这很重要，因为 gcd 的边可以被$d$由成对的倍数确定$d$。 
2.据此，计算每个级别贡献的潜在边的数量$d$使用倍数内的组合配对。 每个级别都贡献一定的边缘容量，可以将其解释为可用于批处理的“单元”。 
3. 按成本递增顺序对 gcd 级别进行排序或迭代。 较低的 gcd 水平对应于更便宜的有效边缘结构。 

直觉是与较小的结构约束相关的边更加丰富，应该首先使用。 
4. 维持剩余需求$m$，并逐级减去可用容量。 

在每个级别，决定要采用多少条边。 如果一个级别有能力$c$， 拿$x = \min(c, m)$。 
5. 对于每个选择的金额$x$，计算这对应了多少个完整批次以及它们产生的成本。 一批尺寸$k$成本$k + 1$，因此将边分布到更大的批次中是有益的。 
6. 在每个级别中，最大化批量大小以减少开销。 这变成了局部贪婪优化：更少的批次意味着更小的附加成本。 
7.如果处理完所有级别后我们仍然有$m > 0$， 输出$-1$，因为没有足够的有效边存在。 

### 为什么它有效

 该算法依赖于由可分性引起的边缘可行性的单调结构。 每条边都属于 gcd 约束的层次结构，并且该层次结构将所有可能的边划分为独立的容量桶。 由于成本与批次大小成线性关系加上每批次的固定开销，因此最小化成本可以减少批次数量，同时尊重容量。 首先贪婪地消耗最大的可行结构永远不会阻止后来的选择，因为较高的 gcd 级别只会限制而不是扩展可用边集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    cnt = [0] * (n + 1)
    for d in range(1, n + 1):
        cnt[d] = n // d

    # number of pairs where gcd is divisible by d
    cap = [0] * (n + 1)
    for d in range(n, 0, -1):
        c = cnt[d]
        cap[d] = c * (c - 1) // 2
        for j in range(2 * d, n + 1, d):
            cap[d] -= cap[j]

    total = 0
    rem = m

    for d in range(1, n + 1):
        if rem == 0:
            break
        use = min(rem, cap[d])
        if use == 0:
            continue

        rem -= use

        k = use
        total += k + 1

    if rem > 0:
        print(-1)
    else:
        print(total)

t = int(input())
for _ in range(t):
    solve()
```该解决方案首先计算每个整数的倍数，该整数构成除数格的主干。 根据这些计数，它使用倍数的包含-排除来计算有多少对的 gcd 可被每个值精确整除。 

数组`cap[d]`表示在 gcd 级别结构上有多少条边可用$d$。 这是从图形约束到数字容量的关键转变。 

最后的循环贪婪地消耗从小的容量$d$向上。 较小$d$对应于更灵活的边，因此首先使用它们可以确保我们不会在后续需求中浪费约束结构。 

成本累积反映了$k$批次成本中的边数$k + 1$。 由于在这个简化的贪婪视图中每个级别都被视为单个批次，因此该代码有效地最大限度地减少了开销添加的数量。

 ## 边缘情况

 一个关键的边缘情况是当$m$超过 gcd 结构隐含的可能边总数。 例如，如果$n=3$，最大边数仅为 3，任何高于该边数的请求都必须返回$-1$。 该算法通过以下方式检测到这一点`rem > 0`耗尽所有能力后。 

当所有必需的边必须来自单个 gcd 级别时，会出现另一种边缘情况。 在这种情况下，算法完全消耗单个容量桶，仅产生一批成本贡献。
