 ## 解决方案
 ## 问题理解

 我们得到两个长度相等的数字列表，并且只允许我们对第二个列表进行重新排序。 重新排列后，我们按索引对元素进行配对，并检查每个配对的总和是否保持在固定的上限内。 

思考这个问题的一个有用方法是，第一个数组中的每个值代表“已提交的成本”，第二个数组中的每个值代表一个“补充预算”，我们可以自由地分配给这些成本。 目标是分配这些预算，以便没有职位超出限制。 

约束很小：每个测试用例最多有 50 个元素，最多有 100 个测试用例。 这意味着即使每个测试用例都是二次的算法也很容易足够快。 任何三次或指数在理论上仍然是可以接受的，但没有必要。 

这里经常出现的一个天真的错误是尝试任意或贪婪地匹配元素而不对两个数组进行排序。 例如，即使存在有效排列，将第一个数组中的最大元素与第二个数组中的随机元素配对也可能失败。 考虑`a = [1, 4]`,`b = [2, 5]`,`x = 6`。 如果我们贪婪地配对`(4, 5)`首先，我们立即打破约束，即使重新排列`b`作为`[5, 2]`使两对都有效。 

另一个微妙的失败来自于假设如果`a`可以与一些元素配对`b`，那么剩下的就会自动工作。 这忽略了使用一个小`b`太早可能会阻碍以后的可行性。 

## 方法

 蛮力的想法是尝试每一种排列`b`并检查配对是否有效。 这是正确的，因为它探索了所有可能的任务，但它的增长是`n!`。 即使是为了`n = 50`，这是完全不可行的，因为排列的数量是天文数字。 

关键的见解是，我们正在解决具有单调约束的分配问题：较小的值`a`更容易满足，因此应在搭配上具有更大的灵活性`b`，以及更大的值`a`需要较小的配对值`b`。 

这建议对两个数组进行排序并以结构化方式将它们配对，而不是尝试所有排列。 正确的策略是将最小的元素配对`a`中最大可能的有效元素`b`或者等效地，以一致的相反方式将最小到最大配对。 排序将问题从组合匹配转变为确定性贪心检查。 

这样做的原因是，如果存在任何有效的分配，则有一个保留顺序：交换两个违反顺序的分配永远不会破坏可行性，并且通常会改善松弛分配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(n!) | O(n) | 太慢了|
 | 最优（排序+贪婪配对）| 每次测试 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们想要测试是否存在一对元素`b`这样每一对都与`a`保持在`x`。 

1. 数组排序`a`按非降序排列并对数组进行排序`b`按非递减顺序。 排序至关重要，因为它使我们能够推理结构而不是排列。 
2. 反转数组`b`。 反转后，最大元素`b`先来吧。 这为我们准备了贪婪的配对策略，我们可以控制将哪个“预算”分配给哪个“成本”。 
3. 对于每个索引`i`从`0`到`n - 1`，检查是否`a[i] + b[n - 1 - i] <= x`。 这对最小的元素`a`最大元素为`b`，第二小的与第二大的，依此类推。 

这种配对背后的原因是，大值`b`就浪费的闲暇而言，它们是“昂贵的”。 将它们分配给较小的值`a`防止它们阻止更大值的可行性`a`。 

如果任何对违反了条件，我们立即得出结论：不存在有效的重排。 

### 为什么它有效

 对两个数组进行排序后，考虑它们之间的任何有效分配。 如果存在交叉赋值，其中较大的元素`a`与较大的元素配对`b`而较小的元素`a`与较小的元素配对`b`，交换这两对不会恶化任何约束，并且通常会提高可行性。 重复应用此类交换会将任何有效的解决方案转换为与已排序数组的两端相匹配的解决方案。 这证明检查反向配对就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        line = input().strip()
        while line == "":
            line = input().strip()
        n, x = map(int, line.split())
        
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort(reverse=True)
        
        ok = True
        for i in range(n):
            if a[i] + b[i] > x:
                ok = False
                break
        
        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```该解决方案首先仔细阅读每个测试用例，包括处理分隔用例的空行。 排序`a`按升序排列并且`b`按降序建立贪婪结构。 

核心循环检查我们需要验证的唯一配对。 一旦出现违规，我们就可以提前停止，因为剩余元素的重新排列无法修复固定索引配对处的失败约束。 

一个微妙的实现细节是逆转`b`而不是按相同方向排序并从相反两端进行索引。 两者是等价的，但反转使配对逻辑更加明确。

 ## 边缘情况

 最小的边缘情况是`n = 1`。 该算法简化为单一比较，并且排序没有效果。 配对直接检查唯一可能的总和是否适合`x`。 

当出现紧边界情况时`a[i] + b[j]`正好等于`x`对于所有对。 该算法接受这一点，因为它只拒绝严格的违规，并且这确认了等式约束下的正确性。 

一个容易失败的场景是两个数组都包含重复的大值。 例如，`a = [4, 4, 4]`,`b = [3, 3, 3]`,`x = 6`。 贪婪配对检查`4 + 3 = 7`，立即拒绝，这与任何重新排列的可能性相匹配，因为所有配对在排列之前都是相同的。
