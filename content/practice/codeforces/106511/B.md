 ## 解决方案
 ## 问题理解

 我们给出了几个测试用例，每个测试用例都是一个仅由字符组成的字符串`6`和`7`。 任务是计算我们可以选择多少对位置，使得第一个位置包含`6`，第二个位置包含一个`7`，以及`7`严格出现在所选选项的右侧`6`。 

换句话说，我们正在计算有序的索引对$(i, j)$在哪里$i < j$，字符位于$i$是`6`，以及位于$j$是`7`。 每个测试用例都是独立的，我们输出每个字符串的计数。 

输入大小最多允许$10^4$测试用例，所有字符串组合的总长度最多为$2 \cdot 10^5$。 这是关键的约束：尽管可能有很多测试用例，但所有测试用例的总工作必须与总字符串长度保持线性。 任何以超过其长度的线性时间处理每个测试用例的方法都会太慢。 

对每个字符串内的所有位置对进行简单的双循环将检查最多$n^2$每个测试用例对。 如果单个字符串有长度$2 \cdot 10^5$，仅此一项就已经存在$4 \cdot 10^{10}$操作，这远远超出了 2 秒的限制所能处理的。 所以我们需要一个方法来处理每个字符串$O(n)$时间。 

在一些边缘情况下，粗心的逻辑会被破坏。 

如果字符串只包含`7`s，例如`777`，没有`6`配对，所以答案必须为零。 一种有缺陷的方法，假设至少一个`6`或从第一个字符开始计数可能会错误地添加值。 

如果字符串只包含`6`s，例如`6666`，仍然没有有效的`7`，所以答案又是零。 这里的错误通常来自尝试计算位置组合而不检查第二个字符类型。 

如果字符串像这样交替出现`6767`，我们必须确保只计算有效的前向对。 这里的正确答案是 3，来自 1`6`在位置 1 与稍后的两者配对`7`s 和第二个`6`与最后一个配对`7`。 

## 方法

 蛮力法很简单：对于每个包含`6`，扫描所有后面的位置并计算有多少个`7`。 这是正确的，因为它直接遵循有效对的定义。 然而，在最坏的情况下，它的运行时间是二次的，因为对于长度的字符串$n$，每个$n$位置最多可扫描$n$未来的职位。 总输入大小达到$2 \cdot 10^5$，这种方法将尝试按顺序$10^{10}$操作，这是不可行的。 

关键的观察是对于每个`6`, 重要的是有多少`7`s 出现在它之后，而不是它们单独的位置。 我们可以维护一个连续计数，而不是重复向前扫描`7`s 仍位于当前位置的右侧。 如果我们知道每个值`6`，我们可以直接将其添加到答案中。 

一种更简洁的思考方式是反转计数方向。 如果我们从右向左遍历字符串，我们会维护多少个`7`到目前为止我们已经看到了。 当我们遇到一个`6`, 每个以前见过的`7`与其形成有效对。 这会将嵌套循环结构转换为单遍。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（检查所有对）| 每个测试用例的 O(n²) | O(1) | O(1) | 太慢了|
 | 带后缀计数的单遍 | 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个字符串。 

1.初始化一个计数器`sevens = 0`跟踪有多少`7`到目前为止，我们从右向左扫描时看到的字符。 这代表任何有效合作伙伴的数量`6`我们稍后会遇到。 
2. 初始化`answer = 0`。 
3. 从最后一个字符到第一个字符迭代字符串。 

当我们看到一个`7`，我们增加`sevens`。 这是因为任何`6`较早出现的可以与此配对`7`。 

当我们看到一个`6`，我们添加`sevens`到`answer`。 这是有效的，因为每个`7`我们已经看到了右边的谎言`6`，形成有效对。 
4.处理完整字符串后，输出`answer`。 

遍历的方向是使逻辑一致的：此时我们处理一个`6`，变量`sevens`已经准确地代表了未来有效头寸的数量。 

### 为什么它有效

 该算法依赖于从右到左扫描期间任何位置的不变量，`sevens`等于`7`s 严格位于当前索引的右侧。 当我们处理一个`6`在索引处`i`， 每一个`7`计入`sevens`形成独特的一对$(i, j)$和$j > i$。 由于每对在处理其左端点时只计算一次，因此最终总和等于字符串中有效对的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        sevens = 0
        ans = 0

        for ch in reversed(s):
            if ch == '7':
                sevens += 1
            else:  # ch == '6'
                ans += sevens

        print(ans)

if __name__ == "__main__":
    solve()
```该代码直接反映了从右到左的推理。 逆转很重要，因为它避免了必须显式地预先计算后缀数组，并且它确保当我们达到`6`, 所有相关的`7`s 已经被计算过了。 

一个微妙的实现细节是剥离输入字符串。 没有`.strip()`，换行符可能会被错误地处理为额外字符，从而导致某些环境中的计数逻辑不正确。

 ## 边缘情况

 一个字符串仅包含`6`s，例如`66666`，触发每个字符都是潜在左端点但没有右端点的情况。 在从右到左扫描期间，`sevens`始终保持为零，因此每个`6`将零添加到答案中，产生正确的结果零。 

一个字符串仅包含`7`s，例如`777`，测试相反的情况。 算法增量`sevens`对于每个角色，但从未遇到过`6`，因此答案中不会添加任何内容。 结果正确地保持为零。 

混合但不平衡的字符串，例如`666777`体现了积累。 从右侧扫描时，前三个步骤构建`sevens = 3`，以及每个`6`答案加 3。 这确保了所有跨界对都被精确计数一次，从而确认“右侧 7 的数量”的不变量足以描述所有有效对。
