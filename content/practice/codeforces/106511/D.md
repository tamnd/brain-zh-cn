 ## 解决方案
 ## 问题理解

 我们给定了一个上限$n$。 有编号从 1 到$n$，但我们不知道我们最终会拥有哪栋房子。 出发前，我们必须购买多组从0到9的数字牌，每张牌的价格相同，并且每个数字可以购买多少张。 

每个门牌号均以十进制书写，不带前导零。 要显示门牌号码，我们必须能够使用我们购买的瓷砖来组成它的数字，并尊重多重性。 任务是确定要购买的最小数字块数量，以便从 1 到每个数字$n$可以形成。 

关键的困难在于不同的数字需要不同的数字频率。 例如，覆盖 17 以内的所有数字需要比数字 7 更多的数字 1 副本，因为 11 和 10 会额外使用 1 和 0。解决方案不是针对每个数字单独覆盖数字，而是覆盖所有数字中每个数字的最大总需求。 

自从$n \le 10^9$，迭代每个数字直到$n$是不可能的。 一次完整扫描需要多达十亿次操作，这远远超出了 1 秒的限制。 即使是一个解决方案$O(n)$字符串转换被排除。 我们需要一种能够有效地计算所有数字中数字使用情况的方法，最好是对数或数字 DP 风格的复杂性。 

进位和重复数字周围出现了一个微妙的问题。 例如，在 9 和 10 之间，数字 0 突然出现，而数字 9 以不同的模式从使用中消失。 另一个棘手的区域是像 99、100、101 这样的数字，其中数字频率会极大地改变结构。 任何独立地递增数字和计数数字的简单模拟都会错误地处理这种转换模式或简单地超时。 

核心观察是我们不是在跟踪单个数字，而是在数字间隔内聚合数字出现次数。 该结构强烈暗示了数字 DP 或位置计数方法。 

## 方法

 暴力解决方案将从 1 迭代到$n$，将每个数字转换为字符串，并将数字频率计数到大小为 10 的全局数组中。答案将是数字之间的最大频率，因为每个图块对应于单个可用的出现。 

这是正确的，但价格昂贵。 转换每个数字的成本$O(\log n)$，并这样做$n$次导致大约$O(n \log n)$运营。 和$n = 10^9$，这是不可行的。 

关键的观察是，可以计算某个范围内的数字出现次数，而无需枚举每个数字。 我们不处理每个数字，而是将数字范围视为位置系统问题。 对于每个数字位置，我们计算每个数字在从 1 到 的所有数字中出现的次数$n$。 这是一个经典的数字计数问题，其中除了边界效应之外，每个位置都独立做出贡献。 

我们使用高部分、当前数字和低部分表示来分解每个数字位置的贡献。 对于固定位置，数字以可预测的模式循环，该位置的周期为 10。 完整周期的计数给出了基本贡献，其余部分处理部分周期。 各个位置的求和给出了总数字频率。 

一旦我们得到了每个数字的总计数，答案就是数字 0 到 9 之间的最大频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \log n)$|$O(1)$| 太慢了|
 | 位置数字计数|$O(\log n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 转换$n$转换为十进制字符串表示形式，以便我们可以按位置访问数字。 这避免了重复划分并简化了位置推理。 
2. 对于从最低有效位到最高有效位的每个数字位置，计算完整周期长度的次数$10^{k+1}$为这一地位做出了贡献。 每个完整周期都会平均分配数字 0 到 9，但前导零约束除外，前导零约束是通过单独调整最高位置来处理的。 
3. 对于当前位置，拆分$n$分为三部分：较高的前缀、当前数字和较低的后缀。 较高的前缀决定了有多少个 10 的完整块完全贡献。 当前数字确定不完整块的部分贡献。 当该数字严格大于目标数字时，后缀确定额外贡献。 
4. 累积每个位置从0到9的每个数字的贡献。 这构建了每个数字在 [1, n] 中所有数字中出现的次数的全局计数。 
5. 处理完所有位置后，计算位数中的最大值。 该最大值代表所需的图块数量，因为我们必须能够为最频繁需要的数字提供足够的副本。 

### 为什么它有效

 每个数字对数字频率都有独立的贡献，并且每个数字位置在整个间隔中以周期性模式演变。 通过将数字分解为位置贡献，我们用计算完整和部分循环来代替枚举。 不变的是处理后的位置$k$，[1, n] 中的每个数字都在该位置上的数字恰好贡献了一次总计数，并且没有数字被重复计算或遗漏，因为每个位置都是独立处理的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = str(n)
    L = len(s)

    cnt = [0] * 10

    for i in range(L):
        power = 10 ** (L - i - 1)
        current = int(s[i])

        left = n // (power * 10)
        mid = (n // power) % 10
        right = n % power

        for d in range(10):
            cnt[d] += left * power
            if d == 0:
                cnt[d] -= power  # adjust leading zero overcount

        for d in range(10):
            if d < mid:
                cnt[d] += power
            elif d == mid:
                cnt[d] += right + 1

    print(max(cnt))

if __name__ == "__main__":
    solve()
```该解决方案是围绕每个位置计数构建的。 数字位置上的循环隔离了每个位置的独立贡献。 数组`left`,`mid`， 和`right`表示标准的数字-DP 分解：来自前缀的完整循环、来自当前数字的部分贡献以及来自后缀的剩余部分。 

对数字 0 的调整是必要的，因为前导零不是有效数字，因此简单的循环计数会过度计算较高位置的零。 此更正确保只有有效的表示才能做出贡献。 

决赛`max(cnt)`反映了这样一个事实：限制资源是最常需要的数字。 

## 工作示例

 ### 示例 1：n = 7

 我们计算数字 1 到 7 的数字使用情况。 

| 职位| 行动| cnt[1..9] 更新 |
 | --- | --- | --- |
 | 单位 | 所有数字都直接贡献 | 每个数字 1..7 出现一次 |

 聚合后，数字 1 到 7 的计数是统一的，每个数字出现一次。 

这会产生数字 1..7 的最大计数 1，因此答案是购买的总共 7 个数字。 

跟踪确认该范围内没有数字重复，因此每个数字恰好贡献了每个数字的一​​个图块要求。 

### 示例 2：n = 17

 数字是1-17。 数字 1 出现在 1、10、11、12、13、14、15、16、17 中，产生多个贡献。 

| 细分 | 贡献 |
 | --- | --- |
 | 1-9 | 1-9 数字 1 出现一次 |
 | 10-17 | 数字 1 又出现 8 次 |

 所以cnt[1]变成9，而其他数字出现的次数更少。 

最大位数为 9，这意味着我们至少需要 9 个数字 1 的副本。 

这条轨迹强调了通过十年边界的转变如何显着增加数字重复，如果不仔细聚合，这种天真的每个数字推理很容易错误计数。

 该算法在限制内运行自如$n \le 10^9$意味着最多 10 位数字位置，并且所有运算都是常数时间算术。

 ## 边缘情况

 对于$n = 1$，仅使用一位数字，因此答案必须为 1。该算法处理此问题是因为所有位置贡献都崩溃为单个单位位置，没有更高的周期。 

为了$n = 10$，数字 1 出现两次，数字 0 出现一次。 位置计数可以正确捕获这两个贡献，因为它单独处理个位和十位，确保不会错过突然出现的新数字。 

对于边界情况，例如$99 \rightarrow 100$，天真的推理经常会失败，因为数字 9 从整个周期中完全消失，而数字 0 的频率却爆炸。 该算法干净地处理了这个问题，因为每个位置都是独立评估的，因此进位转换自然地被吸收到前缀和后缀分解中，而不需要特殊的大小写。
