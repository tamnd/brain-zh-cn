 ## 问题理解

 我们得到一个整数序列，并要求计算有多少个不同的位置三元组产生固定的目标和条件，在这个问题中，这是经典的“3-sum”条件：索引选择的三个不同元素的总和必须为零。 

输入可以理解为单个数组，其中顺序对于最终答案并不重要，重要的是值以及每个值出现的次数。 输出是一个表示索引三元组数量的整数$(i, j, k)$和$i < j < k$使得相应的值满足$a[i] + a[j] + a[k] = 0$。 

关键的困难不是形成一个有效的三元组，而是当数组很大并且可能包含许多重复项时有效地计算所有三元组。 

一个天真的想法是尝试所有索引三元组并检查它们的总和是否为零。 一旦数组增长超过几千个元素，这就变得不可行，因为三元组的数量呈立方增长。 

一个更微妙的问题来自重复。 如果数组包含重复值，则正确的解决方案必须计算索引的组合，而不仅仅是不同的值三元组。 例如，如果数组是`[0, 0, 0, 0]`，正确答案是选择 4 个零中任意 3 个的方法数，即 4。基于集合的重复数据删除方法会错误地返回 1。 

当值同时包含大的正数和负数但不存在有效的三元组时，会出现另一种边缘情况。 正确的解决方案必须仍然有效运行，而不依赖于采用结构的提前终止启发法。 

## 方法

 蛮力策略很简单。 我们迭代所有索引三元组$i < j < k$，计算总和，如果答案为零，则增加答案。 这是正确的，因为它直接评估每种可能组合的问题定义。 

问题在于操作的数量。 对于大小的数组$n$，这种方法的性能约为$\frac{n^3}{6}$检查。 什么时候$n = 5000$，这已经超过了$10^{10}$操作，这远远超出了及时运行的范围。 

改进来自于减少搜索的第三维。 如果我们修复一个元素，问题就变成在剩余后缀中查找总和为特定值的对。 这是标准的 2-sum 结构，如果剩余部分已排序，则可以在线性时间内求解。 

对数组进行排序可以对每个固定的第一个元素进行两指针扫描。 对于选定的索引$i$，我们搜索对$(l, r)$这样$a[i] + a[l] + a[r] = 0$。 这将问题从三次时间减少到二次时间。 

重要的结构增益是排序将任意对搜索变成单调过程，其中移动指针对总和具有可预测的影响。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了|
 | 固定+两个指针|$O(n^2)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 我们依靠排序和重复的两指针扫描。 

1. 对数组进行非降序排序。 这使我们能够推断当指数向内或向外移动时总和如何变化。 
2. 固定三元组的第一个元素在位置$i$。 我们将其视为我们将搜索的所有对的锚值。 
3.设置两个指针，$l = i + 1$和$r = n - 1$，并计算总和$s = a[i] + a[l] + a[r]$。 
4. 如果$s$为零，我们找到了有效的三元组。 如果值为$l$和$r$是不同的，我们计算两侧存在多少重复项并乘以它们的频率。 这可以在一个步骤中正确处理重复的值，而不是单独迭代相同的元素。 
5. 如果$s$小于零，总和太小，所以我们移动$l$向右增加它。 这是可行的，因为增加排序数组中的第二个元素只能增加总和。 
6.如果$s$大于零，总和太大，所以我们移动$r$向左移动以减少它。 
7. 重复步骤 3-6，直到$l$遇见$r$，然后移动$i$转发并重新启动该过程。 

### 为什么它有效

 正确性取决于两个耦合的不变量。 首先，对于任意固定的$i$，两指针扫描检查每个可行的对$(l, r)$在排序数组段的单调遍历中恰好一次。 不会跳过任何有效的对，因为每当总和太小或太大时，只有一个移动方向可能会恢复给定排序的有效总和。 

其次，对重复项进行分组可确保索引的每个组合都只计算一次。 我们不是一一列举相同的值，而是一步计算它们的组合贡献，在保持正确性的同时避免计数过多。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = 0

    for i in range(n):
        l, r = i + 1, n - 1

        while l < r:
            s = a[i] + a[l] + a[r]

            if s < 0:
                l += 1
            elif s > 0:
                r -= 1
            else:
                if a[l] == a[r]:
                    cnt = r - l + 1
                    ans += cnt * (cnt - 1) // 2
                    break

                lv = a[l]
                rv = a[r]

                lc = 0
                while l < r and a[l] == lv:
                    l += 1
                    lc += 1

                rc = 0
                while r >= l and a[r] == rv:
                    r -= 1
                    rc += 1

                ans += lc * rc

    print(ans)

if __name__ == "__main__":
    solve()
```该程序首先对数组进行排序，这对于两指针推理至关重要。 对于每个固定索引`i`，它将问题视为寻找互补对，总和为`-a[i]`。 

重复处理逻辑是最微妙的部分。 当指针落在有效的三重和上时，有两种情况。 如果两个指针位于相同的值，则该块中的每一对都会形成有效的组合，并使用组合公式进行计数。 否则，我们计算左侧和右侧存在多少个相同的值并将它们相乘，因为每个左侧出现的值都可以独立地与每个右侧出现的值配对。 

指针移动确保一旦某个区域被消耗，就不会再被重新访问，从而使整体复杂性保持二次方。

 ## 边缘情况

 关键的边缘情况是有效区域中的所有元素都相同。 用于输入`[0, 0, 0, 0]`，算法进入这样的状态`l`和`r`指向同一个值。 它不是逐对迭代，而是压缩整个范围并使用$\binom{4}{2} = 6$每个固定锚点对，确保所有三元组都包含一次。 

另一种情况是有效的三元组仅存在于数组的边界处。 为了`[-5, -2, 0, 2, 5]`，指针的运动逐渐从两端消除不可能的和。 即使有效组合很稀疏，算法仍然可以达到它们，因为每个单调移位都保留了当前固定索引段内没有跳过可行对的不变量。
