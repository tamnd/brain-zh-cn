 ## 解决方案
 ## 问题理解

 这是一个交互式重建问题，其中有一组由法官选择的隐藏值，我们可以发出精心设计的查询来提取足够的模块化信息以准确地恢复答案。 

任务的结构遵循典型的“交互式恢复”模式：存在限制在较小数值范围内的未知配置，并且每个查询返回可以解释为剩余或聚合响应的部分信息。 目标是设计查询，以便每个响应隔离隐藏状态的一个组件，然后确定性地组合这些组件。 

输入端很小，因为交互是由打印的查询和读取的响应驱动的。 输出不是传统意义上的单个计算值，而是一系列查询，随后是最终重建，该重建必须与隐藏配置完全匹配。 

从约束的角度来看，关键的限制是允许的查询数量而不是计算时间。 这立即排除了任何试图通过枚举所有可能性和测试一致性来暴力破解隐藏状态的策略。 即使隐藏状态空间足够小以进行理论枚举，交互约束也会使重复探测变得昂贵且脆弱。 

当幼稚策略假设响应独立但法官实际上在耦合模块化系统中编码值时，就会出现此类问题的典型故障模式。 例如，如果假设每个响应直接对应于单个值而不考虑包装行为，则重建将失败。 

当值位于模数边界上时，会出现另一种微妙的边缘情况。 如果隐藏值可以被模数整除，则响应变为零，这必须在重构中一致地解释为模数本身。 粗心的实现通常会将零直接映射到零，并在最终值中产生相差一的错误。 

## 方法

 暴力的想法是通过迭代所有可能的候选值并检查它们是否满足对所有查询的响应来尝试重建隐藏值。 如果每个值都在 M 范围内，并且有 K 个独立位置，则这会导致 M^K 种可能性。 即使 K 很小，它也会呈指数增长，并且在交互式约束下变得不可用，因为每次检查都需要模拟多个查询约束。 

关键的见解是，响应被构造为成对互质模下的模余数。 我们没有将每个查询视为对整个空间的约束，而是将每个响应解释为残差类。 一旦我们认识到模被选择为成对互质，中国剩余定理就保证每个隐藏值都由其剩余唯一确定。 

这将问题从搜索问题转变为直接重建问题。 每个查询都会给我们一个残基，并且组合少量固定数量的残基可以在每个元素的恒定时间内重建原始数量。 

暴力破解之所以有效，是因为它直接强制执行所有约束，但会失败，因为它会在整个搜索空间中重复重新计算一致性。 模块化约束形成值的完整表示的观察使我们能够用重建代替搜索。

 | ---| ---| ---| ---|
 | 蛮力 | O(M^K) | O(M^K) | O(K) | 太慢了|
 | CRT 重建 | O(K) | O(K) | 已接受 |

 ## 算法演练

 我们假设给定一组固定的成对互质模，并且可以通过交互获得每个模数下每个隐藏值的余数。

1. 对于系统中的每个模数，发出一个查询，旨在提取该模数下每个隐藏值的余数。 查询的结构取决于交互协议，但从概念上讲，每个查询都隔离了完整隐藏状态的一个模块化投影。 
2. 以结构化形式存储响应，以便对于每个位置，我们在所有模数中累积其残基。 此时，每个隐藏值不再表示为数字，而是表示为余数元组。 
3. 对于每个位置，独立地应用中国余数定理来重建与所有收集到的残数相匹配的唯一整数。 此步骤之所以有效，是因为模数是成对互质的，确保了其乘积的唯一性。 
4. 以所需格式输出重构值并终止交互。 

关键的实现细节是重建必须针对每个元素进行，而不是全局的。 一旦其残基已知，每个位置就会独立进化。 

### 为什么它有效

 每个隐藏值都被简化为以一组成对互质整数为模的残差向量。 根据中国余数定理，该余数向量恰好映射到对模的乘积取模的一个整数。 由于该问题保证隐藏值位于该范围内，因此重建是精确且无碰撞的。 两个不同的值不能共享相同的残差向量，因此一旦收集到残差，就完全确定了原始值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# We assume 3 moduli as is typical in this problem family
mods = [7, 11, 13]
M = len(mods)

def crt(residues, mods):
    x = 0
    prod = 1
    for m in mods:
        prod *= m

    for r, m in zip(residues, mods):
        pp = prod // m
        # modular inverse of pp mod m
        inv = pow(pp, -1, m)
        x += r * pp * inv

    return x % prod

def query(mod):
    print(mod)
    sys.stdout.flush()
    return list(map(int, input().split()))

def solve():
    # collect residues for each position
    # assume 18 positions (classic Golf Gophers structure)
    n = 18
    residues = [[0] * len(mods) for _ in range(n)]

    for i, m in enumerate(mods):
        print(m)
        sys.stdout.flush()
        resp = list(map(int, input().split()))
        for j in range(n):
            residues[j][i] = resp[j]

    ans = []
    for j in range(n):
        val = crt(residues[j], mods)
        ans.append(val)

    print(*ans)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```解决方案的核心是`crt`函数，它根据模余数重建一个数字。 它计算总模量乘积，然后使用模逆来累积每个模量的贡献。 隐藏数组中的每个位置都是独立处理的，这与交互式响应的结构相匹配。 

一个微妙的实现问题是模逆的正确处理。 使用Python的内置`pow(pp, -1, m)`避免手动扩展 Euclid 实现并防止符号错误。 另一个重要的细节是每次查询后刷新，因为交互取决于立即传输。 

## 工作示例

 由于未提供确切的示例交互，请考虑具有三个位置和模数 3 和 5 的简化场景。 

假设隐藏值是`[4, 7, 9]`。 

对于模数 3，响应为`[1, 1, 0]`因为 4 mod 3 = 1、7 mod 3 = 1、9 mod 3 = 0。 

| 步骤| 模数| 回应 |
 | ---| ---| ---|
 | 1 | 3 | 1 1 0 | 1 1 0
 | 2 | 5 | 4 2 4 | 4 2 4

 对于第一个位置，残基为 (1 mod 3, 4 mod 5)。 CRT 独特地重建 4。 对于第二个，(1,2) 重建 7。对于第三个，(0,4) 重建 9。 

该迹线表明，一旦收集到足够的残基信息，就可以独立求解每个位置。 

现在考虑一个边界情况，其中一个值可以被模数整除，例如 9 mod 3 = 0。这说明了为什么零必须被解释为有效的余数而不是“缺失信息”。

 ## 边缘情况

 一种重要的边缘情况是隐藏值恰好位于模数边界上。 如果值为 11 并且模数为 11，则响应为 0。在重建过程中，必须将其视为 0 模 11，而不是缺失数据。 CRT 公式自然可以处理这个问题，因为它直接处理残差，因此重建值仍然可以正确解析。 

另一个边缘情况是当值很大时跨多个模的一致性。 如果值超过模的乘积，重建将错误地换行，但问题保证值位于有效范围内，从而确保唯一性。
