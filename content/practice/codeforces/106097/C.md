 ## 解决方案
 ## 问题理解

 我们有一个起点，我们希望使用两种类型的移动来达到目标距离。 一个动作每单位时间前进固定的小量，而另一个动作是一种特殊的跳跃，它覆盖更大的固定距离，但消耗固定的、不平凡的时间。 关键要求是总距离必须精确匹配，而不仅仅是超过它。 

所以任务是选择一系列步行步骤和跳跃步骤，使得距离之和恰好等于`n`，同时最小化总时间。 步行在时间和距离上都呈线性贡献，而每次跳跃贡献固定距离`b`但需要花费3秒的固定时间。 

重要的微妙之处在于，跳跃的行为并不像“更快的行走”。 它用刚性块代替了一段运动：你要么完全接受它，要么根本不接受它，它总是做出准确的贡献`b`。 

这立即创建了一个结构，其中可行性取决于选择跳跃后的剩余距离是否可以使用大小的单位步长组成`a`。 

这些限制使我们远离模拟。 自从`n`可能非常大（最多 10^18），任何迭代距离或每一步尝试贪婪模拟的解决方案都是不可能的。 即使 DP 超过各州`n`是完全不可行的。 

我们被迫纯粹用算术进行推理：要进行多少次跳跃，以及是否可以使用步行步骤来表示剩余的部分。 

当跳转看似有益但破坏了精确可达性的情况下，就会出现幼稚的错误。 例如，如果`a = 2`,`b = 4`， 和`n = 11`，我们可以尝试将跳跃和行走结合起来，但每种组合只能产生均匀的距离，使得 11 无法到达。 正确答案是`-1`。 

当局部跳跃过冲时会出现另一个失败案例，但似乎对全局有帮助。 例如，减少步行步数的跳跃可能看起来是最佳的，但如果它留下的余数不能被整除`a`，它使整个构造失效。 

## 方法

 蛮力方法会尝试所有的移动序列：每一步要么走要么跳，累积距离直到达到或超过`n`。 这很快就会变成指数级的，因为在每一点我们都会分成两个选择，并且深度可以是`n / a`。 即使我们修剪超过的路径`n`，状态空间仍然巨大，因为不同的序列可以以不同的时间成本到达相同的距离。 

关键的观察是顺序并不重要。 只有跳跃的次数才重要，因为每次跳跃都会贡献相同的距离和时间。 一旦我们确定了跳跃次数`k`，强制剩余距离：`n - k*b`。 剩下的部分必须只能通过步行大小的步数来实现`a`，这减少到整除条件。 

所以问题就变成了：选择一个整数`k >= 0`这样`n - k*b >= 0`和`(n - k*b) % a == 0`，并最小化`3k + (n - k*b)/a`。 

我们不需要随意寻找，只需要考虑可行的`k`价值观。 该结构足够单调，可以检查所有相关的残基类别模`a`或者在一个小的有界范围内迭代就足够了，因为增加`k`线性改变余数。 

这将问题从路径搜索转变为模块化算术优化。

 | ---| ---| ---| ---|

 ## 算法演练

 1.首先检查是否可以表示`n`仅使用步行步骤。 如果`n % a == 0`，这给出了基线答案`n / a`。 这建立了一个不使用跳转的后备解决方案。 
2.考虑一一引入跳跃。 每次跳跃都会移除`b`所需步行距离的单位，但会增加 3 秒的成本。 对于固定次数的跳跃`k`，计算剩余距离`rem = n - k*b`。 如果`rem < 0`，这个选择无效，因为我们超调了。 
3. 对于每个有效`k`，检查是否`rem`可以用行走步数准确表达。 这需要`rem % a == 0`。 如果为 true，则计算总时间`3k + rem / a`并更新最小值。 
4. 有用范围`k`值是有界的，因为一旦`k > n / b`，余数变为负数。 所以搜索空间是线性的`n / b`，考虑到约束条件，它足够小并且也很容易推理。 
5. 跟踪所有有效配置的最短时间，并将其输出。 如果没有配置有效，则输出`-1`。 

### 为什么它有效

 任何有效的策略都可以分解为多组跳跃加上其余的步行步骤。 由于这两种操作都提供独立于顺序的固定距离，因此重新排列它们不会改变可行性或成本。 这意味着每个解决方案都唯一对应于一个选择`k`其余的则纯粹以步行为主。 可整除条件对于可实现余数来说既是充分必要的，因此枚举所有有效的`k`覆盖整个解决方案空间，不会遗漏或重复任何案例。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, n = map(int, input().split())

    INF = 10**30
    ans = INF

    # k = number of jumps
    k = 0
    while k * b <= n:
        rem = n - k * b
        if rem % a == 0:
            ans = min(ans, k * 3 + rem // a)
        k += 1

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```遍历代码，循环枚举可能的跳转次数。 每次迭代都会将问题简化为检查剩余距离是否与步行步长完全一致。 算术检查取代了任何模拟的需要。 使用大哨兵可以避免在不存在有效配置时意外的比较溢出。 

一个微妙的点是，我们不会尝试通过混合贪婪决策来优化，因为每当余数模数时，局部贪婪就会失败`a`对跳跃计数的变化很敏感。 详尽列举了`k`干净利落地避免了这个陷阱。

 ## 边缘情况

 当`n`小于`b`，算法自然只评估`k = 0`，这正确地将问题简化为检查纯步行的可行性。 例如，与`a = 3`,`b = 10`,`n = 1`，循环从不考虑跳转并正确输出`-1`自从`1 % 3 != 0`。 

什么时候`n`正好可以整除`a`，该算法正确地允许零跳跃解决方案，并忽略任何只会恶化成本的跳跃配置。 为了`a = 2`,`b = 5`,`n = 8`，最好的解决方案是四次行走，并且每一次`k >= 1`引入无法整除或增加成本的余数。 

什么时候`b`相对于`n`，循环仅运行一次或两次，确保即使在最大约束下也不会出现隐藏的性能问题。
