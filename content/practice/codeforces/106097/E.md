 ## 解决方案
 ## 问题理解

 两名战士进行一场确定性的决斗，这场决斗在离散的几秒钟内展开。 每秒两个生物都会同时造成伤害：你的生物会根据其攻击值减少对手的生命值，而对手则会根据其攻击值减少你的生物的生命值。 战斗持续进行，直到至少其中一人生命值为零或负值。 

在战斗开始之前，您可以分发有限数量的升级，称为煎饼。 每块煎饼都会使你的攻击力增加 1 点，或者使你的生命值增加 1 点。 我们的目标是确保你的生物在整个决斗中幸存下来，我们希望尽量减少需要的煎饼数量。 

关键的困难在于，生存并不仅仅由攻击或健康的单一阈值决定。 增加攻击力会减少对手的生存回合数，而增加生命值会增加你可以吸收的敌人攻击数量。 这两种效果通过战斗持续的轮数相互作用。 

输入由四个整数组成，代表你的攻击力和生命值，后面是对手的攻击力和生命值。 输出是所需的最小单位升级数量，以便在攻击和生命值之间进行最佳分配后，你的生物不会在战斗中死亡。 

一种天真的解释可能会建议独立地提高攻击力，直到你赢得伤害竞赛，或者独立地提高生命值，直到你生存足够长的时间，但这两种方法都不能孤立地发挥作用，因为提高攻击力可以通过缩短战斗来减少传入的伤害。 

当两个生物在同一个最终交换中死亡时，就会出现一种微妙的边缘情况。 即使对手在最后一击中被减少到零，他们仍然会在该轮造成伤害，因此在最后一次同时攻击后，你的生命值必须严格保持为正值。 

另一种失败模式来自假设固定轮数。 例如，如果您仅使用初始攻击来估计回合，您可能会得出生存是不可能的结论，而攻击的小幅增加将大大减少回合数并使生存变得容易。 

## 方法

 如果我们忽略分割煎饼的能力，那么战斗就变得很容易模拟。 对于固定的攻击和生命值，对手在已知轮数后死亡，我们可以检查总的伤害是否可以生存。 尝试攻击和健康之间煎饼的所有可能分布将给出正确性：对于每次分裂，我们模拟战斗并检查生存情况。 

这种暴力的想法是正确的，因为它尊重战斗的确切机制。 然而，它立即变得不可行。 如果我们分配 k 个煎饼，则有 k+1 种可能的分割，并且 k 本身可以很大。 更糟糕的是，每次模拟都需要计算直到死亡的轮数，如果仔细完成，则会导致额外的对数因子，如果天真地完成，则会导致线性工作。 这在约束下爆炸了。 

关键的观察结果是，战斗结果仅取决于两个量：对手存活了多少轮，以及你每轮受到多少伤害。 如果你的攻击变成A，对手就活下来$$t = \left\lceil \frac{h_2}{A} \right\rceil$$回合。 在这 t 轮中，您准确地采取了$t \cdot a_2$损害。 如果你的最终生命值是H，生存需要$$H > t \cdot a_2$$现在煎饼只线性调整A和H。 我们可以根据可能的战斗长度 t 进行推理，而不是搜索所有分割。 一旦 t 确定，我们就可以计算在 t 轮内迫使战斗结束所需的最小攻击，以及恰好生存 t 轮所需的最小生命值。 从攻击和健康约束解耦的意义上来说，固定 t 的最佳分配变得独立。 

这将问题转化为检查 t 的候选值并采取所需的最小总升级。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配+模拟| O(k·log h2) | O(k·log h2) | O(1) | O(1) | 太慢了|
 | 列举可能的战斗长度 t | O(√h2) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 固定一个候选轮数t，代表对手存活的时间。 整个推理都基于这个值，因为它决定了造成的伤害和所需的攻击。 
2. 确定所需的最小攻击，使得对手最多在t轮内死亡。 这意味着$$a_1 + x \ge \left\lceil \frac{h_2}{t} \right\rceil$$所以所需的攻击升级是$$x = \max(0, \left\lceil \frac{h_2}{t} \right\rceil - a_1)$$3. 一旦 x 被修复，剩余的升级就会进入健康状态。 面对 t 轮伤害，生存需要$$h_1 + y > t \cdot a_2$$所以所需的健康升级是$$y = \max(0, t \cdot a_2 + 1 - h_1)$$4. 对于所选的 t，所需的煎饼总数为 x + y。 这是一个有效的配置，因为一旦 t 固定，攻击和健康升级是独立的。 
5. 观察以下表达式，而不是检查直到 h2 的所有 t$\lceil h_2 / t \rceil$仅当 t 与 h2 的约数相交时才发生变化。 这使我们能够通过扫描 h2 的所有商来有效地枚举候选 t 值，从而最多产生 O(√h2) 个候选值。 
6. 计算每个候选 t 的 x + y 并取所有候选中的最小值。 

### 为什么它有效

 核心不变量是每个有效的最终配置恰好对应一个有效战斗长度 t，定义为对手在所选攻击下生存的回合数。 对于任何固定的 t，我们计算强制 t 轮发生并存活下来所需的最小资源。 由于攻击和健康贡献是独立的，因此成本可以完全分解。 枚举所有不同的可能值$\lceil h_2 / t \rceil$确保我们涵盖每一种结构上不同的战斗模式，而不会错过最佳结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a1, h1, a2, h2 = map(int, input().split())

    ans = 10**30

    # iterate over possible t values using sqrt decomposition
    t = 1
    while t * t <= h2:
        # direct t
        for T in (t, h2 // t):
            if T <= 0:
                continue

            need_attack = max(0, (h2 + T - 1) // T - a1)
            need_health = max(0, T * a2 + 1 - h1)

            ans = min(ans, need_attack + need_health)

        t += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码直接实现了可能的战斗长度的分解。 循环结束`t`和`h2 // t`确保考虑上限划分的所有不同值。 攻击要求使用上限划分公式，而健康要求在最后一轮后强制执行严格的积极性。 

一个微妙的点是`+1`在健康约束下。 如果没有它，该解决方案将错误地允许在最终同时命中后以零生命值生存，这在规则下是无效的。

 ## 边缘情况

 当双方战士都极其虚弱时，例如`1 1 1 1`，最佳解决方案不需要煎饼，因为战斗在一次交换中就解决了，并且双方同时死亡。 该算法通过评估 t = 1 来处理此问题，其中攻击和健康要求评估为零。 

当对手拥有巨大的生命值但攻击力较低时，最佳策略会转向最大化攻击力，从而大大缩短战斗时间。 候选 t = h2 情况捕捉了这种情况，其中攻击要求变为零，仅健康状况决定生存。 

当你的生命值很大但攻击力很低时，算法自然会考虑大的 t 值，其中攻击仍然不足，而生命值主导成本。 对商的分解可确保包含这些情况，而无需显式迭代到 h2。
