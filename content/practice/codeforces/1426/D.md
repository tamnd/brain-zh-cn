 ## 解决方案
 ## 问题理解

 给定一个非零整数序列，并允许在相邻元素之间的任意位置插入任意整数。 目标是修改序列，以便最终数组的连续段的总和为零，同时使用尽可能少的插入元素。 

通过前缀和最容易理解零子数组和。 如果数组中的两个位置具有相同的前缀和，则它们之间的元素之和为零。 因此，在允许我们通过插入新元素“破坏”数组之后，问题相当于在从左到右扫描时防止任何重复的前缀和值。 

约束条件$n \le 2 \cdot 10^5$意味着我们需要一个线性或近线性的解决方案。 任何显式检查所有子数组或重复重新计算修改数组上的前缀和的方法都将太慢，因为插入元素会动态更改结构并可能导致二次传播。 

当多个不相交的段独立创建零和间隔时，会出现微妙的边缘情况。 例如，在像这样的数组中$[1, -1, 2, -2]$， 两个都$[1, -1]$和$[2, -2]$形成零和分段。 仅修复第一次出现的天真贪婪可能会错过以后的冲突，除非它正确跟踪全局前缀行为。 

## 方法

 暴力的想法是模拟所有可能的插入元素的方式，然后检查结果数组是否有任何零和子段。 即使限制为“在每对之间插入或不插入”仍然会导致指数级的可能性。 即使我们修复了一个候选数组，验证它也需要前缀和和哈希集，这是线性的。 但是探索所有插入配置是不可能的，因为配置的数量呈指数增长$n$。 

关键的观察是零和子数组完全由前缀和重复决定。 在扫描数组时，我们维护当前的前缀和。 如果我们达到了我们已经看到的前缀和，则意味着存在一个总和为零的子数组。 为了防止这种情况，我们必须确保前缀和在重复后变得“再次唯一”。 

插入元素有效地重置了前缀和的连续性。 从概念上讲，每次插入都会启动一个新的“段”，其前缀和历史是独立的。 一旦我们在某个点进行分割，就不再比较前后的前缀和。 

因此，问题简化为维护当前段的一组前缀和。 当我们遍历数组时，每当前缀和在当前段内重复时，我们必须在继续之前剪切该段，这相当于插入一个元素。 切割后，我们从零重新开始跟踪前缀和。 

这种贪婪的分割之所以有效，是因为延迟切割只会增加进一步碰撞的机会，而不会减少未来的碰撞。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（尝试所有插入）| 指数| O(n) | 太慢了|
 | 最优（贪婪前缀集重置）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护运行的前缀和以及当前段中看到的一组前缀和。 

1. 从前缀总和等于 0 和仅包含 0 的空集开始。这表示处理任何元素之前的空前缀。 
2. 迭代数组的每个元素，将其添加到当前前缀和中。 
3. 如果当前段中没有看到更新后的前缀和，则将其插入到集合中并继续。 
4. 如果前缀和已经出现，则表示当前段内存在一个子数组，其和为零。 为了消除这个问题，我们在概念上在当前位置之前插入一个数字，这会重置该段。 
5. 将答案加一，清除集合，然后重新启动段，并将前缀和重置为当前值，将其插入到新集合中。 
6. 继续直到数组末尾。 

### 为什么它有效

 不变的是，在每个活动段内，所有前缀和都是不同的。 段内的任何重复完全对应于完全包含在该段中的零和子数组。 由于我们无法修复过去的值，因此消除此类冲突的唯一方法是剪切该段。 每次剪切都会消除所有先前的前缀历史记录，因此我们永远不会向前传送冲突的前缀集。 在第一次重复时贪婪地切割可确保我们永远不会创建超出必要数量的段，因为任何后续切割仍需要分隔相同的冲突前缀对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    seen = set([0])
    prefix = 0
    cuts = 0

    for x in a:
        prefix += x
        if prefix in seen:
            cuts += 1
            seen = set([0])
            prefix = x
            seen.add(prefix)
        else:
            seen.add(prefix)

    print(cuts)

if __name__ == "__main__":
    solve()
```该解决方案维护一个运行的前缀和以及当前段中看到的前缀和的哈希集。 重置步骤是关键操作：当发生重复时，我们增加答案并从当前元素作为新段的第一个元素重新开始跟踪。 这反映了插入数字有效地破坏前缀连续性的想法。 

一个微妙的点是，重置后，我们将当前元素视为新段中的第一个前缀，因此前缀不会重置为零，而是正确地重新初始化。 

## 工作示例

 考虑示例输入：```

```我们跟踪前缀和和集合：

 在步骤4，前缀和1重复，表明当前段中存在零和子数组。 我们插入一个元素并重新启动。 

重置后：

 | --- | --- | --- | --- | --- |
 | 4（重新启动）| 2 | 2 | {0, 2} | 继续 |

 最终答案是1。 

此跟踪显示了前缀重复如何直接触发段拆分。

 ## 边缘情况

 关键的边缘情况是零和段恰好在前一个段的边界处结束。 例如，在`[1, -1, 1, -1]`，前缀和重复多次，每次重复都会强制重置。 

一步一步，处理后`[1, -1]`，前缀返回0，触发剪切。 如果不正确重置，幼稚的实现会错误地跨段合并前缀历史并低估所需的插入。 

另一种边缘情况是重置后立即重复，例如`[1, -1, 1]`。 加工后`[1, -1]`，我们重置。 处理最终结果时`1`，前缀变为1，在新鲜段中已经有效，因此不需要额外剪切。 这证实了重置完全隔离前缀历史并防止跨段干扰。
