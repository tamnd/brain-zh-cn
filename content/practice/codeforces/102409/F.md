 ## 解决方案
 ## 问题理解

 我们得到一个单词，其字符已按 ASCII 值排序。 我们用 ASCII 代码替换每个字符，获得一个由 (N) 个正整数组成的数组。 

加密包括获取该数组的每个可能的子集并记录所选元素的总和。 空子集贡献 (0)。 正好有 (2^N) 个子集，因此输出正好包含 (2^N) 个整数，按非降序排序。 

例如，对于单词`ab`，ASCII 值为 (97,98)。 它的子集是空子集、每个单个字符以及两个字符在一起。 它们的和是(0,97,98,195)，所以加密的输出是`0 97 98 195`。 

约束 (N \le 20) 足够小，使得 (2^N) 易于管理。 最大值为 (2^{20}=1,048,576)，因此输出本身已包含超过一百万个数字。 这给了我们一个有用的下限：任何可接受的算法都必须花费至少 (O(2^N)) 时间才能产生答案。 (O(N2^N)) 算法执行的工作量大约是上限输出大小的二十倍，而 (O(2^N \log 2^N)) 排序方法执行的工作量要多得多。 因此，目标是在 (O(2^N)) 时间内构造所有子集和。 

有几种边缘情况可能会暴露简单实现中的错误。 具有一个字符，例如```
1
a
```唯一的子集和是 (0) 和 (97)，因此输出是```
0 97
```一个常见的错误是仅生成非空子集，这会错误地省略初始零。 

重复的字符值也很重要。 为了```
2
aa
```两个字符都有值 (97)。 四个子集产生 (0,97,97,194)，所以正确的输出是```
0 97 97 194
```两个相等的 (97) 值必须都保留在输出中，因为它们对应于不同的子集。 对总和进行重复删除会产生错误的结果。 

已排序的输入并不意味着每个子集和都是不同的。 例如，这个词`ab`具有不同的值，但对于较大的数组，不同的组合仍然可以产生相同的总和。 该算法必须保留多重性，而不是将子集和视为一个集合。 

## 方法

 直接的方法是使用位掩码枚举每个子集。 对于从 (0) 到 (2^N-1) 的每个掩码，我们检查其 (N) 位并添加相应的数组值。 这会正确地生成每个子集一次。 然后我们可以对得到的 (2^N) 和进行排序。 

问题在于子集生成中的 (N) 因子。 在最坏的情况下，有 (2^{20}=1,048,576) 个掩模，每个掩模可能需要检查所有 (20) 个位置。 这大约是最终排序之前的 (20,971,520) 个元素检查。 对另外一百万个整数进行排序大约会增加 (2^{20}\log_2(2^{20}))，或大约两千万个比较级别。 当输出本身只有大约一百万个元素时，这是不必要的工作。 

有用的结构是输入值已经排序。 更一般地说，假设我们已经处理了前 (k) 个值，并且已经按排序顺序获得了它们的所有子集总和。 当我们添加一个新值 (x) 时，每个旧子集都会产生两种可能性：保持子集不变，给出 (s)，或包含 (x)，给出 (s+x)。 

如果旧的金额是

 [
 s_1 \le s_2 \le \点 \le s_m,
 ]

 那么通过添加 (x) 获得的新总和是

 [
 s_1+x \le s_2+x \le \点\le s_m+x。 
]

 所以我们有两个排序数组：旧的和和移位的和。 我们可以在线性时间内合并它们，而不是生成所有内容然后再排序。 

关键的观察比仅仅避免最终排序更强烈。 每次插入后，整个子集和数组仍保持排序。 开始于`[0]`，每个新角色贡献一个现有列表的移位副本，并且两个列表可以合并。 由于列表的大小在每一步都会加倍，因此总工作量是

 [
 1+2+4+\点+2^{N-1}=2^N-1,
 ]

 在写入输出的成本范围内，这是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(N2^N + 2^N\log 2^N)) | (O(2^N)) | 太慢/不必要的工作|
 | 最佳 | (O(2^N)) | (O(2^N)) | 已接受 |

 ## 算法演练

 1. 读取 (N) 并将该单词的每个字符转换为其 ASCII 值。 这些值已经是非递减的，因为保证单词按 ASCII 值排序。 
2. 从排序列表开始`sums = [0]`。 这表示使用零元素的所有子集和。 空子集是此时唯一的子集，因此零是完整且正确的初始状态。 
3. 一次处理一个字符值。 假设当前排序的子集和是`sums`下一个值是`x`。 
4. 通过添加构造第二个排序序列`x`对每一个元素`sums`。 如果`sums`如果已排序，则此移位序列也已排序，因为向每个元素添加相同的数字可以保留顺序。 
5.合并原来的`sums`并将移位的序列放入新的排序列表中。 原始列表中的每个元素代表一个不使用的子集`x`，而每个移位元素代表确实使用的相应子集`x`。 因此，合并只包含已处理前缀的每个子集一次。 
6. 更换`sums`合并列表并继续下一个值。 处理完(k)个字符后，`sums`恰好包含 (2^k) 个值。 
7. 处理完所有（N）个字符后，打印`sums`。 它的长度是 (2^N)，并且因为每个合并都保留排序顺序，所以输出已经排序并且不需要最终的排序过程。 

### 为什么它有效

 不变量是在处理前 (k) 个字符后，`sums`只包含这 (k) 个字符的每个子集和并进行排序。 

该不变量最初为真，因为空前缀只有一个子集，即空子集，其总和为零。 当添加新值 (x) 时，每个旧子集恰好有两个扩展：一个不包括 (x)，其总和相同；另一个包括 (x)，其总和增加 (x)。 原始列表包含所有排除情况，移位列表包含所有包含情况。 这些情况是不相交的，并且一起覆盖了扩大的前缀的每个子集。 

两个列表都已排序，因此合并它们会按排序顺序生成完整的集合。 这证明了每个字符之后不变式仍然成立，因此最终列表正是所需的加密消息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    word = input().strip()

    values = [ord(c) for c in word]

    sums = [0]

    for x in values:
        m = len(sums)
        shifted = [sums[i] + x for i in range(m)]

        merged = []
        i = 0
        j = 0

        while i < m and j < m:
            if sums[i] <= shifted[j]:
                merged.append(sums[i])
                i += 1
            else:
                merged.append(shifted[j])
                j += 1

        while i < m:
            merged.append(sums[i])
            i += 1

        while j < m:
            merged.append(shifted[j])
            j += 1

        sums = merged

    print(*sums)

if __name__ == "__main__":
    solve()
```这`ord(c)`call 将每个字符直接转换为其 ASCII 值。 不需要手动区分大写字母、小写字母或数字，因为Python已经提供了所需的数字代码。 

该列表最初仅包含`0`，对应于空子集。 对于一个值`x`,`shifted`恰好包含子集的总和，其中包括`x`。 原来的`sums`包含排除它的子集的总和。 

合并使用`<=`而不是`<`。 这个选择是经过深思熟虑的。 对于产生它们的每个子集，必须发出一次相等的总和。 当值相等时选择任一侧仍会保留两个副本，因为一次只有一个指针前进。 

剩下的两个`while`循环追加合并中尚未耗尽的那一半。 省略任一循环都是典型的合并实现错误，并且会丢失有效的子集和。 

对于此处涉及的值，Python 整数不会溢出。 即使最大可能的和也最多是（20 × 122），因为允许的最大字符是小写字母，所以普通的整数运算就足够了。 

输入仅包含一个单词，因此不存在测试用例循环。 输出是由`print(*sums)`，写入由空格分隔的所有 (2^N) 个整数。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(2^N)) | 每个阶段的合并最多对当前列表处理两次，列表大小为(1,2,4,\ldots,2^{N-1})。 |
 | 空间| (O(2^N)) | 最终答案包含 (2^N) 个整数，算法临时存储当前列表和移位列表。 |

 在 (N=20) 处，最终列表包含 (1,048,576) 个整数。 (O(2^N)) 算法是合适的，因为产生这么多输出值已经需要 (2^N) 中的线性工作。 对于这个输入大小，内存要求也在 256 MB 以内，尽管 Python 的整数和列表开销使得避免不必要的额外副本很有用。

def brute_force(word: str) -> str:
    values = [ord(c) for c in word]
    n = len(values)

    result = []

    for mask in range(1 << n):
        total = 0
        for i in range(n):
            if mask & (1 << i):
                total += values[i]
        result.append(total)

    result.sort()
    return " ".join(map(str, result))

 最小输入是```
1
a
```该算法开始于`[0]`。 处理（97）创建移位列表`[97]`，并且合并给出`[0, 97]`。 空子集被保留，并且正好有 (2^1=2) 个结果。 

对于重复值，请考虑```
2
aa
```第一个`a`转变`[0]`进入`[0, 97]`。 第二个`a`创造`[97, 194]`，合并产生```
0 97 97 194
```(97) 的两个副本对应于两个不同的单字符子集。 合并会保留两者，因为它永远不会删除相等的元素。 

第二种微妙的情况是包含大写和小写字符的输入：```
2
Az
```它们的 ASCII 值为 (65) 和 (122)。 开始于`[0]`，第一个值给出`[0, 65]`，第二个给出移位总和`[122, 187]`。 合并产生```
0 65 122 187
```该算法对 ASCII 数值进行操作，因此不需要对大写和小写字母占据 ASCII 表的不同区域的情况进行特殊处理。 

最后，考虑```
3
aaa
```列表大小为 (1)、(2)、(4) 和 (8)。 每次插入都会使子集和的数量加倍，因为每个现有子集对于新子集都有两个选择`a`。 最终输出是```
0 97 97 97 194 194 194 291
```在任何阶段都不会进行重复数据删除，因此即使其中几个子集具有相同的总和，所有八个子集仍然会被表示出来。
