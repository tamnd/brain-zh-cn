 ## 解决方案
 ## 问题理解

 我们有编号从 1 到 (N) 的票，按升序排列在一个圆圈上。 迭戈从票（S）开始。 从当前票证开始，该过程将恰好 (K) 个幸存票证向右移动，并在其着陆处删除该票证。 删除它后，当前票证将成为紧邻其左侧的幸存票证。 圆圈环绕一周，因此经过票证 (N) 后会继续到票证 1。 

任务是确定最后剩下的唯一一张票的 ID。 困难在于当前位置和目的地之间的票可能已经被删除，因此移动是在当前幸存的序列上而不是在原始ID上。 

(N)的值可以大到(10^{18})，同时可以有(10^5)个测试用例。 在这种规模下，即使是对门票进行单次线性传递也是不可能的，更不用说明确地维持圆圈了。 (K\le 10) 是关键的结构限制。 我们可以提供一种算法，其成本取决于 (K) 并且仅以对数方式取决于 (N)，但 (O(N))、(O(NK)) 或 (O(N^2)) 方法会立即被排除。 

有几种边缘情况暴露了常见的建模错误。 例如，如果 (N=1)，输入 (1\ 1\ 1) 必须产生 1，因为没有什么可以消除。 在检查大小之前执行一次消除的模拟可以访问空圆。 

情况（K=1）也很特殊。 对于输入 (5\ 3\ 1)，该过程删除 4，然后删除 5，然后删除 1，然后删除 2，因此票证 3 保留下来。 因此，当 (K=1) 时，答案始终是初始票 (S)。 假设被淘汰的票之前的票仍然存在，则推导出的公式在这里就失效了，因为前一个票本身可能已经被淘汰了。 

环绕是差一错误的另一个来源。 对于输入 (2\ 1\ 2)，将两张票从票 1 移回到票 1 上，因此票 1 被移除，票 2 获胜。 正确的输出是 2。将 (K) 视为普通的 ID 差异将完全忽略这一点。 

最后，搬家时删除的票不能算在内。 对于输入 (4\ 1\ 2)，首先删除票证 3。 下一个移动从票证 2 开始，然后移动到票证 4 和 1，因此接下来将删除票证 1。 剩余的票证是 2 和 4，接下来删除票证 4，留下票证 2。答案是 2。简单地将 (K) 添加到先前 ID 的粗心实现将使用有关不再存在的票证的信息。 

## 方法

 直接的方法是将幸存的票证 ID 保留在循环列表中。 在每一轮中，找到右侧的票 (K) 位置，将其删除，并将当前指针移动到其前一个。 这完全遵循流程，所以其正确性很简单。 

不幸的是，列表的大小最初是（N）。 有 (N-1) 次删除，即使找到目标仅花费 (O(K))，从普通数组中删除也会花费 (O(N))，因为元素必须移动。 在最坏的情况下，这给出了 (O(N^2)) 的工作，当 (N=10^{18}) 时，大约有 (10^{36}) 个基本运算。 链表避免了移位，但定位下一张票仍然需要每次消除跟踪最多 (K) 个幸存节点，给出 (O(NK))，仍然可以达到大约 (10^{19}) 次操作。 

有用的观察结果是 (K) 很小。 我们可以同时执行许多消除，并将剩余的圆变成完全相同问题的较小实例，而不是执行每个消除。 

对于 0 和 (K\ge2) 的相对起始位置，请考虑一圈 (N>K) 票。 第一张被淘汰的票是位置（K）。 删除后，新的当前位置是 (K-1)，它仍然存在，因为 (K\ge2)。 移动另一张 (K) 幸存的票落在 (2K) 上。 同样的争论还在继续，所以第一个

[
 m=\left\lfloor\frac{N-1}{K}\right\rfloor
 ]

 消除就是位置

 [
 K,2K,3K,\ldots,mK。 
]

 因此，我们立即删除了 (m) 张票，留下 (N-m) 张票。 新的当前票据是(mK-1)。 从那时起，剩下的过程又回到了原来的问题，只是在一个更小的圆上，并且对其位置进行了不同的物理标记。 

这与 Josephus 问题的标准 (O(K\log N)) 优化背后的批量删除原理相同，但该问题中的前驱规则将映射更改回原始圆。 

令(F(N,K))为中奖位置，使用从零开始的位置，并假设初始当前票是位置0。批量删除后，定义

 [
 m=\left\lfloor\frac{N-1}{K}\right\rfloor,\qquad
 Q=N-m。 
]

 我们递归计算 (r=F(Q,K))。 原圈内新的当前票是

 [
 P=mK-1。 
]

 在 (P) 之后，幸存的票证首先继续 (mK+1,mK+2,\ldots,N)。 让

 [
 R=N-mK
 ]

 是最后一个部分块的长度。 一旦结束，幸存的票出现在 (K-1) 的块中，即

 [
 1,\ldots,K-1,\quad K+1,\ldots,2K-1,\quad\ldots
 ]

 因为 (K) 的每个倍数都被删除了。 

如果递归答案是(r=0)，则它指的是(P)本身。 否则，设置(u=r-1)。 如果(u<R)，答案就在(P)之后的部分块中，在

 [
 mK+1+u。 
]

 否则，在跳过该部分块之后，设 (v=u-R)。 对应的原位置为

 [
 \left\lfloor\frac{v}{K-1}\right\rfloor K
 +
 (v\bmod(K-1))+1。 
]

 每次递归调用都会将 (N) 减少到大约 (N(1-1/K))。 因此递归深度是(O(K\log N))。 由于 (K\le10)，即使对于 (N=10^{18})，这也很小。

 ## 算法演练

 1. 使用从零开始的仓位，并在初始当前彩票为位置 0 时将 (F(N,K)) 定义为获胜仓位。实际起始彩票 (S) 将用作最终循环移位。 
2. 如果 (K=1)，则返回 0。移动一张票证总是会删除直接后继票证，而新的当前票证是我们开始的票证，因此初始票证会保留下来。 
3. 如果(N\le K)，直接模拟该过程。 在本例中最多有 10 张票，因此这只需要恒定的工作量。 
4. 对于 (N>K) 和 (K\ge2)，计算

 [
 m=\left\lfloor\frac{N-1}{K}\right\rfloor.
 ]

 前 (m) 张被淘汰的票是 (K,2K,\ldots,mK)。 在最后一张之后，当前票是(mK-1)。 
5. 从概念上删除那些 (m) 票并定义

 [
 Q=N-m。 
]

 从新的当前工单来看，剩余的过程与 (Q) 工单上的问题相同。 递归计算 (r=F(Q,K))。 
6. 计算圆回绕之前幸存的部分块的长度：

 [
 R=N-mK。 
]

 如果（r=0），则递归获胜者是新的当前票（mK-1）。 
7. 如果(r>0)，则设置(u=r-1)。 当(u<R)时，获胜者仍在(mK-1)之后的部分区块中，因此其原始位置为(mK+1+u)，模(N)减少。 
8. 如果 (u\ge R)，减去部分块并设置 (v=u-R)。 剩余的票证以 (K-1) 组的形式出现，并以 (K) 的一个已删除倍数分隔。 因此原来的位置是

 [
 \left\lfloor\frac{v}{K-1}\right\rfloor K
 +(v\bmod(K-1))+1。 
]
 9. 从递归计算的基本情况开始，以相反的顺序应用这些映射，直到恢复原始 (N)。 结果值为 (F(N,K))。 
10. 最后将相对获胜者除以实际起始票数。 如果 (F) 从零开始，则答案为

 [
 ((S-1+F)\bmod N)+1。 
]

 ### 为什么它有效

不变量是 (F(N,K)) 始终描述相对于当前彩票的获胜者，而不是相对于彩票 1。对于 (N>K) 和 (K\ge2)，前 (m) 次淘汰恰好是 (K) 的倍数，这些淘汰之后的当前彩票是 (mK-1)。 剩余的票保留其循环顺序，因此从新的当前票来看，游戏的其余部分恰好是一个 (F(N-m,K)) 实例。 映射公式以精确的循环顺序枚举那些剩余的彩票，因此它将递归相对位置转换回原始位置，而不改变获胜者。 基础模拟是精确的，每一个较大的实例都被缩减为一个较小的有效实例，这证明了最终的位置是真正的幸存者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def relative_winner(n, k):
    if k == 1:
        return 0

    frames = []

    while n > k:
        m = (n - 1) // k
        tail = n - m * k
        frames.append((n, m, tail))
        n -= m

    # n <= k, so direct simulation is tiny.
    circle = list(range(n))
    cur = 0

    while len(circle) > 1:
        size = len(circle)
        target = (cur + k) % size
        circle.pop(target)

        size -= 1
        cur = (target - 1) % size

    winner = circle[0]

    # Restore the positions removed by the batch steps.
    for n, m, tail in reversed(frames):
        if winner == 0:
            winner = m * k - 1
            continue

        u = winner - 1

        if u < tail:
            winner = (m * k + 1 + u) % n
        else:
            v = u - tail
            winner = (v // (k - 1)) * k + (v % (k - 1)) + 1

    return winner

def solve(reader=input):
    t = int(reader())
    out = []

    for _ in range(t):
        n, s, k = map(int, reader().split())
        f = relative_winner(n, k)
        answer = (s - 1 + f) % n + 1
        out.append(str(answer))

    return "\n".join(out)

if __name__ == "__main__":
    sys.stdout.write(solve())
```这`relative_winner`函数故意将实际的起始票与递归计算分开。 在函数内部，位置 0 始终表示当前票据，这使得每次归约独立于 (S) 的原始值。 

对于（K=1），相对于起始票的答案立即为零。 这种特殊情况是必要的，因为被消除的票证的前一个票证可能已经消失，因此 (K\ge2) 的批处理参数不适用。 

对于较大的 (N)，每一帧都存储重建一次缩减所需的信息。 数量`m`是批次中移除的 (K) 的倍数，而`tail`是剩余的票数`m * k + 1`通过（N）。 

剩下的小实例是用 Python 列表模拟的。 模拟使用`target = (cur + k) % size`，因为规则规定移动 (K) 个幸存的票，而不是将当前票算作第一次移动。 移除后，`(target - 1) % size`选择幸存的前任。 Python 的取模行为在这里很有用，因为`-1 % size`正确给出最后一个索引。 

重建期间，`winner == 0`意味着递归获胜者正是新的当前票，`m * k - 1`。 否则，`winner - 1`计算递归获胜者在当前票证之后的序列中的位置。 第一个`tail`位置形成一个部分块，其后面的所有内容都被分为 (K-1) 个非 (K) 倍数的块。 

Python 整数具有任意精度，因此高达 (10^{18}) 的值不需要特殊的溢出处理。 该实现还避免了递归，这使调用堆栈保持不变并使 (O(K\log N)) 减少显式化。

 ## 边缘情况

 对于 (N=1)，输入`1 1 10`立即进入一个单元的小圆模拟。 不执行消除，因此返回位置 0 并转换回票证 1。该算法从不尝试计算空列表中的前趋。 

对于 (K=1)，考虑`5 3 1`。 从票证 3 中，票证 4 被删除，然后是票证 5，然后是票证 1，然后是票证 2。票证 3 保留下来。 该算法为每个 (N) 返回相对位置 0，最后的移位将其直接转换为 (S=3)。 这可以避免在其前身假设为假的情况下应用 (K\ge2) 批处理公式。 

对于完全返回到当前票证的移动，请考虑`2 1 2`。 相对于票证 1，移动两张幸存的票证再次到达票证 1，因此票证 1 被移除。 票 2 是唯一剩余的票并且获胜。 基础模拟计算目标指数`(0+2)%2=0`，将其删除，留下相对获胜者 1。最终答案是 2。 

对于删除的车票会改变距离的含义，请考虑`4 1 2`。 首先删除票证 3。 下一个当前票证是 2，并且移动两个幸存票证会到达票证 1，而不是票证 4，因为幸存序列是 2、4、1。该算法从不使用原始 ID 差异来表示移动。 它的批量缩减首先显式地删除 (K) 的倍数，然后通过压缩的幸存序列映射位置。 

对于情况 (N=S=K=5)，输入`5 5 5`从票证 5 开始。五个幸存票证的第一步返回到票证 5，因此将其删除。 然后，该过程围绕剩余的四张票继续进行，最终留下票 1。小圆模拟直接处理此问题，因为 (N\le K)，避免假设第一批包含至少一个 (K) 的完整倍数。 

对于最大值（N=10^{18}），输入`1000000000000000000 1000000000000000000 1`由 (K=1) 快捷方式处理并立即返回起始票证。 更一般地，归约仅使用整数除法、乘法、加法和对以 (10^{18}) 的小倍数为界的值取模，所有这些 Python 都能准确处理而不会溢出。
