 ## 问题理解

 迭戈波利斯正好有 (N=5{,}000{,}000) 个人。 每个人独立地以概率 (1/2) 幸存下来。 令 (X) 为幸存者数量，因此 (X) 服从参数为 (N) 和 (1/2) 的二项分布。 

对于每个测试用例，我们都会给出一个阈值 (K)，并且需要至少 (K) 个人幸存的概率：

 [
 P(X\ge K)。 
]

 答案不需要为浮点概率。 相反，我们采用模运算 (M=10^9+7)，将除法视为模逆的乘法。 最初的问题将人口固定为 500 万，并允许最多 (10^5) 次查询。 

(N) 的大小是关键约束。 即使对每种可能结果执行少量工作的计算也已经执行了大约 500 万次操作，这一次是合理的，但单独为 (10^5) 查询执行此操作将是大约 (5\times10^{11}) 工作，并且完全不可行。 排除任何为每个查询独立显式计算二项式和的方法。 我们需要让所有查询共享昂贵的工作。 

在几种边界情况下，粗心的实施可能会失败。 对于(K=0)，事件是确定的，因此答案正是(1)。 例如，```
1
0
```必须产生```
1
```即使正式声明的下限为 (K\ge1)，因为样本本身包含 (K=0)。 

在另一个极端，(K=N) 意味着每个人都必须生存。 因此答案很简单

 [
 \frac{1}{2^N}。 
]

为了```
1
5000000
```答案是（195206359），如样本所示。 意外计算 (P(X>K)) 而不是 (P(X\ge K)) 的解决方案将在此处返回零。 

阈值 (K=1) 是另一个有用的边界。 它的补充是没有人幸存的事件，所以

 [
 P(X\ge1)=1-\frac1{2^N}。 
]

 对于这个问题就是（804793649）。 如果实现在 (K=1) 处开始累积总和，但忘记了零幸存者的概率，那么这种情况就会出错。 

## 方法

 直接法是直接从二项式分布得出的。 恰好 (k) 个幸存者有概率

 [
 P(X=k)=\binom Nk\frac1{2^N}。 
]

 因此，要求至少 (K) 个幸存者的查询可以通过求和来回答

 [
 \sum_{k=K}^{N}\binom Nk\frac1{2^N}。 
]

 这是正确的，因为可能的幸存者计数是互斥的并且涵盖了所有结果。 问题在于重复工作量。 如果查询要求 (K=1)，我们将处理大约 500 万个术语。 对 (10^5) 个查询执行此操作最多会得到 (5\times10^{11}) 个术语，远远超出了一秒的限制。 

关键的观察结果是二项式概率不是独立值。 连续项有一个简单的比率：

 # \frac{\binom Nk}{\binom N{k-1}}

 \frac{N-k+1}{k}。 
]

 因此，一旦我们知道零幸存者的概率，

 [
 P(X=0)=\frac1{2^N},
 ]

 我们可以使用一个模乘法和一个模逆来生成每个后续概率。 

关于查询还有另一个有用的观察结果。 如果我们对 (K) 的所有查询值进行排序，我们可以在保持尾部概率的同时从最小阈值移动到最大阈值。 假设我们目前知道

 [
 S_k=P(X\ge k)。 
]

 然后

 [
 S_{k+1}=S_k-P(X=k)。 
]

 因此，将阈值向前移动 1 只会花费当前的概率质量。 在所有查询中，我们不需要多次遍历分布，直到最大请求 (K)。 

剩下的问题是如何获得所有模逆 (1^{-1},2^{-1},\ldots,m^{-1})，其中 (m) 是最大查询阈值。 因为 (m<10^9+7)，每个分母都是模 (M) 可逆的。 我们可以使用以下方法在线性时间内生成倒数

 M-\左\lfloor\压裂 Mi\右\rfloor
 \operatorname{inv}[M\bmod i]\pmod M.
 ]

 对于Python来说，存储500万个普通整数会消耗太多内存，因此实现使用`array('I')`，它将每个模值存储在四个字节中。 因此，500 万个条目大约需要 20 MB。 

蛮力方法和优化方法可以总结如下。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(NT)) | (O(1)) | (O(1)) | 太慢了|
 | 最佳 | (O(N+T\log T)) | (O(N+T)) | 已接受 |

 ## 算法演练

 1. 阅读所有查询并记住它们原来的位置。 对查询进行排序可以让我们按照 (K) 的递增顺序回答它们，因此每个二项式概率仅生成一次。 
2. 令(m)为所查询的最大的(K)。 没有理由生成超过 (m) 的概率，因为没有查询询问更大的阈值。 
3. 构建从 (1) 到 (m) 的模逆。 由于 (m<10^9+7)，该范围内的每个整数都有一个模逆。 
4. 计算

 [
 p_0=P(X=0)=2^{-N}\pmod M。 
]

 Python的三参数`pow`有效地计算模幂，因此不需要迭代 (N) 次。 

1. 初始化尾部概率

 [
 S_0=P(X\ge0)=1。 
]

 还保留`cur = 0`和`p = p_0`， 在哪里`p`表示 (P(X=\text{cur}))。 

1. 处理排序后的查询。 如果下一个查询要求 (K)，则重复从`cur`至（K）。 每次移动时，从当前尾部减去 (P(X=\text{cur}))，递增`cur`，并生成新的概率

 P(X=\text{cur}-1)
 \frac{N-\text{cur}+1}{\text{cur}}。 
]

 在递增之前进行减法的原因是，通过删除 (X=cur) 处的概率质量，(P(X\ge cur)) 恰好变为 (P(X\ge cur+1))。 

1.一次`cur == K`，维持的尾部恰好是 (P(X\ge K))。 将其存储在原始查询位置。 
2. 按输入顺序而不是排序顺序打印答案。 重复的阈值不需要特殊处理，因为它们只是从相同的维护状态中得到回答。 

### 为什么它有效

 不变量是在用阈值回答查询之前`cur`,`tail`等于 (P(X\ge cur))，而`pmf`等于 (P(X=cur))。 从 (cur) 移动到 (cur+1) 恰好减去了必须从尾部消失的一个概率质量，因此不变量仍然为真。 复发为`pmf`产生精确的下一个二项式概率，因为连续二项式系数具有比率 ((N-k+1)/k)。 由于不变量以 (P(X\ge0)=1) 和 (P(X=0)=2^{-N}) 开头，因此每个请求的尾部概率都是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from array import array

MOD = 1_000_000_007
N = 5_000_000

def solve():
    t = int(input())
    queries = [int(input()) for _ in range(t)]

    indexed = sorted(enumerate(queries), key=lambda x: x[1])
    max_k = indexed[-1][1]

    # inv[i] = modular inverse of i modulo MOD.
    inv = array('I', [0]) * (max_k + 1)
    if max_k >= 1:
        inv[1] = 1
        for i in range(2, max_k + 1):
            inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

    # P(X = 0) = 1 / 2^N.
    pmf = pow(pow(2, N, MOD), MOD - 2, MOD)

    # tail = P(X >= cur)
    cur = 0
    tail = 1

    ans = [0] * t

    for idx, k in indexed:
        while cur < k:
            # Remove P(X = cur), so tail becomes P(X >= cur + 1).
            tail -= pmf
            if tail < 0:
                tail += MOD

            cur += 1

            # P(X = cur) =
            # P(X = cur - 1) * (N - cur + 1) / cur
            pmf = pmf * (N - cur + 1) % MOD
            pmf = pmf * inv[cur] % MOD

        ans[idx] = tail

    sys.stdout.write('\n'.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```首先生成逆数组，因为从 (P(X=k-1)) 到 (P(X=k)) 的每次转换都需要除以 (k)。 重复避免调用`pow(k, MOD-2, MOD)`五百万次，这太贵了。 

初始概率计算为 (2^{-N})。 代码使用费马小定理将其写为 (2^N) 的逆。 由于 (M) 是素数，

 [
 (2^N)^{-1}\equiv (2^N)^{M-2}\pmod M。 
]

 主循环维护证明中描述的两个量。`tail`从 1 开始，因为每个可能的幸存者计数至少为零。`pmf`从 (P(X=0)) 开始。 减去后`pmf`，阈值增加，并且递归生成属于该新阈值的概率。 

减法以模 (M) 进行。 Python 整数不会溢出，但是`tail`模减法后可能会变成负数，因此代码添加`MOD`必要时。 

查询排序也很重要。 如果没有它，从 (K=4{,}000{,}000) 回到 (K=2) 将需要重建分布或维护额外的信息。 通过排序查询，`cur`只会增加，因此分布转换的总数最多为 (m)。 

这`array('I')`表示是 Python 特定的内存优化。 普通的 Python 整数会带来大量的对象开销，500 万个这样的整数将接近或超过 256 MB 内存限制。 四字节无符号条目使逆表大小接近 20 MB。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(N+T\log T)) | 最多 (N) 个逆向或概率转换，加上对 (T) 个查询进行排序 |
 | 空间| (O(N+T)) | 逆表使用 (O(N)) 紧凑整数，查询和答案使用 (O(T)) |

 这里 (N=5{,}000{,}000) 和 (T\le100{,}000)。 昂贵的部分是 500 万线性的，而不是每个查询 500 万线性的。 紧凑的逆数组将内存使用量保持在 256 MB 以内，而仅排序 (10^5) 查询相对较小。 官方问题给出了 1 秒限制和 256 MB 内存限制，因此在所有查询之间共享分布扫描至关重要。
