 ## 解决方案
 ## 问题理解

 加密的消息不是数字的任意集合。 正好有 (2^N) 个值，每个值对应原始 (N) 个字符代码的每个子集。 如果原始字符代码为 (x_1,x_2,\ldots,x_N)，则传输的数组包含所有可能的和

 [
 \sum_{i\in S}x_i
 ]

 对于每个子集（S）。 该数组已排序，因此其第一个值始终为 (0)，对应于空子集。 

任务是从这些子集和中恢复原始（N）个字符代码。 恢复的代码必须以非递减 ASCII 顺序打印为字符。 由于原始字符是字母数字，因此每个恢复的值对应于有效的数字或字母。 

边界 (N\leq20) 是中心约束。 最大输入中有 (2^{20}=1,048,576) 个子集和，因此每个传输的数字大约有一次操作的算法是现实的。 尝试每个可能的原始单词的算法是完全不可能的，甚至通过整个 (2^N) 元素数组重复执行线性搜索的方法也可以达到大约 (2^{2N}) 的工作。 最大子集总和仅为 (20\cdot122=2440)，因为最大的字母数字 ASCII 值为 122。这个小值范围为我们提供了特别有用的频率数组表示。 

在一些边缘情况下，粗心的实施会失败。 最小的情况是```
1
65
```唯一的子集和是 (0) 和 (65)，因此正确的输出是`A`。 假设总是存在一对非空子集和的解码器可以超出数据的末尾。 

重复的字符代码也是可能的。 例如，```
3
0 65 65 65 130 130 130 195
```来自`AAA`，所以正确的输出是```
AAA
```将子集和存储在集合中而不是保留其多重性的解码器会丢失 (65) 出现 3 次的事实，并且无法正确重建单词。 

即使字符代码不同，不同的子集也可以产生相同的和。 考虑```
3
0 48 49 97 97 145 146 194
```原码为(48,49,97)，对应`01a`。 (97) 的两次出现是不同的子集，即 ({97}) 和 ({48,49})。 将加密值视为不同的数字而不是多重集会默默地破坏此信息。 

字符范围还包括数字。 例如，```
3
0 48 122 122 170 170 244 292
```来自`0zz`。 假设每个恢复值都是大写或小写字母的解码器将拒绝有效答案。 

## 方法

 直接的暴力方法可以尝试每个可能的原始单词，生成其子集和，对它们进行排序，并将结果与输入进行比较。 有 62 个可能的字母数字字符，因此即使在利用所需的排序顺序之前，(N=20) 处也有 (62^{20})、大约 (7.0\cdot10^{35}) 候选单词。 为每个候选生成 (2^{20}) 子集和使得这种方法超出时间限制许多数量级。 

有一种更加结构化的方法来反转加密。 假设一些字符代码已经被恢复，令`subsets`包含由这些恢复的代码形成的所有子集和。 最初没有恢复任何代码，因此`subsets`仅包含 (0)。 

查看尚未消耗的最小子集和。 由于每个字符代码都是正数，因此最小的该值必定是下一个未恢复的字符代码。 一旦该代码为(x)，则可以通过添加(x)来扩展由恢复的代码形成的每个子集。 如果先前的子集和是(s)，则对应的新子集和是(s+x)。 因此，我们确切地知道哪些值必须从剩余的加密多重集中删除：每个 (s+x) for (s) in`subsets`。 

删除这些值后，可以通过将每个 (s+x) 附加到`subsets`。 重复该过程直到恢复了(N)个字符代码。 

剩下的问题是如何有效地查找和删除值。 诸如哈希映射之类的通用多重集可以工作，但是这个问题给了我们一个更强的属性：每个子集总和都位于 (0) 和 (2440) 之间。 我们可以将每个可能和的重数存储在频率数组中。 然后，找到最小的剩余值只需要一个指针从左到右移动最多 2440 个位置，并且删除一个值是一个常数时间的数组递减。 

暴力重建会失败，因为每次所需的删除都可能需要搜索庞大的列表。 通过观察总和范围很小，我们可以用直接索引替换这些搜索，从而将整个重建减少到 (O(2^N)) 操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对可能的单词进行暴力破解 | (O(62^N 2^N)) | (O(2^N)) | 太慢了|
 | 对每个删除进行线性搜索 | (O(4^N)) | (O(2^N)) | 太慢了|
 | 频率阵列重建​​ | (O(2^N + 2440)) | (O(2^N + 2440)) | 已接受 |

 ## 算法演练

 1.读取(N)和(2^N)个加密子集和。 不要依赖它们的排序顺序，而是计算每个和在频率数组中出现的次数`freq`。 由于每个总和最多为 2440，因此该数组仅需要 2441 个条目。 
2. 初始化`subsets = [0]`。 这表示可以从迄今为止恢复的字符代码形成的所有子集和。 在恢复任何内容之前，唯一的子集是空子集。 
3. 保留指针`ptr`最初为零。 推进它同时`freq[ptr]`为零。 第一个具有正频率的位置是尚未由已恢复的字符解释的最小子集和。 
4. 采取`x = ptr`作为下一个字符代码。 这样做的原因是积极性。 每个未恢复的字符都是正的，因此必须通过恰好取一个新字符且没有先前恢复的字符来获得最小的未解释子集和。 
5.让`old_len = len(subsets)`。 对于每一个`old_len`现有子集和`s`, 递减`freq[s + x]`。 这些正是包含新恢复的字符的子集和`x`并以其他方式使用已恢复字符的任何子集。 
6. 附加每个`s + x`到`subsets`。 经过这次操作后，`subsets`包含从所有恢复的字符代码中可以获得的每个子集和，因此它代表下一次迭代所需的新状态。 
7. 准确重复前面的步骤 (N) 次。 将每个恢复的整数转换为字符`chr`并将它们连接起来。 重建自然地产生非降序的代码，因此不需要额外的排序。 

### 为什么它有效

 不变量是恢复(k)个字符代码后，`subsets`恰好包含由这些代码形成的 (2^k) 子集和，而`freq[v]`记录原始加密多重集中有多少次出现 (v) 尚未被这些恢复的代码解释。 

最初，不变量成立，因为没有恢复任何代码，并且唯一的子集和为零。 假设在恢复下一个代码之前它成立。 最小的未解释总和必须是最小的剩余原始字符代码，因为包含该字符的每个其他未解释子集至少与字符本身一样大，并且使用两个或更多正未恢复值的每个子集仍然更大。 称这个值为(x)，包含(x)的子集恰好是(s+x)，其中(s)是已经恢复的代码的子集和。 精确地删除那些出现的情况会精确地留下不包含 (x) 的子集和。 将相同的 (s+x) 值附加到`subsets`添加 (x) 后创建所有子集和。 因此，每次迭代时都会保留不变量，并且在 (N) 次迭代之后，每个原始字符代码都已恢复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = 1 << n

    sums = list(map(int, input().split()))

    # Every original character is alphanumeric, so its ASCII value is
    # at most 122. With at most 20 characters, every subset sum is <= 2440.
    freq = [0] * 2441
    for x in sums:
        freq[x] += 1

    # The input array is no longer needed.
    del sums

    # All subset sums generated by the characters recovered so far.
    subsets = [0]

    answer = []
    ptr = 0

    for _ in range(n):
        while ptr <= 2440 and freq[ptr] == 0:
            ptr += 1

        x = ptr
        answer.append(chr(x))

        old_len = len(subsets)

        # Remove all subset sums that contain the newly recovered value x.
        for i in range(old_len):
            s = subsets[i]
            freq[s + x] -= 1

        # Add those sums to the set of subset sums of recovered values.
        for i in range(old_len):
            subsets.append(subsets[i] + x)

    print("".join(answer))

if __name__ == "__main__":
    solve()
```输入首先被转换为`freq`，保留多样性而不仅仅是成员资格。 这是至关重要的，因为加密数组是多重集，并且许多不同的子集可能出现相同的总和。 

这`subsets`数组从零开始，因为空子集始终可用。 如果当前有 (k) 个恢复值，则其大小恰好为 (2^k)。 当有新值时`x`找到后，代码首先记住旧的大小。 该边界是必要的，因为仅应使用旧的子集和来生成`s + x`。 迭代列表，同时附加到列表而不修复`old_len`将在同一迭代中处理新创建的总和并生成不正确的额外值。 

频率递减发生在附加新的总和之前。 这直接从不变量得出：新生成的和正是由新恢复的字符解释的事件。 

指针仅向前移动。 一次`freq[v]`达到零后，任何后续操作都无法使该特定值再次变得无法解释，因为每个操作仅消耗加密的子集和。 由于最大可能总和为 2440，因此指针总共最多执行 2441 次迭代。 

Python 整数不存在固定宽度整数实现可能存在的溢出问题，尽管所有实际子集总和已经以 2440 为界。最大的结构是`subsets`，最多包含 (2^{20}=1,048,576) 个整数。 

## 工作示例

 ### 示例 1

 加密数组开头为```
0 66 101 101 114 121 167 167 180 187 ...
```第一个非零未解释值是 66，所以第一个字符是`B`。 删除 66 后，下一个无法解释的值是 101，给出`e`。 相同的值再次出现作为下一个字符，因为原始单词包含两个`e`人物。 

| 步骤| 选择代码 | 选择的角色 | 尺寸为`subsets`步骤后| 新解释的金额 |
 | ---| ---| ---| ---| ---|
 | 开始| 0 | | 1 | 0 |
 | 1 | 66 | 66 乙| 2 | 66 | 66
 | 2 | 101 | 101 电子| 4 | 101、167 |
 | 3 | 101 | 101 电子| 8 | 101、167、202、268 |
 | 4 | 114 | 114 r | 16 | 16 114、180、215、281、215、281、316、382 |

 恢复的代码是（66,101,101,114,121），转换为`Beery`。 重复的101自然会被处理，因为`freq[101]`第一次之后保持积极`e`已恢复。 

### 构造示例 2

 考虑角色的三个副本`A`，其 ASCII 码为 65。```
3
0 65 65 65 130 130 130 195
```重建的行为如下。 

| 步骤| 选择代码 |`subsets`之前| 删除总和 |`subsets`之后|
 | ---| ---| ---| ---| ---|
 | 1 | 65 | 65 [0]| 65 | 65 [0, 65] |

 最终的答案是`AAA`。 该迹线显示了为什么频率不能用一组来替换。 在最后一步，完整的加密数组中出现了 3 个独立的 130，对应于三个二元素子集。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(2^N + 2440)) | 在所有迭代中，处理的旧子集和的数量为 (1+2+\cdots+2^{N-1}=2^N-1)，而指针最多扫描 2441 个值。 |
 | 空间| (O(2^N + 2440)) |`subsets`最多有 (2^N) 个元素并且`freq`有 2441 个条目。 |

 对于 (N=20)，重建执行少于 1,048,576 次子集更新，再加上固定 2441 个值范围的扫描。 这对于 3 秒的限制是合适的。 频率数组也比 Python 更节省内存`Counter`包含潜在的数十万个字典条目。

## 边缘情况

 对于 (N=1)，输入```
1
65
```开始于`freq[0]=1`和`freq[65]=1`。 由于空子集不是字符，指针会跳过零，然后选择 65。`subsets`最初仅包含零，因此恰好删除了一次出现的 65。 输出是`A`。 该循环只执行一次，因此不会尝试访问不存在的第二个字符。 

对于重复的字符代码，请考虑```
3
0 65 65 65 130 130 130 195
```第一个选择的值是 65。该算法消耗一次 65 的出现并创建子集和`[0,65]`。 下一个最小的剩余值仍然是 65，因此算法正确地选择了另一个`A`。 它消耗一个 65 和一个 130，然后将子集列表扩展为`[0,65,65,130]`。 第三次迭代再次选择 65 并消耗剩余的 65、两个 130 值和 195。结果是`AAA`。 频率数组使重复值变得可区分。 

对于不同子集产生的相等子集和，使用```
3
0 48 49 97 97 145 146 194
```第一个恢复的代码是48。第二个是49，它消耗了49和97，因为现有的子集和是0和48。此时仍然出现一次97。 第三个恢复的代码是 97。它使用四个现有子集和消耗 97、145、146 和 194。 结果是`01a`。 这说明了为什么该算法跟踪计数而不是简单地删除不同的值。 

对于字母数字边界情况，```
3
0 48 122 122 170 170 244 292
```第一个恢复的值是 48，它成为字符`0`。 下一个值为122，被选择了两次。 输出是`0zz`。 频率数组支持整个允许的总和范围，包括最小的数字代码和最大的小写字母代码。 

最大情况有 (N=20)，所以`subsets`最终包含 (1,048,576) 个值。 即使每个原始代码都是 122，算法也不会分支或回溯。 在每次迭代中，最小剩余值再次为 122，并且频率计数正确地编码了子集和的二项式重数。 经过二十次迭代后，正好二十次`z`字符已被恢复。
