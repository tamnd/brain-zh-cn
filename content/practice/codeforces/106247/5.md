 ## 解决方案
 ## 问题理解

 该问题对高度的完全二叉树进行建模`h`。 根任务一开始就可用。 每一秒，我们都有`p`处理器，每个处理器可以完成一项当前可用的任务。 当一项任务完成后，它的子任务就可以在接下来的几秒钟内使用。 目标是找到完成整棵树所需的最少秒数。 

关键的困难在于任务不限于单一级别。 先前级别未完成的任务可以与稍后新解锁的任务一起处理。 树结构创建了不断增长的可用任务供应，而处理器决定了我们消耗该供应的速度。 

高度足够大以至于不可能构建整棵树。 完全二叉树的高度`h`有大约`2^h`节点，因此任何模拟每个节点的方法很快就会变得不可用。 我们需要处理每个深度的节点数量而不是节点本身。 由于高度足够小，可以迭代各个级别，因此基于`h`是预期的方向。 

一个常见的错误想法是在进入下一关之前完全完成一个关卡。 例如，如果有三个处理器和一棵高度为三的树，则在处理根之后有两个任务。 下一秒完成这两个任务并创建另外四个任务。 在接下来的一秒中，这四个任务中的三个可以被处理，而剩下一个。 剩余的任务可以与更深层次的任务结合起来。 丢弃这些剩余信息的逐级模拟给出了错误的答案。 

当某个级别的任务数量恰好可以被处理器数量整除时，就会出现另一种边缘情况。 对于输入：```
1
3 2
```输出是：```
4
```粗心的实现可能会多算一秒，因为即使没有未完成的工作，它也会保留剩余的时间。 该树总共需要七个任务。 处理器按大小一、二和四的组处理它们，但最后两个级别可以通过可用任务重叠，从而产生至少四秒的时间。 

第二种边缘情况是当前级别上的处理器数量多于节点数量。 对于输入：```
1
3 10
```输出是：```
3
```处理器无法使根的子节点更早出现，因此前两秒是由树依赖性强制的。 之后，剩下的所有任务就可以一起完成了。 将处理器视为能够跳过依赖结构将产生不可能的答案。 

## 方法

 直接的暴力方法是模拟树。 我们保留一个可用节点的队列，最多处理`p`每秒节点，并将其子节点添加到队列中。 这是一个正确的模型，因为它遵循过程的精确规则。 

问题在于节点数量。 完全二叉树呈指数增长，因此模拟大约需要`2^h`运营。 甚至在内存成为问题之前，运行时间对于高高度来说就变得太大了。 

重要的观察结果是相同深度的节点表现相同。 我们不关心哪个特定节点可用。 我们只需要知道有多少任务正在等待。 在深度`i`， 确切地`2^i`如果处理了前一个级别，则会创建新任务。 唯一需要的额外信息是早期级别未完成任务的数量。 

我们按级别处理树，同时保持剩余量。 在每个级别，新的可用工作是在该深度创建的节点加上剩余的工作。 我们使用尽可能多的完整处理器组，并将剩余部分继续使用。 这是可行的，因为每个未完成的任务都永远可用，因此它始终相当于新创建的任务以供将来处理。 

层数仅为`h`，因此整个模拟在高度上变得线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^h) | O(2^h) | O(2^h) | O(2^h) | 太慢了|
 | 最佳 | O(h) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 开始于`left = 0`和`answer = 0`。 变量`left`表示在当前级别之前创建但尚未处理的任务。 
2. 从根层到最后一层迭代树的每个深度。 在深度`i`，添加新任务的数量，即`2^i`，到剩余金额。 
3. 如果可用任务在一秒的处理时间内，计算该秒并删除所有可用任务。 否则，添加所需的完整处理器批次的数量并保留余数。 
4. 处理完所有关卡后，如果有些任务仍在等待，请添加最后一秒来完成它们。 

为什么有效：在每个深度，算法都会准确存储可用但未完成的任务。 没有任务消失，因为剩余的任务会被结转。 每一步处理的量是该深度可能的最大量，因此剩余的工作是可能的最小未完成工作。 在最终级别之后，所有剩余任务都没有子级，这意味着它们可以在没有任何依赖性限制的情况下完成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    h, p = map(int, input().split())

    ans = 0
    left = 0
    nodes = 1

    for _ in range(h):
        cur = nodes + left
        ans += cur // p
        left = cur % p
        if cur % p:
            ans += 1
            left = 0
        nodes *= 2

    if left:
        ans += 1

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```该代码仅保留两个状态。`nodes`是当前级别创建的任务数量，以及`left`存储先前级别未完成的任务。 

每个级别循环运行一次。 在循环内部，除以`p`计算所有处理器都忙碌时的完整秒数。 余数是不适合那些完整秒数的量。 余数立即被清除，因为在计算完部分秒后，那些任务也完成了。 

乘以 2 会更新下一级的节点数。 Python 整数避免了这里的溢出问题，并且迭代次数足够小，计算仍然高效。

import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        h, p = map(int, sys.stdin.readline().split())
        ans = 0
        left = 0
        nodes = 1
        for _ in range(h):
            cur = nodes + left
            ans += cur // p
            left = cur % p
            if left:
                ans += 1
                left = 0
            nodes *= 2
        if left:
            ans += 1
        return str(ans)

    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        out.append(solve())

    sys.stdin = old
    return "\n".join(out)

 ## 边缘情况

 对于单节点树：```
1
1 1
```该算法从一项可用任务开始。 它花了一秒钟的时间来处理它，并且不存在新的级别。 答案是`1`。 

对于处理器过多的情况：```
1
3 10
```第一个级别创建一个任务，第二个级别创建两个任务，最后一个级别创建四个任务。 处理者可以立即完成每个可用的组，但它们不能在父母之前处理孩子。 三个依赖层需要三秒钟。 

对于剩下的场景：```
1
5 3
```在某些级别之后，创建的任务数量大于处理器容量。 该算法将未完成的任务存储在`left`，将它们添加到下一级的新任务中，并一起处理。 这种情况打破了幼稚的逐级解决方案。
