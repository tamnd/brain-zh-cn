 ## 解决方案
 ## 问题理解

 我们被要求计算配对方式的数量$2n$点排列在一条直线上，使得每对线段要么一个线段完全位于另一个线段内，要么两个线段长度相等。 这些点只是简单地编号$1$通过$2n$，因此它们的坐标是固定且不同的。 输入给出$n$，我们需要输出良好配对的模数$998244353$。 

对于约束条件，$n$可以达到$10^6$，这排除了任何显式枚举所有配对的解决方案。 总配对数为$2n$点是$(2n)!/(2^n n!)$，其增长速度超过指数，因此暴力检查是不可行的。 我们需要一个$O(n)$或者$O(n \log n)$方法。 小的$n$喜欢$1$或者$2$是结构最小的极端情况，如果假设每个段都必须存在嵌套段，则很容易错误计算$n$。 

非明显的边缘情况包括$n = 1$，这通常只有一个好的配对，并且$n = 2$，其中允许的段长度结构强制配对必须从末端对称地匹配点； 任何忽略点顺序的幼稚方法都会产生错误的答案。 例如，用点$1,2,3,4$，唯一好的配对是$(1,3),(2,4)$如果我们尝试满足内部或等长条件。 

## 方法

 暴力法会尝试所有的分区方法$2n$点成对，生成所有$n$段，并检查每对段的条件。 这需要迭代$(2n)!/(2^n n!)$配对，以及每个配对检查$O(n^2)$段比较，这在计算上是不可能的$n$一样大$10^6$。 

关键的观察是，为了实现良好的配对，所有段长度必须相等或者段必须嵌套。 如果我们想象一条线上的点，满足这一点而不发生冲突的唯一方法是将第一个点配对$n$点与最后$n$点以对称方式。 也就是说，$i$从开始的第 - 个点与$i$从末尾算起的第 - 点。 这给出了$n!$可能的配对，因为一旦我们固定了长度，我们分配这些对称对的顺序可以任意变化，并且这些段将是嵌套的或长度相等。 这将问题简化为计算$n! \bmod 998244353$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((2n)!/(2^n n!) * n^2) | O(n) | 太慢了|
 | 对称配对| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取整数$n$来自输入。 
2. 初始化变量`fact`为 1 并设置模常数`MOD`到$998244353$。 
3. 循环自$1$到$n$, 相乘`fact`通过循环索引并取模`MOD`在每一步。 这计算$n! \bmod 998244353$高效且无溢出。 
4. 打印最终值`fact`。 

为什么有效：配对第一个$n$点与最后$n$所有可能顺序中的点保证所有线段具有相同的长度或存在嵌套线段，这满足问题的良好配对条件。 这些的每一个排列$n$对称对产生有效的不同配对。 没有其他配置可以满足任意的嵌套/等长约束$n$，因此计算这些对称对的排列可以准确地给出良好配对的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
fact = 1
for i in range(1, n+1):
    fact = (fact * i) % MOD

print(fact)
```我们使用快速 I/O 并从 1 迭代到$n$，在每次乘法时取模以防止整数溢出。 Python 会自动处理大整数，但迭代取模在竞争性编程中既安全又标准。

 ## 边缘情况

 对于$n = 1$，算法正确输出`1`，因为唯一可能的配对是`(1,2)`。 为了$n = 2$，配对点对称`(1,3),(2,4)`确保段嵌套或长度相等。 阶乘计算正确迭代并在每一步应用模，如此之大$n$值例如$10^6$不会溢出并得到有效处理。 任何尝试任意配对的简单方法在这里都会失败，但阶乘捕获了问题所施加的组合结构。
