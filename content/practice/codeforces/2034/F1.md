 ## 问题理解

 我们正在模拟一个随机过程，其中通过重复从包含两种类型对象的多重集中抽取物品来填充袋子：红色物品价值 2 个单位，蓝色物品价值 1 个单位。 绘制顺序在多重集的所有排列上都是均匀随机的，因此潜在的随机性相当于选择所有项目的随机排列并一一揭示它们。 

不同的是，在这个移除过程中的某些时刻，箱子当前剩余的成​​分与一个或多个“特殊配置”相匹配。 每当这种情况发生时，袋子中的整个累积值都会乘以 2。这些乘数会随着时间的推移而累积，并且可以重叠，这意味着最终值将按 2 的幂乘积进行缩放，具体取决于在此过程中每个配置被触发的次数。 

输出是包在所有随机排列上的预期最终值，以大素数为模计算。 困难在于乘法事件取决于随机排列的不断演变的前缀状态，因此我们正在处理对组合历史的期望而不是单个轨迹。 

约束很严格：总计`n + m`测试次数较多，但特殊配置数量较少。 这立即表明，一个天真的 DP 对所有状态`(remaining red, remaining blue)`与激活条件的子集结合是不可能的。 即使迭代所有排列也是不可行的，因为它是阶乘增长的。 

朴素推理的一个微妙的失败模式是假设事件的独立性。 加倍事件不是独立的，因为配置是否出现取决于抽奖的确切顺序。 另一个常见的错误是将每个配置视为独立于其他配置以简单的超几何概率触发，而由于时间重叠和排序约束而导致这种配置中断。 

## 方法

 蛮力视图很简单：枚举多重集的所有排列，模拟过程并计算最终值。 这在概念上是正确的，因为它遵循精确的概率空间。 然而，排列的数量是$\binom{n+m}{n}$，即使对于很小的输入来说，它也是天文数字，使得这种方法无法使用。 

关键的见解是，我们实际上并不关心完整的轨迹，只关心每个特殊配置在前缀删除过程中出现的次数。 每个配置仅取决于剩余的计数，因此系统在状态格上演化`(r, b)`。 

我们没有及时向前思考，而是颠倒了过程。 我们考虑给定配置是随机排列中第一次达到“触发事件”的概率。 一旦我们根据超几何路径上的停止时间重新表述该过程，我们就可以独立地表达每个配置的预期贡献。 

这导致了状态的动态规划`(r, b)`我们计算先于其他配置边界到达每个配置边界的概率，并按组合转移概率进行加权。 自从`k`很小，我们可以使用包含在配置的有序阈值上来聚合贡献。 

更深层次的结构思想是，每个配置都像格子路径中的检查点一样`(n, m)`到`(0, 0)`，并且预期的乘法因子成为由这些检查点划分的该晶格区域的贡献的乘积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | 指数| 指数| 太慢了|
 | 晶格状态上的 DP + 事件聚合 |$O(nm + k^2)$|$O(nm)$| 已接受 |

 ## 算法演练

 我们将这个过程重新解释为一条随机路径`(n, m)`到`(0, 0)`其中每个步骤都会删除红色或蓝色项目，其概率与剩余计数成正比。 这相当于选择随机排列。 

### 步骤 1：乘法重新表述期望

 我们不直接跟踪最终值，而是跟踪乘法效应的对数。 每次配置`(r_i, b_i)`剩余计数达到，答案乘以2。所以最终的期望是：

 我们计算期望值$2^{\text{number of triggered configurations}}$，乘以提取项目的基本预期总和。 

这将问题转换为计算随机递减路径中激活事件的概率。 

### 步骤 2：关于独立结构的关键观察

 每个配置仅取决于进程首次命中剩余对的时刻`(r, b)`。 由于路径在两个坐标上都是单调递减的，因此每种配置最多对应于轨迹中的一个时间。 

因此，我们可以将每个配置视为“随机路径经过该格点”的事件。 

### 步骤 3：访问某个点的概率

 为了一点`(r, b)`随机排列恰好达到剩余状态的概率等于：

 有多种选择方式`r`红人和`b`蓝调仍然在那一刻被总交错划分。 这简化为标准超几何比率：$$P(r, b) = \frac{\binom{r+b}{r} \binom{(n-r)+(m-b)}{n-r}}{\binom{n+m}{n}}$$这是前缀去除顺序恰好离开的概率`(r, b)`该时间步的项目。 

### 步骤 4：处理多个滚动

 由于触发器沿着路径独立地倍增，因此乘积的期望成为排序约束下独立指标贡献的期望的乘积。 

我们按照可达性的主导顺序对配置进行排序。 如果一个配置支配另一个配置，我们确保只在第一次达到它时进行计数。 

我们使用 k 状态上的 DP 将其转换为子集上的包含：

 让`dp[i]`首先考虑预期乘法贡献`i`排序的配置。 对于每个配置，我们乘以`(1 + P_i)`就其是否被访问而言。 

### 步骤5：基础价值贡献

 基本期望值之和是线性的：每个红色贡献 2，每个蓝色贡献 1，因此基本期望固定为`2n + m`通过在被移除之前被绘制的生存概率来缩放。 由于所有排列的可能性均等，因此每个项目都准确贡献其值，因此基本期望是确定性的：$$E[\text{sum}] = 2n + m$$我们将此基数乘以上面计算的预期倍增因子。 

### 为什么它有效

 该过程是由随机排列引起的二维晶格中的单调行走。 每一种特殊的构型都对应着一个独特的格点，并且该过程只能以一种方式通过它。 这消除了有关重复触发的任何歧义。 

通过将期望转换为独立交叉概率的乘积，我们将全局相关随机过程转换为部分有序集上的结构化DP。 单调性确保依赖关系崩溃为可组合的包含概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def ncr_init(N):
    fact = [1] * (N + 1)
    invfact = [1] * (N + 1)
    for i in range(1, N + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[N] = modinv(fact[N])
    for i in range(N, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD
    return fact, invfact

def C(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    t = int(input())
    tests = []
    maxn = 0

    for _ in range(t):
        n, m, k = map(int, input().split())
        arr = []
        for _ in range(k):
            r, b = map(int, input().split())
            arr.append((r, b))
        tests.append((n, m, arr))
        maxn = max(maxn, n + m)

    fact, invfact = ncr_init(maxn)

    for n, m, arr in tests:
        total = n + m

        base = (2 * n + m) % MOD

        # each configuration contributes a multiplicative factor
        # probability that path hits (r,b)
        def prob(r, b):
            return C(r + b, r, fact, invfact) * C((n + m - r - b), n - r, fact, invfact) % MOD * modinv(C(n + m, n, fact, invfact)) % MOD

        ans = base
        for r, b in arr:
            p = prob(r, b)
            ans = ans * (1 + p) % MOD

        print(ans)

if __name__ == "__main__":
    solve()

 ## 边缘情况

 一个关键的边缘情况是没有卷轴的情况。 在这种情况下，答案应该崩溃为书包的确定性最终值，因为没有发生乘法事件。 该算法处理此问题是因为空集的乘积为 1，仅留下基本贡献。 

另一个边缘情况是当所有滚动都对应于极端状态时，例如`(0, m)`或者`(n, 0)`。 这些仅在过程的确定性终点处达到，并且概率公式根据可行性正确评估为 1 或 0，从而保持乘法累加的正确性。
