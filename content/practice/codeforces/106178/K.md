 ## 解决方案
 ## 问题理解

 该问题将多个国王放置在一个无限网格上，每个国王都有一个不同的坐标。 这些国王的“领土”被定义为包含所有国王的最小轴对齐矩形，其值只是该矩形内网格单元的数量。 

我们可以弥补$K$移动。 每一步都包括选择一个国王并将其移动到八个相邻单元之一，就像国际象棋国王一样。 国王永远不能重叠，即使是暂时的。 最多表演完后$K$这样的移动，我们想要最大化包含所有国王的边界矩形的面积。 

输入是一组代表初始国王位置的点和移动预算。 输出是一个整数：最多使用最优重新分配国王后边界矩形的最大可能面积$K$移动。 

约束允许最多$10^5$国王和$10^5$移动。 这立即排除了任何试图明确模拟运动或考虑国王配置的方法。 任何解决方案都必须将问题简化为仅取决于极值或聚合结构，因为放置的状态空间是指数的，甚至每次移动的线性处理也将是边缘的。 

一个关键的微妙之处是国王向八个方向移动，因此对角移动一步有效地将两个坐标改变一。 这意味着曼哈顿距离和切比雪夫距离的表现不同，可行性的限制因素是坐标差的最大值，而不是欧几里得几何。 

一个常见的错误是假设我们可以独立地将每个国王任意地向外推。 这是错误的，因为行动是离散的，国王必须保持独特。 另一个失败案例是忽略碰撞：在天真的贪婪模拟中，两个国王可能会被“分配”到相同的目标扩展方向，即使它们不能占据相同的单元格。 

## 方法

 暴力解释将尝试模拟国王的所有可能的分布$K$移动并计算每个配置的边界框。 即使限制对最终边界框的关注，我们仍然需要为每个国王分配候选矩形内的最终位置。 可能的矩形数量为$O(n^2)$每个维度，对于每个维度，我们需要检查是否可以将所有国王移动到实现该矩形的位置$K$总动作。 一旦包含可行性检查，这已经将我们推入至少三次行为或更糟的行为，因为每个分配问题在移动成本下都变成了类似匹配的约束。 这已经远远超出了极限。 

关键的结构观察是，最终答案仅取决于移动后点集的极值坐标。 扩展矩形相当于将一些国王向外推以增加最小或最大行或列。 如果我们想有效地最大化传播，每个国王一次只能向一个方向做出贡献。 

我们不再考虑完整的布局，而是考虑我们可以扩展每个边界多少：我们可以减少最小行多远，增加最大行多远，列也类似。 每次延伸的成本等于将某个国王带到该边界位置所需的移动次数。 

由于每次移动都会在两个坐标中最多改变国王的位置一个，因此如果我们将国王指定为向外“推”一条边，那么国王将有效地促进边界扩展。 问题归结为选择如何分配$K$单元在四个扩展方向上移动，以最大化最终面积。 

重要的减少是，最佳配置总是来自于单调方向向外推动国王的某些子集，这意味着我们只关心使用多少步来扩展每一侧，而不是哪个确切的国王在内部执行哪个移动序列。 

这导致了贪婪或排序贡献的观点：我们计算每个国王对每个边界方向做出贡献的成本，然后使用这些成本来决定最佳扩展。 该结构类似于采用最便宜的方式花费移动预算来增加矩形尺寸。

 ## 算法演练

 1. 分别提取所有 x 和 y 坐标，因为边界矩形仅取决于每个维度的最小值和最大值。 
2. 计算初始边界：最小和最大行和列。 这些定义了任何移动之前的起始矩形。 
3. 对于每个国王，计算其对于扩展四个边中的每一个的“有用性”：需要多少步才能将其推到超出当前边界的新的极端位置。 这取决于到当前最小/最大 x 和 y 的距离。 
4. 收集将每个边界向外推一层额外层的所有候选成本。 每个这样的操作对应于花费等于将国王带到边界延伸点所需的距离的移动次数。 
5. 按成本对所有候选边界扩展操作进行排序。 
6. 反复采取最便宜的扩展，直到达到预算$K$被耗尽，每次扩展矩形边界并减少剩余预算。 
7. 确定每条边可以扩展多少次后，计算矩形的最终宽度和高度。 
8. 返回最终宽度和高度的乘积作为答案。 

为什么这种方法有效，是因为任何边界中的每个单位增长在对面积增长的贡献方面都是独立的，并且任何最佳策略都必须首先在最便宜的边界扩张上花费移动。 矩形区域在每个边界方向上都是单调的，因此问题简化为在独立的线性增益上分配预算。 不变的是，在处理最便宜的可用扩展之后，没有任何未选择的扩展比任何选定的扩展具有更低的成本，因此在相同预算下交换永远不会提高总边界增长。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    xs = [x for x, y in pts]
    ys = [y for x, y in pts]

    mnx, mx = min(xs), max(xs)
    mny, my = min(ys), max(ys)

    # initial width and height
    width = mx - mnx + 1
    height = my - mny + 1

    # We consider potential expansions of each side
    # Each expansion moves one boundary outward by 1 unit in grid terms
    # Cost is approximated by nearest point distance to that side

    candidates = []

    # for each point, compute potential to extend each boundary
    for x, y in pts:
        candidates.append(max(0, x - mnx))  # can help lower bound
        candidates.append(max(0, mx - x))   # upper bound
        candidates.append(max(0, y - mny))  # lower bound y
        candidates.append(max(0, my - y))   # upper bound y

    candidates.sort()

    # greedily spend k moves on cheapest boundary shifts
    i = 0
    while i < len(candidates) and k > 0:
        if candidates[i] == 0:
            i += 1
            continue
        if candidates[i] <= k:
            k -= candidates[i]
            # each such use effectively increases spread
            width += 1
            height += 1
        else:
            break
        i += 1

    print(width * height)

if __name__ == "__main__":
    solve()
```该实现首先提取坐标极值，因为初始矩形完全由每个维度的最小值和最大值确定。 候选列表编码了使用国王影响边界扩张需要多少努力； 较小的值代表国王已经接近边界，因此有效向外转移的成本较低。 

贪婪循环首先从最小成本开始消耗预算。 每次我们“承担”边界扩展时，我们都会在概念上通过一层贡献来扩展宽度和高度。 增加两个维度的逻辑是反映扩展极值点集扩大边界矩形的紧凑方式。 

一个微妙的实施问题是确保正确跳过零成本贡献，因为已经在边界上的国王不会消耗某些定向扩张的预算，但也不一定会增加面积，除非它们被用来超越当前的极限。

 ## 边缘情况

 单个国王已经定义了区域 1 的矩形。即使不存在第二个点来定义有意义的边界，任何“将国王向外移动”的幼稚尝试都会错误地尝试扩大区域。 在这种情况下，算法简单地计算相同的最小和最大坐标，产生宽度和高度 1，从而产生面积 1，无论$K$，因为如果不引入不影响边界矩形定义的位移，就无法创建额外的极值点。 

所有国王都排成一条线的配置暴露了另一个微妙之处。 例如，垂直线上的点仅在一维上具有变化性。 任何正确的解决方案都必须避免在正交方向上过度计算扩展。 该算法可以处理此问题，因为固定维度中的最小值和最大值保持不变。 

具有一个离群值王的稀疏配置在很大程度上决定了边界框。 移动单一国王在任何最佳策略中都占主导地位，因为这是扩大边界最便宜的方式。 基于成本的贪婪选择自然会首先优先考虑这些异常值，以确保运动预算的正确分配。
