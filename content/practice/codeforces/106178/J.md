 ## 解决方案
 ## 问题理解

 该问题给出了一个代表人群反应流的字符串。 在该弦内，三种特定的声音模式会影响乐谱。 每次子串`ha`出现后，分数加一。 每次`boooo`出现后，分数减一。 每次`bravo`出现后，分数增加三分。 所有出现的次数（包括重叠出现的次数）都会计算在内，并且字符串的所有其他部分均无效。 任务是计算最终得分。 

输入是单个小写字符串。 输出是一个整数，即检查字符串中所有可能的起始位置后的累积分数。 

字符串长度最多为 1000，这个长度足够小，因此检查每个字符的恒定工作量很容易在限制范围内。 线性扫描是理想的选择，因为它只执行几千次操作。 即使是二次方法也可以通过这个界限，但是养成识别直接扫描的习惯是有用的，因为相同的模式出现时具有更大的限制。 

主要的实现陷阱来自重叠匹配和忘记模式可以在字符串末尾附近开始。 

例如，输入```
hahaha
```有输出```
2
```因为`ha`从位置 0、2 和 4 开始？ 实际上只检查了位置0、2、4，但是位置4后面只有一个字符，所以是无效的。 有效的出现位置是位置 0 和 2，得分为 2。如果不小心实现，在找到模式后删除匹配的文本可能会错误地丢失第二次出现。 

另一个例子是：```
brhavo
```带输出```
1
```子串`bravo`从索引 2 开始出现并贡献 3，而`ha`无处出现并且`boooo`无处出现。 仅从字符串开头进行检查的解决方案会错过稍后开始的有效模式。 

最终的边界情况是：```
booo
```带输出```
0
```该字符串看起来接近`boooo`，但它只包含三个`o`之后的字符`b`。 使用不完整长度检查的解决方案可能会意外访问无效位置或将其计为负分。 

## 方法

 最简单的方法是尝试字符串中每个可能的起始位置，并将其后面的字符与每个目标模式进行比较。 由于图案的长度是固定的，因此每个位置只需要不断的工作。 这是正确的，因为模式的每次出现都有一个唯一的起始索引，并且检查所有起始索引涵盖了每种可能性。 

强力实现将在每个位置测试三个字符串。 对于长度为 1000 的字符串，这是无害的。 如果长度很大，重复比较子串将成为不必要的工作，因为大多数位置无法匹配。 通用的子字符串搜索算法可能会有所帮助，但这里的结构提供了更简单的解决方案。 

关键的观察是模式是固定的并且只有三种。 我们不需要搜索任意的单词集合。 我们只需要检查每个位置接下来的几个字符。 一次从左到右扫描就足够了。 在索引处`i`，我们检查这三种模式中的每一种是否都从那里开始，并立即添加其贡献。 

这自然地使重叠发生。 找到匹配项后我们不会向前跳转，因此仍会检查下一个索引。

 ## 算法演练

 1. 读取反应字符串并将答案初始化为零。 
2. 迭代字符串的每个索引。 每个索引都被视为有意义的反应之一的可能开始。 
3. 如果从当前索引开始的子串是`ha`，给答案加一。 检查不得跳过未来的位置，因为重叠匹配是有效的。 
4. 如果从当前索引开始的子串是`boooo`，从答案中减一。 
5. 如果从当前索引开始的子串是`bravo`，在答案中添加三。 
6. 打印最终的累计分数。 

其原理：每一次发生的计数反应都有一个起始位置。 该算法访问每个起始位置并检查可以从那里开始的每个可能的反应。 由于它从不删除字符或跳过索引，因此重叠的出现次数会根据需要准确计数。 每一次分数的变化都对应着一次真实的发生，并且每一次真实的发生都被发现了，所以最终的值是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    ans = 0
    n = len(s)

    for i in range(n):
        if s.startswith("ha", i):
            ans += 1
        if s.startswith("boooo", i):
            ans -= 1
        if s.startswith("bravo", i):
            ans += 3

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案存储输入字符串并扫描一次。 这`startswith`函数自动执行边界处理，因此对字符串末尾附近的检查只会返回 false，而不会导致索引错误。 

这三个条件是独立的。 理论上，一个位置可以开始多个模式，因此它们是分开的`if`陈述而不是`if`和`elif`链。 

循环遍历所有有效的起始位置。 它在找到匹配项后不会停止，因为另一个匹配项可以从下一个字符开始或与当前字符重叠。

 ## 边缘情况

 对于重叠匹配，请考虑：```
hahaha
```该算法检查索引 0 并发现`ha`，将分数增加到 1。在索引 2 处，它找到了另一个`ha`，将分数增加到 2。索引 4 没有足够的字符。 结果是 2，这表明匹配项是按起始位置而不是删除匹配文本来计数的。 

对于远离开头的模式：```
brhavo
```该算法首先检查索引 0，但从那里开始没有任何反应。 在索引 2 处它发现`ha`并添加一个。 它永远不会错误地将整个字符串视为单个单词，因此答案是 1。 

对于几乎匹配的负面反应：```
booo
```在索引 0 处，算法检查`boooo`，但是字符串太短，所以检查失败。 分数不会发生变化，输出为 0。相同的边界处理适用于字符串末尾附近的每个位置。
