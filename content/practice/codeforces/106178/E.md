 ## 解决方案
 ## 问题理解

 我们维护一组盒子，每个盒子都存储正数量的口粮。 该集合随着时间的推移而变化：每次更新要么插入一个具有给定数量的新盒子，要么删除一个具有该确切数量的现有盒子。 

每次更新后，我们都会被问到一个假设性问题。 如果此时开始出现紧急情况，我们希望在最佳策略下，用最短的天数清空​​所有箱子。 每天我们都可以从两项行动中选择一项。 要么我们完全清空一个盒子，要么我们从当前非空的每个盒子中取出一份口粮。 

过程没有及时向前模拟； 相反，我们被要求在每次更新后立即计算最佳总天数。 

关键的困难在于，最佳策略取决于两个竞争行为之间的权衡。 重复使用第二个操作会同时减少所有盒子，但即使没有完全删除任何东西，也要花费一天的时间。 第一个操作是本地操作，完全删除单个框，但无助于减少其他框。 

限制很大，最多有30万次更新。 这立即排除了每次修改后从头开始重新计算答案的可能性。 任何解决方案都必须以每次操作的对数或接近对数的时间更新答案，因为即使$O(Q \sqrt{Q})$已经太慢了。 

当以天真的方式思考时，就会出现一个微妙的问题。 人们可能会尝试贪婪地模拟这两种操作，或者尝试先删除最大的盒子。 这两种方法都会失败，因为最优决策取决于值的全局分布而不是局部排序。 

例如，假设当前的框是：

 输入：```
3
1 100 101
```一个天真的想法可能会建议总是先清空最大的盒子。 简单地解释就是 1 + 100 + 1 = 102 天，但这忽略了重复使用“减少所有框”操作可能会使多个框在达到阈值后同时消失，从而改变最佳平衡。 

核心问题是，答案取决于全局阈值选择，而不是贪婪的删除序列。 

## 方法

 暴力策略会尝试所有可能的操作序列。 在每一步中，我们要么将所有框减少 1，要么完全删除单个框，然后搜索达到全零的最小天数。 即使使用记忆化，状态空间也是巨大的，因为每个盒子独立演化，并且值可以大到$10^9$。 这会发生组合爆炸，并且在非常小的情况下是完全不可行的。 

更好的观点是将过程分为两个阶段。 假设我们决定精确执行“将所有框减 1”操作$k$次。 在这些之后$k$全球减价，每盒价值最多$k$自动变空。 每个剩余的盒子仍然具有积极的内容，但此时可以通过每个盒子的一次操作将其单独删除。 

所以对于一个固定的$k$，总天数变为：$$f(k) = k + \#\{a_i > k\}$$第一项计算全局减量，第二项计算之后仍有多少个盒子存活。 

该问题简化为维护动态多重集并不断查找该函数在所有整数上的最小值$k$。 关键的结构观察是$f(k)$在离散意义上是凸的，因为$k$增加，幸存盒子的数量单调减少，而线性项稳步增加。 

这意味着最优值总是位于由数组的排序值确定的“断点”处，因此我们永远不需要考虑任意$k$，仅围绕现有框尺寸的值。 

主要困难在于在插入和删除时有效地维护这些计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解序列 | 指数| O(n) | 太慢了 |
 | 为每个查询尝试所有 k | O(nQ) | O(n) | 太慢了 |
 | 芬威克树 + k 上的二分搜索 | O(Q log² Q) | O(Q) | 已接受 |

 ## 算法演练

 1. 首先，压缩输入中出现的所有值，因为我们只关心框大小和阈值之间的比较。 这将问题减少到最多的坐标范围$3 \cdot 10^5$。 
2. 使用 Fenwick 树维护这些压缩值的频率数组。 这使我们能够快速计算有多少盒子的价值大于给定的阈值。 

我们需要的重要数量是$\#(a_i > k)$，可以从总计数减去前缀和得出。 
3. 每次更新后，我们都会重新计算最佳的可能值$k$。 由于目标仅取决于现有值的阈值，因此我们搜索压缩索引而不是原始整数。 
4. 对于候选阈值索引$i$，计算：$$f(i) = val[i] + (total\_boxes - prefix\_freq(i))$$这对应于选择$k = val[i]$，这已经足够了，因为该函数在连续的不同值之间是恒定的。 
5. 使用二分查找找到函数停止递减的点。 由于该函数是凸函数，因此斜率恰好改变一次符号，因此基于相邻值的单调条件是有效的。 
6. 评估$f(i)$围绕最佳候选并输出最小值。 

### 为什么它有效

 功能$f(k) = k + \#(a_i > k)$有一个离散斜率，由有多少元素大于$k$。 作为$k$增加，该计数只会减少，这使得斜率总体上不减少。 这保证了凸性。 凸离散函数具有单个全局最小值，并且该最小值必须出现在斜率从负过渡到非负的点处，该点始终与由输入值之一引起的边界对齐。 由于我们动态地维护正确的计数，因此每次评估$f(k)$准确反映当前的多重集，因此每一步计算的最小值始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    q = int(input())
    arr = input().split()

    vals = []
    ops = []

    for x in arr:
        x = int(x)
        if x > 0:
            ops.append((x, 1))
            vals.append(x)
        else:
            ops.append((-x, -1))
            vals.append(-x)

    vals = sorted(set(vals))
    idx = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(len(vals))
    total = 0

    def get_answer():
        if total == 0:
            return 0

        def f(i):
            prefix = fw.sum(i)
            return vals[i - 1] + (total - prefix)

        lo, hi = 1, len(vals)
        while lo < hi:
            mid = (lo + hi) // 2
            if f(mid) <= f(mid + 1):
                hi = mid
            else:
                lo = mid + 1

        best = lo
        return min(f(best), f(max(1, best - 1)))

    out = []
    for x, t in ops:
        if t == 1:
            fw.add(idx[x], 1)
            total += 1
        else:
            fw.add(idx[x], -1)
            total -= 1

        out.append(str(get_answer()))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```Fenwick 树维护每个值类中当前存在多少个框。 这使得我们能够计算在对数时间内有多少个框超过了候选阈值。 

二分搜索应用于压缩的排序值，因为目标函数仅在这些点发生变化。 每个查询都会从头开始重新计算最佳阈值，但每个评估都是$O(\log n)$，这将总复杂性控制在一定范围内。 

实现中的一个常见错误是忘记前缀和必须反映每一步的当前多重集，而不是静态快照。 另一个微妙的问题是评估$f(i)$仅在精确指数处； 在索引之间，函数是常数，因此仅检查边界就足够了。

 ## 边缘情况

 一个关键的边缘情况是所有盒子都相同。 假设我们有：

 输入：```
+10 +10 -10
```在前两次插入之后，最佳策略平衡全局减少与两个相同的大盒子。 该算法仅在值 10 处评估阈值，其中该函数反映两个框保持在任何较小的 k 之上。 当一个盒子被移除时，结构就会发生变化，使得全局减少立即变得更加有效。 

当只有一个盒子时会出现另一种边缘情况。 那么任意阈值$k$直到其值使第二项为零，并且在第一次插入后答案始终为 1。 二分搜索正确地折叠为单个候选，因为凸函数变得平坦，然后在断点后增加。 

最后一个微妙的情况是交替删除最大元素。 压缩的 Fenwick 结构可确保前缀计数正确更新，因此该算法不依赖于过时的最大值，并且始终在每次结构更改后重新计算正确的全局最小值。
