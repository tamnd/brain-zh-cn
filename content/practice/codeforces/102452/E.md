 ## 解决方案
 ## 问题理解

 我们有一个由不同整数组成的奇数长度数组。 一个操作选择三个连续的当前元素，并用它们的中值替换这三个元素，因此数组变短了两个。 三元组的选择是完全灵活的，经过((N-1)/2)次运算后，只剩下一个原始值。 

对于每个原始位置 (i)，我们需要确定是否存在某些操作序列，其中 (a_i) 是最终的幸存者。 输出是一个二进制字符串，其中字符 (i) 等于`1`正是 (a_i) 能够生存的时间。 

考虑固定候选 (x=a_i) 的有用方法是忘记确切的值。 所有其他元素仅根据其与 (x) 的关系而重要。 小于 (x) 的值变为`-1`，大于 (x) 的值变为`+1`，并且 (x) 本身变为`0`。 中值运算仅取决于这三个符号。 

官方约束允许(N\le 5000)，所有测试用例的(N)之和最多为(10^4)。 这使得 (O(N^2)) 解决方案变得实用，因为在极端分布中总工作量最多为 (10^8) 个非常简单的操作，而 (O(N^3)) 解决方案显然过于昂贵。 最初的竞赛限制是一秒，因此实现时应保持内部循环简单，并避免使用大常量的数据结构。 

有几种边缘情况很容易破坏不正确的实现。 对于（N=1），唯一的数字必须生存，所以输入`1 / 1`有输出`1`。 假设至少存在一个操作的实现可能会在这里失败。 

第二种情况是小于候选值和大于候选值的数字出现的频率相同。 例如，与`3 / 2 3 1`, 候选人`2`有一个较小的元素和一个较大的元素。 这三个元素已经具有更小、候选、更大的形式，所以`2`是中位数并且立即生存。 正确的输出是`100`。 要求候选者被同一侧的两个元素包围的方法会错误地拒绝这种情况。 

第三种情况是值顺序端点附近的候选。 为了`3 / 1 2 3`， 仅有的`2`可以生存，因为唯一可能的运算取所有三个数字的中值。 正确的输出是`010`。 对于较大的数组来说，简单地检查候选值是否全局接近中位数是不够的，因为元素的顺序还控制着可以形成哪些三元组。 

该声明保证不同的值，因此完全相等的输入不是有效的官方测试。 如果仍然提供这样的输入，基于比较的算法仍然会自然地运行，因为等于候选的每个元素都被分类为`0`。 例如，`3 / 7 7 7`会产生`111`。 这作为稳健性测试很有用，但不应该用作官方问题约束的证据。 

## 方法

 直接暴力方法是模拟每个可能的操作序列。 当有（m）个元素时，有（m-2）个可能的连续三元组。 选择一项后，还剩下（m-2）个元素，然后是（m-4）个选择，依此类推。 完整的操作序列数为

 [
 (N-2)(N-4)(N-6)\cdots 1=(N-2)!!.
 ]

 即使在考虑模拟每个序列的成本之前，这也变得巨大。 对于（N=5000），可能性的数量远远超出了任何可以列举的范围。 蛮力在概念上是正确的，因为它准确地探索了合法操作，但它没有利用大多数数字信息不相关的事实。 

关键的观察是固定一个候选者（x）并仅询问（x）是否可以生存。 通过与 (x) 的比较来替换所有其他值。 低于 (x) 的值变为`-1`，高于 (x) 的值变为`+1`，并且 (x) 变为`0`。 对于任何不包含 (x) 的三元组，其中位数的符号恰好是其三个符号的中位数。 因此，实际的幅度从问题中消失了。 官方社论正是使用了这种简化为二进制比较序列。 

假设比较序列包含更多`+1`值比`-1`价值观。 定义

 [
 S=#(+1)-#(-1)。 
]

 如果(S=0)，则两侧出现的次数相等。 在这种情况下，候选者可以被保留，而其周围的其余者则被减少，所以答案立即是肯定的。 同一个命题是对称的，当`-1`是大多数。 

有趣的情况是 (S>0)，其中`+1`是大多数。 考虑一个操作可以对 (S) 做什么。 包含两个符号的三元组有一个保留下来的多数符号，所以一个`+1`和一个`-1`消失并且差值（S）不改变。 三重`111`变成单身`1`，所以两个`+1`值消失并且 (S) 减少 2。 没有其他操作可以减少（S）。 因此，如果候选者要生存，我们必须能够创建足够的多数符号三元组以将 (S) 减少到零。 

数组顺序决定了这些多数三元组是否能够真正形成。 我们可以从左到右扫描，同时保持当前有多少未使用的大多数材料可用。 大多数元素会增加这个数量。 符号相反的元素消耗一个单位，因为可以在它周围使用两个多数元素来消除它，而不会改变总体差异。 数量决不允许变为负数。 

每当三个多数单元积累起来时，我们就可以执行`111 -> 1`减少。 这会删除两个多数元素并将 (S) 减少 2。 这种贪婪策略最大化了可以形成的多数三元组的数量，这正是我们在多数阻止 (S) 达到零时所需要的。 该社论描述了与扫描序列并使用连续多数元素来减少多数计数相同的贪婪想法。 

候选人本身就充当了障碍。 当我们减少比较序列时，操作不能简单地通过它，因此当扫描到达候选者时，可用性计数器被重置。 这也是为什么可以在一次线性扫描中执行对固定候选者的测试。 

蛮力法之所以有效，是因为它探索了每一个合法的归约，但它却失败了，因为存在类似阶乘的许多归约顺序。 观察结果表明，只有与候选者的比较才重要，从而将每个候选者简化为一维贪婪扫描。 对所有 (N) 个候选者重复该扫描会给出 (O(N^2)) 算法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (\Theta((N-2)!!)) 操作序列 | (O(N)) | 太慢了 |
 | 最佳| (O(N^2)) | (O(N)) | 已接受 |

 ## 算法演练

 1. 固定位置(i)，令(x=a_i)为候选幸存者。 对于每个位置 (j)，将 (a_j) 分类为`-1`如果 (a_j<x),`+1`如果 (a_j>x)，并且`0`当 (j=i) 时。 这准确地保留了影响中位数是否小于、等于或大于 (x) 的信息。 
2. 计算所有这些符号的总和 (S)。 由于有 (N-1) 个非零符号且 (N-1) 是偶数，因此 (S) 是偶数。 如果（S=0），立即标记候选者为可能的。 相同数量的较小和较大元素可以在候选周围配对，同时将候选保留为中位数。 
3. 如果 (S\ne0)，令`majority = sign(S)`。 多数符号是唯一必须减少计数的符号。 完全由多数符号组成的三元组是唯一改变 (S) 的运算类型，并且它会将 (S) 精确地改变为 2，趋向于零。 
4. 从左到右扫描比较序列。 维持`tp`，当前可用的大多数材料的数量。 当当前符号等于多数时，增加`tp`。 当符号相反时，减小`tp`，但永远不会低于零。 该模型使用多数元素来消除相反元素，同时保留总体差异。 
5. 什么时候`tp`达到三，花费三倍的多数元素。 减少`tp`由于三个相等多数符号被 1 代替，所以将 S 减 2，并且在零的方向上将 (S) 减 2。 如果 (S) 达到零，则候选者是可能的并且扫描可以停止。 
6. 当扫描到达候选人本身时，重置`tp`为零。 候选项不能通过用于简化两侧的操作交叉，因此候选项之前积累的大部分材料不能与其之后的材料组合。 
7. 扫描后，候选者恰好在（S=0）时是可能的。 对每个位置独立重复此测试。 

### 为什么它有效

 对于固定候选，候选同一侧的所有值对于中值运算都是可互换的，因此可以用符号序列替换原始数组。 如果两个符号出现频率相同，则可以保留候选元素，而减少其周围的其他元素。 

否则，一个标志就是绝对多数。 任何包含两个符号的操作都会删除每个符号中的一个，并使差值保持不变。 唯一能够将差值移向零的操作是三个相等的多数符号变成一个多数符号，这会将多数计数减少二。 因此，每次成功的归约都必须执行足够多的多数三元组以消除初始差异。 

贪婪地扫描最大化候选者每一侧可以形成的此类三元组的数量。`tp`记录当前可以使用的多数结构的数量，相反的符号消耗该资源的一个单位。 每当三个多数单位可用时，立即进行减少不会损害未来的减少，因为它会减少所需的多数数量并在相同的位置范围内留下一名多数代表。 在候选项处重置尊重候选项将左右部分分开的事实。 因此，当比较序列可以减少到足以使 (x) 保持最终中值时，扫描正好达到 (S=0)。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    answer = []

    for i in range(n):
        x = a[i]

        # Compare every value with the candidate.
        signs = [0] * n
        sm = 0

        for j, v in enumerate(a):
            if v < x:
                signs[j] = -1
                sm -= 1
            elif v > x:
                signs[j] = 1
                sm += 1

        # Equal numbers below and above x.
        if sm == 0:
            answer.append('1')
            continue

        majority = 1 if sm > 0 else -1
        tp = 0

        for s in signs:
            if s == 0:
                # The candidate separates the two independent sides.
                tp = 0
            elif s == majority:
                tp += 1
            else:
                tp = max(tp - 1, 0)

            # Three majority signs can be reduced to one.
            if tp >= 3:
                sm -= 2 * majority
                tp -= 2

                if sm == 0:
                    break

        answer.append('1' if sm == 0 else '0')

    return ''.join(answer)

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(solve_case(a))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    main()
```外循环选择每个可能的幸存者。 对于固定候选，第一个内循环构造比较信息并计算`sm`同时，因此不需要单独遍历来计算较小和较大的值。 

这`sm == 0`在选择多数符号之前处理案件。 这个边界是必要的，因为`sign(0)`否则将不会给出多数方向，而已知该候选人是可能的。 

什么时候`sm`是非零的，`majority`是`1`或者`-1`。 扫描使用`tp`正如上面描述的贪婪资源。 多数元素增加 1 个单位，相反元素减少 1 个单位，但不能使其变为负数。 这`max(tp - 1, 0)`是重要的。 允许`tp`变为负数会错误地让不匹配的相反元素之前的多数元素影响未来的减少。 

当三个多数单位可用时，`tp -= 2`而不是`tp -= 3`。 三个等号被一个等号取代，因此两个单位从活跃供应中消失。 同时，`sm`变化由`-2 * majority`，完全匹配多数减去少数差异的变化。 

零号是候选人本身。 重置`tp`这可以防止扫描合并来自候选人相反双方的资源。 这是实现中最微妙的边界条件。 

所有值都适合 Python 整数，事实上`sm`总是介于`-(N-1)`和 (N-1)，所以整数溢出不是问题。 

实现使用`sys.stdin.readline`并将输出累积到一个列表中，这使得 I/O 开销足够小，足以满足一秒的竞争限制。

 ### 示例 1

 输入情况是：```

```考虑候选人`3`，这是第一个元素。

| 候选人 | 符号序列| 最初的`sm`| 多数 | 最终的`sm`| 结果 |
 | --- | --- | --- | --- | --- | --- |
 | 3 |`0 -1 -1 +1 +1`| 0 | 无 | 0 |`1`|

 现在考虑候选人`1`，第二个元素。 

其比较顺序为`[+1, 0, +1, +1, +1]`。 初始差是四个较大值减去零个较小值，因此`sm=4`。 大多数是`+1`。 

| 扫描值| 标志 |`tp`步骤后|`sm`步骤后|
 | --- | --- | --- | --- |
 | 3 |`+1`| 1 | 3？ |

 | 4 |`+1`| 1 减少后 | 2 |

```两个成功的候选人是第一个和最后一个位置，与官方样本中的完全一样。

## 边缘情况

 对于单元素情况`N=1`，候选的比较序列仅包含`0`， 所以`sm=0`立即地。 算法输出`1`，这是正确的，因为没有什么可擦除的。 

为了`3 / 1 2 3`，考虑候选人`1`。 其标志是`[0,+1,+1]`, 给予`sm=2`。 大多数是`+1`，但只存在两个多数元素，所以`tp`永远不会达到三。 决赛`sm`仍然是 2，位置 1 的答案是`0`。 候选人`2`有迹象`[-1,0,+1]`， 所以`sm=0`并被接受。 候选人`3`与候选者对称`1`。 最终输出是`010`。 

为了`3 / 2 3 1`， 候选人`2`有迹象`[0,+1,-1]`。 初始差异为零，因此算法在执行扫描之前接受它。 这是最小的例子，表明候选人可以与一个较小和一个较大的邻居一起生存。 输出是`100`。 

对于一方拥有绝对多数票的候选人，例如候选人`1`在已排序的数组中`[1,2,3,4,5]`，标志是`[0,+1,+1,+1,+1]`。 我们从`sm=4`。 扫描可以形成三重`+1`，减少`sm`从四个变成两个，但剩下的两个`+1`值不能形成另一个三元组。 该算法拒绝候选人。 这抓住了一个常见的错误，即假设多数总是可以减少，只是因为它的计数具有正确的奇偶性。 

候选人的位置也是一个真正的边界。 在`[3,1,2,5,4]`， 候选人`3`位于第一个位置，因此零符号立即出现并且`tp`在处理任何其他值之前重置。 右侧仍可独立简化。 该算法不需要候选者两侧都有元素，这是必要的，因为有效的幸存者可能会开始或结束原始数组。 

最后，所有平等的情况`3 / 7 7 7`违反了官方的独特性保证，但每次与候选者的比较都会产生零。 因此`sm=0`对于每个候选者，算法都会返回`111`。 该测试对于检查实现是否意外地假设恰好有一个数组元素与候选值相等非常有用，即使官方输入确实保证了该属性。
