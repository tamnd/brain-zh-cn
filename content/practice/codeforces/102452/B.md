 ## 解决方案
 ## 问题理解

 我们有一个以节点 1 作为根的有根二叉树。 Alice 和 Bob 交替删除一棵子树。 仅当删除的子树是完美的满二叉树时，移动才是合法的，这意味着每个内部节点恰好有两个子节点，并且所有叶子都处于相同的深度。 移除的子树可能是整棵树，因此树可能会变空。 

没有合法动作的玩家就输了。 由于每个非空二叉树至少有一个叶子，并且单个叶子本身就是一个完美的满二叉树，因此每个非空位置总是至少有一个合法的移动。 因此，当每个节点都被移除时，游戏就结束了。 

输入包含多个独立的测试用例。 对于每种情况，边描述有根二叉树，以节点 1 作为根。 任务只是确定第一个玩家 Alice 或第二个玩家 Bob 在最佳游戏下是否获胜。 

一个测试用例中的节点数最多为 5000 个，所有测试用例的节点数总和最多为 50000 个。这个界限对于线性时间解决方案来说绰绰有余，但它排除了枚举大量可能的游戏状态的方法。 事实上，树结构本身根本不重要，所以我们甚至可以避免遍历边缘。 

有两种边缘情况很容易被误处理。 首先，一棵只包含根的树有一个节点，并且该根是完美的满二叉树。 对于输入```
11
```Alice立即删除了根，所以答案是`Alice`。 假设每次移动都会删除至少两个节点的实现会出错。 

第二种边缘情况是一个大小均匀的树，玩家可以删除一个大的完美子树。 例如，```
141 21 33 4
```答案是`Bob`。 Alice 不能仅仅通过选择特定的子树来强制获胜。 每次合法删除都包含奇数个节点，因此每次移动后，剩余节点数的奇偶校验都会翻转。 由于整棵树有四个节点，因此无论选择哪个合法子树，在树变空之前都必须进行偶数次移动。 

## 方法

 直接的博弈论解决方案将递归地检查每一个合法的举动。 对于每个结果树，我们将通过递归检查其合法动作来确定下一个玩家是否获胜。 这是正确的，因为当一个仓位至少有一次移动导致亏损时，该仓位就处于盈利状态。 

问题在于不同位置的数量。 一次移动会删除整个有根子树，不同的删除顺序可以产生许多不同的剩余树。 强力搜索可以有指数级的多个状态。 在尽可能广泛的状态空间范围内最多可以有 2 n 个不同的节点子集，并且检查每个状态本身就需要扫描树。 因此，简单的实现可以达到 O(n2 n ) 的工作量，即使对于 n=5000，这也是完全不切实际的。 

蛮力之所以有效，是因为它明确地模拟了所有可能的选择，但游戏具有更强的不变量。 

每一个合法的举动都会删除一个完美的完整二叉树。 如果这样一棵树的高度为 h，则它的节点数为

 1+2+4+⋯+2h=2h+1−1。 

这个数字总是奇数。 因此，每次移动都会删除奇数个节点。 

还有一个更重要的观察。 非空二叉树总是包含一个叶子，而叶子是高度为零的完美满二叉树。 因此，当树非空时，总是至少有一个合法的移动。 只有当树没有剩余节点时，游戏才能停止。 

假设游戏持续 k 步。 每次移动都会删除奇数个节点，因此删除的节点总数与 k 具有相同的奇偶校验。 由于最终所有 n 个节点都被删除，

 k=n(mod2)。 

当移动次数为奇数时，爱丽丝获胜，因为爱丽丝先移动。 因此，当 n 为奇数时，Alice 恰好获胜。 

树的实际形状、可用的完美子树以及玩家的选择与获胜者无关。 我们只需要节点数的奇偶校验。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 简单状态搜索中的 O(n2 n ) | O(n2 n ) | 太慢了 |
 | 最佳 | O(n) 输入处理，O(1) 游戏逻辑 | O(1) 超出输入存储 | 已接受 |

 ## 算法演练

 1. 读取当前树的节点数n。 边缘不会影响答案，但仍然需要从输入中消耗它们。 
2. 如果n是奇数，则打印`Alice`。 总步数必须是奇数，因此第一个玩家做出最后一步。 
3. 如果n是偶数，则打印`Bob`。 总步数必须是偶数，因此第二个玩家执行最后一步。 
4. 对每个测试用例重复相同的过程。 

### 为什么它有效

 每个合法的移动都会删除一个完美的满二叉树，其节点数为 2 h+1 −1，总是奇数。 非空二叉树始终包含叶子，因此合法的移动始终存在，直到树变空为止。 因此，如果游戏持续 k 步，则 k 个奇数之和等于原始 n，给出 keqn(mod2)。 Alice 进行了第一、第三、第五和其他奇数步，所以当 k 为奇数时，也就是当 n 为奇数时，她就赢了。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    t = int(input())    ans = []
    for _ in range(t):        n = int(input())
        # The edges do not affect the answer, but must be consumed.        for _ in range(n - 1):            input()
        if n & 1:            ans.append("Alice")        else:            ans.append("Bob")
    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":    solve()
```第一行给出了测试用例的数量。 对于每种情况，我们读取 n，然后恰好消耗 n−1 条边缘线，因为输入描述了一棵树。 

奇偶校验测试`n & 1`检查节点数是否为奇数。 无需构建邻接表、树根、计算子树大小或识别完美子树。 所有这些操作都将解决奇偶不变量导致的无关信息。 

单节点的情况就自然处理了。 当 n=1 时，`n & 1`是 true，所以程序打印`Alice`。 

也不存在整数溢出问题。 Python整数可以直接表示输入，并且该算法仅执行奇偶校验。 即使边缘未被使用，边缘读取循环也是必要的，因为不读取它们会破坏下一个测试用例的输入位置。

 ## 边缘情况

 对于单节点树，```
11
```没有边缘线可供阅读。 唯一的节点本身就是一个完美的满二叉树，因此 Alice 可以立即删除它。 该算法看到 n=1，这是奇数，并打印`Alice`。 

对于最小的偶数树，```
121 2
```唯一合法的举动是摘下一片叶子。 一个节点保留下来，另一位玩家将其删除。 游戏有两步，所以鲍勃获胜。 算法打印`Bob`因为2是偶数。 

一棵完美的树可能看起来很特别，但它遵循完全相同的规则。 为了```
171 21 32 42 53 63 7
```爱丽丝可以一步移除整个七节点树，立即获胜。 更一般地，一棵完美的树有 2 h+1 −1 个节点，这总是奇数，所以它的答案是自动的`Alice`。 

最后，形状可能极度不平衡。 路径仍然是有效的二叉树，因为每个节点最多有两个子节点。 对于包含 5000 个节点的路径，大多数子树并不完美，但每个叶子仍然是合法的移动。 确切的可用动作并不重要。 由于 5000 是偶数，因此每个完整游戏的步数都是偶数，鲍勃获胜。 这就是为什么实现可以在使用所有边缘端点后安全地忽略它们。
