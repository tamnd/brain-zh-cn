 ## 解决方案
 ## 问题理解

 标签形成有序的字符串序列。 对于选定的基数 (k)，允许正好 (k) 个十进制数字：(10-k, 11-k, \ldots, 9)。 标签首先按长度排序，并在相同长度内使用允许的数字按字典顺序排序。 

例如，当（k=7）时，可用的数字为（3,4,5,6,7,8,9）。 前七个标签是单字符字符串`3`通过`9`。 它们后面是所有 (7^2) 个双字符字符串，以`33`,`34`，并以`99`。 之后是所有 (7^3) 个三字符字符串。 

每个测试用例都给出基数 (k) 和一个基于 1 的位置 (X)。 任务是输出占据该位置的标签。 

从约束中得到的重要观察结果是，(X) 最多为 (10^9)，而最多可以有 (10^5) 个独立测试用例。 对于单个案例，逐一检查标签的解决方案最多需要 (10^9) 次迭代，这已经太大了。 在 (10^5) 种情况下，即使是 (O(X)) 方法也是完全不切实际的。 我们需要直接跳转到包含答案的块，然后仅构造该答案的数字。 

答案长度也很小。 有 (k^L) 个长度为 (L) 的标签，因此对于 (k=2)，前 (29) 个长度已包含 (2^{30}-2=1,073,741,822) 个标签。 因此，即使在增长最慢的基数中，(X\le 10^9) 的答案最多也有 (29) 个字符。 这使得每个案例的 (O(\log_k X)) 算法足够快。 

几种边界情况可能会导致直接实施失败。 

对于 (k=10) 和 (X=1)，答案是：```
0
```该位置是从 1 开始的，因此第一个标签对应于第一个块内的数字偏移量零。 直接从 (X) 开始转换的粗心实现会产生`1`反而。 

对于 (k=10) 和 (X=11)，答案是：```
00
```前十个位置是一位数字标签`0`通过`9`。 位置 (11) 是第一个两位数标签。 如果实现使用条件 (X \ge k^L) 而不是与整个前面的块进行比较，则它可能会错误地将此位置分配给一位数块。 

对于 (k=7) 和 (X=8)，答案是：```
33
```允许的数字是`3`通过`9`，因此前七个标签占据位置 (1) 到 (7)。 位置 (8) 开始两位数字块。 假设数字总是从零开始的解决方案将构造`00`，这不是该库中的有效标签。 

对于 (k=2) 和 (X=15)，答案是：```
8888
```有 (2+4+8=14) 个长度为 1 到 3 的标签，因此位置 (15) 是第一个四字符标签。 由于允许的最小数字是`8`，每个长度的第一个标签完全由`8`s。 这可以捕获块边界和数字转换中的错误。 

## 方法

 最直接的解决方案是按照实际顺序生成标签。 从所有单字符标签开始，然后是所有两字符标签，然后是所有三字符标签，依此类推。 在每个长度内，普通的碱基（k）计数给出了正确的字典顺序。 我们可以保留一个计数器，将其转换为标签，并在生成第 (X) 个标签后停止。 

这种强力方法是正确的，因为它完全遵循问题定义的顺序。 它的问题是工作量。 对于（X=10^9），它必须生成十亿个标签。 当 (k=2) 时，答案的长度为 (29)，生成前 (10^9) 个标签大约需要 (2.79\times10^{10}) 个字符操作。 即使在考虑 Python 开销之前，这也远远超出了实用的竞争性编程解决方案的范围。 

序列的结构为我们提供了一种更好的计数方法。 每个长度 (L) 块恰好包含 (k^L) 个标签，因为每个 (L) 位置都有 (k) 个选择。 因此，我们不需要生成任何内容来确定答案的长度。 我们可以减去整个块，直到剩余位置落入一个块内。 

假设答案的长度为 (L)，并令其在该块内从零开始的索引为 (r)。 (r) 的 (L) 位基数 (k) 表示（用前导零填充）标识所需的标签。 唯一的区别是问题的数字从 (10-k) 开始，而不是从零开始。 因此，每个基数（k）数字（d）都被转换为打印数字（d+（10-k））。 

暴力解决方案之所以有效，是因为它明确地遍历我们需要索引的相同序列，但会失败，因为该序列可以包含十亿个条目。 观察到每个长度形成一个完整的 (k^L) 个标签块，让我们可以在算术上跳过这些块并仅构造最多 (29) 个字符。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(X\log_k X)) 字符工作 | (O(\log_k X)) | 太慢了 |
 | 最佳| (O(\log_k X)) | (O(\log_k X)) | 已接受 |

 ## 算法演练

 1. 从请求的位置 (X) 开始，考虑长度为 (1) 的标签块。 该块恰好包含 (k) 个标签。 如果 (X) 大于该块，则减去 (k) 并移至长度 (2)。 以同样的方式继续。 

处理完所有较短长度后，剩余值 (X) 是正确长度 (L) 块内的基于 1 的位置。 
2. 通过将 (X) 替换为 (X-1)，将此剩余位置转换为从零开始的偏移量。 这很重要，因为块中的第一个标签对应于数值零，而不是一。 
3. 将从零开始的偏移量转换为基数 (k)。 生成的表示必须恰好包含 (L) 个数字，因此需要在前面添加零，直到其长度为 (L)。 

从 (0) 到 (k^L-1) 的每个 (L) 位基 (k) 数字在长度 (L) 块中恰好出现一次，顺序与标签相同。 
4. 将每个基 (k) 数字转换为问题的实际十进制数字。 如果基数 (k) 数字是 (d)，则打印 (d+(10-k))。 例如，在基数 (7) 中，内部数字 (0,1,2,\ldots,6) 变成打印数字 (3,4,5,\ldots,9)。 
5. 按原始顺序附加翻译后的数字并打印结果字符串。 由于输入最多包含 (10^5) 个案例，因此请独立处理每个案例并在写入之前累积输出。 

### 为什么它有效

 对于每个长度 (L)，恰好有 (k^L) 个可能的标签，并且问题列出了达到长度 (L) 之前的所有较短长度。 减法循环精确地删除了目标块之前的完整块，因此剩余的 (X) 是目标在其自身长度内的基于 1 的位置。

更改为 (X-1) 后，该值的范围为 (0) 到 (k^L-1)。 这些值与内部数字集 (0,\ldots,k-1) 上的所有 (L) 数字字符串之间存在一一对应关系。 当所有表示都填充到长度 (L) 时，Base-(k) 表示按字典顺序递增给出这些字符串。 最后，向每个内部数字添加 (10-k) 将该表示形式精确映射到允许的十进制数字。 因此构造的字符串正是所请求的标签。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_label(k, x):
    length = 1
    block = k

    while x > block:
        x -= block
        length += 1
        block *= k

    # Convert from one-based position inside the block
    # to a zero-based base-k value.
    value = x - 1

    digits = ['0'] * length
    shift = 10 - k

    for i in range(length - 1, -1, -1):
        digits[i] = chr(ord('0') + shift + (value % k))
        value //= k

    return ''.join(digits)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        k = int(input())
        x = int(input())
        out.append(get_label(k, x))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```这`length`变量表示当前正在检查的块。 其对应的`block`值是 (k^{length})，即具有那么多字符的标签数量。 该循环减去整个块，直到目标落入当前块内。 

线路`value = x - 1`是关键的逐一调整。 一旦目标位于固定长度块内，第一个标签必须对应于内部值 0，第二个标签必须对应于内部值 1，依此类推。 

转换循环使用从右到左提取基（k）数字`value % k`。 除以 (k) 会删除刚刚处理的数字。 输出数组的初始化精确为`length`位置，因此前导零会自动保留。 这是必要的，因为`00`和`0`表示不同的标签，即使如果忽略前导零，两者将具有相同的数值。 

表达式`shift = 10 - k`执行数字翻译。 例如，对于 (k=7)，内部数字零变为`3`，而内部数字六变为`9`。 

Python 中不存在整数溢出问题。 无论如何，所需的最大中间块足够小，因为一旦目标位于块内并且(X\le10^9)，循环就会停止。 在固定宽度语言中，使用足够宽的整数类型仍然是可取的。 

输出累积在列表中并写入一次。 使用 (10^5) 个测试用例，重复调用`print`通常仍然是可以管理的，但是收集字符串可以避免不必要的输出开销。
