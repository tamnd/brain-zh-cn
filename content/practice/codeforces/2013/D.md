 ## 解决方案
 ## 问题理解

 我们得到了排列成一行的数字序列。 在一次移动中，我们可以从某个位置取出一个单位并将其推到右侧的下一个位置。 这意味着质量只能向右流动，而不能向后流动，并且每次移动都会保留数组的总和。 

在执行任意数量的此类移动之后，我们希望最终的数组尽可能“平衡”，即其最大值和最小值之间的差异最小化。 

关键的困难在于，虽然我们可以重新分配值，但方向约束使得这与自由排列元素有很大不同。 前面的位置只能损失质量，后面的位置只能通过传播间接获得质量。 

这些约束推动每个测试用例的解决方案大致呈线性或线性算数。 由于总共有多达二十万个元素，任何尝试逐步模拟重新分配或显式探索配置的解决方案都会立即变得太慢。 即使是二次可行性检查也已经是边界，因此该结构必须允许直接计算给定目标范围的答案。 

当数组已经“几乎排序”或“几乎恒定”时，就会出现微妙的边缘情况。 尝试局部平滑的天真贪婪在这里可能会失败，因为局部平滑忽略了全局累积效应。 例如，在像这样的数组中`[5, 1, 1, 1, 1]`，将质量向右推可以改善后面的位置，但可能会使最后一个元素超载，并且决定可行性需要全局推理而不是局部调整。 

当所有值都相等时，会出现另一种边缘情况。 由于不需要移动，所以答案为零。 任何假设至少存在一种有益举措的方法，如果在检查可行性时使用严格的不等式，都可能会在这里失效。 

## 方法

 蛮力的想法是模拟以所有可能的方式重新分配价值的过程，直到无法进行更多改进。 由于每个操作将一个单位向右移动一步，因此每个价值单位都有效地选择了它将行驶多远，但选择之间存在依赖性，因为每个前缀的容量限制了未来的移动。 

即使我们尝试将其建模为流，在最坏的情况下，可能的操作序列的数量也会呈指数增长。 例如，开始时的单个大值可以在后面的索引中推送到许多不同的组合中，从而导致组合爆炸。 

关键的观察是我们不需要模拟操作。 我们只需要决定是否有可能实现给定的最大最小差值。 一旦可行性可测试，我们就可以二分搜索答案。 

为了检查固定界限的可行性，我们尝试看看是否可以确保所有最终值都位于某个区间内`[L, L + d]`。 由于总和被保留并且仅向右移动，我们可以贪婪地确定最小可能的前缀累积，并看看我们是否违反了上限约束。 

这将问题变成了单调的可行性检查`d`，这使得二分搜索适用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(n) | 太慢了 |
 | 二分查找+贪婪可行性| O(n log A) | O(n log A) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题转化为检查给定的范围宽度是否`d`是可以实现的。 

1.修复候选答案`d`，这意味着我们希望最终值位于某个区间内`[L, L + d]`对于某些 L。我们还不知道 L，因此我们根据前缀和的约束进行推理。 
2. 观察到，由于值只能向右移动，因此当我们查看任何前缀时`[1..i]`，我们最多只能从原始数组中接收到该前缀的总和。 这意味着最终的前缀和不能超过初始的前缀和。 
3. 如果我们希望每个元素至少`L`，然后加上前缀`[1..i]`必须至少有总和`i * L`。 将此与上限结合起来`L + d`，前缀和也必须至多`i * (L + d)`。 
4. 这就给出了一个可行性条件：对于每一个`i`，原始前缀和必须与某个宽度区间兼容`d`。 我们可以重新安排它以找到可能的约束`L`。 
5. 我们计算每个前缀的最大下界`L`表示不超过前缀和，表示最小上限，表示不要太低。 如果这些限制对于某些方面重叠`L`，那么所选择的`d`是可行的。 
6.我们二分查找最小的`d`可行性成立。 

重要的结构是前缀和就像一个不能向左移动的“预算”。 任何有效的最终配置必须同时考虑所有前缀预算。 

### 为什么它有效

 该算法是正确的，因为任何允许的操作序列都会保留前缀和上限：质量不能向左跳，因此任何前缀都不能获得超过其初始总数的值。 同时，如果我们可以分配一个满足所有前缀约束的目标区间，我们就可以构造一个实现它的右流分布。 可行性检查准确地捕获了这种分布是否存在，从而使二分搜索结束`d`声音。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(d, a, n, total):
    # We try to see if there exists L such that all values lie in [L, L+d]
    # Using prefix constraints on possible mass flow.
    
    low = -10**30
    high = 10**30
    
    pref = 0
    for i in range(1, n + 1):
        pref += a[i - 1]
        
        # prefix sum must be between i*L and i*(L+d)
        # i*L <= pref <= i*(L+d)
        # L <= pref/i
        # L >= pref/i - d
        
        # update constraints on L
        # from pref <= i*(L+d): L >= pref/i - d
        low = max(low, pref / i - d)
        
        # from pref >= i*L: L <= pref/i
        high = min(high, pref / i)
        
        if low > high:
            return False
    
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    
    # search range for answer
    lo, hi = 0, max(a)
    
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, a, n, total):
            hi = mid
        else:
            lo = mid + 1
    
    print(lo)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该解决方案定义了可行性函数`can(d)`检查最大最小差异是否为`d`可以实现。 它维护一个运行的前缀和并导出对假设基线值的约束`L`。 可行的重叠`L`间隔决定是否选择`d`作品。 

二分查找找到最小的这样的`d`。 搜索范围安全地限定为`0`和`max(a)`因为差值永远不会超过最大的初始值差。 

一个微妙的实现问题是浮点除法。 在严格的竞赛解决方案中，这应该被使用整数的理性不等式操纵所取代，以避免精度问题，但概念结构保持不变。 

## 工作示例

 我们对固定候选人进行可行性检查`d = 2`。 

### 示例 1

 输入：`[1, 2, 3]`| 我| 前缀和| L | 的低约束 对 L | 的高度约束
 | --- | --- | --- | --- |
 | 1 | 1 | -∞, 1 - 2 = -1 | 1 |
 | 2 | 3 | 最大值(-∞, 1.5 - 2 = -0.5) | 1.5 | 1.5
 | 3 | 6 | 最大(-0.5, 2 - 2 = 0) | 2 |

 间隔为`L`保持非空，所以`d = 2`是可行的。 尝试`d = 1`会将下限缩小太多并最终打破重叠。 

这证实了答案是允许一致的前缀分配的最小宽度。 

### 示例 2

 输入：`[4, 2, 3, 1]`| 我| 前缀和| 低约束| 高约束|
 | --- | --- | --- | --- |
 | 1 | 4 | -∞, 4 - d | 4 |
 | 2 | 6 | 最大（上一个，3 - d）| 3 |
 | 3 | 9 | 最大（上一个，3 - d）| 3 |
 | 4 | 10 | 10 最大（上一个，2.5 - d）| 2.5 | 2.5

 为了`d = 1`，约束冲突。 为了`d = 2`，它们相交。 

这显示了严格的前缀行为如何迫使可实现的最小扩展。

 ## 边缘情况

 对于`n = 1`，该数组没有要移入的邻居，因此无法进行任何操作。 该算法仍然会产生有效的区间，因为前缀约束立即崩溃为单个值，产生零差异。 

对于已经统一的数组，例如`[7, 7, 7, 7]`，每个前缀和完全匹配一个常数密度，因此可行区间`L`无论怎样都不会破裂`d = 0`。 二分查找立即锁定零。 

对于高度倾斜的输入，例如`[100, 0, 0, 0]`（或其大值等价物），前缀约束力`L`非常小，而后面的前缀则将其向上推。 可行性检查通过重叠边界来捕捉这种张力`L`，以及最小的有效值`d`反映了单向流动所产生的不可缩减的价差。
