 ## 解决方案
 ## 问题理解

 我们得到了数轴上的位置列表，每个位置代表一个人居住的地方。 目标是选择给定位置之一作为集合点，以便所有人到该选定点的步行距离之和尽可能小。 距离是以直线上的标准绝对差来测量的。 

尽管该问题允许选择任何给定位置，但成本仅取决于所选点如何平衡数轴上的所有值。 直观上，如果交汇点太靠左，则许多点位于右侧并贡献较大的距离； 如果太右，就会出现对称问题。 

输入大小最多可达 200,000 个值，每个值最大可达 10^9。 在最坏的情况下，评估每个候选交汇点与所有其他交汇点的二次解决方案将涉及高达 4×10^10 的距离计算，这远远超出了 Python 中两秒内运行的速度，甚至超出了具有简单实现模式的优化编译代码的速度。 

需要使用线性或线性算术方法，这强烈表明我们必须避免从头开始重新计算每个候选者的距离。 

一个微妙的问题是，如果多个职位产生相同的最低成本，那么答案的价值不一定是唯一的。 由于问题要求从数组中打印位置 Pi，因此任何有效的中位数位置都是可以接受的。 

这里重要的边缘情况包括具有重复值的数组、已排序的数组以及高度倾斜的分布（例如一个极端异常值）。 例如，如果输入为[1, 1, 1, 100]，则最佳交汇点必须为1； 天真的直觉可能会错误地考虑平均或中点逻辑，这是无关紧要的，因为我们被迫选择现有的 Pi。 

## 方法

 蛮力的想法很简单。 对于每个候选位置 Pi，计算绝对差之和 |Pi − Pj| 在所有 j 中，然后选择总和最小的 Pi。 这是正确的，因为它直接评估问题定义的目标函数。 

但是，此方法会为 N 个候选中的每一个重新计算 O(N) 总和，从而导致总运算量为 O(N^2)。 当 N 达到 2×10^5 时，这会导致大约 4×10^10 次操作，这是不可行的。 

关键的观察结果是，最小化一条线上的绝对偏差之和是一个经典的中值属性。 如果我们对数组进行排序，距离总和最小的点就是中值元素。 原因是结构性的：稍微向左或向右移动交汇点会改变两侧元素向相反方向的贡献，并且恰好在中线分割处实现平衡。 

由于 N 是奇数，因此中位数是排序后的单个明确定义的元素，特别是基于零的索引中索引 N/2 处的元素。 

这将问题从评估所有候选者转变为排序一次并选择一个位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了 |
 | 最优（排序后的中值）| O(N log N) | O(N log N) | O(1) 或 O(N) | 已接受 |

 ## 算法演练

1. 读取位置数组。 在此阶段，这些值是任意顺序的，因此尚不存在诸如排序或前缀平衡之类的结构属性。 
2. 按非降序对数组进行排序。 排序至关重要，因为中位数属性只有在有序序列中才有意义。 如果没有排序，就没有左半部分和右半部分的概念。 
3. 选择索引为 N 处的元素 // 2. 由于 N 为奇数，因此该索引对应于中间元素，两侧元素数量完全相同。 
4. 输出该元素作为所选的交汇点。 该值保证是原始位置之一，并且在绝对距离总和目标下是最优的。 

### 为什么它有效

 考虑数轴上的任意候选点 x。 如果 x 向左移动，x 左侧的每个点贡献的距离会减小，如果 x 向左移动，右侧的每个点贡献的距离会增加。 总成本函数是分段线性的，并且根据 x 两侧的点数量而改变斜率。 当少于一半的点位于左侧时，斜率为负；当少于一半的点位于右侧时，斜率为正。 当 x 是中位数时，两个方向都不会提高成本的平衡点。 由于 N 是奇数，因此这种平衡发生在排序顺序中的单个元素上，从而保证中值元素最小化总绝对偏差。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    p = list(map(int, input().split()))
    
    p.sort()
    print(p[n // 2])

if __name__ == "__main__":
    main()
```该解决方案读取所有位置，对它们进行排序，然后打印中间元素。 唯一微妙的实现细节是使用整数除法 n // 2，当 n 为奇数时，它会正确选择从零开始的数组的中值索引。 对于重复或未排序的输入不需要特殊处理，因为排序自然会处理这两者。 

## 工作示例

 ### 示例 1

 输入：

 [7,3,5,1,4]

 排序数组：

 [1,3,4,5,7]

 中位数指数为 2。 

| 步骤| 数组状态| 选择索引 | 选择值 |
 | ---| ---| ---| ---|
 | 排序 | [1, 3, 4, 5, 7] | - | - |
 | 选择| [1, 3, 4, 5, 7] | 2 | 4 |

 这表明 4 平衡了左侧的三个元素和右侧的一个元素，产生了最小的总绝对距离。 

### 示例 2

 输入：

 [10,2,8,9,2]

 排序数组：

 [2,2,8,9,10]

 中位数指数为 2。 

| 步骤| 数组状态| 选择索引 | 选择值 |
 | ---| ---| ---| ---|
 | 排序 | [2,2,8,9,10]| - | - |
 | 选择| [2,2,8,9,10]| 2 | 8 |

 在这里，8 最小化了总距离，因为它将左侧的两个值和右侧的两个值分开，从而实现最佳平衡。 

痕迹证实，该解决方案在排序后始终选择中心平衡点，这正是最小化绝对偏差所需的中值行为。

 | 测量| 复杂性 | 说明|

 ## 边缘情况

 对于像 [10] 这样的单个元素输入，排序会使其保持不变，并且选择索引 0 返回 10，这实际上是最佳的，因为不需要移动。 

对于像 [2, 2, 2, 2, 2] 这样的全相等数组，排序不执行任何操作，中位数仍然为 2。任何选择都会产生零总距离，并且算法始终返回有效的最佳点。 

对于像 [1, 1, 1, 1, 100] 这样的高度倾斜数组，排序给出 [1, 1, 1, 1, 100]，中位数索引为 2，产生值 1。如果试图根据平衡幅度而不是计数的平均值或直觉进行选择，则可能会错误地选择 100 或更接近它的值，但绝对偏差成本仅取决于每一侧的计数，而不是距离 在价值空间中。
