 ## 解决方案
 ## 问题理解

 我们得到一个仅由左括号和右括号组成的字符串。 唯一允许的操作是从某个位置取出右括号并将其重新插入到其左侧的任何位置。 左括号已固定到位。 

目标是确定在任意次数的此类移动之后，我们是否可以将序列转换为格式良好的括号序列，这意味着如果我们插入，它可以表示有效的算术表达式`+`和`1`字符之间。 

允许操作的重要结果是，只要右括号不向右移动，就可以完全重新排序。 换句话说，所有`')'`字符可以任意排列，但只能以相对于原始位置向左移动的方式排列。 左括号无法移动。 

输入大小最多可达 200,000 个字符。 对子串或重复模拟的任何二次甚至接近二次的方法都太慢。 线性扫描或具有恒定额外状态的线性扫描是必要的。 

当字符串以许多右括号开头时，会出现微妙的边缘情况。 例如，`"))(("`无法修复，因为没有任何操作可以将右括号向右移动经过左括号，并且前缀有效性从一开始就从根本上被破坏。 另一个边缘情况是，即使计数全局匹配，右括号的数量也不足以“可分配”以匹配前缀顺序中的开括号。 

## 方法

 强力解释将模拟移动右括号的所有可能方式。 每个操作选择一个`')'`并更早地插入它，所以理论上我们可以尝试在不能向右移动的约束下生成右括号的所有排列。 这导致状态空间的右括号数量呈指数增长。 即使尝试贪婪的本地修复仍然需要重复扫描和更新，在最坏的情况下会导致二次行为。 

关键的观察结果是，该操作消除了对右括号的任何位置限制，除了它们不能向右交叉之外。 这实际上意味着我们可以重新安排所有`')'`角色之间可以自由地互动，只要他们占据的多重位置尊重他们停留在不位于其原始出现位置右侧的位置。 由于我们只被问到是否可以形成正确的括号序列，因此唯一真正的问题是我们是否可以尽早分配足够的右括号以满足前缀平衡。 

正确的括号序列条件可简化为经典的前缀规则：每个前缀必须至少有同样多的前缀`'('`作为`')'`，并且总计数必须匹配。 

由于我们可以有效地将右括号向左“移动”，因此唯一的障碍来自于包含太多右括号的前缀，而与任何地方都可以提前提供它们的开口相比。 考虑到我们无法移动，该结构会崩溃，检查序列是否可以重新排列成有效的戴克词`'('`。 

这会导致贪婪检查：模拟读取字符串，跟踪可用的空缺，并确保我们永远不需要比剩余后缀总数所能提供的更多的结束。

 ## 算法演练

 我们将问题转化为在右括号移动受限的情况下对前缀余额进行可行性检查。 

1. 统计总数`'('`和`')'`。 如果不相等，则返回“否”。 正确的括号序列需要相等的数字，并且没有任何操作改变计数。 
2. 从左到右迭代字符串，同时保持到目前为止我们已经看到的左括号数量。 这代表了有多少无与伦比的`'('`可能可用于支持未来的右括号。 
3. 维护一个计数器，记录我们已经“固定”到有效位置的右括号数量。 我们不考虑实际的移动，而是将其视为确保在每个前缀处，所需的右括号的数量不超过可以提供的数量。 
4. 在每个位置，计算我们必须保留的不匹配开局的最小数量，以保持未来的有效性。 如果在任何时候我们将被迫陷入需要更多前缀的情况`')'`比可用的`'('`，我们得出不可能的结论。 
5. 由于右括号可以向左移动，因此如果后缀总位置中没有足够的空位来补偿，则无法修复前缀中的任何缺陷。 贪婪扫描确保我们永远不会过早过度使用空缺。 

### 为什么它有效

 不变的是，处理完一个前缀后，可用的数量`'('`正好是看到的开仓数量减去我们迄今为止逻辑上匹配的平仓数量。 Because we can only move`')'`左，任何有效的构造都必须遵守以下原则：没有任何前缀需要比整个字符串中迄今为止存在的打开数更多的关闭数。 If a prefix violates this, no rearrangement can fix it, since we cannot introduce new`'('`提前或将它们向右移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    
    open_cnt = s.count('(')
    close_cnt = n - open_cnt
    
    if open_cnt != close_cnt:
        print("No")
        return
    
    balance = 0
    for ch in s:
        if ch == '(':
            balance += 1
        else:
            balance -= 1
        if balance < 0:
            print("No")
            return
    
    print("Yes")

if __name__ == "__main__":
    solve()
```该解决方案首先通过计数检查全局可行性，因为任何有效的括号序列都必须具有相同数量的左括号和右括号。 然后它执行标准前缀余额扫描。 关键思想是，尽管允许操作，但我们仍然无法修复关闭超过打开的前缀，因为没有操作可以创建更早的打开或将打开向右移动。 前缀模拟准确地捕获了这种障碍。 

一个微妙的点是我们没有显式模拟允许的重新插入。 该操作仅影响右括号的相对顺序，但不会改变开口所施加的基本前缀约束，因此经典的有效性检查仍然足够。

 这显示了完全有效的前缀演变，其中余额永远不会低于零并以零结束。 它确认当序列已经正确时不需要重新排列。 

### 示例 2：`())(()`| 我| 字符 | 平衡|

 在位置 3 处，前缀无效，因为当不存在不匹配的左括号时，会出现右括号。 即使存在后来的打开，它们也不能向左移动，因此前缀冲突是永久性的。 

这表明该算法正确地拒绝了早期结构无法挽救的情况。

 ## 边缘情况

 关键的边缘情况是字符串全局平衡但有早期前缀违规，例如`")(()"`。 该算法对其进行如下处理：在第一个字符处，余额变为`-1`，立即引发拒绝。 这符合以下事实：不允许的操作无法在位置 1 之前移动左括号，因此无法修复前缀。 

另一种情况是`"()())("`，其中总计数相等，但前缀仍然在第五个字符处中断。 扫描达到平衡`-1`此时，算法会拒绝。 即使稍后有额外的空缺，也无法将其向左移动足以修复前缀边界处的赤字。 

最终的边缘情况已经是正确的序列，例如`"((()))"`。 余额永远不会低于零，并且算法无需考虑重新排序操作即可接受，这反映出该操作仅在可能需要重新排列时相关，但不会扩展可行的前缀有效字符串的类别。
