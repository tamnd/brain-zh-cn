 ## 解决方案
 ## 问题理解

 我们得到一个根据指令序列从两端收缩的数组。 在每一步中，在删除任何内容之前，我们必须计算所有剩余元素以固定数为模的乘积$m$。 然后该命令告诉我们是否删除最左边或最右边的元素。 

所以这个过程是纯粹动态的：数组是一个由两个指针定义的滑动窗口，每次查询后我们都会将该窗口从两侧缩小一个。 挑战在于支持快速重复的产品查询，同时元素从两端消失。 

约束足够大，每次删除后从头开始重新计算产品会太慢。 幼稚的方法会花费$O(n^2)$在最坏的情况下每个测试用例因为每个步骤可能会乘以$n$再次元素。 总共有$n$最多$2 \cdot 10^5$，这是不可接受的。 

出现微妙的边缘情况时$m = 1$。 在这种情况下，无论数组如何，每个答案都为零，因此正确的解决方案必须避免不必要的计算，并且在重复删除的情况下仍然表现正确。 

## 方法

 强力方法将显式维护当前数组并重新计算乘积模$m$每次操作后。 这是正确的，但效率低下。 每一步花费线性时间，并且有$n$步骤，总体上给出二次复杂度。 

关键的观察结果是数组仅丢失末端的元素。 这意味着我们永远不会插入或修改值，只会删除它们。 这意味着维护正在运行的产品并逐步更新它。 然而，除非我们可以安全地计算模逆，否则模除法不能直接使用，当$m$不是素数或元素共享因子$m$。 

这促使我们采取不同的观点。 我们不是试图维持可逆的产品，而是相反地处理去除。 如果我们想象向后重建数组，那么每次删除都会变成一次插入。 我们可以通过首先删除所有内容然后以相反的顺序重建答案来模拟该过程。 在重建过程中，乘法是安全的，因为我们只添加元素。 

这种反转技术将问题转换为标准的前缀结构，其中我们只将元素乘以乘积，而不是除法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重新计算每一步|$O(n^2)$|$O(n)$| 太慢了 |
 | 增量乘法的逆过程 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取数组和命令字符串。 将这个过程解释为反复从左或右删除，直到没有任何内容为止。 
2. 构建删除元素的序列，而不是向前模拟删除。 我们首先跟踪最终状态（为空），然后通过以与删除相反的顺序重新插入元素来向后模拟。 
3. 为此，需要维护两个指针$l$和$r$。 对于每个命令，记录该步骤将删除哪个元素。 
4. 记录移除顺序后，反转此顺序。 现在我们将数组从空重建为满。 
5. 维护一个从 1 开始的运行乘积。每次我们加回一个元素，将其乘以乘积模$m$。 
6. 每次插入后存放产品。 这些对应于原始过程的相反顺序的答案。 
7. 最后在打印之前反转答案数组。 

### 为什么它有效

 关键的不变量是，在反向过程中，在每一步中，当前的元素集恰好是在正向方向上删除的元素的补充。 由于乘法是结合性和交换性的，因此以相反的顺序重建可以保留每个阶段活动集中前缀积的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        s = input().strip()

        l, r = 0, n - 1
        removed = []

        for c in s:
            if c == 'L':
                removed.append(a[l])
                l += 1
            else:
                removed.append(a[r])
                r -= 1

        res = []
        prod = 1

        for x in reversed(removed):
            prod = (prod * x) % m
            res.append(prod)

        print(*reversed(res))

if __name__ == "__main__":
    solve()
```## 代码如何符合想法

 第一个循环通过用两个指针模拟收缩数组来重建确切的删除顺序。 这避免了任何昂贵的重新计算。 

第二个循环翻转了这个过程：我们不再删除元素并重新计算产品，而是将元素一一添加回来并维护一个正在运行的产品。 这是可行的，因为集合上的乘法不依赖于顺序。 

最终的反转将重构的时间线与原始查询顺序对齐。

 ## 边缘情况

 当$m = 1$，每个乘法结果必须立即变为零。 该算法仍然有效，因为每个乘积运算都是模数$m$，因此所有中间状态仍然有效，并且最终的反向重建产生一系列没有特殊大小写的零。 

当所有元素相同时，移除顺序不会影响正确性，并且重建仍然会产生相同的乘积序列，从而证实解在对称情况下是与顺序无关的。
