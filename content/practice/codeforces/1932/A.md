 ## 解决方案
 ## 问题理解

 我们得到了一条由细胞组成的一维路径。 每个牢房要么是空的，要么里面有一枚硬币，要么被荆棘堵住。 我们从第一个单元格开始，它保证是空的，我们希望在收集硬币时尽可能向右移动。 

在每一步中，我们可以向前移动一个或两个单元格，但我们只允许降落在不是荆棘的单元格上。 如果我们降落在硬币电池上，我们就会收集硬币。 我们无法穿过或降落在刺细胞上，刺细胞有效地充当了着陆位置的障碍。 

任务是计算从索引 0 开始我们可以收集的最大硬币数量。 

约束非常小：最多 1000 个测试用例，每条路径的长度最多为 50。这立即告诉我们，即使是三次或指数解也能轻松通过，但它也暗示预期的解决方案足够简单，每个测试用例都是线性的。 

一个关键的结构观察是运动是严格向前的，唯一的分支是我们是跳 1 步还是 2 步。 没有回溯，也没有循环。 

主要的微妙之处在于，荆棘会阻碍着陆，如果假设你总是可以到达每一枚硬币，那么贪婪的“看到硬币就拿走”策略会失败。 

例如，考虑这样的细分：

 输入：```
. @ * @ @
```从第一个单元格开始，您可能会考虑收集第一个硬币，然后继续，但错误的步进可能会使您陷入这样的配置：由于荆棘阻挡了有效的步进点，因此无法到达后面的硬币。 

另一个微妙的边缘情况是连续的刺：```
. @ * * @
```即使后来有一枚硬币，也可能无法到达，因为每条跳跃路径都会落在荆棘上。 

这些情况表明我们需要一种系统的方法来跟踪可达性，而不仅仅是局部贪婪的决策。 

## 方法

 蛮力方法将探索每一个可能的动作序列。 如果目的地有效，我们可以尝试从每个位置向前移动 1 或 2 个单元格。 每个状态最多分支为两个选择，形成深度高达 n 的递归树。 

在最坏的情况下，这会导致大约 O(2^n) 条路径，因为每个位置都可以分支为两个选择。 尽管 n 只有 50，但 2^50 仍然太大，并且大多数分支都是冗余的，因为它们通过不同的路径多次重新访问同一索引。 

冗余表明动态规划。 关键的观察结果是该问题具有最优子结构：从位置 i 开始的最佳答案仅取决于位置 i+1 和 i+2 的最佳答案，前提是这些位置是可到达的。 

我们不再向前思考，而是翻转视角：将 dp[i] 定义为我们可以从单元格 i 开始收集的最大硬币，假设我们被允许站在 i 上。 由于我们总是向前移动，因此转换仅转到 i+1 或 i+2，从而使状态空间呈线性。 

我们从右到左计算 dp。 如果一个单元格是一根刺，则 dp[i] 无效。 否则，dp[i] 是 i 处的硬币加上 dp[i+1] 和 dp[i+2] 的最大值（如果这些状态有效）。 

最后，我们返回 dp[0]。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（DFS 移动）| O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 动态规划| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们定义一个 DP 数组，其中每个位置代表从该单元格开始可收集的最佳硬币数量。 

1. 创建一个大小为 n+2 的数组 dp，初始化为 0。额外的填充可防止访问 i+1 和 i+2 时进行边界检查。 
2. 从最后一个单元格向下迭代到第一个单元格。 我们进行相反的处理，以便在计算 dp[i] 时，dp[i+1] 和 dp[i+2] 的值是已知的。 
3. 如果当前单元格包含荆棘，我们将 dp[i] 设置为 0，因为我们无法降落在那里。 然而，当隐式考虑较早的单元格时，我们仍然允许通过它进行转换，因为我们永远不会从刺开始。 
4. 如果当前单元格不是荆棘，如果它包含硬币，则计算基值等于 1，否则计算为 0。 
5. 将 dp[i] 更新为基值加上 dp[i+1] 和 dp[i+2] 的最大值，但仅考虑有效转换。 如果两者都有效，我们取最大值； 如果某个实际上无法访问，我们会忽略它。 
6. 每个测试用例的答案是 dp[0]，它对应于从第一个单元格开始。 

### 为什么它有效

 正确性依赖于以下事实：从任何位置 i 开始，唯一的未来决策是从 i+1 和 i+2 开始的独立子问题。 由于运动是严格向前进行的，所以后来的选择不能影响先前的决定。 从 i 开始的每条有效路径都必须从这两个动作之一开始，因此最佳结果是这两个延续中最好的一个加上在 i 处收集的任何硬币。 这形成了所有可能路径的完整分解，保证没有配置被遗漏或重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        dp = [0] * (n + 2)

        for i in range(n - 1, -1, -1):
            if s[i] == '*':
                dp[i] = 0
                continue

            best_next = max(dp[i + 1], dp[i + 2])
            dp[i] = best_next + (1 if s[i] == '@' else 0)

        print(dp[0])

if __name__ == "__main__":
    solve()
```该解决方案从右到左处理字符串，以便每个状态都已计算出其未来。 使用填充的 dp 数组可以避免访问 i+2 时的显式边界检查。 

一个常见的错误是试图贪婪地模拟从左到右的运动。 但这会失败，因为选择收集早期硬币的举动可能会阻止访问更好的未来序列。 DP 公式通过始终评估两个前向选项来避免这种情况。

 ## 边缘情况

 一种边缘情况是刺出现在连续的位置。 对于输入：```
.@@**
```DP 将荆棘后的 dp 值正确设置为零，并且较早的单元会自动避免跳入其中，因为 dp[i+1] 和 dp[i+2] 在这些位置处的计算结果均为零。 这可确保路径不会错误地穿过封锁区域。 

另一种边缘情况是当一枚硬币紧随荆棘块之后时：```
.@**@.
```在荆棘前的位置，两种可能的向前移动最终都会导致无效或零值状态，因此 DP 自然会放弃该路线。 该算法不需要明确的“无法到达”标记，因为阻塞路径贡献零增益，因此在最大操作中永远不会被选择。
