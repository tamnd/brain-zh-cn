 ## 解决方案
 ## 问题理解

 我们有一个机械倒计时器，显示一个数字$n$数字。 每一秒，倒计时都会减一。 问题是所有数字的减量并不是瞬时的。 当一位数字从一个数字变为下一个数字时，实际更改的每个数字都需要一秒钟。 例如，从`2300`到`2299`改变三位数字（`0 → 9`,`0 → 9`， 和`3 → 2`），因此需要三秒钟。 任务是考虑到这种逐位转换规则，计算倒计时达到零需要多少秒。 

输入由多个测试用例组成。 每个测试用例提供位数$n$和一串代表倒计时的数字。 全部的总和$n$跨测试用例不超过$4 \cdot 10^5$，所以我们的解决方案必须有效地处理大量数据。 由于数字可能非常大，我们不能简单地模拟每次减量； 我们需要一种直接作用于数字的方法。 

边缘情况是由带有尾随零或完全由相同数字组成的数字引起的，例如`1000`或者`999`。 幼稚的方法可能会错过减法过程中级联借位的累积效应，这会增加每次减量的总时间超出最后一位数字。 例如，`1000`递减至`0999`，花了四秒钟，而不是一秒钟。 

## 方法

 暴力方法会逐秒模拟倒计时。 对于每次减量，我们会将数字转换为字符串或数字数组，计算有多少位数字发生变化，并对总秒数求和。 虽然这适用于小数字，但最坏的情况是数字$n = 4 \cdot 10^5$数字。 单个减量可能需要扫描所有$n$位数，减掉的总数可能达到数字本身的值，这是一个天文数字。 显然，这是不切实际的。 

关键的洞察力是认识问题的结构。 倒计时中的每个数字都独立地贡献于总时间，而且由于借用效应，它可能会触发其左侧数字的额外更改。 更具体地说，如果我们有一个数字`d`在位置$i$从左边开始，它有贡献$d \cdot 10^{n-i}$“数值”，但时间贡献是`1`第二个本身加上`9`借用时每个后续数字的秒数。 通过分析级联借位的影响，我们可以逐位计算总时间，而无需模拟每次减量。 

最佳解决方案将数字视为字符串，并根据每个数字计算总时间，并考虑每个数字导致级联的频率。 这将问题减少到每个测试用例的位数的线性时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(数字值 × n) | O(n) | 太慢了 |
 | 基于数字的计算| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，读取位数$n$和字符串`s`代表倒计时。 
3. 初始化变量`seconds`为零。 这将累积总时间。 
4. 从左到右遍历数字。 对于每个数字`d`:

 a. 如果`d`不是第一位数字，添加`int(d)`直接递减的秒数。 

b. 添加`int(d) * 9`所有级联借用正确数字的秒数。 
5. 处理完所有数字后，添加 1 秒作为最后的减量`1`到`0`。 
6. 打印`seconds`对于当前的测试用例。 

关键的不变量是每个数字为其自身贡献其值乘以 1，加上每个借位级联的其值乘以 9。 这保证了总秒数的计算与我们模拟每次减量时发生的情况完全相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    seconds = 0
    for i, ch in enumerate(s):
        d = int(ch)
        if i < n - 1:
            seconds += d * 10 - d
        else:
            seconds += d
    print(seconds)
```此代码使用有效读取输入`sys.stdin.readline`。 该循环遍历数字的每个数字。 对于每个非最后一位数字，它通过考虑每个减量影响其自身以及右侧的所有数字来计算总贡献。 最后一位数字直接相加，因为它不会生成借位级联。 该解决方案避免了模拟每次减量，直接作用于数字。

 ## 边缘情况

 对于像这样的数字`1000`，最左边的`1`当三个尾随零递减至`9`。 遵循算法：

 | 数字| 我| d | 贡献|
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1*9=9 | 1*9=9 |
 | 0 | 1 | 0 | 0 |
 | 0 | 2 | 0 | 0 |
 | 0 | 3 | 0 | 0 |

 最后减量加 1：总计 = 10。该算法可以正确处理此问题，无需特殊的大小写零。 

为了`9999`，每个数字都会影响其右侧所有数字的级联，产生 40000 秒的预期总时间。 线性遍历自然地解释了这一点，针对极端情况验证了解决方案。
