 **求解时间：** 4m 24s

 ## 解决方案
 ## 问题理解

 我们得到了一位程序员按时间顺序排列的竞赛分数。 当当前分数严格大于每个先前分数，或严格小于每个先前分数时，性能被称为“惊人”。 

第一场比赛永远不算数，因为没有更早的比赛可供比较。 

任务是处理序列并计算程序员设置新的个人最佳值或新的个人最差值的次数。 

例如，考虑：```
100 50 200 150 200
```第一个分数初始化最好和最差记录。 

第二个成绩，`50`，低于以往的每一次分数，因此打破了最差记录。 

第三个得分，`200`，比以往的每一次成绩都高，因此打破了最好记录。 

其余成绩均未打破任何一项记录。 

答案是`2`。 

限制非常小。 比赛次数最多为`1000`，所以即使是一个`O(n²)`解决方案将在时限内顺利通过。 不过，这个问题有一个非常干净的线性解决方案，它扫描一次数组，同时只维护两个值。 

棘手的部分是正确处理平等。 仅当分数严格大于当前最大值或严格小于当前最小值时，分数才算数。 

考虑这个输入：```
4
10 10 10 10
```正确答案是`0`。 

粗心的实现使用`>=`或者`<=`会错误地将重复值视为破纪录的表现。 

另一个微妙的情况是记录重复交替：```
5
100 50 200 25 300
```正确答案是`4`。 

每个新分数都会打破当前的最小值或最大值，并且这两项记录必须在计数事件后立即更新。 

## 方法

 直接的暴力解决方案将每场比赛与之前的所有比赛进行检查。 

比赛用`i`，我们可以扫描比赛`0`通过`i-1`并确定当前分数是严格大于所有先前分数还是严格小于所有先前分数。 

这是有效的，因为出色表现的定义仅取决于早期的比赛。 逻辑很简单，但每个位置都可以与最多`n-1`较早的元素，导致`O(n²)`时间复杂度。 

和`n = 1000`，这仍然可以在限制内轻松运行。 在最坏的情况下，我们执行大约一百万次比较，这对于现代硬件来说是微不足道的。 

更快的方法来自于观察我们实际上并不需要所有以前的分数。 在任何时候，只有两个值很重要：```
current maximum score
current minimum score
```如果下一个分数大于当前最大值，则打破最佳性能记录。 

如果小于当前最小值，则打破最差性能记录。 

处理完分数后，我们更新相应的记录。 

这将问题简化为具有恒定额外内存的单个从左到右扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读比赛次数和成绩列表。 
2. 初始化两者`best`和`worst`与第一个分数。 

第一次比赛就创造了最初的记录，从来都不算惊艳。 
3. 初始化`answer = 0`。 
4. 从第二场比赛开始迭代得分。 
5. 对于每个分数：

 如果分数严格大于`best`, 增量`answer`并更新`best`。 

如果分数严格小于`worst`, 增量`answer`并更新`worst`。 
6.处理完所有分数后，打印`answer`。 

### 为什么它有效

 每一步，`best`存储迄今为止看到的最大分数，并且`worst`存储迄今为止看到的最小分数。 

当我们处理一个新的分数时，只有三种可能：```
score > best
score < worst
worst <= score <= best
```第一个案例意味着程序员取得了新的最高分。 第二种情况意味着新的最低分数。 第三个案例意味着没有打破记录。 

由于算法在计算新记录后立即更新记录，因此在整个扫描过程中不变量保持正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    scores = list(map(int, input().split()))

    best = scores[0]
    worst = scores[0]
    answer = 0

    for score in scores[1:]:
        if score > best:
            answer += 1
            best = score
        elif score < worst:
            answer += 1
            worst = score

    print(answer)

solve()
```该解决方案首先读取输入并使用第一个比赛分数初始化两个记录值。 

循环从第二个元素开始，因为第一次比赛无法打破任何较早的记录。 

这`if`语句检查当前分数是否超过迄今为止看到的最佳分数。 如果确实如此，我们就会计算出惊人的性能并更新最大值。 

这`elif`处理相反的方向。 使用`elif`而不是第二个独立的`if`逻辑上更清晰，因为一个数字不能同时大于当前最大值和小于当前最小值。 

严格的比较是必要的。 相同的分数并不算破纪录的表现。 

该解决方案仅使用常量额外内存，因为它只存储输入数组之外的三个整数。

import io

def solve():

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

 ## 边缘情况

 考虑所有分数都相同的情况：```
4
10 10 10 10
```该算法开始于：```
best = 10
worst = 10
answer = 0
```每个剩余分数都等于两条记录，因此这两个条件都不会触发。 

最终答案依然存在`0`，这是正确的，因为没有发生严格的改善或下降。 

现在考虑重复的最大值：```
3
5 10 10
```处理第二个分数后：```
best = 10
answer = 1
```第三个分数等于`best`，但不超过它。 由于比较的是`>`而不是`>=`，算法正确地避免了再次计数。 

最后，考虑交替记录更改：```
5
100 50 200 25 300
```记录的顺序变为：```
100 -> new minimum 50 -> new maximum 200 -> new minimum 25 -> new maximum 300
```每个新分数都超过当前边界之一，因此答案每次都会增加。 该算法自然地处理了这个问题，因为它会在每次令人惊叹的表现后立即更新跑步记录。
