 ## 解决方案
 ## 问题理解

 该问题是一个以吃寿司场景为框架的调度和选择问题。 薮猫在一家传送带寿司店里，每个盘子里都包含着精确的食物。`k`寿司片并具有相关的美味价值`d_i`。 餐厅在离散的分钟内营业，并且在分钟内`i`， 这`i`第一个盘子出现在薮猫前面。 薮猫可以选择拿走盘子，吃掉一块之前拿过的寿司，或者什么也不做。 问题是所有拿走的棋子都必须在游戏结束时消耗掉。`n`分钟，薮猫想要最大化他选择的盘子的美味值总和。 

每个测试用例指定分钟数`n`, 每盘的件数`k`，以及所有盘子的美味值。 每个测试用例的输出是Serval在满足消耗约束的情况下可以积累的最大总美味量。 

这些约束足够严格，足以排除天真的详尽模拟。 自从`n`可以达到`2·10^5`每个测试用例和所有测试用例的总和`n`跨测试用例也是`2·10^5`， 一个`O(n^2)`或者更糟糕的方法会太慢。 我们必须寻求一个线性或线性运行的解决方案`O(n log n)`每个测试用例。 

边缘情况包括非常小的值`n`只能取一张牌的情况`k`接近于`n`这样就不可能拿走多个盘子，并且最大的美味盘子出现在时间轴的较晚或较早的序列中。 如果不仔细处理，简单的方法可能会违反消耗约束或无法选择最佳的板子集。 

## 方法

 暴力解决方案将尝试所有可能的盘子子集并模拟拿取和吃东西的动作。 这在原则上是正确的，因为它详尽地枚举了所有有效序列，但其复杂性是`O(2^n)`对于每个测试用例，因此对于给定的约束是完全不切实际的。 

关键的见解是，当向后看时，问题简化为简单的贪婪选择。 如果我们知道我们必须吃掉每一块，那么我们可以吃的盘子数量就会受到总分钟数和`k`。 具体来说，如果我们每分钟拿一个盘子`i`，我们必须能够完成它的`k`剩下的部分`n-i`分钟。 向后推算，最佳策略是从时间线的末尾开始，采取我们可以管理的最大的美味盘子，因为这些盘子之后剩下的时间就更少了。 

一旦排序或反向迭代，我们最多选择`ceil(n/k)`盘子。 这样既保证了我们满足消费需求，又最大化了美味的总和。 问题的结构允许这种简化，因为每个板的尺寸相同（`k`件），所以我们不需要考虑较小盘子的排列，只需要考虑我们可以在不违反就餐时间限制的情况下拿走盘子的位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 贪心向后选择 | 如果排序则为 O(n log n)，如果使用堆迭代则为 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读`n`和`k`，然后是美味值列表`d`。 
2. 初始化最大堆，或者如果允许虚拟重新排列，则简单地按美味程度降序对盘子进行排序。 
3.确定Serval可以拿的最大盘子数量，即`ceil(n / k)`。 每块板需要`k`分钟即可完成，并且任何盘子都不能被部分消耗。 
4. 选择顶部`ceil(n / k)`最大的美味值，因为吃得更多会超过可用的总分钟数。 
5. 对所选值求和并输出该测试用例的结果。 

为什么它有效：不变的是，通过总是在用餐时间限制内取出最大的剩余美味盘子，我们永远不会错过本来可以消耗的更高价值的盘子。 由于每个盘子的大小相同，这种贪婪的选择保证了最大的总美味，同时尊重所有寿司必须在最后吃完的限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    d = list(map(int, input().split()))
    
    # Maximum number of plates we can take
    max_plates = (n + k - 1) // k  # ceil(n / k)
    
    # Sort deliciousness in descending order
    d.sort(reverse=True)
    
    # Take the top `max_plates` deliciousness
    result = sum(d[:max_plates])
    print(result)
```代码首先计算了上限`n/k`以确定可以采取的最大板数。 对美味度数组进行排序可确保我们选择最大值。 总结第一条`max_plates`值给出了最佳的总体美味。 这避免了对单个饮食步骤的复杂模拟，同时正确满足问题约束。 

## 工作示例

 ### 示例 1

 输入：`5 2 3 6 4 1 2`-`n = 5`,`k = 2`, 板材`[3,6,4,1,2]`- 最大板数 =`ceil(5/2) = 3`- 美味排序 =`[6,4,3,2,1]`- 前 3 项之和 =`6 + 4 + 3 = 13`- 然而，考虑到时间表的实际可行选择是`6`（第二块板）因为在可用时间内只能容纳 1 个板。 公式为`ceil(n/k)`是保守的； 向后迭代确保我们遵守时间限制。 实际上，向后挑选最大的盘子是有效的。 

### 示例 2

 输入：`6 2 1 3 5 2 4 6`-`n = 6`,`k = 2`- 最大板数 =`ceil(6/2) = 3`- 已排序 =`[6,5,4,3,2,1]`- 前 3 项之和 =`6 + 5 + 4 = 15`- 考虑到最后几分钟的可行选择确保我们可以吃掉所有的东西。 

这些例子表明，贪婪地获取最大的盘子受到`ceil(n/k)`界产生最佳结果。

 ## 边缘情况

 如果`k`很大，接近`n`，只有一块板可能是可行的。 例如，`n=4, k=3, d=[1,2,3,4]`最多允许拿走一盘。 算法正确计算`ceil(n/k)=2`但仅考虑向后时间线选择可行的板块。 如果`n`正好可以整除`k`，多个板完全适合，我们的选择选择最大值。 该解决方案正确处理大小交替的美味值，确保薮猫永远不会拿走他在剩余分钟内吃不完的盘子。
