 ## 问题理解

 我们得到了一个由最多 20 个小字母表构建的字符串集合。对于每个查询字符串，我们需要从集合中选择一个在特定意义上与其兼容的字符串：所选字符串不得与查询字符串共享任何字符。 在所有此类兼容字符串中，我们必须输出字典顺序最小的一个，如果存在多个，我们取其中最小的索引。 如果集合中没有字符串避开查询的所有字符，则答案为 -1。 

关键结构是兼容性仅取决于字符串中出现的字母，而不取决于它们的顺序或多重性。 这立即建议将每个字符串压缩为最多 20 位的位掩码。 

限制很严格：最多 200,000 个字符串和 200,000 个查询，总长度最多 10^6。 任何将每个查询与所有字符串独立比较的解决方案在最坏的情况下都会导致大约 4×10^10 字符检查，这远远超出了可行的限制。 甚至排除了对所有字符串的每个查询线性扫描。 

字母表界限是关键信号。 最多 20 个字母，字母子集形成大小为 2^20 的空间，大约一百万个。 这个值足够小，可以预先计算所有掩码，但也足够大，以至于如果重复 200,000 次，简单的每个查询子集枚举可能仍然太慢。 

当许多字符串共享相同的字符集时，会出现微妙的边缘情况。 例如，如果所有字符串仅包含一个字母，例如“a”，并且查询包含“a”，则每个字符串都是无效的。 正确的答案是 -1，任何忘记按字符集而不是原始字符串内容进行过滤的方法都会错误地假设某些字符串始终可用。 

另一种情况是多个字符串有效但仅字典顺序不同。 例如，如果我们有字符串“abc”和“abd”，并且查询仅包含两者之外的字母，则我们必须返回“abc”，而不是第一个插入的字符串或最短的字符串。 这强制执行仔细的全局排序，而不是每个掩码的任意选择。 

## 方法

 直接方法根据所有字符串检查每个查询。 对于每一对，我们测试它们的字符集是否相交。 这需要为每个字符串和查询构建一个位掩码，然后检查按位 AND。 检查本身是常数时间，但对每一对重复它会导致 O(nq)，这太大了。 

改进来自于注意到具有相同字符掩码的字符串可以合并：对于每个掩码，我们只关心生成它的字典顺序最小的字符串。 在任何查询中，具有相同掩码的任何其他字符串都不会更好。 

经过这个压缩，我们仍然需要回答：给定一个查询掩码 q，在所有掩码 m 中找到最好的字符串，使得 m 和 q 不相交。 用位掩码术语来说，我们希望所有 m 都是 q 的补集的子集。 

这将问题转化为 20 位空间上的经典子集聚合查询。 我们不是检查每个查询的所有子集，而是为每个掩码预先计算其所有子掩码中的最佳答案。 然后每个查询就变成单个数组查找。 

这正是 SOS DP（子集 zeta 变换风格动态规划）所提供的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | 仅蒙版压缩 | O(n + q·2^20) | O(n + q·2^20) | O(2^20) | O(2^20) | 边界|
 | 子集上的 SOS DP | O(2^20 + n + q) | O(2^20 + n + q) | O(2^20) | O(2^20) | 已接受 |

 ## 算法演练

 我们将每个字符串视为超过 20 个字母的位掩码。

1. 将每个字符串转换为位掩码，其中位 i 表示第 i 个字母的存在。 执行此操作时，跟踪每个掩码产生它的按字典顺序排列的最小字符串。 这确保每个掩码都代表其最佳候选者。 
2. 创建数组`best[mask]`使用该精确掩码的最佳字符串进行初始化，如果没有字符串具有该掩码，则为空。 
3. 构建第二个数组`dp[mask]`它将存储所有子掩码中最好的字符串`mask`。 
4. 初始化`dp[mask] = best[mask]`适用于所有口罩。 
5. 对于从 0 到 19 的每个位位置 i，迭代所有掩码。 如果位 i 设置在掩码中，请尝试改进`dp[mask]`使用`dp[mask without bit i]`。 此步骤将最佳值从较小的子掩码传播到较大的掩码。 
6. 对于每个查询字符串，将其转换为掩码`q`。 计算`comp = full_mask XOR q`但限制为 20 位，代表允许的字母。 
7. 答案是`dp[comp]`如果存在，否则-1。 

关键的想法是`dp[comp]`已经包含完全包含在的所有掩码中最好的字符串`comp`，这正是查询中没有共享字符的条件。 

为什么它起作用来自于处理完位 i 后的不变量，每个`dp[mask]`已包含限制为最高 i 位的所有子掩码中的最佳值。 处理完所有位后，这将扩展到所有 20 位，这意味着`dp[mask]`正确覆盖所有子掩码。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q, w = map(int, input().split())
    
    # map letters to bits
    def to_mask(s):
        m = 0
        for c in s.strip():
            m |= 1 << (ord(c) - 97)
        return m
    
    INF = None
    MAXM = 1 << w
    
    best_str = [INF] * MAXM
    best_idx = [-1] * MAXM
    
    for i in range(n):
        s = input().strip()
        m = to_mask(s)
        if best_str[m] is None or s < best_str[m]:
            best_str[m] = s
            best_idx[m] = i + 1
    
    dp_str = best_str[:]
    dp_idx = best_idx[:]
    
    for bit in range(w):
        for mask in range(MAXM):
            if mask & (1 << bit):
                pm = mask ^ (1 << bit)
                if dp_str[pm] is not None:
                    if dp_str[mask] is None or dp_str[pm] < dp_str[mask]:
                        dp_str[mask] = dp_str[pm]
                        dp_idx[mask] = dp_idx[pm]
    
    full = (1 << w) - 1
    
    out = []
    for _ in range(q):
        t = input().strip()
        qm = to_mask(t)
        comp = full ^ qm
        
        if dp_str[comp] is None:
            out.append("-1")
        else:
            out.append(str(dp_idx[comp]))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现依赖于维护两个并行数组：一个用于字典顺序最小的字符串，另一个用于其索引。 DP 步骤小心地从子掩码向上传播更好的候选者。 传播的顺序可确保正确地重用中间改进。 

一个常见的陷阱是尝试向错误的方向传播，例如使用超集而不是子掩码。 这将错误地允许包含禁止字符的字符串影响结果。

 ## 边缘情况

 关键的边缘情况是没有字符串避免查询字符。 例如，如果每个存储的字符串至少包含查询中的一个字母，则补码掩码将变为空或没有包含条目的有效子掩码。 在这种情况下，`dp[comp]`保持未设置并且算法正确返回 -1，因为没有传播可以引入有效的候选者。 

当多个字符串共享相同的掩码时，会出现另一种微妙的情况。 预处理步骤确保仅保留字典顺序最小的字符串，因此以后的 DP 传播不会意外地生成更差的字符串。 

最后，当补码掩码很大时，该解决方案仍然有效，因为所有子集信息都已预先计算。 不会发生每个查询的组合爆炸，并且查找时间保持恒定。
