 ## 解决方案
 ## 问题理解

 三名候选人在选举中获得选票。 目前第一名候选人已`a`票数，第二个有`b`，第三个有`c`。 更多选票可能仍会到来，但只有第一名候选人的额外选票才重要。 

任务是确定必须给予第一位候选人的最少额外选票数，以便在添加这些选票后，第一位候选人至少拥有所有投票的一半。 “至少一半”意味着如果我们将最终投票算作`A`,`B`， 和`C`， 然后`A`必须满足`A ≥ (A + B + C) / 2`，或等价地`2A ≥ A + B + C`。 

输入大小可达`10^9`，这排除了任何一一添加选票的模拟。 任何解决方案都必须是恒定时间，因为即使对可能的额外投票进行线性迭代也会太慢。 

一个微妙的点是如何解释“50%的选票”。 由于投票是整数，因此我们不进行四舍五入处理。 该条件纯粹是算术性的：第一个候选者必须至少拥有总和的一半，而不是严格更多且不四舍五入。 

一个天真的错误是认为我们需要“模拟直到多数”，逐步增加票数。 在大的约束下，这会立即失败，甚至小情况也会不必要地缓慢。 

另一种常见的错误解释是与其他候选者的最大值而不是总数进行比较。 例如，确保`a+x ≥ max(b, c)`是不够的，因为要求的是总和，而不是成对优势。 

## 方法

 暴力方法会尝试增加额外选票的数量`x`从零开始，每次检查第一个候选人是否至少获得总票数的一半。 每次检查都需要重新计算总数并验证不等式，因此成本为 O(1)，但在最坏的情况下`x`可以长到大约`b + c`，使得整体复杂度为 O(b + c)。 值高达`10^9`，这是完全不可行的。 

关键的观察是条件可以用代数方式重写。 添加后`x`得票数，第一名候选人得票数`a + x`，总计为`a + b + c + x`。 要求变为：`2(a + x) ≥ a + b + c + x`扩展和简化消除了对不断变化的总量的依赖，并将问题简化为直接不平等`x`。 这将任务转换为计算单个表达式而不是搜索。 

问题的结构是线性的，因为添加投票会以可预测的方式增加分子和分母。 这种单调性保证了一旦条件成立，它就保持为真，这就是为什么直接求解不等式会给出精确的最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(b + c) | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们想要最少数量的额外选票`x`使得第一位候选人在添加他们后至少拥有总票数的一半。 

1. 计算所有候选人当前的得票总数。 添加新票数之前的总票数为`S = a + b + c`。 
2. 假设我们添加`x`投票给第一位候选人，因此新的计数变为`a + x`，总数变为`S + x`。 
3. 将条件“至少一半”转化为不等式：`2(a + x) ≥ S + x`。 这消除了除法并避免了浮点推理。 
4. 扩大不等式来孤立`x`。 这给出了`2a + 2x ≥ a + b + c + x`。 
5. 通过收集术语来简化：`a + x ≥ b + c`。 
6. 求解`x`，产生`x ≥ (b + c - a)`。 
7. 自从`x`不能为负数，取`x = max(0, b + c - a)`。 

为什么它有效

 这种不平等恰好捕捉到了第一位候选人的份额超过或达到总数一半的点。 该变换消除了分子和分母之间的动态依赖性，并将所有内容简化为单个线性约束。 因为左边比右边增长得快`x`增加，满足不等式的最小整数正是上面计算的阈值，任何较小的值都不满足条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = int(input().strip())
b = int(input().strip())
c = int(input().strip())

x = b + c - a
if x < 0:
    x = 0

print(x)
```实现直接应用导出公式。 每个输入都是独立读取的，不需要额外的处理。 

唯一的微妙之处是确保结果不是负面的。 如果第一个候选人已经有足够的选票来满足条件，则计算值变为负数，我们将其限制为零。

 ## 边缘情况

 当第一位候选人已经获得足够的选票时，派生表达式`b + c - a`变为负数。 对于像这样的输入`a = 100, b = 50, c = 49`，公式给出`-1`，但正确答案是`0`。 夹紧步骤确保正确性。 

对于输入哪里`a = 0`， 例如`0, 1, 1`，公式给出`2`，逐步验证发现，增加两票后，第一名候选人正好达到总票数的一半。 

附近的大值`10^9`行为相同，因为解决方案仅取决于和与差，而不取决于迭代模拟或缩放行为。
