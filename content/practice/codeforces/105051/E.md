 ## 解决方案
 ## 问题理解

 我们给出了一个尺寸的网格$n \times m$，其中每个单元格包含 0 或 1。1 表示单元格中有糖果，0 表示单元格为空。 玩家从左上角的单元格开始，每次移动只能向右移动一步或向下移动一步。 该路径始终在右下角的单元格处结束，因此每个有效路径都是精确访问的单调路径$n + m - 1$细胞。 

每当玩家落在包含 1 的格子上时，他们就会收集到一颗糖果。 关键的观察是不同的路径可能会经过不同的单元组，因此收集到的糖果总数取决于选择的单调路径。 

然后我们得到$q$查询。 每个查询询问是否存在至少一个有效的单调路径，其访问单元的总和恰好等于$s_i$，其中总和是该路径上 1 单元格的数量。 

约束允许最多$10^5$细胞总数和$10^5$查询。 这立即排除了枚举所有路径。 仅单调路径的数量就可以呈指数增长$n + m$，因为它是组合的$\binom{n+m-2}{n-1}$，因此任何尝试直接模拟路径的方法都会失败。 

一个微妙的点是，答案仅取决于所有单调路径上可实现的总和集，而不取决于单个最优路径。 这将问题转化为类似 DAG 结构中路径和的可达性问题。 

当网格极度倾斜时，就会出现边缘情况。 例如，如果$n = 1$，只有一条路径，因此所有答案都是唯一确定的。 另一个极端情况是所有单元格均为 0 或全部为 1 时； 在这两种情况下，可实现的总和集都会折叠为单个值，因此查询变得微不足道。 任何假设路径总和可变而不处理简并结构的解决方案都将在这里失败。 

## 方法

 暴力方法会尝试枚举从左上角到右下角的所有单调路径，计算每条路径上 1 的数量，并将所有可实现的总和存储在一个集合中。 这在概念上是正确的，因为它直接匹配定义。 然而，这在计算上是不可行的，因为路径的数量随着网格大小呈指数增长。 即使对于一个$20 \times 20$网格中，路径的数量已经是巨大的。 

为了超越暴力，关键的观察是网格形成一个有向无环图，其中每个单元仅依赖于其顶部和左侧的邻居。 我们对单独的路径不感兴趣，而是对到达每个单元格时可以实现的可能总和的范围感兴趣。 

这提出了一种动态编程思想，我们不是存储每个单元格的单个最佳值，而是存储可以到达该单元格的所有可能总和的集合。 然而，朴素的集合传播仍然太慢，因为每次合并都可能变得很大。 

关键的结构来自于单调性。 通往单元格的每条路径都必须来自顶部或左侧，并且两个方向都保持顺序。 这使我们能够为每个单元格维护一系列可实现的总和，而不是一个明确的集合。 每个单元格的可能总和的集合形成一个连续的区间，因为我们可以通过网格结构中的局部调整在路径之间进行插值。 这将问题简化为跟踪每个单元格的最小和最大可能总和。 

一旦我们知道了右下单元格中可实现的最小和最大总和，我们就可以在 O(1) 中回答每个查询：区间内的任何值都是可以实现的，区间外的任何值都不是。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 间隔 DP |$O(nm)$|$O(1)$或者$O(nm)$| 已接受 |

 ## 算法演练

 我们定义$dp[i][j]$作为一对$(mn, mx)$，表示在任意单调路径上可收集的糖果的最小和最大数量$(1,1)$到$(i,j)$。 

1. 初始化起始单元。 值在$(1,1)$是 0 或 1，具体取决于网格。 这是所有道路的基础。 
2. 填充第一行第一列。 第一行中的每个单元格只有一种方式可以到达，即从左侧开始，因此其范围继承自前一个单元格加上当前网格值。 相同的逻辑适用于第一列，它仅取决于其上方的单元格。 
3. 对于每个其他单元格$(i,j)$，计算两个候选者：来自上方$(i-1,j)$从左边过来$(i,j-1)$。 其中每一个都贡献一个由当前单元格的值移动的间隔。 新的最小值是所有可能的传入最小值中的最小值，新的最大值是所有传入最大值中的最大值。 
4. 填满整个 DP 表后，读取以下处的值$(n,m)$。 这给出了一个区间$[L, R]$任何有效路径上所有可实现的糖果数。 
5. 对于每个查询$s_i$，输出“YES”如果$L \le s_i \le R$，否则输出“NO”。 

### 为什么它有效

 通往单元的每条路径都必须以从顶部或从左侧移动结束，以便 DP 正确捕获有效子路径的所有可能扩展。 最小值和最大值完全总结了可达范围，因为每个中间路径都可以通过在网格中移动匝数来进行局部变换，从而保持中间和的可达性。 由于没有路径可以跳过单元格或在收集的 1 数量上产生不连续跳跃，因此可实现的总和集在计算范围内不能有间隙。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    # dp[i][j] = (min, max)
    dp = [[(0, 0)] * m for _ in range(n)]

    dp[0][0] = (int(grid[0][0]), int(grid[0][0]))

    for j in range(1, m):
        val = int(grid[0][j])
        mn, mx = dp[0][j-1]
        dp[0][j] = (mn + val, mx + val)

    for i in range(1, n):
        val = int(grid[i][0])
        mn, mx = dp[i-1][0]
        dp[i][0] = (mn + val, mx + val)

    for i in range(1, n):
        for j in range(1, m):
            val = int(grid[i][j])

            up_mn, up_mx = dp[i-1][j]
            left_mn, left_mx = dp[i][j-1]

            mn = min(up_mn, left_mn) + val
            mx = max(up_mx, left_mx) + val

            dp[i][j] = (mn, mx)

    L, R = dp[n-1][m-1]

    out = []
    for _ in range(q):
        s = int(input())
        out.append("YES" if L <= s <= R else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案构建了一个 DP 表，其中每个状态聚合其两个前任状态的可达总和。 第一行和第一列很特殊，因为它们只有一个传入方向，因此要单独处理它们以避免无效转换。 每次转换都会将当前单元格值添加到间隔的两个端点。 

右下角单元格的最后一个区间代表所有可实现的总数，因此每个查询都简化为简单的范围检查。

 ## 边缘情况

 1×1 网格暴露了初始化敏感性。 DP 不得尝试访问邻居，并且必须直接将单个单元值作为间隔的两个端点。 这里的任何差一错误都会立即破坏所有查询答案。 

单行网格测试实现是否错误地尝试从两个方向合并。 由于仅存在左过渡，因此间隔应该确定性地演变。 所提供的 DP 可以处理此问题，因为每个单元仅存在一个前驱。 

全零网格将每个 DP 值压缩为零。 这强调了解决方案是否意外地允许负间隔或虚假间隔。 

全一网格产生最大可能的路径总和，并确保传播正确地累积值，而不会下溢或错误地混合最小/最大。
