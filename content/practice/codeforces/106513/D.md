 ## 解决方案
 ## 问题理解

 我们有一组由潜在高速公路连接的城市，每条高速公路都有固定的建设成本。 这些道路已经形成一个连通的无向图，因此我们知道使用这些边的某些子集始终存在生成树。 

在所有拟议的高速公路中，有一个特定的边缘是强制的：无论如何，它必须出现在最终的连接网络中。 任务是建造一组成本最低的道路，该道路仍然连接所有城市，同时包括这一强制性边缘。 

用图术语来说，这是最小生成树问题，具有附加约束，即一条边是预先选择的并且必须属于生成树。 

输入大小清楚地表明了为什么这是不平凡的。 高达$10^5$顶点和$2 \cdot 10^5$边，任何试图考虑所有子集或每次边修改从头开始重新计算生成树的解决方案都会太慢。 在强制每个可能的边之后对生成树进行简单的重新计算会将 Kruskal 或 Prim 的成本乘以$m$，这远远超出了可行的限度。 

一个微妙的点是，强制一条边实际上会使最优解比全局 MST 更糟糕，因为它可能会创建一个循环，其中该边是最昂贵的成员。 简单地构建正常 MST 然后“添加”所需边缘的粗心实现将是错误的。 

作为一个具体的失败案例，想象三个节点形成一个带边的三角形：```
1 - 2 (cost 1)
2 - 3 (cost 2)
1 - 3 (cost 100)
```如果强制边是$1-3$，正确答案必须包含它，所以我们不能选择自然的 MST 边。 结果变为 1-3 加上其他边之一，成本为 101。简单的 MST 会给出 3，这是无效的，因为它忽略了约束。 

## 方法

 暴力的想法是将强制边视为固定的，然后在端点已连接的剩余图上重新计算最小生成树。 从概念上讲，我们“收缩”所需边的两个端点并再次运行 Kruskal。 

这是有效的，因为包含固定边的生成树相当于图的生成树，其中该边已被选择并且其端点已合并。 然而，如果重复执行或效率低下，直接重新计算看起来仍然很昂贵，因为 Kruskal 本身就是$O(m \log m)$。 

关键的观察是我们不需要以特殊的方式从头开始重建任何东西。 我们可以简单地将边强制进入 DSU 结构，然后再处理所有其他边。 一旦强制边的端点统一起来，我们就对所有边进行标准克鲁斯卡尔排序。 

这是有效的，因为 Kruskal 算法通过始终采用连接两个不同组件的最小边来构建 MST。 通过预先联合所需边的端点并预先添加其成本，我们模拟了该边已被选择的条件，并且所有后续决策都会自然适应。 

唯一的微妙之处在于，必须对强制边进行计数，即使它会因形成循环而被 Kruskal 跳过。 这正是强制联盟所保证的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 通过图收缩强制边缘后重新计算 MST |$O(m \log m)$每次重建 |$O(m)$| 如果重复或天真地实施则太慢 |
 | 带有预装边缘的 Kruskal |$O(m \log m)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 按增加成本对所有边进行排序，并单独标识强制边。 排序确保我们始终首先考虑更便宜的连接，这是 Kruskal 正确性的基础。 
2. 初始化 DSU 结构，其中每个城市都从自己的组件开始。 这会跟踪哪些节点在构建期间已连接。 
3. 立即合并强制边的端点并将其成本添加到答案中。 此步骤会在任何其他决策之前强制将边缘引入结构，确保以后永远不会将其排除。 
4. 按排序顺序迭代所有边。 对于每条边，检查其端点是否属于不同的 DSU 组件。 
5. 如果它们位于不同的组件中，则将边包含在答案中并合并组件。 这可以保留连接性，同时避免循环，与标准 MST 构造完全相同。 
6. 如果它们已经连接，则跳过该边缘。 添加它会形成环，并且不能降低生成树的成本。 

### 为什么它有效

 Kruskal 的算法依赖于这样的特性：在任何点，所选择的边在经过处理的边前缀上形成最小成本森林。 通过预联合强制边的端点，我们强制该边是初始森林的一部分，无论其权重如何。 从那时起，每个决策都与在两个顶点已经连接的图上运行 Kruskal 相同，这相当于强制该边进入跨越结构。 贪婪选择属性被保留，因为所有剩余的边仍然按全局递增顺序处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def main():
    n, m = map(int, input().split())
    j = int(input()) - 1

    edges = []
    forced = None

    for i in range(m):
        u, v, c = map(int, input().split())
        edges.append((c, u, v, i))
        if i == j:
            forced = (c, u, v)

    edges.sort()

    dsu = DSU(n)
    ans = 0

    fc, fu, fv = forced
    ans += fc
    dsu.union(fu, fv)

    for c, u, v, _ in edges:
        if dsu.union(u, v):
            ans += c

    print(ans)

if __name__ == "__main__":
    main()
```DSU 实现通过迭代减半和按大小并集来使用路径压缩，从而有效地保持操作时间恒定。 关键的实现细节是在任何处理之前而不是之后添加强制边缘成本，否则如果它在最终结构中形成循环，则可能会错误地跳过它。 

排序步骤确保保留 Kruskal 的全局贪婪顺序。 并集检查确保我们永远不会创建循环，这是至关重要的，因为即使一条边是强制性的，生成树也必须保持非循环。

 ## 边缘情况

 当强制边缘已经属于自然 MST 时，算法仍然可以正常工作，因为预联合不会改变后续决策。 例如，在线图中，强制中间边缘简单地反映了标准 Kruskal 行为。 

当强制边缘在一个周期中最昂贵时，DSU仍然会首先接受它，所有更便宜的边缘最终都会连接组件。 这表明贪婪结构没有被违反，只是在初始化时受到约束。 

当图已经与精确最小连接时$n-1$边缘，强制任何边缘只是增加成本，算法的其余部分不执行并集，这正确地生成包含所需边缘的唯一生成树。
