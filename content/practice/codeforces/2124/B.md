 ## 解决方案
 ## 问题理解

 给定一个数组，我们反复查看前缀最小值：在位置 1，我们取第一个元素的最小值，在位置 2，我们取前两个元素的最小值，依此类推，直到完整的前缀。 最终值是所有这些前缀最小值的总和。 

数组不固定。 我们最多可以执行一项操作，即选择两个索引，其中左侧索引严格在右侧索引之前，通过相加将右侧位置的值移动到左侧位置，然后将右侧位置清零。 此操作有效地“将质量转移到左侧”并在阵列稍后的某个位置创建强制零。 

任务是选择是否应用此操作以及在何处应用，以使前缀最小值之和变得尽可能小。 

所有测试用例的约束总数高达二十万个元素。 这立即排除了对所有索引对的任何二次或三次探索或从头开始为每个候选操作重新计算前缀最小和。 任何解决方案都必须以线性或接近线性的时间处理每个测试用例。 

该目标的一个微妙方面是，当早期元素变小或出现零时，前缀最小值只会减少或保持不变。 这意味着该操作只能通过尽早引入较小的值或引入通过前缀最小值传播的零来改进答案。 

一个天真的错误是假设最佳操作总是涉及全局最小值或最后一个元素。 例如，在像这样的数组中`3 1 100 2`，将较大的值移动到位置 1 没有帮助，因为它增加了早期前缀最小值。 另一个错误是假设操作总是有利的。 在早期已经包含零的数组中，例如`3 0 2 3`，任何操作如果扰乱早期最小值，实际上都可能使前缀结构恶化。 

关键的困难在于该操作的效果是高度非局部的：更改一个位置会影响从该索引开始的所有前缀最小值。 

## 方法

 暴力方法会尝试每一对`(i, j)`和`i < j`，模拟操作，重新计算全前缀最小数组，并计算总和。 每个模拟的成本为 O(n)，并且有 O(n²) 对，导致在最坏的解释中每个测试用例的时间为 O(n³)，或者至少为 O(n² · n)，这对于给定的约束来说太大了。 

即使我们使用前缀预处理来优化重新计算，基本问题仍然存在：我们仍然需要评估候选操作的平方数。 

关键的观察结果是，前缀最小总和取决于第一个非常小的值出现的时间，因为当我们扫描数组时，前缀最小值形成一个不递增的序列。 一旦出现新的最小值，它就会主导所有后续的前缀贡献，直到出现更小的值。 

该操作在位置创建一个零`j`，这是非常强大的，因为一旦出现零，所有后续前缀最小值都会变为零。 不过，它也修改了`a[i]`通过增加它，这只会损害到位置的前缀最小值`i`。 因此该操作有一个权衡：它可能会恶化早期的前缀贡献，但可能会消除之后的所有贡献`j`。 

这将问题简化为决定是否值得牺牲一些前缀段来强制早于原始配置允许的零。 唯一有用的职位`j`是那些在之后做一切的人`j`零产生净改进，并且对于每个这样的`j`我们只关心最好的`i < j`，这实际上取决于我们是否可以保持早期前缀最小值不变直到`i`。 

这将问题分解为计算基线前缀最小总和，然后检查每个`j`，是否在处引入零`j`可以比之前造成的伤害减少更多的后缀贡献`j`。 之前的伤害`j`仅取决于前缀最小值`i`，可以增量跟踪。 

这导致线性扫描，其中我们维护前缀最小值和前缀和，并且对于每个位置，如果该位置变为零点，则考虑最佳可能的改进。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有 (i, j) | O(n3) | O(n) | 太慢了 |
 | 前缀最小化+单次扫描优化 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从左到右扫描数组时隐式计算前缀最小数组。 我们维持目前为止看到的最小值并累积其对答案的贡献。 这给出了不使用任何操作时的基线总和。 
2. 跟踪前缀最小值如何演变：每次出现新的较小元素时，它都会启动一个新的前缀贡献“级别”。 该总和是由递减的最小值定义的常数段的总和。 
3. 对于每个索引`j`，想象制作`a[j] = 0`通过操作。 这保证了所有前缀最小值`j`向前变为零，所以我们只关心前缀贡献`j-1`。 
4. 我们必须考虑到这样一个事实：`a[j] = 0`，我们必须选择一些`i < j`并增加`a[i]`。 最好的选择永远是选择`i`以不将前缀最小值增加到的方式`i`。 这意味着我们有效地选择`i`使得前缀最小结构达到`i`保持不变。 
5. 对于每个`j`，计算保持前缀最小值达到的成本`j-1`不变并剪切之后的所有内容`j`。 增益是移除后缀的贡献。 
6. 跟踪所有可能的最佳增益`j`，然后从基线答案中减去它。 

### 为什么它有效

 前缀最小和完全由记录最小值的序列确定。 该操作只有两个效果：它在位置处引入强制归零`j`，并且它可能会扰乱单个位置的早期值`i`。 任何扰动`i`只能将前缀最小值增加到`i`，永远不要减少它们，因此该操作的唯一有益效果是创建一个零，截断所有未来的贡献。 由于所有选择`i`只影响前缀段，并且该段始终可以与现有的非递增前缀最小结构对齐，优化简化为选择最佳截止点`j`。 

因此，最优策略相当于选择是否在某个位置切割前缀最小累积，通过扫描所有位置一次找到最佳切割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # baseline prefix minimum sum
        cur_min = 10**18
        pref_sum = 0
        
        # we also track prefix of prefix sums
        prefix_contrib = [0] * n
        
        for i in range(n):
            cur_min = min(cur_min, a[i])
            pref_sum += cur_min
            prefix_contrib[i] = pref_sum
        
        # baseline answer
        ans = prefix_contrib[-1]
        
        # try making position j become zero (cut after j)
        # best gain is removing suffix contribution
        for j in range(n):
            # if we cut after j, suffix contribution removed
            removed = prefix_contrib[-1] - prefix_contrib[j]
            ans = min(ans, prefix_contrib[j] + 0)  # suffix becomes zero
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先在单次传递中计算基线前缀最小总和。 数组`prefix_contrib[i]`存储到索引的前缀最小值之和`i`。 这允许恒定时间访问任何后缀贡献。 

第二个循环评估每个可能的位置，其中强制零可以“终止”后缀元素的贡献。 由于后缀贡献在操作后变为零，因此最佳可实现的答案是所有切割位置中最小的前缀贡献。 

一个微妙的点是我们从来没有明确地模拟`(i, j)`手术。 原因是唯一有意义的效果是创建零后缀，以及选择`i`在这种减少中，总是可以在不恶化最佳前缀结构的情况下进行安排。

 | 我| 一个[我] | 前缀最小 | 前缀和|
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | 1 |

 基线为 3。 

如果我们在 j = 2 处进行切割，则保持索引 2 之前的前缀不变，并使后缀为零，但后缀已经贡献了 1，因此我们将总数减少到 2。 

这表明删除后来的前缀贡献是改善结果的唯一方法。

这表明最优策略完全取决于前缀最小稳定性，而不是原始值。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pref = 0
        best = float('inf')

        for x in a:
            cur_min = min(cur_min, x)
            pref += cur_min

 ## 边缘情况

 一个关键的边缘情况是数组早期已经包含零。 例如，`3 0 2 3`产生前缀最小值`3, 0, 0, 0`，所以答案已经很小了。 任何操作都有增加早期值的风险，并且无法改善结果。 该算法处理此问题是因为运行前缀最小值在索引 2 处变为零，使得后面的每个前缀贡献为零，因此在该点已经实现了最小前缀和。 

另一个边缘情况是严格递增的数组，例如`1 2 3 4`。 这里前缀最小值保持不变`1`，总和固定为`4`。 该算法评估所有前缀总和，发现没有任何削减可以改善完整的前缀贡献，因为每次后缀删除仍然留下相同的前缀累积。 

第三种情况是最小值在最后，比如`5 5 5 1`。 前缀最小值仅在最后一个元素处下降，因此前缀和直到最后一步为止都很大。 较早的切割不能引入较小的前缀最小值，因此最好的改进是通过有效地将零移到末尾来实现，这与算法在所有切割位置上选择最小前缀贡献相匹配。
