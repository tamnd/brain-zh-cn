 ## 解决方案
 ## 问题理解

 我们得到一个数组`a`。 我们想要选择一个子序列并将其重新解释为一个新数组`b`。 目标是最大化长度`b`，受`b`是一个_good_数组。 

善良的定义是用排列和范围最小值来写的。 乍一看它与子序列无关，但真正的任务是了解哪些数组`b`实际上可以从该结构中出现。 

价值`b_i`表示结束于的段的最左边位置`i`其最小值恰好出现在位置`i`。 由于排列包含不同的值，因此每次比较都是严格的。 事实证明，隐藏在定义中的结构比排列本身重要得多。 

原数组的长度最多为`15000`，以及总和`n²`所有测试用例最多是`15000²`。 这是一个非常强烈的暗示。 一个复杂的解决方案`O(n²)`是有意的。 三次算法大约需要`3·10¹²`在最坏的情况下操作是完全不可行的。 二次动态规划解，约`2.25·10⁸`所有测试的简单操作正是这些约束的设计范围。 

一些边缘情况很容易被错误处理。 

考虑：```
a = [2,2,2,2]
```一个诱人的想法是，平等的价值观总是可以链接在一起。 他们不能。 任何好的数组都必须包含一个其值等于其自身索引的位置。 由于每个值都是`2`，不存在非空的好子序列。 正确答案是`0`。 

考虑：```
a = [1]
```单个元素已经满足所需的结构。 答案是`1`。 

考虑：```
a = [1,1,2]
```整个顺序不太好。 仅基于局部不平等的天真检查会错误地接受它。 最长的好子序列是`[1,2]`，其长度为`2`。 

这些例子表明，关键的困难不是选择位置，而是描述哪些序列实际上是好的。 

## 方法

 蛮力的想法很简单。 枚举每个子序列，测试它是否良好，并保留最大长度。 

对于长度的数组`n`， 有`2^n`子序列。 即使是为了`n = 60`这已经是无望了，而这里`n`可以达到`15000`。 蛮力方法仅作为概念起点。 

真正的突破来自于理解好的数组的结构。 

让`b_i = x`。 看看范围最小解释，位置`x`本身必须是有效块的开始。 展开定义后，我们可以得到以下特征：

 一个序列`b`当且仅当对于每个位置都是好的`i`和`b_i = x`，以下其中一项成立：

 1.`x = i`。 
2.`b_x = x`以及该段上的每个值`[x, i]`至少是`x`。 

这完全消除了问题中的排列。 我们只需要推理索引和值。 

现在想想每个位置`x`满意的`b_x = x`作为块的根。 任何稍后出现的值`x`必须属于该块，并且该块内的所有值必须至少`x`。 

这自然会导致区间动态规划。 我们处理可能的块根并将它们向右延伸。 每当我们遇到更大的值时，我们就可以开始一个嵌套块。 关键的观察是，应尽早贪婪地选择此类嵌套块的起始位置。 这使得所有转换都可以在二次时间内实现。 

由此产生的 DP 完全适合`Σ n² ≤ 15000²`约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n · n)`|`O(n)`| 太慢了|
 | 最佳DP |`O(n²)`|`O(n²)`| 已接受 |

 ## 算法演练

 ### 状态定义

 让`dp[i][j]`表示区间内可以形成的好子序列的最大长度`[i, j]`在以下条件下：

 - 位置`i`被选择，
 - 它的值充当块根，
 - 位置`j`是该根值在构造的子序列中的最后一次出现。 

编辑实现正是存储这个数量。 

### 过渡建设

 1. 处理起始位置`i`从右到左。 
2. 初始化以根为根的块`i`。 

最小的有效子序列仅由出现的`a[i]`。 最初：```
dp[i][i] = a[i]
```变量`curr`存储迄今为止获得的最佳值。 
3. 延伸右端点`j`。 
4.如果`a[j] < a[i]`，该元素不能属于当前块。 

表征要求块内的每个值至少是根值。 
5.如果`a[j] = a[i]`，我们可以免费附加此事件。 

增加`curr`按一并设置：```
dp[i][j] = curr
```6. 如果`a[j] > a[i]`，该元素可能成为嵌套块的根。 

维护一个数组`good[v]`。`good[v]`存储其值为的最早位置`v`并且其 DP 值已经足够大以支持类型块`v`。 
7. 当存在这样的嵌套块时，将其合并到当前结构中：```
curr = max(curr, dp[idx][j])
```在哪里`idx = good[a[j]]`。 
8. 继续，直到处理完所有端点。 

### 提取答案

 计算完所有间隔状态后，在整个数组上再次运行相同的转换逻辑。 

每当有效根可用时，请使用其相应的根`dp`值来更新全局答案。 

最终值`curr`是最长的好子序列的长度。 

### 为什么它有效

 好的数组的特征表明，每次出现值`x`必须属于以该值也为根的位置的块`x`。 

在这样的块内，所有值必须至少为`x`。 这意味着永远无法附加较小的值，相等的值始终扩展块，而较大的值只能通过其根已经递归满足相同属性的嵌套块出现。 

DP 状态准确存储块根的最佳可实现长度和固定的最后一次出现。 每个有效的好子序列都可以分解为这些嵌套块，并且 DP 执行的每个转换都对应于一次合法的分解。 由于最早的可行根对于未来的扩展始终是最佳的，因此使用的贪心选择`good[]`永远不会失去更好的解决方案。 

因此，每个有效的好子序列都被考虑，并且DP产生的每个子序列都满足特征化。 算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    dp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n, 0, -1):
        good = [-1] * (n + 1)

        curr = a[i]
        dp[i][i] = curr

        for j in range(i + 1, n + 1):
            if a[j] < a[i]:
                continue

            if a[j] == a[i]:
                curr += 1
                dp[i][j] = curr
                continue

            if good[a[j]] == -1 and a[j] <= curr + 1:
                good[a[j]] = j

            if good[a[j]] != -1:
                idx = good[a[j]]
                curr = max(curr, dp[idx][j])

    curr = 0
    good = [-1] * (n + 1)

    for j in range(1, n + 1):
        if good[a[j]] == -1 and a[j] <= curr + 1:
            good[a[j]] = j

        if good[a[j]] != -1:
            idx = good[a[j]]
            curr = max(curr, dp[idx][j])

    print(curr)

t = int(input())
for _ in range(t):
    solve()
```外循环计算每个区间状态`dp[i][j]`。 加工`i`从右到左保证未来转换所需的所有嵌套块都已被计算。 

数组`good`为每个起始位置重建。 它记录每个值的最早可用的根。 仅存储第一个这样的位置就足够了，因为较早的根支配较晚的根。 

一个微妙的点是条件：```
a[j] <= curr + 1
```植根于价值的区块`v`至少需要`v - 1`在开始之前就已经构建了位置。 这个条件正是可行性检验。 

另一个微妙的细节是带有`a[j] < a[i]`被完全跳过。 允许它们会违反特征定理并创建无效块。

 ## 边缘情况

 考虑：```
1
4
2 2 2 2
```在全球阶段，价值`2`永远不能成为有效的根，因为当前可实现的长度永远不会达到`1`在必须创建根之前。 没有 DP 状态变得可用，答案仍然存在`0`。 这与特征相匹配，因为非空的好序列必须包含某个位置`i`有价值`i`。 

考虑：```
1
1
1
```唯一的位置同时是根和其块的末尾。 DP初始化`dp[1][1] = 1`，全局阶段立即恢复答案`1`。 

考虑：```
1
3
1 1 2
```前两个元素创建一个以 value 为根的块`1`。 当最终值`2`检查后，DP 检测到完整序列所需的嵌套结构不存在。 The best valid subsequence remains length`2`，对应于`[1,2]`。 

这些示例说明了两个最常见的陷阱：假设相等的值始终可以链接，并忽略每个块必须源自有效根的要求。
