 ## 解决方案
 ## 问题理解

 我们有几堆石头。 每块石头都有一个类型，而石头也有类型`i`最后一定会变成一堆`i`。 一次移动将当前位于非空堆顶部的石头移至另一堆顶部。 目标不是最小化移动次数，只是在允许的限制内产生有效的序列。 

输入描述了初始堆栈。 对于每一堆，我们知道它包含多少块石头以及这些石头从上到下的类型。 输出是移动列表，其中每个移动指定源桩和目标桩。 

约束足够大，以至于尝试搜索可能的移动是不可能的。 最多约`10^5`石头，任何探索状态或在每次移动后重复扫描整个配置的方法都会变得太慢。 我们需要一种每块石头仅被处理固定次数的结构。 

棘手的部分是我们无法自由地访问一堆中间的石头。 只有最上面的石头可以移动，因此尝试直接从每一堆中提取每种类型的方法会被卡住，因为放置不正确的石头可能会阻挡它们下面的石头。 

一个小例子说明了直接排序失败的原因：```
1
3
2 1 3
```如果我们尝试移动类型`1`石头直接堆成`1`，它被埋在类型下面`3`石头。 唯一合法的第一步是移走顶上的石头。 假设随机访问堆栈内容的粗心解决方案会产生无效的移动。 

另一个边缘情况是当一堆已经只包含其正确类型时：```
1
3
1 1
2 2
3 3
```答案可以为空，因为配置已经解决了。 始终执行设置移动而不检查当前状态的解决方案可能仍然有效，但它会浪费移动并且可能超出较大情况的限制。 

关键是暂时收集石头，然后重建正确的石堆，同时尊重堆叠顺序。 

## 方法

 暴力解决方案会将每个可能的移动视为搜索图中的转换。 根据给定的安排，我们可以尝试每个源堆和每个目标堆，递归搜索直到每个堆都排序。 这是正确的，因为每一个有效的最终安排都必须通过一系列合法的行动来达成。 

问题在于可能的安排数量呈爆炸式增长。 即使只有几堆，石头也可以以多种不同的顺序分布在许多堆中，因此状态空间远远超出了我们可以探索的范围。 和`10^5`石头，这根本不可能。 

有用的观察是我们不需要最短序列。 我们只需要任何有效的序列。 这使我们能够创建一个确定性的过程。 

桩`1`和桩`2`可以用作工作区域。 首先，我们将每块石头移入堆中`1`，为我们提供了一个可以一颗一颗检查石头的地方。 加工桩时`1`，每块目的地都不是堆的石头`1`也不堆`2`可以立即到达其最终位置。 石头的类型`1`和`2`很特别，因为桩`1`和`2`被用作临时存储。 

完成这一关后，堆放`2`仅包含 类型的宝石`1`和`2`。 移动型`1`石头回到堆`1`，这让我们可以重复过滤过程，同时输入`2`石头堆起来`3`暂时地。 最后剩下的类型`2`石头可以从堆顶移走`3`回到堆里`2`。 

建筑之所以有效，是因为每块放错位置的石头总是被移近它的最终堆，并且不需要检查任何石头超过恒定的次数。 这与官方社论中描述的线性结构相同。

 ## 算法演练

 1. 将每一堆作为一个堆栈来读取。 输入从上到下列出了石头，因此我们在内部以相反的顺序存储它们，以便最后一个元素始终是当前的顶部。 
2. 移走石堆中的每一块石头`2`通过`M`成堆`1`。 这将创建一个包含所有石头的工作堆。 每个动作都记录在答案中。 
3.边堆边`1`仍有石头，检查其顶部的石头。 如果石头有类型`1`或者`2`，将其移动到堆上`2`。 否则，将其直接移至最后一堆，因为以后的操作不需要打扰它。 
4.边堆边`2`仍然有石头，检查顶部的石头。 移动类型`1`石头回到堆`1`，因为它们仍然需要与临时存储区分开。 移动类型`2`堆石头`3`，用作临时位置。 
5. 堆顶时`3`是一种类型`2`石头，将其移回堆中`2`。 完成这一步后，堆`2`仅包含类型`2`石头。 

为什么它有效：

 重要的不变量是，在步骤 3 之后，除了临时堆之外的每一堆都只包含其正确类型的石子。 唯一未解决的问题是类型`1`和`2`，因为那些是用于临时存储的堆。 步骤4分离这两种类型，步骤5删除临时类型`2`堆里的石头`3`。 由于每块石头最终都会被放入与其类型相匹配的堆中，因此最终的配置是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = input().split()
    if not data:
        return
    n, m = map(int, data)

    piles = [[] for _ in range(m + 1)]

    for i in range(1, m + 1):
        row = list(map(int, input().split()))
        cnt = row[0]
        stones = row[1:]
        piles[i] = stones[::-1]

    ans = []

    def move(a, b):
        ans.append((a, b))
        piles[b].append(piles[a].pop())

    for i in range(2, m + 1):
        while piles[i]:
            move(i, 1)

    while piles[1]:
        t = piles[1][-1]
        if t == 1 or t == 2:
            move(1, 2)
        else:
            move(1, t)

    while piles[2]:
        t = piles[2][-1]
        if t == 1:
            move(2, 1)
        else:
            move(2, 3)

    while piles[3] and piles[3][-1] == 2:
        move(3, 2)

    out = [str(len(ans))]
    out.extend(f"{a} {b}" for a, b in ans)
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```输入转换是第一个微妙的实现细节。 由于该语句从上到下给出了石头，因此反转每一堆让`pop()`在恒定的时间内到达顶部的石头。 

这`move`helper 负责记录操作并更新模拟堆栈。 将这两个操作放在一起可以防止输出序列和内部状态不一致时出现错误。 

第一个循环只收集石头，从不尝试对它们进行分类。 接下来的两个阶段执行实际的分离。 桩的特殊处理`1`,`2`， 和`3`是故意的，因为这些是唯一暂时包含不正确石头的堆。 

Python 整数是无界的，因此不存在溢出问题。 主要限制是存储的移动次数，它是线性的，因为每个阶段最多移动每个石头一次。

 ## 边缘情况

 当所有石子都已位于目标堆中时，该算法仍然有效，因为将所有石子移入堆中`1`重建它们总是有效的。 输出允许包含不必要的移动，因此正确性不依赖于保留初始排列。 

当一块石头的类型`1`或者`2`被埋在其他石头下，算法不会尝试直接访问它。 它首先从顶部移除阻挡的石头，这就是为什么将所有石头收集成堆的原因`1`很有用。 

当棋子很多时，移动的次数仍然有限。 每个阶段仅扫描当前在其工作堆中的石头，并且没有阶段重复搜索已经完成的堆。 这使施工保持在产量限制之内。
