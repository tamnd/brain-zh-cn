 ## 解决方案
 ## 问题理解

 该问题描述了一棵树，其边具有整数权重。 在两个顶点之间移动的成本不是树路径上边权重的总和。 相反，两个顶点之间直接移动的成本是其唯一树路径上所有边权重的按位异或。 我们可以使用任何移动序列，因此任务是找到从选定的起始顶点到每个其他顶点的最短可能距离，然后输出这些距离的总和。 

树是动态的。 更新操作将相同的值异或到每个边权重中。 查询操作询问距一个指定顶点的总最短距离。 

关键观察从约束开始。 一棵树的值最大为`n`并且许多查询无法在每次更新后重新计算所有距离。 对于每个查询遍历树的任何解决方案都将变成二次的。 我们需要将每个查询减少到少量工作，通常是顶点数量的对数。 

用 XOR 路径值表示树的一种有用方法是将其在任何顶点处建立根并定义`value[v]`作为从根到路径上边权重的异或`v`。 两个顶点之间的异或距离`u`和`v`变成`value[u] ^ value[v]`。 

XOR 距离完整图中的最短路径始终是直接 XOR 距离。 对于任意中间顶点`x`，每一位之间的差异`u`和`v`恰好有助于其中之一`(u ^ x)`和`(x ^ v)`，而相同的位数只能增加额外的成本。 因此使用中间顶点并不能使距离变小。 

这将问题转变为维护查询值与所有存储值之间的 XOR 之和。 

全局边缘更新具有特殊的结构。 如果树是有根的，则奇数深度的每个节点的根 XOR 值都会由更新值切换，而偶数深度的每个节点保持相同的值。 这意味着顶点根据深度奇偶性自然分为两组。 

棘手的情况与这种奇偶校验分裂有关。 如果所有顶点都作为一组处理，则更新将破坏存储的值。 

例如，考虑：```
3 2
1 2 5
2 3 7
1 1
2 1
```最初，以顶点 1 为根，值为`0, 5, 2`。 第一个查询询问距顶点 1 的距离：```
0^0 + 0^5 + 0^2 = 7
```更新所有边后`1`，值变为`0, 4, 2`因为只有奇数深度顶点发生变化。 对每个存储值进行异或的解决方案`1`会错误地得到`1, 4, 3`。 

另一个边缘情况是单个顶点树：```
1 1
2 1
```答案是`0`。 没有边，并且从唯一的顶点到其自身的距离为零。 假设至少有一条边的代码可能会在这里失败。 

第三个重要的情况是当查询的顶点处于奇数深度时。 顶点自身的存储值在更新后发生变化，并且仅当与另一个奇数深度顶点进行比较时更新才会取消。 忘记这一点会导致奇数深度顶点的查询得到错误的答案。 

## 方法

 最简单的方法是计算每个查询的每个最短距离。 由于两个顶点之间的最短距离只是它们根值的异或，因此我们可以存储所有根值，并且对于每个查询迭代每个顶点并添加`value[s] ^ value[i]`。 

这种方法是正确的，因为它直接评估答案的定义。 然而，随着`n`顶点和`q`查询，它执行`O(nq)`异或运算。 当两个值都很大时，这会变得太慢。 

有用的观察是查询并不要求任意对。 它要求一个数字与一组固定数字之间的 XOR 之和。 二进制特里树可以通过独立地决定每个位来有效地回答此类查询。 在每一位上，最好的贡献来自于知道有多少数字在该位上有 0 或 1。 

剩下的困难是全局边缘更新。 每次更新后重建所有值是不可能的。 宇称观测解决了这个问题。 我们保留两个二进制尝试：一种用于偶数深度顶点，一种用于奇数深度顶点。 奇数深度 trie 支持惰性 XOR 标记，因为它的所有逻辑值在每次更新后都会移动相同的数字。 

当查询到达时，我们确定源顶点的当前逻辑值，并要求两次尝试进行异或和。 每个 trie 查询都需要对数时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了 |
 | 最佳 | O((n + q) log A) | O(n log A) | O(n log A) | 已接受 |

 这里`A`是最大可能的取值范围，最多为`2^30`，所以特里树高度为 30。 

## 算法演练

 1. 以顶点为树根`1`并运行 DFS。 在遍历过程中，计算`value[v]`，从根到边权重的异或`v`，以及每个顶点的深度奇偶性。 根据深度是偶数还是奇数将这些值存储在两组中。 
2. 为每个奇偶校验组构建一个二进制特里树。 trie 存储该组中的所有当前逻辑值。 奇数深度 trie 还保留一个惰性 XOR 值，表示尚未推送到结构中的更新。 
3. 有价值的更新`x`，仅将 XOR 延迟应用于奇数深度 trie。 偶数深度的顶点不会改变，而奇数深度的顶点都接收相同的 XOR。 
4. 对于来自顶点的查询`s`，求其当前值。 如果`s`深度均匀，不变。 如果`s`具有奇数深度，其当前值为`value[s] ^ lazy_xor_of_odd_group`。 
5. 询问两次尝试与该值的异或距离之和。 将两个结果相加并打印答案。 

为什么它有效：

 不变的是每个 trie 总是准确地表示其奇偶校验组中所有顶点的当前根 XOR 值。 惰性标签不会改变存储的物理结构，它只会改变存储的数字的解释方式。 trie 查询通过相同的惰性 XOR 转换请求的值，使比较相当于与实际的当前值进行比较。 

由于两个顶点之间的最短距离正是它们的根值的异或，因此将两个 trie 结果相加就可以精确地给出所需的总距离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

BITS = 30

class Trie:
    def __init__(self):
        self.child = [[-1, -1]]
        self.cnt = [0]
        self.sum = [[0] * 2]
        self.lazy = 0

    def add(self, x):
        node = 0
        self.cnt[node] += 1
        for b in range(BITS - 1, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] == -1:
                self.child[node][bit] = len(self.child)
                self.child.append([-1, -1])
                self.cnt.append(0)
                self.sum.append([0, 0])
            self.sum[node][bit] += 1 << b
            node = self.child[node][bit]
            self.cnt[node] += 1

    def query(self, x):
        x ^= self.lazy
        node = 0
        ans = 0
        for b in range(BITS - 1, -1, -1):
            if node == -1:
                break
            bit = (x >> b) & 1
            same = self.child[node][bit]
            diff = self.child[node][bit ^ 1]
            if diff != -1:
                ans += self.cnt[diff] * (1 << b)
                node = same
            else:
                node = same
        return ans

    def xor_all(self, x):
        self.lazy ^= x

def solve():
    n, q = map(int, input().split())
    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, w))
        graph[v].append((u, w))

    val = [0] * n
    depth = [0] * n

    stack = [(0, -1)]
    while stack:
        u, p = stack.pop()
        for v, w in graph[u]:
            if v != p:
                val[v] = val[u] ^ w
                depth[v] = depth[u] ^ 1
                stack.append((v, u))

    even = Trie()
    odd = Trie()

    for i in range(n):
        if depth[i] == 0:
            even.add(val[i])
        else:
            odd.add(val[i])

    out = []
    for _ in range(q):
        query = list(map(int, input().split()))
        if query[0] == 1:
            odd.xor_all(query[1])
        else:
            s = query[1] - 1
            cur = val[s]
            if depth[s]:
                cur ^= odd.lazy
            out.append(str(even.query(cur) + odd.query(cur)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS 部分将树表示转换为 XOR 标签。 转换后，树的确切形状不再重要，因为每对距离仅取决于两个标签。 

trie 插入存储由奇偶校验分隔的初始值。 特里树本身是一个普通的二进制特里树，它计算通过每个分支的值的数量。 在查询期间，选择相反的位会产生以下贡献：`2^b`对于该分支中的每个数字，这就是为什么可以从高位到低位贪婪地累积答案的原因。 

奇数特里树中的惰性字段是主要的实现细节。 我们绝不会在更新后修改每个存储的值。 相反，查询操作通过使用相同的惰性掩码转换请求的值来逻辑地应用待处理的异或。 这避免了重建特里树。 

源顶点值也必须遵守延迟更新。 仅奇数深度顶点发生变化，因此来自奇数深度顶点的查询使用`value[s] ^ odd.lazy`，而偶数深度的顶点则使用其原始值。

 ## 边缘情况

 对于单个顶点树，两个尝试仅包含一个值。 来自该顶点的查询询问其自身的距离，并且 trie 正确返回零，因为唯一的 XOR 比较是`0 ^ 0`。 

对于所有顶点都在一条长链中的树，许多顶点在偶数和奇数深度之间交替。 更新恰好更改了一半的顶点，因此解决方案成功，因为它将两组分开，而不是假设整个树均匀更改。 

对于从奇数深度顶点开始的查询，算法首先将奇数组惰性 XOR 应用于源值。 这是必要的，因为源顶点本身属于更新的组。 然后，这两个 trie 查询与确切的当前标签进行比较，产生正确的总和。
