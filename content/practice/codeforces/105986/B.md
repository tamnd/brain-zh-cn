 ## 问题理解

 我们给出了一组节点，其中节点 1 是所有距离的源，并且我们还给出了一组端点完全灵活的加权边。 每条边仅带有一个权重，我们可以决定它连接哪两个不同的节点，唯一的限制是没有边可以将节点连接到自身，而同一对之间允许有多个边。 

将端点分配给所有边后，生成的无向加权图会得出从节点 1 到每个其他节点的最短路径距离。 要求是这些最短路径距离必须与目标阵列完全匹配。 任务不是构建这样一个图，只是确定是否存在至少一个有效的分配。 

约束足够小，每个测​​试用例的二次或稍微超线性的解决方案都是可以接受的。 每个测试用例最多有 500 个节点和 500 个边，即使是对边权重进行排序和使用贪婪匹配的方法也完全在限制范围内，而任何涉及枚举所有端点分配的方法都太大了，因为它会像 n²ᵐ 一样增长。 

这个问题的一个微妙的方面是边缘端点不固定，因此完全选择图的结构来适应距离约束。 这使得问题更接近于使用给定的边长度多重集构建与最短路径一致的度量，而不是经典的最短路径验证问题。 

一些边缘情况很容易被忽视。 

如果节点 1 的距离不为零，则答案立即不可能，因为从节点到自身的最短路径距离始终为零，因此索引 1 处的任何非零值都会破坏一致性。 

如果某个节点的距离小于零，这是不可能的，因为所有权重都是非负的，因此所有最短路径都必须是非负的。 

当距离按递增顺序不一致时，会发生另一个重要的失败情况。 例如，如果 dis = [0, 5, 3]，则在数组排序中，节点 3 看起来比节点 2 更接近节点 1，但我们不会被迫遵守索引顺序，因此这并非自动不可能。 假设索引顺序对应于最短路径树结构的简单方法会错误地拒绝有效情况。 

## 方法

 暴力解释将尝试将 m 个边中的每一个分配给任意一对节点，然后运行最短路径算法来验证所得距离是否与目标数组匹配。 可能的分配数量约为每条边的 n² 个选择，导致大约 (n²)ᵐ 种可能性，即使对于非常小的输入，这也是完全不可行的。 即使是增量构建邻接的结构化搜索仍然会出现组合爆炸，因为每个边的选择都会影响所有未来的最短路径。 

关键的观察是，对可行性唯一重要的是我们是否可以将所需的距离嵌入到其边尊重最短路径一致性的某个图中。 由于端点完全在我们的控制之下，因此每条边都可以被视为一个“约束工具”，可以放置在任何有用的地方。 

在任何有效的最短路径度量中，每条边 (u, v, w) 必须满足三角形不等式约束 |dis[u] − dis[v]| ≤ w，否则该边将立即创建更短或不一致的路径。 相反，如果我们可以安排一个连接结构，其中距离逐渐增加，并且每个使用的边都足够大以覆盖所需的差异，那么我们可以通过仔细排序节点的连接方式来实现目标距离。 

这将问题简化为检查我们是否可以选择边的子集，以距离递增的顺序在节点上形成有效的跨越结构，同时将每个所需的“距离跳跃”与足够大的权重相匹配。

剩下的任务变成了排序距离增量和可用边权重之间的贪婪匹配问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分配| 指数| O(n + m) | 太慢了 |
 | 排序结构上的贪婪匹配 | O((n + m) log m) | O((n + m) log m) | O(n + m) | 已接受 |

 ## 算法演练

 我们首先通过检查节点 1 的距离是否为零来规范化实例。 如果不是，则该配置无法表示从节点 1 到其自身的最短路径，因此答案立即不可能。 

然后，我们根据所需的距离值对所有节点进行排序。 这种排序仅用于构建结构，而不是因为它反映了原始索引。 

接下来，我们对所有边权重进行排序，并为贪婪分配做好准备。 

我们按如下方式进行：

 1. 通过增加 dis 值对节点进行排序，以距离为零的节点 1 作为起点。 这给出了一个序列，其中每个下一个节点不比前一个节点更接近源，这对于构建单调结构至关重要。 
2. 按此顺序计算连续节点之间所需的距离增量。 对于排序序列中的节点 i，将所需的增量定义为 dis[i] − dis[i−1]。 这代表了我们在将该节点附加到不断增长的结构中时必须强制执行的最小“进度”。 
3. 按升序对可用边权重进行排序，以便我们始终可以尝试使用可行的最小可能边来满足每个增量。 
4. 对于每个所需的增量，选择至少与增量一样大的最小未使用边权重。 如果不存在这样的重量，则施工失败。 
5. 如果可以满足所有增量，则声明配置可行。 

步骤 4 背后的原因是，使用最小的足够边缘可以为以后更大的距离间隙保留更大的边缘。 这种贪婪策略可以防止过早消耗重边缘，而重边缘可能是满足排序距离序列中稍后的较大跳跃所必需的。 

### 为什么它有效

 排序的距离顺序强制执行单调结构，其中我们始终将所需距离较高的节点附加在距离较小或相等的节点之后。 每个附件只需要保证我们能够弥补与上一个级别的距离的增加。 

由于可以为边分配任意端点，因此每个选定的边都可以有效地用作该链中两个节点之间的链接。 确保每个所需的增量都有一个对应的边权可以覆盖它，保证我们可以实现从节点1到每个节点的一致的增量路径。 

贪婪匹配是安全的，因为任何可行的解决方案都必须分配至少一条能够覆盖每个增量的边，并且用更大的边替换所选边并不能提高可行性。 因此，始终消耗最小的足够边缘可以保留全局灵活性，而不会失去正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def possible(n, m, w, dis):
    if dis[0] != 0:
        return False

    w.sort()
    dis_sorted = sorted(dis)

    # build increments
    inc = []
    for i in range(1, n):
        inc.append(dis_sorted[i] - dis_sorted[i - 1])
        if inc[-1] < 0:
            return False

    j = 0
    for x in inc:
        while j < m and w[j] < x:
            j += 1
        if j == m:
            return False
        j += 1

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        w = list(map(int, input().split()))
        dis = list(map(int, input().split()))
        print("YES" if possible(n, m, w, dis) else "NO")

if __name__ == "__main__":
    solve()
```排序后，实现首先通过 dis_sorted[0] 检查强制条件 dis[1] = 0。 然后，它将目标距离转换为连续间隙，这表示在排序结构中移动所需的最小“边缘强度”。 

贪心指针 j 遍历排序的权重，总是跳过那些对于当前所需间隙来说太小的权重。 当找到有效权重时，它会被消耗并且指针前进，确保每个边缘最多使用一次。 

关键的微妙之处在于我们从不尝试分配特定的端点； 可行性完全取决于权重的多组是否可以支持所需增量的序列。 

## 工作示例

 考虑距离已经形成简单递增链的情况。 

输入：

 n = 4，m = 3

 dis = [0, 2, 5, 6]

 w = [2, 3, 1]

 排序距离为 [0, 2, 5, 6]，因此增量为 [2, 3, 1]。 排序后的权重为 [1, 2, 3]。 

| 步骤| 所需增量| 指针位置| 选择重量 | 剩余重量 |
 | ---| ---| ---| ---| ---|
 | 1 | 2 | 扫描至2 | 2 | [1, 3] |
 | 2 | 3 | 扫描至3 | 3 | [1] |
 | 3 | 1 | 扫描至1 | 1 | []|

 所有增量都满足，所以答案是“是”。 这演示了如何在必要时为更大的间隙保留更大的边缘。 

现在考虑一个失败的配置。 

输入：

 n = 3，m = 2

 dis = [0, 4, 5]

 w = [1, 2]

 排序距离给出增量 [4, 1]。 排序后的权重为 [1, 2]。 

| 步骤| 所需增量| 指针位置| 结果|
 | ---| ---| ---| ---|
 | 1 | 4 | 数组末尾 | 失败|

 最大的可用边只有2，因此无法支持第一个所需的跳转，从而导致构建无法进行。

 ## 边缘情况

 关键的边缘情况是第一个节点的距离不为零。 由于距源的所有最短路径距离本身都定义为零，因此任何偏差都会立即使实例无效。 该算法在任何处理之前都会检查这一点，避免浪费计算。 

当许多节点共享相同的距离值时，会发生另一种微妙的情况。 排序后，连续增量变为零。 使用权重至少为零的任何剩余边（即所有边）始终可以满足这些条件。 贪婪过程自然会首先消耗最小的可用边，因此零增量不会干扰可行性。 

最后一种情况涉及非常大的距离和很少的边缘。 即使总边权重足够大，如果单个所需增量超过所有可用权重，贪婪结构也会失败。 这正确地反映了没有任何边缘组合可以模拟比该构造模型中所有可用边缘容量更大的单个步骤。
