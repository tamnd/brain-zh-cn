 ## 问题理解

 我们得到了 16 支球队之间完全指定的确定性锦标赛。 每对球队都有一个固定的结果编码在输入中：对于任何初始种子位置 i 和 j，如果他们相遇，则只有一个获胜，并且这个结果永远不会改变。 

实际比赛并不是简单的循环赛。 相反，它是一种结构严格的瑞士式系统：球队在相同胜负记录的小组内重复配对，一旦达到3胜或3负就停止比赛，配对规则取决于种子顺序和不得重赛的限制。 每轮比赛结束后，种子队都会按照层次结构重新计算：首先是获胜次数，然后是根据对手的成绩得出的次要分数，最后是作为决胜局的初始种子队。 

我们最终被要求输出的唯一内容比流程建议的要简单。 对于从 1 到 16 名的每个初始种子队，我们需要瑞士系统完成后的最终胜负数。 

隐藏的关键困难在于，尽管锦标赛规则看起来是自适应和动态的，但整个系统是确定性的，因为所有比赛结果都是预先确定的，而且球队的数量是固定的且非常少。 挑战不是天真的意义上的组合爆炸，而是忠实地模拟依赖于不断变化的排名和历史比赛限制的结构化配对过程。 

输入大小在结构上是恒定的：15 行描述 16 个团队中的所有配对结果。 这立即表明任何具有三次甚至中等重度状态模拟的解决方案都是可行的，但是任何以简单的方式重复重新计算全局匹配的方法都会带来不必要的开销和实现复杂性的风险。 

“不重赛”规则与组内基于种子的选择相结合产生了一种微妙的边缘情况。 粗心的模拟只跟踪输赢，但忽略历史对手，可能会分配无效的配对，并悄悄偏离预期的瑞士结构。 另一个常见的陷阱是错误地重新计算种子顺序，尤其是取决于对手总成绩的二次抢七局。 

## 方法

 直接的暴力解释将逐轮模拟瑞士锦标赛。 每一轮，我们都会根据当前战绩对球队进行分组，然后在每个小组中，我们反复挑选最高种子队，并将其与不违反不重赛限制的最佳对手进行匹配。 我们更新结果并继续，直到处理完所有组，然后重新计算种子并重复。 

这种方法在概念上是正确的，因为它准确地反映了问题陈述。 然而，其复杂性隐藏在有效对手的重复选择中。 在最坏的情况下，对于每场比赛，我们可能会扫描最多 O(n) 个候选者以找到有效的对手，并且所有回合中都有 O(n log n) 或 O(n²) 次比赛决策。 由于频繁重新计算种子顺序和检查对手历史记录，这在实践中很容易变成 O(n3)，对于 n = 16 来说仍然没问题，但实现繁重且容易出错。 

关键的观察结果是 n 是固定的并且非常小。 这使我们能够将视角从优化渐近转向构建忠实的状态机。 我们不必试图巧妙地进行配对，而是可以使用明确的数据结构直接模拟精确的规则：跟踪胜利、失败、对手组，并完全按照定义重新计算排名。 

最重要的简化是认识到一旦初始结果确定，锦标赛就具有确定性。 不存在分支或优化问题。 每一次配对都是由规则强制的，整个过程可以通过仔细的记账一步步模拟。 二级排名可以增量维护，避免从头开始重新计算。

蛮力之所以有效，是因为它明确遵循锦标赛规则，但当它试图“优化配对”而没有完全编码不重赛约束和二级排名定义时，它在概念上会失败。 正确的解决方案是通过仔细的状态更新来拥抱完整的模拟。

 ## 算法演练

 我们逐轮模拟比赛，保留每支球队当前的胜负以及已经面对的对手。 

首先，我们初始化所有零胜零负的球队，以及一个空的对手组。 我们还根据输入预先计算完整的结果矩阵，以便可以在 O(1) 内查询任何匹配结果。 

其次，我们重复执行回合，直到所有球队达到 3 胜或 3 负。 每轮开始时，所有活跃球队均按照当前（胜、负）记录进行分组。 该分组定义了瑞士桶。 

第三，在每个桶内，我们必须生成匹配项。 我们根据当前的种子排序规则对桶中的球队进行排序：首先获胜，然后是所有对手的次要分数（他们的胜利减去损失），最后是初始种子指数作为决胜局。 该顺序决定了选择的优先级。 

第四，我们反复挑选桶中排名最高的未配对球队。 对于这支球队，我们在同一个桶中向下扫描，找到尚未交手的排名最高的对手。 选择第一个这样的有效对手。 我们将两者标记为配对并记录他们的比赛。 此扫描是安全的，因为不重新匹配规则仅禁止先前遇到的对。 

第五，我们使用预先计算的结果矩阵来解决比赛，相应地更新胜负，并记录两队的对手关系。 

第六，处理完所有桶后，我们通过更新的统计数据隐式重新计算全局种子顺序。 这会影响下一轮的分组，但不需要除存储桶构建之外的单独排序步骤，因为分组始终基于（赢，输）。 

我们重复这个过程，直到所有球队都达到 3 胜或 3 负的最终状态。 

这样做的原因是整个系统在配对中是确定性的和局部贪婪的：在每一步中，种子最高的球队总是选择最好的可行对手。 因为 n 很小并且每个约束都是明确的，所以不需要回溯或全局优化。 对手设定的不变量保证不会创建非法重赛，而胜/负计数器保证最终终止，因为每场比赛严格地使至少一支球队走向停止条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = 16

    # read upper-triangular outcome matrix
    win = [[0]*n for _ in range(n)]
    for i in range(n-1):
        row = list(map(int, input().split()))
        for j, v in enumerate(row, start=i+1):
            win[i][j] = v
            win[j][i] = 1 - v

    W = [0]*n
    L = [0]*n
    played = [set() for _ in range(n)]

    active = set(range(n))

    def secondary(i):
        # sum over (opponent wins - losses)
        return sum(W[x] - L[x] for x in played[i])

    while True:
        active = [i for i in range(n) if W[i] < 3 and L[i] < 3]
        if not active:
            break

        # group by (W, L)
        from collections import defaultdict
        groups = defaultdict(list)
        for i in active:
            groups[(W[i], L[i])].append(i)

        # process each group independently
        for key in groups:
            group = groups[key]

            # sort by seed rule
            group.sort(key=lambda i: (-W[i], -secondary(i), i))

            used = set()
            m = len(group)

            for idx in range(m):
                i = group[idx]
                if i in used:
                    continue

                # find opponent
                j = None
                for k in range(idx+1, m):
                    cand = group[k]
                    if cand in used:
                        continue
                    if cand not in played[i]:
                        j = cand
                        break

                if j is None:
                    continue

                used.add(i)
                used.add(j)

                # play match
                if win[i][j]:
                    wi, wj = i, j
                else:
                    wi, wj = j, i

                W[wi] += 1
                L[wj] += 1
                played[i].add(j)
                played[j].add(i)

    for i in range(n):
        print(W[i], L[i])

if __name__ == "__main__":
    main()
```该解决方案存储完整的结果矩阵，因此可以在恒定时间内解决每场比赛。 核心状态由胜利和失败计数器以及每队一组已比赛的对手组成，这强制执行不重赛约束。 

按（W，L）分组直接反映了瑞士的结构。 排序函数对排名规则进行编码：主要按获胜次数排序，次要按对手强度排序，然后是初始索引。 由于 n 很小，所以二级分数是按需计算的； 这里不需要缓存。 

配对是按排序顺序贪婪地完成的，向前扫描以找到之前未玩过的第一个有效对手。 这既尊重种子优先权又尊重重赛限制。

 ## 边缘情况

 一个重要的边缘情况是，一支球队在其桶内多次排名靠前，但所有潜在对手都已标记为已比赛。 在这种情况下，不检查完整对手历史记录的幼稚实现可能会尝试重新分配先前的对手，从而违反瑞士约束。 正确的实现只是跳过在该迭代中对该团队进行配对，将其留给相同或稍后处理顺序的另一个有效匹配。 

另一个微妙的情况是，当二级排名并列分布在具有相同对手组的多支球队时。 由于抢七最终会回到初始种子，因此不包含最终比较可能会导致排序不稳定和配对顺序不一致。 实现的比较器显式地将种子索引作为最后一个键，即使在完全对称的情况下也能确保确定性。
