 ## 解决方案
 ## 问题理解

 我们得到了多个独立的测试用例。 每个测试用例中有几个 Capoo，每个都有一个正的强度值。 我们想选择其中的一些并将它们排列成垂直堆栈。 

堆栈有一个限制，即只有顶部 Capoo 不受限制。 其他每个 Capoo 的强度必须至少等于其上方所有 Capoo 的强度总和。 换句话说，当我们在堆栈中向下移动时，每个 Capoo 必须足够强大以“支撑”其上方的所有内容。 

目标不是最大化总强度或最小化违规行为，而是最大化可以包含的 Capoo 数量，同时仍然能够将它们排序到有效的堆栈中。 

从约束角度来看，所有测试用例的 Capoo 总数最多为 200000 个，每个强度可以大到 10^9。 这立即排除了尝试所有排列或子集的任何方法。 即使简单地检查单个排列也需要线性验证，并且存在许多阶乘，因此暴力破解是完全无法实现的。 

关键的困难在于选择和排序是耦合的。 过早选择弱元素可能会使前缀和过大过快，从而阻止以后的添加。 另一方面，过早放置强元素可能会浪费它们的容量并减少整体适合的项目数量。 

当许多值相等或非常小时，就会出现微妙的边缘情况。 例如，如果所有 Capoo 的强度均为 1，那么堆叠两个就可以了，但堆叠三个就已经失败了，因为第三个必须至少为 2。因此，天真的“获取所有内容”或“任意排序”方法会立即失效。 另一种棘手的情况是当许多小值中存在一个非常大的值时。 例如，诸如 [1, 1, 1, 100] 之类的值。 如果放置不正确，大值可能会过早被消耗，从而即使存在更好的排序，也无法在之后容纳更多小元素。 

## 方法

 一个蛮力的想法是尝试 Capoo 的每个子集，并为每个子集尝试所有排列以查看是否存在有效的堆栈。 对于给定的排序，我们可以通过维护每个位置上方元素的运行总和来验证线性时间内的有效性。 每个排列的成本已经为 O(k)，并且在所有排列中，这都变成了 O(k!)，即使 n 约为 15，这也是不可行的，更不用说 200000 了。 

我们需要对约束的行为进行结构观察。 该条件仅取决于所有先前放置的元素的总和，而不取决于它们的单独排列。 这表明一旦我们修复了排序，构造过程中唯一重要的状态就是当前的前缀和。 

这导致了一个贪婪的见解：如果我们从上到下构建一个有效的堆栈，那么在每一步中我们都希望保持前缀和尽可能小，以便以后可以放置更多元素。 这自然建议排序并始终首先尝试最小的可用有效元素。 

关键的实现是，如果我们维护已放置的所有元素的当前总和 S，则下一个选择的元素必须满足 ai ≥ S。在所有此类有效候选元素中，选择最小的元素可以使 S 在更新后尽可能小，因为 S 变为 S + ai。 这正是贪婪可行性过程的结构。 

因此，我们按升序对所有值进行排序并迭代它们，只要它可以支持当前总和就贪婪地获取一个元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 排序后贪心| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 按升序对所有 Capoo 优势进行排序。

排序确保当我们考虑一个元素时，所有较小或相等的元素都已被考虑，这很重要，因为较小的元素总是更容易提前放置而不违反总和约束。 
2. 初始化变量S = 0，表示已放入堆栈中的强度总和。 

该值模拟下一个选择的 Capoo 必须能够支持的总负载。 
3. 初始化一个计数器 ans = 0 来跟踪我们成功包含了多少 Capoo。 
4. 从最小到最大迭代排序的优势。 对于每个值 x：

 如果 x 至少为 S，我们将其放入堆栈中，将 ans 加 1，并更新 S = S + x。 

如果 x 小于 S，我们会跳过它，因为放置它会立即违反要求。 稍后尝试强制它没有任何好处，因为 S 只会随着时间的推移而增加。 
5.处理完所有元素后，输出ans作为可以堆叠的Capoo的最大数量。 

### 为什么它有效

 在任何时候，扩展有效堆栈的唯一方法是选择一个能够支持当前累积负载 S 的元素。如果在存在较小的有效元素时选择一个比所需的更大的元素，那么我们会增加 S 超过所需的数量，这只会降低未来的可行性，因为所有剩余元素都是固定的且非负的。 

这建立了贪婪的支配属性：在给定步骤的所有有效选择中，最小的有效元素保留最多的未来选项。 由于 S 是单调递增的，因此跳过有效的较小元素永远不会有帮助，因为它只会使每个剩余元素的约束更加严格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        s = 0
        ans = 0
        
        for x in a:
            if x >= s:
                ans += 1
                s += x
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案是围绕一次贪婪扫描构建的。 排序步骤确保我们总是首先遇到较小的候选者，这对于尽可能保持累积总和最小至关重要。 变量`s`跟踪由所选堆栈前缀引起的累积强度要求。 每个决定都是本地的：如果当前可以支持堆栈，我们要么接受一个元素，要么永久跳过它。 

一个常见的错误是尝试按降序构建堆栈。 这种方法往往会提前放置较大的值，这会增加运行总和并减少稍后可以容纳的元素数量。 另一个错误是尝试配对元素或使用两个指针而不强制执行全局前缀和约束，这会导致不正确的可行性推理。 

## 工作示例

 考虑输入：```
1
3
4 7 9
```排序后得到[4,7,9]。 

| 步骤| 当前 x | 当前 S | 行动| 新S | 回答 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 4 | 0 | 采取 | 4 | 1 |
 | 2 | 7 | 4 | 采取 | 11 | 11 2 |
 | 3 | 9 | 11 | 11 跳过| 11 | 11 2 |

 这表明即使 9 很大，但它到达得太晚了，因为累加的总和太大而无法满足约束。 

现在考虑：```
1
3
1 1 1
```排序数组为 [1, 1, 1]。 

| 步骤| 当前 x | 当前 S | 行动| 新S | 回答 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 采取 | 1 | 1 |
 | 2 | 1 | 1 | 采取 | 2 | 2 |
 | 3 | 1 | 2 | 跳过| 2 | 2 |

 只能使用两个元素，因为第三个1无法支持2的累加和。 

这些痕迹显示了随着 S 的增长，约束如何迅速变得更严格，这是核心限制因素。

 ## 边缘情况

 一种重要的边缘情况是所有值都等于 1。对于输入`[1, 1, 1, 1]`，算法取第一个元素，使 S = 1。第二个元素仍然有效，使 S = 2。然后第三个 1 被拒绝，因为它不能支持 2。这表明，由于前缀和快速增加，即使是统一数组也不允许全选择。 

另一种边缘情况是单个大元素被许多小元素包围，例如`[100, 1, 1, 1, 1]`。 该算法首先取 1，然后是 1，然后是 1，但最终 S 会增长并阻止进一步包含。 大元素通常会被延迟（如果有的话），这种排序确保我们不会浪费早期的容量。 

最后的边缘情况是单个元素输入。 由于顶部元素在其上方没有约束，因此任何单个 Capoo 始终有效，并且算法会立即正确返回 1。
