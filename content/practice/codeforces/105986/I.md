 ## 解决方案
 ## 问题理解

 我们正在控制一个生物，其“状态”是从 0 到 n 的整数值。 我们从状态 0 开始并希望最终达到状态 n。 

有一家商店出售辅助生物。 购买一个价值 i 的助手需要花费 ai，并且每个 i 的供应量是无限的。 购买助手后，我们立即将其与我们当前的生物合并。 

如果当前值为 x 并且我们将其与购买的值为 y 的助手合并，则结果是不确定的。 新值成为从 x 和 y 之间的完整整数区间（含）中选择的均匀随机整数。 所以转移范围是[min(x, y), max(x, y)]，并且里面的每个整数都是等概率的。 

每个操作都包括选择一个辅助值、支付其成本以及执行此随机合并。 我们可以重复此操作，直到当前值变为 n。 任务是最小化达到从 0 开始的值 n 的预期总成本。 

重要的是，每个动作都会将状态更改为许多状态的分布，因此成本是决策随机过程的预期成本。 

约束 n ≤ 5000 表明采用 O(n²) 或 O(n² log n) 动态规划方法。 任何涉及状态和转换的三个嵌套循环的事情都会太慢，但具有 O(1) 转换评估的二次转换是可以接受的。 

一个微妙的边缘情况是所选辅助值等于当前值。 在这种情况下，区间会折叠成一个点，因此状态不会改变。 该操作始终是严格次优的，因为它只会增加成本而没有进展，但它仍然出现在决策空间中，并且不得破坏递归逻辑。 

另一个重要的问题是所有转换都取决于 DP 值间隔的平均值。 如果每次都简单地重新计算这些区间和，那么解就会变成三次方并且不会通过。 

## 方法

 考虑该过程的直接方法是根据每个值 x 定义预期剩余成本。 假设我们知道一个函数 E[x]，表示从状态 x 开始到达 n 的最小预期成本。 从状态 x 开始，我们尝试所有可能的辅助值 y。 我们立即支付 ay，然后在 x 和 y 之间的区间内均匀地移动到随机状态。 预期的未来成本是该区间内 E 的平均值。 

这给出了一个递归，其中每个选择 y 都会导致 ay 的预期成本加上一段时间间隔内 E 的平均值。 蛮力方法对每个 x 和每个 y 进行评估，并通过扫描所有元素来计算每对的间隔平均值。 这导致 O(n3) 时间：n 个状态、n 个选择以及计算每个平均值的 O(n) 时间。 当n达到5000时，这远远超出了可行的极限。 

关键的观察结果是，唯一昂贵的部分是在 E 上重复范围求和查询。一旦已知 E 的较大状态，所有区间平均值都可以使用前缀和在 O(1) 中得到答案。 这将每次转换评估减少到恒定时间，将解决方案变成二次动态程序。 该过程自然地从较大的值到较小的值进行，因为 E[x] 取决于较大状态的 E 和包含已计算值的混合区间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 带有前缀和的最优 DP | O(n²) | O(n) | 已接受 |

 ## 算法演练

 我们将 E[x] 定义为从 x 开始达到状态 n 所需的最小预期成本。 我们还维护一个前缀和数组 S，其中 S[i] 存储 E[0] 到 E[i] 的和，这允许在恒定时间内计算间隔平均值。 

我们按照 x 从 n 到 0 的降序计算值，这样当我们计算 E[x] 时，所有需要的较大状态都是已知的。

1. 设置 E[n] = 0，因为一旦达到目标，就不需要更多成本。 
2. 维护一个前缀和数组S，在计算E[i]之后，我们更新S[i] = S[i-1] + E[i]。 这种结构允许快速计算任何时间间隔内的总和。 
3.对于从n-1到0的每个状态x，我们评估从0到n的所有可能的辅助选择y。 每个选择定义一个区间 [l, r]，其中 l = min(x, y) 且 r = max(x, y)。 
4. 对于每个 y，将预期的下一状态成本计算为 E 在 [l, r] 上的平均值。 使用前缀和，这是 (S[r] - S[l-1]) / (r - l + 1)。 选择 y 的总成本是 ay 加上这个期望值。 
5. 取所有 y 的最小值并将其分配给 E[x]。 
6. 完成E[x]后，更新前缀和数组，然后移动到x-1。 

这样做的原因是，一旦我们修复了选择 y，合并后的过程就会丢失除结果值之外的先前状态的所有内存。 这使得问题成为一个纯马尔可夫决策过程，其中最优性仅取决于当前值。 DP 是有效的，因为每个转换成本都干净地分解为立即支付加上对下一个状态的线性期望，并且这些期望完全由先前计算的 E 值决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n_and_rest = list(map(int, sys.stdin.read().split()))
    n = n_and_rest[0]
    a = n_and_rest[1:]
    
    if n == 0:
        print("0.000000")
        return

    E = [0.0] * (n + 1)
    S = [0.0] * (n + 1)

    E[n] = 0.0
    S[n] = 0.0

    for x in range(n - 1, -1, -1):
        best = float('inf')

        for y in range(0, n + 1):
            l = x if x < y else y
            r = y if x < y else x

            length = r - l + 1
            interval_sum = S[r] - (S[l - 1] if l > 0 else 0.0)
            expected_next = interval_sum / length

            cost = a[y] + expected_next
            if cost < best:
                best = cost

        E[x] = best
        S[x] = S[x + 1] + E[x] if x < n else E[x]

    print(f"{E[0]:.10f}")

if __name__ == "__main__":
    solve()
```代码直接遵循DP定义。 数组 E 存储每个状态的最佳预期成本，而 S 旨在支持快速间隔总和。 每个状态 x 都是在所有较大的指数最终确定后计算的，确保期望中使用的每个区间仅指已计算的或稳定的值。 

一个常见的陷阱是错误地更新前缀和数组。 由于我们将 E 从 n 填充到 0，因此必须按照所选顺序一致地重建前缀和。 另一个微妙的点是避免在循环内重新计算区间和，这会破坏二次复杂度。 

## 工作示例

 ### 示例 1

 考虑一个 n = 3 且成本 a = [1, 10, 1, 100] 的小实例。 这个想法是，即使随机性分散了价值，便宜的端点也会鼓励人们跳向它们。 

我们按 3 → 0 的顺序计算 E。 

| x| 考虑 y | 间隔| 平均E | 成本 a[y] + 平均值 | E[x] |
 | ---| ---| ---| ---| ---| ---|
 | 3 | - | - | - | 0 | 0 |
 | 2 | 3 | [2,3]| (E[2]+0)/2 | (E[2]+0)/2 | 100+小| 最好的
 | 2 | 0 | [0,2]| 平均值（E[0..2]）| 1 + 平均 | 分钟|
 | 1 | 3 | [1,3]| 平均值（E[1..3]）| 平均 100+ |
 | 1 | 0 | [0,1]| 平均值（E[0..1]）| 1 + 平均 | |
 | 0 | 全部 y | [0，y] | 平均值（E[0..y]）| a[y] + 平均值 | E[0] |

 这表明决策是通过平衡直接成本与结果间隔的“分散”程度来驱动的。 廉价的端点很有价值，因为即使它们产生随机性，它们也会降低成本。 

### 示例 2

 取 n = 2 且 a = [5, 1, 5]。 

从状态 1 开始，选择 y = 1 是没有用的，因为它不会产生任何进展。 选择 y = 0 或 y = 2 会创建区间 [0,1] 或 [1,2]，两者都会产生随机性但允许移动。 

这说明了为什么存在自转移但永远不会影响最优值。

 ## 边缘情况

 当n = 0时，DP必须立即返回0，因为不需要任何操作。 该算法在任何数组访问之前显式处理此问题。 

当 y 等于 x 时，区间崩溃，预期的下一个状态等于 E[x]。 计算出的成本变为 a[x] + E[x]，这总是比任何改进的转换更糟糕，因此它永远不会影响最小值。 

当成本极度倾斜时，例如非常便宜的高价值助手，DP 可能更喜欢产生宽间隔的大跳跃。 该算法自然地捕捉到了这一点，因为更宽的间隔会增加平均 E 的方差，这直接反映在转移成本中。
