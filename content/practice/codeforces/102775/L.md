 ## 解决方案
 ## 问题理解

 我们收集了一些樱桃树。 每棵树都由三个数字描述：开始开花的日期、添加新花的最后一天以及每日变化中有多少朵花出现或消失。 

对于带有参数的树`a`,`b`， 和`k`, 白天之前花朵数量为零`a`。 当天`a`它有`k`鲜花，每天早上直到白天`b`它获得了另一个`k`花朵。 当天傍晚之后`b`，树失去了`k`每天开花，直到空为止。 任务是找到所有树上的花总数达到最大值的最早一天。 

输入最多包含`10^5`树，天数和花数可以大到`10^9`。 这会立即排除对每个可能的日期进行迭代，因为天数范围可能约为`10^9`，同时树木的数量也很大。 解决方案需要处理功能的重要变化，而不是每一天。 一个`O(N log N)`解决方案是合适的，因为排序`3N`活动非常适合`N = 10^5`。 

有几种边界情况很容易处理不当。 一棵开花期只有一天的树仍然必须正确处理。 

例如：```
1
5 5 10
```答案是：```
5
```这棵树在第 5 天开出 10 朵花，之后开出 0 朵花。 将增长区间视为空的解决方案，因为`a == b`可能会错过高峰。 

另一个棘手的情况是最后一个开花日之后的确切转变。 

例如：```
1
3 4 7
```第 3 天的花朵数为 7 朵，第 4 天的花朵数为 14 朵，第 5 天的花朵数为 7 朵。答案是：```
4
```粗心的实施当天就开始减少`b`而不是一天之后`b`会错误地移动最大值。 

关系也很重要。 所需答案是鲜花数量最多的第一天。 

例如：```
2
1 1 5
3 3 5
```第 1 天总数达到 5，第 3 天又达到 5，所以答案是：```
1
```更新相同值的答案将返回错误的日期。 

## 方法

 最直接的方法是每天模拟花园。 对于每一天，我们都可以计算每棵树的贡献并保留迄今为止最好的总数。 这是正确的，因为它直接评估我们关心的函数。 然而，它太慢了。 最大可能日值接近`10^9`，所以即使每天访问也已经需要数十亿次迭代。 乘以`10^5`树给出的最坏情况远远超出了可用的限制。 

关键的观察是我们不需要单独计算每天的花数。 一棵树以非常有规律的方式变化：它会在一段时间内以恒定的量增加，然后以相同的恒定量减少。 我们可以存储一天到第二天的总变化量，而不是存储花朵数量本身。 

对于一棵树，令`D(day)`是从前一天到今天的花朵变化。 树的贡献`+k`对于这一天的差异`a`通过一天`b`，因为每天早上花数都会增加。 然后就贡献了`-k`从那天起`b + 1`通过一天`2b - a + 1`，因为花朵正在消失。 此后，贡献为零。 

这会将每棵树转换为三个事件，修改当前的每日差异：```
day a:       increase daily change by k
day b + 1:   decrease daily change by 2k
day 2b-a+2:  increase daily change by k
```收集完所有事件后，我们按顺序扫描它们。 在两个事件日之间，每日差异保持不变，因此可以通过将差异乘以间隔长度来更新花朵总数。 这将数十亿可能的天数压缩为仅`3N`有意义的职位。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(max_day × N) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 1. 创建一个事件映射，其中每个键是一天，值是应用于当天每日差异的更改。 对于每一棵树`(a, b, k)`， 添加`+k`在`a`,`-2k`在`b + 1`， 和`+k`在`2b - a + 2`。 这三个事件准确地描述了花朵数斜率何时发生变化。 
2. 对所有活动日进行排序。 只有这些天才能改变当前的每日差异，因此每隔一天属于行为可预测的区间。 
3. 扫描已排序的事件天数，同时维护两个值：下一个处理日之前的当前鲜花数量以及当前的每日差异。 处理活动日之前`x`，从前一个位置跳过间隙到`x - 1`通过添加`daily_difference * gap_length`。 
4. 应用当天的事件`x`更新每日差异，然后使用新的差异向前移动一天。 结果值是当天的花数`x`，因此将其与迄今为止找到的最佳答案进行比较。 
5. 仅当花朵数量变得严格更大时才更新答案。 保留第一次出现会自动处理具有相同最大值的日期。 

为什么它有效：

 扫描保持每个事件边界处总花数的准确值。 在连续的两个事件日之间，没有一棵树改变其生长速度，因此总数以固定的每日差异线性变化。 事件表示恰好在某些树切换行为的日子里改变了这种差异。 由于整数天内分段线性序列的每个可能的最大值必须出现在间隔边界或具有恒定方向的间隔的开始处，因此检查这些压缩位置会找到真正的最早最大日。 

## Python 解决方案```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())
    events = defaultdict(int)

    for _ in range(n):
        a, b, k = map(int, input().split())
        events[a] += k
        events[b + 1] -= 2 * k
        events[2 * b - a + 2] += k

    days = sorted(events)

    current_change = 0
    flowers = 0
    position = 1

    best_flowers = 0
    answer = 1

    for day in days:
        flowers += current_change * (day - position)

        current_change += events[day]

        flowers += current_change

        if flowers > best_flowers:
            best_flowers = flowers
            answer = day

        position = day + 1

    print(answer)

if __name__ == "__main__":
    solve()
```第一个循环中的事件构造是核心转换。 第一个事件启动树的增加部分。 第二个事件删除之前的增加并开始减少，这将每日差异更改为`-2k`。 第三个事件在树变空后取消减少。 

扫荡保持`current_change`作为从一天到下一天的总花数的变化。 变量`flowers`将总计存储在当前处理的位置。 在到达新的事件日之前，代码会立即跳过所有中间日，因为相同的差异适用于整个时间间隔。 

循环内的顺序很重要。 该事件必须在添加事件当天的鲜花之前应用，因为该事件描述了在该确切日期生效的差异。 一天后应用它会在每个边界处引入一个相差一的错误。 

Python 整数会自动用于任意精度，这可以避免溢出，即使最终答案仅保证适合 64 位。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N log N) | O(N log N) | 每棵树恰好有三个事件，对事件日期进行排序是主要工作。 |
 | 空间| O(N) | 事件映射每棵树最多存储三个条目。 |

 和`N = 100000`，算法处理大约`300000`事件并且仅对这么多值进行排序。 它避免了对日期值大小的依赖，因此大天数接近`10^9`不影响性能。

 ## 边缘情况

 对于单日开花情况：```
1
5 5 10
```事件日为 5、6 和 7。在第 5 天，每日变化变为`10`，赠送10朵花。 在第 6 天，每日变化变为`-10`，将总数减少到零。 该算法在继续之前会检查第 5 天，因此它会正确返回 5。 

对于最后一个生长日之后的边界：```
1
3 4 7
```这些事件是：```
3: +7
5: -14
7: +7
```第 3 天开出 7 朵花，第 4 天开出 14 朵花，第 5 天开始减少。 该算法应用了`-14`事件发生在第 5 天而不是第 4 天，保留第 4 天的正确最大值。 

对于相等的最大值：```
2
1 1 5
3 3 5
```第一天扫描达到 5 朵花，并将其存储为最佳结果。 当到达第 3 天时，花朵数量相同，严格比较可以防止替换之前的答案。 

对于非常大的坐标：```
1
1000000000 1000000000 1000000000
```该算法仅围绕大日值创建三个事件。 它永远不会循环开花前的十亿个空天，这是事件扫描符合约束的主要原因。
