 ## 解决方案
 ## 问题理解

 任务是回答有关数学函数的许多独立查询。 对于一个值`a`，函数就是乘积$$f(a)=1^a \cdot 2^{a-1}\cdot 3^{a-2}\cdots (a-1)^2\cdot a^1$$具有特殊的价值`f(0)=1`。 每个查询都要求对该值取模$10^9+7$。 官方声明给出了相同的定义，并将查询的值限制为$10^5$。 

输入最多包含$10^5$查询，以及每个查询`a`最多也是$10^5$。 这立即排除了为每个查询从头开始重新计算产品的情况。 直接计算一次查询需求$O(a)$乘法，这将变成关于$10^{10}$最坏情况下的操作。 2 秒的时间限制要求我们找到一种在查询之间共享工作的方法。 

棘手的案件大多发生在边界附近。 第一个是`a = 0`，其中公式根本不包含任何因素，但答案明确定义为`1`。 一个解决方案从开始相乘`1`并假设每个查询至少有一个因素可能会错误地处理这种情况。 

例如：```
Input
1
0
```正确的输出是：```
1
```粗心的实现将答案初始化为`0`或者尝试访问产品的第一个因素将失败。 

另一个边缘情况是`a = 1`。 该产品仅包含一个术语：$$f(1)=1^1=1$$例如：```
Input
1
1
```正确的输出是：```
1
```基于递归的实现还必须正确处理此转换，因为它应该乘以`1!`并保持该值不变。 

## 方法

 一种简单的方法是独立评估每个查询。 对于查询`a`，我们可以循环遍历所有数字`1`到`a`并将每个数字与其所需的幂相乘。 这直接遵循定义，因此是正确的。 然而，最大可能的查询需求大约是$10^5$因素，并这样做是为了$10^5$查询大致给出$10^{10}$模块化操作。 这远远超出了时间限制所能容纳的范围。 

关键的观察结果来自于比较函数的两个连续值。 不要每次都扩展整个产品，而是进行比较`f(a)`和`f(a-1)`:$$f(a)=1^a\cdot2^{a-1}\cdots(a-1)^2\cdot a$$和$$f(a-1)=1^{a-1}\cdot2^{a-2}\cdots(a-1)^1$$每个现有号码来自`1`到`a-1`恰好获得指数中的一份额外副本，以及新因子`a`出现一次。 比率变为：$$\frac{f(a)}{f(a-1)}=1\cdot2\cdot3\cdots a=a!$$所以递归式是：$$f(a)=f(a-1)\cdot a!$$这彻底改变了问题。 我们只需要预先计算阶乘，然后构建一次答案序列。 之后，每个查询都由单个数组查找来回答。 

暴力破解之所以有效，是因为定义直接描述了值，但它对相邻查询重复了几乎相同的工作。 连续答案仅因阶乘不同的观察结果使我们可以用前缀计算替换重复的乘积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(所有查询值的总和) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(max(a) + n) | O(最大(a)) | 已接受 |

 ## 算法演练

 1. 首先读取所有查询并找到最大的请求值。 我们需要这个最大值，因为所有达到它的值都可以提前准备好，而较小的查询可以重用相同的预先计算的答案。 
2. 计算阶乘`1`到最大值。 让`fact[i]`店铺$i!$模数$10^9+7$。 这些值代表从`f(i-1)`到`f(i)`。 
3. 构建答案数组。 开始于`f(0)=1`。 对于每一个`i`从`1`到最大值，将之前的答案乘以`fact[i]`。 结果值为`f(i)`因为每次转换都只应用一个阶乘。 
4. 对于每个输入查询`a`，输出存储在索引处的预先计算值`a`。 不需要额外的数学工作，因为所有可能的值已经生成。 

为什么它有效：

 预处理期间的不变性是处理后索引`i`，存储的值正好是$f(i)$。 最初，这是正确的，因为存储的值是$f(0)=1$。 搬家时从`i-1`到`i`，我们乘以`i!`，推导的递归证明这恰好产生`f(i)`。 由于每个查询都要求这些已验证的状态之一，因此返回的值始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n = int(input())
    queries = [int(input()) for _ in range(n)]

    mx = max(queries)

    fact = [1] * (mx + 1)
    for i in range(1, mx + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = [1] * (mx + 1)
    for i in range(1, mx + 1):
        ans[i] = ans[i - 1] * fact[i] % MOD

    print("\n".join(str(ans[x]) for x in queries))

if __name__ == "__main__":
    solve()
```输入在处理之前被存储，因为最大的查询决定了预处理必须进行到什么程度。 如果不知道最大值，我们要么浪费内存，要么需要动态扩展数组。 

这`fact`数组存储以所需素数为模的普通阶乘值。 第二个循环使用递归构造实际函数值$f(i)=f(i-1)\cdot i!$。 将这两个数组分开可以避免重复重新计算阶乘。 

的初始化`ans[0]`作为`1`处理特殊定义`f(0)`。 循环开始于`1`，因此空产品不存在相差一的问题。 Python 整数不会溢出，但每次乘法都会减少模数`MOD`保持较小的值并匹配所需的输出。

 ## 边缘情况

 对于`a = 0`，该算法创建答案数组`ans[0]=1`在应用任何转换之前。 关于输入```
1
0
```最大请求值为零，因此不计算阶乘并且保留存储的答案`1`。 输出是正确的，因为该函数是针对这种情况单独定义的。 

为了`a = 1`，算法计算`fact[1]=1`然后更新：$$ans[1]=ans[0]\cdot fact[1]=1\cdot1=1$$对于输入```
1
1
```答案是：```
1
```转换不会意外地引入额外的因子，因为乘以`1!`保持先前的值不变。 

对于许多相同的大型查询，预处理仍然只发生一次。 例如：```
3
100000
100000
100000
```算法构建`f(100000)`一次并随后执行三次数组访问。 这样就避免了重复工作导致直接公式太慢的情况。
