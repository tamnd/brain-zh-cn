 ## 解决方案
 ## 问题理解

 我们有一块 N×N 板。 每个细胞都属于三个类别之一。 一个单元格被标记为`h`将当前棋子变成骑士，标记为单元格`p`将其变成一个特殊的棋子，可以根据问题的移动规则移动，并标记一个单元格`x`根本无法进入。 我们从一个有效单元格开始，需要使用尽可能少的移动到达另一个有效单元格。 

重要的细节是，棋子类型由棋子当前所在的单元格决定。 整个旅程的移动选项并不是固定的，因此同一个方格可以有不同的出局动作，具体取决于我们到达那里并变成骑士还是棋子。 答案是到达目的地所需的最短移动次数，或者`-1`如果不存在合法的移动序列。 

棋盘尺寸最多为 100 x 100，因此最多有 10000 个可用位置。 对于单元数量呈线性或接近线性的图算法来说，这已经足够小了。 尝试所有可能路径的解决方案是不可能的，因为路径数量可能呈指数级增长。 即使重复探索所有细胞对的方法也已经接近 1 亿次操作，并且不会为运动模拟留下太多空间。 

主要的实施缺陷来自于仅通过坐标来处理单元。 相同的坐标并不总是相同的图状态，因为到达一个`h`细胞并到达`p`细胞创造不同的未来可能性。 

例如：```
1
h
1 1
1 1
```正确答案是`0`。 在检查目的地之前强制至少移动一次的解决方案将会失败。 

另一种情况是：```
2
hp
xx
1 1
1 2
```正确答案是`1`因为骑士可以从第一个牢房移动到第二个牢房。 仅在更改棋子类型后检查目的地或假设所有棋子共享相同动作的粗心解决方案可能会产生不正确的结果。 

第三种情况是：```
3
xxx
xpx
xxx
2 2
2 2
```正确答案是`0`。 起始小区可能是孤立的，但到达已经是目的地的小区不需要移动。 

## 方法

 直接的暴力方法是搜索所有可能的运动序列。 从当前单元格开始，我们尝试每一个合法的移动，继续递归，并保持最短的成功路线。 这是正确的，因为考虑了所有可能的路径。 问题在于路径的数量。 在具有许多可到达单元的棋盘上，搜索树会反复分支，并且探索的状态数量可能会变得巨大。 

第一个改进是认识到这是未加权图上的最短路径问题。 每一种可能的情况都可以被视为一个图的顶点，每一个合法的移动都成为一条成本为1的边。 

微妙的部分是正确定义图形状态。 状态不仅仅是一个坐标。 它是一个坐标以及当前活动的棋子类型。 然而，因为每个可到达的非阻塞单元格都会立即确定棋子类型，所以我们可以简单地存储坐标并从该单元格上的角色生成移动。 每个单元都有一组固定的传出边缘。 

由于每条边都具有相同的成本，因此广度优先搜索以距离递增的顺序探索状态。 BFS 第一次到达目标单元格时，距离最小。 棋盘只有 10000 个单元，每个单元都有固定数量的可能移动，因此整个搜索很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 可到达的单元格数量呈指数增长 | O(N²) 递归状态 | 太慢了 |
 | 最佳 | O(N²) | O(N²) | 已接受 |

 ## 算法演练

 1. 从初始单元格开始广度优先搜索。 存储到每个单元格的距离，`-1`这意味着该单元尚未被访问过。 起始单元格接收距离`0`因为不需要移动就能留在那里。 
2. 从 BFS 队列中删除一个单元并检查其类型。 如果是的话`h`，生成所有骑士动作。 如果是的话`p`，生成所有特殊的棋子动作。 移动规则仅取决于当前单元格，因此这足以了解所有可能的下一个状态。 
3. 对于每个生成的位置，检查其是否位于棋盘内部且未被遮挡。 如果没有被访问过，则将当前距离加一并放入队列中。 
4. 继续，直到队列为空或到达目的地。 如果目的地接收到距离，则打印它。 否则，打印`-1`。 

为什么它有效：

 BFS 保持不变，即当一个单元从队列中删除时，存储的距离是从起始点到该单元的最短路径的长度。 每条边都代表一次移动，因此 BFS 处理所有长度的路径`k`在任何长度的路径之前`k + 1`。 由于单元格在第一次到达时就被标记为已访问，因此以后到同一单元格的较长路径无法改善答案。 因此目的地接收到其最短的可能距离。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    board = [input().strip() for _ in range(n)]

    sr, sc = map(int, input().split())
    tr, tc = map(int, input().split())

    sr -= 1
    sc -= 1
    tr -= 1
    tc -= 1

    dist = [[-1] * n for _ in range(n)]
    dist[sr][sc] = 0

    knight_moves = [
        (-2, -1), (-2, 1), (-1, -2), (-1, 2),
        (1, -2), (1, 2), (2, -1), (2, 1)
    ]

    pawn_moves = [
        (-1, 0), (1, 0), (0, -1), (0, 1)
    ]

    q = deque([(sr, sc)])

    while q:
        r, c = q.popleft()

        if r == tr and c == tc:
            print(dist[r][c])
            return

        moves = knight_moves if board[r][c] == 'h' else pawn_moves

        for dr, dc in moves:
            nr = r + dr
            nc = c + dc

            if 0 <= nr < n and 0 <= nc < n:
                if board[nr][nc] != 'x' and dist[nr][nc] == -1:
                    dist[nr][nc] = dist[r][c] + 1
                    q.append((nr, nc))

    print(-1)

if __name__ == "__main__":
    solve()
```棋盘完全按照给定的方式存储，因此检查当前单元格类型会立即给出可用的移动。 距离数组兼作访问标记和答案存储，避免了第二种结构。 

队列仅包含坐标，因为棋子变换已经由棋盘字符编码。 当删除坐标时，代码会在探索邻居之前选择正确的移动列表。 

边界检查发生在访问板之前。 这可以防止无效索引被解释为有效单元格。 目的地检查是在从队列中弹出时完成的，这是安全的，因为 BFS 保证这已经是最短距离。

 ## 边缘情况

 对于第一个边缘情况：```
1
h
1 1
1 1
```BFS 从队列中已有的目的地开始。 第一个移除的状态距离为零，因此算法立即返回`0`。 

对于第二种边缘情况：```
2
hp
xx
1 1
1 2
```起始单元是一个`h`细胞，因此 BFS 生成骑士动作。 目标小区一举可达并接收距离`1`。 使用 pawn 到处移动的解决方案会错误地报告失败。 

对于第三种边缘情况：```
3
xxx
xpx
xxx
2 2
2 2
```中心单元是孤立的，但它也是目的地。 BFS 永远不需要离开它。 存储的初始距离保持不变`0`，这是正确答案。
