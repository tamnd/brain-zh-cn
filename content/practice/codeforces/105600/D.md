 ## 问题理解

 我们得到了一系列数字，每次增加一个元素。 读取前 k 个元素后，Masha 和 Gleb 在该前缀上玩一个游戏，并重复将两个选定的元素组合成一个新值，直到只剩下一个数字。 确切的合并规则是确定性的：当选择两个数字时，它们将被删除并替换为从它们的总和中派生的单个数字，除以二后向下舍入，然后再次加倍。 此操作有效地强制结果为不超过原始总和的偶数。 

游戏是对抗性的。 玛莎和格莱布轮流轮流，每个人都选择目标相反的配对。 Masha希望最终的剩余值尽可能大，而Gleb则希望使其尽可能小。 对于每个长度为 k 的前缀，我们必须确定双方最佳发挥下的最终值。 

输出是答案序列，其中第 k 个值对应于仅限前 k 个元素的游戏结果。 

所有测试用例的总 n 最多为 10^5 的约束意味着任何解决方案都必须接近每个测试用例的线性或线性。 对所有合并选择进行三次甚至二次模拟是不可能的，因为每个游戏状态都包含多个元素，并且每次移动都会将大小减少一，导致在简单模拟中每个前缀执行 O(n^2) 次操作，这将立即超出限制。 

一个微妙的困难是操作本身隐藏了奇偶校验行为。 由于合并结果始终是偶数，因此奇数贡献会以结构化方式系统地向下舍入。 将其视为算术平均乘以二的简单实现可能会忽略只有中间和的奇偶校验才重要，而不是精确值。 

打破朴素推理的边缘情况来自小前缀。 当k等于1或2时，不存在真正的战略选择，直接应用任何推导公式都必须与平凡的结果相匹配。 当所有数字都相等时，会出现另一种边缘情况。 贪婪的合并策略可能会错误地假设稳定性，但奇偶校验调整仍然会根据配对顺序以不同的方式累积，即使最终答案会崩溃为简单的模式。 

## 方法

 解决该问题的一种强力方法是显式模拟每个前缀的游戏，并尝试所有可能的合并序列，同时为两个玩家交替最佳选择。 对于大小为 k 的固定前缀，有 (k − 1) 次移动，每次移动时玩家都会从 O(k^2) 种可能性中选择一对。 即使忽略博弈树交替，将元素配对到归约序列中的方法数量也会呈阶乘增长，并且完整的极小极大搜索呈指数增长。 

即使只是尝试所有贪婪配对序列的更简单的蛮力，每个前缀最多仍然是 O(k^2)，从而导致总体 O(n^3)。 当n达到10^5时，这是完全不可行的。 

关键的观察结果是该操作不保留完整的数字结构。 这种转换总是将信息折叠成仅依赖于排序和奇偶校验累积而不依赖于精确值的东西。 一旦我们重新解释合并，我们就会注意到每个操作的行为都类似于对两个数字求和并将其向下舍入到最接近的偶数。 这意味着每次合并实际上最多损失一个单位的价值，并且该损失仅取决于总和是否为奇数。 

这种结构将游戏从组合配对问题变成了贪婪的会计问题：唯一重要的是每一步存在多少奇怪的贡献，以及玩家如何强制或避免创造它们。 最佳游戏简化为维持跟踪总和的全局值加上由对手强制进行的奇数交互确定的校正。

最后的简化是，我们维护一个运行总计和反映奇偶校验不匹配的二次调整，而不是模拟合并。 每个新的前缀更新都可以在 O(1) 内处理，因为添加一个元素只会更改一个小的本地奇偶校验状态。

 ## 算法演练

 1. 维护目前为止看到的所有元素的总和。 这表示合并产生任何舍入影响之前的基值。 
2. 跟踪当前前缀中有多少个元素是奇数。 这是必要的，因为每个合并操作仅在所选对的总和为奇数时才会引入舍入，这完全由奇偶校验确定。 
3. 对于每个新元素 a[i]，立即通过添加来更新运行总和。 
4. 更新奇偶校验计数器：如果 a[i] 为奇数，则递增奇偶校验计数器。 这使我们能够知道系统中存在多少潜在的“奇怪的相互作用”。 
5. 使用导出的不变量计算前缀 i 的答案：最终值等于总和减去不可避免的奇偶校验丢失的数量，这取决于在最佳对抗配对下有多少奇数元素保持未配对。 

此校正的确切形式简化为减去下限(odd_count / 2)。 每对奇数都可以被迫进行合并，由于舍入行为而恰好丢失一个单位，并且最佳游戏确保这些配对在对抗结构下最大化。 

### 为什么它有效

 每次合并都会替换两个数字，并将它们的总和向下舍入到最接近的偶数。 这相当于在除以二之前先减去和的奇偶校验。 由于奇偶校验是信息丢失的唯一来源，因此整个过程可以简化为跟踪两个奇数被迫组合的次数。 对抗性性质确保所有此类损失都会在任何可能的情况下实现，并且没有任何策略可以造成超出配对赔率的额外损失。 这建立了一个稳定的不变量：处理 k 个元素后，答案仅取决于总和和奇数元素的数量，而不取决于排列或历史。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        s = 0
        odd = 0
        res = []

        for x in a:
            s += x
            if x % 2:
                odd += 1

            # each pair of odds causes one unavoidable loss
            loss = odd // 2
            res.append(s - loss)

        print(*res)

if __name__ == "__main__":
    solve()
```该实现维护一个运行总和和一个奇数元素的计数器。 每次前缀更新后，它都会计算存在多少个完整的奇数对，因为每个这样的对都代表最佳播放下的强制奇偶校验丢失。 立即应用减法，从而可以在恒定时间内生成每个前缀答案。 

唯一微妙的一点是，损失取决于奇数计数除以二的整数除法，而不是跟踪单个合并。 这避免了直接模拟游戏结构的需要。

 ## 边缘情况

 单元素前缀很简单，因为不会发生合并，因此答案必须等于元素本身。 该算法可以处理此问题，因为奇数计数要么为 0，要么为 1，并且整数除法可确保不会产生损失。 

当所有数字都是偶数时，奇数计数器始终保持为零，因此不会减去任何校正。 这证实了合并操作仅影响奇偶校验驱动的情况。 

当所有数字都是奇数时，每两个元素最终形成一对，贡献一个单位的损失。 追踪这样的案例表明，修正值的增长与floor(k/2) 完全相同，与对抗性配对过程的结构相匹配。
