 ## 解决方案
 ## 问题理解

 任务是将给定的数字分为两组。 如果两个数字被放在同一组中，则两个数字将获得其正常总和，但会受到额外的惩罚`h`如果两个数字分开。 在考虑每一对之后，我们查看最大和最小的结果值，目标是使它们的差异尽可能小。 

输入包含数字数量、惩罚值和数字本身。 输出要求尽可能小的差异以及将每个数字有效分配给两组之一。 

数组的大小可以达到`100000`，而值和`h`可以非常大。 这排除了尝试所有分区，因为有`2^n`给元素着色的可能方法。 即使检查每个分区的所有对也是不可能的。 我们需要一个接近的解决方案`O(n log n)`或者`O(n)`。 

棘手的情况来自于允许空组并且惩罚可以主导答案的事实。 例如，如果每个元素都放入一组，则惩罚永远不会出现。 

对于输入：```
3 10
1 2 3
```总是分割数组的粗心解决方案可能会增加不必要的损失。 将所有内容放入一组给出对值`3`,`4`， 和`5`，所以答案是`2`。 

另一种边缘情况是最小和最大元素分开。 为了：```
3 100
1 2 3
```推杆`1`和`2`分成不同的组会产生非常大的最小值，但是将`2`和`3`创建一个非常大的最大值。 最佳决策必须平衡两种影响，而不是只看一方面。 

## 方法

 直接的强力解决方案将尝试将所有可能的元素分配给这两个组。 对于每个作业，我们可以检查所有对并计算最大值和最小值之间的差异。 这是正确的，因为考虑了每个可能的分区。 然而，有`2^n`分区，每个分区最多需要`O(n^2)`工作，给出了粗略的不可行的最坏情况`O(2^n * n^2)`运营。 

有用的观察是，实际值仅取决于哪些元素被分离，最小和最大的数字是可以影响极值的数字。 对值进行排序后，最佳分区可以被视为将排序后的数组分割成两个连续的部分。 如果两个值位于此分割的同一侧，则它们的总和不会增加。 如果它们位于相反的两侧，则它们的总和为`h`。 

对于固定分割，我们只需要知道最小和最大可能的对值。 最小的候选者来自同一侧的最小两个元素，或最小的交叉对。 最大的候选来自同一侧最大的两个元素，或最大的交叉对。 

我们可以在排序后扫描每个可能的分割并在恒定时间内计算这四个边界值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n^2) | O(2^n * n^2) | O(n) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对元素进行排序，同时保留其原始索引。 排序顺序让我们能够推断出最小和最大可能的对和。 
2. 尝试排序元素之间所有可能的分割位置，包括所有元素都位于一组的情况。 分叉的左侧接收一个标签，右侧接收另一个标签。 
3. 对于当前的分割，计算最小可能的对值。 它只能来自左组内的最小对、右组内的最小对或带有附加惩罚的最小跨组对。 
4. 计算最大可能的对值。 它只能来自左组内最大的对、右组内最大的对或带有附加惩罚的最大跨组对。 
5. 最大和最小候选值之间的差值就是本次分割的质量。 保持差异最小的分割并从中重建标签。 

为什么有效：排序后，远离末端只会使最小候选者的总和变大，而最大候选者的总和变小。 不靠近边缘的对不能创建新的全局最小值或最大值，因为它由更极端的对主导。 最佳排列可以通过分离前缀和后缀来表示，因此检查所有此类拆分涵盖了最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, h = map(int, input().split())
    arr = list(map(int, input().split()))

    a = sorted([(x, i) for i, x in enumerate(arr)])

    best = 10**30
    ans = [1] * n
    best_split = 0

    for k in range(n + 1):
        mn = 10**30
        mx = -1

        if k >= 2:
            mn = min(mn, a[0][0] + a[1][0])
            mx = max(mx, a[k - 2][0] + a[k - 1][0])

        if n - k >= 2:
            mn = min(mn, a[k][0] + a[k + 1][0])
            mx = max(mx, a[n - 2][0] + a[n - 1][0])

        if k > 0 and k < n:
            mn = min(mn, a[0][0] + a[k][0] + h)
            mx = max(mx, a[k - 1][0] + a[n - 1][0] + h)

        if k == 0 or k == n:
            mn = a[0][0] + a[1][0]
            mx = a[n - 2][0] + a[n - 1][0]

        if mx - mn < best:
            best = mx - mn
            best_split = k

    for pos in range(best_split):
        ans[a[pos][1]] = 1
    for pos in range(best_split, n):
        ans[a[pos][1]] = 2

    print(best)
    print(*ans)

if __name__ == "__main__":
    solve()
```代码首先存储值和原始位置，因为答案必须按原始顺序打印。 排序仅更改用于推理的顺序。 

循环检查`n + 1`可能的分裂。 边界检查会小心地对待小团体。 少于两个元素的组无法创建同组对，因此它不能贡献最小或最大候选。 的情况下`k`是`0`或者`n`表示将每个元素放入一个组中。 

重建步骤将所选的排序分割转换回原始索引。 分割之前的值得到一种颜色，分割之后的值得到另一种颜色。

 ## 边缘情况

 对于惩罚非常大的情况：```
3 100
1 2 3
```该算法检查一侧有一个元素的拆分。 交叉对获得额外的`100`，因此它们的值变得比同组对大得多。 all-one-group 选项给出了尽可能小的范围，因此选择它。 

对于具有相等值的情况：```
5 10
4 4 4 4 4
```一组内的每对和是`8`，任何分裂对都变成`18`。 最好的选择是将所有东西放在一起，生产范围`0`。 

对于分割看起来很诱人的情况：```
4 5
1 2 8 9
```分离小值和大值通过添加来改变对值`5`到许多组合。 扫描会评估每个分割的确切最小值和最大值，因此它可以避免选择改善一侧而损害另一侧的分割。
