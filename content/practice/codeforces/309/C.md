 ## 解决方案
 ## 问题理解

 我们的内存布局被分成几个连续的空闲段，我们可以将其视为独立的空间块。 每个块都有固定的长度，并且我们还有一个可能想要放入此内存中的数组集合。 每个数组消耗给定长度的连续内存段，并且它必须完全适合单个块。 

任务是选择要放置哪些数组以及放置它们的位置，以便最大限度地增加成功存储的数组数量。 每个块可以容纳多个数组，只要它们不重叠并且不适合其容量，但是数组不能跨块拆分，并且块是独立的，因为我们不能合并它们。 

输入的结构很重要：我们正在匹配两个多重集、块容量和数组大小，目标是在每个块内的间隔包装约束下最大化成功分配的数量。 

约束很大，最多有 10^6 个块和 10^6 个数组。 任何尝试模拟放置或尝试每个块或每个阵列的组合的解决方案都会太慢。 唯一可行的解​​决方案大约是 O(n log n) 或 O(n) 排序和贪婪处理。 这立即排除了对所有子集或每块组合包装的任何动态编程。 

当以错误的顺序进行贪婪匹配时，会出现微妙的边缘情况。 例如，如果我们尝试首先将大型数组放入大块中而不协调剩余空间，则可能会浪费碎片机会。 如果我们独立地处理块并贪婪地打包每个块而不考虑数组的全局最优排序，则会出现另一种失败情况。 

## 方法

 强力解释将尝试将数组分配给块并检查可行性。 即使我们简化为“对于每个数组，尝试将其放入某个块中”，这也会变成 O(nm)，当两者都达到 10^6 时，这远远超出了限制。 

通过对块和数组进行排序，并针对每个数组扫描块以找到合适的块，可以改进更结构化的暴力破解。 这减少了常数因子，但仍然退化为二次行为。 

关键的观察是，每个数组只需要块内的连续段，因此如果我们固定其中使用的数组类型，则大小为 A 的块最多可以容纳大小为 2b 的 Floor(A / (2b)) 数组。 然而，在一个块内混合不同的大小会使直接计数变得复杂。 

关键的见解是，如果可以分配一个较小的数组来代替它，那么我们永远不会从将一个大数组分配到一个块中受益，因为较小的数组更灵活，并且可以为大数组保留大块。 这导致了全局贪婪策略：对数组和块进行排序，并始终尝试首先将最小的数组匹配到可以容纳它们的最小块中，或者等效地从最受约束的一侧进行处理，同时保持可行性。 

强制执行此操作的标准方法是对块大小和数组大小进行排序，并使用指针的贪婪匹配，始终尝试将最小的剩余数组放入可以容纳它的最小可用块中。 当一个块太小时，它会被跳过； 当它足够大时，使用一次，然后我们继续前进。 

这将问题转化为对排序数组和块的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 最优贪心匹配 | O(n log n + m log m) | O(n log n + m log m) | O(1)-O(n+m) | 已接受 |

 ## 算法演练

1. 将每个数组需求转换为其实际内存需求，即2*b[i]。 这将两个输入标准化为可比较的段长度。 
2. 按非递减顺序对块大小进行排序。 排序确保我们始终首先考虑最小的可用容量，这可以防止在较小的块就足够的情况下，在小需求上浪费大块。 
3. 按非递减顺序对数组大小进行排序。 这与首先​​分配限制性最强（最小）的数组的想法是一致的，这样可以最大限度地提高以后分配较大数组的灵活性。 
4. 初始化两个指针，一个用于块，一个用于数组，两者都从排序列表的开头开始。 
5. 当两个指针都有效时进行迭代。 在每一步中，将当前最小的未分配数组与当前最小的可用块进行比较。 
6. 如果当前块太小而无法容纳数组，则丢弃该块并移至下一个较大的块。 这是安全的，因为由于排序，该块不能用于任何剩余的数组。 
7. 如果该块可以容纳该数组，则将该数组分配给该块，增加已放置数组的计数，并将两个指针向前移动。 这确保了每个块在这个简化的匹配模型中最多使用一次，这是有效的，因为任何可以适合当前最小数组的块都可以用于它，而不会损害最优性。 

### 为什么它有效

 正确性依赖于排序引起的单调可行性结构。 一旦数组和块被排序，可行性就成为一个阈值条件：如果一个块不能容纳给定的数组，它也不能容纳任何更大的数组。 这确保了跳过块始终是安全的。 类似地，将最小的可用数组分配给最小的可行块可以避免不必要地消耗大块，从而为将来更大的数组保留容量。 这种贪婪的结构确保所做的每个分配都是局部最优的，并且不会阻止任何可能增加总计数的未来可行分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

a.sort()
b = sorted(x * 2 for x in b)

i = j = 0
ans = 0

while i < n and j < m:
    if b[j] >= a[i]:
        ans += 1
        i += 1
        j += 1
    else:
        j += 1

print(ans)
```该解决方案首先读取两个序列并将数组要求转换为实际的内存长度。 对两个列表进行排序至关重要，因为它创建了双指针扫描所需的单调结构。 

指针`i`跟踪我们想要放置的下一个数组，并且`j`跟踪我们可能使用的下一个块。 当当前块太小时，它会被丢弃，因为它无法为任何等于或大于当前大小的剩余数组提供服务。 当它适合时，我们提交分配并推进两个指针，确保块和数组都不会被重用。 

一个常见的错误是扭转不平等或朝错误的方向迭代。 正确的比较始终是块是否可以容纳数组，而不是相反。

 ## 边缘情况

 关键的边缘情况是当许多小块出现在大型数组所需的大块之前时。 对于输入如：```
3 2
100 1 1
50 50
```排序产生块`[1, 1, 100]`和数组`[50, 50]`。 如果我们允许重用，该算法会跳过两个小块，并将两个数组错误地分配给大块，但由于每个块都是一次性的，因此只有一个 50 适合，所以答案是 1。贪婪指针确保我们不会错误地重用容量。 

另一种边缘情况是当数组都小于除最小的几个块之外的每个块时。 为了：```
4 3
8 7 6 5
1 1 1
```该算法立即将三个最小的数组分配给三个最小的可行块，从而确认小数组的早期消耗始终是安全的，并且不会阻止更大的分配，因为不存在更大的数组。
