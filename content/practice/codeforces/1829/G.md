 ## 解决方案
 ## 问题理解

 该问题的结构是一个由编号罐组成的固定金字塔，其中金字塔中的每个位置都包含一个平方数。 如果我们想象通过罐头在三角形堆栈中的位置对罐头进行索引，则每个罐头上写入的值不是其位置索引，而是整数标签的平方。 重要的机制是当一个罐头被击中时会发生什么：堆叠关系中它“上方”的所有东西也会掉落，形成一条通过金字塔向上延伸的链条。 

任务是计算当我们击中标记的罐子时掉落的所有罐子值的总和$n^2$。 由于下落通过确定性结构向上传播，因此结果纯粹是以下函数：$n$，不是任何动态模拟。 

就查询数量和查询量而言，约束很大$n$，最多可以达到$10^6$。 任何模拟下落的罐头或显式构建金字塔的解决方案在时间和内存上都太慢。 甚至每个测试用例对结构的遍历也与$n$将达到$10^9$最坏情况下的操作。 

正确的方法必须将每个查询减少到恒定时间或对数时间。 这强烈表明下降区域具有封闭形式的结构或对应于已知的算术模式。 

边缘情况出现时$n$很小，比如$n=1$，只有一个可以掉落。 幼稚的解释可能会尝试错误地向上遍历并包含不存在的元素或过多的重复项。 另一个微妙的问题是，下降区域并不是“所有数字都达到$n$”，但是依赖于三角形分层的稀疏子集；即使遍历逻辑看起来一致，缺少这个也会导致求和不正确。

 ## 方法

 暴力解释首先是明确地模拟金字塔。 人们可以想象建造一排金字塔，然后从起始位置执行 BFS 或 DFS$n^2$，遵循“正上方”关系。 每个访问过的节点都将其平方值贡献给答案。 

这在原则上是正确的，因为它精确地模拟了下落传播。 然而，金字塔的高度可达$2023$，并且在多个测试用例中，每个查询的完整模拟是不必要的，而且仍然很昂贵。 更糟糕的是，如果推广到约束隐含的更大隐藏结构，则向上遍历可以是$O(n)$每个查询，变成$10^6$每个测试用例最多$10^9$总操作。 

关键的观察是下降的结构不会任意分支。 每个罐头都有一条唯一确定的向上的“父母”链，这些链对应于整数到三角坐标的特定分解。 当仔细遵循父关系时，所访问的索引集合实际上是通过重复减去递增偏移量生成的一组整数，这相当于选择其二进制表示对应于金字塔的特定结构级别的索引。 

这将问题转换为纯粹的算术计算：我们不是模拟图中的移动，而是确定哪些索引对总和有贡献，并使用贪婪分解直接累加它们的平方值。

 ## 算法演练

 下落罐头的结构可以解释为从整体上反复剥落一层$n$，其中每一层对应于金字塔索引系统中的一个三角形边界。 

1. 从给定的开始$n$，它代表最底层受影响的可以标记$n^2$。 我们维护一个运行指针来跟踪我们向上传播的距离。 
2. 在每一步中，确定当前“层”中有多少个连续整数在结构跳转到下一个结构边界之前做出贡献。 这是由三角形增长决定的，因为金字塔中的每一行都包含越来越多的元素。 
3. 减去最大可行层大小$n$，并将该层中的所有整数记录为贡献值。 每个人都为答案贡献自己的平方。 
4. 对剩余的缩减索引重复该过程，直到没有剩余值。 这确保了我们遵循精确的向上链，而不会跳过或重复计算任何结构祖先。 
5. 在分解过程中累加所有选定整数的平方和。 

关键思想是分解中的每个整数与祖先链中的一个落下的罐子完全对应，并且分解确保了选择的唯一性。 

### 为什么它有效

 从任何一个向上传播都可以形成严格递减的有效标签序列，并且每一步都移动到基于金字塔几何形状的唯一确定的父级。 这种唯一性保证了每个有效的下降可以恰好对应于分解中的一个步骤，并且没有两个步骤产生重叠的索引。 该算法有效地重建了祖先链，而无需显式遍历它，从而保留了贡献的完整性和不相交性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# Precompute prefix sums of squares up to 1e6
MAXN = 10**6
pref = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pref[i] = pref[i - 1] + i * i

def solve_one(n):
    # greedy decomposition based on triangular layer structure
    res = 0
    cur = n
    step = 1

    while cur > 0:
        take = min(cur, step)
        # sum of squares in this segment
        res += pref[step] - pref[step - take]
        cur -= take
        step += 1

    return res

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve_one(n)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案依赖于平方的前缀和数组来在恒定时间内回答段查询。 主循环执行分层分解：每次迭代消耗越来越多的元素，这反映了金字塔行宽度的扩大。 前缀数组避免了重复重新计算平方和。 

一个微妙的细节是处理`step`作为当前图层大小。 它确定性地增加，确保每一层都对应于金字塔中唯一的结构级别。 相差一的错误通常发生在索引前缀和时； 正确的减法是`pref[r] - pref[l-1]`，这里实现为`pref[step] - pref[step - take]`。

 ## 边缘情况

 对于$n=1$，算法初始化`cur = 1`并只取一个元素`step = 1`。 前缀减法返回$1^2$，并且循环立即终止。 这确认了基础层被正确处理而没有进入无效状态。 

对于非常大的$n$， 例如$10^6$，循环逐步增长，但由于每次迭代消耗的元素数量不断增加，因此迭代次数仍然很小。 前缀总和确保即使是大的段也会在恒定时间内聚合，从而防止出现性能问题。 

对于较小的中间值，其中`cur < step`， 这`take = min(cur, step)`逻辑确保我们只消耗剩余的有效元素，避免超出可用结构。
