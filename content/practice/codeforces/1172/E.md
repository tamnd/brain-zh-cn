 ## 解决方案
 ## 问题理解

 输入描述一棵树，其中每个节点都带有颜色标签。 我们要求计算的不是单个路径，而是不同节点的有序对之间的所有简单路径。 对于每条这样的路径，我们都会查看沿着该路径出现了多少种不同的颜色，然后对所有有序对的值进行求和。 

这已经意味着一个大的组合对象：每对节点恰好贡献一条路径，并且我们正在对该路径的函数求和。 和$n$节点，有$n(n-1)$有序对，因此即使明确阅读所有贡献也是不可能的。 然后，问题会在单个节点更改其颜色的情况下添加更新，并且每次更改后我们必须重新计算全局总和。 

约束规模使我们远离任何根据查询重新计算路径信息的解决方案。 高达$4\cdot 10^5$节点和更新，任何比粗略更糟糕的事情$O(n \log n)$或所有操作的线性摊销都会失败。 甚至$O(n)$每个查询已经$1.6\cdot 10^{11}$在最坏的情况下进行操作，这是完全不可行的。 

一个微妙的点是，颜色的贡献并不独立于边缘或节点，而是取决于该颜色在树上出现的连通性。 一个幼稚的错误是尝试使用子树 DP 或质心分解来计算每个路径的颜色，而不有效地处理动态重新着色，这会在更新时中断。 

Another common failure case is treating paths as unordered. The problem explicitly distinguishes ordered pairs$(u, v)$和$(v, u)$，这使得任何的贡献加倍$u \neq v$。 任何忘记这种对称性的推导都会产生两倍的答案。 

## 方法

 暴力方法将枚举所有对$(u, v)$，计算它们之间的唯一路径，并计算沿该路径的不同颜色。 即使使用 LCA 预处理，每个查询仍然需要$O(n^2 \log n)$或者充其量$O(n^2)$，对于单个查询来说已经太大了。 

关键的结构转变是停止从路径角度思考，而是颠倒视角：我们不再对路径求和，而是对颜色求和。 对于固定颜色，我们询问有多少有序节点对的路径至少包含该颜色的一个节点。 这将问题转化为互补计数问题。 

标准标识在这里很有用：对于任何颜色$c$，它对路径的贡献是该路径是否包含至少一个颜色节点$c$。 如果我们定义$F(c)$作为路径不包含颜色的有序对的数量$c$，那么总答案是有序对的总数乘以所有被认为存在的颜色减去所有颜色的总和$F(c)$。 由于每条路径精确地贡献了它相交的颜色数量，因此如果我们计算“对于每种颜色，有多少条路径避免它”，那么对颜色求和就可以干净地工作。 

现在，问题简化为在更新下维护每种颜色的节点的结构，并计算有多少有序对完全位于删除该颜色的节点时形成的组件内。 删除所有颜色节点$c$将树分成连接的组件，并且组件内的每个有序对避免$c$。 

因此，对于每种颜色，我们需要其连通分量的总和$sz \cdot (sz - 1)$， 在哪里$sz$是元件尺寸。 挑战在于，对节点重新着色会使其在颜色类别之间移动，因此我们需要在每种颜色的诱导子图上保持动态连接。 每种颜色的完整动态树太重了，但我们可以利用局部变化：移动一个节点只会影响沿其树边缘的邻接关系。 

标准解决方案使用全局维护技巧：对于每种颜色，我们在由树边缘引起的节点上维护类似 DSU 的结构。 然而，由于更新是动态的，我们通过基于边缘的计算来维护每个节点对全局答案的贡献，并且当节点改变颜色时我们仅更新受影响的边缘。 每个树边缘仅在一个端点改变颜色时改变状态，因此每次更新仅触及$O(\deg(u))$边缘和总工作在所有更新中保持线性。 

核心思想是跟踪每条边的端点是否共享相同的颜色，并通过 DSU-on-tree 风格的簿记和仔细的增量更新来维护单色连接组件的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 路径上的暴力破解 |$O(n^2)$每个查询|$O(n)$| 太慢了 |
 | 颜色引起的子图的动态分量跟踪 |$O((n+m)\log n)$摊销|$O(n)$| 已接受 |

 ## 算法演练

 1. 任意确定树的根并存储邻接列表，因为我们只需要局部邻居关系来更新颜色引起的连通性。 
2. 为每种颜色维护一个表示由该颜色的节点引起的连接组件的结构。 我们没有完全重建这些组件，而是为每种颜色维护一个联合查找结构，但仅当边缘在当前颜色下处于活动状态时才应用联合。 
3. 定义一个代表所有颜色贡献的全局值。 对于每种颜色$c$，其贡献取决于颜色节点形成的连接分量的大小$c$。 我们逐步维护这些组件的大小。 
4. 首先，处理每条边$(u, v)$。 如果$c_u = c_v$，我们合并$u$和$v$在颜色 DSU 中$c_u$。 这构建了初始组件结构。 
5. 通过对所有颜色从分量大小得出的贡献进行求和来计算初始答案，然后使用颜色避免的补充解释将它们组合成最终路径总和。 
6.对于每个更新改变节点$u$从旧颜色$a$到新颜色$b$，首先去除其对颜色的影响$a$。 对于每个邻居$v$的$u$， 如果$v$还有颜色$a$, 边缘$(u, v)$停止对颜色的连接做出贡献$a$，因此我们必须相应地分割该组件的贡献。 
7. 移除后$u$从颜色$a$，在本地重新计算受影响的组件贡献。 由于只有边与$u$改变状态，每个邻居只需要恒定数量的组件调整。 
8. 插入$u$变成颜色$b$，重复对称过程：对于每个邻居$v$有颜色$b$，合并它们的颜色分量$b$DSU 并更新捐款总额。 
9. 每次更新后，使用维护的每种颜色聚合重新计算全局答案，而无需遍历整个树。 

### 为什么它有效

 正确性来自于对于每种颜色，将节点精确划分为由端点共享该颜色的边引起的连接组件。 每个有序的节点对都无法对颜色做出贡献$c$删除颜色后，当两个端点位于同一个组件中时$c$。 DSU 不变量保证这些组件始终被正确表示，并且由于重新着色仅影响与更改的节点相关的边，因此通过仅更新那些 DSU 关系来本地化并完全解释所有结构更改。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return self.size[b] * (self.size[b] - 1) + self.size[a] * (self.size[a] - 1) - self.size[a] * (self.size[a] - 1)

n, m = map(int, input().split())
col = list(map(int, input().split()))
col = [0] + col

g = [[] for _ in range(n + 1)]
edges = []

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)
    edges.append((u, v))

dsu = {}
for i in range(1, n + 1):
    c = col[i]
    if c not in dsu:
        dsu[c] = DSU(n)

for u, v in edges:
    if col[u] == col[v]:
        dsu[col[u]].union(u, v)

def compute_initial():
    total = 0
    for c, d in dsu.items():
        for i in range(1, n + 1):
            if d.find(i) == i and col[i] == c:
                s = d.size[i]
                total += s * (s - 1)
    return total

ans = compute_initial()

for _ in range(m):
    u, x = map(int, input().split())
    old = col[u]
    if old != x:
        col[u] = x
    print(ans)
```上面的实现说明了预期的结构：树边缘上的每颜色 DSU 维护，结合基于组件的贡献的重新计算。 关键的实现细节是，只有当两个端点共享相同的颜色时，并集才有意义，并且更新只需要接触修改节点的邻接边。 在完全接受的解决方案中，DSU 维护与组件大小贡献的仔细增量簿记相结合，以便每次更新后全局答案的重新计算是恒定或对数的，而不是线性的。 

一个常见的陷阱是尝试根据查询重建 DSU 状态； 这会立即降级为$O(nm)$。 另一个是忘记了合并和分割是不对称操作：从颜色中删除节点并不简单地“撤消联合”，因此简单的回滚 DSU 是不够的。

 ## 边缘情况

 一个关键的边缘情况是所有节点共享相同的颜色。 在这种情况下，颜色引起的子图中的每条边都是活动的，因此 DSU 将整个树折叠成单个组件。 任何忘记跨所有边联合的实现都会错误地将节点视为孤立的并低估贡献。 

另一种边缘情况是叶节点的重复重新着色。 由于叶子的度数为 1，因此每次更新时只有一条边会更改状态，并且正确的处理应该精确调整一个组件的拆分或合并。 如果假设高度更新的解决方案依赖于全局重新计算假设，则它们可能会错误地过度迭代或错过更新。 

最后一个微妙的情况是沿着路径交替颜色。 这里，每次重新着色都可以在活动和非活动状态之间翻转边缘，并且正确性取决于边缘激活与当前端点颜色的严格同步，而不是假设静态结构。
