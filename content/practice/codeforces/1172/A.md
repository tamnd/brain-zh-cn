 ## 解决方案
 ## 问题理解

 我们的系统分为两部分：一手牌和一堆牌。 它们一起包含从 1 到 n 的每一张整数卡，并且只包含一次，而零表示空占位符，其行为就像没有值的虚拟卡。 

该堆具有固定的从上到下的顺序，目标是转换该堆，使其从上到下完美排序为 1, 2, 3, …, n。 影响系统的唯一方法是通过消耗手牌中一张牌的操作：我们选择任何手牌位置，将该牌推到牌堆底部，然后立即将牌堆中当前最上面的牌抽回该手牌位置。 

这创建了一个耦合过程：每个动作同时将一张手牌注入到牌堆中，并将一张牌抽取到手牌中。 任务是找到使该堆排序所需的此类操作的最少数量。 

关键的困难在于堆不能自由地重新排序。 其内部顺序只能通过与手牌交换来间接修改，并且每次交换都受到操作的固定结构的约束。 

约束条件很大，n 高达 200,000。 这立即排除了每次操作重复扫描或重建堆的任何模拟。 任何尝试逐步模拟该过程的解决方案在最坏的情况下都会面临 O(n^2) 行为的风险，这太慢了。 

当最有用的牌最初在手上时，就会出现微妙的边缘情况。 例如，如果该堆已经包含一长串正确数字的前缀，但顺序是打乱的，则贪婪地修复最早的不匹配的幼稚策略可能会浪费交换不相关卡片的操作。 另一个有问题的情况是，当零占据早期牌堆位置时，会延迟获得有意义的牌，并会误导性策略，认为早期进展意味着全球进步。 

## 方法

 暴力解释直接模拟该过程。 在每一步中，我们都会尝试所有可能的手选择，应用操作，并探索结果配置，直到堆被排序。 这在原则上是正确的，因为它探索了可达配置的完整状态空间，但每一步的分支因子都是 n，深度也可以是 n 的线性。 这导致可能性呈指数级爆炸，远远超出 n 高达 200,000 的任何可行限制。 

关键的观察结果是，该操作并不有意义地取决于选择的手的位置，仅取决于所玩的值。 一旦一张牌被移入牌堆，牌堆的演变仅取决于插入值的顺序，而不取决于它们的位置。 这意味着问题可以重新定义为决定编号卡“激活”到堆中的顺序。 

现在考虑所需的最终配置：堆必须按顺序从 1 到 n。 这意味着我们正在有效地努力确保当系统稳定时，每个数字 i 相对于之前的数字都出现在正确的位置。 唯一的障碍是，在每张所需的卡片在堆的顶部结构中变得可访问之前，需要进行多少次不相关的插入。 

关键的见解是，我们可以从最终期望的状态向后进行模拟，跟踪按升序“暴露”每个数字所需的操作次数。 每个数字要么已经在堆中，要么被困在其他元素后面，解决它可能需要使用可用的手牌在结构中循环。 

这将问题简化为贪婪重建，其中我们处理从 n 到 1 的数字，并计算在正确放置每个数字之前需要多少次强制操作。

 ## 算法演练

 我们从最大的牌到最小的牌处理最终所需的顺序，维护牌堆和手牌分布的指针。 

1. 为每张牌 1 到 n 建立一个位置图，指示它是从牌堆开始还是从手牌开始。 这允许持续检查每张卡当前所在的位置。 
2. 在堆中维护一个指针，表示我们通过操作有效“清理”或对齐堆的程度。 最初，它位于堆的顶部。 
3. 将目标值从 n 向下迭代到 1。对于每个值 x，确定 x 当前是否已经在当前堆指针处或之前可达。 如果是的话，我们可以从概念上调整它，而无需推进结构之外的额外强制操作。 
4. 如果 x 尚不可访问，我们必须执行有效循环系统的操作，直到 x 可访问。 每个这样的要求都有助于答案，因为它对应于使 x 到位的必要交换周期。 
5. 每次我们模拟需要在堆中“向前跳”以到达 x 时，我们都会增加答案并更新有效状态，以反映通过插入手牌并绘制下一个堆元素已经旋转了堆。 

核心机制是跟踪堆指针如何向前移动，以响应暴露丢失或阻塞元素所需的强制操作。 

### 为什么它有效

 该过程相当于以相反的顺序重复求解下一个最大的所需值。 由于每个操作只能向前推进一个有效步骤来访问更深的堆元素，因此每次遇到尚未到达的值时，我们都被迫花费一个操作来推进系统状态。 这会创建一个单调的进程，其中每个操作都为暴露下一张所需的卡贡献了一个单位的进度。 因为我们总是按降序处理，所以我们永远不会重新审视已经解决的约束，从而确保最优性。

 ## 边缘情况

 一种关键的边缘情况是，所有所需的数字都已按正确顺序排列，但以强制至少一次转移的方式分布在手和堆之间。 例如，如果手中有大多数小数字，算法仍然必须考虑将它们引入到牌堆中会改变后面数字的可访问性这一事实。 

另一个微妙的情况是，堆几乎已排序但包含散布的零。 零对排序没有贡献，但仍然消耗转换，因此任何将它们视为中性的策略都可能低估所需的操作。 该算法处理此问题是因为零永远不会出现在位置图中，因此它们仅通过指针移动间接影响可达性，而不是被误认为有效进度。
