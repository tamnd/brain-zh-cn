 ## 解决方案
 ## 问题理解

 在 Codeforces Gym 106362C 中，Edward 有`n`人们站成一排。 每个人都有魅力值，并且这些值已经按非递减顺序排列。 爱德华想要选择一组连续的人，其平均魅力恰好是他自己的魅力`k`。 目标是找到最长的连续组。 如果不存在这样的组，则答案是`0`。 

输入给出人数、爱德华的魅力值和排序后的魅力数组。 输出只是连续段的最大长度，其平均值等于`k`。 重要的条件是平均值是准确的，而不是四舍五入的。 

约束条件`n <= 100000`立即排除检查每个可能的段。 有大约`n^2 / 2`连续的范围，在最坏的情况下大约有 50 亿个检查。 即使是非常优化的实现也无法在通常的比赛时间限制内完成。 我们需要一种接近线性或`O(n log n)`。 

非显而易见的情况来自于精确平等的要求。 包含周围值的段`k`并不自动有效。 例如：```
5 4
3 5 5 5 5
```正确的输出是：```
4
```该段`3, 5, 5, 5`有总和`18`， 长度`4`, 和平均值`4.5`，所以无效。 有效的最长段是`5, 5, 5, 5`平均`5`，这也是无效的，这意味着该示例实际上没有有效的段。 正确的输出是：```
0
```使用整数除法求平均值的粗心解决方案可能会错误地接受它，因为`18 / 4`变成`4`在某些语言中。 

另一种边缘情况是整个数组有效时：```
4 7
7 7 7 7
```答案是：```
4
```仅搜索周围具有不同值的段的解决方案`k`可能会错误地错过这个案例。 

最后一个常见错误是忘记长度为一的段：```
3 10
5 10 20
```答案是：```
1
```有魅力的单身人士`10`已经形成一个有效的段。 

## 方法

 直接的解决方案是尝试每一个可能的连续段。 对于每个左端点和右端点，我们计算线段总和并检查它是否等于`k * length`。 前缀和将检查一个段的成本降低到恒定时间，但仍然存在`O(n^2)`段。 和`n = 100000`，这大约变成了五十亿次操作，这远远超出了限制。 

关键的观察是我们实际上不需要使用排序属性。 重写条件：```
average = k

sum / length = k

sum - k * length = 0
```对于每一个魅力值`c[i]`，考虑变换后的值：```
b[i] = c[i] - k
```现在的问题是找到最长的连续段，其变换后的值之和为零。 

例如，如果值为：```
3 4 5
```和`k = 4`，变换后的数组为：```
-1 0 1
```整个段的总和为零，因此其平均值恰好为`4`。 

寻找最长的零和子数组是一个经典的前缀和问题。 如果两个前缀具有相同的变换总和，则它们之间的值加起来为零。 我们存储每个前缀和出现的最早位置，因为最早出现的位置给出了以当前位置结束的最长可能的段。 

暴力法之所以有效，是因为它直接检查定义，但由于段太多而失败。 前缀和观察将问题转化为扫描一次时查找重复状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 带有哈希映射的前缀和 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取数组并通过减法变换每个魅力值`k`。 这改变了寻找平均值的目标`k`寻找总和为零的线段。 
2. 遍历变换后的数组，同时维护运行的前缀和。 前缀和表示从开始到当前位置的总变换值。 
3. 存储每个前缀和出现的第一个索引。 第一次出现很重要，因为如果稍后再次出现相同的和，则两个位置之间的距离是在那里结束的最长可能的零和段。 
4. 每当当前前缀和之前出现过时，计算前一个位置和当前位置之间的段长度。 如果该段较长，请更新答案。 
5.输出找到的最长长度。 如果不存在重复的前缀和并且没有单个位置创建零前缀，则答案保持为零。 

为什么它有效：一个细分市场具有平均水平`k`恰好当`(c[i] - k)`该段上的值为零。 两个相等的前缀和之间存在零和段。 该算法检查每个前缀和一次并记录足够的信息以恢复匹配和之间的最长可能距离，因此考虑每个有效段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    c = list(map(int, input().split()))

    first = {0: -1}
    pref = 0
    ans = 0

    for i, x in enumerate(c):
        pref += x - k
        if pref in first:
            ans = max(ans, i - first[pref])
        else:
            first[pref] = i

    print(ans)

if __name__ == "__main__":
    solve()
```字典`first`存储每个前缀和的最早索引。 人工进入`{0: -1}`表示数组开始之前的空前缀。 这就是允许从索引开始的有效段`0`才能正确计数。 

运行总和使用`x - k`而不是原始的魅力值，避免任何除法或浮点精度问题。 所有计算均基于整数，因此不存在舍入误差。 

当第一次看到前缀和时，它的位置将被永久保存。 用稍后的位置替换它会缩短使用该总和的每个未来段，这可能会失去最佳答案。

 ## 边缘情况

 对于平均值看起来很接近但不准确的情况：```
5 4
3 5 5 5 5
```转换后的值为：```
-1 1 1 1 1
```前缀和为：```
0, -1, 0, 1, 2, 3
```重复前缀和`0`出现在第二个值之后，仅对前两个值给出零的段总和。 他们的变换后的总和是`0`，但原始值为`3, 5`，其平均值为`4`，所以正确的答案实际上是`2`。 

对于这个案例：```
5 4
3 5 5 5 6
```转换后的值为：```
-1 1 1 1 2
```重复的前缀和给出了该段`3,5`，算法返回`2`。 这说明了为什么精确的前缀相等而不是近似的平均值是正确的条件。 

对于全平等的情况：```
4 7
7 7 7 7
```每个变换后的值都为零。 索引处的初始前缀和`-1`为零，因此每个后面的索引都会创建一个更长的有效段。 答案来自于`1`到`4`，正确覆盖整个数组。 

对于从第一人称开始的片段：```
3 10
5 10 20
```转换后的值为：```
-5 0 10
```前缀和在索引处变为零`1`。 因为字典的索引处以前缀和零开头`-1`，算法计算段长度为`1 - (-1) = 2`？ 否，来自索引的段`0`到`1`已经改变了总和`-5 + 0 = -5`，所以这不可能发生。 实际的前缀和是：```
0, -5, -5, 5
```重复总和`-5`给出单个有效元素`10`，答案是`1`。 这可以捕获在处理数组之前的虚拟前缀时常见的差一错误。
