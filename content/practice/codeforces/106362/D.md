 ## 解决方案
 ## 问题理解

 系统中的每个商店都有三个参数：基线需求、需求对价格的敏感度以及单位生产成本。 如果我们设定一个售价$p$，单个商店的需求成为随着价格上涨而减少的线性函数。 一家商店的利润是通过销售多少单位乘以每单位利润得出的，即销售价格与成本之间的差额。 

对于单个商店，利润作为价格的函数形成二次表达式$p$。 关键的观察结果是，当我们将多个商店聚集在一个连续的部分时，它们的需求和成本就会简单地相加，因此一定范围内的总利润仍然是单个二次函数$p$，仅具有聚合系数。 

任务是回答多个查询，每个查询都要求尽可能最佳的统一价格$p$（带上盖$m$）最大化给定商店部分的总利润。 

输入大小意味着最多有大约$10^5$商店和查询。 这立即排除了每个查询从头开始重新计算答案的可能性，因为这会导致粗略的结果$10^{10}$最坏情况下的操作。 唯一可行的解​​决方案必须对数据进行预处理，以便可以在恒定或对数时间内回答每个查询。 

当计算出的最优价格超出允许范围时，就会出现一个微妙的问题。 例如，如果二次方表明价格大于$m$，那么使用该值将对应于不可行的市场条件。 当某个范围内的所有需求斜率都为零时，就会出现另一种边缘情况，这意味着价格不会影响需求； 在这种情况下，二次方程会退化，通常的顶点公式也会失效。 

## 方法

 如果我们固定一个查询范围$[l, r]$，我们可以直接模拟这个过程：尝试很多候选价格$p$，计算每个商店的需求，将利润相加，并取最大值。 这是正确的，因为每个价格的利润函数都是明确定义的。 然而，每次评估都需要迭代该范围内的所有商店，甚至对多个价格进行采样也会导致$O(n)$每次查询成本最低。 对于许多查询，这变得太慢。 

关键的结构见解是固定段上的利润函数始终是一个二次多项式$p$。 我们可以在每次查询时计算一次其系数，而不是重复评估该函数。 更好的是，由于系数只是一个范围内的总和，因此前缀和允许我们在恒定时间内检索它们。 

一旦知道了二次方程，最大化它就减少到找到它的顶点。 向下的抛物线在顶点处达到最大值，并且由于价格必须是整数且上限为$m$，我们只需要检查顶点和边界周围最接近的整数候选$m$。 

蛮力方法之所以有效，是因为每个价格的利润都是明确定义的，但会失败，因为它会重复重新计算相同的聚合信息。 聚合将所有内容减少到三个前缀可求数量的观察结果将问题转化为恒定时间查询评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | 前缀和+二次优化 |$O(n + q)$|$O(n)$| 已接受 |

 ## 算法演练

 我们重写一个段的利润表达式$[l, r]$化为标准二次形式$p$。 这是通过扩大每个商店的贡献和分组系数来完成的$p^2$,$p$和常数项。 

我们定义任意范围内的三个聚合值：

 1. 计算$A = \sum_{i=l}^{r} b_i$。 这是需求对价格的总敏感度。 
2. 计算$B = \sum_{i=l}^{r} (a_i + b_i c_i)$。 这收集了所有线性贡献$p$。 
3. 计算$C = \sum_{i=l}^{r} a_i c_i$。 这捕获了常数损失项。 

有了这些，总利润就变成了二次方：$$P(p) = -A p^2 + B p - C$$现在我们处理每个查询：

 1. 构建前缀和$a_i$,$b_i$,$a_i c_i$， 和$b_i c_i$。 

这允许计算$A$,$B$， 和$C$在任何范围内的恒定时间内。 
2. 查询$[l, r]$， 提炼$A$,$B$， 和$C$使用前缀差异。 

此步骤取代了对段的完整扫描。 
3.如果$A = 0$，二次函数塌陷为线性函数。 在这种情况下，增加价格不会引入凹性，因此最佳可行解决方案始终位于边界处$p = m$。 
4. 否则计算抛物线的顶点：$$p^* = \frac{B}{2A}$$这是实值最大化器。 
5. 由于价格必须是整数，因此评估利润为$\lfloor p^* \rfloor$和$\lceil p^* \rceil$，因为对于凹二次方程，整数上的最大值必须最接近顶点。 
6.同时评估$p = m$，因为顶点可能超出允许的范围。 
7. 返回这些候选者中的最大利润。 

### 为什么它有效

 在任何固定线段上，利润函数都是凹二次函数$p$每当$A > 0$。 凹二次方程有一个全局最大值，因此连续最优值位于其顶点。 限制为整数可将搜索减少到顶点周围两个最接近的整数。 由于可行域被另外截断为$m$，还必须检查边界。 前缀和保证为每个查询精确计算二次系数，从而保持所有段的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q, m = map(int, input().split())
    a = [0] * (n + 1)
    b = [0] * (n + 1)
    ac = [0] * (n + 1)
    bc = [0] * (n + 1)

    for i in range(1, n + 1):
        ai, bi, ci = map(int, input().split())
        a[i] = ai
        b[i] = bi
        ac[i] = ai * ci
        bc[i] = bi * ci

    pa = [0] * (n + 1)
    pb = [0] * (n + 1)
    pac = [0] * (n + 1)
    pbc = [0] * (n + 1)

    for i in range(1, n + 1):
        pa[i] = pa[i - 1] + a[i]
        pb[i] = pb[i - 1] + b[i]
        pac[i] = pac[i - 1] + ac[i]
        pbc[i] = pbc[i - 1] + bc[i]

    def get(l, r):
        A = pb[r] - pb[l - 1]
        B = (pa[r] - pa[l - 1]) + (pbc[r] - pbc[l - 1])
        C = pac[r] - pac[l - 1]
        return A, B, C

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        A, B, C = get(l, r)

        def profit(p):
            return -A * p * p + B * p - C

        if A == 0:
            out.append(str(profit(m)))
            continue

        p_star = B / (2 * A)
        candidates = set()

        for x in [int(p_star), int(p_star) + 1]:
            if 0 <= x <= m:
                candidates.add(x)
        candidates.add(m)

        best = -10**30
        for p in candidates:
            best = max(best, profit(p))

        out.append(str(best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现构建了四个前缀数组，因此每个查询都可以在恒定时间内提取聚合系数。 功能`get(l, r)`重建$A$,$B$， 和$C$与数学模型中的推导完全一样。 

这`profit(p)`函数直接计算二次表达式。 这避免了重新计算每个商店的贡献并确保数值稳定性，因为所有操作仍然基于整数。 

候选集包括顶点两侧和上界$m$。 将顶点转换为整数并检查地板和天花板可确保离散最大值不会丢失。 

特殊情况`A == 0`避免被零除并安全地处理退化线性情况。 

## 工作示例

 考虑一个包含三个商店和一个查询的小型实例：

 | 我| a_i | b_i | c_i |
 | --- | --- | --- | --- |
 | 1 | 4 | 1 | 2 |
 | 2 | 2 | 2 | 1 |
 | 3 | 3 | 1 | 3 |

 询问：$l = 1, r = 3, m = 10$我们计算前缀派生值：

 | 步骤| A = Σb | B = Σ(a + bc) | C = Σ(ac) |
 | --- | --- | --- | --- |
 | 1-3 | 1-3 1+2+1=4 | (4+2)+(2+2)+(3+3)=16 | 4·2+2·1+3·3=17 |

 现在的利润函数是：$P(p) = -4p^2 + 16p - 17$顶点是：$p^* = 16 / (2·4) = 2$我们评价：

 | p| 利润|
 | --- | --- |
 | 1 | -4 + 16 - 17 = -5 |
 | 2 | -16 + 32 - 17 = -1 |
 | 3 | -36 + 48 - 17 = -5 |
 | 10 | 10 -400 + 160 - 17 = -257 |

 最大值位于$p = 2$。 

该迹线表明顶点正确地识别了最佳价格，并且边界检查是必要的，因为大价格会迅速降低利润。 

第二种情况展示了边界优势：

 让$A = 0$,$B = 5$,$C = 3$， 和$m = 4$。 

利润变为线性：$P(p) = 5p - 3$。 

| p| 利润|
 | --- | --- |
 | 0 | -3 |
 | 4 | 17 | 17

 算法直接选择$p = m$，在约束下匹配正确的最大值。

 ## 边缘情况

 当所有$b_i = 0$在一段中，二次函数会分解为线性函数。 该算法通过以下方式检测到这一点$A = 0$并立即评估$p = m$。 例如，如果每个商店的需求与价格无关，则提高价格只会提高单位利润，因此边界是最优的。 

当计算的顶点超过$m$，凹抛物线将在可行域之外达到峰值。 候选集总是包括$m$，因此算法正确地将解限制在有效边界上。 

当顶点位于两个整数之间时，评估下限和上限可确保不会错过离散最大值。 例如，一个顶点位于$2.7$可能会使$p = 3$最优即使$p = 2$稍微差一点，两者都被显式检查。 

什么时候$n = 1$，前缀和正确地减少为单元素贡献，并且二次仍然可以正确计算，无需超出一般公式的任何特殊处理。
