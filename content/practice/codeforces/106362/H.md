 ## 解决方案
 ## 问题理解

 我们得到一个无向简单图。 每个顶点代表网络中的一个节点，每条边代表两个节点之间的相互连接。 任务是计算该图中存在多少个不同的三角形，其中三角形是三个顶点$(i, j, k)$这样所有三个边$(i, j), (j, k), (k, i)$存在。 

输入通过其顶点和边的数量以及后面的边列表来描述图。 每条边都是无序的，这意味着它不强加方向。 输出是一个表示三角形总数的整数。 

关键的约束含义是图可以足够大，以至于顶点数量中的任何三次方都立即无法使用，甚至在密集情况下二次邻接检查也太慢。 重复扫描没有结构的邻居列表的解决方案存在多次重新访问相同关系的风险。 

当使用朴素邻居交集而不进行重复数据删除时，会出现微妙的失败情况。 例如，如果我们尝试通过迭代节点的每对邻居并检查邻接性来对三角形进行计数，则根据遍历顺序，可以对同一个三角形进行多次计数。 

像 4 个顶点的完整图这样的输入已经暴露了这个问题。 有 4 个三角形，但除非仔细标准化，否则邻接上的简单三重循环可以轻松地将每个三角形计数 6 次。 

另一种边缘情况是倾斜度分布，例如星图加上叶子之间的一些额外边缘。 天真的“检查所有邻居对”方法会严重退化，因为中心节点强制进行大量的成对迭代。 

## 方法

 蛮力的想法很简单：枚举所有顶点三元组$i, j, k$，并检查所有三个边是否都存在。 这是正确的，因为每个三角形都是由其三个顶点唯一确定的。 然而，这需要$O(n^3)$检查，并且每次检查都可能涉及邻接查找，这使得即使对于中等大小的图也是完全不可行的。 

一个稍微好一点的想法是修复一个顶点$i$，然后迭代所有邻居$j$，然后遍历所有邻居$k$的$j$，检查是否$k$连接回$i$。 这将搜索空间减少到长度为二的游走。 虽然这避免了扫描不相关的顶点，但它仍然会大量重复工作，特别是当存在高度顶点时。 在最坏的情况下，这会变成$O(nm)$，这仍然太慢。 

关键的改进是对边施加一个方向，以便每个无向边变成从较低“等级”顶点到较高“等级”顶点的有向边。 自然的排名就是学位。 我们将每条边从较低度数端点引导到较高度数端点，通过索引任意打破关系。 

这种方向保证每个节点只有有限数量的传出边。 如果一个节点有太多的传出边，它将与更高程度的端点必须吸收这些边的事实相矛盾，从而导致无法全局持续的不平衡。 更具体地说，这确保了前向邻居的数量约为$O(\sqrt{m})$。 

一旦边被定向，每个三角形在该排序下都有一个唯一的“最小”顶点，并且我们仅使用传出边枚举从该顶点开始的三角形。 这可以防止重复计数并显着减少冗余探索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了|
 | 邻居的邻居扫描 |$O(nm)$|$O(n+m)$| 太慢了|
 | 面向度数的三角形计数 |$O(m\sqrt{m})$|$O(n+m)$| 已接受 |

 ## 算法演练

 我们根据度数构建顶点的排序，然后将每条边从较小的度数定向到较大的度数（通过顶点索引打破关系）。 之后，我们只遍历“前向边缘”。 

1. 计算每个顶点的度数。 这可以衡量每个节点在连接方面的“重度”。 
2. 使用规则隐式排序或比较顶点：vertex$u$小于$v$如果$deg(u) < deg(v)$，或者如果度数相等并且$u < v$。 这定义了避免歧义的一致排序。 
3. 建立一个邻接表，但只保留来自的有向边$u$到$v$如果$u < v$在此命令下。 此步骤将每个无向边减少为恰好一个有向边。 
4. 对于每个顶点$u$，迭代所有前向邻居$v$。 对于每一个这样的$v$，迭代所有前向邻居$w$的$v$，并检查是否$w$也是前向邻居$u$。 如果是这样，我们就找到了一个三角形$u \to v \to w$。 
5. 使用每个邻接列表的哈希集或布尔标记来测试成员资格$O(1)$平均时间。 

这样做的原因是每个三角形在度数排序下都有一个唯一的最小顶点。 该顶点将是唯一尝试通过其前边枚举三角形的顶点。 其他两个顶点无法重新枚举它，因为方向阻止向后遍历。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    edges = []
    adj = [[] for _ in range(n)]
    deg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        deg[u] += 1
        deg[v] += 1

    order = list(range(n))
    order.sort(key=lambda x: (deg[x], x))
    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    forward = [[] for _ in range(n)]

    for u, v in edges:
        if pos[u] < pos[v]:
            forward[u].append(v)
        else:
            forward[v].append(u)

    # build fast lookup
    mark = [0] * n
    timer = 1

    ans = 0

    for u in range(n):
        for v in forward[u]:
            mark[v] = timer

        for v in forward[u]:
            for w in forward[v]:
                if mark[w] == timer:
                    ans += 1

        for v in forward[u]:
            mark[v] = 0
        timer += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先计算度数，用于定义全局排序。 这`pos`array 将每个顶点转换为其等级，从而允许常量时间比较。 

这`forward`邻接表对有向图进行编码。 每个无向边在从较低等级到较高等级端点的方向上仅存储一次，这可以防止重复的三角形枚举。 

三角形计数使用标记数组而不是集合。 对于固定节点$u$，其所有前向邻居都被标记。 然后对于每个前向邻居$v$，我们扫描它的前向邻居$w$并测试是否$w$被标记。 这用数组索引取代了哈希查找，更快、更稳定。 

临时的`timer`避免清除每个节点的整个数组，这会太慢。

 ## 边缘情况

 完整的图是重复计算最敏感的情况。 如果没有方向，每个三角形都会根据遍历根多次遇到。 有向构造确保只有排名最小的顶点枚举每个三角形。 

叶子之间有附加边的星形图也会误导天真的邻居对计数，认为存在多个三角形。 实际上，仍然不存在长度为三的闭环，除非有第三条边完成它。 标记方法确保只计算完全连接的三元组，因为如果没有最终的边缘检查，仅两跳可达性是不够的。 

具有孤立节点的稀疏图不会造成任何问题，因为它们的前向列表是空的并且它们从不参与三角形枚举。
