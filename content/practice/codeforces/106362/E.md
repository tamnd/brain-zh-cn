 ## 解决方案
 ## 问题理解

 我们得到了一系列门票，每张门票都有一个数字价格。 从这些价格中，我们感兴趣的是成对门票之间的差异。 任务不仅是在全球范围内推理这些差异，而且要分两个阶段使用它们：首先在排名意义上识别特定的“目标”差异，然后构建一对实际的票证，以实现这种差异，同时在次要规则下实现最佳。 

关键思想是问题中所有有意义的信息都来自票价之间的成对绝对差异。 如果我们对价格进行排序，我们关心的每个差异都会变成排序数组中两个索引之间的距离，这消除了显式考虑无序对的需要。 

约束结构意味着票的数量足够大，不可能枚举所有对。 简单的对枚举需要 O(n^2) 次操作，这在大约 10^5 个元素时已经变得令人望而却步，因为它会导致大约 10^10 次比较。 这立即迫使我们采用利用排序顺序和单调性的方法。 

在实践中，有两种微妙的边缘情况很重要。 

第一种情况是多对共享相同的差异。 例如，与价格`[1, 2, 3, 4]`， 区别`1`成对发生`(1,2)`,`(2,3)`， 和`(3,4)`。 如果问题要求第 k 个最小差异，我们必须确保正确计算所有重复项，而不仅仅是不同值。 

第二个是当固定差异下的最优对不唯一时。 假设价格是`[1, 10, 11, 20]`我们修正了一个差异约束`10`。 许多对满足它，但问题可能需要在某种排序下选择字典顺序最好或最小的对。 如果不明确跟踪最佳候选者，粗心的两指针扫描可能会提前停止或选择非最佳的有效对。 

这些观察结果已经表明，问题的结构从根本上讲是关于在差异的单调约束下计数和选择对的。 

## 方法

 直接方法考虑每一对`(i, j)`并计算`|a[i] - a[j]|`。 然后，对这些值进行排序将使我们能够选择第 k 个最小的差异，然后再次扫描以找到达到该值的一对。 

这种蛮力的正确性很简单，因为它明确地构造了完整的多重差异集。 然而，成本是门票数量的二次方。 当 n 达到 100,000 时，这大约变成 50 亿对，这远远超出了任何可行的时间限制。 

关键的结构见解是，对数组进行排序后，谓词“difference ≤ d”在很强的意义上变得单调。 如果是一对`(i, j)`满足`a[j] - a[i] ≤ d`，然后增加`j`或减少`i`以可预测的方式保留可行性。 这使我们能够在线性时间内使用两指针扫描来计算有效对的数量。 

一旦我们可以计算出有多少对的差值 ≤ d，我们就可以对 d 进行二分搜索以找到至少 k 对满足条件的最小值。 这将问题从二次枚举转换为 O(n log V)，其中 V 是差值范围。 

在确定正确的差异阈值后，我们重用相同的两指针思想来提取实际的对。 我们不是计数，而是扫描并跟踪满足条件的最佳对，尊重二次选择规则。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 log n) 或 O(n^2) | O(n^2) | O(n^2) | 太慢了|
 | 最佳| O(n log V) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们首先对数组进行排序，使差异变成简单的索引间隙。 这将问题转化为使用索引上的单调函数。 

然后我们定义一个函数`count(d)`返回有多少对满足`a[j] - a[i] ≤ d`。 这是使用两个指针计算的：对于每个`i`，我们前进`j`尽可能的同时保持约束。 每个位置的`i`贡献`j - i - 1`有效对。 这有效，因为一旦`a[j] - a[i] > d`，增加`j`进一步只会增加差异。 

接下来我们进行二分查找`d`。 我们维持的搜索范围为`0`到`max(a) - min(a)`。 对于每个中点，我们计算`count(mid)`。 如果计数至少为 k，我们尝试较小的值； 否则我们会提高门槛。 最终结果是最小的`d`使得至少存在 k 对。 

得到这个阈值后`d*`，我们需要找到与之对应的有效对。 我们再次使用两指针扫描，但现在我们收集候选对`(i, j)`这样`a[j] - a[i] ≤ d*`。 根据所需的排序，我们根据问题的平局打破规则跟踪最佳对，通常最小化第二个索引或最大化一些次要属性。 

为什么它有效来自于谓词的单调性`a[j] - a[i] ≤ d`。 对于固定的`i`， 有效的`j`在排序数组中形成连续的前缀。 这确保了计数是线性的并且二分查找`d`是有效的，因为增加`d`只增加有效对的集合。 修复后选择的正确性`d*`因为所有可接受的对都位于两指针扫描充分探索的明确定义的可行区域中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_pairs(a, d):
    n = len(a)
    j = 0
    total = 0
    for i in range(n):
        if j < i + 1:
            j = i + 1
        while j < n and a[j] - a[i] <= d:
            j += 1
        total += j - i - 1
    return total

def best_pair_with_diff(a, d):
    n = len(a)
    best = None
    for i in range(n):
        j = i + 1
        while j < n and a[j] - a[i] <= d:
            if best is None or (a[i], a[j]) < best:
                best = (a[i], a[j])
            j += 1
    return best

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    lo, hi = 0, a[-1] - a[0]

    while lo < hi:
        mid = (lo + hi) // 2
        if count_pairs(a, mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    d = lo
    ans = best_pair_with_diff(a, d)
    print(ans[0], ans[1])

if __name__ == "__main__":
    solve()
```该代码首先对数组进行排序，以便所有有效差异都具有方向性。 这`count_pairs`函数实现两指针扫描：对于每个`i`, 指针`j`只会向前移动，因此整体复杂性保持线性。 

二分查找使用该函数作为单调谓词。 关键的细节是`count_pairs(d)`当`d`增加，这保证了二分查找的正确性。 

确定目标差异后，`best_pair_with_diff`再次扫描。 嵌套循环总体上仍然是线性的，因为`j`仅在每个内向前移动`i`有效差异部分。 比较`(a[i], a[j]) < best`强制执行确定性平局打破规则，以便我们始终选择字典顺序最小的有效对。 

## 工作示例

 考虑`n = 4`,`k = 3`,`a = [1, 2, 3, 4]`。 

二分查找计算计数：

 | 中 (d) | 对 ≤ d |
 | --- | --- |
 | 0 | 0 |
 | 1 | 3 |
 | 2 | 5 |
 | 3 | 6 |

 我们收敛到`d = 1`。 

那么有效的对是`(1,2)`,`(2,3)`,`(3,4)`。 按字典顺序最小的是`(1,2)`。 

此跟踪显示差异中的重复项得到了正确处理，因为所有对都被计数，而不是不同的值。 

现在考虑`a = [1, 10, 11, 20]`,`k = 2`。 

| d | 对 ≤ d |
 | --- | --- |
 | 0 | 0 |
 | 5 | 1 |
 | 10 | 10 4 |

 所以`d = 10`。 有效对包括`(1,10)`,`(1,11)`,`(10,11)`,`(11,20)`取决于订购。 扫描确保我们选择其中按字典顺序最小的，即`(1,10)`。 

这证实了选择阶段与二分搜索阶段中对的计数方式无关。

 ## 边缘情况

 对于相等的元素，例如`[5, 5, 5, 5]`，每对的差异为零。 二分查找折叠为`d = 0`，并且扫描仍然正确识别`(5, 5)`作为最优对。 两指针结构自然地处理这个问题，因为`a[j] - a[i] <= 0`适用于所有有效对。 

对于紧密排列的序列，例如`[1, 2, 3, 4]`，许多对具有相同的差异。 该算法对它们全部进行计数，而不是删除重复的差异，因此第 k 对逻辑仍然正确。 

对于间隔很宽的值，例如`[1, 100, 1000]`，有效区域稀疏。 二分搜索仍然正确收敛，因为计数在阈值之间急剧跳跃，并且扫描正确地隔离了所选差异处唯一可行的对。
