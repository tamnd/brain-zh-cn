 ## 解决方案
 ## 问题理解

 我们得到一个数组，我们可以在处理之前对其重新排序。 修复后，我们从左到右扫描它并维护两个运行值：迄今为止看到的最小元素和迄今为止看到的最大元素。 在每个位置，我们记录这两个极端之间的差异，最终得分是所有这些每个位置差值的总和。 

我们拥有的自由完全在于数组的排列。 之后，前缀最小值和前缀最大值确定性地演化。 

约束足够小，以至于$O(n^2)$甚至$O(n \log n)$每个测试用例的方法都会顺利通过，因为总的$n$所有测试的总和最多为 1000。这表明我们应该关注结构推理而不是优化技巧。 

这里的一个常见错误是假设贪婪地把大数放在前面或最后总是有效的。 这会失败，因为前缀最小值和前缀最大值是全局交互的，而不是本地交互的。 例如，过早放置最大元素会立即修复许多前缀的最大值，从而减少未来的贡献，即使这看起来对局部有利。 

另一个陷阱是尝试独立优化前缀贡献。 孤立地看起来最优的前缀可能会破坏最大最小间隙的未来增量，因此必须将安排作为一个整体来考虑。 

## 方法

 暴力解决方案将尝试所有排列并计算每个排列的分数。 从概念上讲，这是可行的，因为评分函数定义明确，但它是复杂性的阶乘，并且不可能超出非常小的范围$n$。 

关键的观察结果是，分数仅取决于极端情况如何演变，而不取决于中间元素的确切顺序。 我们希望尽可能长时间地保持最大值尽可能“高”，同时尽可能延迟最小值的增加。 这建议尽早放置小元素以维持较低的前缀最小值，稍后放置大元素以逐渐增加前缀最大值。 

最佳地实现此目的的结构是一个简单的贪婪排列：我们交替将当前最小和最大剩余值推入序列中。 这会最大化 max 和 min 之间差距较大的前缀数量。 

直觉是，每次扩展序列时，我们都希望引入一个新的全局最大值或保留一个小的最小值，并且交替的极端确保两种力量都得到最大程度的利用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n!)$|$O(n)$| 太慢了 |
 | 贪婪的极端|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先对数组进行排序。 排序使我们能够控制对最小和最大元素的访问。 

然后我们使用两个指针构造排列，一个位于排序数组的开头，一个位于排序数组的末尾。 

在每一步中，我们附加最小的剩余元素或最大的剩余元素。 选择交替进行。 

我们隐式地模拟前缀评估：我们不是重新计算前缀最小值和最大值，而是依赖于这样一个事实：放置极值可以最大化未来的价差贡献。 

最后，我们通过扫描构造的数组并维护前缀最小值和最大值来计算分数。 

### 为什么它有效

 每个位置的分数仅取决于运行最小值和最大值之间的距离。 在许多前缀中保持这种差异较大的唯一方法是延迟任一极端的稳定。 在最小和最大剩余值之间交替确保两个极端都不会过早“卡住”，从而最大化所有前缀的累积差异。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        l, r = 0, n - 1
        arr = []
        take_max = True
        
        while l <= r:
            if take_max:
                arr.append(a[r])
                r -= 1
            else:
                arr.append(a[l])
                l += 1
            take_max = not take_max
        
        mn = arr[0]
        mx = arr[0]
        ans = 0
        
        for x in arr:
            mn = min(mn, x)
            mx = max(mx, x)
            ans += mx - mn
        
        print(ans)

if __name__ == "__main__":
    solve()
```排序后，我们通过交替取最大和最小剩余值来构建排列。 这确保极值以平衡的方式分布在前缀结构中。 最后的循环只是根据定义使用前缀最小值和最大值计算分数。 

一个微妙的点是初始化：第一个元素设置最小值和最大值，因此第一个贡献始终为零。 此外，交替方向必须以一致的方式开始； 只要在整个结构中保持一致，从任一侧开始都可以。

 ## 边缘情况

 均匀数组是最简单的边界情况。 由于前缀最小值和最大值始终相等，因此无论排列如何，每一项都贡献零，因此任何算法都必须返回零。 

二元素数组直接暴露了核心机制：分数正是绝对差，任何排序都会产生相同的前缀结构。 

严格递增或递减的数组很有用，因为它迫使构造揭示贪婪交替实际上是有益的还是多余的。 在这些情况下，交替策略仍然通过确保尽早引入最大值而延迟引入最小值来保留前缀之间的最大扩展。
