 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，其中每个字符都是一个固定的布尔值。 玩家不会改变这些值。 他们唯一的行动是决定在相邻位置之间放置二元运算符的位置，特别是为每个间隙选择 AND 或 OR。 由于有 n 个角色，因此有 n−1 个间隙，并且每个间隙在游戏过程中只被填充一次，Alice 和 Bob 交替选择。 

放置所有运算符后，将使用固定的归约规则计算生成的布尔表达式：AND 运算在 OR 运算之前以任意顺序解析，但最终值是明确定义的，无论归约顺序如何。 

Alice 希望最终结果为 true，Bob 希望最终结果为 false，并且两者都发挥最佳效果。 

关键的困难在于，玩家不是直接评估表达，而是塑造表达。 每次移动都会改变最终表达式的结构而不是其直接值。 

约束允许跨测试用例的字符总数最多为 2⋅10^5，因此每个测试用例的任何解决方案都必须本质上是线性的。 任何试图模拟所有游戏、所有操作员放置或所有减少的事情都远远超出了可行的限制。 在最坏的情况下，即使每个测试用例的 O(n^2) 推理也已经太慢了。 

一种简单的方法是模拟所有可能的运算符分配或在所有状态上运行极小极大。 这立即爆炸了，因为每个 n−1 间隙都有两种选择，给出 2^(n−1) 个配置。 

还有一个微妙的陷阱：因为在归约过程中 AND 是在 OR 之前评估的，所以分组效果比局部直觉暗示的更重要。 例如，像 101111 这样的字符串的行为可能会非常不同，具体取决于 AND 如何隔离零。 

一个常见的错误假设是只有零或一的数量才重要。 例如，认为“如果至少有一个零，鲍勃可以强制为假”是错误的，因为“或”可以将零与最终评估隔离开。 

## 方法

 暴力策略将枚举所有可能的方法来将 AND/OR 分配给 n−1 个间隙，评估每个结果表达式，然后通过检查 Alice 是否有任何获胜分配来假设最佳游戏。 即使我们忽略最佳游戏结构并只尝试所有分配，我们也已经面临指数增长：每个测试用例有 2^(n−1) 种可能性，并且每次评估成本为 O(n)，从而导致不可行的 O(n·2^n) 总行为。 

核心简化来自于理解 AND 和 OR 在最佳游戏下所施加的结构。 AND 是“破坏性的”，因为它迫使双方都为生存而真实，而 OR 是“宽容的”，因为单一真实的一方就足够了。 由于 AND 在 OR 之前进行评估，因此 AND 倾向于隔离段，从而有效地将字符串拆分为多个组件，其结果由 OR 组合。 

这就产生了一种战略张力：尽早放置 AND 可以通过防止零被吸收到更大的 OR 链中来“保护”零，而 OR 则倾向于传播 1 的影响。 

关键的见解是，游戏简化为控制是否可以将零隔离为强制损失，或者是否可以保护零并将其合并到最终幸存的真实部分中。 在最佳播放中，只有字符串的一个非常小的结构特征很重要：在关键位置至少存在一对连续的相等位，以及除了可以“包含”的孤立零之外，字符串是否以 1 为主。

这导致了一种贪婪的表征：结果取决于 Alice 是否能够迫使至少一个连续片段在 OR-AND 还原中幸存下来，而 Bob 则试图通过策略性地插入 AND 来破坏所有这些幸存的片段。 完整的推导归结为检查本地模式，特别是是否存在一个地方，在鲍勃可以隔离它们周围的零之前，爱丽丝可以强制合并两个1。 

简化最佳游戏交互后，决策简化为线性扫描，检查字符串是否避免了某些允许 Bob 强制获得零结果的阻塞配置。

 ## 算法演练

 关键是要检测 Alice 是否可以通过 AND 布局创建一个保证存活的真实组件，尽管 Bob 有干扰。 

我们扫描字符串并对局部结构进行推理。 

1. 观察到，如果字符串全部为 1，则 Alice 获胜。 每个操作都保留真实性，因为无论放置如何，所有操作上的 AND/OR 的任何组合都保持真实。 
2. 如果字符串包含零，Bob 的目标是使用 AND 运算将它们隔离，以便将表达式折叠为 false。 然而，“或”布局可以通过将“1”连接到“0”来抵消这种情况。 
3. 当零是“内部”时，即两边都有零时，就会出现严重情况。 在这种情况下，Bob 通常可以强制进行分裂，以防止 Alice 合并足够多的分裂来控制表达式。 
4. 决定性的结构是是否存在至少一对相邻的，或者它们是否形成一个不能通过交替移动完全打破的线段。 如果这种稳定的邻接以爱丽丝可以首先利用的方式存在，那么她就赢了。 
5. 具体来说，已知的约简导致了一个简单的规则：Alice 获胜，除非该字符串被 Bob “完全可分离”进入强制错误评估，当 1 过于孤立且每个关键区域中都可以使用零作为分隔符时，就会发生这种情况。 

在实现方面，这简化了检查字符串是否包含至少一对连续的相等字符，这些字符没有被对称阻塞模式中的周围零完全中和。 实际上，这简化为线性扫描，检测 Alice 是否具有强制“合并机会”。 

### 为什么它有效

 游戏动态可以解释为在字符串上构建二叉树，其中 AND 节点约束子树，OR 节点将它们组合起来。 Bob 的最佳玩法总是尝试在边界处插入 AND，以减少幸存真实组件的数量，而 Alice 则尝试通过 OR 连接来保留至少一个连续的链。 

不变量是每次移动后的“活真实成分”的数量只能通过原始字符串中的邻接结构来控制，并且除了连续段之外不存在远程交互。 这将游戏状态空间折叠为局部模式，使得贪婪扫描就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        # If all ones, Alice wins immediately
        if '0' not in s:
            print("YES")
            continue

        # If all zeros, Alice loses
        if '1' not in s:
            print("NO")
            continue

        # Check for a pair of consecutive equal characters (key structural feature)
        ok = False
        for i in range(n - 1):
            if s[i] == s[i + 1]:
                ok = True
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先消除了无关紧要的情况，即无论游戏如何，结果都是固定的：全 1 或全 0。 仅当两个符号都存在时才会出现有趣的行为。 

最后一次扫描检查是否存在至少一对相邻的相等对。 这是结构性“锚”，允许爱丽丝在最佳游戏下保留或创建占主导地位的真实片段。 如果不存在这样的对，则字符串会交替，Bob 可以通过强制破坏性放置来完全控制评估，以防止任何稳定的 OR 传播。

 ## 边缘情况

 像 010101010 这样的完全交替的字符串会造成一种情况，即任何邻接都不会增强稳定区域。 在这种情况下，算法找不到相等的对并正确返回“否”，这与鲍勃阻止爱丽丝形成幸存真实片段的能力相匹配。 

完全统一的一串让 Alice 立即获胜，因为根据评估规则，没有任何操作符放置可以将所有 1 减少为 false。 扫描会尽早检测到这一点并返回“是”，而无需进一步推理。 

具有由零包围的单个 1 块的字符串（例如 0011100）在该块内包含相邻的相等 1。 该算法识别出这一点并返回“是”，反映了爱丽丝有能力保留该块以防止鲍勃试图隔离它。
