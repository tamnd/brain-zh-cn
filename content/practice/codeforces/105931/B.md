 ## 解决方案
 ## 问题理解

 我们给出了长度的排列$n$，意思是数字的排列$1$到$n$无需重复。 对于任何职位$i$，该位置的贡献是该位置的值与指数本身之间的距离（以绝对值表示）。 将所有位置的总和得出排列的总“位移成本”。 

任务是判断是否存在总位移恰好为的排列$k$，如果是，则构造任意一种这样的排列。 

问题的结构不是检查排列，而是控制通过重新排列元素可以引起多少总索引偏移。 

约束条件$n \le 2 \cdot 10^5$排除任何排列的枚举或搜索。 价值$k \le 10^{12}$远大于$n$，所以关键的困难是理解可实现的总和的范围，而不是盲目地构建组合。 

一些边缘情况很容易被误解。 如果$n = 1$，唯一的排列是$[1]$，且成本始终为零。 所以任何$k > 0$是不可能的。 

另一个微妙的情况出现时$k$很大。 虽然$k$可以达到$10^{12}$，尺寸排列的最大可能位移$n$由二次函数界定$n$，所以对于大的$k$相对于$n$，答案一定是“否”。 

第三个陷阱是假设贪婪的本地互换总是可以创造任何价值。 小例子，例如$n=4$表明并非所有中间金额都是可以实现的，并且构建必须尊重交换如何影响总位移的非常严格的结构。 

## 方法

 暴力方法会尝试每个排列，计算其位移，并检查是否有匹配$k$。 这是正确的，但不可行，因为有$n!$排列。 即使是为了$n = 10$，这变得完全棘手。 

需要更结构化的观察：当元素放置得离其原始位置尽可能远时，位移最大化。 增加总和的最自然方法是交换对称对中的元素，将值推离其同一位置。 

关键的见解是，可以通过从左到右处理位置并决定是保持元素固定还是将其与后面的位置交换来增量构建排列。 两个头寸之间的互换对总成本的贡献是可预测的，并且在仔细安排时可以单独处理这些贡献。 

特别是互换位置$i$和$j$贡献$2 \cdot (j - i)$至总位移。 这意味着我们可以考虑使用不相交的段交换来构建答案，每个交换贡献一个可控的偶数。 

这将问题简化为分解$k$转化为这些分段贡献的总和，可以从最大可能的分段向下贪婪地构建。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n!)$|$O(n)$| 太慢了|
 | 段交换建设 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 首先计算最大可能位移。 这是通过反转排列来实现的，总成本变为$\sum_{i=1}^{n} |(n-i+1) - i|$。 如果$k$大于该值，则无法进行施工。 这项检查可以防止将精力花在不可能的目标上。 
2.如果$k = 0$，恒等排列已经满足条件，因为每个元素都与其索引匹配并且贡献为零。 
3. 将排列初始化为恒等数组$[1, 2, \dots, n]$。 我们会分段修改。 
4. 从最左边的索引开始迭代$i = 1$到$n$，并在每个位置决定是否与某个位置应用掉期$j > i$。 的选择$j$是由我们仍然可以使用但不超过的最大剩余贡献驱动的$k$。 
5. 对于一个职位$i$，尽量使用尽可能远的伙伴$j = n - (i - 1)$，从两端向内形成对称交换。 之间的交换$i$和$j$贡献$2 \cdot (j - i)$至总位移。 
6. 如果本次出资小于或等于剩余出资$k$，执行交换并从中减去该值$k$。 否则，跳过该位置并向前移动而不交换。 
7. 继续，直到处理完所有位置或剩余位置$k$变为零。 如果在最后$k$不为零，构建失败。 

### 为什么它有效

 该算法之所以有效，是因为我们执行的每次交换都对应于一个不相交的段，该段对总位移的贡献独立于其他交换。 每次我们选择交换时，我们都会从进一步考虑中删除一个连续的范围，以防止重叠。 对最大有效交换的贪婪选择确保我们永远不会浪费以后可能需要的潜在大量贡献。 由于所有贡献都是均匀的并且围绕对称距离构建，因此任何可实现的总数必须可表示为这些不相交的段贡献的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    # maximum possible displacement
    max_k = 0
    for i in range(1, n + 1):
        max_k += abs(n - i + 1 - i)

    if k > max_k:
        print("No")
        return

    if k == 0:
        print("Yes")
        print(*range(1, n + 1))
        return

    p = list(range(1, n + 1))

    l, r = 0, n - 1

    while l < r:
        cost = 2 * (r - l)
        if cost <= k:
            p[l], p[r] = p[r], p[l]
            k -= cost
        l += 1
        r -= 1

    if k != 0:
        print("No")
    else:
        print("Yes")
        print(*p)

if __name__ == "__main__":
    solve()
```该解决方案首先计算可实现位移的上限，该上限对应于反向排列。 这确保我们永远不会尝试建造不可能的目标。 

构建阶段使用两个向内移动的指针。 每个对称交换都被评估为一个单一决策：要么我们使用该交换的全部贡献，要么跳过它。 的减法$2 \cdot (r - l)$反映了交换对称位置引起的绝对差值的确切变化。 

正确性取决于这样一个事实：每次交换后，剩余的结构仍然是对称的并且独立于之前的选择。

 ## 边缘情况

 对于$n = 1$，算法立即将最大位移计算为零。 如果$k = 0$，它输出$[1]$。 如果$k > 0$，它拒绝。 永远不会进入循环，这避免了任何无效的指针逻辑。 

对于最大$k$，交换循环始终接受每个对称交换。 排列变得完全相反，并且累积成本与预先计算的界限完全匹配，确认贪婪接受所有可用的贡献。 

对于小$k$如果小于最小交换贡献，则算法会跳过所有交换。 由此产生的排列仍然是恒等的，并且因为$k$不能进一步减少，它正确地得出不可能的结论，除非$k = 0$。
