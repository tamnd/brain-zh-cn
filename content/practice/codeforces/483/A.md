 ## 解决方案
 ## 问题理解

 我们被要求在给定区间内构造三个整数，使它们形成非常特定的互质关系模式。 我们需要三个不同的数字$a < b < c$，都位于$l$和$r$，其中相邻对$(a,b)$和$(b,c)$除了 1 之外没有其他共同因数，但最外层的对$(a,c)$共享一个大于 1 的除数。 

更具体地说，我们正在寻找互质性的“破坏传递性”示例：中间的数字与两端互质，但两端互质。 任务是要么构造这样的三元组，要么确定区间中不存在这样的三元组。 

约束条件$r - l \le 50$是关键的结构提示。 虽然$r$本身可以大到$10^{18}$，间隔极小。 这意味着任何检查范围内的所有值或从中构建候选值的方法都是可行的。 对区间内所有三元组进行暴力扫描最多是$\binom{51}{3}$，很小。 

主要的微妙边缘情况是当间隔太小而无法包含三个不同的数字时。 如果$r - l < 2$，那么可用的整数少于三个，答案立即不可能。 当间隔在因子结构方面稀疏时，会出现另一种边缘情况，但由于连续整数通常已经提供了有用的互质模式，因此失败很少且结构化。 

一个天真的错误是假设随机三元组总是存在或尝试固定模式，例如$(x, x+1, x+2)$无需验证整除条件。 当间隔很小时或者局部算术结构不能在端点之间产生共享除数时，这种方法就会失败。 

## 方法

 暴力解决方案将迭代所有三元组$a < b < c$里面$[l,r]$，检查是否$\gcd(a,b)=1$,$\gcd(b,c)=1$， 和$\gcd(a,c)\neq 1$。 因为间隔大小最多为 51，所以这最多涉及约 22,000 个三元组，并且每次检查都使用一个$O(\log r)$gcd computation. 这已经足够快了，但它隐藏了问题的更深层次结构。 

关键的观察是我们不需要任意搜索。 一个简单的构造模式几乎总是有效：连续整数$x, x+1, x+2$。 我们知道连续的数是互质的，所以$\gcd(x,x+1)=1$和$\gcd(x+1,x+2)=1$。 我们必须执行的唯一条件是$\gcd(x,x+2) \ne 1$。 当两端共享一个公共因子时就会发生这种情况，保证这一点的最简单方法就是选择$x$作为偶数，这样$x$和$x+2$都可以被 2 整除。 

因此，问题简化为找到任何偶数$x$这样$x, x+1, x+2$都在区间里。 如果不存在这样的三元组，那么我们就会退回到暴力破解或得出不可能的结论。 

蛮力方法之所以有效，是因为域很小。 建设性方法之所以有效，是因为它利用奇偶性来强制共享除数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3 \log r)$,$n \le 51$|$O(1)$| 已接受 |
 | 建设性（基于奇偶校验）|$O(r-l)$|$O(1)$| 已接受 |

 ## 算法演练

 我们首先转换区间$[l,r]$到一个小的显式整数列表中。 由于范围大小最多为 51，因此安全且快速。 

1. 构建数组$vals = [l, l+1, \dots, r]$。 这使我们能够直接访问所有候选者，而无需重复的算术推理。 
2. 如果这个列表的长度小于3，则立即返回-1。 没有足够的不同数字来形成三元组。 
3. 迭代所有索引对$i < j < k$。 对于每个三元组$(vals[i], vals[j], vals[k])$，计算：

 -$\gcd(vals[i], vals[j])$-$\gcd(vals[j], vals[k])$-$\gcd(vals[i], vals[k])$我们正在寻找前两个 gcd 为 1、最后一个大于 1 的模式。 
4. 一旦找到这样的三元组，就按升序返回它。 

这种逐步搜索可接受的原因是候选数量极少，因此我们有效地对区间进行完整的结构检查，而不是依赖于更深层次的数论捷径。 

### 为什么它有效

 每个有效的解决方案都必须来自给定的区间内，并且每个三元组都经过明确测试所需的互质条件。 由于我们按排序顺序枚举了所有可能的三元组，因此我们不会错过有效的配置。 如果不存在，则通过穷举，在区间内无法形成有效的反例。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from math import gcd

l, r = map(int, input().split())

vals = list(range(l, r + 1))

n = len(vals)
if n < 3:
    print(-1)
    sys.exit(0)

for i in range(n):
    for j in range(i + 1, n):
        for k in range(j + 1, n):
            a, b, c = vals[i], vals[j], vals[k]
            if gcd(a, b) == 1 and gcd(b, c) == 1 and gcd(a, c) != 1:
                print(a, b, c)
                sys.exit(0)

print(-1)
```该解决方案直接枚举范围内所有可能的三元组并检查所需的三个 gcd 条件。 使用`sys.exit(0)`确保一旦找到有效的反例我们立即停止，避免不必要的计算。 

唯一微妙的一点是我们依赖于Python的内置`gcd`，对于这个约束来说已经足够快了，因为它最多会在几千对上被调用。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    l, r = map(int, input().split())
    vals = list(range(l, r + 1))

    if len(vals) < 3:
        return "-1"

    n = len(vals)
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                a, b, c = vals[i], vals[j], vals[k]
                if gcd(a, b) == 1 and gcd(b, c) == 1 and gcd(a, c) != 1:
                    return f"{a} {b} {c}"

    return "-1"

# provided samples
assert run("2 4\n") == "2 3 4", "sample 1"
assert run("1 2\n") == "-1", "sample 2"

# custom cases
assert run("3 5\n") == "-1", "no valid triple in small odd range"
assert run("10 14\n") == "10 11 12" or run("10 11 12\n") == "10 11 12", "consecutive construction exists"
assert run("6 8\n") == "6 7 8", "simple valid consecutive case"
assert run("7 9\n") == "-1", "insufficient parity structure"

 ## 边缘情况

 对于间隔`[1,2]`，算法立即返回 -1，因为数字少于三个。 这证实了对简并输入大小的正确处理。 

对于像这样的间隔`[6,8]`，枚举检查单个三元组`(6,7,8)`。 gcd 值为`gcd(6,7)=1`,`gcd(7,8)=1`， 和`gcd(6,8)=2`，因此它完全按照要求成功。 由于范围很小，暴力循环会在恒定的时间内达到这一点。 

对于数字全部成对互质或端点之间缺少共享除数的区间，该算法会耗尽所有三元组并正确得出不可能性的结论，因为每个候选都根据 gcd 约束进行显式验证。
