 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 排列成一行的数字的排列。 每个位置都代表一个具有独特力量值的“精神病”，并且这条线在离散的回合中演变。 

在一轮中，每个精神病患者都会将自己与紧邻他右边的人进行比较。 如果他的价值更大，他就会杀死正确的邻居。 所有比较同时发生，因此即使一个精神病患者在同一轮中被杀，他也可以杀死某人。 杀戮结束后，剩下的疯子们会紧密团结起来，组成新的队伍，准备进入下一轮。 这个过程不断重复，直到不可能再有杀戮为止。 

任务是确定系统稳定之前发生多少轮，这意味着没有位置的值大于其直接右邻居的值。 

输入大小高达 100,000 个元素，这会立即排除任何重复扫描和删除元素的模拟。 在最坏的情况下，每轮重建列表的简单方法将降级为 O(n²)，这远远超出了 Python 中一秒钟的时间复杂度。 

一个微妙的困难出现在同时删除如何与连锁反应相互作用。 即使一个值注定要在以后被删除，它也可能会在一轮中幸存下来，因为它的右邻居可能会在同一步骤中被杀死。 例如，在递减数组中`[5, 4, 3, 2, 1]`，除了最大值之外的所有内容都会在一轮中消失，而不是逐渐消失。 任何从左到右顺序删除的不正确的贪婪模拟都会低估崩溃的速度。 

另一种边缘情况是当局部增加存在于数组深处时。 例如`[1, 3, 2, 4, 3]`产生多轮，其中不同的部分以不同的速率收缩。 答案取决于某个值被左侧较大值保护之前的最长“延迟”。 

## 方法

 暴力解释很简单：模拟每一轮，扫描数组，标记所有位置`a[i] > a[i+1]`，删除正确的元素，压缩数组，然后重复，直到没有删除发生。 每轮的复杂度为 O(n)，在最坏的情况下，我们可能每轮仅删除一个元素，从而产生 O(n) 轮，因此总复杂度变为 O(n²)。 当 n 达到 100,000 时，这是不可行的。 

关键的观察是，每个元素只有在被杀死之前才相关，并且其生存仅取决于其左侧最近的较大元素。 一旦左侧出现更大的元素，当前元素就“注定”并最终将被删除，但时间取决于该主导元素的距离有多远。 

我们不是模拟回合，而是跟踪每个位置何时被移除。 我们从左到右处理并维持索引的单调结构，其中值正在递减。 对于每个元素，我们会发现它在被左侧更大的值消除之前存活了多少步。 这相当于跟踪类似于具有附加定时传播的单调堆栈的影响链。 

这个问题的经典结果是每个元素的“死亡时间”等于最接近其左链的较大元素的最大死亡时间一倍。 答案是所有元素的最大死亡时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n²) | O(n) | 太慢了 |
 | 带有传播的单调堆栈 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，维护一个索引堆栈，其中值严格按降序排列。 

1.初始化一个数组`death[i] = 0`对于所有职位。 这存储了每个精神病患者被淘汰的回合。 
2. 迭代每个位置`i`从左到右。 
3. 当堆栈不为空且`a[stack[-1]] < a[i]`，从堆栈中弹出。 这些元素较小，不能成为未来元素最接近的主要阻挡者。 他们实际上被`a[i]`。 
4、如果出栈后栈不为空，则栈顶为最左边最近的较大元素。 当前元素最终会因为该元素而被淘汰。 我们设定：`death[i] = death[stack[-1]] + 1`。 

这抓住了这样的想法：`i`比最近的更强的前驱链多存活一轮。 
5. 如果堆栈为空，`death[i]`仍然为 0，因为它的左边没有任何东西支配它。 
6. 推`i`到堆栈上。 
7. 答案是中的最大值`death`。 

### 为什么它有效

 该堆栈保留了“主动主导源”的候选者，这意味着其值从左到右严格递减的索引。 对于任何索引`i`，其左侧的第一个较大元素是唯一最终可以导致其被删除的元素。 它们之间的所有较小元素都是无关紧要的，因为它们较早被淘汰或较早占据主导地位，并且无法阻挡较大值的影响。 

复发`death[i] = death[j] + 1`对于最近的更大的`j`编码分层塌陷结构。 在其占主导地位的前任元素在消除过程中变得活跃之后，每个元素都会多存活一轮。 这确保了消除时间沿着优势链传播，而无需显式模拟回合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stack = []
    death = [0] * n

    for i in range(n):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()

        if stack:
            death[i] = death[stack[-1]] + 1
        else:
            death[i] = 0

        stack.append(i)

    print(max(death))

if __name__ == "__main__":
    solve()
```该实现依赖于单调的索引堆栈。 堆栈总是以降序存储值，确保当我们遇到更大的值时，我们正确地丢弃所有不能影响未来元素的较小候选者。 

这`death`数组是增量计算的，每个条目仅取决于最接近的有效前驱。 这避免了任何重复扫描或模拟回合。 

一个常见的错误是在不保持严格单调性的情况下尝试计算死亡，这破坏了堆栈顶部代表最近的相关较大元素的保证。 另一个微妙的问题是忘记了答案是所有答案中的最大值`death[i]`，不仅仅是最后一个元素。

 ## 边缘情况

 严格递增序列如`1 2 3 4`永远不会触发任何杀戮，因为没有元素在其右侧具有更大的值。 堆栈不断增加，每个元素都得到`death[i] = 0`，最终答案为0。 

严格递减序列如`5 4 3 2 1`产生从左到右的直接统治。 每个元素将第一个值视为其最接近的较大前身，因此所有死亡都取决于索引 0 并计算为 1 步，最多为 1。 

在交替结构中，例如`1 3 2 5 4`，每个峰值都会创造一个新的统治层。 堆栈反复重置，并且传播`death`局部反转后，每当出现新的更强元素时，值就会增加 1。 这演示了该算法如何在无需显式模拟的情况下捕获多轮级联消除。
