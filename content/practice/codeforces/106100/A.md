 ## 解决方案
 ## 问题理解

 我们被赋予了第一个`m`数字排列的元素`1...n`。 这些元素是固定的，无法更改。 

其余`n - m`位置必须完全使用固定前缀中未出现的数字来填充。 填充这些位置后，整个数组必须是包含以下每个数字的有效排列`1`到`n`正好一次。 

在完成排列的所有有效方法中，我们想要一种具有尽可能少的反转次数的方法。 

反转是一对位置`(i, j)`和`i < j`和`p[i] > p[j]`。 

约束条件允许`n`最多`10^5`。 任何明确计算每个可能完成的反转的算法都是极其昂贵的。 即使检查剩余数字的所有排列也需要`(n-m)!`的可能性，而这几乎立即变得不可能。 我们需要一个大致的直接构造`O(n log n)`时间或者更好。 

一些边缘情况很容易被忽略。 

假设固定前缀已经在增加：```
n = 5
m = 4
prefix = [1, 2, 3, 4]
```唯一缺失的数字是`5`，所以答案一定是：```
5
```另一个有趣的案例是：```
n = 4
m = 2
prefix = [4, 1]
```缺失的数字是`{2, 3}`。 

如果我们将它们放置为`[3, 2]`，后缀本身包含一个倒置。 

如果我们将它们放置为`[2, 3]`，后缀包含零个反转。 

涉及固定前缀的反转在两种补全中是相同的，因此第二种安排是最佳的。 

粗心的方法可能会尝试使较大的前缀元素与后缀更好地交互，但这些交叉反转仅由缺失的值决定，而不是由这些缺失值的放置顺序决定。 

## 方法

 强力解决方案将生成丢失数字的每个排列，将其附加到固定前缀，计算结果排列中的反转，并保留最好的排列。 

这是正确的，因为它检查每个有效的完成。 问题在于完成的数量。 如果有`k = n-m`缺失的数字，有`k!`的可能性。 即使是为了`k = 15`，这已经远远超出了实际的极限。 

关键的观察是将反转分为两组。 

第一组由完全在后缀内部的倒装组成。 这些取决于我们为缺失数字选择的顺序。 

第二组由反转组成，其中左侧元素位于固定前缀中，右侧元素位于后缀中。 

考虑一个固定的前缀值`x`。 每个缺失的数字小于`x`创建一个反转`x`，并且每个缺失的数字都大于`x`没有。 计数仅取决于缺失数字的集合，而不取决于它们的顺序。 无论我们如何排列后缀，前缀后缀反转的数量都保持不变。 

这意味着我们唯一可以影响的部分是后缀本身内部的倒置数量。 

在一组不同的数字中，最小可能的反转次数为零，这是通过按升序对它们进行排序来实现的。 

因此，最佳补全就是将缺失的数字按升序排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((n-m)!·n²) | O((n-m)!·n²) | O(n) | 太慢了 |
 | 最佳 | O(n) 或 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`。 
2. 读取固定前缀。 
3. 标记前缀中已出现的每个数字。 
4. 扫描号码`1`到`n`。 
5. 凡是没有标记的号码都是缺失号码，必须属于后缀。 
6. 按升序输出所有缺失的数字。 

步骤 6 是最佳的原因是无论后缀排序如何，前缀后缀反转计数都是固定的，而增加顺序使后缀本身零反转，这是最小的可能值。 

### 为什么它有效

 缺失号码的集合完全由固定前缀决定。 

对于每个前缀元素`p[i]`，后缀元素的数量小于`p[i]`是固定的，因为后缀始终包含完全相同的一组缺失值。 重新排列这些值不能改变其中有多少小于`p[i]`。 

因此，每次涉及至少一个前缀元素的反转都会对答案贡献恒定的量。 

唯一剩下的倒装是完全由后缀内部的对形成的倒装。 当且仅当严格递增时，不同数字的序列具有零反转。 由于零是最小可能的反转计数，因此对缺失的数字进行排序会逐渐产生最佳的完成结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
prefix = list(map(int, input().split()))

used = [False] * (n + 1)

for x in prefix:
    used[x] = True

ans = []
for x in range(1, n + 1):
    if not used[x]:
        ans.append(str(x))

print(" ".join(ans))
```实现直接遵循证明。 

这`used`数组记录哪些值已经出现在固定前缀中。 由于前缀包含来自排列的不同值，因此每个值最多标记一次。 

之后，从一次扫描`1`到`n`收集所有未使用的号码。 由于扫描是按升序执行的，因此生成的后缀已经排序。 

不需要反转计数。 证明表明排序后的缺失数总是最优的。 

一个微妙的点是我们只输出后缀，而不是整个排列。 该问题要求占据位置的值`m+1`通过`n`。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    prefix = list(map(int, input().split()))

    used = [False] * (n + 1)

    for x in prefix:
        used[x] = True

    ans = []
    for x in range(1, n + 1):
        if not used[x]:
            ans.append(str(x))

    print(" ".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

 ## 边缘情况

 考虑：```
4 2
4 1
```缺失的数字是`{2, 3}`。 

该算法输出：```
2 3
```完成的排列是：```
4 1 2 3
```后缀的任何其他顺序，例如`3 2`, 在后缀内引入额外的倒装。 前缀后缀反转保持不变，因为丢失的集合仍然是`{2,3}`。 该算法正确地选择了零后缀反转的排列。 

现在考虑：```
5 4
1 2 3 4
```唯一缺失的值是`5`。 

扫描自`1`到`5`准确找到一个未标记的数字并输出：```
5
```没有选择的自由，算法自然地处理这种边界情况。 

最后，考虑：```
7 3
7 6 5
```缺少的数字是：```
1 2 3 4
```该算法按升序输出它们。 

尽管前缀包含较大的值，会与后缀创建许多反转，但这些反转是不可避免的，因为每个缺失值都小于每个前缀值。 重新排列后缀不能减少该计数。 唯一可控的反转位于后缀本身内部，并且增加顺序将它们最小化为零。
