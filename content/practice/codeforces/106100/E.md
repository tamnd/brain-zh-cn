 ## 解决方案
 ## 问题理解

 我们得到一排气球，由由字符组成的字符串表示`B`和`R`。 

当每个红色气球前面都有一个蓝色气球时，配置被认为是正确的。 在字符串术语中，每次出现`R`必须满足两个条件：

 1. 不能是第一个字符。 
2. 紧邻其左边的字符必须是`B`。 

这意味着有效的配置在位置处不包含红色气球`0`并且没有子串`"RR"`。 

我们最多可以执行一次相邻气球的交换。 任务是确定在零次或一次此类交换后是否可以达到有效配置。 

字符串长度最多为 100。有了如此小的限制，即使尝试每个可能的相邻交换并检查结果字符串也很容易足够快。 每次交换后检查所有位置并验证字符串的解决方案仅执行几千次操作。 

一个微妙的点是理解什么使配置有效。 

考虑：```
BBR
```答案是`YES`因为唯一的红色气球后面紧跟着一个蓝色气球。 

一个常见的错误是假设该排列必须交替为`BRBRBR...`。 那不是必需的。 

另一个容易被忽略的情况是：```
RB
```答案是`YES`。 

交换两个相邻的气球会产生：```
BR
```现在红色气球跟在蓝色气球后面。 

再举一个例子：```
RR
```答案是`NO`。 

唯一可能的交换将字符串保留为`"RR"`，这仍然无效，因为第一个红色气球之前没有蓝色气球。 

## 方法

 最直接的想法就是暴力。 

首先，检查原始字符串是否已经有效。 如果是的话，答案立即`YES`因为我们最多只能执行一次交换。 

否则，尝试每个相邻的对。 对于每个位置`i`， 交换`s[i]`和`s[i+1]`，测试结果字符串是否有效，然后恢复原始顺序。 如果任何尝试成功，则打印`YES`。 

为什么这是正确的？ 因为该问题只允许一项操作，并且该操作只能交换相邻的气球。 枚举所有此类交换涵盖了所有可能的举动。 

长度最多为 100，相邻交换最多为 99 个。 检查有效性需要`O(n)`时间。 总工作量为`O(n²)`，最多大约 10,000 个字符检查。 

不需要更复杂的观察，因为限制很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 已接受 |
 | 最佳 | O(n²) | O(n) | 已接受 |

 对于这个问题，蛮力方法已经足够最优了。 

## 算法演练

 1. 读取字符串。 
2. 定义函数`valid(t)`。 

该函数从左到右扫描字符串。 

如果一个字符是`R`，检查它是否有左邻居以及该邻居是否是`B`。 

如果任一条件失败，则返回`False`。 

如果扫描完成，则返回`True`。 
3. 如果原始字符串有效，则打印`YES`。 

允许零交换，因为问题说“最多一次交换”。 
4. 将字符串转换为可变字符列表。 
5. 对于每个索引`i`从`0`到`n-2`:

 交换位置`i`和`i+1`。 

检查新安排是否有效。 

如果是，则打印`YES`并停止。 

在继续之前恢复交换。 
6. 如果没有相邻的交换产生有效的排列，则打印`NO`。 

### 为什么它有效

 该算法检查零移动中可到达的每个配置以及恰好在一个相邻交换中可到达的每个配置。 

这些正是该问题所允许的所有状态。 有效性测试完全符合每个红色气球必须紧随蓝色气球的要求。 

由于每个合法结果在满足规则时都会被准确地检查和接受，因此算法不会错过有效的解决方案或错误地接受无效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def valid(s):
    n = len(s)
    for i in range(n):
        if s[i] == 'R':
            if i == 0 or s[i - 1] != 'B':
                return False
    return True

def solve():
    s = input().strip()

    if valid(s):
        print("YES")
        return

    arr = list(s)
    n = len(arr)

    for i in range(n - 1):
        arr[i], arr[i + 1] = arr[i + 1], arr[i]

        if valid(arr):
            print("YES")
            return

        arr[i], arr[i + 1] = arr[i + 1], arr[i]

    print("NO")

solve()
```这`valid`函数直接编码正确排列的定义。 每个红色气球的左侧都必须有一个蓝色气球。 

主例程首先检查原始字符串，因为允许零交换。 之后，它会系统地尝试每个相邻的交换。 

每次测试后恢复交换非常重要。 如果不进行恢复，以后的迭代将使用修改后的字符串而不是原始配置。 

由于字符串长度非常小，因此构造和检查这些候选配置完全在限制范围内。

 ## 边缘情况

 考虑：```
RB
```初始配置无效，因为红色气球位于开头。 该算法尝试唯一的相邻交换并获得：```
BR
```现在红色气球前面有一个蓝色气球，所以答案是`YES`。 

考虑：```
BBR
```该算法在尝试任何交换之前检查原始字符串。 唯一的红色气球前面有一个蓝色气球，因此配置已经正确。 由于允许零交换，所以答案是`YES`。 

考虑：```
RR
```第一个红气球违反了规则。 交换唯一的相邻对不会更改字符串。 每个可达配置仍然无效，因此算法正确输出`NO`。 

考虑：```
RBRR
```最初，最后一个红气球跟随另一个红气球。 交换最后两个字符会产生：```
RBRR
```这没有改变任何东西，但是交换中间的一对会产生：```
BRRR
```仍然无效。 该算法检查每个相邻的交换并找到有效的可达排列（如果存在）。 详尽的枚举确保不会忽略任何可能的一次性解决方案。
