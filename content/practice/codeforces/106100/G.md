 ## 解决方案
 ## 问题理解

 我们得到一个长数组`A`和一个目标数组`B`。 

对于任何选定的细分市场`A[L..R]`，我们可以重复删除元素，直到段长度变为`m = |B|`。 删除规则很不寻常：只有当一个元素有右邻居并且两个值不同时才能删除。 

任务是计算有多少个片段`A`可以准确地转化为`B`。 

关键的限制是`n`可以大到`2 · 10^5`， 尽管`m ≤ 100`。 任何检查所有的解决方案`O(n²)`分段是立即不可能的。 甚至`O(n² / 10)`会太大。 的小值`m`才是真正的提示。 它建议我们应该构建一个动态规划解决方案，其复杂度大致为`O(nm)`。 

问题的危险部分是了解哪些元素实际上是可移除的。 

考虑一下细分市场：```
1 1 2
```我们可以删除第二个`1`，然后删除第一个`1`，仅留下`2`。 

现在考虑：```
1 1
```不可能删除。 第一个元素等于其右邻居，第二个元素根本没有右邻居。 

相等值的整个尾部块是特殊的。 如果一个段以以下内容结尾：```
... 5 5 5
```然后所有三个尾随`5`他们被迫生存。 没有什么可以删除它们。 

这一观察结果是解决方案的基础。 

### 不明显的边缘情况 1```
A = [1, 1]
B = [1]
```答案是`0`。 

粗心的解释可能会认为其中之一`1`s 可以被删除。 它不能。 整个后缀运行由相等的值组成，因此两个元素都不可删除​​。 

### 不明显的边缘情况 2```
A = [1, 2, 1]
B = [1, 1]
```答案是`1`。 

中间`2`可以删除，因为它与其右邻居不同。 结果变成`[1,1]`。 

仅考虑独立保留运行的解决方案通常会忽略删除整个运行可能会导致两个相等的值变得相邻并合并。 

### 不明显的边缘情况 3```
A = [7, 7, 7]
B = [7, 7]
```答案是`0`。 

尾随游程长度为`3`，并且该运行中的每个元素都被迫保留。 由于目标长度仅为`2`，转型是不可能的。 

## 方法

 强力解决方案将检查每个部分并确定它是否可以转换为`B`。 

有`O(n²)`段。 即使我们有一个`O(m)`验证程序，总复杂度约为`4 · 10^10`在最坏的情况下进行操作，这是完全不可行的。 

关键的观察是表征从段中可获得的所有可能的最终阵列。 

取任何一段并查看其最后一次相同值的运行。```
x x x x
```这场奔跑的每一个元素都被迫生存。 

最终运行之前的每个位置都是可选的。 我们可以保留它或最终删除它。 

因此，一个段可以产生`B`当且仅当：

 1. 整个尾随运行被映射到后缀`B`。 
2. 剩余前缀`B`显示为该运行之前的子序列。 

这将问题转化为子序列计数问题。 

自从`m ≤ 100`，我们可以扫描`A`一次并维护所有前缀的动态编程值`B`。 对于每一个可能的追踪运行，我们都会问一个问题：```
How many starting positions L allow
B[1..p] to appear as a subsequence
before the run starts?
```民主党的回答是`O(1)`预处理后的时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²m) | O(米) | 太慢了 |
 | 最佳 | O(纳米) | O(m + n) | 已接受 |

 ## 算法演练

 1. 计算在每个索引处结束的等值运行的起始位置。 

如果索引`R`属于开始于`s`，则强制后缀长度为：```
k = R - s + 1
```2. 从左到右扫描数组并维护子序列的 DP 值`B`。 

让`dp[j]`表示子序列的最大可能第一个位置等于`B[1..j]`在已处理的前缀内。 
3. 对于每个跑步起始位置`s`，存储所有的快照`dp[j]`处理位置后的值`s - 1`。 

稍后我们将需要这些值。 
4. 预先计算每个后缀长度`k`是否最后`k`的元素`B`都等于某个值`v`。 
5. 处理每次运行`A`。 

假设跑步开始于`s`, 有价值`v`，和长度`len`。 

对于每个可能的后缀长度：```
k = 1 .. min(len, m)
```对应于结束于：```
R = s + k - 1
```检查是否是最后一个`k`的元素`B`都等于`v`。 
6. 如果没有，该段将永远无法工作。 

如果是，则令：```
p = m - k
```是运行之前必须来自的元素数量。 
7. 什么时候`p = 0`，整个目标是由强制运行形成的。 任意起始位置：```
1 ≤ L ≤ s
```有效，贡献`s`段。 
8. 什么时候`p > 0`，我们需要一个等于`B[1..p]`跑步前。 

存储的 DP 快照位置`s - 1`给出：```
mx = maximum first position of such a subsequence
```每个起始位置：```
L ≤ mx
```作品。 

添加`mx`到答案。 

### 为什么它有效

 段的最终运行是不可变的。 该运行中的每个元素都会在每个有效的转换中生存。 

最终运行之前的每个位置都是可移动的。 通过删除不需要的元素，我们可以准确保留运行之前的前缀的任何子序列。 

因此，通过选择等于前缀的子序列来完全确定有效的变换`B`在运行之前并将强制运行与后缀匹配`B`。 

DP 存储每个匹配的前缀的最新可能的起始位置`B`。 如果比赛可以从位置开始`x`，然后每个段开始`L ≤ x`包含该匹配项。 对此类开始进行计数可以准确地给出有效段的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
A = list(map(int, input().split()))
B = list(map(int, input().split()))

# run starts
run_start = [0] * n
run_start[0] = 0
for i in range(1, n):
    if A[i] == A[i - 1]:
        run_start[i] = run_start[i - 1]
    else:
        run_start[i] = i

# group positions by run start
runs = []
i = 0
while i < n:
    j = i
    while j + 1 < n and A[j + 1] == A[i]:
        j += 1
    runs.append((i, j, A[i]))
    i = j + 1

# snapshots[s] = dp state after processing prefix ending at s-1
snapshots = {}

dp = [0] * (m + 1)

for pos in range(n + 1):
    snapshots[pos] = dp[:]

    if pos == n:
        break

    x = A[pos]

    for j in range(m, 0, -1):
        if x == B[j - 1]:
            if j == 1:
                dp[1] = max(dp[1], pos + 1)
            elif dp[j - 1]:
                dp[j] = max(dp[j], dp[j - 1])

# suffix information of B
suffix_ok = [False] * (m + 1)
suffix_val = [None] * (m + 1)

for k in range(1, m + 1):
    v = B[m - 1]
    good = True
    for t in range(m - k, m):
        if B[t] != v:
            good = False
            break
    suffix_ok[k] = good
    suffix_val[k] = v

ans = 0

for start, end, value in runs:
    length = end - start + 1

    limit = min(length, m)

    state = snapshots[start]

    for k in range(1, limit + 1):
        if not suffix_ok[k]:
            continue
        if suffix_val[k] != value:
            continue

        p = m - k

        if p == 0:
            ans += start + 1
        else:
            ans += state[p]

print(ans)
```DP阵列只有`m + 1`状态，所以更新它的成本`O(m)`每个数组元素。 

的含义`dp[j]`是微妙的。 它存储匹配子序列的最大可能的第一个位置等于`B[1..j]`。 使用最大的第一个位置正是我们所需要的，因为每个段开始不超过该位置都是有效的。 

在处理每个位置之前拍摄快照。 当运行从索引处开始时`s`，我们只需要来自以结尾的前缀的信息`s - 1`，这就是为什么`snapshots[s]`是正确的状态。 

该实现在 DP 值中使用从 1 开始的位置。 这使得计数公式变得简单，因为有效开始的数量正是存储的位置。

 ## 边缘情况

 对于```
A = [1, 1]
B = [1]
```尾游长度是`2`， 尽管`|B| = 1`。 

该算法仅检查`k ≤ m`。 不存在有效配置，因此贡献为零。 

为了```
A = [1, 2, 1]
B = [1, 1]
```最后一次运行有长度`1`，匹配最后一个元素`B`。 

运行前的DP快照记录了有效的子序列`[1]`从位置开始`1`，恰好生成一个有效段。 

为了```
A = [7, 7, 7]
B = [7, 7]
```尾随游程长度已经是`3`。 

由于所有三个元素都是强制幸存者，因此任何以最后一个位置结束的段都无法缩小长度`2`。 由于无法满足所需的后缀长度，算法会自动拒绝它。
