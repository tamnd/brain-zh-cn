 ## 解决方案
 ## 问题理解

 我们有一个带有两个按钮的饮水机。 按红色按钮可以准确地得到`a`毫升水在`100°C`，同时按下蓝色按钮给出准确的`b`毫升在`0°C`。 丁丁想在准确的时间取水`x°C`装在1000毫升的瓶子里，不倒掉任何水。 任务是找到瓶子中能够容纳的最大量的正确调温的水。 

假设丁丁按下红色按钮`i`时间和蓝色按钮`j`次。 热水量为`a * i`，冷水量为`b * j`，总体积为`a * i + b * j`。 所得温度为

 [
 \frac{100ai}{ai+bj}。 
]

 对于中间温度，该方程规定了热水量和冷水量之间的精确比率。 因此，整个问题是整数整除问题而不是模拟问题。 

约束很小，有`a`和`b`最多 1000 个并且`x`介于 0 和 100 之间。瓶子容量固定为 1000 毫升，因此即使直接搜索可能的按钮按下操作原则上也是可行的，但预期的解决方案要简单得多，并且运行时间恒定。 原问题有 1 秒时间限制和 512 MB 内存限制。 

有几种边界情况可能会导致粗心的实施失败。 如果`x = 0`，只能使用冷水。 例如，与```
10
20
0
```答案是`1000`，因为按 50 次蓝色按钮正好产生 1000 毫升。 一个盲目除以的公式`x`会在这里失败。 

同样，如果`x = 100`，只能使用热水。 为了```
300
200
100
```答案是`900`，因为按三下红色按钮会产生 900 毫升。 因此，一般比率公式必须正确处理零系数。 

中间温度也可能根本不可能获得。 为了```
100
101
10
```答案是`0`。 热水和冷水之间所需的比例无法从这两个固定的按钮体积形成，因此假设可能按下按钮的次数会产生无效的肯定答案。 

最后，获得一种有效的混合物并不意味着我们应该就此止步。 如果最小有效混合物有体积`250`，例如，我们可以使`250`,`500`,`750`， 或者`1000`毫升，使用相同混合物的重复副本。 答案是不超过瓶子容量的最大倍数。 

## 方法

 一种简单的暴力方法是尝试按下所有可能的红色按钮和蓝色按钮次数，计算所得温度，并记住最大的有效音量。 由于瓶子只能容纳 1000 毫升，因此可用的压力机数量有限。 一个实现可以检查每一对`(i, j)`和`1 <= i, j <= 1000`，给出多达一百万个候选对。 对于我们评估的每一对

 [
 \frac{100ai}{ai+bj}
 ]

 并检查它是否等于`x`。 

这是有效的，因为每个候选对都被直接测试，因此最终会找到任何可行的混合。 问题在于搜索所做的工作远远超过了结构所需的工作量。 它还鼓励浮点比较，当精确的整数相等可用时，这是不必要的并且有潜在危险。 

关键的观察结果是目标温度决定了热水与冷水的比例。 设热体积为`H`冷量为`C`。 为了`0 < x < 100`,

 [
 \frac{100H}{H+C}=x。 
]

 乘以给出

 [
 (100-x)H=xC。 
]

自从`H = ai`和`C = bj`，我们得到

 [
 a(100-x)i = bxj。 
]

 现在问题已变成以下形式的标准方程`A*i = B*j`。 让

 [
 A=a(100-x)，\qquad B=bx。 
]

如果`g = gcd(A, B)`，最小正解是

 [
 i=\frac{B}{g},\qquad j=\frac{A}{g}。 
]

 相应的最小有效水量为

 [
 M=a\frac{B}{g}+b\frac{A}{g}
 =\frac{100ab}{g}。 
]

 其他所有有效解都是这个最小解的整数倍。 那么一次`M`众所周知，1000毫升瓶子的最大容量是

 [
 \left\lfloor\frac{1000}{M}\right\rfloor M。 
]

 有趣的是，同样的公式也可以处理`x = 0`和`x = 100`。 为了`x = 0`，gcd 变为`gcd(0, 100a) = 100a`, 给予`M = b`。 为了`x = 100`，它给出`M = a`。 因此，在实施过程中不需要特殊情况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(10^6) | O(10^6) | O(1) | O(1) | 原则上接受，不必要的大|
 | 最佳 | O(log(最大(a, b))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`a`,`b`， 和`x`。 定义`A = a * (100 - x)`和`B = b * x`。 这是精确方程中的两个系数`A * i = B * j`。 
2. 计算`g = gcd(A, B)`。 将两个系数除以它们的 gcd 即可得到满足温度方程的最小整数比。 
3. 计算最小有效混合物体积：

 [
 M=\frac{100ab}{g}。 
]

 这里的取消直接来自最小的解决方案`i = B/g`,`j = A/g`。 它们的总水量正好是`100ab/g`。 
4. 计算

 [
 \left\lfloor\frac{1000}{M}\right\rfloor M。 
]

 每个可行的混合物的体积等于`kM`对于某个正整数`k`，所以这正是瓶子中所能容纳的最大可行数量。 
5. 打印该金额。 如果`M > 1000`，商为零，正确表明不能将有效混合物倒入瓶子中。 

关键的不变量是`M`是热部件和冷部件恰好具有所需温度比的最小正体积。 因为每个整数解`A*i = B*j`是约化解的倍数，每个可行的总体积是`M`。 因此，最终的车间操作会考虑每一种可能的可行体积，并选择低于瓶子容量的最大体积。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

a = int(input())
b = int(input())
x = int(input())

g = gcd(a * (100 - x), b * x)
minimum = 100 * a * b // g

answer = (1000 // minimum) * minimum
print(answer)
```两种表达方式`a * (100 - x)`和`b * x`直接来自重新排列温度方程。 保持计算完全积分可以避免浮点精度问题。`math.gcd`也能正确处理零。 什么时候`x = 0`，第二个参数为零，并且当`x = 100`，第一个参数为零。 这就是为什么该实现不需要针对两个极端温度的单独分支。 

表达式`100 * a * b // g`计算最小有效总体积。 Python 整数不会溢出，并且最大的中间值无论如何都很小，因为`a`和`b`最多 1000 个。 

最后，`1000 // minimum`给出适合瓶子的最小混合物的完整副本数. 乘以`minimum`给出实际卷而不仅仅是份数。

 ## 边缘情况

 当`x = 0`，所需的水必须不含热成分。 为了```
10
20
0
```我们得到`A = 1000`和`B = 0`， 所以`gcd(A, B) = 1000`。 最小有效体积为`100 * 10 * 20 / 1000 = 20`。 瓶子里可以装`50`这样的部分，给予`1000`。 该算法自然减少为仅使用蓝色按钮水。 

什么时候`x = 100`，就会出现对称的情况。 为了```
333
7
100
```我们得到`A = 0`和`B = 700`。 最大公约数是`700`，所以最小有效体积为`333`。 三个红色按钮倒出`999`，而四分之一将超出瓶子。 因此输出是`999`。 

当不存在阳性中间混合物时，最小有效体积可以超过瓶容量。 为了```
1000
999
1
```我们有`A = 99000`和`B = 999`，其最大公约数为`9`。 最小有效混合物的体积

 [
 \frac{100\cdot1000\cdot999}{9}=1{,}110{,}000,
 ]

 远高于 1000。因此`1000 // minimum`为零，算法正确打印`0`。 

全相等的情况很有用，因为它测试了最简单的可能比率。 和```
10
10
50
```所需的温度正好是中点，因此需要等量的热水和冷水。 一台红色和一台蓝色压机在 50°C 下可生产 20 毫升，50 份准确装满瓶子。 gcd 约简直接找到这个原始混合物。 

主要的差一陷阱是瓶子边界。 我们需要最大为 1000 的最小有效混合的最大倍数，而不是严格低于 1000 的最小倍数。表达式`(1000 // minimum) * minimum`正确处理精确配合。 如果`minimum = 250`，例如，它返回 1000 而不是 750。
