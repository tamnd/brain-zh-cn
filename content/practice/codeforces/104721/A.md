 ## 解决方案
 ## 问题理解

 我们得到一排苹果，按照原来的从左到右的顺序编号为 1 到 n。 每天，一个固定的确定性规则应用于当前行：从最左边剩余的苹果开始，第一个苹果被删除，然后跳过接下来的两个，然后删除下一个，这种模式一直持续到行尾。 移除后，剩余的苹果会被关闭，同时保留它们的相对顺序，第二天又从这个新序列的第一个位置开始。 

重复这个过程，直到没有苹果剩下。 我们被要求提供两个值：需要多少天该行才会变空，以及最初的第 n 个苹果是在哪一天被移除的。 

n 最大为 10^9 的约束排除了对实际苹果数组的任何模拟。 即使每天线性传递也会太慢，因为天数呈对数增长，但每天仍然可能最初涉及最多 n 个元素，并且简单的过程将涉及重复的重新索引和扫描。 正确的解决方案必须避免显式维护序列。 

当 n 很小时，会出现微妙的边缘情况，因为去除模式是高度结构化的。 例如，当 n 等于 8 时，过程演变如下：在第 1 天，我们删除 1, 4, 7；在第 1 天，我们删除 1, 4, 7； 第 2 天，我们删除 2、6； 在第 3 天，我们删除 3 个； 第 4 天，我们删除 5 个； 在第 5 天，我们删除了 8 个。这表明，即使最后一个元素最初总是存在，但它不一定会在不进行分析的情况下以简单的单调方式提前或晚删除。 

关键的困难在于，苹果的相对位置每天都会发生变化，因此，除非我们了解位置如何变化，否则我们无法独立跟踪指数。 

## 方法

 蛮力策略实际上是维护剩余苹果的列表，每天从左到右扫描，从第一个元素开始删除每三个元素，重建列表，然后重复。 每天的成本为 O(m)，其中 m 是当前大小，并且由于 m 每次大约缩小 2/3，因此总工作量仍然与 n + 2n/3 + 4n/9 + ... 成正比，即 O(n)。 对于 n 达到 10^9 来说这太慢了。 

关键的观察结果是，该过程纯粹是位置性的，不依赖于值，仅依赖于索引结构。 在一天内，如果当前序列的长度为 m，则位置 1、4、7 等处的元素将被删除。 幸存者每三个元素中就有两个组成连续的块。 这意味着新的序列是通过将每三个块压缩为两个而获得的。 

这种压缩给出了位置如何演变的直接公式。 如果某个元素当前位于位置 p，则其下一个位置变为 p 减去其之前已移除元素的数量，即 (p-1)//3。 因此，转换是 p → p - (p-1)//3 = (2p + 2)//3 等价地截断为整数算术。 

这将问题简化为通过对数数量的变换来跟踪单个数字，因为每一步都会将位置缩小大约 2/3 倍。 因此，我们只能模拟给定苹果的轨迹。 

对于所有苹果被移除之前的总天数，我们不需要跟踪个人。 相反，我们跟踪序列的长度。 每天正好删除 ceil(m/3) 个元素，因此递推式为 m → m - ceil(m/3) = Floor(2m/3)。 m 变为零之前的迭代次数就是总天数的答案。 

对于苹果 n 的位置，我们模拟它不断变化的位置，直到它被移除，当它的当前位置在一天开始时与 1 模 3 一致时就会发生这种情况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | O(n) | O(n) | 太慢了 |
 | 位置压缩模拟| O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

我们将解决方案分为两个独立的模拟：一个模拟总天数，另一个模拟第 n 个苹果的命运。 

1. 从 m = n 开始。 这代表每天开始时还剩下多少苹果。 
2.使用m=floor(2m/3)重复更新m。 每次更新对应一整天的删除。 这会计算需要多少轮才能剩下苹果。 
3. 计算此更新被应用了多少次，直到 m 变为零。 此计数是总天数。 
4. 要跟踪原始第 n 个苹果，请设置 p = n。 这代表了它在剩余苹果中的当前位置。 
5. 对于每一天，首先检查是否 p % 3 == 1。如果是，则该苹果在这一天被移除，我们记录天数。 
6. 如果没有被删除，则使用 p = p - (p-1)//3 更新其位置，这反映了在它之前有多少个被删除的元素。 
7. 重复上述步骤，直到苹果被移除。 

这样做的原因是每天将数组划分为三个连续位置的块。 在每个块中，第一个元素被删除，其余两个元素保留。 转换公式精确地减去给定位置之前出现的已删除元素的数量，因此它保留了幸存者的相对顺序，同时将旧索引映射到压缩结构中。 这确保了通过连续压缩跟踪单个元素能够准确地再现其在演变序列中的真实轨迹。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def total_days(n: int) -> int:
    days = 0
    m = n
    while m > 0:
        m = (2 * m) // 3
        days += 1
    return days

def nth_apple_day(n: int) -> int:
    p = n
    day = 0
    while True:
        day += 1
        if p % 3 == 1:
            return day
        p = p - (p - 1) // 3

def main():
    n = int(input().strip())
    print(total_days(n), nth_apple_day(n))

if __name__ == "__main__":
    main()
```总天数计算使用这样一个事实：每天之后的剩余长度仅取决于可以形成多少个三元组。 每三组恰好贡献两个幸存者，因此更新 m = (2m)//3 是该压缩的整数形式。 

第二部分通过仅模拟第 n 个苹果的指数演变来跟踪第 n 个苹果。 条件 p % 3 == 1 准确检测苹果在一天开始时何时处于移除位置，因为每三个块都会移除其第一个元素。 如果它幸存下来，映射 p - (p-1)//3 将其转移到第二天的压缩索引中。

 ## 边缘情况

 对于 n = 1，序列包含一个苹果。 它在第一天被删除，因为它位于位置 1，与规则直接匹配。 总天数模拟立即将 m 从 1 减少到 0，产生 1 天，并且在第 1 天删除跟踪的苹果。 

对于 n = 2，第一天仅移除第一个苹果，在位置 1 留下一个苹果。第二天，剩余的苹果将被移除。 模拟 m: 2 → 1 → 0 确认两天，位置跟踪显示苹果 2 在第 1 天存活下来并在第 2 天被移除。 

对于 n = 3，由于重复重新索引，所有三个苹果都在不同的日子被移除。 该转换确保每次压缩后，剩余结构仍然受相同的三块规则控制，因此该过程会进行多轮，直到耗尽。
