 ## 解决方案
 ## 问题理解

 我们正在计算描述折线的高度序列。 x 坐标固定为`1, 2, ..., n`，所以整个形状仅由序列决定`y1, y2, ..., yn`。 

每个高度必须是整数`1`到`4`，并且相邻高度必须不同，因为禁止水平段。 “驼峰”只是局部最大值。 在位置`i`，我们有一个驼峰，如果`y[i-1] < y[i] > y[i+1]`。 类似地，当`y[i-1] > y[i] < y[i+1]`。 

该问题要求精确包含的序列数`t`局部最大值和精确`t-1`局部最小值。 

这些约束在一个维度上非常小，而在另一个维度上却非常大。 序列长度最多为`20`，这表明指数搜索似乎是可能的。 但每个位置都有四种选择，所以用蛮力会检验`4^20 ≈ 10^12`序列，在两秒钟内完全不可能。 

微小的高度范围才是真正的线索。 由于每个值都属于`{1,2,3,4}`，涉及最近元素的不同状态的数量极少。 这强烈表明对最后几个值和已经形成的驼峰数量进行动态规划。 

一个微妙的点是，局部最大值和最小值只有在看到三个连续值后才能确定。 当我们附加一个新值时，最后三个位置的中间元素将被分类为峰值、谷值或两者都不是。 粗心的实施如果试图过早地对职位进行分类，就会算错。 

另一个容易犯的错误是忘记相邻的相同高度是被禁止的。 例如：```
n = 3, t = 1
```顺序`1 2 2`即使它在视觉上看起来增加然后平坦，也是无效的。 相等的邻居创建一个水平线段，因此不得计算此序列。 

最大值和最小值之间还存在交替性质。 一旦序列开始向上移动，下一个转折点必须是最大值，然后是最小值，依此类推。 独立计算最大值和最小值的有缺陷的解决方案可能会意外地允许不可能的模式。 

例如：```
1 3 2 4
```这里的位置`2`是最大值和位置`3`是最小值。 图案正确交替。 

但是一个序列不能包含两个连续的最大值，而它们之间没有最小值。 几何学禁止它。 

边界附近出现了另一种极端情况。 职位`1`和`n`永远不会被视为峰或谷，因为它们没有两个邻居。 统一检查所有位置的简单实现可能会错误地计算端点。 

例如：```
1 3 2
```这个位置有一个驼峰`2`。 

但：```
3 1 2
```位置没有驼峰`1`， 虽然`3`比它唯一的邻居大。 

## 方法

 暴力解决方案生成所有长度的序列`n`超值`{1,2,3,4}`并过滤掉有效的。 

对于每个生成的序列，如果某些相邻值相等，我们首先拒绝它。 然后我们扫描所有内部位置并计算局部最大值和最小值。 

这是有效的，因为定义是直接且易于验证的。 不幸的是，搜索空间是巨大的：```
4^20 = 1,099,511,627,776
```即使检查一个序列只需要几个 CPU 指令，这仍然是无望的。 

重要的观察是，位置是否`i`成为峰值或谷值仅取决于三个连续值：```
y[i-1], y[i], y[i+1]
```当从左到右构建序列时，一旦我们知道最后两个高度，添加一个新高度就可以完全确定中间高度的作用。 

这意味着未来并不关心整个前缀。 它只需要：```
current length
last two heights
number of maxima so far
number of minima so far
```这是一个经典的动态规划压缩。 由于高度范围只有四个值，状态空间变得很小。 

最多有：```
20 * 4 * 4 * 11 * 11
```州，只有几千个。 

过渡很简单。 假设当前的最后两个值是`(a, b)`我们附加`c`。 

如果：```
a < b > c
```然后`b`是局部最大值。 

如果：```
a > b < c
```然后`b`是局部最小值。 

否则就不会创建任何新内容。 

我们以这种方式扩展所有状态并累积计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(4^n·n) | O(4^n·n) | O(n) | 太慢了 |
 | 最佳DP | O(n·4立方·t²) | O(4²·t²) | O(4²·t²) | 已接受 |

 ## 算法演练

 1. 定义DP状态为：```
dp[pos][a][b][mx][mn]
```其中：

 1.`pos`是当前序列长度。 
2.`a`和`b`是最后两个高度。 
3.`mx`是已经形成的局部最大值的数量。 
4.`mn`是已经形成的局部最小值的数量。 

状态存储有多少序列产生此配置。 

1.初始化所有长度的序列`2`。 

对于每对`(a, b)`和`a != b`， 放：```
dp[2][a][b][0][0] = 1
```在长度二处，尚不存在内部位置，因此不会出现峰或谷。 

1. 一次将序列延伸一个位置。 

假设当前状态以`(a, b)`。 尝试每一个新值`c`从`1`到`4`和`c != b`。 

这维持了相邻高度不能相等的规则。 

1. 判断是否`b`成为一个转折点。 

如果：```
a < b > c
```增加最大值的数量。 

如果：```
a > b < c
```增加最小值的数量。 

否则计数保持不变。 

中间值`b`现在已经完全确定了，因为两个邻居都是已知的。 

1. 将转换结果添加到下一个 DP 状态中。 

新的状态变为：```
(pos + 1, b, c, new_mx, new_mn)
```因为最后两个值向前移动。 

1. 继续直到序列达到长度`n`。 
2. 对所有状态进行精确求和`t`最大值和`t-1`最小值。 

最后两个高度不再重要，因此将所有结束对相加。 

### 为什么它有效

 DP 不变量为：```
dp[pos][a][b][mx][mn]
```等于长度有效序列的数量`pos`以高度结束`(a,b)`恰好包含`mx`局部最大值和`mn`所有完全确定的内部位置之间的局部最小值。 

每当我们附加一个新值时`c`, 只取中间值`b`可能会重新成为一个峰或谷。 早期的位置已经固定，不能再改变，因为它们的邻居都是已知的。 这意味着每次转换都会正确且准确地更新计数一次。 

由于每个有效序列都可以通过重复附加其下一个值来唯一构造，因此 DP 枚举了所有有效序列，没有重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())

    # dp[a][b][mx][mn]
    dp = [[[[0] * (t + 1) for _ in range(t + 1)] for _ in range(5)] for _ in range(5)]

    for a in range(1, 5):
        for b in range(1, 5):
            if a != b:
                dp[a][b][0][0] = 1

    for pos in range(2, n):
        ndp = [[[[0] * (t + 1) for _ in range(t + 1)] for _ in range(5)] for _ in range(5)]

        for a in range(1, 5):
            for b in range(1, 5):
                for mx in range(t + 1):
                    for mn in range(t + 1):
                        cur = dp[a][b][mx][mn]

                        if cur == 0:
                            continue

                        for c in range(1, 5):
                            if c == b:
                                continue

                            nmx = mx
                            nmn = mn

                            if a < b > c:
                                nmx += 1
                            elif a > b < c:
                                nmn += 1

                            if nmx > t or nmn > t:
                                continue

                            ndp[b][c][nmx][nmn] += cur

        dp = ndp

    ans = 0

    for a in range(1, 5):
        for b in range(1, 5):
            ans += dp[a][b][t][t - 1]

    print(ans)

solve()
```实现直接遵循 DP 定义。 

初始化创建所有有效的长度为 2 的前缀。 从长度一开始会使转换逻辑复杂化，因为转折点需要三个值。 

外循环从`2`到`n-1`。 每次迭代都会附加一个新值，从而将序列长度增加一。 

转换检查三元组`(a, b, c)`。 这就是问题的中心思想。 仅中间元素`b`这一刻可以成为高峰或低谷。 

条件排序很重要：```
if a < b > c:
```必须与以下各项分开检查：```
elif a > b < c:
```因为一个位置不能同时是两者。 

修剪：```
if nmx > t or nmn > t:
    continue
```保持 DP 较小并避免不必要的状态。 

最后我们将状态与精确求和`t`最大值和`t-1`最小值。 最后一对`(a,b)`无关紧要，因为所有内部职位都已分类。 

Python 整数自动处理大答案，因此溢出不是问题。

 ## 边缘情况

 考虑：```
3 1
```唯一可能的结构是：```
low high low
```DP 以所有有效对开始`(a,b)`并附加`c`。 仅当满足以下条件时才计算峰值：```
a < b > c
```有效的序列是：```
1 2 1
1 3 1
1 4 1
2 3 2
...
```最终答案变成`4`在遵守高度限制和明确的邻接规则之后。 

现在考虑：```
3 2
```长度为 3 的序列只有一个内部位置。 创建两个峰是不可能的。 在转换期间，DP 最多可以增加一次峰值计数，因此状态`2`永远无法达到顶峰。 算法正确返回`0`。 

另一个棘手的情况是相邻值相等：```
4 1
```粗心的解决方案可能会接受：```
1 3 3 1
```但转换明确跳过：```
if c == b:
    continue
```所以水平段会被自动禁止。 

最后考虑端点处理：```
3 1
```顺序：```
3 1 2
```第一个值`3`不计为峰值，因为仅对三元组的中间元素进行分类。 DP 仅检查涉及的条件`(3,1,2)`，这使得`1`山谷，不是`3`一个高峰。 这与问题定义完全匹配。
