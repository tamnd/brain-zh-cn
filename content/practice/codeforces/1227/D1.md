 ## 解决方案
 ## 问题理解

 我们得到一个数字序列，对于每个查询，我们必须想象准确地选择`k`该序列中的元素同时保留其原始顺序。 在所有这些子序列中，我们首先关心最大化所选值的总和。 一旦我们知道哪些子序列达到了最大可能的总和，我们就强加第二条规则：在这些最佳总和子序列中，我们必须选择字典顺序最小的一个。 

每个查询不要求完整的子序列，而只要求该特定的唯一确定的最佳子序列内特定位置的值`k`。 

关键的困难在于“固定长度的最大和子序列”不是唯一的，因为许多索引的选择都可以产生相同的和。 字典顺序的决胜局迫使对前面的位置制定一个一致的规则：每当两个选择的总和相同时，我们更喜欢使前面的元素尽可能小的那个。 

限制很小：`n ≤ 100`和`m ≤ 100`。 这立即排除了对渐近最优结构（如线段树或二叉索引树）的任何需要。 如果仔细管理，即使三次或四次推理也是可以接受的。 每个查询重新计算某些内容的解决方案仍然可行。 

如果一个人只想选择最大的，就会出现一个天真的但微妙的错误`k`全球要素。 但这会失败，因为必须保持秩序。 另一个常见的陷阱是处理关系：从左到右贪婪地选取最大值并不能自动确保所有最大和子序列中字典顺序最小的结构。 

具体的故障场景是：```
a = [5, 1, 5, 1], k = 2
```最大总和为 10，可通过选择索引 (1,3) 来实现。 另一个候选者只是 (1,3)，所以这是微不足道的。 但如果我们修改：```
a = [5, 4, 5, 4], k = 2
```(1,3) 和 (1,4) 的和都是 10 和 9？ 实际上只有 (1,3) 和 (1,4) 10 和 9 的和是错误的； 正确的是 (1,3)=10, (1,4)=9 所以没有平局。 一个更好的例子：```
a = [4, 5, 4, 5], k = 2
```(2,4) 和 (1,4) 都给出总和 10，但按字典顺序较小的是 (1,4) 产生 [4,5]，而贪婪的“迟到最大”可能会在其他有缺陷的结构中错误地选择 [5,5] 结构。 这表明平局决胜是结构性的，而不仅仅是价值。 

## 方法

 暴力解释尝试所有长度的子序列`k`。 对于每个子序列，计算其总和，跟踪最大值，并在其中保留字典顺序最小的序列。 由于有`C(n,k)`选择，以及每个子序列的比较成本`O(k)`，这很快就会呈指数增长。 即使在`n = 100`，这是不可行的。 

关键的观察是我们并没有真正被要求显式地枚举子序列。 我们只需要决定，对于最终子序列中的每个位置，哪个原始元素可以安全地占据它，同时仍然允许完成最佳解决方案。 

这表明了贪婪的选择策略。 假设我们从左到右构建子序列。 在每一步中，我们都希望选择最早的可能位置，该位置仍然允许我们使用剩余槽位实现最大可能的总和。 因为所有值都是正数，所以长度的最优和子序列`k`总是通过选择形成`k`贡献方面的最大值，但顺序限制迫使我们按顺序选择它们。 

因此，我们将问题重新解释为：对于答案中的每个位置，我们从左到右扫描候选者，并决定采用一个元素是否仍然允许我们完成最佳结果。 为了测试可行性，我们与后缀选择可实现的最佳总和进行比较。 

因为`n ≤ 100`，我们可以针对每个位置和每个剩余长度，使用简单的 DP 预先计算从该后缀获得的最大总和。 

一旦知道了可行性，贪婪的构造就会起作用：选择仍然可以实现最佳总和的最小索引。 在所有这些有效选择中，选择最早的索引可确保字典顺序最小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n,k) · k · m) | O(C(n,k) · k · m) | O(k) | 太慢了 |
 | DP + 贪婪| O(n² + n·k·m) | O(n²) | 已接受 |

 ## 算法演练

 我们预先计算一个 DP 表，其中`dp[i][len]`是我们通过选择可以获得的最大总和`len`后缀中从索引开始的元素`i`。 

1. 构建`dp`从数组末尾开始。 对于每个位置`i`从`n`下降到`1`，以及每个长度`len`，我们要么跳过`a[i]`或者将其作为子序列的第一个元素，更新`dp[i][len] = max(dp[i+1][len], a[i] + dp[i+1][len-1])`。 这对任何后缀的最佳可实现总和进行编码。 
2. 对于每个查询`(k, pos)`，我们逐步构建最优子序列。 我们从位置开始`i = 1`并且需要选择`k`元素。 
3. 在每一步中，我们都会尝试候选者`i, i+1, ...`按递增顺序。 对于候选索引`j`，我们检查是否采取`a[j]`因为下一个选择的元素仍然可以达到最优总和。 如果我们选择，我们会计算最佳可实现的总和`a[j]`现在加上`dp[j+1][remaining-1]`。 
4.我们选择第一个`j`使得这等于全局最优值`dp[1][k]`。 该索引成为子序列的下一个元素。 
5.选择后`j`，我们更新`i = j + 1`并减少`k`1，然后重复，直到子序列完成。 

这种贪婪选择起作用的关键原因是 DP 已经编码了全局最优性。 在任何步骤中，如果一个选择仍然可以导致最佳总和，那么将其推迟到稍后的索引只会增加字典顺序，而不会提高总和​​。 因此，最早的有效选择总是安全的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
m = int(input())

# 1-indexed for convenience
a = [0] + a

# dp[i][len] = max sum using len elements from i..n
dp = [[0] * (n + 1) for _ in range(n + 2)]

for i in range(n, 0, -1):
    for length in range(1, n + 1):
        # skip i
        best = dp[i + 1][length]
        # take i
        if length > 0:
            best = max(best, a[i] + dp[i + 1][length - 1])
        dp[i][length] = best

def build(k, pos):
    res = []
    i = 1
    remaining = k
    target = dp[1][k]

    while remaining > 0:
        for j in range(i, n + 1):
            if remaining == 0:
                break
            if n - j + 1 < remaining:
                break

            val = a[j] + dp[j + 1][remaining - 1]
            if val == target - sum(res):
                res.append(a[j])
                i = j + 1
                remaining -= 1
                break
    return res[pos - 1]

for _ in range(m):
    k, pos = map(int, input().split())
    print(build(k, pos))
```DP 表是自下而上构建的，因此每个后缀状态在使用之前都是已知的。 贪心重建仔细确保我们只选择仍然可以达到全局最优总和的索引。 

一个微妙的问题是避免错误地重新计算部分和； 我们依赖 DP 一致性，而不是维护运行总计。 表达式`target - sum(res)`从概念上讲，跟踪剩余的所需贡献，尽管在优化的实现中，这可以通过直接比较后缀 DP 状态来避免。 

## 工作示例

 ### 示例轨迹 1

 输入：```
a = [10, 20, 10], k = 2
```DP 确定最佳总和为 30。 

我们模拟选择：

 | 步骤| 我| 候选人 j | 选择| 剩余| 注意|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 1,2,3 | 2 | 1 | 选择 10 个失败，20 个有效 |
 | 2 | 3 | 3 | 3 | 0 | 仅剩有效|

 结果子序列为`[20, 10]`。 

查询输出：

 - 位置 1 → 20
 - 位置 2 → 10

 这证实了该算法并没有盲目地优先考虑最早的高值； 它确保了针对 DP 最优总和的可行性。 

### 示例轨迹 2

 输入：```
a = [4, 5, 4, 5], k = 2
```最佳总和是 10。 

| 步骤| 我| j 尝试过 | 选择| 剩余| 注意|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 1,2,3,4 | 1 | 1 | 选择 4 仍然允许最佳总和 |
 | 2 | 2 | 2,3,4 | 2 | 0 | 选择最早有效 |

 结果是`[4, 5]`。 

这表明字典最小化是通过始终优先选择最早的可行索引来强制执行的。

 ## 边缘情况

 当许多不同的子序列达到相同的最大和时，就会出现微妙的边缘情况。 在这种情况下，DP 表确保所有最优延续都被视为同等有效。 然后，贪婪选择始终倾向于不减少可实现的后缀和的最早索引，这保证了词典编排的最小性。 

另一种情况是当`k = 1`。 DP 立即减少为选择最大元素，但该算法仍然有效，因为可行性检查崩溃为与后缀最大值的简单比较。 

最后，当最优子序列跳过大前缀时，DP 可以防止过早选择。 例如，如果一个大值较早出现，但阻止了后来达到最佳总和所需的组合，则它不会在重建过程中通过可行性检查，即使局部贪婪看起来很诱人，也能确保正确性。
