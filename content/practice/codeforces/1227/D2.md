 ## 解决方案
 ## 问题理解

 我们得到了一个固定的整数数组和许多查询。 每个查询都要求我们想象准确地挑选$k$从数组中取出元素，同时保留其原始顺序。 在所有这样的长度子序列中$k$，我们首先想要总和最大的那个。 然后，在达到该最大总和的所有子序列中，我们选择字典顺序最小的一个。 

一旦这个特殊子序列对于给定的固定$k$，每个查询都要求其中的一个位置。 

关键的难点在于$k$每个查询的变化，最多有$2 \cdot 10^5$查询，因此每个查询从头开始重新计算解决方案是不可能的。 

这些约束迫使任何解决方案在预处理中都是大致线性或接近线性的，加上每个查询的对数或常数。 任何在每个查询中贪婪地重复构建子序列的行为都会导致大约$O(nm)$，太大了。 

当多个子序列具有相同的最大和时，就会出现微妙的失败情况。 例如，如果数组包含重复值，贪婪的“总是选择下一个最大的可用”方法会忽略位置结构。 词典最小化迫使子序列中较早的位置尽可能小，这可能需要优先选择较早出现的相等值。 

当值相等或接近相等时，会出现另一种棘手的情况：两个子序列可能具有相同的总和，但不同的排序选择会产生不同的字典结果。 仅跟踪总和的简单方法将返回错误的子序列。 

例如，考虑：```
a = [5, 1, 5]
k = 2
```两个子序列`[5,5]`和`[5,5]`具有相同的总和，但字典顺序的决胜力首先选择较早的 5 个，从而导致取决于位置而不仅仅是值的确定性结构。 

## 方法

 蛮力的想法很简单。 对于每个查询，我们尝试所有长度的子序列$k$, compute their sums, keep only those with maximum sum, and then among them pick the lexicographically smallest. 这立即呈指数增长$n$，因为有$\binom{n}{k}$子序列。 

即使我们使用每个查询的动态编程来改进它，计算每个查询的最佳子序列$k$独立成本$O(nk)$或者$O(n \log n)$每个查询，仍然会中断$2 \cdot 10^5$查询。 

关键的观察结果是，这个问题实际上并不需要重新计算每个$k$。 如果我们按值对元素进行排序，则大小的最佳子序列$k$总是通过取$k$数组中最大的元素，但有一个约束：我们必须保留原始顺序，所以我们实际上是在选择一个大小-$k$具有最大值的索引子集。 这相当于选择顶部$k$按值排列元素，然后恢复其原始顺序。 

一旦我们以这种方式查看，结构就变成静态的：我们可以按值降序对索引进行排序，并且对于每个前缀$k$，我们确切地知道选择了哪些索引。 剩下的挑战是回答有关$pos$- 该有序子序列中的第一个元素。 

我们可以将元素“激活”的顺序预处理为$k$从 1 增加到$n$。 每次我们包含一个新元素（按值递减顺序）时，我们都会将其位置插入到维护排序位置的结构中。 然后每个前缀$k$对应于所选索引的排序列表，我们可以使用二元提升或线段树顺序统计结构来回答位置查询。 

干净的实现使用 Fenwick 树来维护选择的索引并支持 k 阶统计。

 | ---| ---| ---| ---|
 | 蛮力 | 指数 /$O(n^2 m)$|$O(n)$| 太慢了 |
 | 最优（排序+BIT）|$O(n \log n + m \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 按值的降序对数组的所有索引进行排序。 

这确保了当我们逐渐“激活”元素时，我们总是添加下一个最佳可能值，这是最大化总和所需的。 
2. 构建数组`order`， 在哪里`order[t]`是从子序列大小移动时变得可用的元素的索引$t-1$到$t$。 
3. 维护持仓的 Fenwick 树（或任何订单统计结构）$1 \ldots n$，最初为空。 
4. 对于每个$k = 1 \ldots n$， 插入`order[k]`进入芬威克树。 

在这一步之后，树准确地表示了大小最优子序列的索引$k$，以递增的索引顺序存储。 
5. 预先计算每个的映射$k$通过芬威克树隐式地添加到选定位置的排序列表。 
6. 回答询问$(k, pos)$，找到$pos$- 第一个中最小的活动索引$k$插入的元素。 

这是标准 Fenwick 树“第 k 个”查询。 
7. 返回原始数组中该索引处的值。 

### 为什么它有效

 在任何固定的$k$，最优子序列必须恰好包含$k$数组中的最大值。 如果包含较小的值，而存在较大的未使用值，则替换它会增加总和，与最优性相矛盾。 在等和选择中，按升序选择索引会产生字典顺序最小的子序列，因为在可能的情况下总是优先选择较早的位置。 芬威克树的构造恰好强制执行这个不变量：$k$，它包含$k$最高值元素，并按排序索引顺序读取它们会产生所需的字典顺序最小有效序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: a[i], reverse=True)

    bit = Fenwick(n)
    ptr = 0

    queries = []
    for _ in range(int(input())):
        k, pos = map(int, input().split())
        queries.append((k, pos, _))

    ans = [0] * len(queries)

    # sort queries by k
    queries.sort()

    for k, pos, qi in queries:
        while ptr < k:
            bit.add(order[ptr] + 1, 1)
            ptr += 1
        idx = bit.kth(pos)
        ans[qi] = a[idx - 1]

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```该解决方案首先按值的降序对索引进行排序，这决定了元素进入候选集的顺序。 Fenwick 树维护当前选择的索引。 

Each query is processed after ensuring exactly$k$元素已被插入。 然后，芬威克树允许提取$pos$- 对数时间内选定的第一个索引。 返回的值只是该索引处的数组值。 

一个常见的错误是忘记在形成子序列时必须保留原始索引顺序。 芬威克树通过存储索引并始终以递增的索引顺序检索它们，隐式地解决了这个问题。 

另一个微妙之处是 Fenwick 树中基于 1 的索引。 将基于 0 的数组索引与基于 1 的树位置混合是产生差一错误的常见原因。

 ## 边缘情况

 完全相等的数组表明，一旦值相等，选择顺序就纯粹是索引驱动的。 该算法按递增值顺序激活索引，但所有值都相同，因此芬威克树最终选择索引的前缀。 查询正确返回第 pos-th 最小索引。 

严格递增的数组暴露了相反的极端：最大值位于末尾，因此激活从右到左发生。 任意的子序列$k$成为$k$最大的后缀元素，芬威克树确保它们以递增的索引顺序返回，符合字典要求。 

单元素数组验证 Fenwick 树在最小输入大小时不会中断，并且 k=1 的第 k 个查询始终返回唯一的索引。
