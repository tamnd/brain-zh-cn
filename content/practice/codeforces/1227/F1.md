 ## 解决方案
 ## 问题理解

 我们给出了长度多项选择测试的固定答案`n`，其中每个问题都有一个已知的正确选项。 我们还在考虑填写测试答案的所有可能方法，其中每个位置可以取任意值`1`到`k`。 

所选答案数组产生的分数等于与正确答案匹配的位置数。 之后，数组循环移动一个位置，我们使用相同的固定答案重新计算分数。 任务是计算有多少个初始答案数组具有在本轮旋转后分数严格增加的属性。 

困难不在于评估一种配置，而在于计算所有有效配置`k^n`的可能性。 自从`n`最多 2000 并且`k`可以大到 10^9，暴力破解所有数组是不可能的。 即使是任何二次方`k`是无关紧要的，因为状态空间是指数的`n`。 

我们可以利用的唯一结构是原始数组和旋转数组之间的分数差异仅取决于相邻位置之间的局部关系以及与固定数组的比较`h`。 

当所有位置都在`h`是相同的。 然后，匹配结构变得高度对称，并且由于旋转耦合了索引，独立处理位置的朴素推理就会崩溃。 另一个边缘情况是`n = 1`，其中旋转不执行任何操作，因此无论如何，答案都必须为零`k`。 任何假设发生有意义的转变的解决方案都会在这里失败。 

## 方法

 一种直接的方法是迭代每个可能的数组`a`，计算其分数`h`，然后计算旋转后的分数并进行比较。 这是正确的，但立即不可行，因为有`k^n`数组，甚至评估一个数组也需要`O(n)`，导致指数时间。 

关键的观察是停止考虑完整阵列，而是比较旋转前后每个位置的贡献。 各位置`i`贡献`1`如果`a[i] == h[i]`。 旋转后的值是`i`移动到`i+1`，所以贡献取决于是否`a[i] == h[i+1]`。 这将问题转化为比较相邻索引上的两个循环匹配模式。 

对于每个位置，我们只关心是否`a[i]`比赛`h[i]`,`h[i+1]`，两者，或两者都不。 这将每个位置减少为一个小的本地状态，但这些状态必须在整个周期内保持一致。 问题变成了在 4 状态字母表上计算循环序列，并受到实际值分配引起的约束。 

我们不是直接跟踪实际值，而是根据所选值是否等于对位置之间的转换进行分类`h[i]`,`h[i+1]`，或两者都不是。 每个类别的可用值数量取决于是否`h[i] == h[i+1]`或不，这引入了组合权重。 

然后，我们将问题重新解释为循环中的 DP，其中每个位置贡献一种类型，并且转换必须与从中选择实际值一致`[1, k]`。 这成为一种标准的循环 DP，我们在一个位置打破循环并在最后强制一致性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k^n · n) | O(k^n · n) | O(n) | 太慢了 |
 | 在状态之间循环 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们为每个位置定义`i`如何值`a[i]`影响两个相邻的比较：与`h[i]`并与`h[i+1]`（指数模`n`）。 这产生了四个逻辑类别：

 一个值不能匹配任何一个，只能匹配`h[i]`, 仅匹配`h[i+1]`，或者当两者都匹配时`h[i] == h[i+1]`。 

对于每条边`(i, i+1)`，我们计算有多少个值产生每个行为。 这给出了连续位置的“匹配状态”之间的转换权重。 

然后我们在状态编码的位置上构建一个DP`a[i]`等于`h[i]`。 原始分数和旋转分数之间的贡献差异取决于局部转换，因此我们跟踪净增益。 

为了强制执行循环条件，我们固定第一个位置并围绕圆运行 DP，累加总增益是否为正。 

最终答案是所有 DP 路径的总和，其中总增益严格大于零。 

### 为什么它有效

 原始数组和旋转数组之间的分数差异分解为相邻索引之间独立局部贡献的总和。 每个值仅影响两个位置，因此仅影响两个分数项。 这种局部依赖性确保可以通过循环 DP 强制执行全局约束，而不会丢失信息。 每个有效的分配恰好对应于一个DP路径，并且每个DP路径都对应于一个有效的分配，从而保留了双射和正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        return

    # Precompute for each i the categories of values:
    # we only need counts:
    # equal to h[i], equal to h[i+1], equal to both, or neither
    
    cnt = []
    for i in range(n):
        j = (i + 1) % n
        if h[i] == h[j]:
            eq = 1
            neq = k - 1
            cnt.append((eq, 0, 0, neq))
        else:
            # values:
            # 1 value equal h[i]
            # 1 value equal h[i+1]
            # remaining k-2 are neither
            cnt.append((1, 1, 0, k - 2))

    # dp[pos][gain offset] is impossible directly due to large k range
    # Instead we compute expected gain difference contribution-wise.
    # We only need total difference > 0, so we use DP over cumulative gain range.

    # Each position contributes:
    # match at i contributes +1 if a[i]==h[i]
    # after shift contributes +1 if a[i]==h[i+1]

    # net contribution per value at i:
    # if value == h[i] -> +1 old
    # if value == h[i-1] -> affects previous edge etc.

    # We convert to edge contribution:
    # diff = sum_i [a[i]==h[i+1]] - [a[i]==h[i]]

    # each position independent => DP over cyclic sum constraint.

    max_shift = 2 * n
    offset = n

    dp = [[0] * (2 * n + 1) for _ in range(n + 1)]
    dp[0][offset] = 1

    for i in range(n):
        new = [[0] * (2 * n + 1) for _ in range(n + 1)]
        for g in range(2 * n + 1):
            cur = dp[i][g]
            if not cur:
                continue

            j = (i + 1) % n
            if h[i] == h[j]:
                same = 1
                diff = k - 1

                # value equal h[i] gives 0 net change
                new[i + 1][g] = (new[i + 1][g] + cur * same) % MOD
                new[i + 1][g] = (new[i + 1][g] + cur * diff) % MOD
            else:
                # value = h[i]
                new[i + 1][g - 1] = (new[i + 1][g - 1] + cur) % MOD
                # value = h[i+1]
                new[i + 1][g + 1] = (new[i + 1][g + 1] + cur) % MOD
                # other values
                new[i + 1][g] = (new[i + 1][g] + cur * (k - 2)) % MOD

        dp = new

    ans = 0
    for g in range(offset + 1, 2 * n + 1):
        ans = (ans + dp[n][g]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该实现尝试将分数差异编码为扫描位置时的运行平衡。 关键思想是，每个位置贡献 +1、-1 或 0，具体取决于它是否与循环中的后继或前驱匹配。 

DP 维护一个偏移平衡索引，以便可以安全地存储负值。 每个步骤都会根据所选值是否等于来更新可能余额的分布`h[i]`,`h[i+1]`，或两者都不是。 最终总和提取净增益为正的所有配置。 

一个微妙的点是正确处理环绕：位置`n`与位置比较`1`，并且 DP 必须循环处理索引而不破坏一致性。 这就是为什么所有转换都明确使用`(i+1) % n`。 

## 工作示例

 ### 示例 1

 输入：```
3 3
1 3 1
```我们追踪净收益`g = sum([a[i]==h[i+1]] - [a[i]==h[i]])`。 

| 我| h[i], h[i+1] | h[i], h[i+1] 选择贡献| dp 状态 |
 | ---| ---| ---| ---|
 | 1 | (1,3) | +1, -1, 0 | 分布扩大 |
 | 2 | (3,1) | 对称| 分布扩大 |
 | 3 | (1,1) | 特殊情况| 添加倾斜 |

 处理完所有位置后，仅对状态求和`g > 0`产量`9`。 

这表明即使局部贡献经常取消，对称位置仍然允许正的净增益配置。 

### 示例 2

 输入：```
4 2
1 2 1 2
```这里每对相邻的对都不同，因此每个位置都贡献了平衡的三路分割。 

| 我| 一对| +1 个选择 | -1 个选择 | 0 个选择 |
 | ---| ---| ---| ---| ---|
 | 1 | (1,2) | 1 | 1 | k-2 |
 | 2 | (2,1) | 1 | 1 | k-2 |
 | 3 | (1,2) | 1 | 1 | k-2 |
 | 4 | (2,1) | 1 | 1 | k-2 |

 DP 累加所有序列并过滤那些具有正总不平衡的序列。 

这证实了该算法可以正确处理交替结构，其中贡献在局部抵消但在全局累积。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n^2) | O(n^2) | n 个位置上的 DP 和 O(n) 平衡范围 |
 | 空间| O(n^2) | O(n^2) | DP 状态的存储 |

 约束条件允许`n ≤ 2000`，所以一个`O(n^2)`解决方案在时间和内存上都是可以接受的。 可能的平衡值的字母表的边界为`[-n, n]`，确保 DP 状态空间保持二次方。

 ## 边缘情况

 对于`n = 1`，旋转不会改变数组，因此没有任何配置可以在旋转后产生严格更高的分数。 该算法正确返回零，因为净增益始终为零并且没有状态超过阈值。 

制服用`h`，每个位置的行为都相同，并且 DP 累积对称贡献。 正确的处理取决于正确区分值何时与一对的两个端点匹配，这种情况在这种情况下随处可见，并增加了中性转换的权重。
