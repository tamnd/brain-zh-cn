 ## 解决方案
 ## 问题理解

 我们得到了一系列括号，并被允许应用反转任何连续段的操作。 在应用一系列这样的反转之后，我们必须获得一个有效的平衡括号序列，但具有非常具体的结构：当我们从左到右扫描它时，我们想要精确地`k`前缀本身就是一个完整的平衡括号序列的位置。 

解释需求的另一种方法是查看正确的括号序列如何分解。 每个平衡序列都可以唯一地分为“原始块”，其中每个块是平衡的最小前缀，并且内部不包含较早的平衡前缀。 本身是有效完整序列的前缀的数量正是此类基元块的数量。 所以任务是将给定的字符串转换为任何有效的括号序列`k`原始组件。 

我们保证输入有`n/2`开放和`n/2`右括号，所以解决方案总是存在的。 

该操作非常强大：反转任何子字符串使我们能够有效地任意重新定位字符，但只能通过段反转。 由于我们最多可以`n`运营和`n ≤ 2000`，我们可以提供一种建设性的策略，逐步修复字符串，而不是依赖于复杂的优化。 

当贪婪地考虑平衡前缀时，会出现一种微妙的边缘情况。 天真的尝试可能会尝试通过使前缀有效来在本地“修复平衡”。 但这会失败，因为局部修正可能会在以后破坏结构。 另一种失败模式是尝试直接控制前缀平衡而不构造显式目标序列，这变得很难与反转操作协调。 

正确的观点是在构建时停止考虑前缀平衡，而是先确定最终的目标形状，然后将初始字符串转化为目标形状。 

## 方法

 一个强力的想法是将每个状态视为一个节点并尝试所有子串反转，使用 BFS 搜索有效的最终配置。 每个州大约有`O(n^2)`转换，并且状态空间呈指数分布`n`。 即使是为了`n = 200`，这变得完全不可行。 

关键的见解是我们根本不需要搜索。 我们可以明确地构造一个有效的最终序列`k`原始块，然后确定性地将初始字符串转换为它。 

任何有效序列的结构`k`常规前缀位置很简单。 我们想要的正是`k`前缀完全平衡的时间。 最干净的建筑是创造`k-1`最小块`"()"`，后跟一个包含剩余括号的大平衡块：```
"()" * (k - 1) + "(" * a + ")" * a
```在哪里`a = n/2 - (k - 1)`。 

这准确地保证了`k`原始组件：每个`"()"`贡献一个，最后一个大块再贡献一个。 

一旦我们修复了这个目标字符串，剩下的问题就减少到使用子字符串反转将字符的一种排列转换为另一种排列。 这可以从左到右贪婪地完成：通过在字符串中稍后找到每个字符并反转该段以将其向前移动，将每个字符放置在正确的位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 BFS 遍历状态 | 指数| 指数| 太慢了 |
 | 构建目标+贪婪逆转| O(n²) | O(n) | 已接受 |

 ## 算法演练

 我们首先构造一个目标字符串，然后将输入转换为它。 

### 1. 构建目标配置

 我们形成一个字符串，其中包含`k-1`的副本`"()"`，然后是剩余的块`'('`进而`')'`。 

这准确地保证了`k`原始平衡分量，因为每个`"()"`是一个独立的原语，最后一个块是一个大的原语。 

### 2. 将输入贪婪地转换为目标

 我们从左到右处理位置。 

对于每个位置`i`，如果当前字符已经与目标匹配，我们什么都不做。 否则，我们向前搜索一个位置`j`这样`s[j]`等于所需的字符`i`。 

然后我们反转子串`[i, j]`。 这会将所需的角色带到适当的位置`i`同时保留该段中的所有字符，只是重新排序。 

重复此步骤，直到整个字符串与目标匹配。 

### 3.输出操作

 每一次逆转都会被记录下来。 操作次数最多为`n`因为每一次操作都会永久固定至少一个位置。 

### 为什么它有效

 每一步`i`，一旦我们固定位置`i`，我们再也不会碰它了。 这是因为后来的逆转仅适用于严格大于的仓位`i`。 因此，正确性降低为确保在步骤`i`，我们总能在后缀中找到所需的字符，这是有保证的，因为我们只是排列一组相同的括号。 

最终的字符串与目标完全匹配，并且目标被构造为具有精确的`k`常规前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = list(input().strip())

    # build target
    half = n // 2
    left_blocks = k - 1

    target = []
    target.extend("()" * left_blocks)
    remaining = half - left_blocks
    target.extend("(" * remaining)
    target.extend(")" * remaining)

    target = list(target)

    ops = []

    for i in range(n):
        if s[i] == target[i]:
            continue

        j = i
        while j < n and s[j] != target[i]:
            j += 1

        # reverse [i, j]
        s[i:j+1] = s[i:j+1][::-1]
        ops.append((i + 1, j + 1))

    print(len(ops))
    for l, r in ops:
        print(l, r)

if __name__ == "__main__":
    solve()
```目标的构建是核心设计选择。 一旦该结构被固定，算法的其余部分就只是一个受控的排列过程。 反转操作仅用作模拟交换的工具，同时保持实现简单并在允许的操作计数之内。 

一个微妙的实现细节是，我们在构建字符串时永远不需要显式跟踪平衡。 所有平衡约束都被编码到最终目标中，因此正确性降低为纯字符串转换。

def run(inp: str) -> str:

    out_lines = []

        s = list(input().strip())

 ## 边缘情况

 一个重要的边缘情况是当`k = 1`。 在这种情况下，目标变成一个大的原始块，由排列为的所有括号组成`"(" * (n/2) + ")" * (n/2)`。 该算法仍然有效，因为没有`"()"`插入前缀块，贪婪放置只是构建一个完全嵌套的结构。 

另一种情况是当`k = n/2`，其中目标变为`"()"`重复`n/2`次。 这里每个块都是一个基元，因此每两个字符必须形成一对。 贪婪反转过程仍然会成功，因为每个所需的字符都可以独立地拉入到位，而不会影响早期的固定对。 

一个容易失败的场景是尝试在构建期间维持前缀有效性。 例如，如果我们试图在交换时贪婪地确保前缀平衡，我们可能会意外地引入超出的早期有效前缀`k`。 基于目标的构造通过结构性地而不是动态地编码有效前缀的确切数量，完全避免了这种情况。
