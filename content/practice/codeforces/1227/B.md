 ## 解决方案
 ## 问题理解

 给定一个非递减数组`q`，据称是由一些隐藏的排列产生的`p`通过取前缀最大值。 在每个位置`i`,`q[i]`等于第一个值中的最大值`i`的元素`p`。 

任务是重建任何有效的排列`p`尺寸的`n`其前缀最大数组匹配`q`，或确定不存在这样的排列。 

一个关键的解释是`q`告诉我们排列中何时出现新的历史高点。 每当`q[i] > q[i-1]`， 位置`i`必须引入一个以前没有出现过的新的最大值。 每当`q[i] == q[i-1]`， 位置`i`不能引入任何大于当前最大值的东西； 它必须填充一些未使用的较小值。 

这些约束允许测试用例中最多包含 100,000 个总元素。 这立即排除了任何尝试通过暴力或回溯进行排列的解决方案。 我们需要每个测试用例的线性构造。 

当值增加时，会出现微妙的失败情况`q`但这种增加跳过了应该早先出现的数字。 例如，如果`q = [1, 3]`，值`2`在不破坏前缀最大条件的情况下，无处可放置。 这是核心可行性约束。 

另一个重要的边缘情况是重复相同的最大值。 如果`q[i]`重复一遍，它不会对最大增长引入新的约束，但它需要仔细跟踪未使用的数字，以便我们不会意外分配一个会错误地增加前缀最大值的数字。 

## 方法

 一个蛮力的想法是尝试构造排列并检查它们的前缀最大值是否匹配`q`。 对于每个位置，我们可以尝试所有未使用的数字并验证生成的前缀最大数组。 这需要粗略地探索`n!`最坏情况下的排列，这在超出范围之外是完全不可行的`n = 10`。 

问题的结构表明了一种更直接的构造。 数组`q`仅当出现新的最大值时才会改变。 所以我们可以想到`q`定义最大值固定的“分段”，以及引入新最大值的偶尔跳跃。 

每当`q[i]`增加，该值必须恰好放置在位置`i`。 否则，我们将无法创建该大小的新前缀最大值。 这会立即修复数组严格增加的所有位置。 

剩下的位置是那些`q[i] == q[i-1]`。 这些位置必须填充小于当前前缀最大值的值，重要的是，所有小于当前最大值的未使用数字最终必须出现在首次建立该最大值之前的某个位置。 这导致了一种贪婪的策略：维护一个未使用的数字池，并在尊重前缀最大约束的同时尽可能晚地分配它们。 

我们必须检查的唯一可行性条件是在每一步中`q`增加自`q[i-1]`到`q[i]`，从前一个最大值 + 1 到`q[i] - 1`必须已在未使用的池中可用； 否则无法施工。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们在构建排列的同时跟踪哪些数字已被使用并维护可用数字池。 

1. 我们初始化一个布尔数组或设置为跟踪使用过的数字，并准备一个列表或堆栈，其中包含所有数字`1`到`n`尚未放置的。 该池代表仍然可以分配给不需要新最大值的位置的值。 
2.我们维护一个变量`current_max = 0`，表示迄今为止排列中的最大值。 这是必要的，因为放置在“平坦”段中的任何数字都不能超过它。 
3.我们迭代位置`i`从`1`到`n`。 如果`q[i] > q[i-1]`，然后定位`i`是强制放置的`q[i]`。 我们必须将此值放在这里，因为这是前缀最大值第一次增加到该值。 
4. 设置新的最大值之前`q[i]`，我们验证范围内的所有值`(current_max + 1 ... q[i] - 1)`仍然未使用。 如果这些数字中的任何一个已经放置在较早的位置，则该构造无效，因为我们需要它们在最大值增加之前出现。 如果它们未被使用，它们将在早期的平坦段中自然消耗。 
5. 什么时候`q[i] == q[i-1]`，我们分配仍然严格小于或等于的最大剩余未使用数字`current_max`。 这可以确保我们不会意外增加前缀最大值。 
6. 输入值后，我们将其标记为已使用并继续。 
7. 如果在任何时候都无法分配有效的数字（例如，没有未使用的数字≤ current_max），我们返回`-1`。 

### 为什么它有效

 该算法强制要求每次增加`q`正好对应于新引入的最大元素`p`。 在两次增加之间，我们只使用不会影响前缀最大值的数字，这保持了稳定性`q`。 不变量是在每个位置`i`，构造的前缀最大值等于`q[i]`，并且所有未使用的数字始终与未来的约束兼容，因为我们从不消耗支持以后增加所需的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        q = list(map(int, input().split()))
        
        used = [False] * (n + 1)
        res = [0] * n
        
        available = set(range(1, n + 1))
        
        ok = True
        current_max = 0
        
        for i in range(n):
            if i == 0:
                res[i] = q[i]
                used[q[i]] = True
                available.remove(q[i])
                current_max = q[i]
                continue
            
            if q[i] > q[i - 1]:
                if q[i] in used:
                    ok = False
                    break
                res[i] = q[i]
                used[q[i]] = True
                available.remove(q[i])
                current_max = q[i]
            else:
                # pick largest unused ≤ current_max
                found = False
                for v in range(current_max, 0, -1):
                    if not used[v]:
                        res[i] = v
                        used[v] = True
                        available.remove(v)
                        found = True
                        break
                if not found:
                    ok = False
                    break
        
        if not ok:
            print(-1)
        else:
            print(*res)

if __name__ == "__main__":
    solve()
```该代码跟踪哪些值已被使用，并在任何时候直接分配强制最大值`q`增加。 对于平坦段，它贪婪地选择不超过当前最大值的最大剩余值，这避免了过早引入新的最大值。 这`used`数组保证了唯一性，向后扫描确保了我们为未来的放置保留灵活性。 

一个微妙的实现细节是我们永远不需要`available`设置正确性，但它有助于保持与未使用的数字的一致性。 实际的决策逻辑完全依赖于`used`和`current_max`。

 ## 边缘情况

 一种边缘情况是数组以大于 1 的值开头，例如`q = [3, 3, 3]`。 该算法立即尝试放置`3`首先，但没有更小的值可用于填充较早的位置而不违反前缀最大值约束。 这会正确失败，因为不变量需要所有值`1`到`q[0]-1`在第一个最大值建立之前出现，这是不可能的`q[0] > 1`。 

另一个边缘情况是当`q`例如，大幅跳跃的增加`q = [1, 10]`。 在这里，价值观`2`通过`9`必须在最大值变为之前放置在第一个位置`10`，这是不可能的，因此算法正确地拒绝了它。 

最后的边缘情况是一个完全平坦的数组，例如`q = [1, 1, 1, 1]`。 该算法放置`1`在第一个位置，则后续位置没有有效值，导致立即拒绝，除非`n = 1`。
