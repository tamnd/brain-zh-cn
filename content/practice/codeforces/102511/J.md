 ## 解决方案
 ## 问题理解

 每个球员都有一份分数清单，每个洞一个分数。 应用未知限制后记住的值`l`不是原来的分数`x`， 但`min(x, l)`。 对于固定的`l`，每个玩家通过将所有大洞得分替换为`l`。 总数越小越好，玩家的排名是调整后的总数不大于自己的玩家数量。 

我们的任务不是找到一个特定的极限。 相反，我们可以选择`l`这为每个玩家提供了尽可能最好的位置，我们必须输出可达到的最低排名。 

玩家人数最多为 500 人，洞数最多为 50 个。直接模拟超过可能的限制是不可能的，因为分数可能大到`10^9`。 有用的限制是每个玩家的得分值较少。 玩家的调整分数仅在以下情况下发生变化：`l`达到原始洞分数之一，因此有趣点的总数受到以下限制：`p * h`，而不是分数值的大小。 

棘手的部分是，一名玩家的最佳限制可能介于两个分数值之间。 仅检查输入中出现的限制的解决方案可能会错过最佳值。 另一个常见的错误是分别针对每个对手找到最佳限制。 相同`l`必须同时提高玩家对抗所有对手的位置。 

例如：```
2 1
5
10
```如果我们只测试原始值，我们会检查`l = 5`和`l = 10`。 在`l = 5`，两名玩家的得分均为 5，因此第一位玩家的排名为 2。`l = 10`，分数分别为 5 和 10，因此第一个玩家的排名为 1。答案是 1。这个案例说明了为什么限制本身很重要，而不仅仅是限制之间的间隔。 

另一个边界情况是：```
2 2
100 100
1 1
```第一个玩家永远无法击败第二个玩家。 对于每一个积极的`l`，第二个玩家的总得分最多为 2，而第一个玩家的总得分至少为 2，并且绝对不会更好。 正确的排名是：```
2 1
```一个粗心的实现，假设每个玩家最终都能变得更好`l`在这里生长会失败。 

## 方法

 最直接的方法是尝试每一个可能的值`l`，计算所有调整后的分数，对选手进行排序，并记录最好的名次。 这是正确的，因为它确实会检查所有可能的游戏调整。 然而，`l`可以大到`10^9`，所以这是行不通的。 

更好的观点是两两比较球员。 修复一个播放器`i`。 如果我们知道的间隔`l`在哪里`i`击败另一位玩家`j`，那么排名为`i`当在相同限度下击败的对手数量尽可能多时是最好的。 

对于两个玩家来说，他们的分数差是分段线性函数。 公式唯一改变的地方是这两名选手的洞成绩。 在两个连续的此类值之间，每个孔要么已经被封顶，要么仍然等于`l`，所以总分是线性函数`l`。 这意味着我们可以扫描重要范围，准确确定玩家所在的位置`i`变得比玩家更好`j`，并存储这些间隔。 

在收集了所有对手的所有间隔后，剩下的问题是找到覆盖相同整数值的最大间隔数`l`。 这是使用开始和结束事件的标准扫描线问题。 

蛮力方法之所以有效，是因为对于固定限制，得分函数很简单，但由于可能的限制太多，所以会失败。 分数函数是分段线性的观察结果将无限搜索空间减少到一个小的间隔集合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(限制数 * p * h) | O(p) | 太慢了|
 | 最佳 | O(p²h log(ph)) | O(ph) | 已接受 |

 ## 算法演练

 1. 对于每个玩家`i`，假设我们想知道该玩家的最佳排名。 我们会数一下还有多少其他玩家`i`可以严格击败某些共同价值`l`。 
2.对于每个对手`j`，构造极限区间，其中玩家`i`调整后的总得分比玩家小`j`。 
3. 为了构建这些区间，收集属于玩家的所有洞得分`i`和`j`。 这些值将正整数划分为两个调整后的分数均为线性函数的范围。 
4. 在每个范围内，计算两个玩家之间的线性差异。 由于差异具有以下形式`a*l+b`，我们可以找到它为负数的精确整数部分。 这些整数是限制，其中`i`节拍`j`。 
5. 将生成的间隔添加到扫描线结构中。 开始事件会增加被击败的对手的数量，而间隔结束后的事件会减少被击败的对手的数量。 
6、处理完所有对手后，同时活跃区间的最大数量为被击败的玩家的最大数量`i`。 最好的排名是`p - maximum_beaten`。 

为什么它有效：

 对于任何固定的对手，两个玩家之间的比较仅在得分值或两个线性函数交叉的地方发生变化。 区间构造准确地找到了第一个玩家更好的所有限制。 然后，扫描线检查这些间隔所代表的每个可能的限制，并找到可以同时击败的对手的最大数量。 由于排名恰好是未击败的玩家数量加上玩家本身，因此计算出的值很小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def adjusted_diff_coeff(a, b, x):
    m = 0
    c = 0
    for u, v in zip(a, b):
        if x < u:
            m += 1
        else:
            c += u
        if x < v:
            m -= 1
        else:
            c -= v
    return m, c

def intervals(a, b):
    pts = sorted(set(a + b))
    segs = []

    if pts[0] > 1:
        segs.append((1, pts[0] - 1))
    for x in pts:
        segs.append((x, x))
    for x, y in zip(pts, pts[1:]):
        if x + 1 <= y - 1:
            segs.append((x + 1, y - 1))
    segs.append((pts[-1] + 1, None))

    ans = []

    for l, r in segs:
        m, c = adjusted_diff_coeff(a, b, l)

        if r is None:
            if m == 0:
                if c < 0:
                    ans.append((l, None))
            elif m < 0:
                ans.append((l, None))
            continue

        if l == r:
            if m * l + c < 0:
                ans.append((l, l))
            continue

        if m == 0:
            if c < 0:
                ans.append((l, r))
        elif m > 0:
            # m*x+c < 0
            hi = (-c - 1) // m
            if hi >= l:
                ans.append((l, min(r, hi)))
        else:
            # m*x+c < 0, multiply by -1
            lo = c // (-m) + 1
            if lo <= r:
                ans.append((max(l, lo), r))

    return ans

def solve():
    p, h = map(int, input().split())
    scores = [list(map(int, input().split())) for _ in range(p)]

    res = []

    for i in range(p):
        events = []
        for j in range(p):
            if i == j:
                continue
            for l, r in intervals(scores[i], scores[j]):
                events.append((l, 1))
                if r is not None:
                    events.append((r + 1, -1))

        events.sort()
        cur = 0
        best = 0
        k = 0
        while k < len(events):
            pos = events[k][0]
            while k < len(events) and events[k][0] == pos:
                cur += events[k][1]
                k += 1
            best = max(best, cur)

        res.append(str(p - best))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```主函数一次处理一个玩家，因为一个玩家的排名不会影响另一玩家的间隔。 这`intervals`函数处理一对玩家并返回第一个玩家赢得比较的所有限制。 

帮手`adjusted_diff_coeff`计算固定段上分数差的线性表示。 一个洞要么提供一个恒定的原始分数，要么提供一个副本`l`，所以整个差值总是可以写成`m*l+c`。 

间隔代码分隔三种情况。 单个点检查一个精确的限制。 有限线段求解线性不等式。 无限尾部单独处理，因为没有上端点。 即使分数达到Python整数也可以避免溢出`10^9`。 

扫描使用`r + 1`用于结束事件，因为间隔包含整数限制。 忘记这种转换是一种常见的差一错误。

 对于第一个样本：```

```考虑玩家 1。 

| 对手| 玩家 1 的获胜限制 | 迄今为止最大的击败|

 | 玩家 3 | 限制，其中分数 1 < 分数 3 | 2 |

 玩家 1 可以在相同的限制下击败两个对手，因此最好的排名是`3 - 2 = 1`。

 | 玩家| 击败最多对手| 最低等级 |

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(p²h log(ph)) | 每对玩家创建 O(h) 事件，并且每个玩家对所有对手间隔执行扫描。 |
 | 空间| O(ph) | 仅存储当前玩家的事件和得分矩阵。 |

 和`p = 500`和`h = 50`，成对比较的数量是可控的。 该算法从不依赖于分数的大小，只依赖于存在多少分数变化。

 ## 边缘情况

 第一个边缘情况是最佳限制不是原始分数之一。 对于输入：```
2 1
5
10
```间隔`(5,10)`更改比较，算法会对其进行检查，因为评分函数在断点之间是线性的。 

第二个边缘情况是一个玩家永远无法击败另一个玩家。 为了：```
2 2
100 100
1 1
```差分函数永远不会为负。 间隔生成器不产生获胜间隔，因此扫除对第一个玩家的击败对手进行零次计数，对第二个玩家进行一次击败对手计数。 

第三种情况是许多相同的分数：```
3 1
7
7
7
```每对比较总是相等的，因此没有玩家有获胜区间。 击败对手的最大数量为零，每个等级变为3，符合分数相同的定义。
