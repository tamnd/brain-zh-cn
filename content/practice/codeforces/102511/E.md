 ## 解决方案
 ## 问题理解

 路线图是一个无向图。 死胡同标志属于街道的方向，而不属于街道本身。 有方向的街道`u -> v`开车后需要一个标志`u`到`v`，最终没有办法返回到`u`没有立即返回同一条街道。 

思考这个问题的一种直接方法是，标志仅出现在通向图表中无法逃回的部分的街道上。 移除桥后，一侧可能是一棵树，挂在图的其余部分上。 这样一棵悬挂的树内的每个边缘在完整的放置中都是一个死胡同，但其中许多标志是不必要的，因为靠近核心的另一个死胡同标志已经警告了驾驶员。 

输入最多可以包含`500000`顶点和`500000`边缘。 重复搜索路径、检查连通性或处理每对边的算法会太慢。 对于这个尺寸，我们需要一个线性或几乎线性的解决方案，因为即使`O(n log n)`已经接近实用极限了。 

主要棘手的情况不是明显的叶子。 本身就是树的图与具有循环核心的图的行为不同。 

例如：```
3 2
1 2
2 3
```正确的输出是：```
2
1 2
3 2
```每条街道都是一座桥，但只有从树叶开始的两个方向幸存下来。 标志`2 -> 1`会是多余的，因为进入后`3 -> 2`，驾驶员可以到达`2`然后输入`2 -> 1`。 

另一个例子：```
4 4
1 2
2 3
3 1
1 4
```正确的输出是：```
1
1 4
```三角形是一个循环核。 唯一的死胡同是附着在该核心上的叶子，有用的标志从核心指向叶子。 

一个常见的错误是输出每个桥方向。 这会在连接到核心的树内产生冗余标志，并且无法满足最小化要求。 

## 方法

 暴力破解可以从定义开始。 对于每个有向边，删除立即掉头的限制并运行图搜索以查看起始顶点是否可以再次到达。 这可以正确识别每个死胡同方向。 之后，可以对每对标志进行另一次搜索，以删除多余的标志。 

问题是搜索次数太大。 和`m = 500000`，检查每条边已经花费了大约`O(m(n+m))`在最坏的情况下，也远远超出了极限。 

有用的观察结果是，死胡同正是从每个连接组件的循环部分悬挂的树。 循环部分在重复删除叶子的过程中幸存下来。 在修剪过程中移除的所有东西都属于附着在剩余核心上的树。 

这就把问题变成了一个简单的图形剥离过程。 我们反复删除一级顶点。 当循环核心保留时，从核心顶点到移除顶点的每条边都是必要的符号。 当整个组件消失时，该组件就是一棵树，只有原来的叶子才应该产生信号。 

剥离的想法避免了明确地寻找桥梁。 它直接识别与最终答案相关的结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m(n+m)) | O(m(n+m)) | O(n+m) | 太慢了|
 | 最佳 | O(n+m) | O(n+m) | 已接受 |

 ## 算法演练

 1. 存储图并计算每个顶点的度数。 将每个度数最多为 1 的顶点放入队列中。 
2. 反复从队列中删除顶点。 将它们标记为已删除并降低其邻居的度数。 每当邻居成为叶子时，将其添加到队列中。 

经过这个过程留下的顶点正是属于循环核的顶点。 树没有核心，因为剥皮最终会删除每个顶点。 
3. 如果仍有一些顶点，请检查每条原始边。 每当一个端点位于核心且另一端点已移除时，输出从核心端点到已移除端点的方向。 

这些是唯一非冗余的标志，因为进入悬挂的树是司机无法再返回的地方。 
4. 如果没有剩余顶点，则每个连通分量都是一棵树。 检查原始图并输出起始端点具有原始度数 1 的每条边。 

叶子在进入其唯一的边缘后就没有其他方式离开，而从内部树顶点开始的每个标志都被更靠近叶子的标志覆盖。 
5. 在打印之前，先按第一个端点排序结果对，然后按第二个端点排序。 

为什么它有效：

 剪枝过程准确地保留了可以参与循环的顶点。 任何删除的顶点都属于附加到核心或另一个删除的顶点的树。 在非树组件中，进入此类树的第一条边是唯一重要的标志，因为在通过第一个标志后可以到达每个更深的标志。 在树组件中，没有核心，因此唯一没有其他传出路由的顶点是叶子。 因此，生成的集合包含所有必需的警告，没有多余的警告。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    adj = [[] for _ in range(n)]
    edges = []
    deg = [0] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        edges.append((a, b))
        adj[a].append(b)
        adj[b].append(a)
        deg[a] += 1
        deg[b] += 1

    removed = [False] * n
    q = deque()

    for i in range(n):
        if deg[i] <= 1:
            q.append(i)

    while q:
        u = q.popleft()
        if removed[u]:
            continue
        removed[u] = True
        for v in adj[u]:
            if not removed[v]:
                deg[v] -= 1
                if deg[v] == 1:
                    q.append(v)

    ans = []

    if any(not x for x in removed):
        for a, b in edges:
            if removed[a] != removed[b]:
                if not removed[a]:
                    ans.append((a + 1, b + 1))
                else:
                    ans.append((b + 1, a + 1))
    else:
        for a, b in edges:
            if len(adj[a]) == 1:
                ans.append((a + 1, b + 1))
            if len(adj[b]) == 1:
                ans.append((b + 1, a + 1))

    ans.sort()

    out = [str(len(ans))]
    for a, b in ans:
        out.append(f"{a} {b}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```代码的第一部分构建图表并保留原始度数。 仅在整个图是树的特殊情况下才需要原始度数，因为剥离后所有顶点的度数为零。 

基于队列的删除是该算法的核心。 每个顶点最多进入队列一次，并且每条边都会被检查恒定次数，从而给出线性复杂度。 

输出结构将两种情况分开。 如果存在核心，则答案由核心和删除的树之间的边界边形成。 如果不存在核心，则该图是森林，只有原始叶子贡献符号。 

需要最终排序，因为问题指定了打印对的字典顺序。

 ## 边缘情况

 对于树组件，该算法会删除每个顶点。 缺少核心会触发仅叶规则。 在路径示例中：```
3 2
1 2
2 3
```顶点`1`和`3`从一级开始，所以最终的扫描输出`1 2`和`3 2`。 中间的顶点永远不会出现，因为从那里开始的任何一个符号都已经被叶子符号覆盖了。 

对于具有循环和附加树的图，剪枝后剩余的顶点形成核心。 在：```
4 4
1 2
2 3
3 1
1 4
```顶点`4`当顶点被移除时`1,2,3`存活。 唯一的边界边是`1-4`，所以算法打印`1 4`。 

对于孤立的顶点，度数为零。 他们进入剥皮队列，但没有边缘，因此他们从不贡献标志。 答案仍然是空的，这是正确的，因为没有街道可供标记。
