 ## 解决方案
 ## 问题理解

 该问题要求我们查看数组中的每个有序位置对并计算两个选定值的总和。 这对`(i, j)`不同于`(j, i)`，所以正好有`N²`可能的金额。 我们需要找到`K`- 所有这些总和中的第最小值。 

输入包含多个测试用例。 对于每个测试用例，我们收到数组的大小、所需的位置`K`在对和的排序列表中，以及数组本身。 输出是出现在位置的值`K`如果我们显式生成所有对和并对它们进行排序。 

硬版本允许`N`达到`100000`和`K`可以大到`N²`。 直接建造的话，需要创造高达一百亿的资金，这远远超出了记忆和时间所能容纳的范围。 即使检查每一对也需要`O(N²)`操作，并与`N = 100000`那是关于`10^10`对检查，因此任何解决方案都必须避免枚举对。 

这些值可以是负数并且可以大到`10^9`以绝对值表示。 这意味着答案可以小到`-2 * 10^9`或大至`2 * 10^9`，因此搜索空间足够小，可以进行二分搜索。 测试用例的数量也很少，这使得`O(N log C)`风格解决方案，其中`C`是取值范围。 

一些边缘情况可能会破坏更简单的实现。 考虑：```
1
2 4
1 1
```这四项总和分别是`2, 2, 2, 2`，所以答案是`2`。 一种只考虑配对的方法`i < j`会错误地只看到一对并失败，因为问题计算的是有序对。 

另一种情况是：```
1
3 2
-5 0 10
```总和是`-10, -5, 5, -5, 0, 10, 5, 10, 20`。 第二小的是`-5`。 假设数组已排序并在位置上使用二分搜索而不首先排序的实现可能会错误计数。 

最后一个棘手的情况是：```
1
3 7
1 2 100
```排序后的总和是`2, 3, 3, 4, 101, 101, 102, 102, 200`，所以答案是`102`。 一个常见的错误是计算总和严格小于候选值而不是小于或等于候选值的对，这会在存在许多相等总和时改变二分搜索结果。 

## 方法

 最直接的方法是生成所有可能的对。 对于每个索引`i`，我们可以配对`a[i]`与每一个`a[j]`， 店铺`a[i] + a[j]`，对结果列表进行排序，并返回位置上的元素`K`。 

这是正确的，因为它确实创建了问题所描述的精确多重集。 然而，它需要`N²`记忆和`N² log(N²)`排序的时间。 和`N = 100000`，生成的和的数量是`10^10`，所以该方法是不可能的。 

关键的观察是我们不需要实际的排序总和列表。 我们只需要知道在哪里`K`-th 值所在。 如果我们可以回答“有多少对总和小于或等于 X？”的问题，那么我们可以二分查找最小的`X`其计数达到`K`。 

对原数组进行排序后，计数变得高效。 对于每个第一个元素`a[i]`，我们需要知道有多少个第二个元素满足：```
a[i] + a[j] <= X
```这相当于：```
a[j] <= X - a[i]
```因为数组是有序的，所以有效的个数`j`可以通过上限二分查找找到值。 将所有这些计数相加`i`给出不超过的对和的数量`X`。 

蛮力之所以有效，是因为它直接构造有序列表，但在以下情况下会失败：`N`很大。 通过值搜索可以找到答案，结合使用排序数组进行快速计数，可以将问题从每个测试用例的数十亿对减少到大约一百万个操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N² log N) | O(N² log N) | O(N²) | 太慢了 |
 | 对答案进行二分搜索 | O(N log N log A) | O(N log N log A) | O(N) | 已接受 |

 ## 算法演练

 1. 对数组进行排序。 排序允许我们使用二分搜索来计算有多少元素低于阈值。 
2. 设置答案的二分查找范围。 最小可能对和是最小元素与其自身之和，最大可能对和是最大元素与其自身之和。 
3. 对于中间值`mid`,计算最多有多少个有序对有和`mid`。 对于每一个`a[i]`，找到最大的索引`j`在哪里`a[j] <= mid - a[i]`。 有效的第二位置的数量就是直到该索引的元素的数量。 
4. 如果计数至少为`K`，答案最多是`mid`，因此将搜索范围移至左半部分。 否则，金额太少就足够小，因此请移至右半部分。 
5. 当搜索区间包含一个值时，该值是其对和的个数至少为的最小数`K`。 

计数函数起作用的原因是每个有序对选择一个固定的第一个位置。 对于该位置，排序后的数组准确地告诉我们第二个位置有多少种选择可以使总和足够小。 添加这些独立计数涵盖了所有`N²`只订购了一次。 

## Python 解决方案```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve_case(n, k, a):
    a.sort()

    def count_leq(x):
        total = 0
        for v in a:
            total += bisect_right(a, x - v)
        return total

    low = a[0] + a[0]
    high = a[-1] + a[-1]

    while low < high:
        mid = (low + high) // 2
        if count_leq(mid) >= k:
            high = mid
        else:
            low = mid + 1

    return low

def main():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        ans.append(str(solve_case(n, k, a)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```该解决方案首先对数组进行排序，因为后面的每个操作都取决于所排序的元素。 这`count_leq`函数实现了演练中的核心观察。 对于每个可能的第一个元素，`bisect_right`返回所有有效第二个元素之后的第一个位置，因此返回的索引正是有效选择的数量。 

二分搜索使用可能答案的包含范围。 即使对于 Python 中的负值，中点计算也能正确工作，因为整数除法向下舍入，但更新规则仍然保持答案保持在区间内的不变性。 

一个常见的实施错误是使用`bisect_left`而不是`bisect_right`。 计数需要等于限制的值，因为我们计算的总和小于或等于候选值。 使用错误的界限会忽略有效的对，并且可能将二分搜索移得太右。

 ## 边缘情况

 对于单元素情况：```
1
1 1
7
```唯一可能的一对是`(1,1)`, 给出总和`7`。 排序后的数组包含一个值，并且两个二分搜索边界都是`7`，因此算法立即返回正确的结果。 

对于重复值：```
1
3 9
5 5 5
```每个有序对给出`10`。 在计数过程中，每个搜索阈值都低于`10`给出零对，同时`10`给出所有九对。 二分查找找到第一个达到的阈值`K`。 

对于负值：```
1
4 1
-1000000000 0 3 9
```最小可能的总和是第一个元素与其自身相加，`-2000000000`。 答案搜索正是从那里开始，因此不需要对负数进行任何特殊处理。 

对于答案周围的重复总和：```
1
3 7
1 2 100
```第七小的总和是`102`。 计数函数可以正确处理相等的总和，因为它计算小于或等于中点的值。 如果中点是`102`，它会计算所有七个有效对，因此二分搜索会保留该值而不是越过它。
