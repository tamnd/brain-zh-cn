 ## 解决方案
 ## 问题理解

 我们得到一个小整数数组，并且允许我们重复选择所选段内的两个位置，并将后面索引处的值与前面索引处的值进行异或。 此操作在时间顺序上是单向的：来自较早位置的信息可以注入到任何较晚的位置，但不会向后流动。 

每个查询都会询问有关子数组的结构问题。 在该子数组内，我们可以在索引对之间执行任意数量的异或“加法”，并且我们想知道是否可以重新排列值（仅通过这些异或更新，而不是交换），以便最终序列严格递增。 

两个索引必须位于查询区间内的约束意味着每个查询都是 GF(2) 上的独立线性代数系统，仅限于该段。 

界限足够严格，以至于每个查询从头开始重新计算该段的基础的任何解决方案都太慢。 由于元素和查询总数高达 2⋅10^5，每个查询 O(n) 的方法会导致 O(nq)，这是不可行的。 预期的解决方案必须预处理信息，以便可以在大致对数或恒定时间内回答每个查询。 

当数组包含许多重复项或零时，会出现微妙的边缘情况。 例如，像 [1,1,1] 这样的段可能看起来很僵化，但该操作允许消灭元素（通过选择 i=j），产生零，然后在其他地方重建结构。 认为值在 XOR 下不变的天真的解释会错误地拒绝这种情况。 

另一个边缘情况是单调可行性，不取决于实际值，而是取决于段中存在多少个独立位。 具有相同多重集和的两个段可能表现不同，因为异或跨度很重要，而不是算术幅度。 

## 方法

 暴力破解视图是在允许的操作下模拟段的关闭。 从子数组开始，我们反复允许 a[j] := a[j] XOR a[i] 形式的转换，这实际上意味着我们可以采用任何较早的值并将其添加到后面的位置。 随着时间的推移，每个位置都可以成为先前位置的任意线性组合 (XOR)，因此可到达的值集就是前缀向量的线性跨度。 

对于每个查询，暴力尝试将重新计算所有可达向量或尝试对配置进行 BFS。 这立即爆炸：状态空间的段长度呈指数增长，因为每个元素都可以成为早期元素子集的任意异或。 

关键的观察结果是，该操作不依赖于组合意义上的顺序，而仅依赖于 GF(2) 的线性独立性。 在任何段内，我们都可以精确地生成其元素的线性跨度，并且该跨度之外的任何内容都是不可到达的。 

这将问题转换为基础问题：每个段对应一个向量空间。 “我们能否转换成严格递增序列”的问题变成“是否存在一个由 r−l+1 个不同值组成的序列，每个值都可以在跨度内表示，并按递增顺序排列”。 

一个关键的重新表述是，由于我们可以独立地分配任何可达值（通过使用 XOR 组合进行归零和重建），因此真正的约束是跨度是否包含足够的不同可表示值来构造严格递增的序列。 最低要求是我们可以产生至少 r−l+1 个不同的值，但更准确地说，我们需要确保我们可以生成一个集合，其最小可能的构造不会强制排序发生冲突。

决定性的见解是 XOR 运算使我们能够完全控制段的线性基础。 段的可表示空间由其线性基决定，形成严格递增序列的唯一障碍是基是否“足够密集”以在按位排序约束下构造长度等于段大小的链。 这减少了跟踪 XOR 基础和每个段的派生结构不变量。 

一旦我们认识到所有可达值都是 GF(2) 上向量空间的元素，我们就可以预处理前缀上的线性基础结构，并通过合并基础来回答查询。

 ## 算法演练

 我们使用线段树或稀疏可合并结构在子数组上维护线性异或基础。 每个节点存储最多 20 个向量的基，因为值小于 2^20。 

1. 构建一棵线段树，其中每个节点存储其区间的线性基础。 叶节点包含等于 a[i] 的单个向量。 内部节点通过将向量从一个碱基插入另一个碱基来合并两个碱基。 

合并过程是对 GF(2) 的高斯消去，确保我们保持独立性。 
2. 对于查询 [l, r]，通过组合线段树中的 O(log n) 个节点来提取该线段的合并基础。 这产生了子阵列的完整线性基础。 
3. 计算该基的维数，将其称为 d。 这告诉我们该段中存在多少个独立方向。 
4. 将 d 与段长度 k = r − l + 1 进行比较。如果 d 足够大以支持 XOR 闭包下的 k 个不同的可表示值，我们继续； 否则，回答“否”。 
5. 关键的结构检查是跨度必须能够生成 k 个严格递增值的链。 由于 d 维的 XOR 空间包含 2^d 个不同的值，因此可行性简化为检查 2^d ≥ k 是否存在，但这只是必要的，而不是充分的。 
6. 更严格的条件来自观察，只要空间有足够的自由度以避免强制相等约束，我们总是可以构造一个基数缩减序列，以递增的顺序分配不同的值。 在这个问题中，已知的表征完全崩溃到验证段基是否可以无冲突地表示所有前缀最小增量，这相当于使用该基检查在贪婪递增构造中插入数字是否成功。 
7. 我们贪婪地尝试通过维持一个运行目标值来构造一个严格递增的序列。 从 0 开始，对于每个位置，我们尝试使用基础找到严格大于前一个位置的最小可表示值。 如果在任何一步这是不可能的，我们就会拒绝。 

这种贪心算法之所以有效，是因为 XOR 基数允许我们通过对基向量进行位操作以递增顺序枚举可达值。 

### 为什么它有效

 不变的是，在任何点，维护的基础准确地表示处理段的可达线性跨度。 我们为递增序列构造的任何值都是该范围的成员。 贪心构造确保我们总是选择前一个值之上的最小可行值，如果这样的值不存在，则意味着跨度存在间隙，无法形成所需长度的严格递增链。 由于该基础充分描述了所有可达到的值，因此没有替代结构可以绕过这个差距。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXB = 20

def insert_basis(basis, x):
    for b in range(MAXB - 1, -1, -1):
        if (x >> b) & 1:
            if basis[b] == 0:
                basis[b] = x
                return
            x ^= basis[b]

def merge(a, b):
    res = a[:]
    for x in b:
        if x:
            insert_basis(res, x)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.tree = [[0] * MAXB for _ in range(2 * self.size)]
        for i in range(self.n):
            self.tree[self.size + i] = [0] * MAXB
            insert_basis(self.tree[self.size + i], arr[i])
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = merge(self.tree[2 * i], self.tree[2 * i + 1])

    def query(self, l, r):
        l += self.size
        r += self.size
        left = [0] * MAXB
        right = [0] * MAXB

        def add_to(dst, src):
            for x in src:
                if x:
                    insert_basis(dst, x)

        while l <= r:
            if l & 1:
                add_to(left, self.tree[l])
                l += 1
            if not (r & 1):
                add_to(right, self.tree[r])
                r -= 1
            l >>= 1
            r >>= 1

        return merge(left, right)

def can_make_increasing(basis, length):
    vals = []
    for i in range(length):
        cur = i
        for b in range(MAXB):
            if basis[b] and ((cur >> b) & 1):
                cur ^= basis[b]
        vals.append(cur)

    vals.sort()
    for i in range(1, length):
        if vals[i] <= vals[i - 1]:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        arr = list(map(int, input().split()))
        st = SegTree(arr)

        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1
            basis = st.query(l, r)
            length = r - l + 1
            print("YES" if can_make_increasing(basis, length) else "NO")

if __name__ == "__main__":
    solve()
```线段树存储每个区间的异或跨度的压缩表示。 每个节点都保持减少的基础，因此合并保持在 20 个向量的范围内。 查询结合了 O(log n) 个基，然后将它们简化为最终的规范基。 

功能`can_make_increasing`模拟向量空间是否可以通过从基中枚举候选缩减集来生成足够的有序不同值。 关键的实现选择是，我们将基向量视为所有可达值的生成器，并在规范生成的子集上测试排序的可行性。 

合并基数时必须小心：每次插入必须首先消除高位以保留简化形式。 任何偏差都会破坏正确性，因为它可能允许非最小表示，从而扭曲可达空间。 

## 工作示例

 ### 示例 1

 输入：```
n = 4, arr = [1, 2, 2, 1]
query = [1, 4]
```我们一步步打好基础。 

| 步骤| 细分 | 基础尺寸|
 | --- | --- | --- |
 | 1 | [1] | 1 |
 | 2 | [1,2]| 2 |
 | 3 | [1,2,2]| 2 |
 | 4 | [1,2,2,1] | 2 |

 该段的维度为 2，超过 4 个元素，但 XOR 组合允许创建多个值，包括 0、1、2、3。生成的空间足以构造长度为 4 的严格递增链，因此查询返回 YES。 

该迹线表明，重复不会降低可行性，除非它们使基础维度崩溃太多。 

### 示例 2

 输入：```
n = 3, arr = [1, 1, 1]
query = [1, 3]
```| 步骤| 细分 | 基础尺寸|
 | --- | --- | --- |
 | 1 | [1] | 1 |
 | 2 | [1,1]| 1 |
 | 3 | [1,1,1]| 1 |

 只存在一个独立的方向，因此空间中只包含两个值：0和1。不可能形成长度为3的严格递增序列。答案是否定的。 

此示例隔离了关键故障模式：线性独立性不足。

 ## 边缘情况

 长度为 1 的最小段始终会成功，因为除了单个元素之外不存在排序约束。 

完全恒定的段表明 XOR 基础崩溃到维度 1，这阻止了构建更长的严格递增序列，因为只能达到两个值。 

值是二的幂的段最大化了基础独立性，表明全秩段允许在构造递增序列时具有充分的灵活性。
