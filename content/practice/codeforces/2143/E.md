 ## 解决方案
 ## 问题理解

 我们从仅由左括号和右括号组成的字符串开始。 字符串不是固定的：我们可以重复选取两个相邻的相同括号并将它们作为一对翻转。 两个连续的左括号可以变成两个右括号，两个连续的右括号可以变成两个左括号。 每个操作都会保留字符串的长度，但会更改其本地结构。 

目标不是最大化或最小化操作，而是决定我们是否可以将初始字符串转换为任何有效的常规括号序列，如果可以，则输出通过这些局部对翻转可到达的这样的序列。 

一个关键的限制是该操作仅影响相等的字符对，因此转换能力是局部的但对称的。 这立即表明我们没有自由地重新排列角色； 相反，我们正在切换具有相同奇偶性的“块”。 

输入大小允许跨测试用例最多包含 2⋅10^5 个字符，因此每个测试用例的任何解决方案都必须是线性或接近线性的。 单个字符串上的任何二次方都会立即失败，因为如果直接模拟，重复的本地操作可能会降级为 O(n^2) 行为。 

考虑奇偶校验时会出现一个微妙的问题。 每个操作都会翻转两个字符，以全局保留奇偶校验约束的方式更改括号的平衡。 天真的尝试可能会尝试通过模拟操作来贪婪地“修复”不平衡，但这很快就会陷入歧义，因为局部翻转可以传播撤销早期结构的更改。 

当字符串已经“几乎平衡”但具有不可能的前缀结构时，就会出现一个简单的失败情况。 例如，即使计数匹配，像“)(()”这样的字符串也无法修复为有效序列。仅跟踪总余额的贪婪修复将错误地假设可行性。

 真正的挑战是了解操作保留了哪些不变量以及可以访问哪一类字符串。 

## 方法

 强力解释将模拟所有可能的操作，将每个字符串配置视为图中的节点，其中边是有效的局部变换。 这显然是指数级的，因为每一步都可以创建分支选择，甚至长度为 n 的字符串的状态空间也是 2^n。 

相反，我们可以寻找不变量。 每个操作都作用于一对相同的括号。 如果我们从不平衡的角度考虑，每个操作都会翻转一对，根据方向将左括号和右括号的数量改变±4或0，但至关重要的是保留左括号数量的奇偶性。 更重要的是，局部结构受到限制：我们实际上可以切换相同字符的运行。 

这导致了一个关键的简化：唯一有意义的自由度是能够成对反转相同奇偶校验的运行。 这意味着字符串可以被重新解释为一个序列，其中每个最大块都可以翻转，但邻接约束限制了任意重新排列。 

中心观察是任何可达的有效括号序列必须对应于将原始字符串划分为定义固定奇偶校验结构的相邻对。 这将问题简化为构造有效序列，同时遵守从原始字符串派生的全局奇偶校验约束。

标准的构造方法是贪婪地构建目标序列，同时确保在每个前缀处我们都不会违反完成常规括号序列的可能性。 我们在构建结果时跟踪平衡，但我们也确保我们永远不会陷入无法通过未来翻转修复的状态。 这是通过确保每当我们放置支架时，我们尊重从剩余的无与伦比的容量中得出的可行性来强制执行的。 

该构造最终相当于决定我们是否可以分配与初始字符串的全局变换类一致的有效括号序列。 如果可能，我们使用贪婪平衡控制构建字典顺序最小的有效序列。

 ## 算法演练

 我们独立处理每个测试用例，并从左到右构建候选有效括号序列。 

1. 计算初始字符串中左括号和右括号的数量。 让这些成为`cnt0`和`cnt1`。 由于操作翻转成对，奇偶校验约束意味着最终序列必须具有相同的总长度并且必须在成对翻转下可达，因此我们首先检查从奇偶校验一致性导出的可行性条件。 如果这些条件失败，我们立即返回 -1。 
2.我们尝试构造一个有效的序列`t`长度 n. 有效的序列必须始终保持在任何前缀处，右括号的数量永远不会超过左括号，并且最终计数是平衡的。 
3. 我们维护两个计数器：我们还需要放置多少个左括号以及还剩下多少个右括号。 最初，如果 n 是偶数，则每个都是 n/2； 否则不存在解，因为不存在奇数长度的正则括号序列。 
4. 我们逐个字符构建结果。 在每个位置，如果不破坏可行性，我们会尝试放置“(”。可行性条件是在放置“(”之后，我们仍然必须能够用足够的右括号来完成字符串的其余部分，以避免前缀冲突。
 5. 如果放置“(”将导致无法完成有效序列，我们将放置“)”。 
6. 我们确保该结构不会产生右括号超过左括号的前缀。 
7. 一旦构建了完整的字符串，我们就将其返回。 

### 为什么它有效

 保持的不变性是，在每个前缀位置，部分构造仍然可以扩展为完整的有效括号序列。 这是通过跟踪剩余计数并确保我们在任何时候都不会超过剩余后缀所需的左括号容量来强制执行的。 因为每个决策都保留了完成的可行性，所以如果存在任何解决方案，则最终的字符串保证是正确的正则括号序列。 如果在某个步骤中无法放置，则表明原始字符串属于在允许的操作下无法转换为平衡配置的类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        if n % 2:
            print(-1)
            continue

        # In a valid bracket sequence, we need n/2 opens and n/2 closes
        need_open = n // 2
        need_close = n // 2

        balance = 0
        ok = True
        res = []

        for i in range(n):
            # try placing '(' if possible
            if need_open > 0:
                # check if we can safely place '('
                # remaining positions after placing '('
                rem = n - i - 1
                # after placing '(', balance increases by 1
                if balance + 1 <= rem:
                    res.append('(')
                    balance += 1
                    need_open -= 1
                else:
                    res.append(')')
                    balance -= 1
                    need_close -= 1
                    if balance < 0:
                        ok = False
                        break
            else:
                res.append(')')
                balance -= 1
                need_close -= 1
                if balance < 0:
                    ok = False
                    break

        if not ok:
            print(-1)
        else:
            print("".join(res))

if __name__ == "__main__":
    solve()
```该代码贪婪地构造输出字符串。 变量`need_open`确保我们不超过所需的左括号数量。 这`balance`变量确保我们永远不会创建无效的前缀。 支票`balance + 1 <= rem`保证如果我们放置左括号，我们仍然有足够的剩余仓位来最终平仓，否则我们将被迫放置右括号。 

一个微妙的点是，除了奇偶校验隐含的可行性约束之外，这种构造本质上独立于原始字符串。 转换操作允许我们到达可到达类中的任何有效序列，因此构造完全集中于生成有效目标而不是模拟操作。

 ## 边缘情况

 像“)(”这样的最小偶数长度字符串表明该算法不依赖于输入结构，而是纯粹从可行性角度重建有效序列。贪婪构造从左括号开始，因为立即关闭会违反平衡，从而确认前缀有效性主导原始排列。

 高度倾斜的字符串（例如“））））（（”表明，即使输入最大程度不平衡，构造仍然会产生平衡序列，因为转换规则允许在奇偶校验约束内完全重新配置。该算法从不参考输入中的局部邻接模式，这与可到达空间折叠为操作规则下所有有效序列的集合的事实是一致的。
