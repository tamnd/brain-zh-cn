 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，表示 Vasya 在几天内的观察结果。 一个角色`'1'`表示当天收到信号，而`'0'`表示没有信号出现。 

任务是确定接收到的信号是否遵循完全规则的模式。 更准确地说，如果我们看看所有的位置`'1'`字符，连续位置之间的间隙必须全部相同。 如果每个间隔都相同，我们打印`"YES"`。 否则，我们打印`"NO"`。 

例如，在字符串中`001001001`，信号出现在位置`2`,`5`， 和`8`。 差距是`3`和`3`，所以图案是规则的。 

限制非常小。 字符串长度最多为`100`，这意味着即使是低效的解决方案也很容易在限制内运行。 具有大约的二次解`10^4`对于 2 秒的时间限制来说，操作是微不足道的。 尽管如此，这个问题主要是关于干净的实现和正确处理信号的位置。 

棘手的部分不是性能，而是正确解释信号之间的间距。 

考虑输入：```
5
10101
```信号位置是`0`,`2`， 和`4`。 差距是`2`和`2`，所以答案是`"YES"`。 

粗心的实现可能会计算信号之间的零并意外进行比较`1`和`1`，它恰好在这里起作用，但与索引逻辑混合时可能会变得混乱。 

另一个微妙的情况是连续信号出现时它们之间没有零：```
6
111000
```职位是`0`,`1`， 和`2`。 差距是`1`和`1`，所以答案是`"YES"`。 

假设每个信号之间必须至少有一个零的错误方法在这里会失败。 

更危险的边缘情况是只有某些间隔匹配时：```
7
1001001
```信号位置是`0`,`3`， 和`6`。 差距是`3`和`3`，所以答案是`"YES"`。 

但：```
7
1001010
```职位是`0`,`3`， 和`5`。 差距是`3`和`2`，所以正确答案是`"NO"`。 

如果我们只比较第一个和最后一个信号，我们可能会错误地得出该模式是规则的结论。 

## 方法

 最直接的暴力想法是收集包含以下内容的每个位置`'1'`，然后显式计算所有连续差异并比较它们。 

假设信号位置存储在数组中：```
pos = [2, 5, 8, 11]
```我们计算：```
5 - 2 = 3
8 - 5 = 3
11 - 8 = 3
```如果每个差异都等于第一个差异，则该模式是规则的。 

这种方法已经足够快了。 至多有`100`字符，即使重复扫描字符串也可以在限制内轻松工作。 

更简单的暴力变体可以尝试每个可能的间隔长度并验证所有信号是否都遵循它。 这仍然会通过，因为约束很小，但它执行了不必要的工作并使实现变得复杂。 

关键的观察是，问题仅取决于连续的之间的距离`'1'`职位。 一旦我们知道第一个间隔，后面的每个间隔都必须与它完全匹配。 别的都无所谓。 

这种观察将任务简化为对信号位置进行简单的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 已接受 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取整数`n`和二进制字符串。 
2. 遍历字符串并存储字符所在索引`'1'`。 

这些指数代表收到信号的天数。 
3. 计算前两个信号位置之间的距离。 

这成为后面的每一对都必须遵循的预期间隔。 
4. 迭代剩余的连续信号位置对。 

对于每一对，计算它们的指数之间的差异。 
5. 将当前差异与预期间隔进行比较。 

如果任何间隔不同，则打印`"NO"`立即，因为图案不规则。 
6. 如果所有间隔都匹配，则打印`"YES"`。 

### 为什么它有效

 该问题所需的唯一条件是连续信号之间的所有间隔相等。 该算法直接准确地检查该属性。 

令信号位置为：```
p₀, p₁, p₂, ..., pₖ
```该序列有效当且仅当：```
p₁ - p₀ = p₂ - p₁ = ... = pₖ - pₖ₋₁
```该算法计算第一个差异，并根据它验证后面的每个差异。 由于每个所需的间隔都被检查一次，因此算法不会错误地接受或拒绝序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

positions = []

for i in range(n):
    if s[i] == '1':
        positions.append(i)

gap = positions[1] - positions[0]

for i in range(2, len(positions)):
    if positions[i] - positions[i - 1] != gap:
        print("NO")
        break
else:
    print("YES")
```代码的第一部分读取输入并收集包含以下内容的每个索引`'1'`。 直接使用索引可以使逻辑简单，并避免对信号之间的零进行计数的混乱。 

变量`gap`存储信号之间的预期间隔。 由于该声明保证了至少三个`'1'`字符，访问`positions[1]`总是安全的。 

循环从索引开始`2`因为第一个间隔已经用作参考。 对于每个后来的信号，我们将其与前一个信号的距离与`gap`。 

这`for-else`这里的结构很方便。 如果循环结束而没有命中`break`，每个间隔都匹配，我们打印`"YES"`。 

一个常见的差一错误是将零计数与索引差异混合在一起。 例如，职位`0`和`3`相隔的距离为`3`，即使它们之间只有两个零。 直接使用索引可以避免这种歧义。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    positions = []

    for i in range(n):
        if s[i] == '1':
            positions.append(i)

    gap = positions[1] - positions[0]

    for i in range(2, len(positions)):
        if positions[i] - positions[i - 1] != gap:
            print("NO")
            return

    print("YES")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("8\n00111000\n") == "YES", "sample 1"

# custom cases
assert run("5\n10101\n") == "YES", "equal spacing"
assert run("7\n1001010\n") == "NO", "unequal spacing"
assert run("6\n111000\n") == "YES", "consecutive signals"
assert run("3\n111\n") == "YES", "minimum size"
assert run("10\n1001001001\n") == "YES", "large equal intervals"

 ## 边缘情况

 考虑连续信号的情况：```
6
111000
```位置数组变为：```
[0, 1, 2]
```预期差距为：```
1 - 0 = 1
```剩下的支票是：```
2 - 1 = 1
```所有间隔都匹配，因此算法会打印`"YES"`。 

这个例子证实了长度间隔`1`是完全有效的。 

现在考虑一个不规则的模式：```
7
1001010
```职位是：```
[0, 3, 5]
```预期差距为`3`。 

下一个间隔是：```
5 - 3 = 2
```自从`2 != 3`，算法立即打印`"NO"`。 

这表明每个连续的间隔都是独立检查的。 

最后，考虑一个完全规则的稀疏模式：```
9
100100100
```职位是：```
[0, 3, 6]
```预期差距为：```
3
```第二个区间也是`3`，所以算法打印`"YES"`。 

这证实了零的实际数量并不重要。 只有连续距离相等才重要。
