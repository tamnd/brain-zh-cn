 ## 解决方案
 ## 问题理解

 我们被要求将由两种对象（男孩和女孩）组成的序列排列成一行。 我们唯一拥有的自由就是秩序。 安排的质量是通过相邻位置包含不同性别的频率来衡量的，即男孩坐在女孩旁边的次数。 

目标是构建任何有效的顺序，使这些“交替边界”尽可能频繁，同时尊重我们必须准确使用所有给定的男孩和女孩。 

输入给出两个小整数，男孩的数量和女孩的数量。 输出是总长度的单个字符串，由代表两种性别的两个符号组成。 

约束很小，两个计数都最多为 100。这立即排除了任何大量优化的需要。 即使是尝试所有排列的解决方案也会太慢，因为即使对于 10 或 15 等中等大小，排列总数也会呈阶乘增长并且变得巨大。任何超出线性或近线性行为的行为在这里就足够了。 

主要的微妙之处在于，贪婪的想法可能看起来似乎合理，但仍然需要理由：当一个群体比另一个群体大得多时，强制交替是不可能超出某一点的。 当一侧用完时，诸如严格的“BGBGBG...”之类的幼稚交替结构就会中断，并且如果不一致，完成剩余字符的不同方式可能会影响正确性。 另一个潜在的错误是当计数差异显着时从错误的性别开始，这可能会减少交替邻接的数量。 

例如，如果我们有 1 个男孩和 5 个女孩，那么粗心的交替尝试（例如从男孩开始）会产生“BGBGGG”，这很快就会耗尽男孩的精力，然后崩溃成一长串女孩。 从较大的组“GBGGGG”开始，实现相同或更好的交替计数，并避免不必要的早期交替失败。 

因此，真正的任务是决定如何交错两个多重集以最大化邻接变化。 

## 方法

 暴力方法会尝试包含 n 个一个字符副本和 m 个另一个字符副本的多重集的每一种可能的排列，计算每个字符的相邻不匹配数，并保留最佳的。 这是正确的，因为它直接评估所有配置。 然而，排列的数量是$\frac{(n+m)!}{n!m!}$，即使对于适度的投入来说，这也已经是巨大的了。 对于 n = m = 100，这个值是一个天文数字，使得枚举完全不可行。 

关键的观察结果是，在相邻位置之间造成不匹配的唯一方法是将不同的字符彼此相邻放置。 为了最大化这一点，只要两种类型都可用，我们就希望交替使用。 因此，最好的结构是一个交替的序列，直到一种类型用完，之后剩余的必须形成一个块。 剩下的唯一决定是我们是从更频繁的字符还是不太频繁的字符开始。 

从多数字符开始是最佳选择，因为它可以延迟该字符的耗尽，而该字符是限制资源。 如果我们从少数字符开始，我们可能会更早地用完它，从而在边界处创建不必要的相同字符邻接。 

因此，最佳结构是贪婪的：如果有助于维持交替，则始终放置当前更频繁的剩余字符，但实际上，这简化为从较大的计数开始并交替直到一侧耗尽。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((n+m)!) | O(n+m) | 太慢了 |
 | 最优贪心 | O(n+m) | O(n+m) | 已接受 |

 ## 算法演练

 我们一步步构建字符串，始终尝试尽可能长时间地保持相邻字符不同。 

1. 一开始就确定哪一组较大。 我们比较男孩和女孩的数量，因为较大的群体通常应该占据起始位置。 这种选择可以防止较小群体过早耗尽而过早地打破交替。 
2. 初始化代表剩余男孩和女孩的两个计数器。 我们还将起始角色确定为计数较高的角色。 这种选择最大限度地延长了我们可以交替的时间，而不会被迫重复。 
3. 当两个计数均为正数时，重复追加字符。 在每一步中，我们都会附加与上次附加的字符不同的字符，但前提是该字符仍有剩余配额。 如果首选的替代选择不可用，我们就被迫使用剩余的类型。 
4. 一旦其中一个计数变为零，则附加另一种类型的所有剩余字符。 在此阶段，不可能进行进一步的替换，因此我们接受单个相同字符的块。 

该结构确保我们尽可能交替，这直接对应于在相邻位置之间产生不匹配。 

### 为什么它有效

 在两种类型都可用的每一步中，将两个相同的角色放在一起永远不会改善答案，因为它会消耗灵活性，而不会增加未来的交替机会。 只要两个计数器都为正，就总是存在保持邻接交替的选择。 一旦一个计数器达到零，结构上就不再可能进行进一步的交替，因此剩余的段无法通过重新排列来改进。 这使得贪婪决策在每一步都局部最优，并且对于整个序列全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    # 'B' for boys, 'G' for girls
    if n >= m:
        b, g = n, m
        first, second = 'B', 'G'
    else:
        b, g = m, n
        first, second = 'G', 'B'
    
    res = []
    
    turn = first  # start with majority
    
    while b > 0 or g > 0:
        if turn == first:
            if b > 0:
                res.append(first)
                b -= 1
            else:
                res.append(second)
                g -= 1
        else:
            if g > 0:
                res.append(second)
                g -= 1
            else:
                res.append(first)
                b -= 1
        
        # try to alternate next
        if turn == first:
            turn = second
        else:
            turn = first
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```该实现直接反映了贪婪过程。 我们首先规范化哪个字符被视为“多数”以简化逻辑。 变量`turn`代表我们理想情况下想要放置在旁边以保持交替的内容。 如果该角色不可用，我们会自动退回到另一个角色。 

一个微妙的点是我们从来没有明确地计算交替对。 相反，该结构保证了结构上的最大交替，因此不需要评分。 该循环恰好运行 n + m 次迭代，因此不存在隐藏的低效率。

 ## 边缘情况

 当一侧正好相差 1 时，例如`2 1`，算法尽可能长时间地交替，然后附加剩余的字符。 为了`2 1`，从较大的一侧开始会产生类似的序列`BGB`，它已经实现了最大可能的两个交替边界。 

当一侧较大时，例如`1 5`，第一步创建一个单一的交替，之后的所有内容都成为一个块。 该算法正确地确保单个少数元素不会在中间被浪费，从而减少早期交替机会。 

当计数相等时，任一起始选择都有效。 该实现可以产生任一交替模式，并且两者都实现最大可能的转换数量，因为没有不平衡迫使早期崩溃。
