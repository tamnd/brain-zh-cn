 ## 解决方案
 ## 问题理解

 我们会得到一系列数字，并被要求选择一个连续的片段，或者根本不选择任何内容，以便最大化特定的得分函数。 所选片段的分数是其简单总和减去仅取决于其长度的惩罚。 惩罚与块大小成正比`m`需要覆盖该段，其中每个块的成本`k`。 

因此，不是简单的最大子数组和，而是每个附加的`m`元素有效地触发了另一次扣除`k`。 这使得问题的行为类似于标准的 Kadane 式优化，但逐步成本仅在长度跨越数倍时才发生变化`m`。 

输出是一个整数：所有可能的子数组中可达到的最佳分数，包括不选择任何内容的选项，这会产生零。 

这些约束立即排除任何二次或更差的解决方案。 和`n`最多 300,000 个，任何尝试所有子数组甚至重新计算每个子数组之和的方法都会超出时间限制几个数量级。 我们被迫通过某种形式的动态编程进行线性或近线性扫描。 

一个微妙的困难是惩罚的长度不是线性的。 仅当段长度跨越数倍时才会改变`m`。 这会产生不连续性，破坏标准 Kadane 公式。 

一些边缘情况清楚地说明了这个问题。 

如果所有数字都是负数，则朴素的最大子数组和将返回最小负数段，但这里允许使用空子数组并产生零，因此答案绝不能低于零。 

如果`m = 1`，那么每个元素贡献其值减去`k`，将问题转化为变换值的标准最大子数组和`a[i] - k`。 任何无法识别这种退化的解决方案可能仍然有效，但它提供了有用的健全性检查。 

如果假设惩罚可以均匀地分布在各个元素上，就会出现另一种故障模式。 例如，尝试减去`k/m`每个元素是不正确的，因为上限会在边界处产生跳跃。 

## 方法

 蛮力的想法很简单：枚举每个子数组，计算其总和，计算其长度，使用上限表达式评估惩罚，并跟踪最大值。 这是正确的，因为它直接遵循定义。 不过，大致有`O(n^2)`子数组，即使使用前缀和来计算 O(1) 范围内的和，我们仍然花费二次方的时间来评估候选者。 和`n = 3e5`，这是完全不可行的。 

关键的观察结果是，惩罚仅取决于子数组的长度，并且当我们扩展固定的右端点时，长度单调增加。 这建议采用基于前缀的动态规划公式，其中我们维护以每个位置结尾的子数组的最佳分数。 

我们定义一个运行的 DP 状态，表示在位置结束的最佳子数组`i`。 当子数组扩展一个元素时，总和增加`a[i]`，但是惩罚可能会也可能不会增加，具体取决于我们是否跨越了倍数`m`。 这是关键点：在每个大小块内`m`，在块被填满之前添加元素没有额外的惩罚。 

这种结构建议通过对多少个元素进行取模来单独跟踪答案`m`。 对于每个位置，我们维护`m`与当前子数组长度模对应的 DP 状态`m`。 当我们扩展一个元素时，我们会在这些状态之间转换，并且仅当从`m-1`回到`0`我们需要支付额外费用吗`k`。 

这将问题简化为阵列上的小状态 DP，从而给出线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 模块化DP | O(n·m) | O(米) | 已接受 |

 ## 算法演练

 我们维持 DP 状态`dp[r]`， 在哪里`r`表示当前所选子数组的长度取模`m`。 每个状态存储以当前索引结尾的子数组与该余数的最佳可能总和差。 

我们还允许在任何位置重新启动，因为空子数组是有效的，并且我们不会被迫扩展先前的段。 

### 步骤

 1. 将所有 DP 状态初始化为非常负的值，并将全局答案设置为零。 这说明了根本不选择子数组的选项。 
2. 从左到右迭代数组，将每个位置视为子数组的潜在端点。 
3. 在每个元素处`a[i]`，我们考虑开始一个仅包含该元素的新子数组。 这个新子数组的长度`1`，所以它贡献了`a[i]`还没有处罚。 
4. 我们还考虑通过添加来扩展所有以前的 DP 状态`a[i]`。 如果我们用余数扩展一个状态`r`，新的余数变为`(r + 1) % m`。 
5. 当新的余数变为`0`，这意味着我们刚刚完成了一个大小的块`m`，所以我们减去`k`从累计值。 这编码了逐步上限惩罚。 
6. 更新转换后，我们用所有 DP 状态更新答案，因为任何结束子数组都可能是最优的。 
7. 继续直到数组末尾。 

### 为什么它有效

 DP 状态隐式跟踪以当前索引结尾的每个子数组，按超出多个的元素数量进行分组`m`目前有。 任何时候子数组增长超过`m`，恰好是一个额外的惩罚`k`应用，匹配上限定义。 由于每个子数组要么是全新开始的，要么是从先前的有效子数组扩展而来的，因此涵盖了所有可能性。 转换永远不会重复计算惩罚，因为成本仅在精确的边界交叉处触发，这与余数重置为零的转换完全对应。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    NEG = -10**30
    
    dp = [NEG] * m
    ans = 0
    
    for x in a:
        new_dp = [NEG] * m
        
        # start new subarray
        new_dp[1 % m] = max(new_dp[1 % m], x)
        
        # extend previous subarrays
        for r in range(m):
            if dp[r] == NEG:
                continue
            nr = (r + 1) % m
            val = dp[r] + x
            if nr == 0:
                val -= k
            new_dp[nr] = max(new_dp[nr], val)
        
        for r in range(m):
            dp[r] = max(dp[r], new_dp[r])
            ans = max(ans, dp[r])
    
    return ans

if __name__ == "__main__":
    print(solve())
```DP 阵列`dp[r]`存储以当前位置结束且长度等于的任何子数组的最佳值`r mod m`。 转换显式处理启动新段和扩展旧段。 的减法`k`恰好在什么时候`nr == 0`编码上限函数行为。 

使用`NEG`确保无效状态不会干扰转换。 我们不断融合`new_dp`进入`dp`以便所有子数组仍可在以后的位置进行扩展。

 ## 边缘情况

 当数组完全为负时，每个 DP 状态仍可能累积负值，但算法始终与零进行比较，确保空子数组保持最佳状态。 例如，与`[-5, -2]`，每次扩展都会降低分数，并且没有 DP 状态超过零，因此答案保持正确`0`。 

什么时候`m = 1`，每个新元素立即完成一个块。 DP 转换减去`k`每一步都匹配公式`a[i] - k`。 因此，该算法的行为与 Kadane 对变换值的算法完全相同，并且状态压缩不会打破这种特殊情况。 

当最佳段长度不是的倍数时`m`，DP 仍然跟踪部分余数。 最后的不完整块不会产生额外的惩罚，因为只有当余数回零时才会发生减法。 这确保了像长度这样的段`m + 1`只收费一次，而不是两次，精确匹配上限定义。
