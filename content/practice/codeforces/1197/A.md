 ## 解决方案
 ## 问题理解

 我们有几组独立的木板，每块木板都有固定的长度，不能被切割。 我们希望从每组中组装一个称为梯子的结构，并具有尽可能多的台阶。 

精确选择 k + 2 块木板即可形成 k 级梯子。 其中两个必须是“底座”木板，每个底座的长度必须至少为 k + 1。其余 k 块木板是“台阶”木板，每个木板的长度必须至少为 1，这实际上意味着任何木板都可以用作台阶。 

因此，唯一真正的限制是在底座上：我们需要两块足够长的木板来支撑高度为 k 的梯子，其余选定的木板只需要存在即可形成台阶。 

对于每个查询，我们必须选择一些 Plank 子集来最大化 k。 我们可以完全忽略木板，但我们不能拆分或修改它们。 

这些约束允许所有测试用例中总共最多有 100,000 个木板。 这立即排除了任何尝试测试每个可能的 k 的所有子集甚至所有碱基候选对的解决方案。 每个测试用例中 n 的任何二次方都会失败。 每次测试的排序或线性扫描是可以接受的。 

如果我们过于局部地推理，就会出现一些微妙的失败案例。 首先，人们很容易认为答案仅取决于两个最大的木板，但这忽略了是否有足够的剩余木板来形成台阶。 其次，人们很容易忘记增加 k 会使基本要求更加严格，因此在不验证可行性的情况下首先贪婪地选择最大 k 的解决方案将会高估。 

具体的边缘情况是当我们只有两块大木板但木板总数不够时：

 输入：```
1
3
10 10 1
```我们可以形成 k = 1，因为我们可以以 10 和 10 作为基数，剩下的 1 作为步长。 但即使底座足够，k = 2 也是不可能的，因为我们总共需要 4 块木板。 

另一种情况是有很多小木板但没有两块大木板：```
1
5
1 1 1 1 1
```无法建造梯子，因为我们无法形成两个长度至少为 2 的底面。 

这些例子表明“长木板的数量”和“额外木板的可用性”同时重要。 

## 方法

 暴力方法会尝试从 0 到 n − 2 的所有可能的 k 并检查可行性。 对于每个 k，我们将扫描数组，计算有多少个 Plank 至少为 k + 1 作为基本候选，并验证我们至少有两个这样的 Plank 以及至少有 k + 2 个 Plank。 每次检查的成本为 O(n)，并且对所有 k 执行此操作会为每个测试用例提供 O(n^2)，这对于总共 100,000 个元素来说太慢了。 

关键的观察是可行性在结构化方式上是单调的。 随着 k 的增加，基础阈值 k + 1 也会增加，因此可用的基础板组只会缩小。 与此同时，所需的木板总数线性增加。 这表明我们可以按长度降序处理候选碱基，并跟踪我们当前拥有的可用碱基数量。 

如果我们按降序对木板进行排序，我们可以想象逐渐降低 k 的阈值并询问：在什么时候我们首先有足够的木板可以用作基础？ 每次我们考虑候选 k 时，我们需要知道在长度 ≥ k + 1 的木板中是否至少有两个木板，以及我们是否至少有 k + 2 个木板可用。 

我们不是从头开始重新计算每个 k 的计数，而是从最大到最小的 Plank 长度进行扫描，并维护当前有多少元素“符合”作为当前阈值的基础。 这将问题减少到排序后一次通过。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

 我们首先将木板长度按降序排列。 这种顺序让我们可以推断出逐渐严格的基本要求。 

我们维护一个指针 i，该指针在已排序的数组中移动，并表示当前有多少块木板被认为可用作给定阈值下的潜在基础。 我们还根据我们已经处理的木板数量来跟踪当前可以支持多少步 k。 

1. 按降序对数组进行排序，以便我们首先处理最大的木板。 这确保了当我们考虑候选阈值时，所有更大或相等的木板都已被考虑在内。 
2. 初始化一个计数器cnt = 0，它表示到目前为止我们已经看到有多少个木板在当前阈值下有资格成为基础候选者。 
3. 遍历已排序的数组。 在位置 i，我们正在有效地考虑是否可以支持基本阈值为 a[i] 的梯子。 每次添加新的 plank 时，我们都会增加 cnt。 
4. 包含第 i 个木板后，检查我们是否可以使用 cnt 合格的候选碱基形成有效的梯子。 由于我们需要两个碱基，因此我们要求 cnt ≥ 2。 
5. 我们在此阶段可以支持的步骤 k 的数量受限于我们已处理的木板数量减 2，因为总共需要 k + 2 个木板。 所以我们计算 k = min(cnt - 2, i - 1)。 
6. 跟踪所有位置的最大 k。 

关键的推理步骤是，在每个阶段，当前索引 i 对应于我们可以使用的候选木板数量，并且 cnt 跟踪其中有多少块足够强大，可以充当该级别的基础。 

### 为什么它有效

 在排序遍历中的任何一点，我们都恰好有一组至少与当前阈值一样大的木板。 任何有效的高度为 k 的梯子都必须从该组中选取两个底板，因此可行性仅取决于此前缀中剩余的元素数量。 由于当我们移动较小的值时，基本要求和木板总数这两个约束都会单调收紧，因此可实现的最佳 k 必须出现在这些前缀状态之一。 因此，检查每个前缀可以捕获所有可能的最佳配置，而不会丢失任何有效的排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    cnt = 0
    ans = 0
    
    for i, val in enumerate(a):
        cnt += 1
        
        k = min(cnt - 2, i)  # i = number of remaining step capacity minus 1
        if k > ans:
            ans = k
    
    print(max(ans, 0))
```该解决方案首先对木板长度进行排序，以便我们可以按潜在基础强度的降序评估可行性。 变量 cnt 跟踪我们正在考虑的前缀中当前有多少个木板。 在每一步中，i 表示除了第一块木板之外还有多少块额外的木板可用作步骤。 

表达式cnt-2反映了选择两个碱基后可以保留多少块木板作为台阶。 表达式 i 反映了总共有多少个“槽”可用于构建达到此前缀的结构。 取最小值确保我们同时尊重这两个约束。 

最后，我们取所有前缀中的最大值，因为在基本约束变得过于严格之前，最佳阶梯大小对应于最宽松的前缀。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort(reverse=True)

        cnt = 0
        ans = 0
        for i, _ in enumerate(a):
            cnt += 1
            k = min(cnt - 2, i)
            ans = max(ans, k)
        out.append(str(max(ans, 0)))
    return "\n".join(out)

 ## 边缘情况

 一种边缘情况是恰好有两块木板。 该算法对它们进行排序，并在第二次迭代时立即找到 cnt = 2，但 k = min(0, 1) = 0，这正确地产生没有正梯子，因为至少需要一步。 

另一种情况是所有木板都相同且很大。 例如，对于长度为 5 的 6 个木板，每个前缀都满足基本条件，并且限制因素仅为可用木板的数量。 该算法正确地增加 k 直到达到 4，因为 k + 2 = 6 与木板总数完全匹配，并且其中两个被保留作为底板。
