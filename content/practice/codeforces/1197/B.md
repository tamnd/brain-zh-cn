 ## 解决方案
 ## 问题理解

 我们有一排柱子，每根柱子最初只容纳一个圆盘。 每个圆盘都有不同的半径，因此我们可以将输入视为放置在位置 1 到 n 上的从 1 到 n 的值的排列。 

唯一允许的举动是非常严格的。 磁盘可以从一个柱子移动到相邻的柱子，但前提是当前的柱子恰好有一个磁盘。 此外，当将其放置在另一个柱子上时，它必须落在空柱子上或放置在更大的磁盘顶部。 这会产生堆叠约束，其中磁盘只能按半径递减的顺序放置。 

问题是，是否有可能仅使用这些相邻的单盘移动，最终将所有盘收集到一个柱子上。 

n 最大为 2·10^5 的约束迫使我们远离对实际移动的任何模拟。 任何试图显式地逐步移动磁盘的方法都会面临二次行为的风险，因为磁盘可能会遍历许多位置，并且每次移动都是局部的。 

一个微妙的困难是，“一个圆盘只能从当前只有一个圆盘的柱子上移动”的移动限制阻止了任意重新排列。 如果我们尝试将此视为自由排序过程，我们会错误地假设我们始终可以在中间位置之间穿梭磁盘。 事实上，中间配置可能会阻碍未来的移动。 

一个常见的失败案例来自于不考虑邻接约束的贪婪堆叠。 例如，如果大的圆盘没有被定位成可以在一致的向外扩展中剥离较小的圆盘，则天真的贪婪排序仍然会产生有效的递减序列，但忽略了一些所需的中间支柱将暂时包含多个圆盘，从而使移动非法。 

因此，核心困难不是对磁盘进行排序，而是确保邻接约束不会将任何磁盘困在无法作为单例移出的配置中。 

## 方法

 一个蛮力的想法是使用配置上的 BFS 来模拟所有有效的动作。 每个状态都代表堆栈的完整排列，每次转换都会将有效磁盘移动到邻居。 这在理论上是正确的，因为它探索了所有可达的配置，但状态的数量是天文数字。 即使对于中等的 n，跨柱堆叠磁盘的方法数量也会呈指数级增长，使得这种方法完全不可行。 

关键的见解是我们实际上不需要构建移动序列。 我们只需要判断是否存在有效的序列。 邻接约束意味着一个结构属性：在任何时刻，尚未移动的磁盘集必须在当前构建过程周围形成一个连续区域。 更重要的是，因为我们只能从单磁盘支柱移动，所以构建最终堆栈的过程就像从两端向内剥离阵列一样。 

这导致了简化。 我们隐式选择一个目标最终支柱，并尝试模拟是否可以将所有磁盘“收集”到单个递减堆栈中。 由于圆盘必须以降序排列，因此最大的圆盘必须是最终结构的第一个固定元素。 将其作为基础后，所有剩余的磁盘必须按降序连接，并且在每一步中，我们只允许从剩余段的当前端之一取出下一个磁盘。 这是因为只有端点在不违反“单一源支柱”约束的情况下保持可达。 

因此，问题就简化为检查我们是否可以从最大元素的位置开始向外扩展，总是选择比最后选择的磁盘小的相邻的未处理元素。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(exp(n)) | O(exp(n)) | O(exp(n)) | O(exp(n)) | 太慢了 |
 | 两指针贪婪扩张 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们首先定位最大半径圆盘的位置。 该磁盘必须是我们最终堆栈的起点，因为不存在更大的磁盘位于其上方。 

然后我们维护两个指针，一个从该位置向左扩展，一个向右扩展。 我们还维护一个变量来跟踪最终排序中最后选择的磁盘，最初设置为最大磁盘。 

在每一步中，我们都会考虑当前边界处的两个候选者。 仅当候选者的半径严格小于最后选择的值时，我们才允许采用候选者，因为最终堆栈必须严格递减。 在有效的候选者中，我们选择较大的一个。 这种选择很重要，因为过早选择较小的值可能会阻止稍后访问较大的有效候选值，而贪婪的选择保留了灵活性。 

我们继续扩展，直到所有元素都被消耗或直到两个候选边界都无效。 

完成后，如果我们已成功包含所有磁盘，则答案为 YES，否则为 NO。 

正确性依赖于已选择的序列始终严格递减的不变量，并且对应于原始数组中以最大元素为中心的连续段。 每个剩余的候选者都与该段相邻，因此如果存在有效的完整构造，则每个步骤总会有一个不违反降序的有效边界选择。 贪心选择确保我们永远不会过早地丢弃必要的较大元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mx = max(range(n), key=lambda i: a[i])
    last = a[mx]

    l = mx - 1
    r = mx + 1

    used = 1

    while used < n:
        left_val = a[l] if l >= 0 else -1
        right_val = a[r] if r < n else -1

        valid_left = l >= 0 and left_val < last
        valid_right = r < n and right_val < last

        if not valid_left and not valid_right:
            print("NO")
            return

        if valid_left and valid_right:
            if left_val > right_val:
                last = left_val
                l -= 1
            else:
                last = right_val
                r += 1
        elif valid_left:
            last = left_val
            l -= 1
        else:
            last = right_val
            r += 1

        used += 1

    print("YES")

if __name__ == "__main__":
    solve()
```该代码首先识别最大元素索引并初始化其周围的扩展边界。 循环向外增长所选段，同时保持严格递减条件。 

关键的实现细节是仔细的边界处理：当一侧耗尽时，不得将其视为候选侧。 另一个微妙的点是确保比较使用严格的不平等`last`，因为问题陈述不可能有相等的值，但条件仍然强制结构上的正确性。 

左和右之间的贪婪选择是通过直接比较它们的值来实现的，总是向更大的可行边界值延伸。 

## 工作示例

 考虑示例输入：```
4
1 3 4 2
```我们首先在索引 2 处找到最大元素 4。 

| 步骤| 左指针| 右指针 | 最后选择 | 行动|
 | ---| ---| ---| ---| ---|
 | 初始化| 1 | 3 | 4 | 从最大开始|
 | 1 | 1 | 3 | 4 → 3 | 右转 (3) |
 | 2 | 1 | 4 | 3 → 2 | 向右走 (2) |
 | 3 | 1 | 4 | 2 → 1 | 向左转 (1) |

 所有元素均已成功消耗，确认了可行性。 

现在考虑一个失败式的安排：```
4
4 1 3 2
```我们从 4 的索引 0 开始。 

| 步骤| 左指针| 右指针 | 最后选择 | 行动|
 | ---| ---| ---| ---| ---|
 | 初始化| -1 | 1 | 4 | 开始 |
 | 1 | -1 | 1 | 4 → 1 | 必须走对|
 | 2 | -1 | 2 | 1 → 3 无效 | 卡住了|

 在第 2 步，我们不能取 3，因为它大于最后选择的值 1，并且没有有效的左移动。 该过程提前停止，所以答案是否定的。 

这些痕迹表明，可行性取决于向外贪婪扩张是否总能找到递减的边界延伸。

 ## 边缘情况

 关键的边缘情况是最大元素位于极限位置时。 在这种情况下，扩展立即变为单侧，算法必须正确地将缺失的一侧视为无效，而不尝试访问它。 

另一个微妙的情况是，双方都有效，但过早选择错误的一方在局部看来仍然是正确的。 始终选择较大的可用邻居的贪心规则确保我们不会过早地消耗稍后可能需要的小值以保持扩展的可行性。 

最后一个重要的情况是这样的配置，其中多个步骤都存在有效的移动，但最终会导致死胡同。 逐步的边界模拟确保算法在双方都失败了递减约束时准确地检测到这一点，反映了实际过程中不可能进行合法磁盘移动的时刻。
