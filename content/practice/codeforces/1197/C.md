 ## 解决方案
 ## 问题理解

 我们得到一个非递减数组，并要求将其精确地拆分为$k$连续的部分。 每个部分贡献的成本等于其最大元素和最小元素之间的差，并且由于数组已排序，因此这只是该段中最后一个元素和第一个元素之间的差。 

任务是选择$k-1$剪切位置，以使这些段范围的总和最小化。 

约束条件达到$n = 3 \cdot 10^5$，这立即排除了任何尝试所有放置切割方法或使用二次动态规划的方法。 任何超出的事情$O(n \log n)$在实践中存在超时的风险，并且$O(n^2)$段边界上的 DP 速度太慢。 

问题的一个微妙的方面是，虽然我们是“分割成段”，但成本仅取决于段端点，而不取决于内部结构。 这意味着整个优化是由我们放置剪切的位置驱动的。 

天真的直觉的一个失败案例是假设我们应该在全球范围内相邻差异最大的地方进行削减。 例如，取最大的$k-1$如果我们不考虑这些差距如何与细分市场相互作用，那么差距并不总是有效，因为每次削减都会消除对细分市场范围的内部贡献，而不是独立增加成本。 

另一个陷阱是认为使用局部决策从左到右的贪婪分割是最佳的； 局部最小范围段可以阻止更好的全局分区。 

## 方法

 暴力解决方案会尝试所有方法来放置$k-1$之间切入$n-1$可能的差距。 每个配置定义一个分区，我们计算其成本$O(n)$，导致$O(\binom{n}{k} \cdot n)$，即使对于小规模来说，这也是完全不可行的$n$。 

更加结构化的 DP 方法定义了$dp[i][j]$作为分割前缀的最小成本$1 \dots i$进入$j$段。 过渡需要尝试所有先前的切入点，给出$O(n^2 k)$时间以简单的形式出现，但仍然超出了限制。 

关键的观察是，由于数组是排序的，合并两个相邻的段总是以可预测的方式改变成本。 如果我们将整个数组视为一个段，则成本为$a_n - a_1$。 每次我们分开时$i$和$i+1$，我们有效地“消除”了连接的贡献$a_i$到$a_{i+1}$，因为这两个元素不再属于同一段。 

如果阵列是一段，则成本将包括整个跨度。 每次切割位置$i$消除缺口贡献$(a_{i+1} - a_i)$。 因此，我们可以考虑从整个跨度开始，减去通过削减而节省的成本，而不是考虑建造分段。 

为了最小化成本，我们希望最大化移除的总贡献，这意味着选择$k-1$最大相邻差异。 

这将问题转化为简单的排序选择问题$n-1$价值观。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 分区上的 DP | O(n²k) | O(n²k) | O(nk) | O(nk) | 太慢了 |
 | 贪婪缺口选择| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算所有相邻差异$d_i = a_{i+1} - a_i$为了$1 \le i < n$。 

如果我们在两者之间进行削减，这些代表了潜在的节省$i$和$i+1$。 
2. 计算总成本为$a_n - a_1$。 

这相当于我们根本不拆分的成本。 
3. 按降序对差异列表进行排序。 

这使我们能够首先选择最有利的切割位置。 
4. 取最大的和$k-1$差异。 

每个选定的差异都对应于降低总成本的削减。 
5. 从初始总成本中减去该总和并输出结果。 

### 为什么它有效

 该算法依赖于任何分割成本都可以表示为全范围减去通过切割去除的差异之和的不变量。 由于每次切割都会从全局跨度中精确消除一个邻接贡献，并且这些贡献是独立的，因此选择切割不会干扰位置。 因此，最大化移除的贡献相当于选择最大的相邻间隙，保证最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    if k == 1:
        print(a[-1] - a[0])
        return

    diffs = []
    for i in range(n - 1):
        diffs.append(a[i + 1] - a[i])

    diffs.sort(reverse=True)

    saved = sum(diffs[:k - 1])
    print((a[-1] - a[0]) - saved)

if __name__ == "__main__":
    solve()
```该解决方案首先处理不进行切割的琐碎情况。 主要计算构建相邻差异列表，对它们进行排序以优先考虑大差距，然后选择最佳的$k-1$其中。 最终的减法将“最大节省”解释转换回原始成本公式。 

一个常见的错误是忘记了只有$k-1$可以选择差距，或者错误地总结所有差异而不是选择最大的差异。 

## 工作示例

 ### 示例 1

 输入：```
6 3
4 8 15 16 23 42
```相邻的差异是：

 | 我| 一个[我] | 一个[i+1] | 差异|
 | ---| ---| ---| ---|
 | 1 | 4 | 8 | 4 |
 | 2 | 8 | 15 | 15 7 |
 | 3 | 15 | 15 16 | 16 1 |
 | 4 | 16 | 16 23 | 23 7 |
 | 5 | 23 | 23 42 | 42 19 | 19

 我们对差异进行排序：$[19, 7, 7, 4, 1]$。 

我们采取$k-1 = 2$最大：$19 + 7 = 26$。 

初始成本为$42 - 4 = 38$。 

最终答案是$38 - 26 = 12$。 

这证实了最佳切割恰好对应于最大间隙。 

### 示例 2

 输入：```
5 2
1 2 3 10 11
```| 我| 差异|
 | ---| ---|
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 7 |
 | 4 | 1 |

 排序差异：$[7, 1, 1, 1]$。 

挑选$k-1 = 1$: 取7。 

初始成本：$11 - 1 = 10$。 

最终成本：$10 - 7 = 3$。 

我们有效地削减了 3 到 10 个，产生片段$[1,2,3]$和$[10,11]$，其成本为$2$和$1$，总计$3$。 

这显示了单个主导间隙如何决定最佳分区。

 ## 边缘情况

 一个关键的边缘情况是当$k = 1$。 该算法必须避免选择任何差异并直接返回$a_n - a_1$。 在这种情况下，diff 数组是无关紧要的，任何意外的减法都会错误地减少结果。 

另一个边缘情况是所有元素都相等。 每个相邻差异为零，因此排序和选择任何子集仍必须产生零节省。 不管怎样，最终结果都保持为零$k$，确认该算法不会过度计算削减。 

什么时候$k = n$，每个元素都成为自己的段。 成本必须为零，因为每个段的最小值和最大值相等。 该算法可以正确处理这个问题，因为它总结了最大的$n-1$间隙，等于全范围$a_n - a_1$，导致最终答案为零。
