 ## 解决方案
 ## 问题理解

 我们有一排塔楼，每个塔楼都有固定的高度。 然后我们进行一系列风实验。 每个实验都从某个位置开始并严格向右移动。 

风的强度值在经过塔楼时会减小。 当它到达塔楼时，可能会发生两件事。 如果当前塔与风力相比足够高，风会立即停止。 否则，塔被认为被摧毁，风力减弱一，然后继续到下一个位置。 重要的是，即使被摧毁的塔楼在通过时仍然会降低风的强度，因为风在经过每座塔楼时总会损失一个单位的强度。 

对于每个实验，我们需要回答在风停止之前有多少个塔被访问过，要么是被阻挡，要么是耗尽了有效的塔。 

一个关键细节是，被摧毁的塔将永久保留在系统中，高度为零。 这意味着稍后的实验会看到阵列的更新状态，而不是原始状态。 

约束达到二十万个塔和二十万个查询，因此每个查询的直接模拟太慢。 在最坏的情况下，线性扫描每个查询的简单方法将需要多达约 40 亿次操作，这远远超出了两秒的限制。 

当遍历过程中风力变小时，会出现微妙的角落情况。 一旦强度降至零，任何高度为零或更高的塔都会立即停止风，因此即使是“空”塔也会在此时成为阻挡者。 另一个极端情况是塔在被摧毁后会被永久修改，因此未来的查询取决于过去的遍历路径，而不仅仅是初始数据。 

## 方法

 直接模拟通过从起始位置步行、更新塔高度并逐步降低风力来处理每个查询。 这是正确的，因为它严格遵守字面规则。 但是，每个查询可能会扫描几乎整个数组，并且对于许多查询，这会变成二次行为。 

关键的观察结果是，可以以消除对风力减弱的依赖的方式重写停止条件。 

假设我们处于从 s 开始的位置 i。 移动 k 步后，风力为 x − k。 如果 hi ≥ x − k，则风在 i 处停止。 重新排列得到 hi + k ≥ x。 由于 k = i − s，我们得到 hi + i ≥ x + s。 这是关键的简化：塔是否能阻止风仅取决于通过静态值 hi + i 的位置和高度，并与特定于查询的阈值 x + s 进行比较。 

这将每个查询转换为对第一个索引 i ≥ s 的搜索，使得 hi + i 至少为 x + s。 

该数组是动态的，因为当塔被通过并被摧毁时，其高度永久为零，因此其值实际上变为 i 而不是 hi + i。 这仍然与相同的变换条件一致。 

因此我们维护一个支持两种操作的结构。 首先，当塔被摧毁时，点会更新，将其值更改为 i。 其次，查询要求第一个等于或超过 s 且其值至少为给定阈值的索引。 

存储最大值的线段树可以让我们快速定位到第一个满足条件的位置。 我们反复跳到第一个排位指数，如果它挡住了风，我们就停下来。 否则我们就跳过它并继续。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | O(nq) | O(n) | 太慢了|
 | 具有变换条件的线段树 | O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个位置 i 的值定义为 A[i] = hi + i。 该值决定了塔是否可以针对给定查询停止风。

1. 在 A[i] 上构建一棵线段树，存储每个线段中的最大值。 这使我们能够快速测试范围内的任何位置是否可以满足阈值条件。 
2. 对于每个查询 (s, x)，计算阈值 T = x + s。 这将动态风条件转变为 A[i] 上的静态范围条件。 
3、从当前位置cur=s开始。 我们尝试使用线段树找到第一个索引 j ≥ cur 使得 A[j] ≥ T。 这代表了第一座在变换后的坐标中足够坚固以阻止风的塔。 
4. 如果不存在这样的j，那么风永远不会遇到阻挡塔。 风将穿过所有剩余的塔直到最后，所以答案是 n − s + 1。 
5. 如果这样的 j 存在，那么 cur 和 j − 1 之间的所有塔都保证满足 A[i] < T。这些塔在当前风力下可以安全通过，所以我们不停地穿过它们。 
6. 当我们经过一座塔 i 时，我们通过设置 A[i] = i 来更新它以表示破坏。 这反映出它的高度永久为零。 
7. 当我们到达阻塞索引 j 时，我们计算通过了多少个塔，即 j − s + 1，并停止处理该查询。 
8. 对每个查询重复此过程，更新会影响未来的查询。 

重要的微妙之处在于，每个塔从初始状态到最终状态仅转换一次。 它被销毁后就不会再改变，这限制了更新的总数。 

### 为什么它有效

 变换 hi + i ≥ x + s 编码了塔相对于风力减弱而变得足够坚固的确切时刻。 线段树确保我们始终找到最早的此类塔，因此我们永远不会跳过有效的停止点。 由于每个塔在第一次通过后都会永久更新，因此结构在查询中保持一致，并且未来的查询不会错误地将被摧毁的塔视为仍然完好无损。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.t = [0] * (2 * self.size)
        for i in range(self.n):
            self.t[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.t[i] = max(self.t[2 * i], self.t[2 * i + 1])

    def update(self, idx, val):
        i = self.size + idx
        self.t[i] = val
        i //= 2
        while i:
            self.t[i] = max(self.t[2 * i], self.t[2 * i + 1])
            i //= 2

    def first_ge(self, l, x):
        if self.t[1] < x:
            return -1
        i = 1
        left, right = 0, self.size - 1
        while i < self.size:
            mid = (left + right) // 2
            if self.t[2 * i] >= x:
                i = 2 * i
                right = mid
            else:
                i = 2 * i + 1
                left = mid + 1
        idx = i - self.size
        return idx if idx < self.n else -1

def solve():
    n = int(input())
    h = list(map(int, input().split()))
    q = int(input())

    arr = [h[i] + i for i in range(n)]
    seg = SegTree(arr)

    for _ in range(q):
        s, x = map(int, input().split())
        s -= 1
        T = x + s

        cur = s
        while True:
            j = seg.first_ge(cur, T)
            if j == -1:
                print(n - s)
                break

            print(j - s + 1)
            if j >= cur:
                seg.update(j, j)
            break

solve()
```线段树存储转换后的值 A[i] = hi + i，以便每个查询成为后缀上的第一个大于或等于搜索。 查询阈值按起始位置移动，这消除了风变量的减小。 

函数first_ge查找给定位置处或之后可以满足段最大约束的最早索引。 一旦找到该索引，它要么是停止点，要么如果不存在这样的索引，则风会跑到数组的末尾。 

当塔用作停止点时，它会更新为其索引值，表示高度为零。 这确保了未来的查询始终将其视为非原始塔。

 ## 边缘情况

 当风强度恰好在塔之间的边界处减小到零时，就会发生关键的边缘情况。 此时，即使高度为零的塔也会阻塞，因为停止条件变为 hi ≥ 0。转换后的条件 A[i] ≥ x + s 正确地捕获了这一点，因为阈值变得非常小并强制立即停止。 

另一种情况是，所有剩余的塔都弱到足以通过，但数量足够多，以至于风力强度在结束前达到零。 在这种情况下，算法仍然正确地停止在第一个剩余索引处，因为一旦它变得足够小，线段树搜索总是最终会找到满足阈值的位置。
