 ## 解决方案
 ## 问题理解

 我们给出从 1 到 N 的两种数字排列，写成城市布局的两行。 每个数字代表一个温度区域，每个区域在每一侧恰好出现一次。 第一行区域和第二行区域之间可以建立一座“桥”，但前提是它们的标签绝对差最多为 4。此外，每个区域最多可以参与一座桥，并且在两行上方绘制桥时不允许交叉。 

任务是最大化此类非交叉有效桥梁的数量。 

输入大小 N 最大为 1000，这会立即排除任何三次或更高的解。 O(N^2) 或 O(N^2 log N) 方法是可以接受的，而任何涉及指数枚举或显式匹配排列的方法都是不可接受的。 

关键的困难不是局部约束 |a − b| ≤ 4，但桥不能相交的全局约束。 这将问题转化为两个有序序列之间的结构化匹配问题。 

一些边缘情况值得在心理上隔离。 如果两行相同，例如 1 2 3 4 和 1 2 3 4，则每个位置都可以匹配自身，答案为 N。如果仅检查本地兼容性的天真的贪婪算法如果允许隐式交叉，则仍然可能会失败。 

如果行颠倒，例如 1 2 3 4 和 4 3 2 1，许多对在本地有效，但几乎所有选择都会与交叉约束冲突，因此按值差异贪婪会严重失败。 

最微妙的情况是本地存在多个有效匹配，但只有一个子集保留单调排序。 

## 方法

 如果我们忽略交叉约束，问题就变得微不足道了。 我们只需将第一行中的每个元素与第二行中的兼容元素进行匹配，检查绝对差异条件。 这会导致二分匹配问题，其中每个左侧位置都可以连接到标签最多相差 4 的任何右侧位置。当 N 最大为 1000 时，标准最大二分匹配算法的工作时间为 O(N^3) 或 O(N^{2.5})，具体取决于实现。 

然而，这忽略了结构。 交叉限制不是任意的。 因为两行都是排列，所以我们可以将问题重新解释为两个有序序列中的匹配位置，并且交叉与所选匹配对中的反转完全对应。 

这将问题转化为最长递增结构。 一旦我们在顶行的位置 i 和底行的位置 j 之间确定了一对，任何未来的对都必须遵守两行的顺序，否则会发生交叉。 

关键的观察是，我们可以通过一个坐标对所有可能的有效对进行排序，然后将非交叉匹配的最大数量计算为变换空间中的最长递增子序列，或者等效于位置上的动态规划。 

查看它的一种简洁方法是按顺序遍历顶行。 对于每个位置 i，我们尝试将其与底行中所有兼容的位置 j 进行匹配。 由于每个值都出现一次，因此我们可以通过每个值的索引来表示底部位置。 然后我们将问题简化为在值差和索引单调性的约束下选择对 (i, pos[b[i]])，这成为一个 2D LIS 式的 DP。 

我们将 dp[i][j] 定义为最佳匹配，使用顶行到 i 的前缀和底行到 j 的前缀。 仅当值兼容时，转换才允许匹配。 这本质上是具有局部性约束的二部置换图中的最大匹配，可以在 O(N^2) 中求解。

蛮力尝试所有对组合并显式检查交叉有效性，这会花费指数时间。 DP 通过确保我们只扩展非交叉配置来压缩结构。

 ## 算法演练

 我们将值转换为位置以简化兼容性检查。 令 pos2[x] 为第二行中值 x 的索引。 

然后，我们从左到右处理第一行，并维护一个动态编程表，该表跟踪我们可以形成多少个有效的非交叉匹配。 

### 步骤

 1. 构建一个数组 pos2，其中 pos2[value] 给出第二行中该值的索引。 这让我们可以用索引比较来替换值匹配。 
2. 将 dp[i][j] 定义为考虑第一行前 i 个元素和第二行前 j 个元素的有效桥的最大数量。 该公式对非交叉约束进行编码，因为增加索引自然会保留顺序。 
3. 将 dp[0][_] 和 dp[_][0] 初始化为零，因为没有元素意味着没有桥。 
4. 从 1 到 N 迭代 i。对于每个 i，从 1 到 N 迭代 j。在每个状态，我们决定是跳过其中一个元素还是尝试匹配当前对。 
5. 首先传播最佳已知值：dp[i][j] 取 dp[i-1][j] 和 dp[i][j-1] 中的最大值。 这在跳过一侧时提出了最佳解决方案。 
6. 检查第一行的第i个值和第二行的第j个值是否可以连接，即它们的标签的绝对差最多为4。 
7. 如果它们兼容，则尝试通过从 dp[i-1][j-1] + 1 转换为 dp[i][j] 来形成桥接。 这确保我们只匹配每个元素一次并保留顺序，防止交叉。 
8. 答案是 dp[N][N]。 

### 为什么它有效

 DP 在索引 i 和 j 中强制执行单调结构。 任何桥总是连接递增的前缀，因此两个选定的桥不能交叉：如果一个使用 (i1, j1) 而另一个使用 (i2, j2) 并且 i1 < i2，则过渡结构会强制 j1 < j2。 递归仅允许在匹配时沿对角线前进，这编码了严格的顺序保留。 由于每个有效的非交叉匹配都对应于此类对角线移动的单调序列，因此DP捕获所有可行的解决方案并在其中选择最大匹配数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos2 = [0] * (n + 1)
    for i, v in enumerate(b, 1):
        pos2[v] = i

    dp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        ai = a[i - 1]
        for j in range(1, n + 1):
            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

            bj = b[j - 1]
            if abs(ai - bj) <= 4:
                dp[i][j] = max(dp[i][j], dp[i - 1][j - 1] + 1)

    print(dp[n][n])

if __name__ == "__main__":
    solve()
```实现直接遵循DP定义。 嵌套循环枚举所有前缀对。 过渡`max(dp[i-1][j], dp[i][j-1])`确保跳过元素不会丢失最优解。 对角线转换编码选择有效的桥。 绝对差异检查是应用特定于问题的约束的唯一地方。 

一个常见的错误是尝试仅根据一个数组中的位置进行匹配； 这打破了交叉约束，因为它忽略了第二行中的排序。 另一个错误是尽可能贪婪地匹配，这会失败，因为早期匹配可能会阻止多个后续最佳匹配。

 ## 边缘情况

 一种边缘情况是由于差异约束而仅可能进行单个配对。 例如，a = [1, 10, 20]，b = [100, 2, 21]。 如果出现顺序冲突，DP 将仅允许 (10, 2) 或 (20, 21)，但不允许两者同时存在。 通过DP运行，有效匹配仅出现在一致的前缀对齐上，并且算法正确地选择最佳的单链。 

另一个边缘情况是当所有值都在 1 到 5 范围内时，使得每对都局部有效。 在这种情况下，解决方案完全受到交叉约束的控制。 DP 简化为寻找两个排列之间最长的非交叉匹配，并且递归确保只有单调对选择能够生存。 

最后的边缘情况是存在兼容对但相互隔离的情况，例如中间的单个值可以匹配多个位置。 DP 自然地处理这个问题，因为它将跳过转换与对角线匹配进行比较，确保局部良好但全局阻塞的匹配不会被强制。
