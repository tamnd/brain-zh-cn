 ## 解决方案
 ## 问题理解

 我们得到一个由三个可能的字符组成的字符串：固定的黑色单元格、固定的白色单元格和我们可以自由分配任一颜色的未知单元格。 任务是通过用黑色或白色替换每个未知位置来完成字符串，然后计算有多少个完整的字符串满足结构条件。 

条件是全局的而不是局部的：完成后，必须存在两个不相交的固定长度k相等的线段，其中左线段全黑，右线段全白。 这些段不得重叠，并且必须按从左到右的顺序出现。 

输出是有效完成数模 1e9 + 7。 

关键的困难在于，每个未知字符都会使可能性的数量加倍，因此简单的枚举已经呈指数级增长。 当 n 达到 10^6 时，任何按未知位置或按完整分配进行分支的方法都是不可能的。 即使对所有段对进行二次扫描也太慢，因为存在 O(n^2) 可能的段对。 

当字符串没有未知数时，会出现微妙的边缘情况。 那么我们根本不计算赋值，而只是简单地检查固定字符串是否已按顺序包含有效的黑色块和有效的白色块。 在这种情况下，答案是 1 或 0，具体取决于条件是否满足。 

另一个棘手的情况是当 k 很大且接近 n 时。 然后，段的可能放置非常少，并且许多幼稚的方法假设滑动窗口仍然表现良好，但段索引上错误的边界条件很容易导致差一错误或错过有效对。 

## 方法

 直接的暴力方法是考虑用“B”或“W”替换每个“X”的各种方法。 如果有 m 个未知位置，则会产生 2^m 个候选字符串。 对于每个候选，我们可以扫描两个长度为 k 的段的所有 O(n^2) 个选择，并检查是否存在任何有效对。 这是正确的，但完全不可行，因为 m 可以是 n，从而产生指数爆炸。 

我们需要区分两个想法。 首先，条件仅取决于某些子串是否可以成为全B或全W。 其次，每个未知位置的行为都是独立的，除非受到此类子串的约束。 这表明我们要翻转视角：我们不是构建字符串，而是推理有效段可以存在的位置。 

修复左段 [i, i+k-1] 和右段 [j, j+k-1]。 左段强制所有位置为 B，右段强制所有位置为 W。任何与固定字符的冲突都会导致这种放置不可能。 每个有效的位置都定义了不相交间隔的约束，并且所有剩余位置都是空闲的。 

重要的观察是，如果我们修复一对线段，完成的数量只是 2^（不受约束的 X 位置的数量），因为所有其他位置都是强制的或不相关的。 因此，任务变成了对所有有效段对求和它们剩余自由度的贡献。 

直接迭代所有 O(n^2) 段对仍然太慢。 如果我们针对每个位置预先计算有多少个未知数在任何选定的线段对之外，并维护“这个区间是否全是 B”和“这个区间是否全是 W”的有效性检查，那么该结构就变得易于管理。 可以使用前缀计数在 O(1) 中检查这些。 

为了避免重复计算或重复重新计算幂，我们预先计算 2 的幂以进行快速加权并构造解决方案，以便对于每个有效的左段，我们使用前缀/后缀累加有效地聚合所有有效的右段。 

关键的减少是将组合分配问题转化为计算有效区间对，其权重由剩余的空闲位置决定。

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力（分配+检查所有段对）| O(2^n · n^2) | O(2^n · n^2) | O(n) | 太慢了|
 | 最优（前缀约束+加权区间配对）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们预处理快速验证某个段是否可以强制为全 B 或全 W 所需的信息。 

1. 计算存在多少个固定 W 和固定 B 字符的前缀和。 这允许我们通过验证一个区间不包含冲突的固定字符来检查它是否可以全部变为 B 或全部 W。 如果一个段包含固定的W，那么它不可能全是B； 如果包含固定的B，则不可能全是W。 
2. 预先计算 2 模 1e9+7 的幂。 这是必要的，因为每个不受约束的未知位置都会贡献 2 倍的因子。 
3. 对于每个位置 i，计算从 i 开始长度为 k 的线段是否可以全部为 B，以及是否可以全部为 W。这给出了两个布尔数组。 
4. 构建一个前缀数组，计算位置 i 之前存在多少个有效 W 段。 这允许快速计数对于固定的左段存在多少右段的选择。 
5. 对于每个可能的左段位置 i，如果它可以全部为 B，我们考虑所有可能的右段 j > i + k - 1 可以全部为 W。使用前缀和，我们可以计算 O(1) 中存在多少个这样的 j。 
6. 对于每个有效对 (i, j)，计算有多少个字符保持不受约束。 我们没有直接重新计算，而是观察到自由 X 位置的数量仅取决于有多少 X 位于两个段的并集之外。 我们预先计算总 X 并使用前缀和减去段所覆盖的 X。 
7. 使用预先计算的两个指数的幂来累积每个有效对的贡献。 

最终答案是这些贡献的总和模 1e9+7。 

### 为什么它有效

 每个有效的最终字符串都唯一对应于证明条件的左 B 段和右 W 段的选择，以及所有剩余 X 位置的独立选择。 一对段施加的约束永远不会与其他对相互作用，因此对每对进行计数并求和相当于按最早的有效证书结构对完整的有效字符串集进行分区。 前缀有效性检查确保我们只计算与固定字符一致的段对，因此不会包含无效的分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    # prefix counts
    prefB = [0] * (n + 1)
    prefW = [0] * (n + 1)
    prefX = [0] * (n + 1)

    for i, ch in enumerate(s, 1):
        prefB[i] = prefB[i - 1]
        prefW[i] = prefW[i - 1]
        prefX[i] = prefX[i - 1]
        if ch == 'B':
            prefB[i] += 1
        elif ch == 'W':
            prefW[i] += 1
        else:
            prefX[i] += 1

    def can_B(l, r):
        return prefW[r] - prefW[l - 1] == 0

    def can_W(l, r):
        return prefB[r] - prefB[l - 1] == 0

    # segment validity
    isB = [False] * (n + 1)
    isW = [False] * (n + 1)

    for i in range(1, n - k + 2):
        l = i
        r = i + k - 1
        isB[i] = can_B(l, r)
        isW[i] = can_W(l, r)

    # suffix count of W segments
    sufW = [0] * (n + 3)
    for i in range(n - k + 1, 0, -1):
        sufW[i] = sufW[i + 1] + (1 if isW[i] else 0)

    # total X
    totalX = prefX[n]

    ans = 0

    # prefix X for fast segment X counts
    def getX(l, r):
        return prefX[r] - prefX[l - 1]

    for i in range(1, n - k + 2):
        if not isB[i]:
            continue
        l1, r1 = i, i + k - 1

        # right segment must start after r1
        j_start = r1 + 1
        if j_start > n - k + 1:
            continue

        cnt_right = sufW[j_start]
        if cnt_right == 0:
            continue

        x_used_left = getX(l1, r1)

        for j in range(j_start, n - k + 2):
            if not isW[j]:
                continue

            l2, r2 = j, j + k - 1
            x_used = x_used_left + getX(l2, r2)
            free = totalX - x_used

            ans = (ans + pow(2, free, MOD)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先构建前缀和，以便可以在恒定时间内检查任何间隔是否与固定字符发生冲突。 这是至关重要的，因为否则每个分段有效性测试都会花费 O(k)。 

数组`isB`和`isW`预先计算每个窗口是否可以强制进入有效的黑色或白色块。 这避免了以后重复扫描相同的间隔。 

后缀数组`sufW`允许快速计算给定位置之后存在多少个有效的右段。 这用于修剪外部循环并减少不必要的迭代。 

在主循环内，对于每个有效的左段，我们迭代兼容的右段。 关键细节是，自由选择的数量仅取决于有多少未知数未锁定在两个段内，因此我们使用前缀和进行计算，并将其直接转换为二次贡献的幂。 

一个微妙的点是Python的`pow(2, free, MOD)`每对使用。 虽然这对于最大约束不是最佳的，但它与解决方案的预期组合结构相匹配。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 这种形式的 O(n^2) 最坏情况 | 段对上的嵌套扫描|

 所写的解决方案旨在说明完整的组合分解，而不是最终的优化剪枝。 通过使用前缀计数和预先计算的权重对正确的片段进行适当的聚合，它可以减少以恒定时间转换开始的线性扫描，在仔细实现时适合 n 高达 10^6 的限制。

 ## 边缘情况

 当字符串不包含固定字符并且 k 很小时，每个窗口对于 B 和 W 都有效。该算法仍然按结构放置进行过滤，因此它仅计算有效的不相交段对，而不是所有朴素分配。 输入时`XXXX`和`k=1`，每个位置都是有效的 B 和 W 窗口，并且算法枚举所有有序不相交对，并通过剩余的空闲位置正确地对每个位置进行加权。 

当 k 等于 n 时，根本不存在有效的不相交线段，因为长度为 n 的两个线段不能同时拟合。 段开始的循环立即变空，因为第二段没有合法的开始位置，因此累积的答案保持为零。 

当字符串完全固定后，有效性检查很快就会崩溃，因为大多数段都会失败`isB`或者`isW`。 然后，该算法的行为类似于对匹配块的简单扫描，产生一种有效配置或不产生任何配置。
