 ## 解决方案
 ## 问题理解

 我们得到一个由小字母表中的小写字母组成的字符串$k$，加上可以自由替换的通配符。 用该字母表中的字母替换每个通配符后，每个字母都会产生一个值：仅由该字母组成的最长连续块。 我们分别计算每个字母的最长运行，最终字符串的质量是这些字母中的最小值$k$价值观。 目标是为所有通配符选择替换，以使这个最小可能的最长运行值尽可能大。 

该结构是一种平衡的对抗性结构。 我们并不是试图最大化一个字母，而是确保每个字母都出现在最终字符串中某处相当长的连续片段中。 通配符充当灵活的粘合剂，可以分配给有助于平衡这些最长片段的任何字母。 

约束的长度很大，最多$2 \cdot 10^5$， 尽管$k$最多为 17。这立即排除了任何显式分配字符并为每个分配重新计算运行统计信息的方法。 即使存储每个字母的每个位置的完整状态，只有在它是线性或接近线性的情况下才是可接受的。$n$并且仅指数$k$， 自从$k$很小。 任何指数级的东西$n$或二次方$n$将会失败。 

当原始字符串中的一个字母太稀少时，就会出现一种微妙的失败情况。 例如，如果$k = 3$并且字符串仅包含两个字母和许多通配符，天真的贪婪填充可能会意外地将通配符过度集中到字母的子集中，从而使另一个字母仅出现在很小的片段中或根本不出现。 由于漏掉一个字母会导致该字母的得分为零，因此即使是一个不平衡也会破坏答案。 

另一个边缘情况是通配符位于不同字母的固定块之间。 例如，`"a???b"`和$k=2$需要决定是弥合差距还是分开它。 总是扩展现有块的幼稚策略会为一个字母生成过长的片段，而使另一个字母挨饿。 

## 方法

 暴力解释是将每个问号视为一个选择$k$字母。 这产生$k^q$可能性在哪里$q$是通配符的数量。 对于每个完全构造的字符串，我们扫描它并计算每个字符的最长运行$O(nk)$。 这太慢了，因为即使$q = 20$使$k^q$爆炸超出了可行性。 

关键的观察是，我们对字符的精确放置不感兴趣，而是对是否可以保证最小最长运行值感兴趣$x$。 如果我们确定一个候选人$x$，问题就变成了可行性检查：我们能否分配字母，使得每个字母至少有一个连续的长度段$x$？ 一旦重新构建，我们就可以二分搜索答案。 

对于固定的$x$，每个字母必须至少占据一段长度$x$。 这些段可以在通配符位置重叠，但不能在固定冲突字符中重叠。 这表明在位置上有一个贪婪或位掩码 DP 结构：我们尝试放置$k$将所需的段放入字符串中，同时遵守固定的约束。 

自从$k \le 17$，我们可以使用位掩码表示哪些字母已经分配了所需的段。 我们扫描字符串并尝试使用通配符作为灵活位置来扩展或开始段。 这导致对位置和掩码进行 DP，或者等效地对每个字母放置顺序进行贪婪的滑动窗口可行性检查。 

关键的简化是对于固定的$x$，每个字母独立地需要一个长度块$x$，我们只关心字符串是否可以划分为$k$这种可行的放置方式不会发生冲突。 这将问题简化为检查我们是否可以贪婪地放置$k$长度间隔$x$超过兼容位置。 

结合二分查找$x$和可行性检查$O(nk)$产生一个舒适的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(k^n \cdot nk)$|$O(n)$| 太慢了|
 | 二分查找+可行性DP|$O(nk \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题转化为测试是否有固定的候选答案$x$是可以实现的。 

1. 我们对答案进行二分搜索$x$0 到$n$。 

这样做的原因是单调性：如果我们可以确保每个字母都有一个长度游程$x$，那么我们也可以保证它对于任何较小的值。 
2.对于固定的$x$，我们将字符串预处理为一个结构，该结构允许检查长度是否为一个段$x$可以分配给给定的字母。 如果某个位置已经是该字母或者是通配符，则该位置可用于该字母。 
3. 对于每个字母，我们计算有效连续长度块的所有位置$x$可以开始了。 这可以通过滑动窗口来完成，该窗口跟踪窗口对于该字母是否有效。 
4. 我们将可行性检查减少到选择$k$不冲突的展示位置，每个字母一个，这样每个展示位置都覆盖该字母的一个有效窗口。 
5. 我们在已经分配的字母上维护一个位掩码 DP。 对于每个掩码，我们跟踪是否可以在没有重叠冲突的情况下放置所选的字母子集。 转换尝试将新字母分配给不与先前选择的间隔重叠的有效间隔。 
6.如果我们能达到全面罩$2^k - 1$， 然后$x$是可行的。 否则就不是。 

最终答案是最大的$x$这通过了可行性。 

### 为什么它有效

 每个字母通过其最大连续运行对目标独立做出贡献。 字母之间唯一的相互作用来自于位置的共同使用。 通过强制每个字母确保单个连续的长度块$x$，我们将全局约束转化为包装问题$k$间隔。 DP确保两个选择的区间不会发生冲突，而滑动窗口则保证每个选择的区间在原始字符串约束下都是有效的。 这种等价性保留了正确性，因为任何有效的最终着色都带有分数$x$必须包含这样的布局，任何成功的布局都可以扩展到完整的着色。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def can(x, s, n, k):
    if x == 0:
        return True

    # precompute valid windows for each letter
    valid = [[False] * (n + 1) for _ in range(k)]

    for c in range(k):
        ok = 0
        left = 0
        for r in range(n):
            if s[r] != '?' and ord(s[r]) - 97 != c:
                ok += 1

            while r - left + 1 > x:
                if s[left] != '?' and ord(s[left]) - 97 != c:
                    ok -= 1
                left += 1

            if r - left + 1 == x and ok == 0:
                valid[c][left] = True

    # dp over subsets of letters
    size = 1 << k
    dp = [False] * size
    dp[0] = True

    intervals = [[] for _ in range(k)]
    for c in range(k):
        for i in range(n - x + 1):
            if valid[c][i]:
                intervals[c].append((i, i + x - 1))

    for mask in range(size):
        if not dp[mask]:
            continue
        # find next letter
        for c in range(k):
            if mask & (1 << c):
                continue
            for l, r in intervals[c]:
                ok = True
                # check overlap with already used letters
                for c2 in range(k):
                    if mask & (1 << c2):
                        for l2, r2 in intervals[c2]:
                            if not (r < l2 or r2 < l):
                                ok = False
                                break
                        if not ok:
                            break
                if ok:
                    dp[mask | (1 << c)] = True

    return dp[size - 1]

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    lo, hi = 0, n
    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, s, n, k):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先二进制搜索答案。 这`can`函数检查是否可以达到给定的目标游程长度。 对于每个字母，它扫描所有可能的长度 -$x$窗口并标记那些不包含冲突的固定字符的窗口。 这些窗口代表该字母保证运行的有效位置。 

然后，位掩码 DP 尝试为每个字母分配一个不重叠的间隔。 每个 DP 状态代表已放置字母的子集。 转换尝试添加一个新字母，该字母具有不与先前选择的间隔相交的任何有效间隔。 如果所有字母都能放入，则配置可行。 

二分查找确保我们找到最大可行值。

 输入：```

```我们评估可行性$x=4$。 

| 步骤| 面膜| 行动| 结果 |
 | --- | --- | --- | --- |
 | 0 | 00 | 00 启动 DP | dp[00]=真 |

 该跟踪表明，两个字母都可以确保长度为 4 的有效块，而不会发生分配冲突。 DP 成功实现了全面遮罩，证实了可行性。

 ## 边缘情况

 当某些字母根本没有出现在初始字符串中时，就会出现关键边缘情况。 在这种情况下，为它们提供正运行长度的唯一方法是完全依赖通配符，并且如果未能同时为所有字母保留足够的通配符空间，则会导致错误的乐观答案。 可行性检查强制执行全局一致性，确保不会出现信件意外缺货的情况。 

另一种边缘情况是当字符串密集地交替固定字母时，导致通配符分散在不兼容的约束之间。 贪婪填充往往会错误地合并区域，但基于间隔的 DP 正确地拒绝会强制重叠的放置，即使在高度碎片化的输入中也能保持正确性。
