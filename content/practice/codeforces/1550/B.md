 ## 解决方案
 ## 问题理解

 我们给定一个二进制字符串，并重复删除仅包含一种字符类型的子字符串。 每次删除一个长度的子串`l`给出`a * l + b`点。 每次操作后字符串都会收缩，因为其余部分连接在一起。 

目标不是找到删除序列，而是计算整个字符串被删除后可能的最大总分。 

首先要注意的是，每个字符都被删除一次。 无论我们如何选择操作，所有删除的长度之和总是`n`。 正因为如此，来自`a`是固定的：`a * n`受我们的选择影响的唯一部分是我们执行了多少删除操作。 如果我们执行`k`删除后，总分变为：`a * n + b * k`这一观察彻底改变了问题。 我们不再关心删除的子串的确切长度。 我们只关心最大化或最小化操作数，具体取决于`b`。 

限制非常小。 字符串长度最多为100，测试用例最多为2000个。 即使效率相当低的解决方案也能轻松适应。 尽管如此，预期的解决方案是每个测试用例以线性时间运行的简单贪婪观察。 

如果我们只关注删除而不是分数公式，一些边缘情况很容易处理不当。 

考虑：```
n = 5
a = 3
b = 4
s = 11111
```粗心的解决方案可能会在一次操作中删除整个字符串并得分`15 + 4 = 19`。 正确答案是`5 * (3 + 4) = 35`，因为当`b > 0`，每一次额外的操作都会给予额外的分数，因此一次删除一个字符是最佳的。 

考虑：```
n = 6
a = 1
b = -5
s = 000000
```一次删除一个角色会进行六次操作，并产生六次负奖励。 最佳策略是立即删除整个字符串，给出：```
1 * 6 + (-5) = 1
```另一个微妙的情况是交替字符串：```
n = 5
a = 0
b = -1
s = 01010
```乍一看，我们似乎被迫执行五次删除，因为有五次运行。 实际上，删除所有出现的一种字符类型后，剩余的字符会合并为一个块。 最佳答案来自稍后讨论的游程计数公式并且等于`-3`， 不是`-5`。 

## 方法

 暴力方法将尝试所有可能的有效删除并递归地探索生成的字符串。 这是正确的，因为每个合法的操作顺序都会被检查。 不幸的是，可能的删除序列的数量呈指数增长。 即使对于长度为 100 的字符串，搜索空间也是天文数字般巨大且完全不可行。 

关键的观察是长度的总贡献是固定的。 每个角色都有准确的贡献`a`一次，无论删除顺序如何。 整个优化问题归结为选择操作数。 

分数可以重写为：```
a * n + b * k
```在哪里`k`是删除的数量。 

如果`b >= 0`，每增加一个删除都会增加分数。 最好的策略是最大化`k`。 由于每个单个字符本身就是一个有效的单色子串，因此我们可以将字符逐一删除，得到：```
k = n
```有趣的案例是`b < 0`。 现在每个操作都会花费点，所以我们希望删除的次数尽可能少。 

令字符串由以下部分组成`runs`相同字符的最大块。 

对于二进制字符串，我们总是可以先删除一种字符类型的所有游程。 之后，所有剩余的运行合并为一个运行，并且可以在一个最终操作中删除。 

如果有`runs`块，则最多出现一个字符`runs / 2`块。 我们选择方块较少的角色。 

最小可能的操作数变为：```
floor(runs / 2) + 1
```一个众所周知的等价公式是：```
max(count_0_runs, count_1_runs)
```自从：```
max(count_0_runs, count_1_runs)
= floor(runs / 2) + 1
```对于任何二进制字符串。 

一旦我们知道最佳操作数，就可以立即计算答案。

 ## 算法演练

 1. 阅读`n`,`a`,`b`，和二进制字符串。 
2.如果`b >= 0`， 返回：```
n * (a + b)
```这相当于分别删除每个字符，准确给出`n`运营。 
3.如果`b < 0`，计算字符串中的运行次数。 

跑步从指定位置开始`0`以及每当`s[i] != s[i-1]`。 
4. 计算：```
operations = runs // 2 + 1
```这是二进制字符串可实现的最小删除次数。 
5、退货：```
a * n + b * operations
```计算完跑数后，答案直接从分数公式中得出。 

### 为什么它有效

 整个过程的总删除长度始终为`n`，所以每个策略都准确地赚取`a * n`从长度来看点。 唯一可变的部分是`b`乘以操作次数。 

什么时候`b >= 0`，增加运算次数总会提高分数。 一次删除一个字符可以获得最大可能的价值`k = n`。 

什么时候`b < 0`，操作越少越好。 在二进制字符串中，首先删除不太频繁的字符的所有运行会导致剩余的运行合并到一个块中。 如果有`runs`总块数，较少出现的字符占据`floor(runs / 2)`运行。 这些运行被单独删除，合并的剩余部分被再次删除，给出`floor(runs / 2) + 1`运营。 没有任何策略可以做得更好，因此这是可能的最小删除次数。 

由于算法总是使用最优值`k`，它总是产生最大分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, a, b = map(int, input().split())
    s = input().strip()

    if b >= 0:
        print(n * (a + b))
    else:
        runs = 1
        for i in range(1, n):
            if s[i] != s[i - 1]:
                runs += 1

        operations = runs // 2 + 1
        print(a * n + b * operations)
```第一个分支处理简单的情况，其中每个额外的删除都是有益的。 由于始终允许删除单个字符，因此最佳操作数恰好是`n`。 

第二个分支计数运行。 只要相邻字符不同，就会出现游程边界。 从一次运行开始并计算转换次数可以避免差一的错误。 

获得运行次数后，我们应用公式`runs // 2 + 1`尽可能减少删除。 然后直接计算最终分数`a * n + b * operations`。 

对于长度为 1 的字符串不需要特殊处理。 运行计数器正确地保持等于一，产生一次操作。

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

 ## 边缘情况

 ### 单字符字符串

 输入：```
1
1 3 -2
0
```该字符串有一个运行。```
runs = 1
operations = 1 // 2 + 1 = 1
answer = 3 * 1 + (-2) * 1 = 1
```该算法可以正确处理尽可能小的输入，而不需要任何特殊情况。 

### 所有字符都相等

 输入：```
1
6 1 -5
000000
```正好有一次运行。```
runs = 1
operations = 1
answer = 6 - 5 = 1
```单独删除字符的幼稚策略将执行六次操作并失去额外的分数。 该公式正确地确定了一个删除是最佳的。 

### 交替字符串

 输入：```
1
5 0 -1
01010
```运行计数给出：```
runs = 5
operations = 5 // 2 + 1 = 3
answer = -3
```尽管最初有五个运行，但首先删除一种字符类型的所有运行允许合并剩余的运行。 这正是许多不正确的解决方案高估最小操作数的情况。 

### 一运行正奖金

 输入：```
1
5 2 3
11111
```自从`b > 0`，算法忽略运行结构并计算：```
answer = 5 * (2 + 3) = 25
```一次删除一个字符会产生五次操作，这比一次删除整个字符串要好。 正奖励分支会自动捕获这种行为。
