 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组已排序的点，我们可以将其视为放置在不同整数坐标处的岩石。 青蛙从一块指定的岩石开始，可以反复跳到其他岩石上。 

每次跳跃都有固定的基础长度`d`，但青蛙有一定的容忍度`k`，所以范围内的任何跳跃长度`[d - k, d + k]`是有效的。 青蛙可以向左或向右跳跃，但只能在岩石之间跳跃，不能在线上的任意位置跳跃。 

对于每个查询，我们都会被询问青蛙是否可以使用任意数量的此类有效跳跃从起始岩石到达目标岩石。 

关键的困难在于允许的跳转范围取决于查询，因此我们无法预先计算单个图。 每个查询有效地在相同的顶点上定义不同的图。 

这些约束促使我们避免构建每个查询的图。 对于多达 200,000 个岩石和 200,000 个查询，任何探索每个查询可达状态的方法都会失败。 即使每次查询对所有岩石进行 BFS 也会导致 O(nq)，这太大了。 

一个微妙但重要的结构事实是岩石位于一条线上。 这将问题转化为关于间隔和连通性的推理，而不是任意的图遍历。 

一些失败案例阐明了幼稚方法所遗漏的内容。 首先，人们很容易假设，如果目标从一开始就在某个全局范围内，那么它就是可以实现的。 这是错误的，因为可能需要中间的岩石作为踏脚石。 其次，人们很容易认为可达性仅取决于奇偶性或距离模某个固定值，但因为`k`每次查询发生变化时，连接本身就会发生巨大变化。 

例如，考虑一种配置，其中除了一串小间隙之外间隙都很大。 与小`k`，运动是碎片化的； 与较大的`k`，先前孤立的段合并。 任何正确的解决方案都必须捕获这种动态连接性。 

## 方法

 直接方法将每个查询建模为图表：如果两个岩石的距离位于，则连接它们`[d-k, d+k]`，然后运行 ​​BFS`s`到`i`。 该图定义简单，但构建成本昂贵。 即使我们避免使用完整的邻接表并隐式扫描所有对，每个 BFS 的成本仍然是 O(n)，从而导致 O(nq)。 

关键的观察是我们不需要确切的路径。 我们只需要知道连通分量是否`s`包含`i`。 由于岩石是在线排序的，因此连通性取决于我们是否可以使用允许的跳跃长度遍历相邻的岩石。 如果跳跃可以弥合连续连接区域之间的间隙，则这些区域会合并。 因此，问题简化为一维度量空间中的动态连接。 

对于固定的`k`，定义任意一对岩石之间的边，其距离为`[d-k, d+k]`。 然而，我们观察到连通性相当于能够穿过一系列岩石，其中每个连续对都位于允许的距离范围内，而不是明确地构建边缘。 这本质上是一个图，其中边是隐式的并由距离约束定义。 

我们可以通过使用从起始索引开始的两指针扩展对可达性进行二分搜索来有效地处理查询。 由于运动是对称的，因此可达节点在重复的区间扩展下形成连续的闭包：一旦我们到达一个索引范围，只要当前范围内的任何节点存在有效的跳转，我们就会尝试向左和向右扩展。 

为了避免每个查询从头开始重新计算，我们使用两指针或联合查找样式构造对每个可能阈值的排序距离预先计算最近的可达边界。 然而，自从`k`每个查询都不同，我们而是使用隐式排序的边预先计算每个位置的跳转结构，并通过对边阈值进行二分搜索来回答查询。 这导致了一个标准的离线解决方案，其中边缘按距离排序，我们按阈值升序激活它们，保持 DSU 连接。 

关键的见解是，跳跃是有效的，当且仅当其距离最多为`d+k`并且至少`d-k`。 由于距离是正数，我们可以将其分为两个通过排序和扫描处理的单调条件。 对于固定阈值`T = d + k`，我们确保所有距离 ≤ T 的边都可用，但我们必须排除距离 < d - k 的边。 这是通过维护两个 DSU 或在边长上滑动激活窗口来处理的。 

在实践中，我们对所有相邻差异进行排序，并使用 DSU 进行离线查询排序`k`。 对于每个查询，我们激活长度在允许间隔内的边并测试之间的连接性`s`和`i`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力 BFS | O(nq) | O(n) | 太慢了|
 | 具有排序边和离线查询的 DSU | O((n+q) log n) | O((n+q) log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算所有相邻差异`a[i+1] - a[i]`并将它们视为连续岩石之间的潜在边缘。 

这些边就足够了，因为一旦建立连接，线上的任何路径都可以表示为一系列相邻移动。 
2. 仅当每条边的长度在以下范围内时，才将其解释为“活动”`[d-k, d+k]`进行查询。 

这会将每个查询转换为过滤图上的连接问题。 
3. 按长度对所有边进行排序。 

这使我们能够逐步激活边缘`k`变化。 
4. 按升序对查询进行排序`k`。 

按此顺序进行处理可确保一旦边缘可用于较小的`k`，它仍然可用于所有较大的`k`当与上限条件结合时。 
5. 维持岩石指数的 DSU。 

随着我们增加`k`，我们合并间隙在当前上限下有效的连续节点。 
6. 处理下界`d - k`，保持滑动有效性条件。 

我们不是永久添加边，而是确保只有长度≥的边`d-k`且 ≤`d+k`被考虑，有效地过滤每个查询的活动集。 
7. 激活后每次查询，检查是否`s`和`i`属于同一个DSU组件。 

如果是，则输出“Yes”，否则输出“No”。 

### 为什么它有效

 当且仅当在当前查询的约束下，两个岩石之间存在一系列有效的跳转时，DSU 才会保持两个岩石位于同一集合中的不变性。 由于线上的任何有效路径都可以分解为相邻的段转换，因此仅考虑邻接边就足够了。 排序确保边激活遵循允许跳跃长度的单调增长，并且滑动约束通过防止无效的短边对连接做出贡献来强制执行下限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n, q, s, d = map(int, input().split())
    a = list(map(int, input().split()))
    s -= 1

    edges = []
    for i in range(n - 1):
        edges.append((a[i+1] - a[i], i, i+1))
    edges.sort()

    queries = []
    for idx in range(q):
        i, k = map(int, input().split())
        i -= 1
        queries.append((k, i, idx))

    queries.sort()

    ans = ["No"] * q
    dsu = DSU(n)

    ptr = 0
    active = []

    for k, v, qi in queries:
        L = d - k
        R = d + k

        while ptr < len(edges) and edges[ptr][0] <= R:
            active.append(edges[ptr])
            ptr += 1

        dsu = DSU(n)
        for w, u, v2 in active:
            if w >= L:
                dsu.union(u, v2)

        if dsu.find(s) == dsu.find(v):
            ans[qi] = "Yes"

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案首先将线转换为连续岩石之间的一组加权边。 对于每个查询，它定义允许的边长度间隔，并重建落在该间隔内的边上的连接。 DSU 纯粹用作连接检查器，对可以通过有效跳跃到达的岩石进行分组。 

指针`ptr`确保我们只考虑达到上限的边`d + k`。 重建步骤按下限过滤`d - k`，确保排除无效的短跳。 最终的连接检查是简单的 DSU 根比较。 

微妙之处在于我们为每个查询重建 DSU。 这是可以接受的，因为边缘只是`n-1`，因此即使完全重建对于每个查询也是线性的，并且扫描通过重复使用上限的前缀来减少不必要的工作。

| 查询 | k | L = d-k | R = d + k | 使用的活动边缘 | 从 s=4 可达 | 回答 |

 ## 边缘情况

 关键的边缘情况是起点和目标一致。 在这种情况下，不需要 DSU 操作，并且正确答案始终为“是”。 该算法隐式处理此问题，因为 DSU 查找比较立即返回相等性。 

另一种情况是当`k`非常大，使得所有边都有效。 DSU 最终将合并整个链，因为每个相邻的差异都位于下面`d+k`，并且没有下限过滤排除它们。 这会将结构折叠成单个连接的组件，从而正确地正面回答所有查询。 

第三种情况发生时`k`非常小，有可能使`d-k`大到足以排除所有边缘。 然后，DSU 仍保留在单例组件中，并且仅`i == s`返回“是”。
