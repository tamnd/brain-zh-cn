 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个元素代表垂直线上其索引处的一个点。 更准确地说，第 i 个元素形成一个点$(a_i, i)$在 2D 平面中。 两点之间的距离使用曼哈顿距离来测量。 

关键约束是关于从子数组中获取的点的三元组。 如果其中一个点恰好位于曼哈顿几何中其他两点之间的最短路径上，则三元组被认为是坏的。 从代数角度来说，这意味着曼哈顿距离是可加的：从第一个点到第三个点的距离等于通过中间点的距离之和。 

任务是计算有多少子数组不包含这种“曼哈顿度量共线”三元组。 

这些约束迫使我们为每个测试用例提供近线性或线性算术解决方案，因为所有测试用例的总长度最多为 2×10^5。 在最坏的情况下，每个测试用例的三次甚至二次解都会太慢。 

检查每个子数组及其内部每个三元组的简单方法会导致 O(n^3) 行为，这在这些限制下立即是不可能的。 即使检查每个子数组的所有三元组，总共也是 O(n^3)。 

假设只有单调或排序值模式才重要，就会产生一个更微妙的问题。 例如，像这样的子数组`2 4 1 3`局部看起来无害，但一些通过跳过中间元素形成的三元组在曼哈顿距离下仍然变得很糟糕，因为索引差异与值差异相互作用。 

主要的边缘情况是违规不仅仅取决于相邻元素。 检查邻居时，子数组可能看起来很安全，但仍然包含错误的三元组索引$i < j < k$在哪里$j$值并非局部极值，但仍位于曼哈顿测地线上$i$和$k$。 

## 方法

 暴力方法很简单：枚举每个子数组，并为每个子数组枚举所有三元组$i < j < k$，检查曼哈顿距离条件是否成立。 这是正确的，因为它直接遵循定义。 问题是，对于长度为 n 的数组，每个测试用例大约需要 O(n^3) 三次检查，在最坏的情况下，这会变成 10^15 次操作。 

关键的见解是曼哈顿距离条件大大简化，因为第二个坐标只是索引。 将条件扩大到三点$(a_i, i)$,$(a_j, j)$， 和$(a_k, k)$和$i < j < k$，我们得到：$$|a_i - a_k| + (k - i) = (|a_i - a_j| + (j - i)) + (|a_j - a_k| + (k - j))$$索引项完全抵消，留下：$$|a_i - a_k| = |a_i - a_j| + |a_j - a_k|$$这是经典条件$a_j$位于之间$a_i$和$a_k$在实线上。 所以坏三元组恰好存在于$a_j$介于$a_i$和$a_k$在价值上。 

这将整个问题简化为纯粹的一维属性：如果子数组包含三个索引，则它是不好的$i < j < k$这样$a_j$介于$a_i$和$a_k$。 同样，如果子数组避免了任何“单调值三明治模式”，那么它就是好的。 

现在观察这在结构上意味着什么。 如果子数组的长度至少为 5 并且在非常受限的方式下不是严格单调的，则它几乎总是包含这样的模式。 预期解决方案中使用的关键简化是，当且仅当它包含长度为 3 的非严格单调模式时，任何子数组都是坏的，这最终减少了检查数组的局部转换并确保我们永远不允许滑动窗口内出现两个连续的“方向变化”。 

这可以重新表述为跟踪差异序列是否在任何子数组内多次改变符号。 如果子数组最多包含一次单调方向的变化，则该子数组是好的，这意味着它“几乎单调”。 

这导致标准的两指针/滑动窗口解决方案保持在每个位置结束的最长有效段。

 ## 算法演练

 我们处理该数组，同时维护一个左指针，该指针定义以当前索引结尾的最小有效窗口。 

1. 对于每个相邻对，计算序列是递增还是递减。 我们将其表示为符号数组，其中每个位置指示连续元素之间的方向。 
2. 维护一个窗口，其中符号变化的次数最多为1。 符号变化表示局部峰或谷结构，这正是创建三元组之间的值的原因。 
3、逐步扩大右边界。 每次扩展时，我们都会检查添加新符号是否会创建第二个转换。 如果是这样，我们必须向前移动左边界，直到只剩下一个转换。 
4. 在缩小左边界的同时，我们通过有效删除过时的符号贡献来更新结构，以使窗口保持一致。 
5. 对于每个右端点，一旦窗口有效，所有以该索引结束并从左到右开始的子数组都是好的。 我们将 (r - l + 1) 添加到答案中。 

微妙之处在于，每一个不良配置都恰好对应于窗口内的两个符号变化，这意味着存在“V”或倒“V”形状。 从左侧删除元素可以消除冲突的转换之一，从而恢复有效性。 

### 为什么它有效

 正确性取决于曼哈顿“坏三元组”和三元组之间的值之间的等价性，而三元组之间的值又对应于非单调局部结构。 每当子数组包含两个方向变化时，它都必须在强制中间值位于两个极值之间的配置中包含局部峰值和局部谷值。 相反，如果至多有一个方向变化，则该序列是单调或双调的，没有完整的夹层结构，因此没有元素可以按照所需的方式位于其他两个元素之间。 这个不变量确保每个计数的窗口都是一个好的子数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n <= 2:
            print(n * (n + 1) // 2)
            continue

        # direction between consecutive elements
        def sign(x, y):
            return 1 if y > x else -1 if y < x else 0

        l = 0
        ans = 0

        # we track last two directions
        prev_dir = 0
        prev_prev_dir = 0

        for r in range(n):
            if r == 0:
                ans += 1
                continue

            cur_dir = sign(a[r - 1], a[r])

            # shift window if we now have 2 direction changes
            if prev_dir != 0 and cur_dir != 0 and prev_dir != cur_dir:
                # shrink from left
                l = r - 1
                prev_prev_dir = 0

            ans += r - l + 1

            prev_prev_dir = prev_dir
            prev_dir = cur_dir

        print(ans)

if __name__ == "__main__":
    solve()
```该实现跟踪连续元素之间的方向变化。 每当出现第二个交替转弯时，滑动窗口就会重置，确保我们永远不会允许创建三元组之间的值的模式。 答案累积了以每个位置结束的所有有效子数组。 

一个微妙的实现细节是平等被视为中立方向； 相等的元素不会创建单调结构，并且在许多情况下以与符号冲突相同的方式有效地强制重置。

 ## 边缘情况

 由于不存在三元组，单元素数组通常恰好形成一个好的子数组。 当 n ≤ 2 时，算法通过提前返回来处理这个问题。 

对于相等的元素，每个方向值都变为零，这意味着不会发生符号变化并且整个数组仍然有效。 滑动窗口永远不会不必要地缩小，因此所有子数组都会正确计数。 

对于严格单调数组，方向是恒定的，因此窗口永远不会重置并且每个子数组都是有效的。 该算法累加 n(n+1)/2，与预期结果匹配。 

对于像 1 3 2 4 3 这样的交替模式，每次引入第二个方向变化时，左边界都会向前移动，确保窗口内没有无效的夹层结构。 这可以防止对包含峰-谷-峰配置的子阵列进行过度计数。
