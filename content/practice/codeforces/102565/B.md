 ## 问题理解

 任务是评估以字符串形式编写的单个数学表达式。 该表达式包含整数、算术运算符和括号。 所需的结果遵循正常的数学优先顺序：首先是括号，然后是幂，然后是乘法和除法，然后是加法和减法。 具有相同优先级的运算符从左到右进行处理。 

困难不在于算术本身。 使用Python的直接实现`eval`或者递归解析器可能会失败，因为表达式长度可能达到 100000 个字符。 这个大小立即排除了重复复制大子字符串或构建深度递归解析树的方法。 O(n) 或 O(n log n) 解决方案是现实的目标，因为可能需要检查每个角色。 

该表达式还允许中间值为有理数，即使最终答案是整数。 执行整数除法的解决方案将默默地产生错误的答案。 例如，`(1/2)*2`应该评估为`1`，而整数除法会变成`1/2`进入`0`。 

另一个危险的情况是求幂。 用于输入`2^3^2`，许多编程语言对于结合性存在分歧，但是这个问题保证了指数部分是正整数而不是表达式。 处理乘法和除法等幂而不考虑给定结构的解析器可能会误读表达式，例如`35^66*0/35`。 

一元运算符也可能是错误的来源。 该语句保证它们总是被括号包围，因此像这样的表达式`(-5)`出现而不是独立的`-5`在解析过程中。 忽略此细节可能会导致负数处理不正确。 

## 方法

 一种简单的方法是重复查找优先级最高的操作，计算它，用它的结果替换它，然后继续，直到只剩下一个值。 这反映了人类评估表达式的方式并且很容易验证。 问题在于表达式的重复搜索和重建。 如果每个操作都需要扫描 100000 个字符的字符串的大部分，那么最坏的情况会变成二次方，大约 10^10 个字符操作，这远远超出了限制。 

关键的观察结果是该表达式已经具有严格的语法。 我们可以扫描表达式一次，同时保持当前的求值状态，而不是重复搜索下一个操作。 执行此操作的标准方法是基于堆栈的解析器。 

解析器将表达式分为值和运算符。 每当看到一个运算符时，就会将其优先级与在堆栈上等待的运算符进行比较。 较高优先级的操作会立即解决，而较低优先级的操作则会等待，直到必要的值可用。 括号用作暂时阻止计算的标记，直到出现匹配的右括号。 

因为在这个问题中幂总是具有简单的指数形式，所以在遇到它们时可以处理它们，而不需要更复杂的递归解析器。 有理中间值使用分数精确存储，避免浮点错误。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从左到右扫描表达式并标记数字、运算符和括号。 当找到完整的整数时，将其转换为精确的分数值。 从一开始就保持精确的分数可以防止以后出现精度问题。 
2.维护两个堆栈。 一个堆栈存储数字，另一个堆栈存储运算符。 当出现一个数字时，将其压入数字堆栈，因为只有在运算符将其与另一个值连接之前，它才能被组合。 
3. 当出现运算符时，解析已经在运算符堆栈上等待且具有更高或相同优先级的运算符。 相等优先级会立即解决，因为乘法、除法、加法和减法是左结合的。 
4. 当出现左括号时，将其作为特殊标记推送。 它将内部表达式与括号外部的操作分开。 
5. 当出现右括号时，重复应用运算符，直到删除匹配的左括号。 括号内的值现在已成为一个完整的表达式结果。 
6. 完整扫描完成后，应用运算符堆栈中的所有剩余运算符。 唯一剩下的数字就是最终值。 
7. 将最后的分数转换为整数并打印。 该问题保证了这种转换是准确的。 

为什么它有效：

 在扫描期间的每个点，堆栈准确地表示表达式中已读取但尚未最终确定的部分。 仅当未来的令牌仍可以更改计算顺序时，运算符才会保留在运算符堆栈上。 只要不再可能，就会立即应用该运算符。 由于运算符是根据所需的优先级和结合性规则删除的，因此每个运算都按照与数学计算相同的顺序执行。 

## Python 解决方案```python
import sys
from fractions import Fraction

input = sys.stdin.readline

def solve():
    s = input().strip()

    def precedence(op):
        if op == '^':
            return 3
        if op == '*' or op == '/':
            return 2
        if op == '+' or op == '-':
            return 1
        return 0

    def apply_op(nums, op):
        b = nums.pop()
        a = nums.pop()

        if op == '+':
            nums.append(a + b)
        elif op == '-':
            nums.append(a - b)
        elif op == '*':
            nums.append(a * b)
        elif op == '/':
            nums.append(a / b)
        else:
            nums.append(b ** a)

    nums = []
    ops = []

    i = 0
    n = len(s)

    while i < n:
        c = s[i]

        if c.isdigit():
            value = 0
            while i < n and s[i].isdigit():
                value = value * 10 + ord(s[i]) - ord('0')
                i += 1
            nums.append(Fraction(value))
            continue

        if c == '(':
            ops.append(c)

        elif c == ')':
            while ops[-1] != '(':
                apply_op(nums, ops.pop())
            ops.pop()

        else:
            while ops and ops[-1] != '(' and precedence(ops[-1]) >= precedence(c):
                apply_op(nums, ops.pop())
            ops.append(c)

        i += 1

    while ops:
        apply_op(nums, ops.pop())

    print(nums[0].numerator)

if __name__ == "__main__":
    solve()
```解析器使用`Fraction`因为中间除法可以创建非整数值。 例如，读完后`(1/2)`，堆栈包含精确的有理值而不是舍入的浮点近似值。 

数字解析器手动读取连续的数字。 这可以避免创建许多临时子字符串并保持扫描线性。 

优先级函数确定何时应执行在堆栈上等待的运算符。 比较使用`>=`因为同等优先级的操作是从左到右评估的。 

指数运算符与其他运算符略有不同。 该问题保证指数已经是正整数值，因此通过相同的堆栈机制应用它是安全的。 

Python 整数不会溢出，这很有用，因为中间值可能比最终答案大得多。

        if op in '+-':
            return 1
        return 0

        a = nums.pop()

            nums.append(a + b)
        elif op == '-':
            nums.append(a - b)
        elif op == '*':
            nums.append(a * b)

            nums.append(a / b)

            nums.append(b ** a)

        if s[i].isdigit():

 ## 边缘情况

 对于`(1/2)*2`，解析器首先评估括号内的除法。 数栈存储`1/2`准确地说，然后乘法将其与`2`生产`1`。 使用整数除法的解决方案将错误地输出`0`。 

为了`35^66*0/35`，解析器在乘法之前应用幂运算，因为求幂具有更高的优先级。 巨大的中间值不会引起问题，因为 Python 整数支持任意精度，并且后面乘以零会减少结果。 

为了`(5)`，左括号被存储为屏障，并在右括号出现时被删除。 该算法保持所包含的数字不变，产生`5`。 

为了`8/4/2`，第一个除法在第二个除法之前应用，因为当下一个运算符出现时，会立即解析同等优先级运算符。 评价变为`(8/4)/2`, 给予`1`而不是`4`。
