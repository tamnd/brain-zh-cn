 ## 解决方案
 ## 问题理解

 我们有一个 N × N 网格。 Flash 从左上角单元格开始。 对于从 1 到 2N-2 的每个距离值 d，我们考虑通过重复仅向下或向右移动可以到达的所有单元格，其中每次这样的移动都必须将与前一个单元格的曼哈顿距离恰好增加 d。 我们计算每个单元格在 d 的所有值中被标记的次数，并且我们需要最终计数为奇数的单元格数量。 

首先要注意的是，N 可以大到 10^9。 对网格进行模拟是不可能的，因为网格最多包含 10^18 个单元。 即使迭代一行或一条对角线也太昂贵了。 解决方案必须仅取决于坐标的数学属性。 

坐标 (i, j) 处的单元格仅受值 i + j - 2 的影响，因为每次允许的移动都会使 i + j 增加与其曼哈顿距离完全相同的量。 这将问题从二维过程转换为对角线上的计数值。 

主要边缘情况来自非常小的网格以及第一条和最后一条对角线。 对于 N = 1，起始单元格永远不会被计数，因此答案为 0。对于输入 1，输出为 0，因为没有要执行的移动。 如果不小心将起始单元格算作可到达单元格，则会返回 1。 

对于 N = 2，唯一标记的单元格是 (1,2) 和 (2,1)。 两个单元格的对角线值 i + j - 2 均为 1，并且 1 有一个除数，因此输出为 2。这捕获了意外忽略最小非零对角线的解决方案。 

对于较大的 N，最大可能的对角线值为 2N-2。 该实现必须避免迭代所有单元或所有对角线，因为 N 可能是十亿。 

## 方法

 直接方法将模拟 d 的每个值。 对于每个 d，我们可以保留一组当前可到达的单元格并重复应用转换。 这是正确的，因为它完全遵循定义，但网格大小使其不可能。 最坏的情况包含 10^18 个单元格，因此即使触摸每个单元格一次也是无法完成的。 

关键的观察是每个动作都是单调的。 如果我们使用基于零的坐标 x = i - 1 和 y = j - 1，则距离 d 的一次移动会使 x + y 恰好增加 d。 从 x + y = 0 开始，经过几次长度为 d 的移动后，我们只能到达 x + y 是 d 倍数的单元格。 

反方向也是如此。 如果 x + y = k * d，我们可以将所需的 k * d 总移动分成 k 个移动，每个移动总共包含 d 个步骤。 我们在这些移动中分配所需的向下和向右的步骤，因此该对角线上的每个单元格都是可到达的。 

因此，对于 s 的每个正除数，值 s = i + j - 2 的单元格都会被标记一次。 当整数是完全平方数时，正整数的约数个数正好是奇数。 这给我们留下了一个计数问题：有多少个单元格位于索引为完全平方数的对角线上？ 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N²) | O(N²) | 太慢了 |
 | 最佳 | O(平方(N)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 迭代可以作为对角线索引出现的每个完全平方值 s。 最大可能值为 2N-2，因此我们只需要达到该限制的平方。 
2. 对于每个这样的正方形 s，计算有多少个单元格满足 i + j - 2 = s。 这些单元格形成网格的一条对角线。 
3. 将所有这些对角线的尺寸相加。 总和就是最终答案，因为这些对角线有奇数个标记。 

对于对角线值 s，使用从零开始的坐标 x 和 y，我们需要 x + y = s，其中 0 ≤ x，y < N。有效 x 值的数量是该对角线与方形网格之间的交点的长度。 

为什么它有效：

对于单元格的对角线索引的每个除数，单元格都会被计数一次。 除数通常成对出现，一个低于平方根，一个高于平方根。 除数唯一没有不同伙伴的情况是当数字本身是平方时。 因此，当单元格的对角线索引是完全平方数时，单元格就准确地做出贡献。 计算方形索引对角线会计算每个且仅每个具有奇数标记计数的单元格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = 0
    limit = 2 * n - 2

    s = 1
    while s * s <= limit:
        d = s * s

        left = max(0, d - (n - 1))
        right = min(n - 1, d)

        if right >= left:
            ans += right - left + 1

        s += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该循环生成每个可能的方形对角线索引。 价值`d`表示从零开始的对角线 x + y。 

变量`left`和`right`描述x坐标的有效范围。 如果 x 是固定的，则 y = d - x，因此 x 必须保持在 0 和 N-1 之间，并且也将 y 保持在同一范围内。 将这两个范围相交即可得出对角线长度。 

该代码使用Python整数，因此即使答案可能很大，也不存在溢出问题。 边界计算是包容性的，这就是对角线尺寸为的原因`right - left + 1`。 

## 工作示例

 对于 N = 4，最大对角线索引为 6。平方索引为 1 和 4。 

| 方形对角线| 有效 x 值 | 细胞计数 |
 | ---| ---| ---|
 | 1 | 0 到 1 | 2 |
 | 4 | 1 至 3 | 3 |

 总数为 5，与样本相符。 计数的单元格恰好是第一个对角线上的两个单元格和第四个对角线上的三个单元格。 

对于 N = 5，最大对角线索引为 8。平方索引为 1 和 4。 

| 方形对角线| 有效 x 值 | 细胞计数|
 | ---| ---| ---|
 | 1 | 0 到 1 | 2 |
 | 4 | 0 到 4 | 5 |

 答案是 7。这个例子表明，当正方形对角线靠近中心时，它可以接触网格的整个宽度。

 ## 边缘情况

 对于 N = 1，没有正对角线索引。 该算法永远不会进入循环并返回 0，这与初始单元格未标记任何距离的事实相匹配。 

对于 N = 2，唯一可用的平方对角线索引是 1。对角线包含两个单元格，因此两个单元格都有一个除数，并且都对答案有贡献。 

对于非常大的 N，该算法从不构建网格。 它只访问最多 2N-2 的平方数，因此运行时间取决于输入的平方根而不是单元格的数量。
