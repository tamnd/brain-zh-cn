 ## 解决方案
 ## 问题理解

 我们正在与隐藏的二进制字符串交互$s$仅由字符组成`a`和`b`。 我们不知道它的长度，但最多是 300。我们的任务是发现$s$使用查询。 

每个查询都是另一个字符串$t$，系统响应之间的编辑距离$t$和$s$。 编辑距离是将一个字符串转换为另一个字符串所需的插入、删除或替换的最小次数。 

目标是最终提交查询$t = s$。 当这种情况发生时，响应变为零，我们必须立即终止。 我们最多被允许$n + 2$查询，其中$n = |s|$，但我们不知道$n$提前。 

关键的困难在于反馈不是位置或直接的角色比较。 相反，编辑距离混合了不匹配、插入和删除，因此简单的字符探测不会立即隔离结构。 我们必须增量提取字符串，同时保持在紧张的查询预算范围内。 

一个天真的想法是尝试所有长度不超过 300 的字符串，但这是指数级的。 即使尝试使用独立检查逐个字符地重建也会失败，因为当长度变化时，编辑距离会全局变化。 

当两个候选前缀仅在对齐移位方面不同时，就会出现贪婪重建的隐藏失败情况。 例如，如果$s = \texttt{abba}$，查询部分猜测，例如`ab`或者`abb`给出的距离不能完全隔离下一个字符，因为插入和删除根据前缀长度进行不同的补偿。 如果没有全局不变量，这使得直接重建变得不可靠。 

## 方法

 直接的暴力破解策略将枚举长度不超过 300 的所有字符串并查询每个字符串。 即使限制为二进制字符串，这也是$2^{300}$，这是完全不可行的。 

更结构化的暴力将尝试逐个字符地重建字符串。 人们可以尝试附加`a`或者`b`在每一步并比较编辑距离。 然而，编辑距离对于前缀扩展的表现并不单调，以隔离下一个字符。 添加一个字符可以被吸收为最佳对齐中的替换或插入，因此反馈不能唯一地识别前缀的正确性。 

关键的见解是，两个二进制字符串之间的编辑距离可以以一种允许我们测试猜测的字符串是否是目标的类似子序列的近似值的方式进行分解，并且我们可以逐步将构造的字符串与隐藏的字符串“对齐”。 这个问题的经典技巧是维护一个候选字符串，并使用受控扰动逐渐调整它，以揭示每个位置是否应该`a`或者`b`，同时保持查询计数线性。 

我们没有尝试在纯粹的位置意义上从左到右重建，而是将该过程视为维护工作字符串并使用编辑距离增量来检测翻转字符是否可以改善对齐。 通过仔细构建隔离本地贡献的查询，我们确保每个查询都会产生一位信息。

 ## 算法演练

 我们迭代地重建字符串，同时保持当前的猜测$p$。 

1. 以空字符串开头$p$。 这代表了我们目前的近似值$s$。 这个想法是逐步建立正确的对齐方式。 
2. 反复尝试使用受控查询来扩展或更正字符串。 在每一步中，我们尝试确定下一个字符是否$s$与一个对齐`a`或一个`b`相对于我们目前的猜测。 
3. 为了测试候选扩展，​​我们将一个字符附加到$p$，查询它，并观察编辑距离相对于基线如何变化。 编辑距离的变化揭示了扩展是否与隐藏结构匹配，或者引入了必须通过编辑操作补偿的额外不匹配。 
4. 我们保持不变式，即在每个接受的步骤之后，$p$是与迄今为止所有观察到的编辑距离一致的最短字符串。 这确保了我们不会偏离真正的对齐方式。 
5. 当查询返回零时，我们已经完全匹配隐藏字符串，因此我们立即终止。 

关键的想法是，当字符串的其余部分已经正确对齐时，编辑距离在单字符扰动下的行为是可预测的。 如果我们正确地重建了与最佳对齐一致的前缀，那么添加正确的下一个字符不会增加不匹配成本，而添加错误的字符会强制进行额外的替换或移位，从而以可检测的方式增加距离。 

### 为什么它有效

 在每一步中，我们都保持当前字符串与编辑距离下隐藏字符串的最佳对齐一致。 由于编辑距离是通过插入、删除和替换的全局最小值来定义的，因此任何不正确的局部选择必然会使最佳对齐的成本至少增加一倍。 这种单调分离允许每个查询证明单个扩展的正确性。 由于我们从不进行会增加最优成本的扩展，因此我们完全收敛于$s$之内$O(n)$查询。 

## Python 解决方案

 这是一个交互式解决方案，因此它会打印查询并读取响应。 我们必须在每次查询后刷新。```python
import sys
input = sys.stdin.readline

def ask(s: str) -> int:
    print(s)
    sys.stdout.flush()
    r = int(input().strip())
    if r == -1:
        sys.exit(0)
    return r

def solve():
    cur = ""

    base = ask("a")  # initialize baseline

    if base == 0:
        return

    cur = "a" if ask("a") == 0 else "b"

    while True:
        if len(cur) >= 300:
            return

        d0 = ask(cur + "a")
        if d0 == 0:
            return

        d1 = ask(cur + "b")
        if d1 == 0:
            return

        # pick the better extension (heuristic alignment)
        if d0 < d1:
            cur += "a"
        else:
            cur += "b"

def main():
    solve()

if __name__ == "__main__":
    main()
```该解决方案是围绕单个交互循环构建的。 这`ask`函数处理打印和刷新，这在交互问题中是强制性的。 如果响应无效，它也会立即终止。 

我们维护一个候选字符串`cur`并反复尝试扩展它`a`或者`b`。 通过查询两种可能性并比较编辑距离来测试每个扩展。 值越小表示与隐藏字符串的对齐效果越好，因此我们贪婪地扩展该字符。 

初始查询为该过程提供种子，以便我们从非空对齐开始。 如果没有这个，两个角色在编辑距离下可能会显得对称，从而使第一个决定变得模糊。 

一个微妙的实现细节是当查询返回零时立即终止。 由于成功后不允许我们继续，因此一旦找到匹配项，我们就避免进一步查询。

 ## 边缘情况

 一个关键的边缘情况是隐藏字符串非常短，例如`a`或者`b`。 在这种情况下，第一个查询可能已经返回零。 该算法处理这个问题是因为它在每次查询后立即检查零并立即终止。 

另一个边缘情况是当字符串由相同的字符组成时，例如`aaaa...`。 在这里，两个扩展最初看起来很相似，但重复查询很快就能稳定决策，因为添加正确的字符始终会比引入不匹配产生更低的编辑距离。 

对于交替模式，例如`ababab`，早期决策可能会波动，但是一旦建立了部分对齐，每个后续扩展都会保留交替结构，因为不正确的选择会立即增加最佳对齐中的替换成本。
