 ## 解决方案
 ## 问题理解

 我们正在模拟一个以离散动作演变的过程。 有一个容器一开始是空的，Alya 执行得完全一样`n`行动。 第一个动作是固定的：她总是添加一颗糖果。 之后，每个操作都取决于当前状态和不断增长的“批量大小”。 

从第二个动作开始，如果可能的话，她要么移除一颗糖果，要么添加一批糖果。 批次的大小不是恒定的。 每次她选择添加糖果时，她添加的数量都会比上次添加的数量多一倍。 因此，添加形成从 1 开始的严格递增序列，但与删除交错。 

我们给出了两个最终参数：动作总数`n`，以及最终的糖果数量`k`完成所有操作后仍保留在框中。 任务是确定她执行了移除操作的次数，相当于她吃了多少糖果。 

约束条件非常大，`n`最多 1e9。 这立即排除了对该过程的任何逐步模拟，因为即使是对动作的线性扫描也太慢了。 该解决方案必须依赖于从添加和删除交互方式中提取结构。 

当移除在早期占主导地位时，就会出现微妙的边缘情况，因为移除只会使计数减少 1，而添加的数量会增加。 试图“保持盒子非负”而不跟踪添加的全局结构的天真贪婪模拟将会失败。 例如，在频繁添加但早期删除稀疏的小场景中，幼稚的方法可能会低估未来大量添加的贡献，从而导致吃掉的糖果的最终重建不正确。 

关键的困难在于，我们没有被要求模拟这个过程，而是从确定性演化中重建一个缺失的统计数据。 

## 方法

 暴力方法将模拟每个`n`直接行动。 我们将维护当前的糖果数量，跟踪下一个添加大小，并根据我们是添加还是删除来增加计数器。 这很简单并且正确地反映了规则，但是当`n`很大。 在 1e9 步中，即使是简单的循环在 Python 中也太慢了。 

关键的观察结果是，该过程的结构在“添加大小”方面是单调的。 每次我们添加糖果时，数量都会严格增加，与移除量无关。 移除不会影响下一次添加的大小。 这将演化解耦为两个独立的计数器：发生了多少次添加，以及发生了多少次删除。 

让`e`是吃掉的糖果数量（移除）。 那么添加的次数就是`n - 1 - e`，因为第一步始终是加法。 添加的糖果总数是第一个糖果的总和`(n - e)`自然数。 从这个总数中，我们减去`e`对于移除，我们必须匹配最终值`k`。 

这将整个问题简化为求解涉及三角数和线性校正项的单个方程。 由于该函数是单调的`e`，我们可以使用二分查找来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n) | O(1) | O(1) | 太慢了 |
 | 对答案进行二分搜索 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 让`e`是吃掉的糖果的数量。 

1.修复`e`并将该过程解释为`n - e`加法运算总计。 第一个操作总是加法，所以有`n - e`从 1 开始增加添加量。 
2. 计算所有添加的糖果总数，作为第一个的总和`(n - e)`正整数。 这是一个三角形数字，代表插入操作的所有贡献。 
3. 减法`e`从这个总数中算出移除的糖果，因为每次移除都会使盒子恰好减少 1 颗糖果。 
4. 将最终的糖果数量与`k`。 这给出了单调关系`e`，因为增加`e`减少添加量并增加去除量。 
5. 使用二分查找`e`在范围内`[0, n]`找到匹配的唯一值`k`。 

### 为什么它有效

 关键的不变量是对于任何固定数量的移除`e`，最终的糖果数量就完全确定了。 加法的贡献仅取决于发生了多少加法步骤，而去除是独立的单位减法。 作为`e`增加时，我们同时减少加法次数并增加减法次数，因此最终得到的值会严格减少。 这种单调性保证了唯一的解决方案并证明了二分搜索的合理性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def calc(n, e):
    # number of additions = n - e
    a = n - e
    # sum of first a integers
    total_add = a * (a + 1) // 2
    # remove e candies
    return total_add - e

n, k = map(int, input().split())

lo, hi = 0, n
ans = 0

while lo <= hi:
    mid = (lo + hi) // 2
    val = calc(n, mid)
    if val == k:
        ans = mid
        break
    elif val > k:
        lo = mid + 1
    else:
        hi = mid - 1

print(ans)
```功能`calc`重建假设吃掉的糖果数量的最终糖果数量`e`。 二分查找探索所有可能的值`e`并使用单调性在每次迭代中丢弃一半的搜索空间。 

关键细节是将加法解释为自然数的前缀和。 一旦建立，其余的实现就是直接单调反转。

 ## 边缘情况

 一种重要的边缘情况是根本没有删除。 例如，输入`n = 10, k = 55`对应于获取所有添加并且从不使用吃操作。 该算法通过检查来处理这个问题`e = 0`，其中计算出的三角和已经等于最终值。 

当移除量最大时会出现另一种边缘情况。 如果`e = n`，那么除了强制的第一步之外就没有任何加法，系统很快就变成以减法为主。 该公式仍然适用，因为`n - e`在中间推理中变成零或负数，但二分查找限制`e`以便表达式在范围内保持有效。 

最后，情况`k`非常小，可以通过二分搜索自然处理，因为增加`e`减少最终值，并且搜索向更高的移除计数收敛，直到满足相等条件。
