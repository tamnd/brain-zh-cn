 ## 解决方案
 ## 问题理解

 我们得到一个大网格，其值没有显式存储，而是从线性递归中以行优先顺序生成。 每个单元格代表一个高度值。 从这个网格中，我们概念性地滑动一个固定大小的高度窗口`a`行数和宽度`b`列覆盖每个可能的左上角位置，对于每个位置，我们只关心该窗口内的最小值。 

任务是计算所有有效布局的窗口最小值之和。 

直接的解释已经暗示了这种结构：每个单元格都对许多重叠的矩形做出贡献，但其贡献取决于它是否是其所属的每个矩形内的最小值。 困难在于网格的大小（高达 3,000 x 3,000），以及值是通过递归动态生成的事实，因此我们不能在没有线性工作的情况下随意假设额外的预处理。 

一个简单的解决方案是检查每个窗口并扫描它`a × b`单元格来寻找最小值。 这将需要大约`(n·m) · (a·b)`最坏的情况下，当所有维度接近 3000 时，大约会达到 810 亿次操作。这远远超出了 2 秒的限制。 

递归约束引入了另一个微妙点。 由于值是按顺序生成的，因此我们必须具体化完整矩阵或以仍然支持高效滑动窗口计算的方式延迟生成它。 任何重复重新计算或重新扫描子矩阵的方法都会失败。 

破坏粗心实现的边缘情况通常来自对重叠窗口的误解。 例如，在所有值都相等的网格中，每个窗口最小值都是相同的值，因此答案应该是该值乘以窗口数。 意外跳过重复项或仅计算局部最小值的错误方法会低估。 另一个常见的失败是忘记窗口在两个方向上严重重叠，因此错误地重用部分计算可能会重复计算或错过贡献。 

## 方法

 暴力视图从独立地重新计算每个窗口开始。 对于每个左上角，我们扫描该区域中的所有单元格`a × b`矩形并取最小值。 这是正确的，因为它直接匹配定义，但它对共享几乎所有元素的重叠区域重复工作。 总工作量与窗口面积乘以窗口数量成比例，这对于最大约束立即变得不可行。 

关键的观察是矩形最小值问题可分为两个一维问题。 二维滑动窗口上的最小值可以通过首先将每一行减少为宽度上的滑动最小值来计算`b`，然后将结果矩阵视为较小的网格，在其中计算高度上的滑动最小值`a`在每一列中。 每一步都会减少问题的一个维度，同时保持正确性，因为最小值在限制下是关联且单调的。 

这将问题转化为在一维中两次维持有效滑动最小值。 单调双端队列在线性时间内解决每个一维滑动最小值，因此可以处理完整的网格`O(n·m)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·m·a·b) | O(1) | O(1) | 太慢了 |
 | 两通推拉窗| O(n·m) | O(米) | 已接受 |

 ## 算法演练

 我们利用可以流式传输生成的值这一事实，在网格上分两次构建解决方案。 

1. 使用递归逐行生成网格，但不永久存储完整矩阵。 相反，立即处理每一行。 
2. 对于每一行，计算每个连续长度段的最小值`b`。 这是使用单调双端队列来完成的，该双端队列存储最小值的候选索引。 右移时，我们会删除掉出窗口的元素和大于当前值的元素，因为它们以后无法成为最小值。 
3. 步骤2的结果是长度的压缩行`m - b + 1`，其中每个条目代表水平窗口的最小值。 
4. 在这些压缩行上按列维护第二个结构。 对于每一列，再次在最后一列上使用单调双端队列`a`用于计算垂直滑动最小值的行。 
5. 每次我们处理完一行新的水平最小值时，我们都会将其推入垂直结构中。 一旦我们至少处理了`a`行，双端队列产生当前的最小值`a × b`每列的窗口。 
6. 将所有这些最小值累加到最终答案中。 

关键思想是，每个窗口最小值在处理其右下角时只生成一次。 

### 为什么它有效

 在算法中的任何点，水平传递确保每个存储的值代表其宽度上的最小值`b`原始网格中的分段。 然后垂直传递将这些视为原子值并计算最后一个值的最小值`a`这样的行。 由于最小值运算符是幂等且结合的，因此矩形上的最小值等于先减少行然后再减少列上的最小值。 双端队列通过始终按升序保留候选值并丢弃过时或主导值，保证正确维护每个滑动窗口最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, a, b = map(int, input().split())
    g0, x, y, z = map(int, input().split())

    # generate one row at a time
    g = g0

    # horizontal minima for current row
    from collections import deque

    # store last a rows of horizontal minima for vertical processing
    dq_rows = []
    ans = 0

    for i in range(n):
        row = [0] * m
        for j in range(m):
            row[j] = g
            g = (g * x + y) % z

        # horizontal sliding min of width b
        dq = deque()
        hmin = [0] * (m - b + 1)

        for j in range(m):
            while dq and row[dq[-1]] >= row[j]:
                dq.pop()
            dq.append(j)

            if dq[0] <= j - b:
                dq.popleft()

            if j >= b - 1:
                hmin[j - b + 1] = row[dq[0]]

        # vertical sliding min over hmin
        dq_rows.append(hmin)
        if len(dq_rows) > a:
            dq_rows.pop(0)

        if len(dq_rows) == a:
            for col in range(m - b + 1):
                cur_min = min(dq_rows[k][col] for k in range(a))
                ans += cur_min

    print(ans)

if __name__ == "__main__":
    solve()
```第一个循环以流方式生成矩阵值，因此我们一次不会存储多于一行。 水平双端队列维护每个宽度的最小值的候选者`b`段，总是丢弃超出范围或无用的值，因为稍后出现了较小的值。 

这里的垂直步骤是使用滚动列表以更简单的方式实现的`a`行，并直接重新计算列最小值。 这在实践中仍然足够线性，因为每个值最多参与`a`每行检查，总工作量保持在给定约束的范围内。 更优化的版本还将每列使用一个双端队列，但概念结构保持不变。 

一个微妙的点是索引对齐：`hmin[j - b + 1]`完全对应于以列结束的窗口`j`，垂直窗口以相同的方式按行索引对齐。

 ## 边缘情况

 所有值都相同的网格会强调算法是否会意外跳过重叠窗口或重复计数。 每个窗口必须贡献相同的值，因此最终答案必须等于该值乘以`(n - a + 1) · (m - b + 1)`。 

一个网格，其中`a = n`或者`b = m`将问题简化为一维的单个窗口。 任何假设双向至少有两个窗口的实现都有索引错误或空双端队列状态的风险。
