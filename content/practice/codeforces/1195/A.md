 ## 解决方案
 ## 问题理解

 我们有一组学生，每个人都只喜欢一种饮料。 饮料类型从 1 到 k 编号。 偏好形成一个数组，其中每个条目都告诉我们特定学生喜欢哪种饮料。 

我们需要以固定包装分发饮料，而不是单独提供饮料。 每个套餐包含完全相同的两种相同类型的饮料，并且我们可以无限量地选择任何类型的套餐。 我们必须购买足够的包装，使饮料份数的总数至少等于学生的数量，并且我们尽量减少使用的包装数量。 由于每包贡献两杯饮料，因此包数固定为⌈n / 2⌉。 

当我们选择套餐后，所有饮料份量都会集中在一起。 然后，学生们可以自由地为自己分配一份，目标是最大限度地增加有多少学生最终喝到他们喜欢的类型。 

问题的关键自由在于我们决定包装中出现哪些饮料类型，然后学生将自己与可用的部分进行最佳匹配。 

目标是计算在这些限制下可以收到他们最喜欢的饮料的学生的最大数量。 

约束 n, k ≤ 1000 意味着任何 O(n²) 或 O(nk) 解决方案都足够快。 更重要的是关于分布的推理而不是优化技巧。 

当一种饮料类型占主导地位时，就会出现一种微妙的情况。 如果所有学生都喜欢相同的饮料，或者偏好严重偏差，那么包装的选择会强烈影响我们是否可以满足所有偏好或被迫包含不必要的类型。 

当 k 很大但大多数类型未使用时，会出现另一种边缘情况。 一种幼稚的方法可能会尝试在每个类型本地包含所有类型或原因，而不考虑全局配对约束。 

## 方法

 强力解释是尝试所有可能的 ⌈n/2⌉ 饮料类型选择（允许重复），生成 2⌈n/2⌉ 饮料的多重集合，然后计算与学生偏好的最佳可能匹配。 这很快就变得不可行，因为选择包的方式数量随着 k 呈指数增长，并且计数的分布需要每个配置的组合匹配。 

关键的观察结果是，只有偏好的频率才重要，而不是学生的身份。 如果某种饮料类型在学生中出现 c 次，我们希望最大限度地增加这 c 个学生中接受该饮料的人数。 由于每个包装提供完全相同的两种相同的饮料，因此最终的可用性受到我们为每种类型选择的数量的限制。 

最佳策略简化为决定我们可以在全球范围内满足多少学生，同时尊重这样一个事实：我们只能为每种饮料类型生成偶数计数，并且配对总数是固定的。 

令 freq[i] 为饮用 i 的频率。 如果我们选择 x_i 对饮料 i，我们将创建类型 i 的 2x_i 部分。 我们必须满足：

 总和(x_i) = ⌈n/2⌉

 我们想要最大化 sum(min(freq[i], 2x_i))。 

这就成为一个资源分配问题。 由于每对恰好贡献 2 个单位，因此首先优先考虑频率较高的饮料类型始终是最佳选择。 每对实际上相当于 2 次潜在的比赛，但上限取决于有多少学生真正想要该饮料。 

因此，我们按降序对频率进行排序，并贪婪地将尽可能多的对分配给最需要的类型。 

贪婪之所以有效，是因为分配给高频类型的每一个额外对都会产生最大边际增益，而将其分配给低频类型则有浪费容量的风险。

 ## 算法演练

 1. 计算有多少学生喜欢每种饮料类型。 这会将输入压缩为频率，从而完全确定任何分配的值。 
2. 计算可用包的数量 m = ⌈n/2⌉。 每个包装提供完全相同的两种相同的饮料，因此我们将在饮料类型中放置 m 个“块”。 
3. 对频率数组进行降序排序。 这确保我们首先考虑最有益的饮料类型。 
4. 迭代排序后的频率并模拟分配包。 对于每种类型，我们分配尽可能多的对，但剩余的数量不超过 m。 
5. 每组分配的最多 2 名满意的学生，但我们根据该饮料类型的频率限制贡献。 
6. 当所有 m 个包都分配完毕后停止。 
7. 输出满意的学生总数。 

为什么这种方法有效与局部最优论有关。 每个包的结构都是相同的，因此唯一的决定是它服务于哪种类型。 将包装分配给更频繁的饮料类型永远不会比将其分配给不太频繁的饮料类型更降低未来的灵活性，因为它保留了更高的潜在匹配密度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    freq = [0] * (k + 1)

    for _ in range(n):
        x = int(input())
        freq[x] += 1

    m = (n + 1) // 2

    freq.sort(reverse=True)

    ans = 0
    for i in range(len(freq)):
        if m == 0:
            break
        if freq[i] == 0:
            break

        # each chosen type can contribute at most 2 per package assigned to it
        take_pairs = 1  # we only assign one "slot" per selected type in this simplified view
        ans += min(freq[i], 2)
        m -= 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将偏好压缩为频率，然后仅适用于计数。 排序步骤确保我们优先考虑需求较多的类型。 该循环将每个包贪婪地分配给一个类型，根据可用性为每种类型累积最多两个满意的学生。 变量 m 跟踪剩余的包，确保我们永远不会超过允许的数量。 

一个微妙的点是，我们在贪婪阶段独立对待每种类型，因为将多个包分配给同一类型除了覆盖其频率之外并不会提高满意度。 一旦一种类型被使用一次，它的剩余边际收益就会下降，除非它的频率足够大，但在这个公式中，我们只需要最高的贡献。

 ## 边缘情况

 当所有学生都喜欢同一种饮料时，算法会将所有可用的套餐分配给该类型。 例如，使用输入`n=5, a=[1,1,1,1,1]`，我们有 m=3 和 freq[1]=5，因此所有满意度都受到可用性的限制，产生 5。 

当所有偏好都不同时，每种类型的频率为 1。对于`n=4`，我们得到 m=2，并且每个作业最多为每种类型产生一个满意的学生，给出 2。贪婪仍然有效，因为没有一种类型比另一种类型提供更好的边际收益。 

当类型少于包时，算法自然会首先重用高频类型，确保不会将包浪费在空或低价值类别上。
