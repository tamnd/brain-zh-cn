 ## 解决方案
 ## 问题理解

 在每个位置`i`，我们有一对值`(a[i], b[i])`。 唯一允许的操作是交换同一对内的两个值。 我们可以为任何职位独立执行此操作。 

选择要交换的对后，我们获得最终的数组`a`和`b`。 成本是第一个数组中相邻元素之间的绝对差值加上第二个数组中相同数量的总和：$$\sum_{i=1}^{n-1} \left(|a_i-a_{i+1}| + |b_i-b_{i+1}|\right)$$任务就是尽量减少这种成本。 

关键的观察是位置交换`i`仅影响该对`(a[i], b[i])`。 它永远不会改变其他指数的值。 由于目标仅包含相邻的指数对，因此位置的贡献`i`和`i+1`可以独立于阵列的其余部分进行分析。 

限制小得惊人。 每个数组的长度最多为 25，尽管可能有多达 4000 个测试用例。 对所有交换配置进行强力搜索仍然是不可能的，因为每个位置都有两个选择，产生`2^n`配置。 为了`n = 25`，即每个测试用例有超过 3300 万种可能性。 

一个常见的错误是认为不同职位的决策在全球范围内相互作用并且需要动态规划。 他们确实相互作用，但这种相互作用是极其本地化的。 一旦我们理解了成本函数的结构，每个相邻对就可以独立优化。 

考虑：```
a = [1, 10]
b = [10, 1]
```如果没有掉期，成本是$$|1-10|+|10-1|=18.$$交换一个位置给出```
a = [1,1]
b = [10,10]
```有成本`0`。 

贪心规则，例如“每当`a[i] > b[i]`“在许多例子中都会失败，因为目标取决于相邻位置，而不是单个对本身。

 当值已经排序时会发生另一种微妙的情况：```
a = [1,2,3]
b = [6,7,8]
```任何交换只会将小数与大数混合并增加相邻差异。 什么都不做就能得到最佳答案。 始终对对进行归一化而不检查实际贡献的算法可能会产生更大的成本。 

## 方法

 最直接的解决方案是尝试每个交换配置。 每个位置可以保持不变或交换，给出`2^n`的可能性。 对于每种配置，我们可以计算出最终的成本`O(n)`时间。 

蛮力方法是正确的，因为它明确地检查每个可能的最终状态。 问题在于搜索空间的大小。 为了`n = 25`，我们大约需要$$2^{25} \approx 3.3 \times 10^7$$单个测试用例的配置，远远超出了时间限制。 

要找到更好的东西，请查看目标的一项：$$|a_i-a_{i+1}| + |b_i-b_{i+1}|.$$仅职位`i`和`i+1`出现在这个表达式中。 让这对处于位置`i`是`(x,y)`和位置对`i+1`是`(u,v)`。 

对于这两个位置，我们可以选择任一方向：```
(x,y) or (y,x)
(u,v) or (v,u)
```假设我们总是对每一对重新排序，使较小的值排在前面：$$l_i = \min(a_i,b_i), \qquad r_i = \max(a_i,b_i).$$现在考虑相邻位置的贡献：$$|l_i-l_{i+1}| + |r_i-r_{i+1}|.$$其他方向可能会更好吗？ 

对于两对，唯一的可能性是：$$|x-u|+|y-v|$$或者$$|x-v|+|y-u|.$$线上的标准不等式指出，将较小的值匹配在一起和将较大的值匹配在一起永远不会比交叉连接更糟糕：$$|x-u|+|y-v| \le |x-v|+|y-u|$$每当$x \le y$和$u \le v$。 

在内部对每对进行排序后，每个相邻的贡献都会独立最小化。 由于总目标只是所有相邻贡献的总和，因此对每对进行一次排序是全局最优的。 

解决方案变得非常简单：将每一对替换为`(min, max)`，然后计算最终成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | 最佳 | 每个测试用例 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 对于每个位置`i`, 替换该对`(a[i], b[i])`和`(min(a[i], b[i]), max(a[i], b[i]))`。 

这修复了最小化涉及该位置的所有未来相邻贡献的方向。 
2. 初始化答案`0`。 
3. 对于每对相邻的索引`i`和`i+1`， 添加$$|a_i-a_{i+1}| + |b_i-b_{i+1}|$$到答案。 

在第 1 步之后，这些数组已经代表了每对数组的最佳方向。 
4. 输出累加和。 

### 为什么它有效

 对于任何相邻索引，让$$x=\min(a_i,b_i), \quad y=\max(a_i,b_i),$$和$$u=\min(a_{i+1},b_{i+1}), \quad v=\max(a_{i+1},b_{i+1}).$$这两个位置的贡献是$$|x-u|+|y-v|$$或者$$|x-v|+|y-u|.$$自从$x \le y$和$u \le v$，将较小的值配对在一起和将较大的值配对在一起永远不会大于交叉配对。 因此，排序的方向最小化了该相邻对的贡献。 

总目标是这些相邻贡献的总和。 通过相同的局部选择来最小化每一项，即将每对中较小的元素放入第一个数组中，将较大的元素放入第二个数组中。 由于每一项同时最小化，因此总和也最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        for i in range(n):
            if a[i] > b[i]:
                a[i], b[i] = b[i], a[i]

        ans = 0
        for i in range(n - 1):
            ans += abs(a[i] - a[i + 1])
            ans += abs(b[i] - b[i + 1])

        print(ans)

solve()
```第一个循环标准化每一对，以便`a[i] <= b[i]`。 这是关键的贪心步骤。 转换之后，每个相邻的贡献都已处于最佳形式。 

第二个循环完全按照定义计算目标。 由于答案可能大于 32 位整数限制，因此使用 Python 整数可以自动避免溢出问题。 

一个常见的实施错误是在执行所有交换之前计算答案。 证明依赖于首先对每对进行归一化。 另一个错误是忘记贡献包含两个数组，而不仅仅是其中一个。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
2
1 10
10 1
```标准化后：```
a = [1,1]
b = [10,10]
```唯一相邻的贡献是$$|1-1|+|10-10|=0.$$算法输出`0`，这是最优的。 

考虑每个值都相同的输入：```
1
4
5 5 5 5
5 5 5 5
```标准化不会改变什么。 每个相邻的差值都为零，所以答案是`0`。 该算法正确地避免了引入任何人为成本。 

考虑一个没有交换帮助的情况：```
1
3
1 2 3
6 7 8
```所有对都已经满足`a[i] <= b[i]`。 计算出的答案是$$(1+1)+(1+1)=4.$$任何交换都会混合小值和大值，并增加至少一个相邻的贡献。 该算法保持数组不变并返回最优值。 

考虑高度交替的输入：```
1
3
10 1 10
1 10 1
```标准化产生```
a = [1,1,1]
b = [10,10,10]
```每个相邻的贡献都变为零。 这证实了关键的不变量：将每对中较小的元素放入第一个数组中，将较大的元素放入第二个数组中，同时最小化目标的每个相邻项。
