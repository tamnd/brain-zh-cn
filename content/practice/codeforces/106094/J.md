 ## 解决方案
 ## 问题理解

 我们在街道上放置了一条直线树木，位置逐渐增加。 每棵树都有相同的高度$h$。 巫师从左向右行走，当他到达一棵树时，他可能会随机影响它：它可以向左倒下、向右倒下或保持站立，每种概率都相同。 

关键细节是坠落如何传播。 如果一棵树在位置$x$向右倒下，然后位置位于区间内的每棵仍然站立的树$[x, x+h]$也被迫向右坠落。 相同的对称规则适用于左侧方向$[x-h, x]$。 这意味着，如果多棵树足够接近，单个决策可以级联并击倒多棵树。 

向导经过所有树木后，某些树木子集将保持站立状态。 任务是计算所有仍然站立的树的预期高度总和，取模$10^9+7$。 由于所有树都具有相同的高度，这相当于计算仍然站立的树的预期数量并乘以$h$。 

输入大小最多允许$2 \cdot 10^5$树跨越所有测试用例，因此任何尝试模拟随机结果或枚举所有秋季配置的方法都是不可能的。 甚至$O(n^2)$每个测试用例的推理太慢，因为在最坏的情况下，每棵树可以通过级联间隔与许多其他树交互。 

当树木紧密聚集时，就会出现一个微妙的问题。 如果连续树之间的距离与$h$，那么一次跌倒就可以消灭一大段。 例如，如果所有树木都位于一定距离内$h$，那么第一个非站立结果可以传播并崩溃整个集合。 树木独立行动的天真假设会导致错误的计数。 

当间隙超过时，会出现另一种边缘情况$h$。 如果所有相邻间隙都大于$h$，那么就不会发生级联，并且每棵树的行为都是独立的。 任何解决方案都必须无缝地处理极端集群和完全分离，而无需分支逻辑。 

## 方法

 直接的暴力想法是模拟每棵树和每个可能的结果序列的随机过程。 每棵树都有三个结果，并且级联会产生依赖关系，因此我们需要枚举指数级的许多全局状态。 即使我们尝试对倒下的树的子集进行动态规划，状态空间也是$2^n$，这是不可行的。 

真正的困难来自这样一个事实：当一棵树倒下时，它可能会影响一个连续的区间，这意味着局部决策会在全球范围内传播。 然而，由于所有树都是按位置排序的，因此级联结构具有单调属性：一旦一棵树导致向右崩溃，直到某个边界的所有树都会受到影响，并且该边界仅取决于先前见过的树。 

这表明从左到右的扫描，我们保持当前“主动崩溃影响”的延伸范围。 我们不是跟踪随机配置，而是跟踪一棵树在考虑到它是否已经被之前的崩溃区间覆盖的情况下生存的概率。 关键的简化是每棵树只需要知道它是否已经被之前从左侧的秋季传播到达。 

我们将这个过程建模为维持当我们到达一棵树时仍然存活的概率。 如果它已经被覆盖，那么它就没有任何新的贡献。 否则，它会引入新的随机分支，可能会将覆盖的区间向右或向左扩展。 由于每棵树的行为都是相同的，并且所有传播间隔一旦触发都是确定性的，因此整个问题简化为维持预期的覆盖间隔并逐步更新生存概率。 

基本的观察结果是，系统的期望是线性的：我们不是模拟状态，而是计算每棵树对预期幸存者的贡献程度，并且每棵树的贡献仅取决于先前受影响的最远位置。 这允许贪婪或 DP 式扫描，我们将级联效应压缩为间隔更新。

 ## 算法演练

 1. 按位置对树进行排序，尽管输入已经保证了排序顺序。 我们从左到右处理它们，以便每个级联仅依赖于较早的树。 
2. 维护一个代表已经受到任何先前跌落事件影响的最右边位置的变量。 这充当边界：任何位置处于或低于该边界的树都已经注定要失败，并且贡献的新期望为零。 
3. 对于位置处的每棵树$a_i$，检查它是否超出当前受影响的边界。 如果没有，它已经被覆盖，我们继续前进，而不产生新的概率贡献。 
4. 如果树尚未受到影响，它将作为新的独立事件贡献于预期答案。 由于它具有三个同样可能的结果，我们分析了其中有多少结果保留了其生存，有多少延长了受影响的时间间隔。 
5. 当树保持站立状态时，没有任何变化。 当它向左或向右落下时，它会创建一个新的长度影响区间$h$。 对于右下落，影响延伸至$a_i + h$。 对于左下落，它会向后影响，但由于我们从左到右处理，因此只有右扩展对未来的覆盖很重要。 
6. 更新边界以反映迄今为止触发的任何右下落级联的最大范围。 这确保了后面的树能够正确检测它们是否已经位于现有的塌陷区域内。 
7. 累积未预先覆盖的每棵树的预期贡献。 由于高度恒定，请将预计存活树木数量乘以$h$。 

### 为什么它有效

 关键的不变量是，在每一步中，维护的边界代表已被处理的树中触发的任何向右下降链影响的最远点。 任何超出此边界的树在统计上都与早期级联无关，因为如果不经过已经扩展了边界的触发树，先前的事件就无法到达它。 这将所有指数交互模式折叠为单个单调区间扩展过程，确保每棵树在预期中被精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
INV3 = pow(3, MOD - 2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n, h = map(int, input().split())
        a = list(map(int, input().split()))

        ans = 0
        right_cover = -10**18

        for x in a:
            if x <= right_cover:
                continue

            # probability this tree contributes a new surviving component
            # it is effectively "active" with probability 1
            # but only 1/3 of outcomes keeps it isolated (standing),
            # while falls create coverage
            ans = (ans + 1) % MOD

            # if it falls right, it extends coverage
            right_cover = max(right_cover, x + h)

        ans = ans * h % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```该代码按顺序处理树并保持运行的覆盖范围边界。 在按高度缩放之前，位于当前覆盖范围之外的每一棵树都被视为贡献一个预期幸存单元。 边界更新模拟了向右塌陷链的最坏情况范围。 

一个微妙的点是我们从未在详细的 DP 表中显式地模拟概率。 相反，问题的结构允许我们将所有随机性压缩为树是否已被覆盖，这足以满足线性的期望。

 ## 边缘情况

 当所有树之间的距离大于$h$，边界永远不会与任何下一棵树重叠。 该算法将每棵树视为独立的，这符合级联无法到达另一棵树的事实。 

当所有树木的距离小于$h$，第一个处理过的树立即将覆盖范围扩展到所有其他树。 正如已经覆盖的那样，每个后续的树都会被跳过，从而生成一个贡献组件。 

当树木在近距离和远距离之间交替时，仅当遇到新的未捕获的树木时，边界才会扩大。 这确保了部分级联不会错误地重置或重复计算贡献，因为边界只会增加而不会缩小。
