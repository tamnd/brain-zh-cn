 ## 解决方案
 ## 问题理解

 我们被要求建立一个从 1 到 n 的数字子集，使得在这个子集上计算的一个非常具体的数量恰好等于 k。 该数量对不同元素 (a, b) 的有序对进行计数，其中 a 的值早于 b 出现，并且 a 整除 b。 换句话说，我们查看所有选定的数字，并计算较小的选定数字是较大选定数字的约数的次数。 

思考这个问题的一个有用方法是，对于每个选定的严格较小的 b 的除数 a，每个选定的数字 b 都会对答案做出一次贡献。 因此，每个元素都从其除数中“收集贡献”，这些除数也存在于集合中。 

输入大小通常允许 n 达到 10^5 左右，因此任何尝试所有子集的解决方案都是立即不可能的。 在密集情况下，即使迭代子集中的所有对也会太慢，因为子集的大小可能是线性的，从而导致二次行为。 然而，整除性的结构是高度不均匀的：大多数数字几乎没有大的二次方链和相对稀疏的除数，这表明基于乘法结构而不是任意组合的构造。 

一个微妙的问题是，多个构造可以产生相同的 k，但并非所有 k 值都可以实现。 例如，如果 n 很小，则可能根本没有足够的可整除结构来形成大 k。 另一方面，贪婪地选择太多数字往往会超出 k，因为可整除性链会导致对数量呈二次方增长。 

一种根据引入的新对数量独立选择数字的简单方法将会失败，因为添加一个数字可能会极大地改变先前添加的数字的贡献。 例如，选择 1、2、4、8 会创建一条密集链，其中每个前缀都与所有后面的元素相互作用，并且贡献呈二次方增长。 独立处理元素会忽略这种耦合。 

当尝试首先贪婪地选择所有小数字的倍数时，会出现另一个失败案例。 例如，在考虑 3 之前选择 2 的所有倍数会导致快速超调，即使 k 很小，因为链 2、4、8、16 已经贡献了许多内部对。 

## 方法

 控制除数对数量的关键是避免考虑任意子集，而是将所选集合构造成独立的乘法链。 

考虑一个固定的起始数x。 如果我们在 n 范围内重复乘以 2，我们会得到一条链 x、2x、4x，依此类推。 在这样的链中，每个较早的元素都除以每个较晚的元素，因此长度为 L 的链恰好贡献了 L·(L−1)/2 个有效对，并且这些贡献完全在链内部。 

如果我们可以将最终的集合分解为几个不相交的链，那么总的答案就是三角形数在其长度上的总和。 主要挑战是选择三角和等于 k ​​的链长度，同时确保我们不会在链之间重复使用数字。 

蛮力的想法是考虑所有子集并直接计算它们的贡献。 这是 n 的指数并且立即失败。 

关键的观察是，如果链不共享元素，则它们的行为是独立的，并且每个链贡献一个可预测的二次量。 这将问题转化为使用三角形数之和来构建 k，其中每个三角形数对应于原始集合中的几何链。 由于较大的链会提供不成比例的较大贡献，因此我们可以贪婪地从大量可用数字中构建链，并且总是在不超过 k 的情况下获取尽可能多的链。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 贪婪链构建 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们处理从 n 到 1 的数字，并尝试从每个未使用的数字开始形成链。 

1. 维护一个布尔数组，用于标记某个数字是否已被某个链占用。 这确保了链保持不相交。 
2.从n向下迭代i到1。如果i已经被使用，则跳过它，因为它无法启动新链。 
3. 从 i 开始，通过重复乘以 2 来构建乘法链：i、2i、4i、8i，只要该值 ≤ n 并且未使用。 将这些值收集到列表 v 中。这会生成从 i 开始的完整可用链。 
4. 设 L 为 v 的长度。我们现在决定实际采用该链的多少个元素。 取前 t 个元素正好贡献 t​​·(t−1)/2 对，因此我们选择最大的 t，使得 t·(t−1)/2 ≤ k 且 t ≤ L。此步骤是贪婪的，因为较大的 t 严格地为每个链提供更多的值，并且更快地减少 k。 
5. 将 v 的前 t 个元素标记为已使用，并将它们添加到答案集中。 从 k 中减去 t·(t−1)/2。 
6. 继续直到 i 达到 1 或 k 变为 0。如果 k 变为 0，我们可以安全地忽略剩余的数字。 
7. 如果k为0，则输出构造的集合； 否则输出“否”。 

关键的不变量是，处理每个链后，k 始终等于必须由未使用的数字形成的剩余所需对的数量。 每个链都是独立贡献的，因为两个链中没有出现数字，并且在一个链内，每个贡献都是内部的。 贪心选择是有效的，因为在从给定点开始的所有可能的链中，选择最大可行前缀不会阻止未来的构造：任何剩余的要求仍然可以使用较小的链形成，因为我们按照起点的降序进行，并且始终保留未使用的数字以供以后使用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    used = [False] * (n + 1)
    ans = []
    
    for i in range(n, 0, -1):
        if used[i]:
            continue
        
        v = []
        x = i
        while x <= n and not used[x]:
            v.append(x)
            x *= 2
        
        L = len(v)
        
        # find largest t such that t*(t-1)//2 <= k and t <= L
        t = 0
        for c in range(L + 1):
            if c * (c - 1) // 2 <= k:
                t = c
        
        if t > 0:
            for j in range(t):
                used[v[j]] = True
                ans.append(v[j])
            k -= t * (t - 1) // 2
        
        if k == 0:
            break
    
    if k != 0:
        print("No")
    else:
        print("Yes")
        print(len(ans))
        print(*ans)

if __name__ == "__main__":
    solve()
```该代码首先从每个未使用的数字开始构建最大加倍链。 然后，它根据剩余 k 可以吸收的数量来决定从每个链中取出多少元素。 二次项 t(t−1)/2 是完全连接的双倍链内有效整除对的确切数量，因为每个较早的元素都可以除以每个较晚的元素。 

小心的部分是确保我们只采用链的前缀。 采用前缀可以保留内部结构，保证所有整除对都存在，同时避免与跳过元素的部分交叉交互。 

## 工作示例

 ### 示例 1

 考虑 n = 10，k = 3。 

我们从 10 往下处理。 当 i = 8 时，链为 [8]。 无论选择如何，它都会贡献 0 对，因此没有任何变化。 在 i = 4 时，链是 [4, 8]，但根据前面的步骤，8 已经被使用； 假设它还没有被使用。 我们可以取 t = 2，贡献 1 对，将 k 减少到 2。 

当 i = 2 时，链是 [2, 4, 8]，但有些可能已经被使用； 假设剩余的可用结构允许 t = 2，贡献另外 1 对，将 k 减少到 1。 

在 i = 1 时，链是 [1, 2, 4, 8]，但再次按使用情况进行过滤，我们可以采用 t = 2 贡献 1 个以上的对，将 k 减少到 0。 

| 我| 链条v | 选择t | 贡献 | 剩余 k |
 | --- | --- | --- | --- | --- |
 | 4 | [4, 8] | 2 | 1 | 2 |
 | 2 | [2,4,8]| 2 | 1 | 1 |
 | 1 | [1,2,4,8]| 2 | 1 | 0 |

 该迹线显示了 k 如何分解为来自独立链的三角形贡献。 

### 示例 2

 设 n = 6，k = 2。 

当 i = 6、v = [6] 时，贡献为 0。 

当 i = 3, v = [3, 6] 时，我们可以取 t = 2 给出 1 对，因此 k 变为 1。 

当 i = 2 时，v = [2, 4]，再次 t = 2 给出 1 对，因此 k 变为 0。 

| 我| 链条v | 选择t | 贡献 | 剩余 k |
 | --- | --- | --- | --- | --- |
 | 3 | [3, 6] | 2 | 1 | 1 |
 | 2 | [2, 4] | 2 | 1 | 0 |

 这显示了不同的起点如何产生不相交的贡献，并且其总和恰好等于 k。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 每个数字最多出现在一个双链中，并且每个链的长度为 O(log n) |
 | 空间| O(n) | 使用的标记和输出集的数组 |

 运行时很容易满足约束条件，因为每个元素在所有链上都会被访问恒定的次数，并且链构造仅遵循加倍序列。

 ## 边缘情况

 对于 k = 0，算法立即接受，不选择任何有意义的链或仅选择单个元素。 由于单例不贡献对，因此任何单个数字就足够了，并且构造自然会提前终止。 

当 n 很小时，许多链折叠到长度 1，这意味着所有三角形贡献为零。 在这种情况下，k 也必须为零，否则无法进行构造。 该算法正确地失败了，因为没有链可以减少 k。 

对于二的幂的数字，链变得很长并且非常有价值。 该算法通过尽早贪婪地消耗它们来处理这个问题，快速减少 k 而不影响从奇数开始的不相关链，因为这些链是不相交的。
