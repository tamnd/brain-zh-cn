 ## 解决方案

 ## 问题理解

 我们得到几个短字符串，每个字符串仅包含字符`s`和`h`。 我们可以以任意顺序重新排列这些字符串，然后将它们连接成一个长字符串。 一旦形成最终的字符串，我们就将其“噪声”测量为位置对的数量`(i, j)`这样`i < j`, 位置处的字符`i`是`s`，以及位置处的字符`j`是`h`。 换句话说，每一个`s`出现在`h`为每个此类贡献一个单位的噪声`h`。 

任务是选择给定字符串的排序，使总计数最大化。 

约束条件达到`n = 100000`总长度的字符串`100000`。 这立即排除了尝试所有字符串排列的任何方法，因为这将是阶乘`n`。 甚至对所有排列进行排序或对子集进行动态编程也是不可能的。 该解决方案必须基本上以线性算数时间运行，可能`O(n log n)`或更好。 

一个微妙的困难是，字符串的贡献不仅取决于其内部结构，还取决于它如何与放置在其之前或之后的其他字符串交互。 一个天真的想法可能是独立计算每个字符串的贡献，但这忽略了跨边界对，这是问题的全部困难。 

当字符串内部“良好”但排序有害时，就会出现一种重要的边缘情况。 例如，考虑字符串`"sh"`和`"hs"`。 在内部，它们都贡献了很小的噪声，但交换它们的顺序会极大地改变交叉贡献。 另一个边缘情况是仅包含以下内容的字符串`s`或仅`h`，其中内部贡献为零，但它们强烈影响全局排序。 

## 方法

 暴力解决方案会尝试每一种排列`n`字符串，连接它们，并计算所有`s-h`结果字符串中的子序列。 对于每个排列，计算噪声需要`O(total length)`，所以完整的复杂度是`O(n! * 100000)`，即使对于`n = 10`。 

为了简化，请观察每个字符串可以由三个值概括：`s`字符数，个数`h`字符，以及内部对的数量，其中`s`出现在`h`在字符串本身内部。 无论顺序如何，内部贡献都是固定的，因此唯一可控的部分是字符串如何跨边界交互。 

当两个字符串连接时，交叉贡献仅取决于有多少个字符串`s`位于第一个字符串中，有多少个`h`在第二个字符串中。 如果字符串`A`被放置在之前`B`，那么每一个`s`在`A`贡献与每一个`h`在`B`, 生产`sA * hB`新对。 这表明排序问题简化为用两个参数排列项目，`s_i`和`h_i`，最大化成对乘积之和。 

现在考虑交换两个字符串`A`和`B`。 贡献的差异仅来自交叉项。 如果`A`是在之前`B`，贡献为`sA * hB`，如果颠倒过来就是`sB * hA`。 我们希望排序能够使所有相邻交换中一致选择的这些变得更好。 这导致了贪心排序标准：位置`A`前`B`如果`sA * hB >= sB * hA`。 

这相当于按比例对字符串进行排序`s_i / h_i`按降序排列，注意零值。 直观地看，字符串有很多`s`和少数`h`应该早点来，因为他们创造了许多未来的贡献，同时与许多`h`应该稍后来最大化配对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·L) | O(n!·L) | O(L) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个字符串压缩为三个值：`s`，数量`h`，以及弦内的内部噪声。 通过从左到右扫描并计算有多少个来计算内部噪声`s`到目前为止，当我们遇到每个`h`。 

接下来，我们使用基于交叉交互的自定义​​比较器对字符串进行排序。 

1. 对于每个字符串，计数`s_i`,`h_i`， 和`internal_i`。 内部值直接添加到最终答案中，因为它不依赖于排序。 
2.定义两个字符串之间的比较规则`A`和`B`。 我们放置`A`前`B`如果`sA * hB >= sB * hA`。 该条件确保放置`A`与放置相比，第一个永远不会失去交叉贡献`B`第一的。 原因是它直接比较数量`s-h`在两个订单中创建的对。 
3. 根据该比较器对所有字符串进行排序。 这会排列字符串，以便那些贡献更有用的字符串`s`早出现的先出现，贡献多的`h`迟到会出现得更晚。 
4. 排序后，计算前缀和`s`。 按顺序处理每个字符串时，每个`h`在当前字符串中贡献了所有`s`从之前的字符串中累积。 
5. 将总答案累积为内部贡献加上根据排序顺序计算出的交叉贡献之和。 

为什么它有效是基于成对交换论证。 考虑任何相邻的字符串对。 如果根据比较器它们的顺序错误，则严格交换它们会增加或保留交叉对的总数。 由于任何排列都可以通过相邻交换转化为排序顺序，每次交换都不会降低目标，因此最终的排序顺序是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    strings = []

    for _ in range(n):
        t = input().strip()
        s_count = 0
        h_count = 0
        internal = 0
        seen_s = 0

        for ch in t:
            if ch == 's':
                s_count += 1
                seen_s += 1
            else:
                h_count += 1
                internal += seen_s

        strings.append((s_count, h_count, internal))

    def cmp(a):
        s, h, _ = a
        return -s / h if h != 0 else float('inf')

    strings.sort(key=cmp)

    prefix_s = 0
    ans = 0

    for s_count, h_count, internal in strings:
        ans += internal
        ans += prefix_s * h_count
        prefix_s += s_count

    print(ans)

if __name__ == "__main__":
    main()
```该代码首先将每个字符串压缩为三个所需的统计数据。 内部噪声是通过跟踪有多少个来一次性计算出来的`s`到目前为止，角色已经出现。 这可以避免以后重新计算。 

排序步骤对贪心规则进行编码。 字符串与`h = 0`被放在第一位，因为他们只贡献`s`永远不会阻止未来的贡献。 否则按递减排序`s / h`比率确保早期之间的正确权衡`s`和迟到`h`。 

最后，我们使用总计的运行计数来计算交叉贡献`s`到目前为止所看到的。 每个`h`在当前字符串对与所有先前的字符串对中`s`，这与跨级联边界的噪声的定义完全匹配。

 ## 边缘情况

 一个关键的边缘情况是当字符串仅包含`h`。 在这种情况下`s = 0`，因此比较器将其放在末尾。 这是正确的，因为提前放置这些字符串只会增加未来的损失，因为每个`s`之后它不会受到影响，但不会贡献任何有用的前缀`s`。 

对于仅包含`s`，我们有`h = 0`，所以它被放在前面。 这也是正确的，因为它最大化了未来配对的数量`h`后面的字符串中的字符，同时不会造成有害的结构。 

混合字符串，例如`"shsh"`展示内部交互与交叉交互。 在内部，它已经贡献了一些对，并且算法在考虑排序之前正确地添加了一次。 然后，它的位置纯粹由比率决定，确保其内部结构不会扭曲全局优化。
