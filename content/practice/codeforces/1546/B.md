 ## 解决方案
 ## 问题理解

 我们得到一个原始字符串的多重集和扰动过程后形成的第二个多重集。 骚乱分两个阶段进行。 首先，除了一个未配对的特殊字符串外，所有字符串都已配对。 然后，对于每一对，通过在某些选定位置交换字符来部分“混合”两个字符串，最后删除未配对的字符串。 结果列表被打乱，因此顺序不包含任何信息。 

我们还获得了完整的原始集和最终损坏的集。 任务是确定哪个原始字符串完全消失。 

关键的结构性限制是$n$是奇数，因此恰好有一个原始字符串在最终集合中没有对应的字符串。 每个其他原始字符串都恰好参与一对，并且每对仅按位置交换字符，而不更改该对中任何固定位置的多组字符。 这意味着一个守恒原则：在每一对中，每列在交换之前和之后都贡献相同的总字符多重集，仅在两个字符串之间重新分配。 

界限很大：总计$\sum n \cdot m \le 10^5$。 这立即排除了将每个原始字符串与每个最终字符串进行比较的任何解决方案，因为这将是字符串数量的二次方。 即使每次比较都对完整字符串进行哈希处理，仍然需要仔细的线性聚合而不是成对匹配。 

当尝试对相同字符串进行贪婪匹配时，会出现一种微妙的失败情况。 考虑三个字符串，其中两个字符串最初是相同的，但会成对大量交换。 交换后，它们可能不再彼此或任何原始字符串完全匹配，即使它们仍然对应于有效的配对转换。 所以平等匹配是不够的； 我们需要一个在交换中仍然存在的结构不变量。 

另一个陷阱是假设整个字符串或每个字符计数的频率就足够了。 成对交换保留全局字符总数，但不保留每个字符串，因此无法仅从全局频率检测到被盗字符串。 

## 方法

 一个蛮力的想法是尝试删除每个原始字符串候选者并检查剩余的是否$n-1$原始字符串可以分成对，这些对可以通过一些有效的交换操作生成最终的多重集。 这会退化为尝试匹配转换后的对，实际上需要检查所有配对和所有交换配置。 配对数量的阶乘为$n$，甚至验证单个配对也需要比较长度的字符串$m$。 这远远超出了任何可行的限度。 

关键的观察是我们不需要重建配对或交换。 相反，我们利用跨列出现的奇偶性。 一对中的每次交换恰好影响一个位置处的两个字符串，因此对于任何固定位置和任何字符，所有字符中出现的次数$n-1$最终字符串与原始字符串的不同之处在于被盗字符串的贡献。 其他一切都成对抵消。 

因此，对于每个位置，我们都会比较原始多重集和最终多重集之间的字符差异。 由于所有非被盗字符串都出现在两个集合中（可能仅通过对内的交换进行排列和更改），因此它们在所有字符串中的总贡献以结构化方式抵消，留下与丢失字符串相对应的单个一致残基。 

这建议维护每个位置的频率表。 对于每一列$j$，我们使用字母计数来计算类似 XOR 的取消。 被盗的绳子是唯一同时造成所有头寸全球不平衡的一根绳子。 通过累积每个位置的差异，我们可以恢复丢失字符串的确切字符。

 | --- | --- | --- | --- |
 | 暴力配对重建 | 指数| 高| 太慢了 |

 ## 算法演练

 1. 构建所有原始字符串中每个位置的字符频率计数。 对于每个位置$j$，我们存储每个字母在列中出现的次数$j$其中$n$字符串。 这代表初始状态。 
2. 建立相同的频率计数$n-1$最后的字符串。 这代表所有交换和移除后的干扰后状态。 
3. 对于每个位置$j$，计算原始频率阵列和最终频率阵列之间的差异。 由于交换仅对同一位置的配对字符串之间的字符进行排列，因此所有非被盗字符串上的每个位置多重集的总数保持一致。 唯一的差异来自于缺少的字符串。 
4. 对于每个位置$j$，找到原始多重集中计数大于最终多重集中计数的字符。 该字符必须是被盗字符串中位于位置的字符$j$，因为它是最终多重集中唯一未考虑的贡献。 
5. 将这些字符连接到所有位置以重建被盗的字符串。 

关键的一步是每列隔离。 即使在对内交换打乱字符，它们也不会跨位置移动字符，因此每列作为多集保护系统独立运行。 

### 为什么它有效

 在每个位置$j$，考虑所有原始字符串中的多组字符。 配对和交换后，每个未窃取的字符串仍然为最终数组中的该列贡献了一个字符。 交换仅交换成对内的这些贡献，保留成对字符串的多集并集。 因此，在比较原始列和最终列时，所有配对的贡献都完美抵消，每列恰好留下一个不匹配的字符，该字符必须属于被盗的字符串。 由于被盗字符串在所有列中都是一致的，因此这些不匹配的字符会组合成有效的字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        orig = [input().strip() for _ in range(n)]
        final = [input().strip() for _ in range(n - 1)]

        cnt_o = [[0] * 26 for _ in range(m)]
        cnt_f = [[0] * 26 for _ in range(m)]

        for s in orig:
            for j, ch in enumerate(s):
                cnt_o[j][ord(ch) - 97] += 1

        for s in final:
            for j, ch in enumerate(s):
                cnt_f[j][ord(ch) - 97] += 1

        res = []
        for j in range(m):
            for c in range(26):
                if cnt_o[j][c] > cnt_f[j][c]:
                    res.append(chr(c + 97))
                    break

        print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案是通过构建两个按列的频率表来实现的。 字符串和字符上的嵌套循环直接实现每列聚合。 减法逻辑是隐式的：我们在原始状态和最终状态之间找到计数恰好减少 1 的字符。 

一个常见的实施陷阱是忘记每一列必须独立处理。 将字符串视为整个单元会丢失由交换引入的取消结构。

 ## 边缘情况

 当除了被盗的字符串之外的所有字符串都相同时，频率差异将完全集中在该重复模式中。 该算法仍然独立地隔离每一列，因此即使不存在成对区分，也可以准确地重建被盗的字符串。 

当成对交换达到最大时，这意味着每对中的每个位置都会交换，单个字符串会严重扭曲。 然而，按列多重集在成对贡献之间保持不变，因此不平衡逻辑仍然隔离丢失的字符串，而不依赖于原始字符串和最终字符串之间的任何结构相似性。 

什么时候$n = 1$，最终的数组为空。 每个列频差等于唯一的原始字符串，因此算法直接返回它，不会产生歧义。
