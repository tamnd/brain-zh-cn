 ## 解决方案
 ## 问题理解

 两个玩家给我们两个长度相等的数组。 可以通过将单个单元从一个位置重复移动到另一个位置来修改一个阵列。 每一步都会从索引中删除一个`i`并向索引加一`j`，并且每次移动后数组必须保持非负数。 目标是将第一个数组精确地转换为第二个数组，或者认为这是不可能的。 

解释该操作的一个有用方法是它保留数组的总和。 每一次操作只是在坐标之间转移一个单位的值，因此总和永远不会改变。 这立即暗示了一个必要条件：如果两个数组的总和不同，则任何操作序列都不可能使它们相等。 

限制很小：`n`最多为 100，并且每个测试用例跨数组的所有值的总和也以 100 为界。 这意味着即使是明确移动单个单元的解决方案也是安全的，因为需要跟踪的单元总数很小。 任何二次甚至稍微三次的方法`n`很好，但任何指数或涉及复杂流动机械的东西都是不必要的。 

当总和匹配时会出现微妙的边缘情况，但如果我们没有正确推理源和汇，则重新分配是不可能的。 例如，如果`a = [0, 2]`和`b = [1, 1]`，我们需要将一个单位从索引 2 移动到索引 1。粗心的方法可能会尝试贪婪地匹配索引，而不确保在需要时实际可用剩余索引。 另一种边缘情况是数组已经相等； 正确的答案是零操作，而不是具有无效格式的空计划。 

## 方法

 暴力的观点是模拟所有可能的传输序列。 从给定的状态，我们可以选择任何一对索引并尝试移动一个单元，然后递归搜索与目标数组匹配的序列。 这是正确的，因为它探索所有可到达的状态，并且每个状态转换完全对应于一个有效操作。 问题在于状态空间呈爆炸性增长。 尽管总和很小，但分支因子大致为`n^2`，序列很快就会变得难以管理。 

关键的观察结果是，各个单位的身份并不重要。 重要的是每个指数需要上涨或下跌多少个单位。 我们可以计算一个差异数组，其中每个位置告诉我们相对于目标是否有盈余或赤字。 每个正差值必须发送单位，每个负差值必须接收单位。 由于总和保持不变，总盈余等于总赤字，所以我们只是简单地匹配供给和需求。 

这将问题简化为将盈余指数与赤字指数配对并产生明确的变动。 每一步都会修正一个单位的不平衡。 因为不平衡总量最多为100，所以我们最多会进行100次转账。

 ## 算法演练

 我们直接从不平衡簿记中构建解决方案。 

1. 计算两个数组的总和。 如果不同，则立即返回失败。 这是必需的，因为每个操作都会保留总和，因此不匹配的总和会导致目标无法到达。 
2. 建立一份剩余头寸清单，其中`a[i] > b[i]`, 重复索引`i`确切地`a[i] - b[i]`次。 这些代表必须搬走的单位。 
3. 建立一份赤字头寸清单，其中`a[i] < b[i]`, 重复索引`i`确切地`b[i] - a[i]`次。 这些代表必须填写的单位。 
4. 此时，两个列表的长度相等，因为总盈余等于总赤字。 如果它们的大小不匹配，则配置不一致且无法修复。 
5. 按顺序对元素进行配对：采用第一个盈余指数和第一个赤字指数，并创建一个将一个单位从盈余移动到赤字的操作。 重复直到所有元素都配对。 

每个配对同时减少两个位置的绝对差，因此没有中间状态违反非负性。 

### 为什么它有效

 差异数组充分表征了必须改变的内容。 每一次操作都会将 L1 不平衡精确地减少 2，即从盈余头寸中删除一个单位，并在赤字头寸中添加一个单位。 由于我们总是选择有效的盈余指数，因此我们永远不会从零位置减去。 由于总盈余等于总赤字，因此配对总是在没有剩余不平衡的情况下完成，从而保证了有效的全面转换（如果存在）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        if sum(a) != sum(b):
            out.append("-1")
            continue

        surplus = []
        deficit = []

        for i in range(n):
            if a[i] > b[i]:
                surplus.extend([i + 1] * (a[i] - b[i]))
            elif a[i] < b[i]:
                deficit.extend([i + 1] * (b[i] - a[i]))

        ops = []
        for i in range(len(surplus)):
            ops.append((surplus[i], deficit[i]))

        out.append(str(len(ops)))
        for i, j in ops:
            out.append(f"{i} {j}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现首先检查总和必须匹配的不变量。 这是唯一的全局不可能条件。 然后，它将数组转换为必须移动的各个单元的扩展列表，从而避免了复杂的簿记工作。 

配对循环是安全的，因为每个`surplus[i]`保证对应于最初至少有一个额外单位的位置。 即使从同一索引中取出多个单元，每个单元在概念上也是独立的，因此重复索引是有效的。 

最终的输出结构只是序列化这些单元传输。 操作数量自动受到总不平衡的限制，由于限制，总不平衡最多为 100。 

## 工作示例

 考虑转型`a = [1, 2, 3, 4]`和`b = [3, 1, 2, 4]`。 

我们计算每个指数的差异。 索引 1 需要 +2，索引 2 需要 -1，索引 3 需要 -1，索引 4 需要 0。这会产生剩余列表`[2, 3]`和赤字清单`[1, 1]`。 

| 步骤| 剩余| 赤字| 运营|
 | ---| ---| ---| --- |
 | 1 | 2, 3 | 1, 1 | 2 → 1 |
 | 2 | 3 | 1 | 3 → 1 |

 应用这些举措后，每个指数都与其目标值匹配。 这证实了独立配对单元就足够了，因为只要考虑到每个单元的传输，顺序并不重要。 

现在考虑一个单元素的情况`a = [0]`,`b = [0]`。 两个列表都是空的，因此不会生成任何操作。 这表明该算法可以自然地处理琐碎的情况，而无需特殊的分支。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个指数都被处理一次以建立盈余和赤字列表，总操作以差值总和为界 |
 | 空间| O(n) | 存储盈余和赤字单位扩展|

 这些约束确保所有测试的单元总数很小，因此即使显式扩展每个单元也仍然有效。 该解决方案完全符合限制。

 ## 边缘情况

 当两个数组已经相同时，算法会生成空的盈余和赤字列表，直接导致零操作，这与所需的输出格式相匹配。 

当金额不同时，提前终止可以避免构建不一致的盈余和赤字结构，从而防止误导性的部分配对。 

当所有盈余集中在一个指标中时，扩展的盈余列表只是多次重复该指标，并且每次重复都独立地与一个赤字指标配对，这表明只要其初始盈余足够，重复使用单一来源就是有效的。
