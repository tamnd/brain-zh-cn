 ## 解决方案
 ## 问题理解

 我们被要求设计一个两阶段程序，通过单个字符串传达整数数组。 第一次运行时，程序收到一个长度为`n`，其中每个元素最多为 26。它必须将此数组编码为仅由小写英文字母组成的字符串。 在第二次运行时，程序仅接收编码的字符串，并且必须恢复原始数组及其长度。 

主要挑战是运行之间不存在持久内存。 用于解码的任何信息都必须编码到字符串本身中。 限制条件适中：`n`最多可达 10,000 个，每个元素最多 26 个，匹配字母表中的 26 个字母。 输出字符串不能超过100,000个字符，因此数字到字母的简单一对一编码是可行的。 

当多个元素相同或当`n`处于最大值。 例如，如果`n = 3`和`a = [1, 1, 1]`，仅连接不带分隔符的字母的简单编码将产生“aaa”。 如果不小心的话，在没有预定义方案的情况下解码可能会误解长度或顺序。 同样，我们必须处理最小的输入，`n = 1`和`a = [1]`，确保我们的方案适用于单元素数组。 

## 方法

 暴力方法对每个整数进行编码`a_i`作为相应的小写字母，映射 1 → 'a', 2 → 'b', …, 26 → 'z'。 编码只是这些字母的串联。 这种方法之所以有效，是因为所有整数都适合字母表，并且字符串长度最多为 10,000，远低于 100,000 个字符的限制。 解码涉及反转映射：将每个字母转换回其数值。 

该方法正确且快速，因为它直接将数字映射到字母`O(n)`时间和空间。 例如，如果使用多字符代码或数字超过 26，则未经仔细映射的简单变体可能会使字母错位。关键的见解是该问题明确将值限制为 26，从而允许数字和字母之间的简单双射，而无需额外的分隔符。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（每个数字 1 个字母）| O(n) | O(n) | 已接受 |
 | 复杂的方案（多字母编码）| O(n) | O(n) | 此版本不需要 |

 ## 算法演练

 1. **编码阶段（第一次运行）**

 读取整数`n`和数组`a`。 对于每个元素`a_i`，通过计算将其转换为小写字母`chr(ord('a') + a_i - 1)`。 将这些字母连接成一个字符串`s`。 打印`s`并终止。 
2. **解码阶段（第二次运行）**

 读取编码后的字符串`s`。 长度为`s`是`n`。 将每个字符转换回其数值`ord(c) - ord('a') + 1`重建数组`a`。 打印`n`其后的元素为`a`。 

正确性依赖于整数 1-26 和字母“a”-“z”之间的一对一映射。 由于每个字母恰好代表一个数字，并且字符串长度等于数组长度，因此解码时不会出现歧义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

mode = input().strip()

if mode == "first":
    n = int(input())
    a = list(map(int, input().split()))
    # Encode: map 1->'a', 2->'b', ..., 26->'z'
    s = ''.join(chr(ord('a') + x - 1) for x in a)
    print(s)

else:  # second run
    s = input().strip()
    n = len(s)
    a = [ord(c) - ord('a') + 1 for c in s]
    print(n, *a)
```第一个分支将每个整数转换为一个字母。 使用`ord`和`chr`确保映射准确。 第二个分支反转该过程。 使用`*a`print 语句中的内容有效地将数组扩展为空格分隔的值。 边界检查是隐式的，因为问题保证`1 ≤ a_i ≤ 26`。

 ## 边缘情况

 对于`n = 1`和`a = [1]`，编码产生`"a"`。 解码读取单个字符，计算`ord('a') - ord('a') + 1 = 1`，和输出`1 1`。 为了`a = [26, 26, 26, 26]`，编码产量`"zzzz"`; 解码重建`[26, 26, 26, 26]`。 即使所有元素都相同或处于极端情况，映射也会保留数组，从而避免歧义。 

这篇社论表明，对于问题的简单版本，简单的一对一字母映射就足够了。 较难的版本需要更复杂的编码来处理大于 26 的值。
