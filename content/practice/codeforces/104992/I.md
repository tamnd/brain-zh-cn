 ## 解决方案
 ## 问题理解

 我们得到一个视频集合，每个视频都是由大写字母组成的字符串。 每个字符代表某种动物类型的 10 秒片段。 观看视频意味着消耗整个字符串，因此视频的成本与其长度成正比。 

我们需要选择一些视频，不重复，使得总观看时间正好是M分钟。 由于每个角色贡献 10 秒，1 分钟为 60 秒，因此每个角色贡献 1/6 分钟。 这意味着所选视频中的字符总数必须恰好为 6M。 

还有一个额外的排序约束：在所选视频中，观看顺序中的最后一个视频必须以字母 C 结尾。由于其他视频的顺序并不重要，这相当于选择总长度为 6M 的子集，并确保至少有一个所选视频以 C 结尾，因为该视频可以放在最后。 

约束足够小，总长度高达 6000 的二次或伪二次动态规划解决方案是可行的。 当 N 达到 2000 并且目标总和达到 6000 时，O(N·sum) 方法是可以接受的。 

一种天真的方法会尝试视频的所有子集，但这会导致 2^2000 种可能性，这是完全不可行的。 

当存在总和为 6M 的有效子集但其视频均不以 C 结尾时，会出现微妙的边缘情况。这样的子集即使满足时间约束也是无效的。 例如，如果所有选定的视频都以 D 或 P 结尾，则无论顺序如何，我们都无法满足最终约束。 

当存在多个有效子集但只有其中一些包含 C 结尾视频时，会出现另一种边缘情况。 正确的算法必须确保全局强制执行约束，而不是事后才想到。 

## 方法

 暴力策略将枚举视频的所有子集并计算它们的总长度。 对于每个子集，我们还将检查是否至少有一个选定的视频以 C 结尾。这在逻辑上是有效的，因为它直接匹配问题的定义，但它检查 2^N 个子集，甚至评估单个子集也需要求和长度，导致指数爆炸无法在 N = 2000 时完成。 

问题的结构是，我们只关心所选长度的总和以及一个额外的布尔条件，该附加布尔条件描述所选集合是否包含以 C 结尾的视频。这立即暗示了一种背包式动态编程解决方案，其中状态跟踪可实现的总长度以及 C 条件是否已满足。 

我们没有将 C 结尾要求视为排序的约束，而是将其重新解释为子集的属性：最后一个视频始终可以从选定的视频中选择，因此我们只需要至少一个合格的候选者。 

这将问题简化为使用二进制标志来计算总和高达 6000 的可达性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^N·N) | O(2^N·N) | O(N) | 太慢了|
 | 动态规划（总和+标志）| O(N·6000) | O(N·6000) | 已接受 |

 ## 算法演练

 我们将问题建模为背包，其中每个物品的重量等于其绳子长度。 我们维持是否已经选择了至少一个 C 结尾视频。

1、将所需时间M换算为目标字符数T=6M。 这将时间约束变成了纯整数子集和问题。 
2. 定义一个动态规划表 dp[s][b]，其中 s 是到目前为止达到的总长度，b 是一个二进制值，表示我们是否选择了至少一个以 C 结尾的视频。 
3. 在选择任何内容之前将 dp[0][0] 初始化为可达。 
4、对视频进行一一处理。 对于长度为 L 和标志 c 的每个视频 i（如果以 C 结尾则为 1，否则为 0），尝试从每个可达状态 (s, b) 转换到 (s + L, b OR c)，只要 s + L ≤ T。我们按降序处理总和以避免多次重复使用同一视频。 
5. 在执行转换时，我们为每个新到达的状态存储父指针，以便稍后可以重建所选子集。 每个状态都会记住它来自哪个先前状态以及哪个视频创建了它。 
6. 处理完所有视频后，我们检查 dp[T][1] 是否可达。 如果不是，则没有有效的子集。 
7. 如果可达，则通过使用父指针从状态 (T, 1) 向后行走直到到达 (0, 0) 来重建子集。 
8. 从重建的子集中，选择任何以 C 结尾的视频，并将其指定为最后一个视频。 以任意顺序输出剩余视频，然后输出所选的最后一个视频。 

### 为什么它有效

 每个 dp 状态代表已处理视频的一个子集，该子集达到特定的总长度以及是否包含 C 结尾视频的记录。 由于转换一次仅附加一个未使用的视频，因此每个可达状态对应一个有效子集。 父指针确保我们永远不会丢失该子集的实际组成。 

由于除了最后一个元素之外，视频的排序是无关紧要的，并且最后一个元素可以在子集中的 C 结尾视频中自由选择，因此确保 dp[T][1] 相当于确保存在有效的最终排列。 重建保证我们恢复实现该状态的显式子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    videos = []
    for i in range(n):
        s = input().strip()
        videos.append((len(s), s[-1] == 'C', i + 1))

    T = 6 * m

    dp = [[False] * 2 for _ in range(T + 1)]
    parent = [[None] * 2 for _ in range(T + 1)]

    dp[0][0] = True

    for idx, (length, ends_c, vid) in enumerate(videos):
        for s in range(T - length, -1, -1):
            for b in range(2):
                if not dp[s][b]:
                    continue
                nb = b | ends_c
                ns = s + length
                if not dp[ns][nb]:
                    dp[ns][nb] = True
                    parent[ns][nb] = (s, b, vid)

    if not dp[T][1]:
        print("NO")
        return

    # reconstruct subset
    res = []
    s, b = T, 1
    used = set()

    while s != 0 or b != 0:
        ps, pb, vid = parent[s][b]
        res.append(vid)
        used.add(vid)
        length = None
        for L, c, v in videos:
            if v == vid:
                length = L
                break
        s, b = ps, pb

    # choose last C-ending video
    last = None
    for v in res:
        for L, c, vid in videos:
            if vid == v and c:
                last = v
                break
        if last is not None:
            break

    res.remove(last)
    print("YES")
    print(len(res) + 1)
    print(*res, last)

if __name__ == "__main__":
    solve()
```DP 表跟踪直到 T 的每个可能的总持续时间的可达性，而第二个维度确保我们记住所选子集中是否存在有效的结束候选。 父数组记录转换，因此我们可以重建显式解决方案，而不仅仅是决定可行性。 

重建步骤从目标状态向后走并收集选定的视频。 之后，我们分离出一个以C结尾的视频并将其放在最后，这满足了排序约束。 

一个微妙的点是在转换期间按降序处理总和。 这可以防止在同一迭代中多次重复使用同一视频，从而保留选择的 0/1 性质。 

## 工作示例

 ### 示例 1

 我们假设 DP 达到总长度 T = 6M 的有效状态。 

| 步骤| 行动| dp状态总结|
 | ---| ---| ---|
 | 0 | 开始| 只有 dp[0][0] = true |
 | 1 | 过程视频1 | 可达金额扩大 |
 | 2 | 过程视频2 | 添加更多金额 |
 | 3 | 处理视频4 | dp[T][1] 变为 true |

 DP 后，重建会产生一个子集，例如 {1, 2, 4}。 其中视频4以C结尾，可以放在最后。 

这证实了该算法将可行性（子集和）与排序（最终选择）分开。

 | 步骤| 行动| dp状态总结|

 | 0 | 开始| 仅 dp[0][0] |
 | 1-3 | 1-3 处理视频 | 求和形式，但没有有效组合达到带有 C 标志的 T |
 | 决赛| 检查 | dp[T][1] = 假 |

这表明，即使时间约束可以单独满足，附加约束也会使所有解决方案无效。

 ## 边缘情况

 当所有视频一起可以达到所需的总长度但没有一个以 C 结尾时，dp 表将正确地将 dp[T][0] 标记为可达，而 dp[T][1] 保持错误。 该算法立即拒绝这种情况，因为不存在有效的最终视频。 

当只有一个以 C 结尾的有效视频存在但太长而无法与其他视频组合时，包含该视频的 DP 永远不会达到 T，并且重建失败。 向后的父级跟踪证实了不可能。 

当重建子集中存在多个C结尾视频时，可以选择其中任何一个作为最后一个。 该算法安全地选择第一个遇到的，因为其余的顺序无关。
