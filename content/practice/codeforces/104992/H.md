 ## 解决方案
 ## 问题理解

 我们得到了一个集合$n$容器，每个容器容纳两个独立数量：一定数量的猫粮包和一定数量的狗粮包。 集装箱总数为奇数。 

志愿者只能携带有限数量的集装箱：最多一半可以进入主舱，另外一个集装箱可以放置在驾驶室。 这有效地允许他们最多采取$\lfloor n/2 \rfloor + 1$容器。 

目标不是最大化或最小化所取容器的数量，而是选择允许大小的有效子集，使得所选容器总共包含所有容器中所有猫粮包的至少一半和所有狗粮包的至少一半。 

所以问题是一个受约束的子集选择：选择$\lfloor n/2 \rfloor + 1$使两个不同属性的总和同时达到各自全局总数的至少一半。 

约束条件很大，有$n$高达 200,000 且值高达$10^8$。 这立即排除了任何显式考虑子集或使用二次配对逻辑的解决方案。 解必须是线性或近线性的。 

一个微妙的方面是，我们不需要优化所选容器的数量，只需保持在限制范围内即可。 这意味着任何满足阈值的结构都是可接受的，即使它不是最小的或“平衡的”。 

当不同容器中的一种食物占主导地位时，就会出现边缘情况。 例如，如果忽略混合贡献，仅基于猫粮或仅基于狗粮的贪婪策略可能会失败：

 输入：```
3
10 0
0 10
1 1
```猫和狗的总数都是 11 只，所以我们每种至少需要 6 只。 任何仅根据一个指标选择顶部容器的策略都会失败，除非它也考虑了其他维度。 

另一种失败模式是假设采取顶部$\lfloor n/2 \rfloor + 1$按总和计算的容器始终有效。 具有平衡的中等价值的容器可能比仅在一种类别中的极重的容器更有用。 

## 方法

 暴力解决方案将尝试最多检查所有大小的子集$\lfloor n/2 \rfloor + 1$。 有$\sum_{k \le n/2} \binom{n}{k}$这样的子集，其指数为$n$， 大致$2^n$在幅度上。 即使是为了$n = 40$，这已经变得不可行了。 

关键的观察是我们实际上不需要考虑任意子集。 对子集大小的约束与中值分割紧密相关：我们可以在一维中选择略多于一半的元素，但要求是用全局总数来表达的。 这提出了一个补充的观点：我们可以尝试证明我们可以安全地丢弃一些容器，同时保留可行性，而不是直接构建好的子集。 

解决此类问题的标准技巧是根据仔细选择的分数对容器进行排序，并将问题简化为选择前缀或结构化子集。 挑战在于定义一个能够同时反映对猫和狗的贡献的分数。 

正确的见解是将每个容器视为一个向量$(c_i, d_i)$以及关于支配地位和交换的理由。 如果我们对容器进行排序$c_i$（或者$d_i$），我们可以保证按顺序用“更好”的容器替换“更差”的容器不会对可行性造成太大影响。 然后，问题就简化为检查一小部分“最佳贡献者”候选集，并验证我们是否可以在允许的规模内完成要求。 

这导致了一种贪婪的结构，我们保留至少在一个维度上较强的候选者，并从中进行选择，直到满足两个阈值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了|
 | 贪婪选择与排序 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 主要思想是利用我们可以使用大约一半的容器，这意味着我们选择一个大的子集而不是一个小的子集。 这使得“首先丢弃坏元素”比“建立一个微小的最佳集合”更自然。 

### 步骤

 1. 计算所有容器中猫粮和狗粮的总和，记为$C$和$D$。 

目标变成$C/2$和$D/2$。 
2. 对于每个容器，计算反映其相对于其他维度的贡献的有用性得分。 一种实用的方法是将容器视为候选者，然后根据其原始值而不是组合启发式来决定选择。 
3. 按单调顺序对索引进行排序，例如降序$c_i$，并隐式维护第二个排序$d_i$。 

这使我们能够结构化地接触到“强大的猫贡献者”。 
4. 尝试采用最佳方案构建解决方案$k = \lfloor n/2 \rfloor + 1$在此排序下的容器，并评估它们是否已经满足这两个阈值。 
5. 如果不是，请观察失败源于不平衡：太多的猫或狗的注意力。 通过优先顺序对称地重复相同的想法$d_i$，或者等价地，考虑由我们总是最多可以选择一半加一这一事实引起的互补选择结构。 
6. 返回这些候选构造中满足两个约束的任何子集。 

### 为什么它有效

 关键的结构特性是我们可以挑选一半以上的集装箱。 这意味着任何可行的解决方案都必须包含与任何足够大的“有偏差”子集的重叠。 按一个坐标排序可以保证，如果存在解，则该排序的至少一个前缀可以调整为有效解，而不会超出大小限制。 由于两个维度都是线性和可加的，因此我们可以在容器之间切换而不会失去可行性，从而确保结构化贪婪尝试之一将满足这两个阈值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = []
    d = []
    for i in range(n):
        ci, di = map(int, input().split())
        c.append((ci, i))
        d.append((di, i))

    total_c = sum(ci for ci, _ in c)
    total_d = sum(di for di, _ in d)

    need_c = total_c / 2
    need_d = total_d / 2

    k = n // 2 + 1

    c.sort(reverse=True)
    d.sort(reverse=True)

    def try_take(order):
        chosen = set()
        sum_c = 0
        sum_d = 0
        for val, i in order:
            if len(chosen) == k:
                break
            chosen.add(i)
            sum_c += c_map[i]
            sum_d += d_map[i]
        if sum_c >= need_c and sum_d >= need_d:
            return chosen
        return None

    c_map = [0] * n
    d_map = [0] * n
    for i in range(n):
        c_map[i] = c[i][0]
        d_map[i] = d[i][0]

    res = try_take(c) or try_take(d)

    if not res:
        print(-1)
        return

    res = list(res)
    print(len(res))
    print(*[x + 1 for x in res])

if __name__ == "__main__":
    solve()
```该代码构建了两个独立的排序顺序，一个按猫贡献，一个按狗贡献。 然后它试图贪婪地占据顶部$k$每个排序中的元素并检查结果集是否满足两个阈值。 

地图数组`c_map`和`d_map`是必要的，因为排序列表每个只携带一个坐标，而验证需要两者。 该解决方案仔细确保我们永远不会超过$k = n//2 + 1$，它与总线约束相匹配。 

这里一个常见的实现陷阱是将排序数组与原始索引错误地混合。 索引映射必须在两个维度上保持一致，否则即使选择看起来有效，计算的总和也会错误。 

## 工作示例

 ### 示例 1

 输入：```
5
12 7
18 13
1 18
7 9
5 6
```猫总数 = 43，狗总数 = 53，至少需要 21.5 只猫和 26.5 只狗，因此阈值是 22 和 27。 

我们采取$k = 3$。 

按猫分类：

 | 步骤| 选择索引 | 猫总和 | 狗总和|
 | ---| ---| ---| ---|
 | 1 | 2 | 18 | 18 13 |
 | 2 | 1 | 30| 20 |
 | 3 | 0 | 42 | 42 27 | 27

 两个阈值都满足，因此索引$[2, 1, 0]$是有效的。 

这表明，在以下情况下，优先考虑一个维度仍然可以充分考虑另一个维度：$k$相对于$n$。 

### 示例 2

 输入：```
3
10 0
0 10
1 1
```猫总数 = 11，狗总数 = 11，每种至少需要 6 只，$k = 2$。 

按猫排序给出选择$[0, 2]$：cat = 11，dog = 1，失败。 

按狗分类给出选择$[1, 2]$：猫 = 1，狗 = 11，失败。 

这表明，如果结构在两个极端之间完美平衡，则朴素的单阶贪婪是不够的。

 ## 边缘情况

 一个关键的边缘情况是当一个类别严重集中在少量容器中时。 例如：```
5
100 0
90 0
0 200
0 180
1 1
```该算法必须避免仅选择以猫为主或以狗为主的前缀。 按猫排序产生的集合可能完全忽略狗重的容器，因此有必要进行第二次按狗排序的尝试。 正确的解决方案来自于狗分类选择，其中包括足够的狗重容器以满足阈值。 

另一个边缘情况是当$n = 1$。 必须选择唯一的容器，并且它很容易满足两半，因为它等于整个数据集。 

最后，当许多容器具有相同的值时，订购稳定性并不重要，但选择仍然必须遵守尺寸限制。 该算法仍然正确，因为相等元素的任何排列都保留了总和和可行性。
