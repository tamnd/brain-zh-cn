 ## 解决方案
 ## 问题理解

 我们得到了一系列分配给鸟类的不同评级，其中每个位置对应于按顺序遇到的新鸟。 奥列格在第一次遇到每只鸟时都会听一次，但他的行为会带来额外的重新聆听：每当他遇到一只评级低于之前看到的评级的鸟时，他就会“跳回到”迄今为止他见过的评级最高的鸟，并在继续之前再次聆听那只最好的鸟。 

因此，该过程是遍历数组，但偶尔会重置为迄今为止看到的当前最大元素。 每当一个新值出现时，我们总是要花一分钟的时间来听那只新鸟的声音。 此外，如果新值小于当前最大前缀值，我们还会额外花费一分钟来再次监听该最大元素。 

输出要求两件事：监听事件的总数（初始监听加上所有重复），以及在此过程中任何一只鸟被监听的最大次数。 

约束 n 高达 200,000 意味着我们需要 O(n) 或 O(n log n) 解决方案。 由于行为仅取决于前缀最大值和比较，因此任何模拟都必须避免重复扫描最大值，这在最坏的情况下会降级为 O(n^2)。 

当增加最大值后出现许多“下降”时，简单的方法就会失败。 例如，如果序列在高值和低值之间交替，则重复重新计算最大值或低效地跟踪访问将导致重复的全扫描。 

一个微妙的边缘情况是最大值不断变化，就像严格递增的序列一样。 在这种情况下，不会发生重复。 相反，像这样的序列`100, 1, 99, 2, 98, 3, ...`迫使许多人反复跳回到相同的最大值。 

## 方法

 直接模拟将维护已访问过的鸟类的列表，并且在每一步中，只要当前评级低于该最大值，就在其中搜索评级最高的鸟类。 这需要每步进行线性扫描或具有更新的优先级结构，但真正的困难是我们不是动态删除或插入，我们只需要当前的前缀最大值。 

在暴力解释中，在每一步 i 中，我们都会在需要时计算所有先前元素中的最大值。 在最坏的情况下，每一步都会触发一次 O(n) 的扫描，即 O(n^2)。 当 n 达到 200,000 时，这太慢了。 

关键的观察是“迄今为止最好的鸟”只是前缀最大值。 一旦我们增量地维护这个值，我们就不需要重新计算它。 该过程变得确定性：当我们看到 a_i 时，我们将其与当前最大值 M 进行比较。如果 a_i > M，我们更新 M。否则，我们添加对 M 的额外访问。 

这将整个过程简化为单个线性传递，并且我们还可以使用按位置索引的字典或数组来跟踪每只鸟的访问计数，因为每只鸟都是由其位置唯一标识的。 

总分钟数就是我们模拟的总访问次数。 每当我们增加一只鸟的计数器时，单只鸟被访问的最大次数就会更新。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理鸟类，维护两个状态：迄今为止看到的当前最大评级，以及从鸟类索引到已收听次数的映射。 

1. 将当前最大值初始化为第一只鸟的评级，并将其访问次数设置为 1，因为奥列格在第一次遇到时会听一次。 这建立了至少听到一只鸟的声音的基础状态。 
2. 初始化总时间为1，匹配第一个监听事件。 
3. 对于从 2 到 n 的每只下一只鸟 i，首先递增其自己的计数器，因为奥列格总是在新鸟到达时听一次。 这反映了强制性观察步骤。 
4. 将第一次聆听的总时间加 1。 
5. 将 a_i 与当前最大值进行比较。 如果 a_i 大于最大值，则将最大值更新为 a_i 并且不执行其他操作。 原因是之前见过的鸟没有比这只更好，所以不会发生回溯。 
6. 如果 a_i 小于最大值，则找到当前拥有最大值的鸟（我们跟踪其索引），增加其访问计数器，并将总时间加 1。 这个模型让奥列格回去重新聆听迄今为止最好的鸟的声音。 
7. 处理完所有鸟类后，计算所有访问计数器中的最大值。 

正确性取决于以下事实：重新访问的唯一候选者始终是前缀的全局最大值，并且只有当出现严格更大的评级时，该最大值才会发生变化。 

### 为什么它有效

 在每一步中，唯一依赖于历史的决策是是否发生“后跳”，并且该决策仅取决于当前值是否小于所有先前值的最大值。 由于前缀的最大值是唯一定义和单调更新的，因此该算法永远不会错过所需的重新访问，也永远不会执行不必​​要的重新访问。 每次重新访问完全对应于一个实例，其中前缀最大值主导当前元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # track current maximum value and its index
    max_val = a[0]
    max_idx = 0
    
    # visit counts per bird
    cnt = [0] * n
    
    cnt[0] = 1
    total = 1
    
    for i in range(1, n):
        cnt[i] += 1
        total += 1
        
        if a[i] > max_val:
            max_val = a[i]
            max_idx = i
        else:
            cnt[max_idx] += 1
            total += 1
    
    print(total, max(cnt))

if __name__ == "__main__":
    solve()
```实现直接对算法中描述的过程进行编码。 数组`cnt`存储每只鸟被听的次数，同时`max_val`和`max_idx`保持当前最好的鸟在前缀中。 每次迭代都会贡献一次强制监听，有时当当前元素不是新的最大值时会额外贡献一次。 

一个微妙的点是我们永远不会从头开始重新计算最大值。 变量`max_idx`始终指向重新访问的正确候选者，因为前缀的最大值仅在出现严格更大的值时才会更改。

 ## 边缘情况

 对于一只鸟来说，这个过程没有分支。 算法初始化`cnt[0]=1`Total 立即变为 1，并且由于没有发生迭代，因此最大访问计数为 1，与预期输出相符。 

在严格递增的序列中，例如`1 2 3 4`，每个元素都成为新的最大值，所以`max_idx`每一步都会更新，并且不会重新访问。 该实现仅执行“new max”分支，保持总计等于 n 并且所有计数等于 1。 

在严格递减序列中，例如`5 4 3 2 1`，第一个元素成为全局最大值并保持不变。 每个后续步骤都会触发重新访问索引 0。代码重复递增`cnt[max_idx]`，累积第一个元素的 n 次访问并生成总数`2n-1`，与第一个步骤之后每一步额外重新访问一次一致。
