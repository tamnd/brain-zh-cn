 ## 解决方案
 ## 问题理解

 青蛙从一排的第一块石头开始`n`石头并想到达最后一个。 通常它会向前移动一步，按顺序访问每一块石头。 在它的旅程中，只有一次，它可以通过以下方式向前跳跃：`k`位置，完全跳过中间的石头。 

当青蛙被访问时，每块石头都会为青蛙的得分贡献一个值。 青蛙总是访问第一块和最后一块石头，并且对于任何访问过的石头，它都会将其值添加到总分中。 被跳过的石头没有任何贡献，因为它们从未被访问过。 

任务是选择在哪里使用单次长跳转，使得访问值的总和尽可能大。 

约束条件达到`n = 3 · 10^5`，这立即排除了任何在二次时间中天真地尝试所有可能的跳跃位置的解决方案。 任何重新计算每个候选职位的分段总和的方法都会太慢，因为最多有`O(n)`选择和每一个都会付出代价`O(n)`工作。 

一些边缘情况很容易被忽略。 

如果`k = 1`，“跳远”与正常移动相同，因此它不会改变任何内容，答案只是所有值的总和。 

如果`k = n`，青蛙可以直接从第一块石头跳到最后一块石头，跳过中间的所有内容。 在这种情况下，最优策略可能会也可能不会使用跳跃，具体取决于中间值总体是否为负，但在结构上它仍然匹配相同的模型。 

另一个微妙的情况是所有值都为正时。 那么跳过任何东西都是有害的，所以最好的答案还是全额。 

最后一个极端情况是当大的负块存在于其他正数组内时。 这些正是跳跃想要避免的。 

## 方法

 如果我们忽略计算时间的限制，我们可以尝试青蛙使用长跳的所有可能位置。 假设它从位置跳转`i`到`i + k`。 然后青蛙会跳过这些索引之间的所有值，这意味着我们必须重新计算不包括该段的完整路径总和。 直接执行此操作需要对每个值求和一个范围`i`，并且有`O(n)`这样的位置，所以总复杂度变成`O(n^2)`。 

这在逻辑上是有效的，因为它明确地评估每个有效的决策，但是当`n`达到数十万。 

关键的观察是，青蛙在不使用跳跃的情况下的路径是固定的，并且等于所有元素的总和。 使用跳转仅删除精确的连续块`k - 1`总和中的元素。 该块的端点仍然包含在内，因为青蛙仍然访问跳跃的起点和终点。 

所以问题就等同于寻找一段长度`k - 1`具有最小总和。 删除总和最小的段可以得到最大可能的剩余总和。 

一旦看到这一点，解决方案就会简化为固定长度窗口上的经典滑动窗口最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 滑动窗 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题转化为最小化跳过段的成本。 

1. 计算所有值的总和。 这表示不考虑跳跃效果的情况下的分数。 
2.如果`k = 1`，立即返回总和，因为没有任何元素以任何有意义的方式被跳过。 
3. 定义跳过段的长度为`L = k - 1`。 每个可能的跳转对应于删除一个连续的长度子数组`L`。 
4. 计算第一个窗口长度之和`L`。 这给出了最小跳过总和的基线候选。 
5. 在阵列上从左向右滑动窗口。 在每个步骤中，删除前一个窗口的最左边的元素并添加新的最右边的元素。 这会在每个班次的 O(1) 时间内更新窗口总和。 
6. 跟踪在此过程中遇到的最小窗口总和。 
7. 从总和中减去最小跳过总和并返回结果。 

### 为什么它有效

 任何有效的策略完全由单跳的位置决定。 该选择恰好对应于选择一个连续的块`k - 1`不会被访问的元素。 所有其他元素始终包含在内。 因此，每个有效答案都对应于“总和减去固定长度的一个窗口总和”，并且最小化该窗口总和可以保证最佳的最终得分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)

    if k == 1:
        print(total)
        return

    L = k - 1

    window = sum(a[1:1+L])
    min_window = window

    for i in range(2, n - L + 1):
        window += a[i + L - 1] - a[i - 1]
        if window < min_window:
            min_window = window

    print(total - min_window)

if __name__ == "__main__":
    solve()
```代码首先计算所有棋子的总和。 然后它处理特殊情况`k = 1`没有发生有意义的跳过的地方。 

变量`window`跟踪当前跳过的段的总和。 它被初始化为从索引开始的第一个有效段`1`（基于 0 的索引中的第二个元素，因为跳转会跳过端点之间的内部节点）。 该循环通过删除离开窗口的元素并添加新的进入元素，以恒定的时间更新此窗口。 

最终结果从总和中减去最小的此类窗口。 

一个常见的实现错误是跳过的段中的索引相差一。 该段必须开始于`i + 1`并结束于`i + k - 1`，不包括跳转的端点。 

## 工作示例

 ### 示例 1

 输入：```
5 3
1 2 -3 4 5
```这里`k = 3`，所以跳过的段长度为`2`。 

我们计算总和：`1 + 2 - 3 + 4 + 5 = 9`现在评估所有长度为 2 的段：

 | 窗口启动 | 细分 | 总和 |
 | --- | --- | --- |
 | 2 | [2，-3] | -1 |
 | 3 | [-3, 4] | 1 |
 | 4 | [4, 5] | 9 |

 最小跳过总和为`-1`。 

最终答案是`9 - (-1) = 10`。 

这表明最好的策略是跳过有害的部分，与完整路径相比，有效地获得价值。 

### 示例 2

 输入：```
5 2
1 2 3 4 5
```这里`k - 1 = 1`，所以我们要删除一个元素。 

总和是`15`。 

所有单元素窗口都是：

 | 窗口启动 | 价值|
 | --- | --- |
 | 2 | 2 |
 | 3 | 3 |
 | 4 | 4 |
 | 5 | 5 |

 最小值为`2`。 

最终答案是`15 - 2 = 13`。 

这证实了当允许跳过时，算法自然地避免了最小的贡献。

 ## 边缘情况

 当`k = 1`，算法立即返回全部总和。 没有跳过的段长度，因此完全绕过滑动窗口逻辑。 用于输入`1 1`有价值`7`，输出是`7`，这符合没有发生真正跳转的定义。 

什么时候`k = n`，窗口长度变为`n - 1`，这意味着只有一个可能的跳过段。 该算法仍然正确地将其计算为单个窗口总和。 例如，在`5 5`有价值观`1 2 3 4 5`，跳过的段是`[2, 3, 4, 5]`，给出结果`15 - 14 = 1`。 青蛙有效地在完整路径或直接跳跃之间进行选择，并且该公式准确地捕获了这一点。
