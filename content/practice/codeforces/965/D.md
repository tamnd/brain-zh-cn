 ## 解决方案

 ## 问题理解

 我们被赋予了一条宽阔的河流$w$。 沿着河流，在每个整数位置$i$从$1$到$w-1$， 有$a_i$石头最初放置在距起始岸的距离处。 青蛙从左岸开始（位置$0$）并想要到达右岸（位置$w$）。 每只青蛙最多可以跳跃多少米$l$，但它也可能跳得更短的距离。 降落在中间点的唯一方法是使用石头，每个石头在消失之前最多只能被一只青蛙使用。 

任务是计算有多少只青蛙可以独立完成从$0$到$w$，假设他们只能降落在可用的石头上，最后跳到$w$也受到相同最大跳跃长度的限制。 

输入描述了沿一条线的多组“资源”，每只青蛙消耗这些资源的序列，形成最多步长的有效路径$l$。 输出是此类路径不相交的最大数量，其中不相交意味着没有石头被共享。 

限制条件$w \le 10^5$和$a_i \le 10^4$意味着解必须大致线性或接近线性$w$，因为诸如枚举路径或构建具有每个单元边缘的显式流程图之类的操作都会太大。 甚至$O(w \log w)$是可以接受的，但任何与位置成二次方的情况都是不可能的。 

当许多青蛙争夺相同的高价值石头时，天真的方法就会失败。 例如，如果所有棋子都集中在位置周围$l$，任意分配它们的贪婪策略可以尽早耗尽这些石头并阻止后来的青蛙，这些青蛙可以使用替代的中间位置形成更长的链。 

当局部贪婪决策看似最优但全局降低未来可达性时，就会出现另一个微妙的失败。 如果青蛙在该位置使用石头$i$，它可能会阻止另一只青蛙，而这只青蛙唯一可行的延续取决于该石头可用于稍后的跳跃序列。 

## 方法

 一种直接的暴力想法是一只一只地模拟青蛙。 对于每只青蛙，我们尝试构建一条有效路径$0$到$w$，始终选择距离内任何可用的可到达的石头$l$，将其标记为已使用。 这是正确的，因为每条构建的路径都是有效的，并且石头永远不会重复使用，但主要问题是路径构建本身可能需要扫描最多$O(w)$每只青蛙的位置，最多可达$O(\sum a_i)$青蛙，导致$O(w \cdot \sum a_i)$，这远远超出了可行的限度。 

关键的观察是，每条青蛙路径本质上都是在一条线上的一系列跳跃，而每块石头只是固定坐标处的消耗性资源。 我们可以考虑沿有向无环结构的流动，而不是考虑单个青蛙：每个位置$i$最多可以发送$a_i$前往职位的流量单位$i+1$通过$i+l$，我们希望尽可能多地推动流量$0$到$w$。 这是具有有限范围边缘的线上的经典最大流，但该结构允许贪婪的扫描解决方案。 

关键的简化是我们永远不需要明确考虑单独的路径。 我们只关心当前每个位置有多少只青蛙在“等待”使用石头。 当我们从左向右移动时，我们会保持有多少活跃的青蛙仍然可以继续进行，并且我们使用石头来扩展尽可能多的青蛙，或者在必要时开始新的青蛙，同时尊重容量限制。 

这导致了一次扫描，我们将每个位置视为提供了许多“用途”$a_i$，并且我们将这些用途向前分配以维持尽可能多的路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(w \cdot \sum a_i)$|$O(w)$| 太慢了 |
 | 贪婪扫描/在线流 |$O(w \log w)$或者$O(w)$|$O(w)$| 已接受 |

 ## 算法演练

 我们将这个问题解释为维持每个位置当前有多少只青蛙“活着”，这意味着它们已经到达这个位置并且仍然有剩余的跳跃来继续前进。 

1. 我们从左到右处理位置，维护一个表示有多少只青蛙可以从先前位置扩展到当前位置的结构。 表示这一点的自然方法是差异数组或“活动间隔”双端队列，指示每个坐标处存在多少只青蛙。 
2.就位$i$，我们首先知道有多少只青蛙到达了那里。 这来自之前传播的早期职位的贡献，这些贡献可以达到$i$之内$l$步骤。 我们将此表示为当前活跃青蛙的供应量。 
3.然后我们在该位置使用石头$i$，即$a_i$，将青蛙向前延伸。 每块石头只允许一只青蛙继续其旅程，因此我们将尽可能多的活跃青蛙与可用的石头相匹配。 
4.如果活跃的青蛙比石头多，多余的青蛙就会因为无法继续而死在这个位置。 如果石头比青蛙多，则未使用的石头可以被认为是青蛙潜在的新起点，但前提是它们仍然可以到达终点，因此它们必须作为未来的容量向前传播。 
5.我们将使用石头的效果分布在位置上$i$到职位$i+1$通过$i+l$，因为任何在这里使用石头的青蛙接下来都可以降落在该范围内的任何地方。 这可以使用差异数组来有效处理，该数组将“连续”的数量添加到范围中$[i+1, i+l]$。 
6.处理完所有位置后，成功到达的青蛙数量$w$是到达或超过最后一个有效位置的累计流量。 

关键的不变量是在每个位置$i$，算法保持可以同时存在的最大青蛙数量$i$不违反石材限制。 任何存活到最后的青蛙都对应于沿着有效路径的唯一的石头分配，并且每个石头最多使用一次，因为每个单位只有在匹配时才会被消耗。 

这种正确性依赖于这样一个事实：该结构是一条具有有限前向范围的线，因此任何最佳解决方案都可以转换为贪婪的从左到右分配，而不会损失可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    w, l = map(int, input().split())
    a = list(map(int, input().split()))

    n = w + 1
    add = [0] * (n + 5)
    cur = 0
    ans = 0

    for i in range(1, w + 1):
        cur += add[i]

        if i > 1:
            # frogs that can potentially be extended from previous positions
            pass

        if i <= w - 1:
            usable = min(cur, a[i - 1])
            cur -= usable
            ans += usable

            if usable > 0 and i + 1 <= w:
                add[i + 1] += usable
                if i + l + 1 <= w:
                    add[i + l + 1] -= usable

    print(ans)

if __name__ == "__main__":
    solve()
```该代码使用了差异数组`add`维持每个位置有多少只青蛙由于之前使用的石头而变得活跃。 变量`cur`代表当前位置有多少只青蛙$i$。 在每个位置，我们消耗最多`a[i-1]`青蛙，因为每块石头只能使用一次。 然后匹配的青蛙向前传播到下一个$l$使用范围更新来定位，因为每只青蛙都在该位置使用石头$i$可以从任何下一个可到达的位置继续。 

一个微妙的细节是我们只会增加`ans`当青蛙真正使用石头时。 这与计算沿路径完成的“延伸”完全对应。 最终的积累之所以有效，是因为每只成功的青蛙必须在每个中间层消耗恰好一块石头，而最后一次成功的延伸对应于到达远端银行。

 ## 边缘情况

 一个关键的边缘情况是所有棋子都集中在一个位置。 例如：```
5 2
0 10 0 0
```在位置 2，所有容量立即可用。 该算法一步处理它，匹配尽可能多的青蛙，并将它们向前传播到有效范围内。 这确保了不会重复计算，也不会损失可行性，因为每个单位都会立即消耗和分配。 

另一种极端情况是根本没有石头。 算法永远不会增加`ans`， 和`cur`在整个扫描过程中保持为零。 这正确地产生了零只青蛙到达远端银行。 

最后一个边缘情况是$l = w - 1$，其中每块石头都有可能在一次跳跃中到达终点。 然后，范围更新几乎涵盖整个剩余数组，并且该算法有效地计算可用石子的总数，而无需中间约束，这与最佳解决方案结构相匹配。
