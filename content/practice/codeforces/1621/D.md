 ## 解决方案
 ## 问题理解

 我们有一个大小为的正方形网格$2n \times 2n$。 左上象限，由第一个象限组成$n$行和第一行$n$列，最初每个单元格只包含一个朋友。 右下象限，最后一个象限$n$行和最后$n$列，最终每个单元格必须包含一个朋友。 左上象限之外的一些单元格被雪覆盖，除非以给定的成本清除积雪，否则无法穿越。 目标是找到除雪的最小成本，以便所有朋友仅使用循环的行和列移动即可到达右下象限。 

该问题迫使朋友可以以循环方式沿行或列移动：移动经过最后一行或最后一列会绕到第一行或第一列。 然而，如果朋友踩到积雪覆盖的牢房，他们就会生病，因此必须事先清除移动路径上的所有积雪。 

主要限制是$1 \le n \le 250$并且总和$n$跨测试用例最多 250 个。这意味着解决方案迭代所有$2n \times 2n$每个测试用例中的单元格都是可行的。 除雪的成本可能高达$10^9$，所以一定要避免不必要的操作，防止超支。 

一个微妙的点是，只有右下象限对朋友的最终位置很重要，但是在第一个或最后一个循环移动期间可能会被忽略的雪$n$左上象限之外的行/列也可能会阻止移动。 粗心的方法可能会尝试清除右下象限的所有积雪，但这是不必要的。 相反，我们只需要考虑紧邻左上象限的单元格，这些单元格可能会阻塞进入右下象限的“入口”路径。 

例如，如果$n=1$，网格是$2 \times 2$。 左上角有一位朋友$(1,1)$右下角是$(2,2)$。 只有细胞$(1,2)$,$(2,1)$， 和$(2,2)$可能与成本相关。 考虑到右下象限中的所有雪的天真的方法会计算过多。 

## 方法

 暴力方法将尝试模拟沿着循环行和列移动的每个可能序列移动所有朋友，跟踪哪些单元格被雪阻挡。 这在理论上是正确的，但在计算上是不可行的，因为可能的序列数量呈指数增长$n$。 即使检查行/列移动的所有排列也远远超出了$1$第二时间限制。 

关键的见解是，无需单独模拟每个朋友即可确定最小除雪成本。 因为朋友们是无法区分的，而且移动是循环的，所以只有能挡住从左上象限到右下象限的“入口”的雪才重要。 具体来说，左上象限之外正好有四个角，可以立即影响通过一行或一列移动将朋友转移到右下象限的能力。 这些细胞是$(n, n+1)$,$(n+1, n)$,$(n+1, 2n)$， 和$(2n, n+1)$对于一个$2n \times 2n$网格。 最小成本只是右下象限中所有除雪成本的总和（这是不可避免的）加上这四个“入口”单元格中的最小成本。 

这一观察结果减少了潜在的问题$O((2n)^2)$检查到一个简单的$O(1)$每个测试用例的入口成本计算，加上右下象限的线性总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((2n)^2 * n!) | O((2n)^2 * n!) | O((2n)^2) | O((2n)^2) | 太慢了 |
 | 最佳| O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n$然后阅读$2n \times 2n$除雪费用网格。 
3. 将最小成本初始化为零。 这将累积清除右下象限中所有积雪的成本。 
4. 迭代右下象限（行$n+1$到$2n$, 列$n+1$到$2n$）并将所有除雪费用加起来。 这确保了每个朋友在右下象限都有一个有效的最终单元格。 
5. 确定左上象限外部的四个“入口”单元格，这些单元格可能会阻止朋友从左上象限移动到右下象限：

 - 右上角入口：$(1\text{ to } n, n+1)$- 左下入口：$(n+1, 1\text{ to } n)$- 右下排入口：$(n+1, 2n)$- 右下栏入口：$(2n, n+1)$6. 找出这四个入口单元中最小的除雪成本。 将此成本添加到步骤 4 的总和中。 
7. 输出每个测试用例的总最小成本。 

为什么有效：朋友是无法区分的，只有右下象限内的相对位置才重要。 必须始终清除右下象限内的积雪。 四个相邻的单元格代表允许从左上象限到右下象限循环移动所需的最小额外除雪量。 通过选择其中的最小值，我们可以确保始终存在一条有效路径而不会超支。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        grid = [list(map(int, input().split())) for _ in range(2*n)]
        
        # sum of all snow costs in bottom-right quadrant
        total = 0
        for i in range(n, 2*n):
            for j in range(n, 2*n):
                total += grid[i][j]
        
        # four "entrance" cells
        entrance_costs = [
            grid[0][n],     # row 1, column n+1
            grid[n-1][2*n-1], # row n, column 2n
            grid[n][0],     # row n+1, column 1
            grid[2*n-1][n-1] # row 2n, column n
        ]
        total += min(entrance_costs)
        print(total)

if __name__ == "__main__":
    solve()
```该代码读取所有测试用例并构造$2n \times 2n$网格。 它将所有除雪成本汇总在右下象限，因为这些单元格必须可供朋友免费占用。 四个入口单元格被仔细索引：一个位于左上象限的最后一列，一个位于左下象限的第一列，另外两个位于与右下象限相邻的边缘。 我们取其中最小的成本并将其添加到右下角的总和中。 

## 工作示例

 **示例1**：

 输入：```
1
1
0 8
1 99
```步骤跟踪：

 | 细胞| 成本| 原因 |
 | ---| ---| ---|
 | (2,2) | 99 | 99 必须获得最终位置|
 | 入口：(1,2)=8、(2,1)=1、(2,2)=99、(1,2)=8 | 最小值=1 | 只需一项最低入场费 |

 总计 = 99 + 1 = 100。与预期输出匹配。 

**示例2**：

 输入：```
2
2
0 0 0 0
0 0 0 0
9 9 2 2
9 9 9 9
```右下象限总和：2+2+9+9=22

 入口单元格：(1,3)=0、(2,4)=0、(3,1)=9、(4,2)=9 → min=0

 总计 = 22 + 0 = 22。与预期输出匹配。 

这些痕迹表明，只有右下象限和四个入口单元格是相关的。 该算法忽略了不相关的雪，将问题简化为入口的恒定时间选择加上象限上的线性和。
