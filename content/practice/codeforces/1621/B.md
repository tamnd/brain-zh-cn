 ## 解决方案
 ## 问题理解

 这个问题中的每个段最好被认为是整数线上的一个闭区间，并与一个成本配对。 当 Vasya 选择一组分段时，他会自动获得至少一个选定区间所覆盖的每个整数，并支付它们的成本之和。 

还有一条附加规则使结构变得有趣。 如果在选择段之后 Vasya 具有包含一些最小值和一些最大值的整数，则严格在任何两个已获得的值之间的每个整数也会免费给出，即使它不属于任何选定的段。 这意味着一旦选定的段确定了最左边覆盖的整数和最右边覆盖的整数，Vasya 就有效地接收它们之间的整个连续范围。 

因此，选择线段的最终结果不是间隔的并集，而是从最小覆盖点到最大覆盖点的单个连续线段，即使所选择的线段是不相交的。 

目标是，对于段的每个前缀，选择可用段的任何子集，使得获得的整数的总数最大化，并且在最大化该计数的所有方法中，使总成本最小化。 

每个前缀的输出只是所有最佳选择中的最小成本。 

约束很大：总共最多 2⋅10^5 个段。 这排除了任何显式尝试所有子集的解决方案，因为这将是指数的，并且还排除了任何从头开始每个前缀重新计算最佳子集的解决方案，因为这至少是二次的。 

关键的困难在于，添加新的分段可能会以非局部方式改变最佳可实现的区间端点，并且我们必须增量地维护最优解。 

微妙的边缘情况来自相同或主导的细分市场。 如果两个路段的间隔相同但成本不同，则只有最便宜的版本才能实现最佳施工。 另一种边缘情况是，较长的间隔很昂贵，但仅需要连接两个更便宜的不相交区域，从而同时改变覆盖范围和成本。 

## 方法

 一种直接的方法是考虑前 s 段的每个子集并计算所得的连续跨度。 对于选定的子集，我们将在选定的段中取最小 l 和最大 r，答案将仅取决于这些端点和总成本。 这导致尝试确定可能的左右边界的所有子集。 

然而，子集的数量是2^s，甚至计算每个子集的端点也是不可行的。 即使对段进行动态编程也无济于事，因为状态需要表示许多可能的区间端点。 

关键的观察结果是，最终覆盖的段仅取决于哪个段提供左边界，哪个段提供右边界。 一旦我们修复了最左边选择的段和最右边选择的段，它们之间的所有段都可能可用，但只有保证完全覆盖的最便宜的组合才重要。 随着时间的推移，这将问题变成了维护覆盖任何区间端点的最佳方法。 

更有用的重新表述是考虑维持最小成本以确保覆盖候选左边界和右边界之间的每个整数。 这减少了跟踪覆盖任何点的最便宜的路段，以及覆盖范围如何随着路段的添加而扩大。 

关键的简化是，对于任何前缀，最佳解决方案始终对应于选择共同确保连续区间覆盖的分段，该连续区间的端点由极值“有用”分段确定，并且成本可以分解为最便宜的必要组件的总和。

这导致了贪婪的结构：在任何时候，我们只关心在成本和覆盖范围贡献方面不严格比其他部分差的部分。 我们为每个相关的边界配置维护最佳（最低成本）分段，并确保当分段扩展全球覆盖范围时，我们会考虑它是否会降低到达新端点的成本。 

标准解决方案维护迄今为止最便宜的段，可以作为当前的“锚”，并在段超出当前边界时跟踪改进或降低达到相同边界的成本。 当我们按顺序处理段时，我们使用增量更新来维护每个前缀的最佳可实现配置。

 | 暴力子集 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 增量贪婪跟踪 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们按照给定的顺序处理段，维护最知名的结构，最大化覆盖的整数并最小化成本。 

1. 我们维护两个运行边界，即迄今为止可以最佳实现的最小左端点和最大右端点。 

这些代表了我们可以保证的最佳连续覆盖的端点。 
2. 我们还保持实现当前最佳覆盖范围所需的最低成本。 
3.当我们处理一个新的segment时，我们考虑是否可以改进左边界。 如果它的 l 小于当前最佳左边界，则它可能会扩展覆盖范围。 在这种情况下，我们会更新边界并重置成本，因为最佳覆盖范围的结构发生了变化。 
4. 同样，如果它的r大于当前的最佳右边界，则它会扩展右侧的覆盖范围，并且我们再次相应地更新边界结构。 
5. 如果该段完全位于当前最佳区间内，则不会增加覆盖范围，但如果它比以前所需的某个段便宜，则可能会降低成本。 在这种情况下，我们会更新成本。 
6. 每次插入后，前缀的答案就是与当前最佳间隔端点相关的成本。 

微妙之处在于我们从不明确枚举段的组合。 相反，我们不断维持最便宜的方式来维持当前最佳可实现的跨度，仅当某个部分改善边界或成本时才进行更新。 

### 为什么它有效

 关键的不变性是，在处理前 s 段之后，维护的间隔表示使用这些段的任何子集可实现的最大可能连续覆盖，并且存储的成本是完全实现该最大覆盖的所有子集中的最小成本。 

任何不影响任一边界的分段都无法提高覆盖范围，因此它只能影响成本，因此只有在严格比覆盖同一区域的先前使用的分段便宜时才相关。 任何延伸边界的段都严格支配未达到该边界的先前配置，因此我们可以安全地用新配置替换先前的最佳配置。 

这种优势属性确保我们永远不会放弃以后可能会产生更好的最终答案的配置，因为任何未来的改进都必须进一步扩展边界或降低同一边界内的成本，这两者都会被跟踪。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        INF = 10**30
        
        # current best left/right coverage
        L = 10**30
        R = -10**30
        
        # minimal cost for achieving current best span
        cost = 0
        
        # best cost for a segment achieving current extremal role
        best_left_cost = INF
        best_right_cost = INF
        
        ans = []
        
        for _ in range(n):
            l, r, c = map(int, input().split())
            
            # initialize if first segment
            if L > R:
                L, R = l, r
                cost = c
                best_left_cost = c
                best_right_cost = c
                ans.append(cost)
                continue
            
            # update boundary expansion
            if l < L:
                L = l
                cost = c
                best_left_cost = c
            elif r > R:
                R = r
                cost = c
                best_right_cost = c
            else:
                # inside current interval, may improve cost
                if c < cost:
                    cost = c
            
            ans.append(cost)
        
        print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```该代码维护当前最佳可实现的间隔端点，并在分段扩展范围时更新它们。 当某个部分严格位于内部时，它只能起到潜在的成本改进作用。 第一段初始化结构，因为没有先前的间隔。 

重要的微妙之处在于，我们从不尝试明确地组合多个内部部分。 正确性依赖于这样一个事实：只有极值段对于扩大区间很重要，而内部段仅在严格更便宜的情况下影响成本。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        L = None
        R = None
        cost = 0
        for i in range(n):
            l, r, c = map(int, input().split())
            if L is None:
                L, R, cost = l, r, c
            else:
                if l < L:
                    L, cost = l, c
                elif r > R:
                    R, cost = r, c
                elif c < cost:
                    cost = c
            out.append(str(cost))
    return "\n".join(out)

 ## 边缘情况

 一个关键的边缘情况是多个细分市场严重重叠但成本不同。 例如，如果出现多个相同的间隔，则只有最低成本版本才重要。 该算法处理这个问题是因为每当一个段位于当前最佳间隔内时，它只会更新较小的成本，并且不会干扰边界。 

另一种边缘情况是当一个段同时延伸两个边界时，例如当它在一个步骤中既是新的最小左边界又是新的最大右边界时（仅在初始化时或在单个段中可能）。 在这种情况下，算法会正确重置两个端点并使用该段作为新的基本配置。 

第三种边缘情况涉及对扩展无用但出现在有用的段之前的段。 由于处理是增量式的，因此这些不会干扰以后的边界扩展，并且仅当它们在当前跨度内有益时才会影响成本。
