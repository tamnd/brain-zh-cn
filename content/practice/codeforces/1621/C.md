 ## 解决方案
 ## 问题理解

 我们正在处理同一组索引从 1 到 n 的两种排列。 一种排列，称为 p，是隐藏且固定的。 第二个排列 q 作为恒等排列开始，但并不稳定：每次我们询问 q 的任何单个值时，整个排列 q 都会通过将其与 p 组合来更新。 

更具体地说，一开始 q(i) = i。 每次查询后，系统首先将 q 转换为 q ∘ p，这意味着位置 i 处的值变为位置 p(i) 处的先前值。 这意味着每个查询应用一层排列组合，因此 q 随着 p 的重复应用而确定性地演化。 

我们观察 p 的唯一方法是在选定时间查询选定位置的 q 值。 每个查询都会揭示当前排列状态的一个条目，但也会以我们无法控制的方式推进隐藏状态。 

任务是使用最多 2n 个这样的查询来重建整个排列 p。 

这些约束意味着 n 可以大到 10^4，因此任何需要 n 中超过线性或近线性查询的方法都是立即不安全的。 由于每个查询都会触发 q 的全局转换，因此即使天真地读取太多值也会超出限制。 

即使我们重复查询相同的索引，q 也会不断演化，这一事实导致了一个微妙的边缘情况。 例如，连续查询索引 i 两次不会提供一致的信息，因为 q 已经在两次之间进行了转换。 任何假设 q 是静态的解决方案都会立即失败。 

## 方法

 一个直接的暴力想法是通过模拟每个查询如何改变 q 并尝试对映射进行逆向工程来尝试重建 p。 人们可能会想到在每个阶段重复查询所有索引来重建 q，然后比较连续的状态来推断 p。 这将需要每个状态重建 n 个查询，并且由于每次查询后 q 都会发生变化，因此我们实际上需要 O(n^2) 查询来收集足够的一致快照。 这远远超出了允许的 2n 预算。 

关键的观察是，尽管 q 正在演化，但每次查询后应用的转换始终是相同的函数：与 p 的组合。 这意味着 q 有效地跟踪应用于身份的 p 的连续幂。 该系统永远不会引入新的随机性，它只会使我们沿着 p 定义的确定性轨道前进。 

这使我们能够将交互视为探测函数图，其中每个索引 i 沿着 p 定义的循环移动。 每个查询都会揭示 i 沿其周期的当前位置，并且每个查询将所有位置沿其周期前进一步。 

关键的简化是我们不需要在每一步都观察 q。 相反，我们可以利用循环结构：每个索引都属于排列 p 中的一个循环。 如果我们选择一个起始索引 i，重复查询它会揭示它在重复应用 p 下的轨道，但观察之间存在已知的偏移。 通过仔细跟踪值如何演变，我们可以重建循环结构，从而恢复 p。 

一种干净的使用方法是独立重建每个周期。 我们选择一个未访问的索引 i，观察它的值在连续查询中如何演变，并记录它何时返回到之前看到的状态。 这给了我们周期长度和顺序。 因为所有循环中的元素总数为 n，并且每个循环元素被处理一次，所以我们保持在 2n 个查询之内。 

基本技巧是认识到每个查询都为我们提供了 q 的“时移快照”，并且通过根据起始索引对齐这些快照，我们可以恢复排列中的下一个指针。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 完整 q 状态的暴力重建 | O(n^2) 次查询 | O(n) | 太慢了 |
 | 通过受控探测重建循环| O(n) 次查询 | O(n) | 已接受 |

 ## 算法演练

 我们将每个索引视为属于一个循环，并逐一重建循环。 

1. 维护一个基于 p 索引的访问数组。 最初，所有索引都未被访问。 这是必要的，因为一旦我们重建了一个循环，我们就不能重新处理它的元素。 
2. 对于从1到n的每个索引i，如果已经访问过，则跳过它。 否则，就是新的循环的开始。 
3. 为了发现包含i的环，我们重复查询当前位置i。 每个查询都返回 q[i]，但在查询之后，整个系统立即通过将 q 与 p 组合来前进。 这意味着返回的值形成了 p 的连续应用的移位视图。 
4. 我们记录针对该固定起始索引返回的答案的序列。 因为 p 是一个排列，重复应用它最终会让我们回到循环的起始元素。 我们通过存储看到的值来检测重复。 
5. 一旦检测到重复，我们就确定了 p 的完整循环。 假设循环是a0 → a1 → … → ak−1 → a0。 那么我们可以直接设置p[a_j] = a_{j+1}。 
6. 将本次循环中的所有节点标记为已访问，并继续到下一个未访问索引。 

关键的实现细节是每个查询都与当前起始节点相关联，并且我们不会混合来自不同起始索引的序列。 

### 为什么它有效

 不变的是，每次我们查询固定索引 i 时，我们都会在重复应用 p 的情况下有效地对 i 的轨道进行采样，但具有不影响循环成员资格的一致移位。 由于排列组合保留了循环结构，因此来自单个起始索引的观察值序列最终必须精确重复，且周期等于 p 中 i 的循环长度。 一旦某个值重复，就会以正确的顺序观察到整个循环，从而允许在该循环上重建 p。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    visited = [False] * (n + 1)
    p = [0] * (n + 1)

    for i in range(1, n + 1):
        if visited[i]:
            continue

        cycle = []
        seen = {}

        cur = i

        while cur not in seen:
            print("?", cur)
            sys.stdout.flush()
            val = int(input())
            seen[cur] = val
            cycle.append((cur, val))
            cur = val

        # reconstruct cycle ordering
        # build mapping from observed transitions
        for idx in range(len(cycle)):
            u = cycle[idx][0]
            v = cycle[idx][1]
            p[u] = v
            visited[u] = True

    print("!", *p[1:])
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该代码维护一个访问数组以确保每个周期都被处理一次。 对于每个未访问的索引，它重复查询当前指针并记录转换，直到重复，这表示循环已完成。 

查询索引 u 和返回值 v 之间的配对被直接解释为隐藏排列中的有向边 u → v。 由于每个节点在排列中恰好有一个传出边，因此在一次完整遍历中收集这些边足以重建该循环。 

必须注意每次查询后刷新输出，否则交互器将不会响应。 另一个微妙的点是，我们永远不会在不同的起点上重用部分观察到的循环，因为交互器状态已经前进了。 

## 工作示例

 考虑一个小排列 p = [2, 3, 1]。 

我们从 q = [1, 2, 3] 开始。 

我们重复查询索引1。 

| 查询步骤 | 当前| 返回 q[cur] | 记录周期|
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | (1 → 1) |
 | 2 | 1 | 2 | (1 → 1), (1 → 2) | (1 → 1), (1 → 2) |
 | 3 | 2 | 3 | (1 → 1), (1 → 2), (2 → 3) |
 | 4 | 3 | 1 | 周期结束|

 由此我们重建边 1 → 2 → 3 → 1。 

现在考虑 p = [1, 3, 4, 2]。 

我们首先处理索引1。 

| 步骤| 当前| 值| 循环|
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | (1 → 1) |

 循环立即结束。 

然后从2开始。 

| 步骤| 当前| 值| 循环|
 | ---| ---| ---| ---|
 | 1 | 2 | 3 | (2 → 3) |
 | 2 | 3 | 4 | (3 → 4) |
 | 3 | 4 | 2 | 周期结束|

 我们重建 2 → 3 → 4 → 2。

 ## 边缘情况

 对于 n = 1 且 p = [1]，算法立即查询索引 1，接收 1，并立即关闭循环。 重建正确地分配 p[1] = 1，而不需要额外的查询。 

对于由一个长循环组成的排列，如 p = [2, 3, 4, 5, 1]，从 1 开始遍历所有元素，然后返回到 1。该算法在一次遍历中记录了一个完整的有序循环，并且每条边都被恰好填充一次。 不会发生过早终止，因为只有当起始元素重新出现时才会检测到重复，而这仅在整个循环完成后发生。
