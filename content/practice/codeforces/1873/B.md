 ## 解决方案
 ## 问题理解

 我们得到了一小部分数字，并且允许我们将其中一个精确地增加一个单位。 经过一次修改后，我们计算所有数字的乘积并希望最大化它。 

结构故意很简单：数组很小，因此我们不会针对大型序列或复杂状态进行优化。 相反，决定纯粹是应该增加哪个个位数，以便所得的乘积变得尽可能大。 

尽管约束允许最多 10⁴ 测试用例，但每个测试用例最多有 9 个数字。 这会立即排除每个测试用例中常数因素以外的任何因素。 尝试所有可能性是完全安全的，因为每个案例的总工作量最多约为 9 次操作，这是微不足道的。 

主要的微妙之处在于，增加一个数字可能会对产品产生非局部影响。 例如，将 0 增加到 1 会将乘积从 0 更改为潜在的非零值，这在大多数其他更改中占主导地位。 同样，从 9 增加到 10 也不存在，因为在这个问题中数字仍然是单个整数，所以增加后的最大值只是值上的 10，而不是数字结构。 

当存在零时，就会出现边缘情况。 假设“增加最大数字”的天真的方法可能会严重失败：

 例如，考虑`[0, 1, 9]`。 增加 9 得到乘积 0，增加 1 得到乘积 0，但增加 0 得到`[1, 1, 9]`以及产品 9，这是最优的。 

因此，真正的问题不仅仅是大小，而是对产品的边际贡献。 

## 方法

 蛮力方法很简单。 我们尝试将每个索引递增一次，计算乘积并取最大值。 由于 n ≤ 9，这意味着每个测试用例最多有 9 个候选，每个乘积计算最多需要 9 次乘法，因此在实践中总数是恒定时间。 

这是有效的，因为决策空间非常小，并且没有链接多个选择的约束。 仅当我们错误地尝试贪婪优化（假设局部数字属性决定最佳全局乘积）时，暴力破解才会失败。 

解锁该解决方案的观察结果是，除了单个修改位置之外，选择之间不存在任何交互。 每个候选解决方案都是独立的，因此枚举所有可能性是最优且充分的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次测试 O(n²) | O(1) | O(1) | 已接受 |
 | 最佳 | 每次测试 O(n²)（同样的想法） | O(1) | O(1) | 已接受 |

 这里所谓的“最佳”解决方案只是蛮力本身，因为约束已经迫使它成为最佳的。 

## 算法演练

 1. 读取测试用例的数字数组。 
2. 计算基线想法：我们将尝试将每个索引修改一次。 这确保我们探索每一个有效的配置。 
3. 对于每个索引 i，暂时将 a[i] 加 1。 
4. 计算修改后所有数字的乘积。 这直接评估选择 i 的结果。 
5. 恢复a[i]并继续下一个索引。 
6. 跟踪所有选择中看到的最大产品。 
7.输出最大值。 

### 为什么它有效

 每个有效解都由递增数字的位置唯一确定。 没有其他自由度。 由于我们评估每一种可能的选择，因此我们保证包含最佳的选择。 正确性来自于对恒定大小的决策空间的详尽枚举。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    best = 0

    for i in range(n):
        a[i] += 1

        prod = 1
        for v in a:
            prod *= v

        best = max(best, prod)

        a[i] -= 1

    print(best)
```该解决方案直接实现了测试每个可能的增量位置的想法。 对于每个索引，我们修改它，重新计算完整的乘积，然后恢复它。 恢复步骤很重要，因为未能恢复更改会破坏后续评估。 

由于 n ≤ 9，重复重新计算乘积的成本很低。 嵌套循环不会导致任何性能问题。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        best = 0

        for i in range(n):
            a[i] += 1
            prod = 1
            for v in a:
                prod *= v
            best = max(best, prod)
            a[i] -= 1

        out.append(str(best))

    return "\n".join(out)

 ## 边缘情况

 当数组包含零时，最佳移动几乎总是增加一个零，因为它将乘积从 0 转换为正值。 该算法可以正确处理这个问题，因为它明确地评估每个索引，包括零，没有偏见。 

当所有数字都相同时，每个选择都会产生相同的乘积结构，并且枚举自然地捕获了这种对称性。 

当 n = 1 时，唯一有效的操作是递增该单个数字，并且算法会正确评估该唯一可能性并返回其值。
