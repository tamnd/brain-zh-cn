 ## 解决方案
 ## 问题理解

 我们被赋予了一个$10 \times 10$网格代表具有五个同心得分环的目标。 网格的每个单元格都包含一个箭头，表示为`X`，或者为空，表示为`.`。 这些环的编号从 1（最外层）到 5（中心），落在环中的箭头得分等于该环的编号。 对于每个测试用例，我们必须计算网格上所有箭头的总分。 

输入大小是可控的：$t$最多可以进行 1000 个测试用例，每个测试用例都有一个固定的 10x10 网格。 这意味着检查每个网格的每个单元的强力方法最多将执行$1000 \times 100 = 10^5$运营。 这完全在典型的 1 秒时间限制之内。 因此，性能不是瓶颈，但正确性至关重要：我们必须仔细地将每个单元映射到其环。 

非明显的边缘情况围绕着环的形状。 粗心的方法可能会假设环是由行或列索引的简单范围定义的，但环是同心的，而不是矩形的。 例如，像 (1,1) 这样的单元格位于环 1 中，但 (1,5) 位于环 2 中。缺少此详细信息会错误计算分数。 另一个微妙的情况是一个完全空的网格，它应该输出 0，或者一个充满箭头的网格，它正确地汇总所有环分数。 

## 方法

 强力方法是检查 10x10 网格的每个单元格，并通过手动将其坐标与每个环的范围进行比较来确定其环。 这是正确的，因为环很小且固定，但如果您错误计算范围，则可能会容易出错。 例如，如果您混淆了行/列索引到环号的映射，则可能会分配错误的分数。 

简化这个问题的关键观察是环是同心正方形。 每个环都是一个宽度为 1 的边界，围绕着一个较小的正方形。 我们可以预先计算从单元坐标到环点的映射。 对于 (i, j) 处的单元，到最近边缘的距离决定了它的环。 具体来说，环号为`5 - min(i, j, 9-i, 9-j)`。 该公式优雅地捕获同心层，避免了硬编码范围。 通过这种映射，计算总分数减少为迭代网格，为每个分数添加适当的环分数`X`。 解决方案依然是$O(100)$每个测试用例，但变得更加健壮和可读。

 ## 算法演练

 1.读取测试用例数量`t`。 这控制了外循环。 
2. 对于每个测试用例，初始化一个`score`变量为零。 
3. 逐行读取 10x10 网格。 对于每一行，迭代每一列。 
4. 对于每个单元格`(i, j)`其中包含`X`，使用以下公式计算环数`ring = 5 - min(i, j, 9-i, 9-j)`。 这有效是因为`min(i, j, 9-i, 9-j)`给出从单元格到最近边缘的距离，该距离对应于它距最外环的层数。 从 5 中减去将距离转换为评分方案。 
5. 将计算出的环号添加到`score`。 
6.处理完当前测试用例的所有单元格后，打印总计`score`。 
7. 对所有测试用例重复此操作。 

工作原理：每个单元格都根据其与最近边缘的距离进行分类。 由于环是同心的且宽度为 1，因此距离唯一地标识环。 总结一下大家的分数`X`确保总分正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    grid = [input().strip() for _ in range(10)]
    score = 0
    for i in range(10):
        for j in range(10):
            if grid[i][j] == 'X':
                ring = 5 - min(i, j, 9 - i, 9 - j)
                score += ring
    print(score)
```我们使用读取网格`input().strip()`删除任何尾随换行符。 使用`min(i, j, 9-i, 9-j)`直接编码到最近边缘的距离。 这种方法避免了差一错误，因为所有索引都是从 0 开始的，最大索引为 9，与 10x10 网格匹配。 添加`ring`到`score`嵌套循环内部确保我们只为带有箭头的单元格积累点。

 ## 边缘情况
