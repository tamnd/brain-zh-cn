 ## 解决方案
 ## 问题理解

 我们得到一个表示一条单元格的二进制字符串，其中每个位置要么是黑色，要么是白色。 唯一允许的操作是选择任何固定长度的连续段$k$并将该段中的所有单元格重新绘制为白色。 目标是使用尽可能少的分段重绘操作来消除每个黑色单元。 

关键的观察是每个操作都会影响一个连续的大小窗口$k$，并且可以同时清除该窗口内的多个黑色单元格。 然而，操作通过重叠进行交互，因此问题不在于计算黑色单元格，而在于我们如何以最佳方式放置这些固定长度的“橡皮擦”以覆盖所有黑色位置。 

约束允许最多$2 \cdot 10^5$所有测试用例的总字符数。 这立即排除了任何尝试每个黑色单元的所有可能窗口或以二次时间在字符串上简单地模拟每个操作的解决方案。 一个$O(n^2)$方法将涉及重复扫描或更新重叠的片段，并且不会在时间限制内完成。 

这个问题中出现了一些微妙的边缘情况。 

如果$k = 1$，每次操作仅清除一个单元格，因此答案正是黑色单元格的数量。 一个天真的滑动窗口想法可能会使这种情况变得过于复杂。 

如果字符串没有黑色单元格，则答案为零。 任何假设至少需要一次操作的算法都会错误地输出正值。 

如果黑色单元连续出现在长块中，则贪婪方法必须确保我们不会通过不必要地应用重叠擦除来过度计算操作。 

例如，在字符串中`BBBW`和$k = 3$，位置 0 处的一次操作会清除所有三个黑色单元格。 独立处理每个黑色单元的粗心方法可能会应用多个重叠操作和过量计数。 

## 方法

 暴力方法将模拟每个可能的操作序列。 在每一步中，我们可以尝试选择任何大小的窗口$k$覆盖至少一个剩余的黑色单元格，应用它，然后递归。 虽然这在原则上是正确的，但分支因子很大并且状态空间呈指数增长。 即使是反复扫描最佳窗口并更新字符串的贪婪变体也会降级为$O(n^2)$在最坏的情况下，每次操作仅消除少量新的黑色单元。 

该行动的结构表明了一种更直接的策略。 当我们遇到黑色单元格时，唯一有意义的决定是应用覆盖它的操作。 由于任何操作都会影响整个长度段$k$，最佳选择是使用最左边未覆盖的黑色单元格作为锚点并擦除从那里开始的片段。 任何较早或较晚开始的操作要么无法覆盖该单元，要么浪费对已经干净的区域的覆盖。 

这导致了一个简单的贪婪扫描：我们从左向右移动，每当我们发现一个尚未被先前操作覆盖的黑色单元格时，我们就会从该位置开始应用一个操作。 这会立即清除该单元格以及下一个单元格中的所有黑色单元格$k-1$位置，这样我们就可以安全地跳过。

 | ---| ---| ---| ---|
 | 暴力模拟|$O(n^2)$|$O(n)$| 太慢了 |
 | 贪心扫 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时保持最后应用的操作延伸的距离。 

1. 初始化一个指针$i = 0$和一个变量$covered = -1$，它跟踪先前操作清理的最右边的索引。 
2. 从左到右扫描字符串。 
3.如果$i \leq covered$，由于之前的操作，当前单元格已经是白色的，因此我们移动到下一个索引。 
4. 如果$s[i] = 'B'$，这是一个未覆盖的黑色单元格，因此我们必须从以下位置开始应用新的操作$i$。 
5. 增加答案计数器并设置$covered = i + k - 1$，代表此操作清洁的全范围。 
6. 继续扫描。 

每个操作都强制在第一个未覆盖的黑色单元格处进行，因为延迟它或向右移动会使该位置无法处理。 

### 为什么它有效

 该算法依赖于每个操作都覆盖固定长度间隔的事实。 一旦我们决定覆盖位置处最左边未覆盖的黑色单元格$i$，任何最佳解决方案必须包含至少一个涵盖以下操作$i$。 在所有此类操作中，从$i$永远不会比稍后开始更糟糕，因为它可以在修复问题的同时最大化右侧的覆盖范围$i$。 这创建了一个贪婪的选择属性：一旦我们修复了第一个未覆盖的黑色单元格，我们就将问题减少到一个独立于早期决策的更小的后缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()

    ans = 0
    covered = -1

    for i in range(n):
        if i <= covered:
            continue
        if s[i] == 'B':
            ans += 1
            covered = i + k - 1

    print(ans)
```关键的实现细节是`covered`指针，避免显式修改字符串。 我们不是模拟重画，而是记录最后一次操作延伸了多远。 这可以防止不必要的$O(k)$每次操作都会更新并保持解决方案的线性。 

条件`i <= covered`确保我们永远不会重新考虑之前橡皮擦已经处理过的位置。 支票为`'B'`保证我们只在必要时触发操作。

 ## 边缘情况

 当$k = 1$，算法自然地将每个黑色单元视为需要自己的操作。 每一个都未揭开`'B'`增加答案并设置`covered = i`，因此不会发生跳过错误。 

当没有黑色单元格时，循环永远不会触发操作，因为条件`s[i] == 'B'`永远不会满足。 结果仍然为零。 

当黑色单元在小于$k$，第一个遇到的黑色单元格会触发自动覆盖所有黑色单元格的操作。 例如，`BBBW`和$k = 3$套`covered = 2`，跳过其余部分，无需额外操作，符合最优策略。
