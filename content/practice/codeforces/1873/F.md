 ## 解决方案
 ## 问题理解

 我们有一排树，每棵树都有两个属性：高度和水果数量。 我们想要选择这些树的连续部分。 仅当在其中从左向右移动时，每棵树的高度都能被下一棵树的高度整除，该线段才有效。 这将创建一个定向可分链，限制段的开始和结束位置。 

在所有有效段中，我们希望具有最大树木数量的段，但有一个附加限制：从该段收集的水果总数不得超过给定限制$k$。 如果没有段满足这两个条件，则答案为零。 

关键的困难在于有效性取决于两个独立的约束。 一是结构性的，来自于相邻高度之间的可分关系。 另一个是定量的，来自果实的总和。 

输入大小达到$2 \cdot 10^5$跨所有测试用例，因此任何直接检查所有子数组的解决方案都不适合时间限制。 二次枚举将执行大约$n^2$每个测试用例的分段检查，在最坏的情况下大约是$10^{10}$总体而言，远远超出了可行的范围。 

当每个相邻对的整除性立即失败时，就会出现微妙的边缘情况。 例如，如果高度是`[2, 3, 5]`，那么长度超过 1 的段都是有效的。 任何仅检查水果约束的简单解决方案都会错误地考虑较长的片段。 

当整除性随处成立但水果价值很大时，就会出现另一种边缘情况。 例如，身高`[8, 4, 2]`形成一个完全有效的链条，但如果水果`[10, 10, 10]`和$k = 15$，尽管结构有效，但即使长度为 2 的段也是无效的。 

这两个约束以某种方式相互作用，表明我们应该首先将问题分成可管理的块。 

## 方法

 如果我们暂时忽略结构，问题就会简化为找到总和最多的最长子数组$k$，这是一个标准的滑动窗口问题。 仅该部分是线性的。 

如果我们忽略水果约束，我们需要找到每个相邻对满足的最大线段$h_i \bmod h_{i+1} = 0$。 这可以通过将数组分成最大的“有效链”来预先计算，其中整除性连续成立。 在每个链内，任何子段在结构上都是有效的。 

强力解决方案将尝试每个起始索引，向右扩展，同时检查整除性并保持运行总和。 每次扩展的时间复杂度为 O(n)，重复 n 次，导致每个测试用例的时间复杂度为 O(n²)。 总共 n 可达$2 \cdot 10^5$，这太慢了。 

关键的观察是可分性约束定义了独立的块。 一次$h_i$不分开$h_{i+1}$，任何线段都不能跨越该边界。 所以我们可以单独对待每个最大有效块。 在每个块内，问题变得纯粹：sum ≤ k 的最长子数组，可以使用两个指针来解决。 

我们在每个块上维护一个滑动窗口，当总和保持在 k 以内时向右扩展，否则从左侧缩小。 由于每个块中每个元素最多进入和离开窗口一次，因此总复杂度保持线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 块+两个指针| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从左到右扫描数组并识别每个相邻对满足的段$h_i \bmod h_{i+1} = 0$。 这些是最大的结构块。 每当条件失败时，我们都会重置块，因为没有有效的段可以跨越该边界。 
2. 对于每个块，独立处理。 在块内，每个子数组自动满足整除条件，因此只有总和约束保持相关。 
3. 在块的开头初始化两个指针以及水果的运行总和。 
4. 逐步扩展右指针，将当前水果值添加到总和中。 每次延期后，检查总和是否超过$k$。 
5. 如果总和超过$k$，向前移动左指针，同时减去值，直到总和再次有效。 这以尽可能最小的方式恢复可行性，保留在当前右端点结束的最大窗口大小。 
6. 在每个右端点，用当前窗口长度更新答案。 

贪婪收缩的正确性来自于所有值都是正的。 删除不必要的元素只会进一步缩小窗口，而不会启用任何新的有效配置。 

### 为什么它有效

 该算法依赖于两个不变量。 首先，当前窗口始终完全位于最大可分块内，因此它认为的每个候选段在结构上都是有效的。 其次，滑动窗口在调整后保持其总和始终≤ k 的不变性。 因为所有水果值都是正数，所以扩展只会增加总和，收缩只会单调减少总和，确保每个指针朝一个方向移动，并且不会跳过任何有效候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        h = list(map(int, input().split()))

        ans = 0
        l = 0
        s = 0

        i = 0
        while i < n:
            j = i
            while j + 1 < n and h[j] % h[j + 1] == 0:
                j += 1

            # process block [i, j]
            l = i
            s = 0

            for r in range(i, j + 1):
                s += a[r]
                while s > k and l <= r:
                    s -= a[l]
                    l += 1
                ans = max(ans, r - l + 1)

            i = j + 1

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先使用简单的指针扩展将数组拆分为最大有效的可分链。 每次条件失败时，我们都会关闭该块。 这确保我们永远不会尝试跨无效邻接形成分段。 

在每个块内，我们重置滑动窗口并维护一个运行总和。 左指针只向前移动，从不向后移动，保证了线性复杂度。 

这里的一个常见错误是未能重置块边界处的总和和左指针。 如果不进行重置，窗口可能会错误地包含来自先前无效结构段的元素。

 ## 边缘情况

 一个重要的边缘情况是每个相邻对立即无法整除。 在这种情况下，每个块的大小为 1，算法简化为检查每个单个水果值是否≤ k。 滑动窗口永远不会跨元素扩展，因此正确性完全取决于每个索引的重置。 

另一种情况是整个数组是一个长的有效链。 这里算法的行为必须与总和约束下的标准两指针最大长度子数组完全相同。 块逻辑不得干扰窗口连续性。 

当较大的水果值迫使频繁收缩时，就会出现第三种微妙的情况。 因为所有值都是正数，所以重复收缩总是收敛的，并且不可能出现无限循环。
