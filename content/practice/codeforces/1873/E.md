 ## 解决方案
 ## 问题理解

 我们有一排珊瑚柱，每一个都有一定的初始高度。 我们希望通过选择统一的目标高度在该结构上建造一个水箱$h$。 任何珊瑚位于下方的柱子$h$将充满水至$h$，而上面已经有任何列$h$不需要水。 

因此对于每一列，水的贡献是$\max(0, h - a_i)$，总用水量是这些贡献的总和。 目标是选择尽可能大的整数$h \ge 1$使得所需的总水量不超过$x$。 

关键的难点是增加$h$以非线性但结构化的方式增加用水量，因为每列仅在$h$超过其高度。 

约束足够大，以至于每个测试用例的二次或线性扫描太慢。 高达$2 \cdot 10^5$所有测试用例的总元素和$t \le 10^4$，我们大致需要$O(n \log A)$或者$O(n)$每个测试用例。 任何从头开始重新计算许多候选高度用水量的方法都会超时。 

一些边缘情况值得隔离。 

如果全部$a_i$相比而言较大$x$，答案将接近于$\max(a_i)$或略高于它，因为提高$h$仅仅一点点就可能已经超出了用水预算。 例如，如果$a = [100]$和$x = 5$， 然后$h = 105$只有当我们仔细解释定义时才有效：仅$h - a_i$贡献，所以$h = 105$恰好使用 5 水。 

如果全部$a_i$是相等的并且$x$很大，答案线性增长$x$，因为每增加一个单位$h$准确地添加$n$水。 

一个天真的错误是认为水仅取决于连续排序元素之间的间隙，但实际上它同时取决于所有元素并连续累积，如下所示$h$增加。 

## 方法

 直接的方法是尝试所有可能的值$h$从 1 到类似的值$\max(a_i) + x$。 对于每个候选高度，我们通过求和来计算所需的总水量$\max(0, h - a_i)$全面的$i$。 这是正确的，但是每次评估都会花费$O(n)$，以及范围$h$可以大到$10^9 + x$。 甚至限制在合理的范围内，比如说$10^9$，使得这完全不可行。 

关键的观察结果是函数$$f(h) = \sum_{i=1}^n \max(0, h - a_i)$$是单调的$h$。 增加$h$只能增加或保持用水量，而不能减少用水量。 这种单调性允许二分搜索$h$。 

评估$f(h)$有效地，我们对数组进行排序。 一旦排序，我们就可以以结构化的方式计算贡献。 如果我们固定一个阈值$h$，所有大于或等于的元素$h$贡献为零，以下所有元素$h$线性贡献。 通过前缀和，我们可以计算$h - a_i$全面的$a_i < h$预处理后在恒定时间内。 

这将每次检查减少到$O(\log n)$对于二分搜索步骤，或者$O(1)$如果我们预先计算前缀和并使用二分搜索来查找截止索引。 

从而该问题成为经典的“单调约束下的最大可行值”问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \cdot H)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n \log n + \log H)$每次测试|$O(n)$| 已接受 |

 ## 算法演练

 1. 对数组进行排序$a$按非递减顺序。 排序使我们能够将贡献水的元素与不贡献水的元素分开$h$。 
2. 在排序后的值上构建前缀和数组。 这使我们能够快速计算段的总和，而无需每次迭代。 
3. 定义函数$f(h)$计算给定高度所需的总水量。 我们找到第一个索引$i$这样$a_i \ge h$。 该指数之前的所有内容都贡献水。 
4. 如果$k$是元素的数量$a_i < h$，则用水量为$k \cdot h - \text{sum of those } a_i$。 这个公式由展开而来$\sum (h - a_i)$。 
5. 二分查找$h$。 搜索范围可以安全地扩展到$\max(a_i) + x$，因为超出此范围，需水量至少与$n$。 
6. 对于每个中点$h$, 计算$f(h)$。 如果在预算之内$\le x$，我们可以尝试增加$h$。 否则，我们会减少它。 
7.最终答案是最大的$h$则满足约束条件。 

二分查找起作用的原因是，一旦某个高度变得不可行，任何更大的高度仍然不可行，因为每增加一个单位$h$用水量至少增加柱数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import bisect

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        def water(h):
            idx = bisect.bisect_left(a, h)
            return h * idx - pref[idx]

        lo, hi = 1, max(a) + x + 1

        while lo < hi:
            mid = (lo + hi) // 2
            if water(mid) <= x:
                lo = mid + 1
            else:
                hi = mid

        print(lo - 1)

if __name__ == "__main__":
    solve()
```该实现依赖于排序来启用前缀和和二分搜索。 前缀数组对于计算第一个的总和至关重要$k$常数时间内的元素。 

功能`water(h)`分离出关键公式。 这`bisect_left`调用查找有多少个元素严格小于$h$，它直接决定哪些列需要水。 

二分搜索是在答案空间上执行的，而不是在数组的索引上执行的。 上限选择为$\max(a_i) + x + 1$因为即使在最有利的情况下，每增加一个单位的高度也至少要消耗一个单位的水。 

## 工作示例

 我们追踪第一个示例案例：$a = [3,1,2,4,6,2,5], x = 9$。 

| 小时 | idx (a < h) | idx (a < h) | 前缀总和 | 水 = h·idx − 总和 | 可行|
 | ---| ---| ---| ---| ---|
 | 3 | 4 | 1+2+2+？ 实际上 1,2,2,3 → 8 | 3·4 − 8 = 4 | 是的 |
 | 4 | 5 | 8 | 4·5 − 8 = 12 | 没有|

 从表中看，$h = 3$是可行的并且$h = 4$不在这些中间假设下，但继续正确表明二分搜索后的真实截止值是$h = 4$当对所有步骤进行精确评估时。 

现在考虑一个更简单的情况$a = [1,1,1], x = 10$。 

| 小时 | idx | 总和| 水 | 可行|
 | ---| ---| ---| ---| ---|
 | 3 | 3 | 3 | 3·3 − 3 = 6 | 是的 |
 | 4 | 3 | 3 | 4·3 − 3 = 9 | 是的 |
 | 5 | 3 | 3 | 12 | 12 没有|

 这表明一旦所有元素都低于线性增长$h$，其中每次增量都会增加水量$n$。

 ## 边缘情况

 单元素数组公开了最简单的行为。 为了$a = [5], x = 0$，水函数变为$\max(0, h-5)$。 任何$h > 5$无效，因此答案恰好是 5。二分查找仍然可以正确运行，因为可行性会在该边界处翻转。 

当所有元素都相等时，说$a = [2,2,2,2]$，每次增加$h$水量恰好增加了 4。该函数在以下范围内是完全线性的$h=2$，所以最大$h$是$2 + \lfloor x/4 \rfloor$。 该算法通过前缀计算自然地捕获了这一点，而不需要特殊的大小写。 

什么时候$x = 0$，答案一定是$\min(a_i)$只有当我们禁止用水时，因为任何超过最低用水量的增加都会立即消耗正水。 可行性检查正确拒绝了所有$h > \min(a_i)$。
