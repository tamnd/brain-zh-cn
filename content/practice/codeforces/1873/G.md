 ## 解决方案
 ## 问题理解

 我们得到一个仅由字母组成的字符串`A`和`B`，并且我们可以对相邻字符对执行两种类型的操作。 在第一个操作中，`AB`对可以变成`BC`获得一枚硬币。 在第二个中，一个`BA`对可以变成`CB`获得一枚硬币。 目标是最大化收集的硬币数量。 

每个测试用例给出一个字符串，我们必须输出一个整数，表示该字符串可获得的最大硬币数。 约束表明所有测试用例的字符串长度总和最多为 200,000。 这意味着任何在每个测试用例中检查每个字符恒定次数，甚至线性扫描子字符串的算法都将足够快。 显式检查每个子串的二次方法大约需要$n^2$最坏情况下的操作，可能会达到$4 \cdot 10^{10}$的操作，远远超出了时间限制。 因此线性扫描是必要的。 

例如，不明显的边缘情况包括完全由一个字母组成的字符串`AAAAA`或者`BBBB`。 在这种情况下，无法进行任何操作，并且正确的输出为零。 另一个微妙的情况是交替模式，例如`ABABAB`。 如果从左到右贪婪地应用操作，算法必须避免跳过仍可能产生硬币的重叠对。 例如，在`ABA`, 申请`AB → BC`首先仍然允许剩余的`BA`在第二步中进行转换，总共得到两枚硬币。 过早将字符标记为“已使用”的粗心实施可能会低估硬币。 

## 方法

 暴力方法很简单：扫描字符串中的任何内容`AB`或者`BA`配对，应用转换，获得一枚硬币，然后重复，直到不再存在配对。 这是正确的，因为每次转换消耗一对并产生一枚硬币，因此操作总数恰好对应于可获得的最大硬币。 问题的出现很复杂：每次转换可能需要重新扫描字符串以找到新的对，这可能需要$O(n^2)$如果天真地做的话时间。 

关键的观察是，每次发生以下情况都会获得硬币`AB`或者`BA`，并且变换产生`C`代替第二个字母，该字母不能成为新的有效对的一部分。 这意味着每个`AB`或者`BA`如果我们仔细地从左到右扫描，并在进行过程中替换该对，则原始字符串中的值可以精确计算一次。 如果我们从左边贪婪地处理，那么选择一对而不是另一对没有任何优势：重叠的对会自动处理，因为一旦一个字符被转换为`C`，它不会参与任何未来的操作。 这将问题简化为单个线性扫描，检查相邻字符并对字符对进行计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（重复替换）| O(n^2) | O(n^2) | O(n) | 对于大字符串来说太慢 |
 | 最佳（单线性扫描）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将硬币计数器初始化为零。 这将累积从字符串中获得的硬币总数。 
2. 使用索引从左到右开始扫描字符串`i`初始化为零。 
3. 在每个位置，检查当前字符和下一个字符是否形成一个字符`AB`或者`BA`一对。 如果两者都不是，则增加`i`减一并继续。 
4.如果是一对`AB`或者`BA`找到后，将硬币计数器加一。 移动`i`向前移动两个位置以跳过我们刚刚计算的那对。 这是必要的，因为该对的第二个字符被有效地转换为`C`并且不能成为新对的一部分。 
5. 重复步骤3-4，直到索引`i`到达字符串的倒数第二个字符。 
6. 返回硬币计数器作为测试用例的结果。 

为什么它有效：不变的是每次我们遇到一个有效的`AB`或者`BA`对，它可以转换为一个硬币，并且之后不能贡献给另一对。 从左到右扫描可以保证我们对每个可能的硬币精确计数一次，而不会错过任何机会。 重叠对的处理很自然，因为移动`i`两个确保我们不会重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_coins(s: str) -> int:
    n = len(s)
    coins = 0
    i = 0
    while i < n - 1:
        if (s[i] == 'A' and s[i + 1] == 'B') or (s[i] == 'B' and s[i + 1] == 'A'):
            coins += 1
            i += 2
        else:
            i += 1
    return coins

t = int(input())
for _ in range(t):
    s = input().strip()
    print(max_coins(s))
```功能`max_coins`使用字符串的单个线性扫描。 我们检查每个相邻字符对一次。 成功转换后将索引增加 2 可确保我们永远不会重复使用转换为的字符`C`。 对于测试用例管理，主循环读取测试用例的数量，处理每个字符串，并打印结果。

 | ---| ---| ---| ---|

 | 2 | 一个？ | 1 | 只剩下一个字符了，停止|

 输出是`1`。 这里贪婪的从左到右扫描正确地识别了第一个`AB`一对。 其余`A`无法组成一对，确认不会错过任何机会。

 ## 边缘情况

 字符串`AAAAA`没有有效的对。 从左到右扫描，`i`在没有遇到的情况下从 0 移动到 4`AB`或者`BA`。 正如预期的那样，硬币计数器保持为零。 为了`ABA`，从左到右的扫描正确地计算出第一个`AB`对但忽略尾随`A`不能组成一对。 为了`ABABAB`, 每个相邻的`AB`或者`BA`对对进行计数，而不会重复计算重叠字符，从而确认了贪婪跳过的正确性。 这些具体痕迹表明该算法正确处理最小长度、最大长度和交替模式。
