[CF 169B - 替换数字](https://codeforces.com/problemset/problem/169/B)

 **评分：** 1100
 **标签：** 贪婪
 **求解时间：** 1m 32s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一个十进制数字作为字符串，另一个字符串包含我们可以用于替换的额外数字。 第二个字符串中的每个数字最多可以使用一次。 对于每个选定的数字，我们可以替换原始数字中的任何单个位置。 

目标是最大化最终数值。 

关键的细节是替换字符串中的数字顺序并不重要。 我们可以自由选择任何替换数字并将其放置到号码的任何位置。 由于更重要的位置中的较大数字对最终值的贡献更大，因此这立即表明以最左边的位置为中心的贪婪策略。 

输入大小达到$10^5$两个字符串的数字。 任何重复重建字符串或尝试许多替换组合的解决方案都将失败。 二次算法的执行情况约为$10^{10}$最坏情况下的操作，远远超出了极限。 我们需要一种线性或接近线性的方法。 

一些边缘情况很容易被错误处理。 

考虑这个输入：```
999
123
```答案必须仍然是：```
999
```粗心的实施可能会强制使用所有替换数字并意外地减少数字。 

另一个微妙的情况是：```
1000
999
```最好的答案是：```
9991
```数字`9`应首先在最早的位置上使用，因为较早的数字具有更高的重要性。 首先替换最后一位数字会得到更糟糕的结果。 

重复也很重要：```
1234
3321
```正确答案是：```
3334
```将替换数字按降序排序后，我们应该每次都贪婪地消耗最大的有用数字。 过早使用较小的数字会浪费机会。 

最后一个棘手的情况是替换数字等于当前数字时：```
555
555
```答案依然是：```
555
```替换为相同的数字不会改变任何内容，因此它是无害但不必要的。 贪心算法自然应该跳过这样的操作。 

## 方法

 暴力解决方案将尝试一切可能的方法来将替换数字分配给位置。 对于替换集中的每个数字，我们可以使用它或忽略它，如果使用它，我们可以将其放置到原始数字的任何位置。 可能性的数量呈指数级爆炸。 即使长度为 20，搜索空间也会变得巨大。 

我们可以通过关注位置价值来简化思维。 最左边的数字支配其右边的每个数字。 将第一个数字增加 1 总是比将后面的数字增加 9 要好。 

这一观察完全改变了问题。 我们不应该探索组合，而应该始终尝试使用最大的可用替换数字来改善最早可能的位置。 

假设我们按降序对所有替换数字进行排序。 然后我们从左到右扫描原始数字。 在每个位置，如果当前最大的未使用替换数字大于当前数字，则将其替换。 否则，我们会跳过该位置。 

为什么这是最佳的？ 因为如果一个数字可以提高某个位置，那么尽早使用它总是比稍后使用它要好。 如果最大的剩余数字不能改善当前位置，则较小的剩余数字也无法改善当前位置。 

这将问题转化为排序后的简单贪婪传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最优贪心 | O(n + m log m) | O(n + m log m) | O(米) | 已接受 |

 ## 算法演练

 1. 将原始数字作为字符列表读取，以便可以就地修改数字。 
2. 读取替换的数字并按降序排列。 
3. 维护指针`j`到当前最大的未使用的替换数字。 
4. 从左到右扫描原始号码。 
5. 对于每个职位：

 1. 如果所有替换数字已被使用，则停止。 
2. 将当前数字与最大的未使用替换数字进行比较。 
3. 如果替换数字较大，则替换当前数字并移动`j`向前。 
4. 否则，保持当前数字不变。 
6. 打印修改后的号码。 

关键思想是较早的位置支配较晚的位置。 每当我们可以改进某个位置时，推迟改进是没有帮助的。 立即使用最大的剩余数字始终是最佳选择。 

### 为什么它有效

 在每一步中，算法都保持不变，即处理后的前缀已经尽可能大。 

假设我们正在检查位置`i`。 如果最大的未使用的替换数字大于当前数字，则任何最佳解决方案都必须在该位置放置一些改进的数字。 使用最大的数字是最佳选择，因为较早位置的较大数字总是会击败那里具有较小数字的任何排列。 

如果最大的未使用的替换数字不大于当前数字，则没有剩余的数字可以提高该位置。 跳过它是被迫的。 

因为每个决策都是局部最优的并且不会损害未来的位置，所以贪婪策略会产生全局最大数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = list(input().strip())
s = sorted(input().strip(), reverse=True)

j = 0

for i in range(len(a)):
    if j == len(s):
        break

    if s[j] > a[i]:
        a[i] = s[j]
        j += 1

print("".join(a))
```原始数字被转换为列表，因为 Python 字符串是不可变的。 直接更新列表中的字符非常高效，并且可以避免重复重建字符串。 

替换数字按降序排序，因此始终可以轻松访问最大的可用数字。 这是核心的贪婪准备步骤。 

指针`j`跟踪当前未使用的替换数字。 每个替换数字只能使用一次，因此仅当替换实际发生时指针才会前进。 

该循环从左到右处理数字，因为较早的位置更有价值。 如果当前替换数字不是严格大于当前数字数字，则替换不会改善结果。 由于所有剩余的替换数字都更小，因此没有理由尝试进一步替换该位置。 

该算法从不创建前导零，因为仅当新数字大于现有数字时才会发生替换。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m log m) | O(n + m log m) | 对替换数字进行排序的成本为 O(m log m)，扫描是线性的 |

 和$n, m \le 10^5$，排序在运行时占主导地位。 大约$10^5 \log 10^5$操作很容易满足时间限制，并且与 256 MB 限制相比，内存使用量很小。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    a = list(input().strip())
    s = sorted(input().strip(), reverse=True)

    j = 0

    for i in range(len(a)):
        if j == len(s):
            break

        if s[j] > a[i]:
            a[i] = s[j]
            j += 1

    print("".join(a))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue()

# provided sample
assert run("1024\n010\n") == "1124\n", "sample 1"

# minimum size
assert run("1\n9\n") == "9\n", "single digit replacement"

# no replacement helps
assert run("999\n123\n") == "999\n", "all replacements smaller"

# repeated digits
assert run("1234\n3321\n") == "3334\n", "duplicate replacement digits"

# leading digit improvement
assert run("1000\n9999\n") == "9999\n", "replace earliest positions first"

# equal digits should not waste replacements
assert run("555\n555\n") == "555\n", "equal digits skipped"

 ## 边缘情况

 考虑每个替换数字都小于原始数字的情况：```
987
111
```排序后的替换数字仍然是`111`。 在每个位置，当前替换数字都不大于现有数字，因此算法从不执行替换。 输出仍然是：```
987
```这证实了贪婪规则永远不会减少数量。 

现在考虑许多重复的替换数字：```
1111
999
```该算法从左到右处理位置：

 | 位置 | 当前| 更换| 结果 |
 | --- | --- | --- | --- |
 | 0 | 1 | 9 | 9111 |
 | 1 | 1 | 9 | 9911 |
 | 2 | 1 | 9 | 9991 |

 最终的答案是：```
9991
```跟踪显示，每个替换数字仅被消耗一次，并且始终应用于最有价值的剩余位置。 

最后，检查相等的数字：```
4444
4444
```在每个位置，替换数字等于当前数字。 条件`s[j] > a[i]`每次都失败，所以数量保持不变：```
4444
```这避免了在不能改善答案的操作上浪费替换。
