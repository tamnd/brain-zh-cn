 ## 解决方案
 ## 问题理解

 组织者有一份描述 T 恤颜色的值列表。 对于每种颜色，该值要么写为该颜色衬衫的确切数量，要么写为所有具有该颜色的衬衫的百分比。 衬衫的原始总数丢失了，任务是找到使整个列表有效的每个总数。 

对于选定的总数`T`，如果一个值`x`代表一个百分比，它贡献`T * x / 100`衬衫。 如果它代表一个计数，则它的贡献正好`x`衬衫。 所有贡献的总和必须精确`T`。 

输入尺寸可以达到`100000`，值可以大到`10^9`。 尝试将所有可能的值分配给“计数”或“百分比”将需要指数时间，因为每个小值都可能有两种解释。 即使直接检查许多可能的总数也是不可能的。 该解决方案必须利用百分比限制在 1 到 100 范围内的事实。 

棘手的案例来自于模糊的价值观。 诸如以下的值`50`可以是计数或百分比。 例如，输入：```
2
1 50
```有效总数是`2`和`51`。 总计`2`用途`1`作为计数和`50`以百分比表示。 总计`51`使用这两个值作为计数。 始终至多对待价值观的解决方案`100`因为百分比会错过`51`。 

另一个特殊情况是所有值都是百分比。 这是被禁止的，因为该语句保证至少一个精确计数。 例如：```
3
20 30 50
```选择所有三个值作为百分比给出总百分比`100`但没有固定颜色搭配的衬衫数量，所以必须拒绝这样的解释。 

## 方法

 暴力方法将尝试解释为百分比的每个值子集。 对于每个子集，我们可以得出可能的总数并对其进行验证。 这是正确的，因为每个可能的分配都会被检查，但最多可以有`100000`价值观，放弃`2^100000`作业。 即使只有`30`值不明确，案例数量已经太多了。 

关键的观察结果是，只有来自的值`1`到`100`可以是百分比。 更重要的是，所选百分比的总和最多不得超过`100`。 我们不需要知道哪个确切的子集创建了超出此限制的百分比总和。 我们只需要知道哪些金额是可以达到的。 

让`A`是所有输入值的总和。 假设值的子集被解释为百分比，这些百分比的总和为`q`。 剩余的值被解释为固定计数，因此它们的总和是`A - q`。 总计满足：```
A - q + T * q / 100 = T
```重新排列给出：```
T = 100 * (A - q) / (100 - q)
```对于每一个可达的`q`小于`100`，我们可以计算出一个候选答案并检查划分是否准确。 

剩下的唯一困难是确保至少有一个值保留为计数。 如果选定的百分比子集包含每个元素，则分配无效。 由于所有值的总和通常大于`100`，仅当整个数组总和最多为`100`。 

可以通过在该范围内的微小子集和动态规划来找到可能的百分比和`0`到`100`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n + 100^2) | O(n + 100^2) | O(100) | 已接受 |

 ## 算法演练

 1. 计算所有值的总和，`A`。 值大于`100`不能是百分比，但它们仍然自然地参与总和。 
2. 使用子集和动态规划从最多为`100`。 国家`dp[x]`意味着某些有效的百分比值选择具有总百分比`x`。 

极限只是`100`，所以动态规划的大小是恒定的，无论`n`。 
3. 对于每个可达到的百分比总和`q`从`0`到`99`， 计算：```
numerator = 100 * (A - q)
denominator = 100 - q
```如果`numerator`可以整除`denominator`，所得总数是候选者。 

1. 拒绝通过将每个值分配到百分比一侧而创建的候选。 这只能发生在`A == q`，因为所有值都是正值。 
2. 对所有剩余候选进行排序并打印它们。 

为什么它有效：每个有效的解释都会选择一些值的子集作为百分比。 该子集中影响总公式的唯一信息是其百分比之和，`q`。 动态规划找出所有可能的`q`，因此考虑每个有效总数。 可整除性检查保证计算出的总数是一个整数，计数侧检查保证至少一个元素被解释为精确的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total_sum = sum(a)

    dp = [False] * 101
    dp[0] = True

    for x in a:
        if x <= 100:
            for s in range(100 - x, -1, -1):
                if dp[s]:
                    dp[s + x] = True

    ans = set()

    for q in range(100):
        if not dp[q]:
            continue

        if total_sum == q:
            continue

        num = 100 * (total_sum - q)
        den = 100 - q

        if num % den == 0:
            ans.add(num // den)

    ans = sorted(ans)

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```数组`dp`存储可达到的百分比总和。 它向后更新，以便每个输入值在子集中最多使用一次。 前向迭代将允许对相同的值进行多次计数。 

该公式仅计算`q < 100`。 精确的百分比总和`100`将使分母为零。 这种情况只能描述每个值都被视为百分比的情况，这是无效的，因为必须存在一个精确的计数。 

Python 整数不会溢出，因此乘以`100`即使输入值很大时也是安全的。

## 测试用例```python
import sys
import io

def solve_io(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n = int(data())
    a = list(map(int, data().split()))

    total_sum = sum(a)

    dp = [False] * 101
    dp[0] = True

    for x in a:
        if x <= 100:
            for s in range(100 - x, -1, -1):
                if dp[s]:
                    dp[s + x] = True

    ans = set()

    for q in range(100):
        if dp[q] and total_sum != q:
            num = 100 * (total_sum - q)
            den = 100 - q
            if num % den == 0:
                ans.add(num // den)

    res = str(len(ans)) + "\n" + " ".join(map(str, sorted(ans))) + "\n"

    sys.stdin = old
    return res

assert solve_io("2\n1 50\n") == "2\n2 51\n"
assert solve_io("3\n20 30 70\n") == "4\n120 125 140 300\n"

assert solve_io("1\n100\n") == "1\n100\n"
assert solve_io("4\n2 40 90 5\n") == "3\n137 470 840\n"
assert solve_io("3\n10 20 30\n") == "1\n60\n"

 ## 边缘情况

 当某个值既是可能的计数又是可能的百分比时，算法会通过不同的百分比总和来考虑这两种可能性。 对于输入：```
2
1 50
```

`q = 0`给出总数`51`， 尽管`q = 50`给出总数`2`。 两者都留在答案中。 

当所有值的总和恰好达到可能的百分比总数时，算法会删除每个值都变为百分比的无效解释。 对于输入：```
3
20 30 50
```子集和`100`存在，但没有留下确切的计数。 该问题需要至少一次精确计数，因此放弃解释。 

当出现较大的值时，它们不能是百分比，因为百分比最多是`100`。 他们仍然为`A`，并且相同的公式会自动处理它们。 例如，像这样的值`1000000000`只能留在计数侧，防止不必要的分支。
