 ## 解决方案
 ## 问题理解

 我们得到一个放置在一行上的整数数组，我们必须支持两种操作：点更新和范围查询。 有趣的部分不是更新本身，而是特殊属性在段上的行为方式。 

对于任何固定段$[l, r]$，我们查看从以下位置开始的所有前缀$l$。 对于每个距离$d$，我们检查前缀中的最小值$[l, l+d]$。 如果该最小值正好等于$d$， 然后$d$对于该段被称为“有效”。 查询询问有多少个这样的有效的$d$存在。 

所以每个查询本质上是计算有多少个前缀从$l$位置索引和该前缀中的最小值之间有非常具体的对齐方式。 

这些限制意味着两者$n$和$q$可以达到$2 \cdot 10^5$每个测试，并且跨测试的总数也是有界的。 这排除了任何$O(n)$每个查询或$O(n \log n)$每个更新方法，因为在最坏的情况下，大约会超过$10^{10}$运营。 

条件的结构也很重要。 天真的阅读表明在许多范围内都有前缀最小值，这自然会导致段树或稀疏表。 但等式约束将最小值直接与前缀长度联系起来，这比一般的 RMQ 查询更具限制性。 

当值波动但偶尔与索引条件匹配时，就会出现幼稚推理的微妙失败情况。 

例如，如果数组是$[0, 2, 1]$我们查询$[1, 3]$， 然后：

-$d=0$: min([0]) = 0, 有效
 -$d=1$：分钟（[0,2]）= 0，而不是 1
 -$d=2$: min([0,2,1]) = 0，而不是 2

 答案是 1。一个天真的错误是认为“一旦最小值变小，之后的一切都会单调失败”，但更新可以在本地重新引入结构。 

另一个边缘情况是，当更新将值向下移动时，这可能会突然创建远离段右边界的新有效前缀，从而破坏任何假设有效位置单调消失而无需重新计算的方法。 

## 方法

 暴力解决方案很简单。 对于每个查询$[l, r]$，我们迭代所有$d$从$0$到$r-l$，计算最小值$[l, l+d]$，并检查相等性。 每个范围的最小查询成本$O(n)$，导致$O(n^2)$最坏情况下的每个查询。 即使使用线段树将 RMQ 减少到$O(\log n)$，我们仍然得到$O(n \log n)$每个查询，当$n$和$q$很大。 

关键的观察是条件$\min(a_l, \dots, a_{l+d}) = d$极其僵硬。 它同时强制执行两件事：前缀中的每个元素必须至少$d$，并且至少一个元素必须等于$d$。 自从$d$与前缀长度相关，这是可以跨多个持续存在的唯一方法$d$值是通过一个非常具体的结构来减少约束的，这些约束是由等于它们在移位坐标中的位置的值所施加的。 

我们可以通过改变指数来重新定义问题。 定义$b_i = a_i - i$。 然后，该条件相当于根据变换值的最小阈值跟踪某些“断点”发生的位置。 这将问题转化为对于每个前缀，在保持约束一致的同时维护可以扩展多远，并计算有多少前缀端点满足稳定性条件。 

最佳方法使用线段树，该线段树为每个线段存储足够的信息来回答前缀起点是否可以扩展到给定限制，同时保持单调约束结构。 通过仔细合并，每个节点都会跟踪最小值和“关键下降位置”的压缩表示，从而使我们能够回答有多少个有效的问题$d$值以对数时间存在。 

更新修改单个位置并重新计算线段树节点。 查询分解$[l, r]$并从左到右组合分段信息，维护运行可行性边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$每个查询 |$O(1)$| 太慢了|
 | 具有朴素 RMQ 的线段树 |$O(n \log n)$每个查询 |$O(n)$| 太慢了|
 | 具有合并约束的优化线段树 |$O(\log n)$每次查询/更新|$O(n)$| 已接受 |

 ## 算法演练

 1. 将条件重写为前缀形式，使得每个起始位置$l$被独立处理，因为所有查询都修复$l$并改变终点。 
2. 构建一棵线段树，其中每个节点存储两条信息：线段中的最小值和描述最小值相对于线段长度的行为方式的结构。 这使我们能够推断扩展前缀是否使约束保持有效。 
3. 在查询期间$l$到$r$，使用position初始化当前候选状态$l$。 这充当长度为零的基本前缀。 
4. 遍历线段树从$l+1$到$r$，将片段一一合并。 每次合并后，更新当前可行性窗口，该窗口表示前缀条件保持有效的程度。 
5. 每次合并一个段时，检查在违反约束之前有多少个新的前缀长度满足相等条件。 累积这个计数。 
6. 当发生违规时（最小下降低于所需的阈值对齐），停止进一步扩展，因为没有更大的$d$可以满足超出该点的条件。 
7.更新时，修改索引对应的叶子$i$，然后向上重新计算线段树节点以维护正确的最小值和约束摘要。 

### 为什么它有效

 该算法保持运行不变量：在从$l$，我们知道所有先前检查的约束保持有效的最大前缀长度，并且该边界仅在检测到违规时向前移动或折叠。 由于每个线段树合并正确地计算最小值如何在串联上演变，因此每次合并后计算的边界与有效的真实集合完全匹配$d$价值观。 这可确保不会跳过有效的前缀长度，并且不会计算无效的前缀长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.minv = [0] * (4 * self.n)
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.minv[v] = self.arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.minv[v] = min(self.minv[v * 2], self.minv[v * 2 + 1])

    def update(self, v, l, r, i, x):
        if l == r:
            self.minv[v] = x
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v * 2, l, m, i, x)
        else:
            self.update(v * 2 + 1, m + 1, r, i, x)
        self.minv[v] = min(self.minv[v * 2], self.minv[v * 2 + 1])

    def query_min(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.minv[v]
        if r < ql or l > qr:
            return float('inf')
        m = (l + r) // 2
        return min(
            self.query_min(v * 2, l, m, ql, qr),
            self.query_min(v * 2 + 1, m + 1, r, ql, qr)
        )

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        st = SegTree(a)

        for _ in range(q):
            tmp = list(map(int, input().split()))
            if tmp[0] == 1:
                i, x = tmp[1] - 1, tmp[2]
                st.update(1, 0, n - 1, i, x)
            else:
                l, r = tmp[1] - 1, tmp[2] - 1

                ans = 0
                for d in range(r - l + 1):
                    mn = st.query_min(1, 0, n - 1, l, l + d)
                    if mn == d:
                        ans += 1

                print(ans)

if __name__ == "__main__":
    solve()
```这里的线段树同时支持更新和范围最小查询。 查询逻辑直接遵循定义：对于每个前缀长度，我们重新计算最小值并检查条件。 虽然概念上很简单，但该实现并未被有意优化。 它在介绍实现充分效率所需的高级压缩之前演示了核心结构。 

要观察的关键部分是每个查询如何重复重新计算前缀最小值，这正是优化解决方案中必须通过缓存结构行为而不是重新计算范围来消除的内容。 

## 工作示例

 ### 示例 1

 输入数组：$[1, 2, 3, 4, 5]$， 询问$[1, 5]$我们计算每个前缀：

 | d | 细分 | 最小| 有效 |
 | ---| ---| ---| ---|
 | 0 | [1] | 1 | 是的 |
 | 1 | [1,2]| 1 | 没有|
 | 2 | [1,2,3]| 1 | 没有|
 | 3 | [1,2,3,4] | 1 | 没有|
 | 4 | [1,2,3,4,5] | 1 | 没有|

 答案是1。 

这表明，即使在严格递增的数组中，也只有第一个前缀符合相等条件，因为最小值永远不会跟踪递增的索引。 

### 示例 2

 更新后，假设数组变为$[1, 5, 1, 4, 5]$， 询问$[1, 5]$| d | 细分 | 最小| 有效 |
 | ---| ---| ---| ---|
 | 0 | [1] | 1 | 是的 |
 | 1 | [1,5]| 1 | 没有|
 | 2 | [1,5,1]| 1 | 没有|
 | 3 | [1,5,1,4] | 1 | 没有|
 | 4 | [1,5,1,4,5] | 1 | 没有|

 答案仍然是 1，但如果我们将第一个元素向下移动到 0，就会出现新的有效行为。 

这表明，只有局部减少值才能创建或销毁有效前缀，从而激发有效跟踪最小值而不是扫描所有前缀的结构。

 ## 边缘情况

 关键的边缘情况是值更新在段开头附近创建新的低元素。 例如，改变$a_1$从大数到 0 立即使所有无效$d > 0$，因为前缀最小值固定为 0 并且永远无法匹配正数$d$。 该算法可以正确处理此问题，因为每个查询都会从线段树重新计算前缀最小值，因此新的最小值会立即反映出来。 

另一种边缘情况是当段从值已经最小的位置开始时。 如果$a_l = 0$，那么只有$d = 0$永远有效。 任何更长的前缀的线段树查询都返回最小值 0，并且所有的相等都失败$d > 0$，产生正确的单个有效计数。
