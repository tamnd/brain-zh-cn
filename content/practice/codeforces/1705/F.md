 ## 解决方案
 ## 问题理解

 我们被要求恢复在线真/假考试的答案$n$问题。 每个问题都有一个正确答案，“T”代表正确，“F”代表错误。 了解答案的唯一方法是通过评分系统：我们提交长度的候选解决方案$n$并收到正确答案的数量。 我们的目标是使用最多 675 个查询来确定完整密钥。 

首先要注意的是$n$可以大到 1000。这立即排除了我们尝试所有方法的天真的方法$2^n$可能的组合，这是一个天文数字。 675 的查询限制比$n$，但我们仍然无法承受随机猜测或任何指数级的事情$n$。 每个查询都提供一个全局度量（正确答案的数量），因此我们需要利用这个信号来逐位恢复密钥。 

一个微妙的一点是，我们只能看到正确答案的数量，而看不到哪些答案是正确的。 这是一个信息论挑战：每个查询都给我们$\log_2(n+1)$最多只有位信息，因此我们需要仔细构建查询以可靠地提取每一位信息。 边缘情况包括$n=1$一个查询立即解决问题，并且$n=2$翻转单个答案可以完全解决歧义。 

## 方法

 暴力方法是测试每个可能的密钥。 我们可以提交一系列猜测，每个猜测都与之前的一个问题不同，并观察正确计数的变化。 这原则上可行，但需要最多$2^n$查询。 为了$n=1000$，这是不可能的。 

关键的见解是我们可以使用_翻转测试_独立确定每个问题的答案。 如果我们从最初的猜测开始（全部说“T”），我们就知道有多少答案是正确的。 然后，对于每个问题，我们翻转其值并提交修改后的序列。 如果正确答案的数量增加，则翻转纠正了错误的猜测，因此翻转的值是正确的。 如果正确答案的数量减少，则翻转后的值是错误的，因此原始值是正确的。 这让我们可以准确地确定每个位$n$第一个基线之后的查询。 

进一步的优化是使用类似于二分搜索或位掩码的技术一次处理多个位，但使用$n \le 1000$允许 675 个查询，简单的翻转测试已经很好地满足了限制。 暴力方法会失败，因为解空间呈指数增长，但独立翻转方法将问题减少到线性数量的查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 翻转测试| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 首先提交一个长度序列$n$充满“T”。 记录正确答案的数量，$c_0$。 这提供了与翻转进行比较的基线。 
2. 迭代每个问题$i$从 0 到$n-1$。 对于每个问题，创建基线序列的副本并翻转$i$-第一个答案从“T”到“F”（反之亦然）。 提交这个新序列并读取正确答案的数量$c_i$。 
3.如果$c_i > c_0$，翻转修复了错误的答案，因此翻转后的值是正确的。 更新答案并增加基线$c_0 = c_i$。 
4.如果$c_i < c_0$，翻转破坏了正确答案，因此原始值是正确的。 保留答案不变并且$c_0$保持不变。 
5. 处理完所有问题后，顺序现在与实际答案匹配。 提交以完成。 

为什么它有效：该算法依赖于以下不变量：$c_0$始终跟踪正确识别答案的数量。 每次翻转最多改变一个答案的正确性，因此将新计数与基线进行比较可以直接揭示翻转位是否正确。 由于每个问题只被考虑一次，因此每个答案最多被发现$n+1$查询。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

n = int(input())
# Start with all True
seq = ['T'] * n
print("".join(seq))
flush()
c0 = int(input())

for i in range(n):
    # Flip current bit
    seq[i] = 'F' if seq[i] == 'T' else 'T'
    print("".join(seq))
    flush()
    c_new = int(input())
    
    if c_new > c0:
        # Flip was correct, update baseline
        c0 = c_new
    else:
        # Flip was wrong, revert
        seq[i] = 'F' if seq[i] == 'T' else 'T'

# Submit final answer
print("".join(seq))
flush()
```解决方案如下$n$并从对所有“T”的初始猜测开始。 翻转测试使用每个查询仅更改一位的不变量。 精心更新$c_0$确保我们始终知道已发现答案的正确数量。 第一个问题、最后一个问题和单元素序列等边界条件由循环自然处理。

 ## 边缘情况

 对于$n=1$，算法提交“T”。 如果答案是“F”，第一次翻转会立即检测到它。 查询计数为 2，远低于 675。 

对于所有答案最初都猜错的序列（全是“T”，但密钥全是“F”），每次翻转都会增加正确的计数。 后$n$翻转，序列与键匹配。 不会发生相差一位错误，因为该算法一次仅翻转一位并直接比较计数。 

对于最大尺寸$n=1000$，循环仍然只执行 1001 次查询并使用大小为 1000 的线性数组。这仍然有效并避免整数溢出或缓冲区问题。
