 ## 解决方案
 ## 问题理解

 我们有一排房间，每个房间都有一些灰尘。 马克想要清洁除最后一个房间之外的所有房间，使用一种特殊操作将一个单位的灰尘从较早的房间移动到较晚的房间，但前提是之间的所有房间都非零。 具体来说，我们可以选择两个指数$i < j$这样每个房间都从$i$到$j-1$至少有一个单位的灰尘，减少$a_i$加 1，并增加$a_j$1. 任务是确定使除最后一个房间之外的所有房间完全无尘所需的最少操作次数。 

关键的输入约束是$n$可以达到$2 \cdot 10^5$和总和$n$跨测试用例也不超过$2 \cdot 10^5$。 粉尘含量可能高达$10^9$，因此任何尝试直接模拟每个单独操作的算法都会太慢，因为我们最终可能需要$10^9$最坏情况下的操作。 

当一些房间已经零灰尘时，就会出现微妙的边缘情况。 例如，如果第一个房间为零，我们就无法清除其中的灰尘，而必须依赖后面的房间。 另一个棘手的情况是，当灰尘集中在远离最后一个房间的地方时，需要我们将灰尘“推”到几个房间，甚至可能多次。 

如果尝试一步步执行每个操作的幼稚实现假设每次移动总是可能而不检查中间零，那么它会在时间上失败，有时还会在逻辑上失败。 

## 方法

 蛮力方法很简单：对于每个灰尘非零的房间，尝试右侧所有可能的目的地，应用操作，然后重复，直到除了最后一个房间之外的所有房间都为零。 这是可行的，因为每次操作都会减少某些房间的灰尘，但操作次数最多可达所有灰尘值的总和，这可以是$O(n \cdot 10^9)$，显然太慢了。 

关键的见解是我们不需要模拟每个单独的操作。 考虑操作如何进行：房间内每个单位的灰尘$i$最终必须向右移动，增加某些房间的灰尘$j > i$。 由于目标是清除除最后一个房间之外的所有房间，因此房间内的每一单位灰尘$i$至少贡献$1$其本身的操作，再加上等于它到达可以积累它的房间所需行进的距离的额外操作次数。 具体来说，对于每个房间$i < n$，该房间贡献的总操作等于其灰尘加上因灰尘超过零而产生的任何“溢出”。 对每个房间进行求和即可得出最少的操作次数。 

实现此目的的一个简单而正确的方法是从左到右迭代，保持所需操作的运行总数：如果房间有灰尘$a_i$，它贡献$a_i$将其自身减少到零的操作，然后我们可以想象将这些灰尘向前“移动”，这会增加下一个房间的灰尘。 实际上，我们可以将操作次数累积为$a_i + \text{running\_sum}$在哪里$\text{running\_sum}$带走多余的灰尘。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O（所有灰尘的总和）| O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化变量`ops`为零。 这将计算所需操作的总数。 
2. 从第一个房间到倒数第二个房间迭代房间。 每个房间$i$，执行以下操作：

 - 添加灰尘级别`a[i]`到`ops`。 这个房间里的每一单位灰尘都必须清除，所以至少需要这么多操作。 
- 如果存在下一个房间，则将当前房间的灰尘添加到下一个房间。 该模型在计算必要操作的同时推动灰尘向前移动。 它保留了每个房间的灰尘代表仍需要进一步向右移动的单元的不变量。 
3. 循环结束后，`ops`包含将除最后一个房间之外的所有房间归零所需的最少操作数。 

**为什么有效：** 每个房间的灰尘只能向右移动，并且该操作允许一次移动一个单元，可能会跨多个房间。 通过向前积累灰尘，我们确保每个单元每次移动都会被计数一次。 由于操作无法将中间房间的灰尘减少到零以下，因此这种从左到右的累积可以保证最小计数，而无需执行每个单独的移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    ops = 0
    for i in range(n-1):
        ops += a[i]
        a[i+1] += a[i]
    
    print(ops)
```此代码使用快速 I/O 有效地读取多个测试用例。 对于每个测试用例，它都会迭代第一个$n-1$房间，计算每个房间所需的所有操作并将灰尘向前推。 循环以正确的总操作结束。 主要的微妙之处是确保我们永远不会尝试从最后一个房间或更远的地方移动灰尘，并正确更新下一个房间的灰尘以模拟所有中间移动。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    res = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ops = 0
        for i in range(n-1):
            ops += a[i]
            a[i+1] += a[i]
        res.append(str(ops))
    return "\n".join(res)

 ## 边缘情况

 如果第一个房间为零，比如`0 5 0 0`，该算法通过简单地添加零来处理它`ops`并没有推动任何进展。 然后，来自第二个房间的灰尘会根据需要向右移动。 同样，如果最后一个房间最初有灰尘，则不会计入操作，因为只有第一个房间$n-1$房间数必须为零。 这确保了算法永远不会少算或多算操作。 

对于跨多个中间零的单个操作，例如`2 0 0 1`，该算法正确地将运算累加为 2+0+0 = 2，然后向前推进计算总运算，而无需模拟每个中间步骤。 这种抽象确保了正确性和效率。
