[CF 3D - 最低成本括号序列](https://codeforces.com/problemset/problem/3/D)

 **评分：** 2600
 **标签：** 贪婪
 **求解时间：** 1m 23s
 **已验证：** 是的

 ## 问题理解

 我们得到一个包含三种字符的括号字符串：`'('`,`')'`， 和`'?'`。 每一个`'?'`最终必须成为左括号或右括号。 对于每个未知位置，输入提供两个成本，一个用于将其替换为`'('`和一个用于替换它的`')'`。 

目标不仅仅是产生任何有效的常规括号序列，而是所有有效选择中最便宜的一个。 

常规括号序列有两个属性。 左括号和右括号的总数必须匹配，并且每个前缀必须至少包含相同数量的`'('`作为`')'`。 第二个条件是棘手的。 像这样的字符串`"())("`具有相同的计数，但仍然无效，因为前缀`"())"`已经变成负值了。 

字符串长度最多为`5 * 10^4`，这立即排除了任何指数。 如果有`k`问号，然后暴力尝试`2^k`作业。 即使只有 40 个未知数，也已经有大约一万亿种可能性。 我们需要一些接近线性或`O(n log n)`。 

成本值大到`10^6`，所以最终的答案可能会超出32位整数范围。 在 Python 中，这是自动的，但在其他语言中，需要 64 位整数。 

一些边缘情况使这个问题变得微妙。 

假设我们每次都贪婪地选择更便宜的支架`'?'`。 

输入：```
??
1 100
1 100
```天真的贪婪会产生`"(("`因为`'('`两次都便宜。 该序列无效，因为它永远不会关闭。 正确答案是不可能的，所以我们必须打印`-1`。 

另一个陷阱是太晚才达到平衡。 

输入：```
)?(
1 1
```唯一的未知数变成了`"(( "`或者`"))("`，均无效。 尽管总计数可能匹配，但第一个字符已经破坏了前缀条件。 任何正确的算法都必须立即检测负前缀。 

当我们需要修改先前的决定时，就会出现更微妙的情况。 

输入：```
????
10 1
10 1
1 10
1 10
```如果我们总是选择更便宜的支架，我们最初会得到`"))(("`，立即失效。 最佳策略是暂时治疗所有`'?'`作为`')'`，然后选择性地将一些较早的位置转换为`'('`当余额变为负数时。 这种动态修正是公认解决方案的核心思想。 

## 方法

 蛮力方法在概念上很简单。 对于每一个`'?'`，递归地尝试两种可能性。 构造完一个完整的序列后，检查它是否是正则的，如果是，则计算其总成本。 在所有有效序列中，保留最小值。 

这是可行的，因为原则上对于任何固定任务来说问题规模都很小。 有效性检查是线性的，成本计算也是线性的。 问题是作业的数量。 和`k`未知位置，有`2^k`的可能性。 在最坏的情况下`k = 50000`，这是完全不可能的。 

我们需要利用常规括号序列的结构。 

关键的观察结果是有效性取决于前缀余额。 每当运行余额变为负数时，我们就知道之前在某个地方使用了太多右括号。 修复该前缀的唯一方法是更改​​之前选择的前缀之一`')'`括号内为`'('`。 

这表明了一个贪婪的框架。 

我们最初假装每一个`'?'`是`')'`。 这给了我们一个基准成本，因为替换为`')'`成本`b_i`。 

如果后来我们决定该位置实际上应该是`'('`，则额外费用为：$$a_i - b_i$$该值表示将该位置从`')'`到`'('`。 

现在从左到右扫描字符串，同时保持当前平衡。 

每当我们遇到一个`'?'`，我们暂时将其视为`')'`，添加其关闭成本，并将其升级成本存储在优先级队列中。 

如果余额变为负数，我们必须立即修复前缀。 在所有前面的问号中，我们应该翻转额外成本最小的一个。 这种贪婪的选择是最优的，因为每次修复都会使余额恰好增加 2，所以我们总是想要最便宜的可用修复。 

这将问题转化为使用堆的重复局部修正，产生`O(n log n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^k·n) | O(2^k·n) | O(k) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将输入字符串转换为可变列表，以便我们可以在处理过程中替换字符。 
2. 从左向右遍历字符串，同时保持：

 -`balance`，当前不匹配的左括号的数量。 
-`cost`，到目前为止累计的总重置成本。 
- 存储候选问号的优先级队列，稍后可以从中翻转`')'`到`'('`。 
3、遇到时`'('`， 增加`balance`1.
 4、遇到时`')'`， 减少`balance`1.
 5、遇到时`'?'`，暂时替换为`')'`。 

添加结束成本`b_i`到总成本。 

减少`balance`加 1 因为我们目前将其视为右括号。 
6. 对于这个问号，计算稍后将其转换为所需的额外价格`'('`:$$a_i - b_i$$将此值与位置一起推入最小堆。 
7. 处理完当前字符后，检查是否`balance < 0`。 
8. 如果余额为负数，则当前前缀无效。 我们必须立即修复它，更换一个较早的临时部件`')'`进入`'('`。 
9. 在堆中的所有可用候选者中，弹出额外成本最小的候选者。 

将该字符串中的位置更改为`'('`。 

将额外费用添加到总额中。 

增加`balance`乘以 2 因为替换`')'`和`'('`更改贡献来自`-1`到`+1`。 
10. 如果余额变为负数时堆为空，则无法修复，所以答案是`-1`。 
11. 全扫描后，序列仅在以下情况下有效：`balance == 0`。 

否则左括号太多，没办法修复。 
12. 打印总成本和构建的序列。 

### 为什么它有效

 不变的是，在处理每个前缀之后，我们在保持前缀有效的所有分配中保持最小可能的成本。 

每当余额变为负数时，之前的一些问号必须转换为`'('`。 每次此类转换都会将余额固定为完全相同的金额，即`+2`。 由于所有的维修都同样有效，所以唯一重要的是成本。 选择最小的升级成本始终是最优的。 

该算法绝不会延迟必要的修复。 如果前缀的右括号数量已经多于左括号，则未来的字符无法修复该前缀。 必须立即使用之前看到的问号进行更正。 

由于每次修复都经过优化选择并在需要时准确执行，因此最终序列的总成本最低。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    s = list(input().strip())

    q_data = []
    for ch in s:
        if ch == '?':
            a, b = map(int, input().split())
            q_data.append((a, b))

    ptr = 0
    balance = 0
    total_cost = 0

    heap = []

    for i in range(len(s)):
        if s[i] == '(':
            balance += 1

        elif s[i] == ')':
            balance -= 1

        else:
            a, b = q_data[ptr]
            ptr += 1

            s[i] = ')'
            total_cost += b
            balance -= 1

            extra = a - b
            heapq.heappush(heap, (extra, i))

        if balance < 0:
            if not heap:
                print(-1)
                return

            extra, pos = heapq.heappop(heap)

            s[pos] = '('
            total_cost += extra
            balance += 2

    if balance != 0:
        print(-1)
        return

    print(total_cost)
    print(''.join(s))

solve()
```该解决方案从左到右只处理一次字符串。 每个未知括号最初被假设为`')'`，因为这会创建一个简单的基线配置。 堆存储所有有资格稍后转换为的位置`'('`。 

最微妙的部分是平衡修复步骤。 当余额变为负数时，我们立即从堆中弹出最便宜的升级。 该升级较早发生了变化`')'`进入`'('`，这会使余额增加 2。缺少此`+2`调整是一个常见的错误。 

另一个微妙的细节是，当翻转括号时，我们会覆盖字符串列表中的字符。 如果没有此更新，打印的序列将与计算的成本不匹配。 

即使每个前缀都保持有效，最终的余额检查也是必要的。 例如，`"((("`永远不会变为负数，但仍然不是常规序列。 

堆存储`(extra_cost, position)`因此总是首先选择最小的附加成本。 蟒蛇的`heapq`自然支持这种排序。

 ## 边缘情况

 考虑第一个前缀无效的情况。 

输入：```
)?
1 1
```算法读取`')'`首先，做好平衡`-1`。 由于不存在较早的问号，因此堆是空的并且无法修复。 该算法立即打印`-1`。 

这是正确的，因为未来的字符无法修复已经无效的前缀。 

现在考虑不匹配的左括号。 

输入：```
((
```平衡演变为：```
1 -> 2
```它永远不会变成负值，因此不会触发修复。 扫描完成后，余额仍为`2`，这意味着左括号比右括号多。 最终检查拒绝该序列。 

另一个微妙的情况是翻转支架实际上会降低总成本。 

输入：```
??
10 1
1 10
```该算法首先将两个位置视为`')'`，给予：```
"))
```成本是`1 + 10 = 11`。 

第一个前缀立即失效，因此第一个位置被翻转。 额外费用为：```
10 - 1 = 9
```总成本变为`20`。 

在第二个位置，平衡自然回到零。 最终顺序：```
()
```该算法可以正确处理正升级成本和负升级成本，因为堆始终选择最便宜的可用修复。 

最后，考虑可以进行多次修复的情况。
