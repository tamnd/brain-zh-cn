 ## 解决方案
 ## 问题理解

 给定一个写在书中的整数序列，我们想要计算该序列中有多少个连续段的总和位于给定区间内$[l, r]$。 

通过选择两个索引来定义连续段$i \le j$并对所有元素求和$a_i$到$a_j$。 每个这样的片段都被视为候选“咒语”。 任务是计算有多少个段产生的总和至少为$l$并且至多$r$。 

输入大小最多允许$2 \cdot 10^5$数字，值高达$10^9$在幅度上。 这立即排除了任何显式检查所有的解决方案$O(n^2)$子数组。 即使使用前缀和在恒定时间内计算单个总和，迭代所有端点对也会导致大约$2 \cdot 10^{10}$在最坏的情况下进行操作，远远超出了时间限制。 

这促使我们寻求一种解决方案，将问题简化为计算结构化对而不是枚举它们。 

当存在负数时，会出现一个微妙的问题。 前缀和不再是单调的，因此必须仔细处理依赖于子数组和排序的技术。 例如，简单的滑动窗口方法会失败：即使窗口总和超过$r$，扩展或缩小窗口的行为不可预测，因为添加负数会减少总和。 

两个指针的一个小的说明性失败案例是：

 输入：```
3 1 2
2 -2 2
```子数组是$[2], [2,-2], [2,-2,2], [-2], [-2,2], [2]$。 正确的答案取决于精确的枚举，但两指针方法可能会错误地重复收缩或扩展，因为总和不是单调的。 

核心困难在于，在前缀和为任意实数的情况下，我们需要计算差异在一定范围内的所有前缀和对。 

## 方法

 我们从直接的想法开始。 我们可以通过固定左端点来计算所有子数组的和$i$，然后延伸$j$从$i$到$n$，保持运行总和。 对于每个$i$，这花费了$O(n)$，导致$O(n^2)$总操作。 这是正确的，因为每个子数组都是唯一枚举的，但是当$n$达到$2 \cdot 10^5$，其中操作总数约为$4 \cdot 10^{10}$。 

为了改善这一点，我们使用前缀和重写该问题。 让$p[0] = 0$和$p[i] = a_1 + \dots + a_i$。 然后对子数组求和$[i+1, j]$是$p[j] - p[i]$。 条件$l \le p[j] - p[i] \le r$可以重新排列为：$$p[j] - r \le p[i] \le p[j] - l.$$现在问题变成：对于每个$j$，计算有多少个较早的前缀和落在某个值范围内。 这是一个经典的“动态前缀集中的值计数”问题。 

我们从左到右处理前缀和。 每一步$j$，我们需要查询一个区间内有多少个先前的前缀和。 这可以在前缀和的坐标压缩后使用 Fenwick 树（二元索引树）来解决，因为值可以大到$10^{14}$以中间形式。 

每个前缀和被插入到结构中一次，并且每个步骤对结构执行范围查询。 

这将问题转化为排序坐标系上的高效动态频率计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子数组 |$O(n^2)$|$O(1)$| 太慢了|
 | 前缀和 + Fenwick 树 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将数组转换为前缀和，以便每个子数组和变成两个前缀值的差。 这种转换是必要的，因为它将区间和问题转化为配对计数问题。 

然后我们维护一个数据结构来存储我们已经看到的前缀和的数量。 对于每个新的前缀和，我们询问有多少个先前的前缀和位于从以下公式得出的特定数字区间中：$l$和$r$。 

1. 构建一个前缀和数组，其中第一个值为 0，每个下一个值累加输入数组。 这确保每个子数组对应于一对前缀索引。 
2. 收集所有前缀和并排序以构建压缩坐标系。 需要此步骤是因为前缀和可能很大且为负，但芬威克树需要紧凑索引。 
3. 初始化支持点更新和压缩索引上的前缀和查询的 Fenwick 树。 
4. 将初始前缀和 0 插入到结构中，因为它表示数组开始之前的空前缀。 
5. 从左到右迭代每个前缀和。 对于当前前缀值$p[j]$，计算早期前缀和的有效范围为$[p[j] - r, p[j] - l]$。 
6. 使用压缩坐标上的二分搜索将该值范围转换为索引范围。 
7. 查询 Fenwick 树以了解此索引区间内有多少个前缀和，并将此计数添加到答案中。 
8. 将当前前缀和插入 Fenwick 树中，以便它可用于未来的位置。 

关键思想是当我们处理位置时$j$, 全部有效$i < j$已经被插入，所以查询直接计算以结尾的有效子数组$j$。 

### 为什么它有效

 每一步$j$，芬威克树恰好包含前缀和的多重集$p[0] \dots p[j-1]$。 任何以以下结尾的有效子数组$j$对应于选择较早的前缀和$p[i]$使得差异约束成立。 该转换确保每个有效子数组在其右端点精确计数一次，并且不包含无效子数组，因为查询范围与不等式条件完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, l, r = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0]
    cur = 0
    for x in a:
        cur += x
        pref.append(cur)

    vals = sorted(set(pref))
    def get_id(x):
        import bisect
        return bisect.bisect_left(vals, x) + 1

    bit = Fenwick(len(vals))

    ans = 0
    bit.add(get_id(0), 1)

    for j in range(1, n + 1):
        x = pref[j]
        left = x - r
        right = x - l

        import bisect
        L = bisect.bisect_left(vals, left) + 1
        R = bisect.bisect_right(vals, right)

        ans += bit.range_sum(L, R)
        bit.add(get_id(x), 1)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案围绕芬威克树构建，该树维护迄今为止看到的前缀和的计数。 坐标压缩步骤确保任意整数前缀和可以映射到紧凑的索引空间中。 二分运算将值约束转换为索引约束，Fenwick 查询计算有多少有效前缀和落入所需范围。 每个前缀仅在用于计数后才插入，确保以每个位置结束的子数组的正确性。

 ## 边缘情况

 一种关键的边缘情况是所有前缀和都相同。 例如，当所有数组元素均为零时，每个子数组的总和为零。 前缀数组变成重复值的序列，并且 Fenwick 树必须正确计算组合而不是唯一值。 该算法可以处理此问题，因为每个相同的前缀都是单独插入的，因此频率计数会自然累积。 

另一种情况是当$l$和$r$包括零，但数组包含较大的正向和负向振荡。 例如，交替$1, -1$产生许多重复的前缀值。 范围查询仍然正确匹配所有相等的前缀对。 

最后一个微妙的情况是$l$和$r$是大的负界和正界，有效地计算所有子数组。 在这种情况下，每个查询间隔始终覆盖完整的前缀范围，并且算法简化为对所有对进行计数$i < j$，这变成$n(n+1)/2$，仍然通过累积的 Fenwick 更新正确处理。
