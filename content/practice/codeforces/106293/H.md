 ## 解决方案
 ## 问题理解

 我们得到一个宽度非常大、最多 200k 行的网格。 在每一行中，只有一个连续的单元格片段属于一个城市，并且这些片段保证在连续行之间重叠，以便整个形状形成一个连接的正交区域，而不会出现将其分割的间隙。 

在该区域内，仅允许在侧相邻单元格之间移动，并且禁止跨出允许的段。 对于每个查询，我们都会得到一个起始单元格和一个目标单元格，它们都保证位于城市内，并且我们需要在它们之间移动所需的最小单位移动数。 

这些约束立即排除了任何显式探索网格的方法。 宽度最大可达 1e9，因此即使将一行存储为数组也是不可能的。 行数和查询数均高达 200k，因此解决方案必须在行数和查询时间恒定或对数的情况下大致线性或接近线性。 

每个查询的朴素最短路径搜索会将网格视为图形并运行 BFS 或 Dijkstra。 但这种方法失败了，因为网格尺寸巨大，并且每个 BFS 都需要在隐式间隔上进行推理，导致速度太慢。 

第二个天真的想法是注意到曼哈顿距离是空网格中的答案。 然而，走廊的限制可能会迫使人们绕道而行。 当一行缩小走廊时，就会出现一个简单的反例：

 输入：

 3 10

 1 10

 4 7

 1 10

 从 (1,2) 到 (3,9) 的查询

 中间行只允许第 4 至 7 列，因此任何路径都必须水平绕道才能进入该间隔，从而增加了超出曼哈顿距离的距离。 

主要困难在于，路径有时被迫通过由两点之间的所有行确定的“瓶颈间隔”。 

## 方法

 强力视角是将每个行间隔建模为一组单元格，并针对每个查询运行最短路径搜索。 即使我们压缩列，每一行仍然可能连接到 O(m) 个位置，因此 BFS 在 2e5 次查询中仍然太慢。 

关键的结构观察是，两点之间的任何有效路径必须在行中单调移动，因为上下移动会产生循环，而在具有单位权重的网格中没有任何好处。 因此，任何最短路径都可以被视为在两行之间垂直移动，同时选择一个保持在沿途遇到的所有行间隔内的 x 坐标，或者在不可能时绕行。 

这将问题简化为理解当我们遍历行时可行的 x 范围如何演变。 对于行 a 和 c 之间的固定垂直段，每行 i 贡献一个允许的间隔 [li, ri]。 所有这些间隔的交集控制着我们是否可以在垂直移动时保持恒定的列。 如果交集非空，我们可以在这些行之间移动时完全避免水平绕道。 如果它是空的，最好的策略是尽可能靠近交点，并支付额外的水平成本，该成本取决于端点距可行区域的距离。 

这将每个查询减少为间隔内的范围查询：我们需要一段行的最大左边界和最小右边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 网格上的 BFS | 每个查询 O(nm) | O(纳米) | 太慢了|
 | 每个查询的强力区间模拟 | 每个查询 O(n) | O(1) | O(1) | 太慢了|
 | 行间隔稀疏表 | 每个查询 O(1) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 ### 1. 预处理行上的间隔约束

我们在行间隔上构建两个结构。 一个存储左端点的前缀或范围最大值，另一个存储右端点的范围最小值。 这使我们能够针对任何行段快速计算该段中所有行施加的最严格的水平限制。 

这样做的原因是停留在单个列中的可行性仅取决于所有间隔是否重叠。 

### 2.构建范围查询结构

 我们为 li 的范围最大值和 ri 的范围最小值构建稀疏表。 这使我们能够在恒定时间内回答任何段查询。 

### 3.独立处理每个查询

 对于行 a 和 c 之间的查询，我们不失一般性地假设 a 高于 c。 我们取它们之间的行间隔段并计算：

 段中所有行的最大左边界 L

 段中所有行的最小右边界 R

 这给出了两点之间垂直走廊的全局相交约束。 

### 4. 计算垂直移动成本

 垂直距离恰好贡献 |a - c| 因为我们一次移动一行。 

### 5.计算水平调整成本

 我们现在决定如何处理 b 列和 d 列。 

如果区间 [L, R] 与 [min(b, d), max(b, d)] 相交，则存在一列位于可行走廊内部和端点之间。 在这种情况下，我们可以将两个点对齐到交点内的同一列，水平成本就是 |b - d|。 

否则，交点完全位于端点的一侧，我们必须移动到 [L, R] 最近的边界。 如果 R 位于两个端点的左侧，则最佳列为 R，如果 L 位于两个端点的右侧，则最佳列为 L。成本变为从两个端点到所选边界的距离之和。 

### 6. 合并贡献

 最终的答案是垂直距离加上最优水平绕行成本。 

### 为什么它有效

 任何路径都可以转换为在行索引中单调移动而不增加长度的路径，因为重新访问行只会增加循环。 沿着这种单调的垂直遍历，唯一的自由是选择列。 该列必须位于访问的每个行间隔内，因此它必须位于所有这些间隔的交集内。 如果交集非空，则常列路径是可行的。 如果不是，则最佳策略是尽可能靠近交点，并且最好的选择精确地简化为最小化区间内的凸绝对值表达式，这是通过将端点投影到可行范围上来实现的。 这确保计算的成本与约束网格图中的真实最短路径匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_sparse_max(arr):
    n = len(arr)
    LOG = (n).bit_length()
    st = [arr[:]]
    j = 1
    while (1 << j) <= n:
        prev = st[-1]
        curr = [0] * (n - (1 << j) + 1)
        half = 1 << (j - 1)
        for i in range(len(curr)):
            curr[i] = max(prev[i], prev[i + half])
        st.append(curr)
        j += 1
    return st

def build_sparse_min(arr):
    n = len(arr)
    LOG = (n).bit_length()
    st = [arr[:]]
    j = 1
    while (1 << j) <= n:
        prev = st[-1]
        curr = [0] * (n - (1 << j) + 1)
        half = 1 << (j - 1)
        for i in range(len(curr)):
            curr[i] = min(prev[i], prev[i + half])
        st.append(curr)
        j += 1
    return st

def query_max(st, l, r):
    length = r - l + 1
    j = length.bit_length() - 1
    return max(st[j][l], st[j][r - (1 << j) + 1])

def query_min(st, l, r):
    length = r - l + 1
    j = length.bit_length() - 1
    return min(st[j][l], st[j][r - (1 << j) + 1])

def solve():
    n, m = map(int, input().split())
    L = [0] * n
    R = [0] * n

    for i in range(n):
        l, r = map(int, input().split())
        L[i] = l
        R[i] = r

    stL = build_sparse_max(L)
    stR = build_sparse_min(R)

    q = int(input())
    out = []

    for _ in range(q):
        a, b, c, d = map(int, input().split())
        a -= 1
        c -= 1

        if a > c:
            a, c = c, a
            b, d = d, b

        Lseg = query_max(stL, a, c)
        Rseg = query_min(stR, a, c)

        if b > d:
            b, d = d, b

        vertical = c - a
        horiz = abs(b - d)

        lo, hi = b, d

        if Rseg < lo:
            horiz = (lo - Rseg) + (hi - Rseg)
        elif Lseg > hi:
            horiz = (Lseg - lo) + (Lseg - hi)
        else:
            horiz = hi - lo

        out.append(str(vertical + horiz))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现首先为行间隔上的范围最大值和最小值构建稀疏表，这些表直接编码当我们垂直移动时走廊如何变窄。 

每个查询都会标准化行顺序，以便我们始终处理从上到下的段。 然后，我们计算该段上可能的最严格的水平约束。 

水平计算处理三种几何配置：与可行走廊完全重叠、走廊完全位于两个点的左侧或走廊完全位于两个点的右侧。 每种情况对应不同的最优投影策略。

 ### 跟踪示例 1

 行：

 (1,5), (2,6), (1,4)

 | 步骤| LSEG | 搜索结果 b、d | 区域类型| 横向成本|

 这里第 1 行到第 3 行的交集是 [2,4]，它与 [2,5] 相交，因此我们可以通过重叠进行路由，并且只在该可行窗口内支付端点间隔。 

这证实了当存在重叠时，路径的行为类似于仅进行端点调整的自由垂直走廊。

 在这里，走廊在远离两个端点的地方完全变窄，迫使绕道到最近的可行边界。 这说明了为什么答案取决于投影而不是简单的曼哈顿距离。

 ## 边缘情况

 当行段上的交集折叠为单个点或恰好在一个边界行处变空时，就会出现关键边缘情况。 在这种情况下，天真的曼哈顿假设失败了，因为它忽略了所有垂直运动都必须遵守中间缩小的情况。 该算法可以正确处理此问题，因为稀疏表捕获整个段上精确的最小和最大约束，因此即使单个限制行也会立即影响计算的交集并强制正确的绕行成本。
