 ## 解决方案
 ## 问题理解

 Vasya 从一些已解决的竞赛问题和包含固定数量任务的现有竞赛开始。 他的目标是让自己的成功率严格超过一半，也就是说，在他行动之后，解决的任务数量必须超过比赛任务总数的一半。 

他有两种方法可以提高他的进步。 第一个是解决竞赛中的现有任务，这只会增加他已解决的数量。 第二个在结构上更强大：他在竞赛中添加了一个新任务并立即解决它，这增加了解决的数量和任务总数。 

该过程从由两个数字描述的初始状态开始，即已解决的计数和竞赛大小。 每个操作都有时间成本，目标是达到解决的计数严格超过任务总数一半的状态，同时最小化所花费的总时间。 

初始值的约束高达十万，这立即表明任何尝试天真地模拟所有可能的操作序列的解决方案都将失败。 任何对两个操作的所有组合进行分支的方法都必须简化为对单个参数的线性或接近线性决策，否则可能会面临多达十万步的二次探索。 

目标条件本身出现了一个微妙的问题。 该条件取决于两个变量，即已解决的变量和总的变量，但两种操作都会增加已解决的值，而只有一个操作会增加总的值。 这就产生了一个移动目标，其中提高分子也可能增加分母。 天真的贪婪策略总是更喜欢每一步更便宜的操作，而不考虑分母如何演变，在需要添加任务来降低所需阈值增长模式的构造情况下，这种策略将会失败。 

## 方法

 一个蛮力的想法是模拟所有可能的操作序列，直到条件成立。 从当前已解决计数和总计数定义的状态中，我们可以递归地尝试这两个操作，或者通过状态上的 BFS 来尝试这两个操作。 这在逻辑上是有效的，因为每个操作都有固定的效果，而且我们总是可以在有限的步骤中达到目标，因为解决任务单调增加解决的计数。 

然而，可达状态的数量正在迅速增长。 如果我们允许最多 O(n) 操作，每个状态都会分支为两个选择，从而导致指数爆炸。 即使按成本修剪也是不够的，因为已解决和总计之间平衡略有不同的状态可能都是相关的，并且我们无法在不失去最优性的情况下安全地合并它们。 

关键的观察结果是问题的结构分解为单个不等式约束。 每个操作都会产生一个线性表达式，该表达式确定我们是否通过了阈值。 这个条件可以根据我们仍然需要获得多少“优势”来重写。 

让最终条件用代数方式重写。 经过 k 次 A 类型操作和 m 次 B 类型操作后，我们得到了一个新的已求解计数和一个新的总计数。 要求变成 k 和 m 的线性不等式，这意味着问题简化为选择每个操作要执行的数量，而不是按顺序执行。 

一旦我们解决了这个问题，问题就变成了单一线性约束下的成本最小化。 这种结构允许对操作之间的效率进行贪心比较或直接扫描一个变量，因为一旦 m 固定，就强制选择最佳 k。

一种直接且可靠的方法是迭代 B 类操作的数量并计算 A 类操作所需的最小数量。 这是可行的，因为对于 m 的每个选择，约束都变成 k 上的简单一维界限，并且最佳 k 始终是最小的可行整数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力搜索各州| 指数| 指数| 太慢了|
 | 修复 B 操作并贪婪地计算 A | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们首先将成功条件转换为仅取决于使用了多少操作的形式。 假设我们应用 A 操作 k 次，应用 B 操作 m 次。 已解决的计数增加 k + m，而任务总数增加 m。 “解决的结果超过总数的一半”的条件变成了涉及 k 和 m 的不等式。 

然后，我们分离出所有常数项，以了解我们距离最初满足条件还有多远。 这给出了仅取决于起始值的所需改进阈值。 

接下来，我们迭代 m 的所有可能值，因为 m 完全决定了阈值因分母增加而变化的程度。 对于每个固定的 m，我们计算满足不等式所需的最小 k。 由于每个 A 运算对分子的贡献更大，而不影响分母，因此最小 k 始终是满足剩余间隙的最小整数。 

对于每一对 (m, k)，我们将总成本计算为 m 乘以 b 加 k 乘以 a，并跟踪所有选择中的最小值。 

最后，我们返回最小的计算成本。 

### 为什么它有效

 核心不变量是，对于固定数量的“昂贵的结构操作”B，剩余的要求成为A中的线性单调条件。超出不等式边界的k的不同选择之间不存在相互作用，因此取最小可行k总是最优的。 由于所有有效解唯一对应于 m 的某个值及其导出的最优 k，因此枚举 m 覆盖整个解空间，不会遗漏或重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = int(input())
    p = int(input())
    a = int(input())
    b = int(input())

    # Need: (s + k + m) * 2 > (p + m)
    # => 2s + 2k + 2m > p + m
    # => 2k + m > p - 2s
    D = p - 2 * s

    # We need 2k + m >= D + 1
    need = D + 1

    INF = 10**30
    ans = INF

    # try all m
    for m in range(need + 1):
        rem = need - m
        if rem <= 0:
            k = 0
        else:
            k = (rem + 1) // 2

        cost = m * b + k * a
        ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先将获胜条件重写为赤字形式。 变量`D`衡量 Vasya 距满足一开始的不平等性有多远。 然后，我们将条件转换为对操作的线性组合的要求。 

循环结束`m`表示修复 Vasya 使用同时更改任务数量和已解决计数的操作的次数。 一旦解决了这个问题，剩下的要求就变成了一个简单的上限划分，决定了需要多少个纯求解操作。 表达式`(rem + 1) // 2`是满足的最小整数 k`2k >= rem`。 

成本直接累积并与全局最小值进行比较。 迭代范围是安全的，因为一旦m超过要求，k就变为零，额外的m只会增加成本。 

## 工作示例

 考虑一个小场景，其中 s = 1、p = 5、a = 2、b = 3。最初，Vasya 还远远没有解决一半以上的问题。 

我们计算 D = p - 2s = 5 - 2 = 3，因此需求变为 4。 

我们评估不同的 m 值。

这两条轨迹显示了操作之间的平衡如何根据相对成本改变最优策略。

 ## 边缘情况

 当初始状态已经接近阈值时，所需的值D变小，并且对m的循环可能立即发现需要零类型A的操作。 在这种情况下，算法仅正确选择结构操作（如果它们更便宜）。 

例如，当 s = 4 且 p = 7 时，我们已经有 4 > 3.5，因此不需要任何操作。 导出公式给出 D = -1，计算出的需求变为零或负数，导致循环正确返回零成本。 

当 a 与 b 相比极小时，算法自然会优先选择 k 次操作，因为每个 A 对不等式的贡献效率是其两倍。 枚举仍然可以捕获这一点，而不需要显式的贪婪推理。 

当b极小时，循环发现即使增加p，快速增加m也满足条件，并且在m大且k等于0时达到最优解。
