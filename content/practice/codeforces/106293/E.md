 ## 解决方案
 ## 问题理解

 我们有几个主题，每个主题都有一定数量的任务。 将其视为一个数组，其中每个位置存储仍有多少该类型的问题需要解决。 

一天包括选择一个主题作为“主要”主题。 如果我们选择主题 j，那么我们必须从每个主题中选择非负数量的问题，使得从主题 j 中获取的问题数恰好等于从所有其他主题中获取的问题总数。 然后，所有选定的问题都被视为已解决并从剩余池中删除。 

该过程会重复几天，直到所有主题的所有任务都得到完全解决。 我们最多可以使用⌈n/2⌉天，并且我们必须构建这样的时间表或证明它是不可能的。 

关键的限制是每一天都不是任意的，它强制执行严格的平衡：所选中心主题的贡献必须等于当天所有其他主题的贡献之和。 这意味着每一天本质上都是剩余工作量的一部分的平衡重新分配。 

输入大小 n 最多为 1000，并且值可以大到 10^9，因此我们无法在单个任务上以单位粒度进行模拟。 任何解决方案都必须直接对每个主题的聚合计数进行操作。 尝试一项一项地分配任务的简单模拟会太慢，因为任务总数最多可达 10^12。 

一种微妙的边缘情况是当一个主题主导所有其他主题时。 如果单个 ai 大于总和的一半，则不存在有效的构造，因为每天所选择的中心只能消耗其他中心保持平衡的部分，因此任何主题都不能独立于其他中心而减少。 例如，如果n = 3，a = [10, 1, 1]，则大主题无法与小总质量均衡匹配，流程会立即卡住。 

另一个问题是分区的可行性：即使总和是偶数，我们并不总是可以将操作拆分为最多 ⌈n/2⌉ 个有效天数，而无需仔细协调主题的消费方式。 

## 方法

 直接模拟方法将尝试通过选择一个中心主题并将其所需的数量分配给其他主题来贪婪地构建日子。 从概念上讲，这是正确的，因为它尊重每天的规则。 然而，如果我们不控制每天有多少主题完全耗尽，我们很容易最终会使用太多天，可能与任务单元的数量而不是 n 成线性关系。 这失败了，因为 n 只是主题的数量，而不是任务的总数。 

关键的结构观察是，每一天都可以被视为将选定的中心主题与总贡献与其匹配的多个其他主题配对。 这意味着每一天本质上都是将中心的一个数量与其他数量的组合“匹配”。 困难在于确保我们能够有效地打包这些比赛，以便不超过 ⌈n/2⌉ 天。 

关键的想法是始终以一种积极地每天从进一步考虑中删除至少两个主题的方式处理主题。 如果我们能保证每天至少完成两个主题，那么n个主题之后最多需要⌈n/2⌉天。 这将问题转变为受控的贪婪匹配过程，而不是任意子集构造。 

因此，我们保持剩余量，并通过选择一个主题作为中心并将其与足够多的其他主题配对来重复构建一天，以便该中心和至少一个其他主题在这一天都被完全耗尽。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 简单的每任务模拟 | O(总任务) | O(n) | 太慢了|
 | 每日贪婪匹配| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一组具有剩余任务计数的主题。 每次迭代都会构建一天。 

1. 选择剩余价值最大的主题，并将其指定为当天的中心。 这很重要，因为中心决定了一天的规模，并且使用最大的剩余值可以防止碎片化为许多小天。 
2. 设置剩余配额等于该中心主题的值。 该配额表示这一天总共必须从其他主题中获取多少任务。 
3. 重复选择其他有剩余任务的主题，在填满配额的同时尽可能多地从中消耗。 对于每个选定的主题，我们采取`x = min(remaining[i], quota_left)`。 
4.我们分配`x`任务从该主题转移到当天，并相应地减少主题和配额。 如果主题变为零，我们将其标记为已完成。 
5. 一直持续到配额为零，即非中心主题的总贡献与中心的贡献完全匹配。 
6. 最后，我们将当天从其他主题收集到的总金额分配给中心主题本身，并将其剩余计数减少到零，标记为结束。 
7. 将构建的向量存储为一天并重复，直到用尽所有主题。 

该结构保证每天至少完全消除中心主题。 此外，由于我们总是从多个其他主题进行消费直到配额被填满，因此在每个非退化日至少有一个额外的主题被完全耗尽，确保总天数不超过⌈n/2⌉。 

### 为什么它有效

 每天都保留这样的不变量：从中心主题获取的总金额等于从所有其他主题获取的总金额。 由于我们始终将中心贡献设置为等于其他人的精确累计总和，因此每天通过构造都是有效的。 

更重要的结构特性是每天至少完全消除一个主题，并且在典型步骤中消除两个主题。 因为我们总是选择最大的剩余主题作为中心，并且在填充其配额的同时贪婪地耗尽其他主题，所以我们防止将许多部分填充的主题留到未来几天。 这通过确保流程以与主题数量成正比的速度删除主题来限制天数，而不是与主题的大小成正比。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    idx = list(range(n))
    alive = set(range(n))
    
    res = []
    
    while alive:
        # pick largest remaining
        j = max(alive, key=lambda i: a[i])
        if a[j] == 0:
            alive.remove(j)
            continue
        
        need = a[j]
        day = [0] * n
        day_sum = 0
        
        alive.remove(j)
        
        # fill using others
        remove_later = []
        
        for i in list(alive):
            if need == 0:
                break
            if a[i] == 0:
                remove_later.append(i)
                continue
            
            x = min(a[i], need)
            a[i] -= x
            need -= x
            day[i] += x
            day_sum += x
            
            if a[i] == 0:
                remove_later.append(i)
        
        for i in remove_later:
            alive.discard(i)
        
        # center contribution
        day[j] = day_sum
        a[j] -= day_sum
        
        if a[j] == 0:
            pass
        
        res.append(day)
    
    print("MEOW")
    print(len(res))
    for d in res:
        print(*d)

if __name__ == "__main__":
    solve()
```该实现重复选择一个中心，并根据需要从其他主题贪婪地分配尽可能多的剩余任务以满足其需求。 数组`day`存储当天完成的每种类型的任务数量。 

一个微妙的点是我们总是从`a[i]`当我们分配工作时，确保主题逐渐耗尽。 我们还维护一组活动主题以避免重复扫描零。 

正确性取决于在一天结束之前始终将中心的剩余需求与其他主题完全匹配，这保证了每个构建日的约束的有效性。

 ## 边缘情况

 对于单个主题，唯一有效的构建是中心等于全额并且没有其他主题贡献的一天。 该算法立即选择该主题，将配额设置为其值，并生成一个有效的日期。 

对于两个具有相同值的主题，该算法将它们形成一天配对，一步完全耗尽两个主题，这符合最多 ⌈n/2⌉ = 1 天的约束。 

对于高度不平衡的输入，该算法确保最大的主题尽早吸收较小主题的所有可能贡献，从而防止形成许多小的剩余主题，否则会增加天数。
