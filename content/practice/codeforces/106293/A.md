 ## 解决方案
 ## 问题理解

 给定两个固定整数$a$和$b$，我们可以选择第三个整数$c$。 一次$c$被选中，我们组成一个三元组$(a, b, c)$。 目标是使$c$尽可能大，同时保持特定的不等式成立：三个数字的算术平均值不得超过其中位数。 

算术平均值很简单$(a+b+c)/3$。 中位数是将三个数按非递减顺序排序后位于中间的值。 所以对于任何选择$c$，三元组的排序改变了中位数，这使得条件分段并且依赖于如何$c$相比于$a$和$b$。 

关键的限制是$a$和$b$可以大到$10^{18}$，所以任何解决方案都必须避免暴力破解$c$。 尝试的值$c$线性或什至在整个范围内使用二分搜索都太慢，除非我们可以在恒定时间内评估条件。 

一个微妙的困难来自于中位数不固定这一事实。 例如，如果$a = 1$,$b = 10$， 和$c = 5$，那么中位数是$5$，但如果$c = 100$，中位数变为$10$。 条件根据三个可能位置中的哪一个改变结构$c$按排序顺序占据。 

当所有三个数字折叠成一个值或当$c$非常大，成为最大元素。 例如，如果$a = b = 3$，那么任何有效的解决方案都必须尊重对称性，正确的答案就变成$c = 3$，因为任何更大的$c$将以违反不平等的方式推高中位数。 

## 方法

 蛮力方法会尝试增加$c$，每次通过对三元组排序来计算中位数，并检查不等式是否成立。 每张支票都是$O(1)$， 但$c$范围可达$10^{18}$，因此即使迭代有意义的子集也是不可能的。 

关键的观察结果是，三个数字的中位数只有三种结构情况，具体取决于位置$c$相对于而言的谎言$a$和$b$。 一旦我们排序$a$和$b$，我们只需要考虑是否$c$是最小、中间或最大的元素。 在每种情况下，中位数都成为一个固定的表达式，将不等式转变为一个简单的线性约束$c$。 这将问题从搜索整数减少到评估少量代数条件并获取最大可行值。

 ## 算法演练

 我们首先确保两个固定值之间的顺序清晰。 

1. 对输入进行排序，以便$a \le b$。 这消除了对称性并确保以后所有关于相对位置的推理$c$是一致的。 
2. 考虑第一个结构情况，其中$c \le a \le b$。 在这种情况下，排序后的三元组是$(c, a, b)$，所以中位数是$a$。 不等式变为$(c + a + b)/3 \le a$，这简化为$c + b \le 2a$。 自从$b \ge a$，这立即限制了$c \le a$。 因此，该区域的最大可行值是$c = a$。 
3. 考虑第二种情况$a \le c \le b$。 现在排序后的三元组是$(a, c, b)$，所以中位数是$c$。 条件变为$a + b + c \le 3c$，这简化为$a + b \le 2c$， 或者$c \ge (a+b)/2$。 因为我们想要最大化$c$当停留在这个区间时，我们尝试$c = b$。 代入，我们得到$a + b \le 2b$，它总是成立，因为$b \ge a$。 所以该区域的最大可行值为$c = b$。 
4. 考虑第三种情况$a \le b \le c$。 现在排序后的三元组是$(a, b, c)$，所以中位数是$b$。 不等式变为$a + b + c \le 3b$，这简化为$a + c \le 2b$，给出一个上限$c \le 2b - a$。 由于我们在该地区$c \ge b$，最好的选择是$c = 2b - a$。 
5. 最后，比较所有案例中的候选人。 第一个案例中最好的是$a$，从第二个开始就是$b$，从第三个开始就是$2b-a$。 自从$b \ge a$，第一种情况永远不是最佳的。 还，$2b-a \ge b$，所以第三种情况优于第二种情况。 因此最终的答案是$c = 2b - a$。 
6. 如果原始订单有$a > b$，对称性给出$c = 2a - b$。 结合两个方向，答案是$2\max(a,b) - \min(a,b)$。 

### 为什么它有效

 中值约束仅取决于排序，并且对于三个元素，只有三种可能的顺序配置。 在每种配置中，不等式变为线性$c$，产生单个上限或下限。 最佳解决方案必须位于这些区域之一的边界处，并且比较这些边界会穷尽所有可能性，而不会丢失排序之间的转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())
    
    if a > b:
        a, b = b, a
    
    # optimal derived from case analysis
    print(2 * b - a)

if __name__ == "__main__":
    solve()
```该实现首先规范化排序，以便所有推理都假设$a \le b$。 这避免了重复的案例逻辑。 最终公式$2b-a$直接对应于该区域的最佳可实现值$c$成为最大元素，它支配所有其他配置。 

一个常见的错误是忘记最优解总是位于边界处，其中$c$要么与$a$,$b$，或导出的线性界限$2b-a$。 最终的归约将所有这些结构折叠成一个表达式。

 ## 边缘情况

 当$a = b$，算法立即简化为$c = a$。 在这种情况下，所有三个数字都是相同的，因此无论排序如何，均值和中位数始终一致，并且线性公式$2b-a$正确折叠到$a$。 

例如，当一个值与另一个值相比非常大时$a = 1$和$b = 10^{18}$，算法选择$c = 2b - a$。 这对应于放置$c$高于这两个数字，中位数稳定在$b$。 然后不等式在边界处变得紧密$a + c = 2b$，该公式完全满足。 

当交换输入时，标准化步骤可确保一致性。 例如，$a = 10, b = 1$在内部转换为$a = 1, b = 10$，因此同样的推理适用，无需按输入顺序进行分支。
