 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并要求提取尽可能多的不相交的连续段，使得每个选定的段的 XOR 等于 0。 数组的每个元素最多只能属于一个选定的段，因此一旦我们选择了一个段，我们就不能在任何其他段中重用它的索引。 

任务不是完全分区数组，而是选择最大数量的“好”段。 当段内所有元素的 XOR 恰好为零时，该段是好的。 

约束条件达到$2 \cdot 10^5$，这立即排除了子数组上的任何二次或更差的方法。 任何尝试所有段甚至重新计算多对端点 XOR 的解决方案都会超时。 我们需要一些更接近线性或近线性时间的东西，可能带有前缀结构和动态规划。 

一个关键的微妙之处是分段必须不重叠。 这意味着贪婪地选择任何零异或子数组显然并不安全，因为一个短的早期段可能会阻塞两个后面的段。 

一些边缘情况说明了结构：

 如果数组是`[1, 1, 1, 1]`，有效的零异或段包括`[1,1]`在位置 (1-2) 和 (3-4) 处，给出答案 2。选择从索引 1 开始的最长段的天真的贪婪算法可能会采用 XOR 0 的 (1-4)，但结果会变成 1，这会更糟。 

如果数组是`[1, 2, 3]`，整个数组 XOR 为零，因此我们可以取一个段，但没有更小的段给出超过 1 个段。 

如果所有元素都为零，则每个元素都是有效段，所以答案是$n$，任何正确的解决方案都必须干净地处理这个问题。 

这些例子已经暗示问题是以最佳的非重叠方式找到许多零异或子数组，这表明前缀异或结构与位置动态规划相结合。 

## 方法

 强力方法将尝试所有子数组，为每个子数组计算异或，然后选择一组最大的不重叠的有效间隔。 即使我们使用前缀 XOR 预先计算 XOR，因此每个子数组检查的时间复杂度为 O(1)，我们仍然面临$O(n^2)$候选区间。 在所有有效间隔中选择最大的非重叠间隔集成为一个加权间隔调度问题，具有潜在的可能性$O(n^2)$边缘，太大。 

关键的观察是我们实际上并不明确需要所有有效的子数组。 我们只关心每个位置的最佳答案。 这建议从左到右扫描并维护有关前缀 XOR 状态的信息。 

让`pref[i]`与第一个进行异或`i`元素。 一个子数组`(l+1 … r)`恰好当时 XOR 为零`pref[l] == pref[r]`。 因此，对于每个前缀值，如果我们知道它出现的最后位置，我们可以检测到可能的零异或段结束于`r`。 

我们可以进行动态编程，而不是独立跟踪所有先前发生的事件：`dp[i]`是我们可以使用前缀形成的最大有效段数`1…i`。 在位置`i`，我们要么什么也不做，或者我们结束一个段`i`。 如果我们结束一个片段`(j+1 … i)`异或零，然后`dp[i] = dp[j] + 1`。 我们需要这样最好的`j`。 

为了提高效率，我们维护一个字典，将每个前缀 XOR 值映射到最佳值`dp`在出现此前缀的索引处看到的值。 这会将所有有效的先前端点压缩为每个索引的 O(1) 查找。 

暴力枚举所有对`(j, i)`，而前缀 XOR + DP 技巧会压缩所有有效的`j`每个 XOR 值将候选者分为一个最佳代表。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 前缀XOR+DP映射| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护前缀异或值和动态编程表。 

1. 初始化`dp[0] = 0`和前缀异或`px = 0`。 我们还存储了地图`best`在哪里`best[x]`表示具有前缀XOR的所有位置中的最大dp值`x`。 最初，`best[0] = 0`。 这反映出在开始之前，空前缀具有异或零和零段。 
2. 对于每个位置`i`从 1 到`n`， 更新`px = px XOR a[i]`。 这给出了结尾为的前缀的异或`i`。 
3. 初始设定`dp[i] = dp[i-1]`。 这对应于在位置处不结束任何段`i`，有效地离开`i`在段中未使用。 
4. 现在考虑在以下位置结束零异或段`i`。 如果某个较早的位置`j`具有相同的前缀 XOR`px`，那么子数组`(j+1 … i)`异或为零。 所有此类中的最佳选择`j`是最大化的那个`dp[j]`，这正是`best[px]`。 因此我们可以更新`dp[i] = max(dp[i], best[px] + 1)`。 
5. 计算后`dp[i]`，我们更新`best[px] = max(best[px], dp[i])`。 这确保了未来的位置可以重用以前缀 XOR 状态结束的最佳配置。 
6.最终答案是`dp[n]`。 

### 为什么它有效

 该算法依赖于将所有有效段结尾压缩为前缀 XOR 状态。 每个有效段`(j+1 … i)`唯一对应于一对相等的前缀异或值。 DP 值在`j`捕获到该点的最佳分割，并仅存储最大值`dp[j]`每个前缀 XOR 确保我们永远不会丢失更好的转换。 由于转换仅依赖于前缀 XOR 相等性，因此不需要额外的历史结构，并且每个可能的分段都可以通过这些状态来表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dp_prev = 0
    px = 0

    best = {0: 0}

    for i in range(n):
        px ^= a[i]

        dp_i = dp_prev

        if px in best:
            dp_i = max(dp_i, best[px] + 1)

        if px in best:
            best[px] = max(best[px], dp_i)
        else:
            best[px] = dp_i

        dp_prev = dp_i

    print(dp_prev)

if __name__ == "__main__":
    solve()
```该解决方案仅维护先前的 DP 值和前缀 XOR 状态的字典。 微妙的一点是我们更新了`best[px]`计算后`dp_i`，确保我们正确地允许未来的段建立在以该前缀 XOR 结尾的最著名的结构上。 

一个常见的陷阱是更新`best`太早了，这会错误地允许片段在同一位置开始和结束，从而人为地夸大答案。

 ## 边缘情况

 一个关键的边缘情况是许多前缀在早期共享相同的 XOR。 在这种情况下，未能存储每个前缀 XOR 的最佳 DP 将导致计数不足。 例如，在`[0, 0, 0]`，每个前缀异或为零，每个位置都可以扩展之前的最优分割。 正确的行为是不断进步`best[0]`随着 DP 的增加； 否则算法将冻结在 1。 

另一个微妙的情况是，最佳分段需要跳过立即有效的分段，以支持启用两个后面的分段。 DP 公式已经处理了这个问题，因为`dp[i]`总是考虑扩展和不扩展，但前提是我们正确地延迟更新`best`直到计算完成后`dp[i]`。
