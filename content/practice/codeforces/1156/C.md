 ## 解决方案
 ## 问题理解

 我们得到了放置在数轴上的点的集合，目标是形成尽可能多的不相交对。 仅当两个选定点相距足够远时，一对才有效，这意味着它们的坐标之间的绝对差至少是一个固定阈值$z$。 每个点最多属于一对，因此一旦使用点，就不能再次参与。 

任务是选择配对以最大化其数量，而不是总距离或任何加权分数。 这立即表明我们正在处理排序结构上的匹配问题，其中只有相对位置很重要。 

输入大小达到$2 \cdot 10^5$，这排除了任何二次方法。 任何尝试所有配对组合或重复扫描合作伙伴的操作都会出现$10^{10}$在最坏的情况下操作并在时限内失败。 这促使我们将排序与线性或对数配对策略相结合。 

当在没有排序的情况下完成贪婪配对时，会出现微妙的失败情况。 考虑如下输入：```
n = 4, z = 3
points = [1, 10, 2, 11]
```最佳答案是 2，将 (1,10) 和 (2,11) 配对。 如果不进行排序的简单扫描检查相邻的输入顺序（这是无效的，因为它们的距离仅为 1），则可能会首先对 (1,2) 进行配对，然后完全错过最佳结构。 如果一个人贪婪地将每个点与最接近的有效伙伴配对而不考虑全局排序，则会出现另一种失败模式； 这可能会浪费大量的分数，而这些分数应该为以后的比赛保留。 

核心问题是本地配对决策必须尊重沿线的全局顺序。 

## 方法

 蛮力策略会尝试所有可能的配对。 人们可以想象标记点并递归地选择任意两个未使用的索引，其距离至少为$z$，然后探索所有可能性。 虽然原则上是正确的，但分支因素是巨大的。 在最坏的情况下，当有许多有效对时，匹配的数量会组合增长，从而导致指数复杂性。 

即使是一个更简单的蛮力改进，对于每个点，我们向前扫描以找到有效的合作伙伴，也会导致$O(n^2)$行为。 和$n = 2 \cdot 10^5$，这远远超出了可行的限度。 

关键的观察来自对点的排序。 一旦排序，问题就变成了将小元素与大元素配对，同时尊重最小间隙的问题。 如果我们固定一个排序，那么从左到右贪婪地配对就变得有意义：最小的未使用点应该与满足约束的最早可能的点匹配。 如果我们尝试将其与稍后的、不必要的大候选者进行匹配，我们可能会浪费这个更大的值并减少未来的配对机会。 

这建议采用两指针策略：维护左侧的指针（最小的未使用点）和搜索有效伙伴的另一个指针。 

排序后，我们可以以受控方式贪婪地推进两个指针，以便每次成功的配对消耗两个点，而每次失败的尝试仅移动正确的指针。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$或者更糟|$O(n)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将所有点按非降序排序。 这确保了当我们考虑配对时，右侧的所有候选者都大于或等于，因此距离比较变得单调。 
2. 初始化两个指针：一个位于数组的开头（称之为$i$），另一个位于中间位置或从相同位置开始，具体取决于实施策略。 清洁配方是为了治疗$i$作为第一个不匹配的元素并且$j$作为候选伙伴向前扫描。 
3. 移动$j$向前直到我们找到一个点使得$x[j] - x[i] \ge z$。 每一步的移动$j$是合理的，因为任何较小的候选人已经不符合条件，并且以后将永远不会有效。 
4. 如果有这样一个$j$找到，记录一对，并推进两者$i$和$j$。 这反映了消耗两点。 
5. 如果$j$到达终点却没有找到有效的合作伙伴$i$，那么没有点可以配对$i$，因为所有剩余的点都更右，但我们已经以贪婪顺序穷尽了该配置的可行匹配结构。 所以我们搬家$i$前进并继续寻找下一个潜在基点。 
6. 继续，直到任一指针到达数组末尾。 

微妙之处在于我们从不走回头路。 每个指针只向前移动，保证排序后的线性复杂度。 

### 为什么它有效

 排序顺序强制任何涉及点的有效配对$i$必须使用其权利的合作伙伴。 如果$i$匹配时，将其与尽可能小的有效伙伴配对总是安全的：使用较大的伙伴只会降低未来的灵活性，而不会增加配对的数量。 如果$i$不能与当前最小的可行候选匹配，那么它就不能与任何早期的候选匹配（因为没有），并且只保留更大的候选，这相对于早期的选择来说更难满足距离约束。 贪心选择保留了一个不变量，即所有先前的决策都最大化了数组后缀的剩余灵活性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, z = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    i = 0
    j = n // 2
    ans = 0

    while i < n // 2 and j < n:
        if a[j] - a[i] >= z:
            ans += 1
            i += 1
            j += 1
        else:
            j += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先对数组进行排序，然后使用两指针策略，其中`i`跟踪潜在对的较小一侧并`j`寻找有效的合作伙伴。 初始化的选择`j`在`n // 2`反映了一种常见的贪婪优化：我们尝试将下半部分元素与上半部分候选元素配对，减少不必要的比较。 即使这样，逻辑仍然有效`j`从 0 开始，但从中点开始可以减少实践中的扫描开销。 

关键的实现细节是两个指针都只向前移动。 这保证了排序后的线性扫描，并避免重新访问任何元素。

 ## 边缘情况

 一个关键的边缘情况是许多点相同或紧密聚集而没有有效的伙伴。 在这种情况下，算法会不断前进右指针直到耗尽，确保不会发生错误配对。 例如：```
[5, 5, 5, 5], z = 1
```排序后的数组保持不变。 指针`i`0 时将扫描`j`跨越所有元素，从未找到有效的差异，最终`i`增量。 如此重复，直到所有元素都用完，产生 0 对。 

另一种边缘情况是有效对仅存在于极端之间，例如：```
[1, 2, 3, 100], z = 50
```这里只有 (1,100) 有效。 该算法会跳过 2 和 3 作为 1 的伙伴，因为它们未达到阈值，最终达到 100 并恰好形成一对。
