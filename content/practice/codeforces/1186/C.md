 ## 解决方案
 ## 问题理解

 我们得到一个长的二进制字符串`a`和一个更短或等长的二进制字符串`b`。 我们滑行`b`跨越每一个可能的窗口`a`长度相同，对于每个位置，我们逐个字符地比较两个字符串。 

对于每个对齐，我们计算窗口之间有多少个位置不同`a`和`b`。 任务是计算有多少比对产生偶数个不匹配。 

思考这个问题的一个直接方法是我们测量之间的汉明距离`b`和每个子串`a`，我们想要计算其中有多少距离是偶数。 

长度为`a`最大可达 1e6，因此不可能进行二次比较。 任何简单地比较每个窗口的解决方案在最坏的情况下都会执行大约 1e6 × 1e6 的操作，这远远超出了 1 秒所允许的范围。 

关键边缘情况出现时`b`长度为 1 或者当两个字符串都很大并且高度重复时。 在这些情况下，天真的滑动窗口比较看起来仍然很简单，但悄悄地超出了限制。 

## 方法

 暴力方法检查每个子串`a`长度`|b|`，并且对于每一个都计算不匹配`b`。 这是正确的，因为它直接实现了问题的定义。 然而，对于每个大约`n`位置，它执行`m`进行比较，总共得到`O(nm)`运营。 两者都有`n`和`m`接近10^6，这是不可行的。 

为了改善这一点，我们关注真正重要的事情：不匹配数量的奇偶性，而不是确切的计数。 这表明采用模 2 并尝试以更简单的形式表达不匹配奇偶校验。 

让我们将字符编码为位。 位置不匹配`i`发生在`a[i] != b[j]`。 在二进制算术中，不等式对应于 XOR 为 1。因此，从`i`变成总和`j`的：`a[i+j] XOR b[j]`我们只关心这个模 2 的和。在 GF(2) 上，XOR 表现出线性：

 sum (a XOR b) mod 2 等于 sum(a) XOR sum(b)

 这是关键的简化。 不匹配的奇偶校验为：

 (a 中窗口的总和) XOR (b 中的总和)

 所以对于每个窗口，我们只需要窗口中的个数的奇偶校验`a`，我们将其与中的奇偶性进行比较`b`。 

因此，问题归结为滑动窗口奇偶校验计数。 

我们计算前缀和`a`获取任意窗口中 1 的数量，时间复杂度为 O(1)，跟踪奇偶校验，计算奇偶校验`b`一次，然后比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 前缀奇偶校验+滑动窗口| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算 1 的个数`b`并以 2 为模进行减少。该值表示是否`b`有偶数或奇数奇偶校验。 这很重要，因为简化后只有奇偶校验会影响不匹配奇偶校验。 
2. 构建前缀和数组`a`，其中每个条目存储直到该索引的个数。 这允许对任何子字符串进行恒定时间查询。 
3. 迭代每个子串`a`与长度`|b|`。 对于每个起始索引`i`，计算其中的个数`a[i : i+|b|]`使用前缀数组。 
4. 将此窗口和模 2 减少，获得当前子串中 1 的奇偶校验。 
5. 将该奇偶性与以下奇偶性进行比较`b`。 如果它们相等，则该窗口的不匹配计数是偶数，因此增加答案。 

### 为什么它有效

 对于二进制值，某个位置的不匹配相当于 XOR。 总不匹配计数是 XOR 值的总和。 当模 2 约简时，XOR 和分布在加法上，从而允许表达式折叠为 1 总数的 XOR。 这就产生了一个不变量：在每个窗口，不匹配的奇偶校验仅取决于窗口中的奇偶校验。`a`并在`b`，而不是它们的详细结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()

    n, m = len(a), len(b)

    pb = sum(1 for ch in b) % 2

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (a[i] == '1')

    ans = 0
    for i in range(n - m + 1):
        ones = pref[i + m] - pref[i]
        if ones % 2 == pb:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先计算 中的奇偶校验`b`。 这是唯一的财产`b`这会影响还原为奇偶校验后的最终答案。 

接下来，构建一个前缀和数组`a`，允许在恒定时间内计算每个子串和。 这避免了每个窗口的重新计算。 

最后，通过比较该窗口中的奇偶校验与奇偶校验来检查每个窗口`b`。 相等条件直接对应偶数失配计数。 

一个微妙的点是我们从不显式地计算不匹配。 整个转换取决于将不匹配奇偶校验表达式减少为计数的奇偶校验比较。

 ## 边缘情况

 当`b`长度为 1，每个窗口都是一个字符。 该算法简化为比较是否`a[i]`匹配奇偶校验`b`。 前缀和仍然可以正常工作，因为每个窗口和不是 0 就是 1，因此奇偶校验比较是准确的。 

什么时候`a`完全由零组成，每个窗口都有零个，因此所有窗口奇偶校验都为零。 如果`b`也有偶校验，每个窗口都匹配，答案就变成`|a| - |b| + 1`。 该算法直接通过前缀差异来计算。 

什么时候`a`和`b`是相同的重复模式，每个窗口具有相同的奇偶校验结构。 该算法不依赖于结构相似性，仅依赖于计数，因此无论重复如何，它都保持正确。
