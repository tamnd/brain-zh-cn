 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的固定数字排列。 另外，我们有一个较长的数组，其元素也位于 1 到 n 的范围内，但可能会重复。 任务是回答对该数组的子段的许多查询。 

对于每个查询段，我们必须决定是否可以选择该段的某些子序列，该子序列形成给定排列的循环移位。 换句话说，我们可以从段中删除元素，而无需重新排序剩余的元素，并且我们想知道剩余的元素是否可以匹配旋转后的排列。 

循环移位意味着我们采用排列并旋转它，因此每个有效的目标序列都具有与排列相同的元素，但从不同的位置开始。 

关键的结构约束是子序列不需要是连续的，因此我们不搜索子字符串匹配。 相反，我们正在检查该段是否按与某些旋转一致的顺序包含排列的所有元素。 

这些限制迫使我们采用离线或预处理方法。 当 n、m 和 q 达到 2·10^5 时，对段的每次查询贪婪或扫描方法在最坏的情况下将导致 O(mq)，这远远超出了可行的范围。 我们需要更接近 O((m + q) log m) 或 O(m log m) 的东西。 

一个微妙的点是，数组 a 中的重复值除了提供所需排列元素的出现之外没有任何帮助。 然而，顺序非常重要，因为后续约束迫使我们尊重立场。 

当一个段包含所有数字但由于交织而无法形成有效的循环顺序时，就会出现幼稚但重要的边缘故障。 例如，如果我们需要排列 1 2 3，并且段是 1 3 2 3 1，则所有元素都存在多次，但根据边界，某些段中不存在正确旋转顺序的子序列。 这表明我们不能将问题简化为频率检查。 

## 方法

 强力方法将独立处理每个查询。 对于给定的段，我们尝试从每个可能的旋转开始贪婪地匹配排列。 对于每次旋转，我们扫描该段并尝试将 n 个元素作为子序列进行匹配。 在最坏的情况下，每次尝试的时间复杂度为 O(m)，并且我们有 n 次旋转，因此单个查询变为 O(nm)。 超过 q 查询这是完全不可行的。 

关键的观察结果是，当通过下一次出现的结构观察时，排列的循环移位表现得非常严格。 如果我们在排列中固定起始值 x，则完全确定循环顺序：x、排列中的下一个，依此类推。 

我们不考虑子序列，而是重新解释条件：我们希望在段中找到可以按循环顺序遍历排列的位置序列。 这变成了一个“我们可以从某个地方开始并使用下一个事件来跟踪向前转换”的问题。 

我们对排列进行预处理，以了解每个值的循环顺序下一个值是什么。 然后在数组 a 中，对于每个位置，如果我们尝试匹配从该位置开始的排列，我们可以预先计算我们着陆的位置。 这是使用二进制提升风格 DP 完成的：从位置 i 和状态 k 意味着“我们已经按循环顺序匹配了 k 个步骤”，我们跳转到下一个出现的所需值。 

关键的减少是，对于每个起始位置 i，我们计算可以将有效循环子序列贪婪地向前延伸多远。 如果该范围至少为 n 个元素，则 i 是完整循环移位子序列的有效起始锚点。 这减少了标记有效起点的问题。

然后每个查询变成：该段是否包含任何有效的起始位置 i 以使完整匹配完全适合该段？ 这可以通过线段树或下一个有效位置查询来回答。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(q·n·m) | O(1) | O(1) | 太慢了 |
 | 最佳 | O((n + m) log n + q log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建排列的位置图，以便我们知道排列中每个值的索引。 这让我们可以将 a 中的任何值解释为循环顺序中的位置。 
2. 构建“下一个值”关系：对于每个值 x，其循环顺序的后继者是排列中的下一个元素，在末尾环绕。 这将排列变成有向循环。 
3. 使用位置图将数组 a 转换为排列索引数组。 现在 a 的每个元素都表示为循环上的一个节点。 
4. 对于 a 中的每个位置 i，使用下一个出现表计算循环顺序中每个值的下一个出现。 这使我们能够使用 a 中的跳转来模拟循环排列中的前进。 
5. 使用这些转换，计算每个 i 的最远位置 r[i]，以便从 i 开始，我们可以在 a[i..r[i]] 内贪婪地构建一个完整的长度为 n 的循环子序列。 计算是通过按顺序重复跳转到下一个所需值来完成的。 
6. 现在每个 i 代表一个区间 [i, r[i]]，其中 i 是完整循环置换子序列的有效起点。 
7. 对于每个查询 [l, r]，我们只需要检查 [l, r] 中是否存在某个 i 使得 r[i] ≤ r。 这成为一个范围查询问题，可以使用存储范围中最小 r[i] 的线段树来解决。 
8. 通过检查 [l, r] 中的最小值 r[i] 是否 ≤ r 来回答每个查询。 

它之所以有效，是因为每个有效的循环子序列都必须对应于 a 中的某个起始位置，并且从该位置开始的贪婪构造总是会产生最早可能的完成。 如果即使最早的完成结束在查询范围之外，则从该位置开始的任何其他子序列选择都不能容纳在查询范围内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    p = list(map(int, input().split()))
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i

    nxt = [0] * n
    for i in range(n):
        nxt[i] = (i + 1) % n

    # map array values to permutation positions
    b = [pos[v] for v in a]

    # next occurrence of each value position in cycle
    next_pos = [[m] * n for _ in range(m + 1)]
    for j in range(n):
        next_pos[m][j] = m

    for i in range(m - 1, -1, -1):
        for j in range(n):
            next_pos[i][j] = next_pos[i + 1][j]
        next_pos[i][b[i]] = i

    r = [0] * m

    for i in range(m):
        cur = i
        ok = True
        for step in range(n):
            v = (pos[p[0]] + step) % n
            # value position in cycle
            need = v
            cur = next_pos[cur][need]
            if cur == m:
                ok = False
                break
        if ok:
            r[i] = cur
        else:
            r[i] = m

    size = 1
    while size < m:
        size *= 2
    seg = [m] * (2 * size)

    for i in range(m):
        seg[size + i] = r[i]
    for i in range(size - 1, 0, -1):
        seg[i] = min(seg[2 * i], seg[2 * i + 1])

    def query(l, rr):
        l += size
        rr += size
        res = m
        while l <= rr:
            if l % 2 == 1:
                res = min(res, seg[l])
                l += 1
            if rr % 2 == 0:
                res = min(res, seg[rr])
                rr -= 1
            l //= 2
            rr //= 2
        return res

    out = []
    for _ in range(q):
        l, rr = map(int, input().split())
        l -= 1
        rr -= 1
        best = query(l, rr)
        out.append('1' if best <= rr else '0')

    print(''.join(out))

if __name__ == "__main__":
    solve()
```该实现首先将排列值映射到循环顺序上的索引中。 这是至关重要的，因为循环移位变成了索引上的简单模算术，而不是值比较。 

下一个出现表是向后构建的，以便对于每个位置和每个循环状态，我们知道该状态出现的下一个索引。 这是实现快速跳跃的核心结构。 

对于每个起始索引，数组 r 存储可以完成完整循环子序列的最早位置。 如果无法完成，则标记为m。 

r 上的线段树支持范围内的最小查询，它直接回答查询段中是否存在完全包含的任何有效起点。 

一个常见的陷阱是误解我们没有检查连续的排列值块。 子序列性质完全由下一次出现的跳转处理，而不是由数组中的邻接处理。 

## 工作示例

 ### 示例 1

 输入：```
3 6 3
2 1 3
1 2 3 1 2 3
1 5
2 6
3 5
```我们首先映射排列位置：2→0、1→1、3→2。 循环顺序为2、1、3。 

数组变为：[1,0,2,1,0,2]。 

我们尝试从每一个位置入手。 从索引 0 开始，我们可以使用位置 0,1,2 构建完整的循环 2,1,3，因此 r[0]=2。 从索引 1 开始，我们得到一个从 1,1,3 开始的完整循环，因此 r[1]=3。 对于其他启动也存在类似的有效计算。 

对于查询 [1,5]，存在一个起始位置，其 r[i] ≤ 4，因此答案为 1。 

对于 [2,6]，有效的开始存在于范围内且在范围内完成，因此答案为 1。 

对于 [3,5]，没有有效的完整循环完全适合内部，因此答案为 0。 

### 示例 2

 输入：```
2 4 2
1 2
1 1 2 2
1 2
3 4
```排列已经是1→2。 

从索引 0 中，我们可以选取子序列 1,2，因此 r[0]=2。 从索引1开始，我们无法完成一个完整的循环，因此r[1]=4。 

查询 [1,2] 从 0 开始有效，因此答案为 1。 

查询 [3,4] 内部没有有效的开始完成，因此答案为 0。 

这些痕迹显示了有效性如何与从某个索引而不是局部结构开始的完整循环遍历的存在相关联。

 ## 边缘情况

 关键的边缘情况是当段包含所有必需的值但分散的方式阻止完成从段内开始的完整循环遍历时。 在这种情况下，算法会正确拒绝，因为 r[i] 超出了段边界，即使频率方面一切看起来都足够了。 

当 a 中多次出现相同的值时，就会出现另一种边缘情况。 下一个出现表确保我们始终选择最早的有效延续，防止在没有预处理的贪婪扫描中出现人为的可行性膨胀。 

最后的边缘情况是非常短的段，其中 r[i] 有效，但段结束得太早。 线段树最小检查强制完整完成符合查询范围，而不仅仅是它存在于数组中的某个位置。
