 ## 解决方案
 ## 问题理解

 我们得到一个很长的数字字符串，它是通过连续写入几个没有分隔符的整数而形成的。 该字符串的每个连续子字符串都可以解释为一个整数（没有前导零，除非子字符串恰好是“0”，尽管这里的输入保证整个字符串不以零开头）。 

在所有正整数中，根据基于数字的递归规则，有些被标记为“不足”。 从 1 到 9 的个位数总是不够的。 对于较大的数字，充分性取决于没有最后一位数字的数字的充分性，并且还取决于涉及先前构造的不充分数字的顺序及其模 11 的位置的约束，这决定了在附加数字时一个数字可以有多少个子代。 

任务是计算给定字符串中有多少子字符串的计算结果不足，即使数值在不同位置重复，也要单独计算每个出现的次数。 

字符串长度最多为 100,000，因此任何尝试将每个子字符串解析为整数并独立检查条件的解决方案都是不可能的。 天真的$O(n^2)$子字符串的枚举已经是边界，即使子字符串解析是$O(1)$，我们仍然需要一种有效的方法来测试“不充分”的成员资格。 

一个更微妙的限制是“不足的数字”不是由简单的数字属性（如整除性或模式匹配）定义的； 它们是由结构化组合增长规则定义的。 这强烈表明我们正在处理数字上的前缀树，其中每个节点具有有限数量的子节点，具体取决于其在全局枚举中的位置。 

一个关键的边缘情况是子字符串中的前导零。 例如，像“01”或“001”这样的子字符串不是预期意义上的正整数的有效表示，并且不能被视为有效的不足数字。 另一个微妙的问题是表示相同数字的重叠子字符串：它们必须单独计数，因此我们无法按值进行重复数据删除。 

## 方法

 暴力方法很简单：迭代所有子字符串，将每个子字符串转换为整数，然后使用递归定义检查它是否不足。 子串的个数为$O(n^2)$，即使每次检查都是恒定时间，这也已经是大约$5 \cdot 10^9$最坏情况下的操作$n = 10^5$。 将子字符串转换为整数也会增加开销，因此这种方法是完全不可行的。 

该定义的结构表明了一些更强大的东西：不足是通过逐位重复扩展数字来定义的，其中每个前缀“知道”它可以有多少个有效的子代。 这正是 trie 的结构，其中每个节点对应一个前缀数字，并且每个节点都有一个允许的下一个数字范围。 

我们不是枚举子字符串，而是颠倒视角。 我们扫描字符串，并从每个起始位置尝试贪婪地扩展一个数字，同时跟踪当前前缀是否仍然不足。 在每一步中，我们都会在不足的数字的全局排序中维护当前前缀的索引，因为该索引决定了接下来允许的数字数量。 约束“最后一位 < k mod 11”有效地限制了分支，这意味着大多数路径很快就会消失。 

关键的观察是，虽然有很多子串，但每个起始位置在变得无效之前仅生成少量有效扩展。 这在实践中将所有启动的转换总数减少到线性或接近线性。 

我们在遍历时隐式地预先计算或模拟排序结构。 每次我们将有效前缀扩展一位数字时，我们都会在不足的数字中更新其“排名”，并检查从该排名派生的模 11 界限是否允许该数字。

 ## 算法演练

 1. 迭代每个起始索引$i$在字符串中。 每个start代表一个从位置开始的候选编号$i$。 
2.初始化表示到目前为止形成的前缀的当前状态。 这个状态包括数值（对于小前缀），更重要的是，当前的“索引不足”$k$，它跟踪此前缀在不足号码的全局排序中的位置。 
3. 将数字逐位向右扩展，形成子串$s[i:j]$。 在每一步中，更新数字前缀。 
4. 如果当前数字为 0 并且位于子字符串的第一个位置，则立即停止，因为带前导零的数字无效。 
5. 如果前缀长度为1，它总是不够的（数字1-9），所以我们相应地初始化它的等级。 
6. 对于较长的前缀，计算父前缀的排名并使用以下方法确定它可以有多少个有效子前缀$k \bmod 11$。 该值充当允许的最后一位数字的上限。 
7. 检查当前位数是否严格小于允许的上限。 如果不是，请中断此起始位置的循环，因为任何进一步的扩展只会增加数字并保持无效。 
8. 如果有效，则将此子字符串计为一次不足的出现次数。 
9. 继续扩展，直到约束失败或者到达字符串末尾。 

### 为什么它有效

 关键的不变量是每个有效的子串对应于数字扩展树中的有效路径，其中每个节点在不足数字的全局排序中被分配一个确定的位置。 modulo-11 规则确保每个节点的子节点受到的限制方式与允许的下一个状态数量的定义完全匹配。 由于此排序在所有前缀中都是一致的，因此一旦子字符串违反了某个扩展处的数字限制，则任何进一步的扩展都无法恢复有效性。 这保证了提前停止永远不会跳过有效的子字符串，也永远不会包含无效的子字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    ans = 0

    for i in range(n):
        if s[i] == '0':
            continue

        k = 0
        for j in range(i, n):
            d = ord(s[j]) - 48

            if j == i:
                if d == 0:
                    break
                k = d
                ans += 1
                continue

            # compute allowed range based on k
            c = k % 11

            if d >= c:
                break

            k = k * 10 + d
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码在起始位置和结束位置上实现了双循环。 外循环修复子字符串的开头。 内循环一次扩展一位数字，同时保持当前构造的值`k`。 

变量`k`既用作数值，又用作排序不充分的索引的代理。 模 11 条件应用于每个分机以确定是否允许下一个数字。 

早期中断至关重要：一旦数字违反约束，从同一索引开始的子字符串就无法恢复有效性，因为添加更多数字只会增加数字，而允许的数字阈值由前缀状态固定。

 该解决方案在实践中是线性的，因为每个子字符串扩展要么成功并获得有效数字，要么立即失败，并且每次失败都是该起始索引的终结。 这非常适合 1 秒的时间限制$n = 10^5$。

 ## 边缘情况

 一个关键的边缘情况是当子字符串以数字开头时，该数字立即使进一步的扩展无效。 例如，从第一个数字较大的位置开始仍然有效，但后续数字可能很快就无法满足模 11 约束。 该算法通过检查每个扩展处的约束并在违反时立即停止来处理此问题，确保不计算无效子字符串。 

另一个边缘情况是单位数子字符串。 从 1 到 9 的每个数字都是自动有效的，并且算法在应用任何转换规则之前显式地对这些数字进行计数，以确保状态变量的正确初始化`k`。 

通过跳过任何起始位置来处理前导零`s[i] == '0'`，防止根级别的无效数字解释。
