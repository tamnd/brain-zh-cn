 **求解时间：** 1m 48s

 ## 解决方案
 ## 问题理解

 经过一些球插入序列后，我们得到了网格的最终占用模式。 

可以从行的左侧或列的顶部推动球。 球向前移动直到到达一个单元格。 如果该单元格为空，它将保留在那里。 如果该单元格已经包含一个球，则传入的球将占据该位置，并且移位的球继续沿相同方向移动。 

该过程类似于将元素重复插入行或列的前面，并将现有的球移入网格的更深处。 

任务不是重建操作序列。 我们只需要确定是否存在至少一个有效序列来生成给定的最终网格。 

网格尺寸最多为 50 × 50，所有测试用例的单元总数最多为 10,000。 这是一个非常小的输入大小。 甚至一个$O(nm)$或者$O(nm(n+m))$解决方案很容易足够快。 不需要复杂的数据结构。 

困难在于了解哪些最终配置是可以达到的。 

一个常见的错误是认为每个包含球的单元格都必须通过其他球连接到顶部或左侧边界。 这比必要的要强。 

考虑：```
111
111
111
```这个配置显然是可以达到的。 每个细胞都包含一个球。 

现在考虑：```
010
111
010
```尽管角落单元格是空的，但这也是可以到达的。 一个简单的连通性论证会错误地拒绝它。 

另一个容易犯的错误是过于关注操作顺序。 可能的插入序列的数量呈指数增长，因此即使对于小网格，直接模拟或回溯也是不可行的。 

关键是确定每个可到达配置都满足的结构属性，并且该属性也足以实现可达性。 

一个特别有启发性的反例是：```
000
000
001
```答案是`NO`。 

右下角的球需要在其左侧或上方的某个位置存在球才能将其推入网格那么远。 由于两者都不存在，因此没有序列可以创建这种孤立的细胞。 

## 方法

 暴力方法会尝试模拟所有可能的插入序列。 每个操作选择一行或一列。 即使对于 5 × 5 网格，可能的序列数量也会变得巨大。 由于一个测试用例中可能存在多达 2500 个球，因此彻底搜索是完全不可能的。 

为了找到更好的方法，我们需要了解推送的实际作用。 

假设一个细胞$(i,j)$最终配置中包含一个球。 球怎么会到达那里呢？ 

如果是通过row插入的$i$，然后在停止之前$(i,j)$，该行左侧的每个单元格都必须已经包含球。 不然早就停了。 

同样，如果它是通过列插入的$j$，那么该列中其上方的每个单元格都必须已经包含球。 

这个观察立即给出了一个必要条件：

 对于不在第一行和不在第一列的每个被占用的单元格，至少其上方或左侧的一个紧邻单元格也必须被占用。 

事实上，如果两个邻居都是空的，球就无法到达那个位置。 

令人惊讶的是，这个条件也是充分的。 

如果每个被占据的内部单元格的正上方或正左侧都有一个球，那么我们总是可以构建该配置。 看到这一点的一种方法是反转该过程。 任何在其下方没有被占用的单元并且其右侧没有被占用的单元的被占用的单元都可以被认为是最后插入的球。 反复去除这些细胞绝不会违反该条件。 最终整个配置消失，证明存在有效的构造。 

这将整个问题简化为简单的网格检查。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(纳米) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 读取网格。 
2. 迭代每个单元格。 
3. 忽略包含以下内容的单元格`0`，因为它们没有施加任何约束。 
4. 如果单元格位于第一行或第一列，则始终有效。 

球始终可以直接从相应的边界插入。 
5. 对于每个被占用的单元格`(i, j)`和`i > 0`和`j > 0`，检查上面的单元格`(i-1, j)`和左边的单元格`(i, j-1)`。 
6. 如果两个邻居都包含`0`，立即回答`"NO"`。 

从任一插入方向都无法到达这样的单元。 
7. 如果每个被占用的内部单元格都通过了检查，请回答`"YES"`。 

### 为什么它有效

 考虑不在顶行或左列的任何被占用的单元格。 

如果最终占据该位置的球是通过其所在行进入的，那么当它到达时，该行中在它之前的每个位置都必须被占据。 特别是，紧邻其左侧的单元格在最终配置中必须包含一个球。 

如果相反，它通过其列进入，则紧邻上方的单元格在最终配置中必须包含一个球。 

因此，每个可达配置都满足算法检查的条件。 

为了充分性，重复删除下面没有被占用的邻居并且右边没有被占用的邻居的被占用的单元格。 这样的细胞可能是最后插入的球。 局部条件保证在移除它之后，剩余的占用单元仍然满足相同的属性。 继续这个过程最终会移除所有的球，产生有效的反向结构。 因此，通过检查的每个配置都是可达的。 

该条件既是必要的又是充分的，因此该算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    ok = True

    for i in range(1, n):
        for j in range(1, m):
            if g[i][j] == '1':
                if g[i - 1][j] == '0' and g[i][j - 1] == '0':
                    ok = False

    print("YES" if ok else "NO")
```实现直接遵循证明。 

第一行第一列永远不需要检查，因为球可以直接从相应的边界进入。 

对于每个其他被占用的单元，我们测试是否存在至少一个支持邻居。 如果上部和左侧邻居都不包含球，则配置是不可能的，我们将测试用例标记为无效。 

不执行任何模拟。 整个解决方案是对网格的一次扫描。 

一个常见的差一错误是检查所有单元格并访问`i-1`或者`j-1`什么时候`i=0`或者`j=0`。 循环从`1`完全避免了这个问题。

 ## 边缘情况

 考虑最小的占用网格：```
1 1
1
```该算法不执行内部检查，因为没有内部单元。 答案是`YES`。 单击第 1 行或第 1 列即可创建配置。 

考虑孤立角的例子：```
3 3
000
000
001
```算法到达cell`(2,2)`。 它的上邻居是`0`它的左邻居是`0`，所以条件立即失败，答案是`NO`。 这与以下事实相符：在没有中间占用单元的情况下，任何推动序列都无法将球移动那么深。 

考虑仅一侧支持的配置：```
3 3
000
110
011
```对于右下角的单元格，左邻居是`1`，所以即使上邻居是`0`。 算法返回`YES`。 球只需要一个有效的插入路径，无论是从其行还是从其列。 

考虑完全空的网格：```
3 3
000
000
000
```每个单元格都会被跳过，因为没有一个单元格包含球。 没有发生违规，答案是`YES`。 始终允许进行零运算。
