 ## 解决方案
 ## 问题理解

 我们被要求计算回合制游戏中每个参与者成功的钥匙锁匹配的预期次数。 有$n$成员依次轮流，$l$锁，并且准确地$l$键（因为$k = 0$在这个简单的版本中）。 每把钥匙只能打开一把锁。 玩家挑选钥匙和锁，以最大限度地提高匹配成功的可能性，如果多个选择的可能性相同，他们就会随机挑选。 一旦锁被打开，锁和相应的钥匙都不会再次使用。 目标是找到每个成员的预期成功次数，输出模数$10^9+7$。 

输入给出了多个测试用例。 每个测试用例都有玩家数量$n$, 锁的数量$l$，以及假钥匙的数量$k$，在此版本中始终为 0。 输出是$n$每个测试用例的整数，将每个成员的预期成功匹配表示为模整数。 

约束足够小以允许动态规划解决方案：$n$最多为100，$l$最多 5000 个，总和$l$所有测试用例最多 5000 个。这意味着任何$O(n \cdot l)$或者$O(l^2)$解决方案是可行的。 棘手的部分是用分数和模算术正确计算期望值。 

需要注意的一个边缘情况是$l < n$， 例如$n=3, l=1$。 只有第一个玩家能够成功，其余成员的预期匹配为零。 在玩家之间平均分配锁的幼稚方法会给出错误的结果。 另一个微妙的情况是$l > n$，玩家将进行多轮比赛并累积分数预期贡献。 

## 方法

 强力解决方案将模拟每个可能的关键选择序列并计算精确的概率。 这在原则上是正确的，因为它对统一的随机选择进行建模，并在每轮更新可用的密钥和锁。 然而，序列的数量随阶乘增长$l$，这对于$l \le 5000$。 

关键的观察是，在这个问题中，所有钥匙和锁最初都是对称的，并且不存在假钥匙。 因此，玩家在其回合中成功的概率仅取决于剩余的锁数量。 具体来说，如果$m$锁仍然存在，轮到玩家了，打开锁的概率为$1/m$对于他们尝试的每个锁，因为所有选择的可能性都是相同的。 一旦有玩家打开一把锁，剩余的锁就会减一，下一个玩家的预期贡献也以类似的方式计算。 这导致了一种动态编程方法，我们根据剩余锁的数量和轮到谁来跟踪预期的匹配。 

我们可以定义$dp[i][j]$作为玩家的预期成功次数$i$什么时候$j$锁保持在轮次开始时。 利用转旋转模的性质$n$并在每次成功后更新剩余的锁，我们可以计算期望值$O(n \cdot l)$每个测试用例的时间。 使用模逆算术处理分数期望以满足问题的模要求。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(l!) | O(l!) | O(l!) | O(l!) | 太慢了 |
 | 具有模分数的 DP | O(n * l) | O(l) | 已接受 |

 ## 算法演练

 1. 初始化一个列表`expected`尺寸的$n$存储每个玩家的预期比赛，从零开始。 
2. 对于每个锁，从 1 到$l$，计算轮到哪个玩家了：`(lock_index % n)`。 
3. 对于每次尝试的锁定，玩家在所有剩余的锁定中都有相同的成功机会。 最初，每个锁都有一个概率`1 / remaining_locks`。 
4. 使用模算术和模逆来处理分数，将此概率添加到当前玩家的期望值中。 
5. 将剩余锁定计数减 1 并移至下一个玩家。 
6. 重复此操作，直至处理完所有锁。 

不变的是，在每一回合，预期成功匹配的数量与剩余锁的数量成比例分配，并遵循均匀概率原则。 这保证了正确性，因为预期值线性累积并且每个锁只处理一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD-2, MOD)

t = int(input())
for _ in range(t):
    n, l, k = map(int, input().split())
    expected = [0] * n
    remaining_locks = l
    player = 0
    for _ in range(l):
        expected[player] = (expected[player] + modinv(remaining_locks)) % MOD
        remaining_locks -= 1
        player = (player + 1) % n
    print(' '.join(str(x) for x in expected))
```功能`modinv(x)`计算数字的模逆`x`使用费马小定理，这是必要的，因为我们正在对素数进行模运算并且需要处理分数概率。 我们迭代所有锁并添加模块化部分`1 / remaining_locks`到当前玩家的期望值。 模运算确保我们不会因整数除法而损失精度。
