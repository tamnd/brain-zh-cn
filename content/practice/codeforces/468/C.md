 ## 解决方案
 ## 问题理解

 该任务围绕着找到两个整数 _l_ 和 _r_，使得从 _l_ 到 _r_ 的所有数字之和以给定数字 _a_ 为模，为有缺陷的实现产生边缘情况。 函数_f(x)_表示_x_的十进制数字之和。 所讨论的朴素代码计算 _f(x)_ 在区间 [_l_, _r_] 上的总和，对其取模 _a_，然后如果最终结果为非正数，则通过添加 _a_ 来调整结果。 此调整失败的唯一情况是当总和可被 _a_ 整除时，因为模运算返回 0 并且条件检查无法正确处理预期逻辑。 

输入由单个整数 _a_ (1 ≤ _a_ ≤ 10^8) 组成，输出必须是两个整数 _l_ 和 _r_，这样简单的代码就会失败。 间隔 [_l_, _r_] 可以任意大，最大可达 10²⁰⁰，但必须为正且不包含前导零。 

主要挑战在于 _a_ 的巨大程度。 直接计算 10^8 以内的数字的数字和是不可行的。 该解决方案必须利用数字总和中的数学模式，而不是暴力迭代。 当间隔长度刚好足以使数字之和恰好是 _a_ 的倍数时，或者当 _a_ 相对于容易表示的数字极小或极大时，就会出现边缘情况。 例如，如果 _a_ = 46，那么像 [1, 10] 这样的小区间就足以产生可被 46 整除的和，这将破坏简单的代码。 对于非常大的 _a_ 来说，简单地选择 l = 1 和 r = a 的粗心方法可能会失败，因为直接对数字求和是不可能的。 

## 方法

 暴力方法将迭代所有可能的区间 [_l_, _r_]，计算区间中每个数字的数字总和，对它们求和，并检查模 _a_ 的总和是否为零。 这在原则上是正确的，但其复杂性却令人望而却步。 例如，如果 _a_ = 10^8，即使在一秒钟内迭代一万亿个数字也是不可能的。 运算次数大致与求和的位数成正比，对于大范围，运算次数可能会超过 10²⁰ 次。 

关键的见解来自于注意到数字之和与数字大致呈线性增长，并且小数字产生小的、可预测的总和。 我们只需要从 1 开始的一个小区间即可产生可被 _a_ 整除的和。 由于_f(1) + f(2) + ... + f(10) = 46_，前十个数字的数字之和足以测试a = 46。这概括为：选择_l_ = 1，并且_r_作为最小数字，使得从1到_r_的数字之和至少为_a_。 当这个和模 _a_ 等于零时，天真的代码会失败，因为它返回零，然后条件尝试修复它，产生错误的答案。

 ## 算法演练

 1. 初始化_l_ = 1。我们将构造_r_，使得从1到_r_的数字之和至少为_a_。 
2. 初始化 _sum_digits_ = 0。该变量跟踪从 1 到 _r_ 的数字总和。 
3. 从 _r_ = 1 开始。递增 _r_ 直到 _sum_digits_ ≥ _a_。 在每一步中，将 _r_ 的数字总和添加到 _sum_digits_。 由于 _a_ ≤ 10^8，_r_ 永远不需要超过大约 10^8 / 9，这在分析上是可以管理的。 
4. 一旦_sum_digits_≥_a_，我们就可以输出_l_和_r_作为区间。 通过构造，[1, r] 中的数字之和可被 _a_ 整除，从而触发幼稚的代码错误。 
5. 为了确保间隔最小，检查减去最后一个数字 _r_ 是否会将 _sum_digits_ 减少到 _a_ 以下，确认 _r_ 是满足条件的最小整数。

工作原理：该算法从 1 开始递增地构造总和。不变的是，在每一步，_sum_digits_ 表示从 1 到当前 _r_ 的数字之和。 通过当该总和达到或超过 _a_ 时停止，我们保证总和模 _a_ 为零。 无需考虑超出此点的数字，因为简单的代码仅无法实现这种精确的整除性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(n):
    return sum(int(c) for c in str(n))

def main():
    a = int(input())
    l = 1
    total = 0
    r = 0
    while total < a:
        r += 1
        total += digit_sum(r)
    print(l, r)

if __name__ == "__main__":
    main()
```功能`digit_sum`将整数转换为字符串以有效地求和其数字。 这`while`循环递增_r_，更新累积数字和，直到达到或超过_a_。 最后，打印 _l_ = 1 并且找到的 _r_ 给出所需的间隔。 将数字转换为字符串可确保不会跳过任何数字，并且循环会终止，因为数字之和会随着每次增量而增长。 该算法避免显式存储间隔，因此内存使用量保持不变。

 ## 边缘情况

 当 _a_ = 1 时，最小可能区间 [1, 1] 起作用，因为 1 的数字之和为 1，可被 1 整除。算法初始化`total = 0`和增量`r`至 1。累计和等于_a_，满足条件。 对于非常大的 _a_，算法可以正确缩放，因为每个步骤至少添加 1，确保最终终止。 避免使用前导零，因为 _r_ 从 1 开始并自然递增。
