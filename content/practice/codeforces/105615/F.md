 ## 解决方案
 ## 问题理解

 给定一串数字，我们需要通过算术模 4 的角度来推理它的各个部分。任务不是显式计算大数，而是识别字符串各部分的某些数值解释是否满足被 4 整除的条件。输出要求根据此模约束下存在多少种有效解释得出计数或分类。 

一个关键的隐式结构是，尽管字符串可能表示非常大的整数，但我们永远不需要计算完整的值。 模 4 的行为仅取决于一小部分数字后缀，这使得问题变得容易处理。 

这些约束意味着输入大小足够大，以至于子串的任何二次枚举都是不可能的。 如果字符串长度达到$10^5$，然后迭代所有子字符串将产生以下顺序$10^{10}$操作，远远超出了时间限制。 这立即排除了强力子串评估，并迫使我们寻求线性或接近线性的解决方案。 

当子字符串具有前导零时，会出现微妙的边缘情况。 例如，考虑字符串`"004"`。 天真的解释可能会认为`"00"`和`"004"`取决于解析，不一致，但模算术必须将它们统一视为整数。 另一个边缘情况是非常短的字符串，例如`"1"`或者`"8"`，其中只能进行单位数解释，并且一般逻辑在不访问无效索引的情况下仍必须正确运行。 

## 方法

 暴力方法很简单：枚举每个子字符串，将其解释为数字，然后检查它是否能被 4 整除。这是可行的，因为每个子字符串都对应于一个明确定义的整数，并且可以直接检查整除性。 然而，将每个子字符串转换为整数会花费其长度的线性时间，并且对所有子字符串执行此操作会导致三次最坏情况：大致$O(n^3)$时间。 

即使我们使用滚动值优化转换，子字符串本身的数量仍然是$O(n^2)$，仍然太大。 

关键的观察结果是，能否被 4 整除仅取决于数字的最后两位数字。 这意味着对于长度至少为 2 的任何子字符串，只有其最后两个字符才能确定它是否对答案有贡献。 长度为1的子串必须单独处理，检查个位数是否能被4整除。 

这将原本看起来像全局子串问题折叠成局部转换问题。 我们只检查恒定大小的窗口，而不是重新计算值。

 ## 算法演练

 ### ## 算法演练

 1. 我们首先通过扫描每个字符并检查它是否能被 4 整除来考虑所有长度为 1 的子串。由于单个数字本身就是数字，因此这是直接检查。 
2. 然后我们处理长度至少为 2 的子字符串。对于每个索引$i$，我们将其视为子字符串的端点，并查看影响最后两位数字的可能起点。 
3. 对于固定终端位置$i$，任何以$i$并开始于$j \le i-1$与位置组成的子串具有相同的最后两位数字$i-1$和$i$。 这意味着所有以$i$一旦它们的长度至少为 2，就具有相同的整除行为。 
4. 我们检查由以下形式组成的两位数$s[i-1]s[i]$。 如果这个数字能被 4 整除，那么每个以 结尾的子串$i$并从任意位置开始$j \le i-1$有效，贡献$i$选择。 
5. 我们累积所有职位的这些贡献以形成最终答案。 

微妙的推理步骤是认识到，一旦子字符串足够长，其前缀就与模 4 的目的无关。 

### 为什么它有效

 正确性依赖于模属性，即数字的模 4 的余数仅取决于其最后两位数字。 每个以索引结尾的子字符串$i$当考虑整除性时，长度至少为 2 的后缀共享长度为 2 的相同后缀，因为附加或删除高位数字不会影响模 4 的余数。这会产生一个不变量：按结束位置和长度 ≥ 2 分组的所有子字符串都将折叠成仅基于最后两个字符的单个决策。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    ans = 0

    # single digit substrings
    for i in range(n):
        if int(s[i]) % 4 == 0:
            ans += 1

    # substrings of length >= 2
    for i in range(1, n):
        two = int(s[i-1:i+1])
        if two % 4 == 0:
            ans += i

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先直接处理单字符子字符串，因为它们不需要任何结构推理。 然后，它迭代每个可能的结束索引并提取最后两位数字，以确定以该索引结尾的所有较长子字符串是否有效。 添加的$i$来自有效起始位置的数量$0 \le j \le i-1$。 

一个常见的实现陷阱是忘记长度至少为 2 的子字符串在固定端点处共享相同的最后两位数字，这将错误地导致单独重新检查每个子字符串。

 ## 边缘情况

 对于输入`"004"`，算法独立处理每个位置。 在索引 0 和 1 处，如果能被 4 整除，则为个位数；在索引 2 处，则为对`"04"`被解释为 4，它是可整除的。 由于每个端点仅被处理一次，因此贡献会正确累积。 

对于输入`"111"`，没有单个数字可以被 4 整除，并且没有两位数后缀形成 4 的有效倍数，因此该算法生成零。 关键点是，有效后缀的缺失会自动通过计数逻辑传播，而不需要显式的子字符串检查。
