 ## 解决方案
 ## 问题理解

 我们得到了一份课程表列表，每个课程表都由单个循环日的开始时间和结束时间表示，该循环日具有`m`离散时间。 每个班级从开始时间到结束时间占据半开区间，任务是选择尽可能多的班级，使得两个选定的班级在时间上不重叠。 

时间是线性的`0`到`m`，所以虽然解释是“一天中的几个小时”，但没有概括。 唯一的限制是所选择的间隔必须是成对不相交的，并且允许在端点处接触，因为类在时间结束`t`不与起始位置重叠`t`。 

输入可能包含多个独立的测试用例，每个测试用例最多`5 · 10^5`最难版本中的间隔。 该规模立即排除了任何比较间隔对或探索子集的解决方案。 二次或偶数`O(n log n)`每个测试用例的解决方案仍然很好，但任何比`O(n log n)`由于重复排序主导运行时间，总体上会失败。 

当多个间隔共享相同的开始或结束时间时，会出现微妙的边缘情况。 例如，考虑`m = 2`有间隔`[0, 2]`,`[0, 1]`,`[1, 2]`。 最优答案是`2`，但是总是选择最早开始间隔的幼稚策略可能会选择`[0, 2]`并阻止其他一切。 当间隔嵌套时会出现另一个陷阱：`[0, 10]`,`[1, 2]`,`[2, 3]`，其中正确答案是 2，而不是 1。 

这些案例表明，仅基于开始时间的局部贪婪决策是不够的。 

## 方法

 强力方法将尝试所有间隔子集并检查所选子集是否没有重叠，从而跟踪最大大小。 检查一个子集成本的有效性`O(n)`如果通过排序或扫描天真地完成，并且有`2^n`子集，使得这甚至对于`n = 30`。 另一个稍微好一点的想法是通过修剪进行回溯，但最坏情况的行为仍然会退化为指数时间，因为可以安排间隔以避免早期修剪。 

关键的观察是，如果我们按完成时间对间隔进行排序，则该问题具有最优子结构和贪婪选择属性。 一旦我们承诺采用可用选择中最早结束的间隔，我们就可以最大化未来间隔的剩余可用空间。 任何稍后结束的替代选择只能限制或延迟未来的选择，而不会增加我们可以适应的间隔数量。 

这将问题转化为经典的间隔调度最大化问题。 按结束时间排序可确保每一步都做出局部最优选择，从而实现最大的灵活性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最优（贪婪）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 读取所有区间并将它们成对存储`(a, b)`。 这些代表必须选择不重叠的固定时间块。 
2. 按结束时间对所有间隔进行排序`b`。 进行此排序的原因是选择较早完成的间隔可以保留最多的未来可用性。 
3. 初始化变量`current_time = 0`，它跟踪我们可以自由安排下一个间隔的最早时间。 
4. 按排序顺序迭代间隔。 
5. 对于每个间隔`(a, b)`， 如果`a >= current_time`，选择并设置`current_time = b`。 这确保了我们永远不会重叠并始终致力于最早的完成兼容间隔。 
6. 计算我们选择了多少个间隔并输出该值。 

### 为什么它有效

 在每一步中，我们都保持不变式`current_time`是最后一个选择的区间的末尾，所有选择的区间都是不相交的，并且在给定排序顺序的情况下尽早完成。 当我们考虑所有剩余候选间隔中最早结束的间隔时，任何与它重叠但结束较晚的替代间隔只能减少未来的调度空间，而不会增加兼容间隔的数量。 这个交换参数保证用贪婪选择替换任何最优解的第一个不同选择不会减少间隔的总数，因此重复应用会产生最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    it = iter(sys.stdin.read().strip().split())
    out = []
    
    while True:
        try:
            n = int(next(it))
        except StopIteration:
            break
        m = int(next(it))  # unused, but part of format
        
        intervals = []
        for _ in range(n):
            a = int(next(it))
            b = int(next(it))
            intervals.append((b, a))  # sort by end time
        
        intervals.sort()
        
        current = 0
        ans = 0
        
        for b, a in intervals:
            if a >= current:
                ans += 1
                current = b
        
        out.append(str(ans))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现会立即读取所有输入，以避免重复 I/O 调用带来的开销，考虑到总大小可能达到数十万个间隔，这一点很重要。 

间隔存储为`(end, start)`特别是允许 Python 的默认元组排序首先按结束时间对它们进行排序，而无需额外的比较器逻辑。 这比紧密循环中的自定义排序键更简单、更快。 

贪婪扫描维持`current`，表示最后一个选定间隔的结束。 条件`a >= current`强制不重叠，同时仍然允许背靠背调度，这与问题的定义一致。

 ## 边缘情况

 第一个极端情况是间隔完全嵌套。 考虑输入：```
3 10
0 10
1 9
2 8
```该算法按结束时间排序并选择`(2,8)`第一的？ 不，它实际上选择`(8,2)`作为最早的结束，然后拒绝其他的，因为它们都在所选间隔结束之前开始。 最终的答案是`1`，这符合最佳行为，因为在此配置中只能选择一个没有重叠的间隔。 

另一个边缘情况是紧密的背靠背间隔链：```
3 10
0 2
2 4
4 6
```这里每个间隔恰好在前一个间隔结束时开始。 贪心条件`a >= current`允许选择所有这些。 该算法按照结束时间递增的顺序处理它们，更新`current`一步一步，并输出`3`，这是最优的。 

第三种情况涉及相同的结束时间：```
3 10
0 5
1 5
2 5
```排序后，所有区间的末尾相同。 贪心进程选择它遇到的第一个开始有效的进程，然后拒绝其余的进程，因为`current`变成`5`。 结果是`1`，这是正确的，因为所有间隔在其整个持续时间内都重叠，直到时间 5。
