 ## 解决方案
 ## 问题理解

 我们正在使用九位整数来表示 Janise 果仁蜜饼层的可能配置。 每个有效配置只是一个整数$N$在范围从$100{,}000{,}000$到$999{,}999{,}999$。 对于每个测试用例，有一个除数$K$给定，我们必须计算这九位数字中有多少个可以被$K$同时还满足附加的基于数字的约束。 

这个额外的条件涉及反转数字$N$。 当这个倒数可以被 5 整除时，我们认为$N$符合计数条件。 所以任务是同时通过两个属性过滤所有九位数字：原始数字必须能被$K$，其数字反转必须能被 5 整除。 

这些约束将其推向每个查询恒定时间的解决方案。 高达$10^5$测试用例和$K$一样大$10^5$，迭代每个查询的所有候选数字将大致需要$10^9$最坏情况下每次测试的操作次数，远远超出了可接受的限度。 任何枚举数字或模拟每个候选人的数字反转的解决方案都是不可行的。 

在解释反转条件时出现了一个微妙的问题。 如果机械地处理，人们可能会尝试计算每个倍数的反转数$K$，但这会引入不必要的数字操作。 关键是可逆整除条件实际上崩溃为对第一个数字的约束$N$，这消除了对数字其余部分的任何依赖。 

一个常见的错误是认为反转会以复杂的方式改变整除性。 例如，采取$N = 120000005$，反转它给出$500000021$，并且检查能否被 5 整除仅取决于反转数的最后一位数字，而不是完整的结构。 这一观察简化了整个问题。 

## 方法

 一种暴力方法会枚举所有九位数字，反转每个数字，检查能否被 5 整除，并另外测试能否被 5 整除$K$。 有$900{,}000{,}000$这样的数字，每个测试用例都需要扫描整个范围。 高达$10^5$测试用例，这变得完全不可行，超过$10^{14}$运营。 

关键的简化来自于对“逆序可被 5 整除”的真正含义的检验。 当一个数的最后一位是 0 或 5 时，它就能被 5 整除。反转后，反转后的最后一位数就是原数的第一位数。 这将条件简化为对前导数字的限制$N$。 自从$N$是一个九位数字，前导数字不能是0，所以必须是5。 

这将整个搜索空间转换为连续的区间：所有有效数字都位于$500{,}000{,}000$和$599{,}999{,}999$。 那么问题就变成了计算有多少个倍数$K$落在一个固定的区间内，可以用恒定时间内的楼层划分来回答。

 | --- | --- | --- | --- |
 | 蛮力 |$O(T \cdot 10^9)$|$O(1)$| 太慢了|
 | 最佳 |$O(T)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 认识到数字反转仅影响数字顺序，反转后的数字的最后一位数字是原始数字的第一位数字。 因此，能被 5 整除的条件限制了九位数的第一位数字。 
2. 得出第一位数字必须是 5 的结论，因为九位数字不能以 0 开头。这将数字的有效范围固定为单个块，从$500{,}000{,}000$到$599{,}999{,}999$。 
3. 将问题重新表述为计算可被整除的整数$K$在这个区间内。 我们不使用迭代，而是使用倍数的算术计数。 
4. 计算有多少个倍数$K$小于或等于上限$R = 599{,}999{,}999$，并减去严格低于下限的数量$L = 500{,}000{,}000$。 
5. 输出每个测试用例的差异。 

### 为什么它有效

 其正确性在于，每个有效的九位数字都由其在固定区间内的位置唯一确定，并且反转条件不依赖于除第一个数字之外的任何数字。 这就将原来的滤波问题简化为区间交集问题。 计算倍数$K$在一个区间内，通过楼层除法精确地枚举出所有有效的候选者，没有遗漏或重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_multiples(r, k):
    return r // k

T = int(input())
L = 500_000_000
R = 599_999_999

for _ in range(T):
    K = int(input())
    ans = R // K - (L - 1) // K
    print(ans)
```该解决方案完全依赖于整数除法性质。 表达式`R // K`计算所有的倍数$K$达到上限，同时`(L - 1) // K`删除低于有效间隔的那些。 这避免了显式循环并确保每个查询的恒定时间处理。 

一个常见的实施陷阱是忘记减去`L - 1`而不是`L`。 使用`L`当数字是有效倍数时，直接会错误地排除等于下限的数字$K$。

这证实了间隔计数的转换保留了原始基于数字的条件的所有结构。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    L = 500_000_000
    R = 599_999_999
    out = []
    for _ in range(T):
        K = int(input())
        out.append(str(R // K - (L - 1) // K))
    return "\n".join(out)

 ## 边缘情况

 对于$K = 1$，算法返回区间的总大小$599{,}999{,}999 - 500{,}000{,}000 + 1 = 100{,}000{,}000$，匹配范围内的每个数字都是有效的事实。 计算正确地减少到`R - (L - 1)`。 

对于非常大的$K$， 例如$10^9$， 两个都`R // K`和`(L - 1) // K`计算结果为 0，产生正确的结果 0，因为区间内不存在倍数。 

在边界处$K = 500{,}000{,}000$，该区间恰好包含一个倍数，即下界本身。 减法公式确保它被包含在内，因为`(L - 1) // K`不计算它`R // K`做。
