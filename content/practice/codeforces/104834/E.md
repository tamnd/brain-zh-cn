 ## 解决方案
 ## 问题理解

 我们给出了一个尺寸的网格$n \times m$，其中每个单元格都有一个高度值。 糖浆被倒在一些起始单元上，从每个起始点开始，它按照取决于高度和移动限制的规则在网格上扩散。 

从任何单元格，糖浆可以移动到四个特定的邻居：直接向上、直接向下和两个对角线方向，向上移动一行，向左移动一列，或者向下移动一列，向右移动一列。 但是，仅当下一个单元格的高度小于或等于当前单元格时才允许移动。 因此，糖浆总是沿着非增加的高度路径流动，但仅沿着这组有限的边缘流动。 

每次浇注都是独立开始的。 对于每个起始单元格，我们模拟这些规则下的完整可达区域。 每次从起始点可以到达某个单元格时，该单元格就被视为在该倾倒过程中被覆盖一次。 每次浇注完成后，该过程都会重置。 

任务是确定哪个网格单元被最大数量的浇筑覆盖。 如果多个单元格相等，我们选择行索引最小的一个，如果仍然相等，则选择最小列索引。 

网格最多是$100 \times 100$，并且最多有$1000$倒。 就原始尺寸而言，每次浇筑的直接模拟是可行的，但前提是每次模拟都有效。 每个查询的完整 BFS 将访问最多$10^4$节点，导致大约$10^7$总体而言，这是边界，但在仔细实现的情况下，在 Python 中仍然可以接受。 任何在每个单元的简单重复 DFS 中重新计算可达性的解决方案都会爆炸成$10^9$运营。 

如果我们尝试将运动视为无向或忽略高度约束方向性，则会出现微妙的失败情况。 例如，考虑：```
1 3
1 2 3
1 2 1
```从 (1,3) 来看，我们可能会错误地假设我们可以在不检查方向约束的情况下流入较低的邻居，从而错误地扩大覆盖范围。 

另一个问题是重新计算：如果我们尝试使用重复的 DFS 计算每对（开始、单元）的可达性，我们将多次重新计算相同的可达区域，即使许多浇注从相同或相似的区域开始。 

关键的观察结果是每次浇筑都是独立的，我们只需要沿着由网格边和高度约束定义的有向图向前传播可达性。 

## 方法

 蛮力方法独立模拟每次浇注。 对于每个起始单元格，我们运行 BFS 或 DFS 并标记所有可到达的单元格。 然后我们为每个访问过的单元增加一个全局计数器。 由于每个 BFS 最多可以触及$n \cdot m$细胞，并且有$q$倒，最坏情况的成本是$O(qnm)$，这大约是$10^7$运营。 这已经接近极限但仍然可行。 

更简单的替代方案是使用全对可达性或重复洪水填充来预先计算从每个单元到每个其他单元的可达性。 这会导致$O((nm)^2)$或者更糟，这显然是不可行的。 

关键的见解是，我们不需要在不同的注入中重用结果，但我们应该确保每个 BFS 高效并避免重新访问单元格。 由于图很小且有向，因此每个查询使用已访问数组的简单 BFS 就足够了。 运动结构不允许违反高度限制的循环，因此每个 BFS 自然受到网格大小的限制。 

因此，我们可以将每次浇注视为多源可达性问题，但独立执行，累积覆盖率计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力 BFS |$O(qnm)$|$O(nm)$| 已接受 |
 | 预先计算所有对的可达性 |$O((nm)^2)$|$O((nm)^2)$| 太慢了|

 ## 算法演练

 我们使用 BFS/DFS 独立处理每次浇注。 

1. 初始化全局二维数组`cnt`尺寸的$n \times m$为零。 这将跟踪到达每个单元的浇注次数。 
2. 对于从单元开始的每次倾倒$(i, j)$，运行 BFS：

 我们将起始单元推入队列，并将其标记为针对该特定 BFS 已访问。 我们只前进到满足高度限制的邻居。 
3. 在 BFS 期间，每当我们访问一个单元格时，我们都会递增`cnt[cell]`一个。 这确保每次倾倒对每个可到达的单元格贡献一次。 
4. 从每个弹出的单元格中，尝试移动到四个允许的邻居：上、下、左上对角线和右下对角线。 仅当邻居位于网格内部、在此 BFS 中未访问过且高度小于或等于当前单元格时，我们才会将其入队。 
5. 完成一次浇筑的 BFS 后，丢弃访问过的结构并移至下一次浇筑。 
6. 处理完所有浇注后，扫描整个网格以查找具有最大值的单元格`cnt`。 按行断开关系，然后按列断开关系。 

我们在遍历过程中而不是在 BFS 完成后递增的原因是，我们希望每个单元记录每次倾倒的参与情况，而不存储完整的可达集。 

### 为什么它有效

 对于每次倾倒，BFS 都会在沿着允许的移动不增加高度的定向约束下精确探索可到达的单元格集合。 访问的数组保证每个单元每次倾倒最多计数一次。 由于倾倒是独立的，因此将这些贡献相加即可得出每个单元被覆盖的确切次数。 最终扫描选择最大频率单元，并且平局决断确保确定性输出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, q = map(int, input().split())
    h = [list(map(int, input().split())) for _ in range(n)]

    cnt = [[0] * m for _ in range(n)]

    dirs = [(-1, 0), (1, 0), (-1, -1), (1, 1)]

    for _ in range(q):
        si, sj = map(int, input().split())
        si -= 1
        sj -= 1

        vis = [[False] * m for _ in range(n)]
        dq = deque()
        dq.append((si, sj))
        vis[si][sj] = True

        while dq:
            i, j = dq.popleft()
            cnt[i][j] += 1

            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    if not vis[ni][nj] and h[ni][nj] <= h[i][j]:
                        vis[ni][nj] = True
                        dq.append((ni, nj))

    best_i, best_j = 0, 0
    best_val = -1

    for i in range(n):
        for j in range(m):
            if cnt[i][j] > best_val:
                best_val = cnt[i][j]
                best_i, best_j = i, j

    print(best_i + 1, best_j + 1, best_val)

if __name__ == "__main__":
    solve()
```BFS 循环的结构使得每次查询每个单元都只处理一次。 每次浇注都会重新创建访问过的矩阵，以避免模拟之间的污染。 方向数组完全按照指定对四个允许的转换进行编码。 

最终扫描在网格上是线性的，并通过依赖迭代顺序安全地处理平局打破。

 ## 边缘情况

 一个关键的边缘情况是所有高度都相等。 在这种情况下，只要通过允许的方向连接，每个单元都可以从任何起点到达。 例如：```
2 2 1
5 5
5 5
1 1
```(1,1) 的 BFS 访问所有单元格，因为每次移动都满足非递增条件。 该算法正确地将所有四个单元格递增一次，并且最终的最大值相等。 平局规则选择 (1,1)，它与字典顺序最小的单元格匹配。 

另一种边缘情况是，除了开始时之外，由于地形严格增加，移动受到极大限制。 在：```
2 2 1
1 2
3 4
1 1
```只有 (1,1) 是可达的，因为所有邻居都违反了高度条件。 BFS 仅标记起始单元，并且计数保持正确，没有任何传播。 

最后一个微妙的情况是从同一个单元开始重复浇注。 由于每个 BFS 使用独立的访问数组，因此倒入之间的重叠不会产生干扰。 同一区域被多次计数，并且累积反映了准确的频率而不是不同的起始位置。
