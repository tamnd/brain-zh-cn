 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组。 一个数组代表不同订单的目标数量，另一个数组代表准备批次中的当前数量。 每个操作都允许将单个单元从任何批次移动到任何其他批次，从而有效地重新分配值，同时保留总和。 

目标不是将所有批次转换为订单。 相反，我们只需要知道某个订单值是否已存在于批次数组中，或者可以在一系列单位移动之后存在，如果是，则使至少一个批次完全等于一个订单值所需的最小移动次数是多少。 

一个关键的观察是我们没有预先选择配对。 我们可以自由地重塑批量值的多集，但只能通过单位传输，并且我们希望以最便宜的方式使任何一个批次准确地达到任何目标。 

约束很大，最多有 200000 个值，幅度最多为 10^9。 这立即排除了所有订单对和批次与模拟的二次比较。 即使 O(N log N) 解决方案也是边界的，除非每个候选者的核心检查是常数或摊销常数。 该结构强烈建议与全局可行性条件相结合的排序或散列。 

一个微妙的点是可行性取决于总余额。 如果我们尝试使批次等于某个目标值 x，则其余批次的总和仍必须正确。 如果 b 的总和为 S，那么在使一批等于 x 后，剩余的 N-1 批总和必须为 S - x，这总是可能的，因为我们可以任意重新分配。 因此，唯一真正的限制是我们是否可以将某些批次调整为恰好 x，以及需要花费多少单位移动。 

一个幼稚的错误是假设我们必须直接将某些 a[i] 与某些 b[j] 匹配，或者贪婪地选择最接近的值。 但这是失败的，因为跨多个批次的中间重新分配可以显着降低成本。 

另一个错误是认为只有精确匹配才重要。 例如，如果我们有 b = [5, 6] 且 a = [7]，即使没有从 7 开始的批次，我们也可以通过从 5 移动 1 个单位来从 6 到达 7，这会花费 1 次操作。 

## 方法

 蛮力的想法是尝试每个目标值 a[i] 和每个起始批次 b[j]，并计算将 b[j] 转换为 a[i] 的成本。 然而，单个批次无法在不影响其他批次的情况下自由更改。 如果我们尝试增加 b[j]，我们必须从其他批次中获取单位，如果我们减少它，我们必须将其多余部分重新分配到其他地方。 这意味着每个候选成本取决于全局分布，而不仅仅是配对。 

更正确的暴力模型是模拟，对于每个目标 x，必须将多少总单位从高于 x 的批次移动到低于 x 的批次才能使某些批次达到 x。 这需要扫描所有 b 值并计算相对于 x 的盈余和赤字。 对 a 中的每个 x 执行此操作将花费 O(N^2)，因为每次评估都会扫描整个数组。 

关键的见解是，对于固定的目标值 x，使某些批次等于 x 的最小操作数仅取决于必须在阈值 x 上移动多少总质量。 如果我们想象对 b 进行排序，那么对于选定的 x，我们可以计算有多少个单位在 x 上方以及有多少个单位在 x 下方。 为了使一个特定位置达到x，我们有效地将不平衡集中到一个桶中，并且最小成本成为我们“居中”调整的所有可能位置的最小值。

这导致对两个数组进行排序。 排序后，我们对待候选者 x = a[i] 并与排序后的 b 进行比较。 对于每个 x，我们计算 x 上方存在多少总盈余单位以及 x 下方存在多少赤字单位。 所需的移动次数恰好是必须向下推的总盈余（或等效地填补总赤字），因为每次操作都会将一个单位移动越过不匹配边界。 

为了有效地计算这一点，我们使用排序 b 上的前缀计数。 对于给定的 x，我们使用二分查找找到它在 b 中的位置。 所有大于 x 的元素都贡献盈余，所有小于 x 的元素贡献赤字，成本就成为将一个槽位与 x 对齐所需的绝对不平衡之和。 我们对排序 a 中的所有 x 进行评估并取最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个目标的强力模拟 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了|
 | 排序+前缀不平衡+二分查找 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们现在通过推理排序数组中的不平衡来计算答案。 

1. 对数组 a 和 b 进行排序。 需要排序，以便我们可以推断值如何全局比较而不是成对比较。 排序后，我们可以有效地分离大于或小于所选目标的元素。 
2. 预先计算b的前缀和。 这使我们能够在二分搜索后快速计算低于或高于任何阈值的总质量 O(1)。 这是至关重要的，因为每个候选目标都需要全局聚合。 
3.对于a中的每个候选目标值x，使用二分查找定位其在排序b中的位置。 这将 b 分为两组：小于 x 的元素和大于 x 的元素。 
4. 计算 x 上方存在多少超额以及 x 下方存在多少赤字。 x 以上的每个单元必须向下移动，x 以下的每个单元必须接收单元。 所需操作的数量等于这两侧之间的总不匹配。 
5. x 的成本是 b 与一个位置变为 x 的单一完美配置之间的绝对不平衡之和。 跟踪所有 x 的最小值。 
6. 如果在不平衡处理隐含的约束下无法进行转换，则返回 -1。 在这个问题结构中，可行性始终成立，因为我们总是可以重新分配，因此除非违反实现约束，否则答案始终是定义的。 

### 为什么它有效

 关键不变量是每个操作在两个位置之间精确移动一个单位，因此每个操作将当前多重集与任何目标配置之间的总绝对偏差精确地减少 2（就不平衡质量而言）。 对于固定目标 x，所有最优策略都归结为将过剩单位推向赤字地区。 因为成本仅取决于有多少单元必须跨越 x 定义的边界，而不取决于它们的身份，所以排序完全表征了最佳移动。 任何实现 x 的解决方案都必须考虑完全相同的总不平衡性，因此计算的成本对于该 x 来说是最小且唯一的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()

    # prefix sums of b
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + b[i]

    total_b = pref[n]

    import bisect

    ans = float('inf')

    for x in a:
        idx = bisect.bisect_left(b, x)

        # elements < x
        left_count = idx
        left_sum = pref[idx]

        # elements >= x
        right_count = n - idx
        right_sum = total_b - left_sum

        # cost interpretation:
        # left side needs to gain (x * left_count - left_sum)
        # right side needs to lose (right_sum - x * right_count)
        cost = (x * left_count - left_sum) + (right_sum - x * right_count)

        ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码对两个数组进行排序，以便与候选目标的比较成为基于间隔的而不是成对的。 b 的前缀和允许对所选 x 两侧的和进行恒定时间计算。 对于 a 中的每个 x，二分搜索将 b 分成低于和高于 x 的值，然后我们计算每条边与其理想配置（所有值都等于 x）的距离。 

成本公式直接计算必须向上或向下移动多少个单位才能将 b 中的每个值与 x 对齐。 每个单位差异对应于一次操作，因此总不平衡给出了准确的移动次数。 

答案是所有 x 中的最小值，因为我们可以完成任何单个订单。

 ## 边缘情况

 一种边缘情况是所有 b 值都相同。 在这种情况下，每个候选 x 仅取决于与该常量值的距离，并且二分搜索将 b 分为空范围或完整范围。 成本公式干净利落地减少到 n 倍的绝对差异。 

另一个边缘情况是当 a 包含重复项时。 该算法多次正确评估相同的 x，但由于我们取最小值，重复不会影响正确性，只会影响运行时间。 

最后的边缘情况是最优 x 不接近 b 的中值。 由于候选者仅限于 a[i]，我们依赖于最佳目标必须是现有订单大小之一的保证，因为任何中间值只会增加相对于直接与现有需求值对齐的不平衡性。
