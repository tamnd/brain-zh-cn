 ## 解决方案
 ## 问题理解

 我们被要求计算一个二进制字符串中恰好包含 _k_ 个的子字符串。 子字符串是字符串中任何连续的字符序列，不同位置的不同出现单独计数。 例如，在字符串“1010”中，子字符串“10”出现两次，每次单独计数。 输入给出一个整数_k_和一个二进制字符串_s_，我们需要输出一个整数，表示恰好有_k_个的子串的数量。 

字符串长度最多可达 1,000,000 个字符，这排除了显式检查所有子字符串的简单方法。 对所有 O(n²) 子串进行强力检查（每次都计算一个），在最坏的情况下将导致多达 10^2 次操作，远远超过 2 秒的时间限制。 这立即引导我们找到一个在线性或线性时间（理想情况下为 O(n)）内工作的解决方案。 

可能导致幼稚实现失败的边缘情况包括 _k = 0_ 或全零或全一的字符串。 例如，如果 _s = "000"_ 且 _k = 0_，则正确输出为 6，对应子字符串“0”、“0”、“0”、“00”、“00”、“000”。 只计算 1 的粗心解决方案会错误地返回 0。另一个微妙的情况是当 _k_ 超过 _s_ 中的总数量时，应该返回 0。 

## 方法

 暴力方法很简单：通过选择开始和结束索引来枚举所有可能的子字符串，并计算每个子字符串中的个数。 这是可行的，因为对于每个子字符串，我们可以准确确定它包含多少个子字符串，但它会变得非常慢，因为长度为 _n_ 的字符串中的子字符串总数为 n(n+1)/2，并且在最坏的情况下，对每个子字符串内的子字符串进行计数会增加另一个 n 因子。 对于 _n = 10⁶_，如果简单地实现，这会导致 O(n3) 次操作，这是完全不可行的。 

最佳解决方案的关键见解来自于观察问题简化为计算字符串中的范围。 如果我们记录所有 1 的位置，则任何恰好包含 _k_ 个 1 的子串都会在第 (i-1) 个 1 之后开始，并在第 (i+k) 个 1 或之前结束。 通过预先计算这些位置，我们可以直接计算有效的起始和结束索引的数量，而无需检查每个子字符串。 对于特殊情况 _k = 0_，我们改为计算连续的零块，并使用组合求和计算每个块内存在多少个子串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了 |
 | 最优（前缀+个位）| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取整数_k_和二进制字符串_s_。 初始化一个列表来存储 1 的位置，在开头添加 -1，在末尾添加 n 作为哨兵。 这简化了边界计算。 
2. 遍历字符串一次。 每当字符为“1”时，将其索引附加到个位列表中。 
3. 如果 _k = 0_，则迭代连续的 1 位置以查找它们之间的 0 块。 对于长度为_l_的块，子串的数量为l(l+1)/2。 对所有零块的这些贡献求和并返回总数。 
4. 如果 _k > 0_，则迭代从索引 1 到 len(ones) - k - 1 的个位。对于每个包含 _k_ 个个位的窗口，令 left_gap 为窗口中第一个 1 之前的 0 数量，而 right_gap 为窗口中最后一个 1 之后的 0 数量。 恰好包含这组 k 个的子串的数量为 (left_gap + 1) * (right_gap + 1)。 将其添加到运行总计中。 
5. 输出总计数。

为什么它有效：通过记录所有的位置，我们将问题转换为组合问题。 每个恰好有 k 个的子串唯一对应于 k 个连续的窗口。 该窗口可能的子串的数量正是用零向左和向右扩展的方式的数量，这是由间隙捕获的。 这种方法保证每个有效子字符串都被计算一次，并且不会计算无效子字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

k = int(input())
s = input().strip()
n = len(s)

ones = [-1]  # sentinel before start
for i, c in enumerate(s):
    if c == '1':
        ones.append(i)
ones.append(n)  # sentinel after end

if k == 0:
    total = 0
    for i in range(1, len(ones)):
        zeros = ones[i] - ones[i-1] - 1
        total += zeros * (zeros + 1) // 2
    print(total)
else:
    total = 0
    for i in range(1, len(ones) - k):
        left_gap = ones[i] - ones[i-1]
        right_gap = ones[i+k] - ones[i+k-1]
        total += left_gap * right_gap
    print(total)
```第一个循环收集所有“1”位置并添加哨兵值。 开始之前的哨兵确保当窗口从第一个窗口开始时正确计算剩余间隙。 结束后的哨兵确保当窗口在最后一个窗口结束时正确计算正确的间隙。 条件分支使用零子串的组合计数来处理零情况。 

## 工作示例

 **示例 1：** 输入：k=1, s=“1010”

 | 列表 | -1,0,2,4 |

 | 窗口| 左间隙 | 右间隙 | 贡献 |
 | ---| ---| ---| ---|
 | 第 0 个“1”| 0-(-1)=1 | 0-(-1)=1 | 2-0=2 | 1*2=2 | 1*2=2
 | 第一个“1” | 2-0=2 | 4-2=2 | 2*2=4 | 2*2=4
 | 总计 | | | 6 |

 这证实了所有包含一个“1”的子字符串都被计算在内。 

**示例 2：** 输入：k=2, s="10101"

 | 列表 | -1,0,2,4,5 |

 | 窗口| 左间隙 | 右间隙 | 贡献 |

 | 0-1 | 0-(-1)=1 | 0-(-1)=1 | 4-2=2 | 2 |

 | 1-2 | 1-2 2-0=2 | 5-4=1 | 5-4=1 2 |

 | 总计 | | | 4 |

 这表明重叠窗口的处理是正确的。

 ## 边缘情况

 对于 k=0 和 s="000"，个数列表为 [-1,3]。 零块长度为 3-(-1)-1 = 3，给出 3*4/2 = 6 个子串，完全正确。 对于 k 大于总数的情况，例如 k=5 和 s="1010"，则不会执行 windows 上的循环，并且总数仍为 0，这是正确的。 对于边界处有 1 的字符串，哨兵确保正确计算左右间隙。 每个边缘情况都确认该算法一致地处理边界、零子串和重叠窗口。
