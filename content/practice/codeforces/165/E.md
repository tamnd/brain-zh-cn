 ## 解决方案
 ## 问题理解

 给定一个整数数组，对于每个元素，我们必须找到另一个数组元素，其按位与为零。 当两个数字不共享任何设置为的位时，它们完全兼容`1`。 

例如，如果我们看`90`和`36`:```
90  = 1011010
36  = 0100100
AND = 0000000
```没有位位置包含`1`在两个数字中，因此它们是兼容的。 

任务不是计算兼容对。 对于每个数组值`a[i]`，我们只需要输出一个数组元素`x`这样：```
a[i] & x = 0
```如果不存在这样的元素，我们打印`-1`。 

约束完全决定了解决方案的方向。 该数组最多可以包含`10^6`数字，每个值最多`4 * 10^6`。 自从`4 * 10^6 < 2^22`，每个数字都适合 22 位。 

二次解需要检查所有对：```
10^6 * 10^6 = 10^12
```操作，这是不可能的。 

22 位界限才是真正的线索。 当位数很小时，位掩码动态编程就成为可能。 大小的状态空间`2^22`约为 420 万，虽然很大，但在低常数因子实现中，时间和内存仍然可以管理。 

有几种边缘情况会破坏粗心的解决方案。 

假设输入是：```
1
7
```唯一的数字是`7`。 自从`7 & 7 != 0`，答案是`-1`。 有缺陷的实现可能会意外地允许数字与自身匹配而不检查兼容性。 

另一个棘手的情况是重复值：```
3
0 5 5
```数量`0`与一切兼容，因为：```
0 & x = 0
```为所有人`x`。 正确的输出可能是：```
5 0 0
```仅搜索严格子掩码的解决方案可能会错过`0`。 

当设置许多位时，会出现一个更微妙的问题：```
2
4194303 1
```

`4194303 = 2^22 - 1`已设置所有位，因此它不能与任何正数兼容。 正确答案是：```
-1 -1
```错误的补码掩码计算很容易溢出有效的 22 位范围并产生无效状态。 

## 方法

 最直接的解决方案是检查每对数字。 

对于每个`a[i]`，我们迭代整个数组并测试：```
a[i] & a[j] == 0
```按位与运算本身是常数时间，因此总复杂度变为`O(n^2)`。 

这种强力方法是正确的，因为兼容性完全是通过成对比较来定义的。 如果存在任何兼容的号码，详尽的搜索最终将找到它。 

问题在于规模。 和`n = 10^6`，这种方法需要大约`10^12`检查，超出限制数千次。 

重要的观察结果是兼容性仅取决于位模式，而不取决于数组中的位置。 

对于固定数量`x`，我们想要一些数字`y`这样：```
x & y = 0
```这意味着设置的每一位`y`必须位于零位位置内`x`。 

如果我们定义：```
FULL = (1 << 22) - 1
```那么允许的位`y`正是：```
FULL ^ x
```因此，我们可以询问：

 “该数组是否包含任何子掩码`FULL ^ x`？”

 这将问题转化为经典的 SOS DP，也称为子集求和 DP。 

我们创建一个数组`dp[mask]`在哪里：```
dp[mask] = some array value that is a submask of mask
```最初，如果一个数`v`出现在数组中，我们设置：```
dp[v] = v
```然后我们通过掩码向上传播信息。 对于每个掩码和每个设置位，我们从较小的子掩码继承答案。 

预处理之后，查询变得很容易：```
answer(x) = dp[FULL ^ x]
```因为补码掩码的任何子掩码都没有与以下共享设置位`x`。 

预处理成本约为：```
22 * 2^22
```操作，大约 9200 万次转换。 在优化的 Python 中这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 SOS DP | O(22 · 2²² + n) | O(22 · 2²² + n) | O(2²²) | 已接受 |

 ## 算法演练

 1、定义最大位宽为22，因为每个输入的数字都小于`2^22`。 
2. 创建数组`dp`尺寸的`2^22`并将每个条目初始化为`-1`。 
3. 对于每个值`x`在输入数组中，设置：```
dp[x] = x
```这意味着精确的掩码`x`存在于数组中。 
4. 对所有面罩运行 SOS DP。 

对于每个掩码和每个位位置：

 如果当前掩码中设置了该位，请尝试将其删除：```
smaller = mask ^ (1 << bit)
```如果`dp[mask]`仍然是`-1`，继承：```
dp[mask] = dp[smaller]
```这样做的原因是通过重复删除设置位可以到达每个子掩码。 
5. 对于每个数组值`x`，计算：```
complement = FULL ^ x
```每个兼容数字必须是该补码掩码的子掩码。 
6. 输出：```
dp[complement]
```如果数组中不存在有效的子掩码，则该值保留`-1`。 

### 为什么它有效

 DP 不变量为：```
dp[mask] stores some array value that is a submask of mask,
or -1 if none exists.
```最初，对于精确掩码来说这是正确的，因为我们显式存储现有的数字。 

在转换期间，我们仅从通过删除位获得的较小掩码中复制值。 任何子掩码`smaller`也是一个子掩码`mask`，因此不变量仍然有效。 

对于查询值`x`，面具`FULL ^ x`恰好包含位位置`x`有零。 任何子掩码`y`该补集满足：```
x & y = 0
```因为`y`从不使用已经设置的位`x`。 

所以如果`dp[FULL ^ x] = y`， 然后`y`保证兼容`x`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

BITS = 22
SIZE = 1 << BITS
FULL = SIZE - 1

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dp = [-1] * SIZE

    for x in a:
        dp[x] = x

    for bit in range(BITS):
        for mask in range(SIZE):
            if mask & (1 << bit):
                if dp[mask] == -1:
                    dp[mask] = dp[mask ^ (1 << bit)]

    ans = []

    for x in a:
        ans.append(str(dp[FULL ^ x]))

    print(" ".join(ans))

solve()
```该解决方案首先将 DP 数组分配给所有 22 位掩码。 这个数量很大，大约有 420 万个条目，但在存储整数时仍然完全符合 Python 的内存限制。 

初始化步骤将每个数组值直接存储到其自己的掩码位置。 目前，只知道确切的掩码。 

SOS DP 阶段将信息从较小的子掩模传播到较大的掩模。 顺序很重要。 对于每一位，我们处理包含该位的所有掩码，并尝试从删除该位的版本继承。 

一个常见的错误是颠倒过渡方向。 我们想要：```
mask -> mask without one bit
```因为我们正在收集有关子掩码的信息。 

补码计算是另一个出现错误的地方。 我们必须将补码限制为 22 位：```
FULL ^ x
```使用`~x`会在 Python 中创建负数，因为整数是无界的。 

最终的查找是常数时间。 预处理后，每个查询都减少为单个数组访问。

import sys
import io

BITS = 22
SIZE = 1 << BITS
FULL = SIZE - 1

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    dp = [-1] * SIZE

    for x in a:
        dp[x] = x

    for bit in range(BITS):
        for mask in range(SIZE):

                if dp[mask] == -1:
                    dp[mask] = dp[mask ^ (1 << bit)]

    for x in a:
        ans.append(str(dp[FULL ^ x]))

    print(" ".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

assert run("2\n90 36\n") == "36 90", "sample 1"

# minimum size, no compatible value
assert run("1\n7\n") == "-1", "single element"

# zero-compatible structure

assert res[0] in {"2", "4"}
assert res[1] in {"1", "4"}
assert res[2] in {"1", "2"}

# all equal values
assert run("4\n5 5 5 5\n") == "-1 -1 -1 -1", "all equal"

assert run("2\n4194303 1\n") == "-1 -1", "22-bit boundary"

 ## 边缘情况

 考虑输入：```
1
7
```唯一可用的号码是`7`本身。 自从：```
7 & 7 = 7
```它与自身不兼容。 

补码掩码仅包含以下位置的零位：`7`有 1，并且数组中没有现有的子掩码满足它。 DP查找返回`-1`。 

现在考虑重复项：```
4
5 5 5 5
```二进制：```
5 = 101
```任意一对`5`s 仍然共享位：```
101 & 101 = 101
```在预处理过程中，仅`dp[5]`变得拥挤。 没有补码掩码可以通过子掩码转换到达它，因此每个答案仍然存在`-1`。 

最后，检查最大掩码情况：```
2
4194303 1
```

`4194303`等于：```
1111111111111111111111
```所有 22 位均已设置。 

其 22 位内的补码为零：```
FULL ^ 4194303 = 0
```掩模处的DP值`0`是`-1`，因为数组中不存在零。 算法正确输出`-1`。 

对于数量`1`，它的补码包含除最低位之外的所有位，但是`4194303`不是该补码的子掩码，因为它仍然包含禁止的最低位。 所以答案为`1`也是`-1`。
