 ## 解决方案
 ## 问题理解

 我们有一个双向系统，一侧是工人，另一侧是机器，两者的尺寸都不同$N$。 每个工人最初都知道如何操作某些机器子集。 每天，所有工人都按照任意顺序到达。 当工人到达时，他们会查看他们知道尚未分配的机器，然后任意选择其中一台。 一旦一台机器被占用，它将在当天剩余的时间里保持分配状态。 

我们可以添加新的“训练边”，这意味着我们可以以每对 1 的成本教任何工人任何机器，从而有效地在二分图中添加一条边。 目标是保证无论工人如何排序，也无论他们在选择机器时如何打破束缚，在流程结束时，每台机器都会准确地分配给一名工人。 

关键的困难在于对手既控制到达顺序又控制可用机器的选择。 这意味着图中的任何脆弱结构都可以被利用来强制失败。 

约束条件$N \le 25$建议尝试枚举子集或模拟大小状态的解决方案$2^N$可能是可以接受的，但它也为更简单的结构观察（如果存在）留下了空间。 

每当某些工人不了解某些机器时，就会出现微妙的故障情况。 即使静态图中存在完美匹配，贪婪过程仍然可以通过做出“错误的早期选择”来阻止必要的后续分配来破坏它。 

例如，如果工人$A$无法操作机器 2，但工人$B$可以操作两台机器，那么如果$B$先到达并选择机器 1，工人$A$随后被迫同时占用机器 1 或闲置，从而使机器 2 处于未分配状态。 仅有完美匹配的存在是不够的； 系统在所有贪婪执行下必须具有鲁棒性。 

这种稳健性要求是解决方案的驱动力。 

## 方法

 一个自然的起点是考虑二分图上的贪婪匹配。 该过程不是标准的离线匹配问题； 相反，它是一个具有对抗性排序和对抗性打破平局的在线过程。 

人们可以尝试描述贪婪匹配何时总是成功的特征。 这很快就会导致尝试对所有前缀和所有子选择强制实施结构约束，例如霍尔条件。 然而，由于工人可以在多个可用机器中任意选择，因此系统必须在每个可能的破坏性选择序列下保持正确，而不仅仅是某些序列。 

考虑修复图的强力方法是考虑添加边并模拟所有可能的到达顺序和选择。 对于每个配置，我们将验证每个可能的贪婪运行是否产生完美匹配。 这会以组合方式爆炸：即使对于固定图，可能的执行数量在排列和分支选择方面都是指数级的。 

关键的观察结果是，任何缺失的边缘都会引入可被利用的潜在故障点。 假设工人$i$不认识机器$j$。 如果我们试图证明系统仍然安全，我们必须证明机器$j$永远不会因为早期的任意分配而“丢失”。 但由于早期的工作人员可能会消耗保持可行性所需的所有替代机器，因此对手总是可以强制进行配置$j$与所有剩余工人隔离，除了$i$， 和$i$不能接受。 这会导致不可避免的失败。 

这个推理得出了一个非常有力的结论：为了保证任意贪婪行为下的正确性，每个工人必须能够操作每台机器。 一旦这是真的，任何选择都不能消除可行性，因为每个剩余的工人总是有充分的灵活性来使用任何剩余的机器。 

因此，最佳策略就是通过添加每个缺失的工人-机器边来完成二分图。 

答案就是矩阵中零条目的数量。

 | 完成二分完成 |$O(N^2)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 阅读$N \times N$描述哪个工人可以操作哪台机器的矩阵。 每个“1”是一个现有的边缘，每个“0”是一个缺失的边缘。 
2. 数一下有多少对$(i, j)$矩阵中有一个零。 每对都代表一种缺失的能力。 
3. 输出该计数作为成本，因为我们必须添加所有缺失的边以保证鲁棒性。 

### 为什么它有效

 如果缺少任何工作机-机器对，那么在精心选择的到达顺序下，该对可能会变成强制瓶颈。 对手可以确保所有其他工作人员以这样的方式消耗替代机器，即机器唯一剩余的安全分配将需要丢失的边缘。 由于该分配是不可能的，因此不能保证系统完成。 

一旦所有边缘都存在，每个工人总是在所有机器之间拥有充分的自由，无论当前的部分分配如何。 任何贪婪的选择序列都不能消除完成匹配的能力，因为直到最后一步（只剩下一台机器）之前，没有工作人员会用完有效选项。 

这消除了所有可能的故障模式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n = int(input())
        ans = 0
        for _ in range(n):
            row = input().strip()
            ans += row.count('0')
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```代码直接计算必须添加多少训练边。 每行扫描一次，每项缺失的功能都会为答案贡献一美元。 格式遵循所需的输出样式。 

不需要额外的数据结构，因为解决方案仅取决于丢失连接的总数。

 ## 边缘情况

 如果一个工人最初不知道任何机器，则必须添加涉及该工人的每个缺失边。 如果没有这些边缘，无论订单如何，该工人都可能会永久闲置。 

如果没有工人知道一台机器，则还必须添加涉及该机器的每个缺失边，否则永远无法分配该机器。 

在这两种情况下，算法自然会计算全零，确保这些病态配置得到完全修复。
