 ## 解决方案
 ## 问题理解

 我们得到了一组权重，我们必须使用数轴上的两个分割点将这些值分成三组。 严格低于第一个剪切的所有内容都属于一个组，至少第二个剪切的所有内容都属于另一个组，而介于两者之间的所有内容则形成第三组。 

进行此分区后，要求每个组的大小为 2 的幂，并且不允许任何组为空。 如果一个组太小或者它的大小不是2的幂，我们可以向该组添加额外的元素，直到它的大小变成2的幂。 目标是选择两个分割点，以使所有三组中添加的元素总数最小化。 

关键的困难在于两个分割点同时确定三个组的大小，并且移动边界会同时改变两个组。 这以一种防止独立对待每个组的方式将决策结合起来。 

约束足够严格，以至于$O(n^2)$扫描所有边界对是临界的，但如果通过前缀计数和恒定时间评估仔细优化，仍然是可能的。 对分配元素或所有可能的目标二元三元组的所有方式进行完整组合搜索太大，因为每个测试最多可以包含$2 \cdot 10^5$元素总数。 

一个天真的但诱人的错误是假设每个组都可以根据固定分割的当前大小独立地舍入到 2 的下一个幂，而不考虑更好的分割可能会在组之间移动元素并显着减少所需的添加。 另一个常见的陷阱是忘记最初允许一组大小为零的组，但仍然必须使其非零，这已经强制至少插入一次。 

例如，如果所有元素都相等，则任何合理的拆分都会将所有元素放入一个组中，而将其他两个元素留空。 一个幼稚的解决方案可能只考虑对非空组进行舍入，而忽略了激活空组的强制成本。 

## 方法

 如果我们固定两个边界$x$和$y$，三个组的大小变得确定：我们可以计算有多少元素落在下面$x$， 之间$x$和$y$，并且大于或等于$y$。 对于每个团体规模$k$，“修复”它的成本是严格大于或等于 1 但不小于 1 本身的两个的最小幂。 具体来说，我们需要改造$k$转换成最接近的至少为 1 的 2 的幂，成本就是差值。 

蛮力方法枚举所有可能的对$(x, y)$。 自从$x$和$y$仅与数组中出现的值有关，有$O(n^2)$候选人分裂。 对于每个分组，我们计算组大小$O(n)$，导致$O(n^3)$总的复杂性，这太慢了。 

我们可以通过对数组进行排序并使用前缀计数来减少这种情况。 对于固定的$x$，第一组是前缀，对于固定的$y$，第三组是后缀。 中间的一组是有区别的。 这允许在恒定时间内计算每对的所有三种尺寸。 

关键的观察是，成本函数仅取决于组大小，并且每个组成本仅取决于其大小与下一个 2 的幂的距离。 我们可以预先计算每个可能的尺寸$n$，达到下一个二的幂的成本。 

这减少了扫描所有有效分割点的问题$O(n^2)$，这已经足够了，因为总和$n$跨测试是$2 \cdot 10^5$，因此总工作量仍然是可控的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 前缀+配对扫描|$O(n^2)$每次测试 |$O(n)$| 已接受 |

 ## 算法演练

 我们首先对数组进行排序，以便任何有效的分割都对应于选择两个索引$i < j$，其中之前的所有元素$i$重量轻，介于$i$和$j$是中量级，之后$j$都是重量级的。 

我们预先计算一个数组`cost[k]`，给出了增加团体规模所需的额外参与者数量$k$到二的下一个幂。 这是通过找到大于或等于的两个的最小幂来计算的$k$并减去$k$。 

然后我们尝试所有对$(i, j)$并计算：

 1. 轻量组的大小为$i$。 
2. 中间组的大小为$j - i$。 
3. 重量级组的规模为$n - j$。 

对于每次分割，我们计算总成本为`cost[i] + cost[j - i] + cost[n - j]`，并跟踪所有分割的最小值。 

每对代表权重到三个连续组的完整分配，并且由于排序保留顺序，因此每个有效阈值对恰好对应于一个这样的分割。 

这样做的原因是，一旦排序，唯一重要的是有多少元素落入每个区域，而不是它们是哪些特定元素。 成本函数仅取决于计数，并且分割枚举涵盖了阈值选择可能产生的所有可能的计数三元组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    # Precompute powers of two up to max n
    max_n = 2 * 10**5 + 5
    nxt = [0] * (max_n + 1)
    
    p = 1
    for i in range(1, max_n + 1):
        while p < i:
            p <<= 1
        nxt[i] = p
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        
        cost = [0] * (n + 1)
        for i in range(n + 1):
            cost[i] = nxt[i] - i
        
        ans = 10**18
        
        for i in range(n + 1):
            for j in range(i, n + 1):
                left = i
                mid = j - i
                right = n - j
                ans = min(ans, cost[left] + cost[mid] + cost[right])
        
        print(ans)

if __name__ == "__main__":
    solve()
```实现首先为所有大小的 2 的下一个幂建立一个查找表。 这避免了在嵌套循环内重复重新计算对数。 这`cost`数组在恒定时间内将组大小转换为插入成本。 

双循环结束`i`和`j`枚举将已排序数组拆分为三个连续段的所有可能方法。 边界直接对应于两个阈值$x$和$y$，因为排序确保任何阈值选择都会引起这样的分区。 

一个微妙的点是处理空段。 该循环允许`i == 0`或者`j == i`，它产生零大小的组。 成本函数通过将 0 映射到下一个 2 的幂（即 1），正确地强制这些大小变为 1。

 ## 边缘情况

 一个关键的边缘情况是当一个或两个组为空时。 对于像这样的输入`[5]`，任何阈值选择都会产生一组大小为 1 的组和两个空组。 该算法将此评估为成本`0 + 1 + 1 = 2`，正确地强制激活两个缺失的部门。 

另一种边缘情况是当组大小已经是 2 的幂时，例如`[1,1,2,2]`。 正确的分割产生尺寸`[2,2,0]`或类似的排列，非空组的成本变为零，而空组仍然有贡献。 

该算法统一处理这些情况，因为空组被视为大小为零，并通过下一个二的幂计算自动舍入为一。
