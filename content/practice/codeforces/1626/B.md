 ## 解决方案
 ## 问题理解

 我们得到一个大整数，表示为一串不带前导零的数字，并且允许我们执行一个操作：选择两个连续的数字并将它们替换为它们的总和。 如果和是个位数，则直接替换对； 如果总和是两位数字，则两位数字将替换原来的数字对。 目标是在一次操作后以产生最大可能数字的方式选择该对。 

该整数可能非常大，在所有测试用例中最多可达 200,000 位，因此任何尝试所有可能数值的解决方案都是不可行的。 输入字符串长度意味着我们的算法在位数上必须是线性的，因为任何二次方程都将采用以下顺序：$10^{10}$最坏情况下的操作，远远超出了2秒的限制。 

需要仔细处理的边缘情况包括两位数的数字（其中只有一对可能的组合）、包含零的数字，以及组合数字产生两位数和的情况。 例如，输入`90`只有一个有效操作，这将其简化为`9`。 只考虑总和本身而不考虑其位置的幼稚实现可能会错误地替换错误的对并产生较小的数字。 另一个微妙的情况是当组合中间的数字时产生两位数的和，例如`10057`，其中求和`5`和`7`产生`12`将其插入到末尾比组合前面的小数字更有利。 

## 方法

 暴力方法迭代所有相邻数字对，计算总和，并为每个选择构建结果字符串。 在检查了所有可能性之后，我们选择产生数值最大的那个。 这是有效的，因为它详尽地检查了每一个潜在的单一减少。 然而，为每一对构建每个新字符串的成本很高。 对于一个长度的字符串$n$，大约需要$O(n^2)$字符操作，这是不可接受的$n \approx 2 \cdot 10^5$。 

关键的见解是，替换**最右边的总和为 10 或更多**的数字可以保证最大的增长。 如果没有一对的总和等于 10 或更多，则组合**最左边的一对**会产生最大的数字，因为组合后面的较小数字只会减少前面的数字数量，从而减少整体值。 本质上，我们利用的是最高有效数字主导数值的属性，因此字符串后面的两位数总和可以最有效地提高该值。 这使我们能够将解决方案简化为对字符串进行一次遍历，从左到右检查对并记住最后一个产生总和至少为 10 的对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将整数读取为字符串以处理潜在的巨大值。 
2. 初始化一个变量来跟踪最右边总和至少为 10 的对的位置。 
3. 从左到右遍历字符串，检查每对连续的数字。 
4. 如果一对之和为 10 或更多，则将变量更新到此位置。 
5. 完成迭代后，检查是否找到总和≥ 10 的对。 
6. 如果存在这样的对，则将其替换为其和。 这可以添加额外的数字，这是有利的。 
7. 如果不存在这样的对，则替换**第一对**。 尽早对较小的数字求和可以最小化长度，同时保留较高的数字。 
8. 输出结果字符串。 

工作原理：该算法保持了一个不变量，即可以创建两位数替换的最大可能总和被用在最右边的位置。 如果不可能有两位数和，则选择第一对以保持最大有效数字不变。 数字的数字优势确保没有其他数字对会产生更大的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    n = len(s)
    pos = -1
    # find the rightmost pair with sum >= 10
    for i in range(n - 1):
        if int(s[i]) + int(s[i + 1]) >= 10:
            pos = i
    if pos != -1:
        # replace the rightmost pair with sum
        total = str(int(s[pos]) + int(s[pos + 1]))
        s = s[:pos] + total + s[pos + 2:]
    else:
        # replace the first pair
        total = str(int(s[0]) + int(s[1]))
        s = total + s[2:]
    print(s)
```该代码可以有效地读取输入，并且每个测试用例仅迭代字符串一次。 追踪`pos`确保我们选择最右边的一对，产生两位数的和。 如果不存在，我们就回到第一对。 请注意正确构造新字符串，避免切片时出现差一错误。
