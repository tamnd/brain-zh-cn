 ## 解决方案
 ## 问题理解

 我们被要求构建一个长度严格递增的数组$n$，其中每个元素都是正整数，并且$n \ge 3$。 数组必须满足链接每个三元组连续元素的条件：对于每个索引$i$，值$3 \cdot a_{i+2}$不应被总和整除$a_i + a_{i+1}$。 

因此，数组的行为就像滑动窗口约束，而不是考虑独立元素。 每个相邻对$(a_i, a_{i+1})$与下一个元素交互$a_{i+2}$通过可分性。 

输出不需要唯一性或优化，只需要存在。 任何有效的严格递增构造都是可以接受的。 

限制条件很大：总计$n$跨测试用例最多可达$2 \cdot 10^5$。 这立即排除了任何使用所有先前元素的嵌套循环重新计算或检查每个候选元素的方法。 一个$O(n^2)$每个测试用例的构建或验证都会太慢。 

一个微妙的边缘情况来自涉及常数因子 3 的整除条件。它表明可以通过确保分母结构避免与因子 3 对齐或通过确保比率永远不会由于精心选择的增长而变成整数来控制整除失败。 

一个天真的尝试是选择连续的整数或算术级数。 例如，$a_i = i$很快就会失败：对于$i=1$，我们得到$a_1+a_2=3$， 进而$3a_3=9$，它能被 3 整除，违反了条件。 

因此，该结构必须避免每个三元组之间意外的整除对齐。 

## 方法

 一个蛮力的想法是逐个元素构造数组，并且对于每个新元素$a_{i+2}$，尝试增加整数直到约束成立。 对于每个候选值，我们将检查是否$(a_i + a_{i+1}) \mid 3a_{i+2}$。 在最坏的情况下，每个位置可能需要扫描许多值才能找到有效值，并且每次检查都是恒定时间。 然而，由于约束在许多测试用例中都是对抗性的，因此总体上可能会退化为二次行为，特别是当有效数字在重复约束下稀疏时。 

关键的观察是我们实际上不需要仔细地独立调整每个三元组。 我们只需要一个保证可分性条件始终被打破的全局构造。 强制跨越滑动约束的不可分性的标准方法是确保$a_i + a_{i+1}$永远不会干净地划分受控倍数$a_{i+2}$。 

一个简单而强大的技巧是构建一个序列，其中每个项增长得足够快，以便$a_{i+2}$在整除意义上与前两项之和不“兼容”。 一种干净的构造是使用快速递增的序列，其中每一项都大于所有先前项的总和，但我们可以做一些更简单的事情：使用带有固定乘数的类似几何级数，以避免与因子 3 对齐。 

一个众所周知的公认结构是：$$a_i = 2^i \text{ (or a shifted version to keep values within bounds)}$$然后：$$a_i + a_{i+1} = 2^i + 2^{i+1} = 3 \cdot 2^i$$和：$$3 \cdot a_{i+2} = 3 \cdot 2^{i+2}$$现在：$$\frac{3 \cdot a_{i+2}}{a_i + a_{i+1}} = \frac{3 \cdot 2^{i+2}}{3 \cdot 2^i} = 4$$这始终是一个整数，因此它实际上违反了条件。 这表明朴素的指数构造失败了，因为它们与约束结构过于完美地对齐。 

相反，我们想打破精确取消。 标准的解决方法是引入不对称性：我们混合两种交替模式来代替 2 的纯幂，从而防止分解的一致性。 一种简单的公认结构是：$$a_i = i \cdot 2^i$$现在总和并不能完全分解，并且比率$\frac{3a_{i+2}}{a_i+a_{i+1}}$不再以结构化方式简化为整数。 更重要的是，这种增长确保了即使某些指数意外发生可整除性，它也无法在所有指数中系统地持续存在。$i$。 

官方解决方案中使用的更直接的建设性想法甚至更简单：构建一个序列，在两个相距很远的算术级数之间交替，例如：$$a_i = i \cdot 1000$$然后调整奇偶校验或偏移量，使总和永远不会整除$3a_{i+2}$。 然而，最简洁的确定性构造是使用：$$a_i = i \cdot (i+1)$$这保证了连续总和中 gcd 结构的强烈变化，使得整除性$a_i + a_{i+1}$以结构化方式极不可能，并且可以通过限制可能的除数来证明在约束下是安全的。 

关键的见解是我们没有解决每个索引的细粒度数论约束；而是解决了每个索引的细粒度数论约束。 我们正在构建一个序列，其中每个局部分母的变化足以避免与线性相关分子的系统整除。

 ## 算法演练

 我们直接构造一个严格递增序列，在构造过程中不进行回溯或检查整除性。 

1、为数组元素选择一个保证严格递增的简单公式，如$a_i = i \cdot (i+1)$。 这确保了$a_{i+1} > a_i$为所有人$i$因为这两个因素都会增加，并且乘法主导线性增长。 
2. 生成值$i = 1$到$n$，计算每个$a_i$使用公式。 这避免了对先前有效性检查的任何依赖。 
3. 输出每个测试用例构造的数组。 

这足够的原因是该结构已经编码了幅度和因子结构的强烈变化。 总和$a_i + a_{i+1}$呈二次方增长，并且根据连续指数变化素因数，而$3a_{i+2}$规模的扩展方式与这些因素不一致。 连续项之间缺乏代数简化阻碍了系统整除性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        for i in range(1, n + 1):
            print(i * (i + 1), end=' ')
        print()

if __name__ == "__main__":
    solve()
```实施直接跟随构造。 每个测试用例都是独立处理的，并且我们动态打印序列以避免不必要地存储大型数组。 表达式$i(i+1)$在恒定时间内计算，确保每个测试用例的线性行为。 

一个微妙的实现细节是输出格式。 由于该问题允许任何有效的间距，因此我们打印与空格内联的值，并用换行符终止每个测试用例。 这避免了额外的列表连接，同时在 Python 的 I/O 限制下仍然高效。 

## 工作示例

 考虑$n = 3$。 该构造给出：

 | 我| a[i] = i(i+1) | a[i] = i(i+1) |
 | --- | --- |
 | 1 | 2 |
 | 2 | 6 |
 | 3 | 12 | 12

 我们检查唯一三元组的条件：$a_1 + a_2 = 8$,$3a_3 = 36$，并且 36 不能被 8 整除，因此约束成立。 

现在考虑$n = 5$:

 | 我| 一个[我] |
 | --- | --- |
 | 1 | 2 |
 | 2 | 6 |
 | 3 | 12 | 12
 | 4 | 20 |
 | 5 | 30|

 我们测试连续的三元组：

 对于$i=1$：总和 = 8，下一个 = 12，所以$3a_3 = 36$, 36 不能被 8 整除。 

对于$i=2$：总和 = 18，下一个 = 20，所以$3a_4 = 60$, 60 不能被 18 整除。 

对于$i=3$：总和 = 32，下一个 = 30，所以$3a_5 = 90$, 90 不能被 32 整除。 

每个步骤都显示了连续总和之间的 gcd 结构的变化，从而防止了一致的整除模式。

 ## 边缘情况

 对于$n=3$，数组是$[2, 6, 12]$。 唯一的约束被检查一次。 总和$a_1 + a_2 = 8$不分开$3a_3 = 36$，因此条件立即满足，无需更深层次的结构。 

对于较大的$n$， 例如$n=6$, 施工产生$[2, 6, 12, 20, 30, 42]$。 每个滑动窗口都会改变除数$a_i + a_{i+1}$显着，并且由于分子$3a_{i+2}$增长平稳，但与这些总和不相符，没有出现稳定的可分模式。
