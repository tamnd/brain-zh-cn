 ## 解决方案
 ## 问题理解

 我们有一排人，每个人要么面向左，要么面向右。 一个人的贡献取决于有多少人在他所看的方向上撒谎。 面朝右的人只贡献其右侧的人数，而面朝左的人则贡献严格其左侧的人数。 该行的总价值是这些贡献的总和。 

该任务不是单个优化，而是一系列优化。 对于每个整数$k$从 1 到$n$，我们最多可以翻转方向$k$人，我们希望这样做后能获得最大可能的总价值。 

关键的困难在于，单次翻转会以两种相反的方式影响贡献：一个人从贡献“线的一侧”变为贡献另一侧，而这种变化取决于他们的位置。 这立即表明，翻转一个人的好处是依赖于位置的，而独立的翻转可以按有用性排序。 

约束条件意味着$n$可以达到$2 \cdot 10^5$跨所有测试用例，因此尝试所有子集或重新计算每个子集的完整值的任何解决方案$k$会太慢。 一个幼稚的方法将涉及$O(n^2)$或者每个测试用例的行为更差，这在 2 秒限制下是不可接受的。 

当所有有益的翻转都已被使用时，就会出现微妙的边缘情况。 例如，如果字符串在一个方向上已经是最佳的，则额外的翻转不应增加答案，这意味着在某个前缀后输出必须变得恒定$k$。 每个幼稚的重新计算$k$可能会错误地不断更改或重新计算贡献，而不是识别饱和度。 

## 方法

 暴力策略将模拟最多的每一种可能的选择$k$翻转。 对于每个$k$，我们可以尝试所有大小的子集$k$，翻转这些位置，重新计算全部贡献$O(n)$，并取最大值。 即使限制于选择最佳子集，这仍然需要评估其计数为指数的组合，甚至需要尝试每个候选集的简化版本$k$导致$O(n^2)$或者更糟。 

关键的观察是，翻转一个人的效果可以独立于其他翻转进行量化。 如果我们固定一个位置$i$，其贡献取决于方向及其与端点的距离。 当我们翻转一个角色时，我们将其贡献替换为对面的贡献，因此净收益是一个固定值，仅取决于$i$及其目前的方向。 

这将问题简化为计算基线值以及翻转每个位置的潜在收益列表。 如果翻转的话，每个位置都会带来积极或消极的改进，我们希望了解$k$每个前缀的最佳改进$k$。 按降序对这些收益进行排序可以立即给出最佳的改进顺序。 

唯一剩下的微妙之处是有效地计算收益。 对于一个职位$i$，如果是“L”，则当前贡献$i$（0 索引贡献$i$或 0-索引调整），并将其翻转为“R”给出贡献$n-1-i$。 增益为$(n-1-i) - i$。 如果是“R”，则增益为$i - (n-1-i)$。 计算完所有增益后，我们对它们进行排序并构建前缀和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) 到 O(n^3) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算没有任何翻转的字符串的初始贡献。 每个位置的贡献取决于其方向以及到相关边的距离。 这给出了我们稍后将调整的固定基线。 
2. 对于每个位置$i$，计算如果我们翻转它，总价值会发生多少变化。 这是其作为“L”和“R”的贡献之间的差异。 这隔离了每个可能操作的好处。 
3. 将所有计算的增益存储在列表中。 每个增益代表一个独立的操作选择，选择翻转正好对应于获取该增益。 
4. 按降序排列收益，以便首先考虑最有利可图的翻转。 这种排序确保对于任何$k$，尺寸的最佳子集$k$始终是此排序列表的前缀。 
5. 在排序后的增益上构建前缀和数组。 这$k$-th前缀总和表示通过翻转最佳获得的总改进$k$职位。 
6. 对于每个$k$，输出基线加上前缀总和$k$，利用我们最多可以选择的事实$k$翻转，所以我们最多采用尺寸的最佳可用子集$k$。 

### 为什么它有效

 每次翻转都是独立的，因为它的贡献变化不依赖于其他翻转。 一旦我们将问题转化为收益，目标就变成了选择最多$k$具有最大总和的元素。 排序确保任何最佳选择都必须包含最大的可用增益，因为用较大的未使用增益替换所选的较小增益总是会改善或保持总数。 这个交换参数保证了贪婪排序的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        gains = []
        base = 0
        
        for i, ch in enumerate(s):
            if ch == 'L':
                base += i
                gains.append((n - 1 - i) - i)
            else:
                base += (n - 1 - i)
                gains.append(i - (n - 1 - i))
        
        gains.sort(reverse=True)
        
        pref = 0
        res = []
        
        for k in range(n):
            if k < len(gains):
                if gains[k] > 0:
                    pref += gains[k]
            if k < len(gains) and gains[k] <= 0:
                # once gains become non-positive, adding more won't help
                pass
            res.append(str(base + pref))
        
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码首先计算假设没有翻转的基线贡献。 然后，它构建一个增益数组，表示每个索引在翻转时对答案的改善程度。 排序确保我们始终首先考虑最好的翻转。 前缀累积为每个允许的翻转次数构建了可实现的最佳改进。 

一个微妙的点是我们仍然计算所有的值$k$，即使收益变为负值。 这些负值自然会在正确的实现中停止被选择，因为排序增益上的前缀和仅在必要时才会包含它们。

 ## 边缘情况

 一个关键的边缘情况是所有翻转最终都会变得有害。 对于像这样的字符串`RRRRR`，翻转任何角色都会减少贡献。 在这种情况下，所有收益都是负的。 该算法仍然对它们进行排序，但只有前几个（如果有正数）用于前缀和，因此每个$k$产生相同的基线值。 

另一种情况是交替模式，例如`LRLRLR`。 这里的收益根据位置在正负之间交替。 排序可确保首先采用所有强正改进，即使它们相距很远，并防止局部贪婪决策锁定次优翻转。 

最后一个微妙的情况是多个增益相等时。 排序使它们可以互换，并且前缀和保持稳定，因为相等增益的任何排序都会产生相同的累积值。
