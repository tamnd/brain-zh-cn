 ## 解决方案
 ## 问题理解

 在每个测试用例中，我们都会得到一个短字符串，我们需要决定是否可以将其解释为在非常具体的拼写规则下对名称“Timur”的重新排列。 

规则不仅仅是字母匹配。 该字符串必须恰好使用“Timur”中出现的五个字母，具有相同的重数，并且大写结构也必须匹配：字母 T 必须恰好出现一次并且必须是大写的，而其余字母必须是小写字母 i、m、u 和 r，每个字母都恰好出现一次。 

因此，每个测试用例本质上都是询问输入字符串是否是具有固定用例约束的多重集 {T, i, m, u, r} 的有效排列。 

输入大小极小，每个字符串最多 10 个字符，最多 1000 个测试用例。 这立即意味着任何解决方案，即使是简单的每次测试扫描或比较也很容易足够快。 不需要高级数据结构或预处理，因为即使每个测试用例进行 O(10) 检查也是微不足道的。 

主要的微妙之处在于区分大小写和精确匹配。 这里会出现一些常见的错误。 一是忘记了大写字母的重要性，因此即使字母匹配，“timur”也应该失败。 另一种是允许重复的字母，例如“Timuur”，这会引入重复并打破排列要求。 第三种是接受字母正确但长度不正确的字符串，例如“Timr”，它缺少一个字符，应立即拒绝。 

## 方法

 思考该问题的一种强力方法是生成字符串“Timur”的所有排列，并检查输入字符串是否与其中任何一个匹配。 由于该名称有 5 个不同的字符，因此有 5 个！ = 120 种排列。 对于每个测试用例，我们可以与所有 120 个候选者进行比较。 这是可行的，但这是不必要的矫枉过正，并且隐藏了问题的结构。 

如果我们注意到“有效拼写”只是一组固定的五个字符串的成员资格，那么结构就会变得更加清晰。 每个有效答案必须恰好包含固定大小写的每个必需字符之一。 我们可以直接比较输入的排序或频率表示是否与参考模式匹配，而不是生成排列。 

一个更简单的观点是将正确答案视为具有约束的多重集。 我们检查长度是否正好为 5，然后验证每个所需字符是否恰好出现一次且大小写正确。 这将问题减少到每个测试用例的恒定时间检查。 

关键的见解是我们不是在寻找安排；而是在寻找安排。 我们正在验证与具有大小写约束的固定多重集的相等性。

 ## 算法演练

 1. 将名称的准确有效结构预定义为频率图：1 个“T”、1 个“i”、1 个“m”、1 个“u”和1 个“r”。 这充当我们的目标签名。 
2. 对于每个测试用例，首先检查字符串的长度。 如果不是 5，我们可以立即拒绝它，因为有效的拼写必须恰好使用五个字母。 
3. 为输入字符串中的字符构建频率计数器。 由于字符串很小，因此简单的字典或直接计数就足够了。 
4. 将此频率图与目标进行比较。 每个必需的字符必须恰好出现一次，并且不允许出现多余的字符。 
5. 如果所有条件都满足，则输出“YES”； 否则输出“NO”。 

这种排序很重要的原因是效率和正确性、清晰度。 长度检查会立即消除许多无效情况，并确保我们不会意外接受仍包含所有必需字母的重复字符的字符串。

### 为什么它有效

 该算法依赖于名称的有效拼写与固定多组字符的排列完全对应的不变式。 当且仅当两个字符串共享相同的字符频率时，它们才是彼此的排列。 由于区分大小写的要求直接嵌入到多重集定义中，因此频率比较完全捕获了问题的所有约束。 字符串的其他结构属性并不重要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

TARGET = {'T': 1, 'i': 1, 'm': 1, 'u': 1, 'r': 1}

def ok(s: str) -> bool:
    if len(s) != 5:
        return False
    cnt = {}
    for c in s:
        cnt[c] = cnt.get(c, 0) + 1
    return cnt == TARGET

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        print("YES" if ok(s) else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先修复有效名称的预期频率字典。 每个测试用例都是独立处理的，我们忽略提供的长度`n`除了作为一致性检查之外，因为实际的字符串长度是直接测量的。 

频率比较是精确的，因此任何偏差（例如大小写错误、字母丢失或字符重复）都会立即失败。 

一个微妙的实现细节是使用`strip()`读取字符串时。 这可以防止换行符干扰比较，这是竞赛设置中隐藏错误的常见来源。

 ## 边缘情况

 常见的边缘情况是所有必需的字母都存在但大小写错误，例如“timur”。 频率图在结构上匹配，但在精确的键上不匹配，因为小写“t”不是所需的大写“T”。 该算法正确地拒绝了这一点，因为字典相等区分大小写。 

另一个边缘情况是重复的字母，如“Timuur”。 如果其他地方缺少另一个字母，长度可能仍然是 5，但频率比较会立即暴露出不平衡的情况。 “u”的计数变为 2，这与目标的精确匹配失败。 

最后一种边缘情况是包含额外字符的字符串，例如“Timurx”。 即使前五个字母有效，附加字符也会破坏长度条件和频率相等性。 该算法在长度检查阶段拒绝它，防止不必要的计算。
