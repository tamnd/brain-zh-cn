 ## 解决方案
 ## 问题理解

 我们得到了一组轴对齐的矩形，每个矩形都由其高度和宽度定义。 对于每个查询，我们还给出两个边界矩形：一个“小内部约束”矩形和一个“大外部约束”矩形。 

对于带参数的查询$(h_s, w_s, h_b, w_b)$，我们必须只考虑那些矩形$(h_i, w_i)$使得矩形在两个维度上都严格大于小约束，并且在两个维度上严格小于大约束。 在这些有效的矩形中，我们将它们的面积相加$h_i \cdot w_i$。 

因此，每个查询都要求对矩形进行 2D 范围过滤器，然后对其区域进行聚合。 

关键的难点是两者$n$和$q$可以大到$10^5$，并且最多有 100 个测试用例。 这立即排除了任何检查每个查询的每个矩形的解决方案，因为这将需要最多$10^{10}$最坏情况下的操作。 

附加的结构约束很重要：高度和宽度都以 1000 为界。这意味着即使矩形的数量很大，坐标空间也很小且离散。 这强烈表明在固定网格上进行预计算。 

一个天真的但微妙的错误是尝试对矩形进行排序并独立地根据高度和宽度进行二分搜索。 这种方法会失败，因为约束是不可分离的：矩形可能满足高度条件但不满足宽度条件，反之亦然。 例如，一个矩形$h=10, w=1$另一个与$h=1, w=10$两者都通过一维滤波器，但不通过组合的二维滤波器。 任何在没有连接结构的情况下独立处理尺寸的方法都会产生不正确的结果。 

另一个边缘情况是相等处理。 由于需要严格的不平等，因此高度等于的矩形$h_s$或者$h_b$必须排除。 一个常见的错误是意外地将其转换为包含边界，尤其是在转换为前缀和时。 

## 方法

 暴力方法很简单：对于每个查询，迭代所有矩形并检查高度和宽度是否严格位于查询范围内。 如果是这样，请将其面积添加到答案中。 这是正确的，因为它直接遵循有效性的定义。 

然而，这需要花费$O(n)$每个查询，导致$O(nq)$全面的。 和$n = q = 10^5$，这变得太大了。 

关键的观察结果是矩形尺寸很小。 高度和宽度都位于$[1, 1000]$，这仅给出$10^6$可能的对。 我们可以将矩形聚合成二维频率表，而不是将它们视为非结构化列表。 

一旦我们这样做了，每个查询就变成了二维网格上的矩形和查询。 这是一个经典的前缀和问题：如果我们预先计算总面积贡献的二维前缀和，则可以使用包含-排除在恒定时间内回答每个查询。 

这个想法是为每个单元格存储$(h, w)$，所有具有该尺寸的矩形贡献的总面积。 然后在这个网格上构建一个 2D 前缀和，以便我们可以在 O(1) 内查询任意矩形区域的和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | 二维前缀和 |$O(n + 1000^2 + q)$|$O(1000^2)$| 已接受 |

 ## 算法演练

 我们利用高度和宽度以 1000 为界的事实，因此我们构建了一个固定网格。 

1. 初始化一个2D数组`grid[h][w]`大小为 1001 × 1001，带零。 每个条目将累积具有确切高度和宽度的矩形所贡献的总面积。 这会将输入列表转换为小域上的结构化频率图。 
2. 对于每个矩形$(h_i, w_i)$， 添加$h_i \cdot w_i$到`grid[h_i][w_i]`。 此步骤将所有相同的矩形压缩为单个贡献，从而准确地保留总面积。 
3. 构建二维前缀和数组`pref`，其中每个单元格存储矩形中所有值的总和$[1..h][1..w]$。 这是使用网格上的标准包含-排除递归来完成的。 这样做的原因是任何矩形查询都可以分解为重叠的前缀区域。 
4. 对于每个查询$(h_s, w_s, h_b, w_b)$，计算严格矩形上的总和：$$(h_s, h_b) \times (w_s, w_b)$$通过将严格的不等式转换为包含前缀索引：$$h \in [h_s+1, h_b-1], \quad w \in [w_s+1, w_b-1]$$5. 使用前缀和表上的包含-排除公式回答查询。 这给出了每个查询在恒定时间内所有有效矩形的总面积。 

重要的结构决策是，我们不是查询矩形列表，而是查询压缩网格，其中每个坐标代表一个维度对。 

### 为什么它有效

 正确性取决于两个不变量。 首先，每个矩形对其相应的网格单元只贡献一次，因此在压缩过程中不会丢失任何信息。 其次，前缀和变换保留了轴对齐子矩形上的精确和。 由于每个查询条件恰好是经过严格边界平移后的高宽网格中的一个矩形区域，因此包含所有有效矩形并排除所有无效矩形。 不会发生重叠或缺失的情况，因为查询条件和网格子区域之间的转换是双射的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX = 1000

def solve():
    n, q = map(int, input().split())
    
    grid = [[0] * (MAX + 1) for _ in range(MAX + 1)]
    
    for _ in range(n):
        h, w = map(int, input().split())
        grid[h][w] += h * w
    
    pref = [[0] * (MAX + 1) for _ in range(MAX + 1)]
    
    for h in range(1, MAX + 1):
        row_sum = 0
        for w in range(1, MAX + 1):
            row_sum += grid[h][w]
            pref[h][w] = pref[h - 1][w] + row_sum
    
    def get(h1, w1, h2, w2):
        if h1 > h2 or w1 > w2:
            return 0
        return (
            pref[h2][w2]
            - pref[h1 - 1][w2]
            - pref[h2][w1 - 1]
            + pref[h1 - 1][w1 - 1]
        )
    
    out = []
    for _ in range(q):
        hs, ws, hb, wb = map(int, input().split())
        h1, h2 = hs + 1, hb - 1
        w1, w2 = ws + 1, wb - 1
        out.append(str(get(h1, w1, h2, w2)))
    
    print("\n".join(out))

t = int(input())
for _ in range(t):
    solve()
```该解决方案首先将所有矩形压缩到按高度和宽度索引的固定网格中。 这避免了在查询期间处理单独的矩形。 

前缀和构造是逐行完成的，以确保每个单元累积来自左上角子矩阵的所有贡献。 中间体`row_sum`变量对于避免重复重新计算水平总和是必要的，否则会不必要地添加额外的因子 1000。 

查询函数会仔细处理无效范围，其中严格约束会崩溃为空区间。 这可以防止负索引错误并确保边界的正确性。 

在应用前缀和公式之前，每个查询都会从严格的不等式转换为包含边界。

 ### 示例 1

 输入：```

rectangles: (2,3), (3,2)
query: (1,1,3,4)
```我们构建网格：

 | h \ w | 2 | 3 |
 | --- | --- | --- |
 | 2 | 6 | 0 |
 | 3 | 0 | 6 |

 前缀和在 2D 平面上累积这些值。 该查询翻译为：$h \in [2,2], w \in [2,3]$只有单元格 (2,3) 位于该范围内，贡献了 6。 

输出：```
6
```这演示了如何将严格的不平等正确地转化为包容性网格边界。

 ## 边缘情况

 当应用严格边界后查询窗口折叠时，会出现一种微妙的情况。 例如，如果$h_b = h_s + 1$，则有效高度区间变为空。 该算法通过生成来处理这个问题$h_1 = h_s + 1$和$h_2 = h_b - 1$，这导致$h_1 > h_2$。 这`get`函数显式检查此条件并立即返回零，以防止无效的前缀和索引。 

另一种情况是矩形恰好位于查询的边界上。 由于两个不等式都是严格的，因此高度等于的矩形$h_s$或者$h_b$不得贡献。 基于网格的表示自然地确保了这一点，因为这些单元格被简单地排除在前缀范围之外$[h_s+1, h_b-1]$，因此除了索引移位之外不需要特殊处理。
