 ## 解决方案
 ## 问题理解

 每个测试用例都描述了一个小型的三人单词提交游戏。 每个玩家独立地写下相同数量的短字符串，每个字符串的长度恰好为三。 写完所有单词后，评分取决于包含每个不同单词的人数。 

仅出现在一名玩家列表中的单词是该玩家独有的，因此该玩家可获得 3 分。 恰好出现在两个玩家列表中的单词会给这两个玩家各 1 分。 出现在所有三个列表中的单词不会给任何人任何分数。 

任务是计算每个测试用例中每个玩家的最终得分。 

约束足够小，所有玩家的每个测试用例的总单词数最多为 3000。 这会立即排除每个测试用例的任何比线性或近线性处理更繁重的处理。 在嵌套循环内重复比较列表或天真地检查成员资格的方法理论上仍然会通过，但任何对所有单词进行二次计算的方法都是不必要的开销，并且如果不小心实现，则可能在 Python 中面临超时的风险。 

主要的微妙之处在于单词是在集合之间共享的，而不仅仅是在玩家之间成对比较。 一个单词可以出现在两个或三个列表中，评分取决于三组中的确切频率，而不仅仅是它是否存在于一次比较中。 一个幼稚的错误是独立计算每对玩家的重叠次数，然后重复计算或错过“全部三个”的情况。 

例如，如果一个单词出现在所有三个列表中，并且我们只进行两两比较，我们可能会错误地给所有三个玩家得分，而不是零。 另一个常见错误是更新每次出现的分数，而不是更新每个唯一单词的分数，这会破坏正确性，因为每个列表内部包含不同的单词，但全局范围内的列表之间存在重叠。 

## 方法

 暴力解决方案将处理每个玩家列表中的每个单词，并检查其他两个列表中有多少个包含该单词。 由于每个列表最多包含 n 个单词，因此对于每个单词，我们将使用作为列表扫描实现的成员资格检查来扫描最多 2n 个其他单词。 这给出了每个测试用例的最坏情况成本与 n² 成正比，并且在 t 个测试用例中，如果不进行哈希实现，它会变得太慢。 

问题的结构表明了集合并集上的频率聚合。 我们不是重复检查成员资格，而是统计每个单词出现在多少个玩家中。一旦我们知道了计数，我们就可以直接根据固定规则分配积分。 

这是有效的，因为评分仅取决于每个单词的所有者集的基数。 我们从来不需要超出这个数量的排序或成对关系。 将单词映射到 3 位存在掩码或简单的计数器的字典足以在一次传递中重建所有贡献。 

暴力破解之所以有效，是因为成员资格检查在概念上很简单，但当重复扫描主导运行时时就会失败。 每个单词独立贡献的观察使我们能够将问题简化为单次频率累积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例的 O(n²) | O(n) | 最坏情况下太慢 |
 | 最优（哈希计数）| 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例，为三个玩家构建单词的全局频率图。

1. 读取第一个玩家的所有单词并将其记录在字典中，值为 1 表示存在。 这代表到目前为止只有一位玩家贡献了这个词。 
2. 读出第二位玩家的话。 对于每个单词，如果它已经存在于字典中，则将其计数增加到 2。否则将其插入值为 1。此步骤有效地跟踪到目前为止有多少不同的玩家看过每个单词。 
3. 读取第三个玩家的单词并以类似的方式更新字典，确保每个单词的值反映三个玩家中包含该单词的数量。 最终值始终为 1、2 或 3。 
4. 将三个分数变量初始化为零，每个玩家一个。 
5. 再次迭代每个玩家的列表。 对于每个单词，使用最终频率计数：

 - 如果计数为 1，则为该玩家添加 3 分。 
- 如果计数为 2，则为该玩家添加 1 分。 
- 如果计数为 3，则加 0 分。 
6. 输出三个累加分数。 

关键思想是我们将问题分为两个阶段：首先确定全局所有权计数，然后使用这些计数在本地计算每个玩家的分数。 

### 为什么它有效

 对于每个单词，它对玩家得分的贡献仅取决于有多少玩家包含该单词，而不取决于存在哪些其他单词或它在中间检查中出现的频率。 字典准确地存储了该信息。 由于每个单词都是独立处理的，并且每个玩家只添加一次，因此最终计数是所有权集大小的精确编码。 评分是该大小的确定性函数，因此不同单词之间的交互不会影响正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        a = input().split()
        b = input().split()
        c = input().split()

        cnt = {}

        for w in a:
            cnt[w] = 1
        for w in b:
            if w in cnt:
                cnt[w] = 2
            else:
                cnt[w] = 1
        for w in c:
            if w in cnt:
                cnt[w] = 3
            else:
                cnt[w] = 1

        res = [0, 0, 0]

        for w in a:
            if cnt[w] == 1:
                res[0] += 3
            elif cnt[w] == 2:
                res[0] += 1

        for w in b:
            if cnt[w] == 1:
                res[1] += 3
            elif cnt[w] == 2:
                res[1] += 1

        for w in c:
            if cnt[w] == 1:
                res[2] += 3
            elif cnt[w] == 2:
                res[2] += 1

        print(*res)

if __name__ == "__main__":
    solve()
```该实现首先构建一个字典，记录有多少个不同的玩家包含每个单词。 这是通过三轮连续传递完成的，每个玩家一次，根据玩家之间的重复出现将存储的计数从 1 更新到 2 再到 3。 

评分阶段是分开的，以避免计数逻辑与评分逻辑混合。 再次遍历每个玩家的列表，预先计算的频率决定了确切的分数贡献。 这种分离可以防止中间更新可能导致计数失真的错误。 

一个微妙的一点是，一旦设置，我们就不会减少或重新计算计数。 由于每个玩家最多贡献一次每个单词，因此按递增顺序覆盖计数是安全的并保证正确性。

 ## 边缘情况

 关键的边缘情况是一个单词出现在所有三个列表中。 该算法分配计数 3，因此每个玩家都会看到`cnt[w] == 3`并且没有任何贡献。 例如：

 输入：```
1
1
abc
abc
abc
```字典的演变是`abc=1`， 然后`abc=2`， 然后`abc=3`。 计分时，每位玩家检查单词并发现计数为 3，因此不加分。 输出是`0 0 0`，匹配规则。 

另一种情况是，单词被恰好分配给两个玩家，但组合不同。 字典仍然正确编码`cnt[w] == 2`无论哪对拥有它，因此两个拥有者都会获得 1 分，而第三个拥有者则不会获得任何积分。 这表明配对身份无关紧要，只有频率才重要，这正是算法所保留的。
