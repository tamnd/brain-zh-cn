 ## 解决方案
 ## 问题理解

 我们得到一个非常小的网格，只有两个水平条和一些垂直列。 每个单元格包含三种颜色中的一种，但观察者以特定方式存在色盲：绿色和蓝色无法区分，而红色与两者都不同。 

任务是确定逐列比较时，对于色盲观察者来说，这两行是否看起来相同。 换句话说，在应用将绿色和蓝色合并为单一感知颜色的规则后，我们检查每列在两行中是否具有相同的感知颜色对。 

每个测试用例都是独立的，我们多次重复这种比较。 

约束很小：最多 100 个测试用例，每个测试用例最多 100 列。 这立即排除了对线性扫描之外的高级数据结构或优化的任何需求。 在实践中，即使每个测试的 O(n²) 也是可以接受的，但该结构强烈建议每个测试解决方案的 O(n) 。 

关键的微妙之处在于理解“无法区分绿色和蓝色”的真正含义。 这并不意味着它们变红，也不意味着它们消失。 这意味着它们会分解成一个等价类。 任何比较都必须尊重这种等同性。 

一个常见的错误是将字符串视为直接可比较而不进行转换。 例如，比较`G`和`B`因为不同的角色会错误地拒绝应该被视为相等的情况。 

另一个潜在的陷阱是尝试仅比较每个字符的计数。 但这会失败，因为位置很重要。 例如，`RGB`与`BRG`具有相同的多组字符，但即使在色盲映射下也明显不同。 

边缘案例虽然很少，但很有启发性。 

一种情况是两行完全由绿色和蓝色组成，例如：```
GBG
BGB
```这些在色盲规则下都是等效的，因此如果映射后位置对齐，它们应该匹配。 对于不匹配的安排，基于频率的简单解决方案可能会错误地回答“是”。 

另一种情况是单列网格：```
G
B
```它们必须被视为相同，因为两者都映射到相同的感知颜色。 

## 方法

 暴力破解的想法很简单：显式地模拟两行的色盲转换，然后比较结果字符串。 对于每个单元格，我们将绿色和蓝色映射到共享符号，例如`X`，而红色仍然存在`R`。 转换后，我们逐个字符地比较两个结果字符串。 

这是有效的，因为它将问题简化为标准字符串相等性检查。 成本与每个测试用例的列数成线性关系，并且由于网格只有两行，因此没有额外的开销。 

如果我们尝试更复杂的事情，例如跟踪转换或匹配模式，我们就会过度设计一个本质上是标准化和比较任务的问题。 

在这种情况下，暴力破解已经是最佳选择。 关键的观察是，唯一有意义的转换是每个字符的恒定时间映射。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 无需标准化即可直接比较 | 每次测试 O(n) | O(1) | O(1) | 错误|
 | 标准化然后比较 | 每次测试 O(n) | O(n)（或 O(1) 流）| 已接受 |

 ## 算法演练

 1. 读取测试用例的数量，因为每个网格都是独立的，必须单独评估。 
2. 对于每个测试用例，读取整数 n 和代表行的两个字符串。 
3. 从 0 到 n - 1 迭代每个列索引。 
4. 对于每一列，使用相同的规则转换两个字符：treat`G`和`B`等价地，同时保持`R`清楚的。 一个方便的实现是映射两者`G`和`B`相同的符号，例如`0`，和地图`R`到`1`。 
5. 比较每一列中转换后的字符。 如果转换后任何列不同，请立即得出结论：对于色盲观察者来说，这些行不相同。 
6. 如果转换后所有列都匹配，则得出行相同的结论。 

第 5 步中的提前退出很重要，因为任何列中的不匹配都完全决定了答案。 一旦发现差异，无需继续扫描。 

### 为什么它有效

 该算法依赖于这样一个事实：观察者定义了颜色的等价关系，其中`G ≡ B`和`R`与两者不同。 因此，感知行的相等性相当于在逐点应用的等价映射下它们的图像的相等性。 由于映射独立应用于每个单元格并且比较是位置性的，因此逐列保留相等性可以保证全行比较的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def norm(c):
    # map green and blue to same class
    return 0 if c != 'R' else 1

t = int(input())
for _ in range(t):
    n = int(input())
    a = input().strip()
    b = input().strip()

    ok = True
    for i in range(n):
        if norm(a[i]) != norm(b[i]):
            ok = False
            break

    print("YES" if ok else "NO")
```该解决方案独立读取每个测试用例并一次性处理两行。 辅助函数`norm`在每个字符的一个常量时间操作中对整个色盲规则进行编码。 当发现不匹配时，循环立即终止，即使在最坏情况的输入中也能确保最佳行为。 

一个常见的实现错误是忘记从输入字符串中去除换行符，这可能会悄悄地改变索引逻辑。 另一种尝试直接比较原始字符，这特别失败`G`相对`B`。

 ## 边缘情况

 单列网格是最简单的情况。 该算法仅比较一对字符，如果两者属于同一等价类，则返回 YES。 例如，`G`与`B`映射到相同的标准化值，因此结果是正确的。 

完全同质的网格，例如所有`R`两行中的处理都没有任何特殊逻辑。 每次比较的结果都相等，因此循环完成时不会触发提前退出。 

仅绿色和蓝色值混合在不同模式中的情况强调了位置比较的重要性。 该算法正确地拒绝不匹配的排序，因为它不依赖于计数，仅依赖于标准化后对齐的相等性。 

最后一个微妙的情况是确保输入修剪正确。 如果不删除换行符，比较可能会意外涉及`\n`，这会破坏相等性检查。 这`.strip()`调用可确保这种情况不会发生。
