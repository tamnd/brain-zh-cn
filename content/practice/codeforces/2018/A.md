 ## 解决方案
 ## 问题理解

 我们被赋予了多个独立的场景。 在每个卡片中，我们都从一组多张卡片开始，其中每个整数值来自$1$到$n$出现一定次数。 我们最多可以添加$k$我们选择的任何价值的额外卡。 之后，我们必须将所有卡牌分成几个组，使每个组的大小相同，并且没有组包含两张具有相同值的卡牌。 

目标是在最佳地决定购买哪些卡以及如何划分所有内容后，最大化每个组的大小。 

约束条件$n \le 2 \cdot 10^5$跨越所有测试用例并且非常大$k$最多$10^{16}$排除任何尝试模拟分区或显式构造组的解决方案。 输出仅取决于全局频率结构，因此解决方案必须将问题减少到每个候选答案的少量数字检查。 

当许多值的计数为零或非常小时，就会出现微妙的边缘情况。 例如，如果所有$a_i = 0$除了一个值，那么如果不进行购买，我们就无法形成任何大小大于的有效组$1$。 试图“在本地填充缺失类型”的天真贪婪方法在这里失败了，因为组大小的全局一致性是真正的约束，而不是本地可用性。 

另一个失败案例是当$k$非常大。 人们很容易假设我们总是可以使所有频率相等，从而达到群体规模$n$，但每张额外的卡只会增加总容量，而“每组每个值最多一张”的限制仍然限制了每组每个值可以使用的数量。 

## 方法

 直接的暴力方法会尝试所有可能的最终组大小$L$。 对于固定的$L$，我们会尝试决定是否可以将卡片分成大小相等的组$L$这样每个值在每组中最多出现一次，可能是在购买卡片之后。 这需要推理我们可以形成多少个群体以及购买如何在价值之间分配。 甚至检查单个$L$需要模拟赤字如何分布，并迭代所有$L$最多卡的总数使得这完全不可行。 

关键的观察结果是，有效分区的结构仅取决于每个值相对于候选组大小的计数$L$。 对于固定的$L$, 每个值贡献最大$\lfloor a_i / L \rfloor$跨组的完整“垂直列”，剩余的余数控制我们必须购买多少张附加卡才能完成有效的分组约束。 可行性条件变得单调$L$，允许二分查找。 

一旦我们修好$L$，我们计算我们已经可以形成多少个完整的组，以及需要多少张额外的卡片来确保每个组避免重复。 如果需要购买的卡片数量最多为$k$， 然后$L$是可行的。 

这将问题转化为单调的可行性检查$L$。

 ## 算法演练

 我们二分查找答案$L$，每副牌的目标大小。 

对于固定的$L$，我们模拟每个值可以在牌组中贡献多少个完整槽位，方法是$a_i \bmod L$作为需要通过购买补偿的剩余产能。 

我们汇总这些剩余的卡片，以确定需要多少张额外的卡片，以便在不违反“每副牌不重复”约束的情况下填充每副牌。 所需购买数量不得超过$k$。 

步骤是：

 1. 设置搜索范围$L$从$1$到$\sum a_i + k$。 
2. 对于候选人$L$，计算我们必须有效添加多少张卡片，以便每个残基类别可以打包成完整的大小组$L$。 
3. 对于每个值$a_i$, 计算$a_i \bmod L$并累计剩余需求总量。 
4. 将剩余需求转换为所需的购买卡。 
5. 如有需要采购$\le k$，值$L$是可行的。 
6. 二分查找最大可行$L$。 

关键点是每个值都独立地对可行性做出贡献，并且交互仅在总容量约束下发生，这使得检查具有附加性。 

### 为什么它有效

 对于固定的团体规模$L$，每个值的行为就像一种资源，每组最多可以填充一个插槽。 剩下的$a_i \bmod L$衡量有多少组“丢失”了该值的副本。 每份丢失的副本必须通过购买的卡进行补偿。 由于购买不受不同价值的限制，因此只有总赤字才重要。 这将可行性降低为单个不等式，使得谓词单调$L$，这保证了二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(L, a, k):
    need = 0
    for x in a:
        need += x % L
        if need > k:
            return False
    return need <= k

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 1, sum(a) + k
        ans = 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, a, k):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将可行性检查与搜索分开。 功能`can(L, a, k)`计算如果我们强制套牌大小所需的附加牌总数`L`。 当要求超过时使用提前停止`k`，这可以防止不必要的溢出并保持检查线性。 

二分查找保持了所有值的不变量`ans`都是可行的，高于当前上限的一切都是不可行的。 每个中点评估都会细化这个区间。 

一个常见的实施错误是忘记可行性取决于余数而不是原始计数。 另一种是使用楼层除法而不是模数； 这打破了对每组缺失插槽的解释。 

## 工作示例

 考虑第一个样本输入。

 | 中期评价| 2 → 3 → 2 | 通过模 | 计算 确定边界|

 为了$L=2$，剩余数量足够小，所需采购符合预算。 对于较大的$L$，分组约束变得更严格，最终不可行。 

现在考虑一种具有一个主导值的情况，例如$a = [10, 0, 0]$和小$k$。 为了$L=3$，第一个值留下余数$1$每次都积累高额赤字。 这表明，即使牌总数很大，不同类型的不平衡也直接限制了可行的组规模。 

这些痕迹表明，可行性取决于每个值在假设组中分布的均匀程度，而不仅仅是总质量。

 ## 边缘情况

 当所有$a_i$除一个值外均为零，可行性检查由单个模表达式主导，并且二分搜索仍然正确收敛，因为增加$L$减少余数直到它们变为零。 这可以防止高估。 

什么时候$k=0$，不允许购买，因此解决方案简化为找到自然划分多重集结构的最佳组大小。 该算法处理这个问题是因为可行性检查变得严格并且只有自然可分模式才能通过。 

当一个值与其他值相比非常大时，余项可确保不平衡按比例受到惩罚，从而防止组大小的错误膨胀。
