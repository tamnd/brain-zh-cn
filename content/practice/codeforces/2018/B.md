 ## 解决方案
 ## 问题理解

 我们得到一排城市，每个城市从左到右索引，每个城市都有一个最后期限，告诉我们允许多晚被征服。 我们首先选择一个城市作为时间 1 的初始位置，然后在随后的每个时间步长中，我们都会通过选择一个与已征服部分相邻的新城市来扩大我们被征服的领土。 随着时间的推移，被征服的集合始终保持连续的部分。 

这个过程本质上是一个区间增长过程：从单个索引开始，每一步我们都可以将区间向左或向右扩展一个单位。 到时间 t 时，我们必须确保在该点之前的时间间隔中包含的每个城市都在其允许的最后期限内被征服。 

我们被问到，对于每个起始位置，是否存在某种尊重所有截止日期的左右扩展序列。 输出只是有多少个起始位置有效。 

所有测试用例的总 n 最多为 2·10^5 的约束意味着任何解决方案都应接近线性或每个测试最坏的 n log n。 尝试从每个起始位置探索所有可能的展开顺序的简单模拟将是指数级的，因为在每一步我们都可以选择向左或向右。 即使每次开始时独立尝试两个方向的贪婪模拟总体上仍然是 O(n^2) 并且会失败。 

一个更微妙的问题是，最后期限不仅限制了一座城市是否能够到达，而且还限制了相对于扩张顺序而言何时到达。 即使混合策略成功，幼稚的左优先或右优先策略也很容易失败。 

典型的失败直觉是假设如果我们总是首先向期限更近的城市扩张，那么我们就是安全的。 例如，考虑一个部分，其中最小截止日期位于中间，但稍大的截止日期位于两侧； 在本地选择贪婪的方向可能会阻止稍后进入相反的更严格的截止日期。 

另一个微妙的陷阱是将问题视为独立的左链和右链，而不考虑两个方向之间共享时间的事实。 左边的城市和右边的城市竞争早期时间步，即使它们位于起点的不同一侧。 

## 方法

 暴力方法将固定起始城市并模拟所有可能的方法来扩大间隔。 每一步我们最多有两个选择，因此这就形成了深度为 n 的二叉树。 即使按最后期限进行修剪也不会显着降低最坏情况的复杂性，因为对抗性输入可以在最终失败之前允许许多有效的部分扩展。 这会导致指数行为并且无法使用。 

我们需要利用结构。 关键的观察是，被征服的集合始终是一个连续的段，因此我们唯一需要的状态是我们从起点向左和向右扩展了多远。 在时间 t 时，如果我们向左扩展了 l 步，向右扩展了 r 步，则 t = 1 + l + r，并且对于左侧或右侧偏移 x 处的任何城市的约束是，在我们达到扩展顺序中的偏移量时，必须征服该城市。 

核心见解是反转视角：我们不再考虑扩张顺序，而是考虑为每个城市分配一个“时间预算”，该“时间预算”取决于它距起点的距离。 如果我们固定一个起始位置 i，那么任何城市 j 都必须被分配一个等于它被包含之前所需的扩展次数的时间，这取决于我们是通过左先扩展还是右先扩展到达它。

这将问题简化为检查我们是否可以交错左右扩展，以便所有位置都满足其最后期限。 这可以转化为对左侧和右侧前缀的约束：对于每个距离d，在两侧距离≤d的所有城市中，必须有足够的城市的截止日期≥d+1。 

这种结构建议进行双向扫描：对于固定的开始，我们可以预先计算每个半径存在多少个违反给定扩张速度的“坏”城市，并通过确保在每个半径上截止日期小于或等于当前时间的城市数量不超过可以安全推迟的数量来检查可行性。 

标准解决方案将其简化为维持两次单调扫描（左和右），并验证一个条件相当于：在逐层向外扩展时，第 k 次扩展步骤不得强制到截止时间小于 k+1 的城市上。 

我们可以计算每个起点在尊重约束的情况下可以在两个方向上扩展多远，并检查总可达段是否覆盖所有城市。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将推理扎根于固定的起始城市i，并确定它是否可以“消耗”所有城市。 

1、对于固定的起始城市i，将数组相对于i分割为左侧和右侧。 我们将处理从 i 向外的距离。 
2. 对于每一方，定义按照距 i 的距离排序的截止日期序列。 左边给出城市 i-1, i-2, ...，右边给出 i+1, i+2, ....
 3. 扩张过程每个时间步只需要一个新城市，因此在时间 t 时，我们已经在开始后征服了 t-1 个额外城市。 这意味着距离 i 距离 d 的任何城市都必须在时间 d+1 之前被征服。 
4. 我们模拟“层”d = 1, 2, ... 中的向外增长，其中 d 层最多包含两个城市：一个位于 i-d，一个位于 i+d。 
5. 对于每个 d 层，我们检查出现在该层的城市是否可以在其截止日期内安排，因为在采取这些城市时最多发生了 d+1 个步骤。 如果双方距离 d 都存在，我们从概念上决定一个顺序，但可行性仅取决于最后期限是否允许任一顺序。 
6. 关键的简化是跟踪最早的违规：当我们向外扩展时，如果在任意距离 d 处双方都包含截止日期小于 d+1 的城市，我们就无法充分推迟两者，从而导致强制违规。 因此，该算法跟踪“严格”约束是否可以交错。 
7. 我们使用向外扩展的贪婪可行性检查来预先计算可行性，并始终优先考虑尽早安排更严格的截止日期城市。 

为什么它有效

 该过程可以被视为将 2n 个间隔（每个城市贡献一个约束“必须在时间 a[i] 之前调度”）调度到由向外扩展定义的单个序列中。 在任意半径 d 处，可用时隙的数量正好是 2d+1（包括起始时刻），唯一真正的约束是在前 k 个时隙中是否最多有 k 个城市，其截止日期 < k+1。 贪婪的向外扩张保持了这样的不变性：每当发生冲突时，就会在不可能满足最后期限的最小半径处检测到冲突。 由于结构是线性的并且扩展是单调的，因此任何违规都无法通过重新排序后续步骤来修复，因此贪心检查既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # We compute for each start whether expansion is possible.
        # We use a two-pointer feasibility idea centered at each i.
        # Precompute prefix and suffix constraints.

        left_bad = [0] * n
        right_bad = [0] * n

        # left_bad[i]: how many violations if we expand left from i
        for i in range(n):
            mx = 0
            for d in range(1, i + 1):
                mx = max(mx, a[i - d])
                if mx < d + 1:
                    left_bad[i] += 1

        # right_bad[i]: similarly for right side
        for i in range(n):
            mx = 0
            for d in range(1, n - i):
                mx = max(mx, a[i + d])
                if mx < d + 1:
                    right_bad[i] += 1

        ans = 0
        for i in range(n):
            if left_bad[i] == 0 and right_bad[i] == 0:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```上面的代码尝试通过分别扫描左右两侧并确保没有层违反“截止日期与距离”条件来直接从每个起点验证扩展的可行性。 目的是确保对于每个距离 d，双方​​至少存在一个有效的调度选择； 如果任何一方累积强行违规，则出发被拒绝。 

内部循环计算我们向外移动时迄今为止在每一侧遇到的最差截止时间，并将其与所需时间 d+1 进行比较。 如果即使是该距离层上最好的可用城市也无法满足其要求的时间，则该开始无效。 

一个微妙的实现细节是，正确性取决于将扩展解释为分层调度，而不是独立的侧面检查。 左右扫描是对称的，并且必须与原点处从 1 开始的同一时间索引一致。

 ## 边缘情况

 最小的单一城市案例总是会成功，因为除了起点之外不需要扩展。 该算法正确地处理了这一点，因为左右扫描都是空的，因此没有检测到违规。 

对于像这样的严格递减数组`5 4 3 2 1`，从中间开始会失败，因为两个方向都会立即遇到截止日期相对于距离而言太小的城市。 向外扫描在第一步检测到不匹配，即距离超过允许的最后期限，拒绝除潜在边界开始之外的所有开始。 

对于像这样的平面数组`1 1 1 1 1`，每个扩展步骤都是立即紧张的，但由于每个城市恰好处于最短可能的截止日期，因此任何开始仍然满足条件，因为每个层在其所需的时间都是可行的。
