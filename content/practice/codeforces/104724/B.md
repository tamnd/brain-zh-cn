 ## 解决方案
 ## 问题理解

 我们得到一个由小写字母组成的长字符串，并且允许我们重复删除任何相邻的相等字符对。 每次删除都会删除两个相邻的相同字母，然后将字符串的其余部分连接在一起。 

如果在以任意顺序应用此操作任意次数后，可以完全擦除字符串，则该字符串被认为是完全可缩减的。 

该任务不是关于单个字符串，而是关于它的所有连续子字符串。 对于每个子串，我们想知道在相同的删除规则下它是否可以完全缩减为空串，然后统计存在多少个这样的子串。 

输入大小达到 200 万个字符，这立即排除了任何尝试显式模拟每个子字符串减少的解决方案。 任何单独触及每个子串的方法都会退化为二次或三次行为，这远远超出了可行的限制。 唯一可行的方向是在线性时间内预处理字符串，并重用该结构以在恒定或接近恒定时间内回答子字符串的有效性。 

当子字符串在字符频率方面看起来平衡但由于排序限制仍然无法减少时，就会出现微妙的边缘情况。 例如，在像“abca”这样的字符串中，字母的数量并不都是偶数，所以它立即不可能。 然而，即使在像“abba”（可简化）或“abab”（不可简化）这样的情况下，简单的频率推理也会失败。 减少取决于邻接动态而不是全局计数。 

另一个重要的情况是，有效的可约子字符串在取消结构方面不连续，例如“accabccb”，其中内部取消在子字符串中级联。 在不考虑全局结构的情况下从左到右天真的贪婪删除可能无法认识到中间状态的重要性。 

## 方法

 蛮力方法很简单。 对于每个子字符串，我们使用堆栈模拟删除过程：我们从左到右扫描，推送字符，每当堆栈顶部与当前字符匹配时，我们就会弹出它。 如果堆栈最后变空，则子字符串有效。 

这个模拟是正确的，因为它直接模拟了允许的操作：删除相邻的相等字符。 然而，将此应用于每个子字符串意味着我们对每个大约 n² 子字符串重复线性扫描，在最坏的情况下导致 O(n³) 时间。 即使优化子串提取，我们仍然需要 O(n²) 堆栈模拟，这对于 n 高达 2×10⁶ 来说太慢了。 

关键的观察是堆栈过程为字符串的每个前缀定义了唯一的规范形式。 如果我们从左到右处理字符串并维护堆栈，那么每个前缀都对应于一个明确定义的简化状态。 如果我们可以比较它们引发的堆栈变换，两个子串的行为是一致的。 

我们没有重新计算归约，而是将每个前缀视为堆栈的一个状态并对该状态进行编码。 当且仅当从空堆栈开始，应用子字符串使我们回到空堆栈时，子字符串才是可约的。 这将问题转化为计算“抵消”的前缀状态对。 

我们在扫描一次字符串时存储每个中间堆栈状态。 每次到达某个位置时，我们都会将当前状态与之前看到的状态进行比较。 如果两个位置具有相同的堆栈状态，则它们之间的子串必须减少为空，因为该段的净效果是对堆栈演化的无操作。 

这将问题简化为散列和计算相等状态。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（模拟每个子串）| O(n3) | O(n) | 太慢了|
 | 使用散列前缀堆栈状态 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时维护一个执行取消规则的堆栈。 

1. 初始化一个空堆栈和一个哈希表，该哈希表计算每个堆栈状态出现的频率。 我们将空堆栈视为有效的初始状态并记录一次。 
2. 从左到右扫描字符。 对于每个字符，模拟出栈规则：如果栈非空且栈顶等于当前字符，则弹出； 否则推动角色。 

此步骤构建以当前位置结尾的前缀的简化形式。 
3. 更新堆栈后，计算整个堆栈内容的哈希值。 该哈希表示前缀的规范状态。 

重要的一点是，堆栈内容唯一地确定涉及此前缀的所有未来取消。 
4. 将这个确切的堆栈哈希值之前出现的次数添加到答案中。 之前的每个出现都对应于堆栈状态相同的起始位置，这意味着这两个位置之间的子字符串完全减少为空。 
5. 在频率表中记录当前堆栈哈希并继续。 

步骤 4 背后的原因是，如果两个前缀状态相同，则减少两个前缀所需的操作顺序是相同的。 因此，它们之间的部分对堆栈演化没有任何贡献，这意味着它是完全可以取消的。 

### 为什么它有效

 处理前缀后的堆栈状态是截至该点的所有取消行为的完整摘要。 任何子串都对应于从一种堆栈状态转换到另一种堆栈状态。 如果开始和结束状态相同，则子字符串不会引起堆栈配置的净变化，这意味着所有中间压入和弹出完全抵消。 这正是子串完全可约的条件。 

由于每个有效子串唯一对应于一对相等的状态，因此对相等的哈希值对进行计数时，所有有效子串都只计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    # stack simulation
    st = []

    # frequency of stack states
    freq = {(): 1}  # empty stack state
    cur_state = ()
    ans = 0

    for ch in s:
        if st and st[-1] == ch:
            st.pop()
        else:
            st.append(ch)

        cur_state = tuple(st)

        ans += freq.get(cur_state, 0)
        freq[cur_state] = freq.get(cur_state, 0) + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接反映了概念算法。 堆栈`st`保持减少的前缀。 每次更新它时，我们都会将其转换为不可变元组，以便它可以用作表示完整状态的字典键。 

字典`freq`计算每个堆栈配置出现的次数。 当状态重复时，之前的每个出现都会形成以当前位置结尾的有效子字符串。 

空元组用计数一初始化，因为空前缀对应于处理任何字符之前的空堆栈。 

一个微妙的点是我们存储全栈元组。 在严格的实现中，由于重复复制，在最坏的情况下这会太慢。 在优化版本中，该元组将被滚动哈希或持久结构替换，但逻辑机制保持不变。 

## 工作示例

 考虑字符串`acca`。 

我们跟踪堆栈状态和频率。 

| 步骤| 查尔 | 堆栈| 状态| 添加新子字符串 |
 | ---| ---| ---| ---| ---|
 | 0 | - | []| ()| 0 |
 | 1 | 一个 | [一] | （一）| 0 |
 | 2 | c | [一，三] | (a,c) | 0 |
 | 3 | c | [一] | （一）| 1 |
 | 4 | 一个 | []| ()| 1 |

 在第 3 步，状态`(a)`之前已经出现过，所以子串`cc`是有效的。 在第4步，我们返回到空状态，所以`acca`作为一个整体是有效的。 

现在考虑`abac`。 

| 步骤| 查尔 | 堆栈| 状态| 添加新子字符串 |
 | ---| ---| ---| ---| ---|
 | 0 | - | []| ()| 0 |
 | 1 | 一个 | [一] | （一）| 0 |
 | 2 | 乙| [a，b] | (a,b) | 0 |
 | 3 | 一个 | [a、b、a] | (a,b,a) | 0 |
 | 4 | c | [a、b、a、c] | (a,b,a,c) | 0 |

 没有状态重复，因此没有子串完全减少。 

这些痕迹表明，有效性相当于全堆栈状态的重复，而不仅仅是角色平衡。

 ## 边缘情况

 一个关键的边缘情况是取消是嵌套的而不是本地的。 例如，在`abba`，整个字符串减少，但中间状态不为空。 该算法可以正确处理此问题，因为它跟踪完整堆栈状态而不是依赖于本地对删除。 

另一种情况是具有重复相同块的字符串，例如`aaaa`。 每个在匹配奇偶校验位置开始和结束的偶数长度子串都会产生重复状态，并且基于频率的计数可以正确捕获所有这些状态，而无需显式枚举子串。
