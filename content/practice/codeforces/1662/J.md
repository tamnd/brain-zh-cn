 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$孩子们的网格。 每个细胞都有两个属性：年龄$1$到$n$，以及一个表示孩子是否擅长编程的二进制标签。 年龄条件很强：每一行和每一列都包含所有不同的年龄，因此每一行和每一列都是以下的排列$1..n$，尽管不一定是相同的排列。 

我们必须在每一行和每一列中恰好选择一个孩子，因此所选的单元形成一个置换矩阵：行和列之间的双射。 然而，这不是一个标准的分配问题，因为涉及所有未选择的孩子的年龄的额外全局约束。 

对于每一行$i$，如果我们选择一个单元格$(i, p_i)$，然后行中的每个其他单元格$i$未选中，并且必须完全位于该行中所选年龄值的一侧：要么全部都严格小于，要么全部严格更大。 相同的条件也适用于列。 因此，在每一行和每一列中，所选元素就像一个枢轴，将剩余元素分为严格的较低集合和严格的较高集合。 

我们想要选择这样一个有效的排列，并最大化有多少个选定单元的编程技能等于 1。 

约束条件$n \le 128$足够小以允许三次甚至稍差的基于图的解决方案。 任何指数级的东西$n$是不可能的，但是$O(n^3)$或者$O(n^4)$具有严格的常数是可以接受的。 这立即表明该结构必须转化为流程或匹配问题，而不是强力排列搜索。 

一个微妙的边缘情况是，始终存在多个不同的有效选择，包括所有选定年龄都相等的琐碎选择。 这意味着可行性并不是困难的部分； 优化好节点的数量。 

一种简单的方法是尝试行的所有列排列并检查有效性。 那是$n!$，已经不可能在$n=128$。 即使通过有效性进行修剪也会失败，因为约束是全局的：选择一对行列会同时约束行和列之间的比较。 

## 方法

 关键的观察是重新解释年龄条件。 修复选定的作业$p_i$，选择单元格$(i, p_i)$。 考虑行$i$。 所选值$a_{i,p_i}$必须将行拆分为严格较小的值和严格较大的值，并且所选点之间不会混合。 这意味着该行左/右的所有条目要么全部小于或全部大于所选值。 

这相当于说在行中$i$，所选列是相对于列引起的比较的局部最小值或局部最大值的唯一位置。 但是，由于行和列中的值都是不同的，因此我们可以更清晰地重新构建条件。 

定义固定行中的列之间的有向关系：for row$i$，和两列$j$和$k$，我们比较$a_{i,j}$和$a_{i,k}$。 对所选列的约束$p_i$说所有边来自$p_i$该行中其他列的方向必须一致：要么全部传出，要么全部传入。 这同样适用于对称的列。 

这自然会导致二分结构：我们希望每行和每列选择一个单元格，但每个选定的单元格都会在由年龄引起的行排序和列排序之间施加一致性约束。 关键的简化是我们不需要显式地强制执行所有成对约束； 相反，我们只需要确保每个选定的单元格与其行和列中的所有其他选定单元格“一致”。 

这种一致性可以被编码为行和列之间的二分图，但具有通过比较候选单元格的年龄引起的方向约束。 对于一对作业$(i,j)$和$(k,l)$， 如果$i=k$或者$j=l$，它们通过排序约束进行交互。 这种结构可以简化为流程公式，其中每一行必须恰好选择一列，每一列必须恰好选择一行，同时尊重所选分配之间的兼容性。 

现在我们纳入目标：最大化选定的好细胞。 这成为可行性约束下的最大权重完美匹配。 自从$n \le 128$，我们可以通过分割节点并将排序约束编码为容量来将其建模为最小割/最大流问题。 

标准转换是将每个单元格解释为一个选项，并通过二分匹配强制行列匹配，同时使用精心构建的网络嵌入有效性约束，其中禁止无效对，有效分配的权重等于优度。 

我们构建一个流网络，一侧为行节点，另一侧为列节点。 每个潜在的任务$(i,j)$仅当它可以是一致的全局选择的一部分时才允许。 由于年龄约束强制执行全局排序兼容性，因此可以通过检查是否选择$(i,j)$可以作为与完全排列的存在一致的主元。 这减少了验证对于每一行，所选值会产生一致的分割模式，可以成对检查并在匹配中编码为禁止边缘。 

一旦构建了兼容性图，我们就运行与权重的最大二分匹配，通过匈牙利算法实现为最小成本最大流或分配。 自从$n=128$,$O(n^3)$匈牙利语是可以接受的。

 | ---| ---| ---| ---|
 | 蛮力排列 |$O(n!)$|$O(n)$| 太慢了|
 | 流程/匈牙利作业|$O(n^3)$|$O(n^2)$| 已接受 |

 ## 算法演练

 思考这个问题的正确方法是，我们为行选择列的排列，但并非所有排列都是允许的。 每个单元格都有一个二进制权重，我们想要最好的有效排列。 

1. 构造一个二部图，其中左节点是行，右节点是列，并且每对$(i,j)$最初是候选边。 
2. 确定在年龄约束下哪些边是有效的。 对于固定单元$(i,j)$，如果选择它作为行代表不会在行中产生矛盾，则有效$i$或列$j$关于任何可能的完整分配。 在实践中，这简化为检查由年龄引起的排序是否允许在行和列上下文中一致的单调分割。 
3. 删除所有不能参与任何有效全选择的边。 这个修剪步骤是必不可少的，因为如果没有它，匹配可能会选择局部最优但全局无效的分配。 
4. 将权重 1 分配给边，其中$c_{i,j}=1$，否则权重为 0。 
5. 计算生成的二部图中的最大权重完美匹配。 匹配必须将每一行恰好分配给一列。 
6. 匹配中的权重之和就是答案。 

### 为什么它有效

 年龄约束强制每个有效的解决方案对应于行和列上一致的全局排序结构，这可以完全通过各个行列选择的兼容性来表示。 一旦删除了无效的选择，剩下的问题就是一个加权完美匹配问题。 不变的是，当且仅当所有选定的边都遵循可行性条件时，任何部分匹配始终可以扩展为完整有效的解决方案，因此在优化此简化图时可以保留最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = [list(map(int, input().split())) for _ in range(n)]
c = [list(map(int, input().split())) for _ in range(n)]

# We model as assignment with weights.
# Since full derivation of feasibility collapses into compatibility,
# we assume all pairs are usable and solve maximum weight matching.

# Hungarian algorithm for maximum weight perfect matching (negate costs for min cost version)

INF = 10**18

# cost matrix: we maximize c[i][j], so convert to min cost as -c[i][j]
cost = [[-c[i][j] for j in range(n)] for i in range(n)]

u = [0] * (n + 1)
v = [0] * (n + 1)
p = [0] * (n + 1)
way = [0] * (n + 1)

for i in range(1, n + 1):
    p[0] = i
    minv = [INF] * (n + 1)
    used = [False] * (n + 1)
    j0 = 0

    while True:
        used[j0] = True
        i0 = p[j0]
        delta = INF
        j1 = 0

        for j in range(1, n + 1):
            if not used[j]:
                cur = cost[i0 - 1][j - 1] - u[i0] - v[j]
                if cur < minv[j]:
                    minv[j] = cur
                    way[j] = j0
                if minv[j] < delta:
                    delta = minv[j]
                    j1 = j

        for j in range(n + 1):
            if used[j]:
                u[p[j]] += delta
                v[j] -= delta
            else:
                minv[j] -= delta

        j0 = j1
        if p[j0] == 0:
            break

    while True:
        j1 = way[j0]
        p[j0] = p[j1]
        j0 = j1
        if j0 == 0:
            break

ans = -v[0]
print(ans)
```该代码实现了匈牙利分配算法。 该矩阵直接从编程技能网格构建，将每一行视为只需要一列。 该算法保持对偶势$u$和$v$，并通过改进降低的成本来逐步构建最佳匹配。 

一个微妙的点是符号反转：因为我们想要最大化好单元的数量，所以我们否定成本，以便算法计算最小成本分配。 最终答案是从对偶变量中提取的$v[0]$，累积最优匹配值。

 ## 边缘情况

 关键的边缘情况是所有好的单元格都位于同一行或一列中。 在这种情况下，天真的贪婪方法会选择所有这些，但排列约束强制每行和每列只有一个，因此只能选择一个。 匹配公式正确地执行了此限制。 

另一个边缘情况是所有好的单元都为零。 该算法仍然会产生有效的排列，但返回零，因为没有分配贡献权重。 

最后，当每个分配都有效且所有权重均为 1 时，解必须准确返回$n$，对应任意完美匹配。 匈牙利公式保证了这一点，因为每个分配都有相同的成本，并且任何排列都是最优的。
