 ## 解决方案
 ## 问题理解

 在足球比赛中，我们会看到一系列踢球发生的时刻，每次踢球都发生在边线的固定时间和固定位置。 在零时间，我们从位置零开始，然后允许我们以有界速度沿着线连续移动。 当每次踢球发生时，我们可能能够也可能无法仔细观察它：只有在那个确切的时间，我们的位置在运动限制下可达到的所有位置中尽可能接近踢球位置，我们才能成功。 

任务是选择踢球的子集按时间顺序“覆盖”，从而最大化我们在这种最佳意义上可以观察到的数量。 在两次选定的踢腿之间，考虑到最大速度，我们的移动必须在物理上可行。 

关键的困难在于，观察条件迫使我们在选定的踢球时刻达到最佳状态，这实际上意味着在每次选定的踢球时，我们必须精确地定位在该踢球的坐标处，因为任何偏差都将允许严格接近的位置（如果可以到达）。 

输入大小最多可达 200,000 个事件。 对所有踢腿对进行二次甚至稍微超线性的动态规划都太慢。 任何解必须接近线性或 n log n。 

当贪婪策略选择每个本地可到达的踢时，就会出现微妙的失败情况。 例如，如果我们勉强能够到达踢球点，但这样做会阻止许多未来的踢球，那么贪婪可能会失败，因为它忽略了更早或更晚到达可能会允许更多的未来可达性。 

当较大的时间间隙允许长时间移动时，会出现另一种边缘情况。 幼稚的实现可能只比较位置差异，而不按时间差异进行缩放，错误地假设每步移动恒定。 

## 方法

 蛮力方法尝试计算每次踢球是否有可能在之前选择的踢球之后结束于该踢球。 对于每对 i < j 的踢球 i 和 j，我们检查是否可以在时间 t_j - t_i 内从 a_i 移动到 a_j。 如果可行，我们尝试将结束于 i 的最佳链延伸至 j。 这会导致所有对上的动态编程转换，其时间复杂度为 O(n^2)，并且不会通过 200,000 个事件。 

关键的观察是，两次踢球之间的可行性条件仅取决于时间差和位置差，并形成单调可达性约束。 我们不必跟踪所有可能的先前选择，而是可以为每个位置保留每次到达该位置的最佳方式。 然而，在连续位置上存储完整状态是不可能的。 

相反，我们将问题重新表述为可达性约束下的最长链：我们需要一系列踢球，使得每个连续选择的对都满足速度约束。 这在结构上类似于 DAG 中的最长路径，其中仅当 |a_i - a_j| 时才存在边。 ≤ v·(t_j - t_i)。 直接图很稠密，但时间排序允许使用滑动可行边界进行动态规划。 

关键的简化是，对于每个踢 j，我们只需要知道是否存在一些较早选择的踢 i 可以到达 j，并且在这些踢 i 中我们想要最大化链长度的踢 i。 这可以通过随着时间的推移贪婪地传播可达间隔来维持，从而将状态减少到单个最佳候选边界。 

本质上，我们在每次选择的踢球后保持最佳的“覆盖状态”，并根据是否可以从该状态到达来决定是否包括下一个踢球。 如果可以联系到，我们会进行更新； 否则我们会跳过它并继续。

 | 最优贪婪可达性DP| O(n) | O(1) | O(1) | 已接受 |

## 算法演练

 我们按照时间递增的顺序处理踢球。 

1. 我们维持当前的最佳状态，由最后选择的踢球索引和迄今为止选择的踢球数量组成。 最初，没有选择踢，所以最后一个位置在时间 0 处为 0。 
2. 对于按时间顺序排列的每个踢 i，我们测试它是否可以从当前状态到达。 这意味着我们检查是否可以在时间 t_i - current_time 内从当前位置移动到 a_i。 
3. 如果可以的话，我们决定采取这一行动。 我们更新当前状态以反映我们现在在时间 t_i 处的位置 a_i，并递增答案。 
4. 如果不可达，我们跳过这次踢并保持当前状态不变。 
5. 继续，直到处理完所有踢球。 

微妙之处在于“从当前状态可达”就足够了，因为就最大化未来可达性而言，当前状态始终是最佳位置。 任何允许更大灵活性的替代路径都必须更早到达或更接近的位置，这已经主导了所维持的状态。 

### 为什么它有效

 在任何时候，该算法都会维护一个单一的边界状态，表示在最近选定的启动时间处的可行位置，该位置对于未来的可达性而言是最佳的。 任何其他提前结束或在不同位置结束的可行序列如果不首先能够改进该边界，就不能严格改进未来的选择，因为运动约束在时间上是线性的，在距离上是对称的。 因此，贪婪接受标准永远不会丢弃可能导致以后严格更大计数的序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, v = map(int, input().split())
    t = list(map(int, input().split()))
    a = list(map(int, input().split()))

    # current state: time, position, count
    cur_t = 0
    cur_x = 0
    ans = 0

    for i in range(n):
        dt = t[i] - cur_t
        dist = abs(a[i] - cur_x)

        if dist <= v * dt:
            ans += 1
            cur_t = t[i]
            cur_x = a[i]

    print(ans)

if __name__ == "__main__":
    solve()
```代码维护一个单一的演化可行状态。 变量`cur_t`跟踪最后接受踢球的时间，以及`cur_x`跟踪踢球后我们站立的位置。 对于每个传入事件，我们计算自上次接受事件以来我们可以移动多远，并将其与所需的位移进行比较。 

一个常见的实施陷阱是仅在踢球时才忘记更新时间。 使用全局时间而不是最后接受的时间会破坏可行性检查，因为它允许在错误的跳过间隔期间进行移动。

 ## 边缘情况

 一种边缘情况是时间间隙足够大以允许多个位置重置。 例如，如果跳过踢腿，算法不得错误地累积该跳过间隔的运动。 状态仅在接受的踢球时更新，因此跳过的间隔自然会为下一次可行性检查贡献时间，而不会影响位置。 

另一种边缘情况是当位置交替在极左和极右时。 条件`abs(a[i] - cur_x) <= v * (t[i] - cur_t)`正确地防止不可能的振荡，因为所需的距离随时间线性增长，并且切换边需要足够的累积时间。 

最后一个微妙的情况是多次踢球的时间非常接近。 该算法可以正确处理这个问题，因为`dt`变小，使得大多数转换不可行，除非位置也很接近，这符合有界速度的物理约束。
