 ## 解决方案
 ## 问题理解

 给我们一组值从 1 到 n 的硬币，每个值只出现一次，所以我们实际上是在选择整数 1 到 n 的子集。 目标是选择一个总和恰好为 m 的子集。 

然而，选择受到附加前缀规则的限制。 对于每个 i，我们都有一个限制 a_i，这意味着在所有选择的价值最多为 i 的硬币中，我们最多可以选择其中的 a_i。 换句话说，如果我们查看所选集合并将其限制为前缀 [1, i] 中的值，则其大小不得超过 a_i。 

我们必须构造这样的子集或确定不存在有效的子集。 

约束很大，测试中的 n 高达 10^6，因此每个测试用例的任何二次甚至线性超过 O(n log n) 的解决方案都将失败。 这立即排除了对总和或子集进行背包式动态规划的可能性。 在这种规模下，即使是 O(n sqrt n) 的构造也太慢了。 该解决方案必须依赖于具有有效可行性检查的贪婪构造。 

当应用贪婪推理而不考虑全局前缀约束时，会出现微妙的失败情况。 例如，如果人们尝试仅根据总和可行性首先选择大硬币，那么即使最终总和看起来可以实现，它也可能会打破严格的早期前缀限制。 另一种失败模式是在位置 i 处挑选本地有效的硬币，而不考虑同一个硬币会影响所有未来的前缀，这可能会在以后默默地违反约束。 

例如，假设 n = 5，我们提前选择硬币 5，因为它有助于快速达到总和 5，但 a_5 为 0。那么即使在 [1,5] 中进行单个选择也是无效的。 忽略前缀可行性的天真贪婪方法将立即失败。 

核心困难在于，每一种选择的货币都会同时影响所有未来的前缀约束，因此可行性是一种全局属性，而不是局部属性。 

## 方法

 强力解决方案将枚举 {1, 2, ..., n} 的所有子集，计算它们的总和，并检查每个子集的前缀约束。 这是正确的，但不可行，因为有 2^n 个子集，即使 n = 40 这也已经变得太大了，而这里 n 达到了 10^6。 

更结构化的基线是对 sum m 的 0/1 背包动态规划，其中 dp[s] 指示我们是否可以在尊重约束的情况下达到 sum s。 这会立即失败，因为 m 可能与 n(n+1)/2 一样大，这使得时间和内存都令人望而却步。 

关键的观察是，价值是固定的并且严格递增，因此较大的硬币总和上总是更“昂贵”，但数量却更少。 这表明从大值向下进行贪婪构造。 然而，前缀约束耦合了所有决策：选择一个硬币 i 会增加所有 j ≥ i 的前缀计数，因此我们必须确保没有前缀超过其界限 a_j。 

这将问题转化为动态可行性过程，其中每次选择都是对所有未来前缀的范围更新，并且我们必须持续保持所有前缀容量保持非负。 这种结构正是具有惰性传播的线段树所擅长的：我们跟踪每个前缀的剩余容量松弛，并确保它永远不会低于零。 

然后，我们贪婪地尝试首先获取大硬币，但前提是这样做可以使系统可行并且不会超出所需的总和 m。

 ## 算法演练

我们维护一个索引为 1 到 n 的线段树。 在位置 i，树存储我们在前缀 [1, i] 中已经选择了多少个硬币，并且我们将约束转换为松弛值 a_i - selected_prefix[i]。 我们维持的不变量是所有松弛时间必须始终保持非负值。 

我们还维护所选硬币的当前总金额和未处理硬币的剩余总金额。 

1. 初始化一个线段树，其中每个位置 i 存储等于 a_i 的初始松弛。 我们还将 current_sum 设置为 0，total_remaining_sum 设置为 n(n+1)/2。 这让我们在做出任何选择之前都有充分的能力。 
2. 将 i 从 n 迭代到 1，尝试决定是否包含硬币 i。 我们总是首先考虑较大的硬币，因为它们对每件物品的总金额贡献更大。 
3. 在尝试包含 i 之前，检查 current_sum + i 是否超过 m。 如果是这样，我们立即跳过 i，因为我们不能超过目标总和并在以后恢复它。 
4. 如果我们尝试包含 i，我们会对段 [i, n] 应用范围更新，将松弛量减少 1，因为选择 i 会增加每个前缀 j ≥ i 中的计数。 
5.更新后，我们查询线段树中的最小松弛度。 如果最小松弛变为负数，则此选择违反了某些前缀约束，因此我们回滚更新并丢弃 i。 
6. 如果更新有效，我们将i永久保留在答案集中，并通过添加i来更新current_sum。 
7. 处理完所有值后，我们检查 current_sum 是否等于 m。 如果是，我们输出选择的集合； 否则，不存在有效的构造。 

这样做的原因是，只有当整个前缀系统在考虑到其全球影响后仍然可行时，我们才会接受硬币。 线段树强制执行全局可行性条件，而贪婪排序确保我们优先考虑较大的贡献以有效地达到 m，而无需不必要的小选择。 

不变的是，在每个接受的硬币之后，所有前缀约束仍然满足，并且松弛数组正确地反映了剩余容量。 由于每个被拒绝的硬币仅由于立即违反可行性或总和超调而被拒绝，因此不会丢失有效的解决方案，可以在以后修复而不违反单调可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n, arr):
        self.n = n
        self.minv = [0] * (4 * n)
        self.lazy = [0] * (4 * n)
        self.build(1, 1, n, arr)

    def build(self, idx, l, r, arr):
        if l == r:
            self.minv[idx] = arr[l]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid, arr)
        self.build(idx * 2 + 1, mid + 1, r, arr)
        self.minv[idx] = min(self.minv[idx * 2], self.minv[idx * 2 + 1])

    def push(self, idx):
        if self.lazy[idx] != 0:
            for child in (idx * 2, idx * 2 + 1):
                self.minv[child] += self.lazy[idx]
                self.lazy[child] += self.lazy[idx]
            self.lazy[idx] = 0

    def update(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.minv[idx] += val
            self.lazy[idx] += val
            return
        self.push(idx)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, val)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, val)
        self.minv[idx] = min(self.minv[idx * 2], self.minv[idx * 2 + 1])

    def query_min(self):
        return self.minv[1]

def solve():
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    total = n * (n + 1) // 2
    if m > total:
        print(-1)
        return

    seg = SegTree(n, a)
    res = []
    cur = 0

    for i in range(n, 0, -1):
        if cur + i > m:
            continue

        seg.update(1, 1, n, i, n, -1)
        if seg.query_min() < 0:
            seg.update(1, 1, n, i, n, 1)
            continue

        res.append(i)
        cur += i

    if cur != m:
        print(-1)
        return

    res.sort()
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```线段树仅用于维持前缀约束下的可行性条件。 每次我们暂时选择一个硬币 i 时，我们都会从包含 i 的所有前缀中减去一个松弛单位。 如果这导致负最小值，我们立即撤消该操作，确保我们永远不会承诺不可行的部分解决方案。 

总和跟踪与可行性分开，因为前缀约束不直接与总和相互作用，仅与所选索引的结构相互作用。 

最后的排序步骤纯粹是为了输出格式，因为我们按降序构造集合。

 ## 边缘情况

 当早期索引的前缀约束非常小时，就会出现紧缩情况。 例如，n = 5，a = [0, 1, 1, 1, 5]。 任何立即包含硬币 1 的尝试都会使解决方案变得不可能，因为 a_1 = 0。该算法通过在提交硬币 1 之前更新线段树来处理此问题； 最小松弛变为负值，立即触发回滚。 

另一种情况是当总和 m 需要大量硬币时，但由于累积效应，它们的包含违反了早期前缀容量。 例如，如果 a_3 很小，选择硬币 5 和 4 可能仍然是不可能的，即使它们对于总和来说是最佳的。 线段树通过将其效果传播到所有受影响的前缀来确保这一点。 

最后一种情况是 m 等于总和 n(n+1)/2。 该算法将尝试获取每个硬币，但只有在所有前缀约束都与身份 a_i = i 匹配时才会成功。 当松弛在第一次违规期间变为负值时，将检测到任何更严格的约束，从而防止错误的完全选择。
