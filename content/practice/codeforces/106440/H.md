 ## 解决方案
 ## 问题理解

 该问题描述了节奏图随时间切换节奏的时间线。 该图表以节拍为单位，而实际执行时间以秒为单位。 这两者之间的转换取决于当前的 BPM，并且 BPM 在特定节拍位置发生变化。 

更具体地说，我们得到了一系列变化点。 每个变化点表示从某个节拍位置开始，BPM 变为给定值，并且它保持活动状态直到下一个变化点。 由于 BPM 决定一个节拍需要多长时间，因此节拍的每个片段对应于节拍位置和时间之间的线性函数。 

系统必须回答两种类型的查询。 一个查询将节拍位置转换为实时位置，从而有效地评估分段线性函数。 另一个查询将实时转换回节拍位置，这需要反转相同的分段线性函数。 

主要困难来自输入的大小。 最多可以有 500,000 个 BPM 段和 500,000 个查询，因此任何通过线性扫描段来处理每个查询的解决方案都将失败。 即使是每个查询的对数方法也必须围绕预先计算的结构仔细设计，否则许多段上的浮点转换会变得太慢。 

一个微妙的问题是两个转换方向都必须严格遵守段边界。 如果节拍查询落在某个分段内，则应仅使用该分段的恒定 BPM 对其进行评估，而不是错误地进入下一个间隔。 同样，当将时间转换回节拍时，正确的片段是由累积时间而不是节拍索引确定的。 

当解决方案仅预先计算节拍时间前缀和但忘记支持反转时，就会出现常见的失败情况。 例如，如果除了一个 BPM 为 120 的分段外，所有 BPM 均为 60，则使用总持续时间的比例缩放的简单逆操作会将查询错误地放置在较快的分段中，因为那里的时间积累得更慢。 

## 方法

 蛮力解释很简单。 为了回答节拍到时间查询，我们找到哪个 BPM 片段包含该节拍，然后将所有早期片段的贡献相加，最后将部分贡献添加到当前片段内。 对于节拍时间查询，我们模拟时间向前，累积段持续时间，直到超过目标时间，然后计算该段内的小数位置。 

这是可行的，因为每个段都是线性且独立的，但它变得太慢，因为每个查询可能需要扫描所有段。 当 n 和 q 达到 500,000 时，最坏的情况变为大约 10^11 次运算，这是不可行的。 

关键的观察结果是，这两种转换都基于单个单调分段线性函数。 节拍位置通过严格递增且连续的函数映射到时间。 每个段贡献一个由 60/BPM 确定的线性斜率。 如果我们预先计算两个域中的累积断点，我们可以将两个方向转换为段边界上的二分搜索问题。 

具体来说，我们构建两个数组。 一个存储片段开始的节拍位置，另一个存储这些开始处相应的累积时间值。 由于每个段都具有恒定的斜率，因此可以在 O(1) 内计算段内的时间。 这使得定位分段后的节拍时间变得微不足道。 对于心跳时间，我们对时间前缀数组进行二分搜索以找到该段，然后反转其中的线性函数。 

该转换将两种查询类型减少到 O(log n)，以二分搜索为主。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n + q log n) | O(n + q log n) | O(n) | 已接受 |

 ## 算法演练

我们将图表视为片段的集合，其中每个片段从已知的节拍位置开始，并且在下一个断点之前具有恒定的 BPM。 

1. 读取所有分段起始位置和 BPM 值。 这些定义了节拍空间中的音程。 每个间隔都与从节拍到秒的恒定转换率相关联。 
2. 预先计算段上的前缀结构。 对于每个段 i，计算到其开始为止已经过去了多少秒。 这是通过积累来完成的`(s[i+1] - s[i]) * (60 / b[i])`。 这创建了从段索引到时间的严格递增映射。 
3. 构建两个数组：一个用于节拍边界，一个用于相应的时间边界。 这些数组在两个坐标系中定义相同的分段线性函数。 
4. 对于按时间节拍的查询，二分查找最大的段开始`s[i]`这样`s[i] ≤ x`。 一旦找到，计算时间为`t[i] + (x - s[i]) * (60 / b[i])`。 
5. 对于心跳时间查询，二分查找时间数组中最大的段起始位置，使得`t[i] ≤ x`。 然后使用段内反转`s[i] + (x - t[i]) * (b[i] / 60)`。 
6. 使用具有足够精度的浮点运算输出结果。 

正确性取决于两个映射在每个段内都是严格递增和线性的，因此反演永远不会错误地跨越段边界。 

### 为什么它有效

 每个段定义节拍空间和时间空间之间具有正斜率的线性变换。 由于所有斜率均为正，因此全局函数是严格递增的，因此是可逆的。 前缀数组存储该单调函数的精确边界值。 二分查找可以正确识别包含查询的段，因为单调性保证了唯一的有效间隔。 在段内，线性插值是精确的，因为变换在该间隔内不会改变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def find_segment(arr, x):
    # largest i such that arr[i] <= x
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] <= x:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def solve():
    n = int(input())
    s = []
    b = []
    
    for _ in range(n):
        si, bi = input().split()
        s.append(int(si))
        b.append(int(bi))
    
    # compute time at segment starts
    t = [0.0] * n
    
    for i in range(n - 1):
        length_beats = s[i + 1] - s[i]
        t[i + 1] = t[i] + length_beats * 60.0 / b[i]
    
    q = int(input())
    
    for _ in range(q):
        parts = input().split()
        typ = parts[0]
        x = float(parts[1])
        
        if typ == 'B':
            i = find_segment(s, x)
            ans = t[i] + (x - s[i]) * 60.0 / b[i]
            print(f"{ans:.12f}")
        else:
            i = find_segment(t, x)
            ans = s[i] + (x - t[i]) * b[i] / 60.0
            print(f"{ans:.12f}")

if __name__ == "__main__":
    solve()
```该代码首先读取所有段边界，并在每个段开始处构建时间前缀数组。 此前缀构造是将分段定义转变为可直接查询的结构的关键预处理步骤。 

这`find_segment`函数执行二分搜索来定位正确的区间。 它始终返回边界不大于查询的最后一个索引，这确保了节拍和时域的正确片段选择。 

对于节拍查询，我们使用节拍边界数组`s`定位线段，然后应用局部线性公式。 对于时间查询，我们执行相同的操作，但在时间前缀数组上`t`。 两种操作的对称性使解决方案变得干净并避免单独的数据结构进行反转。 

必须小心浮点运算。 所有中间值均保持双精度，最终输出使用足够的小数位以满足 1e-6 容差。 

## 工作示例

 考虑一个包含两个部分的简单图表：节拍从 0 开始，BPM 120，然后在节拍 100 BPM 变为 60。这意味着第一个部分更快，并且累积时间更慢。 

| 步骤| 查询 | 细分 | 计算| 结果 |
 | --- | --- | --- | --- | --- |
 | 1 | B 50 | 0 | 50 * 0.5 | 50 * 0.5 25 | 25
 | 2 | B 120 | 1 | 100 * 0.5 + 20 * 1 | 70 | 70

 该跟踪显示第一段如何使用 60/120 = 0.5 秒每节拍，而第二段如何使用 1 秒每节拍。 前缀结构确保我们正确区分贡献。 

现在考虑对相同结构的反向查询。 

| 步骤| 查询 | 细分 | 计算| 结果 |
 | --- | --- | --- | --- | --- |
 | 1 | S 25 | 0 | 25 * 2 | 25 * 2 50 | 50
 | 2 | S 70 | 1 | 100 + (70 - 50) * 1 | 120 | 120

 这证实了反演正确地重建了原始节拍位置。

 ## 边缘情况

 一种重要的边缘情况是查询恰好落在段边界上。 由于段开头是包容性定义的，因此两个数组必须一致地对待相等性。 例如，如果某个片段以节拍 100 开始，则查询 B 100 必须属于该片段，而不是前一个片段。 二分搜索实现返回值 ≤ x 的最后一个索引，这直接强制执行此规则。 

另一种情况是单段图表。 这里没有转换，因此前缀构造必须避免访问`s[i+1]`。 该实现通过在构建时间前缀时仅迭代至 n-1 来处理此问题。 

最后，精确等于前缀时间的反转查询必须映射到正确的段开始。 由于时间数组严格递增，二分查找再次选择正确的边界而不会产生歧义，从而保持正向和反向映射之间的一致性。
