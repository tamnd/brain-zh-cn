 ## 解决方案
 ## 问题理解

 网格是一个固定的 10 x 10 战场，其中每个单元要么是水，要么是船的一部分。 在任何查询开始之前，船舶就已经正确放置，并且每艘船舶都是由水平或垂直相邻单元格形成的连接形状。 总共有十艘船，它们的大小遵循已知的分布：四艘船占据一个单元，三艘船占据两个单元，两艘船占据三个单元，一艘船占据四个单元。 

读取此网格后，我们处理一系列命令。 一种类型的命令模拟向特定单元开火，另一种类型则要求报告所有船只的当前状态。 一艘船可能处于三种状态之一，具体取决于其被击中的单元数量：完全未受影响、部分损坏或完全摧毁。 

输出要求仅与第二种类型的命令相关。 对于每个报告查询，我们必须及时输出有多少艘船只仍未受到影响，有多少艘已被击中但未被摧毁，以及有多少艘在该时刻被完全摧毁。 

约束非常小：网格固定为 100 个单元，命令数量最多为 100 个。这立即排除了对复杂数据结构或渐近优化查询处理的任何需要。 即使每次查询重新计算完整的船舶状态也是可以接受的，但我们可以通过增量维护状态来做得更好。 

主要的微妙之处在于，当对重复的射击进行双重计数或尝试在不预先计算连接组件的情况下动态推断船舶身份时，幼稚的方法通常会失败。 另一个常见错误是在每次显示时从头开始重新计算船舶状态，这是安全但不必要的，并且在不一致地跟踪部分命中时更容易出错。 

当同一个单元被多次射击时，就会出现具体的边缘情况。 例如，如果一艘二号船被击中一个单元格，然后再次瞄准同一单元格，则只有第一次射击才会改变船的状态。 粗心的实施会增加每个 SHOT 命令的命中计数，这会过早错误地将船只标记为沉没。 

另一个边缘情况是在任何射击之前发出 SHOW 命令，其中所有船只必须报告为未损坏。 任何延迟初始化命中计数的逻辑都有可能对这些早期查询进行错误分类。 

## 方法

 最直接的想法是独立处理每个 SHOT，并且每当 SHOW 出现时，通过扫描整个网格并检查哪些单元已被击中，从头开始重新计算每艘船的状态。 这是可行的，因为网格很小，但从概念上讲，它变得低效，因为每个 SHOW 可能触发 100 个单元格的完整扫描和重复的分组逻辑。 对于最多 100 个查询，这仍然可以接受，但它混合了职责，并且很容易错误地实现，因为船舶成员资格和命中跟踪会被重复重建。 

一种更结构化的方法是将问题分为两个阶段。 首先，我们使用网格上的洪水填充来识别所有船只。 每艘船都成为一个具有固定单元列表和已知尺寸的组件。 然后我们为每艘船维护一个小状态，跟踪其有多少个单元被击中。 每个 SHOT 只更新一个单元，我们使用从单元到船舶的直接映射来在恒定时间内更新相应的组件。 这使得 SHOW 查询变得微不足道，因为我们只需要根据每艘船当前的命中数对其进行分类。 

关键的见解是船舶的身份永远不会改变，只会造成损害累积。 一旦我们预先计算连接的组件，问题的动态部分就减少到维护这些组件的计数器。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 按 SHOW | 重新计算 O(q·100) | O(100) | 已接受 |
 | 预计算船舶+增量更新| O(100 + q) | O(100) | 已接受 |

 ## 算法演练

 我们首先将网格转换为一组标记的船只，以便每个单元都知道它属于哪艘船。 

1. 扫描网格的每个单元格。 每当我们发现包含尚未分配给船舶的船段的单元格时，我们就会从该单元格开始洪水填充。 该洪水填充收集所有连接的船舶单元并为它们分配相同的船舶标识符。 此步骤是必要的，因为后续更新必须影响整艘船，而不仅仅是单个单元。 
2. 对于每艘被发现的船，存储其大小并初始化一个计数器，以计算其有多少个单元被击中。 此时，所有命中计数器均为零，因为尚未发生任何射击。 
3. 构建从每个网格单元到其船舶标识符的直接映射，或者如果它不属于任何船舶，则将其标记为水。 这允许在 SHOT 命令期间进行恒定时间查找。 
4. 维护一个布尔网格来跟踪某个单元格是否已被射击。 这很重要，因为对同一细胞的重复注射不得多次改变状态。 
5. 按顺序处理每个命令。 当 SHOT 命令到达时，将坐标转换为单元格。 如果细胞已经被射击，我们就完全忽略它。 否则，我们将其标记为射击，如果该单元属于一艘船，我们会增加该船的命中计数器。 
6. 当出现 SHOW 命令时，我们迭代所有船舶并对每艘船舶进行分类。 如果其命中次数为零，则表示未损坏。 如果它的命中数等于它的大小，它就会沉没。 否则，就会被部分击中。 

正确性依赖于这样一个事实：每个单元都只对一艘船做出贡献，并且每个单元只能从未射击到射击一次转换。 

### 为什么它有效

 整个过程中保持的不变量是每艘船的命中计数器恰好等于该船迄今为止已被射击的不同单元的数量。 因为我们明确防止重复射击的重复计算，所以每个增量对应于一个唯一的新击中的单元格。 由于船舶成员资格从初始洪水填充开始就固定了，因此 SHOW 期间的分类只是该计数器相对于船舶尺寸的函数，这与未损坏、击中和沉没的定义完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

n = 10
grid = [input().strip() for _ in range(10)]

ship_id = [[-1] * 10 for _ in range(10)]
ships = []

dx = [1, -1, 0, 0]
dy = [0, 0, 1, -1]

def bfs(sx, sy, idx):
    q = deque()
    q.append((sx, sy))
    ship_id[sx][sy] = idx
    cells = [(sx, sy)]
    
    while q:
        x, y = q.popleft()
        for k in range(4):
            nx, ny = x + dx[k], y + dy[k]
            if 0 <= nx < 10 and 0 <= ny < 10:
                if grid[nx][ny] == '#' and ship_id[nx][ny] == -1:
                    ship_id[nx][ny] = idx
                    q.append((nx, ny))
                    cells.append((nx, ny))
    
    return cells

for i in range(10):
    for j in range(10):
        if grid[i][j] == '#' and ship_id[i][j] == -1:
            cells = bfs(i, j, len(ships))
            ships.append({
                "size": len(cells),
                "hits": 0
            })

shot = [[False] * 10 for _ in range(10)]

q = int(input())
for _ in range(q):
    cmd = input().split()
    
    if cmd[0] == "SHOT":
        x = int(cmd[1]) - 1
        y = int(cmd[2]) - 1
        if not shot[x][y]:
            shot[x][y] = True
            sid = ship_id[x][y]
            if sid != -1:
                ships[sid]["hits"] += 1
    
    else:
        undamaged = 0
        hit = 0
        sunk = 0
        
        for s in ships:
            if s["hits"] == 0:
                undamaged += 1
            elif s["hits"] == s["size"]:
                sunk += 1
            else:
                hit += 1
        
        print(undamaged, hit, sunk)
```该代码首先读取网格并使用 BFS 洪水填充对所有船舶单元进行分组。 每个发现的组件都存储其大小和可变的命中计数器。 这`ship_id`矩阵提供从任何单元到其飞船的恒定时间映射。 

在仿真过程中，`shot`矩阵可以防止重复计算。 如果目标单元属于一艘船，则每次有效的新射击都会增加一艘船的计数器。 

对于 SHOW 查询，我们只需扫描所有船舶并根据其累积损坏状态对它们进行分类。 

一个常见的实现陷阱是忘记将输入坐标从基于 1 的索引转换为基于 0 的索引，这会默默地移动所有镜头并产生不正确的分类而不会崩溃。

 ## 边缘情况

 没有船只的网格会被自然处理，因为洪水填充会找到零个组件，因此每个 SHOW 查询都会迭代一个空列表并返回全零。 

一艘大型船舶可确保正确区分部分损坏和完全损坏。 该算法会增加该船的单个计数器，并且仅当计数器等于其总大小时才将其分类为沉没。 

对同一单元格进行重复射击不会影响任何计数器，因为`shot`矩阵块重复更新。 这保留了每个船舶单元最多对其命中计数贡献一次的不变量，从而防止过度计数，否则会错误地触发早期沉没。
