 ## 解决方案
 ## 问题理解

 我们收到一组任务，每个任务都有自己的重复周期（以天为单位）。 如果任务有价值$a_i$，那么一旦在第 0 天完成，就必须在第 7 天再次重复$a_i, 2a_i, 3a_i,\dots$，只要那些日子在接下来的时间内$k$我们计划的日子。 值为$a_i = 0$是一种特殊情况，其中任务在初始完成后不会生成任何未来的重复。 

目标是确定每天从 1 到$k$，当天所有任务的总和需要重复多少次任务。 

一种直接的解释是，每项任务都会“产生”一系列未来的日子。 我们正在计算计划窗口中每天有多少个序列相交。 

约束允许最多$10^5$任务和$10^5$天。 这排除了任何每天模拟每个任务的解决方案，因为天真的传播会导致$O(nk)$最坏情况下的行为，达到$10^{10}$操作，并且是不可行的。 甚至迭代每个的所有倍数$a_i$如果没有结构，单独进行会太慢，因为必须仔细限制更新的总数。 

当出现微妙的边缘情况时$a_i = 0$。 在这种情况下，粗心的实现可能会尝试将其视为正常步长，从而导致在生成倍数时被零除或无限循环。 另一个边缘情况是$a_i > k$，其中在规划范围内不应发生重复，但天真的循环可能仍会尝试不必要的处理。 

例如，如果$n=2, k=6$和$a = [0, 1]$，那么第一个任务在第 0 天之后没有任何贡献，而第二个任务对从 1 到 6 的每一天都有贡献。正确的输出是$1,2,1,2,1,2$。 任何处理不当的解决方案$a_i=0$可能会错误地尝试传播它或崩溃。 

## 方法

 蛮力方法从字面解释问题开始。 对于每个任务，我们通过逐步执行其周期的倍数来模拟其所有未来发生的情况。 对于每个倍数$d = a_i, 2a_i, 3a_i, \dots$最多$k$，我们增加一天的计数器$d$。 

这是正确的，因为它直接构建了每个任务的确切贡献。 然而，当许多任务的值较小时，成本就会成为问题$a_i$。 如果$a_i = 1$对于所有任务，每项任务对每一天都有贡献，产生$O(nk)$更新。 和$n = k = 10^5$，这导致$10^{10}$增量，远远超出了可行的限度。 

关键的观察是，这是一个经典的“筛子式积累”模式。 我们不是独立模拟每个任务，而是按周期聚合任务。 如果我们计算有多少任务共享相同的值$a$，那么每个不同的$a$重复贡献的倍数$a$。 这使我们能够从按任务模拟切换到按值频率累积。 

Once we have a frequency array$freq[a]$，我们只需要迭代可能的步长$a$，并将每个人的贡献分配给所有倍数。 这将重复的工作转变为分组工作，类似于除数或筛问题的优化方式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nk)$最坏的情况|$O(k)$| 太慢了 |
 | 最优（频率+倍数）|$O(k \log k)$|$O(k)$| 已接受 |

 ## 算法演练

 我们将任务列表转换为重复间隔的频率表。 然后我们将贡献有效地传播到倍数上。 

1. 构建数组`freq`在哪里`freq[x]`准确存储有多少个任务具有重复周期`x`。 这将相同的行为组合在一起，避免了多余的工作。 
2. 创建答案数组`ans`大小的`k`，初始化为零。 各位置`ans[d]`将存储当天发生的任务数量`d`。 
3. 对于每个可能的周期值`x`从 1 到`k`， 如果`freq[x] > 0`，我们将其贡献分配给所有倍数`x`范围内。 这意味着迭代`d = x, 2x, 3x, ... ≤ k`并添加`freq[x]`到`ans[d]`。 
4. 忽略所有任务`a_i = 0`，因为它们从不贡献未来的重复。 
5.输出数组`ans[1..k]`。 

每个周期类的行为就像一个“波”，以固定的时间间隔在时间轴上传播。 对它们进行分组可确保每个波处理一次，而不是每个任务处理一次。 

### 为什么它有效

 任何一天$d$, 有周期的任务$x$准确贡献时$d$是的倍数$x$。 该算法确保对于每个$x$，我们将其频率添加到每个这样的倍数中。 由于每个任务在其频率桶中只计算一次，并在其有效天数中精确添加，因此不会发生多算或遗漏的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    freq = [0] * (k + 1)
    
    for x in a:
        if x != 0 and x <= k:
            freq[x] += 1
    
    ans = [0] * (k + 1)
    
    for x in range(1, k + 1):
        if freq[x] == 0:
            continue
        for d in range(x, k + 1, x):
            ans[d] += freq[x]
    
    print(*ans[1:k+1])

if __name__ == "__main__":
    solve()
```该代码首先计算有多少任务共享每个重复间隔。 支票`x != 0`避免无效的步长，因为零不会生成有效的算术级数。 第二个条件`x <= k`确保我们只处理实际出现在时间窗口内的间隔。 

嵌套循环结构是核心传播步骤。 对于每个时期`x`，我们访问它的倍数并增加相应的日计数器。 这反映了周期性事件的数学定义。 

一个微妙的点是索引：答案数组的大小是确定的`k+1`这样日期索引自然地与数组位置对齐，避免写入时出现差一错误`ans[d]`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(k \log k)$| 每个周期都贡献其倍数，形成所有 x | 的调和级数。 
| 空间|$O(k)$| 大小为 k 的频率和答案数组 |

 由于倍数的谐波和受下式限制，运行时间完全在限制范围内：$k \log k$， 和$k \le 10^5$。

 ## 边缘情况

 关键的边缘情况是所有值都为零时。 在这种情况下，不应发生传播并且输出必须完全为零。 频率表不包括零，因此嵌套循环永远不会添加任何贡献。 

另一种情况是所有值都等于 1 时。每个任务对每天都有贡献，算法将所有频率累积到每个位置。 自从`freq[1] = n`，每一天都变成`n`。 

当值超过`k`，它们永远不会在传播循环中作为有效索引出现。 他们被安全地忽略`x <= k`检查，防止浪费迭代并确保正确性，无需特殊处理。 

最后，混合分布（例如许多小值与大值相结合）证明了分组的优势。 小值在运行时占主导地位，但分组可确保每个除数链而不是每个任务处理一次。
