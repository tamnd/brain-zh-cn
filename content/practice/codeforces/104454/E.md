 ## 解决方案
 ## 问题理解

 每个玩家都有一堆硬币，每个硬币的面额从 1 到 n。 硬币堆按从下到上的顺序排列，任何时候都只能访问每堆最上面的硬币。 

单个操作包括选择面额，然后同时移除四个堆栈中价值与该面额匹配的每个顶部硬币。 当前不在顶部的硬币无法被触摸，因此每个堆栈中的进度都受到其自身顶部元素的严格限制。 

该过程继续进行，直到所有四个堆栈都为空。 任务是确定完全清除所有堆栈所需的此类操作的最少数量。 

关键结构是我们不是独立地弹出每个堆栈。 相反，如果多个堆栈碰巧与当前最高值对齐，则单个选定的面额可能会同时推进多个堆栈。 

每个维度的约束都很小。 每叠最多有 30 种面额、最多 30 枚硬币。 这立即表明跟踪所有堆栈的完整状态的任何解决方案都是可行的，因为组合状态空间最多为 31⁴，即大约 80 万个配置。 不可行的是贪婪地处理每个操作而不考虑未来的对齐，因为早期的选择可能会永久破坏堆栈之间的同步机会。 

一种简单的方法是模拟所有可能的操作序列。 即使我们只考虑有效选择，每个步骤也最多有 30 个选项，过程长度可达 120。这会产生一个天文数字般大的分支因子，使得暴力破解变得不可能。 

当两个堆栈在内部较深处但不在顶部共享一个面额时，贪婪推理的一个微妙的失败案例就会出现。 如果我们过早地以贪婪的顺序“追逐”顶级匹配，我们可能会错位堆栈并失去未来一次删除多个硬币的机会。 

例如，假设一个堆栈以一长串面额 1 开始，而另一个堆栈以不同的值开始，但后来也有 1。 如果我们在不考虑对齐的情况下积极删除可用的 1，我们可能会过早消耗第一个堆栈的 1-run，从而阻止稍后同时删除并增加操作数量。 

核心困难在于，成本取决于堆栈随时间的排列方式，而不仅仅是它们各自的序列。 

## 方法

 强力解释是将每个堆栈视为指向其序列的指针，并尝试每种可能的面额选择序列。 从所有四个堆栈的当前剩余后缀定义的状态中，我们分支最多 n 个选择并模拟每个操作的效果。 

这是正确的，因为它明确地探索了所有有效的操作序列，但它失败了，因为可以通过指数级的多种方式达到四个指针的相同状态，并且搜索树以每步 30 个选择的方式增长，最多可达 120 个步骤。 

关键的观察是该过程完全由所有堆栈中的当前后缀位置决定。 一旦我们知道每堆硬币中还剩下多少枚硬币，未来就与我们如何到达那里无关。 这意味着问题变成了状态图上的最短路径问题。 

每个状态都是一个 4 元组的位置。 从任何状态，选择一个面额，通过弹出其顶部硬币与该面额匹配的所有堆栈，确定性地转换到新状态。 由于每个操作都有单位成本，因此我们正在寻找从初始状态到所有堆栈为空的最终状态的最短路径。 

这将问题转化为最多 30⁴ 状态的多维 BFS。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举| 指数| O(1) | O(1) | 太慢了 |
 | 状态图上的 BFS | O(n·m1·m2·m3·m4) | O(m₁·m2·m3·m₄) | 已接受 |

## 算法演练

 我们以相反的顺序表示每个堆栈，以便我们可以有效地从数组的后面而不是前面删除。 每个状态由四个整数定义，指示每个堆栈中剩余多少硬币。 

我们从所有堆栈已满的状态开始运行广度优先搜索，目标是到达所有堆栈为空的状态。 

### 步骤

 1. 翻转每个堆栈，使顶部的硬币成为数组中的最后一个元素。 这允许在索引上使用类似弹出操作的 O(1) 删除操作。 
2. 将初始状态定义为所有四个堆栈的全长元组。 这代表了收集任何硬币之前的情况。 
3. 使用该初始状态初始化 BFS 队列，并为其分配距离零。 
4. 当队列不为空时，提取当前状态。 该状态完全确定当前可以访问哪些硬币，因为只有每个非空堆栈的最后一个元素很重要。 
5. 对于从 1 到 n 的每个可能的面额，模拟执行选择该面额的一个操作。 对于当前顶部等于该面额的每个堆栈，递减其指针。 
6. 结果是应用该操作后的新状态。 如果这个状态还没有被访问过或者可以用更少的步骤到达，则更新它的距离并将其推入队列。 
7. 继续，直到处理完所有可达状态。 答案是为所有四个堆栈都为空的状态记录的距离。 

### 为什么它有效

 该算法依赖于每个状态完全捕获与未来决策相关的所有信息的不变量。 导致相同剩余后缀的两个不同历史是等效的，因为未来的操作仅取决于每个堆栈的当前顶部元素。 BFS 保证我们第一次到达某个状态是通过最少数量的操作，因为每次转换都有相同的成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    m = list(map(int, input().split()))
    
    stacks = []
    for i in range(4):
        arr = list(map(int, input().split()))
        arr.reverse()
        stacks.append(arr)
    
    # state: (p1, p2, p3, p4)
    start = (m[0], m[1], m[2], m[3])
    target = (0, 0, 0, 0)
    
    # distance dictionary
    dist = {start: 0}
    q = deque([start])
    
    while q:
        s = q.popleft()
        d = dist[s]
        
        if s == target:
            print(d)
            return
        
        p1, p2, p3, p4 = s
        tops = []
        
        if p1 > 0:
            tops.append(stacks[0][p1 - 1])
        if p2 > 0:
            tops.append(stacks[1][p2 - 1])
        if p3 > 0:
            tops.append(stacks[2][p3 - 1])
        if p4 > 0:
            tops.append(stacks[3][p4 - 1])
        
        # try all denominations
        for c in range(1, n + 1):
            np1, np2, np3, np4 = p1, p2, p3, p4
            
            if p1 > 0 and stacks[0][p1 - 1] == c:
                np1 -= 1
            if p2 > 0 and stacks[1][p2 - 1] == c:
                np2 -= 1
            if p3 > 0 and stacks[2][p3 - 1] == c:
                np3 -= 1
            if p4 > 0 and stacks[3][p4 - 1] == c:
                np4 -= 1
            
            ns = (np1, np2, np3, np4)
            if ns not in dist:
                dist[ns] = d + 1
                q.append(ns)

solve()
```该代码反转存储每个堆栈，以便最后一个元素始终是当前顶部。 BFS 状态使用剩余长度而不是反向数组的显式索引。 每次转换都会尝试每种面额，并将其一致地应用于所有堆栈。 

一个微妙的细节是，我们永远不需要显式计算某个州可以使用哪些面额。 尽管迭代所有 n 值有点浪费，但 n 最多只有 30，这使得总工作易于管理。

 ## 边缘情况

 当所有堆栈都相同时，就会出现极端情况。 在这种情况下，每次操作都会同时删除最多 4 个硬币，并且 BFS 会迅速崩溃状态空间。 该算法可以正确处理这个问题，因为从初始状态开始，每个面额选择都会导致相同的状态转换，并且 BFS 仍然可以找到重复最佳选择的最短路径。 

另一种情况是堆栈在任何对齐点都不共享公共顶部值。 该算法退化为有效地独立处理每个堆栈，因为每个操作一次只影响一个堆栈。 BFS 仍然有效，因为它自然地探索在堆栈之间交替的序列，直到完成。 

一个更微妙的情况是早期的选择会影响以后的同步。 即使某个面额出现在所有堆栈中，它也可能出现在不同的深度。 BFS 状态表示确保正确捕获这些延迟的对齐，因为状态仅依赖于剩余的后缀，而不依赖于过去的决策。
