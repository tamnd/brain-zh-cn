 ## 解决方案
 ## 问题理解

 四名玩家各自在共享的城市地图上建造两种东西。 首先，他们将行业代币放置到特定的城市。 如果多个代币覆盖所有玩家，一个城市可以包含多个行业。 其次，每个玩家都建造道路，每条道路连接两个城市并且只属于一个玩家。 

道路的评分规则因每条道路而异，但取决于全球行业状况。 对于连接城市的道路`u`和`v`，建造它的玩家获得的积分等于当前城市中存在的行业代币总数`u`加上城市里的`v`。 最终任务是为每个玩家独立计算他们建造的所有道路的得分总和。 

关键的相互作用是，行业对于所有参与者来说都是全球性的，而道路对于每个参与者来说都是私有的。 这意味着道路的价值取决于共享的聚合信息，而不仅仅是玩家自己的行为。 

约束允许最多`10^5`城市，而每个玩家最多贡献`10^4`工业和`10^4`道路。 这使得总共最多`4 * 10^4`行业布局和道路顺序相同。 任何尝试重复计算每条道路或每个查询的行业计数的解决方案都会太慢，特别是如果它扫描列表或从头开始重新计算总和。 需要线性或近线性预处理策略。 

当所有参与者的行业没有正确聚合时，就会出现微妙的失败案例。 例如，如果城市`1`有多个玩家的行业，但我们只计算最后读取的玩家的贡献，涉及城市的道路分数`1`会被低估。 另一个常见的错误是当得分明确取决于全球总人数时，将行业视为每个玩家。 

## 方法

 直接模拟方法将存储所有行业布局，并且对于每条道路，通过扫描整个行业列表来计算两个端点中存在的行业数量。 这意味着对于每条道路，我们可能会遍历所有行业布局，给出最坏的情况`O(G * M)`每个玩家。 和`G`和`M`最多`10^4`，这已经可以达到`10^8`每个玩家在最坏情况下的操作，并且在四个玩家之间这变得太慢。 

改进来自于分离关注点。 每条道路唯一需要的是其两个端点的工业总数。 这个价值并不取决于道路本身，只取决于产业在城市之间的最终分布。 因此，我们首先将所有行业放置压缩到单个频率数组中，而不是重复重新计算`cnt[c]`，代表每个城市有多少个行业。 

一旦建立了这个数组，每条道路的评估就变成常数时间：对于一条道路`(u, v)`，分数很简单`cnt[u] + cnt[v]`。 每个玩家的答案就是他们自己道路上的这个表达式的总和。 

这将问题从重复扫描减少为单个预处理步骤加上所有道路上的线性通过。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（扫描每条道路的行业）| O(G × 行业总数) | O(总工业) | 太慢了 |
 | 按城市进行前缀聚合 | O(N + 工业总数 + 道路总数) | O(N) | 已接受 |

 ## 算法演练

 ### 步骤

 1.读取城市数量`N`并初始化一个数组`cnt`尺寸的`N + 1`带零。 

该数组将存储每个城市存在多少行业代币，无论玩家是谁。 
2. 对于四位参与者中的每一位，请阅读他们的行业排名列表。 对于每个城市指数`x`在该列表中，增加`cnt[x]`一个。 

这将所有参与者的行业合并到一个全球频率表中。 
3. 对于每个玩家，将跑分变量初始化为零。 
4. 阅读该玩家的道路列表。 对于每条道路`(a, b)`， 添加`cnt[a] + cnt[b]`到该玩家的分数。 

这是有效的，因为任一端点的每个行业都对该道路的价值贡献了一次。 
5. 输出四次累计得分。 

### 为什么它有效

 在任何时刻，`cnt[c]`代表放置在城市中的行业代币的确切数量`c`。 该值与道路无关，仅取决于所有参与者的行业行动的联合。 

每条道路的贡献纯粹是在其端点上相加，因此玩家的总分是其函数边缘的总和，该函数仅取决于预先计算的顶点权重。 由于没有道路影响另一条道路，并且读取后没有行业布局发生变化，因此在整个计算过程中，顶点权重的分解是准确且稳定的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cnt = [0] * (n + 1)

    players_industries = []

    for _ in range(4):
        m, g = map(int, input().split())
        inds = list(map(int, input().split()))
        players_industries.append((m, g, inds))
        for c in inds:
            cnt[c] += 1

    res = []

    for i in range(4):
        m, g, inds = players_industries[i]
        total = 0
        for _ in range(g):
            a, b = map(int, input().split())
            total += cnt[a] + cnt[b]
        res.append(total)

    print(*res)

if __name__ == "__main__":
    solve()
```该解决方案首先在所有参与者的行业列表中一次性构建全球行业频率阵列。 然后，它在处理每个玩家的道路时重用该数组，确保在恒定时间内评估每条道路。 

一个常见的陷阱是在道路评估期间尝试重新计算行业计数或错误地分离每个玩家的行业计数。 正确的解释是，所有行业都为共享池做出贡献。 

另一个微妙的点是，道路是在所有行业都已知之后才进行处理的，因此不需要增量更新或排序考虑。

 ## 边缘情况

 一个重要的边缘情况是不同参与者的多个产业聚集在同一城市。 该算法自然地处理这个问题，因为它将所有增量求和为`cnt[c]`在任何道路处理开始之前。 对于一个拥有三大产业的城市来说，`cnt[c]`无论分布如何，都会变为 3，并且使用该城市的每条道路都会正确计算所有三个贡献。 

另一种情况是玩家没有道路。 在这种情况下，道路上的循环没有任何贡献，玩家的分数保持为零，这是正确的，因为分数仅通过构建的道路来定义。 

进一步的情况是不同道路上重复的城市端点。 由于每条道路都是独立的，并且始终使用相同的预计算数组进行评估，因此重复使用城市只需重复使用相同的道路`cnt[c]`价值无副作用或突变。
