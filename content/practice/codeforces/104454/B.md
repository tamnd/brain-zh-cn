 ## 解决方案
 ## 问题理解

 这个问题中的每一步都是击中其中一个的镜头$k$同心环，每个环贡献一个等于其索引的固定分数。 所以一次射击只是一个从 1 到$k$。 艾拉需要$n$镜头，这意味着我们正在考虑所有长度-$n$每个元素介于 1 和 之间的序列$k$，我们关心该序列的总和。 

伊戈尔已经给出了固定分数$p$。 任务是计算有多少种可能的艾拉射击序列产生的总和严格大于$p$。 

重要的结构是，这与概率或期望值无关，尽管该声明提到了相等的可能性。 它纯粹是具有有限元素和的序列的组合计数。 

输入大小迫使我们进行动态规划。 序列数为$k^n$，即使对于中等强度来说，这也是一个天文数字$n$，所以暴力枚举是不可能的。 总和约束$n, k \le 300$和最大总和$n \cdot k \le 90000$表示任何有效的解决方案都必须明确跟踪可实现的总和，而不是枚举序列。 

一种天真的方法会尝试生成所有$k^n$序列并检查它们的总和，但即使对于$n=20$和$k=10$，这已经变成了$10^{20}$，远远超出了可行性。 

第二个天真的想法是对剩余镜头和当前总和使用递归，但如果没有记忆，这会以指数方式重复相同的子问题。 

唯一可行的结构是 DP 超过拍摄次数和达到的总和。 

出现微妙的边缘情况时$p = 0$。 那么除了全零和情况之外的每个序列都符合资格，但由于最低分数是$n$，答案就变得简单了$k^n$。 另一个界限是当$p \ge nk$，其中没有序列可以超过 Igor 的分数，产生零。 

## 方法

 暴力解释很简单：生成每个长度的序列$n$，计算其总和，并计算超出的$p$。 这是正确的，因为它明确地评估了问题的定义。 然而，它需要探索一个分支因子$k$对于每个$n$职位，导致$k^n$序列。 和$k$甚至高达 300$n=10$使这成为不可能。 

一个自然的改进是带有记忆的递归。 我们定义一个基于位置和当前总和的函数，并尝试从 1 到$k$。 这减少了重复工作，但仍有转换成本$O(k)$每个状态，状态数量为$O(n \cdot nk)$，大致如此$O(n^2 k^2)$，仍然太大。 

关键的观察结果是，转换仅取决于前一层和总和的滑动范围。 对于固定次数的镜头，达到sum的方式数$s$是求和的方法之和$s-1, s-2, \dots, s-k$在上一步中。 这是 DP 数组上的滑动窗口，它允许使用前缀和在恒定时间内计算每个状态。 

这将问题简化为经典的有界卷积 DP：我们用长度一致的核反复对分布进行卷积$k$。 

最后，不要直接计算大于的总和$p$，计算所有序列并用 sum 减去那些序列会更容易$\le p$。 序列总数为$k^n$，很容易通过快速求幂来计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(k^n)$|$O(n)$| 太慢了 |
 | DP带推拉窗|$O(n \cdot nk)$|$O(nk)$| 太慢了 |
 | 具有前缀和的优化 DP |$O(n \cdot nk)$但转换 O(1) 所以$O(n \cdot nk)$简化为$O(n \cdot nk)$状态减少到$O(n \cdot nk)$实际上总数$O(n \cdot nk)$→ 最终是$O(n \cdot nk)$但有有效的约束$O(n \cdot nk)$=$O(n \cdot nk)$|$O(nk)$| 已接受 |

 更准确地说，最终的解决方案运行在$O(n \cdot nk)$在哪里$nk \le 90000$，那么关于$300 \times 90000 = 27 \cdot 10^6$运营。 

## 算法演练

 我们定义一个动态规划表，在其中逐个处理镜头并跟踪导致每个可能总和的方式有多少种。 

1. 我们初始化一个零次发射的 DP 数组，其中只有一种方式可以得到和 0。 这代表进行任何射击之前的空序列。 
2. 对于从 1 到$n$，我们计算一个新的 DP 数组，表示该镜头后所有可达到的总和。 每个新状态对应于从 1 到$k$。 
3. 对于固定数量的拍摄$i$, 达到总和的方法数$s$是所有求和方法的总和$s-1$通过$s-k$在上一层中。 这直接编码了这样一个事实：最后一次射击可能贡献从 1 到$k$。 
4.代替求和$k$对于每个状态的值，我们在先前的 DP 数组上维护前缀和，以便可以在恒定时间内计算每个范围和。 这避免了重复地重新计算重叠间隔。 
5.全部处理完毕后$n$镜头，我们将所有 DP 值相加，总和从 0 到$p$。 这给出了失败或未获胜序列的数量。 
6. 我们计算序列总数为$k^n \bmod (10^9+7)$减去失败的次数即可得到答案。 

### 为什么它有效

 在每一步中，DP 层都表示所有固定长度序列按其总和的完整且不相交的划分。 每个转换都保持正确性，因为每个长度序列$i$是通过在其中附加一个值而唯一形成的$[1, k]$到一个长度的序列$i-1$。 滑动窗口公式确保每个有效分机都被精确计数一次，并且不会引入超出允许范围的无效总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, p = map(int, input().split())

    max_sum = n * k

    # dp[s] = ways to get sum s after current number of shots
    dp = [0] * (max_sum + 1)
    dp[0] = 1

    for _ in range(n):
        new_dp = [0] * (max_sum + 1)
        prefix = [0] * (max_sum + 2)

        for s in range(max_sum + 1):
            prefix[s + 1] = (prefix[s] + dp[s]) % MOD

        for s in range(max_sum + 1):
            left = s - k
            if left < 0:
                left = 0
            right = s - 1
            if right >= 0:
                new_dp[s] = (prefix[right + 1] - prefix[left]) % MOD

        dp = new_dp

    total_bad = sum(dp[:p + 1]) % MOD

    total = pow(k, n, MOD)
    print((total - total_bad) % MOD)

if __name__ == "__main__":
    solve()
```DP 阵列跟踪每次拍摄后有多少个序列达到每个可能的分数。 前缀数组在每次迭代时都会重建，以允许对转换进行恒定时间范围总和查询。 该转换通过选择 1 和$k$。 

最后的减法步骤很重要，因为直接计算“大于$p$”将需要跟踪移动阈值；相反，我们计算补集，该补集在模运算下是数值稳定的。

 ## 工作示例

 ### 示例 1

 输入：```
3 3 7
```我们在每次射击后跟踪 dp（仅显示相关总和）。 

| 步骤| dp（非零和）|
 | ---| ---|
 | 0 | {0:1} |
 | 1 | {1:1, 2:1, 3:1} |
 | 2 | {2:1, 3:2, 4:3, 5:2, 6:1} |
 | 3 | {3:1, 4:3, 5:6, 6:7, 7:6, 8:3, 9:1} |

 现在我们计算总和$\le 7$:$1+3+6+7+6 = 23$。 总序列为$3^3 = 27$。 所以答案是$27 - 23 = 4$。 

该跟踪表明 DP 正确地累积了所有有序三元组值$[1,3]$并按总和对它们进行分组。 

### 示例 2

 输入：```
5 5 6
```我们不展开完整的表，但概念上 5 步后的 dp 表示长度为 5 的所有序列$[1,5]$。 答案仅计算那些总和超过 6 的内容，这是大部分空间，因为最小总和为 5。 

DP 确保每个序列都计算一次，无论顺序如何，因为排列是转换结构中的不同状态。

 ## 边缘情况

 当$p = 0$，每个序列至少有和$n$，所以每个序列都获胜。 DP 会将所有质量置于零以上，并且仅正确减去 dp[0] 就可以得到$k^n - 1$仅当$n = 0$，否则满计数。 

什么时候$p = nk$，任何序列都不能超过它。 DP 将所有序列累加到总和中$nk$，减法删除所有内容，产生零。 

什么时候$k = 1$，每个序列都有相同的和$n$。 如果$n > p$，答案变为 1，否则为 0。DP 退化为单个路径，并且滑动窗口正确地减少为单个转换。
