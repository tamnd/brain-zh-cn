 ## 解决方案
 ## 问题理解

 我们得到一个开始时已按非降序排序的序列。 此后，序列不会因插入或删除而被修改，但可以循环旋转多次，无论是向左还是向右。 

除了这些轮换之外，我们还被问到两种类型的问题。 一种执行一定偏移量的旋转，有效地将阵列移动一圈。 另一种询问当前旋转数组中是否存在某个值，如果存在，我们必须报告它在当前布局中第一次出现的位置，否则输出-1。 

该语句中隐藏的重要观察结果是，旋转不会更改值的多重集或其在原始排序数组中的相对顺序。 仅索引的起点发生变化。 因此，该结构始终是通过移动圆形窗口查看的排序数组。 

约束很大，最多有 200,000 个元素和最多 300,000 个查询。 这立即排除了任何在每次移位时物理旋转阵列的方法，因为单次旋转将花费 O(N)，导致最坏情况下的 O(NQ)，这远远超出了限制。 即使为每个查询扫描数组也会太慢。 

多次旋转后的索引会出现一个微妙的问题。 如果我们错误地模拟移位，我们很容易会丢失索引 1 当前所在的位置，从而导致重复值或边界环绕的错误答案。 另一个棘手的情况是重复值，其中“第一次出现”取决于当前旋转的开始，而不是原始顺序。 

例如，考虑`a = [1,1,2]`。 右移1后，数组变为`[2,1,1]`。 查询`1`应该返回索引 2，而不是 3，因为旋转视图中的第一个 1 位于位置 2。任何只记住值的原始位置而不调整旋转的解决方案都会误报。 

## 方法

 蛮力的想法很简单。 我们显式地维护该数组。 每个移位操作使用切片或双端队列操作执行实际的循环旋转。 每个查询都会扫描整个数组以查找目标值的第一次出现。 

这是正确的，因为它确实模拟了所描述的过程。 然而，每次旋转的成本为 O(N)，每次查询的成本为 O(N)。 如果运算次数高达 300,000 次，那么在最坏的情况下这会导致大约 10^10 次运算，这是不可行的。 

关键的观察结果是阵列在旋转之前是静态的。 我们从不改变相对顺序，只改变起始索引。 这意味着我们根本不需要移动元素。 我们只需要维护一个逻辑偏移量，告诉我们哪个索引当前被认为是位置1。一旦我们修复了这个偏移量，每个查询就变成了一个简单的索引转换问题。 

为了支持快速的成员资格查询，我们利用数组是排序的，因此二分搜索适用于原始数组。 唯一的复杂之处是将原始数组中找到的索引转换为其旋转位置。 

我们结合了两个想法：用于旋转的运行偏移量和用于定位值的二分搜索。 这将每个查询减少到 O(log N)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（模拟数组）| O(NQ) | O(N) | 太慢了 |
 | 最优（偏移+二分查找）| O(Q log N) | O(Q log N) | O(N) | 已接受 |

 ## 算法演练

 我们将数组视为固定在内存中并维护一个变量`shift`表示阵列相对于其原始配置向右旋转了多少个位置。 

1. 初始化`shift = 0`。 这意味着索引对齐方式与原始数组相比没有变化。 
2. 对于移位操作`s k`，我们将其标准化为模`N`并更新班次。 右移由`k`增加偏移量，而左移则减少偏移量。 我们存储所有内容的模数`N`所以转变保持在范围内。 此步骤避免了物理旋转阵列。 
3. 查询`? x`，我们首先对原始排序数组进行二分查找，找到第一个出现的索引`i`有价值的`x`。 如果没有找到，我们立即输出`-1`。 
4.一旦我们有了索引`i`在原始数组中，我们使用移位将其转换为旋转数组中的当前位置。 原始索引`i`向前移动`shift`，所以它的新位置是`(i + shift) mod N`，转换为从 1 开始的索引。 
5. 我们输出这个计算出的位置。 

关键思想是每个元素都保持其身份和相对顺序，因此唯一改变的是我们解释索引的方式。 

### 为什么它有效

 在任何时候，数组都相当于取出原来已排序的数组并在某个位置进行切割`shift`，然后交换这两个部分。 这是一个严格的循环变换，因此保留了所有元素的相对顺序。 因此，原始数组中任何值的第 k 次出现仍然是旋转结构中的第 k 次出现，只是其索引均匀移动。 移位变量完全捕获了这种变换，因此通过它映射索引可以保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    shift = 0

    def first_occurrence(x):
        lo, hi = 0, n - 1
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if a[mid] >= x:
                hi = mid - 1
            else:
                lo = mid + 1
        if lo < n and a[lo] == x:
            return lo
        return -1

    for _ in range(q):
        parts = input().split()
        if parts[0] == 's':
            k = int(parts[1])
            k %= n
            shift = (shift + k) % n
        else:
            x = int(parts[1])
            i = first_occurrence(x)
            if i == -1:
                print(-1)
            else:
                pos = (i + shift) % n + 1
                print(pos)

if __name__ == "__main__":
    main()
```该解决方案保持阵列不变，仅保持旋转偏移。 二分查找查找原始排序数组中的第一个匹配项，这是有效的，因为排序是在旋转下保留的。 最后一步使用模运算调整索引。 唯一的微妙之处是确保模运算正确处理负移位，这就是为什么移位在应用之前被标准化的原因。

 ## 边缘情况

 一种边缘情况是数组大小为 1 时。任何移位操作都不会产生可见的效果，因为所有旋转都是相同的。 该算法可以处理此问题，因为移位始终以 N 为模，而模 1 始终为 0，因此位置映射保持稳定。 

另一种情况是重复值。 由于我们总是返回原始数组中的第一个匹配项，因此我们依赖二分搜索返回最左边的匹配项。 旋转后，即使重复项作为块移动，它们的内部顺序也会保留，因此映射索引仍然有效。 

最后一个边缘情况是大的负移。 在应用之前，使用模算术对它们进行归一化。 这可以防止移位值漂移到数组范围之外，并确保即使在多次交替的左右操作之后也能保持一致的映射。
