 ## 解决方案
 ## 问题理解

 我们给出一个从大值开始的连续整数区间`s`，特别是范围内的所有整数`[s, s + w - 1]`。 对于每个整数`n`，有一个预先定义的值`t(n)`，这是所需的步骤数`n`在 Collat​​z 过程下达到 1：如果`n`甚至我们除以 2，否则我们将其替换为`3n + 1`，重复直到达到 1。 

在给定的区间内，我们从概念上将每个整数转换为其 Collatz 停止时间值，生成一个长度的数组`w`。 任务是找到所有这些值都相同的最长连续段。 如果多个段达到最大长度，我们选择最早开始的一个。 

考虑输出的一种直接方法是，我们正在扫描从 Collat​​z 停止时间派生的数字序列，并搜索固定窗口内的最长常数运行。 

这些限制非常重要。 间隔长度`w`取决于`10^6`，因此我们可以在该范围内进行线性扫描，但是任何独立地为每个数字重新计算 Collat​​z 停止时间而不重用的方法都会面临重复高达一百万次昂贵计算的风险。 起始值`s`可以大到`10^10`，所以我们不能预先计算值`s`或依赖任何密集的预计算表。 唯一可行的方向是计算`t(n)`高效按需并尽可能重用结果。 

一种简单的方法是为每个链独立地重新计算完整的 Collat​​z 链。`w`数字。 这变得太慢了，因为即使每个链最终都会减少，中间值在收缩之前也会显着增长，从而导致重复的昂贵工作。 

有两种重要的边缘情况会破坏粗心的实现。 首先，忘记缓存结果会导致相同子链的重新计算。 例如，`t(13)`和`t(40)`两者都很快达到重叠状态； 从头开始重新计算两者都是重复的工作。 其次，解释“完全在间隔内的段”时的相差一错误可能会错误地将运行延伸到允许的窗口末端之外，特别是当恒定运行在右边界附近开始并部分溢出到外部时。 

## 方法

 暴力解决方案计算`t(n)`独立于每个`n`在`[s, s + w - 1]`使用直接 Collat​​z 模拟直到达到 1。每次计算可能需要许多步骤，并且跨越`10^6`数字这很快就变得不可行。 即使单个 Collat​​z 链平均只有几百步，总工作量也可能达到数亿次操作，并且由于重复遍历共享子路径，实际情况会更糟。 

关键的观察结果是 Collat​​z 轨迹严重重叠。 许多不同的起始值最终都会落入相同的中间状态。 这意味着一旦我们知道`t(x)`对于一些中间值`x`，我们可以对所有达到的数字重用它`x`。 

这自然会导致记忆。 我们不是重新计算停止时间，而是缓存模拟过程中遇到的所有中间数字的计算值。 每个 Collat​​z 遍历都将成为每个新发现的值的摊销常数，因为每个中间节点都会计算一次并随后重用。 

一旦我们可以计算`t(n)`有效地为每个`n`在窗口中，第二部分变成对结果数组的简单线性扫描。 我们跟踪最长的等值游程，同时保持当前游程长度及其起始位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(w·链长) | O(1) | O(1) | 太慢了 |
 | 记忆 Collat​​z + 扫描 | O(w·α) 摊销 | O(#访问过的州) | 已接受 |

 ## 算法演练

 我们将解决方案分为两个阶段：通过缓存计算 Collatz 停止时间，并扫描结果序列以查找最长的恒定段。 

1.我们维护一本字典`memo`将整数映射到其已知的 Collat​​z 停止时间。 我们初始化它`memo[1] = 0`，因为 1 需要零步才能到达自身。 
2. 对于每个数字`n`在区间内`[s, s + w - 1]`，我们计算`t(n)`使用迭代 Collat​​z 模拟。 我们保留一份临时清单`path`访问值的数量从`n`。 
3. 模拟时`n`，如果我们遇到一个已经存在于`memo`，我们立即停下来。 这很重要，因为它允许我们重用之前计算的结果，而不是继续这条链。 
4. 一旦停止，我们就会通过存储的路径反向传播已知结果。 如果我们达到一个已知值`x`和`memo[x] = k`，那么路径中的前一个值就有值`k + 1`, 之前的那个`k + 2`， 等等。 我们将所有这些计算值存储在`memo`。 
5.我们存储每个计算的`t(n)`在一个数组中`vals`与间隔对齐。 
6.我们扫描`vals`从左到右，维护当前运行值、当前运行长度和运行的起始索引。 
7. 当我们遇到等于前一个值的值时，我们延长运行时间。 否则，我们将从当前位置开始重置运行。 
8. 每当游程长度超过已知长度时，我们就会更新答案。 如果它等于最佳长度，我们将保留较早的起始索引，因为我们仅在严格较大的运行上进行更新。 

### 为什么它有效

 正确性取决于两个相关的不变量。 首先，记忆确保每个`t(x)`只计算一次并永久存储，因此每当我们再次遇到相同的中间值时，我们都会重复使用精确的正确停止时间，而无需重新计算。 反向传播步骤保留了正确性，因为 Collat​​z 停止时间满足递归式`t(n) = 1 + t(next(n))`，因此从已知端点向后重建值可以保留路径中所有节点的精确值。 

其次，扫描阶段在每个位置都保持`i`，我们正确地跟踪在或之前结束的最长恒定段`i`。 因为每个段在扩展或中断时只被考虑一次，并且更新仅在严格改进时发生，所以最终存储的段保证是最左边的最大长度游程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

memo = {1: 0}

def collatz(n):
    if n in memo:
        return memo[n]

    path = []
    x = n

    while x not in memo:
        path.append(x)
        if x % 2 == 0:
            x //= 2
        else:
            x = 3 * x + 1

    base = memo[x]

    for v in reversed(path):
        base += 1
        memo[v] = base

    return memo[n]

s, w = map(int, input().split())

vals = []
for i in range(w):
    vals.append(collatz(s + i))

best_len = 1
best_start = s

cur_len = 1
cur_start = s

for i in range(1, w):
    if vals[i] == vals[i - 1]:
        cur_len += 1
    else:
        cur_len = 1
        cur_start = s + i

    if cur_len > best_len:
        best_len = cur_len
        best_start = cur_start

print(best_len, best_start)
```功能`collatz`是核心优化。 它不是为每个输入重新计算完整的链，而是将中间结果全局存储在`memo`。 路径列表仅记录轨迹中未见过的部分，并且反转步骤将正确的距离分配回已知结果。 

最后的扫描是单遍，比较相邻值`vals`。 起始索引以绝对值维持（`s + i`）这样我们就可以直接输出需要的位置，无需进行后处理。 

一个微妙的点是，记忆化在所有查询和所有中间值中都是全局的。 这是至关重要的，因为附近数字的 Collat​​z 轨迹严重重叠，如果不共享，最坏情况下的运行时间会显着降低。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(w·α) 摊销 | 每个 Collat​​z 状态通过记忆计算一次，并且每个窗口元素在扫描 | 中处理一次。 
| 空间| O(V) | 将跨路径的所有唯一访问过的 Collat​​z 状态存储在备忘录字典中 |

 的价值`w`可以达到`10^6`，但记忆可确保重复的子路径折叠成恒定时间的查找。 这使得解决方案能够在时间限制内轻松完成，因为主要工作与遇到的不同 Collat​​z 状态的数量成正比，而不是与所有模拟链的总长度成正比。

 ## 边缘情况

 一种边缘情况是尺寸为一的窗口。 扫描永远不会进入循环，答案必须保留`(1, s)`。 的初始化`best_len = 1`和`best_start = s`无需特殊处理即可确保正确性。 

当最长的游程触及右边界时，会出现另一种边缘情况。 由于扫描仅在比较相邻值时更新，因此在循环之后仍然考虑最终运行，因为它的长度被连续跟踪并在每次扩展上进行比较。 

最后一个微妙的情况是存在多个最大段。 条件`if cur_len > best_len`确保关系不会覆盖较早的段。 因为我们只更新严格改进，所以最早的最大值会自动保留，符合选择最左边段的要求。
