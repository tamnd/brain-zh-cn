 ## 解决方案
 ## 问题理解

 我们得到一个无向友谊图`n`球员和`m`友谊的边缘。 

如果两个玩家通过友谊边直接相连，或者他们至少有一个共同的朋友，则可以组成一对。 用图术语来说，如果两个顶点在友谊图中的距离最多为，则它们可以配对`2`。 

每个玩家最多可以属于一对。 任务是输出尽可能多的配对。 

该图最多可以包含`2 · 10^5`顶点和边。 任何显式构建所有有效配对图的算法都是不可能的。 单个高度顶点可以创建 θ(n²) 距离-2 关系。 我们需要一个能够在大致线性时间内直接作用于原始图的解决方案。 

第一个关键观察结果是来自不同连接组件的玩家永远无法配对。 任何有效的对必须完全位于一个连接的组件内。 

第二个观察结果更令人惊讶。 对于包含以下内容的连接组件`s`顶点，总是可以精确地创建`⌊s / 2⌋`对。 由于没有任何组件可以贡献超过`⌊s / 2⌋`无论如何，这是最大的。 

这减少了有效构建此类配对的问题。 

考虑一个由单个孤立顶点组成的组件：```
1
```正确答案是`0`对。 盲目尝试将每个 DFS 父级与子级配对的粗心实现将创建无效的对。 

考虑长度为三的路径：```
1 - 2 - 3 - 4
```玩家`1`和`3`可能会配对，因为他们有共同的朋友`2`，以及玩家们`2`和`4`可能会配对，因为他们有共同的朋友`3`。 正确答案是`2`对。 仅查看友谊边缘会错误地只找到一对。 

考虑一颗星星：```
    2
    |
3 - 1 - 4
    |
    5
```所有叶子都是成对兼容的，因为它们共享玩家`1`作为共同的朋友。 正确答案是`2`对。 任何只考虑原始图边的解决方案都会错过这些配对。 

## 方法

 强力解决方案将首先构建所有有效配对的图表。 对于每个顶点，我们将其连接到所有朋友以及仅用两步即可到达的所有顶点。 构建此图后，我们将搜索最大匹配。 

问题是距离 2 图可以包含 θ(n²) 条边。 一颗星与`2 · 10^5`顶点已经创建了几乎`2 · 10^5²`叶子之间的有效配对。 构建该图是不可能的。 

突破来自于忽略图表的大部分内容。 

取任何连接的组件并在其中选择任意 DFS 树。 该树之外的每一条友谊边都只是一条额外的边。 如果我们已经能够实现`⌊s / 2⌋`仅使用 DFS 树对，则附加边是无关的，因为`⌊s / 2⌋`是理论最大值。 

所以真正的问题就变成了：

 给定一棵树，将尽可能多的顶点配对，使得每对顶点之间的距离最大`2`。 

自下而上的 DFS 正是我们所需要的。 

对于每个节点，处理完所有子节点后，某些子子树可能仍包含一个不匹配的顶点。 任何两个这样的不匹配的孩子都可以配对在一起，因为他们的距离恰好是`2`通过当前节点。 

在将子代表彼此配对后，如果仍然存在一个不匹配的子节点，我们将该子节点与当前节点配对。 他们的距离是`1`。 

这会贪婪地从树中删除顶点，同时保证每个创建的对都是有效的。 

在 DFS 结束时，每个分量最多留下一个不匹配的顶点，这意味着我们准确地获得`⌊s / 2⌋`对。 

相同的 DFS 在原始图上的工作原理不变。 我们只需遍历每个连接组件的一棵 DFS 树并忽略所有非树边。 

该解决方案以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(n²) | 太慢了|
 | 最优DFS构建| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构建友谊图的邻接表。 
2. 从每个未访问的顶点开始 DFS。 每个 DFS 只探索一个连接的组件。 
3. 对于一个节点`u`，递归处理所有未访问的子项。 
4. 每个子 DFS 返回该子树的子树是否仍包含一个不匹配的代表。 
5. 收集所有未匹配的子代表。 
6. 一次将这些代表配对两个。 

如果代表来自儿童`a`和`b`， 然后`a`和`b`分享共同的朋友`u`，所以该对是有效的。 
7. 将尽可能多的子代表配对后，添加`u`本身到集合中。 
8. 再次将集合的元素一次配对两个并存储这些对。 
9. 如果集合大小为奇数，则只有一个代表保持不匹配。 将该信息返回给家长。 
10. 继续，直到整个组件处理完毕。 

### 为什么它有效

 DFS 维护一个简单的不变量。 

完成一个节点的子树后`u`，该子树中的所有顶点都已经配对，除了可能向上返回的一个代表之外。 

每当存在两个不匹配的子代表时，它们就可以安全地配对，因为两者都与`u`在DFS树中。 他们的距离正好是`2`。 

如果还有一个不匹配的孩子，则将其与`u`有效，因为它们的距离是`1`。 

结果，每个操作都会创建一个合法的对，并将不匹配顶点的数量减少两个。 

具有尺寸的组件`s`根结束后最多可以留下一个不匹配的顶点。 因此确切地说`⌊s / 2⌋`产生对。 由于没有匹配可以使用超过`⌊s / 2⌋`成对，结构是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

n, m = map(int, input().split())

adj = [[] for _ in range(n)]

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

vis = [False] * n
ans = []

def dfs(u):
    vis[u] = True

    rem = []

    for v in adj[u]:
        if vis[v]:
            continue

        if dfs(v):
            rem.append(v)

    rem.append(u)

    for i in range(1, len(rem), 2):
        ans.append((rem[i - 1] + 1, rem[i] + 1))

    return len(rem) % 2 == 1

for i in range(n):
    if not vis[i]:
        dfs(i)

print(len(ans))
print("\n".join(f"{u} {v}" for u, v in ans))
```邻接表存储原始的友谊图。 

DFS 仅访问树的边缘。 组件中的任何额外边都将被忽略，因为仅 DFS 树就足以实现最佳对数。 

名单`rem`存储其子树仍包含一个不匹配代表的子顶点。 处理完所有子节点后，当前节点将添加到同一列表中。 

配对连续元素`rem`是安全的。 两名儿童代表在远处`2`通过当前节点，而子代表与当前节点有一定距离`1`。 

返回值指示在子树内所有可能的配对之后是否只有一个代表保持不匹配。 

该实现在内部使用基于 0 的索引，并在存储答案时转换回基于 1 的索引。

 ## 边缘情况

 考虑一个包含单个顶点的组件：```
1 0
```DFS 访问顶点并创建`rem = {1}`。 无法形成配对。 该函数返回一个不匹配的代表，最终答案包含零对。 这是最佳的。 

考虑星图：```
5 4
1 2
1 3
1 4
1 5
```树叶`2`,`3`,`4`， 和`5`所有人都作为无与伦比的代表回归。 在节点处`1`，列表变为：```
{2, 3, 4, 5, 1}
```算法对`(2,3)`和`(4,5)`。 每对都有共同的朋友`1`，所以两者都有效。 由于组件大小为奇数，因此有一个顶点保持不匹配。 

考虑路径：```
4 3
1 2
2 3
3 4
```自下而上的处理创建最终允许配对的代表`(4,3)`和`(2,1)`。 每对都通过友谊边连接，因此两者都是有效的。 所有四个顶点都匹配，达到理论最大值`2`对。 

同样的推理可以扩展到任意连接的组件。 DFS 树单独保证`⌊s/2⌋`对，这对于大小的组件来说已经是最佳的`s`。
