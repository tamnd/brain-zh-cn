 ## 解决方案
 ## 问题理解

 我们收集了一些箱子和钥匙。 每个箱子都有一定的价值，每个钥匙都有一个价格。 爱丽丝可以在箱子上加锁，而锁需要特定的钥匙。 鲍勃选择购买任何钥匙子集，支付费用，然后准确地打开他拥有所有所需钥匙的箱子。 Alice 希望选择锁，这样 Bob 就永远无法获得正利润，同时为放置这些锁支付尽可能少的费用。 

输入描述了箱子和钥匙的数量、箱子的价值、钥匙的价格以及在每个箱子上安装每种可能类型的锁的成本。 输出是保证 Alice 获胜的最小总锁定成本，或者`-1`如果没有任何锁的排列可以工作。 

箱子和钥匙的数量限制很少。 两者都最多为 6，胸部值最多为 4。锁的成本可能很大，高达 10^7，因此算法不能依赖于尝试所有可能的总成本。 由于只有几个箱子和钥匙，因此预期的解决方案使用小尺寸来压缩状态空间。 任何直接考虑每个可能的锁分配的方法每个箱子最多有 64 个选择，提供 64^6 种可能性，这对于一个舒适的解决方案来说已经太大了。 

一个常见的错误是认为在一个有价值的箱子里添加很多锁就足够了。 这些锁必须与鲍勃可以购买的每组可能的钥匙一起工作。 例如：```
1 2
4
1 1
5 5
5 5
```如果唯一的箱子需要两把钥匙，鲍勃就会购买两把钥匙，获得价值 4，并支付 2，所以他赢了。 输出必须是`-1`。 仅检查所有箱子的总价值是否小于总密钥成本的粗心解决方案在这里会失败，因为允许 Bob 选择较小的子集。 

另一个边缘情况是当所有钥匙都无法覆盖总宝箱价值时。 例如：```
1 1
4
1
10
```没有锁装置可以提供帮助，因为鲍勃总是可以购买唯一的钥匙并打开箱子。 正确的输出是`-1`。 

## 方法

 直接的方法是为每个箱子分配一组最终所需的钥匙。 对于每个箱子，我们可以尝试密钥的每个子集，然后检查鲍勃做出的每个可能的选择是否都会给他带来非正利润。 这是正确的，因为最终的锁排列完全决定了 Bob 可能的操作。 问题是每个箱子最多有 2^6 个可能的锁组，因此搜索空间增长到 64^n。 对于六个箱子来说，这是数亿种组合，每种组合都需要检查许多钥匙子集。 

关键的观察结果是箱子的价值非常小。 想想是什么阻止鲍勃打开箱子。 有价值的箱子`x`只需要`x`在最优解中分配给它不同的锁。 如果胸部有超过`x`锁，其中之一对于解决方案背后的最小割论证来说是不必要的。 这意味着每个箱子只需要跟踪它收到了多少锁，而不是确切的历史记录。 

我们一一处理密钥。 对于当前的钥匙，我们决定有多少个箱子收到这个锁。 该状态存储了每个箱子到目前为止收集的锁的数量。 处理完所有钥匙后，每个箱子都必须准确地收集到其价值的锁。 原因是鲍勃打开的任何一组箱子都可以根据这些箱子所需的不同钥匙进行收费。 达到所需的锁定数量使得所有可能的盈利组合都变得不可能。 

DP 过渡很小，因为只有 6 把钥匙，每个箱子最多需要 4 个锁。 状态空间最多是几个计数器的 5^6 倍，很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((2^m)^n * 2^m) | O((2^m)^n * 2^m) | O(1) | O(1) | 太慢了|
 | 最佳| O(m * 5^n * 5^n) | O(5^n) | O(5^n) | 已接受 |

 ## 算法演练

 1. 创建一个 DP 状态，表示在处理某些钥匙前缀后每个箱子有多少把锁。 最初，每个箱子的锁都是零，并且没有处理任何钥匙。 该状态就足够了，因为未来的决策仅取决于每个箱子还需要多少锁。 
2. 按顺序处理按键。 对于当前的钥匙，尝试一切可能的方式将该钥匙的锁分配给各个箱子。 钥匙可以放在箱子上，也可以不放在箱子上，同一把钥匙可以用作多个箱子的锁。 
3. 当箱子收到这把钥匙时，将其锁定计数增加一。 如果钥匙至少在一个箱子上使用，请添加将此钥匙放置在第一个这样的箱子上的成本，并小心处理过渡，以便每个箱子钥匙对只需支付一次成本。 
4.所有钥匙处理完成后，检查每个箱子的状态`a[i]`锁。 这是唯一一个爱丽丝有足够的限制来保证鲍勃无法获利的状态。 
5. 如果最终状态无法到达，则打印`-1`。 否则，存储的最小成本就是答案。 

为什么它有效：

 不变的是，在处理一些密钥之后，DP 值是仅使用那些处理过的密钥来精确创建存储数量的锁的最便宜的方法。 该转换枚举了下一个键的所有可能用法，因此不会跳过任何有效的构造。 最终的要求是每个箱子必须有足够的独立限制，以使任何打开的箱子的总价值不大于所需钥匙的成本。 由于表示了每个可能的锁分配，因此最小可达到的最终状态正是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = [list(map(int, input().split())) for _ in range(n)]

    start = tuple([0] * n)
    dp = {start: 0}

    for key in range(m):
        ndp = {}
        for state, cost in dp.items():
            def dfs(i, cur, add_cost):
                if i == n:
                    ndp[tuple(cur)] = min(ndp.get(tuple(cur), 10**30), cost + add_cost)
                    return
                for take in range(a[i] - cur[i] + 1):
                    cur[i] += take
                    dfs(i + 1, cur, add_cost + (c[i][key] if take else 0))
                    cur[i] -= take

            dfs(0, list(state), 0)

        dp = ndp

    target = tuple(a)
    ans = dp.get(target, None)
    print(-1 if ans is None else ans)

solve()
```输入处理读取完整的成本矩阵，因为每个可能的箱子钥匙对都可以出现在最终答案中。 DP 字典仅保留可达状态，这避免了存储未使用的组合。 

转换会递归地尝试将当前密钥添加到每个箱子中多少次。 一把钥匙只能为每个箱子贡献一把锁，但状态表示会计算已分配给该箱子的已处理钥匙的数量。 递归是有界的，因为每个箱子最多需要四个锁。 

最终查找使用包含所有胸部值的元组。 这是目标，因为有价值的宝箱`a[i]`压缩配方中正好需要那么多锁。 如果从未达到该状态，爱丽丝就无法强行获胜。

 ## 边缘情况

 当所有箱子的总价值大于所有钥匙的总价值时，爱丽丝无法获胜，因为鲍勃可以简单地购买所有钥匙。 该算法处理这个问题是因为需要足够锁的最终状态是无法到达的。 在示例中：```
1 1
4
1
10
```处理完密钥后的唯一状态不足以阻止价值4的箱子，所以答案是`-1`。 

当多个箱子争夺同一个廉价密钥时，贪婪的解决方案可能会失败。 DP 会考虑每个密钥的所有分布，因此它可以决定在一个箱子上留下未使用的廉价钥匙，并在另一个箱子上花费更多的钱（如果这是达到最终安全状态的唯一方法）。 

为了：```
2 3
3 3
1 1 4
10 20 100
20 15 80
```算法达到`(3,3)`仅在以正确的组合使用所有三种钥匙类型之后。 它不会停留在局部廉价的选择上，因为中间状态是在全球范围内进行比较的。
