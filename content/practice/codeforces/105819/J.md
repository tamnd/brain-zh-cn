 ## 解决方案
 ## 问题理解

 该问题描述了一个排列成循环的动物园`n`地点。 访客选择起始位置`a`, 结束位置`b`，以及它们之间围绕循环的两条可能路径之一。 选择的路径必须足够短，最多`k`边缘。 然后，访客进行一次步行，起始和结束时间为`a`，从不离开所选路径，访问所选路径上的每个位置，且总长度最多`m`。 任务是计算所有可能的走模数`10^9+7`。 

关键部分是了解所选路径是什么样的。 一旦方向固定，循环段就变成一条直线。 如果段有长度`d`，它包含位置`0, 1, ..., d`，其中位置`0`是起始位置。 步行开始于`0`，必须结束于`0`，并且必须到达位置`d`至少一次。 

这些限制推动解决方案走向动态规划。 路径长度`k`可以大到`100000`，但步行距离`m`只是`2000`。 一次到达远方的步行`d`并返回到开始至少需要`2d`移动，所以只有`d <= 1000`永远重要。 这意味着我们可以根据步行长度而不是周期大小提供状态空间。 

一些边缘情况很容易被忽略。 如果步行长度太小而无法到达最远端点，则不应计算在内。 例如，输入：```
10 5 1
```答案是：```
0
```因为每个有效选择的段的长度至少`1`，但到达另一端并返回至少需要两步。 

另一种情况是长度恰好为一的路径。 为了：```
4 3 2
```所选边上的有效行走仅`0 -> 1 -> 0`。 每个起点都有两个可能的方向，所以答案是`4 * 2 = 8`。 仅计算路径并忽略所选方向的解决方案将返回正确答案的一半。 

第三个常见错误是计算到达远端但没有返回的步行。 为了：```
5 5 1
```一个序列`0 -> 1`无效，因为它没有在开始处结束。 结束条件是步行定义的一部分。 

## 方法

 直接的蛮力方法将尝试每个可能的起始位置、每个可能的方向、每个可能的路径长度，然后枚举该路径上的所有行走。 这是正确的，因为它完全遵循定义。 然而，可能的步行数量呈指数增长。 长度`m`walk 每一步最多有两个选择，因此搜索空间大致为`O(2^m)`，这是不可能的，当`m = 2000`。 

问题的结构提供了一种更好的计算方法。 循环本身只提供一个倍增因子：在计算一条固定线段上的行走次数后，我们可以选择该线段的起点以及它是顺时针还是逆时针。 

剩下的任务是计算一条线上的行走次数。 我们只需要知道距起始端点的当前距离。 后`i`如果我们处于位置，则移动`j`，下一步要么增加`j`或减少`j`。 我们不能低于零或高于最大允许距离。 由于我们只关心是否已到达远端端点，因此我们可以计算每个可能的最大距离的步行，并添加返回零的步行。 

有用的观察是步行一段距离`i`结束于位置`j`可以根据之前的长度计算。 转换仅取决于相邻位置，因此一个简单的动态规划表就足够了。 我们建立各种长度的状态`m`，保持当前距离。 以上职位`k`是不必要的，因为所选段不能长于`k`。 

计算这些值后，有效行走的数量是行走返回位置的所有长度的总和`0`并且具有正的最大距离。 DP状态可以解释为已经到达所需终点的步行，因为每个位置`j`代表所选线段的端点。 最后的计数乘以`2n`对于两个方向和`n`可能的起始位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^m) | O(2^m) | O(米) | 太慢了|
 | 最佳| O(m * 分钟(k, m)) | O(m * 分钟(k, m)) | 已接受 |

 ## 算法演练

 1. 创建一个动态规划表，其中`dp[i][j]`代表走一段长度的方法的数量`i`并在远处完成`j`从起点开始。 距离的上限为`k`因为无法选择更长的路径。 
2. 初始化`dp[0][0] = 1`。 在做出任何动作之前，步行者处于起点。 
3. 对于从`1`到`m`，更新每个可能的距离。 到达远方`j`，之前的位置一定是`j - 1`或者`j + 1`。 这些对应于先前移动的两个可能的方向。 
4. 保持位置`0`仅限于有效的转换。 从一开始就向左移动是不可能的，因此状态不能变为负值。 
5. 对所有状态求和`dp[i][0]`为了`i >= 1`。 这些是在经过一定次数的移动后返回起始位置的步行。 
6. 将结果乘以`2n`。 有`n`起始位置的选择和所选路径方向的两个选择。 

DP 背后的不变量是`dp[i][j]`精确计算长度游走的所有有效前缀`i`结束于位置`j`。 每个可能的下一步移动都会被考虑一次，并且永远不会添加路径之外的无效移动。 当状态到达位置时`0`，它描述了满足返回条件的完整行走。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())

    limit = min(k, m)
    dp = [[0] * (limit + 2) for _ in range(m + 1)]
    dp[0][0] = 1

    for length in range(1, m + 1):
        for pos in range(limit + 1):
            if pos > 0:
                dp[length][pos] += dp[length - 1][pos - 1]
            if pos < limit:
                dp[length][pos] += dp[length - 1][pos + 1]
            dp[length][pos] %= MOD

    ans = 0
    for length in range(1, m + 1):
        ans += dp[length][0]
        ans %= MOD

    ans = ans * (2 * n) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```桌子的大小是根据`min(k, m)`而不是`k`直接地。 即使`k`是巨大的，步行不能到达的距离大于`m`，所以这些国家永远不会捐款。 

转换会检查两个相邻位置。 第一个条件防止从起点向左移动，而第二个条件防止移动超出所选线段长度。 在数组中使用额外的列使得`pos + 1`无需特殊处理即可安全访问。 

最终的乘法发生在 DP 之后，因为循环的几何形状与运动计数无关。 DP 从一个端点开始计算一个定向段，并且循环仅选择该段的放置位置。

 ## 边缘情况

 当最大行走长度太小时，DP 自然会将所有返回状态保留为零。 在`2 1 1`，唯一可能的运动是从一侧到另一侧，但步行者无法返回，因此答案保持为零。 

当所选路径的长度为一时，唯一有效的步行是穿过边缘并立即返回。 DP 计算位置序列`0 -> 1 -> 0`作为一次归程。 最后的乘法处理该边在循环中可能的位置。 

什么时候`k`远大于`m`，仅距离可达`m`事情。 路径长度大于`m / 2`永远无法到达和返回，因此被忽略的状态不会影响答案。 这就是为什么限制 DP 尺寸是安全的。
