 ## 解决方案
 ## 问题理解

 我们得到一个由三个可能的字符组成的字符串：`'('`,`')'`， 和`'?'`。 

对于每个子串，我们询问是否可以通过替换每个子串将其变成非空的正确括号序列`'?'`独立地与任一`'('`或者`')'`。 这样的子串称为_pretty_。 

任务是计算有多少子串是漂亮的。 

正确的括号序列有两个定义属性。 它的左括号和右括号的总数相等，并且从左到右扫描时，右括号的数量永远不会超过左括号的数量。 

字符串长度最多为5000。大约有$$\frac{n(n+1)}{2}$$子串，大约有 1250 万个$n=5000$。 任何对每个子串执行大量工作的算法都非常昂贵。 三次解是完全不可能的，即使是简单的二次解也必须具有非常小的常数因子。 

一些边缘情况使问题比普通的括号验证更加棘手。 

考虑字符串：```
??
```答案是 1，因为我们可以将其替换为`"()"`。 

一个简单的检查可以治疗`'?'`作为匹配任何内容的通配符都会错误地计算许多无效子字符串。 

考虑：```
?)
```答案也是1.更换`'?'`和`'('`给出`"()"`。 

在决定替换之前坚持当前前缀平衡必须已经非负的方法将错误地拒绝该子字符串。 

考虑：```
(((
```答案是 0。即使不存在无效前缀，左括号和右括号的总数也永远不会相等。 

另一个微妙的例子是：```
???
```答案是1。只有长度为2的子串才是候选。 整个长度为 3 的子串永远不会变得平衡，因为每个正确的括号序列都有偶数长度。 

任何方法都必须同时处理前缀约束和动态选择替换的能力。 

## 方法

 最直接的解决方案是枚举每个子字符串并确定其问号的某些赋值是否会产生正确的括号序列。 

强力版本将枚举所有子字符串，并针对每个子字符串尝试其问号的所有可能替换。 即使是有 20 个问号的子字符串也已经有超过一百万个赋值，这使得这完全不可行。 

更好的暴力想法是枚举每个子字符串并贪婪地检查它是否可以完成为有效的序列。 有$O(n^2)$子字符串，每次检查都需要$O(n)$，导致$O(n^3)$时间。 和$n=5000$，这已经远远超出了极限。 

关键的观察是我们不需要为每个结束位置从头开始重新验证。 

固定起始位置$l$。 现在延伸右端点$r$一次一个字符。 

扫描时，保持两个数量。 

第一个数量是做出贪婪选择后的当前余额。 每当我们看到`'('`，余额增加。 每当我们看到`')'`，余额减少。 每当我们看到`'?'`，我们暂时将其视为`'('`，增加平衡。 

第二个数量是有多少个问号被视为`'('`迄今为止。 这些选择中的任何一个都可以稍后翻转到`')'`，将余额减少 2。 

每当余额变为负数时，我们立即转换之前使用的余额`'?'`从`'('`到`')'`。 这会使余额减少 2 并消耗一次可用的问号转换。 如果没有可用的转换，则从此开始的每个较长的子字符串$l$will also fail, so we stop.

 这个贪婪的过程使余额尽可能小，同时不让任何前缀无效。 

每当当前子串长度为偶数且结果余额恰好为零时，我们就找到了一个漂亮的子串。 

既然我们修复了$l$并延伸$r$每对一次$(l,r)$仅处理一次。 复杂度变为$O(n^2)$，这是可以接受的$n=5000$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子串验证 | O(n3) | O(1) | O(1) | 太慢了 |
 | 从头开始贪婪扫描 | O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将答案初始化为零。 
2. 选择起始位置$l$。 
3. 设置`balance = 0`。 
4. 设置`free = 0`，代表当前有多少个问号被视为`'('`并且以后仍然可以翻转。 
5. 延长结束位置$r$从$l$到字符串的末尾。 
6. 如果`s[r]`是`'('`, 增量`balance`。 
7. 如果`s[r]`是`')'`, 递减`balance`。 
8. 如果`s[r]`是`'?'`, 两者都增加`balance`和`free`。 

这相当于暂时选择`'('`。 
9. 虽然`balance > 0`和`free > balance // 2`不是正确的条件。 相反，每当`balance`变得太大，因为我们积累了许多临时的`'('`，我们还什么都不做。 我们仅在检查有效性时做出反应。 
10.如果`balance < 0`，尝试翻转一个先前可用的问号。 

翻转改变选择`'('`进入`')'`，余额减少 2。 

在实现中，这是通过以下方式完成的：```
balance += 2
free -= 1
```11. 如果尝试修复后余额仍然为负，则停止处理该起始位置。 不再有扩展可以修复已经无效的前缀。 
12. 每当当前子串长度为偶数并且`balance == 0`，增加答案。 
13. 对每个起始位置重复此操作。 

### 为什么它有效

 对于固定的起始位置，每个问号最初被视为`'('`。 This maximizes future flexibility because any such choice can later be converted into`')'`。 

每当余额变为负数时，有效的括号序列就需要在此点之前附加左括号。 获得它们的唯一方法是重新解释之前的一个问号。 立即执行此修复是强制性的，并且不会损害未来的可能性。 

该算法始终在所有分配之间保持最小的可行平衡，使每个处理的前缀都为非负。 如果余额在偶数位置达到零，则存在某些分配，其前缀全部有效且总余额为零。 该赋值形成了正确的括号序列。 相反，如果没有达到这样的状态，则任何赋值都不能同时满足这两个条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    ans = 0

    for l in range(n):
        balance = 0
        free = 0

        for r in range(l, n):
            if s[r] == '(':
                balance += 1
            elif s[r] == ')':
                balance -= 1
            else:
                balance += 1
                free += 1

            if balance < 0:
                if free == 0:
                    break
                balance += 2
                free -= 1

            if (r - l + 1) % 2 == 0 and balance == 0:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```外循环固定子字符串的左端点。 

对于每个起始位置，我们仅扫描右端点一次。 变量`balance`和`free`总结有关当前子字符串所需的所有信息。 

问号最初被视为左括号。 这既增加了`balance`和`free`。 价值`free`记录其中有多少试探性选择仍可用于转换。 

当右括号导致余额变为负数时，唯一可能的修复是将之前的问号重新解释为右括号。 这种变化会通过以下方式修改平衡：`+2`相对于当前状态，因为该角色之前已做出贡献`+1`现在贡献`-1`。 

中断条件至关重要。 如果余额为负且不存在未使用的问号，则当前前缀永久无效。 扩展子字符串不能更改已经失败的前缀，因此不需要进一步的工作。 

奇偶校验也是必不可少的。 正确的括号序列必须具有相同数量的左括号和右括号，这意味着长度均匀。 仅平衡零是不够的。

 ## 边缘情况

 考虑：```
?)
```算法流程`'?'`作为`'('`，给予平衡1.读完后`')'`，balance变为0，统计偶数长度的子串。 输出是1，这是正确的。 

考虑：```
(((
```余额为 1、2 和 3。永远不会达到零，因此不会计算任何子字符串。 输出为0。 

考虑：```
???
```长度为 1 的子串将被忽略，因为平衡序列必须具有偶数长度。 长度为2的子串可以变成`"()"`并被计算在内。 长度为 3 的子字符串永远不能具有相同数量的左括号和右括号。 该算法返回 2，正好对应于两个长度为 2 的子字符串。 

考虑：```
))((
```对于任何起始位置，在任何问号可用于修复之前，余额都会变为负值。 扫描立即停止。 输出为0，符合没有子串可以转换为正确的括号序列的事实。
