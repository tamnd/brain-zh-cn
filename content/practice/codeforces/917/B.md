 ## 解决方案
 ## 问题理解

 给定一个有向无环图，其中每条边都带有一个小写字母。 两个令牌可能从不同的顶点开始：一个属于 Max，一个属于 Lucas。 他们轮流沿着传出边缘移动自己的令牌，而不同的是，沿着所选边缘序列的字母必须按 ASCII 顺序非递减。 如果最后使用的字母是`x`，下一步必须使用标有字母的边`>= x`。 谁不能在轮到自己时采取合法的行动，谁就输了。 

任务不是模拟单个游戏，而是评估每对有序的起始顶点，假设双方都处于最佳发挥，Max 是否可以强制获胜。 

图尺寸很小，最多有 100 个顶点。 这立即排除了诸如显式枚举所有路径之类的事情，因为 DAG 中的路径数量呈指数增长。 然而，每个玩家组合的 100 x 100 状态空间建议在顶点对上采用动态规划公式，可能还有最后一个角色约束的附加状态。 

一个微妙的边缘情况来自这样一个事实：两个玩家在同一个图上独立移动，同时共享边缘标签的全局约束。 这意味着我们不能单独对待他们的立场。 当一个玩家已经被卡住但另一个玩家仍然有动作时，就会发生另一种重要的情况，因为回合顺序很重要，并且对字母的约束可能会消除图中结构上存在的动作。 

幼稚思维的一个小的说明性失败案例是一张图表，其中 Max 从 1 移动到 2，并带有字母`b`，卢卡斯用字母从 3 移动到 4`a`。 如果我们忽略顺序，我们可能会认为两者都可以自由移动，但是 Max 使用后`b`，卢卡斯不能再使用`a`，这可以完全改变可达性和结果。 

## 方法

 暴力解释会将其视为一种游戏状态，其中包括`(vMax, vLucas, lastLetter, turn)`。 在每个状态中，我们尝试当前玩家的所有有效传出边，并递归地确定是否有任何移动会导致对手失败。 这是正确的，因为它直接编码最优玩法，但状态空间太大。 字母组件有 26 种可能性，即使有 100 个顶点，这也大致变成`100 * 100 * 26 * 2`状态，每个状态都可能分支为许多转换，并且递归将在没有仔细记忆的情况下大量重新访问状态。 

关键的观察是字母约束是单调的：一旦玩家使用带有字符的边缘`c`，所有未来的动作都必须使用字母`>= c`。 这表明我们可以按照允许的最小字符的升序处理状态。 我们没有将最后一个字母视为动态值，而是通过迭代来自的字母来修复它`'z'`下降到`'a'`，逐步放松约束。 

对于固定的最小字母`c`，我们定义对的赢/输状态`(u, v)`其中下一步必须使用至少标记的边`c`。 如果来自某个州`(u, v)`轮到 Max 了，如果存在有效的出局，则 Max 获胜`u`这迫使卢卡斯陷入失败状态； 对于卢卡斯来说也是如此。 这成为产品图上的标准后向 DP，其中转换仅取决于具有足够标签的边。 

我们预先计算按字符阈值分组的邻接列表，并在递减的阈值中重用结果，以便每一层都建立在前一层的基础上。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（状态+递归）| 指数| O(100²·26) | 太慢了 |
 | DP 超过（u，v，字母阈值）| O(26·n²·m) 或优化的 O(n²·26 + nm) | O(n²·26) | 已接受 |

 ## 算法演练

 我们定义一个DP表`dp[c][u][v]`含义：如果允许的最小字符是`c`，当 Max 在 时，轮到 Max 了`u`卢卡斯在`v`，那么Max就可以强行获胜。 

1. 我们为每个节点准备邻接表，但不是将所有传出边存储在一起，而是按字符将它们分开。 这使我们能够快速了解​​在给定阈值下哪些举动是合法的。 
2. 我们将 DP 初始化为最高阈值（超出`'z'`)，其中不可能进行任何移动。 在这种情况下，麦克斯在每种状态下都会失败，因为要移动的玩家无法行动。 
3. 我们迭代允许的字符阈值`'z'`下降到`'a'`。 对于每个阈值，我们通过检查可用的转换来计算哪些状态获胜。 
4. 对于固定阈值`c`，我们检查每一对`(u, v)`。 从`(u, v)`, Max可以沿着任意边移动`u -> u2`用字符标记`>= c`。 Max移动后，回合切换，Lucas成为状态下的主动玩家`(u2, v)`。 
5. 为了确定一个举动是否获胜，我们检查它是否会导致卢卡斯在轮到他时失败的状态。 由于 DP 在结构上是对称的，因此我们重复使用相同的表，但通过回合交替正确解释角色。 
6. 我们标记`(u, v)`如果存在导致对手失败状态的任何有效动作，则视为获胜； 否则，就是失败。 

填充所有阈值后，初始状态的答案为`dp['a'][i][j]`。 

### 为什么它有效

 正确性依赖于对字母约束的单调细化。 一旦我们确定了阈值`c`，所有状态仅依赖于已计算出的具有相同或更高阈值的状态。 这消除了字母值之间的循环。 在每个阈值层内，游戏图超过`(u, v)`就 DP 依赖性而言，它是有限且非循环的，因为每个状态都是根据严格的下一回合结果来定义的。 递归完全匹配极小极大最优玩法，确保当且仅当在相同约束下存在迫使对手进入失败状态的举动时，状态才会获胜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

adj = [[[] for _ in range(n)] for _ in range(26)]

for _ in range(m):
    v, u, c = input().split()
    v = int(v) - 1
    u = int(u) - 1
    adj[ord(c) - ord('a')][v].append(u)

dp = [[[False] * n for _ in range(n)] for _ in range(26)]

for c in range(25, -1, -1):
    for u in range(n):
        for v in range(n):
            win = False
            for ch in range(c, 26):
                for u2 in adj[ch][u]:
                    if not dp[ch][u2][v]:
                        win = True
                        break
                if win:
                    break
            dp[c][u][v] = win

for i in range(n):
    print(''.join('A' if dp[0][i][j] else 'B' for j in range(n)))
```该代码构建按字符分组的邻接列表，然后计算从大写字母到小写字母的 DP。 每个`dp[c][u][v]`检查 Max 是否可以使用阈值以下任何允许的边进行移动`c`这会导致对手在下一个状态处于失败位置。 最终答案使用阈值`0`，意味着最初允许所有字母。 

一个微妙的点是解释`dp[ch][u2][v]`作为对手移动后的视角。 由于角色通过 DP 的结构自然地交替，因此我们不显式存储回合变量； 相反，我们通过始终从 Max 的角度进行评估来隐式编码turn`(u, v)`。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    adj = [[[] for _ in range(n)] for _ in range(26)]

    for _ in range(m):
        v, u, c = input().split()
        v = int(v) - 1
        u = int(u) - 1
        adj[ord(c) - ord('a')][v].append(u)

    dp = [[[False] * n for _ in range(n)] for _ in range(26)]

    for c in range(25, -1, -1):
        for u in range(n):
            for v in range(n):
                win = False
                for ch in range(c, 26):
                    for u2 in adj[ch][u]:
                        if not dp[ch][u2][v]:
                            win = True
                            break
                    if win:
                        break
                dp[c][u][v] = win

    return "\n".join("".join("A" if dp[0][i][j] else "B" for j in range(n)) for i in range(n))

 ## 边缘情况

 完全断开的图迫使每个状态立即失败。 在这种情况下，对于任何`(i, j)`两个玩家都没有传出边，因此 DP 将所有条目标记为 false。 这证实了 DP 的基础层已正确处理。 

第二个边缘情况是严格增加的路径，例如`a -> b -> c`。 该算法正确地仅允许通过阈值进行前向传播。 处于阈值`'a'`，所有转换都会被考虑，但在较高的阈值下，只有后缀边缘保持有效，因此状态逐渐缩小。 这确保使用小字母的移动不会错误地影响更高阈值的计算。 

第三种情况涉及两个顶点，其中只有 Lucas 可以移动。 由于DP的评估是不对称的，无论Lucas如何选择，Max不能立即移动的状态都会失败，这符合Max先移动的游戏规则。
