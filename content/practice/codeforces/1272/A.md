 ## 解决方案

 ## 问题理解

 三个朋友坐在数轴上的位置$a$,$b$， 和$c$。 在一次移动中，每个朋友最多可以向左移动一个单位，向右移动一个单位，或者留在原地。 在恰好一次同时移动之后，我们查看它们的分散程度，并将该分散测量为其最终位置之间的成对距离之和。 

任务是为所有三个人选择动作，以使两对总距离变得尽可能小。 

关于输入的关键观察是每个测试用例都是独立的并且仅由三个整数组成，因此每个用例都可以在恒定时间内解决。 拥有多达 1000 个测试用例，超出范围的任何解决方案$O(q)$或者$O(q \log q)$是不必要的，但即使$O(q)$具有大量常数就可以了。 

真正重要的限制不是规模而是结构。 该系统只有三个点，每个点只有一个移动单位，可达到的配置非常有限。 这使得对所有移动组合的暴力破解原则上都是可行的，但我们仍然需要认识到目标的几何形状。 

例如，当所有位置都相等时，会出现微妙的边缘情况$a=b=c=5$。 然后，任何将它们保持在一起的移动都会产生零成本，并且任何假设不同排序或仅计算端点移位的天真的方法如果忘记合并已经是最佳的，则可能会失败。 

另一种边缘情况是当两个点重合而第三个点相距较远时，例如$1, 1000000000, 1000000000$。 幼稚的“贪婪地走向彼此”的做法必须小心处理每人只能拥有一个单位； 你无法完全消除大的差距。 

## 方法

 一种直接的方法是尝试每个朋友的举动的所有可能性。 每个朋友都有三个选择：向左移动、留下或向右移动。 这给出了$3^3 = 27$每个测试用例可能的最终配置。 对于每种配置，我们计算成对距离总和并取最小值。 这已经足够快了，因为$27 \cdot 1000$可以忽略不计。 

这是可行的，因为状态空间非常小。 成本函数也很容易在恒定时间内评估。 

然而，物镜的结构可以提供更清晰的视野。 三个点之间的成对距离之和仅取决于它们的排序顺序。 如果我们将最终位置排序为$x \le y \le z$，则表达式变为：$$|x-y| + |x-z| + |y-z| = (z-x) + (z-y) + (y-x) = 2(z-x)$$因此，最小化总成对距离相当于最小化最小和最大最终位置之间的跨度。 

这将问题简化为控制每个点最多移动 1 后如何将最小值和最大值打包在一起。直观上，我们希望将最小点向上拉，将最大点向下拉，而可以调整中间点以帮助或保持在两者之间。 

每次移动的唯一有意义的效果是一个点是向中心移动还是远离中心。 由于每个点最多可以移动1，所以最终的最佳配置是通过缩小范围来实现的$[\min, \max]$尽量。 

因此，最优策略相当于：

 尝试将最小值向上移动 1，将最大的值向下移动 1，并保留中间的灵活性，然后重新计算所有一致选择的结果范围。 这可以归结为检查恒定数量的案例，或者更直接地观察答案仅取决于我们是否可以缩小初始范围。 

由于每个端点最多可以向内移动 1，因此最佳的新范围是：$$\max(0, (max - min) - 2)$$总的成对距离是该范围的两倍。 

这给出了直接$O(1)$每个测试用例的公式。

 | ---| ---| ---| ---|
 | 暴力破解（27 个州）|$O(q)$|$O(1)$| 已接受 |

 ## 算法演练

 我们专注于基于范围压缩的优化推理。 

1. 对于每个测试用例，读取三个位置$a, b, c$。 我们将它们视为一条线上的一小组点。 
2. 计算三个值中的最小值和最大值。 系统的分布完全由这两个值决定，因为中间值不会影响排序后的极值距离。 
3. 计算初始范围$d = \max(a,b,c) - \min(a,b,c)$。 这代表当前的总价差。 
4. 观察运动如何影响极端值。 最小的点最多可以增加1，最大的点最多可以减少1，因此范围最多可以缩小2。 
5. 更换$d$和$\max(0, d - 2)$。 这样可以在一次移动后获得最佳的压缩效果。 
6. 输出$2 \cdot \max(0, d - 2)$，因为三个点之间的总成对距离等于排序后范围的两倍。 

### 为什么它有效

 对于任意三个点，对它们进行排序表明目标始终等于最小值和最大值之间距离的两倍。 任何中间点都会对称贡献并在总和中抵消。 

由于每个端点最多可以向内移动一个单位，因此对跨度的最佳可能改进恰好是总共两个单位。 中间点的重新安排无法超越通过压缩极端所实现的目标，因为除非它已经位于极端之外或与极端相匹配，否则它无法成为极端。 

这使得问题完全取决于区间端点可以缩小多少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        a, b, c = map(int, input().split())
        mn = min(a, b, c)
        mx = max(a, b, c)
        d = mx - mn
        ans = max(0, d - 2) * 2
        print(ans)

if __name__ == "__main__":
    solve()
```该代码仅计算每个测试用例的最小值和最大值，避免了考虑排列或中间值的需要。 减 2 直接模拟了两个极端都可以向内移动一次的事实。 

一个常见的实现陷阱是忘记最后乘以 2。 被最小化的数量不是范围本身，而是成对距离的总和，它始终是三个排序点的范围的两倍。 

另一个微妙的问题是正确处理小范围。 什么时候$d \le 2$，移动后所有点都可以合并到一个位置，因此答案必须为零。 这`max(0, d - 2)`强制执行这一点。

这些例子表明，变换仅取决于最外面的点，而不取决于内部排列。

 ## 边缘情况

 对于$a=b=c$，算法计算$d=0$，然后钳位至零，产生正确的零输出。 所有的移动都只会增加距离，所以没有什么配置比呆在一起更好。 

对于几乎相等的三元组，例如$1,2,3$，范围为 2。减去 2 后，它变为零，这意味着通过向内移动端点可以完全崩溃。 该算法通过钳位步骤直接捕获这一点。 

对于极端分离，例如$1, 1000000000, 999999999$，范围很大，但仍然只减少了 2。该算法正确地考虑了每个端点只有一个移动单位可用的事实，因此最终的减少是严格有界的。
