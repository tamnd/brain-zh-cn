 ## 解决方案

 ## 问题理解

 我们得到一个按固定顺序排列的整数序列。 我们可以选择从该序列中删除一个元素，或者保持不变。 在此操作之后，我们查看结果序列的所有连续段，并仅关注那些值严格从左到右增加的段。 在所有这些段中，我们想要最大可能的长度。 

简单来说，我们试图尽可能长时间地进行一次“几乎递增的运行”，其中我们可以通过删除破坏趋势的一个元素来精确修复一个局部中断。 

的约束条件为$2 \cdot 10^5$elements 立即排除任何尝试在每个位置模拟删除并从头开始重新计算最长增加段的解决方案。 每次移除后重新计算扫描的二次方法将涉及大约$n^2$工作，这远远超出了 2 秒的限制允许的范围。 我们需要一种线性或接近线性的方法。 

一些边缘案例揭示了为什么天真的思维会失败。 

如果数组已经严格递增，例如：```
5
1 2 3 4 5
```答案是 5，因为我们不会从删除任何内容中受益。 总是删除一个元素的幼稚策略会错误地将答案减少到 4。 

如果数组严格递减：```
5
5 4 3 2 1
```任何单个删除仍然会留下最长的增加片段，其长度最多为2，因为无法形成局部增加链。 如果天真地尝试“修复”多个中断，就会错误地高估一次删除带来的收益。 

一个更微妙的情况：```
5
1 3 2 3 4
```删除中间的 2 将两个递增的游程合并为一个更长的游程。 任何正确的解决方案都必须检测到删除的好处仅来自桥接两个已经增加的段。 

## 方法

 蛮力方法很简单。 对于每个索引，我们模拟删除该元素，然后扫描整个数组以计算最长的严格递增连续子数组。 此扫描是线性的，因此对每个索引执行此操作都会给出$O(n^2)$时间。 和$n = 2 \cdot 10^5$，这需要大约$4 \cdot 10^{10}$的操作，这是不可行的。 

关键的观察是，增加段的结构已经非常规则，没有删除。 我们可以针对每个位置预先计算增加的​​游程向左和向右延伸多远。 一旦知道这一点，删除一个元素的唯一有意义的效果可能是连接结束于的左递增游程$i-1$以正确的递增运行开始$i+1$，假设边界条件$a[i-1] < a[i+1]$成立。 

这将问题减少到跟踪本地运行长度并检查每个索引最多一个合并点。

 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们计算两个描述单调结构的数组。 

1. 计算数组`left[i]`它存储以索引结尾的严格递增的连续子数组的长度$i$。 

这是通过从左到右扫描构建的。 如果$a[i] > a[i-1]$，我们延长之前的运行； 否则我们重置为 1。 
2. 计算数组`right[i]`它存储从索引开始的严格递增的连续子数组的长度$i$。 

这是通过使用相同的逻辑从右向左扫描来构建的。 
3. 将答案初始化为中的最大值`left[i]`。 

这代表我们不删除任何元素的情况。 
4. 对于每个位置$i$，考虑删除$a[i]$。 

删除可能会连接以$i-1$一个开始于$i+1$。 
5. 合并仅在以下情况下有效：$a[i-1] < a[i+1]$。 

如果这成立，则合并后的段长度变为`left[i-1] + right[i+1]`。 
6. 使用所有移除的最大值更新答案。 

### 为什么它有效

 一次删除后最终数组中任何严格增加的连续段都必须属于两个类别之一。 要么它不穿过被删除的元素，这意味着它已经存在于原始数组中并被捕获`left[i]`，或者它穿过删除的位置，这意味着它是通过连接在删除的索引处精确分离的两个原始递增游程而形成的。 不存在其他结构上的可能性，因为严格递增的段不能包含内部递减，因此最多可以通过删除来修复一个“断点”。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

left = [1] * n
right = [1] * n

for i in range(1, n):
    if a[i] > a[i - 1]:
        left[i] = left[i - 1] + 1
    else:
        left[i] = 1

for i in range(n - 2, -1, -1):
    if a[i] < a[i + 1]:
        right[i] = right[i + 1] + 1
    else:
        right[i] = 1

ans = max(left)

for i in range(n):
    if i == 0:
        ans = max(ans, right[1])
    elif i == n - 1:
        ans = max(ans, left[n - 2])
    else:
        if a[i - 1] < a[i + 1]:
            ans = max(ans, left[i - 1] + right[i + 1])
        else:
            ans = max(ans, left[i - 1], right[i + 1])

print(ans)
```这`left`数组捕获我们可以在不进行任何修改的情况下将在每个位置结束的递增段延伸多远。 这`right`array 从右侧进行对称工作。 

循环结束`i`小心处理边界位置。 当删除第一个或最后一个元素时，仅保留一侧，因此最佳可实现的段直接是相应的预计算运行。 

对于内部头寸，关键的检查是两侧是否可以合并。 条件`a[i - 1] < a[i + 1]`确保移除`a[i]`不违反连接点处的严格增加。 如果失败，我们就无法连接这两个段，必须回退到最佳的独立运行。

 ## 边缘情况

 一个关键的边缘情况是删除端点时。 如果删除第一个元素，则最佳结果只是从索引 1 开始的最长递增前缀。该算法直接通过以下方式处理此问题`right[1]`。 例如：```
5
5 1 2 3 4
```去掉 5 得到答案 4，并且`right[1]`正确地捕捉到了这一点。 

另一种情况是合并没有好处。 例如：```
5
5 4 3 2 1
```每一个`left[i]`和`right[i]`为 1，并且任何有效的合并条件都不成立。 该算法自然会回落到 1，这与正确答案匹配，因为删除任何元素仍然不会留下长度超过 1 的增长段。 

最后一种微妙的情况是存在多个潜在的合并点，但只允许删除一个。 为了：```
6
1 2 10 3 4 5
```仅删除 10 即可产生完整合并。 该算法独立正确评估每个指标并选择最佳的单个改进，确保不会重复计算删除。
