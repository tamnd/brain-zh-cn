 ## 解决方案
 ## 问题理解

 我们给出了机器人在从原点开始的无限网格上的一系列移动。 字符串中的每个字符都告诉机器人在四个基本方向之一上移动一步。 我们可以删除这些动作的任何子集，然后在执行它们之前任意重新排序剩余的动作。 

由此产生的运动必须形成具有严格约束的有效行走：机器人不允许多次访问任何网格单元，除非它可以在原点开始和结束。 因此，除了原点之外，路径必须很简单，原点最多可以出现两次，分别在开头和结尾。 

任务是保留尽可能多的动作，以最佳方式重新排列它们，并输出达到最大可能长度的任何有效序列。 

这些限制意味着我们必须在所有测试用例中处理最多 100000 个字符。 这排除了任何指数或二次构造。 我们只能为每个测试用例提供线性工作，本质上是在 O(n) 中计算和构建答案。 

一个天真的解释是建议尝试所有的移动子集并检查排列是否形成有效的简单循环。 这会立即失败，因为有 2^n 个子集，而且 n! 排列，都远远超出了可行的限度。 

一个更微妙的陷阱来自于认为我们可以简单地独立使用所有平衡方向。 例如，左右走很多步，排列成“LRLRLR...”，看上去很平衡，但实际上又回到了中间点，违反了规则。 同样，连续使用多次垂直移动会导致重复访问同一行上的单元格。 约束不仅仅是平衡，而是整个路径的几何简单性。 

## 方法

 暴力策略会尝试选择移动的子集，然后验证某些排序是否会产生有效的非自相交闭合行走。 即使我们修复了一个子集，检查有效性也需要推理所有排列或模拟可能的路径，在最坏的情况下仍然会退化为指数探索。 仅子集的数量就是 2^n，并且每次验证都至少是 O(n)，这太慢了。 

关键的见解是，由于我们可以任意重新排序，因此只有每个方向的计数很重要，而不是原始结构。 这将问题简化为选择我们保留多少 L、R、U 和 D 动作。 

现在我们问什么形状的路径可以最大化长度，同时避免重访。 有效的长路径本质上必须形成一个简单的闭合多边形。 在具有轴对齐台阶的网格上，我们可以构建的最佳结构是一个矩形：向右走一段距离，向上，向左返回，然后向下回到原点。 这保证了没有重复的内部单元。 

为了形成这样的矩形，我们需要匹配水平移动和匹配垂直移动。 如果我们取 x = min(L, R)，我们可以向右构建 x 步，向左构建 x 步。 类似地，y = min(U, D) 给出 y 向上和 y 向下的步长。 如果x和y都是正数，我们可以将它们组合成周长为2(x + y)的矩形。 

如果只有一个轴具有匹配对，我们就无法将其扩展到单个来回对之外而不重新访问中间单元。 所以在这种情况下，我们总共只能取一对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集和排列的暴力破解 | O(2^n · n!) | O(2^n · n!) | O(n) | 太慢了|
 | 计算方向并构建矩形 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。

1. 计算每个方向在输入字符串中出现的次数。 我们存储 L、R、U 和 D 的计数。这是必要的，因为重新排序后顺序无关紧要，因此只有频率重要。 
2. 计算通过取 x = min(L, R) 可以形成多少个平衡的水平移动。 这表示在不破坏对称性的情况下可以使用的左右对的最大数量。 
3. 计算通过取 y = min(U, D) 可以形成多少个平衡垂直移动。 这表示上下对的最大数量。 
4. 如果 x 和 y 都大于零，我们构造一个矩形。 我们输出 x 乘以“R”，然后输出 y 乘以“U”，然后输出 x 乘以“L”，然后输出 y 乘以“D”。 这种顺序确保路径绕过矩形边界并返回原点，而不会两次访问任何单元格。 
5. 如果 x 或 y 之一为零，而另一个为正，则无法形成矩形。 在这种情况下，我们在非零方向轴上恰好输出一对：“LR”或“UD”。 这给出了长度为 2 的有效路径。 
6. 如果 x 和 y 都为零，则不存在有效的移动对，因此答案为空。 

### 为什么它有效

 构建的路径始终是网格中的简单封闭行走。 当使用两个轴时，机器人会追踪矩形的边界。 每个中间单元恰好位于矩形边界的一侧，因此除了原点之外不会重新访问任何单元。 当仅存在一个轴时，任何使用一对以上轴的尝试都将迫使重新访问中间单元，因此限制为一对是必要且最佳的。 

最优性源于以下事实：每条有效的闭合非自相交路径必须使用相等数量的相反方向。 在不违反终点条件的情况下，不能使用任何额外的不平衡。 由于我们独立地最大化 x 和 y，因此我们使用所有可用的平衡对，并且不存在更大的有效构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        s = input().strip()

        L = s.count('L')
        R = s.count('R')
        U = s.count('U')
        D = s.count('D')

        x = min(L, R)
        y = min(U, D)

        if x == 0 and y == 0:
            print(0)
            print()
            continue

        if x == 0:
            print(2)
            print("UD")
            continue

        if y == 0:
            print(2)
            print("LR")
            continue

        ans = []
        ans.append("R" * x)
        ans.append("U" * y)
        ans.append("L" * x)
        ans.append("D" * y)

        res = "".join(ans)
        print(len(res))
        print(res)

if __name__ == "__main__":
    solve()
```该代码首先聚合方向频率，这是允许重新排序后所需的唯一信息。 然后它计算每个轴可用的对称对。 

构造逻辑直接遵循矩形思想。 R、U、L、D 的顺序是有意为之的，因为它追踪边界而不跨越自身。 任何保留这种循环结构的排列都可以，但破坏它会引入重复的单元。 

单轴情况下的边缘处理很重要：即使存在许多对，也只有一对可以安全使用，而不会违反“禁止重访”约束。 

## 工作示例

 我们追踪两个有代表性的案例。 

### 示例 1：`LRU`| 步骤| 左 | 右 | 你| d | x=min(L,R) | y=min(U,D) | 决定| 输出|
 | ---| ---| ---| ---| ---| ---| ---| ---| ---|
 | 输入| 1 | 1 | 1 | 0 | 1 | 0 | 单轴| “LR”|

 这里只存在水平平衡，所以我们不能形成一个矩形。 使用超过一对将迫使重新访问`(1,0)`或者`(0,0)`过早，所以我们只保留一对。 

### 示例 2：`LRUDDLRUDRUL`| 步骤| 左 | 右 | 你| d | x| y | 决定| 输出构造|
 | ---| ---| ---| ---| ---| ---| ---| ---| ---|
 | 计数| 3 | 3 | 3 | 3 | 3 | 3 | 矩形| RRR UUU LLL DDD |

 所有方向完美平衡。 该算法形成一个 3 x 3 的矩形边界，产生一个简单的循环，无需重新访问任何其他单元格即可返回原点。 

这证实了当两个轴都可用时，解决方案始终使用完整的对称容量。

 ## 边缘情况

 当所有移动都仅在一个方向上时，例如`"LLLLRRRR"`，算法正确地将答案减少为单个“LR”对。 尝试使用所有对会导致沿线重复访问，特别是重新访问`(1,0)`多次。 

当所有四个方向都存在但不平衡时，算法仍然安全地仅使用最小匹配计数。 任何额外的不匹配的移动都会被丢弃，因为它们不能成为封闭的简单循环的一部分。 

当仅存在一种类型的移动时，例如`"LLL"`，x 和 y 都为零，并且算法正确地返回空路径，因为无法形成有效的循环。
