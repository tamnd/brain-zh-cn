 ## 解决方案
 ## 问题理解

 我们得到一张由一串数字表示的票，其长度始终为偶数。 如果我们将该字符串分成相等的两半，则当左半部分的数字总和等于右半部分的数字总和时，该票被视为“平衡”。 

该任务与检查余额不同。 我们被迫修改给定字符串的一位数字，将其替换为 0 到 9 之间的任何其他数字，同时保持字符串长度不变。 经过这一单一更改后，我们希望结果数字变得平衡。 在所有可能的有效结果中，我们必须输出字典顺序最小的一个。 如果没有个位数的变化可以达到平衡，则答案为-1。 

关键的困难在于，更改一位数字会影响该数字本身的值以及两半之间的差异，并且我们必须考虑到更改可以解决不平衡问题的所有位置。 

限制总共最多允许 100 位数字。 这意味着任何达到 O(n^2 · 10) 甚至 O(n · 10 · 10) 的解决方案都足够快。 然而，考虑到较小的界限，在不进行预处理的情况下重复为每个位置重新计算总和的解决方案仍然是可以接受的。 

当原始数字已经平衡时，会出现微妙的边缘情况。 即使这样，我们仍然必须精确地改变一位数字，并且我们必须确保新的数字之后是平衡的。 例如，如果字符串已经平衡，但所有可能的个位数变化都会破坏平衡，则答案为 -1。 

另一个棘手的情况是存在多个有效答案。 因为需要字典顺序，所以我们不能贪婪地选择第一个有效的数字变化，除非我们按升序仔细检查所有可能性。 

## 方法

 暴力方法会尝试所有可能的位置和替换数字选择。 对于每个候选修改，我们重新计算两半的总和并检查它们是否匹配。 这很简单：我们模拟用数字 d 替换位置 i，在 O(n) 中计算两个半和，并验证余额。 由于存在 O(n·10) 个候选者，每次检查成本为 O(n)，因此总复杂度变为 O(n^2·10)。 当 n 达到 100 时，这仍然没问题，但它会变得不必要的重复。 

关键的观察是我们不需要每次都从头开始重新计算总和。 两半之间的不平衡可以被追踪一次。 当我们改变一个数字时，它对左半部分和右半部分之间的差异的影响是局部的并且是可预测的。 如果一个数字位于左半部分，则减少或增加它会移动左侧的总和； 右半部分也类似，但对平衡条件有相反的影响。 这将每次检查减少到 O(1)。 

一旦这成为每个候选者的 O(1) 更新，我们就可以有效地扫描所有位置和数字，并且在有效结果中，我们通过按顺序构建候选者来选择字典顺序最小的结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²·10) | O(n) | 可以接受但缓慢|
 | 优化尝试全部 | O(n·10) | O(n) | 已接受 |

 ## 算法演练

1. 计算原始字符串左半部分和右半部分的数字之和。 这给出了双方最初的不平衡。 
2. 从左到右迭代字符串中的每个位置 i。 顺序很重要，因为较早的位置主导着字典顺序。 
3. 对于每个位置 i，尝试用除原始数字之外的 0 到 9 中所有可能的数字替换当前数字。 
4. 对于每次替换，计算此更改如何影响左半部分和右半部分的总和。 如果位置在左半部分，则减去旧的数字并将新的数字添加到左和中； 否则对正确的总和应用相同的更新。 
5. 检查更新后的左和是否等于更新后的右和。 如果是，则候选字符串有效。 
6. 跟踪按升序扫描数字时遇到的第一个有效候选者。 因为我们从左到右处理位置，从小到大处理数字，所以第一个有效候选者是字典顺序最小的。 
7. 输出该候选者。 如果没有找到候选者，则输出-1。 

### 为什么它有效

 在任何步骤中，唯一改变的值是单个数字对两个半和之一的贡献。 字符串的其余部分保持不变，因此平衡条件仅取决于对预先计算的差异的不断调整。 这使得每个候选人的评估都是独立且局部正确的。 由于字典顺序是通过按升序首先扫描位置和第二个数字来强制执行的，因此后面的候选者不能覆盖较早的有效候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s) // 2
    arr = list(map(int, s))

    left_sum = sum(arr[:n])
    right_sum = sum(arr[n:])

    for i in range(2 * n):
        original = arr[i]

        for d in range(10):
            if d == original:
                continue

            if i < n:
                new_left = left_sum - original + d
                new_right = right_sum
            else:
                new_left = left_sum
                new_right = right_sum - original + d

            if new_left == new_right:
                arr[i] = d
                print("".join(map(str, arr)))
                return

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先从概念上将字符串分成两半并计算一次它们的总和。 这样可以避免以后重复重新计算。 

然后对每个位置进行独立测试。 模拟替换时，仅更新两个总和之一，具体取决于索引属于哪一半。 这就是检查 O(1) 的原因。 

循环顺序至关重要。 因为我们从左到右迭代索引，从 0 到 9 迭代数字，所以第一个成功的构造会自动按字典顺序最小化，因此我们永远不需要存储或比较候选者。 

一个常见的错误是就地修改数组而不恢复它，但这里我们仅在找到有效答案时进行分配并立即返回，因此不需要回滚逻辑。

 ## 边缘情况

 一个重要的边缘情况是每次一位数的修改都会打破平衡条件。 例如，如果两半之间的差异太大而无法通过更改单个数字来补偿，则算法将耗尽所有候选者并正确返回 -1。 

另一种情况是不同半部存在多个解。 由于扫描优先考虑较早的索引，因此左半部分的有效修改始终按字典顺序支配右半部分的任何修改，即使两者都修复了平衡。 这种排序对于正确性至关重要，并且避免了完整字符串之间的显式比较。
