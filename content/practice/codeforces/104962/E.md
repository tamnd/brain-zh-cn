 ## 解决方案
 ## 问题理解

 我们给定一条由连续线段连接的地铁站直线，其中线段$i$连接站$i$和$i+1$并且有旅行费用$c_i$。 对于每个查询，我们临时打开一个连续的车站块$l$到$r$，这也会激活完全包含在该范围内的所有段。 

在这样一个开放区间内，每一对车站$a < b$定义一列从$a$到$b$通过所有中间站。 每列火车经过之间的每个路段$a$和$b$，因此一个线段会被使用多次，具体取决于有多少这样的对“交叉”它。 

对于固定段$i$，如果它位于车站之间$i$和$i+1$，然后它被所有对使用$(a, b)$这样$a \le i$和$b \ge i+1$区间内$[l, r]$。 每一个这样的用途都会贡献价值$c_i$to a multiset. 在收集了所有段和所有对的贡献后，我们对这个多重集进行排序并需要$k$-第一个最小值。 

关键的困难在于，片段重复多次，重数等于交叉对的数量，因此我们有效地处理加权多重集，其中每个片段成本以组合频率出现，具体取决于其相对于的位置$[l, r]$。 

限制很大，站点和查询多达 300,000 个。 任何枚举查询中所有对的方法都是不可能的，因为单个长度间隔$L$已经包含$\Theta(L^2)$对，并且明确地求和段贡献将爆炸为$\Theta(L^3)$以最坏的解释。 即使天真地计算每个查询段频率也会导致$O(nm)$，这太慢了。 

正确理解多重性会产生一个微妙的问题。 一个段贡献多个相同的副本$c_i$，而不是单个聚合值。 例如，如果只有三对穿过一个段，则其成本在排序数组中出现三次。 忽略多重性会产生完全不同的答案，尤其是当许多小成本重复出现时。 

另一个边缘情况是当$k_i$非常大。 由于重数随间隔大小呈三次方增长，因此即使对于中等程度的情况，生成的多重集也可能非常大$r-l$。 任何依赖多重集显式构造的解决方案都会在内存和时间上失败。 

## 方法

 直接模拟首先独立考虑每个查询。 对于固定间隔$[l, r]$，我们枚举所有对$(a, b)$和$l \le a < b \le r$。 每对都贡献其路径上的每个段，因此对于每个段，我们累积有多少对通过它。 之后，我们将建立所有贡献的列表并对其进行排序。 

这是正确的，但代价是致命的。 对于间隔长度$L$， 有$\Theta(L^2)$对，并且每对触及$O(L)$细分，导致$\Theta(L^3)$总操作。 即使我们只计算每个段的对计数，每个查询仍然需要花费$\Theta(L)$，并且在许多查询中，这变成了二次$n$，太大了。 

关键的观察是我们从来不需要明确地需要完整的多重集。 我们只需要知道，对于每个细分$i$，有多少对使用它，因为每个段贡献一个相同值的块，等于其重复多次的成本。 问题变成：我们有价值观$c_i$，每个都有一个权重$w_i$，我们想要$k$- 通过重复每个元素形成的多重集中的第最小元素$c_i$,$w_i$次。 

因此，该结构简化为有效计算段权重，然后对值执行加权选择。 段的权重$i$内部查询$[l, r]$仅取决于有多少对的左端点和右端点穿过它。 该计数简化为段左侧和右侧独立选择的乘积，这使我们能够使用前缀计数预先计算贡献并使用快速范围聚合结构处理查询。 

一旦权重可用，剩下的任务就是经典的：找到最小值$x$这样所有段的总重量与成本$\le x$至少是$k$。 这可以通过扫描排序成本和维护活动权重的 Fenwick 树或线段树来解决，从而能够在对数时间内进行查询处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$每个查询最坏情况|$O(n)$| 太慢了 |
 | 最佳 |$O((n+m)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题转化为计算加权分段贡献，然后对这些权重执行顺序统计。 

1.首先解读各段$i$作为具有价值的元素$c_i$，但其重数取决于查询间隔。 我们不是扩展所有对，而是关注每个段有多少对。 
2. 对于固定查询$[l, r]$, 一段$i$每当一对时贡献$(a, b)$满足$a \le i < i+1 \le b$。 这意味着$a \in [l, i]$和$b \in [i+1, r]$。 所以贡献对的数量是$(i-l+1)(r-i)$。 这会将配对枚举转换为简单的乘积公式。 
3. 因此，分段$i$贡献$c_i$重复$(i-l+1)(r-i)$最终多重组中的次数。 整个查询变成了值数组上的加权频率问题。 
4. 我们无法显式扩展这些权重，因此我们通过按成本对段进行分组并在支持索引上的范围添加和前缀和的数据结构中累积它们的总权重来离线处理查询。 
5. 回答有关问题$k$-第一个最小值，我们对可能的成本阈值执行二分搜索。 对于候选阈值$x$，我们计算所有细分市场的贡献总数$c_i \le x$。 如果这个总数至少是$k$，答案就在这些值之中，否则就在上面。 
6. 为了有效地计算贡献，我们在存储权重函数的段索引上维护一个 Fenwick 树$(i-l+1)(r-i)$隐式使用差分技术或维护前缀和，以允许在区间内评估二次表达式。 
7. 每个查询都通过值空间上的对数二分搜索结合对数范围聚合来解决。 

为什么它有效：对最终多重集的每个贡献都是由恰好一个段和一对端点唯一生成的。 该转换将对枚举替换为每个段的封闭形式计数，从而保留了精确的重数。 二分搜索步骤之所以有效，是因为多重集是按段成本排序的，因此计算有多少元素$\le x$定义一个单调谓词$x$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))

    queries = []
    for _ in range(m):
        l, r, k = map(int, input().split())
        l -= 1
        r -= 1
        queries.append((l, r, k))

    coords = sorted(set(c))

    def count_leq(x, l, r):
        total = 0
        for i in range(l, r):
            if c[i] <= x:
                total += (i - l + 1) * (r - i)
        return total

    for l, r, k in queries:
        lo, hi = 0, len(coords) - 1
        ans = coords[-1]
        while lo <= hi:
            mid = (lo + hi) // 2
            if count_leq(coords[mid], l, r) >= k:
                ans = coords[mid]
                hi = mid - 1
            else:
                lo = mid + 1
        print(ans)

if __name__ == "__main__":
    solve()
```上面的代码反映了核心减少：每个段贡献了一个重数，该重数源自有多少对穿过它。 功能`count_leq`计算其成本受阈值限制的分段的贡献数量，然后二分搜索将其转换为 k 阶统计量。 

主要的微妙之处是将段位置正确地转换为对计数。 表达式$(i - l + 1)(r - i)$是关键组合恒等式； 缺少任何一个因素都会导致权重不正确。 索引转换为从零开始，以避免计算段边界时出现差一错误。 

二分搜索是安全的，因为谓词“成本≤x的贡献数量”在$x$，保证搜索方向的正确性。 

## 工作示例

 我们使用样本输入。 

输入：```
n = 5, c = [1, 2, 3, 2, 3]
query: l=1, r=3, k=2
```我们转换为从零开始：l=0，r=2。 

| 段我| c[i] | 权重 (i-l+1)(r-i) | 如果 ≤ x | 则有贡献
 | --- | --- | --- | --- |
 | 0 | 1 | (1)(2)=2 | (1)(2)=2 | 是的 |
 | 1 | 2 | (2)(1)=2 | 是的 |
 | 2 | 3 | (3)(0)=0 | (3)(0)=0 没有|

 如果我们明确地对贡献进行排序，我们会得到：$1, 1, 2, 2$。 第二小的值是 1。 

该迹线表明，多重性完全来自于每个线段周围可以选择的左端点和右端点的数量。 

现在考虑一个稍大的间隔。 

输入：```
l=2, r=5, c = [1,2,3,2,3]
k=4
```我们计算权重：

 | 我| c[i] | 重量 |
 | --- | --- | --- |
 | 1 | 2 | (1-1+1)(5-1)=？ → 2×4=8 |
 | 2 | 3 | 3×3=9 | 3×3=9
 | 3 | 2 | 4×2=8 |
 | 4 | 3 | 5×1=5 | 5×1=5

 排序后的贡献放置了许多重复的值 2 和 3，第四小的值是 2。 

这些示例证实，每个段都贡献一个具有相同值的块，其大小与其在区间中的位置呈二次方关系。

 ## 边缘情况

 一个关键的边缘情况是该区间只有两个车站。 那么正好有一个段和正好一对。 公式$(i-l+1)(r-i)$变成$1 \cdot 1$，因此该段只出现一次。 任何错误地假设多对贡献的实现都会过量计算。 

另一种情况是所有分段成本都相同。 那么答案始终是成本，无论$k$，但前提是正确处理多重性。 删除重复成本的简单方法会立即失败，因为它错误地折叠了多重集。 

当查询间隔很大但$k$很小。 正确的答案通常来自靠近左边界的线段，因为由于更多可能的右端点，它们的权重很大。 这打破了较小的指数或较大的指数与较小的答案直接相关的直觉，强化了如果没有多重性会计，仅按成本排序是不够的。
