 ## 问题理解

 我们给定一个循环`n`房屋。 每个房子都放置在一个圆圈上，因此每个房子都有一个自然的想法，即沿着循环向左或向右移动。 

我们可以选择一个参数`k`。 一次`k`是固定的，每栋房子都直接连接到`k`最近的房屋在其左侧和`k`最近的房屋在其右侧。 建立这些连接后，图表变得比简单的循环更密集，因为从每个节点，您可以一步跳到附近节点的整个块。 

两栋房子之间的距离定义为在这个新图中它们之间移动所需的最小边数。 任务是选择最小的`k`使得任意一对房屋之间的最大可能的最短路径距离最多为`d`。 

换句话说，我们正在控制每个节点沿着圆的一步可以“看到”多远，并且我们希望生成的图最多具有直径`d`。 

约束条件非常大，`n`和`d`最多`10^12`。 这立即排除了每个测试用例的任何图形模拟或 BFS 式推理。 即使存储邻接也是不可能的，因此解决方案必须将结构折叠成直接公式或最多是对数计算。 

一个微妙的边缘情况是`n`非常小。 例如，如果`n = 3`，即使对于小型结构，该结构也几乎完全连接`k`，距离行为变得微不足道。 另一个角落是当`d`足够大，甚至`k = 1`已经满足要求，就像在小循环中，循环的直径已经在界限内。 

一个天真的误解是认为距离取决于复杂的图形快捷方式。 例如，人们可能会尝试在加权区间图上模拟最短路径，但这是不必要的，因为连接具有非常严格的结构：所有边都对应于循环上的有界跳跃。 

## 方法

 直接的暴力方法会尝试以下值`k`开始于`1`，构造图，并使用每个节点的 BFS 计算其直径。 每个 BFS 将是`O(n)`并重复`n`次，给予`O(n^2)`每`k`。 自从`k`还可以达到`n`，即使对于中等大小，这也是完全不可行的，对于`n = 10^12`。 

关键的观察结果是该图是完全对称的。 每个节点都有相同的连接结构，唯一重要的是我们一步可以沿着循环移动多远。 从任何节点，一次移动就可以跳到`k`顺时针或逆时针位置。 这会将图转换为一维度量，其中每一步最多将剩余圆形距离减少`k`。 

如果两个节点相距一个圆距离`x`，那么它们之间的最短路径正是`ceil(x / k)`。 The worst case occurs when`x`尽可能大，即圆上最远的距离，即`floor(n / 2)`。 

所以图的直径就变成了`ceil(floor(n/2) / k)`。 问题简化为寻找最小的`k`使得这个值最多是`d`。 

这个不等式很容易反转，给出了一个直接公式`k`。 整个问题分解为每个测试用例的恒定时间算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（图 + BFS）| O(n²) | O(n) | 太慢了 |
 | 基于公式的推理 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算环上的最大相关距离，即两个节点可以相距的最远距离。 在一个圆上，这是`floor(n / 2)`。 这是因为任何较长的弧都可以更便宜地沿相反方向移动。 
2.用参数观察`k`，一步最多可以覆盖`k`沿周期的位置。 这意味着要旅行一段距离`A = floor(n / 2)`需要`ceil(A / k)`最坏情况下的步骤。 
3.我们要求图形直径最大为`d`，所以我们强制执行`ceil(A / k) ≤ d`。 
4. 将这个不等式转化为条件`k`。 最小整数`k`满足的是`ceil(A / d)`。 
5. 返回该值作为每个测试用例的答案。 

### 为什么它有效

 所有节点在连接方面的行为都相同，因此最坏情况的最短路径纯粹由循环距离决定，而不是由节点身份决定。 每次移动最多减少剩余距离`k`，并且没有路径可以胜过贪婪归约，因为每条边都遵循相同的有界区间结构。 这使得最短路径相当于将距离分成大小块`k`，并且直径完全由循环上可能的最大距离控制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, d = map(int, input().split())
        A = n // 2
        k = (A + d - 1) // d
        out.append(str(k))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现直接应用导出公式。 唯一的微妙之处在于计算`ceil(A / d)`安全地使用整数算术作为`(A + d - 1) // d`。 使用整数除法可以避免浮点错误，这与这里无关，但仍然是竞争性编程中的常见陷阱。 

价值`A = n // 2`捕获最坏情况的圆形距离，其他一切都从该减少中得出。 不需要构建图。

 | --- | --- | --- |

 ## 边缘情况

 对于非常小的`n`， 例如`n = 3`，该循环只有一个有意义的距离值，因此该算法可以正确归约，因为`n // 2`变成`1`。 计算出的`k`总是至少`1`，因此无需特殊处理。 

对于非常大的`d`， 例如`d ≥ floor(n/2)`，公式得出`k = 1`。 这符合直觉，因为即使是基本的循环边缘也已经允许在允许的步数内到达最远的节点。 

对于以下情况`d = 1`，该要求迫使图形直径一次性崩溃。 公式正确返回`k = floor(n/2)`，这意味着每个节点必须能够从最远的节点一步直接到达，这与构造的结构相匹配。
