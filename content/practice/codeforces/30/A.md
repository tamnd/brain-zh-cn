 ## 解决方案
 ## 问题理解

 我们给定三个整数，`A`,`B`， 和`n`。 任务是找到一个整数值`X`这样：$A \cdot X^n = B$

`A`代表王国当年的收入`0`,`B`代表之后的收入`n`年，以及`X`为年增长率系数。 每个值都必须保持整数，包括`X`。 允许负值，并且`X`也可能为零。 

限制非常小。 两个都`A`和`B`至多是`1000`绝对值，并且`n`至多是`10`。 这完全改变了问题的性质。 我们不需要先进的数论或对数。 即使对所有合理的候选整数进行直接暴力破解，也很容易在时间限制内完成。 

棘手的部分不是性能，而是符号和零的正确性。 

一种危险的情况是`A = 0`。 

例如：```
0 0 5
```等式变为：$0 \cdot X^5 = 0$每个整数`X`满足它。 该问题允许打印任何有效答案，因此输出`0`很好。 

但与：```
0 10 3
```我们得到：$0 \cdot X^3 = 10$没有整数可以满足这一点，因为左边总是`0`。 

另一个微妙的情况出现了，答案是否定的，甚至是权力。 

考虑：```
1 -8 2
```我们需要：$X^2 = -8$均匀的幂永远不会变成负数，所以答案是`"No solution"`。 

但与：```
1 -8 3
```我们需要：$X^3 = -8$现在`X = -2`之所以有效，是因为奇数幂保留符号。 

使用浮点根的粗心实现也可能会失败。 计算类似的东西`pow(64, 1/3)`可能会产生`3.999999999`而不是`4`，导致舍入错误。 由于约束很小，整数暴力可以避免所有精度问题。 

## 方法

 最直接的想法就是尝试每一个可能的整数`X`, 计算`A * X^n`，并检查它是否等于`B`。 

为什么这有效？ 因为搜索空间很小。 如果`|B| ≤ 1000`，那么任何有效的整数根也必须保持相当小的值。 例如，如果`|X| ≥ 100`，那么甚至`X²`至少已经变成`10000`，远远超出允许范围，除非`A = 0`。 

尝试每个整数`-1000`到`1000`只给出`2001`候选人。 对于每个候选者，我们计算指数幂`10`。 这只是几万次算术运算，基本上是瞬时的。 

更数学的方法将隔离：$X^n = \frac{B}{A}$然后尝试计算一个整数`n`-th 根。 问题在于处理符号、整除性和浮点精度变得比原始问题本身更烦人。 由于限制如此之小，暴力破解实际上是最干净、最安全的解决方案。 

蛮力之所以有效，是因为每个有效答案都必须位于一个非常小的范围内。 一旦我们意识到这一点，问题就简化为简单的搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有整数进行暴力破解 | O(2000 × n) | O(1) | O(1) | 已接受 |
 | 整数根数学方法| O(n) | O(1) | O(1) | 已接受但容易出错 |

 ## 算法演练

 1. 读取整数`A`,`B`， 和`n`。 
2. 迭代所有整数`x`从`-1000`到`1000`。 

这个范围足够安全，因为`|B| ≤ 1000`。 任何更大的幅度都会使`x^n`除非出现特殊的零情况，否则远远超出目标。 
3. 对于每个候选人，计算：$A \cdot x^n$并将其与`B`。 
4. 如果等式成立，则打印`x`立即并终止。 

该问题允许任何有效的解决方案，因此第一个就足够了。 
5. 如果循环结束时没有找到有效整数，则打印`"No solution"`。 

### 为什么它有效

 该算法检查每个可能满足方程的候选整数。 如果存在解决方案，它必须出现在测试范围内的某个位置，因此算法最终会找到它。 如果没有候选满足方程，则不存在整数解。 

正确性直接来自于对所有可行整数值的详尽搜索。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

A, B, n = map(int, input().split())

for x in range(-1000, 1001):
    if A * (x ** n) == B:
        print(x)
        break
else:
    print("No solution")
```该循环尝试允许范围内的每个整数候选。 当指数为整数且非负时，Python 的整数算术可以正确处理负幂，因此`(-2) ** 3`变成`-8`和`(-2) ** 2`变成`4`自动地。 

这`for-else`结构在这里很有用。 这`else`仅当循环从未命中时才执行块`break`，意味着没有找到有效的解决方案。 

范围`[-1000, 1000]`是故意简单的。 我们可以从数学上得出更严格的界限，但没有任何好处。 目前的搜索规模已经很小了。 

到处使用整数运算可以完全避免浮点精度问题。

import sys, io

def solve():

    A, B, n = map(int, input().split())

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

 ## 边缘情况

 考虑输入：```
0 0 5
```该算法从开始检查`x = -1000`。 

我们计算：$0 \cdot (-1000)^5 = 0$这已经匹配了`B = 0`，所以算法立即打印`-1000`。 

这可能看起来很奇怪，但它是完全正确的。 每个整数都满足这里的等式，并且该语句允许任何有效答案。 

现在考虑：```
0 10 3
```对于每一位候选人`x`，左侧变为：$0 \cdot x^3 = 0$自从`0`永远不等于`10`，循环未成功完成并打印`"No solution"`。 

另一个重要的边缘情况是：```
1 -16 2
```该算法测试来自的所有整数`-1000`到`1000`。 

对于负面候选人：$(-x)^2 > 0$对于积极的候选人：$x^2 > 0$平方总是非负的，所以目标`-16`永远不可能出现。 详尽的搜索正确报告`"No solution"`。 

最后，考虑：```
2 18 2
```两个都`x = 3`和`x = -3`满足方程，因为：$3^2 = (-3)^2 = 9$该算法返回它遇到的第一个有效值，即`-3`。 该问题明确允许任何有效的解决方案，因此这种行为是正确的。
