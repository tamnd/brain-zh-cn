[CF 30D - 国王问题？](https://codeforces.com/problemset/problem/30/D)

 **评分：** 2600
 **标签：** 几何，贪心
 **求解时间：** 2m 12s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们有`n + 1`城市。 第一个`n`城市位于 x 轴上的位置`(x1, 0), (x2, 0), ..., (xn, 0)`。 另外一个城市位于轴外某处`(x_{n+1}, y_{n+1})`。 

国王从城市开始`k`。 他必须至少访问每个城市一次，如果有用的话可以重新访问城市，并且可以在任何地方结束。 每对城市都与欧几里得距离成本直接相连。 我们需要最小的总行程长度。 

几何形状在这里很重要。 除了一个特殊点外，每个城市都位于一条线上。 这种结构完全改变了问题。 一般的旅行推销员问题对于`n = 10^5`，但是一条线有一个非常严格的最佳遍历模式。 

这些约束立即排除了任何二次方。 和`10^5`城市，甚至`O(n^2)`距离转换已经意味着大约`10^{10}`运营。 在排序或预处理之后，我们需要一些本质上线性的东西。 由于轴上的输入城市在原始问题中已按索引顺序给出，因此我们可以利用区间属性并避免任何繁重的图算法。 

有几个微妙的案例打破了天真的推理。 

一种危险的情况是起始城市是离轴城市本身。 

输入：```
2 3
0 10 5
5
```这些城市是`(0,0)`,`(10,0)`， 和`(5,5)`，我们开始于`(5,5)`。 

粗心的解决方案可能会假设最佳路线总是从沿轴向左或向右扫过开始，但这里的第一次移动已经花费了对角线距离。 最优路线是：`(5,5) -> (0,0) -> (10,0)`总长度：`sqrt(50) + 10`。 

当离轴城市位于轴城市覆盖范围之外时，会出现另一种微妙的情况。 

输入：```
3 2
0 5 10 100
1
```特别城市位于最右边`(100,1)`。 最佳路线不再是对称的。 一侧的遍历比另一侧的遍历要昂贵得多。 任何假设特殊城市的行为就像线上的另一个点的实现都会低估距离。 

第三个陷阱是假设路线必须在 x 轴上的一个极端城市结束。 

输入：```
2 1
0 100 50
100
```特别的城市`(50,100)`非常向上。 最好的策略可能是在那里结束，而不是通过队列返回。 由于允许在任何地方结束，因此一个遍历分支可以在特定城市终止，从而节省大量回溯。 

这些案例迫使我们仔细思考直线上的最佳行走实际上是什么样的。 

## 方法

 蛮力观点首先是有用的。 我们可以将城市视为一个完整的加权图，并搜索访问所有节点的最短路线。 这与旅行推销员的变体非常相似。 即使是对子集的动态规划也需要`O(2^n n)`状态，这变得荒谬超出了`n = 20`。 

暴力破解在概念上起作用的原因是每条有效路线都只是访问的顺序。 如果我们列举所有的可能性，最终我们会找到最短的一种。 失败纯粹是计算性的。 

关键的观察是几何的。 除一座城市外，所有城市都位于一条直线上。 在一条线上，访问所有点的结构非常受限。 

假设我们暂时忽略特殊城市。 如果您从某个轴点开始并且必须访问每个轴城市，则最佳步行只能以一种有意义的方式表现：最终您覆盖从最左边的城市到最右边的城市的整个区间。 不必要地重新访问内部部分只会增加距离。 

这意味着整个问题归结为决定将特殊城市插入到这个区间遍历中的位置。 

另一个重要的见解是，最佳路线只能访问特定城市一次。 任何第二次访问都会造成一个可以避免的循环，因为欧几里得距离满足三角不等式。 

现在考虑轴心城市。 该线的任何最佳遍历都可以解释为：

 1. 从起点扫一侧。 
2. 扫另一侧。 
3. 在一次扫描的开始或结束时，在一个地点连接到特定城市。 

一旦将其形式化，就只剩下恒定数量的候选路线。 

最简洁的表述是将两种情况分开。 

如果起始城市是特殊城市，我们只需要从该点出发覆盖整个轴区间的最短路线即可。 最优答案变为：```
interval_length + min(distance to left end, distance to right end)
```否则，起点位于轴上。 那么最优路径相当于遍历所有轴心城市，同时将特殊城市作为附着在某处的端点。 我们可以枚举在覆盖一侧之前或之后是否访问过该特殊城市。 

经过简单的预处理后，这给出了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((n+1)!) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 情况一：起始城市为特殊城市

 如果`k = n + 1`，王从离轴点开始。 

要访问所有轴心城市，他最终必须覆盖从最左边的 x 坐标到最右边的 x 坐标的整个段。 该强制性成本是：```
x[n] - x[1]
```在穿过该路段之前，他必须首先到达左端或右端。 

所以总数变为：

 1.特殊城市到最左边轴心城市的距离，加上间隔长度。 
2.特殊城市到最右轴城市的距离，加上间隔长度。 

我们取最小值。 

### 情况2：起始城市位于轴线上

 现在开始位置`x[k]`。 

轴城市的任何最优遍历都具有以下结构：

 1. 完全清理起点的一侧。 
2. 完全清除另一侧。 
3. 在某个地方结束，没有不必要的回溯。 

唯一的复杂之处在于特殊城市的附属位置。 

我们定义：```
base = x[n] - x[1]
```这是覆盖全轴区间不可避免的成本。 

如果我们在左侧完成，那么右侧的遍历必须加倍。 反方向也同样如此。 

我们评估四种可能性：

 1. 到达最左边的城市，从右侧参观特殊城市。 
2. 到达最左边的城市，从左侧参观特殊城市。 
3. 到达最右边的城市，从左边参观特殊城市。 
4. 到达最右边的城市，从右侧参观特殊城市。 

每个公式只是：```
mandatory interval coverage
+ doubled side
+ one diagonal connection
```更具体地说，假设我们在左侧完成。 然后我们必须从右侧返回：```
2 * (x[n] - x[k])
```然后我们附加特殊城市`x[k]`或来自`x[n]`，以与所选路线形状匹配的为准。 

我们计算所有候选值并取最小值。 

### 为什么它有效

 不变的是每个轴心城市都位于一个区间上。 任何访问所有这些的有效路线都必须覆盖极值 x 坐标之间的整个路段。 

每当路线在区间内改变方向超过必要时，某些子路段就会被额外遍历几次。 由于所有边权重都是欧几里德距离，并且轴城市是共线的，因此消除冗余回溯永远不会增加成本。 

这将每个最佳解决方案简化为最多具有一个双面的简单扫掠结构。 特殊城市恰好贡献了一条对角线，因为重新访问它会通过三角不等式创建一个可移动的循环。 

由于该算法枚举了特殊城市的每个可能的扫描端点和每个可能的附着点，因此测试的候选者之一与最佳路线相匹配。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def dist(x1, y1, x2, y2):
    return math.hypot(x1 - x2, y1 - y2)

def solve():
    n, k = map(int, input().split())

    arr = list(map(int, input().split()))
    y = int(input())

    xs = arr[:n]
    sx = arr[n]

    if n == 1:
        if k == 1:
            ans = dist(xs[0], 0, sx, y)
        else:
            ans = dist(xs[0], 0, sx, y)

        print("{:.15f}".format(ans))
        return

    def special_to(i):
        return dist(sx, y, xs[i], 0)

    left = xs[0]
    right = xs[-1]

    if k == n + 1:
        ans = min(
            special_to(0) + (right - left),
            special_to(n - 1) + (right - left)
        )

        print("{:.15f}".format(ans))
        return

    k -= 1

    ans = float('inf')

    # finish left, attach special from current
    ans = min(
        ans,
        2 * (right - xs[k]) +
        (xs[k] - left) +
        special_to(k)
    )

    # finish left, attach special from right
    ans = min(
        ans,
        2 * (right - xs[k]) +
        special_to(n - 1) +
        (right - left)
    )

    # finish right, attach special from current
    ans = min(
        ans,
        2 * (xs[k] - left) +
        (right - xs[k]) +
        special_to(k)
    )

    # finish right, attach special from left
    ans = min(
        ans,
        2 * (xs[k] - left) +
        special_to(0) +
        (right - left)
    )

    print("{:.15f}".format(ans))

solve()
```实现直接遵循几何分解。 

帮手`dist()`使用计算欧几里得距离`math.hypot`，避免了手动平方并且数值稳定。 

第一个分支处理起始城市是离轴点的特殊情况。 路径必须首先到达一个区间端点，然后精确地扫描整个轴段一次。 

更有趣的部分是第二个分支。 这里起点已经位于轴上。 这些公式对应于四种典型的最佳路线形状。 

例如：```
2 * (right - xs[k]) +
(xs[k] - left) +
special_to(k)
```意思是：

 1. 向右遍历并返回，因此加倍。 
2. 向左端点扫动一次。 
3. 从起始位置连接一次到特殊城市。 

一个常见的实施错误是忘记了可能会在开始或结束时访问特殊城市。 将其限制于内部过渡会错过最佳解决方案。 

另一个容易出现的错误是索引。 该问题使用从 1 开始的城市索引，但 Python 数组是从 0 开始的。 代码转换`k`处理后要小心`k == n + 1`分支。 

这`n == 1`案件也应单独处理。 轴城只有一个，所以答案很简单，就是两个城市之间的直线距离。

 ## 边缘情况

 考虑起始点是特殊城市的情况。 

输入：```
2 3
0 10 5
5
```算法输入`k == n + 1`分支。 

距离：```
to left = sqrt(50)
to right = sqrt(50)
interval = 10
```回答：```
10 + sqrt(50)
```路线到达一个端点并扫过间隔一次。 不会出现额外的回溯。 

现在考虑区间外的一个特殊城市。 

输入：```
3 2
0 5 10 100
1
```特殊城市与轴心城市几乎是水平分离的。 

这些公式正确地考虑了这样一个事实：从右端点连接比从左端点连接便宜得多。 由于检查了所有四个候选扫描结构，因此算法自然会选择正确的附着侧。 

最后，考虑以特殊城市结束为最优的情况。 

输入：```
2 1
0 100 50
100
```距离：```
special_to_start = sqrt(12500)
```一种幼稚的方法可能会在访问特殊城市后强制返回轴，但算法允许特殊城市作为终点。 四个公式之一准确地反映了这种情况，避免了不必要的旅行。
