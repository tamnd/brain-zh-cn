 ## 解决方案
 ## 问题理解

 我们得到一个序列，其行为就像一段时间内的“记录”列表，其中每个元素都可以被认为是一个分数或附加到一个位置的值。 除此之外，我们还获得了一组允许的交换操作。 每个操作都连接两个位置，这意味着我们可以交换当前存储在这两个索引处的值。 

重要的细节是交换不是任意的：我们只允许沿着给定的连接进行交换，并且我们可以多次重用这些连接。 问题是，在执行任何允许的交换序列后，我们可以获得的最佳最终值排列是什么。 

在结构上进行了重新构建，这些连接形成了位置上的无向图。 该图的每个连接组件描述了一组索引，这些索引的值可以使用沿边重复交换在它们之间任意排列。 任务是在每个这样的组件内选择最佳的可能的值重新分配。 

这里“最佳”的自然概念是我们希望最终的数组按字典顺序尽可能大，这意味着前面的位置比后面的位置更重要。 因此，对于每个组件，我们希望将其最大值尽可能早地放置在组件的索引顺序中，因为较早的位置主导字典序比较。 

约束（在典型的 CF 样式中具有最多大约 10^5 或更多位置和边缘）排除了任何尝试直接模拟交换的方法。 单个交换序列可能很长，并且探索所有可能的序列会导致组合爆炸。 即使用 BFS 来考虑排列也是不可能的，因为状态空间是阶乘的。 

一种幼稚的方法是重复模拟交换并尝试贪婪地改进数组，但即使是一次尝试向前“冒泡”大值也可能花费 O(nm) 或更糟的成本，因为每个交换步骤仅进行局部更改，并且可能需要在连接链上重复多次。 

当图结构稀疏但形成长链时，就会出现边缘情况。 例如，如果索引形成路径 1-2-3-4 并且值最初是相反的，则仅考虑相邻有益交换的朴素贪婪交换策略可能需要多次传递，或者如果不尊重全局连接性，甚至可能以错误的顺序进行交换。 另一个边缘情况是当组件很大但彼此断开连接时，组件之间的混合值是不可能的，因此任何全局排序方法都会错误地假设完全自由。 

## 方法

 蛮力的想法是显式模拟所有允许的交换并尝试探索所有可达的排列。 每个交换都会更改当前配置，并且由于我们可以无限期地重用交换，因此这变成了排列的图遍历。 即使限制为 k 大小的单个组件，也有 k 个！ 可能的排列以及它们之间的转换形成了一个巨大的隐式图。 即使 k 约为 10，这也很快变得不可行。 

关键的观察是交换在位置图中生成连通分量，并且在每个连通分量内我们可以任意重新排列值。 这将问题从“交换序列”减少为“组件上的独立排序问题”。 

在组件内部，所有索引在可达性方面都是等效的，因此我们可以自由地排列该组件中的多重值集。 为了按字典顺序最大化，我们希望大值出现在组件内较小的索引处。 这建议按降序对值进行排序，并按升序将它们分配给排序索引。 

关键的结构简化是我们永远不需要模拟交换。 我们只需要组件内的连接和排序。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（模拟交换/探索状态）| 指数| 指数| 太慢了 |
 | 组件+排序| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建一个图，其中每个索引都是一个节点，每个允许的交换都是一条无向边。 该模型准确地模拟了哪些头寸可以通过交换序列交换价值。 
2. 使用 DFS、BFS 或 DSU 查找该图的连通分量。 每个组件代表一组索引，其值可以在它们之间自由排列。 此步骤是必要的，因为交换可达性是可传递的。 
3. 对于每个连接的组件，收集属于它的所有索引，并收集当前存储在这些索引处的值。 此时，我们正在隔离独立子问题。 
4. 按升序对索引列表进行排序。 这些是按字典顺序从左到右排列的重要位置。 
5. 按降序对收集的值进行排序。 这确保了我们总是更早地放置更大的值，从而提高了尽可能早的位置的字典顺序。 
6. 重新分配值：对于组件中的最小索引，分配最大值，对于下一个索引，分配下一个最大值，依此类推。 这种贪婪配对是正确的，因为组件内的任何交换序列都可以实现任何排列。 

### 为什么它有效

 核心不变量是在任何连接的组件内，值的多重集被保留并且完全可置换。 每个允许的交换只是连接图中的一条边，并且重复交换允许在该组件内任意重新排列。 因此，我们唯一的自由是如何排列每个组件内的值。 

字典顺序从左到右比较数组。 在两个数组第一个不同的位置，较大的值决定获胜者。 这迫使采用贪婪策略：在每个组件中，最佳局部决策是首先最大化较早的索引，这是通过对索引升序和值降序排序并将它们配对来实现的。 

一个组件中的任何决定都不会影响另一个组件，因为交换永远不会跨组件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    vis = [False] * n

    def dfs(start):
        stack = [start]
        vis[start] = True
        comp = []

        while stack:
            v = stack.pop()
            comp.append(v)
            for to in g[v]:
                if not vis[to]:
                    vis[to] = True
                    stack.append(to)
        return comp

    for i in range(n):
        if not vis[i]:
            comp = dfs(i)

            idx = sorted(comp)
            vals = sorted([a[i] for i in comp], reverse=True)

            for j, v in zip(idx, vals):
                a[j] = v

    print(*a)

if __name__ == "__main__":
    solve()
```图构造直接编码交换权限。 DFS 将索引分组为组件，并且每个组件都是独立处理的。 对索引进行排序可确保我们尊重字典优先级，而按降序对值进行排序可确保我们贪婪地最大化每个位置。 

一个微妙的点是我们从不尝试显式地模拟交换。 正确性完全取决于这样一个事实：连通性意味着完全的排列自由，这消除了构建实际操作序列的任何需要。 

## 工作示例

 考虑一个具有部分连接的简单情况。 

输入：```
5 3
5 1 4 2 3
1 2
2 3
4 5
```我们有组件`{1,2,3}`和`{4,5}`（从 1 开始的索引）。 第一个组件有索引`[0,1,2]`有价值观`[5,1,4]`。 

| 步骤| 组件| 指数| 价值观 | 排序索引 | 排序值 | 作业 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | {1,2,3} | [0,1,2]| [5,1,4]| [0,1,2]| [5,4,1]| a[0]=5，a[1]=4，a[2]=1 |
 | 2 | {4,5} | [3,4]| [2,3]| [3,4]| [3,2]| a[3]=3，a[4]=2 |

 最终数组变为：```
5 4 1 3 2
```This shows how each component is solved independently and greedily.

 现在考虑一个完全连接的情况。 

输入：```
4 3
1 2 3 4
1 2
2 3
3 4
```一切都是一个组成部分。 

| 步骤| 指数| 价值观 | 排序索引 | 排序值 | 作业 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | [0,1,2,3]| [1,2,3,4] | [0,1,2,3]| [4,3,2,1] | 降序填充 |

 最终输出：```
4 3 2 1
```这证实了完全连接会产生按降序进行完全排序。

 ## 边缘情况

 一个关键的边缘情况是根本没有交换。 每个索引形成其自己的组件，因此算法应保持数组不变。 DFS 仍然运行，但每个组件的大小为 1，因此排序和赋值是无操作的，保留了原始序列。 

另一种情况是图完全连接时。 该算法将所有内容折叠成一个组件，并且整个数组按降序排序。 组件检测中的任何错误都会错误地将其分成更小的部分并破坏最优性。 

长链成分也很重要。 在路径图中，可达性仍然意味着完全的排列自由，即使交换是局部的。 DFS 正确地将整个链合并为一个组件，确保全局重新排列值，而不仅仅是本地交换。
