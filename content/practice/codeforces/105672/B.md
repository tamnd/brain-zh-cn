 ## 解决方案
 ## 问题理解

 我们有一套大炮，每门大炮每次发射都会产生固定数量的伤害。 时间以离散的秒数流逝，每一秒所有大炮同时发射。 然而，OwlBear 有一个旋转护盾：在第 k 秒，它恰好阻挡一门大炮，特别是由 (k−1) mod n 索引的大炮，因此大炮在那一秒贡献零伤害，而所有其他大炮仍然造成全部伤害。 

对于每个查询值 h，我们需要确定最小秒数 t，使得前 t 秒内造成的总累积伤害至少为 h。 

关键的微妙之处在于被阻挡的大炮每秒循环变化，因此每门大炮每n秒才被阻挡一次，并且在很长一段时间内每门大炮被均匀地阻挡。 这造成了贡献的重复模式。 

这些约束意味着 n 最多为 100000，测试中的总 n 加 q 最多为 200000，因此任何解决方案都必须接近线性或每个测试用例的 n log n。 对所有秒进行简单的模拟是不可能的，因为 h 可能高达 10^9，并且每秒的伤害可能足够大，以至于答案可能会达到非常大的 t。 

一种幼稚的方法可能会尝试逐秒进行模拟，每次重新计算所有活动大炮的总和并累加直到达到 h。 这会失败，因为每秒的成本为 O(n)，并且在最坏的情况下 t 也可能很大，导致 O(n·t)，这是完全不可行的。 

更仔细的蛮力通过预先计算所有大炮的总和并每秒减去被阻挡的大炮来稍微改善这一点，但仍然逐秒模拟使得对于大答案来说太慢。 

当 h 很小时，会出现不太明显的边缘情况。 例如，如果 h 小于一秒内可能造成的最大损害，则答案为 1。任何假设至少需要一个完整周期的解决方案都将在此失败。 

当 n = 2 时，会出现另一种边缘情况。护盾会在两门大炮之间交替进行阻挡，因此每一秒都会移除一个不同的元素。 这种模式变得非常有规律，处理模索引时的错误常常会导致大炮在某一秒被阻挡的差一错误。 

## 方法

 蛮力观点很简单。 在每一秒 k，我们将总损害计算为除 a[(k−1) mod n] 之外的所有 a[i] 的总和，然后保持运行的前缀和直到达到 h。 这是正确的，因为它完全遵循规则，但每秒从头开始计算总和的成本为 O(n)，从而使总复杂度为 O(n·t)。 由于 t 可能很大，并且 h 无界到 10^9，因此这种方法将立即超时。 

关键的观察是，所有大炮的总和是恒定的，称为 S。每一秒，恰好排除一门大炮，因此第 k 秒的伤害为 S − a[(k−1) mod n]。 在 n 秒的完整周期中，每门大炮都被排除一次，因此完整周期的总伤害为 n·S − S = (n−1)S。 

这将问题结构从“动态重新计算”简化为长度为 n 的固定重复数组，其中每个元素为 S − a[i]。 然后我们需要找到总和达到h的最小前缀长度，这成为无限周期数组上的标准前缀和+二分查找问题。 我们只需要处理完整的循环和部分循环前缀，这让我们可以在预处理后以 O(log n) 的方式计算每个查询的答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n·t) | O(1) | O(1) | 太慢了|
 | 周期模式上的前缀+二分查找 | O(n + q log n) | O(n + q log n) | O(n) | 已接受 |

 ## 算法演练

1. 计算所有火炮伤害的总和S。 这代表在没有大炮被阻挡的情况下一秒内的伤害。 
2. 构建数组 b，其中 b[i] = S − a[i]。 这代表了炮 i 被阻挡时第二秒的实际伤害贡献。 
3. 在 b 上构建一个完整周期的前缀和数组。 这允许快速计算循环任何前缀上的损坏。 
4. 计算一个完整周期内的总损坏，如下所示：cycle_sum = sum(b)。 
5. 对于每个查询h，首先通过将h除以cycle_sum来确定需要多少个完整周期。 每个完整周期都会造成固定数量的伤害，因此我们可以直接跳过许多秒而无需模拟。 
6. 将剩余所需损坏减少到完整循环后的剩余值。 
7、在剩余的部分循环上，二分查找循环重复的b中前缀和达到剩余损坏的最小前缀长度。 这是有效的，因为在一个周期内序列是固定的并且前缀和是单调的。 

### 为什么它有效

 核心不变量是每秒的损害仅取决于当前被阻止的索引，并且该阻止模式每 n 秒重复一次。 这保证了每秒损坏的序列是周期性的，周期为n。 一旦认识到这一点，整个过程就相当于在固定数组的无限重复上查找前缀和。 由于周期性数组上的前缀和分解为完整循环加上部分循环，因此我们始终可以将答案分成线性数量的完整循环加上一个循环内的有界搜索。 此结构确保贪婪或二分搜索步骤不会跳过有效的较短前缀，因为此构造数组中的前缀和是单调的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        q = int(input())
        queries = [int(input()) for _ in range(q)]

        S = sum(a)
        b = [S - x for x in a]

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + b[i]

        cycle_sum = pref[n]

        for h in queries:
            full = h // cycle_sum
            rem = h % cycle_sum

            if rem == 0:
                out.append(str(full * n))
                continue

            lo, hi = 1, n
            ans = n
            while lo <= hi:
                mid = (lo + hi) // 2
                if pref[mid] >= rem:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1

            out.append(str(full * n + ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先将每一秒的损坏压缩为每个阻塞索引的单个值。 b 上的前缀数组捕获一个周期内的累积损坏，cycle_sum 捕获完整旋转的贡献。 对于每个查询，通过除法提取完整周期数，这避免了任何模拟。 

二分搜索步骤至关重要，因为在一个周期内，损坏累积会随着时间严格增加。 这保证了一旦前缀总和超过剩余要求，所有更长的前缀也满足它，使得搜索有效。 

这里的一个常见错误是忘记阻塞索引每 n 秒重置一次，而不是在没有环绕的情况下全局增加。 这会错误地破坏周期结构并导致错误的答案。 

## 工作示例

 我们使用示例输入：

 n = 4, a = [2, 3, 2, 7]

 首先计算 S = 14，因此 b = [12, 11, 12, 7]，cycle_sum = 42。 

### 查询 1：h = 27

 我们计算 full = 27 // 42 = 0, rem = 27。 

我们搜索 b 的前缀：

 | 秒| 封锁索引 | 前缀和|
 | --- | --- | --- |
 | 1 | 0 | 12 | 12
 | 2 | 1 | 23 | 23
 | 3 | 2 | 35 | 35

 在第 3 秒，我们达到 35 ≥ 27，所以答案是 3。 

这显示了纯粹的部分循环情况。 

### 查询 2：h = 12

 满 = 0，雷姆 = 12。 

第一秒，前缀已经是 12，所以答案是 1。 

这证实了最小阈值的正确性。

 ## 边缘情况

 一个重要的边缘情况是所需的损伤 h 小于第一秒的贡献。 在这种情况下，答案必须是 1，因为第一秒就已经产生了足够的伤害。 该算法处理此问题是因为 rem ≤ pref[1] 立即触发二分搜索返回 1。 

另一种情况是h 是cycle_sum 的精确倍数。 在这种情况下 rem 变为零，并且答案必须恰好是完整周期乘以 n 秒。 该代码通过返回 full * n 来显式处理此问题，避免错误的二分搜索到空余数。 

当 n = 2 时，阻塞索引严格在 0 和 1 之间交替。前缀构造仍然有效，因为 b 正确地独立编码了每一秒的贡献，确保不违反有关独立性的假设。
