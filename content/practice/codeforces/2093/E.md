 ## 解决方案
 ## 问题理解

 我们得到一个数组，并要求将其精确地切成 k 个连续的块，这些块一起覆盖整个数组。 一旦数组被分割，每个片段都有一个 MEX 值，我们关心最差的片段，意味着所有 k 片段中最小的 MEX。 目标是选择分割，使最差的 MEX 尽可能大。 

重新构建这个问题会有所帮助：我们试图强制每个细分市场在少量的情况下都“足够丰富”，因为 MEX 仅取决于我们能多早保证 0、1、2 等的存在。 如果一个段缺少任何整数 x，则其 MEX 最多为 x。 

这些约束意味着每个测试用例的解决方案必须接近线性。 由于测试的总 n 为 2e5，因此任何比每个测试用例的 O(n log n) 或 O(n) 更差的方法都将失败。 如果每个候选值是线性的，则幼稚的贪婪模拟是可以接受的，但每个测试用例的 n 中的任何二次方都是不可能的。 

当 k 很大时，会出现微妙的边缘情况。 如果 k 等于 n，则每个段的长度为 1，因此每个 MEX 为 0 或 1，具体取决于元素是否为 0。另一个棘手的情况是数组根本没有零。 然后每个段都有 MEX 0，因此无论 k 如何，答案都强制为 0。 假设我们总是可以“收集”段内的值的天真的方法将在这里被打破。 

当人们试图过早地贪婪地切割片段时，就会出现另一种失败模式。 例如，如果我们试图通过在包含直到 x-1 的所有数字时立即结束一个段来贪婪地最大化 MEX，那么我们最终可能会使用太多段并且无法达到 k。 

## 方法

 关键思想是将答案视为我们可以测试的东西。 假设我们猜测一个值 x 并询问是否可以将数组分成至少 k 段，使得每个段的 MEX 至少为 x。 如果我们可以检查这个条件，我们就可以二分查找最大的 x。 

对于具有至少 x 的 MEX 的段，它必须包含从 0 到 x-1 的每个数字至少一次。 这将问题转化为滑动窗口的覆盖要求：每个有效段必须“收集”所有所需值才能关闭。 

一种强力方法是尝试所有方法将数组划分为 k 个段，并为每个段计算 MEX。 分区的数量是指数级的，因为每个 n-1 个间隙都可以被切割或不被切割。 即使计算每个段的 MEX 也会是 O(n)，所以这种方法是完全不可行的。 

进步来自于转变视角。 我们不选择剪切并检查 MEX，而是修复 x 并从左到右贪婪地构建段，总是在满足所有所需值 0 到 x-1 时立即结束段。 对于给定的 x，这种贪心构造会产生最大可能数量的有效段。 如果即使这个最大计数小于 k，那么 x 也是不可能的。 

这是有效的，因为将段延伸到它变得有效的点之外只能减少我们以后可以形成的段的数量，而永远不会增加它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区| O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 二分查找+贪心检查 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先对答案 x 进行二分查找，因为如果一个值 x 可行，那么任何较小的值也是可行的。

1. 对于固定的x，定义一个检查器来确定我们是否可以形成至少k个有效段，其中每个段包含从0到x-1的所有整数。 这是 MEX ≥ x 的确切条件。 
2. 从左到右扫描阵列，同时保持当前段的频率结构。 我们还跟踪到目前为止已经看到了多少个从 0 到 x-1 的不同值。 
3. 当我们看到范围 [0, x-1] 内的值 v 时，我们更新其频率，如果它成为当前段中的第一次出现，我们增加满足值的计数器。 
4. 一旦计数器达到x，当前段就有效。 我们立即切到这里，重置频率结构和计数器，然后继续扫描。 
5. 数一下这样可以形成多少个线段。 如果这个计数至少为k，则x是可行的； 否则就不是。 

二分查找范围是从 0 到 n+1，因为 MEX 在任何有意义的分区上下文中都不能超过 n+1。 

### 为什么它有效

 对于固定的 x，贪心策略总是在最早可能的有效位置结束段。 任何后续的切割只会消耗更多的元素，而不会增加有效段的数量。 因此，这种贪婪会产生该 x 可实现的最大数量的有效段。 如果这个最大值低于 k，则任何替代分区都无法成功。 这确定了可行性检查的正确性，然后二分查找给出了最大值 x。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(a, k, x):
    if x == 0:
        return True

    freq = [0] * (x + 1)
    have = 0
    segments = 0

    for v in a:
        if v < x:
            if freq[v] == 0:
                have += 1
            freq[v] += 1

        if have == x:
            segments += 1
            if segments >= k:
                return True
            freq = [0] * (x + 1)
            have = 0

    return segments >= k

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 0, n + 1
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(a, k, mid):
            lo = mid
        else:
            hi = mid - 1

    print(lo)
```检查器功能是该解决方案的核心。 它仅维护有关严格小于 x 的值的信息，因为较大的值不会影响 MEX 是否达到 x。 一旦在段中看到所有必需的值，该段就会立即关闭。 

二分搜索以标准中上形式实现，以避免无限循环并确保收敛到最大可行 x。 

## 工作示例

 ### 示例 1

 输入：```
5 2
2 1 0 0 1
```我们测试不同 x 的可行性。 

对于 x = 2，每个段必须包含 {0,1}。 我们扫描：

 | 索引 | 价值| 有 0 | 有 1 | 细分 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | 0 | 0 |
 | 1 | 1 | 0 | 1 | 0 |
 | 2 | 0 | 1 | 1 | 0 → 切 |
 | 3 | 0 | 1 | 1 | 1 |
 | 4 | 1 | 1 | 1 | 1 → 切 |

 我们得到 2 个段，因此 x = 2 是可行的。 

对于 x = 3，每个段需要 {0,1,2}。 只能形成一个线段，因此 x = 3 失败。 

这证实了答案2。 

### 示例 2

 输入：```
4 4
1 0 0 0
```对于 x = 1，每个段必须包含 0。 

扫描：

 | 索引 | 价值| 有 0 | 细分 |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 0 | 1 | 0 → 切 |
 | 2 | 0 | 1 | 1 → 切 |
 | 3 | 0 | 1 | 2 → 切 |

 仅当每次切割隔离零时，我们才能形成至少 4 个段，但在第一次切割后，我们已经消耗了结构，并且无法生成 4 个有效段。 所以结果是0。 

这显示了如何迫使许多细分市场崩溃可实现的 MEX。

 ## 边缘情况

 当数组根本不包含零时，每个段立即具有 MEX 0。 x = 1 的检查器失败，因为没有段可以收集值 0，因此二分查找正确地折叠为 0。 

当 k 等于 n 时，每个元素必须形成自己的段。 该算法将仅对单个元素已满足要求的段进行计数。 对于 x ≥ 2，这是不可能的，因为单个元素不能同时包含 0 和 1。可行性检查提前停止并根据零是否存在适当返回 0 或 1。 

当k=1时，整个数组就是一个段。 贪心检查简化为检查全局 MEX 条件，二分搜索有效地找到整个数组的 MEX，与问题定义相匹配。
