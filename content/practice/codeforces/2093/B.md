 ## 解决方案
 ## 问题理解

 我们得到一个十进制数作为字符串。 我们可以删除其数字的任何子集，同时保留剩余数字的相对顺序。 尽管允许使用前导零，但生成的数字序列必须表示正数。 

对于每个结果数字，其成本定义为：$$\text{cost}=\frac{\text{number value}}{\text{sum of its digits}}$$在所有有效子序列中，我们希望成本尽可能最小。 一旦达到最小成本，我们希望保留尽可能多的数字，因为输出要求删除的次数最少。 

输入数字最多可以包含 100 位数字，因此它远远大于标准整数类型。 这立即表明任何基于将子序列转换为实际整数的解决方案都是有风险的。 测试用例的数量最多为 1000，这意味着每个测试用例需要接近线性的时间。 由于每个字符串的长度最多为 100，即使是$O(n^2)$解决方案很容易足够快。 

棘手的部分是了解实际可能的最低成本是多少。 

一个容易犯的错误是认为保留更多的非零数字会有所帮助。 考虑：```
n = 12
```可能的有效子序列是`1`,`2`， 和`12`。 

费用为：$$1/1=1,\quad 2/2=1,\quad 12/(1+2)=4$$最小成本为 1，由单个非零数字实现。 正确答案是删除1。 

另一个微妙的情况是前导零变得有用：```
n = 1005
```保持`0005`是不可能的，因为必须保持秩序，但保持`005`是有效的。 其成本为$$5/(0+0+5)=1$$结果是三位数，而不是一位。 仅搜索单个数字的解决方案将错过最佳删除计数。 

第三个常见的陷阱是忘记最终数字必须为正数：```
n = 1000
```仅保留零是无效的，因为结果数字等于零。 最好的有效子序列是`0001`？ 该命令不存在。 最好的选择是`1000`,`100`,`10`， 或者`1`。 最小成本是通过以下方式实现的`1`，并且我们只能保留一位数字。 答案是删除3次。 

## 方法

 暴力解决方案将枚举给定字符串的每个子序列。 对于长度为 100 的数字，有$$2^{100}$$可能的子序列，这是完全不可行的。 即使对于长度 60，这也已经远远超出了可以处理的范围。 

暴力破解在概念上是有效的，因为我们可以计算每个有效子序列的成本并选择最好的一个。 问题在于搜索空间呈指数增长。 

为了找到更好的方法，我们需要了解成本函数的结构。 

假设一个子序列有数字和$S$和数值$V$。 由于该数为正数，$V \ge S$。 

为什么这总是正确的？ 十进制数$$d_k10^k+d_{k-1}10^{k-1}+\cdots+d_0$$至少是$$d_k+d_{k-1}+\cdots+d_0$$因为每个 10 的幂都至少是 1。 

这给出了$$\frac{V}{S}\ge 1$$对于每个有效的子序列。 

因此，最小可能成本永远不会低于 1。 

平等何时成立？ 

我们需要$V=S$。 十进制数等于其数字和的唯一方式是当恰好存在一个非零数字并且每个其他保留的数字都是前导零时。 示例：```
5
05
005
0007
```所有这些都花费了1。 

一旦我们知道可实现的最小成本始终为 1，任务就会完全改变。 我们不再优化一小部分。 我们只需要成本等于 1 的最长子序列。 

这样的子序列必须恰好包含一个非零数字，并且所有其他保留的数字之前必须为零。 该非零数字后面的任何零都会贡献一个小数位并增加数值而不增加数字总和，从而使成本大于 1。 

因此，对于每个非零数字位置，我们可以形成一个 cost-1 子序列，其中包含：

 1. 该位置之前的任何零。 
2. 非零数字本身。 

它的长度等于：$$(\text{number of zeros before it}) + 1$$我们想要最大的长度。 

如果原始字符串长度为$n$最大可保持长度为$L$，则答案为：$$n-L$$| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 最佳|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 设字符串的长度为$n$。 
2. 从左到右扫描字符串，同时保持到目前为止看到的零的数量。 
3. 每当当前数字为`'0'`，增加零计数器。 
4. 每当当前数字非零时，计算以该数字结尾的最长cost-1子序列的长度。 

该长度是：$$\text{zeros\_before}+1$$因为我们可以保留前面的每个零和这个非零数字。 
5. 跟踪所有非零位置上的最大此类长度。 
6. 扫描完成后，令这个最大长度为$L$。 
7. 输出：$$n-L$$因为我们保留$L$数字并删除其余部分。 

### 为什么它有效

 每个正数都满足$V \ge S$，因此每个有效成本至少为 1。当子序列的数值等于其数字和时，子序列恰好达到成本 1。 

对于十进制表示形式，仅当有一个非零数字且所有其他保留数字位于其前面且为零时，才会发生这种情况。 任何额外的非零数字增加的值都超过数字总和。 非零数字后面的任何零都会创建一个额外的小数位，并且还会增加该值。 

对于固定的非零数字，保留所有较早的零可以最大化子序列长度，同时保留成本 1。检查每个非零位置会找到最长的可能成本 1 子序列。 由于成本 1 是全局最小成本，因此最大化这些子序列的长度可以最小化删除的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    s = input().strip()

    zeros = 0
    best = 0

    for ch in s:
        if ch == '0':
            zeros += 1
        else:
            best = max(best, zeros + 1)

    print(len(s) - best)
```变量`zeros`存储当前位置之前出现了多少个零。 

每当我们遇到非零数字时，我们知道前面的每个零都可以与该数字保持在一起以形成成本为1的子序列。 结果长度是`zeros + 1`。 

变量`best`存储整个字符串中最大的此类长度。 

最后，如果`best`如果可以保留数字，同时实现尽可能小的成本，则必须删除所有剩余的数字。 答案是`len(s) - best`。 

一个微妙的细节是，所选非零数字后面出现的零永远不会被计算在内。 它们不能属于 cost-1 子序列，因为它们会增加数值，同时保持数字和不变。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        zeros = 0
        best = 0

        for ch in s:
            if ch == '0':
                zeros += 1
            else:
                best = max(best, zeros + 1)

        out.append(str(len(s) - best))

    return "\n".join(out)
