 ## 解决方案
 ## 问题理解

 我们被要求构造一个长度的字符串`m`，最初填充字母“B”，通过执行`n`由序列定义的操作`a_1, a_2, ..., a_n`。 每个元素`a_i`代表一种选择：在`i`-th 操作，我们可以设置`a_i`第 - 个字符或`(m + 1 - a_i)`- 字符串的第一个字符为“A”。 多个操作可以影响同一位置，但将字符从“A”更改为“A”没有效果。 目标是在所有操作之后获得按字典顺序排列的最小字符串。 

给定界限，与`n`和`m`最多 50 个，对于单个测试用例，对所有可能选择进行强力模拟是可行的，但对于最多 2000 个测试用例，我们需要一个在每个测试用例的线性时间内工作的解决方案，大约`O(n)`或者`O(m)`。 小输入量还表明基于简单比较的贪婪方法将有效地工作。 

非明显的边缘情况涉及以下选择：`a_i`指向对称位置。 例如，如果`m = 5`和`a_i = 2`，我们可以选择位置 2 或 4。总是选择的天真的方法`a_i`可能无法生成按字典顺序排列的最小字符串。 另一种极端情况是多个操作针对同一位置； 该算法必须确保优先考虑较早的位置以实现最小字符串。 

## 方法

 蛮力方法将尝试所有选择序列，设置`a_i`或者`(m + 1 - a_i)`对于每个操作。 和`n`操作，这导致高达`2^n`组合。 即使与`n <= 50`，这对于 2000 个测试用例显然是不可行的。 

关键的观察结果是，对于每个操作，字典顺序较小的选择是将两个可能位置中较小的一个设置为“A”。 这将问题转化为简单的贪婪选择。 由于一旦将位置设置为“A”，同一位置上的任何后续操作都不会恶化结果，因此我们可以安全地迭代`a`，计算两个候选位置，并选择较小的索引进行更新。 

这种方法非常高效，因为它对数组进行单次传递，执行恒定时间更新，并直接构造最终字符串而无需回溯。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(米) | 太慢了|
 | 贪婪最优 | 每个测试用例 O(n) | O(米) | 已接受 |

 ## 算法演练

 1.初始化字符串`s`长度`m`所有字符均为“B”。 这表示任何操作之前的起始状态。 
2. 迭代每个元素`a_i`在序列中`a`。 计算两个候选位置：`left = a_i - 1`和`right = m - a_i`。 这些是字符串中的零索引位置。 
3. 对于每个操作，选择两个位置中较小的一个，`min(left, right)`，设置为“A”。 这确保我们总是首先修改最左边的可用位置，这有助于形成按字典顺序最小的字符串。 
4. 将该位置的字符串更新为“A”。 如果该位置已经是“A”，则后续针对该位置的操作将无效。 
5. 全部运算结束后，输出结果字符串。 

为什么有效：贪婪选择总是选择对称候选之间最左边的可用位置。 从词典上看，较早的位置更重要。 一旦设置为“A”，位置就无法恢复，因此我们保留字符串的最小性。 这个不变量适用于每个操作，保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        s = ['B'] * m
        for ai in a:
            left = ai - 1
            right = m - ai
            pos = min(left, right)
            s[pos] = 'A'
        print(''.join(s))

if __name__ == "__main__":
    solve()
```该解决方案初始化字符串并独立处理每个操作。 选择`min(left, right)`保证最左边的字符优先。 仔细处理从零开始的索引。 这`print`输出每个测试用例的最终字符串。 不存在边界问题，因为`1 <= a_i <= m`。

 ## 边缘情况

 该算法通过始终选择最左边来正确处理对称位置。 例如，`m = 4, a = [1,3]`第一个结果为位置 0 和 3，第二个结果为位置 2 和 1。 贪心选择选择位置 0 和 1，产生`AABB`，按字典顺序排列是最小的。 反复选择，比如`[1,1,1]`，不要覆盖或恶化结果，保持正确性。 最小和最大长度以及针对边缘的操作都由相同的逻辑处理，无需额外的分支。
