 ## 解决方案
 ## 问题理解

 我们得到了代表比赛结果的一系列不递增的分数。 我们的任务是将排名靠前的部分分为三个连续的组：金、银和铜。 铜牌组之后的所有人都没有获得奖牌。 

分割必须遵守大小限制和严格的分数分离限制。 每个金牌参与者必须严格优于每个银牌参与者，每个银牌参与者必须严格优于每个铜牌参与者，每个铜牌参与者必须严格优于每个没有获得任何奖励的人。 

除了结构排序之外，金牌数量必须严格少于银牌和铜牌数量。 最后，获得奖牌的总数最多限于所有参赛者的一半。 

输出不是参与者的身份，而只是这三个连续部分的大小。 

这些约束意味着我们不能在测试用例中做任何二次甚至接近二次的事情。 所有测试的参与者总数达到 400,000，因此每个测试解决方案的 O(n) 或 O(n log n) 是必要的，并且强烈倾向于线性扫描。 

不明显的困难是，组之间的界限必须在严格的分数下降时出现。 如果两个相邻的参与者得分相同，则不能将他们分配到不同的奖牌类型中。 这使得天真的“尝试所有分割”变得脆弱，因为许多候选边界是无效的。 

当贪婪分割忽略相等块时，就会出现典型的失败情况。 例如，如果分数是`[5, 5, 5, 4, 4, 1, 1]`，选择`g=1`和`s=1`立即打破限制，因为黄金和白银将获得相同的分数。 任何正确的解决方案都必须使剪辑与乐谱过渡保持一致。 

## 方法

 蛮力策略会尝试所有三元组`(g, s, b)`从而满足排序和大小的约束。 对于每个候选人，我们将验证分数分离条件是否成立。 即使检查单个配置是线性的，分区的数量也是二次的，因为我们在大小的数组中选择两个分割点`n`。 这导致每个测试用例的配置大约为 O(n²)，这对于 400,000 个总元素来说太慢了。 

关键的观察是有效分区的结构是单调的。 一旦我们确定了黄金尺寸的值`g`，银牌组必须从下一个不同的得分块开始，铜牌组必须遵循相同的规则。 我们永远不需要在等分段内“搜索”； 我们总是跳过相同值的块。 

这将问题减少到扫描一次数组，同时保持块边界值相等。 对于每种可能的黄金尺寸，我们贪婪地将银牌和铜牌扩展到下一个有效边界，同时也强制执行`g < s`,`g < b`，且总数不超过`n/2`。 由于数组已排序，因此每个边界仅由分数变化的位置确定。 

然后，我们通过迭代可能的黄金边界并贪婪地扩展白银和青铜，并跟踪剩余的有效位置来搜索最佳可行配置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有分割）| O(n²) | O(1) | O(1) | 太慢了 |
 | 块贪婪扫描| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 遍历数组并将其压缩为分数相等的连续块。 每个块代表一个不允许内部分割的范围。 

原因是在一个区块内分裂会违反奖牌等级之间严格的不平等。 
2.让这些块有大小`cnt[0], cnt[1], ..., cnt[k-1]`。 
3.我们选择黄金段作为第一段`i`块，累积大小`g`。 
4. 白银必须从区块开始`i + 1`并延伸到至少一个块，所以我们积累块直到我们得到一个大小`s > g`。 
5. 铜牌紧随银牌之后开始，并且还必须满足`b > g`，所以我们进一步延伸，直到青铜尺寸超过黄金尺寸。 
6. 对于每个有效的位置`i`，我们计算`(g, s, b)`并检查是否`g + s + b <= n // 2`。 
7. 我们保留奖牌总数最大化的配置。 

重要的一点是，一旦黄金被固定，白银和青铜就被迫成为最小有效扩展。 任何更大的扩展都只会减少剩余空间，并不能提高以后分区的可行性，因为一切都受到固定的半限制。 

### 为什么它有效

 正确性取决于排序分数引起的单调结构。 任何有效的分区都必须与分数下降对齐，因此问题简化为在块边界中选择两个分割点。 对于固定的金边界，最小的有效银边界始终是最佳的，因为增加银只会减少青铜的可用空间，而无助于满足`s > g`。 同样的逻辑也适用于青铜。 

因此，贪婪扩张产生了唯一可能在约束下最大化总大小的候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        # compress into blocks of equal values
        blocks = []
        i = 0
        while i < n:
            j = i
            while j < n and p[j] == p[i]:
                j += 1
            blocks.append(j - i)
            i = j

        m = len(blocks)
        best = (0, 0, 0)
        total_best = 0

        prefix = 0

        # iterate gold ending at block i
        for i in range(m):
            g = prefix + blocks[i]
            if g >= n // 2:
                break

            # build silver
            s = 0
            j = i + 1
            if j >= m:
                prefix += blocks[i]
                continue

            s_start = j
            while j < m and s <= g:
                s += blocks[j]
                j += 1
            if s <= g:
                prefix += blocks[i]
                continue

            # build bronze
            b = 0
            k = j
            while k < m and b <= g:
                b += blocks[k]
                k += 1
            if b <= g:
                prefix += blocks[i]
                continue

            if g + s + b <= n // 2:
                if g + s + b > total_best:
                    total_best = g + s + b
                    best = (g, s, b)

            prefix += blocks[i]

        if total_best == 0:
            print(0, 0, 0)
        else:
            print(*best)

if __name__ == "__main__":
    solve()
```该代码首先压缩等分段，因为此类段内的任何分割都会违反奖牌类型之间的严格排序要求。 压缩后，每个块都被视为一个原子单元。 

然后我们迭代可能的黄金结局。 变量`prefix`有效跟踪黄金组的规模。 对于每一个黄金选择，我们都会贪婪地延长白银，直到它严格超过黄金，然后对青铜做同样的事情。 如果任一扩展失败，则配置将被丢弃。 

条件`g + s + b <= n // 2`强制执行全局约束。 我们跟踪迄今为止发现的最佳配置。 

一个微妙的点是，一旦黄金增长太大，我们就会提前突破，因为所有进一步的黄金价值只会增加`g`，由于`n/2`约束。

 ## 边缘情况

 一个关键的边缘情况是当大的等分块出现在潜在边界附近时。 如果黄金在这样的区块内结束，那么白银就不能在同一区块内开始。 压缩步骤迫使黄金消耗整个块或不消耗任何块，从而防止无效的部分分裂。 

另一个边缘情况是当`n`很小，特别是`n < 6`。 即使分数排序是完美的，半数限制通常也使得分配三个非空组变得不可能，因为`g + s + b`必须至少为 3 个，但也最多为 3 个`n/2`。 

当所有分数相等时，就会出现第三种情况。 任何形成三层的尝试都会违反相邻组之间的严格不平等，因此正确的输出始终是`0 0 0`。
