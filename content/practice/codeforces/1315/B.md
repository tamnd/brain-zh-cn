 ## 解决方案
 ## 问题理解

 我们得到一个一维城镇，表示为从 1 到 n 索引的十字路口线。 每个位置都只有一种类型的运输站：A 型（总线兼容路段标记）或 B 型（电车兼容路段标记）。 字符串 s 对此布局进行编码。 

Petya 从位置 1 开始，想要到达位置 n。 移动只有通过公共交通才有意义：从任何位置 i 开始，如果从 i 到 j−1 的每个位置都是 A，他就可以使用公共汽车跳到 j；如果从 i 到 j−1 的每个位置都是 B，则他可以使用有轨电车向前跳跃。每次这样的跳跃都会花费固定的价格，具体取决于交通类型，a 代表公交车段，b 代表有轨电车段。 

Petya 被允许从起点步行到某个位置 i，无需支付任何费用，然后必须仅使用从 i 开始的这些运输跳跃才能到达终点。 目标是选择尽可能小的起始位置 i，使得从 i 到 n 的总成本不超过 p。 

关键结构是移动成本仅取决于字符串中连续的统一段。 每个最大的相同字符块对应一个强制的“模式”段，在每个这样的块内，Petya 可以使用单张票自由地遍历。 

这些约束允许跨测试用例最多使用 10^5 个字符，这排除了任何从头开始重新计算每个起始位置成本的解决方案。 在最坏的情况下，重新计算每个 i 的行程成本的二次方法将达到 10^10 次运算，这是不可行的。 我们需要对每个测试用例进行线性或近线性预处理。 

一个微妙的边缘情况是 Petya 在字符串末尾附近的同质块内开始。 例如，如果 s =“AAAAA”并且 a 较大而 p 较小，则在同一块内较早或较晚开始不会改变成本结构，因为成本仅取决于块之间的转换，而不取决于确切位置。 

另一个边缘情况是交替字符串，如“ABABAB”。 这里的每一步都是一个新的段，因此成本几乎随着转换的数量线性增长，并且必须仔细应用关于分组的贪婪直觉。 

## 方法

 一个蛮力的想法是尝试每一个可能的起始位置 i。 对于每个 i，每当我们输入新的常量字符段时，通过向前扫描并求和成本来模拟从 i 到 n 的旅程。 每次模拟都需要 O(n) 时间，并且对所有 i 执行此操作会导致每个测试用例的时间复杂度为 O(n^2)，当 n 达到 10^5 时，这太慢了。 

关键的观察是从 i 到 n 的成本仅取决于从 i 开始的最大连续块的序列。 如果我们将字符串压缩成块，例如“AABBBBAA”变成具有长度的A，B，A，那么块内任何i的成本仅取决于从该块开始的该块序列的后缀。 

这表明了从右到左的动态编程结构。 如果我们将 cost[i] 定义为从位置 i 到 n 的最小成本，我们可以按相反的顺序计算成本。 当我们处于位置 i 时，我们要么停留在同一角色块内，要么过渡到下一个块，根据当前角色支付 a 或 b。 如果 s[i] == s[i+1]，则 cost[i] = cost[i+1]，因为我们仍在同一段内，并且在该边界不需要新票。 否则，我们支付一张票加上 cost[i+1]。 

一旦知道了所有 cost[i]，我们只需找到最小的 i，使得 cost[i] ≤ p。 

改进来自于认识到重复重新计算后缀成本是多余的，因为成本[i]仅取决于成本[i+1]和本地字符比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个 i 的暴力模拟 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 后缀成本上的反向 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

1. 预先计算大小为 n+1 的数组成本，其中 cost[n] = 0，因为已经到达目的地时不需要移动。 
2. 从右向左遍历字符串，从 i = n−1 一直到 1，从 cost[i+1] 计算 cost[i]。 这确保了在计算cost[i]时，后缀cost是已知的。 
3. 如果 s[i] 与 s[i+1] 相同，则设置 cost[i] = cost[i+1]。 这对应于停留在相同的运输类型块内，此步骤不需要新票。 
4. 如果 s[i] 与 s[i+1] 不同，则说明我们跨越了 A 和 B 之间的边界。在这种情况下，我们必须支付从 i 开始的航段的机票费用。 如果 s[i] == 'A'，我们添加 a； 否则我们添加b。 然后设置 cost[i] = cost[i+1] + 该值。 这反映了航段类型的每次更改都会强制生成新机票的事实。 
5. 计算完所有成本后，从 i = 1 扫描到 n 并返回满足 cost[i] ≤ p 的最小索引 i。 这代表了 Petya 能够到达终点的最早点。 

### 为什么它有效

 关键的不变量是 cost[i] 表示使用连续统一字符的最佳分割从 i 移动到 n 所需的确切最小成本。 因为任何有效路径都必须尊重段边界，并且每个边界交叉点都由 s[i] 是否不同于 s[i+1] 唯一确定，因此递归将旅程的所有可能分解捕获为最大单色段。 没有替代路径可以降低成本，因为在不改变字符约束的情况下跳过边界是不可能的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, p = map(int, input().split())
    s = input().strip()
    n = len(s)

    cost = [0] * n
    cost[-1] = 0

    for i in range(n - 2, -1, -1):
        if s[i] == s[i + 1]:
            cost[i] = cost[i + 1]
        else:
            cost[i] = cost[i + 1] + (a if s[i] == 'A' else b)

    ans = 0
    for i in range(n):
        if cost[i] <= p:
            ans = i + 1
            break

    print(ans)
```该实现直接反映了 DP 递归。 成本数组是 0 索引的，而问题是 1 索引的，因此最终答案在转换索引时加 1。 反向遍历确保我们永远不会访问未计算的状态。 

一个常见的错误是尝试先压缩段，然后再模拟跳转； 虽然有效，但没有必要，而且很容易使边界条件出错。 该 DP 完全避免了显式段构造。

 ## 边缘情况

 对于完全由相同字符组成的字符串（如“AAAAA”），每个 cost[i] 为零，因为没有发生转换。 该算法设置 cost[n−1] = 0 并向后传播等式，为所有 i 生成 cost[i] = 0，因此索引 1 始终正确返回。 

对于像“ABABAB”这样的完全交替的字符串，每个步骤都会引入一个新的段边界。 DP 在每个索引处添加 a 或 b，因此 cost[i] 随着到末端的距离线性增长。 该算法可以正确识别预算内最早的后缀，而无需显式分段。 

对于 a 或 b 远大于 p 的情况，只有靠近末尾的位置才有效。 DP 仍然正确地捕获了这一点，因为任何早期的不匹配都会立即累积成本，从而防止由于局部贪婪而导致不正确的可行性。
