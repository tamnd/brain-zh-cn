 ## 解决方案
 ## 问题理解

 我们被要求将三种类型的奖牌分配给比赛中固定数量的参与者。 每个参与者都可以获得一枚奖牌，奖牌有严格的等级制度：金牌最好，然后是银牌，然后是铜牌。 

规则并没有直接给出准确的计数。 相反，当按奖牌质量排序时，他们对排名的_前缀_施加最低覆盖率要求。 所有参与者中至少有十二分之一必须是金牌获得者。 所有参与者中至少四分之一必须获得黄金或白银。 至少一半的参赛者必须至少获得铜牌，这意味着所有获得奖牌的人都必须位于参赛者的上半部分。 

输出是三个整数，分别代表有多少参与者获得金牌、银牌和铜牌。 这些数量必须同时满足所有约束。 在所有有效的分配中，我们必须选择使用尽可能少的金牌的分配。 如果多个发行版共享最低黄金数量，我们就会尽量减少白银。 如果仍然平局，我们会尽量减少铜牌。 

对 n 的约束很小，最多 1000。这已经表明，即使是稍微二次或三次的方法也能轻松通过，但约束的结构表明更简单：所有条件仅取决于 n 的比率，因此应该可以使用算术而不是搜索直接导出答案。 

一个天真的误解是分别准确地分配 n/12 金、n/4 银和 n/2 铜。 这会失败，因为约束是累积的。 例如，如果 n 为 12，则 n/12 为 1 枚金牌，n/4 为总共 3 枚金牌或银牌，n/2 为总共 6 枚奖牌获得者。 简单的分裂可能会产生金 = 1、银 = 2、铜 = 3，但这已经取决于对累积阈值的一致解释。 另一种故障模式是独立地向下舍入每个分数，这可能违反“至少”约束。 例如，如果n = 5，则n/12小于1，但我们仍然需要至少一枚金牌，因为零会违反要求。 

关键的微妙之处在于，这些约束不是独立的分配，而是对累积计数的嵌套要求。 

## 方法

 一个蛮力的想法是尝试所有三元组 (g, s, b)，使得 g + s + b 介于 0 和 n 之间，并检查它们是否满足：

 g ≥ ceil(n/12)，g + s ≥ ceil(n/4)，g + s + b ≥ ceil(n/2)

 然后在 (g, s, b) 下选择字典顺序最小的三元组。 这是正确的，但没有必要。 尽管n只有1000，但在最坏的情况下这仍然会导致大约10^9个状态，这已经很浪费了，更重要的是它隐藏了结构。 

真正的观察是，一旦我们决定给予多少枚金牌，银牌计数就被强制为达到第二阈值的最小值，铜牌也同样被强制。 除了满足最低累积要求外，每个级别内没有任何自由。 因此，我们不进行搜索，而是直接计算最小可行前缀大小。 

我们计算：

 g = 最小整数 ≥ n/12

 s = 最小整数 ≥ n/4 减去 g

 b = 最小整数 ≥ n/2 减去 (g + s)

 这种贪婪的构造之所以有效，是因为增加较高优先级的类别总是有助于满足较低的约束，并且我们明确要求首先最小化金级，然后是银级，然后是铜级。

 ## 算法演练

1. 计算所需的最少金牌数，上限为n/12。 这是强制的，因为任何有效的解决方案都必须独立于其他选择满足第一个阈值。 
2. 准确分配金牌数。 我们选择尽可能小的值，因为黄金是平局规则中的首要任务。 
3. 计算有多少参与者必须至少拥有银牌或金牌：这是 n/4 的上限。 
4. 从该要求中减去已经分配的金牌，以确定需要多少银牌。 如果黄金已经超过阈值，那么白银就为零。 否则，白银将填补这一空白。 
5. 计算有多少参与者必须至少拥有青铜，这是 n/2 的上限。 
6. 从此阈值中减去金牌和银牌的总数来确定铜牌。 同样，如果之前的等级已经超过要求，则青铜级为零。 

### 为什么它有效

 每个约束适用于奖牌分配的累积前缀，而不是独立组。 一旦黄金固定在其最低可行价值，黄金的任何增加只会减轻白银和青铜的负担，而不会违反之前的限制。 同样，一旦黄金被固定，白银将由下一个阈值决定，与青铜无关。 这创建了一个单调结构，其中每一层都可以贪婪地填充，而无需重新审视之前的决策。 词典最小化与按升序排列的处理阈值完全一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    # ceil divisions
    g_need = (n + 11) // 12
    s_need = (n + 3) // 4
    b_need = (n + 1) // 2
    
    g = g_need
    s = max(0, s_need - g)
    b = max(0, b_need - (g + s))
    
    print(g, s, b)

if __name__ == "__main__":
    solve()
```该实现直接使用整数算术对天花板除法进行编码。 表达式 (n + k - 1) // k 用于避免浮点错误。 

首先分配 Gold 作为满足 1/12 条件的最小值。 白银是相对于累积的黄金+白银需求来计算的，而不是独立计算的。 相对于总奖牌覆盖范围要求，铜牌是最后计算的。 当较早的层已经超过阈值时，使用 max(0, ...) 可以防止负分配。 

## 工作示例

 ### 示例 1

 输入：```
n = 1
```阈值：

 g ≥ ceil(1/12) = 1

 g + s ≥ ceil(1/4) = 1

 g + s + b ≥ ceil(1/2) = 1

 | 步骤| 克| 克+s | g+s+b | 剩余要求|
 | --- | --- | --- | --- | --- |
 | 黄金之后| 1 | 1 | 1 | 银 = 0，铜 = 0 |
 | 银牌之后| 1 | 1 | 1 | 青铜= 0 |
 | 铜牌之后| 1 | 1 | 1 | 满意|

 输出：```
1 0 0
```这表明在 n 非常小时，所有阈值都崩溃到相同的要求。 

### 示例 2

 输入：```
n = 10
```阈值：

 g + s ≥ ceil(10/4) = 3

 g + s + b ≥ ceil(10/2) = 5

 | 步骤| 克| 克+s | g+s+b | 剩余要求|
 | --- | --- | --- | --- | --- |

 输出：```

```这演示了在早期分配得到最低限度修复后，后面的层如何吸收剩余的所需覆盖范围。

 ## 边缘情况

 对于 n = 1，所有三个阈值的计算结果均为 1，因此每个参与者都必须在累积解释下获得黄金。 算法设置g = 1，那么银牌和铜牌就变为零，因为累积要求已经立即得到满足。 

对于 n = 11，我们有 g = 1，s 要求 = 3，b 要求 = 6。分配黄金后，白银总共最多填充 3 个，青铜总共最多填充 6 个。 贪心减法正确地将剩余需求跨层级联，而不会过度分配早期类别。 

对于 n = 12，阈值变为精确整数。 g = 1，s = 3 - 1 = 2，b = 6 - 3 = 3，产生一个干净的分区。 该算法与比例期望完全一致，确认了可分点的正确性。
