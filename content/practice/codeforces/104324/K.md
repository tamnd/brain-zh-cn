 ## 解决方案
 ## 问题理解

 我们给出了一组$n$不同的邮政编码，每个邮政编码都写为 5 位数字的字符串（允许使用前导零，因此每个代码都可以视为长度超过 5 位的固定长度字符串$0$到$9$）。 将每个邮政编码视为图中的一个节点。 

如果两个节点的代码完全不同，则它们是连接的$k$位置，这意味着确切地说$k$五个数字位置中的数字不同，其余的$5-k$位置上的数字是相同的。 

对于每个起始节点$s$，Tommaso 从该节点开始，反复发现所有直接连接的节点，然后从这些节点继续，有效地获取图的全连接组件。 任务是为每个节点计算其连接组件的大小。 

关键的限制是$n$可以大到$10^5$，而每个代码有固定长度五。 这种组合很重要：该图的节点数量很大，但每个节点的结构却非常小。 任何尝试显式构建或检查所有对的解决方案都将立即失败，因为$O(n^2)$比较已经是$10^{10}$运营。 

真正的困难在于，邻接是由精确的汉明距离条件定义的，而不是由简单的前缀或相等条件定义的，这阻止了直接的散列或排序技巧直接解决它。 

当许多邮政编码的数字有大量重叠时，就会出现微妙的边缘情况。 例如，如果所有代码仅在一个位置不同，则对于$k=1$该图变得极其密集，并且朴素的对枚举将重复比较许多几乎相同的字符串。 另一个边缘情况是当$k=5$，其中边连接每个位置都不同的代码，这是非局部的，不能通过任何简单的前缀分组来捕获。 

## 方法

 一种直接的方法是比较每对邮政编码并计算它们在五位数位置的汉明距离。 这是正确的，因为它直接遵循边的定义，但它需要$O(n^2 \cdot 5)$运营。 和$n = 10^5$，这变得完全不可行，达到了$10^{10}$比较。 

为了改进，我们尝试利用字符串长度固定为 5 的事实。 我们不再考虑完整的成对比较，而是转变视角：两个代码之间的差异仅取决于哪些位置匹配和哪些位置不匹配。 这建议按固定位置的模式对节点进行分组。 

关键的观察是，不是直接精确地搜索远处的节点$k$，我们可以计算对于每个节点，有多少其他节点在位置子集上与它匹配。 如果我们知道，对于位置的每个子集，有多少节点共享该子集上的这些确切数字，那么我们可以使用位置子集上的包含-排除来重建有多少节点在给定的位置集中完全匹配。 

这将问题从显式图构造转变为计算一个非常小的宇宙中的重叠：五个位置的幂集，其中只有$2^5 = 32$子集。 这种有界结构使我们能够有效地计算所有所需的交互，即使是$10^5$节点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力两两比较 |$O(n^2 \cdot 5)$|$O(1)$| 太慢了|
 | 使用包含-排除进行子集计数 |$O(n \cdot 2^5 \cdot 2^5)$|$O(n \cdot 2^5)$| 已接受 |

 ## 算法演练

 我们将每个邮政编码视为五位数字的数组。 对于位置的任何子集，我们通过仅提取这些位置处的数字来定义签名。 

1. 对于位置的每个子集$S$，我们按签名对所有邮政编码进行分组，仅限于$S$。 对于每个节点$i$，然后我们可以快速计算$A_S(i)$，这是匹配的节点数$i$在所有职位上$S$。 这是有效的，因为相同的签名$S$保证这些职位的平等。 
2. 我们想要比“匹配”更精确的东西$S$”。我们需要确切地知道哪些位置匹配。为此，我们在超集上使用包含-排除。定义$E_S(i)$作为其匹配位置集的节点数$i$正是$S$。 这些值隔离了精确的平等模式。 
3.我们计算$E_S(i)$从已知的值$A_T(i)$， 在哪里$T \supseteq S$。 这种关系来自这样一个事实：如果一个节点匹配$i$至少在所有职位上$S$，它被计入每个$A_T(i)$对于超级组$T$。 我们使用交替和在子集格上反转它。 
4. 一旦所有精确匹配模式都计数$E_S(i)$已知，我们确定所有配置$5-k$位置匹配。 每个这样的子集$S$对应于精确获取汉明距离的有效方法$k$。 我们求和$E_S(i)$在所有子集上$S$尺寸的$5-k$得到节点的最终答案$i$。 

### 为什么它有效

 正确性取决于这样一个事实：每对节点对应于它们一致的位置的唯一子集。 该子集完全决定了它们的汉明距离。 包含-排除步骤确保每对在其真实一致模式下精确计数一次，因为来自较大超集的贡献被精确抵消，只留下匹配的精确结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

n, k = map(int, input().split())
codes = [input().strip() for _ in range(n)]

# precompute all subsets of positions
masks = []
for m in range(1 << 5):
    masks.append(m)

# for each mask, build mapping signature -> list size per node
# A[mask][i] = number of nodes matching i on mask
A = [[0] * n for _ in range(32)]

# build hash maps per mask
for mask in range(32):
    mp = defaultdict(list)
    for i, code in enumerate(codes):
        sig = []
        for pos in range(5):
            if mask & (1 << pos):
                sig.append(code[pos])
        mp[tuple(sig)].append(i)
    for sig, idxs in mp.items():
        for i in idxs:
            A[mask][i] = len(idxs)

# exact match pattern counts E[mask][i]
E = [[0] * n for _ in range(32)]

# inclusion-exclusion over supersets
for mask in range(32):
    for i in range(n):
        val = 0
        sub = mask
        while True:
            comp = ((1 << 5) - 1) ^ sub
            T = comp | mask
            sign = (-1) ** (bin(T).count("1") - bin(mask).count("1"))
            val += sign * A[T][i]
            if sub == 0:
                break
            sub = (sub - 1) & mask
        E[mask][i] = val

# answer: sum over masks with exactly 5-k matches
ans = [0] * n
for mask in range(32):
    if bin(mask).count("1") == 5 - k:
        for i in range(n):
            ans[i] += E[mask][i]

print(*ans)
```该解决方案首先将所有代码读取为固定长度的字符串。 然后，它为每个位置子集构建频率表。 每个表都允许恒定时间检索有多少代码与这些位置上的给定节点相匹配。 

包含-排除循环是核心的微妙之处。 对于每个子集，我们枚举其所有子掩码并将预先计算的计数与交替符号相结合。 这就是消除因超集多次贡献而导致的过度计数的原因。 

最后，我们只聚合那些大小恰好对应的子集$5-k$匹配位置，直接编码所需的汉明距离条件。

 ## 边缘情况

 当除一位数字外所有邮政编码均相同时，并且$k = 1$，每个节点都连接到在该位置不同的所有其他节点。 子集构造通过固定位置签名对节点进行分组，因此共享相同的四个固定数字的节点自然落入相同的桶中，并且包含排除隔离了精确的单位置差异要求。 

什么时候$k = 5$，仅计算没有匹配数字的对。 尽管许多中间子集桶很大，但最终聚合仅考虑大小为零的子集，这对应于完全不匹配模式。 反转步骤确保在达到最终总和之前取消任何意外的部分匹配。
