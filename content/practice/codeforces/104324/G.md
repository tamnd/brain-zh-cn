 ## 解决方案
 ## 问题理解

 我们得到了一组整数，最初以某种未知的顺序排列。 关于原始排序的唯一结构线索不是邻接或排序，而是与索引相关的全局算术属性：如果我们获取每个元素并将其在数组中的位置（1 索引）相加，则得到的数字共享一个大于 1 的公约数。 

等价地，存在某个整数$d > 1$这样每个值$a_i + i$可以整除$d$按照原来的正确顺序。 我们收到的输入只是打乱后的数组值，因此任务是决定是否可以将它们排列到位置$1 \ldots n$使得该整除条件成立，如果成立，则输出一个有效排列。 

关键的困难在于所有职位的约束都是全局的。 我们不在本地匹配对，我们正在尝试对齐值，以便单个隐藏除数$d$同时除所有移位值。 

约束条件$n \le 10^5$排除对排列的任何阶乘或指数搜索。 甚至$O(n^2)$解决方案是边界性的，因此结构必须将问题简化为接近线性或线性算数的问题。 由于值上升到$10^9$，我们也不能依赖密集的频率数组或对从值导出的所有候选除数进行强力枚举。 

当所有值都相等或者数组已经“几乎有效”但由于单个放置而失败时，就会出现微妙的边缘情况。 例如，如果$a = [2, 2, 3]$，即使有效的排序可能存在也可能不存在，尝试贪婪地放置很容易失败。 正确性取决于理解实际上是什么迫使全局除数存在。 

## 方法

 暴力解释是尝试数组的所有排列，计算所有值$a_i + i$，并检查它们的 GCD 是否大于 1。这根据定义是正确的，但立即不可能：有$n!$排列，以及每次检查成本$O(n)$，即使对于$n = 10$。 

关键的洞察力是翻转视角。 我们不考虑值的排列，而是修复由隐藏除数引起的结构$d$。 如果有这样一个$d$存在，那么对于每个位置$i$，我们必须有$a_i \equiv -i \pmod d$。 这意味着每个位置都会对可以放置哪些值施加模块化约束。 

所以对于固定的候选人$d$，问题就变成了在同余条件下位置和值之间的二分匹配。 然而，枚举所有可能的$d$还是太贵了。 关键的观察是$d$必须除以两个有效移位值之间的每个差：$$(a_i + i) - (a_j + j)$$对于任何有效的安排。 这表明$d$是一组结构化差异的除数。 

一个更简单、更强大的重新表述出现了：如果我们修复一个排列，则条件相当于说所有$a_i + i$位于相同的残基类模中$d$， 所以$d$除以所有成对差异。 因此，对于任何候选排列，$d$必须除以所选移位值之间的所有差异，这强烈限制了其可能的大小。 

这导致了一个建设性的策略：我们尝试将最小的元素与最小的索引对齐，假设有效的配置（如果存在）可以在减去索引后标准化为单调结构。 这将问题转化为检查我们是否可以分配值，以便序列$a_i + i$具有不平凡的 gcd，这相当于确保所有值与一致的残基结构对齐。 

最终的解决方案简化为对数组进行排序并测试规范分配，因为任何有效的配置都可以转换为按值排序的配置，而不会破坏移位值中公约数的存在。

 ## 算法演练

 1. 按非降序对数组进行排序，生成候选排列。 

这种选择的动机是，任何有效的配置都可以重新排列成尊重递增值的顺序，同时保留移位值中公约数的可行性。 
2. 计算所有值$b_i = a_i + i$对于这种排序的安排。 

索引结构现已固定，因此我们正在测试此规范对齐是否已经满足所需的 gcd 条件。 
3. 计算所有的gcd$b_i$。 

如果 gcd 大于 1，则该排列有效，我们可以输出它。 
4. 如果 gcd 等于 1，则得出结论：不存在有效排列。 

推理是，任何会产生更大 gcd 的排列都会与排序已经最小化结构变化这一事实相矛盾。$a_i + i$，因此不会出现隐藏的除数。 

### 为什么它有效

 核心不变量是有效的排列需要所有移位的值$a_i + i$位于单个算术残数类模某些$d > 1$。 任何排列仅排列这些移位值的多重集，但不会改变可以生成公约数的差的多重集结构。 

排序产生这种多集对齐的规范代表。 如果即使在这种最结构化的对齐中，gcd 也会崩溃为 1，那么任何重新排列都不能产生非平凡的公约数，因为排列无法创建尚未隐含在可能的移位和集中的新公约数。 因此，排序后的配置充当了可行性见证：要么揭示了有效的 gcd 结构，要么证明了不可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    g = 0
    for i in range(n):
        g = gcd(g, a[i] + (i + 1))
    
    if g == 1:
        print("NO")
    else:
        print("YES")
        print(*a)

if __name__ == "__main__":
    solve()
```解决方案的核心是对数组进行排序，然后评估变换后序列的 gcd$a_i + i$。 gcd 累积从零开始，以便第一个值正确初始化它。 

关键的实现细节是在形成时使用 1 索引位置$a[i] + (i+1)$。 一个常见的错误是混合索引基数，这会立即破坏正确性。 另一个微妙的点是用零初始化 gcd，因为$\gcd(0, x) = x$，这避免了第一个元素的特殊情况。

 ## 边缘情况

 一种重要的边缘情况是所有元素都相同。 用于输入`[k, k, k]`，排序没有任何改变，移位后的值变成`k+1, k+2, k+3`。 gcd 完全取决于`k`以及指数的算术模式。 该算法无需特殊外壳即可正确评估这一点。 

另一种情况是当数组最小时，`n = 2`。 如果值相差 1，例如`[1, 2]`，移位值是`[2, 4]`按排序顺序，产生 gcd 2 和有效答案。 该算法自然地捕获了这一点，而无需分支。 

第三种边缘情况是，数组在结构上看起来很有前途，但由于单个不兼容的值而失败，例如`[1, 2, 3]`。 排序后，移位后的值变为`[2, 4, 6]`并且gcd为2，所以它是有效的。 这表明即使看似“紧密”的序列仍然可以满足条件，并且正确性完全取决于 gcd 计算而不是视觉直觉。
