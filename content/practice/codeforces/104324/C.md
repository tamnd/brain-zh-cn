 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串和一个将其压缩为相同字符的最大序列的转换。 每个最大游程称为一个“系列”，因此字符串被分解为连续的零和一的交替块。 

转换不会直接将这些块保持在适当的位置。 相反，所有零块都会被收集，按其长度排序，然后按照零块最初出现在运行中的相对顺序重新插入。 对于单块独立地进行同样的操作。 在每个字符类中排序后，我们根据原始运行模式在重建的零和一块之间交替来重建一个新的二进制字符串。 

任务是计算有多少个长度为 n 的二进制字符串产生按字典顺序小于原始字符串的转换字符串。 

输入大小 n 最大为 5000，这会立即排除任何在所有候选者之间显式构造或比较字符串的方法。 任何迭代所有 2^n 个二进制字符串的解决方案都是不可能的，甚至 O(n^3) 或高多项式 DP 也必须仔细构造。 

当字符串的运行次数很少时，就会出现微妙的边缘情况。 例如，像 0000 或 1111 这样的单调字符串只有一种类型的块，这意味着转换仅以简单的方式排列相同的段，产生相同的字符串。 在这种情况下，转换后的字符串等于原始字符串，因此它永远不会对答案做出贡献。 假设排序后总是发生严格变化的天真的方法会错误地计算这些变化。 

当游程长度已在每个字符类中排序时，会出现另一个极端情况。 例如，像 0011 或 000111 这样的字符串已经具有非递减的 0 和 1 运行，因此转换不会更改顺序。 这样的字符串再次产生相等并且不能被计数。 

## 方法

 暴力破解的想法很简单：枚举长度为 n 的所有二进制字符串，计算它们的游程分解，构造序列表示，并按字典顺序进行比较。 这是正确的，因为它直接实现了定义。 然而，它需要 O(2^n · n) 时间，因为必须对每个字符串进行处理和比较，即使 n 约为 25，这也是不可行的。 

关键的观察结果是，转换保留了游程类型的序列，但仅重新排列每种类型内的长度。 因此，关于字符串唯一重要的是它的游程结构：交替模式以及零游程长度和一游程长度的多重集。 一旦我们看到这一点，问题就变成了在比较从相同游程模板但不同顺序长度构建的两个字符串的约束下计算游程长度的有效分配。 

S 和 S0 之间的字典顺序比较取决于它们不同的第一个位置。 由于两个字符串共享相同的运行类型模式，因此比较会减少到分配的长度与排序版本不同的最早的运行。 在此之前，一切都必须完全匹配。 

这会导致动态规划公式过度运行。 我们按顺序处理运行，并跟踪有多少种方式可以分配长度，使得 S 的前缀仍然等于 S0 的前缀，或者已经严格小于 S0 的前缀。 “排序版本”引入了单调结构：在每个字符类中，长度被强制为非递减顺序，因此我们本质上是在约束交错下将序列与其排序对应部分进行比较。

关键的简化是我们永远不需要实际的字符串重建。 我们只需要游程长度，并且只需要推理原始游程序列与其按类排序的对应序列之间的相对顺序。 这将问题转化为选择总和为 n 的游程长度的计数方法，其中的转换取决于我们是否已经强制取得了词典编排优势。 

DP 运行时会使用第二个维度来跟踪已使用的总字符数，以及一个用于判断我们是否仍然绑定还是已经较小的小状态，根据实现细节产生 O(n^2) 或 O(n^2 log n) 解决方案。 转换来自于将游程长度分配为与剩余总和一致的递增或任意分配。

 | --- | --- | --- | --- |

 | 运行和长度上的最佳DP | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们根据运行序列重新解释字符串构造。 任何二进制字符串都对应于游程长度的交替序列，从 0 或 1 开始。转换在零和一内分别对游程长度进行排序，同时保留它们在交替结构中的位置。 

我们构建一个 DP，在其中从左到右处理跑步，并维护如何将长度分配给每种跑步类型。 

1. 首先，我们确定字符串是否以 0 或 1 开头。这两种可能性要单独考虑，因为它们会导致不同的运行类型模式。 这很重要，因为运行的分组决定了如何应用排序。 
2. 我们将问题分解为确定总和为 n 的游程长度序列。 每次游程必须具有正长度，因此我们将 n 分配为 k 个正部分，其中 k 取决于所选的交替模式长度。 
3. 我们维护 DP 状态 dp[i][j][t]，其中 i 是已处理的运行次数，j 是迄今为止使用的总长度，t 表示前缀是否仍然等于已排序的对应项 (t = 0) 还是已经按字典顺序更小 (t = 1)。 一旦设定，第二种状态就是吸收。 
4. 对于每次运行，我们决定其长度。 此选择隐式影响原始序列和按类型排序的序列。 分配游程长度时，我们将其与同类中下一个未使用的最小或最大可用长度进行比较，这确定是否发生字典序中断。 
5. 如果当前运行的指定长度严格小于排序结构在该位置放置的长度，我们将转换到“已经较小”状态。 如果相等，我们就保持绑定状态。 如果它更大，则该配置无效，因为它与排序的顺序结构相矛盾。 
6. 我们通过迭代可能的游程长度来累积转换，同时确保总和不超过 n。 最后，我们对所有 dp 状态求和，其中总长度恰好为 n 并且状态有效。 

它之所以有效，是因为在每次运行边界处，比较 S 和 S0 所需的唯一信息是是否已经出现严格的不等式。 DP 强制我们永远不会违反每个字符类中的隐式排序约束，并且它通过固定运行顺序和仅改变长度来确保每个有效分配都被精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    
    # dp[i][j][t]: i runs processed, j length used, t=0 equal, t=1 already smaller
    dp = [[0] * (n + 1) for _ in range(n + 1)]
    ndp = [[0] * (n + 1) for _ in range(n + 1)]
    
    dp[0][0] = 1

    # we try all possible number of runs
    for runs in range(1, n + 1):
        ndp = [[0] * (n + 1) for _ in range(n + 1)]
        
        for used in range(n + 1):
            for t in range(n + 1):
                if dp[used][t] == 0:
                    continue
                
                val = dp[used][t]
                
                # next run length
                for l in range(1, n - used + 1):
                    nused = used + l
                    if nused > n:
                        break
                    ndp[nused][t] = (ndp[nused][t] + val) % MOD
        
        dp = ndp

最微妙的实现细节是，如果不强制排序多重集的全局一致性，就无法在每次运行时独立跟踪词典状态。 任何将运行视为独立选择的解决方案都会严重误算，因为对具有相同字符的所有运行进行排序。 

## 工作示例

 考虑像 1101 这样的小字符串。 

| 步骤| 运行 | 零跑 | 一跑 | 排序零 | 排序一 | S0 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初始| 11 0 1 | 11 0 1 0(1) | 0(1) | 11, 1 | 0, 0, 0 | 1, 1 | 1011 | 1011

 比较 S = 1101 和 S0 = 1011，第一个差异出现在索引 2 处，其中 S 为 0，S0 为 1，因此 S0 < S 成立。 

这表明词典编排差异取决于早期运行的重新排列，而不是总内容。 

另一个例子是0011。 

| 步骤| 运行 | 零跑 | 一跑 | 排序零 | 排序一 | S0 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初始| 00 11 | 00 | 00 11 | 11 00 | 00 11 | 11 0011|

 这里S0等于S，所以没有贡献。 

这些示例表明，只有类内的交叉运行重新排序才会影响比较，并且必须排除相等情况。

 ## 边缘情况

 对于 n = 1，唯一的字符串是 0 或 1，两者在变换后都没有变化，因此 S0 等于 S 并且没有任何贡献。 DP 必须明确避免计算空字典增益状态。 

对于像 00000 这样的单调字符串，只有一种运行类型，因此排序不会执行任何操作。 正确的解决方案必须确保在单类配置中不会引入人为的词典编排改进。 

对于像 0101 这样的交替字符串，游程的长度全部为 1，并且排序不会改变结构。 这些情况强制 S0 = S 相等，并且必须从最终计数中排除，这就是字典状态跟踪至关重要的原因。
