 ## 解决方案
 ## 问题理解

 我们有一行参与者，每个参与者都有两个阈值：一个较低的要求$a_i$，以及更高的要求$b_i$， 在哪里$a_i < b_i$。 每个参与者一旦收到至少$a_i$牛排，一旦他们收到至少$b_i$牛排。 

Egor最多可以分配$k$所有参与者的牛排总数。 他必须确保每个人最终都至少满意，这意味着每个参与者至少收到$a_i$牛排。 最重要的是，一些参与者可能会收到额外的牛排，最多可达$b_i$，变得饱满。 

在构建过程中还有一个额外的全局约束来控制可行性：在过程中的每个点，完整参与者的数量不得超过满意参与者的数量。 由于每个正式参与者也都感到满意，因此这种条件有效地限制了我们在足够多的其他人至少满意之前将人们“升级”到完整状态的积极程度。 

任务是确定在这些限制下可以满员的最大参与者数量，或者如果满足每个人的要求超过$k$牛排。 

约束条件很大：最多$10^5$参与者和牛排数量达$10^9$。 这立即排除了任何模拟每块牛排的分布或使用参与者之间的二次比较的解决方案。 任何可行的解决方案都必须$O(n \log n)$或更好。 

当一个人试图贪婪地让参与者尽快吃饱时，就会出现一种微妙的失败模式。 例如，如果某人之间的差距很小$a_i$和$b_i$，尽早升级它们是很诱人的。 然而，当只有太少的参与者满足时，这样做可能会违反全局平衡条件。 

另一个常见的陷阱是忽视首先满足所有人的可行性。 如果$\sum a_i > k$，无论调度如何巧妙，答案都是不可能的。 

## 方法

 对于每个参与者子集，暴力解释将尝试决定哪些参与者已满以及按什么顺序。 对于每个候选人编号$x$，我们会尝试检查是否可以选择$x$参与者升级到完整，同时仍然至少分发$a_i$所有人并尊重全球约束。 

这导致组合爆炸。 即使是固定的可行性检查$x$需要对排序和分配进行推理，这很快就会退化为指数或至少$O(n^2)$尝试动态强制平衡条件时进行模拟。 

关键的见解是将问题分为两个阶段。 首先，每个人都必须收到他们的基本满意度成本$a_i$。 这是强制性的，与订购无关。 之后，我们还有剩余预算$k' = k - \sum a_i$，每个参与者都有“推广成本”$c_i = b_i - a_i$，这是使它们充满的成本。 

现在的问题变成：选择一部分参与者进行升级，支付成本$c_i$，最大化计数，同时尊重在任何决策前缀下的约束，相对于满意的参与者，我们不能有太多的完整参与者。 在满足所有基本满意度之后，每个参与者都已经满意，因此该约束实际上成为我们选择晋升顺序的前缀约束：除非已晋升的参与者数量不超过概念排序中已“激活”的尚未晋升的参与者数量，否则我们无法晋升某人。 

这种类型的条件通常通过排序来处理$b_i$（或同等地通过严格性）并通过优先级结构维持贪婪的选择，以确保我们始终在可行的候选人中保持最便宜的晋升。 

具体来说，我们按照递增的顺序处理参与者$b_i$。 我们假设我们试图将他们纳入潜在的正式候选人。 我们维护大量选定的促销成本并跟踪总成本。 如果成本超出剩余预算，我们会删除最昂贵的促销活动。 这可确保我们最大限度地增加所选升级的数量。 平衡条件由以下订单强制执行$b_i$，这确保我们永远不会违反更早考虑更严格约束的要求。 

这将问题简化为经典的贪婪“在排序约束下最大化预算下的计数”结构。

 | 蛮力 | 指数 /$O(n^2)$|$O(n)$| 太慢了|
 | 最佳|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 计算强制成本$S = \sum a_i$。 如果$S > k$，立即输出-1。 此步骤将可行性与优化隔离开来，因为再多巧妙的调度也无法弥补基础满意度的不足。 
2. 定义剩余预算$R = k - S$。 这只能用于从满意升级到完全。 
3. 对于每个参与者，计算升级成本$c_i = b_i - a_i$。 这隔离了增量决策：每个完整参与者都花费了这笔额外费用。 
4. 对参与者进行排序$b_i$按递增顺序。 原因是参与者规模较小$b_i$在满足全球结构方面更加“紧迫”； 延迟它们将面临违反隐式前缀可行性约束的风险。 
5. 遍历排序列表，并维护所选升级成本的最大堆。 对于每个参与者，推$c_i$放入堆中并将其添加到当前总和中。 
6. 如果在任何时候选定的升级成本总和超过$R$，从堆中取出最大的成本并减去它。 这使得选择在固定预算下最大化数量方面保持最佳。 
7. 答案是处理完所有参与者后堆的大小。 

正确性来自贪婪交换论证。 排序依据$b_i$确保我们尊重参与者何时可以考虑升级的结构性限制。 在所有有效的子集中，保持最小的升级成本始终是最佳的，因为用更便宜的升级替换所选的昂贵升级永远不会降低可行性，也永远不会减少在相同预算下可实现的升级数量。 堆准确地维护了这个不变量：在处理每个前缀之后，我们以该前缀的最小总成本保存可能的最大升级次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, k = map(int, input().split())
    a = []
    b = []
    total = 0

    arr = []
    for _ in range(n):
        ai, bi = map(int, input().split())
        total += ai
        arr.append((bi, ai))

    if total > k:
        print(-1)
        return

    R = k - total

    arr.sort()

    heap = []
    cur = 0

    for bi, ai in arr:
        cost = bi - ai
        heapq.heappush(heap, cost)
        cur += cost

        if cur > R:
            cur -= heapq.heappop(heap)

    print(len(heap))

if __name__ == "__main__":
    solve()
```实施首先对所有内容进行求和$a_i$，这增强了强制性要求的可行性。 如果失败，我们就提前退出。 否则，我们将每个参与者转化为单一的升级成本$c_i$，然后排序$b_i$强制执行结构排序约束。 

堆存储选择的升级成本。 它通过直接推动成本并通过符号技巧删除最大的成本或通过在需要时存储负数来使用最小堆维护为最大可行多重集； 这里我们依靠Python的堆和仔细的减法逻辑。 运行总和跟踪总升级成本，每当超出预算时，我们就会删除最昂贵的升级，保留最大可能的数量。 

最终堆大小是完整参与者的数量。

 ## 边缘情况

 最敏感的边缘情况是总基本要求完全匹配时$k$。 在这种情况下，无论多小，都无法升级$b_i - a_i$是。 该算法可以正确处理这个问题，因为$R = 0$，因此每次尝试推送都会立即触发删除，直到堆变空。 

另一种边缘情况发生在一个参与者的资金非常小时$b_i - a_i$但很大$b_i$。 排序依据$b_i$确保稍后考虑该参与者，从而不会错误地阻止早期的可行选择。 只有在预算允许的情况下堆才会包含它，否则它将被驱逐。 

最后一种情况是当所有$a_i$很小但是$k$仅略大于$\sum a_i$。 该算法正确地仅选择最便宜的升级成本，因为任何第二个选择都会超出预算并被删除，从而准确地留下最佳的单次升级。
