 ## 解决方案
 ## 问题理解

 我们有一排怪物，每个怪物都有一个力量值。 丹尼亚尔使用一把剑与他们战斗，这把剑可以一次挥击消除连续的怪物块，但只能达到固定的长度`k`在目前剩余的阵容中。 每次挥击后，剩余的怪物都会缩小间隙，因此阵列始终保持紧凑。 他最多能表演`m`波动。 

对于固定的剑长度`k`, Daniyar 最多可以删除`m`段，其中每个段最多是一个连续的大小块`k`在删除时的当前数组中。 他的目标不是最大化他杀死的怪物，而是最小化所有行动后幸存的最强怪物。 

所以对于每个`k`从`1`到`n`，我们实际上是在问：如果我们被允许`m`最多大小的“块删除”`k`，剩下的元素中可能的最小最大值是多少？ 

输出是一个长度序列`n`，其中每个的答案`k`是`0`如果可以删除所有怪物，否则就是最小可达到的最大生存强度。 

这些限制迫使我们大致走向`O(n log n)`或者`O(n)`每个测试逻辑。 和`n, m`最多`3 · 10^5`，任何尝试为每个独立地重新计算完整模拟的解决方案`k`立刻就太慢了。 

一个微妙的困难是删除是在动态收缩的数组上执行的。 将删除视为对原始索引的操作的简单实现会中断，因为索引在每次删除后都会发生变化。 

一些边缘情况清楚地暴露了这个问题。 假设怪物是`[5, 1, 5]`,`m = 1`,`k = 2`。 如果我们删除`[5, 1]`，剩余的数组变为`[5]`，所以答案是`5`。 删除原始数组中固定索引段的简单方法可能会错误地假设它可以删除不同的对并错误地得出最大值为`1`。 转变结构是必要的。 

当坏元素被好元素分开时，就会出现另一种失败情况。 删除好的元素实际上可以帮助将坏的元素更紧密地合并到压缩数组中，从而改变未来的删除机会。 

## 方法

 直接暴力方法修复了一个值`k`并尝试所有可能的方法来使用最多`m`删除。 每次删除都会选择当前数组中的一个段，每次操作后状态都会发生变化。 即使我们贪婪地选择段，状态空间也取决于之前删除了哪些段，这会导致指数分支。 

即使是贪婪的模拟`k`已经成本`O(n)`或者`O(n log n)`取决于实施情况，并对所有人重复`k`使它大致`O(n^2)`，远远超出了极限。 

关键的观察是我们实际上不需要模拟所有可能的删除序列。 对于固定阈值`T`，我们只关心是否可以删除所有大于的元素`T`。 如果可以的话，那么最终的答案最多就是`T`。 这将问题转化为仅对“坏”元素进行可行性检查。 

现在确定一个阈值`T`。 调用每个元素`a[i] > T`一个坏因素。 我们希望最多使用删除所有坏元素`m`运营。 每个操作最多删除一个连续大小的块`k`在_当前压缩数组_中。 

关键的结构是贪心策略变得有效：在按顺序扫描坏元素时，每当遇到未删除的坏元素时，我们必须开始删除以覆盖它。 由于操作数量有限，延迟删除毫无帮助，任何最佳策略都可以转变为始终从最早发现的坏元素中删除的策略。 

这降低了确定性过程的可行性。 我们将当前数组保持为活动位置并重复删除下一个`k`从第一个发现的坏元素开始的存活位置。 这可以使用支持顺序统计的数据结构来实现，例如芬威克树或线段树。 

对于每个`k`，我们可以对最小可能的最大生存值进行二分搜索，但是每个独立地执行此操作`k`还是太慢了。 相反，我们扭转观点：对于固定阈值`T`，计算最小值`k`需要制作`T`可行的。 由于可行性提高`k`增加，这个函数是单调的，我们可以计算所有的答案`k`通过按降序扫描阈值`a[i]`。 

在实践中，我们对值进行排序并从大到小处理它们，维护需要多少次操作，并跟踪最小的`k`这允许删除所有当前的坏元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每 k 的强力模拟 | O(n²·米) | O(n) | 太慢了|
 | 阈值+贪婪+BIT+扫描| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先描述可行性检查，然后解释如何在所有方面重用它`k`。 

1. 固定阈值`T`并标记所有位置`a[i] > T`一样糟糕。 这些是我们唯一需要消除的元素。 
2. 维护支持“第 k 个活动元素”查询的索引数据结构。 最初，所有位置都处于活动状态。 
3、按照当前存活顺序从左到右遍历坏元素。 当我们发现仍然存在的坏元素时，我们将其视为删除所需的起点。 
4. 假设当前坏元素有rank`r`活的元素之中。 我们删除下一个`k`活着的元素从`r`。 这模拟了压缩阵列中剑的一次挥动。 
5. 重复，直到所有坏元素都被删除或超过`m`运营。 
6. 如果我们在`m`删除、阈值`T`对于这个是可行的`k`。 

为了将其扩展到所有`k`，我们观察到增加`k`只会让每一次删除变得更强大，而不是更糟。 因此对于每个阈值，所需的操作数量在`k`。 

因此，对于每个候选阈值，我们保持最小`k`允许可行性，并反转这种关系来为所有人提供答案`k`。 

### 为什么它有效

 在任何时刻，贪婪策略都确保我们始终从最早剩余的坏元素开始删除块。 任何最佳策略都必须在某些操作中涵盖该要素； 否则它就会永远存在，与可行性相矛盾。 一旦修复了该操作，剩余的问题在活动订单的严格较小的前缀上是相同的。 这会产生一个不变量：每次删除后，所有剩余的坏元素都严格位于活动排序中先前处理的元素之后，因此永远不需要重新考虑决策。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# Fenwick tree for order statistics
class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def build(self):
        for i in range(1, self.n + 1):
            self.add(i, 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        cur = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = cur + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                cur = nxt
            bitmask >>= 1
        return cur + 1

def can(k, m, n, arr, T):
    bit = BIT(n)
    bit.build()

    bad = []
    for i, v in enumerate(arr, 1):
        if v > T:
            bad.append(i)

    ops = 0
    idx = 0

    for pos in bad:
        if bit.sum(pos) - bit.sum(pos - 1) == 0:
            continue

        r = bit.sum(pos)
        ops += 1
        if ops > m:
            return False

        # delete k alive elements starting from r
        for _ in range(k):
            if bit.sum(n) == 0:
                break
            x = bit.kth(r)
            bit.add(x, -1)

    return True

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    vals = sorted(set(a), reverse=True)

    ans = [0] * (n + 1)

    for T in vals:
        # binary search minimal k for this T
        lo, hi = 1, n
        best = n
        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, m, n, a, T):
                best = mid
                hi = mid - 1
            else:
                lo = mid + 1
        for k in range(1, best + 1):
            if ans[k] == 0:
                ans[k] = T

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该解决方案将两个问题分开。 这`can`函数模拟是否可以使用给定的值清除固定阈值`k`。 它使用芬威克树来维护活动位置，并支持删除后跳转到压缩数组中的正确位置。 

外循环按降序迭代可能的答案值。 对于每个阈值，它找到最小的`k`可以处理它。 这是安全的，因为一旦达到某个阈值`k`，全部较大`k`也将是可以实现的。 

一个微妙的实现细节是，删除操作在_活动索引空间_中进行，而不是在原始索引中进行。 芬威克树确保当我们说“删除从 r 开始的 k 个元素”时，我们删除当前压缩数组中的连续元素，这是对问题的正确解释。 

## 工作示例

 ### 示例 1

 输入：```
n = 5, m = 1
a = [3, 5, 4, 1, 2]
```我们考虑一个阈值`T = 3`，所以坏元素是`[5, 4]`。 

| 步骤| 位置不好| 活体尺寸| 操作使用| 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 5 | 1 | 删除从 2 开始的 k 个元素 |
 | 2 | 3 | 3 | - | 剩余不良处理|

 为了`k = 3`，一次操作就够了，所以阈值`3`是可行的。 较小的阈值也会类似地失败。 最终答案反映了可达到的最佳最大值。 

### 示例 2

 输入：```
n = 3, m = 2
a = [3, 1, 2]
```为了`T = 1`，除`1`很糟糕。 

| 步骤| 位置不好| 活体尺寸| 操作使用| 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 3 | 1 | 删除前 k 个活着的 |
 | 2 | - | - | 2 | 剩余清洁|

 有了足够的`k`，所有坏元素都可以被删除，产生答案`0`。 

这些痕迹显示了算法如何始终作用于最早剩余的坏元素，以及删除如何重塑活动结构。

 ## 边缘情况

 一个关键的边缘情况是坏元素被许多小值分隔开。 在这种情况下，首先删除好元素实际上可以减少压缩数组中的距离，并允许多个坏元素落入同一删除窗口。 该算法可以正确处理此问题，因为它始终测量活动结构中的位置，而不是原始索引。 

另一种边缘情况是所有元素都已低于阈值。 可行性检查立即返回 true，零操作，正确生成答案`0`。 

最后，当`m = 0`，不允许删除，每个答案`k`只是最大数组元素，阈值公式可以自然地处理它，因为无法删除坏元素。
