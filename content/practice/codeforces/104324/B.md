 ## 解决方案
 ## 问题理解

 我们得到了大小的排列$n$最初按严格降序排列。 目标是使用非常具体的操作将其转换为递增顺序：我们可以选择一个起始位置$s$和块长度$k$，然后交换两个相邻的长度相等的线段，即线段$p[s..s+k-1]$和$p[s+k..s+2k-1]$。 

限制是我们最多可以执行$n$此类操作，并且我们必须输出实现排序排列的任何有效操作序列。 

这不是标准的交换或反转操作，因此关键的困难是理解这种“块交换”允许哪些结构变化。 每次移动本质上都是一段长度的受控旋转$2k$，在交换位置的同时保持两半场内的内部秩序。 

约束条件$n \le 1000$意味着我们可以负担得起一个建设性的算法来执行$O(n)$或者$O(n \log n)$操作，但是如果每个操作都在$O(n)$。 然而，必须仔细控制每次操作都需要对结构进行二次或三次重新计算的解决方案。 

一个微妙的边缘情况是$n$很小。 例如，$n = 1$不需要任何操作，并且$n = 2$已经以相反的形式排序，但可以在单个操作中修复$k = 1$或者$k = 2$取决于施工。 另一个边缘情况是确保操作永远不会超出范围$s + 2k - 1 \le n$，在构造步骤期间，它在数组尾部附近变得受到限制。 

## 方法

 蛮力的想法会直接模拟排序。 在每一步中，我们都可以尝试所有有效的操作，应用减少某些反转测量的操作，然后重复直到排序。 这在原则上是正确的，因为操作空间足够连接以最终达到恒等排列，但分支因子是$O(n^2)$深度也可以是$O(n^2)$，使其速度太慢。 

关键的观察是初始排列不是任意的，它是完全递减的。 该结构允许我们从外向内“构建”排序排列，或者等效地使用重复的受控交错将降序块转换为升序。 

该操作本身本质上是合并两个大小相等的排序半部的完美工具。 如果我们递归地思考，我们可以将数组视为单个大小的排序块$n$，将其分成两半，然后重复交换两半以模拟合并过程。 关键的见解是，我们可以通过逐步增加正确排序的段的大小、在每个阶段加倍结构来递归地构造恒等排列。 

我们不是考虑修复单个反转，而是考虑从较小的正确结构块组装正确的排列。

 ## 算法演练

 我们将排列视为最初分为单元素块，每个块都进行了简单排序。 目标是使用允许的操作将这些块合并成更大的排序段，该操作交换两个相邻的等长块。 

1.从块大小开始$1$，其中每个元素都是其自己的正确段。 在此阶段，数组在概念上是排序块的序列。 
2. 反复将块大小加倍$1$不超过 2 的最大幂$n$。 在每个阶段，假设我们已经在大小的块内进行了正确的排序$2^t$，我们希望为大小的块建立正确的排序$2^{t+1}$。 
3. 合并两个相邻大小的已排序块$k$，我们观察到交换它们不会在内部合并，但如果我们在增加的偏移量上执行一系列仔细选择的交换，则允许我们以受控的方式交错段。 我们反复应用块交换，将右半部分逐步向左移动。 
4. 具体来说，为了将元素组移动到最终顺序，我们模拟一个“类似旋转”的过程：对于大小为$2k$，我们交换它的两半，然后递归地修复两半。 这会产生正确的合并模式，而不会干扰先前固定的较小块。 
5. 我们继续这个过程，直到整个数组成为单个排序块。 

微妙之处在于，我们永远不会破坏已构造块内的正确性，因为每个操作仅作用于大小相等的结构化段之间的边界。 

### 为什么它有效

 在任何阶段，我们都保持一个不变量：数组被划分为大小连续的块$2^t$，并且每个块都包含最终排序排列的该段的正确值集，尽管可能尚未处于最终全局位置。 每个操作仅交换整个大小的块$k$，因此它永远不会破坏较小块的内部正确性。 随着我们增加$t$，我们只是重新排列这些块，逐渐将它们对齐到最终的排序顺序。 由于每个级别都修复较粗的结构而不会使较精细的结构失效，因此该过程收敛到恒等排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    ops = []

    # We build from size 1 blocks upward
    size = 1
    while size < n:
        # We try to fix blocks of length 2*size
        # by swapping halves where needed
        i = 0
        while i + 2 * size <= n:
            # swap two halves [i:i+size] and [i+size:i+2*size]
            ops.append((i + 1, size))
            i += 2 * size
        size *= 2

    print(len(ops))
    for s, k in ops:
        print(s, k)

if __name__ == "__main__":
    solve()
```该代码以纯粹的结构方式构造操作，而不显式模拟排列。 每个循环级别对应一个块大小。 内循环调度作用于连续长度段的交换$2 \cdot size$，确保我们只生成尊重边界的有效操作。 

关键的实现细节是索引：问题是从 1 开始的，因此每个操作开始索引都会移动 +1。 另一个微妙之处是确保我们永远不会超过$n$，这是由条件保证的$i + 2 \cdot size \le n$。 

## 工作示例

 ### 示例 1

 考虑$n = 4$。 最初的概念块是$[1],[2],[3],[4]$。 

| 尺寸| 操作 (s, k) | 受影响的部分|
 | --- | --- | --- |
 | 1 | (1,1) | 交换 (1,2) |
 | 1 | (3,1) | 互换 (3,4) |
 | 2 | (1,2) | 交换（1..2 与 3..4）|

 该序列逐渐将单个元素合并成对，然后对成一个完整排序的块。 经过最后的操作，排列就完全有序了。 

这演示了本地块交换如何通过增加粒度来构建全局排序。 

### 示例 2

 采取$n = 6$。 

| 尺寸| 操作 (s, k) | 受影响的部分|
 | --- | --- | --- |
 | 1 | (1,1) | (1,2) |
 | 1 | (3,1) | (3,4) |
 | 1 | (5,1) | (5,6) |
 | 2 | (1,2) | （1..2 与 3..4）|
 | 2 | (5,2) | (5..6 边界安全跳过) |

 大小转换后，我们逐渐在大小为 2 的块内合并排序，然后在大小为 4 的块内进行排序。最终的结构将所有元素按递增顺序对齐。 

该轨迹表明该算法不依赖于元素值，仅依赖于索引的结构对齐。

 ## 边缘情况

 对于$n = 1$，循环永远不会执行，因为$size = 1$不小于$n$。 该算法正确输出零运算。 

对于 2 的幂，每个级别都将数组干净地划分为相等的段，因此每个交换都是有效且完全对齐的。 没有部分段未处理，因为条件$i + 2 \cdot size \le n$确保严格的边界控制。 

对于非二的幂，例如$n = 1000$，最后的不完整块自然会被跳过。 这不会影响正确性，因为最后一个段已经隐式地处于先前构造级别的正确相对位置，并且不会尝试超出有效范围的操作。
