 ## 解决方案
 ## 问题理解

 我们得到了一系列随着时间的推移应用于一个开始为空的集合的操作序列。 这些操作按顺序处理，并且在每次插入操作之后，我们从概念上获得该集合的一个新“版本”。 后面的查询不是指当前集合，而是指紧接在某些早期操作索引 t 之后的集合的状态。 

查询分为三种。 一个要求操作 t 后集合中的最大元素，另一个要求操作 t 后的最小元素，最后一个要求操作 t 后所有元素的总和。 插入只会增加值，而不会删除任何内容。 

关键的微妙之处在于查询不是关于当前状态，而是关于历史状态。 这意味着我们必须能够回答有关操作序列先前前缀的问题，而不仅仅是最终结果。 

限制允许最多 100000 次操作。 通过重建到时间 t 的设置来从头开始重新计算每个查询的答案的解决方案在最坏的情况下将是二次的，这太慢了。 如果我们从头开始反复重新计算，即使每个查询的对数结构也是不够的。 

一个简单的实现可能会维护一个集合，并且对于每个查询，通过重放直到时间 t 的所有插入来重建它。 当临近结束时有许多查询询问早期前缀时，此操作会失败。 例如，如果我们插入 100000 个元素，然后询问 100000 个查询，所有查询都引用 t = 1，则每个查询将再次扫描几乎整个历史记录，产生大约 10^10 次操作。 

当查询与插入交错时，会出现另一种失败情况。 如果我们只维护当前集合，我们就会丢失有关过去状态的所有信息，因此在不重新计算的情况下查询较早的 t 是不可能的。 

因此，关键要求是一种能够有效维护前缀信息，同时支持随时间变化的范围查询的结构。 

## 方法

 蛮力策略很简单。 我们一一模拟操作。 我们维护所有插入元素的列表。 当我们收到时间 t 的查询时，我们通过迭代前 t 个操作并收集所有插入的值来重建设置状态，然后计算最小值、最大值或总和。 

这在逻辑上是有效的，因为每个查询都准确地询问操作历史记录的前缀。 然而，为每个查询重建前缀会导致重复扫描相同的数据。 在最坏的情况下，每个查询的成本为 O(n)，而 O(n) 查询的成本为 O(n^2)，这对于 100000 次操作来说太慢了。 

改进来自于认识到所有查询仅依赖于前缀，并且仅插入附加信息。 这表明我们可以随着时间的推移预先计算前缀聚合。 如果我们为每个操作索引 i 维护直到 i 为止的所有插入值的最小值、最大值和总和，那么每个查询都会变为 O(1)。 

这是可能的，因为插入是唯一的更新操作，因此每个前缀都可以通过简单的更新从前一个前缀导出。 我们不需要像平衡树这样的动态集合结构，因为我们从不删除或修改过去的值。 

我们维护三个按操作编号索引的数组：前缀最小值、前缀最大值和前缀和。 对于每次插入，我们都会从之前的状态更新这些数组。 对于查询操作，我们直接输出索引 t 处存储的值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 前缀预计算| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们按顺序处理操作，同时为每个步骤构建前缀信息。

1. 初始化用于跟踪前缀状态的三个数组或变量：当前最小值、当前最大值和当前总和。 由于集合开始为空，我们还需要定义如何处理第一次插入。 第一个操作保证是插入，这避免了查询的空集边缘情况。 
2. 对于从 1 到 n 的每个操作 i，读取其类型。 如果是值 x 的插入，我们通过添加 x 来更新当前总和，并相应地更新当前最小值和最大值。 索引 i 处的前缀值成为这些更新值。 
3.如果操作是在t时刻求最大值的查询，则直接输出存储的与前缀t对应的最大值。 这是可行的，因为前缀 t 已经代表了 t 次插入后的设置状态。 
4. 如果操作是要求时间 t 处最小值的查询，我们输出前缀 t 处存储的最小值。 
5. 如果操作是要求在时间 t 求和的查询，我们输出前缀 t 处存储的和。 

关键的设计选择是每次插入都永久定义一个前缀状态。 我们从不重新计算历史，我们只是扩展它。 

它的工作原理基于一个简单的不变量：处理操作 i 后，存储的值准确地表示前 i 操作中所有插入元素的聚合属性。 由于插入永远不会删除元素，因此前缀 i 始终是当时集合的完整表示。 任何询问时间 t 的查询都只是读取先前计算的前缀状态，后续操作不会改变该状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

INF = 10**30

# prefix arrays (1-indexed conceptually)
mx = [0] * (n + 1)
mn = [0] * (n + 1)
sm = [0] * (n + 1)

cur_max = -INF
cur_min = INF
cur_sum = 0

for i in range(1, n + 1):
    parts = input().split()
    typ = int(parts[0])

    if typ == 1:
        x = int(parts[1])
        cur_sum += x
        cur_max = max(cur_max, x)
        cur_min = min(cur_min, x)

    mx[i] = cur_max
    mn[i] = cur_min
    sm[i] = cur_sum

    if typ == 2:
        t = int(parts[1])
        print(mx[t])
    elif typ == 3:
        t = int(parts[1])
        print(mn[t])
    elif typ == 4:
        t = int(parts[1])
        print(sm[t])
```该解决方案在维护运行聚合的同时还存储前缀快照。 重要的细节是我们记录处理每个操作索引 i 后的状态，而不仅仅是插入后。 这种对齐确保引用任何 t 的查询直接索引到正确的前缀状态。 

一个微妙的点是最小值和最大值的初始化。 我们从极端哨兵开始，以便第一次插入正确设置这两个值。 由于第一个操作保证是插入，因此我们永远不会输出未定义的值。 

另一个细节是查询引用过去的索引，因此我们从不直接使用当前状态。 每个答案都是从由 t 索引的数组中读取的。

 ## 边缘情况

 一种重要的边缘情况是，查询引用的是很早的时间，而许多插入发生在较晚的时间。 例如，插入一个大序列，然后对 t = 1 进行多次查询。该算法可以正确处理此问题，因为索引 1 处的前缀状态在计算后被冻结，并且以后的更新不会修改它。 

另一种情况是交替插入和查询。 由于我们在每个索引处存储前缀状态，因此查询始终读取一致的快照，而无需重新计算。 

最后一种情况是严格增加或减少输入，其中最小值或最大值始终在每一步更新。 哨兵初始化确保第一个值正确设置两个边界，并且每个后续更新都保持单调正确性。
