 ## 问题理解

 我们得到了一系列整数，表示一个人在一系列日子里的感受。 每个值都在 -10 和 10 之间（包含 -10 和 10），因此该序列编码简短的每日情绪分数。 任务是计算所有这些值的算术平均值，并将结果分类为三个情感标签之一：正平均值、零平均值或负平均值。 

输出不是数值平均值本身，而只是其符号。 如果所有值的总和除以 n 大于零，我们就会打印一张笑脸。 如果它恰好为零，我们将打印一个中性面。 否则，我们会打印一张悲伤的脸。 

关键的观察结果是，没有必要将平均值显式计算为浮点数。 由于除以正整数不会改变数字的符号，因此我们可以直接使用数组的和。 

约束 n ≤ 100000 意味着线性扫描就足够了。 任何尝试在子范围上重新计算或重复聚合的解决方案仍然会通过，但任何比 O(n) 更糟糕的解决方案都是不必要的。 在最坏的情况下，二次方法最多可以执行 10^10 次操作，这对于 1 秒的限制来说显然太慢了。 

边缘情况主要与符号处理有关。 

一种边缘情况是所有数字都为零。 总和为零，输出必须为“:|”。 如果使用浮点数实现，粗心的浮点平均实现可能会引入舍入问题，但整数和完全避免了这种情况。 

另一种边缘情况是总和非常小但非零，例如 [-1, 1]。 平均值恰好为零，整数算术准确地保留了这一点。 这很重要，因为浮点除法可能会产生一个很小的 ​​epsilon，而不是精确的零，具体取决于实现细节。 

## 方法

 该问题的强力解释是计算所有值的总和并除以 n，然后检查结果。 这已经是线性时间了，因为它需要一次计算总和，然后再进行常数时间除法。 没有有意义的子问题结构，也不需要前缀计算、排序或数据结构。 

稍微简单一点的版本可能会通过重复加法和除法或多次重新计算部分和来计算循环中的平均值。 例如，从头开始重新计算每个元素的总和将导致 O(n^2) 时间，当 n 达到 100000 时，这变得不可行。 

关键的简化是认识到平均值的符号仅取决于总和的符号，因为 n 严格为正数。 这在大多数实现中完全消除了除法的需要，并避免了浮点问题。 

我们将问题简化为数组上的单次累积传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重复重新计算总和 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 单程总和| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整数n，它代表记录的天数。 这决定了我们将聚合多少个值。 
2. 初始化变量`total_sum = 0`。 当我们处理输入时，该变量将累积所有每日分数。 
3. 迭代序列中的每个 n 个整数并将每个值添加到`total_sum`。 这可以一次性构建出所有日常情绪的精确总和。 
4.处理完所有值后，进行比较`total_sum`与零。 由于 n 是正数，除以 n 不会改变符号，因此这种比较完全确定了答案。 
5. 如果`total_sum > 0`， 输出 ”：）”。 如果`total_sum == 0`，输出“：|”。 否则输出“:(”。

 为什么有效：平均值定义为`total_sum / n`。 由于 n > 0，分数的符号完全由下式决定`total_sum`。 除法不能翻转符号，因此直接检查总和相当于检查平均值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    total = 0
    for x in arr:
        total += x
    
    if total > 0:
        print(":)")
    elif total == 0:
        print(":|")
    else:
        print(":(")

if __name__ == "__main__":
    solve()
```该解决方案首先读取输入大小和整数列表。 然后它执行单个累加循环，这是核心计算。 除了整数累加器之外不需要任何中间结构。 

最后的决策步骤将累积和与零进行比较。 这避免了计算实际平均值并完全避免了浮点运算，从而保持了解决方案的精确和安全。

 ## 边缘情况

 一个关键的边缘情况是所有值都为零。 例如：

 输入：```
3
0 0 0
```算法初始化`total = 0`并且永远不会改变它。 最终对比`total == 0`触发并输出“：|”，这是正确的。 

另一个边缘情况是完美取消：

 输入：```
2
-1 1
```处理完两个元素后，运行总和变为 0。 尽管中间值是负数，但最终状态才是重要的。 算法正确输出“:|”。 

最后一个微妙的情况是大的正偏斜或负偏斜，例如全部为 10 或全部为 -10。 由于累加器使用整数运算，并且最大和的大小以 100000 × 10 = 10^6 为界，因此标准 32 位或 64 位整数类型不存在溢出风险。 符号比较保持稳定和确定性。
