 ## 解决方案
 ## 问题理解

 我们有一条线性地铁线路，车站按固定的从西到东的顺序排列。 每个车站都与下一个车站相连，并且在相邻车站之间移动总是需要一分钟。 两个人同时从两个不同的车站出发，都沿着这条线移动。 任务是确定他们可以在同一时刻到达同一站点的最短时间。 

输入给出车站数量，后跟沿线车站名称的有序列表。 之后，我们得到两个站名，表示两个人的起始位置。 输出是一个整数：如果两者都立即开始移动并沿着线路以最佳方式行驶，那么它们可以占据同一站点的最早时间。 

关键的结构是，该图不是一般的图，而是一条简单的路径。 每个站点最多有两个邻居，并且移动的距离是确定的：任何两个站点之间的时间只是它们在列表中的索引差。 

约束很小，最多有 100 个站点，站点名称长度最多为 100。这立即告诉我们，即使对所有站点对采用二次或简单的方法，在限制范围内运行也是微不足道的。 真正的挑战不是性能，而是将满足条件正确地转化为最短时间的表达。 

微妙的一点是，两个人不需要通过明确走向对方来见面。 他们可以沿着线路任意移动，并且集合时间是所有可能的集合站中最短的。 一种天真的解释可能会错误地认为他们必须在中途相遇或只考虑一个方向，这会错过最佳的相遇点。 

值得注意的边缘情况包括当两个人从同一个车站出发时，答案为零，以及当最佳集合点是起始位置之一时，这意味着一个人在原地等待，而另一个人到达。 

## 方法

 思考这个问题的最直接的方法是将每个站点都视为潜在的交汇点。 对于每个站点，计算两个人到达该站点所需的时间，这就是站点列表中索引之间的绝对差。 该车站的集合时间是两个到达时间中的最大值，因为两者必须同时到达。 答案是所有站点中该值的最小值。 

这是有效的，因为每个有效的会议都必须在某个车站发生，并且时间完全由线路上的距离决定。 问题是，如果我们在没有结构的情况下实现这一点，我们将不必要地重复扫描或重新计算距离，但即使这样也没有问题，因为 n 只有 100。 

关键的简化是认识到站名可以直接映射到索引。 一旦我们知道了两个起始站的索引，问题就减少到最小化所有 k 上的 max(|i - k|, |j - k|)。 在一条线上，当 k 位于 i 和 j 之间时，该表达式最小化，并且最佳值正好是它们之间距离的一半（向上舍入）。 

这给出了一个直接的公式：答案是 (|i - j| + 1) // 2。

 | --- | --- | --- | --- |
 | 暴力破解所有会议站 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1.读取站数并按顺序存储列表。 顺序至关重要，因为它定义了图的度量结构。 
2. 构建从站名称到其在列表中的索引的映射。 这允许恒定时间的位置查找。 
3. 检索两个起始站的索引。 设它们为 i 和 j。 
4. 计算直线上它们之间的绝对距离。 这个距离代表如果直接移动的话，一个人到达另一个人的最短时间。 
5. 返回该距离的一半，向上舍入，因为两者可以同时向彼此移动，并且每分钟最多将它们的间隔减少两步。 

原理：在一条路径上，任何交汇点 k 都会导致到达时间 |i - k| 和|j - k|。 会议时间是这两个值中的最大值。 当 k 位于 i 和 j 之间时，该函数最小化，因为将 k 移向间隔会减少两个距离中较大的一个。 一旦 k 位于线段内部，当两侧对称收缩时即可实现最佳平衡，这会导致 i 和 j 之间的总距离分裂。 由于运动在整分钟内是离散的，因此结果是一半距离的上限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
stations = []
pos = {}

for i in range(n):
    name = input().strip()
    stations.append(name)
    pos[name] = i

c, m = input().split()
i = pos[c]
j = pos[m]

dist = abs(i - j)
print((dist + 1) // 2)
```该实现完全依赖于将站名转换为索引，这避免了任何重复扫描。 字典确保对位置的访问为 O(1)。 最终的表达`(dist + 1) // 2`是一种计算一半距离上限的紧凑方法，它与线路上的最佳会议时间相匹配。 

一个常见的错误是尝试逐步模拟运动，但这是不必要的，因为该结构保证了封闭形式的解决方案。 另一个潜在的问题是忘记两者同时移动，这就是为什么距离每分钟最多缩小两个，而不是一个。

 ## 边缘情况

 当两个人从同一站出发时，索引差为零，因此计算出的距离为零，公式返回零。 该算法无需特殊外壳即可正确处理此问题。 

对于相邻站点，例如索引 2 和 3，距离为 1，因此`(1 + 1) // 2 = 1`。 这与如果他们向对方移动一分钟后就会相遇的事实相符。 

对于极端端点，例如索引 0 和 n-1，会议发生在中心区域。 该公式会自动捕获这一点，而无需显式搜索中点，因为它是通过最小化路径上两个线性距离的最大值而得出的。
