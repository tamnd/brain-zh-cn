 ## 解决方案
 ## 问题理解

 蒂亚戈和内森这两名玩家正在玩乒乓球风格的游戏，其中服务器按块切换，而不是像官方规则那样每两分交替一次。 相反，服务器每获得 k 分就会发生变化，无论是谁得分。 蒂亚戈总是在比赛开始时开始发球。 

我们得到多个独立测试用例的当前分数。 对于每种情况，我们需要根据当前的总得分来确定接下来由谁发球。 得分本身不会影响发球变化，除非到目前为止已经打了多少分，因为每分都会推进发球周期。 

每个测试用例提供 k、服务更改的块大小以及当前分数 T 和 N。根据这些，我们计算总共玩了多少分，然后确定已经通过了多少个完整服务块。 如果完成的区块数量是偶数，则蒂亚戈仍然是发球者； 如果是奇怪的，则内森正在发​​球。 

这些约束允许最多 10^4 个测试用例，并且 k 和分数的值最多为 10^9。 这立即排除了任何单独处理每个点的模拟。 在单次测试中，每点模拟最多需要 2 × 10^9 次操作，这远远超出了可行的限制。 每个测试用例的解决方案必须是 O(1)。 

当总点数恰好可以被 k 整除时，就会出现微妙的边缘情况。 在这种情况下，发球会在最后一分之后立即切换，因此下一个发球取决于完成的拦网数量是偶数还是奇数。 另一个特殊情况是当 T = 0 且 N = 0 时，这意味着尚未得分，因此蒂亚戈必须仍在发球。 

## 方法

 天真的想法是逐点模拟游戏。 从 Thiago 作为服务器开始，我们将为每个点增加一个计数器，并每 k 个点切换服务器。 处理完T+N步后，我们将输出当前服务器。 这是正确的，因为它直接遵循规则。 

然而，这种方法在限制下变得不可能，因为 T + N 可以大到 2 × 10^9。 即使每个点执行一次操作也会超出时间限制几个数量级。 

关键的观察是我们永远不需要跟踪单个点。 唯一相关的数量是大小为 k 的已完成块的总数。 一旦我们计算出 S = T + N，满块的数量就是 S // k。 每个块恰好翻转服务器一次，因此服务器仅依赖于该商的奇偶性。 

这将整个问题简化为每个测试用例的恒定时间算术计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 每次测试 O(T + N) | O(1) | O(1) | 太慢了 |
 | 算术块计数 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取每个测试用例的 k、T 和 N。 这些定义了游戏状态中的块大小和当前总点数。 
2. 计算 S = T + N，即到目前为止所玩的总点数。 发球切换仅取决于已经完成了多少个完整的k点段。 
3. 计算块= S // k。 每个完整的块对应于一个完整的服务间隔，之后服务器翻转。 
4. 如果块数为偶数，则输出“Thiago”，因为蒂亚戈开始发球，偶数次翻转将发球权返回给发球手。 
5. 如果出块数为奇数，则输出“Nathan”，因为翻转次数为奇数意味着发球已从发球手手中移开。 

### 为什么它有效

发球仅在全局点序列中大小为 k 的固定边界处发生变化。 这将时间线划分为连续的间隔，每个间隔恰好反转当前服务器一次。 由于蒂亚戈在零时间开始发球，S 点之后的发球仅取决于已经跨越了多少个完整间隔。 当前间隔内的部分进度不会影响下一个服务器，只有完成的间隔才重要。 因此S//k的奇偶性完全决定了答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k, T, N = map(int, input().split())
    total = T + N
    blocks = total // k

    if blocks % 2 == 0:
        print("Thiago")
    else:
        print("Nathan")
```实现直接遵循数学简化。 关键步骤是将状态分解为总分，避免跟踪各个得分序列的需要。 整数除法计算完成的服务间隔数，奇偶校验确定服务器。 

一个常见的错误是忘记切换发生在 k 个点之后，而不是每个第 k 个点（包括零）。 使用楼层划分可以正确处理此问题，而不会出现相差一问题。 另一个微妙之处是我们不需要考虑谁得分最后一分，因为得分不影响发球规则。

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        k, T, N = map(int, input().split())
        total = T + N
        blocks = total // k
        out.append("Thiago" if blocks % 2 == 0 else "Nathan")
    return "\n".join(out)

# provided sample-style cases
assert solve("2\n7 1 0\n2 2 8\n") == "Thiago\nNathan"

# k large, no switch
assert solve("1\n10 3 4\n") == "Thiago"

# exact boundary switch
assert solve("1\n5 3 2\n") == "Nathan"

# multiple switches
assert solve("1\n3 9 0\n") == "Thiago"

# zero points
assert solve("1\n5 0 0\n") == "Thiago"

 ## 边缘情况

 当没有得分时，T = 0且N = 0，总数为S = 0。计算得出blocks = 0 // k = 0，这是偶数，因此蒂亚戈被正确识别为发球员。 

对于S恰好是k的倍数的情况，例如k = 4和S = 8，我们得到块= 2。由于两个完整的发球间隔已经完成，发球已经切换了两次，返回到蒂亚戈。 该实现可以正确捕获这一点，而无需显式检测边界。 

对于非常大的值，例如 k = 10^9 和 S 接近 2 × 10^9，整数除法仍然在恒定时间内运行，并安全地避免了 Python 中的溢出问题。
