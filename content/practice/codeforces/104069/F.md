 ## 解决方案
 ## 问题理解

 我们分配了一批学生，每个学生被分配到四个独立服务柜台之一，每个学生都有固定的服务时间。 每个柜台独立运作，一次只能为一名学生服务。 所有计数器在固定时间限制后同时关闭$T$。 如果学生可以在指定的柜台安排他们的整个服务在时间之前或正好在时间结束，则学生是有效的$T$。 

关键的自由在于，在每个计数器中，我们不必被迫遵守输入顺序。 我们可以对每个柜台的学生进行任意重新排序，以最大限度地增加及时完成的​​学生数量。 

因此，对于四个计数器中的每一个，我们正在解决一个调度问题：给定单台机器上具有截止日期的一组处理时间$T$，最大化可以顺序完成的任务数量。 

输入大小可以大到$4 \cdot 10^5$，所以任何二次或偶数$O(N \log N)$解决方案必须精心构建。 允许排序，但任何涉及嵌套扫描或每个候选子集重复重新计算的操作都会失败。 

当大任务压倒小任务时，就会出现微妙的边缘情况。 例如，如果$T = 10$计数器有时间$[9, 9, 1]$，一个没有正确重新排序的天真的贪婪者可能会选择$9 + 1$甚至没有考虑排序问题。 正确答案是$2$因为我们可以安排$1 + 9$。 任何尊重输入顺序的方法都会错误地得出只有一名学生适合的结论。 

另一个边缘情况是所有任务仅在排序后才适合。 例如，$T = 10$, 次$[8, 7, 3]$。 最优选择是$3 + 7 = 10$， 不是$8$单独的，这再次表明排序是至关重要的。 

## 方法

 直接的强力解释将尝试每个计数器的每个学生子集，并针对每个子集检查是否可以将它们排序以适应时间$T$。 即使忽略排序复杂性，这也已经意味着$2^{N}$子集，这是不可能的$N = 4 \cdot 10^5$。 甚至限制为单个计数器$n$元素，检查所有子集是指数级的。 

我们完善了视角。 对于固定柜台，假设我们决定准确服务$k$学生。 最小化总完成时间的最佳方法是选择$k$最小的持续时间。 这是一个经典的交换论点：如果选定的集合包含较大的元素，而存在较小的未使用元素，则交换它们永远不会增加总时间。 

因此每个计数器变得独立。 对于每一个，我们对其服务时间进行排序，并贪婪地取最小的前缀，直到累积和超过$T$。 答案是这四个独立结果的总和。 

关键的简化是计数器之间没有交互。 每个学生都属于一台机器，因此我们解决了四个独立的“总和约束下的最大化前缀”问题。

 | 蛮力 | 指数| O(N) | 太慢了 |
 | 最佳 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们将四个计数器中的每一个都视为一个单独的处理时间桶。 

1. 根据指定的计数器将所有学生分成四个列表。 这将调度问题隔离为独立的子问题，因为没有学生可以在柜台之间移动。 
2. 对于每个计数器，按服务时间升序对其列表进行排序。 排序是必要的，因为首先执行较小的任务总是在固定的时间预算下为额外的学生留下更多的空间$T$。 
3. 遍历排序列表，同时维护所选时间的运行总和。 从零开始，重复添加下一个最小的时间。 
4.每当下次相加时总和会超过$T$，立即停止。 所有剩余的任务都更大或相等，因此它们无法提高计数。 
5、统计超出之前有多少任务添加成功$T$，并将该值添加到全局答案中。 
6. 将所有四个计数器的结果相加并输出最终总数。 

为什么它有效：在每个计数器内，任何可行的计划都可以重新排列为非递减顺序，而不会改变可行性，因为提前交换更大的任务只会增加或保留前缀和。 因此，最优解总是对应于取已排序数组的前缀，并在前缀和超过的第一个点处停止$T$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, T = map(int, input().split())
    
    groups = {"C": [], "F": [], "P": [], "Q": []}
    
    for _ in range(N):
        b, v = input().split()
        v = int(v)
        groups[b].append(v)
    
    ans = 0
    
    for k in groups:
        arr = groups[k]
        arr.sort()
        
        s = 0
        cnt = 0
        
        for x in arr:
            if s + x > T:
                break
            s += x
            cnt += 1
        
        ans += cnt
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先按学生分配的计数器对学生进行分类。 这一点至关重要，因为每个计数器的行为就像一台具有自己队列的独立机器。 对每个存储桶进行排序可确保我们始终首先考虑最小的持续时间，这是可以在总和约束下最大化任务数量的唯一排序。 

运行总和`s`如果我们提供所选前缀，则跟踪当前完成时间。 那一刻`s + x`超过$T$，我们停止，因为添加任何更大的元素只会恶化可行性。 

全局答案会累积所有四个计数器的结果，因为它们独立运行。

 ### 示例 1

 输入：```

C 5
F 3
P 2
Q 4
C 1
C 6
```分组后：

 C = [5, 1, 6]，F = [3]，P = [2]，Q = [4]

 排序：

 C = [1, 5, 6]，F = [3]，P = [2]，Q = [4]

 C 计数器跟踪：

 | 步骤| 价值| 运行总和 | 行动|
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 采取|
 | 2 | 5 | 6 | 采取 |
 | 3 | 6 | 12 | 12 停止|

 F 取 1，P 取 1，Q 取 1。 

总计 = 2 + 1 + 1 + 1 = 5。 

这表明每个计数器独立运行并贡献自己的最大前缀，即使全局任务按输入顺序交错也是如此。 

### 示例 2

 输入：```
4 10
C 6
C 3
C 4
C 5
```组：

 C = [6, 3, 4, 5] → 排序 [3, 4, 5, 6]

 追踪：

 | 步骤| 价值| 运行总和 | 行动|
 | --- | --- | --- | --- |

这表明首先选择最小的元素是必要的； 单独采取 6 会导致比采取 3 和 4 更糟糕的结果。

 ## 边缘情况

 第一种边缘情况是一个计数器具有许多大值和一些小值。 例如：```
C = [100, 1, 1, 1], T = 3
```排序给出 [1, 1, 1, 100]。 该算法需要三个 1，并在 100 之前停止，产生 3。处理输入顺序的简单方法可能会首先需要 100，然后错误地只得出一个学生的结论。 

第二种边缘情况是所有值都完全匹配。 例如：```
C = [2, 3, 5], T = 10
```排序顺序提供了完整的包含。 运行总和恰好达到 10，全部被取走。 仅当超过时才会触发中断条件$T$，因此可以正确处理相等性，不会出现差一错误。
