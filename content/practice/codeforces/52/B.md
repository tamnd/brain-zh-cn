 ## 解决方案
 ## 问题理解

 我们有一个矩形网格，其中每个单元格要么是空的，要么标记为`*`。 每一个`*`cell 表示位于该单元格中心的点。 我们需要计算可以形成多少个直角三角形：

 - 所有三个顶点都是`*`细胞，
 - 直角由一条水平边和一条垂直边形成，
 - 三角形的边平行于网格轴。 

一旦我们选择了包含直角的顶点，三角形就完全确定了。 如果一个`*`细胞有另一个`*`在同一行和另一行的某个地方`*`在同一列的某处，那么这两个选择形成一个有效的直角三角形。 

网格尺寸最多为`1000 × 1000`，所以细胞总数可以达到一百万。 任何检查所有三元组的解决方案`*`细胞是完全不可行的。 如果重复执行，即使天真地检查每个单元格及其行和列中的所有单元格也会变得太慢。 

有用的观察是，对于固定的直角顶点，水平和垂直选择是独立的。 如果一个细胞有`r`其行中的其他星星以及`c`其列中的其他恒星，则它贡献`r * c`三角形。 

一些边缘情况可能会悄悄地破坏不正确的实现。 

考虑一个只有一行的网格：```
1 5
*****
```正确答案是`0`。 即使水平存在许多对，也不能形成垂直腿。 

考虑一个网格，其中直角顶点本身被意外地算作选择之一：```
2 2
**
**
```正确答案是`4`。 

每个角恰好贡献一个三角形：

 - 左上角使用右上角和左下角，
 - 右上角使用左上角和右下角，
 - 左下角使用左上角和右下角，
 - 右下角使用右上角和左下角。 

一个不小心使用的公式`row_count * col_count`而不是`(row_count - 1) * (col_count - 1)`会通过允许顶点与自身配对来进行计数。 

当行或列恰好包含一颗星时，会出现另一种微妙的情况：```
3 3
*..
.*.
..*
```答案是`0`。 每颗星星的行和列都是孤立的，因此即使总共有三颗星星，也不存在直角三角形。 

## 方法

 蛮力的想法很简单。 枚举每个三元组`*`单元格并测试它们是否形成有效的轴对齐直角三角形。 

假设网格完全被填满。 然后还有`10^6`星星。 检查所有三元组大致需要：$$\binom{10^6}{3}$$操作，这在天文数字上是不可能的。 

稍微好一点的蛮力方法首先修复直角顶点。 对于每一个`*`单元格，扫描其整行以查找水平伙伴并扫描其整列以查找垂直伙伴。 如果一个细胞有`r`横向选择和`c`垂直选择，那么它就会做出贡献`r * c`。 

这种方法是正确的，因为每个有效三角形都有一个直角顶点，一旦该顶点固定，就可以独立选择水平和垂直端点。 

问题是性能。 如果我们重复扫描每个单元格的行和列，则复杂性变为：$$O(n \cdot m \cdot (n + m))$$和`n = m = 1000`，在最坏的情况下，这大约是 20 亿次操作。 

关键的观察是行和列信息永远不会改变。 我们可以进行预处理，而不是重复重新计算计数：

 - 每行有多少颗星星，
 - 每列中有多少颗星星。 

然后每个`*`细胞可以在恒定时间内计算其贡献。 

如果一个细胞`(i, j)`包含一颗星：

 -`row[i] - 1`给出同一行中其他星星的数量，
 -`col[j] - 1`给出同一列中其他星星的数量.

 他们的乘积正是直角三角形的数量，使用`(i, j)`作为直角顶点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·m·(n + m)) | O(n·m·(n + m)) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n·m) | O(n + m) | 已接受 |

 ## 算法演练

 1.读取网格并存储。 
2. 创建数组`row`在哪里`row[i]`存储的数量`*`行中的单元格`i`。 
3. 创建数组`col`在哪里`col[j]`存储的数量`*`列中的单元格`j`。 
4. 遍历网格一次以填充这些数组。 

每当一个`*`发现于`(i, j)`，增量：

 -`row[i]`-`col[j]`5. 再次遍历网格。 
6. 对于每一个`*`细胞`(i, j)`，计算：$$(row[i] - 1) \times (col[j] - 1)$$减法将从两个计数中删除当前单元格本身。 

1. 将所有贡献添加到最终答案中。 
2. 打印答案。 

### 为什么它有效

 每个有效的三角形都有一个唯一的直角顶点。 一旦该顶点被固定，一个顶点必须位于同一行，另一个顶点必须位于同一列。 

对于明星来说`(i, j)`：

 - 正好有`row[i] - 1`有效的水平选择，
 - 正好有`col[j] - 1`有效的垂直选择。 

每一对这样的选择都形成一个唯一的直角三角形，并且每个有效三角形从其直角顶点开始恰好计数一次。 不会出现重复，因为没有三角形可以有两个直角。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

grid = [input().strip() for _ in range(n)]

row = [0] * n
col = [0] * m

for i in range(n):
    for j in range(m):
        if grid[i][j] == '*':
            row[i] += 1
            col[j] += 1

ans = 0

for i in range(n):
    for j in range(m):
        if grid[i][j] == '*':
            ans += (row[i] - 1) * (col[j] - 1)

print(ans)
```第一次遍历计算每行和每列中出现的星星数量。 这个预处理就是整个优化。 如果没有它，我们将重复扫描每个单元格的行和列。 

第二次遍历评估每个`*`细胞独立。 公式：```
(row[i] - 1) * (col[j] - 1)
```计算以下所有可能的组合：

 - 同一排的另一颗星星，
 - 同一列中的另一颗星星。 

减法`1`是必需的，因为当前单元格属于这两个计数。 忘记这一点会创建无效三角形，其中一个端点等于直角顶点本身。 

答案可能会变大，但 Python 整数会自动处理任意大小。 在具有固定宽度整数的语言中，64 位类型是必要的。

 ## 边缘情况

 考虑单行情况：```
1 5
*****
```唯一行的行数是`5`，但每列计数是`1`。 

对于每颗星：

 -`row[i] - 1 = 4`-`col[j] - 1 = 0`每个贡献都变成：$$4 \times 0 = 0$$最终的答案是`0`，这是正确的，因为垂直腿不存在。 

现在考虑完全填充的`2x2`网格：```
2 2
**
**
```每个行数和列数等于`2`。 

对于四个单元格中的每一个：

 -`row[i] - 1 = 1`-`col[j] - 1 = 1`每个只贡献一个三角形。 

全部的：$$4 \times 1 = 4$$这证实了为什么要减去`1`很重要。 如果不进行减法，每个细胞都会错误地将自己算作伙伴。 

最后，考虑对角线上的孤立星星：```
3 3
*..
.*.
..*
```每个行数和列数等于`1`。 

对于每颗星星：

 -`row[i] - 1 = 0`-`col[j] - 1 = 0`所有贡献均为零，因此算法正确报告不存在有效的直角三角形。
