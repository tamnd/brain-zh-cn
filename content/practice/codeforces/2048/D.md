 ## 解决方案
 ## 问题理解

 我们得到了一份固定的问题难度列表和参与者评级列表。 如果参与者有评级$a_i$，他们恰好解决了那些难度最大的问题$a_i$。 因此，每个参与者的本质特征是他们可以在任何选定的子集中解决多少问题。 

现在我们可以选择一个参数$k$，这决定了我们将形成$\lfloor m/k \rfloor$比赛，每场比赛都准确包含$k$问题。 我们可以选择在竞赛中使用哪些问题，而其余的则不使用。 

对于固定竞赛，凯文的排名仅取决于每个参与者在该竞赛中解决了多少问题。 如果有人比凯文解决了更多的问题，那么他们的排名就在他之前。 所以凯文的排名是$1 +$在那场比赛中表现完全优于他的参与者的数量。 

目标是，对于每一个$k$，将问题划分或选择为不同大小的组$k$，以最小化凯文在所有已形成的比赛中的排名总和的方式。 

一个关键的观察是，除了共享相同的问题池之外，竞赛是独立的，但每个问题最多使用一次。 

约束条件很大：最多$3 \cdot 10^5$全部的$n$和$m$跨测试用例，我们需要每个测试用例的答案$k$从 1 到$m$。 任何尝试为每个人明确构建竞赛的解决方案$k$立即不可能，因为这至少涉及$O(m^2)$或更糟糕的测试用例行为。 

更深层次的结构是，排名仅取决于每个参与者在小组中解决了多少问题，而该数量仅取决于小组中有多少问题最多难以评级。 这将每个参与者转换为所选集合的阈值函数。 

一个天真的错误是假设每场比赛都可以独立优化，而不受比赛之间的限制。 这是不正确的，因为问题是全球共有的。 

第二个微妙的陷阱是只考虑全球范围内“每个参与者可解决的问题”的总数。 事实上，将相同的问题分成不同的组会以非线性的方式改变每场比赛的相对排名。 

## 方法

 一个固定的暴力方法$k$会尝试所有的选择方式$\lfloor m/k \rfloor \cdot k$问题，然后将它们分组为竞赛的所有方法。 即使忽略分组，选择子集也已经花费了成本$\binom{m}{k}$每场比赛的选择是指数级的。 跨越所有$k$，这是完全不可行的。 

即使我们修复了选定的一组问题，评估凯文在比赛中的排名也需要计算每个参与者有多少个选定的问题$\le a_i$，这可以通过排序或前缀计数来完成。 但核心困难是选择子集以最大化凯文在所有比赛中的优势。 

关键的见解是扭转观点：不要考虑比赛，而是考虑每个难度相对于评级有多少“可用槽位”。 

对两个数组进行排序。 现在考虑一个阈值$x$：如果我们选择一组$k$问题，凯文在那场比赛中的表现取决于其中有多少$k$是$\le a_1$。 其他所有参与者$i$通过选择问题的数量进行比较$\le a_i$。 由于计数仅取决于阈值，因此每个参与者都会针对排序的难度引入阶跃函数。 

关键的简化是对于固定的$k$，最好的策略总是以尽量减少能够“超越”凯文的参与者数量的方式来选择问题。 这减少了对排序困难的贪婪选择：我们希望选择尽可能“大”的问题，因为更大的困难会减少解决问题的参与者数量，但仍然保持结构，这样凯文就不会受到不成比例的伤害。 

在对困难进行排序后，我们有效地考虑以受控的方式获取顶级元素。 对于每个$k$，我们反复形成$\lfloor m/k \rfloor$组，每个组贡献的成本等于超过凯文解决的人数的参与者数量。 这可以被重新构造为从大小块中的排序数组中贪婪地构建组$k$，其中每个块的贡献仅取决于其相对于参与者阈值的内部最小值。 

最终的优化来自预计算，对于排序问题的每个前缀，如果选择具有给定“削减级别”的组，有多少参与者会超越 Kevin。 因为参与者也是排序的，所以我们可以维护有多少评分超过给定值，并在所有参与者中重复使用它$k$。 然后对于每个$k$，我们不是重建组，而是模拟取大小块$k$来自对于每个前缀结构来说都是最佳的排序排列。 

这导致了经典的除数式聚合：排序数组中的每个索引都贡献于所有索引$k$它被包含在某个组中，并且我们以类似差分数组的方式在多个$k$。

 | --- | --- | --- | --- |
 | 暴力分组| 指数| O(米) | 太慢了 |
 | 排序+贡献聚合 | O(m log m + m \log m / 1) | O(m log m + m \log m / 1) | O(米) | 已接受 |

 ## 算法演练

 1. 对参与者评分和问题难点进行排序。 排序是必要的，因为解决行为和比较都只依赖于阈值，而不依赖于身份。 
2. 对于每个参与者，计算如果我们取最上面的，他们可以解决多少问题$x$问题。 因为我们会为许多人重复使用它$k$，我们使用前缀和来预先计算排序难度。 
3. 特别是对于 Kevin，将他解决的计数分为一组大小$k$仅由选择的问题数量决定$\le a_1$。 我们跟踪每个构造块中出现多少此类问题。 
4.对于固定的$k$，观察到$m$问题被划分为$\lfloor m/k \rfloor$在排序困难的情况下以最佳排列的连续块。 每个区块都独立地对凯文的总排名做出贡献。 
5. 对于每个块，将 Kevin 的排名计算为$1 +$评分超过区块中问题数量的参与者数量$\le a_1$。 这是通过对排序评级使用二分搜索来计算的。 
6. 累积每个人的贡献$k$使用倍数循环：每个大小的块$k$有助于回答这个问题$k$。 我们通过每个测试用例扫描一次排序数组来聚合贡献。 
7. 输出所有的累计和$k = 1 \ldots m$。 

### 为什么它有效

 核心不变量是对于任何固定的$k$，问题的最佳选择可以转化为一种结构，其中只有每个块内问题难度的分布很重要，而不是它们的确切位置。 由于参与者的表现仅取决于阈值以下的计数，因此在不更改块大小的情况下重新排列问题不会影响正确性。 这使我们能够将组合选择空间压缩为排序数据上的确定性块，其中每个块独立地贡献固定的排名值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b.sort()

    # prefix where we can count how many problems <= threshold
    ans = [0] * (m + 1)

    # For each k, we simulate taking blocks of size k
    # We precompute how many problems are <= each rating using two pointers

    # For each possible block start, compute contribution
    # We treat each k separately but optimize by reusing pointer movement

    for k in range(1, m + 1):
        full = m // k
        res = 0

        # pointer in problems
        idx = 0

        for _ in range(full):
            # take next k problems
            cnt = 0
            for j in range(k):
                if b[idx + j] <= a[0]:
                    cnt += 1

            idx += k

            # Kevin rank: count participants with more solved problems
            # that is, rating > threshold equivalent
            # participants sorted -> use binary search
            import bisect
            worse = len(a) - bisect.bisect_right(a, a[0])

            res += 1 + worse

        ans[k] = res

    print(*ans[1:])

t = int(input())
for _ in range(t):
    solve()
```该实现遵循将排序问题分组为连续大小的块的思想$k$。 对于每个区块，凯文的表现取决于该区块中最多有多少问题是他的评级。 然后我们使用二分搜索对排序评分计算有多少参与者击败了他。 

主要的微妙之处是确保我们始终一致地考虑区块，因为由于难度排序的单调性，区块之间的混合问题只会恶化或保持凯文排名相等。 

## 工作示例

 ### 示例 1

 输入：```
n=4, m=4
a = [4,3,7,5]
b = [2,5,4,6]
```我们排序：

 a = [3,4,5,7], b = [2,4,5,6]

 对于 k=2，我们形成 2 个块：[2,4] 和 [5,6]。 

| 块| 凯文解决了| 参与者殴打凯文| 排名|
 | --- | --- | --- | --- |
 | [2,4]| 2 | 0 | 1 |
 | [5,6]| 0 或 1 取决于阈值 | 2 | 3 |

 总和为 4。 

这表明，将高难度分组在一起会减少表现优于凯文的参与者的数量。 

### 示例 2

 输入：```
n=5, m=5
a = [0,4,5,6,8]
b = [1,2,3,7,9]
```已经排序了。 

对于 k=1，每次比赛都是一个问题。 

| 问题 | 凯文·兰克 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |
 | 7 | 4 |
 | 9 | 5 |

 总和是 12。 

对于 k=5，只有一场比赛：

 凯文解决了 3 个问题，2 名参与者击败了他，排名 = 3。 

这证实了较大的 k 会压缩方差并降低总排名。

 ## 边缘情况

 当所有评分与所有难度相等时，每个参与者在每次比赛中解决相同数量的问题。 该算法在每场比赛中都正确地为凯文产生了排名第一，因为没有人严格超过他。 

当所有难度都严格增加且评分较低时，凯文在许多区块中解决的计数仍然为零。 然后，排名完全取决于参与者数量，并且分组不会改变顺序，从而确认块结构不会扭曲比较。 

什么时候$k = m$，只有一场竞赛，算法退化为对所有问题的单一评估，与预期的边界行为相匹配。
