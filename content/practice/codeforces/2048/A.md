 ## 问题理解

 我们得到一个起始整数和一小组修改它的操作。 目标是确定我们最终是否可以将这个数字精确地减少到零。 

这两个操作的行为非常不同。 一种是算术运算：只要当前值至少为 33，我们就可以减去 33。另一种运算是结构性的：如果十进制表示中包含两个连续的数字等于 3，我们可以从数字中删除该子字符串“33”，从而缩短其数字长度。 

关键的困难在于这些操作在数字的不同表示形式之间进行交互。 减法改变数值但保持数字结构基本稳定，而删除改变结构但不直接跟踪数值。 

最多 10^4 个测试用例且 x 最多为 10^9 的约束意味着每个测试必须在位数的大致对数或线性时间内处理。 任何重复尝试所有可能操作序列的模拟都会发生组合爆炸，因为每个步骤都可以分支为两个截然不同的转换。 

当删除在减法后暴露出新的“33”对时，或者当需要减法来“对齐”数字以便删除成为可能时，就会出现微妙的边缘情况。 例如，像 133333332 这样的数字可以在算术缩减和数字压缩之间重复交替。 另一方面，像 666 这样主要由非 3 位数字组成的数字在结构上被阻止删除，并且可能会也可能不会以仍然允许达到零的方式达到 33 的倍数。 

一种尽可能贪婪地减去 33 的幼稚方法会失败，因为它忽略了删除可以从根本上改变整除结构。 类似地，贪婪的删除优先方法也会失败，因为它忽略了算术可行性约束。 

## 方法

 暴力策略会将每个状态视为图中的一个节点：每个整数值或字符串表示形式都是一个状态，每个操作都是一条边。 我们将从初始数字开始运行 BFS 或 DFS，尝试减去 33 并删除任何出现的“33”。 这是正确的，因为它探索了所有可能的操作序列，但它是不可行的，因为即使对于 10 位数字，该数字也可以增长一个巨大的状态图。 分支因子至少为一，通常为二，并且重复的数字重新排列会产生循环和巨大的搜索空间。 

关键的见解是减法 33 是​​唯一以受控线性方式改变数值大小的运算。 同时，删除仅删除出现的固定模式，而不会增加数值。 这建议将问题分为两个阶段：通过删除所有可能的“33”对来标准化数字，然后研究重复减法是否可以达到零。 

关键的观察是，删除仅在是否可以提高 33 的整除性方面起作用。充分利用删除后，剩余的数字就像减去 33 后的标准整数一样。这个过程有效地将问题简化为检查我们是否可以通过数字删除将数字转换为 33 的倍数，然后该倍数是否可以达到零。 

这导致了一个贪婪的稳定想法：每当“33”出现时，就重复消除它们，因为延迟删除无助于创建新的有用的算术结构。 一旦不可能再进行删除，该数字就固定为最小的“压缩”形式，剩下的问题就简化为它是否能被 33 整除。

 ## 算法演练

 我们将数字视为可变的数字字符串，以便轻松应用删除。 

1. 将整数转换为字符串表示形式。 这使我们能够直接检测和删除数字模式。 
2. 重复扫描字符串并删除所有出现的子字符串“33”。 每次移除后，请从之前的位置重新开始扫描，因为可能会形成新的相邻对。 此步骤模拟尽可能积极地应用删除操作。 
3. 一旦不再存在“33”子字符串，则将结果字符串解释为整数值。 
4. 如果结果为零，则立即返回“YES”，因为我们已经达到了目标，无需减法。 
5. 否则，检查该数是否能被 33 整除。如果不能被 33 整除，则返回“NO”，因为除以 33 会保持模 33 同余，并且永远不会达到零。 
6. 如果它能被 33 整除，则返回“YES”，因为重复减去 33 最终会将其减为零。 

### 为什么它有效

 该算法依赖于两个不变量。 首先，删除“33”子串保留了可能性空间，因为任何有效的操作序列都可以在减法之前或之后重新排序删除，而不会影响到零的可达性。 其次，减法 33 保留模 33 的余数，因此任何可以达到零的状态都必须与模 33 的零全等。一旦用尽所有结构约简，唯一剩下的约束就是算术整除性，它充分表征了可达性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def reduce_33(s: str) -> str:
    stack = []
    for ch in s:
        if stack and stack[-1] == '3' and ch == '3':
            stack.pop()
        else:
            stack.append(ch)
    return ''.join(stack)

def solve():
    t = int(input())
    for _ in range(t):
        x = input().strip()
        
        # remove all "33" pairs greedily
        prev = None
        while prev != x:
            prev = x
            x = reduce_33(x)
        
        if x == "":
            print("YES")
            continue
        
        val = int(x)
        if val % 33 == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```核心实现使用基于堆栈的传递来有效地删除相邻的“33”对。 每次传递都会删除所有当前可见的对，并重复直到稳定，确保结构转变后不会留下隐藏的对。 

稳定后，到整数的转换仅发生一次，这使得开销最小。 使用模检查是因为减法 33 可以保持同余，因此达到零需要最终值能被 33 整除。 

重复应用的循环`reduce_33`是安全的，因为每当发生删除时，每次传递都会严格减少字符串长度，从而保证终止。

 ## 边缘情况

 一个关键的边缘情况是当数字不包含“33”模式但仍然可以通过减法来减少时。 例如，66 经过一次减法后变为 33，然后变为 0。该算法处理此问题是因为它不依赖于删除的存在； 它在稳定后检查整除性，66 % 33 等于 0。 

另一种情况是删除完全删除该号码。 对于像 33 这样的输入，堆栈删除会产生一个空字符串。 该算法明确将此视为成功，因为在结构上无需算术运算就已达到零。 

第三种情况是删除和算术相互作用最小的情况，例如666。不存在“33”，因此数字保持不变。 由于 666 可以被 33 整除，因此算法正确地返回 YES，这与即使没有结构运算，重复减法也会导致零的事实相匹配。
