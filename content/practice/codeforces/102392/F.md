 ## 解决方案
 ## 问题理解

 给定树的顶点为根`1`。 可以更自然地将游戏视为另一张图上的游戏。 创建一个图，其顶点是树顶点，并在有根树中只要一个顶点是另一个顶点的祖先时就连接两个顶点。 原始游戏中的移动正是沿着这些边之一移动到之前未访问过的顶点。 原始树边只是描述这种祖先关系的一种方式，一次移动可能会跳过几个级别。 

Alice首先选择任意一个顶点，这相当于在这个祖先图上选择顶点地理游戏的起始顶点。 随后的每一步都会标记一个先前未使用的顶点，并且没有合法未使用邻居的玩家失败。 所需的输出是`Alice`如果第一个玩家有获胜策略并且`Bob`否则。 

最多有`100000`顶点和`99999`边缘。 在一秒的时间限制下，工作量呈二次方增长的算法在 Python 中已经太昂贵了，任何呈指数增长的算法都是完全遥不可及的。 树本身可以在线性时间内处理，因此目标是`O(n)`时间和`O(n)`记忆。 关键的挑战是隐式祖先图可以具有`Theta(n^2)`边缘，因此显式构造它不是一个选项。 

第一个边缘情况是单个顶点。```
1
```正确答案是`Alice`。 爱丽丝做出了唯一可能的初始动作，之后鲍勃就没有动作了。 仅从树边缘开始或假设每个游戏在初始放置后至少包含一个动作的实现可能会错误地处理这种情况。 

第二个边缘情况是具有偶数个顶点的路径。```
4
1 2
2 3
3 4
```答案是`Bob`。 每对顶点在有根路径上都是可比较的，因此在 Alice 做出第一个选择之后，剩下的三个顶点都是可达的。 因此，玩家访问所有四个顶点，鲍勃进行最后一步。 仅基于奇偶校验的解决方案很诱人，但它在分支树上失败，因为无法将不可比较的顶点用作连续移动。 

第三种边缘情况是具有偶数个顶点的分支。```
4
1 2
1 3
1 4
```答案是`Alice`。 爱丽丝可以从一片叶子开始。 Bob可以移动到根，之后Alice移动到另一片叶子，Bob没有合法的移动。 将每对树顶点视为相邻会错误地将其变成完整的图并给出错误的获胜者。 

最后，祖先并不意味着直系父母或孩子。 例如，```
4
1 2
2 3
3 4
```允许顶点`1`直接移动到顶点`4`，因为他们是祖先和后代。 仅构造原始树边的算法解决了不同的游戏，并且可能在隐藏测试中失败。 

## 方法

 直接的暴力解决方案可以表示黑色顶点集并递归地尝试每个合法的下一个顶点。 这是正确的，因为游戏是有限的，因此 minimax 可以检查每一个可能的延续并确定当前位置是否获胜。 然而，在路径上，每个顶点都可以与其他每个顶点进行比较。 一旦选择了第一个顶点，接下来就可以选择任何剩余的顶点，因此游戏包含所有`n!`可能的完整探视订单。 因此，直接的递归搜索有`Theta(n!)`终端分支，扫描每个状态可能的移动可以将工作推送到`O(n * n!)`。 即使有记忆，也可以`Theta(n * 2^n)`州，这仍然是无望的`n = 100000`。 

有用的观察是这个游戏有一个标准的匹配特征。 对于任何无向图，如果存在完美匹配，第二个玩家可以通过移动到与刚刚选择的顶点匹配的顶点来回答每一步移动。 匹配的顶点保证不会被使用，因为它的伙伴是唯一可以更早消耗它的顶点。 

相反的方向也同样有用。 假设最大匹配不完美，让 Alice 从一个不匹配的顶点开始。 鲍勃不能从爱丽丝的起始顶点移动到另一个不匹配的顶点，因为这样的移动将为最大匹配创建一条增广路径。 因此，Bob 可以到达的每个顶点都是匹配的。 爱丽丝可以使用其匹配伙伴来回答，就像完美匹配情况下的第二玩家策略一样。 这给了爱丽丝获胜的策略。 这种匹配特征是博弈论的核心简化。 

所以游戏就简化为一个问题：祖先图是否完美匹配？ 

我们仍然无法构建祖先图，因为它可能包含二次方多条边。 有根树的特殊结构拯救了我们。 在 的子树内`u`，属于两个不同子子树的顶点是不可比较的，因此它们永远不能彼此配对。 中唯一的顶点`u`可以连接不同子子树的子树是`u`本身。 这使得非常小的树DP成为可能。 

让`dp[u]`是在完全在子树内进行最大匹配后留下不匹配的顶点的最小数量`u`。 如果孩子们集体离开`s`不匹配的顶点，那么当`s = 0`,`u`它本身没有下面的人可以配对，因此仍然存在一个不匹配的顶点。 什么时候`s > 0`,`u`可以与那些无与伦比的后代之一配对，留下`s - 1`。 因此

 dp[u]={ 1, s−1, s=0, s>0, ​

 哪里

 s= v u Σ ​ dp[v] 的子级。 

这正是用于问题的祖先-后代匹配公式的树 DP。 

根恰好在以下情况下具有完美匹配：`dp[1] = 0`。 如果为零，则鲍勃获胜。 否则，爱丽丝获胜。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n · n!)`没有记忆|`O(n)`递归/状态 | 太慢了 |
 | 最佳|`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 将原始树构建为邻接表。 我们从不显式地构造祖先-后代边，因为可能存在`Theta(n^2)`其中。 
2. 在顶点处建立树根`1`并计算父数组和遍历顺序。 以反向遍历顺序处理顶点给出了自下而上的树DP，而不依赖于Python的递归深度。 
3. 对于每个顶点`u`, 计算

 s=Σdp[v]

 超过它的孩子`v`。 每个子节点贡献其子树必须公开的最小数量的不匹配顶点。 
4. 如果`s = 0`， 放`dp[u] = 1`。 每个子子树已经可以在内部完美匹配，因此没有可用的后代`u`配对。 顶点`u`其本身必须保持无与伦比。 
5. 如果`s > 0`， 放`dp[u] = s - 1`。 下面某处至少存在一个不匹配的顶点`u`，并且每个这样的顶点都是`u`， 所以`u`可以与其中之一搭配。 这恰好消耗了一个先前未匹配的顶点。 
6.处理完root后，检查`dp[1]`。 值为零意味着整个树可以划分为祖先-后代对，这是游戏图的完美匹配。 在这种情况下，鲍勃获胜。 任何正值都意味着最大匹配至少有一个顶点不匹配，因此 Alice 从这样一个不匹配的顶点开始并获胜。 

为什么它有效：DP 保持不变式`dp[u]`是完全包含在子树中的所有匹配中不匹配顶点的最小数量`u`。 子子树不能相互交互，因为来自不同子子树的顶点是不可比较的。 因此，合并孩子后唯一可能的改进是使用`u`匹配一位暴露的后代。 递归恰好考虑了这两种可能性，因此计算出真正的最小值。 在根部，零个不匹配的顶点相当于完美匹配。 然后匹配的游戏参数决定获胜者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    # Root the tree at 0.
    parent = [-1] * n
    order = [0]
    parent[0] = -2

    for u in order:
        for v in graph[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            order.append(v)

    # Process children before parents.
    dp = [0] * n

    for u in reversed(order):
        total = 0

        for v in graph[u]:
            if parent[v] == u:
                total += dp[v]

        if total == 0:
            dp[u] = 1
        else:
            dp[u] = total - 1

    print("Bob" if dp[0] == 0 else "Alice")

if __name__ == "__main__":
    solve()
```邻接表只存储`n - 1`原始树的边缘。 这`parent`数组以顶点为树根`1`，用索引表示`0`在Python中。 这`order`数组是从根开始的遍历，因此反转它可以保证每个孩子都已经收到了它的`dp`处理其父级时的值。 

DP本身故意做得很小。 对于每个顶点，`total`是其子项值的总和。 表达式`total == 0`是递归中唯一的边界情况。 当它为零时，当前顶点贡献一个不匹配的顶点。 否则，它会消耗一个无与伦比的后代。 

实现是迭代的而不是递归的。 一条路径与`100000`顶点会在周围创建递归深度`100000`，即使手动增加递归限制，这在 Python 中也是不安全的。 整数溢出是不可能的，因为 Python 整数是任意精度的，事实上每个`dp[u]`至多是其子树的大小。 

操作顺序很重要。 在推送邻居之前计算父级可以防止返回父级的无向边被视为子边。 条件`parent[v] == u`然后在 DP 阶段准确识别`u`。 

## 工作示例

 ### 示例 1

 树是一条路径：```
1 - 2 - 3 - 4
```每个顶点在 root 后至多有一个子节点`1`。 

| 顶点| 儿童 | 儿童总和|`dp`|
 | --- | --- | --- | --- |
 | 4 | 无 | 0 | 1 |
 | 3 | 4 | 1 | 0 |
 | 2 | 3 | 0 | 1 |
 | 1 | 2 | 1 | 0 |

 根有`dp[1] = 0`，因此祖先图具有完美匹配。 一种这样的匹配是`(1,2), (3,4)`。 Bob 总是可以使用 Alice 最新举动的匹配伙伴进行响应，因此输出为`Bob`。 

### 示例 2

 生根后在`1`, 顶点`1`有孩子`2`和`3`。 顶点`2`有孩子`4`,`5`,`6`， 和`7`， 尽管`3`是一片叶子。 

| 顶点| 儿童 | 儿童总和|`dp`|
 | --- | --- | --- | --- |
 | 4 | 无 | 0 | 1 |
 | 5 | 无 | 0 | 1 |
 | 6 | 无 | 0 | 1 |
 | 7 | 无 | 0 | 1 |
 | 2 | 4、5、6、7 | 4 | 3 |
 | 3 | 无 | 0 | 1 |
 | 1 | 2, 3 | 4 | 3 |

 根有`dp[1] = 3`，因此在最佳可能匹配之后，三个顶点仍然不匹配。 没有完美的匹配，爱丽丝获胜。 这与示例策略一致，其中 Alice 从顶点开始`3`并使用分支结构来防止Bob维持匹配的响应。

## 边缘情况

 对于单顶点的情况，```
1
```遍历仅包含根。 它的孩子总和为零，所以`dp[1] = 1`。 根不能完美匹配，意味着祖先图没有完美匹配。 Alice 立即获胜，算法打印`Alice`。 

对于四顶点路径，```
4
1 2
2 3
3 4
```自下而上的值为`dp[4] = 1`,`dp[3] = 0`,`dp[2] = 1`， 和`dp[1] = 0`。 根部的零代表匹配`(1,2), (3,4)`。 鲍勃可以使用这些对作为响应，给出`Bob`。 这个案例也证实了 DP 并不是简单地对顶点进行模 2 计数。 

对于分枝树来说，```
4
1 2
1 3
1 4
```每片叶子都贡献`1`，因此根收到的子总和为`3`并获得`dp[1] = 2`。 没有完美的匹配。 爱丽丝可以从一片叶子开始，之后鲍勃被迫到根部，爱丽丝又拿了另一片叶子。 那么鲍勃就没有合法的行动。 算法正确打印`Alice`。 

对于不平凡的完美匹配情况，```
6
1 2
1 3
2 4
3 5
4 6
```值是`dp[6] = 1`,`dp[4] = 0`,`dp[2] = 1`,`dp[5] = 1`,`dp[3] = 0`，最后`dp[1] = 0`。 完美的搭配是`(4,6), (2,1), (3,5)`。 一般来说，这些对不必都是原始树边，只需祖先-后代对即可。 由于匹配覆盖了每个顶点，鲍勃对爱丽丝的每一步移动都有响应。 

对于最大尺寸路径，实现永远不会递归下降`100000`堆栈帧。 它迭代地构造父订单，向后处理该订单，并获得`dp[1] = 0`因为偶数长度的路径具有完美匹配。 结果是`Bob`。 

对于最大尺寸的恒星，每片叶子都有贡献`1`。 根见`99999`无与伦比的后代并消耗其中之一，留下`99998`， 所以`dp[1] > 0`。 结果是`Alice`。 这也发挥了最大可能的程度，并确认子贡献必须求和而不是减少到布尔状态。
