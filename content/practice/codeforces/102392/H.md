 ## 解决方案
 ## 问题理解

 原始树以顶点 (1) 为根，每个顶点 (i>1) 都有一个父顶点 (p_i<i) 和一个边权重 (w_i)。 包含所有这些父值和所有这些边权重的多重集具有 (2n-2) 个元素，但由于数组被打乱，它们的角色丢失了。 

我们不需要重建一棵特定的树。 对于从顶点 (1) 到顶点 (n) 的每个可能的路径长度 (k)，我们需要该路径上的最大可能的权重总和。 如果没有有效的树可以在该路径上恰好具有 (k) 条边，则 (k) 的答案为 (-1)。 

关键的困难在于，打乱数组中的每个数字都可以成为父值或边权重。 用作父代的数字有结构限制，而用作权重的数字则没有这种限制。 解决方案是将这两个角色分开。 

对于 (n\le 10^5)，打乱后的数组几乎有 (2\cdot10^5) 个元素。 一秒的时间限制排除了任何二次方，当然也排除了枚举可能的树或排列。 我们基本上只需要处理每个输入值恒定或对数的次数。 (O(n\log n)) 解决方案就足够了，官方竞赛社论使用相同的渐近界限来实现。 

有几种边缘情况可能会使看似合理的贪婪实现失败。 

考虑```
3
2 2 2 2
```排序后，第一个值为(2)，但顶点(2)的父节点必须小于(2)。 任何排列都不能形成有效的树，因此正确的输出是```
-1 -1
```粗心的解决方案可能会保留一个 (2) 作为权重，并尝试使用另一个 (2) 作为 (p_2)，默默地违反 (p_2<2)。 

重复的值也很重要。 为了```
4
1 1 1 1 1 1
```只有一个不同的值，(1)。 唯一可能的路径有一条边，其权重为 (1)。 正确的输出是```
1 -1 -1
```将相等的值视为不同的可能路径顶点的解决方案可能会错误地声明更长的路径。 

一个不太明显的情况是，即使重复较小的值，也会将值 (i) 强制放到路径上。 例如，```
6
1 1 1 4 4 4 4 4 5 5
```排序后，第四个值为(4)，因此顶点(4)被强制到路径上。 强制路径值是（1）和（4），而（5）是可选路径值。 有效长度为 (2) 和 (3)，给出```
-1 10 13 -1 -1
```简单地采用最小的不同值的幼稚策略会忽略 (4) 是强制性的这一事实。 

最后，(k=n-1) 是真正的边界情况。 为了```
4
1 2 3 3 3 3
```该路径必须包含每个顶点，因此唯一可能的长度是 (3)。 保留父值 (1,2,3) 后，剩余的三个最大值都是 (3)，给出```
-1 -1 9
```(n-1)（哈密顿根到 (n) 路径中的边数）与 (n)（该路径上的顶点数）之间的区别很容易产生差一误差。 

## 方法

 暴力方法将为每个 (2n-2) 数组元素分配父值和权重序列中的一个位置，然后检查生成的树是否有效并记录其路径长度和权重总和。 即使忽略重复值，这也意味着考虑 ((2n-2)!) 安排。 在 (n=10^5) 时，排列的数量如此之大，即使在恒定时间内检查一个排列也是没有意义的。 检查 (O(n)) 中的每个排列给出 (O(n(2n-2)!))，因此暴力仅适用于用于发现模式的微小实例。 

蛮力之所以有效，是因为它明确地探索了每种可能的角色分配。 它失败了，因为几乎所有这些作业都是无关紧要的。 有用的观察结果是父值具有非常严格的排序特征。 

将打乱后的数组排序为

 [
 a_1\le a_2\le\cdots\le a_{2n-2}。 
]

 对于有效的树，对于每个 (i\le n-1)，前 (i) 个元素不能包含大于 (i) 的值。 等价地，

 [
 a_i\le i。 
]

 要了解原因，顶点 (2,3,\ldots,i+1) 需要 (i) 个父值，并且每个父值最多为 (i) 个。 如果 (a_i>i)，则最多 (i) 个可用值少于 (i) 个，因此前 (i) 个顶点不能全部接收合法父节点。 因此，一次违规意味着不存在有效的树。 这是首次大幅削减。 

还有第二个更强烈的后果。 假设

 [
 a_i=i。 
]

 那么顶点 (i) 必须位于从 (1) 到 (n) 的路径上。 最多有 (i-1) 个值小于 (i)，并且顶点 (2,\ldots,i) 已经精确地需要 (i-1) 个合法父值。 这些值完全被较低的顶点消​​耗，因此每个大于 (i) 的顶点至少有一个父顶点 (i)。 从(n)返回到(1)的路径不能从大于(i)的值跳转到小于(i)的值而不经过(i)。 因此 (i) 被迫走上这条路。 

令 (c) 为满足 (a_i=i) 的索引 (i\in[1,n-1]) 的数量。 这些 (c) 值必须出现在从 (1) 到 (n) 的每个可能路径上，因此不存在少于 (c) 条边的路径。 

现在考虑数组中出现的所有不同值。 路径不能两次包含相同的顶点，因此其父值是不同的。 由于路径有 (k) 条边，因此它恰好使用 (k) 个父值，即除 (n) 之外的路径顶点。 因此 (k) 不能超过数组中不同值的数量。 

关键部分是这两个极限之间的每个 (k) 实际上都是可以实现的。 从所有强制值开始。 每当我们需要多一条路径边时，添加尚未选择的最小不同值。 然后将选定的值排序并放置在 (1) 和 (n) 之间以形成路径。 

为什么选择最小的可用值有效？ 排序条件 (a_i\le i) 保证有足够小的父值来支持路径之外的所有顶点。 更具体地说，修复路径后，删除每个路径父值的一次出现。 对剩余的候选父值和仍需要父值的顶点进行排序。 按升序将它们配对。 如果某个候选父节点不小于其分配的顶点，则计算最多有多少个路径顶点和未分配的顶点该值将与原始排序条件 (a_i\le i) 相矛盾。 这是官方社论中使用的建设性论点。 

一旦特定路径可行，其最佳权重就会简单得多。 正好 (k) 个数组元素用作路径的父值。 其余的每个元素都可以是一个权重，并且权重没有上限限制。 因此，最大路径权重是通过在删除每个选定路径值的一次出现后剩下的所有元素中取 (k) 个最大元素来获得的。

这给出了整个算法。 我们对数组进行排序以检测不可能性和强制值。 然后，我们从最小到最大添加可选路径值。 每次相加后，我们需要剩余多重集中的 (k) 个最大值的总和。 值 (1,\ldots,n-1) 上的 Fenwick 树维护剩余出现次数及其总和，允许在 (O(\log n)) 中进行此查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n(2n-2)!)) | (O(n)) | (O(n)) | 太慢了 |
 | 最佳| (O(n\log n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 读取(2n-2)个值并对其进行排序。 排序公开了前缀条件 (a_i\le i)，这是判断是否存在任何有效树的最简单的可能测试。 
2. 检查从 (1) 到 (n-1) 的每个排序位置 (i)。 如果 (a_i>i)，则为每个路径长度输出 (-1) 并停止。 根本不可能存在任何有效的树，因此每个答案都是不可能的。 
3. 为所有值构建频率表，并初始化包含每个数组值的每次出现的 Fenwick 树。 芬威克树存储出现次数和总和，因为稍后我们需要删除选定的父值并查询大量剩余值。 
4. 再次扫描排序后的数组。 每当 (a_i=i) 时，将值 (i) 标记为强制，从 Fenwick 树中删除一次 (i) 的出现，并增加当前路径长度 (k)。 恰好删除一个出现的位置是正确的，因为一份副本被用作进入顶点 (i+1) 的路径边的父值。 
5. 处理完所有强制值后，计算当前 (k) 的答案。 剩余的多重集包含未作为强制路径父级消耗的每个值，因此最佳可能的路径权重是其 (k) 个最大元素的总和。 
6. 按升序处理值 (x=1,2,\ldots,n-1)。 如果 (x) 出现并且尚未强制，则删除一次 (x) 的出现，将其标记为新的路径顶点，并递增 (k)。 递增顺序正是保证剩余值仍然可以作为有效父母的贪心选择。 
7. 每次相加后，查询 (k) 个最大剩余值的总和并将其存储为该路径长度的答案。 不会出现其他路径长度，因为每个可行长度都位于强制计数和不同值的数量之间。 
8. 将该区间之外的每个答案保留为 (-1)。 答案数组已经以这种方式初始化，因此不需要单独构造。 

不变的是，在处理路径长度 (k) 后，Fenwick 树精确地包含值的多重集，在保留 (k) 个所选路径父值之后，这些值仍可用于权重和路径外父值。 通过排序前缀条件和贪婪最小值构造，所选路径本身是可行的。 由于权重没有结构约束，因此选择 (k) 个最大剩余值是最佳的。 因此，每个存储的答案都是可实现的且是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.cnt = [0] * (n + 1)
        self.s = [0] * (n + 1)

    def add(self, x, dc, ds):
        n = self.n
        cnt = self.cnt
        sm = self.s
        while x <= n:
            cnt[x] += dc
            sm[x] += ds
            x += x & -x

    def sum_smallest(self, k):
        if k <= 0:
            return 0

        idx = 0
        cnt = 0
        sm = 0

        bit = 1 << (self.n.bit_length() - 1)
        while bit:
            nxt = idx + bit
            if nxt <= self.n and cnt + self.cnt[nxt] <= k:
                idx = nxt
                cnt += self.cnt[nxt]
                sm += self.s[nxt]
            bit >>= 1

        if cnt < k:
            value = idx + 1
            sm += (k - cnt) * value

        return sm

    def sum_largest(self, k, total_count, total_sum):
        return total_sum - self.sum_smallest(total_count - k)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = 2 * n - 2

    a.sort()

    for i in range(1, n):
        if a[i - 1] > i:
            return " ".join(["-1"] * (n - 1))

    freq = [0] * n
    forced = [False] * n

    bit = Fenwick(n - 1)

    total_sum = 0
    for x in a:
        freq[x] += 1
        total_sum += x
        bit.add(x, 1, x)

    total_count = m

    k = 0

    for i in range(1, n):
        if a[i - 1] == i:
            forced[i] = True
            freq[i] -= 1
            bit.add(i, -1, -i)
            total_count -= 1
            total_sum -= i
            k += 1

    ans = [-1] * (n - 1)

    if k > 0:
        ans[k - 1] = bit.sum_largest(k, total_count, total_sum)

    for x in range(1, n):
        if freq[x] > 0 and not forced[x]:
            freq[x] -= 1
            bit.add(x, -1, -x)
            total_count -= 1
            total_sum -= x
            k += 1

            ans[k - 1] = bit.sum_largest(k, total_count, total_sum)

    return " ".join(map(str, ans))

if __name__ == "__main__":
    sys.stdout.write(solve())
```首先使用排序的数组，因为有关父值的所有结构信息都由其前缀捕获。 仅通过位置 (1,\ldots,n-1) 检查条件，因为正好有 (n-1) 个父值，并且第 (n) 个顶点本身不能是父值。 

这`freq`数组记录哪些不同值仍然可用作可能的路径顶点。 这`forced`array 可以防止当后面的贪婪扫描达到相同值时再次选择强制值。 当一个值出现多次时，这一点很重要。 

芬威克树在每个前缀处存储两个数量，剩余出现的次数及其总和。`sum_smallest(t)`通过芬威克树的二元提升找到最小 (t) 剩余元素的总和。 如果所需的前缀在多次出现相同值的值中途结束，则剩余的副本将在最后一起处理。 

最大 (k) 个剩余值的总和如下所示

 [
 \text{总和}-\text{最小的总和}(m-k)\text{值}。 
]

 这避免了需要单独的最大阶统计结构。 

Python 整数具有任意精度，因此路径和不需要特殊的溢出处理。 最大可能的总和仅为 (O(n^2))，但即使不依赖固定整数宽度，实现也是正确的。 

索引转换也是经过深思熟虑的。 数学数组是一索引的，而 Python 列表是零索引的。 测试`a[i - 1] > i`完全符合数学条件 (a_i>i)，并且`ans[k - 1]`存储包含 (k) 条边的路径的答案。 

## 工作示例

 ### 示例 1

 输入是```
3
1 1 2 2
```排序后，数组已经是([1,1,2,2])。 前缀条件有效，因为 (a_1=1\le1) 和 (a_2=1\le2)。 

(i\le2) 的唯一等式 (a_i=i) 是 (a_1=1)，因此最小可行路径长度为 (1)。 

| 步骤| 选定的路径值 | 剩余多组 | (k) | 最佳总和|
 | --- | --- | --- | --- | --- |
 | 初始| ({1}) | ({1,2,2}) | 1 | 2 |
 | 增值2 | ({1,2}) | ({1,2}) | ({1,2}) | ({1,2}) | 2 | 3 |

 对于 (k=1)，保留一 (1) 作为顶点 (n=3) 的父值。 最大的剩余值为(2)，所以答案为(2)。 

对于 (k=2)，保留一 (1) 和一 (2) 作为路径父值。 两个最大的剩余值是 (2) 和 (1)，得出 (3)。 

结果输出是```
2 3
```该跟踪表明，一个值可以用作父级或权重，并且最佳选择是保留所需的最小路径父级值，同时保留路径权重的最大可能值。

 输入是```

 | --- | --- | --- |
 | 时间 | (O(n\log n)) | 排序需要 (O(n\log n))，并且有 (O(n)) 个 Fenwick 更新和查询，每次需要 (O(\log n))。 |
 | 空间| (O(n)) | (O(n)) | 排序数组、频率数组、答案数组和 Fenwick 树都使用 (O(n)) 内存。 |

import sys
import io

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.cnt = [0] * (n + 1)
        self.s = [0] * (n + 1)

    def add(self, x, dc, ds):
        while x <= self.n:
            self.cnt[x] += dc
            self.s[x] += ds
            x += x & -x

    def sum_smallest(self, k):
        if k <= 0:
            return 0

        idx = 0
        cnt = 0
        sm = 0
        bit = 1 << (self.n.bit_length() - 1)

        while bit:
            nxt = idx + bit
            if nxt <= self.n and cnt + self.cnt[nxt] <= k:
                idx = nxt
                cnt += self.cnt[nxt]
                sm += self.s[nxt]
            bit >>= 1

        if cnt < k:
            sm += (k - cnt) * (idx + 1)

        return sm

def solution(inp: str) -> str:
    data = list(map(int, inp.split()))
    it = iter(data)
    n = next(it)
    a = [next(it) for _ in range(2 * n - 2)]

    a.sort()

    for i in range(1, n):
        if a[i - 1] > i:
            return " ".join(["-1"] * (n - 1))

    freq = [0] * n
    forced = [False] * n
    bit = Fenwick(n - 1)

    total_count = len(a)
    total_sum = sum(a)

    for x in a:
        freq[x] += 1
        bit.add(x, 1, x)

    k = 0

    for i in range(1, n):
        if a[i - 1] == i:
            forced[i] = True
            freq[i] -= 1
            bit.add(i, -1, -i)
            total_count -= 1
            total_sum -= i
            k += 1

    ans = [-1] * (n - 1)

    if k:
        small = bit.sum_smallest(total_count - k)
        ans[k - 1] = total_sum - small

    for x in range(1, n):
        if freq[x] and not forced[x]:
            freq[x] -= 1
            bit.add(x, -1, -x)
            total_count -= 1
            total_sum -= x
            k += 1

            small = bit.sum_smallest(total_count - k)
            ans[k - 1] = total_sum - small

    return " ".join(map(str, ans))

def run(inp: str) -> str:
    return solution(inp)

 ## 边缘情况

 ### 没有有效的树

 对于```
3
2 2 2 2
```排序后的数组以 (a_1=2) 开头。 由于顶点 (2) 的父级必须是 (1)，因此 (2) 的出现不能填补该角色。 有效性扫描立即检测到(a_1>1)并返回`-1 -1`。 芬威克树永远不会被查询，因此无效的实例不会意外地产生合理的路径和。 

### 重复值

 对于```
4
1 1 1 1 1 1
```唯一不同的值是 (1)。 第一个排序位置满足 (a_1=1)，因此一 (1) 成为唯一可能的路径边缘的强制父值。 其余七个副本可用于权重和其他父项，但没有可以放置在路径上的第二个不同的顶点值。 该算法将单边答案记录为 (1)，并将其他位置保留为 (-1)。 

### 强制路径值远离开头

 对于```
6
1 1 1 4 4 4 4 4 5 5
```排序后的前缀满足

 [
 a_1=1，\qquad a_2=1，\qquad a_3=1，\qquad a_4=4。 
]

 因此（1）和（4）被强制到每条路径上。 初始路径长度为(2)。 删除一 (1) 和一 (4) 后，在最大值中留下两 (5) 和四 (4)，因此剩下的两个最大值之和为 (10)。 这给出了 (k=2) 的答案。 

下一个未使用的不同值是 (5)。 去掉一(5)，路径长度为(3)，剩下的三个最大值是(5,4,4)，其和是(13)。 不再有不同的值，因此 (k=4) 和 (k=5) 仍然不可能。 最终输出是`-1 10 13 -1 -1`。 

### 最大路径长度

 对于```
4
1 2 3 3 3 3
```等式 (a_1=1)、(a_2=2) 和 (a_3=3) 将所有三个父值 (1,2,3) 强制到路径上。 因此 (k=3=n-1) 是唯一可行的长度。 在删除 (1,2,3) 中每一个出现的一次后，(3) 的三个副本仍保留在可用作路径权重的值中，因此答案为 (9)。 该算法将其存储在`ans[2]`，对应于 (k=3)，避免将路径的 (n) 个顶点视为 (n) 条边的常见错误。 

上面的社论遵循有效排序前缀、强制路径顶点和附加路径值的贪婪选择的官方特征，同时使用芬威克树作为顺序统计总和。
