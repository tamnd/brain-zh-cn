 ## 解决方案
 ## 问题理解

 史蒂夫有一系列任务，每个任务最多只能完成一次。 在第一级完成之前，任务 (i) 会提供 (x_i) 经验并消耗 (t_i) 分钟。 第一个关卡完成后，相同的任务仅提供 (y_i) 经验值和花费 (r_i) 分钟。 

第一级需要 (s_1) 经验。 一旦史蒂夫达到它，任何超出（s_1）的导致升级的任务经验都会立即计入第二级。 然后，第二级需要另一个（s_2）经验，并因溢出而减少。 目标是选择哪些任务在升级之前完成，哪些任务在升级之后完成，以及使两个级别在最短时间内完成的顺序。 如果不存在这样的选择，则答案为（-1）。 官方问题页面确认任务不能重复，并且第一级的溢出直接进入第二级。 

第一级和第二级要求最多为500，而每个经验值也最多为500。这就是积累经验索引的动态程序可以实用的信号。 任务数量也最多为 500，因此 (O(n s_1 s_2)) 算法在绝对最坏的情况下执行大约 (125.5) 百万次状态迭代。 枚举每个可能的任务分配的解决方案有 (3^n) 种可能性，对于 (n=500) 来说已经是 (10^{238}) 左右，所以暴力破解是完全不可能的。 官方社论给出了相同的 (O(n s_1 s_2)) 动态规划界限。 

在某些情况下，粗心的实施可能会产生看似合理但不正确的答案。 首先是溢出。 考虑```
2 5 5
6 10 1 1
1 1 5 1
```正确答案是`11`。 第一个任务应该在升级之前完成，获得6经验。 第一级只需要5个，所以1个经验会溢出到第二级。 升级后第二个任务会额外提供 5 经验，因此第二级总共获得 6 经验。 简单地将第一个经验限制在 (s_1) 并丢弃多余部分的 DP 将错误地得出第二级仅获得 5 个经验的结论。 

第二个边缘情况是，DP 早期考虑的任务不一定必须在升级之前实际完成。 例如，```
2 100 100
100 100 10 10
101 11 100 10
```有答案`110`。 第二个任务在第一级更便宜，而第一个任务在第二级更便宜，但必须对任务进行排序，以便在使用任务的第二级版本之前实际达到第一级。 将输入顺序视为实际执行顺序的 DP 可能会错过最佳分配。 

第三种边缘情况是不可能的。 为了```
2 20 5
10 10 5 5
10 10 5 5
```答案是`-1`。 两个任务加在一起只提供了20点一级经验，正好够到达一级，但消耗完后就没有剩下二级经验了。 仅检查第一级是否可以完成的粗心解决方案将错误地接受这种情况。 

## 方法

 最直接的暴力为每个任务分配三个角色之一：未使用、在第一级之前完成或在第一级之后完成。 对于每一个（3^n）个任务，我们可以检查一级任务是否可以达到（s_1），计算溢出，然后检查二级任务是否提供剩余的经验。 我们也可以直接搜索可能的顺序，但这更糟糕，因为它在分配选择之上引入了排列。 仅三路分配就提供了 (3^{500}) 种可能性，因此这种方法几乎立即变得不可用。 

自然的下一步是动态规划。 假设我们以某种固定的顺序处理任务，并将（j）保留为第一级经验，将（k）保留为第二级经验。 对于每个任务，我们可以忽略它，将其分配给第一级，或将其分配给第二级。 如果第一级任务将 (j) 推过 (s_1)，则其超出部分必须添加到 (k)。 这给出了仅 (O(s_1s_2)) 的状态，而不是记住已经选择了哪些单独的任务。 

有一个障碍：任务没有固定的执行顺序。 特别是，哪个任务导致第一个级别完成很重要，因为该任务决定了溢出。 

关键的观察是我们可以通过增加 (x_i) 对任务进行排序。 考虑任何有效的解决方案，并查看实际导致第一个级别完成的任务。 假设它的一级经验是（U）。 分配给第一级的所有其他任务都在此之前完成，他们的总经验仍然低于（s_1）。 如果同一解决方案中的另一个第一级任务给出 (V \ge U)，我们可以将该任务移至最终位置。 总时间和所使用的任务组不会改变，而较大的经验值至少能够产生升级。 重复这个参数让我们选择最大的（x_i）第一级任务作为导致溢出的任务。 因此，在按(x_i)排序后，存在一个最优解，其第一级任务按此排序顺序处理。 这正是官方社论中使用的排序观察。 

在此排序处理中较早出现的二级任务仅由 DP 选择。 它们尚未实际完成。 它们都可以推迟到达到第一级之后。 这就是为什么DP即使在(j<s_1)时也可以安全地积累二级经验。 

任务排序完成后，DP 就变得简单了。 该状态存储准确获得第一级和第二级进度所表示的上限数量所需的最短时间。 忽略任务会使状态保持不变。 在第二级将 (k) 增加 (y_i)。 在第一级将 (j) 增加 (x_i)，如果超过 (s_1)，则超出部分将添加到 (k)。 

DP可以就地进行。 我们以降序处理两个维度，因此每次转换都会转移到已经为当前任务处理过的状态。 因此，当前任务不能使用两次。 这会删除直接实现所使用的额外临时（s_1 \times s_2）数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(3^n)) | (O(n)) | (O(n)) | 太慢了 |
 | 最佳DP | (O(n s_1 s_2)) | (O(s_1 s_2)) | 已接受 |

 ## 算法演练

1. 读取所有任务并按 (x_i) 递增排序。 排序为我们提供了可以考虑第一级任务的规范顺序。 最佳解决方案始终可以使用此顺序来表示，因为导致第一级别完成的任务可以被选择为分配给第一级别的任务中的最大（x_i）任务。 
2. 创建`dp[j][k]`， 在哪里`j`是累计的一级经验上限为(s_1)，`k`是累积的二级经验，上限为(s_2)，存储的值是使用迄今为止处理的任务达到该状态所需的最少分钟数。 将每个状态初始化为无穷大，除了`dp[0][0] = 0`。 
3. 对于当前的任务，考虑每个可到达的状态。 第一种可能性是跳过任务。 由于DP是就地执行的，所以跳过根本不需要赋值，也不需要显式操作。 
4.第二种可能是在第一关之后使用任务。 它的状态变成
 [
 (j,\min(s_2,k+y_i))
 ]
 其成本增加 (r_i)。 即使在 (j<s_1) 时也允许此转换，因为 DP 正在选择任务以供以后使用。 其物理执行可以推迟到第一级完成之后。 
5、第三种可能是在第一关之前使用任务。 计算 (j+x_i)。 如果低于 (s_1)，则新状态就是 ((j+x_i,k))，成本增加 (t_i)。 如果达到或超过(s_1)，则一级状态变为(s_1)，超过的部分
 [
 j+x_i-s_1
 ]
 被添加到二级进度中。 因此新的状态是
 [
 \left(s_1,\min(s_2,k+j+x_i-s_1)\right)。 
]
 溢出部分必须保留，因为它直接减少了第二关仍需要的经验量。 
6. 流程`j`从 (s_1) 下降到零并且`k`从 (s_2) 下降到零。 每个非跳过过渡都会增加`j`或者`k`，因此降序迭代意味着当前任务已经访问过其目的地。 因此，该任务不能对同一 DP 层贡献两次。 
7. 处理完每个任务后，检查`dp[s1][s2]`。 如果它是有限的，则该值是完成两个级别所需的最短时间。 如果它仍然是无限的，则任何任务分配都无法完成两个级别，因此答案为（-1）。 

### 为什么它有效

 不变的是，在处理排序任务列表的任何前缀之后，`dp[j][k]`是那些一级进度为 (j)、二级进度为 (k) 的已处理任务的每个可能分配的最短时间，这两个值均以其要求为上限。 每个任务都有三个相关的选择，未使用的，升级前使用的，或升级后使用的。 第一级转换记录恰好在超过阈值时溢出，因此状态保留了以后可能重要的所有经验。 

排序参数保证以 (x_i) 递增顺序考虑第一级任务不会丢失有效的最优值。 一旦达到第一级，分配给第二级的每个任务都可以在之后执行，无论它在 DP 扫描期间出现在哪里。 因此，每个有效的实际执行对应于一条DP路径，并且每个到达((s_1,s_2))的DP路径对应于可以在所有二级任务之前与所有第一级任务一起调度的可行分配。 由于每个转换都存储到达其目的地的最短时间，因此最终状态包含全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    n, s1, s2 = map(int, input().split())

    quests = []
    for _ in range(n):
        x, t, y, r = map(int, input().split())
        quests.append((x, t, y, r))

    # An optimal solution can be represented with first-level
    # quests processed in nondecreasing x order.
    quests.sort(key=lambda q: q[0])

    # dp[j][k] = minimum time to obtain capped first-level
    # progress j and capped second-level progress k.
    dp = [[INF] * (s2 + 1) for _ in range(s1 + 1)]
    dp[0][0] = 0

    prefix_x = 0

    for x, t, y, r in quests:
        prefix_x = min(s1, prefix_x + x)

        # In-place 0/1 DP.
        # Both transitions only increase j or k, so descending
        # iteration prevents using this quest more than once.
        for j in range(prefix_x, -1, -1):
            row = dp[j]

            for k in range(s2, -1, -1):
                cur = row[k]
                if cur == INF:
                    continue

                # Use the quest after reaching level 1.
                nk = k + y
                if nk > s2:
                    nk = s2

                value = cur + r
                if value < row[nk]:
                    row[nk] = value

                # Use the quest before reaching level 1.
                if j < s1:
                    nj = j + x

                    if nj >= s1:
                        overflow = nj - s1
                        nk = k + overflow
                        if nk > s2:
                            nk = s2
                        target = dp[s1]

                        value = cur + t
                        if value < target[nk]:
                            target[nk] = value
                    else:
                        value = cur + t
                        if value < dp[nj][k]:
                            dp[nj][k] = value

    answer = dp[s1][s2]
    return str(answer if answer != INF else -1)

if __name__ == "__main__":
    print(solve())
```任务元组存储为`(x, t, y, r)`这样DP转换就可以直接使用与当前电平相关的值。 排序仅通过`x`，因为排序参数取决于第一级经验而不是时间或第二级经验。 

桌子上有`(s1 + 1) * (s2 + 1)`州。 两个经验维度都有上限，因为任何超出级别所需数量的进度都没有额外价值，除了第一级溢出之外，第一级溢出会在跨越第一级时明确转移到第二级维度。 

循环内的第一个转换处理升级后的任务。 第二个转换处理在升级之前使用它。 这两个转换的顺序不会影响正确性，因为两个目的地在下降的 DP 方向上都严格位于更远的位置。 

下降迭代是微妙的。 如果`j < s1`，在第一级使用任务会增加`j`，因此其目标行已被处理。 在第二级使用它会增加`k`，因此其目标列也已被处理。 这意味着两个转换都无法将当前任务反馈回将再次处理的状态。 

溢出计算使用`j + x - s1`， 不是`min(j + x, s1) - s1`。 前者准确保留跨越第一级边界的数量。 二级值的上限为`s2`因为完成第二关后额外的经验没有任何作用。 

Python 整数不会溢出，但使用固定宽度整数的语言需要 64 位类型。 最大可能的总时间最多为 (500 \cdot 10^9 = 5 \cdot 10^{11})。 

原始竞赛解决方案使用相同的按 (x_i) 排序的 DP，具有 (O(n s_1s_2)) 时间和 (O(s_1s_2)) 内存。

 ## 边缘情况

 第一个重要的边缘情况是第一级的精确完成。 考虑```
2 5 5
5 7 1 1
1 100 5 2
```第一个任务恰好提供 5 经验，因此其溢出为零。 史蒂夫花了 7 分钟，到达第二级，然后使用第二个任务以 2 点的成本获得 5 点经验。 DP 从`(0,0)`到`(5,0)`成本为 7，然后`(5,5)`成本为 9。答案是`9`。 这`>= s1`转换中的边界可以正确处理这种情况，因为零溢出是有效的。 

第二个边缘情况是真正的溢出。 考虑```
2 5 5
6 10 1 1
1 1 5 1
```使用第 1 级的第一个任务会产生 6 经验，因此第一级消耗 5 点经验并进入第二级。 然后第二个任务又提供 5 点经验，总共提供 6 点二级进度。 DP 转变自`(0,0)`到`(5,1)`记录溢出，下一个转换到达`(5,5)`。 总时间是`10+1=11`。 

第三种边缘情况是不可能的：```
2 20 5
10 10 5 5
10 10 5 5
```这两个任务在第一关之前正好可以提供20点经验，但是之后两个任务都已经被消耗掉了。 国家`(20,0)`是可达的，同时`(20,5)`不是。 自从`dp[20][5]`保持无穷大，算法返回`-1`。 

第四个边缘情况是一个在升级之前非常昂贵但之后很便宜的任务。 在示例 2 中，40 经验的任务在升级前需要花费 1000 分钟，升级后只需 20 分钟。 DP 不使用仅基于经验的贪心规则。 它考虑了这两个角色，发现两个 10 经验的任务应该在 20 分钟内完成第一级，之后 40 经验的任务又需要 20 分钟完成第二级。 结果的答案是`40`。 

第五个边缘情况是有许多具有相同值的任务。 和```
4 2 2
1 5 1 1
1 5 1 1
1 5 1 1
1 5 1 1
```升级前必须使用两个任务，升级后必须使用两个任务。 总成本为 (2\cdot5+2\cdot1=12)。 即使对于相同的任务，下降的就地循环也是安全的，因为每个任务都是单独处理的，并且无法转换到在同一迭代期间再次访问的状态。 

最后一个微妙的情况是大量溢出。 和```
2 5 5
8 10 1 1
1 1 5 1
```完成第一个关卡后，第一个任务会贡献 3 点溢出经验。 然后第二个任务又提供 5 个经验，因此第二个级别总共获得 8 个经验。 答案又是`11`。 这证实了溢出必须在限制第二级进度之前添加，而不是在第一级状态达到（s_1）时丢弃。
