 ## 解决方案
 ## 问题理解

 Alice 和 Bob 各自以一个由 (n) 个整数组成的数组开始。 每回合，玩家都会从自己的数组中删除一个值，爱丽丝先移动。 删除操作将持续进行，直到每个数组恰好包含一个值。 如果这些幸存值是 (x) 和 (y)，Alice 希望使 (|x-y|) 尽可能大，而 Bob 希望使其尽可能小。 

输入给出 (n)、Alice 的数组 (a) 和 Bob 的数组 (b)。 我们需要最佳玩法下的 (|x-y|) 值。 

关键的难点是玩家不能从同一个数组中删除。 Alice 永远无法从 (b) 中删除值，而 Bob 永远无法从 (a) 中删除值。 这种独立性看起来很简单，但交替的顺序创造了一种博弈论的互动：鲍勃可以对爱丽丝所做的每一个删除做出反应。 

这里 (n\le 1000)，所以 (O(n^2)) 解决方案最多可以执行大约一百万个成对运算，并且很容易实用。 游戏的指数或阶乘模拟是完全不可能的。 这些值可以达到 (10^9)，因此实现还必须安全地处理差异，尽管 Python 整数没有溢出问题。 

有几种边界情况可能会悄无声息地破坏实现。 如果 (n=1)，则根本没有移动。 例如，```
1
14
42
```有答案（28）。 假设至少删除一次的解决方案将错误地处理这种情况。 

当 (b) 的每个值都位于 (a) 的值的一侧时，就会出现第二个问题。 例如，```
2
10 20
1 2
```对于 (10)，(b) 中最接近的值为 (2)，给出距离 (8)。 对于(20)，又是(2)，给出距离(18)，所以答案是(18)。 当插入位置位于末尾时，仅检查插入位置处的元素的二分搜索实现可能会失败。 

相反的边界也有同样的问题。 为了```
2
1 20
5 15
```最近的距离是（4）和（5），所以答案是（5）。 当搜索(1)时，插入位置是已排序数组的开头，因此前驱不存在。 

重复值是另一个有用的检查。 和```
4
7 7 7 7
7 7 7 7
```答案是（0）。 将相等的值视为单独的游戏选择不会改变该值，并且任何基于排序位置的解决方案仍然必须正确处理重复项。 

## 方法

 每个可能的删除序列都遵循字面上的强力极小极大值。 在玩家的数组中剩余 (k) 个值的状态下，该玩家有 (k) 个可能的删除。 一个数组的完整删除顺序是其 (n) 个元素的排列，因为选择前 (n-1) 个删除的元素唯一地确定了最终的幸存者。 因此，Alice 有 (n!) 个可能的删除历史，Bob 有 (n!) 个可能的删除历史，从而在文字游戏树中给出了 ((n!)^2) 配对的终端历史。 即使 (n=10) 已经给出 (10!^2\approx1.3\times10^{13}) 个终端历史，因此直接极小极大在最大值 (n=1000) 之前很久就无法使用。 

蛮力之所以有效，是因为它明确地考虑了玩家影响最终幸存者的所有可能方式，但它几乎浪费了在删除值的顺序上的所有工作。 实际收益仅取决于两个最终值。 中心观察是，对于每个 Alice 值 (a_i)，我们只需要知道 Bob 可以留下的最接近的值。 

定义

 [
 d_i=\min_j |a_i-b_j|。 
]

 假设 Alice 希望 (a_i) 成为最终值。 她可以简单地保留 (a_i) 并从数组中删除所有其他值。 Bob 希望 (b) 的值尽可能接近 (a_i)。 相关距离恰好是(d_i)。 

剩下的问题是交替删除顺序是否给予 Bob 足够的控制来实现该最小值。 确实如此。 修复对于每个 (a_i)，有一个 Bob 值 (b_{f(i)}) 达到 (d_i)。 Alice 删除一个值后，假设保留 (k) 个 Alice 值。 Bob 此时有 (k+1) 个值。 当前最多需要 (k) 个 Bob 值作为其余 Alice 值的见证人 (b_{f(i)})。 因此，任何剩余的 Alice 值都不需要至少一个 Bob 值，并且 Bob 可以安全地删除该值。 

重复此策略可以让 Bob 为幸存的 Alice 值保留合适的见证人。 因此，Bob 始终可以保证幸存的 (a_i) 的最终距离最多为 (d_i)。 另一方面，Alice 可以选择 (d_i) 最大的 (a_i) 并保持其存活。 因此游戏价值为

 [
 \boxed{\max_i \min_j |a_i-b_j|}。 
]

 这将游戏简化为最近邻问题。 我们可以直接在 (O(n^2)) 中计算它，这对于 (n\le1000) 来说已经足够了。 我们还可以对(b)进行排序，然后通过二分查找找到与每个(a_i)最接近的值，将复杂度降低到(O(n\log n))。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O((n!)^2)) 终端历史 | 指数递归状态 | 太慢了|
 | 成对减少 | (O(n^2)) | (O(n)) | (O(n)) | 已接受 |
 | 最近邻排序| (O(n\log n)) | (O(n)) | (O(n)) | 已接受 |

 下面的实现使用排序 (O(n\log n)) 版本。 相同的博弈论简化也可以通过更简单的 (O(n^2)) 成对扫描来实现。 

## 算法演练

 1. 读取 Alice 的数组 (a) 和 Bob 的数组 (b)，然后按升序对 (b) 进行排序。 排序让我们可以找到与任何 Alice 值最接近的 Bob 值，而无需检查每一对。 
2. 对于每个 Alice 值 (x)，使用二分查找查找 (b) 中至少为 (x) 的第一个值。 呼叫其位置`pos`。 
3.如果`pos`在数组内部，将 (x) 与`b[pos]`。 这是不低于 (x) 的最小 Bob 值，因此在该侧的所有值中，它是唯一可能的最接近候选值。 
4. 如果`pos > 0`，还将 (x) 与`b[pos - 1]`。 这是 (x) 以下最大的 Bob 值，因此它是另一侧唯一可能的最接近的候选者。 
5. 取这些可用距离中较小的一个。 该值是 (\min_j |x-b_j|)，如果 Alice 离开 (x)，Bob 可以强制的最佳距离。 
6. 保持所有最近距离中的最大值 (x\in a)。 Alice可以选择相应的(x)作为她的幸存者，所以这个最大值就是游戏值。 
7. 打印最大距离。 

### 为什么它有效

 让

 [
 T=\max_{x\in A}\min_{y\in B}|x-y|。 
]

 Alice 可以选择达到此最大值的 (x) 并且永远不会删除它。 无论 Bob 是否进行了删除，她的最终值都是 (x)。 

对于 Bob，为每个 Alice 值 (x) 选择一个满足 (|x-f(x)|\le T) 的 Bob 值 (f(x))。 每当 Alice 刚刚进行删除并且她的数组中保留 (k) 个值时，Bob 就剩余 (k+1) 个值。 那些 (k) 个剩余 Alice 值的见证人 (f(x)) 最多使用 (k) 个不同的 Bob 值，因此至少一个 Bob 值不是任何剩余 Alice 值的见证人。 Bob 删除了这样一个不必要的值。 这为未来每一个可能的爱丽丝幸存者保留了有效的证人。 

最后，如果 Alice 离开 (x)，Bob 仍然有一个见证人 (f(x))，距离最大为 (T)。 因此，Bob 保证结果不大于 (T)，而 Alice 保证结果不小于 (T)。 游戏价值正是（T）。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    b.sort()

    answer = 0

    for x in a:
        pos = bisect_left(b, x)
        best = 10**30

        if pos < n:
            best = min(best, abs(x - b[pos]))

        if pos > 0:
            best = min(best, abs(x - b[pos - 1]))

        answer = max(answer, best)

    print(answer)

if __name__ == "__main__":
    solve()
```每个数组的输入只读取一次，然后对 Bob 的数组进行排序。 这`bisect_left`call 查找值至少为当前 Alice 值的第一个位置。 

只需要检查两名候选人。 如果`pos < n`,`b[pos]`是右侧最接近的候选者。 如果`pos > 0`,`b[pos - 1]`是左边最接近的候选者。 没有其他元素可以更接近，因为数组已排序。 

这两个边界检查是故意独立的。 什么时候`pos == 0`，没有前任。 什么时候`pos == n`，右边没有元素。 显式处理这两种情况可以避免在数组外部进行索引。`best`起始值远大于任何可能的答案。 由于所有输入值最多为 (10^9)，因此每个绝对差最多为 (10^9-1)。 Python 整数也使得溢出变得无关紧要。 

最后，`answer`取最大最近邻距离，匹配上面证明的 (\max_i\min_j) 表达式。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n\log n)) | 排序 (b) 成本 (O(n\log n))，然后 (n) 二分搜索成本另一个 (O(n\log n)) |
 | 空间| (O(n)) | (O(n)) | (b) 的数组和排序副本需要线性空间 |

 对于 (n\le1000)，即使是更简单的 (O(n^2)) 实现也只能执行大约 (10^6) 距离检查。 所提出的 (O(n\log n)) 解决方案完全在 1 秒和 256 MB 的限制内。

 ## 边缘情况

 (n=1)的情况不需要游戏模拟。 为了```
1
14
42
```唯一幸存的值已经是 (14) 和 (42)。`bisect_left([42], 14)`回报`0`，因此仅检查正确的候选者，并且最近的距离为 (28)。 一个 Alice 值的最大值也是 (28)。 

当插入位置在开头时，前驱不存在。 为了```
2
1 20
5 15
```搜索 (1) 返回位置`0`，给出距离 (4) 到`5`。 搜索 (20) 返回位置`2`，所以没有合适的候选人，只有`15`检查，给出距离 (5)。 最终答案为（5）。 这两个值作用于排序数组的两端。 

当每个Bob值都小于Alice值时，插入位置总是`n`。 为了```
2
10 20
1 2
```距离 (10) 最接近的 Bob 值是 (2)，距离 (8)，而距离 (20) 最接近的值也是 (2)，距离 (18)。 答案是（18）。 这`pos < n`检查防止无效访问`b[n]`。 

重复的价值观不会创造额外的战略力量。 和```
4
7 7 7 7
7 7 7 7
```每个 Alice 值在距离 (0) 处都有一个 Bob 值。 每次迭代计算的最近距离为 (0)，因此答案为 (0)。 这也说明了为什么争论是关于值及其最近距离，而不是关于唯一索引。 

最大值的情况也是安全的。 如果 Alice 仅包含 (10^9) 而 Bob 仅包含 (1)，则所得差值为 (999999999)。 该算法直接计算此值而不会溢出，并且结果保持在 Python 的整数范围内。
