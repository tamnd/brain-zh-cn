 ## 解决方案
 ## 问题理解

 我们得到一个包含以下内容的字符串`'0'`,`'1'`， 和`'?'`。 

如果我们可以替换每个子串，则该子串被认为是美丽的`'?'`独立地与任一`0`或者`1`使得生成的子字符串成为交替的二进制字符串。 换句话说，相邻的字符必须始终不同。 

任务是计算有多少连续子串具有此属性。 

所有测试用例的总长度最多为`2·10^5`。 这立即排除了任何二次方。 检查每个子字符串的解决方案大约需要`n²/2`子串，大约是`2·10^10`什么时候`n = 2·10^5`。 即使在恒定时间内检查每个子字符串也太慢了。 每个测试用例我们需要一个线性或近线性算法。 

一些边缘情况使问题比最初出现时更加棘手。 

考虑：```
???
```每个子字符串都很漂亮，因为我们可以根据需要分配交替值。 答案是：```
6
```尝试致力于一项特定任务的解决方案`?`字符可能会错误地拒绝有效的子字符串。 

考虑：```
00
```子串`"00"`是不可能交替的。 答案是：```
2
```只有两个长度为 1 的子字符串有效。 

考虑：```
0?0
```整个子串很漂亮，因为中间的字符可以变成`1`，生产`010`。 

仅比较相邻固定字符的本地检查将错过这种可能性。 

考虑：```
?1??1
```整根弦并不美观。 如果位置奇偶性迫使两者都固定`1`如果需要矛盾的分配，则不存在替代。 任何正确的解决方案都必须检测由相距较远的固定字符产生的冲突。 

## 方法

 蛮力的想法很简单。 枚举每个子字符串，然后检查该子字符串是否可以转换为交替字符串。 

子字符串只能匹配两种交替模式之一：```
010101...
```或者```
101010...
```对于每个子字符串，我们可以测试这两种模式，并查看每个固定字符是否与其中至少一个兼容。 

这种方法是正确的，因为当两个交替模式之一适合所有固定位置时，子串就很漂亮。 

问题是子串的数量。 一个长度的字符串`n`有`n(n+1)/2`子串。 和`n = 2·10^5`，大约有 200 亿个子串。 即使对每个子字符串进行 O(1) 检查也是不可能的。 

关键的观察结果是交替字符串强加了奇偶校验规则。 

假设一个子字符串从位置开始`L`。 

如果我们决定那个位置`L`应该是`0`，那么每个位置的奇偶性与`L`也必须是`0`，并且每个具有相反奇偶性的位置必须是`1`。 

如果我们决定那个位置`L`应该是`1`，角色互换。 

当固定字符迫使两种可能性都失败时，就会发生冲突。 

我们不是独立检查每个子字符串，而是从左到右处理字符串并维护以当前位置结尾的最长有效后缀。 

一个有用的技巧是重新解释每个固定字符。 

对于职位`i`:```
expected value = i mod 2
```对应于一种交替模式，而```
expected value = 1 - (i mod 2)
```与另一个相对应。 

每当一个固定角色不同意一种模式时，它就会支持另一种模式。 我们跟踪打破每种模式的最新位置。 

然后，对于每个结束位置`r`，我们可以立即确定有效子字符串可以从左边多远开始。 

这将问题转化为线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n2) 到 O(n3) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从左到右处理字符串。 
2. 维持两个价值观：`last0`= 形成该形态的最新位置`010101...`不可能的。`last1`= 形成该形态的最新位置`101010...`不可能的。 
3.就位`i`， 如果`s[i]`是`'?'`，它永远不会产生冲突，因此两个值都不会改变。 
4. 如果`s[i]`是`'0'`，将其与两种交替模式下的预期字符进行比较。 

如果图案`010101...`期望`1`在这里，然后这个位置打破了这个模式，所以更新`last0 = i`。 

同样更新`last1`如果第二个模式被打破。 
5.如果`s[i]`是`'1'`，执行相同的逻辑。 
6.让```
bad = min(last0, last1)
```任何结尾为的子串`i`并开始于或之前`bad`两种交替模式均失败。 
7. 因此每个起始位置```
bad + 1 ... i
```形成一个美丽的子串，结尾为`i`。 

此类子串的数量为：```
i - bad
```8. 将此数量添加到答案中。 

### 为什么它有效

 对于每个位置，我们都会记住每种交替模式变得不可能的最新位置。 

结束于的子字符串`i`如果在整个子串中至少有一个交替模式仍然可行，那么它就是美丽的。 

如果子字符串开始于或之前`last0`，然后图案`010101...`子串内部已经矛盾了。 

同样，开始于或之前`last1`使模式无效`101010...`。 

仅当两种模式都无效时，子字符串才会失败。 这恰好发生在它的起始位置最多为```
min(last0, last1).
```所有后来的起始位置都至少保留一种图案，因此它们很漂亮。 对每个结束位置的这些开头进行计数，就等于对每个美丽的子字符串进行了一次计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        s = input().strip()
        
        last0 = -1
        last1 = -1
        ans = 0
        
        for i, ch in enumerate(s):
            if ch != '?':
                bit = int(ch)
                
                if bit != (i & 1):
                    last0 = i
                
                if bit != (1 ^ (i & 1)):
                    last1 = i
            
            ans += i - min(last0, last1)
        
        print(ans)

solve()
```变量`last0`和`last1`存储两种可能的交替模式的最新矛盾。 

表达式```
(i & 1)
```是模式所期望的字符```
010101...
```当从零开始索引时。 

表达式```
1 ^ (i & 1)
```是模式所期望的字符```
101010...
```在同一位置。 

每当固定字符与模式不一致时，该模式对于包含该位置的任何子字符串来说都变得不可能。 更新对应的`last`变量记录了这个事实。 

数量```
i - min(last0, last1)
```计算以以下结尾的子字符串的所有有效起始位置`i`。 

答案可能大约有`n(n+1)/2`，这大约是`2·10^10`，因此它必须存储在 64 位整数中。 Python 整数会自动处理这个问题。

## 测试用例```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        last0 = -1
        last1 = -1
        ans = 0

        for i, ch in enumerate(s):
            if ch != '?':
                bit = int(ch)

                if bit != (i & 1):
                    last0 = i

                if bit != (1 ^ (i & 1)):
                    last1 = i

            ans += i - min(last0, last1)

        out.append(str(ans))

    return "\n".join(out)

# alternating already

# off-by-one boundary
assert run("1\n00\n") == "2"

 ## 边缘情况

 考虑：```
???
```每个子字符串都可以补全为交替字符串。 扫描期间也不`last0`也不`last1`变化自`-1`。 补充内容是`1`,`2`， 和`3`，生产`6`。 该算法自然会计算所有子字符串。 

考虑：```
00
```在第二个位置，两个固定零对任何长度为 2 的子串产生了矛盾。 该算法更新冲突位置并仅计算两个单字符子字符串，给出`2`。 

考虑：```
0?0
```中间的角色保持灵活。 该算法永远不会记录阻塞整个字符串的冲突，因为将中间位置分配给`1`产量`010`。 答案就变成了`6`，意味着每个子串都是美丽的。 

考虑：```
?1??1
```这两个固定模式最终会使较大范围内的交替模式之一失效。 这`last0`和`last1`更新准确地捕捉了矛盾出现的地方。 仍然保留至少一种模式的子字符串仍然被计算在内，而不可能的子字符串将被自动排除。
