 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且可以按照我们喜欢的方式排列它。 选择排序后，一对位置$(i,j)$和$i<j$被称为好的，如果$$\gcd(a_i, 2a_j) > 1.$$任务是最大化好对的数量。 

输入包含多个测试用例。 对于每个测试用例，我们收到一个数组，并且必须在重新排序后输出最大可能数量的好对。 

最重要的约束是所有数组的总大小。 尽管可能有多达 1000 个测试用例，但所有测试用例的总和$n$值最多为 2000。这完全改变了复杂性。 一个$O(n^2)$算法是完全安全的，因为$$2000^2 = 4 \cdot 10^6,$$对于 2 秒的限制来说，这个时间太小了。 不需要先进的数论或复杂的数据结构。 

一个微妙的点是，该条件涉及$2a_j$， 不是$a_j$。 This makes every even number extremely valuable. 例如：

 输入：```
1
2
2 3
```如果我们将数组放置为$[2,3]$， 然后$$\gcd(2, 2\cdot3)=\gcd(2,6)=2,$$所以这对很好。 

粗心的解决方案检查$\gcd(a_i,a_j)$相反会错误地得出结论$$\gcd(2,3)=1.$$另一个容易犯的错误是假设只有偶数对才重要。 

输入：```
1
3
2 3 5
```将其订购为$[2,3,5]$给出$$\gcd(2,6)=2,\qquad \gcd(2,10)=2.$$涉及前导偶数的两对都很好。 

当所有数字都是奇数时，就会出现最后的边缘情况。 

输入：```
1
3
1 3 5
```没有重新排序会创建偶数的第一个元素。 答案完全来自直接检查奇数之间的 gcd 条件。 

## 方法

 蛮力的想法很简单。 生成每个可能的排列，计算有多少对满足条件，并保留最大值。 

这是有效的，因为好对的定义很容易评估。 不幸的是，排列的数量是$n!$。 即使是为了$n=15$，这已经是巨大的了。 自从$n$能达到2000，这种做法是完全不可能的。 

关键的观察来自于对条件的观察$$\gcd(a_i,2a_j)>1.$$认为$a_i$是均匀的。 然后$2a_j$也是偶数，所以两个数都可以被整除$2$。 所以$$\gcd(a_i,2a_j)\ge 2.$$这意味着第一个元素为偶数的每对都自动是好的。 

这表明了一种贪婪的策略。 我们希望尽可能多的索引在奇数之前包含偶数。 如果所有偶数都移到前面，那么第一个元素是这些偶数之一的每一对都会自动变好。 

将所有偶数放在第一位后，剩下的对就是奇数对。 对于这些对，我们直接测试 gcd 条件。 

一旦数组以这种方式重新排序，计算答案就很容易了。 我们检查每一对$(i,j)$并数出那些满意的$$\gcd(a_i,2a_j)>1.$$自从$n\le 2000$， 一个$O(n^2)$配对扫描是完全可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n!\cdot n^2)$|$O(n)$| 太慢了|
 | 贪心重排序 + 配对检查 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将数组分为偶数和奇数。 
2. 通过首先放置所有偶数、然后放置所有奇数来构建新的排序。 
3. 将答案初始化为零。 
4. 对于每对索引$(i,j)$和$i<j$, 计算$$\gcd(a_i,2a_j).$$1.如果gcd大于$1$，增加答案。 
2. 输出最终计数。 

步骤 2 是最佳的原因是，前面放置的每个偶数都会与后面的每个元素自动创建良好的配对。 将偶数移到前面只会增加此类对的数量，而不会减少它们。 

### 为什么它有效

 考虑任何偶数值$x$。 对于每个后来的值$y$,$$\gcd(x,2y)\ge 2.$$因此，第一个元素为偶数的每一对都保证是好的。 

为了最大化保证的好对的数量，每个偶数应该出现在每个奇数之前。 任何在偶数之前留下奇数的排序都会浪费潜在的自动好对。 将所有偶数移到前面后，保证好的对的数量最大化。 

在剩余的奇奇对中，不存在进一步的结构简化。 我们必须直接评估 gcd 条件。 因此，所描述的排序后直接计数会产生最大可能的答案。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    even = []
    odd = []

    for x in a:
        if x % 2 == 0:
            even.append(x)
        else:
            odd.append(x)

    a = even + odd

    ans = 0

    for i in range(n):
        for j in range(i + 1, n):
            if gcd(a[i], 2 * a[j]) > 1:
                ans += 1

    print(ans)
```第一部分区分偶数和奇数。 这实现了贪婪排序。 偶数组内和奇数组内的相对顺序并不重要。 

构建重新排序的数组后，嵌套循环会检查每对数组一次。 使用 Python 的内置函数逐字检查语句中的条件`gcd`。 

不存在溢出问题，因为$$a_i \le 10^5,$$所以$$2a_j \le 2\cdot 10^5.$$嵌套循环在所有测试用例中最多运行约 200 万对检查，这很容易满足限制。

## 测试用例```python
import sys
import io
from math import gcd

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even = [x for x in a if x % 2 == 0]
        odd = [x for x in a if x % 2 == 1]
        a = even + odd

        ans = 0
        for i in range(n):
            for j in range(i + 1, n):
                if gcd(a[i], 2 * a[j]) > 1:
                    ans += 1

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

assert run("3\n4\n3 6 5 3\n2\n1 7\n5\n1 4 2 4 1\n") == "4\n0\n9", "sample"

assert run("1\n2\n2 4\n") == "1", "all even"
assert run("1\n2\n1 1\n") == "0", "all odd"
assert run("1\n3\n2 3 5\n") == "2", "single even in front"
assert run("1\n4\n2 2 2 2\n") == "6", "all pairs good"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`2 4`|`1`| 最小的非平凡全偶情况 |
 |`1 1`|`0`| Gcd 永远不会超过 1 |
 |`2 3 5`|`2`| 偶优先贪婪效应 |
 |`2 2 2 2`|`6`| 每双都变得很好|

 ## 边缘情况

 考虑一个完全由偶数组成的数组：```
1
4
2 4 6 8
```每对都满足条件，因为每对的第一个元素是偶数。 该算法将所有数字放在前面，然后进行计数$$\binom{4}{2}=6$$好对。 

考虑一个完全由奇数组成的数组：```
1
3
1 3 5
```重新排序后的数组没有变化。 该算法直接检查每一对：$$\gcd(1,6)=1,\quad \gcd(1,10)=1,\quad \gcd(3,10)=1.$$答案是0。 

考虑只有一个偶数的混合物：```
1
3
3 2 5
```该算法重新排序为```
2 3 5
```这些对是$$(2,3),\ (2,5),\ (3,5).$$前两个很好，因为主导元素是偶数。 最后一个不是。 答案是2，这是最大的。
