 ## 解决方案
 ## 问题理解

 我们得到了代表针织围巾的部分构建序列。 每个位置都是一种颜色，并且围巾的某些前缀已经固定。 我们的任务是将这个前缀扩展成一个完整的长度序列`n`使用颜色来自`1`到`k`，同时遵守间距约束：如果某种颜色出现在某个位置，则它不得在下一个位置再次出现`p - 1`职位。 

同时，在所有有效补全中，我们希望保持任何单一颜色的最大频率尽可能小。 换句话说，我们在防止最近重复的硬约束下尽可能均匀地平衡颜色的使用。 

输入给出目标长度`n`, 颜色数量`k`、间距要求`p`，已经构造的前缀长度`m`，以及固定的第一个`m`颜色。 我们必须将此前缀扩展为完整的有效序列或报告不存在完成。 

约束条件允许`n, k, p`最多 100000，这排除了任何二次构造或重复的序列完整重新扫描。 任何试图通过回扫来检查每个展示位置有效性的方法`p`在最坏的情况下，位置会天真地变得太慢，因为它会降级为 O(n·p)。 我们需要每个位置的恒定或对数工作量。 

一些边缘情况打破了天真的贪婪尝试：

 如果`p = 1`，没有任何限制，因此任何完成都是有效的，平衡频率变得纯粹与分布有关。 

如果`k = 1`和`p > 1`，那么任何长度超过 1 的序列都是不可能的，因为唯一的颜色会立即违反间距。 例子：`n = 5, k = 1, p = 2`和前缀`[1]`强制在距离1内重复，因此不可能输出。 

如果前缀已经在内部违反了约束，我们必须立即拒绝它。 例子：`p = 3`, 前缀`[1, 2, 1]`已经无效了。 

最后，当贪婪扩展选择本地有效颜色但后来由于间距限制而阻止所有选项时，会发生微妙的失败情况。 当我们不考虑每种颜色未来展示位置的可用性时，就会发生这种情况。 

## 方法

 一个蛮力的想法是逐个位置构造序列。 每一步，我们都会尝试每一种颜色`1..k`，通过扫描前一个来检查是否违反了间距约束`p-1`位置，并暂定分配。 这是正确的，因为它直接强制执行约束，但每个位置的成本为 O(k·p)，导致 O(n·k·p)，这对于 100000 规模的输入来说太大了。 

即使我们使用最后看到的数组优化有效性检查，使每次检查变为 O(1)，我们仍然需要一个策略来决定在每一步选择哪种有效颜色。 选择当前频率最小的颜色的天真贪婪方法可能会失败，因为它可能会过早分配颜色，并由于间距间隙而使其稍后不可用。 

关键的观察结果是间距约束是局部的并且仅取决于最后一个`p - 1`位置，而平衡目标仅取决于全局计数。 这种分离使我们能够维护两种结构：一种用于跟踪最近的使用情况（以加强可行性），另一种用于跟踪频率（以平衡分布）。 在每一步中，我们应该选择当前允许的并且在允许的候选者中频率最小的颜色。 

支持这一点的有效方法是为每种颜色维护其最后出现的索引，并维护频率数组。 我们还保留了一种结构，可以在当前有效的颜色中快速检索频率最小的颜色。 自从`k`可能很大，我们用优先级队列来模拟它，该队列存储按顺序排序的候选者`(frequency, color)`，当无效条目违反间距时，我们会懒惰地丢弃它们。 

这将每个放置减少到摊销 O(log k)，因为每种颜色被推送和弹出的次数是有限的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·k·p) | O(n) | 太慢了 |
 | 最佳| O(n log k) | O(n log k) | O(k) | 已接受 |

 ## 算法演练

 我们将序列构造视为从左到右的流式处理，始终尊重前缀。 

1.初始化一个数组`last[c] = -inf`对于每种颜色`c`，并设置频率`freq[c] = 0`。 我们还首先处理给定的前缀，更新两个数组并验证不存在间距违规。 如果发现违规行为，我们会立即停止。 
2. 构建包含所有颜色的优先级队列。 各入口店`(freq[c], c)`。 堆将始终建议最少使用的颜色。 
3. 从位置开始迭代`m+1`到`n`，并且在每个位置，我们需要选择一个有效的颜色。 
4. 反复从堆中弹出，直到找到一种颜色`c`这样`i - last[c] >= p`。 此条件确保颜色不会在最后使用`p - 1`职位。 如果不存在这种颜色，我们就断定施工是不可能的。 
5. 找到有效颜色后，将其分配给位置`i`， 更新`last[c] = i`, 增量`freq[c]`，并将更新后的对推回堆中。 
6. 继续，直到所有位置都被填满。 

关键思想是堆总是试图保持频率平衡，而过滤步骤则增强了可行性。 

### 为什么它有效

 在任何一步`i`，在间距约束允许的所有颜色中，我们总是选择频率最小的一种。 任何其他选择要么保持最大频率不变，要么提前增加它，这只会让以后的平衡变得更加困难。 间距约束仅限制资格，而不限制合格颜色之间的排序，因此按有效候选者之间的频率排序可以保持正确性。 

不变的是在放置位置之前`i`，部分序列满足间距约束，并且堆包含具有正确频率的所有颜色。 每个赋值都保留这两个属性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, k, p = map(int, input().split())
    m = int(input())
    s = list(map(int, input().split()))

    last = [-10**18] * (k + 1)
    freq = [0] * (k + 1)

    # validate prefix
    for i, c in enumerate(s, start=1):
        if i - last[c] < p:
            print("impossible")
            return
        last[c] = i
        freq[c] += 1

    heap = []
    for c in range(1, k + 1):
        heapq.heappush(heap, (freq[c], c))

    def push(c):
        heapq.heappush(heap, (freq[c], c))

    for i in range(m + 1, n + 1):
        while heap:
            f, c = heapq.heappop(heap)
            if f != freq[c]:
                continue
            if i - last[c] >= p:
                break
        else:
            print("impossible")
            return

        s.append(c)
        last[c] = i
        freq[c] += 1
        push(c)

    print(*s)

if __name__ == "__main__":
    solve()
```解决方案首先验证给定的前缀。 此步骤至关重要，因为无论未来如何选择，任何早期无效的间距都会导致整个完成变得不可能。 

堆存储按当前频率排序的所有颜色。 我们使用惰性删除：过时的条目保留在堆中，但在弹出时被忽略。 这避免了昂贵的减少密钥操作。 

在构建过程中，我们反复提取最不常见的颜色，并使用以下方法检查它是否遵守间距约束：`last[c]`。 如果没有，我们将在本次迭代中丢弃它并继续。 

一个微妙的问题是即使频率发生变化，使用堆的正确性也是如此。 这`(f, c)`对可能会过时； 这就是我们比较的原因`f != freq[c]`在使用它之前。

 ## 边缘情况

 已经违反间距的前缀将被立即拒绝。 例如，与`p = 3`， 输入`[1, 2, 1]`失败，因为第二个`1`相对于第一次来说发生得太早了。 该算法在前缀预处理期间检测到这一点`i - last[c] < p`。 

单色系统`p > 1`超过长度 1 就变得不可能。该算法最终将耗尽堆，因为该颜色的每次弹出都无法通过间距检查，并且不存在替代方案。 

什么时候`p = 1`，每种颜色始终有效。 堆只是平衡频率，并且间距检查永远不会阻止任何候选者，因此该算法退化为纯粹的负载平衡。
