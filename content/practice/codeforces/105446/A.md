 ## 解决方案
 ## 问题理解

 给定两个由小写英文字母组成的字符串，我们想要构造第三个字符串，在字母重数方面“覆盖”这两个字符串。 具体来说，如果某个字母在第一个单词中出现 5 次，在第二个单词中出现 2 次，则生成的字符串必须至少包含该字母 5 次出现，因为我们必须能够使用相同的多组字符同时表示这两个单词。 

目标是产生这样一个长度尽可能最小的字符串。 由于字符的顺序与正确性无关，因此结果多重集的任何排列都是可接受的。 

输入大小可以达到每个字符串一百万个字符，这会立即排除任何二次行为，例如重复字符串串联、基于排序的完全扩展合并，或任何每个字符串中的每个字符扫描一个字符串一次的方法。 唯一可行的方向是对字母表进行线性时间计数。 

如果人们考虑合并序列而不是多重集，就会出现一个微妙的问题。 例如，两个单词可能根本不共享字母，而尝试“交错”它们的幼稚方法会错误地尝试保留结构，而不是认识到我们只关心每个字符的最大频率。 

第二种边缘情况是两个单词相同。 在这种情况下，答案是完全相同的单词，并且任何盲目连接两个输入的算法都会不必要地使长度加倍。 

最后，排序是无关紧要的，但正确性完全取决于每个字符的频率比较，因此任何在处理过程中丢失计数信息的方法都会失败。 

## 方法

 一种强力解释是生成组合多重集的所有排列，然后检查哪些排列满足包含两个单词作为子多重集的条件，选择最短的有效排列。 即使我们避免排列并考虑逐步构建候选，任何对排列的搜索都会随着字母数量的增加而增加，即使对于很小的输入也是完全不可行的。 

一个稍微结构化的暴力想法是尝试通过重复添加字符并检查当前多重集是否主导两个输入多重集来构建结果。 问题是每次有效性检查都需要扫描频率表，如果对每个候选扩展进行扫描，总成本将与生成的候选数乘以 26 次比较成正比。 即使将我们限制在最终长度 N，这种增量构造仍然隐藏了排序选择上的指数搜索空间，这是不必要的，因为排序永远不会影响可行性。 

关键的观察结果是，问题不在于排列字符，而在于满足 26 维频率空间中的坐标最大约束。 每个单词都定义了字母表中的计数向量，而最小有效的混合图就是这两个向量的逐点最大值。 一旦看到这一点，问题就减少到对每个字符串计算一次字符，然后发出每个字符所需的数量。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(1) 到 O(n) | 太慢了|
 | 最佳 | O(n + 26) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个字符串视为 26 个小写字母的频率图。 

1. 构建数组`fa`大小为 26，并计算第一个字符串中每个字符的出现次数。 这准确地捕获了第一个单词需要每个字母的次数。 
2. 构建第二个数组`fb`以同样的方式处理第二个字符串。 这独立地隔离了第二个词的要求。 
3.构建结果频率数组`fc`其中每个字母索引`i`，我们设置`fc[i] = max(fa[i], fb[i])`。 此步骤强制要求两个单词都可以从结果多重集中形成，因为每个字母在任一单词中至少出现所需的频率。 
4. 迭代所有 26 个字母并附加每个字符`i`重复`fc[i]`次到输出字符串。 发射的顺序并不重要，因为仅检查多重性的正确性。 
5. 打印结果字符串。 

唯一微妙的一点是我们从不尝试保留输入顺序。 该问题不需要子序列或嵌入，只需要多重集包含，因此最终多重集的任何排列都是有效的。 

### 为什么它有效

 每个输入单词定义一个约束：对于每个字母，结果必须至少有那么多副本。 这些约束在字母之间是独立的，因此可行集是 26 个简单下界的交集。 满足所有约束的最小字符串是通过尽可能紧密地获取每个边界来实现的，这正是两个频率向量的坐标最大值。 所选计数的任何减少都会违反这两个词中的至少一个，因此构造是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()

    fa = [0] * 26
    fb = [0] * 26

    for ch in a:
        fa[ord(ch) - 97] += 1
    for ch in b:
        fb[ord(ch) - 97] += 1

    res = []
    for i in range(26):
        cnt = fa[i] if fa[i] > fb[i] else fb[i]
        if cnt:
            res.append(chr(i + 97) * cnt)

    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案将输入解析与计数分开，以便每个字符串只扫描一次。 使用固定大小的数组可以避免字典开销，并使操作与输入大小保持严格线性关系。 

构造阶段仅迭代超过 26 个字母，与输入长度相比可以忽略不计，并且在最后完成一次连接以避免重复的字符串重建。

 ## 边缘情况

 一种重要的边缘情况是两个字符串相同。 对于像这样的输入`aaaaa`和`aaaaa`，两个频率数组是相同的，因此最大运算保留相同的计数，并且输出是完全相同的多重集，而不是加倍。 该算法自然地避免了重复，因为它从不对计数求和，仅对它们进行比较。 

另一种情况是完全不相交的字母表，例如`abc`和`xyz`。 频率阵列从不重叠，因此最大值只是连接独立的贡献。 输出包含所有六个字母一次，这是最小的，因为不可能减少。 

第三种情况涉及偏态频率分布，例如`aaaaab`和`abbbb`。 这里，最多正确保留五个`a`人物和四个`b`字符，避免计数不足和不必要的重复，因为频率向量中的每个位置都是独立处理的。
