 ## 解决方案
 ## 问题理解

 该任务描述了一个重复的训练计划，该计划根据文本提示将每天分为三类之一：以腿部为重点的训练日、以手臂为重点的训练日和休息日。 每个输入字符串都是一个练习名称，我们必须使用提供的列表将 31 天的月份中的每一天映射到这些类别之一。 

映射规则纯粹基于字符串。 如果练习名称包含子字符串`"rest"`，它被视为休息日。 如果不包含`"rest"`但包含`"leg"`，它变成了腿部日。 否则，如果它既不包含`"rest"`也不`"leg"`，这是一个手臂日。 一旦对每个练习名称进行分类，我们就会在概念上重复所产生的日期类型循环，直到填满所有 31 个日历日。 

输出不是数字而是视觉。 我们必须打印一个 5 周的日历，每周最多包含 7 天，从星期一开始。 每一天都由一个固定的象形文字来表示，该象形文字被选择来代表其类别。 在整个输出中，相同的字符必须始终代表相同的类别。 

尽管该声明谈到了 Unicode 象形文字和选择的灵活性，但正确性约束是结构性的。 仅当保持一致性时，输出才有效：相同的类别必须始终映射到相同的选定字形，并且该字形必须通过其 Unicode 名称匹配所需的语义条件。 

约束 n ≤ 31 意味着周期长度足够小，即使简单的每日处理也是微不足道的。 任何尝试显式模拟日历或重复重新计算字符串分类的解决方案仍然足够快。 真正的困难不是性能，而是执行稳定的类别到符号映射并正确布局覆盖 31 天的固定 5×7 网格。 

一个微妙的边缘情况来自于骑自行车如何与周边界相互作用。 由于 31 天与 7 天周不一致，因此最后一周部分是空的。 另一个问题是分类是基于子串的，因此重叠的子串就像`"leg"`出现在里面`"elegant"`仍然会触发腿部日，如果过于字面解释，这可能会不直观。 

潜在陷阱的示例：

 输入：```
1
elegant
```正确分类：腿日、自`"leg"`是一个子串。 

天真的解释可能会认为这与训练无关，但子串匹配迫使它进入腿部类别。 

另一个边缘情况：

 输入：```
1
restlegarm
```这应该是休息日，因为`"rest"`在分类优先级中出现在第一位。 粗心的实施检查`"leg"`首先会错误地将其归类为腿部日。 

## 方法

 强力解释将明确模拟 31 天的日历。 对于从 1 到 31 的每一天，我们将在循环中进行相应的练习（索引模 n），通过扫描子字符串对其进行分类，动态分配象形文字，并将其存储在 2D 网格中。 这是简单且正确的，但它重复地重新计算分类和映射逻辑。 

暴力破解的成本实际上是循环的 O(31 × n) 加上子字符串检查的 O(31 × s)，其中 s 是最大字符串长度。 由于 n ≤ 31 且 s ≤ 50，因此可以忽略不计。 然而，如果推广，这种方法会做多余的工作：重新计算分类和映射而不是重新使用。 

关键的观察是只存在三个稳定的类别。 一旦我们为每个类别分配了一个符号，我们就不需要再次重新计算分类。 我们可以将输入预处理为 31 长度的类别模式，然后直接渲染日历。 

这将问题简化为两个阶段：分类和格式化。 分类与输入大小呈线性关系，格式设置为恒定大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(31 × n × s) | O(31 × n × s) | O(31) | 已接受 |
 | 预计算+直接映射| O(n × s) | O(31) | 已接受 |

 ## 算法演练

 1. 读取所有练习名称，并使用子字符串检查将每个练习分为三个类别之一。 

分类规则必须优先`"rest"`高于一切，因为像这样的字符串`"restleg"`不应该一不小心就变成腿日了。 
2. 将生成的 31 天周期存储为列表。 如果 n < 31，则循环重复该列表，直到达到 31 个条目。 

这确保了无论输入大小如何，我们始终都能填满整个月。 
3. 为每个类别指定固定符号。 例如，我们可以将rest映射到 ，leg 映射到 ，arm 映射到 。 

这些映射必须在整个输出中保持不变； 在日历中期更改它们会违反一致性。 
4. 构建一个 5×7 的网格（总共 35 个位置），但仅将前 31 个位置填充为实际天数。 

其余单元格留空。 
5. 逐行填充网格，对应于周，并打印每周及其索引。 

为什么它有效

 该算法依赖于这样一个事实：日期分类与日历中的位置无关。 每一天仅由其相应的练习串决定，并且重复引入了固定的周期序列。 一旦知道了这个顺序，渲染就变成了一个确定性的布局问题。 因为未来的决定不依赖于之前的放置，所以贪婪地放置到日历槽中不会使正确性失效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def classify(s: str) -> str:
    # priority: rest > leg > arm
    if "rest" in s:
        return "rest"
    if "leg" in s:
        return "leg"
    return "arm"

def main():
    n = int(input().strip())
    arr = [input().strip() for _ in range(n)]

    # build 31-day cycle
    cycle = []
    for i in range(31):
        cycle.append(classify(arr[i % n]))

    # fixed mapping
    symbol = {
        "rest": "😴",
        "leg": "🦵",
        "arm": "💪"
    }

    # print 5 weeks of up to 7 days
    idx = 0
    for week in range(1, 6):
        line = [str(week)]
        for _ in range(7):
            if idx < 31:
                line.append(symbol[cycle[idx]])
            idx += 1
        print(" ".join(line))

if __name__ == "__main__":
    main()
```分类函数直接对优先级规则进行编码。 检查`"rest"`first 是必不可少的，因为它会覆盖任何其他子字符串匹配。 周期构造使用模块化索引来重复输入列表，直到恰好生成 31 天。 

渲染逻辑维护单个指针`idx`跨越数周。 这避免了重新计算行列坐标并确保我们按顺序消耗正好 31 个条目。 一次`idx`超过31个，剩余槽位被忽略，自然形成了上周的不完整。

 ## 边缘情况

 一个关键的边缘情况是子串重叠，其中`"rest"`出现在一个较长的单词内，该单词还包含`"leg"`。 例如：

 输入：```
1
restlegarm
```分类检查`"rest"`首先，所以结果是休息。 这个周期完全变成休息日，并且日历打印出统一的网格。 一个简单的实现来检查`"leg"`首先会错误地分配腿部日并进行生产。 

另一个边缘情况是不相关单词内的隐式匹配：

 输入：```
1
elegant
```尽管语义上无关，`"leg"`出现在字符串中，所以它必须被分类为leg。 该算法仍然正确地分配并相应地填充整个日历，这表明分类纯粹取决于子串逻辑而不是含义。
