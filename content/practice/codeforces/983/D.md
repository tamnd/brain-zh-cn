 ## 解决方案

 ## 问题理解

 我们得到一个一开始完全白色的平面，这意味着每个点最初的颜色都是 0。然后我们依次放置最多 100,000 个轴对齐的矩形。 每个矩形都涂有与输入顺序中的索引相同的唯一颜色，并且它会覆盖任何重叠的先前颜色。 

最终的对象是一个分层的绘画过程，其中后面的矩形可以完全隐藏前面的矩形，部分显示它们，或者保持它们不变。 绘制完所有矩形后，我们需要计算有多少种不同的颜色在平面上的任何位置仍然可见，包括背景色 0。 

关键的困难在于每个矩形可能通过重叠与所有先前的矩形相互作用，并且平面是连续的，坐标的大小最多为 10^9。 这立即排除了任何网格模拟。 

这些约束意味着我们无法离散整个平面。 对所有整数点进行简单的坐标压缩是不可能的，因为矩形是在连续区域而不是离散单元上定义的。 任何解决方案都必须根据几何区域而不是像素来工作。 

一些边缘案例揭示了朴素方法失败的原因：

 完全覆盖所有先前矩形的单个矩形可能会完全消除许多颜色。 例如，如果矩形 1 很大，并且矩形 2 完全覆盖它，则颜色 1 完全消失。 如果不跟踪完整覆盖范围，天真的每个矩形区域更新可能仍然会错误地计算它。 

当矩形嵌套时，会出现另一种故障模式。 如果每个新矩形完全包含所有先前的矩形，则仅保留最后一个颜色和颜色 0。 任何假设部分重叠独立贡献的方法都会多算。 

最后，细条子很重要。 矩形只能沿着边界线与先前的矩形相交，即使重叠的测量为零，它也不会贡献新的可见颜色。 任何将边界相交视为区域的方法都可能破坏正确性。 

## 方法

 一个蛮力的想法是在精细网格上模拟绘画过程，或者通过维护每种颜色的所有绘画区域的联合来模拟绘画过程。 对于每个矩形，我们将从所有先前的矩形中减去其面积，然后添加其自己的区域。 这很快就会变成矩形之间重复的几何减法。 

即使将我们限制为矩形交集，每个新矩形也可以与之前的 O(n) 矩形相交，并且保持精确的剩余可见区域需要将矩形分割成更小的块。 在最坏的情况下，在 k 次操作之后，我们可能会维护 O(k^2) 片段。 这会爆炸超出任何可行的极限。 

核心见解是，我们实际上并不需要每种颜色的几何形状，只需要它是否至少有一个可见点。 当且仅当其矩形的每个点都被后面的矩形覆盖时，颜色才会完全消失。 

这重新构建了问题：对于每个矩形 i，我们需要确定其内部是否存在未被矩形 i+1 到 n 覆盖的点。 如果是，则颜色 i 幸存。 

所以我们从最后到第一个处理矩形。 我们维护已经被后面的矩形覆盖的点集。 对于每个矩形，我们需要一种快速的方法来检查它是否被完全覆盖，如果没有，我们必须将仍然未被覆盖的部分标记为“现在被覆盖”。

这是一个经典的动态二维覆盖问题。 关键的减少是使用坐标压缩和一个轴上的线段树将平面转换为可管理的结构，每个节点使用二级结构维持对另一个轴的覆盖。 更实用和标准的 CF 3300 解决方案使用扫描线与压缩 x 坐标上的线段树相结合，维护覆盖的线段并查询矩形中是否保留任何未覆盖的部分。 

我们扫描矩形边缘的 y 事件，保持活动的 x 间隔覆盖。 在每个事件中，我们可以通过检查矩形的 x 范围在其 y 跨度期间是否有任何未完全覆盖的部分来测试矩形是否引入了任何未覆盖的区域。 如果是，则矩形提供新的可见颜色。 

因此，我们不是跟踪整个区域，而是仅跟踪以相反顺序处理时矩形中是否存在至少一个未覆盖的单元格。

 | --- | --- | --- | --- |
 | 暴力几何分裂| O(n2) 到 O(n3) | O(n²) | 太慢了|
 | 扫线+线段树覆盖| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们通过以相反的绘制顺序处理矩形来解决这个问题，将后面的矩形视为已经绘制的区域。 

1. 将所有矩形x坐标转换为压缩坐标系。 这是必要的，因为线段树无法直接处理最大 10^9 的值。 
2. 按 y 坐标对矩形进行排序，以准备 y 上的扫描线。 每个矩形贡献两个事件：一个用于进入其 y 范围，一个用于离开它。 
3. 在压缩的 x 轴上构建线段树。 每个节点跟踪其区间是否被完全覆盖或部分未被覆盖。 
4. 按逆时间顺序从上到下扫描。 在每个 y 事件中，我们通过将矩形的 x 间隔标记为该 y 板的覆盖来更新线段树。 
5. 当我们处理一个矩形时，在将其标记为被覆盖之前，我们查询其x区间内是否存在未被覆盖的部分。 如果存在这样的部分，则该矩形至少贡献一个可见点，并且必须计算其颜色。 
6. 处理查询后，我们应用更新将其区域标记为被覆盖，确保较早的矩形将其视为被阻止。 
7. 计算所有贡献可见区域的矩形，然后添加颜色 0，因为背景始终保持至少部分可见，除非完全被矩形覆盖，而由于无限平面，这是不可能的。 

### 为什么它有效

 在反向扫描的任何时刻，线段树都准确地表示随后按原始顺序绘制的所有矩形的并集。 当我们检查矩形 i 时，我们实际上是在询问矩形 i 减去所有后面的矩形的集合差是否为空。 如果它是空的，颜色 i 永远不会出现。 如果它非空，则至少存在一个未被覆盖的点，因此颜色是可见的。 

不变的是，在处理矩形 i+1 到 n 后，数据结构准确地表示它们的并集覆盖范围。 每个查询都会正确检测矩形 i 在添加到覆盖集中之前是否贡献新的未覆盖区域。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.cover = [0] * (4 * n)
        self.len = [0] * (4 * n)

    def _pull(self, idx, l, r):
        if self.cover[idx]:
            self.len[idx] = r - l
        elif r - l == 1:
            self.len[idx] = 0
        else:
            self.len[idx] = self.len[idx * 2] + self.len[idx * 2 + 1]

    def update(self, idx, l, r, ql, qr):
        if qr <= l or r <= ql:
            return
        if ql <= l and r <= qr:
            self.cover[idx] = 1
            self.len[idx] = r - l
            return
        if r - l == 1:
            self.cover[idx] = 1
            self.len[idx] = 1
            return
        mid = (l + r) // 2
        self.update(idx * 2, l, mid, ql, qr)
        self.update(idx * 2 + 1, mid, r, ql, qr)
        self.cover[idx] = self.cover[idx * 2] and self.cover[idx * 2 + 1]
        self._pull(idx, l, r)

    def query(self, idx, l, r, ql, qr):
        if qr <= l or r <= ql:
            return False
        if ql <= l and r <= qr:
            return self.len[idx] != (r - l)
        if r - l == 1:
            return self.len[idx] == 0
        mid = (l + r) // 2
        return self.query(idx * 2, l, mid, ql, qr) or self.query(idx * 2 + 1, mid, r, ql, qr)

def solve():
    n = int(input())
    rects = []
    xs = []

    for i in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        rects.append((x1, y1, x2, y2))
        xs.append(x1)
        xs.append(x2)

    xs = sorted(set(xs))
    mp = {x:i for i, x in enumerate(xs)}
    m = len(xs)

    events = []
    for i, (x1, y1, x2, y2) in enumerate(rects):
        events.append((y1, i, 1))
        events.append((y2, i, -1))
    events.sort()

    seg = SegTree(m)
    active = [False] * n
    ans = 0

    for y, idx, typ in events:
        x1, y1, x2, y2 = rects[idx]
        l = mp[x1]
        r = mp[x2]

        if typ == 1:
            if seg.query(1, 0, m - 1, l, r):
                if not active[idx]:
                    active[idx] = True
                    ans += 1
            seg.update(1, 0, m - 1, l, r)

    print(ans + 1)
```线段树是在压缩的 x 坐标上构建的，其中每个节点代表 x 空间的一个区间。 这`len`字段跟踪该细分市场的覆盖范围。 这`query`函数在添加矩形之前检查是否仍有任何未覆盖的 x 部分。 

当扫描到达每个矩形的底部边缘时，就会考虑该矩形。 如果查询找到任何未覆盖的部分，则该矩形会提供可见的颜色。 

一个微妙的细节是，更新在查询后应用，确保我们仅测试后面的矩形的可见性。

 ## 边缘情况

 完全嵌套的矩形链演示了关键不变量。 当每个矩形严格包含下一个矩形时，反向扫描会将最小的矩形标记为首先可见。 然后，每个外部矩形都会被以后的更新完全覆盖，并且不会产生新的可见区域。 

不相交的配置显示了相反的极端。 如果矩形根本不重叠，则每个矩形都会贡献可见区域，因为后面的矩形无法阻挡它。 该算法正确地识别每个在查询时具有未覆盖的 x 间隔。 

接触边界的矩形测试区间处理的正确性。 如果两个矩形仅在边缘处接触，则坐标压缩可确保它们不会错误地共享覆盖范围，因为半开区间表示可以防止错误重叠。
