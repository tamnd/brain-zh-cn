 ## 解决方案
 ## 问题理解

 我们从一个无限数组开始，其中位置$i$最初包含值$i$。 所以数组开始时是一个简单的恒等映射：索引等于值。 

每一秒，所有位置都会同时更新。 每个位置都成为其自身与其直接相邻位置的按位“或”。 更准确地说，位置$i$取值来自$i-1$,$i$， 和$i+1$，处理边界以便位置$0$仅与位置进行 OR 运算$1$。 此更新规则并行应用于每个索引，这意味着新的数组$t+1$完全根据当时的数组计算$t$，而不是在同一秒内增量。 

我们被要求提供单个索引的值$n$后$m$此类全球更新。 困难在于，值通过按位或向外传播，并且数组是无限的，因此不可能进行暴力模拟。 

约束条件允许$n, m$最多$10^9$最多$10^4$测试用例。 这立即排除了任何模拟每个查询的线性步骤的方法。 甚至$O(n)$每个测试用例都是不可能的，因为$n$本身可以是$10^9$，总的工作量将会爆炸。 

核心微妙之处在于，某个位置的值并不取决于精确的算术传播，而是取决于位如何从附近的整数传播。 一个天真的心理陷阱是认为只有局部价值观在固定的时间内才重要。 这是错误的，因为 OR 单调地合并信息，并且较高位以不同的有效速度传播。 

一个常见的错误假设是，该值在少量步骤后稳定下来，或者仅取决于有界邻域，例如$[n-m, n+m]$。 虽然该部分对于依赖范围来说是正确的，但它并没有直接简化计算，因为该范围内的每个值本身都会以结构化但不平凡的方式随时间变化。 

## 方法

 直接模拟将维护整个数组并应用更新规则$m$步骤。 每一步的成本$O(N)$， 在哪里$N$至少需要$n+m$是正确的。 对于大值来说这已经是不可能的了。 更糟糕的是，数组在概念上是无限的，因此即使选择安全的截止值也很重要。 

关键的观察是，这个过程是一个具有非常规则结构的按位传播问题。 我们不跟踪完整的整数，而是独立地检查每一位。 位置有点$i$在某个时间$0$只是该位是否被设置$i$。 每一秒之后，如果某个位在其任何邻居中处于活动状态，则该位在该位置处变为活动状态。 

这将每一位都变成了一个经典的“扩展区间”问题。 如果在位置设置了一个位$x$， 后$m$影响所有位置的步骤$[x-m, x+m]$。 自从最初有点$k$在索引的二进制表示中存在该位的所有索引处设置，我们可以将过程重新解释为确定距离内是否存在某个初始索引$m$的$n$这贡献了给定的一点。 

等价地，位置的最终值$n$是区间内所有整数的按位或$[n-m, n+m]$，与非负索引相交，因为数组从 0 开始。负索引不存在，因此左侧被剪裁为 0。 

所以问题归结为计算：

 连续范围内的整数的 OR 运算。 

一旦我们看到这一点，任务就变得纯粹是计算 OR$[L, R]$有效地，其中$L = \max(0, n-m)$和$R = n+m$。 

应用标准技巧：可以使用端点之间的最高不同位来计算范围的或。 如果我们看一下二进制前缀$L$和$R$，最高位以下不同的所有位在 OR 结果中都变为 1，因为在覆盖二进制边界两侧的任何完整范围内，都会出现较低位的所有组合。 

因此，可以通过取最高有效位来得出答案$L$和$R$不同，然后将所有较低位设置为 1，同时适当保留较高位。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(m \cdot (n+m))$|$O(n+m)$| 太慢了 |
 | 按位范围或减少 |$O(1)$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 我们转换每个查询$(n, m)$进入一个范围$[L, R]$在哪里$L = \max(0, n-m)$和$R = n+m$。 

1. 计算$L$和$R$。 这代表其值可以影响位置的所有原始索引$n$后$m$步骤。 这是因为我们观察到每一步都会左右扩大一个索引的影响力。 
2.如果$L = 0$，我们将范围视为从零开始。 这很重要，因为原始序列不会扩展到负索引，因此那里不存在可贡献位的值。 
3. 计算中所有整数的按位或$[L, R]$。 我们不进行迭代，而是确定最高位$L$和$R$不同。 该位确定二进制表示发散的第一个位置。 
4. 一旦找到最高的不同位，结果中的所有较低位都会变为 1，因为在范围内我们可以构造在某个点独立翻转这些位的值。 
5. 最终答案是通过保留公共前缀来构造的$L$和$R$，并用 1 填充所有剩余的低位。 

### 为什么它有效

 不变量是每个位位置在“或”传播下独立演化，并且该过程保持影响区间内所有中间整数值的可达性。 更新规则确保任何可到达的起始位置中设置的任何位都对最终结果有贡献。 由于可达性随时间对称扩展，因此贡献初始索引的集合恰好成为一个连续的区间。 连续区间上的 OR 具有稳定的二元结构，仅由端点的二元散度决定，这保证了重建的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def range_or(l, r):
    if l == 0:
        # special case: OR from 0 to r
        # becomes all bits up to MSB of r are 1
        msb = r.bit_length() - 1
        return (1 << (msb + 1)) - 1

    # find highest differing bit between l and r
    x = l ^ r
    msb = x.bit_length() - 1

    # keep prefix above msb, set all lower bits to 1
    prefix = r & (~((1 << (msb + 1)) - 1))
    suffix = (1 << (msb + 1)) - 1
    return prefix | suffix

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    l = max(0, n - m)
    r = n + m
    print(range_or(l, r))
```该实现是围绕一个帮助程序构建的，该帮助程序使用二进制结构而不是迭代来计算一定范围内的 OR。 特殊情况$l = 0$是单独处理的，因为零锚定了范围并保证所有较低位都完全饱和，直到最高位$r$。 

一般情况使用XOR来检测哪里$l$和$r$不同。 该位置决定了可能值的二叉树的分歧程度。 低于该级别的所有内容都会被完全覆盖，因此我们将这些位设置为 1。 的前缀$r$被保留以维持在整个范围内相同的较高位的正确性。 

一个微妙的实现细节是使用`bit_length() - 1`找到最高设置位。 这里相差一的错误很常见； 构建的掩码`(1 << (msb + 1)) - 1`正确地创建一个完整的块，直到并包括该位。

 ### 示例 1：$n = 5, m = 2$我们计算$L = 3$,$R = 7$。

 | ---| ---| ---| ---| ---| ---|
 | 初始化| 3 | 7 | 4 | 2 | - |
 | 建造| - | - | - | - | 前缀 + 后缀 |

 最高的不同位是位 2。低于它的所有位都变为 1，并且保留更高的结构。 结果变成$7$。 

这符合直觉：值$[3,7]$已经覆盖了所有低位模式，因此 OR 饱和到 111。 

### 示例 2：$n = 1, m = 0$我们计算$L = 1$,$R = 1$。 

| 步骤| 左 | 右 | L 异或 R | MSB 差异 | 结果 |

 | 初始化| 1 | 1 | 0 | 无 | 1 |

 由于区间只有一个元素，因此 OR 不变。 这证实了基本情况的一致性。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def range_or(l, r):
        if l == 0:
            msb = r.bit_length() - 1
            return (1 << (msb + 1)) - 1
        x = l ^ r
        msb = x.bit_length() - 1
        prefix = r & (~((1 << (msb + 1)) - 1))
        suffix = (1 << (msb + 1)) - 1
        return prefix | suffix

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        l = max(0, n - m)
        r = n + m
        out.append(str(range_or(l, r)))
    return "\n".join(out)

 ## 边缘情况

 当$n = 0$，范围变为$[0, m]$。 该算法通过从零切换到完整前缀 OR 来显式处理此问题。 例如，与$m = 5$，范围是$[0,5]$，最高位为2，所以结果为$2^3 - 1 = 7$，匹配从 0 到 5 的所有数字的 OR。 

当$m = 0$，范围缩小为$[n,n]$。 XOR 变为零，因此没有位不同并且函数返回$n$不变。 这与没有发生更新的事实相符。 

什么时候$n < m$，左边界钳位为零。 如果没有这个限制，负指数就会错误地做出贡献。 该实现通过显式设置来确保正确性$L = 0$，保留阵列域的物理约束。
