 ## 解决方案
 ## 问题理解

 我们给出了序列必须具有的连续块的长度。 如果签名为 (s_1,s_2,\ldots,s_n)，则最终序列必须包含 (s_1) 个相等值的块，后面是重复 (s_2) 次的不同值，然后是重复 (s_3) 次的另一个不同值，依此类推。 这些值本身是正整数，任务是选择它们以使所有元素的总和尽可能小。 

例如，对于签名 ([2,1,3,1])，块值可能是 (1,2,1,2)，给出序列 ([1,1,2,1,1,1,2])。 四个块值只需与其紧邻的值不同即可。 不相邻的块可以使用相同的值。 

最多可以有 (10^5) 个块，而它们的总长度最多为 (10^6)。 由于输出本身可以包含 (10^6) 个整数，因此 (O(n)) 算法本质上是自然目标。 在最坏的情况下，(n) 中具有二次因子的算法已经需要大约 (10^{10}) 次运算，远远超出了预期的时间限制。 总签名长度受 (10^6) 限制的事实也意味着显式构造答案是可行的，但我们应该避免为每个输出元素做的工作量远远超过恒定量。 

第一个边缘情况是仅包含一个块的签名。 对于输入 (n=1)、(s=[5])，答案是 (1) 的五个副本。 没有相邻块强制使用更大的值，因此使用 (2)、(3) 或任何更大的值只会增加总和。 

第二种边缘情况是当前块的最小值不一定是本地最佳选择。 对于 (s=[1,3])，选择块值 (1,2) 得出的总和为 (1+3\cdot2=7)，而选择 (2,1) 得出的总和为 (2+3=5)。 因此，总是以 (1) 开头的贪心规则是错误的。 

当许多连续块具有相同长度时，会出现第三种边缘情况。 对于 (s=[2,2,2])，最佳块值为 (1,2,1)，产生 ([1,1,2,2,1,1])。 赋值(1,2,3)是有效的，但它的总和更大。 该构造仅要求相邻块值不同，因此交替两个最小值就足够了。 

最后，输出包含重复值，而不是签名本身。 对于(s=[1,3])，输出`2 1 1 1`是正确的，因为它的签名是 ([1,3])。 一个常见的实现错误是正确求解每个块的值，但忘记根据块长度扩展该值。 

## 方法

 直接的暴力方法将为每个块分配一个正整数，检查相邻分配是否不同，扩展块并计算结果总和。 由于签名长度之和最多为 (10^6)，因此考虑从 (1) 到 (10^6) 的值就足够了，因为最佳答案不需要大于总输出长度的值。 即使有这种人为限制，也可以有 ((10^6)^n) 次分配。 最多（n=10^5），即（10^{600000}）个候选者，因此穷举搜索是完全不可行的。 

更结构化的蛮力可以观察到只有很小的值可能很重要，并为每个块尝试几个可能的值。 这在每个位置仍然具有乘法分支因子，因此它仍然是指数的。 真正的问题是为什么大于 (2) 的值永远不会出现。 

考虑一个选定值为 (x) 的块的动态编程状态。 假设对于前一个块，可实现的最小成本由值 (1) 获得。 那么为当前块选择 (2) 是合法的，并且成本低于选择任何 (x\ge3)。 相反，如果前一个块的最小值是通过值 (2) 获得的，则为当前块选择 (1) 是合法的，并且成本低于每个 (x\ge3)。 通过归纳，每个块之后的最佳状态可以由值（1）和（2）之一表示。 至少 (3) 的值始终由这两个选择之一主导。 

一旦只剩下(1)和(2)，问题就变得特别简单。 相邻块必须具有不同的值，因此在选择第一个块的值后，将强制后面的每个值。 只有两种可能的模式：

 [
 1,2,1,2,\l点
 ]

 和

 [
 2,1,2,1,\l点
 ]

 我们可以计算两种模式的成本并选择较小的一种。 因此，对任意值的强力搜索就只剩下两个候选值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(10^{6n})) 个候选 | (O(n)) | (O(n)) | 太慢了|
 | 两种模式 DP | (O(n+\sum s_i)) | (O(n+\sum s_i)) 输出 | 已接受 |

 ## 算法演练

 1. 读取签名(s_1,s_2,\ldots,s_n)。 每个 (s_i) 告诉我们必须写入分配给块 (i) 的值的多少个副本。 
2. 计算使第一个块具有价值的成本 (1) 和使其具有价值的成本 (2)。 它们是 (s_1) 和 (2s_1)。 
3. 对于每个后续块 (i)，交换前两个状态使用的值。 如果前一个块使用 (1)，则当前块必须使用 (2)。 如果前一个块使用 (2)，则当前块必须使用 (1)。 长度 (s_i) 的块的成本是其长度乘以其选择的值。 
4. 保留两种交替模式的总成本。 最后选择总成本较小的模式。 
5. 展开选定的图案。 如果所选块值为 (1)，则附加 (s_i) 个副本`1`; 如果是 (2)，则附加 (s_i) 个副本`2`。 附加整数的总数正好是 (\sum s_i)，最多为 (10^6)。 

为什么它有效可以被描述为一个不变量。 在处理块(i)之后，两个维持的成本正是使用以值(1)和(2)结尾的两种可能的交替模式的解决方案中的最小成本。 任何最优解都可以限制为值 (1) 和 (2)，因为只要值至少为 (3) 的状态可能是最优的，则 (1) 或 (2) 之一可从前面的最优状态中获得，并且对当前正块长度的贡献严格较小。 对于值 (1) 和 (2)，路径约束强制使用两种交替模式之一。 因此，比较这两种模式可以找到全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    # cost1: pattern 1,2,1,2,...
    # cost2: pattern 2,1,2,1,...
    cost1 = 0
    cost2 = 0

    for i, length in enumerate(s):
        if i % 2 == 0:
            cost1 += length
            cost2 += 2 * length
        else:
            cost1 += 2 * length
            cost2 += length

    first = 1 if cost1 <= cost2 else 2

    ans = []
    value = first

    for length in s:
        ans.extend([str(value)] * length)
        value = 3 - value

    sys.stdout.write(" ".join(ans))

if __name__ == "__main__":
    solve()
```第一个循环计算两个可能的总和，而不构建完整的序列。 对于偶数从零开始的索引，第一个模式使用值 (1)，第二个模式使用值 (2)； 对于奇数索引，它们的角色相反。 

比较使用`<=`，因此关系始终选择第一个模式。 接受任何最小值，因此特定的打破平局规则不会影响正确性。 

第二个循环精确地重建所选模式。 表达式`3 - value`开关`1`到`2`和`2`到`1`，避免单独的条件。 

这`ans`list 包含字符串，因为在末尾连接字符串比重复连接到一个大的 Python 字符串要高效得多。 它的大小受总签名长度的限制，最多为 (10^6)。 

Python 整数不会溢出，对于构造的二值解，最大可能的和最多为 (2\cdot10^6)，因此整数运算在这里很简单。 主要的内存使用是输出本身。

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    stream = io.StringIO(inp)
    sys.stdin = stream
    input = stream.readline

    old_stdout = sys.stdout
    output = io.StringIO()
    sys.stdout = output

    try:
        solve()
        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input
        sys.stdout = old_stdout

def signature(arr):
    if not arr:
        return []

    result = []
    current = arr[0]
    count = 1

    for x in arr[1:]:
        if x == current:
            count += 1
        else:
            result.append(count)
            current = x
            count = 1

    result.append(count)
    return result

 ## 边缘情况

 对于单个块，例如`1 / 5`，根本没有邻接限制。 该算法比较两个名义模式，但模式 1 具有成本 (5)，而模式 2 具有成本 (10)，因此它选择值`1`和输出`1 1 1 1 1`。 签名依然存在`[5]`。 

对于局部贪婪反例`2 / 1 3`，第一个模式具有值 (1,2) 和成本 (1+6=7)。 第二个具有值 (2,1) 和成本 (2+3=5)，因此算法选择第二个模式并输出`2 1 1 1`。 这说明了为什么不能简单地为第一个块分配最小的可能值而不考虑其邻居。 

对于重复块长度，`3 / 2 2 2`，这两种模式的成本为 (2+4+2=8) 和 (4+2+4=10)。 选择第一个模式，给出`1 1 2 2 1 1`。 中间块与两个相邻块不同，而第一块和第三块可以安全地使用相同的值，因为它们不相邻。 

对于最大输出长度，`1 / 1000000`，答案由一百万个副本组成`1`。 该算法永远不会创建不必要的替代值，并且输出大小恰好是允许的最大值。 扩展循环对每个输出元素执行一次追加操作，因此其工作与不可避免的输出大小呈线性关系。 

对于最大块数，取 (100000) 个长度为 (1) 的块。 每个相邻块必须不同，因此最佳序列在`1`和`2`。 有两种可能的交替序列，并且因为有偶数个块，所以该模式以`1`总和 (50000\cdot1+50000\cdot2=150000)。 该算法精确地计算此选择，无需对第一个和最后一个块之间的边界进行任何特殊处理，因为只有连续的块受到约束。
