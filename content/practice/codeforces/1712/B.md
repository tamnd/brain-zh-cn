 ## 解决方案
 ## 问题理解

 我们得到一个整数$n$，并且我们必须排列来自$1$到$n$进行排列，以使特定分数尽可能大。 分数是按位置计算的：在索引处$i$，我们取 LCM$i$以及该指数的价值，然后将所有这些贡献相加。 

因此，我们不能随意更改索引，只能更改分配给每个位置的值。 每个数字来自$1$到$n$必须仅使用一次，目标是最大化所有位置的 LCM 值。 

约束允许最多$10^5$每个测试用例最多$10^5$所有测试用例的总计。 这排除了尝试所有排列的任何解决方案，因为$n!$增长速度极快。 即使每个测试用例采用二次方法也会太慢$n$很大，因为$10^5$平方已经是$10^{10}$，远远超出了 1 秒的限制。 这推动我们走向线性或近线性结构。 

出现微妙的边缘情况时$n$很小。 例如，当$n=1$，只有一种排列，所以答案是强制的。 什么时候$n=2$，交换元素以一种不明显的方式改变了 LCM 贡献，如果不仔细检查 LCM 结构，像“将大量数字放在大位置”这样的天真的直觉可能已经失败。 

## 方法

 暴力方法会尝试每种排列，计算每个排列的 LCM 总和，然后选择最好的。 这是正确的，因为它评估所有可能的分配。 然而，它需要评估$n!$排列，以及每个评估成本$O(n)$，导致$O(n \cdot n!)$，即使对于$n = 10$。 

关键的观察结果是两个数字的最小公倍数$i$和$p_i$当它们的乘积很大且最大公约数很小时，就会最大化。 自从$\mathrm{lcm}(i, p_i) = \frac{i \cdot p_i}{\gcd(i, p_i)}$，我们希望对的 gcd 尽可能小，同时尽可能保持两个值都很大。 

这表明以避免共享因素的方式配对数字。 最简单的保证方法$\gcd(i, p_i) = 1$尽可能频繁地成对交换元素。 如果我们配对$i$和$i+1$， 然后$\gcd(i, i+1)=1$，LCM 变为$i \cdot (i+1)$，与任何涉及较小数字的排列相比，它都很大。 

因此，我们可以通过交换相邻元素来贪婪地构造排列，而不是以复杂的方式进行全局优化。 这确保了每一对都贡献一个类似 LCM 的大乘积，并且我们避免在小指数上浪费大值。 

对于奇数$n$，最后一个元素无法配对，因此它保留在原位。

 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot n!)$|$O(n)$| 太慢了|

 ## 算法演练

 1. 从清单开始$[1, 2, 3, \dots, n]$。 这是优化前的基线排列。 
2. 从左到右遍历数组，步长为2。 
3. 对于每对$(i, i+1)$，交换两个值。 这会创建对$(2,1), (4,3), (6,5), \dots$。 
4.如果$n$是奇数，保留最后一个元素不变，因为它没有伙伴。 
5. 输出结果数组。 

我们成对处理的原因是相邻整数保证是互质的，与按顺序排列相比，这可以最大化 LCM。 

### 为什么它有效

 每对交换$(i, i+1)$产生两个 LCM 项：$$\mathrm{lcm}(i, i+1) = i(i+1), \quad \mathrm{lcm}(i+1, i) = i(i+1)$$根据位置按某种顺序。 这绝对比让它们保持对齐要好$\mathrm{lcm}(i,i)=i$和$\mathrm{lcm}(i+1,i+1)=i+1$， 自从$2i(i+1)$呈二次方增长，同时$2i+1$是线性的。 

因为每一对都是独立的，并且交换不会影响其他位置，所以我们可以最大化每个相邻块的局部贡献，并且最优局部选择的总和给出全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(range(1, n + 1))

    for i in range(0, n - 1, 2):
        p[i], p[i + 1] = p[i + 1], p[i]

    print(*p)
```该解决方案通过初始化恒等排列然后交换每个相邻对来在线性时间内构造排列。 循环`range(0, n - 1, 2)`确保我们只交换有效的对，并通过保持最后一个元素不变来自然地处理奇数长度。 

一个常见的错误是尝试更复杂的基于 gcd 的逻辑，但不需要这样做，因为邻接已经保证了本地的最大利益。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(range(1, n + 1))
        for i in range(0, n - 1, 2):
            p[i], p[i + 1] = p[i + 1], p[i]
        out.append(" ".join(map(str, p)))
    return "\n".join(out)

 ## 边缘情况

 对于$n=1$，算法产生$[1]$因为交换循环不执行。 这匹配唯一有效的排列，因此正确性是立即的。 

为了$n=2$，交换产生$[2,1]$。 这是替代方案$[1,2]$给出较小的分数，因为它浪费了交叉配对带来的大量 LCM 增益，从而确认即使是最小的非平凡情况也能得到最佳处理。 

对于奇数$n$， 例如$n=5$，最后一个元素保持不变。 该结构仍然以最佳方式对所有早期元素进行配对，并且未配对的元素在其位置贡献唯一可能的值，因此通过将其移动到其他地方而不破坏更好的对，不可能进行任何改进。
