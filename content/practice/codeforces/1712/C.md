 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例，每个测试用例都包含一个正整数数组。 一次，我们可以选择一个值`x`并同时删除所有出现的`x`通过将它们变成零来在数组中。 任务是尽可能少地应用此操作，以使结果数组变为非递减。 

关键一点是我们没有重新排列元素。 位置的相对顺序永远不会改变，只是值被零替换。 由于零是最小的可能值，因此将元素变成零只能帮助修复较大值出现在较小值之前的反转。 

约束条件`n ≤ 10^5`跨所有测试用例强制每个测试用例采用线性或近线性解决方案。 如果在每次删除后重新计算顺序结构，任何重复扫描数组或天真地模拟每个值的操作都会太慢。 

当数组已经非递减时，会出现微妙的边缘情况。 例如，`[0, 0, 1, 1]`已经有效，所以不需要任何操作。 总是删除某些内容的粗心方法（例如，始终针对第一个反转）可能会错误地执行不必要的操作。 

另一个重要的情况是当值严重“交错”时，例如`[1, 2, 1, 2]`。 天真的直觉可能表明一两个操作就足够了，但由于零会影响全局秩序，因此我们必须仔细推理存在多少个不同的无序“层”。 

## 方法

 暴力策略将模拟所有可能的操作序列。 每个操作都会选择一个值`x`并将其完全删除。 由于每个值最多可以删除一次，因此我们有效地选择不同值的子集，并检查应用它们后结果数组是否已排序。 

最多有`n`不同的值，因此子集的数量是指数级的。 即使我们检查有效性`O(n)`每个子集的时间，这变成`O(2^n · n)`，这是完全不可行的。 

关键的见解是将视角从“我们删除哪些值”转变为“数组中的哪个结构强制删除”。 

观察删除后数组不减少意味着什么。 所有剩余的非零值必须已按排序顺序出现，并且必须通过删除参与反转的两个值中的至少一个来消除每个反转。 

现在考虑从左到右扫描数组，同时保持迄今为止看到的最大值。 每当我们看到下降（小于运行最大值的值）时，该位置就会产生约束：当前值或之前的值最终必须被删除以消除反转。 由于移除是全局的每个值，因此参与此类“中断”的每个不同值都被强制执行至少一个操作。 

关键的观察是，每次我们遇到一个新的“无序层”时，它都对应于一个必须在单独的操作中删除的不同值。 计算有多少不同的值打破了单调性就给出了答案。 

我们可以通过跟踪出现在以下位置的所有值来形式化这一点：`a[i] < max(a[0..i-1])`。 每个这样的值都是“坏的”，必须至少删除一次。 由于一个操作删除了某个值的所有出现，因此答案就变成了出现在递减位置的不同值的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从左到右遍历数组，同时保持到目前为止看到的最大值。 

这捕获了当前的“排序期望”边界。 
2. 每当当前元素大于或等于最大值时，更新最大值。 

这意味着该位置的序列没有被破坏。 
3. 如果当前元素小于最大值，则将该值标记为“bad”。 

原因是该元素参与了与一些较早的较大元素的反转。 
4. 将每个这样的“坏”值存储在一个集合中。 

我们使用集合是因为​​同一值多次出现只需要一次操作。 
5. 处理完整个数组后，答案就是集合的大小。 

### 为什么它有效

 不变的是每次我们检测到`a[i] < max_so_far`，我们确定在任何有效解决方案中都必须删除的值。 这是因为反转涉及`a[i]`并且先前的最大值无法固定，除非`a[i]`或者删除先前较大的值。 由于我们只允许按值删除，不能按位置删除，因此将值标记为`i`足以解释全球范围内的限制。 以这种方式收集的不同值完全对应于消除所有反转所需的最小操作集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = 0
        bad = set()
        
        for v in a:
            if v >= mx:
                mx = v
            else:
                bad.add(v)
        
        print(len(bad))

if __name__ == "__main__":
    solve()
```该代码直接遵循前面描述的扫描。 变量`mx`保持运行最大值，任何违反单调性的元素都会插入到集合中。 最终的答案是不同的此类值的数量。 关键的实现细节是我们不会重置最大值或重新访问较早的元素，因为该决策纯粹基于从左到右的结构。

 ## 边缘情况

 完全排序的数组，例如`[1, 2, 3]`从不触发`v < mx`条件，因此坏集保持为空并且算法正确返回零。 

像这样的数组`[5, 5, 5]`保持`mx`始终保持不变，并且没有任何元素被认为是坏的，因此它不需要任何操作。 

在降序数组中，例如`[4, 3, 2, 1]`，除了第一个元素之外的每个元素都违反了运行最大值，产生错误值`{3, 2, 1}`。 因此，该算法精确计算导致所有反转的不同值，匹配所需删除的最小数量。
