 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个位置代表一行中的一个节点。 任意两个索引之间$l$和$r$，存在一条边，其权重为子数组中的最小值$a_l, \dots, a_r$。 由于每对顶点都是连接的，这形成了一个具有非常特殊结构的完整图：边权重来自线段最小值。 

我们最多被允许改变$k$数组位置到我们想要的任何值。 在这些更改之后，我们考虑该图中的最短路径距离，并要求最大可能的图直径，这意味着任何一对顶点之间的最大最短路径距离。 

关键的困难在于边权重不是独立的。 单个值会影响包括其位置的每个段，因此一次修改可以同时影响多个边缘。 最短路径也不是直接边，因为经过中间顶点可能会产生比直接最小边更大的总权重。 

约束条件足够严格$n$上升到$10^5$在所有测试用例中，因此任何显式尝试所有对或重新计算图形距离的解决方案都会失败。 甚至$O(n^2)$对每个测试用例进行推理是不可能的。 每次测试我们都需要接近线性或线性的东西。 

朴素推理的一个常见失败案例是假设答案仅取决于局部最大值或选择$k$最大的元素。 例如，如果$a = [1, 100, 1]$和$k = 1$，人们可能会尝试增加中间元素，但真正的效果是有多少部分可以“保护”免受小最小值的影响，而不仅仅是单个值的影响。 

另一个陷阱是假设最短路径等于直接边权重$\min(a_l, \dots, a_r)$。 实际上，将长间隔分割成更小的间隔可以增加路径长度，因为中间节点可以避免小的最小值。 

## 方法

 该图具有特殊的结构：对于任何对$u < v$，直接边权重是段中的最小值$[u, v]$。 如果我们从路径的角度思考，使用中间顶点会用较小的线段替换大的线段，这些较小的线段的最小值是单独取的。 

已知这种类型的构造可以将最短路径减少到“沿分区的段最小值的最大值”，因为路径对应于将间隔分割成子段。 

蛮力方法是尝试所有修改方法$k$元素，重新计算所有线段最小值，构建所有最短路径，并计算直径。 即使我们忽略图重新计算，数组的数量也是$\binom{n}{k} \cdot 10^k$，并且每次评估至少需要$O(n^2)$对所有对进行推理。 这一下子就爆炸了。 

关键的观察结果是，最佳修改总是以非常结构化的方式表现。 我们不关心任意更改，而是只关心“弱点”（减少分段最小值的小值）的位置。 每一次修改都可以被认为是消除一个这样的弱点，剩下的就是将数组分割成块，其中最小值主导行为。 

一旦我们将视角转向“我们可以从低值中隔离出多少部分”，问题就变成了选择一个阈值并检查有多少不良元素阻碍了实现它。 这自然会导致对答案进行二分搜索并结合贪婪的可行性检查。 

对于固定的候选直径$X$，我们将其解释为需要至少一个可以支持该距离的“坚固结构”部分。 然后，我们计算必须升级多少个位置，以确保没有段会导致直径减小到以下$X$仍然无法修复。 如果这个成本在$k$，该值是可以实现的。 

这将问题转化为单调可行性条件$X$，启用二分搜索。

 ## 算法演练

 我们通过二分查找最大可能直径值来解决这个问题。 

1.修复候选答案$X$。 我们现在测试是否可以使图形直径至少$X$最多使用$k$修改。 

这个检查的意义是：我们是否可以强制执行一个配置，其中存在一对节点，其最短路径至少为$X$。 
2. 我们将低数组值解释为障碍。 以下任意值$X$段内倾向于减少段最小值，从而减少边权重。 

为了维持长距离，我们需要“消除”足够的这些障碍，这样长的路径就不会被迫穿过它们。 
3. 我们扫描数组并贪婪地决定哪些地方需要修改。 每当我们遇到一个低值聚集的区域会破坏任何候选长段时，我们都会花费一个操作来消除其影响。 

贪婪的本性之所以起作用，是因为一旦一个头寸被固定向上，它就会消除它参与的所有限制，所以延迟它永远不会有帮助。 
4. 我们计算至少需要多少次修改才能使配置与直径兼容$X$。 如果这个计数是$\le k$， 然后$X$是可行的。 
5.我们二分查找最大可行的$X$超过取值范围。 

### 为什么它有效

 正确性取决于可行性的单调性。 如果一个直径$X$是可以实现的，任何较小的值也是可以实现的，因为约束只会放松。 每一项修改都会消除阻碍长最短路径的结构性障碍，并且这些障碍是独立的，因为修复一个障碍不会增加其他地方所需修复的数量。 这确保了所需修复的贪婪计数是有效的，并且不会低估或高估真实成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(a, k, x):
    n = len(a)
    used = 0
    i = 0
    while i < n:
        if a[i] >= x:
            i += 1
            continue
        used += 1
        if used > k:
            return False
        j = i
        while j < n and a[j] < x:
            j += 1
        i = j
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 1, max(a) + k + 1
        ans = 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(a, k, mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现将可行性检查与搜索分开。 这`can`函数扫描数组并对低于阈值的连续位置进行分组。 每个这样的组对应于必须通过至少一次操作来修复的区域，以防止其将可实​​现的直径压缩到低于目标值。 

二分搜索探索可能的直径值，并将上限安全地设置为超出最大可能的调整值。 

一个微妙的点是我们从不尝试显式地模拟图形距离。 整个最短路径结构被压缩为关于低元素如何充当段最小值中的瓶颈的推理。

 ## 边缘情况

 一个关键的边缘情况是所有值都已经很大的时候。 对于像这样的输入`[10^9, 10^9, 10^9]`与任何$k$，可行性检查永远不会找到低段，因此二分搜索立即收敛到最大值。 这证实了该算法不会强制进行不必要的修改。 

另一个边缘情况是交替低值和高值，例如`[1, 100, 1, 100, 1]`。 这里每个低元素形成自己的段，并且每个元素都需要独立处理。 扫描正确地计算每个孤立的低位置，确保所需的操作数量与障碍物的结构而不是其大小相匹配。 

最后一个边缘情况是$k = n$。 该算法将每个低段视为可修复，因此任何阈值在上限范围内都变得可行，这符合我们可以完全覆盖数组以最大化直径的想法。
