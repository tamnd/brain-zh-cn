 ## 解决方案

 ## 问题理解

 我们得到一个最多有 14 个顶点的小型无向图，代表哪些人彼此认识。 每个输入行都是邻接矩阵的位掩码行，因此我们可以快速检查两个人是否连接。 

任务不是直接枚举图或子集，而是所有人的排列。 对于顶点的每个排序，我们都会查看连续的对并编码排列中的每个相邻对是否共享图中的边。 这会产生一个长度为的二进制字符串$n-1$。 每一种排列都恰好构成一个这样的字符串。 

输出要求每个可能的二进制字符串长度$n-1$，解释为整数位掩码，我们必须计算有多少个排列生成它。 

关键的困难是排列的阶乘数。 即使是为了$n=14$,$14!$太大而无法直接枚举。 输出空间仅为$2^{13} = 8192$，因此问题的结构强烈建议将排列压缩到由子集而不是排列索引的状态空间中。 

密集的图表会产生微妙的边缘情况。 如果每个人都认识每个人，那么每个相邻对都是有效的，因此每个排列都会产生一个全为的字符串。 在这种情况下，答案数组在掩码处有一个非零条目$2^{n-1}-1$。 即使输出极其稀疏，尝试显式跟踪每个排列的字符串的简单方法也会由于阶乘爆炸而失败。 

当图表为空时，会出现另一个极端情况。 那么每个邻接都为零，因此所有排列都有助于全零字符串。 这再次破坏了整个状态空间，任何试图在不尊重全局结构的情况下独立处理每个位置的转换的方法都会错误地过度计数。 

## 方法

 直接的暴力方法将产生所有$n!$排列。 对于每个排列，我们构建其二进制字符串$O(n)$，对其进行哈希处理，并增加其计数器。 这是正确的，但要付出代价$O(n! \cdot n)$，即使对于$n=12$，更不用说$n=14$。 

问题的结构表明要扭转观点。 我们不是构建排列，而是增量构建它们。 在任何时候，我们都有一个部分排列，关于未来的唯一重要信息是哪些顶点保持未使用以及哪个顶点当前位于排列的末尾。 当我们添加新顶点时，二进制字符串是逐步确定的。 

这自然会导致子集上的动态规划。 我们通过使用的顶点的子集和部分排列中的最后一个顶点来表示状态。 对于每个这样的状态，我们维护所有可能的后缀位掩码的分布，这些后缀位掩码可以通过从该状态完成排列来生成。 由于最终答案是在所有完整排列上聚合的，因此我们可以从具有完整子集的状态向上传播贡献。 

关键的观察是，转换仅取决于最后一个顶点和下一个选定顶点之间是否存在边。 这意味着每个 DP 转换都会翻转演化后缀掩码中的单个位，其位置由已放置的顶点数确定。 我们不需要显式存储排列，只需存储子集结构和位置。 

最终的解决方案成为具有表示正在构造的部分位掩码的附加维度的子集 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 排列上的子集 DP |$O(n^2 2^n)$|$O(n 2^n)$| 已接受 |

 ## 算法演练

 我们从左到右构建排列，但我们不存储排列，而是跟踪编码部分结构的 DP 状态。 

1.定义一个DP表，其中$dp[mask][v]$是位掩码上的字典或数组，表示我们可以使用中的顶点形成排列的多种方式`mask`并在顶点结束`v`，为当前前缀生成特定的邻接位历史记录。 位历史长度为$|mask|-1$。 
2. 通过设置初始化基本情况$dp[1<<v][v]$单一配置：从顶点开始的一种方法$v$带有空的邻接字符串。 由于不存在相邻对，因此尚无边缘决策。 
3. 迭代子集大小从 1 到$n$。 对于每个州$(mask, v)$，考虑通过选择新顶点来扩展排列$u$不在`mask`。 此扩展在排列中再追加一个位置，将邻接串长度增加一。 
4. 当从$v$到$u$,判断是否为对$(v, u)$是一个边缘。 如果是，则附加的新位为 1，否则为 0。$dp[mask][v]$左移一位，并将新的位附加到最低位置。 
5. 将这些转移贡献累积到$dp[mask \cup \{u\}][u]$。 这确保了所有以$u$正确存储所有可能的邻接历史。 
6.处理完所有状态后，我们只关心尺寸的完整掩模$n$。 对于每个结束顶点$v$，我们将所有存储的位掩码聚合在$dp[(1<<n)-1][v]$进入最终答案数组。 

### 为什么它有效

 在每一步中，DP 状态准确地表示与给定的一组已使用顶点和结束顶点一致的所有部分排列。 步骤之间唯一的依赖是最后一个顶点，因为下一个邻接决策仅取决于最后添加的边。 由于每个扩展都确定性地向序列附加一位，因此 DP 保留了部分排列与其生成的位历史之间的一一对应关系。 不会错误地合并两个不同的历史记录，因为位掩码是通过转换显式携带的，并且每个排列都恰好对应于通过 DP 的一条路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]

    size = 1 << n
    dp = [ [dict() for _ in range(n)] for _ in range(size) ]

    for i in range(n):
        dp[1 << i][i][0] = 1

    for mask in range(size):
        bits = bin(mask).count("1")
        if bits <= 1:
            continue
        for v in range(n):
            if not dp[mask][v]:
                continue
            cur = dp[mask][v]
            for u in range(n):
                if mask & (1 << u):
                    continue
                edge_bit = 1 if g[v][u] == '1' else 0
                new_mask = mask | (1 << u)
                nxt = dp[new_mask][u]
                for bm, cnt in cur.items():
                    nbm = (bm << 1) | edge_bit
                    nxt[nbm] = nxt.get(nbm, 0) + cnt

    full = (1 << n) - 1
    ans = [0] * (1 << (n - 1))

    for v in range(n):
        for bm, cnt in dp[full][v].items():
            ans[bm] += cnt

    print(*ans)

if __name__ == "__main__":
    solve()
```DP 表由子集和结束顶点索引，这确保我们只扩展有效的部分排列。 字典存储位历史的计数； 左移对应于附加新的邻接决策。 

初始化将每个单顶点子集设置为中性历史。 每个转换都会处理所有存储的位模式，这是必要的，因为达到相同状态的不同部分排列在其邻接历史中仍然可能不同。 

最终的聚合组合了所有可能的结束顶点，因为排列没有固定的端点。

 ## 边缘情况

 全连接图将所有排列折叠到单个输出桶中。 DP 仍然处理所有子集转换，但每个边缘位都是 1，因此所有历史都变得相同，并且只有最大位掩码累积计数。 

空图强制每个转换位为零。 每个排列都会产生相同的全零掩码，并且 DP 正确地累积所有$n!$排列成单个条目，而不会错误地分割状态。 

线性链确保只有特定的邻接模式才会产生邻接模式。 DP 必须在每一步区分有效边缘和无效边缘，并且由于位历史是显式携带的，因此在单个邻接决策中不同的两个排列在状态空间中永久分歧。
