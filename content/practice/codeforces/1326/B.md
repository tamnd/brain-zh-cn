 ## 解决方案

 ## 问题理解

 我们得到了一个未知数组的转换版本。 原始数组包含非负整数，对于每个位置，另一个值是从所有先前元素的最大值得出的。 然后从当前元素中减去该最大值以生成我们给出的数组。 

更具体地说，隐藏数组中的每个位置都受到迄今为止在其左侧看到的最大值的影响。 转换通过连续减去此运行最大前缀来隐藏原始值。 

任务是重建任何可以产生给定转换数组的有效原始数组。 尽管多种中间解释似乎是可能的，但问题保证了答案是唯一的。 

约束允许最多 200,000 个元素，这会立即排除任何尝试每个位置的所有可能性的二次重建。 任何解决方案都必须以线性时间运行，或者在最坏的情况下以接近线性时间运行，因为即使 O(n log n) 也已经可以接受，但在这里是不必要的。 

一个微妙的一点是，这种转变并不纯粹是局部的。 每个值都取决于最大前缀，而最大前缀又取决于所有先前的重构值。 这引入了一个依赖链，可以轻松地打破尝试贪婪地分配值而不仔细跟踪前缀最大值如何演变的幼稚尝试。 

一个常见的错误想法是假设我们可以通过猜测前缀最大值来独立重建每个元素。 这会失败，因为前缀最大值本身取决于早期重建的值，并且早期的任何不一致都会向前传播并使后来的重建无效。 

例如，如果我们错误地假设前缀最大值保持很小，我们可能会重建违反后续约束的值，其中提供的差异意味着更大的隐藏值。 位置之间的耦合使得独立重建变得不可能。 

## 方法

 暴力策略将尝试通过猜测隐藏前缀最大序列来重建原始数组。 在每个索引处，我们可以尝试与早期位置一致的所有可能的先前最大值，并验证结果重建是否与给定的转换数组匹配。 这很快就会爆炸，因为每个位置都可能分支到许多可能的最大状态，并且在最坏的情况下，超过 n 个位置就会呈指数增长。 

关键的观察结果是，该变换定义了隐藏数组与其前缀最大值之间的确定性关系。 如果我们从左到右处理数组，我们可以重建原始值，同时保持重建前缀的当前前缀最大值。 

在索引 i 处，如果我们已经知道 a₁ 到 aᵢ₋₁ 的前缀最大值，则定义直接给出 xᵢ。 由于 bᵢ = aᵢ − xᵢ，我们可以重写 aᵢ = bᵢ + xᵢ。 这意味着一旦 xᵢ 已知，aᵢ 就立即固定。 计算 aᵢ 后，我们更新后续步骤的前缀最大值。 

整个重建过程简化为维持运行最大值并在每一步应用直接公式。 问题变成了对原始定义的简单反向模拟。

 ## 算法演练

 我们从左到右重建数组，同时保持所有先前重建值的最大值。

1. 从一个空前缀开始，到目前为止看到的最大值是 0。这符合第一个前缀最大值始终为零的定义。 
2. 对于从 1 到 n 的每个索引 i，在放置 aᵢ 之前计算当前前缀最大值。 该值恰好是 max(a₁, ..., aᵢ₋₁)，我们将其维护为运行变量。 
3. 使用直接关系 aᵢ = bᵢ + current_max 计算 aᵢ。 这是有效的，因为 bᵢ 被定义为该位置的真实值与前缀最大值之间的差。 
4. 计算 aᵢ 后，将运行最大值更新为 max(current_max, aᵢ)。 这确保了未来的位置使用正确的前缀最大值。 
5. 重复直到重建所有值。 

该逻辑永远不需要回溯，因为每一步都确定性地修复了当前值和未来状态。 

### 为什么它有效

 在每个位置 i，算法都保持 current_max 等于 max(a₁, ..., aᵢ₋₁) 的不变式。 因为 aᵢ 的计算方式为 bᵢ 加上该值，所以它满足变换的定义方程。 更新最大值可以保留下一次迭代的不变量。 由于每个步骤都强制执行用于生成 bᵢ 的精确约束，因此重建的数组是唯一有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
b = list(map(int, input().split()))

a = [0] * n

cur_max = 0
for i in range(n):
    a[i] = b[i] + cur_max
    if a[i] > cur_max:
        cur_max = a[i]

print(*a)
```解决方案直接根据定义进行重构。 变量`cur_max`跟踪重构前缀的前缀最大值。 对于每个位置，我们首先使用之间的逆关系计算隐藏的原始值`a[i]`,`b[i]`，以及前缀最大值。 然后我们更新运行最大值以确保后续索引的正确性。 

一个常见的错误是在计算之前更新最大值`a[i]`。 这会颠倒依赖性并产生不正确的结果，因为`b[i]`是使用之前的最大值定义的，而不是更新后的最大值。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    b = list(map(int, input().split()))

    a = [0] * n
    cur_max = 0

    for i in range(n):
        a[i] = b[i] + cur_max
        cur_max = max(cur_max, a[i])

    return " ".join(map(str, a))

# provided sample
assert run("5\n0 1 1 -2 1\n") == "0 1 2 0 3"

# minimum size

 ## 边缘情况

 一种重要的边缘情况是所有 b 值均为零时。 对于输入：```
3
0 0 0
```该算法从 cur_max = 0 开始。每一步计算 a[i] = 0，并且 cur_max 永远不会改变。 输出保持全零，匹配唯一一致的重建。 

另一种情况是当 b 在大峰值之后包含大负值时。 例如：```
3
1000000000 -1000000000 -1000000000
```在 i = 1 时，cur_max 变为 1000000000。在 i = 2 和 i = 3 时，计算出的 a[i] 每次都变为 0，因为我们减去了大前缀最大值。 此后前缀最大值保持不变，并且重建与 xᵢ 的定义保持一致，即每个位置之前的最大前缀。
