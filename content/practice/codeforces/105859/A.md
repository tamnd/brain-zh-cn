 ## 解决方案
 ## 问题理解

 该问题描述了一组候选人以及他们之间的友谊。 我们需要计算对于每个可能的组大小可以选择多少组候选者，以便没有两个被选中的候选者是朋友。 在图术语中，每个候选者都是一个顶点，每个友谊都是一条边，因此我们正在计算按大小分组的独立集合。 输出包含每个尺寸的一个值，从 0 到`n`，其中该值是恰好包含那么多顶点的独立集的数量。 

候选人的数量可以达到40人。这是关键的限制。 对顶点进行正常的图遍历或动态编程是不够的，因为直接计算所有子集需要检查`2^40`可能性，大约是一万亿个州。 即使非常快的实现也无法在几秒钟内处理这个问题。 这个限制强烈建议将问题分成更小的部分，因为`2^20`只有一百万左右，还可以管理。 

有一些容易被忽视的案例。 当没有友谊时，每个子集都是有效的。 例如：```
3 0
```答案是：```
1 3 3 1
```只计算对或尝试贪婪地选择候选者的解决方案将会失败，因为每个可能的组都有效。 

另一种情况是当图表完成时：```
3 3
1 2
1 3
2 3
```答案是：```
1 3 0 0
```只允许空组和单个候选人。 一个粗心的实现，如果忘记检查不同半部的顶点之间的冲突，可能会计算出无效的组。 

第三种边缘情况是断开连接的图：```
4 2
1 2
3 4
```答案是：```
1 4 4 0 0
```成对的`(1,3)`,`(1,4)`,`(2,3)`， 和`(2,4)`有效，但不存在大小为 3 的组。 单独处理两个连接的组件而不正确组合它们的大小可能会给出错误的计数。 

## 方法

 直接的方法是检查候选者的每个子集并检查它是否包含友谊边缘。 对于每个`2^n`子集，我们将扫描选定的候选点并验证没有两个选定的顶点是连接的。 该方法是正确的，因为每个可能的组都只被考虑一次。 问题在于`n = 40`，子集的数量约为`1,099,511,627,776`，所以操作次数远远超出了可以及时运行的范围。 

有用的观察结果是，该图对于完整枚举来说太大，但又足够小，可以拆分。 如果我们将顶点分为两半，每半最多有 20 个顶点，则每半最多有`2^20`子集。 我们可以枚举一半的所有子集，确定哪些子集在内部有效，并存储有助于将它们与另一半组合的信息。 

对于左半部分的子集，重要的信息不仅是它的大小，还包括右半部分的哪些顶点不能用它来选择。 每个左侧顶点都有其右侧邻居的位掩码。 通过对所选左顶点的这些掩码进行“或”运算，我们知道禁止的右顶点。 其余的右侧顶点可用。 

右半部分可以用动态编程数组进行预处理。 对于右顶点的每个掩码，我们存储该掩码内包含多少个有效的独立子集，并按其大小分隔。 然后，每个有效的左子集都可以通过查看允许的掩码来查询选择兼容右子集的方法数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(2^(n/2) * n) | O(2^(n/2) * n) | O(2^(n/2) * n) | O(2^(n/2) * n) | 已接受 |

 ## 算法演练

 1. 将顶点分成两组。 让第一组包含`a`顶点和第二组包含`b`顶点，其中两个值最多为 20。这减少了指数部分`2^40`到关于`2^20`。 
2. 枚举第二组的每个子集并判断其是否是独立集。 对于每个有效子集，存储其大小。 存储的信息稍后会回答：“每个大小的有效右侧组有多少个适合这个可用集合？”
 3. 在第二组上构建子集动态规划表。 从精确掩码的值开始，并将信息传播到更大的掩码。 之后，对掩码的查询会告诉我们其中包含每个大小的多少个独立子集。 
4. 枚举第一组的每个子集。 检查第一组内部是否独立。 如果不是，则丢弃它，因为添加另一半的顶点无法修复内部友谊。 
5. 对于每个有效的左子集，计算被其友谊阻挡的右侧顶点的位掩码。 反转此蒙版以获得仍然可以使用的右侧顶点。 
6. 将可用右侧掩码的存储计数添加到答案中。 最终组的大小是左子集大小加上所选的右子集大小。 

为什么有效：原始图中的每个独立集都可以唯一地分为属于左半部分的部分和属于右半部分的部分。 检查左侧部分是否存在内部冲突，右侧部分仅在左侧友谊未禁止的顶点之间进行计数。 由于右侧预处理精确计算任何允许掩码内的所有有效子集，因此每个可能的独立集都会计算一次，并且不包含无效集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    left = n // 2
    right = n - left

    g_left = [0] * left
    g_right = [0] * right
    cross = [0] * left

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        if a < left and b < left:
            g_left[a] |= 1 << b
            g_left[b] |= 1 << a
        elif a >= left and b >= left:
            x = a - left
            y = b - left
            g_right[x] |= 1 << y
            g_right[y] |= 1 << x
        else:
            if a < left:
                cross[a] |= 1 << (b - left)
            else:
                cross[b] |= 1 << (a - left)

    total_right = 1 << right
    dp = [[0] * (right + 1) for _ in range(total_right)]
    dp[0][0] = 1

    for mask in range(total_right):
        if mask == 0:
            continue
        bit = mask & -mask
        idx = bit.bit_length() - 1
        prev = mask ^ bit

        for k in range(right + 1):
            dp[mask][k] = dp[prev][k]

        if prev & g_right[idx] == 0:
            size = prev.bit_count()
            dp[mask][size + 1] += 1

    for bit in range(right):
        for mask in range(total_right):
            if mask & (1 << bit):
                for k in range(right + 1):
                    dp[mask][k] += dp[mask ^ (1 << bit)][k]

    ans = [0] * (n + 1)
    total_left = 1 << left

    for mask in range(total_left):
        ok = True
        blocked = 0

        for i in range(left):
            if mask & (1 << i):
                if g_left[i] & mask:
                    ok = False
                    break
                blocked |= cross[i]

        if not ok:
            continue

        available = (1 << right) - 1
        available ^= blocked

        size_left = mask.bit_count()
        for k in range(right + 1):
            ans[size_left + k] += dp[available][k]

    print(*ans)

if __name__ == "__main__":
    solve()
```该图存储为位掩码，因为每一半最多有 20 个顶点。 单个整数可以表示顶点的邻居，使冲突检查的时间恒定。 

右侧预处理使用子集动态规划。 该过渡会删除一个选定的顶点，并检查添加它是否会产生冲突。 在第二个传播阶段之后，`dp[mask][k]`表示大小独立子集的数量`k`里面包含的`mask`，不仅仅是精确的掩模本身。 

在左侧枚举期间，条件`g_left[i] & mask`完全捕获所选左子集中的任何友谊。 这`blocked`mask 收集不能与当前左侧选择一起出现的每个右侧顶点。 使用剩余的顶点可以保证交叉边得到尊重。 

该实现依赖于 Python 整数能够轻松保存 20 位掩码。 不存在溢出风险，因为 Python 整数会自动增长。

 ## 边缘情况

 对于空图情况：```
3 0
```右侧预处理将每个子集标记为独立的。 在左枚举期间，没有顶点阻挡任何东西，因此每个左选择与每个右选择相结合。 答案变成二项式计数`1 3 3 1`。 

对于完整的图表情况：```
3 3
1 2
1 3
2 3
```任何包含两个顶点的左子集都会被立即拒绝，因为邻接掩码与所选掩码相交。 唯一幸存的选择是空集和单个顶点，因此输出是`1 3 0 0`。 

对于断开连接的情况：```
4 2
1 2
3 4
```选择顶点 1 不会阻塞顶点 3 或 4，因为友谊完全位于另一个组件内。 该算法将跨半阻塞掩码保持为空并允许所有兼容的右子集。 这可以正确计算四个有效对并避免创建三元组。
