 ## 解决方案
 ## 问题理解

 我们给出了四个整数，它们来自一个非常具体的构造，涉及三个未知的正整数，我们称它们为$a$,$b$， 和$c$。 黑板上的数字正好是三对的和$a+b$,$a+c$,$b+c$，以及总和$a+b+c$，但他们的顺序完全被打乱了。 

我们的工作是恢复任何有效的三元组$(a, b, c)$这可能会产生这个多重集。 

思考这个问题的一个有用的方法是，四个数字之一必须是最大的，并且最大的数字被迫是$a+b+c$，因为当每对和都严格小于全和时$a, b, c$是积极的。 一旦确定，剩下的三个数字分别对应于“总计减去一个变量”，因此每个数字都隐藏了其中一个$a$,$b$， 或者$c$。 

约束非常小，只有四个数字，因此任何超出持续工作的解决方案都已经是不必要的。 即使是对四个职位之间的分配进行简单的枚举，也会受到一个常数因子的限制。 这意味着真正的挑战不是效率，而是识别正确的不变量。 

当人们假设最大值始终是总和而不检查一致性时，就会出现常见的失败情况。 例如，如果输入是`40 40 40 60`，正确的解释是$a=b=c=20$。 如果错误地尝试将非最大元素解释为总数，则重建会立即中断。 

另一个微妙的情况是值重复。 例如，`3 6 5 4`除了通过逻辑而不是值的唯一性之外，没有唯一的排序提示。 任何依赖于独特性的方法在这里都会失败。 

## 方法

 暴力解释是尝试将四个数字中的每一个分配为候选总和，然后尝试重建$a, b, c$从剩下的三个。 对于每个选择的总数$S$，我们计算$S-x_i$对于每个其他值，并检查这三个重建的数字是否与生成成对和的原始多重集一致。 因为只有四种选择$S$，这是持续不断的工作。 

这是有效的，因为结构是刚性的：一旦总和固定，每个剩余的数字都直接映射到一个变量，除了排列之外，没有任何歧义。 

然而，这可以通过观察更强的性质来进一步简化。 正确的总和必须是多重集中最大的元素。 一旦我们接受了这一点，重建就变得确定性了：从总数中减去其他三个数字，我们立即恢复$a, b, c$。 

蛮力方法之所以有效，是因为它尝试了数字的所有可能角色。 一旦我们意识到积极性强制执行严格的排序约束，将搜索空间从四个候选者压缩为一个，这就变得没有必要了。

 | 蛮力（尝试全部）| O(1) | O(1) | O(1) | O(1) | 已接受 |
 | 最优（取最大值作为总计）| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将四个数字读入列表中。 
2. 对列表进行排序，使最大的元素位于最后。 
3. 将最大值作为总和$S = a + b + c$。 
4. 对于其他三个值中的每一个$x$, 计算$S - x$。 这些结果对应于隐藏值$a, b, c$按某种顺序。 
5. 输出三个重构值。 

步骤 4 有效的原因是每个较小的数字代表一个成对的和，例如$a+b$。 从总和中减去它就正好取消了该对中涉及的两个变量，留下第三个变量。 

### 为什么它有效

 每个输入数字要么是成对的和，要么是全和。 总和严格大于任何成对总和，因为所有变量都是正数。 一旦最大值固定为$a+b+c$, 每隔一个数$x$必须等于$S - v$对于恰好一个变量$v$。 这在剩余的三个数字和原始变量之间建立了一对一的映射，从而保证了排列的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    nums = list(map(int, input().split()))
    nums.sort()
    
    S = nums[3]
    
    a = S - nums[0]
    b = S - nums[1]
    c = S - nums[2]
    
    print(a, b, c)

if __name__ == "__main__":
    solve()
```排序步骤至关重要，因为它保证我们正确识别总和。 如果不进行排序，选择任意元素作为候选总数将需要验证逻辑。 

每个减法步骤直接对应于隔离一个未知变量。 输出的顺序并不重要，因此我们不需要跟踪哪个值对应于哪个原始变量。 

一个常见的错误是尝试直接将较小的数字分配为$a, b, c$，但这只有在通过减法变换后才有效。 输入值不是变量本身，而是它们的成对聚合。

 ## 边缘情况

 重复值场景如`40 40 40 60`证明该算法不依赖于唯一性。 选择最大值作为总计后，每次减法仍然会产生相同的值，这正是$a=b=c$。 

在输入已经接近均匀的情况下，例如`2 2 2 6`，只有在使用最大值时，关于总数的任何错误假设仍然可以正确解析，因为较小的选择会产生负值或不一致的值。 排序步骤确保这种故障模式不会发生。 

另一个微妙的情况是当值紧密聚集时，例如`1 2 3 6`。 这里每个数字看起来都像是一个总和，但只能是`6`足够大，可以作为总数。 即使对角色的直觉很弱，减法步骤也能清晰地分离结构。
