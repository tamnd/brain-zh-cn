 ## 解决方案
 ## 问题理解

 该问题描述了一名学生选择参加俱乐部会议。 每个俱乐部都有一个会议时间，并提供一定数量的披萨片。 由于会议重叠，两个俱乐部不能在同一时间同时参加。 学生还规定了在吃饱之前可以吃的最大切片数量。 目标是选择一组俱乐部，使参加俱乐部的数量最大化，同时将披萨总数保持在限制范围内。 

输入给出俱乐部的数量、披萨容量，以及每个俱乐部的一条记录，其中包含其会议时间和披萨数量。 输出是可以选择的最大可能的俱乐部数量。 

俱乐部的数量可以达到 1000 个。尝试每个俱乐部子集的解决方案需要检查$2^{1000}$可能性，这是完全不可能的。 但小时数只有24小时，所以时间维度很小。 这强烈表明国家应该以时间而不是个别俱乐部为基础。 动态规划的解决方案大致为$24 \times c$当披萨容量最多时，状态是可行的$10^6$，因为操作数量保持在几千万左右。 

有几个容易犯的错误。 一是忘记了重叠规则。 例如：```
3 10
5 2
5 3
6 5
```正确的输出是：```
2
```首先选择最便宜的披萨的贪婪方法可以在第 5 小时将两个俱乐部视为两个选择，但这是无效的，因为只能参加第 5 小时的一次会议。 

另一个问题是错误地对待零披萨俱乐部。 考虑：```
2 0
1 0
2 1
```正确的输出是：```
1
```由于学生没有剩余名额，因此无法参加第二个俱乐部，但第一个俱乐部是免费的，应该计算在内。 

最后一种边缘情况是，几个俱乐部共享一个小时，而最好的俱乐部不是披萨最小的俱乐部。 例如：```
3 5
7 5
7 1
8 4
```正确的输出是：```
2
```在 7 点选择单片俱乐部也可以参加 8 点。 独立处理俱乐部的方法可能会错过这种交互。 

## 方法

 最直接的想法就是尝试每一个可能的球杆系列。 对于每个子集，我们检查是否没有两个选定的俱乐部共享相同的时间以及披萨总数是否在限制范围内。 如果有效，我们将保留所选俱乐部的最大数量。 这是正确的，因为每个可能的答案都出现在子集中。 问题是有$2^n$子集，即使对于几十个俱乐部来说也是不可能的，而在这里$n$可以是1000。 

关键的观察结果是，对重叠会议的限制仅取决于 24 小时可能的情况。 对于每个小时，我们只需要决定选择哪一个俱乐部（如果有）。 处理时间的顺序并不重要，因为除了消耗的披萨总量之外，在一小时选择俱乐部永远不会影响另一小时的可用选择。 

这将问题转化为背包式动态规划。 我们一一处理。 该状态表示在考虑某些小时前缀后已使用了多少披萨，并存储了该数量可实现的最大俱乐部数量。 对于每一个小时，我们要么跳过这一个小时，要么选择其中一个俱乐部。 

俱乐部总数为1000个，但俱乐部只有24组。 对于每个小时，我们可以尝试该时间的所有俱乐部和所有可能的披萨数量，给出一个实际的界限。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 最佳DP |$O(24 \times n \times c)$在最坏的情况下|$O(c)$| 已接受 |

 ## 算法演练

 1. 按会议时间对所有俱乐部进行分组。 每小时都会有一个可以选择的俱乐部列表。 
2. 创建一个动态规划数组，其中`dp[x]`存储可以参加的俱乐部的最大数量`x`加工几个小时后的披萨片。 最初，只能使用零个披萨，所以`dp[0] = 0`。 
3.一次处理24小时。 对于当前小时，创建一个以先前状态开始的新数组。 这代表选择在这个时间不参加俱乐部。 
4. 在当前时间尝试每个俱乐部。 对于之前的每个披萨数量`x`，如果添加该俱乐部的披萨未超出容量，则用另外一个参加的俱乐部更新新状态。 
5. 用新状态替换旧状态并继续下一小时。 
6. 处理完所有时间后，存储在 DP 数组中任意位置的最大值就是答案，因为学生可能还有剩余的披萨的最终数量。 

这样做的原因是，在处理几个小时后，关于过去所需的唯一信息是消耗了多少比萨饼以及获得的最大俱乐部数量。 创建该状态的确切选择不再重要。 每个有效的时间表都对应于通过小时转换的一条路径，并且每个转换都遵循每小时只能选择一个俱乐部的规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())

    hours = [[] for _ in range(24)]

    for _ in range(n):
        t, p = map(int, input().split())
        if p <= c:
            hours[t].append(p)

    dp = [-10**9] * (c + 1)
    dp[0] = 0

    for clubs in hours:
        ndp = dp[:]

        for pizza in clubs:
            for used in range(c - pizza + 1):
                if dp[used] != -10**9:
                    ndp[used + pizza] = max(
                        ndp[used + pizza],
                        dp[used] + 1
                    )

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```输入立即按小时分组。 比萨饼数量多于总容量的俱乐部将被忽略，因为它们永远不会出现在有效答案中。 

DP 数组对无法到达的状态使用不可能的负值。 这可以避免意外扩展不存在的状态。 

每个小时，复制到`ndp`是必要的。 如果直接更新`dp`，选择一个球杆可能会影响同一小时内的后续选择，从而允许计算一小时内的多个球杆。 单独的数组代表每小时贡献零或一俱乐部的规则。 

循环结束`used`停在`c - pizza`，这可以防止索引超出容量。 由于最大容量很大但小时数是固定的，因此内存使用量保持在可控范围内。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(24 \times n \times c)$| 每小时都会根据所有可能的披萨数量处理其俱乐部 |

 小时数少是关键因素。 即使球杆数量达到最大，DP 转换的数量也足以满足给定的限制。

 ## 边缘情况

 对于重叠时间的情况：```
3 10
5 2
5 3
6 5
```该算法在第 5 小时创建一组，其中包含两个可能的选择。 当处理第 5 个小时时，两种选择都会被考虑，但只有一个转换可以存活到下一个小时，因为下一个小时是从不变的前一个状态开始的。 最终的最佳状态从第 5 小时开始取出一个球杆，从第 6 小时开始取出一个球杆，产生 2 个球杆。 

对于零披萨的情况：```
2 0
1 0
2 1
```带有一片切片的球杆在 DP 之前被移除，因为它无法安装。 零切片俱乐部保持从披萨 0 到披萨 0 的过渡，并且还有一个参加的俱乐部，因此答案变为 1。 

对于最便宜的披萨本身还不够的情况：```
3 5
7 5
7 1
8 4
```处理时间 7 创建获取 5 个切片或 1 个切片的状态。 后面的一小时只能与 1 片状态结合，总共得到 5 片和 2 球。 这正是民主党旨在维护的决定。
