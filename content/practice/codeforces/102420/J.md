 ## 解决方案
 ## 问题理解

 我们有一个由 (n) 个非负整数组成的数组 (a_1,a_2,\ldots,a_n)。 我们需要每三个不同元素的乘积之和，其中索引必须满足 (i<j<k)：

 [
 \sum_{1\le i<j<k\le n} a_i a_j a_k。 
]

 所选三元组内的顺序并不重要，但每组三个不同位置必须恰好贡献一次。 答案需要模 (10^9+7)。 

困难来自于(n)的大小。 对于 (n\le 10^6)，检查每个三元组是不太实际的。 三元组的个数是

 [
 \binom{n}{3},
 ]

 达到

 [
 \binom{10^6}{3}=166666166667000000
 ]

 在最大尺寸。 即使计算一个乘积只需要一些基本操作，迭代大约 (1.67\cdot10^{17}) 三元组也远远超出了任何合理的时间限制。 

值 (a_i) 也可以大到 (10^6)，因此数学答案是巨大的。 我们必须执行算术模（10^9+7），并且实现应该定期减少中间值，而不是允许不必要的大整数累积。 

有几种边缘情况可能会暴露出不正确的实现。 在元素数量最少的情况下，输入```
3
1 2 3
```正好有一个三元组，所以答案是 (1\cdot2\cdot3=6)。 如果实现意外地需要四个元素，或者在将贡献添加到答案之前开始更新对和，则可能会导致此边界情况错误。 

零值是另一个有用的例子。 为了```
4
0 5 6 7
```每个包含零的三元组没有任何贡献，只留下 (5\cdot6\cdot7=210)。 基于除法或假设每个值都是正数的公式在这里可能会出现错误。 

重复值需要将位置（而不是数值）视为不同的选择。 例如，```
4
2 2 2 2
```有四个三元组，每个三元组贡献 (8)，所以答案是 (32)。 尝试枚举不同值组合而不是索引组合的实现会错误地计算此值。 

最后，仍然必须正确处理非常大的值模 (10^9+7)。 例如，```
3
1000000 1000000 1000000
```答案为 (10^{18})，即 (49) 模 (10^9+7)。 各个输入值非常适合标准整数类型，但乘积和总和的增长速度要快得多。 

## 方法

 直接解法遵循字面定义。 我们选择(i)，然后(j>i)，然后(k>j)，计算(a_i a_j a_k)，并将其添加到答案中。 这是正确的，因为每个有效的索引三元组都被访问一次。 

问题在于迭代次数。 对于 (n=10^6)，三个嵌套循环对每个循环执行一次

 [
 \binom{10^6}{3}=166666166667000000
 ]

 可能的三元组。 即 (O(n^3))，这太慢了。 

有用的观察是包含当前元素的三元组不需要显式构造。 假设我们从左到右处理数组并当前检查 (a_k)。 每个在位置 (k) 结尾的新三元组具有以下形式

 [
 a_i a_j a_k,\qquad i<j<k。 
]

 我们可以分解出 (a_k)：

 [
 a_k\sum_{i<j<k}a_i a_j。 
]

 因此，在处理(a_k)之前，我们只需要知道已经处理过的元素中每对的乘积之和即可。 

拨打此数量`pair_sum`。 我们还需要所有先前元素的总和，因为当 (a_k) 成为一对的一部分时，每个先前元素都与其形成一个这样的对：

 a_k\sum_{i<k}a_i.
 ]

 因此两个运行值就足够了。`sum1`存储先前元素的总和，以及`sum2`存储先前元素中所有对的乘积之和。 

处理(x=a_k)时，现有`sum2`精确地表示 ((i,j)) 与 (i<j<k) 的对。 将其乘以 (x) 添加以 (k) 结尾的每个新三元组：

 [
 \text{答案}\mathrel{+}=x\cdot\text{sum2}。 
]

 之后，(x) 必须成为所有未来对的一部分。 这些新对的总乘积总和

 [
 x\cdot\text{sum1},
 ]

 所以我们更新

 [
 \text{sum2}\mathrel{+}=x\cdot\text{sum1}。 
]

 最后，(x) 可以作为前一个元素：

 [
 \text{sum1}\mathrel{+}=x。 
]

 这些更新的顺序至关重要。 答案必须使用旧的`sum2`，因为以当前位置结尾的三元组必须使用两个较早的位置。 如果我们更新了`sum2`首先，当前元素可能会意外地被使用两次。

 | --- | --- | --- | --- |
 | 蛮力 | (O(n^3)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳| (O(n)) | (O(n)) | (O(1)) 额外 | 已接受 |

 ## 算法演练

 1. 初始化`sum1 = 0`,`sum2 = 0`， 和`answer = 0`。 在处理任何内容之前，没有先前的元素，没有先前的对，也没有先前的三元组。 
2. 从左到右读取每个数组值 (x)。 我们按照自然顺序处理仓位，以便每个新创建的三元组自动按升序排列其索引。 
3. 将 (x\cdot\text{sum2}) 添加到`answer`。 就在此时此刻，`sum2`包含两个索引严格位于当前位置之前的所有产品 (a_i a_j)。 将它们中的每一个乘以 (x) 创建每个三元组，其最后一个索引是当前位置。 
4. 更新`sum2`通过添加 (x\cdot\text{sum1})。 这里`sum1`包含每个先前处理的值，因此这会精确创建由当前元素和一个较早元素组成的所有对。 
5. 更新`sum1`添加 (x)。 当前元素现在是稍后处理的每个位置的前一个元素。 
6. 执行算术模 (10^9+7)。 由于加法和乘法遵循模运算，因此以模为模减少每个运行量会得到与首先计算全整数完全相同的最终余数。 

### 为什么它有效

 处理前 (k) 个元素后的不变式是`sum1`等于

 [
 \sum_{i=1}^{k}a_i,
 ]

 同时`sum2`等于

 [
 \sum_{1\le i<j\le k}a_i a_j,
 ]

 和`answer`等于

 [
 \sum_{1\le i<j<l\le k}a_i a_j a_l。 
]

 当下一个值 (a_{k+1}) 到达时，乘以旧值`sum2`by (a_{k+1}) 精确地添加最大索引为 (k+1) 的所有三元组。 更新中`sum2`然后添加所有涉及 (a_{k+1}) 的新对，并更新`sum1`添加新元素本身。 任何三元组都不能添加两次，因为每个三元组都是在处理其最大索引时添加的，并且不会出现无效三元组，因为`sum2`仅包含较早位置的对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n = int(input())

    sum1 = 0
    sum2 = 0
    answer = 0

    for _ in range(n):
        x = int(input().split()[0]) if False else None
```输入包含第二行的所有 (n) 个数字，因此直接流循环`input().split()`在 Python 中更可取。 完整的实现是：```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n = int(input())
    a = map(int, input().split())

    sum1 = 0
    sum2 = 0
    answer = 0

    for x in a:
        answer = (answer + x * sum2) % MOD
        sum2 = (sum2 + x * sum1) % MOD
        sum1 = (sum1 + x) % MOD

    print(answer)

if __name__ == "__main__":
    solve()
```第一个状态变量，`sum1`，表示处理后前缀的一阶基本对称和。 第二个，`sum2`, 表示二次对称和。 答案本身就是三阶对称和。 

答案之前更新过`sum2`。 这是实现中最微妙的部分。 考虑当前值 (x)。 在处理它之前，`sum2`包含完全由早期元素形成的对，这正是使用 (x) 创建有效三元组所需的。 答案更新后，将 (x\cdot\text{sum1}) 添加到`sum2`为后面的元素准备状态。 

该代码采用的值`map`，因此它不会根据输入构造第二个 Python 整数列表。 输入行本身仍然被标记化`split`，这适合该问题的规模并保持实现简单。 

Python 整数不会溢出，但每次状态更新后仍会执行模归约。 除了保持数字较小之外，这使得与数学模计算的对应关系变得明确。 

对于前两个元素没有特殊处理。 最初`sum2`为零，因此前两个值不能贡献三元组。 处理完两个值后，`sum2`包含他们的乘积，第三个值自然地创建第一个可能的三元组。

 ## 边缘情况

 ### 恰好三个元素

 对于```
3
1 2 3
```初始状态是`sum1 = 0`,`sum2 = 0`,`answer = 0`。 仅处理 (1) 更改`sum1`，给出 (1)。 处理 (2) 创建对和 (2)，而答案仍为零，因为仍然只有两个元素。 处理（3）使用旧的对和，所以`answer = 3 * 2 = 6`。 输出是`6`。 

这会捕获一个差一错误，即实现可能会在计算当前元素的贡献之前更新对状态。 

### 零元素

 对于```
4
0 5 6 7
```处理零使所有三个状态都为零。 处理 (5) 给出`sum1 = 5`。 加工(6)产生`sum2 = 30`。 当 (7) 到达时，它贡献 (7\cdot30=210)。 输出是`210`。 

递归不需要特殊的零情况。 由于零自然会对新对和新三元组贡献零，因此相同的不变量保持不变。 

### 重复值

 对于```
4
2 2 2 2
```前两个值产生`sum2 = 4`。 第三个值贡献 (2\cdot4=8)，配对状态变为 (12)。 第四个值贡献 (2\cdot12=24)。 最终答案是（8+24=32）。 

四个索引三元组是 ((1,2,3))、((1,2,4))、((1,3,4)) 和 ((2,3,4))。 每个都有乘积 (8)，因此总数为 (32)。 递归根据最大索引对它们进行计数，在处理第四个元素时给出三个三元组，在处理第三个元素时给出一个三元组。 

### 最大值和模运算

 对于```
3
1000000 1000000 1000000
```有一个三元组，带有产品

 [
 10^6\cdot10^6\cdot10^6=10^{18}。 
]

 自从

 [
 10^{18}\bmod 1,000,000,007=49,
 ]

 正确的输出是`49`。 

该实现通过在每次更新后减少状态来计算相同的结果。 Python 本身具有任意精度的整数，但模块化归约可以保持运行状态有界并匹配所需的算术。 

### 最大数组大小

 对于 (n=10^6) 且每个值都等于 0，输入包含一百万个元素，而答案仍然为零。 该算法对每个元素精确执行一次恒定时间迭代。 它从不创建三元组的嵌套枚举，因此它的运行时间呈线性增长，而不是立方增长。 

相同的循环结构还可以处理一百万个非零值。 的价值观`sum1`,`sum2`， 和`answer`保持模 (10^9+7) 减少，因此保持状态的大小不依赖于 (n)。
