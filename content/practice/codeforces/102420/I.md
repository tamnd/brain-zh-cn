 ## 解决方案
 ## 问题理解

 我们在数组中有 (n) 个位置，但分配给这些位置的值不是固定的。 对于每次尝试，我们都会收到 (n) 个值，并且可以根据需要对它们进行排列。 

数组上有 (q) 个固定间隔。 一旦选择了排列，每个区间都会贡献其中的最大值。 排列的分数是那些 (q) 最大值的总和。 我们需要每次尝试都能独立获得最大可能的分数。 

例如，如果间隔为 ([1,2]) 和 ([2,3])，则将最大值放置在位置 2 处特别有用，因为相同的值将成为两个间隔的最大值。 问题是确定如何利用间隔之间的重叠。 

约束条件是位置数量较少，为(n\le 30)，最多有30个查询区间。 这使得每次尝试涉及二次甚至三次工作量的算法变得合理。 另一方面，可能有 1000 次尝试，因此 (n) 中的任何指数，例如枚举所有 (n!) 排列，是完全不可能的。 值可以达到 (10^9)，最终答案可以在 (q\cdot10^9) 左右，因此在具有固定宽度整数的语言中，32 位整数是不够的。 

有几种边缘情况可能会暴露不正确的实现。 

当 (n=1) 时，没有有意义的排列可供选择。 例如，对于 (n=1,m=1,q=1)、区间 ([1,1]) 和值 (42)，答案为 (42)。 假设至少有两个位置的实现可能会错误地处理选择循环。 

间隔可能完全重叠。 对于 (n=3)，如果两个区间为 ([1,3]) 和 ([1,3])，且值为 (1,5,2)，则答案为 (10)，因为值 (5) 是两个区间的最大值。 计算每个位置的初始区间覆盖一次而不删除覆盖区间会导致后续贡献不正确。 

位置也可以不属于当前未覆盖的区间。 例如，对于(n=3)、区间([1,1])和([3,3])，在选择位置1作为最大值之后，位置2对剩余区间没有贡献。 为其赋值是无害的，但实现不得将其视为覆盖查询。 

相等的值是另一个微妙的情况。 如果多个值相等，它们的顺序不会影响分数。 例如，对于 (n=3)、一个区间 ([1,3]) 和值 (7,7,7)，每个排列都会给出 (7)。 贪婪的选择可能会任意破坏关系。 

最后，零值是有效的。 对于 (n=2)、区间 ([1,2]) 和值 (0,0)，答案为 (0)。 使用零作为位置或间隔尚未处理的指示的代码可能会悄悄地将合法值与未初始化状态混淆。 

## 方法

 直接暴力解决方案在概念上很简单。 对于 (n) 个值的每个排列，根据该排列放置值，扫描所有 (q) 个间隔，计算每个间隔内的最大值，并保留最大分数。 这是正确的，因为每个可能的顺序都被明确检查。 

问题是排列的数量。 它们有 (n!) 个，如果直接扫描每个区间，则评估一个排列可能需要 (O(qn)) 工作。 在最坏的情况下，这给出 (O(n!,qn))。 对于 (n=30)，即使单独的排列数量也约为 (2.65\cdot10^{32})，因此这种方法根本不可行。 

有用的观察来自于按降序查看值。 

假设最大值是(x)。 一旦我们决定将 (x) 放在哪里，包含该位置的每个区间都会将 (x) 作为其最终最大值，前提是该区间尚未被更大的值处理。 这样的间隔可以不予考虑。 然后我们可以放置第二大的值，然后重复。

任何时候，如果区间内没有放入大于当前放置值的值，则称该区间处于活动状态。 当前值对于包含其所选位置的每个活动间隔仅贡献一次。 

这将问题变成了位置的贪婪排序。 对于当前最大剩余值，选择最大数量的活动区间中包含的未使用位置。 选择后，将所有这些间隔标记为已覆盖。 

不明显的部分是证明这种贪婪的选择是全局最优的。 假设当前最大剩余值为(x)，最优解将其置于位置(r)。 我们的贪心算法选择位置 (p)，它至少属于与 (r) 一样多的活动区间。 

令 (y) 为最优解在 (p) 处的值。 由于 (x) 是最大的剩余值，(x\ge y)。 交换 (x) 和 (y)，将 (x) 放在 (p) 上，将 (y) 放在 (r) 上。 

包含两个位置的活动间隔不受影响。 包含 (p) 但不包含 (r) 的活动区间从 (y) 改进为 (x)。 包含 (r) 但不包含 (p) 的活动区间从 (x) 减少到 (y)。 因此总分的变化为

 [
 (x-y)\左(c_p-c_r\右),
 ]

 其中 (c_p) 和 (c_r) 是包含 (p) 和 (r) 的活动间隔的数量。 这两个因素都是非负的，因此交换永远不会减少答案。 

因此，总存在一个最优解，其最大剩余值被放置在最大有效覆盖的位置。 固定该位置后，完全相同的参数适用于其余的值和间隔。 这就给出了贪心算法。 

间隔可以用 30 位掩码表示，因为 (q\le30)。 对于每个位置，我们存储包含它的查询间隔。 另一个位掩码存储哪些间隔仍处于活动状态。 包含某个位置的活动间隔的数量只需按位与后跟人口计数即可。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n!,qn)) | (O(n+q)) | 太慢了 |
 | 贪心| 每次尝试 (O(n^2+n\log n)) | (O(n+q)) | 已接受 |

 ## 算法演练

 1. 为每个数组位置构建一个位掩码。 当且仅当查询间隔（k）包含该位置时，位（k）被设置。 由于最多有 30 个间隔，因此一个 Python 整数可以代表所有间隔。 
2. 对于一次尝试，按降序对其 (n) 个值进行排序。 我们首先处理最大值，因为它应该确定尽可能多的区间最大值。 
3. 最初将每个查询间隔标记为活动。 活动间隔尚未收到大于当前正在处理的值的值。 
4. 对于当前值，检查每个未使用的位置。 通过将其覆盖掩码与活动间隔掩码相交来计算包含该位置的活动间隔的数量。 
5. 选择数量最多的未使用位置。 如果当前值为 (x) 并且位置覆盖 (c) 个有效区间，则将 (x\cdot c) 添加到答案中。 这些 (c) 间隔现在的最终最大值固定为 (x)。 
6. 将所选位置标记为已使用，并从活动蒙版中删除包含该位置的每个间隔。 这些间隔永远不需要再次考虑，因为所有后面的值都不大于当前值。 
7. 继续使用下一个值，直到分配完每个位置。 已经覆盖的区间不再有任何贡献，而之前未覆盖的每个区间最终都会被其中第一个选定的位置覆盖。 

### 为什么它有效

 不变量是，在处理前 (k) 个最大值之后，从活动集中删除的每个间隔已经具有由这些 (k) 个值之一固定的最终最大值。 每个活动间隔仅包含未使用的位置，因此其最终最大值必须来自其余值之一。

对于下一个最大值 (x)，请考虑剩余值的任何最佳排列。 如果 (x) 放置在位置 (r)，而贪心算法选择位置 (p)，则将 (x) 与 (p) 处的值交换，分数会改变

 [
 (x-y)(c_p-c_r)\ge0。 
]

 第一个因子是非负的，因为 (x) 是最大剩余值，第二个因子是非负的，因为贪婪头寸具有最大的主动覆盖范围。 因此，最优安排总是可以转化为与贪婪选择一致的安排。 

反复应用这个交换论证证明了每个贪婪选择都可以扩展到最优完全排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    q = int(input())

    intervals = []
    for _ in range(q):
        l, r = map(int, input().split())
        intervals.append((l - 1, r - 1))

    # cover[p] is a bitmask of all intervals containing position p.
    cover = [0] * n

    for k, (l, r) in enumerate(intervals):
        bit = 1 << k
        for p in range(l, r + 1):
            cover[p] |= bit

    full_mask = (1 << q) - 1

    answers = []

    for _ in range(m):
        values = list(map(int, input().split()))
        values.sort(reverse=True)

        active = full_mask
        used = [False] * n
        ans = 0

        for value in values:
            best_pos = -1
            best_count = -1

            for p in range(n):
                if used[p]:
                    continue

                count = (active & cover[p]).bit_count()

                if count > best_count:
                    best_count = count
                    best_pos = p

            ans += value * best_count
            used[best_pos] = True

            # Every active interval containing best_pos is now fixed.
            active &= ~cover[best_pos]

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```第一个预处理循环将每个间隔转换为位置覆盖掩模。 例如，如果存在三个间隔，并且位置 2 属于间隔 0 和 2，则其掩码设置了位 0 和 2。 

对于每次尝试，以相反的顺序对值进行排序可以准确地给出贪婪交换参数所需的序列。 这`active`mask 最初包含所有 (q) 个区间。 

表达式`(active & cover[p]).bit_count()`精确计算包含位置的活动间隔`p`。 因为 (q\le30)，整组间隔都适合一个整数。 

选择后`best_pos`, 表达式`active &= ~cover[best_pos]`删除包含该位置的所有间隔。 Python 整数具有无界表示，因此补码`~cover[best_pos]`可能包含无限多个概念上的 1 位，但将其与非负数进行 AND 运算`active`mask 仅清除与所表示的间隔相对应的位。 

在移动到下一个值之前，该位置被标记为已使用。 这可以防止将两个值分配给同一数组位置。 

Python 整数还可以直接处理潜在的大答案。 在具有 32 位整数的语言中，(30\cdot10^9) 左右的答案会溢出，因此需要 64 位整数。 

使用`bit_count()`在这里特别方便，因为查询间隔的数量最多为 30，使得覆盖状态自然地适合一个机器大小的整数。

 每个查询间隔恰好由一个位置组成，因此每个位置最初恰好覆盖一个活动间隔。 这些值按从最大到最小的顺序进行处理。 

对于第一个测试用例，值为 (2,1,1,1,1)。

 ## 边缘情况

 对于最小大小的情况，输入由 (n=1)、一个查询 ([1,1]) 和值 42 组成。唯一的位置有一个活动区间，因此贪心算法选择它，添加 (42\cdot1)，删除区间，然后输出 42。 

对于完全重叠的区间，假设 (n=3)，区间为 ([1,3])、([2,3]) 和 ([1,2])，每个值为 7。每个位置最初覆盖两个或三个区间，但无论选择哪个位置，包含该位置的每个区间都会被删除。 由于所有值都相等，因此交换参数允许任何平局打破，最终答案仍然是 7 的三个贡献，即 21。 

对于到达右边界的区间，请考虑具有区间 ([1,1])、([4,4]) 和 ([2,4]) 以及值 (10,1,2,20) 的输入。 位置 4 覆盖了两个有效间隔，因此 20 被放置在那里并贡献 (40)。 唯一剩余的活动间隔是 ([1,1])，因此 10 被放置在位置 1 处并贡献另外 10。答案是 50。这证实了间隔端点被包含处理。 

对于相等的值，交换证明使用 (x-y\ge0)。 当 (x=y) 时，交换它们不会改变任何结果，因此任意平局打破都是有效的。 因此，该实现不需要对重复值进行任何特殊处理。 

对于零值，请考虑 (n=2)、一个区间 ([1,2]) 和值 (0,0)。 贪心算法仍然选择一个位置，因为它的主动覆盖率为 1，添加 (0\cdot1=0)，删除间隔，并获得正确答案 0。零值永远不会用作哨兵，因此不能将其与未处理状态混淆。 

最大尺寸情况有 (n=q=30) 并且所有 30 个区间都等于 ([1,30])。 每个位置涵盖所有 30 个区间，因此第一个值和最大值立即固定每个区间。 如果值为 (1,2,\ldots,30)，则最大值 30 贡献 (30\cdot30=900)，而后面的每个值贡献为零，因为没有剩余的活动间隔。 结果是 900。这说明了为什么在每次贪婪选择之后都必须删除覆盖区间。
