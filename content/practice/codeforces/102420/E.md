 ## 解决方案
 ## 问题理解

 我们有 (n) 个伐木工人的有序序列。 伐木工 (i) 在一个区间 ([l_i,r_i]) 工作，并在该区间将墙降低半米。 对于选定的连续伐木工人组 (a,a+1,\ldots,b)，我们需要墙上每个坐标处的总减少量为整数。 

由于每个贡献都是 (0.5)，所以唯一重要的是平价。 在每个坐标处，覆盖该坐标的选定间隔的数量必须是偶数。 答案是满足该奇偶校验条件的伐木工人的连续子数组的数量。 

官方限制允许（n=200,000），而竞赛页面给出了 2 秒的时间限制和 512 MB 的内存。 (O(n^2)) 枚举在最坏的情况下执行大约 (n(n+1)/2)，大致为 (2\cdot10^{10}) 子数组检查。 即使每张支票都非常便宜，也远远超出了时间限制。 我们需要一个线性或近线性算法。 

坐标可以小到 (-10^9)，大到 (10^9)，因此将每个整数坐标视为数组索引是不可能的。 只有间隔端点很重要，它最多为我们提供 (2n) 个相关坐标。 

有几种边缘情况很容易被错误处理。 例如，对于一个伐木工来说，答案是零：```
1
1 2
```一个间隔在([1,2])上贡献了半米，因此它本身永远无法形成整数变化。 由于端点不同而对每个间隔进行计数的实现将是错误的。 

第二个常见错误是忘记当一组间隔完全取消时允许空更改。 例如：```
2
1 3
1 3
```答案是 (1)，因为选择两个伐木工会使 ([1,3]) 上正好减少一米。 更一般地说，当我们只考虑奇偶性时，相同的间隔会成对抵消。 

负坐标也必须在没有特殊处理的情况下工作：```
2
-5 -2
-5 -2
```答案仍然是（1）。 任何基于坐标直接数组索引的解决方案都会在这里失败，除非它执行坐标压缩。 

最后，一个间隔可以与另一个间隔的端点具有相同的端点，但间隔不必相同。 例如：```
3
1 2
2 3
1 3
```答案是（1）。 这三个间隔在奇偶校验级别一起取消，而没有适当的非空前缀可以取消。 仅推理间隔长度或仅共享端点数量的解决方案将错过实际的奇偶校验结构。 

## 方法

 直接的方法是检查每一对 ((a,b))。 对于每个选定的子数组，我们可以维护覆盖每个相关坐标的选定间隔的数量，并检查所有这些计数是否为偶数。 这是正确的，因为身体条件恰好是每半米贡献出现偶数次。 即使使用坐标压缩和高效更新，也有 (\Theta(n^2)) 个可能的子数组。 对于 (n=200,000)，有 (20,000,100,000) 个，因此二次方法不可行。 

有用的观察来自于通过其端点而不是通过其内部的每个点来查看区间。 想象一下沿着数轴行走。 当我们穿过端点时，活动间隔数量的奇偶性会发生确切的变化。 间隔 ([l,r]) 在 (l) 处切换奇偶校验，并在 (r) 处切换回奇偶​​校验。 因此，如果我们表示具有奇数重数的端点坐标集，则通过恰好切换两个坐标（l）和（r）来表示区间。 

对于间隔集合，当每个端点坐标出现偶数次时，最终的覆盖奇偶校验在任何地方都为零。 用代数术语来说，每个区间都是 (\mathrm{GF}(2)) 上的向量，其两个端点为 (1)，并且当所有这些向量的 XOR 为零时，所选组恰好有效。 

现在考虑前缀组。 令 (P_i) 为伐木工人 (1) 到 (i) 的端点向量的 XOR，其中 (P_0=0)。 (a) 到 (b) 的区间进行异或运算

 [
 P_b \o加上P_{a-1}。 
]

 恰好在以下情况下该 XOR 为零：

 [
 P_b=P_{a-1}。 
]

 因此，原来的问题变成了一个熟悉的前缀状态计数问题：计算每个伐木工之后的状态并计算相等的状态。 如果一种状态已出现 (k) 次，则下一次出现将创建 (k) 个新的有效子数组。 

这些状态实际上是最多 (2n) 个坐标的奇偶校验集，因此按字面存储它们的成本太高。 我们可以给每个坐标一个随机的 128 位指纹，并对端点的指纹进行异或。 对于两个独立的 64 位组件，相等的奇偶校验集始终会产生相同的指纹，而两个不同奇偶校验集发生冲突的概率可以忽略不计。 新的随机种子使得专门构造输入数据以引起冲突是不切实际的。 

蛮力方法之所以有效，是因为它显式检查每个区间组，但会失败，因为组的数量是平方数。 出于奇偶性目的，观察到间隔完全由其两个端点表征，这让我们可以将每个组转换为前缀 XOR 比较，从而将整个任务减少为使用哈希映射的一次传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n^2)) 或更糟 | (O(n)) | (O(n)) | 太慢了|
 | 带有 128 位指纹的前缀 XOR | (O(n)) 预期 | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

1. 为每个坐标分配一个随机的 128 位指纹，表示为两个独立的 64 位整数。 相同的坐标必须始终接收相同的指纹对，而不同的坐标几乎肯定应该接收不同的指纹。 
2. 从前缀状态 ((0,0)) 开始。 这代表了伐木工的空集合。 将此状态放入计数为 (1) 的频率图中，因为每个等于它的后续前缀都会形成一个从伐木工 (1) 开始的有效子数组。 
3. 从左到右加工伐木工。 对于区间 ([l_i,r_i])，将 (l_i) 的指纹和 (r_i) 的指纹异或到当前前缀状态。 两个端点都会切换，因为进入和离开时间隔会更改活动覆盖奇偶性。 
4. 在频率图中查找新的前缀状态。 如果它之前出现过 (k) 次，则在答案中添加 (k)。 每个先前的出现都对应于一个前缀 (P_j) 和 (P_j=P_i)，并且伐木工人 (j+1,\ldots,i) 因此具有零 XOR。 
5.增加当前状态的频率。 该状态现在可用于形成在稍后位置结束的有效子数组。 
6. 当所有(n)个伐木工人都处理完后，输出累积的答案。 

### 为什么它有效

 对于每个坐标 (x)，仅当间隔在 (x) 开始或结束时，所选覆盖范围的奇偶校验才会发生变化。 因此，一个间隔恰好贡献两个奇偶校验切换，每个端点一个。 当每个坐标被切换偶数次时，一组间隔在各处都有整数高度变化，这正是当它们的端点向量的异或为零时。 

前缀状态(P_i)存储前(i)个间隔的XOR。 当 (P_{a-1}\oplus P_b=0) 或等效 (P_{a-1}=P_b) 时，子数组 (a,\ldots,b) 的端点奇偶校验为零。 频率图准确地计算了 (a-1) 有多少个选择给出了这种等式。 因此，每个有效子数组都会被计算一次，并且不会计算无效子数组。 

唯一的近似方法是用随机 128 位指纹替换完整奇偶校验向量。 理论上，两个不同奇偶校验向量之间的冲突可能会产生错误的答案，但对于两个独立的 64 位值，对于此输入大小，概率可以忽略不计。 

## Python 解决方案```python
import sys
import random

input = sys.stdin.readline

MASK = (1 << 64) - 1
SM_CONST = 0x9E3779B97F4A7C15

def splitmix64(x):
    x = (x + SM_CONST) & MASK
    x = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B9 & MASK
    x = (x ^ (x >> 27)) * 0x94D049BB133111EB & MASK
    return (x ^ (x >> 31)) & MASK

def solve():
    n = int(input())

    seed1 = random.SystemRandom().getrandbits(64)
    seed2 = random.SystemRandom().getrandbits(64)

    state1 = 0
    state2 = 0

    freq = {(0, 0): 1}
    answer = 0

    def fingerprint(x):
        # x is allowed to be negative, so normalize it to 64 bits.
        ux = x & MASK
        h1 = splitmix64(ux ^ seed1)
        h2 = splitmix64(ux ^ seed2)
        return h1, h2

    for _ in range(n):
        l, r = map(int, input().split())

        l1, l2 = fingerprint(l)
        r1, r2 = fingerprint(r)

        state1 ^= l1 ^ r1
        state2 ^= l2 ^ r2

        state = (state1, state2)
        answer += freq.get(state, 0)
        freq[state] = freq.get(state, 0) + 1

    print(answer)

if __name__ == "__main__":
    solve()
```这`splitmix64`函数将坐标转换为混合良好的 64 位值。 两个独立的种子产生两个独立的指纹，使前缀状态总共 128 位。 使用`& MASK`是必要的，因为 Python 整数不会自然地以 64 位换行，而混合函数是通过无符号 64 位算术定义的。 

前缀状态从零开始并插入`freq`在处理任何间隔之前。 该初始出现代表 (P_0)，这是以 lumberjack (1) 开头的子数组所需要的。 忘记它就会丢失所有有效的前缀。 

对于每个间隔，代码将两个端点指纹异或为状态。 XOR 正是奇偶校验所需的运算：两次应用相同的坐标会取消它，因为 (x\oplus x=0)。 两个端点更新的顺序并不重要。 

在增加当前状态的频率之前更新答案。 这使得映射仅代表较早的前缀。 首先添加当前状态将错误地允许零长度子数组，这不在选择范围内 (a\le b)。 

Python 整数具有任意精度，但所有指纹算术都在内部显式缩减为 64 位`splitmix64`。 最终答案本身可以大到 (n(n+1)/2)，大约 (2\cdot10^{10})，Python 可以直接处理。 

## 工作示例

 对于样本 1，区间为 ([1,3])、([2,3])、([2,3]) 和 ([1,3])。 我们可以将坐标（x）的指纹写成（A_x）。 前缀状态象征性地表示为这些指纹的异或。 

| 我| 间隔 | 前缀状态 | 以前的平等状态 | 回答 |
 | --- | --- | --- | --- | --- |
 | 0 | 无 | (0) | 1 | 0 |
 | 1 | ([1,3]) | (A_1\oplus A_3) | 0 | 0 |
 | 2 | ([2,3]) | (A_1\oplus A_2) | 0 | 0 |
 | 3 | ([2,3]) | (A_1\oplus A_3) | 1 | 1 |
 | 4 | ([1,3]) | (0) | 1 | 2 |

 在 (i=3) 处，状态等于第一个伐木工之后的状态，因此伐木工 (2) 到 (3) 形成一个有效组。 在 (i=4) 处，状态返回到零，与空前缀匹配，因此所有四个伐木工人形成另一个有效组。 答案是（2）。 

对于样本 2，区间为 ([1,2])、([2,3]) 和 ([1,3])。 

| 我| 间隔 | 前缀状态 | 以前的平等状态 | 回答 |
 | --- | --- | --- | --- | --- |
 | 0 | 无 | (0) | 1 | 0 |
 | 1 | ([1,2]) | (A_1\oplus A_2) | 0 | 0 |
 | 2 | ([2,3]) | (A_1\oplus A_3) | 0 | 0 |
 | 3 | ([1,3]) | (0) | 1 | 1 |

 只有完整的序列才返回到初始状态。 它的三个区间具有端点多重集 (1,2,2,3,1,3)，因此每个坐标恰好出现两次。 答案是（1）。

 ## 边缘情况

 单伐木工案例```
1
1 2
```从状态 (0) 开始，然后对 (1) 和 (2) 的指纹进行异或，产生非零状态，因为这两个坐标不同。 该状态之前没有出现过，所以答案仍然是（0）。 这正是我们所需要的，因为半米的贡献无法变成一整米。 

对于两个相同的区间，```
2
1 3
1 3
```第一个区间产生 (A_1\oplus A_3)。 第二个应用完全相同的异或，因此状态再次变为零。 零的频率最初为 (1)，表示 (P_0)，因此第二个前缀贡献一个有效子数组。 输出为(1)。 

对于极端坐标，```
2
-1000000000 1000000000
-1000000000 1000000000
```坐标在散列之前被标准化为无符号 64 位值。 每个端点的两次出现都收到相同的指纹，因此两个间隔在前缀状态下完全抵消。 答案是（1），负坐标没有特殊情况。 

对于最大尺寸全相等输入，每个区间具有相同的端点向量。 当子数组包含偶数个间隔时，它才有效。 对于 (n=200,000)，每个合适的起始奇偶校验有 (100,000) 个偶数长度选择，给出

 [
 100000\cdot100000=10^{10}
 ]

 有效的子数组。 前缀状态方法通过两个状态之间的重复交替来对它们进行计数，并且 Python 的整数类型安全地存储答案。
