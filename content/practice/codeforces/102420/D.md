 ## 解决方案
 ## 问题理解

 我们有两个正整数，`a`和`b`，以十进制字符串形式给出，我们考虑来自的每个整数`a`通过`b`。 我们将它们全部相乘，然后重复用十进制数字之和替换所得数字，直到只剩下一位数字。 所需的输出是最后一位数字。 

关键的难点在于`a`和`b`最多可包含 100,000 个数字。 我们无法构建产品，甚至无法安全地将端点转换为普通机器整数。 解决方案必须直接使用十进制表示形式并利用最终数字的属性，而不是按字面意思执行规定的算术。 

重复的数字和就是数字根。 对于每个正整数`x`，其数字根完全由下式决定`x mod 9`：如果余数非零，则答案是余数，而余数零对应的是数字`9`。 因此，巨大的乘积只与模有关`9`。 

有两种边缘情况通常会导致错误的解决方案。 首先，产品可以整除`9`，给出余数`0`，但最后的数字是`9`， 不是`0`。 例如，使用输入`9`和`9`，产品是`9`，所以答案是`9`。 简单打印的解决方案`product % 9`会打印`0`。 

其次，即使其端点是巨大的十进制字符串，间隔也可能很大。 例如，`1`和`100000000000000000000000000000`代表一个区间，其中因素太多而无法枚举。 尝试将每个整数相乘的解决方案不仅速度慢，而且从根本上与输入大小不兼容。 

包含五个或更少连续差异的间隔周围还有一个有用的边界。 例如，`1`通过`5`给出`120`，其数字根是`3`， 尽管`1`通过`6`给出`720`，其数字根是`9`。 发生这种转变是因为六个连续整数必然包含两个整数的倍数`3`，使他们的产品可以整除`9`。 

## 方法

 直接方法完全遵循该声明。 从产品开始`1`，我们将乘以其中的每个整数`a`通过`b`，构造所得的大整数，计算其数字和，并重复直到剩下一位数字。 这是正确的，因为它完全执行了所请求的转换。 

问题是范围大小。 为了`a = 1`和`b = 10^100000 - 1`，正好有`10^100000 - 1`因素，因此即使忽略乘以巨大整数的成本，该算法也能执行`10^100000 - 2`乘法运算。 产品本身也有一个天文数字。 这使得暴力破解变得不可能。 

解决这个问题的观察结果是数字和保留了一个数字模`9`。 如果两个正整数具有相同的模余数`9`，它们有相同的数字根，余数`0`代表为`9`。 因此，我们只需要乘积模`9`。 

这似乎仍然留下许多因素，但模数`9`给了我们一个更强大的捷径。 任何六个连续整数都包含两个倍数`3`。 因此，他们的乘积可以除以`3 * 3 = 9`，因此每个包含至少六个连续数字的区间都有最终答案`9`。 就端点而言，这意味着每当`b - a >= 5`，答案立即`9`。 

只剩下最多五个数字的区间。 我们可以直接处理这些模数`9`，因为最多有五个因素。 我们不需要它们的实际值，只需要它们的模余数`9`。 十进制字符串的余数模`9`只是其数字模之和`9`。 

剩下的技术问题是找到微小的差异`b - a`无需将 100,000 位数字的字符串转换为整数。 因为我们已经知道只有与`0`通过`5`没关系，我们可以将这些小值中的每一个添加到十进制字符串中`a`并将结果与`b`。 这仅需要对输入进行恒定数量的线性扫描。

 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 Ω(10^100000) 因子运算 | 该产品的天文数字| 太慢了|
 | 最佳| O( | a | + | b | ) | O( | a | + | b | ) | 已接受 |

 ## 算法演练

 1. 阅读`a`和`b`作为字符串。 我们特意将它们保留为字符串，因为任一端点都可能有 100,000 个数字。 
2. 计算`a mod 9`通过扫描其数字并累加余数。 这是可能的，因为十进制数满足`10 ≡ 1 (mod 9)`，因此整个数字与其数字之和相等。 
3. 检查是否`b >= a + 5`。 我们可以计算`a + 5`使用普通的十进制字符串加法并将其与`b`。 如果这个条件成立，则该区间至少包含六个整数，因此它至少包含两个整数的倍数`3`。 他们的产品可以除以`9`，最终的数字根为`9`。 
4.如果`b < a + 5`，区间最多包含五个整数。 找出确切的差异`d`通过构建`a`,`a + 1`, ...,`a + 4`作为十进制字符串并将它们与`b`。 自从`a <= b`，这些值之一必须等于`b`。 
5. 乘以`a, a + 1, ..., a + d`模数`9`。 因为`d <= 4`，这最多是五次模乘。 
6. 将所得余数转换为数字根。 余数来自`1`通过`8`已经是答案了。 剩余的`0`表示乘积是 的正倍数`9`，所以答案是`9`。 

为什么有效：在整个算法中，从产品中丢弃的唯一信息是不能影响其数字根的信息。 同余模`9`通过乘法保留，因此留数的乘积与真实乘积具有完全相同的余数。 对于至少有六个数字的区间，乘积必然包含两个可被整除的因数`3`，因此其余数保证为零。 对于较短的间隔，我们显式地乘以每个因子的残数。 因此，每个可能的间隔都由精确的模数处理`9`计算，以及从余数零到最终转换`9`精确给出重复的数字和结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def add_small(s, x):
    """Return the decimal string representing int(s) + x, where x <= 5."""
    digits = list(s)
    i = len(digits) - 1
    carry = x

    while i >= 0 and carry:
        value = (ord(digits[i]) - 48) + carry
        digits[i] = chr(value % 10 + 48)
        carry = value // 10
        i -= 1

    if carry:
        digits.insert(0, chr(carry + 48))

    return ''.join(digits)

def mod9(s):
    r = 0
    for ch in s:
        r = (r + ord(ch) - 48) % 9
    return r

def solve():
    a = input().strip()
    b = input().strip()

    # Six consecutive integers contain two multiples of 3,
    # so their product is divisible by 9.
    if b >= add_small(a, 5):
        print(9)
        return

    # Here b - a <= 4, so we can find the exact difference
    # by checking only five possibilities.
    diff = 0
    for d in range(5):
        if add_small(a, d) == b:
            diff = d
            break

    result = 1
    current_mod = mod9(a)

    for d in range(diff + 1):
        result = (result * ((current_mod + d) % 9)) % 9

    print(9 if result == 0 else result)

solve()
```这`mod9`函数实现集中观察。 它从不构造由字符串表示的巨大整数。 每个数字都可以独立处理，余数始终保留在`0`和`8`。 

这`add_small`函数仅与以下值一起使用`0`通过`5`。 它从右到左执行正常的十进制加法，因此即使是 100,000 位端点也无需整数转换即可处理。 进位可以传播整个字符串，这就是为什么循环必须继续 while`carry`是非零的。 例如，添加`5`到`999`正确产生`1004`。 

比较`b >= add_small(a, 5)`无需计算即可处理大间隔情况`b - a`。 由于输入字符串没有前导零，因此当它们的长度不同或长度相等时，普通的字典比较就足够了。 

一旦已知区间最多包含五个数字，循环就会检查确切的端点，而不是尝试计算一般的大减法。 这是对数学界限的有意使用：只有五个候选者，因此恒定数量的字符串操作就足够了。 

乘法循环使用`(current_mod + d) % 9`为连续值。 自从添加`d`到残渣`a`给出余数`a + d`模数`9`，实际的大整数永远不需要存在。 

对于此处使用的小模值，Python 的任意精度整数不会溢出，但依赖 Python 来解析 100,000 位十进制字符串`int()`是不必要的，并且还会达到 Python 的十进制转换限制。 将端点保留为字符串可以完全避免该问题。

 ## 边缘情况

 当`a = b`，乘积恰好包含一个数字，因此答案只是该数字的数字根。 用于输入`9`和`9`,`mod9("9")`为零。 该算法不打印零，而是将零余数转换为`9`，给出正确的结果`9`。 

当间隔恰好包含五个数字时，不得应用快捷方式。 用于输入`4`和`8`，因素是`4, 5, 6, 7, 8`。 他们的产品是`6720`，其中有余数`6`模数`9`，所以答案是`6`。 算法比较`b`和`a + 5 = 9`，看到`8 < 9`，并明确处理所有五个因素。 

当间隔恰好包含六个数字时，必须应用快捷方式。 用于输入`4`和`9`, 因素包括`6`和`9`。 他们的产品已经贡献了两个因素`3`，所以完整的乘积可以除以`9`。 该算法计算`a + 5 = 9`，观察到`b >= 9`，并立即返回`9`。 

端点可能有 100,000 位数字，因此将它们转换为`int()`不是解决方案的一部分。 对于由 100,000 个 9 组成的端点，算法扫描其数字以获得模数`9`残差，并且仅在比较附近的值时才使用十进制字符串加法。 这项工作在位数上保持线性。 

案例`b - a = 5`对于捕获相差一的错误特别有用。 六个数字意味着五个单位的差异，因此保证乘积可以被整除`9`。 检查的实现`b - a > 5`而不是`b - a >= 5`会错误地尝试将这种情况作为一个短间隔来处理。 例如，`4`和`9`必须产生`9`。
