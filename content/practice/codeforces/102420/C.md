 ## 解决方案
 ## 问题理解

 我们有一个循环数组`n`蜡烛。 每个位置包含三种颜色之一，`R`,`Y`， 或者`B`。 移动可能会重新着色位置`i`，但仅当两个相邻位置，`i - 1`和`i + 1`，目前有不同的颜色。 新的位置颜色`i`可以任意选择。 

任务是对初始循环串进行变换`s`进入目标循环字符串`t`，最多使用`10n`移动。 我们不需要最短的序列，因此主要的挑战是找到一个保证长度是线性的结构。 

索引是循环的，所以位置`0`有邻居`n - 1`和`1`，同时位置`n - 1`有邻居`n - 2`和`0`。 

和`n`最多`100000`，每个位置执行恒定工作量的算法是自然目标。 最初的比赛有两秒的时间限制，因此二次算法在上限上已经太慢了，而对所有颜色进行指数搜索是完全不可行的。 我们大概需要`O(n)`或者在最坏的情况下`O(n log n)`工作。 

第一种非显而易见的情况是不可能进行移动的配置。 当每个位置都有相同颜色的邻居时，就会发生这种情况，这意味着```
s[i - 1] = s[i + 1]
```对于每一个`i`。 这种配置要么是单色的，要么，当`n`是均匀的，两种颜色之间交替。 例如，```
3
RRR
RRY
```没有合法的第一步，所以正确的输出是`-1`。 

对于均匀循环，交替配置也被完全冻结。 例如，```
4
RYRY
RYRB
```无法转化，因为`RYRY`每个位置周围都有相等的邻居。 再次正确输出`-1`。 

同样的障碍也适用于目标。 无法从不同的配置到达冻结配置，因为最终的移动必须改变两个最终邻居相等的某个位置。 这些邻居在搬迁过程中没有发生变化，因此搬迁不可能是合法的。 因此```
3
RYB
RRR
```也有答案`-1`。 

有一种微妙的模式很容易被误读。 考虑```
4
RRYY
YYRR
```初始配置未冻结。 例如，位置`1`有邻居`Y`和`R`，这有所不同。 构造必须寻找两个邻居不同的位置，而不是寻找自己的颜色与两个邻居不同的位置。 在`RRYY`，没有一个位置的颜色与两个相邻位置不同，但合法的移动肯定存在。 

最后，如果`s`和`t`已经相等，答案就是零移动，即使通用配置被冻结。 例如，```
3
RRR
RRR
```有输出`0`。 

## 方法

 直接的暴力解决方案可以将循环的每种颜色视为一种状态。 有`3^n`可能的状态。 从一种状态，我们可以检查每根蜡烛并尝试每种可能的新颜色，然后执行图形搜索，直到找到目标状态。 这是正确的，因为每个合法的移动都表示为两个状态之间的边缘，并且操作是可逆的：如果一根蜡烛可以从一种颜色更改为另一种颜色，那么同一根蜡烛可以变回原样，因为它的邻居没有改变。 

问题在于州的数量。 在最坏的情况下，搜索可能会访问`3^n`配置，并检查最多`n`每个给出的位置`O(n * 3^n)`工作。 为了`n = 100000`，甚至表示状态空间也是不可能的。 

有用的观察是，三种颜色为我们提供了一种施加局部约束的方法，而不会失去下一步行动的能力。 我们可以首先将任何非冻结字符串转换为一种特殊形式，其中距离为 2 的每对位置都具有不同的颜色。 一旦这个属性成立，每个位置都可以在受控循环扫描中改变。 

假设位置`j`正在更改，我们选择的新颜色与当前的颜色不同`j - 2`和`j + 2`。 因为恰好有三种颜色，所以这样的颜色总是存在的。 聪明的部分是选择位置的顺序。 从两个紧邻不同的位置开始，然后顺时针行走。 在第一个位置，移动是合法的。 在以后的每个位置之前`j`, 前面的位置`j - 1`只是改变了与不同的颜色`j + 1`，所以两个邻居`j`是不同的。 因此每一次操作都是合法的。 

在第一次通过之后，距离二处的所有位置都不同了。 这个属性正是第二遍所需的临时结构。 

第二遍使用目标字符串来准备当前字符串以进行最终的直接分配。 选择目标位置`k`其两个目标邻居不同。 开始于`k + 1`,改变每个位置`j`颜色不同于`t[j - 2]`和当前的`s[j + 2]`。 第一次传递保证第一个这样的移动是合法的，并且相同的前驱参数使得每个后续移动都合法。 

在第二次通过之后，每个电流`s[j]`不同于`t[j - 2]`。 这意味着当我们最终从`k + 1`围绕循环并将每个位置直接设置为`t[j]`，每个位置的两个邻居在操作时保证是不同的。 唯一特殊的位置是`k`，这是使用以下事实来处理的：`k`在目标上有所不同。 

官方构造正好使用了三个循环通道，所以需要`3n`操作，舒适地低于允许的`10n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n * 3^n)`|`O(3^n)`| 太慢了|
 | 最佳|`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1.首先检查是否`s`和`t`已经相等了。 如果是，则输出零运算。 这也可以处理两个字符串都被冻结的情况，因为不需要转换。 
2. 对于每个字符串，搜索两个循环邻居具有不同颜色的位置。 这样的位置恰好是至少存在一个合法动作的位置。 如果任一字符串没有这样的位置，则它被冻结。 由于无法从不同的配置到达冻结配置并且无法离开自身，因此输出`-1`。 
3.让`i`担任某职位`s`谁的邻居不同。 开始于`i`，顺时针遍历所有`n`职位。 对于每个位置`j`，选择与两者不同的任何颜色`s[j - 2]`和`s[j + 2]`，并重新着色`j`到那个颜色。 

在`j = i`，移动是合法的，因为 的两个邻居`i`被选择为不同的。 对于以后的每一个`j`， 位置`j - 1`在它之前就被更改了，并且该更改选择了与`s[j + 1]`。 因此`s[j - 1]`和`s[j + 1]`不同，所以`j`改变是合法的。 

当整个过程结束时，每对相距两步的位置都有不同的颜色。 如果一个位置`j`被改变，它明确地不同于`j - 2`，而稍后的操作`j + 2`明确地使`j + 2`不同于`j`。 因此，该财产一直存在到通行证结束为止。 
4.找位置`k`在两个邻居不同的目标字符串中。 开始于`k + 1`，循环遍历所有位置。 对于每个位置`j`, 选择与以下颜色不同的颜色`t[j - 2]`和当前的`s[j + 2]`。 

第一个操作是合法的，因为在第一个操作之后我们知道`s[k] != s[k + 2]`。 对于每个后续操作，前一个位置`j - 1`只是重新着色为与以下不同的值`s[j + 1]`，所以当前位置有不同颜色的邻居。 

在此过程结束时，我们得到了有用的条件`s[j] != t[j - 2]`对于每一个`j`。 特别是，因为最后处理的位置是`k`，我们还有`s[k] != s[k + 2]`。 
5. 执行最后一遍，再次从`k + 1`，并简单地设置每个`s[j]`到`t[j]`。 

第一次操作于`k + 1`是合法的，因为`s[k]`和`s[k + 2]`不同。 对于正常的后期位置`j`，它的左邻居已经变成`t[j - 1]`，而它的右邻居仍然是旧的`s[j + 1]`。 从第二遍开始，`s[j + 1] != t[j - 1]`因为位置处的第二遍条件`j + 1`正是`s[j + 1] != t[j - 1]`。 因此，这两个邻居不同。 

当扫描最终达到`k`，两个邻居都已经成为目标颜色。 他们是`t[k - 1]`和`t[k + 1]`，这因选择而异`k`。 所以最后的操作也是合法的。 
6. 这三遍恰好包含`n`每个操作。 总计为`3n`，这总是至多`10n`。 

### 为什么它有效

 中心不变量是第一遍创建`s[j] != s[j + 2]`到处。 这使得第二遍可以在任意选择的目标位置开始，并且让每个后续位置的前任使该位置合法。 

第二个不变量是`s[j] != t[j - 2]`。 在最后一遍中，已经固定的左邻居位置`j`正是`t[j - 1]`，而未触及的右邻居是`s[j + 1]`。 第二个不变量在`j + 1`说这两种颜色不同。 该参数唯一改变的位置是`k`，并且目标本身保证不同的邻居。 因此每一个`3n`生成的操作是合法的，最终状态正是`t`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

COLORS = "RYB"

def find_movable(a):
    n = len(a)
    for i in range(n):
        if a[(i - 1) % n] != a[(i + 1) % n]:
            return i
    return -1

def choose_color(a, b):
    for c in COLORS:
        if c != a and c != b:
            return c
    raise RuntimeError("No color exists")

def solve_case(n, s, t):
    if s == t:
        return []

    start = find_movable(s)
    target_start = find_movable(t)

    if start == -1 or target_start == -1:
        return None

    a = list(s)
    ans = []

    # First pass:
    # make every pair of positions at distance 2 different.
    for step in range(n):
        j = (start + step) % n
        c = choose_color(a[(j - 2) % n], a[(j + 2) % n])
        a[j] = c
        ans.append((j + 1, c))

    # Second pass:
    # make a[j] different from t[j - 2] for every j.
    k = target_start
    for step in range(1, n + 1):
        j = (k + step) % n
        c = choose_color(t[(j - 2) % n], a[(j + 2) % n])
        a[j] = c
        ans.append((j + 1, c))

    # Third pass:
    # directly construct t.
    for step in range(1, n + 1):
        j = (k + step) % n
        c = t[j]
        a[j] = c
        ans.append((j + 1, c))

    assert ''.join(a) == t
    assert len(ans) == 3 * n
    assert len(ans) <= 10 * n

    return ans

def main():
    n = int(input())
    s = input().strip()
    t = input().strip()

    ans = solve_case(n, s, t)

    if ans is None:
        print(-1)
        return

    print(len(ans))
    for pos, color in ans:
        print(pos, color)

if __name__ == "__main__":
    main()
```这`find_movable`函数准确检查合法操作所需的条件。 它使用模块化索引，以便将第一根和最后一根蜡烛视为邻居。 

第一遍修改`a`就位。 重要的实现细节是，颜色是使用两步之外的位置而不是直接相邻的位置来选择的。 直接邻居决定操作是否合法，而两个位置的距离决定我们想要创建的不变量。 

第二遍使用固定目标字符串`t`在其两个排除之一中。 另一个排除来自当前的可变字符串`a`。 这种区别很重要，因为`t`绝不能修改，同时`a`表示之前所有操作之后的状态。 

循环使用`(k + step) % n`和`step`范围从`1`通过`n`。 这正是访问`k + 1, k + 2, ..., k`循环往复，所以特殊位置`k`是故意最后处理的。 

Python 整数在这里不需要特殊的溢出处理。 答案恰好包含`3n`操作最多`300000`，因此操作列表和所有索引都适合内存中。

from solution import solve_case

def run(inp: str) -> str:
    data = inp.strip().split()
    n = int(data[0])
    s = data[1]
    t = data[2]

    ans = solve_case(n, s, t)

    if ans is None:
        return "-1\n"

    out = [str(len(ans))]
    out.extend(f"{p} {c}" for p, c in ans)
    return "\n".join(out) + "\n"

def validate(inp: str, out: str):
    data = inp.strip().split()
    n = int(data[0])
    s = data[1]
    t = data[2]

    lines = out.strip().splitlines()

    if lines == ["-1"]:
        # Verify independently that at least one endpoint is frozen
        def movable(x):
            for i in range(n):
                if x[(i - 1) % n] != x[(i + 1) % n]:
                    return True

        assert not movable(s) or not movable(t)

        p = int(p)
        assert 1 <= p <= n
        assert c in "RYB"

        i = p - 1
        assert a[(i - 1) % n] != a[(i + 1) % n]

        a[i] = c

    assert ''.join(a) == t

 ## 边缘情况

 单色源完全冻结。 为了```
3
RRR
RRY
```每个位置有两个`R`邻居，所以`find_movable`回报`-1`。 由于字符串不同，算法立即返回`-1`。 它从不试图制造非法的首次操作。 

均匀的交替源也会被冻结。 为了```
4
RYRY
RYRB
```位置`1`有邻居`Y`和`Y`， 位置`2`有邻居`R`和`R`，并且相同的模式在整个循环中持续下去。 源没有可移动位置，因此算法返回`-1`。 

冻结目标同样具有限制性。 为了```
3
RYB
RRR
```源可移动，但目标不可移动。 最后进入`RRR`是不可能的，因为目标中的每根蜡烛都有相同颜色的邻居。 目标检查在构建任何序列之前捕获这一点。 

同等冻结的字符串是不同的。 为了```
4
RYRY
RYRY
```源和目标相同，因此算法在检查配置是否可移动之前返回一个空操作列表。 这是必要的，因为冻结状态本身已经是有效的最终状态。 

配置`RRYY`演示了为什么该结构搜索具有不同邻居的位置，而不是搜索其自身颜色与两个邻居不同的位置。 在```
4
RRYY
YYRR
```位置`1`有邻居`Y`和`R`，所以即使它自己的颜色是可移动的`R`。 第一遍可以从那里开始并建立距离二不变量。 

循环边界是另一个常见的误差源。 在实现中，表达式如`a[(j - 2) % n]`和`a[(j + 2) % n]`到处都在使用。 这使得位置接近`0`与附近的位置正确交互`n - 1`。 第二次和第三次传球故意在位置上完成`k`，这就是为什么他们的循环使用`range(1, n + 1)`而不是`range(n)`。 

最后，操作计数不需要与样本匹配。 示例输出只是有效序列的示例。 我们的施工总是产生`0`移动时`s == t`,`-1`当转变是不可能的，并且确切地说`3n`否则会移动。 自从`3n <= 10n`，每个成功的构建都满足所需的资源限制。
