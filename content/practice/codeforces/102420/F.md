 ## 解决方案
 ## 问题理解

 我们有 (n) 个物理立方体。 每个立方体可以显示其六个面之一上出现的任何数字，但立方体一次只能显示一位数字。 为了构建一个数字，Aurora 选择与该数字的位数一样多的立方体，并为每个数字位置分配一个不同的立方体。 立方体可以自由地重新排列，并且在构造另一个数字时可以重复使用相同的立方体集合。 

任务是找到不可能进行这种分配的最小正整数。 

立方体的有用表示不是确切的六个面，而是其上出现的一组不同数字。 如果一个立方体说`111234`，对于这个问题来说，它和立方体一样有用`112234`，因为两者都可以准确提供数字 (1,2,3,4)。 在同一个立方体上重复复制一个数字永远不会给我们该数字的两个副本，因为该立方体只能占据一个位置。 

输入最多包含 (100,000) 个立方体，用六位数字描述每个立方体。 此界限完全排除了对可能数字的直接搜索。 即使检查一个数字的成本很低，第一个不可能的数字之前的候选数也可以在 (n) 中呈指数增长。 该解决方案必须基本上处理一次立方体，并利用只有十个可能的数字这一事实。 

有几种边缘情况可能会默默地破坏一个简单的解决方案。 

首先，一个立方体上的重复面不得被多次计数。 例如，```
1
111111
```只有一个立方体能够显示数字 (1)，而不是六个独立的副本。 由于数字 (2) 从未出现过，所以正确答案是`2`。 计算面而不是立方体会错误地表明 (1) 的许多副本可用。 

其次，零不能用作第一位数字。 为了```
1
012345
```数字（1,2,3,4,5）可以组成，但数字（6）不能组成，所以答案是`6`。 简单地对称处理每个数字的方法必须小心，因为缺少零与缺少非零数字对数字的影响不同。 

第三，为每个数字单独提供足够的立方体并不总能保证两个数字的组合是可能的。 考虑```
2
012349
456788
```数字（9）恰好出现在一个立方体上，数字（0）也恰好出现在一个立方体上，即同一个立方体。 数量`9`是可能的，并且`99`不可能，但数量较小`90`这已经是不可能的了，因为可以显示 (9) 的单个立方体也是唯一可以显示 (0) 的立方体。 正确答案是`90`。 这种共享立方体的情况是不同数字类型之间唯一必须由最佳算法检查的交互。 

## 方法

 最直接的方法是按升序枚举正整数。 对于每个候选者，创建一个二分图，其左侧由其数字位置组成，右侧由立方体组成。 将包含数字 (d) 的位置连接到每个至少一个面上具有 (d) 的立方体。 当该图具有覆盖每个数字位置的匹配时，候选者是可构造的。 

这种蛮力是正确的，因为匹配正是将不同的立方体分配给数字的位置。 问题在于候选人的数量。 每个立方体的六个面限制了可用的不同数字的数量，但它们并不能阻止第一个不可能的数字具有 (\Theta(n)) 个数字。 例如，通过平衡结构，每个非零数字可以出现在大约 (2n/3) 个立方体上，因此长度约为 (2n/3) 的数字都可以通过各个数字计数测试。 枚举到该点的所有数字意味着大约 (10^{2n/3}) 个候选数字。 即使对每个候选人进行 (O(n)) 检查也是没有希望的。 

关键的观察是我们实际上不需要测试单个数字。 令 (cnt[d]) 为包含数字 (d) 的立方体数量，其中每个立方体最多对该计数贡献一次。 

假设一个数字的长度为 (k)。 如果每个非零数字出现在至少 (k) 个立方体上，并且零出现在至少 (k-1) 个立方体上，则每个 (k) 位数字都是可构造的。 我们通过一一考虑数字位置就可以直接看出这一点。 对于任何请求的非零数字，至少有 (k) 个可能的立方体，而少于 (k) 个位置可能已经消耗了立方体。 对于零，至少有 (k-1) 个可能的立方体，与有效 (k) 位数字中零位置的最大数量完全匹配。 

官方竞赛教程使用相同的方法减少每个数字的立方体计数，然后隔离零和第一个不足的非零数字之间的一个特殊相互作用。 

因此，让

 [
 L=\min\left(cnt[0]+2,\ \min_{d=1}^{9}(cnt[d]+1)\right)。 
]

 每个少于 (L) 位数字的数字都是可构造的，而某些具有 (L) 位数字的数字则不可构造。 因此，答案恰好有 (L) 位数字。 

如果零项决定 (L)，则需要太多零的最小 (L) 位数字是

 [
 100\ldots0。 
]

 如果 (L) 是非零数字，则选择最小的此类数字 (d)。 明显不可能的候选人是

 [
 ddd\ldots d． 
]

 有一个更早的候选人可以击败它，即

 [
 d000\ldots0。 
]

 该候选者需要一个包含 (d) 和 (L-1) 个包含零的立方体的立方体。 在有趣的情况下，(cnt[d]) 和 (cnt[0]) 都等于 (L-1)。 当包含 (d) 和零的立方体集合相同时，它会失败。 我们只需要知道有多少个立方体包含这两个数字，因此我们维护(both[d])。 如果

 [
 cnt[0]=cnt[d]=两者[d]=L-1,
 ]

 然后`d000...0`是不可能的，也是答案。 否则它是可构造的，并且`ddd...d`是第一个不可能数。

 | --- | --- | --- | --- |
 | 蛮力 | (O(n\cdot 10^{\Theta(n)})) | (O(n)) | (O(n)) | 太慢了 |

 ## 算法演练

 1. 读取每个立方体并将其六个面转换为十位掩码。 当该数字出现在立方体上时，该位就被准确设置。 这会自动删除重复的面孔。 
2. 对于每个数字 (d)，计算有多少个立方体设置了位 (d)。 将此值称为 (cnt[d])。 同时，对于每个非零数字 (d)，计算有多少个立方体同时包含零和 (d)，并将结果存储在 (both[d]) 中。 
3. 计算

 [
 L=\min\left(cnt[0]+2,\ \min_{d=1}^{9}(cnt[d]+1)\right)。 
]

 术语 (cnt[d]+1) 表示数字 (d) 的 (cnt[d]) 个副本可用，因此再多一个副本就需要太多的立方体。 零项移位一位，因为第一位数字不能为零。 

1、如果(L=cnt[0]+2)，输出`1`随后是 (L-1) 个零。 只有 (L-2) 个零能力立方体，而这个数字需要 (L-1) 个零能力立方体，所以这是不可能的。 由于它是其长度中最小的数字，因此它立即就是答案。 
2. 否则找到满足(cnt[d]+1=L)的最小非零数字(d)。 所有较小的非零数字至少出现在 (L) 个立方体上，而 (d) 正好出现在 (L-1) 个立方体上。 因此，完全由 (d) 组成的数字是不可能的。 
3. 检查是否`d000...0`是不可能的。 这仅在(cnt[0]=L-1)时需要考虑。 同样，由于 (cnt[d]=L-1)，当每个零能力立方体也具有 (d) 能力时，该数字是不可能精确的，反之亦然。 如果集合大小相等，则相当于 (both[d]=L-1)。 
4. 如果该特殊条件成立，则输出 (d) 后跟 (L-1) 为零。 否则输出 (d) 重复 (L) 次。 

该算法背后的不变性是所有短于 (L) 的数字都是安全的，因为每个数字都有足够的单独可用的立方体。 在长度 (L) 处，只有第一个不足的非零数字可以造成短缺，并且可以利用第二个短缺的唯一字典顺序较早的组合是`d000...0`。 其可行性仅取决于包含 (d) 和零的立方体之间的重叠。 一旦该候选被排除，每个较小的（L）数字对于每个请求的数字都有足够的可用立方体，因此重复的（d）数字是第一个不可能的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    cnt = [0] * 10
    both = [0] * 10

    for _ in range(n):
        s = input().strip()

        mask = 0
        for ch in s:
            mask |= 1 << (ord(ch) - ord('0'))

        for d in range(10):
            if mask & (1 << d):
                cnt[d] += 1

        if mask & 1:
            for d in range(1, 10):
                if mask & (1 << d):
                    both[d] += 1

    L = cnt[0] + 2
    for d in range(1, 10):
        L = min(L, cnt[d] + 1)

    if L == cnt[0] + 2:
        print('1' + '0' * (L - 1))
        return

    d = 1
    while cnt[d] + 1 != L:
        d += 1

    if cnt[0] == L - 1 and both[d] == L - 1:
        print(str(d) + '0' * (L - 1))
    else:
        print(str(d) * L)

if __name__ == "__main__":
    solve()
```第一个循环为一个多维数据集构造一个位掩码。 由于输入正好有六个字符，因此每个立方体需要恒定的时间。 重复的面孔，例如`111111`设置同一位六次但仅贡献一次计数。 

然后两个计数循环更新`cnt`。 第二个仅针对包含零的立方体运行，并记录与每个非零数字的重叠。 累积这些计数后，无需存储立方体本身。 

的计算`L`是中心边界计算。 这`+1`对于非零数字意味着 (cnt[d]) 个可用多维数据集最多可以支持 (cnt[d]) 个出现。 这`+2`对于零意味着长度为 (k) 的有效数量最多可以包含 (k-1) 个零。 

比较`L == cnt[0] + 2`故意处理有利于零候选人的平局。 例如，如果两者`100...0`和`ddd...d`不可能具有相同的长度，前者在数值上总是较小。 

寻找`d`从数字 (1) 开始，因此选择第一个不足的非零数字。 Python整数不会溢出，唯一潜在的大对象是最终答案，其长度最多为(n+1)。

 ## 边缘情况

 具有相同数字重复副本的立方体只能为其数字计数贡献一个单位。 为了```
1
111111
```立方体的掩码仅包含数字 (1)。 因此`cnt[1] = 1`和`cnt[2] = 0`。 公式给出 (L=1)，其中数字 (2) 作为第一个不足的非零数字。 算法输出`2`, which is correct.

 前导零限制会更改零的阈值。 考虑```
2
012345
678999
```Every nonzero digit appears on at least one cube, and digit (1) appears only on the first cube. 零也只出现在那个立方体上。 The first bad length is (2), and the smallest deficient digit is (1). 候选人`10`(1) 和 (0) 需要不同的立方体，但两者只能从同一个立方体中获得。 因此`10`无法建造，同时`1`可以，所以算法输出`10`。 

即使两个单独的计数看起来足够，共享立方体的障碍也是可见的。 为了```
2
012349
456788
```数字 (9) 出现在一个立方体上，零出现在一个立方体上，两次出现都属于第一个立方体。 第一个错误长度是（2），（9）是只有一个可用立方体的最小数字。 普通候选人是`99`， 但`90`在数字上排在第一位。 自从`both[9] = 1 = L-1`，算法检测到`90`不可能并输出它。 

最后，当数字完全缺失时，答案可以只有一个数字。 为了```
1
012345
```数字 (6) 的计数为零，因此 (L=1)。 该算法立即选择 (6) 作为可用立方体和输出为零的最小非零数字`6`。 一旦第一个缺失的数字已经给出了一位数的答案，就不需要对多位数字进行推理。
