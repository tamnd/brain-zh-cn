 ## 解决方案
 ## 问题理解

 我们有以下数字的排列`1`到`n`，和一个整数`c`。 一个操作精确地查看`c+1`连续的位置。 如果该间隔中的最小值位于一个端点，则该端点保持固定，而另一个端点保持不变`c`值可以任意重新排列。 

任务不是找到一种可达的排列。 我们需要在应用此类操作任意多次后可以达到的不同排列的总数，并将答案取模`998244353`。 官方声明使用相同的两个端点情况，一种是最小值在左端点，另一种是最小值在右端点。 

其地位起着决定性的作用`1`。 自从`1`是全局最小的，它永远不能被操作移动。 任何包含以下内容的操作`1`必须有`1`作为其端点。 因此，使用操作`1`只能重新排列`c`紧邻其左侧或右侧的位置`c`紧邻其右侧的位置。 

让它有`L`左边的元素`1`和`R`其右侧的元素。 两侧的操作不必交互，因此可达排列的总数是从左侧可获得的数量与从右侧可获得的数量的乘积。 

这些约束使得指数或阶乘算法不可能实现。 尽管声明允许`n`最多`500000`，总和`n`所有测试用例最多也`500000`。 这意味着预期的解决方案应该与总输入大小基本呈线性。 甚至`O(n log n)`这里是不必要的，而任何涉及`n!`可能的排列立即是不可能的。 

有几种简单的边界情况，粗心的实现可能会导致错误处理。 例如，考虑```
1
2 2
1 2
```没有长度间隔`3`，因此无法进行任何操作。 答案是`1`。 一种解决方案，可以治疗`c`旁边的位置`1`即使少于`c`头寸存在将错误返回`2`。 

另一个重要案例是```
1
3 2
2 1 3
```价值`1`位于中间，因此两侧都只有一个元素。 双方均不包含所需的`c=2`元素。 答案又是`1`。 事实是`1`有附近的元素还不够，整个组`c`可移动元素必须存在。 

另一方面，```
1
3 2
1 2 3
```右侧有两个元素`1`。 整个对可以排列，所以答案是`2`。 这是实际存在操作的最小示例。 

输入保证是排列，因此“所有相等值”测试不是此问题的有效测试。 这样的输入将违反排列的定义。 实现应该依赖于不同的值，并且不应尝试支持重复作为特殊情况。 

## 方法

 一种直接的方法是对可达排列执行广度优先搜索。 对于每个当前排列，检查每个长度间隔`c+1`。 每当最小值位于端点时，生成另一个的每个排列`c`元素并将结果数组插入到访问集中。 

这是正确的，因为每个合法操作都被显式枚举，并且 BFS 会一直持续到没有未见过的排列为止。 问题在于状态空间的大小。 可以有`n!`不同的排列，甚至检查每个状态的所有间隔已经花费`O(n · n!)`。 如果操作内的每个可能的重新排列都是显式生成的，则转换工作包含另一个因素，最多可达`c!`。 和`n`达到`500000`，这不太可行。 

周围的结构`1`给出了更小的描述。 自从`1`永远不会移动，只考虑它的一侧。 假设这一面包含`m`元素，从最接近的位置排序`1`向着外面。 

第一个`c`只要位置存在，就可以对其进行排列。 其中`c`位置，区分一个元素：最小的元素。 它可以在那些里面移动`c`位置，但它无法逃脱它们。 当另一组完整的`c`位置变得可用，同样的推理创建另一个独特的元素，其位置仅限于第一个`2c`侧面的位置。 继续向外，为每一完整组创建一个限制元素`c`职位。 

因此，如果

 [
 k=\left\lfloor\frac{m}{c}\right\rfloor,
 ]

 正是有`k`嵌套限制。 这`j`-第一个受限元素必须占据第一个`jc`职位。 当我们从允许的最小前缀到最大前缀对这些受限元素进行计数时，`j-1`位置已被先前的限制分子占据。 因此`j`-th 元素有

 [
 jc-(j-1)=j(c-1)+1
 ]

 选择。 

毕竟`k`已放置限制元素，其他`m-k`元素没有剩余限制，可以任意排列。 他们的贡献是`(m-k)!`。 

所以一方的贡献包含`m`元素是

 [
 F(m,c)=
 (m-k)!\prod_{j=1}^{k}\left(jc-j+1\right),
 \qquad
 k=\left\lfloor\frac{m}{c}\right\rfloor。 
]

如果`m<c`， 然后`k=0`, 给予`F(m,c)=m!`。 然而，这个表达式对于实际的运算规则来说是错误的，因为当少于`c`元素存在。 在这种情况下，正确的贡献是`1`。 因此我们使用

 [
 F(m,c)=
 \开始{案例}
 1,&m<c,\
 (m-k)!\displaystyle\prod_{j=1}^{k}(jc-j+1),&m\ge c.
 \结束{案例}
 ]

 最终的答案很简单

 [
 F(L,c)\cdot F(R,c)。 
]

 蛮力之所以有效，是因为它明确地探索了组合论证所描述的相同的可达状态空间。 观察关于`1`让我们用两个独立的边和少量嵌套位置限制来代替巨大的状态空间。 这与已发布的解决方案讨论中强调的结构观察相同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n · n! · c!)`在显式过渡版本中 |`O(n!)`| 太慢了|
 | 最佳|`O(n)`每个测试用例|`O(n)`| 已接受 |

 ## 算法演练

 1. 找到位置`1`。 如果是在从零开始的位置`pos`，那么有`L=pos`其左侧的元素和`R=n-1-pos`其右侧的元素。 自从`1`永远不能移动，这两条边可以独立计算。 
2. 预先计算阶乘模`998244353`直到最大的`n`。 最终边公式包含`(m-k)!`，因此常数时间访问需要阶乘值。 
3. 定义边长的贡献`m`。 如果`m<c`， 返回`1`，因为没有足够的元素来形成包含的操作`1`和`c`可移动元件。 
4.否则设置`k=m//c`。 有`k`嵌套受限元素，因为每个完整的组`c`位置又创建了一个前缀，允许在其中移动特定元素。 
5. 开始侧面贡献`(m-k)!`。 这些是在考虑了所有受限元素之后仍然完全不受限制的元素。 
6. 对于每一个`j`从`1`通过`k`, 乘以`jc-j+1`。 这`j`第-个受限元素有`jc`其允许的前缀中的可能位置，但是`j-1`这些位置中的一些已经被先前处理的限制元素占据。 
7. 独立计算左侧和右侧的贡献并将它们乘以模`998244353`。 双方并不争夺位置，因为`1`将他们永久分开。 

### 为什么它有效

 不变的是暴露后`j`完整的组`c`位置正好在一侧`j`区分元素的位置受到限制，并且`j`-第一个允许在第一个内的任何位置`jc`职位。 早期区分的元素保留在这些前缀内，而暴露区域中的所有其他元素都可以自由地重新排列。 

由于这些允许的前缀是嵌套的，因此受限制的元素可以依次放置。 在阶段`j`， 确切地`j-1`第一个内的位置`jc`位置已被先前的限制元素占据，留下`jc-j+1`选择。 一旦全部`k`放置受限制的元素，所有其他元素不受限制，给出`(m-k)!`安排。 

每个可达的安排都满足这些限制，因为操作使最小端点保持固定。 相反，操作可以通过连续暴露下一组来实现满足嵌套限制的每个排列。`c`位置并排列所有当前空闲位置。 因此，该公式对每个可达排列仅计数一次。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

MOD = 998244353

def side_ways(m, c, fact):
    if m < c:
        return 1

    k = m // c
    ans = fact[m - k]

    for j in range(1, k + 1):
        ans = ans * (j * c - j + 1) % MOD

    return ans

def solve():
    t = int(input())

    tests = []
    max_n = 0

    for _ in range(t):
        n, c = map(int, input().split())
        p = list(map(int, input().split()))
        tests.append((n, c, p))
        max_n = max(max_n, n)

    fact = [1] * (max_n + 1)
    for i in range(1, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD

    out = []

    for n, c, p in tests:
        pos = p.index(1)

        left = pos
        right = n - 1 - pos

        ans_left = side_ways(left, c, fact)
        ans_right = side_ways(right, c, fact)

        ans = ans_left * ans_right % MOD
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```对所有测试用例进行一次阶乘预计算。 这很重要，因为最多可以有`100000`测试用例，尽管它们的总长度只有`500000`。 

的位置`1`被发现与`p.index(1)`。 使用从零开始的索引，该位置恰好是其左侧元素的数量，而`n-1-pos`是其右侧的数字。 

这`m<c`检查是必要的。 公式与`k=0`会给`m!`，但当少于`c`元素存在，不存在合法区间`1`，所以边完全不变并且贡献准确`1`。 

为了`m>=c`,`k=m//c`计算完整的组`c`职位。 循环乘以`k`因素`jc-j+1`。 两边的总迭代次数为`O(n/c)`对于一个测试用例来说，最多是`O(n)`。 

Python 整数不会溢出，但每次乘法都会减少模数`998244353`。 阶乘数组还存储以相同模数为模的值。 

使用读取输入`sys.stdin.readline`，根据大总输入大小的需要。

## 边缘情况

 当一侧包含少于`c`元素，不涉及任何操作`1`可以用那一边。 例如，```
1
2 2
1 2
```右边有一个元素，小于`c=2`。 侧面贡献为`1`，并且没有其他有效区间。 算法输入`m<c`分支和返回`1`。 

什么时候`1`严格位于排列内部并且两边都短于`c`，双方都不能参加。 为了```
1
3 2
2 1 3
```两边都有长度`1`。 该算法计算`F(1,2)=1`两次，产生`1`。 

当一方恰好有`c`元素，这些元素可以任意排列。 为了```
1
3 2
1 2 3
```右侧有长度`2`。 这里`k=1`，所以贡献是

 [
 (2-1)!\cdot(2-1+1)=1\cdot2=2。 
]

 左侧有贡献`1`，给出最终答案`2`。 

当边长大于`c`，出现额外的嵌套限制。 为了`m=4,c=2`，我们有`k=2`。 贡献是

 [
 (4-2)!\cdot2\cdot3
 =2\cdot2\cdot3
 =12。 
]

 第一个受限元素有`2`可能的位置，而第二个有`4-1=3`放置第一个受限元素后的选择。 其余两个元素不受限制并贡献`2!`。 

什么时候`c=n`, 双方都不能包含`c`元素，因为它们的组合大小仅为`n-1`。 因此每个测试用例`c=n`有答案`1`。 最大尺寸测试`n=c=500000`正好行使这个边界，并由`m<c`两侧有分支。
