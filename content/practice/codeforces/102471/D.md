 ## 解决方案
 ## 问题理解

 树根位于顶点 1。Pang 从根部开始，最终必须在每个顶点施放一次魔法。 因为每个有向边最多可以使用一次，所以进入并随后通过其父级离开的子树具有完全确定的移动成本：如果子树包含`s`顶点，遍历它并返回到入口顶点使用恰好`2s`移动。 唯一的自由是处理兄弟子树的顺序以及哪个子树包含整个行走的最终顶点。 

让`a[v]`是顶点的温度`v`第一天早上之前，如果Pang在顶点施展魔法`v`当天`t`，傍晚魔术后的温度为`a[v] - t + k`。 如果他那天离开`d`, 一天的早晨`d`已经将该温度降低了适当的天数，因此源顶点必须严格为正。 目的地只需为非负数即可。 这两种不同的不等式导致了几种边界情况。 

输出是 Pang 在顶点 1 可以准备的最后一天，这意味着他当天在顶点 1 施展魔法，并在第二天做出第一步。 如果连第 0 天都无法工作，答案是`-1`。 

界限`n <= 100000`排除任何二次方，特别是因为时间限制只有一秒。 整棵树的遍历已经是线性的，所以目标本质上是`O(n)`或者`O(n log n)`。 温度和`k`值可以达到`10^9`，而子树大小可以达到`10^5`，所以中间表达式如`k + a[v] - 2 * size[v]`应在具有固定宽度整数的语言中使用 64 位算术进行处理。 Python整数具有任意精度，因此在实现中不存在溢出问题。 

一种边界情况是目标温度可能恰好为零。 考虑一个二顶点树`k = 0`和温度`2 1`。```
2 0
1 2
2 1
```答案是`0`。 Pang 在第 0 天在顶点 1 施放，在第 1 天移动，并到达温度为零的顶点 2。 要求目的地具有正温度的粗心实现将错误地拒绝这种情况。 

源顶点具有相反的条件，它必须严格为正。 与同一棵树和`k = 0`，将根部温度更改为`1`。```
2 0
1 2
1 1
```答案是`-1`。 在第 0 天施放后，根部温度为 1，但第 1 天早上将其降至零，因此庞无法移动。 仅检查目标温度会漏掉此故障。 

兄弟子树的顺序也很重要。 考虑```
5 2
1 2
1 3
1 4
4 5
100 1 100 100 100
```正确答案是`93`。 顶点 2 的截止时间非常紧迫，因此必须在以顶点 4 为根的较大子树之前访问其子树。按输入顺序处理子树可以将大子树放在第一位，并使顶点 2 无法及时到达。 即使存在有效的调度，仅尝试按邻接列表顺序进行 DFS 的解决方案也可能会失败。 

最后，第 0 天很特殊，因为那天气温没有下降。 为了```
2 2
1 2
0 1
```答案是`0`。 Pang 可以在第 0 天在顶点 1 施放魔法，将其温度从零升高到 2，然后在第 1 天移动到顶点 2，当天早上其温度恰好为零。 将第 0 天视为已经发生了第一次温度下降会失去此有效解决方案。 

## 方法

 直接方法将枚举穿过树的可能行走。 一旦树扎根，就必须进入、完全探索并返回每个非最终子子树。 最后一个子树是唯一不需要返回的子树。 对于孩子们的每一个可能的命令，我们都可以模拟日子，在每一个动作和魔法操作之前检查温度。 

这是正确的，因为每个合法的遍历都具有这种递归结构。 问题是订单数量。 一颗星与`n - 1`叶子已经有`(n - 1)!`可能的订单，并模拟每个订单需要`Theta(n)`移动。 因此，最坏情况的工作是`Theta(n * (n - 1)!)`，早在我们到达之前`n = 100000`。 

蛮力之所以有效，是因为一棵树迫使每个完成的子树都表现得像一次单次旅行。 关键的观察结果是，这种偏移具有固定的持续时间，恰好是子树中顶点数量的两倍。 一旦子子树按照可输入的最晚日期进行汇总，父级只需在截止日期之前安排这些固定持续时间的游览。 

假设孩子们`u`被排序为`v_1, v_2, ..., v_d`。 如果庞施放于`u`当天`t`，然后孩子`v_i`是在当天输入的

 [
 t + 1 + 2\sum_{j<i} 大小[v_j]。 
]

如果`f[v_i]`是完整往返行程的最晚有效抵达日`v_i`，我们需要

 [
 t + 1 + 2\sum_{j<i} 大小[v_j] \le f[v_i]。 
]

 重新排列给出

 [
 t \le f[v_i]-1-2\sum_{j<i}大小[v_j]。 
]

 这是一个调度问题。 每个孩子都有处理时间`2 * size[v]`，其有效期限为`f[v] + 2 * size[v]`。 按此值对子项进行排序会给出最佳顺序。 这与该问题的官方解决方案说明中描述的顺序相同。 

还有一个复杂的情况。 整个行走不必返回到顶点 1。事实上，它必须在叶子处结束。 因此，我们需要第二个 DP 状态，它允许遍历最终的子子树而不返回其父树。 最后一个孩子之前的孩子仍然必须按照相同的最佳顺序进行安排。 

对于一个固定的最终子项，从有序列表中删除该子项只会更改其后的子项的前缀时间。 前缀和后缀最小值让我们计算每个可能的最终孩子在恒定时间内所有剩余孩子的最佳截止日期。 因此，在对子节点进行排序后，一个顶点的整个过渡在其度数上是线性的。 

比较结果为：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`Theta(n * (n - 1)!)`在一颗星|`O(n)`| 太慢了 |
 | 最佳|`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 以顶点 1 为树根并计算自下而上的顺序。 对于每个顶点`u`， 让`size[u]`是其根子树中的顶点数。 以反向 DFS 顺序处理顶点可以保证当我们处理时每个子节点都已被解决`u`。 
2. 定义`f[u]`作为 Pang 可能到达的最晚日期`u`，在那里施展魔法，遍历整个子树`u`，返回到`u`，最后离开`u`朝向其父级。 此状态描述了一个子树，该子树的行为相当于其父树的完整往返。 
3. 对以下子项进行排序`u`通过

 [
 f[v] + 2size[v]。 
]

 对于一个孩子`v`放置在总大小为的先前子树之后`P`，其入场日为`t + 1 + 2P`，所以需要

 [
 t \le f[v]-1-2P。 
]

 排序规则是这些固定时间游览的最早有效的截止时间规则。 如果两个相邻的子项违反了此顺序，则交换它们不能使最大可行起始日变小，因此重复删除此类倒置即可得到排序顺序。 

1. 排序后，让`deadline[i]`是孩子造成的约束`i`当所有较早的子项都在它之前处理时：

 [
 截止日期[i] = f[v_i]-1-2\sum_{j<i}大小[v_j]。 
]

 所有儿童游览的最佳开始日期是这些值中的最小值。 

庞还必须生存`u`本身。 如果他开始于`u`当天`t`，初始铸造需要`t <= a[u]`。 要遍历整个子树然后离开父树，有`2size[u]-1`选角日后移动。 最终出发需要`u`是积极的，这给出

 [
 t \le a[u] + k - 2size[u]。 
]

 因此，

 [
 f[u] =
 \分钟\左(
 一个[u]，
 a[u]+k-2大小[u],
 \min_i 截止日期[i]
 \右）。 
]

 对于叶子来说，这可以减少为`min(a[u], a[u] + k - 2)`。 

1. 定义`g[u]`作为 Pang 可能到达的最晚日期`u`，在那里进行投射，遍历整个子树，并完成该子树内的任何位置。 不像`f[u]`,`g[u]`不需要最后一步`u`给它的父级。 

如果`u`是一片叶子，庞可以简单地完成那里，所以`g[u] = a[u]`。 

1. 对于内部顶点`u`, 选择一个孩子`c`成为最后一个孩子。 必须完全遍历所有其他孩子并从之前返回`c`已输入。 

让

 [
 S = 尺寸[u]-1-尺寸[c]
 ]

 是所有非最终子子树的总大小。 他们消费`2S`在输入最后一个子项之前移动。 

因此，最后一个子项只能在其自身之前或之前输入`g[c]`截止日期：

 [
 t+1+2S \le g[c],
 ]

 给予

 [
 t \le g[c]-1-2S。 
]

 庞也需要能够离开`u`为了最后一个孩子。 该举动发生在当天`t+1+2S`，因此温度条件为`u`给出

 [
 t \le a[u]+k-2-2S。 
]

 1.我们仍然需要所有非最终子节点的约束。 移除孩子`c`从排序列表中留下之前的孩子`c`不变，而之后的每个孩子`c`开始`2size[c]`几天前。 计算原始子截止日期的前缀最小值和后缀最小值。 儿童用`c`，来自所有其他孩子的最佳约束是

 [
 边（c）=
 \分钟\左(
 前缀[c],
 后缀[c+1]+2大小[c]
 \右）。 
]

 第一个术语涵盖之前的儿童`c`。 第二个学期涵盖以下儿童：`c`，其前缀变小`size[c]`。 

1. 候选人回答时`c`最后一个孩子是

 [
 候选人(c)=
 \分钟\左(
 一个[u]，
 a[u]+k-2-2S，
 g[c]-1-2S,
 侧面(c)
 \右）。 
]

 取所有孩子中的最大值。 该最大值是`g[u]`，因为每次有效的遍历都必须恰好选择一个子节点作为最终顶点所在的方向。 

1. 在根上，Pang 不需要返回到父级。 因此所需的最晚准备日正是`g[1]`。 如果`g[1] < 0`，即使第 0 天的准备也不起作用，所以答案是`-1`。 否则打印`g[1]`。 

### 为什么它有效

 中心不变量是`f[u]`正是完整处理的遍历的最新可行铸造日`u`的子树并返回到其父树，而`g[u]`正是最晚的可行铸造日，此时遍历可以在子树内的任何位置完成。 为了`f[u]`，每个子游览都有固定的持续时间和最晚允许的开始时间，因此交换两个顺序错误的相邻子游览表明排序依据`f[v] + 2size[v]`是最优的。 为了`g[u]`，每个有效的遍历都恰好有一个最终子节点。 所有其他子项都形成完整的游览，并且可以通过相同的最佳顺序进行安排。 前缀和后缀最小值精确计算删除最后一个子项后这些偏移的约束。 由于考虑了每个可能的最终孩子，`g[u]`采取最佳有效选择。 从根本上来说，每一次完整的步行都对应于一个这样的最终儿童选择，所以`g[1]`正是最晚可能的准备日。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        graph[x].append(y)
        graph[y].append(x)

    a = list(map(int, input().split()))

    parent = [-2] * n
    parent[0] = -1

    order = [0]
    for u in order:
        for v in graph[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            order.append(v)

    size = [1] * n
    f = [0] * n
    g = [0] * n

    INF = 10**30

    for u in reversed(order):
        children = [v for v in graph[u] if parent[v] == u]

        if not children:
            size[u] = 1
            f[u] = min(a[u], a[u] + k - 2)
            g[u] = a[u]
            continue

        size[u] = 1 + sum(size[v] for v in children)

        children.sort(key=lambda v: f[v] + 2 * size[v])

        m = len(children)

        deadline = [0] * m
        prefix = [INF] * (m + 1)

        used = 0
        for i, v in enumerate(children):
            deadline[i] = f[v] - 1 - 2 * used
            prefix[i + 1] = min(prefix[i], deadline[i])
            used += size[v]

        suffix = [INF] * (m + 1)
        for i in range(m - 1, -1, -1):
            suffix[i] = min(suffix[i + 1], deadline[i])

        f[u] = min(
            a[u],
            a[u] + k - 2 * size[u],
            prefix[m]
        )

        total_children_size = size[u] - 1
        best = -INF

        for i, v in enumerate(children):
            sv = size[v]

            # Remove v from the child order.
            # Children before v keep their original prefix.
            # Children after v start 2 * sv days earlier.
            side_deadline = min(
                prefix[i],
                suffix[i + 1] + 2 * sv
            )

            remaining_size = total_children_size - sv

            candidate = min(
                a[u],
                a[u] + k - 2 - 2 * remaining_size,
                g[v] - 1 - 2 * remaining_size,
                side_deadline
            )

            best = max(best, candidate)

        g[u] = best

    answer = g[0]
    print(answer if answer >= 0 else -1)

if __name__ == "__main__":
    solve()
```实现的第一部分迭代地为树求根。 避免了递归，因为一棵树`100000`顶点可以是单链，其深度足以超过Python的正常递归限制。 

反向遍历顺序计算从叶子到根的DP。 这`size`在完整的子旅行期间以及处理其所有后代后顶点处的温度约束都需要数组。 

对于每个顶点，子节点按以下顺序排序`f[v] + 2 * size[v]`。 这`deadline`数组存储铸造日的精确界限`u`由每个孩子贡献。 这`prefix`数组给出了在选定的最终孩子之前孩子之间的最短截止日期，而`suffix`给出其后的子代中的最小值。 

表达式`suffix[i + 1] + 2 * sv`很容易出错。 孩子之后`v`被删除，每个后来的孩子都开始`2 * size[v]`几天前，因此它的限制变得不那么严格。 这就是为什么后缀值必须增加而不是减少。 

之间的区别`-1`而零也是故意的。 DP 状态可能为负，因为它代表相对于父级的最近的可行选角日。 然而，从根本上来说，只有非负数天可用。 因此`g[0] == 0`是有效的，同时`g[0] < 0`意味着该实例是不可能的。 

所有算术都是直接使用 Python 整数完成的。 涉及的表达式`2 * size[u]`和`k`可以超过 32 位范围，因此固定宽度的实现应该使用`long long`。 

## 工作示例

 对于样品 1，```
3 1
1 2
1 3
4 3 5
```顶点 2 和 3 是叶子。 他们的状态是`f[2] = 2`,`g[2] = 3`,`f[3] = 4`， 和`g[3] = 5`。 

根对于最终的孩子有两种可能的选择。 

| 顶点|`size`|`f`|`g`|
 | ---| ---| ---| ---|
 | 2 | 1 | 2 | 3 |
 | 3 | 1 | 4 | 5 |
 | 1 | 3 | -1 | 1 |

 孩子们的顺序是`f[v] + 2size[v]`，首先给出顶点 2，然后给出顶点 3。 

如果顶点 2 是最终的，则必须首先处理顶点 3。 根自身的出发界限是`1`，在边游后进入最后一个子节点时给出了一个界限`0`。 因此，该候选人是`0`。 

如果顶点 3 是最终的，则首先处理顶点 2。 最终子约束给出`2`，而根的源温度约束给出`1`，所以候选人是`1`。 

最大值为`g[1] = 1`，匹配示例输出。 

对于样品 2，```
3 1
1 2
1 3
2 10 10
```两片叶子都有`f = 9`和`g = 10`。 无论选择哪一个叶子作为最终子节点，都必须首先访问并返回另一叶子。 

| 顶点|`size`|`f`|`g`|
 | ---| ---| ---| ---|
 | 2 | 1 | 9 | 10 | 10
 | 3 | 1 | 9 | 10 | 10
 | 1 | 3 | -1 | -1 |

 在一次侧向旅行之后，根部必须在温度不高的一天离开去寻找最后一个孩子。 由此产生的`g[1]`是`-1`，所以即使在第 0 天做好准备也不起作用。 输出是`-1`。 

这些痕迹演示了为什么源顶点条件不能被非负检查替换。 根在每次出发时都需要严格的正温度，并且 DP 通过`-2`条款。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n log n)`| 每个顶点的子节点都已排序，总排序成本最多为`O(n log n)`|
 | 空间|`O(n)`| 树、父/顺序数组、子树大小和 DP 状态都是线性的 |

 这棵树最多有`100000`顶点，所以`O(n log n)`很容易在预期的渐近范围内。 该实现还避免了递归 DFS，这对于最坏情况的链很有用。 临时前缀、后缀和截止时间数组仅包含当前处理的顶点的子节点，因此它们的总保留内存保持线性。

 ## 边缘情况

 零温度目的地情况由儿童到达不平等处理`t + 1 <= g[c]`。 到达后没有额外的减法，因此接受正好为零的温度。 在有温度的两顶点情况下`2 1`和`k = 0`，根可以在第 0 天施展并在第 1 天移动，到达温度为零的第二个顶点。 该算法计算`g[2] = 1`，根转移给出`g[1] = 0`，所以它打印`0`。 

严格的源条件出现在`a[u] + k - 2`叶项和内部顶点相应的离开项。 和`n = 2`,`k = 0`和温度`1 1`，根可以在第 0 天铸造，但在第 1 天早上之后温度为零。过渡产生`g[1] = -1`，正确报告不可能。 

儿童订购案例```
5 2
1 2
1 3
1 4
4 5
100 1 100 100 100
```有一个叶子孩子 2 与`f[2] = 1`和一个以 4 为根的两顶点子节点`f[4] = 98`。 他们的有效键是`3`和`102`，因此必须首先处理顶点 2。 在那次旅行之后，可以访问大子树，并且顶点 3 可以是最终子树，给出一天`93`。 前缀截止日期会自动执行此命令。 

零日案例```
2 2
1 2
0 1
```有`a[1] = 0`，因此 Pang 可以在第 0 天对根施法。魔法将其温度提高到 2。在第 1 天，根为正，顶点 2 的温度为零，因此移动是合法的。 根过渡给出`g[1] = 0`，这正是最早和最晚可能的准备日。 

对于一片叶子来说，`g[u] = a[u]`因为庞可能会到来，施展魔法，立刻完成。 当整个路径的最终顶点是叶子时，此边界至关重要。 使用往返状态`f[u]`相反，不必要地需要足够的温度来再次离开叶子，并且可能会拒绝有效的解决方案。 

什么时候`k`为零，魔法根本不会给顶点充电。 这些公式仍然有效，因为每个出发边界都包含相同的`k`学期。 什么时候`k`非常大，到达约束`t <= a[u]`相反，可以成为限制条件，这就是为什么`f[u]`必须使用两个约束的最小值，而不是假设补给条件总是更严格。 

树内的负 DP 值本身并不是错误。 它只是意味着必须在第 0 天之前输入子树才能满足其所有截止日期。 在计算祖先时，这样的状态仍然可以用作边界。 仅有的`g[1]`与零比较，因为第 0 天是 Pang 可以利用的最早准备日。 

上面的社论使用了`f/g`直接制定，因此实现遵循证明，而不需要单独的重新根通过。
