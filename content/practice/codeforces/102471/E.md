 ## 解决方案
 ## 问题理解

 该图具有特殊的形状：它由从源顶点 1 到汇顶点 n 的几条独立路径组成。 每条路线都包含相同数量的边，并且路线不共享内部顶点。 边缘上的容量可以通过单元操作来移动。 一项操作从当前具有一定容量的边缘获取一个容量单位，并将其放在另一边缘上。 

目标不是构建最终能力。 我们只需要所需的最小数量的移动单元，以便最大可能的流量变得与总容量允许的一样大。 

对于具有边缘容量的单一路线`c1, c2, ..., cl`，该路由所能承载的流量就是其最小的边缘容量。 运力重新分配后，所有航线的总运力不变。 由于每个单位的流量都需要一个单位的容量`l`一条路线的边缘，绝对最大流量为：```
total_capacity // l
```这些限制使得模拟变得不可能。 最多可以有 100000 个顶点和 200000 个边，而容量可以大到 10^9。 任何直接依赖于容量值的算法（例如一次增加一个单位的流量）可能需要数十亿次操作。 

主要隐藏的边缘情况来自这样一个事实：最佳的重新分配并不总是独立地平衡每条路径。 

考虑：```
4 3
1 2 0
2 3 100
3 4 100
```路径长度为3。总容量为200，因此最终最大流量为66。尝试使每条路径等于的贪心方法`total/l`通过直接填充所有缺失的边可能在这里可行，但是假设每个额外单元应该均匀分布的方法会失败，因为增加路径的边际成本可能会急剧变化。 

另一种情况是：```
4 3
1 2 5
2 3 5
3 4 5
```答案是 0。当前瓶颈已经是 5，总容量给出了相同的最大流量。 总是在计算理论最大值后执行重新分配的方法会错误地计算不必要的移动。 

最后一个重要的情况是零容量的路径：```
2 1
1 2 0
```最大流量为0，无需任何操作。 在分解路径时假设每条边都具有正容量的实现在这里可能会失败。 

## 方法

 直接的解决方案将反复增加某些路径的流量，直到达到全局最大值。 对于每一个额外的流量单位，它都会找到容量不足的路径边缘并将容量移入其中。 这是正确的，因为每一次操作都可以被视为为某个边缘上丢失的一个单元付费。 然而，最大流量可以约为`10^14`，所以单元模拟是不可能的。 

有用的观察来自于观察一条路径。 假设其当前瓶颈从`x-1`到`x`。 该增加所需的操作数恰好是容量小于的边的数量`x`，因为每一条这样的边都需要一个额外的单位。 这些成本对于每条路径形成一个非递减序列。 

最终的流量值是固定的。 我们需要准确选择`total_capacity // l`所有路径增量序列中总成本最小的增量。 由于所有增量成本都是非递减的，因此可以通过全局最小成本来获得答案。 

成本始终在 0 到`l`，所以我们不需要存储每个可能的增量。 对于每条路径，我们计算有多少个增量的成本为 0、成本 1，依此类推，直到`l-1`。 所有剩余的增量成本`l`。 然后我们从最小成本向上消耗这些计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O（答案）| O(1) | O(1) | 太慢了 |
 | 最佳 | O(n + m + l) | O(n + m + l) | O(n + m + l) | O(n + m + l) | 已接受 |

 ## 算法演练

 1. 从顶点 1 开始遍历图。源的每个出边都开始一条独立路径。 沿着每条路径直到到达顶点 n 并存储其边容量。 由于内部顶点仅属于一条路径，因此每个内部顶点都恰好有一条下一条边。 
2.让`l`是路径的长度。 将目标流量值计算为所有边缘容量的总和除以`l`使用整数除法。 这是重新分配后必须创建的单位路径层的数量。 
3. 对于每条路径，对其边缘容量进行排序。 如果当前所需的流量水平是`x`，达到该水平的成本是小于以下的容量数量`x`。 通过对相等的容量进行分组，计算有多少个连续级别具有每种可能的成本。 
4. 将所有这些计数添加到按操作成本索引的全局频率数组中。 成本小于`l`是有限的。 路径上最大边缘容量之后的任何附加级别都会产生成本`l`。 
5. 从成本 0 开始，采取尽可能多的级别，直到准确选择目标流量值。 所选成本的总和是最少的操作次数。 

为什么有效：最终流的每个单元都对应于一条路径上的一个选定级别。 一条路径只能按顺序选择其级别，但其级别成本永远不会减少，因此全局最便宜的有效选择是通过首先采用最便宜的可用成本来获得的。 成本频率的构建准确地保留了这些边际成本，因此累计总和是移动容量单位的最小可能数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    indeg = [0] * n

    edges = []
    total = 0

    for _ in range(m):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, c))
        indeg[v] += 1
        edges.append((u, v, c))
        total += c

    paths = []
    length = None

    for _, first_c in adj[0]:
        caps = [first_c]
        cur = adj[0][len(paths)][0]

        while cur != n - 1:
            nxt, c = adj[cur][0]
            caps.append(c)
            cur = nxt

        if length is None:
            length = len(caps)
        paths.append(caps)

    if length is None:
        print(0)
        return

    need = total // length

    freq = [0] * length
    cheap_count = 0
    cheap_sum = 0

    for caps in paths:
        caps.sort()
        cur = 0
        idx = 0
        i = 0
        while i < length:
            v = caps[i]
            j = i
            while j < length and caps[j] == v:
                j += 1
            cnt = j - i
            levels = v - cur
            if idx < length:
                freq[idx] += levels
                cheap_count += levels
                cheap_sum += levels * idx
            idx += cnt
            cur = v
            i = j

    ans = cheap_sum
    if need > cheap_count:
        ans += (need - cheap_count) * length

    print(ans)

if __name__ == "__main__":
    solve()
```路径提取依赖于特殊的图结构。 源可以有多个出边，但在进入内部顶点后，只有一个可能的下一条边。 这避免了运行通用图算法。 

频率数组仅存储来自`0`到`l-1`。 一旦路径上的每条边都成为限制边，进一步增加路径流量总是要付出代价`l`，因此可以通过算术计算剩余的贡献。 

所有涉及容量和答案的值都使用 Python 整数。 这是必要的，因为在最大情况下答案可能会超过 32 位和 64 位限制。

 ## 边缘情况

 对于零容量路径：```
2 1
1 2 0
```路径长度为 1，总容量为零。 所需的流层数为零，因此该算法从不选择成本并返回零。 

对于已经具有最大可能流量的图：```
4 3
1 2 5
2 3 5
3 4 5
```总容量为 15，路径长度为 3，目标流量为 5。成本序列包含足够的零成本级别来创建所有五个单元，因此不会移动任何容量。 

对于具有很大边缘的路径：```
4 3
1 2 0
2 3 100
3 4 100
```在第一条边被填充后，该路径会贡献许多便宜的级别。 频率方法通过对级别进行分组而不是迭代 100 次或更多来处理此问题。 它在一次操作中计算所有等成本增量，并且仍然选择全局最便宜的所需层。
