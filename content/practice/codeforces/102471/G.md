 ## 解决方案
 ## 问题理解

 庞先生是其中之一`n`团队参加十题 ICPC 竞赛。 另一个`n - 1`各队已确定最终结果。 庞知道这十个问题中的一部分，解决一个已知问题需要固定的时间，并且在接受之前会产生固定数量的拒绝提交。 

庞必须解决一个又一个的问题。 如果出现问题`x`分钟，那么其接受的提交发生在当前经过的时间加上`x`。 该完成时间将进入团队的解决方案时间列表。 相同的完成时间，加上`20`之前对该问题的每次拒绝都会增加球队的总罚分。 Pang 可以随时停止，但每次接受的提交必须在一分钟内完成`300`。 

该顺序会影响 Pang 的结果，因为后面的问题需要更长的完成时间。 最终排名首先根据已解决问题的数量确定，然后根据总罚分确定，最后根据完成时间的降序排列。 庞在与其他所有球队的比赛中赢得了一场平局。 

幸福感是这个等级的函数，加上一些独立的奖励。 奖牌仅取决于等级。 每个问题都有贡献`800`如果 Pang 完成该问题的时间不晚于其他所有团队完成该问题的时间。 还有一个`700`在整个比赛中最早解决问题的奖励以及`500`拥有最新的奖励。 次数相同，彭获得相应的奖金。 

输入包含`n - 1`固定团队描述，后跟庞的描述。 已解决的状态包含其接受时间和拒绝计数，而`-`意味着问题没有解决。 输出是庞通过选择要解决的已知问题及其顺序获得的最大幸福。 官方声明和示例可在 Codeforces 上获取。 

问题数量少是关键制约因素。 只有十个问题，所以子集动态规划是现实的。 潜在的很大一部分是`n`，可以达到`300`。 这意味着我们应该避免做与`n`数百万种可能的 Pang 时间表。 解决方案围绕`O(n * 2^10 * poly(10))`很容易足够小，同时枚举数百万个时间表并将每个时间表与所有时间表进行比较`300`团队则不然。 

有几种边缘情况很重要，因为它们会改变排名或奖金计算。 庞可能根本解决不了任何问题。 例如，有十支球队，每个状态都等于`-`, Pang 解决的问题为零并且每个团队都平局，所以 Pang 排名`1`并收到`5000`幸福。 假设 Pang 必须解决某些问题的解决方案将无法达到最佳值。 

恰好分钟的边界`300`也具有重要意义。 考虑十个团队，每个团队一次只解决问题 1`300`拒绝运行为零，Pang 具有相同的状态。 庞是排名`1`，首先考虑该解，因为关系有利于 Pang，并且该解既是最早的也是最新的解。 答案是`5000 + 1200 + 800 + 700 + 500 = 8200`。 治疗`300`禁止而不是允许将放弃唯一的解决方案。 

在计算排名时，平局也必须有利于庞。 如果庞的排名键与其他几支球队相同，那么这些球队并不算严格意义上的更好。 这就是为什么该实现在其他团队的排序列表中使用下界。 使用上限将使庞落后于同等球队。 

拒绝惩罚必须与解决时间列表分开。 有问题及时解决`100`三个被拒绝的运行贡献`160`到总惩罚，但其字典序比较的解决时间仍然是`100`。 即使解决的问题数量是正确的，混淆这两个值也会改变排名。 

最后，最新解决的奖金是基于庞的最终经过时间，它是所有选定问题的解决持续时间的总和。 它不仅仅基于最终问题的持续时间。 最早解决方案奖金同样基于首次完成时间。 

## 方法

 直接方法将枚举已知问题的每个可能的有序序列。 序列可以在任意长度后停止，因为允许 Pang 停止求解。 对于十个问题，非空有序序列的数量为`P(10,1) + P(10,2) + ... + P(10,10) = 9,864,100`。 

对于每个这样的序列，我们可以计算 Pang 的排名关键并将其与其他每个团队进行比较。 在最坏的情况下，与`n = 300`，这意味着大约`9,864,100 * 299 = 2,949,365,900`在考虑比较解决方案时间列表的成本之前，先进行团队比较。 蛮力是正确的，因为每个合法的时间表都明确出现，但它太昂贵了。 

第一个有用的观察是其他团队永远不会改变。 我们可以根据确切的排名规则对所有其他球队进行一次排序。 然后可以通过二分搜索找到庞的排名，而不是与每个团队进行比较。 

一支球队的排名可以用一个元组来表示：`(-solved_count, total_penalty, descending_solution_times)`。 

较小的元组代表更好的团队。 对已解决的计数取反会将“解决的问题越多越好”变成普通的元组排序。 降序解决时间列表已经具有正确的词典方向。 

那么，Pang 的排名就是元组严格较小的其他团队的数量加上一。 由于彭赢了平局，`bisect_left`准确给出所需的位置。 

这消除了因素`n`从时间表评估来看，但枚举近千万个时间表仍然是不必要的。 

第二个观察结果是问题的数量只有十个，因此已经解决的问题集可以用位掩码表示。 对于固定子集，最终花费的时间是固定的，因为它只是求解持续时间的总和。 唯一与订单相关的排名数量是完成时间的总和。 

还有另一个重要的属性。 对于固定子集，问题优先奖金的数量可以用作小 DP 维度。 如果两个订单解决完全相同的子集，获得相同数量的问题优先奖金，并且具有不同的总惩罚，则惩罚较小的订单总是更可取的。 每个取决于等级的幸福成分都与等级单调，因此当所有其他奖金相同时，更差的总惩罚永远无法弥补更好的顺序。 

如果惩罚也相等，则只有字典顺序较小的完成时间降序列表才重要。 因此，一个DP状态只需要由总惩罚和解决时间列表组成的最佳对。 

取决于第一个问题本身的唯一好处是`700`最早解决方案奖金。 我们可以通过修复第一个问题并为每个可能的第一问题运行一个子集 DP 来干净地处理这个问题。 只有十个选择。 一旦第一个问题得到解决，每个州的完成时间和最早解决的奖金都是已知的。 

由此产生的 DP 探索子集而不是有序序列。 转换会附加一个未解决的问题。 如果当前经过的时间是`T`和问题`j`需要`x[j]`，其完成时间变为`T + x[j]`。 仅当该值最多为`300`。 

问题优先的奖金特别方便。 对于每个问题，预先计算任何其他团队实现的最早解决时间。 如果 Pang 不晚于这个阈值完成该问题，他就会得到它`800`奖金。 平等案属于庞。 

对于全局奖金，预先计算所有其他团队的最小和最大解决时间。 一旦庞解决了至少一个问题，他的第一次完成时间就决定了`700`奖金和他的最终完成时间决定了`500`奖金。 

蛮力方法之所以有效，是因为它直接考虑每个订单。 它会失败，因为同一子集包含许多冗余前缀。 观察到所有相关的顺序相关信息都可以通过一个子集、一个小的奖励计数和最佳排名键来概括，这让我们可以将这些时间表折叠成只有几千个状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(P(10,1)+...+P(10,10)) * O(n)`|`O(10)`| 太慢了 |
 | 最佳|`O(10 * 2^10 * 10 * 11 * log n)`|`O(2^10 * 11 * 10)`| 已接受 |

 ## 算法演练

 1. 解析每个其他团队的十个问题状态并构建其排名密钥。 计算其已解决的问题，计算其总惩罚为`t + 20w`对于每个已解决的问题，并按降序存储其已解决的时间。 全部排序`n - 1`键。 
2. 在解析其他团队的同时，还计算四个阈值。 对于每个问题，存储其他团队达到的最短解决时间。 存储整个比赛的最小解决时间和整个比赛的最长解决时间。 如果没有人解决某个特定问题，则其阈值可以设置为`301`，因为每个合法的 Pang 解最多是`300`。 如果没有人解决任何问题，请使用`301`为全局最小值和`0`为全局最大值。 
3. 评估庞没有解决任何问题的可能性。 其排名关键是`(0, 0, ())`，并且不适用基于时间的奖金。 必须考虑该候选人，因为解决问题实际上可以降低庞的排名，而不必通过奖金进行补偿。 
4.修复1个已知问题`first`作为庞的第一个问题。 初始化仅包含该问题的子集 DP。 经过的时间是它的求解持续时间，它的惩罚贡献是它的完成时间加上`20`乘以它的拒绝计数，并且它的解决时间列表包含该完成时间。 
5. 对于每一个含有`first`，为每个可能的问题优先奖金数量维持一个状态。 州存储使用该掩码和奖励计数可实现的最小总惩罚。 如果两个状态具有相同的惩罚，则保留字典顺序较小的完成时间降序元组，因为该状态具有更好的排名。 
6. 尝试附加掩码中尚未存在的每个已知问题。 新的完成时间是当前子集的总持续时间加上新问题的持续时间。 如果超过则拒绝转换`300`，因为比赛结束后Pang无法提交。 
7. 将新问题的拒绝惩罚和完成时间添加到总惩罚中。 如果其完成时间不晚于其他团队解决该问题的最佳时间，则将问题优先奖金计数增加 1。 由于新的完成时间晚于之前的每个完成时间，因此将其添加到降序解决时间元组中。 
8. 在处理完第一个问题的所有掩码后，评估每个可到达的状态作为可能的停止点。 其排名密钥直接由子集大小、其存储的惩罚及其存储的降序解决时间元组形成。 使用`bisect_left`在其他队伍的排序列表中即可获得庞的排名。 
9.增加段位幸福感和勋章幸福感。 添加`800`乘以存储的问题优先奖金计数。 由于第一个问题已经解决，添加`700`当其完成时间不晚于其他团队的全局最短解决时间时。 添加`500`当最终经过的时间至少是其他团队的全局最大解决时间时。 
10.对每个可能的第一个问题重复DP，并保留最大的幸福值。 每个合法的非空 Pang 时间表都恰好有一个第一个问题，因此它恰好出现在这十个 DP 运行中的一个中。 

正确性不变量是，对于每个固定的第一个问题、子集掩码和问题优先奖金计数，保留的 DP 状态是准确产生该信息的所有订单中可能的最佳排名状态。 较大的惩罚永远不会提高排名，而相等的惩罚仅由解决时间列表决定，因此丢弃所有其他状态是安全的。 每一个法律时间表都是通过这些转变一次构建一个问题，并且对每个停止点进行评估。 排名关键与比赛的排名规则完全匹配，`bisect_left`发挥庞氏在关系上的优势。 由于每个可能的时间表都被表示，并且每个被丢弃的状态对于所有剩余的幸福成分都是主导的，所以最大评估的幸福是真正的最优。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def parse_team(line):
    result = []
    for item in line.strip().split(","):
        if item == "-":
            result.append(None)
        else:
            t, w = map(int, item.split())
            result.append((t, w))
    return result

def solve_parsed(n, rows):
    other_rows = rows[:n - 1]
    pang_row = rows[n - 1]

    other_keys = []

    first_limit = [301] * 10
    global_min = 301
    global_max = 0

    for line in other_rows:
        team = parse_team(line)

        solved = 0
        penalty = 0
        times = []

        for j, status in enumerate(team):
            if status is None:
                continue

            t, w = status
            solved += 1
            penalty += t + 20 * w
            times.append(t)

            if t < first_limit[j]:
                first_limit[j] = t
            if t < global_min:
                global_min = t
            if t > global_max:
                global_max = t

        times.sort(reverse=True)
        other_keys.append((-solved, penalty, tuple(times)))

    other_keys.sort()

    pang = parse_team(pang_row)

    x = [None] * 10
    y = [0] * 10
    known = []

    for i, status in enumerate(pang):
        if status is not None:
            x[i], y[i] = status
            known.append(i)

    # Rank of Pang. Pang wins a complete tie, so equal keys
    # must be placed after Pang, which is exactly bisect_left.
    def get_rank(solved, penalty, times):
        key = (-solved, penalty, times)
        return bisect_left(other_keys, key) + 1

    def rank_happiness(rank):
        h = 5000 // rank
        q = n // 10

        if rank <= q:
            h += 1200
        elif rank <= 3 * q:
            h += 800
        elif rank <= 6 * q:
            h += 400

        return h

    # Pang solves nothing.
    best = rank_happiness(get_rank(0, 0, ()))

    size = 1 << 10

    # Sum of solving durations for every mask.
    sum_time = [0] * size
    for mask in range(1, size):
        bit = mask & -mask
        j = bit.bit_length() - 1
        sum_time[mask] = sum_time[mask ^ bit]
        if x[j] is not None:
            sum_time[mask] += x[j]

    for first in known:
        first_mask = 1 << first
        first_completion = x[first]
        first_bonus = 1 if first_completion <= first_limit[first] else 0
        first_penalty = first_completion + 20 * y[first]

        # dp[mask] is a dictionary:
        # bonus_count -> (minimum_penalty, descending_solution_times)
        dp = [None] * size
        dp[first_mask] = {
            first_bonus: (first_penalty, (first_completion,))
        }

        for mask in range(size):
            states = dp[mask]
            if not states or not (mask & first_mask):
                continue

            elapsed = sum_time[mask]

            for bonus_count, state in list(states.items()):
                penalty, times = state

                for j in known:
                    bit = 1 << j
                    if mask & bit:
                        continue

                    new_elapsed = elapsed + x[j]
                    if new_elapsed > 300:
                        continue

                    add_bonus = 1 if new_elapsed <= first_limit[j] else 0
                    new_bonus = bonus_count + add_bonus

                    new_penalty = penalty + new_elapsed + 20 * y[j]
                    new_times = (new_elapsed,) + times

                    new_mask = mask | bit
                    if dp[new_mask] is None:
                        dp[new_mask] = {}

                    old = dp[new_mask].get(new_bonus)

                    if old is None or (
                        new_penalty < old[0]
                        or (
                            new_penalty == old[0]
                            and new_times < old[1]
                        )
                    ):
                        dp[new_mask][new_bonus] = (
                            new_penalty,
                            new_times,
                        )

        # Every reachable state is a legal point at which Pang may stop.
        for mask in range(size):
            states = dp[mask]
            if not states:
                continue

            solved = mask.bit_count()
            final_elapsed = sum_time[mask]

            for bonus_count, (penalty, times) in states.items():
                rank = get_rank(solved, penalty, times)

                happiness = rank_happiness(rank)
                happiness += 800 * bonus_count

                # The first problem is fixed in this DP run.
                if first_completion <= global_min:
                    happiness += 700

                if final_elapsed >= global_max:
                    happiness += 500

                if happiness > best:
                    best = happiness

    return best

def main():
    n = int(input())
    rows = [input().strip() for _ in range(n)]
    print(solve_parsed(n, rows))

if __name__ == "__main__":
    main()
```解析代码将每个已解决的状态转换为`(time, rejected_runs)`并代表`-`经过`None`。 对于其他团队，排名密钥在解析后立即构建。 解决时间列表按降序排序，因为这正是最终决胜局所使用的顺序。 

四个阈值是在同一次传递期间收集的，因此无需对团队进行单独扫描。 阈值为`301`是安全的，因为 Pang 的合法完成时间永远不会大于`300`。 

这`get_rank`功能是最微妙的部分之一。 元组使用`-solved`因为Python的普通元组比较将较小的值视为更好。 对所有其他队伍进行排序后，`bisect_left`返回严格较小的键的数量。 相同的键不会被视为更好，因为 Pang 赢得了这些平局。 

子集持续时间数组让每个转换都能以常数时间获取当前经过的时间。 对于从`mask`到`mask | (1 << j)`，新的完成时间就是`sum_time[mask] + x[j]`。 

DP 只存储每个奖励计数的最佳惩罚。 拒绝条款`20 * y[j]`出现问题时添加`j`已解决，同时其完成时间也被添加，因为这是比赛处罚的一部分。 完成时间元组不包括拒绝惩罚。 

将新的完成时间添加到元组中是正确的，因为后面的每个问题都有严格更大的完成时间。 因此，如果按时间顺序排列的完成时间是`t1, t2, t3`，排名表为`(t3, t2, t1)`。 

这`300`边界用途`<=`， 不是`<`。 一个问题在几分钟内完成`300`是合法的。 最早和最新的奖金也使用包容性比较，因为 Pang 赢得平局。 

Python 整数具有任意精度，因此不需要溢出处理。 无论如何，与 Python 的整数范围相比，最大的惩罚是很小的。 

## 工作示例

 官方样本中 Pang 已知 6 个问题，但它们的解决持续时间使得只有少数两题时间表可行`300`分钟。 一个最优调度首先解决问题 1，取`38`分钟，然后是问题 8，再做一次`254`分钟。 该时间表的重要 DP 状态如下所示。 官方示例输出是`1800`。 

| 步骤| 已解决的问题 | 已过去 | 处罚| 求解时间递减 | 问题优先奖金 |
 | ---| ---| ---| ---| ---| ---|
 | 开始|`{}`|`0`|`0`|`()`|`0`|
 | 解决问题1 |`{1}`|`38`|`238`|`(38,)`|`1`|
 | 解决问题8 |`{1,8}`|`292`|`670`|`(292,38)`|`1`|

 其他球队包含一支解决了两个问题并受到处罚的球队`397`，所以 Pang 的罚球`670`让他保持军衔`10`十支队伍之中。 最早的其他解决方案是分钟`4`，所以 Pang 没有收到`700`最早解决方案奖金。 最新的其他解决方案是分钟`290`，而庞完成于`292`，所以他收到`500`最新解决方案奖金。 问题1首先得到解决，因为Pang的`38`比其他所有团队更早地解决该问题。 由此产生的幸福就是`500 + 800 + 500 = 1800`。 

第二个例子隔离了确切的`300`边界。 假设所有其他九支球队每分钟只解决问题 1`300`，Pang 也有同样的单一问题。 

| 步骤| 已解决的问题 | 已过去 | 排名| 问题优先奖金 | 最早奖金 | 最新奖金 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 开始|`{}`|`0`|`1`|`0`|`0`|`0`|
 | 解决问题1 |`{1}`|`300`|`1`|`1`|`1`|`1`|

 Pang 赢得了完整的排名并列，因为他的密钥与其他所有球队的密钥相同，并且平局属于 Pang。 恰好完成`300`是合法的，并且对于所有三种基于时间的奖金来说平等就足够了。 最后的幸福是`5000 + 1200 + 800 + 700 + 500 = 8200`。 

该跟踪说明了为什么 DP 必须允许在经过时间恰好为`300`，为什么排名一定要用`bisect_left`，以及为什么所有时间比较都包含在内。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n * 10 + 10 * 2^10 * 10 * 11 * log n)`| 解析与状态数量成线性关系。 每个第一个问题都运行一个最多有 10 个转换和 11 个奖励计数状态的 DP 子集，并且每个保留状态都可以通过二分搜索进行排名。 |
 | 空间|`O(n * 10 + 2^10 * 11 * 10)`| 存储固定的团队排名密钥，而每个 DP 状态存储惩罚和长度最多为 10 的解决时间元组。 |

 只有十个问题，`2^10 = 1024`。 即使乘以十个可能的第一个问题和十一个可能的奖励计数，状态空间仍然很小。 比赛可以包含`300`团队，但这些团队被处理一次，然后由排序的排名键表示。 该解决方案非常适合`2`第二个和`256 MB`限制。

 ## 边缘情况

 当 Pang 没有解决任何问题时，算法会在输入任何 DP 之前评估空排名键。 对于所有状态均等于的十支球队`-`, 每个团队都有钥匙`(0, 0, ())`。`bisect_left`返回位置`0`，给予庞等级`1`， 和`5000`幸福。 没有时间奖励，因为庞无解。 这可以防止错误的实现迫使 Pang 选择已知问题。 

立即获得解决方案`300`，转移条件为`new_elapsed > 300`， 所以`new_elapsed == 300`仍然合法。 如果其他所有团队都解决了问题 1`300`Pang 也这样做，每个人的排名密钥都是相同的。`bisect_left`给出庞等级`1`。 问题优先比较使用`<=`，所以庞得`800`; 全局最小值和最大值的比较也包含在内，给出两者`700`和`500`。 结果是`8200`。 

对于多个同等球队的排名并列，键本身不包含球队标识符。 这是故意的。 庞不仅与这些球队并列，而且还被定义为排名在他们之前。 如果另外五支队伍拥有与 Pang 完全相同的密钥，`bisect_left`将庞放在所有五人之前。 使用`bisect_right`会错误地将他排在他们之后，并且还可能改变他的奖章和基于等级的幸福感。 

对于问题优先奖励，DP 会比较完成时间，而不是原始解决持续时间。 假设 Pang 首先解决了`50`分钟的问题，然后是`100`分钟问题。 他们的完成时间是`50`和`150`， 不是`50`和`100`。 必须检查第二个问题的首次解决奖金`150`。 转换明确地计算此累积完成时间，因此后面的问题不会意外地仅根据其自己的解决持续时间获得奖励。 

对于最新解决方案奖励，每个选定的问题都将其解决持续时间贡献给最终经过的时间。 如果庞解决了问题`50`和`100`分钟，最终求解时间为`150`无论哪个问题是第二位的。 DP 使用`sum_time[mask]`对于这个值，所以`500`奖金根据实际最终提交时间进行评估。 

对于相等的总惩罚，DP 会比较存储的降序完成时间元组。 这是必要的，因为比赛使用该列表作为第三排名标准。 例如，两个时间表可能都有惩罚`300`，但可以产生`(200, 100)`而另一个产生`(190, 110)`。 后者更好，因为`190 < 200`在第一个不同的位置。 状态比较使用普通的 Python 元组排序，它与所需的词典规则完全匹配。 

对于没有其他人解决的问题，它的第一个解决的阈值仍然存在`301`。 每个合法的 Pang 完成最多`300`，所以 Pang 自动接收到`800`该问题的奖金。 当没有其他团队解决任何问题时，同样的想法也适用于全局最小阈值。 使用`301`而不是一个非常大的哨兵也使边界论证变得明确。 

对于全局最大值，默认阈值是`0`当没有其他团队解决任何问题时。 任何非空 Pang 计划都在正时间结束，因此 Pang 收到`500`最新解决方案奖金。 空时间表单独评估，不接收，因为奖金需要至少一种解决方案。 

提交时要记住的一个小实现细节是，语句中显示的示例在视觉上跨行包装，而实际的法官输入每行只有一个团队描述。
