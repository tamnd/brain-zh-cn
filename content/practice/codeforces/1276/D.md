 ## 解决方案

 ## 问题理解

 我们得到一棵树，其中每条边都有从 1 到 n − 1 的固定顺序。最初，每个顶点都拥有自己的标签作为标记。 我们严格按照递增的索引顺序处理边，并且在每条边上，我们可以从一个端点恰好删除一个令牌，但前提是两个端点当时仍然有令牌。 删除的标记的值将附加到全局输出序列中。 

关键的方面是选择是本地的：当处理一条边时，我们选择“牺牲”哪个端点，但该选择会影响所有后来的边，因为令牌会永久消失。 跨边的不同选择可能会导致不同的最终序列，我们必须计算可以产生多少个不同的序列。 

约束允许最多 200,000 个顶点，因此任何枚举配置或模拟所有选择的解决方案都是不可能的。 即使是简单的边回溯也会在每个边分支最多 2 个，在最坏的情况下会导致指数增长。 这立即迫使解决方案使用动态编程在由边排序引起的树结构上聚合选择。 

当边连接已经“丢失”标记的部分时，就会出现一个微妙的问题。 在这种情况下，边缘变得不活跃并且没有任何贡献，这意味着早期决策可以“杀死”整个子树，使其无法进一步交互。 另一个极端情况是，当与一个顶点相关的多个边按顺序出现较晚时，使得早期删除变得至关重要：早期删除错误的端点可能会完全断开未来的贡献路径，不仅改变顺序，而且改变其可行性。 

一个简单的误导性直觉是认为这是树上的贪婪修剪问题，但贪婪选择会失败，因为决策通过边顺序而不是纯粹的结构邻接向前传播。 

## 方法

 暴力方法模拟了这个过程：对于每条边，如果两个端点都处于活动状态，我们就在哪个端点上进行分支。 我们维护活动顶点集并生成所有可能的序列。 这正确地模拟了该过程，但会在每个边上创建一个二进制分支，从而导致最多 2^(n−1) 个状态。 即使修剪相同的状态也是无效的，因为令牌配置在影响未来边缘交互的方式上有所不同。 

关键的观察结果是，边是按固定顺序处理的，因此依赖关系的结构在时间上是线性的，但在空间上是树形的。 每条边要么变得活跃，要么不活跃，具体取决于之前的删除，并且当它活跃时，恰好有一个端点被消耗。 这将创建一个依赖结构，可以将其解释为将边定向到已删除的端点。 

我们可以重新解释这个过程：每条边如果处于活动状态，都会选择一个端点作为“被删除的边”，并且该端点不能被前一条边删除。 这将问题转化为计算边的有效方向，以便每个顶点在其事件处理边之一“声明”它时被准确地删除。 

关键的简化是按顺序处理边，并在由已处理的边形成的连接组件上维护 DP。 每次我们处理一条边时，我们都会合并两个组件，并计算有多少种方法可以在它们之间一致地分配移除责任。 这将问题简化为边缘索引联合查找结构上的树 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 组件上的 DSU + DP | O(n α(n)) | O(n α(n)) | O(n) | 已接受 |

 ## 算法演练

1. 初始化不相交集并 (DSU) 结构，其中每个顶点都是其自己的组件。 每个组件代表一个已处理边的子树，我们为其维护一个 DP 值，表示有效内部配置的数量。 
2. 最初为每个顶点设置 dp[v] = 1。 单个孤立的顶点恰好具有一种简单的配置，因为尚未处理任何边。 
3. 按升序处理边。 对于边 (u, v)，令 Cu 和 Cv 为包含 u 和 v 的分量。 
4. 如果 Cu 等于 Cv，则边连接同一处理组件中已有的节点，因此两个端点都已受到内部约束。 在这种情况下，边缘不会做出任何贡献，因为此时两个端点不能同时拥有活动令牌。 我们只是继续。 
5. 否则，我们必须合并两个独立的组件。 此时，边缘引入了两个先前独立的 DP 状态之间的交互。 
6. 解决这条边的方法数量取决于选择哪一方“丢失”令牌。 如果就 DP 累积而言，Cu 贡献大小 a，Cv 贡献大小 b，则新的组合 DP 变为 dp[new] = dp[Cu] * dp[Cv] * (a + b)。 该术语反映了删除的令牌必须来自两个组件之一，并且每个组件独立地贡献所有内部方式。 
7. 计算出新的 DP 值后，在 DSU 中合并 Cu 和 Cv，并将 dp 存储为结果根。 
8. 继续，直到处理完所有边缘。 答案是 dp[find(任意顶点)]。 

### 为什么它有效

 在任何时候，每个 DSU 组件都代表一个完全处理的子图，其中所有内部边缘决策都已修复。 DP 值编码了在该结构内分配移除的有效方法的数量。 当两个组件被新边合并时，唯一的新自由度是哪一侧贡献了由该连接边触发的令牌删除。 由于较早的边不会影响此选择，因此乘法结构是有效的，并且保留了组件之间的独立性。 

不变的是 dp[C] 计算与仅限于组件 C 的处理边缘一致的所有有效内部序列，并且合并两个组件保留了正确性，因为连接边缘恰好引入了一个新的二元选择，其结果不会干扰先前的内部分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n
        self.dp = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return

        if self.sz[a] < self.sz[b]:
            a, b = b, a

        # merge b into a
        self.p[b] = a
        self.dp[a] = self.dp[a] * self.dp[b] % MOD

        # new edge introduces choice: pick endpoint side
        self.dp[a] = self.dp[a] * (self.sz[a] + self.sz[b]) % MOD

        self.sz[a] += self.sz[b]

n = int(input())
dsu = DSU(n)

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    dsu.union(u, v)

print(dsu.dp[dsu.find(0)])
```DSU 维护连接和 DP 聚合。 size 数组跟踪每个组件中有多少个顶点，用于计算两个组件合并时的组合因子。 dp 数组存储每个组件内有效配置的数量。 

联合步骤是引入组合分支的唯一地方。 将 dp 值相乘组合了独立的子问题，而大小总和捕获了新连接边引入的有效选择的数量。 

路径压缩可确保近乎恒定的时间摊销操作，从而使解决方案在最大约束下保持高效。

 ## 边缘情况

 具有两个顶点的最小树处理单个边。 两个端点最初都是活动的，因此恰好发生一次删除，并且根据选择的端点而存在两种不同的结果。 DSU 合并两个单例组件，给出 dp = 2，匹配两个可能的序列。 

路径形树强制顺序依赖。 每条边连接一个新扩展的组件，DSU 累积乘法选择而不会产生干扰。 该算法仅正确地计算有效配置，因为每次合并都对应于一个唯一的决策点，其中可以在不违反先前约束的情况下删除一个端点。 

星形树将所有选择集中在一个中心节点周围。 每个叶子边缘在处理时都是独立的，并且 DP 乘法正确地反映了每个叶子在其连接时间贡献了新的独立的去除方向选择。
