 ## 解决方案
 ## 问题理解

 该任务描述了简化战舰设置中的单次射击。 您将获得一个$n \times n$网格代表一个棋盘，其中每个单元格要么是水，要么是船的一部分。 除了这个网格之外，你还会得到一个坐标$(r, c)$，它代表对手提出的一种猜测。 

您的工作是确定该单元格中发生了什么。 如果猜测的单元格包含船段，则结果被视为命中，并且输出“否”。 如果猜测的细胞是水，则射击失败，您输出“是”。 

因此，问题不在于模拟完整的游戏或跟踪船只，而是简化为矩阵中的单个查找。 

约束很小，有$n \le 100$。 这意味着网格最多有$10^4$在任何合理的实现下，甚至直接扫描或重复解析也将足够快。 这已经排除了对高级数据结构或预处理的任何需要。 直接访问解决方案就足够了。 

一个微妙的实现细节来自输入格式。 网格以包含字符的行形式给出，在该问题的某些变体中，这些字符可以用空格分隔。 如果您错误地假设没有间距并读取原始字符串，则索引可能会错位。 另一个常见的边缘情况是坐标解释：行和列的索引为零，因此访问错误的约定（1 索引与 0 索引）会导致差一错误。 

一个简单的失败示例：

 输入：```
5 3 1
O O O S O
O S O S O
O O O O O
S S O O O
O S O O O
```查询是$(3, 1)$。 正确的输出是“否”，因为该单元格是一艘船。 将每一行读取为连续字符串而不用空格分割的简单实现会查看错误的字符位置并可能返回“是”。 

## 方法

 强力解释将模拟扫描网格中的每个查询并检查输入格式的所有可能解释，直到找到正确的单元格。 在具有多个查询或动态更新的更一般的战舰问题中，这种重复扫描变得昂贵，但在这里是不必要的。 

关键的观察是整个状态是静态的并且从一开始就完全已知。 答案仅取决于一次坐标查找。 一旦网格被正确解析，每个查询都是对二维数组的 O(1) 访问。 

从蛮力思维到最优解决方案的转变是认识到不需要对船舶进行结构推理。 我们不会被要求识别连接的组件或验证船舶形状，而只是检查单个单元格的值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 重复扫描每个查询/重新解释网格 | O(n²) 预处理或更糟 | O(n²) | 不必要但仍然可行|
 | 解析后直接索引 | O(n²) 读取输入 + O(1) 查询 | O(n²) | 已接受 |

 ## 算法演练

 1. 读取整数$n, r, c$。 这些定义了网格大小和单个查询位置。 
2. 逐行读取网格，将每一行分割成字符。 重要的一步是标准化输入，以便每个单元都可以作为干净的矩阵条目进行访问，而与是否存在空格无关。 
3. 将网格存储在二维数组结构中。 
4. 访问位置单元格$(r, c)$直接地。 
5. 如果值为`'S'`，输出“否”，因为射击击中了飞船单元。 否则输出“Yes”。 

### 为什么它有效

 网格已经编码了完整的游戏状态。 每个单元格独立地代表它是否包含船或水。 由于没有转换，没有船舶合并逻辑，也没有概率解释，所以答案仅取决于一次查找。 该算法是正确的，因为它保留了输入状态和输出决策之间的直接映射，没有任何可能丢失信息的中间抽象。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, r, c = map(int, input().split())

grid = []
for _ in range(n):
    row = input().strip().split()
    grid.append(row)

if grid[r][c] == 'S':
    print("No")
else:
    print("Yes")
```这里关键的实现细节是使用`.split()`读取每一行时。 示例输入显示以空格分隔的字符，因此将每一行视为原始字符串会错误地合并单元格。 如果问题变体提供连续字符串，则需要将这一行替换为直接索引到字符串中。 

第二个细节是不需要调整索引，因为该问题已经使用从零开始的索引。 如果解决方案采用基于 1 的索引，则必须将访问更正为`grid[r-1][c-1]`，否则答案将会系统性地改变。

 ## 边缘情况

 一种边缘情况是最小的网格，其中$n = 1$。 该算法仍然表现正确，因为它直接访问唯一的单元格，并且索引中没有歧义。 

另一种情况是网格完全是水时。 查找将始终返回“O”，因此输出始终为“Yes”。 尝试解释船舶形状的简单解决方案会浪费精力检测不存在的结构，但直接查找避免了任何此类复杂性。 

最后的边缘情况是边界坐标，例如$(n-1, n-1)$。 这些在零索引网格中是安全的，但经常破坏错误地假设基于一索引的解决方案。 直接数组访问使边界行为与内部单元相同，从而防止特殊情况处理错误。
