 ## 解决方案
 ## 问题理解

 我们给出了一个序列，它表示一次访问每个顶点的步行，因此它已经是从 1 到 n 的数字的排列。 任务是确定该排序是否具有非常特定的形状。 

允许的形状在以下意义上是“金字塔形”。 如果从左到右查看排列，它必须首先在值方面严格沿一个方向移动（严格增加或严格减少），然后它必须恰好切换方向一次并严格沿相反方向继续。 两个部分的长度都必须至少为 2，尽管转折点本身属于两个单调解释，因为它由两个片段共享。 

因此，该结构本质上是单峰或单谷：要么值先上升然后下降，要么先下降然后上升，不允许第二次反转。 

输入只是 n 后面跟着排列。 输出是简单的“是”或“否”，具体取决于是否存在这种单一变化的单调结构。 

n 高达 100000 的约束迫使任何解都是线性的，因为在最坏的情况下任何二次方程都将是大约 10^10 次运算，并且在典型的时间限制下立即不可能。 即使 O(n log n) 方法也是可以接受的，但这里没有必要； 该结构足够局部，一次传递就足够了。 

主要的边缘情况是“几乎单调”序列的微妙失败。 

第一个示例是完全单调的数组，如 [1, 2, 3, 4, 5]。 乍一看，它可能看起来可以接受，因为它没有违规，但它永远不会形成方向改变的两个线段，因此必须拒绝它。 

另一个例子类似于 [4, 5, 6, 1, 2, 3]。 就实际值而言，这会先出现一次明显的增加，然后出现减少，但这种转变与整个序列上的单个峰或谷不一致，因为在对整个排列排序进行解释时，方向会改变不止一次。 

更微妙的情况是像 [1, 3, 2] 这样的短暂振荡。 这是有效的，因为它增加一次然后减少一次，并且两个段都有足够的长度。 

## 方法

 强力解释将尝试每一个可能的分割点 i，将前缀视为一个单调方向，将后缀视为相反方向。 对于每个分割，我们将通过扫描两半来验证单调性。 这会导致 O(n^2) 行为，因为每次分裂成本为 O(n) 并且存在 O(n) 分裂。 当 n = 10^5 时，这远远超出了可行的限制。 

问题的结构是序列已经是一个排列，因此邻居之间的比较充分描述了趋势的所有变化。 我们不需要测试所有的分裂点，而只需要检测相邻差异的方向改变了多少次。 

如果我们计算每个相邻差异的符号，整个问题就简化为检查符号序列是否最多有一次从正到负或从负到正的转变，并且如果存在变化，则初始段在每个方向上至少有一个步骤。 这相当于计算序列在上升趋势和下降趋势之间切换的次数。 

关键的见解是任何金字塔序列只能有一个极值，因此方向最多改变一次。 如果它改变零次，则序列是单调且无效的。 如果改变一次，只要两边不为空就有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分割检查 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 方向变化计数| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们处理相邻差异并跟踪方向变化。

1. 通过比较 a[i] 和 a[i+1] 来计算每个相邻对是增加还是减少。 这将序列压缩为二元趋势表示。 
2. 遍历这个趋势数组并计算趋势从增加到减少或从增加到减少翻转的次数。 每次翻转对应一个潜在的峰值或谷值。 
3. 如果翻转次数大于1，则该结构不能是金字塔形的，因为这意味着有多个转折点。 
4. 如果翻转次数为零，则该数组是完全单调的，不包含所需的单峰或单谷结构，因此无效。 
5. 如果恰好有一个翻转，请检查由该翻转形成的两个段在原始序列中的长度是否至少为 2。 这确保了“金字塔”具有有意义的上升和下降部分。 

核心思想是我们将全局形状条件简化为过渡的局部属性。 

### 为什么它有效

 不变的是序列总是被解释为分段单调路径。 每当我们看到相邻差异的符号发生变化时，我们就识别出单调片段之间的边界。 有效的金字塔路径必须恰好有两个单调线段：一个递增，一个递减，无论顺序如何。 如果存在多个边界，则至少存在三个单调段，这意味着序列多次改变方向，这违反了定义。 如果不存在边界，序列永远不会改变方向，因此它不能形成金字塔。 在单次传递中保持这种不变性可以保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

# build trend array: +1 for up, -1 for down
trend = []
for i in range(n - 1):
    if a[i] < a[i + 1]:
        trend.append(1)
    else:
        trend.append(-1)

changes = 0
for i in range(1, len(trend)):
    if trend[i] != trend[i - 1]:
        changes += 1

# valid pyramidal path must have exactly one change
if changes != 1:
    print("NO")
else:
    print("YES")
```该代码首先将排列压缩为邻居之间的方向序列。 这避免了直接推理价值观，而是关注结构变化。 

第二个循环计算该方向翻转的次数。 该计数直接对应于单调段的数量减一。 

最后，决策检查是否确实存在一个这样的翻转，这是单个峰或谷结构的特征。 

一个微妙的点是，相等永远不会发生，因为输入是排列，因此每个相邻比较都是严格递增或递减的。 这消除了趋势提取中的歧义。 

## 工作示例

 ### 示例 1

 输入：```

```趋势构建：

 | 我| a[i] 与 a[i+1] | 趋势 |
 | ---| ---| ---|
 | 0 | 4 > 3 | 4 -1 |
 | 1 | 3 > 1 | 3 > 1 -1 |

 | 我| 趋势[i-1] | 趋势[i] | 改变 |

这证实了单谷结构：先减小后增大。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 我们扫描排列一次以构建趋势，并扫描一次以计算变化 |
 | 空间| O(n) | 我们存储趋势数组，其大小为 n−1 |

 这些约束允许最多 100000 个元素，因此线性扫描在运行时和内存方面都可以轻松满足限制。 通过动态计算趋势也可以实现恒定空间版本，但这里没有必要。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    trend = []
    for i in range(n - 1):
        trend.append(1 if a[i] < a[i + 1] else -1)

    changes = 0
    for i in range(1, len(trend)):
        if trend[i] != trend[i - 1]:
            changes += 1

    return "YES\n" if changes == 1 else "NO\n"

# provided samples
assert run("5\n4 3 1 2 5\n") == "YES\n"
assert run("3\n1 3 2\n") == "YES\n"

# custom cases
assert run("3\n1 2 3\n") == "NO\n", "fully increasing"
assert run("3\n3 2 1\n") == "NO\n", "fully decreasing"
assert run("4\n2 1 3 4\n") == "YES\n", "single valley"
assert run("6\n1 3 2 4 5 6\n") == "NO\n", "multiple changes"
```| 测试输入| 预期产出 | 它验证了什么 |

 ## 边缘情况

 严格递增序列如`1 2 3 4`产生一个全+1且变化为零的趋势数组，因此立即被拒绝。 该算法不计算翻转并正确输出“否”。 

严格递减序列如`4 3 2 1`行为对称，也产生零翻转并返回 NO。 

最小有效金字塔，例如`2 1 3`产生从 -1 到 +1 的单个变化。 该算法恰好检测到一次翻转并返回 YES，满足两个段都存在且非空的要求。 

具有多次振荡的序列，例如`1 3 2 4`在趋势数组中产生两次翻转，导致拒绝，因为它包含多个极值，这违反了金字塔约束。
