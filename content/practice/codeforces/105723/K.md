 ## 解决方案
 ## 问题理解

 我们得到了一个有符号整数序列，其行为就像一个正确的嵌套结构，类似于多类型括号系统。 每个值恰好出现两次，因为它的正值和负值出现形成匹配对，并且嵌套结构保证这些对要么不相交，要么正确嵌套，永远不会任意交叉。 

从这个序列中，每个查询都会给出一个连续的段，保证在相同的嵌套规则下仍然保持平衡。 对于每个这样的片段，我们需要将其分成最少数量的子序列，使得每个子序列都是“原始的”。 原始子序列具有非常严格的形状：它的所有正数必须首先出现，然后是它的所有负数，并且它仍然必须遵循原始序列引起的配对结构。 

关键的难点在于我们不允许对段内的元素进行重新排序，只能在形成子序列时删除元素，并且每个元素必须恰好属于一个子序列。 

这些约束强制离线每个查询结构或至少对数查询处理。 每个测试最多 10^5 个元素，总体查询最多 10^5 个，任何尝试显式模拟分区或重复扫描段的方法都将超出时间限制。 即使每个查询解决方案使用 O(段长度)，在最坏的情况下也会导致 10^10 次操作，这是不可行的。 

一个微妙的边缘条件是每个查询段都已经保证是平衡的。 这消除了验证段内结构正确性的需要，但它并没有简化内部配对依赖性。 

一个幼稚的错误是假设由于段是平衡的，因此答案始终为 1。例如，考虑像 [1, 2, -2, -1, 3, -3] 这样的段。 它是平衡的，但它不能形成单个原始子序列，因为嵌套结构迫使多个独立的链。 

另一种失败模式是尝试通过从左到右扫描来贪婪地构建子序列，并在负数较早出现时启动新的子序列。 这是因为结构不是线性的而是分层的。 

## 方法

 蛮力视图是直接模拟定义。 对于每个查询段，我们尝试一一构造子序列，贪婪地插入元素，同时保持原始有效性。 每次插入都需要检查添加正数或负数是否保留“所有正数然后所有负数”约束。 这会导致每个子序列重复扫描和簿记，在最坏的情况下，我们可能会多次重新访问几乎每个元素。 对于许多查询，这会退化为二次或更糟糕的行为。 

结构上的突破来自于将序列解释为由嵌套引起的树。 每个值都对应于其正数出现和负数出现之间的间隔。 由于序列是平衡的，这些间隔形成了适当的嵌套结构，相当于嵌入一条线的有根森林。 

在此表示中，每个位置恰好属于一个嵌套间隔链。 原始子序列对应于选择一组节点，以便当按顺序读取时，所有选定的节点都遵循祖先顺序，并且可以分成“打开阶段然后关闭阶段”而无需交织。 此限制意味着在任何有效的子序列中，一旦开始关闭节点，我们就无法在嵌套树的两个独立分支之间切换。

这强制进行了极大的简化：每个原始子序列都可以解释为遵循嵌套层次结构中的单个链。 因此，将一个片段分解为最少数量的原始子序列相当于使用最少数量的根到叶链覆盖该片段的诱导森林。 

在树中，覆盖所有节点所需的根到叶链的最小数量等于限制在段内时启动新的断开组件的节点数，这可以通过计算有多少个节点的父节点位于段之外或者是诱导森林的根来计算。 

这将每个查询减少为计算相对于嵌套树中的父关系的边界节点。

 ## 算法演练

 ### 1. 构建嵌套结构

 我们使用堆栈处理一次序列。 每当我们看到正值时，我们就会将其作为开放节点。 当我们看到其相应的负值时，我们将其弹出并链接为当前堆栈顶部的子级。 这重建了嵌套区间的隐式树。 

这样做的原因是平衡结构保证在任何时候，堆栈都准确地包含嵌套顺序中的活动开区间。 

### 2.记录父母关系

 对于每个节点（绝对值），我们将其父节点存储在树中。 如果当堆栈顶部有另一个节点时打开一个节点，则该顶部将成为其父节点。 

这会将序列转换为有根森林，其中每个节点最多有一个父节点。 

### 3. 预先计算树结构的邻接关系

 我们为每个节点存储其父节点以及可能的深度，但深度对于最终查询并不是严格必需的。 

### 4. 处理查询段

 对于查询范围 [l, r]，我们考虑两次出现完全位于段内的所有节点（由问题条件保证）。 对于这些节点，我们计算有多少个节点的父节点位于段之外或没有父节点。 

每个这样的节点对应于任何有效的原始分解中新链的开始。 

### 5.输出计数

 答案正是这些“边界根”节点的数量。 

### 为什么它有效

 在任何有效段内，嵌套结构的行为就像森林一样。 原始子序列在下降后无法在两个分支之间切换，因为这会以违反其定义的方式强制正负相位交错。 此限制迫使每个子序列保留在诱导森林中的单个根到叶链内。 因此，每当一个节点与其在段内的父节点断开连接时，就必须开始一个新的链，并且任何分解都不能使用比该数量更少的链。 相反，在每个这样的节点处开始一条链并向下跟踪总是会产生有效的原始子序列覆盖。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}
    for i, x in enumerate(a):
        pos[x] = i

    parent = [-1] * (n + 1)
    stack = []

    for x in a:
        v = abs(x)
        if x > 0:
            if stack:
                parent[v] = abs(stack[-1])
            stack.append(v)
        else:
            stack.pop()

    # for each node, store interval [L[v], R[v]]
    L = [0] * (n + 1)
    R = [0] * (n + 1)

    for i, x in enumerate(a):
        v = abs(x)
        if x > 0:
            L[v] = i
        else:
            R[v] = i

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        ans = 0
        for v in range(1, n + 1):
            if L[v] >= l and R[v] <= r:
                p = parent[v]
                if p == -1 or not (L[p] >= l and R[p] <= r):
                    ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案使用带符号序列上的堆栈来重建嵌套森林。 每个值的第一次出现给出了它的入口位置，第二次出现给出了它的退出位置，形成了树节点的区间表示。 

对于每个查询，我们检查哪些节点完全包含在段中，然后测试它们的父节点是否位于段之外。 每个这样的节点都被视为启动一个新的原始子序列。 

该实现在很大程度上依赖于每个查询段平衡的保证，这确保以一致的方式完全包含或完全排除间隔。 

## 工作示例

 ### 示例 1

 考虑顺序`[1, 2, -2, -1, 3, -3]`并查询`[1, 6]`。 

| 步骤| 节点| 间隔| 家长 | 内段| 新链条|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | [0,3]| - | 是的 | 是的 |
 | 2 | 2 | [1,2]| 1 | 是的 | 没有|
 | 3 | 3 | [4,5]| - | 是的 | 是的 |

 答案是 2，因为节点 1 和 3 启动独立组件。 

这证实了即使整个序列是平衡的，独立的顶级区间也需要单独的原始子序列。 

### 示例 2

 序列`[1, 2, 3, -3, -2, -1]`， 询问`[1, 6]`。 

| 步骤| 节点| 家长 | 内段| 新链条|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | - | 是的 | 是的 |
 | 2 | 2 | 1 | 是的 | 没有|
 | 3 | 3 | 2 | 是的 | 没有|

 由于该结构是完全嵌套的，因此只需要一根链。 

这演示了完全嵌套链上的行为，其中整个段折叠成单个原始子序列。

 ## 边缘情况

 一个关键的边缘情况是单个查询中出现多个独立的根区间。 在`[1,2,-2,1,-1,3,-3]`，结构分裂成多个组件。 该算法正确地计算了其父级位于线段之外的每个根的数量。 

另一个边缘情况是完全嵌套结构。 在`[1,2,3,-3,-2,-1]`，每个节点在段内都有其父节点，因此在第一个链之后不会启动新链，从而始终产生答案 1。 

最后一个微妙的情况是包含单个对的最小段，例如`[x,-x]`。 这里，节点没有内部父节点，并且始终被计数，产生答案 1，这与单个对本身始终是原始节点的事实相匹配。
