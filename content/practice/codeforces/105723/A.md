 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，然后重复应用两种类型的运算。 第一个操作很简单：选取任何具有正值的位置并将其减一。 第二个操作更不寻常：选择至少两个值不相同的位置，然后用从所选子集计算出的单个值（特别是该子集中的最大值和最小值之差减一）覆盖所有选定的位置。 

只要这些操作中的至少一项适用，该过程就会继续。 每个操作都算作一次移动，目标是在达到无法进行操作的状态之前最大化我们可以执行的总移动次数。 

输出是所有可能的有效序列的最大操作数。 

这些约束允许跨测试用例最多使用 200,000 个总元素，因此每个测试用例的任何解决方案都必须是线性或接近线性的。 任何涉及重复模拟操作或动态重新计算子集效应的操作都将失败。 关键的挑战是操作二可以在一次移动中显着地重塑数组，可能以非局部方式增加或减少值，因此贪婪的局部模拟是不安全的。 

有一些重要的边缘情况值得尽早隔离。 

如果所有元素都为零，则无法进行任何操作，结果为零。 

如果所有元素都相等且为正，则操作二是不可能的，因为任何选定的子集都具有相等的值，因此唯一有效的移动是重复递减，准确给出数组的总和作为操作数。 

如果数组包含零和正值的混合，则操作二立即可用，并且其效果可以通过在所选子集中创建大的均衡值来主导动态。 

## 方法

 强力解释将模拟该过程：在每一步，枚举操作二的所有有效子集和操作一的所有索引，尝试每一个可能的移动，并递归地继续，跟踪操作的最大数量。 这在概念上是正确的，因为它探索了每一个法律序列，但它立即是不可行的。 即使单独选择子集也是指数级的，并且每个操作都会改变状态空间，导致可能性的爆炸，远远超出任何现实的限制。 

关键的简化来自于注意到操作一仅减少值，而操作二用从该子集范围派生的值替换所选子集。 至关重要的是，操作二从不依赖于绝对大小，只依赖于所选组内的最大值和最小值。 这意味着数组的全局结构比单个位置更重要。 

中心观察是，只有两种根本不同的长期战略。 一种策略完全避免操作二并简单地执行单位递减，直到一切都达到零。 这恰好产生所有元素的总和作为操作数。 

另一种策略使用操作二来尽早将数组折叠成统一的配置。 一旦数组变得均匀，操作二就不再可用，并且过程的其余部分再次变成纯递减。 如果我们对整个数组应用操作二，所有值都会变成`max(a) - min(a) - 1`，然后我们花`n`每单位递减直至为零。 这给出了第二个候选值。 

最佳答案是这两种结构上不同的行为中最好的。

 ## 算法演练

 ### ## 算法演练

 1. 计算数组的总和。 这对应于从不使用操作二并重复应用操作一直到所有值达到零的策略。 
2. 计算数组中的最大值和最小值。 这些决定了在整个数组上应用操作二的唯一可能的效果，因为所得的统一值仅取决于这些极值。 
3. 考虑对整个数组应用操作二一次。 这会产生一个统一的数组，其中每个元素都变成`max(a) - min(a) - 1`。 如果该值为负数，则将其视为零，因为在随后的重复递减下，该值实际上会触底。 
4.这次崩溃之后，剩下的过程纯粹是应用于所有元素的操作一，这有助于`n * new_value`额外的操作。 
5. 添加本场景中使用的单个操作两个，总共得到`1 + n * new_value`。 
6. 取纯递减策略（元素之和）和折叠策略之间的最大值。 

### 为什么它有效

 该过程始终在无法执行操作 2 的状态下终止，这意味着数组要么是统一的，要么大小小于 2。 操作一是在该点之后提取附加操作的唯一机制，并且它为剩余的每单位价值贡献了一次操作。 使用操作二时，只有当它产生最终的均匀水平面且其总质量`n * value`补偿由于从一开始就没有贪婪地使用操作一而造成的任何损失。 由于操作二仅将信息折叠为极值，因此任何最佳序列都可以简化为从不使用它或在整个集合上使用它一次，而不失一般性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        s = sum(a)
        mx = max(a)
        mn = min(a)
        
        # strategy 1: only decrements
        ans1 = s
        
        # strategy 2: one global merge via operation 2
        val = mx - mn - 1
        if val < 0:
            val = 0
        ans2 = 1 + n * val
        
        print(max(ans1, ans2) % MOD)

if __name__ == "__main__":
    solve()
```实施直接遵循两种策略减少。 数组的总和计算一次，表示通过仅递减播放可获得的完整值。 然后极值定义操作二的唯一有意义的应用，全局应用一次。 这`val < 0`钳制是必要的，因为一旦计算值变为负值，重复的递减将占主导地位并有效地迫使系统归零。 

模数仅在最后应用，因为所有中间值都可以安全地适合 Python 整数。 

## 工作示例

 ### 示例 1

 考虑`a = [0, 2]`。 

| 步骤| 数组状态| 行动| 笔记|
 | --- | --- | --- | --- |
 | 1 | [0, 2] | 计算总和 | 2 |
 | 2 | [0, 2] | mx=2，mn=0 | 用于op2 |
 | 3 | [0, 2] | 值 = 2-0-1 = 1 | 崩溃值|
 | 4 | [1, 1] | 应用 op2 一次 | 数组变得均匀 |
 | 5 | [1, 1] | 答案 = 1 + 2*1 = 3 | 加减量|

 这显示了操作二如何以均匀的方式增加有效“质量”。 

### 示例 2

 考虑`a = [3, 3, 3]`。 

| 步骤| 数组状态| 行动| 笔记|
 | --- | --- | --- | --- |
 | 1 | [3,3,3]| 总和 = 9 | 仅减量 |
 | 2 | [3,3,3]| mx=mn=3 | mx=mn=3 op2 没有任何好处 |
 | 3 | [3,3,3]| ans2 = 1 + 3*(3-3-1)=1 | 低于 9 |

 这里的最佳策略显然是完全避免操作二。

 ## 边缘情况

 当所有元素都为零时，两种策略都会自然地产生零：总和为零，折叠值为负，钳位为零，因此任何操作都无法启动。 

当所有元素都相等时，操作二不可用，因此算法正确地退回到纯求和。 计算出的`mx - mn - 1`变成`-1`，它钳制为零，确保第二个策略仅贡献单个无效操作。 

当数组只有一个元素时，公式会完全退化为求和，因为根据定义，操作二是不可能的。
