 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符组成的字符串`a`,`b`， 和`c`。 保证字符串中不存在两个相邻的相同字符，并且所有三个字符在字符串中的某个位置至少出现一次。 

任务是找到该字符串中至少包含一个的最短连续段`a`, 至少一个`b`，以及至少一个`c`。 换句话说，在所有子串中，我们想要“覆盖”所有三个符号的窗口的最小长度。 

输入大小最多可达 100000 个字符。 这会立即排除任何尝试显式检查所有子字符串的行为，因为在最坏的情况下枚举所有子字符串是二次的，并且需要大约 10^10 次操作。 即使是有效窗口上的嵌套循环也会太慢。 

邻接约束（即没有两个相邻字符相等）在结构上很重要，但对于正确性来说并不是严格必需的。 它主要防止病态情况，例如同一字符的长期运行。 然而，即使没有它，核心问题仍然是一样的：我们需要一个包含三个不同符号的最小窗口。 

一些边缘情况值得指出。 

如果字符串已经是这样的`abc`，答案是 3，因为整个字符串是最小的可能有效子字符串。 过于激进地错误地重置窗口的幼稚方法可能会错过这一点。 

例如，如果字符分散`abacbc`，最佳子字符串可能在最后一个缺失字符出现的地方结束。 过早重新启动的天真的贪婪扫描可能会错过在早期有效段内开始的较短窗口。 

另一个微妙的情况是多个有效子字符串严重重叠。 例如`abcbac`，几个窗口包含所有三个字符，并且最小的一个窗口不一定与明显的边界对齐。 

## 方法

 暴力解决方案将检查每个可能的子字符串，并为每个子字符串计数是否`a`,`b`， 和`c`全部出现。 有 O(n^2) 个子串，如果直接完成，每次检查的成本为 O(n)，或者使用预先计算的频率表为 O(1)，但总体上仍然为 O(n^2)。 当n达到100000时，这远远超出了可行的极限。 

我们可以通过注意到我们不需要独立考虑所有子字符串来改进这一点。 相反，我们只关心以特定位置结束的窗口。 如果我们固定右端点，则最佳左端点由每个字符出现的最新位置确定。 

在任意索引处`i`，假设我们知道最后出现的位置`a`,`b`， 和`c`最多`i`。 如果所有三个都至少出现一次，则任何以以下结尾的有效子字符串`i`必须不晚于这些最后看到的位置中最小的一个开始。 早于该时间开始将包含不必要的字符，晚于该时间开始将删除所需字符之一。 这提供了一种直接的方法来计算在 O(1) 中每个位置结束的最佳窗口，从而在 O(n) 中计算完整答案。 

这将问题从枚举子字符串转变为维护三个指针。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时维护每个字符出现的最新索引。 

1.初始化三个变量`last_a`,`last_b`， 和`last_c`表示还没有看到任何角色。 我们还保留一个变量`ans`初始化为一个非常大的数字。 这是迄今为止找到的最佳答案。 
2. 遍历带索引的字符串`i`。 在每一步中，根据是否更新相应的最后看到的位置`s[i]`是`a`,`b`， 或者`c`。 这确保了我们在任何时刻都有每个字符最近出现的位置`i`。 
3. 更新后，检查最后看到的三个位置是否全部有效。 如果其中任何一个仍未初始化，我们就无法形成以以下结尾的有效子字符串`i`，所以我们跳过这一步的其余部分。 
4. 如果所有三个字符都已被看到，则计算最后看到的三个位置中最早的一个。 该位置成为结束于的最小有效子串的左边界`i`仍然包含所有三个字符。 
5. 计算该子串的长度为`i - min(last_a, last_b, last_c) + 1`，并更新`ans`如果这个长度小于当前的最佳长度。 
6. 继续直到字符串末尾。 最终的答案是最小记录值。 

为什么这是正确的左边界是关键点。 任何结尾为的子串`i`必须包含每个字符至少出现一次。 每个字符在之前或之后最近出现的位置`i`是唯一能保证包容性而又不会不必要地扩展的候选者。 最小的有效窗口被强制从这些必需的最后出现中最早的事件开始。 

### 为什么它有效

 在每个索引处`i`，该算法隐式地考虑以结尾的最佳可能子串`i`。 不变的是`last_a`,`last_b`， 和`last_c`始终代表各自角色的最新位置`i`。 任何以以下结尾的有效子字符串`i`必须包含每个字符至少出现一次，因此必须在最后出现的每一个字符处或之前开始。 最严格的开始是其中的最小值。 这确保没有有效的子字符串结尾`i`可以比构造的短，因此取所有最小值`i`产生全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    last = {'a': -1, 'b': -1, 'c': -1}
    ans = 10**18
    
    for i, ch in enumerate(s):
        last[ch] = i
        
        if last['a'] != -1 and last['b'] != -1 and last['c'] != -1:
            start = min(last['a'], last['b'], last['c'])
            ans = min(ans, i - start + 1)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码直接实现了跟踪最后看到的位置的想法。 字典`last`存储每个字符的索引。 每次前进时，我们都会更新一个条目并立即检查是否已看到所有三个角色。 

关键细节是计算最后出现的最小值。 此步骤编码了这样一个事实：窗口必须包含每个字符最近所需的外观。 

离一处理被吸收`+1`在长度公式中，因为两个端点都包含在内。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    last = {'a': -1, 'b': -1, 'c': -1}
    ans = 10**18
    
    s = input().strip()
    for i, ch in enumerate(s):
        last[ch] = i
        if last['a'] != -1 and last['b'] != -1 and last['c'] != -1:
            start = min(last['a'], last['b'], last['c'])
            ans = min(ans, i - start + 1)
    
    return str(ans)

# provided sample
assert run("abac\n") == "3"

# minimum length case
assert run("abc\n") == "3"

# symmetric shuffle
assert run("cab\n") == "3"

# longer mixed case

assert run("acbabc\n") == "3"

 ## 边缘情况

 对于非常短的输入，例如`abc`，算法立即更新所有最后的位置并在最后的索引处生成一个有效的窗口。 最后出现的最小值变为 0，因此答案为 3。 

对于高度交错的字符串，例如`abcbac`，出现多个有效窗口。 该算法不会尝试选择单个“第一个”窗口；而是尝试选择一个“第一个”窗口。 它独立评估每个端点，确保后面的窗口无法隐藏更好的早期窗口。 

对于角色出现较晚的情况，例如`aaabbbccc`如果邻接限制被删除，该方法仍然正确地跟踪最后出现的情况，并且只有在看到所有字符后才形成有效窗口，之后它使用在每个新出现处结束的更紧密的窗口不断更新答案。
