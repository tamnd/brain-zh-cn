 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，以顶点 1 作为根。 每个顶点都带有一个数值和一个唯一的排名。 该任务不是关于树中的任意路径，而是关于受祖先和等级过滤约束的非常具体的路径。 

对于每个顶点 i，我们查看 u 到 v 的所有简单路径，使得 i 是两个端点的祖先。 由于树是有根的，这意味着 u 和 v 都位于 i 的子树内，并且它们之间的唯一路径必然经过 i。 除了结构约束之外，我们只允许使用等级最多为 i 等级的顶点。 最后，在所有这些有效对 (u, v) 中，我们想要沿路径的顶点值的最大可能总和。 

关键的困难在于约束取决于 i，但也限制了哪些顶点在其子树内可用。 因此，每个查询实际上都是在由“i 下允许的节点”诱导的动态过滤树中询问最佳路径。 

约束条件很大，测试用例的总数 n 最多为 5 · 10^5。 这立即排除了任何使用 DFS 或动态编程以简单方式重新计算每个节点最佳路径的方法，因为在最坏的情况下这将是二次的。 即使每个节点的 O(n log n) 也是不可能的。 该结构表明每个节点的答案必须来自全局处理，可能是通过按特定顺序激活顶点来得出的。 

当所有值都为负时，会出现微妙的边缘情况。 那么最好的“路径”不是长链而是单个顶点，因为任何延伸都会减少总和。 另一个极端情况是当节点在其子树中具有最小等级时。 在这种情况下，只有该节点可用，从而迫使答案折叠为其自身的值。 

最后一个重要的观察结果是，排名是唯一的，因此我们可以将它们视为对激活的严格排序。 

## 方法

 直接的强力解决方案将独立考虑每个节点 i。 对于固定的 i，我们将收集其子树中等级最多为 ri 的所有节点，然后计算该过滤集中任意两个节点之间的最大路径和，其中路径必须经过 i。 这减少了在这个过滤子树内找到从 i 开始的两条最佳向下路径。 我们可以每次从 i 运行 DFS，跳过无效节点。 

这是正确的，但非常昂贵。 在最坏的情况下，对于每个节点，我们几乎遍历整个子树，导致总工作量为 O(n^2)。 当 n 达到 5·10^5 时，这是完全不可行的。 

关键的见解是停止独立处理每个 i ，而是按升序处理节点。 如果我们想象按照等级递增的顺序逐渐“激活”节点，那么在我们激活节点 i 的那一刻，正是等级 ≤ ri 的节点处于活动状态。 这与问题中的约束相匹配。 

现在问题变得动态了：随着节点的添加，我们维护有关其最高排名节点是当前节点 i 的最佳路径的信息。 “i 是 u 和 v 的祖先”这一限制意味着 u 和 v 必须位于 i 的活动子树的不同部分，因此我们需要在活动森林的组成部分内保持最佳的向上和向下贡献。 

这是一种经典的动态树连接风格，其中每个激活的节点合并其子组件。 通过 i 的路径的值是通过组合两个不同子子树的最佳向下贡献来确定的。 因此，对于每个节点，我们在每个活动组件内维护最佳的“从该节点开始向下的单路径总和”，并且我们组合两个最大的此类值以形成当前排名的候选答案。 

这将问题转化为树上类似联合的过程，按排序顺序处理，其中每次激活都会更新本地最佳路径信息。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 等级激活+DP合并| O(n log n) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们按照等级递增的顺序处理顶点，因为等级定义了约束边界。 

1. 按升序对所有顶点进行排序。 我们将按照这个顺序一一激活它们。 在处理顶点 i 时，所有具有较小等级的顶点都已处于活动状态且符合条件。 
2. 维护一个布尔数组active[v]，指示当前是否允许某个顶点。 最初，所有这些都处于非活动状态。 
3. 对于每个顶点 i，当它变为活动状态时，将其标记为活动状态并将其视为连接到树中任何已活动的子节点。 这有效地构建了由活跃节点诱导的森林。 
4. 对于每个活动节点 v，维护一个值 dp[v]，定义为仅使用活动节点从 v 开始的下行路径的最大总和。 如果 v 没有活动的子节点，则 dp[v] = a[v]。 如果它有活跃的子节点，则 dp[v] 要么是单独的 a[v]，要么是 a[v] 加上其子节点中最好的 dp。 
5. 当激活节点 i 时，我们查看它的活动子节点。 我们获取它们的 dp 值并对前两个值进行排序或跟踪。 这些代表从 i 开始进入不同子树的最佳两条向下路径。 
6. 将 i 加上不同子节点的两个最大正 dp 贡献之和，得到以 i 作为最高点的最佳路径。 如果存在的积极贡献少于两个，我们就会回到最佳单一路径。 
7. 将此计算值存储为 i 的答案。 
8. 最后继续，直到处理完所有节点。 

重要的实现细节是，dp 值必须在激活的结构中自下而上地维护，因此每当节点变为活动状态时，就会立即从其子树方向上已活动的邻居计算其 dp。 

### 为什么它有效

 在任何时刻，活动节点都会形成一个森林，其中，仅当两个端点都处于活动状态时，每个边都将一个节点连接到其父节点。 因为我们通过递增秩进行处理，所以在处理 i 时，约束 ri 下的任何有效路径都完全包含在该活动森林中。 

对于固定的 i，任何有效路径 u 到 v 都必须经过 i，并且必须完全位于活动节点中。 删除 i 会将树拆分为子子树，并且任何穿过 i 的有效路径必须从一个子树中选取一个端点，并从另一子树中选取另一个端点。 最好的选择正是来自不同孩子的两个最好的独立向下贡献。 dp 结构保证我们始终知道从每个子子树开始的最佳向下路径，因此将前两个子树结合起来即可得到最佳交叉路径。 

这个不变量确保在处理 i 时，正确评估最大秩为 i 的所有候选路径，并且后面的节点不能对 i 为最大秩的路径做出贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parent = [0] * (n + 1)
        p = list(map(int, input().split()))
        for i in range(2, n + 1):
            parent[i] = p[i - 2]

        a = [0] + list(map(int, input().split()))
        r = [0] + list(map(int, input().split()))

        children = [[] for _ in range(n + 1)]
        for v in range(2, n + 1):
            children[parent[v]].append(v)

        order = list(range(1, n + 1))
        order.sort(key=lambda x: r[x])

        active = [False] * (n + 1)
        dp = [0] * (n + 1)
        ans = [0] * (n + 1)

        def get_best(v):
            best1 = 0
            best2 = 0
            for to in children[v]:
                if active[to]:
                    val = dp[to]
                    if val > best1:
                        best2 = best1
                        best1 = val
                    elif val > best2:
                        best2 = val
            return best1, best2

        for v in order:
            active[v] = True

            dp[v] = a[v]
            for to in children[v]:
                if active[to]:
                    dp[v] = max(dp[v], a[v] + dp[to])

            best1, best2 = get_best(v)

            ans[v] = max(a[v], a[v] + best1, a[v] + best1 + best2)

        print(*ans[1:])

if __name__ == "__main__":
    solve()
```该代码直接反映激活顺序。 dp 数组存储当前活动森林中的最佳向下贡献。 对于每个节点，我们通过检查已经活动的子节点来计算激活后的 dp，因为它们的等级较小。 然后我们提取最好的两个子贡献来形成通过该节点的最佳路径。 

一个微妙的点是 get_best 中最佳值的初始化。 我们隐式地对待非正贡献，因为始终允许通过 a[v] 在节点处开始新路径。 这避免了错误地将负分支强加到答案中。

 ### 示例 1

 输入树很小，让我们清楚地看到激活顺序。 假设链 1 → 2 → 3，其等级为 2、1、3，值为 1、5、9。 

我们按等级进行处理：节点 2，然后是 1，然后是 3。 

| 步骤| 活跃节点| dp 值已更新 | 最佳儿童贡献| 答案|
 | --- | --- | --- | --- | --- |
 | 2 | {2} | dp[2]=5 | 无 | 5 |
 | 1 | {2,1} | dp[1]=1+5=6 | 最好的孩子 2 给出 5 | 6 |
 | 3 | {2,1,3} | dp[3]=9 | dp[3]=9 无 | 9 |

 这显示了激活如何逐渐构建可用路径，以及节点 1 如何从合并到已经活跃的子树中受益。 

### 示例 2

 考虑一棵分支树，其中节点 i 有两个具有很强贡献的子节点。 

| 步骤| 活跃节点| dp 值 | 最佳1 | 最佳2 | 答案|
 | --- | --- | --- | --- | --- | --- |
 | 我| 激活我 | dp[i]=a[i] | dp[i]=a[i] | c1 | c2 | a[i]+c1+c2 |

 这演示了关键机制：通过当前节点组合两个独立的子贡献。

 ## 边缘情况

 一种边缘情况是所有值均为负数。 在这种情况下，任何扩展路径的尝试都会减少总和，因此每个节点的正确答案就是它自己的值。 在激活期间，子级的 dp 值永远不会提高父级的基值，因此 best1 和 best2 仍然是非正贡献，并且公式正确地回落到 a[i]。 

另一种情况是星形树，其根有许多子节点。 当处理根时，所有子节点可能已经处于活动状态，并且算法必须正确选择其中两个最大的 dp 值。 激活顺序确保所有子项在根之前可用，因此 get_best(root) 可以看到完整的候选集。 

最后一种微妙的情况是节点只有一个活动子节点。 那么 best2 为零，算法不得错误地假设存在两条路径。 a[i] 的最大值确保了正确性，因为如果没有不同子树中的第二个端点，单个分支无法形成通过 i 的交叉路径。
