 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例，每个测试用例都包含一个整数数组。 对于每个数组，我们可以任意重新排序其元素。 重新排序后，我们计算每个位置的派生值，定义为放置在那里的值减去其位置索引。 

要求是所有这些派生值必须彼此不同。 换句话说，如果我们查看每个位置并计算值与其索引之间的差距，则不允许两个位置产生相同的差距。 如果存在这样的重排，我们必须输出一个； 否则我们输出减一。 

约束条件很大，测试用例多达 100,000 个，元素总数多达 500,000 个。 这立即排除了尝试所有排列或对每个测试用例执行二次检查的任何解决方案。 我们需要一种以线性或线性时间处理每个测试用例的方法，理想情况下排序一次，然后执行一次。 

此类问题中的一个微妙问题是数组中的重复项可能会在派生表达式中产生隐藏的冲突。 例如，如果不小心将许多相等的值跨索引放置，则它们的值减去索引可能会意外重复。 即使在小例子（例如数组）上放置没有结构的任意元素的天真贪婪也可能会失败`[5, 5, 5, 5]`，其中不小心的放置很容易产生重复的差异，例如`5 − 1`和`5 − 2`重新排列选择后两者都会折叠成相同的值。 

## 方法

 强力解释将尝试数组的所有排列，并检查每个排列的派生值是否不同。 对于长度为 n 的数组，有 n 个阶乘排列，并且计算每个排列的有效性需要线性时间，导致总共大约有 n 阶乘乘以 n 次操作。 即使 n 等于 10，这也变得完全不可行，并且对于更大的约束，爆炸会更严重。 

关键的观察是我们实际上不需要探索组合安排。 我们只需要控制顺序，使值减去索引的序列永远不会重复。 如果我们对序列施加强单调结构，我们就可以保证这些派生值也是严格排序的，这自动意味着独特性。 

以非递增顺序对数组进行排序足以强加该结构。 一旦将值从最大到最小排列，向右的每一步都会将 a 的值最多减少零，同时将索引恰好增加 1。 这确保了当我们沿着数组移动时，表达式 a[i] 减去 i 严格减小。 严格递减序列不能包含重复项，因此自动满足条件。

 | 蛮力 | 每个测试用例 O(n!) | O(n) | 太慢了 |

 ## 算法演练

 我们独立处理每个测试用例并构建一个顺序，以保证派生序列的严格单调性。 

1. 读取当前测试用例的数组。 值本身还没有被修改，只是被收集。 
2. 按降序对数组进行排序，以便较大的值在最终排列中始终出现在较早的位置。 这会在值中创建受控的递减结构。 
3. 将排序后的值从左到右放回到位置。 已排序数组的第一个元素位于位置 1，第二个元素位于位置 2，依此类推。 
4. 将导出值概念性地计算为 a[i] 减去 i。 由于数组按降序排序，因此与前一个位置相比，向右的每一步都将表达式至少减少 1。 
5、直接输出构造好的数组。 

### 为什么它有效

 令重新排列后的数组为 b，排序后使得 b1 ≥ b2 ≥ ... ≥ bn。 考虑导出的序列 di = bi − i。 当从位置 i 移动到 i + 1 时，变化为 di − di+1 = (bi − i) − (bi+1 − (i + 1)) = (bi − bi+1) + 1。由于 bi ≥ bi+1，该数量始终至少为 1。因此 di 在整个数组中严格递减。 严格递减序列不能重复值，因此所有di都是两两不同，满足要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        out.append(" ".join(map(str, a)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案完全依赖于按降序对每个数组进行排序并直接打印。 关键的实现细节是使用反向排序，而不是尝试显式跟踪差异。 在执行过程中根本不需要计算 a[i] 减去 i，因为证明仅通过排序就保证了正确性。 

一个常见的错误是在跟踪使用的差异的同时尝试贪婪地构造排列。 这种方法引入了不必要的簿记，如果实施不当，还会面临发生冲突的风险。 排序顺序通过强制执行全局结构来绕过所有这些。 

## 工作示例

 ### 示例 1

 输入数组：`[3, 1, 4, 2]`按降序排序后，我们得到`[4, 3, 2, 1]`。 

我们一步步计算导出值。 

| 我| b[i] | b[i] - 我 |
 | --- | --- | --- |
 | 1 | 4 | 3 |
 | 2 | 3 | 1 |
 | 3 | 2 | -1 |
 | 4 | 1 | -3 |

 每个值都严格小于前一个值，因此不会发生重复。 

该跟踪证实，即使原始数组是无序的，降序排列也会强制派生表达式的严格单调性。 

### 示例 2

 输入数组：`[5, 5, 5, 5]`排序后，剩下`[5, 5, 5, 5]`。 

我们计算：

 | 我| b[i] | b[i] - 我 |
 | --- | --- | --- |
 | 1 | 5 | 4 |
 | 2 | 5 | 3 |
 | 3 | 5 | 2 |
 | 4 | 5 | 1 |

 尽管所有值都相同，但按索引进行减法会创建严格递减的序列，因此可以避免冲突。 

此案例说明了为什么只要排序一致，输入中的重复并不重要。

 ## 边缘情况

 对于所有值都相同的数组，一种简单的方法可能会尝试小心地分散相等的值以避免冲突。 事实上，排序已经固定了结构。 对于像这样的输入`[9, 9, 9, 9]`，算法保持不变，导出值变为`[8, 7, 6, 5]`，它们都是不同的。 

对于已经排序的递增数组，贪婪的尝试可能会使数组保持不变，并在不检查排序结构的情况下错误地假设有效性。 为了`[1, 2, 3, 4]`，该算法将其反转为`[4, 3, 2, 1]`，产生严格递减的派生序列并避免重复值。
