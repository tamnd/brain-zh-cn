 ## 解决方案
 ## 问题理解

 该曲目包含`N`等间隔的标志，维尼修斯计划精确地运行`V`完成圈数。 因为一圈就超过了所有`N`标志，整个训练包括`V * N`签署段落。 

对于从 10% 到 90% 的每个百分比，我们需要最小整数个符号，其完整训练的相应分数至少为该百分比。 输出包含九个值，依次为 10%、20%、...、90%。 

例如，与`V = 3`和`N = 17`，训练有`51`签署段落。 对于30%，要求的值至少是最小的整数`0.30 * 51 = 15.3`，即`16`。 “至少”一词使得向上舍入成为必要。 

两个都`V`和`N`至多是`10^4`，因此符号通道总数可以达到`10^8`。 因此，扫描每个标志通道的解决方案可以执行大约一亿次迭代。 对于一个答案仅由九个数字组成的问题来说，这比所需的工作量要多得多。 计算的结构让我们能够在恒定的时间内解决它，而不管训练的规模有多大。 

主要的边缘情况来自舍入。 有输入`1 1`，整个训练只有一个标志通道。 从 10% 到 90% 的每个正百分比都需要达到唯一的符号，因此正确的输出是`1 1 1 1 1 1 1 1 1`。 使用整数下限除法的粗心实现会为每个百分比产生零。 

另一个有用的边界情况是`3 11`。 总计为`33`，30% 是`9.9`，所以答案一定是`10`， 不是`9`。 完整的输出是`4 7 10 14 17 20 24 27 30`。 没有上限运算的直接整数除法在以下值处默默失败`9.9`。 

精确整除的情况表现不同。 有输入`10 10`，总计为`100`，因此每个请求的百分比都是整数个符号。 输出是`10 20 30 40 50 60 70 80 90`。 上限公式必须保留精确的整数，而不是添加不必要的额外符号。 

## 方法

 一种直接的方法是逐个符号地模拟训练。 有`V * N`总共签署段落。 对于每个百分比，我们可以不断增加通过的标志数量，直到总训练的比例达到所需的百分比。 这是正确的，因为达到阈值的第一个位置正是维尼修斯必须计算的最小符号数。 

问题是最大训练包含`10^4 * 10^4 = 10^8`签署段落。 因此，模拟可能需要多达`10^8`迭代，并且对几个百分比进行单独扫描将使该方法更加浪费。 虽然`10^8`这在数学上不是不可能的，而是没有必要的，并且给解决方案带来了更不舒服的性能裕度。 

关键的观察结果是，一次完整训练的标志数量是立即可知的：`V * N`。 如果我们至少想要`k * 10%`训练中，所需的实数符号数为`(V * N * k) / 10`在哪里`k`范围从 1 到 9。 

答案必须是整数个符号，并且必须足够大以达到阈值。 这意味着我们需要这个值的上限。 对于正整数，上限为`x / 10`可以计算为`(x + 9) // 10`。 因此，九个答案中的每一个都可以直接获得，无需模拟。 

暴力破解之所以有效，是因为它搜索满足每个百分比条件的第一个符号计数，但会失败，因为搜索空间可以包含`10^8`职位。 观察到每个阈值只是已知总数的固定分数，因此我们可以用九种算术计算来代替搜索。

 ## 算法演练

 1. 阅读`V`和`N`， 在哪里`V * N`是完整训练过程中通过的标志总数。 
2. 计算`total = V * N`。 这为我们提供了每个百分比计算的分母，因此没有理由模拟单独的圈数或标志。 
3. 对于每个`k`从`1`通过`9`, 计算`total * k`。 将此数量除以`10`给出对应的确切符号数`10k%`的培训。 
4. 使用该值向上舍入`(total * k + 9) // 10`。 需要向上舍入，因为跑步者需要至少完成所要求的百分比。 如果精确值已经是整数，普通整数除法仍然返回该精确值。 
5. 打印九个计算值，用空格分隔，保留 10% 到 90% 的顺序。 

为什么有效：适用于任何要求的百分比`10k%`，跑步者必须至少通过`(V * N * k) / 10`迹象。 由于传递的符号数是整数，因此最小有效计数恰好是该分数的上限。 表达式`(x + 9) // 10`计算每个正整数的上限`x`，因此每个生成的答案都是充分且最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

V, N = map(int, input().split())

total = V * N

answer = [(total * k + 9) // 10 for k in range(1, 10)]

print(*answer)
```第一行读取描述训练的两个量。 只有一个测试用例，因此程序读取输入后可以立即执行计算。`total = V * N`表示所有计划圈数中的标志通道数。 由于每一圈都包含准确的`N`等距标志，将圈数乘以每圈的标志数即可得出与问题相关的完整训练长度。 

列表理解评估九个请求的百分比。 为了`k = 1`，计算10%阈值； 为了`k = 2`，计算20%； 等等通过`k = 9`。 

表达式`(total * k + 9) // 10`是仅限整数的上限运算。 使用`total * k // 10`只要阈值不是整数，就会出错，因为楼层划分会向下舍入，并且可能会使跑步者低于所请求的百分比。 

Python 整数自动处理大于固定宽度机器整数的值，因此不存在溢出问题。 即使在这里，`V * N`至多是`10^8`，并将其乘以`9`最多给出`9 * 10^8`，它也适合标准 32 位有符号整数。

def solve(inp: str) -> str:

    answer = [(total * k + 9) // 10 for k in range(1, 10)]

 ## 边缘情况

 对于最小输入`1 1`，总计为`1`。 对于每一个`k`从 1 到 9，表达式变为`(k + 9) // 10`，所有九个值均为 1。 因此输出是`1 1 1 1 1 1 1 1 1`。 基于楼层的实现会错误地打印零，因为`k // 10`这些值为零。 

对于边界输入`3 11`，总计为`33`。 30%的门槛是`99 / 10 = 9.9`，所以计算`(99 + 9) // 10 = 10`正确向上舍入。 完整的输出是`4 7 10 14 17 20 24 27 30`。 这抓住了使用的常见错误`total * k // 10`，这将为第三个值生成 9。 

对于精确整除输入`10 10`，总计为`100`。 例如，在 20% 时，阈值恰好是`20`， 和`(200 + 9) // 10`等于`20`， 不是`21`。 对于每个请求的百分比也是如此，给出`10 20 30 40 50 60 70 80 90`。 这`+9`上限公式中仅补偿非零余数，而精确倍数保持不变。 

对于最大输入`10000 10000`，总计为`100,000,000`。 90%的阈值是`90,000,000`，并且所有算术都保持准确。 该算法执行与最小输入相同的九次迭代，因此将训练从一次符号通道增加到一亿次不会增加算法步骤数。
