 ## 解决方案
 ## 问题理解

 我们有一系列`N`爆米花袋在哪里`P[i]`是袋子里爆米花的数量`i`。 有`C`参赛者，每个参赛者最多可以吃`T`每秒爆米花。 

袋子必须分成连续的部分。 竞争对手收到一个段，而竞争对手可能收到一个空段，因此使用的数量少于`C`允许非空段。 由于一袋爆米花不能在参赛者之间分配，因此每个部分的爆米花总数必须由一名参赛者吃完。 所有参赛者同时工作，因此总比赛时间由最慢的参赛者决定。 

对于包含以下内容的段`S`爆米花，它的食用时间是`ceil(S / T)`。 我们需要选择最小化最大此类时间的连续分区并输出最小秒数。 

该数组最多可以包含`10^5`包。 每袋最多含有`10^4`爆米花，所以总量可以达到`10^9`。 二次算法已经执行了大约`10^10`在最坏的情况下进行操作，这远远超出了合理范围。 我们需要一些接近线性或`O(N log N)`。 参赛者的数量也可以多达`10^5`，所以一种方法二次依赖于`C`不适合。 

有几种边界情况可能会暴露出不正确的实现。 如果只有一个包，比如```
1 3 4
5
```答案是`2`，因为一位竞争对手需要`ceil(5 / 4) = 2`秒。 粗心的基于分区的解决方案可能会错误地尝试将单个包分配给多个竞争对手，这是禁止的，因为一个包必须完全属于一个竞争对手。 

另一种情况是竞争对手多于包包时：```
2 5 3
4 7
```答案是`3`。 这两个袋子可以分配给两名参赛者，而其他三名参赛者则什么都不做。 将竞争者的数量视为所需的非空组的数量将拒绝这种有效的安排。 

当一个包比所有其他可能的组都大时，就会出现第三种边缘情况：```
3 2 1
1 1 5
```答案是`5`。 袋子里装有`5`爆米花已经需要五秒钟，无论其他袋子如何分配。 任何仅平衡总量而不考虑单个袋子大小的算法都可能错误地预测较小的答案。 

最后，在计算完竞争对手的总分后，必须进行四舍五入。 为了```
2 2 4
5 5
```每个参赛者都需要`ceil(5 / 4) = 2`秒，所以答案是`2`， 不是`ceil(10 / (2 * 4)) = 2`巧合。 在其他情况下，区别很重要，因此解决方案应该直接推理整数时间限制，而不是对竞争对手的爆米花进行平均。 

## 方法

 直接的暴力解决方案考虑了在连续袋子之间放置边界的所有可能方法。 有`N - 1`可能的边界，每个边界都可以选择或不选择，给出`2^(N-1)`不同的分区。 对于每个分区，我们可以计算分配给每个参赛者的爆米花总数，并保留最大的所需进食时间。 对所有分区取最小值是正确的，因为每个合法的连续分配恰好对应于一组这样的边界。 

问题是分区的数量。 什么时候`N = 10^5`，可能性的数量是`2^99999`，这是一个天文数字。 即使评估每个分区只花费恒定的时间，搜索也已经是不可能的。 用直截了当的`O(N)`每个分区的评估，最坏情况的工作是`O(N * 2^N)`。 这种方法仅适用于微小数组，并且为我们提供了最佳值的定义，而不是实用的算法。 

有用的观察是我们实际上并不需要立即构建最佳分区。 相反，假设我们猜测整个比赛必须在`X`秒。 这样的话，每个参赛者最多能吃到`X * T`爆米花。 问题就变得简单多了：数组最多可以分为`C`连续的组，每个组的总和最多`X * T`？ 

对于固定容量，有一种贪婪的方法来回答这个问题。 从左到右扫描阵列，在不超过容量的情况下，不断向当前竞争对手添加行李。 当下一个袋子的金额太大时，就开始一个新的竞争对手。 因为所有的爆米花数量都是正数，所以在当前细分市场中投入更多的袋子永远不会减少以后需要的竞争对手的数量。 因此，贪婪分区使用该容量的最小可能数量的段。 

可行性也是单调的。 如果`X`秒就足够了，那么任何更大的秒数也足够了，因为每个竞争对手都获得了更大的容量。 如果`X`秒是不可能的，每个更小的值都是不可能的。 这种单调属性允许对答案进行二分搜索。 

我们可以在之间进行二分搜索`1`第二个和`ceil(sum(P) / T)`秒。 对于每个候选时间，我们将其乘以`T`为了获得最大的爆米花，竞争对手可以处理并运行贪婪的可行性检查。 由此产生的复杂度是`O(N log(sum(P) / T))`，这很容易足够快`N = 10^5`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(N * 2^N)`|`O(N)`| 太慢了 |
 | 二分查找+贪心|`O(N log(sum(P) / T))`|`O(N)`| 已接受 |

 ## 算法演练

 1. 阅读`N`,`C`,`T`以及爆米花数量的数组。 还要计算爆米花的总数，因为它为我们提供了答案的上限。 
2. 将二分查找下限设置为`1`第二个和上限`ceil(sum(P) / T)`秒。 上限相当于将所有袋子交给一名参赛者。 尽管可能有`C`竞争对手，只允许有一个非空竞争对手。 
3. 候选人时间`mid`，将一个竞争对手的能力计算为`mid * T`。 我们现在询问是否所有行李最多可以分配给`C`总和不超过此容量的连续组。 
4. 从左到右扫描阵列。 维持分配给当前竞争对手的爆米花数量。 如果添加下一个行李仍处于容量范围内，则将其保留在当前航段中。 如果超出容量，则用该包开始一个新的段，并增加使用的参赛者数量。 
5. 如果任何单个行李大于容量，则立即无法进行候选时间。 否则，在扫描整个数组后，当所需的非空段的数量最多为`C`。 
6. 如果候选可行，则搜索下半部分，因为答案可能更小。 如果不可行，则搜索上半部分，因为需要更多时间。 
7. 继续，直到二分搜索间隔包含一个值。 该值是有效分区存在的最小秒数。 

### 为什么它有效

 对于任何固定容量，贪婪扫描会在开始下一个段之前创建尽可能大的段。 考虑任何有效分区的第一个段。 由于所有行李数量均为正数，因此在保持容量范围内的情况下用另一个行李扩展第一段并不会让剩余的后缀比将该行李留给下一个竞争对手更难划分。 重复此参数意味着贪婪方法最大限度地减少整个数组所需的段数。 

因此可行性检查是正确的。 谓词“可以在`X`秒”是单调的，因为增加`X`只会增加每个竞争对手的能力。 因此，二分查找找到最小的可行值`X`，这正是最佳的比赛时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c, t = map(int, input().split())
    p = list(map(int, input().split()))

    total = sum(p)

    def feasible(seconds):
        capacity = seconds * t
        competitors = 1
        current = 0

        for x in p:
            if x > capacity:
                return False

            if current + x <= capacity:
                current += x
            else:
                competitors += 1
                current = x

                if competitors > c:
                    return False

        return True

    lo = 1
    hi = (total + t - 1) // t

    while lo < hi:
        mid = (lo + hi) // 2

        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```这`feasible`函数实现了算法的贪婪分区。`capacity`是一位参赛者在候选秒数内可以吃的最大数量。 变量`current`存储分配给当前竞争对手的爆米花，同时`competitors`计算已创建的非空段数。 

测试`x > capacity`是必要的，因为没有任何隔板可以分割袋子。 即使有很多未使用的参赛者，超过候选容量的单个行李也不能合法分配。 

什么时候`current + x`超出容量，当前段关闭，新段开始`x`。 没有理由将较早的包移至新的竞争对手，因为这只会使第一段变小，而无法减少剩余后缀所需的段数。 

上限使用整数上限除法，`(total + t - 1) // t`。 该值表示一名参赛者吃完所有爆米花所需的时间。 它始终是一个有效的上限，因为允许未使用的竞争者。 

二分查找使用`lo < hi`，因此当循环结束时，两个界限代表相同的最小可行时间。 Python 整数具有任意精度，因此乘法如`seconds * t`不能溢出。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(N log(sum(P) / T))`| 每个可行性检查都会扫描所有`N`袋，二分搜索执行对数多次检查 |
 | 空间|`O(N)`| 爆米花数量数组存储在内存中 |

 爆米花总量最多为`10^5 * 10^4 = 10^9`，所以二分查找只有大约三十次迭代。 每次迭代最多执行一次线性扫描`10^5`包，提供大约数百万次简单操作。 这完全在约束的预期范围内。

## 边缘情况

 ### 单包

 考虑```
1 3 4
5
```二分查找最终测试`2`秒，给出容量`8`。 唯一合适的袋子，贪婪检查使用一个竞争对手，最多三个。 结果是`2`。 

该算法从不尝试将袋子分给竞争对手。 整个包由同一个贪心段处理，这直接尊重了不可分性规则。 

### 竞争对手比包包还多

 考虑```
2 5 3
4 7
```爆米花总量为`11`，给出上限`4`秒。 在`3`秒，每个参赛者都能处理`9`爆米花。 贪心分区是`[4] | [7]`，需要两名参赛者。 自从`2 <= 5`，候选者可行，答案为`3`。 

支票故意使用`competitors <= C`而不是`competitors == C`。 空竞争者是合法的，因此要求恰好五个非空段将错误地拒绝这种情况。 

### 大于候选人容量的包

 考虑```
3 2 1
1 1 5
```为了`4`秒，容量为`4`。 当贪婪扫描到达最终包含的包时`5`，条件`x > capacity`立即使候选人变得不可行。 重新排列无济于事，因为袋子必须保持整齐，而且袋子本身不能分开。 

在`5`秒容量变为`5`。 贪心分区是`[1, 1] | [5]`，需要恰好两个竞争对手，所以`5`是可行的，并且是最小值。 

### 连续分组很重要

 考虑```
5 2 1
1 1 1 1 1
```对于两个竞争者，三秒就足够了，因为数组可以分割为`[1, 1, 1] | [1, 1]`。 最大的部分包含三颗爆米花，所以答案是`3`。 

两秒钟内，两名参赛者必须处理两颗爆米花，留下一袋未分配的爆米花。 非连续分配可能看起来可以平衡
