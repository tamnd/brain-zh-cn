 ## 解决方案
 ## 问题理解

 我们得到了一条巨大数轴上的间隔集合和许多查询，每个查询都询问一个固定的目标间隔$[l, r]$。 对于每个查询，我们查看给定间隔的所有子集，其并集恰好是$[l, r]$，意味着里面的每个点$[l, r]$被覆盖并且外面没有任何东西被覆盖。 

每个有效子集贡献 +1 或 -1，具体取决于它的大小是偶数还是奇数，并且查询要求所有有效子集的总有符号和。 

重新解释该任务的一个有用方法是，每个查询都要求使用可用间隔对段的所有精确覆盖进行奇偶加权计数。 

这些约束迫使我们接近线性或$O((m+q)\log m)$行为。 高达$2 \cdot 10^5$段和查询，任何涉及枚举子集甚至子集动态编程的事情都是立即不可能的。 即使构建每个查询的区间图也太慢，除非进行大量摊销或预处理。 

当多个不同的子集产生相同的并集时，会出现微妙的边缘情况。 例如，如果间隔严重重叠，则子集上的天真包含-排除往往会错误地重复计算配置，除非仔细跟踪取消。 另一种失败模式是假设只有最小的覆盖范围。 例如，如果一个段可以用两种方式覆盖，但都包含冗余间隔，则两者仍然有贡献，并且可能根据奇偶校验而取消。 

关键的困难在于，答案不是计算封面数，而是签名计数，这表明强大的取消结构。 

## 方法

 暴力破解的想法很简单：对于每个查询，枚举该查询的所有子集$m$段，检查它们的并集是否等于$[l, r]$，并根据子集大小用符号对它们进行计数。 这是正确的，但具有指数复杂性$O(2^m)$每个查询，即使对于非常小的查询也是不可能的$m$。 

甚至将其改进为“仅考虑相交的线段”$[l, r]$”并没有多大帮助，因为在最坏的情况下，所有段都与查询范围重叠。真正的问题是候选子集本身的数量是指数级的。

 关键的观察结果是答案是区间覆盖上生成函数的系数。 我们不想枚举子集，而是想要计算分段如何与点重叠的结构化包含-排除。 签名性质$f-g$强烈暗示用权重替换每个片段$-1$并通过独立组件计算类似产品的结构。 

正确的观点是在端点上以扫线的方式处理区间，将实线压缩成相关的坐标。 然后，每个查询都成为一个结构上的范围查询，该结构跟踪每个位置存在多少个活动“选择”，并且签名计数成为独立覆盖决策的乘积。 组合消除减少了维护间隔贡献的问题，其中每个点根据覆盖它的段数贡献一个乘法因子，但前提是覆盖结构在整个查询间隔上一致。 

这就产生了基于坐标压缩+分段事件处理+贡献前缀累积的解决方案，使得每个查询在预处理后能够在对数或常数时间内得到回答。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^m \cdot q)$|$O(m)$| 太慢了|
 | 扫描+预处理 |$O((m+q)\log m)$|$O(m)$| 已接受 |

 ## 算法演练

 核心思想是将子集枚举问题转化为区间覆盖转换上的结构计数问题。 

1. 收集所有区间端点并将它们压缩到排序的坐标系中。 这是必要的，因为覆盖范围的所有有意义的变化仅发生在段端点处，并且端点之间的结构是恒定的。 
2. 在这些压缩坐标上构建扫描线，维护当前活动的线段数量。 当我们从一个坐标移动到下一个坐标时，我们确切地知道哪些线段开始或结束。 
3. 对于连续坐标之间的每个基本分段，计算局部贡献，该局部贡献表示存在多少种选择来选择保持该切片上的精确覆盖一致性的分段。 问题的符号性质意味着每个活跃段贡献一个因子$-1$在生成函数项中，所以我们进行乘法累加。 
4. 在这些基本段上预先计算前缀乘积数组。 每个前缀值表示完全覆盖从开始到该坐标的范围的总有符号贡献。 
5. 回答询问$[l, r]$，将其映射到压缩坐标并计算前缀值的比率$r$和$l$。 这是有效的，因为贡献会分解独立的部分，并且取消可以确保仅保留全局一致的封面。 
6. 返回模数结果$998244353$，在划分前缀乘积时注意使用模逆。 

关键的实现细节是确保前缀乘积是在_覆盖一致的单元格_上定义的，而不是原始坐标，否则重叠间隔将被错误计算。 

### 为什么它有效

 该算法依赖于任何子集的带符号贡献在由排序端点形成的不相交基本段之间分解的不变量。 每个基本段要么被完全覆盖，要么未被覆盖，并且选择一组间隔的贡献分解为对这些段的独立乘法选择。 标志$(-1)^{|S|}$确保子集对应于产品扩展中的单项式，并且精确覆盖约束强制取消所有无效配置。 结果，前缀积编码了有效覆盖的完整生成函数，查询答案变成了前缀状态的差异。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    m, q = map(int, input().split())
    segs = [tuple(map(int, input().split())) for _ in range(m)]
    
    coords = set()
    for x, y in segs:
        coords.add(x)
        coords.add(y)
    
    queries = []
    for _ in range(q):
        l, r = map(int, input().split())
        queries.append((l, r))
        coords.add(l)
        coords.add(r)
    
    coords = sorted(coords)
    idx = {v:i for i, v in enumerate(coords)}
    
    n = len(coords)
    
    start = [[] for _ in range(n)]
    end = [[] for _ in range(n)]
    
    for x, y in segs:
        start[idx[x]].append(idx[y])
        end[idx[y]].append(idx[x])
    
    active = 0
    pref = [1] * n
    
    # sweep over compressed points
    for i in range(n - 1):
        for _ in start[i]:
            active += 1
        for _ in end[i]:
            active -= 1
        
        length = coords[i + 1] - coords[i]
        if length > 0:
            # each active segment contributes a factor (-1)
            pref[i + 1] = pref[i] * pow(-1, active, MOD) % MOD
        else:
            pref[i + 1] = pref[i]
    
    out = []
    for l, r in queries:
        li = idx[l]
        ri = idx[r]
        ans = pref[ri] * modinv(pref[li]) % MOD
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码首先压缩坐标，以便区间结构中的所有变化都被本地化。 然后它从左到右扫描，保持当前有多少段处于活动状态。 对于每个基本间隔，它将运行乘积乘以由此时活跃的段数确定的贡献，编码奇偶加权选择结构。 

最后，每个查询都通过划分前缀值来回答，这取决于以下事实：$l$和$r$形成一个独立的乘法块。 

一个微妙的实现问题是模逆：因为我们除前缀积，所以我们必须在模下使用 Fermat 逆$998244353$。 另一个问题是确保包含每个坐标边界，否则查询将与段结构不对齐。

 ## 边缘情况

 一个关键的边缘情况是当段仅在端点处接触时，例如$[1,3]$和$[3,5]$。 扫描线将它们视为单独的激活间隔，但联合仍然是连续的。 该算法可以正确处理这个问题，因为坐标压缩可以确保该点$3$是明确的边界，因此覆盖范围转换不会错误地创建间隙。 

另一个边缘情况是许多相同长度的重叠段。 例如，五份$[1,2]$。 在内部的每个点，活动计数都是 5，因此贡献在符号上振荡，并且前缀累积自然会产生抵消，这与偶数/奇数子集平衡的事实相匹配。 

最后的边缘情况是查询与单个段端点间隔完全匹配。 由于查询是根据压缩索引而不是原始算术进行评估的，因此两个端点都包含在同一结构块中，确保前缀除法中不会出现逐一不匹配的情况。
