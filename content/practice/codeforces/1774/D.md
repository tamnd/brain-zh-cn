 ## 解决方案
 ## 问题理解

 我们有`n`二进制行，每个长度`m`。 单个操作选择两行和一列，然后在这两行之间交换该列中的值。 

因为交换发生在同一列内，所以总数`1`整个矩阵中的 s 永远不会改变。 改变的是那些`1`s 分布在行中。 

目标是使每一行包含相同数量的`1`s。 如果这是不可能的，我们输出`-1`。 否则，我们必须输出实现目标的最小操作数和有效的交换序列。 

第一个观察结果是，总数`1`s 是不变的。 如果总数为`1`s 不能被整除`n`，那么均衡是不可能的，因为每一行都需要相同的整数计数`1`是。 
输入尺寸很大。 虽然`n`和`m`可以单独达到`10^5`，总和`n·m`所有测试用例最多是`10^6`。 这强烈表明需要一种矩阵大小呈线性或接近线性的算法。 任何重复扫描每个操作的所有行的方法都会变得太慢。 

棘手的部分不是决定是否存在解决方案。 挑战在于构建最少数量的交换。 

一个常见的错误是认为只要一行有太多`1`s 而另一个的太少了，我们可以随时转移一个`1`直接地。 那不是真的。 仅可在捐赠行具有的列中进行转移`1`接收器行有`0`。 

考虑：```
2 2
1 1
1 1
```两行已经包含两个`1`s，所以答案是零运算。 

现在考虑：```
2 2
1 0
1 0
```总数`1`s 是 2，因此目标是每行一个。 两行都已经有一个`1`，所以答案又是零。 

尝试“平衡列”而不是行计数的粗心实现可能会执行不必​​要的交换。 

另一个微妙的情况是：```
2 2
1 1
0 0
```目标是一个`1`每行。 只需要一次交换。 我们在行之间交换第 1 列或第 2 列。 任何使用两次交换的解决方案在最终状态下都是正确的，但不是最小的。 

最低操作要求很重要。 

## 方法

 暴力策略是重复选择满行和未满行，然后搜索所有列，直到找到可转移的位置。 每次传输后，重新计算所有内容并继续。 

这是有效的，因为每次成功的交换都会使不平衡度减少 1。 最终所有行都达到目标计数。 

问题是效率。 假设有`O(nm)`所需的转账。 如果每次传输都再次扫描整个矩阵，复杂度可以接近`O(nm·min(n,m))`或者更糟，这远远超出了允许的范围。 

关键的观察是，有用的交换看起来总是一样的。 

计数大于目标的行必须捐赠一些`1`s。 

计数小于目标的行必须接收一些`1`s。 

对于固定列，如果一行有`1`并且需要捐赠，而另一行有`0`并需要接收，那么该列就可以执行一次所需的传输。 

这建议独立处理列。 对于每一列，我们收集：

 首先，当前有的行`1`在这一栏仍然有多余的`1`总体而言。 

其次，当前有的行`0`在本专栏中，仍然需要额外的`1`总体而言。 

将第一组中的一行与第二组中的一行匹配会产生有效的交换。 每一次此类互换都会同时减少一项盈余和一项赤字。 

为什么这是最佳的？ 

每次交换都会将两行的计数沿相反方向更改一个单位。 如果某行超出目标`d`，它必须至少作为捐赠者参与`d`次。 对所有剩余行求和即可得出所需的最小传输次数。 我们的结构对每一次传输都执行一次交换`1`，所以它达到了这个下限。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²m) 或更差 | O(1) | O(1) | 太慢了|
 | 最佳 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 读取矩阵并计算`1`每行都有 s。 
2. 计算总数`1`矩阵中的s。 
3. 如果总和不能被整除`n`， 输出`-1`。 
4.让`target = total // n`。 
5. 对于每一列，构建两个临时列表。 

第一个列表包含计数大于的行`target`该列中的值是`1`。 

第二个列表包含计数小于的行`target`该列中的值是`0`。 
6. 按顺序匹配两个列表中的行。 

每对匹配代表一次有效的转账。 在捐赠者和接收者之间交换列值。 
7. 记录操作后，将捐赠者的行计数减 1，将接收者的行计数增加 1。 

此更新至关重要，因为在足够的传输后，一行可能不再是捐赠者或接收者。 
8. 继续浏览所有列。 
9. 输出所有记录的操作。 

### 为什么它有效

 让`target`是所需的数量`1`每行都有 s。 

一行有剩余`s = count - target`必须准确捐赠`s`那些。 连续赤字`d = target - count`必须准确接收`d`那些。 总盈余等于总赤字。 

每当我们进行交换时，我们都会选择捐赠者拥有的列`1`并且接收器有`0`。 交换后，捐赠者失去了一份`1`接收者获得一`1`。 其他行数没有变化。 

每项操作将总失衡减少两个单位，一个盈余和一个赤字。 由于每项操作都恰好传输所需的一个`1`，操作次数等于总盈余，这是可能的最小交换次数。 因此，该结构既正确又最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())

        a = []
        cnt = []

        total = 0

        for _ in range(n):
            row = list(map(int, input().split()))
            a.append(row)

            s = sum(row)
            cnt.append(s)
            total += s

        if total % n != 0:
            print(-1)
            continue

        target = total // n
        ops = []

        for col in range(m):
            donors = []
            receivers = []

            for row in range(n):
                if cnt[row] > target and a[row][col] == 1:
                    donors.append(row)
                elif cnt[row] < target and a[row][col] == 0:
                    receivers.append(row)

            k = min(len(donors), len(receivers))

            for i in range(k):
                x = donors[i]
                y = receivers[i]

                cnt[x] -= 1
                cnt[y] += 1

                a[x][col] = 0
                a[y][col] = 1

                ops.append((x + 1, y + 1, col + 1))

        print(len(ops))
        for x, y, z in ops:
            print(x, y, z)

solve()
```解决方案首先要计算`1`每行都有 s。 这些计数是决定谁必须捐赠和谁必须接受的唯一重要数量。 

首先进行整除性检查，因为没有任何交换序列可以改变总数`1`矩阵中的s。 

对于每一列，我们使用最新的行数来识别当前的捐赠者和接收者。 每次交换后计数都会立即更新。 这个细节至关重要。 以剩余三笔开始的行应在三笔转账后停止捐赠。 

每次操作后矩阵本身也会更新。 如果不更新列值，后续处理可能会错误地重用相同的值`1`多次。 

记录的操作`(x+1, y+1, col+1)`遵循语句要求的从 1 开始的索引。

 ## 边缘情况

 考虑：```
2 2
0 0
0 1
```总数`1`s 是一。 自从`1 % 2 != 0`，不存在均等分布。 该算法立即检测到这一点并输出`-1`。 

考虑：```
2 2
1 0
0 1
```每行已经包含一个`1`。 目标也是一。 在列处理期间，任何一行都不会成为施主或接收者。 没有记录任何操作，答案为零。 

考虑：```
2 2
1 1
0 0
```计数是`(2,0)`并且目标是一个。 在第一列中，第一行是捐赠者，第二行是接收者。 一次交换立即平衡两行。 该算法恰好输出一个操作，这是最少的。 

考虑：```
3 3
1 1 1
0 0 0
0 0 0
```总数`1`s 是三，所以目标是一。 第一行有剩余两个。 其他行各有一个赤字。 处理列独立地找到两个可转移位置并执行两次交换。 在这两次传输之后，每一行都包含一个`1`，并且操作次数等于总剩余，这是可能的最小值。
