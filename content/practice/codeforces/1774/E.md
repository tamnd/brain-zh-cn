 ## 解决方案
 ## 问题理解

 我们有一棵有根树，根在节点处`1`。 

两个棋子从根开始。 片段 A 必须访问给定集合中的每个节点`A`，块 B 必须访问另一个集合中的每个节点`B`。 顺序是任意的。 完成所有必需的访问后，两个部分都必须返回到根。 

一次移动就是将一个棋子精确地移动到一个树的边缘。 整个过程中，两块之间的距离绝不允许超过`d`。 

任务是找到最少的总移动次数。 

该树最多包含`2 · 10^5`顶点。 任何检查顶点对、重复运行图搜索或执行与每个节点的子树大小成比例的工作的解决方案都将太慢。 有了这个输入大小，我们应该期望`O(n)`或者`O(n log n)`解决方案。 

微妙的部分是距离限制。 没有它，这两部分是完全独立的。 有了它，一个块可能会被迫进入子树，即使它在那里没有所需的顶点，只是为了与另一个块保持足够近。 

考虑一条路径`1 - 2 - 3 - 4`和`d = 2`。 假设片A必须访问节点`4`而B块只需要根。 

一种幼稚的方法可能会说 B 块永远不必离开根。 那是不可能的。 当片A到达节点时`4`，到根的距离变为`3`，这超过了`d`。 块 B 必须向下移动到节点`2`而A则探索路径的更深部分。 距离限制会产生额外的强制移动。 

另一个容易犯的错误是假设只有所需的顶点才重要。 认为`d = 2`并且片A必须访问节点`5`在一条长链中。 即使块 B 在该分支中没有所需的顶点，它仍然可能需要输入几个中间顶点，因为 A 走得太深。 这些顶点对答案有贡献，不能被忽略。 

## 方法

 蛮力观点是考虑系统的完整状态。 

状态包含两个部分的位置以及每个部分已经访问过的所需顶点集。 我们可以在这个巨大的状态图中运行最短路径搜索。 这个公式是正确的，但即使对于一棵小树来说，状态的数量也会爆炸。 高达`2 · 10^5`顶点，这是完全不可行的。 

关键的观察来自于对单个作品的观察。 

假设没有距离限制。 那么一个片段只需要遍历连接根及其所有所需顶点的最小有根子树。 该子树的每条边都被恰好遍历两次，一次向下，一次向上返回。 

现在重新引入距离限制。 

取一些节点`u`。 想象一下 A 的子树内没有所需的顶点`u`。 通常 A 永远不会进入该子树。 A 可能仍然需要进入它的唯一原因是当 B 在那里探索所需的深层顶点时陪伴 B。 

B 必须深入多深，A 才被迫提供帮助？ 

如果B-所需的最深顶点在里面`u`的子树位于深度`mxB`，那么当 B 到达该顶点时，A 可以保持在`u`仅当`mxB - depth(u) ≤ d - 1`。 

否则距离会超过`d`，所以 A 也必须通过`u`。 

这将问题转化为每个顶点的纯局部条件。 

对于每个节点，我们需要知道其子树内每种类型所需的最深顶点。 一旦知道了这些深度，我们就可以决定每个部分是否必须访问该节点。 

最终的解决方案成为树上的单个 DFS。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 | 指数| 指数| 太慢了|
 | 树DP / DFS | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 在节点处建立树的根`1`并计算每个节点的深度。 
2. 对于每个节点`u`， 维持：`mxA[u]`= 子树内任何 A 所需顶点的最大深度`u`。`mxB[u]`= 子树内任意 B 要求的顶点的最大深度`u`。 

如果不存在这样的顶点，则值为`0`。 
3. 使用后序 DFS 计算这些值。 

如果`u`本身属于集合A，初始化`mxA[u] = depth[u]`。 

如果`u`本身属于集合B，初始化`mxB[u] = depth[u]`。 

然后通过取最大值来合并来自子级的信息。 
4. 从两个部分必须访问每个非根顶点的假设情况开始。 

每个树的边缘将被每个部分遍历两次。 

最初的答案是`4 · (n - 1)`。 
5. 判断A片是否确实需要节点`u`。 

A 片必须参观`u`如果：

 - 其子树中有一个需要A的顶点，意思是`mxA[u] > 0`, 或
 - B 块所需的顶点比距离更深`d - 1`以下`u`， 意义`mxB[u] - depth[u] >= d`。 

如果两个条件都不成立，则 A 永远不需要进入`u`。 

在这种情况下，我们将边缘 A 的往返成本从`u`到它的父级，减去`2`从答案中。 
6. 对 B 块应用对称规则。 

如果`mxB[u] == 0`和`mxA[u] - depth[u] < d`那么B不需要节点`u`，所以减去另一个`2`。 
7. 以这种方式处理每个非根节点。 剩余的值是最小移动次数。 

### 为什么它有效

 对于一个片段来说，要遍历一条边进入子树，必须有一个原因。 

第一个可能的原因很明显：子树包含它自己所需的顶点之一。 

第二个原因来自于距离的限制。 如果另一块必须至少到达所需的顶点`d`当前节点以下的级别，留在子树之外将违反最大允许距离。 通过该节点进入成为强制性的。 

这是一件作品需要跨越边缘的仅有的两个原因。 

从两个部分都遍历每个边两次的假设开始，计算每个可能的遍历。 对于每个片段和每个节点，我们精确地删除那些不需要的遍历。 DFS 精确计算哪些节点仍然是必要的，因此得到的总数是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

n, d = map(int, input().split())

g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

needA = [False] * (n + 1)
needB = [False] * (n + 1)

arr = list(map(int, input().split()))
for x in arr[1:]:
    needA[x] = True

arr = list(map(int, input().split()))
for x in arr[1:]:
    needB[x] = True

depth = [0] * (n + 1)
mxA = [0] * (n + 1)
mxB = [0] * (n + 1)

ans = 4 * (n - 1)

def dfs(u, p):
    global ans

    if needA[u]:
        mxA[u] = depth[u]

    if needB[u]:
        mxB[u] = depth[u]

    for v in g[u]:
        if v == p:
            continue

        depth[v] = depth[u] + 1
        dfs(v, u)

        mxA[u] = max(mxA[u], mxA[v])
        mxB[u] = max(mxB[u], mxB[v])

    if u != 1:
        if mxA[u] == 0 and mxB[u] - depth[u] < d:
            ans -= 2

        if mxB[u] == 0 and mxA[u] - depth[u] < d:
            ans -= 2

dfs(1, 0)

print(ans)
```DFS 同时计算三条信息。 

这`depth`数组给出了距根的距离。 数组`mxA`和`mxB`将每种类型所需的最深顶点存储在每个子树中。 

最初的答案假设每个部分都对整个树执行完整的 DFS 遍历。 那成本`2(n - 1)`每件移动，因此`4(n - 1)`总共。 

处理完一棵子树后，我们就知道一个片段是否有理由进入它。 如果不是，我们就删除连接该子树与其父树的边缘的一次往返。 往返有贡献`2`移动，这解释了减法。 

根被单独处理，因为它没有父边。 减去根会错误地消除不存在的运动。 

所有算术都可以轻松地用 Python 整数表示。 最大可能的答案是`4(n - 1)`，低于一百万。

 ## 边缘情况

 考虑链条```
4 2
1 2
2 3
3 4
1 4
1 1
```A 片必须到达节点`4`，B块只需要根。 

节点的子树`2`包含深度处 A 所需的顶点`3`。 自从`3 - 1 = 2`，块 B 不能保留在节点上方`2`。 条件`mxA[2] - depth[2] >= d`正是检测到这种情况，所以节点`2`被标记为 B 必需的。算法输出`8`，匹配最优策略。 

现在考虑```
4 2
1 2
1 3
1 4
1 2
1 3
```所需的顶点位于不同的浅分支中。 没有分支包含足够深的顶点来迫使另一部分进入内部。 每个片段只遍历自己的分支，DFS 会删除所有不必要的子树条目。 答案就变成了`4`。 

最后，考虑一个子树，其中任何一个片段都不包含所需的顶点。 两个移除条件都成立，因此每件都节省了一个往返的长度`2`。 这些死亡子树对最终路线没有任何贡献，正如预期的那样。
