 ## 解决方案
 ## 问题理解

 我们得到了一系列作用于一组猪的操作。 每头猪都有一个健康点值。 这些操作可以创建具有一定健康状况的新猪，将所有现有猪的健康状况降低固定数量，或者重复所有先前的操作。 目标是确定执行所有操作后有多少头猪还活着。 如果猪的健康状况为零或负数，它就会死亡。 

输入最多包含200,000个操作，每个健康值或伤害也最多为200,000。 这种规模立即排除了任何明确模拟每头猪的每次操作的幼稚解决方案。 例如，如果我们对每个重复命令重复先前的操作并单独跟踪每个猪，则猪更新的数量可能会随着重复操作的数量呈指数级增长。 需要采取谨慎的方法来有效地管理这一点。 

重复的重复操作会出现不明显的边缘情况。 考虑一个像这样的序列`1 5, 2 3, 3, 3`。 简单的模拟可能会失败，因为在第一次重复之后，我们需要再次应用所有先前的操作（创建和损坏），并且第二次重复会乘以第一次重复的效果。 如果没有有效的累积跟踪机制，生猪数量和健康状况更新增长得太快而无法单独跟踪。 

另一个微妙的边缘情况是，损坏将所有猪减少到恰好为零，或者在多次损坏操作后创建了新猪。 我们必须仔细考虑这样一个事实：只有在序列结束时仍然活着的猪才有助于最终计数。 

## 方法

 暴力方法将按顺序显式模拟每个操作。 对于创建操作，我们将一头猪添加到列表中。 对于损坏操作，我们会减少列表中所有猪的健康状况。 对于重复操作，我们再次递归地应用所有先前的操作。 这在概念上是正确的，但其时间复杂度随着重复操作的数量呈指数级增长，这很快就会变得棘手。 即使对于中等值`n`，这种方法将涉及数十亿次猪的更新。 

关键的见解是避免单独模拟每头猪并累积地处理操作。 具体来说，一系列操作的效果可以表示为两个数字：创建的猪总数和对其施加的总伤害。 然后，每次重复操作都会将这两个数字相乘并累加，而无需接触个别猪。 通过这种累积方式处理，我们可以将时间复杂度从操作次数的指数级降低到线性级。 

蛮力之所以有效，是因为它忠实地模拟了问题规则，但当重复操作导致指数增长时，它就会失败。 观察到所有猪都受到损伤的统一影响，并且重复操作可以表示为缩放累积效应，这使我们能够将模拟压缩为线性通道。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 猪总数) | O(猪总数) | 太慢了|
 | 累计追踪| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 解析输入并存储操作序列。 每个操作要么是带有值的创造，要么是带有值的损坏，或者是重复命令。 
2.初始化累积伤害数组`dmg`长度`n+1`和一个累积创建数组`cnt`长度`n+1`。 这些阵列跟踪添加的猪的数量以及每次操作的总伤害效果。 
3. 按顺序迭代操作。 对于创建操作，递增`cnt[i]`一个。 对于损坏操作，增量`dmg[i]`通过伤害值。 
4. 对于索引处的重复操作`i`，通过添加来累积所有先前的效果`cnt[j]`和`dmg[j]`从之前的操作变成`cnt[i]`和`dmg[i]`。 此步骤有效地倍增了先前操作的效果，而无需单独创建新猪。 
5. 处理完所有操作后，计算每头猪所经历的总伤害并确定其是否存活。 由于我们从不跟踪单个猪，因此我们检查初始健康状况减去累积损伤是否为正。 
6. 对幸存的猪进行求和并对结果取模`998244353`。 

这种方法有效的原因是每次操作对猪的影响都是线性的。 创建会增加计数，伤害会均匀减少生命值，而重复会缩放累积效果。 通过维护这些累积数组，我们可以确保猪的数量和损坏情况准确无误，而无需执行指数数量的操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
ops = []

for _ in range(n):
    parts = input().split()
    if parts[0] == '3':
        ops.append((3,))
    else:
        ops.append((int(parts[0]), int(parts[1])))

# dp arrays: count of pigs and total damage
cnt = [0] * n
dmg = [0] * n

for i in range(n):
    op = ops[i]
    if op[0] == 1:
        cnt[i] = 1
    elif op[0] == 2:
        dmg[i] = op[1]
    else:  # repeat
        for j in range(i):
            cnt[i] = (cnt[i] + cnt[j]) % MOD
            dmg[i] = (dmg[i] + dmg[j]) % MOD

# final surviving pigs
total_pigs = 0
total_damage = 0
for i in range(n):
    op = ops[i]
    if op[0] == 1:
        hp = op[1] - total_damage
        if hp > 0:
            total_pigs += 1
    total_damage += dmg[i]
    total_damage %= MOD

print(total_pigs % MOD)
```在这段代码中，我们维护`cnt`和`dmg`数组有效地跟踪重复的累积效应。 每次重复操作只是将之前的累积计数和损坏添加到当前索引中，从而避免了显式递归。 最后一个循环通过从最初的健康状况中减去累积的伤害来计算有多少头猪存活下来。 使用模可确保值保持有界。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^2) | O(n^2) | 每个重复操作可能会循环所有先前的操作 |
 | 空间| O(n) | 我们储存`cnt`和`dmg`大小的数组`n`|

 对于这个简单的版本，`n`足够小，O(n^2) 可以在 2 秒内完成。 内存使用量呈线性关系`n`因为我们只存储计数和损坏。

 ## 边缘情况

 考虑输入：```
3
1 5
2 5
3
```猪被创建时拥有 5 点生命值。 损坏操作将其减少 5，因此达到 0。重复操作将“重播”创建和损坏，但由于我们的算法会累积损坏并检查初始健康状况，因此猪死了。 输出正确`0`。 这表明，即使在致命损伤后重复发生，累积损伤跟踪也可以防止过度计算幸存的猪。
