 ## 解决方案
 ## 问题理解

 我们有一场锦标赛，选手编号从 1 到$n$，其中每个玩家的“温度”等于其人数。 战斗发生在标记为 0 或 1 的环境中。在环境 0 中，温度较低的玩家获胜，在环境 1 中，温度较高的玩家获胜。 环境序列以字符串形式给出$s$长度$n-1$，按顺序指定每场战斗的结果规则。 

对于每个$x$从 2 到$n$，我们被要求确定其中有多少玩家$[1,x]$如果所有人都参加的话，就有可能获胜。 重要的是，战斗可以按任何顺序安排，因此如果存在至少一个淘汰顺序，使玩家成为最后剩下的玩家，则玩家有机会获胜。 

约束条件允许$n$最多$2 \cdot 10^5$每个测试用例，所有测试用例的总和可达$3 \cdot 10^5$。 这排除了任何模拟所有战斗或所有消除排列的方法，因为可能的序列数量呈阶乘增长。 每个测试用例的解决方案必须以线性或线性时间运行。 

不明显的边缘情况包括“0000”或“1111”等极端玩家占主导地位的字符串，或“0101”等交替模式，其中中等玩家可能根据淘汰顺序成为获胜者。 仅检查第一个或最后一个环境的天真贪婪方法将错过这些可能性。 

## 方法

 暴力方法将模拟每个玩家子集的所有比赛排列，检查每个可能获胜的人。 这是正确的，但不可行，因为排列的数量是玩家数量的阶乘，导致天文数字的运算计数$n\sim10^5$。 

关键的洞察来自于观察，对于一个有机会获胜的玩家来说，他们必须在每一个序列的战斗中生存下来，在这些战斗中，严格更强或更弱的对手可以首先消灭他们。 这将问题简化为组合属性：当且仅当玩家是玩家列表开头或结尾的连续段的一部分（其中所有连续环境类型不会立即消除他们）时，玩家才能获胜。 具体来说，我们可以从左到右扫描以开始时结束的连续 0 的长度，并从右到左扫描以最后一个玩家结束的连续 1 的长度。 这决定了对于每个$x$温度最低或最高的玩家中有多少仍然可以成为胜利者。 

从暴力破解到线性扫描的转变是合理的，因为锦标赛在选择战斗顺序方面是灵活的，并且环境只影响相邻玩家的相对生存。 计算 0 的最大前缀和 1 的后缀可以捕获所有在最佳战斗下能够生存的玩家。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳线性扫描 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n$和环境字符串$s$。 
3.初始化一个数组`res`尺寸的$n+1$存储每个潜在获胜者的数量$x$。 
4. 从最小的玩家子集开始。 任何单个玩家都可以轻松获胜。 
5. 对于每个玩家$i$从左到右，数一下前面出现了多少个连续的 0。 这确定了能够在有利于较低温度的环境中生存的低温玩家。 
6. 对于每个玩家$i$从右到左，数出后面出现了多少个连续的 1。 这确定了能够在有利于较高温度的环境中生存的高温玩家。 
7. 对于每个$x$从 2 到$n$，将边界处玩家的左侧 0 前缀和右侧 1 后缀的计数加一相加。 这给出了可能获胜的玩家总数$[1,x]$。 
8. 输出结果。 

为什么有效：无论战斗顺序如何，这些连续部分之外的任何玩家都无法避免被淘汰。 最大前缀 0 确保最小的玩家可以通过首先消除较大的玩家来获胜。 最大后缀 1 确保最大的玩家可以通过先消除较小的玩家来获胜。 对这些细分进行计数可以捕获每个子集的所有潜在赢家。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        ans = [0]*(n+2)

        # Compute left-to-right 0-prefix counts
        left = [0]*(n+1)
        for i in range(n-1):
            if s[i] == '0':
                left[i+1] = left[i]+1
            else:
                left[i+1] = 0

        # Compute right-to-left 1-suffix counts
        right = [0]*(n+1)
        for i in range(n-2,-1,-1):
            if s[i] == '1':
                right[i+1] = right[i+2]+1
            else:
                right[i+1] = 0

        res = []
        for x in range(2,n+1):
            low = left[x-1]
            high = right[n-x+1]
            res.append(low + high + 1)
        print(' '.join(map(str,res)))

if __name__ == "__main__":
    solve()
```左边的数组计算有多少个前面的 0 允许最小的玩家生存。 右边的数组计算有多少个尾随 1 让最大的玩家生存下来。 总和加一计算边界玩家，得出可能获胜者的正确数量。

 ## 边缘情况

 对于像这样的输入`3\n11\n`，玩家 2 和 3 参与。 右侧后缀 1 会同时计算最后一个玩家和下一个玩家，正确地允许玩家 3 获胜，而玩家 2 则不能。 即使环境字符串的长度为 1，该算法也能正确计算左计数和右计数，从而避免差一错误。 在所有最小和最大$n$在这种情况下，扫描边界可以准确地处理索引，从而确认正确性。
