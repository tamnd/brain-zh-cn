 ## 解决方案
 ## 问题理解

 该问题为我们提供了一个糖果堆列表，以及在 BThero 失去魔法之前一堆糖果可以容纳的糖果数量的限制。 我们可以重复执行复制粘贴操作：选择两堆不同的糖果，并将第一堆中的所有糖果添加到第二堆中。 目标是最大化此类操作的数量，同时确保没有一堆糖果超过允许的最大数量。 输入指定多个测试用例，每个测试用例提供堆数、每堆允许的最大糖果以及初始堆大小。 每个测试用例的输出是一个整数，表示可以安全执行的复制粘贴操作的最大数量。 

限制很小：每个测试用例的堆数不超过 1000，每堆允许的最大糖果数最多为 10,000。 测试用例中所有桩的总和也以 1000 为界。这些约束意味着我们不需要担心具有对数或次线性复杂性的高度优化的数据结构或算法 - 检查每个桩或每个测试用例执行线性操作的解决方案足够快。 

需要注意的边缘情况包括所有堆都已达到最大值的情况、堆中只有一颗糖果的情况，或者从一堆复制到另一堆立即超出限制的配置。 例如，如果`n = 2`,`k = 2`，并且两堆都有 1 颗糖果，在达到极限之前我们只能执行一次操作。 总是尝试复制而不检查限制的幼稚方法可能会错误地尝试第二次操作。 

## 方法

 暴力方法将显式模拟每个复制粘贴操作。 对于每个操作，我们可以尝试每对有效的桩，检查将一堆添加到另一堆中是否使两个桩都保持在限制之下，并更新状态。 虽然这适用于小例子，但它是不必要的且乏味的。 每个测试用例最多可能涉及`n * n`每次操作的检查，操作数量可能与`k / min(a_i)`，即使对于适度的约束，也可能导致数百万次迭代。 

关键的观察结果是问题简化为简单的贪心求和。 复制粘贴操作的最大次数是通过将最小的一堆重复添加到另一堆而不超过限制来确定的。 如果我们对堆进行排序，我们总是可以使用最小的堆作为捐赠堆，并且我们可以将其重复添加到较大的堆中。 一旦最小的堆耗尽（将其添加到任何其他堆中都会超过最大值），我们就会停止。 从数学上讲，这相当于将限制与每堆糖果之间的差值相加，然后除以捐赠堆值，但由于捐赠堆可以在任何较大的堆上多次使用，因此我们可以简单地计算除最大堆之外的所有糖果的总和，然后从最大堆的限制中减去它。 

最佳方法之所以有效，是因为复制粘贴操作是相加的，并且当我们使用最小的堆“填满”最大的堆时，操作数量最大化。 我们不需要模拟单独的移动 - 计算可以安全移动到最大一堆的糖果总数就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 * 操作) | O(n) | 太慢了，没必要|
 | 最优（贪心和）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取桩数`n`以及允许的最大糖果数`k`。 
2. 读取桩列表`a`并按升序排序。 排序确保最小的堆在最前面，最大的堆在最后，使贪婪选择变得简单。 
3. 初始化计数器`ops`为零以跟踪安全复制粘贴操作的数量。 
4. 迭代除了最大的一堆之外的每一堆。 对于每堆`i`有价值`a[i]`，计算它可以添加到最大堆中多少次`a[-1]`不超过`k`。 该堆的操作次数为`min(a[i], k - a[-1])`。 将此号码添加到`ops`，然后更新`a[-1]`包括添加的糖果。 
5. 处理完所有较小的桩后，`ops`包含复制粘贴操作的总数。 
6. 打印`ops`对于测试用例。 

为什么有效：不变的是，在每一步中，我们都不会超过最大堆中允许的最大糖果数量，并且通过始终使用最小的堆作为捐赠者，我们可以最大限度地增加加法操作的数量。 排序顺序确保我们不会错过可能有助于额外操作的一堆。 由于所有操作都是可加和可交换的，因此移动的确切顺序并不重要，重要的是每堆的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    ops = 0
    for i in range(n - 1):
        if a[i] + a[-1] > k:
            ops += k - a[-1]
            a[-1] = k
        else:
            ops += a[i]
            a[-1] += a[i]
    print(ops)
```代码首先对堆进行排序，以便可以使用最小的堆来安全地增加最大的堆。 这`if`语句确保我们永远不会超出限制，调整最大堆并仅计算允许的操作。 这可以避免幼稚的加法会溢出的差一错误`k`。 排序至关重要，因为首先使用任何其他堆可能会减少安全操作的次数。

 ## 边缘情况

 对于所有桩都处于最大值的测试用例，例如`2 2\n2 2`，算法正确地识别出无法执行复制粘贴操作。 排序不会改变数组，并且`if`条件防止任何添加超出`k`。 对于最小桩场景，`2 100\n1 1`，该算法安全地允许从第一堆到第二堆的一个操作，确认贪婪逻辑尊重边界。
