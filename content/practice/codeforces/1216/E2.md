 ## 解决方案
 ## 问题理解

 该序列是通过连接“块”构建的。 第一个块只是字符串“1”。 第二个块是“12”。 第三个块是“123”，依此类推，因此第 i 个块是从 1 到 i 的数字的十进制表示形式，连续写入且不带分隔符。 

这意味着完整的无限序列是通过写入块 1，然后写入块 2，然后写入块 3，永远继续，然后将生成的长字符串视为 1 索引的数字数组来形成的。 每个查询都要求出现在这个无限串联中的位置 k 处的数字。 

困难来自于k的大小。 它可以大到 10^18，因此任何构造序列甚至显式模拟块的方法都是立即不可能的。 即使逐个迭代块也会太慢，因为总长度随 i 呈二次方增长，并且我们无法通过暴力扩展来达到这样的索引。 

一种常见的失败模式是尝试构建块直到前缀长度超过 k。 即使尝试优化字符串构建，潜在的问题仍然是 i 块之后的总长度约为以结构化方式贡献的 1 + 2 + … + i 数字的总和，对于大 k 来说，它仍然增长得太快。 

另一个微妙的边缘情况是索引。 该序列是 1 索引的，数字来自串联的十进制表示形式。 如果错误地对待数字而不是数字，例如认为位置 k 指的是某个块中的第 k 个数字而不是整体的第 k 个数字，则映射会立即中断。 

## 方法

 蛮力的想法很简单。 我们逐块模拟，附加字符串“1”、“12”、“123”等，将它们连接成一个不断增长的字符串，直到其长度超过最大查询 k。 然后每个查询都通过直接索引来回答。 这是正确的，因为它准确地构造了序列定义。 

然而，成本很快就会爆炸。 n 个块之后的总长度大致为 1..i 中总数字的总和，即数字增长术语中的 θ(n^2 log n)。 为了使 k 达到 10^18，n 需要很大，这使得模拟变得不可能。 

关键的观察是我们实际上并不需要完整的序列。 我们只需要知道位置 k 落在哪里：在哪个块内，在该块中的哪个数字内，以及在该数字的哪个数字内。 

我们不是构建块，而是计算块的前缀长度。 对于每个块 i，我们可以计算它贡献了多少位数字：从 1 到 i 的数字长度之和。 这可以使用数字长度分组在 O(log i) 中计算。 然后我们对 i 进行二分搜索以找到最小的块，使得直到 i 的块的总长度至少为 k。 

一旦找到该块，我们就减去之前的前缀长度并关注该块的内部。 现在我们需要在 1..i 内找到一个数字。 我们再次使用数字长度分组：具有 1 位数字、2 位数字等的数字形成连续的范围。 我们进行减法，直到找到包含 k 的确切数字。 最后，在该数字中，我们索引正确的数字。 

这减少了从构建巨大字符串到使用数字长度算术和二分搜索进行重复范围计数的问题。

 ## 算法演练

 ### 1. 预先计算前缀范围的数字长度贡献

 我们定义一个辅助函数，用于计算数字 1 到 x 形成的序列中有多少位数字。 这是通过按数字长度对数字进行分组来完成的：1-9 每个贡献 1 位数字，10-99 每个贡献 2 位数字，依此类推。 这避免了逐个迭代。

### 2. 二分查找找到正确的块

 我们搜索最小的块索引 i，使得块 1 到 i 中的数字总数至少为 k。 这是可行的，因为 i 中的前缀长度是单调的。 

### 3. 减去之前的块

 一旦找到该块，我们就将 k 减去所有先前块的总长度。 现在k指的是第i个块内的位置，即字符串“123…i”。 

### 4. 找到块内的确切数字

 我们再次在 1..i 内使用数字分组。 我们减去 1 位数字的贡献，然后减去 2 位数字的贡献，等等，直到我们确定包含位置 k 的确切整数。 

### 5. 提取数字

 识别数字后，我们将其转换为字符串，并使用剩余的偏移量索引正确的数字。 

### 为什么它有效

 该算法依赖于这样一个事实：两个级别的结构都是固定大小组的单调累积：块的总长度单调增长，并且在每个块内，数字长度形成连续的范围。 由于这两种结构都被划分为具有已知大小的不相交区间，因此二分搜索和贪心减法总是毫无歧义地隔离出正确的区间。 一个位置在任何时候都不能属于两个不同的段，因此分解是唯一的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digits_count_upto(x: int) -> int:
    """Total number of digits in concatenation of 1..x"""
    res = 0
    length = 1
    start = 1
    while start <= x:
        end = min(x, 10**length - 1)
        res += (end - start + 1) * length
        length += 1
        start *= 10
    return res

def find_block(k: int) -> int:
    lo, hi = 1, 10**6  # safe upper bound for this problem
    while lo < hi:
        mid = (lo + hi) // 2
        if digits_count_upto(mid) >= k:
            hi = mid
        else:
            lo = mid + 1
    return lo

def kth_digit_in_range(n: int, k: int) -> str:
    length = 1
    start = 1
    while True:
        end = min(n, 10**length - 1)
        count = (end - start + 1) * length
        if k > count:
            k -= count
            length += 1
            start *= 10
            continue
        offset = (k - 1) // length
        num = start + offset
        digit_index = (k - 1) % length
        return str(num)[digit_index]

def solve():
    q = int(input())
    for _ in range(q):
        k = int(input())

        block = find_block(k)
        prev = digits_count_upto(block - 1)
        k -= prev

        print(kth_digit_in_range(block, k))

if __name__ == "__main__":
    solve()
```该代码首先使用数字长度分组定义一个超过 1..x 的数字计数器。 这是块搜索和块内搜索的支柱。 二分查找在`find_block`确保我们永远不会显式地模拟序列，并且上限是安全的，因为数字增长非常快。 

识别出正确的块后，我们在该块内重用相同的数字分组逻辑来找到确切的数字。 算术`(k - 1) // length`和`(k - 1) % length`是将统一长度段内的位置映射到数字和数字索引的标准方法。 

一个常见的实现陷阱是减去前缀长度时的逐一处理。 这里的所有内容都保持 1 索引，直到最后的映射步骤，这避免了负索引和歧义。

在这个块中，我们再次对数字进行分组：

 1-9 贡献个位数。 位置 20 落在较早区块的多位数累积内，引导我们找到正确的数字，即 5。

```我们找到包含位置 56 的块。经过二分查找后，我们找到正确的块边界并减去先前的前缀长度。

 ## 边缘情况

 一个关键的边缘情况是 k 恰好落在两个块之间的边界处。 在这种情况下，前缀减法必须仅在移动到前一个块后使 k 等于 0，并且二分查找必须确保它返回前缀 ≥ k 的第一个块。 该算法处理这个问题是因为`digits_count_upto(mid)`是非递减的，二分查找使用严格的下界形式。 

另一种边缘情况是跨越块内的数字长度边界，例如从一位数移动到两位数。 分组逻辑确保我们在继续之前减去整个范围，因此 k 始终指代明确定义的段。 偏移计算`(k - 1) // length`当 k 恰好能被段长度整除时，可以防止错位。 

最终的边缘情况 k 非常大，接近 10^18。 二分搜索范围故意很大，但数字增长确保我们永远不需要深入搜索。 即使在极端值下，该算法也会以少量步骤收敛，因为数字积累的增长速度比块索引中的线性增长更快。
