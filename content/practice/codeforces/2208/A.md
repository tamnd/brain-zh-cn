 ## 解决方案
 ## 问题理解

 我们有一个大小为的正方形网格$n \times n$代表一个棋盘，其中每个单元格都包含某种颜色的糖果。 糖果的颜色用整数表示，不同的整数代表不同的颜色。 鲍勃想知道是否可以重新排列棋盘上的糖果，以便没有行或列完全被相同颜色的糖果填满。 

换句话说，重新排列后，每行和每列必须包含至少两种不同的颜色。 输入提供多个测试用例，每个测试用例都有自己的板。 如果董事会可以进行此类重新安排，我们需要回答“是”，否则回答“否”。 

约束条件告诉我们$n$最多可以达到 100，所有的总和$n$跨测试用例不超过 500。这意味着迭代所有单元格的任何解决方案都是可接受的，因为$n^2$每个测试用例最多 10,000 个，所有测试用例的单元总数最多 50,000 个。 

一个关键的边缘情况是当一种颜色出现超过$n$次。 由于只有$n$如果单一颜色出现超过$n$有时，我们无法阻止该颜色形成完全相同颜色的行或列。 例如，如果$n = 3$董事会是：```
1 1 1
2 3 2
3 2 3
```然后上色`1`出现3次，等于`n`。 我们可以重新排列它们，但如果任何颜色出现超过三次，就不可能避免单色的行或列。 仅检查行或列而不计算频率的粗心实现将在这里失败。 

## 方法

 暴力方法会尝试尝试棋盘上糖果的每种排列，检查最终的棋盘是否满足条件。 对于一个$n \times n$董事会，这将涉及$(n^2)!$排列。 这显然即使对于$n = 5$。 原则上，蛮力是有效的，因为重新排列涵盖了所有可能性，但由于排列的数量是天文数字，它会失败。 

关键的见解来自于我们不关心颜色的确切位置，只关心它们的数量。 如果任何颜色出现的次数超过$n$次，因为我们不能放置超过$n$相同的糖果，无需创建单色行或列。 反之，如果每种颜色最多出现$n$有时，我们总是可以以类似对角线的方式重新排列它们，以避免整行或整列都是单一颜色。 这一观察将问题从排列简化为计算每种颜色的出现次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((n^2)!) | O((n^2)!) | O(n^2) | O(n^2) | 太慢了 |
 | 最佳（频率检查）| 每个测试用例 O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n$然后是$n \times n$木板。 
3. 为所有糖果颜色创建频率计数器（字典）。 对于每个细胞$a_{i,j}$，增加计数$a_{i,j}$。 
4. 计数完毕后，检查任意颜色出现的最大频率。 如果这个频率大于$n$，为此测试用例打印“NO”。 否则，打印“YES”。 

这样做的原因是任何颜色的最大频率都是限制因素。 无论我们如何洗牌，如果一种颜色出现的次数超过$n$有时，至少一行或一列的所有位置都必须包含该颜色。 如果所有频率最多$n$，有效的重新排列始终存在，例如，通过沿对角线放置每种颜色并仔细填充剩余位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        colors = []
        for _ in range(n):
            row = list(map(int, input().split()))
            colors.extend(row)
        count = Counter(colors)
        if max(count.values()) > n:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```该解决方案将所有行读取到一个平面列表中`colors`为了简单起见。`Counter`有效地计算每种糖果颜色的出现次数。 支票`max(count.values()) > n`直接实现上面导出的条件。 使用`sys.stdin.readline`确保多个测试用例的快速输入。 必须注意正确压平行； 简单的求和运算可能会错误地连接数字。

 ## 边缘情况

 对于`n = 1`，板上只有一个单元格。 由于任何行或列都不能包含超过一颗糖果，因此无论颜色如何，答案始终是“是”。 该算法处理这个问题是因为`max(count.values()) = 1 <= n = 1`。 

为了`n = 100`单一颜色出现 101 次后，算法正确地打印出“NO”，因为`max(count.values()) = 101 > 100`。 它不会尝试任何重新排列，从而有效地处理大输入大小。 

对于多种颜色准确显示的板`n`每次，算法都会打印“YES”，因为它识别出没有颜色超过限制。 这捕获了仔细排列可以产生有效板但受到频率限制保证的情况。
