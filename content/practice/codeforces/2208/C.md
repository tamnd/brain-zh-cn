 ## 解决方案
 ## 问题理解

 我们收到一系列任务，每个任务都有一个分值和难度百分比。 你一开始的耐力为 1。对于每项任务，你可以跳过它或完成它。 完成任务会使你当前的体力倍增`(1 - p_i / 100)`为下一个任务，同时给你`stamina * c_i`立即积分。 跳过任务会使你的耐力保持不变，并且不会获得任何分数。 目标是最大化任务序列结束时积累的总分。 

输入由多个测试用例组成。 每个测试用例包含许多任务`n`其次是`n`对`(c_i, p_i)`。 总和`n`所有测试用例最多为 100,000 个。 自从`n`可以大到 10^5 并且时间限制为 2 秒，我们不能考虑复杂度低于的解决方案`O(n)`每个测试用例。 尝试所有任务子集的方法（例如朴素的暴力递归或具有 2^n 状态的动态编程）将立即被排除。 

当困难发生时，就会出现微妙的边缘情况`p_i`一项任务为 100。 完成它后，所有后续任务的体力都会为零。 如果我们没有在正确的时间跳过这些任务，我们可能会无意中将未来的收益归零。 同样，任务`p_i = 0`总是可以安全完成，因为它们不会降低耐力。 任务量非常高`c_i`但也高`p_i`需要仔细权衡：接受它们可能会立即获得分数，但会降低未来的潜力。 例如，如果输入是：```
2
100 100
1 0
```完成第一个任务会获得 100 点，但耐力会降至零，因此第二个任务没有任何贡献。 跳过第一个任务会给第二个任务带来 1 分，这显然更糟糕。 正确答案是接第一个任务，100分。 

## 方法

 暴力解决方案将尝试每个任务子集来找到使总分最大化的序列。 这将涉及每个测试用例最多 2^n 种可能性，这对于`n = 10^5`。 即使动态编程解决方案以离散步骤跟踪每个任务的耐力也太慢，因为耐力是连续的，使得记忆不切实际。 

关键的见解是，在任何任务中，如果我们知道当前的耐力，最佳决策就是将完成任务的直接收益与由于耐力减少而导致的未来潜在损失进行比较。 由于耐力减少会乘以当前值`(1 - p_i / 100)`，并且由于所有任务都必须按顺序考虑，因此我们可以采用贪心方法。 我们保持跑步耐力并添加`stamina * c_i`如果完成任务是有益的，那么将耐力乘以`(1 - p_i / 100)`来解释减少的情况。 决定很简单：如果`p_i = 100`以及未来的任务有积极的意义`c_i`，我们应该跳过该任务； 否则，总是用`p_i < 100`因为他们做出了积极贡献，而没有造成灾难性损失。 

更精确的表述是始终接受任务，除非`stamina`极低或`p_i = 100`。 由于问题允许我们放弃任务，因此我们可以递归地思考：任务的最优点`i`向前是跳过任务的值`i`或完成任务`i`加上使用减少的耐力完成剩余任务的最佳点。 因为该运算是乘法且线性的`c_i`，我们可以使用跑步耐力变量在一次前向传递中计算这一点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 贪心前向传递 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化`stamina = 1`和`points = 0`。 耐力代表我们完成的任何任务的当前乘数。 
2. 按顺序迭代任务。 对于任务`i`有价值`c_i`和难度`p_i`:

 1. 计算完成此任务后获得的分数：`stamina * c_i`并将其添加到总分中。 
2. 将下一个任务的耐力更新为`stamina *= (1 - p_i / 100)`。 
3、所有任务处理完毕后，累计`points`变量保存最大可达到的分数。 
4. 输出`points`具有足够的精度（至少 10 位小数）。 

为什么有效：该算法利用点与耐力的线性关系。 由于每项任务都会成倍地降低耐力，因此跳过任务没有任何好处`p_i < 100`因为这样做只会推迟收益，而不会增加未来的乘数。 任务与`p_i = 100`将耐力归零； 如果它们后面跟着非零的任务`c_i`，跳过是最佳的，但这很自然地得到处理，因为乘以零会将更多点减少到零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        tasks = [tuple(map(int, input().split())) for _ in range(n)]
        stamina = 1.0
        points = 0.0
        for c, p in tasks:
            points += stamina * c
            stamina *= (1 - p / 100)
        print(f"{points:.10f}")

solve()
```该代码使用有效地读取多个测试用例`sys.stdin.readline`。 每个任务的分数是通过将当前耐力乘以它的值来计算的。 完成任务后，体力会更新。 浮点运算足以满足所需的精度，并且 print 语句确保至少 10 位小数以确保正确性。 通过直接迭代给定的任务来避免差一错误，并且操作顺序确保在添加点后更新耐力。
