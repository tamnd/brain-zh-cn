 ## 解决方案
 ## 问题理解

 该问题要求我们用较小的方形图块构建一个大的角色图片。 我们得到了一组基本图块，其中每个图块都是一个 S × S 的字符网格。 最终的被子被排列为瓦片位置的 W × H 矩形。 每个位置都会告诉我们在将其放入最终图像之前要使用哪个基本图块以及要应用哪个变换。 

变换仅限于六种情况：保持图块不变、顺时针旋转 90、180 或 270 度、从左到右翻转或从上到下翻转。 输出是将每个图块位置扩展为其变换后的 S by S 块后获得的字符网格。 

这些约束旨在使模拟成为可能。 原始图块的数量和每个图块的边长最多为 15，因此存储和转换所有图块的成本较低。 面组最多可包含 100 x 100 个图块位置，每个图块最多包含 15 x 15 个字符。 最终输出可以包含 2,250,000 个字符，因此任何避免不必要工作的方法都是首选。 为每个输出单元重复搜索、复制或转换大型结构的方法可能会比所需的速度慢，而直接处理每个最终字符则足够高效。 

主要的实施错误来自于错误地处理转换。 旋转特别容易反转，因为源行和列都会发生变化。 另一个常见的错误是混淆水平翻转和垂直翻转。 例如，一块瓷砖```
ab
cd
```变换 4 变为```
ba
dc
```因为列颠倒了。 将此视为交换行的程序将错误地输出```
cd
ab
```对于单个图块，输入```
1 2
ab
cd
1 1
0:1
```应该产生```
ca
db
```因为瓷砖是顺时针旋转的。 使用逆时针旋转公式的实现将输出错误的排列。 

另一种边缘情况是只有一个平铺位置的被子。 输入```
1 1
x
1 1
0:0
```必须输出```
x
```假设多个图块并插入分隔符或错误处理行长度的解决方案在这里可能会失败。 

第三种边缘情况是同一图块的不同变换彼此相邻出现。 应用转换后，程序无法改变存储的原始图块，因为稍后使用同一图块需要未更改的版本。 例如，通过转换 1 和 2 使用一个图块两次需要两个操作都从原始网格开始。 

## 方法

 直接暴力方法是处理每个被子位置，定位其源图块，应用请求的转换，并打印生成的 S by S 块。 这已经是正确的，因为每个输出字符恰好属于一个图块位置，并且每个图块位置都可以独立处理。 

仅当在字符级别重新计算转换时，幼稚实现的问题才会出现。 对于每一个 W 乘 H 的图块位置，我们都可以触摸 S 平方的字符。 最坏的情况执行大约 W * H * S * S 操作。 当W和H等于100，S等于15时，这是2,250,000个字符操作，这个数字很小。 真正的危险不是渐近复杂性，而是重复创建不必要的中间网格。 

关键的观察结果是，转换集很小，并且原始图块被重复使用了很多次。 由于只有六种可能的变换，因此每个原始图块可以一次扩展到所有六个变换版本。 经过预处理后，每个被子位置都变成一个简单的查找，然后将 S 行复制到答案中。 

暴力破解之所以有效，是因为输出字符的总数是有限的。 每个图块转换都可以被缓存的观察结果使我们能够消除重复的工作并保持实现简单。 最终的建造只是组装已经准备好的块。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(宽 * 高 * 小 * 小) | O(S * S) | 已接受，但重复转变 |
 | 最佳 | O(N * 6 * S * S + W * H * S * S) | O(N * 6 * S * S) | 已接受 |

 ## 算法演练

 1.读取所有原始图块，不加修改地保存。 原始方向必须保持可用，因为多个面组位置可以引用具有不同变换的同一图块。 
2. 对于每个图块，生成六个可能的转换版本。 将它们存储在按图块编号和转换类型索引的表中。 这会将未来的转换请求转换为恒定时间的查找。 
3. 逐行阅读被子说明。 每个条目包含一个图块索引和一个变换编号，因此它直接标识预先计算的块之一。 
4. 对于每个被子行，水平附加相应的变换后的图块行。 被子位置为其占据的 S 个输出行中的每一行贡献 S 个字符。 
5. 按顺序打印构建的行。 这些行已经完成，因为每个图块位置都准确地贡献了自己的矩形部分。 

为什么它有效：

 不变量是每个存储的变换后的图块正是将其变换应用于原始图块的结果。 由于每个被子位置只需要一个图块和一个变换，因此检索缓存的版本会给出属于该位置的确切块。 构建过程保留了图块位置从左到右和从上到下的顺序，因此每个输出单元仅接收一次正确的字符。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def rotate90(tile):
    n = len(tile)
    return [''.join(tile[n - 1 - r][c] for r in range(n)) for c in range(n)]

def flip_vertical(tile):
    return [row[::-1] for row in tile]

def flip_horizontal(tile):
    return tile[::-1]

def solve():
    n, s = map(int, input().split())

    tiles = []
    for _ in range(n):
        tile = [input().rstrip('\n') for _ in range(s)]
        tiles.append(tile)

    transformed = []
    for tile in tiles:
        versions = [None] * 6
        versions[0] = tile
        versions[1] = rotate90(versions[0])
        versions[2] = rotate90(versions[1])
        versions[3] = rotate90(versions[2])
        versions[4] = flip_vertical(versions[0])
        versions[5] = flip_horizontal(versions[0])
        transformed.append(versions)

    w, h = map(int, input().split())

    answer = ['' for _ in range(h * s)]

    for quilt_row in range(h):
        specs = input().split()

        for tile_row in range(s):
            line = []
            for spec in specs:
                idx, t = map(int, spec.split(':'))
                line.append(transformed[idx][t][tile_row])
            answer[quilt_row * s + tile_row] = ''.join(line)

    sys.stdout.write('\n'.join(answer))

if __name__ == "__main__":
    solve()
```预处理部分为每个图块创建所有六个方向。 旋转是连锁的，因此应用 90 度操作三次自然会产生剩余的旋转。 这两次翻转直接使用原始图块，因为翻转不依赖于先前的旋转。 

施工阶段避免更改任何存储的瓷砖。 每个规范都分为其图块索引和转换值，然后附加已转换图块的所需行。 行索引计算`quilt_row * s + tile_row`将被子内的平铺行映射到最终字符网格中的正确行。 

索引中不存在危险的边界情况，因为每次转换都会使图块大小等于 S。Python 整数在这里不是问题，因为程序仅存储索引和字符计数。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N * 6 * S * S + W * H * S * S) | 每个转换准备一次，然后每个被子单元复制一个字符 |
 | 空间| O(N * 6 * S * S) | 每个图块的六个版本都被存储 |

 最大可能的产出决定了建筑成本。 由于最终图像本身仅包含几百万个字符，因此该算法保持在限制范围内，同时避免了重复的转换工作。

 ## 边缘情况

 对于单个图块位置，该算法仍然创建相同的变换后的缓存并执行一次正常查找。 输入```
1 1
x
1 1
0:0
```选择唯一的缓存版本并打印一个字符。 没有特殊情况，因为一般结构已经可以处理尽可能小的被子。 

对于同一图块的转换，原始图块永远不会被覆盖。 如果是瓷砖```
ab
cd
```请求转换 1 和 2，缓存包含两者```
ca
db
```和```
dc
ba
```同时。 这可以防止后面的请求依赖于早期的输出操作。 

对于相邻的不同变换的图块，该算法单独写入每个图块行并按被子顺序连接各个部分。 左边的图块不能影响右边的图块，因为每个位置都为当前输出行贡献了 S 个字符。
