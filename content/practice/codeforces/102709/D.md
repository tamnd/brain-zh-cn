 ## 问题理解

 该问题描述了 Zoom 通话中的一队人。 当每个人都看向选定的方向后，每个人都由以下任一者代表`L`或者`R`，具体取决于他们的脸部在屏幕截图中指向的方向。 人群是最大连续的一群人，他们都面朝同一个方向。 任务是计算最后一行中出现了多少个这样的组。 

输入给出了人数以及按照从左到右的顺序指示的方向。 输出是字符恒定的连续段的数量。 

人数可达到$10^5$，这意味着解必须接近线性。 检查每对位置或重复扫描线的大部分的方法将执行以下操作：$10^{10}$在最坏的情况下进行操作，这远远超出了典型的竞争性编程时间限制所允许的。 越过这条线就足够了，因为每个人的方向只需要与他们的近邻进行比较。 

主要的边缘情况来自正确处理变更以及没有错误地计算个人。 例如：```
Input
1
L

Output
1
```一个人总是恰好形成一团。 仅在发现邻居之间的变化后才开始计数的解决方案可能会意外返回零。 

另一种情况是：```
Input
5
L
L
L
L
L

Output
1
```整条线是一团。 一个粗心的实现，对每次出现的情况进行计数`L`将返回 5 而不是 1。 

最后一个案例是：```
Input
4
L
R
L
R

Output
4
```每个相邻的簇都是不同的，因此每个人都会开始一个新的簇。 仅计算一种类型的方向或忘记最后位置的实现会丢失一些组。 

## 方法

 直接强力方法将尝试通过从每个位置开始并向右扩展而方向保持不变来识别每个团块。 这是正确的，因为每个最大段都可以通过从其第一个元素开始增长来找到。 然而，在最坏的情况下，例如一行仅包含`L`角色，首次扩展访问$N$元素，第二次访问$N-1$， 等等。 总工作量变为：$$N + (N-1) + \dots + 1 = O(N^2)$$为了$N = 100000$，这大约是五十亿个比较。 

关键的观察结果是，只有当方向从前一个人改变时，才会开始聚集。 我们不需要知道团块的整个长度。 我们只需要知道当前人是继续上一组还是开始新一组。 这将问题简化为简单的扫描，其中每个相邻对都被检查一次。 

蛮力之所以有效，是因为它明确地发现了每个片段，但它多次重复相同的信息。 团块之间的边界恰好是相邻方向不同的位置，这一观察结果让我们可以直接计算这些边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读说明的顺序。 第一个人总是开始第一个簇，因此将答案初始化为一个。 
2. 从第二个位置开始扫描人员。 将当前方向与先前方向进行比较。 
3. 如果两个方向不同，则增加丛计数，因为新的连续组已开始。 
4. 处理完整行后，输出计数。 

这样做的原因是，出现新簇的唯一可能方式是两个相邻的人面向不同的方向。 前一个簇的确切大小并不重要。 

为什么它有效：

 在扫描过程中，答案始终等于已处理的线部分形成的团块数量。 最初，第一个人创建一丛。 每次方向改变时，当前的人就不能属于前一个丛，因此必须开始一个新的丛。 扫描完成后，每个可能的边界都已被检查，因此计数恰好是整行中的团块数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    directions = [input().strip() for _ in range(n)]

    ans = 1
    for i in range(1, n):
        if directions[i] != directions[i - 1]:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```输入存储为列表，因为比较需要访问前一个方向。 由于只有$10^5$字符，这样内存占用就小了。 该算法从一个团块开始，因为非空行总是至少有一组。 

循环从索引一开始，因为第一个方向没有前一个方向可供比较。 每当当前角色与前一个角色不同时，当前角色就会成为新群体的第一个成员。 

这里没有棘手的边界计算或整数大小问题。 重要的实现细节是避免空输入假设，因为约束保证至少有一个人。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | 每个人都要接受一次检查。 |
 | 空间| O(N) | 方向列表存储输入序列。 |

 时间复杂度符合$10^5$限制，因为它每人只执行恒定量的工作。 内存使用也在限制之内。 通过在线处理输入，该算法可以将额外空间减少到 O(1)，但存储序列可以使实现变得简单。
