 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例中都有$N$二维网格上的点，每个点代表从整数坐标开始的海狸。 所有海狸同时在无限平面上移动。 

运动在时间上是连续的，但受到限制：在一秒钟内，海狸可以改变它的运动方向。$x$最多协调 1 及其$y$坐标最多 1。这意味着有效距离度量是切比雪夫距离，因此到达目标点$(x', y')$从$(x, y)$正好需要$\max(|x-x'|, |y-y'|)$如果我们以最佳方式移动，则需要几秒钟。 

我们可以为所有海狸选择最终位置。 移动后，它们的最终位置必须位于一条“蛇”上，这只是一组点，可以按两个坐标永不减少的顺序列出。 换句话说，如果我们按该顺序对最终位置进行排序，$x$坐标是非递减的，并且$y$坐标也不减。 允许多只海狸在同一点结束。 

任务是尽量减少时间$T$这样最终的位置就存在，并且输出$2T$。 因子 2 只是一个缩放比例； 答案保证是一个整数。 

约束条件意味着最多$2 \cdot 10^5$总体点。 任何尝试显式搜索赋值或排列的解决方案都会太慢，因为即使$N!$或者$2^N$式推理是不可能的。 甚至$O(N^2)$每个测试用例在最坏情况总数中已经处于临界点或太慢。 

一个关键的困难是我们不仅仅是独立地移动点。 最终配置必须满足全局排序约束，它将所​​有点耦合在一起。 

一些边缘情况很容易处理不当。 

例如，如果所有点已经在单调链中对齐$(1,1), (2,2), (3,3)$，答案应该为零，因为不需要移动。 强制严格不平等或试图“分散”点的幼稚方法可能会错误地增加不必要的时间。 

如果所有点共享相同的$x$-协调但有增加$y$，答案又是零。 一些不正确的策略尝试独立地按两个坐标进行排序并假设具有唯一性，这会在此处中断。 

例如，当点交错时会出现另一种微妙的情况$(1,3), (2,1), (3,2)$。 任何有效的排序都必须重新排列它们，其可行性取决于可能目的地的间隔是否以一致的单调方式重叠。 只考虑本地交换的贪婪方法在这里失败了。 

## 方法

 强力解释是考虑明确选择最终配置。 对于固定时间$T$，每只海狸都可以到达一个区域内的任意点$L_\infty$正方形以起始点为中心，半径为半径$T$。 因此，每只海狸都有一个可行目的地的方格，我们必须从每个方格中选取一个点，以便所选点在两个坐标中形成一条非递减链。 

一个天真的解决方案会尝试海狸的所有排列，并对于每个排列检查我们是否可以分配递增的$x$和$y$允许的方块内的值。 这立即失败，因为有$N!$排列甚至检查一个都需要线性分配推理，从而导致阶乘或指数复杂性。 

关键的观察结果是最终的蛇条件强加了全序。 一旦我们决定了这个顺序，可行性就变成了一维约束传播问题。 缺少的部分是如何最佳地选择该顺序。 

如果我们按照原来的样子对海狸进行排序$x$-坐标，任何有效的最终配置都可以重新排列以遵守该顺序，而无需增加所需时间。 直观地说，如果海狸体型较小$x$在一个更大的之后结束$x$，在最终序列中交换它们不会违反可行性，因为两者都在对称内移动$L_\infty$区域，单调约束仅取决于排序，而不取决于同一性。 这减少了检查我们是否可以分配递增的问题$y$- 保持在间隔内的坐标。 

一旦排序$x$, 每只海狸$i$最终有一个可行的区间$y$-协调：$[y_i - T, y_i + T]$。 我们现在需要选择一个非减序列$y'_i$，其中每个$y'_i$位于其区间内。 这是区间约束单调序列的经典贪婪可行性检查。 

我们从左向右扫动，保持尽可能小的电流$y'$。 对于每个间隔，我们设置$y'_i$至少为先前的值，但不超过上限。 如果在任何时候这变得不可能，所选择的$T$是不可行的。 

我们二分查找最小的$T$有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 |$O(N! \cdot N)$|$O(N)$| 太慢了|
 | 排序+贪心+二分查找 |$O(N \log R)$|$O(N)$| 已接受 |

 ## 算法演练

 1. 对所有点进行递增排序$x$-协调。 这修复了构建单调链时唯一重要的顺序，而不失一般性。 
2.二分查找最小值$T$在范围内$[0, 10^9]$。 我们测试的函数是单调的：如果一个时间$T$有效，任何更大的时间也有效，因为所有间隔只会扩大。 
3.对于固定的$T$，为每个点计算一个有效区间$[y_i - T, y_i + T]$。 
4. 按排序顺序遍历点并维护一个变量`cur_y`，代表最小的可能$y$- 构建的链的值，直到前一个元素。 
5. 对于每个间隔，设置`cur_y = max(cur_y, y_i - T)`。 如果这超过$y_i + T$，间隔不能容纳非递减序列，所以这$T$失败。 
6. 如果所有间隔都处理成功，则当前$T$是可行的。 
7. 输出$2T$，所需的缩放答案。 

第5步中的贪婪选择至关重要。 它总是将当前值推得尽可能低，同时保持有效，为未来的时间间隔留下最大的灵活性。 

### 为什么它有效

 排序后$x$，任何有效的解决方案都对应于选择一个$y'_i$从每个间隔使得序列是非递减的。 贪心过程保持不变性`cur_y`是前缀可实现的最小值。 如果在某个步骤我们可以选择一个小于`cur_y`，它只会提高后续步骤的可行性，而不会使其恶化。 因此，在某个时间间隔失败意味着不存在有效的分配$T$，因为即使是最宽松的前缀构造也已经违反了间隔约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(T, pts):
    cur = -10**18
    for x, y in pts:
        lo = y - T
        hi = y + T
        if cur < lo:
            cur = lo
        if cur > hi:
            return False
    return True

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        pts = [tuple(map(int, input().split())) for _ in range(n)]
        pts.sort()  # sort by x then y

        lo, hi = 0, 10**9
        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid, pts):
                hi = mid
            else:
                lo = mid + 1

        out.append(str(lo * 2))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```排序步骤确定了唯一有意义的自由度：水平排序。 这`can`函数实现了前面描述的贪婪区间传播，并且它是每个候选时间所需的唯一可行性检查。 

二分搜索是必要的，因为可行性边界取决于区间如何扩展$T$，并且不存在无需测试即可直接给出最小值的封闭式表达式。 

一个微妙的实现细节是初始化`cur`到一个非常负的数字。 这可以避免错误地约束第一个元素。 另一个细节是所有比较都必须使用整数算术，因为坐标和$T$是整数。 

## 工作示例

 考虑一个小案例：$$(1, 8), (2, 6), (5, 3), (8, 5)$$排序后$x$，顺序已经一致了。 

### 追踪$T = 2$| 点| 间隔$[lo, hi]$| 之前 | 当前 后|
 | ---| ---| ---| ---|
 | (1,8) | [6,10]| -inf| 6 |
 | (2,6) | [4,8]| 6 | 6 |
 | (5,3) | [1,5]| 6 | 失败|

 在第三点，要求的不减值已经是6，但是区间只允许最多5，所以$T=2$是不可行的。 

这表明，即使早期的点是灵活的，后面的一个紧密间隔也可能会导致失败。 

### 追踪$T = 3$| 点| 间隔$[lo, hi]$| 之前 | 当前 后|
 | ---| ---| ---| ---|
 | (1,8) | [5,11]| -inf| 5 |
 | (2,6) | [3,9]| 5 | 5 |
 | (5,3) | [0,6]| 5 | 5 |
 | (8,5) | [2,8]| 5 | 5 |

 所有点都成功，所以$T=3$作品。 

这表明贪婪选择早期稳定并保持一致，证实可行性仅取决于间隔是否可以维持单调链，而不取决于精确定位。

 ## 边缘情况

 当许多点几乎相同时，就会出现极端情况$y$- 坐标但不同$x$。 在这种情况下，贪心算法会反复钳制`cur`没有改变。 输入$$(1, 5), (2, 5), (3, 5)$$和$T = 0$立即通过，因为所有间隔都崩溃为单个点并保持非递减状态。 

另一种情况涉及严格的交替约束，例如$$(1, 10), (2, 0), (3, 10)$$对于小$T$，中点迫使链向下然后向上返回，这违反了单调性。 当中间间隔无法容纳传播的时，该算法会准确地检测到这一点`cur`。 

最后一个微妙的情况是可行性完全取决于二分搜索精度而不是结构。 因为所有界限都是整数，并且答案在加倍后保证是整数，所以使用整数二分搜索可以避免浮点错误，否则会错误分类边界配置。
