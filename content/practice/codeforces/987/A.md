 ## 解决方案

 ## 问题理解

 我们得到了一小组彩色宝石，放置在一个固定的结构中：一个无限手套，总是有六个可能的插槽。 每个插槽对应一颗独特的无限宝石，并且每颗宝石都通过其颜色进行唯一识别。 

输入告诉我们灭霸当前拥有多少宝石，然后列出这些宝石的颜色。 根据这些部分信息，我们必须通过与六种可能颜色的完整固定集进行比较来确定缺少哪些宝石。 输出是丢失宝石的数量及其名称。 

重要的结构细节是，可能性的宇宙是恒定且微小的。 总是有六种颜色，并且所有输入颜色都是不同的。 这立即消除了复杂搜索或优化的需要。 该任务简化为两个固定集合之间的集合减法。 

n 的限制最多为 6，这意味着即使是最简单的重复检查成员资格的方法也非常快。 任何循环遍历常量列表或使用集合的解决方案都将在常量时间内运行。 

唯一的边缘情况来自 n 的边界值。 当n为0时，我们必须输出所有六颗宝石。 当n为6时，我们不输出任何内容。 粗心实现中的一个微妙的失败案例是忘记维护颜色名称和宝石名称之间的正确映射，或者大小写不匹配，因为输出格式需要大写的宝石名称，而输入颜色是小写字符串。 

## 方法

 暴力方法会将其视为一般的成员资格问题。 我们可以将输入颜色存储在一个列表中，并且对于六种可能的颜色中的每一种，扫描该列表以检查它是否存在。 每次成员资格检查的成本为 O(n)，并且我们执行恒定的六次检查，导致 O(6n)，这在此问题中仍然是恒定的。 

然而，即使这样也是不必要的开销。 问题的结构表明颜色和宝石名称之间存在直接映射。 由于宇宙是固定的，我们可以简单地将所有六对存储在字典或列表中，然后删除输入中出现的那些。 

关键的观察结果是我们没有解决动态查询问题。 我们没有被要求处理更新或变化较大的多个测试用例。 我们只是过滤一个固定的目录。 这使得直接设置差异成为最简洁的方法。

 ## 算法演练

 我们通过维护颜色和宝石名称之间的固定映射，然后删除输入中出现的映射来解决该问题。 

1. 建立所有六种宝石的参考表，将每种颜色与其相应的宝石名称配对。 这代表了任何观察之前的完整集合。 
2. 读取所有输入颜色并将它们存储在一个集合中。 使用集合并不是绝对必要的，但它可以确保快速的成员资格检查，并避免在违反输入假设时出现意外重复。 
3. 迭代六种可能颜色的完整列表。 
4. 对于每种颜色，检查它是否出现在输入集中。 
5. 如果没有出现，则将相应的 gem 名称追加到答案列表中。 
6. 处理完所有六个宝石后，输出丢失宝石的数量及其名称。 

我们迭代完整的固定列表而不是迭代输入的原因是我们被要求找到丢失的元素，而不是现有的元素。 这种迭代方向保证我们永远不会忘记考虑缺失的宝石。 

### 为什么它有效

该算法依赖于以下不变量：每颗有效宝石都与一种颜色唯一关联，并且可能颜色的范围是固定且完整的。 在每一步中，我们都会将每种可能的宝石准确地分类为两种状态之一：观察到的或未观察到的。 由于输入不包含重复项且仅包含有效颜色，因此不会出现歧义。 因此，每颗缺失的宝石必须恰好是其颜色未出现在输入集中的宝石，从而保证减法逻辑的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    color_to_name = {
        "purple": "Power",
        "green": "Time",
        "blue": "Space",
        "orange": "Soul",
        "red": "Reality",
        "yellow": "Mind"
    }
    
    present = set()
    for _ in range(n):
        present.add(input().strip())
    
    missing = []
    for color, name in color_to_name.items():
        if color not in present:
            missing.append(name)
    
    print(len(missing))
    for x in missing:
        print(x)

if __name__ == "__main__":
    solve()
```解决方案以字典为中心`color_to_name`，它对输入颜色和输出宝石名称之间的固定双射进行编码。 这避免了循环内的任何条件逻辑或手动映射。 

我们将输入颜色存储在一个集合中，以确保持续时间的成员资格检查。 尽管 n 最多为 6，但这使得逻辑清晰且健壮。 

字典上的迭代确保我们总是检查所有可能的 gem 一次，无论输入大小如何。

 ## 边缘情况

 对于空输入情况`n = 0`，算法将输入集初始化为空。 固定六色列表的每次迭代都无法通过成员资格检查，因此所有六个宝石名称都会被附加。 输出正确地成为全套宝石。 

对于完整的输入情况`n = 6`，该集合包含所有颜色。 每次查找都会成功，因此不会将任何 gem 添加到缺失列表中。 该算法输出零和一个空列表，与所需的格式匹配。 

在这两种情况下，正确性都来自于迭代空间是固定的并且与输入大小无关的事实，因此边界值仅影响成员资格检查，而不影响控制流结构。
