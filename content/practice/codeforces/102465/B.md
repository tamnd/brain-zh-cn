 ## 解决方案
 ## 问题理解

 图片的每一行都包含一个连续的好像素区间。 对于第 (i) 行，好像素占据从 (a_i) 到 (b_i) 的列（含）。 我们需要最大的轴对齐正方形，其每个像素都是好的。 

假设一个正方形使用行 (l) 到 (r)。 这些行中的每一行都必须包含与正方形占据的相同水平间隔。 由于行 (i) 恰好是区间 ([a_i,b_i])，因此所有行可用的公共列是

 [
 [\max_{l\le i\le r} a_i,\ \min_{l\le i\le r} b_i]。 
]

 如果这个交集至少包含 (k) 列且行数也是 (k)，则存在 (k\times k) 正方形。 

特殊的几何条件给了我们额外的简化。 如果两个好像素位于同一列，则该列中它们之间的每个像素也都是好像素。 因此，如果组的第一行和最后一行都包含某个列间隔，则每个中间行也包含该间隔。 我们可以使用第一行和最后一行来测试候选方格，而不是显式检查它们之间的所有行。 

对于 (N\le 100000)，(O(N^2)) 算法已经太慢了。 大致有

 [
 \frac{N(N+1)}2
 ]

 连续的行范围，当（N=100000）时，大约是（5\times10^9）。 即使每对选手的工作量是恒定的，也远远超出了两秒比赛限制所允许的范围。 我们需要一种接近线性时间的算法。 

在一些边缘情况下，粗心的实施可能会出错。 首先，单行始终是有效的 (1\times1) 正方形。 例如，```
1
0 0
```有答案`1`。 如果实现的答案从零开始并且仅使用两行搜索正方形，则可能会错误地返回零。 

第二个问题是宽的单行并不意味着大的正方形。 考虑```
3
0 3
1 2
0 3
```中间行只有两个好像素，因此最大的正方形有边`2`， 不是`4`。 仅基于最宽行的解决方案是错误的。 此输入有效，因为第一行和第三行的公共列也出现在中间行中。 

包含端点是差一错误的另一个常见来源。 例如，```
3
0 1
0 1
0 1
```恰好包含两个好的列，所以答案是`2`。 区间长度为`b_i-a_i+1`， 不是`b_i-a_i`。 

最后，候选方格不能延伸超过最后一行。 为了```
2
0 1
0 1
```答案是`2`，并检查底行为索引的候选者`2`在访问它之前必须停止。 

## 方法

 一个简单的解决方案可以枚举每个可能的顶行和底行。 对于固定对，我们可以将该范围内的所有行间隔相交，并查看所得的水平间隔是否至少与行数一样宽。 通过运行最大的左端点和最小的右端点，可以在恒定时间内处理每个新的底行。 这使得总体工作量为 (O(N^2))，因为有 (N(N+1)/2) 个可能的行范围。 对于 (N=100000)，大约是 (5\times10^9) 个范围，这太大了。 

画面的结构让我们有更强的观察力。 假设我们已经知道存在一个正方形的边。 现在修复它的顶行 (i) 并询问我们是否可以将其扩展到侧面 (s+1)。 所需的行是 (i) 到 (i+s)。 

仅查看行 (i) 和 (i+s)。 他们共同的良好间隔是

 [
 [L,R]=[\max(a_i,a_{i+s}),\min(b_i,b_{i+s})]。 
]

 如果 (R-L+1\ge s+1)，则两个端点行都包含 (s+1) 个连续的公共列。 选择任何这样的 (s+1) 列间隔。 该间隔中的每一列在两个端点行中都很好。 根据陈述中的垂直凸性条件，这两个好像素之间的每个像素也是好的。 因此，每个中间行包含整个区间，给出一个有效的 ((s+1)\times(s+1)) 平方。 

这将问题转化为增量增长。 保留目前为止找到的最大正方形边，称之为`ans`。 对于每个可能的顶行，尝试扩展`ans`由一行和一列组成。 成功的扩展会增加`ans`， 和`ans`在整个算法过程中最多可以增加（N-1）倍。 

关键的摊销是使该方法呈线性的原因。 尽管顶行可能会执行多次成功的扩展检查，但每次成功的检查都会增加全局答案。 最多可以有 (N-1) 个这样的增量。 每个顶行也可以在一次不成功的检查后或因为已到达图片边界而终止。 因此，内循环总共只有 (O(N)) 次迭代。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(N^2)) | (O(N)) | 太慢了 |
 | 最佳| (O(N)) 摊销 | (O(N)) | 已接受 |

 ## 算法演练

 1. 读取每一行的区间([a_i,b_i])并存储两个端点。 区间表示就足够了，因为每行都是水平凸的。 
2. 设置`ans = 1`。 由于每一行至少包含一个好像素，因此 (1\times1) 正方形始终存在。 
3. 处理每一行`i`作为一个更大的正方形的可能的顶行。 我们已经知道正方形的边长`ans`存在于某处，但我们现在问这个特定的顶行是否可以支撑一个正方形的边`ans + 1`。 
4.首先检查是否行`i`本身至少有`ans + 1`好像素。 其宽度为`b[i] - a[i] + 1`，所以如果
 [
 a_i-a_i+1 < 和+1,
 ]
 该行不能是较大正方形的顶部。 没有理由从这里开始尝试更大的正方形。 
1.让`j = i + ans`。 这是有边的候选正方形的底行`ans + 1`。 如果`j >= N`，候选者将延伸到图片之外，因此我们停止处理顶行。 
2. 计算顶行间隔和底行间隔的交集：

 [
 L=\max(a_i,a_j),\qquad R=\min(b_i,b_j)。 
]

 如果

 [
 R-L+1\ge ans+1,
 ]

 两个端点行共享足够的列以形成一个正方形的边`ans + 1`。 

1. 当交集足够大时，递增`ans`并重复相同的检查。 新候选人有立场`ans + 1`因此到达更下方的一排。 
2. 如果终点交叉口太窄，请停在顶行。 增加候选大小不能使交集更宽，因此从该行开始的更大的正方形不能成功。 
3. 处理完所有顶行后，打印`ans`。 

### 为什么它有效

 不变的是`ans`始终是已找到的某个有效正方形的边长。 每当算法递增它时，新候选者的顶行和底行至少共享`ans`列。 该共享间隔中的每一列在两个端点都包含良好像素。 垂直凸性保证这些端点之间的所有像素都是好的，因此整个候选方块都是有效的。 

相反，当一方候选人`s`对于固定顶行失败，其两个端点行的共享间隔小于`s`列。 任何具有相同顶行的较大正方形将使用相同的底行或什至更晚的一行，并且所需的宽度只会增加。 因此，不会遗漏从该行开始的较大正方形。 由于考虑了每个可能的顶行，因此最终的`ans`是最大可能的正方形边长。 

线性复杂度来自于摊销。 每次成功的内循环迭代都会增加`ans`， 和`ans`最多可以增加 (N-1) 倍。 每顶行至多有一次终止迭代，因此内循环迭代的总数为 (O(N))。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    left = [0] * n
    right = [0] * n

    for i in range(n):
        left[i], right[i] = map(int, input().split())

    ans = 1

    for i in range(n):
        while True:
            # Row i must be wide enough for a square of side ans + 1.
            if right[i] - left[i] + 1 < ans + 1:
                break

            # The bottom row of a square of side ans + 1.
            j = i + ans
            if j >= n:
                break

            # Intersection of the top and bottom row.
            L = max(left[i], left[j])
            R = min(right[i], right[j])

            # Need at least ans + 1 columns.
            if R - L + 1 >= ans + 1:
                ans += 1
            else:
                break

    print(ans)

if __name__ == "__main__":
    solve()
```数组`left`和`right`存储每行的两个端点。 不需要表示单个像素，这使内存使用保持线性。 

答案开始于`1`因为每一输入行至少有一个好像素。 条件`right[i] - left[i] + 1 < ans + 1`使用包含区间长度。 将其写为`right[i] - left[i] < ans`是等价的，但是显式的`+1`使像素计数解释更加清晰。 

对于一方候选人`ans + 1`，最下面一行是`i + ans`， 不是`i + ans + 1`。 一个正方形的边`s` beginning at row `i`正好占据行数`i, i+1, ..., i+s-1`，所以对于`s = ans + 1`，最后一行是`i + ans`。 

交集也是包容性的。 其列数为`R-L+1`，它必须至少是候选边长。 Python 中不存在整数溢出问题，所有相关值最多为 (N)。 

实现中最微妙的部分是内部`while`。 即使它嵌套在行的循环内，它也不会导致 (O(N^2)) 工作。 每当它的身体成功时，`ans`增加。 自从`ans`永远不会减少，也不会超过`N`，整个程序最多有（N-1）次成功迭代。 每行最多可以贡献一次最终失败或边界检查。

 ## 边缘情况

 最小尺寸的情况是```
1
0 0
```该算法开始于`ans = 1`。 对于唯一的一行，一方的候选人`2`需要底行`1`，即在图片之外。 循环停止并打印`1`。 不需要特殊情况的分支。 

对于每一行都完全好的图片来说，```
4
0 3
0 3
0 3
0 3
```第一行成功增长`ans`从`1`到`2`，然后从`2`到`3`，最后从`3`到`4`。 当它尝试侧面时`5`，底行将是索引`4`，因此边界检查会停止循环。 答案是`4`，这就是整个图片。 

对于精确宽度的情况，```
3
0 1
0 1
0 1
```候选人一方`2`有端点交集`[0,1]`，其宽度为`1-0+1=2`。 算法接受它。 候选人一方`3`需要三列，但交叉点仍然只有宽度`2`，所以被拒绝。 答案是`2`。 这是典型的差一情况，其中忘记了包容性`+1`会产生错误的结果。 

为了```
3
0 3
1 2
0 3
```第一行和最后一行很宽，但中间行只有列`1`和`2`。 该算法可以从侧面生长`1`到一边`2`使用前两行。 当它尝试侧面时`3`，第一行和第三行在四列中相交，但顶行本身只能通过端点条件来支持候选，并且垂直凸性属性保证共享间隔也必须存在于中间行中。 这里是边的相关公共间隔`3`候选者必须包含三列，而中间行仅包含两列，因此这样的正方形是不可能的。 该算法正确地停止于`2`。 

最大大小的情况包含 (100000) 个相同的行：```
100000
0 99999
0 99999
...
```答案是`100000`。 内循环对每个可能的边长执行一次成功的扩展，然后在图片边界处停止。 因此，即使是最大的输入也只能产生 (O(N)) 功，而不是 (O(N^2))。
