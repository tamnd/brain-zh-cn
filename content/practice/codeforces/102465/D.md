 ## 解决方案
 ## 问题理解

 城市是一个矩形网格。 公交车选择一条横向东行道路，用固定的行坐标表示`y = r`，从西边进入，一路向东行驶，并且必须在同一排离开。 每当它需要访问这条道路上方或下方的古迹时，它可以垂直转向，访问所需的古迹，然后返回主路。 

对于固定主路行`r`，考虑所有纪念碑具有相同的`x`协调。 它们位于一条垂直的街道上，因此巴士可以在一次垂直旅行中访问所有这些区域。 只有最小和最大的`y`坐标在那`x`事情。 如果这些极端情况是`L`和`R`，巴士必须覆盖该区间`[L, R]`并返回到`r`。 

输入给出`X`北行街道和`Y`东行街道，随后是`N`纪念碑坐标`(x, y)`。 输出是选择最佳水平道路所遍历的最小网格块数。 

这些限制足够大，足以排除尝试每一条可能的道路并扫描每一座纪念碑的可能性。 高达`100000`纪念碑和`100000`可能的水平道路，直接`O(NY)`计算量可达`10^10`运营。 甚至`O(XY)`在最坏的情况下具有相同的顺序。 解决方案围绕`O(N log N)`是合适的，因为排序`O(N)`导出值在约束范围内很容易实现。 

有几种边缘情况可能会使看似合理的实现变得错误。 如果几个纪念碑共享一个`x`协调，独立对待它们会超出垂直行程。 例如：```
2 2
2
0 0
0 1
```正确答案是`3`。 公交车可以进排`0`，向东行驶一个街区，无需绕道即可参观同一条垂直街道上的两个纪念碑。 粗心的实施会收费`2 * |r-y|`两个纪念碑独立地得到`5`对于行`0`。 

单个纪念碑是另一个有用的边界情况：```
1 1
1
0 0
```答案是`0`，因为公交车在唯一可用的水平位置处开始和结束，并且没有东西向的块可以穿越。 盲目添加的实现`X`而不是`X - 1`会产生`1`。 

纪念碑也可以位于第一排或最后一行：```
3 5
1
2 4
```选择行`4`给出最小成本，即`2`，因为公交车横向行驶两个街区，从不需要垂直绕行。 假设最佳道路必须严格位于城市内部的某个地方的实现可能会错过这种情况。 

最后，允许重复的坐标：```
2 3
3
0 1
0 1
0 1
```答案是`1`。 重复的纪念碑不会产生额外的旅行。 只保留最小值和最大值`y`对于每个`x`自然地处理重复项。 

## 方法

 一个简单的解决方案是尝试所有可能的水平道路。 对于每个候选行`r`，我们可以检查每个纪念碑并确定需要多少垂直行程。 如果我们独立处理纪念碑，这需要`O(N)`为一名候选人工作，所以所有人`Y`候选人要求`O(NY)`时间。 最坏的情况是`100000 * 100000 = 10^10`纪念碑检查，远远超出一秒的限制所能处理的范围。 

我们可以通过将具有相同特征的纪念碑分组来改进常数因子`x`，但这并没有解决主要问题。 分组后仍然可以有`100000`不同的垂直街道，并尝试一切可能`r`仍然给出二次功。 

关键的观察是，一条垂直的街道只需要最低和最高的纪念碑。 假设这些值为`L`和`R`。 如果主要道路位于`r`，访问整个区间并返回的最短垂直偏移`r`有长度`2 * (R - L)`什么时候`r`在里面`[L, R]`。 

如果`r < L`，巴士必须首先从`r`到`L`，遍历区间，并从`R`到`r`。 它的长度是`2 * (R - r)`。 

同样，如果`r > R`，其长度为`2 * (r - L)`。 

这三种情况可以更紧凑地写为`2 * (R - L + distance(r, [L, R]))`。 

常数部分`2 * (R - L)`不影响选择`r`。 有趣的部分是最小化距离的总和`r`到所有间隔。 

有一个有用的身份：`distance(r, [L, R]) = (|r-L| + |r-R| - (R-L)) / 2`。 

因此，在添加常数项后，最小化整个旅行相当于最小化`sum(|r-L| + |r-R|)`。 

因此，每条被占用的垂直街道都会贡献两个值，即其下端点`L`和上端点`R`，我们只需要一个值`r`最小化所有这些端点值的绝对差之和。 这样的值就是中位数。 

这正是 SWERC 官方分析中使用的观察结果：仅保留极端值`y`每个坐标`x`，对单点间隔进行两次计数，并选择所有结果端点的中位数。 

因此几何形状消失了。 我们首先将每个占用的列减少到一个区间，收集两个端点，对它们进行排序，取中值，并评估生成的旅行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(NY)`|`O(N)`| 太慢了 |
 | 最佳|`O(N log N)`|`O(N + X)`| 已接受 |

 ## 算法演练

 1. 读取所有纪念碑坐标并维护，对于每个`x`，最小和最大`y`出现在那里。 这两个值完全描述了该街道所需的垂直工作，因为参观它们之间的所有内容都涵盖了该街道上的每个纪念碑。 
2. 对于每一个`x`包含至少一座纪念碑，请附加其最小值`y`和最大`y`到端点数组。 如果所有的纪念碑都在那`x`有相同的`y`，最小值和最大值相等，所以同一个坐标故意插入两次。 
3. 对端点数组进行排序。 由于每个区间恰好贡献两个端点，因此存储值的数量最多为`2N`。 
4. 选择排序后的端点中较低的中位数作为主道路行`r`。 任何中位数都会最小化绝对距离之和，因此即使端点数量为偶数，较低的中位数也足够了。 
5. 开始回答`X - 1`，这是坐标处距西边界的东西距离`0`到坐标处的东部边界`X - 1`。 
6. 对于每个被占用的`x`，设其区间为`[L, R]`。 如果`r < L`， 添加`2 * (R-r)`。 如果`r > R`， 添加`2 * (r-L)`。 否则添加`2 * (R-L)`。 这正是从主干道出发，游览整个区间并返回的最短行程。 

该算法背后的不变性是每个可能的主干道旅行`r`具有完全相同的水平成本，`X - 1`，其垂直成本是所占用的独立成本之和`x`坐标。 将每列替换为其极值间隔不会丢失任何信息。 然后，每个间隔的垂直成本可以根据到其两个端点的距离来重写，因此完整的目标变成了与端点数组的绝对偏差之和。 中值可以最小化该目标，这意味着所选道路是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    X, Y = map(int, input().split())
    N = int(input())

    INF = 10**30
    low = [INF] * X
    high = [-1] * X

    for _ in range(N):
        x, y = map(int, input().split())
        if y < low[x]:
            low[x] = y
        if y > high[x]:
            high[x] = y

    endpoints = []

    for x in range(X):
        if high[x] != -1:
            endpoints.append(low[x])
            endpoints.append(high[x])

    endpoints.sort()
    road = endpoints[(len(endpoints) - 1) // 2]

    answer = X - 1

    for x in range(X):
        if high[x] == -1:
            continue

        L = low[x]
        R = high[x]

        if road < L:
            answer += 2 * (R - road)
        elif road > R:
            answer += 2 * (road - L)
        else:
            answer += 2 * (R - L)

    print(answer)

if __name__ == "__main__":
    solve()
```这`low`和`high`数组实现第一个算法步骤。`low[x]`存储垂直街道上最低的纪念碑`x`， 尽管`high[x]`存储最高的一个。 哨兵`high[x] == -1`标识不包含纪念碑的列。 

端点列表恰好包含每个占用列的两个值。 对于仅包含一个不同的列`y`，两个值相等，这会自动给出所需的双倍贡献。 

中位数选择为`(len(endpoints) - 1) // 2`。 对于偶数个端点，这会选择两个中间值中较低的一个。 两个中间值都是有效的最小化器，因此任一选择都会给出相同的最小成本。 

横向贡献为`X - 1`， 不是`X`. The coordinates of the city range from `0`通过`X - 1`，因此从西边界到东边界正好相交`X - 1`块。 

Python 整数具有任意精度，因此累积的答案不会溢出。 无论如何，最大答案很容易在普通的 64 位范围内，但使用 Python 整数可以完全消除这个问题。

 ## 边缘情况

 当几座纪念碑共享一处时`x`坐标，算法将它们替换为一个间隔。 例如，```
2 2
2
0 0
0 1
```给出间隔`[0,1]`。 它的端点是`0`和`1`，所以中位数可以是任意行`0`或行`1`。 选择行`0`，水平成本为`1`和垂直偏移成本`2`, 给予`3`。 这两座古迹可以在一次旅行中参观，而不需要支付两次单独的旅行费用。 

当所有纪念碑的坐标完全相同时，```
2 3
3
0 1
0 1
0 1
```的间隔为`x=0`是`[1,1]`，其端点插入为`1,1`。 因此中位数是`1`。 水平成本为`1`，垂直成本为零，所以答案是`1`。 重复项不会影响几何图形。 

对于唯一可用位置上的单个纪念碑，```
1 1
1
0 0
```端点数组是`[0,0]`，所以选择的道路是`0`。 自从`X=1`，水平成本为`X-1=0`，并且间隔也贡献为零。 结果是`0`。 

对于垂直范围最边缘的纪念碑，```
3 5
1
2 4
```端点数组是`[4,4]`，所以选择的道路是`4`。 纪念碑就位于主干道上。 公交车只需从西侧到东侧，穿过`X-1=2`块，所以答案是`2`。 该算法不假设最佳行是内部坐标。 

对于纪念碑跨度很大的柱子来说，```
3 5
2
1 0
1 4
```端点数组是`[0,4]`。 任意行来自`0`通过`4`最小化到这个区间的距离，较低的中位数选择`0`。 垂直偏移成本`2 * (4-0)=8`，而水平遍历成本`2`, 给予`10`。 如果城市只有5条东行路，则排`0`有效，因为纪念碑坐标范围为`0`通过`4`。 这说明了为什么区间公式必须正确包含两个端点。 

核心教训是，只有在纪念碑共享一个空间之前，这个问题才看起来是二维的。`x`坐标被压缩为垂直间隔。 之后，唯一剩下的决定是一条水平线的位置，整个优化简化为一个经典事实：中值最小化绝对距离之和。
