 ## 解决方案
 ## 问题理解

 我们有 N 个灯，编号从 1 到 N。最初每个灯都亮着。 k 个命令中的每一个都包含一个正整数 x，并且该命令会切换每个编号为 x 倍数的灯。 切换后的灯从开变为关，或从关变为开。 

命令以固定顺序到达，我们需要在任何命令后立即关闭最多数量的灯。 在第一个命令之前的初始状态是零灯熄灭。 

命令数量的限制很小，k≤100，但N可以达到10 6。直接模拟需要触及每个命令的每一个倍数。 如果所有 100 个命令均为 1，则每个命令都会触及所有 10 6 个灯光，从而提供 10 8 个单独的灯光更新。 这对于 1 秒的限制来说太过分了，尤其是在 Python 中。 我们需要更紧凑地表示一整组灯光。 

自然的表示是一个位集。 一位代表一盏灯，位0对应灯1，位1对应灯2，以此类推。 由命令切换的一组灯是一个大整数。 切换整个组变成单个 XOR 操作，对关闭的灯进行计数变成人口计数`int.bit_count()`。 Python 在内部对打包机器字实现这些操作，因此工作是在优化的本机代码中执行的，而不是每个光执行一个 Python 操作。 蟒蛇的`int.bit_count()`直接返回设置的位数。 

有几种边缘情况很容易被错误处理。 和`N=1`，一个命令`1`切换唯一的灯，所以答案是 1。```
1
1
1
```输出是`1`。 仅检查最终状态并意外忽略命令后状态的解决方案仍然可以在这里工作，但更普遍的教训是最大值可能发生在中间时刻。 

重复的命令是另一个陷阱。```
10
2
2
2
```在第一个命令之后，灯 2、4、6、8 和 10 熄灭，因此答案为 5。第二个命令将所有灯重新打开，但答案仍然是 5。仅检查最终配置的解决方案将错误地输出 0。 

最大可能的命令值也需要正确的边界处理。```
5
2
5
1
```命令后`5`，只有灯 5 熄灭。 命令`1`切换每个灯，关闭 4 个灯，打开 5 个灯。 正确的输出是 4。意外停止于的循环`N - 1`会错过5号灯。 

## 方法

 最简单的解决方案存储每个灯的状态，并通过遍历其倍数来处理每个命令。 对于命令 x，我们访问 x,2x,3x,...，切换每个相应的灯，维护当前关闭灯的数量，并更新答案。 这是正确的，因为对于该命令，每个受影响的灯都会被访问一次，并且增量地维护计数可以避免在每次操作后扫描所有 N 个灯。 

问题是最坏的情况。 如果每个命令都是`1`，每个命令访问N个灯。 当 N=10 6 且 k=100 时，即 100⋅10 6 =10 8 次灯光更新。 C++ 参考方法可以在优化的本机代码中处理这种简单的模拟，但 Python 中的相同循环不适合 1 秒的限制。 官方给出的问题约束确实是N≤10 6，k≤100，时间限制为1秒。 

关键的观察结果是命令不需要表示为 1,000,000 个单独的布尔值。 它自然是一组位置，而集合切换正是异或。 我们可以将整个城市的状态编码为一个 Python 整数。 如果位 j−1 为 1，则灯 j 关闭。 命令 x 的掩码在 x 除 j 时精确设置位 j−1。 应用命令很简单`state ^= mask`。 

还有一个额外的细节，因为通过重复执行构建一百万位掩码`mask |= 1 << position`本身会执行大量 Python 级别的操作。 掩码具有非常规则的二进制模式，因此我们用代数方式构造它。 

对于 m=⌊N/x⌋，所需模式的前 mx 位每 x 个位置包含一组位。 价值

 2 x −1 2 mx −1 ​

 具有由模式的 m 个副本组成的二进制表示`1`正好由 x−1 个零分隔。 将其移动 x−1 个位置会将这些设置位移动到位置 x−1,2x−1,…,mx−1，该位置与灯光 x,2x,…,mx 完全对应。 

蛮力方法之所以有效，是因为它明确地维护了每个灯光，但会失败，因为相同的一百万个位置可能会遍历一百次。 位集观察使我们能够将每个完整的切换作为打包位的异或来执行，并使用本机总体计数操作对结果进行计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况 O(kN) | O(N) | Python 太慢 |
 | 比特集 | O(kN/w) 压缩字操作 | O(kN/w) | 已接受 |

 这里 w 是 Python 的任意精度整数内部使用的机器字宽。 实际实现将每个命令掩码存储为单个 Python 整数。 

## 算法演练

 1. 读取 N、k 和命令序列。 必须保留命令顺序，因为问题要求的是过程中的最大值，而不仅仅是最终状态。 
2.对于每个不同的命令值x，构造一个位掩码，其设置的位精确对应于不超过N的x的倍数。令m=N//x。 表达式

 ( 2 x −1 2 mx −1 ​ )2 x−1

 在精确位置 x−1,2x−1,…,mx−1 处产生设置位。 
3. 将构建的掩码存储在字典中。 如果同一个命令出现多次，则其掩码将被重用，而不是再次构造。 
4. 开始于`state = 0`。 零位意味着相应的灯打开，因此最初每个灯都被正确表示。 
5. 按原始顺序处理命令。 将当前状态与命令掩码进行异或。 XOR 是正确的操作，因为命令掩码中的 1 意味着必须切换灯。 XOR 将 0 更改为 1，将 1 更改为 0。 
6. 在每个命令之后，计算`state.bit_count()`并更新最大值。 这会检查最大值可能出现的每个可能时刻。 

### 为什么它有效

 处理完命令的任何前缀后，位 j−1`state`当光 j 被切换奇数次时，恰好为 1。 每个其值除以 j 的命令都会与该位进行一次异或。 偶数次切换会将灯恢复到原来的打开状态，而奇数次则将其关闭。 因此设置位`state`正是当前关闭的灯。 服用`bit_count()`因此给出该前缀之后关闭灯的确切数量，并取所有前缀的最大值给出所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = int(input())

    commands = [int(input()) for _ in range(k)]

    masks = {}

    def build_mask(x):
        if x in masks:
            return masks[x]

        m = n // x

        # (2^(m*x) - 1) / (2^x - 1)
        # has one bit set every x positions, starting at bit 0.
        pattern = ((1 << (m * x)) - 1) // ((1 << x) - 1)

        # Shift the set bits from positions 0, x, 2x, ...
        # to positions x-1, 2x-1, 3x-1, ...
        mask = pattern << (x - 1)

        masks[x] = mask
        return mask

    state = 0
    answer = 0

    for x in commands:
        state ^= build_mask(x)
        answer = max(answer, state.bit_count())

    print(answer)

if __name__ == "__main__":
    solve()
```输入被读取`sys.stdin.readline`，根据竞争性编程的要求。 问题中只有一个测试用例，因此不需要外部测试用例循环。`m = n // x`是的倍数`x`这是有效的光数。 什么时候`x = n`，我们得到`m = 1`，结果掩码仅包含位`n-1`，对应于光n。 什么时候`x = 1`，掩码包含从 0 到`n-1`，因此该命令可以正确切换每个灯。 

掩码构造仅使用整数算术。 分母`(1 << x) - 1`表示 x 个二进制数的块。 全一整数相除`(1 << (m * x)) - 1`通过该块产生倍数所需的重复模式。 最后的移位将第一个设置位与光 x 对齐，而不是与光 1 对齐。`state ^= mask`是故意按照原来的命令顺序完成的。 命令作为最终状态上的操作进行交换，但最大值是在每个前缀之后获取的，因此重新排序命令会更改答案。 

Python整数具有任意精度，因此当状态达到一百万位时不会出现整数溢出。 内置的`bit_count()`直接计算那些设置的位。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(kN/w) 打包字功 | 每个命令在大约 N 位上执行大整数 XOR 和总体计数 |
 | 空间| O(kN/w) | 最多 k 个掩码，每个掩码包含 N 位 |

 最大状态包含 10 6 位，大约 125 KB。 即使保留 100 个不同的掩码也只需要大约 12.5 MB 的原始位存储，远低于 256 MB 的内存限制。 打包表示还避免了直接模拟可能需要的 10 8 Python 级灯光更新。 

掩码构造使用 Python 原生的任意精度整数运算，而不是对所有倍数进行 Python 循环。 这是使位集方法在原始 1 秒限制下实用的关键实现细节。

 ## 边缘情况

 对于最小情况，```
1
1
1
```我们有`x = 1`,`m = 1`，构造的掩模是`1`。 对初始状态进行异或`0`和`1`给出`state = 1`，其人口数为 1。算法返回`1`，这是唯一可能的最大值。 

对于重复的命令，```
10
2
2
2
```的面具`2`代表灯 2、4、6、8 和 10。第一个 XOR 创建了 5 个设置位，因此答案变为 5。第二个 XOR 完全清除了这 5 个相同的位。 最终状态为零，但记录的最大值仍为 5。这就是算法评估的原因`bit_count()`每次命令之后。 

对于等于 N 的命令，```
5
2
5
1
```第一个掩码仅设置了位 4，代表光 5。因此该状态有一个设置位。 第二个命令设置了五个位中的每一位，因此 XOR 将状态从`10000`到`01111`。 设置了四位，给出了正确答案 4。该构造使用了`n // x`准确地处理端点。 

对于最大尺寸的重复情况，```
1000000
100
1
1
...
1
```的面具`1`被所有 100 个命令重复使用。 在每个奇数命令之后，所有一百万个灯都会关闭，而在每个偶数命令之后，所有灯都会打开。 因此最大值为 1,000,000。 该算法不会重建百万位掩码 100 次，状态更改只是对同一打包整数重复执行 XOR 操作。
