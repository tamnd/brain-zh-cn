 ## 解决方案
 ## 问题理解

 我们有`P`地点，正好有 10,000 人每人选择了一个地点。 如果一个地方被选择`c`人，其真实百分比是

 [
 \frac{c}{100}%
 ]

 因为 10,000 人准确地完成了每个百分比步骤`0.01`。 

该机构没有报告这些确切的百分比。 相反，它将每个百分比独立地舍入为最接近的整数，其中`.50`向上舍入。 因此，如果报告的整数是`r`，真实百分比必须介于`r - 0.50`和`r + 0.50`，包括下端点，排除上端点。 由于真实百分比只能有两位小数，因此可能的值是离散的。 

该任务有两个部分。 首先，我们必须确定报告的整数是否可以来自恰好 10,000 人的任何分布。 其次，如果可以的话，我们必须找到每个地方的最小和最大可能的真实百分比，同时尊重所有地方的人口总数恰好达到 100% 的事实。 

姓名必须按其原始顺序打印。 

界限`P <= 10000`意味着周围的算法`O(P)`是理想的。 甚至`O(P log P)`会很舒服，但没有理由排序或执行任何更复杂的全局计算。 百分比本身的范围是`0`和`100`，并且正好有 10,000 人，因此最有用的表示是处理整数人或整数百分之一。 这完全避免了浮点精度问题。 

有几种边界情况可能会导致直接实现错误。 

考虑一个报告为零的地方。```
1
Park 0
```肯定是一万人都选择了那个地方，所以这份报告是不可能的。 处理报告值的粗心实现`0`只是说真实的百分比位于`[0, 0.49]`可能会忘记全局总和并产生明显有效的区间。 正确的输出是：```
IMPOSSIBLE
```另一个极端是，考虑一个报告为 100 的地点。```
1
Park 100
```每个人肯定都选择了它，所以它的实际百分比正好是`100.00`。 正确的输出是：```
Park 100.00 100.00
```一个通用公式为`100.00`通过`100.49`是错误的，因为百分比不能超过 100。 

当独立舍入间隔本身总和不等于 100% 时，会出现不太明显的边界。 例如：```
2
A 50
B 49
```第一名可以单独来自`49.51`通过`50.49`，第二个来自`48.51`通过`49.49`。 即使他们最大的可能总数是`99.98`，因此这 10,000 人不存在分布。 正确的输出是：```
IMPOSSIBLE
```最后，即使每个单独的区间都是有效的，总数也会迫使某个位置远离天真的下端点或上端点。 在四舍五入值总和为 97 的样本中，其他位置无法贡献足够的百分比，无法让第一位置一路跌至其正常下限。 全球总和从最低限度提高`10.51`到`11.06`。 独立舍入间隔与正好 100% 的固定总数之间的相互作用是问题的核心部分。 

## 方法

 直接的暴力方法会考虑每个地方的所有可能的人数。 由于从 0 到 10,000 有 10,001 种可能的计数，因此我们可以测试每个名额的所有 10,001 个候选者，并检查剩余名额是否可以吸收其有效范围内的剩余人员。 通过预先计算下限和上限之和，可以在恒定时间内检查每个候选者。 

蛮力是正确的，因为每个可行的真实百分比都对应于整数人，并且我们明确检查每个这样的可能性。 问题在于可能性的数量。 和`P = 10000`, 有

 [
 10000 \乘以10001 = 100010000
 ]

 候选值。 在输入解析和输出之前已经进行了大约 1 亿次检查，这在 2 秒限制下是不必要的昂贵。 

关键的观察是我们永远不需要检查单个候选人的数量。 对于每个位置，四舍五入立即给出可能计数的连续间隔。 一旦其他位置按其总最小值和最大值进行汇总，全局总和约束就会对当前位置给出准确的附加限制。 

假设一个地方有一个独立有效的区间`[L_i, U_i]`，以百分之一的百分比表示。 如果我们想最小化它的价值，我们应该让其他地方尽可能大。 其他地方最多能贡献一点

 [
 \sum_{j\ne i} U_j。 
]

 由于总数必须正好是百分之一万，所以当前位置必须至少是

 [
 10000-\sum_{j\ne i}U_j。 
]

 因此，其真正的最小值是该值与其自身独立下限中的较大者。 

最大值对称地出现。 最大化空间`i`，使所有其他地方尽可能小。 他们至少贡献

 [
 \sum_{j\ne i}L_j,
 ]

 所以放置`i`最多可以是

 [
 10000-\sum_{j\ne i}L_j。 
]

 其真正的最大值是该值与其独立上限中的较小者。 

这将整个问题转化为计算两个和并在每个位置执行恒定量的算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(P * 10000)`|`O(P)`| 太慢了|
 | 最佳 |`O(P)`|`O(P)`| 已接受 |

 ## 算法演练

 1. 阅读每个位置及其报告的四舍五入百分比。 将报告的百分比转换为可能的百分比整数百分之一的区间。 

对于报告值`r`严格在 0 到 100 之间，可能的真实百分比是

 [
 r-0.49，r-0.48，\r+0.49。 
]

 以百分之一为单位，这给出了

 [
 L_i=100r-49，\qquad U_i=100r+49。 
]

为了`r = 0`，下界不能为负数，所以`L_i = 0`。 为了`r = 100`，上限不能超过 100%，所以`U_i = 10000`。 

1. 计算所有下限的总和以及所有上限的总和。 

如果

 [
 总和 L_i > 10000，
 ]

 即使使每个地方尽可能小也超过 100%，因此报告是不可能的。 

如果

 [
 \sum U_i < 10000，
 ]

 即使使每个地方尽可能大，也不会达到 100%，因此报告也是不可能的。 

因此，报告在以下情况下是可行的：

 [
 \sum L_i \le 10000 \le \sum U_i。 
]

 1.对于每个地方`i`，计算其最小可能值。 

这个地方不能低于它自己的下限`L_i`。 同时，其他地方最多可以贡献

 [
 \text{sumUpper}-U_i。 
]

 所以当前的地方必须至少提供

 [
 10000-(\text{sumUpper}-U_i)。 
]

 将这两个限制结合在一起给出

 [
 \text{最小值}_i=
 \max\left(L_i,\10000-(\text{sumUpper}-U_i)\right)。 
]

 第二项是由于整个分配总和为 100% 的要求而强加到此位置的金额。 

1. 计算同一位置的最大可能值。 

所有其他地方至少贡献

 [
 \text{sumLower}-L_i。 
]

 因此，当前位置最多可以贡献

 [
 10000-(\text{sumLower}-L_i)。 
]

 将此与其自己的独立上限相结合给出

 [
 \text{最大值}_i=
 \min\left(U_i,\10000-(\text{sumLower}-L_i)\right)。 
]

 1. 通过在最后两位数字前插入小数点，将结果的整数百分位转换回百分比。 Python 格式化`value / 100`和`:.2f`在这里是安全的，但直接从整数商和余数进行格式化也避免了对浮点运算的任何依赖。 
2. 按原始输入顺序打印地名及其最小值和最大值。 

工作原理：在考虑特殊边界 0% 和 100% 后，每个位置都以精确的一组值开始，这些值可以四舍五入到其报告的整数。 唯一剩下的条件是所有位置加起来正好包含百分之一万。 为了最小化一个位置，所有其他位置都应在其允许的间隔允许的范围内推高。 为了最大化它，其他所有地方都应该尽可能降低。 由于所有区间都是连续的整数百分之，这些极值选择表征了确切的可行最小值和最大值。 全局可行性测试保证至少存在一个完整的分配，因此这些界限是可以实现的，而不仅仅是必要的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    p = int(input())

    places = []
    sum_lower = 0
    sum_upper = 0

    for _ in range(p):
        name, value = input().split()
        value = int(value)

        lower = max(0, value * 100 - 49)
        upper = min(10000, value * 100 + 49)

        places.append((name, lower, upper))
        sum_lower += lower
        sum_upper += upper

    if sum_lower > 10000 or sum_upper < 10000:
        print("IMPOSSIBLE")
        return

    out = []

    for name, lower, upper in places:
        minimum = max(lower, 10000 - (sum_upper - upper))
        maximum = min(upper, 10000 - (sum_lower - lower))

        min_text = f"{minimum // 100}.{minimum % 100:02d}"
        max_text = f"{maximum // 100}.{maximum % 100:02d}"

        out.append(f"{name} {min_text} {max_text}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入循环将每个位置及其整数下限和上限存储在一起。 将报告的整数乘以 100 将所有内容移至百分之一，因此`32`变成`3200`，普通的舍入区间变为`[3151, 3249]`。 

这`max(0, ...)`和`min(10000, ...)`操作是必要的。 对于报告的零，`-49`百分之一不是法定百分比，因此下限为零。 对于报告的100，`10049`百分之一也是不可能的，因此上限恰好为 10,000。 

两次累加使得全局可行性测试可以进行一次。 无需检查人员的个人分配情况。 

对于每个地方，`sum_upper - upper`这正是所有其他地方可以贡献的最大金额。 从 10,000 中减去它，就得到了当前地方被迫贡献的金额。 这`max`和`lower`将该全局限制与该地点自己的舍入限制相结合。 

最大值反过来使用相同的推理。`sum_lower - lower`是所有其他地方可以贡献的最小金额，因此当前地方不能超过剩余的总数。 这`min`将该限制与其自身的上限结合起来。 

所有算术最多都保持在几百万以内，因此在 Python 或具有普通 64 位整数的标准固定宽度整数语言中，整数溢出不是问题。 更重要的是，不需要浮点运算来决定可行性或计算精确的两位小数答案。 这可以避免诸如以下值的错误`32.50`。

 ## 边缘情况

 第一个边缘情况是报告值为零。 对于报告为零的位置，数学舍入间隔将从`-0.50`，但百分比不能为负数。 因此，在百分之整数的情况下，间隔是`[0, 49]`。 对于输入```
1
Park 0
```下限和上限总和都不足以达到 10,000，因此算法立即打印`IMPOSSIBLE`。 特殊的下限可防止负百分比进入计算。 

第二个边缘情况是报告值为 100。其正常舍入间隔将扩展到 100% 以上，但百分比不能超过 100。该间隔变为`[9951, 10000]`。 由于只有一个位置，总要求迫使该位置恰好为百分之一万，从而产生```
Park 100.00 100.00
```显式的上钳位使得这项工作无需依赖全局约束来修复无效的局部间隔。 

第三个边缘情况是一个不可能的集合，其舍入间隔加起来几乎为 100。考虑```
2
A 50
B 49
```最大可能值为`50.49`和`49.49`, 给予`99.98%`。 以整数为单位，`sum_upper = 9998`，低于 10,000。 该算法在计算任何单独的答案并打印之前检测到这一点`IMPOSSIBLE`。 仅检查每个报告的百分比是否在 0 到 100 之间就会忽略这个矛盾。
