 ## 解决方案
 ## 问题理解

 我们得到一棵有根二叉树。 每个节点包含一个字符：

 -`'L'`意思是“去左边的孩子”
 -`'R'`意思是“去找正确的孩子”
 -`'U'`意思是“去找父母”

 如果请求的目的地不存在，旅行者将留在原地。 

旅行者从根源开始。 在开始之前，我们可以更改任何节点上写入的字符。 每次更改都会花费一次操作。 

我们的目标是让旅行者在步行过程中的某个时刻至少到达一片叶子，同时尽可能少地进行修改。 

首先要注意的是，我们对整个无限运动过程并不感兴趣。 我们只关心最终是否到达某些叶子。 由于树是有限的，一旦我们选择从根到叶子的路径，唯一重要的节点就是该路径上的节点。 

所有测试用例的节点总数最多为$3 \cdot 10^5$。 任何单独尝试每个叶子并重复遍历树的大部分的算法都可能变成二次算法。 和$3 \cdot 10^5$节点，$O(n^2)$是完全不可行的，同时$O(n)$或者$O(n \log n)$很容易足够快。 

一个微妙的点是标记为的节点`'U'`并不总是坏事。 假设某个节点不是所选根到叶路由的一部分。 我们不关心那里发生什么。 只有我们希望旅行者遵循的路线上的节点才能提供答案。 

另一个容易犯的错误是认为路线上的每个节点都必须指向下方。 考虑：```
1('L')
/
2
```节点 2 已经是叶子。 一旦旅行者到达节点2，目标就达到了。 我们永远不需要关心从节点 2 本身执行的移动。 

一个具体的例子：```
n = 2
s = "LU"

1 -> right child = 2
```根想要向左走，但只有一个右孩子存在。 旅行者永远被困在根源上。 更改根从`'L'`到`'R'`成本为 1 并立即到达叶子。 正确答案是 1。 

粗心的基于模拟的解决方案也可能会陷入由`'U'`标签。 例如：```
1('L')
|
2('U')
```从1开始，旅行者永远在1和2之间交替。 然而，仅将节点 2 更改为指向下方某处的叶子就可以解决问题。 我们需要对树进行全局优化，而不是对当前标签的模拟。 

## 方法

 一个蛮力的想法是单独考虑每片叶子。 对于选定的叶子，查看唯一的根到叶子路径。 该路径上的每个内部节点都必须引导旅行者前往路径中的下一个节点。 如果当前标签已经与所需方向匹配，则该节点的成本为 0； 否则为 1。将这些成本相加即可得出到达该特定叶子所需的修改数量。 对所有叶子取最小值即可得到答案。 

这个推理其实是正确的。 问题是效率。 如果我们显式地重建每个叶子的根到叶子路径，高度倾斜的树可能包含$O(n)$叶子有长度的路径$O(n)$，导致$O(n^2)$工作。 

关键的观察结果是，节点的成本贡献仅取决于我们接下来选择哪个子节点。 

假设我们当前处于节点$v$。 

如果我们确定最佳叶子位于左子树中，则节点$v$必须送我们离开。 该节点的成本为：

 - 0 如果其标签是`'L'`- 1 否则

 同样，如果我们继续进入右子树，则成本为：

 - 0 如果其标签是`'R'`- 1 否则

 这就把问题变成了树DP问题。 

让`dp[v]`表示从节点开始到达某些叶子所需的最小修改数量`v`。 

对于叶子来说，不需要做更多的改变，所以`dp[v] = 0`。 

对于内部节点，我们尝试每个现有的子节点。 如果我们向左走，我们支付本地修改费用加上`dp[left]`。 如果走对了，我们支付相应的本地修改费用加上`dp[right]`。 

这些选择中的最小值变为`dp[v]`。 

由于每个节点都被处理一次，因此整个树在线性时间内求解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取树结构和标签字符串。 
2. 定义`dp(v)`作为从节点开始到达某些叶子所需的最小修改数量`v`。 
3.如果`v`是一片叶子，返回`0`。 

我们已经处于一个满足目标的节点。 
4. 将此节点的答案初始化为无穷大。 
5. 如果存在左孩子，则计算：```
cost = (label[v] != 'L') + dp(left_child)
```这表示如有必要，更改当前标签，然后最佳地从左子树到达叶子。 
6. 使用该值更新节点的答案。 
7. 如果存在右孩子，则计算：```
cost = (label[v] != 'R') + dp(right_child)
```8. 用获得的最小值更新节点的答案。 
9. 返回计算值。 
10. 测试用例的答案是`dp(root)`。 

### 为什么它有效

 从根到叶的每条路径都是由沿该路径的子选择序列唯一确定的。 在每个节点，唯一的决定是所选叶子位于左子树还是右子树。 

如果所选路径继续通过左子节点，则当前节点必须包含`'L'`。 任何其他标签都只需要进行一项修改。 支付本地成本后，剩下的问题与从左子节点获取叶子相同。 同样的论点也适用于右孩子。 

由于每个有效的根到叶路线都分解为局部决策加上最优子问题，因此递归会检查所有可能的叶并计算其中的最小总修改计数。 通过子树大小的归纳，`dp(v)`是每个节点（包括根节点）的真正最优答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    left = [0] * (n + 1)
    right = [0] * (n + 1)

    for i in range(1, n + 1):
        l, r = map(int, input().split())
        left[i] = l
        right[i] = r

    dp = [0] * (n + 1)

    def dfs(v):
        if left[v] == 0 and right[v] == 0:
            dp[v] = 0
            return 0

        res = 10 ** 9

        if left[v]:
            res = min(
                res,
                (0 if s[v - 1] == 'L' else 1) + dfs(left[v])
            )

        if right[v]:
            res = min(
                res,
                (0 if s[v - 1] == 'R' else 1) + dfs(right[v])
            )

        dp[v] = res
        return res

    print(dfs(1))
```DFS 只计算每个子树的 DP 值一次。 叶子立即返回 0，因为到达该叶子就已经满足了目标。 

对于内部节点，递归直接反映了证明的推理。 如果我们选择左子树，当前节点必须引导旅行者向左。 表达式```
(0 if s[v - 1] == 'L' else 1)
```正是该节点所需的修改成本。 

标签存储在零索引字符串中，而节点从 1 开始编号，这就是代码访问的原因`s[v - 1]`。 

一个节点可能只有一个子节点。 该实现仅评估现有的子节点，这很重要，因为在尝试到达叶子时，向不存在的子节点移动是没有用的。 

递归深度可达$n$在退化树中，因此在处理测试用例之前增加递归限制。

 ## 边缘情况

 ### 节点只有一个子节点

 输入：```
1
2
LU
0 2
0 0
```根没有左子节点和一个右子节点。 

该算法仅评估正确的转换：```
cost = 1 + dp(2)
```并完全忽略了失踪的左孩子。 结果是1，这是正确的，因为根必须改为`'R'`。 

### 具有不同成本的多个叶子

 输入：```
1
3
ULU
2 3
0 0
0 0
```根可以到达任一叶。 

向左行驶的费用：```
1 + 0 = 1
```走正确的道路成本：```
1 + 0 = 1
```DP 取最小值并返回 1。该算法永远不会过早地提交特定叶子，这对于最优性至关重要。 

### 深链

 输入：```
1
4
UUUU
2 0
3 0
4 0
0 0
```唯一的根到叶路径是：```
1 -> 2 -> 3 -> 4
```每个内部节点必须指向左侧，因此节点 1、2 和 3 各需要一次修改。 

DP 计算：```
dp(4)=0
dp(3)=1
dp(2)=2
dp(1)=3
```并返回 3。 

### 叶子标签不相关

 输入：```
1
2
LR
2 0
0 0
```节点 2 已经是叶子。 它的标签`'R'`没关系，因为一旦到达节点 2，目标就实现了。 

该算法分配：```
dp(2)=0
```无需检查标签，该标签与问题定义完全匹配。
