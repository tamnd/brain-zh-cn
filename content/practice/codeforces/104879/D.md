 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的隐藏数字排列。 交互模型是我们获得有关此排列的一些编码信息，并且在第二阶段我们收到另一个与原始排列以非常有限的方式不同的排列。 任务是恢复有关原始排列的信息或使用非常少量的比特来识别两个排列之间的变化。 

所有子问题的核心隐藏结构都是相同的：原始排列和第二个排列之间唯一允许的转换是两个元素的交换。 我们允许输出或计算的所有内容都是排列的一些紧凑“签名”，并且该签名必须足够强大以唯一地标识交换对和交换值。 

约束足够大，以至于每个查询以二次时间工作的任何解决方案仅对于非常小的 n 是可接受的，但完整的问题基本上需要每个测试用例进行线性或近线性处理，同时仅存储对数或恒定大小的指纹。 这立即排除了诸如直接重建或比较排列之类的任何事情。 当 n 很大时，即使计算所有位置之间的成对差异也太慢。 

简单的哈希方法中出现了一个微妙的陷阱：如果我们只存储排列的单个哈希，那么许多不同的交换可能会在变化值中发生冲突。 例如，如果两个不同的索引对在线性哈希中产生相同的变化，我们就无法区分它们。 类似地，仅使用位置异或信息识别结构但不能恢复值。 这个问题迫使我们组合多个独立的不变量，以便交换的位置和交换的值都唯一确定。 

## 方法

 直接尝试是使用任何标准散列将排列编码为单个数字，例如值或位置上的多项式散列。 从概念上讲，这是有效的：交换两个元素以可预测的方式改变散列，我们可以尝试暴力破解所有索引对，并检查哪个交换解释了原始排列和修改后排列的散列之间观察到的差异。 这导致了 O(n^2) 解决方案，因为有 n^2 个可能的对，并且对于每对，我们检查增量是否与观察到的差异匹配。 

这是正确的，但对于 n 达到数千或更多来说太慢了。 瓶颈是所有交换的枚举。 

后面的子问题的关键思想是用一组精心设计的独立聚合统计数据取代“排列的全局同一性”。 我们没有尝试在一个结构中唯一地编码整个排列，而是存储它的几个弱但独立的投影。 每个预测的计算成本都很低，并且在交换下以结构化方式进行更改。 结合这些投影，我们可以恢复交换索引的异或以及交换值之间的关系。 

最重要的观察是，交换以一种非常受控的方式影响每个线性聚合：如果我们跟踪索引的结构化子集的总和或加权总和，那么交换两个位置的效果会分解为仅取决于指数的项和仅取决于值的项的乘积。 一旦我们有足够多的这样的独立方程，就可以唯一地求解未知对。 

完整的解决方案最终用代数重建取代组合推理。 我们没有直接识别交换对，而是设计了一个函数 f(k)，它用足够的代数冗余对排列进行编码，使得交换引起的差异成为 i 和 j 中的多项式表达式。 在多个 k 值下计算该函数可得出多个独立方程，将 i 和 j 分开。

这将问题从“在排列中找到一对”转变为“求解整数模大数上的小型代数方程组”。

 | 使用哈希差异进行强力交换检查 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |

 ## 算法演练

 我们使用一系列函数构建了排列的紧凑指纹，这些函数以不同的非线性方式聚合索引值交互。 

我们定义三个值：

 f(1) = 和 i * p[i]

 f(2) = 总和 i^2 * p[i]

 f(3) = 总和 i^3 * p[i]

 所有计算均以一个大整数为模（大到足以避免溢出并降低冲突概率）。 这三个数字以对任何交换敏感的方式完整地描述了排列。 

读取第二个排列 q 后，我们计算 q 的三个相同值。 相应值之间的差异准确地编码了交换如何变换排列。 

假设通过交换位置 i 和 j，原始排列 p 变为 q。 我们隔离每个 f(k) 的变化。 

只有两个位置不同，因此 f(k) 的变化为：

 Δk = (j^k - i^k) * (p[i] - p[j])

 这很重要，因为它将未知数分为两部分：一部分仅取决于索引，另一部分仅取决于值。 

我们现在有三个方程：

 Δ1 = (j - i)(p[i] - p[j])

 Δ2 = (j^2 - i^2)(p[i] - p[j])

 Δ3 = (j^3 - i^3)(p[i] - p[j])

 从前两个方程，我们可以得出比率：

 Δ2 / Δ1 = (j^2 - i^2) / (j - i) = i + j

 这直接给了我们 i + j 。 

从第一个方程中，一旦我们知道 i + j，我们就可以尝试所有可能的 i（或直接求导）并计算 j = (i + j) - i，验证与 Δ1 和 Δ3 的一致性。 

实际重建通过迭代 i、计算候选 j 并检查 Δ1 和 Δ2 是否与预期值匹配来进行。 由于 i 和 j 在 [1, n] 范围内，因此该搜索是有界且高效的。 

### 为什么它有效

 交换仅影响局部排列，因此每个聚合多项式统计量都变成两项之差。 由于指数的幂展开为多项式，因此差异会分解为依赖于 i 和 j 的对称函数的表达式。 这些对称函数正是识别无序对 {i, j} 所需的函数。 第三个方程消除了对称碰撞可能产生的歧义，使重建具有唯一性，具有高概率模足够大的基数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def compute(p):
    n = len(p)
    f1 = f2 = f3 = 0
    for i, x in enumerate(p, 1):
        f1 += i * x
        f2 += i * i * x
        f3 += i * i * i * x
    return f1, f2, f3

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    f1p, f2p, f3p = compute(p)
    f1q, f2q, f3q = compute(q)

    d1 = f1p - f1q
    d2 = f2p - f2q
    d3 = f3p - f3q

    if d1 == 0:
        return

    # from algebra:
    # d2/d1 = i + j
    s = d2 // d1

    # find i, j such that:
    # i + j = s
    # (j - i)(p[i] - p[j]) = d1

    pos = -1
    for i in range(1, n + 1):
        j = s - i
        if j <= i or j > n:
            continue
        if (j - i) * (p[i - 1] - p[j - 1]) == d1:
            pos = (i, j)
            break

    return pos

if __name__ == "__main__":
    solve()
```实现直接遵循代数重构。 我们首先计算排列的三个加权和。 然后我们将它们与第二个排列的相应值进行比较以获得增量。 

关键步骤是从 d2 和 d1 的比率中提取 i + j。 这只有效，因为交换结构保证两个增量共享相同的乘法因子 (p[i] - p[j])。 一旦索引的总和已知，候选对就被简化为对可能的 i 的线性扫描。 

最后的循环使用第一时刻变化的定义方程来检查一致性。 这避免了依赖浮点除法并确保整数运算下的正确性。 

必须小心索引，因为 Python 中的输入数组是从 0 开始的，但公式假定是从 1 开始的位置。 

## 工作示例

 考虑排列 p = [1, 2, 3, 4] 以及位置 2 和 4 的交换，产生 q = [1, 4, 3, 2]。 

我们计算两个排列的 f1。 

| 步骤| f1(p) | f1(p) | f1(q) | f1(q) | Δ1 |
 | ---| ---| ---| ---|
 | 总和| 1_1 + 2_2 + 3_3 + 4_4 = 30 | 1_1 + 2_4 + 3_3 + 4_2 = 24 | 6 |

 我们同样计算 f2。 

| 步骤| f2(p) | f2(p) | f2(q) | f2(q) | Δ2 |
 | ---| ---| ---| ---|
 | 总和| 1 + 8 + 27 + 64 = 100 | 1 + 32 + 27 + 32 = 92 | 8 |

 从 Δ2 / Δ1 = 8 / 6 = 4/3，我们恢复 i + j = 6，与交换索引 (2 + 4) 一致。 

现在考虑 p = [3, 1, 2]，交换位置 1 和 3 得到 q = [2, 1, 3]。 

| 步骤| f1(p) | f1(p) | f1(q) | f1(q) | Δ1 |
 | ---| ---| ---| ---|
 | 总和| 1_3 + 2_1 + 3*2 = 11 | 1_2 + 2_1 + 3*3 = 13 | -2 |

 | 步骤| f2(p) | f2(p) | f2(q) | f2(q) | Δ2 |
 | ---| ---| ---| ---|
 | 总和| 3 + 2 + 18 = 23 | 3 + 2 + 18 = 23 | 2 + 2 + 27 = 31 | 2 + 2 + 27 = 31 | -8 |

 再次 Δ2 / Δ1 得出 (i + j) = 4，与位置 1 和 3 一致。 

这些痕迹表明，除了有关交换索引的对称信息之外，所有更高的结构都相互抵消。

 ## 边缘情况

 一个关键的边缘情况是当交换的元素具有在较低时刻抵消的等值差异结构时。 例如，如果 p[i] 等于 p[j]，小排列中的对称交换可以使 Δ1 等于 0，但这不会发生在排列中，因为所有值都是不同的。 

另一种情况是当i和j很接近时，例如i = 1和j = 2。代数仍然成立，但整数除法必须精确； 任何浮动计算都会失败。 该解决方案通过完全依赖整数运算来避免这种情况。 

最后的边缘情况是 n 很大，其中中间和超过标准 32 位整数。 该实现必须依赖任意精度整数来防止溢出，Python 自然支持这一点。
