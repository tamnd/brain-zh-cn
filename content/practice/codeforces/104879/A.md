 ## 解决方案
 ## 问题理解

 我们有几种零食，每种零食类型可以出现多次，并且每种零食都会提供一定量的咖啡因。 关键的简化是，我们不考虑原始质量和百分比，而是直接将每种零食视为贡献固定的咖啡因值。 因此，输入中的每个项目都可以被视为添加了一定量咖啡因的“数据包”。 

任务是使用最少数量的所选零食类型至少达到所需的咖啡因阈值。 重要的细节是，有效地选择一种类型的零食可以让我们使用同一类型的所有零食来积累咖啡因，因此决定是在类型层面而不是单个项目层面做出的。 

输出是我们需要服用的不同零食类型的最小数量，以便这些类型的所有选定零食的总咖啡因至少达到目标值，或者如果即使服用所有零食也不够，则输出为 -1。 

这些约束意味着输入大小可能很大，因此任何尝试所有类型子集或重复重新计算总和的解决方案都会太慢。 每个测试都需要排序或线性传递的解决方案是预期的，因此每个测试大约 O(n log n) 或 O(n) 是可以接受的，而指数或二次行为则不可接受。 

当单独处理零食而不是按类型分组时，会出现一个微妙的失败案例。 如果我们贪婪地挑选单个零食而不按类型聚合，我们可能会从低产量类型中选择多种零食，而早点完全投入高产量类型会更好。 

例如，假设我们有一个类型 A，其中零食在许多项目中贡献了 100 总咖啡因，而类型 B 包含两种零食，每种零食贡献 51，总计 102。如果我们按个体值贪婪地选择，我们可能会先获取 51 秒，然后延迟选择类型 A，但正确的推理取决于按类型贡献进行分组，而不是按项目选择。 

## 方法

 蛮力视角首先考虑零食类型的每个可能的子集。 对于每个子集，我们将属于这些类型的所有零食的所有咖啡因贡献相加，并检查总数是否达到目标。 在所有有效子集中，我们选择类型数量最少的一个。 这是正确的，因为它直接评估每个可能的决定。 但是，如果有 q 个类型，则需要检查 2^q 个子集，并且计算每个子集的总和可能需要项目数量的线性时间。 即使对于中等大小的输入，这也很快变得不可行。 

关键的观察是，在每种类型中，没有理由部分使用其贡献。 一旦我们决定加入一种类型，我们就会拿走它的所有零食，因为每种零食都会对总数做出积极贡献，而且这样做不会受到惩罚。 这将问题从项目级决策分解为类型级权重，其中每种类型都有一个等于其总咖啡因的聚合值。 

一旦减少到类型级别的权重，目标就变成选择总权重至少达到 x 的最少类型。 这是一个经典的贪婪结构：我们希望使用尽可能少的类型来积累尽可能多的咖啡因，因此我们总是首先选择最“有价值”的类型。 

这将任务减少为计算每种类型的咖啡因总量，按该总量按降序对类型进行排序，然后贪婪地累积，直到达到目标。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对类型子集的暴力破解 | O(2^q·n) | O(2^q·n) | O(n) | 太慢了 |
 | 贪心分组+排序| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 阅读所有零食并将其按类型分组，累计每种类型的咖啡因贡献总量。 此步骤将项目级数据转换为紧凑的表示形式，其中每种类型都有一个有意义的权重。 
2. 对于每种类型，计算其咖啡因的总贡献。 这是必要的，因为对于选择该类型的任何决定来说，只有总体才是重要的。 
3. 将所有类型总计存储在列表中，并按降序排序。 排序确保我们始终首先考虑最具影响力的类型，这对于最大限度地减少所选类型的数量至关重要。 
4. 将运行总和初始化为零，并将所选类型的计数器初始化。 
5. 迭代排序后的类型总计，将每一项添加到运行总和中并递增类型计数器。 每次添加后，检查运行总和是否达到或超过目标咖啡因值。 
6. 如果达到目标，则输出到目前为止使用的类型数量。 如果循环结束但未达到目标，则输出-1。 

排序是安全的原因是，每种类型一旦被选择，就会独立且完全地做出贡献，因此重新排列选择顺序除了始终首先选择最大的剩余贡献之外，无法增加所需的类型数量。 

### 为什么它有效

 在这个过程中的任何时刻，唯一相关的状态是已经积累了多少咖啡因以及选择了多少种类型。 由于每种类型都会贡献固定的正数，因此较早用较大的贡献替换较小的贡献永远不会增加达到相同总数所需的类型数量。 这表明始终存在一个最佳解决方案，该解决方案以总咖啡因的非递增顺序选择类型。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    
    from collections import defaultdict
    tot = defaultdict(int)

    for _ in range(n):
        t, c = map(int, input().split())
        tot[t] += c

    vals = sorted(tot.values(), reverse=True)

    cur = 0
    cnt = 0

    for v in vals:
        cur += v
        cnt += 1
        if cur >= x:
            print(cnt)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```该实现直接反映了算法。 该字典一次性聚合每种类型的咖啡因，确保零食数量的线性复杂性。 对聚合值进行排序可确保我们始终选择接下来最好的可用类型。 

唯一微妙的一点是分组步骤必须在排序之前发生。 对原始项目而不是类型聚合进行排序会导致错误的贪婪决策，因为来自同一类型的多个项目可能会不必要地在选择中拆分。 

## 工作示例

 考虑具有三种类型的输入：

 输入：```
5 150
1 50
1 30
2 60
3 40
3 20
```这里，类型 1 总计 80 个，类型 2 总计 60 个，类型 3 总计 60 个。 

| 步骤| 所选类型 | 当前总和| 行动|
 | ---| ---| ---| ---|
 | 1 | []| 0 | 开始|
 | 2 | [1] | 80| 取最大的类型 |
 | 3 | [1, 2] | 140 | 140 添加下一个最大 |
 | 4 | [1,2,3]| 200 | 200 目标达成 |

 选择3种类型后我们就停止了。 

此跟踪表明，即使类型 2 和类型 3 相等，它们之间的顺序并不重要。 重要的是我们始终优先考虑更大的贡献。 

现在考虑一个不可能达到目标的情况：

 输入：```
3 200
1 50
2 60
3 40
```总数为 50、60、40。即使选择所有类型后，我们也只能达到 150，所以答案为 -1。 

| 步骤| 所选类型 | 当前总和| 行动|
 | ---| ---| ---| ---|
 | 1 | [2] | 60| 取最大|
 | 2 | [2,1]| 110 | 110 继续 |
 | 3 | [2,1,3]| 150 | 150 耗尽所有 |
 | 4 | - | 150 | 150 失败|

 这证实了该算法正确处理不可行的目标。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

def solve_capture(inp: str) -> str:
    import sys
    from collections import defaultdict
    input = sys.stdin.readline

    it = iter(inp.strip().split())
    n = int(next(it))
    x = int(next(it))

    tot = defaultdict(int)
    for _ in range(n):

        c = int(next(it))

    cur = 0
    cnt = 0

        cur += v
        cnt += 1
        if cur >= x:
            return str(cnt)

    return str(-1)

 ## 边缘情况

 第一种边缘情况是单一类型已经超出目标。 该算法会立即处理此问题，因为排序后，首先处理最大的类型并一步触发终止。 

另一种情况是，所有类型的贡献都非常小，而答案取决于将其中许多类型组合起来。 由于算法是按排序顺序累加的，所以它自然会不断累加，直到达到阈值或发生耗尽，而不需要任何特殊处理。 

最后一种情况是没有任何组合达到目标。 由于循环在处理完所有聚合类型值后结束，并且总和从未超过阈值，因此算法会正确返回 -1，而不会提前终止。
