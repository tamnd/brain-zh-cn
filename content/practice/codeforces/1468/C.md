 ## 解决方案
 ## 问题理解

 我们在比萨店处理一系列事件。 

每次查询类型`1 m`出现了，有新顾客来了。 客户从以下时间开始收到连续的 ID：`1`，根据到货顺序。 每个客户还有一个预计的消费价值`m`。 

类型的查询`2`要求我们为尚未服务的最早的顾客提供服务。 

类型的查询`3`要求我们以最大预测支出为当前未服务的客户提供服务。 如果多个顾客的消费金额相同，则必须选择其中最早到达的顾客。 

每个顾客只能被服务一次。 对于每个类型的查询`2`或者`3`，我们必须输出所服务客户的ID。 

约束条件`q ≤ 5 · 10^5`每当出现服务查询时，立即排除扫描所有活跃客户。 在最坏的情况下，可能会有数十万顾客同时等待。 一个`O(q)`每次操作扫描将导致大约`O(q²)`工作量太大了。 

我们需要可以返回两者的数据结构：

 1. 最早未服务的顾客。 
2. 最高优先级的未服务客户。 

每个操作都应该以对数时间或更短的时间运行。 

一个微妙的问题是，任何一个服务员都可以选择同一个顾客。 一旦服务完成，该客户必须从两个选择系统中消失。 忘记这一点会产生重复的答案。 

考虑：```
1 10
1 20
3
2
```顾客`2`首先由波利卡普服务。 第二个查询的答案必须是 customer`1`，不是客户`2`再次。 

当几个顾客的支出相等时，就会出现另一个微妙的情况。```
1 10
1 10
3
```答案一定是客户`1`，因为到达顺序会打破联系。 

## 方法

 强力解决方案将所有活跃客户存储在列表中。 

对于查询类型`2`，它向前扫描，直到找到第一个未服务的客户。 

对于查询类型`3`，它会扫描所有活跃客户以找到最大的消费值，然后应用平局规则。 

这种方法是正确的，因为它直接遵循问题定义。 不幸的是，单个查询可能需要检查`O(q)`顾客。 高达`5 · 10^5`操作，最坏情况的复杂度变成`O(q²)`。 

关键的观察是两个服务员使用两种不同的点菜方式。 

Monocarp 总是想要最小的到达索引。 

波利卡普总是想要最大的消费价值，到货顺序是次要的。 

我们不维护一种复杂的结构，而是维护同一客户的两种独立视图。 

类似队列的结构可以访问最早到达的。 

优先级队列可以访问最大的支出值。 

剩下的挑战是同步。 当一名服务员为顾客服务时，该顾客仍然存在于另一栋建筑内。 从堆或队列中删除任意元素的成本很高。 

标准的解决方案是惰性删除。 我们保留一个布尔数组来指示是否已经为客户提供服务。 每当一个结构返回客户时，我们都会重复丢弃已标记为已服务的条目。 

这将这两个操作都变成了高效的对数时间查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(q²) | O(q) | 太慢了|
 | 两种结构+懒惰删除| O(q log q) | O(q log q) | O(q) | 已接受 |

 ## 算法演练

 1. 为每位到达的顾客分配一个唯一的 ID。 

2. 将每个到达的顾客按到达顺序存储在数组或队列结构中。 

3. 同时将客户插入到由以下键控的最大堆中`(spending, arrival order)`。 

4. 维护一个布尔数组`served[id]`。 

5. 对于查询类型`2`，将指针向前移动到到达订单，直到到达未服务的客户。 输出该 ID 并将其标记为已服务。 

6. 对于查询类型`3`，重复删除其客户已被服务的堆条目。 剩下的第一个条目是有效答案。 输出其 ID 并将其标记为已服务。 

7. 继续处理所有查询。 

### 为什么它有效

 到达指针始终从左向右移动，并准确跳过那些已标记为已服务的客户。 因此，它接触到的第一个未服务的客户正是 Monocarp 会选择的客户。 

该堆始终包含曾经到达的每个顾客。 延迟删除仅在过时的条目到达顶部时才将其删除。 当顶部所有已服务的客户被丢弃后，剩下的顶部元素就是支出最大的未服务客户。 由于到达 ID 包含在堆键中，因此完全按照要求解析较早到达的关系。 

由于每个顾客最多被标记为服务一次，因此服务员都不能为同一顾客服务两次。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    q = int(input())

    arrivals = []
    served = [False] * (q + 5)

    heap = []

    next_id = 1
    front = 0

    ans = []

    for _ in range(q):
        parts = input().split()

        if parts[0] == '1':
            m = int(parts[1])

            arrivals.append(next_id)

            heapq.heappush(heap, (-m, next_id))

            next_id += 1

        elif parts[0] == '2':
            while served[arrivals[front]]:
                front += 1

            cid = arrivals[front]
            served[cid] = True
            ans.append(str(cid))

        else:
            while heap and served[heap[0][1]]:
                heapq.heappop(heap)

            _, cid = heapq.heappop(heap)

            served[cid] = True
            ans.append(str(cid))

    print(" ".join(ans))

solve()
```这`arrivals`数组按照顾客进入餐厅的确切顺序存储顾客。 变量`front`其作用类似于队列头。 

堆存储对`(-money, id)`。 Python 提供了一个最小堆，因此否定支出值会将其变成最大堆。 使用客户 ID 作为第二个组成部分会自动执行所需的平局规则，因为较小的 ID 对应于较早到达的人。 

这`served`数组是惰性删除的关键。 每当一位服务员为一位顾客服务时，我们就会标记该顾客。 另一个数据结构最终会遇到陈旧的记录并将其丢弃。 

任何一个结构的中间都不会移除任何客户，这使得所有运营保持高效。
