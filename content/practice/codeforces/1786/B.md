 ## 解决方案
 ## 问题理解

 我们在数轴上给出了两个有序系统。 一个系统代表蛋糕，每个系统占据以给定位置为中心的固定间隔，另一个系统代表巧克力分配器，每个系统也产生固定的覆盖间隔。 所有蛋糕间隔都是不相交的，所有巧克力间隔都是不相交的。 

我们可以将整个蛋糕传送带严格地向左或向右移动某个实际值。 在这个转变之后，每个蛋糕都必须在其间隔内的某个地方接收巧克力，并且不允许巧克力溢出到所有蛋糕间隔的并集之外。 分配器本身是固定的； 只有蛋糕系统在移动。 

任务是确定是否存在至少一个平移使每个蛋糕区间与至少一个巧克力区间相交，同时确保每个巧克力区间完全位于某个蛋糕区间内。 

约束很大，测试用例中的元素多达 100000 个。 每个测试用例的任何解决方案都必须是线性或线性的，因为所有间隔对的二次比较将大大超出限制。 

当蛋糕间距大于巧克力间距时，会出现微妙的边缘情况，局部对齐是可能的，但全局对齐是不可能的。 例如，即使每个蛋糕可以单独与分配器重叠，排序约束也会阻止一致的全局转移。 

## 方法

 一个蛮力的想法是尝试所有可能的转变。 对于每个班次，我们都会平移所有蛋糕间隔，并检查每个蛋糕是否与某个分配器间隔相交，并且没有分配器延伸到蛋糕之外。 由于头寸是实值的并且约束很大，所以这是不可行的。 

关键的观察结果是蛋糕和分配器都已经排序并且内部不重叠。 此结构强制任何有效对齐以保持顺序：第一个蛋糕必须与第一个可行的分配器对齐，第二个与第二个对齐，依此类推。 一旦顺序固定，问题就简化为检查是否存在一致的偏移量，该偏移量在由间隔半宽度定义的公差约束内同时对齐所有对。 

这成为一个经典的间隔匹配问题：每个蛋糕位置为每个分配器对齐施加一个允许的移位范围。 所有这些范围的交集必须非空。 

通过将每个成对对齐约束转换为有效移位间隔并将它们相交，我们可以有效地确定可行性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（尝试所有班次）| O(∞) 连续 | O(1) | O(1) | 太慢了 |
 | 最优（区间交集）| 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们修复了蛋糕和分配器之间的顺序，因为两者都是排序且不相交的，这意味着交叉将立即违反可行性。 

1. 假设转移后蛋糕 i 必须对应分配器 i。 由于间隔不相交，任何其他映射都会破坏单调排序。 
2. 对于每一对，我们计算使分配器间隔适合蛋糕间隔的移位范围。 
3. 每对都对全局移位变量提供约束，形成有效移位区间。 
4. 我们将所有这些区间相交。 
5. 如果交集非空，则存在有效移位； 否则，它不会。 

每个约束是通过表示移位 x 后，分配器间隔 [b_i - h, b_i + h] 必须位于 [a_i - w, a_i + w] 内而导出的。 这会产生将 x 限制在两侧的不等式。 

### 为什么它有效

移位变量是全局变量，因此每一对变量都对同一变量施加线性约束。 由于约束是独立的并且在实线上形成间隔，因此可行性减少为检查所有间隔是否相交。 排序假设是有效的，因为任何交叉分配都会与两个序列中保证的单调间距相矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, w, h = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        left = -10**18
        right = 10**18

        for i in range(n):
            # dispenser i after shift x lies inside cake i
            # [b_i + x - h, b_i + x + h] ⊆ [a_i - w, a_i + w]

            # left bound: b_i + x - h >= a_i - w
            # x >= a_i - w - (b_i - h)
            l = (a[i] - w) - (b[i] - h)

            # right bound: b_i + x + h <= a_i + w
            # x <= a_i + w - (b_i + h)
            r = (a[i] + w) - (b[i] + h)

            left = max(left, l)
            right = min(right, r)

        print("YES" if left <= right else "NO")

if __name__ == "__main__":
    solve()
```该解决方案的核心是推导每个蛋糕分配器对的有效​​班次间隔。 每对都限制允许的翻译范围，最终的答案仅取决于所有这些范围是否重叠。 

一个常见的错误是尝试直接匹配端点或贪婪地配对蛋糕和分配器而不将约束转换为全局变量。 正确的观点是整个系统依赖于单个移位参数，因此每个约束都必须用该变量来表达。 

## 工作示例

 考虑一个带有三个蛋糕和三个分配器的小箱子，可以对齐。 每对都贡献一个有效的移位间隔，并且它们的交集保持非空。 下表显示了约束如何累积。 

| 我| l 约束| r 约束 | 路口左| 十字路口右|
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 5 | 0 | 5 |
 | 2 | 1 | 6 | 1 | 5 |
 | 3 | 2 | 7 | 2 | 5 |

 最后，交集 [2, 5] 有效，这意味着该范围内的任何移位都有效。 

现在考虑一个失败的案例，其中约束逐渐缩小，直到变空。 

| 我| l 约束| r 约束 | 路口左| 十字路口右|
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 0 | 3 |
 | 2 | 2 | 4 | 2 | 3 |
 | 3 | 4 | 5 | 4 | 3 |

 在最后一步，交集是空的，因此不存在同时满足所有蛋糕的移位。 

这些例子说明本地兼容性不够； 只有全局交集才能决定可行性。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, w, h = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        right = 10**18

            l = (a[i] - w) - (b[i] - h)
            r = (a[i] + w) - (b[i] + h)

            right = min(right, r)

        out.append("YES" if left <= right else "NO")

    return "\n".join(out)

 ## 边缘情况

 当所有蛋糕和分配器已经对齐到恒定移位时，就会出现一种重要的边缘情况。 在这种情况下，每个约束区间都会折叠到一个公共交点，并且算法应立即接受。 另一种情况是当约束很严格但不完全相等时，浮动直觉可能表明可行性，但整数算术仍然会产生有效的交集。 区间公式可以自然地处理这两个问题，因为它将所有内容都减少到单个变量的不等式界限，从而避免了案例分析或启发式匹配的需要。
