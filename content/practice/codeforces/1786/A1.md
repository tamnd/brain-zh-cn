 ## 解决方案
 ## 问题理解

 我们正在用一副相同的牌来模拟一个非常具体的发牌过程。 牌是从牌堆顶部以递增的批量大小取出的。 第一步发 1 张牌，第二步发 2 张牌，第三步发 3 张牌，以此类推。 每次移动后，接收者以每四次重复的模式交替：Alice 接收第一个移动，Bob 接收接下来的两个移动，Alice 接收接下来的两个移动，然后 Bob 接收接下来的两个移动，继续此重复循环。 

输入为我们提供了几个独立的测试用例。 每个测试用例都提供了这副牌中的牌数，我们必须计算在流程完成后有多少张牌最终属于 Alice，有多少牌属于 Bob，包括如果牌组中途用完牌，则移动仅部分完成的可能性。 

每个测试用例 n 最多为 10^6，并且最多 200 个测试用例，这意味着我们无法逐卡模拟。 单独迭代每张卡的简单模拟已经是临界点，但仍然可以接受。 然而，低效地重新计算每个步骤或使用具有开销的每卡操作的简单模拟会变得太慢。 该过程的结构表明步骤数约为 sqrt(n)，因为 1 + 2 + ... + k 呈二次方增长。 

当牌组在步骤中间用完时，会出现微妙的边缘情况。 例如，如果 n 很小，如 1 或 2，我们必须确保正确地将剩余的牌分配给当前玩家，而不会尝试错误地继续循环。 另一种边缘情况是当 n 恰好等于一个三角形数时，这意味着该过程恰好在步骤的边界处结束； 有缺陷的实现通常会错误地处理最后一个完整批次或错误地提前转弯。 

## 方法

 直接模拟通过从牌组中取出 i 张牌并根据周期将它们分配给 Alice 或 Bob 来处理步骤 i。 我们不断地从 n 中减去并累加计数。 这是正确的，因为它完全遵循规则，但在最坏的情况下，我们执行大约 k 个步骤，其中 k 满足 k(k+1)/2 ≥ n，因此 k 约为 sqrt(2n)。 对于 n 高达 10^6 的情况，这大约是 1400 个步骤，这已经很好了，但如果实现时存在不必要的开销或每卡循环，它就会变得脆弱。 

关键的观察是我们永远不需要推理单张牌。 每个步骤都是确定性的：我们只关心完成了多少个完整步骤以及哪个玩家接收每个步骤。 由于步长线性增长，我们可以在 O(sqrt(n)) 时间内逐步模拟，同时跟踪剩余的牌。 我们使用基于步长索引模 4 的简单模式来交替所有权，因此我们永远不会重新计算任何昂贵的内容。 

蛮力之所以有效，是因为它精确地模仿了该过程，但如果我们单独处理每张卡，它就会变得低效。 通过观察步骤是结构化的和所有权是周期性的，我们可以将模拟压缩为一个循环步骤。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（每张卡）| O(n) | O(1) | O(1) | 在最坏的情况下实施速度太慢 |
 | 步骤模拟 | O(√n) | O(√n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 将 Alice 和 Bob 的计数器初始化为零，并从步长 i = 1 开始。 
2. 为剩余的牌 n 维护一个变量。 在每一步中，确定实际要拿多少张牌，这是 i 和剩余牌中的最小值。 这确保我们正确处理最后的部分步骤。 
3. 使用重复周期确定谁接收此步骤。 该模式每 4 个步骤重复一次：步骤 1 转到 Alice，步骤 2 和 3 转到 Bob，步骤 4 和 5 转到 Alice，依此类推。 这可以通过检查 i modulo 4 并将其映射到正确的播放器来实现。 
4. 将所拿的牌添加到相应玩家的总数中，然后从剩余的牌库中减去它们。 
5. 增加 i 并重复，直到没有牌剩余。 

这种映射正确的原因是该问题定义了步骤上的确定性周期性分配，并且除了最后的截断之外，每个步骤都与卡片的数量无关。 由于截断仅影响最后一步，不会改变未来的分配（因为过程立即停止），因此模拟步骤边界可以保持正确性。 

保持的不变量是，处理完步骤i后，完成步骤1到步骤i对应的所有卡牌都已按照周期完全计入Alice或Bob的总数中，而剩余的卡牌（如果有）只属于下一步。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        alice = 0
        bob = 0
        
        i = 1
        while n > 0:
            take = i if i <= n else n
            n -= take
            
            # cycle: 1 A, 2 B, 3 B, 4 A, repeats every 4 steps
            r = i % 4
            if r == 1:
                alice += take
            elif r == 2 or r == 3:
                bob += take
            else:
                alice += take
            
            i += 1
        
        print(alice, bob)

if __name__ == "__main__":
    solve()
```该解决方案独立读取每个测试用例并逐步模拟交易过程。 循环继续，直到所有卡都用完，并且每次迭代根据剩余卡分配完整或部分批次。 

基于模的分支对循环进行编码，而不存储任何数组或预计算分配。 唯一的微妙之处在于将步骤 2 和 3 正确分组为 Bob，将步骤 1、4 分组为 Alice，从而匹配流程中描述的重复模式。

 ## 边缘情况

 对于 n = 1，模拟仅执行步骤 1，将其分配给 Alice，并立即停止。 循环运行一次，take 变为 1，Alice 变为 1，剩余的牌降至零，因此不再执行进一步的步骤。 

对于 n = 2，步骤 1 给 Alice 一张牌，然后步骤 2 给 Bob 两张牌，但只剩下一张牌，所以 Bob 正好收到最后一张牌。 该算法正确使用 min(i, n)，确保不会过度分配。 

当 n 恰好等于 6 或 10 之类的三角形数时，该过程正好在步长边界处结束。 模拟永远不会进入部分步骤，因此所有权纯粹由完整步骤周期确定，无需特殊处理。
