 **标签：** 实施
 **求解时间：** 1m 53s

 ## 解决方案
 ## 问题理解

 我们有一副牌`n`卡片的排列方式使颜色严格交替，从白色开始。 爱丽丝以递增的批量大小发这些牌：首先给自己一张牌，然后给鲍勃两张牌，给鲍勃三张牌，给爱丽丝四张牌，给爱丽丝五张牌，给鲍勃六张牌，给鲍勃七张牌，依此类推。 该模式成对交替：两个连续的步骤到达一个玩家，然后接下来的两个步骤到达另一个玩家。 当剩余的牌少于步长时，所有剩余的牌都归当前玩家所有。 

任务是为每个测试用例计算 Alice 和 Bob 的白牌和黑牌的最终计数。 输入的是卡片的数量`n`每个测试用例，输出是四个整数：白卡Alice，黑卡Alice，白卡Bob，黑卡Bob。 

关键约束是`n ≤ 10^6`以及多达 200 个测试用例。 模拟逐张卡分配的简单方法将涉及最多`200 * 10^6`最坏情况下的迭代，速度太慢了。 我们需要一种方法来计算每个测试用例的恒定或对数时间计数。 

例如，需要注意的边缘情况包括非常小的牌组`n = 1`，只有 Alice 获得一张牌，或者剩余牌组小于下一批大小的情况。 另一个微妙之处是在遵循“每个玩家两步”规则的同时，正确地交替玩家之间的批次分配。 

## 方法

 暴力方法很简单：准确模拟交易过程。 将指针指向牌组的顶部，并为每个步骤分配`step`将卡片发给正确的玩家，每次交替两步，计算他们收到的每种颜色的数量。 这是有效的，因为牌组是交替的； 白卡位于位置 1、3、5、...，黑卡位于位置 2、4、6、...。 然而，总的操作次数与第一个操作的总和成正比。`k`整数，直到达到`n`，这大约是`O(n)`每个测试用例。 对于最大的`n`和`t`，这超出了可行的时间限制。 

最佳方法使用两个观察值。 首先，在连续的交替卡片序列中，白牌和黑牌的数量可以直接从片段长度和起始颜色计算出来。 具体来说，对于长度为`l`从白色开始，白卡是`(l + 1) // 2`黑卡是`l // 2`。 其次，我们注意到步骤序列具有重复结构：步骤以整数递增的批次出现，并且两个连续的步骤到达同一玩家。 利用这两个事实，我们可以迭代这些步骤，通过公式计算计数，而无需模拟单个卡片。 这将复杂性降低到`O(√n)`因为第一个的总和`k`整数呈二次方增长，因此步数大致为`√n`。 鉴于这已经足够快了`n ≤ 10^6`和 200 个测试用例。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 对于大型来说太慢`n`|
 | 最佳 | O(√n) | O(√n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化 Alice 和 Bob 的计数：`alice_white = alice_black = bob_white = bob_black = 0`。 开始于`next_card_white = True`和`step = 1`。 
2. 跟踪当前正在接收牌的玩家。 Alice 开始，每个玩家在切换之前都会收到两个连续的步骤。 
3. 当还有剩余牌时（`n > 0`）：

 a. 计算此步骤中要发牌的数量：`deal = min(step, remaining_cards)`。 

b. 确定该批次中白卡和黑卡的数量。 如果下一张牌是白牌，则白牌计数为`(deal + 1) // 2`黑色计数是`deal // 2`。 如果下一张牌是黑色的，则交换这些公式。 

c. 将计数添加到正确玩家的总数中。 

d. 减去`deal`从`remaining_cards`并翻转`next_card_white`标记如果`deal`是奇数，因为奇数张交替的牌会改变下一张牌的奇偶性。 

e. 增量`step`1. 每两步更新一次播放器。 
4. 按顺序输出最终计数：白爱丽丝、黑爱丽丝、白鲍勃、黑鲍勃。 

关键的不变量是，在每个批次之后，我们确切地知道下一张卡片颜色是什么，并且步骤分配遵循每个玩家两步的模式。 这保证了正确的累积，而无需单独模拟每张卡。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        alice_white = alice_black = bob_white = bob_black = 0
        remaining = n
        step = 1
        next_white = True
        # player 0 = Alice, 1 = Bob
        player = 0
        step_count = 0
        while remaining > 0:
            deal = min(step, remaining)
            if next_white:
                whites = (deal + 1) // 2
                blacks = deal // 2
            else:
                whites = deal // 2
                blacks = (deal + 1) // 2
            if player == 0:
                alice_white += whites
                alice_black += blacks
            else:
                bob_white += whites
                bob_black += blacks
            remaining -= deal
            if deal % 2 == 1:
                next_white = not next_white
            step += 1
            step_count += 1
            if step_count == 2:
                step_count = 0
                player ^= 1
        print(alice_white, alice_black, bob_white, bob_black)

if __name__ == "__main__":
    solve()
```该解决方案初始化两个玩家的计数并迭代步骤，直到发完所有牌。 这`next_white`flag 跟踪顶部卡片的颜色。 我们通过翻转下一张卡片颜色来小心地处理奇数长度的批次，并使用简单的计数器在两步后切换玩家。 使用`min(step, remaining)`避免甲板末端的索引错误。
