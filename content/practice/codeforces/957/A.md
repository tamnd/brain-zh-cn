 ## 解决方案
 ## 问题理解

 给定一个一维长度的条带$n$，其中每个位置要么已经用三种颜色之一绘制，要么留空。 空白位置必须使用相同的三种颜色填充，以便两个相邻位置最终不会共享相同的颜色。 

任务不是对所有有效完成进行计数，而只是确定整个条带是否存在至少两个不同的有效完成。 

如果两个完成的至少一个位置的颜色不同，则认为它们不同。 

约束条件$n \le 100$这表明即使是三次或二次动态规划也很容易足够快。 然而，任何试图直接枚举所有颜色的东西都会增长为$3^n$，即使对于中等程度的人来说，这也是不可行的$n$。 这立即将解决方案推向基于状态的 DP 或具有较小恒定状态空间的记忆方法。 

一个天真的但常见的陷阱是尝试贪婪地填充。 在本地为空白位置选择任何有效颜色可以产生有效的完成，但它不会保留有关替代完成的信息。 另一个陷阱是假设如果存在单个完成，那么当有许多问号时总是存在多个完成，这是错误的，因为约束可以强制唯一性。 

贪心推理的具体失败案例是：

 输入：```
3
C?C
```仅有一个有效的完成：`CMC`。 即使有自由位置，也完全受到双方邻居的限制。 

另一个微妙的情况是字符串已经无效，例如：```
3
CCC
```这有零个有效完成，而不是至少一个。 

真正的困难是有效区分零个、一个或至少两个有效的完成。 

## 方法

 暴力方法会尝试对问号的每一种颜色分配。 如果有$k$问号，这会产生$3^k$的可能性。 对于每个候选者，我们将检查邻接约束$O(n)$，导致$O(n \cdot 3^k)$。 在最坏的情况下$k = n = 100$，这是一个天文数字，完全无法使用。 

问题的结构是有效性仅取决于相邻对，并且决策从左到右传播。 这表明了一种动态编程公式，其中状态只需要记住以前的颜色。 

我们不是枚举完整的字符串，而是跟踪到位置为止存在多少有效的部分着色$i$，以每种可能的颜色结束。 由于我们只关心完整解的数量是否至少达到两个，因此我们可以将所有计数限制为 2。这可以防止溢出并避免不必要的计算。 

关键的见解是状态空间只有 3 种颜色，因此每个位置的 DP 保持恒定大小，从而提供线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举 |$O(n \cdot 3^n)$|$O(n)$| 太慢了|
 | 具有上限计数的 DP |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们定义一个 DP，在其中跟踪每个位置存在多少种有效路径，并以最后使用的颜色分隔。 

### 步骤

 1. 为位置0初始化一个DP表。如果第一个字符是固定的，则只允许该颜色； 否则所有三种颜色都是可能的。 每个有效的起始颜色都只贡献一种方式。 这代表长度为 1 的所有有效前缀。 
2. 从位置 1 迭代到$n-1$，从前一个状态更新一个新的 DP 状态。 对于每个位置，我们都会考虑每种可能的当前颜色。 
3. 如果当前位置固定为一种颜色，我们只允许过渡到该颜色。 如果是“？”，我们会尝试所有三种颜色。 
4. 对于每个候选当前颜色，我们将前一个颜色与当前颜色不同的前一个位置的所有 DP 值相加。 这强制执行邻接约束。 
5. 每次更新后，将所有 DP 值限制为 2。如果任何状态已经达到 2，我们不再需要精确的计数，只需要至少有两个解决方案即可。 
6. 处理完所有位置后，将最后一个位置的 DP 值相加。 如果总数至少为2，则输出“Yes”，否则输出“No”。 

### 为什么它有效

 DP 状态对给前缀着色的所有有效方式进行编码，同时仅记住最后一个颜色，这已经足够了，因为未来的有效性仅取决于邻接性。 每个有效的全着色恰好对应于通过这些状态的一条路径。 由于我们将计数上限设置为 2，因此我们保留了最终决策的正确性：是否存在零个、一个或多个解决方案，而不跟踪精确的大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    colors = ['C', 'M', 'Y']

    dp = {c: 0 for c in colors}

    if s[0] == '?':
        for c in colors:
            dp[c] = 1
    else:
        dp[s[0]] = 1

    for i in range(1, n):
        ndp = {c: 0 for c in colors}

        for cur in colors:
            if s[i] != '?' and s[i] != cur:
                continue

            ways = 0
            for prev in colors:
                if prev != cur:
                    ways += dp[prev]
                    if ways >= 2:
                        ways = 2
                        break

            ndp[cur] = min(2, ways)

        dp = ndp

    total = sum(dp.values())
    print("Yes" if total >= 2 else "No")

if __name__ == "__main__":
    solve()
```该实现维护一个大小为 3 的滚动 DP 字典。 在每一步，它都会为下一个位置构建一个新的字典。 内部循环通过排除颜色重复的过渡来强制执行邻接约束。 

关键的实现细节是 2 的上限。如果没有它，计数可能会不必要地增长，但更重要的是，该问题只需要区分 0、1 和至少 2 个解决方案。

 ## 边缘情况

 像这样的单字符字符串`"?"`产生三个有效的完成，立即满足“至少两个”的要求。 DP 开始时所有三个状态均处于活动状态，因此最终总和超过阈值。 

完全固定的字符串，例如`"CMCMCM"`仅有一个有效的完成。 DP 永远不会分支，因此最终总和仍为 1，正确生成“否”。 

完全统一的无效字符串，例如`"CCC"`消除第一次转换后的所有 DP 状态。 一旦所有状态变为零，它们就保持为零，确保算法正确地报告不可能性。
