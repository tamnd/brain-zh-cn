 ## 解决方案
 ## 问题理解

 我们有一个探索者集合，每个探索者都有一个价值`e`描述包含该探险家的任何组中所需的最少人数。 只有当最终团体人数满足每个成员的要求时，团体才有效。 任务是选择一些探索者并将他们分成尽可能多的有效组。 如果某些探索者无法放入有效的组中，则可能会被忽略。 

输入包含多个独立的测试用例。 对于每个测试用例，该数组代表所有探索者的缺乏经验值。 输出是可以从该数组创建的最大组数。 

所有测试用例的探索者总数最多为`3 * 10^5`。 这意味着该解决方案必须仅处理每个资源管理器少量次。 尝试许多不同组组合的方法很快就会变得不可能，因为可能的分区数量呈指数增长。 甚至一个`O(N^2)`当单个测试用例达到时，解决方案会太慢`200000`探索者，因此预期的解决方案需要接近`O(N log N)`或者`O(N)`。 

有少数情况很容易处理不当。 如果每个探险家都有需求`1`，每个探索者都可以独立存在，答案是数组的完整大小。 

例如：```
1
4
1 1 1 1
```正确的输出是：```
4
```总是尝试首先建立尽可能大的组的粗心解决方案可能会创建一个大小为四的组，并失去创建四个组的机会。 

另一个棘手的情况是当大需求与小需求同时出现时。 

例子：```
1
5
2 3 1 2 2
```正确的输出是：```
2
```立即丢弃具有大量需求的探索者的贪婪方法可能会忽略这样一个事实：一个具有需求的探索者`3`可以与其他两个探索者一起使用以形成一个有效的组。 

最后的边缘情况是当需求大于剩余可用探索器的数量时。 

例子：```
1
3
1 1 5
```正确的输出是：```
2
```需要五人一组的探险家不能被包括在内，但其他两名探险家仍然可以组成两个规模为一的小组。 

## 方法

 直接的暴力解决方案将尝试不同的方法将探索者分配给组并保持最佳结果。 从概念上讲，这是可行的，因为考虑了每一种可能的有效安排，因此必须找到最好的安排。 问题是可能的分配数量增长得非常快。 和`N`对于探索者来说，可能的分区数量远远超出了可检查的范围。 即使将搜索限制在许多可能的组边界也需要太多的操作，大约达到`O(N^2)`或者在实际实施中更糟。 

有用的观察来自于观察是什么使一个群体有效。 如果一个团体有规模`s`，里面的每个探险家都必须有`e <= s`。 这意味着需求较小的探索者更容易安置，而需求较大的探索者则需要更多成员。 

对需求进行排序可以让我们按照难度递增的顺序处理探索器。 排序后，我们可以从最小的需求向上建立组。 我们统计当前组已收集了多少探险家。 当该计数达到当前浏览器的要求时，可以关闭该组并计为一个有效组。 

这种贪婪的选择之所以有效，是因为小需求永远不会从等待更大的群体中受益。 如果一个群组已包含足够当前探索者的人数，则创建该群组会立即将这些探索者保存为已完成的群组，并让后来的探索者组成未来的群组。 当有更多潜在的小组成员可用后，才会考虑更大的要求。 

暴力破解之所以有效，是因为它探索了所有有效的分区，但会失败，因为可能性太多。 排序顺序揭示了组变得有效的确切时刻，这一观察结果让我们可以用单个贪婪扫描替换分区搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | 指数或更差，具体取决于搜索策略 | O(N) | 太慢了|
 | 最佳| O(N log N) | O(N log N) | 除了排序之外还需要 O(1) | 已接受 |

 ## 算法演练

 1. 按非降序对探索者的需求进行排序。 应首先处理较小的需求，因为它们需要更少的人成为有效的组成员。 

2. 遍历已排序数组，同时维护`current`，当前为可能的组收集的探险家数量。 

3.添加当前资源管理器到`current`。 如果`current`至少等于该探索者的要求，组成一个小组并增加答案。 

4. 重置`current`形成一个组后为零，因为这些探索者已经被使用并且不能为另一个组做出贡献。 

关键的决定是在群组生效后立即关闭该群组。 假设当前浏览器有需求`x`我们已经有了`x`小组中的探索者。 为该组保留额外的探索者无法创建更多组，而现在完成则为剩余的探索者提供创建另一个有效组的最佳机会。 

为什么它有效：

 在处理排序数组的任何前缀后，算法仅使用该前缀创建最大可能数量的组。 已完成的组是有效的，因为仅当其大小至少满足其中每个已处理资源管理器的要求时才创建它。 当算法关闭一个组时，在未来组中使用任何这些探索者只会从后来的探索者中删除可用的人员，而不会增加组的数量，因此立即完成该组始终是最佳的。 按排序顺序处理资源管理器可以保证检查的每个需求都是当前组内最大的需求，这足以证明有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        e = list(map(int, input().split()))

        e.sort()

        groups = 0
        current = 0

        for value in e:
            current += 1
            if current >= value:
                groups += 1
                current = 0

        ans.append(str(groups))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案首先对需求进行排序，以便扫描遵循贪心证明中使用的顺序。 变量`current`存储未完成的小组已收集了多少个探险家。 每个探险家都会将该计数加一。 

比较`current >= value`是关闭组的确切条件。 因为数组是有序的，`value`是当前组内遇到的最大需求，因此满足它意味着该组中的每个探索者都得到满足。 

重置`current`归零是至关重要的。 忘记这一点将允许同一个探索者为多个小组做出贡献并产生不可能的答案。 

对于这个问题，Python 整数不会溢出，并且总输入大小足够小，可以在限制内对所有测试用例进行排序。

 ## 边缘情况

 对于所有探索者都有要求一的情况：```
1
4
1 1 1 1
```排序后的数组保持不变。 每次探索后计数器都会达到 1，因此该算法会关闭一个组四次并返回 4。 偏好最大可能组的策略会错误地返回一个组。 

对于混合需求情况：```
1
5
2 3 1 2 2
```排序给出：```
1 2 2 2 3
```第一个探险家单独创建了一个团体。 接下来的两个探险家组成了一个两人规模的小组。 其余两个探索者无法满足要求三，因此被忽略。 答案是两个，匹配最大可能的组数。 

对于不可能的大要求：```
1
3
1 1 5
```排序后的数组为：```
1 1 5
```前两名探险家各自创建一个规模为一的小组。 最后一个探险家将计数器增加到 1，但要求是 5，因此不会创建任何组。 该算法返回两个，这是最佳的，因为第三个探索者不能属于任何有效组。
