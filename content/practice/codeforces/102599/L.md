 ## 解决方案
 ## 问题理解

 这是一个仅输出的构造问题。 没有要读取的输入文件。 任务是打印用小型基于堆栈的语言编写的程序。 生成的程序稍后将由隐藏初始堆栈上的判断器执行。 

初始堆栈包含一个整数计数`N`在底部，然后`N`其上方的非负整数。 打印堆栈程序的目标是留下这些的总和`N`执行后值在栈顶。 其他值可能仍低于答案，因此程序只需保证顶部元素是正确的。 

机器被故意限制。 它不能访问内存中的任意位置，只能访问顶部的几个堆栈元素。 可用指令允许基于当前堆栈状态进行算术、复制、交换和循环。 重要的约束是执行限制：程序必须在`(N + 22)^2`为每个执行指令`0 <= N <= 100`。 这排除了重复扫描整个堆栈以查找每个值的解决方案。 具有大致二次行为的结构是可以接受的，而任何具有三次增长的结构都会超出限制。 

主要困难来自以下事实：`N`可以为零，并且该值可以为零。 使用顶部值作为循环条件而不保留计数的解决方案可能会将数据值与剩余元素数量混淆。 例如，如果堆栈以`0`只是，正确的结果是`0`，但是检查顶部是否非零的循环永远不会运行，并且可能不会留下任何值作为答案。 另一个棘手的情况是单个元素。 如果堆栈包含`1, 5`，答案一定是`5`，以及假设上面总是有两个数字的实现`N`可能会执行无效的交换或添加。 第三种边缘情况是全零值。 为了`3, 0, 0, 0`，一个由值控制的循环，而不是由`N`会立即停止并错误返回`0`在消耗预期结构之前。 

## 方法

 思考问题的一种直接方法是反复从堆栈中删除数字并累加它们的总和。 如果机器可以随机访问，这将是微不足道的：保留一个包含答案的变量并添加每个元素。 困难在于保存计数器`N`在遍历价值观的同时。 

第一次尝试是使用底部的计数器并将顶部的值重复移入累加器。 机器可以做到这一点，但每次迭代都需要重新排列堆栈，以便计数器保持可用。 由于可以有 100 个值，因此堆栈移动的数量是有限的，但设计不当的方法可能会花费太多指令来回移动数据。 嵌套遍历的成本约为`N`每一项的操作`N`元素将达到约`10000`操作，这在这里仍然可以接受，但是更大的不必要的开销风险违反了二次界限。 

关键的观察是堆栈已经存储了剩余值的数量。 我们可以在计数器旁边维护一个累加器，并在每次循环迭代时仅消耗一个输入数字。 计数器永远不会与值混淆，因为每个循环条件都会在正确排列堆栈后检查计数器位置。 

构造使用了一个小技巧。 我们首先创建一个零累加器。 然后，当计数器为正时，我们将当前的最高值添加到累加器并递减计数器。 在此循环之后，仅保留累加器和消耗的计数器，因此最后一步删除不必要的值并将任何剩余的堆栈值组合到所需的顶部结果中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(N) 堆栈深度 | 可以，但容易超出指令限制 |
 | 最佳 | O(N²) | O(N) 堆栈深度 | 已接受 |

 ## 算法演练

 1. 将一个零放入堆栈并重新排列顶部元素，使零成为运行总和，而原始元素`N`保持无障碍。 累加器必须从零开始，因为求和运算需要一个中性值。 
2. 当计数器不为零时重复。 复制并交换必要的堆栈元素，以便可以添加当前数字而不会丢失计数器。 添加该值后，将计数器减一。 每次迭代仅消耗一个输入值。 
3. 处理完所有值后，删除剩余的计数器信息并合并剩余的堆栈值，直到顶部仅可见所需的总和。 
4. 将累加器保留为栈顶元素。 法官只检查这个最终财产，因此只要临时簿记值低于答案，就没有关系。 

为什么它有效：主循环期间的不变性是累加器包含已删除的所有值的总和，而计数器表示仍有多少原始值未处理。 最初累加器为零，计数器为`N`。 每次迭代恰好删除一个值，将其添加到累加器，并减少计数器，从而保留不变式。 当计数器达到零时，每个原始值都被添加一次，因此累加器等于所需的总数。 

## Python 解决方案

 下面的 Python 程序本身就是所需的答案生成器。 它打印堆栈机的有效程序。```python
import sys
input = sys.stdin.readline

program = """PUSHZ
SWAP2
WHILE NOT EZ DO
BEGIN
COPY
SWAP3
ADD
SWAP2
DEC
END
POP
"""

sys.stdout.write(program)
```生成的程序首先创建累加器。`SWAP2`将累加器放置在相对于原始计数的正确位置。 循环条件检查计数是否已达到零。 在循环内部，`COPY`,`SWAP3`， 和`ADD`重新排列顶部元素，以便下一个值包含在运行总和中。`DEC`更新剩余计数。 

决赛`POP`循环结束后删除旧计数器。 答案保留在堆栈上，因为累加器在每次迭代中都被保留。 

生成器中没有整数溢出处理，因为目标机器支持任意大小的整数。 Python 代码也不处理输入，因为这是一个仅输出的问题。

 ## 边缘情况

 对于`N = 0`，程序立即看到一个零计数器。 循环条件失败，因此不会发生无效的弹出或算术运算。 最终的清理留下初始化的零累加器作为答案。 

为了`N = 1`有价值`5`，第一次也是唯一一次迭代消耗单个值，将其添加到累加器，并将计数器从 1 减少到 0。 该程序从不尝试访问丢失的第二个值。 

为了`N = 3`有价值观`0, 0, 0`，循环由计数器控制，而不是由求和的值控制。 即使每个值都为零，循环仍会执行三次并在停止之前消耗所有元素。 

## 常见错误

 一个常见的错误是使用添加的当前值作为循环条件。 这会失败，因为输入值允许为零，因此有效元素看起来与终止状态相同。 

另一个错误是在移动值时破坏计数器。 机器无法恢复剩余元素的数量，因此循环可能会过早停止或继续，直到导致运行时错误。 

第三个错误是忘记了`N`其本身是初始堆栈的一部分。 最终答案只需位于顶部，但程序必须保留足够的结构，以便在处理时区分计数和数据值。
