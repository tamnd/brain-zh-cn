 ## 解决方案
 ## 问题理解

 我们遵循一个整数序列。 给出第一个值，并且通过查看当前值的数字来生成每个下一个值。 我们找到以十进制形式出现的最小数字和最大数字，将它们相乘，并将该乘积添加到当前值。 任务是找到位置上的值`K`，其中第一个值有位置`1`。 

输入包含多达 1000 个独立的起点。 起始数字可以大到`10^18`，因此不能使用较小整数问题的固定大小假设来处理。 位置`K`可以大到`10^16`，这是关键约束。 每一步执行一次转换的直接模拟是行不通的，因为即使是单个测试用例也可能需要十万亿次迭代。 该解决方案需要使用序列的属性而不是依赖于序列的大小`K`。 

有几个细节可能会破坏原本合理的实现。 诸如以下的值`1`只有一位数字，因此最小和最大数字相同。 用于输入`1 4`，序列是`1, 2, 4, 8`，所以答案是`8`。 假设至少两位数字的实现在这里会失败。 

另一个边缘情况是包含零的数字。 用于输入`105 2`，第一个转换添加`0 * 5`，所以值保持不变`105`。 正确的输出是`105`。 如果实现在查找最小数字时忽略零数字，则会错误地添加正数。 

第三种情况是所有数字都相等。 用于输入`777 2`，增加值是`7 * 7 = 49`, 给予`826`。 最小和最大数字仍然是有效值，尽管它们之间没有区别。 

## 方法

 最直接的方法是精确模拟重现。 对于每一步，将当前值转换为数字，扫描这些数字以找到最小值和最大值，计算它们的乘积，并将其添加到数字中。 这是正确的，因为每个生成的值都遵循序列的定义。 

问题是值`K`。 如果`K = 10^16`，模拟需要大约`10^16`一个测试用例的转换。 即使过渡只需要几台机器操作，总的工作量也远远超出了时间限制。 

有用的观察来自于查看附加值。 两位小数的乘积总是在`0`和`81`。 如果一个数字包含数字`0`，下一个转换加零并且序列永远停止变化。 否则，每一步至少增加`1`，但最多增加的是`81`。 

这意味着虽然`K`可能很大，序列无法继续自由增长大量步数。 该号码最多以 19 位数字开头，因为`a1 <= 10^18`。 最多添加`81`每一步意味着经过足够多的转换后，在达到包含零的数字或进入下一次加法为零的状态之前，该数字仍将具有相对较小的可能值范围。 实际上，有用的转换数量很少。 

最佳解决方案是在过程仍在变化时进行模拟，一旦下一个增量变为零就尽早停止。 序列快速达到固定点的观察结果减少了依赖于`K`到仅取决于序列的短瞬态部分。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(K * 位数) | O(1) | O(1) | 太慢了|
 | 最佳| O(T * 位数) | O(1) | O(1) | 已接受 |

 这里，`T`是序列停止变化之前的转换次数。 对于给定的限制，它是一个很小的常数。 

## 算法演练

 1. 对于每个测试用例，读取起始值`a`以及所需的位置`K`。 如果`K`已经是`1`，答案是初始值，因为不需要转换。 
2. 虽然`K`大于`1`，找到当前值中的最小和最大数字。 下一个值仅取决于这两个数字，因此不需要存储之前的序列值。 
3. 将最小和最大数字相乘即可得到增量。 如果该增量为零，则序列将永远保持不变。 当前值已经是每个剩余位置的最终答案，因此停止模拟。 
4. 否则，将增量添加到当前值并减少`K`减一是因为已经执行了一次转换。 
5. 循环结束后打印最终值。 

为什么它有效：

 该算法完全遵循用于定义序列的递归。 每个非终结符转换都会计算相同的数字最小值、数字最大值和加法作为数学定义。 唯一的优化是当附加值变为零时提前停止。 此时，下一个值等于当前值，再次应用递归将永远产生相同的数字。 由于所有剩余位置都具有相同的值，因此返回当前数字是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a, k = map(int, input().split())

        while k > 1:
            x = a
            mn = 10
            mx = 0

            while x > 0:
                d = x % 10
                mn = min(mn, d)
                mx = max(mx, d)
                x //= 10

            add = mn * mx

            if add == 0:
                break

            a += add
            k -= 1

        ans.append(str(a))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```外循环处理独立的测试用例。 在每种情况下，只有当还有转换需要执行时，模拟才会继续。 条件`k > 1`使用是因为输入数字已经代表`a1`，因此到达第二个位置只需要一次更新。 

数字扫描使用除以十而不是字符串转换。 两种方法在这里都有效，但算术提取避免创建临时字符串并直接使用整数值。 变量`mn`和`mx`开始于`10`和`0`因为每个小数位都位于`0`和`9`。 

支票`add == 0`是主要的优化。 如果没有它，即使每个未来值都是相同的，程序也会不断迭代。 Python 整数不会溢出，因此大的起始值和加法不需要特殊处理。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(T * D) |`T`是变化的转变的数量，`D`是位数，最多 19 |
 | 空间| O(1) | O(1) | 只存储了几个整型变量 |

 有用转换的最大数量很小，因为每个转换要么达到固定值，要么在小范围内增加值。 该算法从不依赖于巨大的上限`K`，因此很容易满足一秒的时间限制。

 ## 边缘情况

 对于单个数字值，数字搜索必须将该数字视为最小值和最大值。 有输入`1 4`，过渡是`1 -> 2 -> 4 -> 8`，所以答案是`8`。 该算法每次都会扫描唯一的数字并计算出正确的乘积。 

对于包含零的数字，零必须参与最小位数计算。 有输入`105 2`，最小位数为`0`最大位数是`5`。 增量为`0`，所以序列不会改变，答案是`105`。 停止条件立即处理这个问题。 

对于数字相同的数字，没有特殊情况要求。 有输入`777 2`，数字扫描发现`mn = 7`和`mx = 7`，产生增量`49`。 下一个值是`826`，这确认了相同的最小和最大数字仍然可以正常处理。
