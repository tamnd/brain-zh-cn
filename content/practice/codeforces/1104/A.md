 ## 解决方案
 ## 问题理解

 我们得到一个整数$n$，我们希望将其表示为正整数之和，每个正整数都在 1 到 9 之间（包括 1 和 9）。 换句话说，我们正在分割价值$n$分成“数字”，但允许重复，并且不要求数字组成一个数字，只是它们的总和等于$n$。 

在所有可能的分解方式中$n$，我们希望最小化分解中出现的不同数字值的数量。 例如，如果我们可以表达$n$仅使用重复多次的数字 2，这比混合使用 1、2 和 3 更好。 

输出是实现尽可能少的不同数字值的任何有效分解。 我们还输出总共使用了多少位数字。 

约束条件$n \leq 1000$足够小，即使每个测试用例的线性构造也足够了。 任何运行的解决方案$O(n)$或者更好是非常快的。 

一个微妙的点是，目标不是最小化位数，而是最小化所使用的不同数字值的数量。 天真的读者可能会错误地首先尝试减少长度，从而导致错误的推理。 

典型的错误方法是贪婪地获取尽可能大的数字（就像总是使用 9）。 虽然这最大限度地减少了位数，但除非仔细处理，否则它并不能以结构化方式直接保证最小的不同值。 

## 方法

 暴力方法会尝试从 1 到 9 的所有可能的数字多重集合，其总和为$n$，然后计算每个候选多重集中出现多少个不同的值。 这本质上是一个有界整数划分问题，对允许的值有额外的约束，并且对不同的基数有一个次要目标。 的组合数$n$呈指数增长，大致为$2^n$对于不受限制的分割，即使对于$n = 1000$。 

关键的观察结果是，限制不同数字值的数量比看起来要强大得多。 如果我们决定仅使用一位数字值$d$，那么问题就变成检查是否$n$可以整除$d$，如果是这样，则使用$n/d$的副本$d$。 这立即给出了一个有效的分解，其中只有一个不同的数字。 

如果没有一个数字有效，那么我们尝试使用两个不同的数字。 然而，对于这个问题，我们不需要显式地构造复杂的混合物。 相反，我们可以观察到始终允许使用数字 1，并且始终可以完成任何剩余的余数。 因此，我们始终可以确保最多两个不同数字的可行性，并且在实践中，更简单的构造策略就足够了：使用尽可能多的 9 并以余数结束。 

标准的建设性解决方案是最大限度地利用数字 9，然后将剩余的余数作为最终数字处理。 这最多产生两个不同的数字：9 和余数（如果非零）。 由于 1 也是一个数字，因此余数始终有效。 

这种结构是最佳的，因为只有在以下情况下才可能使用单个数字：$n \leq 9$，否则任何一位数字都必须整除$n$，这很少可能。 为了$n > 9$，我们能保证的最好方法是使用恰好两位数的值，并且此构造实现了该限制。

 ## 算法演练

 1. 计算有多少个全9$n$，即$q = n // 9$。 这将最大化大数字的数量，并尽可能减少余数。 
2. 计算余数$r = n \bmod 9$。 这是唯一不能用另一个 9 来表达的值。 
3.如果$r = 0$， 输出$q$数字，全部等于 9。这是有效的，因为$9q = n$，因此使用一位数字值即可满足总和约束。 
4.如果$r \neq 0$， 输出$q$等于 9 的数字和一个附加数字等于$r$。 这确保总和变为$9q + r = n$。 
5. 打印总位数$k = q + (r \neq 0)$，然后是构建的序列。 

9的选择并不是任意的。 它是允许的最大数字，因此它最大限度地减少了达到所需的位数$n$，并且保证任何余数仍在有效数字范围内$[1, 9]$。 

### 为什么它有效

 该构造始终会产生有效的分解，因为每个元素都在 1 到 9 之间，并且总和被精确保留。 在所有仅使用一位数字值的分解中，只有$n$都是可能的，但这种情况很少见。 一旦我们允许第二个数字，使用 9 可以最大限度地减少所需组件的数量，并且任何剩余的余数都无法在不引入额外的不同数字值的情况下进一步拆分。 这确保我们永远不会引入超过两个不同的数字，这对所有数字都是最佳的$n > 9$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    q = n // 9
    r = n % 9
    
    res = []
    
    for _ in range(q):
        res.append(9)
    
    if r:
        res.append(r)
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```代码直接实现了上面导出的构造。 整数除法计算使用了多少个全 9，而取模则计算剩余的余数。 

一个常见的实施陷阱是忘记处理以下情况$r = 0$，这会错误地添加额外的零数字或额外的元素。 另一个问题是错误计算位数$k$，它必须与构造的列表完全匹配。

 ## 边缘情况

 对于$n = 9$，算法计算$q = 1$,$r = 0$，产生一个数字[9]。 这正确地避免了添加无效的零余数数字。 

为了$n = 10$，我们得到$q = 1$,$r = 1$，产生 [9, 1]。 总和被精确保留，并且只出现两个不同的数字，这是最佳的，因为 10 不能使用 [1,9] 中的单个数字来表示。 

为了$n = 1000$，该算法产生 111 个 9 和最后一个 1。该结构在最大输入大小下保持稳定，并且除了列表构造之外不需要溢出或特殊处理。
