 ## 解决方案
 ## 问题理解

 我们在数轴上得到两个已排序的位置序列。 一个序列代表位于街道沿线的垃圾袋，另一个序列代表卡车可以离开街道的出口。 对于每个垃圾袋，我们需要确定到最近出口的距离，并将这些距离汇总作为最终答案。 

关键约束是两个序列都已按非降序排序。 这种结构不是装饰性的，这是该解决方案可以避免从头开始对每个包进行重新计算比较的全部原因。 

如果我们将出口数量表示为 m，将行李数量表示为 n，则直接解释表明我们可以将每个行李与每个出口进行比较。 这会导致 n 乘 m 距离检查，当两个数组都很大时，这太慢了。 

当所有出口都严格位于袋子的一侧时，就会出现微妙的边缘情况。 在这种情况下，最近的出口并不含糊，但仅检查一个方向或不考虑两个邻居的幼稚实现可能会返回不正确的结果。 例如，如果出口位于`[1, 2]`一个袋子在`100`，正确答案是`98`，但是仅比较直到通过包位置然后提前停止的实现可能会错误地错过最后一个有效出口。 

当存在重复值或聚集值时，会出现另一种故障模式。 如果出口是`[10, 20, 30]`和袋子是`[21, 22, 23]`，每个包重置的幼稚指针可以从头开始重复重新扫描，即使正确的最近出口索引仅向前移动，也会产生不必要的二次行为。 

## 方法

 暴力方法计算每个行李到每个出口的绝对距离并取最小值。 这是正确的，因为它显式检查所有可能性，但它执行 n × m 比较。 在较大的约束下，这会变得太慢，因为两个阵列都可能增长到该乘积超出允许的操作数量级的大小。 

关键的观察结果是，当我们沿着袋子从左向右移动时，最近的出口索引不能向后移动。 如果行李稍微向右移动，最佳候选出口要么保持不变，要么移动到下一个出口。 这种单调性允许我们维护一个指向 exits 数组的指针，并且只向前移动它，而不会重置它。 

一旦我们到达当前包右侧或等于当前包的第一个出口，最近的出口始终位于该出口和前一个出口之间。 由于排序顺序，向右或向左的所有内容都肯定会更糟。 这将每个行李的搜索次数减少到摊销常数时间。

 | --- | --- | --- | --- |
 | 蛮力 | O(n·m) | O(1) | O(1) | 太慢了|
 | 两个指针| O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们按升序处理行李，同时按升序穿过出口。 

1. 初始化一个指针`j = 0`在出口数组上。 该指针代表我们尚未排除当前包的第一个出口。 
2. 对于每个行李位置`b[i]`， 进步`j`尽管`j + 1 < m`下一个出口仍然更接近或相等，因为`c[j + 1]`作为候选人并不比`c[j]`对于这个包。 具体来说，我们移动`j`直到`c[j]`第一个出口大于或等于`b[i]`，或者直到我们用完出口。 
3.一次`j`已定位，最近的出口必须是`c[j]`或者`c[j - 1]`如果存在的话。 我们计算两个绝对距离并取最小值。 
4. 将这个最小距离添加到累计总距离中。 
5. 继续下一个袋子，无需重置`j`。 这是有效的，因为未来的行李处于相同或更好的位置，因此较早的退出不会成为新的最佳选择。 

重要的结构决策是我们永远不会重新扫描每个行李的出口。 指针仅向前移动，这样既保留了正确性，又消除了重复工作。 

### 为什么它有效

 不变的是在处理 bag 之前`i`, 指针`j`位于最小的索引处，使得所有的都严格位于左侧`j`保证不会比位于或右侧的任何出口更好`j`对于所有剩余的行李。 因为两个数组都已排序，所以增加袋子位置不能使先前丢弃的出口再次变得最佳。 这种单调优势确保仅检查周围的两个相邻候选者`j`足以保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    j = 0
    ans = 0

    for x in b:
        while j + 1 < m and abs(c[j + 1] - x) <= abs(c[j] - x):
            j += 1

        best = abs(c[j] - x)
        if j > 0:
            best = min(best, abs(c[j - 1] - x))

        ans += best

    print(ans)

if __name__ == "__main__":
    solve()
```该实现保留单个指针`j`超过出口。 仅当下一个出口至少与当前包的当前出口一样好时，内部循环才会推进它，确保我们始终以局部最优候选结束。 第二次检查针对`j - 1`处理最近出口位于指针左侧的边界。 

一个常见的错误是重置`j`每个袋子。 这保留了正确性，但破坏了线性复杂性。 另一个错误是只检查相对于的一个方向`j`，当最近的出口位于另一侧时，该方法会失败。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 行李和出口上方的每个指针仅向前移动，绝不会向后移动 |
 | 空间| O(1) | O(1) | 除了输入存储之外，仅维护几个变量 |

 线性复杂度对于大型输入至关重要，因为它避免了为每个行李重新计算最近出口检查。 每个出口最多被访问一次，这使得执行良好地保持在典型的 Codeforces 限制内。

 ## 边缘情况

 当所有行李都位于第一个出口的左侧时，指针永远不会前进，每个行李都必须仅与第一个出口进行比较。 该算法处理这个问题是因为`j`保持在零并且`j - 1`检查永远不会被触发。 

当所有行李都位于最后一个出口的右侧时，指针前进直至到达最终索引，然后停止。 所有距离仅根据最后一个出口计算，因为右侧不存在更好的候选者。 

当出口稀疏而行李密集时，指针相对于行李缓慢前进，但仍然只向前移动。 即使许多行李共享相同的最近出口区域，这也能保证线性行为。
