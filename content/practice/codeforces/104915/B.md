 ## 问题理解

 我们得到了一条以绝对罗盘方向书写的路线，其中每一步都是四个值之一：北、东、南或西。 执行路线的平台从固定方向开始，最初面向北。 当执行路线时，每个新命令都是在全局坐标系中给出的，但我们想要的是从移动平台的角度将相同的运动重写为一系列相对命令。 

关键的转换是，在每一步中，我们不是将方向解释为绝对向量，而是相对于平台的当前方向解释它。 每次移动后，平台的方向都会更新以匹配它刚刚移动的方向，并且下一个命令必须相对于这个更新的方向来表达。 

因此，输出是相同长度的序列，但不是绝对方向，而是编码平台是否相对于其当前航向继续向前、右转、掉头或左转。 

约束足够小，对字符串进行一次线性扫描就足够了。 任何尝试从头开始重新计算每个位置的相对方向的解决方案仍然是线性的，但任何涉及成对重新计算或预先计算所有转换的操作都是不必要的开销。 自然目标复杂度是 O(n)。 

一个微妙的边缘情况来自处理方向算术中的环绕。 由于方向形成大小为 4 的循环，因此简单的减法可能会产生负值。 例如，从北向西移动会产生 -1 的原始差异，必须将其标准化为有效范围 [0, 3]。 任何忘记模块化标准化的实现都会在这些环绕转换中默默地产生不正确的相关命令。 

另一个常见的陷阱是误解平台方向在每一步后都会发生变化。 例如，如果我们错误地假定固定参考方向（始终为北），则在第一次移动后我们将始终错误地计算相对方向。 

## 方法

 强力解释将逐步模拟平台，并在每一步通过将当前命令的绝对方向与当前方向进行比较来重新计算相对方向。 这已经接近最佳状态，但粗心的实现可能会通过重复扫描或映射对来重新计算差异，从而导致冗余工作。 

清晰的观察结果是，绝对方向和相对转换都位于同一个大小为 4 的循环组中。 如果我们将方向编码为整数，北、东、南、西映射到 0、1、2、3，那么相对命令就是目标方向和当前方向之间的模差。 执行步骤后，我们将当前方向更新为相同的目标方向。 

这将问题简化为维护单个整数状态并针对每个字符执行恒定时间算术。 蛮力思想之所以有效，是因为它已经遵循模拟结构，但如果我们考虑几何向量或基于字符串的变换，它就会变得不必要的复杂。 一旦我们认识到循环结构，一切都会分解为简单的模算术。

 ## 算法演练

1.将每个方向字符转换为一个循环中的整数：北变为0，东1，南2，西3。这样可以通过算术运算来表示旋转。 
2. 将当前方向初始化为 0，因为平台开始面向北。 
3. 对于输入序列中的每个命令，使用减法计算命令方向与当前方向之间的差。 
4. 使用模 4 标准化此差异。如果结果为负，则通过模算术隐式加 4。 这确保我们始终保持在有效的方向状态内。 
5. 将结果值转换回相对命令：0 表示继续前进，1 表示右转，2 表示掉头，3 表示左转。 
6. 将当前方向更新为刚刚执行的绝对方向，因为平台旋转面向其运动方向。 
7. 将相关命令附加到输出序列并继续处理下一个输入字符。 

核心思想是，在每一步中，我们都将绝对方向表示为相对于当前航向的旋转，然后将航向更新为该方向。 状态演化完全由单个整数捕获。 

### 为什么它有效

 该算法保持了存储的方向始终等于最后执行的绝对方向的不变性。 因为每个相对命令都是以模 4 循环中下一个绝对方向与此存储方向之间的差值来计算的，所以它精确地编码了将一个航向转换为另一个航向所需的旋转。 由于四个方向的旋转在模 4 的加法下形成闭循环群，因此每个变换都被唯一地表示，并且跨步骤不会累积模糊性或漂移。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    mp = {
        'N': 0,
        'E': 1,
        'S': 2,
        'W': 3
    }

    rmp = {
        0: 'N',
        1: 'E',
        2: 'S',
        3: 'W'
    }

    cur = 0
    out = []

    for ch in s:
        nxt = mp[ch]
        diff = (nxt - cur) % 4
        out.append(rmp[diff])
        cur = nxt

    sys.stdout.write(''.join(out))

if __name__ == "__main__":
    solve()
```该解决方案依赖于维护单个变量`cur`，代表平台当前的绝对方向。 对于每个字符，我们将其转换为其数字编码并计算模差。 模运算统一处理前向环绕和负减法情况，因此不需要额外的条件逻辑。 

更新内容`cur = nxt`至关重要，因为它反映了执行每个动作后平台的物理旋转。 如果没有此更新，所有后续相对计算将错误地假定固定方向。

 ## 边缘情况

 一种边缘情况是方向在周期中向后跳跃，例如从北向西过渡。 用于输入`NW`，计算从 cur = 0 到 nxt = 3，产生 (3 - 0) % 4 = 3，这正确地映射到左转。 没有模处理的简单减法将产生 -1 并且无法映射到有效命令。 

另一种情况是重复旋转会累积方向变化。 用于输入`NESW`，当前方向在所有四种状态中演变。 算法正确更新`cur`在每个步骤中，每个差异都是相对于正确的帧计算的，从而防止漂移。 

最后一个微妙的情况是长的统一序列，例如`SSSSSS`。 由于每一步都会反复更新向南的方向，因此第一次移动后每个差异都为零，从而产生一致的前进命令。 这证实了当方向重复时状态更新是幂等的。
