 ## 解决方案
 ## 问题理解

 我们得到一行索引从 1 到 n 的钩子。 在进程开始之前，两个边界钩子 1 和 n 被认为已经使用。 之后，系统对剩余未使用的钩子重复执行确定性操作。 

在每一步中，算法都会扫描该线并将其分成未使用的钩子的最大连续段。 在这些段中，它选择最左边具有最大长度的段。 在该段内，它选择其中间位置，或者如果段长度为偶数则选择两个中间位置，并将这些钩子位置标记为已使用。 然后，在更新的一组未使用的钩子上重复该过程。 

关键问题是：对于每个查询钩子 p，我们必须确定使用 p 的步骤号。 

完整问题中的输入大小达到 n 和 q 达到 3·10^5。 重新扫描数组并重新计算每步段的简单模拟将跨 O(n) 个步骤重复遍历 O(n) 个位置，从而导致 O(n^2) 行为，这远远超出了可接受的限制。 当 q 很大时，即使每次查询 O(n log n) 也太慢。 

在考虑贪婪模拟的正确性时，出现了一个微妙的结构问题：段对称收缩，但该过程是由段的全局排序驱动的，而不是仅由局部递归驱动。 粗心的实现可能会在标记中心后错误地重新计算段，特别是当多个段存在相同长度时，因为稳定性取决于严格的从左到右的排序。 

天真的思维的一个具体失败模式是假设我们可以在类似 DFS 的递归中独立处理每个段，而不保留全局从左到右的顺序。 例如，分割一个段 [2, 9] 后，我们必须在所有段中以 FIFO 顺序处理左右部分，而不是首先递归地完全探索一侧。 此顺序对于正确的步长索引至关重要。 

## 方法

 暴力解决方案直接遵循以下语句：维护一个标记已使用钩子的数组，重复扫描所有索引以查找最大未使用段，选择最左边最长的段，计算其中间部分，并将其标记为已使用。 每次扫描的成本为 O(n)，并且有 O(n) 个步骤，每次完整模拟的总工作量为 O(n^2)。 这仅对于非常小的 n 是可接受的。 

关键的观察结果是该过程具有高度规则的递归结构。 每个选定的段始终分为两个较小的独立段，并且下一个操作始终作用于所有当前段中全局最左边的可用段。 这相当于处理队列中的段，其中每个段在处理后生成两个子段。 

一旦这样看，系统就变成了区间 [2, n − 1] 的完美平衡二叉分解树的广度优先遍历。 每个步骤处理一个段，然后将其左右子段排队。 这样就无需重复扫描整个阵列。 

在最终的优化中，我们没有模拟所有步骤，而是直接计算给定位置成为该分解树中特定深度的段中心的步骤。 每级递归将段大小减半，因此深度为 O(log n)。 我们可以从根段向下​​走到该位置，累积在到达该节点之前处理了多少段。

 ## 算法演练

 我们专注于计算单个位置 p 的步数。

1. 我们从初始段 [2, n − 1] 开始，它表示排除边界后所有可用的钩子。 该段处于级别 0，尚未处理任何段。 
2. 在任意线段[L,R]上，我们计算其中间位置mL和mR。 如果 p 位于该段中，则这些是在此步骤中将被删除的候选钩子。 
3. 如果 p 等于中间位置之一，我们立即确定 p 在当前步骤索引处被删除，该索引等于在此之前处理的段数加上该段在其级别中的位置。 然后我们停下来。 
4. 否则，我们决定分割的哪一侧包含 p。 如果 p 小于 mL，我们移动到左侧子段 [L, mL − 1]。 如果 p 大于 mR，我们移动到右侧子段 [mR + 1, R]。 
5. 每次我们深入一层，我们都会考虑到前一层处理的所有段。 每个级别 k 恰好包含 2^k 个段，因此我们在下降之前将这些计数累积到运行总数中。 
6. 我们还在其级别内跟踪当前段的索引。 向左移动使该索引加倍，向右移动则使该索引加倍并加一，因为隐式二叉树结构对应于段排序。 

### 为什么它有效

 第 k 层的每个段对应于由递归中点分裂形成的完全二叉树中的一个节点。 该过程以广度优先的顺序访问节点，这意味着级别 k 的所有节点都会在级别 k + 1 的任何节点之前处理。在级别内，排序是从左到右。 这保证了按完整级别加上级别内的位置对节点进行计数与处理任何段的步骤号完全匹配。 由于每个位置 p 恰好属于其路径上每个级别的一个节点，因此 p 成为中点的第一个级别唯一地确定其移除时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    queries = list(map(int, input().split()))
    
    # initial segment is [2, n-1]
    # if n <= 2, everything is already "boundary-like"
    
    def solve_one(p):
        L, R = 2, n - 1
        k = 0
        x = 0
        processed = 0
        
        while L <= R:
            mL = (L + R) // 2
            mR = (L + R + 1) // 2
            
            # if p is center at this level
            if p == mL or p == mR:
                return processed + x + 1
            
            # accumulate previous full levels
            processed += 1 << k
            
            # go deeper
            if p < mL:
                R = mL - 1
                x = x * 2
            else:
                L = mR + 1
                x = x * 2 + 1
            
            k += 1
        
        return processed

    out = []
    for p in queries:
        out.append(str(solve_one(p)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现反映了概念性的二元分解树。 区间 [2, n − 1] 在其中点处重复分割。 processed 变量跟踪所有先前级别中存在多少个节点，每个级别始终是 2 的幂，因此我们在每个深度添加 2^k。 

变量 x 对当前段在其级别内的索引进行编码，其构建与二进制堆索引完全相同。 向左乘以 2，向右乘以 2 并加 1，保留从左到右的顺序。 

当 p 恰好是中点位置之一时，终止条件发生，这直接给出了 BFS 排序中的步数。 

必须注意差一处理：返回值必须包括先前的完整级别和当前级别内的偏移量。 另一个微妙点是确保中点计算正确分割为偶数长度，因为存在两个中心元素并且都被视为移除点。 

## 工作示例

 考虑 n = 9，因此初始段为 [2, 8]。 查询 p = 4。 

| 步骤| 左 | 右 | 细分 | 毫升| MR | 加工| x| 行动|
 | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 8 | [2,8]| 5 | 4 | 0 | 0 | p < mL，向左|
 | 1 | 2 | 4 | [2,4]| 3 | 3 | 1 | 0 | p == mL，停止|

 在步骤 1，p 成为中点，因此它在时间 1 被移除。 

现在考虑相同设置中的 p = 7。 

| 步骤| 左 | 右 | 细分 | 毫升| MR | 加工| x| 行动|
 | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 8 | [2,8]| 5 | 4 | 0 | 0 | p > mR，向右走|
 | 1 | 5 | 8 | [5,8]| 6 | 7 | 1 | 1 | p == mR，停止|

 在这里我们看到右移会增加二进制索引，因此包含 p 的段是第 1 层的第二个节点，当 p 成为中点时立即将其删除。 

这些痕迹证实该算法遵循一致的 BFS 分段分解顺序，并且每个位置都分配有唯一的发现时间。

 ## 边缘情况

 当间隔长度均匀时会出现临界边缘情况，产生两个中间位置。 对于像 [2, 7] 这样的线段，中点是 4 和 5。等于其中任何一个的位置必须被视为立即删除。 该算法明确地检查两者，确保中心选择没有歧义。 

当重复分割后 p 恰好位于子段的边界时，会出现另一种边缘情况。 由于边界 1 和 n 已预先标记为已使用，因此递归永远不会包含它们，因此任何计算的子段必须始终保持在 [2, n − 1] 内。 该算法通过在向左或向右移动时严格缩小间隔来强制执行此操作，以防止活动区域之外的无效访问。 

最后一个微妙的情况是当 n 非常小时，例如 n ≤ 3，其中初始段 [2, n − 1] 可能为空或单个元素。 在这种情况下，不会发生进一步的拆分，并且查询应立即或简单地解析，具体取决于 p 是否已被视为已使用。
