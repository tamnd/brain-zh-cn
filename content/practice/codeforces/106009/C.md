 ## 解决方案
 ## 问题理解

 我们有一个用网格表示的地雷。 有些牢房里含有金子，有些牢房被石头堵住了，有些牢房已经空了。 斯米洛可以选择一个空单元格并在那里放置炸弹。 炸弹会清除所选单元格周围的一个半径为半径的正方形`k`在切比雪夫距离中。 恰好位于该正方形边界上的黄金被收集，而严格位于该正方形内部的黄金则被丢失。 

目标是选择能够最大限度地收集黄金的爆炸。 困难在于，爆炸后，许多单元格会变空，因此以后的爆炸可能会被放置在新的位置。 

网格尺寸和`k`可以大到 500，但所有测试用例的单元总数是有限的。 这排除了模拟每种可能的爆炸序列的解决方案。 直接搜索空单元格的所有子集是不可能的。 我们需要一种方法来有效地评估所有有用的第一步，并证明可以隐式处理其余的动作。 

一些边缘情况很容易被忽略。 什么时候`k = 1`，炸弹只会影响周围的八个单元格和中心。 一个常见的错误是将整个 3 x 3 的正方形视为丢失的黄金，但中心并不是边界的一部分。 例如：```
1
2 2 1
g.
.g
```唯一的空单元格是右上角。 炸弹会收集对角相邻的黄金，只有当另一颗黄金位于方块内时才会摧毁它。 正确答案是`1`， 不是`0`。 

另一个边缘情况是最佳策略需要多枚炸弹。 只寻找最好的单一爆炸是失败的。 例如：```
1
3 4 2
.g..
g..#
g##.
```一枚炸弹无法收集所有黄金，但两枚炸弹可以。 答案是`3`。 仅计算最佳初始爆炸的解决方案会低估结果。 

第三种微妙的情况是当爆炸到达网格之外时。 爆炸方块的边界仍然存在于矿井之外，因此只有在计算网格中实际存在的单元格时才必须剪裁该方块。 例如：```
1
1 3 5
g.g
```唯一的空单元格位于中间。 爆炸比网格大得多，但两个金格都在正方形的边界上，所以答案是`2`。 

## 方法

 蛮力方法是尝试所有可能的第一个炸弹位置，然后模拟所有未来的选择。 它是正确的，因为它准确地探索了 Smilo 可以采取的可能行动。 问题是可能的序列的数量。 由于总共有 250000 个单元，即使只考虑位置对也已经太昂贵了，并且对序列的全面搜索远远超出了限制。 

关键的观察是，在第一次爆炸之后，任何后续爆炸仅对收集尚未被摧毁的黄金有用。 如果后来的炸弹可以收集黄金，那么它的中心必须位于先前爆炸后可用的区域内。 重要的是，第一次爆炸是唯一可以摧毁在任何清理发生之前仍然存在的黄金的爆炸。 

对于选定的第一个炸弹中心，唯一可以永久丢失而不被收集的金币是严格位于爆炸方块内的金币。 其他一切都可以通过第一颗炸弹或安排稍后的爆炸来收集。 贪婪的想法是选择第一个摧毁最少数量黄金的炸弹。 最终的答案是黄金总量减去最小损失。 

为了检查每个可能的第一个中心，我们需要知道 size 的内部正方形内有多少金子`(2k - 1) x (2k - 1)`。 二维前缀和让我们可以在常数时间内查询它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 太大而无法实际定义| O(纳米) | 太慢了 |
 | 前缀和贪婪 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 计算黄金单元的总数，并构建一个二维前缀和数组，其中每个条目存储矩形中从左上角到该位置的黄金单元的数量。 这使我们能够立即计算任何矩形中的黄金。 
2. 将每个空单元格视为可能的第一个爆炸中心。 这是有效的，因为第一次爆炸是决定哪些黄金在未来的炸弹到达之前消失的唯一决定。 
3. 对于中心`(i, j)`，计算严格位于爆炸内部的内部正方形。 它的行范围是从`i - k + 1`到`i + k - 1`，其列范围是从`j - k + 1`到`j + k - 1`。 坐标被剪切到网格，因为矿井不包含其外部的单元格。 
4. 使用前缀和来计算该内部方块内销毁了多少黄金。 在所有可能的首次爆炸中保持最小的此类值。 
5.从金币总量中减去最小损失金币。 剩余金币是可以收集的最大数量。 

为什么它有效：

 第一次爆炸将黄金分成两组。 爆炸边界上的金子可以立即收集，爆炸外的金子仍然可供后续操作。 严格在爆炸范围内的黄金永远无法收集，因为它会消失。 第一次爆炸后，未来炸弹所需的细胞已被清除，因此在第一次爆炸中幸存下来的任何黄金都可以通过选择适当的后续爆炸来获得。 因此，最大化收集的黄金与最小化第一次爆炸损失的黄金相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[0] * (m + 1) for _ in range(n + 1)]
    total = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'g':
                total += 1
            pref[i + 1][j + 1] = (
                pref[i][j + 1]
                + pref[i + 1][j]
                - pref[i][j]
                + (grid[i][j] == 'g')
            )

    def get(x1, y1, x2, y2):
        if x1 > x2 or y1 > y2:
            return 0
        return (
            pref[x2 + 1][y2 + 1]
            - pref[x1][y2 + 1]
            - pref[x2 + 1][y1]
            + pref[x1][y1]
        )

    lost = total

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '.':
                x1 = max(0, i - k + 1)
                y1 = max(0, j - k + 1)
                x2 = min(n - 1, i + k - 1)
                y2 = min(m - 1, j + k - 1)

                lost = min(lost, get(x1, y1, x2, y2))

    print(total - lost)

def main():
    t = int(input())
    for _ in range(t):
        solve()

main()
```前缀和结构存储黄金计数，而不是细胞类型。 这使得后面的查询变得简单，因为每个矩形查询只需要对四个前缀值进行算术。 

辅助函数`get`返回矩形中黄金单元格的数量。 在调用之前，边界已经被剪裁，这避免了负索引和一个错误。 

内部正方形使用`k - 1`作为它的半径，因为细胞恰好`k`远离中心的位于边界并被收集。 只有严格接近的单元格才会丢失。 

最后一个循环会尝试所有可能的第一个炸弹位置。 由于答案仅取决于这些位置中被破坏的最少黄金，因此无需模拟后来的爆炸。

 ## 边缘情况

 对于`k = 1`在这种情况下，该算法使用零内半径。 矩形查询变成围绕中心的单个单元格查询，因此只有中心单元格会被视为丢失。 由于炸弹中心是空的，因此没有黄金被算作被摧毁。 这可以正确处理最小爆炸尺寸。 

对于需要多个炸弹的策略，该算法不会显式模拟这些炸弹。 相反，它会发现损失最少黄金的第一次爆炸。 该内部区域之外的任何黄金都会在第一步中幸存下来，并可以在以后收集。 这就是为什么即使一次爆炸无法得到答案，第三个样本也能得到正确处理的原因。 

当爆炸大于棋盘时，计算出的内部方块将被剪切到实际的地雷边界。 正方形的外部不含金，因此忽略它不会改变被破坏细胞的数量。
