 ## 问题理解

 我们得到两个长度相等的数组，对于每个索引，我们可以保持该对不变，也可以交换该位置的两个值。 执行任意次数的此类交换后，每个索引仍然为第一个数组贡献一个值，为第二个数组贡献一个值，但我们可以自由决定每个位置的两个值流向哪一侧。 

对于任何最终数组，我们将其分数定义为其包含的不同值的数量。 目标是以最大化两个数组中不同计数总和的方式将每个索引的两个值分配给两个数组，然后输出最大值和实现该最大值的配置。 

关键约束是 n 最大为 100000，值的范围约为 2n。 这立即排除了任何尝试所有 2^n 交换配置甚至任何 n 中的二次方的解决方案。 该解决方案必须接近线性或线性算数，因为大约 10^8 次操作是一秒内的实际上限。 

当一个值在两个数组中多次出现时，就会出现微妙的边缘情况。 例如，如果一个值出现多次，粗心的贪婪交换很容易“浪费”出现次数，因为它会在同一个数组中放置不必要的重复项，从而减少总的不同计数。 当一个值仅出现两次时，会发生另一种极端情况，一次在每个数组中的同一索引处。 如果您始终保持交换在本地对齐而没有全局规划，则最终可能会在一个数组中复制一个值，并在另一个数组中完全丢失该值，这是次优的。 

## 方法

 强力方法将独立处理每个索引并尝试两种选择，要么保留 (a[i], b[i]) 要么交换它们。 这导致 2^n 种可能性。 即使我们在 O(n) 中评估每个配置，总工作量也变为 O(n·2^n)，即使 n 约为 30，这也是完全不可行的。 

如果我们不再考虑数组，而是考虑值的出现，问题的结构就会变得更加清晰。 每个值都会对 a 和 b 的不同计数产生影响，具体取决于它是否在该数组中至少出现一次。 因此，唯一重要的是我们是否可以确保每个值的至少一个副本位于至少一个数组中，同时还要尽量避免浪费一个值可能同时出现在两个数组中的机会。 

关键的观察是，每个索引都让我们可以选择在哪里“放置”小边的两个端点，并且我们希望分布值，以便每个值出现在尽可能多的数组中，而不会阻塞其他值。 这自然是一种匹配式赋值：每个值都需要 a 或 b 中至少有一个代表，而索引是唯一发生赋值决策的地方。 

我们不是贪婪的局部决策，而是使用频率结构间接处理值，并确保每当一个值出现多次时，除非必要，否则我们会避免将两个副本强制放入同一个数组中。 一种简洁的方法是将每个索引视为决策点并分配值，同时跟踪每个值在每个数组中已被“保护”的次数。 我们总是尽力保持多样性平衡，因为一旦一个值出现在两个数组中，它就会贡献两倍，但一旦它从一个数组中完全丢失，就无法恢复。 

这将问题简化为具有频率簿记和仔细分配的线性扫描，而不是任何组合搜索。

 ## 算法演练

1. 为任一数组中出现的所有值构建频率信息。 这让我们知道哪些价值丰富，哪些价值稀缺，这一点至关重要，因为稀有价值必须小心保存。 
2. 对于每个索引，确定交换是否有助于增加两个数组中不同值的数量。 指导原则是除非强制，否则避免将频繁出现的值的两个副本放入同一个数组中。 
3. 维护一个记录，记录每个值是否已经出现在当前版本的数组a和数组b中。 这可以防止重复计算错误，并帮助我们识别何时交换实际上增加了清晰度。 
4. 处理索引 i 时，尝试将 a[i] 分配给尚不存在的数组，对于 b[i] 也是如此。 如果两种选择都可行，请选择增加包含新的不同元素的数组数量的分配。 
5. 如果两个分配发生冲突，意味着这两个值最终都会在各自的数组中重复已经看到的元素，则更喜欢保留未来灵活性的配置，通常是将更“受约束”的值保留在数组中已经出现的位置。 
6. 根据每个索引处选择的方向构造最终数组，并直接计算不同元素的数量。 

它的工作原理与打包不变量有关：在每一步中，我们都认为每个值要么已经在给定过去决策的最佳可能数量的数组中表示，要么我们仍然可以选择稍后将其放入新的数组中。 由于每个索引仅使用一次，并且决策仅影响局部布局，因此我们永远不会失去以后实现更好分布的能力，并且贪婪的选择永远不会阻止严格更好的全局结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    used_a = set()
    used_b = set()

    res_a = [0] * n
    res_b = [0] * n

    for i in range(n):
        x, y = a[i], b[i]

        # try to place x in a and y in b if possible
        gain1 = (x not in used_a) + (y not in used_b)

        # swapped version
        gain2 = (y not in used_a) + (x not in used_b)

        if gain2 > gain1:
            x, y = y, x

        res_a[i] = x
        res_b[i] = y

        used_a.add(x)
        used_b.add(y)

    print(len(set(res_a)) + len(set(res_b)))
    print(*res_a)
    print(*res_b)

if __name__ == "__main__":
    solve()
```该代码独立处理每个索引，同时维护两个集合来跟踪哪些值已放置在每个结果数组中。 每个位置的决策是保留或交换之间的局部比较，基于哪个选择立即引入更多新的不同元素。 

一个微妙的点是贪心比较仅使用增量增益。 这是可行的，因为每个索引对不同计数的贡献对于每个数组都是二进制的，因此一旦增益可用，延迟增益就没有任何好处。

 ## 边缘情况

 对于重复的相同对（x，x），算法始终保持它们不变，因为交换不会改变增益。 这可以避免人为地夸大一个数组中的不同计数，同时使另一个数组挨饿。 

对于完全对称的输入，其中所有 i 的 a[i] = b[i]，每个操作都变得无关紧要。 两个数组的集合同步增长，最终答案只是输入中不同值数量的两倍。 

对于一个数组已经包含许多重复项而另一个数组不同的情况，贪婪增益比较可确保仅当它们实际将新元素引入其中一个集合时才执行交换，从而防止可能减少多样性的不必要的中断。
