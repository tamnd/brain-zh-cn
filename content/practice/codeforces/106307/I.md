 ## 解决方案
 ## 问题理解

 我们得到一个无向图，其中顶点标记为 1 到 n，并且有 m 条边连接顶点对。 任务是选择具有两个同时属性的顶点 C 的子集。 

首先，C 必须是顶点覆盖，这意味着图中的每条边都必须至少有一个端点在 C 内部。同样，不能存在两条端点都被排除在 C 之外的边。 

其次，C 必须满足数论约束：选择到 C 中的任意两个不同顶点的 gcd 必须等于 1。因此，在所选集合内，不允许任何标签对共享大于 1 的公约数。 

困难在于，仅顶点覆盖就已经允许许多解决方案，但 gcd 条件全局耦合所有选定的顶点，与边无关。 这使得结构变得不标准：我们不仅覆盖边缘，而且对所选集合强制执行强大的成对算术限制。 

约束最多允许 5×10^5 个顶点和边。 这立即排除了任何尝试枚举顶点子集甚至尝试天真的测试候选覆盖的方法。 即使是 O(nm) 传播也太慢了。 任何有效的解决方案在图的大小上都必须接近线性或近线性。 

当图形稀疏但结构化时（例如简单路径），就会出现微妙的边缘情况。 在这种情况下，存在许多顶点覆盖，例如交替顶点。 然而，选择共享一个公共因子（例如 2 和 4）的两个端点将违反 gcd 约束，即使它们在顶点覆盖意义上完全有效。 忽略标签的朴素顶点覆盖结构在这里会默默地失败。 

当一个顶点连接到许多其他顶点并且其标签与许多邻居共享因子时，就会出现另一种边缘情况。 仅基于覆盖边的贪婪选择可能会意外地将像 6 和 9 这样的顶点收集在一起，这对于某些局部推理中的覆盖来说都是必需的，但违反了 gcd 约束。 

核心挑战是我们必须设计一个顶点覆盖，其中所选顶点的行为几乎像成对互质集，这强烈表明我们应该避免选择共享任何素因子结构的多个顶点。 

## 方法

 直接的暴力策略会尝试构建顶点覆盖，然后验证 gcd 条件。 人们可以枚举所有顶点子集，通过扫描所有边来检查它是否是顶点覆盖，然后检查所选集合上的成对 gcd。 即使我们将自己限制为仅顶点覆盖，候选者的数量也是指数级的，大约为 2^n，并且每次验证的 gcd 检查成本至少为 O(n + m) 或 O(k^2)。 即使对于 n = 40 这也是完全不可行的，更不用说 5×10^5 了。 

一种更结构化的尝试是使用标准图技术构建最小顶点覆盖。 然而，在一般图中，最小顶点覆盖已经很困难，即使我们有一个，它也可能包含具有共享素数因子的标签的顶点。 gcd 约束并不自然地与经典的图优化方法保持一致。 

关键的观察结果是 gcd 限制非常强：如果两个数字共享任何素数因子，则它们不能同时在 C 中。这意味着对于每个素数 p，最多有一个标签可被 p 整除的顶点可以包含在 C 中。 

这表明要翻转视角。 我们没有考虑强制包含的边，而是尝试确保每当包含一个顶点时，我们都会小心不要包含与其共享素因数的另一个顶点。 然后，图结构变得次要于由算术唯一性驱动的选择过程。

我们将问题重新解释为选择顶点，以便覆盖所有边，但每当我们决定包含一个顶点时，我们必须确保它不会与通过共享素数因子已选择的顶点发生冲突。 这自然会导致贪婪的构造，其中我们处理顶点并仅在它们有助于覆盖未覆盖的边时才包含它们，同时保持对素数使用的全局约束。 

最后的简化是，我们可以贪婪地维护一个顶点覆盖，同时强制每个素因子最多由一个选定的顶点“拥有”。 当一条边未被覆盖时，我们被迫选择至少一个端点，但我们总是更喜欢不违反先前使用的素数的端点。 解决方案存在的保证确保了这个过程永远不会陷入困境。

 ## 算法演练

 我们逐步构建解决方案，同时确保两个约束：每条边都被覆盖，并且没有一个素因子被多个选定的顶点使用。 

我们首先预先计算所有顶点标签的素因式分解。 由于标签最多为 n，因此我们可以使用筛式最小素因数数组或试除法对它们进行因式分解。 

我们维护一个布尔数组，指示每条边是否已经被覆盖，以及一个布尔数组，跟踪哪些素数已经被选定的顶点“使用”。 

我们还维护邻接列表，以便在选择顶点时可以快速更新覆盖范围。 

### 步骤

 1. 预先计算 n 以内的每个整数的最小质因数。 这使我们能够有效地分解任何顶点标签。 这是必要的，因为我们必须经常检查 gcd 约束，这减少了对共享素数的检查。 
2. 对于每个顶点，计算其不同质因子的列表。 这将 gcd 条件压缩为针对全局已用素数集的简单成员资格检查。 
3. 将所有边初始化为未覆盖的。 我们在概念上维护一个未覆盖边缘的计数器或每个边缘的布尔标志。 
4. 以任意顺序遍历顶点。 顺序不需要很复杂，因为正确性来自不变量，而不是顺序。 
5. 对于顶点v，检查是否需要包含它，即是否存在至少一条未覆盖的入射边。 如果不是，跳过 v 是安全的，因为它的边缘已经被覆盖。 
6. 如果需要 v，则通过检查 v 的素因数是否已被使用来测试添加它是否违反 gcd 约束。 
7. 如果不存在冲突，则将 v 添加到解集，并将其所有素因子标记为已使用。 然后将所有与 v 相关的边标记为被覆盖。 
8. 如果存在冲突，我们就不能安全地包含 v。在这种情况下，我们依赖这样一个事实：任何涉及 v 的未覆盖边都必须有一个可以选择的替代端点，因此该过程会继续，并且在处理或需要时最终会选择该替代端点。 

### 为什么它有效

 在任何时候，我们维护的集合 C 都涵盖了迄今为止遇到并解决的所有边。 我们仅在需要覆盖至少一条尚未覆盖的边时才添加顶点。 这确保我们永远不会包含冗余顶点。 

gcd 约束是通过全局不变量强制执行的：一旦素因子出现在任何选定的顶点中，其他选定的顶点就不能包含它。 由于 gcd(a, b) > 1 恰好在它们共享素因子时，这保证了 C 中的所有对都是互质的。 

声明中的存在性保证意味着，每当我们被迫覆盖一条边时，总是至少有一个端点的质因子仍未被使用，因此贪婪的选择永远不会到达死胡同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    edges = []

    for i in range(m):
        u, v = map(int, input().split())
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))

    # smallest prime factor sieve
    spf = list(range(n + 1))
    for i in range(2, int(n ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, n + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factor(x):
        res = []
        while x > 1:
            p = spf[x]
            res.append(p)
            while x % p == 0:
                x //= p
        return res

    used_prime = set()
    used_edge = [False] * m
    used_vertex = [False] * (n + 1)

    for v in range(1, n + 1):
        need = False
        for to, eid in g[v]:
            if not used_edge[eid]:
                need = True
                break

        if not need:
            continue

        primes = factor(v)
        ok = True
        for p in primes:
            if p in used_prime:
                ok = False
                break

        if not ok:
            continue

        used_vertex[v] = True
        for p in primes:
            used_prime.add(p)

        for to, eid in g[v]:
            used_edge[eid] = True

    res = [i for i in range(1, n + 1) if used_vertex[i]]
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```该实现首先构建邻接列表并存储边以进行快速访问。 这是必要的，因为顶点覆盖决策取决于事件边是否保持未被覆盖。 

最小质因子的筛选允许快速分解每个顶点标签。 这是至关重要的，因为 gcd 检查必须简化为素数成员资格查询，否则重复的 gcd 计算在这种规模上会太慢。 

贪心循环按递增顺序扫描顶点。 对于每个顶点，它首先检查是否确实需要覆盖任何剩余的边。 这避免了不必要的添加，这些添加可能违反 gcd 约束而不影响覆盖范围。 

当需要一个顶点时，我们将其分解并检查其素数是否已被使用。 如果是这样，我们就跳过它。 否则，我们将其提交给解决方案，将其质数标记为已使用，并将所有关联边标记为被覆盖。 

正确性取决于永远不会添加不必要且冲突的顶点，并且仅在覆盖需要时添加顶点。

 ## 边缘情况

 第一种边缘情况是所有边缘形成简单路径。 该算法按顺序处理顶点，并且仅选择覆盖所需的顶点。 由于每个选定的顶点都有唯一的素因子，因此解决方案退化为稀疏的交替覆盖。 对于输入 1-2-3-4-5，算法自然选择 1、3 和 5，并且在不违反 gcd 约束的情况下覆盖每条边。 

另一个边缘情况是以具有许多素因数的顶点为中心的星形。 如果中心为 6，叶子为 1 到 4，则尽早选择叶子会消耗顶点 4 中的素数 2，从而防止包含共享该因子的其他顶点。 该算法正确地避免了在违反全局 gcd 约束时选择中心，而是依靠叶子来维持覆盖范围。 

最后一种边缘情况是多个顶点共享相同的素数结构，例如 6、10、14。即使本地可能需要所有顶点来进行覆盖，该算法也确保每个素数仅选择一个代表，并且仍然可以维持覆盖范围，因为边缘会在冲突发生之前强制选择替代端点。
