 ## 解决方案
 ## 问题理解

 我们得到一个写成字符串的数字，可能非常大，并且要求我们确定它的值是否出现在由起始值 f0 = 1 和 f1 = 1 定义的斐波那契序列中，每一项都通过将前两项相加而形成。 

关键的困难在于输入数字 k 最多可以有 100000 位数字，这立即排除了任何将其转换为内置整数类型的方法。 即使 64 位整数也会在此范围之前溢出，因此必须完全使用字符串算术或根本避免将 k 解析为数字类型来解决该问题。 

简单的理解是生成斐波那契数，直到我们达到或超过 k，然后进行比较。 这个想法在结构上是正确的，但只有当我们能够有效地比较大整数时才有效。 

当 k 具有前导零时，会出现一种微妙的边缘情况。 例如，“0001”应被视为“1”，并且必须与斐波那契值 1 匹配。如果 k 非常大并且远远超出内存中适合的任何斐波那契数，则会出现另一个问题，如果没有大整数处理，单纯的数值增长将变得不可能。 

约束驱动的主要见解是斐波那契数呈指数增长，并且其位数大致呈线性增长。 这保证了即使 k 可能有 100000 位，但我们实际需要生成的斐波那契数最多只有几十万的数量级，并且实际上由于指数增长而要小得多。 

## 方法

 蛮力的想法很简单：从 1, 1 开始生成斐波那契数，并重复计算下一个值，直到我们匹配 k 或超过它。 正确性是立竿见影的，因为斐波那契数列是按顺序生成的，而且我们从不跳过值。 

问题是斐波那契数很快就会变得巨大。 第 100000 位斐波那契数是一个天文数字，用本机整数存储或计算它是不可能的。 即使对于大整数，重复添加两个大数（每个数可能有 100000 位长）也会导致每步的数字长度呈二次方行为。 如果生成 M 个斐波那契数列，每个斐波那契数列最多为 D 位，则总成本约为 O(M·D)，在上限下速度太慢。 

关键的观察是，除了大数字的比较和加法之外，我们不需要任何东西。 这使我们能够将斐波那契数表示为字符串并实现按数字加法。 由于序列呈指数增长，迭代次数 M 仍然是可管理的，并且基于字符串的加法就足够了。 

优化不是改变递归，而是使用字符串运算，并在字典长度比较中一旦生成的斐波那契数超过 k 就提前停止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（朴素数字）| O(F·D²) | O(F·D²) | O(D) | 太慢了|
 | 最优（字符串模拟）| O(F·D) | O(D) | 已接受 |

 这里F是直到超过k为止生成的斐波那契项的数量，D是位数。 

## 算法演练

 我们将斐波那契数模拟为字符串。

1. 通过删除前导零来标准化输入字符串 k，因为数字比较仅取决于值。 如果结果字符串为空，则将其视为“0”。 这确保了比较与斐波那契表示法一致。 
2、初始化两个字符串a=“1”和b=“1”，代表连续的斐波那契数。 
3. 比较a 和k。 如果相等，我们可以立即返回 YES，因为第一个斐波那契项匹配。 
4. 使用字符串加法重复生成下一个斐波那契数 c = a + b，其中加法是从右到左带进位逐位进行的。 
5. 计算完 c 后，更新 a = b 和 b = c，保持斐波那契数列不变。 
6. 每次更新后，将 b 与 k 进行比较。 如果相等，则返回 YES。 
7. 如果 b 的数字长度大于 k，或者字典比较显示 b > k，我们可以停止并返回 NO，因为所有进一步的斐波那契数只会变得更大。 

关键操作是字符串比较。 长度比较占主导地位：如果 len(b) > len(k)，我们已经知道 b > k。 如果长度相等，则字典比较对应于数字比较，因为两个字符串都表示不带前导零的非负整数。 

### 为什么它有效

 在每一步中，我们都保持 a 和 b 是按正确顺序连续的斐波那契数这一不变量。 斐波那契数列在初始项之后严格递增，因此一旦 b 超过 k，未来的项就无法与 k 匹配。 由于我们在超调之前检查每一步的相等性，因此我们保证正确性而不会错过有效的匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def strip(s: str) -> str:
    i = 0
    while i < len(s) and s[i] == '0':
        i += 1
    return s[i:] if i < len(s) else "0"

def add_strings(x: str, y: str) -> str:
    i, j = len(x) - 1, len(y) - 1
    carry = 0
    res = []

    while i >= 0 or j >= 0 or carry:
        s = carry
        if i >= 0:
            s += ord(x[i]) - 48
            i -= 1
        if j >= 0:
            s += ord(y[j]) - 48
            j -= 1
        res.append(chr((s % 10) + 48))
        carry = s // 10

    return ''.join(reversed(res))

def greater(x: str, y: str) -> bool:
    x = strip(x)
    y = strip(y)
    if len(x) != len(y):
        return len(x) > len(y)
    return x > y

def main():
    n = int(input())
    k = strip(input().strip())

    a, b = "1", "1"

    if k == "1":
        print("YES")
        return

    while True:
        c = add_strings(a, b)
        a, b = b, c

        if b == k:
            print("YES")
            return

        if greater(b, k):
            print("NO")
            return

if __name__ == "__main__":
    main()
```该实现始终将斐波那契数保留为字符串。 这`add_strings`函数执行带进位的按数字加法，这是标准的大整数结构。 这`strip`函数确保我们避免由于前导零而导致的不匹配。 

比较函数首先检查长度，这是大数的主要比较因素。 只有当长度匹配时，我们才会回退到字典顺序比较。 

循环故意是无限的，因为通过匹配 k 或超过 k 来保证终止。

 ## 边缘情况

 ### 前导零

 输入：

 k =“0001”

 剥离后，k变为“1”。 该算法立即匹配第一个斐波那契数。 如果没有标准化，字符串比较将错误地失败，因为“1”！=“0001”。 

### 非常小的 k

 输入：

 k =“2”

 序列进行 1、1、2。算法会检查每个步骤并正确识别第三项的匹配项。 在达到该值之前不会发生超调。 

### 大非斐波那契数

 输入：

 k =“100000000000000000000”

 生成的斐波那契数列很快就超过了这个数量级。 一旦 b 的数字长度或值超过 k，算法立即停止，确保不会继续进行不必要的计算。
