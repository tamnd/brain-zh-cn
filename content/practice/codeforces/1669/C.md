 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，允许我们重复应用两个全局操作。 一个操作递增奇数位置的每个元素，另一个操作递增偶数位置的每个元素。 每个操作都会向固定的索引子集加 1，并且我们可以应用任一操作任意次。 

任务是确定我们是否可以转换数组，以使所有元素最终具有相同的奇偶校验，这意味着在某些操作序列之后每个值要么是偶数，要么是奇数。 

关键的结构约束是每个测试用例的输入大小较小，最多 50 个元素。 这立即排除了除了每个测试用例的线性或恒定工作之外的任何优化需求。 即使对所有状态进行二次或三次模拟也是可以接受的，但这是不必要的。 

一个天真的陷阱是认为我们可以独立地自由控制每个元素。 这是不正确的，因为每个操作同时影响一半的数组。 例如，如果我们尝试修复单个不匹配的元素，我们不可避免地也会修改同一索引奇偶校验类的所有其他元素。 

另一个微妙的失败案例是假设每个元素的奇偶校验可以通过选择足够的操作来独立控制。 例如，如果我们只查看一个位置并决定它需要多少增量，我们可能会忽略相同的增量适用于同一奇偶校验类的所有位置。 

一个暴露混乱的小例子是一个像这样的数组`[1, 2]`。 人们可能会尝试独立修复两者，但任何操作都会同时更改一个奇偶校验类的两个位置，因此决策是耦合的。 

## 方法

 一个蛮力的想法是模拟对奇数索引和偶数索引的所有可能数量的操作。 如果我们应用奇数索引运算的 x 运算和偶数索引运算的 y 运算，则每个元素的最终值将完全确定。 我们可以尝试所有的配对`(x, y)`并检查所有最终值是否具有相同的奇偶性。 

然而，即使 n 很小，x 和 y 也是无界的。 除非我们限制搜索，否则尝试所有可能性是无限的。 观察奇偶校验行为可以立即解决这个问题。 

每个操作都会翻转其目标索引类中每个元素的奇偶校验。 这意味着唯一重要的是我们应用奇数索引操作的次数是偶数还是奇数，对于偶数索引操作也是如此。 应用两次可以取消其奇偶效应。 

因此，每个索引类别恰好贡献一个二元自由度：无论我们是否翻转其奇偶性。 这将问题简化为检查我们是否可以分配两个二进制翻转（奇数类翻转和偶数类翻转），以便所有生成的奇偶校验都匹配。 

现在结构变得简单了。 我们只需要测试是否可以使用这两个全局切换使所有值变为偶数或所有值变为奇数。 这仅取决于索引之间的初始奇偶校验模式是否以允许对齐的方式保持一致。 

一个直接的简化是，在每个索引奇偶校验组中，我们可以翻转所有它们，也可以不翻转它们。 因此，在选择翻转后，两个组都必须对齐到一个目标奇偶校验。 

这简化为检查我们是否可以同时使两个组与全偶数或全奇数一致，这在至少可以匹配这些全局目标之一时是可能的。

 ## 算法演练

 我们将数组分为两个隐式组：奇数索引处的元素和偶数索引处的元素。 

1. 计算所有元素是否已经具有相同的奇偶校验。 如果是，则答案立即为“是”，因为不需要任何操作。 这可以处理简单的定点情况。 
2. 分别记录奇数索引和偶数索引处的元素的奇偶性。 重要的不是他们的价值观，而是每个群体内部是统一的还是混合的。 
3. 观察到应用奇数索引操作会翻转奇数组中的每个元素，应用偶数索引操作会翻转偶数组中的每个元素。 因此，每个组都有一个独立的二元选择：翻转或不翻转。 
4. 检查是否可以选择翻转使变换后所有元素都变为偶数，以及是否可以分别选择翻转使所有元素都变为奇数。 如果其中任何一个可以实现，那么答案是肯定的。 
5. 仅当由于两组之间的均等结构不一致而无法实现两个全球目标时，才得出“否”的结论。 

### 为什么它有效

 每个操作都会对一个索引类提供类似全局 XOR 的切换。 由于奇偶校验仅取决于模 2 的值，因此重复操作会分解为每个类的二元选择。 这意味着整个变换空间只有四种状态：不翻转、仅翻转奇数、仅翻转偶数或两者都翻转。 如果这些状态都不能在阵列中产生统一的奇偶校验，则任何操作序列都不能产生一致奇偶校验，因为任何更长的序列都会减少到模 2 的这四种情况之一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # check parity groups
        odd = [a[i] % 2 for i in range(0, n, 2)]
        even = [a[i] % 2 for i in range(1, n, 2)]
        
        # if already uniform
        if len(set(a[i] % 2 for i in range(n))) == 1:
            out.append("YES")
            continue
        
        # try target all-even or all-odd
        def can(target):
            # we choose flip_x, flip_y in {0,1}
            # odd group becomes (odd_parity XOR flip_x)
            # even group becomes (even_parity XOR flip_y)
            # all must equal target
            
            # odd group consistency
            ok1 = all((p ^ 0) == target or (p ^ 1) == target for p in odd)
            # even group consistency
            ok2 = all((p ^ 0) == target or (p ^ 1) == target for p in even)
            return ok1 and ok2
        
        if can(0) or can(1):
            out.append("YES")
        else:
            out.append("NO")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接编码了每个索引类可以独立翻转或不翻转的想法。 帮手`can(target)`检查每个组是否可以统一为选定的奇偶校验。 使用 XOR 推理是因为加 1 会翻转奇偶校验。 

一个微妙的点是我们不会模拟超出奇偶校验的实际值。 任何跟踪完整整数的尝试都是不必要的，因为只有均匀性才重要。

 ## 边缘情况

 一个关键的边缘情况是阵列的奇偶校验已经一致。 例如`[2, 4, 6]`。 该算法立即检测到单个奇偶校验类并返回“是”，而无需探索转换。 

另一种边缘情况是一个索引组内部不一致，例如`[1, 2, 1, 3]`。 偶指数组混合了奇偶性，这意味着翻转的组合不能使其统一。 在这种情况下，算法正确地拒绝了两个目标奇偶校验，导致“否”。 

最终的边缘情况是最小尺寸`n = 2`，其中两个元素属于不同的组。 即使在这里，每个组都是独立可控的，因此可行性仅取决于是否存在一致的目标，算法通过相同的奇偶校验逻辑正确评估该目标。
