 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们“打开”各个元素中的位。 每个操作都会选择一个元素并将一个先前为零的位设置为一。 我们最多可能会这样做`k`遍及整个阵列的次数。 

应用这些位插入后，我们对所有数组元素进行按位与计算。 目标是最大化最终的 AND 值。 

关键的困难在于 AND 非常严格：只有当每个元素都包含它时，它才会对最终答案做出贡献。 这意味着，即使有一个元素丢失了一位，该位也完全不会出现在结果中。 因此，任何添加位的操作只有在最终出现在每个元素中时才有用。 

这些限制促使我们采用位级贪婪或计数策略。 总计`n`跨测试用例最多`2·10^5`，因此任何按位检查每个元素固定次数的解决方案都是可以接受的。 但是，任何尝试位或元素子集或直接模拟操作的操作都将立即失败，因为`k`可以大到`10^9`。 

一个天真的解释是尝试为每个元素贪婪地分配位，但这忽略了 AND 创建的全局耦合。 真正的结构是每个bit都是独立的，可以单独分析。 

当解决方案假设我们应该始终最大化每个元素的设置位数时，就会出现微妙的失败情况。 

例如，考虑：```
n = 3, k = 1
a = [1, 0, 1]
```一个天真的想法可能是使用中间元素上的操作来从其他元素复制有用的位，但实际上一个操作不能使一个位出现在所有三个元素中，除非它已经存在于其中至少两个元素中。 所以最好的答案仍然是`0`或者取决于是否可以进行完全对齐。 这强调了我们必须全局推理每个比特，而不是每个元素。 

## 方法

 蛮力的观点是模拟所有应用的方式`k`位插入。 每个操作可以选择一个索引和一个位位置，所以大致有`n * 31`每个操作的选择。 甚至限制在小范围内`k`，分支因子使这个呈指数增长。 

一旦我们将视角从“我们如何分配位”转变为“每个位需要什么才能在 AND 中生存”，问题就变得易于管理。 

修复一下`j`。 在初始数组中，令`cnt[j]`有多少元素已经设置了该位。 为了让位`j`出现在最后的 AND 中，每个元素都必须以它结尾。 这意味着我们需要准确修复`n - cnt[j]`该位缺失位置。 每次操作可以修复一个元素中一位的缺失位置，因此制作位的成本`j`完全存在正是`n - cnt[j]`。 

现在我们看到了结构：每一位都是一个项目，其“利润”等于其价值`2^j`“成本”等于全局激活它所需的操作次数。 我们希望选择一个比特子集来最大化总价值，但总成本≤`k`。 

这是典型的按位重要性贪婪的情况。 由于较高的位在值上支配较低的位，因此我们将位从 30 向下处理到 0，并贪婪地包含一个位（如果我们负担得起的话）。

 | ---| ---| ---| ---|
 | 暴力破解（模拟操作）| 指数| O(n) | 太慢了|
 | 比特成本贪婪 | O(31·n) | O(31·n) | O(31) | 已接受 |

 ## 算法演练

 1. 计算每一位`j`，有多少数组元素已经设置了该位。 这给出了哪些位“几乎已经是全局的”的基线结构。 
2. 对于每一位`j`，计算缺少该位的元素数量，即`cost[j] = n - cnt[j]`。 这是使该位出现在每个元素中所需的操作数。 
3. 初始化变量`remaining_k = k`，它跟踪我们仍然可以花费多少操作。 
4. 初始化答案`ans = 0`。 
5. 将位从 30 向下迭代到 0。对于每个位`j`，检查是否`cost[j] <= remaining_k`。 如果是的话，我们有能力在全球范围内执行这一点。 
6. 如果我们包括位`j`， 添加`2^j`到答案并减去`cost[j]`从`remaining_k`。 
7. 如果我们买不起一点，就跳过它。 较低的比特组合起来可能仍然是负担得起的且有价值的。 

### 为什么它有效

 每个位在操作方面都是独立的，因为设置位`j`元素中的内容不会影响任何其他位。 实现位的完全存在的成本仅取决于当前缺少该位的元素的数量，而不取决于其他位的选择。 

按位重要性的贪婪排序是正确的，因为成本是固定且独立的，而值遵循严格的二进制优势。 任何包含较低位的配置都无法补偿丢失较高位，因此从高到低的处理可确保我们永远不会为了较差的较低位组合而牺牲更好的可实现的高位配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        cnt = [0] * 31

        for x in a:
            for j in range(31):
                if x & (1 << j):
                    cnt[j] += 1

        remaining = k
        ans = 0

        for j in range(30, -1, -1):
            cost = n - cnt[j]
            if cost <= remaining:
                remaining -= cost
                ans |= (1 << j)

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先在阵列中构建位频率，这对于了解每个位距离通用还有多远是必要的。 然后，贪婪循环模拟按重要性降序选择位。 

一个常见的错误是通过全局计算零来错误地计算成本，而没有意识到每个操作仅修复一位的一个元素。 另一种是尝试跨位重用操作； 这是无效的，因为每个 OR 运算都只针对一个元素中的一位。

 ## 边缘情况

 关键的边缘情况是所有元素都已包含一个位。 在那种情况下，`cnt[j] = n`， 所以`cost[j] = 0`，算法总是立即获取该位。 这确保了现有结构得以保留，而无需消耗操作。 

另一个边缘情况是当`k = 0`。 该算法从不包含任何不是全局的位，因为每个`cost[j] > 0`除非完全在场。 结果正好是原始数组的 AND。 

最后，当`k`由于非常大，算法只是尝试包含所有位，但每个位仍然需要可行性。 由于成本是独立的，因此我们最终仅在可能完全覆盖的情况下重建所有元素的按位或，这与预期的优化行为相匹配。
