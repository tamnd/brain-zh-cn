 ## 解决方案
 ## 问题理解

 我们有三摞书。 每个堆栈包含`n`书籍从上到下排列。 每本书上都写有一个非负整数。 

丹增从知识开始，等于`0`。 每当他读一本有价值的书时`v`，他的知识变成`knowledge | v`， 在哪里`|`是按位或运算。 

限制来自堆栈结构。 丹增只能阅读当前书库最上面的书。 读完后，那本书就会消失，下一本书就会出现。 他可以随时在堆栈之间切换，并且可以随时停止。 

目标是确定某些读取序列是否可以使他的最终知识完全等于`x`。 

输入包含多个测试用例。 对于每个测试用例，我们都会收到目标值`x`和三个堆栈。 我们必须输出`"Yes"`如果某个有效的读取序列恰好达到`x`， 否则`"No"`。 

全部的总和`n`整个输入的值最多是`10^5`。 这立即表明每个测试用例需要一个线性或接近线性的解决方案。 任何尝试多种不同阅读顺序或探索 OR 值状态的方法很快就会变得不可行。 

该问题最危险的部分是按位或的不可逆性。 一旦一点点变成`1`，它永远不能回到`0`。 一个幼稚的实现可能会意外地允许书籍介绍不存在的位`x`，即使这样的举动永久地使达到`x`不可能的。 

考虑这个例子：```
n = 1, x = 2

Stack A: 3
Stack B: 0
Stack C: 0
```价值`3`包含位`11₂`， 尽管`x = 2`是`10₂`。 阅读`3`引入了一个不属于的额外位`x`，所以答案是`"No"`。 

另一个微妙的情况是我们可能随时停止。```
n = 1, x = 0

Stack A: 5
Stack B: 7
Stack C: 9
```正确答案是`"Yes"`因为零书阅读是允许的。 

第三个常见错误是认为每一本易于阅读的书都必须阅读。```
n = 2, x = 1

Stack A: 1 2
Stack B: 0 0
Stack C: 0 0
```仅读取堆栈 A 的第一本书已经产生`1`。 进一步阅读会创造价值`3`，这是错误的。 由于允许停止，所以答案是`"Yes"`。 

## 方法

 暴力解决方案会尝试所有可能的读取序列。 在每一步中，我们都可以选择当前非空堆栈之一或停止。 可能的序列数量呈指数增长，因为每个堆栈都可以独立推进。 即使对于适度的值`n`，可能性的数量变得巨大。 

蛮力的想法是正确的，因为它明确地探索每个有效的阅读顺序并检查某些最终的 OR 是否等于`x`。 问题在于`n`最多`10^5`总体而言，这样的探索是完全不可能的。 

关键的观察结果来自于检查何时可以安全地阅读一本书。 

假设当前的知识是`cur`。 如果一本书包含了书中没有的内容`x`，那么执行 OR 运算后该位将永远保留。 准确到达`x`变得不可能。 

这意味着我们读过的每一本书都必须满足：```
(book | x) = x
```同样，书中设置的所有位都已包含在`x`。 

现在从上到下查看堆栈。 一旦我们遇到一本包含禁止内容的书，我们就永远无法阅读那本书。 由于它阻止访问其下面的所有书籍，因此该堆栈的整个剩余部分将变得不可用。 

这给出了非常简单的表征。 

对于每个堆栈，从顶部读取书籍，而它们的位是`x`。 或将所有这些值转换为全局结果。 当我们看到一本无效的书时，停止处理该堆栈。 

为什么 OR 每本可访问的有效书籍都是安全的？ 因为 OR 只加位。 每本可访问的有效书籍都贡献了属于`x`，并且没有理由跳过这些位。 如果可以从一些可访问的有效书籍中获得一些信息，那么将其放在最后的 OR 中只会帮助我们达到`x`。 

处理完所有三个堆栈后，令累加的 OR 为`ans`。 

如果`ans == x`，那么我们可以选择一个阅读顺序，准确地阅读那些可访问的有效书籍并达到`x`。 否则一些`x`永远无法获得，所以答案是`"No"`。

 ## 算法演练

 1. 初始化`ans = 0`。 
2. 从上到下独立处理三个堆栈中的每一个。 
3. 对于当前账面价值`v`，检查其所有设置位是否属于`x`。 

这相当于检查：```
(v | x) == x
```4.如果检查成功，则OR书中的答案：```
ans |= v
```这样的书可以安全地阅读，因为它从未引入禁止的位。 
5. 如果检查失败，则立即停止处理该堆栈。 

它下面的任何书都是无法访问的，因为必须首先从顶部删除书。 
6. 三个堆栈都处理完毕后，比较`ans`和`x`。 
7. 输出`"Yes"`如果`ans == x`，否则输出`"No"`。 

### 为什么它有效

 一本包含一点外面的书`x`永远不会出现在有效的阅读序列中。 读取它会永久设置一个禁止位，使最终值大于`x`在那个位的位置。 

因此，对于每个堆栈，只能访问有效书籍的最大前缀。 第一个无效书之后的任何书都无法访问，因为无法删除阻塞书。 

该算法计算可能参与有效序列的每本书的“或”。 如果结果 OR 等于`x`，然后所有位`x`是可以获得的并且没有出现禁止位。 阅读这些书的收获正是`x`。 

如果结果 OR 缺少一些位`x`，那么没有可访问的书包含该位。 没有任何阅读策略可以创造它，所以达到`x`是不可能的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())

        stacks = [
            list(map(int, input().split())),
            list(map(int, input().split())),
            list(map(int, input().split()))
        ]

        ans = 0

        for stack in stacks:
            for v in stack:
                if (v | x) == x:
                    ans |= v
                else:
                    break

        print("Yes" if ans == x else "No")

if __name__ == "__main__":
    solve()
```解法直接遵循证明。 

条件`(v | x) == x`检查每个位是否设置`v`也设置在`x`。 这是对问题的批判性观察。 使用任何其他条件往往会错过书籍引入禁止位的情况。 

这`break`同样重要。 一旦出现一本无效的书，该堆栈就会永远被阻塞。 继续检查下面的书籍会错误地认为它们是可访问的。 

变量`ans`存储所有可访问的有效书籍的 OR。 由于 OR 具有结合性和交换性，因此确切的读取顺序对于最终值并不重要。 

Python 整数很容易处理所涉及的值，因为所有数字最多`10^9`。

 ## 边缘情况

 ### 目标值为零

 输入：```
1
1 0
5
7
9
```每本顶级书籍都是无效的，因为每本都包含以下内容中不存在的位`0`。 

该算法立即在所有三个堆栈上停止。`ans`遗迹`0`，等于`x`，所以答案是`"Yes"`。 

这相当于不读书。 

### 有用的书隐藏在无效书下面

 输入：```
1
2 2
3 2
0 0
0 0
```A 堆栈中的第一本书是`3`（`11₂`），其中包含禁止位。 堆栈 A 的处理立即停止。 

价值`2`下面它永远不会被检查，因为它在任何有效序列中都是无法访问的。 

最终的 OR 是`0`，所以答案是`"No"`。 

### 达到 x 需要多个堆栈

 输入：```
1
1 7
1
2
4
```加工产量：```
ans = 0
ans |= 1 -> 1
ans |= 2 -> 3
ans |= 4 -> 7
```最终的 OR 等于`7`，所以答案是`"Yes"`。 

这表明该算法正确地从所有可访问的堆栈中收集位并通过 OR 将它们组合起来。
