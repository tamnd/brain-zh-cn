 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例都以一行整数开始，表示排列成一行的一系列彩球。 移动包括选择两个位置$i < j$使这些位置的球具有相同的颜色，然后从$i$到$j$，包括两个端点。 移除后，右侧的所有内容都会向左移动。 我们重复此操作任意多次，目标是最大化总共移除的球数。 

解释这一点的一个有用方法是，每个操作都会删除一个其端点共享相同值的连续块，并且删除后，数组会变得更短，可能会启用以前不相邻的新合并。 

所有约束总和$n$是$2 \cdot 10^5$，所以一个$O(n^2)$每次测试的解决方案太慢，甚至$O(n \sqrt n)$有风险。 每个测试用例我们都需要一种线性或近线性的方法。 

当颜色重复但被大段分隔时，会出现微妙的边缘情况。 例如，在`[1, 2, 3, 1]`，很容易想到这两个`1`s 可以直接贡献较大的删除，但中间结构影响部分删除后可能发生的情况。 总是删除第一个有效对的天真贪婪方法可能会失败，因为它可能会阻止未来更好的配对。 

另一个陷阱是假设每种颜色独立地贡献诸如“第一次出现和最后一次出现之间的距离”之类的东西。 当内部结构允许多阶段删除时，这种情况就会被打破。 

## 方法

 蛮力策略会尝试每一个可能的对$(i, j)$具有相等的值，模拟移除，并递归求解剩余的数组。 这正确地模拟了该过程，但每次删除都会改变数组大小，并且可以有$O(n^2)$候选人在每个州的流动情况。 由于递归分支较多，因此在最坏的情况下总复杂度呈指数级增长。 

关键的观察是我们永远不需要显式模拟中间数组。 相反，我们可以从左到右的处理方式来思考，并决定是否“打开”一段稍后将由匹配颜色关闭的段。 

这自然会导致对前缀的动态编程，我们跟踪每个位置的最佳答案。 主要的困难是当我们在位置关闭一个段时$i$，我们必须考虑将较早出现的相同颜色配对的最佳方式，同时可能跳过内部元素。 

解决此结构问题的标准技巧是维护一个 DP 数组，其中我们在每个位置考虑两种选择：要么将当前元素视为独立元素（不用于任何外部删除），要么将其与某些较早出现的相同颜色相匹配，并以最佳方式删除之间的所有内容。 

对于每种颜色，我们还保留该颜色最后出现的位置的最佳 DP 值。 这避免了重复向后扫描。 

每个测试用例得到的解决方案都是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) 递归 | 太慢了 |
 | 具有最后出现状态的最优 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们定义一个 DP 数组，其中`dp[i]`表示考虑到索引的前缀，移除球的最大数量`i`。 

我们还维护一本字典`best[color]`，在应用我们可能在当前位置关闭线段的想法之后，它存储在该颜色出现的位置处看到的最佳 DP 值。 

### 步骤

 1. 初始化`dp[0] = 0`并设置所有`best[color] = 0`。 

意思是在处理任何东西之前，不可能进行任何删除。 
2. 从左到右迭代数组。 

在位置`i`，我们考虑当前球的颜色`c = a[i]`。 
3、首先，发扬前人的优秀：`dp[i] = dp[i-1]`。 

这代表我们没有在该位置结束任何移除的情况`i`。 
4. 现在考虑关闭结尾为`i`。 

如果我们之前看到相同的颜色`c`在某个位置，那么较早出现的位置可以充当删除的左端点。 
5.对于颜色`c`，计算：$$dp[i] = \max(dp[i], best[c] + 1)$$这表示与较早出现的相同颜色形成有效对，并以已编码的最佳方式删除之间的所有内容`best[c]`。 
6. 更新`best[c] = \max(best[c], dp[i])`。 

这确保了未来发生`c`可以从迄今为止最好的可实现状态中受益。 
7. 处理完所有元素后，答案为`dp[n]`。 

### 为什么它有效

 关键的不变量是`best[c]`始终存储颜色所在的所有位置中可实现的最大 DP 值`c`已经出现，意味着它代表了关闭一段颜色之前的最佳状态`c`”。当我们处理新出现的`c`，将其与最佳的先前出现配对相当于为此处结束的段选择最佳左边界。 由于内部段已经得到最优解`dp`，我们永远不会通过将所有先前发生的事件折叠成一个最佳状态来失去最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        dp_prev = 0
        best = {}

        for x in a:
            cur = dp_prev

            if x in best:
                cur = max(cur, best[x] + 1)

            if x not in best or cur > best[x]:
                best[x] = cur

            dp_prev = cur

        print(dp_prev)

if __name__ == "__main__":
    solve()
```该代码使用滚动 DP 而不是完整数组，因为每一步只需要先前的值。 字典`best`将每种颜色的所有历史状态压缩为单个值，从而避免二次行为。 

过渡`best[x] + 1`编码使用较早出现的相同颜色来关闭以当前位置结束的线段的想法。 增量对应于执行一次删除操作。 

更新时一定要注意`best[x]`计算后`cur`，否则我们会错误地允许状态在同一步骤中重用自身。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):

        a = list(map(int, input().split()))

        best = {}

            cur = dp_prev

 ## 边缘情况

 对于具有所有相同值的数组，算法不断更新`best[color]`，确保每一次新的出现都能延伸之前的最优链。 DP 为每个相邻的事件对构建一个操作，这与每次合并将段至少减少一个完整间隔的事实相匹配。 

对于严格交替的序列，例如`[1,2,1,2,...]`，每种颜色的`best`值独立演化，并且 DP 仅在存在有效的先前状态时才允许转换，从而正确避免了过度计数。 这可以防止不兼容段之间的错误链接。 

对于没有重复的数组，`best`始终保持空状态，因此不会形成任何操作。 DP 正确返回零，因为任何删除操作都不存在有效端点。
