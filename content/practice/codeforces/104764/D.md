 ## 解决方案
 ## 问题理解

 我们在一条线上得到一组不同的整数位置，每个位置代表一只水母。 我们必须从这些位置中准确选择$K$并仅考虑那些选定的点。 在所有可能的选择中$K$点，我们查看任意两个选定点之间的最大距离，并且我们希望使该数量尽可能小。 

一旦选择了一个子集，杰瑞就可以站在任何地方，但这并不能改变群体的分布仅由最左边和最右边选定的水母决定的事实。 任何选定集合内的最大距离只是其最大元素和最小元素之间的差。 因此任务减少为选择大小的子集$K$最小化范围。 

输入大小达到$2 \cdot 10^5$，因此任何尝试所有子集甚至所有组合的解决方案都是立即不可能的。 对或子集的二次扫描将需要以下顺序$10^{10}$最坏情况下的操作，远远超出1秒的限制。 我们最多应该期望一个近线性或$N \log N$解决方案。 

一个天真的陷阱是忘记只有选择的极端才是重要的。 例如，如果位置是$[1, 2, 10, 11]$和$K = 3$，选择$\{1, 2, 11\}$给出范围 10，而$\{1, 2, 10\}$给出范围 9，即使两者都包含相同的小元素。 该结构完全取决于选择排序顺序中的三个连续点。 

另一个微妙的问题是假设杰里的位置对距离很重要。 事实并非如此。 该问题仅要求水母之间的最大距离，因此 Jerry 与目标函数无关。 

## 方法

 蛮力的想法是枚举大小的每个子集$K$，计算其最小和最大元素，并取尽可能小的差值。 这是正确的，因为目标的定义纯粹是子集的组合。 然而，这样的子集的数量是$\binom{N}{K}$，即使对于中等值，它也会变得巨大$N$。 为了$N = 200000$，这是完全不可行的，甚至对于$N = 40$它已经太大了。 

关键的结构观察是，一旦位置被排序，任何大小的最佳子集$K$必须包括$K$按该排序顺序的连续元素。 如果子集跳过其跨度内的元素，则用跳过的较小元素替换较大的选定元素只能缩小范围或保持不变。 这种单调性将搜索空间从组合式折叠为窗口上的线性式。 

因此，排序后，问题就变成了扫描所有长度连续的窗口$K$并计算端点之间的差异。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(\binom{N}{K} \cdot K)$|$O(K)$| 太慢了|
 | 排序数组上的滑动窗口 |$O(N \log N)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 1. 将所有水母位置按升序排列。 这确保了任何组的分布都是由该排序中的连续结构决定的，而不是任意选择。 
2. 用一个非常大的值初始化一个答案变量。 这将跟踪遇到的最佳（最小）范围。 
3. 迭代每个索引$i$这样一个大小的窗口$K$开始于$i$适合数组内部。 对于每个$i$，考虑由元素形成的组$i$到$i + K - 1$。 
4. 计算该组的范围为$a[i + K - 1] - a[i]$。 这是有效的，因为在排序数组中，连续段的最大值和最小值是其端点。 
5. 使用所有此类窗口中的最小值更新答案。 

扫描完成后，存储的答案是可能的最小范围。 

### 为什么它有效

 排序后，假设最优子集在索引顺序上不连续。 则在其最小值和最大值之间至少存在一个未被选中的元素。 用这个缺失的内部元素替换选定的极端元素之一不能增加范围，因为它将端点向内移动或保持不变。 重复这个论点可以将任何最佳子集转换为连续的块，而不会恶化其目标值。 因此，将注意力限制在连续片段上并不会失去最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    ans = float('inf')
    
    for i in range(n - k + 1):
        ans = min(ans, a[i + k - 1] - a[i])
    
    print(ans)

if __name__ == "__main__":
    main()
```该解决方案首先读取输入并对位置列表进行排序。 排序至关重要，因为它将直线上的几何问题转换为结构化数组问题，其中窗口代表候选组。 

起始索引的循环枚举所有有效的大小 -$K$段。 对于每个分段，我们直接从端点计算其分布。 存储所有此类价差的最小值。 使用单通道可确保分拣后的线性扫描。 

一个常见的错误是尝试在不先排序的情况下维护动态窗口。 这会破坏端点属性并导致范围计算不正确。 另一个错误是错误计算索引，尤其是忘记了最后一个有效的开始是$n - k$。

 ## 边缘情况

 一个关键的边缘情况是当$K = 1$。 任何单个元素的范围为零，算法会处理这个问题，因为每个大小为 1 的窗口都会产生$a[i] - a[i] = 0$。 

另一种情况是所有值都相同，尽管该语句保证了不同的位置。 如果删除该限制，滑动窗口仍然正确地返回零$K$，因为所有端点都匹配。 

簇之间的大间隙测试算法是否正确避免选取极端。 例如，$[1, 2, 3, 100, 101]$和$K = 3$产生最佳窗口$[1,2,3]$或者$[100,101, \text{(invalid)}]$取决于位置，并且扫描正确地选择密集区域而不是跨越整个范围的端点。 

该算法自然地处理所有这些，因为每个候选者在排序后通过端点差异进行统一评估。
