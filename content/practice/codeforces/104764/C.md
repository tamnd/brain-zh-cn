 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，表示在固定的午餐时间内每分钟吃掉多少水母。 任务是找到一个连续的分钟段，使得该段中被吃掉的水母总数为奇数，并且在所有这些段中我们想要最大可能的长度。 如果不存在这样的部分，我们必须报告这一事实。 

关键输出不是和本身，而是和具有奇奇偶校验的最长子数组的长度。 

约束允许最多$2 \cdot 10^5$元素，这会立即排除子数组的任何二次或三次枚举。 检查所有子数组的解决方案需要以下顺序：$N^2$段总和，大约是$4 \cdot 10^{10}$最坏情况下的操作，远远超出1秒的限制。 

的价值观$j_i$可以很大，但只有奇偶性对条件很重要，因为我们只关心总和是奇数还是偶数。 这表明将数组简化为奇偶校验信息就足够了。 

一些边缘情况很重要：

 所有元素均为偶数的序列使得每个子数组的总和为偶数。 例如，输入`[2, 4, 6]`没有产生有效的段，所以答案应该是`-1`。 

仅有一个奇数元素的序列仍然可以产生长的有效段，因为任何包含奇数个奇数元素的段都将具有奇数和。 例如，`[2, 1, 2]`允许完整数组，总和为奇数。 

一个微妙的情况是，当整个数组和为偶数时，但删除前缀或后缀可以生成有效的奇数和段。 例如`[1, 2, 3, 4]`总和为偶数，但最佳段可能仍然是整个数组或一个大子数组。 

## 方法

 直接暴力方法检查每个可能的子数组，计算其总和，并记录具有奇数总和的子数组中的最大长度。 从概念上讲，这是通过枚举所有间隔来实现的$[l, r]$, 计算$\sum_{i=l}^{r} j_i$，并检查奇偶性。 

子数组的数量为$O(N^2)$，甚至使用前缀和将总和计算减少到$O(1)$，枚举本身占主导地位。 为了$N = 2 \cdot 10^5$，这导致大约$2 \cdot 10^{10}$迭代，这是不可行的。 

关键的观察结果是，和的奇偶校验表现为模 2 加法。我们不需要跟踪完整的和，而只需要前缀奇偶校验。 让$p_i$是到索引的前缀和的奇偶校验$i$。 然后求一段的总和$[l, r]$恰好当$p_{l-1} \neq p_r$。 

这将问题简化为寻找最远的索引对$l-1$和$r$使得前缀奇偶校验不同。 对于每个位置$r$，如果我们知道两个奇偶校验状态最早出现的时间，我们就可以最大化段长度。 

这将问题转化为跟踪前缀数组中奇偶校验 0 和奇偶校验 1 的第一次出现并将它们与最新的可能索引配对。

 | 最佳（前缀奇偶校验跟踪）|$O(N)$|$O(1)$| 已接受 |

 ## 算法演练

 我们根据和的前缀奇偶校验重写数组。 

1. 当我们从左到右扫描数组时，计算运行奇偶校验值。 该值为 0 或 1，表示当前索引的总和是偶数还是奇数。 
2. 维护两个数组或变量，用于存储已看到每个奇偶校验值（0 或 1）的最早索引。 最初，在处理任何元素之前，奇偶校验 0 在索引 0 处可见。 
3. 当我们移动数组时，更新前缀奇偶校验。 
4. 各位置$i$，如果当前奇偶校验为$p$，然后是奇偶校验的任何先前位置$1 - p$形成一个有效的子数组，结尾为$i$与奇数。 
5. 计算长度$i - earliest[1 - p]$并更新最大答案。 
6. 继续此过程直到数组末尾。 
7. 如果没有找到有效的子数组，则返回-1。 

关键思想是，一旦我们知道每个奇偶校验第一次出现的位置，以后的每次出现都可以尽可能地扩展有效段，并且我们只关心最大化距离。 

### 为什么它有效

 前缀奇偶校验通过模 2 减法对任何子数组和的奇偶校验进行编码。由于模 2 减法相当于 XOR，奇数和的条件简化为比较两个前缀奇偶校验状态。 

每个有效子数组唯一对应于一对具有不同前缀奇偶校验的索引。 因此，最长的有效子数组必须将最早出现的一个奇偶校验与最新出现的相反奇偶校验连接起来。 跟踪最早出现的事件可确保我们始终最大化长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix parity
    parity = 0

    # earliest index where parity 0 or 1 occurred
    first = [-1, -1]

    # prefix at index 0 (empty prefix has sum 0 -> parity 0)
    first[0] = 0

    best = -1

    for i in range(1, n + 1):
        parity ^= (a[i - 1] & 1)

        if first[parity] == -1:
            first[parity] = i
        else:
            # we can form a subarray ending at i
            best = max(best, i - first[1 - parity])

    print(best if best > 0 else -1)

if __name__ == "__main__":
    solve()
```该实现保持运行的 XOR 来维持前缀和的奇偶校验。 数组`first`存储每个奇偶校验发生的最早的前缀索引。 我们初始化`first[0] = 0`因为在读取任何内容之前，总和为零。 

每个步骤仅使用每个值的最低有效位更新奇偶校验，因为较高位不影响奇/偶行为。 当我们遇到前缀奇偶校验时，我们要么记录它的第一次出现，要么使用相反奇偶校验的第一次出现来形成候选段。 

减法`i - first[1 - parity]`给出结束于的有效间隔的长度`i`。 这是避免显式子数组枚举的中心计算。 

一个微妙的点是，我们只初始化第一次出现，之后不再更新它，因为我们需要最大可能的段长度，这总是受益于最早的起始索引。

 ## 边缘情况

 全部为偶数的序列演示了从未发生奇偶校验翻转的故障模式。 在这种情况下，`first[1]`永远不会被设置，并且每个计算出的候选者仍然无效。 算法正确返回`-1`因为`best`从不更新。 

单元素数组测试初始化​​是否处理最小输入。 有输入`[5]`，前缀奇偶校验变为1，`first[1]`设置为索引 1，并且不存在相反的奇偶校验，因此仅当我们将单个奇数元素解释为有效段时，答案才正确为 1。 

像这样的案例`[2, 2, 2, 1]`可见前缀索引的重要性。 最后的奇偶校验翻转发生在最后一个元素，最早的相反奇偶校验位于索引 0，产生全长有效段。
