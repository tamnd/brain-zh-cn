 ## 解决方案
 ## 问题理解

 我们得到了字母表 {A, T, C, G} 上的目标基因组字符串。 我们还得到了一组 DNA 片段，每个片段都可以任意重复使用多次。 任务是确定其连接精确形成基因组的片段的最小数量。 第二种变体引入了一个额外的限制：我们不允许在串联序列中连续两次放置相同的段。 

这是一个字符串构造问题，其中每个段都是一个可重用的“图块”，我们希望用最少数量的图块来平铺目标字符串，首先没有局部邻接约束，然后再有局部邻接约束。 

输入大小使得对所有段序列进行暴力破解是不可能的。 基因组长度和片段数量均高达 1000，片段长度也高达 1000。任何显式尝试所有片段序列或所有片段放置的方法都会使基因组长度呈指数增长，因为在每个位置我们可能有许多匹配的片段。 

一个关键的含义是我们必须避免枚举段序列。 相反，我们需要预先计算哪些片段与基因组的哪些子串匹配，然后解决基因组中位置的最短路径样式问题。 

当一个短段实现局部最优选择而阻碍更好的全局分解时，就会出现天真的贪婪方法的微妙失败情况。 例如，假设基因组是“AAAA”，片段是{“AA”，“A”，“AAA”}。 首先选择最长匹配的贪婪策略可能会选择“AAA”而留下“A”，从而产生 2 个片段，但不同的选择“AA”+“AA”也会给出 2，并且某些贪婪策略可能错误地选择“A”四次，给出 4。该结构本质上是全局的。 

当分段严重重叠并且存在具有不同计数的多个分段时，会出现另一种重要的边缘情况。 这迫使我们考虑所有有效的过渡，而不是尽早做出承诺。 

## 方法

 第一个观察结果是，任何有效的构建都对应于将基因组划分为连续的片段，每个片段等于给定片段中的一个。 这表明对基因组前缀的动态规划公式。 

暴力方法会将基因组中的每个位置视为一种状态，并递归地尝试从那里开始匹配的每个片段。 对于每场比赛，我们向前跳转其长度并在计数中加一。 这探索了一个分支树，其中每个节点最多可以有 N 个传出转换，并且深度与基因组长度成正比。 在最坏的情况下，许多段匹配许多位置，路径的数量在 |G| 中呈指数增长。 

关键的见解是基因组位置形成自然的线性顺序，并且转变只会向前移动。 这意味着问题简化为 DAG 上顶点为 0 到 |G| 的最短路径，其中如果段 s 与 G[i:i+len(s)] 匹配，则存在从 i 到 i+len(s) 的边。 

我们通过检查每个片段是否适合它的每个位置来预先计算所有匹配。 然后我们在前缀位置上运行标准最短路径 DP。 

第二种变体添加了同一段不能连续使用两次的约束。 这引入了对最后选择的段的依赖，因此状态必须不仅包括位置，还包括最后使用的段索引。 这将 DP 状态扩展为 (position, last_segment)，但转换仍然向前，并且仍然形成类似 DAG 的结构。 

我们通过位置动态规划来解决这两个版本，仅在第二种情况下使用附加维度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 段序列上的强力递归 | O(exp( | G | )) | O(exp( | G | )) |
 | DP 位置（以及变体 2 的最后一段）| O( | G | * N * avg_len) | O( | G | * N * avg_len) |

 ## 算法演练

我们首先预处理所有段匹配。 对于基因组中的每个位置 i，我们检查每个片段 s 并验证 G[i:i+len(s)] 是否等于 s。 如果是，我们存储从 i 到 i+len(s) 的转换，并用该段索引标记。 

然后我们对基因组位置进行动态编程。 

1. 初始化一个DP数组，其中dp[i]表示形成前缀G[0:i]所需的最小段数。 将 dp[0] = 0 设置为无穷大。 
2. 对于从 0 到 |G| 的每个位置 i，考虑从 i 开始的所有段匹配。 对于导致位置 j = i + len(s) 的每个匹配段 s，用 dp[i] + 1 更新 dp[j]。这反映了采用一个附加段来扩展有效构造。 
3.处理完所有位置后，dp[|G|]如果可达则包含答案，否则无法形成基因组。 

对于第二个变体，我们改进了 DP 状态。 我们维护 dp[i][k]，而不是单个 dp[i]，其中 k 是最后使用的段的索引。 如果 t != k，我们只允许从状态 (i, k) 转换到 (j, t)。 

转换规则变为：对于每个状态 (i, k)，尝试在 i 处匹配的所有段 t 并更新 dp[j][t] = min(dp[j][t], dp[i][k] + 1)。 

我们在位置 |G| 处取所有最后一段的最小值。 

它之所以有效，是因为每个有效的构造都完全对应于从 0 到 |G| 的路径。 在这个有向无环结构中。 每个段放置严格增加位置索引，因此循环是不可能的。 DP 确保每个可到达的前缀在到达它的所有可能的分解中被分配最小数量的段，并且递归探索所有合法的最后步骤。 在第二个版本中，跟踪最后一个段可确保我们永远不会计算连续重用同一段的转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**9

def solve():
    n = int(input())
    g = input().strip()
    m = len(g)

    segs = [input().strip() for _ in range(n)]

    # precompute matches
    starts = [[] for _ in range(m + 1)]
    for i in range(m):
        for idx, s in enumerate(segs):
            L = len(s)
            if i + L <= m and g[i:i+L] == s:
                starts[i].append((i + L, idx))

    dp = [INF] * (m + 1)
    dp[0] = 0

    for i in range(m + 1):
        if dp[i] == INF:
            continue
        for j, idx in starts[i]:
            if dp[j] > dp[i] + 1:
                dp[j] = dp[i] + 1

    print(-1 if dp[m] == INF else dp[m])

if __name__ == "__main__":
    solve()
```该实现构建了一个前向邻接列表，其中每个位置都知道哪些段可以从那里开始以及它们引导到哪里。 这避免了重复扫描转换内的基因组并保持 DP 清洁。 

DP 数组存储到达每个前缀边界的最小段计数。 关键细节是转换只会向前移动，因此从左到右迭代 i 就足够了，不会出现松弛顺序问题。 

边界处理发生在检查中`i + L <= m`，这可以防止超出范围的子字符串比较。 由于 Python 切片行为，缺少此条件通常会导致无提示的错误答案。

 ## 边缘情况

 一种边缘情况是由于缺失字符或不兼容的片段边界而无法完全覆盖基因组。 对于输入：```
1
ACTG
A
```DP 仅到达位置 0 和 1，而 dp[4] 无法到达，因此输出为 -1。 该算法自然会处理这个问题，因为无法到达的状态保持无穷大。 

另一个边缘情况是严重重叠，其中许多段在同一位置匹配。 对于具有片段{“A”、“AA”、“AAA”}的基因组“AAAAA”，从位置0到1、2和3的dp转变都存在。 DP 仍然有效，因为无论分支因子如何，它都会保持每个前缀的最小成本。 

最终的边缘情况是重复的最佳状态：多个不同的段序列到达同一位置。 由于 dp 只存储最小值，因此冗余路径会被安全地丢弃，而不会影响正确性。
