 ## 解决方案
 ## 问题理解

 我们得到了一组最多 100 个项目。 每个项目在 10 天的某个子集中可用，由 0-1 矩阵描述。 在这 10 天中的每一天，我们都会决定 Yolanda 是否访问商店，因此有效的策略只是天数的子集。 

对于任何固定策略，每个商品最终都会在一定数量的访问天数内被看到，但仅计算其有库存的天数。 所以对于项目$i$，其贡献仅取决于$c_i$，该天的天数$j$既被访问过并且$F_{i,j} = 1$。 

一旦我们知道$c_i$，我们取一个数组$P$并计算范围 XOR 值$[P_1, P_{c_i}]$，约定如果需要可以交换端点。 最终得分是所有项目的这些值的总和。 

我们每 10 天控制一个二元决策，这意味着有$2^{10} = 1024$可能的访问模式。 对于每个模式，我们可以计算所有$c_i$并评价总分。 

影响解决方案的主要限制是天数极少。 这立即排除了任何尝试优化项目或使用大量动态编程的方法$N$。 相反，只要每次评估足够有效，对日子集的暴力破解是可以接受的。 

一个微妙的点是$XOR\_range(a,b)$任一参数都不是单调的，并且根据 XOR 前缀和的奇偶校验结构而表现不同。 假设线性或尝试贪婪地为每个项目分配天数的尝试会失败，因为每天的决策同时影响所有项目。 

第二个陷阱是误解间隔$[P_1, P_{c_i}]$什么时候$c_i = 0$。 该问题指出样本中的参数可能是无序的，因此正确的解释是两个值之间包含的整数间隔的异或，无论顺序如何。 

边缘情况包括：

 一个案例，所有$F_{i,j} = 0$。 然后每$c_i = 0$，并且每个项目都有贡献$XOR\_range(P_1, P_0)$。 一个幼稚的实现假设$c_i \ge 1$会错误索引或跳过贡献。 

选择所有日期的情况。 然后$c_i$等于行中的个数$i$。 这测试了计算交集的正确性，而不是简单地对行值求和。 

两种策略产生相同多重集的情况$c_i$但每个项目的分布不同。 由于目标可以按项目分离一次$c_i$是固定的，只有计数才重要，而不是具体哪一天产生计数。 

## 方法

 蛮力观点很简单。 我们枚举这 10 天的所有子集。 对于每个子集，我们计算$c_i$对于每件商品，检查哪些日期已选择且有库存。 然后我们使用 XOR 范围函数计算每个项目的贡献并对它们求和。 

计算$c_i$所有项目费用$O(10N)$每个子集，这很便宜。 主要成本是枚举子集：1024 种可能性。 所以总工作量约为$1024 \cdot 100 \cdot 10$，完全在限制之内。 

唯一剩下的技术问题是评估$XOR\_range(l,r)$迅速地。 由于值上升到$10^9$，我们无法预先计算所有范围。 相反，我们使用标准前缀 XOR 标识：$$XOR\_range(a,b) = pref(b) \oplus pref(a-1)$$在哪里$pref(x)$是从 1 到 x 的所有整数的 XOR。 这将每个查询减少到 O(1)。 

因此，问题简化为枚举 10 位的所有子集并评估简单的 O(N) 评分函数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集的暴力破解 | O(2^{10}·N·10) | O(2^{10}·N·10) | O(N) | 已接受 |
 | 最优（同样的想法+异或前缀）| O(2^{10}·N) | O(2^{10}·N) | O(N) | 已接受 |

 ## 算法演练

 1. 预先计算一个函数来评估前缀间隔的异或$[1, x]$。 这允许恒定时间范围的异或查询。 
2. 迭代从 0 到 1023 的所有掩码，代表选择了 10 天中的哪一天。 每一位对应于当天的访问。 
3. 对于每个掩码，计算$c_i$对于每个项目，扫描 10 天并计算掩模和库存矩阵均为 1 的位置。此步骤在此计划下建立每个项目的有效曝光。 
4. 对于每个项目，计算其贡献为$XOR\_range(P_1, P_{c_i})$，通过规范化顺序来处理端点隐式反转的情况。 
5. 对该掩码的所有项目的贡献求和。 
6. 跟踪所有掩码的最大总和并将其输出。 

为什么有效：每个有效策略都是 10 天的子集，因此枚举涵盖了所有可能的决策。 对于每个固定子集，计算$c_i$之所以准确，是因为它直接计算所选日期与库存可用性的交集。 由于目标函数仅取决于$c_i$每个项目并且在项目之间是独立的，单独评估项目不会失去交互作用。 因此，所有子集的最大值产生全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def xor_upto(x):
    # XOR of all integers from 1 to x
    # pattern repeats every 4
    if x <= 0:
        return 0
    r = x % 4
    if r == 0:
        return x
    if r == 1:
        return 1
    if r == 2:
        return x + 1
    return 0

def xor_range(a, b):
    if a > b:
        a, b = b, a
    return xor_upto(b) ^ xor_upto(a - 1)

n = int(input())
F = [list(map(int, input().split())) for _ in range(n)]
P = list(map(int, input().split()))

# assume P[1..10] relevant, P[0] unused or extra
# but problem states P1..Pc so we shift accordingly if needed
P = [0] + P

ans = 0

for mask in range(1 << 10):
    total = 0

    for i in range(n):
        c = 0
        for d in range(10):
            if (mask >> d) & 1 and F[i][d]:
                c += 1

        total += xor_range(P[1], P[c] if c < len(P) else P[-1])

    ans = max(ans, total)

print(ans)
```实现直接遵循枚举。 内循环计算所选日期和股票形态之间的交集，这正是以下的定义$c_i$。 

XOR 范围计算被分成前缀 XOR 帮助器，这避免了间隔内的重复循环。 唯一需要注意的一点是处理 range 函数内的排序，因为该问题明确允许端点在解释中颠倒。 

掩码循环是该解决方案的核心，其正确性完全取决于仅存在 10 天的事实，使得穷举搜索变得可行。

 ## 边缘情况

 一个完全空的库存矩阵设置了每个$c_i = 0$。 该算法仍然评估每个掩码，但每个项目始终贡献相同的值$XOR\_range(P_1, P_0)$。 由于这在掩码中是恒定的，因此可以正确返回最大值，而不依赖于调度。 

完全完整的库存矩阵使得$c_i$等于每个项目的访问天数。 然后，掩码枚举有效地搜索计数分布，并且算法根据选择的天数正确区分策略。 

什么时候$c_i$变为 0 或 10，边界索引为$P$必须保持有效。 该实现通过使用安全访问模式并依赖于以下约束来确保这一点：$c_i \le 10$。
