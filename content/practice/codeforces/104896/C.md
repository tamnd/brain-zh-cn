 ## 解决方案
 ## 问题理解

 我们有两个整数数组，我们应该将其视为符号的多重集。 从第一个数组，我们可以形成任何排列，这意味着相同元素的任何顺序。 从第二个数组中，我们得到一个固定的参考序列。 

任务是计算第一个数组有多少个不同的排列产生的序列按字典顺序小于第二个数组。 这里的词典顺序与词典顺序完全相同：我们从左到右比较两个序列，它们不同的第一个位置决定顺序。 如果一个序列是另一个序列的前缀，则较短的序列被认为较小。 

因此，从概念上讲，我们正在计算多重集的字谜词按字典顺序严格位于给定字符串之前的数量。 

这些约束允许两个序列的长度最多为 200,000，并且值可以大量重复。 这立即排除了枚举排列甚至显式生成部分前缀。 即使是阶乘大小的搜索空间也是完全不可行的。 任何解决方案都必须避免迭代排列，而是对它们进行聚合组合计数。 

当构造的排列与目标字符串的全长匹配但之后更长时，就会出现微妙的边缘情况。 按照字典顺序，如果目标字符串是排列的前缀，则认为排列较大，因此一定不能计算在内。 另一种边缘情况是当重复的值创建许多相同的排列时； 将排列视为不同的序列而不是不同的值模式会导致计数过多，除非使用阶乘除法。 

## 方法

 蛮力的想法很简单：生成多重集的所有不同排列，将每个排列与目标字符串进行比较，并计算有多少个较小。 这是正确的，因为它直接遵循问题的定义。 然而，排列的数量是n！ 除以多重性。 即使 n 约为 20，这也会变得巨大，而当 n 高达 200,000 时，甚至无法表示状态空间。 

关键的观察是词典编排比较可以从左到右逐步确定。 我们可以决定排列与目标不同的第一个位置，而不是构建完整的排列。 在每个位置，我们只关心如果我们在那里放置一个较小的值，则存在多少个有效的完成，同时确保剩余的后缀仍然可以从剩余的多重集形成。 

这将问题简化为计算多重集的约束排列，其中我们固定前缀并使用阶乘比率计算完成的数量。 当我们在概念上构建前缀时，主要困难在于在动态删除元素的情况下有效地维护计数和计算多项式系数。 

因此，解决方案的结构是：迭代目标字符串中的位置，维护剩余频率，并在每一步计算有多少排列以到目前为止匹配的前缀开头但在下一个位置发散到较小的值。 这是通过对仍然具有剩余频率的所有可能的较小符号求和并乘以固定该选择后剩余多重集的排列数量来处理的。 

为了有效地支持这一点，我们预先计算阶乘和模逆，并维护运行的多项式系数。 减少频率时的每次更新都可以使用预先计算的倒数以对数或恒定摊销时间完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳 | 具有组合更新的 O(n·K) | O(K) | 已接受 |

 ## 算法演练

1. 计算第一个数组中每个值的出现频率。 这代表我们正在排列的多重集。 
2. 使用模运算预先计算最多 n 的阶乘和逆阶乘。 这允许快速计算 n! 形式的多项系数。 / (c1!c2!...ck!)。 
3. 计算完整多重集的初始排列数。 这不是直接的答案，但它作为增量更新的基础状态。 
4. 迭代目标数组的位置。 在每个位置 i，我们从概念上尝试决定在排列的第 i 个位置放置什么值。 
5. 对于当前位置，考虑严格小于该位置目标值的所有值。 对于仍然具有正频率的每个此类值 v，暂时将其计数减一并计算可以从剩余多重集形成多少个排列。 将该值添加到答案中。 这会计算与当前前缀匹配但恰好在该位置变小的所有排列。 
6. 考虑完所有较小的选择后，我们检查是否可以匹配该位置的目标值。 如果它的频率为零，我们就提前停止，因为没有排列可以继续匹配该前缀； 所有进一步的排列都已计算或无效。 否则，我们通过降低其频率来修复前缀中的该值并继续。 
7. 如果我们成功完成目标字符串的所有位置，我们不会自动计算剩余的排列，因为只需要严格较小的排列。 这隐式处理前缀条件。 

### 为什么它有效

 该算法保持前缀不变：在每一步，我们都考虑将目标字符串精确匹配到当前索引的排列。 每次我们在位置 i 分支到较小的值时，无论后缀如何，该选择的所有完成都保证在字典顺序上小于目标。 相反，如果我们继续匹配目标值，我们保留相等的可能性并将决策推迟到以后的位置。 这确保了每个排列在与较小方向上的目标不同的第一个位置处被精确地计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, m = map(int, input().split())
s = list(map(int, input().split()))
t = list(map(int, input().split()))

maxv = 200000

cnt = [0] * (maxv + 1)
for x in s:
    cnt[x] += 1

fact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact = [1] * (n + 1)
invfact[n] = modinv(fact[n])
for i in range(n, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def multinom(total):
    res = fact[total]
    for v in cnt_vals:
        res = res * invfact[v] % MOD
    return res

total = n
cnt_vals = cnt[:]
den = 1
for v in cnt_vals:
    den = den * invfact[v] % MOD
ans = 0

for i in range(min(n, m)):
    cur = t[i]

    for v in range(1, cur):
        if cnt_vals[v] == 0:
            continue

        cnt_vals[v] -= 1

        ways = fact[total - 1]
        for x in cnt_vals:
            ways = ways * invfact[x] % MOD

        ans = (ans + ways) % MOD

        cnt_vals[v] += 1

    if cnt_vals[cur] == 0:
        break

    cnt_vals[cur] -= 1
    total -= 1

print(ans)
```代码的核心结构反映了前缀构建过程。 这`cnt_vals`array 代表我们模拟修复前缀时剩余的多重集。 阶乘和逆阶乘数组支持多项计数的快速重新计算。 在每个位置，我们明确尝试所有较小的符号并使用多项式公式计算完成次数。 

一个常见的微妙错误是忘记在位置 i 选择较小的符号后，我们必须在计算排列之前临时修改多重集。 另一种是在目标前缀不再匹配后错误地继续； 早期的休息可以解决这个问题。

 ## 边缘情况

 一种重要的边缘情况是目标字符串比构造的排列短。 在这种情况下，任何与整个目标匹配的排列都会由于额外的长度而在字典顺序上变得更大，因此不能将其计算在内。 该算法自然地避免了这种情况，因为它仅在耗尽目标长度之前累积分歧点的贡献。 

另一种情况是多重集中的所有元素都相同。 然后每个排列都是相同的，因此没有排列可以严格小于目标，除非目标在某个位置上具有较小的值，这可以通过“尝试较小的值”步骤正确处理。 

最后一个微妙的情况是目标的第一个字符已经小于所有可用符号。 该算法正确贡献零，因为在零位置不存在更小的分支，并且匹配根据可行性继续或终止。
