 ## 解决方案
 ## 问题理解

 我们需要安排以下值`0`到`n - 1`排列，以便范围查询的集合获得 MEX 值的最大可能总和。 每个查询询问最终排列中的一段位置，其得分是该段中缺少的最小非负值。 任务是选择小值的去向，因为小值决定了 MEX 可以变得多大。 问题的约束条件是`n <= 5000`和`q <= 100000`。 

大量的查询排除了模拟每种可能的排列，甚至排除了针对每种可能的排列处理每个查询。 自从`n`只有 5000，二次动态规划是现实的，但任何周围的东西`O(n^3)`太大了，因为在最坏的情况下这意味着大约 1250 亿次操作。 需要将查询压缩为有用的信息，以便每个 DP 转换都很便宜。 

关键的边缘情况来自这样一个事实：决定答案的是排列位置，而不是值本身。 粗心的方法可能只会最大化大间隔覆盖的查询数量，而忘记贡献是在每个值前缀之后累积的。 

例如：```
Input
3 3
1 3
2 2
2 3
```答案是：```
6
```一个糟糕的贪婪选择`0`在位置`1`可能看起来不错，因为它有助于全范围查询，但最好的安排是`[2, 0, 1]`。 单位置查询`[2,2]`获得墨西哥`1`， 和`[2,3]`获得墨西哥`2`。 

另一个边缘情况是所有查询都相同。```
Input
4 2
1 4
1 4
```答案是`8`。 

值的每个前缀都在唯一的查询范围内，因此两个查询的最佳可能 MEX 是`4`。 任何只计算最终间隔而忘记中间前缀的算法都会错过重复贡献的因素。 

最终的边界情况是`n = 1`。```
Input
1 1
1 1
```答案是`1`。 唯一的值是`0`，因此该范围包含小于的所有值`1`。 

## 方法

 蛮力方法是尝试直接构建排列。 对于每一个可能的位置`0`，那么每个可能的位置`1`，依此类推，我们就可以计算出分数了。 这显然是正确的，因为每个排列都被考虑了。 然而，有`n!`排列，即使对于非常小的排列也是不可能的`n`。 

一个稍微好一点的蛮力想法是考虑值的位置`0,1,2,...`为了。 放置第一个后`k`值时，MEX 贡献仅取决于这些值中的最小和最大位置。 我们不关心区间内的确切值。 这一观察将状态空间从排列减少到区间。 

下一个见解是，我们总是可以变换最优解，使得值占据的位置`0`通过`k-1`形成一个连续的区间。 如果当前间隔内存在间隙，则将下一个未使用的位置移动到该间隙中不会损害任何未来的前缀。 唯一重要的是扩大当前覆盖的细分市场。 

现在这个过程变成了构建一个段。 在每一步中，我们都会在左侧或右侧添加一个新位置。 对于每个间隔，我们可以预先计算它完全覆盖了多少个查询。 然后DP选择增长间隔的最佳方式。 

蛮力之所以有效，是因为它对每个可能的放置进行了建模，但由于放置的数量激增而失败。 间隔观察让我们只保留影响未来分数的信息。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n!)`|`O(n)`| 太慢了|
 | 最佳|`O(n^2)`|`O(n^2)`| 已接受 |

 ## 算法演练

 1. 预计算`score[l][r]`，范围完全包含该段的查询数`[l, r]`。 这是第一次时添加到答案中的金额`r-l+1`值正好占据这个区间。 该段很重要，因为查询至少获取 MEX`k`恰好当所有值`0`通过`k-1`都在里面。 
2. 创建一个DP表，其中`dpCoosh[l][r]`代表获得第一名后的最高总分`r-l+1`值进入区间`[l, r]`。 当前间隔已经包括该前缀的贡献。 
3. 初始化长度为一的间隔。 如果只是价值`0`已放置，贡献是包含该单个位置的查询数量。 
4. 按长度扩展间隔。 获得`[l, r]`，前一个间隔必须是`[l+1, r]`在左侧添加新位置或`[l, r-1]`右侧添加了一个新位置。 取之前较好的值并相加`score[l][r]`。 
5. 最后的区间是整个数组，因为必须放置所有值。 答案是`dpCoosh[0][n-1]`。 

为什么它有效：

 不变的是，放置第一个之后`k`值，DP 状态准确地描述了所有排列中这些值占据特定长度区间的最佳可能得分`k`。 放置下一个值时唯一可能的更改是将间隔扩大一个位置。 由于每个最佳排列都可以具有连续的前缀，因此过渡涵盖了最佳结构。 添加间隔分数说明了在该前缀长度下创建的新 MEX 贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    cnt = [[0] * n for _ in range(n)]

    queries = []
    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        queries.append((l, r))

    for l, r in queries:
        for i in range(l + 1):
            for j in range(r, n):
                cnt[i][j] += 1

    dpCoosh = [[0] * n for _ in range(n)]

    for i in range(n):
        dpCoosh[i][i] = cnt[i][i]

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            dpCoosh[l][r] = max(dpCoosh[l + 1][r], dpCoosh[l][r - 1]) + cnt[l][r]

    print(dpCoosh[0][n - 1])

if __name__ == "__main__":
    solve()
```查询预处理将输入转换为 DP 可以使用的形式。 对于每个可能的间隔，`cnt[l][r]`存储有多少个查询包含它。 自从`n`只有5000，二次存储是可以接受的。 

DP 表通过增加间隔长度来填充。 长度一间隔仅代表值的位置`0`。 更大的间隔来自于在一侧添加新位置。 顺序很重要，因为两个转换都指的是已经解决的较小间隔。 

代码中的索引从零开始。 最终答案使用`dpCoosh[0][n-1]`因为整个排列都被覆盖了。 Python 整数避免了溢出问题，这很重要，因为答案可以围绕`q * n`。

```每个区间都包含在全范围查询中。 

| 长度 | 间隔| 价值|

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n^2 + n^3)`| DP 是二次的，而简单的预处理会在所有查询范围和所有包含区间上循环。 |
 | 空间|`O(n^2)`| 分数表和DP表都存储区间状态。 |

 预处理可以看作`O(qn^2)`以最直接的形式，但`n = 5000`最好使用较低级语言中的差异数组优化来实现。 上面的 Python 版本在概念上遵循相同的想法，但可能需要针对最严格的环境进行进一步优化。 预期的方法是`O(n^2)`高效间隔计数后的DP。

 ## 边缘情况

 第一个边缘情况是必须将一个小值放置在数组中间附近，因为许多查询更喜欢该区域。 为了：```
3 3
1 3
2 2
2 3
```DP给出`[2,2]`作为一个间隔的最佳长度，因为它有分数`2`。 然后区间扩大为`[2,3]`最后`[1,3]`，生产`6`。 

第二种边缘情况是重复相同的查询。 和：```
4 2
1 4
1 4
```每个间隔都会从两个查询接收相同的覆盖范围。 DP 计算长度一到四的贡献，给出`2 + 2 + 2 + 2 = 8`。 仅评估最终排列的解决方案会低估分数。 

最后一个边缘情况是单元素排列：```
1 1
1 1
```唯一可能的区间是`[1,1]`。 基础转换直接分配其分数，最终答案为`1`。
