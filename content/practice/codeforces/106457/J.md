 ## 解决方案
 ## 问题理解

 我们收集了`n`序列。 每个序列包含包含区间中的每个整数`[a_i, b_i]`。 间隔可能会重叠，当参赛者合并他们的作品时，相同的数字会出现多次。 最终列表是按非降序排序的所有间隔的多重集并集。 

对于每个查询，我们都会在这个排序多重集中得到一个位置，并且必须找到存储在该位置的值。 位置可以非常大，因为合并列表中的元素总数可以达到`10^14`，因此明确构建列表是不可能的。 

重要的约束是间隔和查询的数量，两者最多`10^5`，而区间端点可以达到`10^9`。 处理每个间隔内的每个数字的解决方案可能需要大约`10^14`的操作，远远超出了极限。 即使对所有生成的值进行排序也是不可能的，因为生成的值的数量是间隔长度的总和，而不是间隔的数量。 

思考查询的一个有用方法是提出一个不同的问题：对于一个值`x`, 合并列表中有多少个数字小于或等于`x`？ 如果我们能够快速回答这个问题，我们就可以对答案值进行二分搜索。 挑战在于有效地回答许多此类计数查询。 

有几种边缘情况会破坏更简单的实现。 重叠的间隔必须保留重复的值。 例如：```
2 3
1 3
3 5
1 2 3
```合并后的列表为：```
1 2 3 3 4 5
```输出是：```
1
2
3
```将间隔合并为集合的粗心解决方案会产生`1 2 3`并丢失重复的`3`。 

长度为 1 的间隔也必须正确处理。 例如：```
1 2
7 7
1 2
```唯一的序列包含一个数字，因此位置的答案`1`是`7`。 错误地将间隔视为半开范围会完全删除该值。 

靠近最大可能位置的查询也需要小心：```
2 2
1 1000000000
5 5
1000000000 1000000001
```最后一个有效位置是`1000000001`，它的答案是`1000000000`。 任何使用 32 位整数进行计数的实现都会溢出，因为多重集的总大小可能超过`10^9`。 

## 方法

 直接的方法是从每个间隔生成每个值，存储它们，对它们进行排序，并通过索引到已排序的数组来回答查询。 这是正确的，因为它确实构造了所需的合并序列。 然而，像这样的区间`[1, 10^9]`已经包含十亿个值。 和`10^5`间隔，生成的大小可以达到大约`10^14`，所以这种方法甚至无法完成数据的存储。 

关键的观察是我们不需要合并列表本身。 对于候选值`x`，每个间隔都会为前缀计数贡献一个简单的量。 

一个区间`[a, b]`贡献：`0`什么时候`x < a`。`x - a + 1`什么时候`a <= x <= b`。`b - a + 1`什么时候`x > b`。 

所以每个查询都可以通过找到最小的来解决`x`其前缀计数至少是所请求的位置。 剩下的问题是如何快速计算这些前缀计数。 

可以通过扫描所有间隔来回答单个计数查询，但是为每个二分搜索步骤单独执行此操作仍然太慢。 相反，我们一起处理所有二分搜索。 

并行二分搜索为每个查询保留一系列可能的答案。 在每一轮中，每个未解决的查询都会选择一个中点。 我们对这些中点进行排序，并在一次扫描间隔中评估所有这些中点。 这减少了重复工作`O(nq)`粗略地`O((n+q)log(10^9))`。 

扫描保持描述当前活动间隔的贡献的线性函数。 间隔开始添加一个术语`x - a + 1`，而间隔结束后的位置将该间隔转换为恒定贡献。 由于所有中点值均按升序处理，因此每个事件每轮仅应用一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(总间隔长度 + q) | O(总间隔长度) | 太慢了|
 | 最佳| O((n + q) log 10^9) | O((n + q) log 10^9) | O(n + q) | 已接受 |

 ## 算法演练

 1. 将每个间隔存储为两个扫描事件。 在位置`a`，间隔开始贡献`x - a + 1`。 在位置`b + 1`，其贡献变为常数`b - a + 1`。 

这种表示方式使我们能够评估许多前缀计数，而无需触及区间内的每个整数。 
2. 对于每个查询，保留可能答案的二分搜索范围。 最初的范围是从`1`到`10^9`。 

答案是前缀计数达到所需排名的第一个值。 
3. 重复二分查找循环。 对于仍具有多个可能值的每个查询，计算其中点并收集所有中点。 

一起处理所有中点使得解决方案足够快。 
4. 对中点值进行排序并使用间隔事件扫描它们。 维持三个价值观：

 活动间隔的当前斜率。 

活动间隔的当前截距。 

来自已经结束的间隔的持续贡献。 

位置计数`x`是：`slope * x + intercept + constant`。 
5. 对于每个中点，将计算出的前缀计数与查询排名进行比较。 如果计数足够大，则答案位于该中点或之前。 不然的话就更大了。 
6.经过足够多的轮次后，每个查询范围都恰好包含一个值。 输出该值。 

为什么它有效：

 二分查找是有效的，因为前缀计数函数是单调的。 增加`x`只能向前缀添加更多数字，而不能删除它们。 扫描通过将每个间隔分为三种可能的状态来计算完全相同的前缀计数函数：未开始、活动和完成。 由于每个中点都使用相同的区间贡献规则进行评估，因此每个二分搜索决策都保留了真实的答案范围。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    events = []
    for _ in range(n):
        a, b = map(int, input().split())
        events.append((a, 1, 1 - a))
        events.append((b + 1, -1, b - a + 1))

    events.sort()

    queries = list(map(int, input().split()))

    lo = [1] * q
    hi = [10**9] * q

    def count_values(points):
        points.sort()
        ans = [0] * len(points)

        slope = 0
        intercept = 0
        constant = 0
        event_index = 0

        for value, idx in points:
            while event_index < len(events) and events[event_index][0] <= value:
                pos, ds, di = events[event_index]
                if ds == 1:
                    slope += 1
                    intercept += di
                else:
                    slope -= 1
                    constant += di
                    intercept += di - di
                event_index += 1
            ans[idx] = slope * value + intercept + constant

        return ans

    while True:
        mids = []
        active = False

        for i in range(q):
            if lo[i] < hi[i]:
                active = True
                mids.append(((lo[i] + hi[i]) // 2, i))

        if not active:
            break

        counts = count_values(mids)

        for (_, i), cnt in zip(sorted(mids), counts):
            if cnt >= queries[i]:
                hi[i] = (lo[i] + hi[i]) // 2
            else:
                lo[i] = (lo[i] + hi[i]) // 2 + 1

    print("\n".join(map(str, lo)))

if __name__ == "__main__":
    solve()
```事件构建是核心实现细节。 开始事件会增加活动间隔的数量并添加相应的截距调整。 结束事件从活动线性部分中删除间隔，并将其整个长度移动到恒定贡献中。 

二分搜索数组仅存储可能的值，而不存储计数。 中点评估决定哪一半仍然有效。 

数值可以达到`10^14`当计算元素时，Python 整数在这里很有用，因为它们会自动避免溢出。 该代码还避免了完全创建合并序列。 

一个微妙的点是结束事件发生在`b + 1`， 不是`b`。 在`b`该区间仍然通过其线性公式做出贡献。 只有在下一个值时，它才应成为持续的贡献。

 ## 边缘情况

 对于重叠间隔，例如：```
2 3
1 3
3 5
1 2 3
```扫描创建一个开始事件`1`和`2`，然后结束事件`3`和`5`。 当中点达到`3`，两个间隔仍然通过其活动公式做出贡献，因此前缀计数包括两个副本`3`。 

对于单值区间：```
1 2
7 7
1 2
```间隔开始于`7`并结束于`8`。 价值`7`在间隔处于活动状态时进行计数，并且结束事件直到其之后才发生，因此答案仍然存在`7`。 

对于最大边界情况：```
2 2
1 1000000000
5 5
1000000000 1000000001
```第一个查询收敛到长间隔内的最后一个值。 第二个查询达到第二个间隔的额外值。 前缀计数器处理两者，因为它从不扩展间隔，它只评估其贡献公式。
