 ## 解决方案
 ## 问题理解

 我们有一个加权无向城市网络，其中每个城市都包含一定数量的科学家。 科学家可以沿着城市之间的道路旅行，支付沿途的边缘成本总和。 我们可以选择一个城市作为会议地点，每个科学家最终都必须到达那个城市。 每个科学家独立旅行并为自己的最短路径付费。 

任务是选择会议城市，以使所有科学家的总旅行成本最小化。 

输入描述了最多包含 250 个节点和最多 40,000 条边的加权图。 由于所有边权重均为正，因此最短路径是明确定义的，并且可以使用 Dijkstra 或 Floyd-Warshall 进行计算。 每个城市的科学家总数可能高达 10^7，因此贡献必须汇总，而不是单独模拟。 

关键的隐藏结构是每个科学家独立贡献，因此如果科学家从城市 u 开始，相遇城市为 v，则成本贡献为 dist[u][v]。 选择 v 的总成本成为所有城市的加权总和。 

一个天真的错误是认为我们需要模拟流动或构建最小跨越结构。 另一个常见的错误方向是尝试使用图启发法（例如度数或偏心率）来选择“中心”； 这些失败是因为重量很重要并且需求不均匀。 

启发式失败的一个小例子：

 输入：

 n = 3, c = [100, 1, 1]

 边缘：

 1-2 成本 100, 2-3 成本 1, 1-3 成本 100

 如果我们选择城市 1 是因为从天真的意义上来说它似乎是中心城市，那么成本会很大，因为 100 名科学家要长途跋涉。 最佳答案是城市 2 或 3，具体取决于距离； 加权最短路径占主导地位。 

另一个微妙的问题是思维脱节。 如果有人试图独立处理边缘而不计算全局最短路径，他们就会错过间接的更便宜的路线。 

## 方法

 蛮力的想法很简单。 对于遇到城市 v 的每个候选者，计算从每个城市 u 到 v 的最短路径距离。然后将 dist[u][v] 乘以 c[u] 并对所有值求和。 最后取v上的最小值。 

这是正确的，因为每个科学家都贡献了到达所选交汇点的最短路径成本。 瓶颈是计算从每个源或到每个目的地的最短路径。 从每个节点运行 Dijkstra 的成本为 O(n (m log n))，这是临界值，但在这里仍然没问题。 然而，由于 n 只有 250，我们可以进一步推进并更直接地计算所有对的最短路径。 

关键的观察结果是我们不需要运行 Dijkstra n 次。 Floyd-Warshall 是可行的，因为 n 很小。 一旦我们计算出所有对的最短路径，计算答案就变成了对所有对的简单聚合。 

我们将问题简化为经典的全对最短路径+加权列和问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 来自每个节点的 Brute Dijkstra | O(n m log n) | O(n m log n) | O(n^2) | O(n^2) | 已接受但沉重|
 | 弗洛伊德·沃歇尔 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1. 构建距离矩阵`dist`除了对角线上的零之外，所有对都初始化为无穷大。 该矩阵代表任意两个城市之间最知名的旅行成本。 
2. 将所有边作为初始直接距离插入矩阵中。 由于道路是双向的，因此设置两个方向。 
3. 在所有三元组节点上运行 Floyd-Warshall。 对于每个中间节点 k，尝试使用 i → k → j 改进路径 i → j。 此步骤逐渐合并更长的间接路线。 
4. 计算出所有最短路径后，将每个城市 v 视为潜在的交汇点。 对于每个 v，通过对所有 u 求和 c[u] * dist[u][v] 来计算总成本。 
5. 返回所有 v 中此类总数的最小值。 

Floyd-Warshall 在这里工作顺利的原因是 n 足够小，O(n^3) 更新是可行的，并且由于需要评估每个可能的相遇城市，我们无论如何都需要所有对距离。 

### 为什么它有效

 对于每个固定的会面城市v，从任意城市u到v的最优成本独立于所有其他选择； 它正是正加权图中的最短路径距离。 Floyd-Warshall 保证在处理完所有中间体后，dist[u][v] 是 u 和 v 之间的最小可能路径成本。对这些独立正确的贡献求和会产生全局最优值，因为问题在源上线性分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

n, m = map(int, input().split())
c = list(map(int, input().split()))

dist = [[INF] * n for _ in range(n)]
for i in range(n):
    dist[i][i] = 0

for _ in range(m):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    if w < dist[u][v]:
        dist[u][v] = w
        dist[v][u] = w

for k in range(n):
    dk = dist[k]
    for i in range(n):
        di = dist[i]
        for j in range(n):
            if di[j] > di[k] + dk[j]:
                di[j] = di[k] + dk[j]

ans = INF
for v in range(n):
    total = 0
    for u in range(n):
        total += c[u] * dist[u][v]
    ans = min(ans, total)

print(ans)
```实现首先构建一个密集矩阵，这是 Floyd-Warshall 实现其立方结构所必需的。 由于允许多条边，邻接初始化仅保留两个节点之间的最小边。 

三重循环通过预取行引用来稍微改善缓存局部性。 松弛条件是标准的最短路径更新。 

最后，我们计算加权列总和。 从概念上讲，乘法使用 64 位整数； Python 可以安全地处理大整数，但值仍然保持在可管理的范围内。

 | 测量| 复杂性 | 说明|

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    INF = 10**18

    n, m = map(int, input().split())
    c = list(map(int, input().split()))

    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        dist[u][v] = min(dist[u][v], w)
        dist[v][u] = min(dist[v][u], w)

    for k in range(n):
        for i in range(n):
            for j in range(n):
                if dist[i][j] > dist[i][k] + dist[k][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]

    ans = 10**18
    for v in range(n):
        total = 0
        for u in range(n):
            total += c[u] * dist[u][v]
        ans = min(ans, total)

    return str(ans)

 ## 边缘情况

 单节点图是最干净的压力测试。 当 n = 1 且 c[1] 任意时，答案必须为零，因为不需要行程。 该算法初始化 dist[0][0] = 0，u 上的最终总和为 c[0] * 0，正确生成零。 

带有重叶的星形图测试算法是否正确地选择中心节点。 由于从叶子开始的所有最短路径都经过中心，Floyd-Warshall 可以快速稳定距离，并且加权和正确地反映了选择中心可以最小化总加权距离。 

同一对节点之间存在多条路径的图检查我们是否始终保留最小边。 初始化步骤为`min(dist[u][v], w)`确保平行边不会破坏最短路径计算，然后 Floyd-Warshall 根据这些基值构建正确的全局距离。
