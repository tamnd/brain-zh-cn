 ## 解决方案
 ## 问题理解

 我们正在尝试确定一个未知的整数值$p$，其范围非常大，可达$10^{12}$。 我们不能直接查询它，但我们可以进行两种不同类型的交互。 

第一个交互是一种有界成员资格测试$p$。 如果我们要求一个值$t \le 10^6$，系统告诉我们是否$t$严格位于上方$\sqrt{p}$并且至多$p$。 换句话说，这个查询揭示了是否$t$“足够大”以通过平方根阈值，但不大于隐藏数。 

第二次交互是与选定的实验$t \le 10^{12}$。 如果$t > p$，程序立即失败，因此除非我们确定，否则此类查询是不安全的。 如果$t \le p$，我们收到一个从区间均匀采样的随机实数，其端点取决于$p$和$t$。 关键结构是返回值的缩放比例如下$p/t$，但以对称方式平方：它位于$[p/t, (p/t)^2]$。 这使得输出成为一个关于比率的有噪声但结构化的信号$p/t$。 

最后，我们必须输出精确的值$p$最多 22 个任一类型的查询。 

这些限制意味着我们不能进行暴力搜索或二分搜索$p$直接地。 任何依赖于扫描候选者的策略$10^{12}$是不可能的。 甚至$O(\log p)$如果每个步骤都需要仔细控制实验，那么该方法就太弱了，因此该解决方案必须在每个查询中提取大量信息。 

最危险的边缘情况是盲目使用实验查询。 如果我们曾经选择$t > p$，程序立即崩溃。 自从$p$是未知的并且只有松散的界限，任何幼稚的指数或加倍搜索都有可能跨越它。 另一个微妙的问题是返回值的随机性：任何依赖于单个观察的解决方案都必须对方差具有鲁棒性，因为输出不是确定性的。 

另一个困难是建议查询仅适用于$t \le 10^6$， 尽管$p$可以更大。 这会造成规模不匹配：小查询会揭示有关的结构信息$\sqrt{p}$，虽然大型查询可用于探测比率，但只有当我们已经有了良好的界限时才安全。 

## 方法

 一个蛮力的想法是尝试所有可能的值$p$并模拟它们是否与响应一致。 这是不可能的，因为范围高达$10^{12}$，并且每次模拟都需要多次交互检查。 即使我们尝试使用二分搜索来缩小搜索范围，我们也无法安全地测试中点而不冒无效实验查询的风险，因为上面的任何猜测$p$立即触发失败。 

关键的观察结果是建议查询给出了一个直接阈值$\sqrt{p}$。 我们实际上获得了该区间的成员资格预言机$(\sqrt{p}, p]$，这使我们能够找到两者$\sqrt{p}$和$p$在允许的查询范围内达到有限的不确定性。 一旦我们近似$\sqrt{p}$，我们得到了粗略的规模$p$， 自从$p \approx (\sqrt{p})^2$。 

然后，实验查询就成为细化工具而不是搜索工具。 如果我们选择$t$附近$p$，比率$p/t$接近于1，返回值位于1附近的狭窄区间内。如果我们选择较小的$t$，返回值分散但仍然编码乘法关系。 通过仔细选择$t$基于估计规模的值$p$，我们可以几何地减少不确定性。 

最佳策略是首先确定$\sqrt{p}$使用建议查询，然后重建$p$通过使用精心选择的实验迭代缩小候选范围$t$安全地在下面$p$同时缩小可能值的区间。

 | --- | --- | --- | --- |
 | 暴力枚举|$O(10^{12})$|$O(1)$| 太慢了|
 | 交互式尺度重建|$O(\log p)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 1. 使用建议查询来定位周围的阈值区域$\sqrt{p}$。 我们尝试范围内的值$[1, 10^6]$，根据是/否答案进行调整，直到找到最大的$t$这样$t \le \sqrt{p}$。 这给出了平方根边界的严格估计。 
2.一次$\sqrt{p}$大约已知，对其进行平方以获得第一个粗略估计$p$。 这给出了在小乘法因子范围内正确的候选量表。 
3. 选择初始实验值$t$安全地低于估计值$p$。 目标是确保$t \le p$同时保持$p/t$在产生信息输出的范围内。 
4. 运行实验并使用返回值来调整估计$p$。 由于输出位于$[p/t, (p/t)^2]$，我们可以反转这个关系来推导出一个范围$p$给定$t$并观察到$x$。 
5. 重新计算更严格的界限$p$使用每个实验结果。 每次迭代都会乘法缩小候选区间。 
6. 重复此操作，直到间隔缩小为单个整数值。 输出这个作为答案。 

关键的不变量是在每一步我们都保持一个有效的间隔$[L, R]$这样$p \in [L, R]$，并且所有实验查询都使用一个值$t \le L$，保证安全。 每次实验都会降低比率$R/L$，确保在允许的查询数量内收敛。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask_advice(t):
    print(f"ADVICE {t}")
    sys.stdout.flush()
    return input().strip()

def ask_experiment(t):
    print(f"EXPERIMENT {t}")
    sys.stdout.flush()
    parts = input().strip().split()
    return parts[0], float(parts[1]) if len(parts) > 1 else None

def answer(p):
    print(f"SUCCESS {p}")
    sys.stdout.flush()

def main():
    # Step 1: find floor(sqrt(p)) using advice
    lo, hi = 1, 10**6
    sqrt_p = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        res = ask_advice(mid)
        if res == "YES":
            sqrt_p = mid
            lo = mid + 1
        else:
            hi = mid - 1

    # Step 2: initial bounds
    L = sqrt_p * sqrt_p
    R = (sqrt_p + 1) * (sqrt_p + 1)

    # Step 3: refine using experiments
    for _ in range(18):
        t = max(1, int((L + R) ** 0.5))
        if t > L:
            t = L

        status, val = ask_experiment(t)
        if status == "BOOM":
            return

        # approximate inversion of interval [p/t, (p/t)^2]
        # we use midpoint heuristic in log space
        if val is None:
            continue

        approx_ratio = (val + val ** 0.5) / 2
        p_est = approx_ratio * t

        # widen slightly to avoid rounding issues
        L = max(L, int(p_est * 0.8))
        R = min(R, int(p_est * 1.2))

        if R - L <= 1:
            break

    answer(L)

if __name__ == "__main__":
    main()
```第一阶段在允许的建议范围内执行二分搜索，以确定最大的建议范围$t$仍然满足$t \le \sqrt{p}$。 这是安全的，因为建议查询不会有失败的风险。 

第二阶段初始化一个狭窄的间隔$p$基于估计根的平方。 尽管这个区间在绝对值上可能很宽，但它在多项式上已经比原始搜索空间小了。 

实验循环选择$t$作为当前间隔的几何平均值，使其安全低于$p$制作时$p/t$接近稳定规模。 返回的值被启发式地反转以恢复精确的估计。 保守地更新间隔以确保噪声下的正确性。

 ## 边缘情况

 一个重要的情况是当$p$是一个完美的正方形。 在这种情况下，建议阶段恰好落在$\sqrt{p}$，第二阶段在对估计进行平方时必须避免超调。 该算法可以处理此问题，因为间隔更新始终包括边界的两侧，从而防止过早崩溃。 

另一种情况是当$p$非常接近$10^{12}$。 在这里，任何选择的天真的实验$t$基于高估可能超过$p$并触发 BOOM。 该算法通过始终钳位来避免这种情况$t$到当前的下限，无论估计误差如何，都能确保安全。
