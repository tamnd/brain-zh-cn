 ## 解决方案
 ## 问题理解

 我们维护一个动态的字符串集合，这些字符串属于两个不同的组：Barbies 和 Kens。 每次更新要么将字符串插入其中一个组中，要么删除先前插入的字符串。 每次更新后，我们必须报告通过从 Barbie 集中取出一个字符串和从 Ken 集中取出一个字符串可以形成多少个有效对，这样它们的串联形成一个回文。 

计算的关键对象不是单个字符串，而是跨组对。 如果一根芭比绳`b`和一根肯弦`k`被选择，我们检查是否`b + k`向前读和向后读都一样。 每次操作后的答案是所有当前字符串中此类有效对的总数。 

制约因素主要体现在两个方面。 操作数量可以达到一百万，因此任何解决方案都必须在接近恒定的时间内处理每个更新。 同时，所有插入字符串的总长度上限为 500 万，这意味着任何在更新之间重复比较完整字符串的方法都将因每次操作的线性扫描而失败。 

一种简单的方法是在每次更新后通过检查两组之间的所有对来从头开始重新计算答案。 如果有`n`芭比娃娃和`m`肯斯，这是`O(nm)`每个查询，即使对于中等大小，这也会很快变得不可行。 即使通过预先计算反向字符串进行优化仍然会留下二次配对问题。 

当更新频繁删除时，幼稚散列方法会出现微妙的失败情况。 例如，如果我们重复添加和删除相同的字符串，则每次重新计算所有对都会重复遍历整个数据集，即使净变化很小。 

另一个常见的错误是假设回文性只需要比较字符或每对使用滚动哈希。 即使使用散列，每个查询重新计算所有交叉对仍然太慢。 

## 方法

 核心观察是串联对称性强加了非常严格的结构。 对于两个字符串`b`和`k`, 字符串`b + k`是回文当且仅当第二个字符串与第一个字符串完全相反。 这是从匹配串联边界上的对称位置得出的：中的每个字符`b`必须镜像一个角色`k`以相反的顺序，不为部分重叠留下灵活性。 

这将问题简化为频率匹配任务。 我们不需要检查所有对，只需知道每个字符串在 Barbies 中出现了多少次，以及其反转版本在 Kens 中出现了多少次。 每次更新仅影响一个字符串，因此我们可以增量地维护计数。 

暴力方法尝试在每次更新后重新计算所有有效对，迭代两组中所有存储的字符串。 这在概念上是有效的，因为它直接评估定义，但每次操作花费的时间是平方的。 关键的见解是每个字符串都是独立贡献的，因此我们可以维护一个运行总计，并通过添加或删除与该字符串反向相关的贡献来在每次更新的恒定时间内调整它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O(nm) | O(n + m) | 太慢了|
 | 最佳| 每个查询 O(L) | O(n + m) | 已接受 |

 这里`L`是更新后的字符串的长度。 

## 算法演练

 我们维护两个哈希图，计算 Barbies 和 Kens 中字符串的出现次数，以及有效对的运行总数。 

1. 初始化两张频率图，一张为 Barbies，一张为 Kens，并将答案设置为零。 映射存储每个确切字符串当前出现的次数。 
2. 对于每个操作，读取类型、组和字符串。 在修改任何结构之前，请计算该字符串（如果添加或删除）的贡献。 这确保我们正确更新全局计数。 
3. 如果操作是插入 Barbies，则计算当前有多少 Ken 等于该字符串的反转。 这个值是`freqKen[reverse(b)]`，然后我们将其添加到答案中。 然后递增`freqBarbie[b]`。 
4、如果操作是从Barbies中删除，先减1`freqBarbie[b]`，然后减去`freqKen[reverse(b)]`从答案中。 减法反映了字符串先前添加的贡献。 
5. 同样的逻辑对称地适用于 Kens：插入相加`freqBarbie[reverse(k)]`，删除减去它。 
6. 每次操作完成后，输出当前答案。 

在删除过程中，减少的顺序与贡献删除的顺序很重要。 我们必须使用字符串仍然存在的状态来计算贡献，然后将其删除，否则我们会丢失正确的计数。 

### 为什么它有效

 该算法保持不变式`answer`始终等于所有芭比字符串的总和`b`的`freqBarbie[b] * freqKen[reverse(b)]`。 每次更新都会准确地更改一个频率条目，因此会根据该字符串相对于反向匹配的贡献准确地更改总和。 由于所有其他对不受影响，因此在本地调整总数就足够了，并且可以在所有操作中保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    from collections import defaultdict
    
    barbie = defaultdict(int)
    ken = defaultdict(int)
    ans = 0
    
    out = []
    
    for _ in range(t):
        parts = input().split()
        if not parts:
            continue
        
        tp = parts[0]
        grp = parts[1]
        s = parts[2].strip()
        
        rs = s[::-1]
        
        if grp == '+':
            if tp == '1':
                ans += ken[rs]
                barbie[s] += 1
            else:
                ans += barbie[rs]
                ken[s] += 1
        else:
            if tp == '1':
                barbie[s] -= 1
                ans -= ken[rs]
            else:
                ken[s] -= 1
                ans -= barbie[rs]
        
        out.append(str(ans))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```实现上直接遵循增量更新策略。 每个操作计算一次反向字符串，这在总长度约束下是有效的。 哈希映射确保频率更新和查询的恒定时间预期访问。 

关键的微妙之处在于，贡献始终基于反向字符串，而不是部分匹配或子字符串逻辑。 这就是使解决方案在任意插入和删除下保持稳定的原因。

 ## 边缘情况

 一种重要的边缘情况是重复插入和删除同一字符串。 该算法可以处理此问题，因为每次插入都会精确添加当前反向匹配的数量，而每次删除会精确删除相同数量的反向匹配。 即使该字符串出现多次，频率图也能确保贡献正确缩放。 

另一种边缘情况是当一个字符串与其自身相反时，例如`"aba"`。 在这种情况下，只有跨组频率很重要，并且相同的逻辑无需修改即可应用，因为`reverse(s) == s`。 

最后一种情况是所有字符串都是唯一的。 该算法仍然有效，因为每次更新只涉及一个字典条目，因此答案纯粹通过局部调整而演变，而不需要任何全局重新计算。
