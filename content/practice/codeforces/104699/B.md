 ## 解决方案
 ## 问题理解

 我们得到了一排房间，每个房间都包含一定数量的员工。 员工只能在相邻的房间之间移动，目标是将每个人聚集到一个选定的房间中。 将一名员工从一个房间移动到下一个房间需要花费一个单位的“努力”，如果一名员工移动多个房间，则每一步的成本都会累积。 

任务是选择最终的聚集室，使所有员工的总移动成本最小化。 

从计算的角度来看，输入大小高达二十万个房间，因此任何尝试所有成对运动或模拟每个可能目的地的运动的方法都会太慢。 二次或更差的解决方案将立即失败，因为在最坏的情况下它需要大约 10^10 次运算。 

这个问题的一个微妙的方面是，每个员工都独立地为总成本做出贡献，但他们的贡献取决于所选择的目的地。 这创建了一个结构，其中每个位置都会产生加权距离成本，这表明预计算或基于前缀的推理而不是模拟。 

倾向于打破朴素推理的边缘情况包括均匀数组，其中每个位置都是同样最优的，成本是对称的，以及偏斜分布，其中所有员工都集中在一端，如果错误地推理了计数而不是加权距离，则最佳交汇点远离朴素中点。 例如，如果所有员工都已经在一个房间里，例如`[10, 0, 0, 0]`，答案是`0`，因为不需要移动。 如果错误地处理自身距离或重复计算转换，总是错误地假设移动或重新计算的天真的方法可能仍然会累积非零成本。 

## 方法

 蛮力策略很简单。 我们尝试每一个可能的房间作为最终目的地。 对于每个候选房间，我们通过将所有房间中的员工数量乘以到候选者的距离相加来计算成本。 距离只是指数的绝对差。 

这是有效的，因为每个员工独立地贡献与他们移动距离成比例的线性成本。 然而，这种直接评估的成本很高。 对于 n 个可能的目的地中的每一个，我们扫描所有 n 个位置，进行 O(n^2) 次操作。 当 n 达到 2 × 10^5 时，这大约变成 4 × 10^10 次操作，这远远超出了任何可行的限制。 

关键的观察结果是成本函数具有非常结构化的形式。 如果我们固定目标位置 i，则成本为：

 a[j] × |i − j| 的 j 之和

 这是直线上的经典加权绝对偏差问题。 我们可以维护前缀信息：左边和右边有多少员工，以及他们的累计位置，而不是从头开始重新计算每个 i 的总和。 然后我们可以从前一个位置导出下一个位置的成本，时间复杂度为 O(1)。 

当我们将交汇点从 i 移至 i+1 时，只有所有组的贡献以可预测的方式发生变化：左侧的员工进一步移动一个单位，右侧的员工靠近一个单位。 这使我们能够增量更新总成本，而不是重新计算它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 前缀/增量成本| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个位置视为潜在的交汇点，但我们不是独立地重新计算成本，而是首先计算位置 0 的成本，然后在数组中“滑动”交汇点。 

1. 计算所有房间的员工总数。 这代表当交汇点改变时最终将移动的全部质量。 
2. 假设每个人都聚集在位置 0 处，计算初始成本。这是通过对所有 i 求和 a[i] × i 来完成的。 这是可行的，因为索引 i 处的每个员工都必须移动 i 步才能到达位置 0。 
3. 维护两个运行值：当前有多少员工在所选集合点的左侧，以及有多少员工在右侧。 最初，在位置 0 处，所有员工都位于右侧。 
4. 将集合点从左向右移动一个位置。 当从i移动到i+1时，i+1左边的所有员工都变远了一步，而右边的所有员工都变近了一步。 
5. 使用此关系更新成本。 如果我们将 left_count 表示为 [0, i] 中的员工，将 right_count 表示为 (i, n−1] 中的员工，则从 i 到 i+1 的转换会通过将左贡献增加 left_count 并减少右贡献 right_count 来改变成本。
 6. 跟踪所有头寸的最低成本。 

关键思想是每一步都会在恒定时间内更新总距离，仅依赖于计数而不是重新计算距离。 

### 为什么它有效

 该算法保持了不变式，即在位置 i，我们正确地知道将每个人聚集到那里的总移动成本，并且我们还知道有多少员工位于 i 的左侧和右侧。 从 i 移动到 i+1 时成本的变化仅取决于每组距离如何精确地改变一个单位，并且这些变化在计数上线性聚合。 由于除了 i 和 i+1 之间的边界外，没有员工改变立场，因此更新公式准确地捕获了总成本的所有变化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    
    # cost if meeting at position 0
    cost = 0
    for i in range(n):
        cost += a[i] * i
    
    best = cost
    
    left = a[0]
    right = total - a[0]
    
    for i in range(1, n):
        # move meeting point from i-1 to i
        cost += left          # all left side moves 1 step further
        cost -= right         # all right side moves 1 step closer
        
        best = min(best, cost)
        
        left += a[i]
        right -= a[i]
    
    print(best)

if __name__ == "__main__":
    solve()
```该代码首先计算将所有人聚集到零位置的成本，即加权距离之和。 然后，它会迭代地将交汇点向右移动。 变量 left 和 right 跟踪当前会议位置每一侧有多少员工，这对于 O(1) 更新规则至关重要。 更新内容`cost += left - right`反映将交汇点移动一个单位时总距离的净变化。 

一个常见的实施陷阱是在应用成本转换之前错误地更新左右，这会改变不变量并导致相差一的错误。 另一个微妙的问题是忘记了初始左组仅包含 [0]，因为交汇点从索引 0 开始。

## 测试用例```python
import sys, io

def solve():
    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    cost = sum(a[i] * i for i in range(n))
    
    best = cost
    left = a[0]
    right = total - a[0]
    
    for i in range(1, n):
        cost += left - right
        best = min(best, cost)
        left += a[i]
        right -= a[i]
    
    return str(best)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 边缘情况

 一种极端情况是所有员工都集中在一个房间里。 用于输入`4 0 0 0 10`，如果在索引 0 处计算，算法以成本 30 开始，但当交汇点到达最后位置时，滑动更新会立即将成本降低到 0。 该不变量确保不会计算不必要的移动，因为 right_count 在最终位置变为零。 

另一种情况是分布均匀时，例如`5 5 5`。 成本函数变得对称，最小值出现在中心位置。 滑动机制以平衡增量更新成本：left_count 和 right_count 在中心周围保持相等，使成本更改适当取消，直到达到记录最小值的中点。 

第三种情况是 n = 1。算法将成本初始化为零，并且从不进入循环。 由于不存在可能的移动并且左/右分解是退化的，所以该不变量是微不足道的。
