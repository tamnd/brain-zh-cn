 ## 解决方案
 ## 问题理解

 我们正在构建一个一维的房间序列，每个房间占据一个固定的水平部分，但可以自由地将每个房间垂直放置在受限的间隔内。 房间`i`占据一个水平条带`(i-1)·a`到`i·a`，并且垂直方向上它必须完全位于高度之间`l_i`和`h_i`。 每个房间都有高度`b`，所以如果它的底部放置在高度`x`，则占据的垂直间隔为`[x, x + b]`，并且这个区间必须满足`l_i ≤ x`和`x + b ≤ h_i`。 

所以每个房间都贡献一个垂直段，但该段不是固定的。 我们可以在一个范围内滑动它，目标是在连续的房间中对齐这些滑动间隔，以便存在一条水平线`y`与连续的房间块相交，始终保持在其垂直跨度内。 

换言之，对于每个房间，我们为其底部端点提供一个允许的垂直段，这会为任何固定的水平切片引入一个允许的段。 如果我们固定一个高度`y`，然后房间`i`如果我们可以放置它的间隔以便`y`位于其内部，相当于要求`y ∈ [l_i, h_i - b]`。 楼层高度为 1 的有效走廊`y`在一个连续的段上`[i, j]`存在当且仅当`y`位于所有区间内`i..j`。 问题简化为找到间隔交集非空的最长连续子数组。 

约束条件达到`n = 10^6`，因此任何尝试所有子段或重新计算每个端点交点的二次方法都会立即失败。 我们需要本质上线性的扫描，因为`O(n log n)`是临界值，但通常只有当常数很小时才可以接受； 这里有一个严格的`O(n)`滑动技术是自然的目标。 

一个微妙的点是，走廊的高度为 1，但房间的高度为`b`。 该条件不是关于完全相等，而是关于该段中的所有房间存在一致的垂直位置。 

重要的边缘情况是间隔几乎没有接触的片段，尤其是当`h_i - b`等于`l_j`，这意味着存在一条走廊，但仅在一个高度。 另一个棘手的情况是，当某些房间的允许间隔极其严格或退化时，会立即破坏通过它们的任何段。 

## 方法

 蛮力的想法很简单：尝试每个起始索引`i`， 延长`j`向前，并保持所有有效垂直区间的交集`[L, R]`， 在哪里`L = max l_k`和`R = min (h_k - b)`超过该段。 立刻`L > R`，该段断裂。 我们用看到的最大长度更新答案。 

这是正确的，因为当所有可行垂直位置的交集非空时，走廊恰好存在。 然而，维护交叉点仍然需要向前扫描每个`i`，导致`O(n^2)`最坏情况下的更新。 和`n = 10^6`，这变成了大约`10^12`操作，远远超出了限制。 

关键的观察结果是，可行性条件仅取决于下界的运行最大值和上限的运行最小值。 当我们扩展右指针时，两个值都会增量更新，因此我们可以维护一个窗口`[l, r]`当它失效时，贪婪地调整它的左边界。 这正是区间约束上的两指针或滑动窗口。 

核心思想是一旦某个段在该位置失效`r`，如果不删除导致约束的元素，其左边界的任何延伸直到违规点都无法恢复可行性。 这种单调行为允许线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每次启动的强力间隔交集 | O(n²) | O(1) | O(1) | 太慢了|
 | 保持最小/最大的滑动窗口 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.将每个房间改造成一个区间`[low_i, high_i] = [l_i, h_i - b]`。 这代表走廊可以穿过房间的所有高度`i`。 任何有效的走廊都必须选择高度`y`在其段的所有间隔内。 
2.维护滑动窗口`[L, R]`遍历索引并保留两个运行值：所有值中的最大值`low_i`在窗口中，并且最小`high_i`在窗口中。 这些表示当前段中所有间隔的交集。 
3. 扩展右边界`R`从左到右。 对于每个新房间，更新运行的最大值和最小值。 
4. 如果在任何一点交叉路口变空，意味着`max_low > min_high`，当前窗口无效。 缩小左边界`L`向前直到条件再次有效，相应地更新运行极值。 
5. 每次有效调整后，用当前窗口长度更新答案`R - L + 1`。 
6、继续直到结束； 记录的最大窗口长度是最长的可行走廊。 

收缩起作用的原因是，违规是由于至少一个区间边界过于严格而引起的。 除非我们删除或超越定义约束的元素，否则删除较早的间隔无法修复它。 

### 为什么它有效

 在任何位置，线段的可行性仅取决于区间的交集，该交集完全由两个单调量捕获：最大下界和最小上界。 当窗口失效时，表示特定元素已被推送`max_low`多于`min_high`。 较早开始的段的任何有效扩展仍必须包含该违规元素，因此恢复有效性的唯一方法是将左边界移过它。 这确保每个索引最多进入和离开窗口一次，在保持线性复杂性的同时保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())

    low = [0] * n
    high = [0] * n

    for i in range(n):
        l, h = map(int, input().split())
        low[i] = l
        high[i] = h - b

    l_ptr = 0
    cur_max = -10**18
    cur_min = 10**18
    ans = 0

    for r in range(n):
        cur_max = max(cur_max, low[r])
        cur_min = min(cur_min, high[r])

        while l_ptr <= r and cur_max > cur_min:
            cur_max = -10**18
            cur_min = 10**18
            l_ptr += 1
            for i in range(l_ptr, r + 1):
                cur_max = max(cur_max, low[i])
                cur_min = min(cur_min, high[i])

        ans = max(ans, r - l_ptr + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```代码直接实现了上面描述的滑动窗口。 转变`high[i] = h_i - b`将每个房间转换为走廊高度的可行区间。 

为了清晰起见，内部重新计算循环故意简单化，但这并不是最佳的； 完全优化的版本将维护数据结构（如单调双端队列）以在摊销 O(1) 中更新最小值和最大值。 然而，逻辑遵循精确的不变量：窗口始终是以`r`与非空交集。 

左指针只向前移动，确保每个索引最多被丢弃一次。

 ## 边缘情况

 当房间的间隔将可行区域折叠到单一高度时，就会出现极端情况。 例如，如果一间房间有`[l_i, h_i - b] = [5, 5]`，那么包含它的任何有效段都必须强制走廊高度恰好为 5。如果相邻房间不允许高度为 5，则窗口会缩小到超过此索引，并且算法会正确隔离两侧的最大段。 

另一种情况是多个连续的房间逐渐拉紧间隔直至空出。 滑动窗口检测第一个违规点并将左边界移动到足以恢复可行性的程度，从而避免对整个前缀进行重新计算。 

最后，当所有间隔都很宽且重叠时，窗口永远不会缩小，并且算法退化为累积全长度的单遍，这证实了没有发生不必要的删除。
