 ## 解决方案
 ## 问题理解

 我们有几个独立的研究小组，每个小组都有一个所需的阈值。 如果一个群体收到的铀量至少达到其阈值，则该群体被认为已达到“临界状态”。 

关键的问题是我们无法控制铀在群体中的分配方式。 我们只选择铀的总量，然后对手可以自由地以任何方式在各个组中分配它。 我们希望保证无论分配如何发生，至少有一组将不可避免地达到或超过其阈值。 

所以问题不在于聪明的分配策略。 这是关于最坏情况的保证：最小的总金额是多少，使得各组之间该总金额的每一个可能的分割都会迫使至少一个组超过其所需的阈值。 

每个小组都对在不触发铀的情况下可以“隐藏”多少铀做出了限制。 如果一个群体有阈值$a_i$，然后直到$a_i - 1$单元可以安全地放置在那里而不会引起激活。 如果我们想避免触发所有组，我们会尝试将每个组严格保持在其阈值以下。 

对手的目标正是：分配铀，使每个群体最多收到$a_i - 1$。 如果这是可能的，那么任何团体都不会变得至关重要。 

这立即重新构建了任务：我们正在寻找使这不可能的最小总量。 

边缘情况来自零阈值。 如果某个团体有$a_i = 0$，根本没有铀就已经很危急了。 例如，输入`n = 1, a = [0]`应该输出`0`，因为保证已经得到满足。 

另一个微妙的情况是所有阈值都很大但不均匀。 例如，`a = [5, 1, 10]`。 限制因素是可以安全放置的东西的总和：每组最多可以吸收$a_i - 1$。 

幼稚的解释可能会尝试模拟分布或显式检查最坏情况的分配。 一旦我们关注容量，这很快就变得不必要了。 

约束条件允许$n$最多$2 \cdot 10^5$，所以任意$O(n^2)$模拟分布是不可能的。 甚至$O(n \log n)$很好，但结构实际上简化为单个线性通道。 

## 方法

 一个直接的暴力想法是考虑给定的总量$S$，并询问是否存在分布$S$跨组，使得没有组达到其阈值。 这就变成了一个可行性问题：我们能不能赋值$x_i$这样$0 \le x_i \le a_i - 1$和$\sum x_i = S$？ 

如果对于给定的$S$这样的分布存在，那么$S$不足以保证激活。 如果不存在，则每个分布$S$迫使至少一组超过其阈值。 

对于固定的$S$，这个检查很简单：我们可以“隐藏”的最大数量是$\sum (a_i - 1)$。 如果$S$超过这个总和，则不存在安全分布。 

所以暴力方法会尝试增加$S$从零开始，每次都测试这个条件。 这导致了$O(n)$重复检查最多$O(\sum a_i)$，这是完全不可行的，因为值可以达到$10^9$。 

关键的观察是我们不需要搜索$S$。 我们可以直接计算最大安全总数，即所有的总和$a_i - 1$（负值钳位为零）。 超出此范围的任何额外单位都必须迫使至少一组达到其阈值。 

因此答案正是：$$\left(\sum a_i\right) - (n - \text{count of zeros})$$或者更干净，$\sum \max(0, a_i - 1)$，如果我们想保证触发，再加一个单位。 然而，由于该任务要求保证至少一组达到阈值的最小总数，因此我们只需取严格大于安全容量的最小值。 

这给出：$$\sum (a_i - 1) + 1$$但只有当所有$a_i > 0$。 如果有一些$a_i = 0$，答案就变成了$0$，因为没有任何铀，条件已经满足。 

因此，问题简化为使用极端情况计算简单的总和。

 | ---| ---| ---| ---|
 | 蛮力 | O(S·n) | O(S·n) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取所有阈值并计算每个组可以安全吸收多少铀而不会变得临界。 对于有阈值的组$a_i$，这个安全容量是$a_i - 1$，但永远不会低于零。 这模拟了对手尽最大努力避免触发任何群体的情况。 
2. 累计所有组的总安全容量。 这代表了在不强迫任何团体达到其阈值的情况下仍然可以分配的最大铀总量。 
3. 跟踪是否有任何组的阈值为零。 如果这样的组织存在，那么它在没有收到任何东西的情况下就已经很关键了，这意味着即使铀总量为零也可以满足所需的保证。 
4. 如果存在零阈值组，则立即返回 0，因为不需要正数即可保证成功。 
5. 否则，返回总安全容量加一。 这个额外的单位是打破所有可能的安全分布的最小数量，迫使至少一个群体跨越其阈值。 

### 为什么它有效

 中心不变量是，任何避免触发所有组的铀分配都必须最多分配每个组$a_i - 1$。 这些每组限制的总和定义了在不成功的情况下可以分配的最大总质量。 一旦总数超过这个界限，鸽笼效应就不可避免：至少有一组必须收到至少其阈值数量。 因此，解决方案正是超出此全局安全容量的最小整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if any(x == 0 for x in a):
        print(0)
        return
    
    total_safe = 0
    for x in a:
        total_safe += x - 1
    
    print(total_safe + 1)

if __name__ == "__main__":
    solve()
```该代码首先检查零阈值边缘情况，因为它主导所有其他推理。 如果任何组的阈值已经为零，则答案立即确定。 

否则，它通过求和来计算总安全容量$a_i - 1$。 这直接编码了可以分配的最大铀，而无需强制达到阈值。 添加一个给出了打破这种可行性的最小数量。 

不需要排序或高级结构，因为约束是纯粹相加的并且跨组独立。 

## 工作示例

 ### 示例 1

 输入：```

```我们计算安全容量：

 | 步骤| a_i | a_i - 1 | 总安全 |
 | ---| ---| ---| ---|
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 1 | 1 |
 | 3 | 3 | 2 | 3 |

 最终答案是`3 + 1 = 4`。 

这表明在避免任何阈值的情况下最多可以分配 3 个单元，但第 4 个单元必然会迫使至少一组变得关键。 

### 示例 2

 输入：```
1
2
```| 步骤| a_i | a_i - 1 | 总安全 |

这意味着一个单元仍然可以安全隐藏，但第二个单元可以保证唯一的一组超过其阈值。 

这些痕迹证实计算与最大安全隐藏容量相匹配。

 ## 边缘情况

 对于阈值为零的单个组，例如输入`1 / [0]`，算法立即返回 0，而不计算总和。 循环条件检测到零并提前退出，与系统已经处于临界状态的事实相匹配。 

对于混合输入，例如`3 / [1, 1000000000, 1]`，安全容量变为`0 + 999999999 + 0 = 999999999`，所以答案是`1000000000`。 中间较大的值在总数中占主导地位，而这两个值没有任何贡献，表明只有大于 1 的值才会影响容量。
