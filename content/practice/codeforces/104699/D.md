 ## 解决方案
 ## 问题理解

 我们有一张圆桌$n$座位和$n$客人，每个客人都有一个约束区间$[l_i, r_i]$。 此间隔描述了该客人可以坐在的位置：如果我们分配客人$i$到某个座位$j$，那么它必须保持$l_i \le j \le r_i$。 

任务是决定我们是否可以将每位客人分配到不同的座位，以便满足所有约束，并且如果可能的话，构建一个有效的分配。 换句话说，我们正在尝试建立宾客座位排列，以便每位宾客都能进入其允许的区域。 

该结构是两个具有区间约束的有序集之间经典的一对一匹配。 每个座位只能使用一次，因此问题不仅仅是检查每个间隔的可行性，而是协调重叠范围之间的冲突。 

约束条件允许$n$最多$10^5$，这立即排除了任何$O(n^2)$模拟或重复扫描间隔。 任何解决方案都必须依赖于排序或以每次操作的对数或摊销恒定时间处理事件的数据结构。 

当许多区间严重重叠但具有紧密的右端点时，就会出现朴素方法的微妙失败情况。 例如，如果所有间隔都是$[1, n]$除了一个是$[1,1]$，贪婪的“分配范围内的任何可用座位”策略如果没有排序，很容易过晚或过早地消耗座位 1，即使存在正确的分配，也会阻碍可行性。 

当间隔很短但在处理顺序中出现较晚时，就会出现另一种边缘情况。 如果我们不优先考虑紧密的间隔，我们可能会提前将他们唯一可能的座位分配给不同的客人，即使存在有效的全球安排，也会导致不可避免的失败。 

## 方法

 一个蛮力的想法是一个一个地分配座位，并且对于每个座位，尝试选择间隔包含该座位的任何未使用的客人。 这需要扫描所有客人的每个座位，动态检查可行性。 这在概念上是有效的，因为它直接强制执行约束，但每个座位的放置可能会花费$O(n)$，导致$O(n^2)$在最坏的情况下，操作速度太慢$10^5$。 

关键的观察结果是，我们正在解决线路上的分配问题：座位按顺序处理，并且每位客人都可以在$l_i$并到期于$r_i$。 在任何座位位置$i$，唯一相关的客人是那些间隔已经开始但尚未结束的客人。 其中，最佳分配候选者是右端点最小的那个，因为它受到的约束最大，并且是第一个在以后变得不可能的。 

这将问题转化为贪婪调度过程。 我们从左到右扫座位，并保留一组可用的客人，总是选择最紧凑的一个。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了|
 | 最佳|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将每个座位位置从 1 到$n$作为时间步长。 

1. 按出发点对客人进行排序$l_i$。 这使我们能够在客人的有效窗口开始时准确地激活客人。 
2. 将座位位置从 1 扫至$n$。 在每个位置$i$，将所有客人插入到优先级结构中$l_j = i$。 从此时开始，这些人现在有资格就座。 
3. 维护一个最小堆，其键为$r_j$，存储所有当前可用的客人。 该堆代表间隔覆盖当前座位的所有客人。 
4. 在为客人分配座位之前$i$，从堆中删除任何来宾$r_j < i$，因为它们不能再有效地放置在任何地方。 
5. 如果堆变空，则没有客人可以占用座位$i$，因此不可能进行有效的分配。 
6. 否则，选择最小的客人$r_j$从堆中将它们分配给座位$i$。 永久删除它们，以免再次使用。 

### 为什么它有效

 在每个座位位置，我们总是分配一位当前可行的客人。 在所有可行的客人中，选择具有最小右端点的客人是安全的，因为它可以最大限度地减少阻止未来分配的风险。 任何选择更大的替代选择$r_j$永远不会提高可行性，因为较小的$r_j$客人未来的选择非常少，如果要放置的话，必须提前放置。 这保持了不变式，即只要算法不会提前失败，所有剩余未分配的客人在剩余座位中仍然具有至少一个可用的有效位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    add = [[] for _ in range(n + 2)]
    
    for i in range(1, n + 1):
        l, r = map(int, input().split())
        add[l].append((r, i))
    
    import heapq
    heap = []
    ans = [0] * (n + 1)
    
    for pos in range(1, n + 1):
        for r, i in add[pos]:
            heapq.heappush(heap, (r, i))
        
        while heap and heap[0][0] < pos:
            heapq.heappop(heap)
        
        if not heap:
            print("NO")
            return
        
        r, i = heapq.heappop(heap)
        ans[pos] = i
    
    print("YES")
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该解决方案首先按客人的左端点对客人进行分组，以便在扫描到达其起始位置时准确地激活他们。 堆确保我们可以在每个座位上快速找到最紧急的客人（按最小的定义）$r_i$。 

删除过期间隔的清理循环至关重要，因为如果没有它，算法可能会分配超出其有效范围的访客。 对空性的检查保证我们立即发现不可能的情况。

 ## 边缘情况

 一种重要的边缘情况是当多个客人有相同的紧密间隔时，例如$[1,1]$。 在 1 号座位上，只有这些客人有空，大家会在其中任意选择一位。 如果此类来宾的数量多于可用位置，则堆在某个时刻会变空，并正确返回 NO。 

另一种情况是，客人开始较晚，但截止日期很早。 由于堆只包含其$l_i \le i$，这样的来宾甚至不会在截止日期之前进入系统，并且永远不会被分配，从而正确地导致失败。 

最后一个微妙的情况是宽间隔始终可用。 这些人自然会被推到后面的座位，因为他们$r_i$很大，并且只有在不存在更严格的替代方案时才会选择它们。 这保留了所有早期受限分配的可行性。
