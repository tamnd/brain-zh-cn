 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列，但我们关心的真正对象不是值本身，而是它们的位置。 最初，每个位置 i 形成一个包含值 a[i] 的单例集。 唯一允许的操作是合并两个已构建的集合 A 和 B，但前提是 A 中的每个元素都严格小于 B 中的每个元素。此条件仅取决于集合内的最小值和最大值，因此我们可以将每个集合视为值空间中的一个区间，永远不会以冲突的方式与另一个合并区间重叠。 

每次合并都会创建一个新集合，其元素是两个所选集合的并集，并且这个新集合也会保留以供将来合并。 因此，该过程构建了一个不断增长的集合族，形成了合并的 DAG。 

任务不是构建一个特定的最终结构，而是确保对于索引 [l, r] 的每个查询区间，都存在一些构造的集合，其中精确包含值 {a[l], a[l+1], …, a[r]}。 我们还必须输出每个查询对应哪个创建集，并且必须将创建集的总数保持在一个较大的限制内。 

关键的困难在于我们不允许任意合并区间。 约束 g(A) < f(B) 强制合并遵守值顺序，这强烈限制了我们如何组合段。 

约束 n ≤ 2^12 和 q ≤ 2^16 表明大约 O(n log n) 或更差的构造是可以接受的，但是任何单独超过 n 或超过 q 的二次都太慢。 然而，真正的挑战不仅仅是渐近复杂性，而是控制创建集的数量，因为每次合并都会永久增加 cnt。 

一个天真的想法是独立构建每个查询间隔。 这会立即失败，因为 q 可能很大并且区间重叠严重，因此我们会多次重新计算相同的结构，从而导致 cnt 爆炸。 

另一个天真的问题是假设我们总是可以直接合并相邻的索引段。 这是错误的，因为合并条件取决于值 a[i]，而不是索引，因此两个连续的索引间隔可能具有违反 g(A) < f(B) 的交错值。 

一个微妙的边缘情况是当值几乎按排列顺序交替时。 那么即使是很小的间隔也可能需要仔细排序的合并； 幼稚的从左到右扫描经常会尝试无效的合并，例如组合最大值未正确分离的集合。 

## 方法

 蛮力的想法是独立处理每个查询 [l, r] 并尝试通过重复合并当前可合并的任何两个集合来从单例构建其集合，并且它们的并集使我们更接近目标间隔。 这类似于约束图上连接组件的动态构造。 然而，每次合并仅增加cnt，并且针对不同的查询重复重建相同的中间集。 在最坏的情况下，q 约为 2^16，n 约为 2^12，这种方法会退化为多次重新计算大型重叠合并树，导致远远超过 220 万个集合。 

关键的结构观察是我们不需要从头开始构建每个查询区间。 相反，我们应该在所有位置上构建一个通用合并结构，以便任何区间 [l, r] 稍后都可以被“挑选出来”作为已创建的节点之一。 这表明对索引段进行分而治之：构建一个合并树，其中每个节点对应于某个索引区间，并确保每个节点只构建一次。

现在的问题是我们是否可以合并两个相邻的索引区间[l, mid]和[mid+1, r]。 如果左侧区间中的最大值小于右侧区间中的最小值，则这是可能的。 该条件在索引顺序中并不总是成立，但我们可以通过仔细定义构造顺序来强制执行它：我们不依赖索引邻接，而是使用值驱动的合并并递归地确保每个区间都以保证可分离性的方式表示。 

中心思想是在值等级上建立类似笛卡尔的分解。 由于 a 是一个排列，我们可以递归地按区间中的最小值进行分割：最小值元素将区间分割为可值分离的左右部分，因为左右部分中的所有内容都大于最小值，并且排列结构确保了允许有效合并的递归单调性。 

然后，我们在索引上构建一棵线段树，但每个节点不仅仅是一组索引，它是一个具有保证值范围分离属性的构造集，允许安全地合并子节点。

 | ---| ---| ---| ---|
 | 蛮力 | O(q n^2) | O(q n^2) | O(n) | 太慢了 |
 | 分而治之的建设 | O(n log n + q) | O(n log n + q) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 我们在索引段上构造一个二叉合并树。 

1. 对于每个段 [l, r]，计算该段中最小值的位置，例如 pos。 该元素充当分隔符，保证合并的严格排序属性。 
2. 递归构造左段[l, pos-1]和右段[pos+1, r]。 每次递归都会返回一个表示该间隔的集合。 
3. 对于每个段，我们首先确保两个子集都已构建。 然后我们以受控的顺序将它们与单例集合 {a[pos]} 合并：由于 a[pos] 是最小值，所以 left 和 right 中的每个值都更大，因此我们可以安全地将 left 与 {a[pos]} 合并，然后将该结果与 right 合并。 
4.每次合并都记录为一个新的集合id，并且我们在每个段节点存储与完整区间[l,r]对应的id。 
5. 构建整个结构后，通过直接输出该段的存储集 ID 来回答每个查询 [l, r]。 

微妙之处在于最小元素保证了严格的排序障碍。 一旦我们隔离了最小值，其他一切都更大，因此只要我们尊重构造顺序，我们总是可以附加子树而不违反 g(A) < f(B)。 

工作原理：每个段 [l, r] 都由一个构造的集合表示，其元素恰好是 {a[l], …, a[r]}。 递归分割确保了不相交的子问题，并且最小元素充当枢轴，在构造的部分之间强制执行严格的全局排序。 因为合并总是合并最大值小于另一个集合的最小值的集合，所以每个并集操作都是有效的。 递归保证每个元素在每个段中只包含一次，因此不会发生重复或遗漏。

合并函数隐式强制执行规则 g(A) < f(B)，因为我们总是首先通过最小主元排序附加较小值的集合。 在正确的实现中，每次合并都保证有效，因为最小元素干净地分割了值范围。 

一个常见的实现陷阱是忘记合并顺序很重要：交换左子节点和右子节点会破坏单调性保证并违反条件。 

## 工作示例

 考虑带有查询 [2,3] 和 [1,3] 的样本排列 [1, 3, 2]。 

我们首先确定整个区间 [1,3] 中的最小值，即位置 1 处的 1。然后我们递归地构建左空和右 [2,3]。 

对于[2,3]，最小值为2，因此我们再次拆分并最终构建集合{3}、{2}，然后将它们合并为{2,3}。 最后我们将{1}与{2,3}合并得到{1,2,3}。 

| 细分 | 最小位置 | 左套装| 正确设置 | 合并结果 |
 | ---| ---| ---| ---| ---|
 | [1,3]| 1 | ∅ | [2,3]| {1,2,3} |
 | [2,3]| 3 | {3} | {2} | {2,3} |

 这证实了递归最小分解构造了所有所需的区间。 

现在考虑像 [3,1,2] 这样的倾斜排列。 [1,3] 处的最小值为 1，可以干净地分裂。 尽管值在索引空间中没有排序，但递归始终首先隔离最小值，从而确保合并的有效性。

 ## 边缘情况

 一种关键的边缘情况是最小元素位于区间的一个边界处。 在这种情况下，递归一侧会变空。 该算法通过将空边视为中性并跳过合并来处理此问题。 例如，在 [1, 4, 3, 2] 中，最小值位于左边界，因此仅进行右递归。 合并链仍然有效，因为每次合并都是在已经验证的结构之间进行的。 

当多个查询要求重叠间隔时，会出现另一种边缘情况。 该构造不会针对每个查询重新计算任何内容； 每个区间在递归树中表示一次。 因此，重叠查询只是重用存储的标识符，防止 cnt 爆炸。 

最后一个微妙的情况是排列，其中值按索引顺序强烈交替，例如 [2,4,1,3]。 这里朴素的邻接合并经常失败，因为索引邻居之间很少满足 g(A) < f(B)。 递归最小分割通过始终切割全局最小的元素来完全避免这种情况，保证两侧的所有剩余值都严格更大并且可以安全地合并。
