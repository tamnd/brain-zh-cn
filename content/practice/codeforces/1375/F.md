 ## 解决方案
 ## 问题理解

 三个数字代表三堆石头的大小。 互动在我们和对手之间交替进行。 轮到我们输出一个正整数`y`，并且在对手的回合中，他们必须精确地添加`y`石头堆到三堆中的一堆，但有一个限制，即他们不能重复使用在上一步中选择的同一堆石头。 

对手的失败条件纯粹是结构性的：在任何时刻，如果任何两堆相等，他们就会立即失败。 相反，如果 1000 整轮都没有创造平等，对手也会因暂停而失败。 

我们可以选择先行动还是后行动。 由于对手唯一的自由是选择哪堆获得增量，整个游戏就是控制如何创造或不创造平等，同时尊重“连续两次没有相同的堆”的限制。 

初始值的约束最大为 10^9，这意味着绝对大小与暴力搜索无关。 任何试图模拟所有可能的选择序列的解决方案都会失败，因为每次移动都会分支超过三个堆选择，并且我们可能有多达 1000 轮，导致状态数量呈指数级增长。 交互性质还可以防止任何重新计算或离线搜索； 每项决定都必须立即做出。 

如果我们尝试通过始终添加小值或大值而不跟踪结构来“稳定”配置，则会出现微妙的故障模式。 由于对手敌对地选择了这堆牌，天真的贪婪平衡很快就会崩溃：即使我们试图保持较大的差异，一步棋就能将两堆牌打成相等。 

真正的困难在于，对手对连续堆选择的限制是系统中唯一的记忆。 任何正确的策略都必须利用这个约束，而不是试图直接控制原始值。 

## 方法

 蛮力视角会尝试将游戏建模为状态树，其中包含当前的三重堆大小以及最后选择的堆。 从每个状态，我们考虑所有可能的值`y`我们可能会输出所有有效的对手响应。 这成为一个具有无限分支的交互式游戏树`y`，所以即使通过对称修剪也无济于事。 搜索空间在值上不是有限的，仅在结构关系上是有限的，因此暴力破解会立即失败。 

关键的观察是，桩的绝对值并不重要，只有它们之间的差异才重要，因为相等是唯一的失败条件。 如果我们能够在对手被迫采取受限制的行动后迫使某些对堆变得相等，我们就会立即获胜。 

“不能连续两次选择同一堆”的限制是实现控制的原因。 这意味着对手选择了一堆后，我们知道他们下次被迫选择另外两个中的一个。 这创建了一个两步可控循环，我们总是可以对他们的最后选择做出反应。 

获胜的想法是在对手做出受限反应后，重复选择与三堆中的两堆对齐的值。 我们总是选择一个等于不是对手最后选择的两堆之间的差值的值。 这迫使发生可预测的转变：根据允许对手添加的位置，要么两堆立即变得相等，要么我们重新创建具有相同结构但具有移动的“禁止堆”的配置。 这保证了在有限数量的循环内，必须发生强制相等，因为对手无法避免在两种状态记忆约束下无限期地与相同的结构不平衡相互作用。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(1)-O(状态) | 太慢了 |
 | 结构差异策略| O(1000) 次交互 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们致力于以第一名球员的身份进行比赛。 

我们维护对手选择的最后一堆，最初是未定义的。 

每个回合的进行如下。 

1. 观察当前三堆数值以及对手使用的最后一堆索引。 
2. 从三堆中选择两堆，其中两堆都不是对手最后选择的一堆。 由于共有三堆而只有一个禁止堆，因此这样的一对总是存在。 
3. 计算`y`作为这两个选定桩之间的绝对差。 
4. 输出`y`。 
5. 对手的回应是添加`y`到两个允许的堆中的任何一个（如果是他们之前选择的，他们就不能使用禁止的堆；否则他们可以选择任何有效的堆，除了重复上一回合的选择）。 
6.如果对手加`y`到用于定义的两个桩之一`y`，该堆变得与其他选定的堆相等，从而立即给他们带来损失。 
7. 如果他们添加到第三堆，则所选对之间的相等结构将以移位形式保留，并且我们将禁止堆索引更新为他们刚刚选择的索引。 

该过程重复进行。 

关键的不变量是，在对手每次移动之后，我们仍然可以识别一对桩，我们可以在下一步移动中消除其差异，而不会违反我们避免他们最后选择的桩的约束。 每个循环要么产生立即相等，要么保留受控差异结构，同时缩小对手在桩选择历史中的自由度。 由于对手只记得最后一堆，他们无法永久避免与不断演变的配对结构相互作用，最终一步就会迫使对手崩溃。 

## 为什么它有效

 在每个阶段，游戏状态都由对手选择的桩值的三倍和最后桩索引来充分描述。 我们的举动构建了一个值，该值对两个不受限制的桩之间的目标差异进行编码。 对手的限制使他们无法总是避开我们正在同步的对。 

如果他们将增量应用于任一同步桩，则立即创建相等。 如果他们避免它，他们将被迫扰乱第三堆，这会改变配置，但在下一步中保留类似对的存在。 这可以防止它们无限期地逃避同步过程，并且由于每次交互都会严格降低它们保持分离而不重复的能力，因此最终必须在 1000 转限制之前发生丢失相等性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def choose_pair(a, b, c, forbidden):
    # pick two indices not equal to forbidden (0-based)
    idx = [0, 1, 2]
    valid = [i for i in idx if i != forbidden]
    return valid[0], valid[1]

def main():
    a, b, c = map(int, input().split())

    print("First")
    flush()

    piles = [a, b, c]
    last_forbidden = -1  # opponent last chosen pile (0-based)

    for _ in range(1000):
        i, j = choose_pair(piles[0], piles[1], piles[2], last_forbidden)

        y = abs(piles[i] - piles[j])

        print(y)
        flush()

        # read opponent move
        res = input().strip()
        if res == "0" or res == "-1" or res == "":
            return

        k = int(res) - 1
        if k < 0:
            return

        # update piles
        piles[k] += y

        # update last chosen pile
        last_forbidden = k

        # check equality loss
        if piles[0] == piles[1] or piles[1] == piles[2] or piles[0] == piles[2]:
            return

if __name__ == "__main__":
    main()
```该实现跟踪三个堆值和对手最后选择的索引。 每次迭代都会选择两个避开禁止索引的堆并输出它们的差值。 读取对手的响应后，更新相应的堆并刷新禁止索引。 每次更新后立即进行相等性检查，以便在丢失情况出现时立即捕获它。 

一个常见的陷阱是忘记禁止桩约束仅适用于连续的对手移动，而不适用于我们的选择。 因此，我们每轮只排除一个指数。 另一个微妙的点是阅读`"0"`或者`"-1"`必须立即终止以避免交互不同步。

 开始`(10, 4, 7)`。 

| 步骤| 桩| 禁止 | 已选对 | y | 对手行动 | 新状态 |

 ## 边缘情况

 当两堆已经很接近时，差异策略可以在一步后立即产生零或均衡。 例如`(10, 11, 100)`立即产生`y = 1`如果我们选择`(10,11)`，并且对手被迫做出无法维持所有不平等的受限反应。 

当对手由于连续限制而被迫交替堆时，我们的构造始终确保我们选择的对子排除了他们最后的选择。 这可以防止他们持续屏蔽特定的桩，使其不参与差异结构。 

在其中一堆明显大于其他堆的配置中，重复的差异选择最终会减少对手响应后受控对之间的有效间隙，因为避免相等的唯一方法是不断移动“活动”堆，而“活动”堆被内存限制所阻止。
