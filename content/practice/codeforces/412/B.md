 ## 解决方案
 ## 问题理解

 我们拥有一组计算机，每台计算机都有测量的最大互联网速度。 参与者比计算机少，并且每个参与者必须拥有一台单独的计算机。 我们的目标是使所选计算机的速度相等，但我们可以任意降低任何计算机的速度，而不是提高它。 在选择计算机和调整其速度的所有方法中，我们希望最大化分配给参与者的共同速度。 

输入由两个整数组成：计算机总数`n`以及参加人数`k`。 然后是代表每台计算机的最大速度的整数数组。 输出是一个整数：至少可能的最高均匀速度`k`计算机可以在可选减少后实现。 

限制很小：`n`最多为 100。这允许轻松地接近大约 O(n² log n)，因为即使 O(n³) 也是边界。 速度本身是中等整数，最高可达 32768，但我们永远不需要枚举该范围内的所有数字，这要归功于小`n`。 

当许多计算机共享高速但只需要少数计算机时，就会出现可能破坏简单解决方案的边缘情况。 例如，与`n = 5`,`k = 3`，和速度`[10, 10, 9, 9, 8]`，最优选择是`[10, 10, 9]`减少到`9`每个。 只计算精确重复项的粗心方法可能会错误地选择`10`并失败了，因为只有两台计算机拥有它。 另一个微妙的情况是所有计算机具有相同的速度； 答案应该是速度，无论`k`。 

## 方法

 强力方法将考虑从 1 到最大观察速度的每个整数速度。 对于每个候选速度`s`，我们会计算有多少台计算机具有至少速度`s`。 如果至少`k`计算机达到这个阈值，`s`是可行的。 然后我们取最大的可行的`s`。 这是可行的，因为降低速度是允许的，所以任何计算机都比`s`可以做出贡献。 这样做的问题是速度范围高达 32768，所以即使`n`很小，迭代所有 32768 个速度效率很低。 

关键的见解是我们只需要考虑计算机上实际出现的速度。 对数组进行排序可以让我们从最大到最小系统地检查候选速度。 对于给定的候选速度`s`，我们可以计算有多少台计算机至少具有该速度。 一旦这个计数至少达到`k`，我们找到了最佳速度。 这将候选空间从 32768 减少到最多`n`值，这是完全可行的`n`最多 100 个。 

这里的故事是：蛮力原则上是有效的，因为降低速度是允许的，但它效率低下，因为它尝试了不可能或不必要的速度。 仅对现有速度进行排序和检查可以利用问题的结构：只有现有的最大值对于最佳解决方案而言很重要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有速度 1..最大）| O(n * 最大速度) | O(1) | O(1) | 太慢了 |
 | 检查排序速度 | O(n log n + n²) | O(n log n + n²) | O(n) | 已接受 |

 ## 算法演练

 1.读取输入值`n`,`k`，以及最大速度的数组。 对数组进行排序将帮助我们从高速推理到低速。 
2. 按非降序对速度数组进行排序。 原因是速度越高越好，因此我们将从最大到最小尝试候选。 
3. 从最大速度向下迭代数组。 对于每个速度`a[i]`，计算有多少台计算机的速度大于或等于`a[i]`。 我们可以通过从末尾向后扫描数组来做到这一点。 
4. 一旦计算出至少具有速度的计算机`a[i]`至少是`k`， 返回`a[i]`。 这有效是因为`a[i]`是最大的候选者，至少允许`k`计算机来满足它。 我们不需要检查较小的速度，因为它们只会降低公共速度。 

为什么有效：通过仅考虑现有速度并计算有多少计算机可以达到每个速度，我们确保选择可应用于至少`k`电脑。 任何较小的候选速度要么是不必要的，要么不是最佳的。 不变的是，对于每个候选人`s`，计算机数量≥`s`正确地告诉我们可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
speeds = list(map(int, input().split()))

# Sort speeds ascending
speeds.sort()

# Check candidates from largest to smallest
for i in range(n - 1, -1, -1):
    count = sum(1 for speed in speeds if speed >= speeds[i])
    if count >= k:
        print(speeds[i])
        break
```代码首先对速度进行排序。 然后，对于每个候选速度（从最大速度开始），计算有多少计算机可以至少达到该速度。 一旦计数达到`k`，该速度被打印。 这里的微妙之处是从最大到最小扫描并计数`>= speeds[i]`，保证了最大可行速度。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n²) | 排序是 O(n log n)，检查每个候选者在最坏情况下是 O(n²) |
 | 空间| O(n) | 存储速度数组 |

 和`n ≤ 100`，O(n²) 可以忽略不计（最多 10,000 次操作）。 内存使用量微不足道。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    n, k = map(int, input().split())
    speeds = list(map(int, input().split()))
    speeds.sort()
    for i in range(n-1, -1, -1):
        count = sum(1 for s in speeds if s >= speeds[i])
        if count >= k:
            print(speeds[i])
            break
    return output.getvalue().strip()

# Provided sample
assert run("3 2\n40 20 30\n") == "30", "sample 1"

# Custom cases
assert run("5 3\n10 10 9 9 8\n") == "9", "mixed speeds"
assert run("4 2\n5 5 5 5\n") == "5", "all equal"
assert run("1 1\n16\n") == "16", "minimum size"
assert run("6 4\n20 15 15 10 10 10\n") == "15", "need top 4"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`5 3\n10 10 9 9 8`| 9 | Selection and reduction correctness |
 |`4 2\n5 5 5 5`| 5 | 所有速度均等 |

 ## 边缘情况

 对于`n = 1`和`k = 1`与速度`16`，算法立即选择 16。对于`n = 5`和`k = 3`与速度`[10, 10, 9, 9, 8]`，算法首先测试 10（计数 2 < 3），然后测试 9（计数 4 ≥ 3），输出 9。两种边缘情况都表明计数`>= candidate`是必不可少的，从最大的候选者开始可以确保最大化。 该方法处理所有情况`k`等于`n`，所有速度都相等，或者需要减速以匹配均匀速度。
