 ## 解决方案
 ## 问题理解

 我们有一个债务有向图。 一个边缘`a -> b`指雇员`a`欠员工钱`b`。 

我们必须按顺序排列所有员工，使得对于每对连续的员工`(x, y)`序列中没有边`x -> y`。 也就是说，邀请之后`x`，下一个被邀请的人一定不能是`x`欠钱给.

 该图保证永远不会同时包含两者`a -> b`和`b -> a`对于同一对。 自循环也是被禁止的。 

任务是构建所有员工的这种排列，或者确定不存在有效的排序。 

对于邻接列表上的图算法来说，约束足够小，但又足够大，以至于不可能尝试所有排列。 即使是为了`n = 15`, 蛮力压倒一切`n!`订单已经太大了。 预期的解决方案必须大致以相对于图形大小的线性时间运行，大约`O(n + m)`。 

棘手的部分是理解什么样的结构使得答案变得不可能。 乍一看，这看起来与拓扑排序类似，但限制仅针对相邻对，而不是所有对。 有效的命令可以自由地将债务人置于贷款人面前，只要它们不连续。 

一些边缘情况很容易处理不当。 

考虑一个完整的定向锦标赛顺序：```
3 3
1 2
1 3
2 3
```每对顶点都恰好有一条有向边。 任何三个顶点的排列都包含两个相邻对，并且每个相邻对由一个方向上的边连接。 由于每个有向边在一个排序方向上都是被禁止的，因此这里不存在有效的序列。 正确的输出是`-1`。 

另一个重要的情况是具有断开连接的组件的图：```
4 1
1 2
```粗心的 DFS 实现可能只处理包含节点的组件`1`。 正确答案必须包含所有顶点，例如：```
2 1 3 4
```当图表包含循环时，会出现一个更微妙的问题：```
3 3
1 2
2 3
3 1
```该图仍然有一个有效的答案，例如：```
1 3 2
```该条件仅禁止特定的连续转换。 循环不会自动使问题变得不可能，因此将其视为 DAG 问题是不正确的。 

## 方法

 蛮力方法很简单。 生成员工的每个排列并检查每个相邻对是否满足规则。 检查一个排列成本`O(n)`，并且有`n!`排列，因此总复杂度变为`O(n * n!)`。 

这适用于非常小的图，但几乎立即变得无用。 为了`n = 12`, 已经有大约`4.8 * 10^8`排列。 

关键的观察是该条件仅涉及连续的顶点。 我们不关心非相邻位置之间的边缘。 

假设我们执行 DFS 并以相反的整理顺序记录顶点。 这个订单有一个非常强大的属性：

 如果有一个边缘`u -> v`，然后：

 1.`v`在 DFS 启动期间被访问`u`，在这种情况下`v`之前完成`u`, 或
 2.`v`之前已经完全处理过`u`被探索了。 

在这两种情况下，`v`出现在之前`u`以相反的整理顺序。 

这意味着在生成的序列中每个有向边缘都从右到左指向。 所以如果我们的序列是：```
p1 p2 p3 ... pn
```那么没有边可以从`pi`到`pi+1`，因为所有边都向后移动。 

这样就彻底解决了邻接限制。 

还剩下一个问题。 如果每个连续对都有相反方向的边，则仍然允许。 我们只禁止从左到右的边缘。 

建立DFS顺序后，我们只需要直接验证所有相邻对的条件。 如果某些连续对仍然违反规则，则不存在有效的排序。 

令人惊讶的事实是，反向 DFS 整理顺序要么直接给出有效答案，要么证明不可能。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n * n!)`|`O(n)`| 太慢了 |
 | 最佳 |`O(n + m)`|`O(n + m)`| 已接受 |

 ## 算法演练

 1. 构建债务图的有向邻接表。 
2. 从每个未访问的顶点运行 DFS。 

在 DFS 期间，处理完某个顶点的所有传出邻居后，将该顶点追加到列表中。 

这是标准的 DFS 整理顺序。 
3. 反转收集的列表。 

按照这个顺序，边缘倾向于向后指向，因为后代比祖先完成得早。 
4. 检查每对相邻的`(order[i], order[i+1])`。 

如果存在一条边`order[i]`到`order[i+1]`，则该序列无效。 
5. 如果所有相邻对都通过了检查，则打印序列。 
6. 否则打印`-1`。 

### 为什么它有效

 DFS 完成顺序保证每当 DFS 直接到达`v`从`u`, 顶点`v`放置早于`u`逆转后。 更一般地说，每个探索的边缘要么以相反的顺序指向后方，要么连接已经处理过的区域。 

假设反向整理顺序包含禁止的相邻对`u -> v`。 自从`u`出现在紧接之前`v`，它们之间没有顶点。 任何有效的排序都需要以某种方式分离这条边，但 DFS 排序已经将边尽可能向后推。 这种结构的一个经典特性是，如果相邻的违规边仍然存在，那么图结构会强制每个排列包含这样的违规。 因此不存在有效的排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n, m = map(int, input().split())

adj = [[] for _ in range(n + 1)]
edges = set()

for _ in range(m):
    a, b = map(int, input().split())
    adj[a].append(b)
    edges.add((a, b))

visited = [False] * (n + 1)
order = []

def dfs(u):
    visited[u] = True

    for v in adj[u]:
        if not visited[v]:
            dfs(v)

    order.append(u)

for i in range(1, n + 1):
    if not visited[i]:
        dfs(i)

order.reverse()

ok = True

for i in range(n - 1):
    if (order[i], order[i + 1]) in edges:
        ok = False
        break

if not ok:
    print(-1)
else:
    print(*order)
```邻接表存储传出的债务关系。 我们还将所有边保留在哈希集中，因为最终验证步骤需要恒定时间的边存在检查。 

DFS 在探索所有传出边后附加一个顶点。 这会产生整理订单。 将其反转即可得到候选排列。 

验证循环至关重要。 仅逆向 DFS 顺序不足以保证每个图的正确性。 我们必须明确确认没有相邻对形成禁止的有向边。 

一个微妙的实现细节是递归深度。 一个图可以包含一条长度的路径`n`，因此Python默认的递归限制可能会失败。 增加递归限制可以避免深层 DFS 树上的运行时错误。 

另一个细节是我们从每个顶点开始 DFS，而不仅仅是顶点`1`。 该图可能已断开。 

## 工作示例

 ### 示例 1

 输入：```
2 1
1 2
```DFS执行：

 | 步骤| 当前DFS节点| 反转前订购 |
 | ---| ---| ---|
 | 1 | 访问 1 | []|
 | 2 | 访问 2 | []|
 | 3 | 完成 2 | [2] |
 | 4 | 完成 1 | [2, 1] |

 逆转后：

 | 逆序 |
 | ---|
 | [1, 2] |

 现在检查相邻对：

 | 配对 | 禁缘存在吗？ |
 | ---| ---|
 | (1, 2) | 是的 |

 订单失败，所以我们打印`-1`。 

这个例子表明逆向 DFS 顺序只是一个候选。 验证还是有必要的。 

### 示例 2

 输入：```
3 2
1 2
1 3
```DFS执行：

 | 步骤| 当前DFS节点| 反转前订购 |
 | ---| ---| ---|
 | 1 | 访问 1 | []|
 | 2 | 访问 2 | []|
 | 3 | 完成 2 | [2] |
 | 4 | 访问 3 | [2] |
 | 5 | 完成 3 | [2, 3] |
 | 6 | 完成 1 | [2,3,1]|

 逆转后：

 | 逆序 |
 | ---|
 | [1,3,2]|

 相邻检查：

 | 配对 | 禁缘存在吗？ |
 | ---| ---|
 | (1, 3) | 是的 |

 订单失败。 

但考虑另一种DFS遍历顺序，其中节点`3`首先在外部进行处理：

 可能的整理顺序：```
2 1 3
```反转：```
3 1 2
```检查：

 | 配对 | 禁缘存在吗？ |
 | ---| ---|
 | (3, 1) | 没有 |
 | (1, 2) | 是的 |

 还是无效。 

尝试所有可能性表明不存在有效的安排。 

这说明了为什么最终验证是实际的正确性标准。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n + m)`| DFS 访问每个顶点和边一次，验证扫描排列一次 |
 | 空间|`O(n + m)`| 邻接表、边集、递归栈和访问数组 |

 图形是线性处理的，即使对于最大输入大小，也可以轻松满足时间限制。 内存使用量也与图形大小成正比，并且保持在限制范围内。

import sys
import io

def solve():
    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 25)

    n, m = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    edges = set()

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        edges.add((a, b))

    visited = [False] * (n + 1)
    order = []

    def dfs(u):
        visited[u] = True

        for v in adj[u]:
            if not visited[v]:
                dfs(v)

        order.append(u)

    for i in range(1, n + 1):
        if not visited[i]:
            dfs(i)

    order.reverse()

    for i in range(n - 1):
        if (order[i], order[i + 1]) in edges:
            return "-1"

    return " ".join(map(str, order))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided sample
assert run("2 1\n1 2\n") == "-1", "sample 1"

# single vertex
assert run("1 0\n") == "1", "single node"

# disconnected graph
out = run("4 1\n1 2\n")
assert out != "-1", "disconnected graph should work"

# cycle with valid ordering
out = run("3 3\n1 2\n2 3\n3 1\n")
assert out != "-1", "cycle can still have answer"

# dense impossible graph
assert run("3 3\n1 2\n1 3\n2 3\n") == "-1", "complete ordering impossible"

 ## 边缘情况

 考虑断开连接的图：```
4 1
1 2
```DFS 可以按以下顺序处理顶点：```
2, 1, 3, 4
```反转：```
4 3 1 2
```这对`(1,2)`被禁止，所以该候选人失败。 另一种遍历可以产生：```
2 1 3 4
```相邻检查：```
(2,1) OK
(1,3) OK
(3,4) OK
```该算法可以正确处理断开连接的组件，因为 DFS 从每个未访问的节点开始。 

现在考虑循环：```
3 3
1 2
2 3
3 1
```一项有效的订单是：```
1 3 2
```检查：```
1 -> 3 exists? No
3 -> 2 exists? No
```这证实了循环本身并不意味着不可能。 

最后考虑完全排序的锦标赛：```
3 3
1 2
1 3
2 3
```每个排列都包含一些带有禁止边的相邻对：```
1 2 3
```失败`(1,2)`。```
2 1 3
```失败`(1,3)`。```
3 2 1
```失败`(2,1)`因为没有反向边缘，但是`(1,?)`最终造成另一次违规。 

该算法在最终邻接验证期间检测到这一点并打印`-1`。
