 ## 解决方案
 ## 问题理解

 每项遛狗工作都可以看作是Alice最多可以选择一次的项目。 一份工作包含两条信息：7 天需求模式和付款值。 该模式是一个长度为 7 的二进制向量，指示一周中的哪几天必须遛狗。 如果爱丽丝接受了一份工作，她承诺在其模式中标记为 1 的每一天遛狗，并且每项此类承诺都会消耗她的日常能力之一。 

每周的时间表是固定的：在 7 天的每一天，Alice 最多可以遛 2 只狗，因此每天的容量为 2。该约束对于所有选定的作业都是全局的，因为一项作业可能会同时消耗多天的容量。 

任务是选择一个工作子集，使总报酬最大化，同时确保每天需要的所选工作数量不超过 2 个。 

输入规模 N 较小，最多 100 个作业，但 7 天的约束耦合很强。 这立即表明，对工作子集进行暴力破解在概念上是可能的，因为最多有$2^{100}$子集，但显然不可行。 然而，真正的结构是每个作业仅与 7 个共享资源交互，这意味着状态空间从根本上由每日负载而不是 N 本身控制。 

天真的贪婪方法会失败，因为尽早选择高薪工作可能会阻碍多个较小的工作，而这些工作加起来超出了其价值。 例如，一项需要全部 7 天且奖励为 100 的工作在本地可能看起来是最优的，但需要不相交的天数子集的两项工作可能会产生总共 200 天的奖励，同时仍然遵守每天的容量限制。 

当一天中有多个作业严重重叠时，就会发生另一种微妙的失败情况。 选择太多中等价值的工作，并且都包括一天的忙碌，只有在最后才违反可行性，使得贪婪的选择很难追溯纠正。 

## 方法

 直接暴力法枚举每个作业子集，通过模拟每周容量使用情况检查可行性，并计算总利润。 可行性检查费用$O(7N)$每个子集，因为我们计算每天需要多少个选定的工作。 和$2^N$子集，这变成$O(2^N \cdot N)$，对于$N = 100$。 

关键的观察结果是，唯一的共享资源约束是一周中的 7 天，每天的容量为 2。这意味着系统状态可以通过这 7 天中每一天使用了多少个时隙来完整描述，即每个条目所在的 7 维向量$\{0,1,2\}$。 此类状态的总数为$3^7 = 2187$，对于动态规划来说足够小。 

如果坐标不超过 2，每个作业都会通过将固定的二进制向量添加到当前状态来转换系统。这将问题转换为小型多维容量空间上的经典背包式动态规划，其中项目是作业，维度是一周中的日子。 

因此，我们对所有可行的负载配置执行 DP，通过考虑是接受每个作业还是跳过它来更新状态。 将 100 个作业压缩到大小为 2187 的状态空间使解决方案变得高效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^N \cdot N)$|$O(7)$| 太慢了|
 | 日负荷状态下的最佳 DP |$O(N \cdot 3^7)$|$O(3^7)$| 已接受 |

 ## 算法演练

 我们将每个 DP 状态表示为一个整数 7 元组，其中每个条目记录当天已经分配了多少只狗。 每个条目的范围从 0 到 2。 

1.初始化字典或数组`dp`其中键是 7 天的状态，值是可实现的最大利润。 从值为 0 的全零状态开始。这表示不选择作业。 
2. 一项一项地处理工作。 对于每项工作，提取其 7 天需求向量及其付款。 
3. 对于每个现有的 DP 状态，考虑两种可能性：跳过作业，保持状态不变，或接受作业，将其需求向量添加到状态。 
4. 当尝试接受一份工作时，通过确保每天的结果计数不超过 2 来验证可行性。这确保我们尊重 Alice 的容量限制。 
5. 如果结果状态有效，则将该状态的 DP 表条目更新为其当前值和先前状态值中的最大值加上作业报酬。 
6. 处理完所有作业后，答案是所有 DP 状态中的最大值。 

关键思想是 DP 永远不需要记住选择了哪些作业，只需要记住诱导的负载配置。 这是有效的，因为所有未来的约束仅取决于当前的负载，而不是工作身份。 

### 为什么它有效

 在任何时候，每个 DP 状态都会在处理作业前缀后精确编码一组可实现的负载配置，以及每个配置可获得的最佳利润。 处理新作业时，转换会考虑通过排除或包含作业来扩展先前有效配置的所有方法。 由于可行性仅取决于累计日负荷，并且这些负荷在州中得到了充分体现，因此未来决策所需的信息不会丢失。 因此，DP不变量成立：在处理i个作业后，所有可达到的有效状态及其最佳利润都被正确记录。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def encode(state):
    # base-3 encoding of 7 digits
    res = 0
    for x in state:
        res = res * 3 + x
    return res

def decode(x):
    state = [0] * 7
    for i in range(6, -1, -1):
        state[i] = x % 3
        x //= 3
    return state

def add_state(state, req):
    new_state = state[:]
    for i in range(7):
        new_state[i] += req[i]
        if new_state[i] > 2:
            return None
    return new_state

def solve():
    n = int(input())
    jobs = []
    for _ in range(n):
        *days, val = map(int, input().split())
        jobs.append((days, val))

    dp = {encode([0]*7): 0}

    for days, val in jobs:
        cur_items = list(dp.items())
        for mask, profit in cur_items:
            state = decode(mask)

            new_state = add_state(state, days)
            if new_state is not None:
                new_mask = encode(new_state)
                if new_mask not in dp or dp[new_mask] < profit + val:
                    dp[new_mask] = profit + val

    print(max(dp.values()))

if __name__ == "__main__":
    solve()
```DP 表存储为字典，以 7 天负载向量的基 3 编码为键。 这避免了在内部循环中重复复制 7 元素列表，同时仍然保持状态紧凑。 

每个作业都是通过迭代当前状态的快照来处理的。 这很重要，因为当前作业的更新不得立即影响同一作业的其他转换，否则会超出选择范围。 

Base-3 编码确保快速散列和状态比较，并且仅在需要应用转换时才进行解码。 由于状态空间很小，因此这种开销可以忽略不计。
