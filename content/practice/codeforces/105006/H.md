 ## 解决方案
 ## 问题理解

 我们得到一棵最多有 20 个节点的树，其中每个节点代表一种具有固定美味值的美食。 两个玩家不断地移除节点，直到什么都没有留下。 在每次移动中，Bob 首先选择剩余树中当前叶子的任意两个节点。 然后查理决定吃两个中的哪一个，鲍勃吃另一个。 两者都被移除后，它们的关联边缘消失，并且该结构可能会暴露新的叶子以供后续移动。 

两位球员都是完美的最佳球员。 鲍勃想要最大化他最终吃到的总美味，而查理想要最大化他自己的总美味，这间接地最小化了鲍勃从每对选择的叶子中获得的收益，因为查理总是会选择所提供的两片叶子中更有价值的。 

从 Bob 的角度来看，一旦他选择了一对值为 x 和 y 的叶子，他从该移动中获得的保证收益就是 min(x, y)，因为 Charlie 将采取 max(x, y)。 树的结构之所以重要，只是因为它限制了每一步允许哪些节点配对：只能选择当前剩余的导出子图的叶子。 

约束 N ≤ 20 是这里的关键信号。 N 中的状态空间指数是可以接受的，大约可达 2^20 左右，即一百万左右。 任何涉及所有移除顺序的排列都会太大，但子集动态规划变得现实。 

天真的思维的一个微妙的失败案例是假设鲍勃可以简单地将全局最小值配对在一起或贪婪地选择最好看的配对。 树约束可以强制提前删除低价值的叶子，从而改变未来叶子的可用性。 

考虑像 1-2-3-4 这样的简单链，其值为 100, 1, 100, 1。最大叶子的贪婪配对可能会重复选择 (100,100) 或 (100,1)，而不考虑删除如何影响未来的叶子，但叶子对的实际合法性在每次删除后都会发生变化。 

主要困难在于“叶子”不是静态属性。 最初不是叶子的节点可以在以后成为叶子，因此任何解决方案都必须考虑动态结构变化，而不仅仅是初始度数。 

## 方法

 蛮力策略会尝试所有可能的有效动作序列。 在每一步中，我们选择两个当前的叶子，在所有这些对上进行分支，并递归地模拟删除。 选择一对后，我们还假设查理选择最优，因此在每对中鲍勃只收到较小的值。 

这种方法的正确性很简单，因为它直接反映了游戏。 然而，状态的数量由剩余节点的子集和它们被删除的顺序决定。 即使忽略顺序，也有 (2n-1) 个！ 可能的配对，并且随着叶约束的动态演变，分支因子变得爆炸性的。 对于 n = 20，这远远超出了可行的计算范围。 

关键的观察是移动的顺序并不重要，重要的是剩余节点的集合。 一旦我们处于由节点子集定义的状态，唯一相关的信息是接下来可以删除哪些叶子对。 这将问题转化为子集 DP，其中转换一次删除两个节点。 

通过检查节点是否是当前子集的导出子图中的叶子来隐式处理树结构。 这避免了显式模拟超出子集表示的操作序列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 移动序列的暴力递归 | 移动指数（超阶乘）| O(n) 堆栈 | 太慢了|
 | 有效叶对删除的子集 DP | O(2^n · n^2) | O(2^n · n^2) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 我们将节点的每个子集视为代表剩余零食集的状态。

1. 将每个状态表示为大小为 N 的位掩码 S，其中位 i 指示节点 i 是否仍然存在。 
2. 以位掩码形式预先计算邻接关系，以便对于每个节点 u，我们可以快速确定子集 S 中仍然存在 u 的邻居数。这使我们可以通过检查 u 是否最多有一个活动邻居来确定 u 是否是 S 中的叶子节点。 
3. 定义 DP[S] 为 Bob 从剩余集合 S 开始仍可获得的最大总味道。 
4.对于每个子集S，我们考虑所有有效的移动。 一次移动包括选择两个不同的节点 u 和 v，它们都是 S 的导出子图中的叶子。我们计算下一个状态 S' = S（没有 u 和 v），并且 Bob 从这次移动中获得 min(t[u], t[v])。 
5. 我们通过尝试每个这样的有效对并取 DP[S'] + min(t[u], t[v]) 的最大值来计算 DP[S]。 基本情况是 DP[0] = 0。 
6. 按大小递增的顺序迭代子集，以便所有转换都从已计算的较大子集到较小子集。 

关键部分是叶子检查。 如果一个节点在原始树的邻居中，至多一个邻居也存在于 S 中，则该节点是子集 S 中的叶子。这个条件是充分的，因为树的导出子图仍然是森林，并且在任何森林中，叶子恰好是度数最多为 1 的节点。 

### 为什么它有效

 每个有效的游戏状态都精确对应于经过一些合法移动序列后可能保留的节点子集。 从任何这样的状态，唯一可用的决策是当前叶子对，并且每个这样的叶子对都确定性地导致更小的有效状态。 因为 Bob 从每次移动中获得的收益仅取决于所选择的对，而不取决于未来的随机性，所以最优子结构成立：S 的最佳结果完全由所有可达 S' 的最佳结果决定。 这保证了子集上的 DP 捕获所有可能的最佳播放序列，而不会丢失任何可到达的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))
    
    adj = [0] * n
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    size = 1 << n
    dp = [0] * size

    # iterate by increasing subset size
    for mask in range(size):
        nodes = [i for i in range(n) if mask >> i & 1]
        m = len(nodes)
        if m < 2 or m % 2 == 1:
            continue

        # compute degree in induced subgraph
        deg = [0] * n
        for u in nodes:
            deg[u] = bin(adj[u] & mask).count("1")

        # find leaves
        leaves = [u for u in nodes if deg[u] <= 1]

        # try all leaf pairs
        for i in range(len(leaves)):
            for j in range(i + 1, len(leaves)):
                u = leaves[i]
                v = leaves[j]
                if u == v:
                    continue
                nxt = mask ^ (1 << u) ^ (1 << v)
                gain = min(t[u], t[v])
                dp[mask] = max(dp[mask], dp[nxt] + gain)

    print(dp[(1 << n) - 1])

if __name__ == "__main__":
    solve()
```该实现将每个子集编码为位掩码，并通过显式重建哪些节点是该子集中的叶子来计算转换。 邻接被存储为位掩码，以便在计算度数时快速计算相交。 

DP 在子集上自下而上填充。 对于每个状态，仅考虑有效叶子对，并且每个转换恰好删除两个节点，确保我们转向已评估的较小子集。 

一个常见的陷阱是错误地使用原始树叶而不是诱导子图树叶。 这将允许非法行动并产生过于乐观的结果。 每个子集内的度计算避免了这种错误。

 ## 边缘情况

 一种边缘情况是树退化为路径。 在路径中，叶对始终是当前剩余线段的端点。 DP 自然地处理这个问题，因为诱导度正确地识别每个子集的端点。 

另一种情况是星图。 最初只有中心不是叶子，但在成对移除叶子后，中心可能会变得孤立，并在以后的状态中表现为叶子。 子集 DP 正确捕获了此转换，因为叶状态是按子集重新计算的，而不是假定的静态状态。 

最后一种情况是节点之间的值相同。 每个有效的配对都会产生相同的增益，因此 DP 简化为计算移动次数。 该算法仍然有效，因为 min(a,b) 在对之间是不变的，使得所有转换等效，并且 DP 只是累积均匀的贡献。
