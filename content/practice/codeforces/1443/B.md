 ## 解决方案
 ## 问题理解

 我们有一个由一排建筑物表示的城市，每个建筑物可能有也可能没有矿井。 城市地图是一串零和一，其中“1”表示地雷，“0”表示安全建筑物。 工兵有两个操作：他可以花费一定的费用来激活地雷`a`，这会导致该段中的所有连续地雷爆炸，或者他可以在建筑物中放置地雷，但需要付出一定的成本`b`。 我们的目标是以最低的总成本清除所有地雷，确保城市安全。 

输入给出了多个测试用例。 对于每一个，我们都被要求计算所需的最小硬币支出。 约束允许最多`10^5`所有测试用例的建筑物总数。 这排除了任何明确模拟所有可能的地雷激活或放置序列的解决方案，因为即使每个测试用例的 O(n²) 也会太慢。 线性或近线性解是可行的。 

地雷段之间的零序列存在微妙之处。 如果放置地雷的成本`b`比激活单独的地雷要小`a`，通过放置地雷来连接两个独立的地雷段可能比单独激活它们更便宜。 仅独立激活每个现有段的简单方法会忽略此优化。 例如，在字符串“1100011”中`a=5`和`b=1`，分别激活两个段需要花费 10，但在间隙中放置一颗地雷然后激活整个相连的段只需花费 6。 

## 方法

 暴力方法是识别每个连续的地雷块并单独激活它，总结`a`每块。 如果我们忽略放置地雷来合并方块的选项，这将正常工作。 在最坏的情况下，如果所有建筑物都是地雷，则只有一个部分，并且复杂性与建筑物的数量成线性关系。 但如果矿段之间的间隙很小并且`b < a`，强力法将无法找到最小成本，因为它没有考虑合并段。 

关键的观察结果是，激活任何连续的矿区都有固定成本`a`，并合并由`k`零成本`k * b`。 因此，对于段之间的每个零间隙，我们可以贪婪地决定：要么支付`a`单独激活下一段或付费`k * b`填补空白并连接段，然后支付单一`a`激活组合段。 自从`a`和`b`都是小整数，最小值`a`和`k*b`为每个间隙提供更便宜的选择。 

一旦我们将问题简化为评估段之间的差距并最佳地求和成本，解决方案就变成线性的：我们首先识别所有矿段，然后迭代间隙并应用最小公式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（分别激活每个部分）| O(n) | O(1) | O(1) | 正确但可能不是最理想的 |
 | 最佳（考虑合并具有差距成本的细分）| O(n) | O(1) | O(1) | 正确高效|

 ## 算法演练

 1. 对于每个测试用例，请阅读`a`,`b`，以及城市地图字符串。 如果方便的话，将字符串转换为列表。 
2. 忽略任何前导零和尾随零，因为它们不会影响成本。 
3. 确定第一个矿区。 初始化总成本`a`来激活它。 
4. 迭代字符串的其余部分以查找后续的矿段。 对于每个段：

 1. 测量长度`k`紧接在该段之前的零。 
2. 添加`min(a, k * b)`到总成本。 如果放置地雷比单独激活更便宜，我们会模拟连接各个部分。 
5. 处理完所有段后，输出该测试用例的总成本。 

关键的不变量是，在每一步，总成本正确反映了消除当前位置所有地雷的最小成本。 选择`min(a, k*b)`保证每个间隙都得到最佳处理，而无需测试所有组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        s = input().strip()
        n = len(s)

        # find first and last mine
        first = s.find('1')
        if first == -1:
            print(0)
            continue
        last = s.rfind('1')

        total = a  # activate first segment
        i = first
        while i <= last:
            if s[i] == '0':
                zero_count = 0
                while i <= last and s[i] == '0':
                    zero_count += 1
                    i += 1
                if i <= last:
                    total += min(a, zero_count * b)
            else:
                i += 1
        print(total)

if __name__ == "__main__":
    solve()
```该代码首先定位第一个和最后一个地雷，以避免在地雷区域之外对零进行不必要的处理。 我们总是为了成本而激活第一段`a`。 对于段之间的每个零间隙，我们计算其长度并添加`min(a, gap*b)`到总成本。 这捕获了单独激活下一段或将其连接到前一段的选择。 

边界处理很微妙：内部循环不得超出最后一个矿井之外的零数，并且`if i <= last`确保我们只为后续片段之前的间隙付费。

 我们为 1 个硬币激活第一个“1”，然后在下一段之前有 4 个零的间隙。`min(a, k*b) = min(1, 4*1)=1`。 总计 = 2，与预期输出相符。

 第一个分段激活 5。零间隙 1，连接到下一个分段成本`min(5,1*1)=1`。 总共 6 个，与预期输出相符。

 ## 边缘情况

 对于没有地雷的字符串，算法发现`first = -1`并立即打印 0。对于单个地雷，第一段被激活`a`硬币，并且跳过零循环。 对于间隙大于`a/b`，算法通过采取正确的方式在连接段或单独激活之间进行选择`min(a, k*b)`。 对于所有建筑物都有地雷的字符串，第一段覆盖整个城市，总成本为`a`。 在每种情况下，总成本反映每个差距的最小选择的不变性保证了正确性。
