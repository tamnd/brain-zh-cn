 ## 解决方案
 ## 问题理解

 我们有两个水平层的点。 一层位于线上$y=0$，另一个位于$y=2$。 每层都包含不同的 x 坐标。 移动包括选择不位于一条线上的三个剩余点，获得它们形成的三角形的面积，然后永久删除这些点。 

由于每层中的所有点共享相同的 y 值，因此仅当我们从两层中选取点时，任何三元组都是非退化的。 完全在一行内形成的三角形始终是共线的并且没有任何贡献，因此每个有效的操作都必须混合来自两行的点。 

任务不仅是找到此类操作的最大数量，而且还针对每个可能的操作数量$k$，如果我们被迫精确执行，则计算最佳可实现的总面积$k$操作独立于较小的值。 

约束条件很大：最多$2\cdot 10^5$每次测试的总分。 任何尝试模拟操作或直接检查三元组的解决方案都会立即失败，因为三元组的数量是立方的。 即使每次测试基于排序的二次推理在所有情况下仍然太慢。 该解决方案必须将问题简化为由订购得出的一小组聚合数量。 

一个微妙的边缘情况是当其中一行非常小时。 例如，如果$n=1, m=1$，我们总共只有两个点，所以不存在三角形，答案是$k_{\max}=0$。 另一种情况是，当一行恰好有两个点时：那么每个三角形都必须使用这两个点，并且我们被迫进入一种严格的结构，其中每个操作恰好消耗一行中的两个点和另一行中的一个点。 

像“总是取最左边和最右边的点”这样天真的贪婪策略可能会失败，因为三角形的贡献取决于操作之间的配对结构，而不仅仅是单个极端。 最佳排列取决于全局排序和配对一致性。 

## 方法

 蛮力视角将尝试模拟操作：在每一步，尝试所有点的三元组，计算面积，删除最佳的三元组，然后重复。 即使使用记忆化，状态空间的点数也是指数级的，并且每一步都需要扫描$O(n^3)$候选人。 除了微小的输入之外，这会立即失败。 

关键观察是几何结构。 由于所有点都位于两条平行的水平线上，因此任何有效三角形的面积都会大大简化。 如果我们从一条线上选取两个点，并从另一条线上选取一个点，则面积将与两个同一行点之间的水平距离成正比。 垂直高度固定为 2，因此面积本质上是 x 坐标差乘以常数因子。 

这将问题从几何问题转换为排序数组上的配对问题。 每个操作有效地将一行中的两个点与另一行中的一个点匹配，并且总分成为所选成对距离的总和。 该结构进一步简化：最优解总是将极值点配对在一起。 

现在的问题是决定每次操作从每一方拿多少分。 每个操作消耗三个点，因此操作总数受到我们可以形成的三元组数量的限制，即每个三角形必须至少使用相对行中的一个点。 这导致了一个简单的计数界限：$$k_{\max} = \min\left(\frac{n+m}{3}, n, m\right)$$但真实的结构稍微强一些：每个操作必须在最佳配置中恰好使用一行中的两个点和另一行中的一个点。 

在固定的范围内最大化面积$k$，我们想要在排序数组的贪婪配对中选择最大可能的成对距离。 这成为经典的“走极端”匹配：对两个数组进行排序，然后模拟从两端选择最佳对。 每个附加操作的边际贡献可以增量得出。 

而不是从头开始重新计算每个$k$，我们按降序构建贡献：最好的第一个操作使用最大的可用跨度，下一个使用下一个最佳的剩余配置，依此类推。 这会产生单调的增益序列，允许前缀和产生所有$f(k)$。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳 |$O(n \log n)$| O(n) | 已接受 |

 ## 算法演练

 1. 对两个数组进行排序$a$和$b$。 排序至关重要，因为最佳三角形始终取决于极端坐标间隙而不是任意排序。 
2. 预先计算配对极值的绝对贡献。 唯一有用的结构是同一行上选定点之间的距离，因为垂直距离是固定的。 这将每个三角形减少为加权水平跨度。 
3. 每个数组维护两个指针，一个在左端，一个在右端。 在每一步中，考虑将任一数组中的最大剩余跨度与相对行中的点相结合。 
4. 每个操作在两个候选结构之间进行选择：使用来自的两个极值点$a$和一个来自$b$，或两个来自$b$和一个来自$a$。 我们总是选择能产生更大即时增益的配置。 
5. 选择配置后，删除已使用的点并更新指针。 这确保了未来的选择始终作用于剩余的极值结构。 
6. 将每次操作的增益记录在列表中。 由于每一步总是消除极端，因此增益序列是非递增的。 
7. 计算增益数组上的前缀和以获得$f(1), f(2), \ldots, f(k_{\max})$。 

### 为什么它有效

 关键的不变量是，排序后，任何最佳三角形分解都可以重新排列，以便每个操作仅使用当前的极值点，而不会降低总分。 任何内部点都可以向外交换，而不会减少可用跨度，因为面积仅取决于水平差异。 这种交换论证保证了将注意力限制在贪婪的极端配对上不会失去最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, m, a, b):
    a.sort()
    b.sort()

    # total number of operations is bounded by triples
    kmax = min((n + m) // 3, n, m)

    # We will construct gains greedily from extremes
    i, j = 0, 0
    i2, j2 = n - 1, m - 1

    gains = []

    # We simulate taking kmax operations
    for _ in range(kmax):
        if i2 - i + 1 < 2 and j2 - j + 1 < 2:
            break

        # option 1: take 2 from a, 1 from b
        gain_a = 0
        if i2 - i + 1 >= 2 and j <= j2:
            gain_a = (a[i2] - a[i]) * 2

        # option 2: take 2 from b, 1 from a
        gain_b = 0
        if j2 - j + 1 >= 2 and i <= i2:
            gain_b = (b[j2] - b[j]) * 2

        if gain_a >= gain_b:
            gains.append(gain_a)
            i += 1
            i2 -= 1
        else:
            gains.append(gain_b)
            j += 1
            j2 -= 1

    # prefix sums
    for k in range(1, len(gains)):
        gains[k] += gains[k - 1]

    return len(gains), gains

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        kmax, vals = solve_case(n, m, a, b)
        out.append(str(kmax))
        if kmax > 0:
            out.append(" ".join(map(str, vals)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案首先对两个层进行排序，以便极端对对应于最大水平跨度。 两指针边界跟踪未使用的点。 在每一步中，我们都会根据当前宽度比较从顶行或底行花费两个点是否会产生更大的贡献。 因子 2 来自固定的垂直高度 2，它将面积转换为 x 坐标的比例差。 

前缀累积将每次操作的收益转换为所有精确计数的答案，因为每个$f(k)$是第一个的总和$k$选择最佳动作。

现在考虑一个倾斜的情况：

 ## 边缘情况

 例如，当一侧非常小时$n=1, m=3$，算法很快检测到该边不存在有效的同行极值对，因此它总是选择另一行，直到无法形成三角形为止。 增益列表自然会提前截断，产生$k_{\max}=0$。 

当两个阵列在零附近完全对称时，两侧的极差相等。 打破平局的规则变得无关紧要，因为任何选择都会保留最佳的总跨度； 无论分支选择如何，前缀和都保持一致。 

当点紧密聚集在一行中而广泛分布在另一行中时，算法始终首先优先考虑宽行。 一旦耗尽，它就会平滑地过渡到另一行，因为增益之间的比较是局部的并且不依赖于未来的结构。
