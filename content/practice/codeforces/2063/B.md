 ## 解决方案
 ## 问题理解

 我们得到一个数组和一个目标段$[l, r]$。 我们计算该段内元素的总和，但我们可以在测量之前执行一个全局操作。 

该操作不是子数组的标准反转。 相反，我们按升序选择任何一组索引，并反转这些索引中的值。 换句话说，我们采用值的子序列，并通过反转它们的顺序来仅排列那些选定的值，同时将其他所有内容固定在适当的位置。 

目标是最小化固定段内最终值的总和$[l, r]$在这个单一的子序列反转之后。 

重要的观察是我们并不局限于连续交换。 只要我们将两个索引都选择到所选子序列中，段外部的任何位置都可以与段内部的任何位置交互。 

这些限制使我们远离任何组合探索。 和$n \le 10^5$每个测试和总大小也$10^5$，任何二次或偶数$O(n \log n)$每个测试解决方案只有在简单的情况下才是可接受的，但是任何涉及子集枚举或区间 DP 的事情都是立即不可能的。 

当段中的所有值与其余值相比已经是最小值或最大值时，就会出现微妙的边缘情况。 天真的贪婪交换方法可能会尝试重复改进段，但此操作是全局且一次性的，因此过度更新的直觉会失败。 另一个边缘情况是当$l = r$，我们最小化单个元素； 这里的操作退化为选择该元素是否可以通过配对被外部的东西替换。 

## 方法

 强力解释将尝试模拟所有可能的子序列。 我们选择索引的子集，反转它们的值，然后重新计算段总和。 即使我们固定子集大小$k$，选择指数为$\binom{n}{k}$，并对所有内容求和$k$是指数的。 即使对于$n = 40$，因此超出概念正确性之外没有任何意义。 

关键的结构洞察力是停止从排列的角度思考，而是从配对的角度思考。 

反转子序列会执行一些非常具体的操作：它在所选集合内创建不相交的索引对，其中每对交换值。 如果索引未配对，则它保持不变。 所以该操作相当于在仓位之间选择一些不相交的交换。 

现在仅关注段总和如何变化。 仅跨越边界的交换$[l, r]$事情。 如果我们交换内部或外部的两个位置，则段总和不变。 如果我们将内部的一个与外部的一个交换，我们就可以有效地将段中的值替换为外部的值。 

因此问题就变成了：我们最多可以选择$(r-l+1)$段内的元素，并将它们与外部的元素进行匹配，用外部值替换段值，但有一个约束：每个外部元素最多只能使用一次，并且每次交换消耗一个内部索引和一个外部索引。 

为了最小化总和，我们希望用外部的最小值替换段中的最大值。 这建议对候选者进行排序：获取所有段值和所有外部值，并在提高总和时将大段内值与小外部值贪婪地匹配。 

除了这种贪婪配对之外，我们不需要完整的匹配结构，因为每个有益的交换对总和的影响是独立的。

 ## 算法演练

 1. 将数组拆分为两个多重集：里面的值$[l, r]$以及它之外的价值观。 段总和是根据内部集合计算的。 
2. 按降序对内部值进行排序，以便我们可以首先考虑最大的元素。 这些是唯一值得更换的，因为更换较小的部件永远不会比更换较大的部件更有效地提高总和。 
3. 按升序对外部值进行排序，以便我们可以首先考虑最小的可用替换。 这些是进入该细分市场的最佳候选人。 
4. 同时迭代两个列表。 尝试将最大剩余内部值与最小剩余外部值配对。 
5. 仅当外部值严格小于内部值时才执行交换。 这个条件保证了段总和减少； 否则交换是有害的或中性的，不应使用。 
6. 每次成功配对都会将段总和减少内部值和外部值之间的差值，并且两个指针都会前进。 
7. 当任一列表已用尽或无法进一步改进时停止。 

最终答案是原始段总和减去成功交换所获得的所有改进。 

### 为什么它有效

 该操作允许通过子序列反转进行任意配对，因此对段的每次有效更改都相当于在内部索引和外部索引之间交换值。 由于每个元素最多参与一次交换，因此问题简化为选择不相交的有益交换。 

贪心策略是正确的，因为每次交换对总和变化的贡献都是独立的：交换总是以固定差值改变总和。 将最大的可用收益与最小的可用成本配对永远不会阻碍更好的未来选择，因为使用较大的外部值代替较小的外部值会严重恶化或不会改善结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = list(map(int, input().split()))
        
        l -= 1
        r -= 1
        
        inside = a[l:r+1]
        outside = a[:l] + a[r+1:]
        
        inside.sort(reverse=True)
        outside.sort()
        
        base = sum(inside)
        
        i = 0
        j = 0
        
        while i < len(inside) and j < len(outside):
            if outside[j] < inside[i]:
                base += outside[j] - inside[i]
                i += 1
                j += 1
            else:
                break
        
        print(base)

if __name__ == "__main__":
    solve()
```该实现将数组干净地分为内部和外部部分，确保我们只推理值，而不推理位置。 对两组进行排序至关重要，因为它将配对决策变成了一个单调的过程。 

一个微妙的点是交换条件中的严格不平等。 允许相等不会提高总和​​，并且可能会错误地消耗有用的元素。 

另一个重要的细节是我们永远不需要重建数组。 只有多重集结构很重要，因为子序列反转操作不会保留超出配对容量的位置约束。 

## 工作示例

 考虑一个简单的情况，其中$a = [1, 2, 3]$和$[l, r] = [2, 3]$。 

里面是$[2, 3]$，外面是$[1]$。 排序给出里面$[3, 2]$， 外部$[1]$。 

| 步骤| 内部| 外面| 行动| 段总和 |
 | --- | --- | --- | --- | --- |
 | 初始化| [3, 2] | [1] | 无 | 5 |
 | 1 | [3, 2] | [1] | 将 3 与 1 交换 | 3 |

 该算法执行一次有益交换，将 3 替换为 1，将总和从 5 减少到 3。这与最佳配置匹配，因为仅存在一个外部元素。 

现在考虑$a = [5, 1, 4, 2]$和$[l, r] = [2, 3]$。 

里面是$[1, 4]$，外面是$[5, 2]$。 排序给出里面$[4, 1]$， 外部$[2, 5]$。 

| 步骤| 内部| 外面| 行动| 段总和 |
 | --- | --- | --- | --- | --- |
 | 初始化| [4, 1] | [2, 5] | 无 | 5 |
 | 1 | [4, 1] | [2, 5] | 将 4 与 2 交换 | 3 |
 | 停止| [1] | [5]| 2 ≥ 1 无交换 | 3 |

 该轨迹显示了为什么贪婪停止是必要的：一旦最佳可用外部候选值不小于当前内部值，就不可能进一步改进。

 ## 边缘情况

 当段是单个元素时，算法简化为检查是否有任何外部值更小。 排序逻辑仍然有效，但只有一个内部候选存在，因此最多可以替换一个。 痕迹很简单并且符合直觉。 

当所有元素都相等时，排序会产生相同的列表。 交换条件立即失败，因此不会应用任何更改并返回原始总和，这是正确的，因为没有操作可以改进统一值。 

当线段位于边界时，例如$l = 1$或者$r = n$，其中一个列表变为空。 该算法自然执行零交换，并且答案仍然是段的总和，因为没有外部材料可以交换。
