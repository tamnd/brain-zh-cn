 ## 解决方案
 ## 问题理解

 我们有一个无向图，其顶点是服务器，边是物理连接。 服务器只能从属于同一连接组件的另一台服务器下载文件。 服务器标识符是最大 (10^9) 的任意整数，因此它们不能直接用作数组索引。 

对于每个查询，(X) 是目标服务器，以下列表包含当前具有所请求文件的服务器。 我们必须准确保留连接到 (X) 的服务器 (Y)，并按其原始顺序打印它们。 顺序很重要，因此查询列表不能简单地转换为集合。 

该图最多可以包含 (10^6) 条边。 因此，几乎可以有 (2\cdot10^6) 个不同的服务器标识符。 由于只有 1.5 秒的可用时间，为每个查询运行图形遍历的成本太高。 使用（Q\le 1000），即使每个查询扫描一次所有（10^6）条边也可以达到（10^9）条边检查。 查询列表本身很小，因为 (K_i\le100)，所以主要任务是有效地预处理连接。 

该图还可以包含仅在查询中出现的服务器标识符。 这样的服务器是一个孤立的顶点，除非它通过输入边之一连接。 仅存储边中出现的顶点的粗心实现可能会错误地处理图形中不存在 (X) 和 (Y) 的查询。 例如：```
0
1
42 2
42 17
```正确的输出是：```
1 42
```两台服务器是隔离的，但当它们的标识符相等时，它们是同一台服务器。 将每个未知标识符视为属于某个通用“未知”组件将错误地接受`17`。 

第二个边缘情况是图中出现的服务器，但另一个候选服务器没有出现。 例如：```
1
1 2
1
1 2
3 2
```正确的输出是：```
1 2
```服务器`3`是一个孤立的顶点，无法从服务器下载`2`，即使程序已知这两个标识符。 解决方案必须区分不同的孤立顶点。 

第三个边缘情况是，如果输入包含重复项和排序，则答案必须保留它们。 例如：```
0
1
7 3
7 7 8
```输出是：```
2 7 7
```该查询询问三个列出的源，并且都出现`7`是有效的。 对查询列表进行排序或去重会更改所需的输出。 

## 方法

 直接的解决方案是使用 DFS 或 BFS 为每个查询单独找到 (X) 的连通分量。 一旦知道该组件，就可以对照它检查最多 100 个候选服务器中的每一个。 这是正确的，因为连通性正是定义是否可以下载的条件。 

问题在于重复的图遍历。 在最坏的情况下，一次遍历可以检查所有 (10^6) 条边。 在计算额外的顶点工作之前，使用 (1000) 个查询最多可进行 (10^9) 次边缘检查。 对每个候选者 (Y) 进行单独的遍历会更糟糕，可能会进行大约 (10^{11}) 个连接检查。 

图结构为我们提供了更强有力的观察。 每个查询仅询问两个顶点是否属于同一连通分量。 我们永远不需要它们之间的实际路径。 这正是不相交集并集结构 (DSU) 支持的操作。 在读取每条边 ((A,B)) 时，我们合并包含 (A) 和 (B) 的分量。 处理完所有边后，当且仅当两个服务器的 DSU 代表相等时，它们才会连接。 

任意服务器标识符引入了第二个问题。 传统的 DSU 期望紧凑的索引，例如 (0,\ldots,V-1)。 坐标压缩可以解决这个问题，但在 64 MB 内存限制下，存储数百万个 Python 整数和一个大字典是不可取的。 下面的实现使用了一个紧凑的开放寻址哈希表，由`array('I')`。 每个占用的哈希表槽都存储服务器标识符及其 DSU 父代。 由于标识符是正数，因此零可以代表未使用的槽。 

蛮力之所以有效，是因为遍历直接发现了一个连接的组件，但当对许多查询重复相同的昂贵遍历时就会失败。 每个查询只是一个组件成员资格测试这一观察结果让我们可以用几乎恒定时间的 DSU 操作来替换图遍历。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(Q(N+V))) | (O(N+V)) | 太慢了，最多大约 (10^9) 次边缘检查 |
 | DSU + 紧凑哈希表 | 预期 (O(N\alpha(V)+QK\alpha(V))) | (O(V)) | 已接受 |

 这里 (V\le2N) 表示出现在边中的顶点，(\alpha) 是逆阿克曼函数，并且哈希表操作期望 (O(1)) 时间。 

## 算法演练

 1. 读取 (N)，图边的数量，并创建一个足够大的紧凑哈希表以容纳所有可能的端点。 由于最多有 (2N) 个不同的端点，并且我们至少保留两倍数量的插槽，因此负载因子保持在二分之一以下。 这给出了较短的预期探针序列。 
2. 对于每条边 ((A,B))，如果两个服务器标识符不存在，则将它们插入到哈希表中。 新插入的服务器作为其自己的 DSU 根启动。 然后合并(A)和(B)的根。 

DSU 不需要由压缩顶点编号索引的单独父数组。 哈希表槽本身充当顶点索引，它保存另一个映射数组并保持较小的内存使用量。 
3. 实施`find`与路径压缩。 从服务器的槽开始，跟随父槽，直到到达其父槽本身的根。 然后压缩遍历的路径，以便后续操作更快地到达根。 
4. 实施`union`通过找到两个根并将一个根附加到另一个根上。 该实现使用根槽本身作为父值，因此不需要额外的等级或大小数组。 
5. 处理图表后读取每个查询。 对于目的地 (X)，查找其哈希表槽。 如果存在，则其 DSU 根代表其连接的组件。 如果不存在，则 (X) 是隔离服务器。 
6. 按原始顺序阅读 (K) 个候选来源。 对于每个（Y），首先检查其标识符是否存在于图的哈希表中。 如果(X)和(Y)都不存在，则仅当它们的标识符相等时才连接。 如果恰好缺少一个，则它们无法连接。 如果两者都存在，则比较它们的 DSU 根。 
7. 将每个有效来源附加到答案中，而不改变其相对于其他候选者的位置。 打印计数，后跟所选标识符。 

### 为什么它有效

 处理完所有边后，DSU 不变量是，当图中出现的两个服务器之间存在路径时，它们具有完全相同的代表。 每个输入边都连接其两个端点，因此由一系列边连接的每一对最终都会合并到一个 DSU 集中。 相反，DSU 永远不会合并两个组件，除非输入边将它们连接起来，因此两个不同的图组件永远不会收到相同的代表。 

边缘列表中不存在的服务器的度数为零，因此是一个孤立的组件。 当两个这样的服务器具有相同的标识符时，它们就被精确地连接起来。 查询逻辑单独处理这种情况，因此当每个候选属于目标的连接组件时，它都会被准确地接受。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

MASK32 = 0xFFFFFFFF
MULT = 2654435761

def solve():
    n_line = input()
    if not n_line:
        return
    n = int(n_line)

    # At most 2*n different server identifiers occur in edges.
    # Keep the load factor below 1/2.
    need = max(2, 4 * n)
    size = 1
    while size < need:
        size <<= 1

    mask = size - 1

    # 0 means an unused slot. Server identifiers are >= 1.
    keys = array('I', [0]) * size
    parent = array('I', [0]) * size

    def locate(x):
        """Return the slot containing x, or 0 if x is absent."""
        p = (x * MULT) & mask
        while True:
            k = keys[p]
            if k == 0:
                return 0
            if k == x:
                return p
            p = (p + 1) & mask

    def get_slot(x):
        """Find x, inserting it as a new DSU root when necessary."""
        p = (x * MULT) & mask
        while True:
            k = keys[p]
            if k == 0:
                keys[p] = x
                parent[p] = p
                return p
            if k == x:
                return p
            p = (p + 1) & mask

    def find(p):
        root = p
        while parent[root] != root:
            root = parent[root]

        while parent[p] != p:
            nxt = parent[p]
            parent[p] = root
            p = nxt

        return root

    def union(a, b):
        ra = find(a)
        rb = find(b)
        if ra != rb:
            parent[rb] = ra

    for _ in range(n):
        a, b = map(int, input().split())
        sa = get_slot(a)
        sb = get_slot(b)
        union(sa, sb)

    q = int(input())
    out = []

    for _ in range(q):
        x, k = map(int, input().split())
        ys = list(map(int, input().split()))

        sx = locate(x)

        if sx == 0:
            # x is an isolated server.
            ans = [y for y in ys if y == x]
        else:
            rx = find(sx)
            ans = []

            for y in ys:
                sy = locate(y)
                if sy != 0 and find(sy) == rx:
                    ans.append(y)

        if ans:
            out.append(str(len(ans)) + " " + " ".join(map(str, ans)))
        else:
            out.append("0")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```实现的第一部分根据边缘端点的最大可能数量来分配哈希表。 每个边缘保留四个时隙，因此即使每个端点不同，该表的负载系数最多为二分之一。 二次方大小允许使用位掩码而不是更昂贵的模运算来获取哈希位置。`get_slot`在处理边时使用，因为每个端点都必须成为 DSU 顶点。`locate`用于查询，因为从未出现在边中的查询标识符必须保持为孤立的顶点，而不是插入到现有组件中。 

父数组存储哈希表槽编号。 对于新插入的标识符，`parent[p] = p`，使该插槽成为自己的根。 当两个组件合并时，一个根将另一个根存储为其父级。 路径压缩在`find`然后使后续操作几乎恒定的时间。 

Python 中不存在整数溢出问题。 哈希函数使用的乘法被显式屏蔽为 32 位，因为紧凑哈希表是围绕无符号 32 位服务器标识符和 2 的幂表大小设计的。 

仅在图的 DSU 完成后才处理查询列表。 原始顺序被保留，因为候选者被附加到`ans`正如它们被阅读的那样。 不执行排序或重复数据删除。 

一个微妙的边界情况是 (N=0)。 在这种情况下，哈希表中没有图顶点。 每个查询的服务器都是隔离的，因此目标 (X) 的唯一有效源是相同标识符 (X) 的另一个出现。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 预期 (O(N\alpha(V)+QK\alpha(V))) | 每条边执行两次预期 (O(1)) 哈希查找和一次 DSU 合并； 每个查询最多检查 100 个来源 |

 这里 (V\le2N) 表示出现在图边上的顶点。 对于 (N=10^6)，实现最多保留 (2^{22}) 个哈希槽，并且键和父项都使用四字节无符号整数。 因此，两个主阵列占用约 32 MB，为预期内存模型下的输入处理和输出留出空间。 

查询工作最多是（1000\cdot100=10^5）个候选检查，与图预处理相比可以忽略不计。 昂贵的部分只处理一次，而不是每个查询一次。

parts.append("1")
parts.append(f"1 3")
parts.append(f"1 {n + 1} {1_000_000_000}")

maximum_case = "\n".join(parts) + "\n"

assert solve(maximum_case) == f"2 {n + 1} 1", "maximum-size chain"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 | 样品1 |`1 79699669`,`2 64508306 56554555`，然后是两个零 | 基本组件过滤和断开组件|
 | 样品2 | 四行，每行有两个有效来源 | 多组件和源订单保存 |
 | (N=0)，重复的隔离标识符 |`2 42 42`| 未知服务器、隔离标识符相等、重复候选者 |
 | 标识符`1`和`1000000000`|`2 1000000000 1`， 然后`0`| 标识符边界和缺席候选者处理 |
 | 自循环和重复值 | 三个特定于组件的答案 | 自循环、重复和仅包含一台服务器的组件 |

 最大尺寸测试是故意生成的，而不是将一百万条边缘线嵌入到测试源中。 它使用相同的输入大小来确定实际解决方案的内存和时间行为。 

## 边缘情况

 当没有边缘时，每个服务器都是隔离的。 对于输入```
0
1
42 3
42 17 42
```目的地`42`没有图形条目，因此查询逻辑采用独立服务器分支。 它保留了两次出现的情况`42`并拒绝`17`，生产```
2 42 42
```图中出现的服务器可以连接到另一个服务器，而第三个查询标识符仍然不存在。 为了```
1
1 2
1
1 3
2 3 1
```DSU 包含一个组件`{1,2}`。 服务器`3`不存在并且孤立，所以只有`1`属于目的地的组件。 结果是```
1 1
```这就是为什么不存在的标识符不能简单地分配一个特殊的共同代表。 每个缺失的标识符都是其自己的独立组件。 

如果候选人出现多次，则必须对每次出现进行独立评估。 为了```
0
1
7 4
7 7 8 7
```目的地是隔离服务器`7`，因此出现了 3 次`7`都是有效的。 输出是```
3 7 7 7
```实施构造`ans`通过迭代原始列表，因此不会丢失任何顺序或多重性信息。 

自循环不会创建与其他服务器的连接。 为了```
1
1000000000 1000000000
1
1000000000 2
1 1000000000
```DSU 创建一个单例组件，其中包含`1000000000`。 候选人`1`是一个不同的隔离服务器，而`1000000000`是目的地本身。 输出是```
1 1000000000
```重复的边的行为类似。 呼唤`union`在同一 DSU 集中已有的两个顶点上的连接不会改变任何内容，因此重复的连接不会破坏组件结构。 

最后，服务器标识符可能大到（10^9），而服务器的数量要少得多。 哈希表故意将标识符存储为 32 位无符号整数，而不是尝试分配由标识符索引的数组。 这种区别使得内存使用量取决于实际服务器的数量而不是最大标识符值。
