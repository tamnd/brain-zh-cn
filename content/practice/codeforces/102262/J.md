 ## 解决方案
 ## 问题理解

 我们得到一个类似 JSON 的字符串，该字符串是通过删除一个字符从有效消息中获得的。 有效消息的语法故意较小。 整个消息要么是一个字符串，要么是一个对象。 字符串是用双引号括起来的拉丁字母和数字的非空序列。 对象由大括号包围并包含零个或多个键值对。 每个键都是一个字符串，每个值都是字符串或另一个对象，并且这些部分之间的标点符号是固定的。 

我们的任务不是在语义上重建原始数据。 我们只需要在某处插入一个字符，这样生成的字符串就遵循这一语法。 如果删除的字符位于单字符字符串内，则无法推断其确切身份，因此插入任何允许的字母数字字符，例如`a`，就足够了。 

输入长度可以达到(10^5)。 由于一秒的限制，重复扫描整个字符串的算法成本太高。 线性或近线性解析器是自然目标。 语法足够小，我们只能保留当前解析器状态和表示嵌套对象的堆栈，因此不需要通用的 JSON 解析机制。 

在某些情况下，仅基于牙套的简单修复可能会处理不当。 例如，输入`{"key":"value}`缺少该值的结束引号，所以答案是`{"key":"value"}`。 仅计算左大括号和右大括号的策略会看到平衡的大括号并错过实际错误。 

另一种情况是`{"key""value"}`。 缺少的字符是键和值之间的冒号，给出`{"key":"value"}`。 仅搜索不匹配的分隔符的解析器将再次失败，因为所有引号和大括号都已经平衡。 

一个特别小的边缘情况是`{`。 原始 JSON 可能是`{}`，删除了右大括号，所以正确答案是`{}`。 相似地，`}`可以修复为`{}`通过插入缺少的左大括号。 第二种情况很重要，因为丢失的字符位于第一个输入字符之前，而不是之后。 

最后，考虑`""`。 在普通 JSON 语法下，这是一个有效的空字符串，但问题明确禁止空字符串。 它可以通过删除原始字符中的唯一字符来出现`"a"`。 我们可以将其恢复为`"a"`通过在两个引号之间插入任何字母数字字符。 

## 方法

 直接暴力方法很简单。 尝试每个可能的插入位置，尝试每个可能被删除的字符，构造结果字符串，并检查它是否是有效的消息。 字符集由四个结构字符组成`{`,`}`,`:`,`,`、双引号以及 62 个字母和数字，因此有 67 个候选值。 

有 (n+1) 个可能的插入位置。 检查一个候选者需要 (O(n)) 时间，因为必须从头到尾解析结果字符串。 因此，最坏的情况约为 (67(n+1)n) 个字符操作。 对于(n=10^5)，大约是(6.7\cdot10^{11})次操作，远远超出了时间限制。 暴力方法是正确的，因为它确实检查了每一种可能的单字符修复，但它几乎花费了所有时间来重新发现相邻候选者的相同解析器状态。 

有用的观察是有效语法是确定性的。 在有效消息中的每一点，我们都确切地知道接下来会出现哪种令牌。 键字符串后面是一个冒号。 值后面是逗号或当前对象的右大括号。 在字符串内部，只能是字母数字字符或结束引号。 在对象的开头，对象要么立即关闭，要么字符串键开始。 

由于输入与有效消息仅存在一次删除不同，因此我们的确定性解析器无法继续识别丢失字符的第一个点。 我们不需要尝试每个插入位置。 我们在当前位置插入语法所需的字符，并继续解析输入的其余部分，就好像该字符一直存在一样。 

唯一的特殊情况是空字符串。 如果字符串开始并且下一个输入字符已经是其结束引号，则输入在语法上结构正确，但违反了问题的非空字符串规则。 缺失的字符必须是字母数字字符，并且选择`a`给出一个有效的结果。 

嵌套对象意味着解析器需要一个堆栈。 显式堆栈优于递归函数调用，因为嵌套深度可以是 (O(n))，并且深度嵌套的输入不应依赖于 Python 的递归限制或 C 调用堆栈。

 | ---| ---| ---| ---|
 | 蛮力 | (O(67n^2)) | (O(n)) | (O(n)) | 太慢了 |
 | 最佳| (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 从包含语法符号的堆栈开始`VALUE`和`END`。`VALUE`意味着必须解析根消息，而`END`意味着此后不能保留任何输入字符。 
2. 处理栈顶符号。 为了`VALUE`，检查当前输入的字符。 双引号开始一个字符串，并且`{`启动一个对象。 如果当前字符是`}`，唯一可能的单字符修复是缺失`{`，这会创建一个空对象。 对于另一个字符，在问题保证下唯一可行的修复是缺少字符串的左引号。 
3. 将对象展开到序列中`{`，物体主体，`}`。 对象主体要么是空的，要么由一对后跟零个或多个逗号分隔的对组成。 堆栈允许相同的逻辑用于任意深度的嵌套。 
4. 对于一个物体本体，如果当前字符是`}`，将主体留空并让右大括号符号消耗它。 否则开始解析键值对。 
5. 将一对解析为字符串键，然后是`:`，后跟一个值。 如果没有冒号，则终端`:`与当前字符不匹配，因此我们在该位置记录插入并继续而不消耗输入字符。 
6. 在一个值之后，对象可以以`}`或继续`,`和另一对。 如果两个字符都不存在，则由相同的终端匹配规则确定丢失的字符。 
7. 单独解析一个字符串，因为它的内容与语法的其余部分不同。 使用开盘报价，使用所有连续的字母数字字符，然后需要收盘报价。 如果缺少结束引号，请在当前位置插入结束引号。 
8. 如果字符串为空，即开始引号后面紧跟着另一个引号，则插入`a`他们之间。 这将恢复所需的非空字符串属性，而不更改任何现有的输入字符。 
9. 当所需的终结符与当前输入字符不匹配时，将该终结符记录为当前索引处缺失的字符。 故意不消耗输入字符，因为在插入丢失的字符后，现有字符正是解析器应该处理的下一个字符。 
10. 之后`END`达到时，所有原始输入字符必须已被消耗。 然后使用记录的插入位置和字符来构造答案，该位置之前有一个切片，插入的字符及其之后有一个切片。 

### 为什么它有效

 在到达丢失的字符之前，输入是原始有效 JSON 的精确前缀，因此确定性解析器遵循原始语法并正确使用每个字符。 在解析器首先需要一个不存在的字符时，当前输入和原始消息之间的唯一区别正是删除的字符。 在该位置插入语法所需的字符将恢复原始解析器状态。 

插入后，每个剩余的输入字符都按照其在原始有效消息中出现的状态进行处理。 堆栈保留了对象的嵌套结构，而字符串解析器保留了字符串内容和 JSON 标点符号之间的区别。 空字符串情况是输入在结构上可解析但仍违反自定义语法的唯一情况，插入一个字母数字字符可以准确修复该违规行为。 

由于该语句保证在一次插入后存在一些有效消息，因此该确定性解析过程找到的第一个修复是删除的字符及其位置，直到无害的选择`a`当删除的字符本身无法确定时。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def repair(s):
    n = len(s)
    i = 0

    stack = ["END", "VALUE"]
    insert_pos = -1
    insert_char = ""

    def add_missing(ch):
        nonlocal insert_pos, insert_char
        if insert_pos == -1:
            insert_pos = i
            insert_char = ch

    def is_alnum(c):
        return (
            "a" <= c <= "z"
            or "A" <= c <= "Z"
            or "0" <= c <= "9"
        )

    while stack:
        symbol = stack.pop()

        if symbol == "END":
            continue

        if symbol == "VALUE":
            if i < n and s[i] == '"':
                stack.append("STRING")
            elif i < n and s[i] == "{":
                stack.append("OBJECT")
            elif i < n and s[i] == "}":
                add_missing("{")
                stack.append("OBJ_END")
                stack.append("OBJ_BODY")
            else:
                add_missing('"')
                stack.append("STRING")

        elif symbol == "OBJECT":
            if i < n and s[i] == "{":
                i += 1
            else:
                add_missing("{")

            stack.append("OBJ_END")
            stack.append("OBJ_BODY")

        elif symbol == "OBJ_END":
            if i < n and s[i] == "}":
                i += 1
            else:
                add_missing("}")

        elif symbol == "OBJ_BODY":
            if i < n and s[i] == "}":
                continue

            stack.append("MORE")
            stack.append("PAIR")

        elif symbol == "MORE":
            if i < n and s[i] == "}":
                continue

            stack.append("MORE")
            stack.append("PAIR")
            stack.append(",")

        elif symbol == "PAIR":
            stack.append("VALUE")
            stack.append(":")
            stack.append("STRING")

        elif symbol == "STRING":
            if i < n and s[i] == '"':
                i += 1
            else:
                add_missing('"')

            if i < n and s[i] == '"':
                add_missing("a")
                i += 1
                continue

            while i < n and is_alnum(s[i]):
                i += 1

            if i < n and s[i] == '"':
                i += 1
            else:
                add_missing('"')

        else:
            if i < n and s[i] == symbol:
                i += 1
            else:
                add_missing(symbol)

    return s[:insert_pos] + insert_char + s[insert_pos:]

def main():
    s = input().strip()
    print(repair(s))

if __name__ == "__main__":
    main()
```这`stack`包含仍需处理的语法符号。`VALUE`是根非终结符，而`OBJECT`,`OBJ_BODY`,`PAIR`,`MORE`， 和`STRING`描述无需递归即可扩展的语法片段。 

这`VALUE`分支确定从当前位置开始的值类型。 特别的`}`分支处理左大括号被删除的情况，包括嵌套的空对象，例如`{"a":}}`。`OBJECT`消耗一个左大括号并安排对象主体，然后是其右大括号。 的相反顺序`stack.append`调用是有意的，因为堆栈是后进先出的。 例如，附加`OBJ_END`进而`OBJ_BODY`使`OBJ_BODY`先执行。`PAIR`扩展到`STRING`,`:`， 和`VALUE`。 同样，符号以相反的顺序推送，以便解析器首先看到键，最后看到值。`MORE`表示完成一对后的重复。 如果`}`已经存在，重复结束。 否则，将处理丢失或现有的逗号，然后是另一对和另一对`MORE`。 

这`STRING`分支处理语法中唯一长度不由标点符号确定的部分。 它使用开始报价，扫描字母数字内容，然后使用或插入结束报价。 当两个引号相邻时，插入`a`使字符串非空。 

帮手`add_missing`仅记录第一次插入。 在问题保证下，恰好一次插入就足够了，因此后面的每个解析器操作都适用于修复的语法。 原始字符串本身在解析过程中永远不会被修改。 最终的构造只执行一次插入，因此以线性时间运行。 

没有递归，也没有取决于输入大小的整数运算，因此不存在递归深度或整数溢出问题。 显式堆栈可以在深度嵌套的 JSON 对象中包含 (O(n)) 个语法符号。 

## 工作示例

 对于第一个样本，输入是`{"key":"value}`。 解析器成功地使用了对象、键、冒号和值的左引号。 然后它消耗`value`并达到`}`当字符串解析器等待其结束引号时。 

| 输入索引 | 当前角色 | 解析器动作 | 插入|
 | ---| ---| ---| ---|
 | 0 |`{`| 起始对象 | 无 |
 | 1 |`"`| 开始键字符串 | 无 |
 | 6 |`:`| 消耗对分隔符 | 无 |
 | 7 |`"`| 起始值字符串 | 无 |
 | 8..12 |`value`| 使用字母数字内容 | 无 |

 | 14 | 14 结束 | 对象右大括号已存在 | 无 |

 不变量被保留，因为位置 13 之前的每个字符正是语法所期望的。 插入`"`前`}`给出`{"key":"value"}`，之后现有的`}`关闭该对象。 

对于第二个样本，输入是`{"key""value"}`。 键字符串在索引 5 处结束，下一个语法符号是冒号。 相反，当前字符是值的左引号。 

| 输入索引 | 当前角色 | 解析器动作 | 插入|

 关键点是解析器在插入丢失的终端时不会消耗当前字符。 插入后`:`，现有报价保持在当前位置，并成为该值的开盘报价。

 ## 边缘情况

 输入`{`表示可能损坏的最小 JSON 对象。 解析器开始于`VALUE`，看到`{`，并输入一个对象。 它的主体是空的，因为输入已经位于文件末尾，并且`OBJ_END`然后需要`}`。 由于没有剩余字符，解析器记录`}`在位置 1 并产生`{}`。 

输入`}`练习相反的边界。 从根本上来说，`VALUE`看到`}`。 这样的字符不能开始一个值，但是在保证恰好删除一个字符的情况下，自然重建是缺失的`{`就在它之前。 解析器记录`{`, 对待现有的`}`作为空对象的结束分隔符，并产生`{}`。 

输入`""`在结构上与普通语法错误不同。 字符串解析器使用第一个引号并立即看到另一个引号。 由于问题禁止空字符串，因此它插入`a`在第二个报价之前。 结果是`"a"`，这是一个有效的非空字符串，与输入仅相差一个字符。 

为了`{"key":"value}`，解析器到达`}`仍在值字符串内。 字符串语法仅允许字母数字内容后跟`"`，因此所需的字符明确是结束引号。 它紧接在之前插入`}`, 给予`{"key":"value"}`。 

为了`{"key""value"}`，解析器在第二个引号处完成键并期望`:`。 插入冒号时不会消耗当前引号。 然后它会被正确地重新用作该值的起始报价。 插入字符和使用输入字符之间的这种区别可以防止在每个丢失的标点位置处出现差一错误。 

对于深度嵌套的对象，每个`{`在显式堆栈上创建另一个对象上下文。 各对应`}`删除一个上下文。 解析器从不依赖于 Python 调用堆栈，因此与输入大小成比例的嵌套在与浅对象相同的线性传递中进行处理。
