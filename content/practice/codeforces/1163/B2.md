 ## 解决方案
 ## 问题理解

 我们得到了一系列随着时间的推移而出现的颜色，每天一个。 每天都会出现一种颜色。 我们的任务是找到最长的前缀，这样如果我们从该前缀中删除一个元素，剩余的多组颜色就会以一种非常特定的方式完美平衡：仍然出现的每种不同的颜色必须出现相同的次数。 

因此对于选定的长度前缀$x$，我们必须能够恰好删除某一天，并且在删除之后，所有剩余的频率在仍然存在的所有颜色中变得相等。 

输出是此类前缀的最大长度。 

约束条件$n \le 10^5$立即明确排除检查所有前缀和所有删除。 对每个前缀进行天真的检查将花费$O(n)$，对所有前缀执行此操作会导致$O(n^2)$，这太慢了。 

关键的困难在于我们不仅要检查频率的相等性，还要检查删除一个仔细选择的事件后的相等性。 这使得该结构对不同颜色的数量及其频率的分布都很敏感。 

一些边缘模式说明了天真的推理失败的地方。 

如果所有颜色已经具有相同的频率，则删除任何元素都会破坏相等性，除非删除的元素来自频率下降但仍保持所有其他颜色相同的颜色。 例如，在完全统一的前缀中，例如$[1,1,2,2,3,3]$，删除任何单个元素都会产生频率比其他元素低 1 的颜色，从而破坏均匀性，除非结构更仔细地对齐。 

另一个棘手的情况是当一种颜色的频率相差 1 时。例如，$[1,1,1,2,2,2,3]$，删除单个出现的 3 使所有频率相等。 如果许多贪婪检查只跟踪“最大频率”而不跟踪有多少颜色共享每个频率，那么它们就会失败。 

最后，存在多个频率级别但只有一次删除可以修复它们的前缀需要计算每个频率级别有多少种颜色，而不仅仅是频率本身。 

## 方法

 暴力解决方案将迭代所有前缀。 对于每个前缀，我们计算每种颜色的频率，然后尝试删除每个索引并检查所有剩余频率是否相等。 检查前缀需要重新计算或扫描频率分布，从而导致$O(n)$每个前缀。 这给出了$O(n^2)$，这对于$10^5$。 

关键的见解是避免从头开始重新检查前缀。 相反，我们增量地维护频率计数，并维护二级结构：当前有多少种颜色具有给定频率。 

在任何前缀处，“可以删除一个元素以使所有剩余频率变得相等”的条件只能发生在少数结构配置中。 让$f$是颜色的频率图，让$cnt[x]$到底有多少种颜色出现$x$次。 

如果我们修复一个前缀，我们想知道删除一个出现是否可以使所有剩余频率等于某个值$k$。 这意味着频率多重集必须已经几乎一致，并且可以通过单个减量来纠正偏差。 

这将问题简化为跟踪频率的频率并在每一步检查恒定数量的结构模式。 

观察结果是，删除一个元素后，只有一种颜色的频率减少了 1。因此，在前缀中，我们只需要测试是否存在一种方法，使减少一个频率后，所有非零频率都塌陷为单个值。 这导致检查条件涉及：

 要么所有频率都已经相等，除了频率 1 的一个额外元素之外，或者所有频率恰好相差一个级别，并且在较高级别上恰好有一种颜色，或者与所有其他颜色相比，一种颜色恰好出现过多的一种颜色。 

这个可以查$O(1)$每个前缀使用频率计数的哈希图。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 最优（频率 + 频率中的频率图）|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护两张地图：`freq[color]`每种颜色的出现频率，以及`count[f]`目前有多少种颜色有频率`f`。 

我们迭代数组，增量更新这些结构，并在每个位置测试以该位置结尾的前缀是否有效。 

1.初始化空频率图和频频图。 目标是维护前缀的动态摘要。 
2. 对于每种传入颜色，更新其旧频率`count`，减少旧频率的计数，然后增加新频率。 
3. 更新后，通过分析结构来检查当前前缀是否有效`count`。 
4. 有效性检查基于一小部分案例：

 第一种情况是所有颜色的频率为 1，这意味着每种颜色恰好出现一次。 

第二种情况是只有一个频率值。 

第三种情况是当恰好有两个频率值时，比如说$f$和$g$，并且它们相差 1，并且较高的频率出现一次，允许删除一次出现以使频率平坦。 
5. 如果任何前缀有效，则用其长度更新答案。 

### 为什么它有效

 正确性来自这样一个事实：删除一个元素只能影响一种颜色频率，并且这种变化是严格局部的：它正好将一个频率桶减少一个单位。 因此，之后达到均匀状态的唯一方法是当前频率分布是否已经距离频率多重集空间中的均匀性“一步之遥”。 这`count`map 完全捕获了该结构，并且不需要额外的排序信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def valid(count, total):
    # number of distinct frequency values
    keys = list(count.keys())
    if len(keys) == 1:
        f = keys[0]
        # all same frequency
        return True

    if len(keys) == 2:
        f1, f2 = keys
        c1, c2 = count[f1], count[f2]

        # ensure f1 < f2
        if f1 > f2:
            f1, f2 = f2, f1
            c1, c2 = c2, c1

        # case 1: freq 1 occurs once
        if f1 == 1 and c1 == 1:
            return True

        # case 2: higher freq is exactly one extra and occurs once
        if f2 == f1 + 1 and c2 == 1:
            return True

    return False

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = {}
    count = {}
    ans = 0

    for i, x in enumerate(arr):
        old = freq.get(x, 0)
        if old > 0:
            count[old] -= 1
            if count[old] == 0:
                del count[old]

        new = old + 1
        freq[x] = new
        count[new] = count.get(new, 0) + 1

        if valid(count, i + 1):
            ans = i + 1

    print(ans)

if __name__ == "__main__":
    solve()
```这`freq`字典跟踪每种颜色出现的次数。 这`count`字典跟踪有多少种颜色共享每个频率。 有效性函数对仅有的两种可以通过删除一次出现来修复的结构配置进行编码。 

一个微妙的实现细节是我们总是更新`count`改变频率之前和之后。 错过删除旧频率桶会导致幻影频率错误地通过有效性检查。

 ## 边缘情况

 最小输入，例如`[1]`是非常有效的，因为删除唯一的元素会留下一个空的统一状态。 该算法处理这个问题是因为`count`有一个条目`{1:1}`。 

一个完全不同的数组，例如`[1,2,3,4,5]`维持`count = {1:5}`每一步都满足单频条件。 

像这样倾斜的情况`[1,1,1,1,2]`产生频率图`{4,1}`和计数图`{4:1,1:1}`。 有效性检查检测“单个额外出现”模式​​，正确地允许前缀在删除单独的后有效`2`。
