 ## 解决方案
 ## 问题理解

 我们得到一排编号从 1 到 N 的房间。客人一个接一个地到达，并且必须为每位客人分配正好两个相邻的房间，并且在分配时这两个房间仍然是空的。 如果存在多个相邻的空对，则均匀随机选择其中之一。 这两个房间随后将被永久占用。 这一直持续到走廊中任何地方都没有相邻的空对为止，此时该过程停止。 

对于固定房间 K，我们需要知道进程终止时该房间最终被占用的概率。 

关键是这个过程不是确定性的。 在每一步中，选择占据哪个相邻的空对都会引入随机性，不同的选择会导致不同的最终配置。 我们不是模拟一种结果，而是对所有可能的有效随机历史进行平均。 

约束允许 N 最大为 10^7，这立即排除了任何逐步模拟该过程的方法。 如果 T 很大，在最坏的情况下，即使每个测试用例的 O(N) 也会太慢。 该解决方案必须利用强大的结构简化，以便在预处理后可以在大致对数或恒定时间内回答每个测试用例。 

当 K 不在边界附近时，会出现微妙的边缘情况。 例如，当 N = 4 且 K = 2 时，答案始终为 1，因为房间 2 始终是任何最大过程中某个选定对的一部分。 天真的直觉可能会假设每个房间都有一些独立的机会保持空闲，但实际上只有边界房间可以在最终配置中保持不配对。 内部房间在结构上被迫在每个最大结果中进行匹配，这是贪婪邻接匹配在路径上的行为方式的结果。 

当第一个选择将走廊分成互不相连的部分时，就会出现另一个棘手的情况。 例如，在小走廊中选择对 (2, 3) 会立即隔离房间 1。从那时起，房间 1 再也无法被触摸。 这种不可逆的分离是驱动解决方案的核心结构。 

## 方法

 直接模拟将维护所有有效相邻空对的集合，随机均匀地挑选一个，删除其端点，然后重复，直到没有对剩余。 这在概念上是正确的，并且它准确地反映了该过程。 然而，每个步骤都需要更新一组动态的可用边，总共有 O(N) 个步骤。 在具有大 N 的多个测试用例中，这变得不可行。 

关键的观察结果是，该过程从不依赖于连续空闲房间的连接部分之外的几何形状。 一旦选择了一对，走廊就会分成左右部分的独立子问题。 每个分段的演化在统计上与较小 N 上的原始问题相同。 

这种递归分解表明我们不需要模拟整个匹配过程。 相反，我们可以根据段大小来推理事件的概率，并推导出递归。 

一个关键的简化是，只有走廊的端点表现不同。 严格位于走廊内的任何房间最终总是在每个最大结果中匹配，因此其概率为 1。整个问题简化为计算端点房间匹配的概率。 

然后我们重点计算 f(n)，即房间 1 在长度为 n 的走廊中被占用的概率。 第一个选择的对均匀分布在 n−1 个相邻对中。 根据首先选择哪对房间，我们要么立即匹配房间 1，将其永久隔离，要么将问题减少到较小的独立走廊。 

这导致了前缀大小的清晰重现，可以在所有测试用例的最大 N 上以线性时间进行评估。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 每步 O(N)，总共 O(N^2) | O(N) | 太慢了 |
 | 前缀 DP 重复 | O(最大 N) | O(最大 N) | 已接受 |

 ## 算法演练

 我们重点计算 f(n)，即当有 n 个房间时，房间 1 被占用的概率。 

1. 将 f(n) 定义为最左边的房间被占用的概率。 
2. 考虑第一个选择的相邻对。 恰好有 n−1 个可能的对，所有对的可能性都是相等的。 
3. 如果第一个选择的对是 (1, 2)，则房间 1 立即被占用，因此概率为 1。 
4. 如果第一个选择的对是 (2, 3)，房间 1 将被隔离为一个空房间，并且永远不能成为任何未来对的一部分，因此贡献为 0。 
5. 如果第一个选择的对是 (k, k+1)（k ≥ 3），则走廊分为大小为 k−1 的左段和大小为 n−k−1 的右段。 右侧部分与房间 1 无关，左侧部分的行为与大小为 k−1 的新问题完全相同。 所以贡献是f(k−1)。 
6. 对所有可能性求和，给出了以前的 f 值的递推式。 
7. 为了有效地评估这一点，请维护前缀和 S(n) = f(1) + f(2) + … + f(n)。 这允许在预处理后在 O(1) 时间内计算每个 f(n)。 
8. 计算 f(1) = 0 作为基本情况，因为不存在对。 
9. 使用递归迭代计算 f(2)、f(3)、... 直至 max N，并一路存储前缀和。 

对于任何查询 (N, K)，如果 K 为 1 或 N，则返回 f(N)，否则返回 1。 

### 为什么它有效

 整个过程就是一条路径上的随机贪婪匹配。 顶点保持不匹配的唯一方法是，在其周围的结构被冻结之前，从未选择与其关联的每条边。 对于内部顶点，这是不可能的，因为路径的任何最大匹配都会强制覆盖所有内部结构； 不匹配的内部顶点将留下两个相邻的自由顶点，与极大性相矛盾。 这将问题简化为仅分析终点生存。 

递归捕获了过程的第一步分解。 每个结果都由第一个选择的边进行划分，每个分支要么立即终止于房间 1，要么缩减为严格较小的独立实例。 这确保了案例之间没有重叠并保留总概率质量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    queries = []
    max_n = 1

    for _ in range(T):
        n, k = map(int, input().split())
        queries.append((n, k))
        max_n = max(max_n, n)

    if max_n >= 1:
        f = [0] * (max_n + 1)
        pref = [0] * (max_n + 1)

        f[1] = 0
        pref[1] = 0

        for n in range(2, max_n + 1):
            # f(n) = (1 + sum_{i=2..n-2} f(i)) / (n-1)
            total = 1 + (pref[n - 2] - pref[1])
            if total < 0:
                total %= MOD
            inv = pow(n - 1, MOD - 2, MOD)
            f[n] = (total % MOD) * inv % MOD
            pref[n] = (pref[n - 1] + f[n]) % MOD

    out = []
    for n, k in queries:
        if k != 1 and k != n:
            out.append(f"Case #: 1")
        else:
            out.append(f"Case #: {f[n]}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现将问题分为预处理阶段和查询阶段。 预处理使用派生递归和前缀和数组在所有测试用例中将 f[n] 构建为最大 N，以避免重复重新计算总和。 

查询逻辑是即时的。 如果 K 不在走廊的任一端，则答案始终为 1。否则，我们返回预先计算的端点概率 f[N]。 

必须注意模块化划分。 由于我们以 10^9+7 为模，除以 (n−1) 是使用模逆来实现的。 

## 工作示例

 考虑 N = 4、K = 1 的情况。最初，可能的第一步是三个相邻对：(1,2)、(2,3) 和 (3,4)，每个概率为 1/3。 

| 第一对| 所得结构| 1号房间的命运|
 | --- | --- | --- |
 | (1,2) | 1号房间立即入住 | 已占领 |
 | (2,3) | 1 号房间永久隔离 | 免费|
 | (3,4) | 缩小为右侧较小的部分 | 最终通过递归占用|

 因此概率为 2/3，与已知结果相符。 

现在考虑 N = 5，K = 2。房间 2 是内部房间。 无论选择哪一个第一对，它要么直接匹配，要么成为最终必须匹配它的较小段的一部分。 没有任何选择序列会导致房间 2 最终被隔离，同时保持最大配置。 因此概率为 1。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(最大 N) | 每个 f[n] 使用前缀和计算一次 |
 | 空间| O(最大 N) | 最多存储 DP 和前缀数组 N |

 预处理与测试用例中的最大走廊大小呈线性关系，这对于优化的 Python 中的单次传递中的 N 高达 10^7 是可以接受的，并且很容易在编译语言的限制内。 每个查询都在 O(1) 内得到答复。

import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    T = int(input())
    queries = []
    max_n = 1

    for _ in range(T):
        n, k = map(int, input().split())
        queries.append((n, k))
        max_n = max(max_n, n)

    f = [0] * (max_n + 1)
    pref = [0] * (max_n + 1)

    for n in range(2, max_n + 1):
        total = 1 + pref[n - 2]
        inv = pow(n - 1, MOD - 2, MOD)
        f[n] = (total % MOD) * inv % MOD
        pref[n] = (pref[n - 1] + f[n]) % MOD

    out = []
    for i, (n, k) in enumerate(queries, 1):
        if k != 1 and k != n:
            out.append(f"Case #{i}: 1")
        else:
            out.append(f"Case #{i}: {f[n]}")

    return "\n".join(out)

 ## 边缘情况

 对于 N = 2，唯一可能的移动是 (1,2)，因此两个房间始终都被占用。 该算法正确返回 f(2) = 1。 

对于内部位置，例如 N = 5、K = 3，路径上的每个有效最大匹配都必须覆盖该顶点。 在 DP 逻辑中，这种情况甚至不会查询 f(n)； 它们立即被解析为概率 1。 

对于像 N = 4、K = 1 这样的端点情况，递归正确地解释了三个对称的第一个移动，并将概率分布在立即成功、立即失败和递归延续到更小的部分中。
