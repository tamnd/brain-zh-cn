[CF 1399A - 删除最小的](https://codeforces.com/problemset/problem/1399/A)

 **评分：** 800
 **标签：** 贪心，排序
 **求解时间：** 1m 29s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们被要求确定是否可以使用特定操作将正整数数组减少为单个元素：选择两个差值最多为 1 的不同元素，并删除两者中较小的一个（或者如果它们相等则删除其中一个）。 该数组可能包含重复项，并且每个测试用例都是独立的。 

输入由多个测试用例组成。 对于每个测试用例，数组长度最多为 50，每个元素介于 1 到 100 之间。这意味着任何解的二次方为`n`将在时间限制内顺利运行，因为 50 平方仅每个测试用例 2500 次操作。 通过多达 1000 个测试用例，在最坏的情况下我们可以达到 250 万次操作，这对于 1 秒的限制来说是可以接受的。 

非明显的边缘情况包括所有元素都相等的数组、具有单个元素的数组以及连续元素之间的最大间隙大于 1 的数组。例如，`[1, 2, 4]`无法简化为单个元素，因为 2 和 4 相差超过 1，并且任何允许的删除顺序都无法消除此间隙。 相似地，`[5, 5, 5, 5]`总是可以减少到一个元素，而`[100]`已经是一个简单的元素了。 

## 方法

 蛮力方法将模拟所有可能的移动：重复查找差值最多为 1 的一对元素，删除较小的元素，然后继续，直到剩下一个元素或无法移动。 这适用于小型`n`但变得混乱且低效，因为我们需要重复搜索有效对并动态删除元素。 最坏情况下的操作次数约为`O(n^3)`因为每次删除都需要扫描所有对，即使对于`n = 50`。 

关键的观察是，一旦数组排序，删除元素的能力完全取决于连续数字之间的间隙。 如果数组已排序并且每个相邻对最多相差 1，则最终可以删除除最大元素之外的每个元素。 如果任何相邻对相差 2 或更多，则间隙两侧的元素无法减少到一个，从而无法达到单元素数组。 

这一观察简化了对数组进行排序和检查连续差异的解决方案。 分拣成本`O(n log n)`一次线性扫描确认所有差异是否至多为 1，从而给出干净且最优的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 太慢/混乱|
 | 最佳| O(n log n) | O(n log n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 我们将独立处理每个测试用例。 
2. 对于每个测试用例，读取数组长度`n`和数组元素`a`。 
3. 按升序对数组进行排序。 排序确保我们可以直接检查连续元素之间的差异。 
4. 将标志变量初始化为“YES”，假设我们可以将数组缩减为单个元素。 
5. 从第一个元素到倒数第二个元素迭代数组。 对于每个索引`i`，计算之间的差异`a[i+1]`和`a[i]`。 如果该差值大于 1，则将标志设置为“NO”并跳出循环。 这可以识别任何阻碍完全减少的差距。 
6. 检查所有相邻对后，输出当前测试用例的标志。 “YES”表示可以将数组缩减为单个元素，否则表示“NO”。 

原理：一旦数组排序完毕，阻止完全归约的唯一约束就是大于 1 的间隙的存在。任何两个相差 1 或 0 的连续数字最终都可以通过重复的删除操作来归约，因为我们总是可以删除较小的，直到只剩下一个。 任何 2 个或更多的差异都会带来不可逾越的障碍。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    possible = True
    for i in range(n - 1):
        if a[i+1] - a[i] > 1:
            possible = False
            break
    print("YES" if possible else "NO")
```该解决方案首先读取测试用例的数量。 每个数组都经过排序，这允许单个线性扫描检测任何大于 1 的差异。变量`possible`跟踪数组是否可以缩减为一个元素，并且我们会在检测到大于 1 的间隙时提前中断。排序会自动处理重复元素，并保证我们只需要检查连续的元素对。 不需要额外的数据结构。 

## 工作示例

 跟踪输入`[1, 2, 2]`:

 | 步骤| 数组 | 检查 | 行动|
 |---|---|---|---|
 | 1 | [1,2,2]| 2 - 1 = 1 | 好的 |
 | 2 | [1,2,2]| 2 - 2 = 0 | 2 - 2 = 0 好的 |
 | 3 | - | 所有差异 <= 1 | 是 |

 跟踪输入`[1, 2, 4]`:

 | 步骤| 数组 | 检查 | 行动|
 |---|---|---|---|
 | 1 | [1,2,4]| 2 - 1 = 1 | 好的 |
 | 2 | [1,2,4]| 4 - 2 = 2 | 4 - 2 = 2 不允许，打破|
 | 3 | - | 检测到间隙 > 1 | 否 |

 这些痕迹表明，仅检查连续的差异就足够了。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 |---|---|---|
 | 时间 | O(n log n) | O(n log n) | 排序占主导地位，线性扫描为 O(n) |
 | 空间| O(1) 额外 | 可以就地排序 |

 和`n <= 50`和`t <= 1000`，该解决方案最多执行`1000 * 50 log 50 ≈ 85000`操作，完全在1秒之内。 内存使用量极低，轻松容纳在 256 MB 以内。

 ## 边缘情况

 对于单元素数组`[100]`，排序没有效果。 由于只有一个元素，因此不会运行连续差异上的循环。 该算法正确输出“YES”，因为不需要任何操作。 

对于所有元素都相等的数组，例如`[5, 5, 5, 5]`，差异为零，因此算法输出“YES”。 

对于有间隙的数组，`[1, 3]`， 区别`3 - 1 = 2`触发中断条件，立即产生“NO”。 这处理了防止减少到单个元素的关键约束。
