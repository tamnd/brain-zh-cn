 ## 解决方案
 ## 问题理解

 给定一个由小写字母组成的字符串，并且允许我们重复删除子字符串，只要删除的每个子字符串都是回文且长度为偶数。 删除子字符串后，字符串的其余部分会粘合在一起，我们继续下去，直到删除所有内容或陷入困境。 

问题是是否存在任何此类删除序列可以完全删除整个字符串。 

这些约束允许所有测试用例的总长度达到 3·10^5，因此任何解决方案都必须接近线性或每个测试用例至多 O(n log n)。 尝试所有子字符串或显式模拟删除的二次方法将立即失败，因为即使是长度为 10^5 的单个字符串对于 O(n^2) 操作来说也已经太大了。 

一些边缘情况值得注意。 像这样的字符串`uwu`即使它是回文也无法删除，因为它的长度是奇数，所以根本不适用有效的操作。 像这样的字符串`abab`即使所有字符数都是偶数，也无法删除，因为任何地方都没有偶数长度的回文子串。 最后，像这样的字符串`abba`是完全可删除的，因为整个字符串是偶数长度的回文。 

这些例子表明局部对称性还不够。 重要的是字符串是否可以分解为嵌套对称删除的结构。 

## 方法

 直接的尝试是模拟该过程。 在每一步中，我们都会扫描所有子字符串，检查它们是否是偶数长度的回文，如果可能的话删除一个，然后重复。 即使使用散列或两个指针，可能的删除次数也很大，并且每次删除都会重塑字符串，因此在最坏的情况下总复杂度会变成立方体。 这已经远远超出了极限。 

关键的转变是停止考虑删除的顺序，而是考虑如果字符串是完全可删除的，最终的结构必须是什么样子。 每次删除都会删除一个连续的偶数长度回文。 任何偶数长度的回文都可以看作是该段内对称位置的配对。 如果我们一次而不是顺序地跟踪所有删除，则字符串中的每个位置最终都会与同一字符的另一个位置完全匹配，并且这些对不能以冲突的方式交叉，因为删除操作在连续的块上。 

这导致了结构上的重新表述：我们试图决定是否可以将所有索引配对，以便每对连接相同的字符，并且这些对不会以无效的方式交叉。 一旦存在这样的配对，我们总是可以从内到外执行删除。 

强制进行这种配对的一种自然方法是以相反的顺序对每个字符的出现进行配对。 如果某个字符出现 k 次，则第一次出现必须与最后一次配对，第二次出现必须与倒数第二次配对，依此类推。 这会产生一组候选区间。 剩下的问题变得纯粹是结构性的：这些区间是否正确嵌套，或者其中一些区间是否以某种方式交叉而导致分解变得不可能？ 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力删除模拟| O(n^3) | O(n^3) | O(n) | 太慢了|
 | 区间配对+结构检查| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，计算每个字符的出现次数。 如果任何字符出现奇数次，则立即断定不可能删除整个字符串。 这是必要的，因为每次删除都会保留全局计数的奇偶性，而完全删除将要求所有计数都是偶数。 
2. 对于每个字符，单独列出它出现的所有索引。 将第一个匹配项与最后一个匹配项配对，将第二个匹配项与倒数第二个匹配项配对，依此类推。 每对定义了原始字符串的间隔。 

此步骤编码匹配相同字符而不在单个字符类内创建交叉的唯一可能方法。 
3. 将所有字符的所有间隔收集到一个列表中。 
4. 按左端点对间隔进行排序。 我们现在将检查它们是否形成正确的嵌套结构。 
5. 按起始位置升序扫描间隔，维护按其右端点排序的活动间隔堆栈。 当我们进入一个新的区间时，我们会推动它。 当我们到达一个区间的末尾时，它必须对应于最近打开的区间； 否则，发生穿越，施工无效。 
6. 如果我们处理完所有间隔而没有检测到违规，则可以完全删除该字符串。 

### 为什么它有效

 每次删除对应于删除一个连续的偶数长度回文，这会在该段内产生一组对称配对。 在整个过程中，每个位置都只匹配一次，并且匹配总是在相等的字符之间。

通过从外到内配对每个字符的出现，我们强制执行可能由重复对称删除产生的唯一结构。 如果任何两个结果间隔交叉，则意味着两个所需的对称结构必须以连续回文的嵌套删除无法产生的方式交织。 相反，如果所有区间都是嵌套的或不相交的，我们总是可以先删除最里面的区间，然后逐渐向外折叠，而不会破坏有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(s: str) -> bool:
    n = len(s)
    pos = {}
    
    for i, c in enumerate(s):
        pos.setdefault(c, []).append(i)
    
    intervals = []
    
    for c, arr in pos.items():
        if len(arr) % 2 == 1:
            return False
        for i in range(len(arr) // 2):
            l = arr[i]
            r = arr[-1 - i]
            intervals.append((l, r))
    
    intervals.sort()
    
    stack = []
    
    for l, r in intervals:
        while stack and stack[-1][1] < l:
            stack.pop()
        
        if stack and stack[-1][1] > r:
            return False
        
        stack.append((l, r))
    
    return True

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append("YES" if solve_one(s) else "NO")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该代码首先对每个字符的位置进行分组，然后通过匹配对称出现来构造强制配对间隔。 奇偶校验会尽早过滤掉不可能的情况。 

关键部分是区间验证。 按左端点排序后，堆栈维护活动间隔的嵌套结构。 如果我们看到一个区间在前一个区间内结束，但与它的嵌套位置不匹配，我们就会检测到交叉，这使得完全删除变得不可能。 

一个微妙的点是我们根本不模拟删除。 整个过程简化为验证是否存在一致的全局配对。

 ## 边缘情况

 单字符大小写如`a`直接演示了奇偶规则。 该算法立即检测到字符计数为奇数并返回 NO，而不尝试任何结构构造。 

为了`abab`，配对步骤产生区间 (0,2) 和 (1,3)。 这些间隔交叉，因为一个间隔在另一个间隔内开始，但在另一个间隔外结束。 在堆栈验证期间，会检测到这种交叉，因为第二个间隔未正确嵌套在第一个间隔内，从而导致拒绝。 

为了`aabbccdd`，间隔为 (0,1)、(2,3)、(4,5)、(6,7)。 堆栈永远不会看到不匹配，因为所有间隔都是不相交的，因此该结构是有效的并且算法接受它。
