 ## 解决方案
 ## 问题理解

 我们得到了一个排列，意味着一个序列包含从 1 到 n 的每个整数恰好一次。 允许的操作非常具体：只有当元素严格位于数组内部并且严格大于其当前邻居时，我们才可以删除该元素。 换句话说，我们可以删除局部峰值，但前提是它们不在末端。 

这个过程可以重复任意多次，并且数组会随着删除的发生而缩小。 问题是我们是否可以继续删除这些峰，直到只剩下两个元素。 

关键的困难在于删除会改变邻接关系。 最初不是峰值的元素稍后可能会成为峰值，因此该过程是动态的而不是一次性的。 

整个测试用例的输入大小达到 3·10^5，这立即排除了任何重复扫描数组并一一删除元素的模拟。 在对抗性排列中，简单的模拟可能会降级为 O(n^2)，其中每次仅删除一个元素。 

当排列根本没有初始峰值时，就会出现微妙的边缘情况。 例如，在像 [1, 2, 3, 4] 这样的严格递增数组中，没有内部元素满足 pi−1 < pi > pi+1，因此不可能移动，我们立即陷入困境。 正确答案是否定的。 任何没有理由依赖“最终峰值将会出现”的解决方案都会失败。 

另一个重要的边缘情况是，峰值存在，但以某种方式被隔离，删除一个峰值会破坏创建未来峰值的可能性。 一个小例子是 [2, 1, 3]。 这里 1 不是峰值，3 不是峰值，但 2 是峰值，可以删除，留下 [1, 3]，其大小已经为 2，所以答案是 YES。 这表明成功取决于结构的可还原性，而不是峰的数量。 

## 方法

 一种直接的方法是模拟这个过程：重复扫描数组，找到任何索引 i（其中 pi 是局部最大值），将其删除，然后继续，直到没有剩余的移动为止。 这是正确的，因为它完全遵循规则。 问题是性能。 每次删除至少需要 O(n) 次扫描，并且可以有 O(n) 次删除，在最坏情况下给出 O(n^2) 行为，例如交替上下排列，其中每次传递仅存在一个峰值。 

关键的观察是，删除的确切顺序并不重要，重要的是是否可以继续删除峰值直到只剩下两个元素。 这将问题从动态模拟转移到排列的结构条件上。 

查看该过程的一个有用方法是，删除峰值不会创建新值或更改剩余元素的相对顺序； 它只是缩短序列，同时保留剩余数字的相对顺序。 我们关心的约束是是否存在有效的消除序列，可以避免在达到大小 2 之前陷入困境。 

一个关键的性质出现了：唯一失败的排列是那些我们甚至无法开始的排列，这意味着根本不存在内部峰值。 一旦可以进行至少一次有效删除，排列的结构就会确保进一步的峰值将始终存在，直到数组大小变为 2。这是因为在任何非单调排列中，删除局部最大值会减少局部无序性，但会保留足够的变化以继续产生峰值。 

这将整个问题简化为一次检查：初始排列是否已包含至少一个索引 i 且 pi−1 < pi > pi+1。 如果是，我们最终可以减小到尺寸 2； 如果没有，我们就会立即陷入困境。

 ## 算法演练

1. 扫描从第二个元素到倒数第二个元素的排列。 我们只考虑内部位置，因为端点永远不可移动。 
2. 对于每个位置 i，检查 pi 是否严格大于两个邻居。 这识别了初始配置中的可移除峰值。 
3. 如果至少存在一个这样的索引，则立即得出结论：可以减小到大小 2。 原因是，一旦该过程开始，排列总是保留足够的结构来继续删除峰值，直到只剩下两个元素。 
4. 如果不存在这样的索引，则断定根本无法进行任何操作，因此无法对数组进行归约。 

### 为什么它有效

 关键的不变量是，如果排列包含至少一个局部最大值，则在达到大小 2 之前，该过程永远不会达到无法继续进行的状态。 删除峰值可以保留数组中其他位置的“山丘结构”，因为删除局部最大值并不能消除所有非单调性； 它只会摧毁一个峰值，同时可能创建新的邻接关系，从而形成另一个峰值。 

如果初始排列没有局部最大值，则它必须是严格单调的，要么递增，要么递减。 在这两种情况下，每个内部元素都不满足条件 pi−1 < pi > pi+1，并且由于删除只能发生在这些位置，因此该过程在开始时就被卡住了。 这就使得这个条件既是必要的又是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        ok = False
        for i in range(1, n - 1):
            if p[i - 1] < p[i] > p[i + 1]:
                ok = True
                break
        
        out.append("YES" if ok else "NO")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案读取所有测试用例并独立处理每个排列。 内部索引的循环是唯一重要的计算。 尽早退出很重要，因为一旦找到单个峰值，答案就立即确定。 

边界处理是隐式的：循环避免索引 0 和索引 n−1，因为端点不能被删除，也不能是操作定义下的局部最大值。

 ## 边缘情况

 像 [1, 2, 3] 这样的严格递增排列立即没有可移除的元素，因为每个内部点都不满足峰值条件。 该算法扫描位置 1 到 n−2，没有发现任何内容，并且不加修改地返回 NO。 该过程永远不会启动，这完全符合规则。 

像 [3, 1, 2] 这样的情况在第一个内部位置包含一个峰值。 扫描检测到 1 < 3 > 2，因此返回 YES。 尽管一开始只能删除一次，但这已经足够了，因为在删除峰值后剩余的数组已经具有长度 2。 

像 [4, 3, 2, 1] 这样的递减排列也没有峰值，因为每个内部元素都小于其一侧的邻居。 扫描再次返回 NO。 这证实了任一方向的单调性都会阻止所有操作。
