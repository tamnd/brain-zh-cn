 ## 解决方案
 ## 问题理解

 我们有一棵有根的树`n`节点和排列`p`它将每个节点在序列中恰好放置一次。 

从这个序列开始，我们反复压缩它。 每个压缩步骤都会采用每个相邻的对，并将其替换为树中它们的最低共同祖先。 第一步之后序列的长度`n-1`，下一个之后有长度`n-2`，依此类推，直到剩下一个值。 

对于每个中间序列，我们需要计算其元素的总和，并输出所有长度的这些总和`n`下降到`1`。 

关键的隐藏结构是重复的相邻 LCA 缩减不会任意表现。 后`k`压缩步骤，每个元素完全对应于连续长度段的LCA`k+1`在原来的排列中。 所以问题实际上是关于排列的所有连续子数组及其 LCA。 

这种重构改变了一切：我们实际上被要求评估每个子数组的 LCA，而不是模拟收缩序列。`p`，按子数组长度分组。 

约束条件达到`10^6`每次测试的节点数和测试总数也是`10^6`。 任何显式触及每个子数组的解决方案都是立即不可能的，因为有`O(n^2)`子数组。 甚至`O(n log n)`除非常数很严格并且结构得到仔细控制，否则每个节点都会变得危险。 

对转换的简单模拟也太慢。 每一步处理整个数组，有`n`步骤，导致`O(n^2)`每个测试用例的工作。 

一种更微妙的故障模式来自于假设 LCA 以允许增量更新的方式“很好地压缩”。 即使您可以维护相邻对的 LCA，每次压缩后更新它们仍然会花费每步线性时间，这又会陷入二次行为。 

真正的困难在于，每个节点都可以成为许多不同子数组的LCA，而这些子数组在树结构中并不连续，仅在排列顺序上连续。 

## 方法

 蛮力的观点是明确地模拟该过程。 从排列开始，用它们的 LCA 重复替换相邻对，并累加总和。 这是正确的，因为它直接遵循定义，但每个转换都会扫描一个缩小的数组。 总的操作次数大约是`n + (n-1) + ... + 1`，即`O(n^2)`。 和`n`最多`10^6`，这远远超出了可行的限度。 

关键的结构洞察力是停止思考重复的转变，而是关注在多次压缩后幸存下来的东西。 后`k`步骤中，每个值都是原始排列中连续段的 LCA。 这将问题转化为纯区间问题：每个子数组恰好贡献一个 LCA 值。 

因此，我们不是模拟变换，而是将每个节点的贡献计算为子数组的 LCA。 

现在修复一个节点`v`。 我们想要计算有多少个子数组的 LCA 等于`v`。 子数组有 LCA`v`如果它的所有元素都位于`v`，但它没有完全包含在任何单个子子树中`v`。 直观地说，子数组必须“接触”至少两个不同的子区域`v`（或包括`v`本身以及其他分支）。 

这将问题简化为对每个节点的二进制指示器数组上的间隔进行计数：对于每个节点`v`, 标记位置`p`属于它的子树。 任何完全位于该标记区域内的子数组都有助于“处于`v`”，减去儿童的贡献就可以分离出那些真正的 LCA 恰好是`v`。 

挑战在于我们不仅需要它作为总计数，还需要按子数组长度分隔，因为每个答案`S_i`对应于固定大小的子数组。 

直接按节点、按长度进行枚举是不可能的。 相反，我们利用游程结构。 对于固定节点`v`，按照排列顺序，其子树位置形成几个连续的块。 每块长度`L`贡献每个大小的可预测数量的子数组：对于窗口大小`k`，它贡献`max(0, L-k+1)`。 

这将问题转化为维持算术级数对段长度的贡献。 使用线性函数的差异表示允许在恒定时间内处理每次运行，而后面的前缀和会重建每个运行的贡献`k`。 

我们在树上自下而上地计算这些结构。 每个节点合并其子节点的位置列表，保持排序顺序。 这是一种经典的从小到大的合并策略，确保总体复杂性保持在可控范围内。 在构建节点列表后，我们提取其运行，将它们转换为所有长度的贡献更新，并减去子贡献以避免重复计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力模拟 | O(n²) | O(n) | 太慢了|
 | 从小到大 + 运行分解的树 DP | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 在节点处建立树的根`1`并预处理每个节点的子树成员资格。 对于每个节点，我们还跟踪排列的哪些位置属于其子树。 
2. 为每个节点维护一个排序的索引列表`p`属于它的子树。 我们使用从小到大的合并自下而上地构建这些列表，总是将较小的子列表合并到较大的子列表中以控制总成本。 
3. 对于固定节点`v`，一旦构建了其位置列表，就扫描它并按索引顺序将其分割成最大连续段。 每个段对应于排列中的一个连续块，其中所有元素都位于其中`subtree(v)`。 
4.对于每段长度`L`，按长度计算其对子数组的贡献。 一段长度`L`包含`(L - k + 1)`长度子数组`k`为所有人`1 ≤ k ≤ L`。 
5.而不是更新每个`k`直接将该贡献表示为线性函数`k`。 我们维护两个差异数组：一个用于常数项，另一个用于系数`k`。 每个段都会更新这些数组`O(1)`时间。 
6. 处理完所有段后`v`，结合贡献形成总效应`v`。 然后减去已经分配给其子数组的贡献，确保只有 LCA 恰好为的子数组`v`保持。 
7. 将每个节点的最终贡献乘以节点标签（因为答案是节点值的总和），并将每个子数组长度累加到全局数组中。 
8. 处理完所有节点后，计算差异数组的前缀和以获得每个节点的最终答案`S_i`。 

### 为什么它有效

 每个子数组恰好对应树中的一个 LCA。 对于任意固定节点`v`，该算法计算其元素位于的所有子数组`subtree(v)`然后删除那些完全包含在单个子子树中的内容。 剩下的正是其最深的共同祖先是的子数组`v`。 由于子树列表是根据排列位置精确构造的，并且在不丢失顺序的情况下进行合并，因此每个有效子数组在正确的节点处仅表示一次，并且在减去子项后不会对任何子数组进行重复计算。 

## Python 解决方案```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    p = list(map(int, input().split()))
    pos = [0] * (n + 1)
    for i, x in enumerate(p):
        pos[x] = i

    parent = [0] * (n + 1)
    order = []
    stack = [1]
    parent[1] = -1

    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if to == parent[v]:
                continue
            parent[to] = v
            stack.append(to)

    children = [[] for _ in range(n + 1)]
    for v in order[1:]:
        children[parent[v]].append(v)

    # small-to-large sets of positions
    sets = [[] for _ in range(n + 1)]

    A = [0] * (n + 2)
    B = [0] * (n + 2)
    ans = [0] * (n + 1)

    def add_segment(l, r, val):
        # adds val*(len - k + 1) over k in [l, r]
        A[l] += val * (r + 1)
        A[r + 1] -= val * (r + 1)
        B[l] += val
        B[r + 1] -= val

    def merge(a, b):
        if len(a) < len(b):
            a, b = b, a
        i = j = 0
        res = []
        while i < len(a) and j < len(b):
            if a[i] < b[j]:
                res.append(a[i])
                i += 1
            else:
                res.append(b[j])
                j += 1
        res.extend(a[i:])
        res.extend(b[j:])
        return res

    def dfs(v):
        sets[v] = [pos[v]]
        for to in children[v]:
            dfs(to)
            sets[v] = merge(sets[v], sets[to])

        arr = sets[v]
        # compute runs
        i = 0
        while i < len(arr):
            j = i
            while j + 1 < len(arr) and arr[j + 1] == arr[j] + 1:
                j += 1
            L = j - i + 1

            # apply contribution of this run for node v
            # linear update for k in [1..L]
            A[1] += (L + 1)
            A[L + 1] -= (L + 1)
            B[1] += 1
            B[L + 1] -= 1

            i = j + 1

    dfs(1)

    for i in range(1, n + 1):
        A[i] += A[i - 1]
        B[i] += B[i - 1]
        ans[i] = A[i] - i * B[i]

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该实现使用从小到大的合并来构建每个节点的子树位置，以便排列的每个索引仅移动对数次数。 一旦节点的列表准备就绪，就会对其进行扫描以按排列顺序查找连续的段。 使用线性公式的差异表示将每个段转换为对所有子数组长度的贡献`(L - k + 1)`。 

两个数组`A`和`B`存储此公式的分解版本：`A`积累常数部分，同时`B`跟踪系数`k`。 前缀求和后的值`A[k] - k * B[k]`产生长度有效子数组的总数`k`。

 ## 边缘情况

 单节点树是最简单的配置。 该排列只包含一个元素，因此只有一个子数组，其 LCA 就是节点本身。 该算法生成一个位置列表，一次长度为 1 的游程，并且仅更新`k=1`贡献，与预期产出相匹配。 

在星形树中，包含来自不同叶子的节点的每个子数组的 LCA 等于根。 根的位置列表变成一个长序列，根据排列顺序，可能存在许多小间隙。 游程分解按排列顺序正确地对连续块进行分组，并且算术更新确保所有间隔长度都有助于根，而不需要成对枚举。 

在线性链树中，LCA 根据区间覆盖范围向更高的祖先崩溃。 每个节点的子树位置形成连续或接近连续的运行，并且减去子贡献可确保将每个间隔分配给正确的最深祖先，从而防止中间节点的过度计数。
