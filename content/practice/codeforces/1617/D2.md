 ## 解决方案
 ## 问题理解

 我们被赋予了一组`n`球员，每个人都标记为`1`到`n`， 在哪里`n`总是 3 的倍数。其中一些玩家是冒名顶替者，其余的是船员。 我们不知道冒名顶替者的数量`k`提前，但我们保证严格在`n/3`和`2n/3`。 我们的任务是通过提出有限类型的查询来准确识别哪些玩家是冒名顶替者。 

每个查询都允许我们选择三个不同的玩家，并询问其中是否有更多的冒名顶替者或更多的船员。 响应是`0`如果冒名顶替者占大多数并且`1`如果船员占多数。 我们最多可以做`n + 6`此类查询，之后，我们必须报告所有冒名顶替者索引及其总数。 

由于陪审团具有适应性，因此只要响应保持与规则一致，冒名顶替者集合就可以根据我们的查询而改变。 这可以防止简单的策略，例如简单地按顺序查询所有三元组； 该算法必须以受控的、逐步的方式工作，不依赖于固定的冒名顶替者位置。 

约束条件意味着`n`每个测试用例最多可以达到大约 10,000 个，所有测试用例的总和以 20,000 个为界。 每个查询都很便宜，但是枚举所有三元组是不可行的，因为有`O(n^3)`可能的三元组。 因此我们需要一个大致需要的策略`O(n)`查询，与限制兼容`n + 6`。 

不明显的边缘情况包括连续三元组横跨冒名顶替者和队友的情况，可能隐藏第一个有保证的队友或冒名顶替者。 如果粗心的算法假设第一个多数三元组始终包含冒名顶替者或船员，或者当所有三个都是冒名顶替者或所有三个都是船员时它错误地标记了三元组，则它可能会失败。 

## 方法

 暴力方法会查询每个可能的三元组，并尝试根据大多数结果推断冒名顶替者。 原则上这是正确的，因为每个响应都提供了有关一小部分冒名顶替者比例的信息，但这是完全不切实际的，因为`O(n^3)`三元组很快就超出了查询限制和计算资源。 

关键的观察是，自从`n`是3的倍数，我们可以将玩家分为`n/3`不相交的三元组并查询每个三元组一次。 在这些三元组中，至少有一个三元组必须是船员多数，并且至少一个必须是冒名顶替者多数，因为`k`。 识别出一名纯粹或大多数人熟知的队友和一名大多数人熟知的冒名顶替者，使我们只需进行一些额外的查询即可对其余玩家进行分类。 

一旦我们有了一个有保证的队友和一个有保证的冒名顶替者，我们就可以结合这两个“锚”系统地查询剩余的玩家。 通过用未知玩家替换三重成员之一并观察响应是否翻转，我们可以确定未知玩家的角色。 这将问题减少到`O(n)`查询，完全在限制之内。

 | 蛮力 | O(n^3) | O(n^3) | O(n^3) | O(n^3) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 分区`n`玩家进入`n/3`不相交的三元组：`(1,2,3)`,`(4,5,6)`等。查询每个三元组以找到它们的多数类型。 跟踪返回的第一个三元组`0`（冒名顶替者多数）和返回的第一个三元组`1`（船员占多数）。 让我们称这些为`T_imp`和`T_crem`。 
2. 来自`T_imp`和`T_crem`，确定至少一名有保证的冒名顶替者和一名有保证的船员。 这是通过从一个三元组和另一个三元组中查询两个玩家的混合三元组来完成的。 这些回答使我们能够推断出哪些玩家一定是冒名顶替者或船员。 
3. 保证有一名冒名顶替者`I`和一名有保证的船员`C`，迭代所有其他玩家。 对于每一个未知的玩家`X`,查询三元组`(I, C, X)`。 如果响应是`0`， 然后`X`是一个骗子。 如果响应是`1`， 然后`X`是一名船员。 记录每个玩家的类型。 
4.对所有玩家进行分类后，收集所有冒名顶替者的指数。 数一下就可以得到`k`。 以所需格式打印结果。 

为什么它有效：不变的是我们在任何时候都至少有一名已知的船员和一名已知的冒名顶替者。 使用这些作为锚点，对未知玩家的每个查询都会产生明确的分类。 多数船员和多数冒名顶替者三人组的初始识别由以下界限保证`k`（`n/3 < k < 2n/3`)，这确保两种类型都不能缺席。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
print_flush = lambda s: (print(s), sys.stdout.flush())

def solve_case(n):
    triples = []
    answers = []
    
    for i in range(0, n, 3):
        a, b, c = i+1, i+2, i+3
        print_flush(f"? {a} {b} {c}")
        r = int(input())
        triples.append((a, b, c))
        answers.append(r)
    
    # find first crewmate-majority and impostor-majority triples
    idx_crem = answers.index(1)
    idx_imp = answers.index(0)
    T_crem = triples[idx_crem]
    T_imp = triples[idx_imp]
    
    # determine one guaranteed crewmate and one guaranteed impostor
    known = [None] * (n+1)
    a,b,c = T_crem
    x,y,z = T_imp
    
    # We query mixed triples to identify at least one known crewmate and impostor
    query_order = [(a,x,y), (b,x,y), (c,x,y)]
    response = []
    for q in query_order:
        print_flush(f"? {q[0]} {q[1]} {q[2]}")
        response.append(int(input()))
    
    if response[0] == 1:
        known[a] = 1
        known[x] = 0
    elif response[1] == 1:
        known[b] = 1
        known[x] = 0
    else:
        known[c] = 1
        known[x] = 0
    
    # pick one known crewmate C and one known impostor I
    C = next(i for i,v in enumerate(known) if v==1)
    I = next(i for i,v in enumerate(known) if v==0)
    
    # classify all players
    for i in range(1, n+1):
        if known[i] is not None:
            continue
        print_flush(f"? {C} {I} {i}")
        r = int(input())
        known[i] = r
    
    impostors = [i for i in range(1, n+1) if known[i]==0]
    k = len(impostors)
    print_flush(f"! {k} {' '.join(map(str, impostors))}")

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```每一段代码都直接遵循算法。 我们首先识别这两种类型的候选三元组，然后通过混合查询推断出某个特定的船员和冒名顶替者。 最后，我们使用已知锚点的查询对每个剩余的玩家进行分类。 在索引玩家时必须小心避免差一错误，并且所有打印语句都会被刷新以遵守交互协议。
