 ## 解决方案
 ## 问题理解

 我们得到一个仅包含以下内容的二进制字符串`a`和`b`。 从这个字符串中，我们可以恰好删除一个连续的字符块，可能是空的。 删除之后，我们查看剩余的字符并数一下有多少个`a`和`b`剩下了。 

目标是通过选择单个删除的段来使这两个计数相等，同时最小化该删除的段的长度。 如果除了删除整个字符串之外，任何单个删除间隔的选择都无法实现相等，则答案是`-1`。 

关键的限制是删除必须是连续的一段，而不是分散的删除。 这从根本上解决了选择一个窗口的问题，该窗口的移除调整了之间的全局平衡`a`和`b`。 

输入量很大，所有测试用例的总长度高达 200,000。 这立即排除了对子串的任何二次方法。 任何明确尝试所有可能的删除间隔的解决方案都会在最坏的情况下检查 O(n²) 候选者，这太慢了。 

当弦即使在保留结构的移除之后也无法保持平衡时，就会出现微妙的边缘情况。 例如，如果所有字符都是`a`，无论你删除哪个内部段，剩下的字符串仍然只有`a`，所以除非我们删除所有内容，否则平等是不可能的。 同样，如果总计数已经相等，则最好不删除任何内容。 

## 方法

 直接的方法是尝试每一个可能的部分`[l, r]`，将其删除，并检查剩余的字符串是否具有相同的数量`a`和`b`。 每次删除后剩余字符的计数可以使用前缀和进行优化，因此每次检查的时间复杂度为 O(1)。 然而，这样的段有 O(n²) 个，因此总复杂度变为 O(n²)，这对于 2e5 的总长度来说太大了。 

关键的观察结果是，删除一个段会以一种非常结构化的方式改变计数之间的全局差异。 设总不平衡度为：```
D = (#a - #b)
```我们希望删除一段后最终的不平衡为零。 假设我们删除一个段`[l, r]`。 让：```
delta[l, r] = (#a - #b in s[l..r])
```那么剩余的不平衡就变成：```
D - delta[l, r]
```我们想要：```
D - delta[l, r] = 0  →  delta[l, r] = D
```所以问题简化为找到一个子数组，其`(a - b)`值等于总和`(a - b)`整个字符串，同时最小化其长度。 

现在这是一个经典的前缀和变换。 我们分配`+1`到`a`和`-1`到`b`，计算前缀和，并需要两个索引`i < j`这样：```
prefix[j] - prefix[i] = D
```等效地：```
prefix[i] = prefix[j] - D
```我们扫描一次并使用从前缀值到最早出现的哈希映射，从而最小化段长度。 

唯一剩下的复杂性是可行性：如果总计数已经相等，答案是`0`。 如果不存在有效段，唯一可能的方法是删除所有内容，因此我们返回`-1`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 前缀+哈希图 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将字符串转换为数值数组，其中`a = +1`和`b = -1`。 这将问题转化为平衡而不是原始计数。 
2. 计算总和`D`。 如果`D == 0`，字符串已经平衡，因此不需要删除，我们返回`0`。 
3. 从左到右扫描时构建前缀和。 每个前缀值代表该索引的不平衡性。 
4. 存储每个前缀值出现的最早索引。 这很重要，因为使用最早出现的片段可以最大化剩余片段的长度并最小化删除的片段。 
5. 对于每个位置`j`，计算目标前缀值`prefix[j] - D`。 如果我们之前在索引处见过这个值`i`，那么子数组`(i+1..j)`完全不平衡`D`，这意味着删除它可以使其余部分保持平衡。 
6. 跟踪所有此类有效段中的最小长度。 
7. 如果没有找到段，则返回`-1`。 

中心思想是，每个有效的删除完全对应于选择一个不平衡性等于原始不平衡性的子数组。 一旦使用了前缀和，问题就变成了带有查找的线性扫描。 

### 为什么它有效

 该算法依赖于这样一个事实：删除一个片段只会通过该片段自身的贡献影响总不平衡。 前缀变换将每个段变成两点的差异，因此条件变成固定的目标差异。 由于每个可能的段都作为前缀对仅表示一次，因此扫描所有前缀可确保考虑每个有效的删除。 存储最早出现的事件可确保在所有有效对中我们始终获得最短的删除片段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        arr = [1 if c == 'a' else -1 for c in s]
        total = sum(arr)

        if total == 0:
            out.append("0")
            continue

        prefix = 0
        first_pos = {0: -1}
        ans = n + 1

        for i, v in enumerate(arr):
            prefix += v

            need = prefix - total
            if need in first_pos:
                ans = min(ans, i - first_pos[need])

            if prefix not in first_pos:
                first_pos[prefix] = i

        if ans == n + 1:
            out.append("-1")
        else:
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现首先将字符串编码为有符号数组，以便平衡变得可加。 前缀总和跟踪我们在每个索引处距离相等有多远。 字典`first_pos`确保我们始终使用最早出现的前缀值，这对于最小化删除的段长度是必要的。 

关键的微妙之处在于更新的顺序：我们在将当前前缀插入映射之前检查有效的段。 这可以防止在计算长度边界时意外地错误地使用以当前索引结尾的段。

 ## 边缘情况

 仅由一种字符类型组成的字符串，例如`aaaa`，产生恒定的负或正前缀趋势，没有满足所需差异的重复结构。 该算法扫描所有前缀，发现没有有效匹配，并正确返回`-1`。 

当弦已经平衡时，例如`ab`或者`baba`，总和为零。 提前退出可确保我们不会错误地搜索不必要的移除，并且我们会立即返回`0`。 

对于最佳删除位于边界的情况，例如删除前缀或后缀，前缀映射仍然捕获它们，因为我们初始化`prefix = 0`在索引处`-1`。 这保证了从索引开始的段`0`是有效的候选者并与内部段统一处理。
