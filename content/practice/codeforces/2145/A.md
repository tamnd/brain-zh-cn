 ## 解决方案
 ## 问题理解

 莫诺卡普想将一定数量的糖果平均分配给他的三个侄子。 他从`n`糖果，并且需要算出他还必须购买多少（如果有的话）才能使总数能被三整除。 输入由多个测试用例组成，每个测试用例给出一个整数`n`。 每个测试用例的输出是最小的非负整数`k`这样`n + k`能被三整除。 

限制很小：`n`最多可以达到 100 个，并且最多有 100 个测试用例。 这意味着我们可以为每个测试用例提供非常简单的算术运算，而不必担心性能。 不需要复杂的数据结构或算法。 

当出现不明显的边缘情况时`n`已经可以被三整除，在这种情况下 Monocarp 不需要购买任何额外的糖果。 例如，如果`n = 24`，正确答案是`0`。 如果`n = 7`, 单果树需要`2`额外的糖果因为`7 + 2 = 9`，可被三整除。 盲目添加固定数量或忘记处理情况的粗心解决方案`n % 3 == 0`会产生错误的答案。 

## 方法

 蛮力方法在概念上很简单。 对于每个`n`，我们可以从零额外的糖果开始并逐步测试`n + k`直到能被三整除。 这是可行的，因为最终我们将达到一个可以被三整除的数字，但即使有很小的限制，这也是不必要的。 每个测试用例最多需要两次额外检查，这对于这个问题来说是微不足道的，但算术洞察力允许我们直接解决它。 

关键的观察是使`n`被三整除，我们只需要考虑余数`r = n % 3`。 如果`r`为零，则不需要糖果。 如果`r`是一，我们需要`2`更多糖果，如果`r`是两个，我们需要`1`更多糖果。 这来自简单的模运算：我们本质上是在解决`(n + k) % 3 == 0`对于最小的非负数`k`。 

因此，最佳方法是计算余数`n`模三并用三减去它，除非余数为零。 这完全避免了不必要的循环。

 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例 O(1) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`，Monocarp 目前拥有的糖果数量。 
3. 计算余数`r = n % 3`。 
4. 如果`r`为零，打印`0`。 否则，打印`3 - r`。 这给出了要添加的糖果总数可以被三整除的最小糖果数量。 
5. 对所有测试用例重复此操作。 

为什么它有效：不变的是我们总是希望糖果总数能被三整除。 模运算直接测量我们与最接近的三的倍数的距离。 添加`3 - r`修正余数而不会超调。 这保证了额外糖果的最少数量可以被三整除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    r = n % 3
    print(0 if r == 0 else 3 - r)
```代码首先读取测试用例的数量。 对于每个测试用例，它计算余数`n`除以三。 如果余数为零，则输出零； 否则，它输出`3 - r`。 不存在相差一的问题，因为`n % 3`总是产生 0、1 或 2。使用`3 - r`确保我们始终添加所需的最少数量的糖果。 

## 工作示例

 对于输入`7`：

 | n | n % 3 | r | 3 - r | 输出|
 | --- | --- | --- | --- | --- |
 | 7 | 1 | 1 | 2 | 2 |

 添加 2 颗糖果即可获得`9`糖果，可以被三整除，所以每个侄子都会得到`3`。 

对于输入`24`：

 | n | n % 3 | r | 3 - r | 输出|
 | --- | --- | --- | --- | --- |
 | 24 | 0 | 0 | - | 0 |

 不需要糖果，因为`24`已经可以被三整除。

 ## 边缘情况

 对于`n = 0`,`0 % 3`为零，因此算法正确输出`0`。 为了`n = 1`或者`n = 2`，算法计算`3 - r`作为`2`和`1`分别匹配所需的最少额外糖果。 除了简单的模计算之外不需要特殊处理。 为了`n`由于已经可以被三整除，算法输出为零，确保我们永远不会超调。 这些边缘情况中的每一个都证实了基于模的解决方案是稳健的。
