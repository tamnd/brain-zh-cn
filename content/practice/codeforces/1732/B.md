 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，我们希望将其转换为非递减序列，这意味着一旦字符串开始包含`1`，它永远不应该回到`0`。 最终的形式必须看起来像一些`0`s 后面跟着一些`1`s。 

唯一允许的操作是后缀翻转。 我们选择一个索引`i`，并反转每个字符的位置`i`到最后。 此操作在后缀上是全局的，因此一次移动可以修复许多位置，但也可能破坏先前正确的结构。 

任务是找到到达任何形式的字符串所需的此类后缀翻转的最小数量`000...111...`。 

约束足够大，任何直接在字符串上模拟每个操作的翻转的方法都会太慢。 由于总长度高达 2·10^5 和高达 10^4 的测试用例，O(n^2) 模拟在最坏的情况下已经过于昂贵，因此解决方案必须将问题减少到每个测试用例的线性扫描。 

一个幼稚的错误来自于贪婪地思考修复第一个反转。 例如，在`1010`, 第一次翻转`1 -> 0`过渡似乎是合理的，但根据后来的结构，该选择可能不是最优的。 另一个常见的失败是模拟翻转，这会导致 O(n^2) 行为和 TLE。 

更微妙的边缘情况是交替字符串，例如`0101010`，其中每个位置相对于目标结构都是“错误的”，但最佳翻转重叠严重，因此答案不仅仅是不匹配的数量。 

## 方法

 暴力方法试图模拟所有可能的操作序列。 从给定的字符串，我们可以尝试翻转每个后缀，生成最多`n`每一步的新状态。 这自然会导致状态上的 BFS 或操作序列上的递归搜索。 虽然原则上是正确的，但不同状态的数量是指数级的，因为每次翻转都会以高度非局部的方式改变长后缀。 即使缓存状态也没有多大帮助，因为状态空间是`2^n`可能的字符串，它太大了。 

关键的观察结果是最终的字符串非常结构化：它必须是单调前缀`0`s 后面跟着`1`s。 我们不再考虑向前构造最终的字符串，而是跟踪必须从左到右“修复”的转换次数。 

关键的见解是扫描字符串并计算我们被迫改变相对于目标结构的方向的次数。 每当当前角色与我们对单调目标的期望不一致时，我们就会有效地创建一个可能需要翻转的边界。 然而，后缀翻转有一个特定的效果：位置翻转`i`将所有内容向右切换，这意味着未来的字符根据迄今为止应用的翻转奇偶性来改变其含义。 

这将问题简化为跟踪扫描时字符串的“状态”需要切换多少次。 预期方向的每次变化都会对答案产生影响，但相邻的变化可能会根据奇偶校验而取消。 这导致了线性贪婪扫描，我们只关心相等字符之间的转换，并计算字符串迫使我们重新解释后缀奇偶校验的次数。 

另一种看待它的方式是，每次我们遇到一个边界，其中所需的单调结构需要相对于我们当前看到的进行翻转，我们就会增加答案并从概念上切换我们对所有未来字符的解释。

 ## 算法演练

 我们维护一个逻辑“当前奇偶校验”，表示到目前为止后缀是否已被翻转偶数次或奇数次。 我们并不实际修改字符串，而是根据此奇偶校验解释每个字符。 

我们还保留了一个正在运行的答案。 

1. 初始化变量`flip_parity = 0`，意味着尚未应用翻转，并且`ans = 0`。 
2. 从左到右扫描字符串，解释当前奇偶校验下的每个字符。 如果奇偶校验为偶数，则字符不变。 如果奇偶校验为奇数，则字符在逻辑上反转。 
3. 我们将当前解释的字符与先前解释的字符在目标单调意义上进行比较。 有效的结构绝不能来自`1`回到`0`。 所以我们追踪我们是否已经“进入”了`1`地区。 
4. 如果我们在当前解释下检测到违反单调性，则意味着我们无法在不从此处开始应用另一次翻转的情况下修复后缀。 我们递增`ans`并切换`flip_parity`。 
5. Continue scanning, always using the updated parity to interpret future characters.

 关键的推理步骤是，每当单调性被破坏时，在不重新访问早期位置的情况下恢复可行性的唯一方法是从该位置向前翻转，因为后缀翻转是唯一允许的操作。 Thus each detected violation corresponds to one necessary operation in an optimal strategy.

 ### 为什么它有效

 At any prefix of the scan, the algorithm maintains a consistent interpretation of the string after applying some number of suffix flips. 当我们遇到违反该解释下的单调条件的位置时，任何有效的解决方案都必须在该点或之前引入至少一次翻转，以便修复顺序约束。 选择最早的这样的位置绝不会增加以后所需操作的数量，因为延迟翻转只会增加后缀中的矛盾数量。 This makes the greedy choice locally forced and globally optimal.

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    flip = 0
    ans = 0

    prev = 0  # previous interpreted value

    for ch in s:
        cur = int(ch)
        if flip:
            cur ^= 1

        if cur < prev:
            ans += 1
            flip ^= 1
            cur ^= 1

        prev = cur

    print(ans)
```The solution avoids explicit string mutation and instead simulates the effect of flips using a parity flag. 变量`prev`跟踪单调序列中最后一个有效的解释位。 当当前位违反所需的顺序时，我们通过切换奇偶校验并增加操作计数来模拟在该位置应用后缀翻转。 

一个微妙的点是我们立即重新解释`cur`切换奇偶校验后以确保`prev`与转换后的后缀保持一致。 这可以防止检测到违规但未正确传播的差一错误。

 ## 边缘情况

 关键的边缘情况是一个已经单调的字符串，例如`000111`。 该算法永远不会触发翻转，因为`prev`永远不会减少，所以答案保持为零。 

另一个边缘情况是单个长时间运行的交替位，例如`010101`，其中每一步似乎都是局部正确的，但奇偶校验翻转会累积。 该算法对每个结构违规的每次强制校正正确计数一次，并且最终计数与稳定字符串所需的后缀操作的最小数量相匹配。
