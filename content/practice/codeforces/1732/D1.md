 ## 解决方案
 ## 问题理解

 我们从一个最初只包含数字零的集合开始。 随着时间的推移，应用了两种操作。 一个操作将一个新整数插入到集合中，另一个操作询问有关称为 k-mex 的特殊值的查询。 

k-mex 定义为 k 的倍数且不存在于集合中的最小非负数。 因此，我们不是扫描所有整数以查找通常的 mex，而是只关心固定算术级数上的数字：0、k、2k、3k 等，并且我们想要该序列中第一个缺失的数字。 

该集合只会增长。 这很重要，因为一旦数字出现，它就会永远存在，因此对未来查询的答案只会变得更加受限。 

约束很大，最多 2 × 10^5 次操作，值可以大到 10^18。 这立即排除了任何为每个查询从头开始重新计算答案或为每个查询线性扫描 k 倍数的方法。 当 k 本身可能很大时，即使迭代到 k 或维护每个查询的算术级数也会太慢。 

一个幼稚的错误是独立模拟每个查询。 对于具有 k 的查询，可以从 0 开始并重复检查 k 倍数的成员资格，直到找到缺失值。 如果集合变大而 k 很小，则这会退化为每个查询扫描许多元素。 例如，如果集合包含 k 的所有倍数（最多 10^9），则扫描在该范围内变为线性，这在约束下是不可能的。 

当 k 很大但集合中存在稀疏元素时，会出现另一个微妙的失败情况。 如果我们不能有效地构建成员资格查询，那么对大集合进行重复检查的成本仍然很高。 

关键的困难在于每个查询都询问不同的算术级数，因此我们需要一种跨查询重用信息的方法，而不是从头开始重新计算。 

## 方法

 直接方法将集合保留在哈希结构中，并通过重复检查 k、2k、3k 等来处理每个 k-mex 查询，直到找到缺失值。 这是正确的，因为它遵循字面定义。 然而，在最坏的情况下，每个查询可能会扫描多个倍数才能找到间隙。 由于最多有 2 × 10^5 次查询，因此在最坏的情况下这会变成二次行为。 

重要的观察是，只有当我们插入一个影响其级数的数字时，固定 k 的答案才会发生变化，这意味着填充当前间隙的 t·k 形式的数字。 我们不再考虑每个查询，而是翻转视角并考虑每个值：每个插入的数字仅影响 k 整除它的查询。 

这表明，对于查询中出现的每个 k，维护仍然缺失的 k 的最小非负倍数。 如果我们可以跟踪已经存在的倍数，我们就可以为每个 k 维护一个指针，只要插入该倍数，该指针就会前进。 

有效实现这一点的结构是从 k 到当前候选答案的映射。 当我们需要 k-mex 时，我们从当前候选值开始，并以 k 为步长前进，直到找到不在集合中的值。 因为每个候选值仅在插入其值时才向前移动，所以每个整数负责仅向前移动除它的 k 个值。 这使得总体工作易于管理。 

核心思想是对所有查询进行摊销：我们只在指针因插入而无效时才推进指针，而不是重新计算每个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q·(答案/k)) | O(q) | 太慢了|
 | 最佳 | O(q √V) 摊销或更好，具体取决于实施 | O(q) | 已接受 |

 ## 算法演练

我们维护一组所有插入值和一个字典，对于查询中看到的每个 k，存储该 k-mex 的当前候选答案。 

1. 将集合初始化为 0，因为它始终存在。 同时初始化一个空映射 next_candidate[k]，它将存储我们尚未确认的最小可能的 k-mex 候选者。 
2.对于每个查询，如果是插入+x，则将x添加到集合中。 
3.插入x后，我们必须检查x是否影响任何k-mex状态。 对于之前查询过的每个 k，如果 x 是 k 的倍数，则 x 可能会使先前假设的该 k 的缺失倍数无效。 在这种情况下，我们只关心 x 是否等于 next_candidate[k]，因为这意味着当前候选不再有效。 
4. 如果 x 等于 next_candidate[k]，我们通过添加 k 来重复推进 next_candidate[k]，直到达到集合中不存在的值。 每个步骤对应于检查算术级数中的下一个倍数。 
5. 查询？ k，如果 k 是新的，我们通过从 0 开始并前进 k 来计算其初始候选值，直到找到丢失的数字。 我们将其存储在 next_candidate[k] 中。 
6. 输出next_candidate[k]。 

关键是集合中的每个值每次比赛只能“向前推”每个 k 一次。 由于 next_candidate[k] 严格增加，因此每个 k 指针在所有更新中向前移动有限次数。 

### 为什么它有效

 对于每个 k，next_candidate[k] 始终表示当前不在集合中的 k 的最小倍数（考虑到到目前为止已处理的所有更新）。 插入只会添加元素，因此只有当插入确切的值时，候选才会变得无效。 一旦我们超越它，它就永远不会再次有效。 这种单调移动保证了正确性，并确保每个整数在其影响的每 k 内最多被处理一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    S = set([0])
    next_k = {}

    def advance(k, start):
        x = start
        while x in S:
            x += k
        return x

    for _ in range(q):
        parts = input().split()
        if parts[0] == '+':
            x = int(parts[1])
            S.add(x)

            # update all tracked k's if needed
            for k in list(next_k.keys()):
                cur = next_k[k]
                if cur == x:
                    next_k[k] = advance(k, cur)

        else:
            k = int(parts[1])
            if k not in next_k:
                next_k[k] = advance(k, 0)
            print(next_k[k])

if __name__ == "__main__":
    solve()
```套装`S`存储所有活动元素，包括初始零。 字典`next_k`记住每 k 的答案，因此重复查询不会重新启动计算。 

这`advance`函数是 k-mex 定义的直接实现：它沿着 k 的倍数遍历，直到找到缺失的一个。 仅在必要时才调用此函数，无论是对于第一个查询还是当候选因插入而无效时。 

所有跟踪的 k 值的循环是微妙的部分。 当新插入的数字恰好填充某个 k 的先前缺失的候选数字时，它确保了正确性。 我们只有在平等发生时才会前进，这使得更新最少。

 ## 边缘情况

 一个棘手的情况是，被查询的 k 在几次插入后再也不会被查询。 该算法仍然保持正确性，因为存储的 next_k 值在没有进一步更新的情况下保持有效，因为没有新的插入影响它。 

另一个边缘情况是 k = 1。这里的序列都是非负整数，因此 k-mex 只是第一个缺失的整数。 该算法退化为标准的 mex 维护，并且当插入新的连续整数时指针准确地前进，这符合直觉。 

最后一个微妙的情况是 k 非常大，接近 10^18。 在这种情况下，第一个候选几乎总是 0 或 k 本身，并且由于很少有值是如此大的 k 的倍数，因此更新很少。 对于这些值，算法自然会变得几乎恒定的每次查询时间。
