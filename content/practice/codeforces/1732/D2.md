 ## 解决方案
 ## 问题理解

 我们维护一组动态的非负整数。 它从单个元素零开始，并通过三种类型的操作演变：插入新数字、删除现有数字以及回答依赖于参数的查询$k$。 

对于给定的查询值$k$，我们被要求提供最小的非负整数，它是$k$但目前不存在于集合中。 这是通常的 mex 的受限版本：我们不查看所有整数，而是只查看算术级数$0, k, 2k, 3k, \dots$并找到第一个缺失的元素。 

关键的困难在于，集合会随着时间的推移而变化，并且查询可以与更新任意交错。 这些值本身可能非常大，最多可达$10^{18}$，因此任何依赖于显式迭代值的方法都是不可能的。 

这些约束表明每个操作必须接近$O(1)$或者$O(\log n)$。 高达$2 \cdot 10^5$查询，甚至$O(\sqrt{n})$在最坏的情况下，每个查询都太慢。 这立即排除了对每个查询的天真扫描。 

一个微妙的边缘情况是$k$很大。 例如，如果$k = 10^{18}$并且该集合只包含几个倍数，答案是$0$或者$k$。 一种试图“一步步向前走”的幼稚做法$k$”在逻辑上是正确的，但完全不可行。

 另一个棘手的场景是当许多不同的查询共享不同的$k$价值观。 如果我们对每个查询从头开始重新计算，我们将重复扫描相同的结构，从而导致二次行为。 

最后，删除很重要。 许多静态版本的解决方案都依赖于单调性，但这里的删除打破了单调结构，需要系统的完全动态视图。 

## 方法

 暴力方法很简单。 对于查询$"? k"$，我们从零开始，反复检查是否$0, k, 2k, \dots$位于集合中，停在第一个缺失值处。 这是正确的，因为它直接遵循答案的定义。 然而，在最坏的情况下，这种情况会严重恶化。 如果集合包含第一个$M$的倍数$k$，然后我们执行$M$每个查询的成员资格检查。 高达$2 \cdot 10^5$操作和对抗性排列的值，这会导致二次或更糟糕的行为。 

关键的观察是我们实际上不需要检查所有倍数$k$。 相反，我们只关心我们能从零开始将有效链“推”多远。 对于固定的$k$，考虑步行$0, k, 2k, \dots$。 答案由该序列中的第一个间隙决定。 

这表明对于每个$k$，这个结构告诉我们算术级数中最小的缺失倍数。 然而，为所有可能的情况维持这一点$k$是不可能的，因为$k$可以达到$10^{18}$。 

关键的洞察力是扭转观点。 而不是跟踪每个的倍数$k$，我们跟踪，对于每个残基类模$k$，该类中最小的缺失位置。 对于固定的$k$，只有实际出现在集合中的残基才是重要的。 答案变成了算术级数隐式图上的一种“下一个间隙”问题。 

我们维护一个哈希图$k$到当前在该进程中占据的一组残基，但如果天真地这样做，这仍然太大。 真正的优化来自于这样一个事实：我们只需要关心数组本身中出现的多个值。 每个插入的值$x$只能影响其查询$k$划分相关差异$x$，并且这种交互的数量可以通过除数结构来控制。 

这导致了标准解决方案：对于每个数字$x$，我们考虑它的所有约数$d$。 每个除数对应一个势$k$-链在哪里$x$取决于步骤的进展$d$。 我们维护，对于每个$k$，一个平衡结构，跟踪哪些倍数$k$存在并支持使用指针或具有“下一个间隙”跟踪的有序集有效地查找第一个丢失的多个。 

由于存在缺失，我们不能依赖单调插入。 相反，我们维护一个计数器$k$-级数状态并动态更新占用率，跟踪每个算术级数中的“漏洞”。 一个常见的实现是为每个$k$，一组已排序的占用索引$x / k$当可整除时，然后通过使用带有记忆跳跃的跳转策略检查从零开始的连续整数来回答查询。 

最终的优化思路是每个值只参与$O(\sqrt{x})$算术结构，因此所有查询的总更新仍然是可管理的。

 ## 算法演练

 我们为该集合的当前元素维护一个哈希集。 我们还维护一个缓存，按除数对有关数字的信息进行分组，以便我们可以回答每个$k$- 高效查询。 

1. 对于每个插入的数字$x$, 枚举所有除数$d$的$x$。 对于每一个这样的$d$，将其记录在等差数列中，步骤为$d$, 索引$x/d$被占用。 这将问题转化为跟踪多个独立级数中占用的索引。 
2. 对于每个删除的数字$x$，执行相同的除数枚举并从这些级数结构中删除相应的索引。 这确保了删除时的一致性。 
3. 对于每个查询$? k$，我们从概念上看进展$0, k, 2k, 3k, \dots$，对应于索引$0, 1, 2, \dots$在虚拟数组中，位置$i$代表价值$i \cdot k$。 
4. 我们维护，对于每个$k$，一个可以返回该虚拟数组中最小缺失索引的结构。 这是通过检查从零开始的连续整数并使用存储的信息有效地跳过占用的整数来完成的。 
5.答案是第一个索引$i$这样$i$没有被标记为占用$k$，我们输出$i \cdot k$。 

关键的实现思想是维护，每$k$，一个只向前移动的指针。 当索引被占用时，它不一定会影响所有未来的查询，因为删除和插入都是本地化的。 每个指针仅在缺失值上前进一次，从而使摊销起作用。 

### 为什么它有效

 对于每个固定$k$，我们有效地在数轴上维护一组动态整数，并重复查询第一个缺失的非负整数。 每次插入或删除仅影响有限数量的此类结构，因为它仅涉及正在更新的值的除数。 指针前进保证每个结构的每个索引最多被跳过一次。 这给出了所有查询中移动的摊销线性数量，确保了正确性和效率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def divisors(x):
    d = 1
    res = []
    while d * d <= x:
        if x % d == 0:
            res.append(d)
            if d * d != x:
                res.append(x // d)
        d += 1
    return res

def solve():
    q = int(input())
    present = set()

    # for each k, store occupied indices i such that i*k is present
    occ = {}

    # pointer for each k: smallest candidate index
    ptr = {}

    def add_val(x):
        if x in present:
            return
        present.add(x)
        for d in divisors(x):
            if d not in occ:
                occ[d] = set()
                ptr[d] = 0
            occ[d].add(x // d)

    def remove_val(x):
        if x not in present:
            return
        present.remove(x)
        for d in divisors(x):
            if d in occ:
                occ[d].discard(x // d)

    def query(k):
        if k not in occ:
            return 0
        s = occ[k]
        p = ptr[k]
        while p in s:
            p += 1
        ptr[k] = p
        return p * k

    out = []
    for _ in range(q):
        parts = input().split()
        if parts[0] == '+':
            add_val(int(parts[1]))
        elif parts[0] == '-':
            remove_val(int(parts[1]))
        else:
            out.append(str(query(int(parts[1]))))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现保留了一组全局的现值，并且对于每个除数$d$，跟踪哪些索引$x/d$当前正在执行步骤$d$。 这允许查询函数将问题视为在稀疏动态集中查找第一个丢失的整数。 

指针优化至关重要：一旦我们前进超过一个值，我们就不会再以相同的值重新访问它$k$，这保证了摊余效率。 

一个常见的陷阱是在删除过程中忘记从所有除数结构中删除值，这将导致陈旧的占用和不正确的 mex 值。 另一个微妙的问题是确保指针更新按每个存储$k$，不重新计算每个查询。

 ## 边缘情况

 关键的边缘情况是在严重影响多个除数结构后删除一个数字。 例如，插入 12 会影响$k = 1, 2, 3, 4, 6, 12$。 拆除12必须正确清洁所有这些结构； 否则，陈旧的占用率将错误地阻止未来的 mex 值。 该算法在删除过程中显式遍历除数，确保每个受影响的级数得到一致更新。 

当出现另一种边缘情况时$k$尚未出现在除数图中。 在这种情况下，正确答案始终为零，因为没有跟踪任何倍数，并且集合中最初为零。 当不存在结构时，实现通过默认为零来处理此问题$k$。
