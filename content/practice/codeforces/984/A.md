 ## 解决方案
 ## 问题理解

 我们得到了放置在板上的整数列表。 两名玩家轮流从棋盘上恰好删除一个数字。 恰好之后$n-1$消除后，只剩下一个数字，这个数字就是游戏的结果。 

球员们有相反的目标。 第一个玩家删除数字的方式是尝试使最终剩余值尽可能小，而第二个玩家则尝试使其尽可能大。 两名球员始终观察整个阵容并发挥最佳水平。 

重要的不是删除的顺序本身，而是哪个元素被迫在整个战略删除序列中幸存下来。 

约束条件$n \le 1000$意味着我们可以负担得起$O(n^2)$甚至$O(n^3)$原则上推理，但游戏的结构表明贪婪或基于不变的解决方案比对所有游戏状态进行模拟更合适。 

简单的模拟将尝试对每个可能的移除序列和交替的最佳决策进行建模。 这很快就变得不可行，因为每个状态分支都取决于删除的元素，并且两个玩家都会针对未来状态进行优化。 即使积极修剪，仍然会留下一棵大游戏树。 

一个更微妙的问题出现在局部直觉推理中。 例如，人们可能会假设玩家只是交替删除当前的最大值或最小值。 这是不正确的，因为最后剩余元素的身份取决于保护或消除候选者，而不仅仅是在每一步贪婪地去除极端值。 

一个关键的边缘情况是所有数字都相等。 任何移除序列都会产生相同的最终答案，因此最佳游戏变得无关紧要。 另一种边缘情况是数组大小为 2 时。 第一个玩家删除一个元素，第二个玩家删除剩余的一个元素，所以答案只是第一个玩家选择留下哪个元素。 

## 方法

 直接的暴力方法会尝试将游戏建模为剩余元素子集上的极小极大过程。 每个状态由剩余的元素和轮到谁来定义。 从一个状态开始，玩家尝试所有可能的移除并递归地评估结果。 

这种方法是正确的，因为它完全尊重最佳游戏，但它会组合爆炸。 有$2^n$子集以及从每个子集到$n$过渡，大致给出$O(n2^n)$国家，这甚至远远超出了限制$n = 30$。 

关键的见解是，游戏不是要控制中间值，而是要控制哪个元素在最后一次删除中幸存下来。 由于只有一个元素幸存下来，因此该过程相当于选择一个元素来“保护”，而所有其他元素都被删除。 

第二个玩家总是试图确保最终的幸存者尽可能大。 第一个玩家试图通过尽早消灭大型元素来防止它们幸存。 由于玩家交替删除，第一个玩家实际上可以在每轮消除压力中首先选择哪个元素不受保护。 

重新解释该过程的一种有用方法是：每一步都会永久删除一个元素。 后$n-1$移动时，永远不会选择删除一个元素。 最佳游戏简化为决定在交替控制下最难消除哪个元素。 

这种结构大大简化了：两个玩家都在有效地竞争命令删除元素，但由于除了一个元素之外的所有元素都必须被删除，第二个玩家的目标减少到确保最大的元素幸存，而第一个玩家则试图阻止这一点。 然而，第一个玩家总是先行动，这意味着他们总是可以确保在某个时刻至少删除一个“大候选者”。 

这导致了这个问题的经典结果：最佳游戏总是留下第二大元素，如果$n > 1$。 直观上，最大的元素对于第二个玩家来说太有价值了，无法避免间接瞄准，但第一个玩家总是可以及时强制移除它，然后第二个玩家就会保护下一个最佳候选者。 

因此，最终答案是数组的第二个最大值。

 ## 算法演练

 1. 对数组进行非降序排序。 排序用于识别最大和第二大元素，它们是最佳游戏将游戏压缩为端点控制后唯一重要的候选元素。 
2.如果$n = 1$，由于没有进行任何移动，因此立即返回唯一的元素。 
3. 否则，返回第二大元素，该元素位于索引处$n-2$排序后。 

### 为什么它有效

 游戏完全删除了$n-1$元素，留下一名幸存者。 两个玩家都具有完全的可见性和交替控制，但他们无法控制无法删除的增长或缩小的结构。 这意味着任何元素都不能无限期地保留，除非双方玩家始终避免删除它，而在极端竞争时，在交替最佳游戏下这是不可能的。 

第二个参与者的目标是最大化最终值，因此他们将始终尝试保留最大的剩余候选者。 第一个玩家，首先移动，总是可以通过移除它或在随后的回合中迫使其暴露于移除压力来响应保护最大值的尝试。 这种相互作用保证了最大化不能可靠地生存于两个玩家的最优策略。 

一旦最大值不稳定，下一个最强的稳定候选者就是第二个最大值，它成为最佳发挥下的最终幸存者。 没有其他元素可以系统地超越它，因为任何较小的元素对于最大化玩家来说都是更糟糕的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    if n == 1:
        print(a[0])
        return

    a.sort()
    print(a[-2])

if __name__ == "__main__":
    solve()
```该解决方案首先读取数组并直接处理简单的单元素情况。 排序用于对值进行排序，以便可以立即访问最大和第二大元素。 

排序后，从倒数第二个位置取出答案。 这是安全的，因为排序不会更改值的多重集，并且上面的参数表明只有排名信息重要，而不是位置。 

该实现完全避免了模拟。 任何模拟回合的尝试都需要维持游戏状态并评估最佳移动，一旦认识到订单统计数据的减少，这就没有必要了。

 ## 边缘情况

 当$n = 1$，算法立即返回唯一的元素。 从概念上讲不需要排序，也不会发生博弈，因此这是一个直接的基本情况。 

什么时候$n = 2$, 排序产生`[min, max]`算法返回`min`。 这与游戏玩法相匹配，因为第一个玩家删除了一个元素，而第二个玩家别无选择，只能留下另一个元素，因此第一个玩家通过选择保留哪个元素来有效地决定结果。 

当所有元素都相同时，排序会保留它们，并且第二大的元素等于最大的元素。 每个删除序列都是等效的，因此规则正确地折叠为共享值。 

当数组严格递增或递减时，第二大元素总是定义明确且在排序下稳定。 无论初始顺序如何，该算法始终返回正确的基于排名的幸存者。
