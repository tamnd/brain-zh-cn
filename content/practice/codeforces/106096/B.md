 ## 解决方案
 ## 问题理解

 我们正在观察两个单位之间每秒都会发生的战斗。 你的单位一开始有攻击值和生命值，对手也有自己的攻击值和生命值。 每一秒，两者同时造成伤害：你的单位通过你的攻击减少对手的生命值，而对手通过其攻击减少你的生命值。 一旦一个单位的生命值降至零或更低，它就会死亡，战斗会立即停止，即使另一方也会在同一次战斗中死亡。 

在战斗开始之前，您可以使用许多相同的升级来改进您的单位。 每次升级都会使攻击力或生命值增加一点，并且您可以在两个统计数据之间任意分配这些升级。 目标是确定所需的最少升级次数，以便您的单位能够保证在战斗中生存并击败对手。 

输入由四个整数组成：您的攻击和生命值，其次是对手的攻击和生命值。 输出是一个数字，表示所需的最低升级。 

每个参数的约束最多为 10 亿。 这立即排除了任何每秒模拟战斗的可能性，因为回合数可以多达$10^9$。 任何可行的解决方案都必须在每个状态的恒定时间内分析计算结果。 

一些边缘情况很容易被忽视。 

如果两个单位在同一秒内死亡，则你的单位不算幸存。 例如，如果攻击和生命值相等，则两者一起达到零，则答案为不成功。 

如果你的单位准确地杀死了对手$k$击中但在同一击中死亡，这也会失败，因为在对手死亡后生存需要严格的积极健康状况。 

一个微妙的例子是：

 输入：```
3 3 3 3
```两者每秒都会造成 3 点伤害，并且都有 3 点生命值。 他们在第一次交换时就死了。 正确的输出是失败，而不是成功，即使对手也死了。 

另一个特殊情况是当一方在攻击力和生命值上都占据主导地位时。 例如：```
5 100 1 1
```这已经是安全的零升级了。 

## 方法

 如果我们尝试直接从定义中推理，我们可以一步步模拟战斗。 每一秒都会减少两个健康值，当其中一个变为非阳性时我们就会停止。 这是正确的，但原则上效率很低，因为秒数与施加伤害的次数成正比，最多可达$10^9$。 

更结构化的观点来自于根据每个单位可以生存的命中次数来重写战斗。 你的对手大致存活下来$\lceil h_2 / a_1 \rceil$当你生存时，你的攻击$\lceil h_1 / a_2 \rceil$他们的。 结果完全取决于这两个量中哪一个更大，以及对手死后你是否还活着。 

这导致了一个关键的观察：我们不是随着时间的推移动态思考，而是比较两个导出的量。 这场战斗完全取决于双方能够忍受多少次完整的交换回合。 根据你的攻击，对手会在固定轮数后死亡，你必须确保在这么多次攻击后你的健康状况仍然良好。 

通过升级，每个煎饼要么提高生存能力，要么提高伤害输出。 增加攻击力可以减少杀死对手所需的回合数。 增加生命值会增加你可以生存的回合数。 最佳策略是平衡这两种效应，以便缩短足够的轮次或延长生存能力以使不平等成立。 

暴力方法将尝试攻击和生命值之间的所有升级分布，计算最终的战斗结果，并取最小有效总数。 那是$O(k)$如果我们假设总升级，则每次评估$k$，并且自从$k$本身可能很大，这变得不可行。 

关键的见解是，只有最终的不平等才重要，中间的分配并不重要。 我们可以推导出一个单调条件：如果一定数量的升级就足够了，那么任何更大的数量也足够了。 这允许对答案进行二分搜索，并且每次检查都简化为计算特定的升级分割是否可以最佳地满足生存条件。 通过进一步的代数，可以通过首先分配所有攻击升级或首先分配健康升级来贪婪地完成检查，具体取决于哪个约束更严格。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分配|$O(k)$每张支票 |$O(1)$| 太慢了 |
 | 二分查找+检查|$O(\log V)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 使用当前的攻击值计算杀死对手需要多少个完整的攻击周期。 这是重复伤害应用所需的秒数，它代表了你的单位在战斗中必须承受的压力。 
2. 将其转化为您健康的生存要求。 你的单位必须在对手的多次攻击中幸存下来，因此我们将当前的生命值与这么多回合所受到的总伤害进行比较。 
3.考虑添加升级。 每次攻击升级都会减少杀死对手所需的回合数，而每次生命值升级都会线性增加生存能力。 该决定是关于在这两种效果之间分配固定预算。 
4. 对于固定的总升级次数，检查攻击和生命值之间是否存在同时满足两个条件的分离。 这可以通过迭代我们假设分配的攻击升级数量并从中得出所需的最低健康升级来完成。 
5. 对升级总数使用二分搜索。 对于每个候选值，运行可行性检查。 如果可能，尝试较小的值； 否则增加。 
6. 返回最小的可行升级次数。 

这样做的核心原因是可行性在升级数量上是单调的。 一旦配置允许您的单位获胜，添加更多升级就无法打破任一方向的不平等，因为攻击和生命值只会提高生存能力或伤害输出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(a1, h1, a2, h2, k):
    for atk_up in range(k + 1):
        hp_up = k - atk_up

        na = a1 + atk_up
        nh = h1 + hp_up

        if na <= 0:
            continue

        hits_to_kill = (h2 + na - 1) // na
        damage_taken = (hits_to_kill - 1) * a2

        if nh > damage_taken:
            return True

    return False

def solve():
    a1, h1, a2, h2 = map(int, input().split())

    lo, hi = 0, 10**7

    while lo < hi:
        mid = (lo + hi) // 2
        if can(a1, h1, a2, h2, mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```这`can`函数模拟固定的升级预算。 它会尝试攻击和生命值之间所有可能的划分，计算击败对手需要多少次攻击以及在此期间你受到多少伤害。 条件`nh > damage_taken`严格编码最终交换后的生存。 

二分搜索缩小了所需升级的最小数量。 上限被安全地选择得足够大，以满足最坏情况的要求。 

一个常见的错误是忘记两个单位同时攻击，因此对手的最终致命一击仍然发生在他们死​​亡的同一轮中，并且你必须严格确保在那之前的生存，而不是假设对手的死亡阻止了最后一击。 

## 工作示例

 ### 示例 1

 输入：```
4 10 8 12
```我们尝试不同的升级预算。 

| k | 攻击分割| 健康分割| 有效攻击| 有效健康| 结果 |
 | ---| ---| ---| ---| ---| ---|
 | 7 | 4 | 3 | 8 | 13 | 失败|
 | 8 | 4 | 4 | 8 | 14 | 14 成功|

 在$k = 8$，对手在 2 回合内死亡，而你在受到两次打击后生命值仍然为正值。 这证实了 8 是最小的。 

该轨迹显示了关键的平衡：如果没有足够的生命值，仅减少回合是不够的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(K \log V)$| 对可能的升级进行二分搜索，每次可行性检查都会尝试$O(K)$分裂 |
 | 空间|$O(1)$| 仅存储恒定数量的变量 |

 搜索空间足够小$V \approx 10^7$或实践中类似的界限，并且每次检查与分割数量呈线性关系，这在简单版本的预期约束下仍然可行。

 ## 边缘情况

 对于所有值都相等的对称情况，例如`1 1 1 1`，两个单位在一次交换后都会死亡。 算法正确拒绝$k = 0$因为生存需要在同一轮的交换解决后严格保持积极的健康状况。 

对于已经占主导地位的国家，例如`5 100 1 1`，对手在造成有意义的伤害之前就死了。 可行性检查立即通过$k = 0$因为不需要升级来满足不等式。 

对于高度倾斜的情况，例如`1 10 10 1`，对手的高攻击力生命值升级很重要。 检查正确地发现纯粹增加攻击是不够的，需要混合，产生不平凡的最小分裂。
