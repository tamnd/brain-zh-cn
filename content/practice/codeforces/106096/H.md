 ## 解决方案
 ## 问题理解

 我们正在与一个系统交互，该系统在从 1 到 n 的一行中隐藏了两个不同的整数，将它们称为 x₁ 和 x2，其中 x₁ < x2。 我们不知道它们的位置，提取信息的唯一方法是在选定的位置发出查询。 

每个查询都是一个位置 x。 系统根据两个隐藏点中哪一个更接近 x 进行响应。 如果x恰好等于隐藏点之一，系统直接确认。 否则，它会比较与 x₁ 和 x2 的距离，选择较近的一个，并判断所选点是位于 x 的左侧还是右侧。 

关键的困难在于，响应并没有立即直接告诉我们有关这两点的任何信息。 它仅揭示有关当前更接近的隐藏点的方向信息，这取决于几何形状而不是身份。 

对于这种类型的交互问题，约束是极端的：n 可以大到 10⁹，并且我们的查询次数被限制为大约 125 个。 这立即排除了任何在没有结构的情况下以线性甚至对数尺度独立扫描位置或细化两个点的策略。 唯一可行的方向是利用响应函数中的单调行为并通过二元决策减少搜索空间。 

当查询点恰好是隐藏位置之一时，会出现微妙的边缘情况。 在这种情况下，响应是平等而不是方向。 例如，如果隐藏点是 3 和 10，则查询 x = 3 会产生“=”，而查询 x = 4 会根据 3 或 10 是否更接近而产生定向响应。 假设每个响应都是有方向的天真的二分搜索可能会在这里失败，因为相等性不适合排序逻辑，并且必须被视为终端发现。 

另一个重要的边缘情况是当查询恰好位于 x₁ 和 x2 之间的中点时。 在这种情况下，两座塔的距离相等，并且问题指定选择正确的塔。 这种打破平局的规则使得响应函数单调并且可用于二分搜索。 

## 方法

 暴力策略会尝试查询从 1 到 n 的每个位置，直到发现两个隐藏点。 这是正确的，因为最终我们会同时命中 x₁ 和 x2 并收到相等的响应。 然而，在最坏的情况下，这需要 n 个查询，最多可达 10⁹，远远超出 125 个查询的限制。 即使限制随机抽样也无济于事，因为无法保证及时实现两个目标。 

关键的结构观察是，虽然我们不知道给定查询哪个点更接近，但系统有效地定义了一个隐藏的中点 M = (x₁ + x2) / 2。对于任何查询 x，如果 x 小于 M，则保证 x₁ 比 x2 更接近，因此响应纯粹由 x₁ 确定。 如果 x 大于 M，则响应完全由 x2 决定。 恰好在 M 处，双方在距离上的可能性相同，但抢七局迫使双方保持一致。 

这意味着响应方向的行为类似于在 M 处具有单个转变点的单调函数。即使我们不单独知道 x₁ 或 x2，我们也可以对这个转变点进行二分搜索。 一旦 M 已知，问题就会清晰地分解：x₁ 完全位于 [1, M] 中，x2 完全位于 [M, n] 中，并且在每个段内，每个查询的行为就好像只存在一个目标一样。 这将问题简化为两个独立的标准交互式搜索。

 ## 算法演练

 我们分两个阶段构建解决方案：定位两个塔的中点区域分离影响，然后独立定位每个塔。

1. 我们定义一个查询函数，用于打印位置并读取响应，立即刷新输出。 这是必需的，因为交互仅在每次刷新后进行。 
2. 我们对 [1, n] 中的 x 进行二分搜索，以找到响应改变行为的转变点。 在位置 x 处，如果响应为“>”，则表示最近的塔在右侧，这意味着 x 在中点区域的左侧。 如果响应为“<”，则 x 位于中点区域的右侧。 这给出了 x 上的单调谓词。 
3.我们维持一个搜索区间[l,r]。 对于 mid = (l + r) / 2，我们查询 mid 并根据响应调整间隔，向唯一的分割位置 M 收缩。 
4. 一旦确定了 M，我们就知道了一个关键的结构事实：[1, M] 中的每个点都比 x2 更接近 x₁，[M, n] 中的每个点比 x₁ 更接近 x2。 这将问题转化为两个独立的单目标搜索。 
5. 为了找到 x₁，我们在 [1, M] 中进行二分搜索。 当我们查询此范围内的位置 x 时，系统的方向响应现在仅涉及 x₁，因为 x2 在该区域中总是更远。 如果响应指示“>”，则 x₁ 位于 x 的右侧； 否则它位于左侧，否则我们就会达到平等。 
6. 我们在 [M, n] 中重复相同的过程来定位 x2。 
7. 一旦找到两者，我们就按升序输出它们并终止。 

正确性取决于一个不变量：一旦中点 M 固定，M 的每一侧较近的塔的身份都是恒定的。这消除了比较中的歧义，并确保每个二分搜索步骤的行为类似于对单个隐藏值的标准单调搜索。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(x: int) -> str:
    print(x)
    sys.stdout.flush()
    return input().strip()

def find_mid(n: int) -> int:
    l, r = 1, n
    while l < r:
        mid = (l + r) // 2
        res = ask(mid)

        if res == "<":
            l = mid + 1
        else:
            r = mid
    return l

def find_point(l: int, r: int) -> int:
    while l < r:
        mid = (l + r) // 2
        res = ask(mid)

        if res == ">":
            l = mid + 1
        else:
            r = mid
    return l

def main():
    n = int(input())

    mid = find_mid(n)

    x1 = find_point(1, mid)
    x2 = find_point(mid, n)

    if x1 > x2:
        x1, x2 = x2, x1

    print("! {} {}".format(x1, x2))
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```第一个搜索隔离两个隐藏点的影响切换的中点。 第二次和第三次搜索是标准的二分搜索，因为在每个受限段中只有一个隐藏点可以负责所有响应。 最后的交换处理中点恰好位于塔上或搜索在边界处重叠的情况。 

一个常见的实现错误是将相等响应视为二进制排序的一部分。 如果遇到相等，则应视为立即终止，但即使忽略，中点分割的结构也会阻止它破坏二分搜索逻辑。

 ## 边缘情况

 如果隐藏点相邻，例如 x₁ = 4 和 x2 = 5，则中点为 4.5，因此 M 变为 4 或 5，具体取决于整数处理。 第一阶段仍然正确收敛，因为响应在 4 和 5 之间恰好翻转一次。左侧二分搜索将隔离 4，右侧二分搜索将隔离 5，不会产生歧义。 

如果查询恰好提前到达隐藏点，例如查询 x = x₁，系统会立即返回“=”。 该算法应立即终止该搜索分支并继续另一个间隔。 即使没有显式优化，相等性也会自然地将搜索空间压缩为单个值，从而保持正确性。 

如果中点搜索收敛于端点，例如 M = 1 或 M = n，则其中一个段将变为空。 在这种情况下，剩余段中的所有查询仍然正确地识别另一个塔，因为所有响应都由单个隐藏点主导，从而将问题简化为退化的单目标搜索。
