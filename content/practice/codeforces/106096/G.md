 ## 解决方案
 ## 问题理解

 我们面临两个单位之间的一对一战斗，每秒都会交换伤害。 每个单位都有固定的攻击值和固定的生命值，并且每一秒都会同时造成伤害：你的单位通过攻击减少对手的生命值，对手通过攻击减少你单位的生命值。 

在战斗开始之前，你可以使用一些“煎饼”来增强你的单位。 每块煎饼都可以将攻击力或生命值增加一分。 您可以在攻击和健康之间任意分配这些升级。 任务是确定您的单位在战斗中生存所需的最小煎饼数量，这意味着它在对手死亡之前的任何时候都不会达到零或负健康。 

交互是确定性的，因此整个战斗相当于询问会同时发生多少轮。 你的攻击越高，对手死得越快； 如果对手的攻击力更高，你的生命值损失得更快。 核心困难是选择如何平衡额外攻击与额外生命值。 

约束允许的值最大为 10^9。 这立即排除了任何直接模拟煎饼不同分配的方法。 即使迭代攻击和健康之间所有可能的划分也是不可能的，因为这将与答案大小呈线性关系，在最坏的情况下也可能约为 10^9。 

对固定配置的战斗进行天真的模拟是可以的，因为回合数受到生命值除以攻击力的限制，但真正的挑战是搜索分配升级的所有方法。 

当两个单位在同一轮中死亡时，就会出现一种微妙的情况。 在这个问题中，你的要求是生存，因此同时死亡被视为失败。 例如，如果两次攻击相等且生命值相等，则在第一次交换后两者都会降至零。 即使没有人“先输”，但这也是不可接受的。 

另一个极端情况是攻击非常小时。 如果你的攻击为1并且对手的生命值非常大，那么战斗会持续很长时间，并且生命值升级变得比攻击升级更有价值，但如果不考虑回合数，这一点并不明显。 

## 方法

 如果我们修复最终升级后的攻击和生命值，战斗将变得完全确定。 假设你的最终攻击是A，对手的攻击是B，你的最终生命值是H，对手的生命值是K。对手大约需要ceil(K / A)轮才能死亡。 在这些回合中，您每次都会受到 B 伤害，因此总伤害是 B 乘以回合数。 生存要求H严格大于这个伤害。 

这为任何选择的 A 和 H 提供了干净的可行性检查。暴力方法将尝试所有可能的方式将煎饼分配给攻击和健康。 如果我们假设我们在攻击上花费 x 煎饼，在生命值上花费 y，则 x + y = P，我们可以检查结果统计数据是否有效。 从 0 向上尝试所有 P，并且每次将其拆分为所有 x 时，答案大小都是二次方。 由于 P 本身可能很大，所以这太慢了。 

关键的观察结果是，攻击和生命值的贡献在影响战斗持续时间方面并不对称。 增加攻击会以非线性方式减少回合数，因为它会划分对手的生命值。 健康规模呈线性增加。 这表明我们不应该将攻击和健康视为独立的线性贡献，而是修复其中一个并计算另一个的最低要求。

我们可以确定有多少煎饼受到攻击。 如果我们添加 x 攻击，则 A = a1 + x。 一旦 A 确定，所需的最低生命值就直接确定：我们计算我们在对抗对手时能存活多少次，并确保我们的生命值至少达到该数量。 这将问题转化为 x 上的单变量优化。 由于 x 在最差的有用范围内最多为 a1 + a2 + h2，并且该函数的行为呈凸状（攻击通过减少回合数来帮助，生命值线性地帮助），因此我们可以从 0 向上检查所有 x，直到攻击变得如此之大以至于进一步增加停止改进回合。 

更具体地说，一旦A超过h2，对手就会一击毙命，因此进一步增加攻击并没有任何好处。 这限制了有用的搜索空间。

 ## 算法演练

 1. 从 0 开始迭代可能的攻击升级数 x。对于每个 x，设置 A = a1 + x。 我们仅考虑增加攻击仍会影响战斗长度的值，因为超过某一点对手就会在一轮中死亡。 
2. 计算以该攻击值进行战斗的回合数。 对手需要回合 R = ceil(h2 / A)。 这代表您的单位将受到损坏的次数。 
3. 计算生存所需的健康状况。 每轮造成 a2 伤害，因此总伤害为 R * a2。 您的生命值必须严格大于此值，因此所需的生命值至少为 R * a2 + 1。 
4.如果当前的健康h1已经满足这个要求，那么x个煎饼就足够了，我们可以更新答案。 
5. 否则，计算需要多少次运行状况升级：y = max(0, required_health - h1)。 此分割的煎饼总数为 x + y，我们跟踪所有 x 中的最小值。 
6. 返回找到的最小值。 

这样做的原因是，对于每个固定的攻击级别，无需对健康状况做出进一步的决定：任何最佳解决方案都将使用足够的健康状况来生存，因为额外的健康状况永远不会减少回合数。 

### 为什么它有效

 对于固定的攻击值A，轮数是完全确定的，不依赖于生命值。 一旦回合确定，生存仅取决于健康状况是否超过线性阈值。 因此，最优性简化为选择最小化 x + required_health(A) 的最佳 A。 对于同一个 A 来说，任何使用超过必要健康状况的解决方案都会更糟糕，并且任何改变 A 的重新分配都会以可预测的单调方式改变轮数。 这确保了独立评估每个可能的 A 涵盖所有最优分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a1, h1, a2, h2 = map(int, input().split())

    ans = float('inf')

    x = 0
    while True:
        A = a1 + x

        rounds = (h2 + A - 1) // A
        need_h = rounds * a2 + 1

        if need_h <= h1:
            ans = min(ans, x)
        else:
            ans = min(ans, x + (need_h - h1))

        if A > h2 and need_h > h1:
            break

        x += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该循环逐渐增加攻击，并且对于每个选择，它都会计算准确的生存要求。 停止条件依赖于一旦攻击超过对手生命值，对手就会在单回合内死亡，进一步增加攻击并不会提高回合数，只会增加成本。 

一个常见的实施陷阱是忘记这两种攻击是同时发生的。 这就是为什么生存在乘以对手攻击的轮数后使用严格的健康不平等，而不是简单地比较每次攻击的结果。

 ## 边缘情况

 当两个单位在开始时是对称的时，战斗将在一轮中结束且双方都归零。 该算法强制至少进行一次升级，因为生存需要严格的积极性，并且除非健康状况增加，否则健康状况会正确失败。 

当对手的攻击力与你的生命值相比非常大时，算法很快就会发现生命值升级主导了早期的 x 值，并且攻击增加只有在回合数减少时才变得相关。 该循环自然地过渡到注重健康的解决方案，无需特殊外壳。 

当你的攻击已经超过对手的生命值时，循环会立即评估单轮战斗。 在这种情况下，生存减少为检查 h1 > a2 是否，如果不是，算法会正确添加足够的健康升级，而不会浪费攻击升级。
