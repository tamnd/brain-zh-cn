 ## 解决方案
 ## 问题理解

 该问题描述了一家邮局，其经营范围为`n`分钟。 在分钟开始时`i`,`a[i]`克隆进入队列。 在那一分钟内，邮局最多服务`b`来自队列前面的克隆。 服务的克隆人在同一分钟结束时离开。 任何在最后一分钟后仍在等待的克隆体在离开前都会再停留一分钟。 任务是找出每个克隆人在邮局内花费的时间总和。 

输入给出工作分钟数、每分钟的服务容量以及每分钟到达的克隆数量。 输出是一个整数，表示所有克隆的总等待时间和服务时间。 克隆在分钟开始时进入`i`并在分钟结束时离开`i`贡献一分钟。 

限制最多允许`100000`分钟和到达计数可达`10^8`。 单独处理每个克隆的模拟是不可能的，因为克隆的总数可以达到`10^13`。 即使存储所有克隆或更新每个克隆的剩余时间也会超出实际限制。 该算法必须通过仅跟踪当前队列中的克隆数量来工作，这给出了线性解决方案。 

有几个细节可能会导致错误的答案。 一个常见的错误是忘记了在最后工作分钟到达的克隆人仍然会在那里停留，即使他们没有得到服务。 例如：```
Input
1 10
5

Output
5
```所有五个克隆都在仅有的一分钟内进入并立即得到服务，因此每个克隆都花费一分钟。 

另一个错误是忽略了结束后的额外一分钟。 考虑：```
Input
1 1
3

Output
5
```在工作分钟内服务一个克隆并花费一分钟。 剩下的两个克隆体在工作期间在室内呆一分钟，在关闭后再呆一分钟，这样`1 + 2 + 2 = 5`。 

第三个错误是只计算服务后的队列。 例如：```
Input
2 100
3 4

Output
7
```一分钟内进入的每个克隆都会对该分钟做出贡献，即使它立即离开。 正确的总数是`3`从第一分钟开始并且`4`从第二分钟开始。 

## 方法

 直接的方法是模拟每个克隆。 当克隆到达时，我们可以将其放入队列中并在几分钟内移动，最多删除`b`每分钟都有克隆。 为了计算答案，我们将为仍在邮局内的每个克隆添加一个。 这在逻辑上是正确的，因为每个克隆在其剩余的每一分钟中恰好贡献一分钟。 然而，克隆的数量可以大到`10^13`，所以即使一次遍历所有克隆也太慢了。 

关键的观察结果是队列中具有相同位置的克隆的行为相同。 我们不需要知道个体的身份，只需要知道目前有多少克隆人在等待。 对于每一分钟，服务开始时出现的克隆数量足以了解该分钟内贡献了多少时间。 将这个数量添加到答案中后，我们将队列减少所服务克隆的数量。 

蛮力之所以有效，是因为它单独跟踪每个贡献，但由于对象数量巨大而失败。 同一队列状态中的所有克隆都是可互换的这一观察结果将问题简化为维护一个表示当前队列大小的整数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O（克隆总数）| O（克隆总数）| 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 保留一个变量`queue`代表前一分钟后等待的克隆数量，并保持`answer`作为累计花费的时间。 
2. 每分钟将到达的克隆添加到队列中。 当前队列大小现在代表在邮局内度过这一分钟的所有克隆，因此将其添加到`answer`。 
3. 删除这一分钟内提供的克隆。 删除的数量是当前队列大小和服务限制中的较小者`b`。 
4. 处理完所有工作分钟后，再次添加剩余队列大小。 这些克隆体在关闭后会多停留一分钟。 

为什么有效：在每个工作分钟内，当前内部的每个克隆都贡献一分钟。 该算法准确地添加了该分钟内存在的克隆数量，无论它们是在最后离开还是继续等待。 最后的添加处理工作计划之外的唯一时间间隔。 由于每个克隆体的整个停留时间都包含在这些计算的时间间隔内，因此最终的总和是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    queue = 0
    answer = 0

    for x in a:
        queue += x
        answer += queue
        queue -= min(queue, b)

    answer += queue
    print(answer)

if __name__ == "__main__":
    solve()
```变量`queue`仅存储未完成克隆的数量，避免对克隆总数的任何依赖。 在每次迭代开始时，都会添加到达人员，因为他们在服务开始之前进入。 

添加到`answer`在删除服务的克隆之前发生。 这个订单很重要，因为立即送达的克隆人仍然会在邮局内停留一分钟。 删除后移动添加物将丢失所有此类克隆。 

服务步骤使用`min(queue, b)`因为邮局无法为比当前等待的更多的克隆提供服务。 Python 整数会自动处理可能的大答案，这是必要的，因为总时间可能远大于 32 位整数限制。

 ## 边缘情况

 对于邮局关闭且剩余克隆的情况：```
Input
1 1
3
```该算法从一个空队列开始。 将三个到达者相加，得到三个队列，并为答案增加三分钟。 一个克隆被送达，剩下两个。 在完成所有工作分钟后，算法会添加剩余的两分钟。 结果是`5`，匹配所需的行为。 

对于立即提供所有克隆的情况：```
Input
3 100
5 5 5
```每分钟开始时只有新到达的人，因为之前的队列是空的。 该算法添加`5`三次并每次删除所有克隆。 由于没有人留下来，因此没有增加最后一分钟的时间。 

对于没有到达的情况：```
Input
2 10
0 0
```在整个模拟过程中队列保持为零。 答案仍然为零，因为不存在需要计算时间的克隆。 

对于服务限制小于到达的情况：```
Input
3 2
5 0 0
```第一分钟后，剩下三个克隆体。 第二分钟和第三分钟分别在服务前对现有队列进行计数。 结束后，一个克隆留下来并贡献最后一分钟。 该算法自然地处理这个问题，因为它总是在应用服务之前计算当前队列。
