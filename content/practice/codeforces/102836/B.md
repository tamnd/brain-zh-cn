 ## 解决方案
 ## 问题理解

 我们有三个固定容量的储罐。 当前每个罐包含一定量的液体，我们希望达到最终的情况，即三个量与所需值匹配，但所需值可能属于不同罐，因为罐顺序并不重要。 

移动包括选择源坦克和目标坦克。 液体从源头倒入目的地，直到发生以下两个事件之一：源头变空或目的地完全满。 任务是找到所需的最小浇注次数，或者报告无法达到目标配置。 

容量和数量可以大到$10^6$，因此模拟每种可能的金额组合是不可能的。 对所有三元组的直接搜索最多可达$(n_1+1)(n_2+1)(n_3+1)$州。 当容量接近最大时，这大约是$10^{18}$状态，这远远超出了任何合理的记忆或时间限制。 

关键的限制是只有三辆坦克。 尽管理论状态空间巨大，但可达状态的结构要小得多。 任何倾倒后，所涉及的两个水箱中至少有一个变空或满。 这意味着在第一次移动之后，每个可到达的状态都位于六个“边界”表面之一上，其中一个坐标固定为 0 或其容量。 这些表面中的每一个仅包含线性数量的有用状态，因为液体总量是恒定的。 

在某些情况下，粗心的实施仍然可能会失败。 如果初始状态已经是答案，则结果必定是零步。```
Input:
5 7 9
1 3 4
4 1 3
```输出是：```
0
```仅在执行移动后检查新生成的状态的 BFS 会错过这一点。 

另一个陷阱是目标坦克顺序无关。 例如：```
Input:
10 5 3
7 1 2
1 3 6
```总量为 10，因此目标本身是不可能的，因为请求的数量总和为 10，但请求的一个罐体数量超过了所有可能的匹配？ 正确的实现必须与目标值的所有排列进行比较，而不仅仅是检查`(b1, b2, b3)`按原来的顺序。 

第三种边缘情况是，由于目标已满或源已为空，因此浇筑不会发生任何变化。```
Input:
5 5 5
5 0 0
5 0 0
```答案是：```
0
```错误地生成这些转换可能会添加虚假状态或永远循环。 

## 方法

 自然的第一次尝试是对所有可能的储罐填充进行广度优先搜索。 状态是一个三元组`(x, y, z)`描述每个水箱中的当前数量。 从一个状态开始，我们尝试了六种可能的浇注方向。 BFS 是正确的，因为每次转换只花费一次移动，所以当我们第一次访问一个状态时，我们发现了到达该状态的最短序列。 

问题在于州的数量。 由于容量为 100 万升，不可能存储所有可能的三元组。 蛮力搜索将许多不可能或不必要的状态视为同样重要。 

有用的观察来自于倾倒的机制。 假设我们从罐 A 倒入罐 B。只有当 A 达到零或 B 达到其容量时，操作才会停止。 因此，移动后的每个状态至少有一个处于边界值的坦克。 搜索空间不是一个完整的三维盒子。 它是几个二维表面的并集，并且由于总液体量永远不会改变，因此每个表面仅包含线性数量的状态。 

蛮力方法之所以有效，是因为它精确地模拟了过程，但失败了，因为它忽略了浇注规则创建的结构。 通过将 BFS 与边界属性一起使用，我们只访问可达状态，并且访问状态的数量保持足够小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n1 · n2 · n3) | O(n1 · n2 · n3) | O(n1 · n2 · n3) | O(n1 · n2 · n3) | 太慢了|
 | 可达边界态上的最优 BFS | O(n1 + n2 + n3) | O(n1 + n2 + n3) | O(n1 + n2 + n3) | O(n1 + n2 + n3) | 已接受 |

 ## 算法演练

 1. 读取容量、初始量和目标量。 由于目标顺序并不重要，因此通过稍后检查排列来隐式存储三种可能的目标排列。 
2. 在启动 BFS 之前，检查初始状态是否已与目标排列之一匹配。 如果是，则答案为零，因为不需要浇注。 
3. 从初始状态启动BFS。 将每个访问过的状态存储为三倍数量。 队列始终包含按到达它们所需的移动次数的非递减顺序排列的状态。 
4. 对于每种状态，尝试从每个罐中倒入其他两个罐中。 用于从罐中倒出`i`到坦克`j`，将转移量计算为可用液体中较小的一个`i`和可用空间`j`。 
5. 将每个新的结果状态插入 BFS 队列。 由此产生的状态足以描述未来，因为该过程仅取决于当前数量，而不取决于历史。 
6. 当状态与目标量的任意排列匹配时，返回其 BFS 距离。 如果队列变空，则没有任何倾倒序列可以到达目标，因此返回`-1`。 

这种搜索保持高效的原因是由转换规则创建的不变量。 除第一个州外，每个州都至少有一个空罐或满罐。 BFS 永远不需要探索这个可达边界之外的状态，因为没有有效的移动可以创建它们。 

## 为什么它有效

 每个可能的浇注序列都对应于状态图中的一条路径。 BFS 按照路径长度的顺序探索该图，因此第一次到达目标状态时，移动次数最少。 

唯一关心的是缩小的状态空间是否会失去有效答案。 事实并非如此，因为该算法不会人为地删除转换。 它从每一个被发现的状态产生每一个合法的倾注。 边界属性仅解释了为什么发现的状态数量保持可控。 由于每个可能的路径仍然在 BFS 图中表示，因此答案仍然是正确的。 

## Python 解决方案```python
import sys
from collections import deque
from itertools import permutations

input = sys.stdin.readline

def solve():
    n = list(map(int, input().split()))
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    targets = set(permutations(b))

    start = tuple(a)
    if start in targets:
        print(0)
        return

    q = deque([start])
    dist = {start: 0}

    while q:
        state = q.popleft()
        d = dist[state]

        for i in range(3):
            if state[i] == 0:
                continue
            for j in range(3):
                if i == j or state[j] == n[j]:
                    continue

                nxt = list(state)
                amount = min(nxt[i], n[j] - nxt[j])
                nxt[i] -= amount
                nxt[j] += amount
                nxt = tuple(nxt)

                if nxt in dist:
                    continue

                if nxt in targets:
                    print(d + 1)
                    return

                dist[nxt] = d + 1
                q.append(nxt)

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先构建所有有效目标状态的集合。 这解决了物理坦克顺序无关紧要的事实。 可能的排列数量只有六种，因此该检查是常数时间。 

BFS 使用字典而不是单独的距离数组，因为状态是稀疏的。 该字典存储是否访问过某个状态以及需要多少步才能到达该状态。 

转换计算是最重要的实现细节。 移动的量受两个值限制：源中可用的液体和目的地的剩余容量。 使用这两个值中的最小值可以精确地模拟问题的停止规则。 

代码在生成新状态后立即检查目标。 初始状态是单独检查的，因为它永远不会进入转换循环。 

## 工作示例

 考虑：```
10 5 3
7 1 2
3 3 4
```总量为10，目标可排列为`(3, 3, 4)`。 

| 步骤| 当前状态 | 移动| 新状态| 距离 |
 | --- | --- | --- | --- | --- |
 | 0 | (7, 1, 2) | 将罐 1 倒入罐 2 | (3, 5, 2) | 1 |
 | 1 | (3, 5, 2) | 将罐 2 倒入罐 3 | (3, 4, 3) | 2 |

 国家`(3, 4, 3)`是目标的排列，因此答案是 2。此示例表明该算法不要求目标值出现在原始坦克顺序中。 

另一个例子：```
8 5 4
8 0 0
4 4 0
```| 步骤| 当前状态 | 移动| 新状态| 距离 |

 第二个状态已包含目标数量作为排列，因此最小操作数为 2。 

这些痕迹显示了主要的不变量：每次倾倒后，至少有一个水箱是空的或满的。

 ## 边缘情况

 当初始状态已经与目标匹配时，BFS 必须在采取任何行动之前停止。 例如：```
5 5 5
5 0 0
5 0 0
```起始元组已经是目标排列之一，因此算法立即返回零。 

当目标值可以放入不同的罐中时，仅检查原始顺序会给出错误的答案。 例如：```
10 5 3
7 1 2
4 3 3
```目标可以表示为`(3, 3, 4)`，因此该算法接受任意位置具有这三个值的状态。 

当水箱已空或已满时，某些倾倒无效。 例如：```
5 5 5
5 0 0
0 5 0
```尝试从空的第二个水箱中倒入或倒入已经满的第一个水箱中会产生假动作。 转换代码在计算下一个状态之前拒绝这些情况。 

BFS 处理所有这些情况，因为它将状态视为系统的完整描述，仅生成物理上有效的浇注，并检查所有可能的最终安排。
