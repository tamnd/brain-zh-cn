 ## 解决方案
 # 问题理解

 任务是关于一个由小写英文字母组成的字符串。 我们可以从中删除字符，但是删除位置的数量不能超过给定的限制。 目标不是使字符串变短，而是使仍然出现的不同字母的数量尽可能少。 我们必须打印剩余字母的最少数量以及一个可能包含那么多不同字母的子序列。 

输入包含原始字符串和允许的最大删除次数。 输出是可以存活的不同字母的最小计数，后跟通过从原始顺序中删除字符而获得的任何结果字符串。 

重要的限制是字母表只有 26 个可能的字母，即使字符串本身可能很大。 大约 100000 的字符串长度排除了尝试多种可能的删除组合或为每个选择重建答案的可能性。 我们需要一种在线性时间内处理字符串的方法，因为 O(n) 或 O(n + 字母表大小) 左右的算法很容易安全，而涉及字母子集或重复模拟的方法会增长得太快。 

一些边缘情况可能会破坏粗心的实施。 如果可以删除所有字符，则答案必须包含零个不同的字母。 例如：```
Input:
abc
5

Output:
0
```始终保留至少一个字符的解决方案在这里会失败，因为删除限制大于字符串长度。 

另一种情况是某个字母出现多次且无法完全删除。 例如：```
Input:
aaaaa
4

Output:
1
aaaaa
```这封信`a`完全删除需要五次删除，所以它必须保留。 删除四个出现的位置无助于减少不同字母的数量。 

最后一个常见的错误是删除任意字母而不是最便宜的字母：```
Input:
aabbbc
2

Output:
2
aabbb
```去除`c`使用一次删除和移除`a`使用两次删除。 最好的选择是删除`c`首先是因为它以最低的成本减少了不同字母的数量。 删除一个`b`相反，我们会在不减少答案的情况下进行删除。 

## 方法

 直接的暴力方法会考虑剩下哪些字母。 由于有 26 个可能的字母，因此可以想象尝试每个字母子集，检查是否可以在允许的限制内删除所有其他字母。 这是正确的，因为每个可能的最终不同字母集都会被检查。 然而，子集的数量是 2^26，在检查字符串之前大约有 6700 万种可能性。 这远远超出了与字符串处理结合时的合理范围。 

暴力破解的想法之所以有效，是因为唯一重要的是哪些完整的字母组消失了。 它失败了，因为它探索了太多可能的群体。 关键的观察是每个字母都是独立贡献的。 要从最终字符串中删除一个字母，我们必须准确地花费它的删除频率。 由于目标是删除尽可能多的不同字母，因此我们应该首先删除频率最小的字母。 

对 26 个字母频率进行排序后，在剩余删除预算允许的情况下，我们可以重复删除整个字母。 无法删除的字母保留在答案中。 通过再次扫描字符串并仅保留幸存的字母，可以保留字符的原始顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^26 * n) | O(2^26 * n) | O(26) | 太慢了 |
 | 最佳| O(n + 26 log 26) | O(n + 26 log 26) | O(26) | 已接受 |

 ## 算法演练

 1. 计算每个小写字母在字符串中出现的次数。 频率告诉我们完全删除该字母所需的确切删除成本。 
2. 如果删除限制至少为字符串长度，则删除每个字符。 最终字符串为空，不同字母的数量为零。 
3. 按出现频率从小到大对字母进行排序。 频率越小意味着我们可以更便宜地消除一整个不同的字母。 
4. 按此顺序访问字母。 如果当前信件的频率可以使用剩余的删除来支付，则通过从预算中减去其频率来删除它。 否则，将其保留在最终集中。 这种贪婪的选择是正确的，因为每个删除的字母都会使不同字母的数量恰好减少一次，因此应始终首先进行更便宜的删除。 
5. 通过扫描原始字符串并仅保留未删除字母的字符来构建结果字符串。 这保留了所需的子序列属性。 

为什么有效：从答案中消失的每个字母都必须删除所有出现的字母。 删除一个字母的成本与其他所有字母无关，并且等于其出现频率。 贪婪过程首先选择最便宜的可删除字母，因此在停止后，如果不花费比可用的删除更多的删除次数，则无法删除剩余的字母。 任何其他删除更昂贵的字母同时留下更便宜的可移动字母的策略都可以通过交换这些选择来改进，因此贪婪的结果具有最小可能数量的不同字母。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    k = int(input())

    if k >= len(s):
        print(0)
        print()
        return

    freq = [0] * 26
    for c in s:
        freq[ord(c) - ord('a')] += 1

    removed = [False] * 26

    letters = sorted(range(26), key=lambda x: freq[x])

    for x in letters:
        if freq[x] <= k:
            k -= freq[x]
            removed[x] = True
        else:
            break

    ans = []
    for c in s:
        if not removed[ord(c) - ord('a')]:
            ans.append(c)

    print(len(set(ans)))
    print(''.join(ans))

if __name__ == "__main__":
    solve()
```第一部分处理每个字符都可以消失的特殊情况。 当删除预算足够大时，这可以避免在结果中留下不必要的字符。 

频率数组的每个字母都有一个位置，因此计数需要遍历字符串一次。 仅对 26 个元素进行排序实际上是常数时间。 

贪心循环标记了可以完全删除的字母。 这`removed`数组将这个决定与频率分开存储，因为第二次扫描需要知道要保留哪些字符。 

最终扫描按原始顺序重建答案。 它不会删除单个出现的剩余字母，因为部分删除不会改变不同字母的数量，并且问题仅要求不同字母的最小数量。

 ## 边缘情况

 对于删除限制大于字符串的情况：```
abc
5
```算法检查`k >= len(s)`立即并返回零。 如果没有这个检查，后面的贪婪步骤可能会留下一个字母，因为它只考虑在迭代频率时删除整个组。 

对于重复的单个字母：```
aaaaa
4
```频率数组包含`a = 5`。 贪心循环比较移除的成本`a`并拒绝拆除。 生成的字符串保持不变并具有一个不同的字母。 

对于竞争性删除选择：```
aabbbc
2
```频率是`a = 2`,`b = 3`， 和`c = 1`。 该算法去除了`c`首先，留下一个删除。 它无法删除`a`因为剩余预算太少，所以最后的不同字母是`a`和`b`。 答案包含尽可能少的不同字母，因为可用的删除被花费在最便宜的完全删除上。
