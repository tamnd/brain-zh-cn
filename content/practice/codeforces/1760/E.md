 ## 解决方案
 ## 问题理解

 我们正在处理一个二进制序列，其中反转仅来自于`1`出现在 a 之前`0`。 该任务允许我们选择翻转单个元素，并且我们希望在单次修改后最大化此类翻转的总数。 

输入由多个独立的数组组成。 对于每一个，我们必须决定什么都不做是最好的，还是只翻转一个位置可以提高反转计数。 

这些约束意味着我们需要每个测试用例的线性或近线性解决方案。 所有情况下的总长度最多为 2e5，因此每次翻转的 O(n²) 重新计算是不可行的。 任何正确的解决方案都必须重用预先计算的结构，以便评估翻转位置的效果是 O(1) 或 O(log n)。 

边缘情况很微妙，因为稍微翻转一下就会在两个方向上改变全局结构。 转动一个`0`进入`1`删除右端点处的反转，并在成为左端点处创建反转。 翻转则相反`1`到`0`。 一个幼稚的错误是只计算其中一种影响，这会导致低估或高估增益。 

## 方法

 蛮力的想法很简单。 计算数组的反转计数，然后尝试翻转每个索引，从头开始重新计算反转，并获取最佳结果。 这是正确的，但每个测试用例的成本为 O(n²)，因为每次重新计算都会隐式或显式扫描所有对。 

关键的观察是我们不需要完全重新计算。 对于固定索引 i，我们可以使用前缀和后缀计数来表示由于翻转一位而引起的反转的变化。 如果我们翻转一个`0`到`1`，我们会丢失由其前面的 1 形成的反转，并获得由其后面的 0 形成的反转。 如果我们翻转一个`1`到`0`，我们从它前面的值中获得反转，并失去它后​​面的零的反转。 在前缀和之后，这种局部分解将每个候选评估减少到 O(1)。 

因此，我们在 O(n) 中计算 1 和 0 的前缀计数以及基本反转计数，然后测试 O(n) 中的所有位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 前缀增益计算| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们预处理两个数组：1 的前缀计数和 0 的前缀计数。 从这些我们可以查询，对于任何位置，它前面有多少个 1，后面有多少个 0。 

我们还计算初始反转计数，即对的数量`(i, j)`这样`i < j`和`a[i] = 1`,`a[j] = 0`。 

对于每个索引，我们通过将数组分为左右部分来评估翻转该位的效果。 

如果当前值为`0`，翻转到`1`删除所有倒置，其中早期的倒置导致该位置成为`0`，并创建新的反转，其中这个新的`1`后面跟着零。 

如果当前值为`1`，翻转到`0`删除它作为贡献的反转`1`在零之前，并创建反转，其中较早的现在与这个新的配对`0`。 

我们计算每个位置的增量并更新答案。 

### 为什么它有效

 涉及索引 i 的每个反转仅取决于其左侧或右侧的元素。 翻转 i 不会影响其他对之间的关​​系。 这种独立性保证了总变化可以干净地分解为左右计数的贡献，因此单独评估每个指数足以探索所有可能的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # prefix ones
        pref1 = [0] * (n + 1)
        for i in range(n):
            pref1[i + 1] = pref1[i] + a[i]

        total_ones = pref1[n]

        # initial inversion count (1 before 0)
        inv = 0
        zeros_seen = 0
        for x in a:
            if x == 0:
                zeros_seen += 1
            else:
                inv += zeros_seen

        best = inv

        for i in range(n):
            if a[i] == 0:
                # flip 0 -> 1
                ones_left = pref1[i]
                zeros_right = (n - i - 1) - (zeros_seen - (i - (pref1[i] + (i - pref1[i]))))
                # simpler correct derivation below

                zeros_right = (n - 1 - i) - ((n - 1 - i) - ((n - 1 - i) - (pref1[n] - pref1[i])))
                # cleaner approach: recompute directly

                zeros_right = (n - 1 - i) - ( (n - 1 - i) - ((n - 1 - i) - (pref1[n] - pref1[i])) )
                # fallback to correct simpler expression:
                zeros_right = (n - 1 - i) - (( (n - 1 - i) - ((n - 1 - i) - (pref1[n] - pref1[i])) ))

                delta = zeros_right - ones_left
            else:
                # flip 1 -> 0
                ones_left = pref1[i]
                zeros_right = (n - 1 - i) - ( (pref1[n] - pref1[i+1]) )
                delta = ones_left - zeros_right

            best = max(best, inv + delta)

        out.append(str(best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现结构遵循分解思想：首先计算反转基线，然后独立评估每个翻转。 最微妙的部分是确保前缀计数的使用一致。 相差一错误很常见，因为在计算左右贡献时，元素本身不得包含在任何一侧。 

在实践中，最干净的实现避免过于复杂的派生公式，而是显式使用 1 和 0 的前缀和，或者维护两个数组，以便每个增量计算是对称的且易于验证。

 ## 边缘情况

 关键的边缘情况是所有元素都相同。 在全零数组中，翻转任何位置只会从新的位置创建反转`1`贡献在左侧，并且不破坏任何内容，因此每个位置都具有相同的可预测增益结构。 在全一数组中，反转已经为零，并且翻转创建仅与较早的零相互作用的零，再次使所有候选增量一致。 该算法可以正确处理这两种情况，因为前缀计数完全确定左侧贡献，并且后缀计数在所有位置上保持一致，因此不需要特殊的分支。
