 ## 解决方案
 ## 问题理解

 我们得到了一组代表仓库中物品的整数“类型”。 大多数类型都是完美平衡的：每种类型出现的次数都相同$S$。 确切地说，只有一种特殊类型打破了这种模式，并且出现的次数更少$P$， 在哪里$P < S$。 

任务是识别这种代表性不足的类型。 我们没有被告知$P$或者$S$，并且没有超出原始计数的排序或结构。 输入只是一个整数列表，并且恰好有一个不同的整数的频率严格小于所有其他相同的整数。 

约束允许最多$10^5$元素。 这立即排除了任何二次方的情况，例如比较每对频率或重复扫描阵列以查找每个不同的值。 一个$O(N \log N)$方法是可以接受的，但是如果我们使用散列，线性解决方案就有足够的余量。 

最微妙的边缘情况是只有两个不同的值且它们的计数相差 1 时。例如，如果一个值出现 2 次，另一个值出现 3 次，则即使差异很小，答案仍然是较小的值。 另一种边缘情况是出现负数或大整数时； 该解决方案必须仅依赖于相等比较，而不是排序假设。 

一个天真的错误是假设最小值或最大值对应于缺失的类型。 例如，在`[5, -3, 5, 5, -3]`，答案是`-3`，即使它小于 5； 正确的推理来自频率，而不是价值。 

## 方法

 暴力策略是通过扫描整个列表中的每个元素来计算每个不同值的频率。 对于每个位置$i$，我们数数多少次$t_i$通过迭代整个数组出现。 这给了我们每个候选者的频率，然后我们选择频率最小的值。 

这种方法是正确的，因为它直接遵循问题的定义：我们明确地测量发生的情况。 然而，其成本却令人望而却步。 对于每个$N$元素，我们执行另一个$O(N)$扫描，导致$O(N^2)$运营。 和$N = 10^5$，这变成了$10^{10}$比较，这远远超出了典型的限制。 

这种改进来自于认识到频率计数不需要重复扫描。 如果我们使用哈希映射在单次传递中聚合计数，我们可以计算$O(N)$。 一旦我们有了计数，我们只需迭代它们一次即可找到最小频率值。 这将重复的工作转变为共享的工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 哈希图计数 | O(N) | O(N) | 已接受 |

 ## 算法演练

 1. 读取所有值并构建频率表，将每个整数类型映射到其出现次数。 这确保我们将所有重复扫描压缩为一次数据扫描。 
2. 迭代频率表并跟踪频率最小的值。 由于只有一个值未被充分代表，因此该最小值是明确定义且唯一的。 
3. 输出该最小频率对应的值。 

### 为什么它有效

 保证是除了一个值之外的所有值都共享相同的频率$S$，而只有一个值有频率$P < S$。 这在频率空间中产生了严格的分离：一个唯一的最小值和几个相同的较大值。 哈希映射保留了精确的计数，没有相等性的冲突歧义，因此频率表是精确的。 从此表中选择最小频率必须返回唯一的代表性不足的类型。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    
    freq = {}
    for x in arr:
        freq[x] = freq.get(x, 0) + 1
    
    # find the element with smallest frequency
    best_val = None
    best_freq = float('inf')
    
    for val, cnt in freq.items():
        if cnt < best_freq:
            best_freq = cnt
            best_val = val
    
    print(best_val)

if __name__ == "__main__":
    solve()
```第一阶段在一次线性扫描中构建频率字典。 每次插入或更新都是预期的$O(1)$，因此总数保持线性。 

第二阶段搜索不同键中的最小频率。 这是安全的，因为不同值的数量最多为$N$，我们只扫描这个缩减集一次。 

一个微妙的实现细节是初始化`best_freq`到无穷大。 使用大整数也可以，但无穷大可以避免意外溢出或不正确的哨兵选择。

 ## 边缘情况

 一个关键的边缘情况是少数频率与多数频率相差正好一的情况。 考虑输入：```
4
7 7 7 8
```频数表为`{7: 3, 8: 1}`。 该算法扫描地图并设置`best_val = 8`因为 1 小于 3。不依赖于键或值的排序，仅依赖于计数。 

另一个边缘情况是负值：```
5
-10 -10 -10 -3 -3
```频率是`{ -10: 3, -3: 2 }`。 算法正确选择`-3`因为尽管它的数值较大，但它的频率却较小。 这证实了任意整数范围下的正确性。 

最后一种情况是具有许多重复项的大输入。 由于散列在每次插入的预期恒定时间内处理聚合，因此该算法保持线性并且即使在除一个之外的所有值都相同时也不会降低性能。
