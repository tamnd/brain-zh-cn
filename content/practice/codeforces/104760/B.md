 ## 解决方案
 ## 问题理解

 我们有一个小型无向飞行网络，其中机场是节点，航班是边缘。 旅客从机场 1 出发，并且可以恰好乘坐 K 航班。 每个航班都沿着无向边缘移动到邻近的机场。 旅行者可以多次访问机场并重复使用边缘。 唯一的要求是，在恰好 K 次移动之后，旅行者必须最终回到机场 1。我们需要计算长度为 K+1（包括起点）的访问机场的不同序列有多少个满足此条件。 

该结构从根本上讲是关于计算无向图中固定长度的行走，具有固定的起始和结束顶点。 

约束的图形尺寸非常小，但步行长度适中。 当 N 达到 100，K 达到 60 时，任何显式探索所有路径的方法都会爆炸，因为分支因子可能很大，并且长度为 K 的行走数量呈指数增长。 即使是像 N * deg^K 这样的粗略上限，除了极小的 K 之外，暴力破解也是不可能的。 

打破天真的思维的关键边缘情况是存在循环和多种返回 1 的方法。例如，在 K = 2 的三角图中，返回 1 需要出去并立即返回，但可能存在不同的中间节点，如果错误地认为“距离”或最短路径比步行更重要，则可能会创建多个有效路径，这些路径很容易被低估。 

另一个微妙的边缘情况是奇偶校验。 如果图结构使得不可能在恰好 K 个步骤中返回到 1（例如，一棵树和来自二分结构的奇数 K 个约束），则即使存在 K-1 或 K+1 的许多路径，答案也必须正确地变为 0。 

## 方法

 一种直接的方法是递归地模拟从节点 1 开始的所有可能的 K 次移动序列。在每一步，我们分支到所有邻居。 经过 K 步后，我们检查是否回到节点 1。这在概念上是正确的，因为它只枚举一次有效的遍历。 然而，递归状态的数量就像图中长度为 K 的行走数量一样增长，在密集情况下大约为 (N-1)^K。 当K达到60时，这远远超出了可行的计算范围。 

问题的结构表明了一个动态规划的步骤。 我们不是枚举完整路径，而是跟踪 t 个步骤后我们可以到达每个节点的有多少种方式。 这是有效的，因为下一个位置仅取决于当前位置，而不是完整的历史记录。 这是一个经典的“依靠图表行走”DP。 

我们将 dp[t][v] 定义为从节点 1 开始经过 t 次飞行后到达顶点 v 的方式数量。转换是在时间 t 到达节点 u 的每条方式都会在时间 t+1 时对所有邻居 v 做出贡献。 这将指数分支压缩为每步 N 个状态，使过程在边缘上的 K 个转换中呈线性。 

问题简化为迭代此转换 K 次并读取 dp[K][1]。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力DFS枚举| O(N^K) | O(N^K) | O(K) 递归 | 太慢了|
 | DP 的步骤和节点 | O(K * M) | O(N) | 已接受 |

 ## 算法演练

1. 为图构建邻接表，以便邻居查询速度更快。 这是必要的，因为每个 DP 转换需要有效地迭代边缘，而不是扫描所有节点对。 
2. 初始化一个DP数组，其中dp[v]表示当前步数后到达节点v的路数。 设置 dp[1] = 1，因为我们从机场 1 开始，有一条有效的空路径。 
3. 准确重复以下过程 K 次，每次代表一次飞行。 
4. 创建一个用零填充的新数组 ndp。 这种分离很重要，因为更新不得干扰当前步骤的值。 
5. 对于每个节点 u，通过将 dp[u] 添加到 ndp[v]，将 dp[u] 分配给所有邻居 v。 每一次相加都表示将所有以 u 为终点的步态进一步扩展为以 v 为终点的步态。 
6. 处理完所有边后，将 dp 替换为 ndp。 现在 dp 表示下一步之后到达每个节点的方式数。 
7. 完成 K 次迭代后，输出 dp[1]，它对从节点 1 开始和结束的所有长度为 K 的路径进行计数。 

### 为什么它有效

 在每一步 t，dp[v] 精确计算从节点 1 到 v 的所有长度为 t 的行走。转换保留了此属性，因为在 v 处结束的每条长度为 t+1 的行走都必须来自 t 步之后的某个邻居 u，并且通过邻接扩展，所有此类贡献都被精确计数一次。 不会错过任何步行，因为每个可能的下一个边缘都被探索过，并且不会重复计算任何步行，因为每个先前的状态都是独立贡献的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M, K = map(int, input().split())
    adj = [[] for _ in range(N + 1)]

    for _ in range(M):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    dp = [0] * (N + 1)
    dp[1] = 1

    for _ in range(K):
        ndp = [0] * (N + 1)
        for u in range(1, N + 1):
            if dp[u] == 0:
                continue
            for v in adj[u]:
                ndp[v] += dp[u]
        dp = ndp

    print(dp[1])

if __name__ == "__main__":
    solve()
```该实现直接镜像 DP 定义。 邻接列表存储无向图，因此每条边都会遍历两次，每次从每个端点遍历一次，这与双向飞行规则一致。 

每次迭代都会重置 dp 数组，以确保我们只使用上一步中的状态。 跳过零条目可以避免不必要的内部循环工作，但对于正确性而言并不是严格要求的。 最终答案是在恰好 K 次转换后从 dp[1] 中获取的。

 ## 边缘情况

 一种重要的情况是图是二分图并且 K 是奇数。 在这种情况下，从节点 1 开始的任何行走都必须在奇数步后在二分的另一侧结束，因此返回到节点 1 是不可能的。 DP 自然地捕获了这一点，因为在每个步骤之后，值在分区之间交替，并且只要奇偶校验与结构不匹配，dp[1] 就会变为零。 

另一种情况是节点 1 的度数为 1 并且图形是一条简单的线。 对于 K = 2，步行必须出去并返回，恰好产生一种方式。 当 K = 3 时，这又变得不可能了。 DP 正确地反映了这种振荡，因为所有质量都沿着单一路径重复流动并且不能分支。 

第三种情况是完全连接的小图，其中可以进行多次重访。 该算法无需修改即可处理这些问题，因为它不假设路径的唯一性，仅计算转换上的累积，确保每个不同的序列都单独计算。
