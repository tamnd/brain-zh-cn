 ## 解决方案
 ## 问题理解

 我们得到了沿数轴排列的区间集合。 每个间隔代表一盏灯，照亮一段道路，从其起始坐标到结束坐标。 多个灯可能重叠，部分道路可能被多个间隔覆盖或根本没有间隔。 

任务是确定至少一盏灯照亮的道路的总长度。 换句话说，我们需要计算所有给定间隔的并集长度。 

约束允许最多 10,000 个间隔，坐标范围从负十亿到正十亿。 这个尺寸立即排除了任何试图逐点检查道路的方法。 对坐标范围进行简单的离散化需要迭代多达 20 亿个位置，这远远超出了可行的限制。 即使在时间和内存上明确存储每个可能的坐标也是不可能的。 

重叠处理会出现一个更微妙的问题。 例如，如果间隔是嵌套的或严重重叠的，则简单地对它们的长度求和就会超出共享区域的计数。 考虑间隔`[0, 10]`和`[5, 15]`。 对长度求和得出 10 + 10 = 20，但正确的并集是`[0, 15]`，其长度为 15。任何正确的解决方案都必须明确避免重复计算重叠段。 

通常破坏朴素实现的边缘情况包括完全不相交的间隔、完全嵌套的间隔以及仅在端点处接触的间隔。 例如，`[0, 5]`和`[5, 10]`如果端点被认为是连续覆盖，则总长度应为 10，这是该问题的标准解释。 天真的“仅在重叠严格时才合并”的实现可能会错误地将触摸间隔视为单独的。 

## 方法

 强力解释是模拟细粒度数轴上的覆盖范围。 人们可以想象标记任意区间覆盖的每个整数点，然后计算标记了多少个。 虽然概念上很简单，但这会立即失败，因为坐标范围从 -10^9 到 10^9。 即使我们压缩坐标，逐点标记或扫描仍然太慢，因为每个间隔可能非常大。 

另一个残酷的想法是比较每对间隔并重复合并重叠直到稳定。 在最坏的情况下，这会导致 O(N^2) 过程，因为每个合并步骤可能需要扫描和更新许多间隔，并且可能需要重复传递。 

关键的观察是我们实际上不需要知道点级覆盖范围。 我们只需要知道覆盖范围从“未覆盖”到“覆盖”的变化，反之亦然。 一旦间隔按起始坐标排序，重叠就会变得结构化：当我们按顺序处理间隔时，我们只需要维护迄今为止看到的最远的右端点。 任何新的间隔要么扩展当前覆盖的区域，要么开始一个新的不相交区域。 

这将问题简化为对排序间隔的经典扫描，维护当前的活动段并在出现间隙时累积其贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力打标 | O(R) 其中 R 是坐标范围 | O(R)| 不可能|
 | 成对合并 | O(N^2) | O(N^2) | O(N) | 太慢了|
 | 排序+扫 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 1. 读取所有区间并按起始坐标对它们进行排序。 排序可确保当我们从左向右移动时，我们永远不会错误地重新访问之前发现的间隙。 
2. 使用第一个间隔初始化跑步段。 该段代表我们正在构建的重叠间隔的当前联合。 
3. 按排序顺序一一迭代剩余的区间。 
4. 对于每个间隔，将其开始与当前段的结束进行比较。 如果起点小于或等于当前终点，则间隔重叠或接触，因此我们将当前段的终点延伸到两端的最大值。 这可以保持覆盖范围的连续性，而不会重复计算。 
5. 如果开始大于当前结束，则当前覆盖的段与新区间之间存在间隙。 在这种情况下，将当前段的长度添加到答案中，然后从当前间隔开始一个新段。 
6. 处理完所有区间后，将最终的活动段添加到答案中。 

关键思想是，只有当我们确定未来的时间间隔无法延长该段时，我们才会最终确定该段，而这正是在我们检测到间隙时发生的。 

### 为什么它有效

 在每一步，算法都保持一个不变量：当前段准确地表示迄今为止处理的所有间隔的并集，这些间隔彼此相交或通过重叠形成连接链。 由于间隔是按开始的升序处理的，因此任何未来的间隔只能扩展此段或严格在其之后开始。 因此，当我们遇到从当前结束之后开始的新区间时，当前段已完全确定并且不会受到任何未来数据的影响，因此可以安全地将其长度添加到最终结果中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    intervals = []
    for _ in range(n):
        a, b = map(int, input().split())
        intervals.append((a, b))

    intervals.sort()

    cur_l, cur_r = intervals[0]
    total = 0

    for l, r in intervals[1:]:
        if l <= cur_r:
            if r > cur_r:
                cur_r = r
        else:
            total += cur_r - cur_l
            cur_l, cur_r = l, r

    total += cur_r - cur_l
    print(total)

if __name__ == "__main__":
    solve()
```代码首先读取所有间隔并对它们进行排序，这对于确保重叠连续出现至关重要。 变量`cur_l`和`cur_r`跟踪当前活动的合并段。 当新的区间重叠时，只有右边界可能会扩展，这就是我们取最大值的原因。 当发现间隙时，当前段长度被最终确定并添加到`total`，然后我们重新启动该段。 

一个微妙的细节是我们在重叠处理期间从不添加部分贡献。 这完全避免了重复计算，因为每个段在关闭时只计算一次。

 ## 边缘情况

 对于不相交的区间，例如`[0,1]`和`[3,4]`，算法处理第一个区间，然后检测`3 > 1`并在开始新的部分之前完成第一个部分。 这确保了不会在间隙之间发生人为合并。 

对于嵌套间隔，例如`[0,10]`,`[2,5]`,`[3,7]`，运行结束只会增加到 10，并且不会发生过早关闭，因为所有启动都在当前范围内。 不变式是`cur_r`是所有重叠区间的最大右端点，保证正确性。 

对于触摸间隔，例如`[0,5]`和`[5,10]`，条件`l <= cur_r`将它们视为已连接，因此它们合并为`[0,10]`。 这避免了由于连续覆盖问题中的边界分离约定而导致的计数不足。
