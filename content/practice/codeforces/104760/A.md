 ## 解决方案
 ## 问题理解

 我们得到一个线性的壳序列，每个壳都有一个正权重。 贝壳沿着海滩按顺序排列，我们只能取连续的一块。 但是，有一个容量限制：袋子最多可以容纳`K`贝壳，无论其总重量如何。 

任务是选择一个长度不超过的连续段`K`，使得该段内的权重总和最大化。 

输出是一个数字，是所有有效连续段的最大可能总和。 

约束足够大，以至于$O(N^2)$扫描所有子数组是不可行的。 和$N \le 2 \cdot 10^5$，二次方法意味着$4 \cdot 10^{10}$操作，这远远超出了典型的限制。 这立即表明我们需要一种线性或接近线性的方法。 

出现微妙的边缘情况时`K >= N`。 在这种情况下，每个元素都可以被取，所以答案就是整个数组的总和。 始终尝试保持固定窗口大小的简单滑动窗口实现`K`当数组短于时，必须小心不要收缩到有效范围以下`K`。 

另一个潜在的陷阱是假设最佳段总是具有精确的长度`K`。 这不一定是真的，因为如果避免负结构，较短的段可以具有更大的总和，但在这个问题中，所有权重都是正的，因此最好的段将始终使用精确的`K`元素，除非受边界约束。 这个属性使得滑动窗口方法变得干净。 

## 方法

 蛮力方法尝试每一个可能的起始位置并将其扩展到`K`向前迈进，不断积累资金。 对于每个索引`i`，它检查从以下位置开始的所有子数组`i`且长度最多`K`，更新全局最大值。 

这是正确的，因为它显式枚举了每个有效段。 问题在于操作的数量。 对于每个`N`起始点，最多`K`元素可能被处理，导致$O(NK)$时间。 自从`K`可以大到$10^7$，这是完全不可行的。 

问题的结构提出了更好的方法。 我们正在使用固定的最大长度约束来最大化所有连续段的总和。 因为所有权重都是正数，所以扩展窗口总是会增加总和，因此对于任何固定的右端点，以该端点结尾的最佳有效线段是最长的可能线段，直到 length`K`。 这意味着我们最多只需要维护一个大小为的滑动窗口`K`从左到右扫描时，有效跟踪当前金额。 

我们维护当前窗口的运行总和。 当我们向前移动右边界时，我们添加了新元素。 如果窗口超出尺寸`K`，我们删除最左边的元素。 在每一步中，当前总和代表在该位置结束的最佳片段，因此我们更新答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(NK) | O(1) | O(1) | 太慢了|
 | 滑动窗 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化两个指针`l = 0`和一个运行总和`current = 0`，和一个变量`best = 0`。 

这些指针定义了我们正在考虑的当前 shell 窗口。 
2. 迭代`r`从`0`到`N - 1`，将每个位置视为窗口的右端点。 

每一步都通过包含一个额外的外壳来扩展候选片段。 
3. 添加`W[r]`到`current`。 

这会将新的 shell 合并到运行窗口总和中。 
4. 如果窗口大小超过`K`，通过减去从左侧缩小它`W[l]`并递增`l`。 

这确保我们尊重最多的约束`K`贝壳是可以拿的。 如果我们不在这里删除元素，窗口可能会变得任意大并违反问题条件。 
5.调整窗口后，更新`best = max(best, current)`。 

此时，窗口代表结束于的最佳有效段`r`，因为任何较短的前缀只会由于权重的正性而减少总和。 
6.处理完所有位置后，输出`best`。 

### 为什么它有效

 在每个位置`r`，算法维护一个窗口`[l, r]`这是有效的（长度最多`K`) 并且其总和被精确计算。 因为所有权重都是正数，所以任何有效段结束于`r`长度小于当前窗口的总和将更小或相等。 因此，一旦窗口在约束下的长度最大化，它也会最大化该端点的总和。 扫描全部`r`确保考虑每个可能的右边界，因此捕获所有有效段的全局最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = list(map(int, input().split()))
    k = int(input())

    l = 0
    current = 0
    best = 0

    for r in range(n):
        current += w[r]

        if r - l + 1 > k:
            current -= w[l]
            l += 1

        if current > best:
            best = current

    print(best)

if __name__ == "__main__":
    solve()
```该代码在数组上维护一个滑动窗口。 左指针`l`只向前移动，因此每个元素最多添加和删除一次，确保线性复杂度。 条件`r - l + 1 > k`强制执行最大窗口大小约束。 变量`current`始终存储当前有效段的总和，并且`best`跟踪迄今为止看到的最大值。 

一个常见的实施错误是在添加之前检查窗口大小`w[r]`，这可能会导致相差一的错误。 正确的顺序是首先包含该元素，然后根据需要修复窗口。

 ## 边缘情况

 当`K >= N`，窗口永远不会缩小，因为永远不会违反大小约束。 该算法只是将所有元素累加一次，并且`best`成为总和。 

对于像这样的单元素数组`N = 1`，循环运行一次，元素就被添加，并且不会发生收缩。 结果正是该元素，与唯一有效的段匹配。 

在较大值间隔开的数组中，例如`[2, 100, 3, 4, 5, 6, 1]`和`K = 3`，滑动窗口会正确移动以包含适合的最大连续分组。 在每一步中，窗口保持有效，并且在高值簇完全位于窗口内时更新最大值。
