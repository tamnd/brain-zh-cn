 ## 解决方案
 ## 问题理解

 我们得到一个矩形的值网格，其中每个单元格代表可以从该位置收集多少个气泡。 约翰尼最多可以启动一次收割操作四次。 每次激活都会选择整行或整列，选择后，收割机会扫过该行，收集其中的所有值。 如果一个单元格位于多个选定的行中，则其值仍仅收集一次。 

任务是选择最多四行，任意混合行和列，以最大化收集的单元格值的总不同总和。 

关键的困难在于行和列重叠。 如果我们同时选择一行和一列，除非进行更正，否则它们的交叉单元格将被重复计算。 这会在选择之间产生耦合，从而使天真的贪婪选择变得不可靠。 

约束允许最多$N \cdot M \le 10^5$，因此网格可以很大但足够稀疏$O(NM)$预处理。 但是，我们不允许全局尝试行和列的所有子集，因为从最多选择四行的方法数量$10^5$候选人的组合是巨大的。 

一种简单的方法是尝试所有行和列中最多四行的所有组合，每次计算并集值，并取最佳值。 这需要粗略地评估$\binom{N+M}{4}$可能性，即使对于$N+M = 2000$，更不用说$10^5$。 

混合行和列时会出现一个更微妙的问题。 如果我们小心地忽略重叠，我们可能会多算或少算贡献。 例如，选择高值行和高值列可能在本地看起来是最佳的，但它们的交集可能包含极大的值，从而降低了同时采用两者的好处。 

当一个极其有价值的列与许多中等价值的行相交时，就会出现边缘情况。 独立地选择顶行和顶列的天真贪婪选择可能会严重失败，因为重叠占主导地位。 

## 方法

 蛮力的想法很简单：尝试所有行和列中最多四行的每个子集，通过标记覆盖的单元格来计算收集的总值，并取最大值。 这是正确的，因为它直接模拟了该过程。 失败点是选择的数量，它随着选择的数量而增长$O((N+M)^4)$，以及每次评估成本$O(NM)$，导致不可能的运行时间。 

关键的观察结果是，尽管行和列的范围很大，但该解决方案最多只使用四行。 这强烈表明只有一小部分“重要”行和列在最佳解决方案中才重要。 如果一行与另一行相比在总贡献方面非常差，则它不太可能出现在最佳大小 4 选择中，因为任何替换最多会影响每个所选列的四个交叉点，并且不能证明行总和中的巨大赤字是合理的，除非它在其他地方进行补偿。 这使我们能够将注意力限制在行和列总和较高的有界候选行和列集上。 

一旦我们限制在一个小的候选池中，我们就可以对这些候选者中的所有大小最多为四个的子集进行暴力破解。 对于每个子集，我们使用行总和、列总和并减去所选行和列之间的交集来计算其贡献。 

我们评估一个子集$R, C$作为：$$\sum_{i \in R} \text{rowSum}[i] + \sum_{j \in C} \text{colSum}[j] - \sum_{i \in R, j \in C} A_{i,j}$$自从$|R| + |C| \le 4$，每个子集的交叉检查是恒定的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有线路 |$O((N+M)^4 \cdot NM)$|$O(NM)$| 太慢了 |
 | 候选剪枝+子集枚举 |$O(K^4 + NM)$|$O(NM)$| 已接受 |

 ## 算法演练

 1. 计算每行和每列的总和。 

这将网格压缩为行级贡献，因此我们可以评估子集，而无需每次重新计算完整的网格总和。 
2. 选择行和列的一小部分候选行和列，其中行和列的总和最高，通常是前 30 个。 

原因是任何大小最多为 4 的最佳解决方案很可能只涉及高贡献行，并且限制为恒定大小的池使得穷举搜索变得可行。 
3. 将行和列视为单独的类型，但允许它们位于同一子集中。 我们将从这个组合候选池中枚举大小为 0 到 4 的所有子集。 
4. 对于每个子集，将其分成选定的行$R$和选定的列$C$。 

我们根据行总和和列总和计算基本贡献。 
5. 减去重叠贡献。 对于每对$(i, j)$在哪里$i \in R$和$j \in C$, 减去$A_{i,j}$。 

这可以纠正重复计数，因为这些单元格同时包含在行和列中。 
6. 跟踪所有子集的最大值。 

### 为什么它有效

 任何有效的策略都对应于最多选择四行。 在限制到足够丰富的候选池后，每个最优组合都可以通过暴力重建。 由于评估公式与经过重叠校正的选定行和列的并集完全匹配，因此每个子集都会得到正确的评分。 枚举保证我们测试每一种结构上不同的方式，以在最相关的候选者中选择最多四行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    row_sum = [0] * n
    col_sum = [0] * m

    for i in range(n):
        row_sum[i] = sum(a[i])
    for j in range(m):
        col_sum[j] = sum(a[i][j] for i in range(n))

    rows = sorted(range(n), key=lambda i: row_sum[i], reverse=True)[:30]
    cols = sorted(range(m), key=lambda j: col_sum[j], reverse=True)[:30]

    candidates = []
    for i in rows:
        candidates.append(("r", i))
    for j in cols:
        candidates.append(("c", j))

    best = 0
    k = len(candidates)

    from itertools import combinations

    for mask_size in range(1, 5):
        for comb in combinations(range(k), mask_size):
            R = []
            C = []

            val = 0

            for idx in comb:
                t, idd = candidates[idx]
                if t == "r":
                    val += row_sum[idd]
                    R.append(idd)
                else:
                    val += col_sum[idd]
                    C.append(idd)

            for i in R:
                for j in C:
                    val -= a[i][j]

            if val > best:
                best = val

    print(best)

if __name__ == "__main__":
    solve()
```该实现首先将网格压缩为行和列聚合，以便每个候选行具有单个碱基贡献。 然后，枚举步骤探索从减少的池中选取最多四行的所有方法。 校正步骤明确减去所选行和列之间的交集，确保没有单元格被计数两次。 

唯一微妙的部分是候选人限制。 没有它，枚举是不可能的。 有了它，我们将搜索空间减少到恒定大小的组合爆炸。

 ## 边缘情况

 关键的边缘情况是当单个极大值位于行和列的交叉点时。 在这种情况下，同时选择行和列可能看起来很有用，因为两者的总和都很高，但重叠减法会一次性删除该大单元格，这会显着改变最佳子集。 该算法可以正确处理这个问题，因为它显式地减去每个子集评估的每个交集，确保不会出现重复计算。 

另一种边缘情况是最佳解决方案仅使用列或仅使用行。 由于子集包括零行或零列的配置，因此枚举自然包括纯选择，确保在没有特殊大小写的情况下正确评估这些情况。
