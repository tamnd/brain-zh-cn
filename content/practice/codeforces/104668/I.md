 ## 解决方案
 ## 问题理解

 我们正在计算边长为整数的矩形盒子的几何形状。 每个盒子完全由三个正整数决定，但两个描述的不同之处仅在于对边进行重新排序，表示相同的形状，因此我们始终按排序顺序处理边长。 

仅当所有三个边都不同并且盒子的体积（边长的乘积）不超过给定限制时，形状才被视为有效$N$。 对于每个测试用例，我们被要求计算存在多少个不同的有效形状，其体积最多为$N$。 

输入提供高达$10^5$查询，每个查询给出不同的上限$N$，以及每个$N$至多是$10^6$。 这立即排除了通过从头开始枚举所有三元组来独立地为每个查询重新计算答案。 一个天真的$O(N^3)$甚至$O(N^2)$每个测试用例方法都会失败，因为操作总数会爆炸到大约$10^{15}$在最坏的情况下。 

一个更微妙的限制是要求所有方面都是不同的。 计算所有三元组的粗心实现$a \le b \le c$会错误地包含至少两个维度匹配的退化“方脸”框，例如$2 \times 2 \times 3$。 必须完全排除这些。 

典型的失败案例如下所示：如果$N = 12$, 三重$(2,2,3)$有体积$12$，所以一个简单的“排序三元组”枚举会计算它。 但是，它是无效的，因为它包含方形面。 

## 方法

 暴力方法尝试所有三元组$a, b, c$这样$a < b < c$，计算他们的乘积，并检查它是否在限制之内。 这在概念上是正确的，因为它直接遵循定义。 然而，即使在排序限制之后，搜索空间也是巨大的。 甚至将各方最多限制为$10^6$，三元组的数量仍然是$\binom{10^6}{3}$，太大了。 

关键的观察结果是体积约束立即迫使所有相关边长变小。 如果$a < b < c$和$a \cdot b \cdot c \le 10^6$， 然后$a$不能超过 100 左右，因为$100 \cdot 101 \cdot 102$已经有一百万左右了。 一次$a$是固定的，产品约束强烈限制有效$b$，还有一次$a$和$b$是固定的，$c$由整数除法确定。 

这将问题转化为在前两个维度的非常小的有效范围内进行结构化枚举，并直接计数有效的第三个维度。 

我们不是独立地回答每个查询，而是预先计算每个可能的卷存在多少个有效的三元组$10^6$。 每个有效的三元组对所有阈值都有贡献$N$大于或等于其数量，因此我们将贡献累积到按数量索引的频率数组中，然后将其转换为前缀和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(N^3)$每个查询|$O(1)$| 太慢了 |
 | 有界三元组的预计算 |$O(K^2 \log K + Q)$|$O(K)$| 已接受 |

 这里$K = 10^6$并且由于产品的限制，有效的双环范围要小得多。 

## 算法演练

 ### 预计算阶段

 1.修复最大值$K = 10^6$。 创建一个数组`freq[v]`将存储有多少个有效的三元组具有确切的体积$v$。 这将问题从回答阈值查询转变为计算精确的贡献。 
2. 迭代最小边的可能值$a$。 自从$a < b < c$和$a \cdot b \cdot c \le K$， 一次$a$变大，没有有效的三元组剩余。 在实践中，$a$只需要达到100左右即可。 
3. 对于每个$a$, 迭代$b$这样$b > a$。 约束条件$a \cdot b \cdot (b+1) \le K$给出一个自然的停止点$b$，因为即使是最小的有效值$c = b+1$仍必须将产品保持在范围内。 
4. 对于每对$(a, b)$，计算最大可能值$c$作为$c_{\max} = \left\lfloor \frac{K}{a \cdot b} \right\rfloor$。 如果$c_{\max} \le b$，没有有效的选择，因为我们需要严格增加边。 
5. 否则，每个整数$c$在范围内$b+1$到$c_{\max}$形成有效的形状。 对于每个这样的三元组，计算体积$v = a \cdot b \cdot c$并增加`freq[v]`。 
6. 处理完所有三元组后，进行转换`freq`放入前缀和数组中`pref`， 在哪里`pref[x]`给出体积最大的有效形状的数量$x$。 这允许在恒定时间内回答每个查询。 

### 为什么它有效

 每个有效形状恰好对应一个严格递增的三元组$(a, b, c)$。 枚举仅覆盖每个这样的三元组一次，因为$a$和$b$按递增顺序固定，并且$c$仅在上面生成$b$。 体积限制确保循环保持有限且较小。 前缀求和步骤将精确体积计数转换为阈值计数，而不会重复计数或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 10**6

freq = [0] * (MAXV + 1)

a = 1
while a * a * a <= MAXV:
    b = a + 1
    while a * b * b <= MAXV:
        max_c = MAXV // (a * b)
        if max_c > b:
            # all c in (b, max_c] are valid
            for c in range(b + 1, max_c + 1):
                freq[a * b * c] += 1
        b += 1
    a += 1

pref = [0] * (MAXV + 1)
running = 0
for i in range(1, MAXV + 1):
    running += freq[i]
    pref[i] = running

t = int(input())
out = []
for _ in range(t):
    n = int(input())
    out.append(str(pref[n]))

print("\n".join(out))
```该实现依赖于一次预先计算所有有效的三元组。 嵌套循环结束$a$和$b$受到立方体约束的限制，这使得它们在实践中保持很小。 内循环结束$c$仅当存在有效范围时运行，并且生成的三元组总数在以下范围内保持可控$10^6$。 

前缀和数组至关重要，因为每个查询都会询问“最多有多少个具有体积的形状”$N$，”不是精确的体积相等。如果没有前缀和，我们将不得不重新计算每个查询的累积计数，这会太慢。

## 测试用例```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    MAXV = 10**6

    freq = [0] * (MAXV + 1)

    a = 1
    while a * a * a <= MAXV:
        b = a + 1
        while a * b * b <= MAXV:
            max_c = MAXV // (a * b)
            if max_c > b:
                for c in range(b + 1, max_c + 1):
                    freq[a * b * c] += 1
            b += 1
        a += 1

    pref = [0] * (MAXV + 1)
    run = 0
    for i in range(1, MAXV + 1):
        run += freq[i]
        pref[i] = run

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(pref[n]))
    print("\n".join(out))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# edge and sample-style tests
assert run("1\n1\n") == "0"
assert run("1\n6\n") >= "1"
assert run("3\n10\n20\n100\n") == run("3\n10\n20\n100\n")
assert run("2\n30\n1\n") == run("2\n30\n1\n")

 ## 边缘情况

 一个关键的边缘情况是当体积边界非常小时。 为了$N = 1$，没有不同正整数的三元组可以满足条件，并且算法正确返回零，因为循环永远不会生成任何有效的$(a,b,c)$。 

另一种情况是当$N$很大，但仍低于前几个有效产品。 例如，$N = 5$仍然产生零，因为最小的有效三元组是$1 \cdot 2 \cdot 3 = 6$。 前缀和数组自然可以处理这个问题，因为 6 之前的所有条目都保持为零。 

更微妙的情况是，当许多三元组共享相似的小因子时，这可能会导致对同一卷的重复更新。 频率数组正确地累积这些贡献而不会覆盖，并且前缀和确保所有贡献在最终查询结果中只包含一次。
