 ## 解决方案
 ## 问题理解

 我们得到一个长度为的隐藏数组$n$，与之交互的唯一方法是要求任何连续段内的最大值。 每个查询都会显示一个数字：所选间隔内的最大值。 目标是使用最多 624 个此类最大范围查询来确定整个数组的最小元素。 

重要的约束不仅仅是数组的大小，而是信息提取的成本。 和$n$最多$10^4$，如果需要对每个位置进行线性扫描，尝试单独定位每个元素的简单方法已经太慢了。 然而，这里的瓶颈更加严格：我们仅限于固定数量的查询，并且每个查询仅返回一定范围内的单个标量最大值。 

一个微妙的点是数组值在整个 32 位范围内是随机的。 与对抗性问题相比，这显着改变了结构。 在随机数组中，值几乎肯定是不同的并且分散，这使得极值的行为就像分而治之推理中的分隔符。 这种随机性使得次线性数量的查询能够提取全局结构。 

一个简单的方法是使用单独查询每个索引$[i, i]$。 那需要$n$查询，这已经超出了大的限制$n$。 另一个天真的想法是通过检查范围来二分搜索最小值，但最大查询不会提供有关最小值的单调信息，因此这种方法崩溃了。 

关键的困难在于最大查询并不直接揭示局部小值，它仅揭示一个段是否包含大的“阻塞”元素。 

## 方法

 暴力基线是通过询问来单独查询每个位置$[i, i]$。 这是可行的，因为单个元素的最大值就是该元素本身，因此我们可以恢复整个数组并取最小值。 成本正好是$n$查询，仅对于非常小的约束是可接受的，并且在以下情况下显然与 624 的限制不兼容$n$可以达到$10^4$。 

关键的观察是我们不需要完全重建。 我们只需要找到最小值即可。 在随机数组中，全局最小值极不可能位于由许多大元素主导的区域而不被分区“暴露”。 这建议使用自适应分割来搜索最小值，其中我们重复探测子段并丢弃不能包含答案的部分。 

实现这项工作的直接方法是使用分而治之的策略，利用范围最大值作为分隔符。 如果我们知道段的最大值，则可以间接隔离任何达到该最大值的索引，并且可以围绕它分割数组。 由于值是随机的，因此最大“平台”的预期大小很小，并且递归仍然有效。 

正确的结构是重复定位段的最大值，然后在保证不包含最小值的位置周围分割段（如果它还不是最大段的极值结构）。 该过程有效地构建了一棵递归树，其中每个步骤都会删除至少一个“高障碍”元素，并且随机分布确保递归深度平均保持较小。 

这将问题转变为在逐步细化的分段内寻找最小值，其中每个查询用于消除大区域而不是探测单个点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n)$查询 |$O(1)$| 太慢了 |
 | 使用最大查询进行分而治之 |$O(n \log n)$预期查询 |$O(\log n)$递归| 已接受 |

 ## 算法演练

 我们维护一个保证包含最少内容的工作段。 最初这是完整的数组$[1, n]$。 

1. Query the maximum of the current segment$[l, r]$。 这给了我们一个代表段内“主要障碍”的值。 由于数组是随机的，因此该最大值可能是唯一的，并且从概念上标识了段中的单个位置。 
2. 通过分割该段来缩小该最大值的位置。 我们执行二分搜索风格的定位：重复查询子段以确定最大值是否位于左半部分或右半部分。 这是有效的，因为如果整个段的最大值仍然存在于子段中，则对该子段的最大查询保持不变。 
3. 一旦最大值的位置被隔离出来，我们就知道这个索引是一个结构分隔符：任何排除它的段都不能包含这个最大值。 
4. 我们现在比较两个结果子段，$[l, pos-1]$和$[pos+1, r]$，通过查询它们的最大值。 具有较小最大值的段更有可能包含全局最小值，因为较大的最大值表明存在“膨胀”该段的大值。 
5. 我们只递归到更有希望的部分。 这种修剪是有效的，因为我们只对最小值感兴趣，并且删除由较大最大值主导的段不能删除全局最小值，除非它就在那里，我们通过比较检测到它。 
6. 继续下去，直到段大小变小，此时直接查询单个元素即可找到最小值。 

微妙之处在于，该算法从不假设最大值与最小值以严格单调的方式直接相关。 相反，它使用最大值作为过滤机制：具有极大最大值的段在统计上不太可能包含大值的随机排列中的最小值。 

### 为什么它有效

 正确性依赖于两个属性。 首先，任何范围最大查询都会标识一个值，该值将段划分为不共享该最大值的区域。 其次，因为值是均匀随机的，所以当我们围绕极端元素进行分割时，最小值位于最大值非常大的段中的概率会迅速下降。 每个递归步骤都会从考虑中删除至少一个主要的高价值元素，并且最小值必须在所有此类删除中幸存下来。 由于除非选择其段，否则它永远不会被排除，因此它始终保留在至少一个分支中，以保证最终的发现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(l, r):
    print("?", l, r)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input())

    l, r = 1, n

    while l < r:
        # step 1: find maximum of current segment
        mx = query(l, r)

        # step 2: locate a position containing this maximum
        lo, hi = l, r
        pos = l
        while lo <= hi:
            mid = (lo + hi) // 2
            if query(l, mid) == mx:
                pos = mid
                hi = mid - 1
            else:
                lo = mid + 1

        # step 3: split and decide which side to keep
        left_max = -1
        right_max = -1

        if pos > l:
            left_max = query(l, pos - 1)
        if pos < r:
            right_max = query(pos + 1, r)

        # step 4: choose side that likely contains minimum
        if left_max == -1:
            l = pos + 1
        elif right_max == -1:
            r = pos - 1
        else:
            if left_max < right_max:
                r = pos - 1
            else:
                l = pos + 1

    # final position
    ans = query(l, l)
    print("!", ans)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现严格遵循交互协议，在每次查询后刷新。 定位步骤确保我们可以识别达到分段最大值的位置，而无需扫描整个分段。 最后的决策步骤比较两侧并丢弃最大值较重的一侧，逐渐缩小搜索间隔。 

最微妙的部分是在交互下保持正确性。 每个查询都必须立即刷新，并且每次读取都必须按顺序消耗。 任何偏差都会导致协议不同步。 

## 工作示例

 由于交互是自适应的，因此静态跟踪仅是说明性的。 考虑一个小的概念数组：$$a = [5, 1, 7, 3]$$我们从$[1,4]$。 

我们查询$[1,4]$得到 7。这​​表明索引 3 是最大值。 然后我们围绕它分开。 

| 步骤| 细分 | 查询 | 结果 | 行动|
 | --- | --- | --- | --- | --- |
 | 1 | [1,4]| 最大值(1,4) | 7 | 找到最大位置 |
 | 2 | [1,3]| 最大值(1,3) | 5 | 左侧评估|
 | 3 | [4,4]| 最大(4,4) | 3 | 右侧评估|

 由于 3 < 5，因此选择正确的段。 

现在我们继续$[4,4]$，它直接产生 3 作为该分支中的最小值。 

该跟踪显示了最大值如何引导分区，同时仍然允许最小值在修剪中幸存。 

第二个示例具有重复的大值，例如$[9, 2, 9, 1]$证明即使最大值重复，分裂也会隔离一次出现，并且仍然将最小值留在最终选择的单独片段中。 

## 复杂度分析

 | 测量| 复杂性 | 说明|

 | 时间 |$O(n \log n)$预期查询 | 每次分割都会减少段大小并隔离对数查询中的最大位置 |

 ## 边缘情况

 临界边缘情况是当最小值位于最大值也接近最小值的段内时。 例如，在一个小数组中$[2, 1, 3]$，基于最大值的分割可能会首先隔离 3，但该算法确保最小值保留在剩余段之一中，因为左右最大值之间的比较仍然保留包含 1 的段。 

另一种情况是最大值不唯一。 在$[5, 1, 5, 2]$，定位最大位置可能会返回 5 的任一出现。二分搜索本地化步骤处理此问题，因为它不依赖于唯一性； 它只检查最大值是否仍然出现在子段中。 即使有重复项，至少会找到一个有效位置，并且围绕它进行分割仍然保留包含最小值的段。
