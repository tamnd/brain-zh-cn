 ## 解决方案
 ## 问题理解

 我们得到了排列成一行的整数序列。 一步中，我们可以取出两个相邻元素并用它们的和替换它们，从而有效地将序列缩短一个元素，同时保留其他位置的顺序。 任务是减少序列直到它成为回文，并且我们希望最大限度地减少使用此类合并操作的次数。 

这里的回文意味着在所有转换之后，从左到右读取序列给出的值与从右到左读取序列的值相同。 因为合并保留了顺序，但改变了分段，所以问题实际上是决定如何对连续元素进行分组，以使两端的总价值匹配。 

最多一百万个元素的约束意味着尝试所有可能的合并序列或在所有间隔上使用动态编程的任何解决方案都将太慢。 任何二次或更糟糕的事情都会失败，因为合并决策是本地的，但数组很大。 

一些边缘情况很重要。 

如果数组已经向前和向后读取相同的内容，例如`[2, 2]`或者`[1, 3, 1]`，答案为零，因为不需要合并。 

例如，如果所有元素都不同并且数组很长`[1, 2, 3, 4, 5]`，我们将需要多次合并来对齐两端的累积值。 

天真的思维的一个微妙的失败案例是假设我们只比较末端的值，而不考虑允许我们合并和累积值。 例如，`[1, 10, 100]`最初并不平衡，但合并改变了结构，因此必须对段总和而不是原始元素进行比较。 

## 方法

 强力解释将模拟合并相邻对的所有可能方式，直到出现回文，跟踪最小操作数。 每次合并都会将长度减少一，并且在每种状态下，合并位置都有多种可能的选择。 

可能的合并序列的数量呈指数增长，因为每一步都有多达`O(n)`有效的合并位置，我们执行`O(n)`步骤。 这导致搜索空间远远超出了可行的限制`n`最多一百万。 

关键的观察是，最终的结构仅取决于我们如何将数组划分为连续的段，这些段的总和形成回文。 我们可以考虑从两端向内扫描的两个指针，维护每一侧的当前段总和，而不是显式地模拟合并。 

我们随时比较左段的累加和与右段的累加和。 如果相等，双方都可以向内前进，因为我们已经匹配了最终回文的一个“块”。 如果一侧较小，我们必须通过将下一个元素合并到其段中来扩展该侧。 每个这样的扩展对应一个合并操作。 这种贪婪的过程之所以有效，是因为合并仅影响本地前缀或后缀累积，并且永远不会从跳过较小的不匹配以首先解决稍后的不匹配中受益。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 两指针贪婪合并 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们模拟使用两个指针构建两个等值端。 

1. 在数组的开头和末尾初始化一个指针。 我们还从左侧和右侧维护两个代表当前压缩段的运行总和。 最初，两者分别只是第一个和最后一个元素。 
2. 如果指针相遇，则过程结束，因为整个数组已成功匹配为回文结构。 
3. 如果左侧总和等于右侧总和，则我们已成功形成匹配的外部段。 我们将两个指针向内移动，并将两个运行总和重置为下一个未覆盖的元素。 
4. 如果左边的和较小，我们必须将左边的下一个元素合并到当前左边的段中。 我们将该元素添加到左侧总和中，并将左侧指针向右移动。 这对应于一次合并操作，因为我们要组合两个相邻元素。 
5. 如果右和较小，我们从右侧对称合并，将下一个元素添加到右和中，并将右指针向左移动。 这也算作一次操作。 
6. 我们重复这个过程，直到指针相遇，累积执行的合并次数。 

贪婪的选择总是扩展较小总和的一侧，因为只有该侧才能赶上另一侧，而不会超出有效回文分区的结构。 

### 为什么它有效

 在每一步中，该算法都保持指针之间的数组尚未处理的不变性，而左右段表示潜在回文分解的部分块。 任何有效的解决方案最终都必须与每个相应块两端的总和相匹配。 如果一侧的总和较小，则延迟其扩展无济于事，因为增加总和的唯一方法是合并仅在该侧可用的相邻元素。 因此，贪婪地扩展较小的一侧永远不会阻止有效的最佳构造，并确保每次合并直接有助于解决对称块之间的一个不匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    if n <= 1:
        print(0)
        return

    l, r = 0, n - 1
    left_sum = a[l]
    right_sum = a[r]
    ans = 0

    while l < r:
        if left_sum == right_sum:
            l += 1
            r -= 1
            if l < r:
                left_sum = a[l]
                right_sum = a[r]
        elif left_sum < right_sum:
            l += 1
            left_sum += a[l]
            ans += 1
        else:
            r -= 1
            right_sum += a[r]
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现保留两个指针并扩展较小的一侧，直到两个累积的段和匹配。 一旦相等，双方都向内推进，开始新的路段。 每个扩展步骤都算作一次合并操作，这恰好对应于压缩两个相邻元素。 

比赛结束后重置分段总和时需要小心。 我们必须确保新的段从下一个未处理的元素开始； 否则，我们会错误地继承旧的部分和并破坏不变量。

 ## 边缘情况

 单元素数组，例如`[7]`已经是一个回文。 该算法立即终止，因为`l == r`在开始时，所以不计算合并。 

对于已经对称的数组，例如`[1, 2, 2, 1]`，两端开始相等并且指针向内移动而不触发任何合并。 该不变量成立，因为没有段需要扩展。 

在这样的情况下`[1, 3, 2, 2]`，右侧最初的总和较大，因此它会吸收元素，直到与左侧匹配。 该过程在一次合并后停止，这表明该算法仅在存在结构不平衡时才执行合并，并且不会引入不必要的操作。
