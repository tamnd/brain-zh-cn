 ## 解决方案
 ## 问题理解

 我们有一个服务器网络，其中每个服务器都是一个节点，每个连接都是一个无向边。 当前网络可能已断开。 我们的目标不是使其只是连接，而是使其能够抵御任何单个现有连接的故障：如果我们从图中删除任何一条边，则剩余的图必须仍然保持连接。 

同样，我们想要添加最少数量的新边，以便图成为 2 边连接的，即没有一条边是桥梁，其删除会断开图的连接。 如果图一开始就已经断开，我们仍然要求在添加边后，删除任何一条边使整个图保持连接，因此最终的鲁棒性必须全局保持。 

输入大小高达十万个节点和边。 任何尝试模拟边缘删除或重新计算每条边缘连接的解决方案都会太慢。 即使使用 DFS 进行的单个连接检查也是线性的，因此对每条边重复进行检查将是二次的，并且会立即失败。 这推动我们对图进行线性或近线性分解。 

当图形最初断开连接时，会出现一个微妙的点。 一种幼稚的方法可能会尝试使每个组件在内部“安全”，然后再连接组件，但这种分离具有误导性。 要求是全局的：添加边后，在删除任何单个边后整个图必须保持连接。 这迫使我们对整个图上的桥的结构进行推理，而不是独立地对每个组件进行推理。 

打破天真的思维的常见边缘情况是树。 如果输入图已经是一棵树，那么每条边都是一座桥。 例如，在由四个节点组成的线上，删除任何边都会断开图的连接。 一般来说，正确的答案不是零或一，而是取决于我们需要配对多少个端点（桥接组件）。 另一种边缘情况是单周期：即使它已连接，但它已经没有桥，因此不需要额外的边缘。 

## 方法

 一个蛮力的想法是测试每一个可能的添加边集，并检查结果图是否在每次单边删除后仍然存在。 这立即变得不可行，因为即使在 O(N^2) 可能的边中仅选择 k 个边也会产生组合爆炸，并且每次有效性检查都需要完整的图遍历。 即使将我们限制在较小的 k 也无济于事，因为验证本身很昂贵。 

一种更结构化的尝试是考虑删除每条边并检查连通性。 我们可以使用 DFS 低链接值识别原始图中的所有桥。 一旦了解了桥梁，问题就变成了消除它们造成的漏洞。 移除桥梁会将图分成两个部分，因此任何最终构造都必须确保这些部分仍然通过替代路线连接。 这自然会导致将图压缩为其桥接组件。 

如果我们将每个最大 2 边连接组件收缩为单个节点，则组件之间的所有剩余边都是桥。 由此产生的结构是一片森林。 这片森林中的每棵树都代表了组件如何通过脆弱的边缘连接起来。 

关键的见解是，使整个图能够适应任何单边故障，相当于确保该森林在组件级别成为 2 边连接。 对于一棵树来说，使其成为 2 边连接所需的最小边数是众所周知的：它是叶子数一半的上限。 每个叶子对应一个仅与一个桥接边缘相关的组件，这意味着如果该边缘发生故障，它就会断开连接。 在两个叶子之间添加一条边可以将叶子数量减少两个。 

因此，问题简化为：

找到所有桥连接的组件，构建桥树，计算每棵树中的叶子数，并对所有树求和 ⌈leaf_count / 2⌉ 。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(N^2) | O(N^2) | 太慢了|
 | 桥梁+树木减少| O(N + M) | O(N + M) | 已接受 |

 ## 算法演练

 1. 使用发现时间和低链路值运行基于 DFS 的网桥查找算法。 如果 v 的低链路值严格大于 DFS 树边中 u 的发现时间，则每条边 (u, v) 都是桥。 这标识了移除增加连接组件数量的所有边。 
2. 构建一个新图，其中我们忽略所有桥边，而是将节点分组到连接的组件中。 以这种方式形成的每个连接组件都是一个最大子图，即使删除其中的任何单个边，该子图仍保持连接。 
3. 在非桥接边缘上使用 DFS 或 BFS 为每个节点分配组件 id。 现在，每个节点都属于一个“2 边连接块”。 
4. 通过迭代原始边来构造桥树。 对于组件 A 和 B 之间的每个桥边，在组件图中的 A 和 B 之间添加一条边。 该图保证是一个森林，因为桥不能形成循环。 
5. 对于桥树中的每个节点，计算其度数。 度数为 1 的节点是叶子，这意味着它仅通过一座桥连接到结构的其余部分，并且在一个连接点处很容易受到攻击。 
6. 对于桥树的每个连接组件，计算它包含多少个叶子。 
7. 对于每棵树，计算要添加的边数，作为叶子数一半的上限。 将这些值添加到所有树上以获得最终答案。 

配对叶子起作用的原因是，每个添加的边都可以连接脆弱链的两个端点，从而将暴露端点的数量减少两个，同时消除至少一个潜在的桥接漏洞路径。 

### 为什么它有效

 收缩2条边连接的组件后，剩余的每条边都是一座桥，因此该结构是一片森林。 这片森林中的任何一片叶子都代表着一个与其树的其余部分有着脆弱联系的组成部分。 如果一个叶子未通过新边缘与另一个叶子配对，则其单个连接仍然是一个漏洞：删除该桥会将其隔离。 

每个添加的边只能消除对两个叶子的需要，因为它连接两个组件。 因此，最佳策略是在每棵树中任意配对叶子。 这实现了每个叶子都由附加独立路径“支撑”的配置，从而消除了单边缘断开点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]

    edges = []
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append((b, len(edges)))
        g[b].append((a, len(edges)))
        edges.append((a, b))

    tin = [-1] * n
    low = [0] * n
    is_bridge = [False] * m
    timer = 0

    def dfs(v, pe):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1

        for to, eid in g[v]:
            if eid == pe:
                continue
            if tin[to] == -1:
                dfs(to, eid)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[eid] = True
            else:
                low[v] = min(low[v], tin[to])

    for i in range(n):
        if tin[i] == -1:
            dfs(i, -1)

    comp = [-1] * n
    cid = 0

    def dfs2(v, c):
        stack = [v]
        comp[v] = c
        while stack:
            x = stack.pop()
            for y, eid in g[x]:
                if comp[y] == -1 and not is_bridge[eid]:
                    comp[y] = c
                    stack.append(y)

    for i in range(n):
        if comp[i] == -1:
            dfs2(i, cid)
            cid += 1

    deg = [0] * cid

    for eid, (a, b) in enumerate(edges):
        if is_bridge[eid]:
            ca, cb = comp[a], comp[b]
            deg[ca] += 1
            deg[cb] += 1

    leaves = 0
    for i in range(cid):
        if deg[i] == 1:
            leaves += 1

    print((leaves + 1) // 2)

if __name__ == "__main__":
    solve()
```第一个 DFS 计算发现和低链路时间，这是在线性时间内识别网桥的标准方法。 第二次遍历忽略所有桥边并将每个最大非桥连接区域折叠成单个组件。 

之后，我们在桥树上构建度数计数，而无需显式构建邻接列表，因为只需要度数。 每个桥为两个端点组件贡献了一个度数增量。 

最终公式`(leaves + 1) // 2`实现每棵树中叶子数量一半的上限，通过对所有组件上的叶子求和来隐式聚合所有树。 因为每棵树都是独立贡献的，所以对全局叶子求和仍然会产生正确的配对计数。 

一个常见的错误是在找到桥之前尝试单独处理每个原始连接组件。 这会错过将大型组件连接在一起的桥梁，并导致叶子计数不正确。 

## 工作示例

 ### 示例 1

 输入：```
5 4
1 2
2 3
3 4
4 5
```这是一条简单的路径。 每条边都是一座桥。 

| 步骤| 行动| 组件| 桥数| 叶子|
 | ---| ---| ---| ---| ---|
 | 1 | 寻找桥梁| 收缩后所有节点分离| 4 座桥 | 2 个端点 |
 | 2 | 搭建桥梁树| 5 个组件的路径 | 度：1-2-2-2-1 | 2 |
 | 3 | 计算答案 | 叶子 = 2 | (2+1)//2 = 1 | 1 |

 我们需要一条额外的边，它连接链的两个端点，形成一个循环并消除所有单边漏洞。 

### 示例 2

 输入：```
3 3
1 2
2 3
3 1
```这已经是一个循环了。 

| 步骤| 行动| 组件| 桥数| 叶子|
 | ---| ---| ---| ---| ---|
 | 1 | 寻找桥梁| 无 | 0 | 0 |
 | 2 | 组件| 单组分| 0 | 0 |
 | 3 | 回答 | 没有叶子| 0 | 0 |

 不需要额外的边，因为删除任何单个边仍然会留下连接所有节点的路径。

 ## 边缘情况

 树输入突出显示了核心行为。 考虑`1-2-3-4-5`。 桥树与原来的结构相同，产生两片叶子。 该算法将它们配对成一个添加的边，正确地形成一个删除所有桥的循环。 

完全连接的循环显示了相反的极端。 由于没有桥，组件图会折叠成度数为零的单个节点，产生零叶，因此添加零边。 这证实了该算法不会过度纠正已经有弹性的结构。
