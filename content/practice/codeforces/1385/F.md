 ## 解决方案
 ## 问题理解

 我们正在处理一棵树，其顶点逐渐被轮次删除。 在一轮中，我们可以选择一个内部顶点$v$并准确删除$k$它当前的叶子邻居。 如果某个顶点在当前剩余图中的度数为 1，则该顶点算作叶子。 除去这些叶子后，树会收缩并且可能会出现新的叶子。 这个过程还在继续，我们希望最大化我们可以执行的轮数。 

关键的困难是叶子状态是动态的。 最初不是叶子的顶点可以在以后成为叶子，并且早期回合中的选择会影响未来可能的回合数。 

输入数据量很大，最多可达$2 \cdot 10^5$测试用例中的顶点总数。 这立即排除了任何在整个树上逐步模拟每次移动的移除的方法，因为简单的模拟可能会降级为$O(n^2)$在链状结构中，每次移除仅暴露一片新叶子。 

高度不平衡的树（如链条）中会出现微妙的边缘情况。 例如，如果$k = 2$，长度为 5 的路径与星形的行为非常不同，尽管两者都是大小相似的树。 在一颗星中，一个中心周围有许多叶子立即可用，从而允许进行多轮。 在一条链中，任何时候都只有一两个叶子存在，严重限制了移动。 任何假设全局叶子丰度而不跟踪结构的贪婪策略在这里都会失败。 

另一个重要的边缘情况是多个高度节点竞争叶子时。 如果我们总是在本地挑选叶子而不考虑全局耗尽，我们可能会过早地耗尽节点上的叶子，否则该节点将在以后维持更多轮次。 

## 方法

 暴力模拟将重复识别所有叶子，按邻居对它们进行分组，选择任何有效的大小组$k$，删除它们，并更新度数。 每轮都需要扫描所有节点来收集叶子，这需要花费$O(n)$。 由于我们可能执行最多$O(n)$在最好的情况下，这会导致$O(n^2)$总工作量，对于限制来说太慢了。 

关键的观察结果是，每个顶点周围的移除结构在组合意义上是独立的。 每个顶点$v$随着时间的推移，它会贡献叶子，但前提是有足够多的邻居变成叶子。 我们可以考虑每棵子树可以向父树向上“提供”叶子的次数，而不是全局模拟该过程。 

随意给树生根。 对于每个节点，请考虑在其自身的贡献受到限制之前，其子节点可以支持多少个叶子移除。 这变成了一个自下而上的聚合问题：每个子树返回一个计数，表示它最终可以向其父级提供多少叶子，并且每个内部节点贪婪地按大小批量组合这些贡献$k$。 

关键的见解是每个节点有效地将子节点的贡献转换为不同大小的组$k$，并且任何剩余的贡献都会向上传播。 答案是所有节点上形成的完整组的总数。

 ## 算法演练

 我们以任意节点为树根，通常为 1。 

1. 从根开始执行后序 DFS，从叶子向上计算值。 每个节点返回它可以传递给其父节点的“可用叶令牌”数量。 叶节点最初贡献 1 个令牌。 该模型表明，一片叶子可能会在一次操作中被移除。 
2.对于每个节点$v$，收集所有孩子的贡献。 这些贡献代表了以这些孩子为根的每个子树最终可以产生多少叶子。 
3. 在节点处$v$，将所有儿童贡献相加。 这个总和表示子树中当前有多少个叶子端点可用$v$可能会被分组。 
4. 通过除以将该总和转换为完整运算$k$。 每组$k$叶子标记对应于以$v$或通过向上传播$v$的父母。 
5. 通过剩余部分$\text{sum} \bmod k$向上到父级。 这些剩余的标记代表部分完成的组，可以与树中更高的其他子树组合。 
6. 累加所有节点上的商值。 这个总数是有效的移动次数。 

DFS 确保每个子树只处理一次，并且在足够的叶子贡献满足的每个节点本地进行分组。 

### 为什么它有效

 每个子树贡献一定数量的最终叶子，这些叶子可以独立于其他子树实现，直到它们在共同祖先处相遇。 子树之间的唯一交互是在它们的最低共同祖先处，其中来自不同分支的叶标记可以组合成不同大小的组$k$。 由于分组在加法和求商方面是可交换和关联的，因此自下而上执行分组可确保不会遗漏任何组合，并且不会计算无效组合。 任何有效的移动完全对应于形成一组$k$叶令牌在某个节点上，并且每个这样的组在完全可用的最低节点上只被计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        ans = 0

        def dfs(u, p):
            nonlocal ans
            total = 0
            for v in g[u]:
                if v == p:
                    continue
                total += dfs(v, u)

            if total == 0:
                return 1

            ans += total // k
            return total % k

        dfs(1, -1)
        print(ans)

if __name__ == "__main__":
    solve()
```DFS 计算每个节点有多少叶子贡献来自其子节点。 叶子返回 1，表示单个可移动端点。 内部节点聚合这些值。 

当一个节点累计至少$k$贡献，这些对应于以某个祖先为中心的一个有效删除操作，因此我们将答案增加`total // k`。 任何剩余的贡献都会向上返回，因为它们可能会与树中更高的其他分支结合起来。 

一个微妙的点是正确处理叶子。 叶子返回 1 表示它是单个可用端点。 如果节点没有子节点贡献，则它的行为就像简化树中的叶子。 

## 工作示例

 ### 示例 1

 输入：```
n = 5, k = 2
edges:
1-2, 1-3, 3-4, 3-5
```我们从 root 1 运行 DFS。 

| 节点| 儿童贡献 | 总计 | 组 (//k) | 剩余|
 | --- | --- | --- | --- | --- |
 | 2 | - | 1 | 0 | 1 |
 | 4 | - | 1 | 0 | 1 |
 | 5 | - | 1 | 0 | 1 |
 | 3 | 1 + 1 = 2 | 2 | 1 | 0 |
 | 1 | 1（来自 2 组）+ 1（来自 3 组）= 2 | 2 | 1 | 0 |

 答案是2。 

该轨迹显示了来自不同分支的叶子如何在内部节点处组合。 节点 3 首先形成一个完整的组，然后节点 1 在顶层形成另一个组。

 输入：```

 ## 边缘情况

 链显示了叶令牌必须如何向上传播，而不是过早在本地分组。 DFS 在每个叶子上累积一个令牌，并且仅在内部节点处形成组，以确保正确配对。 

星形验证所有叶子必须在可能的情况下组合在单个节点上，因为不存在更深层次的结构来延迟分组。 

什么时候$k = 1$，每个叶子贡献立即变成一个操作。 该算法自然地处理这个问题，因为每个总数都有贡献`total // 1`，这意味着所有令牌都在每个节点上被消耗掉，没有剩余。
