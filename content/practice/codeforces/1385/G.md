 ## 解决方案
 ## 问题理解

 我们有一个两行表$n$列，每个单元格都包含一个介于$1$和$n$。 在每一列中，我们可以保留两个值不变或交换它们，并且每列最多可以交换一次。 目标是决定我们是否可以使两行分别成为以下排列$1 \ldots n$，如果是，则使用尽可能少的交换，同时输出哪些列被交换。 

重新解释该操作的一个有用方法是，每一列都包含两个“选择”来决定其数字的去向。 如果我们什么都不做，专栏$i$贡献$a_{1,i}$到第 1 行和$a_{2,i}$到第 2 行。如果我们交换，列$i$贡献$a_{2,i}$到第 1 行和$a_{1,i}$到第 2 行。任务是为每列选择一个方向，以便两行都成为排列。 

约束条件很大：总和$n$所有测试用例最多可达$2 \cdot 10^5$。 每个测试用例超过线性或接近线性的任何解决方案都不会通过。 这排除了尝试所有的任何事情$2^n$每个测试用例交换配置甚至二次图结构。 

一些失败案例很容易被忽视。 

如果一个数字在整个表中出现两次以上，则答案立即不可能，因为即使在选择方向之后，我们也只能将每个出现位置放入两行之一，而排列需要在每个行位置恰好出现一次。 

例如，如果$n=3$:```
1 1 1
2 2 3
```数字 1 出现了 3 次，因此一行必须包含重复项。 任何策略都会失败。 

另一个微妙的情况是，本地决策似乎可行，但由于奇偶性约束而导致全局一致性失败。 例如：```
1 2
2 1
```这是可以解决的，但是贪婪的每列推理仍然必须确保两行同时保持排列。 

真正的困难在于每个值必须一致地决定它在出现的所有列中属于哪一行。 

## 方法

 暴力方法会尝试交换列的所有子集。 对于每个配置，我们检查两个结果行是否都是排列。 检查需要$O(n)$，所以总计是$O(2^n \cdot n)$，即使对于$n=30$。 

关键的观察是每个值$x$对于可行的解决方案，它在整个表中恰好出现两次：在交换之前在第 1 行或第 2 行中出现一次，在交换之后，它必须在每个最后一行中出现一次。 因此，每个数字都会对如何将其两次出现分配给行产生约束。 

我们可以将每一列建模为二元选择：保留或交换。 值的每次出现都会对该二进制变量施加约束。 如果一个值出现在两个位置，则必须分配这两个位置，以便一个位于第 1 行，另一个位于第 2 行。这正是列之间依赖关系图上的约束传播问题。 

每列都成为具有布尔状态的节点。 每个值都连接它出现的两列，根据它是出现在原始表中的同一行还是不同行中，强制执行“相同方向”或“相反方向”。 这将问题简化为使用双着色（双向检查）和计算每个组件的最小翻转次数的图形一致性检查。 

在每个连接的组件中，恰好有两种有效的着色，我们选择最小化交换的一种。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 图 + 2 着色 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将每一列视为图中的一个节点，其中节点的状态表示我们是否交换该列。 

每个号码$x$恰好出现两次，例如在列中$i$和$j$。 这两次出现在列之间创建了约束$i$和$j$。 

我们区分两种情况：

 如果$x$出现在两列的同一行中，然后恰好交换其中一个会将两个副本移动到同一行，这是无效的。 因此两列必须具有相同的交换状态。 

如果$x$出现在其两列的不同行中，则必须交换两列中的一列，这意味着它们的状态必须不同。 

这将问题转化为一个图表，其中每条边强制端点之间相等或不相等。 

然后，我们使用组件上的 DFS 来解决一致性问题。 

1. 构建列的邻接表。 

每条边都存储一个约束类型：相等或不同。 这体现了交换选择必须如何关联。 
2. 对所有尚未分配状态的列运行 DFS。 

我们分配一个初始状态，例如 0。 
3. 遍历边时，根据约束分配相邻状态。 

如果边要求相等，则传播相同的值。 如果需要不平等，就翻转它。 

此步骤确保本地满足所有约束。 
4. 如果我们遇到节点必须采取两种不同状态的冲突，则实例是不可能的。 

这对应于约束中的奇怪矛盾循环。 
5. 对于每个连接的组件，我们通过 DFS 隐式计算两个可能的初始分配所需的交换次数。 

由于翻转组件中的所有状态给出了另一个有效的解决方案，因此我们选择交换次数较少的方向。 
6. 收集所有最终状态为1的列作为答案。 

它之所以有效，是因为每个值都精确定义了两列之间的一个二元约束。 最终的分配必须同时满足所有此类成对约束，并且这些约束形成一个图，其可行性恰好是具有奇偶边缘的二分性。 每个连接的组件都是独立的，并且在其中恰好存在两个通过全局翻转而不同的一致分配，这就是为什么可以对每个组件进行最小化交换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [[] for _ in range(n + 1)]
    for i in range(n):
        pos[a[i]].append((i, 0))
        pos[b[i]].append((i, 1))

    adj = [[] for _ in range(n)]
    # each edge: (neighbor, type)
    # type = 0 means same, 1 means different

    for v in range(1, n + 1):
        if len(pos[v]) != 2:
            print(-1)
            return
        (i1, r1), (i2, r2) = pos[v]
        if r1 == r2:
            adj[i1].append((i2, 0))
            adj[i2].append((i1, 0))
        else:
            adj[i1].append((i2, 1))
            adj[i2].append((i1, 1))

    color = [-1] * n
    ans = []

    for i in range(n):
        if color[i] != -1:
            continue

        stack = [i]
        color[i] = 0
        comp = []

        while stack:
            u = stack.pop()
            comp.append(u)
            for v, t in adj[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ t
                    stack.append(v)
                else:
                    if color[v] != (color[u] ^ t):
                        print(-1)
                        return

        cnt = sum(color[u] for u in comp)
        # try flip or not
        if cnt > len(comp) - cnt:
            for u in comp:
                color[u] ^= 1

    res = [i + 1 for i in range(n) if color[i] == 1]
    print(len(res))
    if res:
        print(*res)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```构建步骤直接根据每个值的出现构建约束。 每个值恰好连接两列，边缘类型对它们的交换状态是否必须匹配或不同进行编码，具体取决于出现的次数是否在同一行中对齐。 

DFS 为每一列分配一个二进制状态并传播约束。 遍历过程中出现矛盾会立即终止测试用例。 

组件级优化利用了翻转连接组件中的所有状态可以保持有效性的事实。 我们计算当前方向使用了多少次交换，如果这减少了计数，则翻转。 

## 工作示例

 考虑一个小案例：```
1 2 1
2 3 3
```我们有优势：

 1 连接不同行中的第 0 列和第 2 列，因此约束是不等式。 

2 连接不同行中的第 0 列和第 1 列，不等式。 

3 连接不同行中的第 1 列和第 2 列，不等式。 

我们追踪 DFS：

 | 步骤| 节点| 已分配 | 原因 |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 开始 |
 | 2 | 1 | 1 | 边 0-1 不等式 |
 | 3 | 2 | 1 | 边 0-2 不等式会迫使 1 |

 满足所有约束条件。 组件的颜色为 [0,1,1]，因此交换是第 2 列和第 3 列（1 索引，具体取决于解释）。 

这演示了所有约束如何分解为一致的奇偶校验分配。 

现在考虑一个不可能的情况：```
1 1
1 1
```每个值出现四次，违反了每个值必须恰好连接两列的要求。 预处理步骤立即拒绝它。

 ## 边缘情况

 关键的边缘情况是当一个值在同一行中出现两次时。 在这种情况下，两个端点必须采用相同的交换状态。 如果 DFS 错误地将所有边视为“不同”，它将错误地强加矛盾。 

例如：```
1 2
1 2
```这里值 1 在第 1 行中出现两次。 其列之间的约束是相等的。 DFS 将列 0 分配为 0，将列 1 传播为 0，对于值 2 也是如此。不需要交换，这与预期答案相匹配。 

另一个微妙的情况是混合等式和不等式边缘的约束循环。 DFS 自然地处理它，因为循环中的奇偶校验传播要么返回一致的颜色，要么检测到矛盾。
