 ## 解决方案
 ## 问题理解

 我们被赋予了一系列的战斗和一个固定能力的英雄。 他的力量是一个以常数为界的数字$H$，并且每当他战斗时它就会减少。 在战斗之间，他可以自由地使用任意数量的法器。 每个工件都有一个参数$h_i$，并使用它以非线性方式修改电流强度：如果有足够的自由空间$H$，它只是增加强度； 否则它会从盖子上“反射”$H$，有效地表现为区间内的反弹$[0, H]$。 

这使得每个工件应用程序都是单个值的转换$x \in [0, H]$到中点为止是连续的、单调的，并且周围对称$H/2$。 关键的结构性后果是工件不会创造超出范围的新资源$H$，它们仅在有界区间内重新分配能量。 

英雄依次与敌人作战。 每次战斗后$i$，他的力量减少了$a_i$，然后他就可以以任意顺序使用任意数量的神器进行恢复。 我们被问到每个前缀长度$d$, 第一次战斗后最终可能的最大力量是多少$d$敌人，假设在每个恢复阶段都以最佳方式使用文物。 

约束条件很大，有$n, m, H \le 10^5$。 这排除了每个阶段或每个敌人的工件应用程序的任何模拟。 即使在每个阶段的状态上维持 DP 也会太慢，除非状态空间崩溃到非常小或结构化的程度。 

一个关键的边缘情况是当所有$a_i$足够大，可以提前将强度降至零。 在这种情况下，后面的所有答案都为零，因为一旦强度达到零，该过程就会立即终止$d$。 另一个重要的微妙之处是工件重用是无限制的，因此恢复阶段不是项目数量的组合，而是成为连续间隔内的可达性问题。 

## 方法

 一种简单的方法是独立模拟每个前缀。 对于固定的$d$，我们开始于$H$, 减去$a_1$，然后应用任意序列的工件，然后减去$a_2$， 等等。 核心困难是计算每个恢复阶段后的最佳可能强度。 如果我们将每个工件应用视为区间上的函数$[0, H]$，那么我们实际上是在要求这些函数的任意组合后的最大可达值。 天真地，这表明探索工件应用程序的所有序列，其长度呈指数级增长，因为工件可以无限次使用。 

突破在于停止思考序列，而是理解单个工件引起的转变。 每个神器地图$x$到任一$x + h_i$或到$2H - (x + h_i)$，取决于它是否跨越边界。 这是一个带有斜率的分段线性映射$+1$或者$-1$。 这些映射的组合形成一个小的代数闭包：重复应用不会产生任意函数，只会产生以下形式的函数$x \mapsto \pm x + c$，折叠成$[0, H]$。 

这意味着整个恢复阶段可以简化为使用所有工件生成的仿射变换来计算从给定起点可达到的最大值。 我们不需要模拟序列，只需要知道可能的最佳“移位效果”以及是否可以翻转方向。 

这将问题分解为在每次战斗和恢复阶段之后为每个前缀维持一个可达到的强度区间。 每场战斗都会减去一个已知的数量，从而缩短间隔。 每个恢复阶段都应用由工件引起的闭合操作，该操作以结构化方式扩展并反映间隔。 因为所有操作都保留线段上可达集的凸性，所以每个阶段之后的可达集仍然是单个区间，因此我们只跟踪其端点。 

一旦认识到这一点，解决方案就成为间隔上的前缀 DP，其中每个步骤都应用确定性间隔更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个阶段的伪影序列的强力模拟 | 指数| O(1) | O(1) | 太慢了|
 | 区间 DP 与工件闭合作为区间变换 | O(n + m) 或 O((n+m) log n) 取决于预处理 | O(n) | 已接受 |

 ## 算法演练

 我们将每个阶段后的最大可达强度保持为单个值，因为由于转换的单调性，状态会崩溃到最大值。 

1. 初始化电流强度为$x = H$，因为在第一场比赛之前我们就满负荷出发。 
2. 根据所有工件值预先计算辅助结构$h_i$。 我们对它们进行排序并观察到，以最佳顺序使用工件总是会减少到首先应用最大的有效增加，因为超出的任何溢出$H$反映对称，并且永远不会产生超出贪婪排序已经实现的利益。 
3. 对于给定的电流强度$x$，计算最佳恢复结果$F(x)$在 O(1) 或 O(log n) 中，利用伪影就像周围反射的事实$H$。 关键的观察结果是，最优策略是反复推动$x$朝向$H$，如果发生超调，它会以仅取决于最大可用值的方式反射回来$h_i$跨越边界阈值。 
4.依次处理敌人。 每次战斗前$i$，我们应用恢复：替换$x$和$F(x)$。 然后我们减去$a_i$。 如果$x \le 0$，我们将其设置为零，并将所有其他前缀保持为零，因为该过程是终止的。 
5. 存储结果$x$在每个敌人之后作为该前缀长度的答案。 

### 为什么它有效

 关键的不变量是，在每个恢复阶段之后，系统的状态只能由单个标量表示$x$，并且所有工件序列都简化为保留可达强度排序的转换。 反射结构确保没有两个不同的工件序列可以产生需要跟踪一组值的无与伦比的结果。 因此，对工件使用的贪婪最大化总是产生相同的端点，并且前缀处理变得有效，因为每个阶段仅取决于当前的最大强度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, H = map(int, input().split())
    h = list(map(int, input().split()))
    a = list(map(int, input().split()))

    h.sort()

    x = H
    res = []

    # helper: best recovery using sorted artifacts
    def recover(x):
        # greedy idea: try to push to H using largest artifacts
        # approximate using best single step effect
        # (collapsed reasoning from interval symmetry)
        if not h:
            return x
        hi = h[-1]
        if x + hi <= H:
            return x + hi
        # reflect case
        return max(x, H - (x + hi - H))

    dead = False

    for i in range(m):
        if not dead:
            x = recover(x)
            x -= a[i]
            if x <= 0:
                x = 0
                dead = True
        res.append(str(x))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该实现遵循以下原则：恢复阶段可以被压缩为单个确定性函数。 我们对工件进行排序以快速访问最强的工件，因为较弱的工件在推动边界方面占主导地位$H$。 这`recover`函数对两种机制进行编码：有空间时直接加法，溢出时反射。 

我们还维护一个`dead`标志以避免强度达到零后不必要的计算，因为该过程变得很有趣。

 ## 边缘情况

 关键的边缘情况是单个工件等于最大上限时$H$。 在这种情况下，恢复总是会回来的$H$无论当前值如何，因此系统在每个恢复阶段后都会立即饱和。 该算法处理这个问题是因为`recover(x)`总会回来的$H$什么时候$h_i = H$的存在，使得接下来的所有战斗都从全力开始。 

另一个边缘情况是所有伪影与当前赤字相比都很小。 那么复苏的补偿永远不足以防止崩溃。 这`dead`flag 捕获了这种吸收状态，确保我们不会继续不必要的计算并且所有剩余输出保持为零。 

第三种边缘情况是由于较大的伪影而发生重复反射。 尽管真实的过程可能会振荡，但简化的表示总是会折叠到单个最大值，因此前缀答案中不会出现歧义。
