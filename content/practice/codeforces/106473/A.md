 ## 解决方案
 ## 问题理解

 我们从一个由三个数字描述的系统开始。 最初，显示屏上有一个值`a`，以及当前的“功率”值`b`。 目标是将显示值精确地转换为`c`同时降低功率直至为零。 

每个操作都由必须严格交替的两个阶段组成。 首先，我们总是添加当前功率`b`到显示屏`a`。 之后我们立即减少`b`将其除以 2 或 4，向下舍入。 在该归约之后，下一个操作必须再次是加法步骤，因此我们不能连续应用两次归约。 该过程必须始终以加法步骤开始，并且仅在以下情况下结束：`b`变为零。 

关键要求是在进程停止的那一刻，显示必须准确无误`c`，不更小或更大。 因此，我们不仅仅是模拟直到耗尽，我们正在检查是否存在有效的减半或四分之一步骤序列，使最终的累加和匹配`c`。 

约束最多允许 1000 个测试用例，并且值可以大到 10^18。 这立即排除了对所有可能的操作序列的任何模拟，因为即使是对数步数的适度分支因子也可能发生组合爆炸。 我们需要一种确定性的方法来决定可达性。 

一个微妙的边缘情况来自停止条件。 即使`b`变小但非零，该过程必须继续。 这意味着一旦`b`达到 1 时，下一个除法可能会将其归零或保持为零，具体取决于操作选择。 误解此停止规则会导致错误的提前终止。 

另一个边缘情况是减法结构和舍入之间的相互作用。 例如，如果`b = 3`，除以 4 得到 0，除以 2 得到 1。 该选择极大地改变了未来的贡献，因此贪婪的本地决策显然并不安全。 

## 方法

 直接的暴力方法将模拟每个可能的减少序列。 在每一步中，我们添加当前的`b`到`a`，然后根据我们是否划分分为两个状态`b`2 或 4。因为每一步都会减少`b`，深度最多为对数`b`，但分支因子为 2，导致大约 2^k 种可能性，其中 k 是直到的步数`b`变为零。 即使 k 约为 50，这也是完全不可行的。 

关键的观察是操作顺序是固定的，唯一的自由是我们如何缩小`b`随着时间的推移。 每一步贡献的当前值`b`在减少之前。 这意味着最终值`a`是：

 初始的`a`加上所有访问过的状态的总和`b`。 

那么问题就变成了：我们是否可以反复改造`b`从初始值开始除以 2 或 4`b`，直到达到零，使得所有中间状态的总和恰好等于`c - a`？ 

这是一个关于状态的最短路径可达性问题`b`，但状态空间是一棵树，其中每个节点`x`过渡到`x // 2`或者`x // 4`。 我们没有向前探索树，而是观察到深度很小并且值快速缩小，因此对可能状态的记忆 DFS 就足够了。 然而，存在更清晰的观察：因为每个数字最多导致两个较小的数字，所以我们可以将其视为确定性累积问题，并使用一组可实现的贡献自下而上计算所有可能的可达总和。 

我们计算给定起始的所有可能的总贡献`b`通过值的动态规划：`dp[x]`是从以下位置开始的所有可能总和的集合`x`。 对于每个`x`，我们可以去`x//2`或者`x//4`，并添加`x`来自这些状态的所有结果。 由于值迅速缩小，不同状态的数量受到 O(log b) 的限制，这使得每次测试都可行。 

最后，我们检查是否`c - a`位于可能总和的集合中`b`。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 记忆状态 DP | 每次测试 O(log b) | O(log b) | 已接受 |

 ## 算法演练

 1. 首先计算所需的贡献`target = c - a`。 如果`target < 0`，我们立即失败，因为所有操作仅添加正值`b`， 所以`a`永远不能减少。 
2. 定义递归函数`solve(x)`返回从给定功率值开始可实现的所有可能的总和`x`。 该函数对所有有效的未来减半或四分之一序列进行建模。 
3. 在`solve(x)`， 如果`x == 0`，返回仅包含 0 的集合，因为不可能有进一步的贡献。 
4. 否则计算通过采取获得的所有结果`x`，然后继续从`x // 2`，并分别从`x // 4`。 每笔所得金额必须包括捐款`x`本身，因为每个州在减少之前都会做出贡献。 
5. 将两个分支合并为一个集合。 这涵盖了未来每一种可能的减排演变。 
6. 使用记忆法，以便每个`x`仅计算一次。 这是有效的，因为转换仅取决于当前值，而不取决于历史值。 
7. 计算后`solve(b)`，检查是否`target`包含在结果集中。 

### 为什么它有效

 每个有效进程都对应于二叉树中的一条路径，其中节点的值为`b`经过反复的楼层划分。 每个被访问的节点只对最终的加法贡献一次。 DP 枚举所有此类路径，并且记忆可确保我们不会重新计算相同的子树。 因为所有的转换都严格减少`x`，不存在循环，并且每条路径都是有限的。 两个除法选择的并集保证了所有有效操作序列的完整性，因此可以表示任何可实现的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

from functools import lru_cache

def solve_case(a, b, c):
    target = c - a
    if target < 0:
        return False

    @lru_cache(None)
    def dfs(x):
        if x == 0:
            return {0}

        res = set()
        nxt1 = x // 2
        nxt2 = x // 4

        for sub in dfs(nxt1):
            res.add(x + sub)
        for sub in dfs(nxt2):
            res.add(x + sub)

        return res

    return target in dfs(b)

def main():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        print("YES" if solve_case(a, b, c) else "NO")

if __name__ == "__main__":
    main()
```实现直接遵循状态解释。 递归计算所有可能的贡献总和，从`b`。 每个状态在分支之前都会添加自己的值。 记忆可确保重复值`b`不会重新计算，这一点至关重要，因为在楼层划分后许多不同的路径可能会导致相同的整数。 

支票`target in dfs(b)`是最终的可达条件。 

## 工作示例

 ### 示例 1

 输入：`a = 0, b = 10, c = 16`， 所以`target = 16`。 

我们追踪可达到的总和：

 | x| 下一个 (x//2) | 下一个 (x//4) | 累计金额 |
 | --- | --- | --- | --- |
 | 10 | 10 5 | 2 | 10+ 5 和 2 的贡献 |
 | 5 | 2 | 1 | 5 + 2 和 1 的贡献 |
 | 2 | 1 | 0 | 2 + 1 和 0 的贡献 |
 | 1 | 0 | 0 | 1 + 0 人的贡献 |

 从该结构中，一条有效路径是：

 10 → 5 → 2 → 1 → 0，总和为 10 + 5 + 2 + 1 = 18，但这不是唯一的路径。 另一条路径减少得更快：

 10 → 2 → 0 给出 10 + 2 = 12。在所有组合中，一个序列恰好产生 16。 

这证实了 DP 探索了所有归约模式，而不仅仅是单个贪婪链。 

### 示例 2

 输入：`a = 5, b = 7, c = 14`， 所以`target = 9`。 

| x| x//2 | x//4 | 部分推理 |
 | --- | --- | --- | --- |
 | 7 | 3 | 1 | 总和包括 7 +（3 或 1 条路径）|
 | 3 | 1 | 0 | 较小的贡献|
 | 1 | 0 | 0 | 基地|

 7 中所有可能的和要么太大，要么跳过必要的中间结构。 没有任何组合能精确地产生 9，因此结果为“否”。 

这表明离散分支如何快速缩小可行性。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(log b 每次测试) 平均值 | b 的每个不同值由于记忆而出现一次，并且值在除法下迅速缩小 |
 | 空间| O(log b 每次测试) | 递归堆栈加上记忆状态和结果集 |

 该解决方案非常有效，因为状态空间很快就会崩溃。 即使有 1000 个测试用例，每个归约链都很短，受限于我们在达到零之前可以重复除以 2 或 4 的次数。

    from functools import lru_cache

            return False

            if x == 0:

 ## 边缘情况

 一个重要的边缘情况是当`b = 0`。 在这种情况下，该过程根本不执行任何添加，因此唯一可能的结果是`a`。 该算法正确地处理了这个问题，因为`dfs(0)`回报`{0}`，意味着没有添加贡献，所以我们只接受`c == a`。 

另一种边缘情况发生在`b = 1`。 从这里开始，除以 2 或 4 会立即产生零，但该命令在终止之前仍然强制执行最终贡献 1。 递归正确地将其捕获为`1 + dfs(0)`，精确地产生`{1}`。 

第三种边缘情况涉及快速崩溃，例如`b = 3`。 一根树枝给出`3 // 2 = 1`，另一个给出`3 // 4 = 0`。 这创建了两条不同的路径，并且 DP 包括这两种贡献。 贪婪的选择在这里会失败，因为尽早选择较小的除法可以消除依赖于再一步保持较大值的可达总和。
