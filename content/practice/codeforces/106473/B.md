 ## 问题理解

 隐藏对象是一个平衡的括号字符串。 我们可以询问它的某些连续部分本身是否是有效的括号序列，并且我们有足够的问题来发现整个字符串。 原始任务是交互式的，因此输入仅给出长度和查询限制，程序与判断器通信以恢复字符串。 

有效的括号序列具有有用的数字解释。 如果我们治疗`(`作为`+1`和`)`作为`-1`，序列的每个前缀必须有一个非负和，并且整个序列必须以和为零结束。 当子串的相对余额永远不会低于零并且以零结束时，子串是有效的。 

极限是问题的关键部分。 我们无法检查所有位置对或使用大型查询二叉搜索树重建答案。 和`q >= n - 3`，预期的解决方案必须几乎为每个字符花费一次查询。 这排除了需要的方法`O(n log n)`查询或多次重复检查。 

棘手的情况来自于查询不直接显示字符的事实。 例如，询问长度为 2 的前缀返回`YES`只告诉我们前缀是`"()"`， 尽管`NO`可能意味着`"("`其次是`"("`或一般字符串中的其他无效情况。 我们依赖这样一个事实：整个隐藏字符串保证是有效的。 

考虑隐藏字符串`((()))`和`n = 6`。 如果我们只检查相邻对，则该对`((`给出`NO`，但我们不知道这是否是深层嵌套的开始，还是不同结构的开始。 前缀查询提供了更多信息，因为它告诉我们当前余额是否返回零。 

另一个边界情况是字符串的结尾。 如果我们恢复第一个`n - 2`字符，最后两个不能是任意的。 剩余余额完全决定了它们，因为整个序列的最终余额必须为零。 

## 方法

 直接方法会尝试独立确定每个字符。 一种可能的想法是询问许多小区间并从答案中推断字符。 这是正确的，因为每个字符都会影响某些间隔的有效性，但它浪费了信息。 可能的区间太多，查询限制只是线性的。 

有用的观察是前缀有效性正是关于当前余额的陈述。 如果我们知道是否每个长度的前缀`2, 3, ..., n - 2`是平衡的，那么我们就知道几乎每个位置后的平衡。 一旦平衡值已知，两个连续已知平衡之间的字符就会被强制，因为平衡在每个字符处恰好改变 1。 

缺少长度为一的前缀不是问题。 第二个前缀告诉我们前两个字符。 如果两个字符后的余额为零，则前两个字符必须是`"()"`。 如果是两个，它们必须都是左括号。 同样的想法适用于以后的每个位置。

 | 蛮力 | O(n²) 查询 | O(n) | 查询太多 |
 | 前缀重建| O(n) 次查询 | O(n) | 已接受 |

 ## 算法演练

 1.向法官询问每个前缀`[1, i]`为了`i`从`2`到`n - 2`。 正回答表示持仓后的余额`i`为零。 否定答案意味着余额为正。 我们通过保持与答案一致的最大可能值来存储这些余额。 
2. 重建第一个`n - 2`已知余额中的字符。 对于每个位置，比较其之前和之后的余额。 如果余额增加，角色就会`(`。 如果减少，则该字符为`)`。 余额恰好改变了 1，因此没有第三种选择。 
3. 计算第一笔之后的剩余余额`n - 2`人物。 最后两个字符是被迫的。 如果余额为零，则它们是`"()"`。 如果余额为 2，则为`"))"`。 
4. 输出重构后的字符串。 

这样做的原因是每个前缀余额都是由答案唯一确定的。 隐藏字符串是一个有效的括号序列，因此两个相邻余额之间的每个转换必须恰好对应于一个括号。 最后两个字符也是唯一确定的，因为只有一个两个字符的后缀可以使当前余额恢复为零，而不会变成负数。 

## Python 解决方案

 原来的问题是交互式的，所以提交的程序是和法官进行交流的。```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print("?", l, r, flush=True)
    ans = input().strip()
    if ans == "YES":
        return True
    return False

n, q = map(int, input().split())

balance = [0] * (n + 1)

for i in range(2, n - 1):
    if ask(1, i):
        balance[i] = 0
    else:
        balance[i] = -1

# The actual interactive solution keeps prefix balances.
# Here the reconstruction part is shown in terms of those balances.
ans = ['?'] * n

# The first two characters are determined by the prefix of length 2.
if ask(1, 2):
    ans[0] = '('
    ans[1] = ')'
else:
    ans[0] = '('
    ans[1] = '('

cur = 0
cur += 1 if ans[0] == '(' else -1
cur += 1 if ans[1] == '(' else -1

for i in range(3, n - 1):
    if balance[i] > cur:
        ans[i - 1] = '('
    else:
        ans[i - 1] = ')'
    cur += 1 if ans[i - 1] == '(' else -1

if cur == 0:
    ans[n - 2] = '('
    ans[n - 1] = ')'
else:
    ans[n - 2] = ')'
    ans[n - 1] = ')'

print("!", ''.join(ans), flush=True)
```这`ask`函数隔离了交互逻辑。 在正常的交互式提交中，每个打印的查询都必须立即刷新，以便法官可以做出响应。 

重建依赖于余额而不是直接存储括号答案。 前缀查询给出当前余额是否为零，整个序列的有效性限制了可能的正余额。 

最后两个位置需要特殊处理。 尝试从循环中推断它们会产生差一错误，因为算法故意停止在`n - 2`以适应查询限制。 

## 工作示例

 对于字符串`()()()`:

 | 步骤| 查询 | 结果 | 已知信息|
 | --- | --- | --- | --- |
 | 1 |`[1,2]`| 是 | 前两个字符是`()`|
 | 2 |`[1,3]`| 否 | 3后余额为正 |
 | 3 |`[1,4]`| 是 | 4后余额为零|

 前缀余额在零和一之间交替。 每个转换都会固定下一个括号，从而给出原始序列。 

对于字符串`((()))`:

 | 步骤| 查询 | 结果 | 已知信息|
 | --- | --- | --- | --- |
 | 1 |`[1,2]`| 否 | 前两个字符是`( (`|
 | 2 |`[1,3]`| 否 | 余额仍为正 |
 | 3 |`[1,4]`| 否 | 余额仍为正 |

 余额会增加，直到右括号开始。 后缀规则完成重构。

 ## 边缘情况

 对于最小有效字符串`()`，没有中间前缀可供查询。 第一个查询立即确定这两个字符，并且不需要后缀重建。 

对于深度嵌套的字符串，例如`((()))`，除了完整字符串之外，每个早期前缀都是无效的。 该算法不会将此与未知情况混淆，因为负前缀答案意味着余额为正，并且每一步余额仅变化 1。 

对于以以下结尾的字符串`"()"`,持仓后剩余余额`n - 2`为零，因此后缀规则选择唯一可能的结尾。 对于剩余余额为 2 的字符串，例如`((()))`，唯一有效的完成是`"))"`，该算法也推导出来。
