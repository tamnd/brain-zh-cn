 ## 解决方案
 ## 问题理解

 我们有一个由多个建筑物组成的系统，每个建筑物都与一个生产率相关。 时间在离散的日子里流逝，随着时间的增加，每座建筑都会按照自己的速度积累对“食物盒”的需求。 

固定天数$t$,每栋楼$i$需要一定数量的盒子，这取决于它在这些盒子上积累了多少$t$天。 从累积数量到盒子的转换不是线性的，因为食物是按固定尺寸单位包装的，因此每个建筑物的要求在除以恒定的包装尺寸后进行四舍五入。 所有建筑物所需的盒子总数不得超过给定的全球供应限制。 

任务是找到最大天数$t$以便所有建筑物所需的箱子总数保持在可用供应范围内。 

每栋建筑都会贡献更多的需求$t$增长，并且一旦超过供应限制，对于所有较大的值仍然超出$t$。 这种单调行为使得该问题适合对答案进行二分搜索。 

输入包括建筑物的数量、其各自的费率、包装参数以及可用盒子总数的全局限制。 输出是一个表示最大可行天数的整数。 

约束条件允许$t$一样大$10^{12}$，这立即排除了任何模拟日常增长的解决方案。 即使是全天进行一次线性检查也是不可能的。 相反，解决方案必须评估候选人的可行性$t$在$O(n)$，然后搜索一遍$t$使用对数数量的检查。 

重新计算每天累积量的幼稚解释将完全失败。 例如，如果$t = 10^{12}$，日复一日的迭代是不可行的。 如果尝试计算每日增量并累积浮点除法结果，则会出现另一种微妙的故障模式，因为必须精确处理向上舍入并且需要整数精度。 

## 方法

 蛮力方法首先尝试所有可能的天数$t$，从零开始，向上递增。 对于每位候选人$t$，我们计算每个建筑物需要多少食物，使用天花板除法将其转换为盒子，对所有建筑物进行求和，并检查总数是否在可用限制内。 

这种方法是正确的，因为它直接对需求的定义进行建模。 然而，它的运行时间随着最大可能的线性增长$t$，并且自从$t$可以达到$10^{12}$，即使每天一次评估也变得不可行。 瓶颈不是每次检查的成本，而是候选值的数量。 

关键的观察是可行性条件是单调的。 如果一定天数$t$是可行的，那么任何较小的天数也一定是可行的，因为每栋建筑的需求只会减少或保持不变。 这将问题转化为寻找可行值和不可行值之间的边界，这正是二分搜索的设计目的。 

一旦识别出这种结构，任务就减少为有效地检查候选者$t$并在大的数值范围内使用二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(t \cdot n)$|$O(1)$| 太慢了|
 | 二分查找+检查 |$O(n \log 10^{12})$|$O(1)$| 已接受 |

 ## 算法演练

 我们将问题视为决策函数$t$：给定天数，确定是否可以满足供应限制内的所有建筑物。 

### 步骤

 1. 定义一个函数`can(t)`计算是否$t$天是可行的。 对于每栋建筑$i$，使用其累积需求的上限除以计算其所需的盒子$t$按包装尺寸。 将所有这些值相加并与全局限制进行比较。 如果总和在任何时候超过限制，我们已经知道$t$无效，可提前停止。 
2.设置二分查找范围从$0$到$10^{12}$。 选择上限是因为任何可行的答案都必须位于问题的约束范围内，并且可行性函数在超出阈值后就会变得错误。 
3. 对该范围进行二分查找。 在每个中点$mid$， 评价`can(mid)`。 
4. 如果`can(mid)`是真的，存储$mid$作为潜在的答案并将搜索移至右半部分，因为我们正在尝试最大化$t$。 如果为假，则丢弃右半部分并继续左半部分。 
5. 二分查找完成后，存储的最佳值为最大可行天数。 

关键的实现细节是使用整数算术正确计算上限除法。 表达式$\lceil \frac{x}{y} \rceil$必须实施为$(x + y - 1) // y$以避免浮点错误。 

### 为什么它有效

 正确性取决于单调性。 作为$t$增加，每栋建筑的累计需求线性增加，四舍五入到离散的盒子后，只能保持不变或增加。 因此，所需的盒子总数是一个非减函数$t$。 这保证了可行性谓词从 true 到 false 的转换恰好一次，形成有效值的连续前缀。 二分查找正确识别了该前缀的边界，保证了最大有效$t$被发现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(t, a, x, b):
    total = 0
    for ai in a:
        total += (ai * t + x - 1) // x
        if total > b:
            return False
    return True

def solve():
    n, x, b = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 0, 10**12
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, a, x, b):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将可行性检查与搜索逻辑分开。 这`can`函数编码了问题的整个物理解释：需求如何随着时间的推移而扩展以及如何将其离散化为盒子。 

二分查找保持了以下所有值的不变性：`lo`仅当先前观察到并且所有值都正确时才是可行的候选者`hi`是不可行的。 更新步骤根据单调检查移动这些边界。 

早点停在里面`can`很重要，因为总数可能会变大，并且超过`b`使得进一步的计算变得不必要。 

## 工作示例

 ### 示例 1

 假设有 2 栋建筑物，包装尺寸为 3，限制为 10。比率为 [2, 5]。 

我们测试不同的值$t$:

 | t | 1 号楼 | 2 号楼 | 总计 |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 3 |
 | 2 | 2 | 4 | 6 |
 | 3 | 2 | 5 | 7 |
 | 4 | 3 | 7 | 10 | 10
 | 5 | 4 | 9 | 13 |

 最大可行值为$t = 4$。 

该轨迹显示了上限效应如何导致需求分段跳跃，而不是平滑的线性增长。 

### 示例 2

 现在考虑速率 [1, 1, 1]，包装尺寸 2，限制 5。 

| t | 每栋楼 | 总计 |
 | --- | --- | --- |
 | 1 | 1 | 3 |
 | 2 | 1 | 3 |
 | 3 | 2 | 6 |

 答案是$t = 2$，表明多个值$t$由于四舍五入，可以映射到相同的总数。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n \log 10^{12})$| 对答案范围进行二分搜索，每次可行性检查都会扫描所有建筑物一次 |

 对数因子很小（大约 40），因此该解在实践中几乎呈线性$n$。 这可以轻松满足最多的典型约束$10^5$建筑物。

# all equal rates

 ## 边缘情况

 当限制极小时，就会出现一种微妙的边缘情况。 例如，如果允许的盒子总数为 1，即使是最小的建筑物也已经需要超过 1 个盒子$t = 0$，正确答案是 0。二分查找必须正确处理这个问题，而不假设$t = 1$最初总是可行的。 

另一种情况是所有利率为零。 在这种情况下，每座建筑物的贡献始终为零，无论$t$，因此可行性函数在最大范围内始终为真。 二分查找应该正确返回$10^{12}$无溢出或过早停止。 

第三种情况涉及大$t$结合小包装尺寸，其中中间值$ai \cdot t$可以溢出 32 位整数。 使用 Python 自然可以避免这个问题，但在其他语言中，这需要 64 位算术来防止错误的上限计算。 

这些情况都得到了正确处理，因为该算法从不依赖于随时间的增量更新，并且总是直接根据定义重新计算每个状态$t$。
