 ## 解决方案
 ## 问题理解

 我们给出了一种排列，它可以被视为一个有向图，其中每个节点都只有一个出边。 这种结构分解为不相交的有向循环。 每个循环代表一组相互轮换的位置。 

在这种排列之上还有赛车游戏的解释。 我们可以执行一个操作，将一个周期有效地分成两个较小的周期。 关键的自由来自于这样一个事实：我们可以在包含起始位置的循环内选择一个特殊的检查点，这让我们可以控制分裂发生的位置，从而我们可以打破一个长度的循环`L`成更小的周期长度的任意组合，只要它们的总和为`L`。 

目标是让所有参赛者在完成一定步数后同时完成比赛`x`。 从循环的角度解释这一点，这意味着每个循环都必须转换为长度恰好为的循环`x`，因为一个周期的长度`x`准确返回到起点`x`步骤，并且同步要求所有组件共享该周期。 

因此，输入描述了排列，输出是将所有周期转换为允许同步完成的公共大小的周期所需的最小操作数。 

从约束的角度来看，排列大小通常很大，可达约`2 × 10^5`在 Codeforces 风格的问题中。 这立即排除了任何二次方`n`，甚至线性扫描也必须仔细构造，以便每个元素仅被处理恒定的次数。 任何重复模拟分裂循环的方法都是不可行的，因为单个循环可能很大并且会被破坏多次。 

当排列已经是一个循环时，就会出现微妙的边缘情况。 在这种情况下，只有一个周期长度，因此同步很容易受到该长度的限制。 另一种边缘情况是所有循环已经具有相同的长度。 那么除了验证可行性之外不需要分裂，答案就变成了零操作。 

例如，如果排列由长度循环组成`[3, 3, 3]`，一旦决定就不需要进行任何操作`x = 3`。 粗心的方法可能仍然会尝试不必要地“调整”周期，而没有认识到当条件已经满足时不需要拆分。 

## 方法

 蛮力视角首先直接考虑需求：选择目标周期大小`x`，然后模拟将每个周期分割成大小的片段`x`。 对于一个周期长度`L`，我们会反复将其切成段，直到所有碎片都达到尺寸`x`，假设这是可能的。 每次切割都会增加周期数，我们将计算给定的所有周期需要多少次操作`x`。 

这种方法原则上是正确的，因为它直接镜像了允许的操作，但是它变得太慢了，因为对于每个候选者`x`我们需要处理每个循环并模拟重复的分裂。 在最坏的情况下，尝试一切可能`x`最多`n`导致不可行的`O(n^2)`或更糟糕的行为。 

关键的结构观察是周期是独立的，每个周期贡献的成本仅取决于其长度和所选的`x`。 如果一个循环有长度`L`，只能分割成大小相等的块`x`如果`L`可以整除`x`，在这种情况下，它正好需要`(L / x - 1)`分裂。 对所有周期求和得出固定的总成本`x`。 

现在问题变成了选择`x`划分每个周期长度，同时最小化总操作。 自从`(L / x - 1)`减少为`x`增加，最好的选择是最大的有效`x`。 除以所有周期长度的唯一值是其最大公约数的除数，因此最佳值`x`是`g = gcd(l1, l2, ..., lc)`。 

一次`g`是固定的，答案只是周期的总和`(li / g - 1)`，可以简化为`sum(li / g) - c`，或等价地`1 + sum(li / g - 1)`取决于原始公式中最终计数的解释方式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟所有x | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 循环+GCD优化 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ## 算法演练

 1. 将排列分解为不相交的循环并计算它们的长度。 这是系统的自然表示，因为每个元素恰好属于一个循环轨道。 
2. 计算所有周期长度的最大公约数。 这捕获了可以一致地划分每个周期的最大周期大小，确保可以在所有组件之间进行统一划分。 
3. 对于每个周期长度`l`，计算有多少段大小`g`它可以分为`l / g`。 每个这样的循环都需要`l / g - 1`操作，因为每个操作都会将该周期中的段数增加 1，直到到达最终分区。 
4. 将所有周期中的这些值相加，以获得将系统完全规范化为长度周期所需的操作总数`g`。 
5. 输出总和，表示同步所有周期所需的最少操作数。 

步骤 2 有效的原因是任何有效的目标大小必须除以所有周期长度，并且在所有此类除数中，较大的值严格减少每个周期所需的分割数量。 

### 为什么它有效

 每个循环在允许的操作下独立发展，这意味着一个循环内的操作不会影响其他循环，除非通过所有最终循环长度必须匹配的全局约束。 一个周期的长度`L`只能分解为大小相等的部分`x`如果`x`划分`L`，并且分裂过程总是减少一个周期的大小`k·x`分成两个周期，其大小总和为`k·x`。 反复应用表明，`k - 1`需要拆分才能达到`k`大小周期`x`。 因此，每个周期的成本公式都是精确的，并且由于独立性，各个周期的求和是有效的。 最大化`x`同时最小化每个周期的成本，并且在所有周期中保持可行性的唯一候选者是它们长度的 gcd。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    vis = [False] * n
    cycles = []

    for i in range(n):
        if not vis[i]:
            cur = i
            cnt = 0
            while not vis[cur]:
                vis[cur] = True
                cur = p[cur] - 1
                cnt += 1
            cycles.append(cnt)

    g = 0
    for c in cycles:
        g = math.gcd(g, c)

    ans = 0
    for c in cycles:
        ans += c // g - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先通过遍历未访问的节点来提取循环长度。 这保证了每个元素只被处理一次，因为每个元素都属于一个周期。 

gcd 计算聚合了循环约束，确保我们选择最大的可行统一段大小。 最后一个循环使用整数除法计算每个周期的分裂成本，这与理论值相匹配`(li / g - 1)`公式。 

一个常见的实施错误是忘记每个周期减一，这会导致周期数计数过多。 另一个微妙的问题是循环遍历期间的索引，其中忘记从基于 1 的索引转换为基于 0 的索引会破坏循环重建。 

## 工作示例

 考虑循环长度的排列`[4, 2]`。 

我们首先计算gcd，即`g = 2`。 

| 周期长度| 克| 段（升/克）| 操作 (l/g - 1) |
 | --- | --- | --- | --- |
 | 4 | 2 | 2 | 1 |
 | 2 | 2 | 1 | 0 |

 总的答案是`1`。 

这表明只有长度为4的循环需要一次分割，而长度为2的循环已经与目标结构对齐。 

现在考虑单个周期的长度`[6]`。 

| 周期长度| 克| 段（升/克）| 操作 (l/g - 1) |
 | --- | --- | --- | --- |
 | 6 | 6 | 1 | 0 |

 这里的 gcd 是 6，意味着根本不需要分裂。 这证实了当所有结构都已经统一时，算法正确地返回零。

 ## 边缘情况

 完全由定点组成的排列产生的循环长度全部等于 1。gcd 为 1，每个循环都贡献`1/1 - 1 = 0`，所以总答案为零。 该算法直接处理这个问题，无需特殊的外壳。 

单个大循环，例如`n = 10`长度为 10 的一个周期产生等于 10 的 gcd，再次产生零操作。 这证实了当结构已经最大程度对齐时，算法不会错误地尝试不必要的分割。 

类似循环的混合结构`[6, 4, 2]`说明了gcd选择的重要性。 gcd 为 2，只有选择这个值，所有循环才可以分成相等的段，从而确保整个排列结构的一致性。
