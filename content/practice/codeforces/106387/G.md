 ## 解决方案
 ## 问题理解

 我们得到一张图表，其中城市由道路连接，每条道路都有相关的危险值。 一些城市被标记为里程碑城市。 任务是确定尽可能小的危险阈值，这样如果我们只使用危险不超过该阈值的道路，所有里程碑城市最终都会在同一个连接组件内连接。 

换句话说，我们并不是试图优化路径或权重总和。 我们试图找到边权重的截止值，使重要节点的子集可以相互访问。 

输入可以解释为无向加权图。 仅当我们允许其权重级别时，每条边才会贡献连接性，并且当我们增加允许的阈值时，更多的边变得可用，并且连接的组件合并。 输出是所有特殊节点属于一个连接组件的最小阈值。 

从复杂性的角度来看，图结构和边计数意味着任何以简单方式每次查询重复扫描所有边的解决方案都是昂贵的。 如果我们想象多达 10^5 个节点和边，那么即使重复多次的线性扫描也会出现问题。 然而，使这个问题变得容易解决的关键约束是边权重要么很小要么可以排序，并且连通性相对于阈值是单调的。 

一种简单的方法是尝试每个可能的阈值并运行完整的图遍历来检查里程碑节点之间的连接性。 这在逻辑上是可行的，但如果重量范围很大，就会变得很慢。 

当里程碑节点已经在阈值零处连接或当它们被隔离直到最大边缘权重时，会出现微妙的边缘情况。 另一个重要的情况是当只有一个里程碑城市时； 那么答案几乎为零，因为它已经与自身“连接”了。 最后一个极端情况是，即使在允许所有边之后，里程碑节点也位于单独的组件中，在这种情况下，没有阈值就足够了，尽管此问题的典型版本假设在完整图级别保证连接性。 

## 方法

 蛮力的想法很简单：选择一个候选危险阈值 V，丢弃所有权重大于 V 的边，然后运行 BFS 或 DFS 来确定所有里程碑城市是否位于同一连接组件中。 由于在预期约束中 V 的范围为 1 到 100，因此对所有值重复此操作就足够了。 

这是可行的，因为连接是单调的。 如果所有里程碑节点都使用权重最多为 V 的边连接，那么它们在任何更大的阈值内都保持连接。 故障条件也会向相反方向传播：如果它们在 V 处断开，则对于较小的值，它们将保持断开状态。 

这种方法的成本主要是对每个可能的 V 运行完整的图遍历。每次遍历的成本为 O(N + M)，最多执行 100 次会导致 O(100(N + M))，这是可以接受的。 

如果权重范围较大，迭代所有值将变得低效。 关键的观察是，我们正在有效地搜索最小值 V，使得谓词变为真，并且该谓词是单调的。 这立即表明要么对 V 进行二分搜索，要么采用按边权重递增顺序构建连接的结构方法。 

二分查找的时间复杂度为 O((N + M) log W)，但更直接、更干净的解决方案是模拟 Kruskal 算法。 如果我们按权重对边进行排序并逐渐激活它们，我们可以使用不相交的集合并集结构来维护连接的组件。 当我们合并组件时，我们还跟踪每个组件中包含多少个里程碑节点。 当一个组件包含所有里程碑节点时，当前的边权重就是答案。

这与构建最小生成森林的逻辑完全相同，只是当满足节点子集上的全局连接条件时我们会提前停止。

 | --- | --- | --- | --- |
 | 暴力破解（每 V 的 DFS）| O(100(N + M)) | O(N + M) | 已接受 |
 | 克鲁斯卡尔 + DSU | O(M log M) | O(M log M) | O(N) | 已接受 |

 ## 算法演练

 我们使用不相交的集合并集结构，当我们以危险递增的顺序处理边缘时，它会维护连接的组件。 

1. 阅读图表并标记哪些节点是里程碑城市。 计算总共存在多少个里程碑节点，因为这将是我们的目标组件大小。 
2. 初始化 DSU，其中每个节点最初位于其自己的集合中。 对于每个集合，维护其当前包含的里程碑节点数。 最初，每个里程碑节点为其自己的集合计数贡献 1。 
3. 通过增加危险值对所有边进行排序。 这确保了当我们合并组件时，我们始终首先使用尽可能小的边缘，这反映了逐渐放宽阈值的想法。 
4. 按排序顺序迭代边。 对于连接 u 和 v 且权重为 w 的每条边，找到它们的 DSU 代表。 如果它们已位于同一组中，请跳过它，因为它不会更改连接性。 
5. 如果它们在不同的集合中，请将它们合并。 合并时，将两个组件的里程碑计数相加到新的根中。 
6. 每次合并后，检查生成的组件是否包含所有里程碑节点。 如果是，则当前边权重 w 是连接所有里程碑城市的最小阈值，因此我们立即返回 w。 
7. 如果我们完成所有边的处理而没有到达包含所有里程碑节点的组件，那么所有里程碑永远不会在可用边下完全连接，并且根据问题保证，答案将是不确定的。 

它的工作原理来自于排序边缘插入下连接组件的单调增长。 在任何时候，DSU 都准确地表示图的连通性，该连通性仅限于权重最多为当前处理阈值的边。 由于我们按升序处理边，因此所有里程碑节点第一次出现在一个组件中对应于可以实现这种连接的最小阈值。 后面的步骤不能产生更小的有效阈值，因为所有先前的边缘都严格小于或等于并且已经被考虑。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, is_milestone):
        self.parent = list(range(n))
        self.size = [1] * n
        self.milestones = [1 if is_milestone[i] else 0 for i in range(n)]
    
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    
    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return ra
        
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.milestones[ra] += self.milestones[rb]
        return ra

def solve():
    n, m, k = map(int, input().split())
    milestones = [False] * n
    ms = list(map(int, input().split()))
    for x in ms:
        milestones[x] = True

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((w, u, v))

    dsu = DSU(n, milestones)
    total_ms = sum(milestones)

    edges.sort()

    for w, u, v in edges:
        root = dsu.union(u, v)
        if dsu.milestones[root] == total_ms:
            print(w)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```DSU 结构维护连接性和每个组件的里程碑节点数量。 联合操作更新大小和里程碑计数，这很重要，因为停止条件取决于跟踪合并组件内有多少特殊节点。 

排序步骤确保我们第一次达到里程碑节点的完全覆盖对应于最小可能的阈值。 早期退出是安全的，因为任何后续合并仅涉及具有更大或相等权重的边。 

一个常见的实施陷阱是忘记仅在联合后更新根处的里程碑计数。 另一个是如果输入是从 1 开始的，则不会标准化节点索引。

 考虑一个具有 4 个节点和 3 个边的图，其中节点 1 和 4 是里程碑。 

边缘：

 (1-2，w=2)，(2-3，w=3)，(3-4，w=5)

 里程碑：{1, 4}

 ### 追踪

 | 步骤| 边缘 | 联合后的组件 | 里程碑很重要| 都连接了吗？ |
 | --- | --- | --- | --- | --- |
 | 1 | (1,2,2) | (1,2,2) | {1,2}、{3}、{4} | 1, 0, 1 | 1, 0, 1 | 没有 |
 | 2 | (2,3,3) | {1,2}、{2,3}、{4} 合并 -> {1,2,3}、{4} | 1, 1 | 没有 |

此跟踪显示了 DSU 如何逐渐扩展连接性以及里程碑计数器如何跨合并进行聚合，直到达到全局要求。

 ## 边缘情况

 一种重要的边缘情况是只有一个里程碑节点。 在这种情况下，DSU 会在该节点已满足包含所有必需里程碑的条件的情况下进行初始化。 正确的行为是立即返回零，因为不需要边将单个节点连接到其自身。 

另一种情况是里程碑仅通过高权重边连接。 DSU 将首先合并较小的组件，但在处理最终必要的边缘之前，里程碑计数器不会达到全部总数。 这确保了答案正确反映最小连接结构中的最大边缘。 

最后一种情况是多个组件包含里程碑节点的子集。 该算法自然地处理这个问题，因为里程碑计数是在联合期间聚合的，并且只有第一次联合创建覆盖所有里程碑的组件时才会触发答案。
