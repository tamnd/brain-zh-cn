 ## 解决方案
 ## 问题理解

 我们需要构建一系列新郎命运，以便公主按照要求的方式做出反应。 

对于第一位新郎之后的每一位新郎来说，都可能出现两种特殊情况。 

公主说，如果当前的财富比之前的每一次财富都大`Oh...`。 

如果当前的财富大于之前所有财富的总和，公主说`Wow!`反而。 一个`Wow!`取代`Oh...`，两者均不计算在内。 

第一个新郎从来没有做出任何反应。 

我们被给予`n`，新郎的数量，以及确切的数量`Oh...`反应`a`和`Wow!`反应`b`。 任务是输出任意有效的财富序列`1`和`50000`， 或者`-1`如果不存在这样的序列。 

限制很小。 两个都`a`和`b`至多是`15`， 和`n`至多是`100`。 这意味着对任意数组的暴力搜索仍然会爆炸，因为每个位置可能包含最多`50000`选择。 简单的回溯解决方案是完全不可行的。 另一方面，小的限制强烈表明预期的解决方案是建设性的。 我们应该直接构建一个有效的序列，而不是搜索一个。 

棘手的部分是`Wow!`比`Oh...`。 

假设之前的财富总和为`S`当前最大值是`M`。 

如果我们选择一个值：

 -`x <= M`，没有任何反应。 
-`M < x <= S`，我们得到`Oh...`。 
-`x > S`，我们得到`Wow!`。 

这立即揭示了一个重要的事实。 生产一个`Oh...`，我们需要先前的总和严格大于当前的最大值。 否则间隔`(M, S]`是空的。 

例如：

 输入：```
3 1 1
```粗心的构造可能会尝试：```
1 2 3
```但这给出了两个`Wow!`反应，因为：

 -`2 > 1`-`3 > 1+2`从来没有一个`Oh...`。 

另一个容易犯的错误是忘记重复的小值是有用的填充符。 

例如：

 输入：```
5 0 0
```严格递增的序列会立即失败。 正确的想法是保持所有值相等：```
7 7 7 7 7
```没有值超过之前的最大值，因此根本没有反应。 

当我们想要太多时，就会出现一种更微妙的边缘情况`Oh...`相对于的反应`Wow!`。 

考虑：```
3 2 0
```这是不可能的。 

没有任何`Wow!`，如果所有数字都相同，则第一个元素之后的总和和最大值保持相等。 甚至创造一个`Oh...`，我们首先需要总和大于最大值。 快速增加总和的唯一机制是`Wow!`。 

这就引出了关键的可行性条件：```
a <= b + 1
```如果此条件失败，则不存在任何构造。 

## 方法

 最直接的暴力方法是尝试生成所有可能的数组并模拟每个数组的公主反应。 模拟本身很容易。 我们维护当前的最大值和前缀和，然后将每个新值分类为三个类别之一。 

问题在于搜索空间。 即使我们将财富限制为以下值`1`到`10`，数组的数量已经是`10^100`在最坏的情况下。 没有机会探索那个空间。 

反应的结构给出了更好的方向。 每个反应仅取决于前缀中的两个量：

 - 当前最大值
 - 当前前缀和

 一个`Wow!`两者都大幅增加，因为新值超过了之前的总和。 一个`Oh...`仅增加最大值，同时保持在当前总和之内。 

关键的观察是，经过一段时间后`Wow!`，前缀和变得比最大值大得多。 这为未来创造了空间`Oh...`反应。 

例如：```
1
```当前总和 = 1，最大值 = 1。 

如果我们附加：```
2
```我们得到一个`Wow!`。 

现在：```
sum = 3
max = 2
```终于有空间了`Oh...`，因为值在`(2, 3]`存在。 

追加：```
3
```产生一个`Oh...`。 

在那之后：```
sum = 6
max = 3
```又有空间容纳另一个`Oh...`。 

这种模式表明了一种干净的结构：

 - 开始于`1`。 
- 生产每一个`Wow!`使用`sum + 1`。 
- 每次之后`Wow!`，可选地产生一个`Oh...`准确地使用`sum`。 

因为每个`Wow!`为一位有保证的人创造空间`Oh...`，最大数量`Oh...`反应是`b + 1`。 这正是可行性条件。 

创建所有必需的反应后，我们用以下内容填充剩余位置`1`，它永远不会触发任何东西，因为最大值已经至少`1`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 检查是否`a > b + 1`。 

如果发生这种情况，请打印`-1`。 每一个`Wow!`最多可以为一个新人创造空间`Oh...`，并且还可能有一个初始`Oh...`在任何之前`Wow!`。 
2. 开始序列`1`。 

第一个新郎不会引起任何反应，所以这是最简单的开始。 
3.维护两个变量：

 -`s`, 当前前缀和
 -`mx`，当前最大
 4. 如果`a > 0`, 创建一个首字母`Oh...`。 

附加`1`仅当我们不想再次`Oh...`。 否则我们需要一个大于最大值但不大于总和的值。 最初两者都是`1`，所以这是不可能的。 

创建第一个的唯一方法`Oh...`是在一个之后`Wow!`。 
5. 重复`b`次数：

 - 追加`s + 1`。 
- 这保证了`Wow!`，因为新值超过了之前的总和。 
- 更新`s`和`mx`。 
6. 每次之后`Wow!`，如果我们还需要更多`Oh...`反应：

 - 追加`s`。 
- 自从`mx < s <= s`，这会产生一个`Oh...`。 
- 更新`s`和`mx`。 
7. 填写所有剩余位置`1`。 

由于最大值已经远大于`1`，这些位置不会产生任何反应。 

### 为什么它有效

 该结构保持简单的不变量。 

每当我们附加`s + 1`，新值大于整个先前的前缀和，因此反应总是`Wow!`。 

每当我们附加`s`，之前的最大值严格小于`s`，因为最后`Wow!`他们之间产生了差距。 新值不大于先前的总和，因此反应恰好是`Oh...`。 

所有填充值均为`1`，永远不会超过当前最大值。 

的计数为`Wow!`和`Oh...`独立控制，每个附加数字都完全达到预期效果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())

    if a > b + 1:
        print(-1)
        return

    ans = [1]

    s = 1
    mx = 1

    oh_used = 0
    wow_used = 0

    for _ in range(b):
        x = s + 1
        ans.append(x)

        wow_used += 1
        s += x
        mx = x

        if oh_used < a:
            x = s
            ans.append(x)

            oh_used += 1
            s += x
            mx = x

    while len(ans) < n:
        ans.append(1)

    print(*ans[:n])

solve()
```第一个条件是可行性检查。 如果`a > b + 1`，不存在构造，因为每个`Wow!`最多为一个未来创造空间`Oh...`。 

序列开始于`1`因为它使以后的所有计算变得简单。 变量`s`和`mx`跟踪当前前缀总和和最大值。 

循环生成`Wow!`反应附加`s + 1`。 由于该值大于之前的总和，因此总是会触发`Wow!`。 

紧接着，如果更多`Oh...`仍然需要反应，我们准确附加`s`。 此时当前的最大值严格小于`s`，因此新值成为新的最大值，且不超过前缀和。 这正是以下的定义`Oh...`。 

填充循环附加`1`直到数组达到长度`n`。 这些值安全地低于当前最大值，并且不会影响反应计数。 

一个微妙的问题是更新的顺序。 在构造下一个值之前，我们必须在每次追加之后更新前缀和。 使用过时的值将完全改变反应分类。 

另一个微妙的点是切片`ans[:n]`。 如果出现以下情况，施工可能会暂时创建比需要更多的元素`n`接近于`a + b + 1`。 声明保证`n > a + b`，因此截断仍然是安全的。

 ## 边缘情况

 考虑：```
3 2 0
```我们需要两个`Oh...`有反应但没有`Wow!`。 

最初：```

max = 1
```最大值与总和之间不存在严格的整数。 没有一个`Wow!`，那个间隙永远不会出现。 该算法检测到：```

```并正确输出：```

```现在考虑：```

1 1 1 1 1
