 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$网格与一些阻塞的单元格。 杰拉德只能在边界单元上放置筹码，但角落是禁止的起始位置。 放置筹码后，每个筹码一步步移动，精确到$n-1$分钟，总是移动到相邻的单元格，并且移动使得每个芯片最终到达网格的另一侧。 

运动在结构上是确定性的：每个芯片有效地沿直线路径从边界一侧精确地移动到另一侧$n-1$步骤。 然后规则引入了三种失败条件。 芯片绝不能进入被阻塞的单元，两个芯片不能同时占据同一个单元，并且两个芯片不能在一步中交换位置。 

目标是选择尽可能多的起始边界位置，以便同时满足所有这些约束。 

重要的结构含义是，每个有效的芯片布局都定义了从一个边界边缘到另一边缘的固定“路线”，而碰撞完全取决于这些路线在时间上如何相交。 

这些约束足够大，任何试图逐步模拟切屑运动的解决方案都立即不可行。 和$n \le 1000$直至$10^5$如果单元被阻塞，对所有路径或所有路径对的简单模拟将太慢。 任何超出粗略范围的事情$O(n^2)$预处理已经很严格，任何涉及许多路径之间的成对交互检查的事情都将是灾难性的。 

一些微妙的边缘情况很容易被忽视。 

一种情况是，被阻塞的细胞形成“瓶颈”，将边界入口与另一侧断开。 例如，如果中心柱被阻止通过，那么即使起始单元本身是空闲的，放置在该侧的芯片也不会成功。 

另一种情况是多个起始位置共享同一个强制走廊。 即使每条路径单独避开阻塞的单元，两条这样的路径仍然可能在中间发生冲突，因为它们会聚。 

最后，交换是一个隐藏的约束，本质上禁止在同一走廊上沿相反方向进行对称遍历，这排除了在某些配置中沿同一行从左到右和从右到左条目的配对。 

## 方法

 直接的暴力方法将尝试对每个可能的起始位置进行建模并模拟其完整轨迹。 对于每个起始边界单元，我们可以计算其穿过网格的路径，然后检查与所有其他路径的交互。 由于每条路径都有长度$O(n)$并且有$O(n)$边界位置，这已经给出了$O(n^2)$工作只是为了生成路径，成对碰撞检查增加了另一个因素，导致$O(n^3)$最坏情况下的行为。 和$n = 1000$，这是完全不可行的。 

关键的观察结果是，芯片移动不是任意的：每个有效芯片都定义了穿过网格的固定走廊，并且冲突不是全局的，而是共享约束结构的局部冲突。 网格结构意味着每个芯片有效地对应于选择边界单元并遵循确定性链穿过相邻单元直到到达相反的边界。 

我们不考虑时间演化，而是翻转视角：每个单元都可以被视为指向行进方向上的唯一后继单元，除非被阻塞的单元中断了流动。 这将问题转化为计算可以选择多少个不相交的“有效链”而不重叠或冲突。 

一旦识别出这种结构，任务就会简化为边界条目上的匹配式选择问题，其中每个条目有效或无效，具体取决于其诱导路径是否到达另一侧而不触及禁止的单元格。 交换和碰撞约束确保我们不能采用对称走廊的两个方向，从而有效地强制每个连接结构一个选择的规则。 

我们计算所有有效的起始边界位置，然后按它们所属的走廊结构对它们进行分组，并每组最多选择一个。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(n^3)$|$O(n^2)$| 太慢了 |
 | 减少走廊/组件|$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 1. 将每个边界非角单元建模为潜在的起始节点。 我们忽略角点，因为它们被明确禁止，否则会引入不明确的方向选择。 
2. 对于每个起始单元，模拟其在网格上的强制移动，直到它到达相反的边界或碰到阻挡的单元。 该模拟遵循确定性规则：在每一步，只有一个有效的下一个单元格与直接穿过网格一致。 
3. 如果在仿真过程中芯片进入阻塞单元，则立即丢弃该起始位置。 这在本地强制执行第一个失败条件，而不需要全局推理。 
4. 在模拟有效路径时，记录访问过的单元的序列，或者更有效地，将每条路径分配给代表其走廊的标识符。 走廊可以通过其“入口线”和遍历方向来定义。 
5. 为了防止冲突和交换冲突，请将每个走廊视为单个资源。 如果多个起始位置映射到同一个走廊，则只能在那里放置一个芯片，因为任何第二个芯片都会在内部发生碰撞或产生对称交换场景。 
6. 计算至少具有一个有效起始边界单元的不同走廊的数量。 
7. 返回此计数作为答案，因为我们可以在每个有效走廊最多放置一个筹码，并且我们始终可以独立实现该放置。 

### 为什么它有效

 每个芯片路径完全由其起始边界位置和网格约束决定。 当且仅当它们的诱导路径在时空中重叠时，两个芯片才会发生冲突，在这种确定性的直线运动中，这会减少到属于相同的底层走廊结构。 通过将所有起始位置折叠为由相同遍历路线定义的等价类，我们确保两个选定的芯片不会交互，因为不同的类永远不会以冲突的方式相交，并且相同的类永远不会被选择多次。 这同时保留了所有三个故障条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    banned = set()
    for _ in range(m):
        x, y = map(int, input().split())
        banned.add((x - 1, y - 1))

    # Directions: we only care about straight corridors from one side to opposite.
    # We simulate from all non-corner boundary cells.
    dirs = []

    # top row (excluding corners): go down
    for j in range(1, n - 1):
        dirs.append((0, j, 1, 0))

    # bottom row: go up
    for j in range(1, n - 1):
        dirs.append((n - 1, j, -1, 0))

    # left column: go right
    for i in range(1, n - 1):
        dirs.append((i, 0, 0, 1))

    # right column: go left
    for i in range(1, n - 1):
        dirs.append((i, n - 1, 0, -1))

    used_corridors = set()
    ans = 0

    for sx, sy, dx, dy in dirs:
        x, y = sx, sy
        ok = True

        visited = []

        for _ in range(n - 1):
            if (x, y) in banned:
                ok = False
                break
            visited.append((x, y))
            x += dx
            y += dy

        if not ok:
            continue
        if (x, y) in banned:
            continue

        # corridor identity: endpoints define the path uniquely in straight movement
        start = (sx, sy)
        end = (x, y)
        key = (start, end)

        if key not in used_corridors:
            used_corridors.add(key)
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现构造了所有可能的直线边界遍历，并检查每个边界遍历是否在没有碰到阻塞单元的情况下幸存下来。 每次遍历都由其开始和结束边界位置表示，这唯一地标识了确定性运动下的走廊。 

循环完全运行$n-1$每个方向的步数，符合运动要求。 任何对禁止单元的访问都会立即使该路径失效。 最后的重复数据删除步骤可确保结构相同的路由不会被重复计算。 

一个微妙的点是，角点被排除在生成之外，因为否则它们会引入对角线歧义：从角点开始并不能根据问题的规则定义有效的“直走廊”，并且会错误地夸大答案。

 ## 边缘情况

 关键的边缘情况是当单个阻塞单元位于所有直线边界到边界路径上时。 在这种情况下，每个模拟轨迹都会在同一步骤失败。 该算法自然地处理这个问题，因为每个模拟在每一步都会独立检查禁用单元，因此所有候选单元都会被一致拒绝，而不需要全局推理。 

另一种情况是多个起始位置导致相同的终点。 这些通过走廊键折叠，确保我们不会过多计算对称遍历。 

最后，没有阻塞单元的网格代表最大密度情况，其中每个非角边界单元产生有效的独立走廊。 该算法直接对所有数据进行计数，不受重复数据删除结构的干扰。
