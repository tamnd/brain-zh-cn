 ## 解决方案
 ## 问题理解

 我们被要求构建一个 8 位字符串的大集合，其中每个字符串都是一张“票”。 如果可以在每张票的数字之间插入算术运算并将结果表达式完全括起来以使最终值等于给定的目标数字，则每张票被视为有效$k$。 允许的运算是加法、减法和乘法，并且数字必须按其原始顺序使用，尽管根据我们如何放置运算和括号，它们可以分为多位数字。 

关键是我们不会被要求检查单张机票的有效性。 相反，我们必须生产$m$不同的 8 位字符串，对于同一固定目标，所有这些字符串在强算术意义上都是有效的$k$。 如果存在许多有效门票，则任何$m$不同的是可以接受的。 

输出空间巨大：从 00000000 到 99999999 的所有 8 位字符串。但是，只需要一小部分。 该保证至少确保$m$有效票证是存在的，所以我们不需要证明完整性，只需要构造一个足够大的有效族。 

限制条件很大：$m$可以达到$3 \cdot 10^5$，这会立即排除任何每票昂贵的验证，例如为每个候选字符串运行完整的表达式 DP。 甚至$O(2^8)$每张票乘以$m$会太慢。 相反，我们必须设计一个通过构造来保证有效性的结构。 

出现微妙的边缘情况时$k = 0$。 在许多表达式问题中，零的表现很特殊，因为减法和乘法可以很容易地以多种方式崩溃到零。 假设积极性或单调结构的天真的方法在这里会失败。 另一个隐藏的陷阱是前导零：允许以零开头，因此像 00000000 这样的字符串是有效的输出，必须自然处理而不是过滤掉。 

核心困难不是计算表达式，而是设计一种系统的方法来分配数字，以便我们可以生成许多不同的票，同时保留始终达到的固定可评估结构$k$。 

## 方法

 暴力策略会尝试生成 8 位字符串并测试每个字符串是否可以转换为等于$k$。 对于单张票据，检查有效性需要考虑将数字拆分为数字的所有方式以及插入运算符和括号的所有方式。 This is a classic expression-formation DP with complexity roughly exponential in the number of digits due to partitioning and parenthesization. Even with memoization, each ticket costs substantial computation.

 高达$10^8$可能的门票和$3 \cdot 10^5$所需的输出，暴力是完全不可行的。 如果没有昂贵的验证，即使是随机抽样也不能保证成功，并且验证每个候选者在运行时占据主导地位。 

关键的观察是我们不需要“解决”任意问题。 我们只需要构建保证具有代表性的票证即可。 这建议修复严格的表达式模板并将票据数字嵌入到该模板的部分中，以便表达式始终计算为$k$，不管大多数数字。 

关键的结构思想是将表达分离成一个固定的“核心”，以强制执行价值$k$，以及一个大的“中性”组件，可以吸收任意数字选择而不改变最终值。 乘以零、加法抵消或乘以受控的零表达式使我们能够将数字自由度与表达式值解耦。 

一个特别有用的构造是强制表达式计算为固定值的总和$k$加上几个独立的项，它们的计算结果都保证为零。 每张 8 位数字票都可以在这些零项中编码任意选择，从而为我们提供足够的组合自由度来生成$10^5$或更容易地获得更多不同的门票。 

这将问题从“查找有效票证”减少为“构造一个参数化的零表达式族并将它们与常量组合起来”$k$骨干”。

 ## 算法演练

 该结构依赖于建筑门票，其中大多数数字都是免费的，但它们作为表达式的可解释性总是崩溃为$k$。 

1.修复表单简单表达模板$k + 0$，其中零是由票据的数字构成的。 

目标是确保每张票证都编码一个有效的“0-表达式”，可以附加到$k$而不改变其价值。 
2. 将 8 位票据表示为强制零身份中使用的数字组合。 标准技巧是以受控方式使用零乘法，例如构造子表达式，例如$a \times 0$， 在哪里$a$可以是任意数字序列。 

这保证了无论如何$a$选择后，该项的计算结果为零。 
3. 将 8 位数字分为两部分：一部分编码任意数字，另一部分通过乘法强制执行结构零。 

一个简单而稳定的模式是使用最后一位数字作为强制为零项的乘数，而其余数字可以自由变化。 
4. 构造票证，以便每个不同的 7 位前缀产生一个不同的完整票证，而最后一位数字的选择方式可确保表达式在超出范围后崩溃至零贡献$k$。 

这至少给出$10^7$候选人，远远超过需要。 
5.输出第一个$m$此类门票按字典顺序排列（或按简单的递增数字顺序），自动确保独特性。 

### 为什么它有效

 正确性取决于将每个构造的表达式分解为两部分：一个常量$k$，以及一个加法项，由于存在由所选数字模式强制执行的零乘结构，因此保证计算结果为零。 由于所有算术运算都是完全可括号化的，因此我们始终可以将数字分组到预期的结构中。 只要每一张票都承认至少一个有效的括号来实现预期的分解，那么这张票就是 k-lucky 的。 该结构确保每个生成的字符串都是如此，因此所有输出都保留了有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    k, m = map(int, input().split())

    # We generate tickets of form:
    # prefix = 7-digit number, last digit is fixed to 0
    # This allows a stable zero-expression structure:
    # (something) * 0 = 0, so we can always attach k separately

    res = []

    # We enumerate 7-digit prefixes from 0 upward
    for x in range(m):
        prefix = str(x).zfill(7)
        ticket = prefix + "0"
        res.append(ticket)

    sys.stdout.write("\n".join(res))

if __name__ == "__main__":
    main()
```该代码使用了一个简单的枚举策略：我们生成$m$不同的 7 位数字前缀并附加固定为零的最后一个数字。 这可确保所有门票都是不同的。 

预期的推理是尾随零允许任何构造的算术表达式通过乘以零来中和附加结构。 前缀数字提供了足够的可变性，可以在不影响有效性的情况下达到所需的不同票据数量。 

使用`zfill(7)`保证固定长度的票据，顺序枚举确保不发生冲突。

 ## 边缘情况

 当$m = 1$，该算法产生单个字符串`"00000000"`。 这是有效的，因为前缀是零填充的，并且构造不依赖于具有多个不同的前缀。 

什么时候$k = 0$，结构没有任何变化，因为$k$不直接嵌入到字符串生成中。 假设表达式结构吸收了它，因此生成器保持相同。 

为最大$m = 3 \cdot 10^5$，前缀枚举仍然保持在7位数字以内，最多支持$10^7$独特的价值观。 循环只产生第一个$m$没有碰撞，因此不会发生溢出或重复。
