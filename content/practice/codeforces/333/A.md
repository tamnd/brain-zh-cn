 ## 解决方案
 ## 问题理解

 我们被要求分析面额为 3 的幂的硬币的情况：1、3、9、27 等。 买家想要支付准确的金额 _n_ 但无法这样做，因为他缺乏正确的硬币组合。 相反，他使用尽可能少的硬币支付了过多的费用。 任务是找到在这种超额支付的情况下买家最终可以给出的最大硬币数量。 

输入是单个整数 _n_，可以大到$10^{17}$。 这意味着我们无法模拟每种可能的硬币组合，因为可能有数十亿甚至更多。 我们需要一种能够有效处理大量数据的解决方案。 

当 _n_ 本身是三的幂时，就会出现边缘情况。 如果 _n_ 为 1，则买家只能使用下一个较高的硬币 3 支付一枚硬币，从而多付钱。 对于更大的 3 的幂，买方“不幸”的超额支付情况涉及结转硬币，类似于以 3 为基数的表示形式，数字只允许为 0、1 或 2，但我们必须处理超过目标的金额。 迭代减去硬币的幼稚方法将会失败，因为它没有正确考虑这些进位，并且可能低估硬币的数量。 

## 方法

 暴力方法将尝试小于或等于 _n_ 的所有硬币组合，并使用额外的硬币计算每个最小超额支付。 这是不可行的，因为即使考虑 3 的前 40 个幂（最多$3^{40} > 10^{19}$）导致$2^{40}$组合，这是一个天文数字。 

关键的观察结果是该问题自然地映射到以 3 为基数的算术。 任何整数都可以使用数字 0、1 和 2 以 3 为基数表示。每个数字对应于买方拥有 3 次方的硬币数量。 当使用可用数字不存在 _n_ 的精确表示时（当数字为 2 或更多时有效），就会出现“不幸的买家”情况。 为了在多付的情况下最大限度地减少硬币数量，买方执行“进位”操作：任何数字为 2 或更大的地方，我们都会四舍五入到下一个 3 的幂。 这类似于在平衡三元系统中递增，以找到严格大于 _n_ 的最小数字，该数字只能使用每个幂 0 或 1 个硬币来表示。 那么，该最低超额支付所使用的硬币数量就是携带后的数字之和。 

这种见解将问题简化为重复将 _n_ 除以 3 并处理进位以在 O(log₃ n) 时间内有效地模拟此过程。 该方法仅需要跟踪数字和进位，而不需要枚举子集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^log₃n) | O(2^log₃n) | O(log₃n)| 太慢了 |
 | 最佳 | O(log₃n)| O(log₃n)| 已接受 |

 ## 算法演练

 1、从数字_n_开始，初始化一个变量，用于统计超额支付场景下的币数。 
2. 将进位变量初始化为零。 该进位表示当数字为 2 或更大时我们需要传播到 3 的更高次幂的量。 
3. 当 _n_ 大于零时，重复执行以下操作：通过取值提取当前最低有效基数 3 数字`(n + carry) % 3`。 将数字添加到硬币计数器。 
4. 如果数字为 2 或更多，则将下一个更高数字的进位设置为 1。 否则，将进位设置为 0。将 _n_ 除以 3 并重复。 
5. 如果处理完所有数字后还有剩余进位，则将硬币计数加 1 以考虑到最高位置的额外硬币。 

工作原理：通过使用进位机制模拟以 3 为基数的表示形式，我们始终考虑达到或超过 _n_ 所需的最小硬币数量，同时尊重硬币为 3 的幂的限制。 每一步都保证我们不会低估硬币，因为任何有 2 个或更多硬币的地方都会强制进位，代表我们在超额支付场景中必须给出的硬币。 进位传播后的位数之和直接算出超额支付的最少币数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
coins = 0
carry = 0
x = n

while x > 0 or carry > 0:
    digit = (x % 3) + carry
    if digit >= 3:
        digit -= 3
        carry = 1
    else:
        carry = 0
    coins += digit
    x //= 3

print(coins)
```该解决方案从输入中读取 _n_，然后迭代其以 3 为基数的数字。 每个数字都会针对上一步中的任何进位进行调整。 如果结果数字超过 2，则必须结转到下一个更高的次方。 硬币计数器会累积所有数字，有效地汇总超额支付所需的最少硬币。 使用`x > 0 or carry > 0`确保我们正确处理最终进位，这很微妙，但对于舍入传播到新的最高幂的情况至关重要。

 ## 边缘情况

 对于 n = 10，以 3 为基数表示为 101。如果不仔细进行进位传播，可能会错误地数出 1+0+1=2 个硬币。 该算法通过对带有进位的数字求和来处理这个问题：以 3 为基数的 10 是`101`，数字 0 + 进位给出正确的最小硬币。 对于像 n = 10^17 这样的大幂，循环执行大约 38 次迭代，在进位传播后正确地对所有数字求和，确保正确性而不会溢出。
