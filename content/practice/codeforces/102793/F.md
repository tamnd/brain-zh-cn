 ## 解决方案
 ## 问题理解

 我们有一排`n`面板。 每个面板一开始都是关闭的。 成功的代码是完全符合给定条件的配置`k`位置打开，所有其他位置关闭。 操作从数组中选择允许的长度之一`a`并翻转该长度的连续段中的每个面板。 任务是找到达到目标配置所需的最少操作数，或者报告无法完成。 

约束是围绕以下事实设计的：`n`很大，而`k`非常小。 存储或处理每种可能的面板配置的解决方案是不可能的，因为`n`可以达到10000。但是，最多有10个重要位置，因此与答案相关的有意义的状态数量很少，最多`2^k = 1024`。 这表明算法应该将大棋盘压缩为有关特殊位置的信息。 

有少数情况很容易处理不当。 如果目标不能用可用的操作来表示，则答案是`-1`，不是一个大数字。 例如：```
Input:
3 2 1
1 2
3

Output:
-1
```翻转所有三个面板总是会同时更改前两个面板和第三个面板，因此无法达到所需的状态。 

另一个棘手的情况是，某项操作似乎只影响重要位置，但也会更改必须保持关闭状态的面板。 例如：```
Input:
5 1 1
3
2

Output:
-1
```翻转两个片段的长度永远不会在中间创建一个单独的隔离面板，因为操作创建的差异图案始终有两个边框。 

两次应用相同的操作后效果为空是另一个常见的错误。 由于每个操作都是异或翻转，因此两个相同的操作会相互抵消。 任何最短的解决方案都不需要重复相同的过渡。 

## 方法

 直接的解决方案将尝试所有可能的操作顺序。 这是正确的，因为每个有效序列最终都会达到某种配置，并且我们可以保持成功序列中的最小长度。 问题在于，可能的序列数量随着答案呈指数增长。 如果有 100 种可能的长度，而我们甚至需要 10 次操作，则搜索空间已包含最多`100^10`候选人，这远远超出了我们可以探索的范围。 

关键的观察是停止考虑整排面板。 考虑当前配置的异或差异数组。 段翻转仅更改此差异数组中的两个位置：段开始的位置和紧接段结束之后的位置。 段的内部并不重要，因为相邻的更改会取消。 

目标配置只有几个开和关之间的转换，因为只有`k <= 10`细胞已开启。 我们可以将这些转换点表示为位掩码。 每个可能的段操作都成为掩码之间的转换。 由于掩码最多有 1024 个，因此我们可以运行 BFS 并找到最少的操作数。 

对操作的强力搜索会失败，因为它探索了巨大的物理板。 差分阵列观察去除了不相关的单元，只留下影响可达性的小状态空间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 答案长度呈指数增长 | 指数| 太慢了 |
 | 最佳| O((n + l) * 2^k) | O((n + l) * 2^k) | O(2^k) | O(2^k) | 已接受 |

 ## 算法演练

 1. 构建目标配置的 XOR 差异表示。 在状态从一个面板变为下一个面板的每个边界处设置一位。 这些是唯一需要跟踪操作的地方。 
2. 将可能的差异位置压缩为一个重要坐标的小列表。 最多有`2k`这样的位置是因为每个面板最多贡献两个边界。 
3. 在这些压缩位置的掩码上运行 BFS。 起始掩码为零，因为所有面板最初都是关闭的。 目标掩码描述了所需的边界。 
4. 对于每个 BFS 状态，尝试每个允许的操作长度和每个可能的段放置。 计算该段切换了哪些压缩边界并将其用作下一个状态。 
5. 当达到目标掩码时，BFS距离是最小操作次数。 如果 BFS 完成但未到达，则目标配置是不可能的。 

工作原理：XOR 差异表示准确地保留了重建面板状态所需的信息。 段翻转仅影响此表示中的两个边界，因此具有相同差异掩码的两个配置对于​​未来的操作是等效的。 BFS 以越来越多的移动次数探索每个可到达的压缩配置，因此目标第一次出现时，不能存在更短的序列。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, k, l = map(int, input().split())
    x = list(map(int, input().split()))
    a = list(map(int, input().split()))

    target = [0] * (n + 2)
    for pos in x:
        target[pos] ^= 1
        target[pos + 1] ^= 1

    coords = [i for i in range(1, n + 2) if target[i]]
    idx = {v: i for i, v in enumerate(coords)}

    if not coords:
        print(0)
        return

    m = len(coords)
    target_mask = 0
    for i in range(m):
        target_mask |= 1 << i

    moves = []
    seen_moves = set()

    for length in a:
        for start in range(1, n - length + 2):
            end = start + length
            mask = 0
            if start in idx:
                mask ^= 1 << idx[start]
            if end in idx:
                mask ^= 1 << idx[end]
            if mask and mask not in seen_moves:
                seen_moves.add(mask)
                moves.append(mask)

    dist = [-1] * (1 << m)
    dist[0] = 0
    q = deque([0])

    while q:
        cur = q.popleft()
        if cur == target_mask:
            print(dist[cur])
            return
        for mv in moves:
            nxt = cur ^ mv
            if dist[nxt] == -1:
                dist[nxt] = dist[cur] + 1
                q.append(nxt)

    print(-1)

if __name__ == "__main__":
    solve()
```实现的第一部分构造目标的异或差。 翻转面板会更改两个相邻的差异，因此面板上所需的每个都会贡献两个切换。 

名单`coords`仅存储重要的边界。 这是将长度为 10000 的板转换为最多具有 1024 个顶点的图的压缩步骤。 

转换生成会检查每个可能的段，因为压缩状态的数量很少，并且可能的段开始的总数仅为`O(nl)`。 每个转换都会转换为操作切换的边界掩码。 

BFS 数组存储到达每个掩码所需的最少操作数。 由于每条边都代表一个操作，因此 BFS 自动给出最短路径。 不存在溢出问题，因为所有距离最多都是状态数。 

## 工作示例

 对于第一个样本：```
Input:

1 2 3 5 6 7 8 9

```BFS期间的重要状态是：

 | 步骤| 当前掩码含义| 运营| 下一个状态 |
 | ---| ---| ---| ---|
 | 0 | 没有差异| 位置 1 处的翻转长度 3 | 1 和 4 处的差异 |
 | 1 | 第一组固定| 位置 5 处的翻转长度 5 | 目标|

 这两个操作恰好在面板上创建了所需的八个。 

对于第二个样本：```
Input:

3
```| 步骤| 当前掩码| 可用过渡 | 结果 |
 | ---| ---| ---| ---|

 BFS 探索每个压缩状态但从未达到目标，所以答案是`-1`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(nl + 2^k * l) | 我们生成可能的转换并在最多 1024 个状态上运行 BFS |
 | 空间| O(2^k) | O(2^k) | 仅存储压缩后的图距离 |

 该解决方案很合适，因为昂贵的部分取决于`2^k`， 和`k`限制为 10。较大的值`n`只出现在过渡代。

 ## 边缘情况

 处理具有三个面板和长度三操作的不可能示例，因为操作产生的差异掩模与目标掩模不匹配。 BFS 并不假设每组 on 位置都是可达的。 

孤立的中间面板示例由相同的不变量处理。 长度为 2 的翻转始终会创建两个边界，因此所需的单面板边界模式永远不会出现在 BFS 图中。 

位置位于行的开头或结尾的情况通过在位置之后包含边界来处理`n`在差异数组中。 如果没有这个额外的边界，接触最后一个面板的操作将被错误地表示。
