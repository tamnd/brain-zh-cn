 ## 解决方案
 # 问题理解

 该板是一个矩形的单元网格。 相邻单元之间的一些边界包含电缆段。 当狗从一个单元格移动到相邻单元格时，它会切断它穿过的边界上的电缆（如果该边界存在）。 

对于玩家可以站立的每个可能的起始单元，我们需要狗可以切割的最大电缆段数。 狗只能移动到不在其起始位置上方或右侧的单元格。 这意味着选择路线后，每个访问的单元格必须位于与起点相同的对角线上，或者位于网格中更下方和左侧的位置。 

输入给出网格大小、现有电缆段和几个起始位置。 输出包含每个起始位置的一个值：狗可以切割的最佳可能数量的电缆。 

网格维度可以单独达到200000，但维度的乘积最多为200000。这意味着我们无法负担单元格数量呈二次方的算法。 解决方案围绕`O(n*m)`是合适的，因为最多有 200000 个单元格，而如果查询很大，则从每个查询位置运行单独的搜索仍然太昂贵。 查询数量很少，但预处理应该仍然是线性的。 

一个常见的错误是只考虑最短路线或沿着网格边缘的路线。 狗可以自由选择满足运动限制的任何路径，因此必须考虑所需对角线上的所有可能端点。 

例如，如果起始点是对角线上的上部单元格：```
2 3 0
```如果两个单元之间的边界有一根电缆，狗可能会选择实际穿过该电缆的路线。 总是向边界移动并忽略替代路线的贪婪实现可能会错过最佳答案。 

另一种边缘情况是根本没有电缆时：```
n = 1, m = 1, k = 0
query:
1 1
```答案是`0`。 使用负值错误地初始化动态编程值的实现可能会产生错误的答案，因为没有要添加的转换。 

最后的边缘情况是对第一行或最后一列的查询。 例如：```
n = 2, m = 3
query:
1 3
```狗不能向上或向右移动，因此只能在与行至少相同的对角线上的单元格`1`最多和列`3`是有效的。 扫描对角线时使用错误边界的代码可能包含无效单元。 

## 方法

 直接的方法是从每个查询单元格开始图形搜索。 在搜索过程中，我们只允许向下或向左移动并计算交叉的电缆。 这是正确的，因为它准确地探索了狗可以采取的路线。 然而，相同的子问题多次出现。 在最坏的情况下，从一个单元格探索所有可能的路线会触及棋盘的很大一部分，并且对所有查询执行此操作可以接近`O(q*n*m)`工作，这是不必要的。 

有用的观察结果是，通往细胞的每条路线都具有相同的结构。 如果我们计算从左上角到达每个单元格所需的最大电缆数量，则可以从这些预先计算的值中提取查询的答案。 

对于一个细胞`(i, j)`，玩家的每个有效端点`(x, y)`必须满足`i + j = x + y`，因为狗停留在同一条反对角线上。 在这些单元格中，狗不能走到起点的上方或右侧，因此只有带有`i >= x`和`j <= y`是有效的。 由于对角线和是固定的，检查`i >= x`就足够了。 

我们计算每个单元格的动态编程值：`dp[i][j]`是路径上交叉的电缆的最大数量`(1, 1)`到`(i, j)`。 

过渡只需要上邻居和左邻居。 预处理后，每个查询都变成在一条对角线上的查找。 通过存储每条对角线的后缀最大值，可以在恒定时间内回答查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(q_n_m) | O(q_n_m) | O(n*m) | 太慢了|
 | 最佳| O(n*m + q) | O(n*m) | 已接受 |

 ## 算法演练

 1. 将每条电缆存储为有关两个相邻单元之间边界的信息。 我们只需要知道向下移动还是向右移动是否穿过电缆。 
2. 逐行构建动态规划表。 对于每个单元格，优先选择从顶部或从左侧进入的方式，然后添加该移动穿过的电缆。 
3. 按对角线编号对所有单元格进行分组`i + j`。 对单元格的查询仅取决于其自身的对角线。 
4. 对于每个对角线，从下到上处理单元格，并将每个值替换为该对角线上其下方所有单元格中的最大值。 这允许查询立即使用其起始行处的值。 
5. 查询`(x, y)`，使用对角线`x + y`并返回行的存储值`x`。 该值已经排除了高于起点的所有单元格。 

为什么它有效：

 动态编程表存储了从左上角可到达的每个端点的最佳可能电缆数量。 查询要求不在起始单元格上方或右侧的一个特定对角线上的最佳端点。 该对角线上的后缀最大值恰好保持所有有效端点中的最大值。 由于每个可能的狗路线都对应于这些端点之一，并且每个存储的端点值已经代表了到达它的最佳路线，因此返回的值是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    down = [[0] * (m + 1) for _ in range(n + 1)]
    right = [[0] * (m + 1) for _ in range(n + 1)]

    for _ in range(k):
        x1, y1, x2, y2 = map(int, input().split())
        if x1 == x2:
            y = min(y1, y2)
            right[x1][y] = 1
        else:
            x = min(x1, x2)
            down[x][y1] = 1

    dp = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            best = 0
            if i > 1:
                best = max(best, dp[i - 1][j] + down[i - 1][j])
            if j > 1:
                best = max(best, dp[i][j - 1] + right[i][j - 1])
            dp[i][j] = best

    diagonals = {}
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            s = i + j
            if s not in diagonals:
                diagonals[s] = []
            diagonals[s].append((i, dp[i][j]))

    for s in diagonals:
        diagonals[s].sort()
        best = -1
        arr = diagonals[s]
        for idx in range(len(arr) - 1, -1, -1):
            best = max(best, arr[idx][1])
            arr[idx] = (arr[idx][0], best)

    q = int(input())
    ans = []
    for _ in range(q):
        x, y = map(int, input().split())
        arr = diagonals[x + y]
        lo = 0
        hi = len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid][0] < x:
                lo = mid + 1
            else:
                hi = mid
        ans.append(str(arr[lo][1]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```数组`down`和`right`仅存储过渡所需的电缆方向。 向下移动使用当前单元格上方存储的边框，而向右移动则使用当前单元格左侧的边框。 遵守这一约定可以避免一个错误。 

动态规划循环从`(1, 1)`并且只读取已经计算的单元格。 额外的行和列的零消除了顶部和左侧边界的特殊情况的需要。 

对角预处理存储行号和最佳值对。 按行排序允许在每次查询期间进行二分搜索。 后缀最大传递是从末尾开始的，因为查询的有效单元格正是那些行大于或等于查询行的单元格。 

## 工作示例

 考虑一个小网格，其中查询位于单元格上`(2, 3)`。 相关对角线有和`5`。 

| 步骤| Current cell | Diagonal | Stored value |
 | ---| ---| ---| ---|
 | 1 |`(1,4)`| 5 | 2 |
 | 2 |`(2,3)`| 5 | 5 |
 | 3 |`(3,2)`| 5 | 4 |

 后缀最大值将值更改为：

 | 行| 后缀最大值后的值 |
 | ---| ---|
 | 1 | 5 |
 | 2 | 5 |
 | 3 | 4 |

 查询从行开始`2`，所以答案是行中存储的值`2`，即`5`。 这表明该算法忽略了玩家上方的单元格。 

对于另一种情况，假设查询是其对角线上的唯一单元格。 

| 步骤| 当前单元格 | 对角线| 储值|
 | ---| ---| ---| ---|
 | 1 |`(1,1)`| 2 | 0 |

 后缀最大值保持相同的值。 这证实了单个电池和没有电缆的电路板无需特殊逻辑即可处理。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n_m + q_log(n*m)) | O(n_m + q_log(n*m)) | 每个单元格都会处理一次，每个查询都会在一条对角线上执行二分搜索 |
 | 空间| O(n*m) | 网格表和对角线存储每个单元格包含恒定数量的数据 |

 ## 边缘情况

 当电路板不包含电缆时，每个转换都会加零。 动态规划表仍然有效，因为最大路径值仍然是交叉电缆的数量，为零。 

对于棋盘边缘的查询，例如`(1, m)`，二分查找选择该对角线上的第一行。 后缀最大值已经删除了玩家上方所有不可能的单元格，因此不会计算无效路线。 

当多个单元共享相同对角线时，算法不会选择最接近的一个。 它通过后缀最大值隐式检查所有有效端点，这正是所需要的，因为狗可以选择任何使穿过的电缆数量最大化的路线。
