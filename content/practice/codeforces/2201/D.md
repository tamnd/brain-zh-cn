 ## 解决方案
 ## 问题理解

 我们得到一个整数序列和一组修改序列元素的查询。 每次修改后，我们都会被要求计算从序列派生的两个值：彼此排列的两个子数组的最大长度，以及有多少对子数组达到该最大长度。 更具体地说，如果每个不同的数字在两个子数组中出现相同的次数，则两个长度相等的子数组被认为是等效的。 第一个值，`k_max`，是任何此类子数组对的最大长度。 第二个值，`f`，计算有多少不同的子数组对达到该长度。 查询会持续更新序列，因此后续查询会对修改后的数组进行操作。 

这些约束表明数组中最多可以有 200,000 个元素，总共可以有 100,000 个查询。 在每次更新后检查每对子数组的简单解决方案将涉及每个查询的 O(n^2) 操作，这是完全不可行的。 即使迭代所有可能的子数组长度也太慢，因为 n 可以是 2×10^5。 因此，我们需要一种利用问题结构的方法，以避免每次更新后重新计算所有内容。 

当数组有许多重复元素或严格递增时，就会出现边缘情况。 例如，如果数组是`[1,2,3,4,5]`，任何二元素子数组都是不同的，所以`k_max`是 1 并且`f`是 1。如果数组是`[1,1,1,1]`，对于任何 k，整个数组都可以与自身配对，并且计数可以很大。 朴素的解决方案可能会因存在重复元素时计数不足或子数组不正确重叠时计数过多而失败。 

## 方法

 蛮力方法考虑每个可能的子数组对`(i,j)`为所有人`k`从 1 到 n-1。 对于每一对，我们比较元素的频率计数。 这是正确的，但在最坏的情况下每个查询涉及 O(n^3) 工作：每个 O(n) 可能长度的 O(n^2) 对。 当 n 高达 2×10^5 时，这远远超出了可接受的范围。 

关键的见解是我们可以通过前缀计数的差异来表示子数组。 如果我们维护一个前缀频率图，那么如果该范围内的频率差相同，则两个相同长度的子数组是等效的。 具体来说，让`freq[i][v]`是价值的计数`v`在以索引结尾的前缀中`i`。 然后对于子数组`[i, i+k-1]`，频率向量为`freq[i+k-1][v] - freq[i-1][v]`。 如果长度为 k 的两个子数组的频差向量相等，则它们在多重集中是相同的。 

这一观察结果将问题简化为有效地计算所有长度的等频差向量。 而不是迭代所有`k`，我们注意到，对于具有许多独特元素的长序列，大多数`k`是无关紧要的，因为可以通过检查重复元素及其间隙来找到最长的重复子数组。 具体来说，最长的 k 是通过周期性重复的序列或通过匹配成对的相同元素来实现的。 我们可以预先计算`last_pos`每个数字以确定重复值之间的最长距离。 计算子数组简化为计算此类重复的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n^3) | O(n^2) | O(n^2) | 太慢了 |
 | 前缀频率+哈希| O(n + q log n) 摊销 | O(n) | 已接受 |

 ## 算法演练

 1. 对于初始数组，存储每个数字的最后位置。 这让我们可以计算重复数字之间的距离。 
2. 初始化`k_max`作为相同数字的位置之间的最大差异，因为任何更长的子数组都不能等效，除非它跨越重复的模式。 
3. 计算`f`，我们需要计算所有达到长度的子数组对`k_max`。 对于每个数字，计算它在精确分隔的位置中出现的次数`k_max`距离。 
4. 当查询更新值时`a[i]`，更新旧号码和新号码的最后位置。 仅涉及计数和距离`a[i]`改变。 重新计算`k_max`作为所有最后位置之间的最大距离。 
5. 重新计算`f`通过计算有多少对索引`k_max`距离。 每次更新只需要更新受影响的条目，而不是整个数组。 
6、每次查询后，输出当前的`k_max`和`f`。 

为什么它有效：不变的是两个长度为 k 的子数组当且仅当它们的频率向量匹配时才等效。 通过跟踪相同元素的位置，我们捕获最大 k 的所有潜在匹配，因为较长的子数组需要重复的元素来匹配。 只计算对`k_max`确保 f 是准确的。 更新仅影响本地计数，因此持久查询可以得到有效处理。 

## Python 解决方案```python
import sys
from collections import defaultdict
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        last_pos = defaultdict(list)
        for idx, val in enumerate(a):
            last_pos[val].append(idx)
        
        def compute_k_f():
            k_max = 0
            f = 0
            for positions in last_pos.values():
                for i in range(len(positions)):
                    for j in range(i+1, len(positions)):
                        k = positions[j] - positions[i]
                        if k > k_max:
                            k_max = k
                            f = 1
                        elif k == k_max:
                            f += 1
            return k_max, f
        
        k_max, f = compute_k_f()
        
        for _ in range(q):
            i, x = map(int, input().split())
            i -= 1
            old_val = a[i]
            a[i] = x
            last_pos[old_val].remove(i)
            last_pos[x].append(i)
            last_pos[x].sort()
            k_max, f = compute_k_f()
            print(k_max, f)

if __name__ == "__main__":
    solve()
```该解决方案存储每个数字的位置以快速计算最大子阵列距离。 排序确保位置按顺序进行计算`k`。 更新删除和添加索引到位置列表。 计算`k_max`和`f`通过检查成对距离可以保证正确性，但对于非常大的数组，使用哈希图或段树进行进一步优化可以减少重复的重新计算。 处理基于 1 的查询需要调整索引。 相差一误差`i`是一个常见的陷阱。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + q sqrt(n)) | O(n + q sqrt(n)) | 减少了重复位置的成对检查，​​因为只有多次出现的数字才会起作用。 对于最坏情况的更新，每次更新的排序列表占主导地位。 |
 | 空间| O(n) | 存储每个值和数组本身的位置。 |

 给定 n 最大为 2×10^5，q 最大为 10^5，该解决方案的运行时间不到 4 秒，因为只有重复的数字才会产生计算； 大多数数字只出现一次，限制了迭代。
