 ## 解决方案
 ## 问题理解

 我们从一个$n \times n$网格完全是空的，我们逐渐将一些单元格涂成黑色。 在每次绘制操作之后，我们必须确定当前的黑白图案是否避免了涉及两行和两列的非常具体的禁止配置。 

禁止的模式可以用更具结构性的方式重新表述。 选择两个不同的行$i < j$和两个不同的列$k < l$。 看看$2 \times 2$由它们的交集形成的子矩阵。 该条件表示我们一定无法找到这样一个子矩阵，其中值“交叉不匹配”：左上角等于右下角，右上角等于左下角，并且第一列中的两个值不同。 换句话说，在这四个单元格中，颜色不得形成有效的“X 形”图案，其中对角线匹配但行不一致，即两种颜色以交换的方式出现在每行和每列上。 

由于网格仅包含黑色和白色，因此最初全白是有效的。 每个查询都会将单个单元格从白色永久翻转为黑色，每次更新后我们必须决定是否有任何禁止的$2 \times 2$结构已经出现在网格中的任何地方。 

限制是极端的：总体最多可达 200 万次操作，网格侧也最多可达 200 万次。 这立即排除了每个查询检查行或列的任何内容，甚至每个操作执行的工作量超过恒定或接近恒定工作的数据结构也必须仔细控制。 任何尝试检查行或列对或扫描邻域的解决方案都将失败几个数量级。 

一个微妙的问题是，这种情况是全局性的，但表面上是局部性的。 一个幼稚的实现可能会尝试检查受新绘制的单元格影响的所有行对或所有列对，但即使是单个单元格也位于$O(n)$这样的配对，使得这种方法随着时间的推移呈二次方。 

如果我们尝试维护行式或列式位集并直接检查重叠，则会出现另一种故障模式。 禁止结构取决于两行跨两列之间的相关性，而不仅仅是集合的交集，因此简单的集合交集计数是不够的。 

下面是一个小的说明性失败。 假设我们有黑色单元格形成一个具有两条对角线的矩形：$$(i,k), (j,l), (i,l), (j,k)$$仅跟踪行交叉点的简单方法可能会看到行$i$和$j$共享两列并根据聚合得出太晚或太早的结论，忽略了该模式是关于交叉对齐而不仅仅是共享位置的事实。 

关键的困难在于，该条件从根本上讲是关于行和列之间诱导的二分结构是否在组合意义上变得“非单调”。 

## 方法

 暴力解决方案将在每次查询后通过扫描所有行对并检查所有列对是否存在禁止模式来重新计算有效性。 这在概念上很简单：对于每个$2 \times 2$子矩阵，验证是否违反规则。 然而，即使维护黑色单元格列表也无济于事，因为每个查询都可能需要检查$O(n^2)$潜在的行列组合。 超过$2 \cdot 10^6$操作，这变得完全不可行。 

另一种尝试是修复一对行$i, j$并跟踪都有黑色单元格的列。 如果存在两个这样的列，我们可能会怀疑存在违规行为。 但这仍然不够，因为条件不仅仅涉及共享列的存在；还涉及共享列的存在。 它取决于同时通过列交互的_不同对_行之间的互相关性。 

关键的结构见解是根据行之间成对模式的一致性来重新解释条件。 我们不考虑单元格，而是考虑行如何通过共享的黑色列相互关联。 

修复一列$c$。 每个黑格$(r, c)$诱导行之间的关系$r$以及列中也有黑色的所有其他行$c$。 如果两行共享一列，它们就会“通过该列连接”。 当两个不同的列在同一对行之间产生不兼容的成对关系时，就会出现禁止的配置，从而有效地在列支持行对的方式上产生冲突循环。 

这建议跟踪每对行当前连接它们的列数。 当某对行由至少两个不同的列以强制导出结构中矛盾的方式连接时，就会发生违规。 然而，存储所有行对是不可能的。 

因此，我们再次反转视角：我们跟踪每列的交互，而不是行对。 每列维护一组包含黑色单元格的行。 关键的观察结果是，当某对行同时出现在至少两个不同的列中时，就会产生违规。 这意味着我们需要检测是否存在两行，其在活动列集合上的交集的大小至少为 2。 

这减少了为每对行维护一个计数器的问题，该计数器显示当前包含这两个行的列数。 直接维护仍然太大，但我们利用稀疏性：随着时间的推移，每一列仅增加其行集，并且每次更新仅影响一列。 

当插入黑色单元格时$(r, c)$，我们迭代列中所有先前激活的行$c$，并为每对增加一个全局计数器$(r, x)$。 如果任何对达到计数 2，我们立即知道该矩阵无效。 

为了保持这种效率，我们观察到所有更新的增量总数受到列内形成的对总数的限制，即$\sum \binom{s_c}{2}$， 在哪里$s_c$是列中黑色单元格的数量$c$。 在所有操作中，每个新的黑色单元最多只添加$s_c$工作，并且由于每个单元插入一次，因此总复杂性是可控的。 

我们维护一个以有序行对为键的哈希映射或字典来存储计数，以及一个指示任何计数是否达到 2 的全局布尔标志。

 ## 算法演练

 1. 维护从每列到当前在该列中包含黑色单元格的行列表的映射。 这使我们可以在其列内本地处理每个更新。 
2. 维护哈希图`cnt[(r1, r2)]`存储当前两行中有多少列包含黑色单元格$r1$和$r2$， 和$r1 < r2$。 这对每对行累积了多少“共享支持”进行编码。 
3. 维护全球旗帜`bad = False`。 一旦设置，它将永久保持设置状态，因为添加更多黑色单元无法删除禁止的配置。 
4. 对于每个查询$(r, c)$，迭代列中已存在的所有行$c$。 对于每个这样的行$x$, 组成对$(\min(r,x), \max(r,x))$并增加其计数器`cnt`。 
5. 如果任何计数器变为 2，则设置`bad = True`。 这意味着两个不同的列现在支持同一对行，这保证了禁止的存在$2 \times 2$结构。 
6. 附加当前答案：“是”如果`bad`仍为 False，否则为“NO”。 

这样做的原因是创建禁止结构的唯一方法是让两行同时连接在两个不同的列中。 每次插入黑色单元格时，我们都会显式注册该列中形成的所有新行对。 第一次任何对在不同的列中出现两次时，我们就得到了产生交叉的结构$2 \times 2$矛盾，从那一刻起，这种状况就再也无法恢复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())

        col_rows = {}
        pair_cnt = {}
        bad = False

        for _ in range(q):
            r, c = map(int, input().split())

            if c not in col_rows:
                col_rows[c] = []

            lst = col_rows[c]

            # if already bad, just consume input
            if not bad:
                for x in lst:
                    a, b = (r, x) if r < x else (x, r)
                    key = (a, b)
                    pair_cnt[key] = pair_cnt.get(key, 0) + 1
                    if pair_cnt[key] == 2:
                        bad = True

            lst.append(r)

            out.append("NO" if bad else "YES")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```### 代码说明

 该解决方案为每一列维护一个已被涂成黑色的行的列表。 每个新的黑色单元格仅与其列中先前看到的单元格相互作用，这是唯一可以形成新的行对相互作用的地方。 

字典`pair_cnt`存储有多少不同的列在每对行之间创建了连接。 当任何对达到计数 2 时，我们就检测到了禁止结构并将状态永久标记为无效。 

我们按排序顺序存储对以避免重复，因为行对是无向的。 一次`bad`为真时，我们仍然处理输入，但跳过不必要的更新以保持运行时稳定。

 ### 示例 1

 考虑一个小场景：

 | 步骤| 细胞| 列状态| 更新对 | 坏|

```| 步骤| 细胞| 列状态| 更新对 | 坏|
 | --- | --- | --- | --- | --- |
 | 4 | (3,3) | 第 3 栏的 {2,3} | (2,3) → 2 | 是 |

 该对 (2,3) 现在由两列（2 和 3）共享，形成禁止结构。 

这证实了当行对跨列重复时，算法能够准确地检测到违规。

```| 步骤| 细胞| 列状态| 更新对 | 坏|

 ## 边缘情况

 一个关键的边缘情况是当单个列中发生许多更新时。 在这种情况下，每个新插入都会与该列中的所有先前行交互，并且算法必须确保它不会错误地重置或重复计数。 该结构自然地处理这个问题，因为所有交互都仅限于该列的列表，并且每对增量与顺序无关。 

另一个微妙的情况是，由于两个特定列之间的交互而导致违规行为延迟出现。 该算法捕获了这一点，因为它不依赖于邻接，而是依赖于全局对计数：一旦一对出现在两个不同的列中，无论输入序列中的间距如何，都会检测到该条件。 

最后，跨多列的重复行可以创建密集的配对交互。 基于字典的计数确保只有实际的配对出现才重要，一旦配对达到阈值 2，计算就会停止影响正确性，从而保持效率。
