 ## 问题理解

 我们得到了一系列的动作。 一开始，鲍勃拿着两个整数，左手一个，右手一个，都等于零。 每次移动 i，爱丽丝都会给出一个新的数字 ki。 Bob 必须选择是用 ki 替换左手还是右手的值。 另一只手保持不变。 

每次替换后，生成的值对必须位于矩形约束内：左侧值 x 必须满足 ai ≤ x ≤ bi，右侧值 y 必须满足 ci ≤ y ≤ di。 如果在任何时候违反此条件，该过程将立即停止。 鲍勃提前看到所有动作，并且必须为每个步骤决定替换哪只手，以便满足每个前缀的所有约束。 

输出是一系列决策，每次移动一个，指示新数字是向左还是向右，或者声明不存在有效序列。 

约束 n 高达 100000 意味着任何解决方案都必须接近线性或线性算数。 任何在选择上呈指数级分支的方法都是立即不可能的。 除非严重压缩，否则即使是所有前缀上的二次 DP 也太慢。 

一个微妙的问题是，双手的发展是不对称的：每个决定都会以耦合的方式影响未来的可行性。 一个天真的想法是尝试在每一步之后维护所有可能的值对。 这是不可能的，因为值并不局限于一个小域； ki 可以很大，最大可达 10^9。 

另一种失败模式是贪婪地选择一手牌，使当前步骤保持有效，而不考虑未来的约束。 由于当前的分配可能会保留现在的可行性，但会阻止所有未来的时间间隔，因此局部决策是不可靠的。 

## 方法

 直接暴力方法会尝试将每个 ki 的所有分配分配给左侧或右侧。 有 2^n 个这样的分配，对于每个分配，我们都在 O(n) 中模拟该过程，给出 O(n·2^n)。 对于 n = 100000 来说这显然是不可行的。 

关键的结构观察是，任何时刻唯一重要的是写入每只手的最后一个值。 每次移动都会覆盖一个坐标，并且约束仅取决于这两个当前值。 所以状态是一对 (x, y)，但这些值来自一个受限集合：要么是 0，要么是为该手牌选择的某个 ki。 

困难在于，虽然状态空间的值范围很大，但步骤数量很大，但决策是二元的。 这表明随着时间的推移，DP 会随着状态的压缩而变化。 

我们将 dp[i][0/1] 定义为是否可以处理前 i 步，并以分别分配给左或右的第 i 个值结束。 然而，这仍然错过了实际价值的约束。 

相反，我们颠倒了观点：在每一步，我们不是跟踪精确值，而是跟踪每只手可以持有的可能的值间隔，同时仍然允许完成后缀。 这将问题转化为维持向后传播的可行性范围。 

更有效的方法是带有状态剪枝的前向DP。 对于每一步，我们为左值和右值保留一组候选状态。 但我们没有存储所有值，而是观察到，对于固定分配模式，这些值恰好是分配给每只手的 ki 的子序列。 因此，左手由分配给它的选定索引的子序列决定。 

这导致了经典的简化：对于每一步，我们只需要跟踪是否有可能达到最后一次赋值为左或右的状态，以及通过使用父指针向后重建来隐式确定当前值。 每一步的可行性检查都是局部的：如果我们将 ki 分配给左侧，我们必须确保它位于 [ai, bi] 中，右侧也是如此。

因此，我们维护两个 DP 层：dp[i][0] 意味着我们将第 i 张卡分配给左侧，dp[i][1] 意味着分配给右侧。 转换仅取决于先前的分配是否有效以及结果值满足间隔约束。 

这会产生带有回溯的 O(n) DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 每步具有两种状态的 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们在前缀上构建一个动态程序，其中每个状态对哪只手收到当前牌进行编码以及该选择是否保持双手有效。 

1. 我们用 left = 0 和 right = 0 来初始化系统，这已经必须隐式满足第 0 步之后的第一个约束。 
2. 对于每一步 i，我们考虑将 ki 放在左手上。 如果我们这样做，新的左变为 ki，而右保持不变。 仅当 ki 位于 [ai, bi] 范围内并且未改变的右值位于 [ci, di] 范围内时，此移动才有效。 
3. 同样，我们考虑将 ki 放入右手，将右更新为 ki 并检查左值是否保持在其区间内。 
4. 我们将 dp[i][0] 和 dp[i][1] 存储为可达状态，这意味着可以使用步骤 i 中的相应选择来处理最多 i 的情况。 
5. 为了重建答案，我们维护父指针：从每个 dp 状态我们记住它是来自 dp[i−1][0] 还是 dp[i−1][1]。 
6. 处理完所有步骤后，如果 dp[n][0] 和 dp[n][1] 都不可达，则不存在有效序列。 
7. 否则，我们从有效的结束状态回溯并重建选择序列。 

关键的微妙之处在于，状态不仅是在本地选择手牌的可行性，而且是在每次分配后同时维护两个约束的可行性。 由于每步只有一个值发生变化，因此检查有效性减少为根据其间隔检查更新的手牌，同时确保未更改的手牌已经满足上一步的间隔。 

### 为什么它有效

 不变量是，当存在前 i 个步骤的选择序列，在步骤 i 之后产生有效配置，并且第 i 个移动将 ki 分配给手 t 时，dp[i][t] 为真。 由于每次转换仅修改一个坐标，并且约束仅取决于当前坐标，因此除了前一个有效状态之外，没有隐藏的历史记录。 步骤 i 处的每个有效配置必须恰好来自步骤 i−1 处的一个有效配置，通过将 ki 分配给两只手之一，因此 DP 捕获所有且仅有效的序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    k = [0] * (n + 1)
    a = [0] * (n + 1)
    b = [0] * (n + 1)
    c = [0] * (n + 1)
    d = [0] * (n + 1)

    for i in range(1, n + 1):
        k[i] = int(input())
        a[i], b[i] = map(int, input().split())
        c[i], d[i] = map(int, input().split())

    # dp[i][0] = last move to left, dp[i][1] = last move to right
    dp = [[False, False] for _ in range(n + 1)]
    parent = [[-1, -1] for _ in range(n + 1)]

    # initial state: both 0 are in range after step 0 implicitly
    dp[0][0] = dp[0][1] = True

    left_val = [0] * (n + 1)
    right_val = [0] * (n + 1)

    for i in range(1, n + 1):
        for prev in [0, 1]:
            if not dp[i - 1][prev]:
                continue

            l = left_val[i - 1]
            r = right_val[i - 1]

            # put in left
            if a[i] <= k[i] <= b[i] and c[i] <= r <= d[i]:
                if not dp[i][0]:
                    dp[i][0] = True
                    parent[i][0] = prev
                    left_val[i] = k[i]
                    right_val[i] = r

            # put in right
            if a[i] <= l <= b[i] and c[i] <= k[i] <= d[i]:
                if not dp[i][1]:
                    dp[i][1] = True
                    parent[i][1] = prev
                    left_val[i] = l
                    right_val[i] = k[i]

    end = -1
    if dp[n][0]:
        end = 0
    elif dp[n][1]:
        end = 1
    else:
        print("No")
        return

    ans = [0] * (n + 1)
    cur = end

    for i in range(n, 0, -1):
        ans[i] = cur
        cur = parent[i][cur]

    print("Yes")
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该实现维护两个 DP 层并使用父指针重建路径。 数组 left_val 和 right_val 表示创建状态时每手牌的值。 由于每个状态每层仅记录一次，因此这些存储的值与所选的转换保持一致。 

一个常见的陷阱是覆盖 dp 状态而不保留关联值的正确性。 该代码通过仅设置一次 dp 状态并在此时绑定其结果配置来避免这种情况。

 ## 边缘情况

 当两种选择在本地有效但只有一种保留未来的可行性时，就会出现关键的边缘情况。 DP 处理这个问题是因为它不会过早地丢弃替代的可达状态； 它尽可能保留 dp[i][0] 和 dp[i][1] 。 

另一个微妙的情况是，第一步已经迫使一只手偏离零。 由于双手都从零开始，如果第一个 ki 位于一个间隔之外但在另一个间隔内，则只有一个 DP 状态存在，这是正确的，因为不存在替代配置。 

最后一种情况是，当约束非常严格时，中间步骤会迫使双手之间发生振荡。 重建确保每个步骤都使用存储的父指针，而不是贪婪地重新计算，即使在强制切换序列中也能保持一致性。
