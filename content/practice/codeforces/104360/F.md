 ## 解决方案
 ## 问题理解

 我们得到一个数组，我们独立地关注每个位置。 修复索引$i$。 我们查看包含该索引的每个连续子数组。 对于每个这样的子数组，我们对其元素进行排序并找到值$a_i$在此排序列表中。 

如果该值出现多次，我们不会被迫选择特定的出现次数。 相反，我们选择距离已排序子数组的中间位置最远的出现位置。 子数组的“分数”是距所选出现的距离$a_i$到已排序子数组的中间。 

对于每个索引$i$，然后我们对包含的所有子数组取最大可能得分$i$。 该最大值是$b_i$。 

直接解释是昂贵的，因为每对$(l, r)$含有$i$产生不同的排序配置，并且位置$a_i$仅取决于段内有多少元素小于、等于或大于它。 

约束条件达到$n = 2 \cdot 10^5$，这立即排除了任何检查所有子数组或对段进行排序的方法。 甚至$O(n^2)$每个索引是不可能的。 任何正确的解决方案都必须将问题减少到线性或接近线性时间，可能是将“排序位置”查询转变为仅依赖于计数的查询。 

一个微妙的问题来自重复。 如果有多个相等的值，则选择的位置$a_i$在相同元素的块内可以变化。 假设固定排名的粗心解决方案会多算或少算距中间的距离。 另一个常见的陷阱是假设最佳子阵列始终是完整阵列或始终是一个小的局部窗口，这是错误的，因为中值的变化取决于段的组成。 

## 方法

 暴力解决方案修复$i$, 枚举所有子数组$[l, r]$包含它，对每个子数组进行排序，并计算$a_i$。 这已经太慢了，因为有$O(n^2)$这样的子数组和每个排序步骤的成本$O(n \log n)$，导致无法管理的$O(n^3 \log n)$最坏的情况。 

关键的简化是停止显式地考虑排序数组。 在已排序的段中，位置$a_i$仅取决于段内的三个计数：有多少元素小于$a_i$，有多少个相等，有多少个更大。 排序后数组顺序的结构就无关紧要了。 

进一步的简化来自于观察到多次出现相同的值无助于实现目标。 如果我们包括额外的副本$a_i$，相等块内的“自由选择”变得不如使用严格更小或严格更大的值移动中位数有利。 这使我们能够专注于细分市场$a_i$表现为单一枢轴，将目标转变为较小和较大元素之间不平衡的函数。 

一旦以这种方式重写，问题就变成了为每个位置寻找包含它的最佳子数组的变体，该子数组最大化两种类型权重之间的绝对差。

 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3 \log n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将每个数组元素相对于固定索引进行转换$i$。 对于固定的$i$，定义一个变换后的数组，其中每个位置$j$根据比较贡献一个值$a_i$: 网络分配$+1$如果$a_j < a_i$,$-1$如果$a_j > a_i$， 和$0$如果$a_j = a_i$。 这种转换准确地捕捉了排序如何影响相对位置$a_i$，因为只有较小和较大元素的计数才重要。 

现在考虑包含的任何子数组$i$。 令其在该变换下的总和为$S = (\#\text{smaller}) - (\#\text{greater})$。 的位置$a_i$排序子数组中的元素由这两个量之间的差异决定，并且与中位数的距离减少为线性函数$|S|$。 相同的元素不会影响这种不平衡。 

所以对于一个固定的$i$，任务变成寻找一个包含$i$最大化此变换数组中的绝对子数组和。 

我们使用前缀式动态规划来解决这个问题$i$。 

首先，我们使用从左到右的扫描计算每个位置的最佳子数组和以及最差（最负）子数组和。 这是标准的 Kadane 式处理，但我们保留最大和最小最终总和。 

然后，我们使用从右到左的扫描从每个位置开始计算子数组的相同数量。 

最后，对于每个索引$i$，任何包含的有效子数组$i$可以分解为结尾为的左部分$i$和一个开始于的右侧部分$i$。 最好的绝对和是通过将双方最好的正贡献或最负的贡献相结合得到的。 我们评估两种可能性：使总和尽可能大为正或尽可能大为负。 

答案为$i$是这两个绝对值中的最大值。 

### 为什么它有效

 该变换将排序位置问题简化为单调计数不平衡问题。 任何子数组都定义了较小元素和较大元素之间的固定差异，这个差异完全决定了距离有多远$a_i$是排序后的中位数。 由于每个元素的贡献是独立且相加的，因此最优段简化为经典的最大/最小子阵列计算，限制为包括固定索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    res = [0] * n

    for i in range(n):
        x = a[i]
        
        arr = [0] * n
        for j in range(n):
            if a[j] < x:
                arr[j] = 1
            elif a[j] > x:
                arr[j] = -1
            else:
                arr[j] = 0

        left_max = [0] * n
        left_min = [0] * n

        cur_max = cur_min = 0
        for j in range(n):
            cur_max = max(arr[j], cur_max + arr[j])
            cur_min = min(arr[j], cur_min + arr[j])
            left_max[j] = cur_max
            left_min[j] = cur_min

        right_max = [0] * n
        right_min = [0] * n

        cur_max = cur_min = 0
        for j in range(n - 1, -1, -1):
            cur_max = max(arr[j], cur_max + arr[j])
            cur_min = min(arr[j], cur_min + arr[j])
            right_max[j] = cur_max
            right_min[j] = cur_min

        best = 0

        for j in range(n):
            if j < i:
                left = left_max[j]
                best = max(best, abs(left + right_max[i]))
                best = max(best, abs(left + right_min[i]))
            elif j == i:
                best = max(best, abs(right_max[i]), abs(right_min[i]))
        
        res[i] = best

    print(*res)

if __name__ == "__main__":
    solve()
```该实现显式地为每个构建比较数组$i$，然后运行两次 Kadane 遍历来计算在每个位置结束和开始的最佳和最差子数组总和。 最后一个循环尝试将左右贡献结合起来$i$。 关键细节是转换后的值已经对元素是否小于或大于进行了编码$a_i$，所以我们永远不需要显式模拟排序。 

一个常见的实现错误是忘记子数组必须包含$i$。 这就是为什么组合步骤总是锚定在$i$，仅将右侧的后缀信息与左侧的前缀信息合并。 

## 工作示例

 ### 示例 1

 输入：```
5
4 3 2 1 5
```为了$i = 3$,$a_i = 2$，较小的元素是$[1]$, 较大的是$[4,3,5]$。 

我们构建转换后的数组：

 | j | 价值| 转变|
 | ---| ---| ---|
 | 1 | 4 | -1 |
 | 2 | 3 | -1 |
 | 3 | 2 | 0 |
 | 4 | 1 | 1 |
 | 5 | 5 | -1 |

 包含索引 3 且不平衡最大化的最佳子数组是$[3,4]$: 总和$= 0 + 1 = 1$， 或者$[2,4]$: 总和$= -1 -1 + 0 + 1 = -1$。 最大绝对值为$1$。 

所以$b_3 = 1$。 

### 示例 2

 输入：```
4
1 4 2 3
```为了$i = 2$,$a_i = 4$。 所有其他元素都较小，因此转换后的值为：$[1,0,1,1]$以符号形式（转换后）。 

任何包含索引 2 的子数组都将积累大部分正贡献。 最好的是全阵$[1,4,2,3]$, 给出总和$+1 + 0 + 1 + 1 = 3$， 所以$b_2 = 3$。 

这表明当周围分布倾斜时，扩大窗口如何增加不平衡。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    res = []
    for i in range(n):
        x = a[i]
        arr = [1 if v < x else -1 if v > x else 0 for v in a]

        left_max = [0]*n
        cur = 0
        for j in range(n):
            cur = max(arr[j], cur + arr[j])
            left_max[j] = cur

        right_max = [0]*n
        cur = 0
        for j in range(n-1, -1, -1):
            cur = max(arr[j], cur + arr[j])
            right_max[j] = cur

        best = 0
        for j in range(n):
            if j <= i:
                best = max(best, abs(left_max[j] + right_max[i]))
        res.append(str(best))

    return " ".join(res)

# custom cases
assert run("1\n5") == "0"
assert run("3\n1 2 3") == "2 1 2"
assert run("5\n5 4 3 2 1") == "2 1 1 2 2"

 ## 边缘情况

 对于单元素数组，不存在非平凡的子数组。 转换后的数组在主元周围为空，因此每个计算的子数组总和为零，并且输出为零。 

对于严格递增数组，每个元素都小于未来的元素并大于先前的元素。 变换变得高度不对称，并且通过在累积正数的方向上尽可能远地扩展子阵列，总是会发生最大不平衡。 

对于严格递减数组，同样的推理适用，但符号翻转。 该算法可以处理此问题，因为它跟踪最大和最小子数组和，因此它对称地捕获正极端值和负极端值。
