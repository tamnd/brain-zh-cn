 ## 解决方案
 ## 问题理解

 我们得到一串小写英文字母。 每个查询选择一个连续的子字符串，我们使用固定规则转换该子字符串：每个字符都独立扩展，其中位置处的字母`x`字母表中的内容完全重复`x`次。 例如，`a`成为一份副本，`b`变成两份，`c`变成三份，依此类推。 任务不是构造转换后的字符串，而是计算每个查询的最终长度。 

因此，每个查询从根本上要求对子字符串进行加权和，其中字符的权重仅取决于其身份。 如果我们映射`a -> 1, b -> 2, ..., z -> 26`，每个查询都要求在一个范围内这些权重的总和。 

输入限制最多允许 100,000 个字符和 100,000 个查询。 任何从头开始重新计算每个查询总和的解决方案都需要扫描`O(n)`每个查询的字符数，导致`O(nq)`在最坏的情况下，其顺序为`10^10`操作并且不会及时运行。 这立即迫使基于预处理的解决方案具有恒定或对数查询时间。 

如果人们试图过于直白地进行转换，就会出现一个微妙的问题。 构建扩展字符串或模拟每个字符的重复会消耗时间和内存。 即使单个查询也可以生成长度可达的字符串`26 * n`，这远远超出了可行的建设。 唯一有意义的数量是贡献的总和。 

另一种边缘情况是子字符串是单个字符。 答案应该正是它的字母表索引。 这有助于验证前缀处理的正确性，因为前缀和中的相差一错误经常出现在此处。 

## 方法

 暴力破解的想法很简单：对于每个查询，迭代子字符串，将每个字符转换为其字母表位置，然后累加总和。 这是正确的，因为每个字符对最终长度都有独立的贡献。 然而，这种方法对重叠范围重复相同的工作。 和`n = 100000`和`q = 100000`，最坏的情况会重复扫描字符串的大段，导致大约`10^10`字符操作。 

关键的观察是每个字符贡献一个独立于上下文的固定值。 这意味着我们可以预先计算这些值的前缀和。 一旦我们构建了一个数组`pref`， 在哪里`pref[i]`存储第一个的总贡献`i`字符，任何查询`[l, r]`可以回答为`pref[r] - pref[l-1]`。 这将在 O(n) 预处理后将每个查询时间减少到 O(1) 时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了 |
 | 前缀和 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 将字符串转换为数值数组，其中每个字符`c`被映射到`ord(c) - ord('a') + 1`。 这直接表示该字符在虚构的扩展字符串中重复的次数，但我们从不构造该字符串。 
2.构建前缀和数组`pref`尺寸的`n + 1`， 在哪里`pref[i]`等于第一个值的总和`i`人物。 此步骤将所有重复的范围计算压缩为单个结构。 
3. 对于每个查询`[l, r]`，将答案计算为`pref[r] - pref[l - 1]`。 这是有效的，因为前缀和存储累积贡献，而减法隔离了范围。 
4. 立即输出每个结果或最后存储并打印。 

唯一真正的陷阱是索引。 该问题使用从 1 开始的索引，而 Python 数组是从 0 开始的。 在前缀构造和查询时一致地移动是至关重要的。 

### 为什么它有效

 每个字符对最终长度都有独立的贡献，并且变换规则不会引入位置之间的任何交互。 这使得问题成为区间上的线性加性函数。 前缀总和在减法下保留精确的区间总和，因此每个查询都简化为评估两个预先计算的累积值的差异。 不涉及近似或状态依赖性，因此正确性直接来自线性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())
    s = input().strip()

    pref = [0] * (n + 1)

    for i in range(n):
        val = ord(s[i]) - ord('a') + 1
        pref[i + 1] = pref[i] + val

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        out.append(str(pref[r] - pref[l - 1]))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```该代码首先根据字符权重构造前缀和数组。 每个位置贡献其字母表索引，并且前缀数组累积这些值。 

每个查询都通过两个前缀值的减法来回答。 减法`pref[r] - pref[l - 1]`正确处理包含范围，因为`pref`是用前导零条目定义的。 

一个常见的实施错误是忘记`+1`前缀索引的转变或在查询中混合基于 0 和基于 1 的索引。 另一个是每个查询重建前缀数组，而不是全局一次。

 ## 边缘情况

 单字符查询，例如`s = "c", l = r = 1`直接返回`3`。 前缀数组变为`[0, 3]`，所以答案是`pref[1] - pref[0] = 3`。 这证实了基本索引无需特殊处理即可工作。 

全范围查询测试前缀数组是否正确聚合整个字符串。 例如，`s = "abc"`给出前缀`[0,1,3,6]`，并查询`[1,3]`产量`6`，匹配直接和。 

统一字符串如`"aaaaaa"`验证重复的相同贡献是否正确累积。 每个前缀步骤恰好增加 1，因此范围总和减少为与子串长度成正比的简单差值。 

这些情况共同确保索引和累积逻辑在所有查询类型中保持一致。
