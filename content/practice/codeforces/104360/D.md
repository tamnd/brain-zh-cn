 ## 解决方案
 ## 问题理解

 我们有多种产品类型，每种类型都需要固定数量的购买量。 每次购买通常花费 2 个单位的钱。 每次我们购买任何物品（无论​​其类型如何）时，都会有一个全局计数器增加。 对于每种产品类型，一旦购买的商品总数达到该类型特定的阈值，该类型的未来购买就会变得更便宜，只需 1 件而不是 2 件。 

我们唯一的自由是我们购买所有类型的单个商品的顺序。 目标是安排这些购买，以便在折扣解锁之前发生尽可能多的昂贵购买，并在折扣生效后发生尽可能多的廉价购买。 

输入规模大：产品种类多达十万种，总需求项高达万亿。 这立即排除了对单个项目的任何模拟或依赖于明确跟踪每次购买的任何状态。 任何可行的解决方案都必须将每种类型压缩为聚合推理，并在大致线性或线性算数时间内运行。 

天真的解释会尝试一步一步地模拟这个过程，总是选择接下来要购买的物品。 这会失败，因为总共最多可以进行 10^14 次单独购买，因此即使是贪婪的模拟也是不可能的。 

当所有阈值与项目总数相比非常大时，就会出现微妙的边缘情况。 在这种情况下，不会激活任何折扣，答案只是所有数量总和的两倍。 粗心的解决方案可能仍然会尝试不必要地优化排序，但它无法改进任何东西。 

另一种边缘情况是一种类型的阈值非常小但数量巨大。 那么，最好的策略在很大程度上取决于尽早触发折扣，因为这会将大量昂贵购买的后缀转化为廉价购买。 这表明排序在全球范围内都很重要，而不是针对每种类型。 

## 方法

 暴力策略将明确模拟每次购买，为每一步维护已购买的商品数量，并检查每种类型的折扣是否已激活。 在每一步中，我们都会通过尝试所有剩余类型来最佳地选择下一个项目。 这导致复杂度为总项目乘以类型数，当总项目达到 10^14 时，这是完全不可行的。 

关键的观察结果是，折扣条件仅取决于购买的商品的全球数量，而不取决于购买的类型。 每种类型 i 在进行 bi 全球购买后都会打折。 这意味着整个问题简化为决定每个项目是否放置在全局排序中的某个阈值位置之前或之后。 

我们可以将这个过程重新解释为选择所有单个项目的排列。 如果在其类型解锁之前放置，每个物品都会贡献 2 成本，否则成本 1。 面临的挑战是确定每种类型应提前放置多少商品，以全局最优的方式延迟或加速折扣激活。 

关键思想是从“投资”的角度思考。 尽早购买一件物品需要花费 2，但有助于推动所有未来物品更接近其同类物品的折扣。 然而，尽早购买任何物品也有助于所有其他类型更快地达到他们的门槛。 因此，早期购买应该分配给那些延迟折扣危害最小的商品。 

解决此问题的标准方法是根据类型需要提前购买的紧急程度（由阈值 bi 捕获）对类型进行排序。 bi较小的类型应该优先被“延迟”，因为它们的折扣激活得很快，因此从早期操纵中获益较少。 

这导致基于 bi 的贪婪排序，有效地将较小的 bi 视为更敏感并更早地调度它们。

 ## 算法演练

 ## 1. 将每种类型压缩为一对 (ai, bi)

 我们首先独立对待每种产品类型，存储我们必须购买的商品数量以及它们变得便宜的阈值。 

## 2. 按 bi 递增对产品类型进行排序

 门槛较小的类型对早期全球购买更加敏感，因为它们可以快速解锁折扣。 排序确保我们首先处理最“容易解锁”的类型。 

## 3. 维护采购物品的全球计数器

 这个计数器代表了我们在全局序列中的进展程度。 它确定新购买的商品是否仍然昂贵或已经打折。 

## 4. 迭代排序类型并决定贡献

 对于每种类型，我们从概念上决定在我们的计划引起的全局排序中达到其阈值 bi 之前购买多少个 ai 项目。 每个这样的项目贡献成本 2，而其余的贡献成本 1。 

关键的原因是，一旦我们确定了类型的顺序，所有较早类型的商品都将有助于增加全局计数器，从而加速后面类型的折扣激活。 

## 5. 累计总成本

 对于每种类型，我们计算在构建的订单下其折扣生效之前购买了多少件商品。 我们为这些添加 2，为其余添加 1。 

## 为什么它有效

 正确性取决于阈值的单调性。 如果较早处理bi较小的类型，则在任何最佳安排中它都会更快地达到折扣条件，因为推迟它只会增加已购买商品的数量，这只会对其有所帮助。 因此，在最优排序中，类型可以按 bi 的非递减顺序排列，而不会损失最优性。 

一旦以这种方式排序，全局过程就会变得一致：每种类型在折扣开始之前都会经历可预测数量的早期购买，并且以后的重新安排无法在不违反阈值排序约束的情况下提高总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    items = []
    total_a = 0

    for _ in range(n):
        a, b = map(int, input().split())
        items.append((b, a))
        total_a += a

    items.sort()

    taken = 0
    ans = 0

    for b, a in items:
        if taken >= b:
            ans += a
        else:
            need = min(a, b - taken)
            ans += need * 2
            ans += (a - need)
            taken += a

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先按阈值 bi 对商品进行排序，以便首先处理折扣激活较早的类型。 所采用的变量跟踪迄今为止全球已购买的商品数量。 对于每种类型，我们根据当前的全球数量检查其有多少商品仍处于“预折扣”状态。 这些贡献成本 2，而其余贡献成本 1。我们还将全局计数器提前全额 ai，因为这种类型的所有项目都被视为购买序列的一部分。 

一个微妙的点是我们从不模拟单个项目。 相反，我们批量计算有多少项目落在阈值边界之前或之后。 这是至关重要的，因为总 ai 最多可达 10^14。

 ## 边缘情况

 关键的边缘情况是当所有 bi 值超过项目总数时。 在这种情况下，全局计数器永远不会达到任何阈值。 该算法以任意顺序处理所有类型，但由于 take 永远不会与任何 bi 交叉，因此每个项目的定价为 2。循环中的公式永远不会触发折扣分支，因此保留了正确性。 

另一种边缘情况是当一种类型的 bi 等于 1 且 ai 非常大时。 全局处理完第一个商品后，该类型立即打折。 该算法确保在剩余间隙逻辑下，只有该类型的第一个商品贡献成本2，而后续的所有商品都计为成本1，符合尽早触发折扣的预期最优策略。
