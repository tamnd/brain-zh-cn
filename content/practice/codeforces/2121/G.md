 ## 解决方案
 ## 问题理解

 我们被要求处理一个二进制字符串并计算每个连续子字符串的最大频率`0`或者`1`在该子字符串中，然后将所有子字符串中的这些值相加。 例如，在字符串中`0110`, 子串`011`有两个`1`s 和一`0`，因此其最大频率为 2。输出是所有可能子串上这些最大频率的总和。 

输入包含多个测试用例。 每个测试用例给出一个长度最大为 200,000 的字符串，所有测试用例的总长度也以 200,000 为界。 在 2 秒的时间限制下，任何单独检查每个子串的算法都会太慢，因为子串的数量大致呈二次方增长`n*(n+1)/2`。 为了`n = 2*10^5`，大约有 200 亿个子串，远远超出了 2 秒的处理能力。 我们需要一种相对于线性或线性时间运行的方法`n`。 

可能导致简单实现失败的边缘情况包括完全由一个字符组成的字符串。 例如，对于`1111`，每个子串只包含`1`s，最大频率之和是所有子串的长度之和，即 10。粗心的实现，仅计算不同的片段或交替可能会低估。 另一个微妙的情况是交替字符串，例如`010101`; 在这里，子字符串的最大频率取决于长度，因此解决方案必须正确考虑连续相等字符的长度。 

## 方法

 蛮力方法很简单：迭代每对开始和结束索引`(l, r)`,提取子串`s[l:r+1]`, 数数`0`沙`1`s，取最大值，然后求和。 这是正确的，但有复杂性`O(n^3)`如果天真地实施（或`O(n^2)`如果计数是增量维护的），这对于`n`最多 2*10^5。 

关键的见解是子字符串中的最大频率是由连续的相同字符的运行确定的。 子字符串的最大频率是其中最长的连续相同字符块的长度。 因此，我们可以迭代连续相同字符的块并有效地计算它们的贡献，而不是枚举子字符串。 

对于一个长度的运行`k`，本次运行贡献的子串数量`i`最大是通过组合确定的。 所有运行的贡献总和可以通过对序列求和来计算`1 + 2 + ... + k`每次运行。 这是可行的，因为包含部分运行的每个子字符串将至少包含其字符之一，并且最大频率将由其中最长的块决定。 这将问题减少到线性时间`O(n)`每个测试用例。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |
 | 最佳（基于运行的总和）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化变量`answer = 0`为当前字符串的最大频率之和。 
2. 迭代字符串，同时跟踪连续的相同字符。 启动一个计数器`count = 1`。 
3. 对于位置处的每个字符`i`（从第二个字符开始），如果与前一个字符匹配，则递增`count`。 否则，处理当前运行：添加总和`count*(count+1)//2`到`answer`并重置`count = 1`。 
4. 完成循环后，将最后一次运行的总和添加到`answer`。 
5. 输出计算结果`answer`对于这个测试用例。 
6. 对每个测试用例重复上述步骤。 

为什么有效：子字符串中的最大频率始终至少是该子字符串中包含的最长相同字符的长度。 通过对连续运行的一系列长度求和，我们有效地考虑了所有子串的贡献。 每个子串的最大频率在总和中只计算一次，或者作为来自`0`运行或`1`运行它包含的内容。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        answer = 0
        count = 1
        for i in range(1, n):
            if s[i] == s[i-1]:
                count += 1
            else:
                answer += count * (count + 1) // 2
                count = 1
        answer += count * (count + 1) // 2
        print(answer)

if __name__ == "__main__":
    solve()
```该代码有效地处理多个测试用例。 它使用一个简单的计数器跟踪相同字符的运行，并且对于每次运行，使用以下公式计算从 1 到运行长度的所有整数的总和`count*(count+1)//2`。 这可确保正确计算每个子串的最大频率贡献，而无需显式枚举子串。 通过在循环后添加最后一个运行，可以自然地处理单字符字符串或以最后一个字符结束的运行等边缘条件。

 ## 边缘情况

 对于单字符字符串`0`，算法初始化`count=1`，不进入循环，然后添加`count*(count+1)//2 = 1`到`answer`，产生正确的输出。 

对于像这样的字符串`1111`，计数器对整个运行进行计数，然后添加`4*(4+1)//2 = 10`在最后。 包含此运行的子字符串均已正确计入总和中。 

对于交替字符串`010101`，每次运行计数器在 1 秒之间交替，求和`1*2//2`反复。 每个小运行都会正确地对包含它的子字符串做出贡献，并且所有贡献的总和与预期总数相匹配。 这证实了该算法可以处理两个极端：长时间均匀运行和频繁交替。
