 ## 解决方案
 ## 问题理解

 给定两个十进制形式的等长整数，我们可以选择任意整数`x`位于它们之间的包容范围内。 对于一个选择的`x`，我们将其数字与端点的数字进行比较并分配成本：每个位置`x`匹配左端点贡献一个单位，每一个位置`x`匹配右端点也贡献一个单位。 目标是选择一个`x`在使此类匹配位置的总数尽可能小的范围内。 

重要的结构是成本完全是位置上的并且独立于数字，除了以下约束：`x`必须保持在有界区间内。 该约束与其他独立的数字决策相结合。 

由于每个数字最多有 9 位数字，因此可能的状态范围足够小，因此数字动态规划解决方案是可行的。 对所有值的暴力枚举`x`至多是$10^9$每个测试用例对于最多$10^4$测试用例。 

一个幼稚但诱人的错误是独立对待每个数字：尽可能选择与两个端点不同的数字。 这会失败，因为选择本地不同的数字可能会违反保持在范围内的全局约束$[l, r]$。 另一种常见的错误方法是贪婪的逐位选择，而不跟踪我们是否已经严格位于区间内。 

当较高数字的间隔很紧时，会出现微妙的边缘情况。 例如，如果`l = 199`和`r = 201`，可以自由选择中间数字，但是一旦前缀等于`l`或者`r`，后来的决策受到只能通过状态处理的方式的限制。 

## 方法

 强力解决方案将迭代所有整数`x`之间`l`和`r`，计算与两个端点的数字匹配，并跟踪最小值。 这是正确的，因为它直接检查每个有效的候选者。 然而，该区间可能跨越近十亿个值，这使得即使对于单个测试用例也是完全不可行的，更不用说一万个测试用例了。 

关键的观察结果是成本仅取决于数字，有效性约束仅取决于前缀比较。 这正是数字动态规划问题的结构。 在每个位置我们决定一个数字`x`，但是我们必须跟踪前缀是否仍然等于`l`，仍然等于`r`，或者已经在开区间内。 

一旦我们严格地在区间内移动，未来的数字就不受限制。 这将问题转化为具有边界状态的位置上的小 DP，其中转换考虑当前前缀边界允许的所有数字。 每个选择都会增加一个成本，具体取决于它是否与中的相应数字匹配`l`或者`r`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((r - l) · d) | O(1) | O(1) | 太慢了 |
 | 数字DP | O(d·10·4) | O(d·4) | 已接受 |

 ## 算法演练

 我们将这两个数字视为长度相等的字符串。 让`n`是位数。 我们构建一个 DP，其中每个状态都跟踪我们的位置以及我们是否仍然匹配下限和上限约束。 

1. 转换`l`和`r`到数字数组中，这样我们就可以直接访问每个位置。 
2.定义DP状态`dp[i][tightL][tightR]`，表示从位置开始的最小成本`i`当到目前为止的前缀仍然等于`l`如果`tightL = 1`，并且仍然等于`r`如果`tightR = 1`。 如果约束不再严格，则忽略相应的边界。 
3. 各位置`i`，确定允许的数字范围。 如果我们仍然紧`l`，最小位数为`l[i]`，否则就是`0`。 如果我们仍然紧`r`，最大位数为`r[i]`，否则就是`9`。 
4. 尝试每一个数字`d`在这个允许的范围内。 对于每个选择，计算成本贡献为`1`如果`d == l[i]`，加上`1`如果`d == r[i]`。 
5. 转换到下一个状态。 如果我们选择`d == l[i]`，较低的紧度仍然存在； 否则它会破裂。 同样，如果`d == r[i]`，上部松紧度仍然存在； 否则它会破裂。 
6. 选取所有选项中的最小值并记住。 

答案是`dp[0][1][1]`。 

### 为什么它有效

 DP不变量是每个状态代表与给定的紧密性约束一致的所有前缀中的最优解。 由于每次转换都会考虑保留可行性的所有有效数字，因此没有有效的构造`x`永远被排除在外。 同时，通过强制执行从以下内容派生的数字边界，立即修剪每个无效前缀`l`和`r`。 因为决策仅取决于当前位置和紧密状态，所以最优子结构成立，并且 DP 完全捕获搜索空间而没有冗余。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    l, r = input().split().strip()
    n = len(l)
    
    l = list(map(int, l))
    r = list(map(int, r))

    dp = [[[INF] * 2 for _ in range(2)] for _ in range(n + 1)]
    dp[n][0][0] = dp[n][0][1] = dp[n][1][0] = dp[n][1][1] = 0

    for i in range(n - 1, -1, -1):
        for tl in range(2):
            for tr in range(2):
                best = INF

                lo = l[i] if tl else 0
                hi = r[i] if tr else 9

                for d in range(lo, hi + 1):
                    cost = 0
                    if d == l[i]:
                        cost += 1
                    if d == r[i]:
                        cost += 1

                    ntl = tl and (d == l[i])
                    ntr = tr and (d == r[i])

                    best = min(best, cost + dp[i + 1][ntl][ntr])

                dp[i][tl][tr] = best

    return dp[0][1][1]

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```DP 是从最后一位数字向第一位数字自下而上构建的。 每个状态都会尝试与当前前缀约束一致的所有可行数字。 紧密度标志会仔细更新：一旦数字偏离`l[i]`或者`r[i]`，相应的约束被永久放松。 

一个常见的实施陷阱是忘记打破严格约束是不可逆转的，这就是为什么`ntl`和`ntr`使用逻辑 AND 计算。 另一个微妙之处是当松紧度丧失时正确处理边界； 如果没有它，DP 就会错误地限制后面位置的数字。

 ## 边缘情况

 对于`l = r`，DP从来没有任何自由和唯一有效的`x`是同一个数字。 每个数字都与两个端点匹配，因此成本只是长度的两倍。 DP 处理这一问题是因为所有状态都保持两个紧标志处于活动状态并且仅存在一条路径。 

对于像这样的情况`l = 899`,`r = 999`，第一个数字严重限制了选择。 DP 确保只有数字`[8, 9]`被认为是在零位置，并选择`9`立即打破下界约束，允许后面的数字自由地最小化匹配。
