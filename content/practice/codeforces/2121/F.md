 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，对于每个测试用例，有两个目标值：所需的子数组和`s`和所需的最大值`x`。 任务是计算有多少个连续子数组的总和恰好等于`s`其最大元素恰好是`x`。 

考虑这个问题的一个有用方法是每个子数组都贡献两个独立的约束。 总和条件取决于所有元素在一起，而最大值条件仅取决于段内最大的元素。 有效段必须同时满足两者。 

这些约束迫使我们采取线性或近线性行为。 所有测试用例的总长度最多为`2 · 10^5`，因此任何比每个测试用例的 O(n log n) 更糟糕的解决方案都有超时的风险。 对所有子阵列进行二次扫描是立即不可行的，因为在最坏的情况下它会检查最多大约 10^10 的段。 

一些边缘情况很重要，可能会打破天真的逻辑。 

一个问题是何时`x`没有出现在段中，但所有元素都较小。 这些段可能满足求和条件，但必须排除，因为它们的最大值严格小于`x`。 例如，如果`x = 5`一个段是`[1, 2, 3]`，其总和可能匹配`s`，但无效。 

当元素超过时会发生另一种微妙的情况`x`。 任何包含大于的元素的子数组`x`必须完全排除，因为它的最大值自动违反了要求。 例如，如果`x = 3`，然后是一个包含`4`无论其总和如何，始终无效。 

最后，总和计数与最大限制之间存在着重要的相互作用：总和计数对于前缀总和来说很容易，但最大限制将数组分割成独立的区域，必须小心处理。 

## 方法

 直接暴力方法尝试所有子数组`[l, r]`，计算它们的总和和最大值，并计算符合这两个条件的数量。 可以使用前缀和在 O(1) 中计算总和，但除非进行预处理，否则每个段的最大成本仍为 O(n)。 即使进行预处理，枚举所有 O(n^2) 段也会导致二次时间，这对于 n 高达 2 · 10^5 来说太慢了。 

关键的观察是最大约束是真正的结构驱动因素。 我们可以拆分问题，而不是直接检查“max equals x”：

 子数组恰好具有最大值`x`当且仅当：

 1. 每个元素最多`x`, 和
 2.它至少包含一个元素等于`x`。 

这建议将数组分成最大块，这些块之间的元素大于`x`。 在每个块内，所有元素都≤ x，因此有效的唯一剩余条件是“至少包含一个 x”。 

现在问题变成：在每个块内，用 sum 来计算子数组`s`包括至少出现一次`x`。 

我们使用标准分解技巧来处理这个问题：用总和对所有子数组进行计数`s`在块内，然后减去那些不包含的块`x`。 子数组不包含`x`完全生活在通过在每个位置分割块而形成的更小的段内`a[i] == x`。 

所以每个块严格地分成元素段`< x`。 对于每个这样的段，我们用 sum 来计算子数组`s`使用前缀和和哈希图频率计数。 

这将全局问题简化为线性段上的两次前缀和计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

### 1. 按大于 x 的元素拆分数组

 我们扫描数组并将其分成连续的段，其中所有值都≤ x。 任何包含值 > x 的段都不能贡献任何跨越该值的有效子数组，因此它充当硬边界。 

这确保我们只在最大值可能为 x 的区域内工作。 

### 2. 在每个有效段内，单独的位置等于 x

 在一个细分市场中，我们确定索引，其中`a[i] == x`。 这些职位将强制执行“必须包含 x”的要求。 

我们从概念上将段划分为更小的子段，其中所有值都严格小于 x。 

### 3. 统计段内所有有 sum 的子数组

 我们用 sum 计算子数组的数量`s`使用前缀和。 我们维护一个哈希图`freq[prefix_sum]`并对于每个位置计算有多少个先前的前缀和相等`current_sum - s`。 

这给出了总子数组的总和`s`，无论它们是否包含 x。 

### 4.减去不包含x的子数组

 没有 x 的子数组必须完全位于通过每次出现 x 时进行切割而创建的“仅 < x”段之一内。 

因此，我们迭代这些较小的段，并再次用 sum 对子数组进行计数`s`使用相同的前缀求和方法，对所有此类段求和。 

### 5. 合并结果

 对于每个有效段：

 result += (所有 sum-s 子数组的计数) − (没有 x 的 sum-s 子数组的计数)

 ### 为什么它有效

 该算法依赖于将搜索空间划分为不相交的类。 所有元素 ≤ x 的区域中的每个子数组要么完全缺少 x，要么包含至少一个 x。 这两个类别是互不相交的，涵盖了所有可能性。 前缀和方法通过将总和约束转换为前缀差异的频率匹配来正确计算子数组。 由于每个段都是独立处理的，因此不会对任何子数组进行两次计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def count_sum(arr, target):
    freq = defaultdict(int)
    freq[0] = 1
    cur = 0
    res = 0
    for v in arr:
        cur += v
        res += freq[cur - target]
        freq[cur] += 1
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n, s, x = map(int, input().split())
        a = list(map(int, input().split()))

        ans = 0
        i = 0

        while i < n:
            if a[i] > x:
                i += 1
                continue

            j = i
            while j < n and a[j] <= x:
                j += 1

            segment = a[i:j]

            total = count_sum(segment, s)

            # subtract subarrays that contain no x
            bad = 0
            k = 0
            while k < len(segment):
                if segment[k] == x:
                    k += 1
                    continue
                l = k
                tmp = []
                while k < len(segment) and segment[k] != x:
                    tmp.append(segment[k])
                    k += 1
                bad += count_sum(tmp, s)

            ans += total - bad
            i = j

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先隔离可以满足最大约束的有效区域。 然后，它使用前缀频率图对具有所需总和的所有子数组进行计数。 之后，它删除那些从不包含的子数组`x`通过对由出现次数分隔的子段重新计算相同的计数过程`x`。 

一个微妙的细节是我们从未明确检查计数函数内部的最大值。 最大约束是通过分段在结构上强制执行的，而不是直接计算，这避免了每个子数组的任何 O(n) 最大查询。

 ## 边缘情况

 一个关键的边缘情况是每个元素都大于`x`。 在这种情况下，算法立即跳过所有段，因为没有形成有效块。 例如：

 输入：```
1
4 5 2
3 4 5 6
```扫描发现没有段`a[i] <= 2`，所以答案仍然是 0。这是正确的，因为没有子数组的最大值恰好为 2。 

另一种边缘情况发生在`x`出现多次，但求和有效的子数组从不包含它。 在那种情况下，`total - bad`自然变为零，因为所有有效和段都位于无 x 的区域中。
