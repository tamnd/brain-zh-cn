 ## 解决方案
 ## 问题理解

 我们从 1 到 9 的固定多组数字开始，每个数字只出现一次，写成一行。 唯一允许的操作是一位一位删除数字，但限制是当前序列中只剩下两位数字时不允许删除。 在任意次数的删除之后，我们按原始顺序取出剩余的数字并将它们解释为数字。 目标是以形成素数的序列结束。 

这里重要的结构是，我们不是以任意顺序自由选择数字，而只是从原始排列中删除，因此最终序列必须是给定的 9 位字符串的子序列。 由于数字都是不同的，并且只有 9 个，因此可能的子序列总数为$2^9 = 512$，它足够小，可以在需要时进行详尽的推理。 

塑造解决方案的主要约束是每个测试用例的固定输入大小较小。 尽管测试用例多达 5000 个，但每个用例都是独立的并且非常小。 这立即表明任何方法，即使是 9 的稍微指数级的方法都是可以接受的。 

一个微妙的限制是当只剩下两位数字时删除的限制。 这个规则阻止我们减少到长度1或2然后任意继续，但它并没有从根本上改变哪些子序列是可达的。 任何长度至少为 3 的子序列都是可达的，长度为 2 的子序列仅在最后一步受到限制。 由于在这种情况下质数必须至少有两位数，并且所有一位数质数都只有 2、3、5、7，因此我们仍然必须谨慎对待小长度。 

边缘情况出现在以下情况：

 1. 唯一的质数子序列的长度为 1 或 2。例如，如果最佳候选者是像 2 这样的一位数质数，但由于删除规则间接限制了转换，我们不能以长度 1 结束。 
2. 提前删除大数字的贪婪选择可能会在以后破坏唯一有效的素数子序列。 
3. 有些排列可能根本不包含任何形成素数的子序列，在这种情况下我们必须输出-1。 

天真的贪婪删除的一个具体失败示例是始终保留第一个数字或始终删除最大的数字：此类策略忽略了子序列中素数的全局组合结构。 

## 方法

 暴力策略会枚举 9 位字符串的所有子序列，形成相应的数字，并检查素数。 对于每个测试用例，最多有 512 个子序列，并且检查每个形成的数字的素数是常数时间，因为数字最多为 9 位数字。 经过 5000 次测试，这大约是 250 万次检查，这仍然没问题。 

然而，蛮力有点浪费，因为我们反复重新计算类似候选者的素性。 关键的观察结果是搜索空间很小且固定，因此我们可以预先计算最多 999,999,999 的所有素数，或者简单地即时检查素数。 

一种更结构化的方法是预先计算可以通过数字 1 到 9 的子集的排列形成的所有素数的集合，然后对于每个测试用例，检查这些素数中的任何一个是否作为子序列出现。 但即使这样也太过分了。 

最简单的最佳想法是直接生成 9 位字符串的所有子序列，将每个子序列解释为数字，并测试素数。 删除约束并不限制哪些子序列可以作为最终状态到达，因为任何数字子集都可以通过删除补码来获得，而永远不需要在大小 2 处停止，除非我们完成了。 

所以问题简化为：找到形成素数的任何子序列。

 | 暴力子序列 + 素性检查 | O(512·t) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取 9 位字符串并考虑通过选择索引的任何子集形成的所有子序列。 这是有效的原因是删除允许我们删除任意数字，因此每个子序列都是可达的。 
2. 对于从 1 到 511 的每个子集掩码，通过按原始顺序连接数字来构建数字。 我们跳过产生前导零的掩码，尽管这里的数字是 1-9，所以这种情况永远不会发生。 
3. 将结果数字序列转换为整数。 
4. 通过试除到其平方根来检查整数是否为素数。 由于最大值低于$10^9$，检查到 31623 就足够了。 
5. 如果找到素数，则立即输出相应的子序列并停止处理该测试用例。 
6. 如果没有子序列产生素数，则输出-1。 

我们可以提前停止的原因是我们只需要任何有效的素数子序列，而不是全部。 

### 为什么它有效

 每个可达的最终序列与原始字符串的子序列完全对应，因为删除保留顺序并且仅删除元素。 该算法枚举了所有此类子序列，因此它不会错过任何候选序列。 精确检查每个候选数的素性，因此正确性降低为素性测试的正确性。 由于所有候选人都在下面$10^9$，确定性试分是充分且准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

def solve_case(s):
    n = len(s)
    digits = list(s)

    for mask in range(1, 1 << n):
        val = 0
        used = False

        for i in range(n):
            if mask & (1 << i):
                val = val * 10 + (ord(digits[i]) - 48)
                used = True

        if used and is_prime(val):
            # reconstruct subsequence
            res = []
            for i in range(n):
                if mask & (1 << i):
                    res.append(digits[i])
            return "".join(res)

    return "-1"

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve_case(s))

if __name__ == "__main__":
    main()
```该解决方案迭代从 1 到$2^9 - 1$，按照原来的顺序构建相应的数字。 仅当找到素数以输出数字序列时才执行重建步骤，而数字构造用于快速素性检查。 

素性测试是简单的试除法，由于数值范围较小，因此足够了。

 ## 边缘情况

 一个关键的边缘情况是当唯一可用的素数是个位数时。 对于像这样的输入`987654321`，算法仍然发现`3`因为它枚举了所有子序列，包括长度为 1 的子序列。 尽管删除规则限制在处理过程中停止在大小 2，但它并不妨碍在子序列的逻辑模型中实现大小 1 或 2 作为最终结果。 

另一种情况是没有子序列形成素数，例如`111111111`。 每个构造的数字都是 1 的重复，并且没有一个是素数。 枚举耗尽所有掩码并正确返回-1。 

更微妙的情况是，存在较长的子序列，但它是复合子序列，而较短的隐藏子序列是素数。 穷举掩码搜索确保仍考虑较短的子序列，因此算法不会陷入贪婪的较长选择中。
