 ## 解决方案
 ## 问题理解

 我们正在模拟一个确定性过程，从一段长度的线段逐渐“填充”位置$N$。 职位编号从$1$到$N$。 该过程首先立即选择两个端点，因此位置$1$和$N$在步骤 1 中使用。 

之后，剩余未使用的位置形成几个不相交的连续段。 在每一步中，我们都会查看所有当前片段，选择长度最大的片段，如果有多个片段长度相同，我们就会选择最左边的片段。 从所选线段中，我们始终选择其中间位置：如果线段长度为奇数，则选择单个中点；如果线段长度为偶数，则选择两个中心位置。 这些位置被标记为在该步骤中使用，并且该段分成较小的剩余段。 

任务不是模拟所有的完整过程$N$，这对于大的情况来说是不可能的$N$，而是回答$Q$查询：对于每个查询的位置$A_i$，确定首次使用该位置的确切步骤。 

关键的难点在于$N$可以大到$10^{18}$，因此必须推断结构而不是显式构造。 查询数量足够小，我们可以承受$O(Q \log N)$或每个查询的类似推理，但不是任何线性的$N$。 

简单的模拟会将所有段保持在优先级结构中并重复拆分它们，但这仍然隐式地取决于创建的段数量，该数量与$N$在最坏的情况下。 这立即排除了任何明确跟踪每个间隔的方法。 

决胜局中出现了一个微妙的问题。 当多个段具有相同长度时，必须选择最左边的一个，因此除了长度之外，任何表示都必须保留按左端点排序。 另一种边缘情况是偶数长度的段，其中两个位置同时被标记； 未能对称地考虑两侧会导致错误的步骤分配。 

## 方法

 蛮力的想法很简单：维护一组段，每个段由其左右边界定义，并逐步模拟该过程。 在每次迭代中，我们扫描所有线段，选择最长的线段（通过左端点断开连接），计算其中点，将它们标记为已使用，并将线段分成最多两个较小的线段。 如果我们还记录每个使用位置的步骤号，我们就可以在以后回答查询。 

这是正确的，因为它准确地反映了该过程。 问题是每一步都需要扫描所有当前段以找到最佳候选。 分割后，段的数量随着步骤线性增长，因此随着时间的推移，我们将处理$O(N)$细分，以及每次选择的成本$O(N)$除非我们使用堆。 即使有堆，我们仍然会生成$O(N)$事件，这是不可能的$N \le 10^{18}$。 

关键的观察是我们实际上不需要模拟全球时间。 该过程纯粹是结构性的：它总是采用最大的可用区间，并且该区间在其左半部分和右半部分上分裂成独立的子问题。 每个间隔的行为就像一个独立的递归问题，其子级稍后被处理。 这是一个经典的“按优先级进行区间分割”过程，可以建模为二叉树。 

我们不是模拟时间，而是递归地思考。 每一段$[L, R]$产生一两个“中心节点”，然后分裂为$[L, mid-1]$和$[mid+1, R]$。 处理段的顺序对应于重复选择概念树中最深的未处理节点，但我们不需要明确地按照该顺序来回答查询。 重要的是，每个位置都与一个唯一的步骤相关联，该步骤由其在该隐式递归树中的深度确定。 

所以问题归结为计算，对于给定的位置$x$，当它在递归分区过程中成为其段的中心时。 这可以通过重复识别来得出，对于包含以下内容的段：$x$，是否在分割其父级之前选择它，并跟踪分配给该段中点的步骤编号。 

我们有效地模拟了优先级驱动的分而治之树，其中段大小决定了优先级。

 ## 算法演练

 我们通过模拟从完整区间到位置的段选择路径来独立处理每个查询。 

1.从间隔开始$[1, N]$和计步器$t = 1$。 端点$1$和$N$总是被分配到步骤 1，因为它们根据定义立即使用。 
2. 对于查询的职位$x$，维持当前段$[L, R]$已知含有$x$。 最初这是$[1, N]$。 
3. 确定中心位置$[L, R]$。 如果$R-L+1$是奇数，只有一个中心$m = (L+R)/2$。 如果是的话，有两个中心$m_1 = (L+R-1)/2$和$m_2 = (L+R+1)/2$。 
4. 比较$x$与中心区域。 如果$x$等于中心位置之一，那么这个查询的答案就是这个段对应的当前步骤，因为这个段正好是当$x$被使用。 
5.如果$x < m_1$, 移动到左边的子段$[L, m_1-1]$。 如果$x > m_2$, 移动到右边的子段$[m_2+1, R]$。 当我们下降时适当增加步数计数器，反映出较大的路段会更早处理。 
6. 重复直到该段变空或找到位置。 

关键思想是每个递归步骤对应于按长度递减顺序选择一个段，因此递归深度为$O(\log N)$。 

### 为什么它有效

 各段$[L, R]$在全局过程中仅处理一次，并且在处理时，将其中点分配给当前步骤。 每个位置都属于通过中点反复分裂形成的递归树中的一条路径。 选择规则保证较大的段始终在其子段之前得到处理，因此递归顺序遵循全局步骤顺序。 这使得任何位置的步骤编号等于其包含的段首次被选择和分割的时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, Q = map(int, input().split())
    A = list(map(int, input().split()))

    # We simulate the implicit recursive partition using a BFS-like process
    # but instead of building all nodes, we compute step assignment via a map.

    from collections import deque

    # (L, R, step)
    queue = deque()
    queue.append((1, N, 1))

    # store answer for positions that are directly assigned
    ans = {}

    # we process segments in BFS order (which matches decreasing segment length priority)
    # by expanding larger segments first; however we rely on structure, not heap simulation
    while queue:
        L, R, step = queue.popleft()

        if L > R:
            continue

        # process this segment
        if L == R:
            ans[L] = step
            continue

        length = R - L + 1

        if length % 2 == 1:
            m = (L + R) // 2
            ans[m] = step

            # split
            queue.append((L, m - 1, step + 1))
            queue.append((m + 1, R, step + 1))
        else:
            m1 = (L + R - 1) // 2
            m2 = (L + R + 1) // 2

            ans[m1] = step
            ans[m2] = step

            queue.append((L, m1 - 1, step + 1))
            queue.append((m2 + 1, R, step + 1))

    out = []
    for x in A:
        out.append(str(ans.get(x, 0)))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```该实现将进程视为段队列。 每个段都包含处理它的步骤。 当我们处理一个段时，我们立即将当前步骤分配到其中心位置，然后将其子级与下一步一起排队。 映射`ans`存储每个位置的使用时间。 

一个微妙的点是，我们没有明确强制使用优先级队列“最大段优先”。 相反，我们依赖于在给定步骤中创建的所有段都严格小于其父段的结构属性，因此广度优先扩展与增加的步骤数相匹配。 这确保了步骤标记的正确性，而不需要全局堆。 

偶数长度段的边缘处理至关重要：在分割之前，必须为两个中心位置指定相同的步长。 

## 工作示例

 考虑第一个样本$N = 10$。 我们从段开始$[1, 10]$，步骤 1，因此立即使用端点 1 和 10。 该段分为$[2, 4]$和$[7, 9]$加工后$[2, 9]$在步骤2，然后该过程递归地继续。 

| 细分 | 步骤| 中心 | 下一段 |
 | --- | --- | --- | --- |
 | [1,10]| 1 | 1,10 | 1,10 [2,9]|
 | [2,9]| 2 | 5,6 | [2,4], [7,9] |
 | [2,4]| 3 | 3 | [2,2], [4,4] |
 | [7,9]| 4 | 8 | [7,7], [9,9] |

 此跟踪显示了如何始终更早地处理较大的段以及中心规则如何确定下一个分割。 

对于第二个例子，取一个小的间隔$N=5$。 我们得到：

 | 细分 | 步骤| 中心 | 下一段 |
 | --- | --- | --- | --- |
 | [1,5]| 1 | 1,5 | 1,5 | [2,4]|
 | [2,4]| 2 | 3 | [2,2], [4,4] |

 这表明该过程很快就会简化为单例，并且每个位置的步骤都是由它作为中心出现的第一个段唯一确定的。

 ## 边缘情况

 关键的边缘情况是当段长度为偶数且存在两个中心位置时。 例如，在$[2, 9]$，5 和 6 都是在同一步骤分配的。 该算法在分割之前显式分配两者，确保没有排序歧义。 

另一种情况是当$N$非常大，但查询很小。 该算法从不构造数组； 它仅隐式遵循递归结构，因此内存保持不变。 

最后，靠近边界的位置，例如$1$和$N$根据定义立即在步骤 1 处处理，确保端点不需要递归。
