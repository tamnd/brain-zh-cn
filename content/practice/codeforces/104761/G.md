 ## 问题理解

 我们正在 8 × 8 棋盘上处理一个隐藏的国际象棋问题，其中一个象被放置在一个未知的方格上。 我们不知道它的位置，但我们可以查询任何方格并接收有关从隐藏位置到达该方格所需的最小象移动次数的反馈。 如果无法到达某个方格，则响应为 -1。 

每个查询都会为我们提供图中的距离，其中顶点是正方形，边连接位于同一对角线上的正方形。 主教沿着对角线移动，因此可达性由方块颜色决定：两个方块仅当它们共享行加列奇偶性时才可到达。 

我们的任务是使用最多 10 个查询来识别确切的隐藏方块，然后输出它。 

限制非常小：棋盘只有 64 种可能的状态。 这立即排除了任何渐近的担忧。 挑战纯粹是信息性的，这意味着我们必须设计有效划分搜索空间的查询，同时尊重主教的移动限制。 

一种简单的方法是通过询问到每个方格的距离是否为零来测试该方格。 这将需要最多 64 个查询，这违反了限制。 即使对行和列进行二分搜索在这里也没有意义，因为反馈不是基于坐标而是基于图形距离。 

一个微妙的问题是无法访问的查询返回 -1。 这将板分成两个不相连的颜色类别。 如果我们忽略这一点，我们可能会意外地将不可能的方块视为候选方块。 

## 方法

 关键的观察结果是，主教的距离度量编码了足够的结构，可以通过很少的精心选择的查询来唯一地确定其位置。 

在 8 x 8 的棋盘上，每个方格都可以根据颜色奇偶性进行分类。 从黑色方格开始的主教永远无法到达白色方格。 这意味着在对某些方格返回 -1 的单个查询后，正好有一半的棋盘被立即排除。 更重要的是，当一个正方形可达时，距离为 0、1 或 2。这是因为任何两个相同颜色的正方形要么位于同一对角线上（距离 1），要么可以通过一个中间对角线交点（距离 2）连接。 

所以每个查询不仅仅是一个距离探测，而是一个粗分类工具：

 结果 0 立即识别隐藏的方块。 

结果 1 告诉我们隐藏的正方形位于穿过所查询的正方形的两条对角线之一上。 

结果 2 告诉我们隐藏的方块颜色相同但不共享对角线。 

-1 的结果消除了所有相反颜色的方块。 

这允许每个查询显着缩小候选集的策略。 我们首先使用查询确定颜色奇偶性。 然后我们使用精心选择的对角线交点来定位正方形。 

一个简洁的构造是首先查询一个固定的方块，例如 A1。 这根据主教的颜色将棋盘分为可到达和不可到达的两半。 然后，我们查询另外两个选定的方格，使其对角线在少数候选方格中相交，逐渐缩小范围，直到只剩下一个方格。 因为每个查询都会将候选集大约减少 2 到 4 倍，所以在 10 个查询内我们可以确定地隔离答案。 

蛮力会尝试所有方格并查询每个方格，直到出现距离 0。 这是正确的，但超出了查询限制。 优化方法利用主教移动的结构来消除每个查询的大量方块。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(64) 查询最坏情况（最多 64） | O(1) | O(1) | 太慢（查询限制）|
 | 最佳 | O(10) 查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

我们设计的查询逐渐缩小可能的主教位置集。 

1. 查询一个固定的方格，例如A1，并读取响应。 

如果答案是 -1，我们就知道主教的颜色不同。 如果它是非负数，我们就知道它的颜色类别与 A1 匹配。 
2. 维护与颜色约束一致的所有方块的列表。 最初是 32 个方格（与 A1 颜色相同）或 32 个方格（颜色相反）。 
3.查询一个根据对角结构分割剩余候选的正方形，例如D4。 

如果响应为 0，我们就完成了。 如果为 1，则象位于穿过 D4 的两条对角线上之一。 如果它是 2，则它位于相同的颜色上，但不在这些对角线上。 
4. 将候选集与响应所隐含的约束相交。 

这显着减少了可能的方格数量，因为每条对角线最多覆盖 8 个方格。 
5. 仔细选择平分剩余对角线组的正方形，重复上述步骤。 一种有效的确定性策略是循环遍历覆盖独立对角线分区的固定探测方块序列，例如 A1、H1、A8、H8、D4、E5、D5、E4。 
6. 每次查询后，通过过滤与查询方格的预先计算距离与响应相匹配的所有方格来更新候选集。 
7. 当只剩下一名候选者时，将其输出为隐藏主教位置。 

关键思想是每个查询添加一个形式为“隐藏的正方形与主教图中的该顶点的距离为 K”的约束，并且几个这样的约束的交集唯一地确定了这个小图中的顶点。 

### 为什么它有效

 8 x 8 棋盘上的象运动图是高度结构化的，并且每个颜色分量内的直径最多为 2。 每个查询将候选集划分为最多三个有意义的类别：不可到达、相同对角线（距离 1）或相同颜色但不同对角线（距离 2）。 与少量此类分区相交可以唯一地标识单个顶点，因为一旦应用多个独立的对角线约束，图的对称性就会非常低。 保持的不变量是隐藏方块始终包含在当前候选集中，并且每个查询严格减小集合大小而不会消除真实位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

coords = [(c, r) for r in range(1, 9) for c in "ABCDEFGH"]

def dist(a, b):
    # bishop distance
    x1, y1 = a
    x2, y2 = b
    if (x1 + y1) % 2 != (x2 + y2) % 2:
        return -1
    if a == b:
        return 0
    if abs(x1 - x2) == abs(y1 - y2):
        return 1
    return 2

def query(cell):
    print(f"? {cell[0]}{cell[1]}", flush=True)
    return int(input().strip())

def main():
    candidates = coords[:]

    # fixed query sequence designed to split diagonals
    probes = [(1, 1), (8, 8), (1, 8), (8, 1), (4, 4), (5, 5), (4, 5), (5, 4)]

    for p in probes:
        if len(candidates) == 1:
            break
        res = query(p)
        new_candidates = []
        for c in candidates:
            if dist(p, c) == res:
                new_candidates.append(c)
        candidates = new_candidates

        if len(candidates) == 1:
            break

    ans = candidates[0]
    print(f"! {ans[0]}{ans[1]}", flush=True)

if __name__ == "__main__":
    main()
```该解决方案维护所有可能的方块的列表，并在每次交互响应后对其进行过滤。 距离函数准确地编码了主教的移动规则，从而可以对法官的答案进行一致的模拟。 每个查询通过仅保留那些与观察到的距离兼容的方块来细化候选集。 

选择探针序列以与不同的对角线族相交。 角点隔离了长对角线，而像 D4 和 E5 这样的中心点则横跨两个对角线方向，这很快就消除了歧义。 

必须注意每次查询后刷新输出，否则交互器将不会响应。

 ## 边缘情况

 像 A1 这样的角放置是最简单的场景，因为许多查询根据对角线对齐方式立即返回 0 或 1。 该算法仍然统一对待它，因为通过距离约束进行的过滤包括从一开始的真实位置，并且每个探测器都保留或确认它。 

像 H8 这样的长对角线上的正方形的行为类似，但对角探针的响应在对称性上有所不同。 即使早期查询不均匀地减少候选，约束的交集仍然唯一地保留 H8，因为没有其他方块同时匹配所有对角距离关系。 

像 D4 这样的中心正方形是信息最丰富的情况，因为它位于多个对角线上并产生更多的距离 1 响应。 过滤步骤正确地处理了这个问题，因为所有不满足对角线相等的候选都被一致地删除，只留下有效的交集，直到保留最终的正方形。
