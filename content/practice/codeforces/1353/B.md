 ## 解决方案
 ## 问题理解

 该问题给出了两个长度相等的数组，我们可以将其视为不同架子上的两组数字。 我们可以在货架之间交换号码，但最多只能交换号码`k`互换。 我们的目标是在执行这些交换后使第一个架子的总和尽可能大。 每个测试用例都提供数组的长度、允许的最大交换以及数组本身。 输出只是在交换约束下可实现的第一个数组的最大总和。 

限制很小：`n`最多可以是 30 并且`k`最多`n`，而测试用例的数量`t`最多为 200。这意味着我们无需担心扩展到数百万个操作，因此任何二次或对数组进行排序的解决方案都将足够高效。 每个数字也很小，最多为 30，因此不必担心整数溢出。 非明显的边缘情况包括最佳交换次数为零的情况，例如当第一个数组的所有元素已经大于第二个数组的所有元素时。 另一个棘手的情况是当`k`超过有利掉期的数量； 如果不小心进行不必要的交换，可能会减少总金额。 

## 方法

 最简单的方法是尝试所有可能的交换序列。 对于每一步，我们都会选择一对`(i, j)`并交换，递归地探索下一步行动，直到我们达到`k`交换或耗尽可能性。 这是正确的，因为它枚举了所有可能的结果，但是序列的数量增长得非常快 - 最多可达`(n^2)^k`- 即使对于`n = 30`和`k = 30`。 

关键的见解是注意到我们想要增加第一个数组的总和。 为了以最佳方式做到这一点，我们应该将其最小元素与第二个数组的最大元素交换，但前提是第二个数组中的元素较大。 交换其他任何东西都没有帮助。 按升序对第一个数组进行排序，按降序对第二个数组进行排序，使我们能够将最佳的交换候选配对。 然后我们迭代第一个`k`元素，仅当第二个数组中的元素严格大于第一个数组中的元素时才执行交换。 这种贪婪的方法保证我们执行的每次交换都会对第一个数组的总和产生正向贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((n^2)^k) | O((n^2)^k) | O(n) | 太慢了 |
 | 最优（贪婪排序）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和`k`，然后读取数组`a`和`b`。 
3. 排序`a`按升序排列来识别最小的元素。 
4. 排序`b`按降序排列来识别最大的元素。 
5. 迭代第一个`k`元素，考虑到`a[i]`和`b[i]`。 如果`b[i]`大于`a[i]`，交换它们。 否则，打破循环，因为没有进一步的交换可以提高总和。 
6. 计算修改后的数组的总和`a`。 
7. 输出每个测试用例的总和。 

为什么它有效：排序保证我们总是比较最小的可用元素`a`最大可用元素`b`，这正是最大化立即增加的交换`a`的总和。 停止交换的贪婪决定`b[i] <= a[i]`是有效的，因为没有后面的元素`b`由于降序排列，将比前面的元素大，并且后面的元素不会`a`由于升序排列，将小于之前的元素。 这保留了最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort(reverse=True)
        
        for i in range(min(k, n)):
            if b[i] > a[i]:
                a[i], b[i] = b[i], a[i]
            else:
                break
        
        print(sum(a))

solve()
```该代码首先对两个数组进行排序，以使贪婪交换变得简单。 循环最多运行`k`迭代，并且仅在严格提高总和的情况下才执行交换`a`。 使用`min(k, n)`确保我们不会访问超出范围的索引，这是一个容易被忽视的微妙点。 计算`sum(a)`交换后给出最终答案。

 ## 边缘情况

 对于掉期不增加总和的情况，例如：```
2 2
5 6
1 2
```算法排序`a`上升`[5,6]`和`b`下降`[2,1]`。 迭代时`i=0`,`b[0]=2`不大于`a[0]=5`，因此循环立即中断。 不会发生交换，总和仍为 11。这证实了该算法正确处理了交换会产生反作用的情况。
