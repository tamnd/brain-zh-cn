 ## 解决方案

 ## 问题理解

 我们从一个长度的数组开始`n`充满零。 我们反复“填充”数组`n`步骤。 在每一步中，我们都会查看当前的零填充段并选择一个段来放置下一个数字。 

选择段的规则很严格：我们总是采用最长的连续零块。 如果多个段具有相同的最大长度，我们将采用数组中最早出现的一个。 一旦一段`[l, r]`选择后，我们放置下一个整数`i`到该段的中间位置。 如果段长度是奇数，则中间是精确的。 如果是偶数，我们选择左中位置。 

放置后`i`，该位置不再为零，因此该段最多分为两个较小的零段。 这一直持续到所有职位都被填补为止。 

输出只是所有步骤之后的最终数组，但直接模拟它需要仔细处理不断演变的段。 

这些限制促使我们提高效率。 每个测试最多可以有`2 · 10^5`所有情况下的元素总数，因此任何重复扫描数组以查找最大段的方法都会降级为二次行为。 在每个步骤重新计算所有零段的简单模拟将需要扫描整个数组以查找每个插入，从而导致大约`O(n^2)`最坏情况下的操作，对于极限来说太慢了。 

当多个段共享相同长度时，会出现关键的边缘情况。 例如，在对称数组中放置几次后，我们可能在两侧都有两个大小相等的零段。 该规则迫使我们选择最左边的一个，因此任何没有稳定平局打破的无序结构都会失败。 

另一个微妙的情况是偶数长度的段。 指令说要采取左中间位置。 对于一个段`[l, r]`， 这意味着`(l + r - 1) // 2`。 一个常见的错误是使用`(l + r) // 2`，这会向右移动位置并打破未来拆分的整个结构。 

## 方法

 直接模拟维护数组并重复扫描最大的零段。 每一步都需要识别所有零块，选择最好的一个，然后将其分割。 由于每次插入都会花费线性时间，而我们这样做`n`次，总复杂度变为二次。 这太慢了`n`很大。 

该过程的结构提出了不同的观点。 每个零段的行为都是独立的，一旦选择，它就会确定地分成两个较小的段。 这正是优先级系统在时间间隔内的行为。 我们可以将每个段视为一个状态，其优先级由其长度（较大的第一个）定义，然后由其左端点（较小的第一个）定义。 

这自然会导致段的最大堆（优先级队列）。 每个段存储为`(-length, l, r)`以便堆始终提供正确的段来进行下一步处理。 每次弹出一个段时，我们都会计算它的中间位置，分配当前编号，然后将生成的左子段和右子段推回堆（如果它们非空）。 

这避免了完全扫描阵列。 每个段只处理一次，并且由于堆操作，每个操作花费对数时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（每一步扫描段）| O(n²) | O(n) | 太慢了 |
 | 最优（段的优先级队列）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 从包含完整段的优先级队列开始`[1, n]`。 我们首先按最长长度对线段进行优先级排序，对于连接，按较小的左端点进行优先级排序。 
2. 反复提取最佳片段`[l, r]`从队列中。 这保证了我们始终严格遵循问题的选择规则。 
3. 计算中点。 如果长度为奇数，则为`(l + r) // 2`。 如果偶的话，那就是`(l + r - 1) // 2`。 这符合偶数长度的“左中”要求。 
4. 指定当前步骤编号`i`到数组中的该位置。 
5. 将段拆分为`[l, mid - 1]`和`[mid + 1, r]`如果它们有效，则将它们推回到优先级队列中。 
6. 继续，直到所有`n`号码被放置。 

正确性来自于每个零段在队列中总是只出现一次，并且优先级顺序与问题中的选择规则相匹配。 由于每个放置仅影响其自己的段，因此未来的选择仅取决于队列准确维护的更新后的段结构。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        res = [0] * n

        # max heap using negative length
        heap = []
        heapq.heappush(heap, (-n, 1, n))

        for i in range(1, n + 1):
            neg_len, l, r = heapq.heappop(heap)

            length = -neg_len
            mid = (l + r) // 2
            if (r - l + 1) % 2 == 0:
                mid = (l + r - 1) // 2

            res[mid - 1] = i

            if l <= mid - 1:
                heapq.heappush(heap, (-(mid - l), l, mid - 1))
            if mid + 1 <= r:
                heapq.heappush(heap, (-(r - mid), mid + 1, r))

        print(*res)

if __name__ == "__main__":
    solve()
```堆存储活动的零段。 每次我们弹出最佳片段时，我们都会仔细计算其中间索引，遵守偶数长度规则。 分割的段会以正确的长度推回，以便将来的选择保持一致。 

一个常见的实现陷阱是忘记堆排序必须通过左索引打破联系。 在 Python 中，元组已经确保了这一点，因为`(length, l, r)`比较自然更喜欢较小的`l`当求反后长度相等时。 

另一个微妙之处是索引：该问题使用从 1 开始的索引，而 Python 数组是从 0 开始的，因此中点赋值必须减一。

 ## 边缘情况

 单元素数组测试不发生分裂的基本情况。 该算法立即分配唯一的位置，并且在一次操作后堆正确清空。 

偶数长度的片段是主要的微妙之处。 当一个片段像`[1, 4]`选择后，中点变为`2`而不是`3`。 这会改变所有后续的分割。 该算法明确适用`(l + r - 1) // 2`，这确保左半部分永远不会小于规则要求的大小。 

重复等长片段测试平局决胜。 当两个段具有相同的长度时，堆确保最左边的段首先被处理，因为元组第二个比较`l`。 这保留了整个过程中所需的确定性行为。
