 ## 解决方案
 ## 问题理解

 我们得到了一个按时间顺序排列的谷仓日志，奶牛在那里反复进出。 每行输入描述特定牛的一个事件：如果牛当前在外面，则该事件意味着它进入了；如果牛当前在外面，则该事件意味着它进入了。 如果它当前在里面，它就会离开。 谷仓一开始是空的，我们每时每刻都可以准确追踪里面有哪些奶牛。 

任务不是为了好奇而进行模拟，而是根据 Farmer John 的行为理论确定哪些奶牛可能偷走了丢失的食物。 如果在某个时刻满足两个条件，那么一头牛就被认为是可能的嫌疑人：首先，这头牛必须是当时谷仓内唯一的牛，其次，在那一刻之后，这头牛再也不能与另一头牛同时出现在谷仓内。 换句话说，一旦奶牛“单独存在”，此后它就不能再与任何人共用谷仓。 

输入大小最多可达 100,000 个事件。 这立即排除了任何重复扫描所有奶牛或每个事件从头开始重新计算全局状态的解决方案，因为 O(n²) 行为太慢。 具有基于散列的结构的线性或近线性传递是必要的。 

一个微妙的失败案例来自于只考虑一头牛独自一人的那一刻。 一头牛可能多次独自一人，但后来当其他人在场时又重新进入。 这将使其永久失效。 另一个极端情况是奶牛从来都不是单独的，即使它们干净利落地进入和离开，也必须将其排除在外。 

## 方法

 暴力解释将模拟整个过程，并且对于每头牛，尝试通过扫描其单独的每个时刻后的所有事件来验证状况。 对于每个候选“独奏时刻”，我们将检查日志的其余部分，以确保这头牛再也不会与另一头牛重叠。 这可能会导致检查 O(n) 个未来步骤以查找最多 O(n) 个事件，在最坏的情况下产生 O(n²) 行为，这对于 100,000 个事件来说太慢了。 

关键的观察是，我们实际上不需要为每个候选时刻重新扫描未来。 唯一重要的是一头牛是否违反了“单独出现后不得分享”的规则。 一旦我们维护了牛舍内当前的奶牛群，我们就可以在违规行为发生时立即检测到。 此外，我们还可以记录奶牛是否曾经单独呆在谷仓里。 

因此，我们没有进行回顾性检查，而是在网上维护两条信息：谷仓的当前占用情况，以及每头牛的一个标志，表明它是否曾经处于单独的状态。 我们还维护一个全局标志，指示一头牛在第一次独处后是否曾与另一头牛一起呆在里面，从而违反了规则。 这将问题转换为单通道模拟，每个事件都有恒定时间更新。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.维护一套`inside`代表目前在谷仓里的奶牛。 这允许对每个事件进行恒定时间的进入和退出跟踪。 
2. 维护一个布尔数组`ever_alone[x]`表明是否牛`x`当它是唯一的牛时，它曾经在谷仓里。 这直接抓住了候选资格所需的第一个条件。 
3. 维护一个布尔数组`invalid[x]`表明是否牛`x`曾在独自一人后共用谷仓而违反规定。 一旦确定，这头牛就永远不能成为候选人。 
4. 对事件进行一一处理。 对于每个涉及牛的事件`x`，切换其存在于`inside`。 如果存在，请将其删除； 否则插入它。 这使状态始终保持一致。 
5. 每次更新后，检查大小是否`inside`正好是一。 如果是这样，当前里面的那头牛有一段孤独的时刻，所以标记它`ever_alone`旗帜。 这是唯一可以在不事后诸葛亮的情况下可靠地检测到孤独的时刻。 
6. 每次更新后，对于当前里面的每头牛，如果大小为`inside`大于一，则任何已被标记的牛`ever_alone`现在正在目睹违规行为（如果再次出现）。 对于所有这样的奶牛，设置`invalid[x] = True`。 
7. 最后，每头满足的牛`ever_alone[x] == True`和`invalid[x] == False`是有效的候选人。 

### 为什么它有效

 关键的不变量是`invalid[x]`当牛时就变成真`x`在经历了孤独之后，参与违反规则的配置。 因为我们按照时间顺序处理事件，并且只有在严格观察时才标记孤独（大小）`inside`等于 1），不会出现误报。 在那一刻之后任何未来的共存都会立即被检测到并永久取消该奶牛的资格。 相反，如果一头牛从未失效并且至少有一个真正的孤独时刻，那么它就满足了构造所需的两个条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    inside = set()
    ever_alone = {}
    invalid = {}
    
    events = []
    
    for _ in range(n):
        x = int(input())
        events.append(x)
        if x not in ever_alone:
            ever_alone[x] = False
            invalid[x] = False

    for x in events:
        if x in inside:
            inside.remove(x)
        else:
            inside.add(x)

        if len(inside) == 1:
            y = next(iter(inside))
            ever_alone[y] = True

        if len(inside) > 1:
            for y in inside:
                if ever_alone.get(y, False):
                    invalid[y] = True

    ans = []
    for x in ever_alone:
        if ever_alone[x] and not invalid[x]:
            ans.append(x)

    ans.sort()
    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```实现的核心是`inside`set，它完全按照切换逻辑指示跟踪谷仓的当前状态。 每个事件都会在恒定的时间内翻转会员资格。 

这`ever_alone`仅当谷仓大小恰好为 1 时才会更新字典。 这保证了我们只记录真正的孤独，而不是短暂或模糊的状态。 

这`invalid`每当一头已经经历过孤独的奶牛出现在多奶牛配置中时，就会触发该标志。 这强制了“不再与他人在一起”的约束。 

最后，按这两个条件进行过滤可确保仅保留有效的候选者。

 ## 边缘情况

 一个关键的边缘情况是一头牛很早就开始独行，然后当另一头牛出现时才返回。 例如，奶牛 1 可能在时间 1 单独出现，但稍后当奶牛 2 进入时又重新进入。 在这种情况下，算法正确地标记`ever_alone[1] = True`在第一时刻，然后设定`invalid[1] = True`当重叠发生时。 尽管其早期有效，但最终过滤将其排除。 

另一个边缘情况是奶牛根本不会单独行动。 他们可能会多次进入和离开，但不会是唯一的居住者。 该算法永远不会设置`ever_alone[x]`对于他们来说，所以他们最终会被自动排除。 

最后一个微妙的情况是，整个原木中谷仓中只有一头牛。 在这种情况下，那头牛就变成了`ever_alone`立即并且永远不会失效，因此它被正确地包含为有效嫌疑对象。
