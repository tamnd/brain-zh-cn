 ## 解决方案
 ## 问题理解

 我们得到一行 N 个不同的键盘按键，每个按键都标有一个唯一的大写字母。 我们想要通过重复“按下”按键来构造一个字符串，但按键操作有点不寻常：按下内部按键会产生一对相邻的字符，即按键本身和其右侧的下一个按键。 第一个和最后一个键很特殊，因为它们也可以单独按下，只产生单个字符。 

每个键必须在最终构造的字符串中恰好出现 K 次。 目标不仅仅是构造任何有效的字符串，而是在这些规则下可以生成的所有字符串中按字典顺序最小的字符串。 

因此，我们正在使用的结构本质上是一个字符路径图，其中大多数操作都会产生重叠的两个字符贡献，并且我们必须选择一系列可产生精确字符频率的按下序列。 

关键的困难在于每个内部按键都会同时输入两个字符，这意味着选择会跨相邻的字母耦合。 这立即表明，对局部最小字符的天真贪婪选择将失败，因为每个决定都会影响结果多重集中的两个位置。 

这些约束意味着 N 最多为 26，因此字母表很小且固定。 K 可以高达 100,000，因此最终输出可能非常大，在最坏的情况下可达约 2N·K 个字符。 因此，任何解决方案在输出大小上都必须是线性的，并且不能涉及对构造的字符串进行重新计算或回溯。 

微妙的边缘情况来自边界字母。 第一个和最后一个角色的行为不同，因为它们可以单独生成。 如果忽略这种不对称性，就很容易构造出错误的贪婪解决方案，导致端点字符的生成过多或不足。 

例如，如果我们总是更喜欢内部按键，我们可能会避免使用边界单次按键，这可能导致无法满足第一个或最后一个字符的精确计数。 相反，总是尽早使用边界按压可能会导致必须配对的内部字符匮乏。 

## 方法

 暴力方法将模拟所有可能的按键序列，并维护每个字符已产生的次数的计数。 在每一步中，我们选择 N 个可能的操作之一：按中间键（产生两个字符）或按边界键（如果适用，产生一个字符）。 我们继续直到所有计数达到 K。 

这种方法是正确的，因为它明确地探索了所有有效的构造。 然而，状态的数量随着按下的次数呈指数增长，因为每个步骤分支最多为 N 个选择，并且我们需要大约 O(NK) 的总角色贡献。 即使对于小 K 来说，这很快也变得不可行。 

关键的观察是最终的字符串不是任意的； 这完全取决于我们选择每种类型的印刷机的次数。 每个内部压力机都贡献一个固定的相邻对，因此问题变成了折线图中相邻边的多重集的约束构造，以及可选的端点自循环。 

一旦我们将问题视为选择每个邻接边使用多少次，字典极简性就会建议采用从左到右的贪婪策略。 我们希望较早的字符尽早出现，这意味着我们应该更喜欢使用涉及较小索引的印刷机，但我们必须尊重全局可行性，以便剩余的字符仍然可以达到精确的计数。 

这将问题转化为在链上构建类似流的分配，其中每条边贡献两个顶点，端点贡献一个顶点。 由于 N 很小，我们可以通过维护剩余的所需计数来确定性地决定每个位置使用边界或内部贡献的次数。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(NK) | 太慢了|
 | 贪婪建设性分配 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们将每一次新闻重新解读为对角色的贡献。 令 cnt[i] 为字符 i 必须出现的次数，最初每次为 K。 

我们决定使用每个内部边缘 (i, i+1) 多少次，以及可能的端点自使用 0 和 N−1。 

1. 从最左边的字符开始，处理 0 到 N−1 的位置。 我们维护每个字符的剩余所需计数。 
2. 对于从 0 到 N−2 的每个内部位置 i，决定使用产生字符 S[i] 和 S[i+1] 的按压次数。 我们采取尽可能多的，但不超过任一端点字符的剩余需求。 这是因为每次使用都会同时降低这两种要求。 
3. 从 cnt[i] 和 cnt[i+1] 中减去所选数字。 这锁定了这两个字符之间将生成多少配对出现。 
4. 处理完所有内部边缘后，仅剩下端点缺陷，无法通过配对来满足。 这些必须通过边界处的单字符按键来处理。 具体来说，剩余的cnt[0]由单次按下S[0]填充，剩余的cnt[N-1]由S[N-1]填充。 
5. 最后，通过首先以字典顺序一致的顺序发出每个内部边缘贡献，然后发出边界发射来构造字符串，确保较早的字符在约束允许的情况下尽早出现。 

关键的想法是，每个内部配对都被贪婪地最大化，因为延迟它只会降低灵活性，并可能在以后迫使更糟糕的字典排序。 

### 为什么它有效

 在每个内部位置 i，同时减少对 S[i] 和 S[i+1] 的需求的唯一方法是使用它们对。 如果我们不尽早最大化这种使用，我们就有可能留下不匹配的需求，而这些需求必须在以后通过边界操作来满足，边界操作总是会产生字典顺序更差的位置，因为它们不会同时推进两个字符。 

不变量是，在处理位置 i 后，对 i+1 左侧所有字符的剩余需求已经以无法通过未来决策按字典顺序改进的方式固定。 由于每个决策仅影响局部相邻对并且永远不会重新打开较早的字符，因此贪婪的选择是全局一致的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    
    cnt = [k] * n
    used_edge = [0] * (n - 1)
    
    for i in range(n - 1):
        take = min(cnt[i], cnt[i + 1])
        used_edge[i] = take
        cnt[i] -= take
        cnt[i + 1] -= take
    
    res = []
    
    for i in range(n - 1):
        for _ in range(used_edge[i]):
            res.append(s[i] + s[i + 1])
    
    res.append(s[0] * cnt[0])
    res.append(s[-1] * cnt[-1])
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案首先将每个字符所需的频率初始化为 K。然后，我们通过在每个连续对之间获取尽可能多的配对贡献来贪婪地匹配相邻字符。 这直接对内部压力机进行编码。 

数组`used_edge`存储每个邻接被使用的次数，以便我们稍后可以按受控顺序重建字符串。 处理完所有对后，任何剩余的需求都必须属于端点，因为只有端点可以单独生产。 

最后，我们通过发出每个邻接贡献以及剩余的端点重复来构建输出。 

一个微妙的实现细节是我们不会交错边界和内部贡献。 正确性依赖于这样一个事实：内部贡献完全确定所有共享事件，并且一旦所有配对都固定，端点就是独立的。

 ## 边缘情况

 关键的边缘情况是 N = 1 时。该算法简化为仅处理端点，因此 cnt[0] 仍为 K，我们只需输出单个字符的 K 个副本。 完全跳过边缘上的贪婪循环，这避免了任何无效访问。 

另一种边缘情况是当 N = 2 时，所有需求都必须通过单个邻接来满足。 在本例中，我们恰好采用 K 个配对，从而产生长度为 2K 的字符串在两个字符之间交替。 端点逻辑永远不会激活，因为配对后两个 cnt 值都变为零。 

当链具有交替的大字符和小字符时，会发生更微妙的情况，其中贪婪配对完全饱和早期边缘，并且仅留下具有剩余需求的遥远端点。 该算法可以正确处理此问题，因为剩余计数始终仅在端点处累积，而端点是唯一能够在不违反邻接约束的情况下解决不匹配需求的地方。
