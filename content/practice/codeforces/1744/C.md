 ## 解决方案
 ## 问题理解

 交通灯遵循由字符串描述的循环模式。 如果字符串是`"rggry"`，然后在到达终点后又从头开始，产生无限序列。 

我们知道当前的颜色`c`，但我们不知道我们当前正在循环中查看该颜色的哪一次出现。 由于只有当灯变绿时我们才能穿越，因此我们必须考虑循环中颜色为`c`。 

对于每个这样的位置，我们可以问：直到下一个位置必须经过多少秒`'g'`出现？ 由于实际当前时刻可能对应于任何发生的情况`c`，我们需要所有这些职位中最差的等待时间。 最大等待时间就是答案。 

字符串的长度可以大到`2 · 10^5`综合所有测试用例。 这立即排除了昂贵的嵌套扫描。 一个`O(n²)`解决方案需要大约`4 · 10^10`最坏情况下的操作，远远超出了极限。 需要线性或近线性解决方案。 

交通信号灯的圆形特性是细微错误的主要来源。 靠近字符串末尾的位置可能需要等待环绕到开头后出现的绿灯。 

考虑：```
n = 3
c = r
s = "rrg"
```第一个`'r'`等待 2 秒为绿色，而第二个`'r'`等待 1 秒。 答案是 2。仅查看原始字符串内部右侧的解决方案会错误地错过其他示例中的环绕情况。 

另一个容易出现的错误是`c = 'g'`。```
n = 1
c = g
s = "g"
```我们已经处于绿灯状态，因此答案为 0。任何仍尝试查找未来绿灯的通用搜索逻辑都可能返回正值。 

一个更有趣的环绕示例是：```
n = 5
c = y
s = "yrrgy"
```最后一个`'y'`位于位置 4。下一个果岭不在剩余后缀内。 我们必须回到下一个循环的开始并到达位置 3 的果岭，需要 4 秒。 忽略循环结构会产生错误的答案。 

## 方法

 直接的暴力解决方案很容易描述。 对于包含目标颜色的每个位置`c`，在循环字符串中一次一步地重复前进，直到找到绿灯。 记录等待时间并取最大值。 

这是有效的，因为它明确地模拟了问题的定义。 问题是性能。 如果有`O(n)`的出现次数`c`，每个人都可以扫描`O(n)`在到达绿灯之前的位置，总复杂度变为`O(n²)`。 和`n = 2 · 10^5`，这太慢了。 

关键的观察是，每个位置只关心无限循环序列中最靠近其右侧的绿灯。 而不是单独搜索每个出现的`c`，我们可以对字符串进行预处理，以便更容易获得这些最近绿色距离。 

对于循环字符串来说，一个方便的技巧是重复。 如果我们将字符串与其自身连接起来，则原始循环中的每个环绕路径都将成为双倍字符串中的普通向右路径。 

例如：```
s      = yrrgy
s + s  = yrrgyyrrgy
```现在，第一个副本中的每个位置都可以安全地向右搜索下一个绿灯，而不必担心换行。 

我们从右向左扫描双倍字符串，同时记住包含的最新位置`'g'`。 对于每个角色，我们立即知道到下一个绿灯的距离。 每当字符等于`c`，我们用该距离更新答案。 

这将问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.如果`c`是`'g'`， 输出`0`立即，因为现在可以穿越。 
2. 创建双字符串`t = s + s`。 这会将圆周运动转化为普通的向右运动。 
3. 扫描`t`从右到左，同时保持迄今为止看到的最近的绿灯的位置。 
4. 每当当前字符为`'g'`，将存储的绿色位置更新为当前索引。 
5. 每当当前字符等于`c`，计算从该位置到存储的绿色位置的距离。 
6. 只有属于字符串第一个副本的位置才重要。 答案是所有这些位置之间的最大距离。 
7. 输出最大距离。 

### 为什么它有效

 将字符串加倍后，从原始循环中的位置到下一个绿灯的每条路径都完全显示在加倍字符串内，作为简单的向右段。 从右向左扫描时，存储的绿色位置始终是当前索引处或之后最近的绿灯。 因此，对于每次出现`c`，计算出的距离正是直到下一个绿灯的等待时间。 取所有出现的最大值`c`符合我们必须为当前可能最糟糕的情况做好准备的要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, c = input().split()
    n = int(n)
    s = input().strip()

    if c == 'g':
        print(0)
        continue

    doubled = s + s

    next_green = -1
    ans = 0

    for i in range(2 * n - 1, -1, -1):
        if doubled[i] == 'g':
            next_green = i

        if i < n and doubled[i] == c:
            ans = max(ans, next_green - i)

    print(ans)
```第一个特殊案例手柄`c = 'g'`。 由于当前灯已为绿灯，因此无需等待。 

然后该字符串被复制。 通常在循环结束时环绕的任何等待现在表示为在双倍字符串内正常向右移动。 

反向扫描保持`next_green`，当前索引右侧最近的绿色位置。 因为我们从右到左处理索引，所以该值在需要时始终可用。 

条件`i < n`很重要。 我们只需要原始字符串中的出现次数。 第二个副本的存在纯粹是为了使环绕距离易于计算。 

一个常见的差一错误是更新两个副本中出现的情况的答案。 这样做会计算与原始周期中的实际起始位置不对应的状态。

 ## 边缘情况

 考虑：```
1
1 g
g
```由于当前颜色已经是绿色，所以答案一定是`0`。 该算法会在任何扫描开始之前处理此问题。 如果没有这种特殊情况，解决方案可能会不必要地搜索未来的绿灯并产生非零值。 

考虑：```
1
5 y
yrrgy
```的发生`'y'`在原始字符串中，索引 4 的右侧没有绿灯。 加倍后，字符串变成`yrrgyyrrgy`，下一个绿色出现在索引 8 处。距离为`8 - 4 = 4`，计算正确。 这正是破坏忘记循环回绕的实现的情况。 

考虑：```
1
6 r
rrrrrg
```每个红色位置都等待最后的单个绿色。 距离是`5, 4, 3, 2, 1`。 最大值为`5`。 在反向扫描过程中，`next_green`保持固定在绿色位置，因此每个红色立即获得其正确的距离。 

考虑：```
1
3 r
rrg
```第一个红色等待 2 秒，第二个红色等待 1 秒。 该算法计算两个距离并保留最大值。 这验证了我们正在解决最坏情况的保证问题，而不是寻找事件中最短的等待时间。
