 ## 解决方案
 ## 问题理解

 我们在图上给出了一个有向过程，其中每个节点都有一个字符标签。 “旅行”是一系列精确的$l$访问过的节点。 我们可以从任何节点开始，每一步都沿着一条边移动到相邻节点。 当我们访问节点时，我们连接它们的字符，形成一个长度的字符串$l$。 在所有可能的长度步行中$l$，我们被要求找到$k$- 按字典顺序排列的最小字符串，其中如果两条路径在访问节点序列中的任何位置不同，则认为它们是不同的。 

关键的困难不是生成一个有效的步行，而是订购一组天文数字般庞大的步行而不枚举它们。 即使对于中等图表，行走次数也会呈指数增长$l$，因为允许重新访问并且图表可能包含循环。 约束条件$k \le 10^{18}$表明我们无法显式地枚举候选者，而必须依赖于有效地计算前缀。 

输入图可能是断开的，这意味着某些起点对于某些长度无效。 一种简单的方法是尝试从每个节点进行 DFS 并收集所有长度的字符串$l$，然后对它们进行排序。 这会立即失败，因为即使很小的分支因子也会产生指数数量的游走。 第二个天真的尝试是在状态上进行 DP$(node, remaining\_length)$，但这会导致$O(n \cdot l)$状态，当两者都太大时$n$和$l$可以是$2 \times 10^5$。 

当图高度连接时，会出现微妙的边缘情况，例如几个节点上的完整图。 即使是为了$n = 10$, 行走长度的数量$l = 200000$已经超出了任何没有截断的显式计数方法。 另一个问题是何时$k$超过了可能行走的总数，在这种情况下我们必须正确输出`"Impossible"`而不是部分构建。 

## 方法

 蛮力的想法很简单：枚举所有长度$l$，构建字符串并对它们进行排序。 这在概念上是正确的，因为一旦知道所有字符串，字典顺序就已明确定义。 失败点很明显：单个节点的行走次数大致增长如下$d^l$， 在哪里$d$是平均程度。 即使对于小$d = 2$，这在以下位置变得不可行$l = 2 \times 10^5$。 

一个更结构化的想法是将问题视为前缀计数问题。 如果我们可以计算，对于每个节点$u$和剩余长度$t$，有多少步长度$t$开始于$u$，那么我们可以贪婪地构造答案：在每一步，按照字符的字典顺序尝试邻居，从$k$直到我们找到包含所需步行的分支。 

核心障碍是计算这些计数。 所有状态的完整 DP 太大，但我们实际上不需要超出的精确计数$k$。 一旦某个值超过$k$，我们可以限制它。 这一观察改变了问题：我们只传播范围内的值，而不是精确计数$[0, k+1]$。 这种修剪极大地减少了有效计算，因为许多子问题一旦超过阈值就会崩溃。 

然后我们缓存状态结果$(u, t)$。 每个状态都会计算一次，并且其值有上限。 在构建过程中，我们反复查询这些上限计数来决定采用哪个传出边缘。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| 指数| 指数| 太慢了|
 | 具有 Memoization + Cap at k 的 DP |$O(\text{visited states} \cdot \deg)$|$O(\text{visited states})$| 已接受 |

 ## 算法演练

 我们从左到右贪婪地构造答案，保持当前节点和剩余长度。 

1.我们根据目的节点的特征对每个节点的邻接表进行预先排序。 这确保按顺序探索邻居会自动生成结果字符串的字典顺序。 
2.我们定义一个函数$count(u, t)$返回长度的步行数$t$从节点开始$u$，但截断于$k+1$。 这种截断是必要的，因为我们只需要区分一个分支是否小于$k$，等于$k$，或更大。 
3、功能$count(u, t)$是递归计算的。 如果$t = 1$，答案为 1，因为当前节点本身形成有效的长度为 1 的游走。 否则，我们对所有邻居求和$v$的$u$，添加$count(v, t-1)$，但我们立即将总和限制为$k+1$。 记忆化确保每个状态仅计算一次。 
4. 为了构造第 k 个字符串，我们通过按字符排序顺序考虑所有可能的起始节点来迭代第一个位置。 对于每个候选节点$u$，我们计算$count(u, l)$。 如果这个值至少是$k$，我们选择$u$作为开始。 否则，我们递减$k$并继续。 
5. 固定起始节点后，我们对每个后续位置重复相同的想法。 在当前节点$u$和剩余长度$t$，我们按字符顺序迭代邻居。 对于每个邻居$v$，我们计算$count(v, t-1)$。 如果$k$大于此计数，我们将其减去并跳过。 否则，我们移动到$v$并继续。 
6. 如果在任何步骤中不存在有效的转换，则构建失败并且我们输出`"Impossible"`。 

正确性取决于一个不变量：在每一步，$k$表示当前前缀的所有有效补全中的排名，并且$count(u, t)$通过前缀选择正确划分补全空间。 因为我们总是按字典顺序减去搜索空间的整个子树，所以剩下的$k$始终与所需的分支完全对应。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m, l, k = map(int, input().split())
    s = input().strip()

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    for i in range(n):
        g[i].sort(key=lambda x: s[x])

    from functools import lru_cache

    K = k

    @lru_cache(maxsize=None)
    def dp(u, rem):
        if rem == 1:
            return 1
        total = 0
        for v in g[u]:
            total += dp(v, rem - 1)
            if total > K:
                return K + 1
        return total

    start = -1
    cur_k = K

    for u in range(n):
        cnt = dp(u, l)
        if cnt >= cur_k:
            start = u
            break
        cur_k -= cnt

    if start == -1:
        print("Impossible")
        return

    res = [s[start]]
    u = start
    rem = l

    while rem > 1:
        rem -= 1
        found = False
        for v in g[u]:
            cnt = dp(v, rem)
            if cur_k > cnt:
                cur_k -= cnt
            else:
                res.append(s[v])
                u = v
                found = True
                break
        if not found:
            print("Impossible")
            return

    print("".join(res))

def main():
    T = int(input())
    for _ in range(T):
        solve()

if __name__ == "__main__":
    main()
```该解决方案依赖于一个记忆的 DP，该 DP 会对步行进行计数，但一旦计数超过就会停止$k$。 这可以防止密集图中的失控增长。 然后，贪婪构造消耗这些计数以直接导航到所需的词典顺序。 

一个微妙的实现细节是通过缓存$(u, rem)$。 如果没有记忆，贪婪下降期间的重复查询将多次重新计算相同的子问题并且变得太慢。 另一个重要的细节是，一旦金额超过，就提前终止$k$，它保持算术限制并避免溢出问题。 

## 工作示例

 ### 示例 1

 考虑一个简单的链$1 - 2 - 3$, 标签$a < b < c$， 和$l = 3$,$k = 2$。 

我们计算计数：

 | 状态| 计数 |
 | --- | --- |
 | dp(1,3) | dp(1,3) | 所有长度- 3 从 1 步行 |
 | dp(2,2) | dp(2,2) | 全长-2 步从 2 |
 | dp(3,1) | dp(3,1) | 1 |

 从节点 1 开始，字典顺序最小的起始点是固定的。 假设 dp(1,3) = 4 且 dp(2,3) = 2。如果$k = 3$，如果需要，我们会跳过节点 1 的贡献并相应地移动。 贪心选择确保我们总是减去整个完成块。 

这演示了前缀计数如何干净地划分搜索空间。 

### 示例 2

 中心 1 连接到 2、3、4 的星形图$l = 2$。 

| 开始| 长度 2 次行走的计数 |
 | --- | --- |
 | 1 | 3 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 1 |

 如果$k = 4$，我们跳过节点 1 的块（3 个步行），减去并移动到节点 2。这显示了起始节点上的字典顺序如何与子树大小相互作用。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(\text{states visited} \cdot \deg)$| 每个$(u, rem)$计算一次并迭代邻居，但上限为$k$防止爆炸|
 | 空间|$O(\text{states visited})$| Memo 表仅存储可达的 DP 状态 |

 有效状态数由截断控制$k+1$，这阻止了对指数游走空间的充分探索。 考虑到测试用例之间的总体约束，记忆结构在实践中仍处于限制范围内。 

## 边缘情况

 一个重要的情况是当$k$超过可能步行的总数。 例如，一个有两个节点的图$l = 5$可能只有几次交替行走。 在这种情况下，DP根数小于$k$，并且算法在尝试构建之前正确报告不可能性。 

另一个边缘情况是断开连接的图，其中只有某些组件允许长距离行走。 从无法产生长度的节点开始$l$walks 产生 dp(u, l) = 0，确保在初始选择阶段正确跳过它们。 

最后一种情况是具有许多循环的图，其中朴素 DP 将无限循环。 记忆化保证终止，因为每个状态$(u, rem)$被评估一次，递归深度的界限为$l$，在剪枝确保仅可达的同时，相关状态被扩展。
