 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例由一系列整数组成，代表排列成一行的玩具。 唯一允许的操作是交换两个元素（如果一个为偶数，另一个为奇数）。 禁止在两个偶数或两个赔率之间交换。 

任务是确定使用任意数量的此类允许交换可以达到的字典顺序最小序列。 由于交换可以任意重复，因此问题不在于执行固定的操作序列，而在于表征在奇偶校验限制下可以达到哪些排列，然后按字典顺序选择最佳排列。 

测试用例总输入大小的限制最多为 200000 个元素。 这立即排除了任何尝试模拟交换或对排列进行图形搜索的解决方案。 任何有效的解决方案必须基本上在每个测试用例的线性或接近线性时间内处理每个元素。 

当值按奇偶校验交错但已部分排序时，会出现微妙的失败情况。 例如，如果除了一个偶数之外所有数字都是奇数，则该单个偶数可以通过重复交换在所有奇数位置上自由移动，这意味着它可以插入到与赔率相关的任何位置。 只关注局部的天真贪婪交换方法很容易错过全局灵活性。 

当所有数字具有相同奇偶校验时，会出现另一种边缘情况。 在这种情况下，根本不可能进行交换，因此必须原样返回原始数组。 任何盲目排序的解决方案都会错误地修改这种情况。 

## 方法

 强力视角将数组视为状态空间，其中每个状态都是通过交换偶数和奇数元素可达到的排列。 人们可以想象在排列上运行 BFS 或 DFS，但在最坏的情况下，分支因子是二次的，状态数量是阶乘的。 即使表示状态空间超过非常小的 n，也是不可能的，因为每次交换仅更改两个位置，但奇偶校验约束仍然允许排列的大连通分量。 

关键的见解是奇偶性定义了两个独立的组：偶数和奇数。 交换总是在这些组之间交换元素，这意味着元素永远不会在内部混合奇偶校验类，但它们可以通过交叉交换在不同位置之间自由排列。 事实上，任何偶数最终都可以通过一系列交换移动到奇数占据的任何位置，反之亦然。 这意味着值的多集是完全可重新排列的，但值的奇偶性仅确定在重建的每个步骤中每个组“可用”的元素数量。 

为了构建按字典顺序排列的最小数组，我们模拟从左到右构建结果。 在每个位置，我们从剩余的偶数或剩余的赔率中选择最小的可用数字，以在可行性约束下可以合法占据该位置的为准。 由于奇偶校验交换允许组之间任意混合，因此唯一的限制是可用性，而不是位置锁定。 对两个奇偶组进行独立排序为我们提供了贪婪地从中抽取的最佳候选者。 

因此，解决方案简化为将数组分为偶数和奇数，对两个列表进行排序，然后贪婪地合并它们以形成字典顺序最小的序列。

 ## 算法演练

 我们使用奇偶分隔排序和贪婪选择来构造答案。

1. 将数组拆分为两个列表，一个包含所有偶数，另一个包含所有奇数。 这种分离反映了系统中唯一的结构性约束，因为互换仅在奇偶校验上定义。 
2. 按升序对偶数列表和奇数列表独立排序。 这可以随时从每个组中准备最小的可用候选人。 
3. 维护两个指针，一个用于偶数列表，一个用于奇数列表。 这些指针跟踪每组中最小的未使用元素。 
4. 从左到右迭代最终数组的每个位置。 在每一步中，决定是从偶数列表还是奇数列表中获取。 
5. 选择当前偶数候选者和奇数候选者中较小的一个，并将其附加到结果中。 将指针在相应的列表中前进。 这种贪婪的选择是安全的，因为每个奇偶组内的未来可用性仍然不受早期选择的影响。 
6. 继续，直到两个列表都用完，产生完整的排列。 

### 为什么它有效

 该系统允许跨奇偶校验边界进行完全重新排列，这意味着最终的排列相当于合并两个排序的多重集，其中每个多重集对应于奇偶校验。 由于允许所有交叉奇偶校验交换，因此没有元素被锁定到相对于其他奇偶校验组的固定位置。 唯一重要的结构是每个奇偶校验类中的全局排序。 贪婪合并会产生最小的字典顺序，因为在每个前缀处，选择最小的可用元素不会限制未来的选择，除了从其自己的排序池中删除该元素之外。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        evens = []
        odds = []
        
        for x in a:
            if x % 2 == 0:
                evens.append(x)
            else:
                odds.append(x)
        
        evens.sort()
        odds.sort()
        
        i = j = 0
        res = []
        
        while i < len(evens) and j < len(odds):
            if evens[i] < odds[j]:
                res.append(evens[i])
                i += 1
            else:
                res.append(odds[j])
                j += 1
        
        while i < len(evens):
            res.append(evens[i])
            i += 1
        
        while j < len(odds):
            res.append(odds[j])
            j += 1
        
        print(*res)

if __name__ == "__main__":
    solve()
```该解决方案首先按奇偶校验对数字进行分区，然后对每个组进行排序，以便始终可以访问剩余的最小候选者。 合并步骤是一种标准的两指针技术，类似于合并两个已排序的数组。 每个决策都会附加最小的可行下一个元素，确保词典编排最优性。 

一个常见的错误是假设交换只允许相邻的重新排列，这将导致局部排序尝试。 另一个问题是忘记了平价并不限制最终位置，只限制交换资格，这使得组内和组间的全面重新排序有效成为可能。

 ## 边缘情况

 当所有数字共享相同的奇偶校验时，奇数或偶数列表将变为空。 合并循环被跳过，并且原始排序逻辑不会干扰，因为没有发生跨组比较。 例如，输入`3 7 5 1`仅产生奇数列表，并且由于不可能进行交换，因此该算法有效地返回构造逻辑所需的原始排序。 

当只有一个元素奇偶校验不同时，例如`[1000000000, 2]`，拆分会在每个列表中生成一个元素，合并会选择较小的第一个元素。 由于两个元素可以通过奇偶校验交互进行交换，因此这反映了正确的可达排序。 

当值大量交替时，贪婪合并确保在每一步都选择最小的全局可用奇偶校验值，并且没有隐藏的约束阻止以后的重新排列，因为奇偶校验交换保留了跨组的完全可达性。
