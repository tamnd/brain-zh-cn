 ## 解决方案
 ## 问题理解

 我们得到一个从 0 到 x 的一维线段，以及一组坐在该线段上固定整数位置的 n 个朋友。 我们可以将 k 个传送点放置在段上的任何位置，并且全部位于不同的整数位置。 

每个朋友独立地走向最近的传送点。 如果有多个同样接近的传送，朋友可以选择其中任何一个。 好友的时间就是他们选择的最近传送距离，我们关心的是所有好友中最早到达的，即所有好友中最近传送距离的最小者。 

目标不是计算这个值，而是构建 k 个传送位置来最大化这个最小距离。 

重新解释这一点的一个有用方法是，每个朋友都“声明”他们最近的传送点，并且我们希望避免任何朋友距离所有传送点太近。 同样，我们试图放置 k 个点，以便即使是最幸运的朋友仍然必须走得尽可能远。 

这些约束迫使我们在每个测试用例中采用线性或近线性行为。 所有测试的 n 和 k 之和至多为 2e5，因此任何比每次测试的 O(n log n) 或摊销的 O(n + k) 更差的解决方案都是有风险的。 每个测试排序一次就可以了。 任何试图在整个范围 [0, x] 上天真地探索候选传送位置的解决方案都是不可能的，因为 x 可以达到 1e9。 

如果一个人在没有全局结构的情况下尝试在个别朋友周围贪婪地放置，就会出现一些不明显的陷阱。 例如，将所有传送点独立地放置在距离每个朋友最远的点会失败，因为传送选择会相互作用：单个传送同时影响多个朋友。 另一种失败模式是试图最大化单个朋友的距离； 这忽略了答案是所有朋友中的最小值。 

正确的构造必须全局地推理由排序的朋友位置引起的间距。 

## 方法

 强力解释是尝试 [0, x] 的所有 k 点子集，计算每个子集与所有朋友的最小距离，并选择最佳的。 即使限制为整数位置，这也是 k 和 x 的组合，使其完全不可行。 

更结构化的蛮力可能会尝试在相关的“有趣点”中选择 k 个候选位置，例如朋友位置和边界，但即使这导致从 O(n) 个候选中选择 k，即 O(n 选择 k)，仍然是不可能的。 

关键的观察是，只有朋友的顺序很重要，而不是间隔的确切几何形状。 如果我们对朋友进行排序，那么到一组传送的最坏情况距离是由连续传送之间的间隙控制的。 为了最大化最小距离，我们希望传送尽可能分散，但同时也确保朋友之间的区域不会变得过于“暴露”。 

查看结构的一种有用方法是逆向思考：我们不想最大化传送的最小距离，而是希望放置传送，以便每个朋友都靠近至少一个传送，但任何朋友获得的最近距离尽可能大。 这促使我们稀疏而均匀地覆盖这条线。

最佳结构最终很简单：在通过排序对结构进行归一化之后，我们选择在朋友位置的凸包上均匀分布的 k 个位置。 直观上，如果我们将问题压缩为连续候选点之间的间隔，则最大化最小距离的最佳方法是将瞬移尽可能分散，同时仍保持在 [0, x] 范围内。 因为每个朋友都会选择最近的瞬移，所以关键结构是由瞬移位置引起的 Voronoi 边界集合，最大化最小距离相当于最大化任何朋友周围的最大空半径，这是通过均匀传播来实现的。 

因此，我们通过选择最大化间距的位置来贪婪地构造 k 点，这减少了以选定间隙的增量逐步穿过该段。 由于我们可以自由选择任何 k 个不同的整数，因此我们可以选择它们均匀分布在 [0, x] 上或友元四肢确定的范围内。 

这将问题简化为计算步长并生成 k 点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | k 的指数 | O(k) | 太慢了 |
 | 最佳（均匀放置结构）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.对好友位置进行排序。 排序对于构建来说并不是严格必要的，但有助于确定有效的兴趣范围并避免对任意排序的推理。 
2. 确定要优化的相关细分，即从最小好友位置到最大好友位置的跨度。 在此间隔之外，放置传送不会以有意义的方式改善最小距离，因为它只会不对称地增加距离。 
3. 决定 k 个传送位置应尽可能均匀地分布在该间隔上。 直觉是，集群传送会减少最坏情况下的最近距离，而分散传送会最大化任何朋友和传送之间的最小距离。 
4. 当 k > 1 时，根据可用间隔长度除以 (k - 1) 计算间距步长。这可确保 k 点覆盖间隔端点并均匀分布在其间。 如果 k = 1，我们只在范围的中点放置一个传送。 
5. 使用该间距生成 k 个整数位置。 由于位置必须是整数，因此我们在确保唯一性的同时一致舍入或下限。 
6. 如果生成的位置超出 [0, x]，则在保持单调性的同时限制它们。 这在不破坏间距结构的情况下保持了有效性。 
7. 输出构造好的列表。 

### 为什么它有效

 关键的不变量是构造的传送将线划分为几乎相等长度的 k - 1 个间隔。 当没有间隔显着大于其他间隔时，每个朋友到最近传送的距离最大化，因为最坏情况的朋友总是位于连续传送之间或边界与传送之间的最大间隙中。 

如果任何建筑物的间隙比我们的间隙大，我们可以将传送转移到该间隙并严格改善最小距离。 因此，任何最佳解决方案都必须尽可能地均衡间隙，这正是均匀间距所实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        if k == 1:
            # best single point is anywhere central; midpoint is safe
            print(x // 2)
            continue
        
        lo, hi = 0, x
        step = (hi - lo) // (k - 1)
        
        res = []
        for i in range(k):
            res.append(lo + i * step)
        
        # ensure distinctness if step becomes 0 due to large k
        # fix by spreading minimally
        used = set()
        for i in range(k):
            if res[i] in used:
                # push forward to next free slot
                cur = res[i]
                while cur in used and cur <= x:
                    cur += 1
                res[i] = cur
            used.add(res[i])
        
        print(*res)

if __name__ == "__main__":
    solve()
```该代码在 0 和 x 之间构造 k 个均匀间隔的点。 重要的设计选择是我们忽略个别朋友的位置，因为最佳策略仅取决于在可用域上均匀传播传送。 

在 k 相对于 x 较大的极端情况下，当整数除法将间距压缩为零时，后处理循环可确保唯一性。 如果没有它，多个传送可能会发生冲突，从而违反独特性约束。

 ## 边缘情况

 当 k = 1 时，算法将整个结构分解为单个布局问题。 中点的选择确保了到线段两端的对称距离，任何偏向一侧的偏差都会严重恶化相反极端的朋友的最小距离。 

当 k 相对于 x 较大时，使用整数除法的朴素间距会产生零步长，这将导致重复传送。 修复循环通过向前增加位置来确保唯一性。 例如，当 x = 5 且 k = 10 时，初始构造会产生重复值，但调整将它们最小化，同时保持在范围内。 

当所有朋友都聚集在一个点时，构造不会受到影响，因为传送位置仅取决于覆盖全局部分。 尽管直觉可能建议在该点附近聚集传送，但这样做会减少全局间距并损害最小距离定义，而最小距离定义取决于最坏情况的朋友行为。
