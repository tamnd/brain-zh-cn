 ## 解决方案
 ## 问题理解

 我们得到一个仅由左括号和右括号组成的固定字符串。 对于每个查询，我们都会收到该字符串的一个片段，保证在结构意义上表现良好，并且我们必须根据更强的正确性概念来计算该片段内有多少子字符串也是“良好”的。 

这里的正确性概念不是标准的平衡括号定义。 相反，如果我们可以重复删除单个点或连续的点，则字符串被认为是有效的。`"()"`配对，直到什么都没有留下。 由于此版本中不存在点，因此我们正在有效地使用一种结构，其中有效子字符串的行为类似于嵌套或连接的有效括号块，但具有比经典堆栈平衡稍微更宽松的折叠规则。 

最重要的是，一个“简单”的有效子字符串必须满足额外的边界条件：它必须是非空的，并且不能以点开头或结尾。 在此版本中，这些条件转化为排除退化情况，但重要的结构结果是简单的有效子字符串与较大查询段内“独立”的格式良好的平衡段完全对应。 

每个查询都会给出一个已保证是简单有效结构的子字符串。 我们必须计算其中有多少子子串本身就是简单有效的结构。 

约束很大，最多有 300,000 个字符和 300,000 个查询。 这立即排除了任何检查每个查询的所有子字符串的解决方案。 二次或偶数$O(n \log n)$每个查询方法都会失败。 我们需要预处理，将每个查询减少到接近恒定或对数的工作。 

一个微妙的边缘情况是，并非每个平衡段在查询内都是独立的。 例如，重叠的有效子串必须单独计数。 在像这样的字符串中`"()()"`， 两个都`"()"`块和完整的`"()()"`是有效的，并且仅计算最大块的幼稚计数策略会错过内部结构。 

另一个陷阱是假设经典的前缀和平衡就足够了。 虽然平衡有助于识别有效结构，但它不会直接计算另一个有效段内有效子段的数量。 我们需要一种方法来聚合嵌套有效区间的贡献。 

## 方法

 暴力破解的想法很简单：对于每个查询段，枚举所有对$(i, j)$，检查是否$s[i..j]$是一个有效的平衡结构，并另外验证简单性。 基于堆栈的检查进行验证$O(n)$，所以每个查询变成$O(n^2)$在最坏的情况下，当字符串长度和查询数量都很大时，这远远超出了可行的限制。 

关键的观察结果是，有效子串的行为类似于括号序列的结构分解中的匹配对。 每个位置都可以在规范分解中与唯一的匹配括号配对，形成嵌套段的树状结构。 一旦知道了该结构，每个有效子串都对应于该分解中的一个节点或一起形成连续有效块的相邻兄弟节点的联合。 

这将问题转化为计算在给定间隔内存在多少“有效节点”或“有效节点串联”。 我们不是重新计算每个子字符串的有效性，而是预先计算匹配结构并构建一个允许我们在有效组件之间跳转的表示。 

实现此目的的标准方法是使用堆栈计算匹配的括号，然后构建一个数组，其中每个位置都知道其匹配的伙伴。 由此，我们得出原始有效段的父子结构。 该问题简化为计算有多少段完全位于每个查询范围内，这可以使用范围计数技术（例如芬威克树或离线扫描段端点）来处理。 

暴力破解会失败，因为它会重复重新计算有效性，而最佳解决方案将所有有效子字符串压缩为一组结构化的规范区间，并通过范围查询对它们进行计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$跨查询的最坏情况|$O(1)$| 太慢了 |
 | 最佳 |$O((n+q)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们通过将其简化为计算由匹配的括号段表示的有效间隔来解决该问题。 

1. 首先使用堆栈计算每个位置的匹配括号。 每个右括号都与最近的未匹配的左括号配对。 这给出了一个函数`match[i]`。 
2. 使用匹配数组，构建原始有效段的结构。 每次我们找到一对`(l, r)`在哪里`r = match[l]`，我们对待`[l, r]`作为基本有效块。 
3. 我们观察到任何简单的有效子串要么是这些原始块之一，要么是完美对齐而没有间隙的连续块的串联。 
4. 我们将结构压缩为沿着字符串的一系列原子有效段。 每个段都有一个开始和结束索引，如果连续的段形成有效的串联，则可以合并它们。 
5. 我们创建一个线段端点数组，并在右端点上使用 Fenwick 树（或线段树）。 我们按左端点对段进行排序，以便我们可以在左边界移动时激活段。 
6. 查询`[l, r]`，我们计算有多少段满足`l ≤ start`和`end ≤ r`。 这是一个标准的二维计数问题。 
7. 我们通过按左端点对段和查询进行排序并从右向左扫描来离线回答所有查询，从而更新芬威克树。 

### 为什么它有效

 每个简单的有效子串都对应于原始匹配块的一次规范分解。 堆栈匹配保证了配对的唯一性，因此不会遗漏或重复计算有效的子字符串。 通过在这种分解上将子字符串转换为间隔，每个查询都成为间隔端点上的优势计数问题，Fenwick 结构可以准确处理该问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    match = [-1] * n
    stack = []

    for i, c in enumerate(s):
        if c == '(':
            stack.append(i)
        else:
            if stack:
                j = stack.pop()
                match[i] = j
                match[j] = i

    segments = []
    for i in range(n):
        if s[i] == '(' and match[i] != -1:
            l = i
            r = match[i]
            if l < r:
                segments.append((l, r))

    segments.sort()

    queries = []
    for idx in range(q):
        _, l, r = map(int, input().split())
        queries.append((l - 1, r - 1, idx))

    queries.sort(reverse=True)

    bit = Fenwick(n)
    ans = [0] * q

    ptr = len(segments) - 1

    for l, r, qi in queries:
        while ptr >= 0 and segments[ptr][0] >= l:
            bit.add(segments[ptr][1] + 1, 1)
            ptr -= 1

        total = bit.sum(r + 1)
        ans[qi] = total

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```堆栈部分构建精确的括号配对，以便识别每个最大有效基元区间。 分割步骤提取那些代表原子有效结构的间隔。 

芬威克树存储段端点的计数。 在处理查询时，我们确保只有在查询范围内开始的段是活动的，然后计算在查询右边界之前有多少个结束段。 这直接计算完全包含多少个有效段。 

按左端点排序至关重要，因为它确保每个段在与具有较小左边界的查询相关时仅插入一次。

 ## 边缘情况

 关键的边缘情况是完全嵌套的结构，例如`"(((())))"`。 该算法必须确保每个嵌套层都作为单独的有效段起作用。 堆栈匹配创建间隔`(1,8)`,`(2,7)`,`(3,6)`,`(4,5)`，并且全部插入。 覆盖整个范围的查询对所有四个段进行计数，匹配嵌套有效子字符串的预期组合结构。 

另一个重要的情况是交替括号`"()()()()"`。 这里不存在嵌套，只有不相交的基元块。 段提取产生四个间隔，并且在整个范围内的查询正确地计算仍然形成有效子字符串的各个块及其串联。 

微妙的边界情况是等于单个基元块的查询。 由于我们只插入有效的`(l,r)`对，精确匹配一个块的查询返回精确的一个贡献，避免过度计算不是有效子串的部分重叠。
