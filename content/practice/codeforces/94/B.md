 ## 解决方案
 ## 问题理解

 我们正好有五个人。 有些人彼此认识，输入列出了所有这样的熟人关系。 

任务是确定是否存在：

 1. 三个人，每一对都互相认识。 
2. 三人互不相识。 

这自然是一个图问题。 每个人都是一个顶点，熟人关系是一条无向边。 我们正在寻找：

 1. 图中的三角形。 
2. 补图中的三角形。 

如果至少存在其中一个结构，我们将打印`"WIN"`。 否则我们打印`"FAIL"`。 

限制非常小。 只有五个顶点，最多十条边，因为五个顶点上的无向图有`5 * 4 / 2 = 10`可能的对。 即使对所有三元组进行强力搜索也很小。 三元组的总数仅为`C(5, 3) = 10`。 

主要的困难不是表现，而是正确地执行条件。 

一个容易犯的错误是只检查友谊三角形而忘记了独立的三元组。 考虑这个输入：```
2
1 2
3 4
```正确答案是：```
WIN
```人们`1, 3, 5`两两互不相识。 仅搜索友谊三角形的解决方案将错误地打印`"FAIL"`。 

另一个常见的错误是按照指示处理图表。 该关系是对称的，因此如果`(1, 3)`出现，那么`3`也知道`1`。 粗心的邻接结构可能会忘记这一点并错过有效的三元组。 

例如：```
3
1 2
2 3
1 3
```正确答案是：```
WIN
```这是一个三角友谊。 如果实现仅存储每条边的一个方向，则检查可能会失败。 

一个更微妙的边缘情况是空图：```
0
```正确答案是：```
WIN
```任意三个人组成三对陌生人。 假设至少存在一条边的解决方案在这里可能表现不正确。 

## 方法

 最直接的解决办法就是对所有三人进行暴力破解。 

只有五个人，所以我们可以枚举每个组合`(a, b, c)`在哪里`a < b < c`。 对于每个三元组，我们检查两个条件：

 1. 所有三对都是边。 
2. 三对都不是边。 

如果任何一个条件对于任何三元组为真，我们立即返回`"WIN"``。 

这种蛮力方法已经足够快了。 只有十个三元组，每次检查检查三对，因此总工作量是恒定的。 

这种方法如此自然地起作用的原因是我们关心的属性完全是三元组的局部属性。 我们永远不需要更大的图结构、最短路径、连接的组件或任何全局的东西。 

更简单的暴力破解版本将显式构建所有人员子集，然后测试大小为 3 的所有子集。 这仍然有效，因为图很小，但它引入了不必要的开销。 

关键的观察结果是，问题精确地简化为检查每个三元组一次。 由于图大小固定为 5，因此这成为一个紧凑的实现问题而不是优化问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 通用子集暴力破解 | O(2^5) | O(2^5) | O(1) | O(1) | 已接受 |
 | 三重枚举 | O(C(5,3)) | O(C(5,3)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 创建一个`5 x 5`邻接矩阵初始化为`False`。 

该矩阵让我们检查两个人在恒定时间内是否彼此认识。 
2. 阅读每一对熟人`(a, b)`。 

将索引转换为从零开始的索引并设置两者`adj[a][b]`和`adj[b][a]`到`True`。 

该图是无向的，因此必须存储两个方向。 
3. 枚举每个不同的人的三重`(i, j, k)`和`i < j < k`。 

使用有序三元组可以避免重复，并保证每组三人都被检查一次。 
4. 对于当前的三元组，计算所有三对是否都连接。 

所需的边是：`i-j`,`i-k`， 和`j-k`。 
5. 计算是否所有三对都不存在。 

这意味着这三个边都不存在。 
6. 如果任一条件为真，则打印`"WIN"`并停止。 

我们只需要一个有效的三元组。 
7. 如果检查了所有三元组且没有一个满足条件，则打印`"FAIL"`。 

### 为什么它有效

 每个有效答案仅取决于三人一组。 该算法对每个可能的三元组只检查一次。 对于每个三元组，它检查问题中的两个定义：

 1. 两两相识。 
2. 两两不相识。 

如果这样的三元组存在于图中的任何位置，则枚举最终将到达它并返回`"WIN"`。 如果算法完成时没有找到一个，则不存在合格的三元组，因此`"FAIL"`是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# solution

def solve():
    m = int(input())

    adj = [[False] * 5 for _ in range(5)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        adj[a][b] = True
        adj[b][a] = True

    for i in range(5):
        for j in range(i + 1, 5):
            for k in range(j + 1, 5):

                ab = adj[i][j]
                ac = adj[i][k]
                bc = adj[j][k]

                all_friends = ab and ac and bc
                all_strangers = (not ab) and (not ac) and (not bc)

                if all_friends or all_strangers:
                    print("WIN")
                    return

    print("FAIL")

solve()
```邻接矩阵是这里最简单的表示，因为图很小，而且我们经常问“边是否存在”形式的问题？`(u, v)`存在吗？”。每次查找都变成单个数组访问。

 循环使用`i < j < k`所以每个三元组只出现一次。 这样可以避免重复工作，并防止同一个人出现多次的意外情况。 

变量`ab`,`ac`， 和`bc`使逻辑更易于阅读并减少重复的索引操作。 由于每个三元组只有三个相关边，因此明确命名它们可以使条件清晰。 

该实现分别检查两个必需的模式：```
all_friends = ab and ac and bc
all_strangers = (not ab) and (not ac) and (not bc)
```将这些条件混合到一个表达式中通常会产生逻辑错误，尤其是否定时。 

程序在找到有效的三元组后立即退出，因为一个见证人就足以确定答案。

 ## 边缘情况

 考虑空图：```
0
```邻接矩阵仅包含`False`价值观。 第一个三重`(1,2,3)`根本没有边缘。 该算法计算：```
all_friends = False
all_strangers = True
```所以它正确打印：```
WIN
```这证实了该算法可以处理没有边的图。 

现在考虑五循环反例：```
5
1 2
2 3
3 4
4 5
5 1
```每个三元组要么恰好包含一条边，要么恰好包含两条边。 没有一个包含零个边或三个边。 该算法系统地检查所有十个三元组，但从未找到有效的三元组，因此它打印：```
FAIL
```这是关键正确性案例，因为它证明该陈述对于五个人来说并不普遍正确。 

最后，考虑一个纯粹的友谊三角：```
3
1 2
2 3
1 3
```当算法达到三倍时`(1,2,3)`，所有三个必需的边都存在：```
1-2 = True
1-3 = True
2-3 = True
```所以`all_friends`变成`True`，算法立即打印：```
WIN
```这证实了该图被视为无向并且友谊三角形被正确检测到。
