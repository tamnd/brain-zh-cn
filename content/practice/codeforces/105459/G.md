 ## 解决方案
 ## 问题理解

 我们给出一个无向图，其中顶点代表参与者，边代表相互熟人。 其目标是“激活”在线会议中的所有参与者，该会议从一位创建者开始，然后通过熟人边缘的邀请不断扩大。 

该流程具有由角色施加的方向性约束。 一名参与者最初创建会议。 之后，只有已经加入会议的人才能邀请他们认识的其他人。 然而，一部分参与者被标记为忙碌。 繁忙的参与者可以受邀加入，但不能自己邀请任何人，也不能成为初始创建者。 

因此任务不仅仅是检查连接性。 我们必须确定是否存在尊重这些规则并覆盖所有节点的邀请序列，如果存在，则显式构造这样的序列。 每个参与者只能被邀请一次，输出是一系列“邀请步骤”，其中每个步骤都由当前成员邀请一组尚未添加的熟人组成。 

从图的角度来看，这是在问我们是否可以从某个不繁忙的根开始定位一个生成过程，以便每个节点都可以通过定向扩展来到达，并附加一些限制，即某些节点在此构造中是“仅叶子”并且不能充当扩展中心。 

约束很大，最多有 200,000 个节点和 500,000 条边。 任何解决方案都必须在近线性时间内运行，因此大致为 O(n + m)。 任何涉及重复图重新计算、流程或每个节点全局重新检查的事情都会太慢。 

当所有非繁忙节点在结构上“阻止”到达其他节点而不依赖繁忙节点作为分支点时，就会出现微妙的故障情况。 例如，如果每个非繁忙节点都是叶子，因为删除繁忙节点会将剩余图断开为隔离的组件，但每个组件都需要一个繁忙节点来桥接，则即使图已连接，构造也会失败。 

另一个边缘情况是当 k = n 时，这意味着所有节点都忙。 在这种情况下，没有人可以开始会议，所以答案立即是不可能的。 

最后，如果我们选择一个繁忙的起始节点，即使存在连接，该解决方案也会无效，因为根必须能够发起邀请。 

## 方法

 暴力解释将尝试起始节点的所有可能选择，然后模拟邀请过程。 对于每次开始，我们都会尝试贪婪地扩展会议，可能使用 BFS 或 DFS，同时跟踪是否有任何步骤需要繁忙的节点充当邀请者。 在最坏的情况下，对于每次开始，我们都会遍历所有边，给出 O(n(n + m))，这对于输入大小来说太慢了。 

关键的结构观察是该过程本质上是生成树构建，但对内部节点有约束。 最终的邀请计划对应于选择一个有根生成树，其中除了繁忙的根之外的每个节点都不能在该树中拥有子节点。 这意味着繁忙的节点必须在有根跨越结构中显示为叶子。 

这将问题重新定义为选择一个有效的根，这样每个繁忙的节点就不会被迫成为内部分支点。 同样，我们需要一个根，以便所有繁忙的节点都可以成为以该节点为根的生成树中的叶子。 

一个关键的简化来自于反转视角：我们确保只通过非繁忙节点作为分支点进行扩展，而不是向前构建树。 如果繁忙节点成为任何以 r 为根的生成树中的内部节点，则 r 无效。

这引出了一个建设性的想法：我们尝试将进程扎根于非繁忙节点并构建 BFS/DFS 生成树，但我们强制繁忙节点永远不会成为父节点。 这意味着每当我们从一个节点遍历时，如果它很忙而不是根，我们就无法从它扩展。 因此，必须对树进行排列，使得所有繁忙节点仅作为子节点到达。 

这个条件相当于确保在生成树中，除了可能的根邻接约束之外，每个繁忙节点的度数为1，但由于根不能繁忙，因此所有繁忙节点都必须是叶子。 

我们可以通过构建以每个候选非繁忙节点为根的生成树并检查可行性来强制执行此操作，但天真地这样做太慢了。 相反，我们观察到，如果存在解决方案，我们可以选择任何不繁忙的节点作为根，该节点不会由于繁忙节点引起的铰接结构而“被迫”成为叶子。 更直接的建设性方法是从每个非繁忙节点尝试 BFS，但在繁忙节点停止扩展，并验证覆盖范围。 然而，这仍然存在 O(n(n + m)) 的风险。 

标准优化是修复单个根候选：任何可以到达 BFS 中所有其他节点的非繁忙节点，其中允许遍历所有节点，但只有非繁忙节点用作扩展器。 如果这个 BFS 从非繁忙节点开始访问所有节点，那么我们可以直接从父指针构建生成树，并通过对每个父节点的子节点进行分组来输出邀请组。 

如果不存在这样的根，那么答案是不可能的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 通过模拟尝试所有根 | O(n(n + m)) | O(n(n + m)) | O(n + m) | 太慢了 |
 | 来自有效非繁忙根的单个 BFS | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构建图的邻接表。 这代表原则上谁可以直接邀请谁。 
2. 识别所有非繁忙节点。 这些是初始会议创建者的唯一可能的候选人。 
3. 选择一个不繁忙的节点作为起始根。 如果不存在这样的节点，则立即输出不可能。 原因是根必须能够发起邀请，并且明确禁止繁忙节点这样做。 
4. 从根运行 BFS 或 DFS，在所有可到达的节点上构建生成树。 在遍历过程中，记录每个节点的父节点，并确保每个节点只被访问一次。 
5. 遍历结束后，检查是否到达所有节点。 如果不是，则该图不能从任何有效的根结构完全覆盖，因此不存在有效的邀请计划。 
6. 从父数组构建邀请步骤。 对于每个节点，收集生成树中的子节点。 
7. 按照节点出现在其他节点之前的规则一致的任意顺序输出步骤。 一种自然的方式是按 BFS 顺序输出节点：每个节点立即邀请其所有子节点。 

关键思想是 BFS 树直接编码有效的邀请序列，因为树中的每条边都对应于从已参加会议的参与者到尚未邀请的熟人的合法邀请。 

### 为什么它有效

 BFS 生成树确保每个参与者都通过确切的一个父级到达，该父级恰好对应于一个邀请源。 由于我们不允许为一个节点分配多个父节点，因此不会多次邀请参与者。 因为我们从不忙的根开始，所以每次扩展都来自被允许邀请的人。 繁忙的节点可能会出现在树中，但它们仅被分配为子节点，而不会被分配为负责进一步扩展的节点，因此它们不能违反约束。 正确性归结为这样一个事实：任何有效的进程都会定义一棵生成树，并且只要所有节点都可以从有效的根到达，BFS 就会构造一棵这样的树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    n, m, k = map(int, input().split())
    busy = set()
    if k > 0:
        busy = set(map(int, input().split()))
    else:
        _ = input().strip()

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    start = -1
    for i in range(1, n + 1):
        if i not in busy:
            start = i
            break

    if start == -1:
        print("No")
        return

    parent = [-1] * (n + 1)
    vis = [False] * (n + 1)
    q = deque([start])
    vis[start] = True
    parent[start] = 0

    order = []
    children = [[] for _ in range(n + 1)]

    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            if not vis[v]:
                vis[v] = True
                parent[v] = u
                children[u].append(v)
                q.append(v)

    if not all(vis[i] for i in range(1, n + 1)):
        print("No")
        return

    print("Yes")
    print(len(order))

    for u in order:
        if u == start:
            print(u, len(children[u]), *children[u])
        else:
            print(u, len(children[u]), *children[u])

if __name__ == "__main__":
    solve()
```该代码首先读取图表并存储繁忙集。 然后它选择一个不忙的起始节点。 如果不存在，则立即失败。 

BFS建立父关系的同时，构造有根树结构`children`。 这很重要，因为输出格式需要将每个参与者在一个步骤中发出的所有邀请进行分组。 

访问数组确保每个节点只处理一次，从而防止重复邀请。 

BFS 之后，可达性检查保证构建的树跨越整个图。 如果不是，则没有有效的方法来邀请从所选根开始的所有参与者。 

最后，我们按 BFS 顺序输出节点，每个节点后面跟着其子节点，这直接对应于邀请步骤的有效序列。

 | ---| ---| ---| ---| ---|
 | 1 | [1] | {1} | 1=根| 启动 BFS |
 | 2 | [2,3]| {1,2,3} | 2←1, 3←1 | 展开 1 |
 | 3 | [3,4]| {1,2,3,4} | 4←2 | 展开 2 |

 节点 3 和 4 很忙，但只显示为子节点，从不显示为扩展器。

 1 邀请 2 和 3，然后 2 邀请 4。 

这证实了繁忙的节点可以安全地作为叶子包含在内，同时保持完全可达性。 

### 示例 2

 输入：```
4 5 3
2 4 3
1 2
1 3
2 3
3 4
2 4
```非繁忙节点只有{1}。 BFS 从 1 开始到达所有节点，但根据结构，节点 3 或 4 需要充当分支点。 

这里BFS仍然访问所有节点，但是违反了结构要求，因为繁忙的节点在约束下被迫成为任何以1为根的生成树中的内部角色。 在这种结构中，当解释需要仔细的角色分配时，仅可达性是不够的。 BFS 表明覆盖是可能的，但邀请有效性在约束解释下失败，产生“否”。

 ## 边缘情况

 当所有参与者都很忙时，算法会立即拒绝，因为不存在有效的起点。 例如，在一个 3 节点三角形中，每个节点都标记为忙碌，没有合法的创建者，因此输出为“否”。 检查是通过在 BFS 之前扫描任何非繁忙节点来处理的。 

在具有一个非繁忙端点的线性链中，BFS 沿着链确定性地扩展。 每个节点都被访问一次并分配一个父节点，因此每个邀请步骤都是有效的，并且繁忙的节点不需要分支。 

在断开图中，BFS 从任何有效开始都无法到达所有节点。 最终的访问检查捕获了这种情况，确保部分生成树不会被错误地接受。
