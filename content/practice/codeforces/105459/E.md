 ## 解决方案
 ## 问题理解

 有$m$弹珠，每个弹珠都在实线上移动。 每个弹珠首先选择其中一个$n$随机均匀地固定轴负侧的起始位置，独立于所有其他位置。 选择之后，大理石$i$以自己的速度向右移动$v_i$，因此它的位置随时间线性变化。 

因为所有起始位置都是负值，速度都是正值，所以每个弹珠最终都会恰好穿过零一次。 穿过的时刻取决于所选的起始位置和弹珠的速度。 

随时$t$，我们看全部$m$当前位置并取中值坐标。 这是$\frac{m+1}{2}$-第最小位置。 随着时间的增加，所有位置都向右移动，因此中位数是分段线性递增函数$t$，并且它恰好过零一次。 

任务是计算在所有随机选择的起点中，当该中位位置变为零时的时间期望值。 

限制条件$n, m \le 500$意味着任何立方或更差的解决方案$m$已经太慢了，甚至$O(m^3)$需要小心处理。 解决方案围绕$O(n m^2)$或者$O(m^3)$处于边界上，但在编译语言中仍然可以接受。 

幼稚的方法会在很多方面失败。 一个微妙的陷阱是假设中位时间是各个穿越时间的中位数。 例如，如果一个弹珠速度极快，但从最左边开始，则其穿越时间可能会长或短，具体取决于所选的起点，并且这些相互作用会破坏任何直接平均捷径。 

另一个问题是思维独立性允许单独处理每个时间步骤。 中位数取决于所有位置的顺序，而不仅仅是每个弹珠是否高于或低于零，因此我们必须跟踪全局顺序统计数据而不是简单的计数。 

## 方法

 直接模拟将枚举弹珠起点的每次分配。 有$n^m$这样的分配，对于每个分配，我们都会计算所有交叉时间，每次都对它们进行隐式排序，并检测中位数何时达到零。 这是完全不可行的，因为即使$2^{500}$已经远远超出了任何计算极限。 

关键的结构简化来自于用单个随机变量重写每个弹珠的运动。 如果是大理石$i$选择起始位置$x_j$，然后它在某个时间过零$$T_{i,j} = -\frac{x_j}{v_i}.$$所以每个弹珠都有一个独立的离散分布$n$可能的穿越时间。 

任何固定时间$t$，当弹珠选择的穿越时间大于$t$。 这意味着当时的仓位配置$t$完全取决于有多少个随机交叉时间位于上方或下方$t$。 

现在考虑中间位置。 由于所有负值始终小于所有正值，因此至少在以下情况下中位数变为正值：$\frac{m+1}{2}$弹珠已过零。 这将问题简化为跟踪随机变量的顺序统计量$T_i$。 

让$k = \frac{m+1}{2}$。 中位数恰好在以下时刻过零：$k$-所有穿越时间中最小的$T_i$发生。 

所以整个问题归结为计算期望值$k$的阶统计量$m$独立的离散随机变量，其中每个变量都有$n$可能的值。 

一旦我们意识到事件“$k$第最小的$\le x$” 相当于“至少$k$的$T_i$是$\le x$”。这将问题转化为对不同伯努利变量的类似二项式概率的重复计算。

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 枚举所有作业 |$O(n^m m \log m)$|$O(m)$| 太慢了 |
 | 订单统计 DP 超过阈值 |$O(n m^2)$（或者$O(n m^3)$天真） |$O(m^2)$| 已接受 |

 ## 算法演练

 1.将每一个可能的起始选择转化为穿越时间$T_{i,j} = -x_j / v_i$。 每一颗弹珠$i$贡献了一份清单$n$候选人时间。 
2. 对所有不同的值进行排序$T_{i,j}$。 这是顺序统计量的分布可以改变的唯一时刻。 
3. 对于固定阈值$x$，为每个弹珠定义$i$概率$p_i(x)$它的穿越时间是$\le x$。 这就是它的数量$n$值是$\le x$，除以$n$。 
4. 将每个弹珠解释为伯努利变量，如果它在时间上过零，则该变量处于“活动”状态$x$。 活跃弹珠的数量是具有不同概率的独立伯努利变量的总和。 
5. 使用动态编程数组，其中`dp[j]`表示准确的概率$j$处理一些弹珠前缀后，弹珠会被激活。 
6. 一颗一颗地处理弹珠，使用伯努利变量的标准卷积以成功概率更新 DP$p_i(x)$。 这给出了一次活动计数的完整分布$x$。 
7. 根据该分布，计算$P(\text{at least } k \text{ marbles active})$。 这就是概率$k$-第最小的穿越时间最多为$x$。 
8. 扫描排序后的值$x$，并使用连续值之间的差异来重建期望：$$\mathbb{E}[T_{(k)}] = \sum P(T_{(k)} \ge x_i)\cdot (x_i - x_{i-1})$$这将期望转变为阶次统计分布恒定的间隔内的累积。 

### 为什么它有效

 关键的不变量是在任何时候$x$，整个系统仅取决于下面有多少个交叉时间$x$，而不是他们的身份或顺序。 中值交叉事件恰好对应于$k$这些独立随机阈值的阶统计量。 一旦建立了等价性，一切都简化为计算独立伯努利变量之和的尾部概率，这正是 DP 所维护的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())
    xs = list(map(int, input().split()))
    vs = list(map(int, input().split()))

    k = (m + 1) // 2

    times = []
    per_marble = []

    for i in range(m):
        v = vs[i]
        arr = []
        for x in xs:
            arr.append(-x / v)
        arr.sort()
        per_marble.append(arr)
        times.extend(arr)

    times = sorted(set(times))

    def prob_leq(arr, x):
        l, r = 0, n
        while l < r:
            mid = (l + r) // 2
            if arr[mid] <= x:
                l = mid + 1
            else:
                r = mid
        return l / n

    def dp_at_x(x):
        dp = [0.0] * (m + 1)
        dp[0] = 1.0

        for i in range(m):
            p = prob_leq(per_marble[i], x)
            ndp = [0.0] * (m + 1)
            for j in range(i + 1):
                if dp[j] == 0:
                    continue
                ndp[j] += dp[j] * (1 - p)
                ndp[j + 1] += dp[j] * p
            dp = ndp

        return sum(dp[k:])

    ans = 0.0
    prev = 0.0

    for i, x in enumerate(times):
        cur = dp_at_x(x)
        ans += cur * (x - prev)
        prev = x

    print(int(ans % MOD))

if __name__ == "__main__":
    solve()
```DP 的结构是围绕计算有多​​少弹珠已经过零达到给定阈值而构建的。 对于每个阈值$x$，我们从头开始重新计算概率分布，因为每个弹珠的概率取决于有多少个候选时间低于$x$。 

对排序时间的扫描可确保概率仅在有意义的点发生变化。 在两个连续阈值之间，$k$-th 交叉时间不会改变，因此对期望的贡献在该间隔内是线性的。 

解释中使用了浮点算术，但在严格的实现中，通常会用分数的模算术代替它。 

## 工作示例

 考虑一个小案例$m=3$,$k=2$，和两个起点。 每个弹珠都有一小组可能的穿越时间，这些时间源自其选择的起点。 

处于门槛$x$，我们计算每个弹珠过零的概率，然后构建 DP 表。 

| 步骤| 大理石加工| p(i, x) | p(i, x) | dp 状态 |
 | ---| ---| ---| ---|
 | 0 | 无 | - | [1, 0, 0, 0] |
 | 1 | 大理石 1 | p1 | 更新分布 |
 | 2 | 大理石 2 | p2| 更新分布 |
 | 3 | 大理石 3 | p3 | 最终分配|

 该表显示了每个弹珠如何逐步细化按时间跨过零的弹珠数量的分布$x$。 最终的尾部和直接给出中位数是否过零。 

相同的结构重复增加$x$价值观构建了完整的期望。

 ## 边缘情况

 一种微妙的情况是，多个弹珠对于不同的起始选择共享相同的穿越时间。 在这种情况下，DP 仍然独立对待它们，因为平等影响概率而不是结构。 由于相等仅影响间隔之间的边界，因此对排序的唯一时间进行扫描可确保不会发生重复计数。 

另一种情况是所有起点都非常接近。 然后全部$T_{i,j}$几乎是相同的，并且期望崩溃成一个紧密的值簇。 该算法仍然可以正确处理此问题，因为它将每个不同的值视为单独的事件，并且相同的值在重复数据删除后自然合并。 

最后一个边缘情况是弹珠之间的速度相同。 然后，每个弹珠在交叉时间上具有相同的分布，并且 DP 简化为对称二项式系统。 该算法不依赖对称性，仍然会产生正确的分布，因为每个大理石都是在相同的结构中独立处理的。
