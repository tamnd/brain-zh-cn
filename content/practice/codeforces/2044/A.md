 ## 解决方案
 ## 问题理解

 我们被要求计算有序的正整数对$(a, b)$这样$a + b = n$，对于多个测试用例。 每个测试用例给出一个整数$n$，我们必须输出对的总数$(a, b)$满足方程。 关键是两者$a$和$b$必须严格为正。 

限制很小：$2 \le n \le 100$以及多达 99 个测试用例。 因为$n$最多 100，任何在每个测试用例中以线性时间运行的解决方案都是完全可以接受的。 这种朴素的方法足够快，但我们仍然可以推理出封闭式公式。 

尽可能最小的$n$是 2。在这种情况下，唯一的一对是$(1,1)$。 如果解决方案忽略正数要求并计算零或负数，则会产生错误的答案。 同样，如果算法重复计算对称对或错误计算边界值，例如$n=2$或者$n=100$，那就错了。 

## 方法

 蛮力方法迭代所有可能的值$a$从 1 到$n-1$并计算其中的对$b = n - a$是积极的。 这有效是因为$b$唯一确定的是$a$， 和$a$永远无法到达$n$自那以后$b$将为零。 对于这样一个小问题，暴力解决方案是正确的，但不必要的冗长。 

关键的见解是对于给定的$n$，所有对的形式为$(1, n-1), (2, n-2), ..., (n-1, 1)$。 每个$a$从 1 到$n-1$产生一个有效的$b$，所以对的数量就是$n-1$。 这是一个封闭式的解决方案，完全消除了循环，是最简单、最直接的方法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例 O(n) | O(1) | O(1) | 由于 n 小而被接受 |
 | 封闭式| 每个测试用例 O(1) | O(1) | O(1) | 被接受且最简单的 |

 ## 算法演练

 1.读取测试用例数量$t$。 这决定了我们将重复计算多少次。 
2. 对于每个测试用例，读取整数$n$。 这是我们想要分成两个正整数的总和。 
3. 计算有效对的数量为$n-1$。 这是有效的，因为这些对完全是$(1, n-1), (2, n-2), ..., (n-1, 1)$，并且有$n-1$条款。 
4. 立即打印结果或将其存储在列表中以便在所有测试用例之后打印。 

为什么它有效：不变性是对于每个整数$a$在 1 到$n-1$,$b = n - a$自动为正值。 不会跳过或重复计算任何值，并且会考虑每个可能的对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print(n - 1)
```该解决方案首先读取测试用例的数量。 对于每个测试用例，它读取$n$和打印$n-1$。 使用`sys.stdin.readline`确保快速输入处理，即使输入大小很小。 不需要额外的数据结构。 减法处理所有有效的$n \ge 2$自动，避免差一错误。 

## 工作示例

 跟踪样本 1 输入`3\n2\n4\n6\n`：

 | 测试用例| n | 计算| 结果 |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 - 1 | 2 - 1 1 |
 | 2 | 4 | 4 - 1 | 4 - 1 3 |
 | 3 | 6 | 6 - 1 | 6 - 1 5 |

 该表显示对于每个$n$，减 1 可以正确计算所有有效对。 为了$n=2$， 仅有的$(1,1)$存在。 为了$n=4$，对$(1,3),(2,2),(3,1)$总和为 4，得到 3 对。

 给定$t \le 99$和$n \le 100$，该解决方案在现代硬件上是即时的，并且完全在内存限制内。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        output.append(str(n-1))
    return "\n".join(output)

# Provided samples
assert run("3\n2\n4\n6\n") == "1\n3\n5", "sample 1"

# Custom cases
assert run("1\n2\n") == "1", "minimum n"
assert run("1\n100\n") == "99", "maximum n"
assert run("2\n3\n5\n") == "2\n4", "small n, odd and even"
assert run("1\n50\n") == "49", "mid-range n"
assert run("1\n99\n") == "98", "odd n near max"
```| 测试输入| 预期产出 | 它验证了什么 |

 | 1\n100\n | 99 | 99 最大 n 值 |

 ## 边缘情况

 边缘情况与$n=2$处理正确。 该算法计算$2-1=1$，给出单个对$(1,1)$。 最大的边缘情况$n=100$产生$99$，这正是$(1,99),(2,98),...,(99,1)$。 不需要循环，因此该解决方案完全避免了差一错误。 积极性要求自然会被强制执行，因为$a$从 1 开始，直到$n-1$。
