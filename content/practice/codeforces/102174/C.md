 ## 解决方案
 ## 问题理解

 森克需要依次击败(n)只怪物。第(i)只怪物有(d_i)点生命值和(x_i)点力攻击，森克此时的攻击力为(k)。本轮森克先攻击，如果怪物没有被本次攻击杀死，怪物将会反击一次，所以森克真正承受伤害的次数，就是结束战斗中怪物到下一轮的次数。 

森克再次有 (c) 份力量炖水果。每吃一份，当前循环的攻击力增加 (k)，由此，如果这一轮吃了 (t) 份水果，森克这一击造成 ((t+1)k) 点伤害。水果的掉效果只持续当前回合，吃的水果也不能使用。 

我们需要决定水果如何分配，使所有怪物被击败后森克承受的总伤害最小。简单地把这个写出来。 

对于第(i)只怪物，如果不使用水果，它需要完全

 [
 q_i=\left\lceil\frac{d_i}{k}\right\rceil
 ]

 第二次攻击才能死亡。由于森克始终先手，其中最后一次攻击不会受到反击，所以这只怪物造成的伤害为

 [
 (q_i-1)x_i。 
]

 关键认为是一份水果就能带来多少收益。如果在某场战斗中额外获得一份水果，实际上额外增加基础攻击单位(k)。假设有一次不知需要(q_i)次攻击，现在为这只怪物参与(f)份水果，那么总共拥有(q_i+f)个单位的攻击力，可以把这些攻击力分配到若干回合中。只要末端需要的多边数量为 (q_i-f)，就可以把水果带来的攻击力全部用于提前战斗结束。每投入一个水果，最多可以让这只怪物少反击一次，也因此正好减少 (x_i) 点伤害。 

一只怪物最多只能从 (q_i) 个循环到一个循环，所以它最多能使用

 [
 q_i-1
 ]

 于是问题已经从模拟战斗变成了一个资源分配问题：每只怪物提供（q_i-1）个位置，每个位置使用一份水果可获得（x_i）的收益，总共只有（c）份水果。 

由于 (n) 可以达到 (10^5)，而 (k,c,d_i,x_i) 最大可以达到 (10^6)，任何涉及所有水果状态和所有怪物状态的二维动态规划都无法通过。比如 (O(nc)) 会达到 (10^{11}) 水平的状态，1 秒的限制下完全无法安装。我们需要利用每一个水果带来的源码实际上它被分配给哪一只模型这个程度。 

还需要注意一些容易出错的边界情况。 

第一种情况是怪物只需要一个回合。例如输入```
1 10 100
7 5
```输出应该是`0`因为基础攻击力已经足以一击击杀怪物，怪物根本没有机会反击。若代码直接把 (q_i x_i) 立即伤害，就会错误得到5。 

第二种情况是生命值正好是攻击力的整数倍。例如输入```
1 3 1
6 7
```输出应该是`0`。没有水果时需要两次攻击，但只用一个水果，第一轮攻击力变成6，可以直接击杀。若把轮次数写成`d // k + 1`，就会出现典型的整除边界错误。 

第三种情况是水果数量超过所有可以产生收益的数量。例如输入```
2 10 100
1 4
1 9
```输出仍然是`0`。两只怪兽都只需要一次，出来的水果没有任何价值。如果代码简单地把所有 (c) 份水果都当产生有效收益，就会产生负数。 

第四种情况是水果应该优先给予攻击力更高的怪物。例如```
2 3 1
3 3
4 5
```第一个只怪物只需要一个回合，本身没有一个回合的攻击次数。第二个只怪物需要两个回合，一个水果可以直接在第一个回合死亡，因此答案为`0`如果按怪物生命值大小分配水果，而不是按每份水果实际减少的伤害排序，就可能得到错误策略。 

## 方法

 最直接的做法是把每只怪物看成一个资源消耗对象。先计算每只怪物不使用水果时需要的循环数(q_i)，然后考虑前面给几个只怪物各自式分配多少份水果。可以做一个动态规划，令状态表示处理到某只怪物时使用了多少份水果，转移时枚举当前怪物使用的水果数量。这个办法完全针对原问题，因为我们显着尝试了在怪物之间的所有分配。 

即使进一步优化转移，这类方法仍然需要至少处理 (n) 和 (c) 的二维状态。最坏情况下状态数量达到

 [
 n c=10^5\times10^6=10^{11},
 ]

 这已经超出了默认范围。若真的枚举每只怪物可以使用的水果数量，复杂度还会更高。 

真正的突破来自一个更简单的观察。第(i)只怪物而言，它本来是次攻击，会对反击(q_i-1)次。每额外使用一个水果，就相当于增加一次基础攻击单位，可以让所需的攻击次数减少一次。少反应就少承受(x_i)点伤害，所以这只怪物的每一个有效水果都具有强大的收益(x_i)。 

那么第(i)只怪物实际上贡献了(q_i-1)个价值为(x_i)的物品。所有物品的重量都是1，而背包容量是(c)。这样的背包需要动态规划，直接选择价值最大的物品即可。 

因为同一只怪物产生的所有物品价值都相同，我们甚至不需要真的建立这些物品。把所有怪物按照 (x_i) 从大到小排序，然后把元素相互攻击力最高的怪物即可。每只怪物最多拿 (q_i-1) 份，拿满后再处理下一个怪物。 

最终答案是所有怪物在没有水果时造成的伤害：

 [
 \sum_i(q_i-1)x_i。 
]

 每使用一个水果，就从答案中减去当前怪物的(x_i)。所以只需要按(x_i)降序贪心小镇收益。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DP | (O(nc)) 或更高 | (O(c)) | 太慢了 |
 | 排序和贪婪 | (O(n\log n)) | (O(n\log n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 对每个怪物计算在没有水果时需要的攻击次数

 [
 q_i=\left\lceil\frac{d_i}{k}\right\rceil
 =\frac{d_i+k-1}{k}。 
]

 因为最后一次攻击不会反击，所以它最终造成的伤害为((q_i-1)x_i)。 
2. 将第 (i) 只怪物的可用水果数量记为

 [
 cap_i=q_i-1。 
]

 每使用一份水果，最多可以让该怪物少进行一次会导致反应的循环，因此每份水果可以减少 (x_i) 点伤害。一个怪物最多只能出现一个循环，所以不能使用超过 (q_i-1) 份水果。 
3.把所有怪物按照攻击力(x_i)从大到小排序。 

这样排列后，前面的水果意味着一份水果能够节省更多的生命值。由于所有水果的消耗都是1，而每份水果只关心它带来的伤害减少量，优先使用收益最大的水果一定不会差于把它带来收益更小的位置。 
4.依次处理排序剩余后的怪物。设置当前还(c)份水果，那么最多可以给当前怪物使用

 [
 \min(c,cap_i)
 ]

 将这些水果从答案中获得的收益，然后减少剩余水果数量。 
5. 当水果用完，或者所有怪物都已经没有可圈定的循环时结束。得到的答案就是最小总伤害。 

### 为什么它有效

 把每只怪物拆成 (q_i-1) 个虚拟物品，每个物品消耗一个水果并提供 (x_i) 的收益。任何一个水果对某只怪物的作用，都可以独立地看成其中一个这样的虚拟物品，因为每减少一次怪物的反击，就少受到一次 (x_i) 点伤害。于是原题等价从这些单位重量的物品中选最多 (c) 个，使价值总和最大。 

对于单位重量项目，优化方案选择显然价值最大的项目。这里每个价值项目就是对应怪物的攻击力(x_i)，所以按(x_i)从大到小选择，而每只怪物最多选择(q_i-1)个，就是全局优化方案。最终伤害最小获得的收益后，得到的就是最小伤害。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, c = map(int, input().split())

    monsters = []
    answer = 0

    for _ in range(n):
        d, x = map(int, input().split())

        rounds = (d + k - 1) // k
        useful = rounds - 1

        answer += useful * x

        if useful > 0:
            monsters.append((x, useful))

    monsters.sort(reverse=True)

    remaining = c

    for x, useful in monsters:
        if remaining == 0:
            break

        use = min(remaining, useful)
        answer -= use * x
        remaining -= use

    print(answer)

if __name__ == "__main__":
    solve()
```代码先计算`rounds = (d + k - 1) // k`，是整数形式的向上取整。这里不能写成`d // k + 1`，因为当 (d) 正好被 (k) 整除时，两者不同。`useful = rounds - 1`表示这只怪物最多有多少次反击可以被水果消除。若`useful`为0，这只怪物已经一击死亡，没必要把它加入排序队列。 

指标`answer`先保存完全不吃水果时的总伤害。对于每个怪物来说，这个值就是`(rounds - 1) * x`。 

受访者按照`x`降序排序。Python的元组排序会先比较第一个元素，因此`monsters.sort(reverse=True)`恰好按照攻击力从大到小排列。第二个元素只是容量，不影响我们需要的主要排序顺序。 

处理一个怪物时，实际使用的水果数量为`min(remaining, useful)`。这样既不会超过剩余的水果，也不会使同一只怪物被围观到零循环。每份水果都减少`x`点最终伤害，所以直接执行`answer -= use * x`。 

所有数值限制都需要使用整数计算。最大总伤害可以达到约 (10^5\times10^6\times10^6=10^{17}) 的量级，Python 的整数没有固定 64 位，因此不会发生溢出。在 C++ 中则应使用`long long`。

 ## 边缘情况

 当怪物本身一回合绕过被杀死时，(q_i=1)，所以`useful = 0`。例如```
1 10 100
7 5
```计算得到 (q=1)，任何初始伤害就是 ((1-1)\times5=0)。算法不会给它分配结果，因为它没有有效的位置，最终输出`0`。 

当 (d_i) 恰好是 (k) 的倍数时，向上取整得到准确的整数商。例如```
1 3 1
6 7
```有(q=6/3=2)，所以没有水果时受到一次反击，伤害为7。单个水果可以让第一轮攻击力变成6，直接击杀怪物，收益为7，最终答案为`0`。使用`(d + k - 1) // k`可以正确处理这个边界。 

当水果数量超过总有效位置时，算法只有真正能够减少水果的响应次数。```
2 10 100
1 4
1 9
```两只怪兽都有 (q_i=1)，所以所有`useful`都是0。排序队列为空，答案从一开始就是0。剩下的水果没有任何用途，也不会被错误地算成负伤害。 

当不同怪物的攻击力不同，而水果数量有限时，排序是决定正确性的核心。```
2 3 1
3 3
4 5
```第一只怪物没有有效位置，第二只怪物有一个值为 5 的位置。唯一水果移位第二只怪物可以减少 5 点伤害，正好把它从两个循环战斗变成一个循环战斗，因此答案为 0。算法攻击按照力排序后自然得到这个选择。 

最后，当(c)非常大的时候，不能写成循环执行(c)次并每次寻找最优怪物。(c)可以达到(10^6)，虽然单独看并不算巨大，但结合(n=10^5)会使错误的(O(nc))方法达到(10^{11})级别。当前对每只怪物瞬时计算的算法`use = min(remaining, useful)`，所以无论 (c) 有多大，处理水果的循环仍然只有 (O(n)) 次。
