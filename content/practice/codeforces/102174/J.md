 ## 解决方案
 ## 问题理解

 我们需要正好 (n) 个字符的每个有效表达式的值之和。 表达式以数字开头和结尾，运算符永远不会相邻出现，唯一的运算符是`+`和`-`。 允许使用前导零，因此最大数字块被简单地解释为普通的十进制整数，即使它以零开头。 所需的答案是所有求值表达式模 (998244353) 的总和。 官方声明和示例可在 Codeforces 上获取。 

困难不在于评估一个表达式。 长度为 (n) 的字符串具有指数级的多种可能性，一旦 (n) 达到 (5\times10^5)，即使检查所有字符串也已无望。 由于多达 500 个测试用例共享相同的上限，可接受的解决方案基本上需要最大 (n) 的线性预处理，然后每个测试用例持续进行工作。 在最大输入大小下， (O(n^2)) 递归已经需要大约 (2.5\times10^{11}) 次操作，远远超出一秒的限制。 

在一些边界情况下，看似自然的重现可能会出错。 对于(n=1)，不能出现任何运算符，因此十个表达式`0`通过`9`贡献 (45)，而不是零或 (10)。 对于 (n=2)，运算符仍然不会出现，因为它必须占用两个端点之一，因此答案是所有两位数字符串的总和 (4950)。 假设每个表达式都有一个运算符的递归在这两种情况下都会失败。 

另一个常见的错误是只计算第一个运算符之后的数字块。 例如，对于 (n=3)，表达式如`1+2`和`1-2`两者都存在。 它们的总贡献为 (3+(-1)=2)，因此后缀值取消，而前缀值保留两倍。 这种取消是有效重现背后的关键观察结果。 

前导零也很重要。 对于（n=2），`00`是一个有效的表达式并且贡献为零，而`09`是一个有效的表达式，贡献了 9 个。 有必要将数字块视为普通字符串，而不是要求其第一个数字非零。 

## 方法

 蛮力方法很简单。 生成超过十二个可用字符的每个长度为 (n) 的字符串，丢弃违反语法规则的字符串，评估每个剩余的表达式，并添加其值。 在有效性检查之前有 (12^n) 个原始字符串，因此对于 (n=5\times10^5) 来说，候选者的数量是天文数字。 即使生成所有有效表达式也是指数级的，因为有效表达式可以在许多位置选择运算符或数字。 这种方法是正确的，因为它直接枚举了我们需要其值的对象，但它几乎立即变得不可用。 

一种更有前途的方法是在第一个运算符处拆分表达式。 假设第一个运算符出现在 (i) 个字符之后。 前缀 (A) 本身是长度 (i) 的有效表达式，而后缀 (B) 仅包含数字，因为分割是在第一个运算符处进行的。 因此，后缀恰好有 (10^{n-i-1}) 个可能的字符串。 

对于每个固定对 (A,B)，有两个表达式：(A+B) 和 (A-B)。 他们的价值观增加了

 [
 (A+B)+(A-B)=2A。 
]

 后缀从总和中完全消失。 这是核心简化：要计算第一个运算符位于特定位置的每个表达式的贡献，我们只需要前缀的总值和可能的纯数字后缀的数量。 

令 (F_n) 为长度为 (n) 的所有有效表达式的值之和。 令 (P_n) 为所有 (n) 位字符串的总和，其中允许有前导零。 有 (10^n) 个这样的字符串，并且每个数字在每个位置出现的次数相同，给出

 [
 P_n=\frac{10^n(10^n-1)}2.
 ]

 不带运算符的表达式完全贡献 (P_n)。 对于第一个运算符出现在长度为 (i) 的前缀之后的表达式，`+`和`-`版本是

 [
 2F_i\cdot10^{n-i-1}。 
]

 因此

 [
 F_n=P_n+2\sum_{i=1}^{n-2}F_i10^{n-i-1}。 
]

 剩下的问题就是这个公式中的卷积。 我们可以通过定义来删除它

 [
 S_n=\sum_{i=1}^{n-2}F_i10^{n-i-1}。 
]

 从 (S_{n-1}) 转移到 (S_n) 会将每个现有项乘以 (10)，与 (i=n-2) 对应的新项是 (10F_{n-2})。 因此

 [
 S_n=10S_{n-1}+10F_{n-2}。 
]

 由于 (F_n=P_n+2S_n)，我们可以完全消除 (S)：

 [
 \开始{对齐}
 F_n
 &=P_n+20S_{n-1}+20F_{n-2}\
 &=P_n+10(F_{n-1}-P_{n-1})+20F_{n-2}。 
\结束{对齐}
 ]

 纯数项很好地简化了：

 [
 P_n-10P_{n-1}=45\cdot10^{2n-2}。 
]

 因此最终的递归是

 [
 \boxed{F_n=10F_{n-1}+20F_{n-2}+45\cdot10^{2n-2}}
 ]

 与

 [
 F_1=45，\qquad F_2=4950。 
]

 这将原来的指数枚举变成了线性递归。 我们可以预先计算一次最大请求的所有答案 (n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(12^n\cdot n)) | (O(n)) | (O(n)) | 太慢了|
 | 最佳| (O(\max n+T)) | (O(\max n)) | 已接受 |

 ## 算法演练

 1. 读取所有测试用例并找到最大的请求长度（N）。 仅预计算最多 (N) 可以避免为较小的输入做不必要的工作。 
2. 预先计算 (10) 模 (998244353) 的幂。 递归需要 (10^{2n-2})，因此一种方便的选择是维护 (p_n=10^n) 并使用 (p_{n-1}^2)。 
3. 设置（F_1=45）和（F_2=4950）。 在这些情况下，运算符无法出现，因此答案只是所有一位数和两位数字符串的总和。 
4. 对于每个 (n\ge3)，计算

 [
 F_n=(10F_{n-1}+20F_{n-2}+45p_{n-1}^2)\bmod998244353。 
]

 由于 (p_{n-1}=10^{n-1})，最后一项正好是 (45\cdot10^{2n-2})。 
5. 存储每个(F_n)。 然后可以通过直接打印预先计算的值来回答每个查询。 

为什么它有效可以通过第一算子分解来总结。 每个包含运算符的表达式都只有一个第一个运算符。 它前面的所有内容都是任意有效表达式 (A)，后面的所有内容都是任意数字字符串 (B)。 第一个算子的两个选择分别贡献(A+B)和(A-B)，其和为(2A)。 因此，每个表达式只计算一次，其贡献由递归表示。 从卷积到二阶递推的代数变换保留了相同的量，因此每个存储的（F_n）正是所需的和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    queries = [int(input()) for _ in range(t)]
    mx = max(queries)

    ans = [0] * (mx + 1)

    if mx >= 1:
        ans[1] = 45

    if mx >= 2:
        ans[2] = 4950

    pow10 = [1] * (mx + 1)
    for i in range(1, mx + 1):
        pow10[i] = pow10[i - 1] * 10 % MOD

    for n in range(3, mx + 1):
        # 45 * 10^(2n-2) = 45 * (10^(n-1))^2
        pure_term = 45 * pow10[n - 1] % MOD * pow10[n - 1] % MOD

        ans[n] = (
            10 * ans[n - 1]
            + 20 * ans[n - 2]
            + pure_term
        ) % MOD

    sys.stdout.write("\n".join(str(ans[n]) for n in queries))

if __name__ == "__main__":
    solve()
```第一部分在进行动态编程之前读取每个查询。 这使程序可以确定所需的最大长度并执行一次共享预计算，这特别有用，因为可能有数百个测试用例。 

数组`pow10`存储 (10^i\bmod MOD)。 在位置 (n) 处，非齐次项为 (45\cdot10^{2n-2})，计算公式为`45 * pow10[n - 1] * pow10[n - 1]`。 乘法减少模数`MOD`在每个阶段，Python 永远不需要操纵 10 的巨大精确幂。 

递归仅使用`ans[n - 1]`,`ans[n - 2]`， 和`pow10[n - 1]`。 基数 (F_1) 和 (F_2) 是分开处理的，因为递归描述了第一个运算符分解之后的表达式，并且需要两个先前的长度。 

Python 中不存在整数溢出问题，每次乘法后进行归约可以保持中间值较小。 在固定宽度语言中，在取模之前应使用足够宽的整数类型执行乘法。

 [

 [

import io

MOD = 998244353

def solve():
    input = sys.stdin.readline

    t = int(input())
    queries = [int(input()) for _ in range(t)]
    mx = max(queries)

    ans = [0] * (mx + 1)

    if mx >= 1:
        ans[1] = 45
    if mx >= 2:
        ans[2] = 4950

    pow10 = [1] * (mx + 1)
    for i in range(1, mx + 1):
        pow10[i] = pow10[i - 1] * 10 % MOD

        pure_term = 45 * pow10[n - 1] % MOD * pow10[n - 1] % MOD
        ans[n] = (
            10 * ans[n - 1]
            + 20 * ans[n - 2]
            + pure_term
        ) % MOD

    sys.stdout.write("\n".join(str(ans[n]) for n in queries))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

def mat_mul(a, b):
    return [
        [
            sum(a[i][k] * b[k][j] for k in range(3)) % MOD
            for j in range(3)
        ]
        for i in range(3)
    ]

def mat_pow(a, e):
    r = [
        [1, 0, 0],
        [0, 1, 0],
        [0, 0, 1],
    ]

    while e:
        if e & 1:
            r = mat_mul(r, a)
        a = mat_mul(a, a)
        e >>= 1

    return r

def max_case_expected(n):
    # State:
    # [F_n, F_(n-1), 10^(2n-2)]
    #
    # F_(n+1) = 10 F_n + 20 F_(n-1) + 45 * 10^(2n)
    #
    # The third component is multiplied by 100.
    trans = [
        [10, 20, 4500],
        [1, 0, 0],
        [0, 0, 100],
    ]

    if n == 1:
        return 45
    if n == 2:
        return 4950

    # At n = 2:
    # state = [F_2, F_1, 10^2]
    p = mat_pow(trans, n - 2)
    state = [4950, 45, 100]

    return sum(p[0][i] * state[i] for i in range(3)) % MOD

 ## 边缘情况

 对于 (n=1)，唯一有效的字符串是十个单独的数字。 初始化集（F_1=45），即（0+1+\cdots+9）。 不尝试重复步骤，因此不存在对较短表达式的无效引用。 

对于 (n=2)，运算符必须占据第一个或第二个字符，这两个字符都是被禁止的。 因此，每个有效表达式都是一个两位数字符串`00`通过`99`。 初始化（F_2=4950）给出了正确的结果。 

对于(n=3)，运算符首先成为可能。 纯数字串贡献

 [
 0+1+\cdots+999=499500。 
]

 带有运算符的表达式具有一位数前缀和一位数后缀。 对于每个前缀值 (a)，该对`a+b`和`a-b`贡献（2a）。 对十个可能的前缀和十个后缀求和得出

 [
 2\cdot45\cdot10=900。 
]

 因此

 [
 F_3=499500+900=500400。 
]

 这正是第一个操作符取消变得相关的第一点。 

对于包含多个运算符的表达式，分解仍然有效，因为仅选择第一个运算符。 例如，诸如此类的表达式`12-3+45`被分割为 (A=12), 运算符`-`，并且（B=3+45）在概念上仅当（B）允许包含运算符时，这不在我们的分解范围内。 相反，第一个运算符位于`12`，所以实际的后缀是数字块`3`，以及剩余的`+45`仅当稍后选择第一个运算符时，才属于不同前缀分解的结构。 更直接地说，每个完整的表达式都有一个唯一的第一个运算符，并且该位置之前的所有内容都是有效表达式，而其之后的所有内容不包含运算符。 这种唯一性可以防止重复计算。 

对于前导零，`00`,`007`， 和`00042`都是合法的数字块。 (10^k) 项计算所有 (k) 位字符串，而不是恰好具有 (k) 位十进制数字的整数。 这就是为什么纯字符串和是

 [
 P_k=\frac{10^k(10^k-1)}2
 ]

 而不是从 (10^{k-1}) 到 (10^k-1) 的整数之和。 

对于 (n=500000)，该算法从不构造表达式，也从不计算大的十进制数。 它对每个长度执行一次相同的递归，减少每个数量模 (998244353)。 大输入大小仅改变线性时间迭代的次数，而不改变解的数学结构。
