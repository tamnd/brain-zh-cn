 ## 解决方案
 ## 问题理解

 我们收到一个排列`p[1..n]`包含来自的每个值`1`到`n`正好一次。 输入序列只能从左到右被消耗。 每个消耗的值都可以被推送到可用堆栈之一上，并且稍后堆栈的顶部值可以被附加到答案或移动到另一个堆栈上。 最终输出必须准确无误`1, 2, ..., n`。 

任务是找到使这成为可能的最小堆栈数量。 

最令人惊讶的是，答案永远不会大于`2`。 使用一个堆栈，某些排列已经可以排序，而无法使用一个堆栈排序的每个排列可以使用两个堆栈来处理。 因此，整个问题简化为识别给定的排列是否是有效的单栈输出序列。 

自从`n`可以达到`10^5`，具有二次行为的算法已经需要大约`10^10`最坏情况下的基本操作，远远超出了一秒竞赛限制所能容忍的范围。 我们需要一个`O(n)`或者`O(n log n)`解决方案。 排列属性还意味着每个值都是唯一的，因此我们永远不必像真正的情况一样处理相等的元素。 

有几种边缘情况可能会欺骗粗心的模拟。 为了`n = 1`，排列`[1]`只需要一个堆栈，所以答案是`1`。 假设至少一个元素必须保留在堆栈中的幼稚实现可能会错误地返回`2`。 

对于已经增加的排列，例如`1 2 3`，答案也是`1`。 每个值都可以被消耗并立即输出。 首先推送每个输入值的实现将不必要地创建堆栈状态`[1, 2, 3]`，其顶部是`3`，并且可能会错误地得出堆栈不足的结论。 

重要的故障模式是`2 3 1`。 前两个值必须先存储`1`可以输出，给出堆栈状态`[2, 3]`。 后`1`被生产出来，`2`被困在下面`3`，所以一个栈无法输出`2`下一个。 正确答案是`2`。 仅检查排列是否包含递减对，或者仅检查其最长递减子序列是否具有某个特定长度的粗心实现可能会对此类情况进行错误分类。 

## 方法

 直接的暴力方法可以尝试所有可能的堆栈数量并明确探索合法操作。 对于固定配置，每个输入值可以分配给不同的堆栈，并且顶部值也可以在输出之前在堆栈之间移动。 可能的操作序列的数量呈指数增长，因为相同的值可以以多种顺序通过不同的堆栈。 甚至将搜索限制为所有可能的堆栈分配也已经给出了`k^n`的可能性`n`输入值和`k`堆栈，当`n = 10^5`。 

一种更合理的简单方法是通过模拟标准堆栈排序过程来测试一个堆栈是否有效。 目标输出是强制的：下一个所需值始终是`1`， 然后`2`， 然后`3`， 等等。 当下一个输入的值是需要的值时，我们可以立即输出。 否则必须将其压入堆栈。 每当堆栈顶部成为下一个所需值时，我们就会将其弹出。 

关键的观察是，这个贪婪过程完全决定了一个堆栈是否足够。 将所需值保留在堆栈顶部永远不会有任何好处，因为输出必须不断增加。 同样，如果下一个输入值是所需的输出值，则延迟它也无济于事。 

因此，可以进一步减少对堆栈计数的强力搜索。 我们只需要区分一个堆栈和多个堆栈即可。 如果排列通过单栈模拟，则答案为`1`。 否则答案是`2`，因为两个堆栈足以满足每个排列。 当第一个堆栈包含阻塞下一个所需值的元素时，第二个堆栈可用作临时存储。 这正是问题看似通用的多堆栈操作模型崩溃为二进制答案的原因。 

单堆栈条件也相当于避免经典的堆栈可排序排列模式`231`，但与显式检查禁止模式相比，实现模拟更简单且不易出错。

 ## 算法演练

 1. 设置`need = 1`，意味着`1`是必须出现在排序输出中的下一个值。 创建一个空的辅助堆栈。 输出本身不需要存储，因为我们只关心是否可以按顺序生成每个所需的值。 
2. 从左到右处理排列。 如果当前输入值等于`need`，消耗它并立即增加`need`一个。 这是最佳的，因为该值已经恰好是最终递增序列所需的下一个值。 
3. 如果当前输入值不是`need`，将其压入堆栈。 它还不能输出，因为这样做会违反所需的递增顺序。 
4. 每个输入值处理完毕后，重复检查栈顶。 虽然顶部等于`need`，弹出并增加`need`。 这种贪婪的弹出是被迫的：最高值已准备好输出，并将其保留在那里并不能让未来的安排变得更好。 
5. 毕竟`n`输入值已被消耗，检查堆栈。 如果为空，则每个值都已按要求的顺序输出，所以一个堆栈就足够了，答案是`1`。 
6. 如果栈不为空，则一个栈无法对排列进行排序。 两个栈就足够了，所以答案是`2`。 

### 为什么它有效

 不变的是，在处理输入的任何前缀后，所有小于的值`need`已经完全按照所需的顺序输出，而当前存储在堆栈中的每个值都在等待轮到。 每当`need`位于堆栈顶部，因此必须立即输出它，因为最终序列无法首先输出更大的内容。 每当当前输入等于`need`，首先将其放入堆栈只会延迟已经可用的正确输出。 

因此，当存在合法的单堆栈执行时，贪婪模拟就会成功。 如果它留下了元素，则这些元素无法在一个 LIFO 结构内进行足够的重新排列以按顺序生成缺失值。 一般的两栈结构给出了上界`2`，因此失败的单栈案例精确地具有最小答案`2`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        stack = []
        need = 1

        for x in p:
            if x == need:
                need += 1
            else:
                stack.append(x)

            while stack and stack[-1] == need:
                stack.pop()
                need += 1

        ans.append("1" if not stack else "2")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```变量`need`表示尚未放入最终排序序列的最小值。 它开始于`1`并达到`n + 1`处理成功后。 

名单`stack`代表单堆栈测试中唯一可用的堆栈。 当当前排列值不能立即使用时，它将被推送到此列表中。 蟒蛇的`append`模拟堆栈推送，同时`pop`删除顶部元素。 

这`while`循环是必要的，而不是单个`if`。 一个新消耗的值可以暴露其下面的另一个所需的值。 例如，通过排列`3 2 1`，所有三个值都被压入，然后是顶部序列`1, 2, 3`可以连续弹出。 错过这种重复弹出是堆栈模拟中常见的逐一错误。 

测试为`x == need`发生在推动之前`x`。 如果传入的值恰好是下一个需要的值，则它永远不需要进入堆栈。 这就是允许增加排列的原因，例如`1 2 3`使用一个堆栈进行处理，而不留下任何存储的内容。 

不存在整数溢出问题，因为所有值最多都是`10^5`，Python 整数无论如何都直接处理计数器。 存储的数据总量与`n`。 

## 工作示例

 ### 示例 1

 对于排列`3 2 1`，堆栈模拟进行如下。 

| 输入值|`need`加工前 | 堆栈之前 | 行动|`need`之后| 堆栈之后 |
 | --- | --- | --- | --- | --- | --- |
 | 3 | 1 |`[]`| 推 3 | 1 |`[3]`|
 | 2 | 1 |`[3]`| 推 2 | 1 |`[3, 2]`|
 | 1 | 1 |`[3, 2]`| 推入 1，然后弹出 1、2、3 | 4 |`[]`|

 什么时候`1`到达时，它会被推送，因为模拟会统一处理每个非立即值。 它成为堆栈的顶部，所以`1`被弹出。 这暴露了`2`，这也是下一个需要的值，所以`2`也被弹出。 最后`3`被暴露并弹出。 

堆栈最后是空的，所以输出是`1`。 这个例子说明了为什么重复`while`循环是必要的。 

### 示例 2

 对于排列`2 1`，迹线为：

 | 输入值|`need`加工前 | 堆栈之前 | 行动|`need`之后| 堆栈之后 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 1 |`[]`| 推 2 | 1 |`[2]`|
 | 1 | 1 |`[2]`| 推入 1，然后弹出 1 和 2 | 3 |`[]`|

 后`1`被推入后，可以立即弹出。 这暴露了`2`，现在正是下一个所需的值。 因此，这两个值都是使用一个堆栈按排序顺序生成的。 

最终栈为空，给出答案`1`。 

### 示例 3

 对于排列`2 3 1`，迹线为：

 | 输入值|`need`加工前 | 堆栈之前 | 行动|`need`之后| 堆栈之后 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 1 |`[]`| 推 2 | 1 |`[2]`|
 | 3 | 1 |`[2]`| 推 3 | 1 |`[2, 3]`|
 | 1 | 1 |`[2, 3]`| 推 1，弹出 1 | 2 |`[2, 3]`|

 后`1`是输出，下一个需要的值是`2`，但是栈顶是`3`。 自从`2`被困在下面`3`，一个堆栈无法继续。 

剩下的堆栈证明答案不是`1`。 两个栈就足够了，所以答案是`2`。

## 测试用例

 原始问题保证每个输入都是排列，因此“全等值”测试不是有效的测试用例。 最接近的有意义的边界测试是严格递增的排列，其中每个值都可以立即输出。```python
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        stack = []
        need = 1

        for x in p:
            if x == need:
                need += 1
            else:
                stack.append(x)

            while stack and stack[-1] == need:
                stack.pop()
                need += 1

        ans.append("1" if not stack else "2")

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

# Provided samples
assert run(
    "3\n"
    "3\n"
    "3 2 1\n"
    "2\n"
    "2 1\n"
    "3\n"
    "2 3 1\n"
) == "1\n1\n2", "provided samples"

# Minimum-size input
assert run(
    "1\n"
    "1\n"
    "1\n"
) == "1", "single element"

# Already sorted, every value can be output immediately
assert run(
    "1\n"
    "5\n"
    "1 2 3 4 5\n"
) == "1", "increasing permutation"

# A classic one-stack failure
assert run(
    "1\n"
    "4\n"
    "2 3 1 4\n"
) == "2", "231 pattern"

# Decreasing permutation, requiring repeated pops
assert run(
    "1\n"
    "6\n"
    "6 5 4 3 2 1\n"
) == "1", "maximum stack depth"

# Large boundary case, increasing permutation
n = 100000
p = " ".join(map(str, range(1, n + 1)))
assert run(f"1\n{n}\n{p}\n") == "1", "maximum n"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 / 1 / 1`|`1`| 最小可能的输入和边界初始化`need`。 |
 |`1 / 5 / 1 2 3 4 5`|`1`| 可以直接输出值，无需使用堆栈。 |
 |`1 / 4 / 2 3 1 4`|`2`| 检测到`231`阻塞并防止错误的单堆栈结果。 |

 ## 边缘情况

 对于`n = 1`，输入正好是`1`。 模拟开始于`need = 1`，看到当前值等于`need`，和增量`need`到`2`。 堆栈仍然是空的，所以答案是`1`。 

对于已经排序的排列，例如`1 2 3 4 5`，每个传入值等于`need`。 该算法从不推送任何东西，并且`need`预付款来自`1`到`6`。 最终堆栈为空，所以答案是`1`。 这会捕获在尝试弹出之前不必要地推送每个输入值的实现。 

对于阻碍`2 3 1`，前两个值被压入，产生`[2, 3]`。 什么时候`1`到达，它被推入并立即弹出，离开`[2, 3]`和`3`在顶部的同时`2`是必须的。 堆栈无法产生正确的下一个值，因此模拟以非空存储结束并返回`2`。 

对于递减排列`6 5 4 3 2 1`，每个值最初都会被推送。 一次`1`到达时，`while`循环删除`1`， 然后`2`， 然后`3`， 然后`4`， 然后`5`，最后`6`。 堆栈变空，证明深堆栈本身并不是需要多个堆栈的原因。 捕获值的顺序很重要。 

对于最大输入大小，长度递增排列`100000`每个值都会产生一个恒定时间决策，并且永远不会增加堆栈。 相同大小的递减排列会推送每个值，然后将每个值弹出一次。 在任何一种情况下，堆栈操作的总数都保持线性，因此实现保持在预期的复杂性范围内。
