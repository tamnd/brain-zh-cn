 ## 解决方案
 ## 问题理解

 我们有一个多项式

 [
 f(x)=a_nx^n+a_{n-1}x^{n-1}+\cdots+a_1x+a_0。 
]

 输入给出其次数 (n)、必须应用微分的次数 (k) 以及从最高次数到常数项的 (n+1) 个系数。 我们需要输出第 (k) 个导数的系数，仍然使用 (n+1) 个位置。 任何次数消失的项贡献系数为零。 每个结果系数都需要对 (2019) 求模。 

关键的索引细节是输入数组按降序排列。 如果`a[j]`是从零开始的位置(j)的元素，它表示(x^{n-j})的系数。 微分 (k) 次后，该系数移动到次数 (n-j-k)，前提是该次数是非负的。 

这里 (1\le n,k\le100)，因此即使对每个微分进行直接模拟也是很小的。 当（n=100）和（k=100）时，系数更新的总数仅为

 [
 100+99+\cdots+1=5050。 
]

 因此，在这些约束下，(O(nk)) 解的速度相当快。 更有用的观察是，每个原始系数在 (k) 导数之后都有一个简单的封闭形式贡献，给出 (O(n)) 解并使索引更容易推理。 

在某些情况下，实施可能会悄无声息地出错。 如果 (k>n)，则每一项都消失。 例如，```
2 3
1 2 3
```表示(x^2+2x+3)，三阶导数为零，因此输出为```
0 0 0
```盲目地访问 (i+k) 次系数的粗心实现可能会超出范围。 

常数项也必须正确处理。 为了```
1 1
7 5
```多项式为 (7x+5)，因此导数为 (7)。 所需的输出有两个位置：```
0 7
```前面的零代表(x^1)的系数，微分后不再存在。 仅打印非零度部分的实现会产生错误的格式。 

最后，系数可以在最终模运算之前快速增长。 例如，100 次项的重复微分会引入阶乘大小的乘数。 Python 整数可以安全地处理这个问题，但整个计算仍应减少模 (2019)。 在具有固定宽度整数的语言中，推迟模数可能会溢出。 

## 方法

 最直接的方法是一次模拟一个阶的微分。 对于从最高次到最低次存储的多项式，微分将(x^i)的系数(a_i)变为(i a_i)，其成为(x^{i-1})的系数。 常数项变为零。 重复此过程 (k) 次是正确的，因为它完全遵循重复微分的定义。 

该模拟的复杂度为(O(nk))。 在最大允许值（n=k=100）下，系数乘法次数最多为（100+99+\cdots+1=5050）。 因此，由于规定的限制，这种方法实际上是可以接受的。 如果约束大幅增加，特别是当（n）和（k）都很大时，它的吸引力就会降低。 

更快的方法来自于查看一个原始单项式，而不是模拟整个多项式。 假设原项是

 [
 a_jx^j。 
]

 经过一阶导数后，它变成

 [
 a_jj x^{j-1}。 
]

 经过两次求导后就变成了

 [
 a_jj(j-1)x^{j-2}。 
]

 经过 (k) 次导数后，假设 (j\ge k)，则变为

 [
 a_j\cdot j(j-1)\cdots(j-k+1)x^{j-k}。 
]

 乘数是一个下降阶乘。 如果我们想要最终多项式中的 (x^i) 系数，则其原始次数必须为 (i+k)。 因此

 [
 b_i=a_{i+k}(i+k)(i+k-1)\cdots(i+1)。 
]

 我们只需要计算原始度数 (j=k,k+1,\ldots,n)。 每个较低阶项都完全消失。 

因为只有 (n+1) 个原始系数，所以我们可以对每个系数处理一次。 我们还可以逐步构建下降阶乘乘数，避免阶乘并保持每个中间值模（2019）。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(nk)) | (O(nk)) | (O(n)) | (O(n)) | 接受这些限制 |
 | 最佳| (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 按降序读取(n)、(k)和系数。 将它们存储在数组中`a`， 在哪里`a[j]`是 (n-j) 次的系数。 
2. 创建 (n+1) 个零的输出数组。 保持原始长度是必要的，因为所需的输出包含从 (n) 到 (0) 的每个度数的系数槽。 
3. 如果 (k>n)，则将整个输出保留为零并打印它。 每个单项式的次数均小于 (k)，因此在 (k) 微分后它们全部消失。 
4. 对于从 (k) 到 (n) 的每个原始度数 (j)，计算 (k) 导数后的系数。 原项 (a_jx^j) 变为

 [
 a_j\frac{j!}{(j-k)!}x^{j-k}。 
]

 最终的度数为(j-k)，因此对应的输出位置为(n-(j-k))。 

1. 通过将 (j-k+1) 到 (j) 的 (k) 个连续整数相乘，计算乘数 (j!/(j-k)!)，每次相乘后减少模 (2019)。 由于 (k\le100)，这已经足够小，但模块化形式还避免了不必要的大中间值。 
2. 将得到的系数存储在第(j-k)次对应的位置，最后打印所有(n+1)个输出系数，并用空格分隔。 

不变的是，每当算法处理原始度 (j) 时，度 (j-k) 处的值恰好是单个单项式 (a_jx^j) 的 (k) 阶导数。 微分是线性的，因此将这些贡献加到所有原始单项式上即可得到完整的 (k) 阶导数。 (j<k) 项不存在，因为重复微分最终达到常数项，然后为零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 2019

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ans = [0] * (n + 1)

    if k <= n:
        for j in range(k, n + 1):
            multiplier = 1

            for t in range(j - k + 1, j + 1):
                multiplier = multiplier * t % MOD

            coefficient = a[n - j] % MOD
            coefficient = coefficient * multiplier % MOD

            final_degree = j - k
            ans[n - final_degree] = coefficient

    print(*ans)

if __name__ == "__main__":
    solve()
```输入数组采用降序排列，因此(x^j)的系数为`a[n - j]`。 此转换是实现中的主要索引细节。 

循环开始于`j = k`因为小于 (k) 的度无法在 (k) 微分中生存。 对于每个幸存学位，最终学位是`j - k`，其输出位置因此为`n - (j - k)`。 

乘数计算如下

 [
 (j-k+1)(j-k+2)\cdots j。 
]

 这正是 (j!/(j-k)!)，由 (k) 个连续导数引入的因子。 每次乘法后取模 (2019) 可以保持中间值较小，并给出相同的最终余数。 

除了次数计算之外，不需要对常数项进行特殊处理。 一旦一个术语被微分，它的最终位置直接由它的原始程度决定。 

该问题只有一个测试用例，因此该解决方案读取两行输入一次并打印一行结果。

 ## 边缘情况

 当 (k>n) 时，不存在具有足够阶次的单项式来承受所有微分。 为了```
2 3
1 2 3
```2 阶项在三阶导数之后变为零，较低阶项更早消失。 该算法永远不会进入`j`循环因为`k <= n`为 false，因此预初始化输出`[0, 0, 0]`是直接打印的。 

当存在常数项时，它对任何正序导数没有任何贡献。 为了```
1 1
7 5
```多项式为 (7x+5)。 该循环仅处理阶数 1，计算乘数 (1)，并将 7 置于最终阶数 0 处。结果为`0 7`，保留所需的 (n+1) 个系数位置。 

当较低阶项消失但较高阶项仍然存在时，算法会跳过消失的项，而不是尝试区分它们。 为了```
4 2
0 0 0 7 9
```多项式为 (7x+9)，其二阶导数为零。 原始度数 1 和 0 都低于 (k=2)，因此两者都不会被处理，并且每个输出位置都保持为零。 

即使度数减少，输出也必须保留原始位置数。 对于样本 2，二阶导数的阶数为 3，但输入阶数为 5，因此前两个输出项必须为零。 该算法根据其实际最终度数写入每个幸存项，并将每个其他槽初始化为零。 

需要模数减少，因为下降阶乘乘数可能会变大。 实施减少了`multiplier`在每次乘法之后，然后也减少最终的系数乘积。 由于模乘法保留了完整乘积的其余部分，因此这恰好产生了所需的模数系数 (2019)。
