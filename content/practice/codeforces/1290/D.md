 ## 解决方案
 ## 问题理解

 我们得到一个长度为的隐藏数组$n$，其中每个位置代表一家咖啡馆，并且每家咖啡馆只生产一种类型的咖啡。 位置处的值$i$是咖啡品种标签$a_i$，但我们从来没有直接看到它。 

相反，我们可以查询一家咖啡馆并收到一个二进制答案，该答案取决于最后一个的滑动窗口$k$尝过咖啡。 如果我们查询的咖啡馆品种已经出现在最后一个中$k$尝过咖啡后，系统会给出肯定的答复，否则会给出否定的答复。 每次查询后，品尝到的咖啡会被追加到最多 size 的队列中$k$，并且较旧的条目会被删除。 我们也可以随时重置这个记忆。 

任务是仅使用这些嘈杂的成员资格检查来确定隐藏数组中存在多少个不同的值，而只要答案保持一致，对手甚至可以自适应地选择数组。 

关键的困难在于每个查询都不是纯粹的相等测试。 这取决于历史记录，因此对同一索引的重复查询可能会根据之前的交互产生不同的答案。 

自从$n \le 1024$,天真的$O(n^2)$交互策略在查询预算中可能是可以接受的，但前提是仔细控制。 然而，内存的自适应性质意味着不小心重用查询可能会损坏信息，因此任何依赖于稳定比较的方法都必须主动管理内存状态。 

当尝试直接检测重复项时，会出现微妙的故障模式。 例如查询索引$i$和$j$交替地不重置会导致交叉污染：肯定的答案可能反映记忆历史而不是相等$a_i$和$a_j$。 另一个问题是假设“第一次看到”的查询总是反映新颖性，一旦从窗口驱逐后相同的值重新出现，这种查询就会中断。 

因此，解决方案必须模拟受控环境，其中每个查询都在已知的内存状态下进行解释。 

## 方法

 一个直接的暴力想法是将每个咖啡馆视为候选新品种，并尝试检查它是否与任何先前确认的代表相匹配。 人们可能会尝试比较每一对$(i, j)$通过重置内存并仔细探测两个索引。 这需要$O(n^2)$比较，每个比较可能涉及多个查询以稳定内存效应。 在最坏的情况下，在严格的查询预算下这会变得太慢。 

关键的观察结果是，内存窗口仅对_最近的历史记录_起作用，并且我们可以使用重置来完全消除它。 一旦我们在任何受控比较块之前重置，每个查询序列都会从干净的石板开始，这意味着答案仅取决于当前查询是否与新构造的窗口中的元素匹配，而不取决于之前的实验。 

这使我们能够构建确定性探测模式：我们隔离每个索引并显式构建受控历史记录，在该历史记录中我们确切地知道哪些值位于内存窗口内。 然后，我们可以通过强制成员资格进入窗口并观察稍后的查询是否检测到它来间接测试相等性。 

标准的高级策略是使用重置分隔会话来模拟成对比较。 我们维护一组已发现的代表。 对于每个新索引，我们通过重建仅包含该代表的受控内存窗口并检查新索引是否报告匹配来测试其值是否与任何已知代表匹配。 

这将问题减少到重复的“等于任何已知类”检查，每次检查都在干净的内存环境中执行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 没有结构的天真的成对交互比较 |$O(n^2)$开销很大的查询|$O(1)$| 太慢/不可靠 |
 | 受控的基于重置的分类与代表 |$O(n^2 / k)$查询 |$O(n)$| 已接受 |

 ## 算法演练

 我们维护一份代表性指数列表，每个指数代表我们迄今为止已确认的独特咖啡品种。 

1. 从空的代表列表开始，并发出重置以确保内存状态为空。 这保证了每次后续交互都从已知的基线开始。 
2. 遍历所有咖啡馆$1$到$n$。 对于每个索引$i$，我们确定它是否属于现有的已知品种。 
3. 每位代表$r$，我们进行受控测试。 我们重置内存，然后查询$r$确切地$k$次。 这保证了$a_r$存在于内存窗口中。 
4. 建立这个受控内存状态后，我们再次重置并再次重建相同的状态，但确保只有代表的值在窗口中。 然后我们查询$i$。 如果在此受控设置下答案是肯定的，我们得出结论$a_i = a_r$。 

这样做的原因是平等可以在相同的构造窗口下转换为成员资格。 由于每次测试前都会完全重置内存，因此之前的检查不会造成污染。 

1. 如果没有代表匹配$i$，我们添加$i$作为新代表。 
2. 继续，直到处理完所有索引。 答案就是代表人数。 

### 为什么它有效

 在每个比较阶段，内存状态都会从头开始完全重建，这意味着任何查询的答案仅取决于该会话中显式插入的咖啡序列。 这消除了对先前交互的任何依赖，并将交互系统简化为我们构建的窗口的确定性函数。 由于每个代表都由仅包含其值的窗口唯一标识，因此相等性检查变得一致且具有传递性，从而确保每个咖啡馆都准确地分配给一个类。 因此，最后维护的代表数量等于隐藏数组中不同值的数量。 

## Python 解决方案```python
import sys

input = sys.stdin.readline
print = sys.stdout.write

def query(x):
    print(f"? {x}\n")
    sys.stdout.flush()
    return input().strip()

def reset():
    print("R\n")
    sys.stdout.flush()

def main():
    n, k = map(int, input().split())

    reps = []

    # We will store one representative per discovered value
    for i in range(1, n + 1):
        found = False

        for r in reps:
            reset()

            # build memory: insert r k times
            for _ in range(k):
                query(r)

            # now test i in this controlled environment
            reset()
            for _ in range(k):
                query(r)

            ans = query(i)
            if ans == 'Y':
                found = True
                break

        if not found:
            reps.append(i)

    print(f"! {len(reps)}\n")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```该实现是围绕严格的重置分离交互块构建的。 辅助函数隔离查询和重置逻辑，以便刷新和格式化保持一致，这在交互问题中至关重要。 

代表性循环确保我们永远不会依赖不稳定的内存状态。 每次比较都会从头开始重建环境。 双重置模式可确保候选检查之间不会发生残余状态泄漏，这是此类问题中错误答案的最常见来源。

 ## 边缘情况

 临界边缘情况是当相同的值在数组中出现相距很远时，因此它的出现落在内存窗口之外。 在这种情况下，不进行重置的简单方法可能会多次错误地将同一值分类为新值。 基于重置的构造通过确保在新构造的内存状态下执行每个相等检查来防止这种情况，因此原始数组中的距离是无关紧要的。 

另一个边缘情况是当$k = 1$。 这里，内存仅包含最后一个查询的元素，因此任何重复的值在插入受控窗口后都必须立即进行比较。 该算法的每次测试前重置结构保证了正确性，因为它从不依赖于历史持久性。 

最后一个边缘情况是对抗性自适应行为。 由于数组可以依赖于查询，因此任何假设固定隐藏结构的策略都会失败。 重置隔离确保每个决策都是从一致的本地视图做出的，从而使自适应更改与之前完成的比较无关。
