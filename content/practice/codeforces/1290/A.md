 ## 解决方案
 ## 问题理解

 我们得到一个数字数组和一排人，他们将一个一个地从数组中删除元素。 当轮到每个人时，他们会看到当前的数组并获取最左边或最右边的元素。 获取一个元素后，该人将永远离开该过程。 

你坐在位置上$m$在这一行中，所以轮到你恰好在$m-1$拆除工作已经发生。 在任何事情开始之前，您可以“锁定”最多$k$人们：对于每个被选中的人，你强迫他们总是选择左端或右端，无论什么对他们来说是最佳的。 

所有其他人都表现得敌对，并且可能在每一步中以对你最不利的方式选择任一端。 

您的目标不是直接最大化您选择的值，而是最大化保证的下限。 我们想要最大的价值$x$这样，无论人们的行为如何不受控制，您最终选择的元素始终至少是$x$。 

因此，核心困难不是预测一场比赛，而是确保在最坏情况的对手行为下的安全，同时允许“修复”最多$k$提前做出决定。 

约束的总规模较小，总规模$n$跨测试用例最多 3500 个。这立即表明$O(n^2)$甚至$O(n^3)$每个测试用例的动态编程解决方案可能是可以接受的，但任何指数或涉及所有策略的重复模拟的解决方案都是不可接受的。 

当你假设人们行为贪婪时，幼稚推理的一个微妙的失败案例就会出现。 例如，如果您认为对手总是采取较大的一方，那么这是不正确的：他们会积极尝试减少您的最终结果，这可能意味着尽早牺牲大量价值以迫使稍后采用更糟糕的结构。 

另一个常见的陷阱是对待你的职位$m$作为静态。 实际上，每次删除都会移动剩余的数组并改变您将看到的内容，因此问题在于删除时间隔的演变。 

## 方法

 暴力方法会模拟不受控制的玩家的所有可能的决定，同时也会尝试所有选择的方法$k$固定玩家并为每个固定玩家分配一个方向。 对于每种配置，我们都会模拟整个游戏并记录您获得的值。 

这很快就变得不可行。 即使没有控制决策，每个$m-1$对手可以选择向左或向右，从而导致$2^{m-1}$的可能性。 添加选择哪个$k$除此之外，玩家控制还引入了组合爆炸。 

关键的观察是，唯一重要的是当轮到你时，数组中仍然可以包含你的答案的部分。 每个较早的玩家都会将当前的间隔大小减少一倍，并且每次移动都是从左或右进行。 所以之后$m-1$移动，你的位置总是一些子数组$[L, R]$长度$n-(m-1)$，但确切的子数组完全取决于左/右选择的顺序。 

控制玩家可以消除此序列中某个步骤的不确定性。 如果我们将这个过程视为一个序列$m-1$二元决策，我们可以修正$k$其中。 其余$m-1-k$决策是对抗性的。 

现在关键的转变是反转视角：我们不是向前模拟，而是问在最坏情况下，哪些值仍然可以被强制进入最终区间。 您可以确保的最佳保证是通过选择窗口大小来确定的$m$最多可以通过修复来“保护”免受对抗性删除$k$移动到它之外。 

这导致了滑动窗口风格的想法。 对于每个可以存活到轮到你的候选区间，我们询问是否可以确保最多$k$删除以保留边界的方式影响其边界。 对于固定的目标间隔，保护它的成本正是需要阻止对手将其缩小到超过该间隔的次数。 

这将问题简化为检查每个可能的长度段$m$，有多少“坏举动”就会毁掉它。 然后，在保护成本最多为的约束下，选择最小元素最大化的段$k$。 

更有效的看待这一点的方法是：您的最终选择始终是某个区间内能够承受对抗性修剪的最佳（最大）或最差（最小）可到达元素。 由于对手会最小化您的结果，因此他们会有效地尝试强制您的时间间隔排除大值。 您的控制权允许您阻止最多$k$此类排除。 

因此，我们减少评估，对于您的位置周围的每个可能的窗口，在允许最多的情况下可实现的最佳最坏情况值$k$对强制删除的“更正”。 这可以计算为$O(n)$每个测试用例通过扫描和维护必须从左侧或右侧排除多少个元素来强制给定候选最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(2^{n})$|$O(n)$| 太慢了|
 | 滑动窗口+可行性检查|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题重新表述为检查哪些值可以保证作为最终结果。 我们不直接模拟游戏，而是假设一个候选答案$x$并测试我们是否可以确保每个元素都小于$x$在轮到我们之前就被删除了，除了最多可控数量的对抗性决策。 

1. 按值阈值对元素进行排序或隐式考虑。 我们将问题视为确定以下所有元素是否$x$可以强制退出轮到我们之前的时间间隔，除非我们无法控制。 
2. 固定阈值$x$如果元素小于，则将其分类为“坏”$x$。 游戏变成了一个问题，即对手是否能够确保至少有一个坏元素能够进入你的最后一段。 
3. 根据可能轮到您的任何时间间隔内剩余多少坏元素来模拟该过程。 我们维护一个滑动窗口，表示之后可以保留的段$m-1$搬迁。 
4. 计算从最终间隔中消除所有坏元素所需的最小强制删除次数。 每当一个坏元素出现在可能间隔的末端时，对手就可以选择保留它，除非我们控制该移动。 
5. 统计一下相对于你的职位的前缀和后缀中存在多少这样的“不良保存机会”。 每一个不受控制的机会都对应着一个对抗性的选择，这可能会导致不良因素继续发挥作用。 
6. 如果这样的机会最多有$k$，然后阈值$x$是可以实现的。 否则就不是。 
7. 二分查找结束$x$使用可行性检查，取最大有效值。 

### 为什么它有效

 关键的不变量是每个偏差都可以保持低于$x$对应于移除序列中的单个二元决策点。 每个此类决定只能通过修复一名玩家的行为来抵消。 因此，可行性仅取决于有害决策点的数量是否最多为$k$，与确切的顺序无关。 这将游戏从指数决策树简化为关键选择的线性计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, m, k, a):
    lo, hi = 1, max(a)
    
    def can(x):
        # We try to ensure all elements < x can be avoided in our path
        bad = [1 if v < x else 0 for v in a]
        
        # prefix and suffix counts simulate worst-case survival pressure
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + bad[i]
        
        total_bad = prefix[n]
        
        # If there are too many bad elements overall, we rely on control
        # We check worst-case window that reaches position m
        # left part: m-1 moves before us, right part: remaining
        
        left_bad = prefix[m - 1]
        right_bad = total_bad - left_bad
        
        # In worst case, adversary can preserve bad elements from both sides
        # We need to "fix" enough decisions to prevent their survival
        # Each control removes one harmful choice
        return min(left_bad, right_bad) <= k
    
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(mid):
            lo = mid
        else:
            hi = mid - 1
    
    return lo

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        out.append(str(solve_case(n, m, k, a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该代码对答案使用二分搜索，因为实现阈值的可行性$x$是单调的：如果你能保证$x$，那么你可以保证任何较小的值。 

在可行性检查中，我们将数组转换为相对于$x$。 然后，我们使用前缀和来计算您的位置之前和之后有多少“坏”元素。 这个想法是，只有这些区域对于对抗性选择是否能让坏分子继续生存直到轮到你来说很重要。 

检查将游戏简化为计数问题：如果不受控制的决策可以保留太多坏元素，我们就会失败。 否则，我们最多能成功$k$被迫的决定。

 输入：```

 | ---| ---| ---| ---|
 | x=8 | 3 (2,2,3) | 3 (2,2,3) | 1 (5) | 1 (5) | 可行|

 为了$x = 9$，更多的结构变得至关重要。 

| 步骤| m-1 前缀坏 (<9) | 后缀坏| 决定|
 | ---| ---| ---| ---|
 | x=9 | 3 | 2 | 不可行|

 所以答案是$8$。 这证实了我们正在平衡在轮到你之前可以迫使多少小元素离开。

 ## 边缘情况

 一个关键的边缘情况是当$m = 1$，意味着您立即移动。 在这种情况下，不存在前缀，只有后缀行为很重要。 该算法正确地简化为检查在控制极限下是否可以在右侧消除足够的小元素。 

另一个边缘情况是$k = 0$，其中没有可用的控制。 可行性检查变得纯粹是对抗性的，答案归结为纯粹从强制最坏情况拆除中可以生存的东西。 该实施仍然有效，因为它将所有不良因素都视为无法控制的压力。 

当所有元素都相等时，每个阈值$x$要么包含全部数组，要么不包含任何数组。 二分搜索正确返回该值，因为可行性从不依赖于结构，只依赖于在分割之间保持一致的计数。
