 ## 解决方案
 ## 问题理解

 我们需要建立一个无向图`n`不存在三角形的城市。 三角形表示三个不同的城市，每对城市都直接相连。 在所有没有 3 循环的图中，我们想要具有最大可能道路数的图，并且我们还必须打印一个有效的构造。 

输入仅包含城市数量。 输出必须首先打印最大道路数，然后列出每条道路。 

界限`n ≤ 100`足够小，几乎任何多项式时间构造都可以顺利进行。 甚至一个`O(n^3)`验证步骤就可以了，因为`100^3 = 1,000,000`运营。 真正的挑战不是性能，而是发现最大化边数同时避免三角形的极值图结构。 

一个常见的错误是在检查三角形是否出现时试图贪婪地添加边。 这种方法可能会陷入非全局最优的局部最优配置。 

例如，假设`n = 4`。 

粗心的贪婪构造可能会构建：```
1-2
2-3
3-4
```该图只有 3 条边。 但最佳答案是 4 条边：```
1-3
1-4
2-3
2-4
```这是一个带有分区的完整二部图`{1,2}`和`{3,4}`。 

另一个微妙的情况很奇怪`n`。 

为了`n = 5`，分成相等的两半是不可能的。 如果我们选择大小的分区`2`和`3`，边数变为`2 × 3 = 6`。 

有缺陷的实现可能会错误地尝试分区`1`和`4`，仅产生 4 条边。 最佳分区大小必须尽可能平衡。 

最小的案例也很重要。 

为了`n = 1`，该图没有边。 

为了`n = 2`，恰好有一条边是可能的。 

盲目连接两个分区上的所有对的结构仍必须正确处理空分区。 

## 方法

 蛮力的想法很简单。 考虑每个可能的边子集`n(n-1)/2`候选边，测试图是否包含三角形，并保留最大的有效图。 

这是可行的，因为定义是明确的：我们只需要拒绝包含任何 3 周期的图。 三角形检测本身可以在`O(n^3)`通过检查每个三重顶点。 

问题是图表的数量。 有`2^(n(n-1)/2)`可能的无向图。 即使是为了`n = 20`，这变得天文数字般大。 穷举搜索是完全不可能的。 

一个更合理的贪心想法是一条一条地添加边，同时避免三角形。 这仍然不能保证最优性，因为局部决策可能会阻塞未来的边缘。 

关键观察是经典的极值图结果：具有最大边数的无三角形图始终是完整的二分图，并且两部分尽可能平衡。 

为什么两党在这里很重要？ 任何三角形都需要三个顶点，每对顶点都相互连接。 在二分图中，顶点分为两组，边仅穿过组。 三角形需要来自同一组的两个顶点，但不存在同一组边。 所以二分图自动是无三角形的。 

在二分图中，如果一个分区有大小`a`另一个有尺寸`b`，那么每个交叉对都可以连接，给出`a × b`边缘。 

自从`a + b = n`，产品`a × b`当两个值尽可能接近时最大化。 所以最佳分区大小是：```
⌊n/2⌋ and ⌈n/2⌉
```然后我们简单地将第一部分的每个顶点连接到第二部分的每个顶点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(n2) · n3) | O(2^(n2) · n3) | O(n²) | 太慢了 |
 | 最佳 | O(n²) | O(1) 不包括输出 | 已接受 |

 ## 算法演练

 1.读取数值`n`。 
2. 将顶点尽可能均匀地分成两组。 

让：```
left = n // 2
right = n - left
```第一组将包含顶点`1...left`，第二组将包含顶点`left+1...n`。 
3. 创建一个空的边列表。 
4. 对于每个顶点`i`在第一组中，将其连接到每个顶点`j`在第二组中。 

这将创建一个完整的二分图。 
5. 打印边数。 
6. 打印每个存储的边缘。 

### 为什么它有效

 该图是二分图，因此同一分区内的顶点之间不存在边。 任何三角形都需要至少一条这样的边，这是不可能的。 因此该构造始终是无三角形的。 

现在考虑边数。 如果分区大小是`a`和`b`，该图包含`a × b`边缘。 自从`a + b = n`，当两个数字尽可能平衡时，该乘积最大化。 我们的构造正是使用这些分区大小，因此没有三角形的图可以包含更多的边。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

left = n // 2

edges = []

for i in range(1, left + 1):
    for j in range(left + 1, n + 1):
        edges.append((i, j))

print(len(edges))

for u, v in edges:
    print(u, v)
```代码直接实现了构造性证明。 

变量`left`存储第一个分区的大小。 第二个分区自动包含剩余的顶点。 

嵌套循环生成两个分区之间的每个交叉边。 由于每对都只添加一次，因此不会出现重复的边。 

顶点范围经过精心选择，以避免相差一的错误。 第一个分区是：```
1 ... left
```第二个分区是：```
left + 1 ... n
```这对于偶数和奇数都正确`n`。 

例如，当`n = 5`：```
left = 2
first group  = {1, 2}
second group = {3, 4, 5}
```所有六个交叉边均已添加。 

内存使用量很小，因为最多`2500`边存在时`n = 100`。

import sys
import io

def solve():
    input = sys.stdin.readline

    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

 ## 边缘情况

 考虑尽可能最小的输入：```
1
```该算法计算：```
left = 0
```所以第一个分区是空的，第二个分区包含顶点`1`。 嵌套循环永远不会执行，产生零边：```
0
```这是正确的，因为不可能存在道路。 

现在考虑：```
2
```分区变为：```
{1}
{2}
```该算法恰好添加一条边：```
1 2
```不存在只有两个顶点的三角形。 

奇数大小的情况更加微妙：```
5
```分区变成大小`2`和`3`。 该算法生成`2 × 3 = 6`边缘。 

使用分区的有缺陷的实现`1`和`4`只会产生 4 条边：```
1-2
1-3
1-4
1-5
```该图是无三角形的，但不是最大的。 平衡分割对于最大化产品是必要的。 

最后，考虑：```
6
```分区完美平衡：```
{1,2,3}
{4,5,6}
```该图包含`3 × 3 = 9`边缘。 任何在任一分区内添加边的尝试都会立即创建一个三角形。 

例如，添加边缘`(1,2)`创建：```
1-2-4-1
```因为两者`1`和`2`已经连接到`4`。 这证实了为什么完整的二分结构是最大的。
