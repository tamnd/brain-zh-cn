 ## 解决方案
 ## 问题理解

 我们有一支英雄小队，每个人都有固定的实力。 对于每条龙，我们必须选择一个英雄来对抗它，而所有剩余的英雄都留在后面保卫城堡。 

龙有两个要求。 选择的攻击者必须至少有实力`x`，并且所有防御者的总力量必须至少为`y`。 

我们可以花费金币来增强英雄的实力。 每一点力量都需要花费一枚硬币，并且升级是暂时的，因为每条龙都是独立处理的。 

对于每条龙，我们必须确定所需的最小金币数量，以便某些英雄能够满足攻击要求，而其余英雄满足防御要求。 

这些限制立即排除了任何针对每条龙检查每个英雄的解决方案。 两个都`n`和`m`可以达到`2 · 10^5`，所以一个`O(nm)`算法将大致执行`4 · 10^10`操作，这远远超出了两秒的限制。 

英雄的力量可以大到`10^12`，防御要求可以大到`10^18`。 这意味着我们必须使用 64 位整数运算。 Python 会自动处理这个问题。 

一些边缘情况很容易被错误处理。 

考虑：```
Heroes: [10]
Dragon: x = 5, y = 100
```攻击者已经满足了攻击要求，但是一旦该英雄离开，防御者就有力量了`0`。 答案是`100`， 不是`0`。 只关注攻击英雄会产生错误的结果。 

考虑：```
Heroes: [5, 100]
Dragon: x = 50, y = 5
```选择最强的英雄似乎很有吸引力，因为不需要攻击升级。 但防守者有实力`5`，这已经足够了。 成本是`0`。 

如果我们选择英雄`5`，我们需要`45`硬币达到攻击力`50`。 攻击者的选择很重要。 

另一个微妙的情况：```
Heroes: [4, 8]
Dragon: x = 6, y = 100
```选择英雄`8`费用：```
attack = 0
defense = 100 - 4 = 96
total = 96
```选择英雄`4`费用：```
attack = 6 - 4 = 2
defense = 100 - 8 = 92
total = 94
```最接近的英雄`x`并不总是最佳的。 有时，为攻击者支付更多费用足以改善防御者的水平，从而降低总成本。 

这些例子表明我们必须仔细评估哪个英雄成为攻击者。 

## 方法

 蛮力的想法很简单。 对于每条龙，尝试每一个英雄作为攻击者。 

假设英雄强度为`a[i]`所有英雄的总实力为`S`。 

如果该英雄发起攻击，则防御者会做出贡献`S - a[i]`。 

攻击要求成本：```
max(0, x - a[i])
```防御要求费用：```
max(0, y - (S - a[i]))
```总成本是这两个值的总和。 

检查每个英雄都会给出正确的答案，因为它明确评估所有可能的攻击者并采取最小值。 不幸的是，每个查询都需要`O(n)`工作。 和`2 · 10^5`英雄和`2 · 10^5`龙，这大致变成`4 · 10^10`评价。 

关键的观察结果是成本函数以非常结构化的方式变化。 

让英雄有力量`h`。 

攻击贡献为：```
max(0, x - h)
```作为`h`增加，该数量减少。 

防御贡献为：```
max(0, y - (S - h))
```这相当于：```
max(0, y - S + h)
```作为`h`增加，这个数量就会增加。 

一部分人喜欢较大的英雄，另一部分人则喜欢较小的英雄。 

这意味着最佳值出现在攻击要求从不满足变为满足的点附近，即围绕强度`x`。 

对英雄进行排序后，我们可以二分查找第一个强度至少为`x`。 

任何比它小得多的英雄`x`需要额外的攻击币。 任何比这个大得多的英雄`x`不必要地削弱了防守者。 最小值只能发生在距离最近的英雄中`x`。 

具体来说，我们只需要检查：

 1、实力至少第一的英雄`x`。 
2. 紧邻它之前的英雄。 

这些是唯一能够击败所有其他候选人的候选人。 

每个查询变成一次二分搜索和两次评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n log n + m log n) | O(n log n + m log n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1.读取所有英雄的实力并计算他们的总实力`S`。 
2.对英雄实力进行排序。 

排序允许对英雄的优势进行二分搜索。 
3. 对于每条龙`(x, y)`, 找到第一个强度至少为`x`。 

使用二分查找（`bisect_left`）。 
4. 如果存在这样的英雄，则评估使用该英雄作为攻击者。 

攻击要求已经成立，因此攻击成本可能为零。 防御成本为：```
max(0, y - (S - hero))
```5. 如果二分查找位置之前有英雄，则也评估该英雄。 

这个英雄是下面最强的英雄`x`。 它可能需要攻击升级：```
max(0, x - hero)
```加上任何防御升级。 
6. 在被评价的候选人中取成本最小的。 
7. 输出查询的答案。 

### 为什么它有效

 让进攻的英雄有力量`h`。 

成本是```
f(h) =
max(0, x - h)
+
max(0, y - (S - h))
```第一项减少为`h`增加。 第二项增加为`h`增加。 

对于下面的英雄`x`，移动到更大的英雄永远不会增加第一项，只能逐渐增加第二项。 下面最好的英雄`x`是下面最大的一个`x`。 

至少对于英雄来说`x`，第一项变为零。 在这样的英雄中，选择体型更大的英雄只会削弱防守者，而无济于事。 至少是最好的英雄`x`至少是最小的一个`x`。 

经过排序，这两个英雄正是前任和后继者`x`在已排序的数组中。 其他所有英雄都被这些候选者之一所支配，因此仅检查这两种可能性总是能找到最佳选择。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()
total = sum(a)

m = int(input())

for _ in range(m):
    x, y = map(int, input().split())

    pos = bisect_left(a, x)
    ans = 10**30

    if pos < n:
        hero = a[pos]
        cost = max(0, y - (total - hero))
        ans = min(ans, cost)

    if pos > 0:
        hero = a[pos - 1]
        cost = max(0, x - hero) + max(0, y - (total - hero))
        ans = min(ans, cost)

    print(ans)
```第一部分对英雄进行排序并计算他们的总实力。 每个查询都会重复使用总数，从而可以立即计算防守者的实力：`total - hero`。 

对于每条龙来说，`bisect_left`找到第一个力量至少达到所需攻击值的英雄。 该英雄是无需攻击升级即可战斗的最小英雄。 

前任也被检查，因为它是门槛以下的最强英雄。 任何较弱的英雄都需要更多的攻击升级，同时无法提供补偿优势。 

最初的答案设置为一个非常大的数字。 每个有效的候选人都会更新它。 

一个常见的错误是忘记防守者的力量排除了进攻英雄。 正确的防守力量是`total - hero`， 不是`total`。 

另一个常见的错误是只检查二分查找结果而忽略前一个结果。 几个最优解需要选择稍微下面的英雄`x`因为更强的防守者总体上可以节省更多的金币。

4

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n + m log n) | O(n log n + m log n) | 排序一次，然后每个查询进行一次二分搜索 |
 | 空间| O(1) 额外 | 除了英雄阵列本身之外 |

 排序阶段成本`O(n log n)`。 每个龙查询执行二分搜索并评估最多两个候选者，因此它的成本`O(log n)`。 

和`n, m ≤ 2 · 10^5`，这很容易符合限制。

 ## 边缘情况

 考虑：```
2
5 100
1
50 5
```排序后的数组是`[5, 100]`，总强度为`105`。 

二分查找找到英雄`100`。 

为了英雄`100`:```
attack cost = 0
defense cost = max(0, 5 - 5) = 0
total = 0
```为了英雄`5`:```
attack cost = 45
defense cost = 0
total = 45
```算法返回`0`，正确选择更强的英雄。 

现在考虑：```
2
4 8
1
6 100
```总强度为`12`。 

为了英雄`8`:```
0 + (100 - 4) = 96
```为了英雄`4`:```
(6 - 4) + (100 - 8) = 94
```该算法检查相邻候选者并返回`94`。 任何至少只选择最小英雄的解决方案`x`会错误输出`96`。 

最后，考虑：```
2
10 20
1
5 100
```两位英雄都已经满足了攻击要求。 二分查找指向英雄`10`。 

为了英雄`10`:```
attack cost = 0
defense cost = 80
```为了英雄`20`:```
attack cost = 0
defense cost = 90
```该算法选择较小的合格英雄，因为它留下了更多的力量来保卫城堡。 这也正是为什么继任者候选人至少是最小的英雄`x`，不是任意合格的英雄。
