 ## 解决方案
 ## 问题理解

 我们得到一个整数序列。 我们的目标是将该序列拆分为最少数量的子序列，其中每个子序列“值连续”。 也就是说，在一个子序列中，每个相邻的对正好相差一。 

例如，如果我们有`[3, 4, 3, 2]`，一个有效的子序列可以是`[3, 4, 3, 2]`因为每一步变化±1，但是`[3, 3, 4]`无效，因为`3`到`3`相差0。 

每个测试用例的输出只是满足此属性的子序列的最小数量。 原始序列中的每个整数必须恰好出现在一个子序列中。 

约束允许最多`10^6`所有测试用例的元素总数。 这排除了任何二次解`n`， 因为`10^12`需要进行操作。 因此，我们需要一种线性或线性算术方法。 

一个不明显的边缘情况是具有重复元素的序列。 例如，`[2, 2, 2]`不可能全部都在一个子序列中，因为`2-2=0`。 每个`2`必须开始一个新的子序列。 同样，在值中“跳跃”的序列，例如`[1, 3, 2, 3, 2]`，需要仔细计数：从左到右的天真贪婪合并可能会产生不必要的子序列。 

## 方法

 暴力方法将尝试生成满足连续差异属性的所有可能的子序列，然后选择最小覆盖。 这显然是不可行的，因为有多种方法可以选择子序列。 即使是没有适当簿记的贪婪的从左到右分配也可能会失败，因为您可能会留下一个可能已合并到以后的子序列中的元素。 例如，`[3, 2, 3]`从左到右贪婪地可能会创建三个子序列而不是一个。 

关键的见解是根据频率和联系而不是顺序来思考。 对于每个整数`x`，如果您知道当前有多少个子序列结束于`x-1`，您可以附加`x`给其中之一。 如果不存在，则必须在以下位置开始一个新的子序列`x`。 这将问题简化为计算以每个数字结尾的“开放子序列”。 

我们可以通过字典（或数组）将整数值映射到以该数字结尾的子序列的计数来有效地实现这一点。 对于每个数字，迭代序列`x`检查是否存在结尾为的开子序列`x-1`。 有的话附上`x`到它（减少计数`x-1`，增量计数`x`）。 否则，开始一个新的子序列`x`。 处理后，所有计数的总和就是子序列的总数。 这是有效的，因为每个数字要么延续前一个链，要么开始一个新链，并且贪婪地选择附加到`x-1`确保最小的子序列。

 ## 算法演练

 1.初始化一个计数器`end_count`它将整数映射到当前有多少个子序列以该值结尾。 
2. 迭代每个元素`x`以任意顺序排列。 对于每个`x`，检查是否`end_count[x-1] > 0`。 
3. 如果子序列结束于`x-1`存在，递减`end_count[x-1]`并增加`end_count[x]`。 这有效地附着`x`到那个后续。 
4. 如果没有子序列结束于`x-1`, 增量`end_count[x]`开始一个新的子序列。 
5.处理完所有元素后，将其中所有值相加`end_count`是子序列的最小数量。 每个计数代表以该数字结尾的子序列。 

为什么它有效：每个元素要么扩展现有的子序列，要么开始一个新的子序列。 附加到`x-1`贪婪地确保我们永远不会留下一个可以继续孤立序列的数字。 重复的元素自然会创建新的子序列，因为`x-1`可能有零个可用端。 不变的是`end_count`始终跟踪当前的“开放链”，我们从不错过任何合并的机会。 

## Python 解决方案```python
import sys
from collections import defaultdict
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        end_count = defaultdict(int)
        for x in a:
            if end_count[x - 1] > 0:
                end_count[x - 1] -= 1
            end_count[x] += 1
        print(sum(end_count.values()))

if __name__ == "__main__":
    solve()
```该解决方案使用`defaultdict(int)`以避免检查密钥是否存在。 对于每个数字，我们检查它是否可以附加到以`x-1`。 如果是，则递减该子序列并递增`x`。 否则，开始一个新的子序列。 最终总和为`end_count.values()`给出子序列的最小数量。
