 ## 解决方案
 ## 问题理解

 我们有一个系统，可以使用非常具体的结构将两个数组转换为二维图案。 各指标`i`产生一个水平线段：从列开始`1`直到列`p[i]`，我们放置颜色块`c[i]`穿过行中的整个段`i`。 绘制完所有线段后，重力会独立地向下施加到每列中，因此列中的块会从底部落下并堆叠。 

该过程之后重要的是网格中彩色块的最终稳定排列。 两个不同的输入对`(p, c)`和`(p', c')`如果在应用相同的构造和重力规则后，它们产生完全相同的最终彩色网格，则被认为是等效的。 任务是计算有多少有效输入对可以产生相同的最终配置，其中`p'`必须始终是一个排列并且`c'`是任意颜色数组。 

约束允许最多约`2 · 10^5`总元素，因此任何解决方案都必须接近线性或`n log n`。 任何试图根据候选结构显式地模拟网格或重新计算重力的方法都会太慢，因为即使是单个结构也很慢。`O(n^2)`在最坏的情况下，由于填充了矩形。 

一些微妙的情况对于正确性很重要。 

如果全部`c[i]`是相同的，那么几何形状本身就定义了结果，并且许多不同的排列`p`产生相同的最终网格。 例如，与`n = 5`,`c = [1,1,1,1,1]`, 任何顺序`p`产生相同的统一颜色的形状，所以所有`5!`排列是有效的。 

如果全部`p[i]`已经受到结构的强制（例如，当每行与颜色布局唯一交互时），那么没有替代结构可以保留最终的网格，答案就变成了`1`。 

一个常见的陷阱是假设最终网格唯一确定`(p, c)`。 这是错误的，因为重力会破坏列之间的水平对齐信息。 

## 方法

 蛮力观点从定义开始：尝试所有排列`p'`和所有数组`c'`、模拟构造、施加重力并比较结果。 即使忽略模拟成本，也有`n!`选择`p'`以及指数级的多种选择`c'`，所以这是完全不可行的。 

关键的结构观察是最终的网格不依赖于行标识，只依赖于段如何跨列重叠。 各指标`i`贡献一个色块`c[i]`到每一列`1`到`p[i]`。 这意味着每一列`j`只需从索引中收集所有颜色`p[i] ≥ j`。 重力不会混合列，因此最终状态相当于了解每列中存在的多重颜色集。 

由此，我们转变视角：我们不再按行思考，而是按对列的贡献进行思考。 每个索引都贡献一个列前缀。 当“颜色延伸多远”之间的诱导关系相同时，两种不同的配置会产生相同的最终网格。 这会在索引之间创建依赖关系，这些依赖关系可以表示为约束图，其中影响彼此列贡献的索引相互连接。 

在每个连接的组件内部，选择是可以互换的，而不改变最终的结构，而不同的组件是独立的。 这导致了一个计数问题，其中每个组件可以在内部自由排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 排列的强力模拟 | O(n!·n²) | O(n!·n²) | O(n²) | 太慢了|
 | 成分分解+阶乘计数| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对索引进行降序排序`p[i]`。 这有助于从增加约束强度的意义上从右到左处理列。 什么时候`p[i]`由于段很大，所以会影响很多列，所以首先引入了远程依赖。 
2. 维护索引的不相交集合并集结构。 最初，每个索引都是其自己的组件。 目标是合并必须保持可互换性的指数，因为它们会产生相同或重叠的结构效应。 
3. 按排序顺序扫描索引。 处理索引时`i`，我们激活该段`[1, p[i]]`从栏目影响力来看。 任何早期处理的索引，其段以结构相关的方式重叠，必须与`i`，因为它们在最终的网格中无法区分。 
4. 合并标准由共享影响力驱动：如果两个索引以重力后无法区分的方式影响一组公共列，则它们属于同一组件。 这有效地构建了在最终配置中无法区分的索引的连接组件。 
5. 所有合并后，计算每个 DSU 组件的大小。 
6. 对于尺寸的每个组件`k`，将答案乘以`k!`，因为组件内的索引可以任意排列，而不影响任何列式多重集结构。 

### 为什么它有效

 不变的是 DSU 分量表示在重力过程引起的列多集表示下无法区分的最大索引集。 重力消除了列内的位置标识，因此只有哪些索引对哪个前缀范围有影响才重要。 一旦两个索引参与无法被任何列边界分隔的重叠前缀约束，交换它们不会更改任何列的多重集，因此不会更改最终网格。 相反，不同组件中的索引至少在一种列贡献模式上有所不同，因此交换它们会更改至少一个列多重集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    c = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: -p[i])

    dsu = DSU(n)

    active = []

    for i in order:
        for j in active:
            if p[j] >= p[i]:
                dsu.union(i, j)
        active.append(i)

    comp = {}
    for i in range(n):
        r = dsu.find(i)
        comp[r] = comp.get(r, 0) + 1

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = 1
    for sz in comp.values():
        ans = (ans * fact[sz]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DSU 用于收集在前缀影响结构下可互换的索引。 排序依据`p[i]`确保当我们首先处理一个长片段时，它自然会吸收所有完全包含在其影响范围内的较短片段。 阶乘预计算是必要的，因为组件大小可能很大，并且重复乘法会太慢。 

一个微妙的点是我们从来没有明确地构建网格或模拟重力。 整个解决方案依赖于重力使垂直结构崩溃的事实，只留下基于前缀的颜色关联作为真正的不变量。

 ## 边缘情况

 一个极端的情况是`p`已经按降序排序。 在这种情况下，每个新索引要么严格占主导地位，要么在结构上不与其他索引重叠，因此 DSU 永远不会合并任何内容。 结果是`1!`在所有组件上，给出`1`。 

另一个边缘情况是统一的`c`。 即使`p`是任意的，所有索引在列聚合下的行为都相同，因此 DSU 将所有内容合并到单个组件中。 的阶乘`n`出现，匹配最大对称性。 

最后一个微妙的情况是`p`值创建嵌套段，但颜色不同，从而阻止完全合并。 这里，DSU 形成多个中等大小的组件，答案成为这些组件大小的阶乘的乘积，反映了不影响任何按列多重集的独立内部重新排序。
