 ## 解决方案
 ## 问题理解

 我们有`n`纪念品。 每件纪念品必须恰好分配给两个朋友中的一个。 如果留念`i`转到第一个朋友，它有贡献`a_i`第一个朋友幸福，第二个朋友什么也没有。 如果它传给了第二个朋友，则价值会发生相反的情况`b_i`。 

我们的目标不仅仅是找到一种最佳发行版。 我们需要第一个`2^min(n,20)`按两个朋友的总幸福感之间的绝对差排序时的分布。 

差异可以用更简单的方式写出来。 对于每件纪念品，定义：`d_i = a_i - b_i`选择第一个朋友添加`d_i`到最后的差别。 选择第二个朋友会添加`-d_i`。 最终的绝对差是所有的有符号和的绝对值`d_i`。 

输入大小足够小`n`达到 40，但可能的分布数量最多为`2^40`，大约是一万亿。 枚举每个分布的解决方案是不可能的，因为即使是数十亿次操作也已经远远超出了典型的竞赛时间限制。 

输出大小故意很大。 什么时候`n`是 40，我们必须打印`2^20`值，大约一百万个答案。 这告诉我们围绕`O(2^20 log 2^20)`是现实的，而任何接近的东西`O(2^n)`不是。 

在某些情况下，仅找到最小差异的实现会失败。 例如：```
Input
2
-1 10
-1 10

Output
9 9 11 11
```粗心的解决方案可能会找到最小值`9`并停止。 该任务需要四个最佳分布，包括重复值。 

另一个常见的错误是忘记这些迹象可能是负面的。 考虑：```
Input
1
-5
10

Output
15 15
```两种选择产生差异`|-5 - 10| = 15`和`|10 - (-5)| = 15`。 将价值观始终视为积极的会改变答案。 

最后一个棘手的情况是有许多相同的答案。 在：```
Input
4
1 2 3 4
4 3 2 1
```许多不同的作业给出相同的最小差异。 输出需要所有这些副本，而不仅仅是唯一值。 

## 方法

 直接的方法是生成所有可能的纪念品分配。 对于每个分配，我们计算`d_i`值，取其绝对值，收集所有结果，并对它们进行排序。 

这是正确的，因为每种可能的分布都恰好对应于一种符号选择。 然而，有 40 件纪念品`2^40`的可能性。 即使存储这些值也是不可能的，对它们进行排序将需要大约一万亿个元素。 

有用的观察是答案只要求第一个`2^20`价值观。 我们可以把纪念品分成两半。 每一半最多有 20 个项目，因此我们可以生成一半内的每个带符号和。 这将创建两个最多的数组`2^20`价值观。 

现在每个完整的分布都表示为：`left_sum + right_sum`问题变成找到两个数组中所有对中的最小绝对值。 

关键是两个数组都可以排序。 对于一个值`x`在第一个数组中，第二个数组中的最佳搭档接近`-x`。 因为第二个数组已排序，所以第一个数组的所有候选者`x`可以通过从位置向外扩展来以增加的绝对值产生`-x`将被插入。 

我们将这些排序的候选流与优先级队列合并。 最初，左半部分的每一笔钱都会贡献其最好的合作伙伴。 每次我们删除当前最小的答案时，我们只会将该流推进到下一个候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 中间相遇+堆| O(2^(n/2) log 2^(n/2)) | O(2^(n/2) log 2^(n/2)) | O(2^(n/2)) | O(2^(n/2)) | 已接受 |

 ## 算法演练

 1. 计算`d_i = a_i - b_i`每一份纪念品。 最终的幸福差异是这些值的所选有符号版本之和的绝对值。 
2. 将差异数组分成两部分。 每个部分最多有 20 个元素，因此可以生成一个部分内的每个可能的有符号和。 
3. 对后半部分的总和列表进行排序。 我们将使用此排序来快速找到最接近任何目标的值。 
4. 对于每一笔金额`x`从上半部分开始，找到插入位置`-x`在排序后的后半部分中。 该位置将产生负总数和正总数的值分开。 
5. 为每个创建两个可能的下一个候选者`x`：插入位置之前的值和插入位置处的值。 这些是最接近的可能性，因此它们是可以属于答案的第一个值。 
6. 将所有这些候选者按其绝对差值排序放入优先级队列中。 
7. 反复删除最小的候选者。 将其值添加到答案列表中。 然后将同一流在产生已删除候选者的一侧进一步移动一步。 

流移动起作用的原因是，对于固定的前半值，插入点左侧的后半值在向右移动时会变得更近，而右侧的值在向右移动时会变得更远。 两边都已经按绝对值排序了。 

为什么它有效：

 对于每个固定的左和，我们通过绝对最终差得到所有可能的右和的有序序列。 堆包含每个此类序列中最小的未使用元素。 优先级队列合并始终提取所有序列中最小的剩余元素，因此每个生成的答案都是下一个最小的可能分布。 由于每个分布恰好属于一对半和，因此不会错过任何候选。 

## Python 解决方案```python
import sys
import bisect
import heapq

input = sys.stdin.readline

def generate(vals):
    res = [0]
    for v in vals:
        res += [x + v for x in res]
        res += [x - v for x in res[:len(res)//2]]
    return res

def generate(vals):
    res = [0]
    for v in vals:
        cur = []
        for x in res:
            cur.append(x + v)
            cur.append(x - v)
        res = cur
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    diff = [a[i] - b[i] for i in range(n)]

    mid = n // 2
    left = generate(diff[:mid])
    right = generate(diff[mid:])

    right.sort()

    heap = []
    for i, x in enumerate(left):
        pos = bisect.bisect_left(right, -x)
        if pos < len(right):
            heap.append((abs(x + right[pos]), x + right[pos], i, pos, 1))
        if pos > 0:
            heap.append((abs(x + right[pos - 1]), x + right[pos - 1], i, pos - 1, -1))

    heapq.heapify(heap)

    need = 1 << min(n, 20)
    ans = []

    while len(ans) < need:
        _, value, i, j, direction = heapq.heappop(heap)
        ans.append(value if value >= 0 else -value)

        nj = j + direction
        if 0 <= nj < len(right):
            heapq.heappush(
                heap,
                (abs(left[i] + right[nj]), left[i] + right[nj], i, nj, direction)
            )

    print(*sorted(ans))

if __name__ == "__main__":
    solve()
```这`generate`函数构建所有带符号的和。 对于之前的每一笔金额，下一个纪念品都会产生两种可能性，增加或减少纪念品价值。 

后半部分已排序，因为二分搜索和有序扩展取决于该属性。 对于剩下的每一笔金额，`bisect_left`找到不小于的第一个后半值`-x`。 

堆存储每个左半部分中当前最佳未使用的候选者。 该元组包含用于排序的绝对值、实际有符号差以及在提取后推进同一流的足够信息。 

Python 整数是任意精度的，因此输入中的大值不需要特殊处理。 唯一微妙的边界条件是检查插入点的两侧，因为`-x`可能超出排序数组的范围。 

## 工作示例

 ### 示例 1

 输入：```
4
1 2 3 4
4 3 2 1
```差异是`[-3, -1, 1, 3]`。 

| 步骤| 堆动作| 当前答案值 |
 | ---| ---| ---|
 | 开始| 从每个左边的总和中插入最接近的候选者 | 空 |
 | 流行 | 最小绝对差为 0 | 0 |
 | 流行 | 另一对给出 0 | 0, 0 |
 | 继续 | 更多零组合出现 | 0, 0, 0, ... |

 此跟踪显示了为什么必须保留重复项。 几种不同的纪念品分发可以产生完全相同的差异。 

### 示例 2

 输入：```
2
-1 10
-1 10
```差异是`[0, 0]`。 

| 步骤| 堆动作| 当前答案值 |
 | ---| ---| ---|
 | 开始| 生成和 0 和 0 | 空 |
 | 流行 | 第一对给出 0+0 差值 0 | 0 |
 | 继续 | 还检查了剩余的对 | 0, 0, 0, 0 | 0, 0, 0, 0 |

 这表明带符号的变换可以自然地处理负幸福值。

 ## 边缘情况

 幸福值为负的情况是通过将每件纪念品转化为签名捐款来处理的。 为了：```
1
-5
10
```差值是`-15`。 两个可能的签名和是`-15`和`15`，所以两个答案都是`15`。 

具有许多相同答案的情况是有效的，因为堆单独存储每个可能的分布。 如果十次不同的分配产生相同的差异，则该值将在结果中插入十次。 

边界情况`-x`小于右半部分中的每个值时，仅使用插入点的右侧（如果存在）来处理。 同样，如果`-x`比每个值都大，只有左边有效。 这可以避免访问无效位置，同时仍然考虑最接近的候选者。
