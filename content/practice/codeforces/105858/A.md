 ## 解决方案
 # 问题理解

 我们得到一个非零整数数组。 我们需要选择一个子序列，这意味着我们保留一些元素的原始顺序并丢弃其余的。 所选元素必须具有交替的符号，因此每个正数必须后跟一个负数，每个负数必须后跟一个正数。 在所有这些子序列中，我们想要所选值的最大可能总和。 允许空子序列，因此答案可以为零。 

数组长度可以达到$10^5$，值可以大到$10^9$以绝对值表示。 二次方法需要大约$10^{10}$在最坏的情况下进行操作，这远远超出了典型的比赛时间限制。 我们需要一个接近线性时间的解决方案，因为单次传递$10^5$元素易于管理。 

棘手的部分不是交替条件本身，而是处理等号组以及获取数字比跳过它更糟糕的可能性。 例如，对于所有负数，例如：```
3
-5 -2 -7
```答案是：```
0
```总是选择至少一个元素的粗心解决方案会错误地输出`-2`。 

另一种边缘情况是一组相同符号的数字，其中只应取一个。 为了：```
5
3 8 1 -10 5
```最好的答案是`8 - 10 + 5 = 3`。 在给出负数之前选择每个正数`3 + 8 + 1 - 10 + 5 = 7`，但符号不会交替，因为正值在子序列中相邻。 该算法必须理解每个连续符号块中只有一个值可以贡献。 

最终的边界情况是单个元素：```
1
100
```答案是`100`，因为单元素子序列已经满足交替规则。 

# 方法

 一个简单的想法是尝试每个子序列并保留最好的有效子序列。 长度数组的子序列数$n$是$2^n$，所以即使对于中等规模的小阵列，这也是不可能的。 我们可以通过动态编程来改进它，动态编程会记住以正数或负数结尾的最佳答案。 这可行，但它的状态超出了问题的需要。 

关键的观察是，在具有相同符号的连续数字块中，子序列最多可以包含一个元素。 连续取两个正数会违反交替，并且取较小的正数而不是较大的正数永远不会有帮助。 同样的推理也适用于负块：因为我们想要最大化总和，所以我们应该取危害最小的，即最大值。 

这将问题简化为扫描数组，将其分成等号的最大块，从每个块中取出最大元素，然后添加这些选定的值。 空子序列自然会被处理，因为每个选择的块最大值只能改善结果，并且如果所有可用选择都是负的，则最终答案应该与零进行比较。 

蛮力之所以有效，是因为它探索了所有可能的有效选择，但由于搜索空间巨大而失败。 对符号块的观察消除了所有不必要的选择，只留下每个块的最佳代表。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 动态规划| O(n) | O(1) | O(1) | 已接受 |
 | 贪婪符号块| O(n) | O(1) | O(1) | 已接受 |

 # 算法演练

 1. 从第一个元素开始。 它创建第一个符号块，该块内当前的最佳值就是该元素。 
2. 从左向右移动数组。 如果当前元素与当前块具有相同的符号，则更新该块存储的最大值。 原因是子序列只能从该块中获取一个值，因此我们保留最好的值。 
3. 当符号改变时，前一个块完成。 将其最大值添加到答案中，然后使用当前元素开始一个新块。 
4. 循环结束后，添加最后一个块中的最大值，因为没有后续符号更改来触发更新。 
5. 如果结果和为负，则输出零，因为不允许选择任何元素。 

其工作原理：每个有效子序列最多可以包含每个最大同号段中的一个元素。 贪心选择从每个分段中获取最大可能的元素，因此对于每个分段，它独立地给出最佳贡献。 由于从一个片段中进行选择不会影响可以从另一片段中选择哪个值，因此组合这些局部最佳选择会产生全局最佳子序列。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    cur = a[0]
    sign = 1 if a[0] > 0 else -1

    for x in a[1:]:
        current_sign = 1 if x > 0 else -1

        if current_sign == sign:
            cur = max(cur, x)
        else:
            ans += cur
            cur = x
            sign = current_sign

    ans += cur

    print(max(ans, 0))

solve()
```变量`cur`将最佳值存储在当前符号块内。 它从第一个数组元素开始，因为每个块必须至少包含一个值。 

扫描期间，等号仅更新`cur`，因为在有效的交替子序列中不可能从同一块中选择另一个元素。 当符号改变时，前一个块不能再增长，因此它的最佳值被添加到`ans`。 

循环处理最后一个块后的最后添加。 忘记此步骤是一种常见的差一错误，因为最后一个块永远不会遇到符号更改。 这`max(ans, 0)`处理每个可能的子序列和为负数的数组。

 # 边缘情况

 对于全否定的情况：```
3
-1 -1 -1
```整个数组是一个负块。 该算法保留最大值，即`-1`，但添加它会减少总和。 最终与零的比较正确地选择了空子序列。 

对于重复的符号随后发生变化：```
5
3 8 1 -10 5
```第一个块是积极的并且有贡献`8`，第二个块为负并有贡献`-10`，最后一个块贡献`5`。 结果是`3`，对应于有效子序列`[8, -10, 5]`。 

对于单个值：```
1
100
```有一个块，其最大值为`100`。 最后的添加给出了正确的答案，不需要任何特殊情况的代码。
