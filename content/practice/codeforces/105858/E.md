 ## 解决方案
 ## 问题理解

 该问题定义了无限网格上的二维分形图案，通过将平面反复细分为相等的正方形块并在每个尺度上删除中间的特定区域来构造。 经过无限多层次的这种构造后，一些单元保持“填充”状态，而另一些单元则变成“洞”。 

任务是回答有关各个网格坐标的查询。 每个查询都会给出一个单元格位置，我们必须确定该单元格是否在递归删除过程中幸存下来，或者在构建的某个级别被删除。 输出通常是每个查询的二进制答案，指示单元是地毯的一部分还是属于已删除的区域。 

尽管网格在概念上是无限的，但输入中的坐标很大但有限，通常高达 10^18 左右。 这立即排除了任何尝试模拟网格或显式构建中等前缀的方法。 单层扩展已经使网格大小成倍增加，经过几层后，结构变得太大而无法存储或遍历。 任何依赖于单元迭代或维护二维数组的解决方案都会超出时间和内存限制。 

一个常见的微妙失败案例来自于尝试逐级模拟每个查询的构造。 例如，如果规则是删除中心单元的 3×3 细分，那么通过构建高达 10 级的网格来检查点就已经意味着处理 3^20 比例结构，这是不可行的。 

另一类不正确的解决方案来自于仅检查顶级细分。 例如，考虑一个点不在第 1 层的中心已移除块中，但位于第 2 层或更深的中心块中。 浅检查会错误地将其标记为已填充。 

作为一个具体示例，假设该规则删除了每个 3×3 块的中心单元。 点 (1, 1) 立即被删除。 点 (4, 4) 位于第一层的非中心块中，但在缩放到其子块后变为 (1, 1)，因此也应该将其删除。 任何仅检查第一个分解步骤的解决方案都会错误地输出 (4, 4) 的“filled”。 

关键的困难在于，去除不是单一的全局条件，而是在每个尺度上应用的重复的局部条件。 

## 方法

 蛮力方法试图明确地模拟分形结构。 对于每个查询点，我们维护一个网格并重复将其细分为 3×3 块，在每次迭代时将中心块标记为已删除。 理论上，经过足够的迭代后，我们可以决定一个点是否存活。 

这种方法是正确的，因为它遵循构造的精确定义。 然而，每个级别都会将块的数量乘以 9，如果我们显式地模拟结构，即使限制自己跟踪单个点的包含块也没有多大帮助。 如果坐标达到 10^18，则级别数约为 log₃(10^18) ≈ 38，并且在乘以许多查询时，快速重建结构或扫描每个级别的块的简单模拟会变得昂贵。 

关键的观察是结构是自相似的。 在每一层，每个子方块内都应用相同的规则。 这意味着我们不需要构建网格，而只需跟踪查询点在连续缩放块内的位置。 每一步都会将问题规模缩小 3 倍，唯一重要的信息是该点是否落在禁区中心位置。 

因此，问题变成了以 3 为基数的数字分解问题：我们反复以 3 为模减少坐标，以确定它们在每个级别的 3×3 网格内的位置。 如果在任何级别，两个坐标都落在中间索引 (1, 1) 中，则该点将被删除。

这将指数几何结构简化为对数系统检查。

 | ---| ---| ---| ---|
 | 暴力模拟| O(9^d) | O(9^d) | O(9^d) | O(9^d) | 太慢了 |
 | 3 进制数字检查 | 每个查询 O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取每个查询点(x,y)。 目标是确定该点是否在任何递归级别落入已删除的中心区域。 
2. 当 x > 0 或 y > 0 时，重复检查 3×3 块内点的当前局部位置。 这是使用 x % 3 和 y % 3 完成的。此步骤确定该点位于分形当前尺度内的位置。 
3. 如果在任何步骤 x % 3 == 1 且 y % 3 == 1，则立即断定该点已被删除并停止处理此查询。 此条件恰好对应于 3×3 块的中心单元，该单元在每个递归级别都会被删除。 
4. 否则，通过更新 x //= 3 和 y //= 3 移动到下一个更高级别。这有效地缩小到分形层次结构中的父块。 
5. 如果循环结束时没有遇到禁止的中心位置，则该点在所有级别中都存在并成为地毯的一部分。 

正确性取决于每个除法步骤都保留相同的结构：每个 3×3 块都是整个模式的缩放副本，因此逐位检查基数 3 中的数字可以完全捕获递归定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_filled(x, y):
    while x > 0 or y > 0:
        if x % 3 == 1 and y % 3 == 1:
            return False
        x //= 3
        y //= 3
    return True

def main():
    q = int(input())
    for _ in range(q):
        x, y = map(int, input().split())
        print("YES" if is_filled(x, y) else "NO")

if __name__ == "__main__":
    main()
```功能`is_filled`实现对基数 3 中的点进行逐位检查。每次迭代使用模算术隔离当前级别的局部坐标。 如果该点落在移除的中心，我们会提前终止。 否则，整数除法会将视角转移到分形的下一个级别。 

一个微妙的实现细节是必须在每个级别同时检查两个坐标。 仅检查一个坐标会错误地对位于对角线或偏离中心禁区的点进行分类。 

## 工作示例

 考虑具有两个点的查询序列：(1, 1) 和 (4, 4)。 

对于 (1, 1)，我们跟踪它的进展：

 | 步骤| x| y | x % 3 | % 3 | 决定|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 1 | 1 | 1 | 删除 |

 该点位于中央单元格中，因此它不是地毯的一部分。 

对于 (4, 4)，我们追踪：

 | 步骤| x| y | x % 3 | % 3 | 决定|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 4 | 4 | 1 | 1 | 删除 |

 尽管 (4, 4) 在第一个比例下视觉上并不位于中心，但当以基数 3 表示时，它会映射到子块的中心单元，因此它也会被删除。 

这些示例表明，该条件递归地适用于每个级别，而不仅仅是顶层。

 ## 边缘情况

 一个关键的边缘情况是原点 (0, 0)。 在此公式中，它永远不会落入已移除的中心，因为两个坐标在所有级别中都保持为零，因此它始终被归类为填充。 该算法可以正确处理此问题，因为循环会立即终止而不会触发禁止条件。 

另一种微妙的情况是只有一个坐标与中心位置模 3 匹配时。例如 (1, 0) 或 (0, 1) 不会被删除。 该算法正确地保留了它们，因为移除要求两个坐标同时等于 1 模 3。 

更深层次的情况是点很大，但结构上相当于一个小的移除单元，例如 (3^k + 1, 3^k + 1)。 这些在第 k 次迭代时崩溃为 (1, 1)，并且循环正确地检测到该级别的删除而不是第一个，这表明递归检查是必要的而不是一次性条件。
