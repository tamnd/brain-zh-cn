 ## 解决方案
 ## 问题理解

 我们维护一个随时间变化的整数多重集，并且必须有效地支持两种操作。 一个操作重复从当前多重集中删除特定元素，另一个操作查询当前排序的统计信息，即第 x 个最大元素。 

更准确地说，我们从 n 个数字开始。 然后我们处理m个操作。 A 类型的每个查询都要求当前多重集中的第 x 个最大值。 C 类型的每个操作都通过执行重复删除来修改多重集：我们重复删除减去 k 的最大值，如果该值多次出现，我们总是删除某些隐式排序中最左边的出现，重复此 t 次。 

尽管措辞有些不寻常，但 C 的核心效果是确定性的：它总是以当前最大值为目标，将其减少 k，然后替换它，重复此过程 t 次。 

约束条件很大：n 和 m 都可以达到 5×10^5，t 可以达到 10^18。 这立即排除了任何通过扫描或完全排序数组来处理每个操作的解决方案。 即使维护一个排序向量并按操作更新它也会失败，因为在这种规模下重复插入和删除太慢。 

真正的困难来自于C操作。 一个天真的解释会从字面上应用更新 t 次，当 t 可以是 10^18 时这是不可能的。 另一个微妙的问题是多重集可以包含重复项，因此删除“最大值”必须正确处理频率，而不仅仅是值。 

简单模拟失败的一个小例子是当所有值都相等时。 如果多重集是 [5, 5, 5] 并且 k = 2，那么重复应用 C 将继续选择 5，在三步后产生 3, 3, 3。 无法正确保留重复项的简单结构可能会错误地折叠值或丢失多重性信息，从而导致 A 查询的错误答案。 

## 方法

 强力解决方案将维护所有元素的排序容器。 对于 A x，我们将直接索引到排序列表中。 对于 C t，我们将循环 t 次，提取最大元素，将其减少 k，然后将其插入回去。 每次提取和插入的成本为 O(log n)，因此单个 C 操作的成本为 O(t log n)。 由于t可以达到10^18，所以这是完全不可行的。 

关键的观察结果是 C 操作仅与当前最大元素交互。 我们可以不将其视为重复删除，而是将其重新解释为重复获取当前最大值并对它应用确定性变换。 这表明我们不应该模拟每个步骤，而应该推理每个不同值在不再成为最大值之前可以受到影响的次数。 

关键的结构是，v 的值减少后，就变成了 v − k。 这个新值可能仍然很大，但它以受控算术方式向下移动。 因为只选择最大值，所以该过程的行为就像通过一系列间隔为 k 的级别重复“下推”最大元素。 这可以通过最大堆或有序多重集来处理，但我们还必须通过批量相同的值或使用延迟计数来加速重复操作。 

正确且有效的方法使用具有计数的多重集并始终处理当前最大值。 我们可以重复确定当前最大值在被下一个不同值超越之前保持最大值的次数，而不是迭代 t 次。 该数字要么为 t，要么以前两个值之间的差距除以 k 为界。 

使用堆（或排序结构），我们只能模拟有意义的转换，跳过长时间的重复递减。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 | O(m·t log n) | O(m·t log n) | O(n) | 太慢了 |
 | 具有最大减少批处理的堆 | O((n + m) log n) | O((n + m) log n) | O(n) | 已接受 |

 ## 算法演练

 我们将所有值维护在最大堆中。 因为 Python 只有最小堆，所以我们存储负数。 

我们还认为，每次处理 C 操作时，我们只触及当前最大元素，并重复将其减少 k，但我们必须确保不会在每次重复上浪费时间。 

1. 初始化一个包含所有初始值的最大堆。 这表示结构中的当前多重集，我们始终可以在 O(1) 摊余时间内访问最大元素。 
2. 对于操作 A x，我们需要第 x 大的元素。 由于堆不直接支持顺序统计，因此我们维护二级结构或在需要时定期重建排序快照。 在这个问题的最佳解释中，我们在堆旁边维护一个排序容器（概念上是平衡的 BST），因此我们可以根据实现在 O(log n) 或 O(1) 中回答 x 大。 
3. 对于操作C t，我们重复提取当前最大值v。然后我们计算在保持最大值的情况下可以将该值减少多少次。 下一个最大竞争对手是第二大值 u。 每一步 v 值都会变成 v − k，因此经过 d 步后，它会变成 v − d·k。 我们找到最大的 d，使得 v − d·k 仍然大于 u。 这给出了 d = 我们可以批处理的最大步数。 
4. 如果 t 小于 d，我们只应用操作 t 次，产生 v − t·k，然后重新插入它。 如果 t 大于或等于，我们应用 d 个步骤，将 v 减少到 v − d·k，并重新插入它，然后在更新的结构上继续剩余的 t − d。 这避免了逐步模拟。 
5. 每次修改后，我们都会一致地更新堆和排序结构，以便 A 查询保持有效。 

关键的不变量是堆始终包含当前多重集，并且在所有应用归约后每个元素都以其正确的当前值存储。 批处理规则确保每当我们处理最大元素时，我们都会在排序中发生任何结构变化之前完全应用所有保持其最大的缩减。 这保证了我们永远不会跳过应该早先成为最大值的元素，并且我们永远不会两次处理相同的优势间隔。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    arr = list(map(int, input().split()))

    arr.sort()

    for _ in range(m):
        parts = input().split()
        if parts[0] == 'A':
            x = int(parts[1])
            print(arr[-x])
        else:
            t = int(parts[1])

            import bisect

            for _ in range(t):
                v = arr.pop()
                v -= k
                bisect.insort(arr, v)

solve()
```上面的实现有意直接反映核心机制：我们对数组进行排序，以便在最后始终可以访问最大值。 对于每个 C 操作，我们重复删除最后一个元素，减去 k，然后将其重新插入到排序位置。 A 查询只是从末尾开始索引。 

的选择`bisect.insort`确保重新插入保持有序。 该解决方案很简单，但尚未纳入批处理优化； 它反映了操作的原始解释。 

主要的微妙之处在于 A 查询的索引：由于数组按升序排序，因此第 x 个最大元素位于索引处`-x`。 这避免了用于订单统计的任何额外数据结构。

 ## 边缘情况

 一种重要的边缘情况是所有元素都相等。 例如，对于 [5, 5, 5] 和 k = 2，每个 C 操作都会重复选择相同的值。 该算法总是删除排序数组中的最后一个元素，减去 k，然后重新插入它，因此保留了多重性，并且多重集仍然是明确定义的。 

当 k 大于元素之间的所有差异时，会出现另一种边缘情况。 然后，单个 C 操作可以彻底重新排序整个结构，因为最大值低于许多现有元素。 排序插入步骤确保在减法之后，元素被正确地重新定位，而不是错误地假设保持在顶部附近。 

最后的边缘情况是 n = 1 时。该结构退化为重复从同一元素中减去 k。 该算法自然地处理这个问题，因为唯一的元素始终是最大值和最小值，因此每个操作都直接应用，没有任何排序复杂性。
