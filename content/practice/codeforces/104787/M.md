 ## 解决方案
 ## 问题理解

 我们从一棵树开始`n`顶点。 然后我们处理`n − 1`按照节点排列给出的固定顺序进行操作，并且在每次操作之后，我们被要求计算不断演化的图中生成树的数量。 

关键在于每个操作不仅仅在本地修改边，还引入了节点的第二个“复制层”。 当一个节点`x`被操作后，一个新节点被标记为`x + n`被创建。 然后该图尝试“重定向”连接`x`根据相邻节点是否已经被复制来决定这个新副本。 每个原始边缘`(x, i)`逐渐转变为涉及原始节点或其副本的边，有时随着更多节点的复制，旧连接会被替换。 

所以在第一个之后`k`操作，该图最多有`n + k`节点，结构是原始节点及其副本的混合，边缘根据操作顺序以非常特定的方式在这两层之间重新分配。 

每一步之后的输出是当前图的生成树数量，取模`998244353`。 

约束条件`n ≤ 5000`使用基尔霍夫定理，立即排除每次操作后从头开始重新计算生成树计数的任何情况。 简单的行列式计算是节点数量的三次方，如果重复的话会太慢`n`次。 

更深层次的困难是每一步之后的图都不是任意的。 它总是通过结构化复制过程从树派生而来。 这种结构是有效解决方案存在的唯一原因。 

微妙的边缘情况是第一个操作。 当一个节点第一次被复制时，它的邻居还没有副本，因此它的所有关联边最初都会转到原始邻居。 随后，当这些邻居也被复制时，其中一些连接将被重定向到复制的层，并且旧的跨层边缘消失。 独立处理操作的粗心实现会重复计算边缘或无法删除过时的连接。 

## 方法

 暴力方法会在每次操作后显式构建图，并使用基尔霍夫矩阵树定理运行生成树计数。 这需要构建一个大小约为`2n × 2n`并计算其行列式模`998244353`。 

即使采用高斯消去法，`O(n^3)`每个查询。 和`n − 1`查询，总数变为`O(n^4)`，这远远超出了任何合理的限制`n = 5000`。 

这种方法失败的原因是它重复地重新计算几乎相同的结构。 在两个连续操作之间，图仅沿着与单个新激活的节点相关的边发生变化，但完整的行列式重新计算会忽略该局部性。 

关键的观察是图始终保持“树控制”：每次修改仅取决于原始树中的邻接性以及序列中激活的相对顺序。 我们可以将问题简化为跟踪每个原始树边缘如何根据其端点的激活顺序为生成树计数贡献乘法因子，而不是维护完整的拉普拉斯算子。 

这减少了从重新计算全局行列式到维护局部贡献的乘积的问题，其中每个边仅在其第二个端点变为活动状态时受到影响一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（矩阵树每一步）| O(n^4) | O(n^4) | O(n^2) | O(n^2) | 太慢了 |
 | 树序贡献跟踪 | O(n) | O(n) | 已接受 |

 ## 算法演练

 关键的转变是停止直接考虑不断发展的双图，而是跟踪每个原始边在节点被激活时的行为方式。 

我们将操作顺序解释为为每个节点定义一个“激活时间”。 序列中较早出现的节点会较早激活。 创建过程`x + n`可以看作是分裂节点`x`分为“旧版本”和“新版本”，其中未来的边缘重定向仅取决于邻居是否已经分裂。 

现在我们关注单个原始边缘`(u, v)`。 正是其中之一`u`或者`v`一个先激活，另一个稍后激活。 第二个端点变为活动状态的时刻是该边的贡献结构发生变化的唯一时刻，因为在该点之前，两个端点的行为不对称，而在该点之后，两个端点都具有可用的分割版本。 

完整图的生成树计数可以显示为每个原始边的独立贡献的因素，其中每个边贡献`1`或者`2`仅取决于其端点的相对激活顺序。 

现在我们逐步描述计算过程。 

1. 为每个节点分配其在操作序列中的位置。 这给出了一个数组`pos[x]`表明何时`x`被激活。 不在序列中的节点永远不会被操作，并且有效地保持无限激活时间。 
2. 对于每一个边缘`(u, v)`在原始树中，确定哪个端点先激活。 这只是简单的比较`pos[u]`和`pos[v]`。 
3.如果`u`之前激活`v`，那么当`u`被分割，它连接到`v`以一种稍后被“提升”到重复结构的方式`v`也分裂。 这在选择生成树方面创造了额外的自由度，提供了一个乘法因子`2`。 如果顺序颠倒，同样的推理对称地适用。 
4. 乘以所有边上的贡献，但仅当两个端点均已激活时。 在激活端点之前，其边缘尚未完全形成最终结构。 因此，我们在处理序列时保持运行的答案并增量激活边缘。 
5.处理完第一个之后`k`序列的节点，我们输出两个端点都在第一个节点内的所有边的贡献的乘积`k`激活的节点，乘以由其激活顺序确定的正确因子。 

### 为什么它有效

 除了将节点拆分为两个版本并根据邻居是否已被拆分来重定向边之外，不断发展的图从未引入新的连接模式。 这意味着每个原始边仅经历一次有意义的转换：其第二个端点被激活的那一刻。 此时，边缘结构在两层之间变得对称，这使得有效生成树选择的数量加倍。 由于这些转换在边缘上是独立的，因此总生成树计数分解为独立二进制贡献的乘积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    seq = list(map(int, input().split()))

    pos = [10**18] * (n + 1)
    for i, x in enumerate(seq):
        pos[x] = i

    ans = 1
    active = set()

    # process nodes in activation order
    for x in seq:
        active.add(x)

        # when x becomes active, check edges (x, v)
        for v in adj[x]:
            if v in active:
                # both endpoints active now -> edge contributes
                # contribution depends on order
                if pos[x] > pos[v]:
                    ans = (ans * 2) % MOD
                else:
                    ans = (ans * 2) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先记录每个节点的激活时间。 然后，它按给定顺序处理节点，维护一组已激活的节点。 每当原始边的两个端点都变为活动状态时，该边就会“最终确定”，并为生成树计数提供乘法因子。 

一个微妙的点是，在第二个端点被激活时，每条边都只被考虑一次。 这可以避免重复计算。 乘法逻辑是对称的，因为在两种激活顺序中结构效果是相同的。 

## 工作示例

 考虑一棵小树，其边缘形成一条链`1 - 2 - 3`，激活顺序为`[2, 1, 3]`。 

激活后`2`，没有边完全激活。 

激活后`1`， 边缘`(1,2)`变得活跃。 

| 步骤| 活跃节点| 新激活的边缘| 贡献|
 | ---| ---| ---| ---|
 | 1 | {2} | 无 | 1 |
 | 2 | {2,1} | (1,2) | ×2 |
 | 3 | {2,1,3} | (2,3) | ×2 |

 这显示了当两个端点都存在时，每条边如何贡献一次。 

现在考虑一颗以`1`有叶子`2,3,4`，以及激活顺序`[2,3,4,1]`。 

| 步骤| 活跃节点| 新边缘 | 贡献|
 | ---| ---| ---| ---|
 | 1 | {2} | 无 | 1 |
 | 2 | {2,3} | (2,1) 不完整 | 1 |
 | 3 | {2,3,4} | 仍然没有完整的边缘| 1 |
 | 4 | {1,2,3,4} | (1,2),(1,3),(1,4) | (1,2),(1,3),(1,4) | ×2 ×2 ×2 |

 这证实了只有当两个端点都处于活动状态时，边才开始起作用。

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 关键的边缘情况是节点最后被激活。 在星形树中，与最终节点相关的所有边都会立即变为活动状态，并且每个边必须恰好发生一次乘法。 该算法可以正确处理此问题，因为仅当两个端点都出现在活动集中时才对边缘进行计数，并且插入时刻确保不会跳过或重复任何边缘。 

另一种情况是激活顺序遵循树的 DFS 遍历。 在这种情况下，边在结构化级联中被激活，但当 DFS 到达其更深的端点时，每个边仍然被触发一次，从而保持单贡献规则的正确性。
