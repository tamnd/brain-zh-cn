 ## 解决方案
 ## 问题理解

 我们得到了一个单词集合，但每个单词唯一重要的属性是它的长度。 每天，可依都会选择一些单词来学习，并且有一个特殊的规则：如果她决定学习一个长度的单词$k$，那么她必须学习所有长度的单词$k$当天。 换句话说，长度就像不可分割的组。 

每天都有容量限制$W$，意味着当天学习的单词总数不能超过$W$。 由于选择一个长度会强制该长度的所有单词，因此真正的决定是将哪些长度打包到同一天，但其总频率不超过$W$。 

输入给出$n$单词长度，每个长度在 1 到 13 范围内。任务是将这些长度划分为最小有效天数，其中每一天都是长度组的子集，并且一天中组大小的总和不超过$W$。 

输出是覆盖所有单词所需的最少天数。 

这些限制以非常具体的方式发挥作用。 虽然$n$可以大到 50000，长度的值空间很小，以 13 为界。这立即表明任何依赖于不同长度数量的解决方案都是小且易于管理的。 跟踪每个长度计数的解决方案就足够了； 迭代所有长度子集仍然是可行的，因为最多有$2^{13}$的可能性。 

一种幼稚的解释可能会尝试一个接一个地分配单词，或者贪婪地模拟逐日打包，而不考虑全局结构。 这很容易被打破，因为分组决策是相互依赖的：尽早选择一个大的组可能会阻碍以后更好的打包。 

当一个长度主导容量时，就会出现一种微妙的边缘情况：

 输入：

 n = 5，W = 4

 长度：[1, 1, 1, 1, 1]

 每个长度组只是长度 1，频率为 5。由于我们必须将它们全部放在一起，但每天不能超过 4，所以我们至少需要 2 天。 任何试图在不尊重组约束的情况下“拟合剩余单词”的贪婪方法都可能会错误地分割或低估。 

另一个边缘情况是，当许多小组紧密结合以恰好填满天数而不是稍微超出容量时，其中最佳包装取决于子集选择而不是排序。 

## 方法

 关键的抽象是忘记单个单词，而是将输入压缩为每个长度的频率计数。 由于长度范围仅从 1 到 13，因此我们最多得到 13 组，每组都有固定的大小。 

现在问题变成：我们最多有 13 个项目，每个项目的权重等于其频率，并且我们希望将所有项目打包到容量最少的箱中$W$，其约束条件是项目不可分割。 

这正是一个物品数量很少但重量可能很大的装箱问题。 蛮力的想法将模拟将组分配到几天，尝试所有可能的分配。 这会导致对展示位置的指数搜索，大致如下$O(k^n)$在哪里$k$是箱数，即使对于中等输入也是不可行的。 

然而，由于最多有 13 个不同的组，因此我们可以对组的子集使用位掩码动态编程。 每个状态代表哪些组已经被打包，我们尝试通过选择总大小不超过的剩余组的子集来填充一天$W$。 对于每个有效子集，我们通过将这些组标记为已使用并添加一天来进行转换。 

这将问题转化为子集上的最短路径，其中每次移动对应于最佳地填充一天。 

关键的观察是，除了剩余未使用的组之外，一天的打包与前几天无关。 因此，每一次 DP 转换都完全代表一天的工作。

 | ---| ---| ---| ---|
 | 暴力分配| 指数| O(n) | 太慢了 |
 | 子集上的位掩码 DP |$O(2^{13} \cdot 2^{13})$或优化$O(2^{13} \cdot 13)$|$O(2^{13})$| 已接受 |

 ## 算法演练

 我们将输入压缩到频率数组中`cnt`大小为 13，其中`cnt[i]`是长度的单词数$i+1$。 

然后，我们将这 13 组中的每一组视为具有权重的项目`cnt[i]`。 

我们定义一个位掩码 DP，其中每个掩码代表哪些长度组已经完全分配给天。 

我们将 DP[mask] 计算为打包所有组所需的最少天数`mask`。 

### 步骤

 1. 计算`cnt[0..12]`来自输入。 
2. 预先计算组的所有有效子集。 如果子集的计数总和不超过，则子集有效$W$。 这代表单日包装。 
3.初始化大小的DP数组$2^{13}$对于较大的值，设置 DP[0] = 0。 
4.迭代从0到的所有掩码$2^{13}-1$。 
5. 对于每个掩码，考虑剩余未使用组的所有子集。 
6. 如果子集有效且与当前掩码不相交，则通过添加 1 天过渡到新掩码。 
7. 对所有转换取最小值。 
8. 答案是DP[(1<<13)-1]。 

关键的设计决策是预先计算有效子集，因为在 DP 内重复检查权重会不必要地增加运行时间。 由于13很小，枚举所有子集是可行的。 

### 为什么它有效

 在任何 DP 状态下，掩码都会准确编码剩余的组。 每次转换都会选择一组可以容纳在一天中的剩余组。 由于组是不可分割的并且必须完全安排，因此每个组在所有转换中都只出现一次。 DP 将 13 个组的所有可能分区探索为容量箱$W$，并且由于每个有效分区对应于子集删除的某个序列，因此 DP 上的最小值捕获最佳天数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, W = map(int, input().split())
    a = list(map(int, input().split()))

    cnt = [0] * 13
    for x in a:
        cnt[x - 1] += 1

    # Precompute subset weights
    m = 13
    subset_weight = [0] * (1 << m)
    for mask in range(1 << m):
        s = 0
        for i in range(m):
            if mask & (1 << i):
                s += cnt[i]
        subset_weight[mask] = s

    valid = []
    for mask in range(1 << m):
        if subset_weight[mask] <= W:
            valid.append(mask)

    INF = 10**9
    dp = [INF] * (1 << m)
    dp[0] = 0

    full = (1 << m) - 1

    for mask in range(1 << m):
        if dp[mask] == INF:
            continue
        remaining = full ^ mask
        for sub in valid:
            if (sub & mask) == 0:
                new_mask = mask | sub
                if dp[new_mask] > dp[mask] + 1:
                    dp[new_mask] = dp[mask] + 1

    print(dp[full])

if __name__ == "__main__":
    main()
```该实现首先将输入压缩到 13 长度的频率数组中。 这一步至关重要，因为它减少了潜在的大$n$将问题转化为固定大小的状态空间。 

这`subset_weight`计算是核心预处理步骤。 它评估长度的每个子集，并计算如果在一天内一起选择这些长度，将包含多少个单词。 

这`valid`列表仅存储符合每日限制的子集$W$。 这避免了 DP 转换期间重复的容量检查。 

DP 循环按升序迭代掩码。 对于每个状态，它尝试添加未使用组的有效子集。 XOR 检查确保我们永远不会重复使用组。 每个转变对应于正好消耗一天。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, W = map(int, input().split())
    a = list(map(int, input().split()))

    cnt = [0] * 13
    for x in a:
        cnt[x - 1] += 1

    m = 13
    subset_weight = [0] * (1 << m)
    for mask in range(1 << m):
        s = 0
        for i in range(m):
            if mask & (1 << i):
                s += cnt[i]
        subset_weight[mask] = s

    valid = [mask for mask in range(1 << m) if subset_weight[mask] <= W]

    INF = 10**9
    dp = [INF] * (1 << m)
    dp[0] = 0

    full = (1 << m) - 1

    for mask in range(1 << m):
        if dp[mask] == INF:
            continue
        for sub in valid:
            if (sub & mask) == 0:
                dp[mask | sub] = min(dp[mask | sub], dp[mask] + 1)

    return str(dp[full])

# minimal

# each must be separate

 ## 边缘情况

 当单个长度组超过一半时，就会出现关键边缘情况$W$，使其无法与大多数其他群体结合。 例如，如果一组的大小为 5 并且$W = 6$，只有非常特定的组合才有效。 DP 自然地处理这个问题，因为子集有效性纯粹是通过和约束来检查的，与贪婪排序无关。 

另一个边缘情况是多个组合完全匹配时$W$。 在这种情况下，贪婪策略可能会首先选择次优子集并将剩余组分段。 DP 避免了这种情况，因为它对称地探索所有有效子集，并且始终最小化每个可到达掩码状态的总天数。 

最后一个微妙的情况是，所有组各自都很小，但在许多方面集体超过了容量，使得包装高度组合。 即使在这里，子集枚举也保证考虑所有有效的包装，并且通过状态最小化而不是构造顺序找到最佳划分。
