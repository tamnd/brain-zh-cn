 ## 解决方案
 ## 问题理解

 我们被要求减少数量`n`使用一系列受奇偶校验约束的减法来归零。 每个操作都允许我们减去之间的任何数字`1`和`k`，但如果当前`n`是偶数，我们必须减去一个偶数，如果`n`是奇数，我们必须减去一个奇数。 目标是以最少的操作次数来完成此操作。 输入提供多个测试用例，每个测试用例指定`n`和一个奇怪的`k`（至少 3 个）。 每个测试用例的输出是达到零的最小操作数。 

关键的限制是`n`可以大到`10^9`并且最多可以有`10^4`测试用例。 这排除了任何天真地尝试每个减法的解决方案，因为在最坏的情况下`n`每个测试用例的操作将导致大约`10^13`总的操作量，远远超出了2秒内可行的范围。 我们需要一个解决方案来计算每个测试用例的恒定或对数时间结果。 

当出现微妙的边缘情况时`n`小于`k`。 自从`k`是奇数，我们不能总是减去`k`直接，特别是当奇偶校验不匹配时。 例如，如果`n = 2`和`k = 3`，我们不能减去`3`因为它大于`n`，但我们还必须减去一个偶数（2本身），因此解必须正确选择`2`。 同样，如果`n = 1`和`k = 3`，我们可以减去`1`立即地。 总是试图减去的粗心方法`k`首先会在这些小值上失败。 

## 方法

 蛮力方法很简单：`n > 0`，重复选择最大的有效数`x`（尊重平等和`1 <= x <= k`）并从中减去它`n`。 计算操作次数。 这是有效的，因为在每一步你都会减少`n`，但是当`n`很大，因为每个减法可能是一个单独的操作，导致最多`n`每个测试用例的迭代次数。 

最佳解决方案的关键是考虑奇偶校验结构。 自从`k`是奇数，它保证奇数减法总是可用，偶数减法总是至少`2`。 那么问题就简化为两种情况：如果`n`是奇数，我们总是可以减去最大的奇数`k`并减少`n`迅速地。 如果`n`是偶数，最大的偶数减法是`k-1`（如果`k > 1`） 或者`2`。 一般来说，我们可以将操作数计算为`ceil(n / k)`什么时候`n`是奇数，并且`n / 2`什么时候`n`是偶数并且`k`足够大。 简化一下，最少的操作是：

 - 如果`n`是奇数：`(n + k - 1) // k`- 如果`n`是偶数：`n // 2`如果`k > 1`每个测试用例的恒定时间计算避免了迭代每个减法。

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和`k`。 
3.如果`n`能被2整除，计算`n // 2`作为操作的数量。 推理是最小偶数是`2`，并减去`2`反复将达到零`n / 2`步骤。 自从`k >= 3`，我们总是可以减去`2`。 
4. 如果`n`是奇数，计算`(n + k - 1) // k`。 这相当于上限`n / k`因为我们可以减去的最大奇数是`k`。 每次减法都会减少`n`有效地同时遵守奇校验约束。 
5. 打印每个测试用例的结果。 

为什么它有效：不变的是每次减法都遵循奇偶性`n`。 通过始终减去具有正确奇偶校验的最大允许数量，我们可以最大限度地减少操作总数。 案例涵盖了所有可能`n`因为偶数总是可以通过减法减半`2`，并且奇数总是可以使用最大奇数减法有效地减少`k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    if n % 2 == 0:
        print(n // 2)
    else:
        print((n + k - 1) // k)
```该解决方案首先读取测试用例的数量，然后处理每对`n`和`k`。 我们检查奇偶性`n % 2`。 对于甚至`n`, 减去`2`反复确保最少的操作，所以`n // 2`给出了答案。 对于奇数`n`，我们使用天花板除法`(n + k - 1) // k`使用最大可能的奇数减法确定最少的运算。 请注意正确执行整数除法以避免差一错误。

 ## 边缘情况

 对于`n = 1, k = 3`，算法正确识别`n`是奇数，计算`(1 + 3 - 1) // 3 = 1`，和输出`1`，避免过度减法。 为了`n = 2, k = 3`,`n`是偶数，公式`2 // 2 = 1`正确输出`1`。 这些边缘情况证实基于奇偶校验的公式可以正确处理最小数字并防止无效减法。
