 ## 解决方案
 ## 问题理解

 每个怪物都有生命值`HP`和攻击值`ATK`。 在每一秒中，所有还活着的怪物都会首先攻击英雄，因此英雄会失去攻击值的总和。 然后英雄选择一只活着的怪物并攻击它。 

对特定怪物造成的伤害仅取决于该怪物已被攻击的次数。 它首次收到热门优惠`1`，其第二笔交易`2`，其第三笔交易`3`， 等等。 因此，如果怪物需要`k`攻击致死，这些攻击必须处理

 [
 1+2+\cdots+k=\frac{k(k+1)}2
 ]

 伤害总计。 问题是如何选择攻击顺序，使得英雄受到的总伤害尽可能小。 

输入最多包含`10^3`测试用例，最多有`10^5`一个测试用例中最多有怪物`10^6`所有测试用例中的怪物。 生命值和攻击值最多为`10^5`。 这些界限排除了任何涉及怪物子集或排列的情况。 甚至一个`O(n^2)`当方法太昂贵时`n=10^5`，因此预期的解决方案必须将问题简化为本质上的排序。 

对于每个怪物来说，尽管潜在的生命值很大，但所需的攻击次数却非常少。 和`HP <= 10^5`,`447`攻击已经处理`100128`伤害，所以每个怪物最多需要`447`攻击。 原始约束和输出格式由官方问题页面确认。 

有几种边缘情况可能会导致简单的实现错误。 

对于单个怪物来说，根本没有顺序决定。 例如，```
1
1
1 1
```有答案`1`。 一个不小心将怪物多算一秒的公式会产生`2`，这是错误的，因为怪物攻击一次，然后在英雄第一次攻击后立即死亡。 

恰好等于三角数的健康值也需要正确处理。 为了```
1
1
3 2
```怪物只需要两次攻击，因为`1 + 2 = 3`，所以答案是`4`。 使用严格的`>`而不是`>=`当发现所需的攻击次数时，会错误地需要第三次攻击。 

相等的排序比是另一种边界情况。 如果有两个怪物`(k_1, ATK_1) = (1, 2)`和`(k_2, ATK_2) = (2, 4)`，那么两者都有比率`k / ATK = 1/2`。 任一订单的总成本相同。 比较器必须将其视为平局，而不是强加不一致的排序。 

最后，答案可以超过 32 位整数。 为了`100000`怪物与`HP=1`和`ATK=1`，完成时间为`1,2,...,100000`, 给予

 [
 \frac{100000\cdot100001}{2}=5000050000。 
]

 32 位整数会溢出。 Python整数没有这个问题，但是对应的C++实现需要`long long`。 

## 方法

 直接的暴力方法是尝试所有可能的顺序来彻底杀死怪物。 对于一个固定的顺序，我们可以计算出每个怪物需要攻击的次数，然后模拟累计时间。 这是正确的，因为考虑了所有可能的排序，因此最好的排序必须出现在候选排序中。 

问题在于候选人的数量。 和`n`有怪物`n!`排列，并且评估一个排列需要`O(n)`时间。 因此，最坏情况的工作是`Theta(n * n!)`。 甚至`20! * 20`是关于`4.87 * 10^19`基本的订单处理步骤，远远超出了实际限制。 为了`n=10^5`，排列枚举是不太可行的。 

有用的观察是，怪物所需的总攻击次数在战斗开始之前是固定的。 如果怪物需要`k`攻击，实际的攻击可以被认为是处理时间的工作`k`。 其攻击值`ATK`是该怪物存活的每一秒所付出的成本。 

假设所有怪物都有总攻击值`S`，并考虑一个需要`k`攻击。 如果之后被杀`C`英雄攻击已经发生，它的贡献正是`ATK * C`影响英雄的总伤害。 因此，整个问题变成了调度问题：每个怪物都是一个有处理时间的作业`k`和重量`ATK`，我们希望最小化加权完成时间的总和。 

最优顺序可以通过两个怪物交换论证得出。 考虑怪物`A`和`B`，具有所需的攻击计数`k_A`,`k_B`和攻击值`w_A`,`w_B`。 忽略这两个怪物面前的一切，让现在的时间成为现实`C`。 

如果`A`首先被杀，他们的贡献是

 [
 w_A(C+k_A)+w_B(C+k_A+k_B)。 
]

如果`B`首先被杀，他们的贡献是
 [
 wB(C+k_B)+x_I(S+k_B+x_I)。 
]
 通用条款取消。 推杆`A`首先并不更糟
 [
 k_A w_B \le k_B x_I。 
]
 相当于，
 [
 \frac{k_A}{k_A}\le\frac{k_B}{w_B}。 
]
 所以怪物应该按升序排序`required_attacks / ATK`。 这与标准加权完成时间调度规则中使用的交换参数相同，并且该问题的现有解决方案中出现了相同的跨产品比较。 

暴力破解之所以有效，是因为完整的排序完全决定了每个怪物的完成时间，但它会失败，因为存在多个阶乘排序。 交换参数让我们消除所有包含反转的排序，留下一个全局最优的排序顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n · n!)`|`O(n)`| 太慢了 |
 | 最佳 |`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1.计算每个怪物的最小数量`k`杀死它所需的英雄攻击次数。 我们需要最小的`k`满意的

 [
 \frac{k(k+1)}2\ge 生命值。 
]

自从`HP <= 10^5`,`k <= 447`，因此可以使用预先计算的三角数表有效地找到这些值。 
2.将每个怪物视为一个有处理时间的工作`k`和重量`ATK`。 处理时间意味着怪物死亡之前需要多少英雄回合，而重量意味着英雄在怪物存活的每一秒内受到多少伤害。 
3.按升序对怪物进行排序`k / ATK`。 对比一下就可以理解，不用划分：怪物`A`属于怪物之前`B`当

 [
 k_A ATK_B \le k_B ATK_A。 
]

 这种叉积形式是精确的数学比较，避免了与除法相关的排序问题。 
4.遍历排序好的怪物。 维持`time`，用于杀死所有先前处理的怪物的英雄攻击总数。 对于当前怪物，增加`time`按其所需的攻击次数`k`。 它的死亡发生在这个新的时间，所以它有助于

 [
 攻击力×时间
 ]

 对答案的损害。 
5. 将这些加权完成成本相加，并将结果打印在所需的表格中`Case #x: answer`格式。 

不变量是在处理完第一个之后`i`怪物按顺序排列，`time`正是杀死这些怪物所需的英雄攻击次数，并且`answer`是按该顺序完成相同怪物的所有计划中可能的最小加权伤害贡献。 交换论证表明，每当两个相邻的怪物违反比例顺序时，交换它们不会增加结果。 重复删除每个倒置会产生排序顺序，因此没有其他调度可以具有更小的总成本。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

# The largest possible number of attacks is 447 because
# 447 * 448 // 2 = 100128 >= 100000.
MAX_HITS = 447

triangular = [0]
for k in range(1, MAX_HITS + 1):
    triangular.append(triangular[-1] + k)

def solve(inp=input):
    t = int(inp())
    out = []

    for case_id in range(1, t + 1):
        n = int(inp())
        monsters = []

        for _ in range(n):
            hp, atk = map(int, inp().split())

            # Smallest k such that k * (k + 1) / 2 >= hp.
            k = bisect_left(triangular, hp, 1)

            monsters.append((k, atk))

        # Under the given bounds, distinct rational ratios k / atk
        # are separated by at least 1 / 10^10, much more than the
        # floating-point precision around these values.
        monsters.sort(key=lambda x: x[0] / x[1])

        time = 0
        answer = 0

        for hits, atk in monsters:
            time += hits
            answer += time * atk

        out.append(f"Case #{case_id}: {answer}")

    return "\n".join(out)

if __name__ == "__main__":
    sys.stdout.write(solve())
```三角数数组构建一次。 因为最大的健康是`100000`，所需的攻击次数最多为`447`。`bisect_left`找到第一个达到怪物生命值的三角形数字，准确给出所需的攻击计数。 

每个怪物都存储为`(hits, atk)`。 排序的关键是比率`hits / atk`，按递增顺序。 数学规则基于精确的交叉乘法，但这里的实现可以安全地使用浮点比率，因为`hits <= 447`和`atk <= 100000`。 两个不同的此类分数至少相差`1 / 10^10`，而双精度在以下时间间隔内具有更精细的绝对分辨率：`0`到`447`。 

重要的边界是使用`bisect_left`。 如果健康度正好是三角形，比如`HP=3`，第一个有效值必须是`2`， 不是`3`。 下限搜索正好给出了这一点。 

在最后的穿越过程中，`time`在添加当前怪物的贡献之前更新。 这与战斗顺序相匹配：怪物在每一秒内进行攻击，直到英雄杀死它的那一秒。 因此，怪物在时间完成`C`贡献`ATK * C`。 

答案可能是数十亿或更多，因此实现故意将计算保留在 Python 的任意精度整数中。 

## 工作示例

 对于样本 1，怪物是```
HP  ATK
1   1
2   2
3   3
```他们所需的攻击次数是`1`,`2`， 和`2`。 

| 怪物| 惠普| 攻击力| 所需攻击| 比率`hits / ATK`| 完成时间 | 贡献 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 3 | 3 | 3 | 2 |`2/3`| 2 | 6 |
 | 1 | 1 | 1 | 1 |`1`| 3 | 3 |
 | 2 | 2 | 2 | 2 |`1`| 5 | 10 | 10

 排序的顺序是怪物`3`、怪物`1`、怪物`2`。 总计为`6 + 3 + 10 = 19`，匹配示例输出。 该痕迹显示了为什么具有高攻击值的怪物通常应该尽早被杀死，即使它需要更多的英雄攻击。 

对于样本 2，怪物是```
HP  ATK
3   1
2   2
1   3
```所需的攻击次数为`2`,`2`， 和`1`。 

| 怪物| 惠普| 攻击力| 所需攻击| 比率`hits / ATK`| 完成时间 | 贡献 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 3 | 1 | 3 | 1 |`1/3`| 1 | 3 |
 | 2 | 2 | 2 | 2 |`1`| 3 | 6 |
 | 1 | 3 | 1 | 2 |`2`| 5 | 5 |

 最优顺序是怪物`3`，然后怪物`2`，然后怪物`1`。 总计为`3 + 6 + 5 = 14`。 

这个例子清楚地展示了比率规则。 怪物`3`攻击值最大，只需要一次攻击，所以即使是短暂的存活也是昂贵的。 排序后的比例会自动将其放在第一位。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n log n)`| 计算所需的攻击需要`O(n log 447)`，然后排序占主导地位`O(n log n)`|
 | 空间|`O(n)`| 怪物数组每个怪物存储一对 |

 在所有测试用例中最多有`10^6`怪物，因此总排序工作受相应总和的限制`n log n`条款。 该算法不执行子集枚举、单个秒的模拟或成对的模拟`O(n^2)`处理，这使得它适合所述`10^5`每次测试和`10^6`总界限。 官方声明给出了10秒的时间限制和256MB的内存限制。

 ## 边缘情况

 对于最小尺寸的情况```
1
1
1 1
```三角数搜索发现`k=1`。 排序后的数组包含一个怪物，所以`time`变成`1`答案就变成了`1 * 1 = 1`。 怪物攻击一次后就会死亡，因此死亡后不会造成额外伤害。 

对于精确的三角形边界```
1
1
3 2
```三角形数字开始`0, 1, 3, 6`。`bisect_left`查找索引`2`，所以怪物需要两次攻击。 其完成时间为`2`, 给予`2 * 2 = 4`。 这避免了将平等视为损害不足的常见错误。 

对于比例排序情况```
1
2
1 2
2 3
```第一个怪物需要`1`攻击并具有攻击值`2`, 给定比例`1/2`。 第二个要求`2`攻击并具有攻击值`3`, 给定比例`2/3`。 该算法及时杀死第一个怪物`1`, 贡献`2`，然后及时杀死第二个`3`, 贡献`9`，总共`11`。 反转它们会给出`6 + 6 = 12`，因此仅按攻击值排序或仅按所需攻击排序将错过最佳值。 

对于相等的比率，请考虑```
1
2
1 2
2 4
```两个怪物都有比例`1/2`。 如果先处理第一个，则成本为`2*1 + 4*3 = 14`。 如果先处理第二个，则成本为`4*2 + 2*3 = 14`。 交换条件变为相等，因此任一顺序都是最优的。 

为了最大程度的健康，```
1
1
100000 1
```该算法发现`447`因为

 [
 \frac{446\cdot447}{2}=99681<100000
 ]

 同时

 [
 \frac{447\cdot448}{2}=100128\ge100000。 
]

 因此，怪物在第 447 次英雄攻击时死亡，并且由于其攻击值为`1`，答案是`447`。 

最大尺寸的等怪物箱包含`100000`怪物，每个需要一次攻击并具有攻击值`1`。 每个订单都是等效的。 他们的完成时间是`1`通过`100000`，所以答案是

 [
 1+2+\cdots+100000=5000050000。 
]

 本案例同时锻炼了`O(n log n)`排序实现以及需要能够保存大于的答案的整数类型`2^32`。
