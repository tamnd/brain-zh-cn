 ## 解决方案
 ## 问题理解

 有两个相关的概率问题。 

在第一个问题中，乘客 1 至 (n) 按升序登机。 乘客1丢失了他所分配的座位信息，并统一随机选择(n)个座位中的一个。 如果还有空位，后来的每位乘客都会坐在指定的座位上。 如果已被占用，该乘客也统一从当前空座位中选择。 我们需要最后登机的乘客 (n) 最终坐在座位 (n) 上的概率。 

在第二个问题中，有（m）名乘客和（m）个座位，但现在登机顺序本身是均匀随机排列。 乘客 1 仍然不知道他的指定座位，并且每当乘客发现其指定座位已被占用时，都会使用相同的规则。 我们需要最后登机的人获得自己座位的概率。 

每个测试用例包含(n)和(m)，均最多50个。测试用例最多有50个。 小的数值限制可能表明动态规划，但真正的解决方案要简单得多。 我们可以将两个答案都减少为封闭形式，因此每个测试用例的总工作量是恒定的。 尽管如此，50 的界限还是有用的，因为它允许我们在需要时用小的递归来验证公式，同时避免对大型数值机器的需要。 

第一个边缘情况是 (n=1)。 只有乘客 1，也只有座位 1，因此乘客必须坐在正确的座位上。 用于输入`1 1`，输出是`Case #1: 1.000000 1.000000`。 盲目应用第一个问题的通常 (1/2) 答案的粗心实现会错误地打印 0.5。 

第二个边缘情况是 (n=2)。 乘客 1 以 (1/2) 的概率选择任一座位。 如果他选择座位1，则乘客2是正确的； 如果他选择座位 2，则乘客 2 被迫坐在座位 1。因此第一个答案恰好是 0.5。 用于输入`2 2`，输出是`Case #1: 0.500000 0.750000`。 将第二个公式应用于第一个问题恰好会给出相同的值，但这是巧合，而不是有效的推导。 

第三种边缘情况是（m=1）。 在随机顺序版本中，乘客 1 必然是最后一位乘客，并且只有一个可能的座位，因此第二个答案为 1。 对于输入`1 1`，两个答案都必须恰好为 1。公式 ((m+1)/(2m)) 也给出 1，因此第二个问题不需要特殊分支。 

两个值相等的边界情况也很有用。 用于输入`50 50`，第一个答案是 0.5，因为 (n>1)，而第二个答案是 (51/100=0.51)。 在这种情况下，在第二个公式中意外使用 (n) 而不是 (m) 的实现将会失败。 

## 方法

 直接模拟在概念上很简单。 我们可以枚举每个登机顺序，枚举每个可能的随机座位选择，模拟乘客，并计算有多少种结果让最终乘客坐在正确的座位上。 这是正确的，因为每个基本随机选择和每个登机顺序都可以明确表示。 

问题是结果的数量。 对于随机顺序版本，有 (m!) 种可能的登机排列。 在模拟过程中，最多可以有 (m-1) 个随机座位选择，并且每个这样的选择最多有 (m) 个可能的结果。 因此，一个简单的上限是 (m!\cdot m^{m-1}) 个完整的结果分支，如果直接模拟每个分支，则还有另一个因子 (O(m))。 对于（m=50）来说，这远远超出了任何可行的范围。 即使是更加谨慎的基于国家的暴力也将是不必要的工作。 

蛮力之所以有效，是因为该过程本身很容易模拟，但失败是因为它将每位乘客和每个随机选择视为独立的细节。 关键的观察结果是，几乎每个人都完全没有受到丢失机票的影响。 一旦乘客 1 占据了其他乘客的座位，受影响乘客之前的所有乘客仍然可以正确就座。 唯一的不确定性是座位被盗的乘客。 这将过程分解为相同概率问题的较小副本。 

对于第一个问题，设 (f(k)) 为当有 (k) 名乘客且乘客 1 是唯一没有座位信息的人时，最后一位乘客正确的概率。 乘客 1 有概率 (1/k) 选择座位 1，这立即使其他人都正确。 如果乘客 1 选择座位 (j>1)，则乘客 2 至 (j-1) 不受影响，乘客 (j) 成为新的被替换的乘客。 从那时起，不确定部分与乘客 (j,j+1,\ldots,k) 上的问题完全相同。 

这给出了重现

 [
 f(k)=\frac{1}{k}\left(1+\sum_{j=2}^{k} f(k-j+1)\right)
 =\frac{1}{k}\sum_{r=1}^{k-1}f(r)。 
]

 对于 (f(1)=1)，递归给出 (f(2)=1/2)。 一旦 (f(2)=f(3)=\cdots=f(k-1)=1/2)，我们得到

 [
 f(k)=\frac{(k-1)/2}{k}=\frac{k-1}{2k}。 
]

 这个表达式本身似乎与已知的答案相矛盾，因为重复必须包括乘客 1 作为完全成功分支占据自己座位的事件。 仔细写出递推式和简化的问题给出

 [
 f(k)=\frac{1}{k}+\frac{1}{k}\sum_{r=1}^{k-1}f(r)。 
]

 现在 (f(1)=1), (f(2)=1/2)，如果从 2 到 (k-1) 的所有值都是 (1/2)，

 [
 f(k)=\frac{1}{k}+\frac{1+(k-2)/2}{k}
 =\frac{1}{2}。 
]

 因此，当 (n=1) 时，第一个答案为 1，对于每个 (n>1)，第一个答案为 (1/2)。 这一标准降低也与已发表的问题分析一致。 

第二个问题有额外一层随机性，即乘客1在登机顺序中的位置。 令最后一位乘客为在随机排列中占据最终位置的乘客。 

有一种特别干净的方法来调节乘客 1。乘客 1 以概率 (1/m) 排在最后。 如果发生这种情况，其他所有乘客都已就座，因此乘客 1 统一从剩余的一个座位中选择，该座位必定是座位 1。因此，在这种情况下，最后一位乘客正确的概率为 1。 

以概率 (1-1/m)，乘客 1 不是最后一个。 考虑乘客 1 登机的那一刻。 在他之前登机的每位乘客都必须坐在自己的座位上，因为乘客 1 是座位分配错误的唯一来源，而且他还没有登机。 从乘客 1 开始，剩余的过程与第一个问题具有相同的结构，只是最终的乘客现在是随机排序后缀的最终成员。

该后缀正确结尾的概率为 (1/2)。 因此

 \frac{1}{m}\cdot 1
 +
 \left(1-\frac{1}{m}\right)\cdot\frac12。 
]

 简化，

 [
 g(m)=\frac{1}{m}+\frac{m-1}{2m}
 =\frac{m+1}{2m}。 
]

 对于 (m=3)，这给出 (4/6=2/3)，与样本匹配。 对问题的独立编辑分析给出了相同的封闭形式。 

重要的简化是我们永远不需要模拟流离失所的乘客链。 该链条仅通过其最终最后一位乘客正确的不变概率起作用，一旦至少剩下两名乘客，该概率恰好为（1/2）。

 ## 算法演练

 1. 阅读当前测试用例的 (n) 和 (m)。 这两个值属于不同的子问题，因此必须独立处理。 
2. 当 (n=1) 时，将第一个答案计算为 1，否则计算为 0.5。 对于每个 (n>1)，递归位移过程都会为最终乘客留下特殊座位的两种对称可能性中的一种，给出概率 (1/2)。 
3. 计算第二个答案

 [
 \frac{m+1}{2m}。 
]

 该公式来自于乘客 1 是否是最后一位乘客的条件。 如果他是最后一个，概率为 (1/m)，那么最后一位乘客肯定是正确的。 否则剩余的位移过程贡献概率(1/2)。 

1. 打印两个概率，精确到小数点后六位。 Python 的浮点精度对于 (m\le50) 来说绰绰有余，并且该语句保证第七位十进制数字不正好位于有问题的舍入边界处。 

### 为什么它有效

 第一个问题具有单一的不确定性链。 乘客 1 要么坐在自己的座位上并立即终止链条，要么坐在另一名乘客的座位上并将相同的问题转移给该乘客。 重现表明，至少有两名乘客的每个问题都有概率 (1/2) 以最终乘客正确结束。 

对于第二个问题，以乘客 1 的位置为条件来区分唯一的例外情况。 如果乘客 1 是最后一个，其他人都已经正确就坐，最后剩余的座位是座位 1，所以答案是 1。如果乘客 1 不是最后一个，则所有较早的乘客都是正确的，并且未解析的后缀具有相同的 (1/2) 最终座位概率。 这两个互斥的情况涵盖了所有可能的登机顺序，因此它们的加权和就是所需的概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for case_id in range(1, t + 1):
        n, m = map(int, input().split())

        first = 1.0 if n == 1 else 0.5
        second = (m + 1.0) / (2.0 * m)

        print(f"Case #{case_id}: {first:.6f} {second:.6f}")

if __name__ == "__main__":
    solve()
```输入循环遵循所需的多测试用例格式。 每个测试用例都是独立的，因此不需要从一个用例转移到下一个用例。 

第一个表达式使用 (n=1) 的显式检查。 仅当至少有两名乘客时，值 0.5 才有效。 该边界是第一个答案的主要实现细节。 

第二个表达式直接实现((m+1)/(2m))。 使用浮点除法可以避免意外的整数除法，尽管 Python 3 的`/`运算符已经产生浮点结果。 

最终格式化的字符串完全按照要求使用小数点后六位数字。 不存在整数溢出风险，因为涉及 (m) 的唯一算术运算最多为 50。

 ## 边缘情况

 对于`1 1`，第一个公式检测 (n=1) 并返回 1。第二个公式给出 ((1+1)/(2\cdot1)=1)。 最终输出是`Case #1: 1.000000 1.000000`。 不存在流离失所的乘客，因此没有需要解决的概率链。 

为了`2 2`，第一个问题只有两种可能的初始选择。 乘客 1 以 (1/2) 的概率选择座位 1，产生正确的最终乘客，并以 (1/2) 的概率选择座位 2，产生错误的最终乘客。 因此第一个值为 0.5。 对于第二个问题，乘客 1 排在最后的概率为 (1/2)，在这种情况下成功概率为 1。 当乘客 1 排在第一位时，通常的两人过程给出的概率为 (1/2)。 因此结果是 (1/2+1/2\cdot1/2=3/4)，给出`Case #1: 0.500000 0.750000`。 

为了`1 50`，尽管 (m) 的值很大，但第一个答案必须保持为 1，因为这两个问题是独立的。 第二个答案是（（50+1）/（100）=0.51）。 预期输出是`Case #1: 1.000000 0.510000`。 这会捕获意外对两个答案使用相同参数的实现。 

为了`50 50`，第一个答案是 0.5，因为 (n>1)。 第二个答案是（51/100=0.51）。 预期输出是`Case #1: 0.500000 0.510000`。 这是一个有用的边界测试，因为两个参数都处于最大值并且彼此相等，因此交换 (n) 和 (m) 不会在这里暴露，而错误的第二个公式（例如 (1/2)）则会暴露。 

为了`3 1`，乘客 1 必然是回程实例中唯一的乘客，因此第二个答案恰好是 1。第一个答案是 0.5，因为有 3 名乘客参与固定订单流程。 输出是`Case #1: 0.500000 1.000000`。 这抓住了一个常见的错误，即假设第二个答案总是接近二分之一，而忘记了最后一个乘客 1 的特殊贡献。
