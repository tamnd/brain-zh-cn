 ## 解决方案
 ## 问题理解

 我们最初有一个空堆栈。 每个测试用例没有明确列出操作。 相反，它给出了伪随机生成器的参数，我们必须重现相同的序列`PUSH`和`POP`作为生成器进行操作。 推动在之间创造价值`1`和`m`，而 pop 会删除当前顶部元素（如果存在）。 每次操作后，我们需要堆栈中当前存在的最大值，使用`0`当堆栈为空时。 所需的答案是按位异或`i * maximum_i`综合各项经营指标`i`。 官方限制允许最多`5 * 10^6`一个测试用例中的操作，最多有 50 个测试用例和 256 MB 内存限制。 

的大值`n`决定了溶液的形状。 仅当每次操作的时间恒定时，即使对每个元素重复少量的工作也是可以接受的。 在每次操作后扫描整个堆栈的算法可以大致执行`1 + 2 + 3 + ... + n = n(n + 1) / 2`比较。 为了`n = 5 * 10^6`，这大约是`1.25 * 10^13`比较，这远远超出了10秒的限制所能容忍的。 预期的解决方案必须在 O(1) 时间内处理每个生成的操作。 官方问题页面给出了相同的`5 * 10^6`限制和 10 秒限制。 

有几种边缘情况很容易被错误处理。 第一的，`POP`当堆栈已空时允许。 对于第一个示例，生成的操作以两次弹出开始。 第一个操作使堆栈为空，因此它的贡献是`1 * 0 = 0`; 第二个也做同样的事情。 假设每个弹出都有效的解决方案可能会访问无效的堆栈元素。```
1
1 1 1 4 23333 66666 233333
```这里生成的第一个操作与示例 1 的第一个操作相同，即`POP`，所以正确的输出是`Case #1: 0`。 不检查空性而读取顶部元素的粗心实现将会失败。 

第二个边缘情况是弹出当前最大值并不意味着新的最大值为零。 如果之前的最大值下面的另一个元素仍然存在，则必须重新出现。 这就是为什么仅仅存储一个全局最大值是不够的。 例如，之后`PUSH(3), PUSH(8), POP()`，剩余的最大值为`3`， 不是`0`。 正确的数据结构必须记住与每个堆栈深度相关的最大值。 

第三种边缘情况是重复相同的值。 假设堆栈包含`7, 7, 7`我们弹出一次。 最大还是`7`。 仅存储最大值严格增加的位置的表示可能会失去对这种多重性的跟踪。 前缀最大表示避免了这个问题，因为每个深度都存储自己的最大值。 

最后，生成器本身使用 32 位无符号算术。 Python 整数不会自然溢出，因此每次状态更新`SA`,`SB`， 和`SC`必须减少模数`2^32`。 忽略屏蔽会改变生成的操作，并且即使堆栈逻辑是完美的，也可能会产生错误的答案。 

## 方法

 直接的解决方案是存储每个实际的堆栈值。 在推送时附加该值。 在弹出窗口中，删除最后一个值。 要在每次操作后获得最大值，请扫描整个堆栈并取其最大值。 这是正确的，因为扫描会准确检查堆栈中当前存在的元素。 

问题是重复扫描。 如果堆栈增长到一定大小`n`并且保持很大，第一个查询可能会检查一个元素，然后检查接下来的两个元素，依此类推。 在最坏的情况下，总工作量变为 O(n²)，大约`1.25 * 10^13`堆栈元素检查`n = 5 * 10^6`。 生成器是有意使用的，以便输入本身不会变得巨大，但这并不能使 O(n²) 算法可行。 

关键的观察是我们从堆栈前缀中需要的唯一信息是它的最大值。 考虑几次压入后的堆栈。 在深度`k`，存储第一个中的最大值`k`实际元素。 当有新值时`x`被推入，新的最大值就是`max(previous_maximum, x)`。 当顶部被弹出时，最大值自动变为先前深度存储的值。 

这意味着实际推送的值是不必要的。 例如，假设真实的堆栈是`[4, 2, 9, 3]`。 我们可以将其替换为`[4, 4, 9, 9]`。 最高值`9`是当前最大值。 如果我们弹出一次，表示就会变成`[4, 4, 9]`，其顶部仍然是正确的最大值。 再次弹出就变成了`[4, 4]`, 揭示`4`，与原始堆栈完全相同。 

因此，该结构只是另一个包含前缀最大值的堆栈。 每个操作都变成常数时间。 我们可以在实现中更进一步，因为推送后不再需要实际值。 每个堆栈深度一个 32 位整数就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`p`,`q`,`m`，以及三个生成器状态`SA`,`SB`， 和`SC`。 必须准确地再现生成器，因为操作序列隐含在这些值中。 
2. 分配一堆前缀最大值，其中包含一个额外的槽`0`。 让`depth`表示当前逻辑堆栈中的元素数量。 深度为零的标记意味着空堆栈的最大值可立即为零。 
3. 操作`i`，调用一次生成器来决定操作是push还是pop。 条件是`rng61() % (p + q) < p`。 
4. 如果操作是推送，则调用`rng61()`第二次产生价值`v = rng61() % m + 1`。 增加栈深度并存储`max(stack[depth - 1], v)`在新的深度。 如果堆栈先前为空，则先前的最大值为零，因此存储的值只是`v`。 
5.如果操作是pop，则减少`depth`仅当堆栈非空时。 如果它已经为零，则保持不变。 然后哨兵给出正确的最大值零。 
6. 执行操作后，读取`stack[depth]`作为当前最大值。 异或`i * stack[depth]`进入答案。 乘法使用问题所需的基于一的运算索引。 
7. 毕竟`n`操作，使用所需的值打印累积的 XOR`Case #x: y`格式。 

### 为什么它有效

 不变的是`stack[d]`等于真实堆栈第一个中的最大值`d`元素。 最初`d = 0`，并且空最大值为零。 在推送期间，新的实际堆栈由先前的堆栈组成`d`元素后跟`v`，所以它的最大值恰好是`max(stack[d], v)`，这就是我们深度存储的内容`d + 1`。 在弹出过程中，最后一个真实元素消失，因此剩余堆栈的最大值正是已经存储在深度的值`d - 1`。 因此，不变量在每次操作中都存在，并且读取的值`stack[depth]`始终是所需的最大值。 由于每个贡献在其相应操作之后立即进行异或，因此最终答案正是所需的异或。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

MASK = 0xFFFFFFFF

def rng61(sa, sb, sc):
    sa ^= (sa << 16) & MASK
    sa &= MASK

    sa ^= sa >> 5
    sa &= MASK

    sa ^= (sa << 1) & MASK
    sa &= MASK

    t = sa
    sa = sb
    sb = sc
    sc = (sc ^ t ^ sa) & MASK

    return sc, sa, sb, sc

def solve():
    t = int(input())
    out = []

    for case_id in range(1, t + 1):
        n, p, q, m, sa, sb, sc = map(int, input().split())

        # stack[d] = maximum of the logical stack when its size is d.
        # stack[0] = 0 represents the empty stack.
        stack = array('I', [0]) * (n + 1)
        depth = 0
        ans = 0
        total = p + q

        for i in range(1, n + 1):
            r, sa, sb, sc = rng61(sa, sb, sc)

            if r % total < p:
                r, sa, sb, sc = rng61(sa, sb, sc)
                value = r % m + 1

                previous_max = stack[depth]
                depth += 1

                if value > previous_max:
                    stack[depth] = value
                else:
                    stack[depth] = previous_max
            else:
                if depth > 0:
                    depth -= 1

            ans ^= i * stack[depth]

        out.append(f"Case #{case_id}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`rng61`函数镜像 C++ 生成器。 明确的`& 0xFFFFFFFF`需要操作，因为 C++`unsigned int`算术换行取模`2^32`，而 Python 整数则无限增长。 每次 XOR 和左移之后的掩码使得每个后续操作的行为就像对 32 位无符号值所做的那样。 

数组称为`stack`不包含原始推送值。 在索引处`d`，它包含第一个的最大值`d`元素。 这已经足够了，因为对堆栈进行的唯一查询就是其最大值。 

该数组被预先分配给`n + 1`无符号 32 位整数。 Python 列表将存储对 Python 整数对象的引用，并且最大深度可能消耗超过 100 MB。 这`array('I')`表示每个条目使用 4 个字节，因此 500 万深度需要大约 20 MB 的堆栈空间。 

这`depth`变量是逻辑堆栈大小。 推送写入`stack[depth + 1]`，而有效的 pop 会递减`depth`。 保持`stack[0] = 0`当堆栈变空时，不再需要特殊的最大值。 

对于每个操作决策，必须调用生成器一次。 在推送时，必须为推送的值再次调用它。 以不同的顺序调用它会改变整个后续生成器状态。 答案在堆栈操作后更新，因为`a_i`指的是之后的最大值`i`第-次操作。 

Python 的整数对于最终表达式也很有用。 最大的产品最多是`5 * 10^6 * 10^9 = 5 * 10^15`，它非常适合 Python 的整数表示形式，也适合有符号的 64 位整数。

 ## 边缘情况

 对于空栈弹出，使用示例 1 的第一个操作作为具体案例：```
1
1 1 1 4 23333 66666 233333
```第一个生成的随机值选择`POP`。 逻辑深度从零开始，因此弹出条件`if depth > 0`为 false 并且深度保持为零。 哨兵`stack[0]`为零，贡献`1 * 0 = 0`。 输出是`Case #1: 0`。 不会发生超出有效范围的堆栈访问。 

对于重复的相等值，请考虑：```
1
5 1 1 1 65536 65536 65536
```所有三个生成器状态均以偶数开始。 转换仅使用移位、异或和赋值，因此每个状态都保持偶数。 和`p = q = 1`，偶数随机值满足`value % 2 < 1`，所以每一个操作都是一个push。 因为`m = 1`，每个生成的值是`1`。 前缀最大堆栈变为`[0, 1, 1, 1, 1, 1]`。 贡献是`1, 2, 3, 4, 5`，其异或为`1`。 重复的最大值不需要特殊处理。 

对于最大尺寸边界，具有相同的构造`n = 5 * 10^6`产生 500 万次推送的价值`1`。 堆栈达到其最大可能深度，但程序仅存储 500 万个 32 位前缀最大值，大约 20 MB。 答案是所有整数的异或`1`通过`5,000,000`。 自从`5,000,000 mod 4 = 0`，异或等于`5,000,000`。 这会在允许的最大范围内测试内存表示和循环边界`n`。 

对于操作索引边界，使用示例 1 的前三个操作：```
1
3 1 1 4 23333 66666 233333
```操作是`POP, POP, PUSH(1)`。 前两项贡献为零。 在操作三时，最大值为一，因此贡献为`3 * 1 = 3`。 答案是`3`。 在 XOR 表达式中使用从零开始的循环索引此时会错误地贡献零，因此这种情况会捕获该差一错误。 

对于生成器边界，相同的测试还验证推送消耗两个随机数，而弹出仅消耗一个。 在示例 1 中，前两个操作是弹出操作，因此每个操作仅调用一次生成器。 第三个操作是推送，因此操作选择调用之后紧接着是值生成调用。 如果实现在弹出后调用生成器获取值，则所有后续操作都会发生变化，并且最终的 XOR 会变得不正确。 Python 实现遵循原始生成器的确切调用顺序。
