 ## 解决方案
 ## 问题理解

 我们有一个完整的城市无向加权图。 城市`i`有风险值`r[i]`， 和`d[i][j]`是城市之间的直接旅行距离`i`和`j`。 一个查询给出两个端点`u`和`v`，以及风险阈值`w`。 

对于该查询，我们想要从`u`到`v`在一个限制下：航线上每个中间城市最多必须有风险`w`。 无论风险如何，端点本身都是允许的，因为该限制适用于两个端点以外的城市。 直接边从`u`到`v`因此，当`u != v`。 

输入包含最多 50 个独立测试用例。 每个测试用例最多200个城市，最多20000条查询。 距离矩阵已经给出了每对城市之间的边缘，因此该图是密集的。 自从`n`只有200，一个`O(n^3)`预处理算法实用。 大量的查询计数改变了我们应该避免的情况：为每个查询独立运行完整的最短路径计算将过于昂贵。 

估计暴力成本的一个有用方法是取最大值，`n = 200`和`q = 20,000`。 Floyd-Warshall 计算需要大约`200^3 = 8,000,000`一个查询的松弛迭代。 对所有查询重复此操作，大致得出`1.6 * 10^11`在考虑 Python 开销之前，最坏情况下的迭代。 我们需要使昂贵的图计算独立于查询数量。 

有几种边缘情况很容易被错误处理。 首先，端点不必满足阈值。 例如，考虑```
1
2 1
10 1
0 5
5 0
1 2 1
```根本没有中间城市，所以从城市1到城市2的直达路线是有效的，答案是`5`。 消除每个风险超过的城市的解决方案`w`，包括端点，会错误地声明该路线不可能。 

其次，端点可以是同一个城市。 例如，```
1
1 1
100
0
1 1 1
```答案是`0`。 该城市不需要满足阈值，因为我们已经到达目的地，并且没有使用中间城市。 

第三，一条路径可以使用多个允许的中间城市。 例如，```
1
3 1
1 1 2
0 10 100
10 0 10
100 10 0
1 3 1
```有门槛`1`，城市2被允许作为中间城市，所以路线`1 -> 2 -> 3`成本`20`，这比直接成本更好`100`。 仅检查直接边缘或仅检查一个中间城市而不允许重复 Floyd-Warshall 松弛的解决方案将错过这一改进。 

“其他城市”一词还意味着阈值是对中间顶点的限制，而不是对整个路径的顶点集的限制。 这种区别是解决方案背后的核心细节。 

## 方法

 一种简单的方法是独立处理每个查询。 对于查询`(u, v, w)`，我们可以从原始距离矩阵开始并运行 Floyd-Warshall，同时只允许具有`r[i] <= w`作为中间顶点。 Floyd-Warshall 在这里是正确的，因为在处理了一组允许的中间城市之后，`dist[i][j]`代表从最短路径`i`到`j`其内部顶点属于该集合。 

问题是重复工作。 和`n = 200`, 一场 Floyd-Warshall 运行成本`O(n^3) = O(8 * 10^6)`。 和`q = 20,000`查询，最坏的情况是`O(qn^3)`， 大约`1.6 * 10^11`弛豫操作。 图本身在查询之间不会改变，只有最大允许风险会改变，因此重新计算相同的松弛是浪费的。 

关键的观察是，允许的中间城市集合单调增长为`w`增加。 假设我们按风险对所有城市进行排序。 对于较小的门槛，也许只有最安全的城市可以作为中间。 当阈值增加到足以包含下一个城市时，我们不需要重新计算之前的所有工作。 我们可以采用当前的最短路径矩阵，并使用新启用的城市执行一个 Floyd-Warshall 阶段。 

这正是弗洛伊德-沃歇尔的结构。 它是`k`第阶段添加顶点`k`可以在内部使用的顶点集。 在这里，我们只是根据城市风险而不是城市指数来选择这些阶段的顺序。 

我们可以按升序处理查询`w`。 在浏览排序的查询时，我们逐步激活风险最高为当前查询阈值的每个城市。 每当一座城市变得活跃时，我们就会在其中运行一个 Floyd-Warshall 放松阶段。 毕竟城市`r[i] <= w`已激活，矩阵包含精确使用该查询允许的中间城市的最短路径。 

端点在概念上需要特殊考虑，但矩阵中不需要特殊修改。 即使`u`或者`v`风险大于`w`，直接边`u -> v`仍然存在，并且允许 Floyd-Warshall 矩阵使用任一端点作为源或目的地。 我们只控制哪些顶点用作中间顶点。 

比较结果为：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(qn^3)`|`O(n^2)`| 太慢了 |
 | 最佳 |`O(n^3 + q log q)`|`O(n^2 + q)`| 已接受 |

 这`q log q`术语来自对查询进行排序。 弗洛伊德-沃歇尔阶段有助于`O(n^3)`因为每个`n`城市仅被激活一次。 

## 算法演练

 1. 读取每个城市的风险和完整的距离矩阵。 将矩阵保留为当前最短路径矩阵，最初仅包含直接行进距离。 
2. 按风险值对城市指数进行排序。 排序顺序确定每个城市何时可用作中间顶点。 
3. 读取所有查询并将每个查询及其原始位置存储在一起。 按阈值对查询进行排序`w`，因为按此顺序处理它们意味着允许的中间城市集只会增长。 
4. 维护一个指向已排序城市列表的指针。 对于当前查询阈值`w`，激活每一个风险最大的城市`w`。 对于每个新激活的城市`k`，执行 Floyd-Warshall 松弛```
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```对于每对`i, j`。 

这里的顺序很重要。 城市激活一次，待所有风险较小的城市都激活后才进行放松。 这与标准 Floyd-Warshall 不变量相匹配，其中风险顺序取代了数字顶点顺序。 
5. 毕竟风险最大的城市`w`已被激活，`dist[u][v]`是查询的答案。 将其存储在查询的原始位置，以便最终输出保持输入顺序。 
6. 按照原始查询顺序打印答案，前面加上所需的内容`Case #x:`标头。 

### 为什么它有效

 考虑一下刚刚经过一个城市的那一刻`k`已被激活。 较早激活的所有具有较小或相同风险的城市都已可用作中间顶点。 加工前`k`,`dist[i][j]`是中间城市属于已激活集合的最短路径。 添加后变得可能的任何新改进的路径`k`有形式`i -> ... -> k -> ... -> j`，双方仅使用之前激活的中间城市。 Floyd-Warshall 放松法通过以下方式准确检查了这种可能性：`dist[i][k] + dist[k][j]`。 

通过激活顺序归纳，激活每个风险最大的城市后`w`,`dist[i][j]`是中间城市风险最大的最短路径`w`。 由于端点不受限制，这正是查询允许的路由集。 因此`dist[u][v]`是必需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    output = []

    for case_id in range(1, t + 1):
        n, q = map(int, input().split())
        risk = list(map(int, input().split()))

        dist = [list(map(int, input().split())) for _ in range(n)]

        cities = sorted(range(n), key=risk.__getitem__)

        queries = []
        for idx in range(q):
            u, v, w = map(int, input().split())
            queries.append((w, u - 1, v - 1, idx))

        queries.sort()

        ans = [0] * q
        city_ptr = 0

        for w, u, v, idx in queries:
            while city_ptr < n and risk[cities[city_ptr]] <= w:
                k = cities[city_ptr]

                dk = dist[k]

                for i in range(n):
                    di = dist[i]
                    dik = di[k]

                    for j in range(n):
                        candidate = dik + dk[j]
                        if candidate < di[j]:
                            di[j] = candidate

                city_ptr += 1

            ans[idx] = dist[u][v]

        output.append(f"Case #{case_id}:")
        output.extend(map(str, ans))

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```实现的第一个主要部分直接将矩阵读入`dist`。 我们在整个算法中改变这个矩阵，所以在城市被激活后，`dist`包含使用所有当前可用的中间城市的最佳距离。 

这`cities`数组存储城市索引而不是风险值本身。 排序依据`risk.__getitem__`给出将顶点引入 Floyd-Warshall 的确切顺序.

 查询存储为`(w, u, v, original_index)`并排序`w`。 原始索引是必要的，因为排序改变了计算答案的顺序，而输出必须遵循输入的顺序。 

这`while`循环激活所有满足条件的城市`risk[city] <= w`。 对比是故意的`<=`， 不是`<`。 允许风险等于查询阈值的城市。 

对于每个激活的城市`k`，嵌套循环执行一个完整的 Floyd-Warshall 阶段。 变量`dk`,`di`， 和`dik`是用于减少 Python 索引开销的本地引用。 由于 C++ 的时间限制相对宽松，但 Python 的每次操作成本明显更高，因此当矩阵达到其最大尺寸时，这些小的优化就很重要。 

松弛使用 Python 整数，因此不存在整数溢出问题。 最短简单路径最多使用`n - 1`边，并且每条边至多`10^5`，无论如何，答案都在 Python 的整数范围内。 

端点永远不会根据其风险而被删除。 矩阵始终包含每条直接边，并且算法仅限制选择作为 Floyd-Warshall 中间点的顶点。 因此，诸如以下的查询`u = 1`,`v = 2`,`w = 1`即使城市 1 存在风险，仍然有效`100`。 

自查询情况也无需特殊处理即可工作，因为`dist[u][u]`从零开始，并且不能通过最短路径松弛变为正值。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n^3 + q log q)`| 每个城市都会造成一个`O(n^2)`Floyd-Warshall 阶段，所有查询都排序一次 |
 | 空间|`O(n^2 + q)`| 距离矩阵取`O(n^2)`，而存储的查询和答案则需要`O(q)`|

 为了`n <= 200`，预处理只需要`n`弗洛伊德-沃歇尔阶段，或大约`8 * 10^6`最大测试用例中的配对松弛。 这些查询在预处理后仅添加排序工作和恒定时间查找。 内存使用量也适中，因为算法只保留一个`n x n`矩阵，而不是为每个可能的阈值存储单独的最短路径矩阵。

 ## 边缘情况

 第一个边缘情况是风险高于阈值的端点。 在`case3`, 城市1有风险`100`，而查询阈值仅为`1`。 该图有两个城市和直线距离`5`。 不需要中间城市，所以答案是`5`。 激活循环仅控制哪个城市可以作为`k`处于弗洛伊德-沃歇尔阶段。 它永远不会从矩阵中删除城市 1，所以`dist[0][1]`遗迹`5`。 

第二个边缘情况是从城市到其自身的查询。 在`case2`，唯一有风险的城市`7`，而第一个查询使用阈值`1`。 不需要城市作为中间顶点，因为出发城市已经是目的地。 对角线条目开始为`0`，每个 Floyd-Warshall 更新都有以下形式`dist[i][i] <= dist[i][k] + dist[k][i]`，因此零仍然是最佳值。 答案是`0`。 

第三个边缘情况是平等边界。 在`case4`，城市2恰好有风险`2`，查询阈值为`2`。 激活循环中的条件是`risk[cities[ptr]] <= w`，因此城市 2 变得可用。 路线`1 -> 2 -> 3`成本`10 + 10 = 20`，提高直接距离`100`。 使用`< w`相反，会错误地让城市 2 禁用并返回`100`。 

第四种边缘情况是可能需要多个中间城市。 在`case5`，从城市 1 到城市 4 的路线可以同时使用城市 2 和城市 3，给出`8 + 7 + 6 = 21`当所有城市都可用时。 对于从城市2到城市4的查询，最佳路线是`2 -> 3 -> 4`, 成本核算`7 + 6 = 13`。 连续的 Floyd-Warshall 阶段会发现这些路径，因为每个阶段都允许新激活的城市与已经通过早期城市形成的路径相结合。 

最后的微妙之处是查询排序。 查询在内部按阈值排序，因此矩阵以正确的单调顺序演化。 它们的原始索引被保留，答案被写回这些位置。 如果没有该索引，计算值将是正确的，但可能会以错误的顺序出现在输出中。
