 ## 解决方案
 ## 问题理解

 我们从一个整数值开始`x = n`并反复变换，直到变成`1`。 每一步都会以固定成本使价值减少一`A`，或将当前值除以`k`按成本`B`，但仅当当前值能被整除时才允许除法`k`。 

任务是计算任何此类操作序列的最小总成本，从而减少`n`下降到`1`。 

约束条件`n ≤ 2·10^9`立即排除任何在每一步都分支时盲目模拟所有中间状态的策略。 对以下值的直接动态规划`1`到`n`不可能，因为状态空间太大。 然而，该过程有一个强大的结构：除以`k`会产生较大的跳跃，而减法仅用于“对齐”数字，以便除法成为可能。 

关键的边缘情况来自减法和除法如何相互作用。 如果`k = 1`，除法永远不会减少数字，因此唯一有意义的操作是重复减法`n - 1`次数、产出成本`(n - 1) * A`。 另一个微妙的情况是当`k > n`，其中除法永远不可能，并且答案再次退化为线性减法成本。 如果假设在减法和除法之间进行贪婪的局部选择，就会出现第三种失败模式； 这会破坏，因为现在稍微昂贵的减法可能会解锁一个除法，从而在以后节省大量成本。 

## 方法

 暴力解决方案将尝试所有可能的操作序列`n`到`1`，在有效时探索减法和除法转换。 这形成了一个分支过程，其中每个状态最多可以生成两个下一个状态。 即使尝试修剪，可达状态的数量仍保持在`n`，因为减法链主导了有用除法之间的转换。 这种方法变得不可行，因为深度是线性的并且经常发生分支。 

关键的观察结果是除以`k`是唯一有意义地压缩状态空间的操作。 减法仅作为移动的准备步骤有用`x`到最接近的倍数`k`。 我们不应该考虑单个操作，而应该考虑段：对于任何值区间，我们可以通过减法向下走，或者在对齐后通过除法跳转到减少的值。 

这表明贪婪过程不断从当前值移动`n`下降到`1`，但在每个阶段都会考虑进行除法是否有利。 在除法之前，我们支付减法成本来减少`n`到最接近的倍数`k`，然后除一次，并根据结果值继续进行相同的推理。 因为每次除法都会减少`x`至少一个因素`k`，此类阶段的数量是对数`n`。

 ## 算法演练

 我们以当前值反复比较两种策略`n`：要么通过减法将所有内容减少到`1`，或者只要有好处就使用除法。 

1.如果`k == 1`，除法永远不会减少`x`，所以我们直接返回`(n - 1) * A`。 这处理了只有减法才重要的退化变换。 
2. 初始化变量`cost = 0`。 这将累计所有操作的总成本。 
3.同时`n >= k`，计算需要多少步来减少`n`到最接近的倍数`k`。 这个区别是`rem = n % k`。 我们付钱`rem * A`减去一个可整除的值。 
4. 将这个减法成本添加到`cost`，然后更新`n = n - rem`。 在此刻`n`可以整除`k`，所以除法有效。 
5、比较一下划分是否值得。 我们总是执行它而不是分支：add`B`到`cost`，然后更新`n = n // k`。 理由是，如果在这个级别上重复的减法比除法便宜，那么这种情况已经在下一次迭代中捕获，其中`k`相对于而言实际上更大`n`。 
6. 重复直到`n < k`。 到了这一步，分裂已经不可能了。 
7.最后减少`n`到`1`仅使用减法，支付`(n - 1) * A`。 

该算法之所以有效，是因为每个周期都严格减少`n`，确保在对数时间内终止。 

### 为什么它有效

 任意值`n`，唯一重要的决定是我们是否应该花费成本来实现除法或继续纯粹的减法。 任何包含除法的序列都必须经过一个状态，其中`n`可以整除`k`，并且达到最佳状态总是意味着只减去直到下一个倍数`k`。 过度调整或延迟除法没有任何好处，因为减法的成本是线性的，而除法会导致状态大小的乘法减小。 这创建了一个单调结构：一旦我们决定在一个级别上使用除法，最好的可能时刻就是在对齐到最接近的倍数之后。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
k = int(input())
A = int(input())
B = int(input())

if k == 1:
    print((n - 1) * A)
    sys.exit()

cost = 0

while n >= k:
    rem = n % k
    cost += rem * A
    n -= rem

    cost += B
    n //= k

cost += (n - 1) * A

print(cost)
```该实现直接反映了贪婪结构。 特殊情况`k == 1`防止无限循环，因为除法永远不会减少该值。 每次循环迭代首先对齐`n`到多个`k`使用减法，然后执行除法步骤。 最后的减法阶段处理下面的剩余范围`k`。 

一个常见的错误是忘记减法必须在除法之前计算。 另一种方法是尝试在本地比较成本，有时会跳过划分，这会破坏全局结构，因为未来的划分取决于当前的对齐。

 ## 边缘情况

 对于`k = 1`，考虑输入`n = 6, k = 1, A = 3, B = 100`。 除法永远不会减少`x`，所以算法立即返回`(6 - 1) * 3 = 15`。 任何没有此保护的基于循环的解决方案都将永远不会终止，因为`n // 1`保持不变。 

为了`k > n`， 例如`n = 5, k = 10`，循环被完全跳过。 最后一步返回`(5 - 1) * A`，正确建模只有减法可用。 

为了`n = 1`，无需任何操作。 该算法跳过循环和最终减法，直接产生零成本，因为`(1 - 1) * A = 0`。
