 ## 解决方案
 ## 问题理解

 我们给出了数轴上的几个点。 每个点只是一个整数坐标。 我们希望保留这些点的子集，以便控制剩余点的分布，特别是最大和最小保留点之间的差异不得超过给定的限制`d`。 

任务不是直接选择子集，而是确定必须删除的最小点数，以便剩余点最多适合某个长度区间`d`。 

关键的观察是，一旦我们决定了剩余集合的最左边和最右边的点，它们之间的所有内容都可能按排序顺序保留。 这使得结构本质上是一维的，排序成为核心工具。 

限制很小：`n ≤ 100`并且坐标也以 100 为界。这立即告诉我们，即使是二次解也是可以接受的，并且扫描后的排序很容易足够快。 除此之外的任何东西，比如指数子集，都是不必要的，但由于输入大小较小，在技术上仍然可行。 

当所有点都位于 ≤ 范围内时，就会出现微妙的边缘情况`d`。 在这种情况下，不需要删除。 另一个边缘情况是当`d = 0`。 那么只有相同的坐标才能保持在一起，这意味着我们实际上正在寻找单个值的最大频率。 例如，输入`3 0`有积分`1 2 1`应该保留两个`1`s 并删除一个点。 

一个幼稚的错误是尝试贪婪地删除极值点而不排序或不考虑所有有效窗口。 例如，迭代删除当前最小值或最大值可能会失败，因为删除一个极端可能会使另一个先前有效的窗口变得次优。 

## 方法

 思考这个问题的蛮力方法是尝试每一个可能的点子集并检查其直径是否至多`d`。 对于每个子集，计算最小值和最大值并验证约束。 这是正确的，因为它探索了所有可能性，但它在计算上是不可行的，因为有`2^n`子集。 和`n = 100`，这彻底爆炸了。 

一旦我们对点进行排序，问题的结构就会变得简单得多。 排序后，任何直径≤的有效点集`d`删除一些元素后，必须对应于此排序数组中的连续段。 我们不需要选择任意子集，而是只需要找到最大的连续块，其中`a[r] - a[l] ≤ d`。 这将问题简化为找到满足差异约束的最长窗口，这是经典的两指针模式。 

我们滑动左指针并尽可能扩展右指针，同时保持约束。 每当违反约束时，我们就会向前移动左指针。 最大有效窗口给出了我们可以保留的最大点数，答案是`n - best_window_size`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(1) | O(1) | 太慢了|
 | 排序+两个指针| O(n log n) | O(n log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对点坐标数组进行非降序排序。 排序至关重要，因为它可以将直径检查简化为间隔端点之间的简单差异。 
2.初始化两个指针`l = 0`并迭代`r`从左到右。 想法是治疗`r`作为候选有效段的扩展端点。 
3. 对于每个位置`r`,检查当前段是否`[l, r]`满足`a[r] - a[l] ≤ d`。 这直接代表当前子集的直径。 
4. 如果违反条件，则移动`l`向前直到条件再次有效。 每增量`l`删除当前窗口中的最小元素，这是减小排序数组直径的唯一方法。 
5. 在每一步中，计算有效窗口的大小`r - l + 1`并跟踪最大此类尺寸。 这代表了我们可以保留的最大子集。 
6.全部处理完毕后`r`，将答案计算为`n - best_window_size`，因为所有不在最佳窗口内的内容都必须被删除。 

### 为什么它有效

 排序保证任何达到最小值和最大值的子集对应于按排序顺序的连续范围。 两指针过程维护一个始终满足直径约束的窗口。 每当违反约束时，恢复有效性的唯一方法是将左边界向右移动，因为除非极值发生变化，否则删除内部元素不会影响最大最小间隙。 这确保了考虑每个有效的候选窗口，而不会丢失任何最佳配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
a = list(map(int, input().split()))

a.sort()

l = 0
best = 0

for r in range(n):
    while a[r] - a[l] > d:
        l += 1
    best = max(best, r - l + 1)

print(n - best)
```排序步骤是将问题转换为单调序列上的滑动窗口。 如果不进行排序，直径条件将无法对应于简单的左右差异，并且两指针方法将失败。 

这`while`循环确保在更新最佳答案之前当前窗口始终有效的不变性。 重要的是，`l`只向前移动，因此指针移动的总数是线性的。 

## 工作示例

 ### 示例 1

 输入：```
3 1
2 1 4
```排序数组：`[1, 2, 4]`| r | 我| 窗口| a[r] - a[l] | a[r] - a[l] | 有效 | 最好的|
 | ---| ---| ---| ---| ---| ---|
 | 0 | 0 | [1] | 0 | 是的 | 1 |
 | 1 | 0 | [1,2]| 1 | 是的 | 2 |
 | 2 | 1 | [2,4]| 2 | 否 → 调整 l | 2 |

 什么时候`r = 2`, 窗户`[1,2,4]`无效，因为`4 - 1 = 3 > 1`。 我们搬家`l`直到窗口变成`[2,4]`，这仍然违反，所以我们再次移动到`[4]`。 

最终最佳窗口大小为`2`，所以答案是`3 - 2 = 1`。 

这说明最优解不一定包含最小元素； 删除它可以解锁有效的较大段。 

### 示例 2

 输入：```
5 0
1 2 2 3 2
```排序数组：`[1, 2, 2, 2, 3]`| r | 我| 窗口| a[r] - a[l] | a[r] - a[l] | 最好的|
 | ---| ---| ---| ---| ---|
 | 0 | 0 | [1] | 0 | 1 |
 | 1 | 1 | [2,2]| 0 | 2 |
 | 3 | 1 | [2,2,2]| 0 | 3 |
 | 4 | 2 | [2,3]| 1 > 0 → 移位 l | 3 |

 最好的窗口是`3`，所以答案是`5 - 3 = 2`。 

这证实了`d = 0`case 的行为就像选择最常见的值。

 ## 边缘情况

 当所有点都相同时，排序会产生一个常量数组，并且窗口始终满足条件，无论`d`。 该算法将窗口扩展至完整尺寸并正确返回零移除。 

什么时候`d = 0`，只有相等的值才能共存。 滑动窗口自然地折叠成相同数量的块，并且最大窗口恰好对应于任何坐标的最大频率。 

当一个值远远超出其他值时，排序会将其放在一端。 窗口将暂时包含它，然后在它违反约束时立即缩小，确保将其排除在外，除非它可以放入有效的段内。
