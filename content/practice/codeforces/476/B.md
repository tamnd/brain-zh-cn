 ## 解决方案
 ## 问题理解

 Drazil 发送一系列移动命令。 每个`'+'`将 Dreamoon 向右移动一步，并且每`'-'`向左移动一步。 

我们知道原始命令字符串以及 Dreamoon 收到的字符串。 接收到的字符串可能包含`'?'`字符，代表无法识别的命令。 对于每一个`'?'`、Dreamoon自主选择`'+'`或者`'-'`以相同的概率。 

任务是计算 Dreamoon 在遵循原始命令序列时到达的位置完全相同的概率。 

字符串的长度最多为 10。该约束完全改变了问题的性质。 即使接收到的字符串中的每个字符都是`'?'`，只有$2^{10} = 1024$可能的解释。 在有限的时间内，列举每一种可能性都是微不足道的。 

主要挑战不是效率，而是正确计算概率。 每一个任务的`'?'`字符的可能性是相同的，因为每个未知命令都是由独立的公平抛硬币决定的。 

一个常见的错误是逐个字符地比较字符串而不是比较最终位置。 例如：```
s1 = "++--"
s2 = "+?+-"
```不同的命令序列仍可能产生相同的最终位置。 目的地很重要，而不是移动的确切顺序。 

另一个容易犯的错误是忘记所有分配的可能性都是相等的。 考虑：```
s1 = "+"
s2 = "?"
```有两种可能的结果，`'+'`和`'-'`。 只有一个到达目标位置，所以答案是`0.5`， 不是`1`。 

当无论如何都无法到达目标位置时，就会出现第三种边缘情况。`'?'`选择的字符：```
s1 = "+++"
s2 = "?--"
```目标位置是`+3`。 接收到的字符串只能在以下位置结束`-1`或者`-3`。 正确的概率是`0`。 

## 方法

 最直接的解决办法就是暴力破解。 

首先计算 Drazil 想要的目的地。 然后考虑每一种可能的替代方案`'?'`接收到的字符串中的字符。 对于每个分配，模拟生成的运动序列并计算其最终位置。 计算有多少作业达到了目标位置。 

如果有`k`未知命令，确切地说有`2^k`作业。 由于字符串长度永远不会超过 10，因此最坏的情况也只有 1024 次赋值。 即使是简单的递归搜索也非常快。 

这种蛮力方法之所以有效，是因为每项任务都对应于抛硬币的一个同等可能的结果。 如果`good`任务达到目标并且有`2^k`总分配，期望的概率是：$$\frac{good}{2^k}$$还有一种组合观察。 我们可以计算有多少个任务，而不是枚举任务`'+'`需要在未知位置中进行选择并使用二项式系数。 这是可行的，因为只有最终的位移很重要。 

对于这个问题，微小的约束使得枚举更简单，更容易正确实现。 这已经足够优化了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| O(2^k \cdot n) | O(2^k \cdot n) | O(k) | 已接受 |
 | 组合计数| O(n) | O(1) | O(1) | 已接受 |

 这里`k`是的数量`'?'`字符和`n ≤ 10`。 

## 算法演练

 1. 计算原始字符串产生的目标位置。 

对待`'+'`作为`+1`和`'-'`作为`-1`，然后对所有运动求和。 
2. 数一数有多少个`'?'`字符出现在接收到的字符串中。 

这些位置是该过程中唯一不确定的部分。 
3. 使用深度优先搜索来生成未知命令的所有可能的替换。 

在每个`'?'`，分为两种可能性：`'+'`和`'-'`。 
4. 处理完所有位置后，计算最终的位置。 

如果等于目标位置，则增加成功分配的数量。 
5. 跟踪探索的作业总数。 

递归的每一片叶子都对应一个同样可能的结果。 
6. 输出：$$\frac{\text{successful assignments}}{\text{total assignments}}$$### 为什么它有效

 每个`'?'`代表一次独立公平的抛硬币。 替换所有未知位置会准确生成可能结果的样本空间。 递归访问每个结果一次且仅一次。 

对于每个结果，我们检查其最终位置是否等于目标位置。 当所有结果的可能性相同时，成功结果的数量除以结果总数正是概率的定义。 由于未知命令的每次分配都有概率$(1/2)^k$，计算有利的作业就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s1 = input().strip()
s2 = input().strip()

target = 0
for ch in s1:
    target += 1 if ch == '+' else -1

good = 0
total = 0

def dfs(idx, pos):
    global good, total

    if idx == len(s2):
        global target
        total += 1
        if pos == target:
            good += 1
        return

    if s2[idx] == '+':
        dfs(idx + 1, pos + 1)
    elif s2[idx] == '-':
        dfs(idx + 1, pos - 1)
    else:
        dfs(idx + 1, pos + 1)
        dfs(idx + 1, pos - 1)

dfs(0, 0)

print("{:.12f}".format(good / total))
```第一部分计算 Drazil 想要的目的地。 

递归函数从左到右处理接收到的字符串。 参数`pos`存储处理以索引结尾的前缀后到达的位置`idx - 1`。 

对于已知命令，只有一个延续。 为了`'?'`有两个延续，对应于抛硬币的两个同样可能的结果。 

当递归到达字符串末尾时，就构建了一个完整的赋值。 我们增加总计数并检查结果位置是否与目标匹配。 

答案是成功作业与所有作业的比率。 由于赋值次数最多为 1024，因此递归是完全安全的。

 ## 边缘情况

 考虑：```
+
?
```目标位置是`+1`。 未知命令可以变成`'+'`或者`'-'`。 递归恰好生成两个赋值。 一到达位置`+1`，另一个达到`-1`。 算法返回`1/2 = 0.5`。 

考虑：```
+++
?--
```目标位置是`+3`。 接收到的字符串中唯一可能的最终位置是`-1`和`-3`。 在枚举期间，没有任何分配与目标匹配。 成功计数仍然为零，所以答案是`0.0`。 

考虑：```
+-
??
```目标位置是`0`。 递归探索了四个作业。 两端在位置`0`，一处`+2`，和一个在`-2`。 该算法计算两次成功的分配并输出`2/4 = 0.5`。 

这些示例涵盖了概率为分数、目标不可能实现以及多个不同的分配导致相同目的地的棘手情况。 计数方法可以自然地处理所有这些问题。
