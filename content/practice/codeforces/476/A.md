 ## 解决方案
 ## 问题理解

 Dreamoon 想要到达楼梯顶部，里面有`n`步骤。 每个动作可以覆盖 1 步或 2 步。 在所有可能的方法中达到准确的步骤`n`，我们需要用来整除的移动次数`m`。 

该任务不要求不同序列的数量。 它要求尽可能最小的移动次数，该次数是`m`并且仍然允许 Dreamoon 准确到达顶峰。 如果不存在这样的移动计数，我们必须打印`-1`。 

限制非常小。 楼梯高度最多为 10000 并且`m`最多为 10。即使对所有可能的移动计数进行简单的线性扫描也足够快。 不需要动态规划、图搜索或组合学。 

关键的观察来自于理解哪些移动计数是可能的。 

如果每次移动都是 2 步移动，则移动次数尽可能少。 该最小值是`ceil(n / 2)`。 

如果每次移动都是 1 步移动，则移动次数尽可能多。 该最大值是`n`。 

这两个值之间的每个整数移动计数都是可以实现的。 从所有 2 步移动开始，将 1 个 2 步移动替换为两个 1 步移动，移动计数恰好增加 1，同时保持总爬升距离不变。 

有一些边缘情况很容易导致错误。 

考虑：```
3 5
```最小可能的移动次数是`2`最大值是`3`。 没有的倍数是`5`在这个区间内，所以答案是：```
-1
```一个粗心的解决方案，简单地将最小移动计数向上舍入到下一个倍数`m`将获得`5`，这是不可能的，因为五步不能爬三级台阶。 

另一个重要案例是：```
1 2
```唯一可能的移动计数是`1`。 自从`1`不能被整除`2`，正确答案是：```
-1
```假设总有答案的解决方案在这里会失败。 

最后：```
10 2
```最小可能的移动次数是`5`。 自从`6`是第一个倍数`2`那至少是`5`，答案是：```
6
```算法必须在可行区间内搜索，而不是盲目取任一端点。 

## 方法

 暴力方法是枚举每个可能的移动计数并检查它是否可以对应于有效的攀登。 一次移动计数`k`是可行的，如果`ceil(n/2) ≤ k ≤ n`。 在所有可行值中，我们选择能被整除的最小值`m`。 

对于这个问题，区间最多包含 10000 个值，因此即使是线性扫描也是完全可以接受的。 

有趣的部分是认识到为什么可行区间恰好来自`ceil(n/2)`到`n`。 

当我们使用尽可能多的两步移动时，移动次数就会最少。 这给出了`ceil(n/2)`移动。 

当每次移动都是 1 步移动时，移动次数最多。 这给出了`n`移动。 

中间的每个值都是可以达到的，因为用两个 1 步移动替换单个 2 步移动会使移动计数恰好增加 1，而不会改变总爬升距离。 

一旦理解了这个性质，问题就变得非常简单了。 我们只需要最小的倍数`m`位于区间内`[ceil(n/2), n]`。 

我们可以直接计算第一个倍数，而不是扫描整个区间`m`那至少是`ceil(n/2)`。 如果该倍数不超过`n`，这就是答案。 否则不存在有效的移动计数。

 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算可能的最小移动次数。 

这是`ceil(n / 2)`，可以写成`(n + 1) // 2`使用整数运算。 
2. 找出最小的倍数`m`至少是这个最小值。 

让`mn`是最小移动次数。 所需的倍数是：`((mn + m - 1) // m) * m`这是将数字向上舍入到下一个倍数的标准方法。 
3. 检查该倍数是否仍然是可行的移动计数。 

如果倍数大于`n`，它位于可实现的区间之外，并且不存在答案。 
4.如果可行则打印倍数，否则打印`-1`。 

### 为什么它有效

 每次有效的攀爬都会使用一定数量的 1 步移动和一定数量的 2 步移动。 移动次数永远不能小于`ceil(n/2)`并且永远不能超过`n`。 

此外，这些界限之间的每个整数都是可以实现的。 从最小移动解决方案开始，每次将一个 2 步移动替换为两个 1 步移动，移动计数就会恰好增加 1，同时保留爬升的总距离。 

因为区间内的所有移动计数都是可行的，所以问题简化为找到最小的倍数`m`在那个区间内。 该算法精确计算该值。 如果第一个这样的倍数超过上限`n`，则不存在有效倍数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

mn = (n + 1) // 2
ans = ((mn + m - 1) // m) * m

if ans <= n:
    print(ans)
else:
    print(-1)
```第一个计算找到可实现的最小移动次数。 使用`(n + 1) // 2`避免浮点运算并正确实现取整运算。 

下一行将该最小值向上舍入到最接近的倍数`m`。 这直接给出了最小的候选答案。 

最后的检查至关重要。 可行区间之上可能存在倍数。 例如，与`n = 3`和`m = 5`，四舍五入后的值为`5`，但五步不能只爬三级楼梯。 比较`n`捕捉到这种情况并产生`-1`。 

所有计算都适合标准整数类型，Python 可以自然地处理它们。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    n, m = map(int, input().split())

    mn = (n + 1) // 2
    ans = ((mn + m - 1) // m) * m

    print(ans if ans <= n else -1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("10 2\n") == "6", "sample 1"

# sample-like impossible case
assert run("3 5\n") == "-1", "sample 2"

# minimum staircase
assert run("1 2\n") == "-1", "minimum size"

# exact multiple at lower bound
assert run("4 2\n") == "2", "lower bound already valid"

# answer requires rounding up
assert run("7 3\n") == "6", "round to next multiple"

# large boundary
assert run("10000 10\n") == "5000", "maximum n"

 ## 边缘情况

 考虑：```
1 2
```该算法计算：`mn = (1 + 1) // 2 = 1`2 的第一个倍数至少是 1 是 2。 

自从`2 > 1`，该值位于可行区间之外`[1, 1]`。 该算法打印：```
-1
```这是正确的。 

现在考虑：```
3 5
```可行的移动次数只有 2 和 3。 

该算法计算：`mn = 2`至少 2 的第一个 5 的倍数是 5。 

自从`5 > 3`，不存在可行倍数，因此输出为：```
-1
```最后考虑：```
4 2
```最小移动次数为：`mn = 2`由于 2 已能被 2 整除，因此四舍五入后的倍数仍为 2。 

因为`2 ≤ 4`，算法输出：```
2
```这验证了该解决方案是否正确处理最佳答案恰好是最小可行移动计数的情况。
