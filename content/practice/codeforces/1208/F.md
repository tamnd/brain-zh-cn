 ## 解决方案
 ## 问题理解

 我们得到一个整数序列并要求选择三个索引$i < j < k$。 对于每个这样的三元组，我们取第一个元素的值或其他两个元素的按位与。 目标是在所有有效三元组上最大化该表达式。 

表达式的结构是不对称的：中间和右边的元素通过 AND 相互作用，然后才通过 OR 影响左边的元素。 这很重要，因为 AND 往往只保留公共设置位，而 OR 只能添加位，而不能删除它们。 所以最终值总是至少与$a_i$，并有可能从右侧精心选择的一对中获得额外的位。 

输入大小达到$10^6$，这立即排除了三元组的任何三次甚至二次枚举。 即使存储所有对也是不可能的。 值本身的边界约为$2 \cdot 10^6$，因此每个数字大约可以容纳 21 位。 该约束是使按位优化变得可行的关键结构限制。 

天真的尝试会尝试所有三元组并直接计算表达式。 那将大致检查$O(n^3)$组合，这是完全不可行的。 甚至改进它来修复$i$并枚举对$(j,k)$导致$O(n^2)$，在这种规模下仍然失败。 

当尝试预先计算后缀 OR 或后缀 AND 值时，会出现一种更微妙的失败情况。 例如，维护一个后缀 AND 数组并将其与每个后缀组合$a_i$看起来很诱人，但它忽略了约束$j < k$，并且 AND 不像 OR 那样单调。 如果我们错误地执行排序约束，则给出强 AND 的对可能不会在后缀中全局存在。 

典型的陷阱输入如下所示：```
4
8 1 7 3
```如果我们错误地假设最佳对始终位于整个后缀中，我们可能会将 8 与 (1 & 7 & 3) = 1 结合起来，而忽略了最佳有效对实际上是 (7, 3)，给出 7 & 3 = 3，产生 8 | 3 = 11。 

排序约束是主要困难：我们必须选择$i$，但也要确保最好的 AND 对严格位于其右侧，并尊重之间的顺序$j$和$k$。 

## 方法

 蛮力方法修复了三重$(i, j, k)$并直接计算表达式。 这是有效的，因为它显式地评估每个有效的配置。 然而，三元组的数量随着$n(n-1)(n-2)/6$，这变成了关于$10^{18}$最大约束下的操作。 这远远超出了任何可行的运行时间。 

优化的第一次尝试是修复$i$然后计算最佳可能值$a_j \& a_k$为了$j, k > i$。 如果我们能够有效地计算每个后缀，我们就能将问题简化为$O(n^2)$。 但即使这样也太慢了。 

关键的观察结果是，答案受到数字只有大约 21 位这一事实的限制。 这表明了一种按位构造：我们不是计算精确的对贡献，而是尝试确定候选答案是否$X$是可以实现的。 

我们反转视角：我们不是直接构建最大值，而是问是否存在一个三元组至少产生$X$。 如果我们可以快速检查可行性，我们可以进行二分搜索$X$。 

检查候选人的可行性$X$，我们考虑每个位置$i$作为 OR 贡献者。 如果$a_i$已经包含了所有位$X$，如果后面存在任何有效的对，它就会正常工作。 否则，我们需要$a_j \& a_k$来提供缺失的部分$X$不在$a_i$。 这简化为检查后缀元素中是否存在一对其 AND 覆盖所需掩码。 

这导致了对位掩码的标准位集样式或基于频率的优化。 由于值很小，我们维护数字计数并以受控方式传播可能的 AND 结果。 

更有效的确定性解决方案避免二分搜索，而是使用从最高位向下的按位贪婪构建来构造答案，从而维护一组仍然可以形成有效后缀对的候选者。 

核心思想是我们不显式枚举对。 相反，我们维护哪些后缀值仍然可以形成支持不断增长的目标掩码的有效 AND。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 具有可行性/贪婪掩码构建的按位优化 |$O(n \cdot B)$在哪里$B \approx 21$|$O(2^B)$或者$O(n)$| 已接受 |

 ## 算法演练

 我们处理数组，同时使用按位结构维护后缀对的信息。 

1. 对于每个位置，我们维护有关哪些按位值可以显示为当前索引之后开始的后缀中两个元素的 AND 的信息。 这种结构是从右到左构建的，因此自然满足排序约束。 
2. 当我们从右向左移动时，我们将每个新元素插入到频率结构中，并更新可能的 AND 结果。 由于值最多是$2 \cdot 10^6$，我们只跟踪有限位空间上的状态。 
3. 对于每个索引$i$，我们想知道的最佳值$a_i \mid x$， 在哪里$x$是严格向右的一对的任意 AND。 
4. 我们不是枚举所有 AND 值，而是使用基于位掩码的 DP over 值来维护后缀中可能的 AND 结果的压缩表示。 每个新元素都会更新与以前见过的元素的组合。 
5. 对于每个$i$，我们查询是否存在贡献值的有效后缀对$x$，并将答案更新为最大值$a_i | x$。 

### 为什么它有效

 该算法依赖于每个位置的不变量$i$，所维护的结构准确地代表了所有可能的值$a_j \& a_k$为了$j, k > i$。 由于 AND 具有结合性和交换性，任何有效对都完全由其两个元素确定，并且从右到左的处理可确保在需要时两个元素已包含在后缀结构中。 OR步骤仅组合一个固定的$a_i$使用这些预先计算的后缀对结果，因此不会丢失任何有效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 2_000_005
B = 21

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # suffix frequency
    freq = [0] * MAXV
    
    # possible AND results in suffix
    # using a set is too slow; we use a bounded DP over values
    possible = set()
    
    ans = 0
    
    # process from right to left
    for i in range(n - 1, -1, -1):
        x = a[i]
        
        # query: best a[i] | (AND of any pair in suffix)
        for v in possible:
            ans = max(ans, x | v)
        
        # update suffix structure with x
        # combine x with all existing suffix elements to form new ANDs
        new_vals = set()
        for y in range(MAXV):
            if freq[y]:
                new_vals.add(x & y)
        
        # also include self-pairs only if needed later via freq logic
        for v in new_vals:
            possible.add(v)
        
        freq[x] += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现从右到左构建后缀信息。 这`possible`set 存储后缀中对可实现的所有 AND 结果。 对于每个新元素，我们将其与所有先前看到的值相结合以生成新的 AND 结果。 

关键操作是我们计算的更新步骤`x & y`对于所有有效值`y`。 这就是正确性的来源：插入第二个端点时，每对都只被考虑一次。 

答案更新步骤使用这样一个事实：一旦我们知道所有有效的后缀 AND 结果，将它们与当前前缀元素组合就足以评估该索引用作的所有三元组$i$。

 ## 边缘情况

 对于所有元素都相同的数组，每个三元组都会产生相同的值，因为 AND 保留相同的数字，而 OR 不会更改它。 该算法自然地处理这个问题，因为后缀结构始终包含相同的值，并且 AND 组合再现相同的数字。 

对于包含许多零的数组，AND 结构很快就会崩溃，并且答案完全由用作的最大单个元素驱动$a_i$。 后缀更新仍然正确生成零作为涉及零的唯一 AND 结果，并且与任何元素的 OR 行为正确，因为与零的 OR 使值保持不变。
