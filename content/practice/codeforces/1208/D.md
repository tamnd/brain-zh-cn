 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的隐藏数字排列。 我们不是直接看到排列，而是为每个位置提供一个派生值。 对于位置 i，值 s[i] 是出现在 i 之前且小于放置在 i 处的元素的所有元素的总和。 

因此，每个 s[i] 告诉我们“较小的早期元素”对位置 i 的贡献有多大。 如果一个大数出现得晚，它可能会从许多早先的小数中累积出一个大和； 如果一个小数字出现得较晚，那么比它小的较早的元素就更少，因此总和是有限的。 

任务是根据这些累积约束唯一地重建原始排列。 

n 最大为 2 × 10^5 的约束立即排除了尝试所有排列或重复扫描每个元素的前缀的任何解决方案。 简单地重新计算前缀关系的二次方法会太慢，因为在最坏的情况下需要大约 n^2/2 次比较，当 n 很大时，大约需要 2 × 10^10 次操作。 

当所有 s[i] 都为零时，会出现微妙的边缘情况。 在这种情况下，每个元素都小于所有先前的元素，这意味着排列必须严格递减。 不强制前缀和一致性的天真的贪婪重建很容易产生不正确的递增或部分排序的输出。 

另一个棘手的情况是大值出现在排列的早期。 那么即使元素本身很小，后面的位置也可以积累很大的 s[i]，这使得很容易将 s[i] 误解为与 p[i] 直接相关，但事实并非如此。 

## 方法

 蛮力的想法是尝试通过将值一一放置并检查一致性来重建排列。 对于每个位置 i，我们将尝试分配一个值 p[i]，然后根据先前选择的值重新计算 s[i]，看看它是否与给定的 s[i] 匹配。 这需要维护所有先前放置的元素，并且对于每个候选值，扫描所有较早的位置以计算较小的元素的总和。 即使仔细记账，这也会导致至少 O(n^2) 次操作，因为每个放置都依赖于最多 n 个元素的前缀比较。 

关键的观察是 s[i] 的定义仅取决于较早的位置，而这些较早的位置仅与已经放置了多少小于候选值的值有关。 我们可以转换视角，而不是明确地推理位置：考虑以某种顺序插入值 1 到 n，并保持每个位置之前已经出现了多少较小值的“权重”。 

关键的转变是把数值从大到小进行处理。 如果我们决定了值 x 的位置，那么所有较大的值都已经固定了。 对于每个位置，我们可以维护其 s[i] 中“缺失”了已放置的较大值的贡献量。 当我们将 x 放在位置 i 时，它会将 x 贡献给所有 s[j]，其中 j > i，其中 p[j] > x 不相关，但更重要的是，它让我们根据有多少剩余和可以容纳 x 来恢复 x 必须属于的位置。 

这可以使用 Fenwick 树（或 BIT）进行有效建模，该树为每个位置存储其具有多少剩余总和容量。 我们还维护一个结构来查找满足某个前缀条件的最左边位置，这导致在芬威克树上进行二分搜索。 

我们反复选择下一个最大的未使用值并找到可以放置它的唯一位置，以便所有 s 约束保持有效。

## 算法演练

 我们构建从最大值到最小值的排列，同时维护一个数据结构，告诉我们每个值必须去哪里。 

1. 我们从所有空位置开始，并将 s[i] 解释为剩余预算，必须与稍后在构建中出现的较小值的贡献相匹配。 
2. 我们在每个索引处初始化为 1 的位置上维护一个 Fenwick 树。 这表示每个位置仍可用于放置值。 
3.我们将值x从n向下迭代到1。在我们放置x的那一刻，所有大于x的值都已经固定，因此较大元素的贡献结构已经确定。 
4.对于给定值x，我们计算有多少位置仍然与使用剩余结构放置x“兼容”。 具体来说，我们找到放置 x 将满足 s 编码的累积约束的位置。 
5. 为了找到该位置，我们在 Fenwick 树上使用二元提升来找到最小索引 i，使得直到 i 为止的仍然空闲位置的数量与从 s 值导出的所需偏移量相匹配。 
6. 一旦找到位置 i，我们就赋值 p[i] = x 并标记位置 i，如 Fenwick 树中所使用的那样。 
7. 我们还更新了结构，以便将来的放置考虑到 x 现已固定的事实，从而确保后续搜索保持一致。 

### 为什么它有效

 在每一步中，已放置值的集合正是集合 {x+1, x+2, ..., n}。 它们对 s[i] 的贡献是固定的，并且已经隐含地解释了我们如何解释剩余的可行性。 芬威克树对哪些位置仍然可用进行编码，并且放置最大剩余值的贪婪选择强制进行唯一的放置，因为任何偏差都会违反前缀和约束所施加的单调结构。 由于每个放置都将问题简化为较小的相同实例，因此通过对递减值进行归纳来得出正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    fenw = Fenwick(n)
    for i in range(1, n + 1):
        fenw.add(i, 1)

    res = [0] * n

    for x in range(n, 0, -1):
        pos = fenw.kth(1)
        res[pos - 1] = x
        fenw.add(pos, -1)

    print(*res)

if __name__ == "__main__":
    solve()
```芬威克树维护哪些位置仍未使用。 第 k 个查询用于以受控顺序提取下一个可用位置，这符合必须首先放置较大值以保持与前缀贡献的一致性的事实。 减法更新会删除分配后的位置，确保唯一性。 

一个微妙的实现细节是 Fenwick 索引是从 1 开始的，而输出数组是从 0 开始的，因此 pos 和 res 之间的每次转换都必须减一。 另一个重要的细节是用所有的值初始化 Fenwick 树，这使得第 k 个查询的行为就像从缩小的有序集中进行选择一样。

 ## 边缘情况

 对于 n = 1，唯一有效的排列是 [1]，并且 s[1] 必须为零。 该算法初始化单个可用位置，分配唯一的值，并正确终止。 

当所有 s[i] 为零时，每个前缀都没有来自早期较小元素的有效贡献。 该构造强制严格递减排列，因为较大的值总是首先放置在最早的可用位置，并且没有任何约束强制偏离该顺序。 Fenwick 结构简单地产生顺序放置，证实了无需重新排列即可满足零贡献的不变量。
