 ## 问题理解

 该任务围绕对数字输入应用精确的舍入规则进行。 每个输入值都以文本形式给出，我们需要根据标准舍入行为将其转换为整数，其中小数部分决定我们是否将值向上或向下移动。 

具体地，每个数字可以包含小数部分。 输出需要将其替换为最接近的整数，使用以下约定：小数部分小于 0.5 的值向下舍入，而小数部分大于或等于 0.5 的值向上舍入。 

从计算的角度来看，对于此类问题，在典型的 Codeforces 方式中，输入大小从小到中等，这意味着对输入的每个字符进行线性扫描就足够了。 即使所有测试用例最多有 10^5 个字符，单遍解析方法也能在时间限制内轻松完成。 

舍入问题中的主要边缘情况来自如何处理小数边界以及整数部分在进位传播附近的行为方式。 

第一个微妙的情况是小数部分正好是 0.5。 例如，像 2.5 这样的输入必须变为 3。仅当精度处理正确时，在添加 0.5 后进行截断或取底的简单实现才有效； 浮点表示可能会引入错误，例如 2.5000000001 的处理不一致。 

第二种情况是没有任何小数点的数字，例如 7。这些应该保持不变，任何假设存在小数点的解析逻辑都会失败或抛出异常。 

第三种情况是大整数部分，转换为浮点可能会丢失精度。 例如，像 999999999999.6 这样的字符串不能在所有环境中安全地表示为浮点数，因此需要直接基于字符串的解析。 

## 方法

 最简单的方法是将每个数字解析为浮点值，应用语言的内置舍入函数，然后打印结果。 这在概念上是有效的，因为标准库直接支持舍入。 然而，这种方法依赖于浮点表示，这会引入大整数或边界小数值的精度问题。 此外，如果输入大小很大，字符串和浮点数之间的重复转换可能会成为瓶颈。 

更可靠的方法是完全避免浮点运算并将数字作为字符串处理。 这个想法是手动分离整数和小数部分。 一旦识别出小数部分，我们检查它的第一位数字来决定是否增加整数部分。 这完全避免了精度问题，并将问题简化为简单的字符串操作和进位处理。 

关键的观察结果是四舍五入仅取决于小数点后的第一位数字。 除此之外的所有内容都与决策无关，这意味着我们永远不需要以数字方式解释完整的分数值。

 ## 算法演练

1. 将每个输入数字作为字符串读取，以便在解析过程中不会丢失精度。 这确保我们准确地保留给定的所有数字。 
2. 检查字符串是否包含小数点。 如果不是，则该数字已经是整数，可以直接输出。 
3. 将字符串拆分为两部分：小数点之前的整数部分和小数点之后的小数部分。 这种分离隔离了影响舍入的唯一部分。 
4. 检查小数部分的第一位。 如果小于“5”，则完全丢弃小数部分并不变地输出整数部分。 
5. 如果第一个小数位是“5”或更大，我们需要在整数部分加一。 这需要对字符串进行手动添加，因为整数部分可能很大。 
6. 从整数部分的最后一位开始执行进位传播加法。 如果所有数字都是“9”，则该进位可能会将数字位数增加一位。 
7. 输出结果整数字符串。 

### 为什么它有效

 正确性取决于四舍五入到最接近的整数仅取决于小数值是否至少为 0.5。 由于十进制数字在该阈值的第一个小数位上在字典顺序上是一致的，因此仅检查该数字就足够了。 进位运算正确地模拟整数增量，而不会溢出或精度损失，从而确保即使是大输入也能完全按照算术指令运行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def add_one(num: str) -> str:
    s = list(num)
    i = len(s) - 1
    carry = 1

    while i >= 0 and carry:
        if s[i] == '9':
            s[i] = '0'
            carry = 1
        else:
            s[i] = chr(ord(s[i]) + 1)
            carry = 0
        i -= 1

    if carry:
        s.insert(0, '1')

    return ''.join(s)

def round_number(x: str) -> str:
    if '.' not in x:
        return x

    integer_part, fractional_part = x.split('.')

    if fractional_part[0] < '5':
        return integer_part

    return add_one(integer_part)

def solve():
    data = sys.stdin.read().strip().split()
    out = []
    for x in data:
        out.append(round_number(x))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现完全依赖于字符串处理。 辅助函数`add_one`执行手动增量，这对于避免整数溢出假设是必要的。 主函数一次读取所有令牌以提高速度并独立处理每个令牌。 

一个微妙的点是我们从不尝试将完整数字转换为整数类型。 这是故意的，因为约束可能允许非常大的整数超出某些语言的本机限制，并且 Python 的任意精度不能依赖于统一的竞争性编程解释。

 ## 边缘情况

 关键边缘情况是整数部分完全由 9 组成的数字，其中小数数字触发进位。 对于像 999.5 这样的输入，整数在传播后变成 1000。 该算法通过将进位传播到所有数字并在需要时插入新的前导数字来处理此问题。 

另一种情况是输入没有任何小数点。 例如，1234 应保持不变。 检查“.”是否存在 确保这些值绕过所有舍入逻辑。 

最后一种情况是最小影响分数，例如 0.0 或 0.9。 在 0.0 中，第一个小数位低于阈值，因此结果仍为 0。在 0.9 中，超过阈值并且整数递增到 1，这证明了对两个极端的正确处理。
