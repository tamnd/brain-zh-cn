 ## 解决方案
 ## 问题理解

 我们得到一个由以下内容组成的字符串`'+'`和`'-'`。 对于每个非空子串，我们必须确定它是否是_promising_。 

如果在应用操作之后，子字符串是有希望的```
"--" -> "+"
```任意次数，我们都可以获得平衡的字符串，这意味着最终的字符串包含相同数量的正负。 

该操作删除两个相邻的减号并用一个加号替换它们。 每个应用程序都会改变符号的长度和计数，因此我们需要准确了解这些计数是如何演变的。 

简单版本的长度最多为 3000，所有测试用例的长度总和也最多为 3000。这是一个强烈的暗示，$O(n^2)$旨在解决方案。 有$O(n^2)$子串，因此每个子串花费恒定时间或较小的摊余时间是可以接受的。 一个$O(n^3)$方法大致需要$27 \cdot 10^9$在最坏的情况下运行，远远超出了极限。 

一些边缘情况很容易被错误处理。 

考虑子串`"---"`。 

计数是：```
plus = 0
minus = 3
```它不平衡。 然而，一次操作将其变成`"+-"`，这是平衡的。 这个子串的正确答案是有希望的。 任何仅检查当前计数是否平衡的解决方案都会错过它。 

考虑子串`"--"`。```
plus = 0
minus = 2
```一次操作产生`"+"`。 

现在我们一加零减，这是不平衡的。 无法进行进一步操作。 这个子串前景并不乐观。 仅检查差异是否可以减少的粗心方法可能会错误地接受它。 

考虑子串`"-+-"`。 

没有相邻的`"--"`任何地方，因此无法执行任何操作。 弦不平衡，因此前景不佳。 任何仅使用计数并忽略可用性的解决方案`"--"`配对在这里会失败。 

## 方法

 最直接的方法是枚举每个子串并模拟所有可能的操作序列。 这是正确的，因为它确实遵循定义。 不幸的是，不同的操作选择可能会导致不同的中间字符串，并且可能性的数量呈指数级增长。 即使我们尝试贪婪地模拟，我们仍然会花费$O(length)$每个子串或更多，导致至少$O(n^3)$时间。 

关键的观察是我们实际上并不关心最终的字符串本身。 我们只关心一定次数的运算能否使正负数相等。 

假设一个子字符串包含：

 -$p$加号
 -$m$减号

 每个操作都会消耗两个减值并产生一个加值。 

应用操作后$k$次数：

 - 优点变成$p + k$- 缺点变成$m - 2k$为了使生成的字符串保持平衡，$$p+k = m-2k$$这给出了$$3k = m-p$$因此所需的操作次数是唯一确定的：$$k = \frac{m-p}{3}$$这立即给出了两个必要条件。 

第一的，$m-p$必须为非负数且能被 3 整除。 

其次，我们必须真正能够执行$k$运营。 

有多少种操作可用？ 每个操作都需要一对相邻的减号。 让$c$是出现的次数`"--"`在子串内。 

一个关键事实是每个操作都会消耗一个这样的对，并且如果子字符串包含$c$最初相邻的负对，我们最多可以执行$c$运营。 对于这个问题，这正是我们需要的信息。 

所以一个子串是有希望的 iff：$$m-p \ge 0$$

$$(m-p) \bmod 3 = 0$$

$$c \ge \frac{m-p}{3}$$自从$n \le 3000$，我们可以枚举所有$O(n^2)$子串并维护：

 - 当前余额$m-p$- 相邻负对的当前计数

 增量地同时延伸右端点。 

这会产生一个$O(n^2)$解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$或者更糟|$O(n)$| 太慢了|
 | 最佳 |$O(n^2)$|$O(1)$| 已接受 |

 ## 算法演练

 1.固定起始位置`l`。 
2.初始化：

 -`diff = 0`，代表`(minus - plus)`在当前子字符串中。 
-`pairs = 0`，代表相邻的个数`"--"`当前子串中的对。 
3. 延伸右端点`r`从`l`到`n-1`。 
4、添加时`s[r]`：

 - 如果是的话`'-'`, 增量`diff`。 
- 如果是的话`'+'`, 递减`diff`。 
5. 如果`r > l`以及两者`s[r-1]`和`s[r]`是`'-'`, 增量`pairs`。 

这对每个相邻的负对恰好计数一次。 
6. 所需操作次数为$$k=\frac{\text{diff}}{3}$$但只有当`diff >= 0`和`diff % 3 == 0`。 

1.如果

 -`diff >= 0`-`diff % 3 == 0`-`pairs >= diff // 3`那么这个子串是有希望的，所以在答案中加一。 
2. 对所有起始位置重复此操作。 

### 为什么它有效

 对于一个子串$p$优点和$m$缺点，平衡后$k$操作需要$$p+k=m-2k.$$重新排列给出$$k=\frac{m-p}{3}.$$因此，所需操作的数量是固定的。 如果$m-p$为负数或不能被 3 整除，无有效整数$k$存在。 

每个操作必须消耗一个相邻的负对。 让$c$是子串中此类对的数量。 我们最多能表演$c$操作，因此需要$k$必须满足$k \le c$。 

这些条件也足够了。 每当$k \le c$，我们可以选择$k$相邻的负对并精确执行$k$操作，达到计数$$(p+k,\;m-2k),$$它们在构造上是相等的。 因此，当算法接受该子串时，该子串就是有希望的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        ans = 0
        
        for l in range(n):
            diff = 0      # minus - plus
            pairs = 0     # number of "--" pairs
            
            for r in range(l, n):
                if s[r] == '-':
                    diff += 1
                else:
                    diff -= 1
                
                if r > l and s[r] == '-' and s[r - 1] == '-':
                    pairs += 1
                
                if diff >= 0 and diff % 3 == 0 and pairs >= diff // 3:
                    ans += 1
        
        print(ans)

solve()
```外循环固定子字符串的左端点。 内部循环一次将右端点扩展一个字符。`diff`商店`minus - plus`而不是分别保存两个计数。 这已经足够了，因为平衡条件仅取决于它们的差异。 

每当添加新角色时，我们都会更新`diff`在恒定的时间内。 我们还检查新字符和前一个字符是否形成一个`"--"`一对。 如果他们这样做，`pairs`增加一。 

接受条件正是之前导出的数学表征。 顺序很重要。 我们首先要求`diff >= 0`，因为负值意味着负数的操作。 然后我们要求能被三整除，最后验证是否存在足够的相邻负对。 

所有计数器都适合 Python 整数，并且不存在索引陷阱，因为仅在以下情况下才执行对检查：`r > l`。 

## 工作示例

 ### 示例 1

 输入子串来源：```
-+---
```完整的字符串本身很有希望。 

| r | 人物 | 差异（负加）| 成对| 公认？ |
 | ---| ---| ---| ---| ---|
 | 0 | - | 1 | 0 | 没有 |
 | 1 | + | 0 | 0 | 是的 |
 | 2 | - | 1 | 0 | 没有 |
 | 3 | - | 2 | 1 | 没有 |
 | 4 | - | 3 | 2 | 是的 |

 在最终位置我们有：$$diff=3$$因此只需要一项操作。 自从`pairs = 2`，存在足够多的相邻负对。 子串很有希望。 

此示例说明字符串最初不需要平衡。 一次操作可以弥补三倍的差异。 

### 示例 2

 输入子串来源：```
----
```| r | 人物 | 差异| 成对| 公认？ |
 | ---| ---| ---| ---| ---|
 | 0 | - | 1 | 0 | 没有 |
 | 1 | - | 2 | 1 | 没有 |
 | 2 | - | 3 | 2 | 是的 |
 | 3 | - | 4 | 3 | 没有 |

 子串`"---"`被接受是因为：$$diff=3,\quad k=1,$$并且有足够多的相邻负对。 

子串`"----"`不被接受，因为：$$diff=4,$$不能被 3 整除。任何整数次操作都不能使计数相等。 

这个例子证实了被三整除的必要性。

 ## 边缘情况

 考虑：```
1
3
---
```唯一有希望的子字符串是整个字符串。 扫描期间：

 | r | 差异| 成对|
 | ---| ---| ---|
 | 0 | 1 | 0 |
 | 1 | 2 | 1 |
 | 2 | 3 | 2 |

 在最后，`diff = 3`，因此需要一次操作。 自从`pairs = 2`，条件成立并且算法对其进行计数。 

现在考虑：```
1
2
--
```我们得到：

 | r | 差异| 成对|
 | ---| ---| ---|
 | 0 | 1 | 0 |
 | 1 | 2 | 1 |`diff = 2`不能被 3 整除，因此该子字符串被拒绝。 执行一项操作给出`"+"`，仍然不平衡。 

最后考虑：```
1
3
-+-
```不存在相邻的负对。 

| r | 差异| 成对|
 | ---| ---| ---|
 | 0 | 1 | 0 |
 | 1 | 0 | 0 |
 | 2 | 1 | 0 |

 整个子串有`diff = 1`，无法修复。 自从`pairs = 0`，该算法绝不会错误地假设操作可用。 输出是正确的。
