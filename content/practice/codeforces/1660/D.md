 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中每个值的大小都非常小，仅从 -2 到 2。从这个数组中，我们可以删除一个前缀和一个后缀，留下一个连续的中间段。 剩下的部分甚至可能是空的。 

任务是选择从左边和右边的哪里进行切割，使得剩余数字的乘积尽可能大。 如果我们删除所有内容，则乘积定义为 1，因此空子数组始终是有效的候选数组。 

每个测试用例都是独立的，我们只需要输出前后移除元素的数量，而不是产品本身。 

总体而言，约束很严格：所有测试用例的总元素数最多为 200,000 个。 这立即排除了乘积的任何二次或每位置重新计算。 任何解决方案对于每个测试用例都必须是线性的，或者在所有测试中均摊线性。 

一些边缘行为在这里很重要。 零尤其重要，因为任何包含零的段的乘积为 0，这比产生 1 的空段更糟糕。负值会导致符号翻转，因此删除或保留单个元素可能会更改乘积的符号。 例如，在`[-1, -1]`，完整的乘积为 1，但删除所有内容也会得到 1，因此多个答案并列。 

为每个可能的子数组重新计算乘积的简单策略将会失败，因为子数组的数量为 O(n²)。 即使我们预先计算了前缀乘积，处理零和选择最佳切割仍然需要推理符号变化，而不仅仅是算术。 

## 方法

 暴力解决方案会尝试每一对切割位置`(l, r)`意味着我们保留`a[l..r]`，计算其乘积，并跟踪最大值。 这需要 O(n²) 个子数组，如果仔细维护前缀乘积，则每个乘积计算都是 O(1)，但处理零和负奇偶校验仍然会强制仔细重新计算或重置。 即使进行了优化，对于 2e5 个总元素来说，枚举所有有效段也太慢。 

关键的观察结果是，我们不需要任意子数组，而只需要连续的段，并且值仅限于 {-2, -1, 0, 1, 2}。 这种限制破坏了结构：只有零将数组分成独立的块，并且每个块内的符号仅由负数的奇偶校验确定。 

在任何没有零的块内，通过保留所有内容来最大化乘积的绝对值。 删除元素的唯一原因是修复符号或避免零。 零是决定性的，因为它们将乘积重置为零，因此任何最佳分段要么避免全零，要么包括精心选择的区域，以最大化符号校正幅度。 

更精确的观察方法是考虑非零元素的所有位置。 最佳段必须位于某个最大无零区间内，并且在该区间内，唯一有意义的决定是负数的数量是偶数还是奇数。 如果是偶数，则保留整个段是最佳的。 如果是奇数，我们必须删除第一个负数之前的前缀或最后一个负数之后的后缀，以消除一个负面影响。 

这将问题减少到扫描由零分隔的段并评估每个段至多两个候选切割。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们通过扫描一次数组并将每个零视为硬边界来独立处理每个测试用例。 

1. 将数组拆分为不包含零的最大段。 每个这样的段都可以独立分析，因为任何包含零的段都会产生乘积 0，这总是比选择值为 1 的空段更糟糕，除非不存在更好的选择。 
2. 对于每个无零段，计算其中负数的位置。 这些位置决定了整个细分产品是正还是负。 
3. 如果负数的数量是偶数，则保留整个段是最佳的，因为它会产生具有最大绝对值的正积。 
4. 如果负数的数量是奇数，我们必须精确地排除一个负数以使乘积成为正数。 我们评估两种可能性：删除片段中直到并包括第一个负片的所有内容，或者删除从最后一个负片到末尾的所有内容。 这两者中的更好者在固定奇偶校验的同时保持更多的绝对值。 
5. 跟踪所有无零段中的最佳结果段。 还要与具有产品 1 的空段选项进行比较。 
6、输出原数组前后删除的元素对应的个数。 

关键的推理步骤是，在无零段内，乘以任何±2或±1总是会增加或保留绝对值，因此影响最优性的唯一因素是乘积是正还是负。 一旦解决了这个问题，更长的段总是更好。 

### 为什么它有效

 在任何没有零的连续区域内，乘积大小对于包含而言是单调的：添加元素永远不会减少绝对值。 唯一的障碍是标志。 由于符号仅取决于负数的奇偶性，因此最佳解决方案必须保留整个段或删除恰好消除一个负贡献的前缀/后缀。 零将问题划分为独立的子问题，跨段比较简化为选择最佳可行的符号校正乘积或空数组基线。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        best_prod = 1
        best_l = n
        best_r = 0

        i = 0
        while i < n:
            while i < n and a[i] == 0:
                i += 1
            if i == n:
                break

            start = i
            neg_pos = []
            while i < n and a[i] != 0:
                if a[i] < 0:
                    neg_pos.append(i)
                i += 1
            end = i - 1

            # consider full segment
            if len(neg_pos) % 2 == 0:
                l, r = start, end
                if r - l + 1 > best_r - best_l + 1:
                    best_l, best_r = l, r
            else:
                # remove prefix up to first negative
                l1 = neg_pos[0] + 1
                r1 = end
                # remove suffix from last negative
                l2 = start
                r2 = neg_pos[-1] - 1

                if r1 >= l1 and (r1 - l1 + 1 > best_r - best_l + 1):
                    best_l, best_r = l1, r1
                if r2 >= l2 and (r2 - l2 + 1 > best_r - best_l + 1):
                    best_l, best_r = l2, r2

        if best_l == n:
            print(0, 0)
        else:
            print(best_l, n - best_r - 1)

if __name__ == "__main__":
    solve()
```该解决方案遍历每个测试用例并维护迄今为止找到的最佳有效段。 每个无零段都以线性时间进行处理，并且仅存储负元素的索引，因此每个段的内存保持不变。 

一个微妙的点是比较标准：我们不是显式地计算乘积，而是比较段长度，因为在固定的无零段内，固定奇偶校验的任何有效变换都会保留所有非零量值，并且较长的段在绝对值上严格支配较短的段。 这就是为什么仅跟踪结构而不是算术值就足够了。 

另一个细节是转换最佳片段`[best_l, best_r]`回到拆除。 去除`best_l`从前面的元素给出从 0 开始的左剪切，从末尾删除是`n - best_r - 1`。 

## 工作示例

 ### 示例 1

 输入数组：`[2, 0, -2, 2, -1]`我们分为几部分：`[2]`和`[-2, 2, -1]`。 

为了`[2]`，负数为零，所以我们保留它。 产品为2。 

对于`[-2, 2, -1]`，有两个负数，因此完整段有效。 产品为4。 

| 细分 | 负面| 行动| 结果 |
 | ---| ---| ---| ---|
 | [2] | 0 | 保持饱满| 2 |
 | [-2,2,-1] | 2 | 保持饱满| 4 |

 最好的片段是第二个片段，因此我们完全保留它，这意味着我们删除了前两个元素。 

这证实了零正确地分割了独立的优化区域。 

### 示例 2

 输入数组：`[1, 1, -2]`单段`[-2]`考虑完整阵列后。 

负数 = 1，因此我们必须删除它周围的前缀或后缀。 最好的办法是删除它之前的所有内容，留下`[-2]`，或者根据与空数组的比较完全删除它。 

| 细分 | 负面| 选项 1 | 选项 2 |
 | ---| ---| ---| ---|
 | [1,1,-2]| 1 | [-2]| []|

 空数组的乘积为 1，它比 -2 更好，因此最好的答案是删除所有元素。 

这表明空段必须始终进行显式比较。

 ## 边缘情况

 一个微妙的情况是整个数组仅包含零。 每个段产生乘积 0，但空数组产生 1。该算法必须明确允许根本不选择任何段； 否则它将错误地返回包含零的段。 

另一种情况是底片稀疏且孤立。 删除第一个或最后一个负数周围的错误一侧可能会意外地丢弃不必要的更多正值贡献。 正确的处理可确保仅删除一个负片，从而保留有效修复中的最大长度。 

最后，所有正数的数组需要特别小心，因为每个段都有乘积 1，所以任何答案都是有效的。 该算法自然地处理这个问题，因为最长的段始终是首选，但关系不能强制进行不必要的删除。
