 ## 解决方案
 # 问题理解

 该问题要求我们回答有关一系列送货公司的许多范围查询。 白天到达的快递公司被记录为数组`a`。 对于每个同事，我们都会得到一个该数组的间隔，表示该同事可以点餐的时间段。 我们必须找到该区间内出现次数最多的公司编号。 如果多家公司的最大频率相同，则接受其中任何一家。 

数组长度和查询次数都可以达到`100000`，而公司标识符可以大到`10^9`。 标识符范围大意味着我们不能直接使用公司编号作为数组索引，因此需要进行压缩。 尺寸为`n`和`q`排除检查每个间隔的每个元素。 独立扫描每个查询的解决方案可以执行以下操作`10^10`最坏情况下的操作，远远超出了一秒的限制。 我们需要一种方法，其中通过数组的总移动量接近`n * sqrt(n)`。 

一个常见的错误是错误地处理领带。 答案不需要是唯一的。 例如：```
5
1 2 1 2 3
1
1 4
```正确的输出可以是`1`或者`2`，因为两者都出现了两次。 从数据结构中删除元素后，假设找到的第一个最大值始终稳定的解决方案可能会失败。 

另一个边缘情况是包含单个元素的查询：```
3
7 8 9
1
2 2
```答案一定是`8`。 将当前最大频率初始化为零并忘记正确添加第一个元素的实现可能会返回无效值。 

第三种情况是一家公司在多次更新后占据主导地位：```
6
5 1 5 2 5 3
1
1 6
```答案一定是`5`。 仅增加当前最大值但在删除后不修复它的惰性更新策略可能会保持过时的频率并产生错误的答案。 

## 方法

 直接的方法是单独处理每个查询。 对于一个间隔`[l, r]`，我们扫描之间的所有位置`l`和`r`，计算每个公司的出现次数，并选择最大的计数。 这是正确的，因为它准确地检查属于查询的元素。 问题是重复工作。 如果所有查询覆盖整个数组，则每个查询的成本`O(n)`, 给予`O(nq)`，这变成`10^10`最大输入大小的操作。 

问题的结构是查询仅询问范围内的频率，并且相邻查询通常严重重叠。 我们可以对查询重新排序并维护一个移动窗口，而不是每次都从零开始重建频率信息。 这就是Mo算法背后的想法。 

Mo的算法将数组分成大致大小的块`sqrt(n)`。 查询按其左端点排序，然后按右端点排序。 当从一个查询移动到下一个查询时，我们仅添加或删除发生更改的位置。 维护的窗口始终包含当前的查询间隔，因此频率表始终准备就绪。 

剩下的挑战是在人员进出窗口时保持最频繁的陪伴。 我们保留一个用于压缩公司标识符的频率数组，另一个数组告诉当前有多少家公司拥有每个频率。 当删除元素时，如果当前最大频率消失，我们会降低它，直到存在具有该频率的某个公司。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | 最佳 | O((n + q)√n) | O((n + q)√n) | O(n) | 已接受 |

 ## 算法演练

 1. 将所有公司标识符压缩为连续整数。 原始值单独保存，以便最终答案可以转换回来。 
2. 选择一个左右的块大小`sqrt(n)`并按照 Mo 的顺序对查询进行排序。 具有较小左块的查询首先出现，并且在一个块内，右端点的顺序逐渐增加。 这可以最大限度地减少当前间隔整体移动的距离。 
3. 用两个指针维持当前间隔。 最初该间隔是空的。 当左边界或右边界发生变化时，添加或删除相应的数组位置。 
4. 添加公司时，增加其频率。 更新具有该频率的公司数量，并在必要时提高当前最大值。 
5. 删除公司时，减少其频率。 更新频率计数器。 如果以前的最大频率不再存在，则降低最大频率，直到保留有效频率。 
6. 对于每个已处理的查询，选择频率等于当前最大频率的任何公司并存储其原始标识符。 

不变的是，每次指针移动后，频率表都会准确描述当前区间内的元素。 第二种结构保证存储的最大频率始终是窗口中实际出现的频率。 由于答案仅从具有该频率的公司中选择，因此每个生成的答案都是所请求范围的有效模式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    values = sorted(set(arr))
    comp = {v: i for i, v in enumerate(values)}
    a = [comp[x] for x in arr]

    q = int(input())
    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, i))

    block = int(n ** 0.5) + 1

    queries.sort(
        key=lambda x: (
            x[0] // block,
            x[1] if (x[0] // block) % 2 == 0 else -x[1]
        )
    )

    freq = [0] * len(values)
    freq_count = [0] * (n + 1)

    answers = [0] * q
    current_max = 0
    best = -1

    def add(x):
        nonlocal current_max, best
        old = freq[x]
        if old:
            freq_count[old] -= 1
        new = old + 1
        freq[x] = new
        freq_count[new] += 1
        if new > current_max:
            current_max = new
            best = x

    def remove(x):
        nonlocal current_max, best
        old = freq[x]
        freq_count[old] -= 1
        new = old - 1
        freq[x] = new
        if new:
            freq_count[new] += 1
        if old == current_max and freq_count[old] == 0:
            current_max -= 1
            while current_max and freq_count[current_max] == 0:
                current_max -= 1
            if current_max:
                for i, f in enumerate(freq):
                    if f == current_max:
                        best = i
                        break

    left = 0
    right = -1

    for l, r, idx in queries:
        while left > l:
            left -= 1
            add(a[left])
        while right < r:
            right += 1
            add(a[right])
        while left < l:
            remove(a[left])
            left += 1
        while right > r:
            remove(a[right])
            right -= 1

        answers[idx] = values[best]

    print("\n".join(map(str, answers)))

if __name__ == "__main__":
    solve()
```压缩步骤用小索引替换大公司数字，这允许恒定时间访问频率数组。 原来的数字仍保留在`values`，因此输出仍然使用输入中的标识符。 

这`queries`排序顺序是Mo算法的主要部分。 右端点的交替方向减少了相邻块之间不必要的指针移动。 

这`freq`数组存储每个压缩公司的当前出现次数。 这`freq_count`array 回答了一个不同的问题：当前是否存在特定频率。 这避免了每次移除后重建所有频率。 

Python 整数不会溢出，因此频率值是安全的。 重要的边界细节是维护的间隔包含两侧，因此在移动指针时，添加和删除操作必须以正确的顺序进行。

 ## 边缘情况

 处理平局的情况是因为该算法仅搜索当前频率最高的公司。 它从不假设某家特定公司一定会获胜。 为了：```
5
1 2 1 2 3
1
1 4
```维持的频率是`1:2`和`2:2`，因此任一公司都可以返回。 

对于单元素查询：```
3
7 8 9
1
2 2
```Mo的算法通过仅添加位置来扩展空窗口`2`。 的频率`8`变为 1，最大频率变为 1，因此返回的结果正是`8`。 

For a dominant value after many updates:```
6
5 1 5 2 5 3
1
1 6
```最终的频率表包含`5:3`，而其他所有公司都有频率一。 维护的最大值变为 3，算法返回`5`。 即使删除暂时降低了获胜者的频率，相同的逻辑也会起作用，因为频率计数器会在回答下一个查询之前修复最大值。
