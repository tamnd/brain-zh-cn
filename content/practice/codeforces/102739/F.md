 ## 解决方案
 # 问题理解

 我们的任务是让每个健身追踪器的价值都能为 Sasha 所接受。 如果某个值是素数或 2 的幂，则该值是可接受的。 对于每个记录的数字，我们需要找到不小于记录的最小可接受数字。 输出包含每天一个答案。 

输入最多包含$10^5$记录的值，每个值可以大到$10^7$。 为每个查询单独检查每个候选编号的解决方案可能会变得过于昂贵。 在最坏的情况下，向前扫描许多数字并测试每个数字的素性可能会比$10^8$操作，这在一秒竞争性编程环境中是不安全的。 最大值的大小表明对所有相关答案进行一次预处理是预期的方向。 

边缘情况主要是由于答案不一定是素数这一事实引起的。 一个值已经可以是 2 的幂，并且该幂可能小于下一个素数。 例如，输入```
1
1023
```有输出```
1024
```因为 1024 是 2 的幂，并且小于 1023 之后的下一个素数。仅搜索素数的解决方案将错误地返回 1031。 

另一个常见的错误是忘记零和一不是素数，但在这个问题的解释中，一是二的有效幂，因为它是$2^0$。 例如：```
1
0
```有输出```
1
```仅素数解决方案将会失败，因为它没有小于 2 的素数答案，并且从$2^1$会错过正确的值。 

重复的值也很重要。 例如：```
3
16 16 17
```有输出```
16 16 17
```该算法应该预处理一次并一致地回答所有查询，而不是重新计算相同的信息。 

## 方法

 一种简单的方法是独立处理每个查询。 从给定值开始，我们可以测试接下来的每个整数，直到找到一个素数或 2 的幂。 这是正确的，因为我们按升序检查候选项，因此第一个有效候选项恰好是所需的最小值。 问题在于重复工作量。 如果许多查询接近一个大值，则每个查询都会重复几乎相同的素性检查。 和$10^5$周围的查询和值$10^7$，这种方法很容易需要数十亿次小操作。 

问题的结构给了我们更好的选择。 可能的答案只有两种类型：素数和二的幂。 2的幂是极其罕见的，所以我们可以直接存储它们。 使用埃拉托色尼筛一次就可以生成最大可能答案的素数。 之后，每个查询就变成了一个查找问题：找到第一个不小于该值的素数，并将其与不小于该值的第一个2的幂进行比较。 

剩下的问题是如何快速找到下一个素数。 由于最大值仅约为$10^7$，我们可以构建一个数组，其中每个位置存储该位置或该位置之后最接近的素数。 单个反向扫描填充该数组。 然后每个查询都会在恒定时间内得到答复。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 间隙 * sqrt(A)) | O(1) | O(1) | 太慢了 |
 | 最佳| O(M log log M + M + n) | O(M log log M + M + n) | O(M)| 已接受 |

 这里$M$是我们筛选到的最大值。 筛选是主要的预处理步骤，而回答查询与天数呈线性关系。 

## 算法演练

 1. 首先读取所有值并确定出现的最大值。 我们需要这个，因为筛子只需覆盖可以影响答案的范围。 
2. 稍微扩大范围并运行埃拉托斯特尼筛法。 筛子标记每个合数，准确地留下可用于查询的素数位置。 
3. 构建素数后缀数组。 从范围的末尾向开头扫描，记住最近看到的素数。 本次扫描后，位置处的值$i$是大于或等于的最小质数$i$。 
4. 生成所需范围内的所有 2 的幂。 按排序顺序存储它们。 对于每个查询，二分搜索此列表以查找至少是查询值的 2 的第一个幂。 
5. 对于每个原始数字，比较下一个素数和下一个 2 的幂。 较小的一个就是答案，因为两个候选者都是有效的，并且都是各自类别中最早可能的候选者。 

工作原理：预处理后，每个素数候选都由下一个素数数组表示，每个二次幂候选都由生成列表上的二分搜索表示。 对于任何输入值$x$，任何有效答案都必须属于这两个类别之一。 该算法从每个类别中选择最小的候选者，并返回两者中较小的一个，因此不能存在更小的有效数字。 

## Python 解决方案```python
import sys
import bisect

input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    n = data[0]
    a = data[1:]

    mx = max(a)

    limit = mx + 100000

    prime = bytearray(b'\x01') * (limit + 1)
    prime[0] = 0
    if limit >= 1:
        prime[1] = 0

    i = 2
    while i * i <= limit:
        if prime[i]:
            start = i * i
            prime[start:limit + 1:i] = b'\x00' * (((limit - start) // i) + 1)
        i += 1

    next_prime = [0] * (limit + 2)
    nxt = 0
    for i in range(limit, -1, -1):
        if prime[i]:
            nxt = i
        next_prime[i] = nxt

    powers = []
    x = 1
    while x <= limit:
        powers.append(x)
        x *= 2

    ans = []
    for value in a:
        p = next_prime[value]
        idx = bisect.bisect_left(powers, value)
        pw = powers[idx]
        if p < pw:
            ans.append(str(p))
        else:
            ans.append(str(pw))

    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```该代码首先读取所有查询，因为预处理大小取决于最大输入值。 该筛子使用的是`bytearray`因为它只存储布尔信息，并且比 Python 整数列表的内存效率更高。 

筛子中的切片分配同时标记素数的所有倍数。 生成的`next_prime`数组是向后填充的，因此每个位置立即知道其右侧最近的素数。 这避免了对每个查询都对素数进行二分搜索。 

权力列表从 1 开始，因为$2^0$对于零这样的情况是需要的。 二分查找返回不小于当前值的第一个幂。 最终的比较处理唯一剩下的决定：最接近的可接受数字是素数还是 2 的幂。 

最大查询值之后的额外 100000 个位置提供了足够的空间来到达下一个素数。 这也避免了对最大可能输入值的复杂处理，同时保持筛子尺寸较小。

import bisect

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    if not data:
        return ""

    a = data[1:]

    limit = mx + 100000

    while i * i <= limit:
        if prime[i]:
            prime[i * i:limit + 1:i] = b'\x00' * (((limit - i * i) // i) + 1)
        i += 1

    x = 1

 ## 边缘情况

 用于输入```
1
1023
```筛子找到的下一个素数为 1031，而二次方搜索找到的下一个素数为 1024。比较返回 1024。算法成功是因为它从不假设素数始终是最接近的数学数字。 

用于输入```
1
0
```主要候选者为 2，但生成的幂列表以 1 开头。二分查找返回 1，两个候选者中的最小值是正确的。 这个案例证实了发电量必须包括$2^0$。 

用于输入```
3
16 16 17
```两次出现 16 都会找到相同的下一个素数和二次幂候选者。 预处理是共享的，因此对于相同的输入，结果是相同的，并且不需要重复计算。
