 ## 解决方案
 # 问题理解

 画廊包含`n`画作按照从左到右的固定顺序排列。 阿丽娜从画廊的第一侧开始，走向最后一幅画。 在步行过程中，她只能停在当前方向前方的画作处。 到达画廊的尽头后，她转身继续朝相反的方向走。 语音导览记录了她实际观看所有画作的顺序。 

任务是重建可以产生这种观看顺序的穿过画廊的最少次数。 从左到右的行走必须包含按记录顺序递增的绘画编号，而从右到左的行走必须包含按记录顺序递减的绘画编号。 

输入给出了绘画数字的排列。 每幅画都只出现一次，因此序列本身告诉我们每幅画被观看的确切时刻。 输出是分割该序列所需的最小数量的交替递增和递减段。 

主要限制是`n ≤ 100000`。 这排除了尝试序列的每个可能的划分或在每次通过时重复模拟所有绘画的解决方案。 解决方案需要对每幅画进行固定次数的处理，这表明`O(n)`方法。 

微妙之处在于，当我们到达那个方向看到的最后一幅画时，步行并没有结束。 它只有在到达画廊的物理末端后才结束。 因此，即使较长的数学子序列仍可能增加或减少，音频序列中的下一幅绘画也可能会强制进行新的行走。 

考虑这个输入：```
4
1 2 4 3
```正确的输出是：```
2
```第一个从左向右走可以看到`1 2 4`。 绘画`3`位于当前位置的后面，所以阿丽娜必须掉头。 一个粗心的解决方案，只寻找一个长的递增子序列，可能会错误地决定更少的步行是可能的。 

另一个极端情况是接下来的每一幅画都需要改变方向：```
5
1 5 2 4 3
```正确的输出是：```
5
```每次绘画后，序列会在增加和减少之间交替。 错误地处理相等或单元素行走可能会导致此处出现相差一的错误，因为每幅画仍然需要完整的行走。 

## 方法

 一种直接的方法是模拟画廊行走。 我们可以维护已看过的一组绘画，从一端开始，并在画廊中重复移动，以当前方向搜索下一幅可用的绘画。 这种做法是正确的，因为它完全符合故事的脉络。 然而，直接实施它可能需要每次扫描许多画作。 在最坏的情况下，可能会出现`n`通行证，每通行证都可以检查`n`绘画，导致`O(n²)`操作，这对于`n = 100000`。 

关键的观察结果是音频序列已经包含我们需要的唯一信息。 在一次行走中，所观看的绘画数字必须形成一个单调的序列。 第一次步行必须增加，第二次减少，第三次增加，依此类推。 因此，这个问题相当于在从左到右读取排列时找出我们需要在递增和递减运行之间切换多少次。 

暴力模拟之所以有效，是因为每次行走都对应一个单调片段。 它失败是因为它反复花费时间来发现序列中已经存在的信息。 通过观察，当前行走的方向是由之前查看的绘画确定的，这让我们可以将整个模拟简化为一次扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从一次步行开始。 它的方向是从左到右，所以当前段一定是递增的。 
2. 按照语音导览存储的顺序扫描画作。 保留之前的绘画编号和当前行走所需的方向。 
3、如果当前方向是递增的，并且下一个画数比上一个大，则可以继续同样的行走。 
4. 如果当前方向是递减，并且下一个绘画数量小于前一个，则可以继续相同的行走。 
5. 否则，当前行走不能包括这幅画。 增加步行次数并反转方向，因为阿琳娜必须已经到达画廊的尽头并转身才能观看。 
6. 将前一个绘画编号替换为当前绘画编号，然后继续，直到处理完整个序列。 

贪婪切换足够的原因是每次行走都有固定的方向。 一旦连续两幅画违反了这个方向，任何早期的选择都无法修复这种情况。 第二幅画实际上位于阿丽娜的错误一侧，因此重新行走是不可避免的。 

为什么它有效：

 不变的是，在处理音频序列的任何前缀后，算法已经准确地计算出该前缀所需的最小行走次数，并且当前方向是下一次行走的唯一可能方向。 每当下一幅绘画适合当前方向时，延长当前行走始终是最佳选择，因为它不会增加答案。 每当它不适合时，前一个路径就不能包含该画，因此必须再添加一个路径。 由于每个决定都是被迫的，贪婪过程会产生尽可能少的游走次数。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 1
    direction = 1
    prev = a[0]

    for x in a[1:]:
        if direction == 1:
            if x < prev:
                ans += 1
                direction = -1
        else:
            if x > prev:
                ans += 1
                direction = 1
        prev = x

    print(ans)

if __name__ == "__main__":
    solve()
```变量`direction`存储当前画廊行走的方向。 值为`1`意味着当前的步行从较小的绘画数量到较大的绘画数量，而`-1`意味着它朝相反的方向发展。 

扫描仅比较音频序列中的相邻绘画。 如果比较与当前方向相矛盾，则代码立即开始新的行走并翻转方向。 

初始化与`ans = 1`是安全的，因为第一幅画总是需要至少一次步行。 约束保证`n`至少为一，因此访问`a[0]`是有效的。 

不需要额外的数组，因为算法只需要之前的绘画、当前的方向和当前的答案。

 ## 边缘情况

 对于单个绘画案例：```
1
1
```该算法从一次行走开始，永远不会进入循环。 答案依然存在`1`，这与 Arina 只需进入画廊并观看那幅画的事实相匹配。 

对于已经在增加的序列：```
5
1 2 3 4 5
```每次比较都与当前从左到右的方向一致。 该算法永远不会改变方向并返回`1`。 到达最后一幅画后总是交替的解决方案在这里会过多。 

对于第一步向后退的情况：```
4
4 3 2 1
```第一次行走不能包含第二幅画，因为 Arina 正在从较小的索引转向较大的索引。 该算法计算包含的初始递增行走`4`，然后切换到包含其余部分的递减步行。 答案是`2`。 

对于频繁变化的序列：```
6
1 6 2 5 3 4
```每个相邻的对都会破坏当前方向。 算法在每次比较后改变方向并返回`6`，匹配第一幅画之后的每幅画都需要单独遍历的事实。
