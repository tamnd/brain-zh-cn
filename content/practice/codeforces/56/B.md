 ## 解决方案
 ## 问题理解

 我们从排序的排列开始`1 2 3 ... n`。 有人恰好选择一个连续的片段并将其反转。 我们得到了最终的排列，并且必须确定它是否可以通过恰好一个这样的逆转来产生。 

任务不是对数组进行排序。 我们只需要识别一个段`[l, r]`这样，反转原始排序数组中的该段就会产生给定的排列。 如果不存在这样的段，我们打印`0 0`。 

约束很小，`n ≤ 1000`，所以即使是二次算法也是可以接受的。 一个`O(n^2)`该解决方案在最坏的情况下执行大约一百万次操作，这在 2 秒限制内是微不足道的。 这意味着我们不需要复杂的数据结构或高级算法。 干净的实施比微观优化更重要。 

棘手的部分不是效率，而是边缘情况的正确性。 

一个容易犯的错误是忘记反转必须来自原始排序数组，而不是来自某种中间排列。 考虑：```
5
1 3 2 5 4
```粗心的方法可能会注意到两个递减的部分，并尝试以某种方式将它们组合起来。 但一次逆转不能同时交换两者`(2,3)`和`(4,5)`。 正确的输出是：```
0 0
```当排列已经排序时，会发生另一种微妙的情况：```
4
1 2 3 4
```该语句需要反转具有不同端点的段。 除非我们反转长度为 1 的段，否则不会将数组更改为自身，这是禁止的，因为`l < r`。 正确答案是：```
0 0
```简单地搜索不匹配的简单实现可能会错误地打印类似的内容`1 1`。 

第三种边缘情况是反向线段接触边界时：```
5
5 4 3 2 1
```这里整个数组被颠倒了，所以正确答案是：```
1 5
```相差一个的错误在这里很常见，因为段从第一个元素开始并在最后一个元素结束。 

## 方法

 蛮力的想法很简单。 由于原始排列总是`1 2 3 ... n`，我们可以尝试每一个可能的对`(l, r)`，反转该段，并检查结果是否与输入排列匹配。 

有`O(n^2)`可能的片段。 反转并比较阵列成本`O(n)`时间，因此总复杂度变为`O(n^3)`。 和`n = 1000`，这意味着在最坏的情况下大约有 10 亿次操作，这在 Python 中太慢了。 

问题的结构使我们能够更好地观察。 如果排列是通过反转一个线段创建的，那么该线段之外的所有数字都必须仍出现在其原始位置。 

这意味着第一个索引在哪里`a[i] != i + 1`must be the left endpoint of the reversed segment. Similarly, once we start moving through the reversed segment, the values must decrease exactly as a reversal would produce.

 例如：```
1 6 5 4 3 2 7 8
```第一个不匹配发生在位置`2`。 从那里开始，数字减少，直到位置`6`。 反转原始排序数组中的该间隔可以准确地重建排列。 

这将任务简化为识别一个候选片段并对其进行验证。 我们只扫描数组固定次数，因此复杂度变成线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读出排列。 
2.找到第一个位置`l`在哪里`a[l] != l + 1`。 

如果不存在这样的位置，则排列已经排序，因此不存在有效的反转。 打印`0 0`。 
3. 从`l`， 延长`r`而序列是严格递减的。 

从排序数组中取出的反向段必须以降序出现在最终的排列中。 此步骤识别最大候选片段。 
4. 反转子数组`l`到`r`。 

我们直接对排列的副本执行反转，以测试此操作是否恢复排序顺序。 
5. 检查结果数组是否等于`1 2 3 ... n`。 

如果是，则打印`l + 1`和`r + 1`使用从 1 开始的索引。 

否则，打印`0 0`。 

### 为什么它有效

 第一个不正确的位置必须属于反转段，因为它之前的位置已经与原始排序排列匹配。 

在反转段内，值必须按降序出现。 由于原始数组严格递增，因此反转任何连续部分只会翻转该顺序一次。 延伸`r`而序列递减则确定了唯一可能的候选片段。 

如果反转该段可以恢复已排序的数组，则排列恰好是由一次反转产生的。 如果不匹配，则任何其他段都无法工作，因为任何有效段都必须从第一个不匹配处开始，并遵循反转创建的递减模式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    l = -1

    for i in range(n):
        if a[i] != i + 1:
            l = i
            break

    if l == -1:
        print(0, 0)
        return

    r = l

    while r + 1 < n and a[r] > a[r + 1]:
        r += 1

    b = a[:]
    b[l:r + 1] = reversed(b[l:r + 1])

    if b == list(range(1, n + 1)):
        print(l + 1, r + 1)
    else:
        print(0, 0)

solve()
```第一个循环搜索排列和排序顺序之间最早的不匹配。 这标识了反转段必须开始的位置。 

如果不存在不匹配，则排列已经排序。 由于问题需要`l < r`，我们不能使用空操作或长度为1的反转，所以答案变成`0 0`。 

第二个循环扩展了右边界，同时序列不断减小。 这捕获了通过反转原始排列的递增段而产生的精确形状。 

该行：```
b[l:r + 1] = reversed(b[l:r + 1])
```在撤消可疑的反转后创建数组的正确版本。 

最后，我们与排序后的排列进行比较。 此验证步骤至关重要，因为仅减少段是不够的。 数组如：```
1 5 4 3 2 6 8 7
```包含多个扰动区域并且不能通过一次反转来修复。 

使用复制的数组可以避免意外修改原始数据。 边界仔细使用 Python 切片约定，其中`r + 1`是必需的，因为正确的端点是独占的。

 ## 边缘情况

 考虑已经排序的排列：```
4
1 2 3 4
```该算法扫描第一个不匹配并没有找到，所以`l`遗迹`-1`。 此时它立即打印：```
0 0
```这是正确的，因为该问题需要具有不同端点的逆转。 

现在考虑触及两个边界的反转：```
5
5 4 3 2 1
```第一个不匹配发生在索引处`0`。 递减扫描一直持续到索引`4`。 反转该段可以准确地恢复排序顺序，因此算法输出：```
1 5
```这证实了边界索引已正确处理。 

最后，检查具有两个独立破碎区域的排列：```
5
1 3 2 5 4
```第一个不匹配出现在位置`2`。 递减段变为仅`3 2`。 反转它会产生：```
1 2 3 5 4
```数组仍未排序，因此验证失败，算法打印：```
0 0
```最后的验证步骤可防止不代表单个全局反转的局部递减片段产生误报。
