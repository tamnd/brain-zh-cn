 ## 解决方案
 ## 问题理解

 我们有一个大小为网格对齐的矩形`n × m`。 每个有效点之间的整数坐标`(0, 0)`和`(n, m)`。 

我们必须在其中选择另一个轴对齐的矩形。 矩形由四个整数描述`(x1, y1, x2, y2)`。 所选矩形必须满足三个条件。 

首先，它必须包含给定的点`(x, y)`。 

其次，它的边长必须遵循精确的比例`a : b`。 如果矩形的宽度是`W = x2 - x1`高度是`H = y2 - y1`， 然后：$\frac{W}{H}=\frac{a}{b}$由于所有坐标都是整数，因此`W`和`H`也必须是整数。 

第三，在所有有效矩形中，我们想要面积最大的矩形。 如果几个矩形具有相同的面积，我们最小化它们之间的欧几里德距离`(x, y)`和矩形中心。 如果仍然存在平局，我们选择字典顺序最小的四元组。 

约束条件非常大，最多可达`10^9`。 这立即排除了任何涉及坐标、尺寸或候选矩形迭代的情况。 甚至一个`O(sqrt(10^9))`如果不小心，每个维度的循环就已经很可疑了。 预期的解决方案必须是基本恒定的时间。 

关键的数学观察来自于比率条件。 任何有效的矩形尺寸必须类似于：$W = k\cdot a,\quad H = k\cdot b$对于某些整数比例因子`k`。 

所以整个问题归结为寻找最大整数`k`这样：$k\cdot a \le n,\quad k\cdot b \le m$之后，我们只需要定位矩形，使其包含`(x, y)`并且尽可能以该点为中心。 

一些边缘情况很容易被错误处理。 

假设缩放后的矩形恰好等于整个板。 

输入：```
5 3 2 1 5 3
```唯一有效的答案是：```
0 0 5 3
```一个粗心的实施，试图围绕`(2,1)`先独立移动，然后独立移动可能会产生负坐标或超出边界。 

当点位于边界附近时，会出现另一种微妙的情况。 

输入：```
10 10 0 0 3 2
```最大矩形尺寸为`(9,6)`。 最佳放置位置是：```
0 0 9 6
```如果我们天真地以`(0,0)`，我们会尝试将矩形的一部分放置在网格之外。 

领带的处理也很精致。 

输入：```
8 8 4 4 1 1
```最大平方为`8 × 8`，给予：```
0 0 8 8
```许多居中放置是不可能的，因为矩形已经占据了整个板。 字典顺序仅在最大化面积和最小化中心距离后才重要。 

## 方法

 强力解决方案将枚举尺寸满足比率条件的每个矩形。 由于有效尺寸是以下的倍数`(a,b)`，我们可以迭代所有可能的缩放因子`k`，生成包含以下内容的每个展示位置`(x,y)`，并评估区域和平局规则。 

这种方法在数学上是正确的，因为每个有效的矩形都必须出现在枚举中。 问题在于展示位置的数量。 即使对于一维对，也可以有`O(nm)`展示位置。 接近极限`10^9`，这是完全不可能的。 

突破来自于认识到比率限制只留下一个有意义的选择：最大的可行比例因子。 

如果矩形使用尺寸`(k·a, k·b)`，则其面积为：$Area = (k\cdot a)(k\cdot b)=k^2ab$自从`a`和`b`是固定的，最大化面积与最大化完全相同`k`。 

最大有效比例很简单：$k = \min\left(\left\lfloor\frac{n}{a}\right\rfloor,\left\lfloor\frac{m}{b}\right\rfloor\right)$计算出最佳尺寸后，剩下的任务就是纯粹的几何放置。 

为了最小化之间的距离`(x,y)`和矩形中心，我们希望该点尽可能靠近中心。 沿一个轴，如果矩形长度为`W`，理想的区间以`x`：$\left[x-\frac{W}{2},\ x+\frac{W}{2}\right]$因为坐标必须是整数并且矩形必须位于板内，所以我们将左端点限制在有效范围内`[0, n-W]`。 

相同的逻辑独立适用于 y 轴。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nm) 或更差 | O(1) | O(1) | 太慢了 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算最大可能的缩放因子：```
k = min(n // a, m // b)
```这给出了仍适合板内的最大矩形尺寸。 
2. 计算矩形尺寸：```
w = k * a
h = k * b
```每个具有最大面积的有效矩形必须完全使用这些尺寸。 
3. 将矩形水平放置。 

理想的左边框是：```
x - w // 2
```这试图使矩形以目标点为中心。 
4. 将左边框限制在有效范围内。 

矩形必须满足：```
0 <= x1 <= n - w
```所以：```
x1 = max(0, min(x - w // 2, n - w))
```5. 计算：```
x2 = x1 + w
```6. 垂直重复相同的过程：```
y1 = max(0, min(y - h // 2, m - h))
y2 = y1 + h
```7. 输出`(x1, y1, x2, y2)`。 

为什么它有效：

 面积仅取决于比例因子`k`，因此面积最大的矩形必须使用最大的可行`k`。 一旦尺寸固定，到中心的最小距离就沿着 x 轴和 y 轴变得独立。 围绕`(x,y)`是最佳的，并且当边界迫使矩形时，夹紧只会移动矩形。 任何额外的移动都会使中心移得更远。 当多个放置给出相同的距离时，夹紧公式自然会产生尽可能小的坐标，这也给出了字典顺序上最小的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, x, y, a, b = map(int, input().split())

    k = min(n // a, m // b)

    w = k * a
    h = k * b

    x1 = x - w // 2
    y1 = y - h // 2

    x1 = max(0, min(x1, n - w))
    y1 = max(0, min(y1, m - h))

    x2 = x1 + w
    y2 = y1 + h

    print(x1, y1, x2, y2)

solve()
```第一部分计算最大可行比例因子。 由于每个有效的矩形尺寸必须是以下的倍数`(a,b)`，最大化面积减少为最大化`k`。 

下一部分计算实际矩形的宽度和高度。 这些保证适合，因为`k`是从楼层部门中选出的。 

放置逻辑是微妙的部分。 我们首先尝试将矩形居中`(x,y)`使用`x - w // 2`和`y - h // 2`。 在考虑边界之前，这给出了最接近的可能中心。 

然后我们夹住起始坐标。 有效范围为`x1`是`[0, n-w]`。 如果居中位置超出任一边界，我们会进行足够的移动以使其有效。 这保留了尽可能小的中心距离。 

顺序很重要。 我们必须先计算中心位置，然后夹紧。 在居中之前直接捕捉到边界将会导致打破平局的情况失败。 

所有计算都适合 64 位整数。 无论如何，Python 整数都是无界的，所以溢出从来都不是问题。

 ## 边缘情况

 考虑矩形填充整个板的情况。 

输入：```
5 3 2 1 5 3
```比例因子为：```
k = min(5 // 5, 3 // 3) = 1
```所以：```
w = 5
h = 3
```居中尝试给出：```
x1 = 2 - 2 = 0
y1 = 1 - 1 = 0
```有效范围是：```
0 <= x1 <= 0
0 <= y1 <= 0
```所以矩形被迫：```
0 0 5 3
```该算法可以自然地处理这个问题，因为钳位范围会缩小为单个值。 

现在考虑边界上的一个点。 

输入：```
10 10 0 0 3 2
```我们得到：```
k = 3
w = 9
h = 6
```居中的矩形将从以下位置开始：```
x1 = -4
y1 = -3
```这些值无效，因此钳位会将它们向上移至零：```
x1 = 0
y1 = 0
```最终的矩形变为：```
0 0 9 6
```这是最接近的有效放置，因为任何有效的矩形都必须完全留在板内。
