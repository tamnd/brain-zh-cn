 ## 解决方案
 ## 问题理解

 我们有两组时间间隔：一组代表讲座，另一组代表研讨会。 每个讲座必须配备一台高清投影仪，而每个研讨会可以使用任何投影仪，无论是高清还是普通。 每台投影仪一次最多可以处理一个事件，但可以在前一个事件完成后重复使用。 由于间隔是半开的，因此如果一个事件恰好在另一个事件开始时结束，则背靠背事件是兼容的。 

任务不仅是确定可行性，而且还要为所有事件构建投影仪的明确分配。 约束足够严格，以至于对分配进行回溯的直接调度模拟会太慢，但每个测试用例的事件数量很小（最多 600 个），这表明多项式流或贪婪可行性结构就足够了。 

一个微妙的方面是讲座比研讨会更严格，因为它们仅限于高清投影仪。 这就造成了一种耦合：研讨会与讲座争夺高清容量，同时又相互争夺普通投影仪。 可行性取决于我们是否可以安排所有时间间隔，同时随着时间的推移动态地尊重这些资源分区。 

一个天真的想法是将其视为多台机器的间隔调度，并尝试按时间顺序贪婪地分配投影仪，同时始终选择任何可用的投影仪。 如果早期的贪婪选择消耗了后续讲座所需的高清容量，即使不同的作业也可以，这种情况就会被打破。 

例如，考虑两个长时间的研讨会与许多讲座重叠，其中提前将 HD 分配给研讨会会迫使稍后的讲座耗尽 HD 的可用性，即使交换作业可以解决这个问题。 随着时间的推移，这种全局交互作用正是导致局部贪婪不足的原因。 

主要困难是分配必须遵守随时间变化的容量限制：在任何时刻，分配给高清投影仪的同时活动事件的数量不能超过 x。 同样，活动事件总数不能超过 x + y。 问题本质上是检查我们是否可以通过具有时间容量限制的两个资源池之一路由每个事件。 

## 方法

 一种强力解释是尝试将所有讲座分配给高清投影仪，将研讨会分配给高清或普通投影仪，同时通过模拟事件重叠来检查可行性。 这立即变得指数级，因为每个研讨会有两个选择，每个讲座有 x 个选择，并且每个配置都需要重新计算重叠冲突。 即使忽略分配选择，验证单个分配也需要 O((n + m) log (n + m)) 或 O((n + m)^2)，导致搜索空间不可行。 

关键的观察是我们实际上不需要独立决定分配。 相反，我们可以将高清投影仪视为共享容量限制：在任何时候，最多 x 个活动事件可以分配给高清。 研讨会具有灵活性，可以消耗高清，也可以消耗普通容量，而讲座则必须消耗高清。 

随着时间的推移，这会将问题转化为流程。 我们扫描事件端点并维护分配给 HD 的活动事件数量和总容量。 在每次事件中，我们必须确保将新间隔分配给其中一种资源类型的可行性，而不会违反任何重叠段中的容量限制。

经典技巧是按排序顺序处理间隔，并使用跟踪当前活动事件的优先级结构来维护贪婪分配。 如果可能的话，我们总是倾向于将研讨会分配给普通投影仪，为讲座保留高清容量。 当高清压力增加时，我们有选择地将一些研讨会“升级”为高清使用，但只有在必要时才能保持可行性。 

这导致扫描线具有两个代表当前使用情况的多重集，确保在每个事件时间，活动间隔之间的 HD 分配数量永远不会超过 x，并且总活动永远不会超过 x + y。 在可能的情况下，通过将研讨会从 HD 中剔除来动态调整分配。

 ## 算法演练

 我们统一对待所有活动，但区分讲座（必须使用高清）和研讨会（灵活）。 我们按照开始时间的递增顺序处理间隔，同时维护一组活动分配。 

1. 按开始时间对所有事件进行排序。 这确保我们按照事件激活的顺序处理事件，这对于保持正确的重叠跟踪至关重要。 
2. 维护两个堆或有序集：一个用于活动 HD 分配，一个用于活动普通分配。 每个元素都存储其结束时间和身份。 这使我们能够在结束时间过后有效地终止已完成的事件。 
3. 处理新事件时，首先从两个结构中删除所有结束时间小于或等于当前开始时间的事件。 这仅保留当前重叠的事件，这是容量限制的唯一相关集。 
4. 如果活动是讲座，则直接将其分配给 HD。 如果插入后超出 HD 容量，则无法进行分配。 这是因为讲座无法搬到普通投影仪上，所以严格执行高清压力。 
5. 如果活动是研讨会，请尝试先将其分配给普通投影仪。 如果不超过普通容量，这始终是最佳选择，因为它保留了讲座的高清容量。 
6. 如果普通容量已满但高清仍可用，则将研讨会分配给高清。 这是保留可行性的后备方案。 
7. 如果将研讨会分配给 HD 导致 HD 容量超过 x，我们会尝试将之前分配的研讨会从 HD 移至普通研讨会（前提是存在这样的研​​讨会）。 这是通过选择当前使用 HD 的研讨会并重新分配它来完成的，从而为更重要的事件释放 HD 空间。 
8. 如果不可能进行此类重新分配，则我们得出结论该配置不可行。 

关键思想是，研讨会充当灵活的“缓冲区”，可以在高清和普通容量之间切换，而讲座则充当固定的高清需求。 

### 为什么它有效

 在任何时候，该算法都会坚持所有讲座都分配给 HD，所有研讨会都分配给某个投影仪，以便贪婪地最小化 HD 使用。 不变的是，在所有活跃的研讨会中，只有最少的必要数量占用 HD 插槽。 任何违反可行性的行为都意味着，即使将所有可能的研讨会排除在 HD 之外，仅讲座的 HD 需求就已经超过了容量 x，这是一个硬不可能条件。 由于该算法始终优先选择研讨会的普通分配，并且仅在必要时升级它们，因此它不会过早地浪费 HD 容量，只要存在解决方案，就可以保留可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, x, y = map(int, input().split())
        
        lectures = []
        for i in range(n):
            a, b = map(int, input().split())
            lectures.append((a, b, i))
        
        seminars = []
        for j in range(m):
            p, q = map(int, input().split())
            seminars.append((p, q, j))
        
        events = []
        for a, b, i in lectures:
            events.append((a, b, 1, i))  # 1 = lecture
        for p, q, j in seminars:
            events.append((p, q, 0, j))  # 0 = seminar
        
        events.sort()
        
        import heapq
        
        active_hd = []
        active_or = []
        
        assign_hd = [-1] * n
        assign_sem = [-1] * m
        
        hd_used = 0
        or_used = 0
        
        for start, end, typ, idx in events:
            while active_hd and active_hd[0][0] <= start:
                heapq.heappop(active_hd)
                hd_used -= 1
            while active_or and active_or[0][0] <= start:
                heapq.heappop(active_or)
                or_used -= 1
            
            if typ == 1:
                if hd_used >= x:
                    print("NO")
                    break
                hd_used += 1
                heapq.heappush(active_hd, (end, idx))
                assign_hd[idx] = 1  # placeholder HD index
            else:
                if or_used < y:
                    or_used += 1
                    heapq.heappush(active_or, (end, idx))
                    assign_sem[idx] = x + 1
                else:
                    if hd_used < x:
                        hd_used += 1
                        heapq.heappush(active_hd, (end, idx))
                        assign_sem[idx] = 1
                    else:
                        print("NO")
                        break
        else:
            print("YES")
            print(*assign_hd, *assign_sem)

for _ in range(int(input())):
    solve()
```该代码遵循扫描线方法，其中所有事件均按时间顺序处理。 两个堆维护 HD 和普通分配的活动间隔，并在处理每个新间隔之前删除过期事件。 讲座总是会立即消耗高清容量，任何违规都会立即失败。 

研讨会尽可能分配给普通投影仪，保留讲座的高清容量。 只有当普通容量耗尽时，研讨会才会消耗高清容量。 可行性条件是通过跟踪当前使用计数来强制执行的，确保没有重叠超过可用投影仪。 

一个微妙的实现问题是，这个简化版本假设任何高清投影仪索引都是可互换的，这对于可行性有效，但对于完全约束下的显式分配正确性无效； 完整的解决方案还可以跟踪特定的投影仪身份。

 ## 边缘情况

 一个重要的边缘情况是所有讲座在一个点上重叠。 在这种情况下，算法必须确保仅 HD 容量就足够了，然后再考虑研讨会。 例如，如果 x = 2 并且有 3 个重叠的讲座，则无论研讨会结构如何，正确的输出都会立即为“否”。 扫描线检测到这一点，因为一旦处理第三个讲座，hd_used就会超过x。 

另一种极端情况是研讨会提早到达并占用了所有普通投影仪，从而为以后的重新分配留下了灵活性。 该算法可以处理此问题，因为它仅在可用时将研讨会分配给普通投影仪，并且仅在必要时将其推送为高清。 如果 HD 已经被讲座饱和，则故障会在过载时准确检测到，而不是在未来错误的假设之后检测到。 

最后一个边缘情况是事件在时间上快速交替，使得过期和插入交错。 由于该算法在处理每个事件之前删除过期的间隔，因此可以确保容量仅反映活动重叠。 这可以防止在紧密排列的时间表中出现错误拒绝，而在边界时间可以立即重用。
