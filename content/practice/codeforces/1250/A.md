 ## 解决方案
 ## 问题理解

 我们正在模拟社交媒体源，其中帖子根据传入的点赞不断交换位置。 最初，柱子从上到下以固定的垂直顺序排列，柱子 1 位于顶部，柱子 n 位于底部。 每次帖子收到点赞时，它都会尝试通过与其正上方的帖子交换来向上移动一个位置，除非该帖子已经位于顶部。 

提要随着时间的推移而演变，从初始配置开始，然后在每次点赞之后。 对于每个帖子，我们都被要求确定整个时间线上的两个值：它曾经到达的最佳位置（最接近顶部，意味着最小的索引），以及它曾经到达的最差位置（最接近底部，意味着最大的索引）。 

关键的困难在于头寸是动态的并且取决于之前的所有掉期。 如果我们在每一步都模拟完整的数组和跟踪位置，则每次交换都是 O(1)，但是更新位置需要搜索 post，这会导致效率低下，除非我们维护辅助结构。 

该限制允许最多 100,000 个帖子和 400,000 个点赞。 任何扫描数组以查找每个点赞上的帖子的解决方案都会降低到 O(nm)，这远远超出了可行的范围。 甚至 O(m log n) 也是不必要的； 该结构非常简单，我们可以通过直接索引在线性时间内维护所有内容。 

当一个帖子连续获得多个点赞时，就会出现一种微妙的边缘情况。 在这种情况下，它可能会小幅向上振荡，天真的直觉可能会错误地认为它到达位置 1 的次数比实际情况要多。 另一种极端情况是某个帖子根本不被喜欢； 它的最小位置最初仍然是 1，并且它的最大位置始终保持为 n。 

## 方法

 强力模拟保留代表提要的整个数组，并且对于每个喜欢的帖子，搜索喜欢的帖子的位置，将其与其上面的元素交换，然后继续。 这正确地对系统进行了建模，但每次搜索的时间复杂度为 O(n)，并且有 m 个操作，导致复杂度为 O(nm)。 对于最坏情况的输入，这超过了 4 × 10^10 次操作。 

关键的观察是我们永远不需要知道每一步之后的完整结构。 我们只需要知道每个帖子当前在哪里，并且只更新本地交换。 这建议维护一个位置数组，将每个帖子映射到其当前索引。 那么每次交换就变成了 O(1)，因为我们可以直接访问和更新仓位。 

为了计算最小和最大位置，我们跟踪每个帖子的两个数组：它曾经占用的最小索引和它曾经占用的最大索引。 每次帖子移动时，我们都会更新其当前位置，并可能更新其记录的边界。 

与暴力破解的区别在于，我们不是搜索数组，而是维护从后到索引的逆映射，将每个操作变成恒定时间簿记。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 | O(纳米) | O(n) | 太慢了 |
 | 带跟踪的位置测绘 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个数组 pos，其中 pos[i] 是帖子 i 的当前位置，以及一个数组 order，其中 order[p] 是当前位于位置 p 的帖子。 我们还为每个帖子维护最好和最差的数组。

1. 初始化order，使得order[1] = 1，order[2] = 2，...，order[n] = n，并为所有i设置pos[i] = i。 为所有帖子设置 best[i] = i 和 bad[i] = i。 这会捕获任何喜欢之前的初始配置。 
2. 对于每个类似的 a_j，检索其当前位置 p = pos[a_j]。 这是 O(1)，因为我们维护直接索引。 
3. 如果 p 已经是 1，除了确保边界保持正确之外，我们只更新任何内容，因为不会发生任何移动。 
4. 否则，令其上方的帖子为 b = order[p - 1]。 我们交换 order 数组中的 a_j 和 b，并相应地更新它们在 pos 中的位置。 
5. 交换后，使用新职位更新两个受影响职位的最佳和最差。 只有这两个柱子改变位置，因此只有它们可以影响边界。 
6. 继续按顺序处理所有点赞。 

处理完所有更新后，best[i]和worst[i]包含帖子i所达到的最小和最大索引。 

### 为什么它有效

 该系统仅通过相邻交换来发展，因此每个操作恰好影响两个帖子。 由于位置是明确跟踪的，因此 pos 数组始终准确无误地反映当前配置。 每次职位变动时，我们都会立即评估其新职位是否提高了历史最小值或最大值。 由于没有其他帖子受到该交换的影响，因此不需要进行额外的更新。 这保留了正确性，同时避免了全局重新计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))

pos = [0] * (n + 1)
order = [0] * (n + 1)

best = [0] * (n + 1)
worst = [0] * (n + 1)

for i in range(1, n + 1):
    pos[i] = i
    order[i] = i
    best[i] = i
    worst[i] = i

for x in a:
    p = pos[x]
    if p == 1:
        continue

    y = order[p - 1]

    order[p], order[p - 1] = order[p - 1], order[p]
    pos[x] = p - 1
    pos[y] = p

    best[x] = min(best[x], p - 1)
    worst[x] = max(worst[x], p - 1)

    best[y] = min(best[y], p)
    worst[y] = max(worst[y], p)

for i in range(1, n + 1):
    print(best[i], worst[i])
```其核心结构是岗位与职位之间的双向映射。 pos 数组避免了任何搜索，并且顺序确保我们可以在恒定时间内更新邻居。 唯一微妙的一点是，两个交换的帖子必须在交换后立即更新其最佳和最差值，因为两者都改变​​了位置。

 ## 边缘情况

 从未被点赞的帖子永远不会移动，因此其最佳位置仍为 1，最差位置仍为 n。 该算法可以处理此问题，因为初始化正确设置了两个边界，并且没有任何更新触及该帖子。 

获得重复点赞的帖子可以逐步向顶部移动。 每次交换都会更新两个参与者，因此中间位置都会被捕获。 由于每个运动都是局部的，因此不需要全局重新计算。 

当前顶部元素上的 like 不会触发交换。 位置 1 的条件检查可防止无效的数组访问并确保不会发生不必要的更新，从而保持正确性并避免索引错误。
