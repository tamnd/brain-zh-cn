 ## 解决方案
 ## 问题理解

 我们有一个城市和道路的有向图。 城市`1`是首都。 每条道路要么已经可用，要么已损坏。 破损的道路可以被修复，之后它的行为就像正常的有向边缘一样。 

政府希望从首都可以到达每个城市。 我们可以修复任何损坏的道路，但我们必须尽量减少修复次数。 

图是有向的，彻底改变了问题。 一条路从`u`到`v`仅在这个方向上有帮助。 即使有回去的路，也无助于首都到达城内。 

输入给出每个边以及一个标志：

 -`0`意味着道路已经通车。 
-`1`意思是路坏了，必须修好才能使用。 

输出是：

 -`-1`如果修复了所有破损的道路后仍然无法到达某个城市，或者
 - 已修复道路的最小数量以及一组有效的边缘索引。 

限制很大：两者`n`和`m`达到`10^5`。 任何重复运行图遍历或从头开始重新计算可达性的算法都会失败。 例如，尝试每条破损道路的子集是不可能的，甚至每个顶点运行一次 BFS 也已经变得太慢了。 

需要线性或近线性图算法。 周围有东西`O(n + m)`是理想的。 

一些边缘情况很容易被错误处理。 

考虑这个图：```
1 -> 2 (broken)
2 -> 3 (good)
```输入：```
3 2
1 2 1
2 3 0
```仅修复第一个边缘就足够了。 一个粗心的解决方案会分别最大限度地减少每个城市的修复，可能会错误地多次计算相同的修复边缘。 

另一个危险的情况是无法访问的组件：```
4 2
1 2 0
3 4 1
```城市`3`和`4`即使每条道路都修好了，与首都的联系也断开了。 正确答案是：```
-1
```一些实现仅使用当前良好的道路进行搜索，并错误地得出修复某处的边缘会有所帮助的结论。 

周期也很重要：```
3 3
1 2 1
2 3 0
3 2 0
```修边`1 -> 2`解锁两者`2`和`3`。 最佳答案是修复一个边缘，而不是两个。 

问题的结构是全球性的。 我们并不是独立连接城市。 我们正在建设一个从首都直达的区域。 

## 方法

 蛮力的想法很简单。 将每个断边视为可选，尝试断边的所有子集，并检查是否所有顶点都可以从首都到达。 

如果有`k`破损的边缘，这需要`2^k`子集。 可达性检查成本`O(n + m)`每次。 即使只有`40`破损的边缘，这将变得天文数字般巨大。 

稍微聪明一点的蛮力会独立尝试每个城市的最短路径。 分配成本`0`良好的优势和成本`1`到破损的边缘。 然后计算到达每个顶点所需的最小修复次数。 

这对于个别城市是有效的，但并不能解决真正的优化目标。 不同的城市可以共享修复的边缘。 对独立的最短路径成本求和会超出维修成本。 

关键的观察是，我们只关心每个顶点是否可达，而不是分别最小化每个路径。 

假设我们分配权重：

 -`0`到良好的边缘，
 -`1`到破损的边缘。 

现在想象一下构建一棵以首都为根的最短路径树，其中节点的距离意味着到达该节点所需的最小修复边数。 

如果该加权图中的每个节点都是可达的，则选择最短路径树中使用的父边会给出一组全局最优的已修复道路。 

为什么这有效？ 

最终解决方案中的每条修复边都必须出现在从首都出发的路径上的某个位置。 最短路径树保证以尽可能少的修复边数到达每个节点。 更重要的是，所有父边的联合形成了有向树状结构。 该树中任何修复的边都有助于到达至少一个新顶点。 没有浪费修复。 

由于边权重仅`0`和`1`，我们可以在线性时间内使用 0-1 BFS 计算最短路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解修复子集 |$O(2^k \cdot (n+m))$|$O(n+m)$| 太慢了 |
 | 每个城市独立的最短路径 |$O(n(n+m))$|$O(n+m)$| 错误的想法|
 | 0-1 BFS+最短路径树|$O(n+m)$|$O(n+m)$| 已接受 |

 ## 算法演练

 1. 构建有向图。 

对于每条边，存储：

 - 目标顶点，
 - 维修费用（`0`或者`1`),
 - 原始边缘索引。 
2.从城市运行0-1 BFS`1`。 

通过良好的边缘成本`0`。 

跨越破碎的边缘需要付出代价`1`。 

因为所有的权重都是`0`或者`1`，我们可以使用双端队列：

 - 推动成本前沿`0`,
 - 推迟成本`1`。 

这将计算到达每个城市所需的最小修复边缘数量。 
3. 放松边时，存储产生最佳距离的父边。 

对于每个顶点`v`， 保持：

-`parent[v]`= 用于到达的边缘索引`v`,
 -`parent_cost[v]`= 该边缘是否破损。 
4. 如果某些城市仍然无法到达，则打印`-1`。 

这意味着即使修复了每个破损的边缘之后也不存在定向路径。 
5. 重建所选的修复集。 

除首都外的每个顶点在最短路径树中都恰好有一条父边。 

遍历所有顶点：

 - 如果父边被破坏，则将其索引添加到答案中。 
6. 输出收集到的边缘索引。 

这种边的数量是最少的。 

### 为什么它有效

 该算法保持不变式`dist[v]`等于达到所需的最小修复边数`v`来自首都。 

父指针定义最短路径树。 每个顶点都通过一条达到最小修复次数的路径连接到首都。 

假设另一种解决方案修复的道路总体较少。 那么，我们的树中至少有一个顶点需要使用比其最短路径距离更少的修复边来到达，这是不可能的。 

所选择的修复边正是最短路径树中出现的断边。 删除其中任何一棵都会断开至少一棵子树与首都的连接。 每一次选择的修复对于树结构都是必要的。 

由于树到达所有顶点并沿每条从根到顶点的路径使用尽可能少的已修复边，因此已修复道路的总数全局最小。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for idx in range(1, m + 1):
        a, b, c = map(int, input().split())
        graph[a].append((b, c, idx))

    INF = 10**18

    dist = [INF] * (n + 1)
    parent = [-1] * (n + 1)
    parent_cost = [0] * (n + 1)

    dist[1] = 0

    dq = deque([1])

    while dq:
        u = dq.popleft()

        for v, w, idx in graph[u]:
            nd = dist[u] + w

            if nd < dist[v]:
                dist[v] = nd
                parent[v] = idx
                parent_cost[v] = w

                if w == 0:
                    dq.appendleft(v)
                else:
                    dq.append(v)

    for v in range(1, n + 1):
        if dist[v] == INF:
            print(-1)
            return

    ans = []

    for v in range(2, n + 1):
        if parent_cost[v] == 1:
            ans.append(parent[v])

    if not ans:
        print(0)
    else:
        print(len(ans))
        print(*ans)

solve()
```该图存储为邻接列表，因为约束对于邻接矩阵来说太大。 

实现的核心部分是0-1 BFS。 普通的 BFS 只适用于未加权的图，而 Dijkstra 可以工作，但在这里不必要地昂贵。 由于每个边权重都是`0`或者`1`，双端队列在线性时间内模拟 Dijkstra。 

当放松改善时`dist[v]`，代码也更新了：

 - 用于进入的边缘`v`,
 - 该边缘是否需要修复。 

最短路径树通过这些父指针隐式存储。 

一个微妙的点是我们仅在以下情况下更新`nd < dist[v]`， 不是`<=`。 一旦顶点已经有了最佳距离，就没有必要将其替换为另一个等距离的父顶点。 

另一个重要的细节是无法到达的检测。 如果节点仍有距离`INF`在BFS之后，即使修复所有断边也无法将其连接到首都，因为根本不存在有向路径。 

最后，通过扫描父边缘来重建答案。 每个破损的母边都必须修复。

 ## 边缘情况

 考虑断开连接的图：```
4 2
1 2 0
3 4 1
```BFS从城市开始`1`并且只到达城市`2`。 城市`3`和`4`保持距离`INF`。 

该算法立即打印：```
-1
```这是正确的，因为即使每一条破损的道路都被修复，也不存在从首都出发的直接路径。 

现在考虑共享修复：```
3 2
1 2 1
2 3 0
```距离变为：

 -`dist[2] = 1`-`dist[3] = 1`两个城市都依赖于相同的修复边缘`1 -> 2`。 最短路径树只包含一条断边，所以答案是：```
1
1
```幼稚的按城市计算的方法可能会错误地计算两次维修。 

最后，考虑周期：```
3 3
1 2 1
2 3 0
3 2 0
```BFS修复边缘`1 -> 2`一次，然后之间循环`2`和`3`已经可以通过良好的道路使用。 

该算法输出：```
1
1
```该循环不会混淆父树结构，因为每个顶点仅保留最知名的传入边。
