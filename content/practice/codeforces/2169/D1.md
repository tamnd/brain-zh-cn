 ## 解决方案
 ## 问题理解

 我们从自然数的无限序列开始，有效地将其视为数组`1, 2, 3, 4, ...`。 该过程根据固定步长重复删除元素`y`：每次应用操作时，我们都会删除位于该位置的元素`y, 2y, 3y, ...`在当前序列中（在 _current_ 压缩数组中位置始终为 1 索引）。 

执行此操作`x`次，在所有删除之后，我们想知道什么数字最终出现在位置上`k`剩余序列的长度，或者序列是否变得太短。 

关键的难点在于，每次删除后，序列都会缩小，所以“位置”的含义`y`” 动态变化。我们不会删除可被整除的值`y`，但是在不断演化的数组中按_rank删除_，这使得大规模的直接模拟变得不可能。 

这些限制使得这种情况变得更加严重。 两个都`y`和`k`可以达到$10^{12}$， 和`x`可以达到$10^5$。 这排除了任何显式构建甚至迭代序列的方法。 即使在概念范围内维护线段树也是不可行的，因为宇宙是无界的。 

出现微妙的边缘情况时`y = 1`。 在这种情况下，第一个操作会删除每个元素（因为每个位置都是 1 的倍数），并且序列立即变为空。 任何`k ≥ 1`必须返回`-1`。 假设“某些元素幸存”的幼稚方法将立即失败。 

另一个重要的情况是当`y`与当前序列大小相比非常大。 那么后面的操作可能什么都不做，但粗心的模拟可能仍会尝试迭代并删除不存在的索引，如果不仔细检查边界，则会导致错误的行为。 

最后，当`k`非常大，答案通常很简单`-1`因为序列在操作过程中会成倍地缩小。 许多不正确的解决方案都因未正确跟踪真实的剩余尺寸而失败。 

## 方法

 如果我们尝试直接模拟，我们会维护当前列表并重复删除每个`y`-th 元素。 每个操作都针对一个大小序列`n`需要$O(n)$，所以整个过程成本$O(xn)$。 由于初始序列在概念上是无限的，即使我们将其限制为`k`或略高于，值`k`最多$10^{12}$使这完全不可行。 

关键的观察是我们实际上不需要跟踪单个元素。 我们只需要了解还剩下多少元素以及索引如何转换。 

当我们删除每一个`y`- 长度序列中的第一个元素`n`，我们粗略地删除`n / y`元素，留下：$$n - \left\lfloor \frac{n}{y} \right\rfloor$$更重要的是，这个操作相当于压缩序列，同时“跳过”周期位置。 这个结构是稳定的：每次操作后，新序列仍然是一个有间隙的自然数递增序列，并且删除规则仅取决于_当前长度_，而不取决于实际值。 

这引出了第二个见解：我们可以计算有多少原始数字在达到阈值时仍然存在，而不是构建序列`N`，然后二分查找最小的`N`这样至少`k`数字幸存下来。 

剩下的任务变成评估，对于一个固定的`N`, 有多少个数字来自`1..N`之后生存`x`轮次删除每个`y`进化序列中的第-个位置。 我们仅模拟对计数的影响，这本质上是对数的，因为每轮都会将活动集缩小一个接近于`y/(y-1)`。 

因此，我们可以对第 k 个元素的值进行二分搜索，并通过模拟删除过程来验证每个候选者$O(x)$。 

自从`x ≤ 10^5`，这是可以接受的：每个检查都是线性的`x`，我们执行关于`log(10^12)`检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(x \cdot n)$|$O(n)$| 太慢了 |
 | 二分查找+计数模拟|$O(x \log A)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将问题重新表述为寻找最小的数字`ans`这样在所有删除之后，至少`k`无限序列中的数字是`≤ ans`。 

### 步骤

 1. 我们对待候选答案`mid`作为截止点并模拟有多少个数字`1..mid`全部生存下来`x`运营。 

这样做的原因是序列是严格递增的，并且删除永远不会重新排序元素，因此生存仅取决于等级进化。 
2.我们维护一个变量`cnt = mid`，表示我们正在跟踪的段中当前存在多少个元素。 
3. 对于每个操作`1`到`x`，我们减少`cnt`经过`cnt // y`。 

该模型消除了每个`y`当前压缩序列中的第一个元素。 

直觉是，在每个块中`y`连续的幸存位置，恰好有一个被删除。 
4.全部应用后`x`运营，`cnt`代表有多少个数字`1..mid`存活。 
5. 如果`cnt >= k`, 候选人`mid`足够大，所以我们将二分查找向左移动。 

否则，我们增加`mid`。 
6.我们二分查找`mid`在足够大的范围内包含答案，通常达到安全上限，例如$10^{18}$。 

### 为什么它有效

 核心不变量是，每次操作后，剩余元素的行为就像一个统一的序列，其中删除仅取决于相对位置，而不是实际值。 这使得计数演化独立于身份并完全由`cnt`。 因为每个步骤都以单调方式转换集合（较大的初始段总是产生较大的幸存者），谓词“`mid`足以产生至少`k`幸存者”是单调的，可以进行二分搜索。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(mid, x, y, k):
    cnt = mid
    for _ in range(x):
        if cnt == 0:
            return False
        cnt -= cnt // y
    return cnt >= k

t = int(input())
for _ in range(t):
    x, y, k = map(int, input().split())

    if y == 1:
        print(-1)
        continue

    lo, hi = 1, 10**18
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, x, y, k):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)
```功能`can(mid, x, y, k)`模拟所有的效果`x`对长度前缀的操作`mid`。 每次迭代都会将当前计数减少`cnt // y`，表示该阶段删除的元素数量。 

二分搜索包装了这个可行性检查，并找到仍然至少留下的最小前缀长度`k`幸存的元素。 

特殊情况`y = 1`是单独处理的，因为序列在第一次操作后立即崩溃为零。 

## 工作示例

 ### 示例 1

 输入：```
2 3 5
```我们寻找最小的`mid`这样经过 2 次操作后`y = 3`，至少有 5 个数字幸存。 

| 中| 操作 1 之后 | op2 之后 | 结果 |
 | --- | --- | --- | --- |
 | 10 | 10 10 - 3 = 7 | 10 - 3 = 7 | 7 - 2 = 5 | 7 - 2 = 5 5 |
 | 9 | 9 - 3 = 6 | 9 - 3 = 6 6 - 2 = 4 | 6 - 2 = 4 4 |

 为了`mid = 10`，我们至少还有 5 名幸存者，所以它是有效的。 为了`mid = 9`，我们没有。 二分查找收敛于`10`。 

这表明了可行性条件的单调性。 

### 示例 2

 输入：```
1 1 1
```为了`y = 1`，第一个操作删除了每个位置，因此任何候选者`mid`立即变成零幸存者。 

| 中| 操作 1 之后 | 结果 |
 | --- | --- | --- |
 | 1 | 0 | 0 |

 由于我们至少需要一个元素，所以答案是`-1`。 这证实了特殊情况处理是必要的。

 ## 边缘情况

 当`y = 1`，第一个操作删除序列中的每个位置。 该算法显式返回`-1`，这与以下事实相符：无论发生什么，都没有元素能够生存`x`或者`k`。 

为了`mid = 1`，模拟正确应用`cnt -= cnt // y`，只有当`y = 1`，否则它保持 1。这确保了最小边界得到正确处理，而无需超出特殊范围`y = 1`。 

什么时候`k = 1`，二分查找自然会找到最小的`mid`在所有删除之后至少有一个元素幸存下来。 由于生存条件是单调的`mid`，即使在多次删除删除大多数元素的情况下，搜索也会收敛到第一个有效前缀。 

对于非常大的`x`，重复应用可以快速稳定计数，通常达到零或固定点。 循环仍然运行在$O(x)$，但每次迭代都是恒定时间，并且不会发生溢出或结构变化，因为仅使用整数除法。
