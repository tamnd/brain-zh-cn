 ## 解决方案
 ## 问题理解

 该任务模拟将数字插入到一个小哈希表中。 该表有固定数量的桶，以及`x`被分配到桶`x mod p`。 每个桶只能存储一个数字。 数字按照给定的顺序一个接一个地到达，我们必须找到插入尝试使用已经包含另一个数字的存储桶的第一个位置。 如果每次插入都进入空桶，则答案是`-1`。 

输入给出桶的数量`p`，要插入的值的数量`n`，然后是值的序列。 输出是第一个冲突插入的从 1 开始的索引。 

约束很小，两者都有`p`和`n`限制为 300。这意味着即使是简单的模拟也足够快。 插入次数只有几百，因此具有线性或二次行为的算法都适合。 不需要高级的哈希结构，因为整个表很小。 

主要的边缘情况来自插入的顺序以及看起来不同但映射到同一存储桶的值。 例如，与：```
5 3
1
6
11
```正确的输出是：```
2
```因为`1 mod 5`,`6 mod 5`， 和`11 mod 5`都等于`1`。 第二次插入已经是一个冲突。 存储原始数字而不是存储桶位置的粗心实现会错误地认为所有三个值都是不同的。 

另一种情况是当所有桶都被填满且没有冲突时：```
4 4
0
1
2
3
```正确的输出是：```
-1
```假设最后一次插入必须失败的解决方案是错误的。 如果每个值都插入到唯一的存储桶中，则完整表仍然有效。 

最终的边界情况是相同的值出现两次：```
10 2
123456789
123456789
```正确的输出是：```
2
```第二个值映射到与第一个值完全相同的存储桶。 仅比较原始值是否重复是不必要的，因为不同值之间也可能发生冲突。 

## 方法

 暴力方法是完全按照描述模拟哈希表。 维护每个存储桶的当前内容。 对于每个传入的号码，使用余数运算计算其桶索引，并检查该桶是否已被占用。 如果为空，请将其标记为已使用并继续。 如果被占用，则当前位置就是答案。 

这种方法是正确的，因为问题要求实际插入顺序中的第一个冲突，并且模拟直接遵循该顺序。 最坏的情况执行`n`插入和每次插入进行一次恒定时间检查，因此即使直接实现也只需要大约 300 次操作。 

关键的见解是哈希表本身是唯一重要的状态。 一旦一个值被转换成它的存储桶索引，原始数字就不再影响未来的决策。 我们根本不需要存储数字，只需要存储每个桶是否已经接收到一个元素。 

暴力模拟和最优解实际上是相同的想法。 优化是认识到状态可以用一个简单的布尔数组来表示`p`。

 ## 算法演练

 1. 创建一个代表哈希表桶的数组。 每个位置存储该桶是否已被使用。 
2. 按出现的顺序读出每个数字。 计算其桶索引为`x mod p`。 
3. 检查对应的桶。 如果已经被占用，则输出当前插入位置，因为这是第一次冲突。 
4. 如果桶是空的，则将其标记为已占用并继续处理下一个数字。 
5、如果所有数字都处理完没有发现冲突，则输出`-1`。 

这样做的原因是，以后的每次插入仅取决于哪些存储桶被占用，而不取决于哪些值创建了这些被占用的存储桶。 准确保留此信息足以重现哈希表的行为。 

为什么它有效：处理第一个之后`i`值，桶数组与真实的哈希表完全匹配`i`插入。 对于下一个值，算法会检查实际插入将使用的相同存储桶。 如果被占用，则真实进程和算法都在这一步检测到冲突。 如果为空，则将其标记为已填充并继续。 由于每次插入后不变式都成立，因此第一个报告的冲突始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    p, n = map(int, input().split())
    used = [False] * p

    for i in range(1, n + 1):
        x = int(input())
        bucket = x % p

        if used[bucket]:
            print(i)
            return

        used[bucket] = True

    print(-1)

if __name__ == "__main__":
    solve()
```数组`used`代表哈希表桶。 它的尺寸正好是`p`，所以每个可能的桶索引都有一个对应的位置。 

循环开始于`1`因为答案是基于插入数，而不是基于零的数组索引。 在将存储桶标记为已占用之前，代码会检查它是否已被使用。 这个顺序很重要，因为首先更改值会隐藏冲突。 

Python整数直接处理大输入值，因此不需要对溢出进行特殊处理。 模运算立即将每个值减少到之间的有效桶索引`0`和`p - 1`。

 ## 边缘情况

 对于不同值发生冲突的情况，比如：```
5 3
1
6
11
```算法过程`1`并标记桶`1`。 当它达到`6`，它计算`6 mod 5 = 1`，看到那个桶`1`已经被占用，立即输出`2`。 它永远不需要检查剩余的值，因为第一个冲突已经被发现。 

对于完全有效的表格填充：```
4 4
0
1
2
3
```每个值映射到不同的存储桶。 该算法标记桶`0`,`1`,`2`， 和`3`为了。 没有遇到被占用的桶，所以循环结束后返回`-1`。 

对于重复值：```
10 2
123456789
123456789
```第一个插入标记桶`9`。 第二次插入计算相同的桶索引并发现它已被占用。 算法报告`2`，匹配所需的第一个冲突位置。
