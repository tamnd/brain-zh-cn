 ## 解决方案
 ## 问题理解

 我们得到了目标空间量，以及大小为 2 的幂的可用块的集合。 任务是决定我们是否可以使用这些块精确地组合目标大小，如果不能，则报告不可能。 如果可能的话，我们希望尽量减少将大块分割成小块的次数。 

关键操作是任意大小的块$2^k$可以分成两个大小的块$2^{k-1}$。 此操作在可用性方面是免费的，但算作一个分区。 分割后，我们可以使用生成的较小块来填充所需的总大小。 

我们并不是试图选择任意子集；而是尝试选择任意子集。 相反，一切都归结为管理我们在每个 2 的幂上有多少个块，并决定何时被迫分割一个更大的块以满足目标丢失的较低位。 

约束条件$n \le 10^{18}$立即告诉我们，我们无法使用大循环来模拟简单的逐位构造中的目标$n$。 位数最多为 60，因此任何解决方案都应在$O(\log n)$每个测试用例。 测试中的盒子总数为$10^5$，因此只有在总输入大小保持线性的情况下，诸如每框重模拟之类的东西才是可接受的。 

当我们贪婪地获取更大的块而不仔细考虑未来的分裂时，就会出现微妙的失败情况。 例如，如果我们消费$2^k$块的更高位$n$即使稍后需要分裂的较低位，我们也可能低估或高估所需的分裂数量。 当我们有足够的总和但二进制对齐不正确时，例如有许多$1$-块但需要尽早获得更大的块，通过分割更高的权力来强制进行多次合并。 

真正的困难在于分裂向下传播，有时我们必须借用较高位来满足较低位，而这种借用就是产生分裂成本的原因。 

## 方法

 直接的强力视图会将其视为块大小的多集配置的状态问题。 在任何时候，我们都可以使用一个与所需大小匹配的块，或者将一个较大的块分成两个较小的块。 对 2 的幂的所有块分布进行 BFS 或 DP 最终会找到最小的分割数。 然而，即使限制为每位级别的计数，每个级别也可以增长到$10^5$，而且多达60级，因此状态空间变得天文数字般大。 即使是仔细的最短路径解释也会失败，因为转变会在各个层面上反复重新分配质量，从而产生状态爆炸。 

关键的观察是我们永远不需要任意重新排列块; 我们只需要跟踪每个 2 的幂有多少个块，并从最低有效位向上处理目标位。 当一点点$n$需要一个大小的块$2^i$，我们要么已经有了一个，要么必须通过分割更大的块来构造它。 分裂一个$2^k$阻止进入$2^i$需要$k - i$分裂，并且它还产生必须考虑的中间块。 

这表明对位位置的贪婪模拟：我们维护每个 2 的幂的可用计数，并且对于每个位$n$，我们保证供应。 如果丢失，我们从最近的较高级别拉出并向下传播盈余，仔细计算分裂。 

该结构之所以有效，是因为二进制表示$n$是固定的，因此每一位独立地需要该功率的一个单位，并且任何不匹配都可以通过以确定性成本借用更高的功率来在本地解决。

 ## 算法演练

 我们将可用框表示为 2 的幂的计数。 让`cnt[i]`有多少块大小$2^i$我们目前有。 

然后我们处理这些位$n$从最低到最高，维持一个运行模拟，当我们分割较大的块时，块如何向下流动。 

1. 构建频率数组`cnt`，按指数对所有输入框进行分组$i$这样$a = 2^i$。 这为我们提供了每个级别的初始供应量。 
2. 从 0 到 60 遍历位位置，因为$n \le 10^{18}$。 在每个位置$i$，检查是否$i$第 位$n$已设置。 
3. 如果该位已设置并且我们已经有一个块`cnt[i]`，我们消耗一个并继续。 
4. 如果该位已设置但`cnt[i]`为零，我们寻找最近的$j > i$这样`cnt[j] > 0`。 如果不存在，任务就不可能完成。 
5. 一旦我们找到这样一个$j$，我们重复分割一个大小的块$2^j$缩小尺寸$2^i$。 每次分割都会将答案增加 1，并生成填充之间所有级别的中间块$i$和$j$。 
6.分裂后，我们递减`cnt[j]`，并相应地增加所有中间级别，确保质量守恒。 
7. 现在我们在一级消耗一个单位$i$。 
8. 满足所需位后，我们通过计数隐式处理向上传播剩余部分，因为未使用的块仍然可用于较高位。 

微妙的不变量是处理后的级别$i$，以下级别的所有剩余块$i$已正确说明，未来的操作不需要重新访问它们。 

正确性依赖于这样一个事实：每次分裂都严格以受控方式向下移动质量，并且贪婪地选择最近的可用更高块可以最大限度地减少分裂数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        cnt = [0] * 61

        for x in map(int, input().split()):
            cnt[x.bit_length() - 1] += 1

        ans = 0

        for i in range(61):
            if (n >> i) & 1:
                j = i
                while j < 61 and cnt[j] == 0:
                    j += 1

                if j == 61:
                    ans = -1
                    break

                while j > i:
                    cnt[j] -= 1
                    cnt[j - 1] += 2
                    ans += 1
                    j -= 1

                cnt[i] -= 1

            cnt[i + 1] += cnt[i] // 2
            cnt[i] %= 2

        print(ans)

if __name__ == "__main__":
    solve()
```该实现使用位长度将所有盒子大小压缩为指数计数，因为每个$a_i$是二的幂。 主循环扫描位位置$n$。 当所需的位丢失时，它向上搜索最近的可用较大块并执行重复减半。 每减半算一次。 

处理完级别的需求后$i$，我们通过向上携带剩余的对来标准化系统，因为两个大小的块$2^i$可以形成一个大小的块$2^{i+1}$。 这确保了表示对于未来的步骤保持最小且一致。 

一个微妙的实现细节是我们总是递减`cnt[i]`满足一点后，因为那一点代表了实际的消费。 另一个微妙之处是每次迭代后的进位步骤，这可以防止过度计算碎片小块。

 ## 边缘情况

 当最大可用块远高于所需位时，例如需要$2^0$但只有$2^{50}$。 该算法反复向下分割，对每一步进行计数，并正确累加了 50 次操作。 这避免了将其视为单个部门的错误捷径。 

另一种边缘情况是当可用块的总和足够但在 2 的幂上未对齐时。 例如，多个$2^1$块不能直接满足$2^2$要求，无需通过进位或借用进行合并。 进位机制确保多余的小块被正确聚合。 

尽管总金额很大，但最终的边缘情况是不可能的。 如果在所需时刻不存在更高的块，则搜索更高指数失败并且算法返回$-1$立即地。 这可以正确处理分解无法桥接缺失层次结构级别的情况。
