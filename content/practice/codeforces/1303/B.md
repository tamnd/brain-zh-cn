 ## 解决方案
 ## 问题理解

 我们正在建设一条漫长的道路$n$，其中每个道路单位最终必须只铺设一次沥青。 建设日复一日地进行，每天我们要么只做一个单元，要么什么也不做。 

天气是有周期性的。 它从一个块开始$g$美好的日子，接下来$b$糟糕的日子，这种模式会永远重复。 这个过程总是在美好的一天开始。 如果我们在天气好的时候铺设沥青，那么该单元的质量就会很高； 如果我们在糟糕的一天放置它，它的质量就会变差。 跳过一天不会提前施工，但仍会提前日历。 

目标不是天真的意义上最小化成本或时间，而是最小化所需的总天数，以便所有$n$单位已完成，但有一个额外的限制，即至少其中一半必须是高质量的。 所需的高质量单位数量为$\lceil n/2 \rceil$。 

约束条件$n, g, b \le 10^9$和$T \le 10^4$排除几天内的任何模拟。 即使模拟单个测试用例达到答案范围也是不可能的，因为答案本身可能约为$10^{18}$。 该解决方案必须依赖于对时间前缀中出现多少好日子的直接数学表征。 

当好日子比坏日子少时，就会出现一个微妙的问题。 像“总是在好的日子里工作，用坏的日子填充其余的日子”这样天真的贪婪策略可能会误导直觉，因为跳过会改变与周期结构的对齐。 另一个失败案例是假设我们可以独立选择哪些日子可以使用，而不考虑它们的固定周期位置。 

## 方法

 强力解释将逐日模拟，跟踪每一天是好是坏，并计算我们建造了多少优质单元和总单元。 一旦到达我们就会停下来$n$单位并检查至少一半是否是高质量的。 这在概念上是可行的，因为它直接遵循流程定义，但它可能需要迭代直到答案时间，该时间可能非常长。 在最坏的情况下，当好日子很少出现并且我们经常跳过或浪费对齐时，模拟可能会增长到$O(\text{answer})$，这远远超出了限制。 

关键的观察是，如果我们之前已经有足够的好机会，那么我们永远不会从完成更少的总单元中受益。 相反，该结构仅取决于第一个发生的好日子的数量$d$日历的天数。 由于该模式是完全周期性的，因此我们可以计算任何前缀中的好天数，而无需进行模拟。 

对于任何前缀$d$天，我们有完整的周期长度$g+b$，并且每个周期都准确贡献$g$美好的日子。 其余贡献$\min(g, d \bmod (g+b))$美好的日子。 因此：$$\text{good}(d) = \left\lfloor \frac{d}{g+b} \right\rfloor g + \min(g, d \bmod (g+b))$$现在构造问题变成：找到最小的$d$这样我们就可以放置$n$总单位数$d$天，同时确保至少$\lceil n/2 \rceil$这些展示位置中有一部分是在美好的日子里进行的。 由于我们随时都可以工作，因此总安置数为$d$日子简直就是$d$，所以我们只需要$d \ge n$，真正的限制是最初的日子是否美好$d$天数至少$\lceil n/2 \rceil$。 如果没有，我们必须延长$d$直到足够多的好日子出现。 

因此，问题简化为二分搜索$d$，检查单调条件。

 | ---| ---| ---| ---|

 ## 算法演练

 我们专注于单个测试用例。 

1. 计算所需的高质量单元数量为$need = \lceil n/2 \rceil$。 这是我们必须用沥青铺设“覆盖”的最少好天数。 
2. 定义函数$good(d)$返回第一个出现的好日子数$d$使用循环算术的天数。 这样就避免了模拟，直接使用周期结构。 
3. 检查是否给定$d$是足够的：它必须同时满足$d \ge n$（我们必须至少有足够的天数来铺设所有单元）并且$good(d) \ge need$（存在足够多的优质展示位置）。 
4. 使用二分查找$d$在很大的范围内，通常$[1, 10^{18}]$，因为当糟糕的日子占主导地位时，答案可能会非常大。 
5. 对于每个中点，评估条件。 如果可行，则向左移动； 否则向右移动。 我们正在寻找最小的可行天数。 
6.输出第一个$d$满足这两个约束条件。 

二分查找有效的原因是增加$d$只能增加好天数和可用时段总数，因此可行性单调。 

### 为什么它有效

 核心不变量是可行性仅取决于前缀长度而不取决于调度选择。 对于任何固定的$d$，我们总是有确切的$d$铺设沥青的机会，并且准确地$good(d)$其中都是优质机会。 由于我们可以选择将哪些单位分配给哪些天，因此唯一的限制是是否存在足够的好天数来满足所需的计数。 一旦前缀可行，任何更大的前缀仍然可行，因为总计数和良好计数都不会减少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def good_days(d, g, b):
    cycle = g + b
    full = d // cycle
    rem = d % cycle
    return full * g + min(g, rem)

def solve():
    T = int(input())
    for _ in range(T):
        n, g, b = map(int, input().split())
        need = (n + 1) // 2

        lo, hi = 1, 10**18
        ans = hi

        while lo <= hi:
            mid = (lo + hi) // 2
            if mid >= n and good_days(mid, g, b) >= need:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```功能`good_days`直接实现周期计数公式。 二分搜索同时强制执行两个约束：足够的总天数来完成道路和足够的好天数来满足质量要求。 

一个常见的陷阱是忘记`mid >= n`健康）状况。 如果没有它，搜索可能会返回一个具有足够好天数但没有足够的总天数来完成构建的前缀。

 ## 边缘情况

 当$g \ge n$，所有需要的好单位都可以放置在好日子的第一块内。 该算法处理这个问题是因为$good(n) = n$，使二分查找立即稳定在$d = n$。 

什么时候$g \ll b$，好日子极其稀少，大部分周期都被浪费了。 二分查找扩展$d$直到积累了足够的周期，并且算术公式正确地计算出部分周期而无需模拟。 

什么时候$n = 1$，要求很简单，并且第一天总是有效，因为序列从美好的一天开始，所以$good(1) = 1$。
