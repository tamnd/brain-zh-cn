 ## 解决方案
 ## 问题理解

 任务是计算慢速版本的欧几里得算法执行了多少次迭代。 该算法以两个正整数开始。 虽然这两个值不同，但它会重复从较大值中减去较小值并递增计数器。 答案是该计数器的最终值，而不是最大公约数本身。 

例如，从`15 10`，过程是`15 10 -> 5 10 -> 5 5`，所以答案是`2`。 挑战在于输入值可能非常大，因此不可能模拟每个减法。 

输入最多包含 500 对正整数，每个整数可以大到`10^18`。 直接模拟可能需要几乎`10^18`运营。 一对如`1 1000000000000000`会减去`1`从更大的数字近一万亿倍，这无法适应任何实际的时间限制。 该解决方案必须处理整组相同的减法步骤。 

棘手的情况来自于精确的停止条件和非常大的商。 如果两个数字已经相等，则不会发生减法。```
Input
7 7
```正确的输出是：```
0
```总是执行至少一次减法的粗心实现会产生不正确的结果。 

另一种边缘情况是一个数字除另一个数字时。```
Input
1 1000000000000000
```正确的输出是：```
999999999999999
```最后的减法很特殊，因为经过多次减法`1`，数字变得相等。 计数`1000000000000000`减法就太多了。 

第三种情况是第一次除法留下余数。```
Input
15 10
```正确的输出是：```
2
```第一个减法将该对更改为`5 10`，第二个将其更改为`5 5`。 将运算计数仅视为商`15 // 10`会错过后来的欧几里得步骤。 

## 方法

 最直接的方法是准确地实现给定的算法。 虽然这两个数字不同，但用较大的数字减去较小的数字并增加答案。 这是正确的，因为每次循环迭代都与原始过程中的一次减法相匹配。 

问题在于迭代次数。 如果值为`1`和`10^18`，循环执行`999999999999999`运营。 即使是单个这样的测试用例也太大了，并且可能有数百个测试用例。 

关键的观察是许多连续的循环迭代都做同样的事情。 当较大的数字远大于较小的数字时，算法会重复减去相同的值。 我们可以计算一组中发生了多少次减法，而不是单独执行这些减法。 

假设当前值为`a > b`。 写：```
a = q * b + r
```如果`r`不为零，慢算法减去`b`确切地`q`较大值变为之前的次数`r`。 状态从`(a, b)`到`(b, r)`。 

如果`r`为零，之后`q - 1`相减，值变得相等。 这`q`不执行 -th 减法，因为一旦达到相等，循环就会停止。 状态变成`(b, b)`并做出贡献`q - 1`运营。 

这与欧几里得算法背后的压缩思想相同，但我们不是只找到 gcd，而是跟踪较慢版本将执行的减法步骤数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O（答案）| O(1) | O(1) | 太慢了|
 | 最佳| O(log(最大(a, b))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取一对数字并将答案计数器初始化为零。 
2. 如果两个数字已经相等，则返回零，因为原始循环条件立即为 false。 
3. 当数字不同时，取较大的数字`a`和较小的数字`b`。 
4. 计算`a // b`和`a % b`。 商表示慢速算法会减去多少次`b`从`a`在价值跌破以下之前`b`或变得相等。 
5. 添加`a // b`当有余数时才给出答案。 如果没有余数，则比商减一，因为最后的减法将使数字相等并终止循环。 
6. 用下一个欧几里得状态替换该对`(b, a % b)`并继续直到两个值相等。 

这样做的原因是每个压缩步骤代表相同减法的连续序列。 唯一需要的调整是当较大数字是较小数字的精确倍数时，因为原始算法比正常除法过程更早停止一次减法。 

### 为什么它有效

 在每一点，慢速算法仅通过减去较小的数字来改变较大的数字。 将这些相同的操作分组在一起不会更改分组完成后的中间值。 

为了`a > b`, 商`a // b`正好是最大次数`b`可以在该值小于之前减去`b`或达到零。 如果有余数，所有这些减法都发生在下一对之前`(b, remainder)`出现。 如果没有余数，则最后一次减法将产生相等，因此将其排除。 重复此转换遵循与原始算法相同的状态，仅跳过每组内的单独操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_operations(a, b):
    ans = 0

    while a != b:
        if a < b:
            a, b = b, a

        q, r = divmod(a, b)

        if r == 0:
            ans += q - 1
            break
        else:
            ans += q
            a, b = b, r

    return ans

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        a, b = map(int, input().split())
        out.append(str(count_operations(a, b)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```功能`count_operations`保留当前的值对和压缩减法步骤的数量。 交换使`a`应用除法之前的较大值，匹配原始循环中的条件。 

这`divmod`call 立即计算商和余数。 这避免了手动计算它们并直接公开重复减法的次数。 

这`r == 0`分支处理两个数字相等的边界条件。 添加`q`这里会多计数一，因为原始循环不执行创建相等的减法。 

Python 整数可以存储大于`10^18`，因此不存在溢出风险。 该循环仅遵循欧几里德归约，因此迭代次数仍然很少。

 ## 边缘情况

 对于相等的值，例如：```
Input
7 7
```算法进入循环条件检查并立即返回零。 不计算商，因为原始过程中不存在减法。 

对于很大的倍数，例如：```
Input
1 1000000000000000
```该算法交换值，以便较大的值除以`1`。 商是`1000000000000000`余数为零。 它添加了`999999999999999`，匹配减法循环在到达之前运行的次数`(1, 1)`。 

对于有余数的一对：```
Input
15 10
```商是`1`剩下的就是`5`，因此计算一次操作，该对变为`(10, 5)`。 下一步检测与商的精确除法`2`，仅添加`1`，并结束于`(5, 5)`。 总计为`2`，与原来的减法过程完全一致。
