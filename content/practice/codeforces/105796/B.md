 ## 解决方案
 ## 问题理解

 该问题给出了一个非常大的正整数，以十进制字符串形式编写，可能长达一百万位。 任务是计算两个连续整数的平方之间的差：如果数字是$n$，我们必须输出$(n+1)^2 - n^2$。 

扩展此表达式消除了对直接对大数进行平方的任何依赖。 从代数上来说，它简化为$2n + 1$。 因此，整个任务简化为将一个大整数乘以二，然后加一。 

输入格式强化了这种简化的重要性。 该数字不是以机器整数类型给出，而是以原始数字形式给出，因为它可能大大超出标准 64 位限制。 由于溢出或输入解析限制，任何尝试将其解析为内置整数类型的解决方案都会立即失败。 

主要限制是数字的长度，最多$10^6$数字。 这意味着任何在位数上比线性更差的算法都将无法及时完成。 二次串操作（例如重复串联或带有重复移位的简单大整数模拟）会太慢。 

当数字完全由 9 组成时，就会出现微妙的边缘情况。 例如，如果输入是999，那么$2n + 1 = 1999$。 进位传播到每个数字，正确的解决方案必须能够将数字的长度扩展一位数。 假设固定长度输出或忽略最终进位的简单方法会产生不正确的结果，例如 0999 或 9999。 

另一个边缘情况是尽可能小的输入，单个数字，例如 0 或 1 位数字。 尽管公式很简单，但错误处理进位逻辑的实现在这些最小情况下通常会失败，因为它们假定至少有一个超出最低有效位置的内部数字。 

## 方法

 蛮力的想法是从字面上计算$n+1$，然后将两个数字平方，然后相减。 这需要大整数乘法两次，然后再进行减法。 即使有一个像样的大整数实现，将数字与$m$数字需要$O(m^2)$时间。 自从$m$可以达到$10^6$，这种方法变得不可行，因为它需要按顺序$10^{12}$最坏情况下的操作。 

关键的观察是我们根本没有真正被要求执行平方。 扩展代数完全消除了繁重的运算，并将一切简化为线性变换。 一旦我们认识到这一点$(n+1)^2 - n^2 = 2n + 1$，问题就变成了一个经典的大整数算术任务，只需乘以一个小常数和一个增量。 

这种结构使数字模拟变得自然。 乘以 2 可以从最低有效数字到最高有效数字进行进位，并且加 1 可以合并到同一遍中。 由于每个数字都会处理一次，并且每个数字只需要进行恒定的额外工作，因此该解决方案以数字位数的线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 直接大整数平方 |$O(m^2)$|$O(m)$| 太慢了|
 | 线性数字模拟$2n+1$|$O(m)$|$O(m)$| 已接受 |

 ## 算法演练

 最佳解决方案将数字视为字符串并从右到左处理它，完全模拟手工算术。 

1. 将数字作为字符串读取，这样就不会发生数字溢出。 字符串本身是整数的工作表示。 
2. 将进位值初始化为 0。该进位将从两位数和最后加 1 开始累加。 
3. 将字符串从最后一位数字遍历到第一位数字。 在每个位置，将字符数字转换为整数并计算$2 \cdot d + \text{carry}$。 结果给出了一个新的数字和一个新的进位。 

这样做的原因是乘以 2 分布在十进制表示上，但会产生超出单个数字的溢出，这正是进位捕获的内容。 
4. 将当前数字替换为$(2 \cdot d + \text{carry}) \bmod 10$，并将进位更新为$(2 \cdot d + \text{carry}) // 10$。 这使每个位置与以 10 为基数的算术局部一致。 
5. 完成所有数字后，如果还有进位，则将其附加到结果中。 这可以处理像全九这样数字长度增长的情况。 
6. 反转构造的数字，因为我们从最低有效数字向上处理。 

### 为什么它有效

 在遍历的每一步中，算法都保持不变，即当前位置右侧的所有数字都已正确转换为最终表示形式$2n + 1$。 进位准确地表示必须应用于下一个更有效数字的溢出贡献。 由于以 10 为基数的算术是位置算术并且进位不会向后传播，因此一旦数字确定，就无需重新访问。 这保证了单次向左传递产生正确的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input().strip())
    s = input().strip()

    carry = 0
    res = []

    for i in range(len(s) - 1, -1, -1):
        digit = ord(s[i]) - ord('0')
        val = digit * 2 + carry
        res.append(str(val % 10))
        carry = val // 10

    if carry:
        res.append(str(carry))

    print("".join(res[::-1]))

if __name__ == "__main__":
    solve()
```该实现反映了算法中描述的逐位结构。 唯一微妙的一点是输入长度`m`计算并不严格需要，因为实际的字符串长度已经定义了要处理的位数。 

反转遍历顺序以模拟从最低有效数字向上的进位传播。 结果被反向构建，并在最后通过单个反向操作进行校正，从而保持复杂性呈线性。 

一个常见的错误是尝试在加倍后单独加 1。 这也可行，但需要仔细处理第二个进位链。 将两个操作合并到一个通道中可以避免额外的复杂性。

 ## 边缘情况

 关键的边缘情况是每个数字都是 9。在这种情况下，每个位置都会生成一个进位，最后的进位会生成一个新的前导数字。 对于像 999 这样的输入，算法将每个数字处理为 9×2+进位，总是产生 19，并且进位直到最后才稳定。 最后附加的进位成为新的最高有效数字，这对于正确性至关重要。 

另一个边缘情况是单位数输入。 对于输入 9，计算结果为 18，算法必须正确输出两位数字，而不是覆盖单个位置。 进位机制自然会处理这个问题，前提是实现不会丢弃最终的进位。 

最后一个微妙的情况涉及输入中的零。 对于 0，结果应为 1。由于没有进位传播，算法会立即生成正确的数字，从而确认相同的逻辑无需特殊分支即可处理简并传播场景和最大传播场景。
