 ## 解决方案
 ## 问题理解

 We are given a string of digits representing a phone number. 任务是将这个字符串分成几部分，每部分的长度为 2 或 3。这些组必须按原始顺序出现，并且它们用`-`输出中的字符。 

该问题并不要求所有可能的分区。 接受任何有效的分组。 

限制很小。 电话号码长度最多为 100，因此即使效率相当低的解决方案也能在限制内轻松运行。 这改变了问题的性质。 挑战不是优化，而是构建始终有效的分组并正确处理小角落情况。 

The tricky part is that greedy choices can accidentally leave a single digit at the end. A group of length 1 is illegal, so the algorithm must avoid creating that situation.

 考虑输入：```
5
12345
```如果我们先贪婪地取 3 组，我们会得到：```
123-45
```这是有效的。 

但如果我们以不同的方式处理并首先以 2 人为一组：```
12-34
```我们只剩下`5`，无法形成有效的组。 

另一个微妙的情况是当剩余长度变为 4 时。例如：```
7
1234567
```如果我们立即采取 3 人一组：```
123-456
```我们只剩下`7`，这是无效的。 

正确的策略是：```
12-34-567
```或者```
123-45-67
```两者都有效，因为最终剩余长度总是可分解为 2 和 3。 

最小的有效输入也需要注意：```
2
98
```整个字符串本身已经是一个有效的组。 总是尝试先提取 3 位数字的粗心实现会立即失败。 

## 方法

 暴力解决方案会尝试一切可能的方法来分割字符串。 在每个位置，我们可以取 2 位数字或 3 位数字，然后递归求余数。 由于每个位置都有两个选择，因此可能性的总数呈指数级增长。 

对于 100 左右的长度，递归状态的数量变得巨大。 尽管许多分支很早就死亡，但对于这种结构化问题来说，天真的详尽搜索是不必要的工作。 

蛮力在概念上起作用的原因很简单。 每个有效分区只是长度 2 和 3 之间的一系列选择。如果我们探索所有序列，我们最终会找到一个有效的序列。 

关键的观察是我们不需要搜索。 每个长度至少为 2 的数字都可以仅使用 2 和 3 来表示，长度 1 除外。因此，真正的目标只是避免恰好留下一位数字未分组。 

这导致了直接的建设性战略。 当剩余的数字超过 4 位时，我们安全地以 2 为一组。为什么是 2？ 因为反复减去 2 可以保留以 2 或 3 为一组完成剩余后缀的能力。 

一旦剩余长度变成2、3、4，我们就停下来直接处理：

 如果还剩下 2 位数字，则取 2 位为一组。 

如果还剩下 3 位数字，则取 3 位为一组。 

如果还剩下 4 位数字，则将其分成两组，每组 2 位。 

这保证了没有组具有无效的大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 概念上太慢|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取电话号码字符串。 
2. 创建一个名为的空列表`groups`存储结果块。 
3.维护一个指向当前未读位置的索引。 
4. 当剩余位数大于 4 时，取出接下来的 2 位数字并将其附加到`groups`。 

重复取 2 位数字是安全的，因为它可以防止余数变成 1。 
5. 循环结束后，剩余长度必须为2、3或4。 
6. 如果还剩下 2 位数字，请将它们附加为最后一组。 
7. 如果还剩下 3 位数字，请将它们附加为最后一组。 
8. 如果还剩下 4 位数字，则将它们分成两组，每组 2 位，然后将它们都追加。 

分成4份`2 + 2`避免产生大小为 1 的禁止组。 
9. 打印所有加入的组`-`。 

### 为什么它有效

 该算法保持一个简单的不变量：每一步之后，剩余的位数仍然可以仅使用大小为 2 和 3 的组来表示。 

从大于 4 的任何有效剩余长度中减去 2 使余数保持有效。 该过程最终达到基本长度 2、3 或 4 之一，所有这些都具有直接有效的分解。 

唯一不可能的余数是 1，该算法专门设计用于避免产生它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

groups = []
i = 0

while n - i > 4:
    groups.append(s[i:i + 2])
    i += 2

remaining = n - i

if remaining == 2:
    groups.append(s[i:i + 2])
elif remaining == 3:
    groups.append(s[i:i + 3])
else:
    groups.append(s[i:i + 2])
    groups.append(s[i + 2:i + 4])

print("-".join(groups))
```解决方案直接遵循建设性策略。 

变量`i`跟踪已处理的数字数。 当剩余超过 4 位数字时，循环将继续，因为长度 2、3 和 4 已经可以安全完成，无需进一步决策。 

长度4的处理是最重要的边界条件。 一个常见的错误是先取 3 个一组，然后留下一个数字。 分裂成`2 + 2`完全避免了这个问题。 

该实现在原始字符串上使用切片，这对于这些小约束来说是干净且高效的。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    groups = []
    i = 0

    while n - i > 4:
        groups.append(s[i:i + 2])
        i += 2

    remaining = n - i

    if remaining == 2:
        groups.append(s[i:i + 2])
    elif remaining == 3:
        groups.append(s[i:i + 3])
    else:
        groups.append(s[i:i + 2])
        groups.append(s[i + 2:i + 4])

    print("-".join(groups))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue().strip()

 ## 边缘情况

 考虑输入：```
4
1111
```该算法立即跳过循环，因为只剩下 4 位数字。 它进入最终的情况并将字符串拆分为：```
11-11
```粗心的贪婪方法首先获取 3 位数字会产生：```
111-1
```这是无效的，因为禁止大小为 1 的组。 

现在考虑：```
7
1234567
```该算法处理：```
12
```留下5位数字。 然后它处理：```
34
```留下 3 位数字，可以安全地成为最后一组：```
567
```最终的答案是：```
12-34-567
```这显示了重复删除 2 位数字如何防止余数变为 1。 

最后，检查最小边界：```
2
98
```循环永远不会运行，因为剩余长度已经有效。 算法直接输出：```
98
```不需要特殊的技巧，因为基本情况自然会处理允许的最短输入。
