 ## 解决方案
 ## 问题理解

 彼得站在一排队伍中的某个地方，其中有`n`人们。 职位编号从`1`在前面到`n`在后面。 

关于他的职位，他知道两件事。 至少`a`人们站在他面前，最多`b`人们站在他身后。 我们必须计算有多少个不同的位置满足这两个条件。 

如果 Petr 站在这个位置`p`，那么正好`p - 1`人们就在他面前，而且正是`n - p`人们在他身后。 任务变成找出有多少个整数`p`满足两个不等式：

 -`p - 1 >= a`-`n - p <= b`限制很小，因为`n <= 100`。 即使对每个位置进行暴力循环也足够快。 不需要高级优化、数据结构或动态编程。 主要的挑战是将措辞转化为正确的不等式，而又不犯一点点的错误。 

最常见的错误是误解“不少于”这句话`a`前面的人”。这意味着`at least a`，不完全是`a`。 

考虑这个例子：```
5 2 1
```有效职位是`3`和`4`。 

位置`5`无效，因为有`0`Petr 背后的人，这是允许的，但是有`4`前面的人，这也是允许的。 实际上位置`5`也有效。 一个粗心的实现，准确地假设`a`前面的人会错误地只返回一个位置。 

另一个微妙的边缘情况出现时`b = 0`。 

例子：```
4 1 0
```彼得必须站在最后面，因为没有人可以站在他身后。 唯一有效的位置是`4`。 错误的解释例如`behind < b`而不是`behind <= b`会拒绝正确答案。 

在位置和计数之间进行转换时，还存在一个简单的差一陷阱。 

例子：```
3 0 2
```所有职位均有效。 位置`1`有`0`前面的人和`2`在后面。 位置`3`有`2`在前面和`0`在后面。 忘记位置编号从`1`经常打破这些边界情况。 

## 方法

 蛮力方法直接测试每个可能的位置`1`到`n`。 

对于每个位置`p`，我们计算：

 - 前面的人=`p - 1`- 后面的人=`n - p`如果两个条件都成立，我们就增加答案。 

这是可行的，因为约束非常小。 最坏的情况下我们会检查`100`位置，这实际上是瞬时的。 

有趣的是我们认识到我们可以在不迭代的情况下以数学方式得出答案。 

从：```
p - 1 >= a
```我们得到：```
p >= a + 1
```从：```
n - p <= b
```我们得到：```
p >= n - b
```因此 Petr 的位置必须同时满足两个下界：```
p >= max(a + 1, n - b)
```最大可能的位置总是`n`，因此每个有效位置位于：```
[max(a + 1, n - b), n]
```该区间内的整数个数为：```
n - max(a + 1, n - b) + 1
```这简化为众所周知的紧凑公式：```
min(n - a, b + 1)
```这两种方法在这里都是完全可以接受的。 该公式更清晰且时间恒定，而暴力法最初更容易推导。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整数`n`,`a`， 和`b`。 
2. Petr 必须至少有`a`他面前的人。 

自位置`p`有`p - 1`前面的人，最小的有效位置是`a + 1`。 
3. Petr 最多必须有`b`他身后的人。 

自位置`p`有`n - p`后面的人，我们解决：```
n - p <= b
```这给出：```
p >= n - b
```4. 这两个下界中较严格的一个决定了第一个有效位置：```
start = max(a + 1, n - b)
```5. 每个位置从`start`通过`n`是有效的。 

使用间隔长度对它们进行计数：```
answer = n - start + 1
```6. 打印答案。 

### 为什么它有效

 一个位置当且仅当它同时满足两个约束时才有效。 

第一个条件排除了距离前方太近的位置。 第二个也排除了距离前方太远的位置，因为太多的人会留在彼得后面。 

将这两个语句转换为不等式后`p`，每个有效位置形成一个连续区间，结束于`n`。 计算该区间内的整数可以准确地给出合法位置的数量，既不会丢失也不会添加任何情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, a, b = map(int, input().split())

start = max(a + 1, n - b)
answer = n - start + 1

print(answer)
```该程序直接遵循演练中的数学推导。 

表达式`a + 1`是第一个位置至少有`a`前面的人。 这是最容易犯差点错误的地方。 位置`a`只会有`a - 1`前面的人。 

表达式`n - b`来自重新安排Petr身后人的条件。 另一个常见的错误是写作`n - b + 1`，这会错误地改变间隔。 

最后，`n - start + 1`计算包含区间的大小。 这`+1`很重要，因为两个端点都算作有效位置。

 ## 边缘情况

 考虑输入：```
4 1 0
```该算法计算：```
a + 1 = 2
n - b = 4
start = 4
answer = 1
```唯一位置`4`之所以有效，是因为彼得不能有任何人支持他。 该算法正确处理包含条件`<= b`。 

现在考虑：```
5 0 4
```我们得到：```
a + 1 = 1
n - b = 1
start = 1
answer = 5
```每个位置都是有效的。 这证实了该公式可以正确处理全范围情况。 

最后，考虑：```
3 0 2
```计算变为：```
a + 1 = 1
n - b = 1
start = 1
answer = 3
```所有三个位置都被计算在内。 此案例验证了位置和前面人数之间的转换处理没有差一错误。
