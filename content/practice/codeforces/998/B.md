 ## 解决方案

 ## 问题理解

 给定一个整数序列，我们可以通过在相邻元素之间进行切割将其分成连续的段。 每个段必须满足结构约束：段内偶数值的数量必须等于奇数值的数量。 

每一次潜在的削减都有一个本地成本，该成本由它分开的两个数字的绝对差决定。 我们有一个预算，我们希望最大限度地提高执行的削减次数，同时将总成本保持在该预算范围内，并保持每个结果段的有效性条件。 

关键约束是序列总体上已经包含相同数量的偶数和奇数值，这保证了至少存在一个有效的全序列分段而没有切割。 

界限很小，n 最大为 100，预算最大为 100，这立即表明二次或三次动态规划是可以接受的。 任何尝试直接枚举所有分段的解决方案本质上都是指数级的，因为每个 n−1 间隙都可以被切割或不被切割，从而导致 2^(n−1) 种可能性。 在最坏的情况下，这会变成 10^30 左右，这远远超出了任何可行的计算。 

像“只要看起来便宜就削减”这样天真的贪婪策略会失败，因为廉价的早期削减可能会阻碍更好的全球安排。 例如，如果进行小额成本削减迫使您随后花费昂贵的成本削减来重新平衡细分市场，那么本地决策就会产生误导。 

当一个段在多个有效位置达到平衡时，就会出现另一种微妙的失败情况。 选择最早的可能削减可能会浪费稍后削减所需的预算，从而产生总体上更平衡的细分市场。 

真正的困难在于剪切不是独立的：决定一个片段的结束位置决定了所有未来片段的结构。 

## 方法

 暴力方法会考虑 n−1 个可能切割位置的每个子集。 对于每个子集，我们将检查每个结果片段是否具有相等的偶数和奇数计数，并计算所选切割的总成本。 这是正确的，因为它明确验证了所有可能性。 

然而，这需要迭代 2^(n−1) 个子集，并且对于每个子集，我们可以在 O(n) 中扫描段，从而给出指数级的总复杂度。 即使 n = 100，这也是完全不可行的。 

关键的观察是我们实际上不需要全局推理所有子集。 相反，我们可以从左到右处理数组，并跟踪我们在当前段中看到的偶数和奇数。 一旦某个细分市场变得平衡，我们就有了一个允许削减的候选位置。 

在每个这样的候选剪切位置，我们都面临一个选择：要么在这里剪切，要么跳过它。 切割会消耗成本，并将切割次数增加一，而跳过则使段保持开放状态，有可能合并未来的有效端点。 这正是一个经典的“预算内数量最大化”动态规划问题。 

我们通过位置和剩余预算定义 DP 状态，并尝试所有有效的切入点。 由于可以预先计算有效的切入点，因此转换变得易于管理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | DP 超过各州 | O(n^2·B) | O(n^2·B) | O(n·B) | O(n·B) | 已接受 |

 ## 算法演练

1. 预先计算所有允许切割的位置。 我们扫描数组，同时保持偶数和奇数元素数量之间的差异。 每当该差异变为零时，此处结尾的前缀就可以形成有效的段边界。 
2. 让这些有效的剪切位置按升序存储。 我们只考虑在这些位置处进行切割，因为任何有效的分段都必须在这样的平衡点处结束每个分段。 
3. 定义一个动态规划表 dp[i][b]，其中 i 表示到目前为止我们已经考虑了多少个有效的切割位置，b 表示剩余预算。 存储的值是可实现的最大切割次数。 
4. 对所有 b 初始化 dp[0][b] = 0，因为在任何剪切位置之前都不会进行剪切。 
5.对于每个有效的切割位置i，计算在那里切割的成本，即abs(a[pos] - a[pos+1])。 该成本是固定的并且独立于其他决策。 
6. 对于每个预算值，传播转换：要么我们不在 i 处进行切割并向前传送 dp[i−1][b]，或者如果 b 足够则进行切割，更新 dp[i][b] = max(dp[i][b], dp[i−1][b − cost] + 1)。 
7. 最终答案是 dp[last][b] 中所有 b ≤ B 中的最大值。 

### 为什么它有效

 关键的不变量是 dp[i][b] 表示仅使用前 i 个有效削减位置和最多支出 b 预算的可实现的最佳削减数量。 每个有效的分段都必须从该集合中选择剪切边界，因为只有这些位置才能保留平衡的分段。 由于每个状态转换要么包含或排除固定有效边界处的切割，所以我们枚举所有结构上有效的分段而没有冗余，并且预算通过 DP 维度精确执行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, B = map(int, input().split())
    a = list(map(int, input().split()))

    # find valid cut positions (prefix balanced in parity sense)
    valid = []
    diff = 0  # evens - odds

    for i in range(n - 1):
        if a[i] % 2 == 0:
            diff += 1
        else:
            diff -= 1

        if diff == 0:
            cost = abs(a[i] - a[i + 1])
            valid.append(cost)

    # dp[i][b]: using first i cuts, budget b
    m = len(valid)
    dp = [[0] * (B + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        cost = valid[i - 1]
        for b in range(B + 1):
            dp[i][b] = dp[i - 1][b]
            if b >= cost:
                dp[i][b] = max(dp[i][b], dp[i - 1][b - cost] + 1)

    print(max(dp[m]))

if __name__ == "__main__":
    solve()
```该实现首先将问题压缩为前缀平衡的候选剪切位置列表。 每个候选者只存储在那里切割的成本，因为该结构保证了位置之间的独立性。 

DP 表是根据这些候选者逐行构建的。 在每一步中，我们要么跳过，要么削减，尊重剩余预算。 所有预算的最终最大值反映了可实现的最佳削减数量。 

一个微妙的细节是我们只计算有效前缀边界的成本。 这避免了考虑会破坏奇偶校验要求的非法削减，从而确保 DP 状态空间是正确的。

 输入：```

```这里没有前缀具有相等的偶数和奇数计数，因此不存在有效的剪切位置。 DP 表始终保持为零，答案为 0。

 ## 边缘情况

 一个关键的边缘情况是序列在末尾之前从未形成平衡前缀。 在这种情况下，有效列表为空并且 DP 永远不会转换。 用于输入`1 3 5 7`，算法不会产生候选，因此 dp 保持为零并且输出正确为 0。 

另一种情况是存在许多平衡前缀但其成本超出预算。 尽管在结构上许多削减是可能的，但 DP 由于预算限制正确地拒绝了它们，确保不会发生无效的多计。
