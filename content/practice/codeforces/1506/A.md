 ## 解决方案
 ## 问题理解

 我们有一个矩形网格$n$行和$m$列。 每个单元格包含一个唯一的编号$1$到$n \cdot m$，但编号以两种不同的方式定义。 

首先，想象一下逐列填充网格。 我们从最左边的列开始，从上到下填充它，然后移动到下一列，然后重复。 这会产生一个固定的编号方案，其中值在列内向下增加，然后跳到下一列的顶部。 

其次，我们考虑一种不同的、更自然的编号：逐行。 我们从左上角的单元格开始，从左到右填充每一行，然后逐行向下移动。 

对于每个查询，我们给出$n$,$m$，和一个值$x$对应于按列编号的单元格标签。 任务是确定同一单元格在按行编号时将具有什么数字。 

约束允许最多$10^4$测试用例，与$n, m$最多$10^6$， 和$x$最多$10^{12}$在某些情况下。 这立即排除了任何网格模拟。 由于内存和时间的限制，即使构建单个网格也是不可能的。 解决方案必须是$O(1)$每个测试用例。 

索引产生了一个微妙的问题。 由于两种编号方案都是基于 1 且结构不同，因此行和列计算中的差一错误是最常见的故障点。 另一个潜在的陷阱是整数溢出，如果中间产品像$n \cdot m$是用 32 位算术计算的，尽管 Python 自然地避免了这种情况。 

一种幼稚的方法可能会尝试重建网格并重新索引它。 例如，对于$n=3, m=5$，我们将按列顺序填充整个表，存储它，然后重建行顺序。 对于较大的约束，这已经失败了，但即使手动推理也表明这是不必要的。 

## 方法

 蛮力的想法很简单：将按列编号模拟到二维数组中，然后分别分配按行编号，最后将值映射回来。 每个单元被访问两次，因此复杂度为$O(nm)$每个测试用例。 高达$10^4$测试用例和$nm$潜在地$10^{12}$，这是完全不可行的。 

关键的观察是，两个编号系统只是同一矩阵的不同线性化。 按列编号的结构为我们提供了一种直接解码数字的方法$x$进入其行和列位置。 一旦我们知道了坐标，转换为按行编号就很简单了。 

在按列编号时，每列恰好包含$n$元素。 这意味着列索引$x$由前面有多少完整列决定。 具体来说，$(x-1) // n$给出列索引，并且$(x-1) \% n$给出行索引。 

一旦我们有了位置$(r, c)$，转换为按行编号只是将其放置在一个序列中，其中行是大小连续的块$m$。 所以最终的值为$r \cdot m + c + 1$。 

该转换将问题从网格重建简化为简单的算术索引。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm)$每次测试 |$O(nm)$| 太慢了|
 | 最佳 |$O(1)$每次测试 |$O(1)$| 已接受 |

 ## 算法演练

 1. 解读价值$x$作为网格的列优先线性化中的位置$n$行。 这意味着每个大小的块$n$对应于单个列。 
2. 计算列索引为$(x - 1) // n$。 这是有效的，因为每一列都准确贡献$n$移动到下一个元素之前。 
3. 将行索引计算为$(x - 1) \% n$。 这标识了列内从上到下的位置。 
4. 现在重新解释同样的内容$(row, column)$按行优先顺序排列的位置。 在按行编号时，每一行都准确贡献$m$移动到下一行之前的元素。 
5. 使用以下命令将坐标转换回线性值$row \cdot m + column + 1$。 这会生成同一单元格的按行标签。 

### 为什么它有效

 该算法依赖于两个编号系统都是同一网格上的双射这一事实。 按列编号定义映射$f(r, c) = c \cdot n + r + 1$，而按行编号定义$g(r, c) = r \cdot m + c + 1$。 由于两者代表相同的坐标系，解码$x$通过$f^{-1}$并通过重新编码$g$保留正确性。 不存在冲突或歧义，因为每个整数恰好对应于一个网格位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, x = map(int, input().split())

        x -= 1
        col = x // n
        row = x % n

        ans = row * m + col + 1
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案在恒定时间内独立处理每个测试用例。 关键步骤是首先将给定索引转换为基于 0 的坐标，这可以避免除法和模运算期间的差一复杂性。 计算完行和列后，我们直接重新应用行优先索引。 

一个常见的错误是忘记在分割为坐标之前减去 1，这会错误地移动所有结果。 另一个正在交换$n$和$m$在除法步骤中，这完全打破了列解释。

 ## 边缘情况

 一个重要的边缘情况是当$x = 1$。 这里从 0 开始的值是 0，所以行和列都是 0，正确的答案会变成 1。对从 1 开始的索引的任何错误处理都会将其转换为 0 或无效索引。 

另一种情况是当$x = n \cdot m$，网格中的最后一个单元格。 减一后，我们得到$x-1 = nm - 1$，产生列$m-1$和行$n-1$。 代入公式可得$(n-1)m + (m-1) + 1 = nm$，正确保留最后一个标签。 

出现微妙的失败情况时$n = 1$。 网格变成单行，并且列向和行向编号相同。 该公式简化为$col = x$,$row = 0$，生产$x$，符合预期。
