 ## 解决方案
 ## 问题理解

 我们得到一串小写字母。 我们可以重复删除字符，但有一个限制：只有当该字符仍然出现在字符串中的其他位置时，我们才能删除该字符。 我们继续删除，直到结果字符串不包含重复字符，这意味着每个剩余的字母都恰好出现一次。 

关键的自由在于删除不是强制的，也不是按照固定的顺序连续进行的。 我们选择删除的位置和顺序。 不同的选择会导致不同的最终“不同字符”字符串。 在所有有效的最终字符串中，我们想要字典顺序最大的一个。 

所以任务不仅仅是删除字符串的重复项。 它是决定删除哪些出现的重复字符，以便最终的唯一字符串按字典顺序尽可能大。 

这些限制非常重要。 所有测试用例的总长度最多为 200,000。 这排除了任何试图通过重复扫描字符串并在慢速循环中更新频率来简单地模拟删除的解决方案，因为在最坏的情况下这可能会退化为二次行为。 

一个天真的想法是反复尝试贪婪地删除字符，同时维护多个计数集。 这已经遇到了麻烦，因为每次删除都会改变结构，并且从头开始重新计算“最佳选择”可能会很昂贵。 

当字母在重叠范围内重复时，会出现微妙的边缘情况。 

例如，考虑：```
abacaba
```如果我们贪婪地删除早期出现的小字符，我们最终可能会保留一个按字典顺序排列的比必要的更小的前缀。 正确答案是：```
cba
```简单地保留最后出现的字母或删除最左边的重复项而不进行全局规划的粗心策略将会失败，因为最佳答案取决于平衡“尽早保留大字母”与“稍后保留较大字母的可用性”。 

当字符串已经具有所有唯一字符时，会出现另一种失败情况。 那么不允许删除，答案就是字符串本身。 任何假设至少删除一次的算法都必须小心，不要意外删除唯一字符。 

## 方法

 暴力破解的观点是将这个过程视为对字符串的状态搜索。 从任何当前字符串中，我们可以尝试删除任何字符出现多次的索引，然后递归直到所有字符都是唯一的。 这将探索所有有效的删除序列。 

国家的数量是巨大的。 即使每个字符被删除一次，我们本质上也是选择出现的一个子集来保持约束，这会导致组合爆炸。 在最坏的情况下，比如长度为 n 的所有相同字符的字符串，每次删除都是允许的，直到剩下一个，并且如果天真地探索分支选择仍然会导致指数行为。 

关键的观察结果是，最终字符串始终由原始字符串中每个不同字符恰好出现一次组成。 唯一真正的决定是保留每个字符的哪个出现，但这些选择受到字典顺序和未来可用性的限制。 

我们从左到右处理字符串，但我们不会立即决定是否保留某个字符。 相反，我们保持最佳的后缀选择：在任何时候，如果我们可以安全地删除某个字符的早期出现，同时确保它仍然稍后出现，我们应该延迟它的包含，以获得更大的词典结果。 

这成为一个经典的贪婪问题：我们使用单调堆栈思想与最后出现约束相结合来构造答案。 我们总是尝试让字符按照“期望值”递增的顺序排列，但是如果较早的字符稍后再次出现，我们可以丢弃它们。 

最终结构简化为构建字典顺序最大的子序列，该子序列恰好包含每个不同字符的一次出现。

 ## 算法演练

 我们通过贪婪地构建尽可能最好的子序列同时确保唯一性来解决这个问题。 

1. 计算字符串中每个字符最后一次出现的索引。 这告诉我们现在丢弃一个角色并在需要时仍然选择它是否安全。 如果我们在位置 i，并且 s[i] 最后一次出现是 j，那么我们知道在 i 之后我们还有另一次机会获取 s[i]。 
2. 维护一个堆栈（或列表）来表示当前正在构建的答案。 
3. 维护一个布尔数组“used”，标记字符是否已包含在堆栈中。 这强制执行最终的唯一性约束。 
4. 从左到右迭代字符串。 对于位置 i 处的每个字符 c：

 - 如果 c 已被使用，则完全跳过它。 
- 否则，尝试决定是否现在应该插入它，或者我们是否应该从堆栈末尾删除一些较小的字符。 
5. 当堆栈非空，并且堆栈中的最后一个字符小于c，并且最后一个字符仍然较晚出现（其最后出现索引大于i）时，我们可以安全地弹出它。 这是因为我们保证有另一个机会稍后放置它，并且现在替换它可以改善字典顺序。 
6. 在所有有效删除之后，将 c 添加到堆栈并将其标记为已使用。 
7. 继续直到字符串末尾。 堆栈就是最终的答案。 

### 为什么它有效

不变的是，在每个步骤中，堆栈表示从已处理的前缀形成的字典顺序上最大的可能序列，前提是堆栈中的每个字符仍然有一个可行的方式使用后面的位置来完成。 每当我们删除一个角色时，我们只有在它稍后再次出现时才会这样做，以确保保留可行性。 每当我们保留一个字符时，都是因为删除它会违反可行性或无法改善词典顺序。 这保证了局部次优选择不会阻碍全局最优配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    last = {c: i for i, c in enumerate(s)}
    used = [False] * 26
    stack = []

    for i, c in enumerate(s):
        idx = ord(c) - 97

        if used[idx]:
            continue

        while stack:
            top = stack[-1]
            if top < c and last[top] > i:
                used[ord(top) - 97] = False
                stack.pop()
            else:
                break

        stack.append(c)
        used[idx] = True

    print("".join(stack))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该解决方案依赖于计算最后出现的次数，因此我们永远不会永久丢弃某个字符，除非我们知道它稍后会再次出现。 堆栈强制执行子序列结构，并且使用的数组确保每个字符在最终输出中仅出现一次。 

最微妙的部分是弹出循环中的条件。 仅当最上面的字符严格小于当前字符且仍稍后出现时，我们才会删除该字符。 如果任一条件失败，我们会立即停止，因为删除它会违反唯一性或失去可行性。

 ## 边缘情况

 对于像这样的单字符字符串`a`，算法立即产生`a`因为没有触发删除或弹出。 使用的数组可以防止重复，但在这里无关紧要，因为只出现一次。 

对于具有所有相同字符的字符串，例如`aaaaa`，由于使用了数组，第一个字符之后的每个字符都会被跳过。 由于每个字符没有严格更大的字典替换机会，因此堆栈永远不会增长到超过一个元素。 

对于已经唯一的字符串，例如`abc`，在插入之前没有任何字符被标记为已使用，并且不会发生弹出，因为最后一次出现并不重要。 结果保持不变。 

对于递减的字符串，例如`dcbaabcd`，该算法首先构建一个递减堆栈，然后仅当稍后出现严格更大的字符时才允许替换。 由于可行性受到最后出现位置的限制，因此只有安全的弹出才会发生，最终结果反映了在不违反唯一性的情况下最好的词典排列。
