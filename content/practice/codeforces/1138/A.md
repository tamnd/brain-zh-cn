 ## 解决方案
 ## 问题理解

 我们有一排寿司片，每片都是其中一种类型`1`或输入`2`。 我们想要选择这一行的一个连续段。 

如果一个段由两个不同寿司类型的连续块组成，并且两个块具有相同的大小，则该段是有效的。 例如，`[2,2,2,1,1,1]`有效，因为它是三`2`s 后面跟着三个`1`s。 像这样的一段`[2,2,1,1]`也是有效的。 像这样的一段`[1,2,1,2]`无效，因为每一半都包含两种类型。 

任务是找到这样一个有效的连续段的最大可能长度。 

数组长度可以大到`100000`，这立即排除了检查所有子数组的昂贵方法。 大致有`n²`可能的子数组，大约是`10^10`在最坏的情况下进行检查。 甚至一个`O(n²)`算法太慢了。 我们需要一个能够以线性时间或接近线性时间处理数组的解决方案。 

棘手的部分是所选段不必使用相等值的整个运行。 它可能仅使用运行的一部分。 

考虑：```
1 1 1 1 2 2
```跑步有长度`4`和`2`。 最佳有效段是：```
1 1 2 2
```与长度`4`。 只考虑完整运行的粗心实现将错误地返回`6`。 

另一个微妙的情况是：```
1 2 1 2
```每次跑步都有长度`1`。 

正确答案是`2`，因为最好的片段是`[1,2]`或者`[2,1]`。 不再有有效的段。 尝试合并多个交替运行的实现会产生不正确的结果。 

另一种边缘情况是：```
1 1 1 2
```游程长度是`3`和`1`。 

答案是`2`， 使用`[1,2]`。 更大的运行并不强迫我们使用它的所有元素。 我们只需要两次相邻运行的相等计数。 

## 方法

 强力解决方案将枚举每个可能的子数组，并检查它是否恰好由大小相等的不同寿司类型的两个连续块组成。 检查单个子数组可能需要线性时间，从而给出最坏情况的复杂性`O(n³)`。 即使进行了优化，也要检查所有`O(n²)`子数组是不可能的`n = 100000`。 

关键的观察结果来自于将数组视为相等值的游程。 

例如：```
2 2 2 1 1 2 2
```变成：```
[3, 2, 2]
```其中每个数字代表连续块的长度。 

任何有效答案都必须由相邻的两次运行形成。 如果两个相邻的游程有长度`a`和`b`，我们可以取：```
min(a, b)
```来自每一面的元素。 

这将创建一个有效的长度段：```
2 * min(a, b)
```例如，运行`(3,2)`产生一段长度`4`，运行时`(5,7)`产生一段长度`10`。 

由于每个有效段必须恰好位于两个相邻运行之间的一个边界上，因此问题简化为查找以下最大值：```
2 * min(run[i], run[i+1])
```在所有相邻的运行对上。 

构建游程长度需要遍历数组一次，检查相邻游程则需要另一次遍历。 这给出了线性解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n2) 到 O(n3) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从左到右扫描寿司数组并将其压缩为游程长度。 

例如：```
2 2 2 1 1 2 2
```变成：```
[3, 2, 2]
```每个数字记录了最大一块相同寿司的大小。 
2. 迭代每对相邻的运行。 

如果长度是`a`和`b`，跨越其边界的最大有效段使用`min(a,b)`每次运行的碎片。 
3. 计算`2 * min(a,b)`对于每一个相邻的对。 

这是可以围绕该边界形成的最大有效段。 
4. 保留看到的最大值。 
5.输出最大值。 

### 为什么它有效

 每个有效段恰好包含两组连续的寿司，每种类型各一组。 这样的一段必须跨越压缩表示中两个相邻游程之间的一个边界。 

假设相邻的游程长度是`a`和`b`。 为了保持两种寿司数量相等，我们最多可以使用`min(a,b)`每一侧的碎片。 使用更多将超出较小运行的大小并打破相等条件。 

因此与该边界相关的最佳线段具有长度`2 * min(a,b)`。 由于每个有效段都对应于某个相邻的运行对，因此在所有相邻运行中取最大值会检查每个可能的答案并返回最佳值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))

    runs = []
    cnt = 1

    for i in range(1, n):
        if t[i] == t[i - 1]:
            cnt += 1
        else:
            runs.append(cnt)
            cnt = 1

    runs.append(cnt)

    ans = 0
    for i in range(len(runs) - 1):
        ans = max(ans, 2 * min(runs[i], runs[i + 1]))

    print(ans)

solve()
```代码的第一部分构造寿司序列的游程编码。 变量`cnt`跟踪当前块大小。 每当寿司类型发生变化时，就会存储已完成的运行并开始新的运行。 

扫描完成后，还必须附加最终运行。 忘记此步骤是一个常见的错误，因为最后一次运行之后永远不会发生更改。 

第二个循环检查每对相邻的运行。 对于每一对，表达式`2 * min(runs[i], runs[i + 1])`给出跨越该边界的最大有效线段.

 答案就是这些值中的最大值。 

不需要对原始数组的边界进行特殊处理，因为每个有效段都由一对相邻的游程表示。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 一次构建运行，一次检查相邻运行 |
 | 空间| O(n) | 在最坏的情况下，每个元素都会开始新的运行 |

 该解决方案仅对每个数组元素执行恒定量的工作。 和`n ≤ 100000`，线性时间很容易满足时间限制，并且游程数组最多需要`100000`整数，完全在内存限制之内。

def run(inp: str) -> str:

            cnt = 1

    runs.append(cnt)

    return str(ans) + "\n"

 ## 边缘情况

 考虑：```
4
1 1 1 2
```游程长度为：```
[3, 1]
```该算法计算：```
2 * min(3, 1) = 2
```并返回`2`。 这对应于有效段`[1,2]`。 较大的运行不能贡献超过一种元素，因为较小的运行仅包含一种寿司。 

现在考虑：```
4
1 2 1 2
```游程长度为：```
[1, 1, 1, 1]
```候选值为：```
2, 2, 2
```答案是`2`。 该算法正确地避免了组合两次以上的连续运行。 

最后，考虑：```
8
1 1 1 1 2 2 2 2
```游程长度为：```
[4, 4]
```答案是：```
2 * min(4, 4) = 8
```整个数组有效，算法返回完整长度。
