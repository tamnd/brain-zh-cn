 ## 解决方案
 ## 问题理解

 我们从一个正整数数组开始。 唯一允许的操作是选择一个元素并将其分成两个正数部分，其总和等于原始值。 每次分割都会使数组长度增加一。 

目标是使最终数组不减，同时使用尽可能少的拆分操作。 

思考该操作的一个有用方法是，在重复分割一个值之后`a`，我们最终将其替换为几个正整数，其总和仍然为`a`。 如果一个值被分割成`k`件，正是需要的`k - 1`运营。 

输入最多包含`10^4`测试用例，所有测试用例的数组元素总数最多为`2 · 10^5`。 任何解决方案明显慢于线性或线性算术`n`将无法舒适地适应限制。 二次解大约需要`4 · 10^10`最坏情况下的操作，远远超出一秒所能执行的范围。 

棘手的部分是分割一个元素会影响所有涉及该元素的未来比较。 我们没有显式构造最终数组，因为它的大小可能会变得非常大。 相反，我们需要推断每个值必须分解为多少部分。 

一个容易犯的错误是贪婪地分割而不考虑右边的元素。 

考虑：```
3
3 2 1
```答案是`3`。 

如果我们只尝试修复局部反转，我们可能会分裂`3`一旦进入`1 + 2`, 生产`[1,2,2,1]`，这仍然不是非减的。 分割的效果必须根据其右侧所有内容所允许的最大值来判断。 

另一个微妙的情况是当值已经足够小时。```
2
4 5
```答案是`0`。 

粗心的实现可能仍然会计算正数的片段并添加不必要的操作。 只要当前值最多是允许的限制，我们就应该保持不变。 

当该值不能被所选的件数整除时，就会出现第三种边缘情况。```
2
10 3
```答案是`3`。 

分裂`10`分成三块，给出尺寸`3.33`，所以一件会变成`4`，仍然大于`3`。 我们实际上需要四块：`3,3,2,2`。 由于四块需要三次操作，所以答案是`3`。 此处使用楼层划分而不是天花板划分会产生错误的结果。 

## 方法

 强力的观点是显式地执行分割，直到数组变得非递减。 对于每个违规元素，我们可以尝试不同的方式对其进行分区并递归地继续。 这是正确的，因为可以探索每个有效的操作序列。 

问题在于可能的分区数量呈爆炸式增长。 即使是单个值，例如`100`可以用多种不同的方式分割，并且每一个新的部分都可以再次分割。 在达到输入限制之前，搜索空间就会变得巨大。 

关键的观察是，各个部分的确切排列大多是无关紧要的。 重要的是分裂后产生的最大的一块。 

假设我们从右到左处理数组。 想象一下，右边的所有内容都已经处理完毕，并且我们可以在该后缀之前放置的最大值是`mx`。 

如果当前值`a[i]`最多已经是`mx`，我们保持不变。 

否则，我们必须将其分成几部分，以便每个结果部分最多`mx`。 由于我们想要最少的操作数，因此我们想要尽可能少的块数。 

如果我们分裂成`k`块，最大的块至少是`ceil(a[i] / k)`。 最多做好每一件`mx`，我们需要：$$\left\lceil \frac{a[i]}{k} \right\rceil \le mx$$最小有效值`k`是：$$k = \left\lceil \frac{a[i]}{mx} \right\rceil$$使用更少的部件会迫使某些部件超过`mx`。 

一旦我们选择了这个最小值`k`，操作次数增加`k - 1`。 

还有一个细节。 分割后，什么值应该成为进一步左边元素的新限制？ 

其中`k`块，最小的可能块是：$$\left\lfloor \frac{a[i]}{k} \right\rfloor$$左侧不得超过该块的第一块，因此该最小块成为新的允许最大值。 

这将问题转化为简单的从右到左贪婪扫描。

 ## 算法演练

 1. 初始化答案`0`。 
2. 设置`mx`到数组的最后一个元素。 这是前一个元素最终可能产生的最大值。 
3. 从索引开始，从右向左处理数组`n - 2`。 
4. 如果`a[i] <= mx`，无需拆分。 更新`mx = a[i]`。 

The current value itself becomes the new restriction for everything further left.
 5. Otherwise, compute the minimum number of pieces needed so that every piece is at most`mx`:$$k = \left\lceil \frac{a[i]}{mx} \right\rceil$$6. 分裂成`k`件需要`k - 1`运营。 将其添加到答案中。 
7. 最佳平衡划分中可获得的最小块为：$$\left\lfloor \frac{a[i]}{k} \right\rfloor$$放：$$mx = \left\lfloor \frac{a[i]}{k} \right\rfloor$$这成为剩余元素的新限制。 
8.处理完所有元素后，输出累计答案。 

### 为什么它有效

 在每个位置，右侧的后缀已经施加了最大允许值`mx`。 任何有效的最终安排必须分开`a[i]`足够的时间，以便生产的产品不会超过此限制。 

满足该条件的最小件数恰好是`ceil(a[i] / mx)`。 任何较少数量的碎片都会留下至少一个大于`mx`，使得数组无法按非降序排列。 

在划分为最少数量的块的所有分区中，尽可能均匀地平衡各个块可以最大化最小的块。 最小的一块等于`floor(a[i] / k)`，这是我们可以安全地向左通过的最大限制。 保持这个限制尽可能大只能帮助未来的元素需要更少的分割。 

因为每个位置都是用最优局部选择来处理的，并且该选择为剩余前缀留下了最宽松的状态，所以贪婪策略是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    mx = a[-1]

    for i in range(n - 2, -1, -1):
        if a[i] <= mx:
            mx = a[i]
        else:
            k = (a[i] + mx - 1) // mx
            ans += k - 1
            mx = a[i] // k

    print(ans)
```变量`mx`表示当前位置在不破坏已经处理的后缀的情况下可能产生的最大值。 

什么时候`a[i] <= mx`，我们保持该值不变。 由于该值现在是已处理后缀的第一个元素，因此它成为新的限制。 

什么时候`a[i] > mx`，我们使用上限除法计算最小件数：```
k = (a[i] + mx - 1) // mx
```该表达式是以下表达式的整数实现`ceil(a[i] / mx)`。 

添加的操作数为`k - 1`因为将一个值分成`k`碎片需要那么多的分割。 

最后，```
mx = a[i] // k
```计算`floor(a[i] / k)`，这是最佳平衡分区中最小的部分。 使用这个值至关重要。 使用最大的块或平均值会打破贪婪不变量。 

Python 整数很容易处理这个问题，因为最坏情况下的运算次数可能会超过`32-bit`限制。

### 示例 2

 输入：```
3
3 2 1
```| 我| 一个[我] | 之前 | mx k | 添加操作 | MX 之后 | 总计 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 1 | 2 | 1 | 1 | 1 |

最右边的`1`强制每个生成的块最多`1`。 价值`2`必须变成两个，并且值`3`必须变成三个。 操作总数为`1 + 2 = 3`。 

此示例说明约束向左传播。 一旦极限变成`1`，每个早期的值最终都必须被分解。

 ## 边缘情况

 ### 小限制之前的大值

 输入：```
1
2
10 3
```开始于`mx = 3`。 

为了`10`，我们计算：$$k=\left\lceil\frac{10}{3}\right\rceil=4$$需要三个操作。 新的限制变为：$$\left\lfloor\frac{10}{4}\right\rfloor=2$$算法输出`3`。 

解决方案使用`10 // 3 = 3`件会错误地认为三件就足够了，但一件必然有尺寸`4`。 

### 已经是非递减数组

 输入：```
1
4
1 2 3 4
```扫描过程如下：```
mx = 4
3 <= 4
2 <= 3
1 <= 2
```不执行任何拆分，答案仍然存在`0`。 

这验证了贪心算法没有引入不必要的操作。 

### 极限变成一

 输入：```
1
3
3 2 1
```最右边的元素修复`mx = 1`。 

为了`2`，我们需要`k = 2`，添加一项操作。 

为了`3`，我们需要`k = 3`，再添加两个操作。 

最终的答案是`3`。 

这个案例说明了为什么从右到左的处理是自然的。 一旦允许的最大值变为`1`，每个较早的值都必须完全分解为 1，并且算法会立即捕获该值。
