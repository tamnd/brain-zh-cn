 ## 解决方案
 ## 问题理解

 每个测试用例都描述一组正方形图片。 每张图片都有边长$s_i$放置在更大的方形纸板上。 纸板形成宽度均匀的框架$w$在图片周围，并且还覆盖图片本身后面的区域。 这意味着一张图片所用纸板的总边长是$s_i + 2w$，其面积为$(s_i + 2w)^2$。 

在所有图片中，纸板总面积是这些单独正方形的总和，该总和为$c$。 任务是恢复未知整数$w$，知道$w \ge 1$并且保证有效的解决方案。 

约束将解决方案推向$O(n)$或者$O(n \log n)$每个测试用例。 高达$2 \cdot 10^5$总图片，任何尝试迭代所有可能的方法$w$为每个候选者重复计算值或重新计算昂贵的表达式将会失败。 关键的难点在于$c$可以大到$10^{18}$，因此中间计算必须安全地使用 64 位算术。 

一个微妙的边缘情况来自于公式的二次增长。 一种简单的方法可能会假设线性$w$，但展开式会产生依赖于两者的交叉项$s_i$和$w$，忽略它们会导致错误的聚合。 

例如，如果有人错误地将每个区域建模为$s_i^2 + 2ws_i$，他们想念$4w^2$每张图片的术语。 输入时$n=1, s_1=3, w=2$，正确的面积是$7^2 = 49$，但线性化公式会给出$9 + 12 = 21$，这显然是错误的。 

当尝试进行二分搜索而不注意单调性时，会出现另一种失败情况。 由于总面积严格按照$w$增加，函数是单调的，但不正确的实现通常会低效地重新计算总和，从而导致 TLE。 

## 方法

 蛮力的想法很简单：尝试每一个可能的值$w$，计算纸板总面积，并检查它是否等于$c$。 对于每位候选人$w$，我们求和$(s_i + 2w)^2$全面的$i$。 自从$w$可以很大，我们必须先绑定它。 

最大合理$w$来自所有情况$s_i$很小并且$c$很大。 因为每个术语都像$4w^2$，我们估计$w$最多约$10^9$。 尝试达到此范围的所有值是不可能的，并且每次检查都会花费$O(n)$，给出总复杂度$O(n \cdot 10^9)$，这远远超出了限制。 

关键的观察结果是总面积是单调函数$w$。 如果我们扩展表达式：$$\sum (s_i + 2w)^2 = \sum s_i^2 + 4w \sum s_i + 4nw^2$$这是一个二次函数$w$。 我们可以计算一次常数，然后求解$w$通过二分查找，因为该函数严格递增$w \ge 1$。 每次评价都变成$O(1)$，将问题简化为大整数范围内的对数搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nW)$|$O(1)$| 太慢了 |
 | 最优（二分查找）|$O(n \log C)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 根据输入数组计算两个聚合：所有聚合的总和$s_i$，以及所有的总和$s_i^2$。 这些使我们能够评估任何区域的总面积$w$无需迭代所有元素。 
2. 定义函数$F(w)$使用扩展公式返回纸板总面积：$$F(w) = \sum s_i^2 + 4w \sum s_i + 4nw^2$$该函数在恒定时间内评估完整配置。 
3. 设置二分查找范围$w$。 下限为 1。上限可以安全地设置为一个较大的值，例如$10^9$， 自从$c$至多是$10^{18}$并且函数呈二次方增长。 
4. 执行二分查找$w$。 对于每个中点$mid$, 计算$F(mid)$。 如果$F(mid) < c$，真实的$w$必须更大，因此将左边界向上移动。 否则，将右边界向下移动。 
5. 继续直到边界收敛。 最终的值是最小的$w$这样$F(w) \ge c$。 因为问题保证了有效的解决方案，所以这将等于正确的解决方案$w$。 

### 为什么它有效

 功能$F(w)$是具有正主系数的二次多项式$4n$，所以对于所有人来说都是严格递增的$w \ge 0$。 这保证了二分搜索永远不会跳过正确的解决方案，并且搜索空间被正确地划分为太小的值和足够大的值。 解决方案的唯一性源于严格的单调性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        s = list(map(int, input().split()))

        sum_s = 0
        sum_sq = 0
        for x in s:
            sum_s += x
            sum_sq += x * x

        def F(w):
            return sum_sq + 4 * w * sum_s + 4 * n * w * w

        lo, hi = 1, 10**9

        while lo < hi:
            mid = (lo + hi) // 2
            if F(mid) < c:
                lo = mid + 1
            else:
                hi = mid

        print(lo)

solve()
```该实现将预处理与评估分开，以便每个二分搜索步骤都是恒定时间。 Python 中隐含使用 64 位整数，但在较低级语言中，主要风险是溢出$w^2$期限和累计金额。 

二分查找条件使用$F(mid) < c$，这确保我们仅在当前配置非常小时才向右移动。 即使多个中间值理论上可能超调，这也能保持正确性。

 ## 边缘情况

 一个关键的边缘情况是当所有$s_i$是相同的。 在这种情况下，该功能变得特别流畅，并且天真地尝试“猜测”$w$从单张图片中得出的结果会失败，因为它忽略了聚合效应。 该算法可以正确处理此问题，因为它从不依赖于预处理后的单个元素。 

另一个边缘情况是当$n=1$。 该方程简化为一个二次方程$(s_1 + 2w)^2 = c$，这可能会引发直接平方根解。 二分搜索仍然可以干净地处理这个问题，无需特殊的大小写。 

大值$c$靠近$10^{18}$强调整数运算。 平方项$4nw^2$可以很快超过 32 位限制，但 Python 的任意精度避免了溢出，而在 C++ 中这正是`long long`成为强制性的。 

单调结构确保即使当$w$非常大，搜索收敛，无需显式计算根或处理浮点精度问题。
