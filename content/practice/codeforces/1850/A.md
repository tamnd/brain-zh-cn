 ## 解决方案
 ## 问题理解

 我们被要求使用三位数字，称呼他们`a`,`b`， 和`c`，每个范围从 0 到 9。任务是确定我们是否可以在这三个数字中选取任意两个不同的数字，以便它们的总和至少为 10。我们重复此操作`t`独立的测试用例。 如果存在这样的对，则输出应该是简单的“YES”；如果三个可能的对中没有一个的总和达到 10，则输出应该是“NO”。 

限制非常小：每个数字最多为 9，并且我们最多有 1000 个测试用例。 这意味着即使是检查每个测试用例的所有可能对的解决方案也会很快，因为对于每个测试用例只有三对：`(a, b)`,`(a, c)`,`(b, c)`。 将 3 对乘以 1000 个测试用例仅给出 3000 次操作，远低于任何时间限制。 

例如，值得注意的边缘情况包括所有数字都很小的情况`0 0 0`。 正确的输出是“NO”，因为没有任何对的总和等于 10。同样，如果所有数字都很大，例如`9 9 9`，任何对的总和都是 18，所以答案是“是”。 微妙的边缘是当两个数字处于边界时，例如`1 9 0`-这里只有一对`(1, 9)`满足条件。 粗心的代码可能会错误计算对的数量或尝试对同一元素求和两次，从而给出错误的答案。 

## 方法

 蛮力方法很简单。 对于每个测试用例，考虑所有三对可能的数字并检查它们的总和是否至少为 10。如果任何对满足标准，则打印“YES”； 否则打印“NO”。 这是正确的，因为它会检查所有组合，但一般来说，如果输入集较大，则检查所有对的效率可能会很低。 对于三个元素，暴力破解的速度相当快。 

稍微优雅的解决方案的关键是我们只需要检查三对的总和`(a + b)`,`(a + c)`,`(b + c)`。 这是可行的，因为条件是对称的并且仅取决于对，并且由于只有三个元素，这三个和涵盖了所有可能性。 不需要排序或更高级的数据结构。 检查可以内联执行，从而实现非常简单且可读的实现。

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取三个整数`a`,`b`， 和`c`。 
3. 计算三个可能对的总和：`a + b`,`a + c`， 和`b + c`。 
4. 检查这些总和是否大于或等于 10。 
5. 如果至少有一项总和满足标准，则输出“YES”。 否则，输出“NO”。 

为什么有效：该算法会检查每对不同的数字。 因为该问题仅询问**任何对**的总和是否达到 10，因此覆盖所有三对就足够了。 除这三种情况外，没有任何隐藏情况，因此结果保证正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    if a + b >= 10 or a + c >= 10 or b + c >= 10:
        print("YES")
    else:
        print("NO")
```代码直接实现了最优算法。 我们使用`sys.stdin.readline`对于快速输入，这在以下情况下更重要`t`很大。 每个测试用例都是独立处理的，并使用简单的逻辑 OR 语句评估条件，确保检查所有对。 使用`>= 10`确保我们正确捕获边界。 除了读取测试用例之外没有任何循环，因此复杂性很小。

import sys, io

def run(inp: str) -> str:

 ## 边缘情况

 该算法处理所有数字都为零的边缘情况。 输入`0 0 0`结果总和为 0, 0, 0。没有一个满足条件，因此输出为“NO”。 对于最大位数`9 9 9`，所有和都是 18，产生“YES”。 对于边界条件，例如`1 9 0`，它正确识别了`(1, 9)`配对并输出“YES”。 每个不明显的场景都被覆盖，因为算法明确地检查所有三个可能的对。
