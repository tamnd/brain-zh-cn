 ## 解决方案
 ## 问题理解

 我们拥有一个由有向但可双向通行的路线连接的公交车站系统。 每条路线都是按固定顺序排列的停靠点，沿着路线上相邻的停靠点在任一方向上行驶只需花费一分钟。 每条路线都标有公交车型号，最多有十种不同的型号。 

从第 1 站开始，我们最多需要行驶 T 分钟，并且在移动时我们必须确保每个模型上的至少一个路段至少骑行过一次。 我们可以在共享站点立即切换路线。 在最多 T 分钟的运动之后，我们还必须在停止 1 处结束。问题是这样的步行是否存在。 

输入大小很小，强烈建议进行状态搜索而不是大量渐近优化。 当 N 和 T 达到大约 100 时，朴素最短路径或类似 BFS 探索的自然上限约为 N 乘以 T 乘以一些附加状态维度。 附加维度是已访问过的模型集，其边界为 2^K，其中 K 最多为 10。这立即表明最多具有约 100 × 100 × 1024 个状态的状态图是可行的。 

一种粗心的方法是将其视为停止图上的普通最短路径，同时贪婪地将模型标记为第一次遇到时已访问的模型。 但这会失败，因为收集模型的不同子集可以到达相同的物理位置，并且选择一条早期路径可能会阻碍以后收集丢失模型的能力。 例如，如果两条路线都经过停靠站 2，一条给出模型 1，另一条给出模型 2，则提前承诺一条路线的贪婪行走可能会迫使稍后重新访问成本更高的路径，而最佳解决方案需要在不同状态下延迟或重新访问停靠点。 

另一个常见的错误是将问题压缩为“我们能否在 T 步内以任意顺序到达每个模型”，并且仅在停止时运行 BFS。 这忽略了到达停止并不是目标，目标是通过访问模型的特定历史记录来达到目标​​，而这些历史记录决定了时间限制内的可行性。 

## 方法

 蛮力观点是模拟从第 1 站开始的所有可能的步行，每分钟跟踪我们在哪一站以及到目前为止使用了哪些模型。 每次到达某个站点时，我们都可以选择经过该站点的任何路线，然后移动到该路线中的相邻站点。 在最坏的情况下，我们可以从每个状态分支到几个相邻的路线段，并且我们维护一组已访问的模型。 这创建了一个巨大的隐式搜索空间，其中每分钟都会将可能性乘以外出路线边缘的数量。 经过 T 个步骤，这在 T 中呈指数增长，即使在考虑子集状态之前也是立即不可行的。 

关键的观察结果是，时间足够小，可以将“花费的分钟数”视为最短路径图中的一个维度，而模型集合方面是一个位掩码。 每个状态变成一个三元组：当前停止、当前时间和收集的模型。 转换是确定性的，每次边缘遍历仅花费一分钟。 这将问题转化为最多具有 N × T × 2^K 状态的分层图中的可达性。 

暴力破解会失败，因为它会重复重新计算相同的配置，而分层状态图可确保每个配置最多处理一次。 K 值较小，使得指数因子易于管理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力步行模拟| T 中的指数 | 指数| 太慢了 |
 | (节点、时间、掩码) 状态上的 BFS | O(N·T·2^K + 边) | O(N·T·2^K) | O(N·T·2^K) | 已接受 |

 ## 算法演练

我们在表示当前站点、当前时间以及我们已经乘坐过的公交车型号的状态上构建了一个 BFS。 

1.我们将状态定义为（位置，时间，掩模）。 掩码是一个大小为 K 的位集，指示到目前为止已使用哪些模型。 这种表示就足够了，因为未来的可行性仅取决于我们所处的位置、剩余时间以及仍缺少哪些模型。 
2. 我们用状态 (1, 0, 0) 初始化 BFS，这意味着我们从时间 0 的停止点 1 开始，没有使用任何模型。 
3. 从每个状态，我们考虑所有可能的一分钟动作。 每条路线都是一系列停靠点，因此每对连续的停靠点都会创建一条标有该路线模型的无向边。 从一个站点出发，我们可以沿着包含该站点的任何路线移动到任何相邻站点。 
4. 当我们遍历属于模型 d 的边时，我们通过设置位 d 来更新掩码。 这是记录模型使用情况的唯一方式，并且当我们花时间在该路线上行驶时，就会发生这种情况。 
5. 每次转换都会将时间增加 1。我们只允许在时间 < T 时进行转换，因为我们不能超过限制。 
6. 我们将访问过的状态存储在 3D 数组或哈希结构中，以避免重新访问相同的配置。 如果我们再次到达相同的位置（位置、时间、掩码），则它无法产生新信息并被丢弃。 
7. 如果我们到达 t ≤ T 的任何状态 (1, t, full_mask)，BFS 就会成功终止，这意味着我们回到了停止点 1，收集了所有模型。 
8. 如果BFS结束时没有这样的状态，那么答案是不可能的。 

正确性取决于将每一分钟视为统一的边权重。 BFS 保证如果某个状态是可达的，那么它将按照时间递增顺序被发现，因此将找到 T 内的任何有效解决方案。 

### 为什么它有效

 不变的是，队列中的每个状态都代表在其记录的分钟数之后的不同可实现的配置。 由于所有转换的成本相同，因此 BFS 会在非递减时间内探索状态。 这保证了当第一次达到某个状态时，在达到相同（位置、掩码）组合的所有方式中，以尽可能短的时间达到该状态。 由于任何未来的延续仅取决于这两个组成部分和剩余时间，因此修剪重复项不会错过最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    N, M, K, T = map(int, input().split())

    adj = [[] for _ in range(N + 1)]
    for _ in range(M):
        c, d, *rest = map(int, input().split())
        d -= 1
        stops = rest
        for i in range(c - 1):
            u = stops[i]
            v = stops[i + 1]
            adj[u].append((v, d))
            adj[v].append((u, d))

    FULL = (1 << K) - 1

    # dist[pos][mask][time] is too big; instead store visited as (pos, mask, time)
    # but we can BFS layer by layer in time
    visited = [[[False] * (1 << K) for _ in range(N + 1)] for _ in range(T + 1)]

    q = deque()
    q.append((1, 0, 0))  # pos, mask, time
    visited[0][1][0] = True

    while q:
        u, mask, t = q.popleft()

        if u == 1 and mask == FULL:
            print("Yes")
            return

        if t == T:
            continue

        nt = t + 1

        for v, d in adj[u]:
            nmask = mask | (1 << d)
            if not visited[nt][v][nmask]:
                visited[nt][v][nmask] = True
                q.append((v, nmask, nt))

    print("No")

if __name__ == "__main__":
    solve()
```该代码首先将每条路线转换为连续站点之间的邻接边，并将路线的模型作为边标签。 BFS 状态包括当前停止、收集模型的位掩码和经过的时间。 访问的结构按时间显式索引，以确保我们不会合并具有不同剩余时间的到达同一位置的状态，因为时间是一个硬约束。 

一个微妙的实现细节是，仅在当前时间严格小于 T 时生成转换。这可以防止在时间 T+1 生成状态，否则会违反约束。 另一个重要的一点是，我们仅在返回停止点 1 时检查是否成功，而不是仅在其他地方收集所有模型时检查是否成功，因为返回条件是要求的一部分。 

## 工作示例

 ### 示例 1

 考虑具有 3 个停靠点、2 个模型且 T = 3 的最小设置。假设安排路线使得模型 1 连接 1-2，模型 2 连接 2-1。 

| 步骤| 职位| 面膜| 时间 |
 | --- | --- | --- | --- |
 | 0 | 1 | 00 | 00 0 |
 | 1 | 2 | 01 | 1 |
 | 2 | 1 | 11 | 11 2 |

 在步骤 1 中，我们沿着模型 1 的边移动，收集该模型。 在步骤 2 中，我们返回使用模型 2，完成掩模并返回到开始。 这证实了收集不同方向的模型并提前返回是有效的。 

该跟踪表明，重新访问起点本身并不是终点条件； 它必须与完整的掩模完成相结合。 

### 示例 2

 考虑到达所有模型都需要绕道的情况：

 | 步骤| 职位| 面膜| 时间 |
 | --- | --- | --- | --- |
 | 0 | 1 | 000 | 000 0 |
 | 1 | 2 | 001| 1 |
 | 2 | 3 | 011| 2 |
 | 3 | 2 | 111 | 111 3 |

 这里的最佳策略需要留下部分有用的路径并通过不同的路线返回以拾取丢失的模型。 BFS 捕捉到这一点是因为 (2, 001, 1) 和 (2, 011, 2) 是不同的状态； 贪婪的方法会错误地合并它们并失去完成第三个模型的可能性。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N·T·K + 总路线边数·T) | 每个状态都会处理一次，并且每个转换都会在更新位掩码时检查邻接边缘 |
 | 空间| O(N·T·2^K) | O(N·T·2^K) | 商店跨时间层访问过的州 |

 边界 N、T ≤ 100 和 K ≤ 10 使状态空间大约为 100 × 100 × 1024，这完全在 Python 或 C++ 中的 BFS 的限制范围内。

 ## 边缘情况

 当模型只能通过稍后重新访问停靠点才能到达时，就会出现关键的边缘情况。 例如，如果站点 1 较早连接到模型 1，而模型 2 仅在绕过一个循环后才出现，则避免重访的贪婪方法将失败。 BFS 可以处理这个问题，因为它允许使用不同的掩码和时间重新访问同一站点，从而保留未来的可能性。 

另一个微妙的情况是，当最佳路径在返回停止 1 之前达到完全掩码时。简单的实现可能会在看到收集到的所有模型后提前终止，但这会忽略返回约束。 该算法明确要求在同一状态下同时满足两个条件。 

最后，多条路线共享相同的停止序列但不同模型标签的路径可能会混淆合并邻接列表而不跟踪边缘标签的实现。 这里，每条边都必须保留其模型身份，因为这是对掩模有贡献的唯一信号。
