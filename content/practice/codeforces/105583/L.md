 ## 解决方案
 ## 问题理解

 我们得到了一系列开关和灯泡，但接线是隐藏的。 每个开关恰好连接到一个灯泡，并且每个灯泡至少连接有一个开关。 因此，隐藏结构是将开关划分为最多$N$组，其中每个组对应一个灯泡。 

当我们在开关上选择二进制掩码时，我们会打开某个子集。 对于每个灯泡，我们计算其有多少个开关处于活动状态，然后使用固定规则将该计数转换为亮度值：零个活动开关贡献 0，一个活动开关贡献 3，两个活动开关贡献 5，较大的计数从 5 开始以斜率 1 线性增长。 

对于任何选定的开关子集，交互作用只为我们提供所有灯泡的亮度总和。 我们的目标不是最大化或最小化任何东西，而是重建一种特定的配置：我们必须输出一个掩模，其中每个灯泡都有一个活动开关。 由于每个灯泡贡献亮度为 3，因此该条件相当于使总亮度等于$3N$，但更重要的是，这意味着从每个未知组中准确选择一个代表性开关。 

就以下方面而言，限制很小$N$， 但$K$可以达到 1000 个，但我们仅限于 500 个查询。 关键的困难在于每个查询仅返回所有灯泡的单个聚合值，而隐藏结构是开关上的分区。 

一个天真的想法是通过激活对并观察答案如何偏离可加性来直接测试开关之间的关系。 这是有效的，因为当两个开关属于同一个灯泡时，亮度函数恰好是非线性的。 然而，检查所有对将需要以下顺序：$K^2$查询，远远超出了限制。 

主要的边缘情况是灯泡有多个开关。 例如，如果灯泡有五个开关，则包含多个开关的任何子集都会产生非线性贡献，这是区分成员资格的唯一信号。 任何假设线性或独立处理开关的解决方案都会失败，因为无论单个开关属于哪个灯泡，它总是产生相同的贡献。 

## 方法

 如果我们根据基线线性行为重写亮度函数，问题的结构就会变得更加清晰。 如果灯泡具有完美的线性响应，那么每个有源开关都会贡献固定的量，那么问题就微不足道了。 仅当同时选择同一灯泡的两个或多个开关时，才会出现线性偏差，其中贡献变得小于线性期望。 这为我们提供了两个交换机是否属于同一组的一致性检查。 

这导致了一种自然的强力策略：对于每对开关，仅在这两个开关处于活动状态时查询系统，将结果与各个激活的总和进行比较，并确定它们是否属于同一个灯泡。 一旦知道了所有等价性，我们就重建分区。 这在逻辑上是正确的，因为成对检验准确地表征了成员资格。 

失败点在于复杂性。 这种方法需要$O(K^2)$交互式查询，远远超出了允许的 500 个限制。 

关键的观察是我们实际上并不需要所有的成对关系。 我们只需要最多将交换机集群成$N \le 100$组。 每个交换机必须准确地分配给一个组，因此如果我们可以维护已发现组的代表，我们只需要针对这些代表测试成员资格。 然后，交互变成聚类过程：将每个新交换机与现有组进行比较，直到找到匹配项。 

这减少了增量构建分区的问题。 困难在于确保每次比较仅使用常量查询，并且比较总数仍受查询限制的限制。 通过仔细缓存单交换机响应和重用结果，每个成员资格测试都可以减少为对一对交换机的一个新查询。 

因此，解决方案成为由成对非线性测试驱动的确定性聚类过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力配对测试 |$O(K^2)$查询 |$O(1)$额外 | 太慢了 |
 | 通过代表进行增量分组 |$O(KN)$查询 |$O(K)$| 已接受 |

 ## 算法演练

 我们依赖这样一个事实：两个开关属于同一个灯泡，当且仅当激活它们时产生的亮度严格小于它们单独激活的总和。 

1. 我们首先通过在仅打开该开关的情况下发出查询来计算每个单独开关的亮度。 每个此类查询都会返回相同的值，但我们会将其存储起来以供以后重用，这样我们就可以计算附加基线而无需重新查询。 
2. 我们维护一份已发现组的列表，每个组由一个选定的“领导者”交换机代表。 
3. 对于每个新的切换，我们都会将其与现有的组领导者进行比较。 为了测试它是否属于领导者组，我们在两个开关都打开的情况下发出查询。 我们将此结果与它们各个单开关值的总和进行比较。 
4. 如果组合查询显示没有非线性下降，则这些开关属于不同的灯泡，因此我们继续针对下一个领导者进行测试。 
5. 如果检测到非线性下降，我们将当前交换机分配给该领导者组并停止检查其他领导者。 
6. 如果交换机与任何现有组都不匹配，它将启动一个新组并成为其代表。 
7. 处理完所有开关后，每一组恰好包含属于一个灯泡的开关。 
8. 我们通过从每组中选择一个开关并关闭所有其他开关来构建最终答案。 

正确性取决于结构中的每个组完全对应于一个灯泡的不变量，并且没有开关可以属于两个组，因为成对非线性测试对于共享成员资格来说既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(mask: str) -> int:
    print("R", mask)
    sys.stdout.flush()
    return int(input().strip())

def build_mask(n, indices):
    arr = ["0"] * n
    for i in indices:
        arr[i] = "1"
    return "".join(arr)

def main():
    N, K = map(int, input().split())

    single = [0] * K
    for i in range(K):
        m = ["0"] * K
        m[i] = "1"
        single[i] = ask("".join(m))

    groups = []
    rep = []

    for i in range(K):
        placed = False
        for g_id, r in enumerate(rep):
            m = ["0"] * K
            m[i] = "1"
            m[r] = "1"
            val = ask("".join(m))

            if val != single[i] + single[r]:
                groups[g_id].append(i)
                placed = True
                break

        if not placed:
            groups.append([i])
            rep.append(i)

    answer = ["0"] * K
    for g in groups:
        answer[g[0]] = "1"

    print("A", "".join(answer))
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```该解决方案首先单独查询每个交换机，存储基线贡献。 尽管这些值在理论上是相同的，但缓存它们允许我们在比较对时计算预期的附加行为。 

该算法的核心是针对群体代表的成对测试。 对于每个候选交换机，我们仅将其与每个发现的组中的一个代表进行比较。 如果组合查询偏离可加性，我们立即知道两个开关属于同一个灯泡。 

分组完成后，为每组选择一名代表可确保每个灯泡只有一个活动开关，因为组与灯泡完全对应。 

## 工作示例

 考虑一个具有三个灯泡和六个开关的小型系统，其中灯泡位于$\{0,1\}, \{2,3\}, \{4,5\}$。 

对于交换机 0 和 1，单交换机查询各返回 3。 合并查询返回5，小于6，因此将它们放在同一组中。 对于开关0和2，组合查询返回6，匹配可加性，因此它们属于不同的组。 

| 步骤| 我| 领导检查 | 查询结果 | 单[i] + 单[领导者] | 决定|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 无 | 单身| - | 新组 |
 | 2 | 1 | 0 | 5 | 6 | 同组|
 | 3 | 2 | 0 | 6 | 6 | 不同|
 | 4 | 2 | 1 | 6 | 6 | 不同→新团体|

 该迹线表明，非线性仅出现在真正的灯泡内，而跨灯泡对的行为则呈相加性。 

组大小不均匀的第二个示例，例如一个灯泡具有三个开关，而其他灯泡各有一个，证实相同的检测规则仍然正确地隔离了密集组，因为其中的任何对都会产生非线性下降。

 ## 边缘情况

 一个关键的边缘情况是灯泡包含许多开关。 在这种情况下，灯泡内的每对开关都会产生非线性响应，并且算法始终将它们合并到同一组中，因为始终会检测到与可加性的偏差。 例如，如果开关 0、1 和 2 属于同一个灯泡，则它们中的每一对产生的组合亮度严格小于各个查询的总和，因此所有三个开关都可以传递地合并到一组中，而不会产生歧义。 

当每个灯泡只有一个开关时，就会出现另一种边缘情况。 在这种情况下，没有一对开关会产生非线性响应，因此每个开关都成为自己的组，并且该算法正确地输出所有开关作为解决方案，因为每个开关已经满足每个灯泡一个活动开关的要求。
