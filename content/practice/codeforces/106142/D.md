 ## 解决方案
 ## 问题理解

 我们被要求处理多个独立的查询。 每个查询给出一个区间$[a, b]$和一个目标数$k$。 对于每个整数$x$在那个区间内，我们转换$x$转换为不带前导零的二进制，并计算有多少位等于 1。任务是计算区间中有多少个数字恰好符合$k$其二进制表示形式。 

输入约束足够严格，可以立即排除每个查询直接检查每个数字的可能性。 自从$b$可以达到$10^9$，二进制表示最多有 30 位。 位长度的小上限是关键的结构属性：问题本质上是关于长度最多为 30 的位掩码的分布。 

一个天真的每次查询扫描$a$到$b$将花费高达$10^9$最坏情况下的操作次数，远远超出了 1000 次查询所允许的范围。 即使平均间隔很小，最坏情况的行为在竞争性编程中也很重要。 

一个微妙的边缘情况是由于我们计算不带前导零的二进制表示形式这一事实而产生的。 这很重要，因为我们不使用固定宽度的位串； 最高位位置取决于数字本身。 例如，$7 = 111_2$有三个，而$8 = 1000_2$具有一一，即使如果填充的话两者都是 4 位表示。 

另一个边缘情况是当$k$超过区间内数字的位长度。 例如，如果$a = 1, b = 3$，最大数量为 2，因此任何查询$k \ge 3$必须返回零。 正确的解决方案必须自然地处理这个问题，而无需特殊的外壳。 

## 方法

 蛮力方法直接迭代每个数字$x \in [a, b]$，将其转换为二进制，计算设置的位数，并检查它是否等于$k$。 这是正确的，因为它完全遵循问题的定义。 每个号码的成本为$O(\log x)$，因为计数位需要扫描二进制表示。 经过一段时间间隔，这变成了$O((b-a+1)\log b)$每个查询。 在最坏的情况下，如果$a=1$和$b=10^9$，这是关于$10^9 \cdot 30$每个查询的操作数，这是完全不可行的。 

关键的观察是条件仅取决于二进制表示，并且数字最多为$10^9$适合 30 位以内。 我们不是迭代值，而是使用二进制表示上的数字动态编程来计算给定范围内存在多少个有效位模式。 一旦我们可以计算一个函数$F(x)$，计算中的数字$[0, x]$正好有$k$个，每个查询都变成一个减法$F(b) - F(a-1)$。 

这将问题从迭代值转变为迭代位位置（以 30 为界）。状态空间变得很小且固定，与范围大小无关。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O((b-a)\log b)$每个查询|$O(1)$| 太慢了 |
 | 数字DP |$O(30 \cdot k)$每个查询|$O(30 \cdot k)$| 已接受 |

 ## 算法演练

 我们定义一个函数$F(x)$计算有多少个整数$[0, x]$正好有$k$二进制表示的那些。 

1. 转换$x$转换为从最高有效位到最低有效位的二进制表示形式。 这为我们提供了一个固定长度的结构来遍历，这对于数字 DP 至关重要。 
2. 我们在二进制字符串中的位置上定义 DP 状态。 在每个位置，我们决定是否放置 0 或 1，但我们必须遵守不超过的约束$x$。 这是使用紧密标志来处理的，该标志指示到目前为止的前缀是否完全等于$x$。 
3. 我们还跟踪我们已经放置了多少个。 该计数是状态的一部分，因为最终答案取决于它。 
4. 转换考虑当前位的两种选择。 如果我们放置 1，我们就会增加 1 的计数； 如果我们放置 0，则计数保持不变。 我们只允许不超过的转换$k$，因为任何路径超过$k$可以尽早丢弃。 
5. 当我们到达位串的末尾时，我们检查 1 的数量是否等于$k$。 如果是，则这是一个有效的数字。 
6. 对于每个查询，计算$F(b) - F(a-1)$。 减法正确地隔离了区间。 

关键的设计选择是，我们不是迭代数字，而是迭代位位置并增量构造有效数字，确保我们永远不会违反上限。 

### 为什么它有效

 中的每个整数$[0, x]$恰好对应于一个长度最多为 30 的二进制字符串（概念上用前导零填充）。 DP 以结构化方式枚举所有此类字符串，不重复。 严格的约束确保我们生成的数字永远不会大于$x$，个数维度确保我们只累积有效的配置。 由于每个有效数都只生成一次并且不计算无效数，因此 DP 结果是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def count_upto(x, k):
    bits = list(map(int, bin(x)[2:]))
    n = len(bits)

    @lru_cache(None)
    def dp(i, tight, ones):
        if ones > k:
            return 0
        if i == n:
            return 1 if ones == k else 0

        limit = bits[i] if tight else 1
        res = 0

        for b in (0, 1):
            if b > limit:
                continue
            res += dp(i + 1, tight and (b == limit), ones + b)

        return res

    return dp(0, True, 0)

t = int(input())
for _ in range(t):
    a, b, k = map(int, input().split())
    print(count_upto(b, k) - count_upto(a - 1, k))
```该解决方案在上限的二进制表示上构建递归数字 DP。 功能`count_upto`计算有效数字最多`x`恰好与`k`那些。 记忆确保每个状态被计算一次。 

这`tight`flag 强制执行前缀约束：当为 true 时，当前位不能超过对应位`x`。 一旦我们放置了较小的位，我们就会切换到自由状态。 

这`ones`参数跟踪到目前为止已经放置了多少个。 及早修剪时`ones > k`避免探索无效分支。

 ## 边缘情况

 对于像这样的单值区间$a=b=2^{30}$，二进制表示形式是单个 1 后跟零。 DP 从等于完整位模式的严格约束开始，仅允许一条有效路径。 个数计数器恰好达到 1，因此当$k=1$否则为 0。 

对于以下情况$k=0$， 例如$a=1, b=10$，没有正整数符合条件，因为每个正数都至少有一个设置位。 DP 正确地拒绝所有路径，因为不可能在遵守排除前导仅零数字的表示规则的同时放置所有零，但不在区间中的数字 0 除外。
