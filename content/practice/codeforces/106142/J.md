 ## 解决方案
 ## 问题理解

 我们有一个非常大的矩形网格`n`行和`m`列。 有些细胞被石头挡住了，而所有剩余的细胞都是自由的。 任务是计算有多少个不同的位置`2 × 2`正方形的存在使得正方形的所有四个单元都位于网格内，并且它们都不包含石头。 

的放置`2 × 2`正方形完全由其左上角的单元格决定。 如果左上角是`(i, j)`，然后正方形覆盖`(i, j)`,`(i, j+1)`,`(i+1, j)`,`(i+1, j+1)`。 因此，有效的位置与范围内的左上角完全对应`1 ≤ i ≤ n-1`和`1 ≤ j ≤ m-1`这样所有四个被覆盖的单元格都是空闲的。 

网格大小的约束是极端的，`n`和`m`高达十亿。 这使得任何遍历网格的方法都是不可能的。 阻塞单元的数量最多为 200,000 个，足够小，可以直接迭代。 这种不平衡是中心结构提示：解决方案必须仅取决于阻塞的单元格，而不取决于网格尺寸。 

天真的尝试会枚举所有`(n-1)(m-1)`可能的`2 × 2`展示位置并检查每个展示位置是否有效。 这是不可行的，因为网格最多可以包含`10^18`候选人职位。 

第二个天真的想法是迭代每个被阻止的单元格并标记所有受影响的单元格`2 × 2`正方形。 这更接近正确，但需要小心，因为多个棋子可能会使同一个方块无效，因此必须正确处理重复的棋子。 

通常破坏错误解决方案的边缘情况包括没有棋子的网格、棋子位于边界上的网格（影响较少的方块）以及多个棋子导致相同无效的情况`2 × 2`地区。 例如，如果两块石头位于同一块内`2 × 2`面积，该方格仍必须仅被算作无效一次。 

## 方法

 直接计数方法从观察到每个有效位置对应于一个左上角`2 × 2`堵塞。 没有任何石头，答案很简单`(n - 1) × (m - 1)`。 

引入石头只会删除其中一些位置。 如果一个位置的四个单元格中至少有一个包含石头，则该位置无效。 我们不是检查所有展示位置，而是反转视角：从所有可能的展示位置开始，减去那些被阻止的展示位置。 

关键的困难是避免重复计算。 每颗棋子最多影响棋子的四个可能的左上角`2 × 2`包含它的正方形。 如果我们收集所有此类受影响的位置并将它们视为无效位置，那么当多个棋子影响同一个方块时，自然会出现重复。 这建议使用一个集合来存储所有无效的左上角。 

最终的答案是放置总数减去从所有棋子中收集的不同无效放置的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有方格| O(纳米) | O(1) | O(1) | 太慢了 |
 | 枚举石头中受影响的方块 | O(k) 平均 | O(k) | 已接受 |

 ## 算法演练

 1. 计算可能的总数`2 × 2`空网格中的放置位置为`(n - 1) × (m - 1)`。 这代表所有可能容纳正方形的左上角。 
2. 维护一个集合来存储所有左上角`2 × 2`由于至少有一颗棋子而无效的方格。 
3. 对于位于`(x, y)`，确定哪个`2 × 2`它可以属于的方块。 一块石头可以位于一个正方形中，其左上角是以下之一`(x, y)`,`(x-1, y)`,`(x, y-1)`,`(x-1, y-1)`前提是这些坐标位于有效的左上角范围内。 
4. 对于每个这样的候选左上角`(i, j)`，检查是否`1 ≤ i ≤ n-1`和`1 ≤ j ≤ m-1`。 如果有效，则插入`(i, j)`进入无效展示位置集合。 
5.处理完所有石子后，从放置总数中减去无效集的大小。 

这样做的原因是每个无效的`2 × 2`正方形必须包含至少一块石头，因此在处理该石头时必须发现它。 相反，每个方块最多在集合中添加一次，无论它包含多少块石头，因为集合消除了重复项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    total = (n - 1) * (m - 1)
    
    bad = set()
    
    for _ in range(k):
        x, y = map(int, input().split())
        
        # possible top-left corners of 2x2 blocks containing (x, y)
        candidates = [
            (x, y),
            (x - 1, y),
            (x, y - 1),
            (x - 1, y - 1)
        ]
        
        for i, j in candidates:
            if 1 <= i <= n - 1 and 1 <= j <= m - 1:
                bad.add((i, j))
    
    print(total - len(bad))

if __name__ == "__main__":
    solve()
```该解决方案首先依赖于计算完整计数，然后删除无效配置。 候选生成步骤是关键部分：每颗宝石仅影响恒定的许多潜在位置，因此总工作量与`k`。 该集合确保多个宝石的重叠影响不会导致过度减法。 

## 工作示例

 ### 示例 1

 输入：```
3 3 2
1 3
3 3
```总计可能`2 × 2`展示位置是`(2 × 2) = 4`。 

我们加工石材`(1, 3)`第一的。 

| 石材| 候选左上角| 有效角点已添加到错误集中 |
 | ---| ---| ---|
 | (1,3) | (1,3), (0,3), (1,2), (0,2) | (1,3), (0,3), (1,2), (0,2) | (1,2) |
 | (3,3) | (3,3)、(2,3)、(3,2)、(2,2) | (2,2) |

 现在`bad = {(1,2), (2,2)}`。 

答案就变成了`4 - 2 = 2`。 

该跟踪表明，尽管多个棋子通常可能会贡献候选者，但每个无效方格都被恰好捕获一次。 

### 示例 2

 输入：```
3 5 3
2 4
2 2
2 3
```总展示位置为`(2 × 4) = 8`。 

所有石头都位于连续列的第 2 行，这严重污染了所有石头`2 × 2`穿过该行的正方形。 

处理完所有候选项后，每个可能的左上角都会出现在无效集中。 

最终结果是`0`，匹配每个可能的事实`2 × 2`正方形至少包含一个被阻挡的单元格。 

这个例子表明，该算法可以自然地处理密集的石头簇，而无需特殊的外壳。

 ## 边缘情况

 没有石子的网格直接用公式处理`(n - 1) × (m - 1)`因为无效方块集仍然是空的。 该算法不会产生候选插入，因此减法不会执行任何操作。 

边界上的一块石头，例如`(1, m)`仅当左上角保持在边界内时才对有效左上角起作用。 候选生成自然地过滤掉无效坐标，例如`(0, m)`或者`(1, m)`什么时候`m`超出了左上角的限制。 

当多个石头位于同一个石头中时`2 × 2`区域中，它们都尝试将相同的左上角插入到集合中。 该集合确保该方格在无效集合中仅计算一次，从而防止过度减法。 

完全封锁`2 × 2`区域被正确处理，因为其中的每个石头都会生成相同的左上候选，从而确保该方块仅包含在无效集中一次。
