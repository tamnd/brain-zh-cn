 ## 解决方案
 ## 问题理解

 我们得到了一个简短的整数调整序列，一个接一个地应用于运行总计。 每个值都可以增加或减少总和，具体取决于它是正数还是非正数，但实际上它们只是按原样添加。 

问题不仅仅在于最终的完整序列。 我们可以选择这些值的任何子集，保留它们的原始值，并确定是否存在至少一个其总和恰好为 14 的子集。如果存在这样的选择，则输出为正，否则为负。 

该结构本质上是在询问 14 是否可以由一小部分整数（可能包括负数、零和正数）组成子集和。 

对元素数量的限制非常小，n 最多为 19。这个界限是问题中的关键信号。 这种大小的列表允许对所有子集进行指数探索，因为子集总数为 2^19，略高于 50 万。 它足够小，可以在 Python 的时间限制内直接进行评估，而无需中间相遇或动态编程位集等高级优化技术。 

每个元素的值范围从 -10 到 19，不需要超出正常整数运算的特殊处理。 然而，它确实意味着中间和可能为负或超过 14，因此如果应用剪枝策略，则必须谨慎使用。 

一些边缘情况值得关注。 如果所有数字都是正数且大于 14，则任何子集都不能达到 14，并且正确答案立即为负数。 例如，输入`[20, 30]`显然不能形成 14。相反，如果有一个元素等于 14，则答案立即为正。 另一个微妙的情况是零存在时。 零不会改变总和，但仍算作不同的子集选择，因此无论是否包含额外的零，达到 14 的子集仍然有效。 

## 方法

 最直接的方法是尝试给定数字的每个可能的子集并计算其总和。 由于每个元素都有两个选择，要么包含，要么不包含，这就导致了 2^n 种可能性。 对于每个子集，我们以 O(n) 计算总和或在位掩码枚举期间维护增量总和。 因此，在简单的实现中，总工作量约为 n 乘以 2^n。 

当 n = 19 时，这个上限大约是 19 × 524,288，大约是一千万个原始操作。 在 Python 中，这仍然是可以接受的，特别是因为加法和位运算很便宜。 所以即使是蛮力也已经足够了。 

另一种观点是对可实现的总和进行动态规划，但由于值包含负数，因此具有固定偏移量的经典背包 DP 变得稍微麻烦一些。 我们需要改变范围或使用一组来跟踪可达到的总和。 这也是可行的，但与此约束机制中的简单子集枚举相比，它并没有提高渐近复杂性。 

关键的见解是，除了枚举子集之外，我们不需要进行优化。 明确选择 n 的约束以使穷举搜索成为预期的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 | O(n·2^n) | O(n·2^n) | O(1) 或 O(n) | 已接受 |
 | DP / 和集 | O(n·S)，其中 S 是总和范围 | O(S)| 已接受但没有必要 |

 ## 算法演练

 我们将每个子集视为长度为 n 的二进制掩码。 每个比特指示对应的元素是否包括在子集中。 

1. 读取整数数组并将其存储在列表中。 这为我们提供了子集构造的直接索引访问。 
2. 迭代 0 到 2^n − 1 之间的所有整数。每个整数代表数组的一个子集。 二进制表示对每个元素的包含或排除进行编码。 
3. 对于每个子集掩码，计算相应位被设置的所有元素的总和。 这是通过扫描从 0 到 n-1 的所有位置并检查该位是否有效来完成的。 重新计算而不是维护增量总和的原因很简单，并且考虑到限制，成本仍然可以接受。 
4. 如果在任何时候计算出的总和等于 14，我们可以立即返回成功，因为我们只需要存在一个有效子集。 
5. 如果在用尽所有掩码后没有子集产生和 14，我们得出结论这是不可能的。 

### 为什么它有效

 数组的每个子集恰好对应一个二进制掩码，并且每个二进制掩码恰好对应一个子集。 这种双射保证了对所有掩码的迭代可以枚举所有可能的子集，而不会遗漏或重复。 由于我们明确检查每个子集的总和，因此在迭代过程中必须遇到总和为 14 的任何有效组合。 因此，如果存在，算法就会找到它； 如果不存在，则完整枚举将完成而不会触发成功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    n = int(data[0])
    arr = list(map(int, data[1:]))

    # in case input is split across lines
    while len(arr) < n:
        arr.extend(map(int, input().split()))

    target = 14

    for mask in range(1 << n):
        s = 0
        for i in range(n):
            if mask & (1 << i):
                s += arr[i]
        if s == target:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```解析步骤考虑了稍微不规则的输入格式，其中数字可能跨行分割或不一致地组合。 核心逻辑是位掩码枚举。 每个掩码都被独立解释，并且我们累积一个局部总和变量`s`。 一旦找到有效的子集，发现 14 的早期退出可以防止不必要的探索。 

一个微妙的实现细节是确保输入解析不会采用第一个标记之外的严格行结构。 在竞争性编程环境中，防御性解析可以避免格式错误的间距造成的运行时错误。

我们枚举子集：

这表明该算法可以正确地将整个集合识别为有效子集，而不需要任何修剪或启发式方法。

 ## 边缘情况

 单个元素等于 14 的情况将立即由仅选择该元素的子集掩码处理。 在迭代期间，恰好具有与该元素相对应的一位集的掩码产生和 14 并触发提前终止。 

所有数字均为负数的情况表明没有子集可以将总和增加到正目标。 该算法仍然枚举所有子集，但每个计算出的和仍然为非正数，因此永远不会触发 14 的相等检查，最终输出为“否”。 

包含零的情况表明，没有贡献的额外元素不会影响正确性。 仅包含元素 14 的子集仍然存在于掩码中，额外的零只会创建重复的和，但不会影响目标子集的检测。
