 ## 解决方案
 ## 问题理解

 我们得到一个整数的多重集合，两个玩家在严格的约束下轮流从中选择数字。 当玩家选择一个号码时，该号码必须严格大于他们之前选择的每个号码，并且所选号码将从池中删除。 当玩家无法做出任何有效的移动时，游戏结束，该玩家失败。 丹尼先行动，两位球员都发挥最佳。 

关键的结构细节是，每个玩家都构建一个从数组中选择的严格递增的值序列，并且该数组是共享的，因此两个玩家都在竞争相同的排序资源。 

输入大小可以达到一百万个元素，这立即排除了任何显式模拟游戏的策略。 任何尝试对所有游戏状态进行建模或跟踪子集上的逐轮选择的解决方案都会发生组合爆炸。 即使 O(N log N) 或 O(N √N) 方法也是可以接受的，但任何比线性或近线性更糟糕的方法都将无法生存。 

当所有数字都相同时，就会出现一个微妙的问题。 在这种情况下，没有玩家可以选择多个元素，因为选择一个值后，下一个所需的值必须严格更大，而这是不存在的。 这会导致在极少量的移动后立即终止，并且任何假设玩家总是耗尽数组或均匀交替的解决方案都将在这里失败。 

另一个极端情况是数组已经严格递增。 在这种情况下，两个玩家都可以玩很长时间，结果完全取决于有多少元素可以分配到交替递增的序列中，而不仅仅取决于价值大小。 

真正的困难在于，游戏的重点不是数值本身，而是数值可以在交替递增的链上“使用”多少次。 

## 方法

 游戏的直接模拟将维护每个玩家当前最后选择的值，扫描数组以查找有效的下一步动作，将其删除，然后继续交替回合。 这将需要每次移动重复扫描最多 N 个元素，并且总共最多需要 N 个移动，从而导致最坏情况运行时间为 O(N²)。 当N达到一百万时，这是不可能的。 

为了改进，我们发现数组中数字的确切位置并不重要，重要的是它们的频率和排序关系。 如果我们对数组进行排序，游戏就相当于以升序重复消耗值，但尽可能在玩家之间交替分配。 

一个更有用的观点是根据递增序列的“层”来思考。 每次我们选择一个值时，我们都会有效地将其分配给两个递增子序列之一。 由于每个子序列必须严格递增，因此重复项不能出现在同一子序列中，但可以跨子序列拆分。 

这将问题转化为理解需要多少个递增链来覆盖多重集。 由于恰好有两个玩家，我们询问多重集是否可以划分为最多两个严格递增的序列。 

根据经典的排序参数，当我们将“增加”解释为需要严格不等式时，划分多重集所需的严格增加序列的最小数量等于任何值的最大频率。 然而，仅靠这一点还不够，因为游戏是轮流进行的，而且玩家不合作。 

相反，我们将这个过程重新解释为对排序数组的贪婪消耗：两个玩家总是更喜欢最小的可用有效下一个元素，因为过早获取较大的元素会降低未来的灵活性。 在最佳发挥下，该结构会崩溃为不同价值水平上的交替传球。

决定性的简化在于，只有不同“选择层”数量的奇偶性才重要。 每次我们移动到超出前一层边界的新的严格更大的值时，我们都会有效地提高游戏深度。 如果有效层总数为奇数，则先走最后一步的玩家获胜； 否则，第二个玩家获胜。 

关键的观察结果是此类层的数量等于数组中不同值的数量。 每个不同的值都会在任何增加的选择过程中引入一个新的强制步骤，因为在单个玩家的序列中，值必须严格增加，并且相同的值不能在该序列中重复使用。 

因此，两个玩家都有效地交替遍历不同值的排序集合，并且获胜者完全取决于不同值的数量是奇数还是偶数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(N²) | O(N) | 太慢了 |
 | 排序 + 不同计数奇偶校验 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 1. 读取所有数字并对它们进行排序，使相等的值相邻。 这是必要的，因为只有相等结构很重要，并且排序以线性形式公开该结构。 
2. 扫描已排序的数组并计算出现的不同值的数量。 每次遇到与前一个不同的值时，我们都会增加不同的计数器。 这捕获了游戏中强制“价值级别”的数量。 
3. 根据本次计数的奇偶性确定获胜者。 如果不同值的数量是奇数，那么先开始的丹尼将做出最后一个有意义的举动。 如果是平局，则由对手采取最后一步。 
4. 如果计数为奇数，则输出 WIN，否则输出 LOSS。 

之所以有效，是因为每一步都必然消耗一个严格递增值的“层”，并且由于严格递增约束，任何层都不能被跳过或合并。 由于玩家在这些层上完美交替，因此最后一层决定了获胜者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    distinct = 0
    prev = None
    
    for x in a:
        if prev is None or x != prev:
            distinct += 1
            prev = x
    
    if distinct % 2 == 1:
        print("WIN")
    else:
        print("LOSS")

if __name__ == "__main__":
    solve()
```排序步骤确保所有相等的值都被分组，从而可以在单个线性传递中对不同元素进行计数。 该循环维护运行的先前值，并且仅当出现新值时才递增计数器。 

最终的奇偶校验对游戏的交替性质进行编码：每个不同的值实际上对应于必须按顺序消耗的一个“回合层”。

 ## 边缘情况

 对于所有值都相同的输入，例如：```
5
4 4 4 4 4
```排序扫描仅产生一个不同的值。 算法算数`distinct = 1`，所以丹尼赢了。 事实上，在丹尼选择一个 4 后，任何一位玩家都无法再进一步移动，因此他立即获胜，符合平价规则。 

对于严格增加输入：```
4
1 2 3 4
```每个元素都会增加不同的计数器，产生 4。由于这是偶数，所以丹尼输了。 追踪游戏玩法，玩家交替消耗不断增加的选择链，第二个玩家采取最后的强制行动。 

对于混合重复：```
6
1 1 2 2 3 3
```不同的值是`{1,2,3}`给出 3，所以丹尼获胜。 尽管频率相等，但值级别的数量是奇数，因此第一个玩家确保层之间的最终转换。
