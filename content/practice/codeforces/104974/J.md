 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 在每个测试用例中，都有几种花类型，每种类型都有固定的“美丽系数”，并且恰好有 100 朵相同的花可用。 每朵花1第纳尔，我们最多能买`c`总共花。 

如果我们购买一些鲜花系列，则花束得分定义为一个比率：所选鲜花的总美丽度除以商店中所有鲜花的总美丽度。 由于每种类型都会贡献 100 朵相同的花，因此测试用例的分母是固定的，并且仅取决于输入数组，而不取决于我们购买的商品。 

这将任务变成了纯粹的最大化问题：我们希望在预算约束下最大化所选花朵的总美丽总和，然后将其标准化为常数值。 

每种花型`i`贡献`a_i`总共有 100 份。 所以店铺就相当于拥有`100 * n`项目其中每个`a_i`正好出现 100 次。 我们最多可以选择`c`项目。 

输出是表示该归一化最大值的实数。 

约束允许最多`5 × 10^4`每个测试用例的类型，最多`10`测试用例。 显式扩展所有花将产生最多`5 × 10^6`项目，这是边界，但在优化语言中仍然可行，但没有必要。 

主要的边缘情况是`c`非常大，最多`10^9`。 在这种情况下，约束实际上是无关的，因为我们不能超过可用的`100n`花朵。 

一个幼稚的错误是将其视为分数或连续优化问题，或者将分母误解为取决于所选子集。 例如，如果错误地假设分母随着选择而变化，贪婪选择可能会变得无效。 另一个微妙的陷阱是扩大所有`100n`没有考虑到许多值是重复的，从而导致不必要的开销。 

一个小的说明性案例：

 输入：```
n = 2, c = 3
a = [5, 1]
```我们有 100 个 5 的副本和 100 个 1 的副本。最佳选择显然是 3 个 5 的副本，而不是混合 1。 任何无法对相同值进行分组的方法都会做额外的工作，但仍然必须尊重这种结构。 

## 方法

 如果我们直接模拟这个过程，我们构造所有`100n`花，按美丽程度排序，然后取顶部`c`。 这是正确的，因为每朵花对总和都有独立的贡献。 问题在于规模：每个测试用例排序最多 500 万个元素是临界值，但仍在一定范围内，尽管显然没有必要。 

关键的观察结果是结构已经分组。 我们可以将每种类型视为由 100 个相同值组成的块，而不是考虑单个花朵。 由于所有项目都是独立且相加的，因此最优选择总是倾向于更高的`a_i`价值观第一。 在一个类型中，所有副本都是相同的，因此只有当我们超出预算时才会选择部分类型。 

这减少了排序问题`n`类型按`a_i`按降序排列，贪婪地从每种类型中获取最多 100 个，直到耗尽预算`c`。 

一旦我们计算出可达到的最大总和，最终的答案就是该总和除以所有花朵的恒定总美丽，即`100 * sum(a_i)`。 将分子和分母乘以 1 可将表达式简化为稳定的浮点计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（展开所有花朵）| O(100n log(100n)) | O(100n log(100n)) | O(100n) | 已接受但沉重|
 | 最优（排序类型+贪婪）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.计算所有美丽系数的总和，`S = sum(a_i)`。 这表示归一化分母达到常数因子。 
2. 对数组进行排序`a`按降序排列。 这确保了我们始终首先考虑最有价值的花朵，这是必要的，因为每朵花都具有更高的价值`a_i`支配任何较低的花`a_i`。 
3. 初始化变量`taken_sum = 0`并跟踪剩余预算`c`。 
4. 迭代排序列表。 对于每个值`a_i`，确定我们可以从这种类型中取出多少朵花：`take = min(100, c)`。 这既考虑了可用性约束又考虑了预算约束。 
5. 添加`take * a_i`到`taken_sum`，并减去`take`从`c`。 
6. 如果出现以下情况，请尽早停止`c`变为零，因为不可能有进一步的贡献。 
7. 将最终答案计算为`taken_sum / S`。 

### 为什么它有效

 该过程是对多组独立加权项的贪婪选择的直接应用。 每朵花在其类型中都是相同的，因此任何最佳解决方案都相当于选择所有花的排序多重集的前缀。 排序可确保此前缀按贡献递减排序，因此用较高价值的未选择的花替换任何较低价值的选定花总是会提高或保留总和。 由于分母是恒定的，最大化比率减少为最大化分子，所以这种贪婪的结构产生最优的花束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(float, input().split()))
        
        total = sum(a)
        a.sort(reverse=True)
        
        rem = c
        taken = 0.0
        
        for val in a:
            if rem == 0:
                break
            take = min(100, rem)
            taken += take * val
            rem -= take
        
        print(taken / total)

if __name__ == "__main__":
    solve()
```该代码首先读取所有花卉类型并计算归一化总和。 排序确保我们首先处理最有价值的类型。 该循环贪婪地消耗每种类型最多 100 朵花，但绝不会超出预算`c`。 最后的除法将累积的选择分数转换为所需的归一化值。 

一个微妙的实现细节是一致地使用浮点运算，因为输入和输出都涉及实数。 另一个重要的一点是提前终止，当`rem`达到零，这避免了不必要的迭代`c`相比之下较小`n`。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, c = 4
a = [4, 2, 1]
```我们有以下流程：

 | 步骤| 当前类型| 雷姆 | 采取 | 总和|
 | ---| ---| ---| ---| ---|
 | 1 | 4 | 4 | 4 | 16 | 16
 | 2 | 2 | 0 | 0 | 16 | 16
 | 3 | 1 | 0 | 0 | 16 | 16

 我们取四朵价值为 4 的花，并在耗尽预算后立即停止。 分母是`4 + 2 + 1 = 7`，所以结果是`16 / 7`。 

这证实了将预算集中在最高值上是最佳的。 

### 示例 2

 输入：```

 | 3 | 2 | 0 | 0 | 600 |

 在接触较低值类型之前，我们会完全耗尽这两种高值类型。 这表明，在预算允许的情况下，该算法自然会填充完整的 100 项块。

 ## 边缘情况

 当`c`超过`100n`，该算法完全处理每种类型，获取所有可用的花朵。 循环自然会处理这个问题，因为`min(100, rem)`上限始终为 100，直到预算用完或所有类型都用完为止。 

如果全部`a_i`相等，排序不会改变顺序，但算法仍然可以通过按顺序填充类型来正确运行。 例如，与`a = [2,2,2]`和`c = 250`，我们从前两种类型中各取 100，从第三种中取 50，产生与统一权重一致的比例结果。 

什么时候`c`非常小，只有前几个最高值类型被触及。 由于该算法始终按降序处理，因此在用完较高价值的花朵之前不会选择任何低价值的花朵，即使在预算极度匮乏的情况下也能保持最优性。
