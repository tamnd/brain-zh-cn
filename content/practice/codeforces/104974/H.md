 ## 解决方案
 ## 问题理解

 我们得到一个字符串集合，每个字符串都附加到从 1 到 N 的不同索引。任务是确定我们是否可以选择四个不同的索引，这样如果我们按顺序连接前两个字符串，我们将得到与按顺序连接其他两个字符串完全相同的字符串。 

当不存在这样的四元组时，输出要么是否定答案，要么是肯定答案以及满足串联相等性的四个不同索引的任何有效选择。 

约束 N ≤ 1000 足够小，可以接受指数的二次工作。 然而，所有字符串的总长度可以达到 10^6，这立即排除了任何为每对显式重复构造串联字符串的解决方案。 构建每个成对串联的简单方法将产生最多 N^2 个字符串，在最坏的情况下，其总长度很容易超过数十亿个字符，这是不可行的。 

第二个隐藏的困难是，即使比较两个串联结果也不是恒定的时间，除非我们使用预先计算的表示。 当考虑到字符串长度时，任何在双循环内重复执行字符串连接和比较的方法都有可能转向三次行为。 

天真的思维的一个典型失败案例是假设可以直接完成对相等性的检查：

 输入：```
4
a
aa
aaa
aaaa
```粗心的方法可能会尝试所有对并直接比较连接的字符串，从而导致重复构造长字符串和不必要的重新计算。 虽然这会传递小情况，但当所有字符串都很长时，它会变得太慢。 

正确的解决方案必须避免具体化串联，而是依赖于支持快速相等检查的紧凑表示。 

## 方法

 蛮力策略很简单。 我们迭代所有有序对 (i, j) 并形成串联字符串 Si + Sj。 然后我们将其与所有其他对 (k, l) 进行比较，确保所有索引都是不同的。 这是正确的，因为它直接对问题定义进行编码。 然而，有 O(N^2) 对，比较两个连接的字符串的成本为 O(L)，其中 L 是它们的组合长度。 在最坏的情况下，如果天真地完成，这会导致大约 O(N^4 * L) 行为，或者最多 O(N^4) 比较，这远远超出了可行的限制。 

关键的观察是我们实际上从来不需要完整的连接字符串。 我们只需要一种方法来唯一地识别它并有效地比较它。 这正是字符串哈希所实现的。 如果每个字符串都经过预先哈希处理，并且我们还预先计算了基数的幂，则可以在恒定时间内根据各个哈希值和长度计算出 Si + Sj 的哈希值。 

一旦每对 (i, j) 都可以映射到固定大小的密钥，问题就变成找到产生相同密钥的两个不同对。 这减少了检测哈希表中的冲突的任务，同时还验证所涉及的索引是否不同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^4·L) | O(N^4·L) | O(1) | O(1) | 太慢了|
 | 基于哈希的配对 | O(N^2) | O(N^2) | O(N^2) | O(N^2) | 已接受 |

 ## 算法演练

 1. 为每个字符串及其长度预先计算滚动哈希。 这使我们能够在恒定时间内查询任何字符串的哈希值和长度。 需要这样做的原因是串联不仅取决于哈希值，还取决于将一个哈希值移位另一个字符串的长度。 
2. 预先计算哈希基的幂，直到最大可能的字符串长度。 这确保了当我们一个接一个地追加字符串时，我们可以在添加第二个哈希之前正确缩放第一个哈希。 
3. 迭代所有有序索引对 (i, j)。 对于每一对，使用以下公式计算串联字符串 Si + Sj 的哈希值：将 Si 的哈希值移位 Sj 的长度，然后添加 Sj 的哈希值。 
4. 使用字典将每个计算的哈希对映射到生成它的第一对索引。 字典键表示整个连接字符串，而无需显式构建它。 
5. 每当字典中已经存在新计算的哈希对时，检索先前存储的哈希对 (k, l)。 检查所有四个索引 i、j、k、l 是否不同。 如果是，我们就找到了有效的解决方案并可以立即输出。 
6. 如果在检查所有对后没有碰撞产生四个不同的索引，则得出不存在有效四元组的结论。 

正确性依赖于相同的串联产生相同的散列这一事实，并且通过足够强的散列方案，在实践中对于竞争性编程约束，冲突可以忽略不计。 独特性检查确保我们不会在两对中重复使用相同的索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    s = [input().strip() for _ in range(N)]

    base = 91138233
    mod = (1 << 64)

    # precompute powers up to total length
    max_len = sum(len(x) for x in s)
    pow_base = [1] * (max_len + 1)
    for i in range(1, max_len + 1):
        pow_base[i] = (pow_base[i - 1] * base) % mod

    # precompute prefix hash and length
    h = []
    L = []
    for st in s:
        cur = 0
        for c in st:
            cur = (cur * base + ord(c)) % mod
        h.append(cur)
        L.append(len(st))

    def concat_hash(i, j):
        return (h[i] * pow_base[L[j]] + h[j]) % mod

    mp = {}

    for i in range(N):
        for j in range(N):
            val = concat_hash(i, j)
            if val in mp:
                k, l = mp[val]
                if len({i, j, k, l}) == 4:
                    print("YES")
                    print(k + 1, l + 1, i + 1, j + 1)
                    return
            else:
                mp[val] = (i, j)

    print("NO")

if __name__ == "__main__":
    solve()
```该解决方案首先读取所有字符串并为每个字符串计算多项式滚动哈希。 每个字符串都被压缩为单个类似整数的值，而不是重复重新计算子字符串的哈希值。 幂数组用于在连接时正确移位哈希值，因为附加字符串相当于将第一个哈希值乘以等于第二个字符串长度的基数幂。 

嵌套循环枚举所有有序对。 这种顺序很重要，因为 Si + Sj 与 Sj + Si 不同，并且两者都是有效的候选者。 该字典存储每个串联哈希的第一次出现。 当出现重复的哈希时，我们立即测试索引是否重叠； 这可以避免返回重复使用相同巧克力类型的无效解决方案。 

使用 64 位模数可以模拟自然溢出算术并保持 Python 中的运算速度，同时使冲突很少发生以满足竞争限制。

 ## 边缘情况

 一个微妙的情况是，多个对映射到相同的串联结果但重用索引。 例如，如果许多字符串相同，则大多数对都会产生相同的串联。 该算法必须确保索引的唯一性，否则它将在两对中错误地重复使用同一元素两次。 

另一种情况是，由于索引重叠，遇到的第一次冲突无效。 字典每个哈希仅存储一对代表性的对。 如果该代表与当前对共享索引，则该代表将被拒绝并继续搜索。 这避免了误报，同时仍然保证最终会发现任何有效的解决方案，因为所有对都被枚举并且每个哈希冲突至少被测试一次。
