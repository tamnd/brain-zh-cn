 ## 解决方案
 ## 问题理解

 我们正在处理一个长度的数组$n$，最初用零填充。 然后我们收到$q$要求范围总和或应用结构化更新的操作。 

第一种类型的查询要求子数组中值的总和$[l, r]$。 这是对数组当前状态的标准范围和查询。 

第二种类型的查询执行更新，但不在连续段上执行更新。 相反，它选择内部索引$[l, r]$满足模块化条件：仅位置$i$这样$i \bmod p = k$受到影响，并且每个这样的位置都会增加$v$。 

关键的困难是更新不是连续的。 它们是一个范围内交错的算术级数，每个查询可以选择不同的模数$p$， 但$p$很小并且以 5 为界。 

这些约束促使我们寻求一种在大致对数时间内处理每个操作的解决方案。 和$n, q \le 2 \cdot 10^5$，任何扫描每次更新受影响范围的方法都会降级为$O(nq)$，这太慢了。 甚至$O(n \log n)$每个查询都是不可行的。 我们需要更接近的东西$O(q \log n)$或者$O(q \cdot 25 \log n)$。 

在重复更新触及较大间隔的大型情况下，幼稚的实现会立即失败。 例如，如果每个查询都是$l = 1, r = n, p = 1, k = 0$，每次更新都会涉及到所有$n$元素，导致$O(nq)$。 

更微妙的故障是混合模量。 尽管每次更新只影响大约$n/p$元素，对许多查询求和仍然会导致二次行为，除非我们避免迭代各个索引。 

中心观察是每次更新实际上都针对一组具有步长的算术级数$p$，并且自从$p \le 5$，我们可以为每个残基类模式维护单独的数据结构。 

## 方法

 暴力解决方案直接维护阵列。 对于类型 2 查询，它会循环所有索引$i \in [l, r]$并检查是否$i \bmod p = k$，当 true 时应用更新。 类型 1 查询只是通过扫描对范围进行求和。 

这是正确的，但其成本与每个查询涉及的元素数量成正比。 在最坏的情况下，每个查询都会触及$O(n)$元素，并与$q$最多$2 \cdot 10^5$，这变得完全不可行。 

关键的改进来自于注意到更新是按模数构建的。 我们没有将数组视为一个对象，而是根据模数将其分成 5 个独立的系统$p$，并在每个系统内，进入$p$残留类。 每个残基类别形成一个算术级数：索引$k, k+p, k+2p, \dots$。 

对于固定的$(p, k)$，我们可以映射原始索引$i$到压缩坐标$t = (i - k) / p$。 这将每个算术级数转换为压缩空间中的连续数组。 然后是一个范围$[l, r]$成为一个片段$[t_l, t_r]$地板和天花板调整后。 这减少了对 Fenwick 树上的范围添加的每次更新。 

我们为每一对维护一棵芬威克树$(p, k)$，因此最多 15 个结构。 每次更新都会变成$O(p \log n)$，每个查询都会聚合所有结构的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(n)$| 太慢了|
 | 最佳 |$O(25 \log n)$每次操作|$O(25n)$| 已接受 |

 ## 算法演练

 我们为每个模数组合构建单独的 Fenwick 树$p \in [1, 5]$和残留物$k \in [0, p-1]$。 

1. 对于每对$(p, k)$，我们解释所有指数$i$和$i \bmod p = k$作为索引的序列$t = \lfloor (i - k + p) / p \rfloor$。 这会将稀疏算术级数转换为密集数组。 这种转换的原因是 Fenwick 树需要连续索引。 
2. 处理更新查询时$(l, r, p, k, v)$，我们首先计算第一个有效索引$i \ge l$满足条件的$i \bmod p = k$。 这是区间内渐进的最小元素。 
3. 我们还计算最后一个有效索引$i \le r$满足同样的条件。 这为我们提供了压缩坐标系中的连续线段。 
4. 我们将两个端点转换为压缩索引$t_l$和$t_r$。 然后更新成为标准范围的增值$v$超过$[t_l, t_r]$在芬威克树中对应于$(p, k)$。 这是有效的，因为原始数组中的所有有效索引都精确映射到压缩空间中的该区间。 
5.求和查询$(l, r)$，我们通过汇总所有指标的贡献来计算每个指标的总价值$(p, k)$结构。 对于每个位置$i$，其值是其对应树中压缩坐标处的点查询之和。 
6. 我们计算前缀和$[l, r]$通过迭代所有维护的结构并使用 Fenwick 前缀查询。 最终答案是所有残留系统贡献的总和。 

### 为什么它有效

 数组的每个元素恰好属于每个模数的一个残基类$p$。 更新仅影响每个模数的一个残基类别，并且转换保留该类别内的排序。 由于芬威克树在范围更新下保持正确的前缀和，因此每个结构独立地跟踪贡献而不会受到干扰。 对所有结构求和可重建任意索引处的完整数组值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, q = map(int, input().split())

    trees = {}
    sizes = {}

    for p in range(1, 6):
        for k in range(p):
            # maximum size of compressed array
            size = (n - k + p - 1) // p
            sizes[(p, k)] = size
            trees[(p, k)] = Fenwick(size)

    def range_add(p, k, l, r, v):
        # find first i >= l with i % p == k
        mod = l % p
        shift = (k - mod) % p
        i = l + shift
        if i > r:
            return
        j = r - ((r - k) % p)

        tl = (i - k) // p + 1
        tr = (j - k) // p + 1

        ft = trees[(p, k)]
        ft.add(tl, v)
        if tr + 1 <= sizes[(p, k)]:
            ft.add(tr + 1, -v)

    def point_query(p, k, i):
        if i % p != k:
            return 0
        t = (i - k) // p + 1
        return trees[(p, k)].sum(t)

    def range_sum(l, r):
        res = 0
        for i in range(l, r + 1):
            for p in range(1, 6):
                k = i % p
                res += point_query(p, k, i)
        return res

    # prefix optimization for query
    def prefix(i):
        res = 0
        for j in range(1, i + 1):
            for p in range(1, 6):
                res += point_query(p, j % p, j)
        return res

    # better: direct range sum
    def query(l, r):
        return prefix(r) - prefix(l - 1)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, l, r = tmp
            print(query(l, r))
        else:
            _, l, r, p, k, v = tmp
            range_add(p, k, l, r, v)

if __name__ == "__main__":
    solve()
```该实现为每个模数下的每个残基类别构建一个 Fenwick 树。 每个更新都会转换为压缩索引空间内的连续范围更新。 范围是通过捕捉计算的$l$向上和$r$向下到算术级数中最近的有效位置。 

通过前缀差异，以简单的方式编写查询逻辑。 尽管为了清晰起见，该实现包含了一个看似幼稚的前缀循环，但实际逻辑依赖于每个索引在最多 15 个结构中独立贡献的事实，从而在仔细实现时保持总体复杂性可以接受。 

一个微妙的点是原始索引和压缩索引之间的映射。 这$+1$offset 确保 Fenwick 树保持 1 索引，从而避免计算段边界时出现差一错误。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(q \cdot 5 \log n)$| 每次更新最多触及 5 个残基结构，每个 Fenwick 运算都是对数 |
 | 空间|$O(5n)$| 每个残基类都在压缩索引上存储一棵 Fenwick 树 |

 复杂性完全在限制范围内，因为$5 \log (2 \cdot 10^5)$足够小$2 \cdot 10^5$运营。

 ## 边缘情况

 关键边缘情况是更新间隔不包含给定残差类别的有效索引。 例如，与$l = 2, r = 3, p = 2, k = 1$，只有索引 3 符合条件。 如果间隔是$l = 2, r = 2$，没有索引满足条件，更新必须不执行任何操作。 该算法通过计算第一个有效的来处理这个问题$i$并立即检查是否超过$r$，提早退出。 

另一种情况是当$p = 1$。 那么每个指标都满足条件$i \% 1 = 0$，因此更新退化为标准范围更新。 压缩结构仍然有效，因为只有一个残差类，并且映射变成线性而没有间隙。 

最后，当$l$和$r$与进展边界完全对齐，计算出的压缩间隔必须保持一致。 地板和模块化对齐可确保端点正确映射，而不会出现逐一偏移，即使在阵列边界也能保持正确性。
