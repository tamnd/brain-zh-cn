 ## 解决方案
 ## 问题理解

 我们在 2D 平面上得到一组不同的点。 任务是计算有多少种方法可以选择四个不同的点，使所有四个点都位于同一条直线上。 

换句话说，我们想要计算索引的四元组$i < j < k < l$其中对应点共线。 这里的共线性意味着所有四个点共享一条线，而不仅仅是每对点形成某种任意对齐。 

输入大小足够小，我们可以考虑每个点的二次或三次推理。 和$n \le 400$， 一个$O(n^3)$该方法已经处于临界状态，但有时在 C++ 中可以接受，而在 Python 中则很严格。 一个$O(n^2)$或者$O(n^2 \log n)$解决方案是理想的。 

一个天真的方向是直接尝试所有四元组，这将是$O(n^4)$， 但$400^4$已经太大并且会超时。 共线性的结构表明我们应该按方向或线标识对点进行分组，而不是枚举所有四元组。 

当许多点位于同一条线上时，会出现微妙的边缘情况。 例如，如果所有点都在一条线上，则答案为$\binom{n}{4}$。 在这种配置中，任何只计算三元组或对而没有正确聚合每行所有点的方法都会少算或多算。 

另一个棘手的情况是垂直线，其中斜率计算可能会因除以零而中断。 例如：```
4
0 0
0 1
0 2
0 3
```正确答案是 1，但基于斜率的浮点分组通常会失败，除非仔细标准化。 

## 方法

 蛮力的想法很简单：枚举每个 4 元组的点并检查它们是否共线。 检查共线性可以通过叉积来完成。 对于四个点，我们可以验证点$A, B, C$共线并且$A, B, D$共线。 这给出了一个$O(1)$检查每四元组，但有$\binom{n}{4}$这样的四元组，大约是$10^9$什么时候$n = 400$。 这太慢了。 

更好的视角是固定一个点$i$并看看与之相关的所有其他点。 每一条经过的线路$i$对应于方向向量。 如果我们按照归一化方向对所有其他点进行分组$i$，然后任意大小的组$k$对应于与以下共线的一组点$i$。 然而，四元组并不以单个枢轴为中心； 有效的四元组可能不包含选定的参考点。 

这引出了关键的观察结果：每组$k$共线点贡献$\binom{k}{4}$有效的四元组，无论如何找到该线。 因此，问题简化为识别所有最大共线组并对它们的贡献求和。 

为了有效地做到这一点，我们考虑所有的点对。 每对定义一条独特的线。 如果我们可以计算出该线上有多少个点，那么我们就可以计算出该线贡献了多少个四元组。 挑战在于避免多次计算同一行。 

我们通过以标准化规范形式对每一行进行编码来解决这个问题。 一条线可以表示为$Ax + By + C = 0$， 在哪里$A, B, C$是从两点导出的整数。 我们规范化这种表示，以便所有等效行映射到相同的键。 然后，我们通过检查所有对并递增来计算每个线表示上有多少个点。 

这给了我们一个从线→点集的地图，通过对处理隐式构造。 最后，对于每一行$k$支撑点，我们添加$\binom{k}{4}$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解四倍 |$O(n^4)$|$O(1)$| 太慢了|
 | 基于对的线路分组 |$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 1. 对于每对无序点$(i, j)$，以标准化整数表示形式计算穿过它们的线。 这确保了同一几何线上的所有对都产生相同的密钥。 
2. 维护一个从线表示到一组点（或增量计数器结构）的字典。 对于每对$(i, j)$，将两个端点添加到与该线关联的集合中。 这确保我们最终恢复每条线上的所有点。 
3. 处理完所有对后，迭代所有存储的线并计算每条线上不同点的数量。 让这成为$k$。 
4. 对于每一行，添加$\binom{k}{4} = \frac{k(k-1)(k-2)(k-3)}{24}$到答案。 
5. 输出累计和。 

步骤 2 使用集合而不是仅仅计算对的原因是，具有许多点的线会生成许多对，并且我们需要对点进行重复删除以恢复该线的真实基数。 

### 为什么它有效

 每个共线四元组恰好位于一条几何线上。 当我们按唯一的线表示对点进行分组时，每个有效的四元组都会被计数一次，因为它恰好属于一个线组。 在包含以下内容的行内$k$点，大小为 4 的所有子集都是有效的并且与排序无关，因此求和$\binom{k}{4}$在所有行上正确枚举所有有效的四元组而不重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import gcd
from collections import defaultdict

def norm_line(x1, y1, x2, y2):
    A = y2 - y1
    B = x1 - x2
    C = A * x1 + B * y1

    g = gcd(gcd(abs(A), abs(B)), abs(C))
    if g:
        A //= g
        B //= g
        C //= g

    if A < 0 or (A == 0 and B < 0):
        A, B, C = -A, -B, -C

    return (A, B, C)

def comb4(k):
    if k < 4:
        return 0
    return k * (k - 1) * (k - 2) * (k - 3) // 24

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    lines = defaultdict(set)

    for i in range(n):
        x1, y1 = pts[i]
        for j in range(i + 1, n):
            x2, y2 = pts[j]
            key = norm_line(x1, y1, x2, y2)
            lines[key].add(i)
            lines[key].add(j)

    ans = 0
    for s in lines.values():
        k = len(s)
        ans += comb4(k)

    print(ans)

if __name__ == "__main__":
    solve()
```核心实现细节是线表示的标准化。 系数$A, B, C$减去它们的最大公约数，以便相同的几何线折叠成相同的字典键。 符号归一化确保同一条线不会以相反的符号表示两次。 

我们每行使用一个集合来避免对来自同一行上的多个对的点进行重复计数。 这很重要，因为每一行都带有$k$点产生$\binom{k}{2}$对，但我们只想要最终的不同点数，而不是对重数。

 ### 示例 1

 输入：```
5

```所有点都位于一条对角线上。

 | ---| ---| ---|
 | (1,2) | 同一条线| {1,2} |

 最终设置大小为 5。 

贡献是$\binom{5}{4} = 5$。 

这证实了一旦所有点都聚集在一条归一化线下，计数就会正确地减少为组合选择。 

### 示例 2

 输入：```
4
1 1
1 2
2 1
2 2
```没有三个点共线，因此没有一条直线包含 4 个点。 

| 配对处理 | 线路键 | 设置尺寸|
 | ---| ---| ---|
 | (1,2) | 垂直| 2 |
 | (1,3) | 水平式 | 2 |

最终答案是0。 

这表明，除非一条线累积了至少 4 个不同的点，否则偶然的配对分组不会影响结果。

 ## 边缘情况

 关键的边缘情况是许多点位于同一条垂直线上。 例如：```
4
0 0
0 1
0 2
0 3
```每对都会产生一条具有相同标准化表示的垂直线。 该集合累加所有四个点，算法计算$\binom{4}{4} = 1$，这与正确答案相匹配。 由于除以零，没有归一化的基于斜率的方法在这里会失败。 

另一种情况是当点形成共享点但并非全部共线的多条重叠线时。 基于集合的分组可确保独立处理每条几何线，并且重叠的贡献不会干扰，因为四元组仅在每个不同的线组内进行计数。
