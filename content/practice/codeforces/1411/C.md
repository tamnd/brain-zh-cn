 ## 解决方案
 ## 问题理解

 我们有一个棋盘，其中没有两个车最初共享一行或一列，因此每个车都位于不同的行和不同的列中。 一次移动允许我们选择一个车并将其沿水平或垂直直线滑动任意距离，只要移动后它仍然不与任何其他车共享行或列。 

目标是重新定位所有车，使它们准确地位于主对角线的单元格上，这意味着每个车必须占据表格的唯一位置$(i, i)$。 由于有$m$车和$m < n$，我们本质上是选择要填充哪些对角线单元格以及如何将初始配置转换为行与列的有效匹配。 

这些约束推动每个测试用例的线性或近线性解决方案。 总和$n$所有测试用例的总和是$10^5$，所以任何比$O(n \log n)$全球面临超时的风险。 需要一种以恒定或接近恒定的时间处理每个车的解决方案。 

一个微妙的困难来自于动作之间的依赖性。 移动一个车可能会释放或阻挡行或列，从而影响另一个车是否可以直接移动到其目标对角位置。 例如，如果两个车形成一个循环，例如$(1,2)$和$(2,1)$，两者都不能在不首先暂时干扰结构的情况下直接进入其对角单元。 

一个小的说明性边缘情况是：

 输入：```
2
2 2
1 2
2 1
```预期输出：```
3
```一种幼稚的贪婪策略，试图将每个车独立地移动到$(x_i, x_i)$失败是因为每个车都阻挡了对方的目标列。 

核心问题是车定义了一个功能图结构，而不是独立的对象。 

## 方法

 思考这个问题的一种强力方法是模拟动作。 在每一步中，尝试移动任何可以无冲突地到达其对角位置的车。 每次移动后重新计算有效性。 这需要重复检查所有车，每次检查都涉及验证行和列的占用情况。 在最坏的情况下，每一步都会触发$O(m)$检查，我们可能有$O(m)$移动，导致$O(m^2)$每个测试用例或更糟，这对于$10^5$总大小。 

关键的观察是每个车都从唯一的行和列开始，因此我们可以将每个车视为将其行映射到其列。 这产生了一种有向结构，其中每一行都指向一列，并且由于列也是唯一的，因此这成为涉及索引的类似排列的结构。 

该结构中的每个连接组件都独立运行。 在一个组件内部，车可以形成循环或链。 关键的事实是，一个周期的长度$k$准确地要求$k$简单意义上的移动，但其中一个移动可以通过使用临时的空闲对角槽来优化，从而将每个组件的成本降低 1。 

这就导致了标准约简：答案是车的数量加上行和列之间的映射形成的有向循环的数量。 

为了准确起见，我们将每只车解释为$(x, y)$作为行的边缘$x$到专栏$y$，我们想把这个结构转换成不动点$i \to i$。 每个循环都需要与其大小相比额外的移动，因为打破循环需要中间自由位置。 

因此，我们构建一个有向图，其中每个节点都是行或列标签，并且每个车创建一个有向连接。 最小移动量等于：$$m + (\text{number of cycles})$$这将问题转化为在函数图中查找周期计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 模拟 |$O(m^2)$|$O(m)$| 太慢了|
 | 图循环分解 |$O(m)$|$O(m)$| 已接受 |

 ## 算法演练

 我们将配置建模为有向图，其中每一行恰好有一个到列的传出边缘。 

1. 对于每一个车$(x, y)$，创建有向边$x \to y$。 这形成了一个函数图，因为没有两个车共享一行或一列，因此每个节点最多有一个传出边和一个传入边。 
2. 我们在所有显示为行或列的节点上维护一个已访问数组。 我们遍历每个具有出边的未访问节点。 
3. 从这样一个节点开始，我们沿着边链前进，直到重新访问一个节点或到达一个没有传出边的节点。 这一遍历收集一个连接的组件。 
4. 在遍历过程中，如果遇到当前路径中已经见过的节点，则检测到循环。 我们在每个这样的周期增加一次周期计数。 
5. 重复此操作，直到处理完所有节点。 
6. 最终答案是 m + \text{cycle_count}。 

这样做的原因是每个连接的组件都是一组依赖关系，其中车在循环中相互阻塞。 每个非循环链都可以在没有超出其大小贡献之外的额外成本的情况下被解决，但是每个循环都会迫使一个额外的移动来打破循环阻塞，然后才能将所有车放置在对角线上。 

### 为什么它有效

 每个车的移动最终对应于将车分配到由其行索引的最终对角位置。 由于每一行都需要一个唯一的列，因此初始映射分解为不相交的组件。 在树状链的组件中，除了移动每个车一次之外，我们可以按顺序解决分配，而不会产生冲突开销。 循环会引入死锁：循环中的任何车都无法在不取代同一循环中的另一个车的情况下直接到达目标。 这会强制进行一次额外的临时搬迁，从而为每个周期提供一次额外的移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    
    nxt = {}
    indeg = {}
    nodes = set()
    
    for _ in range(m):
        x, y = map(int, input().split())
        nxt[x] = y
        indeg[y] = indeg.get(y, 0) + 1
        nodes.add(x)
        nodes.add(y)
    
    visited = set()
    cycles = 0
    
    for start in nodes:
        if start in visited:
            continue
        
        cur = start
        path_index = {}
        step = 0
        
        while cur in nxt and cur not in visited:
            if cur in path_index:
                cycles += 1
                break
            path_index[cur] = step
            visited.add(cur)
            cur = nxt[cur]
            step += 1
        
        for v in path_index:
            visited.add(v)
    
    print(m + cycles)
```该代码构建了从行到列的功能映射的字典表示。 然后，它使用路径行走来探索每个连接的组件。 本地字典跟踪当前遍历中的节点以检测循环。 每次我们检测到同一路径内的重新访问时，我们都会增加循环计数。 

一个微妙的点是节点包括行和列标识符，而不仅仅是车位置。 这可以确保我们正确地遍历组件，即使链条延伸到车的直接位置之外也是如此。 

最终答案加上车的数量和检测到的周期数。

 ## 边缘情况

 一个关键的边缘情况是当车形成单个 2 周期时，例如$(1,2)$和$(2,1)$。 遍历检测到重新访问立即，标记一个周期。 答案就变成了$2 + 1 = 3$，满足临时位移移动的需要。 

另一种边缘情况是结构完全非循环时，例如$(1,2), (2,3), (3,4)$。 遍历永远不会碰到重复的节点，因此循环计数保持为零，并且每个车只贡献一次移动以到达其对角线位置。
