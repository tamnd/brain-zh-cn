 ## 解决方案
 ## 问题理解

 我们被要求找到大于或等于给定数字的最小整数，并且该数字可被所有非零数字整除。 换句话说，如果对于数字中不为零的每个数字 d，数字模 d 等于零，则该数字是公平的。 对于每个测试用例，我们都会得到一个整数 n，并且我们必须生成最小公平数 x，使得 x ≥ n。 

约束允许 n 最大为 10^18 以及最多 1000 个测试用例。 这排除了任何以简单方式单独检查每个整数的算法，因为在合理的时间内迭代一次高达 10^18 的范围是不可能的。 蛮力方法可以适用于小 n，但我们需要更系统的方法来利用数字和整除性的结构。 

非明显的边缘情况包括包含数字 0 的数字，因为 0 不能整除任何东西，但这并不妨碍公平性。 例如，102 是公平的，因为它除以 1 和 2，忽略 0。另一种边缘情况是略低于大数字倍数的数字，例如 n = 282，其中 282 % 8 != 0 但 288 % 8 == 0； 粗心的加一方法可能无法有效地跳转到正确的公平数。 

## 方法

 暴力法在概念上很简单：从 n 开始，递增 1，直到找到一个可以被每个非零数字整除的数字。 这保证了正确性，因为它会检查每个候选者，但在最坏的情况下，如果 n 接近 10^18 并且下一个公平数要大得多，我们将执行 10^18 模运算的顺序，这太慢了。 

高效解决方案的关键见解是，我们可以逐位生成候选值，并跳过不可能产生公平数字的范围。 每个数字都施加了整除性约束。 例如，如果当前数字以 3 结尾，并且它不能被 3 整除，我们可以将该位置递增到下一个 3 的倍数，这可能会影响更高的数字。 在实践中，考虑到位数较少（最多 18 位），一个一位一位移动的简单增量检查实际上对于 1000 个测试用例来说已经足够快了，因为每次检查只需要评估数字，而不是迭代整个数字空间。 我们只对每个候选人执行大约 18 次模检查，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(18 * 增量数) | O(1) | O(1) | 适用于基于数字的优化 |
 | 最佳| O(18 * log(n) * t) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例数t。 
2. 对于每个测试用例，读取 n 并设置候选编号 x = n。 
3. 定义函数`is_fair(number)`它将数字转换为字符串并迭代每个字符。 如果字符不是“0”，则将其转换为整数 d 并检查是否`number % d == 0`。 如果任何检查失败，则返回 False； 否则，返回 True。 
4. 虽然`is_fair(x)`返回 False，将 x 加一。 这肯定会最终终止，因为数字无限增长，并且在任何起点之上都存在一个公平的数字。 
5. 打印 x 作为此测试用例的答案。 

为什么它有效：不变的是我们总是考虑数字 x ≥ n。 这`is_fair`函数直接实现定义，并且递增确保第一个通过检查的数字是最小的。 该算法不会跳过任何潜在的候选者，因此保证了最小性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_fair(number):
    s = str(number)
    for ch in s:
        if ch == '0':
            continue
        d = int(ch)
        if number % d != 0:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = n
        while not is_fair(x):
            x += 1
        print(x)

if __name__ == "__main__":
    solve()
```功能`is_fair`正确处理零数字并确保所有非零数字都能整除该数字。 主循环递增，直到实现公平。 使用`sys.stdin.readline`确保最多 1000 个测试用例的快速输入。 加 1 是安全的，因为可以保证正确评估每个候选者，并且数字最多只有 18 位数字。

 对于输入 282：

 | x| 数字| 可以被全部整除吗？ |

 | 286 | 286 2、8、6 | 286% 8！= 0 |

 | x| 数字| 可以被全部整除吗？ |

 | 1234568040 | 已检查数字 | 可被所有非零数字整除 |

 该算法返回 1234568040，展示了对大数和零的正确处理。

 ## 边缘情况

 对于 n = 101，算法设置 x = 101。数字为 1,0,1。 101 % 1 == 0, 101 % 1 == 0。零被忽略。 由于所有非零数字都能整除 101，因此 x = 101 是公平的，因此返回。 增量循环不执行，确认零和最小值的正确处理。 

对于 n = 282，第一个候选失败，因为 282 % 8 != 0。递增直到 288 可确保该数字满足所有整除条件。 这证实了略低于一位数的倍数的数字已正确调整，而不会跳过有效的候选者。
