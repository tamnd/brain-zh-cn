 ## 解决方案
 ## 问题理解

 我们收到了几条聊天消息。 每条消息都是一个包含小写英文字母和字符的字符串`)`。 

如果连续发送的次数超过该消息的数量，则该消息被认为是错误的`)`字符串末尾的字符严格大于其之前的所有剩余字符的数量。 

例如，在字符串中`ab))))`，末尾有 4 个右括号，前面有 2 个其他字符。 自从`4 > 2`，消息不好。 

对于每个测试用例，我们必须确定消息是否错误并打印`"Yes"`或者`"No"`。 

限制非常小。 每个字符串的长度最多为 100，并且最多有 100 个测试用例。 即使算法多次扫描每个字符也足够快了。 目标不是优化，而是正确识别右括号的后缀并将其大小与字符串的其余部分进行比较。 

一个容易犯的错误就是计算全部`)`字符串中的字符，而不仅仅是末尾的连续字符。 

考虑：```
7
a)b)c))
```连续的后缀`)`字符的长度为 2。剩余部分的长度为 5。因为`2 > 5`为假，则答案为`"No"`。 

一个重要的解决方案`)`会得到 4 并错误地得出该消息不好的结论。 

另一种边缘情况是整个字符串由右括号组成。```
3
)))
```后缀长度为3，剩余长度为0。由于`3 > 0`，答案是`"Yes"`。 

第三个微妙的情况是平等。```
6
abc)))
```后缀长度为3，剩余长度也是3。定义要求严格更大的计数，所以正确答案是`"No"`。 

粗心的实现使用`>=`会在这里失败。 

## 方法

 暴力解决方案将首先识别字符串的每个可能的后缀，检查它是否完全由`)`字符，然后计算其长度。 由于字符串长度最多为 100，因此即使是这种低效的方法仍然可以在限制内轻松运行。 

问题结构给出了更简单的观察。 仅最后一个连续块`)`很重要。 该块之前的所有内容都属于“剩余字符”计数。 

我们可以从字符串的末尾开始计算有多少个连续的后缀，而不是检查许多后缀`)`字符出现。 当我们遇到任何其他角色时，我们就会停下来。 该计数正是语句所需的后缀大小。 

如果后缀包含`cnt`括号，那么剩下的部分包含`n - cnt`人物。 当出现以下情况时，该信息就很糟糕：```
cnt > n - cnt
```暴力方法之所以有效，是因为它最终找到了结束块，但向后扫描一次会直接给出相同的信息。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取长度`n`和字符串`s`。 
2. 从字符串的最后一个字符开始向左移动。 
3. 统计有多少个连续的`)`字符出现在末尾。 Store this count in`cnt`。 
4. 当出现与以下字符不同的字符时立即停止`)`遇到，因为只有最后一个连续块很重要。 
5. 计算剩余字符数：`n - cnt`。 
6. 如果`cnt > n - cnt`， 打印`"Yes"`。 
7. 否则，打印`"No"`。 

### 为什么它有效

 错误消息的定义仅取决于字符串末尾的连续右括号。 通过向后扫描，我们可以准确计算出该数量。 

不属于该结束块的每个字符都是字符串剩余部分的一部分。 因此`n - cnt`正是声明中提到的剩余字符数。 

该算法直接检查定义中的条件，因此其答案始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        cnt = 0
        i = n - 1

        while i >= 0 and s[i] == ')':
            cnt += 1
            i -= 1

        if cnt > n - cnt:
            print("Yes")
        else:
            print("No")

solve()
```实现完全遵循算法。 

变量`cnt`存储由连续的后缀组成的长度`)`人物。 循环从最后一个索引开始，并在当前字符出现时继续向左移动`)`。 

一旦出现不同的字符，后缀就结束了，不需要继续扫描。 剩余字符数很简单`n - cnt`。 

最终比较使用`>`而不是`>=`。 这个细节至关重要，因为相同的计数并不会使消息变得糟糕。 

由于字符串长度非常小，因此这里不存在整数溢出和内存问题。

 ## 边缘情况

 ### 两部分之间相等

 输入：```
1
6
abc)))
```向后扫描计数`cnt = 3`。 剩下的字符是`6 - 3 = 3`。 

比较就变成：```
3 > 3
```这是错误的，所以输出是：```
No
```这证实了条件严格更大。 

### 整个字符串由括号组成

 输入：```
1
3
)))
```扫描到达字符串的开头并计数`cnt = 3`。 

其余部分包含：```
3 - 3 = 0
```自从：```
3 > 0
```输出是：```
Yes
```该算法自然地处理这个问题，没有任何特殊情况。 

### 括号出现在字符串的前面

 输入：```
1
7
a)b)c))
```从末尾开始扫描仅计算最后一个块：```
cnt = 2
```前面的括号将被忽略，因为它们不是结束后缀的一部分。 

剩余长度为：```
7 - 2 = 5
```自从：```
2 > 5
```为假，则答案为：```
No
```这验证了算法遵循问题的确切定义，而不是计算字符串中的所有括号。
