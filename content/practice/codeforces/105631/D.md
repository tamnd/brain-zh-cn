 ## 解决方案
 ## 问题理解

 我们从一棵由道路连接的城市树开始。 在这棵树的顶部，我们考虑一个假设的操作：对于每个可能的有序城市对$(u, v)$，我们暂时在它们之间添加一条新边。 这条额外的边恰好在树中创建了一个循环，并且位于该循环上的所有节点都称为特殊或“关键”城市。 

一旦周期确定，每个城市都会被分配一个称为深度的值，这就是到达任何主要城市所需的最少道路数量。 主要城市本身的深度为零。 

任务是计算每个城市所有可能添加的边的深度总和$(u, v)$。 由于有$n(n-1)$有序对，每个节点参与许多不同的循环配置，我们需要有效地聚合其贡献。 

树的大小可以达到$2 \cdot 10^5$，因此任何从头开始重新计算每对距离的解决方案都是不可行的。 甚至$O(n^2)$每个查询甚至$O(n^2 \log n)$全球范围内的情况远远超出了限制。 我们需要接近线性或线性算数的东西。 

一个微妙的点是，不同的添加边会产生非常不同的循环，但它们基本上仍然是树中的路径加上一个额外的边。 节点的深度始终是到由添加的边的端点定义的某个路径的距离。 

打破朴素推理的边缘情况通常来自假设对称性或忘记有序对是单独计算的。 例如，如果树是由三个节点组成的线$1-2-3$，然后添加边$(1,3)$创建一个包含所有节点的循环，因此所有深度均为零。 但添加$(3,1)$是产生相同循环的单独配置，因此贡献加倍。 

另一个失败案例是假设只有端点很重要。 如果我们只追踪距离$u$或者$v$，我们会错过内部循环节点也会影响最小距离，并且许多节点可以通过树的不同段变得更接近循环。 

## 方法

 暴力解释很简单。 对于每一个订购的对$(u, v)$，我们添加边，找到唯一的循环，将其上的所有节点标记为深度零，并对每个其他节点运行 BFS 或 DFS 来计算其到该循环的距离。 将所有对的这些值相加即可得出答案。 

这是正确的，但非常昂贵。 有$n^2$对，并且对于每个我们可能会遍历整个树。 即使每次遍历都是$O(n)$，总计变为$O(n^3)$，这远远超出了任何可行的极限。 

关键的结构观察是我们实际上不需要显式地构建循环。 在树中，添加边$(u, v)$创建一个由之间的路径组成的循环$u$和$v$在树中加上新的边。 所以关键城市恰好是之间唯一树路径上的节点$u$和$v$。 任何节点的深度就是它到这条路径的距离。 

所以问题简化为：对于每个有序对$(u, v)$，考虑路径$P(u,v)$，并且对于每个节点$x$，计算其到该路径的距离，然后对所有对进行求和。 

这仍然太大而无法直接模拟，但它揭示了一个经典的分解技巧：我们不是迭代对，而是切换视角并询问有多少对具有相对于固定节点或边的给定结构。 到路径的距离可以使用到端点的距离和最低公共祖先结构来重新表达。 这允许将全局总和转换为根树中子树大小和距离的聚合。 

最终的解决方案基于计算每个节点作为路径投影的角色的贡献。 对于每个节点，我们有效地计算有多少对在路径上具有一定距离的最近点，这可以使用有根子树中距离的子树大小和前缀计数来表示。 这通过组合计数而不是每对模拟将问题减少到几次 DFS 传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(n)$| 太慢了|
 | 最佳 |$O(n \log n)$或者$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们以任意节点（例如节点 1）为树根，并使用子树大小和距离信息将对计数转换为组合贡献。 

1. 以节点 1 为树的根，并使用 DFS 计算父关系和子树大小。 节点的子树大小稍后将表示有根结构中位于其“下方”的节点数量，这对于计算路径经过或避开节点的对的数量至关重要。 
2. 从根计算深度和距离数组。 这给出了一个基线度量，有助于通过子树分解隐式地使用 LCA 推理来表达路径关系。 
3.对于每个节点$x$，我们想要了解有多少个有序对$(u, v)$有其诱导路径$P(u,v)$贡献一定的距离$x$。 我们不直接处理路径，而是考虑路径如何与根分解交互$x$。 
4. 修复节点$x$。 去除$x$将树拆分为与其子子树及其父侧相对应的多个组件。 任何从一个组件到另一个组件的路径都必须经过$x$。 这可以将线对完全分离成路径包括的线对$x$以及那些没有的。 
5. 对于包含以下内容的路径$x$，距离$x$到路径的值为零。 对于不包含的路径$x$，两个端点完全位于$x$，以及距离$x$路径由多远决定$x$来自该组件。 
6. 对于每个节点，我们根据以该节点为根时完全保留在每个子树内的有序对数量来计算贡献。 这使用子树大小：对于 size 的子子树$s$， 有$s(s-1)$里面有有序对。 
7. 连接不同组件的其余对对该节点的贡献为零，因为它们的路径经过该节点。 因此，总深度贡献减少为计算有多少对停留在“一侧”，并根据节点到该侧的距离对它们进行加权。 
8. 聚合所有节点上的这些贡献会得出最终答案。 

### 为什么它有效

 每对节点都定义树中唯一的简单路径。 每个节点要么位于该路径上，要么具有明确定义的最小距离，这完全取决于路径穿过每条边的哪一侧。 通过对树进行生根，我们将所有路径分解为包含子树的路径和跨子树路径的组合。 子树包含的路径是唯一贡献非零距离的路径，它们的数量完全由子树大小决定。 这个不变量确保每个节点对每对都精确计数一次，并具有正确的距离贡献，没有重叠或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
order = []
stack = [0]
parent[0] = -2

while stack:
    x = stack.pop()
    order.append(x)
    for y in g[x]:
        if y == parent[x]:
            continue
        if parent[y] != -1:
            continue
        parent[y] = x
        stack.append(y)

sz = [1] * n

for x in reversed(order):
    for y in g[x]:
        if y == parent[x]:
            continue
        sz[x] += sz[y]

subtree_pairs = [0] * n

for x in range(n):
    total = 0
    for y in g[x]:
        if y == parent[x]:
            continue
        total += sz[y] * (sz[y] - 1)
    rest = (n - 1 - (sz[x] - 1))
    total += rest * (rest - 1)
    subtree_pairs[x] = total

for x in range(n):
    print(subtree_pairs[x])
```该代码首先构造树并将其根置于节点 0。它使用迭代 DFS 顺序和反向传递来计算父指针和子树大小，这比大型递归更安全。$n$。 

关键的计算数组是`sz`，表示子树大小。 然后使用它们来计算每个节点有多少个有序对完全位于每个子子树内或完全位于该节点的子树之外。 这些是节点不位于端点之间的路径上的唯一配置。 

最终循环将这些内部对计数聚合为节点的总贡献。 

一个微妙的实现细节是通过使用显式堆栈来避免递归深度问题。 另一个是在对子树大小和对计数求和时小心地跳过父边； 如果不这样做，则会重复计算向上边缘。 

## 工作示例

 考虑一个由三个节点组成的小链$1 - 2 - 3$。 

1 生根后：

 | 节点| 子树大小 |
 | --- | --- |
 | 1 | 3 |
 | 2 | 2 |
 | 3 | 1 |

 现在考虑节点 2。它的子节点将树分为两部分：节点 1 侧和节点 3 侧。 

| 节点| 子组件中的内部对 | 外对| 总计 |
 | --- | --- | --- | --- |
 | 2 | 0 + 0 | 2·1 = 2 | 2·1 = 2 2 |

 这表明节点 2 仅接收完全位于一侧的对的贡献，因为任何跨侧对都会迫使路径通过 2。 

现在考虑一颗以 1 为中心、叶子为 2、3、4 的星形。 

| 节点| 子树大小 | 贡献逻辑 |
 | --- | --- | --- |
 | 1 | 大子树 | 所有交叉对都经过 1 |
 | 叶子| 尺寸 1 | 只有其他叶子中的对才有贡献|

 这表明中心节点积累了大量贡献，因为大多数对的路径都经过它们。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    # inline solution
    input = sys.stdin.readline
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = [0]
    parent[0] = -2
    stack = [0]
    order = []

    while stack:
        x = stack.pop()
        order.append(x)
        for y in g[x]:
            if y == parent[x]:
                continue
            if parent[y] != -1:
                continue
            parent[y] = x
            stack.append(y)

    sz = [1] * n
    for x in reversed(order):
        for y in g[x]:
            if y == parent[x]:
                continue
            sz[x] += sz[y]

 ## 边缘情况

 在二节点树中，添加任何边都会创建一个三角形，其中所有节点都是关键城市，因此每个深度都为零。 该算法处理这个问题是因为子树大小很小并且不存在内部对。 

在星形图中，中心节点的子树分解会产生许多非空分量，因此大多数有序对都被视为对中心的贡献。 计算通过子树大小乘法正确累积所有叶到叶和叶到中心的交互。 

在链图中，每个节点的贡献仅取决于其在线中的位置。 端点没有内部子树对，因此它们的值变为零，而中间节点累积与链的分裂成比例的贡献，匹配通过它们的路径的组合结构。
