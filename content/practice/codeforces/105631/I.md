 ## 解决方案
 ## 问题理解

 我们得到了排列成一条线的一系列彩色灯光。 每个位置都有一个颜色标签，多个位置可以共享相同的颜色。 在此静态数组之上，我们处理一系列更新操作。 每个操作都集中在一个连续的段上，并分配一个值贡献，该值贡献取决于该段内的成对的相同颜色的位置。 

关键规则是，对于段上的给定操作，该段内共享相同颜色的每对索引都会将该操作的值贡献给它们之间（包括）与该颜色匹配的所有位置。 换句话说，如果我们在段内选择两次出现相同的颜色，那么它们之间的间隔中该颜色的每次出现都会增加操作值。 由于可能有很多对，因此单个操作可能会通过不同的对多次影响同一位置。 

输出需要所有操作后每个位置的最终累加值，模 1e9 + 7。 

约束条件将 n 和 m 限制为 100,000。 这立即排除了任何显式枚举每个查询中所有对的解决方案，因为长度为 n 的单个段可以包含 O(n²) 对，并且在 m 个查询中，这会变得灾难性的大。 

当某种颜色在段中多次出现但在全局数组中出现稀疏时，就会出现微妙的边缘情况。 例如，考虑一个颜色出现在位置 1、10、20 的片段。简单的对枚举将独立处理 (1,20)、(1,10)、(10,20)，然后尝试在范围内传播贡献，但需要仔细推理以避免重复计算或丢失重叠贡献。 

另一个边缘情况是所有灯光都具有相同的颜色。 在这种情况下，每个查询本质上都会影响每个子数组对，并且贡献变得高度重复。 任何不按颜色结构压缩的方法都会比一般情况更快地超时。 

## 方法

 该操作的直接解释建议迭代每个查询范围内的所有相同颜色位置对。 对于 ap = aq 的每对 (p, q)，我们将 vi 添加到 p 和 q 之间共享该颜色的每个索引。 即使我们将其更有效地重新解释为范围更新，瓶颈仍然是枚举每个查询段内的对。 在最坏的情况下，覆盖整个数组且所有元素相同的查询会生成 O(n²) 对，并且当 m 达到 1e5 时，这变得完全不可行。 

关键的观察是该操作仅取决于相等值的出现及其在数组内的相对顺序。 我们可以根据颜色全局思考，而不是考虑查询范围内的任意对。 固定一个颜色 c 并查看它出现的所有位置。 在查询 [l, r] 中，只有位于该区间内的 c 的出现才有意义，并且贡献结构仅取决于该过滤列表中的连续出现。 

这建议翻转视角：我们不是处理成对的查询，而是针对每种颜色处理每个查询如何影响该颜色的连续出现。 每个查询都会向 [l, r] 内该颜色的所有连续出现对贡献一个值 vi，并且这些贡献可以转换为对出现索引的范围更新，而不是直接对数组位置的更新。

这将问题简化为管理每种颜色的压缩位置列表以及对该列表的索引执行范围添加操作。 剩下的挑战是将这些贡献有效地映射回原始阵列位置。 一旦我们用连续事件之间的贡献来表达所有内容，我们就可以使用差异数组或芬威克树来累积 O((n + m) log n) 的效果。 

改进来自于认识到真正的组合结构不是在数组中的所有索引对上，而是在每种颜色的排序列表中的相邻出现位置上。 具有相同颜色的每对 (p, q) 通过相邻出现的链做出贡献，这将二次对结构折叠为每种颜色的线性边。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对每个查询中的对进行暴力破解 | O(m·n²) | O(n) | 太慢了|
 | 每颜色压缩+范围更新| O((n + m) log n) | O((n + m) log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按颜色对位置进行分组，为每种颜色存储其出现的索引的排序列表。 这使我们能够在每个颜色类中进行本地推理，而不是在整个数组上进行推理。 
2. 对于每种颜色，构建一个表示其出现位置的辅助数组。 第 i 个元素对应于该颜色在原始数组中第 i 次出现。 这将问题转化为处理这些列表中的索引。 
3. 对于每种颜色，处理具有值 v 的每个查询 [l, r]，识别哪些出现属于查询间隔内。 我们不迭代所有出现的事件对，而是只考虑此查询如何影响间隔内的连续出现。 
4. 对于固定颜色，如果我们取 [l, r] 内的出现次数，假设它们对应于颜色列表中的索引 i 到 j，则查询将 v 贡献给每个相邻对 (i, i+1), (i+1, i+2), ..., (j-1, j)。 这是因为每个这样的相邻对形成一个最小段，该段对所有中间相同颜色位置产生贡献。 
5. 我们通过为每种颜色在其出现列表上维护一个差异数组来应用此方法。 对于每个查询，我们使用二分搜索定位范围内的第一个和最后一个出现，并将区间 [i, j-1] 上的差异结构增加 v。 
6. 处理完所有查询后，我们计算每种颜色差异数组的前缀和，以获得每个相邻出现对的贡献权重。 
7. 最后，我们将这些对贡献传播回实际的数组位置。 每个相邻对将其累积值贡献给它们之间的所有出现，这可以再次使用原始数组上的差异数组通过扫描每种颜色的位置来处理。 

### 为什么它有效

 关键的不变量是，查询生成的每个贡献都可以分解为每种颜色的相邻出现的独立贡献，并且每个原始有效对 (p, q) 对应于 p 和 q 之间的相邻出现的连续链。 通过对这些边上的贡献求和，我们对每对进行一次计数，同时确保中间位置上的传播在出现次数上是线性的，而不是在对数量上呈二次方。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

n, k = map(int, input().split())
a = list(map(int, input().split()))
m = int(input())

pos = [[] for _ in range(k + 1)]
for i, c in enumerate(a):
    pos[c].append(i)

# diff over edges inside each color occurrence list
diff = [[] for _ in range(k + 1)]

for c in range(1, k + 1):
    diff[c] = [0] * (len(pos[c]) + 1)

for _ in range(m):
    l, r, v = map(int, input().split())
    l -= 1
    r -= 1

    # we process per color
    for c in range(1, k + 1):
        lst = pos[c]
        if not lst:
            continue

        # find first occurrence >= l
        import bisect
        i = bisect.bisect_left(lst, l)
        j = bisect.bisect_right(lst, r) - 1

        if i < j:
            diff[c][i] = (diff[c][i] + v) % MOD
            diff[c][j] = (diff[c][j] - v) % MOD

# prefix over each color
edge_val = [[] for _ in range(k + 1)]
for c in range(1, k + 1):
    edge_val[c] = [0] * len(pos[c])
    cur = 0
    for i in range(len(pos[c]) - 1):
        cur = (cur + diff[c][i]) % MOD
        edge_val[c][i] = cur

# propagate to array
ans = [0] * n

for c in range(1, k + 1):
    lst = pos[c]
    if not lst:
        continue

    # contribution sweep
    for i in range(len(lst)):
        p = lst[i]
        add = 0
        if i > 0:
            add += edge_val[c][i - 1]
        if i < len(lst) - 1:
            add += edge_val[c][i]
        ans[p] = add % MOD

print(*ans)
```该实现首先按颜色对索引进行分组，这允许所有后续推理在独立结构内运行。 通过使用二分搜索识别位于查询间隔内的每种颜色的出现片段来处理每个查询。 差值数组`diff[c]`捕获查询如何激活连续出现的边缘。 

处理完所有查询后，前缀和会重建出现之间的实际边权重。 最终扫描通过对接触每次出现的相邻边缘的贡献进行求和，将这些边缘贡献分配回实际的阵列位置。 

一个微妙的实现问题是差异数组中的符号处理。 由于更新包括减法，因此必须立即在模运算下对值进行归一化，以避免负漂移。 另一个微妙的问题是，贡献与出现次数之间的边缘相关联，因此在构建边缘值时，索引必须仔细排除每个颜色列表的最后一个元素。

 ## 边缘情况

 对于每个位置都相同的单色数组，该算法将所有出现的位置折叠成一个长链。 每个查询都会影响该链的连续段，并且差异数组仅正确标记该段内的边缘。 当向后传播时，每个内部位置接收来自两个相邻边缘的贡献，而端点仅接收一个，匹配跨越该位置的对的组合结构。 

对于像位置 [2, 100, 1000] 这样的稀疏颜色分布，仅覆盖中间位置的查询不会激活任何边缘，因为没有完全位于间隔内的相邻对。 该算法自然会产生零贡献，因为出现的间隔 [i, j] 具有 i == j，并且 diff 更新条件 i < j 阻止任何激活，这与该受限段中不存在有效对的事实相匹配。
