 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例都描述一个整数序列，其中每个元素代表一段音乐的“节奏值”。 还有一个固定的下界L。我们可以独立地减少每个元素，但永远不能低于L。经过此修改，整个片段的美感被定义为所有最终值的按位或。 

任务是在允许的范围内为每个元素选择新值，以便最终的 OR 变得尽可能大。 

重述该问题的一个有用方法是：每个位置 i 给我们一个可控的值区间 [L, ai]。 我们必须从每个区间中选择一个数字，并且我们希望所有选定数字的按位或最大化。 

约束很大：测试用例的元素总数达到 2×10^5，值达到 2^60。 这立即排除了尝试所有分配甚至尝试每个元素的所有值组合的任何解决方案。 任何即使每个测试用例都是二次的也太慢了。 

操作的结构也很重要。 OR 运算是单调的，即一旦某个位在任何选定值中变为 1，它在最终答案中将保持为 1。 因此，真正的问题是决定哪些位可以出现在至少一个选定的数字中。 

一些边缘情况值得指出。 

如果所有 ai 等于 L，则每个区间都会折叠为一个点，并且答案只是所有 ai 的或，因为不可能进行修改。 

如果 L 为 0，则每个区间都变为 [0, ai]，并且我们可以自由选择 ai 以内的任何值。 这是最灵活的场景，但仍然受到上限的限制。 

当间隔很紧时会出现更微妙的情况，例如 L = 8 且 ai = 9。即使 ai 很小，间隔也可能太短而无法“达到”所需的位模式。 这就是“我们总是可以独立调整位”之类的天真的推理的突破点。 

## 方法

 暴力视角首先考虑每个元素：对于每个 ai，我们可以选择 [L, ai] 中的任何 bi。 如果我们枚举所有选择，我们将计算 OR 并取最大值。 这显然是 n 中的指数，因为每个元素都贡献了一系列可能性，甚至采样值也会导致组合爆炸。 

更结构化的蛮力会尝试贪婪地决定每个 bi，但即便如此，我们也需要考虑元素之间的依赖关系，因为 OR 将所有选择耦合在一起。 尝试所有位贡献子集很快就会导致 O(2^60) 式推理，这是不可能的。 

关键的观察是我们永远不需要直接推理完整的数字。 我们只关心每一位是否可以出现在至少一个选定的值中。 因此，我们将视角从价值转向比特。 

固定位位置 B. 我们问一个更简单的问题：我们是否可以选择至少一个元素 i 并在 [L, ai] 中为其分配一个值，使得第 b 位为 1？ 

如果是，那么这一点有助于最终答案。 如果否，则该位不可能，结果必须为 0。 

因此，问题归结为检查使每个位出现在某处的可行性。 

现在二进制数的结构变得很重要。 对于固定位 b，该位在整数上的模式是周期性的：大小为 2^(b+1) 的块，前半部分为 0，后半部分为 1。这种周期性结构允许我们确定区间 [L, ai] 是否包含任何位 b = 1 的数字。 

对于给定的 i，位 b 根本不能出现在 [L, ai] 中的唯一方法是，如果整个间隔位于位 b 始终为 0 的区域内。当两个端点都落入周期块的同一“零半”内并且不交叉到“半”时，就会发生这种情况。

因此，对于每一位，我们只需要检查是否存在至少一个 i ，其区间没有完全陷入仅零区域内。 如果存在这样的i，则该位是可以实现的。 

这将问题简化为 O(n·60)，这很容易足够快。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 对于从 0 到 59 的每个位位置 b，我们最初假设该位不能成为最终答案的一部分。 
2. 对于固定位 b，我们计算块大小 P = 2^(b+1)。 这会将所有整数划分为重复段，其中每个段由零半 [0, 2^b - 1] 和二分之一 [2^b, 2^(b+1) - 1] 组成。 
3. 对于每个元素 i，我们检查区间 [L, ai] 是否完全包含在位 b 的零半区域内。 当 L 和 ai 位于同一个块中（即 L // P == ai // P）并且都位于该块的前半部分（即 L % P < 2^b 和 ai % P < 2^b）时，这是正确的。 发生这种情况时，我们可以从此区间中选择的每个值的位 b 都等于 0，因此该元素无法对设置位 b 做出贡献。 
4. 如果我们找到至少一个索引 i 使该条件不成立，则 [L, ai] 中存在激活位 b 的值，因此我们将位 b 标记为可实现。 
5. 处理完该位的所有元素后，如果可以实现，我们将在答案中添加 2^b。 
6. 对所有位重复并输出累加的 OR 值。 

检查单个间隔背后的原因是 OR 仅需要每位成功的贡献者。 我们永远不需要为同一个位协调多个元素。 

### 为什么它有效

 每个元素提供一个连续的可选值区间。 对于固定位，唯一的障碍是该间隔完全包含在该位始终为零的区域中。 如果即使一个元素具有该位集的可达值，我们也可以将该值分配给该元素，并将任意有效值分配给其他元素，而不会影响可行性。 因此，位独立性成立，并且检查每个位的存在性足以构造最佳 OR。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, L = map(int, input().split())
        a = list(map(int, input().split()))
        
        ans = 0
        
        for b in range(60):
            P = 1 << (b + 1)
            half = 1 << b
            
            ok = False
            
            for x in a:
                if (x - L) >= 0:
                    # check if there exists a way to get bit b = 1 in [L, x]
                    # impossible only if both endpoints lie in zero half of same block
                    if (L // P == x // P) and (L % P < half) and (x % P < half):
                        continue
                    ok = True
                    break
            
            if ok:
                ans |= (1 << b)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码反映了逐位可行性测试。 对于每一位，它都会扫描所有元素，直到找到一个可以生成该位集的值的区间。 一旦找到这样的元素，该位就被确认，并且我们提前停止以提高效率。 

关键的实现细节是每比特的区间分类：将数字分组为大小为 2^(b+1) 的块，并检查两个端点是否落在同一块的零部分。

 ## 边缘情况

 一种重要的边缘情况是当 L 和 ai 落入高位的同一零位段内时。 在这种情况下，不可能从该元件激活该位。 该算法正确地处理了这个问题，因为两个端点都落在同一个块中，并且都位于中点下方，从而触发跳过条件。 

另一个边缘情况是当 L = ai 时。 这里每个间隔退化为一个点，因此可行性检查总是失败，除非该固定值已经包含该位。 该算法自然地简化为检查原始值的“或”。 

第三种情况是当L非常小时而ai非常大时。 那么大多数位都是可以轻松实现的，因为每个间隔跨越多个周期性块，因此每个间隔中至少有一个值将激活任何给定位。 扫描快速找到有效元素并设置所有低位和中位，与预期的最大 OR 匹配。
