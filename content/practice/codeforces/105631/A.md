 ## 解决方案
 ## 问题理解

 我们被赋予了多个独立的场景。 在每个场景中，都有三种类型的气球：标记为 S 的气球、标记为 Y 的气球和标记为 U 的气球。我们希望从这些气球中重复组装称为 SYSU 集的相同装饰束。 

有效的 SYSU 集使用固定的字母模式：它需要两个 S 气球、一个 Y 气球和一个 U 气球。 每个气球最多只能使用一次，因此一旦将气球分配给一个集合，就不能在另一个集合中重复使用。 

对于每个测试用例，任务是确定可以从 S、Y 和 U 气球的可用计数中形成多少个完整的 SYSU 集。 

限制很小：最多 100 个测试用例，每个测试用例最多 10,000 个。 这立即表明，任何在每个测试用例中运行恒定时间的解决方案都是足够的。 即使每个测试用例的 O(x + y + z) 仍然微不足道，但我们应该致力于直接算术解决方案。 

在此类问题中，一个常见的错误是假设每个字母独立贡献，而不考虑 S 的双倍要求。另一个微妙的问题是忘记所有三个资源必须同时可用，因此限制因素始终是最受限制的成分。 

边缘情况大多是退化计数。 如果 x、y 或 z 中的任何一个为零，则无法形成集合。 另一个有趣的边界是当 S 丰富但 Y 或 U 较小时，反之亦然。 例如，如果 x = 100、y = 1、z = 1，则即使 S 看起来很多，也只能有一组。 相反，如果 y 和 z 很大但 S 很小，S 就会成为瓶颈，因为每组需要两次。 

## 方法

 思考这个问题的一种蛮力方法是逐个模拟搭建套件。 对于每次尝试，我们都会检查是否至少有两个 S 气球、一个 Y 气球和一个 U 气球可用。 如果是这样，我们减去这些计数并增加我们的答案。 我们重复直到我们不能再形成一组。 

这种方法是正确的，因为它直接遵循流程的定义。 然而，它的性能取决于形成的集合的数量。 在最坏的情况下，如果 x、y、z 很大，我们可能会为每个测试用例重复减去 10,000 次。 对于 100 个测试用例，这在这里仍然可以接受，但这是不必要的，并且隐藏了问题的真实结构。 

关键的观察结果是，每个集合都消耗固定资源，与之前的选择无关。 跨步骤没有耦合或重新排列的好处。 这意味着最大组数完全取决于每个资源可以支持其所需使用的次数。 S 通过 x // 2 限制我们，Y 通过 y 限制我们，U 通过 z 限制我们。 最终答案必须同时满足所有约束，因此它是这三个独立能力中的最小值。

 ## 算法演练

1. 对于每个测试用例，读取值 x、y 和 z。 这些分别代表 S、Y 和 U 气球的可用数量。 目标是计算这些固定电源可以形成多少个完整的 SYSU 捆绑包。 
2. 计算 S 气球单独可以支撑多少束。 由于每个束需要两个 S 气球，因此 S 的可能贡献数量为 x 除以 2（使用整数除法）。 这表示在不考虑其他约束的情况下，S 可以维持的最大集合数。 
3. 将 y 视为集合数的直接上限。 每组恰好需要一个 Y 气球，因此组数不能超过 y。 
4. 将 z 视为另一个直接上限。 每组恰好需要一个 U 形气球，因此 z 也限制了可能组的总数。 
5. 最终答案是这三个值中最小的一个，因为每个有效集必须同时满足所有三个约束，超过任何一个资源都会导致进一步构造变得不可能。 

### 为什么它有效

 每个SYSU集独立且不可逆地消耗资源。 这意味着形成k个集合的可行性仅取决于所需总资源，即2k个S气球、k个Y气球和k个U气球是否可用。 因此，可行性的条件是 2k ≤ x、k ≤ y 和 k ≤ z。 满足所有不等式的最大 k 恰好是 x // 2、y 和 z 中的最小值，这保证了最优性而不需要模拟。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        x, y, z = map(int, input().split())
        out.append(str(min(x // 2, y, z)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接将数学可行性条件转化为代码。 整数除法 x // 2 捕获了 S 个气球的配对要求。 取三个计算限制中的最小值会同时强制执行所有约束。 通过列表和连接使用缓冲输出可以避免重复的 I/O 开销，尽管在这种规模下这并不是绝对必要的。

 输入：

 这演示了 Y 是限制因素的情况。 尽管 S 和 U 足以容纳更多组，但仅存在 2 个 Y 气球，将总数限制为 2 个完整的气球束。

 输入：

 这里 S 成为瓶颈，因为每组需要两次。 即使Y和U丰富，也只能形成5对完整的S。 

这些痕迹表明，答案始终由三个独立资源中最严格的约束控制。

 ## 边缘情况

 当 x 小于 2 时，算法会正确生成零，因为 x // 2 变为零，无论 y 或 z 如何，都会立即阻止任何可能的形成。 例如，输入 1 10 10 得到 x // 2 = 0，因此答案为 0，这符合没有两个 S 气球就无法形成 SYSU 集的事实。 

当 y 或 z 之一为零时，即使 S 个气球很丰富，最小运算也可确保结果为零。 例如，输入 100 0 100 产生 min(50, 0, 100) = 0，正确反映每个集合同时需要 Y 和 U。 

在 S 非常大但成对约束占主导地位的情况下，例如 10000 1 1，计算量减少到 min(5000, 1, 1) = 1，这表明无需模拟即可正确识别瓶颈。
