 ## 解决方案
 ## 问题理解

 公钥是由一对私有正整数创建的`(p, q)`。 第一个公共值是该对的最大公约数，第二个是最小公倍数。 我们得到了公共对`(x, y)`并需要计算有多少个有序的私人对`(p, q)`可能已经生成了它。 

两个给定的数字可以大到`10^12`。 这排除了尝试可能的值`p`和`q`，因为即使迭代所有除数`y`如果不使用gcd和lcm的结构，成本就太高了。 成功的解决方案必须利用 gcd 和 lcm 之间的数学关系，并将任务简化为对单个数字进行因式分解。 由于平方根为`10^12`只是`10^6`，试除法达到该限制在 Python 中是实用的。 

破坏粗心解决方案的主要情况与整除性和数量有关`1`。 如果`x`不分开`y`，不存在可能的私钥。 例如，输入`10 11`有输出`0`，因为 lcm 始终是 gcd 的倍数，所以 gcd 为`10`无法生产 lcm`11`。 

另一个边缘情况是两个公共值相等时。 用于输入`7 7`，唯一可能的私钥是`(7, 7)`，所以答案是`1`。 一种仅计算素数分配而忘记剩余乘积可以是的解决方案`1`可能会对这个案子处理不当。 

第三种情况是当`y / x`包含重复的质因数。 用于输入`4 36`，比率为`9`。 有效的标准化对是`(1,9)`和`(9,1)`，给出私钥`(4,36)`和`(36,4)`。 素数的指数不会产生额外的选择，因为在删除 gcd 后两个数字不能共享相同的素因数。 

## 方法

 一种直接的方法是搜索可能的私钥。 由于该对的 lcm 必须是`y`，两个数字必须是以下的约数`y`。 我们可以枚举每个除数对`(p, q)`的`y`，检查是否`gcd(p, q) = x`和`lcm(p, q) = y`，并计算匹配数。 这是正确的，因为每个可能的私钥都必须出现在该枚举中。 然而，生成并检查接近的数字的除数`10^12`可能已经需要很多操作，并且该方法没有使用gcd和lcm之间的特殊关系。 

关键的观察结果来自于分离出 gcd。 认为：`p = x * a`和`q = x * b`。 

去掉公共部分后，剩下的值`a`和`b`必须互质。 lcm 变为：`lcm(p, q) = x * a * b`。 

所以：`a * b = y / x`。 

原来的问题现在是问这个数字有多少个有序互质因式分解`y / x`有。 如果这个数有质因数分解：`n = r1^e1 * r2^e2 * ... * rk^ek`然后每个完整的素数幂`ri^ei`必须完全去`a`或完全为了`b`。 分裂素数幂将使两个数字共享该素数，从而违反了互素条件。 每个`k`不同的质数给出了两个选择，所以答案是`2^k`。 

唯一剩下的任务是找到不同质因数的数量`y / x`。 因为这个值最多是`10^12`，检查除数至`10^6`就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(y 的除数数)，具有昂贵的 gcd 检查 | O(1) | O(1) | 太慢并且忽略结构|
 | 最佳| O(sqrt(y / x)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.首先检查是否`y`可以整除`x`。 如果不是，则任何对都不能拥有 gcd`x`和液晶显示器`y`，所以答案是立即`0`。 lcm 必须始终是 gcd 的倍数。 
2. 计算`n = y / x`。 这是从两个私钥值中删除 gcd 后剩余的两个互质部分的乘积。 
3.因式分解`n`通过尝试可能的除数`2`向上。 当找到除数时，将其视为一个不同的质因数，并从其中删除所有出现的它`n`。 消除全部幂是必要的，因为只有不同素数的数量会影响答案。 
4. 如果试除后的值大于`1`仍然是比原数的平方根大的质因数。 将其视为另一个不同的素数。 
5. 返回`2`提高到找到的不同质因数的数量。 每个质数幂可以独立地分配给互质对的任一侧。 

为什么它有效：

 将两个私有数除以它们的 gcd 后，剩余部分的 gcd 必须等于`1`。 这些部分的乘积固定为`y / x`。 在互质因式分解中，乘积的每个质因数恰好属于一侧。 对于每个不同的素数，只有两种选择：将其全部幂放在第一个数字或第二个数字中。 这些选择是独立的，因此将这些选择相乘得出`2^k`， 在哪里`k`是不同质因数的数量。 每个计数的分配都会创建一个有效的私钥，并且每个有效的私钥都对应于一个分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())

    if y % x != 0:
        print(0)
        return

    n = y // x
    cnt = 0

    d = 2
    while d * d <= n:
        if n % d == 0:
            cnt += 1
            while n % d == 0:
                n //= d
        d += 1

    if n > 1:
        cnt += 1

    print(1 << cnt)

if __name__ == "__main__":
    solve()
```第一个条件在进行任何分解之前处理不可能的公钥。 如果`x`不分开`y`，gcd和lcm关系所要求的比值不是整数。 

变量`n`存储去除 GCD 贡献后剩余的 LCM 部分。 因式分解循环仅计算不同的素数。 每当找到除数时，内部循环都会删除其整个指数，因为像这样的值`2`,`4`， 和`8`不要创建单独的作业选择。 

循环条件使用`d * d <= n`而不是计算平方根。 这避免了接近值的浮点精度问题`10^12`。 Python 整数不会溢出，因此乘法是安全的。 

最终检查为`n > 1`处理剩余的素因数。 例如，在去除小因素后`12`，剩余值变为`3`，仍然贡献一个独立的选择。

import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    x, y = map(int, input().split())

    if y % x != 0:
        return "0\n"

    n = y // x
    cnt = 0
    d = 2

    while d * d <= n:
        if n % d == 0:
            cnt += 1
            while n % d == 0:
                n //= d
        d += 1

    if n > 1:
        cnt += 1

    return str(1 << cnt) + "\n"

assert solution("5 10\n") == "2\n", "sample 1"
assert solution("10 11\n") == "0\n", "sample 2"
assert solution("527 9486\n") == "4\n", "sample 3"

assert solution("1 1\n") == "1\n", "minimum values"
assert solution("7 7\n") == "1\n", "equal public values"
assert solution("4 36\n") == "2\n", "repeated prime factor"
assert solution("1 1000000000000\n") == "16\n", "large composite value"

 ## 边缘情况

 用于输入`10 11`，算法首先检查整除性。 自从`11 % 10`不为零，则返回`0`立即地。 仅基于因式分解的方法`y`可能会错误地继续搜索对并在不可能的情况上浪费时间。 

用于输入`7 7`，比率变为`1`。 因式分解循环找不到素数，因此不同素数计数为零，答案为`2^0 = 1`。 这正确地代表了单对`(7,7)`。 

用于输入`4 36`，比率为`9`，其中因子为`3^2`。 该算法仅计算一个不同的素数，给出`2^1 = 2`。 这两个作业是`(1,9)`和`(9,1)`，这成为`(4,36)`和`(36,4)`。 它不计算拆分两个因子`3`因为这会使标准化值变得非互质。
