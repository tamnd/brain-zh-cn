 ## 解决方案
 # 问题理解

 瓦西亚有一系列菜肴。 每道菜都有一份配料表，其中包含一份所需的数量，并且每道菜都是为已知数量的客人准备的。 任务是模拟整个购物过程：确定每种可用食材必须购买多少包，计算总价，并计算一道菜的营养价值。 

输入包含两个独立的目录。 第一个描述商店包装：包装尺寸、计量单位和价格。 第二个描述了每种成分一定量的营养数据。 相同的成分可以以不同的单位出现在食谱和目录中，因此所有计算必须首先转换为通用单位。 

这些限制足够小，可以直接处理。 最多有 1000 道菜，每道菜最多有 100 种食材，两个目录最多包含 1000 个条目。 这意味着配方成分的总数最多为 100000。需要一种与总输入大小成正比的算法。 重复扫描所有目录中的每种食谱成分仍然可以进行大约 1 亿次比较，但使用字典更简单，并提供干净的线性解决方案。 

棘手的部分主要与单位以及一份和所有份之间的差异有关。 例如，如果食谱需要`500 ml`牛奶和商店出售`1 l`套餐，购买计算必须使用`0.5`包装向上取整，而营养成分计算必须准确使用`500 ml`。 

一个常见的错误是将具有不同含义的单位视为可以互换。 例如，`tens`和`cnt`两者都描述了一定数量的物体，但是`kg`和`l`无法转换。 该语句保证我们需要的每个转换都是有效的，因此实现只需应用正确的乘数。 

另一个微妙的例子是出现在几道菜中的一种成分。 例如：```
2
a 1 1
x 500 g
b 1 1
x 700 g
1
x 1000 g 1
1
x 1000 g 1 0 0 0
```正确的包裹数量是`2`，因为总金额是`1200 g`。 单独对每道菜进行四舍五入的解决方案也将得到`2`在这里，但是与`100 g`和`100 g`食谱和`150 g`包裹会错误地购买两个包裹而不是两个？ 重要的规则是购物是在汇总所有所需金额后完成的。 

另一种情况是以营养目录中不同单位测量的食谱成分：```
1
cake 1 1
milk 500 ml
1
milk 1 l 10
1
milk 1 l 20 0 0 100
```营养价值是目录条目的一半。 使用原始数字`500`目录值为`1 l`会使结果加倍。 

# 方法

 一个简单的解决方案是独立处理每道菜和每种原料。 对于每种食谱成分，搜索目录、转换数量、计算营养并更新所需数量。 这是正确的，因为每种成分的贡献都是独立的，并且添加足以将它们结合起来。 这种方法的问题是重复搜索。 如果10万个配方条目中的每一个都扫描1000个元素目录，则比较次数大约达到1亿次。 

有用的观察是每个目录中的成分名称都是唯一的。 这意味着可以使用哈希映射对目录进行一次索引。 之后，每次成分查找都变成常数时间。 

第二个观察结果是所有单位转换都是乘法的。 我们可以将每个数量转换为基本单位：克代表质量，毫升代表体积，单件代表数量。 一旦所有内容都采用相同的表示形式，求和需求、计算包装数量和计算营养就成为普通的算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总配方项目 * 目录大小) | O(1) | O(1) | 在最坏的情况下太慢|
 | 最佳 | O(总配方项 + k + m + n) | O(k + m + n) | 已接受 |

 # 算法演练

 1. 阅读价格目录并按名称存储每种成分。 将每个包裹尺寸转换为基本数量，以便包裹计算不依赖于原始单位。 
2. 阅读营养目录并存储每种成分对应于一个基本单位的蛋白质、脂肪、碳水化合物和能量的量。 除以转换后的目录数量可以直接乘以每个配方数量。 
3. 对于每道菜，存储其名称并计算其营养价值。 对于食谱中的每种成分，将每份的量转换为基本单位，然后乘以每个基本单位的营养价值。 
4.同时将食材量乘以客人人数添加到全局所需量图上。 这张地图代表了所有菜肴所需的每种原料的确切数量。 
5. 所有菜肴加工完成后，根据价格表计算每种食材的包装数量。 将所需金额除以包裹大小并向上舍入，因为无法购买部分包裹。 
6. 输出每道菜的总价、包装数量以及计算出的营养成分。 

该算法背后的不变性是，在处理任何菜肴前缀后，全局需求图准确地包含该前缀所需的量，并且每个存储的营养价值都是根据标准化成分数量计算的。 由于每个剩余的菜肴都是独立贡献的，因此继续相同的更新可以保持正确性，直到处理完所有菜肴。 

# Python 解决方案```python
import sys
import math
input = sys.stdin.readline

def factor(u):
    if u == "kg" or u == "l":
        return 1000
    if u == "tens":
        return 10
    return 1

def solve():
    n = int(input())
    dishes = []
    for _ in range(n):
        name, c, z = input().split()
        c = int(c)
        z = int(z)
        ing = []
        for _ in range(z):
            s, a, u = input().split()
            ing.append((s, int(a), u))
        dishes.append((name, c, ing))

    k = int(input())
    price = {}
    order = []
    for _ in range(k):
        t, p, a, u = input().split()
        a = int(a)
        price[t] = (int(p), a * factor(u))
        order.append(t)

    m = int(input())
    nutrition = {}
    for _ in range(m):
        t, a, u, pr, f, ch, fv = input().split()
        amount = int(a) * factor(u)
        nutrition[t] = (
            float(pr) / amount,
            float(f) / amount,
            float(ch) / amount,
            float(fv) / amount
        )

    need = {}
    answers = []

    for name, cnt, ing in dishes:
        cur = [0.0, 0.0, 0.0, 0.0]
        for s, a, u in ing:
            amount = a * factor(u)
            if s not in need:
                need[s] = 0
            need[s] += amount * cnt

            pr, f, ch, fv = nutrition[s]
            cur[0] += amount * pr
            cur[1] += amount * f
            cur[2] += amount * ch
            cur[3] += amount * fv
        answers.append((name, cur))

    total = 0
    packs = []
    for t in order:
        p, size = price[t]
        cnt = math.ceil((need.get(t, 0) - 1e-12) / size)
        packs.append((t, cnt))
        total += cnt * p

    out = [str(total)]
    for t, c in packs:
        out.append(f"{t} {c}")
    for name, vals in answers:
        out.append("{} {:.10f} {:.10f} {:.10f} {:.10f}".format(name, *vals))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```这`factor`函数将每个支持的单位转换为其基本表示形式。 公斤和升变成了各自基本单位的千分之一，而十变成了十个单独的物体。 

价格字典以与菜谱使用的相同表示形式存储包装尺寸。 这将从最终购买计算中删除所有单位处理。 

营养字典存储每个基本单位的值，而不是每个目录条目的值。 例如，如果目录说 100 克含有 20 克蛋白质，则存储的值为`0.2`每克蛋白质。 

在配方处理期间，代码执行两次独立的更新。 这`need`地图跟踪所有客人的购物数量，同时`cur`跟踪单个完整菜肴的营养成分。 混合这两个值是错误答案的常见来源。 

最终的上限运算包含一个小的 epsilon，因为浮点除法可能会产生如下值`1.000000000001`。 约束很小，因此在 Python 中整数溢出不是问题。

 # 边缘情况

 该算法通过在任何算术之前进行转换来处理单位不匹配。 以牛奶为例，`500 ml`变成`500`基本单位，而营养目录存储每个值`1000 ml`，因此结果恰好是目录值的一半。 

该算法通过更新来处理共享成分`need`每次成分出现时。 如果需要两道菜`100 g`每个和包装尺寸是`150 g`，最终的要求是`200 g`, 给予`ceil(200 / 150) = 2`包。 它从不提前舍入个别食谱。 

还处理零使用目录条目。 输出需要打印每种价格目录成分，包括任何食谱都不需要的成分。 查找使用`need.get(t, 0)`，为这些成分生产零包装。
