 ## 解决方案
 ## 问题理解

 该图包含由加权无向边连接的顶点。 我们必须用两种颜色给顶点着色，同时使用两种颜色，并查看端点接收到相同颜色的边。 在这些边中，我们关心最小的权重。 目标是使这个最小的内部边缘尽可能大。 

查看目标的一个有用方法是选择答案值`x`。 如果所有边的权重都小于`x`被迫在两组之间移动，那么组内剩下的每条边至少都有权重`x`。 问题是子图是否仅由权重小于的边组成`x`可以分为两侧，这正是这个子图是否二分的问题。 

输入大小达到`100000`顶点和`100000`边缘。 尝试所有可能的分区是不可能的，因为有`2^n`着色。 即使具有二次行为的算法对于这些限制来说也太慢了，因为`10^10`操作将远远超出实际。 我们需要一种接近`O((n+m) log C)`， 在哪里`C`是可能答案的范围。 

在某些情况下，不正确的实现可能会默默地失败。 具有不同权重的重复边必须单独处理。 例如：```
3 3
1 2 1
1 2 5
2 3 4
```正确答案是`4`。 重量的边缘`1`检查小阈值时很重要，但权重的边缘`5`仍然可以成为最终分区的内部边缘。 仅保留两个顶点之间的一条边的解决方案可能会删除答案所需的信息。 

另一种情况是，整个图几乎是二分的，但仅仅因为一个较重的边而变得不可能：```
3 3
1 2 1
2 3 1
1 3 10
```正确答案是`10`。 对于每个值高达`10`，由较小边形成的图是二分图。 在`11`，整个图被包括在内并且不是二分图。 仅检查原始图是否为二分图的解决方案错过了阈值解释。 

最后的边缘情况是答案可以是图中最大的边缘权重：```
3 3
1 2 2
2 3 2
1 3 7
```正确答案是`7`。 该算法必须允许阈值达到最大边缘权重，因为具有该权重的边缘可能是零件内剩余的唯一边缘。 

## 方法

 直接的解决方案是将每个可能的顶点划分枚举为两个非空组。 对于每个划分，我们将扫描所有边，找到端点位于同一组中的边，并保持最小的权重。 这是正确的，因为它准确地检查了问题所要求的数量。 

问题是可能的划分数量。 和`n`顶点有`2^n`两种颜色的分配，即使忽略交换两种颜色的对称情况，工作量仍然是指数级的。 为了`n = 100000`，这种方法不太可行。 

关键的观察是我们不需要直接构建最佳分区。 我们可以问一个不同的问题：答案至少可以是`x`？ 为此，权重小于的每条边`x`必须连接不同组的顶点。 换句话说，如果我们暂时只保留权重小于的边`x`，该图必须是二分图。 

蛮力之所以有效，是因为它会检查所有可能的颜色，但当颜色数量爆炸时就会失败。 阈值观察让我们可以用对边权重的搜索来代替对分区的搜索。 该属性是单调的：如果边小于`x`形成二分图，则小于任何较小值的边也形成二分图。 这允许二分搜索`x`。 

对于每个二分搜索步骤，我们使用 BFS 或 DFS 对权重低于当前阈值的所有边运行二分检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * m) | O(2^n * m) | O(n) | 太慢了|
 | 具有二分检查的二分搜索 | O((n + m) log W) | O(n + m) | 已接受 |

 ## 算法演练

 1. 存储所有边。 在检查过程中我们需要的唯一操作是确定边权重是否低于所选阈值。 
2.二分查找之间的答案`1`和`100001`。 对于候选值`mid`，我们测试权重是否小于的所有边`mid`形成二部图。 
3. 在检查过程中，创建一个颜色数组。 未着色的顶点被分配一种颜色，然后 BFS 将相反的颜色传播到权重小于阈值的每条边上。 
4. 如果权重小于阈值的边连接两个已经具有相同颜色的顶点，则对于该阈值，该图不是二分图。 候选答案太大，因此在下半部分继续进行二分查找。 
5. 如果检查成功，则可以实现候选值。 我们向上移动二分搜索范围以找到更大的可能答案。 
6. 打印最大成功阈值。 由于保证整个图不是二分图，因此搜索不会错误地返回所有边都可以放置在两组之间的值。 

该算法背后的不变量是阈值`x`当可能成为禁止的小内部边缘的每条边缘都可以通过两种颜色分隔时，该方法准确有效。 双向检查证明这种着色是否存在。 由于增加阈值只会向检查的图添加更多边，因此一旦阈值失败，每个更大的阈值也会失败。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((u - 1, v - 1, w))

    def check(limit):
        graph = [[] for _ in range(n)]
        for u, v, w in edges:
            if w < limit:
                graph[u].append(v)
                graph[v].append(u)

        color = [-1] * n

        for start in range(n):
            if color[start] != -1:
                continue
            color[start] = 0
            q = deque([start])

            while q:
                v = q.popleft()
                for to in graph[v]:
                    if color[to] == -1:
                        color[to] = color[v] ^ 1
                        q.append(to)
                    elif color[to] == color[v]:
                        return False
        return True

    left = 1
    right = 100002

    while left + 1 < right:
        mid = (left + right) // 2
        if check(mid):
            left = mid
        else:
            right = mid

    print(left)

if __name__ == "__main__":
    solve()
```边列表保持其原始形式，因为每次二分搜索迭代都需要按权重过滤边。 重建里面的临时图`check`保持逻辑简单并避免过时边缘的错误。 

二分查找使用范围`[1, 100002)`。 上限是排他性的，因为边权重最多为`100000`，大于每条边的阈值将包括整个图。 保证原始图不是二分图意味着这样的阈值必须失败。 

BFS 颜色分别连接组件。 这很重要，因为图表可能包含多个断开连接的部分，并且每个组件都可以独立着色。 仅当已经有颜色的邻居需要相同的颜色时，才会出现冲突。 

Python整数在这里不会溢出，唯一涉及答案的算术是二分查找中点计算。 使用`sys.stdin.readline`双端队列使输入和图形遍历速度足以满足约束条件。

 ## 边缘情况

 对于重复的边，请考虑：```
3 3
1 2 1
1 2 5
2 3 4
```支票为`limit = 5`仅使用第一条和第三条边。 它们形成一条路径，因此它们是二分的。 支票为`limit = 6`包括所有边，还包括较重的平行边。 答案就变成了`5`，因为保持较小边图二分的最大阈值恰好是`5`。 该算法从不合并平行边，因此两种可能性都被保留。 

对于最大边就是答案的图：```
3 3
1 2 2
2 3 2
1 3 7
```当阈值是`7`，只有权重的两条边`2`被检查。 它们形成一条路径并且可以是两种颜色的。 当阈值变为`8`, 权重边缘`7`添加后，三角形将变为非二分三角形。 二分查找返回`7`，它匹配最佳的内部边缘。 

对于最小尺寸图：```
3 3
1 2 1
2 3 1
1 3 1
```每个阈值大于`1`包括整个三角形，不能用两种颜色来着色。 唯一成功的门槛是`1`，所以算法输出`1`。 这证实了搜索的下边界已正确处理。
