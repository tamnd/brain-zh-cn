 ## 解决方案
 ## 问题理解

 我们有一系列沙滩椅，每张椅子都有一个描述其外部特征的编号。 任务是选择两个不同的椅子，其编号具有尽可能小的 XOR 值。 XOR 以二进制形式衡量两个数字的差异程度，因此目标是找到差异最小的一对。 

输入包含多个测试用例。 对于每个测试用例，第一个值给出椅子的数量，后面是分配给这些椅子的特征值。 每个测试用例的输出是通过比较任意两个不同的椅子可以获得的最小 XOR 值。 

所有测试用例的值总数可以达到\(10^6\)。 这立即排除了检查每一对的可能性，因为\(n^2\)运营将变得围绕\(10^{12}\)，这远远超出了典型的竞争性编程限制所允许的范围。 我们需要一个接近线性或\(n \log C\)， 在哪里\(C\)是数字的最大可能值。 因为每个值最多都是\(10^9\)，只有大约 30 个二进制数字重要。 

有少数情况很容易处理不当。 如果两把椅子的值完全相同，则答案为零，因为它们的 XOR 为零。 例如，输入```
1
3
7 7 12
```有输出```
0
```仅在排序后检查相邻值而不正确处理重复值的解决方案可能会错过这一点。 

另一种情况是最小的对不是由数值上最接近的两个值形成的。 例如，```
1
4
1 2 8 16
```有输出```
3
```最好的一对是 1 和 2。它们的数值差异很小，但 XOR 是实际度量，因此仅用减法进行推理是不够的。 

当值很大并且使用高位时，会出现第三种边缘情况。 例如，```
1
2
0 1000000000
```有输出```
1000000000
```检查太少位的二进制 trie 实现将会失败，因为值接近\(10^9\)需要 30 位。 

## 方法

 直接的解决方案是比较每对可能的椅子。 对于每对索引\(i\)和\(j\)，我们计算\(a_i \oplus a_j\)并保留最小的结果。 这种方法是正确的，因为它确实检查了每个可能的候选答案。 问题是对的数量。 和\(n = 10^6\)，比较次数大约为\(5 \times 10^{11}\)，这是不可能及时完成的​​。 

XOR的结构给了我们更好的方向。 为了最小化与固定数字的异或，我们希望另一个数字尽可能具有相同的位，特别是最高位。 高位的差异比低位的差异对最终 XOR 值的贡献更大。 

二进制字典树按位存储数字。 从最高有效位开始，我们可以遍历 trie，并且总是更喜欢包含与当前数字相同位的分支。 如果存在这样的分支，则该位对异或的贡献为零。 仅当匹配分支丢失时，我们才必须采用相反的位，这会将该位的值添加到答案中。 

蛮力方法之所以有效，是因为它检查了每个可能的伙伴，但它失败了，因为它重复了太多工作。 trie 存储独立为每个数字做出最佳选择所需的信息，从而将所有对的搜索减少到大约 30 个级别的一次遍历。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 二进制特里树 | O(30n) | O(30n) | O(30n) | O(30n) | 已接受 |

 ## 算法演练

 1. 创建一个空的二进制 trie。 每个节点代表插入数字的二进制表示的前缀。 一个节点最多有两个子节点，一个用于位 0，一个用于位 1。 

2. 通过从最高有效位到最低有效位处理位，将第一个数字插入到 trie 中。 在每一位上，创建所需的子级（如果不存在）。 

3. 对于后面的每个数字，在 trie 中搜索与其产生最小 XOR 的值。 在每个位位置，检查 trie 是否包含与当前数字相同的位。 如果是，则遵循该分支，因为它使当前 XOR 位保持为零。 否则，遵循相反的分支，将该位的值与当前的异或结果相加。 

4. 找到当前数字的最佳搭档后，更新全局最小答案并将当前数字插入到特里树中。 

5. 打印处理完所有数字后找到的最小值。 

搜索之所以能够贪婪地选择相等的位，是因为二进制数是按重要性进行比较的。 较高位的差异永远无法通过较低位的选择来补偿。 保留尽可能高的位始终是最好的决定。 

为什么它有效：插入一些数字后，特里树包含所有可能的先前伙伴。 在查询过程中，遍历选择从最高位到最低位逐位最小化异或的路径。 由于较高位主导最终数值，因此这种贪婪选择会与 trie 中已有的任何数字产生尽可能最小的异或。 通过此最佳查询，除第一个数字之外的每个数字都会与所有较早的数字进行比较，因此每个可能的对都会被考虑一次。 这些最佳对值中的最小值就是全局答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class BinaryTrie:
    def __init__(self):
        self.children = [[-1, -1]]

    def insert(self, x):
        node = 0
        for bit in range(30, -1, -1):
            b = (x >> bit) & 1
            nxt = self.children[node][b]
            if nxt == -1:
                nxt = len(self.children)
                self.children[node][b] = nxt
                self.children.append([-1, -1])
            node = nxt

    def query(self, x):
        node = 0
        result = 0
        for bit in range(30, -1, -1):
            b = (x >> bit) & 1
            if self.children[node][b] != -1:
                node = self.children[node][b]
            else:
                result |= 1 << bit
                node = self.children[node][1 - b]
        return result

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        trie = BinaryTrie()
        trie.insert(a[0])

        best = 1 << 31
        for x in a[1:]:
            best = min(best, trie.query(x))
            trie.insert(x)

        ans.append(str(best))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`BinaryTrie`类存储先前处理的值的二进制表示。 这`insert`方法遵循从 30 到 0 的位，因为\(10^9\)小于\(2^{30}\)，所以这 31 个位置足以表示每个可能的输入值，包括零。 

这`query`方法是算法的贪心部分。 它试图在每个级别上保持不变。 如果该分支存在，选择它对异或的贡献为零。 如果不存在，则强制执行相反的分支，并将相应的位添加到答案中。 

第一个数字插入在任何查询之前，因为一对需要两把不同的椅子。 从空字典树开始会使第一个查询无效。 每次查询后，都会插入当前号码，以便将来的号码可以将其用作候选号码。 

Python 整数不会溢出，因此位操作是安全的。 初始值`best`比任何可能的 XOR 结果都大，因为下面两个数字的最大 XOR\(2^{30}\)下面是\(2^{31}\)。

 ## 边缘情况

 对于相等的值，trie 自然会在每个级别上找到相同的位。 考虑：```
1
3
7 7 12
```插入前 7 个。 当查询第二个 7 时，每个位都遵循相同的分支，产生 XOR 0。由于零是最小的可能答案，因此后面的数字无法改进它。 

对于数值上最接近的对不明显的值，特里结构遵循位而不是排序距离。 考虑：```
1
4
1 2 8 16
```对 2 的搜索更喜欢 1 的路径，因为它们共享所有高位，仅在位 1 上有所不同。生成的 XOR 是 3，它成为答案。 

对于较大的值，该算法包括输入范围所需的每一位。 考虑：```
1
2
0 1000000000
```trie 处理位 30 到位 0，因此它正确地表示了完整的值。 唯一可能的对产生 XOR 1000000000，并返回。
