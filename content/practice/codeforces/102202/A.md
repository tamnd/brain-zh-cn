 ## 解决方案
 ## 问题理解

 我们有一串长度为 (N) 的字符串，其中每颗宝石都是其中之一`R`,`B`， 或者`V`。 我们可以选择一个连续的子串并希望其最大可能长度。 

选定的子串对于三个不同的观察者来说必须看起来不同。 正常观察者可以区分所有三种颜色，而红色盲观察者则可以区分`V`作为`R`，并且蓝色盲观察者对待`V`作为`B`。 对于每个观察者来说，邻近的珠宝必定具有不同的感知颜色。 

结合这三个要求的有用方法是检查每对可能的相邻原始颜色。 对于普通观察者来说，两种相同的颜色是被禁止的。 这对`R,V`对于红色盲观察者来说是被禁止的，因为它变成了`R,R`。 这对`B,V`对于蓝色盲观察者来说是被禁止的，因为它变成了`B,B`。 因此，在所有可能的不同对中，唯一幸存的对是`R,B`。 

这给出了问题的更简单的重述：长度至少为 2 的有效子字符串只能包含`R`和`B`，并且每个相邻的对必须交替。 一个`V`只能出现在长度为一的有效子串中。 

界限（N \le 250,000）排除了预期解决方案中的二次或更差算法。 单次线性扫描仅对每个宝石执行恒定量的工作，这在 Python 中完全在 1 秒的限制内。 检查每对位置的算法已经在最大输入大小下执行大约 (31) 十亿对检查，因此需要直接利用有效子串的结构。 

在一些小情况下，仅基于原始定义的实现可能会出错。 用于输入`1`其次是`V`，答案是`1`，因为单宝石子串没有相邻的一对来违反任何条件。 一个粗心的实现，只寻找交替`R`和`B`可能会错误地返回零。 

用于输入`3`和`RVB`，答案是`1`。 虽然三种原色颜色不同，`RV`变成`RR`对于红色盲观察者和`VB`变成`BB`对于蓝色盲观察者来说。 仅检查相邻原始字符是否不同会错误地接受整个字符串。 

用于输入`4`和`RBRB`，答案是`4`。 每个相邻对都是`RB`或者`BR`，因此三个观察者在每个边界处都会看到不同的颜色。 过于宽松地对待多种颜色的实现可能会错过完全交替的颜色`R/B`字符串有效。 

## 方法

 直接的暴力解决方案可以枚举每个连续的子串并测试它是否满足所有三个观察者。 对于子串，检查每个相邻对所花费的时间与其长度成正比，因此该方法是正确的，因为它在更新最佳答案之前显式验证了定义。 

问题是子串的数量。 有(N(N+1)/2)个，如果每一个都从头开始检查，则字符检查的总数为

 \frac{N(N+1)(N+2)}{6}。 
]

 对于（N=250,000），这大约是（2.6\times10^{15}）次操作，远远超出了时间限制。 即使是扩展每个起始位置直到遇到无效边界的改进的暴力实现，在最坏的情况下仍然需要 (O(N^2))，因为交替字符串允许每个扩展继续。 

关键的观察结果是，三种色盲条件消除了所有相邻的配对，除了`R,B`和`B,R`。 一旦认识到这一点，我们就不再需要检查任意子字符串。 我们只需要最长的连续运行，其中每个相邻对都包含不同的`R`和`B`人物。 

从左到右扫描时可以保持此属性。 如果当前字符是`R`或者`B`与前一个字符不同的是，当前的交替运行延长了一个。 否则，当前运行必须在当前字符处重新开始。 一个`V`总是开始长度为 1 的新游程，因为长度至少为 2 的有效子串不能包含它。 

暴力破解之所以有效，是因为它明确地测试了每个可能的间隔，但由于间隔太多而失败。 观察到有效的局部转换恰好是`R -> B`和`B -> R`将问题转化为找到最长的交替运行，这可以一次完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N^3)) 从头开始​​检查每个子字符串 | (O(1)) | (O(1)) | 太慢了 |
 | 提前停止的暴力破解 | (O(N^2)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳扫描| (O(N)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取字符串并将当前有效游程长度初始化为零，将最大答案初始化为零。 游程表示以当前位置结束的后缀，其每个相邻对都是有效的。 
2. 从左到右处理字符串。 对于第一个字符，开始一个长度的运行。 没有前一个字符，因此没有边界可供检查。 
3. 对于后面的每个字符，检查当前字符和前一个字符是否都属于`{R, B}`以及它们是否不同。 这正是新的相邻对要么是的条件`RB`或者`BR`。 
4. 如果该条件成立，则将当前游程长度增加一。 新添加的边界有效，并且运行中所有早期的边界都已经有效。 
5. 否则，从当前字符开始新的长度为 1 的运行。 这涵盖了`V`和重复的颜色，例如`RR`或者`BB`。 两者都不能扩展先前的有效子字符串。 
6. 确定当前游程长度后，更新最大答案。 扫描期间遇到的最长的串是最长的有效子串。 

### 为什么它有效

 不变量是处理完位置(i)后，`current`正是以位置 (i) 结束的最长有效子串的长度。 如果新的边界是`RB`或者`BR`，附加当前字符可保留有效性，因此前一次运行会延长 1。 对于每个其他边界，长度至少为 2 的有效子串不能跨越该边界，因此以当前位置结尾的唯一有效子串的长度为 1。 取这些结束长度中的最大值会考虑每个可能的有效子串恰好在其结束位置，因此最终的最大值是全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    best = 1
    current = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            current += 1
        else:
            current = 1

        if current > best:
            best = current

    print(best)

if __name__ == "__main__":
    solve()
```使用读取输入`sys.stdin.readline`，这对于长度 (250,000) 的字符串来说足够了，并且避免了不必要的输入开销。`current`存储以当前位置结束的有效交替后缀的长度。 条件```
s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]
```精确检查位置之间的边界是否`i - 1`和`i`是允许的。 两个字符都必须是非`V`，而且它们一定是不同的。 由于字母表只包含`R`,`B`， 和`V`，这相当于说这对是`RB`或者`BR`。 

当条件不成立时，`current`变成`1`，而不是`0`。 当前的宝石本身始终是有效的单宝石珠，即使它是`V`。 

答案初始化为`1`因为 (N \ge 1)。 这也处理所有 -`V`没有任何特殊分支的情况。 Python 中不可能出现整数溢出，唯一存储的输入大小的对象是字符串本身。

 输入是`RBBB`。 唯一有效的相邻转换是在不同的之间`R`和`B`人物。 第一个之后`B`，下一个`B`打破交替运行，剩下的`B`再次打破它。

 输入是`RBRBB`。 前四个字符形成交替`R/B`顺序。 决赛`B`与另一个相邻`B`，因此它开始新的运行。

 子串`RBRB`长度为四，每个相邻对都是`RB`或者`BR`。 决赛`BB`边界阻止长度为五的答案，所以结果是`4`。

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    s = input().strip()

    best = 1
    current = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            current += 1
        else:
            current = 1

        best = max(best, current)

    print(best)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("4\nRBBB\n") == "2", "sample 1"
assert run("5\nRBRBB\n") == "4", "sample 2"

# Minimum-size input
assert run("1\nV\n") == "1", "single V"

# All equal values
assert run("5\nRRRRR\n") == "1", "all equal"

# V cannot participate in a valid substring of length > 1
assert run("3\nRVB\n") == "1", "V blocks both neighboring transitions"

# Maximum-size input
n = 250000
s = "".join("R" if i % 2 == 0 else "B" for i in range(n))
assert run(f"{n}\n{s}\n") == str(n), "maximum alternating string"

# Boundary and off-by-one case
assert run("6\nBRBBRB\n") == "3", "longest run is BRB"

 |`5 / RRRRR`| 1 | 重复的颜色不能形成有效的相邻对 |

 ## 边缘情况

 对于单个宝石，考虑输入```
1
V
```根本不存在相邻对，因此每个观察者都认为该珠子是有效的。 算法开始`current`和`best`在`1`并且永远不会进入循环，产生`1`。 

对于包含的子串`V`， 考虑```
3
RVB
```在位置一，一对`RV`无效，因为红色盲的人将其视为两颗红色宝石。 该算法将运行重置为`1`。 在第二个位置上，`VB`由于类似的蓝色盲原因无效，因此运行仍然存在`1`。 结果是`1`。 

对于重复的颜色，请考虑```
5
RRRRR
```第一个`R`创建长度为 1 的游程。 随后的每一个`R`等于前一个字符，因此每个转换都是无效的，并且运行会重复重置为 1。 答案是`1`。 

对于完全交替的珠子，请考虑```
6
RBRBRB
```每个边界都是`RB`或者`BR`， 所以`current`增加自`1`通过`6`。 最大值变为`6`，表明该算法没有对交替的长度施加任何不必要的限制`R/B`顺序。 

边界情况`BRBBRB`对于捕获相差一错误很有用。 扫描产生游程长度`1, 2, 1, 1, 2, 3`，所以答案是`3`，由最后的子串表示`BRB`。 在重置之前更新最大值或比较错误的索引对的粗心实现可能会错误地报告`2`或者`4`。
