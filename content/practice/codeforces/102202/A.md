 ## 解决方案
 ## 问题理解

 我们有一串长度为 (N) 的字符串，其中每颗宝石都有颜色`R`,`B`， 或者`V`。 我们可以选择一个连续的子串并将其放弃。 所选子串对于三个不同的观察者来说必须看起来丰富多彩。 

正常的观察者可以区分所有三种颜色，因此相邻的珠宝必须具有不同的原始特征。 红色盲观察者看到`R`和`V`为相同的颜色，而蓝色盲观察者看到的`B`和`V`作为相同的颜色。 对于这些观察者中的任何一个，所选子串必须没有相同的相邻颜色。 

关键结果比最初表明的原始条件更强。 考虑任何相邻对包含`V`。 如果另一颗宝石是`R`，红色盲观察者看到两颗连续的红色宝石。 如果另一颗宝石是`B`，蓝色盲观察者看到两颗连续的蓝色宝石。 如果该对是`VV`，每个人看到的颜色都是相同的。 因此`V`不能与有效子字符串内的任何内容相邻。 

唯一一个在所有三个观察者中幸存下来的相邻对是`RB`或者`BR`。 因此，每个长度至少为 2 的有效子串必须仅包含`R`和`B`，并且这些字符必须交替出现。 

例如，`RBRB`是有效的，同时`RVB`不是。 单个宝石，例如`V`始终有效，因为它根本没有相邻对。 

输入最多可包含 (250,000) 颗宝石。 (O(N^2)) 算法将大致检查 (N(N+1)/2) 个子字符串，当 (N=250,000) 时，该子字符串约为 (31.25) 十亿个。 这远远超出了一秒的时间限制。 我们只需检查字符串固定次数，给出 (O(N)) 解决方案。 

有几种边缘情况很容易导致错误的实现。 

考虑```
1
V
```答案是`1`。 仅搜索交替的解决方案`R`和`B`段可能会错误地返回零，忘记单个宝石始终有效。 

考虑```
4
RVBR
```答案是`1`。 虽然`V`不等于任何一个相邻字符，它不能相邻`R`对于红色盲观察者或`B`对于蓝色盲观察者。 仅检查原始字符串中相邻字符的解决方案将错误地接受包含以下内容的部分：`V`。 

考虑```
5
RBRBB
```答案是`4`， 从`RBRB`。 决赛`BB`打破了交替模式，因此在看到无效对后保持当前长度的粗心实现可能会导致计数过多。 

最后，```
5
RRRRR
```有答案`1`。 相等相邻`R`Jewels 立即无效，但每个单独的 Jewel 仍然是有效的子字符串。 

## 方法

 一种直接的方法是枚举每个连续的子串并检查它对于所有三个观察者来说是否都是彩色的。 有 (N(N+1)/2) 个子串。 如果通过扫描其所有相邻对来检查每个子串，最坏情况的工作是 (O(N^3))，这显然是不可能的。 

我们可以通过固定起始位置并一次扩展一颗宝石来使这个天真的想法变得更好。 一旦出现无效的相邻对，从同一位置开始的每个较长的子串也无效，因此我们不需要重新扫描整个子串。 这将工作量减少到 (O(N^2))，因为在最坏的情况下，我们仍然检查每个起始位置的每个可能的结束位置。 对于 (N=250,000) 来说，大约有 (312.5) 亿个扩展，仍然太多了。 

蛮力方法之所以有效，是因为有效性完全由相邻对决定。 有用的观察是，在结合所有三个观察者的要求后，几乎每一对都被禁止。`R`旁边`B`是唯一有效的对。 一个`V`永远不能参与长度大于 1 的有效子字符串。 

这意味着我们根本不需要考虑任意子字符串。 我们只需要找到每个字符所在的最长连续部分`R`或者`B`并且每一个相邻的对都是不同的。 这样的部分只是一个交替序列，例如`RBRBR`或者`BRBRB`。 

我们可以扫描一次字符串。 当当前角色继续交替时`R`/`B`序列，增加其长度。 否则，如果当前字符是，则开始一个长度为 1 的新序列`R`或者`B`。 为了`V`，不再有序列可以通过它，因此当前长度变为 1。 

由于一颗宝石始终有效，因此答案至少是一颗。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(N^3)) | (O(1)) | (O(1)) | 太慢了 |
 | 增量蛮力 | (O(N^2)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳扫描| (O(N)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1.读取字符串并初始化最佳有效长度为`1`。 单宝石子串没有相邻的对，因此它总是彩色的。 
2. 维护`cur`，以当前位置结束的最长有效子字符串的长度。 最初`cur = 1`。 
3. 对于第一个位置之后的每个位置，检查前一个和当前的字符。 如果两者都是`R`或者`B`并且它们是不同的，该对对所有三个观察者都有效，因此通过设置来扩展当前子字符串`cur += 1`。 
4. 否则，前一个子串无法通过该位置扩展。 放`cur = 1`，因为当前的宝石本身始终是有效的子字符串。 
5. 更新全局答案`max(ans, cur)`处理完每个字符后。 

我们可以在无效对之后立即丢弃前一个子字符串的原因是，在当前位置结束并在无效对之前开始的每个较长子字符串仍将包含相同的禁止相邻对。 保留其中任何一个都没有任何好处。 

### 为什么它有效

 为了使长度至少为 2 的子串对于所有三个观察者来说都是彩色的，每个相邻对必须对于所有三种颜色解释都有效。`R-B`和`B-R`是唯一这样的对。 每对包含`V`对于至少一个观察者来说是无效的，并且等于`R`或等于`B`对正常观察者来说是无效的。 

因此，长度至少为 2 的有效子串恰好是以下的交替序列`R`和`B`。 在扫描过程中，`cur`正是在当前位置结束的最长序列。 有效的`R/B`对扩展它，而任何其他对都使扩展不可能，并强制最好的有效后缀成为当前的单个宝石。 取最大值`cur`因此，在所有位置上给出最长的有效连续子串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    ans = 1
    cur = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            cur += 1
        else:
            cur = 1

        if cur > ans:
            ans = cur

    print(ans)

if __name__ == "__main__":
    solve()
```输入被读取`readline`，对于长度为 (250,000) 的字符串来说绰绰有余。 字符串本身存储一次。`cur`表示以当前位置结尾的有效后缀。 条件```
s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]
```准确检查新的相邻对是否是`RB`或者`BR`。 检查成员资格`RB`是必要的，因为`V`不能出现在长度大于 1 的有效子字符串中。 

当条件不成立时，`cur`变成`1`而不是`0`。 这可以处理两种普通的中断，例如`BB`以及特殊情况`V`。 当前的宝石总是可以自己开始一个新的有效子串。 

Python 中不存在整数溢出问题，并且`cur`绝不会超过 (N)。 扫描从索引处开始`1`，因此前一个字符访问始终位于字符串内部。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(N)) | 每颗宝石在第一颗宝石之后都会被加工一次。 |
 | 空间| (O(N)) | 输入字符串需要(O(N))存储； 算法本身使用 (O(1)) 额外空间。 |

 对于 (N \le 250,000)，算法仅对每个字符执行一些恒定时间操作。 这完全在一秒的约束范围内，而二次方法在最坏的情况下将需要数十亿次迭代。 

## 测试用例```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(input())
    s = input().strip()

    ans = 1
    cur = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            cur += 1
        else:
            cur = 1

        ans = max(ans, cur)

    sys.stdin = old_stdin
    return str(ans)

# Provided samples
assert solution("4\nRBBB\n") == "2", "sample 1"
assert solution("5\nRBRBB\n") == "4", "sample 2"

# Minimum-size input
assert solution("1\nV\n") == "1", "single V is always valid"

# All equal values
assert solution("5\nRRRRR\n") == "1", "equal adjacent colors are invalid"

# V cannot be part of a multi-character valid substring
assert solution("5\nRVBRB\n") == "4", "longest valid part is BRBR"

# Maximum-size input
assert solution("250000\n" + "RB" * 125000 + "\n") == "250000", \
    "entire maximum-length alternating string is valid"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`1\nV\n`|`1`| 最小尺寸和单个的事实`V`有效 |
 |`5\nRRRRR\n`|`1`| 重复相同的颜色必须打破顺序 |
 |`5\nRVBRB\n`|`4`|`V`不能属于长度大于 1 的有效子字符串 |

 ## 边缘情况

 对于单颗宝石盒```
1
V
```由于没有相邻对，因此循环不会执行。`ans`开始于`1`，所以算法打印`1`。 这就是为什么只有在实现单独处理空扫描时才将答案初始化为零才有效，而所选的初始化自然与问题的保证 (N \ge 1) 相匹配。 

对于包含的子串`V`， 考虑```
4
RVBR
```在位置`1`，这对`RV`是无效的，所以`cur`变成`1`。 在位置`2`，这对`VB`也是无效的，所以`cur`遗迹`1`。 在位置`3`,`BR`是有效的，所以`cur`变成`2`。 答案是`2`，对应最后的子串`BR`。 这表明`V`不仅仅是两个序列之间的分隔符，而且它根本不能参与多宝石有效子字符串。 

对于重复的颜色，```
5
RRRRR
```每个相邻对都是`RR`。 每对交替失败`R/B`条件，所以`cur`反复重置为`1`。 最大剩余量`1`，这是正确的，因为任何长度至少为 2 的子串都包含相等的相邻红色宝石。 

对于最长序列到达末尾的边界，```
5
BRBRB
```每对都是有效的。`cur`进展通过`1, 2, 3, 4, 5`， 和`ans`达到`5`。 没有特殊的字符串结尾处理，因为答案在处理最后一个字符时更新。 

对于最大尺寸的交替输入，包括`250000`图案中的字符`RBRB...`，每个相邻对都是`RB`或者`BR`。 当前长度因此达到`250000`，算法返回整个珠子。 这证实了线性扫描可以处理最大允许输入，而无需任何特殊情况逻辑。
