 ## 解决方案
 ## 问题理解

 我们有两个正整数，`A`和`B`。 唯一允许的操作是将一个变量加倍，或将一个变量添加到另一个变量。 任务是打印最多 5000 个此类操作的任何序列，最终使两个变量相等。 

困难不在于原则上找到某种顺序。 由于重复加法可以模拟欧几里得算法，因此解总是存在的。 困难在于当初始值可能大到 10 18 时，需要在 5000 次操作内生成序列。 

直接模拟减法就足以揭示问题。 开始于`A = 1, B = 10^18`，自然加法过程的逆过程会减去`1`从`B`大约10 18次。 这远远超出了输出限制和一秒钟内可用的计算量。 巨大的数字范围也排除了对可能的值对的任何搜索。 

有几种边缘情况，粗心的实现可能会处理不当。 如果`A == B`，例如，正确答案只是零运算。 用于输入`1 1`，即使打印一个操作也是不必要的，并且可能会使其他正确的结构更难以推理。 如果一个值是偶数，例如`2 3`，我们必须利用加倍运算而不是重复相加`2`到`3`。 最后，输入诸如`1 1000000000000000000`对于每单位进度执行一次加法的任何算法来说都是危险的，因为所需的计数可能比 5000 大得多。 

中心观察是，将两个数字乘以同一个正因子不会改变问题是否可解。 一系列添加应用于`(A, B)`可以应用于`(kA, kB)`同样，每个中间值都简单地乘以`k`。 这为我们提供了一种重新解释加倍的有用方法。 

## 方法

 自然的暴力方法是逆转该过程。 如果`A < B`, 减去`A`从`B`; 如果`B < A`, 减去`B`从`A`。 这正是欧几里得算法的减法形式。 一旦两个值相等，反转所有减法以获得有效的正向运算。 

这种方法是正确的，因为每次从较大值中减去较小值都对应于将较小值与较大值相加。 问题在于重复次数。 为了`(1, 10^18)`，减法欧几里得执行 10 18 -1 次迭代。 这大大超出了允许的 5000 次输出操作。 

解决这个问题的观察方法是加倍运算。 假设概念状态是`(A/2, B)`， 在哪里`A`是均匀的。 而不是实际划分`A`， 履行`B += B`关于真实变量。 真实状态变为`(A, 2B)`，正好是两倍`(A/2, B)`。 由于将两个变量乘以相同的因子可以保留每个未来的加法关系，因此我们可以认为`B += B`作为划分的概念操作`A`两个。 

这为我们提供了欧几里得过程的快速版本。 每当一个数字是偶数时，从概念上将其除以二。 如果两个数字都是奇数且不相等，则将较小的数字与较大的数字相加。 较大的变得均匀，因此下一阶段可以将其除以二。 更具体地说，如果`A < B`两者都是奇怪的，将概念对替换为

 (A,B)→(A, 2 A+B​)。 

新的区别是

 2 B−A​，

 所以每一次这样的奇数到奇数的转变都会使差异减半。 这是迭代次数保持较小的关键原因。 

初始值最多为 10 18，因此在正值达到 1 之前最多有大约 60 次减半。在一次奇数转换期间，加法创建的值低于 2⋅10 18，这需要最多 61 次减半才能还原回奇数值。 最多可以进行 60 轮有意义的差异减半。 大约 60⋅61+60（低于 5000）的宽松界限已经足以满足所需的限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 减法欧几里得| O(最大(A,B)) | 最坏情况下的 O(max(A,B)) 输出 | 太慢了 |
 | 基于减半的 Euclid | O(logmax(A,B)) 概念回合，加上输出 | 奥(5000) | 已接受 |

 ## 算法演练

 1. 阅读`A`和`B`。 如果它们已经相等，则输出零运算。 没有什么可以构建的。 
2. 虽然`A`和`B`不同，重复删除其中两个因子`A`。 从概念上讲，替换`A`经过`A/2`通过执行来模拟`B += B`。 实际的对在其第二个坐标中加倍，因此真实状态仍然是概念状态的公倍数。 
3. 做同样的事情`B`。 每个概念的划分`B /= 2`模拟为`A += A`。 
4. 两个值均为奇数后，进行比较。 如果`A < B`， 履行`B += A`并在概念上更新`B`到`A + B`。 新的`B`是偶数，因为它是两个奇数之和。 
5.如果`B < A`，对称执行`A += B`并在概念上更新`A`到`A + B`。 同样，新的较大值是偶数，并且可以在下一次迭代期间减半。 
6. 继续，直到概念值变得相等。 然后按照原始顺序打印记录的操作。 因为每个概念状态都由实际状态表示，直至公共比例因子，所以概念值的相等意味着实际变量的相等。 

算法快速终止的原因是，在两个值都是奇数之后，将较小的值与较大的值相加，然后将较大的值减半，从而改变了与`D`到`D/2`。 因此，每次奇数转换，差异至少会丢失一个二进制数字。 只要有可能，这些值本身也会损失两倍，因此轮数和发出的操作数都无法接近巨大的输入量级。 

### 为什么它有效

 保持实际变量对是概念变量对的公正倍数这一不变量`(A, B)`由算法维护。 最初乘数为 1。 

当算法概念上划分时`A`两倍，记录的操作是实际操作的两倍`B`。 如果实际的一对是`k(A,B)`，就变成`(kA,2kB)`，等于`2k(A/2,B)`。 同样的论点也适用于概念上的划分`B`。 

当算法将较小的数字与较大的数字相加时，相应的实际操作对实际的数字对执行完全相同的加法，从而保留了常见的缩放关系。 因此，每次操作后，不变式都成立。 

当概念值相等时，实际值是相同的乘数乘以这些相等值，因此实际变量根据需要相等。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    a, b = map(int, input().split())    operations = []
    while a != b:        while a % 2 == 0:            # Conceptually: a /= 2            # Actually: double b, so the real pair is scaled by 2.            operations.append("B+=B")            a //= 2
        while b % 2 == 0:            # Conceptually: b /= 2            # Actually: double a.            operations.append("A+=A")            b //= 2
        if a < b:            operations.append("B+=A")            b += a        elif b < a:            operations.append("A+=B")            a += b
    print(len(operations))    sys.stdout.write("\n".join(operations))

if __name__ == "__main__":    solve()
```两人`while`循环实现概念上的减半操作。 什么时候`a`是偶数，代码记录`B+=B`但改变了概念`a`到`a // 2`。 The same relationship is used in reverse for an even`b`。 

在更新概念变量之前记录加法操作。 这种顺序很重要，因为打印操作描述了真实状态发生的情况，而局部变量表示规范化的概念状态。 

Python整数具有任意精度，因此在构造序列时不存在溢出问题。 在固定宽度语言中，实际值可能暂时超过 10 18，因此需要使用足够宽的整数类型。 

这`elif`也是故意的。 第一次比较后，只有一个变量可以较小。 没有理由在一次迭代中执行这两项添加。

 ### 示例 1

 For the provided input`2 3`，算法首先注意到`A`是均匀的。 它记录了`B+=B`以及概念上的改变`A`从2到1。 

| 步骤| 运营| 概念A | 概念B | 实际A | 实际 B |

 考虑`1 5`。 两个数字都以奇数开头，并且`A < B`，所以算法添加`A`到`B`。 新概念`B`是 6，是偶数，因此下一个操作在概念上将其减半。 

| 步骤| 运营| 概念A | 概念B | 实际A | 实际 B |

 概念值之间的差异从 4 到 2，然后到 1。实际序列仅经过五次操作就以相等的值结束，尽管原始值被四分开。

 ## 边缘情况

 对于`1 1`，外层循环永远不会启动，因为概念值已经相等。 程序打印出`0`并且没有任何操作。 盲目进入循环的结构可能会意外地发出不必要的操作并错过最简单的有效答案。 

为了`2 3`，第一个值是偶数。 算法记录`B+=B`并从概念上改变了这对`(2,3)`到`(1,3)`。 真实的一对变化自`(2,3)`到`(2,6)`，是概念对的两倍。 后续操作产生`(2,8)`进而`(4,8)`，这样就达到了平等。 

为了`1 5`，两个值都是奇数且不相等。 该算法执行`B+=A`，给出概念性的`(1,6)`，然后反复从 6 中删除因数 2。概念状态是`(1,5)`,`(1,6)`,`(1,3)`,`(1,4)`,`(1,2)`,`(1,1)`。 实际状态结束于`(8,8)`。 此案例说明了为什么奇数对必须首先使用加法来创建偶数值。 

为了`1 1000000000000000000`，减法欧几里得需要近 10 18 次加法。 相反，所提出的算法重复地将概念偶数减半。 在大约 60 次减半后，该值从 10 18 下降到 5，而每一次概念性减半仅对应一次打印操作。 其余的奇数过渡也以几何方式减少了差异，使整个结构安全地保持在 5000 次操作以下。 

为了`999999999999999999 1000000000000000000`，数字是连续的并且具有不同的奇偶性。 从概念上讲，偶数立即减半，之后算法重复归一化奇偶校验，并在必要时添加较小的奇数。 这捕获了假设两个数字具有相同奇偶校验或忘记在加法后重新检查奇偶校验的实现。
