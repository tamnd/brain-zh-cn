 ## 解决方案
 ## 问题理解

 我们从两个正整数开始，`A`和`B`。 更改它们的唯一方法是将当前值之一添加到任一变量。 因此，一项操作可以将一个变量加倍，或者用两个变量之和替换一个变量。 目标是输出最多 5000 个此类操作的任何序列，使两个值相等。 输入包含初始值`A`和`B`, 每个最多\(10^{18}\)。 官方竞赛声明正是有这样的结构和限制。 citeturn3search1

 的界限\(10^{18}\)立即排除任何操作次数与值线性相关的方法。 一个建筑需要\(A+B\),\(|A-B|\)，甚至 \(\max(A,B)\) 步可能需要大约\(10^{18}\)运营。 5000 次操作限制是真正的算法约束，因此我们需要一个对数或类似的小型构造。 由于输入仅包含两个整数，因此不需要复杂的数据结构，并且内存限制足够大，存储几千个操作字符串是微不足道的。 

第一个边缘情况从一开始就是平等的。 用于输入`5 5`，正确的输出很简单`0`，因为不需要任何操作。 总是进入归约循环的粗心实现可能会执行不必​​要的操作，更严重的是，可能会偏离已经有效的答案。 

第二个边缘情况是偶数值。 用于输入`4 6`，我们可以从概念上将这对简化为`(1, 3)`将两个值减半，但允许的运算不包含除法。 建筑必须间接地实现这些划分。 输出`B+=B`对应于治疗`A`去掉二的公因数后减半，而`A+=A`起着对称作用`B`。 直接写`A//=2`如果不产生相应的运算，则会产生数学上有用的计算，但会产生无效的答案。 

第三种边缘情况是一对奇值。 用于输入`3 5`，将较小的值与较大的值相加得到`(3, 8)`。 新的较大值是偶数，因此可以在归一化表示中减半。 如果我们在不使用奇偶校验的情况下重复添加较小的值，则这些值可能会增长而不是接近相等。 

## 方法

 一种直接的方法是搜索可能的操作序列。 每个州都有四种选择，所以之后\(k\)步骤可以有多达\(4^k\)要考虑的序列。 搜索到允许的深度 5000 是完全不可能的，因为序列计数约为\(4^{5000}\)。 即使记忆状态也没有给出有用的界限，因为值增长很快并且可到达的状态太多。 

更自然的建设性尝试是本着与欧几里德算法相同的精神使用加法。 问题在于欧几里得算法需要减法，而每个可用的运算只需要加法。 例如，从`(1, 1000000000000000000)`，如果我们尝试直接模拟减法，则重复将较小的值与较大的值相加将需要大量的加法。 

关键的观察结果是，将两个数字乘以相同的正因子不会影响它们是否相等。 我们可以自由地推理通过除以两个的公因子而获得的归一化对。 这让我们将加倍操作重新解释为虚拟减半操作。 

假设标准化对是`(A, B)`和`A`是均匀的。 如果我们进行真正的操作`B+=B`，物理对变为`(A, 2B)`。 如果我们从概念上将两个值除以二，这相当于`(A/2, B)`。 因此，一次合法操作为我们提供了与减半相同的标准化状态`A`。 相似地，`A+=A`可以看作是减半`B`在标准化表示中。 

一旦两个归一化值都是奇数，假设`A < B`。 我们表演`B+=A`, 给予`(A, A+B)`。 由于两个操作数都是奇数，`A+B`是偶数，因此下一个归一化可以将较大的值除以二。 概念转变是\[
(A,B)\rightarrow \left(A,\frac{A+B}{2}\right).
\]这是关键的减少。 如果`B-A=C`，那么在此转换之后新的差异是\[
\frac{A+B}{2}-A=\frac{B-A}{2}=\frac C2.
\]因此，当两个值都是奇数时，先进行一次加法，然后进行归一化，将差异大致减半。 这与二进制欧几里得算法背后的奇偶校验思想相同。 

所得到的构造重复地删除因子 2，然后将较小的奇值与较大的奇值相加。 归一化值稳步下降，直到它们都变为一，此时实际值相等，因为所有变换都保留了相等关系。 详细的操作计数参数给出了低于 5000 的界限，更严格的分析给出了 3969 次操作，值高达\(10^{18}\)。 引用turn4view0

 ## 算法演练

 1. 保留`a`和`b`作为用于推理的标准化值。 它们不代表每次操作后判断器存储的文字值。 相反，它们表示除去两个的公因数后的等价对。 

2. 虽然`a`是偶数，附加`B+=B`到答案并替换`a`经过`a // 2`。 实际操作加倍`B`，并且在概念上将两个值除以 2 后，归一化状态与减半完全相同`a`。 

3.同时`b`是偶数，附加`A+=A`并替换`b`经过`b // 2`。 这就是对称变换。 实际操作加倍`A`，相当于减半`B`去掉两者的公因数后。 

4. 如果`a == b`， 停止。 归一化值相等，因此它们代表的实际值也相等。 

5. 如果两个归一化值现在都是奇数且`a < b`, 附加`B+=A`并替换`b`经过`a + b`。 两个奇数之和是偶数，因此下一次迭代将能够减半`b`。 

6. 如果两个归一化值都是奇数且`b < a`, 附加`A+=B`并替换`a`经过`a + b`。 同样，更新后的较大值是偶数，并且将在下一次迭代开始时减半。 

从差异中最容易看出流程取得进展的原因。 认为`a < b`两者都很奇怪。 加起来并随后减半后，差值变为`(b-a)/2`。 因此，每当需要加法步骤时，两个归一化值之间的距离就会减小两倍。 奇偶校验删除步骤本身减少了数字。 

### 为什么它有效

 不变的是归一化对`(a, b)`表示当前实际对，直到两个值乘以相同的 2 的正幂。 这种共同的缩放不能改变两个值是否相等。 

什么时候`a`是偶数，`B+=B`更改实际对`(A,B)`到`(A,2B)`。 两者除以二给出`(A/2,B)`，因此替换归一化`a`经过`a/2`是合法的。 同样的论点适用于`b`是均匀的。 

当两个归一化值都是奇数且不相等时，将较小的值与较大的值相加是合法的操作。 所得的较大值是偶数，并且以下归一化将其减半。 如果较小的值是`a`，这对概念从概念上发生了变化`(a,b)`到`(a,(a+b)/2)`。 新的区别是`(b-a)/2`，因此该过程不能永远保持相同的正差。 最终归一化值达到相等，然后不变量告诉我们实际值也相等。 

操作数也足够小，不超过 5000 次限制。 一个有用的界限将过程分为几个阶段，其中标准化值的乘积至少减少两倍。 每个这样的阶段最多需要\(2\lfloor\log_2 B\rfloor+1\)操作，并且因为初始产品如下\(10^{36}\)，对这些界限求和得出的操作数少于 7200 次。 更清晰的相位分析给出了所需的 3969 界限，远低于 5000。 citeturn6view0turn4view0

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    ans = []

    while a != b:
        while a % 2 == 0:
            ans.append("B+=B")
            a //= 2

        while b % 2 == 0:
            ans.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            ans.append("B+=A")
            b += a
        else:
            ans.append("A+=B")
            a += b

    print(len(ans))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```输入被读取一次，因为问题具有一对值。 这`ans`数组存储必须打印的确切合法操作。 

第一个`while`循环处理每个因数二`a`。 答案附加的操作是`B+=B`， 不是`A+=A`，因为将另一个实际值加倍就可以减半`A`共同归一化后有效。 这种逆转是最容易出错的实现细节。 

第二个循环执行对称操作`b`。 由于原始值最多为\(10^{18}\)，Python的整数绰绰有余，不存在溢出问题。 

两次循环后，如果归一化值相等，则构造完成。 否则两者都是奇怪的。 正好有一个较大，所以我们将较小的一个添加到较大的一个中。 新的较大值是偶数，这保证了下一次迭代中有用的工作。 

该代码并未显式模拟每次操作后的实际值。 这样做是不必要的，而且会使推理变得混乱。 归一化值就足够了，因为每个减半步骤都代表从实际对中删除 2 的公因数。

 ## 边缘情况

 对于`5 5`，算法进入外循环条件`a != b`，看到它已经是假的，并立即打印零操作。 这是唯一合理的构造，因为目标条件已经成立。 

为了`4 6`，归一化算法首先从其中删除两个因子`a`。 第一个`B+=B`代表`4 -> 2`，第二个代表`2 -> 1`。 然后`A+=A`代表`6 -> 3`。 现在是正常化状态`(1,3)`。 操作`B+=A`从概念上将其更改为`(1,4)`，之后两个`A+=A`操作代表`4 -> 2 -> 1`。 归一化状态达到`(1,1)`，实际值已达到`(32,32)`。 

为了`1 1000000000000000000`，大值包含许多二的因素。 该算法使用以下方法消除了这些因素`A+=A`标准化表示中的操作，而不是执行\(10^{18}\)个别补充。 一旦暴露出剩余的奇数部分，加法步骤就会重复将相关差值减半。 这正是直接加法方法会失败但基于奇偶校验的构造仍保持在操作限制内的情况。 

为了`999999999999999999 1000000000000000000`，值相邻但具有相反的奇偶性。 第一个奇偶校验消除阶段立即通过虚拟减半来改变偶数归一化值。 该算法从不假设原始值都是奇数，只是在奇偶校验删除循环之后它们都是奇数。 此边界条件可防止奇数加奇数转换的错误应用。 

为了`1 1`，最小可能的输入，答案又是零。 为了`1000000000000000000 1000000000000000000`，最大可能的相等输入表现相同。 当相等已经存在时，整数的大小没有影响。
