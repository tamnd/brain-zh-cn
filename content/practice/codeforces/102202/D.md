 ## 解决方案
 ## 问题理解

 我们有两个正整数`A`和`B`，最初最多 (10^{18})。 唯一允许的移动将当前值之一添加到任一变量。 目标是产生最多 5000 次此类移动的序列，之后两个变量相等。 法官接受任何有效的序列，因此我们可以自由地为了简单性而不是为了唯一的答案进行优化。 官方问题正是使用了这四个操作和相同的 5000 步限制。 

(10^{18}) 的大小限制排除了与任一输入的数值成比例的任何内容。 重复添加较小数字的策略可能需要几乎 (10^{18}) 次操作，这远远超出了 5000 次移动预算。 同时，输入仅包含两个整数，因此我们可以进行对数甚至几千次算术运算。 Python 整数还可以处理超出 (10^{18}) 的值，这很有用，因为中间加法可能会暂时超出输入范围。 

第一个边缘情况从一开始就是平等的。 用于输入`5 5`，正确的输出很简单`0`，因为不需要任何操作。 总是执行至少一个操作的粗心实现永远无法从中恢复，因为每个允许的操作都会严格增加这两个值之一。 

第二种边缘情况是一个值为偶数而另一个值为奇数时。 用于输入`2 3`，我们不能从字面上划分`2`乘以二，因为除法不是允许的运算。 有用的技巧是将另一个变量加倍。 后`B+=B`，实际状态变为`(2, 6)`，这恰好是概念状态的两倍`(1, 3)`。 直接编写除法运算的解决方案将产生无效的输出。 

第三种边缘情况是两个值都是偶数时，例如`8 12`。 将两个概念值除以二给出`(4, 6)`，并且这不会改变该对最终是否可以相等。 一次只处理一个偶数的粗心实现仍然可以工作，但它可能会掩盖常见的缩放不变量，并使终止参数更难建立。 

第四个边缘情况是一个大的奇数对，例如`1 999999999999999999`。 反复添加`1`到更大的值将需要几乎 (10^{18}) 次操作。 相反，预期的构造利用了两个奇数之和为偶数这一事实，允许在一次加法后大幅减少 2 的幂。 

## 方法

 一种直接的方法是反复将较小的值与较大的值相加。 如果`A < B`，我们执行`B += A`; 如果`B < A`，我们执行`A += B`。 这是正确的，因为每当较小的值与较大的值相加时，两个值之间的差异就会减小，并且最终这些值对于正整数而言变得相等。 

问题在于操作次数。 为了`(1, 10^18)`，这个贪心方法需要 (10^{18}-1) 次加法。 即使对可能的操作序列进行详尽的搜索也会更糟糕，因为每一步都有四个操作可用，从而在深度 (k) 处给出了大约 (4^k) 个序列的搜索空间。 这两种方法都完全没有达到 5000 步限制的目的。 

关键的观察是，如果两个数字乘以或除以同一个正整数，则为了确定是否可以达到相等，状态保持不变。 假设概念状态是`(A/2, B)`， 在哪里`A`是均匀的。 将两个概念值乘以 2 得出`(A, 2B)`， 和`(A, 2B)`从真实状态获得`(A, B)`准确地使用`B += B`。 因此`B += B`可以模拟除法`A`两个。 对称地，`A += A`可以模拟除法`B`两个。 

一旦两个概念值都是奇数，它们就不可能相等，除非它们都是一。 如果`A < B`，添加`A`到`B`给出`A + B`，这是偶数。 然后我们可以重复模拟该新值除以二，直到它再次变为奇数。 这类似于压缩的欧几里得算法，只不过我们不是做减法，而是加一次，然后除以 2 的幂。 差异以对数尺度反复减小。 

由此产生的算法完全基于奇偶校验。 每当一个值是偶数时，从概念上删除两倍并发出相反变量的加倍运算。 当两个值都是奇数且不相等时，将较小的值与较大的值相加，然后从所得的偶数值中删除所有 2 的因数。 这种结构是该问题的标准解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重复添加较小的值 | (O(\max(A,B))) 操作 | (O(1)) 除了输出 | 太慢了|
 | 详尽的搜索| (O(4^{5000})) 最坏情况 | 指数| 太慢了 |
 | 平价和减半建设| (O(\log^2 \max(A,B))) | (O(\log \max(A,B))) 输出 | 已接受 |

 ## 算法演练

 1. 阅读`A`和`B`。 如果它们已经相等，则输出零运算。 这是算法在进行任何转换之前应终止的唯一情况。 
2. 虽然`A`是偶数，概念上替换`A`经过`A / 2`。 在实际序列中，附加`B+=B`反而。 如果概念状态是`(A/2, B)`，将两个值加倍得到`(A, 2B)`，正是真实操作产生的状态。 
3.同时`B`是偶数，概念上替换`B`经过`B / 2`。 在实际序列中，附加`A+=A`。 同样的通用缩放参数也适用，因为`(A, B/2)`乘以二是`(2A, B)`。 
4. 奇偶校验清理后，如果`A == B`， 停止。 现在这两个值都是奇数，因此公共缩放解释保留了相等性。 
5. 如果两个值都是奇数并且`A < B`, 附加`B+=A`。 从概念上讲，这对变成了`(A, A+B)`。 由于两个奇数的和为偶数，因此第二个值现在可以被二整除。 
6. 继续奇偶校验清理。 每除以二表示为`A+=A`什么时候`B`是均匀的。 这会反复缩小新放大的值，直到变成奇数。 
7. 如果两个值都是奇数并且`B < A`，执行对称运算`A+=B`，然后进行奇偶校验清理。 较大的值变得均匀，因此可以立即减少 2 的幂。 
8. 重复直到概念值相等。 该构造达到了相等性，因为奇数到奇数的转换将相关差异减少了两倍，而中间的减半操作仅从值中删除了 2 的幂。 

### 为什么它有效

 中心不变量是真实状态始终是概念状态的公二次方倍数。 当概念算法划分时`A`乘以二，真正的算法反而加倍`B`，得到的实际对恰好是概念对的两倍。 同样的论证在除法时也适用`B`。 

当两个概念值都是奇数且不相等时，假设`A < B`。 后`B += A`，概念对是`(A, A+B)`。 将第二个值除以二得出`(A, (A+B)/2)`在任何进一步的划分之前。 差异变为

 [
 \frac{A+B}{2}-A=\frac{B-A}{2}。 
]

 如果需要额外的除法，新处理的值只会变小。 因此，算法反复移动到较小规模的对。 由于这些值是正整数，因此该过程不能无限地继续并最终达到相等。 该构造及其对数行为由同一问题的独立解决方案记录。 

移动界限也正好低于 5000。输入以 (10^{18}<2^{60}) 为界限，2 的相关幂数最多为 60。此结构的标准充电参数给出的界限约为 (60^2+O(60))，大约 3600 次操作，在所需的 5000 次以下留下了很大的空间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    ans = []

    while a != b:
        # Conceptually divide A by 2.
        # In the real state, double B instead.
        while a % 2 == 0:
            ans.append("B+=B")
            a //= 2

        # Conceptually divide B by 2.
        # In the real state, double A instead.
        while b % 2 == 0:
            ans.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            # Conceptually: b <- a + b
            # Since a and b are odd, the new b is even.
            ans.append("B+=A")
            b += a
        else:
            # Conceptually: a <- a + b
            # Since a and b are odd, the new a is even.
            ans.append("A+=B")
            a += b

    print(len(ans))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```两个内部循环实现模拟除法。 当概念代码执行时`a //= 2`，实际操作是`B+=B`。 我们仅更新概念`a`在程序中，因为未来的决策是根据标准化表示做出的。 发出的操作序列对于原始变量仍然有效，因为每个概念状态与相应的真实状态仅相差一个公因子。 

奇偶校验使用`a % 2 == 0`而不是任何浮点运算，因此 (10^{18}) 附近的值不存在精度问题。 Python 的任意精度整数还消除了在固定宽度语言中执行以下操作时可能出现的溢出问题：`a += b`暂时接近 (2\cdot10^{18})。 

两个奇偶校验循环的顺序在概念上很重要。 我们首先从其中删除所有 2 的因子`A`，然后两个的所有因数`B`，然后才执行加法。 因此，每次加法都发生在两个奇数概念值之间，因此被放大的值一定会变成偶数。 

输出计数取自生成的操作列表，因此它不能与操作行数不一致。 该问题只有一个测试用例，因此没有外部测试用例循环。

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return solve_text(inp)

def validate(inp: str):
    a0, b0 = map(int, inp.split())
    out = run(inp)
    lines = out.strip().splitlines()

    n = int(lines[0]) if lines else 0
    assert 0 <= n <= 5000
    assert len(lines) == n + 1

    a, b = a0, b0

    for op in lines[1:]:
        if op == "A+=A":
            a += a
        elif op == "A+=B":
            a += b
        elif op == "B+=A":
            b += a
        elif op == "B+=B":

 ## 边缘情况

 对于`1 1`，立即跳过外层循环，因为变量已经相等。 输出恰好包含一行`0`。 不需要任何操作，更重要的是，执行任意操作都会使该对不相等。 

为了`2 3`，第一次奇偶校验清理看到`A`是均匀的。 概念值变为`1`，而实际输出是`B+=B`。 实际状态从`(2,3)`到`(2,6)`，是概念值的两倍`(1,3)`。 下一步操作`B+=A`产生`(2,8)`，对应于概念`(1,4)`。 二`A+=A`操作然后产生`(8,8)`。 即使算法内部推理出较小的值，输出在原始变量中也是有效的。 

为了`8 12`，前两个概念简化给出`(4,12)`和`(4,6)`，代表为`B+=B`其次是`A+=A`。 进一步奇偶校验清理达到`(2,3)`。 从那里开始，该对是奇数且不相等的，因此算法将较小的值添加到较大的值并开始另一个减半阶段。 此案例说明了为什么实现必须在每次加法后继续消除 2 的幂，而不是在一次除法后停止。 

为了`1 576460752303423488`，第二个值为 (2^{59})。 奇偶校验循环反复将概念性减半`B`发射时`A+=A`按实际顺序进行操作。 经过 59 次这样的概念划分后，这对就变成了`(1,1)`。 这正是使用固定数量的奇偶校验迭代或浮点对数公开实现的输入类型。 

为了`5 13`，两个值都是奇数且不相等。 自从`5 < 13`，算法发出`B+=A`，给出概念对`(5,18)`。 新的第二个值是偶数，因此下一个发出的操作是`A+=A`，从概念上将其简化为`9`。 这对就变成了`(5,9)`，差异已从`8`到`4`。 同样的机制一直持续到达到平等为止。 这是核心缩减，用对数多次运算取代了潜在的巨大重复加法。
