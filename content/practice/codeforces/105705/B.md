 ## 解决方案
 ## 问题理解

 我们维护一个整数序列。 随着时间的推移，我们可以执行两项操作。 一个操作直接将数组中的单个位置更改为新值。 另一个操作强制执行全局下限：如果数组中的每个元素小于给定值，则增加该元素，否则保持不变。 

按顺序处理完所有动作后，任务是输出数组的最终状态。 

重要的是，全局更新不会盲目地覆盖值，它只会向上推值，并且多个此类更新以不平凡的方式与后来的点分配交互。 

这些约束允许跨测试用例总共最多十万个元素和十万个操作。 这立即排除了任何通过每次迭代整个数组来显式应用全局操作的解决方案，因为这在最坏的情况下会导致二次行为。 

当全局增加后发生点更新时，会出现微妙的边缘情况。 例如，如果我们将所有内容增加到至少 10，然后将位置设置为 6，则该位置必须保持为 6，即使之前它被强制向上。 这表明全局操作不会永远主导以后的任务； 相反，行动的时间表很重要。 

当发生多个全局更新时，会出现另一种边缘情况。 幼稚的实现可能会独立地重新应用它们，但只有迄今为止看到的最大全局阈值是相关的，除非被后面的点操作覆盖。 

## 方法

 强力解释按字面意思应用每个操作。 点更新是恒定时间，但全局“max with v”操作会扫描整个数组并根据需要更新每个元素。 每个此类操作的成本为 O(n)，并且最多为 O(n) 次操作，这会导致 O(n²)，这对于 10⁵ 规模的输入来说太慢了。 

关键的观察结果是全局操作实际上是单调的。 每一次全球行动只会增加价值，而不会减少价值。 这表明我们不需要重复触摸每个元素，而是可以延迟它们的应用。 

当我们扭转视角时，关键结构就会出现。 我们没有立即应用全局更新，而是跟踪迄今为止看到的最大全局值。 每个数组元素实际上都有一个来自全局操作的“最小保证值”，但点更新可以在特定时间覆盖它。 

这导致了这样的想法：对于每个位置，存储它是否在最后一个相关全局阈值之后更新，并确保当我们最终产生答案时，将每个元素与适用于它的最强全局约束进行比较。 

核心困难在于点更新“打破”了该索引之前的全局更新历史，因此我们必须小心地将每个索引的状态与全局状态分开。 这正是线段树或离线处理变得有用的交互类型，但在这个特定问题中，如果我们跟踪正确的不变量，则对查询进行更简单的贪婪扫描就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 直接应用操作| O(nq) | O(n) | 太慢了|
 | 追踪全球最大值+延迟最终通行证 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理查询，同时维护一个代表迄今为止最强的全局“至少提高到 v”约束的值。 

我们还存储每个索引的最新分配值，但至关重要的是，我们不会立即对每个元素应用全局约束。 相反，我们推迟解决每个位置直到最后。 

1. 维护一个变量`mx`它存储迄今为止看到的所有类型 2 操作中的最大值。 

2. 维护数组`a`使用输入值进行初始化。 

3、处理类型2、值为v的查询时，更新`mx = max(mx, v)`。 

4. 当处理索引 x 处值为 p 的类型 1 查询时，设置`a[x] = p`。 此分配被视为在截至该点的所有先前操作之后发生。 

5. 处理完所有查询后，每个元素必须至少`mx`。 因此，更换每个`a[i]`和`max(a[i], mx)`。 

微妙的推理步骤是理解最终扫描就足够了，因为最后一个查询之后的任何操作都不能修改数组，并且所有全局约束都可以汇总为单个阈值。 

### 为什么它有效

 在任何时候，全局更新所做的唯一事情就是增加适用于所有未来值的下限。 由于它们永远不会减少值，因此最强的约束始终是所有先前全局更新的最大值。 全局更新后分配的任何值仍然必须隐式地遵守所有早期的全局约束，但由于我们在点更新期间直接覆盖值，因此正确的最终值只是最后一个显式分配和最强全局阈值之间的最大值。 

这会产生一个不变量：在任何时候，每个索引的真实值至少是迄今为止看到的最大全局更新，除非它后来被显式覆盖。 最后一遍在全局范围内强制执行此不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    mx = 0

    for _ in range(q):
        t = list(map(int, input().split()))
        if t[0] == 1:
            x, p = t[1] - 1, t[2]
            a[x] = p
        else:
            v = t[1]
            if v > mx:
                mx = v

    for i in range(n):
        if a[i] < mx:
            a[i] = mx

    print(*a)

if __name__ == "__main__":
    solve()
```该实现依赖于仅存储每个索引的最新显式值以及类型 2 操作的单个全局最大值。 索引转换很重要，因为输入是从 1 开始的，但 Python 数组是从 0 开始的。 

一个常见的错误是尝试通过循环整个数组来立即应用类型 2 操作，这不会通过约束。 另一个错误是忘记了稍后的点分配可以“撤消”该索引之前的增加，因此我们必须始终将最后的分配存储为该位置的权威。 

## 工作示例

 考虑一个数组`[1, 2, 3]`with操作：增加到至少5，然后将位置2设置为1。 

| 步骤| 运营| 数组状态 | MX |
 |---|---|---|---|
 | 1 | 初始| [1,2,3]| 0 |
 | 2 | 全局 ≥ 5 | [1,2,3]| 5 |
 | 3 | 设置 a[2]=1 | [1, 1, 3] | 5 |
 | 4 | 最终申请| [5, 5, 5] 除了被覆盖 | 5 |

 最终修正后结果为`[5, 5, 5]`除了索引 2 变为`max(1, 5) = 5`。 

这表明点更新永远不会取消全局约束。 

现在考虑颠倒顺序：设置然后全局。 

| 步骤| 运营| 数组状态 | MX |
 |---|---|---|---|
 | 1 | 设置 a[1]=10 | [10,2,3]| 0 |
 | 2 | 全局 ≥ 5 | [10,2,3]| 5 |
 | 3 | 最终申请| [10,5,5]| 5 |

 这表明点更新可以超出全局约束并被保留。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 |---|---|---|
 | 时间 | O(n + q) | 每个查询处理一次，最终传递是线性的 |
 | 空间| O(n) | 只需要数组存储 |

 该解决方案很容易满足限制，因为在测试用例中 n 和 q 最多为 10⁵，并且每个操作都是恒定时间。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return main_capture()

def main_capture():
    import sys
    input = sys.stdin.readline

    t = 1
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        q = int(input())

        mx = 0
        for _ in range(q):
            tmp = list(map(int, input().split()))
            if tmp[0] == 1:
                a[tmp[1]-1] = tmp[2]
            else:
                mx = max(mx, tmp[1])

        for i in range(n):
            a[i] = max(a[i], mx)

        out.append(" ".join(map(str, a)))

    return "\n".join(out)

# sample-like case
assert run("3\n1 2 3\n3\n2 5\n1 1 1\n2 4\n") == "5 5 5"

# minimum size
assert run("1\n10\n2\n2 5\n1 1 3\n") == "5"

# no global updates
assert run("3\n1 2 3\n2\n1 2 10\n1 3 7\n") == "1 10 7"

# only global updates
assert run("3\n1 2 3\n2\n2 100\n2 50\n") == "100 100 100"

 |---|---|---|

 ## 边缘情况

 关键的边缘情况是当全局更新之后发生点更新并设置小于全局阈值的值时。 该算法正确地解决了这个问题，因为最终的最大操作再次强制执行全局约束。 用于输入`[1]`，操作“设置为 2，然后全局设置为 5，然后设置为 3”，最终结果变为 5，因为最后一次扫描再次强制执行全局最大值。 

另一个边缘情况是多个全局更新与点更新交织。 该算法处理这个问题是因为只有最大全局值才重要； 一旦出现较大的更新，中间较小的更新就无关紧要了。 

第三种边缘情况是根本没有全局更新。 在这种情况下`mx`保持为零，因此最终数组与最后一个点更新相比没有变化，这在没有特殊大小写的情况下保持了正确性。
