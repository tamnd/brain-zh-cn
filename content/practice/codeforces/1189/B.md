 ## 解决方案
 ## 问题理解

 我们得到一组数字，并询问是否可以将它们全部放在一个圆上，以便每个元素都严格小于其两个相邻元素的总和。 邻接是循环的，因此第一个和最后一个元素也是邻居。 

条件是局部的，每个值仅针对其两个邻居进行检查，但放置是全局的。 这很重要，因为重新排列单个元素可能会同时影响两个不等式。 

约束允许最多$10^5$数值高达$10^9$。 任何尝试所有排列的解决方案都是立即不可能的，因为$n!$即使对于$n = 20$。 这推动我们走向$O(n \log n)$或者$O(n)$战略。 

当一个元素与其他元素相比非常大时，就会出现微妙的边缘情况。 例如，如果我们有`[100, 1, 1, 1]`，任何排列都会迫使 100 位于两个总和最多为 2 的小值之间，从而违反了条件。 如果不考虑最终的环绕约束，则在构建循环时仅检查部分局部有效性的天真贪婪可能会错误地接受此类情况。 

当值几乎相等时，会出现另一个棘手的情况。 例如`[3, 3, 3, 3]`有效，但是`[3, 3, 3, 2]`也有效，同时`[10, 3, 3, 3]`失败。 差异不在于局部邻接性，而在于最大元素的相对优势。 

## 方法

 蛮力的想法很简单：尝试数字的每种排列并检查所有循环邻接约束是否成立。 对于每一种安排，我们都会扫描所有$n$位置并验证$a_i < a_{i-1} + a_{i+1}$。 这是正确的，因为它直接测试条件，但它需要$O(n \cdot n!)$操作，甚至远远超出任何限制$n = 10$。 

关键的见解来自于关注真正可以打破这种状况的因素。 如果某个元素太大，无论顺序如何，它都可能会对其邻居失败，除非这些邻居也很大。 这表明最大的元素主导可行性。 

排序揭示了结构。 假设我们对数组进行排序。 如果最大的元素与第二大和第三大的元素相比太大，那么没有任何安排可以修复它，因为在一个圆圈中，最大的元素总是有两个邻居，为了最大限度地保护它，我们必须在它旁边放置下一个最大的可能数字。 如果这些还不够，那么答案就是不可能的。 

如果条件可能满足，下一个想法是避免将大量数字彼此相邻，从而导致少量“支持”匮乏。 此类“邻居和”问题的标准构造是将数字以之字形或围绕圆交替的模式放置，以便将大值分开，并且每个位置都由中等大的邻居支持。 

排序后，我们将数组分开并交错两半。 这确保了大元素被间隔开，并且没有一个大值最终与两个非常小的值相邻。 这种结构正是保持每个元素严格小于其邻居元素之和所需的。

 | 蛮力 |$O(n \cdot n!)$|$O(n)$| 太慢了|
 | 排序+构建|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 如果存在，我们使用排序和交错构造一个有效的排列。 

1. 对数组进行非降序排序。 这为我们提供了从小到大元素的清晰排序，这对于控制邻接效应是必要的。 
2. 将排序后的数组分成两部分，较小的一半和较大的一半。 这个想法是为了防止大元素聚集在一起。 
3. 将两半的元素交错，始终在较大一侧和较小一侧之间交替。 这会将大值均匀地分布在圆周围，并确保每个大元素都与较小的元素相邻。 
4. 构建循环后，以循环方式验证每个索引的条件。 如果任何索引违反$a_i < a_{i-1} + a_{i+1}$，该安排无效。 
5、如果检查通过，则输出排列； 否则输出NO。 

### 为什么它有效

 正确性依赖于控制最大元素的局部环境。 在任何有效的解决方案中，最大值必须受到足够大的邻居的“保护”。 排序可确保我们知道哪些值可以提供该支持。 交错保证没有大元素只被小元素包围，同时仍然保持大元素分离。 

关键的不变量是，构造后，每个元素都与已排序数组的另一半中的至少一个元素相邻。 这可以防止病态配置，即大值夹在两个小值之间，这是不等式在顶端失败的唯一方法。 一旦最大的元素是安全的，较小的元素就会自动满足条件，因为它们的邻居至少包含中等大的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    # interleave halves
    left = a[:n//2]
    right = a[n//2:]
    
    res = []
    
    i = 0
    j = 0
    
    while i < len(right) or j < len(left):
        if i < len(right):
            res.append(right[i])
            i += 1
        if j < len(left):
            res.append(left[j])
            j += 1
    
    # verify circular condition
    for k in range(n):
        if res[k] >= res[(k-1) % n] + res[(k+1) % n]:
            print("NO")
            return
    
    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先对数组进行排序，以便元素之间的结构关系变得明确。 然后，它将数组分成两半并交错排列，交替放置上半部分的较大值和下半部分的较小值。 这保证了大值不相邻。 

构造完成后，验证循环直接检查循环条件。 模索引确保第一个和最后一个元素之间的环绕邻接。 构造有意简单化，依靠排序来强化结构，而不是在放置期间尝试局部修复。

 ## 边缘情况

 一个关键的边缘情况是当一个元素明显大于所有其他元素时。 输入中`[10, 1, 1]`，该算法仍然会产生圆形排列，但验证正确地拒绝了它，因为最大元素的邻居总和仅为 2。这说明了为什么在没有最终验证步骤的情况下仅构建是不够的。 

另一个微妙的情况是所有元素都相等。 为了`[5, 5, 5, 5]`，任何圆形排列都满足条件，因为每个值都严格小于其邻居的总和。 该算法构造了一个交错，但检查很容易通过，确认不需要特殊处理。 

第三种情况涉及临界金额，例如`[1, 2, 3]`。 在排序和交错之后，该结构确保每个元素都有其总和超过它的邻居，即使一个元素接近相等。 验证循环确认正确性并防止意外接受无效排列。
