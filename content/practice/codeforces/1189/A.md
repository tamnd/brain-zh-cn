 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，它是仅包含的字符序列`0`和`1`。 如果零的数量与一的数量不同，则该字符串被定义为良好。 任务是将原始字符串分割成最少数量的连续子串，使得每个子串都是好的。 输出必须首先说明子字符串的数量，然后是子字符串本身，并用空格分隔。 

限制很小：字符串长度$n$最多 100。这允许算法运行在$O(n^2)$尽管存在线性解，但还是很舒服。 由于我们处理的是小的二进制字符串，因此复杂性更多地取决于分割逻辑的简单性，而不是处理能力。 

不明显的边缘情况包括已经好的字符串和所有字符都相同的字符串。 例如，如果输入是`111`或者`0`，子串的最小数量是 1，因为字符串本身已经很好了。 相反，字符串如`10`或者`01`不好，所以每个字符必须分成单独的子字符串。 粗心的解决方案可能会尝试始终将字符串拆分为两半，或者仅在相邻字符不同时贪婪地拆分，这会失败`111000`或者`1000`。 

## 方法

 暴力方法将尝试将字符串分割成连续的子字符串，并检查哪种组合仅产生数量最少的好子字符串。 分裂的数量呈指数级增长，特别是$2^{n-1}$，所以即使对于$n = 100$。 

关键的观察是，善良的属性仅取决于`0`和`1`。 如果所有字符都相同或者不完全平衡，则该字符串是好的。 这减少了问题：已经好的字符串可以保持完整。 只有具有相同数量的完美平衡的弦`0`和`1`需要拆分。 对于二进制字符串，这相当于检查字符串是否恰好由 1 组成`0`和一个`1`长度为二或更大。 因此，在实践中，子字符串的最小数量几乎总是 1，除非字符串具有完全相同数量的 0 和 1。 在这种情况下，我们可以将字符串分成两部分：一部分包含一个`0`或者`1`和其余的，这保证了两个子字符串都是好的。

 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算输入字符串中 0 和 1 的总数。 这使我们能够确定整个字符串是否已经良好。 
2. 如果计数不同，则整个字符串都是好的。 输出`1`接下来是原始字符串。 
3. 如果计数相等，我们必须分开。 最简单的策略是将第一个字符作为一个子字符串，其余部分作为第二个子字符串。 这保证了两个子字符串都是好的，因为第一个子字符串对于单个字符的计数为 1，而第二个子字符串在删除任一类型的一个字符后计数不相等。 
4. 打印子串的个数，即`1`如果字符串是好的，或者`2`如果需要分割，然后打印子字符串。 

为什么有效：通过维护零和一的计数，我们可以立即确定整个字符串是否满足良好条件。 当计数相等时拆分单个字符可以保证生成的子字符串是好的，因为其余的子字符串现在将具有不相等的计数。 没有其他分割产生更少的子串，从而确保最小性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

zeros = s.count('0')
ones = s.count('1')

if zeros != ones:
    print(1)
    print(s)
else:
    # counts are equal, split into first character and the rest
    print(2)
    print(s[0], s[1:])
```该代码首先计算字符串中的零和一，这是确定字符串是否正确所必需的。 如果计数不同，则整个字符串将打印为单个子字符串。 否则，我们会在第一个字符处拆分。 使用`s.strip()`确保我们从输入中删除任何尾随换行符，避免打印子字符串时出现细微的错误。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    s = input().strip()
    zeros = s.count('0')
    ones = s.count('1')
    if zeros != ones:
        return f"1\n{s}"
    else:
        return f"2\n{s[0]} {s[1:]}"

# Provided samples
assert run("1\n1\n") == "1\n1", "sample 1"
assert run("2\n10\n") == "2\n1 0", "sample 2"
assert run("6\n100011\n") == "2\n1 00011", "sample 3"

# Custom cases
assert run("3\n000\n") == "1\n000", "all zeros"
assert run("3\n111\n") == "1\n111", "all ones"
assert run("4\n0101\n") == "2\n0 101", "equal zeros and ones"
assert run("5\n00100\n") == "1\n00100", "unequal counts"
```| 测试输入| 预期产出 | 它验证了什么 |

 | 3\n111 | 3\n111 1\n111 | 1 一串相同的就好了|
 | 4\n0101 | 2\n0 101 | 2 相同数量的 0 和 1 触发 split |

 ## 边缘情况

 最小输入`1`带绳子`1`或者`0`处理正确：默认情况下计数不同，因此不会发生拆分。 长度的字符串`2`具有相同的数字，例如`01`或者`10`正确产生两个子串。 具有所有相同字符的字符串，例如`000`或者`111`，作为单个子字符串返回。 该算法保证所有场景下的子串最少，因为唯一需要拆分的情况是计数相等时，而这种情况无法进一步改进。
