 ## 解决方案
 ## 问题理解

 这项任务非常小而且直接：我们收到了来自多个人的一系列响应，其中每个响应要么是“这很容易”，要么是“这很难”。 目标是确定该问题总体上是否仍然可以被认为是简单的。 

规则很简单。 如果连一个人都认为这个问题很难，最后的结论就会变成“难”。 只有当每个人都同意这很容易时，我们才会认为它很容易。 

因此，输入只是一个二元意见列表，其中一个值代表“容易”，另一个值代表“困难”。 输出是一个单词，总结是否存在任何“强硬”意见。 

限制很小，最多有 100 个意见。 这立即排除了对性能的任何担忧。 即使是二次扫描或嵌套扫描也可以，但结构表明我们只需要一次扫描。 

主要的边缘情况主要是关于最小输入和统一输入。 如果只有一个人并且他们说容易，那么答案一定很容易。 如果同一个人说得很难，答案就会立即翻转。 另一个微妙的情况是，当硬性意见出现在最后或最开始时，这不应该影响正确性，但如果有人不小心实现它，可能会暴露不正确的提前终止逻辑。 

## 方法

 强力解释会将输入视为值的集合，并重复检查子集或模拟决策过程。 例如，人们可能会想象检查每个前缀并重新计算该前缀是否“干净”的硬性意见。 这是正确的，但不必要的重复，因为每次检查都会再次扫描相同的元素。 在最坏的情况下，人数会成二次方，大约$n^2$，这对于$n \le 100$但已经表明浪费了工作。 

关键的观察是，该决定仅取决于存在。 我们不在乎有多少人认为这很难，也不在乎他们出现在哪里。 我们只需要知道列表中是否至少存在一个“1”即可。 这将整个问题简化为带有布尔标志的单次扫描。 

一旦看到这一点，解决方案就变成了流式检查：一旦出现硬性意见，答案就确定了。 无需为了正确性而处理更多元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（重新检查前缀）| O(n²) | O(1) | O(1) | 已接受但没有必要 |
 | 单程扫描| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.阅读意见数量。 这告诉我们将扫描多少个值，但不会影响循环边界之外的逻辑。 
2. 初始化一个标志`hard_found`为假。 这个变量代表我们是否已经遇到过任何将问题标记为困难的意见。 
3. 迭代列表中的每个响应。 对于每个值，检查它是否等于 1，这代表“硬”投票。 
4. 如果发现硬投票，则设置`hard_found`为真。 至此，即使我们继续寻找实现的简单性，最终的答案也已经在逻辑上确定了。 
5. 处理完所有值后，如果有则输出“HARD”`hard_found`为真，否则输出“EASY”。 

早期检测背后的原因是，该问题实际上是所有输入的 OR 归约。 一旦看到一个真值，全局 OR 就已经为真。 

### 为什么它有效

 决策规则相当于对所有输入值计算逻辑或，其中 1 表示 true，0 表示 false。 最终答案仅取决于此 OR 计算结果是否为真。 由于 OR 是幂等且与顺序无关的，因此顺序扫描并跟踪是否出现任何真值可以保持正确性。 不需要重新排列或计数，并且任何后续值都不能推翻之前看到的硬性意见。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
arr = list(map(int, input().split()))

hard_found = False

for x in arr:
    if x == 1:
        hard_found = True

print("HARD" if hard_found else "EASY")
```该解决方案一次性读取所有值并扫描一次。 我们维护的唯一状态是布尔标志。 没有必要提前退出，尽管可以在不改变正确性的情况下添加它。 

一个常见的实现错误是试图在计数或分段逻辑方面过于聪明。 这会带来不必要的复杂性。 另一个问题是忘记输入是单行上以空格分隔的整数，如果处理不当，可能会导致部分读取。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个意见在线性扫描中仅检查一次 |
 | 空间| O(1) | O(1) | 仅存储一个布尔标志 |

 和$n \le 100$，这远远低于任何实际限制。 即使约束更大，相同的线性扫描仍然是最佳的，因为每个输入必须至少读取一次。

 ## 边缘情况

 一种边缘情况是只有一名参与者时。 该算法仍然有效，因为循环只运行一次并直接反映该单一意见。 

另一种情况是强硬意见出现在最后。 错误地假设提前终止或误读输入的幼稚实现可能会错过它，但线性扫描会在标志出现时正确更新该标志。 

最后一种情况是所有值都很简单。 在这里，该标志始终保持错误，并且输出正确地保持“EASY”，确认缺乏证据被视为缺乏硬度而不是含糊不清。
