 ## 解决方案
 ## 问题理解

 我们得到了一系列文凭级别和一系列奖项类型，并且我们必须计算有多少种一致的方法可以将奖项分配给按文凭级别分组的参与者。 

有$m$文凭类别。 类别$i$正好有$i$参与者，以及同一类别的所有参与者必须获得相同的奖品类型。 奖品类型编号为$1$到$n$，并且较小的数字对应于严格更好的奖品。 

我们还指定了每种奖品类型的容量：奖品类型$j$存在数量$j + a - 1$。 每个参与者必须获得一份奖品，并且我们可以保留未使用的奖品。 

作业必须遵守单调的质量规则：具有更好文凭的参与者不得获得更差的奖品。 由于奖项指数越小越好，如果文凭组$i$比团体好$j$，然后分配给组的奖品$i$索引必须小于或等于分配给组的奖金$j$。 

因此，决定实际上是为每个文凭组分配一个单一的奖项类型，形成一个非递减的长度序列$m$，同时尊重供应限制。 团体$i$消耗$i$其收到的任何类型奖品的副本。 

约束意味着$n \le 5000$，所以任何解决方案$O(n^2)$或者$O(n^2 \log n)$是合理的，但任何立方体$n$太慢了。 自从$m \le n$，我们应该期望在两个维度的前缀上有一个动态规划解决方案。 

一个微妙的点是，每个文凭组贡献与其大小相等的不同权重。 这立即阻止了将其视为标准的未加权分区问题，并迫使我们仔细跟踪前缀和。 

一个常见的错误是认为每个组贡献一个单位，这会导致错误的贪婪或简单组合模型。 例如，与团体$1,2,3$，将它们全部分配给一种奖品类型消耗$6$单位，不$3$，这显着改变了可行性。 

另一个失败案例是忽略单调性。 如果我们允许任意分配，我们就会过多计算配置，例如将较差的奖项分配给更好的文凭组。 例如，将组 1 分配给类型 3，将组 2 分配给类型 2 违反了规则，即使容量允许也是如此。 

## 方法

 蛮力解释很简单：对于每个文凭组，按非递减顺序选择奖品类型，然后验证是否满足所有容量限制。 这探索了所有序列$t_1 \le t_2 \le \dots \le t_m$，对于每个序列，我们计算每种类型消耗的奖品数量。 

此类序列的数量大致为重复组合的顺序$\binom{n+m-1}{m}$，当$n,m \approx 5000$。 即使在检查可行性之前，枚举这些序列也是不可行的。 

瓶颈在于可行性检查需要汇总每种奖项类型的加权组大小，这使得每个候选者的成本都很高，从而使总复杂性远远超出了限制。 

关键的结构观察是单调性迫使分配给相同奖品类型的所有组形成序列的连续部分$1 \dots m$。 一旦我们分配了较高编号的奖品类型，我们就永远不会返回较小的奖品类型，因此分配相当于对前缀进行分区$1 \dots m$分成连续的段。 每个分段对应一个奖品类型，并且按奖品类型索引的升序分配分段。 

这将问题转化为选择分段边界并将每个分段分配给奖品类型，以便每个分段的总重量适合该奖品类型的可用容量。 

现在问题变成了组前缀和奖品类型前缀上的 DP，其中转换取决于有效的段范围。 使用组大小的前缀和允许我们在恒定时间内检查段权重，并且两个指针允许我们有效地预先计算有效范围。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举赋值| 指数为$m$|$O(m)$| 太慢了 |
 | 具有两个指针的段上的 DP |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们围绕每个奖项类型服务于单个连续的文凭组块的想法构建解决方案。 

1. 计算组大小的前缀和。 让$S[i] = 1 + 2 + \dots + i = i(i+1)/2$。 这让我们可以计算任何部分的参与者总数$[l, r]$作为$S[r] - S[l-1]$。 这是至关重要的，因为可行性仅取决于段总和。 
2. 对于每种奖品类型$j$，计算其容量$c_j = j + a - 1$。 我们将决定它可以覆盖哪些群体。 
3. 对于每个起始位置$l$段的最大结束位置$r$使段总和适合容量$c_j$。 这是通过使用两指针扫描来完成的$r$， 自从$S[r]$正在增加。 
4. 定义一个动态规划表，其中$dp[j][i]$是覆盖第一个的方法的数量$i$文凭组使用的奖项类型高达$j$，尊重顺序。 
5. 过渡：如果我们决定奖品类型$j$覆盖一段$[l, r]$，然后先覆盖任何有效的方法$l-1$使用类型最多的组$j-1$可以扩展到首先覆盖$r$团体使用$j$。 
6.而不是迭代所有$l$对于每个$j$，我们使用范围更新。 对于每个$l$，一旦我们知道它是有效的$r$，我们添加$dp[j-1][l-1]$致所有州$dp[j][l..r]$。 
7. 为了高效实现，我们在每个 DP 层使用一个差分数组，因此每个贡献都变成一个恒定时间范围加法，然后是下一个 DP 行的前缀和重建。 

### 为什么它有效

 核心不变量是每个有效的分配都唯一对应于序列的一个分区$1..m$分成多个部分，其中每个部分都按升序分配给一种奖品类型。 DP 确保我们考虑每个前缀的每个可能的最后段边界，并且范围更新保证每个可行的段分配从其正确的先前状态被精确地计数一次。 由于容量是在形成段时强制执行的，因此无效的分配不能向前传播，并且由于所有转换都保留排序，因此不会错过任何有效的分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, a = map(int, input().split())
    m = int(input().strip())

    # prefix sums of group sizes: S[i] = 1+...+i
    S = [0] * (m + 1)
    for i in range(1, m + 1):
        S[i] = S[i - 1] + i

    dp_prev = [0] * (m + 1)
    dp_prev[0] = 1

    for j in range(1, n + 1):
        cap = j + a - 1

        diff = [0] * (m + 2)

        r = 0
        for l in range(1, m + 1):
            if r < l - 1:
                r = l - 1

            while r < m and S[r + 1] - S[l - 1] <= cap:
                r += 1

            if r >= l:
                add = dp_prev[l - 1]
                if add:
                    diff[l] = (diff[l] + add) % MOD
                    diff[r + 1] = (diff[r + 1] - add) % MOD

        cur = [0] * (m + 1)
        run = 0
        for i in range(m + 1):
            run = (run + diff[i]) % MOD
            cur[i] = run

        for i in range(m + 1):
            cur[i] = (cur[i] + dp_prev[i]) % MOD

        dp_prev = cur

    print(dp_prev[m] % MOD)

if __name__ == "__main__":
    solve()
```该实现仅保留两个 DP 层，因为转换仅依赖于前一层。 两指针逻辑确保每一对$(j, l)$单调地推进右端点，使总复杂度保持二次方。 

差异数组至关重要，因为它压缩了来自固定值的所有转换$j$进入线性时间$m$，避免额外的因素$m$来自线段端点的简单枚举。 

索引时必须小心：segment$[l, r]$为国家做出贡献$r$，之前的状态是$l-1$，这是通常出现相差一错误的地方。 

## 工作示例

 考虑一个小例子，其中$n = 3$,$a = 1$,$m = 3$。 容量为$1,2,3$，组大小为$1,2,3$带前缀和$1,3,6$。 

我们跟踪 DP 而非奖品类型。 

| j | 帽 | 有效段| dp进化总结|
 | --- | --- | --- | --- |
 | 1 | 1 | 仅 [1,1] | 只能分配第一组 |
 | 2 | 2 | 仅 [1,1]、[2,2] | 第二组可能单独出现|
 | 3 | 3 | [1,2] 和 [3,3] 等 | 出现更大的灵活性|

 这说明了如何逐渐增加容量来允许更长的段。 

现在考虑一个情况$m=2$, 团体规模$1,2$，并且只有当$a$足够大。 DP根据可行性正确区分分裂和合并。 

| 步骤| dp_prev | 新的有效段| dp_cur |
 | --- | --- | --- | --- |
 | j = 1 | [1,0,0]| 仅 [1,1] | 更新状态 1 |
 | j = 2 | [1,1,0]| 可能 [1,2] | 合并到状态 2 |

 这些痕迹显示了段合并是如何通过容量限制严格控制的。

 ## 边缘情况

 当容量足够大以至于可以实现多种分组模式时，尤其是当单一奖品类型可以覆盖所有文凭组时，就会出现关键的边缘情况。 在这种情况下，DP 应该正确计算形成线段的所有方式，而不仅仅是简单的单线段解决方案。 该算法处理此问题是因为两指针步骤将扩展每个起始位置$l$到整个范围，差异数组将在所有可到达的端点上传播贡献。 

当容量非常小时，就会出现另一种边缘情况，迫使每个组占据自己的部分。 在这里，仅$r = l$转变得以幸存，DP 退化为单一的强制结构。 该实现仍然有效，因为范围减少为单点更新，而差异数组自然支持这一点。 

第三种微妙的情况是，某些奖品类型由于容量不足而实际上无法使用。 DP 仍然对它们进行迭代，但没有段满足约束，导致该层的转换为零，从而正确地继承先前的有效计数而不添加新的计数。
