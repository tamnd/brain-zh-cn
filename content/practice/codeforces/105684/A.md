 ## 解决方案
 ## 问题理解

 我们得到固定数量的糖果和固定数量的员工。 每位员工必须收到恰好 2 颗糖果或恰好 3 颗糖果。 如果员工收到 3 颗糖果，则认为他们很高兴； 否则，他们会收到 2 颗糖果，并且不高兴。 任务是在分发所有糖果的同时最大化快乐员工的数量，以便每个员工都能获得有效的糖果包。 

输入包含两个大整数，即糖果总数和员工人数。 约束允许值高达$10^9$用于糖果及最多$5 \cdot 10^8$对于员工来说，因此任何解决方案都必须在每个测试用例中以恒定或对数的时间运行。 仅当存在多个边界较小的测试用例时，对员工或糖果的线性扫描才是可接受的，但这里的规模已经表明了直接算术构造。 

微妙的一点是，糖果总数至少是员工人数的两倍。 这保证了为每个人分配 2 颗糖果总是可行的，因此我们永远不会遇到某些员工无法获得最低要求数量的不可行情况。 问题纯粹是通过重新分配剩余糖果将一些员工从 2 颗糖果升级到 3 颗糖果。 

边缘情况来自平价和盈余结构。 

如果$n = 2m$，那么每位员工必须恰好收到 2 颗糖果。 没有空间可以将任何人提升到 3 颗糖果，因此答案为 0。例如，$n = 10, m = 5$，总分配是被迫的，谁也高兴不起来。 

如果$n = 3m$，那么每个员工可以得到3颗糖果，所以大家都很高兴，答案是$m$。 

在这些极端之间，我们必须仔细推理在不违反可行性的情况下可以进行多少 1 糖果升级。 

## 方法

 暴力方法会尝试为每个员工分配糖果，为每个员工选择 2 或 3 颗糖果，并检查所有组合。 和$m$员工，这导致$2^m$可能的分配，即使对于$m = 40$，更不用说达到$5 \cdot 10^8$。 

更结构化的视图是从每个人收到 2 颗糖果的基线开始。 这消耗$2m$糖果。 其余$n - 2m$糖果代表额外的单位，可用于将某些员工从 2 颗糖果升级到 3 颗糖果。 每次此类升级都会额外花费 1 颗糖果，并使快乐员工的数量增加 1 名。 

然而，升级所有剩余的糖果并不总是直接等同于答案，因为我们必须确保不超过员工数量。 即使有很多剩余的糖果，我们也不能超过$m$快乐的员工。 因此，答案受到盈余和雇员数量的限制。 

这导致了一个直接的解释：每个快乐的员工恰好消耗了 3 颗糖果，所以如果我们选择$x$快乐的员工和$m - x$不开心的员工，总共需要的糖果是$$3x + 2(m - x) = 2m + x.$$这最多应该是$n$， 所以$x \le n - 2m$。 还$x \le m$。 最大可行$x$因此是这两个界限的最小值。

 ## 算法演练

 ### 最优推理步骤

 1. 首先想象每个员工收到的最少分配是 2 颗糖果。 这正好消耗$2m$糖果，由于约束，此配置始终有效$n \ge 2m$。 
2. 计算基线分配后剩余的糖果数量。 让这成为$r = n - 2m$。 这些是唯一可以增加幸福感的糖果。 
3. 观察将一名员工从 2 颗糖果增加到 3 颗糖果，正好额外消耗 1 颗糖果，并将该员工转变为快乐的员工。 因此，每个快乐的员工对应于花费 1 个单位$r$。 
4. 得出最多的结论$r$使用剩余的糖果可以让员工感到高兴。 
5.还要注意快乐员工的数量不能超过员工总数$m$，因为每个员工最多可以计数一次。 
6. 取这两个约束中的最小值，$r$和$m$，作为最终答案。 

### 为什么它有效

 通过从每个快乐的员工中减去 1 颗糖果，每个有效的分配都可以转换为所有 2 糖果员工的基线分配。 这显示了解决方案之间的一一对应关系$x$快乐的员工和配置$x$多余的糖果被分配在基线的顶部。 由于基线是固定的并且消耗尽可能少的糖果，因此任何有效的配置都必须满足$x \le n - 2m$。 没有任何安排可以绕过这个界限，因为每个幸福单位都有一个固定成本，即超出基本要求的额外糖果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    base = 2 * m
    surplus = n - base
    if surplus < 0:
        surplus = 0
    print(min(m, surplus))

if __name__ == "__main__":
    solve()
```实现直接对推理进行编码。 变量`base`代表强制分配，每个人获得 2 颗糖果。 这`surplus`变量捕获我们可以分配多少额外的 1 糖果增量。 最终答案受到盈余和员工数量的限制。 在限制条件下，对负盈余的防范在技术上是不必要的，但如果放松或误读限制，则它可以保持正确性。

 ## 边缘情况

 对于以下情况$n = 2m$，每位员工正好收到 2 颗糖果，并且无法升级。 例如，输入`10 5`生产基地$2m = 10$和剩余 0。算法集`surplus = 0`并返回`min(5, 0) = 0`，正确匹配强制分布。 

什么时候$n$足够大，可以支持所有收到 3 颗糖果的员工，例如`6 2`，计算得出基数 4 和余数 2。结果为`min(2, 2) = 2`，意味着所有员工都能幸福。 该算法自然饱和于$m$，即使盈余很大，也能防止过度计算。
