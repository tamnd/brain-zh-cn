 ## 解决方案
 ## 问题理解

 我们正在模拟固定数量人员的顺序分配过程。 有$m+1$参与者总数：一名特殊参与者、一名实习生、以及$m$相同的正式员工。 的列表$n$礼物按顺序送达，每件礼物都具有积极的价值。 每份礼物都会立即分配给一名参与者。 

分配的规则是贪婪的：在每一步，下一份礼物都会送给当前总收集价值在所有参与者中最小的人。 如果多人共享这个最小值，则可以选择其中任何一个。 这种打破平局的自由是过程中唯一的可变性来源。 

实习生被迫接受第一份礼物。 此后，对于所有剩余的礼物，该过程将按照相同的规则继续进行。 问题不是模拟单次运行，而是根据解决平局的方式来确定实习生的最终总数可以变得多小或多大。 

约束达到$n \le 2 \cdot 10^5$，这立即排除了任何二次甚至$O(n \sqrt n)$决策分支的模拟。 该过程本身本质上是顺序的，因此$O(n \log n)$或者$O(n \log m)$模拟是自然的目标。 

平局的情况会带来一个微妙的困难。 当几位参与者共享最低价值时，选择其中一位可以改变实习生未来获得礼物的机会。 任意解决平局的简单模拟将计算单个结果，但这里我们需要对抗性平局打破下的极值结果。 

一个重要的边缘情况是所有员工平等地开始并在一段时间内保持平等。 例如，如果所有礼物都是相同的，那么在第一次分配后系统可以保持完美平衡。 在这种情况下，实习生可能会或可能不会收到连续的礼物，具体取决于平局的选择，而这些决定会影响他是与其他人保持平局还是落后。 

当实习生严格落后或严格领先时，就会出现另一个极端情况。 如果他的总数严格小于其他人，他就被迫接受下一份礼物。 如果他的总数严格更大，他肯定会被跳过。 这消除了系统的自由，只有平等的情况才对优化有意义。 

## 方法

 直接模拟会保留每个参与者的总数，并重复选择其中的最小值$m+1$价值观。 这在概念上是有效的，因为该过程是由这些最小值精确定义的。 然而，一旦我们引入探索最佳和最差平局打破的必要性，蛮力就需要在每个平等事件中进行分支。 在最坏的情况下，许多参与者可以重复共享相同的最小值，从而导致可能的决策路径呈指数级增长。 即使是尝试所有平局选择的更加结构化的蛮力也会退化远远超出可行的极限。 

关键的观察结果是，只有实习生和当前最小组之间的相对顺序很重要。 所有非实习员工都是可以互换的，因此我们不需要他们的身份，只需要他们目前持有每个总价值的数量。 

我们可以将系统维护为员工总数的多集$m$正式工，同时单独跟踪实习生。 在每一步中，我们都会将实习生的价值与正式员工的最低价值进行比较。 如果实习生严格来说较小，则他是唯一的最小值，并且必须收到礼物。 如果他严格来说更大，他就被排除在决策之外。 唯一有趣的情况是当他的价值等于其他人中最低的时候。 

在这种平局的情况下，极端策略会出现分歧。 为了最大化实习生的最终总分，我们总是在他属于最小组时选择他。 为了尽量减少这种情况，每当有最低限度的员工存在时，我们总是避免给他礼物。 

每项任务都会更新一名参与者的总数，并有可能将该员工转移到更高价值的桶中。 这可以通过一堆值加上计数来有效地跟踪。

 ## 算法演练

 我们维护三个状态：实习生当前的总数、实习生的多组总数$m$正式员工，以及允许快速检索正式员工中最小总数的结构。 

最初，所有员工都从零开始。 实习生立即收到第一份礼物，因此他的价值变为$a_1$。 每个正式员工仍然为零，因此多重集从$m$零。 

剩下的礼物，我们按顺序处理。 

1. 我们计算正式员工中最小的总数。 
2. 我们将其与实习生当前的总数进行比较。 
3. 如果实习生的总金额严格小于其他最低金额，则他是唯一的最低金额，必须收到当前的礼物。 
4. 如果实习生的总数严格较大，则必须有某个正式员工收到礼物，我们会相应更新该员工的存储桶。 
5. 如果实习生的总数等于其他中的最小值，我们会根据计算的是最大结果还是最小结果而以不同的方式解决此问题。 
6. 对于最大的情况，我们将礼物分配给实习生，增加他的总数。 
7. 对于最低限度的情况，我们将礼物分配给最低级别的某个正式员工，将该员工移至更高的总类别。 

每次分配后，我们都会更新多重集结构中受影响的总计。 这确保了下一步可以有效地查询最小值。 

正确性基于以下事实：所有正式员工都是对称的。 影响未来决策的唯一状态是总数的多重集以及实习生当前是否符合最小值。 正式员工之间的任何决胜局都不会改变总计集，只会更新相同的元素。 

不变的是，在每个步骤之后，数据结构正确地表示正式员工中的总数的多重集以及实习生的确切当前总数。 未来的每个决策仅取决于这些值，因此保留它们可以确保模拟反映所有有效的决胜结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq
from collections import defaultdict

def simulate(n, m, gifts, maximize):
    # multiset for regular employees: value -> count
    cnt = defaultdict(int)
    heap = []

    # all regular employees start at 0
    cnt[0] = m
    heapq.heappush(heap, 0)

    # intern gets first gift
    intern = gifts[0]

    def get_min_other():
        while heap and cnt[heap[0]] == 0:
            heapq.heappop(heap)
        return heap[0]

    for i in range(1, n):
        ai = gifts[i]
        mn = get_min_other()

        if intern < mn:
            # intern is unique minimum
            intern += ai

        elif intern > mn:
            # must assign to some regular min
            cnt[mn] -= 1
            if cnt[mn] == 0:
                cnt.pop(mn)
            newv = mn + ai
            cnt[newv] += 1
            heapq.heappush(heap, newv)

        else:
            # intern == mn
            if maximize:
                intern += ai
            else:
                cnt[mn] -= 1
                if cnt[mn] == 0:
                    cnt.pop(mn)
                newv = mn + ai
                cnt[newv] += 1
                heapq.heappush(heap, newv)

    return intern

def main():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # intern gets first gift
    min_val = simulate(n, m, a, maximize=False)
    max_val = simulate(n, m, a, maximize=True)

    print(min_val, max_val)

if __name__ == "__main__":
    main()
```该实现将两个极值行为分离为由标志控制的单个模拟函数。 普通员工的多重集被存储为与堆相结合的频率图，以便有效地检索最小值，并使用惰性删除来处理过时的堆条目。 

由于实习生是单个实体，因此其值会直接更新。 唯一的分支发生在他的值与其他值中的当前最小值匹配时，这正是打破平局影响结果的地方。 

一个常见的错误是忘记只有正式员工才需要多组跟踪。 另一个微妙的点是维护堆一致性：计数降至零的值不得被视为有效最小值，因此在遇到它们时会被延迟删除。

 ## 边缘情况

 当所有员工以相同的价值观开始时，系统会在完全绑定状态下执行几个步骤。 在这种制度下，实习生的命运完全取决于关系的解决对他有利还是不利，算法通过明确检查与全局最小值的相等性来捕捉这一点。 

当实习生严重落后于其他人时，他将被迫接受随后的每一份礼物，直到恢复平等。 模拟自然地处理了这个问题，因为比较`intern < mn`立即触发强制分配。 

当实习生严格领先时，他永远不会被选择，直到其他人赶上，这可以防止在最大化情况下意外的过度分配。 平等部门是唯一进行控制的地方。 

这些行为都符合这样一个不变量：只有实习生相对于当前最小桶的相对位置才重要，而不是正式员工的内部安排。
