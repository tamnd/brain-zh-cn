 ## 解决方案
 ## 问题理解

 我们给出一长串小写字母和一个固定整数$k$。 对于任何子串，我们被问到是否可以重新排列它的字母，使得子串恰好变成$k$相同的块连接在一起。 换句话说，在对子字符串内的字符进行排列后，我们希望它可以整除为$k$相等的多组字符。 

如果子串的总长度可以被整除，则子串有效$k$，如果每个字符出现的倍数$k$次在里面。 第二个条件保证我们可以将字母的多重集分成$k$相同的组。 

每个查询都会给出字符串的一段，我们必须计算完全位于该段内有多少子字符串满足此条件。 

约束条件很大：最多$3 \times 10^5$用于字符串长度和查询数量。 任何检查每个查询的所有子字符串的解决方案都是立即不可能的，因为即使是单个查询也有$O(n^2)$最坏情况下的子字符串，以及变得天文数字般大的查询。 即使扫描一次所有子字符串也是边界，因此解决方案必须将每个查询的子字符串计数减少到接近线性或对数。 

一个微妙的边缘情况是子字符串长度不能被整除$k$。 例如，如果$k = 2$，长度为 3 的子串永远不能重新排列成两个相等的部分，无论其字符如何。 仅检查字符整除性但忘记长度整除性的幼稚方法将错误地计算此类情况。 

另一个陷阱是假设仅检查频率奇偶性或单个字符条件就足够了。 例如，对于$k = 3$，像“aabccc”这样的子字符串的总长度为 6，但计数为$a=2, b=1, c=3$。 尽管有些计数可以被 3 整除，但并非所有计数都可以被 3 整除，所以它会失败。 

核心困难在于我们正在计算频率向量位于由整除性定义的约束格中的子串$k$，在任意查询范围内。 

## 方法

 暴力解决方案尝试每个查询范围内的每个子字符串，计算字符频率并检查条件。 对于每个子串，我们将维护一个大小为 26 的频率数组。从每个左端点扩展的成本$O(26)$，所以每个查询变成$O(n^2 \cdot 26)$在最坏的情况下。 和$3 \times 10^5$，这是完全不可行的。 

我们可以先把条件简化一下。 子串重排后有效$k$相同的块当且仅当该子字符串中的每个字符数都可以被整除$k$。 长度条件是自动隐含的，因为总长度是计数的总和。 

所以问题就变成了：计算字符频率向量与零模全等的子串$k$。 

这建议使用前缀和模$k$。 为每个前缀定义一个 26 维模数向量$k$。 一个子串$l..r$如果 prefix[r] 等于 prefix[l-1] 逐分量取模，则有效$k$。 因此，问题就变成了计算范围查询中相等向量对的数量。 

现在结构很清晰了：每个前缀映射到 26 维空间模中的一个状态$k$，并且我们需要计算查询范围中的相等状态。 26 维向量的直接散列是可能的，但我们还需要在许多查询中对相等值进行有效的范围计数。 

这是一个经典的离线问题。 我们可以将每个前缀状态压缩为哈希，然后使用 Mo 算法或频率图线段树处理查询。 然而，如果不小心的话，26 维会使朴素哈希对冲突敏感，因此我们通常使用随机基数或每个维度的大模数进行编码。 

更清晰的观察进一步改善了这一点。 由于我们只需要向量相等，因此我们可以将每个前缀状态视为 26 个值的元组$[0, k-1]$。 我们使用散列为每个唯一状态分配一个整数 ID。 那么每个查询就变成：对前缀 ID 子数组内的相等 ID 对进行计数，这是一个标准范围对计数问题，可以用 Mo 的算法解决$O((n+q)\sqrt{n})$。 

我们在移动查询指针时保持每个状态的频率。 添加频率元素时$f$，它贡献$f$新对； 删除时，它会删除$f-1$相应地配对贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解子串 |$O(n^2 \cdot 26)$每个查询 |$O(26)$| 太慢了 |
 | 前缀哈希+Mo’s算法|$O((n+q)\sqrt{n})$|$O(n)$| 已接受 |

 ## 算法演练

 1. 构建前缀频率向量模$k$。 对于每个位置$i$，维护一个 26 长度的数组，其中每个条目存储该字符模数的计数$k$最多$i$。 这将子字符串频率查询转换为前缀状态之间的比较。 
2. 将每个前缀向量编码为单个可散列表示。 由于每个组件都在$[0, k-1]$，我们使用滚动混合基散列或随机权重将它们组合起来，以便向量的相等性对应于散列的相等性。 此步骤将 26 维比较减少为整数相等。 
3. 构建数组$a[i]$在哪里$a[i]$是位置前缀状态的哈希值$i$。 我们还在索引 0 处包含一个虚拟前缀，表示空前缀。 
4. 转换每个查询$(x, y)$进入前缀数组的范围：我们正在计算对$i < j$在$[x-1, y]$这样$a[i] = a[j]$。 
5. 使用 Mo 的排序对查询进行排序，以便连续查询以较小的增量移动端点。 
6. 维护频率表`cnt[state]`在当前的 Mo 窗口和运行的答案上。 当我们添加一个位置时$i$，之前每一次出现的`a[i]`贡献`cnt[a[i]]`新对，所以我们将其添加到答案中并增加频率。 拆除时$i$，我们首先减少频率并减去它之前贡献的对的数量。 
7. 处理完所有查询后，按原始顺序输出存储的答案。 

关键的不变量是在 Mo 算法的任何时候，`cnt[v]`正好等于哈希值的前缀位置的数量$v$在当前窗口内，维护的答案等于该窗口内相等对的数量。 由于每个有效子串双射对应于一对相等的前缀状态，因此该算法精确地计算所需的子串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, q = map(int, input().split())
    s = input().strip()

    # prefix modulo-k frequency states
    freq = [0] * 26
    prefix = [(0,) * 26]

    for ch in s:
        freq[ord(ch) - 97] += 1
        freq[ord(ch) - 97] %= k
        prefix.append(tuple(freq))

    # coordinate compress prefix states
    comp = {}
    arr = []
    for p in prefix:
        if p not in comp:
            comp[p] = len(comp)
        arr.append(comp[p])

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r, i))

    block = int(len(arr) ** 0.5)

    def mo_cmp(x):
        l, r, _ = x
        return (l // block, r if (l // block) % 2 == 0 else -r)

    queries.sort(key=mo_cmp)

    cnt = [0] * (len(comp) + 5)
    cur_l, cur_r = 0, -1
    cur_ans = 0
    res = [0] * q

    def add(i):
        nonlocal cur_ans
        v = arr[i]
        cur_ans += cnt[v]
        cnt[v] += 1

    def remove(i):
        nonlocal cur_ans
        v = arr[i]
        cnt[v] -= 1
        cur_ans -= cnt[v]

    for l, r, idx in queries:
        while cur_l > l:
            cur_l -= 1
            add(cur_l)
        while cur_r < r:
            cur_r += 1
            add(cur_r)
        while cur_l < l:
            remove(cur_l)
            cur_l += 1
        while cur_r > r:
            remove(cur_r)
            cur_r -= 1
        res[idx] = cur_ans

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```该实现依赖于将子字符串计数转换为前缀相等计数。 前缀数组包含索引 0，以便统一处理从 1 开始的子字符串。 Mo 例程仔细维护频率表并使用配对计数逻辑增量更新答案。 

一个常见的陷阱是颠倒更新的顺序`remove`。 递减必须在扣除捐款之前发生； 否则移除的对数会被错误计算。 

另一个微妙的点是前缀状态必须取模$k$每一步，而不仅仅是存储为原始计数。 如果没有模约减，向量的相等性将无法反映$k$-折叠结构。

 ## 边缘情况

 当子串的长度不能被整除时，就会出现临界边缘情况$k$。 例如，与$k = 3$，任何长度为4的子串自动无效。 该算法隐式地处理这个问题，因为模数上的前缀状态相等$k$除非总计数对齐，否则不会发生，因此此类子字符串不存在一对相等的前缀状态。 

另一种情况是整个字符串具有统一的字符。 在这种情况下，每个前缀状态在少量向量之间循环，产生许多相等的对。 基于频率的配对计数正确累加$f \cdot (f-1)/2$贡献，无需过多计算。 

最后一个微妙的情况是当查询是大型结构内的小范围时。 由于 Mo 的算法仅维护当前窗口内的计数，因此查询间隔之外的前缀状态永远不会起作用，即使在全局频率分布高度倾斜的情况下也能确保正确性。
