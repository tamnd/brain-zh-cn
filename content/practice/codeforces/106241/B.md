 ## 解决方案
 ## 问题理解

 我们正在模拟两个相同的台球在大小为矩形的网格内移动$n \times m$。 每个单元格都有整数坐标$(i, j)$，并且两个球都从内部位置开始，而不是在边界上。 每个球每单位时间沿四个对角线方向之一移动一步：右上、左上、右下或左下。 

在每一步中，每个球都会通过对角线移动来更新其位置。 如果它离开网格，它就会从边界反射：击中水平边界会翻转运动的垂直分量，击中垂直边界会翻转水平分量。 这相当于矩形墙壁上的完美弹性反射。 

此外，当两个球同时落在同一个单元格上时，它们会立即交换移动方向，然后继续移动。 

后$k$步骤，我们必须报告两个球的最终位置，按字典顺序打印。 

这些限制立即排除了直接模拟。 网格最多可包含$2 \cdot 10^5$细胞和$k$可以大到$10^{12}$。 因此，逐步模拟是不可能的，因为即使$10^7$步骤在 C++ 中已经处于临界状态，而 Python 会更早失败。 

天真的解释还隐藏了一个微妙的陷阱：碰撞取决于同时位置，而不是顺序更新。 如果尝试在球 2 之前完全移动球 1，或者在不同步的情况下立即更新方向，则碰撞行为将变得不正确。 

第二个微妙的问题是周期性。 每个球都在有界状态空间中确定性地移动，因此它的运动最终必须重复。 忽略这一点会导致计算浪费或模拟长轨迹的错误尝试。 

## 方法

 强力方法模拟每个步骤：更新两个位置，处理墙壁反射，如果两个位置匹配，则交换方向。 这是正确的，因为它完全遵循规则。 然而，每一步都是$O(1)$，所以总复杂度是$O(k)$。 和$k = 10^{12}$，这是不可行的。 

关键的观察结果是，每个球在具有反射的确定性系统中独立移动，这相当于“展开的网格”上的直线运动。 我们可以想象通过镜像副本来无限扩展网格，而不是反射。 在这个展开的空间中，每个球以匀速沿直线对角线移动。 

因此，每个球的位置$k$可以使用双轴上的模算术独立计算步数：我们模拟长度线上的运动$2(n-1)$对于行和$2(m-1)$对于列。 这将反射转换为简单的模算术。 

唯一剩下的困难是碰撞处理。 一旦运动在展开空间中线性化，我们就可以将每个球的位置视为时间的函数。 如果两个坐标同时匹配，就会发生碰撞。 然而，我们观察到，碰撞时交换方向相当于将球视为彼此穿过的不可区分的粒子，而不是动态模拟交换。 这个经典事实之所以成立，是因为碰撞时交换速度使得轨迹相当于没有相互作用的相交。 

因此，我们独立地计算每个球，就好像它穿过另一个球一样，完全忽略碰撞，然后输出排序后的最终位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(k)$|$O(1)$| 太慢了|
 | 最佳 |$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 对于两个坐标，我们将有界网格中的运动减少为双线性段上的运动。 

1. 将每个方向转换为一对 delta$(dr, dc)$，其中每个组件是$+1$或者$-1$。 这给出了独立于方向名称的运动的统一表示。 
2.对于长度单一的坐标轴$L$，通过考虑一段时间来替换反射$2(L-1)$。 之后的位置$k$步骤变成了弹跳线上的简单算术表达式。 
3. 对于每个球和每个轴，分别计算：

 沿展开线的有效位置$k$步骤。 

这样做的原因是每次反射都完全对应于围绕双线段的环绕。 
4. 将展开的坐标映射回原始线段$[1, L]$。 如果位置处于周期的后半段，则通过对称性将其反映回来。 
5. 对行和列维度独立重复以获得最终结果$(i, j)$每个球的位置。 
6. 模拟期间忽略碰撞交换。 将球视为相互穿过会产生相同的最终位置，因为交叉点处的交换保留了多组轨迹而不影响端点。 

### 为什么它有效

 每个坐标都像线段上的一维台球一样独立演化。 展开的结构将反射转换成具有周期的线上的周期性运动$2(L-1)$，在每一步中保留精确的位置对应关系。 由于系统是确定性的，并且碰撞仅交换身份而不改变轨迹，因此无论模拟还是忽略交换，最终占据的位置集都是不变的。 

因此，每个球的终点仅取决于其初始状态，而不取决于交互历史。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def reflect(pos, L):
    # period is 2*(L-1)
    if L == 1:
        return 1
    period = 2 * (L - 1)
    pos %= period
    if pos < 0:
        pos += period
    if pos <= L - 1:
        return 1 + pos
    return L - (pos - (L - 1))

def move(x, dx, L, k):
    # convert to 0-indexed
    x0 = x - 1
    pos = x0 + dx * k
    return reflect(pos, L)

def parse_dir(d):
    if d == "UR":
        return (-1, +1)
    if d == "UL":
        return (-1, -1)
    if d == "DR":
        return (+1, +1)
    return (+1, -1)

n, m, k = map(int, input().split())

i1, j1, d1 = input().split()
i1 = int(i1); j1 = int(j1)
i2, j2, d2 = input().split()
i2 = int(i2); j2 = int(j2)

dr1, dc1 = parse_dir(d1)
dr2, dc2 = parse_dir(d2)

r1 = move(i1, dr1, n, k)
c1 = move(j1, dc1, m, k)

r2 = move(i2, dr2, n, m, k)
c2 = move(j2, dc2, m, k)

p1 = (r1, c1)
p2 = (r2, c2)

if p1 < p2:
    print(r1, c1)
    print(r2, c2)
else:
    print(r2, c2)
    print(r1, c1)
```实现的核心是将弹跳运动简化为双倍间隔上的模运算。 功能`reflect`实现从展开坐标映射回原始线段。 它使用一段时间$2(L-1)$，它编码完整的来回遍历。 

每个球都使用独立处理`move`，首先将坐标转换为基于零的系统，应用线性运动$x + dx \cdot k$，然后将其向后折叠。 

方向解析确保所有移动都减少为有符号整数，从而消除以后的大小写区别。 

最后，根据输出规范的要求按字典顺序进行排序。 

一个微妙的实现点是索引的一致性：错误地混合基于 0 的坐标和基于 1 的坐标将使反射移动一个单位，从而在边界处产生系统性的差一误差。

 ## 边缘情况

 一种边缘情况是当$k = 0$。 该算法必须返回初始位置而不应用任何变换。 由于该公式使用直线运动$x + dx \cdot k$， 什么时候$k = 0$它减少到原始坐标，并且反射不会改变它。 这确保了身份行为。 

另一种边缘情况是球展开后恰好位于角落处。 在这种情况下，位置模$2(L-1)$恰好落在 0 或$L-1$，两者都正确映射到边界单元。 反射函数自然地处理这个问题，因为段的两端对应于有效的端点。 

第三种边缘情况是两个球反复碰撞。 由于我们忽略碰撞交换，因此轨迹独立地继续。 例如，如果两者对称地开始并在中心多次相遇，则最终位置不受影响，因为交换仅排列身份，而不排列坐标。
