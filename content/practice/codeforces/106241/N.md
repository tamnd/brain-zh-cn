 ## 解决方案
 ## 问题理解

 我们得到一个整数$x$，我们想知道它是否可以分成三个正整数的完全平方数。 换句话说，我们试图找到整数$a, b, c \ge 1$这样它们的平方加起来正好等于$x$，还有额外的约束$a \le b \le c$只是为了避免以不同的顺序计算相同的三元组。 

输出只是一个二元决策：是否至少存在一个这样的三元组。 

输入大小达到$10^8$，它立即告诉我们有关任何可行解决方案的结构的重要信息。 的平方根$10^8$是$10^4$，因此涉及所有可能值的任何直接推理$a, b, c$生活在大小约为$10^4$。 一个简单的三嵌套循环解决方案将尝试以下顺序$10^{12}$操作，这远远超出了任何实际限制。 即使是双环尺寸$10^4 \times 10^4$给出$10^8$迭代，这在 Python 中是边界，但通过严格的实现和早期的修剪仍然可以接受。 

不明显的困难不仅仅是大小，还有排序限制$a \le b \le c$。 忽略排序的粗心方法将导致计数过多，但对于存在性检查来说仍然是正确的。 真正的风险是平方检查步骤的性能和正确性。 

出现微妙的边缘情况时$x$很小。 例如，$x = 2$。 没有办法将 2 表示为三个正平方和，因此答案一定是否定的。 允许零的幼稚实现会错误地接受类似的情况$1^2 + 1^2 + 0^2 = 2$，但问题明确禁止零，因此该快捷方式无效。 

另一个边缘情况是当$x < 3$。 由于最小可能的总和是$1^2 + 1^2 + 1^2 = 3$, all such inputs must immediately return NO. 任何不显式或隐式尊重积极性的算法都会在这里失败。 

## 方法

 最直接的想法就是尝试所有可能的三元组$(a, b, c)$。 由于每个变量最多$10^4$，这导致大约$10^{12}$组合。 即使我们修剪使用$a \le b \le c$，数量级仍然是立方的$10^4$范围，这是完全不可能的。 

第一个改进是修复两个变量并计算第三个变量。 如果我们选择$a$和$b$， 然后$c^2$被唯一地确定为$x - a^2 - b^2$。 这将问题简化为检查该值是否是完全平方以及所得结果是否$c$尊重排序约束$c \ge b$。 

关键的观察结果是，可以使用预先计算的平方或整数平方根验证在恒定时间内完成检查完美平方。 这将问题从三个维度减少到两个嵌套循环，从而将复杂性降低到大约$10^8$最坏情况下的操作。 虽然这个值很大，但在严格约束下的优化 Python 中是可以接受的，特别是因为许多迭代在剩余总和变为负数时提前终止。

 蛮力之所以有效，是因为它直接探索所有有效的配置，但当三元组的组合爆炸变得太大时就会失败。 这种改进之所以有效，是因为一旦两个值被固定，第三个值就不再是一个选择，而是一个确定性值，从而压缩了搜索空间。

 ## 算法演练

 我们通过枚举可能的值来工作$a$和$b$，并推导$c$从剩余金额中。 

1. 通过迭代隐式计算所有平方$a$从 1 到$\lfloor \sqrt{x} \rfloor$。 这已经足够了，因为任何大于$x$不能是总和的一部分。 
2.对于每个固定$a$, 迭代$b$从$a$向上同时$a^2 + b^2 \le x$。 该命令强制执行$a \le b \le c$在此阶段无需进行额外检查。 
3. 对于每对$(a, b)$，计算剩余值$r = x - a^2 - b^2$。 如果$r < 0$，我们停止增加$b$因为进一步的值只会增加总和。 
4. 检查是否$r$是一个完美的正方形。 我们计算$c = \lfloor \sqrt{r} \rfloor$并验证$c^2 = r$。 
5. 如果$c$有效，请检查确认订购$c \ge b$。 如果这个成立，我们立即得出结论，存在一个有效的三元组。 
6. 如果没有一对产生有效的$c$，我们返回NO。 

关键的设计选择是我们只计算$c$从等式中，永远不要枚举它。 这消除了搜索空间的一整维。 

### 为什么它有效

 该算法保留了每个检查状态对应于唯一有序三元组候选的不变性$a \le b \le c$。 每个有效的解决方案必须成对出现一次$(a, b)$因为$c$由方程唯一确定。 循环排序保证不会跳过任何有效对，平方检查确保重建的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    x = int(input().strip())

    if x < 3:
        print("NO")
        return

    import math

    limit = int(math.isqrt(x))

    for a in range(1, limit + 1):
        a2 = a * a
        if a2 > x:
            break

        for b in range(a, limit + 1):
            s = a2 + b * b
            if s > x:
                break

            r = x - s
            c = int(math.isqrt(r))
            if c < b:
                continue
            if c * c == r:
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    main()
```该代码遵循算法的确切结构。 外循环修复$a$，并且内循环修复$b$，当部分总和超过时提前停止$x$。 使用整数平方根将剩余值测试为完美平方。 

一个微妙的细节是订购检查`c < b`。 如果没有它，算法仍然会找到正确的分解，但可能会违反约束$a \le b \le c$，特别是在计算出的情况下$c$小于$b$。 这个条件确保我们只接受有效的有序三元组。 

使用`math.isqrt`避免了使用时会出现的浮点精度问题`sqrt`来自浮点运算。

 ## 边缘情况

 对于$x < 3$，算法立即拒绝输入。 例如，$x = 2$触发基本条件并返回 NO，而不进入搜索循环，这与三个正平方的最小可能和为 3 的事实一致。 

对于以下情况$x$正好是一个完全平方数，例如$x = 9$，该算法仍然表现正确，因为它不假设单项表示。 仅当有效的第三个方块与排序约束一起存在时，它才会接受分解。 为了$x = 9$，不存在有效的正整数三元组，因此算法正确地耗尽所有对并返回 NO。 

对于更大的结构化值，例如$x = 27$，算法在搜索空间的早期找到一个解决方案$(1,1,5)$，证明提前终止是正确处理的，并且不依赖于详尽的探索。
