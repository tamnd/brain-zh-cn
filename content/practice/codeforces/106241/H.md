 ## 解决方案
 ## 问题理解

 给定一个数组，我们可以稍微调整每个元素，但每个位置只能调整一次，而且调整极其有限：对于每个索引，我们可以不执行任何操作，也可以添加/减去 1 到 10 之间的整数。 

经过这些独立的每个位置调整后，所得数组必须形成算术级数，这意味着存在共同差异$d$这样每个连续的对都完全不同$d$。 

任务不是在所有情况下都显式地构造序列，而只是确定允许的修改的某些选择是否可以使数组适合该刚性线性结构。 

约束很大：跨测试用例的元素总数最多可达$10^5$。 这立即排除了每个测试用例的任何二次方。 任何试图以嵌套方式独立枚举每个位置可能性的解决方案都将无法生存。 我们需要一种方法来将问题减少到可以在每个测试用例基本上线性的时间内进行检查，或者每个元素几乎恒定的工作量。 

一个微妙的困难是每个元素都有_小的局部不确定性区间_，但全局结构是_完全刚性的_。 一个幼稚的错误是独立对待每个位置，或者贪婪地修复前几个元素，而不考虑后来的约束可能会使早期的假设无效。 

一些打破天真的思维的边缘模式：

 如果除了一个大的异常值之外所有元素都相等，例如：

 输入：`[10, 10, 10, 100]`我们可能认为调整最后一个元素最多 10 不可能修复它，但如果巧妙地选择序列斜率（例如较大的正差或负差），可行性取决于所有位置的对齐，而不仅仅是局部接近度。 

另一个棘手的情况是当局部灵活性以多种方式重叠时：

 输入：`[1, 100, 200]`每个元素都有一个±10的窗口，但是否存在一致的算术级数取决于我们是否可以将三个区间对齐到具有固定斜率的单条线上，而不仅仅是端点是否重叠。 

关键的困难是通过“粗点”的线的全局一致性。 

## 方法

 强力解释会尝试猜测最终的算术级数。 这意味着选择第一项和公差，然后检查每个元素是否可以在 ±10 范围内调整以匹配级数的相应项。 问题是第一个术语和差异可能有很大差异。 差异本身可以大到$2 \cdot 10^9$，并且第一项也是无界的。 尝试所有的可能性是不可能的。 

更结构化的强力方法会选择两个索引，假设修改后的最终值，导出共同差异，然后验证整个数组的一致性。 每个元素最多有 21 个选择（保留、+1..+10、-1..-10），因此对已经以组合方式爆炸。 

关键的观察结果是，算术级数完全由其第一项和公差决定，并且每个数组元素将其索引处该行的可能值限制在一个小区间内。 对于索引$i$，最终值必须位于：$$[a_i - 10, a_i + 10]$$因此，我们不再考虑离散选择，而是将每个位置重新解释为线性函数的约束：$$x_i = A + i \cdot d$$在哪里$x_i$必须位于已知区间内。 

这成为一个经典的几何可行性问题：是否存在一条与所有垂直间隔在整数 x 坐标处相交的线？ 每点的约束是线性的$A$和$d$，并且该结构变得易于管理，因为我们可以通过锚定两个点来减少候选斜率。 

我们尝试了前两个选定值如何在 ±10 范围内移动的所有可能性。 这决定了候选人的差异$d$。 一次$d$是固定的，第一项是强制的，我们可以验证是否可以调整所有剩余元素以适应。 

由于每个元素只有 21 个可能的最终值，但我们不会全局迭代所有组合，因此我们只枚举前两个位置的可能性，最多给出$21^2 = 441$候选斜坡。 然后在线性时间内验证每个斜率。 

这将问题从指数组合减少到少量恒定数量的线性扫描。

 ## 算法演练

 1. 对于每个测试用例，隐式地为每个索引构造一组可能的调整值作为区间$[a_i - 10, a_i + 10]$。 这代表该位置处所有可达到的最终值。 
2. 迭代其区间内位置 0 的最终值的所有选择。 每个选择代表算术级数的一个可能的起点。 
3. 对于每个这样的选择，迭代所有选择以获得其区间内位置 1 的最终值。 计算候选公差$d = (x_1 - x_0)$。 这是必要的，因为任何算术级数完全由两个连续值决定。 
4. 与$x_0$和$d$固定，计算每个索引的隐含值$i$作为$x_0 + i \cdot d$，并检查它是否在区间内$[a_i - 10, a_i + 10]$。 如果所有索引都满足这个条件，则存在有效的构造，我们可以返回“YES”。 
5. 如果以上都没有$441$前两个位置的组合产生有效的级数，返回“NO”。 

### 为什么它有效

 正确性取决于这样一个事实：任何算术级数都是由其前两项唯一确定的。 如果存在有效的变换，则索引 0 和 1 必须存在一些与前两项完全对应的调整值选择。 通过枚举这两个位置的所有可能的调整值，我们确保我们不会错过真正的潜在进展（如果存在）。 

一旦确定了候选级数，所有其他元素就变成了简单的可行性检查：其允许的区间是否包含该索引处所需的值。 由于每个元素的约束是独立的，因此一次违规就足以丢弃候选元素，并且不会保留任何隐藏的依赖关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def possible(a):
    n = len(a)

    # try all choices for first two points
    for x0 in range(a[0] - 10, a[0] + 11):
        for x1 in range(a[1] - 10, a[1] + 11):
            d = x1 - x0

            ok = True
            for i in range(n):
                val = x0 + i * d
                if val < a[i] - 10 or val > a[i] + 10:
                    ok = False
                    break

            if ok:
                return True

    return False

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n == 1:
            print("YES")
            continue
        if n == 2:
            print("YES")
            continue

        print("YES" if possible(a) else "NO")

if __name__ == "__main__":
    solve()
```该实现直接遵循使用前两个位置锚定进程的想法。 索引 0 和 1 的可能值上的嵌套循环会探索修改后的所有有效端点。 立即计算差异，然后在整个阵列上进行测试。 

微妙的细节处理小$n$。 什么时候$n \le 2$，任意两点总是可以在±10以内独立调整，因此总是可以形成等差级数。 这避免了不必要的计算并防止退化循环。 

验证步骤是严格线性的：对于每个候选线，我们计算每个索引的期望值并检查它是否位于允许的区间内。 提前终止可确保实践效率。

 ## 边缘情况

 一种边缘情况是当$n = 1$。 任何单个值都是算术级数，因为对差异没有限制。 该算法明确地短路了这种情况，避免了不必要的枚举。 

另一种情况是$n = 2$。 任何两个值始终可以在 ±10 范围内独立调整，因此我们始终可以选择与两个调整值相匹配的差值。 该算法将其视为始终有效，这是正确的，因为没有第三个约束来违反一致性。 

一种更微妙的边缘是存在多个候选斜率但只有一个全局有效。 例如，如果局部间隔允许前两个点有多个候选线，则大多数候选线在全扫描期间都会失败。 验证循环确保只有全局一致的线路才能生存，提前退出可以保证效率而不会丢失有效配置。
