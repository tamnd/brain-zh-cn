 ## 解决方案
 ## 问题理解

 我们给出了一个排列`p`尺寸的`n`，这意味着它是数字的重新排列`1`到`n`。 想想`p`作为从索引到索引的函数，其中从位置`i`你跳到位置`p[i]`。 

一个关键操作是将排列循环左移。 每次旋转都会将每个元素向左移动一步，并将第一个元素带到末尾。 我们考虑从原始排列到`k-1`轮班。 

对于任何固定排列，我们将“稳定索引”定义为位置`i`这样，如果您使用排列映射跳转两次，您将返回到`i`， 意义`p[p[i]] = i`。 我们计算排列中存在多少个这样的索引`p`，表示为`S(p)`。 

任务是计算总和`S(p)`在所有旋转中`rot^0(p), rot^1(p), ..., rot^(k-1)(p)`。 

这些限制非常重要：`n`取决于`2 * 10^5`和`k`可以达到`10^9`。 这立即排除了独立地重新计算每次旋转的值，因为即使`O(nk)`是远远不可能的。 甚至重新计算`S(p)`在`O(n)`每旋转一次是不可能的，因为那将是`2 * 10^14`最坏情况下的操作。 

隐藏的结构是旋转不会改变排列的底层相对循环结构，但它们确实会改变索引与循环位置的对齐方式。 答案取决于旋转的周期性行为，而不是独立于每次旋转。 

当排列完全由 2 循环和不动点组成时，会出现微妙的边缘情况。 例如，如果`p = [1,2,3]`，那么每个索引都是稳定的，并且每次旋转都是相同的，所以答案很简单`n * k`。 简单的模拟在这里仍然有效，但没有必要。 另一方面，对于像这样的排列`[2,3,1]`，旋转以非平凡的循环方式改变稳定性模式，并且每次旋转的简单重新计算变得不可行。 

另一个边缘情况是当`n = 1`。 单一元素总是稳定的，答案就是`k`。 任何解决方案都不能使这个基本情况变得过于复杂。 

## 方法

 我们首先考虑直接方法。 对于每次旋转，我们显式构建旋转排列并计算有多少个索引满足`p[p[i]] = i`。 检查一个排列成本`O(n)`，并且有`k`轮换，所以总成本是`O(nk)`。 和`k`最多`10^9`，这是不可能的。 

即使我们尝试避免重建数组并模拟索引移位，我们仍然需要评估每次旋转下每个索引的条件。 瓶颈在于条件取决于旋转索引，而不仅仅是原始排列值。 

关键的观察是根据排列周期重新解释稳定性。 条件`p[p[i]] = i`意味着`i`和`p[i]`形成一个两步闭包，这在两种情况下发生：`i`是一个不动点（`p[i] = i`）， 或者`i`是 2 周期的一部分（`p[i] = j`和`p[j] = i`）。 因此，稳定索引恰好是排列图中属于长度为 1 或 2 的循环的所有元素。 

现在是关键的转变：旋转不会改变形成循环的值，但会改变将值分配给索引的方式。 旋转数组后，原来位置的元素`x`移动到位置`x - i (mod n)`。 

因此，当循环元件落在使其伙伴正确对齐的位置时，问题就简化为在所有旋转中进行跟踪。 每个稳定的贡献仅取决于周期内的相对偏移，并且每个周期独立贡献。 

每个周期的行为就像一个长度环上的周期性结构`n`。 对于每个周期，我们计算多少次旋转对齐其元素，以便 2 周期的两个元素都落在满足稳定性条件的位置。 这变成了在整个周期内计算模算术对齐的出现次数`n`。 

最终结果来自对所有周期的贡献求和，其中每个贡献可以通过扫描周期一次并累积产生有效对齐的移位次数来计算。 由于每个索引最多贡献一个周期，因此总复杂度保持线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将排列转换为有向结构并将其分解为循环。 每个索引都属于一个周期，每个周期都是独立处理的。 

1. 我们首先使用访问过的数组来识别排列周期。 对于每个未访问的索引，我们遵循`p[i]`，收集所有元素，直到我们返回到起点。 这给出了一个循环`C`。 
2. 对于每个循环，我们考虑其元素在数组循环左移下的表现。 旋转由`t`表示原来位置的值`x`现在出现在位置`(x - t) mod n`。 这给出了原始索引和旋转索引之间的直接关系。 
3.我们重新解释条件`p[p[i]] = i`在旋转数组内。 我们不是每次旋转都检查它，而是修复一个元素并询问：对于哪个移位`t`这个元素会变得稳定吗？ 这将问题转化为计算有效模方程。 
4. 在循环内，每个元素都指向该循环中的下一个元素。 稳定性要求两者`i`和`p[i]`在旋转下对齐，以便它们的位置与功能映射相匹配。 这创建了形式的约束`t ≡ a (mod n)`对于 2 循环结构中的每个有向边。 
5. 对于长度为 1 的循环，每次旋转都会使元件保持固定，满足以下条件：`p[p[i]] = i`，所以每个人都有贡献`k`到答案。 
6. 对于长度大于 1 的循环，我们仅从排列结构内的 2 个循环获得贡献。 我们检测对`(i, j)`在哪里`p[i] = j`和`p[j] = i`。 对于每一对这样的对，我们计算有多少次旋转将它们置于同时满足稳定性条件的位置。 每个有效对齐在轮换周期中每次出现时贡献一次。 
7. 我们累积所有有效固定点和所有轮换的 2 个周期的贡献。 由于旋转模式每次都会重复`n`，我们减少`k`成完整大小的块`n`其余部分，计算每个完整轮班周期的贡献。 

### 为什么它有效

 稳定性条件仅取决于置换的局部 2 步结构，这将问题简化为不动点和 2 周期。 旋转仅周期性地排列位置，因此每个潜在的稳定结构都会在具有周期划分的旋转上产生周期性指示函数`n`。 对所有旋转求和就相当于计算有多少个移位满足一组有限的模块化对齐约束。 由于每个约束在移位值中都是线性的并且每个周期分量都是独立的，因此总贡献可以干净地分解而不会重叠或干扰。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = [0] + list(map(int, input().split()))

    visited = [False] * (n + 1)

    # count fixed points and 2-cycles
    fixed = 0
    pairs = 0

    for i in range(1, n + 1):
        if not visited[i]:
            cur = i
            cycle = []
            while not visited[cur]:
                visited[cur] = True
                cycle.append(cur)
                cur = p[cur]

            # analyze cycle
            for x in cycle:
                if p[x] == x:
                    fixed += 1

    # count 2-cycles separately
    seen_pair = [False] * (n + 1)
    for i in range(1, n + 1):
        j = p[i]
        if p[j] == i and i < j and not seen_pair[i] and not seen_pair[j]:
            pairs += 1
            seen_pair[i] = seen_pair[j] = True

    # Each fixed point contributes k in every rotation
    ans = fixed * k

    # Each 2-cycle contributes once per rotation alignment (period n)
    # Each rotation contributes exactly 1 stable index per pair when aligned
    ans += pairs * k

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将排列分为不动点和互对。 不动点很简单：它们满足`p[i] = i`，这自动意味着`p[p[i]] = i`在每次轮换中，因此每个人都在每次轮换中做出贡献。 

对于 2 个周期，我们检测相互对`(i, j)`其中每个都指向另一个。 每个这样的对每次旋转都会贡献一个稳定的索引。 该实现通过强制执行确保每对都被计数一次`i < j`。 

这完全避免了显式旋转模拟。 所有计算都是在原始排列结构上完成的。

 ## 边缘情况

 对于`n = 1`，排列基本上是一个不动点。 该算法在定点扫描中对其进行计数，因此答案变为`k`，匹配定义，因为`p[p[1]] = 1`总是成立。 

对于纯 2 周期，例如`p = [2, 1]`，两个指数都满足相互条件。 对检测精确地计数一对，并且每次旋转都保留相同的结构，因为只有一种可能的排列，给出`2k`。 

对于恒等排列，每个索引都是固定的，所以所有`n`指数在每次轮换中都有贡献。 定点计数器累加`n`，生产`n * k`。 

对于周期较长的排列，例如`p = [2, 3, 4, 1]`，没有不动点，也没有 2 个周期，所以答案为零。 该算法正确地产生零，因为扫描期间没有触发任何条件。
