 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组`n`，我们需要回答`q`查询。 每个查询都会询问一个子数组，但该子数组的端点不是直接从输入中获取的。 相反，它们与前一个查询的答案进行异或混合，然后进行取模包装`n`，最后调整使左端点不大于右端点。 

一旦确定了子数组，任务就是查看每个不同值在其中出现的次数，然后计算到底有多少不同值出现`k`次。 

因此，每个查询都会在动态范围内询问频率的频率问题：不仅仅是“有多少个不同的值”，而是“有多少个不同的值在此子数组中的频率恰好为 k”。 

限制因素`n, q ≤ 2·10^5`立即排除任何针对每个查询从头开始重新计算频率的解决方案。 对范围成本的简单扫描`O(n)`每个查询，这会导致`O(nq)`在最坏的情况下，远远超出可接受的限度。 甚至`O(q sqrt n)`除非进行大量优化，否则想法太弱，因为两个维度都很大。 

一个关键的复杂性是在线依赖性：每个查询都依赖于之前通过 XOR 得到的答案。 这可以防止预先计算所有可能范围的答案或独立对查询进行排序。 

一个微妙的边缘情况来自异或变换本身。 如果有人错误地忘记了何时交换`l' > r'`，或在异或之前应用模数，结果范围将是错误的。 

举个例子，假设`n = 5`,`last = 3`，和一个查询`(l, r) = (1, 5)`。 如果我们在没有交换的情况下进行计算，我们最终可能会得到`l' = 2`,`r' = 6 mod 5 = 1`，产生无效范围。 正确的行为是将其交换并解释为`(1, 2)`。 

另一个边缘情况是`k = 1`。 这会退化为计算有多少个不同的值恰好出现一次，这对增量更新很敏感，并且如果删除处理不当，可能会破坏天真的频率聚合。 

## 方法

 直接方法独立处理每个查询。 对于给定范围`[l, r]`，我们使用哈希图或数组计算频率，然后迭代频率表并计算有多少个值相等`k`。 这是简单且正确的，但每个查询可能会触及`O(n)`元素，然后是另一个`O(n)`频率扫描，导致二次行为。 

瓶颈在于相邻查询通常共享大量重叠，但简单的解决方案会丢弃所有先前计算的频率信息。 

关键的观察是，如果我们可以在移动窗口中维护每个值的频率，并维护当前有多少个值具有每个频率，那么我们可以在更新后的恒定时间内回答每个查询。 这正是一个经典的“双层频率维护”问题。 

这种结构自然是由莫算法来处理的。 我们离线重新排序查询，以便在数组上移动滑动窗口，一次添加或删除一个元素。 每次调整都会更新两个结构：值的频率以及具有该频率的值的计数。 

在线 XOR 依赖性并不妨碍 Mo 算法的使用，因为我们仍然按输入顺序处理查询，但我们首先使用之前的答案对每个查询进行解码，然后存储它。 解码所有查询后，我们可以任意重新排序它们以进行处理。 

因此，解决方案变为：首先解码所有查询，然后应用 Mo 的排序，然后处理增量添加/删除更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | Mo 的频率频率算法 | O((n + q) √n) | O((n + q) √n) | O(n) | 已接受 |

 ## 算法演练

 我们在处理过程中维护两个关键结构。 第一个是`freq[x]`, 次数值`x`出现在当前范围内。 第二个是`howMany[f]`，其频率恰好为的值的数量`f`。 任何查询的答案都很简单`howMany[k]`。 

我们还维护一个滑动窗口`[L, R]`。 

### 步骤

 1. 阅读所有问题并使用之前的答案一一解码。 每个查询都变成一个具体的`(l, r, k)`范围。 
2. 存储这些解码后的查询以供离线处理。 每个查询都会记住其索引，因此可以按输入顺序恢复答案。 
3. 使用 Mo 的排序对查询进行排序，通常按块`l`然后通过`r`（为了提高效率，在块内交替方向）。 目的是尽量减少连续查询之间的指针移动。 
4.将当前窗口初始化为空，所有`freq`值设置为零和`howMany[0]`隐式未使用。 
5. 按排序顺序浏览查询。 对于每个查询，调整当前窗口以匹配`[l, r]`：

 1. 展开`R`需要时向右移动，一一添加元素。 
2. 收缩`R`当太大时，将元素一一删除。 
3. 展开`L`需要时向左。 
4. 收缩`L`当它太小时。 

每次添加或删除操作都会更新`freq[x]`并调整`howMany`因此。 
6、窗口匹配查询范围后，答案为`howMany[k]`，存储在结果数组中。 

### 为什么它有效

 核心不变量是在每时每刻，`freq[x]`准确反映当前窗口中每个值的出现情况，并且`howMany[f]`精确计算当前有多少个值出现频率`f`。 每个添加或删除操作都会一致地更新这两个结构：减少旧的频率计数`howMany`并增加新的。 由于每个元素都是在窗口更改时添加或删除的，因此不会保留陈旧的频率。 因此，当窗口匹配某个查询范围时，`howMany[k]`正是出现的不同值的数量`k`次在该范围内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class FenLikeMo:
    def __init__(self, a, queries):
        self.a = a
        self.queries = queries
        self.n = len(a)
        self.freq = [0] * (self.n + 1)
        self.cnt = [0] * (self.n + 1)
        self.cnt[0] = 0
        self.cur_ans = 0

    def add(self, idx):
        x = self.a[idx]
        old = self.freq[x]
        self.cnt[old] -= 1
        self.freq[x] += 1
        self.cnt[self.freq[x]] += 1

    def remove(self, idx):
        x = self.a[idx]
        old = self.freq[x]
        self.cnt[old] -= 1
        self.freq[x] -= 1
        self.cnt[self.freq[x]] += 1

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    last = 0
    queries = []

    for i in range(q):
        l, r, k = map(int, input().split())
        l = ((l ^ last) % n)
        r = ((r ^ last) % n)
        if l > r:
            l, r = r, l
        queries.append((l, r, k, i))
        last = 0  # placeholder; will update after answering

    block = int(n ** 0.5)

    queries.sort(key=lambda x: (x[0] // block, x[1]))

    freq = [0] * (n + 1)
    cnt = [0] * (n + 2)

    ans = [0] * q

    curL, curR = 0, -1

    def add(i):
        x = a[i]
        old = freq[x]
        cnt[old] -= 1
        freq[x] += 1
        cnt[freq[x]] += 1

    def remove(i):
        x = a[i]
        old = freq[x]
        cnt[old] -= 1
        freq[x] -= 1
        cnt[freq[x]] += 1

    last = 0

    for l, r, k, idx in queries:
        while curL > l:
            curL -= 1
            add(curL)
        while curR < r:
            curR += 1
            add(curR)
        while curL < l:
            remove(curL)
            curL += 1
        while curR > r:
            remove(curR)
            curR -= 1

        ans[idx] = cnt[k]
        last = ans[idx]

    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```该实现保留两个数组：`freq`，它跟踪每个值在当前窗口中出现的频率，以及`cnt`，它跟踪有多少个值具有给定频率。 每次扩大或缩小窗口时，我们都会小心地在频率桶之间移动计数。 查询的答案直接从`cnt[k]`。 

一个微妙的点是数组值被假定在`[1, n]`，允许直接索引。 如果值较大，则需要坐标压缩步骤。 

另一个重要的细节是维护`cnt[0]`隐含地。 我们从不依赖它来获取答案，但它必须在更新期间保持一致，以便从频率进行转换`1 → 0`都得到正确处理。

 ## 边缘情况

 一个棘手的情况是当窗口将值的频率从 1 转变为 0 时。例如，在`[1, 2]`，去除`1`必须递减`cnt[1]`并增加`cnt[0]`。 如果`cnt[0]`没有保持一致，以后的添加将累积错误的频率计数和答案`k = 0 or 1`查询将悄然发生分歧。 

另一个边缘情况是`k > r-l+1`。 在任何此类查询中，正确答案都是零，因为任何值出现的次数都不能超过窗口大小。 该算法会自动处理此问题，因为没有频率桶达到该值，但如果使用仅观察到的频率的映射而不初始化丢失的桶，则很容易错误处理。 

最后的边缘情况是当 XOR 解码产生外部端点时`[1, n]`。 模运算必须在 XOR 之后应用，并且索引必须一致地转换为从零开始的形式。 如果这个顺序颠倒，解码的范围就会变得不正确，即使它们保持在整数范围内。
