 ## 解决方案
 ## 问题理解

 我们被要求计算可被给定整数整除的页码最后一位数字的总和。 坡旅甲读一本页码从 1 到 n 的书。 每个可被 m 整除的页码都会被记录，但只写入最后一位数字。 我们需要多个查询的这些数字的总和，每个查询都有不同的 n 和 m。 

限制是惊人的。 n 和 m 都可以达到$10^{16}$，我们最多可能有 1000 个查询。 循环遍历 m 到 n 的每个倍数的简单方法是不可行的，因为这可能会达到$10^{16}$单个查询中的迭代。 甚至与 n 成比例的线性运算也被完全排除。 

容易被忽略的边缘情况包括 m 大于 n 的情况。 例如，如果 n=5 且 m=10，则没有可被 m 整除的页，因此总和必须为零。 另一个微妙的情况是当 m 是一位数时； 此处，最后一位数字的模式每 10 倍重复一次。 对于非常大的 n 来说，尝试对数字求和而不考虑这种周期性的粗心方法将是低效的或错误的。 

## 方法

 蛮力方法很简单。 对于每个查询，迭代从 m 到 n 的所有 m 倍数，取出每个倍数的最后一位数字，并将它们加在一起。 虽然这在逻辑上是正确的，但操作次数大约为 n/m，最多可达$10^{16}$在最坏的情况下。 对于时间限制来说这太慢了。 

关键的洞察来自观察最后的数字。 最后一位数字以长度为 10 的周期重复。如果我们检查序列 m, 2m, 3m, ..., 10m，这 10 个数字的最后一位数字形成重复模式。 10 个倍数的每个完整周期的数字和是恒定的。 因此，我们可以计算单个周期的总和，并将其乘以完整周期的数量（以 n/m 为单位）。 最后，我们添加最后一个完整周期后剩余倍数的贡献。 这将每个查询的复杂度从 O(n/m) 降低到 O(10)，因为每个循环最多有 10 个元素，并且我们仅根据循环重复计算总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n/m) | O(1) | O(1) | 对于大 n 来说太慢 |
 | 最佳 | 每个查询 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算 m 到 n 的倍数 k = n // m。 这告诉我们波旅甲有多少页记录。 
2. 生成 m 的前 10 个倍数的最后一位模式：将 m 乘以 1, 2, …, 10，然后对每个模 10。将此序列存储在列表中`pattern`。 
3. 计算 10 个倍数的一个完整周期的总和：`cycle_sum = sum(pattern)`。 
4. 确定 k 中有多少个 10 的完整循环：`full_cycles = k // 10`。 乘`cycle_sum`经过`full_cycles`获得所有完整周期的总和。 
5. 处理未完成完整循环的剩余倍数：`remaining = k % 10`。 将第一个数字的最后一位数字相加`remaining`中的元素`pattern`并将其添加到总和中。 
6. 输出查询的总和。 

原理：任何以 10 为模的整数的最后一位数字仅取决于 m 乘以乘数的最后一位数字，因此在 10 倍之后，该模式会重复。 这可确保计数周期和部分周期正确涵盖所有贡献。 该方法保证不会遗漏 m 的倍数，也不包含额外的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n, m = map(int, input().split())
        k = n // m  # total number of multiples
        
        # generate last-digit pattern for first 10 multiples
        pattern = [(m * i) % 10 for i in range(1, 11)]
        cycle_sum = sum(pattern)
        
        full_cycles = k // 10
        remaining = k % 10
        
        total = full_cycles * cycle_sum + sum(pattern[:remaining])
        print(total)

if __name__ == "__main__":
    solve()
```该代码读取查询数量并迭代它们。 对于每个查询，它计算 k 的倍数并生成 m 的 10 长度最后一位模式。`full_cycles`捕获模式完全重复的次数，以及`remaining`处理剩余的倍数。 这可以确保不会出现差一错误，因为 Python 切片是从零开始的。 使用整数除法和取模可以有效地处理极大的数字。 

## 工作示例

 跟踪查询`n=15, m=5`:

 | k | 图案| 周期总和 | 完整周期 | 剩余| 总计 |
 | ---| ---| ---| ---| ---| ---|
 | 3 | [5,0,5,0,5,0,5,0,5,0] | 25 | 25 0 | 3 | 5+0+5=10 |

 算法正确计算出有 3 个倍数（5、10、15），最后一位数字之和为 10。 

跟踪查询`n=1024, m=14`:

 k = 1024 // 14 = 73

 模式 = [4,8,2,6,0,4,8,2,6,0]

 周期总和 = 40

 full_cycles = 73 // 10 = 7

 剩余 = 73 % 10 = 3

 总计 = 7*40 + (4+8+2) = 280 + 14 = 294

 这证明了完整循环和部分循环的正确处理。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 对于 n=5、m=10、k=0，模式不相关，full_cycles=0，剩余=0，总计=0。 代码正确输出0。 

对于 n=9、m=9、k=1、pattern = [9,8,...]、remaining=1、sum(pattern[:1]) = 9。输出如预期为 9。 

对于 m=1 的非常大的 n，该算法可以正确处理整数除法和循环，使用重复的最后一位模式在恒定时间内对数千万亿项求和。
