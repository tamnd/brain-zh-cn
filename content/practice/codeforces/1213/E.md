 ## 解决方案
 ## 问题理解

 我们被要求构建一个长度的字符串$3n$在字母表上$\{a,b,c\}$，其中每个字符完全出现$n$次。 除了这个平衡约束之外，还给出了两个禁止模式，每个模式都是长度为 2 的字符串。 构造的字符串不得包含这两对中的任何一个作为其内部任何位置的相邻字符。 

因此，任务不是松散意义上的子序列或重新排列，而是对多组字符进行排序，以便连续字母之间不会出现禁止的有向边缘。 每个长度为 2 的禁止字符串的行为就像一个有向约束：如果我们看到`"ab"`在输入对列表中，那么我们不允许放置`a`紧接着`b`在最终的安排中。 

限制条件很大：$n$可以达到$10^5$，所以最终的字符串长度可达$3 \cdot 10^5$。 任何尝试尝试排列或回溯放置的解决方案都将立即失败，因为状态空间呈阶乘增长。 即使是二次构造也可能是边缘性的。 预期的解决方案必须是线性或接近线性的。 

一个微妙的问题来自于约束之间的相互作用。 单独地局部避免每个禁止对是不够的，因为如果提前放置一个字符，如果它造成了在不违反计数或约束的情况下无法排列剩余字符的情况，则可能会阻止未来的放置。 

总是仅基于当前最后一个字符附加安全字符的天真贪婪可能会失败。 例如，如果我们总是选择字典顺序最小的有效下一个字符，那么当只有禁止的转换仍然可用时，我们可能会陷入困境。 

另一个不明显的陷阱是假设如果两个禁止对共享一个字符，比如说`"ab"`和`"ac"`，那么我们可以简单地避免放置`a`在两者之前`b`和`c`没有进一步的结构。 这是具有误导性的，因为我们仍然必须准确地放置所有计数，并且某些顺序可能会完全隔离一个字符。 

## 方法

 暴力视图将尝试逐步构造字符串，在每个位置尝试所有可能的剩余字符并检查附加它是否会创建禁止的对或导致不可能的后缀。 这实际上成为对深度最多为 3 的分支因子的回溯搜索$3n$。 即使进行了修剪，最坏情况的行为也会呈指数级增长，因为许多部分字符串在本地仍然有效，但在全局范围内无法挽救。 

关键的结构观察是只有三个字符。 任何禁止对最多删除 3 节点有向图中的一个有向边。 这意味着我们本质上是在一个微小的有向图上构建遍历，同时尊重确切的顶点访问计数。 由于图的大小是恒定的，我们可以利用案例分析而不是搜索。 

我们将问题解释为在节点上构建序列$a,b,c$，其中边对应于允许的转换。 每个禁止对从 6 个可能的转换的完整有向图中删除一个有向边。 由于仅禁止两个边，因此至少允许四个转换。 

关键思想是选择字符的“基本顺序”，然后小心地将第三个字符插入块中，以便我们永远不会使用禁止的转换。 如果我们将一个字符视为“分隔符”或“锚点”，通常可以将问题简化为将剩余两个字符排列在安全的交替结构中，然后将第三个字符插入块中。 

经典的技巧是固定三个字符的顺序，例如$x, y, z$，并尝试构造一个字符串，我们首先决定如何$x$和$y$交互，然后分发$z$而不创建禁止对。 Since only two transitions are forbidden, at least one permutation of$(a,b,c)$将避免破坏结构。 

我们不是随机猜测，而是尝试所有$6$字符的排列并尝试为每个字符进行确定性的构造。 对于固定顺序，我们贪婪地构建字符串，同时保持计数并确保我们永远不会放置禁止的相邻对。 Because the alphabet is tiny, this deterministic construction is enough.

 当我们总是尝试在最后放置的字符之后放置一个不被禁止的字符时，贪婪策略会起作用，并且更喜欢那些剩余数量的字符。 如果构造失败，则意味着排序不兼容，我们需要切换排列。 

这将问题从指数搜索减少为线性贪婪构造的不断尝试。

 ## 算法演练

 我们尝试通过尝试字符的所有排列来构建答案`a`,`b`,`c`。 

对于每个排列：

 1. 初始化剩余计数：每个`a`,`b`,`c`是$n$。 还启动一个空结果字符串。 
2. 重复选择要附加的下一个字符。 

我们考虑当前排列顺序中的字符，并选择仍然具有剩余计数并且不会与最后一个字符创建禁止的相邻对的第一个字符。 

按排列顺序扫描的原因是为了保持构造的确定性并避免振荡。 
3. 追加所选字符，减少其剩余计数，并更新最后一个字符跟踪器。 
4. 如果在某个时刻，在计数剩余的情况下无法放置任何字符，则中止此排列并重新开始下一个排列。 
5. 如果我们成功放置了所有$3n$字符，立即输出结果。 

为什么这种贪婪的工作与状态空间非常小有关。 在每一步中，我们只需要避免当前字符至多两个禁止的传出边缘。 由于总共存在三个选项，因此在有效排列中至少有一个候选在结构上始终是安全的。 尝试所有排列可以保证我们最终选择与禁止的转换一致的顺序。 

### 为什么它有效

 该结构保持了字符串的每个前缀不包含禁止的相邻对的不变性。 该算法失败的唯一原因是剩余字符都导致从当前最后一个字符开始禁止转换。 如果发生这种情况，则意味着所选择的全局排序强制进入死胡同，这意味着在该排列下不存在完成。 由于正确的解决方案必须对应于与约束一致的字母表的某种排序，因此六种排列之一避免了这种死胡同并取得了成功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build(order, n, bad):
    cnt = {c: n for c in "abc"}
    res = []
    
    for _ in range(3 * n):
        placed = False
        last = res[-1] if res else None
        
        for ch in order:
            if cnt[ch] == 0:
                continue
            if last is not None and last + ch in bad:
                continue
            cnt[ch] -= 1
            res.append(ch)
            placed = True
            break
        
        if not placed:
            return None
    
    return "".join(res)

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()
    bad = {s, t}
    
    chars = "abc"
    
    from itertools import permutations
    
    for order in permutations(chars):
        ans = build(order, n, bad)
        if ans is not None:
            print("YES")
            print(ans)
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```该解决方案首先将禁止的转换编码为 O(1) 查找的集合。 然后，它尝试将字母表的所有 6 种排列作为潜在的结构优先级。 

这`build`函数贪婪地构造一个固定顺序下的有效序列。 关键的细节是，在附加候选者之前，我们总是根据禁止集检查最后放置的字符。 如果没有候选者在某个步骤中起作用，我们就完全放弃当前的排列。 

一个常见的实现错误是未能在排列之间干净地重新启动状态。 另一个微妙的问题是忘记空前缀没有最后一个字符，必须单独处理。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()
    t = input().strip()

    bad = {s, t}

    from itertools import permutations

    def build(order):
        cnt = {c: n for c in "abc"}
        res = []
        for _ in range(3 * n):
            last = res[-1] if res else None
            ok = False
            for ch in order:
                if cnt[ch] and (last is None or last + ch not in bad):
                    cnt[ch] -= 1
                    res.append(ch)
                    ok = True
                    break
            if not ok:
                return None
        return "".join(res)

        ans = build(order)
        if ans is not None:
            return "YES\n" + ans + "\n"

    return "NO\n"

 ## 边缘情况

 当两个禁止对消除同一字符的转换时，就会出现一种边缘情况。 例如，如果`s = ab`和`t = ac`， 然后`a`不能去任何一个`b`或者`c`。 该算法处理这个问题是因为在排列中`a`如果提前被强制，它将很快无法扩展字符串，并且排列将被丢弃。 成功的排列位置`a`稍后或避免使其成为瓶颈状态。 

另一种情况是当禁止对形成一个循环时，例如`ab`和`ba`。 这里`a`和`b`不能在任一方向相邻。 该结构自然地将它们分开`c`，以及任何排列`c`他们之间成功了。 贪心进程永远不会尝试非法邻接，因此分隔符的作用`c`自动出现。 

第三种情况是两个禁止对都涉及概念上重复的相同有序对，例如相同的输入。 这有效地减少到一个约束，并且该算法仍然尝试所有排列并且微不足道地成功，因为至少一种排序避免了单个禁止边缘。
