 ## 解决方案
 ## 问题理解

 我们得到一棵加权树，其中每条边都有成本，并且我们被问到多个关于顶点对之间的路径有多“昂贵”的问题。 

对于任意两个顶点$u$和$v$，它们之间只有一条简单的路径，因为图是一棵树。 沿着这条路径，我们查看所有边权重并取最大的一个。 查询询问：在所有不同的顶点对中，有多少个在其连接路径上的最大边权重不超过给定阈值$q$。 

因此，每个查询本质上都是在问：是否只允许我们“使用”边权重$q$，有多少对节点仅通过此类边连接。 

直接的解释是，我们正在计算位于图的同一连通分量中的顶点对，该图通过仅保留最多权重的边而形成$q$。 

约束条件达到$2 \cdot 10^5$顶点、边和查询。 这会立即排除每个查询从头开始重新计算连接的情况。 任何尝试为每个查询运行 DFS 或 BFS 的方法都会导致粗略的结果：$O(m(n + n))$，这远远超出了可行的限度。 

第二个微妙的问题是对所有查询的独立计数。 除非我们利用排序和重用结构，否则答案并不是天真的意义上的增量。 

一个幼稚的错误是单独解释每个查询并每次都重建一个过滤图。 例如，如果所有边都是不同的并且查询也很大，则即使对于中等输入，重复遍历也会超时。 

另一个常见的陷阱是尝试使用 LCA 预处理来计算每对的路径最大值。 虽然 LCA 可以计算路径上的最大边$O(\log n)$，为所有人做这件事$O(n^2)$成对是不可能的。 

## 方法

 蛮力观点是从定义开始的。 对于每个查询$q$，我们会检查每一对$(u, v)$，计算其路径上的最大边权重，并计算有效对。 即使使用 LCA 预处理，每个查询也会花费$O(n^2 \log n)$，这对于$n = 2 \cdot 10^5$。 

更结构化的观点来自于翻转视角。 我们不是询问“对于每对，其路径上的最大边是多少”，而是询问“对于每个阈值，当激活达到该阈值的边时，有多少对成为连接”。 

当我们增加允许的重量时，边缘会以递增的顺序出现。 每次我们添加一条边时，它可能会合并两个以前独立的组件。 当两个分量的尺寸$a$和$b$合并，他们贡献$a \cdot b$新的有效对，因为一个组件中的每个顶点现在可以使用至多当前权重的边到达另一个组件中的每个顶点。 

这一观察结果将问题转换为排序边上的动态连接过程，这正是 DSU（不相交集并集）有效维护的。 我们不是按查询重新计算组件，而是以增加的权重处理边并增量地维护连接对的数量。 

查询还可以按阈值排序，使我们能够按顺序扫描边缘和查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(m n^2)$或者更糟|$O(n)$| 太慢了 |
 | DSU + 排序 |$O((n + m)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们以递增的权重处理边，同时以递增的顺序回答查询$q$。 

1. 按权重以非降序对所有边进行排序。 

这确保了当我们处理一条边时，所有之前处理过的边都不比它重。 
2. 对查询进行排序，但跟踪原始索引。 

这使我们能够按原始顺序输出答案，同时仍能高效处理。 
3. 初始化 DSU，每个节点都在其自己的组件中。 

由于没有连接两个不同的节点，因此每个组件最初贡献零对。 
4. 维护运行变量`ans = 0`表示当前仅使用已处理边连接的有效对的数量。 
5. 将指针保持在边缘上方。 

对于每个查询阈值$q$，我们在边权重的同时推进边指针$\le q$。 

每次我们处理一条边$(u, v, w)$：

如果$u$和$v$位于不同尺寸的 DSU 组件中$a$和$b$，合并它们会增加`ans`经过$a \cdot b$。 

然后我们联合组件。 
6. 处理完所有边缘后$q$， 店铺`ans`作为该查询的答案。 

### 为什么它有效

 在加工边缘时随时达到重量$q$，DSU分量正是由权重最多的边形成的子图的连通分量$q$。 同一组件内的每对节点都有一条路径，其最大边最多为$q$，因为组件中的所有边都满足此边界。 

相反，如果两个节点位于不同的组件中，则它们之间不存在使用边的路径$\le q$，所以它们的路径必须包含大于$q$。 因此，它们被正确排除。 

每个并集操作都准确地考虑了新添加的边引入的新的可达对，并且不会对任何对进行两次计数，因为一旦两个节点连接起来，它们就会在所有更大的阈值内保持连接。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        pairs = self.size[a] * self.size[b]
        self.size[a] += self.size[b]
        return pairs

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    queries = list(map(int, input().split()))
    q = [(queries[i], i) for i in range(m)]
    q.sort()

    dsu = DSU(n)
    ans = 0
    ei = 0
    res = [0] * m

    for val, idx in q:
        while ei < len(edges) and edges[ei][0] <= val:
            w, u, v = edges[ei]
            ans += dsu.union(u, v)
            ei += 1
        res[idx] = ans

    print(*res)

if __name__ == "__main__":
    solve()
```DSU 存储组件大小，以便每次合并都准确贡献所创建的新顶点对的数量。 边和查询的排序确保我们永远不会重新访问边或重新计算连接性。 

一个微妙的实现细节是返回来自的贡献`union`而不是在 DSU 内进行全局更新。 这使逻辑清晰并避免意外的重复计算。 

另一个重要的点是索引：顶点会立即转换为从零开始的索引，以避免在 DSU 操作期间重复转换。

 ## 边缘情况

 关键的边缘情况是所有边缘的权重都大于最小查询。 在这种情况下，在回答早期查询之前不会发生并集，因此所有答案必须保持为零，直到阈值穿过最小边权重。 DSU 确保了这一点，因为直到`edges[ei][0] <= q`。 

另一种情况是所有边具有相同的权重。 然后，每个查询要么返回零（如果低于该权重），要么在处理所有边后返回完整的对数。 该算法自然地处理这个问题，因为当达到阈值时，所有等权重边缘都会在单个批次中处理。 

第三个微妙的情况是大型部件过早形成。 当非常小的边连接两个大的子树时，对贡献立即变大。 union 函数计算`size[a] * size[b]`在合并时，确保计数在连接时准确且不会在以后重新计算，从而避免未来查询中的重复计算。
