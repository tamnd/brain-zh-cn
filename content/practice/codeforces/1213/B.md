[CF 1213B - 糟糕的价格](https://codeforces.com/problemset/problem/1213/B)

 ## 解决方案
 ## 问题理解

 我们得到了几个独立的实验，每个实验都由产品的每日价格序列组成。 对于每个序列，我们需要确定有多少天是“不幸运”的，在以下意义上：如果存在稍后某一天的价格严格低于当天的价格，则认为这一天是糟糕的一天。 

因此，对于数组中的每个位置，我们实际上是在询问其右侧是否有更小的值。 如果存在这样的值，则该位置有助于得出答案。 

约束条件总计很大，所有序列的总长度高达 150,000。 这立即排除了将每个元素与其右侧的所有元素进行比较的任何解决方案，因为在最坏的情况下这将是二次的，并导致对抗性输入中大约 1010 次操作。 每个测试用例需要进行线性或近线性扫描。 

当数组严格递增时，会出现微妙的边缘情况。 例如，在`[1, 2, 3, 4]`，没有元素在其右侧具有更小的值，因此答案为零。 如果没有正确检查严格较小的值而不是较小或等于的值，则幼稚的方法可能会错误地计算比较。 

另一个边缘情况是严格递减的数组，例如`[5, 4, 3, 2, 1]`。 除最后一个元素之外的每个元素后面都有一个较小的元素，所以答案是`n-1`。 这是暴力破解的最坏情况，因为每个前缀元素都属于坏元素。 

## 方法

 直接解释导致一个简单的暴力方法：对于每一天`i`,全天扫描`j > i`并检查是否有`a[j] < a[i]`。 如果存在这样的一天，我们将增加该天的答案`i`。 

这是正确的，因为它遵循字面定义。 然而，其成本是有问题的。 在最坏的情况下，例如递减序列，我们大致执行`n + (n-1) + ... + 1`，每个测试用例的比较次数为 O(n²)。 总共有`n`达到 150,000 时，这变得太慢了。 

关键的观察是我们不需要知道哪个未来值更小，只需要知道是否至少存在一个。 这建议维护有关数组后缀的信息。 如果我们从右向左遍历，我们可以跟踪到目前为止看到的最小值。 在每个位置，我们将当前元素与该后缀最小值进行比较。 如果当前值大于其右侧的最小值，那么我们已经知道存在更小的未来元素，所以这个位置不好。 

这将问题减少到每个测试用例一次通过，因为后缀最小值可以增量更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 后缀最小扫描 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例并从右到左扫描数组。 

1.从最后一天开始，初始化一个变量`min_suffix`与最后的价格。 这代表严格位于当前位置右侧的所有日期中看到的最小价格。 
2. 一次左移一步，每天检查一次`i`。 
3. 对于每个位置，进行比较`a[i]`和`min_suffix`。 如果`a[i] > min_suffix`，那么存在价格较低的较晚一天，因此这一天`i`很糟糕，我们增加答案。 
4.无论是否增量，我们都会更新`min_suffix = min(min_suffix, a[i])`确保它始终反映从以下位置开始的后缀中的最小值`i`。 
5. 继续，直到处理完第一个元素。 

正确性取决于这样一个事实：当我们处理索引时`i`,`min_suffix`完全等于`min(a[i+1], ..., a[n])`，所以比较相当于检查右侧是否存在更小的元素。 

### 为什么它有效

 每一步，`min_suffix`将后缀的最小值严格存储在当前索引的右侧。 这个不变量成立，因为我们仅在处理每个元素后更新它。 因此，条件`a[i] > min_suffix`当存在某些时正是正确的`j > i`这样`a[j] < a[i]`。 没有关于身份的信息`j`所需要的只是它的存在，它被后缀最小值完全捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    min_suffix = a[-1]
    bad = 0
    
    for i in range(n - 2, -1, -1):
        if a[i] > min_suffix:
            bad += 1
        if a[i] < min_suffix:
            min_suffix = a[i]
    
    out.append(str(bad))

print("\n".join(out))
```实现直接遵循反向扫描。 变量`min_suffix`始终表示当前索引右侧的最小值，因此比较`a[i] > min_suffix`是“糟糕的一天”定义的精确翻译。 更新条件确保我们正确传播新的最小值。 

初始化时必须小心`min_suffix`对于最后一个元素，因为最后一天没有未来的日子，而且永远不会是坏的。 此外，每个测试用例都会保留答案累加器，以避免数据集之间的交叉污染。

 ## 边缘情况

 在单元素数组中，例如`[10]`，反向扫描初始化`min_suffix`为 10 并且永远不会进入循环。 没有进行比较，因此答案仍然是 0，这符合定义，因为没有未来的日子。 

在严格递增的序列中，例如`[1, 2, 3, 4]`，每一步的后缀最小值总是大于或等于当前值，所以条件`a[i] > min_suffix`永远不会触发。 该算法正确地避免了误报。 

在严格递减序列中，例如`[5, 4, 3, 2, 1]`，除了最后一个元素之外的每个元素都大于该点的后缀最小值，因此每个元素都被视为坏元素。 该算法精确递增`n-1`次，与每个前缀元素具有较小的未来值的事实相匹配。
