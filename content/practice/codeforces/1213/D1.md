 ## 解决方案
 ## 问题理解

 我们得到一个整数列表，并且可以通过将其替换为向下舍入的一半来重复减少任何选定的数字。 每一次这样的更换都需要一次手术。 目标不是使所有数字相等，而是在经过一定序列的这些减半操作后，强制其中至少 k 个值完全相同。 

关键的困难在于平等不是被赋予的，而是被制造出来的。 像 10 这样的值可以变成 10, 5, 2, 1, 0，具体取决于我们除它的次数。 因此，每个元素都定义了一个可达值链，我们试图找到一个至少 k 个元素可以以最小的总成本达到的目标值。 

约束非常小，n 最多为 50，值最大为 200000。这立即排除了 n 中的任何指数。 然而，它强烈表明我们可以模拟每个元素的转换，甚至收集每个元素的所有可能状态，因为每个数字只能除以 log2(200000) 的 2，这不到 20 个步骤。 

一个微妙的边缘情况来自这样一个事实：不同的起始值可能以不同的成本折叠成相同的中间值。 例如，8 分两步变成 2，9 也分两步变成 2，尽管它们的路径不同。 另一个边缘情况是零：一旦一个数字变为零，它就保持为零，因此许多元素可以廉价地收敛到那里。 像选择最常见的初始值这样天真的贪婪选择会失败，因为只有在转换之后才能实现相等。 

## 方法

 暴力方法会尝试直接确定目标值。 对于每个可能的目标，我们可以尝试计算可以将多少个元素转化为它以及以什么成本，然后以最小的成本总和选择其中的 k 个。 具体来说，对于每个元素，我们可以模拟除以 2，直到达到所有可能的值，记录达到每个元素的成本，然后对每个目标进行聚合。 

这种强力的想法已经接近最佳，因为每个元素可到达的状态数量很少。 每个数字最多生成大约 20 个状态，因此在 50 个元素中，我们总共只有大约 1000 个转换。 关键的观察是，我们不需要考虑这些链生成的目标之外的目标。 每个有效的相等值必须出现在至少一个转换链中，因此我们只考虑这些候选值。 

对于每个候选值，我们从可以到达它的元素中收集所有成本，对它们进行排序，并取最小的 k 成本。 答案是所有候选人中的最低答案。 这是有效的，因为一旦我们确定了目标值，问题就变得独立于每个元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（每个目标的完全模拟）| O(n * A log A) | O(n * A log A) | O(nA) | 太慢/尴尬|
 | 最优（预计算所有状态+聚合）| O(n * log A + S log S) | O(n * log A + S log S) | O(S)| 已接受 |

 这里S是生成状态的总数，大约是n log A。 

## 算法演练

 1. 对于每个元素，生成通过重复除以 2 可达到的所有值，同时跟踪达到每个值所需的操作次数。 

这将为该元素构建从价值到成本的映射。 
2. 对于每个可达值，存储一个对列表（cost，element_index）。 

这颠倒了观点：我们不是询问一个元素可以产生什么值，而是收集哪些元素可以产生值。 
3. 对于所有元素中看到的每个不同值，将其视为候选最终目标。 
4. 对于固定的候选值，收集可以达到该值的所有元素的所有成本。

如果少于 k 个元素可以到达它，则跳过它，因为它不能形成 k 个相等的数字。 
5. 对收集到的成本进行排序，并取最小的 k 值之和。 
6. 跟踪所有候选值的最小总和。 

### 为什么它有效

 元素上的每个操作序列完全由我们除以 2 的次数决定，因此每个可达状态在预计算链中都唯一表示。 k 个元素相等的任何有效的最终配置必须对应于至少一个链中出现的某个值。 对于固定值，选择 k 个最小成本是最优的，因为每个元素独立贡献，并且我们只关心最小化总操作，而不是路径结构。 由于所有候选都已被枚举，因此不能错过全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    from collections import defaultdict

    # value -> list of (cost)
    pos = defaultdict(list)

    for x in a:
        cur = x
        dist = 0
        while True:
            pos[cur].append(dist)
            if cur == 0:
                break
            cur //= 2
            dist += 1

    ans = float('inf')

    for v, costs in pos.items():
        if len(costs) < k:
            continue
        costs.sort()
        ans = min(ans, sum(costs[:k]))

    print(ans)

if __name__ == "__main__":
    solve()
```核心实现准确地反映了转换链。 对于每个数字，我们模拟重复减半并记录到每个遇到的值的距离（操作次数）。 该字典对不同元素达到相同值的所有方法进行了分组。 

在评估候选值时，排序是必要的，因为我们希望在所有贡献者中进行 k 个最便宜的转换。 前 k 个排序成本的总和直接代表了选择我们“花费”哪些元素来达到该值的最佳方式。 

一个常见的错误是忘记同一个值可以在同一个元素链中出现多次； 在此实现中，它是安全的，因为每个元素只为每个步骤级别贡献一个成本。 

## 工作示例

 ### 示例 1

 输入：```
5 3
1 2 2 4 5
```我们计算链：

 | 元素| 链（价值：成本）|
 | ---| ---|
 | 1 | 1:0 → 0:1 |
 | 2 | 2:0 → 1:1 → 0:2 |
 | 2 | 2:0 → 1:1 → 0:2 |
 | 4 | 4:0 → 2:1 → 1:2 → 0:3 |
 | 5 | 5:0 → 2:1 → 1:2 → 0:3 |

 现在考虑值 2 作为目标：

 达到 2 的成本为：从 2 (0) 开始、从 2 (0) 开始、从 4 (1) 开始、从 5 (1) 开始。 

我们选择 k = 3 个最小成本：0 + 0 + 1 = 1。 

| 目标| 成本| 选定 k=3 | 总和|
 | ---| ---| ---| ---|
 | 2 | [0,0,1,1] | [0,0,1]| 1 |

 这符合最佳答案。 

### 示例 2

 输入：```
4 2
10 20 40 1
```链条包括：

 10: 10,5,2,1,0

 20: 20,10,5,2,1,0

 40: 40,20,10,5,2,1,0

 1:1,0

 考虑目标 5：

 | 元素| 成本为 5 |
 | ---| ---|
 | 10 | 10 1 |
 | 20 | 2 |
 | 40 | 40 3 |

 我们需要 k=2 最小的：1 + 2 = 3。 

这表明最佳目标不一定是一开始就已经频繁出现的值，而是可以通过多个元素廉价地达到的值。

 ## 边缘情况

 一种重要的边缘情况是所有数字都相等。 例如`7 7 7`任意 k ≤ 3。该算法记录每个元素中值 7 的零成本条目，因此候选 7 立即产生总和 0。 

另一种情况是最佳交汇点为零时。 对于像这样的输入`1 2 3`，所有链最终都归零，零积累了足够多的贡献者。 成本不同，但算法自然会选择零作为候选，并选择最便宜的 k 条路径。 

第三种情况是最优值不在原始数组中。 在`10 20 40 1`，值 5 最初从未出现，但可以通过较小的成本从多个元素到达。 因为记录了每个中间状态，所以仍然考虑 5 并且可以成为最佳状态。
