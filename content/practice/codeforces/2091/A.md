 ## 解决方案
 ## 问题理解

 我们被要求找出最早的步骤，可以从一串数字序列中形成一个特定的日期，即 2025 年 3 月 1 日。 不带分隔符的日期是`01032025`，所以目标是检测我们何时按顺序绘制这些数字，从而允许忽略中间的额外数字。 每个测试用例给出一个序列`n`按时间顺序绘制的数字。 如果序列不包含正确顺序的所有数字，我们返回`0`。 

限制很小：`n`最多 20。这意味着我们可以多次扫描数组或维护简单的计数器，而不必担心效率。 测试用例数量`t`最大可达 10^4，因此我们必须确保每个测试用例的处理速度快，理想情况下是线性的`n`。 

一个微妙的问题是日期的数字必须**按顺序**出现，包括前导零。 例如，如果我们看到`1 0 3 2 0 2 5`，我们不能使用第一个`1`日期，因为它紧随其后`0 3`而不是`0 1`当日期开始时。 另一个棘手的情况是当额外的数字副本提前出现时：`0 0 1 0 3 2 5 0 2 5`。 一个粗心的算法，只检查所有数字是否存在（没有顺序），会错误地表示日期是在第二个数字之后形成的`0`，但正确的顺序需要遵循`01032025`命令。 

## 方法

 暴力方法是尝试迄今为止绘制的每个数字组合，并检查它们是否可以形成日期`01032025`。 自从`n`最多可达 20 个，这将涉及检查最多`2^20`子集，这在 1 秒内是不可能的。 即使显式生成所有子序列也是矫枉过正。 

关键的见解是我们不需要所有子集，只需要**按顺序最早出现的**。 我们可以将该问题视为从左到右扫描序列，同时将指针与日期相匹配。 每次我们看到一个数字等于日期中的当前目标时，我们就将指针前进。 当指针到达日期末尾时，我们找到了包含完整日期的最小前缀。 这是可行的，因为任何跳过的数字都不会影响顺序； 只有每个日期数字第一次出现才重要。 自从`n`很小，简单的线性扫描就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * 8) | O(2^n * 8) | O(n) | 太慢了 |
 | 最佳 | 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 定义目标日期序列为`01032025`。 
2. 初始化一个指针`j`到`0`。 该指针跟踪我们当前尝试匹配的日期的哪一位。 
3. 使用循环索引迭代绘制的数字`i`从`0`到`n-1`。 
4. 如果当前抽到的数字匹配`date[j]`, 增量`j`。 这意味着我们已成功匹配日期的下一个所需数字。 
5. 每次增量后，检查是否`j`等于日期的长度 (8)。 如果是，则返回`i+1`作为形成日期所需的位数，因为索引是从零开始的。 
6. 如果循环结束并且`j`小于8，输出`0`，表示日期不能形成。 

为什么它起作用：指针`j`始终指向下一个所需的数字`01032025`。 每次我们看到这个数字，我们就前进。 这保证了按正确的顺序选择数字。 跳过的数字并不重要。 第一次`j`达到 8 正是我们按顺序收集包含日期的最早前缀的时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    digits = list(map(int, input().split()))
    date = [0,1,0,3,2,0,2,5]
    j = 0
    for i in range(n):
        if digits[i] == date[j]:
            j += 1
            if j == 8:
                print(i + 1)
                break
    else:
        print(0)
```该解决方案读取多个测试用例并将输入数字转换为列表。 一个指针`j`迭代目标日期。 这`else`于`for`循环处理日期未完成的情况，这在幼稚的实现中很容易被忘记。 递增`i+1`打印时确保输出计算绘制的位数，而不是基于零的索引。
