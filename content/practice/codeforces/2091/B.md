 ## 解决方案
 ## 问题理解

 我们有一组学生，每个学生都有固定的技能值，我们必须将他们分成小组，以便每个学生都属于一个小组。 对于任何团队，其实力定义为团队中的学生人数乘以团队中的最小技能。 仅当计算出的强度至少达到给定阈值时，团队才被视为有效。 

任务不是最大化总实力或平衡球队，而只是在将每个人精确划分一次后最大化有多少支球队满足实力条件。 

关键的压力在于，将更多的学生分组会增加乘数，但会降低团队内部的最低技能。 分组结构完全决定了一支球队能否晋级。 

从限制条件来看，所有测试用例的学生总数最多为 200,000 人。 这立即排除了任何尝试考虑所有分区甚至所有子集的解决方案，因为这些分区呈指数增长。 即使每个测试用例的 O(n^2) 在最坏情况聚合中也是不安全的。 我们应该期待一种基于排序的线性或近线性贪婪方法。 

当一个学生拥有极高的技能但却被孤立时，就会出现一种微妙的边缘情况。 例如，如果 x 很大，并且除一个大值之外的所有技能都很小，则天真的贪婪者可能会错误地隔离优秀学生或过于激进地合并。 另一个失败的情况是，分组时没有考虑到添加一个弱学生可能会减少最低限度并破坏一个原本有效的团队。 

## 方法

 蛮力的想法是尝试一切可能的方法将学生分成小组，并检查有多少小组满足条件。 即使限制我们以不同的顺序贪婪地组建团队，仍然会导致分组选择的组合爆炸。 对于 n 个学生，分区的数量是指数级的，即使决定局部最优合并也是不够的，因为早期的决定会影响以后的可行性。 

关键的观察结果来自于重写团队的条件。 如果一个团队具有最低技能 m 和规模 k，则当 k·m ≥ x，或等效地 k ≥ ceil(x / m) 时，该团队是强团队。 这意味着一旦我们修复了团队中最弱的成员，我们就知道支持他们所需的最少人数。 

这建议按技能对学生进行分类，并尝试使用较强的学生来“分配支持”给较弱的学生。 一个有用的思考方法是将学生从最强到最弱进行处理，积累一个候选团队。 一旦积累的规模足以支持当前的最小规模，我们就可以立即确定团队。 由于我们是按降序处理的，因此当前学生始终是当前组中的最小值。 

这种贪心是有效的，因为每次我们决定组建一个团队时，首先使用最强的可用学生可以确保我们不会在早期较弱的分组上浪费潜在的力量。

 ## 算法演练

 1. 对技能数组进行降序排序。 这确保了当我们逐步建立团队时，最后添加的元素始终是当前细分中最弱的元素。 当我们决定关闭一个团队时，这使得评估实力变得容易。 
2. 维护计数器`cnt`代表目前组建团队中有多少学生。 我们还维护我们已经组建了多少个有效团队。 
3. 迭代排序的技能。 对于每个学生，增加`cnt`因为我们正在暂时将他们添加到当前的团队中。 
4. 每次添加后，检查是否`cnt * current_skill ≥ x`。 自从`current_skill`是当前组中最小的（因为排序），此条件检查当前组是否已经可以形成有效的团队。 
5. 如果条件成立，我们最终确定该团队：增加答案并重置`cnt`为零，从下一个学生开始一个新的团队。 

### 为什么它有效

 该算法保持当前组始终由最强的剩余学生按降序排列组成的不变量，因此最后添加的元素始终是该组中技能最低的元素。 每当我们决定组建团队时，我们都会在团队生效后尽早进行。 延迟只会包括未来团队中较弱的部分或减少可能的有效团队的数量。 因为我们总是在条件满足时就确定下来，所以我们不会错过任何一个潜在的组队，也不会因为将优秀的学生配对成不必要的大组而浪费他们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        cnt = 0
        ans = 0
        
        for v in a:
            cnt += 1
            if cnt * v >= x:
                ans += 1
                cnt = 0
        
        print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先按降序对技能进行排序，以便当我们按顺序构建一个组时，当前元素始终是该部分组中最弱的元素。 柜台`cnt`跟踪正在进行的组的大小。 每次扩展组时，我们都会检查其大小乘以最弱的元素是否满足阈值。 如果是这样，我们立即关闭该组并重置。 

一个常见的错误是试图维持多个部分形成的小组或试图贪婪地将学生分配到垃圾箱中而不进行排序。 降序可以保证每次检查正确地代表当前组的真实最小值。

 ## 边缘情况

 一种重要的边缘情况是所有值都相等但乘以全尺寸时略低于阈值。 例如：```
n = 5, x = 10, a = [2,2,2,2,2]
```排序后，我们累计计数：1 为 2，2 为 4，3 为 6，4 为 8，5 为 10，这样就形成了一个完整的团队。 该算法正确地延迟形成，直到该组足够大。 

另一种边缘情况是当单个大值占主导地位时：```
n = 3, x = 5, a = [10,1,1]
```我们立即用 10 人组成一个团队，因为在尺寸 1 时已经满足 1·10 ≥ 5。剩下的弱元素可能无法组成第二个团队，这也是正确的。 

第三种情况是贪婪的诱惑建议首先将弱元素配对。 排序可以防止这种错误，因为弱元素总是稍后出现，确保它们仅在必要时做出贡献，而不是过早消耗强元素。
