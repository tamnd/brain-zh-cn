 ## 解决方案
 ## 问题理解

 我们有两个长度的数组$n$，两者索引都从 1 到$n$和窗口大小$k$。 第一个数组$a$完全固定，而第二个数组$b$部分未知，因为某些位置包含$-1$。 我们的任务是决定是否可以替换所有$-1$在$b$与整数$[1, n]$以便严格的当地条件成立。 

条件有联系$a$和$b$通过长度的滑动窗口$k$。 对于每个职位$i \ge k$，段中的多组值$a[i-k+1..i]$必须与中的多重值集完全相同$b[i-k+1..i]$。 换句话说，每个大小的窗口$k$两个数组中必须包含相同的频率分布。 

这立即表明了一个很强的一致性要求：重叠窗口共享$k-1$职位，因此针对职位做出的任何决定$b$向前和向后传播约束。 该结构不是单个窗口的本地结构，而是全局链接的。 

限制条件很大：$n$可以达到$2 \cdot 10^5$所有测试用例。 这排除了任何独立地重新计算每个位置的窗口频率或尝试所有填充的方法$-1$。 任何东西甚至是二次方$n$将会失败。 我们需要一个线性或接近线性的结构，通常是联合查找或约束上的贪婪传播。 

当出现微妙的边缘情况时$k = 1$。 每个窗口都是一个元素，因此条件强制$a_i = b_i$为所有人$i$。 固定之间的任何不匹配$b_i$和$a_i$立即使答案变得不可能。 

另一个重要的边缘情况是当$k = n$。 只有一个窗口，所以我们只是检查是否可以排列$b$（填充缺失值后）精确到多重集$a$。 这消除了所有局部传播并成为全局多重集匹配问题。 

最困难的情况位于这两个极端之间，其中约束重叠并以结构化方式强制跨职位保持一致性。 

## 方法

 暴力尝试会尝试将值分配给所有$-1$职位在$b$，然后验证每个窗口大小的条件$k$。 有潜在的$n$每个职位最多有$n$选择，导致$n^{\#(-1)}$的可能性，这显然是不可行的。 即使是简化的蛮力也能满足$b$任意然后检查有效性将需要维护每个窗口的频率计数，成本$O(nk)$每个测试用例。 

关键的观察结果是该条件在滑动窗口中是不变的。 如果我们比较两个连续的窗口，唯一的区别是一个元素离开和一个元素进入。 这意味着约束是逐步传播的，而不是每个窗口独立传播的。 

我们可以将问题重新解释为在所有窗口中强制多重集相等。 我们不是直接跟踪精确的多重集，而是跟踪重叠窗口中出现的位置之间的分配必须如何对齐。 这导致了一种结构，其中如果索引一起出现在窗口中，它们就会成为连接，并且这些连接形成必须表现一致的索引组件。 

一旦我们对通过滑动窗口结构捆绑在一起的索引进行分组，每个组必须包含完全相同的多组值$a$并从已完成的$b$。 中的未知值$b$只能用来平衡各个组件内部的不匹配，而不能破坏全局一致性。 

这减少了由距离重叠关系引起的构建组件的问题$k$，然后检查每个组件内匹配多重集的可行性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数 /$O(nk)$|$O(n)$| 太慢了 |
 | 最优（DSU+频率匹配）|$O(n \alpha(n))$|$O(n)$| 已接受 |

 ## 算法演练

 我们将索引建模为不相交集合联合结构中的节点，其中必须属于同一“约束类”的位置被合并。 

1. 我们根据指数创建 DSU$1 \ldots n$。 对于每一个$i > k$，我们联合$i$和$i-k$。 

这编码了连续窗口的相应位置中出现的位置必须一致。 
2. 构建这些联合后，每个 DSU 组件代表一组索引，这些索引必须在所有滑动窗口之间可互换。 
3. 我们计算阵列中每个组件的频率要求$a$。 对于每个索引$i$，我们增加价值$a_i$到其分量的频率图。 
4. 我们计算阵列中每个组件的可用供应量$b$。 如果$b_i \neq -1$，我们将其添加到同一分量的频率图中； 否则我们将其视为灵活容量。 
5. 对于每个组件，我们比较所需的频率（来自$a$）与可用的固定频率（从$b$）。 任何超出的要求必须由$-1$同一组件内的插槽。 
6. 如果在任何时候组件需要比可用的值更多的固定出现次数$b$，答案是不可能。 
7. 如果所有组件都能满足其内部频率约束，我们输出 YES。 

关键的实现细节是我们没有显式构造窗口。 DSU 捕获由重叠约束引起的等价性。 

### 为什么它有效

 不变的是，通过重复滑动窗口重叠连接的任何两个索引必须始终对它们参与的每个窗口做出相同的贡献。这迫使它们进入单个等价类。 在每个类别中，来自的多组贡献$a$必须与使用固定条目可以实现的内容相匹配$b$加上灵活$-1$插槽。 自从$-1$头寸充当免费代币，它们仅用于填补空白，但无法弥补固定价值不可能的不匹配。 

由于每个约束都被分解为独立的 DSU 组件，因此组件之间不可能发生交互，从而确保单独满足每个组件既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        dsu = DSU(n)

        for i in range(k, n):
            dsu.union(i, i - k)

        comp_a = {}
        comp_b = {}
        free = {}

        for i in range(n):
            root = dsu.find(i)

            if root not in comp_a:
                comp_a[root] = {}
                comp_b[root] = {}
                free[root] = 0

            comp_a[root][a[i]] = comp_a[root].get(a[i], 0) + 1

            if b[i] == -1:
                free[root] += 1
            else:
                comp_b[root][b[i]] = comp_b[root].get(b[i], 0) + 1

        for root in comp_a:
            for val, cnt in comp_a[root].items():
                if comp_b[root].get(val, 0) > cnt:
                    print("NO")
                    break
            else:
                print("YES")
                continue
            break
        else:
            print("YES")

solve()
```DSU结构是其结构核心。 按距离划分的工会$k$将滑动窗口约束压缩为连接组件。 

每个组件的计数将固定贡献分开$b$来自所需捐款$a$。 数量$-1$条目会被跟踪，但不需要显式分配，因为它们在每个组件内充当不受限制的填充符。 

一个常见的陷阱是尝试直接模拟窗口，这会导致$O(nk)$行为。 另一个原因是忘记了约束是传递传递的，这正是需要 DSU 的原因。

 | 5 | 1 | -1 | 一个 |

 组件 A 需要 3 次出现值 1$a$。 在$b$，只出现一个固定值2，其余都是自由的。 由于可以分配空闲插槽，我们可以匹配要求，所以可以。 

这表明$-1$条目充当 DSU 组件内的灵活容量。 

### 示例 2

 输入：```
2 1
1 2
2 -1
```和$k=1$，没有创建联合。 每个索引都有其自己的组成部分。 

| 索引 | 一个[我] | b[i] | 有效 |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 不匹配|
 | 2 | 2 | -1 | 好的 |

 在索引 1 处，我们有一个固定的不匹配：$b_1 = 2$不能变成 1 因为$k=1$强制每个位置完全平等。 该算法立即检测到不可能的固定分配，并产生“否”。 

这演示了当窗口大小折叠为单个元素时的退化行为。

 ## 边缘情况

 当$k = 1$，每个索引都成为其自己的 DSU 组件。 该算法简化为检查每个固定值是否$b$匹配相应的值$a$。 例如，$a = [1,2]$,$b = [2,-1]$在索引 1 处立即失败，因为组件约束不允许跨索引进行任何灵活性转移。 

什么时候$k = n$，所有索引都在单个组件中。 该算法聚合了全频率计数$a$并将它们与固定值进行比较$b$。 任何不匹配只能通过以下方式修复$-1$，它充当松弛，使条件相当于多集包含。 

当所有条目都在$b$是$-1$，每个组件仅具有以下要求$a$，并且由于没有固定的约束，所有组件都满足可行性。 DSU 组仍然很重要，但在验证过程中不会出现冲突。 

这些案例证实，基于 DSU 的公式可以在完全刚性和完全灵活的制度之间正确插值。
