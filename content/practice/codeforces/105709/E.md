 ## 解决方案
 ## 问题理解

 我们得到了一群雀类，每只雀最初都生活在自己独立的庇护所中。 每只雀都有一串固定的特征，其中每个特征位置都是一个小字母表中的字符`'a'`到`'j'`。 随着时间的推移，达尔文根据这些特征执行合并保护区的操作，我们必须不断跟踪每个最终保护区的大小以及最大保护区的总体大小。 

该过程由三种操作驱动。 一次操作会激活一个特定的特征位置，从那一刻起，任何两个庇护所包含至少一只在该位置共享相同特征的雀类，都被视为连接并有效合并。 这不是一次性合并；而是一次合并。 这是一个持续存在并与早期激活相互作用的全局规则。 另一项操作要求提供包含特定雀类的保护区的大小。 最终操作要求目前形成的最大庇护所的大小。 

这些限制在某种程度上表明我们无法在每次激活后从头开始重建连接。 最多有 100000 只雀、100000 个特征和 100000 个查询，而特征字符串的总输入大小约为 100 万个字符。 任何针对每个查询重复重新计算所有雀类连接性的解决方案都会太慢，因为即使每个查询的线性扫描也已经接近 10^10 次操作。 

重复激活同一特征指数会产生一个微妙的问题。 如果一个简单的方法独立地处理每个激活并只为该激活重新计算并集，它可能会意外地错过这样一个事实：早期合并已经改变了组件结构，因此未来的激活必须对已经合并的组而不是原始的雀进行操作。 

另一个边缘情况来自特征位置内的重复字符。 如果许多雀类在一个位置共享相同的字符，那么它们都必须最终形成一个连接组件，而不仅仅是取决于处理顺序的成对合并。 没有适当分组的天真的成对合并可能会导致部分连接或二次爆炸。 

作为具体的故障场景，假设所有雀类都具有相同的特征`'a'`在位置 1，我们激活该位置。 将每对联合起来的幼稚方法将执行大约 n^2 操作，这已经太慢了。 正确的行为是它们全部立即成为一个连接的组件。 

## 方法

 暴力策略将直接模拟合并过程。 我们在每个保护区都保留了明确的雀类群。 当特征位置被激活时，我们扫描所有雀类，并将那些在该位置具有相同特征的雀类分组在一起，合并它们的集合。 查询类型二将计算包含雀的集合的大小，类型三将跟踪最大集合大小。 

这种方法的正确性很简单，因为它确实遵循规则：每次激活都会根据特征强制执行新的等价关系，并且集合会相应地合并。 问题在于它的成本。 每次激活可能需要扫描所有雀类并可能执行许多合并。 当 n 和 q 达到 10^5 时，这会在最坏的情况下导致大约 O(nq) 的行为，这远远超出了可行的范围。 

关键的观察结果是，该过程的结构从根本上来说是一个类似于二分结构的动态连接问题：雀类仅通过激活位置上的共享特征值进行连接。 每只雀最初都是孤立的，边缘逐渐显露出来。 一旦激活边缘类型（特征索引），该索引处的所有等字符组就会立即完全连接。 

这表明我们不应该将雀直接视为融合的主要对象。 相反，我们通过提前按每个特征位置的字符对雀进行一次分组，然后在查询时激活整个组，将每次激活的效果压缩为少量联合操作。 不相交集并集 (DSU) 结构成为自然的工具，因为我们只合并组件而从不拆分它们。 

我们对每个特征索引和每个字符预处理在该位置具有该字符的雀类列表。 然后，当激活某个特征时，我们会将该特征的每个字符桶内的所有雀联合起来。 每个 finch 最多参与 k 个桶，每个桶仅处理一次，因此所有激活中的总联合工作在 nk 中呈线性。

 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(nk) | O(nk) | 太慢了|
 | 最优（DSU + 分组）| O(nk + q α(n)) | O(nk + q α(n)) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

 我们将每只雀表示为不相交集合联合结构中的一个节点。 每个节点都从其自己的大小为 1 的组件开始。 我们还维护一个全局变量来跟踪最大组件大小。 

我们预先计算一个结构，将每个特征索引和字符映射到在该位置具有确切值的雀类列表。 这会将输入字符串转换为代表所有潜在的未来合并操作的存储桶的集合。 

然后我们按顺序处理查询，但我们确保每个特征索引最多被激活一次。 布尔数组跟踪特征是否已被应用，因为重复它没有额外的效果。 

该算法进行如下。 

1. 在 n 个节点上构建 DSU，将父指针初始化为自身，并将大小初始化为 1。最大组件大小从 1 开始。这建立了 DSU 中存储的每个组件大小都是精确的不变量。 
2. 预先计算存储桶，以便对于每个特征位置 j 和每个字符 c，我们存储所有索引 i，其中 finch i 在位置 j 处具有字符 c。 此步骤将未来的激活转换为一组批处理联合。 
3. 维护一个数组activated[j]，用于跟踪特征j是否已被处理。 这可以防止重复工作并确保每个组只合并一次。 
4. 对于具有特征 j 的类型 1 的查询，如果未激活，则迭代来自`'a'`到`'j'`。 对于位置 j 处的每个字符桶，重复将该桶中的所有雀鸟与桶中的第一个雀鸟合并。 这形成了每个（j，字符）的单个连接组件。 处理完毕后，将j标记为已激活。 
5. 对于类型2的查询，输出包含所查询的finch的DSU组件的大小。 
6. 对于类型3的查询，输出全局最大组件大小。 

关键的实现细节是，在处理存储桶时，我们不会合并所有对。 相反，我们选择一个代表并将所有其他元素合并到其中，确保每个桶的线性工作。 

### 为什么它有效

 每个激活都会引入“在位置 j 共享相同字符的雀属于一组”形式的等价关系。 这些关系在每个字符类中都是传递的，因此每个桶在归纳图中形成一个完整的派系。 DSU 在增量边缘插入下正确维护连接的组件。 由于每个桶只被处理一次，所以每个所需的边都被添加一次，并且不会发生丢失连接的情况，因为必须连接的任何两个雀鸟共享至少一个激活的（j，字符）对并在该桶内合并。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.max_size = 1

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        if self.size[a] > self.max_size:
            self.max_size = self.size[a]

n, k, q = map(int, input().split())
traits = [input().strip() for _ in range(n)]

buckets = [[[] for _ in range(10)] for _ in range(k)]
for i in range(n):
    for j, ch in enumerate(traits[i]):
        buckets[j][ord(ch) - 97].append(i)

dsu = DSU(n)
used = [False] * k

for _ in range(q):
    tmp = input().split()
    t = int(tmp[0])

    if t == 1:
        j = int(tmp[1]) - 1
        if used[j]:
            continue
        used[j] = True

        for c in range(10):
            lst = buckets[j][c]
            if not lst:
                continue
            root = lst[0]
            for v in lst[1:]:
                dsu.union(root, v)

    elif t == 2:
        i = int(tmp[1]) - 1
        print(dsu.size[dsu.find(i)])

    else:
        print(dsu.max_size)
```DSU 实现使用路径压缩和按大小联合，以便跨大存储桶的重复合并保持高效。 Buckets 数组压缩特征信息，以便每个联合操作每个（位置，字符）仅生成一次。 使用的数组确保我们永远不会重新处理特征索引，这是至关重要的，因为重新应用它会不必要地重复联合。 

一个微妙的点是，联合总是相对于桶的固定代表来执行。 这避免了如果我们重复合并任意 p 时会出现的二次行为
