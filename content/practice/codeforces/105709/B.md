 ## 解决方案
 ## 问题理解

 该任务是关于维护有根树并回答节点对之间的关系查询。 对于树中的任何两个给定节点，我们需要确定它们的最低公共祖先，这意味着有根结构中位于从根到它们的路径上的最深节点。 

输入可以解释为由边描述的树，后跟多个查询。 每个查询给出两个节点，我们必须返回表示它们通往根的路径首先汇聚的单个节点。 

即使没有明确的约束，此类问题几乎总是涉及多达数十万个节点和查询。 这立即排除了通过一次向上走一步来重新计算每个查询的路径的任何方法，因为在最坏的情况下这会退化为二次行为。 解决方案必须对树进行预处理，以便可以在对数或接近恒定的时间内回答每个查询。 

一些边缘情况往往会破坏简单的实现。 如果树是一条链，例如 1 连接到 2，连接到 3，连接到 4，则端点的最低公共祖先始终是链中较高的端点。 一个简单的向上行走解决方案可能会在每次查询时重复爬一步，从而产生与树的深度成正比的最坏情况成本。 

当一个节点是另一个节点的祖先时，会发生另一种微妙的情况。 例如，如果节点 2 是节点 5 的父节点，则查询 (2, 5) 的答案必须为 2。任何试图错误地均衡深度或超过祖先的方法，如果在相等时刻不小心停止，都可以轻松跳过正确的节点。 

## 方法

 回答两个节点查询的最直接方法是重建它们到根的路径并进行比较。 我们可以存储每个节点的父节点，并且对于每个查询，重复向上移动每个节点直到到达根，记录访问过的节点。 最低共同祖先就是这两条路径中的最后一个共享节点。 

这是正确的，因为每个节点都有一个父节点，因此到根的每条路径都是唯一定义的。 然而，为每个查询构建这些路径的成本很高。 如果树的高度与 n 成正比并且有 q 个查询，则此方法可能需要每个查询进行 O(n) 工作，从而导致总操作量为 O(nq)，当 n 和 q 都很大时，这太慢了。 

关键的观察结果是，跨查询重复向上移动是多余的。 树的结构不会改变，因此可以预先计算祖先关系。 我们可以为每个节点预先计算大小为 2 的幂的跳跃，而不是一次步进一个父节点。 这使我们能够将任何节点向上提升一大步，从而在对数时间内有效地跳过中间祖先。 

这种技术称为二元提升。 我们存储一个表，其中 up[k][v] 表示节点 v 的第 2^k 个祖先。通过这种结构，我们可以首先将两个节点对齐到相同的深度，然后从两个可能的最高幂向下将它们一起提升，直到它们相遇。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（路径行走）| 每个查询 O(n) | O(n) | 太慢了|
 | 二元提升| O((n + q) log n) | O((n + q) log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

1. 以节点 1 为树的根，并运行深度优先搜索或广度优先搜索来计算每个节点的父节点和深度。 这建立了一个参考系，因此每个节点都知道它距根有多远。 
2. 构建一个二进制提升表，其中 up[0][v] 是 v 的直接父级，up[k][v] 定义为 up[k-1][up[k-1][v]]。 这对距离呈指数增加的祖先进行编码。 
3. 预先计算 log2(n) 之前所有 k 的表。 这确保我们可以以对数步数跳跃任意距离。 
4.对于每个查询(u,v)，首先比较它们的深度。 如果一个节点较深，则使用二元升降台将其向上提升，直到两个节点处于相同深度。 这避免了必须一步一步移动。 
5. 两个节点深度对齐后，检查它们是否已经相同。 如果是，则该节点是最低共同祖先。 
6. 如果它们不同，请尝试将两个节点从两个的最高幂向上提升到零。 每当给定级别的祖先不同时，将两个节点同时向上移动。 这使它们在 LCA 以下保持同步。 
7. 完成所有跳转后，两个节点都将是最低公共祖先的直接子节点，因此返回任一父节点都会给出答案。 

### 为什么它有效

 正确性来自祖先表的结构。 算法中的每次向上移动都保留了真实 LCA 仍然位于两个节点之上的不变量。 当我们将节点提升到相同的深度时，我们不会改变它们的相对祖先，只是调整它们与根的距离。 然后，当我们尝试从 2 的高次方向下进行大跳跃时，只有在不超过 LCA 的情况下，我们才会进行跳跃。 这保证了我们永远不会绕过正确的祖先，并且最终两个节点都会收敛到仍然严格低于 LCA 的最高节点，因此它们的父节点必须是 LCA 本身。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    LOG = (n).bit_length()

    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    stack = [(1, 0)]
    parent = [0] * (n + 1)
    parent[1] = 1

    while stack:
        node, p = stack.pop()
        parent[node] = p
        for nei in adj[node]:
            if nei == p:
                continue
            depth[nei] = depth[node] + 1
            stack.append((nei, node))

    for v in range(1, n + 1):
        up[0][v] = parent[v]

    for k in range(1, LOG):
        for v in range(1, n + 1):
            up[k][v] = up[k - 1][up[k - 1][v]]

    def lift(x, dist):
        k = 0
        while dist:
            if dist & 1:
                x = up[k][x]
            dist >>= 1
            k += 1
        return x

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        a = lift(a, depth[a] - depth[b])

        if a == b:
            return a

        for k in range(LOG - 1, -1, -1):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]

        return up[0][a]

    q = int(input())
    out = []
    for _ in range(q):
        u, v = map(int, input().split())
        out.append(str(lca(u, v)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现首先构建树的邻接列表表示。 父数组和深度数组是通过以节点 1 为根的基于堆栈的遍历来计算的，确保每个节点都知道其直接祖先以及距根的距离。 

然后，二进制升降台被自下而上地填充。 关键细节是 up[k][v] 取决于 up[k-1][v]，因此必须先计算较小的跳转，然后再计算较大的跳转。 

提升函数执行深度均衡步骤。 它解释二进制距离并应用与设置位相对应的跳转。 这比一次重复移动一层更有效。 

lca 函数首先对深度进行归一化，然后对 2 的幂执行自上而下的检查。 条件 up[k][a] != up[k][b] 确保我们仅在祖先仍安全地低于 LCA 时才移动。 

## 工作示例

 考虑一棵根部为 1 的小树：

 输入边沿：

 1-2、1-3、2-4、2-5

 查询：(4, 5)

 两个节点的深度均为 2。算法跳过提升步骤。 在最高跳跃级别，两个节点在提升决策后在节点 2 处共享相同的祖先，因此结果为 2。 

| 步骤| 一个 | 乙| 行动|
 | --- | --- | --- | --- |
 | 开始 | 4 | 5 | 相同深度|
 | 检查 k=2 | 2 | 2 | 两人的祖先都不同 |
 | 决赛| 2 | 2 | 返回父级 |

 这证实了对兄弟姐妹的正确处理。 

现在考虑查询 (3, 4)。 

节点 3 的深度为 1，节点 4 的深度为 2，因此 4 被提升到 2 的水平，成为 2。现在比较 (3, 2)，它们是不同的，并且最高有效提升表明它们的父级收敛于 1。 

| 步骤| 一个 | 乙| 行动|
 | --- | --- | --- | --- |
 | 开始 | 3 | 4 | 深度不同 |
 | 电梯| 3 | 2 | 均衡深度|
 | 检查| 3 | 2 | 向上移动|
 | 决赛| 1 | 1 | 返回 1 |

 这演示了对不同深度的节点的正确处理。

 ## 边缘情况

 诸如 1-2-3-4 之类的链形树测试提升逻辑是否正确处理最大深度差异。 对于查询 (4, 1)，算法通过二进制跳转将节点 4 向上提升：4 跳转到 2，然后跳转到 1，而节点 1 保持不变。 最终的比较正确地收敛于 1，因为 1 的所有祖先本身都在有根表示中。 

一个节点是另一个节点的祖先的情况（例如树中的查询 (2, 5)，其中 2 直接在 5 之上）验证均衡深度不会超调。 提升后，节点 5 变为 2，并且由于节点立即匹配，因此算法返回 2，而无需进行不必要的向上移动。
