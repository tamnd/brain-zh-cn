 ## 解决方案
 ## 问题理解

 斯克鲁奇通过沿着折线移动笔来签署文件。 签名从第一个点开始，然后在连续点之间绘制直线段，直到到达最后一个点。 他的笔速固定为每秒 50 毫米，并重复完全相同的签名`k`次。 

任务是计算签署所有文件所花费的总时间。 

输入按顺序给出折线的点。 每对连续点形成签名的一段。 笔行进的总距离是所有这些线段的欧几里得长度之和。 一旦我们知道一个签名的总距离，我们就将其乘以`k`并除以写入速度。 

限制很小。 最多有 100 个点，因此最多有 99 个段。 即使是昂贵的计算也可以轻松地满足该限制。 对这些段进行简单的线性扫描就足够了。 几何问题有时需要仔细的优化或精确的技巧，但这里的数字很小并且公式很直接。 

主要的实施风险是精确处理。 由于平方根，点之间的距离通常不是整数。 使用整数运算会默默地截断值并产生错误的答案。 

考虑这个输入：```
2 1
0 0
1 1
```段长度为`sqrt(2) ≈ 1.41421356`。 正确的时间是：```
1.41421356 / 50 ≈ 0.028284271
```如果解决方案不小心使用整数除法或在除法之前将距离转换为整数，它将打印`0`，这是不正确的。 

另一个容易犯的错误是忘记乘以`k`。 

例如：```
2 5
0 0
10 0
```一个签名有长度`10`，所以一个签名需要`10 / 50 = 0.2`秒。 由于共有 5 篇论文，因此正确答案是：```
1.0
```只计算一个签名的粗心实现会输出`0.2`。 

第三种微妙的情况是负坐标。 距离取决于坐标差，而不是绝对位置。 

例子：```
2 1
-3 -4
0 0
```距离依然`5`， 因为：```
sqrt((0 - (-3))^2 + (0 - (-4))^2) = sqrt(9 + 16) = 5
```直接使用绝对坐标值而不是差异会打破这种情况。 

## 方法

 暴力破解的想法在这里已经足够快了。 我们可以独立处理每个线段，使用距离公式计算其欧几里德长度，并将所有长度加在一起。 

连续两点`(x1, y1)`和`(x2, y2)`，段长度为：$d=\sqrt{(x_2-x_1)^2+(y_2-y_1)^2}$拖动点以更新两点之间的距离。-10-8-6-4-2246810-10-5510A(6.0, 6.0)B(-6.0, -6.0)d = 16.97Delta x = 12Delta y = 12

 将所有线段长度相加后，我们乘以`k`因为相同的签名重复了`k`次。 最后，我们除以写入速度`50`。 

暴力方法之所以有效，是因为签名路径是作为连续段明确给出的。 没有隐藏结构需要重构，也不需要优化重复计算。 每一段都独立地对总距离做出贡献。 

有时，几何问题会诱使人们过度思考交叉点或重叠路径。 这些在这里都不重要。 即使多段线与自身交叉或折回较早的线段，斯克鲁奇仍然沿着整个路径物理移动笔，因此每个线段都必须按照绘制的方式精确计数。 

最佳方法与蛮力方法相同，因为约束非常小，以至于单次线性传递已经是最佳的。 我们只需遍历折线一次即可。

 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`k`。 
2. 阅读全部`n`折线的点按顺序排列。 
3. 初始化变量`total_distance = 0.0`。 
4. 迭代连续的点对。 

对于每一个`i`从`0`到`n - 2`，取点：```
(x[i], y[i]) and (x[i+1], y[i+1])
```5. 计算两点之间的欧氏距离。 

距离公式测量连接它们的直线段的精确长度。 
6.将此段长度添加到`total_distance`。 

处理完所有对后，`total_distance`等于一个签名的完整钢笔移动。 
7. 乘法`total_distance`经过`k`。 

每次签名都是相同的，因此总行驶距离与纸张数量成线性比例。 
8. 将结果除以`50`。 

笔速为每秒 50 毫米，因此：```
time = distance / speed
```9. 将答案打印为浮点数。 

### 为什么它有效

 每个签名都由连续点之间的片段组成。 该算法对每个片段进行一次处理，并使用欧几里德距离公式计算其精确的几何长度。 

循环期间的不变性是在处理完第一个`i`段，`total_distance`等于沿着这些线段的笔总移动量。 由于每个段都是独立贡献的，并且没有段被跳过或重复计算，因此最终的总和恰好是一个完整签名的长度。 

乘以`k`给出所有签名的总距离，除以恒定速度将距离转换为时间。 由于计算直接匹配问题中描述的物理过程，因此该算法是正确的。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

# solution

def solve():
    n, k = map(int, input().split())

    points = [tuple(map(int, input().split())) for _ in range(n)]

    total_distance = 0.0

    for i in range(n - 1):
        x1, y1 = points[i]
        x2, y2 = points[i + 1]

        dx = x2 - x1
        dy = y2 - y1

        total_distance += math.hypot(dx, dy)

    total_time = (total_distance * k) / 50.0

    print(f"{total_time:.9f}")

solve()
```解决方案直接遵循算法。 首先，它将所有点读入列表中，以便可以轻松访问连续的点。 

在循环内部，`dx`和`dy`存储相邻点之间的坐标差。 功能`math.hypot(dx, dy)`计算：```
sqrt(dx^2 + dy^2)
```这比手动编写平方根公式更安全、更简洁。 

累加器`total_distance`是一个浮点值，因为段长度通常不是整数。 

乘以`k`在计算整个签名长度之后发生。 这避免了不必要地重复相同的计算。 

最终的打印结果使用了小数点后9位数字，完全满足了精度要求。

 ## 边缘情况

 考虑段长度不合理的情况。 

输入：```
2 1
0 0
1 1
```该算法计算：```
dx = 1
dy = 1
distance = sqrt(2)
```然后：```
time = sqrt(2) / 50
```因为该实现使用浮点运算并且`math.hypot`，整数截断不会损失精度。 

现在考虑重复签名。 

输入：```
2 5
0 0
10 0
```该循环计算单个签名距离`10`。 循环后：```
total_distance = 10
```然后：```
total_time = (10 * 5) / 50 = 1
```乘法发生在计算完整路径长度之后，因此每个签名都被正确计数。 

最后，考虑负坐标。 

输入：```
2 1
-3 -4
0 0
```该算法计算：```
dx = 3
dy = 4
distance = 5
```只有坐标差异很重要，因此折线在平面中的位置不会影响正确性。 最终的答案是：```
5 / 50 = 0.1
```
