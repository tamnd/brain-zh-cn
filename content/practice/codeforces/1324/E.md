 ## 解决方案

 ## 问题理解

 我们正在跟踪一个在一系列决策中逐步演变的过程。 有`n`睡眠事件。 开始时，时间是`0`，并且在每个事件之后我们将当前时间提前`a_i`或者`a_i - 1`。 这会创建一个累积时间链，其中每一步都会稍微调整我们前进的距离。 

每一步之后，我们检查当前时间是否对日长取模`h`进入“好”区间`[l, r]`。 既然时间包裹着每一个`h`小时，仅值`time % h`决定睡眠是否良好的重要因素。 

目标是在每一步独立选择是否减 1，以便其结果模位置位于的步数`[l, r]`被最大化。 

限制因素`n ≤ 2000`和`h ≤ 2000`立即建议任何解决方案都必须大致是二次的或更好的。 状态和转换的三次解仍然很好，但是任何涉及枚举所有的东西`2^n`选择是不可能的，因为这是指数级的。 同样，存储所有全时间值是不必要的，因为只有余数模`h`很重要。 

一个微妙的边缘情况是由于每一步减 1 是可选的这一事实而产生的。 总是试图降落在内部的贪婪方法`[l, r]`目前的步骤失败了，因为它可能会将残留物转移到更糟糕的方向，从而破坏未来的机会。 另一个微妙的情况是当`l = 0`和`r = h - 1`，其中每个状态都很好，并且答案很简单`n`，这对于验证正确性很有用。 

第二个边缘情况是当间隔为空或非常小时，例如`l = r`。 然后 DP 必须小心地传播可达性，因为即使错过了精确的残差，也会破坏潜在的最佳路径。 

## 方法

 暴力解决方案会尝试每一个决策序列，选择`a_i`或者`a_i - 1`对于每一步。 这导致`2^n`对于每种可能性，我们都会模拟运行总和并计算模数落在良好区间内的次数。 即使与`n = 2000`，这是完全不可行的，因为状态空间呈指数爆炸。 

关键的观察是，尽管绝对时间增长，但重要的是模数余数`h`。 这将状态空间压缩到最多`h`可能的值。 在每一步中，从给定的余数`t`，我们可以过渡到两个可能的下一个余数：`(t + a_i) % h`或者`(t + a_i - 1) % h`。 

这自然会导致对步骤和余数的动态规划。 我们不是记住所有路径，而是只存储处理完步骤前缀后每个余数的最佳可实现结果。 如果新的余数位于，则每次转换都会添加“良好”奖励`[l, r]`或不。 

这将问题从指数分支减少到分层图最短路径样式 DP`n * h`州。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳DP | O(n·h) | O(n·h) | O(h) | 已接受 |

 ## 算法演练

 我们定义`dp[t]`作为处理当前事件前缀后可实现的良好睡眠的最大数量，以时间剩余结束`t`。 

1. 将所有状态初始化为不可达状态，除了`dp[0] = 0`，因为我们从时间 0 开始，良好的睡眠时间为零。 
2. 对于每个事件`i`从 1 到`n`，我们创建一个新的DP数组`ndp`填充非常负的值来表示无法到达的状态。 
3. 对于每个余数`t`在`[0, h-1]`可以到达`dp`，我们考虑两种选择：

 第一个是搬到`(t + a_i) % h`，第二个是`(t + a_i - 1) % h`。 这捕获了两个允许的睡眠时间。 
4. 对于每个所得的余数`nt`，我们通过检查是否来计算现在是否是好时机`l ≤ nt ≤ r`。 如果是，我们将分数加 1； 否则，我们添加 0。 
5.我们更新`ndp[nt]`所有转变可实现的最大价值`nt`。 
6. 处理完当前所有状态后`i`，我们替换`dp`和`ndp`。 
7. 处理完所有事件后，答案是所有最终余数中的最大值`dp`。 

关键思想是我们在每一步中独立地传播每个残基类别的最佳可能结果。 

### 为什么它有效

 每一步`i`,`dp[t]`代表以余数结束的所有选择序列中可实现的最佳睡眠次数`t`。 每个可能的决策序列都对应于通过这些状态的一条路径，并且每个转换都保留了正确性，因为它考虑了增量的两种有效选择。 由于我们总是在所有到达某个状态的方法上取最大值，因此不会丢弃任何最佳路径。 因此，DP 隐含地探索了完整的决策树，同时通过模等价压缩状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, h, l, r = map(int, input().split())
    a = list(map(int, input().split()))

    NEG = -10**9
    dp = [NEG] * h
    dp[0] = 0

    for x in a:
        ndp = [NEG] * h

        for t in range(h):
            if dp[t] == NEG:
                continue

            for add in (x, x - 1):
                nt = (t + add) % h
                val = dp[t] + (1 if l <= nt <= r else 0)
                if val > ndp[nt]:
                    ndp[nt] = val

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```实现直接遵循DP定义。 这`NEG`哨兵确保无法到达的状态不会传播。 嵌套循环结束`h`状态和每个状态的两个转换给出了预期的`O(nh)`复杂。 

一个常见的错误是忘记在每次转换后取模。 还有一个正在更新`dp`到位，这会混合不同步骤的状态并破坏正确性。 使用单独的`ndp`array prevents this contamination.

 ## 工作示例

 ### 示例 1

 输入：```
n=3, h=5, l=1, r=3
a = [2, 2, 2]
```我们跟踪 DP 与残留物的关系。 

| 步骤| dp 状态（非-inf）| 过渡选择| 下一个状态 |
 | ---| ---| ---| ---|
 | 0 | dp[0]=0 | dp[0]=0 开始 | - |
 | 1 | dp[0]=0 | dp[0]=0 +2 → 2，+1 → 1 | dp[2]=1, dp[1]=1 |
 | 2 | dp[1]=1, dp[2]=1 | 展开 | dp 更新了所有可达的 |
 | 3 | 所有州均已更新 | 决赛| 最佳 = 最大 dp |

 该表显示了每个状态如何分支成两个新的残基，良好的状态会增加分数。 这证实了 DP 正确地累积了独立于路径结构的贡献。 

### 示例 2

 输入：```
n=2, h=4, l=2, r=3
a = [3, 2]
```| 步骤| DP | 选择| 结果|
 | ---| ---| ---| ---|
 | 0 | dp[0]=0 | dp[0]=0 开始 | - |
 | 1 | dp[0]=0 | dp[0]=0 +3→3，+2→2 | dp[3]=1, dp[2]=1 |
 | 2 | dp[2], dp[3] | dp[2], dp[3] | 展开 | 计算所有转换 |

 最终答案是第 2 步之后的最佳 dp 值，显示不同的早期选择如何影响未来的可达残基。 

这些例子说明局部决策改变了可达残基，但DP同时保留了所有可能性。

 ## 边缘情况

 每小时都好的情况，比如`l = 0, r = h - 1`，导致每个转换加 1。DP 仍然有效，但它实际上变成了步数计数。 例如：

 输入：```
n=3, h=5, l=0, r=4, a=[1,2,3]
```每一步，每`nt`满足条件，因此每次转换都会增加分数。 DP正确产生`3`无论路径如何。 

紧密间隔的情况，例如`l = r = 0`迫使 DP 追踪准确的残留物。 例如：

 输入：```
n=2, h=4, l=0, r=0, a=[1,1]
```只有恰好落在残基 0 处的路径才会起作用。 DP 在每一步正确保留多个候选残基，并且仅在满足约束时才进行计数。 

具有许多不可达状态的案例说明了为什么`NEG`哨兵是必要的。 如果没有它，无效的转换将错误地传播并夸大结果。
