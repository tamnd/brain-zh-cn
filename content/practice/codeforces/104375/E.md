 ## 解决方案
 ## 问题理解

 我们被赋予了一个公司层次结构，形成了有根树。 每个员工对应一个节点，每个节点都有一个子树，由他们直接或间接监管的所有员工组成，包括他们自己。 

公司处理一系列奖励事件。 每个事件都针对特定的员工，并且奖金在概念上分配给该员工的整个子树。 该数量在该子树中的所有节点之间平均分配。 除法的任何余数都由该子树的根保留，但该余数对于任何其他员工来说并不重要。 

每个员工也有一个个人阈值。 每次奖金活动结束后，一些员工可能会达到或超过其阈值，具体取决于该活动中的每人份额是否适用于他们。 我们必须为每个员工确定最早的奖金事件索引，使他们的累计收到金额至少达到其阈值。 

关键的困难在于每次更新都会影响一个子树，而我们需要回答最多 100,000 个节点和 100,000 个更新的最早阈值查询。 

这些约束意味着任何重新计算每个查询的子树贡献的解决方案都太慢。 每个查询的简单遍历将花费 O(NQ)，这在最坏的情况下是 10^10 次操作，并且立即不可行。 除非我们利用跨查询的结构，否则即使独立地重新计算每个节点的前缀贡献也无济于事。 

随着时间的推移，重复贡献的积累会产生一个微妙的问题。 例如，如果所有奖励都针对根，则每个节点每次都会受到影响，并且天真的每个节点模拟将重复遍历整个树。 

另一个边缘情况是，员工的门槛非常高，只有在多次小额贡献后才能达到。 如果我们贪婪地处理每个查询，我们可能会错过累积在多次更新中缓慢发生的情况，而不是在单个事件中发生的情况。 

最后，根处的余数与其他节点无关，因此任何错误地向下传播它们的解决方案都将产生错误的累积值。 

## 方法

 直接模拟会独立对待每项奖金。 对于赋予值为 b 的节点 x 的奖励，我们计算 x 的子树的大小，然后将 b / size[x] 分配给该子树中的每个节点。 每个查询已经是 O(子树大小)，并且在最坏的情况下，更新链仍然可以触及每个查询的 O(N) 个节点。 当 Q 达到 10^5 时，这会变得太慢。 

核心观察是每个奖励将统一的值分配给整个子树。 因此，每次更新都是对子树的欧拉游览段的范围添加操作。 如果我们通过 DFS 为节点分配进入和退出时间，则每个子树都会成为一个连续的段。 每个奖励都成为该段上值 b / size[x] 的范围加法。 

现在问题变成：我们最多有 10^5 个范围添加，我们想知道对于每个节点，其前缀和达到阈值的最早时间。 

这是一个经典的线下“首次穿越时间”问题。 我们不是独立地模拟每个节点的时间前进，而是随着时间的推移执行分而治之。 对于查询序列中的候选中点，我们应用直到该中点的所有更新，并检查哪些节点已达到其阈值。 已经满足条件的节点可以移动到左半部分； 其他人去右半边。 这种随时间推移的二分搜索与支持范围更新和点查询的数据结构相结合，提供了一种有效的解决方案。 

欧拉游览阵列上的 Fenwick 树或线段树可以维护所有应用的奖金的前缀贡献。 每次检查只是查询节点的累计值。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NQ) | O(N) | 太慢了 |
 | 并行二分查找 + BIT | O((N+Q) log Q log N) | O(N) | 已接受 |

 ## 算法演练

 1. 将树转换为欧拉环，使得每个子树对应一个连续的区间。 这允许子树更新转换为数组上的范围更新。 
2. 在 DFS 期间计算子树大小。 这是必需的，因为每个奖金将 b / size[x] 分配给 x 子树中的每个节点。 
3. 将每个奖励事件表示为欧拉数组上的范围更新：将值 b / size[x] 添加到 x 的子树区间中的所有索引。 
4. 对于每个节点，在表示其可能达到其阈值的最早奖励的查询索引上维护一个搜索间隔。 
5. 对查询索引范围重复执行分而治之。 在每个步骤中，选择一个中点并应用直到该中点的所有更新。 
6. 使用 Fenwick 树，计算该中点处每个节点的累积值。 
7. 将节点分为两组：累计值达到阈值的节点向左，其余的向右。 
8. 继续，直到每个节点的间隔崩溃为单个答案索引或变得无效。 

它之所以有效，是因为随着时间的推移，累积值的单调性。 一旦节点在某些更新前缀处达到其阈值，它将对所有后续前缀保持满意，因为所有更新都是附加的且非负的。 这种单调结构保证了随着时间的推移二分搜索会产生正确的最早索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0.0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0.0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_add(self, l, r, v):
        self.add(l, v)
        self.add(r + 1, -v)

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
a = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
tin = [0] * n
tout = [0] * n
sub = [0] * n
order = []
t = 0

stack = [(0, 0, 0)]
# iterative DFS for tin/tout and subtree sizes
while stack:
    u, p, state = stack.pop()
    if state == 0:
        parent[u] = p
        tin[u] = t
        t += 1
        order.append(u)
        stack.append((u, p, 1))
        for v in g[u]:
            if v == p:
                continue
            stack.append((v, u, 0))
    else:
        sub[u] = 1
        for v in g[u]:
            if v != p:
                sub[u] += sub[v]
        tout[u] = t - 1

def apply(fw, u, val):
    fw.range_add(tin[u] + 1, tin[u] + sub[u], val)

ops = []
for _ in range(q):
    x, b = map(int, input().split())
    x -= 1
    ops.append((x, b))

ans = [-1] * n
lo = [0] * n
hi = [q] * n

fw = Fenwick(n)

active = list(range(n))

while True:
    mids = {}
    for i in active:
        if lo[i] <= hi[i]:
            m = (lo[i] + hi[i]) // 2
            mids.setdefault(m, []).append(i)

    if not mids:
        break

    fw = Fenwick(n)

    keys = sorted(mids.keys())
    cur = 0
    ptr = 0

    for mid in keys:
        while cur < mid:
            x, b = ops[cur]
            val = b / sub[x]
            fw.range_add(tin[x] + 1, tin[x] + sub[x], val)
            cur += 1

        for i in mids[mid]:
            if fw.sum(tin[i] + 1) >= a[i]:
                hi[i] = mid
            else:
                lo[i] = mid + 1

    active = [i for i in active if lo[i] <= hi[i]]

for i in range(n):
    print(lo[i] if lo[i] <= q else -1)
```DFS 构建了一个子树区间表示，因此每个子树都成为一个连续的段。 芬威克树保持了这些部分的累积贡献。 每个奖励都使用子树大小划分转换为范围更新。 

对答案的二分搜索结构是通过以下方式实现的`lo`和`hi`，其中每个员工独立搜索满足阈值条件的第一个查询索引。 

一个微妙的点是浮点除法`b / sub[x]`。 由于阈值可能很大并且重复加法会累积，因此这依赖于精度。 在更严格的版本中，缩放到整数或使用分数会更安全，但预期模型假设精确的算术或足够小的误差容限。

 ## 边缘情况

 一个关键的边缘情况是当一个节点仅通过对其祖先的重复更新来接收其所有贡献时。 例如，每次更新都针对根的深层链会导致每个节点积累相同的增量。 该算法可以正确处理此问题，因为每次更新都应用于根的完整欧拉区间，因此每个节点查询都会在所有中点上看到一致的累积。 

另一种边缘情况是当节点的阈值小于第一更新贡献时。 在这种情况下，二分查找将立即将其答案放置在索引 1 处，因为应用第一次更新后的中点检查已经满足条件。 单调性确保它永远不会错误地向右移动。 

最后的边缘情况是没有更新达到节点的阈值。 在这种情况下，二分查找会不断将节点的间隔向右推，直到`lo > q`，最终输出变为 -1，匹配无法达到的阈值所需的行为。
