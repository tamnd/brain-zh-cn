 ## 解决方案
 ## 问题理解

 我们遇到这样的情况：咖啡首先被装入几个相同的小容器中。 每个小容器总是准确地容纳$K$咖啡单位，并且有$N$这样的容器。 所以咖啡的总量就是$N \times K$。 

然后，必须将这种咖啡重新包装到更大的容器中，每个大容器最多可以容纳$L$单位。 目标是确定在最佳包装的情况下需要多少个大容器，这意味着我们在使用下一个容器之前尽可能填充每个大容器。 

因此任务减少为计算有多少容量-$L$需要存储总共的垃圾箱$N \cdot K$单位。 

限制很小：$N, K, L \leq 1000$。 这立即告诉我们咖啡的总量最多是$10^6$，因此即使是对单位或简单算术的模拟也足够快。 输入大小甚至咖啡总量中任何达到线性时间的值都是可以接受的，但我们可以明确地瞄准$O(1)$算术解决方案。 

当总量可以被整除时，就会出现微妙的边缘情况$L$。 例如，如果$N=2, K=3, L=6$，总计为$6$，而我们正好需要一个桶。 简单的整数除法方法必须确保它通过向上舍入正确处理可整除和不可整除的情况。 

另一个极端情况是当$L = K$。 那么每个大桶所装的正好是一个小桶所装的，答案就变成了$N$。 如果一个实现错误地执行整数除法而不考虑总聚合，它可能会错误地崩溃结构，但这里正确的推理仍然是纯粹基于总的。 

## 方法

 思考这个问题的一种直接方法是模拟一次填充大桶的过程。 我们取咖啡总量$N \cdot K$, 反复减去$L$，并计算我们这样做的次数。 这是正确的，因为每次减法都代表装满一个大桶。 

然而，这种方法在最坏的情况下会变得低效。 如果$N \cdot K$很大并且$L = 1$，我们将执行到$10^6$迭代。 虽然仍然处于可接受的范围，但考虑到问题的结构，这是没有必要的。 

关键的观察是，我们本质上是将固定数量划分为不同大小的组$L$。 这正是带有向上舍入的整数除法。 我们不进行模拟，而是直接计算上限$\frac{N \cdot K}{L}$。 这会在一个表达式中捕获完整的存储桶和任何部分填充的最终存储桶。 

从模拟到算术的转变来自于认识到在此过程中没有任何变化，只有整体才是重要的。 一旦我们将所有咖啡聚合成一个值，它最初包装的内部结构就变得无关紧要了。

 | 暴力模拟|$O(NK)$|$O(1)$| 最坏情况下太慢|

 ## 算法演练

 1. 读取数值$N$,$K$， 和$L$。 这些定义了小型容器的数量、容量以及大型容器的容量。 
2. 计算咖啡总量：$T = N \cdot K$。 此步骤将整个初始配置折叠成单个数量，因为只有总质量对重新包装很重要。 
3. 计算有多少个满载的大集装箱$T$，即$T // L$。 
4、检查是否有余数$T \bmod L$。 如果有剩余的咖啡，则需要额外一个大容器来存放。 
5、输出$T // L + (1 \text{ if } T \bmod L \neq 0 \text{ else } 0)$。 

### 为什么它有效

 填充大型容器的过程仅取决于总体积。 每个容器独立容纳$L$单位，因此任何最佳包装策略都会尽可能完全填满容器。 提取尽可能多的完整大小组后$L$尽可能地，任何剩余的正数必须正好占用一个额外的容器。 这保证了公式计算所需的最小容器数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N, K, L = map(int, input().split())

total = N * K

ans = total // L
if total % L != 0:
    ans += 1

print(ans)
```该解决方案首先将输入压缩为单个总值。 这避免了模拟任何包装过程。 整数除法给出完全填满的大桶的数量，而条件增量处理剩余的情况，确保正确的上限行为。 

一个常见的错误是忘记了剩余的情况而只打印`total // L`。 当总数不是精确倍数时，就会低估$L$。 

## 工作示例

 ### 示例 1

 输入：```
2 3 6
```这里$T = 2 \times 3 = 6$。 

| 步骤| 总 T | T // 长 | T % L | 回答 |
 | --- | --- | --- | --- | --- |
 | 计算总计 | 6 | - | - | - |
 | 除以 L | 6 | 1 | 0 | 1 |

 总数恰好填满了一大桶，所以没有剩余。 这证实了精确整除不会产生额外的桶。 

### 示例 2

 输入：```
5 3 4
```这里$T = 5 \times 3 = 15$。 

| 步骤| 总 T | T // 长 | T % L | 回答 |
 | --- | --- | --- | --- | --- |
 | 计算总计 | 15 | 15 - | - | - |

 三个满的大小为 4 的桶占 12 个单位，还剩下 3 个单位，需要第四个桶。 这演示了当有余数时天花板效应如何出现。

 ## 边缘情况

 当$N = 1, K = 1, L = 1$，总数恰好为 1，算法计算$1 // 1 = 1$，没有余数。 答案正确地变为 1，表明基本情况行为正确。 

当总数小于$L$， 例如$N=3, K=2, L=10$，总数为 6。除法给出 0 个满桶，余数为 6，触发额外的桶。 该算法输出 1，这符合即使少量仍需要一个容器的要求。 

当总数可以整除时，例如$N=1000, K=500, L=1000$，总数为 500000。除法给出 500 个满桶，余数为零，因此不会添加额外的桶。 这证实了该算法在干净除法的情况下不会过度计数。
