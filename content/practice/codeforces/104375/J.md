 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中每个值代表物质的“跳跃能量”。 当两种物质具有能量$a$和$b$混合在一起，它们贡献的能量为$ab$。 当两种以上的物质混合在一起时，总能量定义为所选元素中所有成对乘积的总和。 

所以对于任意查询范围$[L, R]$，我们取子数组$A_L, A_{L+1}, \dots, A_R$并计算：$$\sum_{L \le i < j \le R} A_i A_j$$每个查询都要求对该值取模$10^9 + 7$，并且最多可以有$10^6$查询大小可达的数组$10^6$。 

直接阅读表明我们需要在许多子数组上重复计算一个函数，并且该函数取决于子数组内的所有成对相互作用。 

关键的约束含义是$N$和$Q$足够大，任何解决方案都可以做到$O(R-L)$每个查询太慢。 每个查询二次方法是完全不可能的，因为单个最坏情况查询已经是$O(10^{12})$运营。 

稍微不那么幼稚的方法仍然不够：即使$O(N)$每个查询导致$10^{12}$总操作。 

唯一可接受的目标大致是$O((N+Q)\log N)$或者$O(N+Q)$。 

朴素的公式中出现了一个微妙的问题：每个查询独立地重新计算对和会导致重复的工作，除非我们重构表达式，否则这些工作是不可重用的。 

## 方法

 暴力方法直接遵循定义。 对于每个查询$[L, R]$，我们迭代所有对$i < j$并积累$A_i A_j$。 这是正确的，因为它完全符合能量作为成对乘积之和的定义。 然而，对于一定的长度范围$k$，这需要$k(k-1)/2$乘法。 在最坏的情况下$k = N = 10^6$，所以单个查询已经变得不可行。 

即使我们尝试通过修复一个端点并对另一个端点求和来改进它，每个查询在范围大小上仍然保持线性，这仍然会导致最坏情况下的二次总复杂度。 

关键的观察结果是成对和具有标准的代数恒等式。 如果我们定义：$$S = \sum A_i, \quad S_2 = \sum A_i^2$$然后：$$\left(\sum A_i\right)^2 = \sum A_i^2 + 2\sum_{i<j} A_iA_j$$重新排列给出：$$\sum_{i<j} A_iA_j = \frac{S^2 - S_2}{2}$$这将问题从“所有对的总和”转换为计算两个前缀和的问题：元素和和平方和。 一旦这些可用，每个查询就会变成 O(1)。 

我们预先计算前缀和：$$P[i] = \sum_{k=1}^{i} A_k,\quad Q[i] = \sum_{k=1}^{i} A_k^2$$然后进行查询$[L, R]$:$$S = P[R] - P[L-1], \quad S_2 = Q[R] - Q[L-1]$$答案是：$$(S^2 - S_2) \cdot inv2 \bmod (10^9+7)$$除以 2 需要 2 的模逆。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(NQ) | O(1) | O(1) | 太慢了 |
 | 前缀和+恒等| O(N + Q) | O(N) | 已接受 |

 ## 算法演练

 1. 预先计算数组上的值的前缀和以及前缀平方和。 

这允许在恒定时间内计算任何段总和或平方和。 
2. 对于每个索引$i$， 店铺：$P[i] = P[i-1] + A[i]$和$Q[i] = Q[i-1] + A[i]^2$。 

我们提前对值求平方的原因是最终公式取决于线性和二次聚合。 
3. 预先计算 2 的模逆$10^9+7$。 

这是必要的，因为对计数引入了除以 2 的过程，必须用模算术来处理。 
4. 对于每个查询$[L, R]$，计算：$S = P[R] - P[L-1]$和$S_2 = Q[R] - Q[L-1]$，归一化模。 

这些代表所选线段的总和和平方和。 
5. 使用以下命令将段转换为对和：$(S^2 - S_2) / 2$。 

此步骤依赖于展开总和平方的代数恒等式。 
6. 输出结果取模$10^9+7$。 

### 为什么它有效

 正确性来自于在多重集上展开总和的平方。 每一个产品$A_iA_j$和$i \ne j$恰好出现两次$S^2$，一旦作为$A_iA_j$并一度作为$A_jA_i$。 减法$\sum A_i^2$删除对角项，留下所需成对和的两倍。 除以二可以纠正计数过多的情况，确保每个无序对只贡献一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
INV2 = (MOD + 1) // 2

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for i in range(1, n + 1):
        x = a[i - 1] % MOD
        pref[i] = (pref[i - 1] + x) % MOD
        pref2[i] = (pref2[i - 1] + x * x) % MOD

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        s = (pref[r] - pref[l - 1]) % MOD
        s2 = (pref2[r] - pref2[l - 1]) % MOD

        ans = (s * s - s2) % MOD
        ans = (ans * INV2) % MOD
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```前缀数组`pref`和`pref2`分别存储累积和和累积平方和，两者均取模$10^9+7$。 每个查询都会减少对这些预先计算值的恒定时间算术。 

乘法`s * s`在模算术下是安全的，因为所有操作都已经对模 MOD 进行了约简。 减法也被归一化以避免负值。 由于 MOD 是质数，因此 2 的倒数会预先计算一次。 

## 工作示例

 ### 示例 1

 输入：```
5 3
1 2 3 4 5
1 2
1 5
3 5
```我们构建前缀和：

 | 我| A[i] | P[i] | Q[i] |
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | 1 |
 | 2 | 2 | 3 | 5 |
 | 3 | 3 | 6 | 14 | 14
 | 4 | 4 | 10 | 10 30|
 | 5 | 5 | 15 | 15 55 | 55

 供查询$[1,2]$,$S=3$,$S_2=5$。 

回答$= (9 - 5)/2 = 2$。 

为了$[1,5]$,$S=15$,$S_2=55$。 

回答$= (225 - 55)/2 = 85$。 

为了$[3,5]$,$S=12$,$S_2=50$。 

回答$= (144 - 50)/2 = 47$。 

这证实了恒等式将对和转换为前缀计算。 

### 示例 2

 输入：```
10 2
3 1 5 2 3 1 5 6 1 1
7 10
2 3
```前缀推理：

 对于$[7,10]$：值是$5,6,1,1$。 

和$S=13$, 正方形$S_2=25 + 36 + 1 + 1 = 63$。 

回答$= (169 - 63)/2 = 53$。 

为了$[2,3]$：值是$1,5$。 

和$S=6$, 正方形$S_2=26$。 

回答$= (36 - 26)/2 = 5$。 

这表明即使是不相交的分布和混合量值在相同的变换下也表现得一致。

 ## 边缘情况

 一种关键的边缘情况是范围只有一个元素。 对于输入如：```
1 1
7
1 1
```正确答案是 0，因为没有配对。 该算法处理这个问题是因为$S^2 = S_2$，因此减法在除法之前产生零。 

另一种情况是大型均匀数组，其中幼稚的实现存在由于重复乘法而导致溢出或速度减慢的风险。 例如，所有值都是$10^6$导致中间和很大，但模算术使值保持有界，并且前缀计算保持稳定。 

最后一个微妙的情况是减法在模算术中产生负的中间结果。 该实现通过在每次减法后取模来解决这个问题，即使在$P[L-1]$或者$Q[L-1]$大于对应的前缀$R$。
