 ## 解决方案
 ## 问题理解

 该游戏可以建模为有向图，其中每个级别都是一个节点，每个先决关系是一个有向边。 如果水平面有边缘`u`达到水平`v`，然后整理`u`解锁`v`， 所以`v`之后即可播放`u`已完成。 

单个游戏通关（称为运行）从任何一个指定的起始关卡开始，沿着有向边缘进行，始终移动到解锁关卡，直到到达可玩选项之间没有传出转换的关卡，该关卡保证是指定的结束关卡之一。 完成一次运行后，玩家从头开始新的游戏，但有严格的限制：任何先前运行中使用的每个级别都将永久不可用于所有未来的运行。 

目标是在无法从任何起始级别开始另一次运行并达到任何结束级别而不重用已消耗的节点之前，最大化可以执行的完整运行次数。 

关键的相互作用是运行不是独立的。 每次运行都会消耗其所选路径上的所有级别，并且这些节点以后无法重复使用。 这将问题转化为从起始节点集合到结束节点集合选择尽可能多的有效路径，约束条件是任何节点不能出现在多个路径中。 

限制条件`N ≤ 100`强烈建议路径的指数枚举是不可行的。 即使是中等的分支因子图也可以包含源和汇之间指数级的许多简单路径，因此任何尝试列出或尝试所有运行的方法都将失败。 预计会出现基于多项式流或基于匹配的公式。 

当多个起始级别可以达到重叠的中间结构时，会出现微妙的边缘情况。 例如，如果两个起点在到达接收器之前都进入共享链，则对一条路径的天真贪婪选择可能会阻止稍后更优化的组合。 

当一个关卡从一开始就可以到达并且位于通往不同终点的多个潜在路径上时，就会出现另一种边缘情况。 在贪婪路径选择中尽早选择它可以减少可能的不相交运行的总数。 

## 方法

 直接的尝试是贪婪地模拟运行。 人们可以重复选择一个起始节点，使用 DFS 或 BFS 查找到结束节点的任何路径，删除该路径上的所有节点，然后重复，直到不存在有效路径为止。 这很简单，每次运行都是单独有效的。 

然而，这种方法在很大程度上取决于路径选择的顺序。 本地有效路径可能会消耗对于稍后启用其他两条不相交路径至关重要的节点。 在具有共享瓶颈的图中，贪婪选择可以显着减少总计数。 

核心观察是，每次运行都是从某个源节点到某个接收节点的路径，并且没有节点可以在运行之间重用。 这正是具有多个源和汇的有向图中的顶点不相交路径的最大数量问题。 

这可以使用节点分裂转化为最大流问题。 每个节点被分为由容量为 1 的边连接的“内节点”和“外节点”，强制该节点最多可用于一次运行。 每个原始有向边`u -> v`变为无限容量边缘`u_out`到`v_in`。 超级源连接到所有起始节点，所有结束节点连接到超级接收器。 

该网络中的最大流量等于不相交有效运行的最大数量。 每个流单元对应于从开始到结束的一条完整路径，并且节点容量约束保证在不同的运行之间不会重用任何级别。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 贪心路径去除 | 最坏情况下呈指数 | O(N + M) | 太慢/不正确 |
 | 节点分裂的最大流量 | O(F·E) 与 Dinic，F ≤ N | O(N + M) | 已接受 |

 ## 算法演练

 我们将问题转换为流网络，其中路径对应于运行，流单元对应于已完成的游戏。 

1. 拆分每个节点`i`分成两个节点`i_in`和`i_out`，并将它们与容量 1 的边连接起来。这强制每个级别最多只能在一次运行中使用。 
2. 对于每个先决条件`u -> v`，添加一条有向边`u_out`到`v_in`具有无限的容量。 这保留了原始的移动规则，而不限制可以穿越边缘的不同运行数量。 
3.添加超级源节点。 将其连接到`s_in`对于每个起始级别`s`容量为 1。这确保每个起始级别最多可以启动一次运行。 
4.添加超级汇聚节点。 连接`e_out`每个结局关卡的水槽`e`容量为 1。这确保每个结束级别最多可以终止一次运行。 
5. 运行从超级源到超级汇的最大流量算法。 生成的流值是不相交运行的最大数量。 

这种构造起作用的原因是，任何有效的运行都对应于流网络中的一条路径，并且任何流单元都对应于选择这样的路径。 节点分裂保证了所有运行的不相交。 

### 为什么它有效

 任何可行的游程集都定义了一组从源到汇的顶点不相交路径，因此可以直接映射到每条路径承载一个单元的有效流。 相反，任何整数流都可以分解为源到汇的路径，并且每个分裂节点上的容量一约束确保没有节点出现在多于一条的路径中。 这在有效解和可行流之间建立了一对一的对应关系，因此最大化流可以最大化运行次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = [s]
        self.level[s] = 0
        for u in q:
            for v, c, _ in self.adj[u]:
                if c > 0 and self.level[v] == -1:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] != -1

    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                pushed = self.dfs(v, t, min(f, c))
                if pushed:
                    self.adj[u][i][1] -= pushed
                    self.adj[v][rev][1] += pushed
                    return pushed
        return 0

    def max_flow(self, s, t):
        flow = 0
        INF = 10**9
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF)
                if not pushed:
                    break
                flow += pushed
        return flow

n, s, e = map(int, input().split())
starts = list(map(int, input().split()))
ends = set(map(int, input().split()))
m = int(input())

N = 2 * n + 2
SRC = 2 * n
SNK = 2 * n + 1

dinic = Dinic(N)

for i in range(1, n + 1):
    dinic.add_edge(2 * (i - 1), 2 * (i - 1) + 1, 1)

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    dinic.add_edge(2 * u + 1, 2 * v, 10**9)

for st in starts:
    st -= 1
    dinic.add_edge(SRC, 2 * st, 1)

for en in ends:
    en -= 1
    dinic.add_edge(2 * en + 1, SNK, 1)

print(dinic.max_flow(SRC, SNK))
```实现首先构建节点分割结构，其中每个级别提供一个由容量 1 连接的内节点和外节点。 这是在所有运行中强制单一使用的机制。 

先决边从具有大容量的出节点添加到入节点，因此它们不会限制结构之外的重用。 

开始从超级源连接到入节点，结束从出节点连接到超级接收器，确保每次运行正确开始和结束。 

最后，Dinic 算法计算不相交的源到汇路径的最大数量，这直接对应于游戏运行的最大数量。

 ## 边缘情况

 关键的边缘情况是多个有效路径竞争单个中间节点。 例如，如果两个起始层在到达不同末端之前都通向共享走廊，则只有一个运行可以通过该走廊，因为节点容量为 1。 在选择第一条路径后，流模型自然会通过使共享节点的分割边缘饱和来强制执行此操作。 

另一种情况是起始级别也是结束级别。 该结构允许通过该节点从源到接收器的直接连接，并且其容量限制确保它只能在所有运行中使用一次。 该流程要么将其用作独立运行，要么将其保留用于更长的路径，具体取决于全局最优性。 

最后一种情况是完全断开的图，其中没有起始级别可以到达任何结束级别。 在这种情况下，流网络中不存在增广路径，因此最大流为零，这与不可能运行的事实相匹配。
