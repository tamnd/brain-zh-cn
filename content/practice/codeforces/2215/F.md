 ## 解决方案
 ## 问题理解

 我们正在研究一款两人确定性游戏，其牌组除了一张特殊牌外几乎都是相同的牌。 这张特殊的卡片最初是绿色的，位于顶部的已知位置。 每回合，玩家从牌堆顶部取出固定数量的牌，可以选择丢弃最多一张抽到的牌，然后可以重新排序并将其余牌放在底部。 关键的变化是绿卡不是静态的：每当爱丽丝抽出它并选择不丢弃它时，它的“价值”就会增加，并且她会被告知重新排列后的新位置。 

爱丽丝试图在绿卡被她丢弃时最大化写在绿卡上的最终值，而鲍勃则试图通过尽可能自己丢弃绿卡来迫使游戏以零值结束。 

交互不是关于整套牌的状态，而是关于控制绿卡在被抽出和被掩埋之间循环的速度。 每一步动作实际上都是在控制绿牌是否暴露在k大小的窗口内，以及对手是否可以先到达。 

这些约束迫使我们对这个过程进行纯粹的数学描述。 当 n 和 k 达到 10^9 时，任何对回合或牌组状态的模拟都是不可能的。 唯一可行的方法是将游戏简化为一小组结构状态，描述鲍勃何时保证获得绿卡，何时爱丽丝可以无限期地避免失败，以及何时爱丽丝可以以不断增加的计数器值强制最终捕获。 

最危险的边缘情况是绿卡永远不会达到任何玩家被迫丢弃它的状态。 在这种情况下，爱丽丝可以永远循环它，每次安全处理它时都会增加它的价值。 这会导致无限的结果。 

当鲍勃可以保证在他的第一个抽奖窗口中看到绿卡时，就会出现另一个微妙的边缘情况。 即使 Alice 以最佳方式向后移动，初始位置 s 可能已经位于 Bob 的第一个 k 窗口内，这意味着游戏立即以零分结束。 

最后，一个不太明显的问题是，许多天真的方法假设绿卡的地位是确定性发展的。 实际上，双方玩家都可以任意对未弃牌进行重新排序，因此状态仅取决于每次移动后绿牌是在当前 k 窗口内部还是外部，而不取决于确切的顺序。 

## 方法

 游戏的暴力视图将模拟每个回合。 我们将明确维护牌组顺序，提取前 k 张牌，决定丢弃哪一张，重新排序其余牌，并跟踪绿牌位置。 这在原则上是正确的，因为它完全遵循规则。 然而，每一圈都需要 O(k) 次操作，并且圈数可以随着 n 线性增长，甚至在循环配置中更多。 当n达到10^9时，这是完全不可行的。 

关键的观察结果是，除了绿卡在大小为 k 的滑动窗口内的相对位置之外，牌组顺序无关。 每次操作后，玩家可以自由重新排序，因此唯一有意义的问题是玩家行动时绿牌是否在接下来的k张牌中，以及哪个玩家优先将其移除。 

这将游戏变成了单一状态变量的可达性问题：绿卡距顶部的距离，以及轮到谁了。 每个回合要么减少控制（鲍勃试图将其带入窗口并丢弃它），要么延长循环（爱丽丝试图将其推出并在看到它时增加其价值）。 

该过程稳定为三种状态之一：鲍勃立即捕获，在固定数量的增量后由爱丽丝强制有限捕获，或永久循环，其中爱丽丝始终可以避免失败，同时继续增加分数。

一旦简化为这种结构，解就成为 n、k 和 s 上的确定性算术条件。

 ## 算法演练

 我们仅使用绿卡最初是否在鲍勃的直接触及范围内以及爱丽丝是否可以继续将其重新定位在强制捕获范围之外来对游戏进行建模。 

1. 检查Bob 是否可以在第一步立即获得绿卡。 当初始位置 s 在前 k 张牌内时，就会发生这种情况。 在这种情况下，Bob 立即绘制它并丢弃它，因此答案为 0。 
2. 否则，考虑爱丽丝的第一步。 她可以自由地取出k卡并重新排序。 如果她抽到了绿卡，她可能会选择保留它，增加其价值，然后将其重新插入牌组的深处。 
3. 关键量成为 Alice 可以强制执行的有效“安全距离”。 因为她可以在每次抽奖后任意重新排序，所以如果她选择不丢弃绿卡，她总是可以将绿卡推到抽奖部分的底部。 这意味着位置相对于 n − k 重置。 
4. 游戏变得周期性，因为在 Alice 和 Bob 移动的每个完整周期之后，绿卡要么：

 - 进入鲍勃的强制窗口，结束游戏，或者
 - 返回安全区域，爱丽丝可以再次延迟捕获。 
5. 如果安全区域非空，从而阻止 Bob 强制捕获，则 Alice 可以无限期地重复该循环。 在这种情况下，每次爱丽丝处理绿卡时，绿卡的价值都会增加，从而导致无限的分数。 
6. 否则，我们计算在绿卡不可避免地落入鲍勃的窗口之前，爱丽丝可以成功执行多少次“救援”。 每次救援都会将值加1，所以最终的答案就是计数。 

### 为什么它有效

 不变量是，在每轮最佳游戏之后，唯一有意义的状态是绿牌是否位于 Bob 控制的当前牌组方向的前 k 个位置内，或者在 Alice 的控制下。 由于两个玩家都可以任意排列所有非特殊卡牌，因此在回合中不会保留其他结构信息。 这使整个游戏陷入二元安全状态。 一旦爱丽丝可以无限期地将绿卡保留在鲍勃的窗口之外，该过程就永远不会达到最终丢弃状态，否则她可以避免捕获的次数是有限的，并且完全由初始间距和窗口大小决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, s = map(int, input().split())

        # immediate capture by Bob
        if s <= k:
            print(0)
            continue

        # if k == 1, Bob always eventually reaches any position
        if k == 1:
            print(0)
            continue

        # main reduction:
        # Alice can indefinitely avoid only if she can always push green
        # beyond Bob's reach; this happens when k < n/2 structure allows
        # perpetual cycling. Otherwise finite increments until forced capture.
        if k * 2 <= n:
            print("Infinity")
        else:
            # finite phase: compute number of safe cycles
            # each cycle reduces distance effectively by (n-k)
            dist = s - k
            cycle = n - k

            # number of full safe pushes before entering Bob window
            ans = (dist + cycle - 1) // cycle
            print(ans)

if __name__ == "__main__":
    solve()
```实施从处理琐碎的即时损失案例开始。 如果初始位置位于 Bob 的初始抽签窗口内，则游戏在 Alice 影响任何事情之前结束。 

k == 1 的情况会崩溃，因为每回合都会移除一张牌，因此控制权消失，无论重新排列能力如何，鲍勃最终都会到达绿牌。 

核心结构分裂在于两种制度之间：牌组相对于 k 足够大，爱丽丝可以在每次交互后始终“隐藏”绿卡；而鲍勃的窗口足够大，最终占据主导地位。 条件 k * 2 <= n 编码了这种分离：如果鲍勃的窗口相对于整副牌来​​说不是太大，那么爱丽丝可以不断地将绿卡循环到超出范围的范围。 

否则，该过程将变成有限的倒计时。 每个成功的循环都会将绿卡到鲍勃窗户的有效距离减​​少固定量，该量取决于每轮消耗的牌组数量。 算术级数产生强制捕获之前的最终增量数。

 ## 边缘情况

 绿卡在前 k 个位置内开始的立即丢失情况在算法的一开始就被处理。 在这种情况下，鲍勃的第一次抽签已经包括绿卡，因此不再需要进一步推理周期问题。 

当 k 等于 1 时，每一步都会从顶部删除一张牌，因此重新排列的自由度是无关紧要的。 该实施强制结果为零，因为在鲍勃的最佳发挥下，绿卡在某个时刻不可避免地成为顶牌。 

基于 k * 2 <= n 的状态分裂捕获了无限循环和强制收敛之间的过渡。 在 n = 10、k = 3 等小例子中，条件成立，Alice 可以通过在每次交互后将绿卡分发到前 3 个位置之外，始终使 Bob 无法触及绿卡。 当 n = 10、k = 6 时，条件失败，安全区域的重复收缩保证了最终捕获，与有限计算分支相匹配。
