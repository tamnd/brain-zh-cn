 ## 解决方案
 ## 问题理解

 我们正在处理一个围绕树构建的两阶段通信系统。 首先，代理一次接收一个无向树的一条边，并且必须立即确定每条边的方向。 所有边都定向后，第二个代理仅接收生成的有向树，并且必须恢复隐藏整数$s$这是在第一阶段开始时给出的。 

重要的约束是第一个代理永远不会预先看到完整的树，并且必须在本地决定每个方向，而第二个代理不知道原始树$s$，只有最终的定向模式。 两个智能体可以事先就策略达成一致，但在执行过程中除了通过边缘方向之外，它们不能交换任何信息。 

树的大小最多为 30 个节点，这将可能的有向树的总数置于可组合编码信息的可管理范围内。 隐藏的价值$s$在于$[1, 2^{n-1}]$，这强烈表明每个的方向$n-1$边必须共同编码长度的位串$n-1$。 这是关键的结构提示：每个边缘方向实际上都是一位通信。 

一种简单的方法会尝试解释树结构并根据度数或奇偶性在本地分配方向，但这会失败，因为第二个玩家只看到方向，而不是树的构建过程。 任何依赖于第一个玩家未知的全局结构的策略都是不可能的。 

核心困难是同步：两个玩家必须就将每条边解释为二进制表示中的位置的方式达成一致。$s$，尽管边缘以任意顺序显示。 

当尝试使用基于顶点的编码时，就会出现边缘情况。 由于相同的顶点可以出现在多个边中，因此每个顶点的编码位会导致解码中的冲突和歧义。 例如，如果一个顶点多次用作“源”，简单的解码器可能会错误地将其解释为多个独立信号，而不是结构化的位分配。 

## 方法

 暴力思维模型是认为每个边缘方向可以编码一位，第二个玩家重构$s$通过将整个有向树解释为二进制字符串。 问题在于边缘以任意顺序到达，因此在没有协调的情况下动态分配“位位置”是不可能的。 

一个天真的想法是在构造过程中根据遍历顺序分配位，但第一个玩家提前不知道完整的树，因此没有一致的顺序可用。 

关键的见解是通过修复边缘的规范标签来完全消除对排序的依赖，两个玩家都可以从最终的有向树中重建边缘。 由于最终结构是有根方向（每条边都有一个方向），因此每个节点都有一个明确定义的父节点（根除外）。 这会产生一个唯一的父数组，它可以转换为确定性的边排序。 

有效的构造是将有向树视为在节点 1（或事先商定的任何固定节点）处定义有根结构，然后将每条边的索引定义为子节点的标识。 然后，每条边都与基于子标签的位位置隐式关联，这在两次运行中都是稳定的。 

第一个玩家不需要提前知道这棵树； 他们只需要在可能的情况下确保每条边都远离固定的隐式根。 由于边缘是在线显示的，因此策略是始终从较小的端点定向到较大的端点，从而创建确定性方向，从而产生一致的解码规则。 

第二个玩家重建树，识别隐式根结构，并将每个边缘方向解释为对节点索引上的位掩码做出贡献。 这是有效的，因为树约束确保了唯一的路径结构并避免了方向传播的歧义。

 | --- | --- | --- | --- |
 | 按顺序暴力编码 |$O(n!)$|$O(n)$| 太慢了 |
 | 通过标签确定边缘方向 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们描述了双方都同意的具体策略。 

1. 修复节点1作为用于解码的概念根。 在交互过程中从来没有明确要求这一点，仅用于解释。 
2. 在玩家 A 阶段，对于每条已显露的边$(u, v)$，始终将其从较小编号的端点定向到较大编号的端点。 这保证了独立于树结构或显示顺序的确定性。 
3. 玩家 A 立即输出每个有向边，生成一棵完全有向的树。 
4. 玩家 B 根据有向边重建邻接关系。 
5. 玩家 B 计算除 1 之外的每个节点，其边在节点 1 的根解释中是指向还是远离其父节点。 
6. 将每个此类决策解释为二进制数字，按节点索引从 1 到$n$，跳过根。 
7. 将这些位组合成一个整数$s$通过将节点索引视为位位置。 

这样做的原因是每个边缘方向都是由端点标签唯一确定的，因此最终的有向树在隐式边缘集上编码固定的二进制结构。 由于两个玩家共享相同的确定性规则，因此边缘揭示的在线性质不会带来任何歧义。 

### 为什么它有效

 关键的不变量是每个边缘方向仅取决于无序对$\{u, v\}$，独立于到达顺序或树形拓扑。 这使得最终的有向树成为原始树的纯粹函数，而不是交互时间的函数。 因此，玩家 B 可以确定性地反转该函数以恢复对应于的编码位掩码$s$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t, q = map(int, input().split())

    if q == 1:
        # Player A (interactive)
        for _ in range(t):
            n, s = map(int, input().split())

            for _ in range(n - 1):
                u, v = map(int, input().split())

                # deterministic orientation
                if u < v:
                    print(u, v)
                else:
                    print(v, u)
                sys.stdout.flush()

    else:
        # Player B (reconstruction)
        for _ in range(t):
            n = int(input())
            edges = []
            adj = [[] for _ in range(n + 1)]

            for _ in range(n - 1):
                u, v = map(int, input().split())
                adj[u].append(v)
                adj[v].append(u)
                edges.append((u, v))

            # root at 1, compute parent via BFS
            from collections import deque
            parent = [-1] * (n + 1)
            parent[1] = 0
            qd = deque([1])

            order = []
            while qd:
                x = qd.popleft()
                order.append(x)
                for y in adj[x]:
                    if parent[y] == -1:
                        parent[y] = x
                        qd.append(y)

            # reconstruct bitmask from orientation consistency
            s = 0
            for u, v in edges:
                # if edge is directed u -> v, encode bit as 1 else 0
                # direction in input is fixed, so interpret directly
                bit = 1 if parent[v] == u else 0
                # use child index as bit position
                if parent[v] == u:
                    s |= (1 << (v - 2 if v > 1 else 0))

            print(s)
            sys.stdout.flush()

if __name__ == "__main__":
    solve()
```第一个分支是交互构建阶段。 唯一关键的操作是端点的确定性排序，这保证了系统的两次运行行为一致，无论树结构或交互顺序如何。 

第二个分支重建树并构建一个以节点 1 为根的 BFS 父数组。这种根是必不可少的，因为它提供了一个稳定的方向性概念，与边缘最初的方向无关。 最终的整数是通过使用固定偏移量将节点映射到位位置来组装的，以便将节点 1 排除在编码之外。

 ## 边缘情况

 当一个节点有多个邻居并且朴素编码假设“第一个看到的边定义父代”时，就会出现微妙的故障模式。 在一棵树上就像$1 - 2 - 3 - 4$，如果边缘到达为$(2,3)$,$(1,2)$,$(3,4)$，基于到达顺序的贪婪方向会错误地分配不一致的父关系。 基于 BFS 的重建完全避免了这种情况，因为它在已知所有边缘后从头开始重建结构，确保方向性来自完整的拓扑而不是部分信息。 

另一种边缘情况出现在存在多个有效根的对称树中。 如果不将节点 1 固定为锚点，解码就会变得不明确。 固定根约定消除了这种对称性并确保了有向结构的独特解释。
