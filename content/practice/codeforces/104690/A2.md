 ## 解决方案
 ## 问题理解

 我们有一个圆形的时钟，上面有几根指针，但所有的指针看起来都一样，所以我们不能直接辨别哪一个对应于小时、分钟或秒。 每只指针以固定周期均匀旋转，因此在任何时刻，三只指针都会形成三个角度，这三个角度由午夜以来的基本时间决定。 

输入以三个角度描述了时钟的一个快照，但这些角度未标记。 任务是确定这三个观察角度是否存在对三个真实时钟指针的有效分配，以便它们对应于午夜后的一致时间，如果是，则唯一地重建该时间。 

思考这个问题的一个有用方法是，时间是一个隐藏的整数值，从午夜开始以纳秒为单位测量，并且每个手的位置都是该值的确定性函数。 时针走动极其缓慢，每12小时旋转一整圈，分针每小时旋转一圈，秒针每分钟旋转一圈。 因此，观察到的状态是相同隐藏值的三个模线性表达式。 

该约束足够严格，即使有六种可能的观察角度分配给真实的手，但其中大多数不会对应于任何有效时间。 输出要么是没有分配起作用，要么是使配置一致的确切时间（以小时、分钟和秒为单位）。 

隐藏的规模非常大，因为问题是以纳秒为单位定义的，但结构是纯粹的算术模数约束。 这立即排除了任何随时间推移的模拟或暴力破解可能的次数，因为在典型公式中范围高达 10^18 比例。 相反，该解决方案必须依赖于时钟几何形状的直接重建。 

当两只或多只手重合时，就会出现关键边缘情况。 在这种情况下，分配的多个排列会产生相同的角度集。 例如，如果所有三个指针都指向 0 度，则任何分配都是一致的，但重建时间必须仍然有效并与所有约束一致。 假设从角度到手的映射具有唯一性的简单解决方案将因过度约束或拒绝有效案例而失败。 

当浮动精度或模块化环绕处理不正确时，会出现另一种微妙的情况。 由于每个指针位置都是以完整旋转为模定义的，因此相差一个完整周期的值必须被视为相同。 没有模块化标准化的简单角度比较可能会错误地拒绝手已完成完整旋转的有效配置。 

## 方法

 蛮力的想法很简单。 由于只有三只指针，并且我们不知道哪个观察角度对应于哪只真实的手，因此我们可以尝试这三个观察角度的所有排列，并将它们分配给时针、分针和秒针。 对于每个作业，我们尝试重建底层时间。 

一旦分配确定，时针直接确定以 12 小时为模的时间。 由此，我们可以得出以纳秒为单位的候选绝对时间。 使用这个候选，我们重新计算分针和秒针应该在哪里，并检查它们是否与模等价下观察到的角度匹配。 如果它们匹配，我们就找到了有效的解决方案。 

这是可行的，因为从时间到手位置的映射是确定性的，因此任何正确的分配都必须同时满足所有三个约束。 然而，由于暴力法只存在6种排列，所以它需要不断地工作，因此现阶段真正的困难不是组合爆炸，而是高精度地正确处理模运算并确保一致性。

关键的见解是，仅用一只手就足以重建整个时间。 时针以粗略但内射的方式在整个兴趣范围内对时间进行编码。 一旦我们将其角度解释为精细离散圆上的位置，它就会为完整时间戳提供唯一的候选者。 剩下的两只手充当验证约束而不是歧义源。 

因此，问题简化为迭代分配、从时针解码时间并验证其余部分。

 ## 算法演练

 我们将角度视为大圆上的整数刻度，并进行缩放，以便一次完整旋转对应于一个固定常数。 这使我们能够完全避免浮点运算。 

我们尝试将三个观察角度分配给小时、分钟和秒的各种排列。 

对于每个作业，我们首先将时针位置解释为定义候选时间。 由于时针每 12 小时完成一个完整周期，我们可以直接将其角度映射到以整个周期为模的纳秒时间戳。 此步骤有效地猜测我们距离 12 小时窗口还有多远。 

一旦我们有了候选时间戳，我们就可以使用已知的周期来计算分针和秒针当时应该在哪里。 这是时间到角位置空间的直接模乘。 

然后，我们将计算的位置与指定的观测值进行比较。 如果两者在模等价下完全匹配，则分配有效，我们可以输出解码时间。 

如果没有排列产生一致的分配，则配置是不可能的。 

### 为什么它有效

 正确性来自于这样一个事实：每个手的位置都是单个隐藏变量（自午夜以来的时间）的确定性线性函数。 当限制为时针的完整 12 小时间隔时，此函数是单射的，这意味着它唯一地确定问题域内的基础时间戳。 一旦时间戳被固定，另外两只手就不是自变量而是派生值，因此它们无法引入替代解决方案。 因此，任何有效的解决方案都必须在至少一种排列下保持一致，并且任何通过验证的排列都对应于真实的底层时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# constants based on full circle discretization
FULL = 12 * 60 * 60 * 10**9  # nanoseconds in 12 hours
HOUR = 60 * 60 * 10**9
MINUTE = 60 * 10**9
SECOND = 10**9

def check(h, m, s):
    # try interpreting h as hour hand
    # recover time from hour hand angle
    # scale assumption: h = t * (FULL / FULL) mod FULL in canonical form
    t = h % FULL

    mh = (t // MINUTE) % 60
    sh = (t // SECOND) % 60
    hh = (t // HOUR) % 12

    # convert observed m, s back to comparable scale
    # since all are modulo FULL, we compare normalized positions
    return (m % FULL == (t % FULL) * 60 // 1 % FULL) and (s % FULL == (t % FULL) * 3600 // 1 % FULL)

def solve():
    a = list(map(int, input().split()))

    for i in range(3):
        for j in range(3):
            if j == i:
                continue
            k = 3 - i - j

            h, m, s = a[i], a[j], a[k]
            if check(h, m, s):
                # reconstruct time in hh:mm:ss
                t = h % FULL
                hh = (t // HOUR) % 12
                mm = (t // MINUTE) % 60
                ss = (t // SECOND) % 60
                print(hh, mm, ss)
                return

    print("Impossible")

if __name__ == "__main__":
    solve()
```该代码首先读取三个观察到的角度值。 然后，它迭代这些值对三个时钟指针的所有分配。 对于每个作业，假设候选者的时针固定绝对时间模 12 小时。 

检查函数负责验证剩余两只指针是否与导出的时间匹配。 重建使用整数运算来避免精度问题。 最后一步将时间戳转换回标准小时、分钟和秒格式。 

一个微妙的实现细节是所有比较必须保持在相同的模块化域中。 在这种问题类型中，将原始角度与导出的时间分量混合在一起而没有一致的缩放比例是错误答案的最常见来源。

 ## 边缘情况

 当所有三个观察角度都相同时，算法仍然正常进行。 每个排列都会导致相同的重构时间戳，因此第一个有效检查会触发并返回零时间。 

当两只手共享相同的角度时，多个排列变得无法区分，但只有正确的语义映射才能通过导出值和观察值之间的一致性检查。 这样可以防止歧义影响正确性。 

当值接近模边界时，例如在完成完整旋转之前，通过模 FULL 进行归一化可确保同等位置得到相同处理。 重建时间保持稳定，因为所有比较都发生在同一循环域中。
