 ## 解决方案
 ## 问题理解

 我们给出了“金属”的目标多重集，其中每种金属类型都由正整数索引标识，并且我们必须能够为每个索引至少生成所需数量的单位，最多可达某个最大值。 我们从选定的单一基础金属开始，并且可以重复应用固定的转换规则：取一个金属单位`i`消耗它并生产较小指数的金属`i - a`和`i - b`（当这些指数为正时）。 指数小于 1 的金属不会做出任何贡献，因此当我们向下时，该过程自然会“消失”。 

任务不是模拟固定的过程，而是确定尽可能小的起始金属指数，以便在多次应用此转换并丢弃多余的之后，我们可以满足所有所需的数量。 

输入给出所需的最高金属指数`N`，两个偏移量`A`和`B`定义每种金属如何分裂，然后定义金属的需求数组`1`通过`N`。 输出是可以生成所有需求的最小起始索引，或者没有起始索引起作用的信号。 

尽管这种转变看起来像是创建了一个分支过程，但关键的困难在于我们可以自由地丢弃多余的东西。 这使得该结构更接近依赖有向图上的可行性问题，而不是模拟问题。 

约束（在最初的问题中，这来自 Codeforces 健身房内的 Code Jam 风格设置）允许`N`太大，因此任何模拟每个候选起始值的完全扩展的解决方案都会太慢。 简单的模拟会反复扩展节点，在最坏的情况下，单个单元可能会触发多个级别的级联，导致在重复尝试起始值时出现二次或更糟糕的行为。 

一个微妙的边缘情况是，当需求仅存在于小指数时，但由于由以下引起的类似奇偶校验的传播约束，可能仍然需要大的起始金属：`(i - A)`和`(i - B)`。 总是假设“更高的金属总是更好”的天真贪婪可能会失败，因为某些起点即使更大，也无法产生某些残基。 

## 方法

 蛮力法的观点很简单：选择一个起始金属指数`S`，模拟嬗变过程，跟踪我们最终可以生产多少单位的每种金属，并检查是否满足所有需求。 每种金属最多可以生成两个较小的金属，因此在最坏的情况下，创建的节点数量会像分支树一样增长。 即使有记忆，也要对每个候选人重复此操作`S`最多`N`导致操作计数顺序为`O(N^2)`或者更糟糕的是，这对于大量输入来说太慢了。 

关键的观察是，我们永远不需要从每个候选者开始显式地模拟前进。 相反，我们可以扭转观点：金属指数的每项需求都可以被认为需要来自更高指数的“支持”，这些指数可以通过重复的反向转换来产生需求。 每个金属指数仅取决于两个较大的指数，即`i + A`和`i + B`。 这将问题转化为反向图中的依赖传播或可达性条件。 

我们不是单独测试每个起点，而是通过向上传播需求来计算固定的起始索引是否足够。 如果我们想象我们“需要”一个金属单位`i`，那么我们必须将该要求置于其可能的父母身上`i + A`和`i + B`。 结构变得单调：如果起始索引`S`有效，那么任何更大的起始索引也有效，因为我们有更多的空间来生成所有内容。 这种单调性允许二分查找`S`。 

固定项目的可行性检查`S`贪婪地从高指数到低指数进行，将所需的计数向上推。 这避免了显式模拟并使每个检查保持线性`N`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每次启动时进行强力模拟 | O(N^2) 或更糟 | O(N) | 太慢了|
 | 反向传播+二分查找 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们修复候选起始索引`S`并测试它是否可以生成所有需要的金属。 

1.我们初始化一个数组`need[i]`等于每种金属所需的单位数`i`。 
2.我们从索引迭代`1`最多`S`，推动任何要求`i`向上至`i + A`和`i + B`。 每次我们“使用”一个单位时`i`，我们假设它一定是由更高的金属制成的，所以我们递减`need[i]`并增加`need[i + A]`和`need[i + B]`有效时相应地进行。 这模拟了转换的逆过程。 
3. 我们按升序处理指数，这样一旦我们解决了某个头寸，就不再需要它了。 这种排序之所以有效，是因为所有依赖项都指向上方。 
4. 传播后，我们检查是否所有`need[i]`为了`i ≤ S`为零或负数。 如果任何积极需求仍处于区间内，则起始指数`S`是不够的。 
5. 我们进行二分查找`S`从`1`到`max possible index`，使用上面的可行性检查。 

正确性取决于以下事实：所有转换都严格减少指数，因此每个生产链都是非循环的，并且从较大的指数流向较小的指数。 反转这个方向会产生一个有向非循环依赖图，并且传播完全捕获可以满足需求的所有方式。 

### 为什么它有效

 每个位置的需求单位`i`最终必须来自某个更高索引的链，并且每个这样的链都对应于逆边的重复应用`(i → i + A)`和`(i → i + B)`。 传播确保每个所需的单元都被“提升”到所有可能的祖先。 如果完全传播后候选范围内没有出现矛盾`S`，则存在仅使用索引 ≤ 的所有需求的有效分解`S`，意味着存在有效的构造。 可行性的单调性`S`保证二分查找找到最小有效起点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(S, N, A, B, req):
    need = req[:]
    
    for i in range(1, S + 1):
        if need[i] <= 0:
            continue
        
        cnt = need[i]
        need[i] = 0
        
        j1 = i + A
        j2 = i + B
        
        if j1 <= N:
            need[j1] += cnt
        if j2 <= N:
            need[j2] += cnt
    
    for i in range(1, S + 1):
        if need[i] > 0:
            return False
    return True

def solve():
    N, A, B = map(int, input().split())
    req = [0] + list(map(int, input().split()))
    
    lo, hi = 1, N
    ans = -1
    
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, N, A, B, req):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码将可行性检查与对可能的起始金属的搜索分开。 这`can`函数执行反向传播，确保每个需求都按照逆变换规则一致地向上推。 二分搜索利用了可行性的单调性。 

一个常见的实现陷阱是忘记在每次检查时复制需求数组，因为传播会改变它。 另一个微妙的问题是边界处理`i + A`或者`i + B`超过`N`，必须忽略，因为这些金属超出了要求的范围，并且不影响正确性。 

## 工作示例

 ### 示例 1

 假设`N = 5`,`A = 1`,`B = 2`，要求是`[0, 0, 1, 0, 0, 0]`。 

我们测试`S = 3`。 

| 我| | 之前需要[i] 行动| 传播 |
 | ---| ---| ---| ---|
 | 1 | 0 | 跳过| 无 |
 | 2 | 1 | 推| 需要[3] += 1，需要[4] += 1 |
 | 3 | 1 | 推| 需要[4] += 1，需要[5] += 1 |

 处理完后，里面的所有需求`≤ S`都解决了，所以`S = 3`作品。 

这说明了单个需求如何扩展到多个更高的依赖项，以及为什么需要贪婪的本地解决方案。 

### 示例 2

 让`N = 4`,`A = 1`,`B = 2`，有需求`[0, 1, 1, 0, 0]`。 

| 我| | 之前需要[i] 行动| 传播 |
 | ---| ---| ---| ---|
 | 1 | 1 | 推| 需要[2] += 1，需要[3] += 1 |
 | 2 | 2 | 推| 需要[3] += 2，需要[4] += 2 |
 | 3 | 3 | 推| 需要[4] += 3 |

 现在，指数 4 积累了需求，但超出了任何进一步的传播范围。 如果`S`太小，剩余需求仍然存在，表现出不可行。 

这说明了为什么选择`S`即使局部扩展看起来足够了，太小也会失败。

 ## 边缘情况

 一个关键的边缘情况是所有需求都集中在索引处`1`。 在这种情况下，如果重复的反向传播力需求向上的速度快于预期，则甚至可能需要相对较大的起始指数。 该算法可以处理此问题，因为传播始终尊重两个父分支，因此不会丢失隐藏的依赖关系。 

另一种情况是当`i + A`或者`i + B`超过`N`。 这些转变被安全地忽略，这对应于创建不相关金属类型的生产。 由于该问题允许丢弃多余的内容，因此这不会影响可行性，并且可以通过传播中的边界检查正确处理。
