 ## 解决方案
 ## 问题理解

 我们得到了一组盒子，每个盒子里装有一定数量的糖果。 每个朋友都只有一个盒子，目标是让所有盒子都包含相同数量的糖果，这样没有一个朋友会感到被遗漏。 我们只能吃盒子里的糖果； 我们无法添加任何内容。 输入提供多个测试用例，每个测试用例有框数`n`以及代表每个盒子中糖果的整数列表。 输出是我们必须吃掉的最小糖果总数，以平衡每个测试用例的所有盒子。 本质上，问题归结为确定我们可以在所有盒子中留下的糖果的最大数量（这是数组的最小值），并计算我们必须从每个盒子中移除多少糖果才能达到该水平。 

限制很小：`n`最多为 50 个，每个糖果数量最多可达`10^7`。 因为`n`很小，我们不需要复杂的数据结构或算法； 甚至每个测试用例多次迭代这些框也是可以接受的。 全部的总和`t * n`跨测试用例在一秒钟内即可管理。 不明显的边缘情况包括所有盒子已经拥有相同数量糖果的数组、只有一个盒子的数组或最小糖果数量与其他盒子相比非常低的盒子，这可能会导致较大的减法总和。 

## 方法

 暴力方法会尝试从 1 到数组中的最大值的所有可能的最终糖果计数，并计算每个候选者吃掉的糖果总数。 这是正确的，因为它考虑了每一个可能的统一目标，但效率很低。 对于每个测试用例，此方法可能需要迭代`10^7`对于每个框，单个测试用例可能会进行数亿次操作。 显然，这是不必要的，因为最佳统一数始终是数组中的最小糖果数。 减少低于该值的任何盒子只会增加吃掉的糖果数量，而不会影响其他盒子，而保留高于该值的盒子可以让我们最大限度地减少总消耗量。 

通过观察糖果的目标数量是数组中的最小值，我们可以将问题简化为每个测试用例的单个线性传递：找到最小值，然后将每个盒子与该最小值之间的差异相加。 这种方法的时间复杂度与`n`每个测试用例，考虑到限制，这是完全可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有目标 | O(n * 最大(a_i)) | O(1) | O(1) | 太慢了|
 | 最优（从最小值中减去）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取盒子的数量`n`和糖果计数列表`a`。 
2. 计算最小糖果数`min_candies`在列表中。 这代表每个盒子可以容纳的糖果数量，且不超过任何盒子的原始数量。 
3. 初始化计数器`candies_eaten`为零。 遍历每个框`i`在列表中，计算`a[i] - min_candies`，并将此差异添加到`candies_eaten`。 这代表我们必须从盒子里吃的糖果`i`使其与最小值相等。 
4. 输出`candies_eaten`对于当前的测试用例。 对所有测试用例重复此操作。 

其原理：这里的不变条件是，任何盒子中的糖果都不能多于它原来包含的糖果，因此任何统一的糖果数量都必须小于或等于最小值。 通过选择最小值，我们保证所有盒子都最小化以达到相等，从而确保吃掉的糖果总和最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        min_candies = min(a)
        candies_eaten = sum(x - min_candies for x in a)
        print(candies_eaten)

solve()
```该解决方案读取每个测试用例，计算列表中的最小值，并对差异求和。 使用生成器表达式求和既简洁又高效。 自从`n`最多为50，这种线性扫描是瞬时的。 唯一的微妙之处是确保我们使用快速 I/O 正确处理输入和输出，因为问题有多个测试用例。

 ## 边缘情况

 考虑只有一个盒子的边缘情况，例如，`[7]`。 最小值为 7，并且没有其他框可以均衡。 该算法正确计算出吃掉了 0 颗糖果。 另一种边缘情况是所有盒子都相等，例如`[5,5,5]`。 该算法仍然计算 0。其中一个框比其他框高的情况，例如`[1,1,1,2]`，结果只会吃掉多余的部分，并且计算正确地输出 1。这些示例证实了该算法正确处理了微不足道的输入和稍微倾斜的输入。
