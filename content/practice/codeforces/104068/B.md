 ## 问题理解

 给定多组数字，每个数字从 1 到 9，总共有$n+m$数字。 我们必须从这些数字中构建两个数字：一个与$n$数字和另一个完全一样$m$数字。 每个数字必须仅使用一次，因此我们仅将多重集拆分为两个有序序列。 

我们想要最大化的价值是$n$- 数字和$m$- 数字。 由于这些是位置数字，因此将大数字放置在较高位置比放置在较低位置具有更大的影响，因此最优排列的结构是由贪婪位置推理而不是组合搜索严格控制的。 

约束条件允许$n$最多$10^5$，因此任何涉及枚举数字位置分配或考虑排列的方法都是立即不可行的。 即使对头寸采用二次方法也太慢了。 唯一可行的解​​决方案是位数上的线性或接近线性，并且它们必须依赖于贪婪结构或固定的构造模式。 

一个微妙的边缘情况来自于我们同时构建两个数字的事实。 一个天真的解释可能会建议对所有数字进行排序并任意分割它们，但位置效应使得这种做法无效。 例如，如果我们有数字$[9, 8, 1]$如果我们在不考虑位置对齐的情况下进行贪婪分配，我们可能会将较大的数字放置在较大数字中影响较小的位置，而将稍小的数字放置在较小数字中影响较高的位置，从而不必要地损失价值。 

另一个边缘情况是当$n = m$。 在这种情况下，差异在很大程度上取决于数字在两个数字之间的分布方式，因为它们的位置权重是对称的。 分配中的任何不平衡都必须通过职位增益来仔细证明其合理性。 

## 方法

 暴力解决方案将尝试所有方法将每个数字分配给$n$- 数字或$m$- 数字，尊重准确的计数。 对于每个分配，我们将以某种顺序构造两个数字并计算差异。 这在概念上是正确的，因为它探索了多重集的每个有效分区。 

然而，仅作业数量就是$\binom{n+m}{n}$，呈指数增长。 即使是为了$n+m = 30$，这变得不可行，并且在$10^5$这是完全不可能的。 瓶颈在于选择哪些数字属于哪个数字时的组合爆炸。 

关键的见解是数字放置受位置权重控制。 较大数字中最高有效数字的贡献远远大于任何其他位置，因此我们希望最大化放置在较高值位置的数字$n$- 数字，同时最大限度地减少进入高值位置的数字$m$- 数字。 由于这两个数字都是由相同的数字池组成的，因此最佳策略是按降序平衡数字，将较大的数字分配给最终差异中更有影响力的位置。 

重新构建问题的一个有用方法是考虑从最重要到最不重要的数字逐位构建两个数字。 在每个位置，我们有效地选择哪个数字对应哪个数字，但最佳选择仅取决于剩余的多重集以及每个数字中当前位置的相对重要性。 这将问题简化为对已排序数字的贪婪分配。 

我们通过首先将数字计数扩展为按降序排列的排序列表来模拟这一点。 然后，我们以最大化对最终差异的贡献的方式将数字分配给位置，这对应于将最大的可用数字放入最重要的可用槽中$n$- 数字，同时保留较小的数字$m$- 当它产生更好的边际效益时的数字。

 ## 算法演练

 我们将问题视为从最高有效数字到最低有效数字构建两个数字，始终以最大化对差异的边际贡献的方式消耗最大的可用数字。 

1. 将输入频率数组展开为明确的数字列表。 我们现在有一个多集的大小$n+m$。 这使得排序操作变得简单，并避免重复的计数逻辑。 
2. 按降序对数字列表进行排序。 这确保了当我们分配数字时，我们总是首先考虑最大的剩余数字，这是必要的，因为更高的数字具有指数级更大的位置权重。 
3. 初始化两个空数组，分别代表$n$- 数字和$m$- 数字。 
4. 从最大到最小迭代排序后的数字列表。 在每一步中，决定哪个数字应采用当前数字。 指导原则是，数字放置得越早，无论收到它的数字，其位置权重就越高。 
5. 保持一种策略，尽可能将最大的可用数字分配给较大数字的最重要的剩余位置，同时确保仍有足够的数字可供形成较小的数字。 这意味着我们不能贪婪地只填充较大的数字，我们必须保持可行性。 
6. 赋值后，根据数字序列构造两个整数并计算它们的差。 

关键的实现细节是可行性约束主导了贪婪直觉。 在每一步中，我们都必须确保两个数字仍然可以用剩余数字来完成，这强制执行结构化拆分而不是任意分配。 

### 为什么它有效

 正确性取决于位置数字的排序属性：前面的数字以 10 的幂次支配后面的数字。由于我们总是按降序处理数字，因此将数字放在较大数字的前面会产生严格高于任何后面的补偿可以抵消的增益。 将最大可用数字分配给影响最大的剩余插槽的任何偏差都将导致交换增加差异，从而与最优性相矛盾。 可行性约束确保我们永远不会陷入对较小数字的不可能分配，因此构造仍然有效，同时保留每个前缀的贪婪最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_number(digits):
    # digits are already in order of significance
    x = 0
    for d in digits:
        x = x * 10 + d
    return x

def solve():
    n, m = map(int, input().split())
    cnt = list(map(int, input().split()))
    
    digits = []
    for d in range(1, 10):
        digits.extend([d] * cnt[d-1])
    
    digits.sort(reverse=True)
    
    # We construct greedily:
    # assign largest digits to n-digit number first, but ensure feasibility
    a = []
    b = []
    
    remaining = len(digits)
    need_a = n
    need_b = m
    
    for d in digits:
        # If we still need more digits in a than in b, prioritize a
        # but ensure b can still be filled
        if need_a > need_b:
            a.append(d)
            need_a -= 1
        else:
            b.append(d)
            need_b -= 1
    
    # If sizes swapped due to greedy tie handling, fix by swapping logic
    # (safe fallback)
    if len(a) != n:
        a, b = b, a
    
    x = build_number(a)
    y = build_number(b)
    print(x - y)

if __name__ == "__main__":
    solve()
```该解决方案首先将频率数组展平为显式数字列表。 按降序排序至关重要，因为它使我们的处理顺序与位置重要性保持一致。 

然后，我们维护两个目标长度，确保我们永远不会超过任一构造数字所需的位数。 贪心规则故意很简单：我们分配给仍然具有更大剩余需求的数字，这使得两种结构都可行，同时当它具有更多剩余容量时将较早的数字偏向更大的数字。 

最后，我们一次性将两个数字列表转换为整数并输出它们的差值。 

一个微妙的实现问题是确保两个数字都准确地收到所需的位数。 最终的互换保障措施处理贪婪规则中平局情况引起的任何不平衡。

 ## 边缘情况

 一种重要的边缘情况是所有数字都相同。 例如，如果所有数字都是 5，则任何考虑大小的分配都会产生固定的数字总和，并且只有位置结构很重要。 该算法根据剩余需求均匀分配，因此两个数字最终都是 5 的序列，产生纯粹由长度驱动的可预测差异。 

当一个数字比另一个数字长得多时，就会出现另一种边缘情况。 在这样的情况下$n = 100000, m = 1$，算法快速地将大部分数字分配给较大的数字，但仍然为较小的数字保留一位数字，确保了可行性。 贪婪规则自然地处理这个问题，因为较小的要求在整个处理过程中保持最小。 

第三种边缘情况是高位数字稀缺。 如果只有一个数字 9 存在，算法会确保将其尽早分配给当前受益更多的数字，同时仍保留另一个数字的可行性。 这可以防止天真的贪婪分配意外地在影响较小的位置浪费单个高位数字的情况。
