 ## 解决方案
 ## 问题理解

 随着时间的推移，一系列土豆到达。 每个土豆都有一个到达时间戳，一旦进入机器，其“煮过头的价值”就会随着时间线性增长。 在任何时刻，我们都可以一次操作将机器内当前所有的土豆拉出来。 每次这样的拉动都有固定的惩罚加上额外的成本，该成本等于当时所有土豆累积的煮过头的总和。 

任务是选择一组拉动时间，以便每个马铃薯最终都被恰好移除一次，同时最小化所有成本的总和。 

输入是到达时间的非递减序列。 这种单调性很重要，因为它确保当我们考虑将土豆分组为一次拉动时，内部的土豆组始终是按时间顺序连续的后缀。 

最大 10^6 的约束 n 强制任何解都是线性或接近线性的。 任何涉及成对转换、所有区间的动态规划或基于排序的二次合并的操作都将失败。 我们需要一个结构，其中每个马铃薯都被处理一次或恒定的次数。 

当 k 很大时，会出现关键的边缘情况。 如果拉动成本很高，我们可能更喜欢多次小拉动。 如果 k 为零，我们可能希望尽可能延迟并立即提取所有内容。 另一个边缘情况是到达时间相等或几乎相等，因为分组行为对合并是否会降低成本变得敏感。 

一个说明结构的小例子：

 输入：

 n = 3，k = 2

 t = [0, 1, 2]

 如果我们在时间 2 拉一次，成本为 k + (2 + 1 + 0) = 5。 

如果每次到达时分别拉3次，费用就是3k = 6。 

因此，分组在这里是有益的，但并不总是如此。 

该决定完全是关于将时间线划分为多个片段。 

## 方法

 从暴力视图开始：我们选择执行拉取的时间子集。 每次拉取定义了自上一次拉取以来到达的一组土豆。 对于将数组固定划分为段的情况，段的成本取决于所选的拉取时间，并且在段内，最佳拉取时间是其最后到达时间。 

因此，如果我们固定分段边界，我们可以直接计算成本：每个分段贡献 k 加上分段中上次到达时间之间的差值之和。 

暴力枚举 n 个项目的所有分区。 这本质上是 2^(n-1) 种可能性，因为每个间隙都可以被切割或不被切割。 即使评估一个分区的时间复杂度为 O(n)，总复杂度也会呈指数级增长并且对于 n 达到 10^6 时不可用。 

关键的观察结果是成本在本地分解并且可以增量地表示。 当我们扩展一个段时，我们要么继续在同一个拉动中积累，要么开始一个新的拉动。 这会在将当前元素合并到最后一段或在此处剪切之间创建一个经典的决策。 

我们将问题重新表述为线性扫描，并动态维护运行段成本。 每个新土豆都会根据其未拉动的时间贡献额外的等待成本，并且每个部分贡献固定的 k。 该结构相当于决定在哪里进行削减，并且可以通过维持扩展当前段是否比开始新段更差来贪婪地计算最佳结构，这减少了将增量成本增长与 k 进行比较。 

这导致了线性 DP，其中我们跟踪直至 i 的最佳成本，最后一段以 i 结束，并使用前缀和更新 O(1) 中的转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最优 DP / 贪婪分区 | O(n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

我们以一种明确的方式重写成本。 假设一个段在索引 r 处结束，并在 l 处开始。 我们在时间 t_r 拉取，因此成本是 k 加上 (t_r - t_i) 的 [l, r] 中 i 的总和。 

我们预先计算 t 的前缀和。 然后段成本变为 k + (r - l + 1) * t_r - (sum t[l..r])。 

我们将 i 从 1 处理到 n 并维护一个 DP 值，该值代表处理前 i 个土豆的最低成本。 最后一段以 i 结束，因此我们考虑上一次剪切的位置。 

## 算法演练

 1. 排序是不必要的，因为时间已经是非递减的。 我们依靠这种排序，以便段对应于连续的范围。 
2. 计算到达时间的前缀和，以便我们可以在 O(1) 内评估路段成本。 这避免了在每个转换内重新计算总和。 
3. 定义 dp[i] 为加工前 i 个土豆的最小成本。 
4. 对于每个 i，考虑最后一段从某个 j 开始并在 i 结束。 过渡是：

 dp[i] = dp[j] + cost(j+1, i) 的 j < i 上的最小值。 
5. 使用前缀和扩展段成本：

 成本(j+1, i) = k + (i - j) * t[i] - (前缀[i] - 前缀[j])。 
6. 重新排列术语以隔离 j 相关部分：

 dp[i] = k + i * t[i] - prefix[i] + min 超过 (dp[j] - j * t[i] + prefix[j]) 的 j < i。 
7. 观察到，对于固定 i，t[i] 在最小化内是恒定的，因此我们在 j 上维护一个数据结构，用于存储以下形式的行：

 value_j(x) = dp[j] + 前缀[j] - j * x,

 在 x = t[i] 处计算。 

这是一个凸包技巧结构，其中斜率为 -j，随着 j 的增加而单调，允许根据实现进行分摊 O(1) 或 O(log n) 查询。 
8. 按升序插入每个 j，为未来 i 保留最佳候选。 在 t[i] 处查询以计算 dp[i]。 
9. 初始化 dp[0] = 0 并包括基线 j = 0。 
10.答案是dp[n]。 

### 为什么它有效

 每个状态j代表选择前一个拉动位置。 凸包变换编码对 t[i] 的线性依赖，单调到达时间保证查询点不减。 这确保我们永远不需要以破坏最优性的方式重新考虑早期的线路。 每个 dp[i] 都是根据所有可能的最后一段的精确分解而构造的，因此不排除任何可行的分区，并且每个分区恰好映射到一个转换序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    t = list(map(int, input().split()))
    
    if n == 0:
        print(0)
        return

    # prefix sums of t
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + t[i - 1]

    # Convex hull trick with monotone slopes and queries
    hull = []  # each item: (m, b) representing m*x + b

    def add_line(m, b):
        # remove last if new line makes it obsolete
        while len(hull) >= 2:
            m1, b1 = hull[-2]
            m2, b2 = hull[-1]
            m3, b3 = m, b
            # check intersection condition
            if (b3 - b2) * (m2 - m1) <= (b2 - b1) * (m3 - m2):
                hull.pop()
            else:
                break
        hull.append((m, b))

    ptr = 0

    def query(x):
        nonlocal ptr
        if ptr >= len(hull):
            ptr = len(hull) - 1
        while ptr + 1 < len(hull):
            m1, b1 = hull[ptr]
            m2, b2 = hull[ptr + 1]
            if m1 * x + b1 >= m2 * x + b2:
                ptr += 1
            else:
                break
        m, b = hull[ptr]
        return m * x + b

    dp0 = 0
    add_line(0, 0)  # j = 0

    for i in range(1, n + 1):
        x = t[i - 1]
        best = query(x)
        dp0 = k + i * x - pref[i] + best
        add_line(-i, dp0 + pref[i])

    print(dp0)

if __name__ == "__main__":
    solve()
```该实现跟踪前缀和来评估段成本，而无需重新计算。 DP 递归被嵌入到凸包结构中，其中每个状态 j 变成一条线。 斜率是 -j，截距是 dp[j] + prefix[j]，与转移的代数重排相匹配。 

基于指针的查询之所以有效，是因为斜率和查询点都是单调的。 指针永远不会向后移动，从而提供摊销的线性复杂度。 

一个常见的错误是忘记 dp 贡献必须在截距中包含 prefix[j]； 缺少它会破坏线性变换并产生不正确的段成本。 

## 工作示例

 考虑输入：

 n = 3，k = 2

 t = [0, 1, 2]

 我们计算前缀和 pref = [0, 0, 1, 3]。 

| 我| x = t[i] | 最佳线路值| dp[i] 计算 |
 | ---| ---| ---| ---|
 | 1 | 0 | 0 | 2 + 1*0 - 0 + 0 = 2 |
 | 2 | 1 | 距行数分钟 | 2 + 2*1 - 1 + 最佳 |
 | 3 | 2 | 距行数分钟 | 最终合并与拆分|

 当 i = 3 时，结构倾向于单个段，产生 dp[3] = 5。 

该轨迹显示了早期决策如何被更好的远程分组覆盖，这正是凸包正在编码的内容：每个端点的最佳先前切割。 

现在考虑一个对比情况：

 n = 3，k = 10

 t = [0, 1, 2]

 这里 k 占主导地位，所以最好的解决方案是单个段。 dp 转换总是更喜欢延伸同一条线而不是引入新的有效中断。 船体仍然可以工作，但不会切换最佳前身。 

这表明该算法无需明确的案例工作即可自动适应两种制度。 

## 复杂度分析

 | 测量| 复杂性 | 说明|

 ## 边缘情况

 当 n = 1 时，唯一有效的操作是单次拉动，因此成本恰好为 k。 该算法初始化 dp[0] 并使用基线 j = 0 构建 dp[1]，产生 k + 0。 

当所有到达时间都相等时，每个马铃薯在任何段内的内部成本都为零。 该决策减少到最小化拉动次数，因此该算法实际上更倾向于将所有项目合并到一个段中，除非 k 强制拆分。 凸包退化为相同的查询点，但单调结构仍然返回正确的 dp 转换。 

当 k = 0 时，最佳策略始终是执行一次最终拉动。 DP 永远不会从开始新段中受益，并且船体不断选择 j = 0 作为最优，产生的总成本等于所有 i 的 (t[n] - t[i]) 之和。
