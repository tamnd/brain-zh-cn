 ## 解决方案
 ## 问题理解

 我们给出了一组$n$标记的顶点必须成为树的叶子。 我们可以添加额外的顶点，但这些额外的顶点彼此无法区分，并且每个这样添加的顶点在最终树中的度数必须恰好为 3。 每个原始标记顶点的度数必须恰好为 1，这意味着每个标记顶点都是叶子。 

因此，我们计算的结构是一棵树，其中所有标记的顶点都是叶子，每个内部顶点的度数为 3。如果两棵树在标记的叶子上的邻接结构不同，则认为它们不同。 内部顶点没有标记，因此重命名它们不会创建新的配置。 

输入包含许多测试用例，每个测试用例给出一个值$n$，我们必须输出有效树的数量模 998244353。 

这些约束意味着我们不能对每个测试用例做任何线性的事情。 高达$10^6$查询和$n$还高达$10^6$，任何每次测试的 DFS、DP 或类似阶乘的重新计算都会太慢，除非完全预先计算一次。 该解决方案必须在一次预处理之后将每个查询减少到恒定时间。 

一种简单的方法会尝试枚举通过 3 度内部节点连接标记叶子的树拓扑。 即使对于小$n$，未标记的树形状的数量呈超指数增长。 例如，与$n=6$，通过内部节点对叶子进行不同的分组方式已经产生了很多组合结构，直接生成是不可行的。 

一种常见的失败模式是尝试通过一一附加叶子并在本地计算选择来“增量构建树”。 这严重夸大了，因为许多构建序列都会导致相同的最终未标记的内部结构。 

## 方法

 蛮力视角是考虑构建一棵树，其叶子正是标记的顶点。 每个内部节点的度数必须为 3，因此每个内部节点将剩余结构分为三部分。 人们可以想象将标记的叶子递归地划分为通过内部节点连接的组。 这很快就变成了标记集的所有三元分解的计数问题，并且每个分解对应于许多等效的未标记内部排列。 

关键的观察是这种结构不是任意的。 任何所有内部节点的度数为 3 并且所有标记的顶点都是叶子的树正是无根的完整二元系统发育树。 组合学的一个经典结果表明，此类树的数量$n$标记的叶子是$$(2n - 5)!!$$这是从 1 到 的所有奇数整数的乘积$2n - 5$。 

这个公式也可以归纳推导。 如果我们已经知道树的数量$n-1$叶子，添加新的标记叶子相当于细分现有边缘并附加新叶子。 在步骤$n$，正好有$2n-5$任何有效树中的边，这给出了乘法递归。 

因此，我们完全避免任何结构枚举，而是计算一个简单的乘积序列。 

暴力破解会失败，因为它试图探索呈指数级增长的树形状，而正确的视图会通过增量插入将整个结构折叠成单个封闭形式的产品。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举| 指数| 指数| 太慢了|
 | 乘法公式$(2n-5)!!$|$O(n + T)$|$O(n)$| 已接受 |

 ## 算法演练

 计算减少为预先计算所有值$(2n-5)!!$达到最大$n$在输入中。 

1.观察基本情况是$n = 3$，其中只有一棵有效的树。 这符合以下事实：$(2\cdot 3 - 5)!! = 1!! = 1$。 
2. 维护数组`dp[n]`在哪里`dp[n]`存储有效树的数量$n$标记的叶子。 
3. 使用从边缘插入导出的递归：当增加来自边缘插入的叶子数量时$n-1$到$n$，可用附着位置的数量为$2n - 5$。 这产生$$dp[n] = dp[n-1] \cdot (2n - 5)$$4. 预计算`dp[n]`迭代地从$n=3$直至最大输入值。 
5.对于每个查询，直接输出`dp[n]`。 

计算纯粹是乘法，因此所有值都构建在一次线性扫描中。 

正确性取决于每个有效树的不变量$n$标记的叶子正好有$2n-5$可以插入新叶子的边，同时保留度数约束。 每次插入都是可逆的，并产生一个唯一的更大的树，因此乘法对每个扩展恰好计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    t = int(input())
    ns = [int(input()) for _ in range(t)]
    max_n = max(ns)

    dp = [0] * (max_n + 1)

    if max_n >= 3:
        dp[3] = 1
        for n in range(4, max_n + 1):
            dp[n] = dp[n - 1] * (2 * n - 5) % MOD

    out = []
    for n in ns:
        out.append(str(dp[n]))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```DP数组构建一次达到查询的最大值$n$。 每个转换都乘以从相应树中可用边的数量导出的奇数线性项。 通过查找在恒定时间内回答查询。 

一个微妙的点是初始化$n=3$。 从这个基数开始可以避免处理公式中无效的负索引。 重复仅从以下日期起有效$n \ge 4$。 

## 工作示例

 考虑较小的值以查看序列如何展开。 

为了$n=3$，我们设置：

 | n | dp[n] | dp[n] | 过渡|
 | ---| ---| ---|
 | 3 | 1 | 基地|

 为了$n=4$:

 | n | dp[n] | dp[n] | 过渡|
 | ---| ---| ---|
 | 3 | 1 | 基地|
 | 4 | 1 × 3 = 3 | 1 × 3 = 3 乘以$2·4-5=3$|

 为了$n=5$:

 | n | dp[n] | dp[n] | 过渡|
 | ---| ---| ---|
 | 3 | 1 | 基地|
 | 4 | 3 | 上一步 |
 | 5 | 3 × 5 = 15 | 3 × 5 = 15 乘以$2·5-5=5$|

 这与叶子增加时树拓扑的预期增长相匹配。 每个步骤都引入严格增加数量的附着位置，反映了立方树的扩展组合结构。

 ## 边缘情况

 对于$n=3$，树没有内部结构，答案必须是 1。算法显式设置此基本情况，因此在较小的索引处不会错误地应用递归。 

对于大型$n$，乘积增长很快，但在模运算下仍然可以管理。 该实现确保乘法始终以 998244353 为模进行减少，从而防止溢出并保持值有界。 

为了$n=4$，正好有 3 棵有效树。 这是递归激活的第一个重要情况，它验证了该因子$2n-5$正确计算可用的附件位置。
