 ## 问题理解

 我们正在模拟一个回合制系统，其中怪物以一定的生命值开始，并且可以重复应用两种动作。 每个操作都会以确定性的方式改变健康状况：一个操作将健康状况大致减半，然后添加一个固定常数，而另一个操作则减去一个固定常数。 

目标是确定是否存在这些操作的任何序列，并考虑每个操作可以使用的次数上限，最终将运行状况降至零或更低。 

每个测试用例都会给出一个初始健康值和两个代表每个咒语可以使用多少次的计数器。 我们必须确定这些有界操作的某些顺序是否会使健康状况变得非积极。 

操作计数的约束很小，因为两个限制最多为 30。这立即排除了在大型状态空间上进行复杂图搜索的任何需要。 即使对所有可能的咒语计数进行状态探索在最坏的情况下也是可行的，因为组合的数量最多为 31 x 31。然而，棘手的部分是排序很重要，因为一个操作非线性地缩小值，而另一个操作线性地减去值。 

主要的陷阱是假设固定的贪婪排序总是在没有理由的情况下起作用。 例如，总是先应用减半咒语可能会失败：

 输入：```
x = 64, n = 1, m = 3
```如果我们先应用虚空吸收，我们会得到64→42，然后三击：12→2→-8→-18，这有效。 但在类似情况下错误地逆转选择很容易陷入零以上的状态。 减半和减法之间的相互作用并不是天真的意义上的单调。 

当减半变得有害时，会出现另一种失败情况：

 输入：```
x = 10, n = 1, m = 0
```虚空吸收给予地板(10/2)+10 = 15，增加而不是减少生命值。 总是使用可用的虚空吸收的幼稚策略会立即使情况变得更糟。 

因此，关键问题是该法术并非一律有益，最佳选择取决于当前的生命值大小。 

## 方法

 暴力解决方案将尝试最多 n + m 操作的所有可能序列。 在每一步，它都会根据我们是否应用虚空吸收或雷击而分支，并尊重剩余计数。 这是正确的，因为它探索了整个决策树。 然而，分支因子导致大约 2^(n+m) 个状态，在最坏的情况下达到 2^60，远远超出了可行的限制。 

关键的观察是，生命值一旦变小就会趋于缩小，而唯一危险的情况是虚空吸收可能会暂时增加或几乎不会降低该值。 一旦生命值很大，只使用雷击是合理的，因为减半加10往往比反复减10更糟糕。 但当生命值变小时，应用虚空吸收就不再有用，因为与直接减法相比，它开始增加值或减少值太慢。 

这种结构建议进行修剪的贪婪模拟：如果生命值足够大，我们总是在可能的情况下更喜欢闪电打击，并且仅在有助于降低强度或打击耗尽时才使用虚空吸收。 由于 n 和 m 很小，我们可以安全地模拟所有有意义的转换，而不必担心长链。 

一种简洁的形式化方法是，只要有好处，就反复尝试贪婪地应用雷击，偶尔应用虚空吸收来更快地减少大值，但永远不要超过必要的程度。 由于状态空间很小，我们可以安全地进行模拟，直到无法进一步改进或耗尽界限为止。

 ## 算法演练

 我们模拟每个测试用例的过程，总是试图尽可能有效地减少健康状况。 

1.如果我们仍然有虚空吸收的用途，并且应用它会显着降低生命值并保持其有用，那么我们会考虑在生命值较大时应用它。 

变换可以根据大小减少或增加值，因此必须有选择地使用。 
2. 否则，我们优先考虑闪电打击，因为它是严格单调的，并且总是以固定的量减少生命值。 
3. 我们重复这个决策过程，直到健康状况变为零或负，或者我们用完这两个操作。 
4. 如果我们在用尽所有有效申请后仍无法将健康状况降至零或更低，则我们断定这是不可能的。 

关键思想是系统没有可以无限利用的循环，因为每个操作计数都是有界的，并且每个操作要么降低健康状况，要么最终变得比替代方案更糟糕。 这确保了模拟快速收敛。 

不变的是，在每一步中，我们都会在贪婪优先级下保持剩余操作的最佳可实现健康状况：当雷击直接有助于减少时，总是使用闪电打击，而虚空吸收仅在不会导致可避免的恶化时使用。 由于这两种操作都是有界的，并且变换严格减少了有效搜索空间，因此模拟不会错过有效序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, n, m = map(int, input().split())

        # We try a greedy reduction:
        # Use Void Absorption only while it helps reduce large values.
        # Otherwise use Lightning Strike.
        h = x

        # First, try to use Void Absorption when it is clearly beneficial.
        # Empirically, it is useful only when h > 20.
        while n > 0 and h > 20:
            h = h // 2 + 10
            n -= 1

        # Then use all Lightning Strikes
        h -= 10 * m

        if h <= 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该实施反映了这样的观察：虚空吸收仅在高健康状况下才有帮助。 一旦数值跌破一个小阈值，减半加10就不再比直接减法有效，所以我们提前停止使用，将所有剩余资源转化为直接伤害。 

阈值行为是关键的微妙之处：没有它，简单的交错策略可能会振荡或浪费操作。 所选择的截止点确保我们永远不会应用会增加或阻碍进度的转换。

 ## 边缘情况

 一个关键的边缘情况是当生命值较小而虚空吸收会增加它时。 例如，从 10 开始，没有可用的攻击和一个无效法术，转换产生 15，这使情况变得更糟并导致失败。 该算法通过不在健康状况不佳的情况下应用虚空吸收来避免这种情况。 

当生命值很大但只有少数虚空法术可用时，会出现另一种边缘情况。 在这种情况下，尽早应用所有虚空法术是有益的，因为它可以迅速将价值降低到打击占主导地位的区域。 贪婪阈值确保这种加速发生在切换策略之前。 

最后一种边缘情况是仅存在雷击的情况。 然后解决方案简化为检查 m * 10 是否至少为 x，这由最后的减法步骤正确处理。
