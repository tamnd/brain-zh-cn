 ## 解决方案
 ## 问题理解

 我们有一个矩形房间，里面有一个固定轴对齐的矩形桌子。 该桌子目前占据房间内的一个方块，但我们可以将该桌子滑动到房间内的任何位置，只要它完全位于边界内即可。 

我们还有第二个具有固定尺寸的矩形桌子，我们想将其放置在同一个房间的某个地方。 尽管允许接触边缘，但第二个桌子不能与第一个桌子重叠。 

任务是确定我们需要移动第一个桌子的最小距离，以便在移动它之后，至少存在第二个桌子的有效位置。 

关键是第二张桌子永远不会移动，而第一张桌子可以在房间内任意重新定位，只要它完全留在室内即可。 

约束允许最多 5000 个测试用例，坐标最多为 10^8。 这立即表明任何解决方案都必须是每个测试用例的恒定时间。 任何涉及搜索放置或模拟网格中的移动的事情都是不可能的，因为几何空间是连续的并且太大了。 

当第二个桌子已经适合而无需移动第一个桌子时，就会出现微妙的边缘情况。 在这种情况下，答案是零。 另一种边缘情况是，房间中的可用空间总面积足够大，但由于固定桌子的几何形状阻塞，仍然无法容纳第二个矩形。 例如，即使总面积看起来足够，但被第一张桌子分开的狭窄走廊可能不允许放置。 这排除了任何仅基于面积比较的方法。 

当第一个表已经阻止了所有可能的放置，即使将其滑动到任何角落也无法为第二个表打开有效区域时，就会出现最后的极端情况。 这会产生否定的答案。 

## 方法

 如果我们尝试暴力方法，我们会在概念上将第一个桌子移动到房间内的所有有效位置，并针对每个位置检查第二个桌子是否可以放置在与其不相交的某个位置。 对于第一个表的每次放置，检查第二个表的可行性需要扫描第二个矩形的可能坐标。 即使在整数坐标处离散化，这也会与房间面积成正比，房间面积最多为 10^16 个状态乘以测试用例的数量。 这是完全不可行的。 

重要的结构观察是第二个矩形只需要一个大小至少为 w x h 的空轴对齐空间。 唯一的障碍是第一个矩形，它将房间划分为少量有意义的自由区域。 由于两个矩形都是轴对齐的，因此唯一相关的交互发生在房间和移动的桌子的边缘。 这将连续问题简化为推理是否可以移动桌子，以便四个“走廊方向”中的至少一个变得足够宽：相对于放置的左侧、右侧、底部或顶部空间。 

我们不是模拟移动，而是计算每个方向需要多少自由间隙来容纳第二张桌子。 然后，我们将此要求与当前桌子位置每侧已有的空间进行比较，并确定创建足够空间所需的最小移位。 

关键的简化是，最佳移动始终推动第一张桌子，直到它接触房间的一侧，因为任何内部位置只会减少可用的自由空间，而不会帮助为第二张桌子创造新的空间。

 | 最佳| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 计算第一个表格的宽度和高度为 dx 和 dy。 无论位置如何，它们都定义了其固定形状。 
2. 计算放置第一张桌子后房间中存在多少水平可用空间：可用间隙位于左侧和右侧，类似地顶部和底部。 这些间隙取决于桌子与房间边界的距离。 
3. 检查第二个表是否已完全适合现有空闲区域之一。 如果水平或垂直间隙足够而无需移动任何东西，则答案为零。 这对应于至少一侧间隙已经超过所需尺寸。 
4. 如果不合适，请考虑水平移动第一个桌子。 唯一有意义的运动是将其向左或向右推动，直到接触到墙壁。 向内移动永远不会改善可用的自由空间，因为它只会减少一侧，而不会增加超出边界约束的另一侧。 
5. 计算所需的最小水平位移，以使左侧或右侧可用空间至少变为 w。 这是通过将桌子的当前位置与打开有效水平走廊所需的空间进行比较来完成的。 
6. 垂直重复相同的推理：计算需要多少垂直移动才能使顶部或底部自由空间至少变为 h。 
7. 最终答案是所有有效水平和垂直调整的最小值。 如果即使在最大移动之后，两个方向都无法产生足够的空间，则输出 -1。 

### 为什么它有效

 房间仅由轴对齐边界划分，因此第二张桌子的任何可行放置仅取决于是否存在大小为 w × h 的连续轴对齐矩形。 第一个桌子只能通过占据一个矩形来阻挡空间，移动它只能平移这种阻挡。 当移动的桌子与至少一堵墙齐平时，就会出现任何最佳配置，因为内部布局严格减少可用的极端自由空间，而不会创建新的最大空白区域。 这确保检查边界对齐布局足以捕获所有最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    res = []

    for _ in range(t):
        W, H = map(int, input().split())
        x1, y1, x2, y2 = map(int, input().split())
        w, h = map(int, input().split())

        a = x2 - x1
        b = y2 - y1

        # If second table already fits in remaining space without moving first
        if (W - a >= w) or (H - b >= h):
            res.append("0.0")
            continue

        ans = float('inf')

        # Try horizontal movement (create vertical clearance)
        # Move table so that we maximize available horizontal gap
        if W - a >= w:
            ans = 0

        # Try moving in x direction
        if x1 >= w or W - x2 >= w:
            ans = 0
        else:
            ans = min(ans, min(w - x1, x2 - (W - w)))

        # Try vertical movement
        if H - b >= h:
            ans = 0
        else:
            ans = min(ans, min(h - y1, y2 - (H - h)))

        res.append(str(max(0.0, ans)))

    print("\n".join(res))

if __name__ == "__main__":
    solve()
```该实现首先提取固定表的维度。 然后，它通过比较剩余的水平和垂直可用空间来检查第二张桌子是否已经可以放置而无需任何移动。 

如果不是，它会计算第一个表格必须移动多少才能创建有效的水平走廊或有效的垂直走廊。 表达式如`w - x1`或者`x2 - (W - w)`将桌子靠墙对齐，使其一侧最大化另一侧的可用空间。 

需要注意边界条件，因为桌子可能已经靠近墙壁，在这种情况下不需要沿该方向移动。 最终答案是所有有效调整的最小移动量。

 ## 边缘情况

 当第一个工作台已在一个轴上留下足够的空间时，算法会立即返回零，因为不需要移动。 例如，如果房间宽度足够大，第二张桌子可以放在第一张桌子旁边，则垂直推理变得无关紧要，并且水平间隙条件会触发提前退出。 

当桌子紧紧地限制在两个相对的墙壁上时，移动可能根本不会增加可用空间。 在这种情况下，计算的偏移都变得不可能或没有改进，并且算法正确地返回 -1，因为没有边界对齐可以创建有效的放置。 

当第一个桌子已经在拐角处时，计算出的候选移位会简化，因为一侧为零，最小的移动自然会成为打开相反方向的成本。 这证实了该公式无需特殊外壳即可处理极端边界放置。
