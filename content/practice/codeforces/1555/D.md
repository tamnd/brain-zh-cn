 ## 解决方案
 ## 问题理解

 我们得到一个仅由三个可能的字母组成的字符串。 对于任何子字符串，我们都可以更改字符，每次更改都会用三个字母中的任何一个替换一个字符。 目标是使子串“美丽”，这意味着它不能包含任何长度至少为 2 的回文子串。 

一个关键的观察是，超过三个字母的字符串可以包含长度至少为 2 的回文的唯一方法是包含两个相等的相邻字符，或者包含长度为 3 的窗口的第一个和第三个字符匹配的模式。 任何更长的回文都必然包含这两种模式之一。 因此，当字符串避免以下两个条件时，它就是美丽的：没有相等的邻居以及位置 i 和 i+2 之间不相等。 

因此，每个有效字符串必须满足严格的局部约束：对于每个位置 i，字符 i 必须不同于 i−1 和 i−2。 

每个查询都会询问：给定一个子字符串，需要进行多少次更改才能将其转换为满足这些本地约束的任何字符串。 

约束最多可达 200,000 个字符和查询，这会立即排除每个查询从头开始重新计算答案的可能性。 在最坏的情况下，对子字符串的任何每次查询扫描都会导致二次行为。 因此，我们需要一种表示形式，使我们能够在常数或对数时间内评估每个范围。 

一个微妙的边缘情况是，最佳解决方案取决于全局模式对齐，而不仅仅是局部不匹配。 例如，子字符串“aba”已经违反了条件，因为位置 1 和 3 匹配，即使没有相邻字符相等。 仅对对进行贪婪修复可能会错过此类依赖性，因为修复一个位置会改变未来的约束。 

## 方法

 一种幼稚的方法尝试独立地修复每个查询。 对于给定的子字符串，我们尝试通过从左到右扫描来构造有效的字符串，每当出现冲突时，我们都会更改当前字符。 这是正确的，因为一旦之前的字符被固定，每个新位置最多有两个禁用字母。 然而，为每个查询执行此操作的成本为 O(子字符串长度)，在最坏的情况下变为 O(nm)。 

关键的结构见解是，最终的有效字符串对索引奇偶校验模 3 具有重复依赖性。由于位置 i 处的字符仅受 i−1 和 i−2 约束，因此该过程的行为类似于仅具有三种状态的 DP：我们在 i 处放置的字母仅取决于前两个位置。 这意味着我们不需要考虑任意字符串，而只需要考虑由三个字母的排列形成的六种可能的周期模式。 

正好有3个！ = 6 个有效的基本模式，我们选择 {a, b, c} 的顺序并循环重复。 每个漂亮的字符串都必须在位置上匹配这些模式之一，因为任何偏差都会在本地窗口中引入禁止的相等性。 因此，对于任何子串，最佳答案是这六种模式中与子串不同的位置数中的最小值。 

我们可以为六种模式中的每一种预先计算不匹配前缀和，从而实现恒定时间查询评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 | 每个查询的暴力破解 | 每个查询 O(n) | O(1) | O(1) | 太慢了|
 | 预计算 6 模式 DP | 每个查询 O(1) | O(n) | 已接受 |

 ## 算法演练

 我们隐式构建六个参考字符串，对应于字母表 {a, b, c} 的所有排列。 每个引用都定义了索引的重复循环。

1. 生成这三个字母的全部 6 种排列。 每个排列定义整个字符串的候选目标模式。 
2. 对于每个模式，构建一个前缀不匹配数组。 在位置 i，我们存储 s[1..i] 中有多少个字符与模式在 i 处的字符不同。 这使我们能够在 O(1) 内计算任意间隔上的不匹配计数。 
3. 对于查询 [l, r]，使用前缀差异计算 6 个模式中每一个模式的不匹配成本。 答案是这六个值中的最小值。 
4. 输出每个查询的最小值。 

重要的推理步骤是任何有效的美丽字符串必须恰好是六个循环结构之一。 这会将所有有效字符串的指数搜索空间折叠成一组恒定的模板。 

### 为什么它有效

 任何超过三个字母且没有长度至少为 2 的回文子串的有效字符串不能具有相等的相邻字符，并且不能有 a[i] == a[i+2]。 这些约束迫使字符串形成严格的 3 周期结构。 一旦前两个字符被固定，接下来的每个字符都是唯一确定的，以避免重复它们中的任何一个。 这种确定性的传播意味着只存在六个全局结果，对应于前两个位置的初始选择，这恰好映射到字母表的排列。 因此，检查所有六种模式可以保证真正的最低编辑成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve():
    n, m = map(int, input().split())
    s = input().strip()

    alph = ['a', 'b', 'c']
    patterns = []

    for p in permutations(alph):
        patterns.append(p)

    # build prefix mismatch for each pattern
    pref = []
    for p in patterns:
        arr = [0] * (n + 1)
        for i in range(n):
            arr[i + 1] = arr[i] + (s[i] != p[i % 3])
        pref.append(arr)

    for _ in range(m):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        ans = n
        for k in range(6):
            cost = pref[k][r + 1] - pref[k][l]
            if cost < ans:
                ans = cost
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先枚举所有有效的循环模板。 对于每个模板，它都会构建一个前缀和数组，计算与输入字符串的不匹配情况。 然后，每个查询都会简化为这些前缀数组上的范围总和查询。 模 3 索引强制每个候选模式的重复结构。 

一个常见的错误是与“abcabc…”等单一固定模式进行比较，但这会错过最佳的重新标记。 这六种排列是必要的，因为字母的初始分配决定了整个结构。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from itertools import permutations

    input = sys.stdin.readline
    n, m = map(int, input().split())
    s = input().strip()

    alph = ['a', 'b', 'c']
    patterns = list(permutations(alph))

    pref = []
    for p in patterns:
        arr = [0] * (n + 1)
        for i in range(n):
            arr[i + 1] = arr[i] + (s[i] != p[i % 3])
        pref.append(arr)

    out = []
    for _ in range(m):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        ans = n
        for k in range(6):
            ans = min(ans, pref[k][r + 1] - pref[k][l])
        out.append(str(ans))
    return "\n".join(out)

2 3
""") == """1
2
0
1"""

# all equal
assert run("""3 1

""") == "1"

assert run("""3 1
abc
1 3
""") == "0"

1"""

 ## 边缘情况

 像“aa”这样的短子字符串测试解决方案是否错误地假设需要更长的模式。 正确的行为是一次更改就足够了，因为任何有效的模式都会在每一步中交替结构，因此必须立即纠正重复项。 

像“aaaaaa”这样完全统一的字符串强调解决方案是否可以处理最大重复。 每个位置至少与六个模式中的两个发生冲突，并且前缀减法必须正确累积不匹配，而不会出现溢出或相差一错误。 

像“ababab”这样严格交替的字符串验证并非所有交替结构都是有效的，只有那些与 3 周期一致的结构才保持最佳状态。 该算法正确地识别出完全对齐至少需要两次更改，而较小的子范围可能需要较少的编辑，具体取决于与周期阶段的对齐。
