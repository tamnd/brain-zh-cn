 ## 解决方案
 ## 问题理解

 该问题给出了三组平行线。 第一组包含水平线，第二组包含倾斜 60 度的线，第三组包含倾斜 120 度的线。 对于每条线，我们都知道它与 Y 轴相交的位置。 任务是计算每组中一条线有多少种不同选择创建了一个非退化等边三角形。 当所选择的三条线中至少有一条不同时，两个三角形被认为是不同的。 

几何形状得到了有用的简化。 来自不同组的任何三条线要么形成一个等边三角形，要么全部交于一点。 唯一不计算在内的三元组是并发三元组。 输入大小允许每组最多 5000 行，坐标可以大到 10^9。 直接检查每个三元组将需要多达 5000 立方 = 1250 亿次操作，这远远超出了程序在几秒钟内可以完成的操作。 我们需要将几何条件简化为更快的计数问题。 

棘手的情况是由多条线交叉在同一点引起的。 仅计算三元组总数的解决方案会将退化情况计为三角形。 

例如：```
2
0 0
2
1 1
2
1 1
```三元组的总数为 2 × 2 × 2 = 8。正确答案是 8，因为三条线的每一个选择都形成一个三角形。 重复的坐标并不意味着重复的线被删除，因为每条线都是一个单独的对象。 

另一个案例：```
1
0
1
0
1
0
```唯一选择的三条线都经过原点，因此它们不形成三角形。 答案是 0。组大小的简单乘法会错误地返回 1。 

## 方法

 一个简单的方法是尝试每一个可能的三重线。 对于每条水平线、每条60度线和每条120度线，我们可以计算它们的交点并检查它们是否并发。 这是正确的，因为每个可能的三角形都由一条三重线表示。 然而，每组有 5000 行，三元组的数量达到 1250 亿，使得这种方法变得不可能。 

关键的观察是并发具有简单的代数条件。 设水平线有Y截距`x`, 60 度线有 Y 截距`y`，并且 120 度线有 Y 截距`z`。 他们的方程是：```
Y = x
Y = sqrt(3)X + y
Y = -sqrt(3)X + z
```当以下情况时，最后两条线的交点恰好位于第一条线上：```
2 * x = y + z
```所以几何图形消失了。 我们只需要计算有多少个三元组满足这个方程。 

我们从所有可能的三元组开始，`a * b * c`。 然后我们减去并发三元组的数量。 为了有效地计算这些值，我们对两组中的对进行计数，并在第三组中查找匹配值。 

对于每个值`y`来自第二组和每个值`z`从第三组中，我们计算`y + z`。 具有价值的水平线`x`创建一个坏的三元组时`2*x = y+z`，因此我们存储第一组中的双倍值并计算匹配的总和。 由于最大的组大小为 5000，因此检查两个组之间的所有对最多需要 2500 万次操作，这非常合适。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(a·b·c) | O(a·b·c) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(a·b + a + b + c) | O(a · b + a + b + c) | O(a) | 已接受 |

 ## 算法演练

 1. 读取三组线截距。 存储水平线的双倍值，因为并发条件包含`2*x`。 
2. 计算可能的三元组总数。 每个方向每选择一条线都是一个候选三角形，因此初始值为`a * b * c`。 
3. 构建所有值的频率图`2*x`从水平线。 需要频率是因为多条线可能具有相同的截距，并且每条单独的线都会创建一个单独的可能的三元组。 
4. 迭代由一条 60 度线和一条 120 度线组成的每对线。 计算它们的总和`y + z`。 
5.添加频率`y + z`映射中无效三元组的数量。 每场比赛代表一条水平线，使三条线并存。 
6. 从三元组总数中减去无效三元组并打印结果。 

为什么有效：从不同方向选择的三条线要么是有效的等边三角形，要么是并发三元组。 该算法首先计算所有可能的三元组，然后使用导出方程精确计算不满足三角形条件的三元组`2*x = y+z`。 由于不存在其他类型的故障，因此删除这些情况将精确地留下三角形的数量。 

## Python 解决方案```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    a = int(input())
    first = list(map(int, input().split()))

    b = int(input())
    second = list(map(int, input().split()))

    c = int(input())
    third = list(map(int, input().split()))

    doubled = defaultdict(int)
    for x in first:
        doubled[2 * x] += 1

    bad = 0
    for y in second:
        for z in third:
            bad += doubled[y + z]

    answer = a * b * c - bad
    print(answer)

if __name__ == "__main__":
    solve()
```字典`doubled`存储有多少条水平线的每个可能值`2*x`。 这可以避免当多条线具有相同截距时丢失信息。 

嵌套循环仅遍历第二组和第三组中的对。 对于每一对，代码检查有多少水平线满足并发方程。 三元组总数的乘法使用 Python 整数，因此不必担心溢出。 

运算顺序很重要，因为在减法之前必须计算无效三元组。 最终答案是所有选择的数量减去折叠成单个交点的选择。

 ## 边缘情况

 对于```
1
0
1
0
1
0
```该地图包含`{0: 1}`。 成角度的线中唯一的一对有总和`0`，它与水平加倍值匹配。 该算法标记一个坏三元组，从一个可能的三元组中减去它，然后返回 0。 

对于```
2
0 0
2
1 1
2
1 1
```水平地图是`{0: 2}`。 每对有角度的线产生总和`2`， 不是`0`，因此不存在并发三元组。 答案依然存在`2 * 2 * 2 = 8`。 

一般来说，对于重复拦截，频率图是防止错误的部分。 如果三个不同的水平线具有相同的截距，则它们是三个单独的选择，并且当找到一对匹配的有角度的线时，每个选择都必须单独做出贡献。
