 ## 解决方案
 ## 问题理解

 该问题要求我们计算为形成一行的火柴棒着色的有效方法的数量`n`连接的正方形。 该行包含`n + 1`垂直棒和`2n`水平棍子。 当两根棍子在其中一个方块的一角相遇时，它们被认为是冲突的，因此冲突的棍子不能获得相同的颜色。 可用颜色的数量是`k`，并且答案必须以模计算`998244353`。 这是 Codeforces Gym 问题“Хорошие раскраски - 2024”。 

的价值`n`可以大到`10^18`，这立即排除了对正方形的任何模拟。 甚至一个`O(n)`动态规划解决方案是不可能的，因为操作数量将达到五千万亿左右。 解决方案必须将行的重复结构减少到较小的状态并使用快速求幂。 

颜色数`k`小于模数，但它仍然可以很大。 我们无法迭代颜色，因此解决方案必须仅使用涉及的算术表达式`k`。 

一个常见的错误是将正方形的所有四个边视为互不相同。 正方形的顶部和底部的木棍永远不会相互接触，左右垂直的木棍也永远不会接触。 只有同一正方形内的水平与垂直对才会产生限制。 

为了`n = 1`和`k = 5`，答案是`260`。 如果粗心地要求正方形的所有四个边都有不同的颜色，那只会算数`5 * 4 * 3 * 2 = 120`颜色，这是错误的，因为相对的两侧可能匹配。 

另一种边缘情况是相邻的垂直棒具有相同的颜色。 例如：```
n = 1
k = 3
```两根垂直的棍子可能都是红色的。 顶部和底部的棍子只需要避免红色，因此每个人都有两种选择，这种情况有贡献`4`的可能性。 假设相邻垂直棒必须不同的解决方案将丢失有效的颜色。 

## 方法

 直接的强力解决方案可以尝试对所有棒进行每种可能的颜色分配。 有`3n + 1`棍子，所以这大约需要`k^(3n+1)`尝试。 即使对于非常小的`n`，搜索空间呈指数增长，因此该方法仅作为理解结构的一种方式。 

有用的观察结果是，每个方块内的水平棒只关心与该方块接壤的两个垂直棒的颜色。 假设一个正方形的左右垂直棒有颜色`a`和`b`。 

如果`a = b`，每个水平棒有`k - 1`选择，所以正方形贡献`(k - 1)^2`。 

如果`a != b`，每个水平棒有`k - 2`选择，所以正方形贡献`(k - 2)^2`。 

整个问题变成了选择颜色`n + 1`垂直的棍子。 相邻垂直棒之间的每个过渡都有两个权重之一。 这是一个两种状态转换系统，因为我们只需要知道当前垂直颜色是否等于所选参考颜色或与之不同。 

让`same`是所有处理过的以固定颜色结尾的垂直序列的总权重，并让`diff`是以与该固定颜色不同的颜色结尾的总重量。 过渡是：```
new_same = same * (k - 1)^2 + diff * (k - 1) * (k - 2)^2
new_diff = same * (k - 2)^2 + diff * ((k - 2) * (k - 2) + (k - 2) * (k - 3))
```第二个公式计算与参考不同的一种特定颜色的过渡。 当前颜色可以通过两种方式与参考保持不同：它可以来自相同的先前颜色或来自另一种不同的颜色。 

因为我们需要应用这个转换`n`次和`n`很大，我们将其表示为矩阵并使用二进制求幂。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(k^(3n+1))`|`O(3n)`| 太慢了 |
 | 最佳 |`O(log n)`|`O(1)`| 已接受 |

 ## 算法演练

 1.固定一种颜色作为参考颜色。 最初，第一根垂直棒在一种状态下具有这种颜色，在另一种状态下具有不同的颜色。 这可以让我们避免存储所有可能的颜色。 
2. 建立一个`2 x 2`转移矩阵。 该矩阵描述了再添加一个方块如何改变这两种状态。 这些条目包含在处理完一个垂直边缘及其附加的水平棒后在状态之间移动的方式数量。 
3. 转换矩阵的幂`n`使用二进制求幂。 每次乘法都会使处理的平方数加倍，使我们能够处理`10^18`正方形。 
4. 将所得矩阵应用于初始状态向量。 两个结果状态的总和给出了完整着色的数量，其中最后一个垂直棒等于或不同于参考颜色。 
5. 将结果乘以`k`，因为参考颜色本身可以是任何可用颜色。 

该算法背后的不变性是在处理一定数量的方块后，`same`和`diff`准确地表示根据最后一个垂直棒与一个固定参考颜色之间的关系分类的部分着色的加权数量。 转换对每个可能的下一个垂直颜色精确计数一次，并添加正确数量的水平颜色选择，因此重复应用可以保留状态的含义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mul(a, b):
    return [
        [
            (a[0][0] * b[0][0] + a[0][1] * b[1][0]) % MOD,
            (a[0][0] * b[0][1] + a[0][1] * b[1][1]) % MOD
        ],
        [
            (a[1][0] * b[0][0] + a[1][1] * b[1][0]) % MOD,
            (a[1][0] * b[0][1] + a[1][1] * b[1][1]) % MOD
        ]
    ]

def mat_pow(a, e):
    res = [[1, 0], [0, 1]]
    while e:
        if e & 1:
            res = mul(res, a)
        a = mul(a, a)
        e >>= 1
    return res

def solve():
    n = int(input())
    k = int(input())

    x = (k - 1) % MOD
    y = (k - 2) % MOD

    a = x * x % MOD
    b = y * y % MOD

    trans = [
        [a, (k - 1) * b % MOD],
        [b, ((k - 2) * (k - 2) + (k - 2) * (k - 3)) % MOD]
    ]

    powered = mat_pow(trans, n)

    same = 1
    diff = 0

    end_same = (powered[0][0] * same + powered[0][1] * diff) % MOD
    end_diff = (powered[1][0] * same + powered[1][1] * diff) % MOD

    print((end_same + end_diff) % MOD * k % MOD)

if __name__ == "__main__":
    solve()
```乘法函数处理两个的乘法`2 x 2`矩阵模`998244353`。 由于矩阵大小是固定的，因此每次乘法都会花费恒定数量的运算。 

求幂函数是标准的二进制求幂。 它重复地对转换矩阵进行平方，并在当前位`n`已设置。 迭代次数与中的位数成正比`n`，最大输入约为 60。 

过渡值使用`(k - 1)^2`和`(k - 2)^2`因为每个方格都有两根独立的水平木棍。 第二行的表达式很容易出错，因为它计算了保持“与参考不同”状态的所有方式，而不仅仅是颜色变化的方式。

 ## 边缘情况

 对于单个正方形的情况：```
1
5
```该算法从一种参考颜色开始。 矩阵转换计算两个垂直棒匹配和不同的情况。 最终乘以`5`选择实际的参考颜色，产生`260`。 

对于相邻垂直棒共享颜色的情况：```
1
3
```转换保持匹配状态，因为允许相等的相邻垂直棒。 水平棒只需要避开该一种颜色，因此保留了该状态的贡献。 该算法从不假设相邻的垂直棒必须不同。 

对于最大可能的方块数：```
1000000000000000000
900000000
```矩阵求幂中的循环仅运行大约 60 次，因为它取决于`n`，不在`n`本身。 这避免了迭代计数的任何溢出并在所需的限制内完成。
