 ## 问题理解

 我们有一个花园，里面有两种花：白玫瑰和红玫瑰。 从这个花园中，我们希望通过选择任意数量的花朵（可能是全部或没有颜色）来形成花束。 

花束必须同时满足两个约束。 首先，所选花的总数必须至少达到给定阈值。 其次，所选择的鲜花中，红玫瑰的数量必须是奇数。 

对于每个测试用例，我们只询问是否可以选择这样的花子集，而不是如何构建它。 

关键是，我们不会重新排列任何东西或选择有序的结构，只是决定数量：在可用性的限制下，包含多少红玫瑰和多少白玫瑰。 

限制条件允许每种颜色最多有 10^18 朵花。 这立即排除了任何试图列举可能性或模拟选择的方法。 任何正确的解决方案都必须将问题减少到每个测试用例的算术检查次数恒定。 

一个微妙的失败案例来自于只贪婪地考虑达到最小尺寸。 例如，假设有足够的鲜花来达到所需的总数，但达到或超过阈值的唯一方法是强制使用偶数数量的红玫瑰。 在这种情况下，天真的“尽可能多地采取”的方法会错误地得出成功的结论。 

另一个特殊情况是根本没有红玫瑰。 例如，如果 w 很大且 r 为零，则任何花束都有零朵红玫瑰，这是偶数，因此无论总大小如何，它都会自动满足奇偶校验要求。 

同样，当只有一两朵红玫瑰时，平价可能会迫使我们留下一朵未使用，即使它有助于达到尺寸要求。 

这些观察结果已经表明问题在于将总大小的下限与一个组件的奇偶校验约束相结合。 

## 方法

 蛮力的想法是尝试花束中所有可能的红玫瑰数量，从 0 到 r，并且对于每个选择，决定是否可以使用白玫瑰填充花束的其余部分，同时遵守最小尺寸限制。 对于固定数量的红玫瑰 x，我们将检查 x 是否为奇数，以及 x 加上一定数量的白玫瑰 y 是否满足 x + y ≥ k 且 y ≤ w。 

这是有效的，因为它直接反映了问题的定义，但它太慢了。 在最坏的情况下，r 可能高达 10^18，因此迭代所有可能性是不可能的。 

关键的观察结果是结构非常简单：只有红玫瑰的奇偶性很重要，而白玫瑰只是达到所需总尺寸的灵活填充物。 一旦我们决定是否想要奇数朵红玫瑰，最佳策略始终是每种类型尽可能多地采摘有效的花朵。 

对于固定奇偶校验选择，我们能做的最好的事情就是在尊重约束的同时最大化总计数。 这将问题简化为检查至少两种情况之一的可行性：选择奇数个红色，或者因为在限制范围内不存在这样的奇数选择而失败。 

我们只需要知道是否存在一些奇数 x ≤ r 使得 k − x ≤ w 和 k − x ≥ 0。一旦我们意识到我们总是想要奇偶校验的最小有效调整，这就变成了一个简单的区间可行性检查。

 ## 算法演练

 我们分别对待红色和白色计数，并且仅根据总数和奇偶性进行推理。

1. 首先，我们检查是否可以总共采摘 k 朵花。 由于我们最多可以选取 w + r 朵花，如果 w + r < k，则无论奇偶性如何，都无法满足大小约束，因此答案立即是否定的。 
2.接下来我们重点满足奇红要求。 我们想知道是否存在数量为 x 的红色花朵，使得 x 为奇数，x ≤ r，并且我们仍然可以使用白色来达到总共 k 朵花朵。 
3. 如果我们采摘 x 朵红花，我们必须一起采摘 k − x 种白色和红色花朵，因此需要的白花数量为 k − x − x_red_pa​​rt，简化为 k − x ≤ w。 这意味着 x 必须满足 k − w ≤ x ≤ r。 
4. 所以我们要在区间 [max(0, k − w), r] 内寻找至少一个奇数整数 x。 
5. 如果存在这样的奇数，我们就可以构建一个有效的花束。 如果不是，答案是否定的。 
6. 为了测试区间中是否存在奇数，我们检查端点：如果下界是偶数，则如果它≤ r，我们可以使用它； 否则我们尝试下一个奇数。 

为什么它有效可以归结为分离约束。 总大小约束仅限制 w + r 之和，而白色填充的可行性将 x 限制为连续区间。 在任何整数区间内，奇偶校验约束简化为检查是否至少有一个奇数整数位于其中。 由于白花是完全灵活的，因此没有进一步的结构干扰这种区间推理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        w = int(input())
        r = int(input())
        k = int(input())
        
        if w + r < k:
            out.append("No")
            continue
        
        # we try to find an odd number of red flowers x
        # such that k - x <= w and 0 <= x <= r
        L = max(0, k - w)
        R = r
        
        # find first odd >= L
        if L % 2 == 0:
            x = L + 1
        else:
            x = L
        
        if x <= R:
            out.append("Yes")
        else:
            out.append("No")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码首先消除了即使拿走所有花也不够的不可能情况。 然后，它将问题简化为查找计算的可行范围内是否存在奇数整数。 唯一重要的实现细节是将下界正确地与第一个奇数候选对齐，因为跳过此步骤将错误地拒绝间隔从偶数开始但紧随其后包含奇数的有效情况。

 ## 边缘情况

 当没有红色花朵时，r = 0 强制任何花束中的红色计数为零，即偶数。 该算法正确处理了这个问题，因为可行区间 [max(0, k − w), 0] 不包含奇数，因此它立即返回“No”。 

当白花较多而红花较少时，例如w = 10^18且r = 1, k = 10^18，则区间变为[0, 1]。 第一个奇数候选值是 1，它在范围内，因此解正确接受。 

当最小要求比较严格时，例如k = w + r，算法简化为检查r本身是否为奇数，或者是否可以在满足可行性的情况下调整一个红色计数单位，这与区间逻辑完全匹配。
