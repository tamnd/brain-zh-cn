 ## 解决方案
 ## 问题理解

 我们被要求计算长度的排列$n$其中序列的最大公约数$1 \cdot p_1, 2 \cdot p_2, \dots, n \cdot p_n$严格大于 1。这里$p$是从 1 到 的整数的排列$n$。 简单来说，每个元素都乘以它的位置，我们希望所有这些乘积共享一个大于 1 的公因子。 

输入由多个测试用例组成，每个测试用例指定一个$n$。 输出是“美丽”排列模数$998244353$。 

约束条件允许$n$最多 1000 个和最多 1000 个测试用例。 生成所有排列的简单解决方案将会很复杂$O(n!)$，即使对于$n = 10$。 我们需要一种大致有效的方法$O(n^2)$或者$O(n \log n)$每个测试用例。 

很容易错过的边缘情况包括非常小的$n$。 为了$n=1$，唯一的排列是$[1]$，其中有$\gcd(1) = 1$因此并不美丽。 为了$n=2$，排列$[2,1]$有效是因为$\gcd(2,2) = 2 > 1$。 这些表明我们不能假设任何$n > 1$自动有解决方案。 

另一个微妙之处是，当可以重新排列序列以使所有产品都是偶数时，通常会出现美丽的排列。 这表明了一种组合模式，而不是单独检查每个排列。 

## 方法

 暴力方法会枚举所有$n!$排列和计算$\gcd(1\cdot p_1, \dots, n \cdot p_n)$对于每个。 这在原则上是正确的，因为它直接实现了问题陈述，但速度慢得令人绝望。 即使是为了$n=10$，这需要检查 360 万次排列，乘以$n$操作每$\gcd$计算远远超过允许的 1 秒运行时间。 

关键的见解是对于$\gcd$要超过 1，所有数字必须有一个公因数。 要考虑的最小素数是 2。如果我们能保证所有乘积都是偶数，则$\gcd$至少为 2。这导致了一个简单的构造：将偶数分配到使其乘积偶数的位置。 通过分析，我们可以推导出一个计算排列的递推式，其中前半部分数字占据偶数索引，后半部分占据奇数索引，调整为$n$是偶数还是奇数。 经过一些组合工作后，这简化为$(n//2)!^2$模数$998244353$对于甚至$n$, 0 表示奇数$n$。 

该观察依赖于奇数位置乘以奇数得出奇数乘积的事实。 因此，对于$n$奇数，至少有一个产品仍然是奇数，给出$\gcd$1.仅偶数$n$允许所有产品共享因子 2 的完整排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 最佳 | O(n + t) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算阶乘直至最大值$n$模数$998244353$。 这允许$O(1)$阶乘查找并避免对每个测试用例重新计算。 
2.读取测试用例数量$t$并迭代每个$n$。 
3. 对于每个$n$，检查是否为奇数。 如果是，则输出 0，因为至少有一个产品是奇数，并且$\gcd$将是 1。 
4.如果$n$是偶数，计算美丽排列的数量为$(n//2)!^2 \mod 998244353$。 这计算将下半部分数字分配给奇数位置并将上半部分分配给偶数位置的方法。 
5. 打印每个测试用例的结果。 

为什么它有效：不变的是我们保持所有产品都是偶数的属性当且仅当$n$是偶数并且数字是分布的，以便每个乘积至少包含一个偶数因子。 通过对阶乘进行平方$n/2$，我们分别考虑两半数字的所有有效重新排列。 没有其他安排可以产生更大的效果$\gcd$因为引入奇怪的产品会迫使$\gcd$降至 1。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAX_N = 1000

# Precompute factorials modulo MOD
fact = [1] * (MAX_N + 1)
for i in range(1, MAX_N + 1):
    fact[i] = fact[i-1] * i % MOD

t = int(input())
for _ in range(t):
    n = int(input())
    if n % 2 != 0:
        print(0)
    else:
        half = n // 2
        res = fact[half] * fact[half] % MOD
        print(res)
```该代码首先预先计算阶乘以避免重复计算。 对于每个测试用例，我们处理奇数$n$立即打印 0。对于偶数$n$，我们计算排列的每一半的阶乘乘积，对阶乘进行平方，因为两半的排列是独立的。 模数$998244353$确保我们不会溢出并符合问题要求。 

## 工作示例

 输入样本`4`：

 | n | n%2 | n%2 | 一半| 事实[一半] | 结果 |
 | ---| ---| ---| ---| ---|
 | 4 | 0 | 2 | 2 | 4 |

 解释：`n=4`是均匀的。 一半是2。`2! = 2`。 平方得到 4。有四种漂亮的排列：[2,1,4,3]、[2,3,4,1]、[4,1,2,3]、[4,3,2,1]（最多重新排序每一半）。 

输入样本`3`：

 | n | n%2 | n%2 | 结果 |
 | ---| ---| ---|
 | 3 | 1 | 0 |

 解释：`n=3`很奇怪。 任何排列在某处都有奇数积，gcd=1。 因此 0 个美丽的排列。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 998244353
    MAX_N = 1000
    fact = [1] * (MAX_N + 1)
    for i in range(1, MAX_N + 1):
        fact[i] = fact[i-1] * i % MOD
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n % 2 != 0:
            out.append("0")
        else:
            half = n // 2
            res = fact[half] * fact[half] % MOD
            out.append(str(res))
    return "\n".join(out)

 ## 边缘情况

 对于`n=1`，算法立即识别出`n%2==1`并输出 0。这可以正确处理最小的输入。 为了`n=2`,`n%2==0`, 一半=1,`1!*1! = 1`输出1，匹配单个美丽排列`[2,1]`。 为了`n=1000`，预先计算的阶乘允许我们计算`500!^2 % MOD`高效。 该算法明确处理奇数和偶数输入，因此奇数“n”没有排列
