 ## 解决方案
 ## 问题理解

 我们给出了一个隐藏的构造过程，该过程从某个区间的干净的连续整数段开始$[l, r]$。 Gojou 首先获取该区间内的所有整数，然后对它们进行任意打乱。 之后，他应用相同的未知 XOR 掩码$x$每个元素，产生我们观察到的最终数组。 

我们的任务是恢复任何有效值$x$可能会产生给定的最终数组，只知道$l$,$r$，以及生成的置换和异或数组。 

考虑变换的一个有用方法是原始多重集恰好是来自$l$到$r$，最终的多重集是通过将该集合的每个元素与固定隐藏值进行异或来获得的$x$。 排列步骤与值无关，只会破坏顺序。 

总体而言，约束非常严格，但每个测试用例的约束却并非如此。 每个值的边界为$2^{17}$，并且所有测试的元素总数也最多为$2^{17}$。 这立即表明，任何执行与值范围成比例的工作或在 17 位掩码上使用按位频率聚合的解决方案都是可行的。 每个测试用例的段长度的二次方总体上也很好，但每个测试用例重复的大量散列或排序是不必要的。 

一种幼稚的方法会尝试所有候选人$x$值高达$2^{17}$，将其应用于给定数组，并检查结果是否与以下排列匹配$[l, r]$。 那需要$O(2^{17} \cdot n)$每个测试用例已经处于临界状态，更糟糕的是，需要反复构建和比较多重集。 

如果试图贪婪地“对齐”元素，则会出现更微妙的失败情况。 由于 XOR 不保序且不单调，因此错误地配对元素仍然可能会意外匹配小示例中的值集，从而产生正确性的错误感觉。 

误导性贪婪想法的示例：

 输入：```
l=0 r=3
a = [1, 2, 3, 0]
```错误的尝试可能会尝试直接匹配最小元素并推断出每个位置不一致的 XOR，但正确的解决方案仅取决于多重集结构，而不取决于位置配对。 

关键的缺失观察是，对整个集合进行异或是 17 位整数空间中的全局按位转换。 这个结构足够坚固，我们可以恢复$x$通过分析整个域的频率对准而不是搜索。 

## 方法

 从直接解释开始。 我们知道应用 XOR 后$x$，生成的多重集必须等于：$$\{l \oplus x, (l+1) \oplus x, \dots, r \oplus x\}$$所以我们要寻找一个值$x$这样对给定的数组进行异或运算$x$精确产生区间$[l, r]$。 

蛮力的想法很简单。 对于每位候选人$x$, 变换每个元素$a_i \oplus x$并检查结果多重集是否等于$[l, r]$。 这是正确的，因为 XOR 是可逆的，因此有效$x$必须准确地重建原始区间。 

瓶颈在于检查每个候选人。 即使使用基于集合的检查，我们仍然需要$O(n)$每个候选人的工作量，并且有$2^{17}$候选人。 这导致大约$2^{17} \cdot 2^{17}$最坏情况下的操作太大了。 

结构上的见解是 XOR 独立于位起作用。 我们不是对完整值进行推理，而是比较整个 17 位空间上的频率分布。 如果我们预先计算目标间隔和给定数组的频率数组，那么正确的$x$必须满足：$$\text{freq}_A[v] = \text{freq}_B[v \oplus x]$$这正是异或卷积对齐条件。 我们可以使用按位属性计算正确的移位，而不是天真地测试所有移位：对于任何有效的映射，通过 XOR 移位整个频率数组必须完美对齐。 

由于域很小（$< 2^{17}$），我们可以枚举所有$x$但使用频率数组的单次传递来有效地验证它们，或者在 XOR 索引下预先计算频率分布的哈希值。 

更简单和标准的观察甚至可以避免完全验证：XOR 掩码是通过对齐任何单个元素来唯一确定的。 如果我们选择最小值$l$，那么在原始集合中它必须对应于某个元素$a_i \oplus x = l$，这意味着$x = a_i \oplus l$。 我们可以计算一个候选人$x$从一对中，然后在所有元素上验证它。 

这是有效的，因为原始集和最终集之间的映射是双射的，因此任何正确的配对都会产生相同的 XOR 值。

 ## 算法演练

 我们依赖这样一个事实：如果我们猜测一个原始值和一个观察值之间的正确对应关系，则 XOR 掩码是固定的。 

1. 构建目标间隔的频率计数器$[l, r]$。 这表示我们在反转 XOR 后必须匹配的多重集。 
2. 取任意元素$a_0$从给定的数组中尝试将其与某个值配对$v$在$[l, r]$。 这给出了候选掩码$x = a_0 \oplus v$。 这样做的原因是 XOR 是确定性的，因此一旦固定了一个对应关系，整个转换就固定了。 
3. 申请该候选人$x$到数组中的每个元素并计算$a_i \oplus x$。 
4. 检查生成的多重集是否与间隔频率完全匹配。 如果是，我们返回$x$。 
5. 如果失败，请尝试使用不同值进行另一次配对$v$从间隔到有效$x$被发现。 

更有效的实现可以通过修复来避免多次尝试$v = l$。 由于区间保证有效，因此数组中至少有一个元素对应于$l$，因此尝试从匹配中派生的所有候选者$l$对每个$a_i$保证快速成功。 

### 为什么它有效

 该变换定义了两个大小相等的多重集之间的双射。 这意味着每个原始值通过具有相同固定掩码的 XOR 精确映射到一个观察值$x$。 因此，选择任何正确的一对$(a_i, t)$在哪里$t \in [l, r]$立即判定真伪$x$。 只有正确的配对才能在全局应用时重现完整的间隔，而错误的猜测将导致验证失败，因为它们破坏了双射中的至少一个映射。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        l, r = map(int, input().split())
        n = r - l + 1
        a = list(map(int, input().split()))

        target = set(range(l, r + 1))

        # try pairing a[0] with every possible value in [l, r]
        # but in practice one of them will work immediately
        for v in range(l, r + 1):
            x = a[0] ^ v
            ok = True

            for i in range(n):
                if (a[i] ^ x) not in target:
                    ok = False
                    break

            if ok:
                print(x)
                break

if __name__ == "__main__":
    solve()
```该代码将预期间隔构建为快速成员资格检查的集合，然后尝试通过修复数组的第一个元素以对应于间隔中的某些候选值来确定 XOR 掩码。 一旦成为候选人$x$导出后，它验证对整个数组进行异或是否可以重建原始范围。 

一个微妙的点是我们只需要成员资格检查而不是排序或频率比较。 由于间隔是连续整数的排列，因此集合成员资格足以验证正确性。 

候选循环是安全的，因为所有间隔大小的总和是有界的，因此即使在最坏的情况下，我们也不会超出全局约束。

 ## 边缘情况

 一种边缘情况是当$l = r$。 间隔包含单个值，因此数组恰好有一个元素等于$l \oplus x$。 该算法尝试将该元素与$l$，生产$x = a_0 \oplus l$，它总是重建正确的值。 

另一种情况是数组已经与间隔相同。 然后$x = 0$是有效的。 验证步骤接受$x=0$立即，因为没有任何变换会改变区间中的成员资格。 

第三种情况是数组被反转或严重洗牌。 由于该算法从不使用排序，仅使用 XOR 后的成员资格，因此所有排列都会崩溃到相同的验证条件。
