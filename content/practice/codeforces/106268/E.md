 ## 解决方案
 ## 问题理解

 给我们一块边长为整数的矩形豆腐块$a$,$b$， 和$c$。 我们只能通过沿着平行于块面的平面完全切片来切割它，因此每次切割都会分裂它相交的所有部分。 在执行任意次数的此类切割后，我们最终将原始体积划分为轴对齐的矩形块。 

从这些片段中，我们至少想要获得$k$相同的立方体。 每个立方体必须具有相同的边长$x$，并且立方体必须仅使用面对齐切割从所得碎片中切割出来，这意味着每个立方体对应于一个完整的立方体$x \times x \times x$子块与原始轴对齐。 

目标是最大化$x$，并将其输出为约简分数。 

关键的解释是，一旦我们确定了候选立方体的边长$x$，我们可以获得的立方体的数量完全取决于有多少$x$- 长度段适合每个维度。 也就是说，沿着长度$a$，我们可以拟合$\lfloor a / x \rfloor$立方体，类似地$b$和$c$，所以总立方体为：$$\lfloor a/x \rfloor \cdot \lfloor b/x \rfloor \cdot \lfloor c/x \rfloor.$$我们需要最大的理性$x$使得该产品至少$k$。 

限制条件很大：$a, b, c, k \le 10^9$，直到$10^4$测试用例。 任何解决方案都必须$O(\log \text{range})$或每个测试用例更好。 对可能的情况进行简单的线性或枚举搜索$x$是不可能的。 

主要的边缘情况来自于答案不一定是整数这一事实。 例如，当$a=b=c=2$和$k=1$，答案是$2$，但是当$k=8$，答案就变成了$1$。 更有趣的是，当不可能精确平铺时，就会出现分数答案。 

一个微妙的陷阱是假设函数对于朴素舍入来说足够连续或平滑。 该函数是逐步常数，因此有很多值$x$产生相同的立方体数量，并且真正的最大值可能位于其中一个楼层分区发生变化的边界处。 

## 方法

 直接的方法是尝试所有可能的边长$x$从非常小的值到$\max(a,b,c)$。 对于每位候选人$x$，我们计算：$$\lfloor a/x \rfloor \cdot \lfloor b/x \rfloor \cdot \lfloor c/x \rfloor$$并检查是否至少是$k$。 这是正确的，因为它准确地模拟了构建过程。 然而，可能的范围$x$太大了。 如果我们尝试以单位粒度的整数步骤达到$10^9$，这已经超出了任何可行的时间限制，并且真正的答案通常是分数，这需要更细的粒度。 

关键的观察是立方体的数量是单调不增加的$x$。 如果我们增加立方体的大小，每个维度可以容纳的立方体就会减少，因此总乘积不会增加。 这种单调性使我们能够二分搜索最优实值$x$。 

对于固定的$x$，我们可以在常数时间内计算可行性，因此对实数（实现为有理数或足够精度）的二分搜索成为核心思想。 

但是，由于保证答案是有理数，因此我们可以通过隐式对分数执行二分搜索来避免浮动精度问题。 更清晰的视图是搜索$x$使用浮动边界作为实数，然后将最终结果转换为约简分数。 这种减少来自于观察到可行性变化的边界必须发生在一个有理值处，该有理值是通过除以以下之一得出的：$a,b,c$通过一个整数。 

这导致了标准的单调决策+二分搜索结构。

 | ---| ---| ---| ---|
 | 暴力枚举$x$|$O(\max(a,b,c))$每次测试|$O(1)$| 太慢了|

 ## 算法演练

 ### 可行性函数

 对于给定的候选立方体边$x$，我们计算可以形成多少个立方体：$$f(x) = \lfloor a/x \rfloor \cdot \lfloor b/x \rfloor \cdot \lfloor c/x \rfloor.$$我们检查是否$f(x) \ge k$。 

### 步骤

 1. 定义一个函数，给定$x$，返回是否至少$k$可以形成立方体。 这直接对构造约束进行编码。 
2. 寻找最大实数$x$使得该函数返回 true。 由于较大$x$总是减少或保留可行性，谓词是单调的，这允许二分搜索。 
3. 保持搜索间隔$[l, r]$， 在哪里$l$绝对可行并且$r$肯定是不可行的。 初始化$l = 0$,$r = \max(a,b,c)$。 
4. 反复平分区间并测试中点。 如果中点可行，则将下限上移； 否则将上限向下移动。 
5. 经过足够的迭代后，间隔足够小，足以代表精确的有理边界。 通过将最终实际值解释为可行性变化边界的有理近似值，将该值转换为与问题要求一致的分数形式。 

### 为什么它有效

 功能$f(x)$是单调非增的$x$。 一旦有一个值$x$太大而不允许$k$立方体中，任何更大的值都无法恢复可行性，因为每个楼层项只能保持不变或减少。 这保证了可行区域和不可行区域之间的单一过渡点。 二分搜索收敛到该阈值，而不会丢失最佳值可能所在的任何候选区域。

import sys
input = sys.stdin.readline

def can(a, b, c, x, k):
    return (a // x) * (b // x) * (c // x) >= k

def solve_case(a, b, c, k):
    lo, hi = 1, max(a, b, c)

    while lo <= hi:
        mid = (lo + hi) // 2
        if mid == 0:
            break
        if can(a, b, c, mid, k):
            lo = mid + 1
        else:
            hi = mid - 1
