 ## 解决方案
 ## 问题理解

 我们得到一个大整数$N$, 直至$10^{17}$。 我们可以把它分成两个正整数$a$和$b$这样$a + b = N$。 对于每个这样的分割，我们通过连接十进制表示形式形成一个新数字$a$紧接着是十进制表示形式$b$。 在所有可能的分割中，我们想要最大可能的连接值。 

这里的连接是纯粹的十进制字符串连接，所以如果$a = 92$和$b = 10$，结果是$9210$，不是算术表达式。 

输入大小的值非常大，但结构非常小，因为我们只得到一个数字。 这立即排除了任何试图枚举或构造与$N$。 甚至$O(N)$分割迭代是不可能的，因为$N$可以是$10^{17}$。 相反，我们必须推理最佳分割的结构。 

一个微妙的边缘情况是由于最佳分割并不总是靠近数字的中间或与数字平衡相关这一事实而产生的。 例如，在像 102 这样的小数字中，分割为 92 + 10 会产生比平衡分割（如 51 + 51 或 60 + 42）大得多的串联。这表明最大化串联在很大程度上取决于数字长度交互而不是数字接近度。 

另一个边缘情况是当$N$刚好高于十的幂边界。 改变数字长度的分割$a$或者$b$可以极大地改变串联幅度。 例如，从 99 移动到 100 完全改变了串联结构，因为数字计数发生了变化。 

## 方法

 蛮力方法尝试每一个有效的分割$a$从 1 到$N-1$，计算$b = N - a$，并通过字符串转换构造串联值​​。 这是正确的，因为它直接评估所有可能性，但它执行$O(N)$迭代，这是不可行的$N$最多$10^{17}$。 即使在概念上迭代该范围也是不可能的。 

关键的观察是串联的值主要取决于有多少位数字$a$和$b$具有，而不是算术意义上的精确平衡。 对于数字长度方面的固定分割位置，最佳候选者$a$是数字长度不超过的最大可能数字$N-1$。 一次$a$是固定的，$b = N - a$确定了，并且级联值就完全确定了。 

这表明减少：而不是迭代所有可能的值$a$，我们只需要考虑候选人$a$有特定的数字长度。 对于每个可能的长度$k$，我们尝试最大化$a$在这样的约束下$1 \le a < N$，并计算所得的串联。 自从$N$最多有 17 位数字，数字长度边界的数量是恒定的，因此我们只评估恒定数量的候选者。 

该优化之所以有效，是因为串联函数在每个数字长度类别中都是单调的$a$。 如果$a$在固定数字长度内增长，前缀和生成的串联都按字典顺序增长，因此最大值始终出现在该数字长度的可行性边界处。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(N)$|$O(1)$| 太慢了|
 | 数字长度候选人 |$O(\log N)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将这个问题视为探索所有有意义的方法来选择中的位数$a$，然后贪婪地最大化$a$每个选择下。 

1. 转换$N$转换为字符串，以便我们可以直接推断数字边界。 这可以避免算术溢出并使串联变得自然。 
2.让$s$是的字符串表示形式$N$，并让$d$是它的长度。 我们考虑候选者分裂，其中$a$有$k$数字，对于所有$1 \le k < d$。 案例$k = d$无效，因为$b$将为零或负数。 
3. 对于每个数字长度$k$，构造一个候选者$a_k$作为最大的数字$k$数字使得$a_k < N$。 这实际上是前缀$N$或稍小的数字（如果前缀等于或超过）$N$。 这一步保证了推送时的可行性$a$尽可能高。 
4.一次$a_k$确定，计算$b_k = N - a_k$。 这保证了分解约束的正确性。 
5. 通过将两个数字转换为字符串并连接它们来形成串联值。 跟踪所有候选人的最大值。 
6. 输出最大串联值。 

唯一微妙的决定是如何调整$a_k$当朴素前缀等于$N$或违反积极性$b$。 在这种情况下，我们减少$a_k$同时保留数字长度，因为减少了$a$略有增加$b$但保留了可行性。 

### 为什么它有效

 该算法依赖于这样一个事实：对于固定数字长度$a$，串联严格增加$a$，直到可行为止$b = N - a$休息。 因此，最优解必须是最大可行解$a$在每个数字长度类别内。 由于数字长度只有$O(\log N)$可能性，检查每个类别的一名代表可以捕获全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = str(n)
    d = len(s)

    best = 0

    for k in range(1, d):
        # largest k-digit number
        a = int("9" * k)
        if a >= n:
            a = n - 1

        b = n - a
        if b <= 0:
            continue

        cand = int(str(a) + str(b))
        if cand > best:
            best = cand

    print(best)

if __name__ == "__main__":
    solve()
```该代码迭代可能的数字长度$a$，为每个构建最大的可行候选，并评估生成的串联。 字符串操作是安全的，因为值最多有 17 位数字。 

一个微妙的点是对以下情况的处理：$9^k$超过或等于$N$。 在这种情况下，我们夹住$a$到$N-1$以保持有效性。 这确保了$b$保持正数并保持枚举的正确性。 

## 工作示例

 考虑$N = 102$。 

| k | 候选人 | b = N - a | 连接|
 | ---| ---| ---| ---|
 | 1 | 9 | 93 | 93 993 | 993
 | 2 | 99 | 99 3 | 993 | 993
 | 3 | 无效| - | - |

 最大值为 993，两者均达到$9 + 93$和$99 + 3$。 这表明多种数字长度选择可以得到相同的最佳值。 

现在考虑$N = 92$。 

| k | 候选人 | 乙| 连接|
 | ---| ---| ---| ---|
 | 1 | 9 | 83 | 83 983 | 983
 | 2 | 91 | 91 1 | 911 | 911

 最大值为 983，表明最佳分割不一定是使$a$单独数值尽可能大，而是平衡数字串联效应。 

这些示例表明，数字长度枚举就足够了，并且每个候选者都捕获了解决方案的不同结构体系。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(\log N)$| 我们最多测试每个数字长度的一个候选者$N$，每个人都不断努力|
 | 空间|$O(1)$| 只存储少数整数和最多 17 位的字符串 |

 运行时间很容易在限制范围内，因为$N$最多有 17 位数字，因此循环最多执行 16 次迭代。

 ## 边缘情况

 对于$N = 2$，唯一的分割是$1 + 1$。 该算法考虑$k = 1$, 构建$a = 1$，计算$b = 1$，并输出串联$11$，匹配唯一有效的配置。 

为了$N = 10$，数字长度循环评估$k = 1$。 候选人$a = 9$给出$b = 1$，生产$91$。 如果天真的方法只尝试平衡分割，它可能会错误地考虑$5 + 5$，这给出了$55$，缺少真正的最大值。 

为了$N = 100000000000000000$，算法仅迭代 17 次。 每次迭代最多对 18 位数字执行恒定时间字符串操作，因此它会立即完成，不会产生内存压力或溢出风险。
