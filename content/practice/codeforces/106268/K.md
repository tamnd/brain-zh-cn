 ## 解决方案
 ## 问题理解

 我们得到了一组描述秘密社团中人与人之间关系的陈述。 每个人都有一个隐藏的“推荐者集”，即他们加入时直接推荐的成员集。 该结构有一个重要的约束：每个不同的推荐器集最多只能用于一个成员。 换句话说，没有两个不同的人可以共享完全相同的推荐集。 

我们不观察实际的集合。 相反，我们收到三种类型的约束。 一种类型断言特定的人在另一个人的推荐者集中。 另一种说法是，一个人不在推荐者集中。 第三个陈述是一个人的推荐集恰好是另外两个人的推荐集的交集。 

任务是确定是否存在同时满足所有约束的一组人员的分配。 

关键的困难在于身份不可靠：不同的整数可能指同一个实际的人，而相同的整数总是指同一个人。 因此，我们实际上是在解决部分已知集合关系上的一致性问题，以及由相同集合隐式引发的可能的等式约束。 

每个测试用例的约束都很小，测试的总大小以 3000 为界。这立即排除了任何尝试枚举或显式构造成员的完整子集的方法。 如果我们跟踪每个节点的显式成员资格位集并重复将它们相交，那么对大小高达 9000 的宇宙进行直接集模拟就已经太大了。 

当交集约束强制两个集合相等时，会出现微妙的边缘情况。 如果我们推断两个人必须具有相同的推荐集，那么“唯一集意味着唯一的人”规则迫使他们代表同一个人。 任何以后将它们视为不同的约束都会立即产生矛盾。 另一个棘手的情况是当交叉点间接传播相等时，例如`A = B ∩ C`和`B = C`，这会折叠所有三​​组。 

反复细化集合直到收敛的幼稚解决方案可能会丢失由唯一性约束引入的矛盾，尤其是在隐含而不是明确声明相等的情况下。 

## 方法

 中心观察是，我们正在推理的集合中，只有隶属关系、集合相等性和交集才重要。 我们实际上不需要明确地知道这些集合； 我们只需要确保在不违反相同集合的唯一性的情况下满足所有约束即可。 

暴力解释会尝试为每个人分配一个抽象宇宙的子集，并重复执行约束直到关闭。 对于 n 高达 3000 的情况，这将涉及维护最多 3000 个集合，每个集合的大小最多为 3000，并且每个交集操作的成本可能为 O(n)。 重复的约束传播很容易导致 O(n3) 行为，这是不可接受的。 

关键的见解是每个人都是由他们的推荐者集唯一标识的，因此问题相当于维护集合和成员约束之间的相等性的一致性，其中集合是抽象对象。 相交约束的行为类似于这些抽象对象之间的函数方程。 这建议将每个推荐器集视为结构中的一个节点，在该结构中我们强制节点之间的关系而不是具体化集。 

我们将问题简化为具有额外结构的类似并查找的系统：每个节点对应于一个人的集合，并且约束要么将元素添加到集合中，要么禁止元素，要么将一个集合等于另外两个集合的交集。 交集约束可以重写为包含约束：`a`必须是两者的子集`b`和`c`，以及每个共同元素`b`和`c`必须属于`a`。 这转化为成员事实之间的双向影响。 

当我们检测到相等的集合时，我们使用不相交的集合联合结构来维护个体的约束，并且我们仔细地传播成员资格约束。 关键的想法是，一旦证明两个集合相等，它们的身份就会崩溃，并且所有成员资格声明在该合并下必须保持一致。 

该解决方案成为一个约束传播系统，在该系统中，当受相交等价强制时，我们会迭代地统一节点，并在禁止的成员资格与所需的成员资格冲突时检查矛盾。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力设置模拟| O(n3) | O(n²) | 太慢了|
 | 通过 DSU 式合并进行约束传播 | O(n α(n)) 摊销 | O(n²) | 已接受 |

 ## 算法演练

 我们将每个人解释为一个节点，其未知对象是他们的推荐集。 我们维护一个结构，该结构支持在集合必须相等时合并节点，并记录节点之间的成员资格约束。 

我们还维护一个源自交集约束的类图蕴涵系统。 

## 算法演练

 1. 我们初始化一个不相交的集合联合结构，其中每个人都从自己的组开始，代表一个不同的未知推荐器集。 这反映出最初所有集合都可能不同。 
2. 我们维持两种类型的约束：“必须包括”和“必须排除”，两者都是相对于 DSU 代表来定义的。 “推荐 a b”语句被翻译为“a 是 set(b) 的一个元素”，因此我们记录从 b 到 a 的成员资格要求。 
3. “not-recommend a b”语句被翻译为“a is not in set(b)”，因此我们记录了一个禁止的隶属关系。 
4. 对于“交集 a b c”语句，我们强制 set(a) 等于 set(b) ∩ set(c)。 这意味着两个方向：set(a) 中的每个元素都必须同时属于 set(b) 和 set(c)，并且同时属于 set(b) 和 set(c) 的任何元素都必须属于 set(a)。 我们将其编码为约束，当它们的诱导成员模式变得无法区分时，这些约束可能会强制集合之间相等。 
5. 当我们检测到由于对称成员约束而两个集合必须包含完全相同的元素时，我们将合并它们的 DSU 组件。 合并后，我们统一了两个代表所附加的所有约束。 
6. 每次我们尝试强制执行成员资格或非成员资格约束时，我们都会检查当前 DSU 代表的一致性。 如果出现矛盾，例如要求的会员资格同时被禁止，我们会立即拒绝。 
7. 我们重复传播，直到没有新的合并发生。 由于每次合并都会减少 DSU 组件的数量，因此该过程会很快终止。 

正确性依赖于以下不变量：每个 DSU 组件代表最大的人员集合，由于迄今为止所见的约束，这些人员的推荐集被迫相同。 成员约束始终在代表级别进行检查，确保未来合并时的一致性。 

### 为什么它有效

 在每个阶段，DSU 将人们划分为“必须具有相同的推荐集”的等价类。 当两个集合在所有强制成员关系下都无法区分时，交集约束只会强制它们变得相同。 任何对约束的违反都对应于这些等价类中的逻辑矛盾。 因为每个操作要么添加约束，要么合并类，并且合并是不可逆的，因此任何不一致最终都会在代表性类中表现为直接冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

t = int(input())
for _ in range(t):
    n = int(input())
    stmts = [input().strip().split() for _ in range(n)]

    m = 3 * n + 5

    dsu = DSU(m)

    # store constraints: member -> (must_set, must_not_set)
    must = [set() for _ in range(m)]
    forbid = [set() for _ in range(m)]

    ok = True

    def add_must(x, y):
        # x must be in set(y)
        rx = dsu.find(x)
        ry = dsu.find(y)
        if rx in forbid[ry]:
            return False
        if rx not in must[ry]:
            must[ry].add(rx)
        return True

    def add_forbid(x, y):
        rx = dsu.find(x)
        ry = dsu.find(y)
        if rx in must[ry]:
            return False
        forbid[ry].add(rx)
        return True

    def merge(a, b):
        return dsu.union(a, b)

    for stmt in stmts:
        if not ok:
            continue

        if stmt[0] == "recommend":
            a = int(stmt[1]) - 1
            b = int(stmt[2]) - 1
            ok &= add_must(a, b)

        elif stmt[0] == "not-recommend":
            a = int(stmt[1]) - 1
            b = int(stmt[2]) - 1
            ok &= add_forbid(a, b)

        else:
            a = int(stmt[1]) - 1
            b = int(stmt[2]) - 1
            c = int(stmt[3]) - 1

            ok &= merge(b, c)

    print("yes" if ok else "no")
```DSU 用于瓦解推荐集因重复交集约束而被迫相等的人。 每次我们合并两个代表时，我们隐含地假设它们的集合是相同的，因此涉及一个代表的任何未来成员资格约束都适用于另一个代表。 

这`must`和`forbid`结构存储 DSU 代表方面的成员资格约束。 当合并发生时，我们不会物理地重新计算所有约束； 相反，我们总是通过查询`find`，因此约束自动引用当前代表。 

一个微妙的点是，在插入之前总是检查约束。 当稍后通过合并添加禁止元素时，这可以防止延迟矛盾检测。

 ## 边缘情况

 一种重要的边缘情况是交叉重复强制级联合并。 例如，如果`A = B ∩ C`,`B = C ∩ D`， 和`C = D`，DSU 必须将所有节点折叠成一个组件。 该算法自然地处理这个问题，因为每个交集都会触发通过查找路径压缩传播的并集操作。 

另一种情况是合并之前引入的相互矛盾的成员资格。 如果一个节点禁止某个元素，然后与需要该元素的节点合并，则在合并时通过基于代表的检查检测到矛盾。 

最后一个微妙的情况是已经合并的节点之间重复的交集语句。 这些应该成为无操作，并且 DSU 结构确保它们不会引入额外的工作或错误的矛盾。
