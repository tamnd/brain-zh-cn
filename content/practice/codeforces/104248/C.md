 ## 解决方案
 ## 问题理解

 我们得到了几堆石头。 在每次移动中，玩家精确地选择一堆并从中移除任意正数的石子。 移走最后一块石头的玩家会输掉游戏而不是赢得游戏，这使得这是标准减法游戏的悲惨版本。 

这项任务是双重的。 首先，假设双方都处于最佳发挥状态，我们必须确定第一位玩家是否强制获胜。 其次，如果存在获胜策略，我们必须输出一个有效的第一步，这意味着选择哪堆棋子以及移除多少棋子，以使对手的位置进入失败状态。 

约束非常小：最多 100 堆，每堆大小最多 100。这立即排除了对状态的任何指数博弈树探索。 所有移除的完整极小极大将产生大量分支，因为每堆大小最多为 100 的每次移动最多允许 100 个选择，即使只有 100 堆，状态空间也会变得天文数字般大。 

微妙的边缘情况来自 Misère 规则。 在正常的 Nim 中，策略仅取决于堆大小的异或。 在这里，当所有牌堆大小均为 1 或几乎为空时，失败条件会发生变化。 例如，像这样的位置`1 1 1`与标准 Nim 的行为不同，因为被迫拿走最后一块石头的玩家输了而不是赢了。 

当所有桩都是相同的小值时，会出现另一种边缘情况。 例如，如果我们只有一堆尺寸为 1 的牌，第一个玩家必须拿走它，然后立即输掉。 如果不调整 Misère 规则，基于 XOR 的简单实现会错误地对此进行分类。 

## 方法

 暴力解决方案会将每个可能的游戏状态建模为游戏树中的节点。 从一个状态开始，我们通过拾取一堆并移除 1 和 ai 之间的棋子来尝试所有移动，递归地确定结果位置是赢还是输。 这在概念上是可行的，因为它探索了完整的游戏图，但它是完全不可行的。 

即使在大小为 100 的单堆中，这也已经创建了 100 个状态的链。 有了 100 个桩，分支就会在桩上成倍增加并移动选择，从而导致指数级爆炸。 最坏情况下的状态数量大约是石堆上所有石块的划分数量，这远远超出了任何计算极限。 

关键的观察结果是，该游戏是带有 Misère 规则的标准 Nim 变体。 在正常的 Nim 中，一堆的 Grundy 值就是它的大小，所有堆的 XOR 决定了获胜者。 唯一的修改发生在所有桩的尺寸均为 1 时，或者当我们将问题简化为仅包含单石桩的配置时。 

如果至少一堆的大小大于 1，则游戏的行为与正常 Nim 完全相同，因此所有桩大小的 XOR 决定结果。 如果 XOR 为零，则仓位丢失。 否则，存在使异或为零的举动，我们可以通过将一堆减少到所需的值来直接构造它。 

如果所有牌堆都恰好为 1，那么游戏就简化为简单的奇偶游戏。 每一步都会完全消除一堆，拿走最后一堆的玩家就输了。 因此，如果堆的数量是奇数，则第一个玩家输； 如果相等，则第一个玩家获胜。 

这将问题从指数搜索减少为单个线性扫描和一次异或计算。

 ## 算法演练

 我们根据所有桩的尺寸是否为 1 来不同地对待游戏。 

1. 扫描所有堆并检查每堆是否恰好有一颗石头。 

这种区别很重要，因为 Misère 规则唯一一次偏离正常的 Nim 就是在这种退化的情况下。 
2. 如果所有堆都是 1，则计算 n 是奇数还是偶数。 

如果n是奇数，则第一个玩家最终必须拿走最后一堆并输掉，因此该位置正在输。 如果 n 是偶数，则第一个玩家总是可以镜像移动。 
3. 如果全一条件成立且 n 为偶数，则输出获胜棋步：移走一整堆（任何索引，移走 1 个石子）。 

这会将计数减少到奇数，迫使对手处于失败位置。 
4. 否则，计算所有堆大小的 XOR。 

这是正常游戏的标准 Nim 不变量。 
5. 如果 XOR 为零，则输出“Lose”。 

在最佳游戏假设下，没有任何动作可以将零异或位置转换为另一个零异或位置。 
6. 如果 XOR 非零，我们构建获胜的棋步。 

找到一堆，减少它会使异或为零。 对于一堆 a[i]，我们计算 target = a[i] XOR xor_all，并删除 a[i] - 目标石子。 
7. 输出所选的桩指数和清除计数。 

### 为什么它有效

核心不变量是堆大小的 XOR 表征了正常 Nim 中的失败位置，唯一的例外是 Misère 游戏下的全 1 配置。 每个合法的移动都会改变一堆，并且 XOR 在此类更新下的表现是可预测的：将一堆从 x 翻转到 y 会将 XOR 从 X 更改为 X XOR x XOR y。 选择 y 使其等于 0 可以保证对手处于失败状态。 全一的情况是分开的，因为当所有堆都是相同的单例时，单独的 XOR 并不能捕获最后一步丢失规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    all_ones = all(x == 1 for x in a)

    if all_ones:
        if n % 2 == 1:
            print("Lose")
        else:
            print("Win")
            # remove one stone from any pile
            print(1, 1)
        return

    xr = 0
    for x in a:
        xr ^= x

    if xr == 0:
        print("Lose")
        return

    print("Win")
    for i, x in enumerate(a):
        target = x ^ xr
        if target < x:
            print(i + 1, x - target)
            return

if __name__ == "__main__":
    solve()
```该解决方案首先分离特殊的全 1 情况，因为 Misère 行为仅在此处有所不同。 然后它计算所有堆大小的异或。 如果 XOR 非零，我们搜索可以减少的一堆，使其新值等于`x XOR total_xor`，这保证了全局异或为零。 减去的金额正好是当前堆大小与该目标之间的差值。 

堆上的循环是安全的，因为当 XOR 非零时，必须存在至少一个有效的堆。

 ## 边缘情况

 一个重要的边缘情况是单堆尺寸为 1 的情况。 输入`1 / 1`立即触发全1分支。 该算法识别出 n = 1（奇数），因此输出“Lose”。 这符合第一个玩家必须拿走最后一颗石头并输掉的规则。 

另一种情况是当所有桩都是一个但 n 是偶数时，例如`1 1`。 该算法输出胜利并从第一堆中移除一颗石子。 此步之后，只剩下一堆，迫使对手平局。 

第三种边缘情况是混合配置，例如`1 1 5`。 XOR 不为零，因此该算法忽略全 1 快捷方式并使用正常的 Nim 逻辑。 它找到一堆（5）并减少它，使 XOR 变为零。 这是有效的，因为大于一个的堆的存在可以恢复标准的 Nim 结构，并且 Misère 复杂性不再适用。
