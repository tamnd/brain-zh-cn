 ## 解决方案
 ## 问题理解

 我们得到了一个有向图$n$每个顶点至多有一个出边的顶点。 每个顶点还带有一个小写字符标签。 一些顶点指向另一个顶点，而另一些顶点是终端并且不指向任何东西。 

如果确定性比较过程无法将两个顶点分开，则认为两个顶点无法区分。 该过程并行比较两个起始顶点：首先是它们的标签，然后是它们是否具有出边，如果两者都是终端，则它们立即被认为是相等的。 否则，如果两者都有传出边，则在其各自的传出邻居上递归地继续进行比较。 

关键思想是，如果当您重复跟踪传出边时，您始终看到相同的标签序列和结构选择直到终止，则两个顶点是等效的。 这使得问题本质上是通过顶点生成的链的“签名”对顶点进行分组。 

约束条件$n \le 10^5$排除任何成对比较方法。 比较所有对将是$O(n^2)$，甚至模拟比较也会太慢，因为每次比较都可能沿着长度链进行$O(n)$，在最坏的情况下给出立方行为。 

当多个顶点形成最终合并的长链时，就会出现微妙的边缘情况。 例如：

 输入：```
a 2
a 3
a 0
a 0
```顶点 2 和 3 都指向终端节点，但通过不同的路径。 仅比较直接邻居或仅比较标签的简单方法会根据实现细节错误地合并或分离它们。 正确的等价取决于传出路径的完整结构。 

另一个边缘情况是循环。 由于每个顶点至多有一个出边，因此循环是可能的。 在一个循环中，除非我们检测到状态的重复，否则比较永远不会自然终止。 简单的 DFS 比较将永远循环或错误地假设不等式。 

## 方法

 暴力方法试图通过模拟给定的过程来比较每对顶点。 对于每一对，我们沿着输出边缘同步行走，比较标签和结构。 如果我们遇到不匹配的情况，我们就会停止； 否则我们继续直到两条路径都终止。 

这在概念上是正确的，因为它直接反映了等价的定义。 然而，在具有链或循环的图中，单个比较可以遍历$O(n)$顶点。 对所有对执行此操作会导致$O(n^2)$比较，每个都可能$O(n)$， 导致$O(n^3)$最坏情况下的时间。 

关键的观察是每个顶点的结构完全由两个组成部分决定：其标签和其传出邻居的等价类。 如果两个顶点具有相同的标签，并且已知它们的传出邻居是等效的，那么这些顶点本身就变得等效。 终端顶点是没有出边的基本情况。 

这自然建议以反向依赖顺序处理顶点，但由于图可能包含循环，因此不存在简单的拓扑顺序。 相反，我们将每个顶点的“签名”视为递归定义的对象，并使用迭代散列和稳定计算等价类。 

我们为每个顶点分配一个签名，该签名由其标签和其传出邻居的当前类组成（或终端节点的特殊空值）。 然后，我们反复重新计算类，直到没有发生任何变化。 由于每次细化都严格划分或稳定状态空间，因此收敛发生在对数或近线性迭代中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力配对模拟 |$O(n^3)$|$O(n)$| 太慢了 |
 | 迭代签名细化|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将等价的递归定义压缩为顶点签名的迭代细化。 

1. 将每个顶点的类别初始化为 0。这表示在考虑结构之前，最初假设所有顶点都是相同的。 
2. 对于每个顶点，定义一个临时键，该临时键由其标签和其传出邻居的当前类组成，或者如果没有传出边，则定义一个特殊值。 这准确地编码了比较过程在递归一步中看到的内容。 
3. 对这些键进行排序或散列，以一致地分配新的类 ID。 具有相同键的顶点具有相同的类别。 
4. 重复步骤 2 和 3，直到班级分配稳定。 稳定性意味着没有顶点在迭代中改变其类，因此进一步的细化不会改变等价性。 
5. 输出最终的类ID。 

我们迭代重新计算的原因是传出邻居的类本身就是定义的一部分。 最初，我们不知道正确的等价性，因此我们开始粗略并逐步细化，直到完全捕获结构。 

### 为什么它有效

 不变的是，在每次迭代之后，如果两个顶点具有相同的计算类，那么它们的传出子结构在当前的细化深度之前是无法区分的。 每次迭代都有效地将沿传出边缘的“前瞻深度”增加一步。 由于每个顶点至多有一个出边，因此该结构是链和循环的集合，并且细化沿着这些结构确定性地传播。 一旦分区停止变化，类就会准确地编码由完全递归比较定义的等价关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
label = []
to = []

for _ in range(n):
    parts = input().split()
    label.append(parts[0])
    t = int(parts[1])
    to.append(t - 1 if t != 0 else -1)

cls = [0] * n

while True:
    keys = []
    for i in range(n):
        nxt = cls[to[i]] if to[i] != -1 else -1
        keys.append((label[i], nxt, i))

    keys.sort()

    new_cls = [0] * n
    cur = 0
    new_cls[keys[0][2]] = 0

    for i in range(1, n):
        if keys[i][0] != keys[i - 1][0] or keys[i][1] != keys[i - 1][1]:
            cur += 1
        new_cls[keys[i][2]] = cur

    if new_cls == cls:
        break
    cls = new_cls

print("\n".join(map(str, cls)))
```该代码构建初始图表示，将传出边转换为从零开始的索引。 每次迭代都会为每个顶点构造一个签名，结合其标签及其传出邻居的当前类别。 对这些签名进行排序会将相同的结构分组在一起，并相应地分配新的类 ID。 

终止检查会比较迭代之间的完整类数组。 一旦稳定，进一步的细化不会改变分组，所以我们停止。 

一个微妙的实现细节是在键元组中包含原始索引。 这确保了排序后稳定地分配回顶点。 没有它，我们将失去排序顺序和顶点标识之间的映射。 

## 工作示例

 ### 示例 1

 输入：```
a 2
b 3
b 0
b 3
```初始状态：

 | 顶点| 标签| 出 | 班级 |
 | ---| ---| ---| ---|
 | 1 | 一个 | 2 | 0 |
 | 2 | 乙| 3 | 0 |
 | 3 | 乙| - | 0 |
 | 4 | 乙| 3 | 0 |

 第一次迭代键：

 | 顶点| 关键|
 | ---| ---|
 | 1 | (a,0) | (a,0) |
 | 2 | (b,0) |
 | 3 | (b,-1) | (b,-1) |
 | 4 | (b,0) |

 排序后，类变为：

 | 顶点| 新班级 |
 | ---| ---|
 | 3 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 4 | 1 |

 第二次迭代使用更新的邻居类。 顶点 2 和 4 都指向 3，现在其类别为 0，因此它们的签名再次匹配为 (b,0)。 顶点 1 仍然不同，因为它指向具有不同细化结构的顶点 2。 稳定后，顶点 1、2、4 落入反映完整结构同一性的一致等价组。 

这表明平等不仅取决于标签，还取决于输出链的稳定结构。 

### 示例 2

 输入：```
3
a 2
a 3
a 1
```这就形成了一个循环：1→2→3→1。 

最初所有班级都是平等的。 第一次细化为所有顶点分配相同的键，因为所有标签都匹配并且所有邻居都具有类别 0。在任何迭代中都不会出现任何区别，因此算法立即稳定下来。 

这证实了当循环节点在该过程下结构对称时是等效的。

 ## 边缘情况

 一种边缘情况是所有顶点都是终端。 在这种情况下，每个顶点都没有出边，只有标签很重要。 该算法纯粹通过标签分配初始键，因此相同的标签立即形成组，并且在一次迭代中发生稳定。 

另一个边缘情况是一条以终端节点结束的长链。 例如，$1 \to 2 \to 3 \to 4 \to 5$。 等价性向后传播：节点 5 是基础，然后节点 4 依赖于它，依此类推。 迭代细化逐渐捕获这一点，确保不同深度的节点在其下游结构不同时接收不同的类。 

最后的边缘情况是一个循环馈送到链中。 由于每个顶点只有一条出边，因此这种结构很简单，但仍然需要在循环中传播终端区别。 一旦循环节点看到一致的下游类，细化过程就会稳定下来，确保正确分组。
