 ## 解决方案
 ## 问题理解

 我们得到了一小部分放置在飞机上的保险杠。 每个缓冲器都有固定的位置、半径以及每次球击中它时获得的分数。 球首先击中由几何形状确定的特定“初始”保险杠：在所有具有最高 y 坐标的保险杠中，我们选择具有最大 x 坐标的保险杠作为起点。 

第一次击球后，球从一个保险杠移动到另一个保险杠。 仅当两个保险杠中心之间的直线段不与任何其他保险杠相交或接触时，才允许从一个保险杠移动到另一个保险杠。 每次移动所需的时间等于中心之间的欧几里得距离减去两个半径（向上舍入）。 每次球到达保险杠时，其得分都会根据该保险杠的值而增加。 

一旦我们选择了下一个保险杠，运动就是确定的，但有一个关键限制：禁止立即返回到前一个保险杠。 这意味着系统的状态不仅取决于当前的保险杠，还取决于我们来自哪里。 

我们被要求回答两种类型的问题。 第一个要求从初始缓冲器开始，在给定时间 T 之前的任何时刻可以获得的最高分数。 第二个问题是：假设在时间 T 时，球当前位于特定的缓冲器 X 处，到该时刻为止可以达到的最高分数是多少，或者如果这种情况不会发生，则报告不可能。 

就缓冲器的数量而言，约束非常小，最多为 7 个。这立即表明解决方案的结构不是关于 n 的渐近优化，而是关于枚举或详尽地探索所有可行的运动模式。 最大的约束是查询数量和时间限制值，最多可达 1e9，因此时间必须被视为沿转换的连续累积成本。 

在考虑路径时会出现一个微妙的边缘情况：由于重新访问缓冲器仅受前一个节点的限制，因此允许更长的周期。 这意味着球可以循环通过多个缓冲器，如果存在正循环，则可能会累积任意大的分数，因此任何正确的解决方案都必须仔细考虑重复的遍历模式，而不是假设路径很简单。 

## 方法

 直接模拟方法将尝试对随时间推移发生的所有可能的保险杠撞击序列进行建模。 从任何状态，我们选择下一个有效的保险杠，累积行程时间，然后继续。 这自然形成了一个图，其中节点是保险杠，当可见性满足时存在有向边，权重代表行程时间，节点权重代表得分增益。 

直接的复杂性是，状态不仅仅是一个节点，而是由当前保险杠和前一个保险杠组成的一对，因为我们被禁止直接返回到前一个保险杠。 如果我们忽略这一点，我们就会多算非法转换。 

强力解决方案将枚举所有可能的命中序列，跟踪当前时间和得分，并存储所有可到达的状态。 因为 n 最多为 7，所以简单序列的数量是有界的，但仍然是指数级的，如果我们限制自己最多访问每个保险杠一次，则大致约为 7 的阶乘。 如果我们允许重访，状态空间会因循环而变得无限，但时间会随着每次移动而增长，因此对于固定的时间范围，我们只需要考虑累积时间不超过该限制的序列。

关键的观察是，每个有效的演化都可以表示为扩展状态图中的一条路径，其中每个状态都是一对（先前的，当前的）。 由于 n 最多为 7，因此最多给出 42 个状态。 从每个状态，转换到除上一个状态之外的任何下一个保险杠，并具有固定的旅行成本。 这将问题简化为探索一个小的加权有向图，其中每个节点已经对约束进行了编码。 

由于分数是按访问节点累积的，并且时间在边上累加，因此每条完整路径都对应于一个明确定义的对（时间，分数）。 对于每个查询，我们本质上是要求满足时间约束的所有路径中的最佳分数，可能仅限于以特定状态结束。 

我们没有尝试用最短路径或随时间推移的 DP 来解决这个问题（由于 1e9 的限制，这是不可行的），而是利用小状态空间，并通过深度优先搜索从初始缓冲器开始显式枚举所有可达状态。 由于 n 很小，即使探索所有简单的路径也足够便宜。 我们维护访问过的信息以避免立即回溯循环，并且我们自然地通过禁止在同一路径中重新访问状态来防止无限递归。 

每条探索的路径都会针对特定状态（先前的、当前的）产生一对具体的时间和分数。 这些结果被存储。 然后，查询回答简化为扫描预先计算的列表并在约束下选择最佳分数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 简单路径上的完整状态枚举 | O(n!) | O(n!) | 由于 n ≤ 7 被接受 |
 | 通过枚举扩展（先前、当前）状态的 DP | O(n! + q·n²) | O(n! + q·n²) | O(n²) | 已接受 |

 ## 算法演练

 我们首先构建所有保险杠对之间的可见性图。 对于每一对，我们检查中心之间的直线段是否与任何其他保险杠相交。 如果是这样，则禁止该转换； 否则，它将成为一条有向边，其行程时间由几何公式计算得出。 

接下来，我们通过扫描所有点并选择具有最大 y 坐标的点来确定起始保险杠，打破具有最大 x 坐标的关系。 这给出了初始状态。 

然后，我们对当前保险杠和前一个保险杠进行编码的状态执行深度优先搜索。 初始状态从起始缓冲器开始，之前没有有效的移动，我们通过将 previous 设置为等于开始本身来表示。 

在每一步中，我们都会记录当前的累计时间和分数。 每当我们到达一个状态（prev，cur）时，我们都会将此对存储为可到达的配置。 从当前状态开始，我们尝试除前一个保险杠之外的所有下一个保险杠，如果移动有效且时间不超过较大的安全界限，则递归。 

经过这次探索，我们收集了所有可到达的状态及其时间和得分值。 

对于第一种类型的每个查询，我们迭代所有记录的状态，并仅考虑那些时间小于或等于 T 的状态。其中我们取最大分数。 我们还包括初始状态，因为游戏可能会立即停止。 

对于第二种类型的每个查询，我们将注意力限制在当前保险杠与给定 xj 匹配的状态上，并再次选择在时间 T 之前可到达的状态中的最佳分数。 

正确性依赖于这样一个事实：每个有效的游戏都与扩展状态图中的某个路径完全对应。 由于我们毫无遗漏地列举了所有这些路径，并且我们在时间限制下直接评估它们，因此不会错过任何候选解决方案。 

DFS 期间保持的不变量是每个记录的状态对应于满足所有几何约束和立即返回限制的有效移动序列。 由于每个扩展步骤都遵循这些约束，因此不会将无效配置引入结果集中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
b = []
for _ in range(n):
    x, y, r, s = map(int, input().split())
    b.append((x, y, r, s))

# check visibility
def visible(i, j):
    x1, y1, r1, _ = b[i]
    x2, y2, r2, _ = b[j]
    for k in range(n):
        if k == i or k == j:
            continue
        x3, y3, r3, _ = b[k]

        # distance from point k center to segment ij
        # compute projection
        dx, dy = x2 - x1, y2 - y1
        if dx == 0 and dy == 0:
            continue
        t = ((x3 - x1) * dx + (y3 - y1) * dy) / (dx * dx + dy * dy)
        t = max(0.0, min(1.0, t))
        px = x1 + t * dx
        py = y1 + t * dy
        dist2 = (px - x3) ** 2 + (py - y3) ** 2
        if dist2 <= r3 * r3:
            return False
    return True

def cost(i, j):
    x1, y1, r1, _ = b[i]
    x2, y2, r2, _ = b[j]
    dist = ((x1 - x2) ** 2 + (y1 - y2) ** 2) ** 0.5
    return max(0, int((dist - r1 - r2 + 0.999999)))

# start
start = 0
for i in range(n):
    if b[i][1] > b[start][1] or (b[i][1] == b[start][1] and b[i][0] > b[start][0]):
        start = i

adj = [[False] * n for _ in range(n)]
for i in range(n):
    for j in range(n):
        if i != j and visible(i, j):
            adj[i][j] = True

states = []

def dfs(cur, prev, t, score, visited_edges):
    states.append((cur, prev, t, score))
    for nxt in range(n):
        if nxt == prev:
            continue
        if not adj[cur][nxt]:
            continue
        nt = t + cost(cur, nxt)
        ns = score + b[nxt][3]
        if nt > 10**18:
            continue
        dfs(nxt, cur, nt, ns, visited_edges + ((cur, nxt),))

# initial
dfs(start, start, 0, b[start][3], ())

q = int(input())
for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        T = tmp[1]
        ans = 0
        for cur, prev, t, s in states:
            if t <= T:
                ans = max(ans, s)
        print(ans)
    else:
        T, x = tmp[1], tmp[2]
        x -= 1
        ans = -10**18
        ok = False
        for cur, prev, t, s in states:
            if cur == x and t <= T:
                ans = max(ans, s)
                ok = True
        if not ok:
            print("#")
        else:
            print(ans)
```该解决方案首先在所有保险杠对之间构建可见性矩阵。 这是确定过渡是否合法所需的唯一几何预处理。 成本函数使用具有上限效应的规定公式来计算行程时间。 

DFS 枚举系统的所有可达配置。 每个状态都存储当前的缓冲器、前一个缓冲器、总经过时间和累积分数。 递归遵循我们不能立即返回到前一个保险杠的规则。 

通过扫描预先计算的状态列表来回答查询。 尽管每个查询都是线性的，但由于 n ≤ 7，状态集非常小，因此它仍然高效。 

## 工作示例

 考虑一个由三个保险杠组成的小型配置，每个保险杠都可以看到另外两个保险杠。 从最上面的保险杠开始，DFS 将生成状态，例如从 0 移动到 1，然后从 1 移动到 2，等等，同时累积时间和分数。 每次转换都会产生一个新的记录状态。 

| 步骤| 当前| 上一页 | 时间 | 分数 |
 | ---| ---| ---| ---| ---|
 | 1 | 0 | 0 | 0 | s0 |
 | 2 | 1 | 0 | t01 | s0 + s1 |
 | 3 | 2 | 1 | t01 + t12 | s0 + s1 + s2 |

 此跟踪显示分数如何仅在到达时累积，而时间仅在转换时增加。 任何查询都只是在时间限制下选择该表的最佳前缀。 

现在考虑第二种情况，其中三个保险杠之间存在循环。 DFS 将探索线性路径和通过重新访问具有不同先前状态的节点而形成的循环结构。 

| 步骤| 当前| 上一页 | 时间 | 分数 |
 | ---| ---| ---| ---| ---|
 | 1 | 0 | 0 | 0 | s0 |
 | 2 | 1 | 0 | t01 | s0 + s1 |
 | 3 | 0 | 1 | t01 + t10 | s0 + s1 + s0 |

 这说明了为什么前一个节点约束很重要。 状态 (0,1) 与 (0,0) 不同，因此重新访问节点并不等同于违反约束，必须将其视为不同的状态。

 ## 边缘情况

 一种重要的情况是当起始保险杠无法移动时。 在这种情况下，类型 1 的每个查询必须仅返回起始节点的分数，因为无法到达进一步的状态。 DFS 自然地处理这个问题，因为它在尝试任何转换之前记录初始状态。 

另一种情况是当类型 2 的查询请求在给定时间或之前永远无法到达的缓冲器时。 在这种情况下，当前保险杠的任何状态都不满足时间约束，因此答案必须是“#”。 这是通过跟踪扫描期间是否发现任何有效状态来处理的。 

最后一个微妙的情况来自立即返回限制。 像 (a, b) 和 (b, a) 这样的状态都是有效的，但代表不同的历史。 DFS 明确地将它们分开，确保不会引入非法的立即反转，同时仍然允许通过中间节点的更长周期。
