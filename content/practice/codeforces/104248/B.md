 ## 解决方案
 ## 问题理解

 我们被要求计算使用前 m 个小写拉丁字母可以形成多少个长度为 n 的字符串，以满足特定的周期约束。 

约束由固定偏移 k 定义。 对于从 1 到 n − k 的每个位置 i，位置 i 处的字符必须与位置 i + k 处的字符不同。 换句话说，如果您查看字符串并将每个位置与前 k 步的位置进行比较，则这些对都不允许匹配。 

这创建了一个位置由距离 k 连接的结构。 与其将字符串视为单行，不如将其视为通过对 k 取模索引形成的 k 个独立列更有用。 每个这样的列的行为就像一个链，其中相邻元素（以 k 为步长）必须不同。 

约束很小：n ≤ 40、m ≤ 8、k ≤ 8。这立即告诉我们，位置上的指数或状态压缩方法是可行的。 即使 O(n·m^k) 或 O(m^n) 也是不可接受的，但是任何分解为 k 个小的独立子问题或在位置和前 k 个字符上使用 DP 的方法都是可行的。 

当 k ≥ n 时会出现微妙的边缘情况。 在这种情况下，根本没有任何约束，因为不存在满足 i + k ≤ n 的索引 i。 那么答案应该是 m^n。 任何在不检查这一点的情况下盲目应用转换的解决方案仍然有效，但某些 DP 公式如果假定存在依赖关系，则可能会意外地低估。 

另一个不明显的角点是当 k = 1 时。那么每个相邻对都必须不同，这是标准的“没有两个连续的相等字符”问题。 任何错误地假设模 k 位置之间的独立性而不仔细处理 k = 1 的方法可能仍然有效，但它会严重影响 DP 转换，并且是一个很好的健全性检查。 

## 方法

 暴力方法很简单：生成长度为 n 超过 m 个字符的每个可能的字符串，并检查它是否满足 k 差约束。 对于每个字符串，我们扫描从 1 到 n − k 的所有 i 并验证 s[i] ≠ s[i + k]。 在最坏的情况下，这会花费 O(m^n · n) 时间，因为有 m^n 个字符串，并且每次验证都会花费线性时间。 当 n = 40，m 达到 8 时，这是一个天文数字，完全不可行。 

关键的观察结果是约束仅连接由 k 分隔的位置。 这意味着位置 i 只与 i − k 和 i + k 相互作用，因此结构根据残基类别以 k 为模分成独立的链。 每个链都是一个序列，其中连续元素必须不同。 一旦我们修复了一条链的分配，它就不会影响其他链。 

因此，我们不是全局考虑 n 个位置，而是按 i mod k 对索引进行分组。 对于每个残基类别 r，我们考虑序列 r、r + k、r + 2k 等。 每个这样的序列都是独立的，其行为就像较短长度上的简单“不相等相邻”约束。 然后我们将所有 k 个链上的有效序列的数量相乘。 

这将问题简化为计算对于每个长度为 L 的链，用 m 个字母填充它以使相邻元素不同的方法的数量。 这是一个标准的线性动态规划，其中第一个元素有 m 个选择，接下来的每个元素有 (m − 1) 个选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(m^n · n) | O(m^n · n) | O(n) | 太慢了 |
 | 模块化链条 DP | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立地处理每个残数类模 k 并将结果相乘。

1. 根据位置索引模 k 将位置分成 k 组。 每个基团形成一条链，如 r、r + k、r + 2k 等。 这是有效的，因为约束仅连接距离恰好为 k 的索引，因此不同组之间不会发生交互。 
2. 对于每个组，计算其长度 L。这是满足 i ≤ n 且 i == r (mod k) 的索引 i 的数量。 群的结构就变成了长度为L的简单序列。 
3. 计算使用 m 个字母填充长度 L 链的方式有多少种，使得相邻位置不同。 我们将 dp[j] 定义为填充链的前 j 个元素的方式数。 
4. 初始化 dp[1] = m，因为第一个位置可以是 m 个字母中的任何一个。 
5. 对于每个 j ≥ 2 的下一个位置，选择一个与前一个不同的字母。 如果前一个位置有 m 个选择，则每个选择都允许下一个位置有 (m − 1) 个选择，因此 dp[j] = dp[j − 1] · (m − 1)。 
6. 将 dp[L] 乘以每个组的全局答案。 

最终结果是所有 k 组的乘积。 

### 为什么它有效

 核心不变量是每个模类形成一个独立的链，其中约束仅与该链中的连续元素相关。 一旦我们以一个组的固定分配为条件，就不会再有任何约束跨越到另一个组，因为任何禁止对 i 和 i + k 都保持在同一残基类别内。 因此，全局配置空间分解为独立链配置的笛卡尔积，并且分别对每个链进行计数并相乘，得到有效序列的总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    # answer is product over k independent chains
    ans = 1

    for r in range(k):
        # compute length of this residue class
        length = 0
        i = r + 1
        while i <= n:
            length += 1
            i += k

        if length == 0:
            continue

        # first position: m choices, rest: (m-1) choices each
        if length == 1:
            ways = m
        else:
            ways = m * (m - 1) ** (length - 1)

        ans *= ways

    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循分解为残差类。 对于每个类，我们通过步长 k 逐步遍历索引来显式计算其长度。 考虑到约束（n ≤ 40），这是安全的，并且避免了对算术公式的任何需要，尽管也可以使用整数除法来计算长度。 

每个链都使用封闭形式 m·(m − 1)^(L − 1) 进行评估，这是因为第一个元素是自由的，并且每个后续元素仅排除前一个值。 

一个常见的陷阱是忘记不同的残基类别是独立的。 另一个错误是将公式 m·(m − 1)^(n − 1) 应用于整个字符串，这是错误的，因为邻接仅存在于链内，而不存在于整个序列中。

 ## 边缘情况

 对于 k ≥ n，除了可能的一个之外，每个残基类的长度都是 0 或 1。该算法自然地处理这个问题，因为每个链根据长度贡献 m 或 1，并且不会引入无效约束。 

当 k = 1 时，整个序列变成单链，公式简化为 m·(m − 1)^(n − 1)。 该算法没有对此进行特殊处理，它直接从残差类构造中产生。 

对于 m = 1，任何长度大于 1 的链都会产生零路，因为 (m − 1) = 0。这是正确的，因为距离 k 处没有两个位置可以相等，因此任何长度 ≥ 2 都不可能。
