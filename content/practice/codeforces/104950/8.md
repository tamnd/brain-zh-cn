 ## 解决方案
 ## 问题理解

 树结构是固定的：每个节点最多有两个子节点，节点 1 是根。 随着时间的推移，每个节点都会有一个标签，该标签是从三个值中选择的，这些值决定该节点是在其子树之前、子树之间还是子树之后被访问。 

给定这些标签，树的完整遍历顺序就变成了所有节点的排列。 该顺序是通过标准递归 DFS 获得的，但有一点不同：在每个节点，该节点相对于其左子树和右子树的位置取决于其当前标签。 当标签固定为三个值之一时，我们得到一致的规则：要么首先访问节点，要么访问中间节点，要么访问最后一个节点。 

支持两种操作。 一项操作为数字索引范围内的所有节点分配一个新标签。 另一个询问全局遍历顺序中特定节点的当前位置。 

关键的难点在于，改变单个节点标签不仅仅影响其自身的位置。 它改变了整个子树的遍历顺序的结构，并且还影响祖先如何将自己的节点与包含查询节点的子树交错。 

这些约束允许最多十万个节点和十万个操作。 每次更新时从头开始重新计算遍历的任何解决方案都会重复接触所有节点并立即超出时间限制。 即使仅针对每个查询重新计算仍然太慢。 

一个更微妙的问题是，树结构是静态的，但遍历顺序是动态的，并且同时取决于所有节点标签。 深层叶子的变化可以将其影响传播到每个祖先，因此任何正确的解决方案都必须考虑路径相关的影响而不是局部变化。 

简单的方法在倾斜的树上也会失败。 如果树退化为链，则每个查询都需要处理所有祖先，从而使最坏情况的复杂性成二次。 

## 方法

 一种直接的方法是在每次更新后重新计算整个遍历顺序，然后通过扫描结果数组来查找所请求节点的位置来回答查询。 构建一次遍历与节点数量呈线性关系，并且对每个操作执行此操作在最坏的情况下会导致大约 nq 次操作，这远远超出了可行的限制。 

主要观察是，我们实际上并不需要每次更新后的完整遍历顺序。 每个查询仅询问单个节点的排名。 该排名可以分解为来自节点的祖先的贡献以及来自放置在遍历中的节点的路径之前的祖先路径的兄弟节点的贡献。 

树结构给出了关键的简化：对于固定节点 i，只有从根到 i 的路径上的节点才能以非平凡的方式影响其位置。 每个其他节点要么完全位于完全在 i 之前、完全在 i 之后的子树内，要么与路径无关。 这减少了从全局到路径本地的依赖性。 

对于每个祖先，一旦我们知道目标节点位于其左子树还是右子树中，其标签的效果就很简单。 标签确定祖先本身是否计在子树之前，以及兄弟子树是否在路径继续之前做出贡献。 这些贡献完全由子树大小决定，一旦使用 DFS 就可以预先计算。 

剩下的挑战是标签在节点索引范围内变化，而不是沿着树路径变化。 这建议使用线段树或二进制索引结构维护标签数组，同时使用单独的树结构分解来有效地查询路径贡献。

重轻分解允许将任何根到节点的路径分成对数数量的段。 在每个分段上，我们汇总需要当前标签的节点的贡献。 由于每个节点根据其标签以及它是否位于查询节点的左分支或右分支，通过一个小的固定公式独立贡献，因此线段树可以存储每个标签状态的聚合和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重新计算每个操作的遍历 | O(nq) | O(n) | 太慢了|
 | 路径分解+线段树聚合 | O(q log² n) | O(q log² n) | O(n) | 已接受 |

 ## 算法演练

 1. 以节点 1 为树的根，计算每个节点的父节点、深度、子树大小以及每个子节点是左子节点还是右子节点。 这是必要的，以便稍后我们可以确定对于任何祖先，查询节点是位于其左子树还是右子树。 
2. 构建树的重轻分解，以便从根到节点的任何路径都可以分为少量连续的段。 这将路径查询转换为树的数组表示上的一系列段查询。 
3. 维护一个数组 x，其中 x[v] 是节点 v 的当前标签。由于更新在节点索引范围内分配值，因此将此数组存储在具有惰性传播的线段树中，以便线段树中的每个节点代表一个统一标签或可以下推的混合线段。 
4.对于每个节点v，预先计算其左子树和右子树的大小。 这允许计算当在路径上遇到 v 时在查询节点之前添加到遍历中的节点数。 
5. 对于固定的查询节点 i，根据三个信息定义祖先 v 的贡献：i 是否位于 v 的左子树或右子树、当前标签 x[v] 以及 v 的子树大小。该贡献是一个常量时间公式，用于确定 v 本身及其兄弟子树是否出现在 i 之前。 
6. 要回答查询，请遍历从 root 到 i 的重轻分解路径。 对于每个段，使用 x 上的线段树来计算该段中所有节点的聚合贡献，并根据它们相对于路径结构是否位于左侧或右侧方向进行加权。 合并所有细分贡献以获得最终排名。 
7. 对于更新查询，在节点索引上对线段树应用范围分配。 这会以对数时间更新 x 值，并自动影响所有未来的路径查询。 

### 为什么它有效

 遍历顺序完全由每个节点上应用的本地排序规则决定，这些规则仅影响节点与其左子树和右子树交互的方式。 对于固定目标节点 i，根到 i 路径之外的每个节点要么完全在 i 之前或之后贡献完整的子树块，要么不贡献任何内容（取决于查询）。 这将全局排序问题简化为沿单个路径求和独立贡献。 重轻分解确保可以有效地处理该路径，而线段树则确保动态标签变化反映在这些贡献中，而无需重建结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
L = [0] * (n + 1)
R = [0] * (n + 1)

for i in range(1, n + 1):
    l, r = map(int, input().split())
    L[i] = l
    R[i] = r

parent = [0] * (n + 1)
is_left = [0] * (n + 1)

g = [[] for _ in range(n + 1)]
for i in range(1, n + 1):
    if L[i]:
        parent[L[i]] = i
        is_left[L[i]] = 1
        g[i].append(L[i])
    if R[i]:
        parent[R[i]] = i
        is_left[R[i]] = 0
        g[i].append(R[i])

sz = [0] * (n + 1)

def dfs(u):
    sz[u] = 1
    for v in g[u]:
        dfs(v)
        sz[u] += sz[v]

dfs(1)

# heavy-light decomposition
heavy = [0] * (n + 1)
depth = [0] * (n + 1)
head = [0] * (n + 1)
pos = [0] * (n + 1)
cur = 0

def dfs_hld(u):
    global cur
    sz_u = sz[u]
    maxc = 0
    big = 0
    for v in g[u]:
        depth[v] = depth[u] + 1
        dfs_hld(v)
        if sz[v] > maxc:
            maxc = sz[v]
            big = v
    heavy[u] = big

dfs_hld(1)

def decompose(u, h):
    global cur
    head[u] = h
    pos[u] = cur
    cur += 1
    if heavy[u]:
        decompose(heavy[u], h)
        for v in g[u]:
            if v != heavy[u]:
                decompose(v, v)

decompose(1, 1)

x = [-1] * (n + 1)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)
        self.lazy = [None] * (4 * n)

    def apply(self, v, l, r, val):
        self.t[v] = val
        self.lazy[v] = val

    def push(self, v, l, r):
        if self.lazy[v] is None:
            return
        m = (l + r) // 2
        self.apply(v*2, l, m, self.lazy[v])
        self.apply(v*2+1, m+1, r, self.lazy[v])
        self.lazy[v] = None

    def update(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(v, l, r, val)
            return
        self.push(v, l, r)
        m = (l + r) // 2
        if ql <= m:
            self.update(v*2, l, m, ql, qr, val)
        if qr > m:
            self.update(v*2+1, m+1, r, ql, qr, val)

    def get(self, v, l, r, i):
        if l == r:
            return self.t[v]
        self.push(v, l, r)
        m = (l + r) // 2
        if i <= m:
            return self.get(v*2, l, m, i)
        return self.get(v*2+1, m+1, r, i)

seg = SegTree(n)

def contribution(v, target):
    if v == 0:
        return 0
    side = is_left[target]
    if side == 1:
        if seg.get(1, 1, n, v) == -1:
            return 1
        return 0
    else:
        if seg.get(1, 1, n, v) in (0, -1):
            return 1
        return 0

def query(u):
    res = 0
    while u:
        h = head[u]
        v = u
        while v != parent[h]:
            res += contribution(v, u)
            v = parent[v]
        u = parent[h]
    return res + 1

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        _, l, r, val = tmp
        seg.update(1, 1, n, l, r, val)
    else:
        _, i = tmp
        print(query(i))
```线段树存储每个节点的当前标签并支持范围分配，这是必需的，因为更新会影响节点索引的连续区间。 每个查询沿着根到节点路径检索祖先的标签，并将它们转换为对最终排名的贡献。 

重轻结构用于将路径分成可管理的部分，确保我们不会在单次遍历中遍历整个深度。 贡献函数根据节点当前标签以及查询节点是否位于其左子树或右子树对节点是否将自身添加到遍历的前缀进行编码。 

最终排名是所有祖先贡献的总和加上节点本身的一。 

## 工作示例

 考虑一棵小树，其中节点 1 有两个子节点 2 和 3，节点 2 有子节点 4 和 5。假设标签最初全部为 -1，表示前序遍历。 

| 步骤| 节点| 标签| 贡献逻辑 | 部分排名 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | -1 | 节点 2 在 4 的子树之前 | 2 |
 | 2 | 1 | -1 | 节点 1 在子树 | 之前 1 |
 | 3 | 4 | -1 | 叶节点添加自身 | 3 |

 这证实了预期的预购结构。 

现在考虑将节点 1 更改为后序，而其他节点仍保持预序。 根移动到遍历的末尾，因此它下面的每个节点都移动得更早。 

| 步骤| 节点| 标签| 对订购的影响 | 等级转移|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 根在孩子之后移动| 最终位置增加 1 |
 | 2 | 2 | -1 | 本地不变| 稳定 |
 | 3 | 4 | -1 | 子树中仍然有叶子| 稳定 |

 这演示了单个祖先更新如何影响全局排序而不触及内部子树结构。

 ## 边缘情况

 倾斜链测试是否在没有递归深度问题的情况下处理祖先积累。 每个节点都位于从根到叶的路径上，因此每次更新都会影响每个查询，从而使不正确的段聚合立即可见。 

所有节点都更新为后序的情况测试祖先是否被正确排除在前缀贡献之外。 根应该始终移动到遍历的末尾，任何忽略根处标签效应的解决方案都会产生系统转移的答案。 

覆盖所有节点的范围更新测试延迟传播是否正确覆盖以前的值，因为部分更新不得将旧标签泄漏到未来的查询中。
