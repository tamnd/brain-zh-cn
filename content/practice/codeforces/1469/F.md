 ## 解决方案
 ## 问题理解

 我们给出了几个线性链，每个线性链只是一个简单的路径图。 从这些链中，我们可以将其中一些附加到从单个白色根顶点开始的生长树上。 每次附加一条链时，我们都会选择该链的一个顶点并将其连接到当前树的现有白色顶点。 这个新连接的端点和链内选定的顶点都变成黑色，链中的其他所有内容都保持白色。 

目标是构造一棵至少包含 k 个白色顶点的树。 在所有这些构造中，我们关心从根到第 k 个最近的白色顶点的距离，并且我们希望最小化这个距离。 

被优化的关键对象不是树本身的形状，而是白色顶点按距根的距离的分布。 一条链提供了一组结构化的潜在白色顶点，其深度不断增加，具体取决于我们如何附加它。 

约束条件很大，n 高达 2⋅10^5，k 高达 10^9。 这立即排除了任何尝试显式模拟树或枚举顶点的解决方案。 任何有效的方法都必须将每个链减少到少量的摘要信息，并对聚合贡献使用贪婪或二分搜索推理。 

一个天真的错误是假设附加更长的链总是有直接帮助，或者链的所有顶点贡献相同。 例如，如果 k 很小但链很长，天真的贪婪者可能会通过假设整个链保持白色来过多计算浅深度的白色顶点，这是不正确的，因为每条链恰好有一个附着点将其一部分变成黑色。 

另一个微妙的边缘情况是当 k 大于可能的白色顶点总数时。 由于每个链仅根据附件贡献有限数量的可用白色顶点，因此有时即使使用所有链也是不够的，答案必须为 -1。 

## 方法

 蛮力的想法是考虑选择链的所有方法，选择每个链内的附着点，并构建结果树，然后计算到所有白色顶点的距离。 这显然是链数量的指数，因为每个链都可以使用或不使用，并且如果使用，附着位置会改变白色顶点沿树的分布。 即使忽略附着位置，仅子集选择也会给出 O(2^n)，这对于 n 高达 2⋅10^5 来说是不可能的。 

关键的观察结果是，每条链在连接时都会对可到达的白色顶点产生非常结构化的单调效果。 一旦连接了一条链，恰好有一个顶点成为连接点，并且链中该点之外的所有内容就距根部的距离而言都是“上方”，而距离较近的所有内容都因变黑而实际上被浪费了。 这意味着每条链都可以被视为产生一段可用的白色顶点，其贡献可以通过成本效益曲线来概括：在一定的距离阈值下我们获得了多少白色顶点。 

我们没有构建树，而是颠倒了视角。 假设我们固定一个距离限制 D 并问：我们能否确保距离 ≤ D 时至少有 k 个白色顶点？ 如果我们能回答这个问题，那么我们就可以二分搜索最小的 D。对于固定的 D，每个链要么贡献可以放置在深度 D 内的所有顶点，要么根据我们附加它的位置部分贡献。 固定 D 的最佳策略是贪婪的：我们总是以最大化距离 D 内的白色顶点数量的方式附加链。这将每个链简化为 D 及其长度的简单函数。 

这将问题转化为排序和贪婪地累积贡献，以在 D 上的二分搜索中进行可行性检查。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集和附件的暴力破解 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 二分查找+贪心可行性| O(n log n log n) | O(n log n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先将任务重新表述为关于候选答案 D 的决策问题，即到第 k 个白色顶点的最大允许距离。 

1. 我们在 [1, max(l_i)] 范围内二分搜索 D。 目标是找到最小的 D，以便我们可以获得距根距离 D 内至少 k 个白色顶点。 这是有效的，因为如果一个配置适用于 D，它也适用于任何更大的 D。 
2. 对于固定的 D，我们计算可以使多少个白色顶点位于距离 D 内。每个长度为 L 的链根据其连接方式做出贡献。 如果我们附加它，使其一部分顶点位于距离 D 内，那么我们能做的最好的事情就是选择一个附加点，使落在距离限制内的顶点数量最大化。 
3. 对于长度为 L 的链条，考虑我们沿链条选择切割位置 t。 切口的一侧变得更靠近根部，另一侧变得更远，但只有一个端点用于附着，因此实际上我们只能保留可用白色顶点的连续部分。 固定 D 的最佳贡献取决于如果我们对其进行最佳对齐，可以将链的多少个顶点放置在距离 D 内。 
4. 我们为每个链计算它在距离 D 内可以贡献的最大顶点数。我们收集所有正贡献，对它们进行排序，并首先贪婪地获取最大的贡献，直到达到 k 或耗尽所有链。
 5、如果贡献之和至少达到k，则D可行； 否则就不是。 
6. 我们对最小可行 D 进行二分搜索。 

### 为什么它有效

 关键的不变量是，对于固定的 D，每个链的行为都是独立的：它对可达白色顶点计数的贡献仅取决于 D 及其长度，而不取决于对其他链所做的选择。 这种独立性来自于树结构是非循环的并且附着点仅影响局部距离的事实。 因此，最大化距离 D 内的白色顶点总数可以简化为独立地最大化每个链的贡献并对它们求和。 首先贪婪地选择贡献较大的链是最优的，因为贡献是累加的，并且链之间没有交互惩罚。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(D, a, k):
    gains = []
    total = 0

    for L in a:
        if D <= 0:
            continue
        # maximum usable segment we can fit within distance D
        # optimal contribution behaves like taking best placement of chain
        # effectively we can "center" the chain around attachment
        gain = min(L - 1, D)
        gains.append(gain)

    gains.sort(reverse=True)

    for g in gains:
        total += g
        if total >= k - 1:
            return True
    return False

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # impossible even in best case
    if sum(L - 1 for L in a) + 1 < k:
        print(-1)
        return

    lo, hi = 1, max(a)

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, a, k):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```二分查找超出了答案距离。 可行性检查将每条链转换为简单的上限贡献。 表达式`L - 1`反映了每条长度为 L 的链只能贡献根连接结构之外的 L-1 个附加顶点，因为一个端点变黑并且不贡献为可用的白色顶点。 

里面`can`，我们估算每条链上有多少个顶点可以放置在距离 D 内。贪婪累积确保我们总是更喜欢在约束下可以贡献更多白色顶点的链，这与链的独立性相一致。 

早期的不可能性检查确保即使使用所有链也无法到达 k 个白色顶点时，我们不会进行二分搜索。 

## 工作示例

 考虑一个具有长度链的小实例`[4, 3]`和`k = 3`。 

我们测试候选 D = 2。 

| 链条| 左 | D 内增益 | 运行总计 |
 | ---| ---| ---| ---|
 | 1 | 4 | 2 | 2 |
 | 2 | 3 | 2 | 4 |

 我们至少达到 k-1 = 2 个额外的白色顶点，因此 D = 2 是可行的。 

这演示了如何将每个链简化为简单的有界贡献并贪婪地组合。 

现在考虑`[3, 3, 3]`,`k = 5`，D = 1。 

| 链条| 左 | D 内增益 | 运行总计 |
 | ---| ---| ---| ---|
 | 1 | 3 | 1 | 1 |
 | 2 | 3 | 1 | 2 |
 | 3 | 3 | 1 | 3 |

 我们无法达到 k-1 = 4，因此 D = 1 不可行，迫使距离更大。 

这些痕迹表明可行性如何仅取决于总体贡献，而不取决于结构。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log max l_i) | O(n log max l_i) | 距离上的二分搜索，每次检查对 n 个贡献进行排序 |
 | 空间| O(n) | 存储每张支票的收益 |

 约束最多允许 2⋅10^5 条链，因此每次可行性检查进行排序是可以接受的。 二分搜索深度约为 18 次迭代，使解决方案很好地保持在时间限制内。

 ## 边缘情况

 当使用所有链几乎无法实现 k 时，就会出现一种边缘情况。 在这种情况下，二分搜索收敛到接近最大链长度的值。 可行性检查仍然表现正确，因为每个链最多贡献 L−1，并且总和条件精确地捕获了严格的可行性。 

另一种边缘情况是当所有链都很短且 k 很大时。 例如，许多长度为 3 且 k 接近 2⋅10^9 的链。 初步检查`sum(L - 1) + 1 < k`立即触发，防止不必要的计算。 

第三种情况是一条很长的链支配所有其他链。 贪心选择确保该链在可行性检查中始终被优先考虑，因为它的增益在任何 D 下都是最大的，因此较小链的结构不会扭曲决策。
