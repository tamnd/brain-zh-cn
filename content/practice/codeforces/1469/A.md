 ## 解决方案
 ## 问题理解

 我们得到一个仅由三种字符组成的短字符串：左括号、右括号和问号。 不同的是，字符串不是固定的，因为每个问号都可以独立地成为左括号或右括号。 两个特殊的事实大大简化了结构：字符串恰好包含一个固定的左括号和一个固定的右括号，而其他一切都是灵活的。 

任务是决定是否存在任何方法来替换所有问号，以便得到的序列是正确的括号序列。 正确的序列意味着，如果我们将其解释为括号，则每个前缀的左括号至少与右括号一样多，并且总数完全匹配，因此最终余额为零。 

尽管每个测试用例的输入看起来很小，但测试用例的数量可能很大。 每个字符串长度最多为 100，因此每个测试用例的任何二次或更差的解决方案都已经是安全的，而如果我们尝试直接探索所有问号分配，则任何指数都会太慢。 

一个立即失败的天真的想法是暴力破解每一个问号的替换。 如果有 k 个问号，则有 2^k 种可能性。 当 k 达到大约 100 时，这将变得非常大。 即使我们修剪掉无效的前缀，分支仍然太大而无法在限制内处理。 

另一个微妙的失败案例来自于仅根据局部平衡贪婪地将每个问号分配为打开或关闭。 例如，尽早决定前缀“需要”右括号可能会导致稍后当剩余后缀无法正确平衡时陷入死胡同。 这表明不考虑全局结构的局部贪婪决策是不安全的。 

关键的缺失结构是只有两个固定锚：一个保证打开，一个保证关闭。 这意味着答案主要取决于这两个锚点是否可以以允许将序列分割成有效的前缀后缀结构的方式定位，并具有从问号到填补空白的足够灵活性。 

## 方法

 暴力方法为每个问号分配“(”或“)”，然后使用线性扫描检查结果序列是否有效。 这是正确的，因为它直接模拟了问题的定义。 然而，如果有 k 个问号，它会评估 2^k 个字符串，每次有效性检查的成本为 O(n)，从而使总复杂度为 O(n·2^n)。 即使对于中等的 n 来说，这也是无法使用的。 

关键的观察是我们实际上不需要独立决定每个角色。 有效的括号序列必须保持前缀平衡，并且由于所有不确定性都集中在问号中，因此唯一有意义的问题是我们是否可以在某个点之前分配足够的左括号并在其之后分配足够的右括号。 

固定的开括号和闭括号有效地将字符串划分为一个结构，我们只需要确保它们周围的序列可以平衡。 该条件简化为检查交换两个固定锚点是否会破坏维持前缀平衡的能力。 具体来说，如果我们假设固定的“(”必须位于固定的“)”之前，我们可以尝试验证该字符串是否有效； 如果它们的相对顺序错误，则这是不可能的，因为问号的分配无法在不违反前缀约束的情况下修复该倒置。 

因此，整个问题简化为检查字符串中唯一的“(”和“)”的相对位置。

 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 扫描字符串并记录唯一左括号和唯一右括号的索引。 

我们需要他们的位置，因为其余的角色是灵活的，不会直接限制结构。 
2. 检查左括号是否出现在右括号之前。 

这个条件很重要，因为任何有效的括号序列都必须有一个前缀，在我们开始过量消耗右括号之前，左括号的容量可用。 
3. 如果左括号出现在右括号之后，则立即返回NO。 

在这种情况下，即使问号的最佳放置也无法对固定结构进行重新排序，因此无效性是不可避免的。 
4. 否则，返回YES。 

当左括号较早时，我们总是可以分配问号来平衡固定位置前后的前缀。 

### 为什么它有效

 有效的括号序列必须具有以下属性：在每个前缀处，左括号的数量至少是右括号的数量。 固定的左括号保证可以尽早创建一些正平衡，而固定的右括号则强制稍后至少减少一个。 如果右括号出现在左括号之前，则存在一个前缀，无论我们如何分配问号，都已经违反了所需的平衡条件，因为没有问号可以改变这两个固定约束的顺序。 如果左括号较早，我们总是可以选择保持前缀可行性的问号分配，直到遇到右括号，然后完成平衡。 所有其他位置的灵活性确保不会出现额外的结构限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    
    open_pos = -1
    close_pos = -1
    
    for i, ch in enumerate(s):
        if ch == '(':
            open_pos = i
        elif ch == ')':
            close_pos = i
    
    if open_pos < close_pos:
        print("YES")
    else:
        print("NO")
```该代码首先标识唯一有保证的左括号和右括号。 然后它直接比较他们的位置。 这是有效的，因为所有其他字符都是灵活的，并且不能强制执行比这两个锚点的相对顺序更强的任何排序约束。 

一个微妙的一点是我们根本不尝试分配问号。 这是有意为之的：它们唯一的作用是提供冗余，并且它们对可行性的限制绝不会超过固定对已经造成的限制。

由此可见关键失效模式：固定结构颠倒无法修复。

 ## 边缘情况

 关键的边缘情况是两个固定括号相邻但顺序错误。 例如，输入`)(??`。 该算法立即记录 open_pos > close_pos 并返回 NO。 这是正确的，因为即使存在问号，第一个字符也已经违反了前缀有效性。 

另一种情况是问号在字符串中占主导地位，例如`??(??)?`。 这里 open_pos 仍然在 close_pos 之前，所以算法返回 YES。 这是有效的，因为始终可以分配问号以保持前缀平衡，直到到达固定的右括号，然后完成序列。 

最终的边缘情况是最小的有效配置`()`。 扫描发现 open_pos = 0 且 close_pos = 1，因此条件成立并立即返回 YES，与常规括号序列的定义匹配。
