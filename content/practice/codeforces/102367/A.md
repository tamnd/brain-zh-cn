 ## 解决方案
 ## 问题理解

 我们需要将一块蛋糕切成少量整数重量的块。 客人的数量事先是未知的：正好是（A）、（B）或（C）。 对于这三种可能性中的每一种，每件物品都必须有一个预定的接收者，并且在分发所有物品后，每位客人必须收到完全相同的总重量。 

输出通过四个数字描述每个物理块。 首先是它的重量。 其他三个数字表示当有 (A)、(B) 或 (C) 客人时谁收到该作品。 在这三种情况下，同一个物理块可以分配给不同的人。 

蛋糕本身的总重量可以是从 (1) 到 (10^{18}) 的任意总重量，因此我们可以自由选择一个方便的总重量。 三个客人的数量最多为（1000）。 这使得具有 (O(A+B+C)) 块的构造完全实用，而具有最多 (10^9) 块的构造则不然。 5000 块的限制是关键约束，它告诉我们搜索压缩表示而不是每克构建一个块。 

一个有用的边缘情况是 (A=B=C=1)。 正确的输出可以简单地包含在所有三种情况下分配给人员 1 的一份权重 1。 如果不删除重复的边界，基于内部边界的粗心构造可能会意外地创建零重量块。 

例如，使用输入`1 1 1`，唯一的边界为 0，最终边界为 1。恰好有一个区间，因此输出为`1`其次是`1 1 1 1`。 将三组边界视为单独的数组而不进行重复数据删除可能会多次错误地对同一间隔进行计数。 

另一个边界情况是`1 2 3`。 最小公倍数为 6。 三个均分边界为 1 名客人的 0 和 6，2 名客人的 0、3、6，以及 3 名客人的 0、2、4、6。 他们的工会是`0, 2, 3, 4, 6`，生产四件。 示例输出正是这四个间隔的一种有效实现。 使用浮点除法的粗心实现也可能会错误地识别大值的边界，因此每个边界都必须使用整数算术来计算。 

最后，最大输入值对于所选结构仍然无害。 由于 (\operatorname{lcm}(A,B,C)) 除 (ABC)，因此总是可以选择重量最多为 (1000^3=10^9)、远低于 (10^{18}) 的蛋糕。 不同内部边界的数量最多为((A-1)+(B-1)+(C-1))，因此件数最多为(A+B+C-2)，即最多2998。因此5000件的限制还有很大的余地。 

## 方法

 一个简单的结构是将蛋糕重量选择为 (L=\operatorname{lcm}(A,B,C)) 并使每克成为单独的一块。 有（L）个单位块。 对于 (A)-客人场景，为每位客人分配 (L/A) 个连续的单元件。 对 (B) 和 (C) 进行类似的操作。 这是正确的，因为 (L) 可被所有三个客人计数整除，因此每位客人分别准确地收到 (L/A)、(L/B) 或 (L/C) 克。 

问题是件数。 在最坏的情况下 (L) 可能接近 (10^9)。 例如，(A=997)、(B=998) 和 (C=999) 具有最小公倍数 (994010994)。 因此，一个单元结构需要 994010994 条输出线，远远超出了 5000 条的限制，也远远超出了一秒钟可以处理的范围。 

关键的观察结果是，我们实际上并不需要为每克单独的一块。 对于固定的客人数量，将蛋糕想象为从 0 到 (L) 的连续区间。 如果有（A）位客人，则客人1需要从0到（L/A）的间隔，客人2需要下一个间隔，依此类推。 接收者唯一可以改变的地方就是边界

 [
 0,\frac{L}{A},\frac{2L}{A},\ldots,L。 
]

 对 (B) 和 (C) 执行相同的操作。 现在将所有这些边界结合起来，只在那里切蛋糕。 

每个生成的片段完全位于一个 (A)-客体区间、一个 (B)-客体区间和一个 (C)-客体区间内。 因此，我们可以将整个作品分配给每个场景中相应的收件人。 这些碎片正是三等分的共同细化。 

最多有 (A-1)、(B-1) 和 (C-1) 个内部边界，因此在取它们的并集后，最多有 (A+B+C-2) 个内部切口和最多 (A+B+C-1) 个片段。 三个值最多为 1000，因此最多为 2999 件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(\operatorname{lcm}(A,B,C))) | (O(\operatorname{lcm}(A,B,C))) | 太慢了 |
 | 最佳 | (O((A+B+C)\log(A+B+C))) | (O(A+B+C)) | 已接受 |

 ## 算法演练

 1. 计算 (L=\operatorname{lcm}(A,B,C))。 这样得到的蛋糕的总重量可以平均分配给三个可能的客人数量中的任何一个。 
2. 创建一个包含 0 和 (L) 的集合。 这是蛋糕的两端。 
3. 对于从 1 到 (A-1) 的每个整数 (i)，将 (i(L/A)) 插入到集合中。 这些正是当有（A）客人时收件人改变的地方。 
4. 对 (B) 和 (C) 重复相同的过程，插入 (i(L/B)) 和 (i(L/C))。 由于 (L) 可被所有三个值整除，因此每个边界都是整数。 
5. 对生成的边界集进行排序。 连续值 (x<y) 定义一块物理蛋糕的重量 (y-x)。 重复的边界已被集合删除，因此每个权重都是正的。 
6. 对于从 (x) 开始的每个间隔，计算每个场景下的接收者。 对于 (A) 客人，包含 (x) 的区间属于客人

 [
 \left\lfloor\frac{x}{L/A}\right\rfloor+1。 
]

 (B)和(C)的相应公式给出了另外两个接收者。 因为 (x) 本身是并集的边界，所以该区间不能跨越属于任何场景的另一个边界。 
7. 输出每件物品的重量，后跟三个接收者索引。 总重量正好（L），件数在5000件以下。

### 为什么它有效

 不变的是，对于三个可能的客人计数中的每一个，每个生成的块完全位于一个均等间隔内。 考虑 (A)-来宾分区。 它的边界都包含在我们的全局边界集中，因此生成的片段不能跨越 (A)-来宾边界。 因此，每件作品都属于一个 (A) 嘉宾区间，我们将其分配给该区间的嘉宾。 由于每个间隔都有重量 (L/A)，因此每一位 (A) 客人都会收到精确的 (L/A) 克。 相同的论点独立地适用于(B)和(C)。 这些碎片是正的，因为它们是由不同的排序边界形成的，并且它们的总重量望远镜到（L）。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def lcm(a, b):
    return a // gcd(a, b) * b

def solve():
    A, B, C = map(int, input().split())

    L = lcm(lcm(A, B), C)

    cuts = {0, L}

    part_a = L // A
    part_b = L // B
    part_c = L // C

    for i in range(1, A):
        cuts.add(i * part_a)

    for i in range(1, B):
        cuts.add(i * part_b)

    for i in range(1, C):
        cuts.add(i * part_c)

    cuts = sorted(cuts)

    ans = []

    for i in range(len(cuts) - 1):
        left = cuts[i]
        right = cuts[i + 1]
        weight = right - left

        a = left // part_a + 1
        b = left // part_b + 1
        c = left // part_c + 1

        ans.append((weight, a, b, c))

    out = [str(len(ans))]
    out.extend(f"{w} {a} {b} {c}" for w, a, b, c in ans)
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一部分计算常见蛋糕重量。 嵌套的`lcm`调用是安全的，因为 Python 整数具有任意精度，尽管在此问题中结果值已经低于 (10^9)。 

三个`part_*`变量是每位客人必须收到的确切重量。 它们还充当三种可能情况下等间隔的宽度。 

这`cuts`布景是建筑的核心部分。 收件人发生更改的每个可能位置都只插入一次。 使用集合很重要，因为相同的边界可能出现在多个分区中。 例如，当(A=2)和(B=4)时，中点(L/2)也是四个(B)客体间隔中的两个之后的边界。 

分类后，连续的切割描述了实际的碎片。 表达式`right - left`始终为正，因为重复的剪切已被删除。 

接收方计算使用整数除法而不是浮点。 如果`left`位于 (A) 分区的第 (j) 个区间，则`left // part_a`是 (j-1)，因此加一将从零开始的区间数转换为所需的从一开始的人物索引。 

Python 中不存在溢出问题。 在具有固定宽度整数的语言中，64 位整数就足够了，因为该问题明确允许总计达到 (10^{18})，并且这里的构造比这个小得多。

            cuts.add(i * pc)

            y = cuts[i + 1]

    lines = output.strip().splitlines()

    K = int(lines[0])
    assert K == len(lines) - 1
    assert 1 <= K <= 5000

    pieces = []
    total = 0

    for line in lines[1:]:
        w, a, b, c = map(int, line.split())
        assert w > 0
        assert 1 <= a <= A
        assert 1 <= b <= B
        assert 1 <= c <= C
        pieces.append((w, a, b, c))
        total += w

    assert 1 <= total <= 10**18

        sums = [0] * (count + 1)

        for w, a, b, c in pieces:
            person = (a, b, c)[column - 1]
            sums[person] += w

        assert len(set(sums[1:])) == 1

 ## 边缘情况

 对于`1 1 1`，最小公倍数为 1，并且生成内部边界的所有三个循环均为空。 边界集很简单`{0, 1}`。 唯一的间隔的权重为 1，并且所有三个接收者索引均为 1。该算法无法创建零权重片段，因为它对集合而不是包含同一边界的重复副本的列表进行排序。 

为了`1 2 3`，蛋糕的重量为 6。(A)-分区没有内部切口，(B)-分区在 3 处有切口，(C)-分区在 2 和 4 处有切口。并集给出`0, 2, 3, 4, 6`，因此四个输出权重为 2、1、1 和 2。单个 (A) 访客接收所有四个部分，而其他两个场景则在自己的边界处分割这些相同的部分。 

为了`2 3 4`，蛋糕的重量为 12。(A) 边界为 0, 6, 12，(B) 边界为 0, 4, 8, 12，(C) 边界为 0, 3, 6, 9, 12。合并边界产生六块。 他们的接收者分配是通过对宽度 6、4 和 3 进行整数除法来确定的，因此每个客人在相应的场景中恰好收到 6、4 或 3 克。 

对于大案`1000 999 997`，最小公倍数低于 (10^9)，但该算法从不构造 (10^9) 块。 它在重复删除之前最多创建 (999+998+996+1=2994) 个边界位置，因此最多 2993 个片段。 每个边界都是三个分区宽度之一的精确整数倍，因此即使在允许的最大输入值下也不需要浮点运算。
