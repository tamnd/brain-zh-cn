 ## 解决方案
 ## 问题理解

 我们有一个由 (N) 个字符串表示的 (N \times N) 棋盘。 一个`*`是对手棋子，`K`是我们的国王，并且`-`是一个可能放置棋子的空方格。 棋子向上移动，意味着第 (r+1) 行、(c) 列的棋子攻击两个方格 ((r,c-1)) 和 ((r,c+1))。 国王攻击每一个行和列与自己最多相差一个的方格。 任务是放置尽可能少的额外棋子，以便每个`*`受到国王或新棋子之一的攻击。 棋子不能放置在已经被其他棋子占据的方格上`*`或者`K`。 官方给出的问题有（8 \le N \le 1000），时间限制为1秒，内存限制为256 MB。 

第一个有用的观察是攻击特定行的棋子必须恰好放置在下一行。 (r) 行中的星星只能被 (r+1) 行中的棋子攻击，而不能被其他行中的棋子攻击。 因此，一旦我们考虑到国王，每一行都可以独立解决。 如果 (N) 最多为 1000，则最多有 100 万个板单元，因此 (O(N^2)) 解决方案是完全合理的。 探索可能的棋子位置的子集或重复搜索整个棋盘以查找每颗星星的方法过于昂贵。 

一些边界情况可能会使看似合理的实现变得错误。 底行的星星没有下面的行，因此没有棋子可以攻击它。 例如，```
8
--------
--------
--------
--------
--------
--------
--------
*------K
```有答案`-1`，因为星不能被棋子攻击并且不与王相邻。 如果不小心实现，仅检查两个对角列而不检查行边界，则可能会访问无效单元格或错误地计算棋子。 

星也可以同时占据两个潜在的棋子方格。 例如，```
8
--------
--------
--------
--------
--------
--------
-*-*----
-K------
```不是这种情况的有效示例，因为国王更改了覆盖范围，因此请考虑一行中的相关局部模式：如果星星位于第 2 列，并且下一行第 1 列和第 3 列的单元格均被现有棋子占据，则没有棋子可以攻击该星星。 正确的结果是`-1`除非国王已经覆盖了它。 将每个对角方格视为可能的棋子位置的实现将错误地声明一个棋子可用。 

另一个微妙的情况是两颗星被一列分开。 如果两颗星星都没有被覆盖，并且下一行的中间方块是空的，则一个棋子覆盖两颗星星。 例如，```
8

--------
--------
--------

```有答案`1`。 独立处理每颗星星并为每颗星星放置一个棋子的解决方案将返回`2`，忽略了一个棋子可以攻击两个端点的事实。 

最后，国王可能已经覆盖了一些星星，并且在棋子优化之前必须将这些星星从考虑中删除。 在官方示例中，国王旁边的星星不需要棋子，而其他星星总共需要两个棋子。 

## 方法

 直接的暴力解决方案可以将空单元的每个子集视为棋子位置的可能集合，测试该集合是否攻击每个星，并保留最小的成功子集。 如果有 (E) 个空单元格，则有 (2^E) 个子集，并且检查一个子集可能需要 (O(N^2)) 工作。 在最坏的情况下，(E) 接近 (N^2)，大致给出 (O(N^2 2^{N^2})) 次操作。 对于 (N=1000)，其数量级为 (10^6 2^{10^6})，这根本不可行。 

通过查看一行的几何形状，我们可以做得更好。 假设一颗星星位于 (c) 列。 能够攻击它的棋子必须位于下一行的 (c-1) 或 (c+1) 列。 如果同一行的两颗星星出现在 (c) 和 (c+2) 列，则下一行 (c+1) 列的方块会同时攻击它们。 因此，在去除已经被国王攻击的星星之后，每一行就变成了一个一维覆盖问题。 

有用的贪心规则是从左到右扫描星星。 当在 (c) 列遇到未覆盖的星星时，首先尝试在 (c+1) 列放置一个棋子。 如果该方格为空，则选择它始终至少与选择 (c-1) 一样好，因为 (c+1) 攻击当前的星星，也可能攻击 (c+2) 处的下一颗星星。 如果(c+1)不可用，则唯一剩下的可能性是(c-1)。 如果两者都不可用，则该恒星根本无法受到攻击。 

这种贪婪的选择之所以安全，是因为它是局部的。 当处理(c)栏时，左边没有未来之星。 (c-1) 处的 pawn 只能帮助当前星和已处理的区域，而 (c+1) 处的 pawn 可以帮助当前星以及可能下一个未处理的星。 选择右边的方块永远不会花费更多，而且只能保留更多的未来覆盖范围。 

这些行是独立的，因此对每一行应用这种贪婪扫描会给出 (O(N^2)) 算法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(N^2 2^{N^2})) | (O(N^2)) | 太慢了|
 | 最佳 | (O(N^2)) | (O(N^2)) | 已接受 |

 ## 算法演练

 1. 阅读整个棋盘并找到国王。 国王的位置是必要的，因为有些星根本不需要棋子。 
2. 扫描每颗星星，只要它的行和列都在国王的一个单元格内，就将其标记为已被覆盖。 满足此条件的星不参与棋子优化。 
3. 独立加工每排板。 (r) 行中的星星只能被 (r+1) 行中的棋子攻击，因此为一行所做的选择不会影响任何其他行。 
4. 对于每一行，从左到右扫描列。 当当前单元格不是未覆盖的星形时，继续下一列。 
5. 当在 (c) 列发现未覆盖的星星时，首先检查第 (r+1) 行、(c+1) 列的候选棋子方格。 如果该单元格存在并包含`-`，在那里放置一个棋子并将答案加一。 

右边的候选者是首选，因为它攻击当前的星星，也可以攻击第 (c+2) 列的未来星星。 选择左边的候选者不能为尚未处理的恒星提供任何新的帮助。 
6. 如果右手候选者不可用，则检查第(r+1)行、(c-1)列的左手候选者。 如果它存在并且为空，则在其中放置一个棋子并增加答案。 
7. 如果两个候选者均不存在为空单元格，则当前星不能被任何棋子攻击。 既然已经确定不被王覆盖，那么整盘是不可能的，答案是`-1`。 
8. 继续，直到处理完每一行。 累计的棋子数量就是最小答案。 

### 为什么它有效

 对于每颗未覆盖的星星，唯一可能的棋子位置是下一行中的两个对角方块。 当扫描到达该星时，先前选择的棋子只能位于其左侧候选位置，因为所有早期决策都位于左侧。 如果存在这样的棋子，则星形已被覆盖并且不需要新的棋子。 否则，如果正确的候选者为空，则选择它会覆盖当前的星星，并留下用相同的棋子覆盖下一个星星的可能性。 任何使用左侧候选的解决方案都可以替换为使用右侧候选的解决方案，而无需增加棋子的数量。 如果右侧候选者被阻止，则左侧候选者是唯一剩余的选择。 如果两者都被阻挡，则任何溶液都无法覆盖恒星。 因此，每个贪婪决策都与最优解决方案兼容，并且独立处理所有行给出全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    board = [input().strip() for _ in range(n)]

    kr = kc = -1
    for r in range(n):
        pos = board[r].find('K')
        if pos != -1:
            kr, kc = r, pos
            break

    answer = 0

    for r in range(n):
        c = 0

        while c < n:
            if board[r][c] != '*':
                c += 1
                continue

            # Already attacked by the king.
            if abs(r - kr) <= 1 and abs(c - kc) <= 1:
                c += 1
                continue

            # A pawn must be in the row below the star.
            pr = r + 1

            # No row below means no pawn can attack this star.
            if pr == n:
                print(-1)
                return

            # Prefer the right candidate. It may also cover
            # a future star two columns to the right.
            if c + 1 < n and board[pr][c + 1] == '-':
                answer += 1
                c += 1
                continue

            # Otherwise try the left candidate.
            if c - 1 >= 0 and board[pr][c - 1] == '-':
                answer += 1
                c += 1
                continue

            # Neither possible pawn position is available.
            print(-1)
            return

    print(answer)

if __name__ == "__main__":
    solve()
```棋盘存储为字符串列表，因为算法只需要检查现有棋子。 我们实际上不需要将新放置的棋子写入棋盘中。 在从左到右的扫描过程中，新选择的棋子只能影响当前的星星和紧随其后的相关星星，并且扫描的位置已经捕获了这种关系。 

通过搜索每一行可以找到一次国王。 对于每颗星星来说，条件`abs(r - kr) <= 1 and abs(c - kc) <= 1`精确地表示八个相邻的方格加上国王自己的行和列的偏移量。 由于单元本身是星形，因此两个坐标不能同时出现相等情况，但使用标准切比雪夫距离条件可以使逻辑保持简单。 

候选典当行是`r + 1`， 不是`r - 1`，因为输入的第一行是棋盘的顶部，并且棋子向较小的行索引移动。 一个棋子连续攻击一颗星星`r`因此必须在行中位于其下方`r + 1`。 

右侧候选者先于左侧候选者被检查。 这种排序是中心贪婪选择。 如果右边的方块是空闲的，使用它可以额外覆盖右侧两列的星星。 左翼候选人没有这样的未来利益。 

代码前进`c`放置棋子后加一。 典当于`c + 1`攻击当前恒星`c`，如果另一颗星出现在`c + 2`，当扫描到达该星时，该星将看到该棋子。 无需跳过它或维护单独的覆盖数组。 

Python 整数具有任意精度，因此不存在溢出问题。 最大可能的答案是至多板单元的数量，只有（10^6）。
