 ## 解决方案
 ## 问题理解

 我们有偶数个索引石子，每个石子都带有一个 0 到 1000 之间的整数。我们必须将所有石子分成对。 一对含宝石`i`和`j`贡献`x[i] ^ x[j]`到总成本，我们想要最小可能的总成本和达到该最小值的不同配对的数量，模`10^9 + 7`。 

即使两颗宝石具有相同的价值，指数也很重要。 例如，四块石头包含`5 5 5 5`具有三种不同的配对，因为即使所有配对成本为零，宝石本身也是不同的。 

官方样本有`N = 6`， 其次是`7 14 17 4 2 1`，它的答案是`31 3`。 

上限`N <= 74`对于周围的算法来说足够小`O(N^2)`或者`O(N^2 log V)`，但完全排除枚举所有配对。 有`(N-1)!!`完美的配对，所以对于`N = 74`暴力搜索有`(73)!!`叶子，每个叶子需要 37 次异或计算。 配对成本评估的确切数量是`37 * 73!!`，其顺序为`10^55`。 值界`x[i] <= 1000`特别有用，因为只有位`0`通过`9`可能会发生，给我们一个只有 10 个级别的二元分解。 

有几种边缘情况，粗心的实现可能会处理不当。 用两块石头，例如```
2
0 1000
```唯一的配对是有成本的`1000`，所以答案是`1000 1`。 An implementation that assumes every recursive node has two nonempty children can fail here because one side of the binary split may be empty.

 Duplicate values require counting indexed stones separately. 为了```
4
5 5 5 5
```答案是`0 3`，因为所有三个完美配对的成本都是零。 仅计算不同的值排列将错误地返回 1。 

当位分割的两侧都具有奇数大小时，会出现更微妙的情况。 对于官方样本，```
6
7 14 17 4 2 1
```最高位分隔`{17}`从`{7,14,4,2,1}`，所以两边都是奇数。 恰好有一对必须穿过此分割，但该对有多种可能的选择。 仅基于立即异或的贪婪选择可能会错过全局最佳配对，更糟糕的是，可能会在计数时错过一些最佳配对。 

边界值`1000`也值得关注。 为了```
4
0 1000 511 512
```最优对是`(0, 511)`和`(1000, 512)`，有成本`511`和`488`, 给予`999 1`。 将值视为只占用最低九位会导致`1000`在错误的分区中。 

## 方法

 直接的方法是递归地生成每个完美匹配。 选择一个当前未使用的石头，将其与其他所有未使用的石头配对，然后递归。 这是正确的，因为每个完美匹配都有一个与第一个选择的石头对应的伙伴，因此递归最终只会访问每个配对一次。 问题是叶子的数量。 和`N`有石头`(N-1)!!`配对，并且每个配对包含`N/2`边缘。 在`N = 74`，这恰好意味着`37 * 73!!`对成本计算，远远超出任何实现的执行能力。 

有用的结构来自于查看两个值的最高不同位。 假设一个二进制 trie 节点表示其高位已经相同的值，并假设它的两个子节点在位上不同`b`。 两个孩子之间的任何边缘交叉都有位`b`集，所以它至少贡献`2^b`。 

关键的交换论点是，最佳匹配最多可以包含两个子项之间的一条边交叉。 假设两个交叉对是`(a,b)`和`(c,d)`， 在哪里`a,c`属于左孩子并且`b,d`属于合适的孩子。 它们的两条边加在一起至少贡献`2^(b+1)`仅从当前位来看。 将它们替换为`(a,c)`和`(b,d)`。 两个新边的当前位均为零，并且每个边的值严格低于`2^b`，所以它们的总成本严格低于`2^(b+1)`。 更换总是更好。 

这给出了非常强大的递归结构。 如果两个孩子的大小相等，则最佳解决方案不使用交叉对。 如果两个孩子的大小均为奇数，则最佳解决方案仅使用一对交叉。 如果整个节点的大小为奇数，则其两个子节点具有相反的奇偶性，并且最佳解决方案不使用交叉对，从而在奇数子节点中留下一个不匹配的石头。 

剩下的问题是奇数大小的子树必须返回什么信息。 我们不能简单地返回一个数字，因为父级需要知道哪一颗石头未被匹配。 相反，我们计算每块石头`i`在奇数子树中，将所有其他石头配对并离开的最小成本`i`无与伦比的，以及实现这一成本的方法数量。 由于最多有 74 块石头，因此每块石头存储一种状态很便宜。 

在有两个奇数子节点的节点，我们尝试所有可能的不匹配的石头`i`从左边的孩子开始，`j`来自正确的孩子。 这两颗棋子成为独特的交叉对，而其余的棋子在各自的子代中进行最佳匹配。 这是唯一需要二次转换的地方。 

比较结果为：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O((N/2) * (N-1)!!)`|`O(N)`| 太慢了|
 | 最佳 |`O(N^2 log V)`|`O(N log V)`| 已接受 |

 这里`V <= 1000`， 所以`log V <= 10`。 

## 算法演练

 1. 预计算`ways[k]`，完美配对的数量`k`索引宝石。 对于甚至`k`, 递推式为`ways[k] = (k - 1) * ways[k - 2]`， 和`ways[0] = 1`。 这也给出了匹配奇数组中除一颗宝石之外的所有宝石的方法数，因为`ways[k - 1]`是所需的计数。 
2.从最高有效位到最低有效位递归地处理一组石头索引。 根据当前位拆分索引。 如果集合中的所有值都具有相同的位，则只有一个非空子代，因此我们只需继续处理下一位。 
3. 对于两个子节点都是偶数的偶数节点，将它们的独立最优匹配组合起来。 不需要交叉对，因为两个交叉对会更糟，并且零交叉对是可行的。 成本是两个孩子成本之和，路数是他们的乘积。 
4. 对于一个偶数大小的节点，其两个子节点都是奇数，则需要恰好一个交叉对。 对于每一块石头`i`在左孩子和每块石头里`j`在右孩子中，使用其奇数子树状态并计算`dp_left[i] + dp_right[j] + (x[i] ^ x[j])`。 

保留最小值，并在另一个选择达到相同最小值时对计数求和。 每个结果配对都有一个独特的交叉对，因此不会重复计算。 
5. 对于奇数大小的节点，只有一个子节点是奇数，另一个是偶数。 最优解没有交叉对。 因此，无与伦比的石头必定来自奇怪的孩子。 将偶数孩子的完全匹配成本添加到奇数孩子的每个不匹配石头状态，并乘以相应的计数。 
6. 当递归到达最后一位以下时，当前集合中的所有值都相等。 每对都有异或零。 如果集合的大小均匀`m`，返回成本为零并且`ways[m]`配对。 如果它具有奇数尺寸，则对于每个可能的不匹配石头，返回成本为零并且`ways[m - 1]`配对。 
7. 使用所有索引和位开始递归`9`，因为 1000 小于`2^10`。 返回的偶数状态成本是最小总异或，其计数是最小配对​​数模`10^9 + 7`。 

### 为什么它有效

 不变量是每个递归状态都包含该状态所表示的精确条件下的最优解。 偶数状态代表其宝石的完整配对，而奇数状态则由`i`代表每颗宝石的配对，除了`i`。 

交换参数证明最佳匹配永远不需要两条边穿过当前 trie 节点的两个子节点。 因此，当两个子节点都是偶数时，偶节点具有零交叉边；当两个子节点都是奇数时，偶节点恰好具有一个交叉边。 奇数节点不能使用一个交叉边，因为它的子奇偶校验不同，并且使用两个或多个交叉边会比可行的零交叉构造更糟糕。 因此，每个最佳匹配都恰好具有过渡所考虑的递归形式之一。 

在叶子上，所有 XOR 值均为零，因此基本情况会计算每个最佳配对。 在内部节点，转换将每个结构上可能的最佳匹配枚举一次。 归纳起来，返回的最小成本和计数对于根来说是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAX_BIT = 9

def solve_case(a):
    n = len(a)

    # ways[k] = number of perfect pairings of k indexed elements,
    # for even k.
    ways = [0] * (n + 1)
    ways[0] = 1
    for k in range(2, n + 1, 2):
        ways[k] = ways[k - 2] * (k - 1) % MOD

    def dfs(ids, bit):
        m = len(ids)

        # All remaining bits are equal, so every XOR is zero.
        if bit < 0:
            if m & 1:
                cnt = ways[m - 1]
                return [(0, cnt) for _ in ids]
            return (0, ways[m])

        mask = 1 << bit
        left = []
        right = []

        for i in ids:
            if a[i] & mask:
                right.append(i)
            else:
                left.append(i)

        # The current bit does not distinguish these values.
        if not left or not right:
            return dfs(ids, bit - 1)

        dl = dfs(left, bit - 1)
        dr = dfs(right, bit - 1)

        nl = len(left)
        nr = len(right)

        if m & 1:
            # Exactly one child is odd and the other is even.
            if nl & 1:
                odd_dp = dl
                even_cost, even_count = dr
            else:
                odd_dp = dr
                even_cost, even_count = dl

            result = []
            for cost, count in odd_dp:
                result.append(
                    (cost + even_cost, count * even_count % MOD)
                )
            return result

        # The current node is even.
        if (nl & 1) == 0:
            # Both children are even, so no crossing pair is needed.
            left_cost, left_count = dl
            right_cost, right_count = dr
            return (
                left_cost + right_cost,
                left_count * right_count % MOD
            )

        # Both children are odd, so exactly one crossing pair is needed.
        best_cost = None
        best_count = 0

        for i, (cost_i, count_i) in zip(left, dl):
            for j, (cost_j, count_j) in zip(right, dr):
                cand_cost = cost_i + cost_j + (a[i] ^ a[j])
                cand_count = count_i * count_j % MOD

                if best_cost is None or cand_cost < best_cost:
                    best_cost = cand_cost
                    best_count = cand_count
                elif cand_cost == best_cost:
                    best_count = (best_count + cand_count) % MOD

        return best_cost, best_count

    return dfs(list(range(n)), MAX_BIT)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    cost, count = solve_case(a)
    print(cost, count)

if __name__ == "__main__":
    solve()
```这`ways`数组处理组合基本情况。 例如，`ways[4] = 3`，对应于将四个索引棋子划分为两对的三种方法。 保持这些值的模数`10^9 + 7`就足够了，因为后面的每个计数都是由这些计数的和与乘积形成的。 

递归函数返回两种不同类型的状态。 偶数大小的子树返回 1`(cost, count)`一对，因为它的所有宝石都是匹配的。 奇数大小的子树返回 1`(cost, count)`对每个可能的不匹配索引。 这种区别使得父母能够决定哪两颗宝石应该形成其独特的交叉对。 

分区使用`1 << bit`, 带位`9`作为起始位。 自从`1000 < 1024`，不能出现更高位。 递归调用`bit - 1`最终达到`-1`，其中所有剩余值对于每个可能的位都是相同的。 

仅当两个子项均为奇数时才会执行二次循环。 每个候选交叉对使用每个孩子的一个状态。 计数的乘法结合了两个子树的独立最优选择，而最终的总和则累积了交叉边的不同选择。 计数减少模数`MOD`每次乘法或加法之后。 

Python 整数不会溢出，因此成本计算不需要特殊的整数类型。 最大实际成本最多为`37 * 1023`，无论如何，它很小。 

## 工作示例

 官方的样本是```
6
7 14 17 4 2 1
```在第 4 位，这些值分为`{7,14,4,2,1}`和`{17}`。 两组都是奇数，因此必须选择一对交叉组。 第一组需要一个未匹配的石头，该表显示了针对每个可能的未匹配索引匹配其他四个石头的最佳成本。 

| 无与伦比的`{7,14,4,2,1}`| 内部成本| 方式数量 | 异或与`17`| 总计 |
 | ---| ---| ---| ---| ---|
 |`7`| 13 | 1 | 22 | 22 35 | 35
 |`14`| 6 | 1 | 31 | 37 | 37
 |`4`| 12 | 12 1 | 21 | 21 33 | 33
 |`2`| 14 | 14 1 | 19 | 19 33 | 33
 |`1`| 15 | 15 3 | 16 | 16 31 |

 最小值是通过离开获得的`1`下组内无与伦比，并将其与`17`。 最佳匹配方式有3种`{7,14,4,2}`成本为 15，所以最终答案是`31 3`。 这三种可能性是不同的，因为宝石是有索引的。 

对于第二个例子，考虑```
4
0 1 2 3
```在位 1，两个孩子是`{0,1}`和`{2,3}`，两者都是偶数。 因此，最佳结构在该位处不包含交叉对。 

| 位| 左组| 右组| 左状态| 正确的状态 | 综合结果|
 | ---| ---| ---| ---| ---| ---|
 |`1`|`0,1`|`2,3`| 成本`1`， 数数`1`| 成本`1`， 数数`1`| 成本`2`， 数数`1`|
 |`0`| 里面`{0,1}`| 里面`{2,3}`| 一对`0,1`| 一对`2,3`| 不变|

 唯一的最佳配对是`(0,1)`和`(2,3)`，具有异或成本`1`和`1`。 答案是`2 1`。 此示例演示了偶偶转换，其中两半可以独立求解。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(N^2 log V)`| 在每一位上，只有当元素对位于同一 trie 节点的相对子节点中时，才会考虑这些元素对。 跨越一个级别有`O(N^2)`这样的对。 |
 | 空间|`O(N log V)`| 每个元素每位参与一个递归状态，每个奇数状态存储一对值。 |

 这里`V <= 1000`， 所以`log V`最多 10 个。`N <= 74`，二次因子仅为每位数千次操作，加上少量的递归开销。 该算法完全在 3 秒和 256 MB 的限制范围内。

 ## 边缘情况

 对于两颗宝石的情况```
2
0 1000
```根最终只包含那两块石头。 仅在处理了所有区分位之后，奇/偶转换才减少为包含两个与当前递归相等的值的单个偶数叶。 两块石头必须形成一对，给出成本`0 ^ 1000 = 1000`并且恰好是一对。 输出是`1000 1`。 

对于重复值，```
4
5 5 5 5
```所有四个索引都到达同一片叶子。 叶子有四块石头，所以它的成本为零，`ways[4] = 3`。 该算法永远不会将等值的宝石合并到一个对象中，因此所有三个索引配对都会被计算在内。 输出是`0 3`。 

对于官方样本，```
6
7 14 17 4 2 1
```最高位将一颗石子与五颗石子分开。 双方都是奇数，迫使正好一对交叉。 五子方的动态保持其无与伦比的石头的身份，并且尝试每个可能的不匹配索引表明：`1`与`17`给出最小总和`31`。 其他四颗宝石有三种最佳内部匹配，产生`31 3`。 

对于边界情况，```
4
0 1000 511 512
```最好的配对是`(0,511)`和`(1000,512)`。 它们的异或值为`511`和`488`，因此总计为`999`。 其他可能的配对的总数更大。 trie 从第 9 位开始，其中`1000`和`512`处于高位，而`0`和`511`都偏低，因此该算法无需任何特殊的数值情况即可处理边界。 输出是`999 1`。 

对于最大输入，```
74
1000 1000 ... 1000
```每个 XOR 都为零。 递归过程到达包含所有 74 个索引石块的单个叶子。 成本为零，每一次完美的搭配都是最优的。 计数正好是`73!!`, 计算模数`10^9 + 7`由`ways`复发。 这种情况既锻炼了最大递归状态大小，又锻炼了模块化计数逻辑。
