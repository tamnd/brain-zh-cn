 ## 解决方案
 ## 问题理解

 我们正在研究整数和模算术，但如果我们将无限数轴视为由周期规则着色，则结构会变得更加清晰。 

对于任意整数$x$，我们计算两个值：首先我们取$x \bmod a$，然后将该结果模数减少$b$。 同时，我们还计算$x \bmod b$接下来是模数$a$。 如果这两个最终结果不同，我们计数$x$。 

每个查询给出一个段$[l, r]$，并且我们必须计算该范围内有多少整数满足这个不等式条件。 

关键的难点在于$l$和$r$可以大到$10^{18}$，所以我们不能单独评估每个数字。 该结构仅取决于余数模$a$和$b$，两者都很小（最多 200），这强烈表明与以下相关的某个周期的周期性$a$和$b$。 

蛮力的想法是测试每个查询范围中的每个数字。 当查询间隔很大时，这已经立即中断。 例如，如果$l = 1$和$r = 10^{18}$，迭代是不可能的。 

一个更微妙的问题是，即使我们预先计算前缀的值，相等的模式也取决于 mod$a$和模组$b$，所以我们需要一个结构化的重复参数，而不是朴素的前缀模拟。 

边缘情况出现时$a = b$。 在这种情况下，这两个表达式对于所有$x$，所以答案始终为零。 假设周期性行为而不检查这一点的粗心实现仍然可以工作，但会浪费计算或带来除法边缘混乱的风险。 

另一种边缘情况是当其中之一$a$或者$b$等于 1。然后模数链之一折叠为零，并且表达式显着简化。 实现仍然必须在通用公式中干净地处理这个问题。 

## 方法

 暴力方法评估每个查询间隔中每个整数的条件。 每次评估都需要恒定的时间，因此单个查询的成本$O(r - l + 1)$，在最坏的情况下这是$10^{18}$。 这立即是不可行的。 

核心观察是条件仅取决于$x \bmod a$和$x \bmod b$。 这两个残基以句点重复$a$和$b$，所以这对一起重复周期$\mathrm{lcm}(a, b)$。 自从$a, b \le 200$，这个周期最多为 40000，足够小以进行预计算。 

因此，我们可以计算出一个完整周期的长度$L = \mathrm{lcm}(a, b)$，有多少个值满足条件。 然后任何前缀$x$可以表示为：

 完整周期加上剩余段。 

因此，我们在一个周期内构建一个前缀数组，并使用两个前缀评估来回答每个查询。 

这会将预处理后的每个查询时间减少到恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(\sum (r-l))$|$O(1)$| 太慢了|
 | LCM 上的周期前缀 |$O(a \cdot b + q)$每次测试 |$O(a \cdot b)$| 已接受 |

 ## 算法演练

 1. 计算$L = \mathrm{lcm}(a, b)$。 这定义了所有相关残基对的重复周期，因为两个模模式在此长度之后同时重复。 
2. 构建数组`bad[i]`为了$i \in [1, L]$， 在哪里`bad[i] = 1`如果$((i \bmod a) \bmod b) \ne ((i \bmod b) \bmod a)$，否则为 0。这直接编码每个位置是否对答案有贡献。 
3.构建前缀和数组`pref`， 在哪里`pref[i]`存储有多少个有效值$[1, i]$。 这允许在周期内进行恒定时间范围计数。 
4. 预计算`total = pref[L]`，一个完整周期内有效值的数量。 这让我们可以通过将大范围分割成完整周期加上余数来处理大范围。 
5. 回答询问$[l, r]$，计算：

 中有效值的数量$[1, r]$减去中的数字$[1, l-1]$。 其中每一个都是使用完整周期计算的：$$f(x) = (x // L) \cdot total + pref[x \bmod L]$$小心处理时$x \bmod L = 0$。 

### 为什么它有效

 表达式的值仅取决于对$(x \bmod a, x \bmod b)$。 由于两个残基均独立重复$a$和$b$，组合状态每重复一次$\mathrm{lcm}(a, b)$。 这使得指标函数具有周期性，因此对大范围进行计数减少为对整个周期加上固定前缀进行计数，从而保留每个整数间隔的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def lcm(a, b):
    import math
    return a // math.gcd(a, b) * b

t = int(input())
for _ in range(t):
    a, b, q = map(int, input().split())
    L = lcm(a, b)

    bad = [0] * (L + 1)
    pref = [0] * (L + 1)

    for i in range(1, L + 1):
        x = i % a
        y = i % b
        if (x % b) != (y % a):
            bad[i] = 1
        pref[i] = pref[i - 1] + bad[i]

    total = pref[L]

    def calc(x):
        if x <= 0:
            return 0
        cycles = x // L
        rem = x % L
        return cycles * total + pref[rem]

    out = []
    for _q in range(q):
        l, r = map(int, input().split())
        out.append(str(calc(r) - calc(l - 1)))

    print(" ".join(out))
```该实现依赖于显式构建函数的一个完整周期，并使用前缀和将范围查询转换为常数时间算术。 

主要的微妙之处是正确处理索引。 该数组是从 1 开始的，因此余数的前缀和使用`pref[rem]`直接，整个周期乘以`pref[L]`。 另一个重要的细节是使用`l - 1`安全地在里面`calc`，其中非正值必须返回零。

 ## 边缘情况

 当$a = b$，每个项的计算结果都是相同的，因为两个表达式都简化为相同的计算，因此算法的标记数组完全为零。 前缀和保持不变，每个查询都返回零，与预期的数学简化相匹配。 

什么时候$a = 1$或者$b = 1$，表达式的一侧全部折叠为零$x$。 该实现仍然有效，因为模运算正确地产生常数余数，并且周期结构退化为长度等于其他参数的简单循环。 

什么时候$l$和$r$跨越多个完整周期加上部分尾部，`calc`函数将范围干净地分割为`(x // L)`完整的重复和剩余部分。 这避免了对查询边界与循环边界对齐的任何依赖，确保任意间隔的正确性。
