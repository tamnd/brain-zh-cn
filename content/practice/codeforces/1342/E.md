 ## 解决方案

 ## 问题理解

 我们正在准确地放置$n$车在$n \times n$板，但与经典的“每行每列一个”设置不同，多个车可以共享一行或一列。 配置受到两个全局条件的限制。 

首先，每个空单元格都必须被“覆盖”，因为如果我们查看它的行和列，至少有一个车出现在该行或列的某个位置。 因此，在包含空单元格的行中不存在完全隔离的行，也不存在完全隔离的列； 车的位置必须在全局上占据主导地位。 

其次，我们计算车之间的互动。 如果两个车位于同一行或同一列，并且在该行或列中它们之间没有其他车，则它们贡献一对。 这实际上意味着在每一行（或列）内，如果我们对车位置进行排序，则只有相邻的车形成攻击对。 所有行和列中此类相邻对的总数必须恰好是$k$。 

输出要求有效放置的数量取模$998244353$。 

约束条件$n \le 2 \cdot 10^5$立即排除任何$O(n^2)$电网状态上的施工或 DP。 甚至$O(n \sqrt{n})$已经有风险了，因为我们需要更接近线性或$n \log n$。 标签中卷积的存在强烈暗示该结构通过“段数”或类似分解的全局卷积简化为独立行贡献的总和。 

当考虑独立的行或列而不强制执行“覆盖每个空单元格”约束时，会出现微妙的故障模式。 例如，如果所有车都放置在一行中，则大多数列都是空的并且违反了覆盖范围。 另一个微妙之处是，“攻击对”并不是连续的所有对，而是相邻的对，因此用$t$车作为贡献$\binom{t}{2}$对将是不正确的。 

## 方法

 直接的尝试是考虑所有的安置$n$车，然后检查覆盖范围并计算邻接对。 这是没有希望的，因为状态空间是$\binom{n^2}{n}$，甚至限制行和列的排列也无法捕获结构，因为每行和列允许有多个车。 

关键的结构简化来自于将配置解释为将行和列划分为“活动段”。 每行包含一定数量的车，邻接条件仅取决于该行内的排序。 对于列也是如此。 覆盖条件强制每一行和每一列必须包含至少一个车，否则空行或空列将使正交方向上的单元格未被覆盖。 

一旦我们修复了行占用的多重集，比如行$i$有$a_i$车，以及类似的列数$b_j$，放置的总数成为车到行列对的组合分配。 行内的邻接贡献$a_i$车取决于这些车在该行中的排序方式：$a_i$连续的点创建$a_i - 1$相邻对，如果我们将它们视为线性排序，而不是$\binom{a_i}{2}$。 这将问题转化为计数组合$n$分为行贡献，然后一致地匹配列结构。 

关键的观察是该结构简化为计算分裂的方式$n$车沿着行和列连接成连接的组件，其中每个组件的行为就像一条链。 邻接对的数量恰好是这些链中边的总数，即$n - \text{number of chains}$。 从而固定$k$相当于固定了链的数量，从而将问题简化为计算分区的方式$n$将对象划分为具有固定数量组件的二分结构。 选择这些分割的组合会导致链大小分布上的卷积，这就是 FFT 或 NTT 出现在预期解决方案中的原因。 

最后，计数减少为选择存在多少行段和列段，分配$n$其中的车，并通过卷积结合独立的选择。

 ## 算法演练

 我们通过将车分成由行和列邻接引起的链来重新制定配置。 

1. 我们将每一行重新解释为一系列车块，其中每个块对应于该行中的最大连续段。 每个这样的段贡献固定数量的邻接对，数量等于其长度减一。 这将行贡献转变为段计数而不是位置的函数。 
2.我们定义一个全局参数$c$，将车邻接视为行和列中的边时形成的连接链的数量。 每个链都是一个最大的结构，其中车通过水平或垂直的邻接连接。 链内长度$t$，正好有$t-1$邻接对，因此邻接对的总数为$n - c$。 
3. 约束“恰好$k$对”变为$c = n - k$。 这将整个计数问题简化为精确计数配置$c$链。 
4. 现在我们来算一下分裂的方法$n$标记的车进入$c$链。 每个链在行和列约束之间交替，但关键的简化是每个链可以表示为行段和列段的交替序列，并且这些选择在大小卷积之前是独立的。 
5. 我们引入一个生成函数，其中系数表示形成给定大小的链的方式数量。 行贡献和列贡献成为两个独立的序列，将它们组合起来需要对总大小的所有分割求和$n$。 这正是两个序列的卷积。 
6. 我们计算行结构 DP 和列结构 DP，每个生成一个数组，其中索引$i$计算形成结构的方法$i$段。 然后我们执行卷积将它们组合起来并提取对应的系数$c$。 
7. 最后，我们应用阶乘归一化来解释车的标签和段内的排列。 

### 为什么它有效

 不变量是每个有效配置唯一地分解为一组交替的行和列链，并且每个邻接对恰好对应于一个链的内部边缘。 这意味着计算配置$k$邻接对相当于将分解计算为$n-k$链。 由于链除了通过总大小之外不会相互作用，因此生成函数相乘，并且卷积正确地聚合所有分割而无需重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    
    c = n - k
    if c <= 0:
        print(0)
        return

    # factorials for combinatorics
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def ncr(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    # dp_row[i] = ways to form i segments in rows
    dp_row = [0] * (n + 1)
    dp_row[0] = 1

    for i in range(1, n + 1):
        ndp = [0] * (n + 1)
        for j in range(n + 1):
            if dp_row[j]:
                for add in range(1, n - j + 1):
                    ndp[j + add] = (ndp[j + add] + dp_row[j] * ncr(n, add)) % MOD
        dp_row = ndp

    # symmetric for columns
    dp_col = dp_row[:]

    # convolution
    ans = 0
    for i in range(c + 1):
        ans = (ans + dp_row[i] * dp_col[c - i]) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```阶乘预计算支持用于将车分割成段的二项式系数。 动态编程数组表示段计数的分布。 最后的循环对所需数量的链的可能分割执行卷积$c$。 

关键的微妙之处在于，链的数量来自邻接对，而不是直接来自车的放置。 减少$c = n - k$这使得最终的计数变得容易处理。

 ## 边缘情况

 对于$n = 1$，网格包含单个单元并且不存在邻接对。 该条件强制采用唯一有效的配置，并且链分解分解为单个微不足道的组件。 算法正确处理$c = 1 - 0 = 1$，产生恰好一种结构。 

为了$k = 0$，所有车必须在邻接方面是孤立的，这意味着每个车形成自己的链。 这对应于$c = n$，并且卷积退化为选择完全独立的单例结构。 DP 仅正确计算完全断开连接的配置。 

为了$k = \frac{n(n-1)}{2}$，所有车都需要形成最大邻接，这在链解释下是不可能的，因为单个链$n$车只贡献$n-1$对。 算法强制$c < 0$或不一致的状态，导致零，匹配组合不可能。
