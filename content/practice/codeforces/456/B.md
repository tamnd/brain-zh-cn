 ## 解决方案
 ## 问题理解

 当一个非常大的数字 _n_ 的前四个倍数之和除以 5 时，该任务要求得到余数。换句话说，您需要计算`(1*n + 2*n + 3*n + 4*n) mod 5`。 输入 _n_ 是一个整数，最多可以有 10,105 位数字，这远远超出了标准 64 位整数可以存储的范围。 这意味着您不能直接使用典型的整数算术或在内存中将 _n_ 乘以 10^4，然后取模，因为数字本身可能非常巨大。 

输出是 0 到 4 之间的单个整数，表示这四个倍数的总和除以 5 后的余数。问题本质上是要求模算术中的模式，因为总和`1 + 2 + 3 + 4`是常数，所以唯一重要的是 _n modulo 5_。 要考虑的边缘情况包括 _n_ 为零、一位数或具有数万位数字。 一个尝试存储的幼稚实现`4*n`对于大的 _n_ 显式会失败，要么由于内存溢出而崩溃，要么花费太长时间。 

## 方法

 暴力解决方案首先需要计算每个倍数`1*n`,`2*n`,`3*n`， 和`4*n`，对它们求和，然后取模 5。这种方法对于小数字是正确的，因为乘法和加法很简单。 但是，如果 _n_ 有 10,000 位数字，则计算`4*n`明确是不切实际的。 即使使用大整数库，这也会花费大量时间和内存，远远超过预期的 1 秒限制。 

关键的观察是模算术对于加法和乘法是分布式的。 那是，`(a + b) mod m = ((a mod m) + (b mod m)) mod m`和`(a * b) mod m = ((a mod m) * (b mod m)) mod m`。 系数之和`1 + 2 + 3 + 4`是 10，所以`(1*n + 2*n + 3*n + 4*n) mod 5 = (10*n) mod 5`。 由于 10 能被 5 整除，`(10*n) mod 5`无论 _n_ 为何，始终为 0。 这极大地简化了问题：输出始终为 0。无需读取 _n_ 的数字或对实际数字执行任何算术。

 ## 算法演练

 1. 认识到 _n_ 的前四个倍数之和可以因式分解：`1*n + 2*n + 3*n + 4*n = (1+2+3+4)*n = 10*n`。 
2. 认识到这一点`(10*n) mod 5`简化，因为 10 可以被 5 整除，给出`(10*n) mod 5 = 0`。 
3. 直接返回 0，因为对于任何非负整数 _n_，无论其大小如何，表达式的计算结果始终为 0 模 5。 

为什么有效：模运算的分配性保证了正确性。 由于 10 是 5 的倍数，因此将其乘以任何整数 _n_ 仍能被 5 整除。然后模运算产生余数为零。 不存在边缘情况，因为零乘以 10 也得到零，并且该公式对于 _n_ 的所有允许值都有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = input().strip()
print(0)
```此解决方案将输入读取为字符串，这是必要的，因为 _n_ 可能非常大。 我们不将其转换为整数，因为在意识到结果始终为零之后，_n_ 的大小就无关紧要了。 这`strip()`方法删除所有尾随换行符。 印刷`0`无需对 _n_ 执行任何算术运算即可产生正确的输出。

 ## 边缘情况

 对于 _n = 0_，前四个倍数之和为`0 + 0 + 0 + 0 = 0`，模 5 为 0。对于具有 10,105 位数字的 _n_，算法无需执行任何算术即可正确打印 0。 即使对于不能被 5 整除的个位数，总和`1*n + 2*n + 3*n + 4*n`是 10 的倍数，模 5 结果仍然是 0。不存在违反此模式的边缘情况。
