 **求解时间：** 1m 28s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到了一系列笔记本电脑。 每台笔记本电脑都有价格和质量价值。 价格各有不同，品质也各有不同。 

Dima 认为，更昂贵的笔记本电脑必然具有更好的质量。 亚历克斯声称这不一定是真的。 他说可能存在两台笔记本电脑，其中较便宜的一台实际上比较昂贵的一台具有更高的质量。 

我们的任务是确定 Alex 的说法对于给定的笔记本电脑组是否正确。 

输入最多包含$10^5$笔记本电脑。 对于每台笔记本电脑，我们都会收到两个整数：价格和质量。 输出是`"Happy Alex"`如果存在至少一对，其中较便宜的笔记本电脑比较昂贵的笔记本电脑具有更高的质量。 否则我们打印`"Poor Alex"`。 

约束条件$n \le 10^5$立即排除检查每台笔记本电脑的可能性。 二次算法的执行大致如下$$\frac{10^5 \cdot (10^5 - 1)}{2} \approx 5 \times 10^9$$最坏情况下的比较，远远超出了一秒内可以运行的范围。 我们周围需要一些东西$O(n \log n)$或更好。 

一个微妙的点是笔记本电脑指数并不重要。 只有价格和质量之间的关系才重要。 在输入中出现较早的笔记本电脑并不意味着它更便宜或更贵。 

考虑这个例子：```
3
10 100
20 200
30 300
```正确的输出是：```
Poor Alex
```每一次价格的上涨都伴随着质量的提高。 

现在考虑：```
3
10 300
20 200
30 100
```正确的输出是：```
Happy Alex
```售价 10 的笔记本电脑比售价 20 和 30 的笔记本电脑质量更好。 

另一个容易犯的错误是只比较相邻的输入行：```
3
30 300
10 200
20 100
```正确的输出是：```
Happy Alex
```只有在按价格订购笔记本电脑后，矛盾才变得明显。 原始输入顺序不包含有用的结构。 

## 方法

 最直接的解决办法就是暴力破解。 对于每台笔记本电脑，将其与其他笔记本电脑进行比较。 每当我们发现两台笔记本电脑，其中一台价格更低但质量更高时，Alex 的说法就得到了证实，我们就可以停止了。 

这是有效的，因为它显式地检查问题陈述中的确切条件。 不幸的是，与$10^5$笔记本电脑，对数约为$5 \times 10^9$。 即使非常快的实现也无法在时限内处理那么多比较。 

关键的观察是条件仅取决于价格的排序。 如果我们按价格对所有笔记本电脑进行排序，那么右侧的每台笔记本电脑都比左侧的每台笔记本电脑更贵。 

假设我们按价格排序并获得质量序列：```
100 200 150
```质量从 200 下降到 150，而价格却上涨。 这立即给出了一个有效的对。 质量200的笔记本电脑比质量150的笔记本电脑便宜。 

更一般地说，在按价格排序后，当且仅当质量也严格增加时，迪马的信念才是正确的。 由于所有质量值都是不同的，质量的任何下降都意味着我们找到了质量更好的更便宜的笔记本电脑。 

所以我们只需要按价格排序并扫描结果的质量即可。 如果在任何位置当前质量小于之前的质量，则 Alex 是正确的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将所有笔记本电脑读取为`(price, quality)`对。 
2. 按价格升序对笔记本电脑进行排序。 

排序后，每台笔记本电脑都会出现在所有更昂贵的笔记本电脑之前。 
3. 从左到右扫描排序后的列表。 
4. 对于每对相邻的对，比较它们的质量。 
5. 如果当前笔记本电脑的质量低于之前的笔记本电脑，则打印`"Happy Alex"`并终止。 

以前的笔记本电脑由于排序顺序而更便宜，但质量更高。 这正是亚历克斯所描述的情况。 
6. 如果扫描完成后未发现质量有任何下降，请打印`"Poor Alex"`。 

### 为什么它有效

 按价格排序后，笔记本电脑按从最便宜到最贵的顺序排列。 如果向右移动时质量下降，那么较便宜的笔记本电脑比较昂贵的笔记本电脑具有更高的质量，这证明了亚历克斯的说法。 

相反，如果质量永远不会下降，那么质量就会随着价格而增加。 由于所有品质都是不同的，这意味着每台更昂贵的笔记本电脑也具有更高的品质。 不存在矛盾对。 

该算法精确地检查这个属性，因此它会产生正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
laptops = []

for _ in range(n):
    price, quality = map(int, input().split())
    laptops.append((price, quality))

laptops.sort()

for i in range(1, n):
    if laptops[i][1] < laptops[i - 1][1]:
        print("Happy Alex")
        break
else:
    print("Poor Alex")
```第一部分将所有笔记本电脑描述读入成对列表中。 致电给`sort()`按价格对它们进行排序，因为价格是每个元组的第一个元素。 

扫描从第二台笔记本电脑开始。 对于每个位置，我们都会将其质量与按价格顺序排列的前一台笔记本电脑的质量进行比较。 

质量的下降足以证明Alex的说法。 一旦发现这种减少，答案就已知，我们立即终止。 

这`for-else`这里施工方便。 这`else`仅当循环完成且未遇到`break`，意味着没有发现质量下降。 

不存在溢出问题，因为所有值最多都是$10^5$，并且该算法仅执行比较和排序。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    laptops = [tuple(map(int, input().split())) for _ in range(n)]

    laptops.sort()

    for i in range(1, n):
        if laptops[i][1] < laptops[i - 1][1]:
            print("Happy Alex")
            return

    print("Poor Alex")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("2\n1 2\n2 1\n") == "Happy Alex", "sample 1"

# minimum size
assert run("1\n5 10\n") == "Poor Alex", "single laptop"

# already increasing
assert run("4\n1 10\n2 20\n3 30\n4 40\n") == "Poor Alex", "perfect agreement"

# contradiction appears after sorting
assert run("3\n30 300\n10 200\n20 100\n") == "Happy Alex", "must sort first"

# contradiction far apart
assert run("5\n1 10\n2 20\n3 30\n4 40\n5 15\n") == "Happy Alex", "late decrease"

# two laptops only, opposite ordering
assert run("2\n100 200\n200 100\n") == "Happy Alex", "smallest non-trivial case"

 | 严抓素质 | 可怜的亚历克斯| 迪玛的信念成立 |

 ## 边缘情况

 考虑尽可能最小的输入：```
1
5 10
```整理完毕后，仍然只有一台笔记本电脑。 扫描永远不会执行，因为没有可比较的对。 该算法正确打印：```
Poor Alex
```因为亚历克斯的要求需要两台笔记本电脑。 

考虑一个输入，其中矛盾被原始排序隐藏：```
3
30 300
10 200
20 100
```按价格排序会产生：```
(10, 200)
(20, 100)
(30, 300)
```扫描期间，第二个元素的质量从 200 下降到 100。 该算法立即输出：```
Happy Alex
```这说明了为什么直接检查输入顺序是不正确的。 

考虑一个矛盾出现在接近尾声的情况：```
5
1 10
2 20
3 30
4 40
5 15
```排序顺序不变。 在最后一次比较之前，扫描发现质量不断提高：```
40 -> 15
```由于质量下降而价格上涨，算法输出：```
Happy Alex
```这表明必须检查价格顺序中的每个相邻比较，直到发现违规为止。
