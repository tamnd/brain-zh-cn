 ## 解决方案
 ## 问题理解

 我们得到一棵树，其中每个节点都带有一个初始整数值。 唯一允许的操作是选择端点当前具有相同值的边，将这两个端点合并为单个节点，并将两个值的总和分配给该新节点。 新节点继承两个端点的所有关联边（合并边本身除外），因此结构始终保持树状，只是节点较少。 

该过程将继续，直到所有节点合并为单个节点或不再保留有效的合并。 任务是确定是否存在任何有效合并序列可以将整个树缩减为一个节点。 

尽管树结构最初是静态的，但值的演变方式很快就打破了一致性。 一次合并后，新值通常是唯一的，除非其他地方的匹配合并产生相同的总和。 这使得朴素的模拟变得极其脆弱：该过程的值不是单调的，并且可合并边的集合会发生不可预测的变化。 

总量约束$n \le 2 \cdot 10^5$在所有测试用例中排除任何合并步骤的模拟。 每次合并都会将节点数减一，因此可以有$O(n)$合并，但每次合并都需要更新邻接并跟踪等值边缘，这已经表明每个操作的接近线性或对数的开销会太慢。 

如果我们尝试贪心模拟，一些故障模式会立即出现。 首先，提前合并可能会阻止以后的有效合并，因为它会更改值。 其次，如果两个相同的值属于无法同步其总和的不同合并链，则它们可能相邻但仍然不可用。 

局部贪婪失败的一个小例子是三个节点的路径：```
1 - 1 - 1
```前两个节点的贪婪合并会产生一个值为 2 的节点，该节点连接到值为 1 的节点，并且该过程会停止，尽管先合并最后两个节点也会失败。 事实上，没有任何顺序有效，但幼稚的策略可能会错误地假设灵活性。 

真正的困难在于，合并的行为就像在每一步构建受邻接性和相等性约束的二叉合并树，而不是原始树上的简单匹配问题。 

## 方法

 一个蛮力的想法是显式模拟所有可能的合并序列。 在每一步中，我们都会扫描所有边并尝试合并任何有效的对。 由于每次合并都会更改图，因此这变成了对指数级多个序列的动态搜索。 即使我们积极修剪，分支因子在密集值情况下仍然很大，并且最坏情况的增长速度比任何可行的界限都快$n = 2 \cdot 10^5$。 

关键的观察结果是合并后的实际值几乎与结构决策无关。 一旦两个节点有值$x$合并，他们创建一个有价值的节点$2x$，并且该值不太可能出现在其他地方，除非同时发生结构相同的合并。 这使得不可能依赖长链的价值传播。 相反，合并实际上就像配对操作一样，沿边消耗两个相同的值。 

这重新构建了该过程：每次合并都会消耗两个具有相同当前值的相邻节点，并将它们从活动节点池中删除，并用一个不会进一步参与的新节点替换它们，除非其他地方发生相同的构造。 因此，问题归结为树是否可以分解为沿边的局部配对序列，以便最终消耗每个节点。 

这导致了一个结构条件：在共享相同初始值的节点的任何连接区域内，我们必须能够执行成对的边缘删除，直到没有任何剩余。 这相当于每个值类上的导出子图可分解为边不相交对，这些边不相交对可以收缩，而不会留下不匹配的节点搁浅。 

当值类组件具有奇数个节点时，就会出现唯一的障碍，因为每个操作在它们从值转换之前从该组件中恰好删除两个节点。 任何剩余的单例将立即变得不可合并。 

这将问题简化为检查由相等值引起的每个连接分量，其大小是否均匀。

 | ---| ---| ---| ---|
 | 暴力模拟| 指数| O(n) | 太慢了|
 | 组件奇偶校验| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 根据输入构建树的邻接表。 这种表示使我们能够有效地探索连接的组件。 
2. 遍历树并按节点的值对节点进行分组，但仅限于具有相等值的连通分量内。 这是通过从每个未访问的节点运行 DFS 或 BFS 来完成的，限制遍历具有相同值的邻居。 此限制的原因是仅允许在相等值的相邻节点之间进行合并，因此只有这些边与可行性相关。 
3. 对于每个发现的组件，计算其大小。 此大小表示在与其他值进行任何交互之前，有多少节点可能参与该值类中的内部合并。 
4. 如果任何组件大小是奇数，请立即断定完全合并是不可能的。 原因是每次有效的合并都会消耗来自同一值组件的两个节点，因此奇数大小的组件会导致陷入困境的节点无法找到有效的伙伴。 
5. 如果所有值的所有组件都具有均匀大小，则得出结论：可以完全缩减为单个节点。 

### 为什么它有效

 关键的不变量是，合并永远不会混合值，除非它们在合并时相同，并且任何合并都会立即更改结果节点的值，从而将其与进一步的参与隔离开来，除非其他地方出现相同的构造。 这会阻止跨组件同步。 因此，唯一重要的稳定结构是将树划分为原始状态下具有相同值的连接组件。 在每个这样的组件中，每次合并都会恰好删除两个节点，因此可行性降低到组件是否可以成对地完全耗尽，这相当于具有偶数大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    vis = [False] * n

    def dfs(start):
        stack = [start]
        vis[start] = True
        val = a[start]
        cnt = 0

        while stack:
            u = stack.pop()
            cnt += 1
            for v in g[u]:
                if not vis[v] and a[v] == val:
                    vis[v] = True
                    stack.append(v)
        return cnt

    for i in range(n):
        if not vis[i]:
            if dfs(i) % 2 == 1:
                print("NO")
                return

    print("YES")

t = int(input())
for _ in range(t):
    solve()
```该解决方案构建树，然后探索限制为固定值的每个连接组件。 DFS 是迭代的，以避免倾斜树下的递归深度问题。 

每个组件的尺寸都是独立计算的。 一旦发现组件尺寸不正常，程序就会提前停止，因为没有进一步的结构可以解决这种不平衡问题。 

一个微妙的点是，遍历受到值相等的限制，因此我们找到的不是普通的树组件，而是值引发的连通组件。 

## 工作示例

 考虑一棵小树，其中的值已经形成了一个干净的配对结构：```
n = 4
values = [1, 1, 2, 2]
edges:
1-2, 3-4, 2-3
```我们加工组件：

 | 开始| 价值| 访问过的节点 | 元件尺寸|
 | ---| ---| ---| ---|
 | 1 | 1 | {1,2} | 2 |
 | 3 | 2 | {3,4} | 2 |

 两个组件的大小相同，所以答案是肯定的。 

现在考虑一个有障碍的情况：```
n = 3
values = [1, 1, 1]
edges:
1-2, 2-3
```遍历：

 | 开始| 价值| 访问过的节点 | 元件尺寸|
 | ---| ---| ---| ---|
 | 1 | 1 | {1,2,3} | 3 |

 元件尺寸为奇数，所以答案是否定的。 

这直接显示了故障模式：一个节点在其值类中总是不匹配，从而阻止了完全约简。

 ## 边缘情况

 最小边缘情况是具有相同值的两个节点的树。 DFS 找到大小为 2 的单个分量，该分量是偶数，因此算法接受它，这与可以立即进行合并的事实相匹配。 

一个更微妙的情况是星形树，其中所有节点共享相同的值。 即使中心的度数很高，遍历时仍然将整个组件算作一组。 如果节点数量为奇数，算法会立即拒绝它，这正确地反映了无论合并顺序如何，一个节点将始终保持不配对状态。 

另一个重要的情况是当值沿边缘交替时，例如由不同值分隔的等值对的二分结构。 每个值引起的组件都是隔离的，因此 DFS 永远不会跨越值边界。 每个组件都是独立评估的，防止跨不兼容区域的错误合并。
