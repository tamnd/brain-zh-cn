 ## 解决方案
 ## 问题理解

 我们得到一个随时间变化的括号字符串。 每次更新后，我们必须计算当前字符串有多少个子串形成正确的、完全平衡的括号序列。 

如果子字符串在被解释为括号时，其余额永远不会变为负数并且以总余额为零结束，则该子字符串对答案有贡献。 我们不被要求输出子字符串本身，只要求每次交换相邻字符后存在多少个这样的子字符串。 

关键难点在于每次操作都要交换两个相邻的字符，操作次数多达200000次。 该字符串也很大，因此每次交换后从头开始重新计算答案太慢了。 

简单的重新计算将扫描所有 O(n^2) 子字符串并在 O(n) 中验证每个子字符串，这是完全不可行的。 即使每个带有前缀余额和基于堆栈的检查的查询进行一次重新计算也会花费 O(n)，这在最坏的情况下会导致 O(nq)。 

这些限制迫使我们采用一种解决方案，其中每次交换仅影响非常小的局部区域，并且我们在支持快速更新的数据结构中维护全局信息。 

一种微妙的边缘情况是交换创建或破坏了远远超出交换位置的正确子字符串。 例如，在长交替模式内进行交换，如下所示：```
()()()()()
```可以更改许多有效的子字符串，而不仅仅是那些触及交换对的子字符串。 这排除了任何仅更新固定窗口的解决方案。 

## 方法

 暴力方法通过检查每个子字符串在每次交换后重新计算分数。 对于每个子字符串，我们使用平衡计数器验证它是否是常规括号序列。 这需要 O(n) 每个子字符串和 O(n^2) 个子字符串，为每个查询提供 O(n^3)，这已经是不可能的了。 即使使用前缀和将验证提高到 O(1)，每个查询也会将其减少到 O(n^2)，但仍然太大。 

更合理的基线是使用堆栈或前缀平衡以及动态编程风格计数以 O(n) 的方式重新计算每个查询的答案。 这仍然是 O(nq)，在最坏的情况下大约是 4e10 次操作。 

关键的见解是，答案取决于可以通过本地贡献来表达的全球结构。 每个有效子串对应于一个匹配的括号结构，并且每个字符最多参与序列到原始平衡段的规范分解中的一个结构单元。 

这建议维护一个段结构，跟踪段中存在多少个有效子字符串，同时还跟踪左括号和右括号如何跨段边界“流动”。 正确的工具是线段树，它存储每个区间内存在多少个平衡子串，以及足够的信息来合并两半。 

交换仅影响两个相邻位置，因此只有恒定数量的线段树叶子发生变化。 更新这些叶子后，我们通过在 O(log n) 时间内拉起树来重新计算答案。 每个节点合并都使用已知的括号序列 DP，它组合左子节点和右子节点，同时考虑新形成的跨越边界的有效子串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O(n^2) | O(n) | 太慢了|
 | 线段树合并 DP | 每个查询 O(log n) | O(n) | 已接受 |

 ## 算法演练

 我们在字符串上维护一棵线段树。 每个节点代表一个区间并存储足够的信息来计算该区间内和跨合并的有效子字符串的数量。 

每个节点存储：

 完全包含在段中的有效子字符串的数量，加上平衡配置文件，使我们能够在合并时将左侧的左括号与右侧的右括号相匹配。 

我们为每个段定义：

 1. 内部形成的匹配对的计数。 
2. 一种以支持合并的方式跟踪剩余多少个不匹配的“(”和“)”的结构。 

一种简洁的思考方式是，每个段的行为就像一组不匹配的括号，合并会贪婪地取消匹配，同时累积新形成的平衡子字符串。 

### 步骤

 1. 构建一棵线段树，其中每个叶子对应一个字符。 叶子存储它是左括号还是右括号，以及零内部匹配。 
2. 对于每个内部节点，定义左子节点 A 和右子节点 B 之间的合并操作。在合并过程中，我们将尽可能多的 A 中的“(”与 B 中的“)”进行匹配。 每个这样的匹配都有助于形成跨越边界的有效子串。 
3. 合并时，我们计算：

 通过以贪婪方式将左侧不匹配的开端与右侧不匹配的闭端配对而创建的新的跨界有效子串的数量。 这是使用可用的不匹配计数之间的最小运算来完成的。 
4. 节点的总答案是两个子节点答案的总和加上合并期间计算的跨边界贡献。 
5. 每个交换操作交换位置p 和p+1 处的字符。 我们更新线段树中的两个叶子节点，并重新计算受影响的节点直至根节点。 
6. 每次更新后，根存储我们输出的完整字符串的总分。 

### 为什么它有效

每个有效的子字符串都对应于括号的配对结构。 线段树确保每个这样的结构在完全包含它的最低间隔处被精确地计数一次。 内部子串在子节点中进行计数，而跨越边界的子串在合并期间两半相遇时精确计数。 不匹配的打开和关闭之间的贪婪配对是有效的，因为两个独立段之间的任何最佳匹配都必须以非交叉方式配对，并且段边界强制内部结构的独立性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("ans", "open", "close")
    def __init__(self, ans=0, open_=0, close_=0):
        self.ans = ans
        self.open = open_
        self.close = close_

def merge(a, b):
    res = Node()
    res.ans = a.ans + b.ans
    match = min(a.open, b.close)
    res.ans += match

    res.open = a.open + b.open - match
    res.close = a.close + b.close - match
    return res

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.t = [Node() for _ in range(4 * self.n)]
        self.s = s
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            if self.s[l] == '(':
                self.t[v] = Node(0, 1, 0)
            else:
                self.t[v] = Node(0, 0, 1)
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.t[v] = merge(self.t[v * 2], self.t[v * 2 + 1])

    def update(self, v, l, r, pos):
        if l == r:
            if self.s[pos] == '(':
                self.t[v] = Node(0, 1, 0)
            else:
                self.t[v] = Node(0, 0, 1)
            return
        m = (l + r) // 2
        if pos <= m:
            self.update(v * 2, l, m, pos)
        else:
            self.update(v * 2 + 1, m + 1, r, pos)
        self.t[v] = merge(self.t[v * 2], self.t[v * 2 + 1])

    def query_all(self):
        return self.t[1]

def solve():
    n, q = map(int, input().split())
    s = list(input().strip())

    st = SegTree(s)
    arr = s

    for _ in range(q):
        p = int(input()) - 1
        arr[p], arr[p + 1] = arr[p + 1], arr[p]

        st.s = arr
        st.update(1, 0, n - 1, p)
        st.update(1, 0, n - 1, p + 1)

        print(st.query_all().ans, end=' ')

if __name__ == "__main__":
    solve()
```该实现依赖于标准线段树，其中每个节点跟踪不匹配的开括号和闭括号以及在其间隔内形成的匹配对的数量。 合并函数是关键部分，因为它确保跨边界形成的任何新的有效结构都被精确计数一次。 

更新步骤仅涉及两个交换的位置，并且每次更新以 O(log n) 的速度传播，从而保持解决方案的高效。

 ## 边缘情况

 一个关键的边缘情况是交换在段边界上创建了以前不可能实现的新平衡。 例如，在几乎交替的字符串中，单个交换可以对齐打开和关闭，以便大量新子字符串变得有效。 线段树合并可以正确处理此问题，因为每次边界重新计算都会重新评估不匹配括号之间的最大匹配。 

另一个边缘情况是在同一位置上重复交换，这可以在不改变多个步骤的全局平衡的情况下切换局部结构。 由于更新是本地的并且完全重新计算，因此树中不会保留陈旧的信息，因此分数保持一致。
