 ## 解决方案
 ## 问题理解

 我们有两个序列。 第一个序列`a`是我们要匹配的模式，第二个序列`b`是无限重复但仅有限次数的基本序列。 如果我们重复`b`确切地`k`有时，我们会得到一个很长的序列`k`的连续副本`b`。 

任务是找到最少的重复次数`k`这样`a`可以作为该重复序列内的子序列找到。 如果无限重复的话`b`无法形成`a`作为子序列，我们必须返回`-1`。 

子序列意味着我们从左到右扫描并挑选元素而不重新排序，可能会跳过元素。 

关键的难点在于`k`没有给出。 我们必须确定有多少次完整通过`b`需要“消耗”所有元素`a`为了。 

这些约束允许所有测试用例中最多包含 200,000 个总元素。 这立即排除了任何试图显式构建的方法`dup(b, k)`或模拟与不断增长的副本的匹配`b`对于许多候选值`k`。 每次测试中任何比线性或接近线性更差的东西都会失败。 

当某些元素出现时，会出现微妙的边缘情况`a`从未出现在`b`。 例如，`a = [1]`,`b = [2, 3]`。 再多的重复也无济于事，答案必须是`-1`。 错误重置的天真贪婪扫描可能仍然会循环并错误地假设进展是可能的，除非它显式检查以下位置的可达性：`b`。 

匹配时会发生另一个棘手的情况`a`需要在副本中重新启动`b`。 例如，`b = [1, 2, 3]`,`a = [2, 3, 1, 2]`。 我们可能会完成完整的通行证`b`完成之前`a`，所以我们需要多个循环，并且我们必须计算我们绕了多少次`b`。 

## 方法

 直接模拟方法很简单。 我们尝试匹配`a`反对`b`，将指针移入`a`每当我们在中找到匹配元素时`b`。 一旦我们到达终点`b`，我们增加一个计数器来记录我们已经使用了多少完整副本并重新开始扫描`b`从一开始。 我们继续直到`a`完全匹配，或者我们发现不可能取得进展。 

这是可行的，因为子序列匹配本质上是贪婪的：只要我们可以匹配的下一个元素`a`，我们应该在最早的位置匹配它`b`。 

然而，如果我们重新启动扫描，简单的实现就会变得低效`b`太多次并从头开始重复扫描。 在最坏的情况下，每个元素`a`可能需要完整遍历`b`，导致 O(nm) 行为，当两个数组都很大时，速度太慢。 

关键的观察是每次重复中的行为`b`是相同的。 而不是重复扫描`b`，我们可以预处理每个值的位置`b`并使用二分搜索“跳转”到下一个有效的匹配项。 这使得匹配的每一步都变成了`a`转换为对数或摊销常数运算。 

我们维护一个指向虚拟无限的指针`b`。 对于每个`a[i]`，我们发现下一个出现在`b`这严格位于我们当前在周期内的位置之后。 如果不存在这样的情况，我们跳到下一个循环并从第一个出现的地方继续`b`, 递增`k`。 

这将问题简化为有效地查找循环数组中的下一个位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n·k·m) | O(n·k·m) | O(1) | O(1) | 太慢了|
 | 预处理位置+二分查找 | O((n + m) log m) | O((n + m) log m) | O(米) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们根据中的每个值构建一个映射`b`到它出现的索引列表。 这允许快速查找我们可以放置每个元素的位置`a`。 索引的排序至关重要，因为我们需要下一个有效位置。 
2.我们初始化两个变量：`pos`，它在一个副本中跟踪我们当前的索引`b`（从 0 开始），以及`k`，它计算有多少个完整副本`b`到目前为止我们已经使用过（如果可以匹配则从 1 开始）。 
3.我们迭代每个元素`x`在`a`。 对于每个`x`，我们查阅其职位列表`b`。 如果这个列表为空，我们立即得出答案是`-1`因为`x`从未出现在`b`。 
4. 我们尝试找到列表中严格大于的最小索引`pos`。 这是我们下一个可以匹配的地方`x`不违反当前副本内的顺序`b`。 如果存在这样的位置，我们会更新`pos`并继续。 
5. 如果不存在这样的位置，则意味着我们必须进入下一个重复`b`。 我们递增`k`， 重置`pos`到第一次出现`x`在`b`，然后继续。 这反映了环绕到新副本`b`。 
6. 处理完所有元素后`a`，最终值`k`是所需的最小副本数。 

### 为什么它有效

 在每一步中，我们总是将每个元素`a`在重复结构中最早可能的有效位置。 这种贪婪的放置确保我们永远不会人为地延迟匹配，因此永远不会不必要地增加所需的重复次数。 任何延迟比赛的替代安排只会让我们更进一步`b`并且可能需要更早而不是更少的额外周期。 

不变的是处理后`a[i]`,`pos`的位置是`a[i]`在最早的副本中`b`与有效的子序列构造一致，并且`k`准确计算我们跨越边界的次数`b`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from bisect import bisect_right

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos_map = {}
        for i, x in enumerate(b):
            if x not in pos_map:
                pos_map[x] = []
            pos_map[x].append(i)

        # feasibility check
        for x in a:
            if x not in pos_map:
                print(-1)
                break
        else:
            k = 1
            pos = -1  # current index in b
            for x in a:
                lst = pos_map[x]
                idx = bisect_right(lst, pos)
                if idx < len(lst):
                    pos = lst[idx]
                else:
                    k += 1
                    pos = lst[0]
            print(k)

if __name__ == "__main__":
    solve()
```代码首先构建`pos_map`，对每个值的分组索引`b`。 这种结构使我们能够避免扫描`b`反复。 

这`pos`我们上次在副本中匹配的变量轨道`b`。 使用`bisect_right`，我们有效地找到下一个有效的出现。 如果不存在，我们通过递增来模拟移动到下一个重复`k`并从该值第一次出现时重新开始。 

一个微妙的细节就是初始值`pos = -1`，这确保第一个元素可以匹配第一个副本中的任何位置`b`。 

## 工作示例

 ### 示例 1

 考虑`a = [1, 2, 3]`,`b = [1, 2]`。 

| 步骤| x| 之前的位置 | 选择索引| k | 后 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | -1 | 0 | 1 | 0 |
 | 2 | 2 | 0 | 1 | 1 | 1 |
 | 3 | 3 | 1 | 无 | - | 不可能|

 我们失败于`3`因为它不存在于`b`，所以输出是`-1`。 

这证实了立即检测到丢失的元素并防止错误的继续。 

### 示例 2

 让`a = [2, 3, 1, 2]`,`b = [1, 2, 3]`。 

| 步骤| x| 之前的位置 | 选择索引| k | 后 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 2 | -1 | 1 | 1 | 1 |
 | 2 | 3 | 1 | 2 | 1 | 2 |
 | 3 | 1 | 2 | 0（下一个周期）| 2 | 0 |
 | 4 | 2 | 0 | 1 | 2 | 1 |

 我们需要 2 份`b`。 

该跟踪显示了为什么需要环绕，以及算法如何仅在需要时正确计算完整周期。

 ## 边缘情况

 一个关键的边缘情况是当`a`不存在于`b`。 例如，`a = [5]`,`b = [1, 2, 3]`。 算法检查`pos_map`在任何匹配开始之前，因此它立即返回`-1`。 如果没有这种检查，简单的指针方法可能会无限循环或错误地重置周期。 

另一种情况是当`a`完全包含在一次遍历中`b`， 例如`a = [1, 3]`,`b = [1, 2, 3, 4]`。 这里`k`遗迹`1`因为`pos`永远不需要包装。 该算法永远不会递增`k`，因为每个下一个出现都是在当前周期中找到的。 

最后一种情况是大量重复，例如`a = [1, 1, 1, 1]`,`b = [1]`。 每个元素强制重复使用相同的索引或循环增量。 算法正确增加`k`每次不存在向前发生时，产生`k = 4`，它与所需的重复次数相匹配。
