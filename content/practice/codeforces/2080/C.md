 ## 问题理解

 在这个问题中，我们给出了一个序列`n`卡片排成一排。 每张牌都有一个显示 0 或 1 的面。唯一允许的操作是选择牌的连续部分并翻转该部分中的所有牌（0 变为 1，1 变为 0）。 我们的目标是将原始序列转换为所有卡片都显示 1 的序列。我们需要确定实现此目标所需的最少操作数。 

输入由一个整数组成`n`后面跟着一个长度的字符串`n`代表卡面。 输出是一个整数，即翻转的最小次数。 

考虑到以下约束`n`最多可以达到 10^5 并且时间限制是标准的（通常是 1-2 秒），我们可以预期在最坏的情况下执行大约 10^8 次操作。 这排除了任何显式尝试所有可能的连续段的算法，因为段的数量以 n(n+1)/2 的二次方增长。 

非明显的边缘情况包括 0 和 1 交替出现的序列、所有牌都已经为 1 的序列以及所有牌都为 0 的序列。例如，对于`1010`，一次翻转一个 0 的简单方法可能需要四次操作，但存在仅使用两个操作的翻转序列：翻转段`1-1`和`3-3`。 如果所有卡都已经是 1，则答案为 0。如果所有卡都为 0，则整个数组的一次连续翻转就足够了，给出 1 次操作。 粗心的实现经常会通过单独翻转每个 0 来过度计算操作。 

## 方法

 蛮力方法很简单：迭代每个可能的连续段并尝试翻转它，递归地检查结果序列，直到到达所有序列。 这是有效的，因为翻转任何片段都是允许的，并且最终会将序列转换为所有片段。 然而，连续段的数量是n(n+1)/2，并且检查所有可能的组合是n的指数，这对于n=10^5来说是完全不可行的。 

关键的观察是我们不需要明确地跟踪各个翻转。 每次翻转只重要于它如何将 0 变为 1。 我们可以从左到右扫描序列并计算连续的 0 段的数量。 每个这样的段都需要至少一次翻转，并且在一次操作中翻转它是最佳的，因为翻转包含 1 的较大段不必要地增加了复杂性，而不会减少操作数量。 因此，最小翻转次数等于连续 0 段的数量。 

蛮力之所以有效，是因为它最终会达到全一序列，但由于指数复杂性而失败。 观察到连续的 0 可以翻转在一起，从而将问题简化为对数组进行一次遍历，从而产生 O(n) 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`flips`到 0。这将存储所需操作的数量。 
2. 初始化索引`i`为 0 从最左边的卡片开始扫描。 
3.同时`i`小于`n`，查看当前卡：

 a. 如果是1，则递增`i`并继续，因为不需要翻转。 

b. 如果为0，则增加`flips`1，然后通过移动跳过所有连续的 0`i`向前直到 1 或到达序列末尾。 这确保了每个 0 段都被精确计数一次。 
4. 一旦到达序列末尾，输出`flips`。 

为什么它有效：不变的是每个连续的 0 段都被精确地计算一次。 翻转该段会在一次操作中将其所有 0 变为 1，而翻转超出该段将不必要地影响已经正确的 1。 通过从左到右扫描并计算段数，我们保证了最少的翻转次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def min_flips_to_all_ones(cards: str) -> int:
    n = len(cards)
    flips = 0
    i = 0
    while i < n:
        if cards[i] == '1':
            i += 1
        else:
            flips += 1
            while i < n and cards[i] == '0':
                i += 1
    return flips

def main():
    n = int(input())
    cards = input().strip()
    print(min_flips_to_all_ones(cards))

if __name__ == "__main__":
    main()
```功能`min_flips_to_all_ones`执行序列的单个线性扫描。 内部 while 循环确保连续的 0 被视为单个段。 使用`strip()`输入时防止隐藏的换行符干扰索引。

 ## 边缘情况

 对于交替模式`010101`，该算法正确地将每个孤立的零计数为一个单独的段。 从索引 0 开始，它跳过 1，在索引 1 处对 0 的翻转进行计数，跳至索引 2 (1)，对索引 3 (0) 处的翻转进行计数，并在索引 5 (0) 处计数翻转，从而恰好产生 3 次翻转。 这与尽可能少的操作相匹配。 

对于全 1 序列，算法会跳过每张牌并且从不递增`flips`，产生 0，这是正确的。 对于单卡序列，它正确处理 0 和 1，仅在必要时翻转。
