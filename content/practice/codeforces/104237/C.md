 ## 解决方案
 ## 问题理解

 我们得到了沿着路径按固定顺序排列的一系列垃圾堆。 每堆都有一个重量，鲍勃必须从左到右拿起一堆，不能跳过或重新排序。 他反复前往垃圾桶，每次行程中他都可以从上次停下的地方开始搬运一块连续的垃圾堆，只要该行程的总重量不超过固定限制$K$。 

任务是计算处理整个序列所需的最小行程数，同时考虑顺序约束和容量约束。 

关键约束是$N \le 10^5$，这会立即排除任何尝试所有分区或显式检查所有子数组的解决方案。 二次或更差的方法的性能可达$10^{10}$最坏情况下的操作，在 1 秒限制下是不可行的。 这促使我们采用单一线性扫描策略。 

当单堆重量等于$K$。 在这种情况下，即使它出现在一系列小堆中，它也必须形成自己的行程。 另一个极端情况是所有桩都适合一次行程，这意味着答案应该是 1。在这种情况下，错误重置或过早开始新行程的天真方法会导致计数过高。 

## 方法

 暴力策略将模拟所有可能的方法，将序列分割成有效的行程。 由于每个行程都是一个连续的段，其总和最多为$K$，可以尝试每个断点并递归计算最小段数。 这自然会导致尝试数组的所有分区。 

然而，一个分区的数量$N$-元素数组呈指数增长。 即使我们将自己限制在有效的拆分上，最坏的情况（所有元素都很小）也允许在几乎任何地方进行拆分，从而导致粗略的结果$2^{N-1}$的可能性。 这远远超出了任何可行的计算。 

一旦我们将其解释为贪婪的打包过程，问题的结构就会大大简化。 由于 Bob 必须按顺序处理项目并且不能重新排序或跳过，因此每次行程只是从当前位置开始的最大前缀，其总和不超过$K$。 进一步延长行程总是会减少或维持行程数量，因为由于严格的排序约束，较早开始新行程永远无法帮助更有效地组合未来的元素。 

这使得最优策略变得简单：从左到右扫描，不断累积权重，每当添加下一堆会超过$K$，我们承诺当前的旅行并开始新的旅行。

 ## 算法演练

 1. 从代表当前跳闸负载的运行总和以及跳闸次数的计数器开始。 两者都从零开始。 
2. 按顺序从左到右遍历一堆。 
3. 对于每一堆，检查将其重量添加到当前行程中是否会超过$K$。 
4.如果不超过$K$，通过增加运行总和将该堆包含在当前行程中。 
5. 如果超过$K$，通过增加行程计数器来完成当前行程，将运行总和重置为当前堆的重量，并从此堆开始新的行程。 
6. 处理完所有桩后，如果还有未完成的行程（非零运行和），则计为最终行程。 

第 5 步背后的原因是，一旦违反约束，我们就无法重新安排之前的决策。 由于顺序是固定的，唯一有效的修复是在违规元素之前立即切断行程边界。 

### 为什么它有效

 在扫描中的任何点，算法都会维护代表当前行程的连续桩段，并且在其总和最多为的约束下，该段始终是最大的$K$。 如果我们比必要的时间更早地结束了一次旅行，我们就会增加旅行的数量，而不会获得任何合并未来元素的能力，因为未来的元素不能被提前移动或交换。 因此，每次削减时，我们都是出于可行性而不是选择，从而确保了最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    trips = 0
    current = 0
    
    for x in a:
        if current + x <= k:
            current += x
        else:
            trips += 1
            current = x
    
    if current > 0:
        trips += 1
    
    print(trips)

if __name__ == "__main__":
    solve()
```其实现完全遵循贪婪扫描。 变量`current`跟踪正在进行的行程重量。 当新的一堆不适合时，我们立即关闭之前的行程并仅用该堆开始新的行程。 

最终检查确保部分填充的最后行程被计算在内。 如果没有这个，当末尾没有发生溢出时，最后一个段将被丢失。

 ## 边缘情况

 最小输入，例如`1 5 / 3`处理正确，因为循环永远不会触发分割并且最终的非零`current`正好贡献一趟行程。 

全容量单桩式`1 5 / 5`立即创建一个完整的行程，因为溢出检查永远不会触发，但会计算最终的累积量。 

每堆都相等的序列$K$， 例如`4 3 / 3 3 3 3`，在每个元素上都强制进行新的旅行。 每次`current + x`超过$K$，算法重置，确保没有堆被错误地合并。 

紧密排列的序列，例如`6 5 / 2 3 2 3 2 3`证明了贪婪打包总是在切割之前尽可能多地填充每个行程，并且从不延迟可以提高可行性的切割。
