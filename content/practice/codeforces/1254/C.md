 ## 解决方案
 ## 问题理解

 我们在平面上得到一组隐藏的点，每个点仅由从 1 到 n 的索引标识。 我们看不到坐标，但我们可以提出涉及任意三个不同索引的几何查询。 从这些查询中，我们可以获得两倍的三角形有符号面积或由三个点形成的转弯的方向。 

隐藏的承诺是这些点形成一个严格的凸多边形，并且正确的答案正是其顶点逆时针方向的循环排序。 另外，保证顶点 1 是位置 p1 处的多边形顺序的一部分。 

任务是仅使用几何基元和最多 3n 个查询来重建此循环顺序。 

交互的结构为我们提供了两个基本有用的工具。 面积查询提供了在排列下一致的幅度信息，而叉积查询的符号给出了方向，在仿射变换下是不变的。 然而，由于我们受到查询计数的限制，因此解决方案必须避免类似于完全成对几何重建的任何事情。 

最重要的约束是 3n 次查询限制，最多 1000 个点。 这立即排除了任何依赖于比较所有对或所有三元组的 O(n²) 方法。 即使是 O(n² log n) 的构造也是不可能的。 我们必须在查询方面以基本上线性的时间构建凸包排序，这意味着每个点只能被“触及”恒定的次数。 

一个微妙的边缘情况在于避免简并。 该问题保证没有三个点共线，因此每个方向查询都会返回 +1 或 -1。 如果没有这一点，许多贪婪的船体构造将由于打破平局的模糊性而失败。 

另一个陷阱是假设顶点 1 是最左边或最底部的点。 它不是。 唯一的保证是它以最终的循环顺序出现。 任何尝试在不首先识别船体结构的情况下按围绕固定参考的角度对点进行排序的解决方案都会失败。 

## 方法

 一个天真的想法是使用距离和面积查询显式重建坐标。 如果我们可以确定成对距离或精确的三角形面积，我们可以嵌入这些点，然后使用标准几何计算凸包。 然而，重建坐标需要 O(n²) 信息，因为每个点必须与许多其他点进行比较以确定其相对位置。 如果只有 3n 个查询，这是不可能的。 

第二个天真的想法是选择一个参考点并使用方向查询按极角对所有其他点进行排序。 这更接近预期的结构，但仍然存在问题：排序需要 O(n log n) 次比较，并且每次比较都涉及一个查询。 这已经超出了查询预算。 

关键的观察是我们不需要来自固定枢轴的完整角度顺序。 相反，我们只需要凸包的循环顺序。 对于凸多边形，局部结构就足够了：每个顶点恰好有两个邻居，并且连续三元组之间的方向条件是一致的。 

这建议逐步建造船体。 我们从一个已知的顶点开始，然后通过选择下一个保留凸性的顶点来重复扩展链。 在每一步中，我们只需要针对部分船体的最后一个边缘来测试候选者。 因为结构是凸的，所以正确的下一个顶点是由简单的方向标准唯一确定的。 

我们可以维护一个候选链并使用方向查询来消除无效的转换。 每个点在被接受到船体中或被丢弃之前仅参与恒定数量的检查。 这使得查询总数保持在 O(n) 以内。

订购时不一定需要区域查询； 它可用于一致性检查或解决初始化问题，但核心排序来自方向。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 强力几何重建 | O(n²) 查询 | O(n²) | 太慢了|
 | 从固定枢轴进行极坐标排序 | O(n log n) 次查询 | O(n) | 查询太多 |
 | 增量式凸链结构| O(n) 次查询 | O(n) | 已接受 |

 ## 算法演练

 我们依赖这样一个事实：如果我们能够使用方向测试一致地按逆时针顺序选择下一个顶点，则可以恢复凸包。 

1. 固定点1作为船体序列的起始顶点。 我们将以逆时针方向生长船体。 
2. 为第二个顶点选择初始候选点。 一个常见的技巧是尝试第 2 点。正确性并不取决于此选择，仅取决于一致的方向处理。 
3. 维护当前的有序列表`hull`，最初包含 [1, 2]。 
4. 对于从 3 到 n 的每个剩余点 i，通过检查它是否保持凸性来尝试将其插入到外壳链中。 我们通过将最后两个船体点的方向与候选点 i 进行比较来做到这一点。 如果顺时针转动，则最后一个船体点无效，必须删除。 
5. 重复凸度检查，直到船体至少有两个点或不再需要去除。 然后附加新点 i。 
6. 处理完所有点后，通过验证最后一个和第一个点相对于第二个和倒数第二个点也保持凸性来结束循环。 如果没有，请从末端进行最终去除，直到船体变成凸形。 
7. 结果列表是从点 1 开始按逆时针顺序排列的凸包。 

整个过程中的关键操作是orientation(i, j, k)，它告诉我们从线段i→j到j→k的转动是否是逆时针的。 这保证了我们可以维持单调凸链。 

### 为什么它有效

 在任何阶段，维持的序列都是凸链：每个连续的三元组都保留逆时针方向。 当附加一个新点时，任何违反凸性的行为只能出现在链的后缀处，因为早期的部分已经是凸的并且不受插入的影响。 从末尾删除可以恢复不变量。 

由于最终的点集是凸多边形，因此属于船体的每个点都必须在所有删除中幸存下来，而任何会产生凹转弯的点都将被消除。 这确保了剩余序列恰好是正确循环顺序的边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cross(i, j, k):
    print(2, i, j, k, flush=True)
    return int(input().strip())

def build_order(n):
    hull = [1, 2]

    for i in range(3, n + 1):
        hull.append(i)
        while len(hull) >= 3:
            a, b, c = hull[-3], hull[-2], hull[-1]
            if cross(a, b, c) == -1:
                hull.pop(-2)
            else:
                break

    # final cleanup to ensure convex cycle
    changed = True
    while changed and len(hull) > 2:
        changed = False
        if cross(hull[-2], hull[-1], hull[0]) == -1:
            hull.pop()
            changed = True
        if len(hull) > 2 and cross(hull[-1], hull[0], hull[1]) == -1:
            hull.pop(0)
            changed = True

    # rotate so that 1 is first
    idx = hull.index(1)
    hull = hull[idx:] + hull[:idx]

    return hull

def main():
    n = int(input())
    ans = build_order(n)
    print(0, *ans, flush=True)

if __name__ == "__main__":
    main()
```该解决方案仅使用方向查询，并且从不尝试恢复坐标。 外壳列表作为动态链进行维护，其中添加每个新点，然后通过删除无效的中间顶点进行纠正。 这`cross`函数直接对应于交互式类型2查询，并且每次调用都会按照交互协议的要求立即刷新。 

最后的旋转步骤确保符合顶点 1 必须首先出现在输出排列中的要求。

 ## 边缘情况

 极端情况是第二个顶点的初始选择与实际外壳上的 1 不相邻。 在这种情况下，算法最初构建的链不是全局正确的，但凸性修剪可确保删除任何违反后面点方向的不正确的中间顶点。 最终，只剩下真正的外壳顶点。 

另一种情况是当多个点早期出现在非船体位置时。 这些点可以暂时插入链中，但一旦后面的点与它们形成凹转弯，它们就会从中间移除。 这说明了为什么该算法不需要提前知道船体成员资格。
