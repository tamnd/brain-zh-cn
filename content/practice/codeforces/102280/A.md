 ## 解决方案
 ## 问题理解

 我们有`n`驱动程序，最初按它们在日志中占据的位置排序。 日志是一个字符串`R`,`S`， 和`P`，但游戏回合之间的界限已被消除。 

一轮由当前留在相关组中的每个车手进行，因此如果当前组包含`k`司机，确切地说`k`连续的字符属于该轮。 如果所有三个迹象都出现，或者所有迹象都相同，则没有人被淘汰，同一组再次比赛。 如果恰好有两个迹象出现，则根据通常的石头剪刀布规则，其中一个迹象就会失败。 每个显示出丢失标志的驾驶员都会成为候选者，只有这些候选者才能继续当前的淘汰过程。 当该过程仅留下一名驾驶员时，该驾​​驶员将离开路线，并且前一组将在没有他们的情况下恢复。 

任务是从日志中重构这个过程，并输出最终剩余的驱动程序的编号。 如果日志不能描述完整的合法的游戏顺序，答案是`FAIL`。 

关键的困难在于日志没有明确说明回合结束的位置。 幸运的是，一轮的长度并不是未知的。 正是当前组中驾驶员的数量。 一旦遇到决定性的一轮，失败的标志决定下一组，因此其大小也是已知的。 

驾驶员数量最多为`100`，所以描述当前游戏的状态很小。 但是，日志最多可以包含一百万个字符。 这排除了日志长度中的任何指数，并使日志的线性扫描成为自然目标。 的小值`n`也意味着复制或过滤一组驱动程序的成本很低。 

一些边缘情况可能会使粗心的实现失效。 例如，```
2
RRRR
```必须产生`FAIL`。 每轮都包含两个等号，因此每一轮都是平局，没有人离开。 仅处理可用字符直到字符串结束的解决方案可能会错误地报告剩余的驱动程序。 

另一种情况是包含所有三个标志的回合：```
3
RSP
```这是平局，不是淘汰。 日志随后立即结束，所以正确答案是`FAIL`。 将两个不同迹象的存在视为足以消灭某人在这里是错误的。 

一个不太明显的情况是决定性的一轮，其中失败的标志只出现一次：```
2
RP
```

`R`输给`P`，所以驱动程序`1`叶子和司机`2`是最后的幸存者。 正确的输出是`2`。 在这种情况下，假设决定性回合总是留下至少两名候选人的解决方案将失败。 

最后，一个完整的游戏不能有未使用的日志字符：```
2
RPRP
```第一轮就已经决定了比赛的胜负，因为`R`输给`P`。 司机`1`叶子和司机`2`赢了，所以额外的`RP`使日志无效。 答案是`FAIL`。 

## 方法

 暴力解决方案可以将丢失的轮次边界视为未知，并尝试将日志的每个可能的分区划分为轮次，模拟每个候选分区。 一个长度的字符串`L`有`2^(L-1)`在相邻字符之间放置边界的可能方法。 模拟一个分区需要`O(L)`，所以这种方法需要`O(L * 2^L)`在最坏的情况下工作。 为了`L = 1,000,000`，甚至可能的分区数量本身就比任何可行的操作数量都要大得多。 

这种蛮力是不必要的，因为游戏本身决定了每个边界。 在任何时刻，当前组的大小都是已知的`k`，所以下一轮必须正好占据下一个`k`人物。 我们可以立即检查该轮。 一画离开`k`不变。 决定性的一轮给了我们失败的标志，因此通过该标志过滤当前组给出了必须继续淘汰的确切组。 

简单的迭代模拟必须保留一种状态。 当一个较小的失败组被解决时，我们暂时离开了它的父组。 一旦该较小的组产生了一名被淘汰的车手，父组必须在删除该车手的情况下恢复比赛。 这自然由父组堆栈来表示。 

生成的算法仅消耗每个日志字符一次。 涉及驱动组的操作只需要`O(n)`每个消除级别最多有`n-1`消除。 自从`n <= 100`，这个额外的工作可以忽略不计。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(L · 2^L)`|`O(L)`| 太慢了|
 | 最佳 |`O(L + n^2)`|`O(n^2)`| 已接受 |

 这里`L`是对数长度，`n`是司机的数量。 

## 算法演练

 1. 从当前包含驱动程序的组开始`1, 2, ..., n`。 维护一个指针`pos`到日志的下一个未读字符。 当前组始终按照其驱动程序写入标志的顺序存储。 
2. 准确取`len(current)`日志中的字符。 如果剩下的字符较少，则日志在一轮中间结束，因此日志无效，答案为`FAIL`。 
3. 确定本轮出现哪些标志。 如果只有一个明显的标志，则该轮为平局，当前组不变。 进步`pos`根据小组规模并进行另一轮。 
4. 如果这三个迹象全部出现，则该轮比赛也为平局。 再次，前进`pos`按组大小调整而不更改当前组。 
5. 如果恰好有两个符号出现，则确定哪个符号失败。 对于成对的`R,S`,`S,P`， 和`P,R`，损失符号分别为`S`,`P`， 和`R`。 
6. 过滤当前组，精确保留符号等于失败符号的驱动程序。 这些就是继续淘汰的候选人。 在替换当前组之前，请将旧组压入堆栈，因为在消除完成后它必须恢复。 
7. 如果新组包含至少两个驱动程序，则继续以完全相同的方式进行处理。 每一个决定性的回合都会严格减少组的大小，因此这个嵌套过程不能无限期地继续下去。 
8. 如果新组中包含一名车手，则该车手已被确定为当前淘汰赛中失败并离开车库的车手。 从堆栈中弹出父组并从中删除该驱动程序。 然后父组再次成为当前组。 
9. 当当前组仅包含一名车手且没有剩余父组时，该车手为最终获胜者。 该日志仅在以下情况下有效`pos`正是`len(log)`。 任何剩余的字符都意味着录制的游戏包含额外的事件，所以答案是`FAIL`。 

为什么它有效：在每次迭代中，`current`正是按照正确的记录顺序进行下一轮比赛的车手组。 它的大小决定了唯一可能的下一轮边界。 平局会使该组保持不变，而决定性的一轮会唯一地确定失败的标志，因此通过该标志进行过滤可以准确地给出规则规定的候选人。 当该候选组到达一个驱动程序时，从保存的父组中删除该驱动程序将准确地重建递归消除开始之前的游戏状态。 因此，不变量在每次转换中都存在，并且当只剩下一个根级驱动程序时，该驱动程序必然是最终的获胜者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    log = input().strip()

    pos = 0
    current = list(range(1, n + 1))
    stack = []

    while True:
        k = len(current)

        if k == 1:
            winner = current[0]

            if stack:
                parent = stack.pop()
                parent.remove(winner)
                current = parent
                continue

            if pos == len(log):
                return str(winner)

            return "FAIL"

        if pos + k > len(log):
            return "FAIL"

        round_ = log[pos:pos + k]
        pos += k

        signs = set(round_)

        if len(signs) == 1 or len(signs) == 3:
            continue

        if signs == {"R", "S"}:
            loser = "S"
        elif signs == {"S", "P"}:
            loser = "P"
        else:
            loser = "R"

        next_group = [
            player
            for player, sign in zip(current, round_)
            if sign == loser
        ]

        stack.append(current)
        current = next_group

print(solve())
```这`current`list 存储实际的驱动程序编号而不仅仅是驱动程序的数量。 这是必要的，因为最终答案取决于身份，而不仅仅是剩余群体的规模。 

这`pos`变量始终指向尚未分配给回合的第一个字符。 表达式`log[pos:pos + k]`之所以有效，正是因为每一轮都包含当前组中每位车手的一个标志。 

这组符号区分了三种可能的圆形类型。 一个不同的标志意味着一致平局，三个不同的标志意味着三路平局，两个不同的标志意味着淘汰。 

对于决定性的一轮比赛，`zip(current, round_)`将每个记录的标志与相应的驱动程序相关联。 过滤`loser`为递归消除构造精确的候选组。 驱动程序的顺序被保留，这很重要，因为日志编号是基于记录顺序的。 

堆栈存储父组。 只有当决定性的一轮产生较小的小组时，家长才会被推动。 一旦该较小的组到达一个驱动程序，该驱动程序就会从父级中删除，并且父级将恢复。 由于最大嵌套深度仅为`n-1`，堆栈的安全边界为`99`元素。 

Python中不存在整数溢出问题，并且所有索引都由`pos + k > len(log)`。 最终平等`pos == len(log)`也是必要的，因为成功找到获胜者并不会使超长的日志变得有效。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(L + n^2)`| 每个日志字符被处理一次，而过滤和删除驱动程序的成本最多`O(n^2)`总体 |
 | 空间|`O(n^2)`| 堆栈包含嵌套组，每个组的大小最多`n`|

 和`L <= 1,000,000`和`n <= 100`，主要工作是对日志的单次传递。 与驱动程序相关的状态很小，因此该解决方案可以轻松满足 64 MB 内存限制。

## 边缘情况

 对于全平等的情况，```
2
RRRR
```该算法消耗`RR`，识别一个独特的符号，并保持`[1, 2]`。 然后它消耗另一个`RR`到达终点时仍有两名司机在场。 由于没有父组，也没有单一的获胜者，算法返回`FAIL`。 

对于三路抽签来说，```
3
RSP
```当前组是`[1, 2, 3]`，唯一的一轮是`RSP`。 它的符号集大小为 3，因此算法使该组保持不变。 日志结束，同时剩下三个驱动程序，这会正确生成`FAIL`。 

对于单身失败组来说，```
2
RP
```该轮包含`R`和`P`。 Rock 输了，所以下一组是车手`1`。 当前组已达到规模一，因此 driver`1`从其父级中删除`[1, 2]`。 父母成为`[2]`，并且由于日志已被完全消耗，驱动程序`2`作为获胜者返回。 

对于额外的字符，```
2
RPRP
```第一个`RP`已经消除了驱动程序`1`，离开司机`2`作为最后的幸存者。 然后算法检查`pos`对照日志长度并找到两个未使用的字符。 由于合法的完整游戏不能包含确定获胜者后的事件，因此它会返回`FAIL`。 

最大长度情况强调不同的边界。 该算法从不假设日志长度接近`n`，并且它从不尝试枚举可能的圆形边界。 每轮消耗的大小恰好是当前组的大小，因此即使是近一百万个字符也可以通过相同的确定性状态转换来处理。
