 ## 解决方案
 ## 问题理解

 我们有两辆独立的小巴。 在08:00至09:00的一小时间隔内，每辆小巴恰好到达路口一次，其到达时间均匀分布在每小时的3600秒内。 

交通灯在时间 0 处开始呈绿色。绿色持续`g`秒，红色持续`r`秒，并且这种模式会重复。 当两辆小巴在红灯亮时到达时，一场危险的比赛就开始了，更具体地说，两辆小巴都在同一个红灯阶段等待。 如果它们在不同的红色阶段到达，它们就不会相遇，也不会发生竞赛。 

输入包含`g`和`r`，均在 1 到 3600 之间。输出是两个到达时间属于同一红色区间的概率。 

3600 的上限足够小，即使几千次操作也微不足道。 然而，最有用的解决方案不需要模拟每一秒或每对到达时间。 周期性结构使我们能够将整个概率计算减少到恒定数量的算术运算。 由于所需的误差仅为`10^-6`，普通双精度浮点就绰绰有余了。 

主要的边缘情况来自这样一个事实：一小时的观察间隔不一定在交通灯周期结束时结束。 例如，与`g = 3600`和`r = 1`，整个小时都是绿色的，所以答案正是`0`。 假设一小时内至少有一个完整的红色阶段的粗心公式会错误地添加红色间隔。 

另一个边界情况是`g = 3000`,`r = 1000`。 第一个周期持续 4000 秒。 在我们的 3600 秒观察窗口中，前 3000 秒灯光为绿色，仅最后 600 秒灯光为红色。 正确的概率是`600^2 / 3600^2 = 1 / 36 ≈ 0.0277777778`。 

始终添加完整红色区间长度的解决方案`r`对于最后一个循环将使用`1000^2`而不是`600^2`并给出错误的答案。 

最小可能的输入是`g = 1`,`r = 1`。 每小时有 1800 个完整周期，每个红色区间的长度为 1。概率为`1800 / 3600^2 = 1 / 7200 ≈ 0.000138888889`。 

这种情况很有用，因为它既检查周期计数，又检查答案可能非常小这一事实。 

## 方法

 直接方法可以将小时划分为 3600 个一秒间隔，并检查每个有序的到达秒对。 有`3600 * 3600 = 12,960,000`最坏情况下成对。 对于每一对，我们可以确定这两秒是否属于同一个红色阶段。 这在概念上是正确的，因为交通灯状态在每个开放的一秒间隔内是恒定的，并且对于连续分布的到达时间，精确边界的概率为零。 然而，近 1300 万对检查是不必要的，并且不适合最初的 0.5 秒限制。 

蛮力的想法之所以有效，是因为我们最终测量的是可能到达时间的平方的面积。 设第一个到达的为`x`第二个是`y`。 由于两者在 3600 秒内都是一致的，所以每个点`(x, y)`在广场上`[0, 3600] × [0, 3600]`具有均匀的概率密度。 比赛发生时`x`和`y`位于同一个红色区间内。 

这一观察给出了关键的简化。 假设一个红色区间有长度`L`。 两个到达时间必须独立地落入该间隔内，因此`(x, y)`平面是一个有边的正方形`L`和面积`L²`。 不同的红色间隔产生不相交的正方形。 因此，如果小时内的红色间隔有长度`L1, L2, ...`，总有利面积为`L1² + L2² + ...`。 

所有可能对的总面积是`3600²`，所以答案是`(L1² + L2² + ...) / 3600²`。 

所有完整的交通灯周期都恰好包含一个红色间隔的长度`r`。 如果小时包含`q`完整的循环，他们贡献`q * r²`。 最后也可能有一个不完整的循环。 让`rem`是完整循环后剩余的秒数。 第一个`g`剩余的秒数为绿色。 仅有的`max(0, rem - g)`秒可以属于红色，因此不完整的周期贡献了该长度的平方。 

这样整个计算就变成了常数时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3600²) | O(1) | O(1) | 对于严格的限制来说太慢了 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将观察长度设置为`T = 3600`秒和交通灯周期长度`cycle = g + r`。 划分`T`经过`cycle`给出数字`q`完全包含在一小时内的完整周期。 
2. 计算`rem = T % cycle`。 这是一小时结束时不完整周期的长度。 如果`rem <= g`，整个余数都是绿色的，因此它对竞争概率没有任何贡献。 
3.如果`rem > g`, 第一个之后的部分`g`不完整周期的秒数为红色。 它的长度是`rem - g`。 这个红色部分贡献`(rem - g)²`到有利区域。 
4. 每一个`q`完整的周期包含长度为红色的区间`r`。 他们共同做出贡献`q * r²`。 
5. 将全部和部分贡献相加并除以`T²`。 分子是引起竞争的所有到达时间对的面积，而分母是所有可能的到达时间对的面积。 
6. 打印得到的浮点值，其中包含足够的位数以满足要求`10^-6`容错性。 

### 为什么它有效

 对于每个长度的红色区间`L`，当两个独立的到达时间落在同一时间间隔内时，一场竞赛恰好发生。 在到达时间对的二维空间中，这些可能性形成面积的平方`L²`。 属于不同红色区间的正方形是不相交的，因此可以将它们的面积相加。 该算法精确计算与一小时窗口相交的每个红色间隔的长度，包括可能被截断的最终间隔。 将它们的长度平方除以总面积`3600²`因此准确给出了所需的概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

T = 3600

def solve():
    g, r = map(int, input().split())

    cycle = g + r
    full_cycles = T // cycle
    rem = T % cycle

    favorable = full_cycles * r * r

    partial_red = max(0, rem - g)
    favorable += partial_red * partial_red

    answer = favorable / (T * T)
    print(f"{answer:.12f}")

if __name__ == "__main__":
    solve()
```前三个整数计算确定如何将小时划分为完整和不完整的交通灯周期。 自从`g`和`r`是整数且最多 3600，在 Python 中不存在整数溢出的危险，并且相同的算术在标准 64 位整数实现中也是安全的。 

表达式`max(0, rem - g)`处理最后的部分循环。 如果余下的比赛在绿色期间结束，`rem - g`为负数，但没有红色区间可计数。 将其钳位到零可以避免意外添加正平方。 

乘以`r * r`在转换为浮点之前发生。 这使得几何计算在最终除法之前保持精确。 最终答案以小数点后 12 位打印，比要求的精度高得多`10^-6`。 

红绿灯边界本身不需要特殊处理。 在连续均匀分布下，单个精确时间（例如绿色变为红色的瞬间）的概率为零，因此无论将该端点分配给一个相还是另一相都不能改变答案。 

## 工作示例

 ### 示例 1

 对于`g = 1800`和`r = 1800`，一个完整的周期正好持续 3600 秒。 整个一小时由一个绿色间隔和一个红色间隔组成。 

| 变量| 价值|
 | --- | --- |
 |`T`| 3600 | 3600
 |`cycle`| 3600 | 3600
 |`full_cycles`| 1 |
 |`rem`| 0 |
 |`partial_red`| 0 |
 |`favorable`| 3,240,000 | 3,240,000
 |`answer`| 0.25 | 0.25

 唯一的红色区间长度为 1800，因此有利区域为`1800² = 3,240,000`。 总到达时间区域为`3600² = 12,960,000`, 给予`3,240,000 / 12,960,000 = 0.25`。 

### 示例 2

 对于`g = 2700`和`r = 3600`，一个完整的周期持续 6300 秒，比整个小时还要长。 不存在完整的循环。 在第一个周期的 3600 秒处，一小时结束，经过 2700 秒的绿色，剩下 900 秒的红色。 

| 变量| 价值|
 | --- | --- |
 |`T`| 3600 | 3600
 |`cycle`| 6300 |
 |`full_cycles`| 0 |
 |`rem`| 3600 | 3600
 |`partial_red`| 900 | 900
 |`favorable`| 810,000 |
 |`answer`| 0.0625 | 0.0625

 有利区域是`900² = 810,000`。 除以`3600²`给出`0.0625`。 

这些痕迹说明了为什么必须单独处理部分循环。 在第一个示例中，恰好有一个完整的周期，没有剩余。 在第二个示例中，根本没有完整的周期，但一小时的最后部分包含大量的红色间隔。

 ## 边缘情况

 对于`1 1`，周期长度为2，所以`3600 // 2 = 1800`完整的周期和`rem = 0`。 每个红色区间的长度为 1，给出有利区域`1800 * 1² = 1800`。 结果是`1800 / 12,960,000 = 0.000138888889`。 该算法永远不需要迭代这 1800 个周期。 

为了`3600 3600`，循环长度为 7200，因此完整循环数为零，`rem = 3600`。 由于余数正是绿色持续时间，`partial_red = max(0, 3600 - 3600) = 0`。 答案是零。 这捕获了意外地将绿色端点视为正长度红色间隔的实现。 

为了`3600 1`，周期长度为 3601。同样，完整周期为零，并且 3600 秒的观察恰好在第一个红色阶段开始前一秒结束。 部分红色长度为`max(0, 3600 - 3600) = 0`，所以答案为零。 

为了`3000 1000`，周期长度为 4000。该小时包含前 3000 秒绿色，然后 600 秒红色。 因此`full_cycles = 0`,`rem = 3600`， 和`partial_red = 600`。 有利区域是`600² = 360,000`，生产`360,000 / 12,960,000 = 0.027777777778`。 这是主要的差一样式情况，因为可见红色间隔比配置的红色持续时间短。 

为了`1000 2000`，周期长度为 3000。一小时包含一个完整周期和 600 秒的剩余时间。 剩余部分仍在下一个绿色阶段内，因此它没有任何贡献。 唯一有利的区域来自长度为 2000 的完整红色区间，给出`2000² / 3600² = 0.308641975309`。 这证实了余数不应仅仅因为它存在而被计算在内，只有绿色阶段之后的部分才重要。
