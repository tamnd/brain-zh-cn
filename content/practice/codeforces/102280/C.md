 ## 解决方案
 ## 问题理解

 有 (n) 名司机和 (n) 辆瞪羚车。 每个驾驶员恰好收到一辆车，并且每辆车都被分配给恰好一个驾驶员，因此分配是汽车的排列。 

如果司机收到自己的汽车，则被称为固定司机。 该条件规定，在任何选定的 (k) 名驾驶员中，至少有一名驾驶员必须驾驶其他人的汽车。 同样，不可能找到 (k) 个都拥有自己汽车的司机。 

这给出了一个更简单的公式：排列最多可以包含 (k-1) 个固定点。 我们需要计算 (n) 个元素的所有排列，最多具有 (k-1) 个固定点，模 (10^9+7)。 

原始语句在提供的文本中存在格式问题：示例合并在一起。 官方竞赛页面给出的样本为 (4\ 2 \to 17) 和 (30\ 1 \to 568643488)。 

约束允许 (n) 达到 1000。这立即排除了涉及所有排列的任何内容，因为 (1000!) 远远超出了任何可行的操作数量。 即使 (O(n^2)) 解决方案也只能执行大约一百万次基本迭代，而 (O(n!)) 对于小至几十的 (n) 来说已经是不可能的了。 0.5 秒的限制也使得简单的 (O(n^2)) 动态程序在 Python 中缺乏吸引力，因此 (O(n)) 解决方案更可取。 

有几种边界情况很容易处理不当。 对于 (n=1,k=1)，唯一的分配给驾驶员自己的汽车，因此条件失败，答案为 (0)。 一个粗心的实现简单地为 (k=n) 返回 (n!) 也是错误的。 例如，对于（n=2，k=2），两个驾驶员不能同时接收自己的汽车，因此只有交换才有效，答案是（1），而不是（2）。 更一般地，当 (k=n) 时，除了恒等式之外的每个排列都是有效的，给出 (n!-1)。 在另一个极端，(k=1) 意味着即使是一个驾驶员也不允许拥有自己的汽车，因此每个有效的分配都必须是一种混乱。 例如，(n=3,k=1) 恰好有两个有效排列。 

## 方法

 直接暴力方法是生成 (n) 辆车的每个排列，计算有多少个位置是固定的，如果该数字小于 (k)，则保留排列。 这是正确的，因为汽车的每种可能的分布在 (n!) 种排列中只出现一次，并且条件仅取决于固定位置的数量。 在最坏的情况下，如果我们明确检查每个排列的所有 (n) 个位置，则工作量为 (n\cdot n!)。 对于(n=1000)，即(1000\cdot1000!)位置检查，这是完全不可行的。 

有用的观察结果是，具有规定数量的固定点的排列具有标准的组合结构。 假设 (i) 司机收到了自己的汽车。 我们可以以 (\binom ni) 方式选择那些 (i) 驱动程序。 修复它们后，剩下的（n-i）个驾驶员必须都收到不同的驾驶员的车，因为否则就会有另一个固定点。 因此，剩余的分配是 (n-i) 个元素的排列。 

令(D_m)表示(m)个元素的排列数量。 恰好具有 (i) 个固定点的排列数为

 [
 \binom ni D_{n-i}。 
]

 由于我们最多允许 (k-1) 个固定点，所以答案变为

 [
 \sum_{i=0}^{k-1}\binom ni D_{n-i}。 
]

 剩下的任务是有效地评估这个总和。 混乱满足重现

 [
 D_m=(m-1)(D_{m-1}+D_{m-2}),
 ]

 其中（D_0=1）和（D_1=0）。 因此，直到 (n) 的所有紊乱值都可以在 (O(n)) 中计算。 

我们还需要 (0\le i<k) 的所有二项式系数 (\binom ni)。 由于 (n\le1000)，我们可以预先计算模逆并使用更新当前二项式系数

 \binom n{i-1}\frac{n-i+1}{i}。 
]

因为每个 (i\le1000) 都小于素数模 (10^9+7)，所以 (i) 的模逆存在。 这给出了另一个 (O(n)) 计算。 

蛮力方法之所以有效，是因为它直接检查定义，但会失败，因为排列的数量呈阶乘增长。 观察到只有固定点的数量才重要，这让我们可以将指数级的排列分成 (n) 个组合类别，而混乱循环让我们可以在线性时间内评估这些类别。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n\cdot n!)) | (O(n)) | (O(n)) | 太慢了|
 | 最佳 | (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 阅读(n)和(k)。 所需的排列正是具有少于 (k) 个固定点的排列。 
2. 计算乱序数组 (D)。 设置（D_0=1）和（D_1=0）。 对于每个 (m\ge2)，使用 (D_m=(m-1)(D_{m-1}+D_{m-2})) 模 (10^9+7)。 这种循环计算了没有人保留原来的汽车的排列。 
3. 预先计算从 (1) 到 (n) 的模逆。 由于模数是素数且 (n<10^9+7)，因此该范围内的每个数字都具有模数的倒数。 
4. 从 (\binom n0=1) 开始。 对于从 (0) 到 (k-1) 的每个 (i)，添加
 [
 \binom niD_{n-i}
 ]
 到答案。 该术语首先准确选择哪些（i）驾驶员保留自己的汽车，然后扰乱所有剩余的驾驶员，这样他们就不会被意外修复。 
5. 处理完 (i) 的当前值后，使用以下命令更新下一次迭代的二项式系数
 [
 \binom n{i+1}
 =
 \binom ni\frac{n-i}{i+1}。 
]
 所有乘法和除法均使用预先计算的模逆来执行模 (10^9+7)。 

### 为什么它有效

 考虑任何有效的排列并使其恰好具有 (i) 个不动点。 这些固定点可以精确地 (\binom ni) 方式选择。 一旦他们被选中，剩下的（n-i）个司机就不能拥有自己的汽车，否则排列将有超过（i）个固定点。 因此，他们的汽车形成了一种混乱，恰好给出了 (D_{n-i}) 种可能性。 因此 (\binom niD_{n-i}) 对具有正好 (i) 个固定点的每个排列进行一次且仅一次的计数。 对 (i=0,\ldots,k-1) 的数量求和可以精确计算原始条件允许的排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, k = map(int, input().split())

    # D[i] = number of derangements of i elements.
    der = [0] * (n + 1)
    der[0] = 1

    if n >= 1:
        der[1] = 0

    for i in range(2, n + 1):
        der[i] = (i - 1) * (der[i - 1] + der[i - 2]) % MOD

    # Modular inverses of 1..n.
    inv = [0] * (n + 1)
    if n >= 1:
        inv[1] = 1

    for i in range(2, n + 1):
        inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

    # C(n, 0) = 1.
    comb = 1
    ans = 0

    for i in range(k):
        ans = (ans + comb * der[n - i]) % MOD

        if i + 1 < k:
            comb = comb * (n - i) % MOD
            comb = comb * inv[i + 1] % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```这`der`array 实现了算法的混乱重现。 初始化`der[0] = 1`即使原始问题至少有一个驱动因素，也是必要的，因为在计算 (D_2) 时递归达到 (D_0)。 

逆数组使用标准素数模数递推

 MOD-\left\lfloor\frac{MOD}{i}\right\rfloor
 \operatorname{inv}(MOD\bmod i)\pmod{MOD}。 
]

 当前值`comb`始终 (\binom ni) 位于循环的开头。 在计算下一个系数之前更新答案，因此循环恰好包含 (i=0,\ldots,k-1)。 该边界是该问题中主要的差一细节。 

Python 整数不会溢出，但所有值在相乘后都会按模 (10^9+7) 减少。 减少使中间值保持较小并反映问题所需的算术。 

更新内容```
comb = comb * (n - i) % MOD
comb = comb * inv[i + 1] % MOD
```相当于

 \binom ni\frac{n-i}{i+1}。 
]

 对值取模后使用普通整数除法`MOD`是不正确的。 需要模逆是因为模除法不是普通的整数除法。 

## 工作示例

 对于第一个样本，(n=4,k=2)。 我们可能有零个或一个固定点。 

| (一) | (\binom{4}{i}) | (D_{4-i}) | 贡献 | 运行答案|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 9 | 9 | 9 |
 | 1 | 4 | 2 | 8 | 17 | 17

 值 (D_4=9) 计算没有人拥有自己的汽车的分配。 对于恰好一个固定点，我们以 (4) 种方式选择该驱动程序，并以 (D_3=2) 种方式扰乱其余三个驱动程序。 总数为（9+8=17），与官方样本相符。 

对于第二个样本，(n=30,k=1)。 由于循环仅包含 (i=0)，因此没有驾驶员可以接收自己的汽车。 

| (一) | (\binom{30}{i}) | (D_{30-i}) | 贡献 | 运行答案|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | (D_{30}) | (D_{30}) | 568643488 |

 问题已直接减少到混乱计数（D_{30}）。 计算递归模 (10^9+7) 给出 (568643488)，这是官方的第二个样本输出。

 ## 边缘情况

 当 (n=1,k=1) 时，唯一的排列是`[1]`。 它有一个固定点，但最大允许数量为（k-1=0）。 该算法计算 (D_1=0)，仅在 (i=0) 时进入循环，并添加 (D_1)，产生`0`。 输入是`1 1`。 

当(k=1)时，求和在(i=0)之后立即停止。 答案正是（D_n），因为允许零个固定点，但已经禁止一个固定点。 为了`3 1`，两个有效排列是由下式表示的循环分配`2 3 1`和`3 1 2`，因此算法返回 (D_3=2)。 

当(k=n)时，允许的固定点数为(n-1)。 除恒等式外，每个排列最多有 (n-1) 个固定点，因此答案必须是 (n!-1)。 为了`2 2`，这两种排列是恒等和交换，只留下一个有效的赋值。 求和计算出 (D_2+\binom21D_1=1+0=1)，这与这种解释一致。 

恰好允许 (k-1) 个固定点的情况也是一个差一陷阱。 为了`5 3`，我们需要零、一或两个固定点，而不是零、一、二或三个。 贡献是 (D_5=44)、(5D_4=45) 和 (\binom52D_3=20\cdot2=40)，给出`129`如果只使用前三个贡献。 正确的总数实际上是 (44+45+40=129)，因此这种情况可以有效检查组合项是否正确形成。 将条件解释为“至多 (k) 个固定点”的粗心实现将另外包括 (\binom53D_2=10)，从而错误地生成`139`。 

对于最大情况`1000 1000`，该算法从不构造排列，也从不使用阶乘大小的对象。 它计算高达 (D_{1000}) 的排列，一次生成一个二项式系数，并执行 1000 个求和步骤。 由于 (k=n)，数学答案是 (1000!-1) modulo (10^9+7)，即`641419707`。 这既锻炼了最大允许输入，又锻炼了定点条件的精确上限。
