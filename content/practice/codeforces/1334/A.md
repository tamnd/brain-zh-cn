 ## 解决方案
 ## 问题理解

 我们多次观察游戏关卡的统计数据。 在每次观察中，我们都知道两个值：关卡已玩了多少次以及已通关了多少次。 

一次成功的尝试会使两个数字同时增加一。 失败的尝试只会增加播放次数。 在两次观察之间，任何数量的玩家都可能尝试过该级别，包括零个玩家。 

对于每个测试用例，我们必须确定记录的序列是否真的会发生。 如果一些成功和不成功的尝试序列按时间顺序准确地产生了这些观察结果，我们打印`"YES"`。 否则我们打印`"NO"`。 

限制很小。 最多有 500 个测试用例，每个测试用例最多包含 100 个观察值。 即使是比较每对观察值的算法也能轻松运行。 不需要复杂的数据结构或优化。 对观察结果进行线性扫描就足够了。 

微妙的部分是理解打球和清球之间的关系。 有几种看似无害的情况实际上是不可能的。 

假设游戏次数保持固定，而清除次数增加。 

输入：```
1
3
0 0
1 1
1 2
```正确答案是：```
NO
```新的清除总是来自于新的玩法，因此清除的增量永远不会超过玩法的增量。 如果粗心的解决方案仅检查两个序列是否非递减，则会错误地接受这种情况。 

另一个棘手的情况是当清除总数超过游戏总数时。 

输入：```
1
1
3 5
```答案是：```
NO
```五次成功的尝试至少需要五次比赛。 

另一个陷阱是降低值。 

输入：```
1
3
10 2
15 3
14 3
```答案是：```
NO
```统计数据只会随着时间的推移而增加。 任何减少都会立即使记录变得不可能。 

## 方法

 强力解释将尝试重建观察之间的每一次尝试。 如果播放次数增加 1000 次，我们可以想象将这 1000 次尝试分为成功和不成功的所有可能方式。 这种方法是正确的，因为它明确地模拟了该过程，但可能的历史数量随着尝试次数呈指数增长。 即使一个时段有 1000 场新比赛，也已经拥有了巨大的可能性。 

关键的观察是我们永远不需要知道成功和失败的确切顺序。 只有三个条件很重要。 

首先，戏份不能减少。 

其次，清除不能减少。 

第三，每当我们从一个观察转向下一个观察时，新清除的数量不能超过新播放的数量。 每一次成功的尝试都会贡献一次进攻和一次清球，因此获得五次额外的清球需要至少五次额外的比赛。 

同样的想法也适用于第一个观察。 在任何时候，清除的总数都不能超过游戏的总数。 

一旦检查了每一对连续的这些条件，答案就确定了。 单个无效对使得整个记录不可能。

 ## 算法演练

 1. 阅读当前测试用例的所有观察结果。 
2. 检查第一个观察结果。 如果清除次数超过播放次数，则答案为`"NO"`因为每一场比赛都必须来自一场比赛。 
3. 从左到右遍历观察值。 
4. 对于每对连续观察，计算出局和清除的变化。 
5. 如果播放量减少，记录就不可能了，因为统计数据永远不会倒退。 
6. 如果清除减少，则由于同样的原因无法进行记录。 
7. 如果清除次数的增加大于播放次数的增加，则记录不可能。 成功的尝试次数不会超过总尝试次数。 
8. 如果这些检查都没有失败，则打印`"YES"`。 

### 为什么它有效

 在处理任何一对连续观测值后，该算法保持不变，即存在至少一个尝试序列，产生迄今为止看到的所有观测值。 

当从一个观察转向下一个观察时，唯一重要的信息是出现了多少新的戏剧和新的清除。 只要两个数量都是非负的，并且新清除的数量不超过新游戏的数量，我们就可以将这些新清除解释为成功的尝试，将剩余的新游戏解释为失败的尝试。 因此，有效的扩展始终存在。 如果违反了这些条件中的任何一个，则任何尝试序列都无法解释该转变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    records = [tuple(map(int, input().split())) for _ in range(n)]

    ok = True

    if records[0][1] > records[0][0]:
        ok = False

    for i in range(1, n):
        prev_p, prev_c = records[i - 1]
        cur_p, cur_c = records[i]

        dp = cur_p - prev_p
        dc = cur_c - prev_c

        if dp < 0 or dc < 0 or dc > dp:
            ok = False

    print("YES" if ok else "NO")
```该解决方案首先读取一个测试用例的所有观察结果。 将它们保留在列表中可以使成对比较变得简单。 

第一个观察值得特殊对待。 如果关卡的通关次数已经多于播放次数，则在考虑任何转换之前就不可能进行记录。 

对于每一对连续的对，我们计算出局数和清除数的增加。 负差异意味着某些统计数据减少，但这是不可能发生的。 条件`dc > dp`捕捉更微妙的情况，即新完成的运行数量超过新开始的运行数量。 

检查的顺序并不重要，因为任何违规都会产生答案`"NO"`。 发现错误后无需立即停止，尽管这样做也可以。 

由于所有值最多为 1000，因此在 Python 中整数溢出不是问题。

```现在考虑这样一种情况，第一次观察就已经违反了基本要求。 

输入：```

```在进入循环之前，算法会检查清除是否超出播放次数。 这里`5 > 3`，因此它立即将测试用例标记为无效并打印：```
NO
```最后，考虑减少统计数据。 

输入：```
