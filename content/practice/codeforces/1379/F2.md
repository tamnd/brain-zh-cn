 ## 解决方案
 ## 问题理解

 我们正在研究一个非常大的网格$2n \times 2m$，但我们只关心白色单元格，即那些坐标之和为偶数的单元格。 在这些白色单元格中，有些单元格会通过一系列更新在可用和不可用之间动态切换。 

每次更新后，我们需要决定是否可以准确选择$n \cdot m$白色单元格，使得没有两个选定的单元格相邻，包括对角线。 换句话说，没有两个选定的单元可以共享边缘或角。 

这是图上的打包问题：每个白色单元格都是一个顶点，边连接切比雪夫距离 1 内的单元对。我们被问到是否可以选择一组大小$n \cdot m$在当前可用的顶点内形成一个独立的集合。 

关键的限制是董事会很大并且更新最多$2 \cdot 10^5$，因此在每次切换后重新计算最大独立集是不可能的。 任何甚至触及每个查询的所有单元格的解决方案都会立即变得太慢。 我们被迫采用一种结构，其中每次更新都以大致对数或摊销对数时间进行处理。 

当可用单元形成几乎完整的有效配置（除了两个单元对角相邻的小区域之外）时，会出现微妙的边缘情况。 尽管对角邻接感觉比边邻接弱，但它在这里同样被禁止，而这正是朴素贪婪构造失败的地方。 例如，在一个$2 \times 2$白色单元格（由于奇偶校验限制而交替），如果保留任意两个对角相邻的单元格，则不可能选择三个单元格，即使局部计数表明可行性。 

困难在于约束并不纯粹基于局部度； 它编码具有严格容量限制的全局奇偶校验二分结构。 

## 方法

 如果我们忽略效率，自然的想法是在每次切换后从头开始重新计算可行性。 我们构建可用白细胞的图，计算最大独立集或等效的最小顶点覆盖，并将其与所需的大小进行比较$n \cdot m$。 这原则上是正确的，因为国王对应于国王图中的独立集合。 

然而，该图有$O(nm)$顶点和边，太大了。 即使每个查询进行单个最大匹配或流计算也是不可能的。 

关键的观察结果是，棋盘上的王图可以分解为一种结构，将问题简化为检查某个二分匹配是否饱和固定目标。 这种转换来自于在旋转坐标系中查看棋盘：我们不是在正方形上工作，而是将约束映射到网格中，其中邻接对应于一小组方向边，并且可行性条件变为削减容量条件。 

这个问题的一个经典结果是，我们可以放置的国王的最大数量等于网格的大小减去派生二分图中最小顶点覆盖的大小。 由于该结构是平面的且局部一致，因此问题简化为维持某个动态切割值是否保持在阈值以下。 

在硬版本中，单元会切换，因此我们需要一个完全动态的结构。 关键的见解是，每个单元仅对少量局部约束做出贡献，而全局条件可以使用扫描结构表示为行和列上的贡献之和。 这允许随着时间的推移进行分而治之，并结合存储边活动间隔的线段树，其中每个边（冲突对）仅在两个端点都可用的查询间隔期间才处于活动状态。 

然后，我们在时间轴上运行分治法，维护具有回滚功能的 DSU，以跟踪由活动冲突引起的约束图中的连接组件。 可行性简化为检查二分组件结构是否违反固定界限。

 ## 算法演练

 我们用禁止对的方式重新解释这个问题。 如果两个白细胞在切比雪夫距离 1 内，则它们会互相攻击。这意味着每个细胞参与恒定数量的冲突边。 

我们动态跟踪可用性，因此每个单元在几个不相交的时间段内都处于活动状态。 对于两个白细胞之间的每个冲突边缘，我们确定它们的活动间隔的交集。 在这些时间间隔内，冲突图中的边处于“活动”状态。 

我们现在在查询索引上使用线段树来处理时间。 

1. 将每个单元格切换转换为活动间隔。 每个细胞都会在不活动和活动之间交替，因此我们会随着时间的推移存储其活动片段。 此步骤是必要的，因为边缘活动取决于两个端点同时处于活动状态。 
2. 对于相邻白单元之间的每个冲突边（包括对角邻接），计算其活动间隔的交集，并将该边插入到覆盖这些间隔的线段树节点中。 这将动态图转换为间隔分配边的静态集合。 
3、用DFS遍历线段树。 在每个节点上，维护一个具有回滚功能的 DSU，用于存储活动冲突图的连接组件。 
4. 当进入一个节点时，合并该节点存储的所有边。 这模拟激活在该时间段内有效的所有冲突。 
5. 如果我们处于查询时间对应的叶子，则计算当前结构是否违反可行性。 这减少了检查是否有任何组件违反了王包装边界隐含的二分平衡约束。 
6. 处理完线段树节点的子节点后，回滚在此节点上完成的所有 DSU 操作。 这确保了时间段之间的独立性。 

关键部分是 DSU 不仅跟踪连接性，还跟踪双方奇偶校验一致性。 每个联盟合并奇偶校验状态； 如果出现矛盾，则配置无效。 

### 为什么它有效

 冲突图准确地编码了国王的禁止邻接关系。 任何有效的放置都对应于从由邻接约束引起的每个封闭邻域区域中选择至多一个顶点。 二分结构确保可行性仅取决于连接组件内奇偶校验约束的一致性。 因为每条边在连续的时间间隔内都是活动的，所以线段树分解保证我们永远不会混合不一致的时间状态。 DSU 回滚通过确保独立评估每个间隔，同时仍然聚合所有相关约束来保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.parity = [0] * n
        self.stack = []
        self.bad = 0

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def unite(self, a, b):
        ra = self.find(a)
        rb = self.find(b)

        if ra == rb:
            if self.parity[a] == self.parity[b]:
                self.stack.append((-1, 0, 0, 0))
                self.bad += 1
            else:
                self.stack.append((-1, 0, 0, 0))
            return

        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
            a, b = b, a

        self.stack.append((rb, self.parent[rb], self.size[ra], self.parity[rb]))

        self.parent[rb] = ra
        self.parity[rb] = self.parity[a] ^ self.parity[b] ^ 1
        self.size[ra] += self.size[rb]

    def snapshot(self):
        return len(self.stack), self.bad

    def rollback(self, snap):
        t, bad0 = snap
        while len(self.stack) > t:
            rb, prev_parent, prev_size, prev_parity = self.stack.pop()
            if rb == -1:
                continue
            ra = self.parent[rb]
            self.size[ra] -= self.size[rb]
            self.parent[rb] = prev_parent
            self.parity[rb] = prev_parity
        self.bad = bad0

 ## 边缘情况

 关键的边缘情况是当只剩下几个单元格但它们形成对角邻接链时。 即使可用单元的数量等于所需的国王数量，该配置也是无效的。 该算法捕获了这一点，因为当同一组件中的两个单元需要相同的奇偶校验分配时，DSU 奇偶校验结构会检测到不一致。 

另一种边缘情况是重复切换同一单元，这会创建多个不相交的活动间隔。 如果没有线段树分解，简单的方法就会错误地合并这些约束并过度计数约束。 基于间隔的插入确保每个激活周期都被独立处理，防止时间段之间的泄漏。
