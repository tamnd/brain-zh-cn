 ## 解决方案
 ## 问题理解

 我们得到一条表示为单个字符串的街道。 每个字符描述一个停车位。 破折号表示该插槽空闲，而 X 表示该插槽已被阻止且无法使用。 

我们只能将车辆放入连续的空闲槽位中。 每辆汽车恰好占用一个插槽，一辆 SUV 恰好占用两个相邻的插槽，一辆卡车恰好占用四个相邻的插槽。 车辆不会重叠，也不能使用封锁位置。 任务是计算使用这三种车辆类型可以有多少种不同的方式完全填充所有空闲槽位。 

关键点是我们没有选择按顺序到达的特定车辆。 相反，我们用大小为 1、2 或 4 的图块来平铺空闲槽的每个最大连续段。如果至少一个槽被不同类型的车辆占用，则两次填充是不同的，这相当于将不同的分段划分为长度 1、2 和 4。 

输入可能包含多个这样的街道描述，每个描述都在单独的行上，并且我们必须每行输出一个整数：该行的有效配置数。 

每行最多 70 个字符的限制是关于复杂性的主要信号。 对所有布局进行简单的指数搜索将会失败，因为即使是 70 长度的空闲段也会有大量的分区。 相反，我们需要每个段的线性或最坏的二次动态规划。 由于 70 很小，即使每行 O(n²) 也是安全的，但结构表明标准线性递归就足够了。 

主要的边缘情况是阻塞的细胞如何分裂问题。 将整个字符串视为一个片段的简单方法会错误地允许车辆跨越 X 边界。 

例如，考虑`-X-`。 正确答案是 1，因为每一侧都是独立的，并且每个段只有一个单元格。 对整个字符串的天真的 DP 可能会错误地尝试将 2 长度的车辆放置在 X 上，这是无效的。 

另一个微妙的情况是段短于 4。例如`----`有多种可能性，但是`---`无法放置卡车，因此只有较小的组合才重要。 任何解决方案都必须严格遵守段边界。 

## 方法

 暴力解决方案会尝试从每个自由位置开始递归地放置车辆，并在合适的时候分支为尺寸 1、2 或 4 的选择。 这是正确的，因为它直接枚举所有有效的平铺。 然而，在长度为 n 的段中，每个位置的分支因子最多为 3，这在最坏的情况下导致大约 O(3ⁿ) 状态。 即使有记忆，如果不小心实现，它仍然会探索部分填充配置的大状态空间。 

关键的观察结果是，该问题具有最佳的子结构：一旦我们确定了空闲段的第一部分的填充方式，其余后缀就是独立的。 这将问题转化为一维平铺计数问题。 对于长度为 i 的前缀来说，唯一重要的是使用以 i 结尾的有效图块大小可以形成多少种方式。 

这将每个空闲段减少为简单的动态编程递归。 令 f[i] 为填充长度为 i 的空闲段的方法数。 最后放置的车辆的长度必须为 1、2 或 4，因此只要这些索引有效，最后一步就来自 f[i−1]、f[i−2] 或 f[i−4]。 这将指数分支折叠为线性扫描。 

然后我们将整条街分成 X 个街区。 每个最大自由段都是独立求解的，最终的答案是段结果的乘积，因为不同段中的选择不会相互作用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对展示位置进行强力递归 | 每段 O(3ⁿ) | O(n) 递归堆栈 | 太慢了|
 | 具有一维递归的分段 DP | 每段 O(n) | O(n) 或 O(1) | 已接受 |

 ## 算法演练

 1. 将输入字符串分割成最大连续块`-`。 每个块都是一个独立的子问题，因为 X 单元充当车辆无法跨越的硬分隔符。 
2. 对于每个长度为 L 的块，计算使用大小为 1、2 和 4 的车辆对其进行平铺的方式数。我们定义一个 DP 数组，其中 dp[i] 表示填充长度为 i 的前缀的方式数。 
3. 初始化 dp[0] = 1。这表示空前缀，只有一个有效配置。 
4. 对于从 1 到 L 的每个 i，通过考虑最后放置的车辆来计算 dp[i]。 如果我们放置一辆车，它会消耗一个槽并贡献 dp[i−1]。 如果我们放置一辆 SUV，它会消耗两个槽并贡献 dp[i−2]。 如果我们放置一辆卡车，它会消耗四个槽并贡献 dp[i−4]。 任何具有负索引的术语都会被忽略，因为它对应于无效的放置。 
5. 将此部分的结果乘以全局答案。 由于段是独立的，因此配置总数是所有段 DP 结果的乘积。 
6. 输出每条输入线的最终结果。 

### 为什么它有效

 正确性来自于以下事实：每个有效的平铺在每个前缀中都有唯一定义的最后一辆车。 任何长度为 i 的平铺都必须以允许的车辆尺寸之一结束，并且删除最后一辆车会留下较小前缀的有效平铺。 这会在长度为 i 的完整平铺与长度为 i−1、i−2 和 i−4 的平铺并集（通过一个最终放置扩展）之间创建双射。 由于没有车辆可以穿过 X，因此一个段中的配置不会影响另一个段，因此段之间具有独立性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(s: str) -> int:
    MOD = None  # no modulo in problem; values fit in 1e18

    n = len(s)
    ans = 1

    i = 0
    while i < n:
        if s[i] == 'X':
            i += 1
            continue

        j = i
        while j < n and s[j] == '-':
            j += 1

        length = j - i

        if length == 0:
            i = j
            continue

        dp = [0] * (length + 1)
        dp[0] = 1

        for k in range(1, length + 1):
            total = 0
            total += dp[k - 1]
            if k >= 2:
                total += dp[k - 2]
            if k >= 4:
                total += dp[k - 4]
            dp[k] = total

        ans *= dp[length]

        i = j

    return ans

def main():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        print(solve_case(line))

if __name__ == "__main__":
    main()
```该实现直接反映了分段逻辑。 外循环隔离空闲块，确保不会发生无效的跨块放置。 在每个块内，DP 是对允许的车辆尺寸的重复性的直接转换。 乘法步骤是安全的，因为最终答案保证符合规定的 10^18 范围内。 

一个常见的实现错误是忘记重置每个段的 DP，这会错误地混合独立块之间的状态。 另一个是当 k < 4 时意外地允许像 dp[k−4] 这样的转换，必须明确地保护它。

 ## 边缘情况

 对于完全阻塞的字符串，例如`XXXX`，该算法产生 1，因为没有空闲段，因此零段上的乘积仍为 1。这与存在一种不执行任何操作的方法的解释相匹配。 

对于像这样的字符串`-X--X---`，算法将其分成长度为1、2和3的段。每个段独立求解，最终答案是它们的DP结果的乘积。 这避免了任何意外的跨界放置，因为分段在结构上强制执行正确性，而不是通过 DP 内部的约束。
