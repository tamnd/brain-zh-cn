 ## 解决方案
 ## 问题理解

 该任务是对太大而无法适应大多数编程语言中可用的正常整数类型的整数执行算术。 输入包含两个以十进制字符串形式写的非负整数，输出是以十进制形式写的它们的和。 

字符串可以包含许多数字，因此将它们转换为内置整数类型并不是有效的方法。 64 位整数只能存储最多 19 位十进制数字的值，而大整数问题的设计使得位数可以更大。 

输入的大小决定了算法。 如果数字包含`n`和`m`数字，阅读它们已经花费了`O(n + m)`时间，因此任何可接受的解决方案都必须以相同的数量级起作用。 随着数字计数的增长，尝试重复转换整个数字或对每对数字执行操作的方法会变得太慢。 

主要的边缘情况来自手动添加的工作方式。 一个常见的错误是忘记最后的进位。 例如，输入```
9
1
```产生```
10
```因为添加最后一个数字会创建一个新数字。 

另一个错误是假设两个数字具有相同的长度。 例如，```
999
1
```必须产生```
1000
```较短的数字缺少前导数字，其行为类似于零，并且进位继续超出较短字符串的末尾。 

粗心的实现也可能会错误地处理零值。 例如，```
0
0
```应该输出```
0
```答案不应包含不必要的前导零。 

## 方法

 最简单的方法是依赖语言的整数类型并将输入字符串解析为数字。 仅当值足够小时，这才有效，因为普通整数类型具有固定的位数。 一旦输入包含的数字多于类型可以存储的数字，转换就会在实际加法发生之前溢出或失败。 

需要手动模拟。 十进制加法有一个有用的局部属性：某个位置的数字仅取决于该位置的两位数字和来自前一位置的进位。 这意味着整个数字不需要表示为一个机器整数。 

这个想法与在纸上添加数字时使用的过程相同。 从最低有效数字开始，将相应数字和当前进位相加，存储结果数字，并将新进位传递到下一个位置。 当一个数字结束时，缺失的数字将被视为零。 处理完所有位置后，任何剩余的进位都会成为新的前导数字。 

就数学工作而言，蛮力方法和最优方法实际上是相同的，但最优方法避免了不可能的转换步骤。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 使用内置整数进行暴力破解 | O(n) | O(n) | 当数字超过整数限制时失败 |
 | 手动数字添加 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 将两个数字读取为字符串而不是整数。 字符串保留每个数字并避免溢出。 
2. 将指针设置在两个字符串的最后一个字符处，并将进位初始化为零。 加法是从右边开始的，因为小数进位是从低位移到高位的。 
3. 当任一指针仍在其字符串内或保留进位时，从每个数字中取出当前数字（如果存在），否则使用零。 将两位数字和进位相加。 
4. 将和的最后一位存储为当前结果位，并使用整数除以 10 来更新进位。 这将属于当前位置的数字与传输到下一个位置的值分开。 
5. 将两个指针向左移动并继续，直到处理完每个数字。 
6. 由于加法是从数字末尾开始的，所以生成的数字是相反顺序的。 在打印之前反转结果。 

为什么它有效：

 算法期间保持的不变性是，处理一个位置后，存储的结果准确地包含已处理的所有位置的正确数字，并且进位准确地包含必须添加到下一个位置的金额。 一旦知道传入的进位，每个小数点位置都是独立的，因此从右到左处理位置会重现正常的加法过程。 在最后一个位置之后，唯一可能缺失的贡献是最终进位，循环也处理它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def add_bigints(a, b):
    i = len(a) - 1
    j = len(b) - 1
    carry = 0
    result = []

    while i >= 0 or j >= 0 or carry:
        digit_a = ord(a[i]) - ord('0') if i >= 0 else 0
        digit_b = ord(b[j]) - ord('0') if j >= 0 else 0

        total = digit_a + digit_b + carry
        result.append(chr(ord('0') + total % 10))
        carry = total // 10

        i -= 1
        j -= 1

    result.reverse()
    answer = ''.join(result)

    answer = answer.lstrip('0')
    return answer if answer else "0"

def solve():
    data = sys.stdin.read().split()
    if len(data) < 2:
        return

    print(add_bigints(data[0], data[1]))

if __name__ == "__main__":
    solve()
```功能`add_bigints`逐位执行整个数字模拟。 指针`i`和`j`表示当前添加到每个输入数字中的数字。 它们从最低有效数字移向最高有效数字，与进位自然传播的方式相匹配。 

条件数字提取很重要，因为数字可能具有不同的长度。 当指针移动到字符串开头之前时，缺少的数字将被视为零。 

结果是向后构建的，因为第一个计算的数字是个位数字。 最后反转即可恢复正常的十进制顺序。 最终删除前导零可以处理输入表示包含不必要的零的情况，同时保留答案`0`有效的。

## 复杂度分析

 该算法仅对每个数字执行恒定量的工作，因此它随输入大小线性缩放，并且适用于仅受内存限制的任意大数字。

 ## 边缘情况

 对于`9 + 1`，算法首先处理唯一的数字。 总和为 10，因此它存储 0 并进位 1。 两个字符串都已完成，但进位保持循环运行并创建前导数字。 输出变为`10`。 

对于不同长度的数字，例如：```
999
1
```第二个数字在其第一个位置之后用完所有数字。 该算法用零替换缺失的数字，因此剩余的添加变为`9 + 0 + carry`。 这一直持续到进位消失，产生`1000`。 

对于零值：```
0
0
```该算法创建结果数字为零。 删除前导零会产生一个空字符串，因此最终条件将其替换为`"0"`。 这使表示保持有效。
