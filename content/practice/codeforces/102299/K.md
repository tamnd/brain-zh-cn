 ## 解决方案
 ## 问题理解

 我们有一系列积极的章节价格。 每当债务到期时，陀思妥耶夫斯基都可以出售已写完的章节的任何子集，并且当其价值等于该子集的总和时，可以准确地偿还债务。 同一章不能为一笔债务出售两次，因此相关问题是子集和问题。 

我们需要不能形成为给定价格的某个子集之和的最小正整数。 答案不一定比每章的价格都大。 例如，与价格`2, 5`, 债务`1`已经不可能了，所以答案是`1`。 

该数组最多可以包含`5 * 10^5`章节，而每个价格可以大到`10^12`。 这立即排除了枚举子集，因为可能有`2^n`其中。 在这种规模下，即使是考虑许多对或章节间隔的方法也会太慢。 我们需要一个接近的算法`O(n log n)`，这对于 2 秒限制内的 50 万个元素来说是实用的。 

每个价格的大值也意味着由总和索引的固定大小的动态编程数组不可行。 总价可以达到`5 * 10^17`，远远超出基于总和的 DP 可以分配的范围。 幸运的是，该解决方案只需要一个运行值，因此 Python 的任意精度整数可以直接处理潜在的大答案。 

在几种边缘情况下，实现可能会默默地出错。 如果最低价格大于`1`，那么答案就是立即`1`。 例如，使用输入`1`和价格`2`，输出是`1`，因为没有一个子集可以产生一卢布。 从第一个价格开始并假设它可以构建低于该价格的每个值的粗心实现将错误地错过这种情况。 

当所有值在某个点上都是可构造的，但下一个价格会产生差距时，就会出现第二种边缘情况。 例如，与价格`1 2`，我们可以使`1`,`2`， 和`3`，但不是`4`，所以答案是`4`。 仅检查当前值本身是否是子集和而不是跟踪整个连续可达间隔的实现可能会错过此间隙。 

第三种情况是下一个价格恰好比当前可达到的价格大 1 时。 有价格`1 1 3`，前两个值让我们构造每个总和`0`通过`2`。 价值`3`将其扩展到`5`，所以答案是`6`。 边界条件必须是`price <= reachable + 1`， 不是`price < reachable + 1`。 

## 方法

 直接的方法是生成章节的每个子集，计算其总和，并记录哪些总和是可能的。 有`2^n`子集。 即使每个子集总和都得到有效维护，我们仍然需要`O(2^n)`工作。 如果每个子集都是通过检查所有`n`元素，操作计数将是`O(n * 2^n)`，这对于`n = 5 * 10^5`。 甚至`2^60`已经远远超出了时限内可执行的范围。 

更熟悉的替代方案是子集和动态规划。 我们可以标记哪些金额是可以达到的，并针对每个价格更新它们。 问题是总和可能大到`5 * 10^17`，所以即使是理论上有效的`O(n * sum)`DP 无法适应记忆或时间。 

有用的结构来自于每个价格都是正值的事实。 假设我们已经处理了一些章节并且可以构造每个值`1`通过`R`。 现在考虑下一个价格`x`，对所有价格进行日益排序后。 

如果`x <= R + 1`，那么旧的章节使每个值都来自`0`通过`R`，同时添加`x`让我们从中创造每一个价值`x`通过`x + R`。 因为`x <= R + 1`，这两个区间接触或重叠。 因此，他们的结合是来自`0`通过`R + x`。 

如果相反`x > R + 1`， 然后`R + 1`无法形成。 每个已处理的章节最多是`R`，并且每个子集使用`x`或稍后，甚至更大的章节至少有总和`x`，大于`R + 1`。 所以`R + 1`绝对是最小的不可能值。 

这给出了一个贪心算法。 对价格进行排序，维护已知完全可构造的最大正和前缀，并在下一个价格不留下缺口时扩展该范围。 暴力方法显式地探索所有子集，因为它没有关于保证存在哪些和的信息。 上面的观察将所有信息压缩为一个整数，`R`。 

由此产生的复杂性是：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n * 2^n)`|`O(2^n)`| 太慢了|
 | 子集和 DP |`O(n * S)`|`O(S)`| 太慢且内存太多|
 | 最优贪心 |`O(n log n)`|`O(n)`| 已接受 |

 这里`S`表示所有章节价格的总和。 最佳方法几乎将所有时间都花在对数组进行排序上。 

## 算法演练

 1.阅读所有章节价格并按非降序排列。 排序使我们能够推断出每个尚未处理的价格至少与当前价格一样大。 
2. 初始化`reachable = 0`。 这意味着不使用章节，我们可以构造总和`0`，此时区间中的每个值`1`通过`reachable`是可空构的。 
3. 按从小到大的顺序处理排序后的价格。 对于当前价格`x`，将其与`reachable + 1`，尚未保证可建造的最小正量。 
4.如果`x > reachable + 1`， 返回`reachable + 1`。 前面的章节只能形成总结`reachable`，而任何包含的子集`x`至少有价值`x`。 因此`reachable + 1`存在于真正的差距中，这就是答案。 
5. 否则，`x <= reachable + 1`，所以添加`x`到`reachable`。 添加前`x`，每一笔金额来自`0`通过`reachable`是可能的。 使用`x`与这些相同的子集一起给出来自`x`通过`x + reachable`。 自从`x <= reachable + 1`，两个区间之间没有间隙，因此每个值`0`通过`reachable + x`成为可能。 
6. 如果所有价格都处理完没有发现差距，则返回`reachable + 1`。 那时，每个值都来自`0`总和是可以构造的，而大于总和的总和是不可能的。 第一个这样的值正是`reachable + 1`。 

### 为什么它有效

 不变的是，在处理当前价格之前的每个价格之后，来自`0`通过`reachable`可以形成。 如果下一个价格超过`reachable + 1`， 然后`reachable + 1`无法形成：没有该价格的子集最多是`reachable`，并且包含它的子集至少是下一个价格。 如果价格最多`reachable + 1`，没有它的总和涵盖`[0, reachable]`，并且使用它的总和涵盖`[x, x + reachable]`。 这些间隔重叠或接触，因此它们一起覆盖`[0, reachable + x]`。 因此，不变量被保留，并且第一个检测到的间隙恰好是最小的不可能正和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    prices = list(map(int, input().split()))

    prices.sort()

    reachable = 0

    for x in prices:
        if x > reachable + 1:
            print(reachable + 1)
            return
        reachable += x

    print(reachable + 1)

if __name__ == "__main__":
    solve()
```前两行显示章节数量及其价格。 由于输入恰好包含`n`价格在第二行，一通电话`input()`对于指定的格式就足够了。 

排序步骤将价格按升序排列。 贪心证明取决于这种排序，因为在确定当前价格太大而无法弥补下一个缺失值之后，每个剩余价格至少同样大，因此也无法填补该空白。`reachable`表示最大的整数，使得来自的每个值`0`通过`reachable`是可构造的。 支票`x > reachable + 1`是临界边界。 平等是允许的，因为如果`x == reachable + 1`，新的章节本身会填充下一个缺失值并扩展连续范围。 

当当前价格可用时，`reachable += x`更新新覆盖的区间的端点。 不需要存储哪些子集产生总和，因为不变量只需要知道区间中的所有值都可用。 

Python 整数在这里是合适的，因为总数可以达到`5 * 10^17`。 具有固定宽度整数类型的语言需要一个 64 位整数来表示该值，而 Python 会根据需要自动增长整数表示形式。 

## 工作示例

 ### 示例 1

 价格是`2, 1, 10000000000`。 排序后就变成了`1, 2, 10000000000`。 

| 现价`x`|`reachable`之前|`reachable + 1`| 行动|`reachable`之后|
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 |`1 <= 1`, 延伸 | 1 |
 | 2 | 1 | 2 |`2 <= 2`, 延伸 | 3 |
 | 10000000000 | 3 | 4 |`10000000000 > 4`，停止| 3 |

 加工后`1`和`2`，每个值来自`0`通过`3`是可能的：`0`,`1`,`2`， 和`1 + 2 = 3`。 下一章的成本为一百亿美元，所以涉及它的任何子集都无法产生`4`。 答案是`4`。 

### 示例 2

 其中一章的售价为`2`。 

| 现价`x`|`reachable`之前|`reachable + 1`| 行动|`reachable`之后|
 | --- | --- | --- | --- | --- |
 | 2 | 0 | 1 |`2 > 1`，停止| 0 |

 没有正和小于`2`可以成立，所以`1`立即是最小的不可能债务。 该跟踪练习了答案小于最便宜的章节的情况。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log n)`| 排序在线性贪婪扫描中占主导地位。 |
 | 空间|`O(n)`| 价格存储在一个数组中； 扫描本身使用`O(1)`附加状态。 |

 至多有`5 * 10^5`价格方面，排序在给定的范围内是实用的，并且后续的线性扫描与排序成本相比很小。 该算法永远不会分配与总价格成比例的内存，这是至关重要的，因为总价格可以达到`5 * 10^17`。

import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    prices = list(map(int, input().split()))
    prices.sort()

    reachable = 0

    for x in prices:
        if x > reachable + 1:
            print(reachable + 1)
            return
        reachable += x

    print(reachable + 1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("3\n2 1 10000000000\n") == "4", "sample 1"
assert run("1\n2\n") == "1", "sample 2"

# Minimum-size input, cheapest possible chapter
assert run("1\n1\n") == "2", "single chapter worth 1"

# All equal values
assert run("5\n1 1 1 1 1\n") == "6", "all equal values"

# Boundary case: x == reachable + 1 must extend the range
assert run("3\n1 1 3\n") == "6", "exact boundary"

# Gap after several constructible values
assert run("4\n1 2 2 10\n") == "6", "gap after continuous range"

# Large values must not cause fixed-range DP assumptions
assert run("3\n1000000000000 1000000000000 1000000000000\n") == "1", "large prices"

# Maximum-size case, all values equal to 1

assert run(f"{n}\n" + " ".join(["1"] * n) + "\n") == "500001", "maximum n"

 | --- | --- | --- |

 ## 边缘情况

 如果最便宜的一章花费超过一卢布，答案一定是`1`。 对于输入```
1
2
```最初的`reachable`是`0`， 所以`reachable + 1`是`1`。 由于排序后的价格`2`大于`1`，算法返回`1`在添加章节之前。 这可以防止常见的错误，即假设答案必须至少是最小的章节价格。 

对于已经完成的间隔后的间隙，请考虑```
4
1 2 2 10
```排序后，第一个价格`1`变化`reachable`从`0`到`1`。 价格`2`满足`2 <= 2`， 所以`reachable`变成`3`。 下一个`2`满足`2 <= 4`，将范围扩大到`5`。 最终价格`10`大于`6`， 所以`6`无法形成并被退回。 两个较小的副本`2`证明为什么算法必须考虑整个已经可达的区间而不是仅考虑单个子集的总和。 

平等边界由以下方式处理```
3
1 1 3
```第一个`1`给出`reachable = 1`，第二个给出`reachable = 2`。 下一个价格正是`3`，等于`reachable + 1`，所以必须接受。 可达区间扩展为`5`，答案就变成了`6`。 使用严格的比较，例如`x >= reachable + 1`会错误地返回`3`。 

非常大的章节值不需要特殊处理。 为了```
3
1000000000000 1000000000000 1000000000000
```第一个排序的价格已经大于`reachable + 1 = 1`，所以算法返回`1`。 这也说明了为什么用可能的货币金额索引的 DP 是错误的抽象：即使实际答案很小，数值也可能很大。
