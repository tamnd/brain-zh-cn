 ## 解决方案
 ## 问题理解

 我们有 (N) 对 ((p_i,f_i))。 当达到一对时，玩家收到 (p_i) 卢布并可以立即停止，支付 (f_i) 卢布。 如果(f_i)为负数，支付它就意味着收到额外的钱。 如果玩家到达最后一对，则必须在那里停止。 

赌场在游戏开始前选择所有对的顺序。 然后玩家选择最佳的停止点。 我们的任务是选择使玩家的最佳最终增益尽可能小的排序，并输出最小的可能增益。 

对于固定顺序，假设前 (i) 对已经玩过。 如果玩家恰好停在那里，她的增益是

 [
 p_1+p_2+\cdots+p_i-f_i。 
]

 玩家可以选择任何停止位置，包括最后一个。 因此，对于固定排列，玩家的最佳增益是

 [
 \max_{1\le i\le N}\left(\sum_{j=1}^{i}p_j-f_i\right)。 
]

 因此，问题变成了纯粹的排序问题：排列这些对，以使这些前缀表达式的最大值最小化。 

当 (N) 达到 (10^5) 时，枚举排列是不可能的。 即使是二次算法，在最大情况下也已经执行了大约 (10^{10}) 次运算，远远超出了可用时间。 我们需要一个基于排序的解决方案，它给出 (O(N\log N))。 

有几种边缘情况很容易导致错误的解决方案。 负数 (f_i) 必须按字面意思处理。 例如，```
1
1 -2
```玩家收到 (1)，然后收到另一个 (2)，因此答案是 (3)，而不是 (1) 或 (-1)。 假设费用始终为非负的解决方案会出错。 

最后的一对在游戏描述中也比较特殊，但在公式中不需要单独处理。 例如，```
1
0 1
```强制玩家支付 (1)，所以答案是 (-1)。 表达式 (0-1=-1) 已经捕获了这一点。 将最后一对视为玩家可以简单地忽略其费用会产生错误的答案。 

(p_i) 的零值是允许的。 为了```
2
0 1
3 4
```显示的顺序给出了前缀值 (-1) 和 (-1)，因此答案是 (-1)。 依赖于每一轮都严格增加累计金额的证明或实现是无效的。 

最后，相等的 (f_i) 值不需要特殊的平局打破规则。 相等 (f_i) 值之间的任何顺序都是最佳的。 例如，```
3
2 5
1 5
3 5
```具有任意顺序的前缀值 (-3,-2,1)，因此答案是 (1)。 

## 方法

 直接的方法是尝试 (N) 对的每种排列。 对于每个排列，从左到右扫描，维护累加的 (p)，并计算 (prefix-f_i) 的最大值。 这是正确的，因为它准确地评估了最佳玩家对每个可能的停止位置可用的增益，然后采取最好的一个。 然而，有 (N!) 种排列，每种排列都需要 (O(N)) 时间来评估，从而给出 (O(N\cdot N!)) 次操作。 即使在 (N=10) 时，也已经有大约 (36) 万个基本位置需要检查，而 (N=11) 则将其提高到大约 (440) 万个。 在 (N=10^5) 时，这种方法不太可行。 

有用的观察是，玩家的收益恰好具有调度目标的形式。 将 (p_i) 视为作业 (i) 的处理时间，将 (f_i) 视为其到期日期。 处理完第 (i) 个作业后，其完成时间为第 (p) 个作业的前缀和，其迟到时间为

 [
 C_i-f_i。 
]

 我们需要最小化最大延迟。 经典的交换论点认为，工作应该按照截止日期的非递减顺序进行处理，这意味着通过增加 (f_i) 对工作对进行排序。 

无需依赖调度术语即可直接得出原因。 假设两个相邻对 (a) 和 (b) 当前排序不正确，因此 (f_a>f_b)。 令 (S) 为这两对之前的累积 (p)。 按照 (a,b) 的顺序，两个相关值是

 [
 S+p_a-f_a
 ]

 和

 [
 S+p_a+p_b-f_b。 
]

 因为 (f_a>f_b) 和 (p_b\ge0)，第二个值始终至少是第一个值。 因此这对贡献

 [
 S+p_a+p_b-f_b
 ]

 到最大。 

现在将它们交换为顺序 (b,a)。 这两个值变为

 [
 S+p_b-f_b
 ]

 和

 [
 S+p_b+p_a-f_a。 
]

 第一个不大于旧的最大值，因为 (p_a\ge0)。 第二个并不大，因为(f_a>f_b)，所以减去(f_a)只能使其小于减去(f_b)。 因此，交换反转不能增加玩家的最佳增益。 

重复删除每个反转会使对按增加 (f_i) 排序，并且永远不会使答案变得更糟。 因此这个排序顺序是最优的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N\cdot N!)) | (O(N)) | 太慢了|
 | 最佳| (O(N\log N)) | (O(N)) | 已接受 |

 ## 算法演练

 1. 读取所有对 ((p_i,f_i))。 决定它们相对顺序的唯一属性是 (f_i)，因此我们可以保持每对完整并按其第二个分量排序。 
2. 通过增加 (f_i) 对这些对进行排序。 交换参数表明，每当较大的 (f) 出现在较小的 (f) 之前时，交换这两对不能增加玩家可用的最大增益。 重复这个过程就可以得到准确的排序顺序。 
3. 从左到右扫描排序对并维护`prefix`，迄今为止收到的总金额。 添加一对 ((p,f)) 后，玩家可以停在这对上并获得`prefix - f`。 
4. 保持所有值中的最大值`prefix - f`。 该最大值是玩家针对所选顺序的最佳增益，因为已考虑了每个可能的停止位置。 
5. 打印最大值。 由于排序是最优选择的，因此这是任何排序可以让最佳玩家获得的最小增益。 

### 为什么它有效

 对于任何固定顺序，玩家可以恰好停在一个位置，停在位置 (i) 给出值 (prefix_i-f_i)。 因此，玩家的最佳增益正是这些值中的最大值。 

考虑任何相邻反演，其中 (f_a>f_b)。 当两对排序为 (a,b) 时，它们的两个受影响的停止值中较大的一个是 (S+p_a+p_b-f_b)。 交换后，两个受影响的值是（S+p_b-f_b）和（S+p_a+p_b-f_a）。 两者至多都是旧的最大值，因为 (p_a\ge0) 和 (f_a>f_b)。 所有其他停止位置具有完全相同的前缀和并且不变。 因此，消除倒置永远不会增加目标。 

通过重复删除反转，每个排列都可以转换为非递减 (f) 顺序。 由于这些交换都不会增加目标，因此排序顺序的目标值不大于任何其他排序。 因此它是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pairs = [tuple(map(int, input().split())) for _ in range(n)]

    pairs.sort(key=lambda x: x[1])

    prefix = 0
    answer = None

    for p, f in pairs:
        prefix += p
        value = prefix - f
        if answer is None or value > answer:
            answer = value

    print(answer)

if __name__ == "__main__":
    solve()
```输入以对的形式存储，因此排序永远不会将 (p_i) 与其对应的 (f_i) 分开。 排序键是第二个组成部分，增加 (f_i)。`prefix`在计算之前更新`value`。 这对应于玩家在决定是否离开该轮之前收到 (p_i) 的信息。 计算`prefix - f`在添加 (p_i) 之前将代表不同的游戏并产生差一错误。`answer`开始为`None`而不是一个大的硬编码数字。 这特别方便，因为正确答案可能是否定的，如示例 3 所示。Python 整数还自动处理最大可能的前缀。 所有 (p_i) 的总和可以达到 (10^{14})，这在 C++ 等语言中会溢出 32 位整数，尽管 Python 具有任意精度整数。 

最后一对没有单独的分支。 当扫描到达它时，它的值就被包含在内，并且因为玩家必须停在那里，所以表达式`prefix - f`正是所需的最终收益。 

## 工作示例

 对于样本 1，输入对为 ((1,2))、((3,3)) 和 ((2,1))。 按 (f) 排序得出 ((2,1))、((1,2))、((3,3))。 

| 配对 | 前缀 | 前缀 - f | 当前答案 |
 | --- | --- | --- | --- |
 | ((2,1)) | ((2,1)) | 2 | 1 | 1 |
 | ((1,2)) | ((1,2)) | 3 | 1 | 1 |
 | ((3,3)) | ((3,3)) | 6 | 3 | 3 |

 玩家的三种可能的停止收益是 (1)、(1) 和 (3)。 她选择了最大的一个，即 (3)。 由于增加 (f) 阶数是最佳的，因此没有其他排列可以强制获得较小的最佳增益。 

对于样本 2，只有一对 ((1,-2))。 

| 配对 | 前缀 | 前缀 - f | 当前答案 |
 | --- | --- | --- | --- |
 | ((1,-2)) | ((1,-2)) | 1 | 3 | 3 |

 负费用会增加玩家的收益，即 (1-(-2)=3)。 强制最终付款自然由相同的表达式处理。

 ## 边缘情况

 单一负费用对```
1
1 -2
```通过对单元素数组进行排序并计算来处理`prefix = 1`， 其次是`prefix - f = 1 - (-2) = 3`。 该算法并不假设停止需要花钱。 负数（f）只是玩家离开时的奖励。 

强制的最后一对不需要特殊情况。 为了```
1
0 1
```扫描得到`prefix = 0`并计算`0 - 1 = -1`。 因为这是唯一可能的停止位置，所以答案正是 (-1)。 更一般地，最终位置包含在与每个较早位置相同的停止表达式中。 

零 (p_i) 值也可以直接处理。 在```
2
0 1
3 4
```这些对已经按 (f) 排序。 第一个前缀是 (0)，表示 (-1)，第二个前缀是 (3)，表示 (3-4=-1)。 最大值为 (-1)。 交换证明使用 (p_i\ge0)，因此零处理时间是完全有效的。 

相等的 (f_i) 值不会影响贪婪参数。 为了```
4
2 5
2 5
2 5
2 5
```每种可能的订购都是等效的，因为所有费用都是相同的。 前缀值为(2,4,6,8)，因此停止增益为(-3,-1,1,3)，答案为(3)。 这里排序稳定或者不稳定都不影响结果。 

否定的答案是有效的，并且不能与没有利润相混淆。 样本 3 产生 (-1)，因为每个可用的停止位置都会损失一卢布。 将答案初始化为零会错误地将其转换为 (0)，这就是实现从第一个计算值初始化它的原因。 

最大累计金额可为(10^5\cdot10^9=10^{14})。 Python 的整数表示可以准确地处理这个问题，而 32 位实现会溢出。 该算法永远不会对大于此范围的值执行算术，因此 Python 中不存在数值问题。
