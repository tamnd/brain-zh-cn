 ## 解决方案
 ## 问题理解

 我们得到一个仅由四个可能的字符组成的字符串：P、D、A 和 O。每个字符代表一种排成一排的战士。 我们可以选择这条线的任何连续段，这意味着我们选择一个子串，并将其称为“联盟”。 

如果在该子字符串内所有四个字符出现相同的次数，则联盟被视为有效。 我们的任务是找到最长的有效联盟，并输出它的长度。 如果没有非空子字符串满足条件，我们返回零。 

这里的关键结构是我们正在搜索子字符串，但条件不是局部的。 它取决于四个类别的全局计数，这表明直接枚举子字符串将过于昂贵。 

输入长度最大可达200​​,000。 对所有子字符串进行简单的二次扫描，即使快速计算字符，在最坏的情况下也会导致大约 200 亿次检查，这在典型的时间限制下是不可行的。 任何解决方案都必须减少每个查询的 O(n) 子字符串检查或完全避免枚举子字符串。 

边缘情况以微妙的方式发挥着重要作用。 如果字符串类似于“AAAA”，则不存在有效的子字符串，因为我们无法平衡所有四个字母，因此答案为零。 如果琴弦在整个范围内已经完美平衡，则整个琴弦就是答案。 如果有多个有效子字符串，我们必须确保选择最大长度，而不仅仅是找到的第一个。 

常见的失败情况是由于忘记从两端删除字符相当于选择任何子字符串，而不仅仅是前缀或后缀。 例如，在“PDAOPDAOOPDA”中，有效答案存在于许多移位窗口中，并且将注意力限制在类似前缀的结构上会错过其中的大多数。 

## 方法

 暴力方法会检查每个子字符串。 对于每对索引 l 和 r，我们计算 P、D、A 和 O 的出现次数并验证相等性。 这是正确的，因为它直接强制条件，但每个子字符串需要 O(n) 工作。 由于存在 O(n²) 个子串，如果计数比较幼稚，则总复杂度变为 O(n³)，或者使用前缀和则变为 O(n²)，但即使是 O(n²) 对于 200,000 来说也太慢了。 

关键的观察是条件“P、D、A、O 的数量相等”可以重写为对前缀差异的约束。 如果我们定义每个字符的运行计数，那么当这些计数之间的差异以特定方式保持一致时，子字符串恰好有效。 

我们不是直接跟踪四个数字，而是将问题转换为低维表示。 如果在子字符串中所有计数都相等，那么对于该子字符串我们必须有：

 计数 (P) − 计数 (D) = 0

 计数 (P) − 计数 (A) = 0

 计数 (P) − 计数 (O) = 0

 因此，当且仅当三个独立差为零时，所有四个计数都相等。 

因此，我们跟踪这些差异的前缀向量。 当且仅当两个位置 i 和 j 的前缀差异状态相同时，它们才形成有效的子串。 这将问题简化为查找前缀哈希图中两个相等状态之间的最大距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或 O(n³) | O(1) | O(1) | 太慢了|
 | 前缀状态哈希 | O(n) | O(n) | 已接受 |

 ## 算法演练

1. 将每个字符转换为四个计数器的更新，当我们从左到右扫描字符串时，保持 P、D、A 和 O 的运行总计。 这使我们能够简洁地表示每个前缀。 
2. 对于每个位置，计算仅捕获计数之间的相对差异的归一化状态。 一个方便的选择是像 (P−D, P−A, P−O) 这样的元组。 这消除了冗余，因为不需要绝对值，只需要前缀之间的相等性。 
3. 维护一个字典，将每个状态映射到它出现的最早索引。 我们存储最早的索引的原因是，相同状态的任何后续出现都会形成一个有效的子字符串，该子字符串具有该状态的最大可能长度。 
4. 使用字符串开始前的空前缀对应的状态初始化映射。 这允许自然地考虑从索引 0 开始的子字符串。 
5. 当我们迭代字符串时，计算当前状态并检查它以前是否见过。 如果有，则计算当前索引和第一次出现之间的长度，如果该长度较大，则更新答案。 
6. 如果尚未看到该状态，则将当前索引存储为其第一次出现的位置。 
7. 处理完整个字符串后，存储的最大长度就是答案。 

为什么存储第一次出现的情况很重要：后来的出现给出了更短的子字符串，并且由于我们想要最大长度，所以越早越好。 

### 为什么它有效

 字符串的每个前缀对应于三维差分空间中的一个点。 当两个端点映射到该空间中的同一点时，子字符串的所有字符计数相等，这意味着它们的差异为零。 该算法将问题简化为在单次扫描中找到最远的一对相等点。 由于每个状态都对有关相对计数的所有必要信息进行编码，因此不会错误地合并两个不同的有效子字符串，并且不会丢失任何有效子字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    cp = cd = ca = co = 0
    
    first = {}
    first[(0, 0, 0)] = -1
    
    ans = 0
    
    for i, ch in enumerate(s):
        if ch == 'P':
            cp += 1
        elif ch == 'D':
            cd += 1
        elif ch == 'A':
            ca += 1
        else:
            co += 1
        
        state = (cp - cd, cp - ca, cp - co)
        
        if state in first:
            ans = max(ans, i - first[state])
        else:
            first[state] = i
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现保留四个正在运行的计数器，并在每个索引处将它们压缩为三分量状态。 字典`first`确保我们只保留每个状态最早出现的情况。 正在初始化`(0,0,0)`在索引处`-1`允许从索引零开始的子字符串正确贡献。 

一个常见的陷阱是忘记哨兵初始化。 如果没有它，从字符串开头开始的子字符串将永远不会被计算在内。

### 示例 2：PPPOOPPOOAAAADDDD

 这里的字符串已经被构造成平衡块。 

该算法反复重新访问差异被抵消的状态。 状态 (0,0,0) 出现多次，最远的重复给出全长 16。 

这表明该算法自然地压缩平衡前缀并且不需要显式搜索结构。

 ## 边缘情况

 一种边缘情况是根本不存在有效的子字符串。 对于输入“AAAA”，每个前缀状态都是不同的，并且不会以平衡所有四个字符的方式重复初始状态。 算法初始化`(0,0,0)`在索引处`-1`，但之后的前缀不会返回到此状态，因此答案仍然为零。 

另一种情况是整个弦平衡时。 对于“PDAOOPDA”，状态返回到`(0,0,0)`在最终索引处。 由于这种状态出现在`-1`，计算出的长度跨越整个字符串，产生正确的最大值。 

第三种情况是重复部分余额。 在像“PDAO PDAO PDAO”这样的字符串中，相同的状态出现多次，并且算法正确地倾向于最早出现的状态，从而最大化以最后一次重复结束的子字符串长度。
