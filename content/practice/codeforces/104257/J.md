 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并且允许我们删除元素，同时保持剩余元素的原始顺序。 目标是使结果子序列尽可能长，同时满足其连续差异的严格交替模式。 

具体来说，如果我们查看所选子序列，每个相邻对都必须不同，并且这些差异的符号必须严格交替。 如果第一个差值为正，则下一个差值必须为负，然后再次为正，依此类推。 如果第一个差值为负，则同样成立。 任何零差异都会立即破坏有效性，因为交替模式内不允许相等。 

任务是计算这样一个子序列的最大可能长度。 

约束条件$n \le 10^5$排除尝试所有子序列的任何解决方案。 一个天真的$O(2^n)$枚举是立即不可能的。 偶数二次$O(n^2)$动态编程在最坏的情况下存在太慢的风险，因此该解决方案必须基本上以线性时间处理数组，每个元素仅使用常数或对数工作。 

一些边缘情况比它们最初出现时更重要。 

如果所有元素都相等，则每个差值均为零，因此任何转换均无效且答案必须为 1。 

如果序列严格递增或严格递减，则一开始只有一个方向可用，之后交替条件立即失败，因此对于任何大于 1 的非平凡长度，答案再次折叠为 2。 

如果有许多重复值与变化交错，则未明确丢弃零差异的幼稚方法可能会错误地将它们视为有效转换，从而产生夸大的答案。 

## 方法

 暴力策略会尝试每个子序列并检查它是否满足交替符号条件。 对于每个选定的长度子序列$k$，验证有效性需要$O(k)$，并且有$2^n$子序列，因此总成本是指数级的，即使对于$n = 40$，更不用说$10^5$。 

我们需要将问题压缩为局部问题。 关键的观察是，对于扩展有效子序列唯一重要的是最后选择的元素和最后一个非零差值的符号。 一旦我们知道当前预期是增加还是减少，每个新元素要么延续该模式，要么打破它。 

这将问题变成了贪婪扫描。 我们不需要记住整个子序列，只需要记住最后选择的值和最后的方向。 每当我们遇到一个可以产生有效方向变化的值时，我们都会采用它并翻转预期方向。 如果差异为零，我们完全忽略它，因为它无法促成有效的交替。 

这与经典的“摆动子序列”问题具有相同的结构：将数组压缩为正斜率和负斜率的最大交替游程。

 ## 算法演练

 我们扫描数组，同时跟踪最后一个有意义的变化方向。 

1. 将答案长度初始化为 1，因为任何单个元素始终有效。 还要保留一个变量来存储先前未设置的差异符号。 
2. 从第二个元素开始迭代数组并计算当前元素与前一个元素之间的差异。 
3. 如果差异为零，则完全跳过它，因为它不能产生任何有效的交替子序列。 这避免了破坏方向逻辑。 
4. 如果差异为正，并且我们尚未跟踪方向或前一个方向为负，则我们接受该元素作为子序列的一部分，并将方向设置为正。 
5. 如果差异为负，并且我们尚未跟踪方向或之前的方向为正，则我们接受此元素并将方向设置为负。 
6. 否则，当前差异继续与之前相同的方向，并且不能扩展交替模式，因此我们忽略它。 
7. 接受的转换数量加一即为答案长度。 

关键的想法是，每次方向翻转时，我们都保证使用该转换的最极端的可用点，因此未来的元素无法在不破坏交替的情况下提高计数。 

### 为什么它有效

 在扫描中的任何点，算法都会维护一个在方向发生变化的最近枢轴处结束的子序列。 任何被忽略的元素要么具有零差值，要么继续相同的斜率方向。 保留它不会允许未来无法实现的交替，因为增加长度的唯一方法是创建新的符号变化，并且只有当斜率翻转时才可能发生符号变化。 因此，只进行斜率翻转的贪婪选择保留了最大可能的交替次数，这直接决定了子序列的长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 0:
        print(0)
        return
    
    count = 1
    prev_diff = 0  # 0 means unset, 1 means positive, -1 means negative
    
    for i in range(1, n):
        diff = a[i] - a[i - 1]
        
        if diff == 0:
            continue
        
        sign = 1 if diff > 0 else -1
        
        if prev_diff == 0 or sign != prev_diff:
            count += 1
            prev_diff = sign
    
    print(count)

if __name__ == "__main__":
    solve()
```该解决方案依赖于对阵列进行一次扫描，并且仅在连续差异的符号发生变化时才做出反应。 变量`prev_diff`存储最后接受的坡度方向。 零差异被明确忽略，因此它不会干扰交替逻辑。 

关键的微妙之处在于我们总是与原始序列中的相邻元素进行比较，而不是与所选的子序列进行比较。 这已经足够了，因为任何最佳子序列都可以转换为仅使用连续“转折点”而不减少其长度的子序列。

 ## 边缘情况

 一种重要的边缘情况是序列包含位于方向变化之间的重复值。 例如，在类似的输入中`1 2 2 1`， 区别`2 -> 2`为零并且必须被忽略，否则它会错误地干扰检测随后的下降。 该算法通过显式跳过零差异来处理此问题，因此有效序列变为`1 -> 2 -> 1`，产生正确的长度 3。 

另一种情况是单调数组，例如`1 2 3 4 5`。 第一次增加被接受，但所有后来的增加都被忽略，因为它们不会创建新的符号翻转。 结果稳定在 2，这与只需要两个点来表示单个递增游程的事实相符。 

最后一种情况是一个平面数组，例如`7 7 7 7`。 每个差异都为零，因此不会接受任何转换。 该算法正确地将计数保留为 1，这反映出任何单个元素都会形成有效的微不足道的抖动序列。
