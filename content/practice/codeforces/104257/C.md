 ## 解决方案
 ## 问题理解

 我们获得了最多 2021 个用户的有向关系图。 每个用户可以关注所有用户的某个子集。 在这个宇宙中，聊天室中仅存在大小为 m 的子集，任务是确定该子集中是否存在“名人”。 

名人是根据仅限于聊天室的关系来严格定义的：聊天室中的所有其他参与者都必须关注此人，此人不得在聊天室中关注任何人，此外，此人在聊天室中必须至少有一名关注者。 最后一个条件可以防止出现退化情况，即与所有聊天室交互隔离的人被错误地接受。 

输入并不直接给出聊天室的邻接矩阵； 相反，它为 m 个用户中的每一个提供其在 n 个用户的完整全局集合中的传出关注列表。 这迫使我们仅在检查条件时才将边缘过滤到聊天室。 

约束 n ≤ 2021 和 m ≤ n 足够小，因此 O(m²) 甚至 O(nm) 解决方案很容易实现。 尝试重建完整邻接矩阵的解决方案在内存中也很好，因为 n² 最坏情况下约为 400 万个条目，这在 Python 中是可以接受的。 

“至少一个追随者”条件产生了一种微妙的边缘情况。 被所有人关注但没有人关注的用户仍然需要在聊天室内至少有一个传入边，如果 m ≥ 2，则可以保证这一点。但是，当 m = 1 时，条件失败，因为“聊天室中至少有一个关注者”无法满足，因此答案必须为 -1。 

另一个棘手的方面是输入格式：当 t = 0 时，第二行实际上是“0”，而不是空行或省略的列表。 假设列表始终存在的天真的解析器将在这里崩溃。 

## 方法

 最直接的方法是计算每个聊天室成员有多少其他聊天室成员关注他们以及有多少个聊天室成员关注他们。 一旦知道这些计数，我们就可以直接检查这三个条件。 

为了做到这一点，我们可以构建一组聊天室用户，然后对于其中的每一对 (u, v)，通过扫描 u 的邻接列表来检查 u 是否跟随 v。 如果我们天真地进行此检查，则在最坏的情况下每次查找可能会花费 O(n)，因为邻接关系存储为列表。 这导致了 O(m²·n) 复杂度，这仍然是临界值，但考虑到较小的约束是可以接受的。 

然而，我们可以通过将每个用户的关注列表转换为一个集合来改进这一点，使成员资格检查复杂度为 O(1)。 然后，对于每个候选人，我们只需要在 O(m) 内计算与其他聊天室用户的关系，总共为 O(m²)。 

关键的观察是我们永远不需要聊天室之外的关系。 一切都崩溃为仅限于 m 个节点的成对检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 使用列表进行简单配对检查 | O(m²·n) | O(n + 边) | 接受（勉强）|
 | 使用哈希集进行优化 | O(平方米) | O(n + 边) | 已接受 |

 ## 算法演练

 我们将全局关注信息转换为允许快速查询的结构，然后将注意力限制在聊天室中的 m 个用户。

1.读取聊天室中的所有用户并将其存储在集合S中。这可以让我们快速测试follow Edge是否留在聊天室中。 
2. 对于每个聊天室用户 u，存储他们的关注列表，但进行过滤，以便只保留 v，使得 v 也在 S 中。这将问题简化为 S 上的诱导子图。 
3. 对于 S 中的每个候选 c，计算两个量：S 中有多少用户关注 c，以及 S c 中有多少用户关注。 
4. 检查c是否在S中没有关注任何人。如果失败，则c不能是名人，我们立即丢弃它。 
5. 检查S中是否至少有1个用户遵循c。 这强制执行非隔离条件。 
6. 检查所有其他 m−1 用户是否遵循 c。 如果 S 中的任何用户不关注 c，则 c 不是有效的候选者。 
7. 如果恰好有一个用户满足所有条件，则输出其 ID。 如果不存在或存在多个，则输出-1。 

唯一的微妙之处是步骤 6 必须小心地忽略自关系，因为问题陈述不允许自跟随，但在实现中仍应安全处理。 

### 为什么它有效

 该算法显式地评估聊天室集 S 上的归纳子图中名人的定义。每个条件都严格按照规定进行检查：S 内的传出边必须为零，传入边必须恰好为 m−1，传入边必须至少为 1。 由于所有检查都是 S 的局部检查，因此外部边缘不能影响决策。 这保证了正确性，因为定义本身纯粹是内部集合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    follows = {}
    chat_users = []

    # read chatroom users
    raw_info = []
    for _ in range(m):
        u, t = map(int, input().split())
        arr = list(map(int, input().split()))
        if t == 0:
            arr = []
        raw_info.append((u, arr))
        chat_users.append(u)

    S = set(chat_users)

    follow = {}
    for u, arr in raw_info:
        follow[u] = set(x for x in arr if x in S)

    if m == 1:
        print(-1)
        return

    for c in chat_users:
        out_cnt = len(follow[c])
        if out_cnt != 0:
            continue

        in_cnt = 0
        ok = True

        for u in chat_users:
            if u == c:
                continue
            if c in follow.get(u, set()):
                in_cnt += 1
            else:
                ok = False
                break

        if ok and in_cnt >= 1:
            print(c)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先读取所有 m 个聊天室用户并存储他们的 ID 和关注列表。 对 t = 0 的特殊处理确保我们正确地将“0”行视为空列表而不是文字节点。 

然后我们构造一个仅包含聊天室用户的集合 S。 每个邻接列表都会被过滤，以便仅保留 S 内的边。 这是关键的缩减步骤，确保我们只推理归纳子图。 

在候选人评估期间，我们首先通过检查过滤后的传出集是否为空来强制执行“在聊天室中无人关注”条件。 这是最强的剪枝条件，所以首先检查。 

然后，我们通过扫描所有其他聊天室成员并检查其传出组中的成员资格来计算传入边缘。 如果任何会员不关注该候选人，我们将立即拒绝。 否则，我们确保至少存在一条传入边。

 ## 边缘情况

 一种重要的边缘情况是 m = 1 时。对于输入：```
1 1
1 0
```该算法立即返回 -1，因为没有节点可以满足“聊天室中至少有一个关注者”。 这可以避免错误地接受一个简单的单例。 

另一种情况是，一个节点没有跟随任何人，但也没有被所有其他节点跟随。 例如：```
3 3
1 1
2 1
2 0
```这里节点 2 的出边为零，但节点 1 不跟随 2，因此传入条件失败。 该算法在传入扫描期间正确拒绝它。 

第三种情况是密集的相互追随。 如果每个节点都跟随其他节点，则没有候选节点通过，因为所有节点的传出约束均失败。 基于传出集大小的早期拒绝确保我们永远不会错误地接受完全连接的节点。
