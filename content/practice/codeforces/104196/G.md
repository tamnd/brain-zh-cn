 ## 解决方案
 ## 问题理解

 我们得到一个算术表达式，其中包含三个写为字符串的整数，其形式为$x + y = z$或者$x \times y = z$。 我们收到的表达式是故意错误的，但它是由一种特定类型的错误产生的：有人取出三个数字中的两个，将它们每个拆分为非空前缀和后缀，然后仅交换这两个数字之间的前缀。 后缀保持不变。 

所以如果我们取两个数字`x = AB`和`y = CD`，我们选择分割点，以便`x = A|B`和`y = C|D`，然后我们将它们转化为`C|B`和`A|D`。 第三个数字不变。 对这三个数字中的一对数字进行一次这样的运算后，表达式就变成了正确的方程。 

任务是恢复原来的正确方程。 该保证表示，存在一种有效的方法来选择一对数字和前缀分割点，使等式成立。 

输入大小足够小，每个数字都低于$2^{31}$，这意味着每个数字最多包含 10 位数字。 这立即排除了任何高级优化的需要。 即使是对分割位置的嵌套暴力破解也是可以接受的，因为总搜索空间的边界约为$10 \times 10 \times 3$每对数字的可能性，并且只存在三对。 

一个微妙的细节是，交换的结果可能会在中间字符串中引入前导零，但在解析时这些仍然是有效的整数。 因此，我们必须将字符串视为原始数字序列，并且仅在验证时将它们解释为整数。 

边缘情况主要来自前缀分割的行为方式。 分割必须是正确的，这意味着我们不能采用空前缀或整个字符串。 例如，`"12"`只能拆分为`"1|2"`， 不是`"|12"`或者`"12|"`。 当数字的长度为 1 时，这一点变得很重要，因为它根本无法参与交换。 

另一个边缘情况是依赖于操作员的正确性。 我们必须确保完全按照给定的方式测试加法和乘法，而不对操作数进行任何重新排列。 

## 方法

 一种直接的方法是尝试一切可能的方法来模拟所描述的错误。 我们选择三个数字中的两个，然后尝试每个数字中的每个有效分割位置，交换前缀，重建数字，并检查所得方程是否有效。 

这是可行的，因为结构受到极大的限制。 唯一允许的转换是在两个选定的字符串之间交换前缀。 这意味着对于一对长度的字符串$n$和$m$， 有$(n-1)(m-1)$分割它们的可能方法。 自从$n, m \le 10$，每对最多大约 81 次操作。 只有三对，所以总工作量很小。 

一种强力替代方案是将每个数字视为可能由两个原始数字的任意组合产生的结果，并尝试重建隐藏的原始状态，但这是不必要的，因为前向模拟空间已经很小且结构化。 

关键的观察是，我们永远不需要一次考虑多次交换，也永远不需要考虑交换后缀或更复杂的重新排列。 该问题明确地将损坏限制为单个前缀交换，从而使枚举完整且安全。

 ## 算法演练

 我们将这三个数字视为字符串，并系统地模拟每个允许的腐败逆转。 

1. 将输入解析为三个字符串$x$,$y$， 和$z$，并读取运算符。 这使我们能够以字符串形式工作，因此前缀操作很容易。 
2. 对于其中的每个无序对$(x, y)$,$(x, z)$， 和$(y, z)$，我们假设这些是因交换前缀而损坏的两个数字。 
3. 对于所选对，迭代第一个字符串中的所有有效分割点和第二个字符串中的所有有效分割点。 位置处的分割点$i$表示前缀是前面的子串$i$，后缀来自$i$向前。 分割必须满足$1 \le i < \text{len}$。 
4. 通过交换前缀同时保持后缀固定来构造两个字符串的交换版本。 如果原始字符串是$a = A + B$和$b = C + D$，变换后的字符串变为$C + B$和$A + D$。 
5. 交换后重建完整的三元组。 第三个数字保持不变。 
6. 将所有三个字符串转换为整数，并检查给定运算符下等式是否成立。 如果操作员是`+`，我们验证$a + b = c$。 如果是的话`*`，我们验证$a \times b = c$。 
7. 如果有效，则立即输出重建的方程，因为保证了唯一性。 

它之所以有效，是因为通过枚举所有可能的前缀分割，原始损坏过程是完全可逆的。 每个有效的变换都必须出现在这个搜索空间中，因为我们尝试了每一对数字以及其中的每个合法分割点。 没有替代结构可以在不通过此枚举生成的情况下生成最终方程，因此保证正确的配置仅遇到一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse(expr):
    parts = expr.strip().split()
    return parts[0], parts[1], parts[2], parts[3]

def check(a, op, b, c):
    if op == '+':
        return a + b == c
    else:
        return a * b == c

def try_pair(a, b, c, op):
    na, nb = len(a), len(b)

    for i in range(1, na):
        for j in range(1, nb):
            a1 = b[:j] + a[i:]
            b1 = a[:i] + b[j:]

            x = int(a1)
            y = int(b1)
            z = int(c)

            if check(x, op, y, z):
                return a1, b1, c
            if check(x, op, z, y):
                return a1, c, b1

    return None

def solve():
    expr = input().strip().split()
    x, op, y, eq, z = expr

    pairs = [
        (x, y, z),
        (x, z, y),
        (y, z, x)
    ]

    for a, b, c in pairs:
        res = try_pair(a, b, c, op)
        if res:
            A, B, C = res

            if (A, B, C) == (x, y, z):
                print(f"{A} {op} {B} = {C}")
            elif (A, C, B) == (x, y, z):
                print(f"{A} {op} {C} = {B}")
            elif (B, A, C) == (x, y, z):
                print(f"{B} {op} {A} = {C}")
            elif (B, C, A) == (x, y, z):
                print(f"{B} {op} {C} = {A}")
            return

if __name__ == "__main__":
    solve()
```该代码将所有内容保留为字符串形式，直到最后的验证步骤。 这可以避免在需要时进行不必要的算术。 每对都是独立测试的，对于每对，我们耗尽所有前缀分割组合。 

一个常见的陷阱是忘记交换的对可以对应于最终方程中三个位置中的任意两个，因此实现显式测试第三个未触及数字的所有位置的一致性。

 ## 边缘情况

 一种关键的边缘情况是当一个数字的长度为 1 时。在这种情况下，不存在有效的前缀分割，因此该数字无法参与交换。 该算法自然会处理这个问题，因为分割点上的循环从 1 开始，以长度负 1 结束，不会产生迭代。 

例如，考虑`5 + 12 = 17`。 如果我们尝试参与`5`在交换中，没有有效的分割，因此该货币对没有任何贡献。 然后该算法仅考虑涉及的对`(12, 17)`或其他，确保正确性。 

另一种情况是交换引入前导零。 例如，交换前缀`"103"`和`"45"`可以产生`"403"`和`"15"`。 根据转换规则，这些仍然是有效整数，因此整数检查仍然正确。 

最后一个微妙的情况是确保正确分配哪个重构的数字对应于方程中的哪个位置。 由于交换的对可以以任一顺序着陆，因此我们在验证期间明确测试了两个方向。 这可以防止算术正确但操作数放置错误的静默不匹配。
