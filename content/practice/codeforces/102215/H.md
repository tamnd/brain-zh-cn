 ## 解决方案
 ## 问题理解

 我们有一个长度为 n 的数组。 它的元素是从 0 到 n 的不同整数，因此不会恰好出现该范围内的一个值。 数组本身是隐藏的。 我们无法直接读取它的值。 相反，对于任何数组位置 i 和位位置 b，我们可以向交互器询问 a i 的第 b 位。 

任务是在最多使用 2n+19 位查询时确定缺失值。 官方声明确认交互以n开始，每个查询返回一位，最终答案必须打印为`! x`。 

界限 n≤1000 足够小，因此对所有值 0,…,n 的普通计算都很便宜。 困难的约束是查询限制。 读取每个数组元素的每一位将大约使用 nlog 2 ​ n 个查询，当 n=1000 时，大约需要 10000 个查询，远高于允许的 2019 个。该算法必须减少问题数量，而不仅仅是优化本地计算。 

有两种边缘情况通常会导致错误。 首先，缺失值可以是 0。例如，当 n=1 时，唯一可能的数组是`[1]`，所以答案是`0`。 将答案初始化为非零值或将零视为特殊失败情况的解决方案可能会出错。 

其次，缺失值可以是 n，包括当 n 本身是 2 的幂时。 例如，n=4 和数组`[0,1,2,3]`，答案是`4`。 需要位位置 2，因为 4 是`100`以二进制形式。 一个粗心的循环仅使用`range(int(log2(n)))`会在查询该位之前停止，并且永远无法区分 4 和较小的值。 

保证数组包含不同的值。 因此，输入如`n=3`和`[1,1,2]`不是有效的测试用例。 特别是，“全相等”数组超出了问题的范围，因此它不能有意义地用作所提交的交互式解决方案的正确性测试。 

## 方法

 直接的解决方案将完全重建每个数组元素。 由于每个值都在 0 到 n 之间，因此每个值最多需要 ⌊log 2 ​ n⌋+1 位。 对于 n=1000，即 10 位，因此在最坏的情况下重构所有 1000 个元素需要 10000 次查询。 一旦知道这些值，找到缺失的数字就很简单了，但查询预算已经超出了。 

有用的观察是我们不需要知道任何完整的数组值。 我们只需要知道缺少的一个值的位。 

假设我们已经知道丢失数字的几个低位。 考虑从 0 到 n 的所有值都具有这些位。 称它们为可能的值。 在实际的数组元素中，包含缺失值的组中恰好少了一个元素，而其他所有组中的元素数量都恰好符合预期。 

现在查询下一位，但仅查询其已知位与缺少的前缀匹配的数组位置。 我们获得两组，一组具有位 0，一组具有位 1。我们还知道从 0 到 n 有多少个值应属于每一组。 观察到的大小小于其预期大小的组必须包含缺失值。 

这样做节省查询的原因是，在固定 b 低位之后，可能的数字具有相同的模 2 b 的余数。 他们的下一位几乎平分了他们。 因此，候选数组位置在每次迭代时大约缩小两倍。 我们从不查询已经被淘汰的职位。 

蛮力之所以有效，是因为每个查询的位都提供了足够的信息来重建元素，但它失败了，因为它花费了 θ(nlogn) 查询来重建我们不需要的信息。 观察到只有包含缺失值的组很重要，这让我们可以通过这个隐式二进制分区遵循一条路径，将查询总数减少到 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nlogn) 查询 | O(n) | 查询太多 |
 | 最佳 | O(nlogn) 本地计算，O(n) 查询 | O(n) | 已接受 |

 ## 算法演练

 1. 从 0 到 n 的每个值作为可能的缺失值，并将每个数组索引作为候选位置。 

此时我们对缺失的数字一无所知，因此每个值和每个数组元素都是相关的。 
2. 从最低有效位向上处理位位置`n.bit_length() - 1`。 

这些正是 0 到 n 的数字中可能出现的位。 首先处理低位很方便，因为具有相同处理位的值形成几乎均匀的算术级数，这提供了所需的收缩特性。 
3. 将当前可能的值拆分为`possible_zero`和`possible_one`根据当前位。 

这些列表告诉我们如果没有丢失的话，应该有多少个值具有位 0 和位 1。 
4. 对于每个当前候选数组索引，向交互器询问该位并将索引拆分为`candidate_zero`和`candidate_one`。 

我们只询问先前发现的位与缺失数字一致的候选者。 所有其他数组元素都已被排除为缺失值的来源。 
5. 将观察到的组大小与预期组大小进行比较。 

如果`len(candidate_zero) < len(possible_zero)`，缺失值的位为 0。否则，它的位为 (1`，因为包含缺失数的组中恰好缺少一个值。
 6. 仅保留对应的值组和候选索引组。 

现在保留了不变量：`possible_values`包含与丢失数字的所有已发现位完全一致的值，而`candidates`确切地包含其值具有相同位的数组位置。 
7. 当选择的组是第 1 位组时，设置答案的相应位。 

处理完每一个相关位后，只剩下一个可能的值。 使用交互式答案格式打印它。 

### 为什么它有效

 在每次迭代开始时，候选数组位置表示与缺失值具有相同处理位的所有当前值。 相应的`possible_values`包含具有相同位模式的从 0 到 n 的所有值。 由于恰好缺少一个值，因此在包含缺失值的组中，实际数组的元素比预期少了一个。 比较观察到的和预期的组大小可以唯一地识别丢失的位。 过滤这两个组然后保留下一位的不变量。 在处理完所有位之后，两个不同的值不能共享每个相关位，因此剩余的可能值正是丢失的数。 

## Python 解决方案

 实际的 Codeforces 问题是交互式的，因此下面的程序必须作为交互式解决方案提交。 语句示例中显示的空行只是演示格式，真正的交互需要在每次查询和最终答案后刷新。```python
Pythonimport sysinput = sys.stdin.readline

def main():    n = int(input())
    possible_values = list(range(n + 1))    candidates = list(range(n))
    answer = 0
    for bit in range(n.bit_length()):        possible_zero = []        possible_one = []
        for value in possible_values:            if (value >> bit) & 1:                possible_one.append(value)            else:                possible_zero.append(value)
        candidate_zero = []        candidate_one = []
        for idx in candidates:            print("?", idx + 1, bit, flush=True)            response = int(input())
            if response == -1:                sys.exit(0)
            if response == 0:                candidate_zero.append(idx)            else:                candidate_one.append(idx)
        if len(candidate_zero) < len(possible_zero):            possible_values = possible_zero            candidates = candidate_zero        else:            possible_values = possible_one            candidates = candidate_one            answer |= 1 << bit
    print("!", answer, flush=True)

if __name__ == "__main__":    main()
```程序首先初始化`possible_values`包含所有 n+1 个值，因为其中任何一个值最初都可能丢失。`candidates`包含每个数组索引，因为尚未排除任何位置。 

对于每一位，可能的值在提出问题之前被划分。 这给出了每个位组的确切预期数量。 然后逐一查询数组位置，并将响应形成相应的观察组。 

比较`len(candidate_zero) < len(possible_zero)`是中央的决定。 不可能有两个缺失值，因此如果零组小于预期，则其缺失成员必定是答案。 如果不小于，则该组一定缺少一名成员。 

仅当选择一组时才设置应答位。 不需要明确地构造答案`possible_values`，尽管在最后一次迭代之后该列表只包含一个数字。`idx + 1`是必要的，因为 Python 存储数组索引从 0 开始，而交互器从 1 开始编号位置。 该位本身不会移位或调整，因为该语句对位进行编号从零开始。 

循环使用`n.bit_length()`而不是`int(log2(n))`。 对于n=4，`n.bit_length()`是 3，所以位 0,1,2 被处理并且值 4=100 2 被正确处理。 Python 整数不会溢出，因此不需要特殊的整数类型。 

这`flush=True`在交互式问题中，每个查询都是强制性的。 如果没有它，Python 可能会将查询保留在其输出缓冲区中，同时程序等待交互器的响应，从而导致死锁。 该语句明确要求刷新每个交互消息。
