 ## 解决方案
 ## 问题理解

 将提问策略视为二元决策树。 每个内部节点都是一个问题，它的两个出边对应于答案“是”和“否”，并且每个叶子都准确地标识一个人。 由于问题可能包含当前可能的人员的任何子集，因此可以在节点处使用候选者的任何二进制分区。 那么原来的游戏就是构建二叉前缀树的问题。 

如果人 (i) 最终到达深度 (l_i)，则 Akinator 在选择该人时会准确询问 (l_i) 个问题。 由于 (p_i=a_i/\sum a_j)，预期问题数为

 [
 \frac{\sum_i a_i l_i}{\sum_i a_i}。 
]

 分母是固定的，所以真正的优化目标是整数

 [
 \sum_i a_i l_i。 
]

 树的最大深度必须为 (k)。 当 (n\le 2^k) 时，存在具有 (n) 个叶子且高度最多为 (k) 的二叉树。 如果失败，任何提问策略都无法区分允许数量的问题中的所有人。 二进制前缀码的 Kraft 绑定也是如此。 

(n) 中的约束很小，但它们不允许枚举树或子集。 对于 (n\le100)，即使 (O(n^3)) 也是无害的，而 (n) 中的任何指数都是完全不可行的。 概率由大到 (10^{12}) 的整数表示，因此实现应该完全使用精确的整数而不是浮点数。 

有几种边界情况可能会欺骗幼稚的实现。 对于一个可能的人来说，不需要提问。 例如，```
1 1
1000000000000
```有答案`0/1`。 假设每个人至少需要一个问题的解决方案将错误地输出正值。 

深度限制可能使普通的霍夫曼构造变得不可能。 例如，```
3 1
1 2 3
```有输出`No solution`，因为一个二元问题只有两个可能的答案序列。 运行普通的霍夫曼编码而不检查高度约束可以默默地生成深度为二的树。 

相反的边界是 (n=2^k) 时。 那么无论权重如何，每片叶子都必须精确地位于深度 (k) 处。 例如，```
4 2
1 2 3 4
```具有加权成本 (2(1+2+3+4)=20)，所以答案是`2/1`。 试图为一个人提供较短代码的策略不可能在不让另一个人比两个问题更深入的情况下实现这一目标。 

最后，相等的权重对于检测排序错误很有用。 和```
3 2
1 1 1
```最佳深度为 (1,2,2)，给出总成本 (5) 和答案`5/3`。 最常出现的人在这里并不特殊，因此任何正确的领带处理仍然必须产生相同的总数。 

## 方法

 直接方法会尝试每种可能的二元决策树。 在当前可能的人的集合 (S) 中，一个问题选择一个非空真子集 (A\subset S)，其中 (A) 成为 Yes 分支，(S\setminus A) 成为 No 分支。 子集上的递归动态程序可以记住每个子集的最佳成本和剩余深度。 

这是正确的，因为每个可能的提问策略都有这样的第一分区，并且在第一个问题之后产生的两个子问题是独立的。 不幸的是，有 (2^n) 个子集，并且考虑所有可能的分割会在此基础上进行指数工作。 在所有子集中，有序非平凡分割的数量为

 [
 \sum_{S\ne\varnothing} (2^{|S|}-2)
 =3^n-2^{n+1}+1。 
]

 对于 (n=100)，(3^{100}) 约为 (5.15\cdot10^{47})，因此这种方法不太可行。 

有用的观察是，我们实际上并不关心哪个人访问哪个确切的二进制字符串。 我们只关心深度（l_i）。 当一组深度满足 Kraft 不等式时，可以通过二叉前缀树实现

 [
 \sum_i2^{-l_i}\le1。 
]

 对于最优树，等式成立，因为如果总和较小，我们可以在不违反约束的情况下缩短一些代码。 因此，问题变成了长度受限的霍夫曼编码问题：最小化 (\sum a_i l_i) 服从 (1\le l_i\le k) 和 (\sum 2^{-l_i}=1)。 

有一种特别干净的方法可以解决这个受限霍夫曼问题。 想象一下，每个人最初的长度都为零。 则 Kraft 总和为 (n)。 将人 (i) 的长度从 (l-1) 增加到 (l) 会使 Kraft 总和减少 (2^{-l})，并且成本正好为 (a_i)。 我们需要执行长度增加，其总牛皮纸减少量为 (n-1)。 

这将问题变成了二进制硬币收集器问题。 为每个人 (i) 创建 (k) 个面额的硬币

 [
 2^{-1},2^{-2},\l点,2^{-k},
 ]

 并给出每一枚硬币的价值（a_i）。 我们需要一个面额总和为 (n-1) 的最小值集合。 如果选择了级别(l)对应的硬币，则代表该人的代码长度增加到级别(l)。 这是长度有限的霍夫曼编码的包合并背后的标准缩减。 

因为所有面额都是 2 的幂，所以硬币问题有一个贪婪的解决方案。 对于最小面额的硬币，任何选定的硬币都必须成对出现，因为每个较大面额的硬币都是两倍大。 最便宜的货币对由两种最便宜的可用硬币组成。 然后，这对硬币可以被视为下一个面额的一枚硬币。 如果剩下一枚硬币，它永远无法参与精确解决方案，因此可以丢弃最昂贵的剩余硬币。 重复此过程会产生包合并算法。 

暴力破解之所以有效，是因为它明确地探索了所有二进制分区。 包合并观察让我们仅用包含最便宜的相关包的 (k) 个排序列表来替换所有这些树。 由于 (n,k\le100)，即使是简单的 (O(nk)) 实现也很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(3^n)) | (O(2^n)) | 太慢了 |
 | 最佳包合并 | (O(nk)) | (O(nk)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 按非降序对权重 (a_i) 进行排序。 可以以任何顺序放置相同的权重。 包合并算法总是需要按值递增的顺序排列项目，并且由两个相邻排序项目形成的包的值不小于前一个包。 
2. 检查是否(n\le2^k)。 如果不是，则深度 (k) 内不可能有 (n) 个不同的叶子，因此打印`No solution`。 
3. 将排序后的权重视为面额 (2^{-k}) 的硬币的初始列表。 这些是最小的硬币，因此它们是最先可以配对的硬币。 
4. 重复以下过程 (k-1) 次。 从两个最便宜的开始，将当前排序列表的连续元素配对。 每对都成为一个包，其值是其两个元素的总和。 然后将包列表与原始权重的另一个副本合并，并对结果进行排序。 

原始重量代表新面额两倍的普通硬币。 这些包装代表两枚较小的硬币，它们已组合成完全相同的面额。 将这两种选择保留在一个排序列表中，可以让以后的决策在单一昂贵的硬币和更便宜的包装之间进行选择。 
5. 在这 (k-1) 轮之后，最后一次将连续元素配对，但不要将结果包与原始权重合并。 这些包装现在的面额为 (1)。 
6. 选择 (n-1) 个最便宜的最终包并添加它们的值。 该总和是最小可能的加权问题数。 
7. 将所得整数除以 (S=\sum a_i)。 计算分子和 (S) 的最大公约数，将两者除以它，然后打印约简分数。 

### 为什么它有效

 令 (l_i) 为分配给人员 (i) 的最终深度。 从每个 (l_i=0) 开始，Kraft 总和为 (n)。 将 (l_i) 从 (l_i-1) 增加到 (l_i) 会使总和减少 (2^{-l_i})，同时将目标增加 (a_i)。 达到有效的完全二叉树需要 Kraft 总和恰好变为 (1)，因此所选的约简必须具有总值 (n-1)。 

包合并结构正好解决了这个最小值选择问题。 对于每种面额，有效的解决方案只能使用最小面额偶数次。 如果它使用 (2r) 个这样的硬币，那么使用 (2r) 个最便宜的硬币总是最佳的，并且这些硬币可以分为 (r) 个连续的对。 用一包替换每一对可以保留其总面额和总价值。 因此，贪婪地解决小面额层会准确地产生下一层所需的选择集。 

在最后一层，每个选定的项目都有面额 (1)，因此选择其中 (n-1) 即可得到总面额 (n-1)。 扩展包会为每个代码长度每增加一个单位提供一个选定的硬币，因此总包价值恰好是（\sum_i a_i l_i）。 由于包合并最小化了该值，因此生成的代码具有最少的预期问题数量。 所得长度满足 Kraft 等式且最多为 (k)，因此存在实现它们的二叉前缀树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def merge_sorted(a, b):
    """Merge two already sorted lists."""
    res = []
    i = 0
    j = 0

    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            res.append(a[i])
            i += 1
        else:
            res.append(b[j])
            j += 1

    if i < len(a):
        res.extend(a[i:])
    if j < len(b):
        res.extend(b[j:])

    return res

def solve():
    n, k = map(int, input().split())
    weights = list(map(int, input().split()))
    weights.sort()

    if n > (1 << k):
        print("No solution")
        return

    current = weights[:]

    # Move from denomination 2^(-k) up to denomination 2^(-1).
    # At every intermediate level, packages are merged with
    # the original coins of the new denomination.
    for _ in range(k - 1):
        packages = []
        for i in range(0, len(current) - 1, 2):
            packages.append(current[i] + current[i + 1])

        current = merge_sorted(weights, packages)

    # One final packaging step creates denomination-1 items.
    final_packages = []
    for i in range(0, len(current) - 1, 2):
        final_packages.append(current[i] + current[i + 1])

    # final_packages is already sorted.
    numerator = sum(final_packages[:n - 1])
    denominator = sum(weights)

    g = __import__("math").gcd(numerator, denominator)
    numerator //= g
    denominator //= g

    print(f"{numerator}/{denominator}")

if __name__ == "__main__":
    solve()
```输入权重在开始时排序一次。 排序就足够了，因为包值是通过添加排序列表的相邻元素形成的，因此生成的包列表也是排序的。 

这`merge_sorted`函数利用了这个属性。 它在线性时间内将（n）个原始权重与当前包列表合并。 在每个级别对整个列表重新排序仍然可以轻松地通过 (n,k\le100)，但合并使预期的 (O(nk)) 复杂性变得明确。 

该循环仅运行前 (k-1) 个级别。 最终级别故意单独处理，因为最终包装的面额为（1），并且不存在面额（1）的原始硬币。 将原始权重混合到最终列表中会在面额结构中产生相差一的错误。 

创建对时使用的范围是`range(0, len(current) - 1, 2)`。 如果当前列表有奇数个元素，则其最后一个元素将不被使用。 由于列表已排序，因此该元素是最昂贵的元素，这正是 package-merge 丢弃的项目。 

可行性检查使用`1 << k`，因此不存在浮点对数，也不存在舍入问题。 Python 整数还可以安全地处理最大可能的中间值。 最大的相关加权成本约为 (n^2\cdot10^{12})，远低于 Python 的任意精度整数可以轻松处理的范围。 

最终的包列表已经排序，因为`current`已排序，并且每个连续对的总和是非递减的。 因此，(n-1) 个最便宜的包就是它的前 (n-1) 个元素。 

对于 (n=1)，该切片为空，分子为零。 分母为正，因此减少后的答案是正确的`0/1`。

 ## 边缘情况

 对于一个人来说，输入```
1 1
1000000000000
```通过容量检查。 初始列表包含一个值，并且没有可形成的对。 最终的套餐列表为空，因此选择 (n-1=0) 最便宜的套餐成本为零。 分母为正，给出`0/1`。 这与 Akinator 已经知道这个人是谁的事实相符。 

对于太多人来说，考虑```
3 1
1 2 3
```该算法立即检查 (3>2^1)。 高度为 1 的二叉树不能有三个叶子，所以它打印`No solution`。 这可以防止不完整的最终包列表被误认为是有效的代码。 

对于精确的容量边界，```
4 2
1 1 1 1
```四片叶子必须占据深度二处的所有四个位置。 第一次包装创建两个价值包（2），最终的包装只有在中间列表形成后才创建一个价值包（4），最终选择的成本为（8）。 除以总重量 (4) 得出`2/1`。 没有空间容纳较短的码字，因为缩短一个叶子会迫使另一叶子超出深度二。 

对于三个人同等重量的情况，```
3 2
1 1 1
```第一个包列表是`[2]`，与原始权重合并得到`[1,1,1,2]`。 最终的包是`[2,3]`，两者都必须选择。 它们的总价值是（5），而总概率权重是（3），给出`5/3`。 对应的长度为(1,2,2)，其Kraft和为(1/2+1/4+1/4=1)。 

对于最大的输入尺寸，```
