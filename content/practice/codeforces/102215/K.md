 ## 解决方案
 ## 问题理解

 我们有一个长度为 (n) 的字符串，其中每个字符都是以下之一`R`,`G`， 或者`B`。 该字符串从上到下描述了牌组。 我们可以将卡片一张一张地分成两堆。 由于每张新牌都放置在其所选牌堆的顶部，因此每堆牌内的顺序相对于其牌在原始牌堆中出现的顺序是相反的。 最后，一整堆被放置在另一堆之上，因此最终的牌是原始字符串的两个反向子序列的串联。 

目标是决定最终的牌组是否可以将每种颜色的所有牌放在一起。 三个色块可以以任何顺序出现。 官方问题允许（1 \le n \le 1000）。 

仅 1000 个字符的界限就足够大，无法穷举所有分发卡片的方式。 两堆牌有 (2^n) 次分配，因此即使在 (O(n)) 时间内检查一个分配也会给出 (O(n2^n)) 次操作。 对于 (n=1000)，这远远超出了 2 秒限制可以处理的范围。 相反，解决方案应该利用只有三种颜色的事实，只为最终色块提供六种可能的顺序。 

有几种边界情况可能会欺骗粗心的实现。 一副牌，例如`R`必须返回`YES`，因为它已经排序并且不需要有意义的分割。 假设所有三种颜色都出现的实现可能会失败。 甲板如`RGB`也必须返回`YES`，即使每种颜色只出现一次。 需要重复出现每种颜色的解决方案会错误地拒绝它。 

缺失的颜色也需要特殊处理。 例如，`RRR`已经排序了，所以答案是`YES`。 当被选为候选排序的第一个或最后一个颜色的颜色没有出现时，就没有实际的第一个或最后一个出现可用作边界。 例如，将不存在的第一次出现视为位置 (n) 可能会意外地计算出不应属于该方的牌。 下面的实现显式处理不存在的颜色。 

## 方法

 直接的暴力解决方案可以将每张牌独立分配到两堆牌中的一堆。 对于每个 (2^n) 作业，我们可以构建两个堆，反转它们的内部顺序，以两种可能的顺序将它们连接起来，并检查生成的牌组是否最多包含三个颜色块。 这是正确的，因为每个合法的操作序列都恰好对应于这样的分成两堆的划分。 然而，有 (2^n) 个分区，每次检查都需要 (O(n))，从而提供 (O(n2^n)) 工作。 在 (n=1000) 时，单独的分配数量约为 (10^{301})，因此这种方法不太可行。 

有用的观察结果是最终的牌只包含三个色块。 假设我们按某种顺序选择三种不同的颜色（A、B、C）。 我们将构建两个堆，以便在反转并连接它们之后，结果是 (C^*B^_A^_)，这已经是一个有效的排序牌组。 (A,B,C)只有六种选择。 

对于固定选择（A，B，C），将每张（A）卡放入第一堆，将每张（C）卡放入第二堆。 剩下的（B）卡只有两个有用的位置。 在第一张 (C) 之前出现的 (B) 卡可以进入第二堆。 最后一张（A）之后出现的（B）牌可以进入第一堆。 

为什么要选择这些职位？ 当按照原始牌组顺序阅读时，第一堆的形式为

 [
 A A \ldots A B B \ldots B.
 ]

 翻转后就变成了

 [
 B B \ldots B A A \ldots A.
 ]

 第二堆有原来的顺序

 [
 B B \ldots B C C \ldots C,
 ]

 所以反转后就变成了

 [
 C C \ldots C B B \ldots B.
 ]

 将第二堆放在第一堆上面给出

 [
 C C \ldots C B B \ldots B A A \ldots A,
 ]

 已排序。 

唯一的问题是，是否可以将每张（B）牌分配到这两堆牌中的一组，而无需将同一张牌分配两次。 第一个 (C) 之前的 A (B) 属于第二堆，而最后一个 (A) 之后的 (B) 属于第一堆。 如果某个 (B) 位于第一个 (C) 和最后一个 (A) 之间，则不能通过此结构放置它。 如果两个区域重叠，则 a (B) 也可能被计数两次。 因此，当分配到两堆的牌的数量为 (n) 时，构造就成功了。 

这种特征对于每一种可能的有效排序来说也足够了。 如果最终颜色顺序为 (X,Y,Z)，则取 (A=Z)、(B=Y) 和 (C=X)。 最后两堆之间的切割可以发生在中间色块内的任何位置。 将两块翻转，将属于第一块的（Y）卡放在原牌组（X）之前，将剩余的（Y）卡放在（Z）之后，这正是上面的构造所测试的结构。 枚举所有六种排列涵盖了每种可能的最终颜色顺序。 已发布的解决方案中也使用了相同的结构思想来解决该问题。

 ## 算法演练

 1. 数一下每项出现了多少次`R`,`G`， 和`B`发生。 还记录每种颜色的第一次和最后一次出现。 这些值让我们可以测试每个候选排序，而无需重复搜索字符串。 
2. 枚举三种颜色的所有六种排列（(A,B,C)）。 我们将 (A) 解释为放置在最终排序的牌组底部的颜色，(C) 解释为放置在顶部的颜色，(B) 解释为中间的颜色。 
3. 将每张 (A) 卡放入第一堆，将每张 (C) 卡放入第二堆。 这修复了两个外部颜色块。 
4. 数出第一张 (C) 牌之前的 (B) 牌。 这些牌可以安全地进入第二堆。 翻转该堆牌后，它们出现在所有 (C) 卡牌后面。 
5. 计算最后一张 (A) 牌之后的 (B) 牌。 这些卡片可以安全地放入第一堆。 翻转该牌堆后，它们出现在所有 (A) 卡牌之前。 
6. 添加（A）卡、（C）卡和两组可用的（B）卡的数量。 如果总数恰好为 (n)，则每张卡都被分配了一次，因此所选的排序给出了有效的排序。 如果总数小于（n），则一些（B）牌位于禁止的中间区域。 如果大于(n)，则双方都算一些(B)牌。 无论哪种情况都意味着这种排列不起作用。 
7. 如果六种排列中的任何一种成功，则打印`YES`。 如果没有成功，则打印`NO`。 

当颜色没有出现时，边界需要经过深思熟虑的解释。 如果(C)不存在，则没有第一张(C)，因此没有(B)牌可以被分类为在第一张(C)之前。 如果(A)不存在，则没有最后一张(A)，因此每一张(B)牌都在最后一张(A)之后。 代码直接表示这两种情况`first_c = n`和`last_a = -1`，然后显式处理相应的计数。 

### 为什么它有效

 对于固定排列（A、B、C），该结构将第一堆分配给所有（A）牌的序列，然后是最后一张（A）牌之后选定的（B）牌。 因此，它的反转是一块（B）牌，然后是一块（A）牌。 第二堆牌包含选定的 (B) 张牌，在第一张 (C) 牌之前，然后是所有 (C) 卡。 它的反转是一块（C）牌，然后是一块（B）牌。 因此，将第二堆与第一堆连接起来会产生 (C^*B^_A^_)。 

当每张原始牌都属于这两个牌堆之一时，计数的总数恰好等于 (n)。 因此，每次成功的排列都会产生有效的排序。 相反，任何有效的排序都具有三个色块以及两个最终堆之间的边界。 以这些块的相反顺序选择 (A,B,C) 使得分配到两堆的卡片完全具有算法测试的边界结构。 由于检查了所有六种排列，因此表示了每个有效的排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve(s: str) -> str:
    n = len(s)
    colors = "RGB"

    count = {c: 0 for c in colors}
    first = {c: n for c in colors}
    last = {c: -1 for c in colors}

    for i, ch in enumerate(s):
        count[ch] += 1
        first[ch] = min(first[ch], i)
        last[ch] = i

    # Prefix counts let us count how many B cards occur
    # before an arbitrary position in O(1).
    prefix = {c: [0] * (n + 1) for c in colors}

    for i, ch in enumerate(s):
        for c in colors:
            prefix[c][i + 1] = prefix[c][i]
        prefix[ch][i + 1] += 1

    for a, b, c in permutations(colors):
        taken = count[a] + count[c]

        # B cards before the first C.
        if first[c] != n:
            taken += prefix[b][first[c]]

        # B cards after the last A.
        if last[a] != -1:
            taken += count[b] - prefix[b][last[a] + 1]
        else:
            # No A exists, so every B is after the last A.
            taken += count[b]

        if taken == n:
            return "YES"

    return "NO"

def main():
    s = input().strip()
    print(solve(s))

if __name__ == "__main__":
    main()
```第一个循环记录每种颜色的频率和边界。`first[c]`被初始化为`n`， 尽管`last[a]`被初始化为`-1`，因此可以检测到不存在的颜色，而无需超出有效索引范围的特殊哨兵值。 

前缀计数数组使两个 (B) 区域易于测量。`prefix[b][first[c]]`严格计算之前的位置`first[c]`，这正是第一个区域所需要的。 对于其他地区来说，`count[b] - prefix[b][last[a] + 1]`严格计算位置之后`last[a]`。 这`+1`是必要的，因为前缀数组使用半开范围。 

Python 中不存在整数溢出问题，所有计数最多为 1000。这六种排列由以下命令生成`itertools.permutations`，因此三种颜色的每种可能的顺序都会被检查一次。 

该实现使用一个额外的 (3(n+1)) 前缀计数结构。 这对于 (n \le 1000) 来说很小，并且它使每个排列的实际测试保持恒定时间。 

## 工作示例

 ### 示例 1

 考虑`RGBRGB`。 进行排列 (A=R,B=G,C=B)。 相关边界是最后的`R`在索引 3 和第一个处`B`在索引 2 处。 

| 排列| 计数 A | 计数 C | B 在第一个 C 之前 | 最后一个 A 之后 B | 拍摄 | 结果 |
 | ---| ---| ---| ---| ---| ---| ---|
 | （红、绿、蓝）| 2 | 2 | 1 | 1 | 6 | 是的 |

 这两堆可以直接理解。 第一堆接收所有`R`卡和`G`最后一张之后的卡`R`，给出原始顺序`RRG`。 第二堆接收`G`在第一个之前`B`和所有`B`卡片、给予`GBB`。 反转它们会产生`BGG`和`RR`，因此将第二堆放在第一堆之上给出`BGGRR`。 更准确地说，使用实际位置产生样本的有效结构，其最终甲板具有三个连续的色块。 关键的不变量是每张牌都被分配一次，并且在逆转之前每堆牌最多有两种颜色。 

### 示例 2

 对于`RGBRGBRGB`，排列 (R,G,B) 给出以下值。 

| 排列| 计数 A | 计数 C | B 在第一个 C 之前 | 最后一个 A 之后 B | 拍摄 | 结果 |
 | ---| ---| ---| ---| ---| ---| ---|
 | （红、绿、蓝）| 3 | 3 | 1 | 0 | 7 | 否 |

 剩下的两个`G`卡片位于第一张卡片之间`B`和最后一个`R`，所以这个特定的顺序不能分配所有的卡。 其他五种排列由于相同的结构原因而失败。 两个桩之间不可能有边界可以容纳重复的`RGB`模式，所以答案是`NO`。

 ## 边缘情况

 对于单卡输入`R`，算法立即考虑包含的排列`R`。 如果`R`被选为（A），`count[A] = 1`，而其他颜色的计数为零。 不需要额外的卡，所以`taken = 1 = n`答案是`YES`。 该算法从不假设所有三种颜色都存在。 

为了`GGGGGG`，选择（A=G）。 每张牌都已经是 (A) 代表的外部块的一部分，所以`count[A] = 6`总数正好是(n)。 缺失的颜色不会导致任何意外计数，因为缺失的 (C) 在其不存在的第一次出现之前不会贡献任何卡片。 

为了`BGR`，考虑 (A=R,B=G,C=B)。 第一个`B`位于索引 0 和最后一个`R`位于索引 2 处。没有`G`第一张之前的卡片`B`没有`G`最后一张之后的卡片`R`，所以这个特定的排列不会成功。 另一种排列则与已排序的顺序相对应`B-G-R`。 该示例演示了为什么必须检查所有六种排列而不是固定一种颜色顺序。 

为了`RGBRGBRGB`，每个候选排序在所需结构下不属于任何一堆的区域中至少留下一张中间颜色的卡片。 对于 (A=R,B=G,C=B)，第一个`B`发生在索引 2 和最后一个`R`在索引 6 处。只有一个`G`发生在第一个之前`B`，并且在最后一个之后没有发生`R`，同时有三个`G`卡总数。 因此，九张牌中只占了七张。 其他五种颜色顺序对称地失败，给出了所需的`NO`。
