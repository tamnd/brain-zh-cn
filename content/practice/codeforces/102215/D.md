 ## 解决方案
 ## 问题理解

 我们有一棵城市树。 对于每个预测，一些顶点是红色的，一些顶点是蓝色的，所有剩余的顶点都是中性的。 我们可以移除任何我们喜欢的道路。 删除它们后，每个红色城市仍必须属于一个连通分量，每个蓝色城市必须属于另一个连通分量，并且没有红色城市可以连接到任何蓝色城市。 

关键的困难在于我们移除的道路被许多可能的路径共享。 连接两个红色城市可能会迫使我们保留经过中立城市的道路，而这些中立城市可以成为红色区域的一部分。 蓝色城市的情况也是如此。 问题实际上是包含所有红色顶点的最小连通子树是否可以与包含所有蓝色顶点的最小连通子树不相交。 官方输入最多有（200000）个城市，所有预测的彩色顶点总数也最多为（200000）。 

对于 (n=200000)，(O(n^2)) 算法远远超出了两秒的限制。 有用的目标大致是 (O(n\log n)) 预处理，然后每个预测进行 (O((r+b)\log n)) 工作，因为每个预测的总 (r+b) 仅是 (200000)。 我们可以为每个有色城市进行对数工作，但我们无法为每个预测扫描所有 (n) 个城市。 

有几种边缘情况无法对问题进行更简单的解释。 首先，红色和蓝色的斯坦纳子树可以在中立城市相遇，即使没有城市同时具有两种颜色。 例如：```
5
1 2
1 3
2 4
3 5
1
2 2 4 5 3
```这里红色城市是(2,4)，蓝色城市是(5,3)。 红色连接使用 (2-1)，而蓝色连接使用 (3-1)，因此两个连接区域都包含城市 (1)。 正确答案是`NO`。 一个粗心的解决方案，仅检查显式着色的顶点是否重叠会错误地返回`YES`。 

同样的现象也出现在第一个样本中。 对于第二个预测，红色城市为 (4,6)，蓝色城市为 (5,7)。 它们的彩色顶点完全分开，但两个所需的连接都经过城市 (1)，因此答案是`NO`。 

当一种颜色的所需子树包含另一种颜色的 LCA 时，会出现第二种边缘情况。 考虑链条```
4
1 2
2 3
3 4
1
2 1 1 3 4
```红色城市是(1,3)，所以它们所需的子树包含(1,2,3)。 蓝色的城市是（4）。 这些可以通过切削刃（3-4）分开，所以答案是`YES`。 红色 LCA 是蓝色顶点的祖先这一事实本身并不意味着答案是否定的。 

相反的情况是```
4
1 2
2 3
3 4
1
2 1 1 4 3
```红色城市是(1,4)，蓝色城市是(3)。 红色路径是整条链，并且必然包含蓝色城市，所以答案是`NO`。 仅比较两个 LCA 顶点的测试会错过这一点。 

## 方法

 从概念上讲，直接的暴力方法是可能的。 对于每条道路，移除该道路并检查所得的两个组件。 我们可以检查是否所有红色城市都在一侧，所有蓝色城市都在另一侧，以及红色组和蓝色组是否各自相连。 由于有 (n-1) 条候选道路，并且完整验证可以检查 (O(n)) 个城市，因此一次预测可能需要 (O(n^2)) 时间。 预测的数量可以大到（100000），因为每个预测至少包含一个红色和一个蓝色城市，而彩色城市的总数以（200000）为界。 因此，最坏情况的构造可以达到大约 (10^5\cdot 2\cdot 10^5=2\cdot10^{10}) 顶点检查，这根本不可行。 

蛮力之所以有效，是因为树的有效划分始终由连接组件之间的切割边表示。 问题是在没有明确考虑每条边的情况下找到这些组件。 

有用的观察是，在一棵树内，任意两个城市之间只有一条路径。 因此，如果几个红色城市必须保持连接，那么它们之间的每条路径都是被迫的。 他们的联合是一个独特的最小连通子树。 蓝色城市也是如此。 这正是斯坦纳子树的树版本，包含一组指定的终端的最小连通子图。 

如果所需的两个子树是顶点不相交的，我们可以将每个边保留在每个子树内，并剪切将它们与树的其余部分分开的边。 红色城市保持连接，蓝色城市保持连接，两组无法相互到达。 如果两个子树相交，则任何道路移除选择都无济于事，因为包含所有红色城市的每个连接组件必须包含红色子树，并且包含所有蓝色城市的每个连接组件必须包含蓝色子树。 

现在将树植根于城市 (1)。 对于任意一组顶点，令其 LCA 为该组中所有顶点的最低公共祖先。 如果(A)是所有红色城市的LCA，则每个红色顶点都位于(A)的子树中。 类似地，如果（B）是所有蓝色城市的LCA，则每个蓝色顶点都位于（B）的子树中。 

那么只有两种结构可能性。 如果 (A) 和 (B) 都不是对方的祖先，则它们的根子树是不相交的，因此所需的两个子树是不相交的，答案是`YES`。 如果 (A) 是 (B) 的祖先，则蓝色所需的子树位于 (B) 的子树内部。 红色所需子树与其相交的唯一方法是某个红色城市本身位于 (B) 的子树内。 当 (B) 是 (A) 的祖先时，对称论证适用。 

这给出了与该问题的已知解决方案所使用的相同的基于 LCA 的表征。 

我们可以使用二元提升在 (O(\log n)) 中找到两个顶点的 LCA。 然后逐步获得整个颜色类的 LCA：从第一个红色城市开始，反复用它和下一个红色城市的 LCA 替换当前的 LCA。 同样的过程给出了蓝色的 LCA。 因为所有预测中的有色城市总数最多为 (200000)，所以这已经足够快了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(qn^2)) 的直接形式 | (O(n)) | (O(n)) | 太慢了 |
 | 最佳| (O(n\log n + S\log n))，其中 (S\le 200000) 是彩色城市的总数 | (O(n\log n)) | 已接受 |

 ## 算法演练

 1. 以城市 (1) 为树的根，并计算每个城市的深度和直接父级。 父关系为我们提供了 LCA 查询所需的结构。 
2. 搭建一个二元升降台。`up[k][v]`存储 (v) 的祖先，即其上方 (2^k) 条边。 这让我们可以在对数多次操作中向上移动很远的距离。 
3. 对于每个预测，读取所有红色城市并增量计算它们的共同 LCA。 从第一个红色城市开始`red_lca`。 对于接下来的每个红色城市 (x)，设置`red_lca = LCA(red_lca, x)`。 生成的顶点是最低的顶点，是每个红色城市的祖先。 
4. 对所有蓝色城市进行同样的操作，得到`blue_lca`。 
5. 计算`common = LCA(red_lca, blue_lca)`。 如果`common`与两个 LCA 都不同，那么两种颜色的 LCA 都不是另一种颜色的祖先。 两个所需区域位于不同的子子树中`common`，所以输出`YES`。 
6.如果`red_lca == common`，那么红色 LCA 是蓝色 LCA 的祖先。 蓝色所需的子树包含在以`blue_lca`。 检查每个红色城市 (x)。 如果`LCA(x, blue_lca) == blue_lca`，则 (x) 位于蓝色 LCA 子树内。 由于红色子树必须将 (x) 连接到其他红色城市，因此它达到`blue_lca`，属于蓝色所需子树。 区域相交，因此输出`NO`。 如果那里没有红色城市，则输出`YES`。 
7. 剩下的情况是`blue_lca == common`，所以蓝色 LCA 是红色 LCA 的祖先。 对每个蓝色城市进行对称测试，检查是否`LCA(x, red_lca) == red_lca`。 一个交集给出`NO`; 否则两个所需区域是不相交的，答案是`YES`。 

该算法背后的不变量是`red_lca`和`blue_lca`总是描述它们各自所需的连接子树的强制根。 当两个 LCA 位于不同的根子树中时，所需的区域无法相遇。 当一个 LCA 包含另一个 LCA 时，交集只能发生在后代 LCA 的子树内部，并且当相反颜色在那里有终结符时，该交集恰好存在。 这体现了每一种可能的安排，因此每一种`YES`对应于一组可实现的道路切口，并且每个`NO`对应着不可避免的交叉点。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def solve(reader=None):
    input = reader if reader is not None else sys.stdin.readline

    n = int(input())

    graph = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    # Root the tree at 1.
    parent = array('i', [0]) * (n + 1)
    depth = array('i', [0]) * (n + 1)

    parent[1] = 1
    stack = [1]

    while stack:
        u = stack.pop()
        pu = parent[u]
        du = depth[u] + 1

        for v in graph[u]:
            if v == pu:
                continue
            parent[v] = u
            depth[v] = du
            stack.append(v)

    # Binary lifting table.
    log = n.bit_length()
    up = [parent]

    for _ in range(1, log):
        prev = up[-1]
        cur = array('i', (prev[prev[v]] for v in range(n + 1)))
        up.append(cur)

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        bit = 0

        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for k in range(log - 1, -1, -1):
            ua = up[k][a]
            ub = up[k][b]
            if ua != ub:
                a = ua
                b = ub

        return up[0][a]

    q = int(input())
    answers = []

    for _ in range(q):
        parts = list(map(int, input().split()))
        r, b = parts[0], parts[1]

        red = parts[2:2 + r]
        blue = parts[2 + r:2 + r + b]

        red_lca = red[0]
        for x in red[1:]:
            red_lca = lca(red_lca, x)

        blue_lca = blue[0]
        for x in blue[1:]:
            blue_lca = lca(blue_lca, x)

        common = lca(red_lca, blue_lca)

        if red_lca != common and blue_lca != common:
            answers.append("YES")
            continue

        if red_lca == common:
            possible = True

            for x in red:
                if lca(x, blue_lca) == blue_lca:
                    possible = False
                    break

            answers.append("YES" if possible else "NO")
        else:
            possible = True

            for x in blue:
                if lca(x, red_lca) == red_lca:
                    possible = False
                    break

            answers.append("YES" if possible else "NO")

    return "\n".join(answers)

if __name__ == "__main__":
    sys.stdout.write(solve())
```邻接表存储原始树。 DFS 是迭代的而不是递归的，因为树可以是长度为 (200000) 的链，这将超出 Python 的正常递归深度。 

这`parent`array 是一个紧凑的整数数组，而不是 Python 列表。 每个二进制提升级别都使用相同的表示形式。 这在 (256) MB 内存限制下很重要，因为 (200000) 整数的 Python 列表比压缩整数数组具有更多的开销。 蟒蛇的`array`type 紧凑地存储固定大小的数字元素。 

根将自身作为其父代。 因此，根部上方的重复跳跃保留在顶点（1）处，这使得 LCA 实现简单并避免了对零祖先的特殊处理。 

LCA 函数首先使用深度差异的二进制表示来均衡深度。 之后，它考虑从二的最大幂向下跳跃。 如果两个对应的祖先不同，则两个顶点都可以安全地向上跳跃，因为它们的 LCA 严格位于这些祖先之上。 当不可能进行更大的跳跃时，它们的直接父级是 LCA。 

对于每个查询，红色和蓝色列表直接从输入行中切片。 这些约束保证完整的查询适合一个输入行。 保留列表是因为，在祖先的情况下，我们必须检查相反颜色的每个终端。 

Python 中不存在整数溢出问题。 用作顶点标识符、深度和表条目的最大值最多为 (200000)。 

使用`array('i')`还保持 (O(n\log n)) 二进制升降台紧凑。 该表大约有 (200000\cdot18) 个整数条目，并且每个压缩整数在通常的实现中占用四个字节，因此表本身只有大约 15 MB，而不是数百兆字节的 Python 整数对象。

 该语句要求预测中的所有城市标识符都是不同的，因此所有输入城市值都相等的字面测试是无效的。 全彩色星星是相关的边界情况：每个城市都属于两个颜色类别之一，没有留下可以吸收交叉点的中性城市。 

## 边缘情况

 对于单个红色城市和单个蓝色城市，每个所需的子树仅由其彩色顶点组成。 由于两个城市标识符不同，因此两个子树不能相交。 算法得到`red_lca = red`,`blue_lca = blue`，而他们的LCA就是其中之一，因此到达了祖先案例。 遏制检查失败，因为相反颜色的城市不能位于其自己的不同顶点的子树内。 答案是`YES`。 

对于中性顶点处的交点，考虑```
5
1 2
1 3
2 4
3 5
1
2 2 4 5 3
```红色 LCA 是 (2)，因为红色城市是 (2,4)。 蓝色 LCA 是 (3)，因为蓝色城市是 (5,3)。 他们共同的LCA是（1），两者都不同。 乍一看，这看起来像是分离的情况，但红色所需的子树是 (2-4)，而蓝色所需的子树只是 (3-5)。 它们实际上并不相交，所以正确答案是`YES`对于这个特定的输入。 

要行使真正的中立交叉点，请使用```
5
1 2
1 3
2 4
3 5
1
2 2 5 4 3
```红色城市为 (5,4)，因此它们的 LCA 为 (1)。 蓝色城市 (3,4) 会违反不同的颜色，因此干净的示例是具有红色 (4,6) 和蓝色 (5,7) 的示例结构：```
7
1 2
1 3
2 4
2 5
3 6
3 7
1
2 2 4 6 5 7
```红色LCA为(1)，蓝色LCA为(1)，算法立即进入祖先案例。 检查红色城市 (4) 与蓝色 LCA (1) 得出`LCA(4,1)=1`，因此检测到交集，输出为`NO`。 

对于仍然可分离的祖先关系，请考虑```
5
1 2
2 3
3 4
4 5
1
2 1 1 3 5
```红色LCA为(1)，蓝色LCA为(5)，普通LCA为(1)。 该算法检查任一红色城市是否位于 (5) 的子树中。 也没有，所以它返回`YES`。 前沿（4-5）将蓝色城市分开，同时将红色城市连接起来。 

对于相反的情况，```
5
1 2
2 3
3 4
4 5
1
2 1 1 5 3
```红色LCA为(1)，蓝色LCA为(3)，普通LCA为(1)。 红色城市 (5) 位于以 (3) 为根的子树中，通过以下方式检测到`LCA(5,3) == 3`。 红色连接必须经过蓝色城市 (3)，因此算法返回`NO`。 

最后，最大尺寸的星星```
200000
1 2
1 3
...
1 200000
1
199999 1 2 3 ... 200000 1
```每片叶子都是红色的，中心是蓝色的。 所有红色城市的LCA都是(1)，这也是蓝色的LCA。 第一片红叶已经满足`LCA(2,1) == 1`，因此查询终止于`NO`。 这表明该算法一旦发现强制交集就可以立即拒绝大型查询，同时仍然在预期的渐近边界内处理完整的 (200000) 顶点输入。
