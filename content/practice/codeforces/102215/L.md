 ## 解决方案
 ## 问题理解

 我们有两个圆盘，每个圆盘都由一个中心和一个正半径来描述。 它们的圆周正好在两点相交，因此两个圆盘都不包含另一个圆盘，并且它们的交点是一个非简并透镜形状的区域。 

我们需要找到完全适合这个镜头的最大可能的圆。 输出是该圆的中心及其半径，具有足够的精度以满足 (10^{-9}) 的绝对或相对误差。 

坐标和半径的大小最多为 (1000)，因此所有相关距离都在普通浮点范围内。 也没有很大的输入大小：问题仅包含两个圆圈。 因此，2 秒限制对于 (O(1)) 几何解来说不是问题。 即使具有数百次迭代的迭代数值方法也足够快，但几何结构使我们可以完全避免迭代。 

第一个微妙的情况是圆的半径相等。 例如，```
0 0 5
6 0 5
```答案是```
3 0 2
```粗心的实现可能会假设最佳中心是原始中心之一，但正确的中心位于它们之间的中间。 更一般地说，对称性将答案放在连接两个圆心的线上，而不一定是在其中点。 

另一种情况是半径不同时：```
0 0 5
7 0 3
```这里圆相交，因为 (2 < 7 < 8)。 最佳中心位于远处

 [
 \frac{7+5-3}{2}=4.5
 ]

 从第一个中心开始，得到的半径是

 [
 \frac{5+3-7}{2}=0.5。 
]

 一个常见的错误是无论半径如何，都使用中心的中点。 这会给出错误的答案，因为较大的圆可以容纳距离较小的圆更远的最佳中心。 

最后的边缘情况涉及边界相交非常接近相切的圆。 例如，```
0 0 1
1.999999 0 1
```答案的半径非常小，大约为 (5\times10^{-7})。 使用整数算术、精度不足或涉及几乎相等数量减法的公式的实现可能会失去准确性。 使用中心距的直接公式通过 Python 的双精度对于所需的误差保持足够稳定。 

## 方法

 简单的几何方法可以在精细网格上搜索可能的中心位置。 对于每个候选点，我们将计算可以放置在那里的半径有多大，即其到两个圆边界的距离中较小的一个。 为了在大约 (2000) 的坐标范围内达到 (10^{-9}) 位置精度，统一网格需要的量级为

 [
 2000^2 / 10^{-18} = 4\cdot10^{24}
 ]

 候选点。 即使每个点进行一次常数时间计算也是没有希望的。 

更合理的数值方法是将搜索减少到一维并使用三元搜索。 镜片的对称性意味着最佳中心位于两个原始中心的连线上。 我们可以参数化该线并以数值方式最大化可行半径。 几百次迭代就已经足够了，因此这种方法实际上足够快，但它是不必要的，并且引入了精确几何避免的收敛和精度细节。 

关键的观察结果是，对于连接中心的线段上的点，到第一个中心的距离恰好随着到第二个中心的距离的减小而增加。 假设中心为 (C_1,C_2)，它们的距离为 (d)，候选中心 (P) 与 (C_1) 的距离为 (t)。 那么就是(C_2)的(d-t)。 

以 (P) 为中心的圆适合第一个半径最大的圆盘

 [
 r_1-t，
 ]

 它适合最大半径的第二个圆盘

 [
 r_2-(d-t)。 
]

 因此 (P) 处的最大可行半径为

 [
 f(t)=\min(r_1-t,\r_2-d+t)。 
]

 第一个表达式随 (t) 减小，而第二个表达式随 (t) 增大。 它们的最小值的最大值正好出现在它们相等的地方。 解决

 [
 r_1-t=r_2-d+t
 ]

 给出

 [
 t=\frac{d+r_1-r_2}{2}。 
]

 替换这个值给出

 [
 r=\frac{r_1+r_2-d}{2}。 
]

 该问题保证圆周恰好有两个公共点

 [
 |r_1-r_2|<d<r_1+r_2。 
]

 因此，计算出的 (t) 严格位于 (0) 和 (d) 之间，并且计算出的半径严格为正。 然后我们可以将答案放在两个中心之间的线上的相应点上。 

蛮力搜索之所以有效，是因为它直接评估候选中心的可行半径，但它几乎浪费了所有探索二维连续区域的工作。 最佳中心必须位于中心到中心轴上的观察结果将问题简化为一维，而两个极限半径是线性函数这一事实将一维优化简化为求解一个方程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(1/\varepsilon^2)) 网格样本 | (O(1)) | (O(1)) | 太慢了 |
 | 数值三元搜索| (O(I)) | (O(1)) | (O(1)) | 已接受但没有必要 |
 | 几何公式| (O(1)) | (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取圆心 (C_1=(x_1,y_1))、(C_2=(x_2,y_2)) 和半径 (r_1,r_2)。 我们最初需要的唯一几何量是两个中心之间的距离。 
2. 计算

 [
 d=\sqrt{(x_2-x_1)^2+(y_2-y_1)^2}。 
]

 由于圆相交于两点 (d>0)，因此从 (C_1) 到 (C_2) 的方向是明确定义的。 

1. 确定所需中心距离 (C_1) 有多远：

 [
 t=\frac{d+r_1-r_2}{2}。 
]

 这是通过平衡两个可用边界距离来实现的。 如果答案更接近 (C_1)，第一个圆将允许更大的半径，而第二个圆将是限制圆。 如果进一步接近(C_2)，情况就会逆转。 最大值恰好位于平衡点处。 

1. 将距离（t）转换为坐标。 从 (C_1) 到 (C_2) 的单位向量为

[
 \left(\frac{x_2-x_1}{d},\frac{y_2-y_1}{d}\right)。 
]

 因此答案中心是

 [
 x=x_1+\frac{x_2-x_1}{d}t,
 \qquad
 y=y_1+\frac{y_2-y_1}{d}t。 
]

 1. 使用任一限制圆计算半径：

 [
 r=r_1-t。 
]

 将(t)的值代入后，也可写为

 [
 r=\frac{r_1+r_2-d}{2}。 
]

 1. 打印圆心和半径，小数点后多位数字。 蟒蛇的`float`是 64 位 IEEE-754 双精度数，它提供的精度远高于所需的 (10^{-9}) 误差。 

### 为什么它有效

 对于以透镜内的点 (P) 为中心的任何圆，其半径不能超过 (P) 到任一原始圆周的距离。 可以在连接原始中心的线上选择最佳中心，因为通过该线反射任何可行的圆可以保留两个原始圆盘，并且透镜关于该线对称。 在此轴上，两个可用半径为 (r_1-t) 和 (r_2-d+t)。 一个随着中心向(C_2)移动而减少，而另一个则增加。 它们的最小值正好在它们的交点处最大化。 该算法计算交点并将中心放置在那里，因此没有其他点可以容纳更大的圆。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    d = math.hypot(dx, dy)

    t = (d + r1 - r2) / 2.0

    x = x1 + dx * t / d
    y = y1 + dy * t / d

    r = (r1 + r2 - d) / 2.0

    print(f"{x:.15f} {y:.15f} {r:.15f}")

if __name__ == "__main__":
    solve()
```第一部分读取两个圆并计算`dx`和`dy`，从第一个中心到第二个中心的位移。`math.hypot(dx, dy)`计算中心距离而不需要我们显式地写出平方根。 

变量`t`是从第一个中心到最优中心的距离。 关于两个交点的保证意味着`t`严格为正且严格小于`d`，所以除以`d`是安全的。 

坐标是通过从第一个中心向第二个中心的方向精确移动得到的`t`。 将计算写为`dx * t / d`和`dy * t / d`避免单独构造单位向量元组。 

半径使用对称公式`(r1 + r2 - d) / 2`。 直接计算比计算简单`r1 - t`，并且避免了不必要的额外减法。 

Python 中不存在整数溢出问题，因为整数具有任意精度。 唯一的浮点运算涉及的值最多为几千，因此双精度可以轻松处理它们。 

在小数点后打印十五位数字比所需的精度要高得多。 法官比较的是数值，而不是格式。 

## 工作示例

 ### 示例 1

 输入是```
0 0 5
6 0 5
```主要变量演变如下。 

| 变量| 价值|
 | ---| ---|
 | (dx) | (6) |
 | (dy)| (0) |
 | (d) | (6) |
 | (t=(d+r_1-r_2)/2) | (3) |
 | (x= x_1+dx\cdot t/d) | (3) |
 | (y= y_1+dy\cdot t/d) | (0) |
 | (r=(r_1+r_2-d)/2) | (2) |

 两个原始圆的可用半径在中点处相等，均为(5-3=2)。 移动任一方向都会使其中一个变小，因此中点是最佳的。 

### 示例 2

 输入是```
-12 34 56
78 -90 123
```位移和导出值大约为

 | 变量| 价值|
 | ---| ---|
 | (dx) | (90) |
 | (dy)| (-124) | (-124)
 | (d) | (153.2239) |

 这里的半径有很大不同，因此最佳中心不在原始中心的中间。 它更靠近小圆的中心，正如平衡方程所预测的那样。

## 测试用例

 对于浮点输出，比较完整的输出字符串是不合适的，因为许多不同的十进制表示可以描述相同的答案。 下面的测试助手解析这三个数字并以严格的绝对和相对容差检查它们。```python
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    d = math.hypot(dx, dy)

    t = (d + r1 - r2) / 2.0

    x = x1 + dx * t / d
    y = y1 + dy * t / d

    r = (r1 + r2 - d) / 2.0

    print(f"{x:.15f} {y:.15f} {r:.15f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def assert_answer(inp: str, expected, message: str):
    out = run(inp).split()
    got = list(map(float, out))

    assert len(got) == 3, message

    for a, b in zip(got, expected):
        assert math.isclose(a, b, rel_tol=1e-9, abs_tol=1e-9), (
            f"{message}: got {got}, expected {expected}"
        )

# Provided sample 1
assert_answer(
    "0 0 5\n6 0 5\n",
    (3.0, 0.0, 2.0),
    "sample 1"
)

# Provided sample 2
assert_answer(
    "-12 34 56\n78 -90 123\n",
    (13.322257821855908, -0.888444110112585, 12.890601098820779),
    "sample 2"
)

# Minimum radii, equal circles, center distance 1
assert_answer(
    "0 0 1\n1 0 1\n",
    (0.5, 0.0, 0.5),
    "minimum-size circles"
)

# Equal values and diagonal center displacement
# d = sqrt(2), so t = sqrt(2)/2 and the answer is (0.5, 0.5).
assert_answer(
    "0 0 1\n1 1 1\n",
    (0.5, 0.5, (2.0 - math.sqrt(2.0)) / 2.0),
    "equal circles on a diagonal"
)

# Very close to external tangency
assert_answer(
    "0 0 1\n1.999999 0 1\n",
    (0.9999995, 0.0, 0.0000005),
    "near-tangent circles"
)

# Unequal radii, catches midpoint assumptions
assert_answer(
    "0 0 5\n7 0 3\n",
    (4.5, 0.0, 0.5),
    "unequal radii"
)
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`0 0 1`和`1 0 1`|`(0.5, 0, 0.5)`| 最小半径和对称情况 |
 |`0 0 1`和`1 1 1`|`(0.5, 0.5, (2-sqrt(2))/2)`| 对角线方向和距离归一化 |
 |`0 0 1`和`1.999999 0 1`|`(0.9999995, 0, 0.0000005)`| 近切线精度 |
 |`0 0 5`和`7 0 3`|`(4.5, 0, 0.5)`| 不等半径和非中点最优 |

 ## 边缘情况

 等半径情况```
0 0 1
1 0 1
```有 (d=1)，所以

 [
 t=\frac{1+1-1}{2}=0.5
 ]

 和

 [
 r=\frac{1+1-1}{2}=0.5。 
]

 中心是`(0.5, 0)`。 基于中点的实现恰好在这里起作用，但该公式解释了它起作用的原因，并且还推广到不等半径。 

对角线情况```
0 0 1
1 1 1
```有(d=\sqrt2)。 公式给出

 [
 t=\frac{\sqrt2}{2}。 
]

 从第一个中心到第二个中心的单位方向是

 [
 \left(\frac1{\sqrt2},\frac1{\sqrt2}\right),
 ]

 所以乘以 (t) 得出`(0.5, 0.5)`。 这会捕获意外使用的实现`dx`和`dy`就好像中心距离始终是水平的一样。 

近切线情况```
0 0 1
1.999999 0 1
```有

 [
 d=1.999999
 ]

 因此

 [
 r=\frac{2-1.999999}{2}=0.0000005。 
]

 最优中心是`(0.9999995, 0)`。 半径为正但非常小，这测试了实现是否保留了足够的浮点精度。 

最后，不等半径情况```
0 0 5
7 0 3
```给出

 [
 t=\frac{7+5-3}{2}=4.5
 ]

 和

 [
 r=\frac{5+3-7}{2}=0.5。 
]

 中心是`(4.5, 0)`， 不是`(3.5, 0)`。 这是针对常见但不正确的假设（即对称性总是将答案放在两个原始中心的中点）的最有用的测试。
