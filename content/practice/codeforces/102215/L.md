 ## 解决方案
 ## 问题理解

 我们有两个圆，每个圆都由圆心和半径来描述。 它们的圆周正好在两点相交，因此两个圆都不包含另一个圆，并且两个圆盘在适当的透镜形状区域中重叠。 我们需要完全适合重叠部分的最大圆，并且必须打印它的中心和半径。 输入范围和所需精度是原始问题陈述中给出的。 

设中心为 (O_1=(x_1,y_1)) 和 (O_2=(x_2,y_2))，半径为 (r_1) 和 (r_2)。 让

 [
 d=|O_1O_2|
 ]

 是中心之间的距离。 恰好有两个交点给出了严格的不等式

 [
 |r_1-r_2|<d<r_1+r_2。 
]

 上限保证正重叠，而下限则防止一个圆盘完全位于另一个圆盘内部。 这些严格的不等式特别有用，因为它们保证最终半径为正并且两个中心不同。 

坐标范围仅为([-1000,1000])，因此这里没有组合输入大小。 挑战在于几何精度，而不是运行时间。 执行恒定数量的浮点运算的解决方案很容易在 2 秒和 256 MB 的限制内，而无需进行数值搜索或密集枚举。 

当圆的半径相等但中心不在水平线上时，粗心的实现可能会失败。 例如，```
0 0 5
3 4 5
```有 (d=5)，所以答案是以 ((1.5,2)) 为圆心、半径为 (2.5) 的圆。 仅更改 (x) 坐标或假设中心始终位于 (x) 轴上的解决方案会产生错误的中心。 

不等的半径是另一个常见的错误来源。 考虑```
0 0 5
6 0 9
```这里 (d=6)，答案以 ((1,0)) 为中心，半径为 (4)。 该中心不是两个原始中心的中点。 盲目使用中点会给出半径 (3)，即使较小的圆一侧仍有未使用的空间。 

几乎相切的情况在数值上也很重要。 例如，```
-1000 0 1000
999 0 1000
```有 (d=1999)，因此答案的半径为 (0.5)，中心为 ((-0.5,0))。 尽管输入值很大，但所需的半径很小，因此应以浮点形式进行计算并打印足够的位数。 

## 方法

 字面上的蛮力方法会尝试中心的可能位置，并保留两个磁盘内剩余的最大圆。 对于候选中心（P），第一个圆允许的最大半径为（r_1-|PO_1|），第二个圆允许的最大半径为（r_2-|PO_2|）。 因此候选半径是它们的最小值。 

问题是中心是连续的点，所以暴力需要离散化。 如果我们尝试在可能的坐标范围 ([-2000,2000]) 上检查间距 (10^{-9}) 的网格上的每个坐标，则沿每个轴将有 (4\cdot10^{12}) 个位置，或者

 [
 (4\cdot10^{12})^2=1.6\cdot10^{25}
 ]

 候选人中心。 这不仅太慢了 2 秒，而且对于保证所要求的精度来说也是一种尴尬的方式。 

更复杂的数值搜索可以大大减少工作量，但几何形状为我们提供了精确的恒定时间解。 暴力法之所以有效，是因为可以直接检查候选中心的有效性。 关键的观察是最佳中心根本不需要二维搜索。 

取镜头内的任意候选中心 (P)。 将 (P) 投影到直线 (O_1O_2) 上，得到 (Q)。 投影无法增加到 (O_1) 或 (O_2) 的距离。 因此，

 [
 r_1-|QO_1|\ge r_1-|PO_1|
 ]

 和

 [
 r_2-|QO_2|\ge r_2-|PO_2|。 
]

 因此，将中心移动到连接两个原始中心的线上永远不会使可能的内切半径变小。 我们可以将整个优化限制在一维。 

现在将候选中心 (P) 放置在 (O_1) 和 (O_2) 之间。 如果(t=|O_1P|)，则(|PO_2|=d-t)。 两个圆允许半径

 [
 r_1-t
 ]

 和

 [
 r_2-(d-t)。 
]

 当这两个量相等时，它们的最小值恰好出现。 否则，如果一个较小，我们可以将（P）稍微移向相应的圆并增加较小的数量。 

解决

 [
 r_1-t=r_2-d+t
 ]

 给出

 [
 t=\frac{d+r_1-r_2}{2}。 
]

 将其代入任一半径表达式给出

 [
 R=\frac{r_1+r_2-d}{2}。 
]

 一旦 (t) 已知，中心就是在 (O_2) 方向上距 (O_1) 距离 (t) 的点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(G^2)) 对于 (G\times G) 坐标网格 | (O(1)) | (O(1)) | 太慢，自然无法保证(10^{-9})精度 |
 | 最佳 | (O(1)) | (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取两个圆心及其半径。 计算

 [
 dx=x_2-x_1,\qquad dy=y_2-y_1
 ]

 和

 [
 d=\sqrt{dx^2+dy^2}。 
]

 保证两个交点意味着(d>0)，因此除以(d)是安全的。 
2. 计算最大圆的半径为

 [
 R=\frac{r_1+r_2-d}{2}。 
]

 这是因为使新中心到两个原始圆周的距离等于相同的半径。 
3. 计算 (O_1) 到新中心的距离：

 [
 t=\frac{d+r_1-r_2}{2}。 
]

 这是线段 (O_1O_2) 上的唯一点，两个原始圆都精确地留下 (R) 单位的径向间隙。 
4. 将该距离转换为坐标位移。 从 (O_1) 到 (O_2) 的单位向量为

 [
 \left(\frac{dx}{d},\frac{dy}{d}\right)。 
]

 因此，新中心是

 [
 x=x_1+\frac{dx}{d}t,
 \qquad
 y=y_1+\frac{dy}{d}t。 
]
 5. 打印（x）、（y）和（R）多位数字。 小数点后 15 位的精度远高于所需的精度 (10^{-9})。

关键的不变量是所选中心位于 (O_1O_2) 上，并且距两个圆边界的间隙完全相同。 任何以别处为中心的有效圆都可以投影到这条线上，而不会减小其可能的半径。 沿着这条线，第一个圆的可用半径随着中心远离 (O_1) 而减小，而第二个圆的可用半径则增大。 它们的最小值恰好在交叉点处最大化。 因此计算出的圆既可行又最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    d = (dx * dx + dy * dy) ** 0.5

    radius = (r1 + r2 - d) / 2.0
    dist_from_first = (d + r1 - r2) / 2.0

    x = x1 + dx * dist_from_first / d
    y = y1 + dy * dist_from_first / d

    print(f"{x:.15f} {y:.15f} {radius:.15f}")

if __name__ == "__main__":
    solve()
```前两行`solve`完全按照给定的方式读取两个圆圈。 所有输入值都是整数，所以`dx * dx + dy * dy`也在取平方根之前精确计算。 

价值`d`是原始中心之间的距离。 因为圆周恰好有两个公共点，所以圆心不能重合，所以`d`是严格正数。 不需要人工 epsilon 检查或重合中心的特殊情况。 

表达式`(r1 + r2 - d) / 2`是最终的半径。 严格的交集条件保证其分子为正。 

变量`dist_from_first`是从第一个中心到答案中心的距离。 乘以归一化向量`(dx / d, dy / d)`通过这个距离将答案放置在沿着原始中心之间的线的正确位置。 

Python 中不可能出现整数溢出，即使在固定宽度语言中，与 64 位整数限制相比，此处的平方坐标差异也很小。 最终计算使用浮点，因为答案可能是无理数。

## 测试用例

 下面的断言将浮点值与容差进行比较，而不是比较格式化字符串。 这反映了实际的判断条件，其中许多不同的十进制表示形式都可以是正确的。```python
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1
    d = (dx * dx + dy * dy) ** 0.5

    radius = (r1 + r2 - d) / 2.0
    t = (d + r1 - r2) / 2.0

    x = x1 + dx * t / d
    y = y1 + dy * t / d

    print(f"{x:.15f} {y:.15f} {radius:.15f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def check(inp: str, expected):
    out = run(inp).split()
    got = list(map(float, out))

    assert len(got) == 3
    for a, b in zip(got, expected):
        assert math.isclose(a, b, rel_tol=1e-12, abs_tol=1e-12), (
            f"got {got}, expected {expected}"
        )

# Provided samples
check(
    """0 0 5
6 0 5
""",
    (3.0, 0.0, 2.0),
)

check(
    """-12 34 56
78 -90 123
""",
    (13.322257821855908, -0.888444110112585, 12.890601098820779),
)

# Minimum radii, equal circles, simple horizontal placement
check(
    """0 0 1
1 0 1
""",
    (0.5, 0.0, 0.5),
)

# Equal circles with a non-horizontal center line
check(
    """0 0 5
3 4 5
""",
    (1.5, 2.0, 2.5),
)

# Unequal radii, catches the incorrect-midpoint solution
check(
    """0 0 5
6 0 9
""",

)

# Maximum coordinate values while still having two intersections
check(

999 0 1000
""",

)

 ## 边缘情况

 对于最小尺寸的情况```
0 0 1
1 0 1
```我们得到(d=1)。 半径为

 [
 R=\frac{1+1-1}{2}=0.5,
 ]

 到第一个中心的距离也是(0.5)。 方向是((1,0))，所以答案正是((0.5,0,0.5))。 该算法永远不需要半径 (1) 的特殊分支。 

对于非水平情况```
0 0 5
3 4 5
```中心距为(5)。 半径相等给出

 [
 R=\frac{5+5-5}{2}=2.5
 ]

 和

 [
 t=\frac{5+5-5}{2}=2.5。 
]

 从第一个中心到第二个中心的单位方向是((3/5,4/5))，所以答案中心是

 [
 (0,0)+2.5\left(\frac35,\frac45\right)=(1.5,2)。 
]

 这捕获了错误地将几何图形视为沿 (x) 轴的一维的实现。 

对于不等半径，```
0 0 5
6 0 9
```我们有（d=6）。 半径为

 [
 R=\frac{5+9-6}{2}=4,
 ]

 同时

 [
 t=\frac{6+5-9}{2}=1。 
]

 因此中心是((1,0))。 两个间隙均为 (4)：

 [
 5-1=4
 ]

 和

 [
 9-(6-1)=4。 
]

 这两个量的相等正是最优性条件。 

对于近切线边界情况，```
-1000 0 1000
999 0 1000
```中心相距 (1999) 个单位。 最终半径为

 [
 R=\frac{1000+1000-1999}{2}=0.5。 
]

 答案中心位于两个原始中心的中间，即

 [
 \frac{-1000+999}{2}=-0.5。 
]

 所以输出是```
-0.500000000000000 0.000000000000000 0.500000000000000
```直至允许的误差。 此案例说明了为什么实现不能假设答案半径可以轻松地从零分离。 输入保证给出正半径，但它相对于坐标和半径大小可以任意小。
