 ## 解决方案
 ## 问题理解

 地牢是一连串的房间。 通道`i`连接房间`i-1`到房间`i`，因此向出口移动始终意味着从左到右处理数组。 

每个数组值都描述通道的颜色和通道的行为。 正值`c`表示通道检查是否通过`c`仍然有效。 负值`-c`意思是通道总是可以穿越的，但是穿越之后，就通过了`c`变得无效。 

对于起始房间`s`，所有通行证最初都是有效的。 我们需要在无法移动之前成功穿越的通道数量。 等价地，如果第一个被阻塞的通道是`j`，答案是`j - s - 1`。 如果没有通道阻挡我们，答案是`n - s`。 

关键的相互作用是一种颜色的负面出现和随后相同颜色的正面出现之间的相互作用。 一旦我们穿越`-c`，每隔一段时间`+c`成为阻塞通道。 消极的通道本身永远不会阻碍运动。 

和`n`最多`500000`，独立模拟从每个起始房间开始的旅程的算法太昂贵了。 简单的模拟检查最多`n-s`开始的段落`s`, 给予

 [
 n+(n-1)+\cdots+1=\frac{n(n+1)}2
 ]

 通行检查。 最大时`n`，这是关于`1.25 \cdot 10^{11}`操作，不能满足 2 秒的限制。 我们需要一个线性或近线性的解决方案。 

有几种边界情况很容易导致差一错误。 以一篇文章为例，```
1
-1
```答案是`1`，因为消极的段落永远不会阻碍人。 将失效视为立即停止的解决方案将错误地输出`0`。 

第二个重要的情况是负数段落后跟相同颜色的正数段落：```
2
-1 1
```从房间开始`0`，我们穿过第一条通道，然后被第二条通道拦住，所以输出是`1 1`。 正面通过本身并不算成功穿越。 

出发房间之前发生的负面事件不得影响旅程。 例如，```
3
-1 1 1
```有输出`1 2 1`。 从房间开始`1`，较早的`-1`无关紧要，因为通行证在旅程开始时最初有效。 记住全局所有负面事件而不是仅记住起始房间右侧的负面事件的解决方案会出错。 

最后，多种颜色可以创建多个可能的停止位置。 例如，```
5
1 -1 2 -2 2
```产生`3 3 2 1 1`。 从房间开始`0`， 颜色`1`不会造成未来的问题，但颜色`2`通过时无效`4`，所以通过`5`成为第一阻挡者。 

## 方法

 暴力方法完全遵循该声明所描述的内容。 对于每个起始房间`s`，创建一个新的状态，其中每个通道都有效，扫描通道`s+1, s+2, ...`，并维护哪些颜色已失效。 负值使其颜色无效，而正值如果其颜色已无效则停止模拟。 这是直接正确的，因为它模拟了实际的旅程，没有做任何假设。 

问题是相邻的起始房间重复几乎所有相同的工作。 从房间开始`s`从房间开始`s+1`两者都检查几乎整个数组的后缀。 在最坏的情况下，暴力破解会执行`n(n+1)/2`通行检查，关于`1.25 * 10^11`什么时候`n=500000`。 

有用的观察是，旅程可以向后分析。 假设我们正在处理段落`i`从右到左。 对于每种颜色，我们都可以记住该颜色右侧最近的正通道。 如果`a[i]`为正，通过`i`当它是旅程的第一条通道时，它总是可以穿越的，所以它的起始房间的答案只是比穿越它后的答案多一个。 

如果`a[i]`颜色为负`c`，该段落本身是可交叉的，但它无效`c`。 如果没有积极的`c`在它的右边，无效永远不会重要，所以我们可以再次穿过通道并继承下一个房间的答案。 

有趣的情况是当最接近的正值`c`右边是通道`p`。 然后是在通过时或之前开始的旅程`i`和十字架`-c`无法通过通道`p`。 只能到达房间`p-1`。 可能已经有一个更早的停止位置，这是由另一次向右更远的负通道引起的，因此我们维持一个全局最右边可到达的房间，并采取所有此类限制中的最小值。 

这就是反向扫描如此有效的原因。 每个正通道都将其位置贡献给每种颜色的查找，每个负通道都可能收紧一个全局边界，并且每个数组位置仅处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳反向扫描 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 使用基于 1 的段落索引读取数组。 让`ans[i]`表示从房间出发时成功通过的次数`i-1`。 我们还定义`ans[n+1] = 0`，代表最后一段之后的空后缀。 
2. 扫描段落`n`下降到`1`。 至此，右边的每一个通道都已经被分析过了，对于每一种颜色，我们都可以知道该颜色右边最接近的正通道。 
3. 维护`pos[c]`，最接近的带颜色的正通道`c`迄今为止在反向扫描中遇到的情况。 最初每种颜色都没有这样的通道。 
4. 如果`a[i]`是积极的，旅程从房间开始`i-1`总能穿越通道`i`，因为所有通行证最初都是有效的。 穿越之后的情况正是下图所代表的情况`ans[i+1]`。 因此我们设置`ans[i] = ans[i+1] + 1`。 只有在计算出这个答案之后我们才会存储`pos[a[i]] = i`，因为该正通道可以影响位于其左侧的负通道。 
5.如果`a[i]`颜色为负`c`和`pos[c]`不存在，穿越通道`i`使无效`c`，但未来的通道不会检查颜色`c`。 失效永久无关，因此旅程的其余部分就像从房间开始的旅程一样`i`。 我们设定`ans[i] = ans[i+1] + 1`。 
6. 如果`a[i]`颜色为负`c`和最接近的正数`c`正在通过`p`，然后穿越通道`i`使通过`p`不可能跨越。 由于此特定失效而最后可到达的房间是`p-1`。 我们维持`limit`，已处理的所有负面通道中最小的可到达房间，并更新`limit = min(limit, p-1)`。 
7.更新后`limit`，从房间开始的旅程`i-1`最多可以到达房间`limit`。 因为它从房间开始`i-1`，成功通过的次数为`limit - (i-1)`，即`limit - i + 1`。 我们将该值存储在`ans[i]`。 
8. 反向扫描后，`ans[1], ans[2], ..., ans[n]`与起始房间完全对应`0, 1, ..., n-1`，所以按顺序打印它们。 

### 为什么它有效

 不变的是处理后的位置`i`,`limit`是已处理后缀中每个否定段落所施加的最早可到达的房间。 消极的段落`-c`只能通过第一个正数来创建限制`+c`在其右侧，因为这是实际检查无效通行证的第一个地方。 超越这些限制的最小值给出了可以停止旅程的第一个通道。 积极的通道本身永远不会产生限制，而右侧没有积极发生的消极通道永远不会影响未来的运动。 这样，反向扫描计算出的每个答案正是相应起始位置能够成功穿越的通道数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # pos[c] = nearest positive passage of color c to the right.
    pos = [0] * (n + 1)

    # limit is the smallest room index that can be reached because
    # of a restriction created by a negative passage in the suffix.
    # Initially there is no restriction, so room n is reachable.
    limit = n

    ans = [0] * (n + 2)

    for i in range(n, 0, -1):
        x = a[i - 1]

        if x > 0:
            # Passage i is always crossable when it is the first
            # passage of the journey.
            ans[i] = ans[i + 1] + 1

            # This passage may block a negative occurrence of the
            # same color located to its left.
            pos[x] = i
        else:
            color = -x

            if pos[color] == 0:
                # The invalidated pass is never checked later.
                ans[i] = ans[i + 1] + 1
            else:
                # Passage pos[color] is the first positive check of
                # this color to the right, so we can reach only the
                # room immediately before it.
                limit = min(limit, pos[color] - 1)
                ans[i] = limit - i + 1

    print(*ans[1:n + 1])

if __name__ == "__main__":
    solve()
```数组`pos`直接按颜色索引，因为每种颜色都位于`1`和`n`。 零值意味着向后扫描时尚未遇到该颜色的正向通道。 

这`limit`变量存储为房间索引而不是通道索引。 如果阻塞正通道是`p`，该人可以进入房间`p-1`但无法进入房间`p`，所以对应的边界正好是`p-1`。 这使得答案公式`limit - i + 1`与事实相符`ans[i]`从房间开始`i-1`。 

更新内容`pos[x] = i`计算后发生`ans[i]`。 位置上的积极通道`i`必须对严格位于其左侧的负段落可见，但它不应该影响第一个段落是其本身的旅程的计算。 之后处理分配自然会给出正确的顺序。 

Python 中不可能出现整数溢出，事实上每个答案最多是`n`。 该实现还避免了递归，并且仅使用大小与`n`，这适用于`500000`元素限制。 

## 工作示例

 对于样品 1，```
6
1 -1 -1 1 -1 1
```反向扫描的行为如下。 

|`i`|`a[i]`|`pos[1]`步骤后|`limit`|`ans[i]`|
 | ---| ---| ---| ---| ---|
 | 6 |`1`| 6 | 6 | 1 |
 | 5 |`-1`| 6 | 5 | 1 |
 | 4 |`1`| 4 | 5 | 2 |
 | 3 |`-1`| 4 | 3 | 1 |
 | 2 |`-1`| 4 | 3 | 2 |
 | 1 |`1`| 1 | 3 | 3 |

 在通过时`5`，负数`-1`看到积极的一面`+1`在通过时`6`，因此它将可到达的房间限制为`5`。 通道`4`是另一个积极的方面`1`，其左侧的负面段落可以将其用作更早的阻止者。 在通过时`3`，这会创建更紧密的边界`3`，给出最终答案`3 2 1 2 1 1`。 

对于样品 2，```
7
2 -1 -2 -3 1 3 2
```反向扫描为：

 |`i`|`a[i]`| 相关的`pos`更新 |`limit`|`ans[i]`|
 | ---| ---| ---| ---| ---|
 | 7 |`2`|`pos[2] = 7`| 7 | 1 |
 | 6 |`3`|`pos[3] = 6`| 7 | 2 |
 | 5 |`1`|`pos[1] = 5`| 7 | 3 |
 | 4 |`-3`|`limit = min(7, 5)`| 5 | 2 |
 | 3 |`-2`|`limit = min(5, 6)`| 5 | 3 |
 | 2 |`-1`|`limit = min(5, 4)`| 4 | 3 |
 | 1 |`2`|`pos[2] = 1`| 4 | 4 |

 负面的`-3`在通过时`4`使颜色无效`3`，所以通过`6`无法跨越，将可到达的空间限制为`5`。 后来的`-2`不会收紧该边界，因为其相应的正值`2`是更右边的。 这`-1`在通过时`2`是否将其紧固到房间`4`，生产`4 3 3 2 3 2 1`。 

这些痕迹还表明了为什么限制是累积的。 消极的段落本身并不一定决定最终的停止点。 我们需要后缀中所有相关失效的最小可达空间。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个段落处理一次，每次查找和更新都是 O(1)。 |
 | 空间| O(n) | 输入、答案数组和每种颜色位置数组均使用 O(n) 内存。 |

 和`n <= 500000`，该算法在每个段落中仅执行恒定量的工作，因此大约涉及几百万个简单的 Python 操作。 内存使用量也是线性的，并且完全在这种方法的 256 MB 限制之内。

import io

def solution():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    limit = n
    ans = [0] * (n + 2)

    for i in range(n, 0, -1):
        x = a[i - 1]

        if x > 0:
            ans[i] = ans[i + 1] + 1
            pos[x] = i
        else:
            color = -x

            if pos[color] == 0:
                ans[i] = ans[i + 1] + 1
            else:
                limit = min(limit, pos[color] - 1)
                ans[i] = limit - i + 1

    print(*ans[1:n + 1])

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solution()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run(
    "6\n"
    "1 -1 -1 1 -1 1\n"
) == "3 2 1 2 1 1", "sample 1"

assert run(

 ## 边缘情况

 最小输入```
1
-1
```由负分支处理。 没有积极的`1`向右，所以`pos[1]`为零，算法使用`ans[2] + 1 = 1`。 该人越过唯一的通道，之后通行证就失效了。 输出正确`1`。 

为了```
2
-1 1
```反向扫描首先看到`+1`在通过时`2`, 存储`pos[1] = 2`。 当它达到`-1`在通过时`1`，它改变了`limit`到`1`，因为这个人可以到达房间`1`但无法穿越通道`2`。 答案是`1`，和通道`2`不计算在内，因为它是被阻塞的通道。 从房间开始`1`, 仅有通道`2`仍然存在并且它的通行证最初是有效的，所以第二个答案也是`1`。 

为了```
3
-1 1 1
```反向扫描存储段落中出现的阳性事件`3`进而`2`。 加工`-1`在通过时`1`找到最近的正值出现位置`2`， 所以`limit`变成`1`和`ans[1] = 1`。 从房间出发时`1`，然而，通过`1`根本不是旅程的一部分。 答案由以下计算得出`ans[2] = 2`, 给予`2`。 最终输出是`1 2 1`，确认起始位置之前出现的负数是无关的。 

对于多色情况```
5
1 -1 2 -2 2
```反向扫描首先发现`+2`在通过时`5`， 然后`-2`在通过时`4`，这将可到达的房间限制为`4`。 较早的`-1`在通过时`2`看到`+1`在通过时`1`除非该积极通道位于其右侧，但事实并非如此，因此它不会产生新的限制。 从房间开始`0`, 通道`4`使颜色无效`2`，和通道`5`被堵塞，因此三个通道被交叉。 输出是`3 3 2 1 1`。 

全部为正值的最大尺寸情况根本不会失效。 每个起始房间都可以遍历整个剩余的后缀，所以答案序列正好是`n, n-1, ..., 1`。 反向递归直接计算这一点，并且因为每个段落都被处理一次，所以该案例还证实了实现可以扩展到完整的约束。
