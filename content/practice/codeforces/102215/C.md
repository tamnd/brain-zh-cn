 ## 解决方案
 ## 问题理解

 芯片从点开始`0`在包含的圆上`p`点，编号`0`通过`p - 1`。 第一步，它前进`1`，第二个由`2`，第三次由`3`， 等等。 运动环绕圆周，因此每个位置都被视为模数`p`。 

后`k`移动，总移动距离为

 [
 1+2+\dots+k=\frac{k(k+1)}2.
 ]

 所以之后的位置`k`动作是

 [
 pos_k=\frac{k(k+1)}2\bmod p。 
]

 任务是计算有多少个不同的值出现在`pos_0, pos_1, ..., pos_n`。 初始位置`0`包括在内，所以即使当`n = 0`，答案是`1`。 

该圆最多可以包含`10^7`点，而移动次数可以大到`10^18`。 后一个界限立即排除了模拟每一个动作。 甚至`10^7`对于 2 秒的 Python 程序来说，迭代次数已经接近实际极限，因此我们需要证明只有运动序列的有界前缀才重要。 256 MB 的内存限制也使得 Python`set`包含数百万个整数没有吸引力，而紧凑`bytearray`可以仅使用每个点一个字节来表示每个点是否已被访问过。 

关键的周期性来自三角数公式。 对于每一个`k`,

 [
 pos_{k+2p}
 =\frac{(k+2p)(k+2p+1)}2
 \相当于\frac{k(k+1)}2
 \pmod p。 
]

 因此位置序列每次都会重复`2p`移动。 我们永远不需要模拟超过`2p`移动，无论是否`n`是`10^6`或者`10^18`。 

有几种边界情况，粗心的实现可能会处理不当。 为了`p = 1, n = 0`，正确的输入是`1 0`答案是`1`，因为起点已经是唯一点。 仅计算移动后的目的地的解决方案将错误地打印`0`。 

为了`p = 3, n = 10`，位置是`0, 1, 0, 0, 1, 0, ...`，所以答案是`2`。 假设一个解决方案的周期为`p`在没有证明的情况下移动仍然可以偶然得到一些案例，但实际周期是`2p`。 

为了`p = 4, n = 3`，访问过的位置是`0, 1, 3, 2`，所以已经达到了每个点，答案是`4`。 少于后停止`n`移动，或单独错误地处理起始位置，会导致相差一错误。 

## 方法

 直接解决方案完全遵循芯片。 保持当前位置，并且对于每一个动作`i`， 添加`i`模数`p`。 每当新的位置以前没有见过时，就增加答案。 由圆位置索引的布尔数组提供恒定时间的成员资格检查，因此这是正确的，因为它精确记录了芯片到达的位置集。 

问题是值`n`。 在最坏的情况下，`n = 10^18`，因此直接模拟最多需要`10^18`迭代，这是完全不可行的。 

解锁优化的观察结果是芯片在`k`移动是一个三角数模`p`。 自从

 [
 (k+2p)(k+2p+1)-k(k+1)
 =4pk+2p(2p+1),
 ]

 差值可除以`2p`，除以之后`2`，对应的位置相差数倍`p`。 因此`pos_{k+2p} = pos_k`。 

暴力方法之所以有效，是因为每次模拟的移动都会给出一个准确的位置，并且访问的数组会记录它。 当`n`是巨大的。 周期性观察将问题最多简化为`2p`移动。 自从`p <= 10^7`，这最多意味着`2 * 10^7`迭代，独立于潜在的天文价值`n`。 

我们还可以避免所有的第二次传递`p`当达到以前未见过的点时，立即增加答案来确定位置。 一个`bytearray`紧凑地存储访问过的标志。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(p) | 太慢的时候`n`很大 |
 | 最佳| O(min(n, 2p)) | O(p) | 已接受 |

 ## 算法演练

 1. 阅读`p`和`n`。 芯片已经访问过点`0`，因此用 point 初始化访问的结构`0`标记且答案等于`1`。 
2. 将移动次数替换为`min(n, 2p)`。 该序列每重复一次`2p`移动，因此在第一个完整周期之后模拟任何内容都无法添加新点。 
3. 保留`cur`当芯片的当前位置和过程从`1`通过减少移动次数。 对于搬家`i`， 进步`cur`经过`i`模数`p`。 
4. 如果之前未标记结果位置，请标记它并增加答案。 一个位置可能会被多次访问，但只有在第一次访问时才会对答案做出贡献。 
5. 打印标记位置的数量。 因为当遇到新位置时答案恰好增加，所以它已经等于不同访问点的数量。 

### 为什么它有效

 不变量是在处理完第一个之后`i`移动，`cur`正是移动后芯片的位置`i`，并且在这些移动期间访问的每个点都在访问数组中进行标记。 初始化建立了移动的不变量`0`，自点`0`是起始位置。 每次迭代精确地前进下一个跳跃长度并标记结果位置，从而保留不变量。 

唯一剩下的问题是是否停止`2p`移动可能会失分。 它不能，因为对于每一个`k`,

 [
 pos_{k+2p}=pos_k。 
]

 第一个之后到达的每个位置`2p`上一周期内已到达相应位置的移动次数。 因此第一个`min(n, 2p)`移动包含在请求的执行期间可以访问的每个不同点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    p, n = map(int, input().split())

    visited = bytearray(p)
    visited[0] = 1
    answer = 1

    moves = min(n, 2 * p)

    cur = 0
    step_mod = 1

    for _ in range(moves):
        cur += step_mod
        if cur >= p:
            cur -= p

        if not visited[cur]:
            visited[cur] = 1
            answer += 1

        step_mod += 1
        if step_mod == p:
            step_mod = 0

    print(answer)

if __name__ == "__main__":
    solve()
```这`visited`数组正好有`p`条目，每个点一个。 一个`bytearray`使用而不是 Python 列表或集合，因为它的元素仅占用一个字节，这在以下情况下很重要`p`与`10^7`。 

变量`moves`直接实现周期性参数。 如果`n < 2p`，每个请求的动作都会被模拟。 如果`n >= 2p`，只需要一个完整的周期。 

实施保持`step_mod`而不是存储完整的跳跃长度。 由于仅对跳跃长度取模`p`影响位置，这个是等价的。 每一个动作之后，`step_mod`模数递增`p`。 

更新内容```
cur += step_mod
if cur >= p:
    cur -= p
```相当于`cur = (cur + step_mod) % p`。 在每次迭代中`cur`和`step_mod`在`[0, p - 1]`，所以它们的总和小于`2p`，意味着一次减法就足够了。 避免`%`在主循环中使 Python 实现变得更加轻量。 

Python 中不存在整数溢出问题，因为整数具有任意精度。 在固定宽度语言中，原始值`n`需要足够宽的整数类型，但是应用后的循环计数器`min(n, 2p)`至多是`2 * 10^7`。 

循环运行的移动次数恰好是仍然可以引入新位置的移动次数。 初始点是单独计算的，所以循环故意处理移动`1`通过`moves`而不是不小心将起始位置视为一次移动。 

## 工作示例

 对于样品 1，`p = 3`和`n = 10`。 期间是`2p = 6`，因此只需要检查前六步。 

| 移动| 步进模数`p`| 职位| 新点？ | 回答 |
 | ---| ---| ---| ---| ---|
 | 0 | 0 | 0 | 初始点| 1 |
 | 1 | 1 | 1 | 是的 | 2 |
 | 2 | 2 | 0 | 没有 | 2 |
 | 3 | 0 | 0 | 没有 | 2 |
 | 4 | 1 | 1 | 没有 | 2 |
 | 5 | 2 | 0 | 没有 | 2 |
 | 6 | 0 | 0 | 没有 | 2 |

 跳跃长度为`1, 2, 3, 4, 5, 6`，但是取模`3`他们是`1, 2, 0, 1, 2, 0`。 仅积分`0`和`1`发生，所以答案是`2`。 其余四个请求的移动重复同一周期。 

对于样品 2，`p = 5`和`n = 3`。 自从`n < 2p`，所有三个动作都是模拟的。 

| 移动| 步进模数`p`| 职位| 新点？ | 回答 |
 | ---| ---| ---| ---| ---|
 | 0 | 0 | 0 | 初始点| 1 |
 | 1 | 1 | 1 | 是的 | 2 |
 | 2 | 2 | 3 | 是的 | 3 |
 | 3 | 3 | 1 | 没有 | 3 |

 访问过的点有`{0, 1, 3}`，给出所需的答案`3`。 该跟踪还说明了为什么计算移动和计算新访问的点是不同的操作。 第三步落在现有点上，因此不会增加答案。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(min(n, 2p)) | 最多`2p`模拟动作，每次动作持续做功 |
 | 空间| O(p) | 每个圆点存储一个字节 |

 自从`p <= 10^7`，算法最多执行`2 * 10^7`迭代，即使当`n = 10^18`。 这`bytearray`最大值时大约需要 10 MB`p`，明显低于 256 MB 内存限制。 解决方案基于相同的`O(p)`- 该时期使规模模拟成为可能`2p`，而不是试图处理潜在的巨大价值`n`。

 ## 边缘情况

 对于`p = 1, n = 0`，该算法创建一个单元素`bytearray`, 标记位置`0`，并设置`answer = 1`。 自从`moves = min(0, 2) = 0`，循环不执行。 输出是`1`，正确计算起点。 

为了`p = 3, n = 10`，该算法替换`n`和`min(10, 6) = 6`。 开始于`0`，六次模拟移动后的位置是`1, 0, 0, 1, 0, 0`。 唯一位置`1`是新的，所以最终答案是`2`。 第七步到第十步不能添加任何内容，因为它们重复了周期序列的前四个位置。 

为了`p = 4, n = 3`，循环处理位置`1, 3, 2`。 连同最初的`0`，访问集变为`{0, 1, 2, 3}`，所以答案是`4`。 这捕获了忘记起始点已经是访问集的一部分的常见错误。 

为了`p = 3, n = 6`，该算法正好处理一个完整的周期。 职位是`0, 1, 0, 0, 1, 0, 0`，所以结果仍然是`2`。 最后一个位置返回到的事实`0`也是对身份的具体检查`pos_{2p} = 0`。 

为了`p = 8, n = 10^18`，所要求的移动次数是巨大的，但是`moves`变成`16`。 该算法仅检查这十六个动作。 此后，相同的位置每十六次移动就会重复出现，因此从第一个周期获得的答案也是整个请求执行的答案。
