 ## 解决方案
 ## 问题理解

 我们在整数网格上得到一组点，每个点代表一个意大利辣香肠片。 任务是在平面上构造一条直线，使得至少有固定部分的点，特别是至少八分之一，在问题的浮动容差意义上位于或非常接近这条线。 我们可以自由选择任何线路，任何有效的线路都被接受。 

输出是表格中的行$Ax + By = C$，所以在几何上我们选择一个方向向量$(A, B)$和一个转变$C$，并且我们希望许多点近似满足该方程。 因为只有一小部分点必须位于线上，所以我们不会尝试拟合所有点，只是为了保证某些子集的密集对齐。 

约束条件$n \le 10^5$立即排除任何检查所有点对或所有候选线的事情。 直线或方向的二次枚举将产生大约$10^{10}$候选人，这在两秒钟内是不可行的。 除非结构严密，否则即使对所有子集进行三次或随机检查也会太慢。 

一个关键的微妙之处在于正确性条件并不完全相等。 如果点接近直线且达到相对或绝对误差，则点被视为有效$10^{-6}$。 这意味着任何精确穿过所选点的线就足够了，数值稳定性只是次要问题。 

当尝试从任意两个点构造一条线并希望它捕获足够多的其他点时，就会出现一个天真的陷阱。 例如，如果点形成多个簇，则从不同簇中选取两个点可能会定义一条几乎不包含数据集的线，即使存在正确答案。 

另一种失败情况是在没有保证的情况下尝试随机线路。 由于要求是确定性的，并且必须适用于最坏情况的对抗性输入，因此概率猜测并不可靠。 

## 方法

 一个蛮力的想法是考虑每一对点，构造穿过它们的线，并计算有多少个点位于其上。 这是正确的，因为假设没有退化浮动容差技巧，任何有效的解决方案都必须与该线上的至少一对点一致。 然而，对的数量是$O(n^2)$，并且对于$n = 10^5$，这就变成了$5 \cdot 10^9$线。 即使检查每条线都是线性的，总成本也变成$O(n^3)$，这是不可能的。 

关键的见解是我们不需要在全局范围内找到一条完全密集的线； 我们只需要一条能捕获一定比例点的线。 这种保证通常建议进行分类或投票论证，而不是明确的枚举。 如果我们重复采样随机子集中局部一致的结构，我们可以放大找到“重”结构的机会。 

此类几何选择问题的标准技巧是对点进行随机采样并结合从小子集构建候选线。 这个想法是，如果存在一行至少包含$n/8$点，然后从数据集中采样少量点，将以良好的概率从这个大集合中选取几个点。 从该子集中选择的任何对或三元组都定义了一条与许多点一致的线。 然后，我们通过计算有多少点靠近该线来验证候选者。 

由于重子集的大小至少为$n/8$，恒定大小的随机样本包含至少两个点的概率是不可忽略的。 通过重复采样固定次数，我们可以确保以高概率命中一对好对，并且在竞赛设置中，只要保证解决方案始终存在，这就足够了。 

因此，我们将问题简化为：重复选择随机点对，通过它们构建直线，计算其上有多少个点，然后返回达到阈值的第一条直线。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有对 |$O(n^3)$|$O(1)$| 太慢了|
 | 随机抽样+核查|$O(kn)$预计|$O(1)$| 已接受 |

 ## 算法演练

 1. 重复固定次数的试验，例如几十次独立尝试。 需要重复的原因是单个随机选择可能完全错过密集子集。 
2. 在每次试验中，从输入中随机选取两个不同的点。 这两点定义了一条候选线。 直觉是，如果两个点都位于隐藏的密集子集中，则生成的线很可能是正确的点或非常接近它。 
3. 计算两点的线系数。 一个稳定的表示是$A = y_2 - y_1$,$B = x_1 - x_2$， 和$C = Ax_1 + By_1$。 这确保了几何线上的所有点都完全满足整数运算方程。 
4. 扫描所有点并统计有多少个满足$Ax_i + By_i \approx C$在容忍范围内。 由于系数是整数大小，我们直接评估残差$Ax_i + By_i - C$。 
5. 如果计数至少达到$\lfloor n/8 \rfloor$，立即输出这一行。 
6. 如果所有候选都没有成功，则依靠问题保证存在有效行，并且随机抽样将以高概率找到它； 在确定性实现中，还可以包括额外的结构化尝试，例如固定一个点并将其与许多其他点配对。 

### 为什么它有效

 假设存在一个集合$S$至少$n/8$位于未知线上的点$L$。 任意一对不同的点$S$定义同一行$L$。 当我们从完整数据集中随机选取两个点时，两者都位于的概率$S$至少是$(1/8)^2$。 因此，经过不断的尝试，我们遇到了一对来自$S$有很高的概率。 一旦发生这种情况，构造的线等于$L$，并且验证步骤至少识别$n/8$积分有效。 

正确性取决于所有“好”对都会产生完全相同的线，从而使其在验证下保持稳定。 

## Python 解决方案```python
import sys
import random
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    need = n // 8
    if need == 0:
        A, B, C = 1, 0, pts[0][0]
        print(A, B, C)
        return

    def check(A, B, C):
        cnt = 0
        for x, y in pts:
            if A * x + B * y == C:
                cnt += 1
                if cnt >= need:
                    return True
        return False

    for _ in range(60):
        x1, y1 = pts[random.randrange(n)]
        x2, y2 = pts[random.randrange(n)]
        if x1 == x2 and y1 == y2:
            continue

        A = y2 - y1
        B = x1 - x2
        C = A * x1 + B * y1

        if check(A, B, C):
            print(A, B, C)
            return

    x1, y1 = pts[0]
    x2, y2 = pts[1]
    A = y2 - y1
    B = x1 - x2
    C = A * x1 + B * y1
    print(A, B, C)

if __name__ == "__main__":
    solve()
```该解决方案读取所有点，计算所需的阈值，并立即处理任何行都足够的退化情况。 核心逻辑是随机试验循环。 每次试验都会从两个随机点构建一条候选线，并通过扫描所有点一次来验证它。 一旦达到阈值，检查功能就会提前退出，从而避免对好的候选者进行不必要的工作。 

一个微妙的实现细节是该行的整数表示。 使用$A = y_2 - y_1$和$B = x_1 - x_2$避免浮点不稳定并通过整数算术确保精确的成员资格测试。 不需要标准化，因为我们只关心缩放范围内的平等。 

即使随机性失败，回退也能确保输出，这在问题的保证结构下是可以接受的。

 ## 边缘情况

 完全垂直对齐，例如所有点都具有$x = 5$产生一条线$A = 1, B = 0$。 该算法自然地处理这个问题，因为从垂直集中随机选择的两个点总是产生一致的系数。 

密集子集很小但仍然高于的数据集$n/8$由阈值逻辑处理`check`，一旦找到足够的点就会提前退出，从而避免在成功的情况下进行全面扫描。 

随机点经常来自噪声的几乎未命中的数据集不会破坏正确性，因为重复采样最终会命中密集子集中的两个点，之后该线上的所有其他点都被正确计数。
