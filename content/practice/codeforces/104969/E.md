 ## 解决方案
 ## 问题理解

 每个披萨由圆形排列的切片和一个中心点组成。 每片都有一个成本参数，披萨周围的外皮也有一个成本参数。 基本思想是，我们可以使用两种类型的连接（基于切片的连接和基于外壳的连接）来“连接”该结构的顶点，并且我们希望连接整个披萨所需的总成本最小。 

对于每个披萨，这减少了寻找一种最便宜的方法来确保所有切片顶点和中心属于单个连接的组件。 有两种自然策略。 一种是使用切片连接将每个切片直接连接到中心。 另一种是使用地壳连接在一个循环中连接切片，然后使用最便宜的切片连接将中心连接一次。 每个披萨的答案是这两种结构中成本最低的。 

一旦为每个披萨计算出这个值，它就变成了一个调度问题。 每个披萨需要一个单位的时间来吃，从时间零开始，披萨i必须严格在时间d_i之前吃完，否则被认为是浪费，并为惩罚贡献v_i。 由于一次只能吃一个披萨，因此我们有效地将单位长度的作业分配给整数个时间段，其中每个作业都有一个截止日期，如果没有及时完成就会受到惩罚。 目标是尽量减少因错过最后期限而造成的总处罚。 

约束条件允许最多 100,000 个披萨，因此任何尝试所有排列或模拟二次时间调度的方法都行不通。 我们需要接近 O(N log N) 的东西，因为排序和优先级队列操作是可行的，但对所有状态进行重复重新扫描或动态编程则不可行。 

一个微妙的失败案例来自于将连接成本 d_i 与调度约束混淆。 通过增加 v_i 或增加 d_i 而不遵守最后期限来安排披萨的贪婪方法很容易失败。 另一个错误是将 d_i 视为独立的，而没有认识到它仅取决于每个披萨的小型结构优化。 

## 方法

 我们首先处理一个披萨。 如果我们忽略结构，我们可能会尝试在大小为 s_i + 1 的图上使用通用 MST 方法来计算连接所有顶点的最小方式。这在概念上可行，但如果以幼稚的方式独立为每个披萨完成，则速度太慢。 

关键的观察结果是，该图具有非常具体的形式：具有均匀地壳成本 c_i 的切片循环，以及连接到具有成本 q_i 的每个切片的中心。 在这种结构中，最佳生成树必须采用两种形式之一。 要么我们将每个切片直接连接到中心，计算所有 q_i 的总和，要么我们对圆周围除一个连接之外的所有连接使用循环边，并仅通过最便宜的切片连接中心。 这给出了成本 (s_i - 1) * c_i + min(q_i)。 取这两者中的最小值即可得出每个披萨的 d_i，复杂度为 O(1)。 

一旦计算出所有 d_i，每个披萨就成为一个单位时间工作，其截止日期为 d_i，如果未按时完成则将受到惩罚 v_i。 我们希望在截止日期前完成的工作的总价值最大化。 

强力调度方法会尝试披萨的所有排列、模拟时间进展并计算惩罚，从而导致 O(N!) 或最多 O(N^2) 检查，这对于 N 高达 100,000 来说是不可能的。 

对于有截止日期的单位时间工作的标准观察是，我们应该按照截止日期的升序处理工作。 在扫描时，我们维护一组选定的作业。 如果在任何时候我们选择的作业数量多于当前截止日期允许的作业数量，则我们必须丢弃一个作业，并且丢弃的最佳选择是 v_i 值最小的作业。 这种贪婪的交换论证确保我们保留最有价值的可行集。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力调度 | O(N!) 或 O(N^2 N!) | O(1) | O(1) | 太慢了|
 | 最优（计算 d_i + 贪婪调度）| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 ### 1. 计算每个披萨的连接成本

 对于每个披萨，计算两个候选成本。 第一个是所有切片强度 q_i 的总和，表示将每个切片直接连接到中心。 第二个是 (s_i - 1) * c_i 加上最小切片强度，表示对除一个连接之外的所有连接使用地壳循环，并通过最便宜的切片连接中心。 取这两者中的最小值作为d_i。 

此步骤将几何结构简化为每个披萨的单个截止时间值。 

### 2. 将每个披萨视为一项调度作业

 如果在截止日期之前完成，每个披萨将成为一个处理时间为 1、截止日期为 d_i 且利润为 v_i 的作业。 错过它意味着支付 v_i 作为浪费。 

我们将视角从几何转向调度。 

### 3. 按截止日期对披萨进行排序

 按 d_i 升序对所有作业进行排序。 这确保我们始终首先考虑最紧迫的约束。 

### 4.维护一组精选的披萨

 迭代排序的作业，维护最大可行子集。 将每项工作暂时添加到所选披萨的集合中。 

### 5. 使用最小堆值强化可行性

 如果所选作业的数量超过了截止日期排序所暗示的当前时间限制，则删除 v_i 最小的作业。 这保留了仍然可以调度的最有价值的子集。 

直觉是，每当我们超出容量时，我们就必须丢弃一些东西，而成本最低的损失总是最佳的丢弃方式。 

### 为什么它有效

 对于按截止日期排序的任何作业前缀，该算法都会维护适合该前缀的可用时隙的最佳作业子集。 不变的是，在处理完所有截止时间≤T的作业后，我们最多保留T个作业，并且在所有这些子集中，我们保留总价值最大的一个。 每当我们超出容量时，用较大的 v_i 作业替换较小的 v_i 作业可以保留可行性并提高或维持总价值。 这种交换论证保证了贪婪删除不会排除任何最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    jobs = []
    
    for _ in range(n):
        s, q, c, v = map(int, input().split())
        
        total_q = s * q
        min_q = q
        
        # connectivity cost
        d = min(total_q, (s - 1) * c + min_q)
        
        jobs.append((d, v))
    
    jobs.sort()
    
    import heapq
    heap = []
    heap_sum = 0
    
    for d, v in jobs:
        heapq.heappush(heap, v)
        heap_sum += v
        
        # we can keep at most d jobs by time d
        if len(heap) > d:
            heap_sum -= heapq.heappop(heap)
    
    total = sum(v for _, v in jobs)
    print(total - heap_sum)

if __name__ == "__main__":
    solve()
```该实施首先将每个披萨压缩到其有效期限内。 堆存储我们决定按时完成的披萨的值。 每当我们超过当前截止日期前缀允许的作业数量时，我们就会删除最小值，因为它对最终目标的贡献最小。 

最终答案的计算方式为总价值减去所选准时作业的总和，这直接给出了总浪费价值。 

## 工作示例

 ### 示例 1

 考虑具有计算截止日期和价值的披萨：

 | ---| ---| ---| ---|

 在这里，当超出容量时，我们总是删除最小值。 最终保留价值最大化。 

这表明较早的截止日期限制了可以安排的作业数量，并且基于价值的修剪可以保持最优性。

 ## 边缘情况

 当所有切片都相同并且外壳比切片连接便宜得多时，就会出现极端情况。 在这种情况下，d_i 变为 (s_i - 1) * c_i + q_i，并且采用最小切片强度而不是完整 q_i 时的任何错误都会高估可行性。 

另一个边缘情况是许多披萨都有相同的小期限。 该算法反复超出同一阈值的容量，从而强制进行多次删除。 基于堆的选择仍然有效，因为每次违规都是通过丢弃最不有价值的工作在本地解决的，并且即使多个约束同时发生冲突，该决定仍然有效。
