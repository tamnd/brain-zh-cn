 ## 解决方案
 ## 问题理解

 我们在一个巨大的二维网格上得到了一组点。 每个点代表位于坐标处的一个敌人$(x_i, y_i)$并承载重量$s_i$。 没有两个敌人共享相同的坐标。 

对于每个敌人，我们需要计算从原点延伸到敌人位置（包括边界在内）的矩形区域中存在多少总力量。 换句话说，对于一个查询点$(x_i, y_i)$，我们总结所有敌人的力量$(x_j, y_j)$这样$x_j \le x_i$和$y_j \le y_i$。 

因此，每个输出值都是由坐标优势定义的 2D 偏序的前缀和。 

困难来自规模。 多达 200,000 个点，坐标值高达$2 \cdot 10^9$，我们无法构建网格或直接模拟坐标上的前缀累积。 任何尝试检查每个查询的所有早期点的方法都会导致粗略的结果$O(N^2)$行为，已经远远超出了极限。 

如果尝试仅按以下方式进行排序，那么一种幼稚的方法也会巧妙地失败：$x$并积累$y$- 没有仔细结构的前缀和。 原因是支配关系是二维的，而不是一维的，因此以单个排序顺序进行处理不会自动保持正确性，除非我们主动维护第二维上的结构。 

不存在棘手的重复坐标问题，因为坐标保证是不同的，但值可能很大，这迫使我们压缩或以其他方式避免直接索引。 

## 方法

 一种直接的方法是通过扫描所有点并检查两个坐标是否较小或相等来独立回答每个查询。 这正确地实现了定义，但需要$N$每个查询的比较，结果是$O(N^2)$总工作量。 和$N = 2 \cdot 10^5$，这变成了$4 \cdot 10^{10}$比较，这是不可行的。 

关键的观察结果是查询是二维中的经典优势前缀和。 如果我们可以按升序处理点$x$，那么此时我们处理一个点$(x_i, y_i)$，所有较小的点$x$已经被核算了。 剩下的挑战是有效地总结其中那些也满足$y \le y_i$。 

这减少了维持动态结构的问题$y$- 支持前缀和和点更新的坐标。 每个点贡献一次力量，我们需要查询到目前为止已经插入了多少总权重$y$- 以阈值为界的坐标。 

因为$y$可以达到$2 \cdot 10^9$，我们将坐标压缩为等级。 压缩后，我们使用芬威克树（二叉索引树）$y$- 排名。 我们对所有点进行排序$x$，按升序处理它们，对于每个点，我们查询 Fenwick 树的前缀和，直到其$y$-秩。 然后我们将其权重插入 Fenwick 树中。 

一个微妙之处是我们必须按照输入点的原始顺序输出答案。 因此，在按正确排序顺序进行处理时，我们存储每个索引的结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了|
 | 排序 + 芬威克树 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们首先将问题转化为可以沿着一个轴增量处理的问题，同时支持另一个轴上的快速查询。 

1. 为每个点分配一个与其输入位置相对应的索引。 这是必需的，因为我们将在处理过程中对点重新排序，但必须按原始顺序输出答案。 
2. 全部提取$y_i$值并将它们压缩到一个连续的范围内$[1, N]$。 此步骤保留顺序，同时可以使用 Fenwick 树。 压缩之所以有效，是因为只有相对顺序$y$-值对于前缀和很重要。 
3. 对所有点进行递增排序$x_i$。 如果两点相等$x$，它们之间的顺序在这里并不重要，因为坐标是不同的，但即使它们不是不同的，我们通常也会任意断开关系。 
4. 在压缩后初始化 Fenwick 树$y$-范围，最初为空。 
5. 按排序顺序扫描点$x$。 对于每个点$(x_i, y_i, s_i)$:

 1. 查询 Fenwick Tree 以获取压缩后的所有强度的总和$y \le y_i$。 这给出了位于所需矩形内的所有先前处理的点的总贡献。 
2. 将此值存储为当前点的答案。 
3. 通过添加更新 Fenwick 树$s_i$在位置$y_i$，所以未来的点更大$x$可见其贡献。 

处理完所有点后，存储的答案与所需的完全对应$F(x_i, y_i)$。 

它起作用的原因归结为保持一个干净的不变量：在扫描过程中的任何时刻，芬威克树都准确地存储了所有点的强度总和，这些点的强度$x$-坐标小于或等于当前扫描位置$x$，按其索引$y$-协调。 因此，前缀查询$y$精确选择满足两个坐标约束的子集。 由于每个点在查询其自身贡献后仅插入一次，因此不会遗漏或重复计算任何值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n = int(input())
pts = []
ys = []

for i in range(n):
    x, y, s = map(int, input().split())
    pts.append((x, y, s, i))
    ys.append(y)

ys_sorted = sorted(set(ys))
comp = {v: i + 1 for i, v in enumerate(ys_sorted)}

pts.sort(key=lambda p: p[0])

bit = Fenwick(len(ys_sorted))
ans = [0] * n

for x, y, s, idx in pts:
    cy = comp[y]
    ans[idx] = bit.sum(cy)
    bit.add(cy, s)

print("\n".join(map(str, ans)))
```Fenwick 树是核心结构，可在压缩后的数据上实现高效的前缀聚合。$y$-轴。 这`add`函数以对数时间执行点更新，而`sum`检索前缀和。 坐标压缩确保我们永远不会按比例分配内存$2 \cdot 10^9$。 

排序依据$x$确保当我们处理一个点时，所有具有较小或等于的有效贡献者$x$已经在结构中了。 按原始索引存储结果可以保留输出顺序。 

一个常见的陷阱是交换查询和更新的顺序。 正确的行为是首先查询，然后插入当前点，因为除非问题定义明确表示，否则点不应该对自己的前缀和做出贡献，这与严格包含在已处理的前缀中完全对应。

 ### 示例 1

 按顺序输入点：$(1,1,5), (2,1,10), (1,2,10), (3,3,15)$排序依据$x$:$(1,1,5), (1,2,10), (2,1,10), (3,3,15)$我们跟踪压缩状态下的芬威克状态$y$:

该跟踪显示了如何早期$x$-坐标逐渐累积，而芬威克树保持排序$y$。

 ## 边缘情况

 一种重要的边缘情况是所有点共享相同的点$x$-协调。 在这种情况下，排序依据$x$将所有内容组合在一起，答案完全取决于$y$-前缀积累。 该算法仍然有效，因为在固定的时间内$x$，没有一点对同一批次中的另一个做出贡献，因为更新发生在查询之后。 例如，用点$(1,3,10), (1,1,5), (1,2,7)$，处理将所有查询产生为零，这与定义匹配，因为没有点严格小于$x$。 

另一种边缘情况是严格递减坐标，例如$(3,3), (2,2), (1,1)$。 排序后，扫描变得越来越大，每个点只能看到较早的较小对。 芬威克树确保即使输入顺序颠倒，仍能正确评估优势关系。 

最后一个微妙的情况是当值很大且稀疏时。 如果没有压缩，Fenwick 树将无法分配。 压缩会保留顺序，因此即使是像这样的值$y = 10^9$一旦映射，其行为与小索引相同。
