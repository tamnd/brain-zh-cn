 ## 解决方案
 ## 问题理解

 在雪莉到达之前，我们会得到固定的队列，并共享披萨片、炸玉米饼和酱汁。 队列中的每个人都独立选择要拿多少物品，但他们受到两个规则的限制：他们总共最多可以拿两件食物，如果他们正好拿两件酱汁，他们可以额外拿一件自己选择的食物。 

Shelly 的订单已经固定为一片披萨和一份炸玉米饼，所以她关心的不是她自己的选择，而是她前面的人能否消耗足够的资源，在她到达柜台之前吃完披萨或炸玉米饼。 问题是，前面的人是否存在任何有效选择序列，使得在轮到雪莉之前，至少有一个披萨或炸玉米饼库存变为零或负数。 

输入给出了 Shelly 之前的人数，后面是披萨、炸玉米饼和酱汁的初始数量。 输出只是在任何有效的选择序列下是否可能耗尽披萨或炸玉米饼。 

限制允许最多 100,000 人和最多 100,000 个物品。 这立即排除了任何试图探索每个人所有可能的选择组合的模拟，因为即使是很小的分支因子也会爆炸到指数时间。 解决方案必须将问题简化为推理最坏情况下的人均消费量。 

一个微妙的问题是，酱汁的供应量可能会改变每个人的摄入量。 如果不小心处理，人们可能会错误地认为酱汁是无关紧要的或总是足够的。 另一个陷阱是假设每个人总是拿相同数量的物品，而事实上“额外物品加两种酱汁”规则创建了两种不同的消费模式，影响某人是否可以最大限度地使用披萨或炸玉米饼。 

核心边缘情况是当酱汁刚好足以满足所有人的额外消费时，这可以显着增加可能的总需求并改变是否可以实现消耗。 

## 方法

 蛮力视角会尝试模拟 n 个人中每个人在受约束的情况下选择物品的所有可能方式，跟踪剩余的披萨、炸玉米饼和酱汁。 对于每个人，我们会考虑他们是否带零份、一份或两份食物，以及他们是否花费酱汁。 即使我们在资源变为负数时修剪无效状态，可能的状态数量也会随着 n 呈指数增长，因为每个人都会引入多个独立的决策。 当 n = 10^5 时，这是完全不可行的。 

关键的观察是，我们不关心选择的确切顺序，只关心是否存在耗尽披萨或炸玉米饼的序列。 这就把问题变成了“最大可能消耗”问题。 我们不是单独模拟人们，而是问：在最佳对抗行为下，前 n 个人可以拿走的披萨或炸玉米饼的最大数量是多少？ 

每个人最多可以拿两样东西，如果正好有两种酱汁，有时还可以拿第三样东西。 这意味着真正的问题是有多少人可以“升级”到获取 3 件物品而不是 2 件。由于每次此类升级恰好消耗 2 个酱汁，因此升级的人数受到 Z 和 n 的限制。 

因此，拿走的物品的最大数量的上限是最大化有多少人拿走 3 件物品，然后其余的人拿走 2 件。由此，我们通过假设所有拿走的物品都集中在披萨（或炸玉米饼）上来计算单个物品类型的最坏情况消耗。 如果 X 或 Y 小于或等于单个类别的最大可能需求，则可能出现耗尽。 

问题简化为检查是否：

 我们可以在 n 个人之间分配足够的“物品槽”，假设最多 min(n, Z // 2) 个人可以拿走 3 件物品，其余的人拿走 2 件物品。

 ## 算法演练

 我们将问题转化为计算前 n 个人可以消费的最大物品数量。 

1. 计算有多少人可以从酱汁中获得额外的物品。 每个这样的人需要2个酱汁，所以升级的人数是`k = min(n, Z // 2)`。 这最大限度地增加了可以利用酱汁的人数，而不会超过酱汁供应或可用人数。 
2. 对于这 k 个人，每人拿 3 件而不是 2 件，贡献`3k`消耗的总项目。 
3.对于剩余的`n - k`人，每个人只需要 2 个项目的基本最大值，贡献`2(n - k)`项目。 
4. 将这些贡献相加，得到雪莉到达之前可以消耗的最大物品总数：`total = 3k + 2(n - k)`。 
5. 由于我们只关心披萨或炸玉米饼是否可以用完，所以我们考虑最坏情况的集中度：如果所有消耗的物品都是一种类型，那么单个资源的最大可能消耗是`total`。 我们比较`total`反对 X 和 Y。 
6. 如果 X <= 总计或 Y <= 总计，则输出“yes”，否则输出“no”。 

### 为什么它有效

 关键的不变量是，每个有效的选择顺序都对应于每人最多选择两个项目，当且仅当他们花费两种酱汁时，一部分人可以选择恰好获得一个额外的项目。 表达式`3k + 2(n-k)`捕获任何有效配置可以生成的最大物品槽总数，因为它独立地满足两个约束：酱汁限制升级和每人上限。 任何实际的执行都不能超过这个界限，并且存在一种策略，可以通过尽可能最大化每人的物品数量来实现这一目标。 这将对抗性问题简化为单个标量比较。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    X, Y, Z = map(int, input().split())

    k = min(n, Z // 2)
    total = 3 * k + 2 * (n - k)

    if X <= total or Y <= total:
        print("yes")
    else:
        print("no")

if __name__ == "__main__":
    solve()
```该实现直接计算可以使用酱料升级的人数，然后得出总消费能力。 唯一的微妙之处是确保整数除法`Z // 2`，因为每个升级的人只消耗两种酱汁。 

最终的比较独立地检查这两种资源，因为耗尽其中任何一个就足够了。 

## 工作示例

 ### 示例 1

 输入：```
n = 21
X = 60
Y = 70
Z = 108
```我们计算有多少人可以使用酱汁进行升级。 

| 步骤| k = min(n, Z//2) | k = min(n, Z//2) | 总项目 | X | 是 | 状况 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 分钟(21, 54) = 21 | 3_21 + 2_0 = 63 | 3_21 + 2_0 = 63 | 60| 70 | 70 X <= 总计 |

 在这里，21个人都可以升级，因为108个酱汁允许54个升级，但只有21个人存在。 每人拿 3 份，因此总消费量为 63。由于披萨供应量为 60，因此披萨有可能在 Shelly 到达之前就用完。 

这一痕迹表明，酱汁丰富可以让每个人最大化消费，增加资源压力。 

### 示例 2

 输入：```
n = 19
X = 60
Y = 70
Z = 108
```| 步骤| k | 总项目 | X | 是 | 状况 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 分钟(19, 54) = 19 | 3*19 = 57 | 3*19 = 57 60| 70 | 70 X > 总计且 Y > 总计 |

 即使酱料全部使用，总消耗量也只有57种。 披萨和炸玉米饼都超过了这个界限，所以两者都不能完全耗尽。 

这表明，当供应超过最大可能的消费能力时，任何订购策略都不会导致耗尽。

 ## 边缘情况

 一种极端情况是前面没有人。 在这种情况下，不会发生任何消费，披萨和炸玉米饼都不会在雪莉之前用完。 公式给出`k = 0`,`total = 0`，并正确地得出“否”。 

另一种情况是酱料供应量极大但n很小。 即使 Z 很大，升级也会受到 n 的限制，因此该算法可以正确地防止高估消耗。 

第三种情况是 Z 为零时。 那么就无法升级，并且严格限制总消耗`2n`。 这正确地模拟了任何人都不能超过两项的约束。
