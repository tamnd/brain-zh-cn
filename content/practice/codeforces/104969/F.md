 ## 解决方案
 ## 问题理解

 我们得到一组从 1 到 n 标记的披萨，其中每个标签也是其半径。 我们必须将所有披萨排列在一个垂直的堆栈中，这相当于选择从 1 到 n 的数字排列。 

对于堆叠中的任意两个披萨，请考虑物理上较低的一个和上面的一个。 如果下面的披萨的半径比上面的披萨的半径大，那么这一对就构成了问题中所谓的“正确的一对”。 在排列语言中，这正是一种倒置：一对索引 i < j，使得 i 处的值大于 j 处的值。 

因此，任务变成计算有多少个大小为 n 的排列恰好包含 k 个反转。 

约束 n ≤ 1000 和 k ≤ 1000 立即表明我们没有直接在阶乘或指数空间中工作。 对所有排列的简单枚举将涉及 n! 可能性，这在 n = 12 或 13 左右就变得不可能了。即使 n = 100 也远远遥不可及。 这推动我们采用动态编程方法，通过逐渐插入元素并跟踪形成的反转次数来计算排列。 

边缘情况主要是结构性错误，而不是实现错误。 当 k = 0 时，只有递增排列起作用。 当 k 最大时，k = n(n − 1)/2，只有递减排列有效。 任何解决方案都必须正确处理这些极端情况，而不依赖于 k < n 或 k 相对于 n 较小的假设，即使 k ≤ 1000 限制了 DP 状态空间。 

一个微妙的情况是当 n 大而 k 小时。 例如，n = 1000 且 k = 1 仍然需要推理如何通过在许多已经固定的相对位置中准确地放置一个无序元素来创建单个反转。 除非仔细定义 DP 结构，否则简单的组合学往往会失败。 

## 方法

 强力方法将生成 1 到 n 的所有排列，并计算每个排列的反转次数。 计算每个排列的反转需要 O(n^2)，并且有 n！ 排列，因此总工作量为 O(n!·n^2)，这几乎立即变得不可行。 

我们需要一个可以增量构建排列的结构。 关键的观察是考虑按标签递增顺序一一插入数字。 假设我们已经构建了数字 1 到 i − 1 的有效排列。当我们插入数字 i 时，我们可以将其放置在现有 i − 1 个元素中的任何位置。 如果我们将它插入到左侧的位置 t 处，它会创建 i − 1 − t 个新的反转，因为它将被放置在那么多较小的元素之前。 

这给出了一个干净的递归：每个插入仅根据其位置贡献可控数量的新反转。 这种独立性使得动态编程成为可能。 

我们将 dp[i][j] 定义为前 i 个数字恰好具有 j 个反转的排列数。 对于每个 i，我们尝试将 i 的所有可能插入位置放入大小为 i − 1 的排列中，并累积反转贡献。 

直接转换将为每个状态尝试 O(i) 个位置，从而导致总时间为 O(n^3)。 但是，我们可以使用前一个 dp 行的前缀和进行优化。 这会将内部转换变为 O(1)，从而将完整解减少为 O(nk)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n^2) | O(n!·n^2) | O(n) | 太慢了|
 | 带有前缀和的 DP | O(nk) | O(nk) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

 我们构建一个表 dp，其中 dp[i][j] 计算 {1..i} 的排列，恰好有 j 个反转。

1. 初始化 dp[1][0] = 1。单个元素恰好有一次排列和零次反转。 这锚定了结构。 
2. 对于从 2 到 n 的每个 i，我们从 dp[i − 1] 计算 dp[i]。 在此阶段，我们假设较小集合的所有计数都已经正确。 
3. 对于固定的 i，考虑将元素 i 插入到大小为 i − 1 的排列的每个可能位置。如果我们将其插入到位置 p（0 索引），它将贡献 (i − 1 − p) 个反转。 
4. 将其转化为递推式：dp[i][j] 等于 dp[i − 1][j − t] 在从 0 到 i − 1 的所有 t 上的总和，其中 t 是插入 i 引入的反转次数。 这是 dp[i − 1] 上的滑动窗口总和。 
5. 使用 dp[i − 1] 的前缀和有效计算 dp[i][j]。 对于每个 j，我们维护 dp[i − 1] 的最后 i 个值的运行窗口总和。 
6. 确保我们只考虑 j 到 k，因为较大的值与答案无关。 

这样做的关键原因是插入最大元素 i 不会扰乱 1..i − 1 之间的相对顺序，因此所有反转结构仅来自其位置。 每个大小为 i 的排列都是通过将 i 插入到大小为 i − 1 的排列中的一个位置而唯一形成的，因此 DP 覆盖了所有状态而没有重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, k = map(int, input().split())

dp = [[0] * (k + 1) for _ in range(n + 1)]
dp[1][0] = 1

for i in range(2, n + 1):
    window_sum = 0
    for j in range(0, k + 1):
        window_sum += dp[i - 1][j]
        if j - i >= 0:
            window_sum -= dp[i - 1][j - i]
        dp[i][j] = window_sum % MOD

print(dp[n][k] % MOD)
```该代码逐行构建 DP。 这`window_sum`在前一行上维护一个大小为 i 的滑动窗口，恰好对应于当前数字 i 的 i 个可能的插入位置。 每个 dp[i][j] 累积来自 dp[i − 1][j]、dp[i − 1][j − 1]、...、dp[i − 1][j − (i − 1)] 的贡献。 

一个常见的陷阱是忘记窗口大小随着 i 的增长而增长。 另一个微妙的问题是当 j − i 变为负数时的边界处理，它不能索引到数组中。 每次状态更新后应用模数以防止溢出。

 ## 边缘情况

 对于 n = 1 且 k = 0，DP 初始化 dp[1][0] = 1 并立即返回它。 没有转换步骤，因此不存在访问 dp[0] 或无效索引的风险。 

对于 n = 4 和 k = 0，滑动窗口永远不会累积超出 dp[i][0] 的任何正贡献，因为所有较高的反转计数都是无关的。 该算法在每个级别都保留 dp[i][0] = 1，因为在末尾插入最大元素会引入零反转，并且所有其他插入都会被 k 边界过滤掉。 

对于 n = 4 和 k = 6（4 个元素的最大反转计数），DP 只能正确计算完全反转的排列。 滑动窗口通过在每个排列开始时的连续强制放置自然地积累了一条有效的构造路径。
