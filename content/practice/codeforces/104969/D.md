 ## 解决方案
 ## 问题理解

 我们有一系列学生，每个学生都按固定顺序要求一定数量的披萨片。 有K个相同的披萨，每个披萨有相同的未知容量S片。 学生们被一个接一个地服务：如果当前的披萨仍然有足够的剩余切片以满足下一个学生的要求，则从该学生中获得服务； 否则，剩余的披萨片将被丢弃，打开一张新鲜的披萨，并为学生提供新的披萨。 

关键问题不是服务如何进行，而是 S 必须有多大，以便在最多有 K 个披萨可用的情况下完成此过程而不会用完披萨。 

所以任务是选择最小的整数 S，这样当我们模拟这个贪婪的服务过程时，我们永远不需要超过 K 个披萨。 

输入大小最多允许 100,000 名学生和最多 100,000 个披萨。 这立即排除了任何试图通过模拟每个候选过程来检查 S 的所有可能值的解决方案。 S 的朴素上限是所有需求的总和，最大可达 10^11，因此 S 上的任何线性搜索都是完全不可行的。 

我们需要一个解决方案，将问题简化为单调的可行性检查。 

一些微妙的情况很重要：

 如果单个学生请求大量切片，例如 d_i = 10^6，则 S 必须至少有那么大。 否则，算法会重复为一名学生打开披萨，这是允许的，但会浪费容量； 更重要的是，正确性条件仍然成立，但在小S下可行性变得不可能。 

当 K 比 N 大时，就会出现另一种边缘情况。例如，如果 K ≥ N，即使 S = max(d_i) 也总是有效，因为原则上每个学生都可以开始一个新的披萨。 这不会改变答案结构，但有助于确认边缘处理的正确性。 

最后，主要的微妙之处在于，当打开新的披萨时，剩下的切片总是被丢弃。 这意味着我们有效地将序列划分为段，其中每个段的总和最多为 S，但段是由溢出强制的，而不是由最佳打包强制的。 这种强制贪婪结构是解决方案的驱动力。 

## 方法

 直接的暴力方法将尝试候选值 S 并模拟服务过程：保留当前披萨中的剩余切片，在为学生提供服务时减少它，并计算需要打开一个新披萨的次数。 如果超过 K，S 无效。 

该模拟对于固定的 S 是正确的，并且花费 O(N) 时间。 然而，S 本身可以与所有需求的总和一样大。 尝试从 max(d_i) 向上的所有值最多需要 10^11 次检查，这是不可能的。 

关键的观察是可行性在 S 中是单调的。如果给定的 S 足以为 K 个披萨内的所有学生提供服务，那么任何更大的 S 也足够了，因为增加容量只能减少或维持披萨开口的数量。 这将问题转化为对 S 的二分搜索。 

每次可行性检查都是一次贪婪扫描：我们模拟该过程并计算使用了多少个披萨。 如果在任何时候单个需求超过 S，我们立即知道 S 是无效的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力S枚举| O(N * 总和 d_i) | O(1) | O(1) | 太慢了|
 | 二分查找+模拟| O(N log max d_i) | O(N log max d_i) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们搜索最小的 S，以便我们可以使用最多 K 个披萨为所有学生提供服务。

1. 将 S 的搜索范围设置为 max(d_i) 到 sum(d_i)。 下限是必要的，因为任何学生都必须适合单个披萨段。 
2. 定义函数can(S)，模拟为学生提供披萨容量S。初始化pizzas_used = 1，remaining = S。 
3. 对于每个需求d_i，检查其是否适合当前剩余容量。 如果剩余≥d_i，则从剩余中减去d_i并继续。 
4.如果剩余< d_i，则将pizzas_used加1，将剩余重置为S，然后减去d_i。 该模型丢弃剩余的切片并打开一个新的披萨。 
5. 如果在任何时候 Pizzas_used 超过 K，则立即返回 False，因为 S 不足。 
6. 对S进行二分查找。如果can(S)为真，则尝试较小的值； 否则，增加S。 

关键的设计选择是我们从不尝试优化学生的分组方式。 这个过程是被迫的，所以贪心模拟是唯一有效的解释。 

### 为什么它有效

 对于固定的 S，模拟会生成尽可能少的披萨，因为只有在剩余容量不足时才会打开新的披萨。 任何提前打开披萨的替代策略只会增加使用量。 因此can(S)正确地反映了可行性。 

单调性确保有效 S 值的集合形成整数后缀，从而保证二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(d, n, k, s):
    pizzas_used = 1
    remaining = s

    for x in d:
        if x > s:
            return False
        if remaining >= x:
            remaining -= x
        else:
            pizzas_used += 1
            if pizzas_used > k:
                return False
            remaining = s - x

    return pizzas_used <= k

def solve():
    n, k = map(int, input().split())
    d = list(map(int, input().split()))

    lo = max(d)
    hi = sum(d)

    while lo < hi:
        mid = (lo + hi) // 2
        if can(d, n, k, mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```该代码将可行性检查与二分搜索分开，这对于清晰度和正确性至关重要。 该函数可以仔细执行强制打开规则：每当剩余容量不足时，我们立即打开一个新的披萨并重置计数器。 

一个微妙的点是将 lo 初始化为 max(d)。 这避免了对无效 S 值的不必要检查，并确保模拟永远不会尝试为学生分配比披萨所能容纳的更多的切片。 

二分搜索收敛是因为每一步都会基于单调可行性缩小区间 [lo, hi)。 

## 工作示例

 考虑一个需求为 [5, 2, 7, 3] 且 K = 2 的输入。 

我们测试候选 S = 7。 

| 学生| 需求| 之前剩余 | 行动| 使用的披萨|
 | ---| ---| ---| ---| ---|
 | 1 | 5 | 7 | 发球，剩余 = 2 | 1 |
 | 2 | 2 | 2 | 发球，剩余 = 0 | 1 |
 | 3 | 7 | 0 | 开新披萨| 2 |
 | 3（续）| 7 | 7 | 发球，剩余 = 0 | 2 |
 | 4 | 3 | 0 | 开新披萨| 3 |

 我们超过了 K = 2，因此 S = 7 无效。 这表明，尽管每个需求都适合单独的需求，但碎片化却会导致额外的披萨。 

现在测试 S = 10。 

| 学生| 需求| 之前剩余 | 行动| 使用的披萨|
 | ---| ---| ---| ---| ---|
 | 1 | 5 | 10 | 10 服务 | 1 |
 | 2 | 2 | 5 | 服务 | 1 |
 | 3 | 7 | 3 | 打开新披萨，上桌| 2 |
 | 4 | 3 | 3 | 服务 | 2 |

 我们正好使用 2 个披萨，因此 S = 10 是可行的。 这演示了增加 S 如何减少强制断点处的碎片。

 ## 边缘情况

 一种重要的边缘情况是当单个需求超过当前候选 S 时。例如，d = [10, 1, 1] 且 S = 5。算法立即拒绝 S 而不进一步模拟，因为不存在可行的分割。 这可以防止浪费计算并保持二分搜索边界的正确性。 

另一种情况是当 K 非常大时，例如 K ≥ N。在 d = [3, 4, 2]，K = 10 时，最优 S 变为 max(d) = 4。模拟永远不会打开第二个披萨，除非被大于剩余容量的需求所强制，并且由于每个需求都适合，所以我们很容易保持在 K 内。 

最后一种情况是严重碎片化：d = [6, 6, 6]，K = 2。当 S = 6 时，每个学生都会强制要求一个新的披萨，需要 3 个披萨，但失败了。 当 S = 12 时，前两个学生适合一个披萨，最后一个学生迫使第二个学生保持在 K 范围内。这表明 S 如何控制分段而不仅仅是局部可行性。
