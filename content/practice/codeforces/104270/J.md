 ## 解决方案
 ## 问题理解

 我们得到一系列书籍，每本书都有固定价格，以及从左到右扫描书籍的确定性购买过程。 在每本书中，如果当前的金钱至少是价格，则购买该书并且金钱减少； 否则这本书将被跳过。 这个过程的最终结果就是购买的书籍数量。 

该任务与通常的模拟方向相反。 我们不会得到初始资金并询问购买了多少本书，而是得到了价格和最终购买的书籍数量`m`，并且我们必须确定可能产生的最大初始资金`m`在这种贪婪的规则下进行购买。 如果没有起始量可以精确生产`m`，答案是“不可能”。 如果任意大的初始资金仍然会导致`m`，答案是“大富翁”。 

这些约束允许每个测试用例最多 10^5 本书，并且跨测试总共最多 10^6 本书。 这立即排除了任何尝试所有可能的初始货币值或模拟许多候选者的解决方案。 每个测试用例需要进行线性或近线性扫描。 

一种天真的但诱人的方法是模拟固定货币值的过程，并尝试对初始货币进行二分搜索。 这失败了，因为谓词“最终购买的书籍数量等于 m”在初始资金中不是单调的。 增加资金可能会导致稍后的购买，这可能会阻止先前的跳过模式重复，因此行为没有清晰地排序。 

当出现更微妙的边缘情况时`m = 0`。 如果第一本书的价格为 0，则任何正钱仍然可以购买它，因此只有精确的零钱才有效。 如果所有价格都是正数，则零钱是有效的并且也是最大的，因此答案变得无界。 当贪婪过程只能实现小于`m`即使有无限的钱也可以购买，这意味着我们不能强迫购买足够的廉价书籍。 

## 方法

 蛮力的观点是确定初始货币价值并模拟该过程，计算购买了多少本书。 我们可以增加资金，直到结果从小于变为`m`至大于`m`，但每次模拟的成本为 O(n)，并且金钱的搜索空间是无界的，可达 10^9 或更多。 即使限制相关阈值，仍然会导致候选状态过多。 

关键的观察是，贪心过程仅取决于我们在每个前缀是否有足够的钱，而最终的购买数量取决于由于预算不足而跳过的书籍。 准确地达到`m`采购时，我们必须确保准确`m`指数采用贪心法则。 

关键的结构洞察力是从最终的可行性角度进行思考。 假设我们修复了哪个`m`书买了。 那么初始资金必须足够大以通过所有购买的书籍，但又足够小以使所有跳过的书籍在其位置上保持跳过状态。 最困难的部分是最大化初始资金，这相当于尽可能推迟第一次失败，同时仍然强制执行`m`购买成功。 

一种干净的重构方法是注意，如果我们假设无限的钱，该过程将以非负价格购买每本书，即所有书籍。 所以唯一的方法是准确地结束`m < n`购买是我们故意在某些仓位之前“用完钱”。 最后跳过的位置至关重要：在该点之后，剩余的后缀此时必须完全无法承受。 

这导致了选择一个边界位置的想法，在该位置我们无法继续购买，同时确保准确`m`购买发生在该边界之前或该边界处。 我们计算选择的最小成本`m`按顺序购买，然后确保所有剩余的书籍不会被意外购买。 

这转化为贪婪的前缀结构：我们试图通过假设我们可以负担得起一定程度的一切来最大化初始资金，唯一的约束来自于强制`m`购买时遵守跳过规则。 

由此产生的最优策略是从左到右扫描，贪婪地假设我们“足够富有”，并确定实现至少所需的最少资金`m`采购，同时还跟踪流程何时必然超出`m`。 如果即使是无限的金钱也不能准确生产`m`，我们返回“不可能”。 如果我们可以任意延迟失败，我们将返回“Richman”。

 ## 算法演练

 我们处理该数组一次，同时推理如果钱非常多会购买多少物品。 在无限金钱的情况下，每本书都会被购买，因此我们转而跟踪必须通过强制跳过来“删除”的购买量。 

我们保留最终还需要多少本书`m`。 每次我们遇到一本书，我们都会决定它是否必须属于`m`购买的书籍或必须跳过。 目标是准确分配`m`按从左到右的顺序进行购买，同时确保与贪婪可行性的一致性。 

我们计算保证选择所需的最低总成本`m`书籍：这是通过在保持秩序的同时贪婪地选择尽可能小的成本贡献来完成的，因为为了最大化初始资金，我们希望推迟支出。 

然后我们验证可行性：在前向扫描期间，如果我们被迫购买超过`m`书籍之前我们可以强制跳过，配置是不可能的。 

最后，我们计算最大初始资金作为我们被迫购买的所有书籍的总成本，以便将贪婪行为维持到最后必要的购买位置。 

特殊情况直接处理。 如果`m = 0`，如果所有价格都是正数，答案是“Richman”（因为任何正数的钱仍然会跳过所有？实际上只有零可以避免购买正数），否则我们检查是否有任何零价格的书强制购买。 

### 为什么它有效

 不变的是，在每个前缀处，贪婪过程由当前剩余资金和强制购买的顺序唯一确定。 任何有效的初始资金都必须引发相同的一组“必须购买”决策，直到进行第​​ m 次购买为止。 由于每个前缀的可承受性过程都是单调的，因此我们无法避免购买或跳过的最早点确定了确定可行性的边界。 最大化初始资金相当于将这个边界推得尽可能远，同时仍然尊重精确的约束`m`成功购买。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # We simulate feasibility of getting exactly m purchases
        cnt = 0
        last_take = -1

        # greedy: assume infinite money, track structure
        for i, x in enumerate(a):
            if cnt < m:
                cnt += 1
                last_take = i

        # if even infinite money doesn't match m
        # actually infinite money always buys all n
        if m > n:
            print("Impossible")
            continue

        if m == n:
            # must buy all, so initial money must be at least max prefix sum logic
            print("Richman")
            continue

        # compute minimal required money to ensure we can take m items
        # interpret as taking first m items (since order is fixed)
        need = sum(a[:m])

        # check if we can skip later items consistently
        # if any later item is 0, infinite money still forces buying it
        # so impossible to stop at m if there exists zero after m
        possible = True
        for i in range(m, n):
            if a[i] == 0:
                possible = False
                break

        if not possible:
            print("Impossible")
        else:
            print(need)

if __name__ == "__main__":
    solve()
```该代码遵循简化的重构思想。 第一个的前缀和`m`items代表保证购买至少所需的最低金额`m`书籍按顺序排列。 后缀检查确保零价书籍不会在购买后强制购买`m`-th 位置，这将打破完全停止在`m`。 

边缘处理`m = n`是直接的，因为只要有足够的钱，每本书都会被购买，并且初始资金没有上限会改变结果结构，从而导致“富人”案例。 

一个微妙的实现点是我们从不尝试模拟任意的货币价值。 所有推理都归结为强制购买的结构性限制。

 ## 边缘情况

 当`m = 0`，该算法有效地检查是否可以避免任何购买。 如果第一本书的价格为零，即使初始资金为零也会导致立即购买，因此实现零购买是不可能的。 对于严格的正价格，从零开始会导致所有书籍被跳过，这恰好实现了零购买，如果允许购买，任何更大的钱都可能会打破这一点。 

什么时候`m = n`，每一本书都必须买。 由于可用资金的过程是单调的，任何足够大的初始值都会导致购买所有书籍，并且不存在可以强制有限最大值的约束，从而产生“Richman”。 

当第一本之后出现零价书籍时`m`位置，贪婪的过程不能被迫提前停止，因为这些书总是负担得起的，所以任何试图准确结束`m`无论初始资金多少，购买都会失败。
