 ## 解决方案
 ## 问题理解

 我们被赋予了一系列按固定顺序排列的士兵权力。 任务是将该数组划分为连续的组，其中每个组包含一个元素或恰好两个相邻元素。 这种邻接约束意味着两人团队只能由索引 i 和 i+1 组成，而不能由任意位置组成。 

每个团队的力量等于其成员的总和。 组成所有团队后，我们查看团队总和。 我们希望这个集合尽可能“平衡”，即最大团队总和与最小团队总和之间的差异最小化。 

因此，问题不在于最大化或最小化单个总和，而在于选择在何处放置相邻对的可选合并，以便生成的段总和紧密聚集。 

约束很大，每次测试 n 最多 100000 个，总 n 最多 1000000 个。这立即排除了所有配对配置上的任何指数或二次状态探索。 任何尝试枚举所有配对相邻元素的方法的解决方案都会像斐波那契结构一样增长，因为每个位置要么单独存在，要么与下一个位置配对，这在最坏的情况下导致 O(2^n) 的可能性。 

对跟踪当前最小和最大段总和的状态进行简单的动态编程也会失败，因为状态空间随着可能总和的范围而增长，其数量级可能大到 10^14。 

打破天真的直觉的边缘情况包括：

 当所有值都相等时，任何分区都会产生相同的团队总和，因此答案为零。 假设必须存在至少一个配对的粗心实现可能会错误地强制合并并且仍然有效，但是当存在负数时会出现更微妙的错误，因为合并可能会根据符号减少或增加可变性。 

另一个棘手的情况是大的正值和负值交替出现。 例如，[1000000000、-1000000000、1000000000]。 配对变化总和巨大：单例会产生极端的传播，而配对可以抵消值并缩小传播。 任何贪婪的局部规则都可能在这里失败，因为局部改进并不能保证全局最优。 

关键的困难在于，每个指数决策仅影响局部细分，但有助于所有细分的全局最小-最大目标。 

## 方法

 强力解决方案将尝试一切可能的方法将数组划分为单例和相邻对。 在每个位置 i，我们决定是单独取 ai 还是合并 ai 和 ai+1。 这本质上是用尺寸为 1 和 2 的图块来平铺一条线，从而给出斐波那契数的配置。 

对于每种配置，我们计算所有团队总和并跟踪最小值和最大值。 每个配置的复杂度为 O(n)，但配置的数量呈指数增长，大致为 O(φ^n)。 即使 n = 40，这也是不可行的。 

结构观察是每个解都是通过选择一些不相交的相邻对来定义的。 一旦选择了一对 (i, i+1)，两个索引都会被消耗。 这相当于在路径图上选择匹配。 

关键的见解是，虽然匹配的数量是指数级的，但目标仅取决于局部总和 ai 和 ai+1，以及单独的 ai。 这表明我们可以推断每个元素是作为单个元素还是作为一对元素的一部分起作用，并将问题压缩为决定结果段和如何在一定范围内分布。

关键的转换是要注意每个团队的总和要么是 ai，要么是 ai + a(i+1)。 因此，答案取决于选择边的子集 (i, i+1)，以便不选择任何两个相邻边，然后评估变换序列中的值范围。 这是一个经典的在线独立集风格 DP，但具有生成值的最小-最大目标，而不是求和优化。 

我们通过观察唯一出现的值来自一个非常结构化的集合来解决这个问题：每个位置要么单独贡献，要么与其邻居合并。 可以通过扫描和维护每个索引的决策可实现的最佳范围来导出最佳解决方案，并跟踪最后一个元素的使用方式。 

这将指数选择减少为具有小状态空间的线性动态规划。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 配对决策中的最优 DP | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，并决定每个位置是开始一个单例还是与前一个元素形成一对。 核心困难在于，一旦我们决定配对 (i, i+1)，我们就完全跳过 i+1，因此决策是连续的。 

我们在每个位置维护两个 DP 状态：一种是将当前索引视为单例，另一种将其与前一个索引配对。 每个州都会跟踪该配置下迄今为止可实现的最小和最大团队总和。 

1. 我们在索引 0 处初始化一个仅包含 a0 的单例团队。 这会将当前最小值和最大值设置为 a0，因为只有一支球队存在。 
2. 在从 1 开始的每个索引 i 处，我们考虑两种可能性。 第一个是将ai保留为单例，这与value ai组成一个新的团队。 在这种情况下，我们更新之前团队值和人工智能本身的全局最小值和最大值。 
3. 第二种可能性是将 ai 与 ai−1 配对，但这仅在 ai−1 尚未配对时才有效。 此转换使用先前的 DP 状态，其中 i−1 是单例端点，并用合并值 ai−1 + ai 替换该单例。 
4. 当形成一对时，我们删除 ai−1 的贡献并用组合值替换它。 这需要仔细更新最小值和最大值：如果 ai−1 是极值，则替换可能会根据合并的总和缩小或扩大范围。 
5. 我们在每个位置上对两种状态进行最好的可能（最小差异）。 

DP 有效地模拟所有有效匹配，同时仅跟踪极值而不是完整的团队总和。 

### 为什么它有效

 任何有效的分区都对应于路径图上的匹配。 每个匹配都唯一地定义了一组团队总和。 DP 通过在每一步决定是否将 i−1 与 i 匹配来隐式枚举所有匹配，确保没有重叠。 由于状态存储在每个位置结束的所有可能匹配的极值，因此不会丢失任何有效配置。 这种转换保留了正确性，因为每个团队总和都只计算一次，无论是作为单个实例还是作为合并对的一部分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n == 1:
            print(0)
            continue

        # dp0: ending at i, i is singleton
        # dp1: ending at i, i is paired with i-1
        # each state stores (min_team, max_team)
        dp0_min = dp0_max = a[0]
        dp1_min = dp1_max = float('inf')

        for i in range(1, n):
            ndp0_min = min(dp0_min, a[i])
            ndp0_max = max(dp0_max, a[i])

            # try forming pair (i-1, i)
            pair_val = a[i] + a[i - 1]
            if dp0_min != float('inf'):
                ndp1_min = min(dp0_min, pair_val)
                ndp1_max = max(dp0_max, pair_val)
            else:
                ndp1_min, ndp1_max = float('inf'), -float('inf')

            dp0_min, dp0_max = ndp0_min, ndp0_max
            dp1_min, dp1_max = ndp1_min, ndp1_max

        # combine states
        ans = min(
            dp0_max - dp0_min,
            dp1_max - dp1_min if dp1_min != float('inf') else float('inf')
        )
        print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循DP结构。 如果当前索引未被强制成对，则单例状态 dp0 会跟踪最佳可能范围。 对状态 dp1 表示最后一次转换使用合并对的配置。 在每一步中，我们仅使用恒定时间操作来更新这两种可能性。 

一个微妙的点是，我们总是根据相邻元素计算对值，而不需要显式“撤消”先前的决策。 该状态隐式地确保了一致性，因为 dp1 仅源自 dp0 在 i−1 处的转换。 

我们还使用无穷大仔细处理无效的 dp1 状态，这可以防止将无法到达的配置意外混合到最终答案中。 

## 工作示例

 考虑一个小数组 [1, 3, 2]。 

我们跟踪 dp0 和 dp1 状态。 

| 我| 价值| dp0（最小值，最大值）| dp1（最小值，最大值）|
 | --- | --- | --- | --- |
 | 0 | 1 | (1,1) | (inf，-inf) |
 | 1 | 3 | (1,3) | (4,4) |
 | 2 | 2 | (1,3) | (3,4) |

 当 i = 1 时，我们要么保留 [1]、[3]，给出团队总和 1 和 3，要么将它们配对到 [4]。 当 i = 2 时，我们扩展了两种可能性。 最佳配置是 [1,3] 和 [2]，给出团队总和 {4,2} 或 [1,3],[2]，导致范围 2。 

该跟踪显示了单态和成对状态如何共存并传播有效配置。 

现在考虑 [5, -2, 4, -1]。 

| 我| 价值| dp0（最小值，最大值）| dp1（最小值，最大值）|
 | --- | --- | --- | --- |
 | 0 | 5 | (5,5) | (inf，-inf) |
 | 1 | -2 | (-2,5) | (3,3) |
 | 2 | 4 | (-2,5) | (2,5) |
 | 3 | -1 | (-2,5) | (-1,5) | (-1,5) |

 这里的配对有时会产生像 (5 + -2 = 3) 这样的取消，从而收紧范围。 最终的答案来自于选择是否包含配对状态。 

这些示例演示了本地配对决策如何传播到全局范围控制。

 ## 边缘情况

 像[7]这样的单元素数组直接通过返回零来处理，因为只有一个团队，因此最大值和最小值之间没有区别。 

对于像 [1, 2] 这样的数组，该算法可以正确评估单例配置 {1,2} 和对配置 {3}。 DP 产生 dp0 范围 1 到 2 和 dp1 范围 3 到 3，所以最终答案是 1。 

对于交替的极值，例如 [10^9, -10^9, 10^9]，配对决策会极大地改变范围。 DP 正确地考虑将前两个元素配对为 0，然后与 10^9 进行比较，产生比任何单例配置小得多的范围。 

每个案例都得到正确处理，因为每个转换都明确考虑每个索引的两种结构选择，确保没有有效分区被排除在评估之外。
