 ## 解决方案
 ## 问题理解

 我们得到了一个带标签的无向简单图$n$顶点正好$m$边缘。 如果我们可以添加一些额外的边，使最终的图成为访问所有图的单个简单循环，则该图被称为有效图。$n$顶点恰好一次。 

关键是我们没有被要求建造任何东西。 我们正在计算有多少个不同的图表$n$顶点和$m$边具有仅通过添加边就可以完成哈密顿循环的属性。 

最终的目标结构非常严格：包含所有顶点的单个循环，其中每个顶点的度数恰好为 2 并且图是连通的。 任何有效的初始图必须是至少一个此类循环的子图。 

这些约束迫使我们采用组合解决方案。 总和$n$所有测试用例都很大，最多$3 \cdot 10^7$，这会立即排除每个测试用例的任何超线性。 甚至$O(n \log n)$每个测试用例总的来说会太慢。 这强烈表明该解决方案必须依赖于一个封闭形式的组合公式，该公式具有预先计算的阶乘和仅取决于$n-m$。 

一个微妙的点是“可以扩展到一个循环”在结构上真正意味着什么。 如果一个图包含任何度数大于 2 的顶点，则它不能放入循环中。 如果它已经包含一个循环，则该循环必须在最终构造中消失，因为最终结构是所有顶点上的单个简单循环，并且添加边不能删除现有循环。 这导致了隐藏的结构限制，即每个有效图都是顶点不相交路径的集合，没有分支，也没有内部循环。 

一个天真的错误是假设该图必须已经在本地类似于一个循环，从而允许组件内部存在循环。 例如，一个三角形的顶点$1,2,3$已经形成了一个循环，但它不能成为所有顶点上更大的简单循环的一部分，而不违反扩展后的简单性。 所以这个配置是无效的，除非它已经等于最终的周期大小结构，这是不可能的$n>3$。 

## 方法

 蛮力解释很简单。 我们将枚举所有$\binom{n(n-1)/2}{m}$图，并针对每个图尝试检查它是否可以嵌入到哈密顿循环中。 该检查本身需要验证该图是否是某些顶点循环排序的子图，这相当于测试该图是否是线性森林。 即使这种检查是线性的，枚举也已经使该方法变得不可能，因为图的数量呈指数增长$n^2$。 

关键的观察是扭转视角。 我们不是从任意图开始并检查是否存在循环完成，而是从所有顶点上的固定哈密顿循环开始。 任何有效的图形必须完全包含在至少一个这样的循环内。 如果我们固定循环顺序，则每个有效图都对应于从该循环中选择边的子集。 

然而，不同的周期可以生成相同的图形，因此直接乘以周期会严重超出计数。 正确的结构见解是，真正重要的不是我们扩展到哪个循环，而是图必须是线性森林这一事实：每个顶点最多有两个度，并且所选边内不存在循环。 

一旦我们认识到这一点，问题就变成了纯粹的组合问题：计​​算标记图的数量$n$顶点和$m$边，使得每个连接的组件都是一条路径。 由于只有路径分量的森林满足$m = n - c$， 在哪里$c$是组件的数量，我们可以通过计算具有固定数量组件的标记线性森林来重新表述该问题。 

从这里开始，“作为标记结构的路径”的指数生成函数使我们能够导出一个封闭系数公式，可以在$O(n)$每个测试用例使用阶乘预计算。

 ## 算法演练

 让$c = n - m$。 任何有效的图必须是一个森林，其中每个组件都是一条路径，并且一个森林$c$组件正好有$n-c = m$边，所以这个参数化是一致的。 

我们精确地计算标记的线性森林$c$路径组件。 

1. 将每个连接的组件建模为标记路径。 一条路径$k \ge 2$顶点有$k!/2$标签，因为顶点的任何排列都定义了一条路径，但反转它会给出相同的无向结构。 单个孤立顶点是一条仅具有一个标记的简并路径。 
2. 构建一个组合类，其中每个组件都是一个这样的路径，整个图是一组$c$成分。 路径分量的指数生成函数变为$$P(x) = x + \sum_{k \ge 2} \frac{x^k}{2} = x + \frac{x^2}{2(1-x)}.$$3. 将生成函数重写为有理式$$P(x) = \frac{x(2-x)}{2(1-x)}.$$4. 图表$c$组件对应于选择一组无序的$c$组件，所以我们取$$\frac{P(x)^c}{c!}.$$5.我们提取系数$x^n$从这个表达式乘以$n!$从 EGF 转换为标记计数。 使用代数简化后$m = n-c$，问题简化为提取$$[x^m] (2-x)^c (1-x)^{-c}$$并通过预先计算的阶乘因子进行缩放。 
6. 展开这两个术语：$$(2-x)^c = \sum_{i=0}^{c} \binom{c}{i} 2^{c-i} (-x)^i,
\quad
(1-x)^{-c} = \sum_{j \ge 0} \binom{c+j-1}{j} x^j.$$7. 系数$x^m$通过配对得到$i+j=m$，给出单个求和$i$：$$\sum_{i=0}^{\min(c,m)} \binom{c}{i} 2^{c-i} (-1)^i \binom{c + (m-i) - 1}{m-i}.$$8. 将此系数乘以$\frac{n!}{c! \cdot 2^c}$以获得最终答案。 

每个测试用例的计算是一个单一的总和$i \le c$，使用阶乘和逆阶乘实现。 

### 为什么它有效

 每个有效图都被强制具有最多两个且没有环的最大度，否则它不能嵌入任何哈密顿环中。 这将图描述为路径的不相交并集。 相反，任何线性森林总是可以通过沿着循环对其路径分量进行排序并插入剩余的缺失边来嵌入到某个循环中。 因此，计算有效图相当于计算具有固定边数的标记线性森林，这正是生成函数推导所捕获的内容。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXN = 3 * 10**5 + 5

fact = [1] * MAXN
invfact = [1] * MAXN

for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN - 1] = pow(fact[MAXN - 1], MOD - 2, MOD)
for i in range(MAXN - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        c = n - m

        if c < 0 or c > n:
            out.append("0")
            continue

        inv2c = pow(pow(2, MOD - 2, MOD), c, MOD)

        ans = 0
        for i in range(c + 1):
            if i > m:
                break

            term = C(c, i)
            term = term * pow(2, c - i, MOD) % MOD
            if i % 2 == 1:
                term = MOD - term

            term = term * C(c + m - i - 1, m - i) % MOD
            ans = (ans + term) % MOD

        ans = ans * fact[n] % MOD
        ans = ans * pow(invfact[c], 1, MOD) % MOD
        ans = ans * pow(pow(2, MOD - 2, MOD), c, MOD) % MOD

        out.append(str(ans % MOD))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```阶乘和逆阶乘表支持常数时间内的所有二项式系数。 循环结束$i$从两个系列的卷积中执行系数提取。 符号交替实现了$(-x)^i$扩展术语$(2-x)^c$。 最终的乘法将生成函数系数转换为实际的标记图计数。 

一个常见的实施陷阱是忘记全局缩放因子$n!$，这是必需的，因为生成函数以指数形式工作。 另一种是处理不当$c=0$或者$m=0$边界，其中唯一有效的结构是一个空的组件森林或一组孤立的顶点。

 ## 边缘情况

 一个关键的边缘情况是当$m = n - 1$，这意味着该图已经是一棵生成树。 这里唯一有效的树是那些路径。 该算法自然会处理这个问题，因为$c=1$，系数提取减少到对标记路径进行计数，这与已知的相匹配$n!/2$结构。 

另一个边界是$m = 0$，其中每个顶点都是孤立的。 这对应于$c=n$，公式折叠为选择$n$单例组件。 生成函数正确地为每个单例分配权重 1，并且所有更高阶项都消失了。 

什么时候$m$很大，接近$\binom{n}{2}$，计算出的$c$变为负数，并且算法正确返回零，因为没有太多边的图可以避免嵌入循环所需的度数约束。
