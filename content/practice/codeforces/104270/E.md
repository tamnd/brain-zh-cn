 ## 解决方案
 ## 问题理解

 我们得到了一系列植物，索引从 1 到 n。 每个植物 i 都有固定的位置 i 和生长速率 a[i]。 最初，每株植物的防御价值为零。 机器人从位置 0 开始，即“房子”。 

机器人在整数线上执行最多 m 个单位的移动序列。 每一步要么向东一步，要么向西一步。 每次移动后，如果机器人恰好降落在某个植物的位置 i 上，则该植物立即获得 [i] 防御。 对同一工厂的多次访问会多次积累其价值。 

目标是设计最多 m 步的行走，以便在所有移动之后，所有植物之间的最小防御尽可能大。 

核心困难在于每个工厂必须“访问足够多的次数”，但访问是通过单个移动机器人间接产生的，受到总步数预算的限制。 

这些约束使我们远离任何显式路径模拟。 n 可以高达 100000，m 可以大到 10^12，因此答案仅取决于我们推断访问计数的效率，而不取决于逐步构建步行。 任何试图模拟运动或枚举路径的解决方案都是不可能的。 

当人们试图贪婪地在本地“平衡访问”时，就会出现一种微妙的失败案例。 例如，在单个工厂附近交替东向和西向对该工厂的帮助并不比精心计划的回溯策略（在多个工厂之间重复利用移动成本）更好。 相邻位置之间的耦合是全局的，而不是局部的。 

另一个陷阱是假设每个工厂都需要与其指数成比例的独立旅行成本。 由于机器人可能会超程并返回，因此一次扫描可以在多个工厂之间共享访问，因此简单的距离计算会高估成本。 

## 方法

 强力解释将尝试枚举长度最多为 m 的所有行走，并计算每个植物的最终访问计数。 这原则上是正确的，因为每个有效序列都会被考虑。 然而，分支因子为每步 2，因此序列数为 2^m，即使 m = 50，这也是完全不可行的。 

即使我们将注意力限制在计算每个位置被访问的次数上，结构仍然很复杂，因为具有相同步数的不同路径可能会产生不同的访问分布。 

关键的观察是扭转视角：我们不考虑产生访问的路径，而是问每个植物必须被访问多少次才能实现目标最小防御值 x。 由于每次访问工厂 i 都会贡献 a[i]，因此工厂 i 必须至少被访问 ceil(x / a[i]) 次。 

现在问题变成：给定所需的访问次数c[i]，我们是否可以设计一条长度至多为m的游走，并且访问每个位置i至少c[i]次？ 

线上的机器人运动结构具有很强的单调性：一旦我们决定覆盖从 1 到 k 的段，我们就可以将运动组织为对前缀的重复扫描。 从 0 到 k 以及返回的每次完整扫描都会花费 2k 步，并且每次扫描都会访问该范围内的每个位置两次（一次在出去，一次在返回），取决于奇偶校验的端点除外。 

这降低了前缀贡献上的贪婪打包问题的可行性。 我们从左到右累积所需的访问次数，并跟踪需要对前缀进行多少次完整遍历才能满足每个位置的需求。 每当某个职位需要的访问次数多于之前扫描当前提供的访问次数时，我们就会扩大范围并支付与扩展范围成比例的额外费用。 

该结构是单调的，因此我们可以通过二分搜索计算最大可行x。 每个可行性检查都与 n 呈线性关系。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^m·n) | O(2^m·n) | O(n) | 太慢了 |
 | 可行性+二分查找| O(n log m) | O(n log m) | O(n) | 已接受 |

 ## 算法演练

 我们想要测试候选的最小防御值 x 是否可以实现。 

1. 将 x 转换为每株植物的需求量 c[i] = (x + a[i] - 1) // a[i]。 这代表工厂 i 必须被访问多少次。 
2. 从左到右扫描工厂，维护先前付费的前缀完整遍历已经“保证”的访问次数。 我们维护一个变量 cur 来表示重复扫描的累积覆盖范围。 
3. 在位置 i，如果 cur < c[i]，我们必须将工作范围扩展到 i。 每个扩展允许我们对 [1, i] 执行额外的全面扫描，每个扩展对该范围内的每个位置贡献 2 次访问。 
4. i 处需要的额外扫描次数为 (c[i] - cur + 1) // 2，因为每次扫描都会增加两次访问。 我们将其添加到总扫描的运行计数中，并通过添加 2 倍扫描次数来相应地更新 cur。 
5. 如果在任何时候这些扫描所隐含的总移动成本超过 m，则候选 x 是不可行的。 
6. 在 [0, max(a[i]) * m] 范围内二分搜索 x，每次检查可行性。 

关键的想法是，一旦我们致力于达到位置 i，我们就不再需要单独处理之前的位置。 所有早期的要求都已被相同的扫描覆盖，因此该过程是单调且贪婪的。 

### 为什么它有效

 正确性依赖于最佳移动可以分解为完整的前缀扫描这一事实。 线路上的任何行走都可以重新安排，而不会减少访问次数，以便以结构化的方式来回扫描前缀来进行访问。 这种变换不会减少覆盖范围，因为边缘的每次交叉对相邻前缀覆盖范围的贡献相等，并且不必要的绕行可以被压缩为重复的最大偏移。 这导致了单调覆盖模型，其中只有前缀扩展决策很重要，并且贪婪规则确保每个缺陷点的扫描次数最少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(x, a, m):
    n = len(a)
    cur = 0
    cost = 0

    for i in range(n):
        need = (x + a[i] - 1) // a[i]
        if cur < need:
            add = need - cur
            # each sweep gives 2 visits per position in range
            sweeps = (add + 1) // 2
            cost += sweeps * 2 * (i + 1)
            cur += sweeps * 2

        if cost > m:
            return False

    return cost <= m

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 0, max(a) * m
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, a, m):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```功能`can`模拟是否可以实现目标最低防御。 变量`cur`跟踪每个位置从先前决定的全面扫描中已经有效接收的访问次数。 当我们到达位置 i 时，我们计算它需要多少次访问，并在当前覆盖范围不足时添加额外的扫描。 每次扫描前缀 [1, i] 都会花费 2*(i+1) 步，因为机器人必须从房子走到 i 并返回。 

二分搜索是必要的，因为可行性在 x 中是单调的：如果我们能够实现某个最小防御，那么任何较小的值也是可以实现的。 

一个常见的实施错误是忘记由于向前和向后传递，每次扫描都会对每个位置贡献两次访问，而不是一次。 

## 工作示例

 考虑一个小实例 a = [3, 2, 6]，m = 30，并测试 x = 6。 

我们计算所需的访问次数 c = [2, 3, 1]。 我们从左到右处理。 

| 我| 一个[我] | c[i] | 之前 | 当前 赤字| 扫荡| 后| 成本|
 | ---| ---| ---| ---| ---| ---| ---| ---|
 | 1 | 3 | 2 | 0 | 2 | 1 | 2 | 4 |
 | 2 | 2 | 3 | 2 | 1 | 1 | 4 | 12 | 12
 | 3 | 6 | 1 | 4 | 0 | 0 | 4 | 12 | 12

 处理后，cost=12≤30，所以x=6是可行的。 

此跟踪显示了覆盖率如何跨前缀累积。 第二个位置不重置结构，它仅检查现有扫描是否足够。 

现在考虑一个更严格的实例 a = [5, 5], m = 8, x = 10。 

c = [2, 2]。 

| 我| c[i] | 当前| 赤字| 扫荡| 成本|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 2 | 0 | 2 | 1 | 4 |
 | 2 | 2 | 2 | 0 | 0 | 4 |

 我们无法承担在位置 2 进行另一次扫描，因为成本将超过 m，因此可行性取决于前缀重用。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log (最大 a[i] * m)) | 每个可行性检查都是线性的，我们对答案范围进行二分搜索 |
 | 空间| O(1) 额外 | 除了输入存储之外，仅维护少数计数器 |

 这些约束允许每次测试最多使用 10^5 个元素，跨测试总共允许使用 10^6 个元素，因此使用对数搜索进行线性检查完全在限制范围内。

 ## 边缘情况

 m = 0 的零移动场景迫使所有植物保持零防御，无论生长速度如何。 该算法处理这个问题是因为二分查找只接受 x = 0； 任何正 x 都会立即失败，因为所需的访问次数不为零。 

与其他植物相比，一种植物具有极大的 a[i] 的情况突出了整数除法行为。 由于该工厂所需的访问量很小，因此该算法可以避免过度分配扫描，并且前缀重用可以正确地提供来自早期扩展的访问量。 

严格递增的 a[i] 序列强调前缀扩展。 每个位置都可能引入新的扫掠要求，而贪婪的积累确保我们只在必要时进行扩张。
