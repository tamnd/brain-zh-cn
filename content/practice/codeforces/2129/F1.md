 ## 解决方案
 ## 问题理解

 我们被要求恢复从 1 到 1 的数字的隐藏排列$n$通过一组有限的交互式查询。 每个查询都会从选定的索引子集中返回最大元素或其位置，挑战是在遵守严格查询限制的同时重建排列。 

简单版本上限$n$845，这意味着如果我们想将查询总数控制在 30 个以下，就不能简单地单独查询每个位置。 类型 3 和类型 4 查询可以覆盖数组的大块，但只允许一个这样的查询。 Type-1 和 type-2 查询最多返回 60 个元素，如果满足以下条件，则需要仔细批处理$n$超过60。 

当排列在开始或结束时具有局部最大值时，就会出现边缘情况。 例如，如果$p = [845, 1, 2, ..., 844]$，忽略极端值的简单查询可能会错过最大的元素。 另一个微妙之处是 type-2 和 type-4 返回数字的位置，而不是数字本身，因此混淆这两者会产生不正确的重建。 

## 方法

 暴力方法将使用 type-1 单独查询每个位置以获得准确的值。 这是有效的，因为每个查询都会返回单个元素，为我们提供索引和值之间的完整映射。 然而，这会消耗$n$查询数，最多可达 845 个。这超出了 30 个查询的限制，因此不切实际。 

关键的观察结果是排列具有唯一的最大值，并且查询返回子集中的最大元素。 这允许采用分而治之的策略。 我们可以使用 type-3 查询来询问整个数组中最大的元素，它会立即识别$n$及其位置。 一旦我们知道最大值的位置，我们就可以重复查询不包括已知最大值的子集以找到下一个最大元素。 这将问题简化为使用返回顶部元素的查询逐一或批量识别元素，但查询次数不超过 30 个。 

我们还可以利用 2 类查询来确定元素的确切位置，而无需单独查询它们。 通过系统地分割未知位置并结合 top-k 结果，我们可以有效地重建排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) 次查询 | O(n) | 查询太多 |
 | Top-K 分而治之 | O(n) 次操作，≤30 个查询 | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个数组`pos`尺寸的$n+1$存储每个数字的位置。 所有条目均以未知开头。 
2. 对从 1 到 的整个索引集发出类型 3 查询$n$。 这将返回顶部$k = \min(300, n)$数字。 此响应中最大的数字是$n$，它在指数中的位置告诉我们`pos[n]`。 
3. 标记位置$n$如被占用。 在后续查询下一个最大元素时，不会考虑该位置。 
4. 虽然有些数字的位置未知，但选择剩余未分配索引的子集。 对此子集发出类型 1 查询。 查询最多返回 60 个最大的数字。 记录尚未分配位置的最大数，并将其在子集中的位置分配给中的对应值`pos`。 
5. 重复步骤4，直到所有位置都在`pos`已满。 该循环确保每个查询在不超出查询限制的情况下最大化发现的新位置的数量。 
6. 放置完所有数字后，进行转换`pos`进入排列`p`将每个数字放置在其确定的位置。 输出`! p_1 p_2 ... p_n`。 

为什么它有效：该算法保持一个不变量`pos`总是正确地将已知数字映射到它们的位置。 通过始终查询未分配子集中的最大剩余数字，不会将任何数字分配到错误的位置，并且 top-k 保证确保我们永远不会错过子集中的最大值。 每一步都会严格减少未知数的数量，直到排列完成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(qtype, indices):
    print(qtype, len(indices), *indices)
    sys.stdout.flush()
    return list(map(int, input().split()))

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        pos = [0] * (n + 1)
        unknown = set(range(1, n + 1))
        # find the largest number n and its position
        top_vals = query(3, list(range(1, n + 1)))
        largest = max(top_vals)
        idx = top_vals.index(largest)
        pos[largest] = idx + 1
        unknown.remove(idx + 1)

        remaining = n - 1
        while remaining > 0:
            batch = list(unknown)[:60]
            response = query(1, batch)
            for val in response[::-1]:
                if val not in pos or pos[val] == 0:
                    pos[val] = batch[response.index(val)]
                    unknown.remove(pos[val])
                    remaining -= 1

        # build permutation p
        p = [0] * n
        for i in range(1, n + 1):
            p[pos[i]-1] = i
        print('!', *p)
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该代码遵循以下算法：首先找到全局最大值，然后迭代查询子集以按值递减的顺序发现剩余的数字。 我们反转响应以确保首先分配最大的数字，这保留了不变量。 使用切片`unknown`确保我们永远不会超过类型 1 查询的 60 个元素限制。 通过将位置映射到值来重建排列。

 ## 边缘情况

 对于最大值位于开始处的排列，`p = [n, 1, 2, ..., n-1]`，第一个类型 3 查询发现`n`正确。 后续类型 1 查询从剩余索引中分配数字。 每个步骤都遵循前 60 名约束并正确填充位置。 输出与预期的排列相匹配。 

为了`n`正好 60，单个类型 3 查询足以获取所有值。 该算法通过首先返回正确的最大值，然后使用单个类型 1 查询填充剩余位置来处理此问题。
