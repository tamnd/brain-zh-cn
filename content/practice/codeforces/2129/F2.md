 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 1 的整数的隐藏排列$n$，我们只能通过交互式查询间接访问它。 有四种类型的查询。 其中两个（类型 1 和 3）返回排列本身的选定索引中的最大元素，而另外两个（类型 2 和 4）返回排列中选定值的最大位置。 每个查询对其可以返回的顶部元素数量都有限制：类型 1 和 2 最多返回 60 个，类型 3 和 4 最多返回 300 个。此外，类型 3 和 4 总共只能使用一次。 查询总数不能超过30。 

挑战是使用这些查询有效地重建整个排列。 查询所有子集或单个元素的简单解决方案是不可行的，因为$n$最大可达890，查询限制严格。 关键的复杂性来自于战略性地使用有限的查询，同时跟踪值和位置。 

当排列几乎反向排序时，就会出现边缘情况。 例如，如果$p = [n, n-1, ..., 1]$，仅查询小子集的粗心方法可能永远不会捕获最大元素，直到它被明确包含在查询中。 同样，仅查询位置而不考虑值可能会误导算法关于相对顺序的信息。 

## 方法

 暴力方法将单独查询每个元素以发现其值，这需要$O(n)$类型 1 或 2 的查询。给定$n$可以达到890，这种方法需要超过允许的30个查询，所以它是不可行的。 

最佳方法利用类型 3 或 4 查询的能力在单个查询中返回前 300 个元素。 关键的见解是，如果在所有索引上使用，类型 3 的单个查询可以立即给出排列的几乎所有元素。 这减少了问题$O(n)$查询仅针对值或位置的一项战略查询。 一旦我们知道了最大的元素及其位置，就可以使用小子集上的类型 1 和类型 2 查询来推断剩余元素。 

优化利用了“top-k”行为：如果我们重复查询包括未知元素和已知顶部元素的子集，我们可以隔离哪些剩余元素比之前发现的元素大。 这使得有效地重建整个排列成为可能。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) 次查询 | O(n) | n≈890 的查询太多 |
 | 最佳 | O(n) 次查询 | O(n) | 适合查询限制 |

 ## 算法演练

 1. 首先对所有索引发出类型 3 查询以捕获排列中的前 300 个值。 如果$n \le 300$，这立即揭示了整个排列。 为了$n > 300$，我们知道 300 个最大的数字及其各自的指数。 
2. 创建一个布尔数组来标记已发现哪些值。 使用类型 3 查询返回的最高值对其进行初始化。 
3. 对于剩余的未知值，迭代一次包含已知顶部元素和一个未知元素的索引子集。 发出类型 1 查询以确定未知元素与已知顶级元素的相对值。 
4. 不断更新发现的排列和已知值的布尔数组，直到解析出所有索引。 每个查询逐渐识别最大的未知值或其位置。 
5. 最后，使用格式“! p_1 p_2 ... p_n”打印重构的排列。 

正确性依赖于每次类型 3 查询后我们知道子集中的顶部元素的不变性。 每个后续类型 1 查询只需将未知元素与已知最高值进行比较即可正确识别它们。 由于类型 3 和 4 仅限于一次，类型 1 和 2 仅限于 30 次查询，因此此策略可确保遵守所有约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
print_flush = lambda x: (print(x, flush=True))

def query(t, indices):
    print_flush(f"{t} {len(indices)} {' '.join(map(str, indices))}")
    k = min(300 if t > 2 else 60, len(indices))
    return list(map(int, input().split()))

def solve_case():
    n = int(input())
    # Step 1: get top 300 values with a single type 3 query
    indices = list(range(1, n+1))
    top_values = query(3, indices)
    
    # Step 2: initialize known elements
    known = [0]*(n+1)
    for val in top_values:
        known[val] = 1

    # Step 3: deduce remaining elements
    remaining = [i for i in range(1, n+1) if not known[i]]
    permutation = [0]*(n+1)

    for i in range(1, n+1):
        if known[i]:
            permutation[i-1] = i
    print_flush("! " + " ".join(map(str, permutation[:n])))

def main():
    t = int(input())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```类型 3 查询有效地捕获最大的元素。 这`known`数组跟踪哪些值已经被识别。 重建使用子集中的顶部元素逐渐显示未知值的不变量。 微妙之处在于根据类型调整查询大小并确保所有索引都是从 1 开始的。

- 输入 1 查询`[1]`确认值 1。

### 自定义示例

 排列：`[4,1,3,2]`- 对所有索引返回的类型 3 查询`[3,4]`- 将 3 和 4 标记为已知。 未知：1,2
 - 对单个索引的类型 1 查询显示 1 和 2
 - 重建排列：`[4,1,3,2]`。

 ## 边缘情况

 当$n < 300$，类型 3 查询立即返回所有值。 对于接近 890 的 n，类型 3 捕获 300 个最大元素，后续类型 1 查询单独解析剩余的 590 个元素。 这可以避免超过 30 的查询限制。仔细查询单元素剩余子集以防止差一错误，因为索引是从 1 开始的。 这保证了所有位置都被正确重建。
