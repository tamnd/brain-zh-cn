 ## 解决方案
 ## 问题理解

 这个问题要求我们通过关闭尽可能少的门来阻止黄色穿过网格。 网格包含始终被阻挡的墙壁、始终打开的走廊以及可以打开或关闭的门。 黄色从左上角的单元格开始，想要到达右下角的单元格。 我们需要找到关闭导致目的地无法到达的最少门数。 如果仅走廊已经给出了一条路径，冒名顶替者就无法阻止黄色，所以答案是`-1`。 官方问题描述了这个带有行、列、墙、门和走廊的网格分离任务。 

网格最多可以有 1000 行和 1000 列，这意味着最多可以有 100 万个单元格。 任何显式尝试许多路径的算法都会太慢，因为可能的路径数量呈指数增长。 即使处理每对细胞的算法也已经太昂贵了。 我们需要一种只接触每个单元少量次数的方法，这指向具有近线性复杂度的图算法。 

主要棘手的案件来自非普通开放空间的牢房。 起始单元和结束单元本身可以是门。 粗心的解决方案可能会假设它们总是可访问的，而忽略了关闭其中任何一个都会立即阻止黄色。 例如：```
2 2
..
.@
```正确答案是`1`。 关闭起始门就足够了，但是仅考虑起始点和结束点之间的门的解决方案会错误地输出更大的值。 

另一种边缘情况是路径仅包含走廊。 由于走廊无法关闭，因此任何门都无法断开两个端点的连接。```
2 2
@@
@@
```正确答案是`-1`。 仅计算一条已发现路径上的门的最短路径搜索可能会错误地输出`0`，尽管另一条走廊路径仍然存在。 

最后一个微妙的情况是答案为零，因为墙壁已经将端点分开。```
3 3
@#.
###
.@.
```正确答案是`0`。 该算法必须允许最小割完全不包含门。 

## 方法

 自然的暴力方法是考虑要关闭的门的每个可能的子集。 对于每个子集，我们可以从一开始就运行洪水填充并检查目的地是否仍然可达。 这是正确的，因为每种可能的阻挡门的方式都经过测试，但子集的数量是`2^D`， 在哪里`D`是门的数量。 有数十万种可能的门，这是不可能的。 

关键的观察是，这实际上并不是一个寻路问题。 我们不是在寻找黄色的路线。 我们正在寻找最小的一组可移动障碍物，其移除将两个位置分开。 这正是最小割的定义。 

网格可以转化为流网络。 每个单元格都成为一个图节点，并且在相邻单元格之间移动成为无限容量的边。 墙壁被简单地省略了。 走廊具有无限的容量，因为它们无法被堵塞。 门的容量为一，因为穿过这样的单元就代表恰好关闭一扇门。 

剩下的挑战是标准最小割算法在边缘上工作，而成本属于单元。 这是通过节点分裂来解决的。 每个单元变成两个节点：入口节点和出口节点。 从入口到出口的边缘承担着移除该单元的成本。 移动边缘从一个单元的出口侧到具有无限容量的相邻单元的入口侧。 最低限度`s-t`cut 然后选择要切割的单元边缘，它们的容量之和正是关闭的门的数量。 

由于网格包含多达一百万个单元，因此我们需要高效的最大流实现。 Dinic 的算法在这里效果很好，因为图很稀疏。 每个单元仅创建恒定数量的边，因此网络保持可管理性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^D * (R*C)) | O(2^D * (R*C)) | O(R*C) | 太慢了 |
 | 最佳| Dinic 的 O(V^2E) 最坏情况，在这个稀疏网格上实用 | O(R*C) | 已接受 |

 ## 算法演练

 1. 将每个非壁单元转换为两个图节点，一个入口节点和一个出口节点。 从入口到出口添加一条边。 其容量为`1`代表门，无穷大代表走廊。 仔细选择源和目的地，因为起始单元和结束单元也可能是门。 
2. 对于每对相邻的非壁单元，添加一条从第一个单元的出口节点到第二个容量无限的单元的入口节点的有向边。 也添加相反的方向。 这代表黄色能够在相邻单元格中双向移动。 
3. 从起始端到目的端运行最大流算法。 根据最大流最小割定理，该流的值等于分隔两侧的最便宜的边集的容量。 
4. 如果产生的流量值至少为无穷大，则意味着每个可能的分离都需要切割不可能的走廊边缘。 在这种情况下，答案是`-1`。 否则，流量值为必须关闭的门的最小数量。 

为什么它有效：图中唯一的有限容量边缘是门的入口到出口边缘。 任何有限切割都必须选择其中一些边，而不能选择走廊边。 切割门边缘恰好代表关闭那扇门。 任何阻挡黄色的门组都会创建相同成本的有效切割，并且任何有限切割都会创建一组有效的关闭的门。 因此，最小切割值恰好是所需的最小门数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.g[u].append([v, c, len(self.g[v])])
        self.g[v].append([u, 0, len(self.g[u]) - 1])

    def max_flow(self, s, t):
        flow = 0
        n = self.n
        INF = 10**9

        while True:
            level = [-1] * n
            level[s] = 0
            q = [s]
            for u in q:
                for v, c, _ in self.g[u]:
                    if c and level[v] == -1:
                        level[v] = level[u] + 1
                        q.append(v)

            if level[t] == -1:
                return flow

            it = [0] * n

            def dfs(u, pushed):
                if u == t:
                    return pushed
                while it[u] < len(self.g[u]):
                    e = self.g[u][it[u]]
                    v, c, rev = e
                    if c and level[v] == level[u] + 1:
                        tr = dfs(v, min(pushed, c))
                        if tr:
                            e[1] -= tr
                            self.g[v][rev][1] += tr
                            return tr
                    it[u] += 1
                return 0

            while True:
                pushed = dfs(s, INF)
                if not pushed:
                    break
                flow += pushed

def solve():
    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]

    total = r * c * 2
    dinic = Dinic(total)

    def inside(x, y):
        return 0 <= x < r and 0 <= y < c

    def node(x, y, out):
        return (x * c + y) * 2 + out

    INF = 10**8

    for i in range(r):
        for j in range(c):
            if grid[i][j] == '#':
                continue
            cap = 1 if grid[i][j] == '.' else INF
            dinic.add_edge(node(i, j, 0), node(i, j, 1), cap)

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    for i in range(r):
        for j in range(c):
            if grid[i][j] == '#':
                continue
            for dx, dy in dirs:
                ni, nj = i + dx, j + dy
                if inside(ni, nj) and grid[ni][nj] != '#':
                    dinic.add_edge(node(i, j, 1), node(ni, nj, 0), INF)

    source = node(0, 0, 0)
    sink = node(r - 1, c - 1, 1)

    ans = dinic.max_flow(source, sink)
    print(-1 if ans >= INF else ans)

if __name__ == "__main__":
    solve()
```图的构造直接遵循节点分裂的思想。 入口到出口边缘存储移除单元的成本，因此只有门对最终切割值有贡献。 走廊的容量非常大，因为有效的最小切割永远不应该选择移除它们。 

移动边添加在单元边缘之后，因为它们将一个单元的出口侧连接到另一个单元的入口侧。 该方向与 Yellow 已经进入和离开单元格后的状态相匹配。 两个方向都是需要的，因为允许在所有四个方向上移动。 

源使用第一个单元的入口侧，接收器使用最后一个单元的出口侧。 这处理任一端点是门的特殊情况。 如果源门或汇门是移除成本最低的东西，则流算法可以选择该边缘。 

用于无穷大的值只需大于最大可能答案。 由于答案不能超过单元格的数量，`10^8`是安全的大。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | Dinic 最坏情况为 O(V^2E) | 网格创建 O(R_C) 个节点和 O(R_C) 个边，稀疏结构在实践中表现良好 |
 | 空间| O(R*C) | 每个单元创建两个节点和恒定数量的边 |

 由于有 100 万个单元，图形很大，但输入大小仍然是线性的。 该实现避免将网格存储为具有不必要连接的图形，并使用邻接列表，从而将内存使用量保持在限制内。

 ## 边缘情况

 当起始单元是门时，源必须通过门的容量边缘连接。 为了：```
2 2
..
.@
```第一个单元的源极到出口边缘具有容量`1`。 最小切割可以立即移除该边缘，给出的流量值为`1`。 

当走廊形成不可避免的路径时，就不存在有限切口。 为了：```
2 2
@@
@@
```所有路线仅由无限容量的边组成。 Dinic 无法通过门边缘推动有限间隔，因为不存在门边缘，因此流量达到无穷大阈值并且算法输出`-1`。 

当墙壁已经断开网格时：```
3 3
@#.
###
.@.
```在构建的图中没有从源到接收器的路径。 Dinic 中的初始 BFS 无法到达接收器，因此最大流量保持为零，并且答案正确报告为`0`。
