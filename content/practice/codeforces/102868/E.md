 ## 解决方案
 # 问题理解

 任务是将无限网格上的点从一个格点移动到另一个格点。 一次移动恰好改变一个坐标一个单位，因此每次移动都是四个基本方向之一。 限制是同一方向不能连续使用两次。 例如，禁止连续两次向北移动，但向北、向东、向北移动是允许的。 

对于每个场景，我们都会得到该点的起始坐标和结束坐标。 所需的输出是在遵守方向限制的情况下所需的最小移动次数。 

坐标可以大到$10^{18}$，最多可以有 1000 个场景。 这立即排除了路径或图形搜索的任何模拟。 解决方案必须在每个测试用例中仅使用算术运算，因为即使迭代点之间的距离也可能需要最多$10^{18}$步骤。 

关键的困难在于曼哈顿最短路径并不总是有效。 正常的最短路径恰好使用所需数量的水平和垂直移动，但它可能连续包含太多一种类型的移动。 路径必须经常在水平和垂直移动之间交替。 

考虑一下这些因粗心实施而失败的情况。 

对于从$(0,0)$到$(5,0)$，曼哈顿距离为 5。简单的解决方案会输出 5，但这是不可能的，因为所有移动都是水平的。 正确答案是 10。一条有效路线是右、上、右、下、右、上、右、下、右、下。 

对于从$(0,0)$到$(2,1)$，曼哈顿距离为 3。这已经有效，因为两个水平移动可以通过垂直移动分开。 正确的输出是 3。当两个坐标均非零时总是增加额外弯路的方法会产生错误的答案。 

对于从$(1,1)$到$(1,1)$，答案为 0。不需要添加绕道，因为不需要移动。 

# 方法

 暴力的想法是在跟踪当前位置和先前方向的同时尝试逐步构建路径。 这正确地模拟了限制，因为每个状态都包含决定哪些动作合法所需的信息。 然而，网格是巨大的。 可能位置的数量随着坐标距离的增加而增加，并且对位置进行广度优先搜索或动态规划是不可能的。 当坐标位于周围时，即使是曼哈顿距离的简单模拟也会失败$10^{18}$。 

有用的观察是，实际方向一开始并不重要。 重要的是使用了多少水平移动和垂直移动。 任何有效的移动序列都必须在水平移动和垂直移动之间交替，除非一种类型可能比另一种类型在序列的两端出现多一次。 

假设所需的水平和垂直距离为$x$和$y$。 我们至少需要$x$水平移动并且至少$y$垂直移动。 额外的移动仅作为回溯对有用，因此轴的移动总数必须与其所需距离具有相同的奇偶性。 最初可能的最小计数是$x$和$y$。 如果它们的差异最多为1，那么它们就已经可以排列成交替序列了。 

当一根轴比一轴大时，较小的轴需要额外的移动才能充当分隔符。 由于额外的移动是成对出现的，因此我们将较小的计数增加最小偶数，使差值最多为 1。

 # 算法演练

 1. 计算起点和终点之间的绝对水平和垂直距离。 打电话给他们$x$和$y$。 只有距离很重要，因为无论我们向左或向右、向上或向下移动，相同的结构都会起作用。 
2.让`big`是较大的$x$和$y$，并让`small`成为另一个。 如果`big - small`至多为 1，曼哈顿路径已经与交替方向规则兼容，所以答案很简单`big + small`。 
3. 如果差值大于1，则增加`small`偶数。 添加的移动表示在较小的轴上来回移动。 我们选择最小的偶数加法，将两个移动计数之间的差异减少到最多 1。 
4. 返回新的总移动次数。 

这样做的原因是每条有效路径都可以被视为水平和垂直移动的交替序列。 在这样的序列中，一个类别不能在另一个类别之外多次出现。 该算法找到精确满足该条件所需的最少额外移动次数。 额外的移动仅成对添加，这保留了最终坐标，因此结果计数既可实现又最小。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a, b, c, d = map(int, input().split())

        x = abs(c - a)
        y = abs(d - b)

        big = max(x, y)
        small = min(x, y)

        diff = big - small
        if diff > 1:
            add = diff - 1
            if add % 2:
                add += 1
            small += add

        ans.append(str(big + small))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```程序首先将坐标变化转换为两个非负距离。 移动的迹象是无关紧要的，因为任何额外的移动总是一个回程。 

变量`big`和`small`表示解决交替问题之前每个轴所需的移动次数。 当较大轴的移动次数过多时，代码会按均匀量增加较小轴。 奇偶校验调整是必要的，因为额外的分隔符必须包含移走和移回，这总是添加两个移动。 

Python 整数处理$10^{18}$直接坐标范围，因此不需要溢出处理。 该实现不构造路径，从而保持运行时间和内存恒定。

 # 边缘情况

 当两点相同时，如输入：```
1
3 4 3 4
```距离是$x=0$和$y=0$。 差值为零，因此算法立即返回零。 它不会添加不必要的动作，因为不存在方向冲突。 

当运动仅存在于一个轴上时，例如：```
1
0 0 5 0
```初始计数是水平的$5$和垂直的$0$。 相差五，所以先加四纵，但数量必须是偶数。 四足以将差距缩小到一，并且因为较小的一方必须具有正确的奇偶性，所以还需要一对，给出五次垂直移动，最终答案为十。 

当两个轴的距离相似时，例如：```
1
0 0 3 2
```计数相差一，因此不需要额外的移动。 该算法返回五，并且移动可以按水平、垂直、水平、垂直、水平的顺序排列。 

当坐标极大时，例如：```
1
0 0 1000000000000000000 0
```该算法仅执行减法、比较和加法。 它从不尝试构建路径，因此巨大的距离不会影响运行时间。
