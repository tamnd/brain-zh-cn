 ## 解决方案
 ## 问题理解

 我们得到一个由 2 x 2 网格排列的四个像素组成的小图像。 每个像素都标有小写字母，代表其当前颜色。 目标是使用一系列绘画操作使所有四个像素最终具有相同的颜色。 

每个操作允许我们最多选择两个像素，但前提是这些像素当前共享相同的颜色。 选择它们后，我们将两个选定的像素重新绘制为我们选择的单一新颜色。 如果我们只选择一个像素，也可以单独重新绘制一个像素。 

任务是计算使每个测试用例的整个 2 x 2 网格颜色均匀所需的此类操作的最少数量。 

由于网格大小是固定的并且非常小，因此不存在算法缩放问题。 这些限制使我们能够通过不断的工作独立地处理每个测试。 任何检查四个电池并解释其颜色分布的解决方案都可以在限制范围内顺利运行。 

主要的微妙之处在于，如果我们低估了配对操作的工作原理，那么“将所有内容更改为最常见的颜色”之类的天真贪婪想法可能会失败。 例如，如果四种颜色都不同，看起来我们需要四次移动，但只有当存在重复时，我们可以通过巧妙配对来做得更好。 

边缘情况本质上都是由频率分布决定的。 如果所有像素都相同，则不需要任何操作。 如果有三个相同和一个不同，或者两对，或者全部不同，答案会以一种不明显但结构化的方式改变。 

## 方法

 暴力策略将尝试所有可能的有效操作序列，直到所有像素匹配。 从任何配置中，我们可以选择大小为一或二的任何颜色类，将其重新绘制为任何其他颜色，然后继续。 状态空间很小，但分支很快就会爆炸，因为每次重绘都会以多种方式改变颜色配置，并且不同的序列可能会重复导致相同的状态。 尽管只有四个位置，但对颜色分配的简单 BFS 仍然会探索许多冗余的过渡。 

关键的观察是，我们从不关心中间颜色，只关心有多少像素已经与最终目标颜色匹配。 如果我们固定目标颜色，则可以忽略已经具有该颜色的每个像素，而必须转换其余像素。 成本完全取决于有多少像素已经匹配该目标。 

对于固定的目标颜色，假设它出现`k`次。 我们需要将剩余的`4 - k`像素。 每个操作一次最多可以转换两个像素，但前提是我们可以选择两个相同的当前颜色。 由于我们可以自由地重新绘制，因此我们总是可以安排转换，以便在可能的情况下，配对永远不会比单独的动作更糟糕。 这减少了检查每个颜色类别中已有多少像素并选择最佳目标的答案。 

因此，我们只需尝试网格中出现的所有颜色作为潜在的最终颜色，并计算每种颜色的成本。 这些候选者中的最小值是最佳的。

 | --- | --- | --- | --- |
 | 蛮力状态搜索 | O(大，指数) | O（状态）| 太慢了 |

 ## 算法演练

 1. 计算每种颜色在 2 x 2 网格中出现的次数。 这给出了最多 4 个字母的频率图。 

原因是最终答案仅取决于有多少像素已经与选定的最终颜色匹配。 
2. 对于网格中的每种不同颜色，将其视为候选最终颜色。 

我们假设我们将把所有其他像素转换成这种颜色。 
3. 对于选定的目标颜色和频率`k`，计算需要改变多少像素，即`4 - k`。 
4. 每次移动最多可以重新绘制两个像素，因此修复所需的移动次数最少`4 - k`像素为：$$\lceil (4 - k) / 2 \rceil$$该表达式捕获了可重绘像素的最佳可能配对。 
5. 取所有候选目标颜色的最小值并输出。 

### 为什么它有效

 关键的属性是，任何最佳解决方案都可以被视为首先选择最终颜色，然后将其他所有内容转换为它。 由于我们只关心最终的均匀性，因此除了启用配对操作之外，中间颜色并不重要。 每个操作最多可将不匹配像素的数量减少两个，并且我们始终可以安排操作，以便在存在两个可转换像素时永远不会浪费配对机会。 因此，固定目标的成本完全取决于有多少像素还不是该颜色，并且尝试所有目标可确保我们不会错过最佳选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        grid = [input().strip() for _ in range(2)]
        
        freq = {}
        for row in grid:
            for ch in row:
                freq[ch] = freq.get(ch, 0) + 1
        
        ans = 4
        for k in freq.values():
            need = 4 - k
            moves = (need + 1) // 2
            ans = min(ans, moves)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将 2 x 2 网格压缩到频率字典中。 每个条目代表一种潜在的最终颜色。 对于每种颜色，我们计算有多少像素已经正确，并得出有多少像素需要更改。 表达式`(need + 1) // 2`实现所需的上限除法，因为每个操作最多可以修复两个不匹配的像素。 

答案是所有候选颜色中的最小值，这确保我们选择最有利的最终颜色配置。

 ## 边缘情况

 关键的边缘情况是所有四个像素已经共享相同的颜色。 在这种情况下，频率图包含值为 4 的单个条目。计算得出`4 - 4 = 0`，导致零移动，这符合要求，因为不需要重新绘制。 

另一种情况是当颜色均匀地分成两对时，例如`a a / b b`。 频率图是`a:2, b:2`。 对于任一目标，不匹配的次数都是 2，上限除法给出 1 次移动。 该算法正确地认识到，通过选择两个相同颜色的像素，可以在一次操作中重新绘制两个不匹配的像素。 

第三种情况是所有颜色都不同。 频率图有 4 个条目，均为 1。任何目标都会留下 3 个不匹配项，并且`(3 + 1) // 2 = 2`。 这反映出在一次配对后，还剩下一个像素，必须单独处理，需要进行第二次操作。
