 ## 解决方案
 ## 问题理解

 我们得到一个固定的参考字符串，然后要求处理许多短查询字符串。 对于每个查询，我们临时将查询字符串附加到引用，计算结果串联的前缀函数，并仅输出与附加部分相对应的前缀函数值。 每次查询后，状态都会重置回原始参考字符串。 

关键的难点在于位置上的前缀函数$i$取决于以结尾的前缀的最长边界$i$，这又取决于早期的前缀函数值和字符比较。 如果我们为每个查询从头开始重新计算所有内容，我们将重复扫描长度可达的长基本字符串$10^6$，这是不可行的放弃$10^5$查询。 

这些约束意味着任何解决方案都必须将基本字符串视为预处理结构，并及时处理每个查询，且时间仅与查询长度成正比。 由于每个查询字符串的长度最多为 10，因此每个查询的总额外工作量必须为$O(|t|)$，否则解将超出极限。 

一个简单的实现会重新计算前缀函数$s+t$每个查询的完整信息。 仅此一点就已经意味着$10^6 + 10$每个查询的工作，重复$10^5$次，这是远远超出可接受范围的。 

如果尝试仅重新计算后缀部分但仍反复与完整前缀进行比较，则会出现更微妙的失败情况$s$无需维护持久的自动机或压缩的转换结构。 前缀函数可以一步“跳回”多次，因此针对整个字符串的每个字符模拟在最坏的情况下可能会降级为线性行为。 

例如，如果$s = aaaa\ldots a$和$t = aaaaa$，每个前缀函数步骤都会通过长匹配链重复回退。 在所有查询的最坏情况下，每次向后扫描的朴素循环仍然会变成二次方。 

## 方法

 暴力破解的想法很简单：对于每个查询，形成$s+t$，使用标准线性 KMP 过程计算前缀函数，并输出最后一个$|t|$价值观。 这是正确的，因为前缀函数纯粹是在连接字符串上定义的，不依赖于查询结构。 

问题是成本。 每个计算是$O(|s|+|t|)$，所以跨越$q$查询这变成$O(q|s|)$，这大约是$10^{11}$最坏情况下的操作。 这不能通过。 

关键的观察是前缀函数计算相当于在由前缀函数故障链接定义的自动机中行走。 如果我们将每个前缀长度解释为一个状态，那么每个新字符都会导致一个转换：我们重复跟踪失败链接，直到找到可以由当前字符扩展的状态。 

这种结构建议进行预处理：我们为每个状态构建$v$和每一个字母$c$，如果我们当前处于状态，则下一个前缀函数状态$v$并阅读$c$。 这正是 KMP 自动机。 一旦构建完成，每个查询就成为对该自动机的简单模拟，从与完整字符串对应的状态开始$s$。 

我们首先计算前缀函数$s$。 这给了我们起始状态$cur = p[|s|]$。 然后我们使用故障链接预先计算转换。 之后，查询中的每个字符都会被处理$O(1)$，立即产生下一个前缀状态，然后我们输出它。 

这将问题简化为线性预处理加上所有查询字符的总线性工作。

 ## 算法演练

 1. 计算基本字符串的前缀函数$s$。 这为我们提供了失败链接，使我们能够跳转到最长的正确前缀，该前缀也是每个位置的后缀。 
2.对待每个前缀长度$v$作为自动机中的状态。 来自州$v$，我们想知道如果我们追加一个字符我们最终会在哪里$c$。 
3. 预先计算一个转换表`nxt[v][c]`对于所有州$v$和字母$c$。 为了正确计算它，我们通过故障链接重用之前计算的转换，而不是从头开始重新计算匹配。 
4. 将查询的初始状态设置为`cur = p[len(s)]`，表示读取整个基本字符串后最长的前缀后缀匹配。 
5. 对于每个查询字符串$t$，一一处理字符：

 1. 更新`cur = nxt[cur][t[i]]`。 
2. 输出`cur`作为连接字符串中该位置的前缀函数值。 
6. 完成查询后，不执行任何重置操作，因为`cur`已经代表了之后的状态$s$，并且每个查询都是独立的。 

正确性取决于自动机转换精确编码前缀函数更新规则的事实：我们总是移动到可以由下一个字符扩展的最长前缀，并且故障链接确保我们有效地跳过无效匹配。 

### 为什么它有效

 在任意一点，变量`cur`表示最长前缀的长度$s + t_{processed}$这也是该字符串的后缀。 这正是前缀函数状态的定义。 转换规则保持这种不变性，因为每次更新要么扩展当前匹配的前缀，要么沿着失败链接回退，直到找到有效的扩展。 由于失败链接始终保留边界属性，因此不会跳过任何有效的候选者，并且结果状态始终是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_pi(s):
    n = len(s)
    pi = [0] * n
    for i in range(1, n):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def build_automaton(s, pi):
    n = len(s)
    nxt = [[0] * 26 for _ in range(n + 1)]

    for v in range(n + 1):
        for c in range(26):
            if v < n and ord(s[v]) == ord('a') + c:
                nxt[v][c] = v + 1
            else:
                if v == 0:
                    nxt[v][c] = 0
                else:
                    nxt[v][c] = nxt[pi[v - 1]][c]
    return nxt

def solve():
    s = input().strip()
    q = int(input())
    pi = build_pi(s)
    nxt = build_automaton(s, pi)

    cur = 0
    for ch in s:
        cur = nxt[cur][ord(ch) - 97]

    out = []
    for _ in range(q):
        t = input().strip()
        ans = []
        for ch in t:
            cur = nxt[cur][ord(ch) - 97]
            ans.append(str(cur))
        out.append(" ".join(ans))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现首先构建基本字符串的前缀函数，然后构建 KMP 自动机的完整转换表。 每个状态对应一个前缀长度，并且在读取字符后转换对下一个可能的边界长度进行编码。 

一个微妙的点是构建`nxt`。 当一个字符与前缀中预期的下一个字符不匹配时，我们不会立即从零重新开始。 相反，我们遵循失败链接`pi[v-1]`，它代表下一个最佳边界候选者。 这种递归确保了正确性，而无需重新检查字符。 

另一个细节是初始化`cur`通过自动机重播基本字符串。 这保证了处理后与前缀函数状态的一致性$s$，避免预处理和查询模拟之间的任何不匹配。

 ## 边缘情况

 一种边缘情况是查询字符立即中断所有现有匹配。 例如，如果$s = "aaaa"$查询开头为$b$，自动机应该直接跳转到状态 0 并停留在那里。 转换表确保了这一点，因为所有不匹配路径最终都会到达根状态。 

另一种边缘情况是当查询不断地将匹配延伸到超出原始字符串的长度时。 如果$s = "abc"$和$t = "abcabc"$，自动机必须正确地重用早期的前缀作为新的边界。 故障链接链保证在达到完整匹配长度后，进一步的匹配从正确的边界继续，而不是错误地重新开始。 

最终的边缘情况是最小输入，其中$s$长度为 1。在这种情况下，所有转换要么在匹配字符时转到状态 1，要么在其他情况下转到状态 0。 自动机正确地退化为二状态机，并且逻辑与一般情况保持一致。
