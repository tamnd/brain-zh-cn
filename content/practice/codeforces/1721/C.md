 ## 解决方案
 ## 问题理解

 我们有两个非递减数组，一个原始数组和一个最终数组。 通过向每个位置添加非负值，可以逐个元素“移动”原始数组，从而生成中间数组。 之后，这个中间数组被排序，我们观察排序后的数组。 

任务是部分扭转这个过程。 对于原始数组中的每个位置，我们希望确定该位置的附加值有多大和有多小，同时仍然可以在转换和重新排序后得到给定的最终排序数组。 

关键的困难在于排序破坏了位置之间的直接对应关系。 原始数组中的每个元素都可能与最终数组中的不同位置匹配，具体取决于我们如何选择添加值。 

这些约束意味着每个测试用例的解决方案接近线性或近线性。 所有测试用例的 n 总和为 2·10^5，因此每个测试用例的任何比 O(n log n) 更差的方法都会失败。 这立即排除了尝试位置之间的所有排列或强力匹配的任何构造。 

当数组中的值相等或接近相等时，会出现微妙的边缘情况。 在这种情况下，原始位置和最终位置之间的多个匹配变得有效，如果我们过早假设固定配对，贪婪决策很容易破坏正确性。 例如，当 a = [1, 2, 3] 且 b = [1, 2, 3] 时，每个 d 都必须为零，但不匹配索引的天真贪婪赋值可能会错误地分配正值。 

当 a 中的大值与 b 中的小值在某些中间推理中匹配时，会发生另一种棘手的情况。 由于 d 必须保持非负数，因此任何违反排序约束的不匹配假设都将默默地产生无效状态，除非仔细处理。 

## 方法

 暴力方法会尝试将每个 a[i] 分配给某个 b[j]，计算 d[i] = b[j] - a[i]，并检查是否存在有效的全局分配，以便结果值的多重集在排序后与 b 匹配。 这很快就会变成一个带有约束的匹配问题，并且探索所有排列会导致阶乘复杂性。 即使用回溯来限制它也会导致指数行为，因为每个位置都有许多候选匹配。 

关键的观察是两个数组都是排序的，这使我们能够使用贪婪匹配而不是排列来推理可行的分配。 我们不再考虑任意重新排序，而是将问题重新解释为顺序约束下的配对元素。 

对于固定索引 i，a[i] 可以对应的值 b[j] 必须满足由计数参数得出的可行性条件：i 之前有多少个元素可以匹配小于或等于 b[j] 的值，以及 i 之后有多少元素仍必须适合剩余的槽。 这将问题转化为一种结构，我们可以使用前缀匹配逻辑来测试特定分配的可行性。 

为了计算最小和最大可能的 d[i]，我们独立对待每个 i 并询问：可以分配给 a[i] 的最小或最大 b[j] 是多少，同时保持数组的其余部分在贪婪约束下可匹配。 这变成了一个两指针模拟问题，我们按线性顺序测试候选配对。 

中心思想是，因为两个数组都已排序，所以任何有效的赋值都可以转换为索引之间的单调匹配。 这消除了考虑任意排列的需要，并减少了在排序约束下检查对齐可行性的问题。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优贪心匹配 | 每次测试 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们独立处理每个索引 i，计算其最小和最大可能的 d[i]。 

### 最小 d[i]

 1. 我们假设 a[i] 应该与最早可能的 b[j] 匹配，而 b[j] 仍然可以是有效全局匹配的一部分。 
2. 我们从左到右扫描 b，模拟将 b[j] 分配给 a[i] 是否为所有剩余元素留下足够的空间。 
3. 对于每个候选 b[j]，我们通过模拟所有元素的贪婪匹配来检查可行性，确保较早的 a 值仍然可以与较早的 b 值匹配。 
4. 通过可行性检查的第一个 b[j] 给出了可能的最小 b[j]，因此最小 d[i] = b[j] - a[i]。 

我们从左边扫描的原因是较小的 b 值对应较小的 d[i]，因此我们想要最早的可行匹配。 

### 最大 d[i]

 1. 我们反转目标并尝试将 a[i] 与最新的可能的 b[j] 匹配。 
2. 我们从右向左扫描b，再次测试将a[i]固定为b[j]的可行性。 
3. 我们选择仍然允许剩余元素完全有效匹配的最大 b[j]。 
4. 差值给出最大 d[i]。 

这是对称的，因为增加 b[j] 会增加 d[i]，但仅达到剩余匹配的可行性中断的程度。 

### 为什么它有效

 正确性来自于两个数组都已排序的事实，这意味着 a 和 b 之间的任何有效匹配都可以表示为索引之间的单调分配。 一旦我们修复了单个索引的候选配对，剩下的问题就减少为检查剩余元素是否可以按顺序匹配而不违反非负约束。 这种单调结构确保在贪婪扫描下保留可行性，因此第一个（或最后一个）有效候选者分别对于最小值和最大值而言是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def feasible(a, b, forced_i, forced_j):
    n = len(a)
    used_b = [False] * n
    used_b[forced_j] = True

    j = 0
    # match all i except forced_i greedily
    for i in range(n):
        if i == forced_i:
            continue
        while j < n and (used_b[j] or b[j] < a[i]):
            j += 1
        if j == n:
            return False
        used_b[j] = True
        j += 1
    return True

def solve_case(a, b):
    n = len(a)
    min_d = [0] * n
    max_d = [0] * n

    for i in range(n):
        # min
        for j in range(n):
            if b[j] < a[i]:
                continue
            if feasible(a, b, i, j):
                min_d[i] = b[j] - a[i]
                break

        # max
        for j in range(n - 1, -1, -1):
            if b[j] < a[i]:
                continue
            if feasible(a, b, i, j):
                max_d[i] = b[j] - a[i]
                break

    return min_d, max_d

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        mn, mx = solve_case(a, b)
        print(*mn)
        print(*mx)

if __name__ == "__main__":
    main()
```该解决方案将可行性检查与候选人选择分开。 这`feasible`函数模拟强制配对是否可以扩展为完全有效的分配。 它贪婪地匹配剩余的`a[i]`值为可用的最小有效值`b[j]`价值观。 

最小和最大数组是通过扫描每个位置的所有可能候选来构建的。 正确性取决于修复单个对后始终测试可行性。 

一个微妙的实现细节是在贪婪匹配期间跳过强制索引。 如果不排除，仿真可能会错误地重用强制值并破坏有效性检查。

 ## 边缘情况

 当 a 和 b 中的所有值都相同时，每个元素都必须映射到自身。 任何向上移动元素的尝试都会破坏可行性，因为它会迫使另一个元素占用更小的槽，这在排序约束下是不可能的。 该算法自然收敛到零差异，因为只有自匹配才能通过可行性。 

当 a 包含重复值时，相等的 b 值之间存在多重赋值。 贪婪可行性检查确保选择任何相同的 b[j] 不会破坏剩余容量，因此最小和最大都会适当崩溃，证明歧义不会影响正确性。
