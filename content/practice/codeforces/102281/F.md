 ## 解决方案
 ## 问题理解

 我们有一系列相同的发电机。 文档说的正是`n`发电机生产`k`焦耳期间`m`分钟。 所需的系统必须至少产生`q`焦耳期间`p`分钟。 我们需要满足此要求的最小整数生成器。 

五个输入值是`n`,`m`,`k`,`p`， 和`q`。 前三个描述了发电机的生产率，而`p`和`q`描述所需的能量以及必须产生能量的时间。 输出是必须安装的最小发电机数量。 

关键是产量与发电机数量和时间都是线性的。 如果`n`发电机生产`k`焦耳`m`分钟，然后一台发电机产生`k / (n * m)`每分钟焦耳。 和`x`发电机，期间产生的数量`p`分钟是`x * p * k / (n * m)`。 

我们需要这个数量至少`q`， 所以`x * p * k / (n * m) >= q`。 

乘以正分母后，`x * p * k >= n * m * q`。 

因此答案是满足这个不等式的最小整数。 

所有五个值最多为`10^6`。 他们的产品可以达到`10^18`，因此实现必须能够适应该大小的整数值。 对可能数量的生成器进行循环是不可行的，因为答案本身可能与`10^18`。 预期的解决方案需要恒定的时间和恒定的内存。 

有几种边界情况很容易破坏实现。 如果所需的量完全可以实现，我们就不能添加不必要的发电机。 例如，与`1 1 1 1 1`，一台发电机恰好产生一焦耳，所以答案是`1`。 一个粗心的实现总是在加一后向上舍入会返回`2`。 

相反的情况是所需的量仅略大于一种配置产生的量。 为了`2 2 2 1 3`，两台发电机仅产生`2`一分钟焦耳，而三个发电机产生`3`，所以正确答案是`3`。 使用普通整数除法而不是上限除法将错误地获得`2`。 

大型产品是另一个实施边界。 为了`1000000 1000000 1 1 1000000`，所需数量为`10^18`。 具有固定宽度整数类型的语言需要足够宽的整数类型作为中间产品`n * m * q`。 Python 整数自动增长，因此这种情况不需要特殊的溢出处理。 

## 方法

 一种直接的方法是尝试一台发电机，然后是两台，然后是三台，依此类推。 对于每一位候选人`x`，我们可以检查是否`x * p * k >= n * m * q`。 

这是正确的，因为产量单调增长`x`。 一旦候选人足够了，每个更大的数字也足够了，所以第一个成功的候选人恰好是最小的。 

问题在于第一个成功候选人的可能规模。 考虑`n = m = q = p = 10^6`和`k = 1`。 答案是`10^6 * 10^6 * 10^6 / 1 = 10^18`。 

然后循环将执行到`10^18`迭代，这远远超出了任何合理的时间限制。 这种暴力方法的时间复杂度是`O(answer)`，最坏的情况是`O(10^18)`运营。 

蛮力之所以有效，是因为存在可行答案的单调序列，但我们实际上不需要搜索该序列。 不等式可以进行代数变换，直接给出答案。 

让`A = n * m * q`和`B = p * k`。 

我们需要最小的整数`x`这样`x * B >= A`。 对于正整数，最小的此类值是上限`A / B`:`x = ceil(A / B)`。 

整数上限除法可以写成`(A + B - 1) // B`。 

这里还有一种更安全、更简洁的写法：`A // B + (A % B != 0)`。 

后者避免添加`B - 1`到分子，尽管 Python 可以安全地处理这两种形式。 由于每个输入都是正数，`B`永远不会为零。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(答案)，最多 O(10^18) | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`m`,`k`,`p`， 和`q`。 这些值完全决定了生产率和所需的能量。 
2. 计算`required = n * m * q`。 这是清除生产不平等中的分数后出现在右侧的总量。 
3. 计算`per_generator = p * k`。 这是一台发电机对所需功率的贡献`p`分钟，使用与以下相同的整数缩放表示`required`。 
4. 计算上限`required / per_generator`使用`required // per_generator + (required % per_generator != 0)`。 余数告诉我们是否可以进行精确除法。 如果有剩余，则需要额外一台发电机。 
5. 打印结果值。 产量达到或超过的最小整数`q`焦耳。 

### 为什么它有效

 中心不变量是不等式`x * p * k >= n * m * q`。 对于每个可能数量的发电机`x`，这个不等式相当于原来的能量需求，因为两边都是原来的不等式乘以正值得到的`n * m`。 该算法计算阈值的数学上限`n * m * q / (p * k)`，所以返回值满足要求。 任何较小的整数都低于该阈值并且不能满足要求，这证明了极小性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k, p, q = map(int, input().split())

    required = n * m * q
    per_generator = p * k

    answer = required // per_generator
    if required % per_generator != 0:
        answer += 1

    print(answer)

if __name__ == "__main__":
    solve()
```第一个乘法形式`n * m * q`，这是清除生产分数后所需发电机数量的分子。 第二种乘法形式`p * k`，表示在相同缩放比例下，一台发电机在所需时间间隔内的贡献。 

除法使用整数商和余数而不是浮点运算。 浮点是不必要的，并且当值接近时会变得危险`10^18`，因为并非该大小的每个整数都可以用典型的浮点类型精确表示。 

余数检查处理精确整除边界。 如果`required`可以整除`per_generator`，商已经产生了所需的能量。 否则，根据定义，商是不够的，因此需要多一个生成器。 

Python 的任意精度整数也消除了溢出问题。 在C++等语言中，需要64位整数类型，因为中间产品可以达到`10^18`。 

只有一种输入用例，因此不需要测试用例循环。

import io

def solve():

    required = n * m * q
    per_generator = p * k

    answer = required // per_generator
    if required % per_generator != 0:

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)

    finally:

 ## 边缘情况

 第一个边缘情况是精确整除。 为了`2 3 6 2 4`，所需缩放量为`2 * 3 * 4 = 24`，一台发电机贡献`2 * 6 = 12`以相同的比例表示。 商正好是`2`余数为零，因此算法返回`2`。 整数除法后盲目加一的公式会错误地返回`3`。 

第二种边缘情况是严格落在两个整数个生成器之间的要求。 为了`2 2 2 3 4`，阈值是`16 / 6`。 整数除法给出`2`， 但`2 * 6 = 12`是不够的。 由于余数不为零，算法将结果增加到`3`， 和`3 * 6 = 18`满足要求。 

最小情况`1 1 1 1 1`练习每个输入的下限。 分子是`1`，分母是`1`，答案正是`1`。 不存在被零除的情况，因为每个输入都是正数。 

最大的算术情况是`1000000 1000000 1 1 1000000`。 这里的分子是`10^18`分母是`1`，所以答案正是`10^18`。 基于循环的解决方案最多需要`10^18`迭代，而最优解执行一次除法和一次余数运算。 Python 的任意精度整数精确地表示该值。 

最后的微妙之处是所提供的语句中的示例格式已损坏。 显示的值不会形成可靠的第二个样本，并且如果假设其显示的输出是，则可见的第一行与该语句的字面物理解释不一致`3`。 上述算法遵循问题文本中描述的数学条件：`n`发电机生产`k`焦耳`m`分钟，所需产量至少为`q`焦耳`p`分钟。 根据该定义，生成器计数为`ceil(n * m * q / (p * k))`。
