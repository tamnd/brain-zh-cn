 ## 解决方案
 ## 问题理解

 虫洞形成一个有向图。 每个已知的从一个虫洞到另一个虫洞的转换都有两种成本之一。 超转换的成本为一蚂蚁小时，而空转换的成本为零。 飞船从虫洞 1 出发，必须到达虫洞 n。 

我们需要一条总成本最小的路线。 还有一个额外的限制：一条路线不能两次访问同一个虫洞。 输出必须包含最小的蚂蚁小时数，后面是路线中的虫洞数量以及路线本身。 如果从虫洞 1 无法到达虫洞 n，则输出为`IMPOSSIBLE`。 

该图最多可包含 100,000 个虫洞和 100,000 个有向跃迁。 在这样的规模下，枚举可能的路线是完全不可行的。 即使是检查所有顶点对的算法，例如时间为 (O(n^3)) 的 Floyd-Warshall，也远远超出了限制。 我们需要一种图算法，其运行时间基本上与顶点和转换的数量呈线性关系。 每个转换成本要么为零或一的事实是为我们提供这种算法的结构属性。 

有几种边缘情况可能会导致粗心的实施失败。 

考虑尽可能最小的图：```
1 0
```船已经到达目的地了。 正确路线是单虫洞`1`，成本为零：```
0 1
1
```始终期望遍历至少一条边的实现可能会错误地报告`IMPOSSIBLE`或产生一条空路线。 

第二种情况是目的地无法到达：```
2 0
```没有从虫洞 1 到虫洞 2 的过渡，因此唯一正确的输出是：```
IMPOSSIBLE
```搜索实现必须区分未到达的顶点和距离恰好为零的顶点。 

零成本周期是另一个微妙的例子：```
3 3
1 2 0
2 1 0
2 3 1
```最优路线是`1 2 3`，成本为一。 循环`1 -> 2 -> 1`没有贡献时间，但仍然被禁止，因为虫洞 1 会被访问两次。 最短距离算法内部可能会遇到这样的循环，但重构的最短路径一定不包含它。 

最后，几条最短路线的成本可能完全相同。 例如：```
4 4
1 2 1
1 3 1
2 4 0
3 4 0
```两个都`1 2 4`和`1 3 4`已花费一。 问题接受其中之一。 解决方案不得依赖于现有的特定最短路线。 

## 方法

 最直接的方法是枚举从虫洞 1 开始的路线，跟踪已经访问过的虫洞，这样一个顶点就不会出现两次。 每当到达目的地时，我们就可以将路线的成本与迄今为止找到的最佳答案进行比较。 

这是正确的，因为每条合法途径都被明确考虑。 问题是路线的数量。 具有许多分支转换的图可以具有指数级的许多简单路径。 在足够密集的图中，简单路径的数量可能约为 (n!)，因此即使只有 100,000 个可用顶点，在输入达到其最大大小之前很久就无法进行搜索。 对重复顶点的限制使得暴力枚举变得更加复杂，因为状态不仅是当前顶点，而且是先前访问过的顶点的完整集合。 

暴力方法之所以有效，是因为它直接代表了合法路线的定义，但它失败了，因为需要检查的路线太多。 

关键的观察是，对重复虫洞的限制实际上并不需要特殊的最短路径算法。 所有转移成本都是非负的，因此如果一次行走包含重复的顶点，则该顶点的两次连续出现之间的部分是一个循环。 删除该周期不会增加总成本。 如果周期的成本为正，则路线会变得更便宜。 如果成本为零，则该路线将保持完全相同的成本。 重复此过程会删除每个重复的顶点，并生成一条简单的路径，而不会产生更大的成本。 

因此，总有一条简单的最佳路线。 我们可以解决一个普通的最短路径问题并重建一条最短路径。 特殊的边权重限制为 0 和 1，允许我们使用 0-1 BFS。 

0-1 BFS 本质上是专门针对权重 0 和 1 的 Dijkstra 算法。 它使用双端队列而不是优先级队列。 当遍历零成本边改善距离时，新顶点被放置在前面，因为它的距离与当前顶点相同。 当遍历单成本边增加了距离时，新顶点会回到后面，因为它的距离恰好大了一个。 

这使得顶点以非递减的距离顺序进行处理，同时每次成功的松弛只需要恒定时间的双端队列操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下呈指数增长 | (O(n+m)) 加上路线状态 | 太慢了 |
 | 最优，0-1 BFS | (O(n+m)) | (O(n+m)) | 已接受 |

 ## 算法演练

 1. 构建有向邻接表。 对于每一次转变`a -> b`与类型`t`， 店铺`(b, t)`。 方向很重要，因为过渡可能是单向的。 
2. 初始化`dist[1] = 0`以及所有其他到无穷远的距离。 还存储`parent[v]`，它将记住所选最短路径上的前一个虫洞`v`。 将顶点 1 放入双端队列中。 
3. 取一个顶点`v`从双端队列的前面。 对于每个传出转换`v -> to`有成本`w`， 计算`new_dist = dist[v] + w`。 
4. 如果`new_dist`小于`dist[to]`， 更新`dist[to]`并设置`parent[to] = v`。 如果`w`为零，则将`to`在双端队列的前面。 如果`w`是一，把`to`在后面。 

零成本边不会增加当前距离，因此其端点必须在距离已经较远一个或多个蚂蚁小时的顶点之前处理。 一成本边将距离恰好增加一，因此其端点属于具有相同距离的当前可用顶点之后。 
5. 继续，直到双端队列为空。 在此刻`dist[v]`是从虫洞 1 到每个可到达虫洞的最小可能成本，所以特别是`dist[n]`是到达目的地的最短旅行时间。 
6. 如果`dist[n]`仍然是无穷大，打印`IMPOSSIBLE`。 否则，开始于`n`并反复关注`parent[v]`直到到达顶点 1。这会产生向后的路线，因此在打印之前将其反转。 
7、保证重建的路由不重复虫洞。 如果它确实包含重复的顶点，则两次出现之间的部分将是一个循环。 删除该周期所提供的路线不会比最短距离所代表的路线更昂贵。 由于前驱链是由严格有效的最短距离松弛形成的，因此可以选择结果路径作为简单的最短路径。 

### 为什么它有效

 中心不变量是，每当从双端队列处理顶点时，双端队列都会按照其当前距离的非递减顺序维护顶点。 零成本松弛保持相同的距离并移到前面，而一成本松弛则创建一个大一的距离并移到后面。 因此，Dijkstra 算法的第一个最短距离处理行为在没有优先级队列的情况下得以保留。 

每次松弛仅用一个更小的值替换距离，并且`parent[to]`记录实现新距离的边。 当算法完成时，目的地距离是从 1 到 n 的任何路线的最小成本。 由于所有边成本都是非负的，因此包含循环的每次行走都可以删除该循环，而不会增加其成本。 因此存在一条最优简单路由，并且前驱链给出了这样一条最优路由。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, t = map(int, input().split())
        graph[a].append((b, t))

    INF = 10**18
    dist = [INF] * (n + 1)
    parent = [-1] * (n + 1)

    dist[1] = 0
    dq = deque([1])

    while dq:
        v = dq.popleft()

        for to, w in graph[v]:
            nd = dist[v] + w

            if nd < dist[to]:
                dist[to] = nd
                parent[to] = v

                if w == 0:
                    dq.appendleft(to)
                else:
                    dq.append(to)

    if dist[n] == INF:
        print("IMPOSSIBLE")
        return

    path = []
    cur = n

    while cur != -1:
        path.append(cur)
        if cur == 1:
            break
        cur = parent[cur]

    path.reverse()

    print(dist[n], len(path))
    print(*path)

if __name__ == "__main__":
    solve()
```邻接表使用从 1 到`n`，匹配输入中的编号。 索引零处的额外元素避免了重复地从顶点数中减一。`dist`存储当前已知的最小蚂蚁小时数。`parent`存储重建所需的前身。 仅当找到严格较小的距离时才会更改前趋，因此它始终对应于当前分配给该顶点的距离。 

双端队列是关键的实现细节。`appendleft`处理零成本优势，同时`append`处理单成本优势。 对任一边缘类型使用错误的一端都会破坏 0-1 BFS 所依赖的距离排序。 

目的地允许为顶点 1。在这种情况下`dist[1]`已经为零，重建循环立即生成路线`[1]`。 

Python 整数不会溢出，尽管无穷大值`10**18`无论如何是绰绰有余的。 最大可能的有用最短路径成本至多是简单路径中的边数，因此它低于 (10^5)。 

重建工作遵循父母的`n`回到`1`，然后反转结果列表。 明确的`cur == 1`检查防止意外继续`parent[1]`，即`-1`。

 ## 边缘情况

 ### 起点等于目的地

 对于```
1 0
```双端队列最初包含顶点 1 和`dist[1]`为零。 无需处理任何转换。 重建工作开始于`n = 1`，立即停止，返回`[1]`。 输出是`0 1`其次是`1`。 这是一种边界情况，假设路径必须包含至少一条边，则捕获实现。 

### 无法到达的目的地

 对于```
2 0
```双端队列仅包含顶点 1。由于没有传出转换，因此顶点 2 保持无穷大。 算法打印`IMPOSSIBLE`而不是试图跟随`parent[2]`。 这就是为什么可达性检查必须在重建之前进行。 

### 零成本周期

 考虑```
3 3
1 2 0
2 1 0
2 3 1
```第一个零成本过渡集`dist[2] = 0`和`parent[2] = 1`。 处理 2 可以检查边缘回到 1，但是该边缘再次给出距离零，这并不严格优于现有的`dist[1] = 0`，所以 1 的父级没有改变。 边缘`2 -> 3`给出`dist[3] = 1`和`parent[3] = 2`。 重建产生`3 -> 2 -> 1`，这反过来为`1 -> 2 -> 3`。 禁止循环永远不会进入前驱链。 

### 多条最优路线

 对于```

2 4 0
3 4 0
```两条可能的路线都花费一美元。 根据邻接顺序和双端队列处理，算法可以选择`1 2 4`或者`1 3 4`。 两者都是有效的，因为距离是最佳的并且每个顶点仅出现一次。 该问题明确允许任何此类解决方案，因此不需要确定性地选择一个特定的最短路径。 

### 最大输入大小

 包含 100,000 个顶点和 99,999 个转换的链需要算法基本上处理整个图。 作为放宽的一部分，每个邻接条目都会检查一次，而距离和父数组由于基于 1 的索引而仅包含 100,001 个元素。 运行时间保持线性，并且内存消耗保持与输入大小成正比。 

核心教训是，表面上困难的“不要访问虫洞两次”条件不需要跟踪最短路径状态下的访问集。 非负边缘成本保证循环总是可以从最佳行走中删除，因此普通的最短路径算法就足够了。 然后，零或一成本限制将 Dijkstra 的优先级队列简化为双端队列，从而给出 (O(n+m)) 解决方案。
