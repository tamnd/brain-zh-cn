 ## 解决方案
 ## 问题理解

 我们有两个火柴盒，每个火柴盒最初都包含`n`匹配。 每次X教授需要火柴时，他都会随机选择两个口袋中的一个，并尝试从那个盒子里拿一根火柴。 当他选择一个已经空的盒子时，这个过程就结束了。 

任务是计算此时另一个框中仍然存在的匹配项的预期数量。 

唯一的输入是`n`， 和`1 <= n <= 30`。 上限足够小，甚至算法多项式`n`很容易就足够快了。 然而，所有随机选择历史的直接枚举是指数的，因此问题的有趣部分是识别停止历史的组合结构，而不是模拟每种可能性。 

有两种边界情况很容易处理不当。 首先，另一个盒子仍然可以容纳所有`n`匹配。 例如，与`n = 1`，教授可能会选择同一个口袋两次：第一个选择删除了唯一的匹配项，第二个选择发现那个盒子是空的，而另一个盒子仍然包含`1`匹配。 事实上，预期的答案是`n = 1`是`0.5`。 仅考虑另一个框已被使用的情况的实现将错误地错过这种情况。 

其次，最终的空箱发现是一次不成功的选择，因此它必须包含在特定历史的概率中。 为了`n = 2`，正确答案是`0.875000000000000`。 如果我们在盒子收到最后一次成功匹配时立即停止，那么我们正在解决不同的随机实验并获得错误的期望。 

上限`n = 30`也使数字问题变得简单。 出现的最大的两个指数是`2n = 60`，所以普通双精度足以满足所需`1e-6`容错性。 

## 方法

 直接的暴力解决方案可以生成每个可能的口袋选择序列，直到找到空盒子。 每个选择都有两种可能，所以如果考虑到最后的不成功选择，历史最多只有长度`2n + 1`。 为了`n = 30`，枚举该最大长度的所有二进制字符串给出`2^61`， 大约`2.3 * 10^18`，候选人历史。 为每条历史模拟最多 61 个选择，需要的数量级为`61 * 2^61`， 大致`1.4 * 10^20`基本操作。 那是完全不可行的。 

蛮力之所以有效，是因为每个可能的序列都有一个简单的概率，即`1/2`。 失败的原因在于单独处理不同的排序，即使它们导致剩余比赛的最终数量相同。 

假设当发现空盒子时，另一个盒子恰好包含`k`匹配。 那么空框一定是被选中的`n`在最终失败的选择之前多次成功。 必须准确选择另一个框`n-k`次。 因此，在最终失败的选择之前，恰好有`n + (n-k) = 2n-k`成功的选择。 

对于最终发现哪个盒子为空的固定选择，第一个`2n-k`选择恰好包含`n`该框的选择和`n-k`另一个框的选择。 有`C(2n-k, n)`安排这些选择的方法。 

每一个这样的安排都是有效的。 在最终选择之前，即将变空的盒子已经被准确使用过`n`次，而另一个盒子至少有`k`剩下的比赛。 因此，这两个盒子之前都不可能是空的。 

最后的选择必须选择已经用完的方框。 包括该选择给出的概率为`C(2n-k, n) / 2^(2n-k+1)`将一个特定的盒子作为第一个空盒子。 任何一个盒子都可以扮演这个角色，并且这两种情况具有相同的概率。 所以`P(k) = C(2n-k, n) / 2^(2n-k)`。 

因此，剩余比赛的预期数量为`E = sum(k * P(k))`为了`k = 0..n`。 

由于只有`n+1`的可能值`k`，我们将问题从指数级多的历史减少到只有`O(n)`概率项。 

我们可以评估这些项，而无需重复计算二项式系数。 开始于`k = n`。 在这种情况下，另一个框从未被选中，所以`P(n) = 1 / 2^n`。 

对于减少`k`，连续概率之间的比率是`P(k-1) / P(k) = (2n-k+1) / (2(n-k+1))`。 

因此，每一个下一个概率都可以通过恒定的算术量从前一个概率获得。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n * 2^(2n+1))`|`O(n)`| 太慢了|
 | 最佳 |`O(n)`|`O(1)`| 已接受 |

 ## 算法演练

 1. 阅读`n`。 我们将计算准确的概率`k`匹配项保留在未发现为空的框中。 
2. 开始于`k = n`和概率`p = 2^(-n)`。 这对应于选择相同的框`n`成功多次，然后再次选择同一个盒子。 因此，另一个盒子从未被碰过。 
3.添加`k * p`到预期值。 这是当前可能剩余比赛数的贡献。 
4. 移动自`k`到`k-1`。 使用更新概率`p *= (2*n-k+1) / (2*(n-k+1))`。 

该递推式直接从两个二项式概率表达式的比率获得，因此避免了大型组合计算。 
5. 继续直到`k = 0`。 价值`k = 0`是有效的，因为当教授最终发现其中一个盒子时，两个盒子都可能是空的。 它对期望的贡献为零，但它的概率仍然是分布的一部分。 
6. 打印累积的期望值，并保留足够的小数位以满足所需的精度。 

### 为什么它有效

 对于每一个可能`k`，一个停止历史记录`k`另一个框中剩下的匹配项恰好有`n`成功从盒子中进行选择，该盒子将变为空且准确`n-k`在最终失败选择之前从另一个框中成功选择。 选择这些人的位置`n`选择给出`C(2n-k,n)`有效的前缀，最终的选择是强制的。 考虑到任一盒子是空的，就给出了准确的概率`P(k)`由算法使用。 这些事件是相互排斥的，涵盖了所有可能的停止历史，因此总结`k * P(k)`精确给出所需的期望值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    # Probability that exactly n matches remain in the other box.
    p = 2.0 ** (-n)
    ans = 0.0

    for k in range(n, -1, -1):
        ans += k * p

        if k > 0:
            p *= (2 * n - k + 1) / (2 * (n - k + 1))

    print(f"{ans:.15f}")

if __name__ == "__main__":
    solve()
```变量`p`表示当前值的概率`k`。 我们开始于`k = n`因为该概率具有最简单的形式，`2^-n`。 

循环访问每个可能的值`k`正好一次。 表达式`ans += k * p`直接应用数学期望的定义。 

仅当以下情况时才执行更新`k > 0`。 在`k = 0`，没有下一个要计算的概率，并且尝试递归将除以无效的边界表达式。 

所有算术都是使用 Python 浮点数完成的。 最大指数只有60，最多迭代31次，累计数值误差远低于要求`1e-6`。 

整数溢出是不可能的，因为该实现根本不构造二项式系数。 递归仅使用小整数因子和浮点除法。

import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())
    p = 2.0 ** (-n)
    ans = 0.0

    for k in range(n, -1, -1):
        ans += k * p
        if k > 0:
            p *= (2 * n - k + 1) / (2 * (n - k + 1))

    print(f"{ans:.15f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def reference(n: int) -> float:
    # Independent calculation using the closed-form probability.
    import math

    ans = 0.0
    for k in range(n + 1):
        p = math.comb(2 * n - k, n) / (2.0 ** (2 * n - k))
        ans += k * p
    return ans

# Provided samples.
assert run("2\n") == "0.875000000000000", "sample 1"
assert run("3\n") == "1.187500000000000", "sample 2"

# Minimum-size input. The two possible remaining counts, 0 and 1,
# are equally likely, so the answer is 0.5.
assert run("1\n") == "0.500000000000000", "minimum n"

# Boundary case n = 4, with all possible k values contributing.
assert run("4\n") == "0.992187500000000", "off-by-one boundary"

# Maximum allowed n.
assert abs(float(run("30\n")) - reference(30)) < 1e-12, "maximum n"

# Another symmetric case, checked against the direct combinatorial formula.
assert abs(float(run("5\n")) - reference(5)) < 1e-12, "probability distribution"

 ## 边缘情况

 对于`n = 1`，两个盒子最初各包含一个匹配项。 有概率`1/2`，教授选择同一个盒子两次，所以另一个盒子包含`1`。 有概率`1/2`，他选择了两个不同的盒子，所以第二个选择发现一个空盒子，另一个盒子包含`0`。 因此期望值是`1/2`，算法从中获得`P(1) = 0.5`和`P(0) = 0.5`。 

为了`n = 2`，完整的分布是`P(2) = 1/4`,`P(1) = 3/8`， 和`P(0) = 3/8`。 由此产生的期望是`2 * 1/4 + 1 * 3/8 = 7/8`。 这`k = 2`结果对于捕获当框变空时而不是随后选择空框时停止分析的错误特别有用。 

为了`k = 0`，当教授发现第一个空盒子时，另一个盒子也是空的。 这种情况的概率为正，尽管它对预期值的贡献为零。 例如，与`n = 2`，其概率为`3/8`。 一个只会带来积极影响的实施`k`值仍然可能意外地得到一些例子，但它的概率分布是不完整的，任何相关的计算都会是错误的。 

对于最大输入`n = 30`，所使用的两个的最大幂是`2^60`，并且循环仅包含 31 次迭代。 递归永远不需要构造大量可能的历史，因此相同的恒定大小的状态表示在上限上保持不变。
