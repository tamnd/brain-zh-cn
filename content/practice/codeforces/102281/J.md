 ## 解决方案
 ## 问题理解

 我们有 (n) 个独立的连锁店。 第 (i) 条链包含 (a_i) 个环。 操作打开一个环，将其从原始链中移除，然后围绕两条链的末端闭合该环。 因此，打开的环成为两个部件之间的连接器。 

目标是获得一条连接的链，同时打开和关闭尽可能少的环。 成本正是打开的环的数量，无论这些环来自哪条链。 

关键的困难在于，开放环不仅仅是两个现有链之间的连接。 如果我们从同一条原始链条上打开多个环，该链条最终可以完全拆卸成连接器环。 一条带有 (a_i) 个环的完全拆卸的链条为我们提供了 (a_i) 个连接器环，同时移除该链条也消除了必须连接的原始链条之一。 

当 (n) 达到 (10^5) 时，(O(n^2)) 解决方案已经太慢了，任何指数都是完全不可行的。 (a_i)的值可以达到(10^9)，因此算法必须依赖于链的数量而不是环的总数。 排序后进行一次线性扫描很容易足够快。 

在一些边缘情况下，天真的解释可能会失败。 如果只有一条链，则无需操作。 例如，输入`1 / 100`有答案`0`，因为链已经连接了。 始终假设 (n-1) 个连接的解决方案将错误地输出`1`。 

含有一个环的链条尤其有价值。 为了`3 / 1 6666 100500`，答案是`1`。 打开第一条链条上的单个环，并用它连接其他两条链条。 坚持为每个原始合并执行一个操作的天真的解决方案仍然会碰巧得到`2`，这是错误的。 

也可以多个短链一起使用。 为了`4 / 1 1 1 100`，答案是`2`。 两个一环链可以完全打开，得到两个连接环，剩余的部分可以与这两个连接器一起排列成一条链。 连接器可能会在最终链中变得相邻，因此将每个打开的环视为需要不同的原始链来连接将错过有效的结构。 

## 方法

 一种直接的暴力方法是决定哪些原始链将被完全打开。 对于选定的集合（S），打开这些链中的每个环都会花费

 [
 K=\sum_{i\in S} a_i。 
]

 让(r=|S|)。 (S) 中的链条作为单独的部件消失，因为它们的所有环现在都可以用作连接器。 其他 (n-r) 条链都可以完整地保持完整。 对于 (K) 个连接环，最多需要 (K+1) 个这样的部件才能形成一条链，因此选择在以下情况下是可行的：

 [
 n-r\le K+1,
 ]

 或同等地，

 [
 \sum_{i\in S}(a_i+1)\gen-1。 
]

 因此，暴力算法可以枚举（n）条链的每个子集，检查这个不等式，并保持最小值（\sum a_i）。 有 (2^n) 个子集，甚至在 (O(n)) 中评估每个子集都会给出 (O(n2^n)) 次操作。 对于 (n=10^5)，即使仅子集枚举也需要 (2^{100000}) 种情况，因此这种方法根本不可行。 

有用的观察结果是，选择长度为 (a_i) 的链具有成本 (a_i)，但对可行性条件有贡献 (a_i+1)。 贡献和成本之间的差值始终恰好为 1。 

假设我们决定精确选择 (k) 个链。 我们需要它们的总长度来满足

 [
 \sum a_i+k\ge n-1。 
]

 在所有 (k) 个链组中，具有 (k) 个最小长度的组具有最小的可能成本。 如果即使那些（k）条链也不满足不等式，则没有其他组（k）条链可以以更小的成本满足它。 由于所有 (a_i) 都是正数，因此前缀的成本随着我们添加更多链而增加，因此我们只需对长度进行排序并采用最短的链，直到条件成立为止。 

这将指数搜索转变为排序问题，然后进行单次扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n2^n)) | (O(n)) | (O(n)) | 太慢了|
 | 最佳 | (O(n\log n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 按非递减顺序对所有链长度进行排序。 我们想要最便宜的一组完全开放的链，因此对于每个固定数量的选定链，我们应该更喜欢最短的链。 
2. 初始化`opened = 0`和`count = 0`。 这里`opened`是我们计划打开的环总数，而`count`是完全打开的链的数量。 
3. 将排序后的长度从小到大进行处理。 将当前链长度添加到`opened`并增加`count`一个。 
4. 添加长度为 (a) 的链后，检查是否

 [
 打开+计数\ge n-1。 
]

 左侧恰好是所选链的 (\sum(a_i+1))。 一旦达到 (n-1)，就有足够多的打开的环和完全拆除的链条，将所有剩余的碎片排列成一条链条。 
5. 在第一个满足条件的前缀处停止并输出`opened`。 因为长度是正数，所以每个额外选择的链都会增加答案，因此第一个可行的前缀是最佳的。 

### 为什么它有效

 考虑任何有效的构造，并令 (S) 为每个环被打开的原始链的集合。 令 (K) 为开环总数，(r=|S|)。 (S) 外面的每条链都包含至少一个从未打开过的环，因此它至少贡献了一个完整的碎片。 有 (n-r) 个这样的片段。 包含 (K) 个打开的连接器环的序列最多可以分离 (K+1) 个非空块，因此

 [
 n-r\le K+1。 
]

 重新排列给出

 [
 K+r\ge n-1,
 ]

 这正是

 [
 \sum_{i\in S}(a_i+1)\gen-1。 
]

 相反，如果这个不等式成立，则打开所选链中的每个环。 它们的 (K) 个环可以充当连接器位置，而 (n-r) 个剩余的原始链充当非空件。 由于 (n-r\le K+1)，这些部件和连接器环可以订购成一条链。 因此，不等式既是必要的，也是充分的。 

对于固定数量（k）的选定链，用较短的未选定链替换任何选定链不会增加总成本，也不会降低选择的有用性，因为其成本和贡献都减少了完全相同的量。 因此，(k) 个最短的链始终是最便宜的候选者。 因此，扫描前缀可以找到全局最小成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    opened = 0

    for count, length in enumerate(a, 1):
        opened += length

        if opened + count >= n - 1:
            print(opened)
            return

if __name__ == "__main__":
    solve()
```输入被读取一次，并且数组被排序，因为最佳选择的链形成排序顺序的前缀。 变量`opened`存储这些选定链中的环总数。 

这`enumerate(a, 1)`呼叫使`count`等于所选链的数量而不是从零开始的索引。 这避免了条件中容易出现的差一错误。 加工后`count`链，可行性表达式为`opened + count >= n - 1`。 

当找到第一个可行前缀时，立即打印答案。 没有必要继续，因为每个环计数都是正数，所以添加更多的链只能增加`opened`。 

Python 整数具有任意精度，因此最大可能的总数最多 (10^5\cdot10^9=10^{14})，无论如何都不需要特殊的溢出处理。 

## 工作示例

 对于第一个样本，输入是`5 / 3 3 3 3 3`。 

| 计数 | 当前长度 | 已开业 | 打开+计数| 可行|
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 3 | 4 | 是的 |

 第一条链已经给出 (3+1=4=n-1)。 打开它的三个环正好提供了连接其他四个链所需的三个连接器，所以答案是`3`。 

对于第二个样本，输入是`3 / 1 6666 100500`。 

| 计数 | 当前长度 | 已开业 | 打开+计数| 可行|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 2 | 是的 |

 这里(n-1=2)。 一环链足以提供一个连接器，并且移除原始链可以将单独链的数量减少一个。 剩下的两条链正好需要一个连接，所以答案是`1`。

import io

    n = int(input())

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)

    result = sys.stdout.getvalue()

    sys.stdout = old_stdout

 ## 边缘情况

 对于`1 / 1000000000`，初始链数已经是一个。 阈值是（n-1=0），所以算法不需要选择任何东西并返回`0`。 这解决了盲目要求至少有一个开口环的常见错误。 

为了`2 / 1 1`，第一个排序链的长度为 (1)。 选择之后，`opened = 1`和`count = 1`, 给予`opened + count = 2`，至少为 (n-1=1)。 答案是`1`。 打开一个环，用于连接两条原来的链条。 

为了`4 / 1 1 1 100`，在选定一条链后，该值为 (1+1=2)，低于所需的 (3)。 选定两条链后，变为(2+2=4)，因此算法返回`2`。 两个打开的环都可以作为最终链中的连接器位置出现。 这种情况很有用，因为连接器环不必与保持完整的原始链条一一对应。 

对于每个环有 (100000) 个链的最大情况，选择 (k) 个链后，我们有`opened = k`和`count = k`。 条件变为(2k\ge99999)，其最小整数解为(k=50000)。 答案是`50000`。 这既锻炼了阈值边界，又锻炼了答案大约是 (n) 的一半的事实。
