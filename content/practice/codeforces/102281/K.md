## 方法

 Самый прямой способ решения буквально повторяет действия администратора。 Пока существуют неудалённые программы, можно просмотреть их все и найти такую программу, все зависимости которой ещё установлены。 Как только такая программа найдена, её можно удалить 和 продолжить。 Если после полного прохода удалить ничего не получилось, остаются только программы, которые ждут друг друга, значит ответа нет。 

Такой алгоритм корректен, потому что на каждом шаге он удаляет програму, удовлетворяющую исходному условию. Если существует некоторый допустимый порядок, то среди оставшихся программ обязательно существует хотя бы одна програма, которая должна удаляться следующей。 Но стоимость такого подхода слишком велика。 

普苏斯图`m`равно общему количеству зависимостей。 В худшем случае мы можем делать до`n`проходов по програмам， проверка программ требует просмотра их зависимостей。 普鲁查亚特西亚`O(n(n + m))`。 普里`n = 1000`число зависимостей может достигать`1000 * 999 = 999000`, поэтому только повторная обработка зависимостей может потребовать до`1000 * 999000 = 999000000`проверок。 Для лимита в 1.5 секунды это уже слишком много。 

Ключевая идея появляется, если посмотреть не на вопрос «можно ли сейчас удалить программу`i`？»，а на то，сколько программ должно быть удалено перед каждой вершиной。 

Мы уже построили граф с ребром`i -> p`, 埃斯利`p`нужна для удаления`i`。 Тогда ребро говорит, что`i`жна стоять раньше`p`в ответе。 Для вершины`v`её входящая степень показывает количество программ, которые обязаны быть удалены раньше`v`。 

Если входящая степень вершины равна нулю, перед её удалением ничего делать не требуется. Значит，такая программа доступна прямо сейчас。 После её удаления все её исходящие рёбра становятся неактуальными, поэтому для каждой зависимости`p`уменьшается количество ещё не удалённых предшественников。 Когда это количество становится нулём,`p`также становится доступной。 

Это ровно механизм топологической сортировки Кана. Разница только в интерпретации графа: здесь ребро направлено в сторону програмы, которая должна быт удалена позже。 

Если в какой-то момент очередь доступных программ пуста, но удалены ещё не все программы, оставшийся граф содержит цикл。 Цикл означает, что каждая программа в нём ждёт другую программу из того же цикла, поэтому начать удаление внутри цикла невозможно。

 ## 算法演练

 1. Считаем зависимости и строим ориентированный граф. Для каждой строки программы`i`и каждой указанной программы`p`добавляем ребро`i -> p`。 Такое направление выбрано потому, что`i`жна быть удалена раньше`p`。 
2. Одновременно увеличиваем`indegree[p]`。 Это количество программ, которые ещё должны быть удалены перед`p`。 埃斯利`indegree[p] == 0`, 普罗格拉玛`p`уже можно удалять，потому что ни одна другая программа не обязана исчезнуть перед ней。 
3. Все вершины с нулевой входящей степенью помещаем в очередь。 Их можно удалить в любом порядке。 Мы используем обычную очередь`deque`， поэтому каждая вершина будет извлечена ровно один раз。 
4. Извлекаем програму`v`из очереди 和 добавляем её в ответ。 共 0页0条记录`v`удалённой。 Для каждого ребра`v -> p`尤梅尼埃姆`indegree[p]`на единицу, потому что одна из программ, которая должна была быть удалена перед`p`， только что удалена。 
5. Если после уменьшения`indegree[p]`значение стало равно нулю, добавляем`p`в очередь。 Теперь все програмы, которые требовались перед удалением`p`、 уже удалены、 поэтому`p`стала допустимым следующим шагом。 
6. Повторяем процесс, пока очередь не опустеет。 Если в ответе оказалось ровно`n`программ，найден полный допустимый порядок。 Если програм меньше`n`, оставшиеся вершины образуют зависимость, которую невозможно разрешить, поэтому выводим`-1`。 

### 为什么它有效

 Главный инвариант состоит в том, что перед каждым извлечением программы`v`из очереди все её входящие рёбра уже были обработаны, а значит все программы, которые должны быть удалены перед`v`， уже находятся в ответе。 Следовательно,`v`действительно можно удалить в этот момент。 

科达·普罗格拉马`v`удаляется, каждое ребро`v -> p`означает，что одно требование для`p`теперь выполнено。 Именно поэтому мы уменьшаем`indegree[p]`。 Как только он становится нулём, все необходимые предшественники`p`уже удалены, и добавление`p`в очередь безопасно。 

Если алгоритм не смог удалить все вершины, то у оставшегося графа нет вершины с нулевой входящей степенью. Конечный ориентированный граф с таким свойством содержит цикл。 Внутри цикла каждая программа требует существования другой программы из этого же цикла, поэтому первой удалить ни одну из них невозможно。 Значит,`-1`действительно является правильным ответом。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n = int(input())

    graph = [[] for _ in range(n + 1)]
    indegree = [0] * (n + 1)

    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        m = data[0]

        for p in data[1:]:
            graph[i].append(p)
            indegree[p] += 1

    q = deque()

    for v in range(1, n + 1):
        if indegree[v] == 0:
            q.append(v)

    answer = []

    while q:
        v = q.popleft()
        answer.append(v)

        for p in graph[v]:
            indegree[p] -= 1
            if indegree[p] == 0:
                q.append(p)

    if len(answer) != n:
        print(-1)
    else:
        print(*answer)

if __name__ == "__main__":
    solve()

# Boundary case with several independent vertices unlocked at different times
assert run(
    """5
2 2 3
1 4
1 5
0
0
"""
) == "1 2 3 4 5", "dependency chain with multiple zero-indegree vertices"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 / 0`|`1`| 最低限度`n`，以及没有依赖性的情况 |
 | 四行包含`0`|`1 2 3 4`| 所有程序均可立即删除 |
 |`1 -> 2`,`2 -> 1`，加上独立的`3`|`-1`| 循环检测|
 | 链条长度`1000`|`1 2 ... 1000`| 最大限度`n`、从1开始索引、重复解锁|
 |`1 -> {2,3}`,`2 -> 4`,`3 -> 5`|`1 2 3 4 5`| 多个顶点可用且边缘方向正确 |

 最大尺寸链对于查找相差一错误特别有用。 程序`1000`没有依赖关系，而程序`999`准确地要求`1000`，所以唯一有效的链方向是`1, 2, ..., 1000`。 反转边缘解释会立即产生错误的顺序。 

## 边缘情况

 ### 一个没有依赖关系的程序

 对于```
1
0
```该图有一个顶点，没有边。 它的传入度为零，因此它立即进入队列。 该算法将其删除，获得长度为一的答案，并打印`1`。 

假设每个程序至少有一个依赖项的粗心实现将在这里失败，即使`mi = 0`是明确允许的。 

### 所有程序独立

 对于```
4
0
0
0
0
```所有四个传入度数均为零，因此初始队列包含`[1, 2, 3, 4]`。 该算法可以按该顺序删除它们。 由于图是空的，因此不处理任何边。 

关键属性是拓扑顺序不需要是唯一的。 可以任意选择第一个可用的程序。 

### 一个循环

 考虑```
3
1 2
1 1
0
```该图包含`1 -> 2`和`2 -> 1`。 最初`indegree[1] = 1`和`indegree[2] = 1`，所以两个程序都不能进入队列。 程序`3`具有零传入度并且首先被移除。 然后队列变空，而答案中仍然缺少两个程序。 

自从`len(answer) != n`，算法打印`-1`。 这正是拓扑排序检测循环的点。 

### 稍后必须删除的依赖项

 考虑```
3
1 3
1 3
0
```两个程序`1`和`2`需要程序`3`保持安装状态。 该图有边`1 -> 3`和`2 -> 3`。 最初`1`和`2`传入度数为零，因此两者都可用。 程序`3`尚无法删除，因为必须先删除两个程序。 

一种有效的执行是`1`， 然后`2`， 然后`3`。 如果实现意外地将边构造为`3 -> 1`和`3 -> 2`，它会产生`3`首先，违反了原来的删除条件。 

### 一个程序的多个依赖项

 对于```
4
2 2 3
1 4
1 4
0
```程序`1`两者都需要`2`和`3`，同时两者`2`和`3`要求`4`。 该图是```
1 -> 2
1 -> 3
2 -> 4
3 -> 4
```初始零入度顶点为`1`。 去掉后，两者`2`和`3`变得可用。 只有将两者都删除后，传入的度数才会`4`达到零。 

该算法自然地处理这个问题，因为`indegree[4]`从 2 开始，对于两个传入边沿中的每一个递减一次。 

### 最大尺寸链条

 对于`n = 1000`， 考虑```
1000
1 2
1 3
1 4
...
1 1000
0
```每个程序都延续这种模式`i`根据`i + 1`，所以程序的最后一行`1000`是`0`。 

初始队列仅包含程序`1`。 去除`1`使`2`可用，删除`2`使`3`可用，依此类推，直到`1000`。 每个顶点都被处理一次，每个边都被处理一次，因此尽管允许的最大值，运行时间仍与实际输入大小保持线性关系`n`。 

所有这些案例的主要教训是，条件与删除时系统的状态有关。 一旦该条件被表达为排序约束，每个依赖关系就变成有向边，整个问题就干净地简化为拓扑排序。
