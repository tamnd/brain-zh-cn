 ## 解决方案
 ## 问题理解

 我们从`n`修理机器人和`m`独立的纳米损伤。 在一秒钟内，每个现有机器人都会选择一个动作。 它要么修复一个损坏，要么用第二个时间创建一个新机器人。 新创建的机器人从下一秒起即可使用。 

输出必须描述最佳时间表。 我们每一秒都会打印出当前现有机器人有多少个在复制。 所有剩余的机器人都会在那一秒内修复损坏。 第一行是所需的最小秒数。 如果无法修复所需数量的损坏，我们将打印`IMPOSSIBLE`。 

原来的声明允许两者`n`和`m`一样大`10^100`，因此在具有固定宽度算术的语言中普通机器整数是不够的。 Python 的任意精度整数在这里特别方便。 时间限制还告诉我们，我们无法模拟每个可能的机器人数量或每个可能的时间表。 有用的答案只需要对数秒的时间，因为机器人数量可能会增加一倍。 

有几种边缘情况很容易被错误处理。 如果输入是`0 0`，船已经没有损坏，所以正确答案是`0`，没有命令行。 总是打印至少一秒的粗心实现并不是最佳的。 

如果输入是`0 1`，没有能够修复任何东西的机器人，也无法创建第一个机器人，所以正确的输出是`IMPOSSIBLE`。 盲目计算对数或重复将机器人计数加倍的实现可能会陷入困境或被零除。 

如果输入是`10 10`，一秒钟就够了。 我们根本不需要复制，所以命令可以是`0`。 总是从复制开始的策略将花费两秒，并且会失去最优性。 

如果输入是`10 11`，一秒不够，两秒就够了。 我们可以在第一秒让所有十个机器人进行复制，获得二十个机器人，然后在第二秒使用其中的十一个进行修复。 命令序列是`10 9`。 一个常见的错误是输出`10 0`，它修复了 20 个损坏，但不是仅修复 11 个现有损坏的有效时间表。 

存档的 Codeforces 声明证实了`10^100`边界和下面使用的两个示例实例。 

## 方法

 直接的暴力解决方案可以尝试每秒复制的所有可能数量的机器人。 如果有`R`机器人在一秒开始时，有`R + 1`选择，从复制任何人到复制所有人。 状态空间增长极其迅速。 尽管每个州至少有`n + 1`可能的选择，深度探索`t`已经至少包含`(n + 1)^t`时间表。 调度的确切数量可以递归地描述为`S(0, R) = 1`和`S(t, R) = sum(S(t - 1, R + x))`为了`0 <= x <= R`。 

随着人口的增长，实际的分支会更大。 对于包含一百位数字的数字，这种方法不太可行。 

蛮力之所以有效，是因为它明确考虑了当前修复工作和未来复制之间的所有可能的权衡。 它失败了，因为这样的权衡太多了。 关键的观察结果是，对于固定的剩余秒数，较早执行复制更有价值。 

假设有`R`机器人和准确地说`t`还剩几秒，`t >= 2`。 如果我们做`x`机器人在当前这一秒内进行复制，然后`R - x`机器人立即修复损坏并`R + x`机器人留待下一步`t - 1`秒。 递归地假设可修复的最大数量`t - 1`秒数`R + x`机器人是`(R + x) * 2^(t-2)`。 总计变为`R - x + (R + x) * 2^(t-2)`可以重新排列为`R * (1 + 2^(t-2)) + x * (2^(t-2) - 1)`。 

为了`t >= 2`，系数`x`是非负的，所以最好的选择是`x = R`。 换句话说，当还剩至少两秒时，每个机器人都应该立即复制。 

这给出了一个简单的公式。 和`R`机器人和`t`可用秒数，可修复的最大损坏数为`R * 2^(t-1)`。 

这是可以通过积极使用复制并留出最后一秒进行修复来实现的。 更一般地说，一旦我们知道`m <= n * 2^(t-1)`，我们可以做第一个`t - 1`秒纯复制。 此时正好有`n * 2^(t-1)`机器人。 在最后一秒，我们选择足够的机器人进行复制，以便剩余的机器人相等`m`。 因此所有`m`损坏得到准确修复。 

现在的问题变成了寻找最小的`t`满意的`n * 2^(t-1) >= m`。 

我们甚至不需要二分搜索。 开始于`capacity = n`和`t = 1`, 反复加倍`capacity`并增加`t`直到`capacity >= m`。 自从`m <= 10^100`，这只需要几百次迭代。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 至少`Ω((n+1)^t)`时间表| 指数| 太慢了|
 | 最佳 |`O(log m)`大整数运算 |`O(log m)`输出空间| 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`作为任意精度整数。 如果`m = 0`，船已经修好了，所以设置`t = 0`并且不输出任何命令。 
2.如果`n = 0`尽管`m > 0`， 输出`IMPOSSIBLE`。 没有机器人可以修复损坏或创建另一个机器人。 
3. 否则开始`t = 1`和`capacity = n`。 这里`capacity`表示在最后一秒内可以执行维修的机器人的最大数量`t`-第二个最佳时间表。 
4. 虽然`capacity < m`， 双倍的`capacity`并增加`t`。 每多一秒，可用于最后修复秒的机器人数量就会增加一倍，因此容量恰好如下`n * 2^(t-1)`。 
5.第一个`t - 1`秒是纯粹的复制。 在第一个这样的第二个期间`n`机器人在接下来的所有时间里进行复制`2n`机器人复制，然后全部`4n`机器人可以复制，等等。 因此，复制命令是`n, 2n, 4n, ...`。 
6.最后一秒开始有`capacity`机器人。 我们想要的正是`m`机器人修复剩余的损坏，所以准确地说`capacity - m`机器人应该复制。 因此最后一个命令是`capacity - m`。 
7. 输出`t`以及由此产生的序列。 每个命令都在零和当前现有机器人的数量之间，因此调度在物理上是有效的。 

### 为什么它有效

 不变的是之后`k`初始复制秒数，机器人数量正好是`n * 2^k`。 上面的递归证明，对于任何固定的秒数，只要还剩下至少两秒，就使每个可用的机器人在当前秒内进行复制是最佳的。 因此，没有时间表`t`秒可修复超过`n * 2^(t-1)`损害。 该算法选择最小的`t`对于这个上限达到`m`，因此不存在更小的答案。 其构建的时间表正好达到`m`仅调整最后一秒即可修复，证明了可行性和最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    if m == 0:
        print(0)
        return

    if n == 0:
        print("IMPOSSIBLE")
        return

    t = 1
    capacity = n

    while capacity < m:
        capacity *= 2
        t += 1

    commands = []
    robots = n

    for _ in range(t - 1):
        commands.append(robots)
        robots *= 2

    commands.append(robots - m)

    print(t)
    print(*commands)

if __name__ == "__main__":
    solve()
```前两个条件处理任何加倍发生之前的两个零情况。 如果没有损坏，零秒是最佳选择。 如果有损坏但没有机器人，复制和修复都是不可能的。 

循环维持`capacity = n * 2^(t-1)`。 它停在第一个值`t`为此，最后的维修第二次有足够的机器人来弥补所有损坏。 Python的整数可以精确地表示所有中间值，包括超出的值`10^100`。 

命令结构反映了证明。`robots`是当前秒之前的机器人数量。 对于每一个第一个`t - 1`秒，每个机器人都会复制，所以命令是`robots`人口翻倍。 

在最后一秒，`robots`等于`capacity`。 印刷`robots - m`意味着这么多机器人复制，留下精确的`m`机器人来修理。 最后的减法也是我们不能简单地为每个复制命令打印零的原因。 时间表所修复的损坏不得多于实际存在的损坏。 

为了`t = 1`，生成复制前缀的循环执行零次。 唯一的命令变成`n - m`，这是正确的，因为所有`n - (n-m) = m`机器人在可用的一秒内进行修复。

import sys
import io

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        n, m = map(int, sys.stdin.readline().split())

        if m == 0:
            print(0)
            return sys.stdout.getvalue()

        if n == 0:
            print("IMPOSSIBLE")
            return sys.stdout.getvalue()

        t = 1
        capacity = n

        while capacity < m:
            capacity *= 2
            t += 1

        commands = []
        robots = n

        for _ in range(t - 1):
            commands.append(robots)
            robots *= 2

        commands.append(robots - m)

        print(t)
        print(*commands)

        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def run(inp: str) -> str:
    return solve_io(inp)

 ## 边缘情况

 对于`0 0`，算法立即看到`m == 0`和打印`0`。 不需要第二次，因为没有什么可以修复的。 命令序列为空，正好符合要求`t`命令。 

为了`0 1`，算法达到`n == 0`确定损坏存在后的情况。 由于不存在机器人，因此未来任何一秒都不会发生修复，所以`IMPOSSIBLE`是唯一可能的结果。 

为了`10 10`，初始容量已经是 10，因此循环永远不会运行。 我们有`t = 1`，最终的命令是`10 - 10 = 0`。 所有十个机器人在那一秒内各修复一个损坏，总共修复了十次。 

为了`10 11`，初始容量十个太小，所以加倍到二十个，`t`变成两个。 第一个命令是`10`，生产二十个机器人。 最终命令是`20 - 11 = 9`，所以九个机器人进行复制，另外十一个进行修复。 船正好在第二秒结束时被修复。 

为了`10^100 10^100`，不需要加倍。 Python 将两个数字读取为任意精度整数，直接比较它们，并生成`1`其次是`0`。 该算法从不将值转换为浮点型，因此不存在精度损失。 

该结构还处理以下情况`m`严格位于两个二次幂之间`n`。 例如，与`n = 10`和`m = 31`, the minimum capacity is forty, so three seconds are necessary. 前两个命令是`10`和`20`，留下四十个机器人等待最后一秒。 最终命令是`40 - 31 = 9`, so exactly thirty-one robots repair. 同样的论点适用于每个可能的值`m`两个连续容量之间。
