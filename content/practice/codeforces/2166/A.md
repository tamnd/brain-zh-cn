 ## 解决方案
 ## 问题理解

 我们得到一串小写字母。 在一步操作中，我们选择一个位置并用紧邻其右侧的字符覆盖其字符。 该操作只允许从右向左复制，因此信息严格沿一个方向流动。 

目标是使用最少数量的此类复制操作将整个字符串转换为单个重复字符。 

关键限制是方向性的：你不能随意将一个字符更改为你想要的任何字符，你只能将其替换为其右侧的字符。 这立即表明最终的统一字符必须已经存在于字符串中，因为不能引入新的字母。 

限制很小。 每个字符串的长度最多为 100，所有测试用例的总长度也最多为 100。这意味着即使三次或二次策略也是可以接受的，但操作的结构允许更简单和直接的操作。 

当字符串已经统一时，会出现微妙的边缘情况。 在这种情况下，不需要进行任何操作。 另一种值得注意的情况是所需的最终字符仅在字符串末尾出现一次。 在这种情况下，所有其他字符最终都必须通过从右到左的副本链进行转换，并且不考虑传播顺序的天真贪婪选择可能会低估所需的操作。 

## 方法

 暴力的观点是模拟所有可能的操作序列，直到字符串变得均匀。 从任何状态，我们都可以选择任何索引并将其右邻居复制到其中，从而分支到许多可能的状态。 即使使用很小的字符串，它也会以组合方式爆炸，因为每个步骤都会创建最多 n 个新分支，并且我们可能需要最多 O(n) 个步骤，从而导致指数状态空间。 

关键的观察是我们永远不需要独立考虑不同的目标字母。 如果我们修复最后一个字符，问题就变成：使用允许的从右到左传播将整个字符串转换为该字符。 由于我们只能从右向左复制，因此每个尚未等于最终字符的位置都必须被其右侧已具有最终字符的位置“覆盖”。 

这使得这个过程变成了从右到左的贪婪扫描。 如果我们决定最后一个字符，我们从右向左扫描，每当我们看到不匹配时，我们必须在该位置执行操作以复制其右邻居。 这有效地迫使该位置变得正确，并且我们积累了成本。 

由于最终的字符串必须是统一的，因此我们尝试将字符串中的每个不同字符作为候选目标并计算成本，然后取最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(n² 状态) | 太慢了|
 | 尝试所有目标+贪婪传播 | O(26·n) | O(26·n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 识别字符串中所有不同的字符。 这些字符中的每一个都是潜在的最终目标，因为最后剩余的字符必须已经存在于初始字符串中。 
2. 对于每个候选字符c，计算需要多少次操作才能将整个字符串变成c。 
3. 要计算固定 c 的成本，请从右向左遍历字符串。 
4. 维护一个表示当前“有效区域”的指针，由于先前的传播，其中位置已经等于 c。 
5. 当我们遇到一个位置 i 使得 s[i] 不是 c 时，我们在 i 处进行操作，使得 s[i] 变成 s[i+1]。 这确保了位置 i 现在与已经传播到右侧的任何内容相匹配。 
6. 将每个此类不匹配视为一次操作，因为每个不匹配都会强制进行直接修复。 
7. 处理完所有位置后，记录该候选人的总操作次数。 
8. 返回所有候选者中的最小值。 

我们从右向左遍历的原因是每个操作都取决于右邻居是否已经正确。 反向处理保证了当我们决定固定位置 i 时，位置 i+1 已经与目标对齐。 

### 为什么它有效

 对于固定的目标字符，每个不等于它的位置最终必须通过一系列从右到左的副本变得相等。 每个操作只修复一个位置，并且无法通过单个操作修复两个独立的不匹配，因为操作一次仅影响一个索引。 因此，从右到左扫描中需要校正的失配数量与所需操作的最小数量完全匹配。 尝试所有可能的目标字符可确保我们不会错过最佳的最终统一值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cost(s, c):
    n = len(s)
    ops = 0
    for i in range(n - 2, -1, -1):
        if s[i] != c:
            ops += 1
    return ops

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        best = n
        for c in set(s):
            best = min(best, cost(s, c))
        
        print(best)

if __name__ == "__main__":
    solve()
```该解决方案隔离了一个辅助函数，该函数计算使字符串与所选字符一致的成本。 主循环尝试每个不同的字符，这已经足够了，因为任何最佳解决方案都必须以已经存在的字符结束。 

成本函数依赖于这样的观察：除了可能在最右边的位置之外的每个不匹配都需要一次操作。 从右到左的扫描确保我们始终从正确的后缀进行传播。 

一个常见的错误是尝试从左到右的模拟，但会失败，因为操作取决于未来的状态。 反向扫描完全避免了这种依赖性。

 ## 边缘情况

 一个关键的边缘情况是当字符串已经统一时，例如`aaaa`。 该算法仍然将每个字符评估为目标，但对于该字符，不匹配计数为零，从而产生正确的答案。 

另一种情况是两个字符的字符串，例如`ab`。 从右到左扫描发现目标不匹配`a`，产生一个操作。 对于目标`b`，它还产生一个操作，确认对称性并表明没有错过任何与方向相关的捷径。 

第三种情况是最佳字符仅在最右侧出现一次，例如`abcde`有目标`e`。 扫描将每个较早的位置都视为不匹配，从而产生四次操作。 这符合这样的直觉：每个字符都必须通过从右到左的传播链来覆盖，并且没有任何操作可以独立地修复多个位置。
