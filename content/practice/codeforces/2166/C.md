 ## 解决方案
 ## 问题理解

 我们给定一组围绕圆放置的值，然后反复压缩该圆，直到只剩下一个值。 每次移动都会删除两个相邻元素，并用一个元素替换它们，该元素的值是两个元素中较大的一个，并且我们还支付等于该较大值的成本。 

运营结构比最终价值更重要。 无论我们如何合并，最后剩下的数字总是一些原始元素，但总成本很大程度上取决于我们选择的合并顺序。 任务是选择一个合并顺序，使所有选定最大值的总和最小化。 

这些约束清楚地表明，尝试所有可能的合并顺序的任何解决方案都是不可能的。 由于总元素多达 2×10^5，即使每个测试用例采用二次或接近二次动态规划方法也会失败。 每次测试我们需要更接近线性或 n log n 的东西。 

一个微妙的方面是，每次合并后邻接都会发生变化，并且环形结构允许在第一个和最后一个元素之间进行包装合并。 这种循环是复杂性的主要来源。 

一些边缘情况值得牢记。 

如果所有值都相等，则每次合并都会花费该值，并且任何策略都会产生相同的总数。 例如，[2,2,2] 总是给出成本 2+2=4。 贪心方法一定不能意外引入不必要的结构。 

如果有一个非常大的值被小值包围，例如 [1,1000,1,1]，则错误合并可能会强制执行涉及 1000 的多个昂贵操作。最佳策略会尝试延迟接触大值，直到有必要为止。 

如果两个大峰值之间存在许多小值，则首先天真的贪婪合并局部最小值可能会增加成本，因为它可能会重复创建等于大邻居的新最大值。 

这些例子暗示，真正的结构是关于每个元素在合并步骤中可以充当最大值的次数，以及合并如何沿着圆圈传播影响。 

## 方法

 暴力模拟将显式地维护循环列表并尝试每种可能的合并序列。 每一步都有 O(n) 个选择，我们执行 n−1 个步骤，导致可能性大致呈阶乘增长。 即使对状态进行记忆化，合并后不同的循环配置的数量也是指数级的，因为每次合并都会改变邻接结构并以非局部方式折叠状态空间。 

关键的简化是停止动态地思考该过程，而是将其重新解释为选择哪个元素“主导”每个合并事件。 每次合并所贡献的成本等于两个相邻组件的最大值。 该最大值必定是尚未消除的原始元素之一。 

这建议翻转视角：我们不跟踪合并，而是跟踪每个元素可以生存多长时间以及它最多可以“覆盖”多少个合并。 

一个重要的观察结果是，每次两个相邻段合并时，成本由幸存的较大段端点决定。 如果我们从段扩展的角度考虑，a[i] 值可以用作合并的成本贡献者，直到它最终被更大的东西吸收。 这与为每个位置维护两侧最近的严格较大元素密切相关。 

正确的结构是将每个元素视为潜在的“阻止者”，阻止较小的值在其中传播。 每个元素贡献其值乘以在最佳合并期间成为所选最大值的次数。 该多重性取决于在圆形排列中的任一侧遇到严格更大的值之前它可以延伸多远。

为了有效地计算这些边界，我们使用单调堆栈为每个位置查找圆形数组左侧和右侧最近的较大元素。 这定义了一个区间，其中 a[i] 是最大元素。 在此间隔内，可以安排合并，以便在最佳调度中将间隔内的每个缩减步骤恰好记入 a[i] 一次。 将所有 i 的这些贡献相加得出最小的总成本。

 ## 算法演练

 我们通过将数组加倍来将圆转换为线性结构，使圆形边界变成线性段。 然后，我们使用单调递减堆栈计算每个位置最近的较大元素边界。 

1. 通过将数组与其本身连接起来，将数组扩展到长度 2n。 这允许循环环绕查询被视为子数组查询。 
2. 使用单调堆栈计算每个索引右侧的下一个更大元素。 我们从左到右扫描，维护一堆值递减的索引。 当我们看到更大的值时，我们会弹出，直到恢复不变量。 对于每个位置，这给出了其右侧的第一个严格更大的元素。 
3. 通过从右向左扫描，以类似的方式计算左侧的前一个较大元素。 
4. 将这些边界限制回原来的 n 长度窗口。 对于每个 i，我们现在知道 a[i] 是最大元素的最大段。 
5. 将此段解释为 a[i] 可以负责合并成本的区域。 它可以主导的合并数量对应于其主导区间内有多少元素，经过调整，以便重叠贡献不会被重复计算。 
6. 捐款总额 a[i] 乘以其有效覆盖范围。 

第 5 步背后的原因是，每次合并都会将段计数减少 1，并且每次减少都必须“支付”一个幸存的最大值。 单调结构确保同一元素始终主导其有效区间而不会发生冲突。 

### 为什么它有效

 每个合并操作选择两个相邻组件中的最大值，这意味着成本始终分配给两个竞争段中较大的一个。 如果我们修复一个元素 a[i]，它只能负责在不存在更大元素来阻止它的区域中进行合并。 最近的较大边界将圆划分为最大优势区域。 

在这样的区域内，可以重新排列合并，而无需更改每个操作中哪个元素是最大的，因为相邻合并的任何序列仍然遵循较大元素定义的主导层次结构。 这将问题划分为独立的区域，并对这些区域进行求和，得出全局最优成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 2:
            print(max(a))
            continue
        
        # duplicate for circular handling
        b = a * 2
        m = 2 * n
        
        # next greater to right
        nxt = [m] * m
        st = []
        for i in range(m):
            while st and b[st[-1]] < b[i]:
                nxt[st.pop()] = i
            st.append(i)
        
        # previous greater to left
        prv = [-1] * m
        st = []
        for i in range(m - 1, -1, -1):
            while st and b[st[-1]] <= b[i]:
                prv[st.pop()] = i
            st.append(i)
        
        ans = 0
        
        for i in range(n):
            left = prv[i]
            right = nxt[i]
            
            # clamp to circular window
            if left < 0:
                left = i - n
            if right >= i + n:
                right = i + n
            
            # number of elements where i is maximum candidate
            contrib = (i - left) * (right - i)
            ans += b[i] * contrib
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案在双倍数组上构建两个单调堆栈。 下一个更大的数组标识每个元素在其右侧失去主导权的位置，而上一个更大的数组在左侧执行相同的操作。 这些边界定义了一个跨度，其中元素在圆形意义上局部最大。 

最后的循环通过将每个值乘以其主导区域的大小来聚合贡献。 乘法反映了该元素可以保持控制最大值的合并步骤数。 

处理重复数组的边界时需要小心。 钳位确保我们只计算与长度最多为 n 的有效圆段相对应的贡献。

 ## 边缘情况

 像 [5,5,5,5] 这样的平面数组可确保单调堆栈不会错误地创建人为的优势边界。 每个元素都具有相同的价值，因此任何元素都不应被视为严格大于另一个元素，并且贡献会均匀崩溃。 

诸如 [1,100,1] 之类的单峰场景测试算法是否正确地将最大值的影响扩展到整个圆，同时防止较小的元素被过度计算。 100 的优势间隔应涵盖所有合并。 

像 [4,3,2,1] 这样的严格递减序列检查每个元素仅主导其自然的向右合并，直到被循环解释中左侧的较大元素阻挡。
