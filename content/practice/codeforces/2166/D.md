 ## 解决方案
 ## 问题理解

 我们得到了一个整数的多重集，它只是一个元素可以重复的集合。 任务是计算通过将原始多重集重复划分为任意数量的非空组，然后从每个组中取一种模式，可以生成多少个不同的多重集。 群的众数是出现最频繁的任意元素； 如果多个元素都满足最大频率，则可以选择其中任何一个。 输出是我们可以通过此过程创建的所有不同多重集的计数，模 998244353。 

每个测试用例的输入大小最多为 5000 个元素，所有测试用例的元素总和以 5000 为界。这表明每个测试用例复杂度约为 O(n²) 的算法是可以接受的，但任何立方体都可能太慢。 此外，由于元素可以重复，所有分区的简单枚举将发生组合爆炸； 例如，10个元素可以以超过115,000种方式进行划分，这显然是不可行的。 

需要注意的边缘情况包括当所有元素都相同时、当所有元素都不同时或者当存在少量重复元素时可能会生成具有相同模式的许多不同分区。 例如，对于输入`[1,2,2]`，我们可以生成的可能的多重集是`{2}`,`{1,2}`,`{2,2}`， 和`{1,2,2}`。 仅查看子集而不是分区的简单方法会错过一些多重集。 

## 方法

 暴力方法是生成数组的所有分区，计算每个分区的众数，然后枚举生成的多重集。 这在原则上是正确的，但不切实际，因为集合的分区数量的增长速度比 n 的指数增长速度更快。 即使n=10，也有超过100,000个分区，而对于n=5000，这是完全不可行的。 

关键的见解是从频率角度考虑问题。 由于我们只关心每个分区的模式而不关心分区的确切结构，因此我们可以将问题简化为动态规划方法。 主要观察是，挑选多重集的方法数量可以表示为重复元素计数的卷积。 我们可以按值和频率对元素进行排序，并通过考虑将每个元素作为新子集中的众数包含多少次来迭代构建多重集的计数。 通过使用组合来处理重复元素，我们避免直接枚举分区。 这将问题从指数规划减少到 O(n²) 动态规划。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(分区数) | O(分区数) | 太慢了|
 | 动态规划+组合数学| O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 计算多重集中每个唯一元素的频率。 这将问题从处理 n 个元素转变为最多 n 个不同值及其计数。 让`freq[x]`是元素 x 出现的次数。 
2.初始化一个DP数组`dp[i]`在哪里`dp[i]`表示创建总大小为 i 的多重集的方法数。 开始于`dp[0] = 1`因为只有一种方法可以创建空多重集。 
3. 迭代每个独特的元素`val`在`freq`命令。 对于该元素的每个可能计数`k`从 1 到`freq[val]`，更新 DP 数组以包含通过以下方式形成的新多重集`k`的副本`val`。 这是一个经典的组合步骤：如果我们之前可以制作多个大小的集合`i`，我们现在可以制作多组尺寸`i+k`通过添加`k`的副本`val`。 
4.处理完所有元素后，将所有元素求和`dp[i]`为了`i >= 1`计算所有非空多重集。 对 998244353 求和模。 
5. 返回该总和作为测试用例的答案。 

工作原理：DP 阵列有效地跟踪我们可以实现的所有不同的多重集大小。 因为我们迭代每个元素并考虑所有计数，所以我们保证对可以使用模式选择过程形成的每个可能的多重集进行计数。 该方法避免了显式枚举分区，但仍然通过按与频率计数相对应的步骤递增 DP 阵列来考虑多种模式的组合可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        from collections import Counter
        freq = list(Counter(a).values())
        
        dp = [0]*(n+1)
        dp[0] = 1
        
        for f in freq:
            ndp = dp[:]
            for i in range(n+1):
                if dp[i]:
                    for k in range(1, f+1):
                        if i+k <= n:
                            ndp[i+k] = (ndp[i+k] + dp[i]) % MOD
            dp = ndp
        
        ans = sum(dp[1:]) % MOD
        print(ans)

solve()
```在此解决方案中，计数器收集每个唯一元素的频率。 这`dp`数组跟踪大小多重集的计数`i`。 对于每个元素频率，我们创建一个临时数组`ndp`以避免在更新期间覆盖现有的 DP 状态。 内循环确保我们考虑取 1 到`f`元素的副本。 求和`dp[1:]`给出非空多重集的总数.

 ## 工作示例

 用于输入`[1,2,3]`，频率列表为`[1,1,1]`。 DP阵列的演变如下：

 | 步骤| DP 数组（仅限非零条目）|
 | --- | --- |
 | 初始| dp[0]=1 | dp[0]=1 |
 | 流程1 | dp[1]=1 | dp[1]=1 |
 | 流程2 | dp[1]=2, dp[2]=1 |
 | 流程3 | dp[1]=3，dp[2]=3，dp[3]=1 |

 求和`dp[1:]`给出 7，与预期输出匹配。 

用于输入`[1,2,2]`，频率列表为`[1,2]`:

 | 步骤| DP阵列|
 | --- | --- |
 | 初始| dp[0]=1 | dp[0]=1 |
 | 流程1 | dp[1]=1 | dp[1]=1 |
 | 流程2 | dp[1]=2，dp[2]=1，dp[3]=1 |

 总和`dp[1:]`是 4，符合预期输出。 

这些痕迹表明 DP 正确地计算了由模式选择过程形成的所有多重集，包括那些需要跨组分割元素的多重集。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 对于每个频率（最多 n 个元素），我们循环遍历 DP 状态（最多 n）和可能的计数（最多频率 ≤ n）|
 | 空间| O(n) | 我们存储一个大小为 n+1 的 DP 数组 |

 每个测试用例 n ≤ 5000 并且总和 ≤ 5000，此 O(n²) 解决方案可以在时间和内存限制内轻松运行。
