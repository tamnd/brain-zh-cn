 ## 解决方案
 ## 问题理解

 给定一个整数序列，我们希望将其元素拆分为几个子序列。 每个元素必须恰好属于一个子序列，并且在每个子序列中，连续选择的元素的值必须恰好相差 1。 

子序列不需要在原始数组中连续，只需保留相对顺序。 因此，每个子序列都是通过按递增索引顺序选取元素来形成的，但有一个限制，即值必须沿着整数线逐步移动，每次仅移动±1。 

任务是最小化覆盖所有元素所需的此类子序列的数量。 

所有测试用例的总长度最多为 10^6 的约束立即排除了序列上的任何二次构造。 任何尝试显式测试多对元素之间的转换的解决方案都会太慢。 问题的结构表明我们需要在线性或近线性时间内在线处理元素，维护“当前活动子序列”的一些紧凑摘要。 

当多个子序列可能吸收相同的值时，就会出现微妙的困难。 例如，如果我们已经有以值 5 和值 7 结尾的序列，则新元素 6 可以扩展到任一侧。 选择不当可能会阻止未来的扩展并增加以后的子序列数量，即使当前的选择看起来无害。 

一个小例子可以说明这个问题：

 输入：```
1
5
5 6 5 6 5
```最佳答案是 2，但是总是附加到第一个可用邻居而不考虑结构的贪婪可以通过过早消耗有用的端点来轻松创建 3 个或更多序列。 

因此，核心挑战不仅仅是找到匹配，而是以保留未来灵活性的方式选择扩展。 

## 方法

 思考问题的一种直接方法是逐个构建子序列。 我们反复获取一个未使用的元素，并尝试通过向前搜索相差 ±1 的元素来贪婪地扩展链。 这在概念上是可行的，但每次扩展扫描都可以触及许多剩余元素，并且在最坏的情况下，这会退化为超过 10^6 个元素的二次行为。 

关键的转变是停止考虑构建完整的子序列，而是从左到右处理数组，仅维护子序列当前的“开放端”。 在任何时刻，每个子序列都有一个最后的值，新元素可以开始一个新的子序列，也可以附加到恰好相差一的现有开放端之一。 

因此，问题变成了流分配问题：对于每个值 v，我们必须决定是否将其附加到以 v−1 或 v+1 结尾的现有子序列，或者如果两者都不可用，则开始一个新的子序列。 

关键的观察是，关于子序列的唯一重要信息是它的最后一个值。 我们从不需要完整的链，只需要有多少个活动链在每个值处结束。 这将状态简化为值的频率图，表示每个整数当前有多少子序列“等待”。 

当处理新值 v 时，我们尝试扩展以 v−1 或 v+1 结尾的现有链。 如果两种选择都存在，任意选择并不安全； 我们需要一个规则来避免浪费更“受限”的一面。 一种一致的贪婪策略是始终附加到当前具有更多可用端点的邻居值，因为从较大的池中消耗可以为将来的强制匹配保留较小的灵活性。 

这将整个问题简化为维护活动端点的数量，并在可能的情况下将每个传入值贪婪地匹配到兼容的端点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解后续构建 | O(n²) | O(n) | 太慢了|
 | 与频率图匹配的贪婪端点 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个频率表`cnt[x]`， 在哪里`cnt[x]`是当前最后一个元素所在的子序列的数量`x`。 

我们也维持答案`ans`，到目前为止创建的子序列的数量。 

1. 从左到右处理元素。 
2. 对于每个值`v`，检查我们是否可以扩展现有的子序列：

 如果`cnt[v-1] > 0`或者`cnt[v+1] > 0`，那么至少有一个有效的子序列可以吸收该元素。 

如果两者都不存在，我们必须开始一个新的子序列，增加`ans`增加 1 并增加`cnt[v]`。 
3. 如果至少存在一个邻居，则选择延伸到哪一侧。 

如果两者都`cnt[v-1]`和`cnt[v+1]`是正数，我们选择计数较大的一侧。 直觉是，我们希望首先从更丰富的端点池中消耗资源，为未来可能没有其他选择的元素保留较稀缺的部分。 

我们减少所选邻居的数量并增加`cnt[v]`，有效地向前移动子序列端点。 
4. 如果只有一个邻居存在，我们必须使用它。 我们相应地更新计数。 

处理完所有元素后，`ans`是形成的子序列的数量。 

### 为什么它有效

 在任何时刻，活动子序列的结构都可以通过其中有多少个子序列以每个值结束来完全捕获。 每一步要么创建一个新的子序列，要么精确扩展一个现有子序列，并且扩展只能沿着有效的 ±1 转换进行。 

贪婪选择不会尝试进行全局优化，但它保留了一个关键的不变量：在迄今为止分配端点的所有有效方法中，该算法绝不会过度降低未来唯一需要的值的可用性。 通过在两者都可能的情况下始终从更丰富的邻居类中进行消费，我们可以避免出现以下情况：罕见的端点类型在早期被浪费，而丰富的端点类型仍然未使用但稍后又无法使用。 

这确保了每当未来元素到达时，如果它有任何可能的前任，算法不会通过次优的早期选择人为地阻止这种可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # frequency of subsequences ending at value x
        cnt = {}
        ans = 0
        
        for v in a:
            left = cnt.get(v - 1, 0)
            right = cnt.get(v + 1, 0)
            
            if left == 0 and right == 0:
                ans += 1
                cnt[v] = cnt.get(v, 0) + 1
                continue
            
            # choose better side to extend
            if left >= right:
                if left > 0:
                    cnt[v - 1] -= 1
                    if cnt[v - 1] == 0:
                        del cnt[v - 1]
                else:
                    cnt[v + 1] -= 1
                    if cnt[v + 1] == 0:
                        del cnt[v + 1]
            else:
                cnt[v + 1] -= 1
                if cnt[v + 1] == 0:
                    del cnt[v + 1]
            
            cnt[v] = cnt.get(v, 0) + 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码独立处理每个测试用例并仅维护端点计数。 字典`cnt`跟踪当前有多少子序列以每个值结束。 

分支逻辑确保只要两个邻居都存在，我们就会优先从人口较多的一侧进行消费。 这是贪婪选择唯一重要的部分； 其他一切都是保持端点一致性的直接结果。 

这里一个常见的实现陷阱是忘记在使用 from 之后`cnt[v±1]`，我们还必须增加`cnt[v]`，因为子序列继续并且其新端点转移到`v`。

 ## 边缘情况

 最小单元素输入表明，当不存在邻居时，算法可以正确初始化新的子序列。 

严格递增序列如`1 2 3 4 5`表明每个元素都可以链接到单个子序列中，因为每个步骤都有一个有效的 ±1 前驱，因此算法永远不会在第一个元素之后增加答案。 

交替序列，例如`1 2 1 2 1 2`强调需要小心重用端点。 每个`2`可以连接到`1`反之亦然，贪婪端点平衡可以防止不必要的额外子序列的创建。 

对称图案如`10 9 10 9`确认当双方始终可用时，算法一致地选择有效的扩展而不分割结构，从而恰好产生两个子序列。
