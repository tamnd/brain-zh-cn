 ## 解决方案
 ## 问题理解

 我们得到了多个独立的查询。 每个查询定义一个封闭的数字区间`l`到`r`，连同两个参数：目标数字和`x`和一个等级`k`。 在这个区间内，我们从概念上看所有正整数，其数字之和恰好等于`x`。 如果我们按升序列出这些数字，任务就是返回`k`- 此过滤列表的第一个元素。 如果少于`k`这样的数字存在，答案是`-1`。 

核心困难不在于过滤数字，而在于快速过滤。 的价值观`l`和`r`足够大以至于迭代范围内的每个整数是不可行的。 即使单个查询允许最多大约 10^18 个值，直接扫描它们也将远远超出任何时间限制。 

数字和约束引入了与间隔长度无关的结构。 问题不再是单独推理每个数字，而是减少到计算给定范围内存在多少个有效数字。 一旦我们能够回答“有多少个整数 ≤ n 的数字和恰好为 x”的前缀查询，区间版本就变成了两个前缀计数的差值。 

一个天真的方法会枚举所有数字`[l, r]`，计算数字和，收集有效数字，并选择第 k 个。 当以下情况时，这立即失败`r - l`很大。 例如，如果`l = 1`和`r = 10^18`，甚至单次通过也是不可能的。 

当在没有记忆的情况下实现数字和过滤时，会出现更微妙的失败情况。 重新计算每个数字的数字和很便宜，但仍然需要迭代整个范围。 瓶颈在于数字的数量，而不是每个数字的成本。 

真正的边缘情况是当`k`很大，但有效数字很少。 例如，在这样的范围内`[10^17, 10^18]`具有严格的数字和约束，例如`x = 1`，只有几个有效数字（例如十的幂）。 线性扫描在得出答案之前会进行近万亿次无用的检查。 

## 方法

 蛮力的想法很简单：迭代`l`到`r`，计算每个数字的数字和，存储那些匹配的`x`，并返回第 k 个元素。 这是正确的，因为它直接构造了所需的排序。 然而，它执行`O(r - l + 1)`每个查询的迭代次数，在最坏的情况下，这远远超出了可行的限制。 

关键的观察是条件“数字和等于 x”是前缀友好的。 我们可以计算有多少有效数字低于阈值，而不是扫描间隔`n`。 如果我们定义一个函数`F(n, x)`作为整数的个数`[0, n]`其数字和正好是`x`，然后计入`[l, r]`变成`F(r, x) - F(l - 1, x)`。 

这将问题转化为数字计数问题，这正是数字动态规划的设计目的。 一旦我们能够有效地计算前缀计数，我们就可以通过二分查找最小的数字来找到答案`y`在`[l, r]`使得有效整数的数量达到`y`区间内达到`k`。 

结构变为：数字DP用于计数，二分查找用于定位第k个元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(r − l) | O(1) | O(1) | 太慢了|
 | 数字DP+二分查找| 每个查询 O(log R · 数字 · x) | O(数字·x) | 已接受 |

 ## 算法演练

 我们通过两个概念层解决该问题：计算有效数字直至达到极限，并使用该计数函数来定位范围内的第 k 个有效数字。 

### 1. 构建一个数字DP计数函数

 我们定义一个函数`count(n, x)`返回有多少个整数`[0, n]`精确地得到数字和`x`。 我们从最高有效位到最低有效位处理数字，跟踪剩余的总和以及我们是否仍然受到前缀的限制`n`。 

在每个数字位置，我们尝试所有不超过当前限制约束的可能数字。 我们相应地减少剩余金额并继续递归。 状态通过位置、剩余金额和严格约束来记忆。 

这是可行的，因为任何数字都由其数字序列唯一表示，并且可行性仅取决于剩余的数字和容量。 

### 2. 将范围查询转换为前缀计数

 对于每个查询，我们计算区间内存在多少个有效数字`[l, r]`使用：`total = count(r, x) − count(l − 1, x)`如果`total < k`，答案立即`-1`。 

此步骤之所以有效，是因为数字 DP 给出了累积计数，并且减法隔离了间隔。 

### 3.二分查找第k个有效数字

 我们寻找最小的数`y`在`[l, r]`这样：`count(y, x) − count(l − 1, x) ≥ k`这个谓词是单调的`y`，因此二分查找完全适用。 条件成立的第一个位置恰好是第 k 个有效数字。 

### 为什么它有效

 正确性来自于两个单调结构。 第一的，`count(n, x)`不减于`n`，因为添加更大的上限永远不会删除有效数字。 二、限制区间`[l, r]`减去固定前缀后保持单调性`count(l - 1, x)`。 这保证了二分查找始终收敛到第 k 个元素出现的第一个有效阈值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def digit_dp(n, target_sum):
    s = str(n)

    @lru_cache(None)
    def dfs(pos, remaining, tight):
        if remaining < 0:
            return 0
        if pos == len(s):
            return 1 if remaining == 0 else 0

        limit = int(s[pos]) if tight else 9
        res = 0

        for d in range(limit + 1):
            res += dfs(pos + 1, remaining - d, tight and d == limit)

        return res

    return dfs(0, target_sum, True)

def count_upto(n, x):
    if n < 0:
        return 0
    return digit_dp(n, x)

def solve():
    t = int(input())
    for _ in range(t):
        l, r, k, x = map(int, input().split())

        base = count_upto(l - 1, x)
        total = count_upto(r, x) - base

        if total < k:
            print(-1)
            continue

        lo, hi = l, r
        ans = r

        while lo <= hi:
            mid = (lo + hi) // 2
            cur = count_upto(mid, x) - base

            if cur >= k:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```数字DP功能`digit_dp`负责计算有效数字直到边界。 关键状态是`(pos, remaining_sum, tight)`， 在哪里`tight`确保我们不超过前缀`n`。 记忆化至关重要，因为如果没有缓存，递归就会以指数方式多次重复相同的子问题。 

功能`count_upto`包装此 DP 并处理边缘情况`n < 0`，计算时需要`count(l - 1, x)`。 

主循环计算区间内有效候选者的数量，然后执行二分搜索`[l, r]`。 二分搜索中的谓词重用相同的计数逻辑，但按前缀基线进行移位。

如果`k = 2`，我们预计 12。

 输入：```

```中没有号码`[10, 20]`数字和为 50，因此总计数为零。 算法立即返回`-1`在第一次前缀差异检查后，不进入二分查找。

 ## 边缘情况

 一个棘手的情况发生时`l = 0`或者`l = 1`，由于计算`count(l - 1, x)`需要处理`-1`。 该实现对于负输入显式返回零，确保前缀减法行为正确。 

另一个微妙的情况是当`x = 0`。 只有号码`0`满足这一点，因此不包括零的范围必须立即返回`-1`。 DP 正确地处理了这个问题，因为它只接受数字末尾的数字和的全部消耗。 

当出现最终边缘情况时`k`等于范围内有效值的总数。 在这种情况下，二分查找仍然必须收敛于`r`如果`r`本身是有效的。 单调谓词保证正确选择正确的边界，而不会出现差一错误。
