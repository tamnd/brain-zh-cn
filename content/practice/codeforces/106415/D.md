 ## 解决方案
 ## 问题理解

 我们有一个完整的二叉任务树。 根任务一开始就可用。 每当处理一个任务时，它的两个子任务就可供将来处理。 有`p`处理器，因此在某一时刻我们最多可以完成`p`当前可用的任务。 变得可用的任务将保持可用状态，直到处理器处理它。 

目标是找到处理高度树中每个任务所需的最小时刻数`h`。 

输入包含许多独立的测试用例。 每个测试用例都给出树的高度和处理器的数量。 输出是该对所需的最小轮数。 

高度足够小，可以模拟关卡，但测试用例的数量可能非常大。 高度大约 50 意味着树本身可以容纳大约`2^50`节点，因此构建树甚至迭代所有任务都是不可能的。 我们需要一种取决于高度而不是节点数量的算法。 一个接近的解决方案`O(h)`每个测试用例的操作是预期的方向。 

一个常见的错误是在移动到下一个级别之前完全处理一个树级别。 处理器不是这样工作的。 未完成级别的剩余任务可以与更深级别的新创建任务一起处理。 

例如，与身高`3`和`2`处理器，正确答案是`4`。```
h = 3, p = 2
```轮数为：```
round 1: process root
round 2: process 2 children
round 3: process 2 of the 4 grandchildren
round 4: process remaining 2 grandchildren
```逐级模拟假设第三轮必须在考虑未来工作之前完成所有四个孙子，在较大的情况下可能会错误地计算。 

另一种边缘情况是处理器的数量大于某个级别中可用任务的数量。 例如：```
h = 2, p = 10
```该树只有三个任务。 正确的输出是：```
2
```第一轮处理根，第二轮处理两个子节点。 将每个级别大小除以的公式`p`并且忘记了级别之间的依赖关系可能会错误地回答`1`。 

第二个重要的情况是处理器没有精确划分级别大小。 例如：```
h = 3, p = 3
```正确的输出是：```
4
```处理完根及其两个子节点后，有四个任务。 第三轮处理其中三个，留下一个未完成的任务。 该剩余任务在下一轮中仍然可用，并且必须与新可用任务一起计数。 

## 方法

 直接的方法是想象树中的每个任务。 我们可以保留一个可用任务的队列，最多处理`p`每轮任务，并添加已处理节点的子节点。 这是正确的，因为它遵循实际的执行顺序。 然而，一个高度`50`二叉树大约包含`2^50`节点，这远远超出了任何实际内存或时间限制。 

有用的观察结果是，同一深度上的所有任务的行为都是相同的。 我们永远不需要知道单个任务的身份。 在深度`i`，新可用任务的数量恰好是`2^i`。 我们唯一需要的额外信息是有多少来自先前深度的任务仍在等待。 

蛮力模拟失败是因为它跟踪了太多细节。 树结构仅通过每个处理层之后可用的任务数量来影响。 我们可以将整个树压缩为计数序列。 

让`carry`表示已经可用但在完成一轮后尚未处理的任务。 当我们达到新的深度时，可用的任务变为：```
2^depth + carry
```处理器会删除尽可能多的内容。 每个完整的组`p`任务需要一轮，剩余的任务需要额外一轮。 余数成为下一个深度的进位。 

所有级别之后的最后一个进位代表在最深生成级别之后仍在等待的任务，因此它贡献了最后一轮。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^h) | O(2^h) | O(2^h) | O(2^h) | 太慢了|
 | 最佳| O(h) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 开始于`carry = 0`和`answer = 0`。 进位存储之前关卡中未完成的任务，而答案则计算已完成的回合数。 
2. 对于每个深度`0`到`h - 1`，计算该深度可用的任务为`2^depth + carry`。 价值`2^depth`是通过处理前一级别创建的节点数。 
3. 将可用任务划分为`p`。 每个完整的组`p`任务消耗一轮。 将商添加到答案中。 
4. 将余数存储为新进位。 这些是尚未完成的任务，并将在下一轮中继续完成。 
5、所有深度处理完毕后，如果`carry`不为零，则添加最后一轮，因为其余任务没有子任务，只需要处理器来完成它们。 

为什么这有效来自于每次迭代后的不变量，`carry`正是在当前深度上使用所有可能的完整处理器组后可用但未完成的任务数。 由于未来的轮次始终可以将这些任务与新生成的任务结合起来，因此仅保留此数字可以保留最佳计划所需的所有信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        h, p = map(int, input().split())

        carry = 0
        rounds = 0
        nodes = 1

        for _ in range(h):
            available = nodes + carry
            rounds += available // p
            carry = available % p
            nodes *= 2

        if carry:
            rounds += 1

        ans.append(str(rounds))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该循环一次处理树​​的一个深度，而不创建任何节点。`nodes`存储当前深度出现的任务数量，由于树是二叉树，因此每次迭代后都会加倍。 

划分由`p`计算可以立即完成多少个完整处理器批次。 剩余的任务不会被丢弃，因为这些任务仍在等待并且可以与未来的任务组合。 这是区分正确解决方案和简单关卡模拟的主要细节。 

这些值在数学描述中呈指数增长，但高度最多为 50，因此 Python 整数可以安全地处理它们。 该代码还避免了浮点运算，例如`2 ** h`使用对数近似，消除了精度问题。

 ## 边缘情况

 对于这个案例：```
1
2 10
```这棵树包含一个根和两个子节点。 该算法从一项可用任务开始，对其进行处理，然后查看两个子任务。 由于两个孩子都适合一轮处理器，所以答案是`2`。 它不会错误地将根和子级合并到同一轮中，因为在父级完成之前子级不存在。 

为了：```
1
3 3
```前两个深度创建了剩余任务。 该算法记录剩余部分而不是丢弃它。 在最后一个深度，可用量包括该等待任务，从而产生正确的答案`4`。 

为了：```
1
50 10000
```该算法永远不会分配与节点数量成比例的内存。 它仅将计数器加倍 50 倍并保持进位值，因此巨大的隐式树大小不会影响可行性。
