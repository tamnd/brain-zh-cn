 ## 解决方案
 ## 问题理解

 我们有一个以无向图表示的相连国家。 每个城市都是一个顶点，每条道路都是一条边。 一条道路可能已经可以使用，也可能已经损坏。 目标是在进行一些更改后仅使用工作道路从城市 1 行驶到城市 n。 

我们可以修复破损的道路或破坏工作道路。 更改后，唯一应保留的工作道路是属于从城市 1 到城市 n 的最短路径的道路。 在所有可能的有效最终状态中，我们必须改变尽可能少的道路并输出这些改变。 

关键是最终路径必须具有最小边数长度，而不是最小修复成本。 在所有最短路径中，我们更喜欢已经包含尽可能多的工作道路的路径，因为该路径上的每个破损边缘都需要修复。 

图的大小允许线性或接近线性的图算法。 由于顶点和边多达大约 10^5 个，检查每条可能的路径或尝试每条最短路径组合是不可能的。 我们需要接近 O((n + m) log n) 的东西，这指向标准的最短路径技术。 

一些边缘情况很容易被忽略。 如果最短路径包含破损的边缘，则即使另一条较长的路径可能已经完全工作，也必须修复该边缘。 例如：```
3 3
1 2 0
2 3 0
1 3 1
```最短路径的长度为 1，因此必须保留从 1 到 3 的直接道路。 如果需要，正确的输出会将另外两条道路更改为断开状态，而不是直接道路。 仅计算维修次数的贪婪方法可能会错误地选择穿过城市 2 的较长路径。 

另一种情况是存在多个最短路径。 例如：```
4 4
1 2 1
2 4 0
1 3 0
3 4 0
```两条路径的长度均为 2。正确的选择是经过城市 2 的路径，因为它只需要进行一次更改。 首先运行 BFS 并选择第一个发现的最短路径的方法可能会进行不必要的修复。 

最后一个常见错误是忘记所选最短路径之外的道路。 如果一条道路当前正在运行，但不是所选最短路径的一部分，则必须将其销毁。 例如：```
2 1
1 2 1
```道路已经是正确的，不需要改变。 在较大的图中，必须明确处理每条未使用的工作道路。 

## 方法

 直接的方法是首先找到城市 1 和城市 n 之间的所有最短路径，然后检查每条路径并选择断边最少的路径。 这是正确的，因为每个有效答案都必须恰好留下一条最短路径的工作道路。 然而，最短路径的数量可能是指数级的，因此即使在中等图上也无法枚举它们。 

使问题易于管理的观察结果是，目标可以折叠到最短路径搜索本身中。 我们首先需要边数最少的路径，并且在边数相同的路径中，断路数最少。 这可以通过为每条边分配一对成本来表示。 

一条可行的道路是有成本的`(1, 0)`因为它使路径长度增加一但不需要修复。 破碎的道路是有代价的`(1, 1)`因为它也会使长度增加一倍并且额外需要一次修复。 

如果我们使用这些对的字典顺序比较来运行 Dijkstra，算法首先会最小化距离，并且仅使用第二个值作为平局断路器。 保证生成的路径是所有最短路径中断路最少的最短路径。 

恢复这条路径后，其上的每条边都必须正常工作。 其破损的边缘已修复。 所有其他工作边缘都必须被摧毁。 改变的边的数量是最少的，因为所选择的路径已经最小化了修复的数量，并且它之外的所有其他工作边都必须在每个有效的最终图中消失。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最短路径数量呈指数增长 | O(n + m) | 太慢了|
 | 最佳| O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构建图表，同时存储每条道路及其端点、原始状态和索引。 稍后需要索引，因为输出需要更改的确切道路。 
2. 从城市 1 运行 Dijkstra，其中每个州存储两个值：已使用的道路数量和已使用的破损道路数量。 优先级队列总是按字典顺序处理最小的对。 
3. 松弛边缘时，添加`(1, 0)`用于工作道路和`(1, 1)`为了一条破路。 如果新对较小，则替换目标的当前最佳值。 
4. 每当城市收到更好的路径时，就存储父边缘。 如果城市 n 以其最终最短对到达，则这些父指针描述所选择的最佳路径。 
5. 使用父边从城市 n 向后走到城市 1，并根据需要标记该路径上的每条边都可以工作。 
6. 扫描所有道路。 如果道路位于所选路径上并且已损坏，则输出修复操作。 如果道路不在路径上并且正在工作，则输出破坏操作。 

工作原理：Dijkstra 保持不变式，即一旦从优先级队列中删除一个顶点，存储的对就是最小可能的对`(path length, number of broken edges)`在来自源的所有路径中。 由于成对比较首先考虑长度，因此恢复的路径总是最短的。 由于第二个部件在同等长度中最小化，因此需要的维修也最少。 所有剩余的改变都是强制的，因为每一条非道路工作道路都必须被拆除。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]
    edges = []

    for i in range(m):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        edges.append((a, b, c))
        graph[a].append((b, c, i))
        graph[b].append((a, c, i))

    inf = (10**18, 10**18)
    dist = [inf] * n
    parent = [-1] * n

    dist[0] = (0, 0)
    pq = [(0, 0, 0)]

    while pq:
        d, bad, u = heapq.heappop(pq)
        if (d, bad) != dist[u]:
            continue

        for v, c, idx in graph[u]:
            nd = d + 1
            nbad = bad + (1 - c)

            if (nd, nbad) < dist[v]:
                dist[v] = (nd, nbad)
                parent[v] = idx
                heapq.heappush(pq, (nd, nbad, v))

    on_path = [False] * m
    cur = n - 1

    while cur != 0:
        e = parent[cur]
        on_path[e] = True
        a, b, c = edges[e]
        if a == cur:
            cur = b
        else:
            cur = a

    ans = []

    for i, (a, b, c) in enumerate(edges):
        if on_path[i]:
            if c == 0:
                ans.append((a + 1, b + 1, 1))
        else:
            if c == 1:
                ans.append((a + 1, b + 1, 0))

    out = [str(len(ans))]
    for a, b, c in ans:
        out.append(f"{a} {b} {c}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```邻接列表保留每条道路的两个方向，因为在任一方向上都可以进行移动。 每个存储的边还携带其原始索引，以便路径重建可以标记准确的道路。 

Dijkstra 状态包含两个整数而不是一个。 第一个统计所有走过的道路，第二个统计其中的破损道路。 Python中的优先级队列排序自然地按字典顺序比较元组，这与所需的优化顺序相匹配。 

父数组存储用于到达每个城市的最后一条边。 Dijkstra 完成后，从城市 n 向后沿着这些边恰好标记出一条最佳最短路径。 

最终扫描是产生图形修改的地方。 路径边缘仅在破损时才需要修复。 路径之外的任何工作边缘都必须被销毁。 无需进行其他更改。 

## 工作示例

 考虑：```
4 4
1 2 1
2 4 0
1 3 0
3 4 0
```Dijkstra 的迹为：

 | 步骤| 当前城市 | 距离对| 行动|
 | ---| ---| ---| ---|
 | 1 | 1 | (0,0) | (0,0) | 添加城市 2 和 3 |
 | 2 | 2 | (1,0)| 使用 (2,1) | 添加城市 4
 | 3 | 3 | (1,1) | 城市4候选人更差|
 | 4 | 4 | (2,1) | 找到最终路径 |

 该算法选择路径1到2到4。它是最短的，并且只需要一次修复。 

另一个例子：```
3 3
1 2 0
2 3 0
1 3 1
```| 步骤| 当前城市 | 距离对| 行动|
 | ---| ---| ---| ---|
 | 1 | 1 | (0,0) | (0,0) | 城市 3 的直接边为 (1,0) |
 | 2 | 3 | (1,0)| 目的地已确定 |

 选择直接施工道路是因为在维修计数之前考虑了长度。 通过城市 2 的较长路径无关紧要。

 ## 边缘情况

 对于第一个边缘情况：```
3 3
1 2 0
2 3 0
1 3 1
```Dijkstra 为直接边分配的成本为`(1,0)`路线越长，成本为`(2,2)`。 由于第一个值占主导地位，因此立即选择直接道路。 最终扫描发现所有道路都已符合所需状态，因此输出为`0`。 

对于多个最短路径的情况：```
4 4
1 2 1
2 4 0
1 3 0
3 4 0
```两条可能的路径都有两条边。 经过城市 2 的路径会产生成本`(2,1)`，而通过城市 3 的路径接收到`(2,2)`。 第二个部分打破了平局，因此仅修复了 2 至 4 号道路。 

对于必须拆除的外部道路：```
4 5
1 2 1
2 4 1
1 3 1
3 4 1
1 4 0
```通过断开的直接道路，最短路径的长度为一。 Dijkstra有成本地选择它`(1,1)`因为每两条边的路线都更长。 该算法修复道路 1 至 4，并破坏不属于所选最短路径的两条工作道路。 这满足了最终图表仅包含最短路径的要求。
