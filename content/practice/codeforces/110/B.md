 ## 解决方案
 ## 问题理解

 我们需要构建一个长度为小写的字符串`n`满足重复字母的特殊条件。 

对于每个角色，我们都会查看它出现的所有位置。 如果一个字符出现多次，连续位置之间的差值一定是一个幸运数字。 在这个问题中，幸运数字是十进制表示仅包含数字的整数`4`和`7`。 

任务不仅仅是构造任何有效的字符串。 在所有长度有效的字符串中`n`，我们必须输出字典顺序最小的一个。 

约束足够小，直接构造答案是预期的方向。 和`n ≤ 10^5`，我们可以轻松负担线性时间，甚至`O(n log n)`，但是任何指数或基于字符串的强力搜索都是不可能的。 即使在一个小字母表上尝试所有字符串也会立即爆炸，因为有`26^n`可能的小写字符串。 

关键的困难是词典编纂的极简性。 天真的贪婪选择可能会意外地创建无效的未来状态。 我们需要一种始终有效且可证明最小的模式。 

当以下情况出现时，会出现一种容易被忽略的边缘情况：`n < 4`。 由于最小的幸运数字是`4`, distance 之前不能有重复的字母`4`。 例如：

 输入：```
3
```正确输出：```
abc
```过早重复字母的粗心解决方案可能会产生`"aba"`，但是两个`'a'`位置的不同之处在于`2`，这并不幸运。 

另一个微妙的情况是当字符串长度恰好是`5`。 

输入：```
5
```正确输出：```
abcda
```重复的`'a'`职位是`1`和`5`， 不同之处`4`，这是幸运的。 如果我们尝试过`"abcab"`相反，`'a'`位置的不同之处在于`3`， 无效的。 

第三个陷阱是假设我们需要很多幸运距离。 在实际应用中，距离`4`仅此一项就足以构建整个答案。 一些解决方案通过混合使构造变得过于复杂`4`和`7`，但这是不必要的。 

## 方法

 蛮力的想法很简单。 按字典顺序生成字符串并检查每个字符串是否满足条件。 为了验证字符串，我们存储每个字符的所有位置，并确保每个相邻的差异都是幸运的。 

验证本身很便宜，大致`O(n)`。 问题是候选字符串的数量。 即使是像这样的小字母表`{a,b,c,d}`, 已经有`4^100000`的可能性，这是完全不可行的。 

接下来的观察完全改变了问题。 我们实际上并不需要任意的幸运距离。 最小的幸运数字是`4`，如果字母的每次重复出现都恰好是`4`位置分开，条件自动满足。 

这表明重复的长度块`4`。 

考虑以下模式：```
abcdabcdabcd...
```每一个`'a'`出现的位置不同`4`。 这同样适用于`'b'`,`'c'`， 和`'d'`。 自从`4`很幸运，字符串是有效的。 

现在我们必须说明为什么这种模式在字典顺序上是最小的。 

为了按字典顺序最小化，在每个位置我们都需要不违反条件的最小可能字符。 第一个字符显然应该是`'a'`。 第二个不能是`'a'`因为距离`1`运气不好，所以就变成了`'b'`。 第三个不能是`'a'`或者`'b'`，所以就变成了`'c'`。 第四个变成`'d'`。 

在第五个位置，我们可以重用`'a'`因为之前的`'a'`正是`4`职位较早。 自从`'a'`是最小的有效选择，我们就接受它。 同样的推理永远重复，产生周期字符串`"abcd"`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建重复基本图案`"abcd"`。 
2. 逐个字符地构建答案。 
3、对于职位`i`, 附加`pattern[i % 4]`。 

这会重复该序列：```
a b c d a b c d ...
```4. 打印结果字符串。 

这样做的原因是同一个字符的每次重复出现都是准确的`4`位置分开。 自从`4`是一个幸运数字，每个字符列表内的所有邻接差异都有效。 

### 为什么它有效

 该建筑同时保留了两种属性。 

第一，有效性。 每个字符仅在恰好之后重复`4`职位。 连续相等的字母`'a'`,`'b'`,`'c'`， 和`'d'`总是有所不同`4`，这是幸运的。 

第二，词典编纂的极简性。 在每个位置，我们都会选择不违反规则的最小字符。 前四个位置必须全部不同，因为距离`1`,`2`， 和`3`并不幸运。 这迫使`"abcd"`。 之后，重复使用四个位置之前的角色是有效的，并且选择任何较小的角色是不可能的。 通过归纳法，周期`"abcd"`模式是最小的有效字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pattern = "abcd"

    ans = []
    for i in range(n):
        ans.append(pattern[i % 4])

    print("".join(ans))

solve()
```实现故意简单，因为构造本身就是整个解决方案。 

变量`pattern`存储重复块。 对于每个职位`i`，我们取`pattern[i % 4]`，循环索引`0, 1, 2, 3`。 

使用列表和`"".join()`是在 Python 中构建大型字符串的标准有效方法。 循环内重复的字符串连接可能会变成二次的。 

如果在头脑中使用基于一的推理，索引很容易出错。 模运算自然适用于从零开始的索引：

 | 我| 我 % 4 | 人物 |
 | --- | --- | --- |
 | 0 | 0 | 一个 |
 | 1 | 1 | 乙|
 | 2 | 2 | c |
 | 3 | 3 | d |
 | 4 | 0 | 一个 |

 这恰好产生了预期的周期序列。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    pattern = "abcd"

    ans = []
    for i in range(n):
        ans.append(pattern[i % 4])

    print("".join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue().strip()

# provided sample
assert run("5\n") == "abcda", "sample 1"

# minimum size
assert run("1\n") == "a", "single character"

# small boundary
assert run("4\n") == "abcd", "first full block"

# repeat begins
assert run("8\n") == "abcdabcd", "two full blocks"

# off-by-one check
assert run("9\n") == "abcdabcda", "correct modulo cycling"

# large input
res = run("100000\n")
assert len(res) == 100000, "maximum size length"
assert res[:8] == "abcdabcd", "pattern consistency"

 ## 边缘情况

 当`n = 1`，算法输出：```
a
```没有重复的字符，因此条件为空。 该结构自然地处理了这个问题，因为它只采用模式的第一个字符。 

什么时候`n = 3`，算法输出：```
abc
```追踪：

 | 职位| 人物 |
 | --- | --- |
 | 0 | 一个 |
 | 1 | 乙|
 | 2 | c |

 没有字符重复，这避免了无效距离，例如`1`,`2`， 或者`3`。 重用的粗心贪婪解决方案`'a'`太早的话会失败。 

什么时候`n = 5`，输出变为：```
abcda
```两人`'a'`职位是`1`和`5`， 不同之处`4`。 这是重复变得合法的第一个时刻，算法立即利用它来保持字典顺序最小化。 

对于非常大的输入，例如`100000`，该模式周期性地继续，没有任何额外的逻辑。 每次重复出现的情况仍然完全不同`4`，所以正确性不依赖于字符串长度。
