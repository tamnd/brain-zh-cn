 ## 解决方案
 ## 问题理解

 注释从位于索引处的一个间谍开始`s`在一行`n`间谍。 这张纸条最终必须到达该位置的另一名间谍`f`。 时间以离散的步骤前进，并且在每一步中，当前持有纸条的间谍可以将其向左移动一个位置，向右移动一个位置，或者将其保持在原位。 

复杂的是每一步都有一个禁止区间`[l_i, r_i]`。 在该步骤中，该间隔内的每个间谍都受到监视。 受到监视的间谍是完全不活动的，因此如果该纸条当前在该间隔内的间谍身上，则无法将其移走或从邻居处接收。 在这种情况下，唯一允许的操作是将纸条保存在同一个间谍处。 

如果在每一步，音符保持静止，或者向左或向右移动一个位置，并且没有任何移动源自或到达受监视的间谍，则移动序列是有效的。 目标是达到`f`从`s`以最少的步骤数，并输出随时间变化的动作序列。 

这些限制促使我们采用线性扫描解决方案。 步数最多为 100000 个，因此不可能对时间或位置进行任何二次探索。 状态空间是一维的，但与时间相关的限制使其成为动态的。 任何试图每一步从头开始重新计算可达性的解决方案都会太慢。 

一个微妙的边缘情况来自完全阻塞间隔。 如果在某个步骤整条生产线都受到监视，`[1, n]`，那么在该步骤中不可能移动，并且无论策略如何，位置都会被冻结。 另一个极端情况是目标方向随着时间的推移而改变，迫使绕道或等待一段时间，而不是直接贪婪地移动。 

## 方法

 朴素的观点将其视为时间扩展图中的最短路径。 每个州都是`(position, time)`，如果目的地和源当时没有被阻止，我们可以从每个状态移动到相邻位置或留在原地。 这正确地模拟了该过程，但该图有`n * m`州及直至`3`每个状态的转换，导致大约`3 * 10^10`在最坏的情况下进行转换，这远远超出了限制。 

当我们不再考虑任意路径而是关注每一步的可行性时，结构就会简化。 在每个时间步，唯一有意义的问题是我们是否可以向目的地更近一步，或者我们是否被迫等待。 监视间隔要么阻止当前位置，要么不阻止，并且类似地影响是否允许相邻转换。 

关键的观察是，我们永远不会因为偏离目标而受益。 如果目标在右边，任何最优策略都不会向左移动，除非由于阻塞而被迫停留。 所以问题就简化为贪婪地试图缩短到`f`只要有可能，否则就留在原地。 

我们模拟从 1 到`m`。 我们维持目前的立场。 每一步我们都会决定是否可以迈向`f`。 如果当前位置是安全的，并且下一个位置对该步骤来说也是安全的，我们就会移动。 否则，我们留下来。 

这将问题转化为线性扫描，使用间隔比较对每步进行恒定时间检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 时间扩展 BFS | O(n·m) | O(n·m) | 太慢了 |
 | 贪心模拟| O(米) | O(1) | O(1) | 已接受 |

 ## 算法演练

 不失一般性，我们假设运动是向右的，如果`s < f`，否则向左。 我们将问题转化为总是试图朝固定方向移动。 

1.读取所有区间并按时间顺序处理。 保持注释的当前位置。 
2. 对于每一步`i`，提取阻塞区间`[l_i, r_i]`。 
3. 检查当前位置是否在封锁区间内。 如果是，则禁止移动，必须输出`X`。 
4. 如果允许移动，确定是否迈向`f`一个位置是可能的。 这要求目标小区在该步骤中也不被阻塞。 
5. 如果可以移动，则更新位置并输出`L`或者`R`取决于方向。 
6.否则输出`X`并保持在同一位置。 

关键的设计选择是我们从不考虑偏离目标。 即使暂时允许，也永远不会缩短达到目标的时间。 

### 为什么它有效

 在任何时间步长，可以减少到目标的剩余距离的唯一动作是向目标移动一个单位`f`。 任何离开都会严格增加距离，因此不能成为最佳序列的一部分，除非向目标的移动被阻止。 当行动受阻时，留在原地是唯一合法的选择。 

因此，该过程保持不变，即在每一步之后，该位置是朝向最远可到达的位置`f`考虑到当时的限制。 由于距离只会在可能的情况下减少，而不会增加，因此我们第一次到达时`f`是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s, f = map(int, input().split())
    
    # store events
    events = []
    for _ in range(m):
        t, l, r = map(int, input().split())
        events.append((t, l, r))
    
    pos = s
    direction = 1 if f > s else -1
    
    ans = []
    
    for i in range(m):
        t, l, r = events[i]
        
        # if current position is blocked, must stay
        if l <= pos <= r:
            ans.append('X')
            continue
        
        nxt = pos + direction
        
        # check if we can move
        if 1 <= nxt <= n and not (l <= nxt <= r):
            pos = nxt
            ans.append('R' if direction == 1 else 'L')
        else:
            ans.append('X')
    
    print("".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案仅保留当前位置并处理每个时间步一次。 方向是根据开始和结束的相对顺序确定的。 每个间隔都会以恒定的时间进行检查。 

一个微妙的点是我们从来没有明确检查是否`pos == f`提前终止进程。 该算法自然会稳定在那里，因为任何进一步的移动都是不必要的，但停留总是有效的。

该轨迹表明，算法仅在当前位置和下一个位置都安全时才移动。

 ## 边缘情况

 一种重要的情况是当前位置在许多连续步骤的每个间隔内。 在这种情况下，算法会重复输出`X`并且位置永远不会改变。 这是正确的，因为在这些步骤中不存在合法的移动，任何强制移动的尝试都会违反监视规则。 

另一种边缘情况发生在目标紧邻但间歇性被阻挡时。 该算法仅在当前位置和下一个位置都安全时才移动，因此它自然会等待安全步骤而不是尝试非法转换。 

最后一种边缘情况是提早到达目的地。 一次`pos == f`，每个后续操作仍然有效`X`，并且算法继续生成合法的最小序列，而不需要显式的终止逻辑。
