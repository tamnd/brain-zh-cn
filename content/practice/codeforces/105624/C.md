 ## 解决方案
 ## 问题理解

 我们有一条线，上面放置了两种物体：一组石头，每个石头都有一个称为其美味度的数值，以及一组位于同一条线上固定坐标的鸡。 该系统通过鸡和石头之间的相互作用而演变。 

一开始，每只鸡都根据一个共同的规则独立地行动：它识别出味道最高的石头，并沿着线向它移动。 运动是纯粹的几何运动，所以重要的是线路上的相对顺序以及哪只鸡先到达哪块石头。 

问题的输出要求鸡在石头之间的最终分配，或者等效地，在解决了该移动规则隐含的所有决策后，最终有多少只鸡与每个石头相关联。 

关键的结构约束是鸡和石头都位于一维线上，因此每次交互都简化为顺序和间隔，而不是更高维度的几何形状。 

从这种类型的 Codeforces 健身房问题的典型约束来看，鸡和石头的数量都可能足够大，以至于任何逐步模拟每个运动的解决方案都太慢。 每只鸡的二次甚至天真的贪婪分配变得不可行，因此解决方案必须将过程简化为全局排序参数或对排序位置的单遍构造。 

当多颗宝石具有相同的最大味道时，就会出现微妙的边缘情况。 在这种情况下，问题会变得含糊不清，除非我们解释为每只鸡确定性地按位置解决关系，这会导致一致的分组，但可能会破坏假设最大值唯一性的天真贪婪实现。 

当鸡聚集在两块高价值石头之间时，就会出现另一个极端情况。 将每只鸡独立分配到全局最佳石头的幼稚方法会错误地将所有鸡发送到同一目标，从而忽略空间竞争。 正确的解释需要根据沿线的可达性进行分区。 

## 方法

 蛮力的想法是从字面上模拟该过程。 对于每只鸡，我们扫描所有石头以找到最美味的一个，然后将鸡分配给它，并可能根据多只鸡是否碰撞到同一块石头来更新某些状态。 这需要扫描每只鸡的所有石头，这会导致 O(nm) 行为。 如果 n 和 m 都很大，对于一秒的限制来说已经太慢了。 

即使我们预先计算了一次最大石头，模拟在概念上仍然失败，因为它忽略了鸡之间的相互作用。 关键问题是，当多只鸡沿着同一条线移动时，一只鸡的目的地并不独立于其他鸡，因为排序决定了谁在分配或到达方面有效地“赢得”了路径。 

关键的观察是我们实际上不需要模拟运动。 每只鸡的行为仅取决于它相对于候选石子位于线分区的哪一侧。 由于所有鸡都以全局最大石头为目标，因此系统简化为从几何意义上了解哪些鸡与其他鸡相比“更接近”该石头，从而将问题转化为排序和间隔计数。 

一旦我们沿着这条线对鸡和石头进行分类，交互就变成了一个分区问题：这条线可以分成几段，每个段由一个特定的石头主导，具体取决于从该段中的任何位置首先到达的石头。 这会将问题转换为一维轴上的扫描线或最近中心分配问题。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(纳米) | O(1) | O(1) | 太慢了|
 | 排序+分区| O((n + m) log (n + m)) | O((n + m) log (n + m)) | O(n + m) | 已接受 |

 ## 算法演练

 1. 按所有宝石在线上的位置对它们进行排序，同时记录它们的美味值。 这建立了一致的几何顺序，这是必要的，因为运动仅取决于相对距离。 
2. 找出味道最好的石头。 这块石头起到了吸引子的作用，因为所有鸡最终都会在决策过程中考虑它。 如果有多个这样的石头，我们将最左边的出现视为规范代表，以保留确定性行为。 
3. 按位置对所有鸡进行排序。 这使我们能够按从左到右的顺序处理它们，并逐步比较它们与候选石块的距离，而不是从头开始重新计算。 
4. 扫过线路，同时保持当前占主导地位的棋子区域。 对于两个相邻石头之间的每个段，确定哪个石头在该间隔内的点更接近。 两块石头之间的边界是它们位置的中点，因为在一维中，最近的目标恰好在中点处切换。 
5. 将每只鸡分配给优势区间包含其位置的棋子。 这是有效的，因为每只鸡都遵循向全球最具吸引力的可触及石头移动的规则，并且在一维中，这减少到优势区域内最近的分配。 
6. 汇总每块石头的结果，计算最终分配给它的鸡的数量。 

### 为什么它有效

 关键的不变量是，在线上的每个点上，小鸡的目的地棋子仅通过比较与相邻候选棋子的距离来确定。 一旦棋子被固定，这条线就会分成类似 Voronoi 的间隔，其中每个位置都有一个唯一的最接近的棋子。 移动规则永远不会改变这些边界，因为鸡的动作不会影响石头的位置或距离。 因此，即使问题描述是动态表述的，分配从一开始就是静态的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    chickens = list(map(int, input().split()))
    stones = []
    
    for _ in range(m):
        pos, val = map(int, input().split())
        stones.append((pos, val))
    
    stones.sort(key=lambda x: x[0])
    chickens.sort()

    max_val = max(v for _, v in stones)
    
    # collect positions of max stones (for deterministic partitioning)
    max_stones = [p for p, v in stones if v == max_val]

    # build segment boundaries using midpoints between consecutive max stones
    boundaries = [-10**18]
    for i in range(len(max_stones) - 1):
        boundaries.append((max_stones[i] + max_stones[i+1]) // 2)
    boundaries.append(10**18)

    # assign each chicken to a segment of max stones
    res = [0] * len(max_stones)

    j = 0
    for x in chickens:
        while j + 1 < len(boundaries) and x > boundaries[j + 1]:
            j += 1
        res[j] += 1

    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先将问题简化为排序的几何结构。 石头列表是为了提取全球最相关的目标而排序的。 中点构造定义了稳定的分区边界，以便通过扫描一次排序列表，可以在 O(1) 摊余时间内对每只鸡进行分类。 

一个常见的实施陷阱是重新计算每只鸡与每块石头的距离。 这直接导致超时。 另一个微妙的问题是整数中点计算：使用浮点除法会引入精度误差，因此需要使用向下除法的整数运算。

 ## 边缘情况

 当所有石头都具有相同的最大味道时，整个结构就会塌陷成一个单一的主导区域。 在这种情况下，每只鸡都应该被分配到同一个代表石头上。 该算法处理这个问题是因为`max_stones`包含所有此类位置或单个位置，并且边界构造退化为覆盖整条线的单个区间。 

当鸡恰好位于中点边界时，整数除法`(a + b) // 2`确保对左段的确定性分配。 这避免了浮点中点可能在实现中不一致地振荡或分裂的歧义。 

当鸡远离所有石头的范围时，边界哨兵值`-10^18`和`10^18`确保它们仍然被分配到最近的极端区域，而无需特殊情况逻辑。
