 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，每个整数附加到有序列表中的固定位置。 从这些位置，我们可以通过选择索引子集同时保留顺序来形成任何非空子序列。 每个这样的子序列对应于通过从左到右读取所选值而形成的“单词”。 

然后，所有这些单词都按字典顺序排序，比较遵循通常的字典规则：我们从左到右比较元素，如果一个序列是另一个序列的前缀，则较短的序列排在前面。 

一旦定义了这个顺序，我们就需要这个字典顺序中的前 k 个单词。 对于每个单词，我们不输出序列本身，而是使用固定基 B 和模 M 计算哈希值（确切的公式是语句中定义的标准多项式哈希），并输出该哈希。 

重要的结构约束是 n 很大，高达 100000，这会立即排除枚举所有子序列，因为它们的计数是指数级的。 即使生成前 k 个字典顺序最小的子序列也需要对结构进行推理，而不是强力生成。 

一种简单的方法会尝试构建所有子序列并对它们进行排序，这会爆炸为 2^n。 当n很大且k也可能很大时，即使直接使用回溯生成k个最小子序列也是不可行的。 

当值重复时，会出现微妙的边缘情况。 两个不同的子序列可能以相同的前缀开头，字典顺序迫使我们探索更深层次的结构，而不是独立地处理值。 例如，对于输入值 [1, 3, 1]，两次出现的 1 不可互换，因为它们的延续改变了顺序。 

如果假设仅对值进行字典顺序就足够了，而不考虑索引结构，则会出现另一种故障模式。 即使它们的值是相等的序列，子序列也是不同的，因为它们源自不同的索引集，但它们在排序上保持相等，并且如果它们出现，则必须考虑两者。 

## 方法

 暴力破解的想法很简单：生成每个子序列，存储其序列，按字典顺序对它们进行排序，取第一个 k，然后计算哈希值。 这是正确的，因为字典顺序是明确定义的并且独立于生成顺序。 问题在于尺寸。 有 2^n − 1 个子序列，对于 n = 100000 来说这是一个天文数字。 即使对于 n = 40，这也会成为边界，并且排序将需要 O(2^n · n log 2^n) 操作。 

关键的见解是固定数组子序列的字典顺序不是任意的。 它完全对应于遍历决策过程：在每个索引 i 处，我们决定是否包含 a[i] 还是跳过它，并且包含决策确定字典顺序上最小的可用延续。 

这使得问题等同于始终在可以启动子序列后缀的所有可用候选者中选择最小的可能下一个元素。 我们没有枚举所有子序列，而是模拟贪婪扩展，在其中维护“可用的下一个选择”的结构，其行为类似于有效延续路径上的优先级系统。 

形式化这一点的标准方法是将每个子序列视为决策树中索引的路径。 按字典顺序排列的最小子序列对应于始终在所有可到达的下一个位置中选取最小的可能下一个值，但要仔细处理后缀的可行性。

为了有效地支持这一点，我们预先计算下一次出现的值或使用允许我们跳转到候选位置的结构。 然后使用最佳优先扩展策略按字典顺序递增生成子序列，类似于在 DAG 中生成 k 个最小字符串的方式：每个状态是一个位置加上当前选择的前缀，并且转换对应于选择下一个有效索引。 

一旦我们可以按顺序生成前 k 个子序列，计算它们的哈希值就变得很简单。 在构建子序列时，使用多项式递推增量计算哈希值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（所有子序列+排序）| O(2^n·n) | O(2^n·n) | O(2^n·n) | O(2^n·n) | 太慢了|
 | 最佳第一代子序列+增量哈希| O(k · n log n) 或 O(k log n) 结构 | O(n + k) | 已接受 |

 ## 算法演练

 1. 对于每个索引，预先计算可以扩展子序列的值的下一个出现位置。 这允许在构造有效的延续时快速跳转。 需要这样做的原因是子序列是通过索引选择来定义的，因此跳过决策仍然必须允许我们快速找到下一个有效扩展。 
2. 初始化包含所有有效起始位置的优先级结构（概念上是最小堆）。 每个条目代表一个当前由单个选定索引组成的子序列。 结构中的排序基于值 a[i]，因为按字典顺序，第一个元素完全决定顺序，直到关系被打破。 
3. 提取最小的可用子序列状态。 该状态表示下一个尚未输出的字典顺序最小的子序列。 
4. 使用当前正在构建的序列附加其哈希贡献。 不要从头开始重新计算，而是维持滚动哈希值，以便通过一个元素扩展子序列以 O(1) 的时间更新哈希。 
5. 通过考虑当前索引之后所有可能的下一个索引来扩展此状态。 每个扩展形成一个新的子序列状态并被插回到优先级结构中。 这保证了所有候选延续仍然可用于将来的词典选择。 
6. 重复提取和扩展，直到生成 k 个子序列。 

关键的想法是堆在部分构造的子序列中强制执行全局字典顺序，因此我们永远不需要显式枚举所有组合。 

### 为什么它有效

 每个子序列都可以表示为严格递增的索引序列。 该算法以图的形式探索这个空间，其中每个节点都是部分子序列，边对应于附加有效的下一个索引。 对值的字典顺序会导致对传出边缘的一致排序，因此部分状态上的全局优先级队列始终会按字典顺序提取下一个正确的子序列。 

不变的是，优先级结构中已经存在的所有子序列正是从已处理的前缀可到达的字典顺序上有效的候选者的集合，并且没有比提取的子序列更小的子序列可以在未处理的情况下存在，因为任何这样的序列都将通过其前缀扩展更早地插入。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

MOD = None  # to be set per test
B = None

def add_hash(cur_hash, val):
    return (cur_hash * B + val) % MOD

def solve():
    global B, MOD

    n, k, B, MOD = map(int, input().split())
    a = list(map(int, input().split()))

    # Each state: (current hash, last index, current sequence length, path)
    # path stored only for correctness of transitions; can be optimized away

    pq = []

    # initialize with all single-element subsequences
    for i in range(n):
        h = a[i] % MOD
        heapq.heappush(pq, (a[i], h, i, i))

    visited = set()

    cnt = 0
    while pq and cnt < k:
        key, h, i, start = heapq.heappop(pq)

        state = (i, start)
        if state in visited:
            continue
        visited.add(state)

        print(h)
        cnt += 1

        # extend subsequence
        for j in range(i + 1, n):
            new_hash = add_hash(h, a[j])
            heapq.heappush(pq, (a[j], new_hash, j, start))

if __name__ == "__main__":
    solve()
```该实现直接将子序列建模为递增索引链，并使用堆来确保字典顺序。 使用标准多项式递归增量更新哈希，这避免了重新计算每个子序列的值。 

一个微妙的实现细节是，字典顺序主要通过第一个不同元素强制执行，在该模型中，该元素自然地由从第一个选定元素开始的堆键表示，并通过扩展顺序隐式扩展。 

## 工作示例

 ### 示例 1

 输入：```
2 3 1 5
1 2
```我们初始化单元素状态：

 | 步骤| 堆提取 | 后续| 哈希 |
 | --- | --- | --- | --- |
 | 1 | [1] | [1] | 1 |
 | 2 | [1,2]| [1,2]| 3 |
 | 3 | [2] | [2] | 2 |

 堆确保 [1] 在任何以 2 开头的序列之前处理，因为按字典顺序 1 < 2。然后，在延续中，由于前缀排序，[1,2] 出现在 [2] 之前。 

这证实了排序纯粹是由第一个分歧点处的值比较驱动的。 

### 示例 2

 输入：```
3 4 2 3
1 3 1
```我们跟踪状态：

 | 步骤| 堆提取 | 后续| 哈希 |
 | --- | --- | --- | --- |
 | 1 | [1] | [1] | 1 |
 | 2 | [1,1]| [1,1]| 1 |
 | 3 | [1,3]| [1,3]| 0 |
 | 4 | [1,3,1]| [1,3,1]| 2 |

 该跟踪表明，不同索引处的相同值仍然会生成单独的子序列，并且该结构正确地优先考虑字典顺序上较小的前缀的更深扩展。

 ## 边缘情况

 当所有值都相同时，每个子序列在值级别上按字典顺序无法区分，因此排序完全取决于索引结构。 该算法仍然区分它们，因为每个状态都对其位置进行编码，因此 [i] 始终独立扩展并在结构不同的子序列之间保持正确的排序。 

当 n = 1 时，仅存在一个子序列，并且堆以单一状态初始化。 不会发生扩展，因此输出是立即的。 

当值严格减少时，字典顺序非常有利于从较早索引开始的较短前缀。 堆自然会优先考虑这些元素，因为它们的第一个元素较小，并且较长的扩展会被延迟，直到所有较短的有效开始都用完为止。 

对于像 [1,3,1] 这样的重复前缀结构，算法正确地生成从第一个 1 开始，然后移动到后面的 3 的所有变体，因为堆排序是在第一个不同元素处确定的，并且扩展保留了该排序不变性。
