 ## 解决方案
 ## 问题理解

 该问题描述了一只鹦鹉已经沿着坐标网格上部分书写的路线行驶。 该路线由四个移动命令组成：向右、向左、向上或向下移动。 执行现有命令后，鹦鹉处于某个位置。 目标是找到必须附加到路线末尾的最少数量的额外命令，以便鹦鹉到达给定的目的地点。 

输入给出了当前路线、长度以及鹦鹉需要到达的最终坐标。 输出只是所需的额外移动次数，而不是实际的移动顺序。 

这些约束使预期的想法比搜索问题简单得多。 如果路线长度最多几百个字符，直接模拟运动只需要线性时间。 即使路线长度更长，单次通过仍然是正确的方法，因为每个命令都会独立影响最终位置。 任何尝试探索可能路径或模拟转弯的解决方案都是不必要的，因为鹦鹉可以在给定前缀之后选择任何命令。 

主要的边缘情况来自正确处理最终位置。 粗心的实现可能会假设目标始终位于右上角，而忘记剩余距离可能需要向左或向下移动。 例如，输入：```
1
R
0 0
```鹦鹉结束于`(1, 0)`。 正确的输出是：```
1
```因为左移一步就足够了。 仅添加正坐标差的实现将错误地产生零。 

另一种情况是当前路线已经到达目的地时。 例如：```
2
RU
1 1
```正确的输出是：```
0
```因为不需要额外的命令。 总是添加至少一步的代码在这里会失败。 

第三个常见错误是将当前位置与目的地坐标混淆。 为了：```
3
DDD
0 -5
```当前位置是`(0, -3)`，所以剩下的距离是向下移动两步。 正确的输出是：```
2
```直接比较目标坐标与路线长度或忽略模拟位置的解决方案将无法正确处理此问题。 

## 方法

 最直接的方法是尝试通过考虑所有可能的附加命令序列来解决问题。 由于每个新动作都可以是四个方向之一，因此需要对深度进行强力搜索`k`会检查`4^k`的可能性`k`添加了命令。 这是正确的，因为它会检查每条可能的路由延伸，但它呈指数增长，很快就变得不可能。 

暴力是不必要的，因为网格有一个有用的属性：当我们只关心最终位置时，移动的顺序并不重要。 现有的命令只是确定鹦鹉距离目的地有多远。 一旦我们知道了水平和垂直的差异，就可以强制选择最短路径。 每个水平差异都需要一次水平移动，每个垂直差异都需要一次垂直移动。 

观察到两个网格点之间的曼哈顿距离给出了轴对齐移动的最小数量，从而将整个问题简化为单个模拟过程，然后进行简单的计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(4^k) | O(4^k) | O(k) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取现有路线，从原点进行模拟。 每次向右移动时增加 x 坐标，每次向左移动时减少 x 坐标，每次向上移动时增加 y 坐标，每次向下移动时减少 y 坐标。 这给出了路线已知部分之后的确切位置。 
2. 计算目标位置与当前 x 坐标之间的水平差。 计算目标与当前 y 坐标之间的垂直差。 这些值描述了鹦鹉在每个方向上仍需要行驶多远。 
3. 将两个差值的绝对值相加。 结果是最少的额外移动次数，因为每次移动可以精确地改变一个坐标一个单位。 

为什么它有效：不变的是，在处理给定路线的任何前缀之后，存储的坐标与鹦鹉在该前缀之后的真实位置完全匹配。 处理完整个路线后，就知道到达目的地的剩余位移。 任何有效的延续必须修复水平和垂直差异的每个单位，至少需要`abs(dx) + abs(dy)`移动。 直接沿着这些差异移动就可以实现那么多移动，因此该值既是下限又是可以实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    x, y = map(int, input().split())

    cx = 0
    cy = 0

    for c in s:
        if c == 'R':
            cx += 1
        elif c == 'L':
            cx -= 1
        elif c == 'U':
            cy += 1
        elif c == 'D':
            cy -= 1

    print(abs(x - cx) + abs(y - cy))

if __name__ == "__main__":
    solve()
```代码的第一部分读取路线信息并初始化鹦鹉在原点的位置。 模拟循环遵循算法演练中描述的相同转换，因此坐标始终表示处理后的前缀之后的实际位置。 

最终表达式使用绝对差，因为鹦鹉可能需要在任一方向上纠正其位置。 不需要自己构建命令，因为只需要它们的最小计数。 

该实现不使用任何数组或额外的数据结构。 它还通过扫描一次路由来避免不必要的字符串操作。 Python 整数对于这些坐标计算不存在溢出问题。

 ## 边缘情况

 对于目的地需要沿与当前路线相反的方向移动的情况，该算法有效，因为它从不假设方向。 在：```
1
R
0 0
```模拟给出`(1, 0)`。 差异是`-1`水平和`0`垂直，所以答案变成`abs(-1) + abs(0) = 1`。 

当路线已到达目标时，剩余位移为`(0, 0)`。 为了：```
2
RU
1 1
```模拟结束于`(1, 1)`，做出答案`0`。 该算法不会添加不必要的动作。 

对于创建负坐标的路径，模拟仍然遵循相同的规则。 在：```
3
DDD
0 -5
```鹦鹉到达`(0, -3)`。 剩余垂直距离为`-2`，并且绝对值给出了正确答案`2`。 坐标的符号仅决定方向，而不决定所需的移动次数。
