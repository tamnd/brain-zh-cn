 ## 解决方案
 ## 问题理解

 给定一个正整数数组，并要求我们构建一系列不重叠的子数组。 这些子数组必须按从左到右的顺序选择，并且它们的长度是固定的，以形成从某个值开始的递减序列$k$下降到$1$。 所以第一个选择的线段有长度$k$，第二个有长度$k-1$，依此类推，直到最后一段有长度$1$。 所有片段必须按位置升序出现，并且不得重叠。 

在所有这些有效的结构中，我们希望最大化我们可以选择的段数，即最大化$k$，在附加约束下，当我们移动序列时，每个选定段内的元素总和必须严格增加。 

关键的困难在于段长度不是任意的，它们被严格限制为固定的降序模式，并且我们必须同时尊重数组中的排序和增加总和约束。 

约束条件允许$n$最多$10^5$跨测试用例。 这排除了任何显式尝试所有段分区的三次甚至二次方法。 甚至$O(n^2)$在最坏的情况下，每个测试用例都太慢，因为$n$可以很大并且最多有 100 个测试用例。 我们需要每个测试用例接近线性或线性对数的东西。 

当早期的选择迫使稍微次优的总和随后阻塞更长的链时，天真的贪婪想法的微妙失败案例就会出现。 例如，选择给定长度的局部最大和段可能会阻止形成更长的有效链，因为未来的段取决于位置和和排序。 

另一个常见的陷阱是假设我们可以独立地为每个长度选择最佳片段。 这会失败，因为段位置受到全局限制：一旦我们放置了长度$k$段，所有较短的段必须严格位于右侧。 

## 方法

 暴力方法将尝试枚举第一段长度的所有可能选择$k$，然后递归选择下一段长度$k-1$， 等等。 对于每个段长度，我们将尝试所有有效的起始位置，动态或通过前缀和计算总和，并强制执行递增顺序约束。 

即使前缀和使每个范围和$O(1)$，选择段起点的方法数量是组合的。 在最坏的情况下，这就像探索数组的许多分区，它随着$n$。 这是不可行的$n = 10^5$。 

关键的结构观察是我们永远不需要明确地决定固定的所有段$k$从头开始。 相反，我们可以逆向思考：对于一个固定的$k$，我们希望从左到右贪婪地放置段，始终放置所需长度的最早可能的有效段，从而产生严格递增的和序列。 

更深入的见解是我们不需要修复$k$直接地。 相反，如果我们总是贪婪地扩展一条有效链，我们可以计算可以构建多长的链。 每一步都会减少数组的剩余可用长度，问题就变成了对给定的可行性检查$k$，这表明二分搜索。 

然而，我们可以做得更好。 因为所有$a_i > 0$，段总和随着段位置右移而增加，但长度并非严格单调。 这允许贪婪的构造总是尝试尽可能远地扩展链而不需要二分搜索。 

我们维护一个指向下一个可用起始位置的指针，并迭代地尝试选择所需长度的段，使其总和大于先前选择的总和。 由于所有值都是正数，一旦一个段在某个位置变得有效，向右移动它只会增加其总和，因此我们可以贪婪地为每个长度放置最早的有效段。 

这将问题简化为一次从左到右的扫描，并仔细维护段总和。

 ## 算法演练

 我们预先计算前缀和，以便可以在恒定时间内查询任何段和。 这是必要的，因为我们反复评估候选片段。 

然后，我们尝试从不同的潜在值开始构建最长的链$k$，而不是显式地测试每个$k$，我们观察到我们可以模拟一次该过程并测量形成了多少个段。 

1. 计算数组的前缀和，以便快速查询范围和。 这允许对任何段总和进行恒定时间评估，这是至关重要的，因为我们将重复比较候选段的总和。 
2. 从数组的左侧开始，用一个指针指示下一段可以开始的最早位置。 最初，这是位置 1。 
3. 尝试按照长度递减的顺序放置段，而不是预先定义$k$，我们贪婪地增长链条。 我们维护要尝试的下一个段的长度以及最后选择的段的总和。 
4. 对于给定的段长度，从当前指针开始扫描，找到最早存在有效段且其总和严格大于前一个段总和的位置。 
5. 一旦找到这样的段，就提交它，更新最后的和，并将指针移动到该段之后的位置。 
6. 继续将段长度减 1 并重复该过程，直到无法放置有效段。 
7. 成功放置线段的数量就是答案。 

关键的决定始终是为每个长度选择最早的有效段。 这可以防止过早浪费“好的”高和段，并确保以后较短段的最大灵活性。 

### 为什么它有效

 在每一步中，我们都保持不变，即最后选择的段在达到其总和阈值的所有有效选择中具有最小可能的结束位置。 因为所有元素都是正数，所以向右移动一个段只会增加其总和并减少剩余空间。 因此，任何较晚的选择只会比较早的有效选择更能限制未来的可行性。 这使得贪婪的最早选择策略变得最优：它永远不会阻止可以进一步扩展的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def range_sum(l, r):
        return pref[r] - pref[l]

    # we try to build maximum number of segments
    # segment lengths conceptually decrease from k, but we build greedily
    res = 0
    prev_sum = 0
    i = 0

    # we try increasing number of segments implicitly
    # by always attempting next possible segment
    length = n

    while i < n and length > 0:
        found = False

        while i + length <= n:
            s = range_sum(i, i + length)
            if s > prev_sum:
                prev_sum = s
                i = i + length
                res += 1
                found = True
                break
            i += 1

        if not found:
            break

        length -= 1

    print(res)

t = int(input())
for _ in range(t):
    solve()
```该代码构建前缀和，以便任何段和查询都是恒定时间。 然后我们维护一个指针`i`以获得最早可能的起始位置。 对于每个尝试的段长度，我们向前扫描，直到找到总和超过前一个段总和的段。 一旦找到，我们就会承诺并继续前进。 如果不存在这样的段，我们就停止。 

一个微妙的点是我们总是前进`i`即使跳过无效的启动。 这是至关重要的，因为由于非重叠约束和不断增加的需求，任何跳过的开始都不能重复用于相同或较晚的段长度。

 ## 边缘情况

 一个关键的边缘情况是当存在许多短段但由于总和限制而无法形成链时。 例如，在像这样的数组中`[1,1,1,1,1]`，每个段的总和相等，因此只有一个段有效。 该算法正确地选择了第一个完整段，然后无法找到任何严格更大的总和。 

另一种边缘情况是早期的片段很诱人但不是最理想的。 在`[1,2,1,1,3,2,6]`，一个天真的方法可能会选择`[1,2,1]`然后陷入困境，但贪婪扫描确保如果稍后存在更好的有效段，它将被选择，从而保留扩展链的可能性。 

最后，后缀和快速增加的情况确保正确处理跳过。 由于指针仅向前移动，因此我们从不重新考虑较早的位置，由于正性对分段可行性的单调效应，这是安全的。
