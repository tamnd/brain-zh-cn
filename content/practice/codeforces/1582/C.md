 ## 解决方案
 ## 问题理解

 我们得到一个由小写字母组成的字符串。 我们可以精确地选择字母表中的一个字母，然后从字符串中删除该所选字母的所有出现位置，可能没有或全部删除。 在这些删除之后，我们希望生成的字符串成为回文，并且我们希望最小化删除的字符数。 如果没有任何一个字母选择可以使字符串成为回文，我们必须报告这是不可能的。 

一个关键的限制是删除受到严格限制。 我们不允许随意删除不匹配的字符； 我们只能删除出现的一个固定字符。 这一限制将问题变成了检查字符串是否可以通过“过滤掉”一种字符类型来变成回文。 

每个测试用例的输入大小最多可达 100,000 个字符，总字符数最多可达 200,000 个。 这立即排除了任何尝试模拟删除选择和对每个字母和每个删除组合独立进行回文检查的解决方案。 重复重建字符串的简单方法将达到 O(n * 26 * n)，这远远超出了可接受的限制。 

当字符串已经是回文时，会出现微妙的边缘情况。 在这种情况下，无论我们选择哪个字母，答案都是零。 当对称位置存在不匹配但无法通过删除单个字符类型来解决所有不匹配时，就会出现另一种棘手的情况。 例如，如果不匹配的对需要删除两个不同的字母，则即使字符串“几乎”看起来对称，也不存在有效的解决方案。 

## 方法

 暴力破解的想法很简单：尝试 26 个可能的字母中的每一个作为所选的删除字符。 对于每个选择，通过跳过该字母来构建结果字符串，然后检查剩余的字符串是否是回文。 如果是，计算执行了多少次删除并保持最小值。 

这是有效的，因为它直接模拟允许的操作。 然而，每次回文检查的时间复杂度为 O(n)，构建过滤字符串的时间复杂度也为 O(n)。 由于我们对 26 个字母重复此操作，如果不小心实现重复的字符串构造，复杂度将变为 O(26 · n²)，或者每次检查的复杂度为 O(26 · n)，导致最差实现模式中所有检查的复杂度为 O(26 · n²)。 当 n 达到 10⁵ 时，这是不可行的。 

关键的观察是我们实际上不需要为每个候选字母重建字符串。 相反，我们可以将问题视为带有约束的两指针回文检查：当我们看到不匹配时，我们被迫通过删除所涉及的两个字母之一来“修复”它，并且删除选择必须在所有不匹配中保持一致。 这意味着唯一有意义的候选者是在外部第一次不匹配时出现的两个字母。 任何有效的解决方案都必须从冲突对中完全删除其中一个字母，否则无法恢复对称性。 

因此，我们将问题简化为检查最多两个从第一个不匹配中派生的候选字母，并模拟受约束的回文检查，其中我们跳过该字母的出现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(26·n²) | O(26·n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从字符串的两端使用双指针扫描。

1. 初始化两个指针，左边为0，右边为n − 1。只要字符匹配，就将它们向内移动。 这验证了已经成立的前缀后缀对称性。 
2. 如果指针交叉，则该字符串已经是回文，因此不需要删除。 
3. 如果我们在 left 和 right 位置找到第一个不匹配，我们就有两个候选字母：s[left] 和 s[right]。 任何有效的解决方案都必须删除所有出现的这两个字母之一才能解决此不匹配问题。 
4. 对于每个候选字母，模拟回文检查，其中我们忽略该字母的所有出现。 我们再次使用两个指针，跳过等于所选字母的字符。 
5. 如果跳过一个字母后字符串变成回文，我们计算删除的字符数，即原始字符串中该字母的总数减去有效回文结构中剩余的出现次数。 
6. 取两位候选人的最小结果。 如果两个候选者都没有产生有效的回文，则返回 -1。 

将候选者限制为失配对背后的原因是，对称性失败的第一个位置已经迫使失配的一侧在任何有效的解决方案中被完全消除。 

### 为什么它有效

 该算法依赖于以下事实：位置 l 和 r 处的回文不匹配无法通过删除不相关的字符来修复。 由于我们只能全局删除一个字母，因此必须从所有相关位置中删除 s[l] 或 s[r] 中的至少一个。 一旦删除该字母，字符串的其余部分在两指针配对下必须在结构上保持一致。 这保证了任何成功的配置都必须对应于两个候选删除之一，因此仅检查这些就足够且完整了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(s, ch):
    l, r = 0, len(s) - 1
    removed = 0
    while l < r:
        while l < r and s[l] == ch:
            l += 1
            removed += 1
        while l < r and s[r] == ch:
            r -= 1
            removed += 1
        if l >= r:
            break
        if s[l] != s[r]:
            return float('inf')
        l += 1
        r -= 1
    return removed

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        l, r = 0, n - 1
        while l < r and s[l] == s[r]:
            l += 1
            r -= 1

        if l >= r:
            print(0)
            continue

        c1, c2 = s[l], s[r]

        ans = min(check(s, c1), check(s, c2))
        print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```该解决方案首先找到第一个不匹配，它标识了唯一值得考虑的两个相关字符。 辅助函数`check`模拟删除所有出现的所选字符，同时使用两个指针维护回文检查。 这`removed`计数器跟踪需要删除多少次，无效的配置立即返回无穷大。 

主要逻辑依赖于这样一个事实：一旦我们承诺删除两个不匹配字符之一，字符串的其余部分在回文约束下必须已经一致。 

## 工作示例

 考虑字符串`abcaacab`。 

我们首先从两端进行比较，直到不匹配为止：

 | 左| 对| s[左] | s[右] | 行动|
 | ---| ---| ---| ---| ---|
 | 0 | 7 | 一个 | 乙| 不匹配止损 |

 候选人是`a`和`b`。 

为了`a`，删除所有`a`字符产量`bcaacb`，这是一个回文。 删除次数为4。 

对于`b`，删除所有`b`字符产量`acaaca`，这也是一个回文。 所需删除次数为 2。 

最小值为 2。 

现在考虑`khyyhhyhky`。 

不匹配发生在迫使候选人的最外层不匹配处`k`和`y`。 

检查`k`跳过所有内容后，删除会导致一致的回文`k`字符，同时删除`y`需要更多的删除，但仍然产生有效的回文结构。 该算法选择最小可行删除计数。 

这些痕迹表明，该算法从不探索不必要的字母，只探索那些直接解决第一个结构冲突的字母。

 ## 边缘情况

 当字符串已经对称时，两指针扫描完成而不会遇到不匹配。 该算法立即返回零，这是正确的，因为不需要删除，并且任何选择的字母只会增加成本。 

当不匹配发生在字符串的最末端时，例如`ab`，候选字母是`a`和`b`。 每次删除尝试都会生成一个单字符字符串，这通常是一个回文。 该算法正确返回较小的删除成本，这两种情况都是一个。 

当字符串较深处存在多个不匹配时，第一个不匹配仍然确定唯一可行的删除候选者。 即使后来的不匹配涉及其他字符，任何有效的解决方案都必须已经解决第一个冲突，因此将注意力限制在这两个字母仍然足够，并且算法正确地拒绝不可能的情况。
