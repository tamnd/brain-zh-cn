 ## 解决方案
 ## 问题理解

 我们得到了一组歌曲，分为三种类型：一些持续 1 分钟，一些持续 2 分钟，一些持续 3 分钟。 对于每个测试用例，我们必须将每首歌曲分配给两场音乐会之一。 每首歌曲必须仅使用一次，并且每场音乐会的持续时间只是分配给它的歌曲持续时间的总和。 

目标是分割歌曲，使两场音乐会的总持续时间之间的绝对差异尽可能小。 

如果我们从结构的角度思考，问题实际上就是将由许多 1、2 和 3 组成的多重数字集划分为总和平衡的两组。 

约束条件很大，a、b、c 每个最多 10^9，最多 1000 个测试用例。 这立即排除了任何尝试显式构建或模拟单首歌曲分配的方法。 任何方法都必须在每个测试用例的恒定时间内工作。 

当总和非常小时或当一种类型占主导地位时，就会出现常见的微妙边缘情况。 例如，如果我们只有一种歌曲类型，比如 a = 1、b = 0、c = 0，那么我们能做的最好的就是将其完全放在一场音乐会中，给出差值 1。当完美配对不可能时，任何贪婪的“配对”想法仍然必须正确处理剩余的内容。 

另一个重要的边缘情况是混合不同的歌曲长度可以实现精确的平衡。 例如，一首 3 分钟的歌曲可以精确平衡一首 1 分钟和一首 2 分钟的歌曲，因此局部贪婪匹配很重要。 

## 方法

 一种幼稚的方法是尝试将每首歌曲一首一首地分配到两场音乐会中较轻的歌曲中。 这种贪心模拟需要迭代所有 a + b + c 歌曲，在最坏的情况下可能高达 3 × 10^9。 这是完全不可行的。 

另一种强力解释是将其视为分区问题并尝试歌曲的所有子集。 歌曲数量呈指数级增长，而且立即不可能实现。 

关键的观察是，只有每种类型的计数很重要，而不是个别歌曲。 我们实际上是在选择有多少个 1、2 和 3 进入第一场音乐会； 其余的进入第二个。 这将问题简化为平衡三个变量的两个线性组合。 

总金额是固定的。 如果我们用S表示，那么最小化两个子集之间的绝对差相当于找到一个总和尽可能接近S/2的子集。 

关键的结构是我们不能自由选择任意子集和； 我们只能使用有限的价值 1、2 和 3 的硬币来求和，并且具有很大的重数。 这使得可达总和足够密集，以至于可以通过简单的贪婪平衡规则来表征最佳解决方案。 

我们试图贪婪地建造一场音乐会，争取总金额的一半。 我们首先使用尽可能多的大歌曲（3分钟），然后用2分钟的歌曲进行调整，最后用1分钟的歌曲修复剩余的间隙。 由于值很小且结构化，因此这种贪婪的构造始终会产生可实现的最佳平衡。

 | 蛮力 | O(2^(a+b+c)) | O(2^(a+b+c)) | O(1) | O(1) | 太慢了 |

 ## 算法演练

 我们计算总持续时间 S = a + 2b + 3c，然后目标是建立尽可能接近 S/2 的第一场音乐会总和。

1. 计算 S = a + 2b + 3c。 这是所有歌曲组合的总持续时间，任何有效的分区都必须将此总和分为两部分。 
2. 设置目标 T = S // 2. 我们希望在不超出可行性约束的情况下使一个子集尽可能接近该目标。 
3. 尝试在第一场音乐会中使用尽可能多的 3 分钟歌曲，但不超过 c，不超过 T // 3. 这是最佳选择，因为 3 分钟歌曲对每项贡献最大，因此它们可以最快地缩小差距。 
4. 从剩余目标中减去所选 3 分钟歌曲的贡献。 然后转向 2 分钟的歌曲，在不超过更新目标的情况下尽可能多地录制歌曲。 原因是相同的：我们正在使用最大的可用单位贪婪地填补剩余的空白。 
5. 最后，用 1 分钟的歌曲来填补剩余的空白，限制为 a。 此时，剩余的每个单元都必须是 1 分钟的歌曲，因此我们只需取 min(a, 剩余间隙)。 
6. 设 X 为第一场音乐会的构造和。 第二场音乐会是 S − X，所以答案是 |S − 2X|。 

这种方法有效的原因是，可达总和的结构足够连续，每一步的局部最优选择不会阻碍任何更好的全局安排。 由于我们总是在不超过目标的情况下选择最大可能的贡献，因此我们绝不会在可以用较小物品填补的小缺口上浪费高价值物品。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        
        S = a + 2*b + 3*c
        target = S // 2
        
        take3 = min(c, target // 3)
        target -= 3 * take3
        
        take2 = min(b, target // 2)
        target -= 2 * take2
        
        take1 = min(a, target)
        target -= take1
        
        X = 3 * take3 + 2 * take2 + take1
        print(abs(S - 2 * X))

if __name__ == "__main__":
    solve()
```该代码计算总和，然后贪婪地构建最接近的可实现子集总和，使其达到一半。 减法步骤确保我们永远不会超过目标。 最终公式将构造的子集转换为两个分区之间的绝对差。 

唯一微妙的细节是我们不需要明确跟踪第二场音乐会。 一旦我们了解了一方面，另一方面就确定了。

 ## 边缘情况

 当只存在一种类型的歌曲时，例如只有 1 分钟的歌曲，贪婪构造只需通过 min(a, target) 步骤隐式地获取其中的一半。 例如，当 a = 5、b = 0、c = 0 时，总计为 5，目标为 2。算法采用 2 个，在另一个 Concert 中留下 3 个，并正确返回差值 1。 

当一首大歌曲占主导地位时，例如 c 很大并且 a = b = 0，算法将其中的地板 (c/2) 放入一侧，因为它向 S/2 填充。 例如，c = 3 得出总计 9，目标 4。该算法采用一首 3 分钟的歌曲，留下无法填充的目标 1，导致最终差异为 3，匹配不可避免的不平衡。 

当存在完美取消时，例如 (1, 1, 1)，贪婪匹配可以确保 1 + 2 与 3 完全取消，因为首先使用 3 分钟的歌曲来锚定目标，而较小的歌曲会填充剩余的间隙而不会出现过冲，从而产生精确的相等。
