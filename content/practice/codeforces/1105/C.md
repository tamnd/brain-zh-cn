 ## 解决方案
 ## 问题理解

 我们被要求计算有多少个长度的数组$n$可以形成使得每个元素都位于固定区间内$[l, r]$，所有元素的总和可被 3 整除。 

问题不在于构造一个特定的数组，而在于同时计算两个约束下的所有有效配置：每个位置的值限制和对总和的全局模块化约束。 

限制条件很大：$n$可以达到$2 \cdot 10^5$数组中的值可以大到$10^9$。 这立即排除了任何迭代所有可能的数组甚至所有可能的和的方法。 任何有效的解决方案都必须将问题减少到一个小的固定状态空间，通常基于模算术而不是实际值。 

当考虑范围时会出现一个微妙的困难$[l, r]$。 尽管值很大，但能否被 3 整除的重要因素只是它们的模 3 的残数。区间中残数的分布并不总是均匀的，特别是当区间长度不能被 3 整除时。 

一个常见的陷阱是假设每个残基类别出现的频率相同，而不处理边界。 例如，在一个小范围内，例如$[1, 3]$，每个残基只出现一次，但在$[1, 4]$，残留物计数变得不均匀。 任何忽略这一点的解决方案都会错误地计算有效数组。 

另一个边缘情况是当$n = 1$。 那么答案很简单，就是有多少个数字$[l, r]$可以被 3 整除，并且朴素的 DP 公式可能会通过独立处理位置而不强制执行全局总和约束来错误地过度计算。 

## 方法

 暴力破解的想法很简单：生成每个长度的数组$n$,检查每个元素是否在范围内$[l, r]$，计算其总和，并验证能否被 3 整除。数组的数量为$(r-l+1)^n$，即使对于很小的输入来说，这也是一个天文数字，使得这完全不可行。 

关键的观察结果是，条件仅取决于模 3 的和。每个元素仅将其模 3 的余数贡献给最终的和。 这将每个数组元素从潜在的巨大整数空间减少为三类：与 0、1 或 2 模 3 同余的数字。 

一旦进行了这种简化，问题就变成了经典的长度DP$n$以及运行总和的模状态。 唯一缺少的部分是确定有多少个整数$[l, r]$落入每个残留类别。 之后，转换变成纯粹的组合：在每个位置，我们选择一个残基类并更新模 3 的总和。 

这将问题从指数枚举简化为具有恒定状态大小的线性动态规划。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O((r-l+1)^n)$|$O(n)$| 太慢了 |
 | 最佳DP |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们首先将输入范围压缩为模 3 的余数计数。 

1. 计算有多少个数字$[l, r]$与 0、1 和 2 模 3 全等。 

这是使用算术级数计数来完成的。 对于每个残基类别，我们找到该残基的区间中的第一个数字，并计算大小为 3 的步数，直到$r$。 这一步是必要的，因为我们不能直接迭代范围。 
2. 令这些计数为$c_0, c_1, c_2$。 数组中的每个位置都有效地选择这些残基类别之一。 
3. 定义一个DP数组，其中$dp[i][m]$是选择第一种的方法数$i$其总和模 3 等于的元素$m$。 

我们只关心$m \in \{0, 1, 2\}$。 
4. 初始化$dp[0][0] = 1$，因为只有一种方法可以选择总和为 0 的任何内容。 
5. 对于从 1 到$n$，更新一个新的DP状态：

 我们尝试放置一个带有余数 0、1 或 2 的数字。 

每一个选择都有贡献$c_0$,$c_1$， 或者$c_2$分别方式，并相应地改变模状态。 

例如，放置一个残数 1 的元素会移动状态$m$到$(m+1) \bmod 3$。 
6. 处理完所有位置后，答案为$dp[n][0]$，因为我们希望总和能被 3 整除。 

### 为什么它有效

 在每一步中，DP 状态都会准确捕获所有有效前缀上的部分和模 3 的分布。 该转换保留了正确性，因为每个数组前缀都是通过附加三个残差类之一唯一形成的，并且每个类准确地贡献了间隔中正确数量的值。 由于模加法是封闭的和确定性的，因此两个不同的构造路径不会错误地干扰，并且所有数组都只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def count_residues(l, r):
    cnt = [0, 0, 0]
    for rem in range(3):
        # first number >= l with value ≡ rem (mod 3)
        start = l + (rem - l % 3) % 3
        if start > r:
            cnt[rem] = 0
        else:
            cnt[rem] = (r - start) // 3 + 1
    return cnt

def solve():
    n, l, r = map(int, input().split())
    
    c0, c1, c2 = count_residues(l, r)
    
    dp = [0, 0, 0]
    dp[0] = 1
    
    for _ in range(n):
        ndp = [0, 0, 0]
        for m in range(3):
            if dp[m] == 0:
                continue
            ndp[m] = (ndp[m] + dp[m] * c0) % MOD
            ndp[(m + 1) % 3] = (ndp[(m + 1) % 3] + dp[m] * c1) % MOD
            ndp[(m + 2) % 3] = (ndp[(m + 2) % 3] + dp[m] * c2) % MOD
        dp = ndp
    
    print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```该代码首先将值范围压缩为三个计数，每个残留类别一个。 DP 数组仅跟踪三种状态，对应于模 3 之和。每次迭代都会模拟放置一个数组元素，并使用预先计算的计数更新所有可能的模转换。 最终的答案是总和能被3整除的全长序列的数量。 

一个微妙的实现细节是残留计数公式。 表达式为`start`仔细对齐`l`向上到具有正确模数的下一个数字，除以 3 计算算术级数中的完整步长。 

## 工作示例

 ### 示例 1

 输入：```
2 1 3
```我们首先计算残留计数$[1, 3]$：残基 0、1、2 各一个数字，所以$c_0 = c_1 = c_2 = 1$。 

| 步骤| dp[0] | dp[0] | dp[1] | dp[1] | dp[2] | dp[2] |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 1 | 1 |
 | 2 | 3 | 3 | 3 |

 最终的答案是$dp[2][0] = 3$，对应数组$[1,2], [2,1], [3,3]$。 

该迹线显示了残基类之间的对称性如何产生平衡的转换，以及多个路径如何以相同的模状态结束。 

### 示例 2

 输入：```
1 2 4
```残留物在$[2,4]$是$2 \equiv 2$,$3 \equiv 0$,$4 \equiv 1$，所以再一次$c_0 = c_1 = c_2 = 1$。 

| 步骤| dp[0] | dp[0] | dp[1] | dp[1] | dp[2] | dp[2] |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 1 | 1 |

 答案是$dp[1][0] = 1$，对应单个有效数组$[3]$。 

这演示了基本情况行为，其中长度 1 直接减少到计算可被 3 整除的有效元素。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n)$| 每一个$n$步骤在 3 个状态上执行恒定大小的 DP |
 | 空间|$O(1)$| 仅维护固定的3元素DP数组|

 该解决方案很容易满足限制，因为$n \le 2 \cdot 10^5$，并且每次迭代仅涉及少量算术运算。

 ## 边缘情况

 当区间不包含给定残基类别的数字时，就会出现一种边缘情况。 例如，如果$l = 1$和$r = 1$，仅出现残基 1。 然后 DP 崩溃为仅重复添加一种类型的转换。 该算法可以正确处理此问题，因为其他残留计数为零，因此它们永远不会对转换产生影响。 

另一种情况是当范围极大但均匀分布在残基上时，例如$[1, 10^9]$。 计数公式仍然可以正确地计算每个残基类别几乎相等的计数，而无需迭代，并且 DP 保持稳定，因为它只使用聚合计数而不是单独的值。 

第三种情况是$n = 1$，其中答案应该只是区间中可被 3 整除的元素数量。 DP 开始于$dp[0][0]$，并且在一次迭代之后，仅应用直接转换，准确地生成残差 0 元素的计数，与预期结果匹配。
