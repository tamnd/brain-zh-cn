 ## 解决方案
 ## 问题理解

 我们得到一组从 1 到 n 编号的圆盘，其中较大的数字代表较大的圆盘。 这些圆盘最初被分成 m 个塔，每个塔已经将其圆盘从下到上按尺寸递减的顺序堆叠起来。 

我们可以通过从一个塔中取出所有棋子并将它们放置到另一个塔上来重复合并两个塔，但只能以保留有效堆叠规则的方式：只有当该塔当前顶部棋子大于该塔时，该棋子才能放置到该塔上。 合并操作实际上意味着我们正在重新组织光盘的分组方式，最终目标是形成一个包含所有内容的塔。 

我们关心的成本不是塔内的移动次数，而是最佳策略中所需的此类塔合并操作的数量，以最终得到一个有效的塔。 

每次查询后，两个现有的塔会合并为一个，我们必须报告整个当前配置的难度，这意味着完成将所有内容合并到一个塔中所需的最少操作数。 

约束很大，有多达200000个盘和塔，这立即排除了任何直接模拟合并过程或从头开始重复重新计算全局结构的方法。 每个查询的任何二次都太慢，甚至在最坏的情况下每个查询的线性重新计算也会太昂贵。 

一个天真的想法是模拟每个查询，重建所有塔，并从头开始重新计算难度。 这将需要扫描所有光盘并在每次合并后检查它们之间的关系，从而导致大约 O(nm) 的行为，这远远超出了限制。 

天真的贪婪思维的一个更微妙的失败案例是假设合并两座塔总是将难度增加一倍，或者可以在没有全局结构的情况下进行本地计算。 例如，即使合并了两个塔，效果也可以通过索引空间中相距很远的磁盘之间的许多邻接关系传播。 

关键的困难在于，答案取决于随着时间的推移，盘标签如何划分为连接的组件，并且合并会同时影响许多邻接关系。 

## 方法

 如果我们忽略效率，我们可以将每个光盘视为位于塔标签中。 最终目标是将所有棋子放入一个有效的递减堆栈中。 考虑难度的一个有用方法是按递增顺序考虑从 1 到 n 的圆盘序列，并询问该序列相对于塔成员资格的碎片程度。 

如果两个连续的圆盘 i 和 i+1 属于不同的最终合并塔，那么在构建过程中的某个时刻它们必须分开，从而增加了所需操作的数量。 如果它们属于同一个最终塔，则它们之间不需要操作边界。 

这表明答案与计算连续索引 i 和 i+1 之间的“中断”密切相关，其中它们当前的塔代表不同。 

现在考虑一下当我们合并两个塔时会发生什么。 两座塔内的所有圆盘突然都具有相同的身份。 这意味着一些以前“坏”的相邻对变得“好”，因为它们的端点现在属于同一个合并组件。 

这导致了位置 1 到 n 的固定线上的动态连接问题，其中每个位置都属于一个 DSU 组件（其塔），并且我们维护有多少相邻对跨越组件边界。 

暴力方法会在每次合并后通过扫描所有 n 个位置来重新计算该邻接计数。 每次查询的成本为 O(n)，总共为 O(nm)，这太大了。

关键的见解是合并两个 DSU 组件仅影响接触合并组件中元素的邻接边。 如果我们为每个组件维护它包含的位置列表，那么在合并两个组件时，我们只需要检查较小组件的元素并检查它们的邻居 i−1 和 i+1。 

这使我们能够使用按大小并集在近乎线性的总时间内增量更新答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每次合并后重新计算 | O(纳米) | O(n) | 太慢了 |
 | 具有邻接跟踪功能的 DSU | O(n α(n)) | O(n α(n)) | O(n) | 已接受 |

 ## 算法演练

 我们将每个塔建模为设置在圆盘位置上的 DSU。 每个圆盘位置 i 存储它当前属于哪个塔。 我们还维护一个全局计数器，记录有多少相邻对 (i, i+1) 属于不同的 DSU 集。 

### 步骤

 1. 初始化 DSU，其中每个塔都是其自己的组件，并为每个组件存储属于它的盘位置列表。 

这允许我们稍后在组件合并时仅更新受影响的位置。 
2. 通过扫描 i 从 1 到 n − 1 并计算位置 i 和 i+1 属于不同塔的次数来计算初始难度。 

这表示初始配置中组件之间的边界数量。 
3. 对于每个合并查询 (a, b)，找到两个塔的 DSU 代表。 
4. 如果它们已经在同一个组件中，则结构不会改变，并且仅打印当前答案。 
5. 否则，请确保我们始终将较小的组件合并到较大的组件中。 

这保证了每个盘位置在合并过程中最多移动对数多次。 
6. 对于较小组件中的每个位置 x，检查其邻居 x−1 和 x+1（如果存在）。 
7. 对于每个邻居检查，如果邻居在合并之前属于不同的组件，则该边当前对答案贡献 1。 合并后，两个端点都成为同一组件的一部分，因此这种贡献消失，我们减少答案。 
8. 将较小组件的所有元素移至较大组件并执行 DSU 并集。 
9. 处理完毕后，输出当前答案。 

### 为什么它有效

 关键的不变量是答案始终等于相邻索引对 i 和 i+1 的数量，因此它们的 DSU 代表不同。 每个合并操作仅更改合并组件内的 DSU 连接性，因此只有接触这些组件的邻接边才能更改状态。 由于我们明确地检查较小组件中的所有此类受影响的位置，并为每个受影响的边缘精确更新一次边界贡献，因此计数器始终保持正确。 

没有其他邻接关系可以从相等变为不相等，因为合并只会统一组件而不会拆分它们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    t = list(map(int, input().split()))

    parent = list(range(m + 1))
    size = [1] * (m + 1)

    comp = [set() for _ in range(m + 1)]
    for i, c in enumerate(t):
        comp[c].add(i)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    ans = 0
    for i in range(n - 1):
        if t[i] != t[i + 1]:
            ans += 1

    def union(a, b):
        nonlocal ans
        a = find(a)
        b = find(b)
        if a == b:
            return

        if len(comp[a]) < len(comp[b]):
            a, b = b, a

        # merge b into a
        for x in comp[b]:
            for y in (x - 1, x + 1):
                if 0 <= y < n:
                    if find(t[y]) == a:
                        ans -= 1
            comp[a].add(x)
            t[x] = a

        comp[b].clear()
        parent[b] = a

    for _ in range(m - 1):
        a, b = map(int, input().split())
        union(a, b)
        print(ans)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案在塔和每个组件的磁盘位置容器上维护 DSU。 数组 t 被重用来存储每个位置的当前代表成员资格。 在合并期间，仅检查较小组件中的元素，并且每个邻接更新都在本地处理。 

一个微妙的点是，只有当我们检测到邻接边用于跨越两个不同的组件但在合并后变为内部时，我们才会递减答案。 我们在合并期间从不增加答案，因为合并不能创建新的分离。 

## 工作示例

 考虑一个小例子，其中光盘的分布如下：

 输入：```
5 3
1 1 2 3 3
1 2
2 3
```初始状态有邻接数组：

 | 我| 1 | 2 | 3 | 4 |
 | ---| ---| ---| ---| ---|
 | t[i] | t[i] | 1 | 1 | 2 | 3 |
 | 差异？ | 0 | 1 | 1 | 1 |

 最初的答案是3。 

合并 1 和 2 后，将检查属于组件 2 的位置，并影响 (2,3) 之间的边界。 

| 步骤| 合并| 受影响的职位 | 回答 |
 | ---| ---| ---| ---|
 | 0 | 无 | 无 | 3 |
 | 1 | (1,2) | 检查边界 2-3 | 2 |
 | 2 | (2,3) | 检查边界 3-4 | 1 |

 这表明每次合并只是消除现有边界，而不是全局重组一切。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 仅当其组件合并为更大的组件时，每个位置才会移动 |
 | 空间| O(n + m) | DSU 阵列加上每个组件的位置存储 |

 按大小并集策略保证每个盘位置在所有合并中处理有限次数，使解决方案保持在 n 最多 2×10^5 的限制内。

 ## 边缘情况

 一个关键的边缘情况是所有圆盘最初都属于不同的塔。 在这种情况下，每个相邻对都会对初始答案做出贡献，并且随着组件的统一，每次合并都会逐渐缩小这些边界。 该算法可以正确处理此问题，因为每次合并仅删除邻接贡献，并且从不尝试从头开始重新计算。 

另一种情况是当合并连接在磁盘索引空间中没有邻接的塔时。 在这种情况下，答案根本不应该改变。 该算法正确地执行不递减，因为在合并之前没有邻居检查找到匹配的组件。 

最后，当重复合并目标已经统一的组件时，DSU 检查立即退出，确保答案不会重复计算或损坏。
