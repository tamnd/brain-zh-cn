 ## 解决方案

 ## 问题理解

 我们得到了一系列不同的整数，代表排成一行的战士。 我们还给出了一个目标序列，也由不同的整数组成。 目标是使用两个操作将初始行转换为目标行，这两个操作以不同的方式修改序列，并且每个操作都会产生成本。 

一次操作以固定成本删除恰好包含 k 个元素的连续块。 另一种操作作用于本地相邻元素：它比较两个邻居并删除较小的元素，从而有效地允许我们使用重复的本地战斗“冒泡出”较弱的元素。 我们可以按任何顺序应用这些操作，并且我们希望最终得到完全按顺序的目标序列，从而最小化总成本或报告不可能。 

关键的结构约束是所有值都是不同的，因此我们可以将序列视为数字的排列。 这消除了关系的模糊性，并确保每个元素都有唯一的身份。 

边界足够大，任何直接模拟操作的解决方案都是不可能的。 当 n 达到 200,000 时，即使 O(n²) 推理也太慢，甚至 O(n log n) 解决方案也必须围绕线性扫描或两个指针仔细构建。 这立即表明我们不应该在每次操作后动态地对序列进行建模，而应该推理哪些元素必须生存以及如何批量删除它们。 

当我们尝试从左到右贪婪地删除元素而不考虑未来的分组时，就会出现幼稚的失败情况。 例如，如果 k = 3，并且每当我们看到不匹配时就会贪婪地应用火球术，我们可能会销毁稍后实际需要的元素以支持更便宜的狂暴删除配置。 如果我们仅依靠狂暴来“清理”所需元素之间的所有内容，则会出现另一种故障模式：狂暴每次操作只能删除一个元素，因此长长的不相关元素会使成本过高，除非我们使用火球对它们进行批处理。 

## 方法

 如果我们翻转视角，问题就会变得更加清晰：我们不是从源构建目标，而是考虑必须保留初始数组的哪些元素，以便剩余序列按顺序等于目标序列。 由于两个序列都是排列，因此目标中的每个值对应于源中的唯一位置。 

让我们将目标中的每个值映射到其在原始数组中的索引。 这给出了原始数组中严格递增的索引序列。 任何不在目标中的元素都必须被删除。 核心难点是如何删除所有非目标元素，同时保持目标元素有序，最小化成本。 

一旦我们修复了原始数组中的目标位置，问题就分解为连续目标元素之间的间隙。 在每个间隙内，我们必须删除一段连续的“坏”元素。 然而，这些坏段会被结构约束打断：我们可以使用狂暴来廉价地消除单个元素，但只能消除相邻的元素，并使用火球来删除大小为 k 的块。 

这导致了经典的区间覆盖 DP 结构。 对于连续保留元素之间的每个段，我们计算消除所有内部元素的成本。 在一个段中，我们可以重复使用狂暴（成本与删除次数成正比），或者使用火球删除大小为 k 的块（每 k 块摊销成本），或者混合两者。

关键的观察结果是，berserk 有效地允许以成本 y 删除任何单个元素，而火球术以成本 x 删除 k 个连续元素。 因此，在长度为 L 的任何连续段内，删除它的最小成本是将其过度分割为火球块和单个删除的最小成本。 

因此，对于每个间隙，我们计算：

 我们采取L个坏元素，我们可以使用火球移除地板（L/k）组，并使用狂暴移除剩余的组。 这会产生 (L//k)*x + (L%k)_y 的成本，但我们还必须与全狂暴成本 L_y 进行比较，因为火球只有在比 k 个狂暴便宜时才有用。 

因此每个完整块的有效成本是 min(x, k*y)，其余部分单独处理。 

因此，每个间隙成本变为：

 下限(L/k) * min(x, k*y) + (L%k)*y。 

我们还必须确保可行性：目标元素必须以正确的顺序出现在原始数组中。 如果不这样做，答案为-1。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟操作| O(n²) | O(n) | 太慢了 |
 | 映射+差距成本优化| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们使用位置映射和间隙分解来处理数组。 

1. 构建位置数组 pos，其中 pos[v] 是值 v 在初始序列中的索引。 这使我们能够跟踪每个目标元素在原始数组中出现的位置。 
2. 验证目标对应的位置序列是否严格递增。 如果不是，则无法获得目标排序，因为没有操作对目标元素相对于彼此重新排序。 
3. 将数组拆分为多个段：第一个目标元素之前、连续目标元素之间以及最后一个目标元素之后。 每个段完全由必须删除的元素组成。 
4. 对于每个段，计算其长度 L。这些元素不属于最终序列，必须完全删除。 
5. 通过对删除进行最佳分组来计算删除段的成本。 每组 k 个元素可以使用火球术移除，也可以反复使用狂暴。 最佳选择是将整个块视为具有成本 min(x, k_y)，因为 k 个狂暴等于 k_y 成本，并且火球可能更便宜。 
6. 将 (L // k) * min(x, k*y) + (L % k) * y 添加到每个段的答案中。 
7. 对所有段求和并输出结果。 

### 为什么它有效

 转换过程永远不需要在所需元素的不同部分之间进行交互，因为目标元素充当固定分隔符。 在段内，操作仅与删除的元素数量有关，而不与它们的身份有关，因为所有非目标元素对于最终排序约束都是不相关且无法区分的。 Berserk 以成本 y 提供单元删除能力，而火球以成本 x 提供大小 k 的批量删除，因此每个段内的问题简化为将 L 划分为大小 k 的组和单个删除的简单成本最小化。 没有任何操作可以改进此结构，因为这两种操作都不会创建新的有用元素或更改所需元素之间的邻接关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x, k, y = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    # check order feasibility
    for i in range(1, m):
        if pos[b[i]] < pos[b[i - 1]]:
            print(-1)
            return

    ans = 0

    def cost(L):
        if L <= 0:
            return 0
        full = L // k
        rem = L % k
        return full * min(x, k * y) + rem * y

    # left segment
    ans += cost(pos[b[0]])
    # middle segments
    for i in range(1, m):
        ans += cost(pos[b[i]] - pos[b[i - 1]] - 1)
    # right segment
    ans += cost(n - 1 - pos[b[-1]])

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先构造位置映射，以便每个目标元素都可以在 O(1) 内定位。 单调性检查确保目标序列遵循原始顺序； 否则任何删除序列都无法恢复它。 

成本函数是核心洞察力的编码所在。 我们将删除分为大小为 k 的完整块和余数。 对于每个完整的块，我们选择一个火球和 k 个单独的狂暴之间更便宜的一个，因为任何最佳解决方案都可以重新排列，以便将火球应用于不相交的 k 长度组而不影响其他删除。 其余部分必须始终通过狂暴操作来处理，因为火球术无法部分应用。 

最后，我们累积非目标元素的所有分段的成本，因为这些分段是独立的。 

## 工作示例

 ### 示例 1

 输入：

 n = 5, m = 2, a = [3, 1, 4, 5, 2], b = [3, 5]

 职位：

 3 → 0, 5 → 3

 细分：

 左边 3 个：无

 3 和 5 之间：[1, 4] 长度 2

 5 的右边：[2] 长度 1

 令 k = 2、x = 5、y = 3。 

| 细分 | 左 | 完整块 | 雷姆 | 成本|
 | ---| ---| ---| ---| ---|
 | 3 到 5 之间 | 2 | 1 | 0 | 分钟(5, 6) = 5 |
 | 5 的右边 | 1 | 0 | 1 | 3 |

 总成本 = 5 + 3 = 8

 该轨迹显示了单个火球如何变得比整个块中的两个狂暴更好，而剩余元素则单独处理。 

### 示例 2

 输入：

 n = 6, m = 3, a = [1, 2, 3, 4, 5, 6], b = [2, 5, 6]

 职位：

 2 → 1, 5 → 4, 6 → 5

 细分：

 前2：[1] L=1

 2 到 5 之间：[3,4] L=2

 5 和 6 之间：[] L=0

 假设 k = 2、x = 4、y = 3。 

| 细分 | 左 | 成本|
 | ---| ---| ---|
 | 前 2 | 1 | 3 |
 | 2 到 5 之间 | 2 | 最小值(4,6)=4 |

 总成本 = 3 + 4 = 7

 这个例子强调了分割是独立的，并且每个间隙都是单独优化的。

 ## 边缘情况

 关键边缘情况是目标序列在索引顺序方面不是原始数组的子序列。 例如，如果原始是[1,2,3]，目标是[3,1]，则位置递减，因此任何删除序列都不能固定顺序，答案必须是-1。 

当 k 为 1 时，会出现另一种情况。这里火球相当于删除一个元素，因此每次删除都是 x 或 y，解决方案简化为为每个元素选择更便宜的操作。 任何假设 k ≥ 2 结构的解决方案都会在这里多计数或少计数。 

第三种情况是 x 远大于 k_y。 在这种情况下，火球术永远不是最佳的，解决方案必须减少到纯粹的狂暴删除。 如果一个实现总是贪婪地对整个块应用火球，那么它将付出过高的代价，但成本公式通过取 min(x, k_y) 来正确处理这个问题。
