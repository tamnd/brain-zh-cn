 ## 解决方案

 ## 问题理解

 我们得到了一个排列，这意味着从 1 到 n 的每个数字都按某种顺序恰好出现一次。 任务是检测三个索引 i、j、k 的特定模式，其中 i < j < k，使得 j 处的值在约束意义上是“局部峰值”：它大于其左侧选择的元素和右侧选择的元素，而左侧元素严格小于它。 

换句话说，我们想要一个中间位置 j，我们可以在其左侧某处找到较小的值，在其右侧某处找到较小的值。 确切的要求是 p[i] < p[j] 且 p[k] < p[j]，其中 i 严格位于 j 的左侧，k 严格位于 j 的右侧。 我们不需要邻接，只需要索引的排序。 

约束很小：n 最多为 1000，并且最多有 200 个测试用例。 在 Python 中，针对单个测试用例的三次方法已经可以接受，但重复 200 多个用例就变得不安全了。 这促使我们朝着每个测试用例接近二次或更好的方向发展。 

当人们假设最佳三元组必须涉及 j 的邻居时，天真的解释常常会失败。 这是不正确的，因为有效的 i 和 k 可能相距很远。 例如，在像 [1, 3, 2, 4] 这样的排列中，有效的三元组是 i=1, j=2, k=3 或 i=1, j=4, k=3，具体取决于选择； 见证元素不一定是相邻的。 

如果试图选择 j 作为全局最大值，则会出现另一种微妙的故障模式。 这并不能保证有效的三元组，因为最大值可能位于端点，或者所有较小的元素可能仅位于一侧。 例如，[1,2,3,4]没有有效的三元组，尽管到处都有递增结构。 

关键的困难在于，我们必须找到一个双方都有支持的峰值，而不是任意一个峰值。 

## 方法

 蛮力的想法很简单。 对于索引 i < j < k 的每个三元组，我们直接检查是否 p[i] < p[j] 和 p[k] < p[j]。 这是正确的，因为它枚举了所有可能性，并且任何有效的配置最终都会被测试。 

但是，这会检查每个测试用例的 O(n^3) 三元组。 当 n = 1000 时，每个测试用例大约需要 10^9 次检查，这远远超出了可行的范围，尤其是在多达 200 个测试用例中。 即使在 Python 中，这也离通过还差得很远。 

我们可以通过改变视角来显着减少这种情况。 我们没有明确选择 i 和 k，而是固定中间索引 j 并询问它的左侧是否至少有一个较小的元素，右侧是否至少有一个较小的元素。 如果两者都存在，我们就立即完成。 

这一观察将问题简化为扫描每个 j 并检查两个存在条件。 直接扫描每个 j 的时间复杂度为 O(n^2)，对于 n 到 1000 来说这是可以接受的。一旦找到有效的 j，我们就可以选择任何合适的 i 和 k。 

我们还可以通过预先计算每个位置左侧是否存在较小的元素以及右侧是否存在较小的元素来优化存在检查。 但考虑到限制，即使是简单的扫描也足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有三元组）| O(n^3) | O(n^3) | O(1) | O(1) | 太慢了|
 | 通过扫描修复中间 j | O(n^2) | O(n^2) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 从 1 到 n 迭代每个索引 j。 

我们将 j 视为潜在峰值位置。 目标是确定它是否可以是有效三元组的中间元素。 
2. 扫描 j 的左侧以查找满足 p[i] < p[j] 的任意索引 i。 

这确保了左边的条件得到满足。 当我们找到这样的 i 时，我们立即停止，因为存在就足够了。 
3. 扫描 j 的右侧以查找满足 p[k] < p[j] 的任意索引 k。

这确保了满足正确的条件。 再说一遍，我们只需要存在。 
4. 如果找到有效的 i 和 k，则输出 YES 和三元组 (i, j, k)，并终止此测试用例的处理。 
5. 如果没有 j 满足两个条件，则输出 NO。 

### 为什么它有效

 对于任何有效的解决方案，必须存在某个中间索引 j，其中左侧存在一个较小的元素，右侧存在另一个较小的元素。 该算法检查 j 的每个可能选择并准确验证此条件。 由于我们穷尽了中间位置的所有候选者，并且对于每个候选者我们都正确地测试了可行性，因此我们不会错过有效的三元组。 相反，如果没有 j 通过测试，则根据定义不存在有效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))

    found = False

    for j in range(n):
        left_i = -1
        right_k = -1

        for i in range(j):
            if p[i] < p[j]:
                left_i = i
                break

        if left_i == -1:
            continue

        for k in range(j + 1, n):
            if p[k] < p[j]:
                right_k = k
                break

        if right_k != -1:
            print("YES")
            print(left_i + 1, j + 1, right_k + 1)
            found = True
            break

    if not found:
        print("NO")
```该方案的核心结构是直接执行固定中间策略。 外层循环选择j，两次内层扫描寻找双方的目击者。 当两个见证人都存在时，我们立即输出，这可以防止不必要的工作。 

一个常见的实现陷阱是忘记索引在 Python 中是从 0 开始的，但必须打印为从 1 开始。 另一个微妙的问题是提前突破：一旦找到有效的 i，就没有必要继续向左扫描，但更重要的是，一旦找到完整的三元组，我们必须完全跳出 j 循环以避免多个输出。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        found = False

        for j in range(n):
            i = -1
            k = -1

            for x in range(j):
                if p[x] < p[j]:
                    i = x
                    break

            if i == -1:
                continue

            for x in range(j + 1, n):
                if p[x] < p[j]:
                    k = x
                    break

            if k != -1:
                out.append("YES")
                out.append(f"{i+1} {j+1} {k+1}")
                found = True
                break

        if not found:
            out.append("NO")

    return "\n".join(out)

 ## 边缘情况

 像 [1, 2, 3] 这样的小排列永远不会产生有效的 j，因为没有元素可以同时具有较小的左邻居和较小的右邻居。 该算法检查 j=0,1,2，并且每个都至少有一侧失败，因此它正确地返回 NO。 

在像 [5, 4, 3, 2, 1] 这样的反向排列中，每个元素仅在一侧具有较小的元素，而不是在两侧都有较小的元素。 扫描对每个 j 都确认了这一点，从而防止误报，即使存在许多本地比较。 

像 [2, 1, 4, 3] 这样的情况显示了预期的行为：j=2（值 4）两侧都有较小的元素，算法立即找到 i=0 和 k=3，生成有效的三元组。
