 ## 解决方案
 ## 问题理解

 我们被要求推理一个无限字符串，该字符串不是直接逐个字符构建的，而是按顺序从正整数生成的。 对于每个整数$i = 1, 2, 3, \dots$，我们根据整除性附加字符：我们附加`F`如果$i$能被 3 整除，我们追加`B`如果$i$可以被 5 整除。如果一个数字可以同时被 3 和 5 整除，则两个字符都按该顺序附加，这意味着`F`首先然后`B`。 

这会在字母表上产生一个无限序列`{F, B}`。 每个整数贡献零个、一个或两个字符，因此字符串增长不均匀，但具有确定性。 

每个查询给出一个短字符串$s$长度最多为 10，我们必须确定它是否在这个无限生成的字符串中的某个位置出现为连续段。 

约束条件是$k \le 10$是关键的结构提示。 如此小的长度的子串不需要我们深入探索其构造。 任何正确的解决方案只需要了解无限序列的有界部分，因为局部模式会定期重复。 

天真的尝试可能会尝试模拟大范围整数的过程，但是一旦我们注意到该结构每 15 个整数重复一次，这很快就变得不必要了，因为被 3 和 5 整除仅取决于$i \bmod 15$。 

如果我们只检查整数的单个小前缀而不处理跨边界的子字符串重叠，就会出现一个微妙的错误。 例如，一种模式可能从 15 个整数组成的一个块的末尾附近开始，并继续到下一个。 另一种失败模式是将进程视为每个整数的序列而不是每个发出的字符，这会导致子字符串对齐不正确。 

## 方法

 暴力破解的想法是通过迭代整数并附加字符来模拟 FB 字符串的构造，直到字符串变得“足够长”，通常直到它超过查询长度的某个倍数。 由于每个整数最多生成 2 个字符，并且$k \le 10$，我们可以安全地模拟每个测试用例可能几百个整数，然后运行子字符串检查。 

这种方法是正确的，因为它忠实地重建了定义。 然而，如果扩大规模，它就会变得低效，因为即使结构确定性地重复，每个测试用例也会重复模拟许多整数。 

关键的观察是周期性。 每个整数的贡献仅取决于它是否能被 3 和 5 整除，这完全由其模 15 的余数决定。每个 15 个连续整数块都会产生完全相同的附加字符序列。 这意味着整个无限 FB 字符串是对应于整数 1 到 15 的固定有限字符串的重复。 

一旦我们有了这个基本块，就可以通过在其足够重复的版本中搜索来找到无限字符串的任何子字符串。 由于最大查询长度为 10，因此少量复制基本块可以保证我们永远不会错过跨越边界的子字符串。

 ## 算法演练

 我们通过模拟从 1 到 15 的整数来构造 FB 串的一个完整周期。然后我们重复此块几次以安全地覆盖跨越边界的子串。 最后，我们检查查询字符串是否出现在该扩展字符串内。 

1. 迭代 1 到 15 之间的整数并构建一个基本字符串。 

对于每个整数，附加`F`如果能被 3 整除，则附加`B`如果能被 5 整除，则按此顺序。 这产生了基本的重复块。 
2.重复该块几次，例如3次。 

这确保了长度最多为 10 的任何子串都被完全包含，即使它跨越了两个块之间的边界。 
3. 对于每个查询字符串，检查它是否是该构造的有限字符串的子字符串。 
4. 输出`YES`如果找到，否则`NO`。 

### 为什么它有效

 该构造仅取决于可被 3 和 5 整除，并在整数上以周期 15 重复。 由于每个整数仅基于此属性独立贡献，因此发出的字符序列恰好每 15 个整数重复一次。 因此，无限串的任何子串都包含在固定有限块的重复副本中。 将块稍微扩展到一个周期之外可以保证跨越边界的子串也被捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# build one period (1..15)
base = []
for i in range(1, 16):
    if i % 3 == 0:
        base.append("F")
    if i % 5 == 0:
        base.append("B")

base = "".join(base)

# repeat enough to cover substrings up to length 10 crossing boundaries
text = base * 3

t = int(input())
for _ in range(t):
    k = int(input())
    s = input().strip()
    if s in text:
        print("YES")
    else:
        print("NO")
```该解决方案首先在整数索引 1 到 15 上构造 FB 字符串的最小重复单元。然后，它重复该单元 3 次，以确保长度最多为 10 的任何子字符串都能得到完整表示，即使它跨越一个周期的末尾和另一个周期的开头。 每个查询都使用直接子字符串检查来回答，这是有效的，因为文本和模式都很小并且大小固定。 

唯一微妙的一点是，当整数可被 3 和 5 整除时，确保附加字符的正确顺序。代码通过附加来保留这一点`F`首先和`B`第二。

 ## 边缘情况

 一种棘手的情况是子字符串在一个 15 整数循环末尾附近开始并继续到下一个。 该算法处理这个问题是因为重复构造`base * 3`保证每个边界区域完全出现在有限表示内部。 

例如，如果模式从一个块的最后一个字符开始并继续到下一个，则构造的字符串仍包含重复的中间副本中的重叠。 然后，子字符串检查会直接找到它，而不需要对索引或整数对齐进行特殊处理。
