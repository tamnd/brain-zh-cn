 ## 解决方案
 ## 问题理解

 我们得到了按时间顺序排列的摔跤技术日志。 每个条目都是一个整数，描述了谁执行了该移动以及它贡献了多少分。 正值意味着第一个摔跤手执行的动作值得那么多分，而负值意味着第二个摔跤手执行的动作值得该数字的绝对值。 

从这个流中，我们重建了两个序列：一个是第一个摔跤手按照出现顺序获得的分数序列，另一个是第二个摔跤手获得的分数序列。 最后，分三个阶段决出获胜者。 首先，我们比较总分。 如果一位摔跤手拥有更大的金额，他们立即获胜。 如果总数相等，我们按字典顺序比较两个序列，较大的序列获胜。 如果两个序列的值和长度都相同，则获胜者是执行输入中最后一步的摔跤手。 

约束 n 高达 2·10^5 意味着任何解在时间上都必须是线性的或接近线性的。 重复比较前缀或重复重新扫描序列的二次方法会太慢，因为在最坏的情况下可能会达到 10^10 次操作。 我们需要一次性处理输入并避免重复比较。 

当总数相等但序列仅在最后一个不同元素处不同时，会出现微妙的边缘情况。 例如，如果一个序列是另一个序列的前缀，则字典顺序比较取决于长度。 另一个边缘情况是当序列的值和长度相同时，获胜者仅由最后一个非零事件决定，该事件可能属于任一摔跤手。 

## 方法

 强力解释将显式构建两个序列，然后计算它们的总和，最后按字典顺序比较它们。 这在概念上是可行的，但词典比较本身可能会降低质量。 在最坏的情况下，两个序列可能最多包含 n 个元素，并且从头开始对每个决策点进行比较或多次遍历数据仍然保持线性，但如果在处理时尝试重复模拟比较，则会出现真正的低效率。 

关键的观察是我们不需要重复比较序列。 我们只需要构造一次，然后在最后执行三个确定性比较：总和比较、字典序比较和最后一步比较。 由于构造序列的复杂度已经是 O(n)，因此每次比较的所有剩余操作也必须是 O(n) 或 O(1)。 

我们维护两个数组，一个对应每个摔跤手，以及两个运行总和。 我们还跟踪最后走势的指数。 一旦输入被完全处理，我们就会比较总和。 如果相等，我们使用 Python 的本机字典比较来比较列表，这是最优的并在 C 中实现。如果仍然相等，我们检查哪个玩家做出了最后一步。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 已接受但不必要的开销 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 读取 n，然后按顺序迭代所有动作。 对于每个值 aᵢ，通过检查其符号来确定哪个摔跤手执行了该操作。 此步骤对于忠实地重建两个评分序列是必要的。 
2. 如果 aᵢ 为正数，则将其附加到第一个摔跤手的序列中，并将其添加到他们的运行总和中。 如果 aᵢ 为负数，则将其绝对值附加到第二个摔跤手的序列中，并将其添加到它们的总和中。 这使得分数积累和序列重建在一次传递中保持同步。 
3. 跟踪最后一步的索引以及执行该步的玩家。 仅当所有其他比较都以平局结束时才需要此信息。 
4. 完成所有动作后，比较两名摔跤手的总和。 如果其中一个更大，我们可以立即决定获胜者，而无需考虑序列结构。 
5. 如果总和相等，则按字典顺序比较两个序列。 此比较遵循标准字典顺序：由第一个不同元素决定，否则如果一个是另一个的前缀，则较长的序列获胜。 
6. 如果两个序列相同，则根据执行最后一步的人返回获胜者。 

### 为什么它有效

 该算法直接反映了问题的决策层次：总和比较主导字典序比较，字典序比较主导最后一步的平局决胜局。 由于每条信息（序列、总和、最后一步）都完全按照问题中的定义保存，因此不会引入任何变换或近似。 正确性源于这样一个事实：字典顺序仅取决于第一个不同的位置，并且我们保留完整的序列，因此不会丢失比较所需的信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
first = []
second = []
sum1 = 0
sum2 = 0

last = 0  # 1 for first, 2 for second

for _ in range(n):
    x = int(input())
    if x > 0:
        first.append(x)
        sum1 += x
        last = 1
    else:
        x = -x
        second.append(x)
        sum2 += x
        last = 2

if sum1 > sum2:
    print("first")
elif sum2 > sum1:
    print("second")
else:
    if first > second:
        print("first")
    elif second > first:
        print("second")
    else:
        print("first" if last == 1 else "second")
```该代码构造两个序列，同时在一次输入中计算它们的总和。 变量 Last 存储谁执行了最近的移动，仅当两个序列的值和结构最终相同时才使用该变量。 

比较`first > second`利用 Python 内置的词典列表比较，它与问题定义完全匹配。 这避免了手动逐个元素的比较，并使实现保持紧凑并避免索引错误。 

最终的抢七局使用存储的最后动者，确保序列完全相同时的正确性。

 ## 边缘情况

 当两个序列相同但以不同的移动顺序构建时，就会出现一种边缘情况。 考虑输入：```
2
1
-1
```第一个序列是 [1]，第二个序列是 [1]。 总和相等，字典序比较也相等。 该算法正确地回退到最后一步，即第二步，产生“第二步”。 

另一种边缘情况是一个序列是另一个序列的严格前缀：```
3
1
2
-1
```这里第一个 = [1,2]，第二个 = [1]。 总和不同，所以答案已经确定为“第一”。 如果在修改后的场景中人为地使总和相等，则词典比较将正确地倾向于较长的序列，因为 Python 列表比较完全按照问题定义的要求处理前缀排序。
