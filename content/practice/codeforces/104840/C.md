 ## 解决方案
 ## 问题理解

 我们给出了一个放置在类似堆栈的结构中的排列`a`，其中只有最后一个元素`a`是可以直接访问的。 还有第二个空栈`b`。 我们需要删除其中的所有号码`1`到`n`按升序排列，但我们只允许执行一组非常有限的操作：我们可以将一个堆栈的顶部元素移动到另一个堆栈，或者我们可以删除（释放）任一堆栈的顶部元素。 每个此类操作都会花费一次操作。 

因此，系统的行为就像两个交互的堆栈，每时每刻我们都只能看到顶部的元素。 任务是将初始配置转换为一系列删除操作`1, 2, ..., n`同时最大限度地减少操作次数。 

约束条件达到`n = 2 · 10^5`，因此任何试图非贪婪地探索状态或模拟选择的解决方案都将不起作用。 甚至`O(n log n)`很好，但是任何类似于配置上的 BFS 或堆栈状态上的动态编程的东西都会立即变得太大，因为每个状态转换都是昂贵的，并且配置的数量呈指数级增长。 

这个问题的一个微妙问题是“正确”的元素并不总是位于`a`，即使它被掩埋了，我们也可能不得不暂时将阻挡元素移入`b`。 关键的困难在于移动元素的成本也很高，因此如果没有结构，盲目地模拟直到下一个所需的数字出现可能会效率低下。 

一种常见的故障模式是尝试始终耗尽`a`进入`b`每当被阻塞时。 这可能会导致不必要的来回传输，例如，如果更仔细地选择操作顺序，则可以更早地释放元素。 

另一个陷阱是假设一旦一个元素被移动到`b`，它应该留在那里直到需要为止。 事实上，有时将元素移回原处是最佳选择，因为`b`可以成为所需号码的唯一可到达的地方。 

## 方法

 蛮力观点将该过程视为状态上的最短路径问题`(a, b, next_required)`，其中每一步都是一条边。 这在原则上是正确的，但是状态空间是巨大的。 每个元素可以位于任一堆栈中，并且顺序很重要，因此配置的数量会组合增长。 即使是为了`n = 30`，这已经变得不可行了。 

关键的简化来自于观察，我们永远不需要以任意的方式重新考虑早期的决定。 在任何时刻，只有两个堆栈的顶部元素很重要，唯一有意义的目标是公开下一个所需的数字`x`。 这将问题简化为贪婪过程：我们不断地操作栈顶，直到`x`变得可访问，然后将其删除。 

该结构的行为类似于使用两个堆栈的排序过程的受控模拟。 最佳策略是避免不必要的转移，并始终执行唯一的移动，严格减少与下一个所需数字的“距离”。 

由此产生的算法是一种确定性模拟，在每一步中，我们要么释放所需的数字（如果它是可见的），要么执行一次安全传输，以保持揭示它的进度。

 ## 算法演练

 我们维护两个栈`a`和`b`，和一个指针`need`最初等于`1`。 

1. 虽然`need ≤ n`，我们反复尝试暴露和删除`need`。 
2. 如果顶部`a`等于`need`，我们将其从`a`并增加`need`。 这是理想的情况，因为不需要额外的工作。 
3. 否则如果顶部`b`等于`need`，我们将其从`b`并增加`need`。 这意味着该元素已暂时存储并且现在已准备就绪。 
4. 否则，我们将被封锁。 在这种情况下，我们必须移动元素来改变可访问性。 如果`a`非空，我们将其顶部元素移入`b`。 这是一种从原始堆栈中剥离阻碍元素的受控方法。 
5. 如果`a`是空的，我们移动顶部`b`回到`a`。 发生这种情况时`b`包含阻止访问所需值的元素，我们必须重新调整可访问性。 

每一次移动花费一次操作，每次移除也花费一次操作。 

关键的想法是我们永远不会“猜测”长序列的动作。 只有当两个堆栈都无法公开所需的值时，我们才会执行移动，以确保每个操作都有助于取得进展。 

### 为什么它有效

 任何时候，只有缩短彼此之间的距离，才能取得进步。`need`及其在当前可见结构中的位置。 移动不存在的元素`need`不会丢失信息，它只会改变暂时隐藏的元素。 由于每个元素最终都必须被删除一次，因此延迟其移动永远不会提高总成本，除非它直接有助于暴露当前的元素`need`。 

这确保了每个操作要么是最终删除，要么是必要的重新安排以公开未来的删除，并且没有任何操作在不有助于最终可访问性的意义上是多余的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # treat a as stack: end is top
    a = a[::-1]
    b = []
    
    need = 1
    ops = 0
    
    while need <= n:
        if a and a[-1] == need:
            a.pop()
            need += 1
            ops += 1
        elif b and b[-1] == need:
            b.pop()
            need += 1
            ops += 1
        else:
            if a:
                b.append(a.pop())
            else:
                a.append(b.pop())
            ops += 1
    
    print(ops)

if __name__ == "__main__":
    solve()
```该实现反转输入数组，使最后一个元素成为堆栈顶部`a`。 这避免了索引混乱并使得`pop()`自然代表允许的操作。 

如果下一个所需的数字可见，则循环始终优先删除该数字。 只有当它不可见时，我们才会在堆栈之间执行传输。 这保证了每个操作都是有意义的：要么完成所需的删除，要么使系统更接近暴露所需的值。 

一个微妙的点是，当阻塞时，两个堆栈都会被对称处理。 如果`a`是空的，我们必须依靠`b`，所以我们将元素移回来。 这可以防止所有剩余元素都在的死锁情况`b`但由于订购而无法访问。

 ## 边缘情况

 对于`n = 1`，两个堆栈都是微不足道的，并且单个元素可以立即访问，因此该算法只执行一次删除。 

对于完全递减的初始堆栈，例如`[n, n-1, ..., 1]`，该算法永远不需要传输，因为每个所需的元素都已经按顺序位于顶部，并且它只是重复地从`a`。 

对于完全递增的堆栈`[1, 2, ..., n]`，每个元素都被隐藏，直到达到正确的序列，迫使模拟移动元素的传输进入`b`然后返回，但每个元素仍然只处理固定次数，保持线性复杂性。
