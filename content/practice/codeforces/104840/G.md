 ## 解决方案
 ## 问题理解

 我们在数轴上得到了一组线段。 每个片段代表一系列“现实”，必须将其作为单个项目进行搜索。 我们执行的操作是将这些段分组：一个组包含多个段，处理一组意味着我们一起处理其中的所有段。 

在单个组内，不允许任何两个线段相交。 这里的交集意味着它们至少有一个共同点，因此如果一条线段在另一条线段结束之前开始，则两条线段不兼容。 

任务是将所有段分成尽可能少的组，并输出每个组的组成。 

输入大小达到二十万段，每个端点可以大到十亿。 这立即排除了任何尝试比较所有线段对的方法，因为这将是二次的并且远远超出时间限制。 即使维持一个明确的兼容性矩阵也是不可能的。 

一个微妙的点是，这些段是闭区间的。 这对于邻接情况很重要，例如`[1, 3]`和`[3, 5]`，它们确实相交于点 3，因此不能属于同一组。 这迫使兼容性的严格条件成为`r < l`。 

一个天真的错误是假设接触端点可以安全地组合。 例如：

 输入：```
3
1 3
3 5
6 7
```粗心的分组可能会将第一段和第二段放在一起，但它们在 3 处相交，因此这违反了规则。 正确的解决方案必须将该边界视为冲突。 

另一个常见的陷阱是在没有全局排序策略的情况下贪婪地将段打包到第一个可用组中。 如果不按开始时间排序，分组可能会变得依赖于顺序并产生不必要的组。 

## 方法

 一个蛮力的想法是一个接一个地建立小组。 我们重复选择一个未分配的线段，开始一个新组，然后扫描所有剩余的线段以添加与组内已有的线段不相交的线段。 每次添加都需要检查该组所有当前成员的兼容性。 

这在逻辑上是有效的，因为它明确地强制执行非相交约束。 问题是性能。 在最坏的情况下，如果段严重重叠，则每个组可能只占用一个段，并且每次尝试填充组都会扫描几乎所有剩余段。 这会导致 n 平方数量级的二次行为，这对于 200,000 个元素来说远远超出了可接受的范围。 

关键的观察是这是一个经典的区间着色问题。 所需的最小组数等于任意点重叠间隔的最大数。 我们不是以任意顺序贪婪地构造组，而是处理按起点排序的段，并维护当前活动组的结构，每个组由分配给它的最后一个终点表示。 

在任何时候，如果一个组的最后一个段严格在当前段开始之前结束，那么该组就有资格被重用。 所以我们要快速找到一个结束时间最小且仍然满足这个条件的组。 组结束时间上的最小堆恰好提供了此功能。 

如果可能，每个段都会分配给现有的兼容组，否则将创建一个新组。 这确保了组的最佳重用并保证了最少的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按左端点对所有线段进行排序。 这确保了我们始终按照间隔开始的顺序处理间隔，这对于保持“当前开放”组的一致概念至关重要。 
2. 维护一个最小堆，其中每个元素代表一个组，由放入该组的最后一个段的右端点作为键控。 每个堆条目还存储组标识符。 
3. 按排序顺序迭代段。 对于每个段`[l, r]`，检查堆。 
4.如果堆不为空且最小的结束组有end`< l`，弹出它并将当前段分配给该组。 我们选择最小的一端，因为它可以最早释放空间，从而最大限度地提高未来的重用机会。 
5. 否则，没有现有组可以接受该段，因此我们创建一个新组并将该段分配给它。 
6. 分配后，将更新后的组以当前段的结束时间推回到堆中。 
7. 存储组成员列表，以便我们可以在最后输出它们。 

### 为什么它有效

 在任何时候，堆都会存储所有活动组，这些活动组按照它们不再可用时的顺序排列。 将一个段分配给结束时间最短的组是安全的，因为如果任何组可以容纳该段，则该组是最受限制的； 如果它做不到，那么其他团体也做不到。 这种贪婪的选择保留了所有未来的可能性，并避免创建不必要的群体。 

不变的是，在处理每个段之后，堆中的每个组都代表一个有效的非重叠段链，并且稍后分配的任何段都与其组中已有的所有段兼容。 由于我们总是在可能的情况下重用兼容的组，因此我们永远不会增加组数，除非受到重叠结构的强制。 这符合区间划分最优性的定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i + 1))

    segs.sort()

    import heapq
    heap = []
    groups = []
    
    for l, r, idx in segs:
        if heap and heap[0][0] < l:
            end, gid = heapq.heappop(heap)
        else:
            gid = len(groups)
            groups.append([])

        groups[gid].append(idx)
        heapq.heappush(heap, (r, gid))

    print(len(groups))
    for g in groups:
        print(len(g))
        print(*g)

if __name__ == "__main__":
    solve()
```该解决方案首先按间隔的左端点对间隔进行排序，这确保我们始终按时间顺序扩展组。 堆存储成对的`(end_time, group_id)`这样我们就可以有效地找到最早空闲的组。 

条件`heap[0][0] < l`是关键的细节。 它强制执行严格的不相交：如果一个组在某个时间结束`r`，它只能接受从`l`什么时候`r < l`。 

当我们从堆中弹出时，我们承诺重用该组。 如果没有有效的组，我们分配一个新的组，这对应于增加区间图的色数。

 输入：```

```我们跟踪小组作业：

 | 细分 | 堆之前 | 行动| 团体成立|
 | --- | --- | --- | --- |
 | (1,5) | 空 | 新组 0 | [1] |
 | (2,3) | (5,0)| 新组 1 | [1], [2] |

这表明重用如何取决于最早的整理组，而不是到达顺序。

 ## 边缘情况

 一个关键的边缘情况是间隔仅在端点处接触。 例如，`[1,2]`和`[2,3]`不能分组在一起，因为它们相交于 2。 堆条件`end < l`严格执行这一点，防止无效重用。 

另一种边缘情况是间隔以相反顺序到达时。 无论输入顺序如何，按左端点排序都可以确保正确性，因为分组仅取决于结构，而不取决于顺序。 

最后，当许多间隔从同一点开始时，算法会快速创建多个组。 堆仍然确保每个新间隔在现有链中以最佳方式放置，并且组的数量与该点的最大同时重叠相匹配。
