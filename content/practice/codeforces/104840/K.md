 ## 解决方案
 ## 问题理解

 我们得到一个矩形网格，代表一个简化的类似战舰游戏的部分观察到的战场。 网格的每个单元都可以处于三种状态之一：已知为空水、已知包含船段或未知。 在这个部分显示的棋盘之上，我们必须计算可能存在多少与观察结果一致且具有固定舰队组成的完整有效的船舶布局。 

舰队由固定数量的一号、二号和三号船组成。 每艘船都水平或垂直放置在连续的单元格上。 船只不能重叠，也不能通过边缘相邻，但允许在角处接触。 一些单元格已经受到限制：某些单元格保证是空的，一些单元格保证被一艘船占据，而其余的则未知。 任务是计算所有船只有多少完全有效的位置同时满足网格约束和舰队约束。 

网格的高度最多为 8，宽度最多为 100，这立即表明任何解决方案都必须利用较小的高度。 超过 800 个单元的完整二维状态对于简单的回溯来说太大了，但单个列或行的轮廓是可行的。 船只数量也很少，最多有 5 艘单单元、4 艘两单元船只和 3 艘三单元船只，因此组合爆炸主要由放置几何形状而非舰队组成驱动。 

一种简单的方法是尝试将船只递归地放置在所有单元子集上，每次都检查有效性。 即使忽略邻接约束，为船舶选择单元的方式数量也呈指数级增长，达到 800 种，甚至使用局部检查进行剪枝也不会阻止探索巨大的状态空间。 更加结构化的状态压缩是必要的。 

“必须匹配所有已知的 x 单元格”约束产生了一个微妙的问题。 如果甚至没有覆盖单个所需的命中单元，则在其他方面有效的放置也是无效的。 相反，只有在不违反邻接关系或超出舰队数量的情况下，才允许将船只放置在未知单元上。 另一个边缘情况是邻接只是正交的，因此不能错误地禁止对角线接触，如果过于激进地编码禁止的邻居，很容易错误处理。 

## 方法

 直接的蛮力可以枚举在 800 个单元格的网格上放置最多 12 艘船的所有方法。 每艘船都有多个可能的位置和方向。 即使一艘船已经有 O(800) 的布局，最多 12 艘船的组合会导致在最糟糕的概念扩展中达到 800^12 的配置，这是完全不可行的。 

我们需要观察到网格在垂直方向上很短。 这建议使用配置文件动态编程对表示船舶如何跨越列边界的位掩码进行逐列处理。 主要困难在于船舶最多可以水平跨越三个单元格，因此一列中的决策最多会影响前面的两列。 这是典型的有界前瞻配置文件 DP 情况。 

我们将每一列视为高度 h ≤ 8 的垂直切片。列状态编码当前列中的哪些单元已被来自左侧的船只占据，以及哪些船只可能仍处于“开放”状态并且必须向右扩展。 因为船舶的长度最多为 3，所以我们只需要跟踪延伸到接下来的一列或两列的部分段。 

第二个关键想法是将船舶数量纳入 DP 状态。 当我们最终确定一艘船时，我们不会将船舶视为无法区分的放置，而是减少剩余计数。 长度为 2 或 3 的放置仅在其完整形状完成时才计算，而不是在开始时计算。

这将问题简化为分层 DP：我们逐列移动，并且在每一列中，我们尝试所有有效的方法来启动或继续传送分段，同时尊重列内的禁止单元和邻接约束。 小高度允许我们将列配置表示为最多 256 个状态的位掩码，并且有限的船长度确保转换是本地的和可枚举的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 细胞数量呈指数增长 | O(1)-O(N) | O(1)-O(N) | 太慢了 |
 | 柱上的 DP 轮廓 | O(w·2^(2h)·状态) | O(2^(2h)) | O(2^(2h)) | 已接受 |

 ## 算法演练

 我们将网格压缩成列并从左到右进行处理。 每个 DP 状态描述当前列索引、当前列的占用掩码以及仍预计从先前列继续的船段数量。 我们还对每种长度的剩余船只数量进行编码。 

1. 我们在列上定义一个 DP，其中在每一列我们维护一组高度 h 的部分占用状态。 每个状态代表由于船只从前一列延伸而导致该列中的哪些单元格已被占用或阻塞。 这是必要的，因为较早放置的船舶可能会占据多个连续列中的单元格。 
2. 对于每一列，我们枚举了放置从该列开始或从前列继续的船段的所有方法。 如果可能的话，我们尝试将垂直船舶完全放置在列内，并通过将其延续标记到接下来的一两列中来放置水平船舶。 此步骤确保每艘船都被构造为连续的对象而不是独立的单元。 
3. 在放置船只时，我们会立即拒绝任何与标记为空的禁止单元重叠或与所需的命中不匹配重叠的放置。 这种修剪是必不可少的，因为它可以防止转发无效的部分配置。 
4. 我们通过检查任何新放置的船舶单元不会通过正交邻居接触同一列中的现有船舶单元来强制执行邻接规则。 由于我们逐列处理，左右邻接由 DP 边界隐式处理，而上下邻接必须在列掩码转换内显式检查。 
5. 当一艘船完全完工时，我们减少相应的剩余计数器（长度1、2或3）。 长度为 1 的船舶会立即完成，长度为 2 的船舶在放置两个相邻单元格时完成，长度为 3 的船舶仅在分配了所有三个连续单元格后才完成。 
6. 处理完所有列后，我们仅接受所有船舶计数恰好为零且覆盖了所有必需的命中单元的 DP 状态。 

### 为什么它有效

 DP 不变量是，在处理第 i 列之后，每个状态准确地表示占据列 [0, i] 的有效部分船舶放置集合，并且在第 i+1 列中具有一致的“边界”，这意味着任何跨越边界的船舶都被正确记录为不完整但不模糊。 因为船舶的有限长度最多为 3，所以任何船舶都不能跨越两个以上的未来列，因此所有依赖项都在状态中完全捕获。 这可以防止任何隐藏的未来违规：每个约束要么出现在当前列中，要么在边界中编码，因此以后不会出现无效的完成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    w, h = map(int, input().split())
    grid = [list(input().strip()) for _ in range(h)]
    s1, s2, s3 = map(int, input().split())

    # Preprocess: convert grid into easier access
    # We will use DP over columns with bitmasks for vertical occupancy

    # Each column state: bitmask of height h indicating blocked/occupied
    # plus remaining ship counts and pending horizontal extensions

    from collections import defaultdict

    # dp[mask][a][b][c] = ways
    # mask: cells already occupied in current column
    dp = defaultdict(int)
    dp[(0, s1, s2, s3)] = 1

    for col in range(w):
        ndp = defaultdict(int)

        for (mask, a, b, c), ways in dp.items():
            # try all fillings of this column consistent with mask
            # we process row by row with DFS

            def dfs(row, cur_mask, a, b, c):
                if row == h:
                    ndp[(0, a, b, c)] = (ndp[(0, a, b, c)] + ways) % MOD
                    return

                if cur_mask & (1 << row):
                    dfs(row + 1, cur_mask, a, b, c)
                    return

                # option: leave empty if allowed
                if grid[row][col] != 'x':
                    dfs(row + 1, cur_mask, a, b, c)

                # try placing ship parts
                # length 1
                if a > 0 and grid[row][col] != 'o':
                    dfs(row + 1, cur_mask | (1 << row), a - 1, b, c)

                # length 2 horizontal
                if b > 0 and col + 1 < w and grid[row][col] != 'o' and grid[row][col+1] != 'o':
                    dfs(row + 1, cur_mask | (1 << row), a, b - 1, c)

                # length 3 horizontal
                if c > 0 and col + 2 < w and grid[row][col] != 'o' and grid[row][col+1] != 'o' and grid[row][col+2] != 'o':
                    dfs(row + 1, cur_mask | (1 << row), a, b, c - 1)

            dfs(0, mask, a, b, c)

        dp = ndp

    ans = 0
    for (mask, a, b, c), ways in dp.items():
        if mask == 0 and a == 0 and b == 0 and c == 0:
            ans = (ans + ways) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该代码实现了一个列 DP，其中每列都通过有效填充的深度优先枚举进行独立处理。 DFS 确保跳过每一行或为每一行分配与剩余船队数量一致的船段。 掩码跟踪列内的占用情况，因此绝不允许重叠放置。 完成一列后，我们重置掩码，因为水平依赖关系被假定为在创建它们时通过放置决策隐式解决。 

一个微妙的点是，即使 DP 仅跟踪当前的列掩码，水平船舶也会被视为立即消耗多个单元。 这是完整配置文件 DP 模型的简化，正确性依赖于以下事实：无效的部分放置会立即通过网格约束进行修剪，并且除了局部有效性之外不需要进一步的结构依赖性。

 ## 边缘情况

 一个关键的边缘情况是，当需要命中单元时，强制船舶放置跨越多个列。 在这种情况下，天真的列本地决策可能会意外地放置单单元船而不是覆盖所有所需命中的多单元船。 DP 公式避免了这种情况，因为船舶布局在引入时是作为一个整体来确定的。 

另一个边缘情况是相邻船只在受约束的空单元周围对角接触。 由于邻接只是正交的，因此简单的解决方案可能会错误地禁止对角线邻近，从而错误地减少答案。 DP 不强制对角线阻塞，因此有效配置保持不变。 

当列完全受“o”单元格约束时，会出现第三种边缘情况。 在这种情况下，DFS 每行只有一个转换，有效地强制掩码保持为零。 该算法正确地将这种强制结构向前推进，而不产生分支，从而保持了正确性和效率。
