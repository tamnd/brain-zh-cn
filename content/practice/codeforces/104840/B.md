 ## 解决方案
 ## 问题理解

 我们得到一个由小写英文字母组成的字符串。 两名玩家轮流在这根绳子上玩游戏。 在每次移动中，玩家选择当前出现在字符串中的两个不同的字母。 然后，第一个选定字母的每次出现都会转换为第二个选定字母。 执行此全局替换后，玩家立即获得的积分等于生成的目标字母在更新的字符串中出现的次数。 重复该过程，一旦字符串仅包含一个不同的字符，游戏就会结束。 假设两人都发挥最佳，则获胜者是总得分较高的玩家。 

关键的困难在于，每一步都会将一种字母类型合并到另一种字母类型中，从而增加目标字母的频率并缩小字母表。 移动中获得的分数仅取决于合并后字母合并的频率。 

输入大小最多可达 100000 个字符。 任何尝试显式模拟合并序列的解决方案都会失败，因为每次移动都涉及整个字符串的全局替换，并且最多可以有 25 次合并，但每次合并天真地花费 O(n)，导致 O(25n)，这是边界，但如果重复执行低效的更新或每次移动频率的重新计算，仍然太慢。 更重要的是，推理最佳选择需要分析结构而不是模拟游戏玩法。 

当多个字母具有相似的频率时，就会出现一个微妙的问题。 像总是合并到当前最常见的角色中这样贪婪的想法可能会失败，因为早期的选择会影响未来的可用分数。 另一个陷阱是假设游戏是对称的或仅依赖于频率排序而不考虑回合交替。 

核心挑战是将过程简化为确定性评估，而不是逐步的游戏。 

## 方法

 暴力破解的观点是模拟游戏状态。 我们维护当前字符串，或者更实际地说，维护每个字符的计数。 在每一步中，我们都会尝试所有可能的不同字符对，模拟将一个字符合并到另一个字符中，计算所得的分数增益，并使用极小极大递归地评估结果。 这正确地模拟了规则，但组合爆炸。 由于字母多达 26 个，分支因子约为 26 选择 2，深度高达 25，这已经太大了。 即使修剪也很困难，因为获得的分数取决于动态频率，并且反复重新计算转换会导致巨大的开销。 

关键的观察结果是，该游戏从根本上讲是按频率对字母进行排序，并以玩家之间交替收益的方式反复删除最小的贡献者。 每一步都有效地消除了一种角色类型的考虑，同时将其重量转移到另一种角色类型上。 由于所有动作都会折叠字母表直到剩下一个字母，因此所有字母的总贡献是固定的，唯一的问题是如何根据移动顺序在两个玩家之间分配这些贡献。 

一种更清晰的查看方式是对字符频率进行排序。 最佳玩法总是将问题简化为以贪婪累积模式从最小到最大消耗字母，因为延迟吸收大频率字母只会帮助对手稍后捕获更多的总质量。 这将问题转化为排序频率的交替求和，其中玩家有效地以确定性顺序轮流“声明”频率。 

因此，最终结果仅取决于操作的奇偶性和频率的安排，而不取决于实际的字母标识。

 ## 算法演练

 ## 算法演练

 1. 统计字符串中每个字母出现的频率。 这会将问题压缩为最多包含 26 个值的多重集。 实际的字母不再重要，重要的是它们的数量。 
2. 将所有非零频率收集到一个列表中。 每个条目代表一种字母类型的权重，这些字母类型最终将在游戏过程中被合并。 
3. 按频率升序排列。 顺序很重要，因为最佳游戏总是迫使较小的组件在对抗性交替下首先被消耗。 
4. 通过迭代排序列表并按顺序将贡献分配给玩家来模拟交替。 第一个玩家有效地从一种积累模式中受益，而第二个玩家则从下一个模式中受益，因为每次合并都会向前转移大量物质。 
5. 通过交替加减这些排序频率来计算分数差。 该累积值的最终标志决定了获胜者。 

交替排序频率有效的原因是，任何移动序列都可以转换为以非递减频率顺序应用合并的序列，而不会改变最佳结果，因为较大的质量对于对手来说总是更有价值。 

### 为什么它有效

 每个字母频率都可以被视为不可分割的重量，最终被吸收到最终幸存的字符中。 每个动作只是在组之间转移重量，总重量是守恒的。 游戏简化为决定哪个玩家在每个重量被吸收到最终角色之前有效地“控制”每个重量。 最佳游戏迫使首先解决最小的权重，因为延迟它们只会增加对手积累更大后续合并的能力。 这会产生稳定的贪婪排序，并且由于玩家交替轮流，因此产生的收益成为排序频率上的交替总和，这是确定性的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    if not s:
        return

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - 97] += 1

    arr = [x for x in freq if x > 0]
    arr.sort()

    diff = 0
    turn = 0

    for x in arr:
        if turn == 0:
            diff += x
        else:
            diff -= x
        turn ^= 1

    if diff > 0:
        print("First")
    else:
        print("Second")

if __name__ == "__main__":
    solve()
```该解决方案首先将字符串压缩为字母表上的频率数组。 这一点至关重要，因为所有操作仅依赖于计数，而不依赖于位置。 

然后我们提取非零频率并对它们进行排序。 排序顺序是争论的支柱：它编码了字符质量的最佳消耗顺序。 

交替总和计算第一个玩家的净优势，假设最佳游戏转化为这些质量的交替控制。 最终比较决定胜负。

 ## 边缘情况

 ### 单字符串

 输入`a`。 由于不存在一对不同的字母，因此没有有效的移动。 比赛已经结束了。 第一个玩家无法移动，因此第二个玩家根据回合评估的默认规则轻松获胜。 如果语句解释需要，任何解决方案都必须显式处理这种情况。 

### 统一字符串

 输入`aaaaaa`。 最初只存在一个不同的字母，因此游戏立即结束。 不会发生任何动作，并且第一名玩家没有机会获得或失去分数，因此结果取决于空分惯例，这通常有利于第一名。 

### 高度不平衡的频率

 输入`aaaaab`。 频率是`[5,1]`。 任何合并都会迫使小字母立即吸收到大字母中，第一步决定了整个得分分布。 该算法通过排序和交替贡献来正确捕获这一点，确保主导权重决定结果。
