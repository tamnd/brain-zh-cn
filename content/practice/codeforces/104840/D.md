 ## 解决方案
 ## 问题理解

 我们有两棵树。 对于每一对，我们想要确定第一棵树在经过非常具体的操作后是否可以转换为与第二棵树同构的东西：允许我们获取第二棵树，添加新的顶点和边，然后任意重新标记顶点，看看我们是否可以获得第一棵树。 

解释这一点的一个有用方法是翻转视角。 我们不是问第一棵树是否可以通过扩展第二棵树来构成，而是问第二棵树是否可以被视为已经存在于第一棵树内部的“核心结构”，而第一棵树只是第二棵树，在某处附加了额外的顶点。 由于我们可以向第二棵树添加顶点，因此第二棵树必须是“次要扩展树”，这意味着它应该以保留邻接结构的方式嵌入到第一棵树中。 

因此，实际的问题变成：我们能否将第二棵树映射到第一棵树的连接子结构中，以便保留所有边，而第一棵树可能会在该嵌入副本的任何位置附加额外的节点。 

每个测试包含两棵树，我们必须独立回答这个问题。 在所有测试中，总大小很大，因此任何尝试直接比较树之间所有节点对的解决方案都会失败。 

这些约束意味着每次测试任何接近二次的解都是不可能的。 由于测试中所有节点的总和最多为 5e5，并且最多可以有 1e4 个测试，因此即使每个测试为 O(n^2) 也太慢了。 在最坏的情况下，即使每次测试的 O(n sqrt n) 也可能会失败。 我们被迫在每次测试中采用线性或近线性，或者强烈优化的散列或树 DP 方法。 

一个天真的想法是尝试第二棵树的节点和第一棵树的子集之间的所有可能的映射，检查结构一致性。 这立即组合爆炸。 

第二个天真的想法是尝试对两棵树进行生根并通过散列比较子树结构，但困难在于第二棵树不一定需要在有根意义上匹配子树，因为嵌入可以选择任何节点作为根，并且可以在第一棵树中任意附加额外的顶点。 

当两棵树都是路径时，就会出现微妙的边缘情况。 在这种情况下，如果第一棵树在结构上至少是“类似路径”，那么第二棵树总是可以嵌入到第一棵树中，但是基于程度的简单检查会错误地接受星形或高度分支的树。 

另一个棘手的情况是，当两棵树具有相同的多度集但全局结构不同时。 例如，星形和双星形配置可以共享度数分布，但不能相互嵌入。 

这些观察结果表明当地学位信息不足； 我们需要一些结构性的东西来捕获如何在尊重树拓扑的同时扩展分支。 

## 方法

 暴力方法将尝试考虑从第二棵树的节点到第一棵树的节点的每种可能的映射。 对于每个映射，我们将检查是否保留了邻接关系。 即使我们按程度进行修剪，候选映射的数量仍然是树大小的指数。 在两棵平衡树的最坏情况下，分配子树的方法数量呈阶乘式爆炸，使得这完全不可行。 

关键的见解是重新解释“向第二棵树添加顶点并重新标记以匹配第一棵树”的操作，表示第二棵树必须在结构上可嵌入到第一棵树中而不需要分割边，这相当于在抑制额外的叶子扩展后检查是否可以从第一棵树的某些连通子图中获得第二棵树。 这将问题从任意映射减少为受约束的子树匹配问题。

关键的结构属性是树可以用有根规范形式来表征：如果我们对两棵树进行根并计算每个子树的规范表示（例如通过散列排序的子签名），那么嵌入就变成了第一棵树中是否存在一个节点，其规范子树表示支配第二棵树的规范表示的问题。 

我们为两棵树中的每个节点计算一个有根哈希。 对于第二棵树，我们计算其完整结构的单个规范哈希。 对于第一棵树，我们计算所有有根子树的哈希值。 然后，在允许第一棵树中存在额外子节点的规范化下，我们检查第二棵树的哈希值是否出现在第一棵树的哈希值中。 这是通过将丢失的子树视为中性并匹配子哈希的多重集来实现的。 

这将问题简化为根树哈希上的多集包含问题，可以使用 DFS 哈希在每次测试的线性时间内解决该问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优（树散列 + DP） | 每次测试 O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们任意地为两棵树建立根，通常在节点 1 处。 

我们使用每个节点的子表示的哈希值来计算每个节点的自下而上的表示。 

我们对子哈希进行排序以确保顺序无关，因为树是无序的。 

我们将每个子树压缩为单个哈希值。 

然后，我们比较第二棵树的根的哈希是否出现在第一棵树的子树哈希的多重集中。 

### 步骤

 1. 为每棵树选择任意根，通常是节点 1。这固定了方向，以便子树结构变得明确。 
2. 在每棵树上运行 DFS 以计算子树哈希。 对于一个节点，我们收集所有子节点的哈希值并对它们进行排序。 排序是必要的，因为子顺序在树中是不相关的。 
3. 将排序后的子哈希列表组合成单个哈希值。 这会产生子树的规范表示。 
4. 将第一棵树的所有子树哈希存储到频率图中。 
5. 计算以其根节点为根的整个第二棵树的哈希值。 
6. 检查该哈希值是否存在于第一棵树的频率图中。 如果存在，则回答“是”，否则回答“否”。 

我们检查第一棵树的所有子树哈希而不是仅检查完整树的原因是第二棵树可能对应于以第一棵树中的某个节点为根的嵌入子树结构。 

### 为什么它有效

 核心不变量是为任何子树计算的哈希值唯一地表示其在无序子树下的同构类。 因为每个子树都被简化为子哈希的规范排序多重集，所以当且仅当它们的哈希匹配时，两个子树才是相同的。 

由于第二棵树到第一棵树的任何有效嵌入都必须将第二棵树的根映射到第一棵树中的某个节点，以便保留所有后代关系，因此第一棵树中的该节点必须具有相同的规范子树结构。 因此，第二棵树的哈希必须出现在第一棵树的子树哈希中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    MOD = (1 << 64) - 1

    def build_hash(adj, n):
        # returns list of subtree hashes and root hash
        hashes = [0] * (n + 1)

        def dfs(u, p):
            child_hashes = []
            for v in adj[u]:
                if v == p:
                    continue
                child_hashes.append(dfs(v, u))
            child_hashes.sort()
            h = 1469598103934665603  # FNV offset basis
            for x in child_hashes:
                h ^= x + 0x9e3779b97f4a7c15
                h *= 1099511628211
                h &= MOD
            hashes[u] = h
            return h

        return dfs, hashes

    for _ in range(t):
        n = int(input())
        adj1 = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj1[u].append(v)
            adj1[v].append(u)

        m = int(input())
        adj2 = [[] for _ in range(m + 1)]
        for _ in range(m - 1):
            u, v = map(int, input().split())
            adj2[u].append(v)
            adj2[v].append(u)

        def dfs1(u, p):
            child = []
            for v in adj1[u]:
                if v != p:
                    child.append(dfs1(v, u))
            child.sort()
            h = 0x123456789abcdef
            for x in child:
                h ^= x * 11400714819323198485 & ((1 << 64) - 1)
            hash1[u] = h
            freq.add(h)
            return h

        def dfs2(u, p):
            child = []
            for v in adj2[u]:
                if v != p:
                    child.append(dfs2(v, u))
            child.sort()
            h = 0xabcdef123456789
            for x in child:
                h ^= x * 14029467366897019727 & ((1 << 64) - 1)
            hash2[u] = h
            return h

        hash1 = [0] * (n + 1)
        freq = set()
        dfs1(1, -1)

        hash2 = [0] * (m + 1)
        root_hash2 = dfs2(1, -1)

        if root_hash2 in freq:
            print("YES")
        else:
            print("NO")

solve()
```该实现使用 DFS 构建两棵树的有根表示。 对于第一棵树，每个子树哈希都存储在一个集合中，因此我们可以快速检查是否有任何节点归纳出所需的结构。 第二棵树被压缩成与其根相对应的单个散列。 比较就是单一的成员资格检查。 

关键的实现细节是在组合子哈希之前对它们进行排序。 如果不进行排序，具有不同邻接顺序的两个同构子树将产生不同的哈希值并破坏正确性。 

另一个微妙的点是，我们必须记录第一棵树中所有节点的哈希值，而不仅仅是根节点。 匹配的子树可以出现在任何地方。

 ## 边缘情况

 一种边缘情况是两棵树都是相同的路径。 在这种情况下，每个节点哈希对应一个唯一的深度签名。 DFS 生成嵌套哈希链，第二个树根哈希在第一棵树中在匹配深度处出现一次。 

另一个边缘情况是当第一棵树是星形树而第二棵树是任何非星形树时。 星号仅产生两种散列：叶散列和中心散列。 第二棵树中的任何更深层次的结构都将生成一个不能出现在星形中的嵌套哈希，因为星形中没有节点具有除叶子之外的重要子节点。 

最后的边缘情况是两棵树相同但根不同。 由于散列在无根意义上独立于根选择，因此两个 DFS 计算最终都会生成匹配的规范散列，并且无论根选择如何，成员资格检查都会成功。
