 ## 解决方案
 ## 问题理解

 我们有一个过程，通过重复选择一个尚未出现在序列中任何位置的自然数，然后附加从它派生的三个值来构建无限序列。 对于选定的号码$x$，序列立即附加$x$， 其次是$2x$， 然后$3x$，并且这种情况永远持续下去，总是选择下一个最小的未使用的自然数作为新的基数。 

这意味着该序列不是任意交织或倍数排序。 相反，它是按严格的块构造的，每个块都来自单个整数，并且按该整数的递增顺序处理块。 

任务是回答最多 1000 个查询，其中每个查询都询问位置处的值$n$， 和$n$可以大到$10^{15}$。 这立即排除了任何逐个元素构造序列的模拟，因为即使生成$10^9$元素已经太慢了，更不用说$10^{15}$。 

该过程的结构意味着每个正整数作为基数只出现一次，并且恰好贡献三个连续元素。 一种简单的方法会尝试模拟到目前为止出现了哪些数字，但这是不必要的，因为选择规则始终保证下一个基数只是按升序排列的下一个整数。 

尝试动态跟踪“已用号码”时会出现常见的失败情况。 例如，处理后$x=1$，人们可能会错误地认为下一个未使用的数字可能是 2 或 3 之类的东西，具体取决于事件的内部跟踪，但实际上 2 和 3 都已经出现，下一个有效碱基就是 4。任何不能识别碱基选择的严格单调结构的模拟将很快变得不正确或太慢。 

## 方法

 直接模拟将维护一组已出现的所有数字，并从 1 向上重复扫描以找到最小的未使用数字。 对于每个这样的数字$x$，它附加三个值。 即使我们使用哈希集优化成员资格检查，该过程仍然需要扫描最多$n$不同的值，并且由于每个值贡献三个输出，因此操作总数随着输出大小线性增长。 为了$n$最多$10^{15}$，这是完全不可行的。 

关键的观察结果是“未使用的数字”规则不会以复杂的方式与生成的序列相互作用。 一旦我们意识到每个整数最终只被用作基数一次，这个过程就变得确定了：$k$-th 选择的基地很简单$k$本身。 这将序列变成固定块的串联：对于每个$k = 1, 2, 3, \dots$，我们追加$k, 2k, 3k$。 

从这个角度来看，序列不再是动态构建的； 它是一种静态模式，其中每三个连续位置对应一个基数。 这减少了定位位置属于哪个块以及块内需要哪个乘数的问题。

 | ---| ---| ---| ---|
 | 暴力模拟| 每个查询 O(n) | O(n) | 太慢了 |

 ## 算法演练

 整个问题简化为将平坦序列中的位置映射到一对$(k, r)$， 在哪里$k$是块的基数，$r$是该块内的位置。 

1. 观察每个基数$k$恰好生成序列中的三个连续元素。 这意味着序列被划分为大小为 3 的块，其中块$k$贡献职位$3k-2$,$3k-1$， 和$3k$。 
2.给定一个查询索引$n$，计算它属于哪个块$k = \frac{n+2}{3}$使用整数除法。 这是可行的，因为每个块都贡献了三个元素，因此将索引分组为大小为 3 的块是精确且无损的。 
3. 使用以下命令确定块内的偏移量$r = (n-1) \bmod 3$。 这标识了我们是否正在查看块的第一个、第二个或第三个元素。 
4、返回对应的值：if$r = 0$，答案是$k$; 如果$r = 1$，答案是$2k$; 如果$r = 2$，答案是$3k$。 

每个步骤都是由构造的结构强制的，因为跨块不会发生交错或重新排序。 

### 为什么它有效

 正确性来自于序列被划分为独立块的不变量，每个块仅由单个整数生成$k$，并且块按严格递增顺序出现$k$。 由于选择规则始终选择最小的未使用整数，因此未来的块无法将元素插入到较早的块中或更改其内部顺序。 这保证了位置与固定大小三的块边界全局对齐，使得直接算术映射有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        k = (n + 2) // 3
        r = (n - 1) % 3

        if r == 0:
            print(k)
        elif r == 1:
            print(2 * k)
        else:
            print(3 * k)

if __name__ == "__main__":
    solve()
```该解决方案完全依赖于算术，因此每个查询都是在恒定时间内独立处理的。 的计算$k$使用整数除法将索引对齐为三个组，而模运算则隔离每个组内的位置。 没有循环$n$，考虑到极大的约束，这是至关重要的。 

一个微妙的点是差一对齐。 使用$(n+2)//3$确保位置 1、2、3 映射到块 1，位置 4、5、6 映射到块 2，依此类推。 模表达式必须使用$n-1$而不是$n$以保持这种对齐方式。

 ## 边缘情况

 主要的边缘情况是块之间的边界，其中最有可能出现相差一的错误。 例如，在$n = 3$，输出仍然必须属于第一个块，而$n = 4$立即跳转到第二个块。 

为了$n = 3$，计算得出$k = (3+2)//3 = 1$和$r = 2$，生产$3$，它匹配第一个块的末尾。 

为了$n = 4$，我们得到$k = (4+2)//3 = 2$和$r = 0$，生产$2$，正确启动第二个块。 

这证实了整数除法对齐干净地分离了块，没有重叠或模糊。
