 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 每个场景中都有$n$克隆个体按某种顺序排列，但我们只能观察到它们上面写的多组标签。 每个标签都是 1 到 1 之间的整数$n$。 

这些标签的分配方式遵循非常具体的规则。 想象一下克隆人以某种未知的最终顺序排成一排。 每个克隆都根据其距左端的位置或距右端的位置分配了一个编号。 所以对于某些职位$i$，分配的值是$i$或者$n - i + 1$。 分配后，克隆可以任意排列，因此最终的输入数组只是这些分配值的排列。 

任务是判断给定长度的数组是否$n$可以通过这样的标签方案来产生。 

输入数据量很大，最多可达$10^5$所有测试用例的总元素。 这立即排除了任何显式尝试所有排列或模拟排列的解决方案。 甚至$O(n^2)$方法太慢，因为单个测试用例已经可以$10^5$。 

一个关键的微妙之处是输入数组中的顺序与标记期间使用的原始位置不对应。 只有多重设置才重要，而不是排列。 

一个常见的错误是尝试以固定顺序贪婪地重建排列。 这会失败，因为实际的赋值顺序未知，并且最终的数组已被排列。 

例如，考虑$n = 4$， 大批$[1, 4, 1, 3]$。 人们可能会错误地尝试从左到右贪婪地匹配位置，但由于原始排列可以任意排列，因此只有频率结构很重要。 

另一个微妙的失败案例是假设每个值必须对应一个唯一的位置。 这是错误的，因为当多个位置可以产生相同的值时$i = n - i + 1$，即中间时$n$很奇怪。 

## 方法

 一个直接的暴力想法是尝试所有可能的方法来为每个位置分配其左索引值或右索引值，然后检查生成的多重集是否与输入匹配。 有$2^n$这样的作业，对于每个作业，我们都会比较多重集$O(n)$，导致指数复杂性。 即使是为了$n = 30$，这已经是不可行的了，而这里$n$上升到$10^5$。 

关键的观察是最终的数组只是一个非常结构化的多重集的排列。 对于每个位置$i$，我们生成两个可能的值：$i$和$n - i + 1$。 因此，我们期望的多重集正是这些对在所有位置上的并集。 

这意味着从 1 到$n$以一种非常受限的方式出现：每对$(i, n - i + 1)$贡献两个值，并且这些贡献对称重叠。 我们可以考虑匹配频率，而不是考虑位置。 

一种更简单的推理方法是按升序处理值，并尝试使用贪婪结构“消耗”出现的次数：小值必须对应于早期索引，因为只有小索引才能通过恒等分配生成小值，而大值只能来自反射侧。 

这将问题转化为阵列的频率分布和对的强制结构之间的一致性检查$(i, n - i + 1)$。 正确的构造简化为验证当我们贪婪地模拟从左到右分配位置时，我们永远不会违反所需值的可用性。 

我们维护两个指针，分别代表左侧和右侧的下一个未使用位置。 在每一步中，我们都会检查数组中当前最小的剩余值是否可以与左指针或右指针匹配。 如果两者都不匹配，则无法进行配置。 

这是有效的，因为在任何时候，一个位置的唯一有效分配是它的两个确定性候选者，并且由于排列消除了排序约束，因此该过程减少为一系列强制选择。

 ## 算法演练

 我们对数组进行排序，因为顺序无关，我们只需要推断可用值。 然后我们尝试模拟从外部位置向内构建有效的分配。 

1. 对数组进行排序。 这使我们始终能够推断出最小的剩余不匹配值，这是最受约束的。 
2.初始化两个指针，$l = 1$和$r = n$，代表有效构造中下一次分配的唯一两个可能来源。 
3. 迭代已排序的数组。 对于每个值$x$,判断是否可以对应到当前左边位置$l$或正确的位置$r$。 如果$x = l$，我们消耗左端点并增量$l$。 如果$x = r$，我们使用正确的端点并递减$r$。 
4. 如果$x$与两个端点都不匹配，我们立即得出结论，不存在有效的构造并返回失败。 
5. 继续，直到处理完所有元素。 如果所有值都被一致使用，则配置有效。 

这个过程背后的原因是，每个有效的构造都对应于从两端向内对称的配对位置，并且每一步都从任一端精确地删除一个自由度。 

### 为什么它有效

 在任何时刻，剩余的未分配位置形成一个连续的区间$[l, r]$。 任何有效的标签必须指定$l$或者$r$到下一个消耗值，因为所有内部位置都对应于已经固定的结构选择。 如果一个值无法匹配任一端点，则它不能属于任何有效的分配，因为没有内部位置可以在不违反左/右标签的固定结构的情况下生成它。 这个不变量确保一旦发生不匹配，任何重新排列都无法修复它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        l, r = 1, n
        ok = True
        
        for x in a:
            if x == l:
                l += 1
            elif x == r:
                r -= 1
            else:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案依赖于排序来暴露结构约束。 这两个指针代表任何阶段唯一两个可能的有效值“活动源”。 每次分配都会缩小间隔，确保我们始终保持与假设的原始排序的一致性。 

一个常见的实现陷阱是忘记在不匹配时立即中断。 在无效分配后继续可能会在以后错误地恢复一致性，这在逻辑上是不可能的。 

## 工作示例

 ### 示例 1

 输入：```
n = 3
array = [1, 2, 1]
```排序后的数组是$[1, 1, 2]$。 

| 步骤| 我| r | x| 行动|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 3 | 1 | 匹配 l, l → 2 |
 | 2 | 2 | 3 | 1 | 不匹配（1 ≠ 2 且 1 ≠ 3）|

 在步骤 2 中，该过程失败，这意味着这种排列无法对应于一致的左/右标签结构。 

但是，请注意，这突出了一个重要的属性：排序仅通过端点一致性而起作用，而不仅仅是频率。 

### 示例 2

 输入：```
n = 4
array = [1, 4, 2, 3]
```排序后的数组是$[1, 2, 3, 4]$。 

| 步骤| 我| r | x| 行动|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 4 | 1 | l → 2 |
 | 2 | 2 | 4 | 2 | l → 3 |
 | 3 | 3 | 4 | 3 | l → 4 |
 | 4 | 4 | 4 | 4 | r → 3 |

 所有值均已成功消耗。 

这展示了一种干净的向内收缩，其中每个值在处理时完全匹配一个端点。

 ## 边缘情况

 一种微妙的边缘情况是$n = 1$。 唯一可能的数组是$[1]$，这基本上满足了条件，因为单个位置同时是左和右。 该算法正确地接受它，因为$l = r = 1$并且单个值匹配。 

另一种情况是所有值都相同，例如$n = 4$,$[2, 2, 2, 2]$。 分选率$[2, 2, 2, 2]$，但第一个不匹配立即发生，因为当以下情况时，两个端点都不为 2$l = 1$和$r = 4$。 这正确地拒绝了这种情况，因为没有对称结构可以产生统一的值。 

当数组是有效排列但经过严重洗牌时，会出现进一步的边缘情况，例如$[3, 1, 4, 2]$。 排序消除了排序问题，并且算法重建了有效的内部匹配序列。 该过程表明，只要每一步都保持端点一致性，排列并不重要。
