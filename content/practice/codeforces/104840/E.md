 ## 解决方案
 ## 问题理解

 给定一个排列，我们反复将其向左旋转一个位置，因此第一个元素移动到末尾。 每次旋转后，我们都会获得一个新的排列，并且每个版本都有自己的反转次数，这意味着索引对中较大的值出现在较小的值之前。 

任务是找出需要多少次旋转，直到排列达到所有循环移位中可能的反转计数最小的状态。 如果多次旋转达到相同的最小值，则任何小于 n 的有效答案都是可接受的。 

n 最大为 200000 的约束立即排除了每次旋转时从头开始重新计算反转计数的可能性，因为这将是 O(n^2 log n) 或更糟。 即使 O(n^2) 操作也太大了。 我们需要评估所有 n 个旋转状态，同时重用以前的计算。 

当最佳配置已经是初始排列时，会出现微妙的边缘情况。 例如，如果数组已经按 [1, 2, 3, 4] 排序，则除恒等之外的每次旋转都会增加反转，因此答案应该为 0。另一个极端情况是当多次旋转与最小反转相关时，例如 [2, 1, 3] 等小循环模式，其中多次旋转产生相同的反转计数。 任何小于 n 的有效索引都是可接受的。 

关键的困难在于旋转以非局部方式改变全局反转结构，因此我们需要一种方法来更新每个班次 O(1) 或 O(log n) 的反转计数。 

## 方法

 一种直接的方法是独立计算 n 次旋转中每次旋转的反转计数。 对于每次旋转，我们可以使用 Fenwick 树或合并排序来重建数组并计算反转次数，时间复杂度为 O(n log n)。 执行此操作 n 次会导致 O(n^2 log n)，这对于 2·10^5 元素来说太慢了。 

重要的观察是，我们不需要在旋转后从头开始重新计算反演。 左旋转删除第一个元素 x 并将其附加到末尾。 所有其他相对顺序保持不变，因此反转计数仅由于涉及 x 的对而变化。 

在旋转之前，x 对其右侧小于 x 的元素进行反转。 旋转后，x 成为最后一个元素，因此它不再作为左索引出现在任何对中。 相反，它成为一个正确的索引，并与它之前和大于它的元素进行反转。 

这意味着我们可以使用两个量来表达反转变化：后缀中有多少个小于 x 的元素，以及剩余的多重集中有多少个大于 x 的元素。 两者都可以使用值上的 Fenwick 树以及位置上的前缀/后缀结构来维护。 

我们计算一次初始反转计数。 然后，对于每个位置 i，我们将 a[i] 视为移动到末尾的元素，并计算如果我们在该步骤进行旋转，反转计数将如何变化。 这使我们能够以 O(n log n) 的时间评估所有旋转状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 重新计算每次旋转 | O(n^2 log n) | O(n^2 log n) | O(n) | 太慢了 |
 | 基于 Fenwick 的每次旋转增量 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每次旋转视为“从前面删除元素 a[i] 并将其附加到末尾”，但我们使用原始数组和前缀/后缀范围来计算效果。 

1. 使用值上的 Fenwick 树计算数组的初始反转计数。

我们从左到右扫描，对于每个值 x，我们计算有多少个先前值大于 x。 这给出了基线反转计数 inv0。 
2.使用另一个Fenwick树预先计算值的前缀信息，这样对于任何值x，我们都可以查询整个数组中有多少元素小于或等于x。 
3、对于每个索引i，我们还需要后缀信息：位置i+1到n有多少个元素小于a[i]。 这可以通过使用维护后缀多重集的 Fenwick 树从右到左迭代来计算。 
4. 对于每个 i，计算将 a[i] 移动到末尾的效果。 设 x = a[i]。 

在删除之前，x 贡献的反转等于后缀中小于 x 的元素数量。 
5. 将x移动到末尾后，它成为最后一个元素。 现在，它贡献的反转等于大于 x 的剩余元素的数量。 该数量仅取决于值频率，而不取决于位置。 
6. 计算这两个贡献之间的差值以获得 delta[i]，即当旋转发生在 i 时反转计数的变化。 
7. 在 delta[i] 上构建前缀和，同时模拟从索引 0 开始的旋转。跟踪最小反转值和相应的旋转索引。 

### 为什么它有效

 每次反转要么不涉及移动的元素，要么只涉及一次。 所有不涉及 a[i] 的反转在旋转后保持不变，因为其他元素之间的相对顺序被保留。 因此，反转计数唯一可能的变化来自包含 a[i] 的对。 通过仔细区分 a[i] 是旋转前后反转中的左侧元素还是右侧元素，我们将全局更新减少为两个值范围内的计数查询。 由于这些查询与旋转顺序无关，因此我们可以在预处理后在线性时间内评估每个候选旋转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

n = int(input())
a = list(map(int, input().split()))

# 1) initial inversion count
bit = BIT(n)
inv0 = 0
for x in a:
    inv0 += bit.range_sum(x + 1, n)
    bit.add(x, 1)

# 2) suffix structure: suffix_less[i]
bit2 = BIT(n)
suffix_less = [0] * n
for i in range(n - 1, -1, -1):
    x = a[i]
    suffix_less[i] = bit2.sum(x - 1)
    bit2.add(x, 1)

# 3) global value counts
bit3 = BIT(n)
for x in a:
    bit3.add(x, 1)

def total_leq(x):
    return bit3.sum(x)

best = inv0
ans = 0
cur = inv0

for i in range(n):
    x = a[i]

    old = suffix_less[i]
    remaining_leq = total_leq(x) - 1
    new = (n - 1) - (remaining_leq - 0)

    # new formula simplifies to: (n - total_leq(x))
    new = n - total_leq(x)

    delta = new - old

    cur += delta
    if cur < best:
        best = cur
        ans = i

print(ans)
```该代码首先使用值上的 Fenwick 树以标准方式计算反转计数。 这建立了比较所有旋转的基线配置。 

后缀数组`suffix_less[i]`通过从右向左扫描来构建，为每个位置存储其后出现的较小值的数量。 这直接对应于每个元素的“旋转前”贡献，作为移动时它参与的反转的左端点。 

功能`total_leq(x)`在整个数组上使用 Fenwick 树来计算有多少元素小于或等于某个值。 这允许在 O(log n) 中计算有多少元素大于 x。 

对于每个旋转候选 i，我们计算当移动到末尾时 x 的反转贡献如何变化。 我们更新运行反演总数`cur`这样我们就可以有效地按顺序模拟所有旋转，同时仅应用局部增量。 跟踪所有状态的最小值。

 ## 边缘情况

 关键的边缘情况是当排列在索引 0 处已经是最佳时。在这种情况下，每个元素的后缀贡献最小，并且计算出的增量值永远不会产生比起始状态更好的反转计数。 算法初始化`best = inv0`和`ans = 0`，因此如果迭代期间没有出现改进，则输出仍为 0。 

另一种情况是多次旋转产生相同的最小反转计数。 因为算法仅在找到严格较小的值时更新答案，所以保留第一次出现的最小值，这在任何小于 n 的索引都可接受的要求下始终有效。 

最后，循环结构不会在步骤之间引入任何隐藏的依赖关系。 每个增量都是独立于原始数组计算的，因此即使我们模拟累积更新，正确性也不依赖于假设中间数组与原始位置匹配。
