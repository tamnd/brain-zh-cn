 ## 解决方案
 ## 问题理解

 我们被要求构建一个大小为$n \times n$，意思是一个充满数字的网格$1$到$n$这样每个数字在每行中恰好出现一次，在每列中恰好出现一次。 除了这个标准约束之外，从左上角到右下角的对角线有一个固定的总和，我们必须要么产生满足该对角线要求的任何有效拉丁方，要么报告这是不可能的。 

输入由多个测试用例组成。 每个测试用例给出了大小$n$和目标值$k$。 每个测试用例的输出要么是满足条件的有效拉丁方，要么是指示不可能的单词。 

从复杂性的角度来看，关键的含义是我们不处于每个测试用例的任意排列或图形匹配都可以接受的体制中，除非$n$很小。 该结构强烈表明解决方案要么是建设性模式，要么是带有修剪的回溯搜索。 对角线约束是行之间的唯一耦合，因此除了这个单一的全局总和条件之外，逐行独立性几乎是正确的。 

当目标总和超出可行范围时，会出现微妙的边缘情况。 最小可能的对角线和是$n$（所有对角线元素均为 1），最大的是$n^2$（所有对角线条目都是$n$）。 任何$k$超出这个区间是不可能的。 

另一种失败模式来自于尝试在不考虑对角线的情况下贪婪地填充拉丁方。 例如，标准循环拉丁方$n = 4$结构上有效，但其对角线和是固定的。 如果需要的话$k$不同的是，即使存在许多有效的解决方案，幼稚的构造也总是会失败$k$。 

## 方法

 一个自然的起点是考虑逐行构建正方形。 对于每一行，我们选择一个排列$1 \ldots n$，同时保持列不重复值。 这本质上是增量构建拉丁方，可以将其建模为带有列使用跟踪的回溯。 

这种强力方法的工作原理是尝试每行的每个有效排列，并拒绝违反列唯一性或超出对角线和的配置。 它是正确的，因为它系统地探索了所有有效的拉丁方，并且仅接受所有约束同时满足时的配置。 

然而，拉丁方的数量增长极其迅速。 即使是为了$n = 5$，可能性的数量足够大，以至于不进行修剪的简单搜索变得不可行。 最坏的情况涉及探索最多$n!$每行的排列$n$行，大致导致$(n!)^n$国家，这远远超出了任何合理的限度。 

使问题可解决的关键观察是约束在行和列中是局部的，对角线和是唯一的全局耦合。 这允许积极的修剪：一旦部分对角线和超过目标或即使在最佳情况下也无法达到目标，我们就可以丢弃该分支。 此外，列约束显着降低了分支因子。 

因此，解决方案变成了每一步都进行可行性检查的约束置换构造，而不是对所有拉丁方进行盲目枚举。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 拉丁方的暴力枚举|$O((n!)^n)$|$O(n^2)$| 太慢了|
 | 通过行和对角线修剪进行回溯 |$O(\text{pruned search})$|$O(n^2)$| 接受小$n$|

 ## 算法演练

 我们使用回溯逐行构造拉丁方，同时保留每列中已使用的数字。 

1. 首先，我们检查目标对角线和是否$k$甚至是可行的。 如果$k < n$或者$k > n^2$，不存在任何构造，因为每个对角线条目都位于$1$和$n$。 
2. 我们准备一个网格和一个列使用结构。 列跟踪器确保列中没有重复的数字。 
3.我们定义一个填充行的递归函数$r$。 在每一行，我们尝试所有排列$1 \ldots n$尊重列约束。 
4. 在构造候选行时，我们还跟踪对对角线的贡献。 如果我们处于位置$(r, r)$，所选值会影响运行总和。 
5. 完成一行后，我们计算剩余对角线和的界限。 未来可能的最小贡献是$1$每个剩余的对角线单元格，最大值为$n$每个细胞。 如果剩余所需金额超出此范围，我们会立即回溯。 
6. 如果我们成功填充所有行并且对角线和等于$k$，我们输出网格。 

关键的剪枝步骤是对剩余对角线和的可行性检查。 没有它，搜索空间就会爆炸； 有了它，大多数无效的部分分配都会立即被丢弃。 

### 为什么它有效

 该算法在每个递归深度都维护一个部分拉丁方，因此行和列约束始终在局部得到满足。 唯一的全局约束是对角线和，并且在每一步中，我们确保剩余的未填充对角线单元格仍然具有足够的灵活性来达到目标​​和。 这建立了一个不变量：递归探索的任何部分状态都可以扩展到完整有效的解决方案，除非由于不可行而被明确修剪。 由于所有有效配置都可以通过列约束下的行排列来实现，因此搜索在有效解空间上完成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, k):
    grid = [[0] * n for _ in range(n)]
    used = [[False] * (n + 1) for _ in range(n)]

    cols = [set() for _ in range(n)]
    ans = None

    def backtrack(r, diag_sum):
        nonlocal ans
        if ans is not None:
            return

        if r == n:
            if diag_sum == k:
                ans = [row[:] for row in grid]
            return

        remaining = n - r
        min_possible = diag_sum + remaining * 1
        max_possible = diag_sum + remaining * n
        if not (min_possible <= k <= max_possible):
            return

        def gen(row, curr, used_row):
            if len(curr) == n:
                yield curr[:]
                return
            for v in range(1, n + 1):
                if not used_row[v] and v not in cols[len(curr)]:
                    used_row[v] = True
                    curr.append(v)
                    cols[len(curr) - 1].add(v)
                    yield from gen(row, curr, used_row)
                    cols[len(curr) - 1].remove(v)
                    curr.pop()
                    used_row[v] = False

        for perm in gen(r, [], [False] * (n + 1)):
            grid[r] = perm
            new_diag = diag_sum + perm[r]
            backtrack(r + 1, new_diag)
            if ans is not None:
                return

    backtrack(0, 0)
    return ans

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        res = solve_case(n, k)
        if res is None:
            print("IMPOSSIBLE")
        else:
            for row in res:
                print(*row)

if __name__ == "__main__":
    main()
```该代码遵循逐行构造策略。 这`cols`结构通过跟踪每列中已使用的值来强制拉丁方属性。 递归生成器在这些约束下构建行的所有有效排列。 

仅当我们分配一行时才会更新对角线和，使用`perm[r]`。 这使得行之间的耦合最小化并且局部化为单个整数。 

基于剩余行的修剪条件可以防止搜索退化为完全枚举。 

## 工作示例

 考虑一个小案例$n = 3, k = 6$。 一种有效的解决方案是：

 | 步骤| 行| 部分网格| 对角线和|
 | ---| ---| ---| ---|
 | 0 | - | 空 | 0 |
 | 1 | [1,2,3]| [1 2 3] | 1 |
 | 2 | [2,3,1]| [1 2 3； 2 3 1] | 4 |
 | 3 | [3,1,2]| 完整| 6 |

 该迹线显示了对角线如何逐渐累积。 每个行选择都会影响局部拉丁约束和全局总和。 

现在考虑一个失败的案例$n = 3, k = 2$。 该算法很快就会拒绝分支，因为即使在放置第一行后可实现的最小对角线和也已经超出了可行性界限。 

| 步骤| 行| 部分网格| 对角线和| 可行范围|
 | ---| ---| ---| ---| ---|
 | 0 | - | 空 | 0 | [3,9]|
 | 1 | [1,2,3]| [1 2 3] | 1 | [2,9]|
 | 2 | 任何| 部分 | >2 不可能 | 修剪|

 修剪会尽早激活，防止不必要的探索。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(\text{pruned permutations})$| 通过从列约束和对角线边界进行积极修剪来回溯行排列 |
 | 空间|$O(n^2)$| 网格存储和递归状态|

 通过可行性检查和列约束大大减少了指数搜索。 对于小$n$，这很适合在限制范围内，而对于更大的$n$，修剪确保只探索一小部分状态。

 ## 边缘情况

 当$k < n$，算法在搜索开始之前立即拒绝。 这对应于甚至将所有对角线条目分配为$1$没有达到目标。 

为了$n = 2, k = 3$，搜索空间很小。 回溯尝试排列$[1,2]$对于第一行和$[2,1]$对于第二行，生成一个具有对角线和的有效平方$1 + 1 = 2$。 由于这不匹配$k$，它会回溯并尝试替代安排，最终找到正确的配置（如果存在）。 

对于不可能的情况，例如$n = 3, k = 2$，每个部分分配都会在第一行之后被切断，因为剩余行的最小可实现对角线和已经超过了目标。 这说明了剪枝条件如何在早期主导搜索并阻止全面探索。
