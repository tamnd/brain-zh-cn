 ## 解决方案
 ## 问题理解

 我们得到了一个时间间隔列表，代表必须在两个相同资源上安排的任务，通常被认为是两个人轮流工作。 每个间隔都有开始时间和结束时间，并且每个任务必须完全分配给这两个资源之一。 一种资源一次只能处理一项任务，因此其分配的时间间隔不得在时间上重叠。 

目标是确定是否可以在两个资源之间分配所有间隔而不发生冲突。 如果可能的话，我们必须输出一个有效的分配，指示哪个资源处理每个间隔。 如果不可能，我们输出不存在分配。 

输入大小最多允许大约十万个间隔，这会立即排除尝试所有分配的任何解决方案。 强力分配将检查每个间隔的两个选择，导致 2^n 种可能性，这在 n 超过 20 左右时变得不可行。即使在每次分配后天真地检查重叠也会将其进一步推向二次行为，这也太慢了。 

共享端点的间隔会出现一个微妙的问题。 例如，如果一项任务在时间 5 结束，另一项任务在时间 5 开始，则它们通常被视为不重叠。 将触摸间隔视为重叠的粗心实现会错误地拒绝有效案例。 

另一种边缘情况是多个间隔同时重叠时。 例如，三个间隔可能在单个时间点重叠，从而无法将它们安排在两个资源上。 在不考虑全局重叠结构的情况下分配间隔的贪婪方法在这里可能会失败。 

## 方法

 一个强力的想法是将每个间隔分配给资源 1 或资源 2，然后验证两个生成的计划是否有效。 这在概念上很简单：我们尝试所有 2^n 分配并检查是否有任何分配避免了每组内的重叠。 正确性是显而易见的，因为我们详尽地搜索了所有可能性。 失败点是性能。 对于 n 高达 100000 的情况，分配的数量是天文数字，甚至验证单个分配的成本也为 O(n log n) 或 O(n)，使得总数完全不可行。 

关键的观察是，这实际上并不是一个组合搜索问题。 该结构纯粹是时间性的。 在任何时刻，我们只需要知道有多少个间隔是活跃的。 由于只有两个资源，因此当三个或更多间隔同时重叠时，系统就会失败。 这将问题转化为与作业构造相结合的扫线可行性检查。 

我们不是猜测分配，而是按照开始时间的升序处理间隔。 我们维持这两种资源的当前可用性。 当一个间隔开始时，我们将其分配给当时当前空闲的任何资源。 如果两者都被占用，我们会检测到三个间隔重叠并得出不可能的结论。 这是有效的，因为最多允许两个同时活动间隔，并且我们总是贪婪地重用释放的资源。 

因此，最佳解决方案依赖于按开始时间对间隔进行排序并动态跟踪哪个资源首先变得空闲。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最优扫描+贪婪分配 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们以尊重时间顺序的方式处理间隔，因为冲突完全是由重叠的时间窗口决定的。

1. 读取所有区间并附加它们的原始索引，以便我们稍后可以重建输出分配。 这是必要的，因为排序会破坏原始顺序。 
2. 按开始时间对间隔进行排序。 这确保了当我们处理一个间隔时，所有较早开始的间隔都已被考虑，因此当前的重叠状态得到正确维护。 
3. 维护两个变量，表示两个资源何时变为空闲，最初都设置为 0。 
4. 按排序顺序迭代间隔。 对于每个时间间隔，检查资源 1 在时间间隔开始时间或之前是否空闲。 如果是，则将此时间间隔分配给资源 1，并将其下一个空闲时间更新到该时间间隔的末尾。 
5. 如果资源1不可用，则以同样的方式检查资源2。 如果空闲，则在那里分配时间间隔并更新其可用性。 
6. 如果两个资源都不可用，则意味着在该时间间隔开始时两者仍处于繁忙状态，因此此时三个时间间隔重叠。 在这种情况下，安排是不可能的，我们会提前终止。 
7. 将赋值存储在按原始位置索引的数组中，以便我们可以按输入顺序输出它们。 

正确性来自于以下不变量：在扫描中的任何点，两个跟踪的结束时间表示两个当前活动间隔的最后完成时间。 如果新的间隔无法放入任一槽位，则意味着存在第三个同时重叠，这违反了容量限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    intervals = []
    for i in range(n):
        s, e = map(int, input().split())
        intervals.append((s, e, i))

    intervals.sort()

    end1 = 0
    end2 = 0
    ans = [0] * n

    for s, e, i in intervals:
        if end1 <= s:
            ans[i] = 1
            end1 = e
        elif end2 <= s:
            ans[i] = 2
            end2 = e
        else:
            print("NO")
            return

    print("YES")
    print("".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```排序步骤确保我们始终以增加的开始时间处理间隔，从而使贪婪分配与实时可行性保持一致。 两个变量`end1`和`end2`代表每个资源的下一个可用时间。 支票`end <= s`在允许相等的意义上是严格的，这意味着在时间 t 结束的时间间隔恰好在 t 处释放资源。 

一个常见的实现错误是忘记保留原始索引，这会导致输出排序不正确。 另一个微妙的问题是打印格式：作业必须连接在一起，不带分隔符。

 ## 边缘情况

 一个关键的边缘情况是间隔仅在端点处接触。 例如，`(1,2)`和`(2,3)`应该可以在同一资源上进行调度。 在算法中，当第一个间隔在时间 2 结束时，`end1 = 2`，第二个间隔从 2 开始，所以`end1 <= s`持有并重复使用有效。 这证实了将末端相等视为不重叠的正确性。 

另一个重要的情况是始终两个间隔的最大重叠，例如`(1,10), (2,9), (3,8), (4,7)`。 该算法在两个资源之间交替分配，而不会触发失败，这表明容量二是足够的。 

最后，当第三个间隔在前两个间隔之一结束之前开始时，就会出现故障模式。 扫描线准确地捕捉到了这一点，因为`end1`和`end2`超过当前开始时间，在违反约束的那一刻强制拒绝。
