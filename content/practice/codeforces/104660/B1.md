 ## 解决方案
 ## 问题理解

 我们得到了连续书写的数字序列。 任务是在该序列周围插入括号，以便每个数字最终被多个等于其值的匹配括号包围，解释为嵌套深度。 

思考这个问题的一个有用方法是，我们正在构建一个位于数字之上的有效括号表达式。 每个数字代表它在左括号和右括号的层次结构中的“深度”。 如果数字为 0，则它不应位于任何括号内。 如果是 3，那么在该位置括号结构的深度一定已经是 3。 

输出不仅仅是数字，而是插入了额外括号的原始字符串，这样如果我们在从左到右扫描时跟踪当前有多少个左括号处于活动状态，那么该数字与我们打印时的每个数字完全匹配。 

这个问题的约束足够小，我们只需要在每个测试用例中处理一次字符串。 即使对于大型输入，任何与字符串长度呈线性的解决方案都足够了，因为我们只对每个字符执行恒定的工作。 任何试图全局搜索或递归构建有效结构的方法都将是不必要的开销，并且如果不小心实施，将面临二次行为的风险。 

一些边缘情况往往会破坏简单的实现。 当数字之间的转换很大时，就会发生一种常见的故障。 例如，从 0 到 9 需要一次添加 9 个左括号，从 9 回到 0 需要同时添加 9 个右括号。 忘记在最后完全关闭剩余深度的幼稚方法将留下无法匹配的括号。 

另一个微妙的情况是数字减少但不为零。 例如，从 4 移动到 2 需要在打印数字 2 之前关闭两个级别。如果解决方案仅打开括号并延迟关闭它们，则会违反有效性。 

最后，单字符输入，例如`"0"`或者`"9"`测试实现是否在不依赖先前上下文的情况下正确处理同一位置的打开和关闭。 

## 方法

 思考这个问题的强力方法是尝试在数字周围构建所有可能的平衡括号字符串，然后检查哪个字符串与每个位置所需的深度约束相匹配。 这很快就变得不可行，因为每个位置都可以打开、关闭或不执行任何操作，并且可能性的数量随着字符串长度呈指数增长。 即使我们尽早修剪无效结构，我们仍然有效地探索部分括号配置的大状态空间。 

关键的观察是我们实际上不需要猜测任何事情。 每个位置所需的深度由数字本身确定。 这意味着当我们从左到右扫描时，我们可以保持当前的嵌套深度并贪婪地调整它。 如果下一个数字需要比当前数字更深的级别，我们只需添加左括号即可​​。 如果需要较浅的级别，我们会关闭括号。 一旦深度匹配，我们就打印数字。 

这将问题转化为堆栈深度的单遍模拟，其中括号仅用于协调连续所需深度之间的差异。

 ## 算法演练

 我们从左到右处理字符串，同时跟踪当前的嵌套深度。 

1. 从当前深度等于 0 开始，因为开头没有括号。 这代表最外层。 
2. 对于字符串中的每个数字，将其值与当前深度进行比较。 如果数字大于当前深度，我们需要打开括号，直到深度匹配。 每个左括号都会将深度增加一。 这是必要的，因为如果不明确输入该级别，我们就无法将数字放置在更深的级别。 
3. 如果数字小于当前深度，则关闭括号，直到返回到所需的深度。 每个右括号都会将深度减一。 这可以确保我们不会将数字困在不正确的嵌套级别中。 
4. 一旦当前深度等于数字值，我们就输出数字本身。 此时，左括号的结构正确反映了该位置所需的嵌套。 
5. 处理完所有数字后，我们关闭所有剩余的左括号，直到深度返回到零。 需要进行最后的清理才能产生平衡的表达式。 

正确性依赖于维持这样的不变性：在打印每个数字之前，左括号的数量恰好等于数字值。 由于我们仅在深度与所需值不同时调整深度，因此我们从不引入不必要的括号，也从不违反有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    cur = 0
    out = []

    for ch in s:
        d = ord(ch) - 48

        while cur < d:
            out.append('(')
            cur += 1

        while cur > d:
            out.append(')')
            cur -= 1

        out.append(ch)

    while cur > 0:
        out.append(')')
        cur -= 1

    sys.stdout.write("".join(out) + "\n")

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该实现保持运行深度变量`cur`代表当前有多少个左括号处于活动状态。 对于每个数字，我们移动`cur`通过附加左括号或右括号来指向目标数字。 只有达到正确的深度后，我们才会添加数字本身。 

一个常见的实现错误是忘记了最后的清理循环，该循环关闭了最后一个数字之后剩余的括号。 如果没有它，输出在语法上将是无效的。 另一个微妙的问题是混淆何时添加相对于数字的括号； 当增加深度时，必须在数字之前发出括号；当减少深度时，也必须在数字之前发出括号，以确保数字放置在正确的嵌套级别。 

## 工作示例

 考虑输入字符串`"021"`。 

| 步骤| 数字| 当前深度| 行动| 输出|
 | ---| ---| ---| ---| ---|
 | 1 | 0 | 0 | 打印数字 | 0 |
 | 2 | 2 | 0 | 添加“((”，然后打印 | 0((2 |
 | 3 | 1 | 2 | 关闭“)”然后打印 | 0（（2）1 |

 处理后，我们关闭剩余的括号，给出`0((2)1)`。 

该跟踪显示了如何增量调整深度而不是从头开始重建。 每次转换仅取决于连续数字之间的差异。 

现在考虑`"312"`。 

| 步骤| 数字| 当前深度| 行动| 输出|
 | ---| ---| ---| ---| ---|
 | 1 | 3 | 0 | 打开 3，打印 3 | (((3 |
 | 2 | 1 | 3 | 关闭 2，打印 1 | (((3))1 |
 | 3 | 2 | 1 | 打开 1，打印 2 | (((3))1(2 |

 由于深度以 2 结束，所以不需要最终的闭包，因此我们添加两个右括号来得到`(((3))1(2))`。 

此示例强调了算法如何自然地处理递增和递减转换而无需回溯。

 ## 边缘情况

 完全零的字符串，例如`"000"`练习从未打开括号的情况。 算法保持`cur`始终为零，因此它仅打印数字而不进入调整深度的循环。 

严格递增序列如`"0123"`测试重复打开行为。 在每一步，算法都会比以前多打开一个括号，确保深度平滑增长而不会跳跃。 

严格递减序列如`"3210"`在打印数字之前验证关闭是否正确发生。 每个数字都会迫使算法首先减少深度，防止数字放置得太深。 

一位数`"9"`一次性检查开始和最终的清理工作。 该算法打开九个括号，打印数字，然后在最后关闭所有九个括号，从而在不依赖先前上下文的情况下确保平衡。
