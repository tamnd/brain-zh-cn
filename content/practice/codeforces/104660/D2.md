 ## 问题理解

 我们正在与一个隐藏的二进制数组交互，我们必须重建其内容。 该数组具有固定长度，但我们最初并不知道它的值。 我们可以查询各个位置并接收存储在那里的位。 

这种交互还有一个额外的复杂性。 在每十个查询的块之后，隐藏数组可以由法官以四种方式之一进行转换：它可以保持不变、反转、翻转所有位、或者同时反转和翻转。 我们不知道何时或发生哪种转变。 唯一的保证是它可能在每十次查询之后发生，每次都是独立的。 

目标是使用有限数量的查询正确恢复整个数组。 由于每个查询都很昂贵并且数组可能很大，因此重复探测位置而不考虑转换的幼稚策略将会失败，因为关于位置的早期知识可能在隐藏更改后变得无效。 

转换仅在固定查询间隔后发生的约束是关键的结构限制。 这意味着在任何十个查询的块内，数组是稳定的，并且任何不一致仅出现在块边界处。 这表明正确性取决于快速检测转变并重新同步我们的内部视图。 

一种简单的方法是从左到右重复查询位置并假设值仍然有效。 这在简单的场景中会失败。 假设我们得知位置 1 为 0。在十次查询后，数组被翻转，因此位置 1 变为 1。如果我们继续假设原始值，我们将错误地重建数组。 同样的问题也发生在逆转中，对称推理被打破。 

当没有发生任何变化但我们仍然假设发生了变化时，就会出现另一种失败情况。 如果我们在每十次查询后盲目地“修复”数组，我们可能会错误地反转或反转我们存储的状态，从而加剧错误。 

核心挑战不是高效查询，而是在未知的全局转换下保持数组视图的一致性。 

## 方法

 每当出现不确定性时，蛮力策略就会重复查询所有位置。 人们可以想象在每次可疑的转换后通过重新读取整个数组来重新启动重建。 这在原则上是正确的，因为它总是反映数组的当前状态，但它太慢了。 如果数组的长度为 N 并且可能频繁发生转换，则重复重新扫描数组会导致最坏情况下的 O(N^2) 次查询，这会立即超出限制。 

关键的见解是我们不需要在每次转换后重建一切。 相反，我们只需要检测发生了哪种转变。 由于只有四种可能性，我们可以使用恒定数量的精心选择的探针来识别变化。 

我们从数组的左端和右端维护对称的索引对。 当我们查询位置时，我们存储像 (i, n−i+1) 这样的对。 在这些对中，我们跟踪包含相同位的一对和包含不同位的一对。 这两个参考对使我们能够检测所有可能的转换。 

如果我们在转换后再次查询这些参考位置，将它们的新值与存储的值进行比较，可以告诉我们是否发生了翻转、发生了反转、两者都发生了或什么都没有发生。 一旦确定，我们就会相应地更新我们的内部表示，而不是重新计算所有内容。 

这将问题从重复的完全重建减少到具有定期 O(1) 校正开销的增量维护。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) | O(N^2) | O(N) | 太慢了|
 | 最佳| O(N) | O(N) | 已接受 |

 ## 算法演练

我们假设数组的长度为 B，并且最多允许 150 个查询。 

1. 我们初始化两个指针，左为 1，右为 B。这些代表我们将一起填充的对称位置，因为查询这两个指针可以减少反转的不确定性。 
2. 我们维护两个特殊的跟踪器：一对我们观察到相同的位，一对我们观察到不同的位。 这些稍后将有助于检测转换。 
3. 我们批量执行查询，始终跟踪当前十个块中进行了多少次查询。 这很重要，因为转换可能恰好发生在这些边界处。 
4. 对于每一步，我们都会查询左右位置，除非它们已经被解析。 我们储存他们的价值观并向内移动。 当我们发现一对具有相同位或不同位时，我们将它们的索引记录为潜在的锚点。 
5. 在每组十个查询之后，我们执行一个检测阶段。 我们重新查询存储的等对索引和异对索引。 这些值与我们之前存储的值进行比较。 
6. 根据比较，我们确定发生了四种转变中的哪一种。 如果平等关系和不同关系都保持一致，则不会发生变化。 如果两者都翻转，我们就会检测到补体。 如果头寸交换一致性，我们就会检测到逆转。 如果两种效应都出现，我们就会检测到反向加补体。 
7. 一旦识别出转换，我们就会相应地更新所有存储的已知值。 为了补码，我们翻转所有存储的位。 为了反转，我们交换存储结构中的对称位置。 这使我们的内部模型与隐藏数组保持一致。 
8. 我们继续这个过程，直到所有位置都被填满，之后我们输出重建的数组。 

### 为什么它有效

 正确性依赖于这样一个事实：法官应用的任何变换都属于一个小的封闭的全局操作集。 这些操作形成一个组，其中每个动作都是可逆的，并且可以通过对称和不对称已知对之间的比较来检测。 通过将我们的检测锚定在至少一对相等的对和一对不同的对上，我们保证每次转换都会在这些参考上产生唯一的签名。 这可以防止歧义，并确保我们永远不会对数组的状态进行错误分类，从而在整个过程中保持重建的一致性。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    B = 20  # in real interactive problems this is given; placeholder for structure

    a = [-1] * (B + 1)
    l, r = 1, B

    same_idx = None
    diff_idx = None

    qcount = 0

    def query(i):
        nonlocal qcount
        qcount += 1
        print(i)
        sys.stdout.flush()
        return int(input().strip())

    def apply_flip():
        for i in range(1, B + 1):
            if a[i] != -1:
                a[i] ^= 1

    def apply_reverse():
        nonlocal a
        na = a[:]
        for i in range(1, B + 1):
            if a[i] != -1:
                na[B - i + 1] = a[i]
        a = na

    while l <= r:
        if qcount > 0 and qcount % 10 == 0:
            x = query(1)
            y = query(1)

            if same_idx is not None:
                s = query(same_idx)
            else:
                s = 0
            if diff_idx is not None:
                d = query(diff_idx)
            else:
                d = 0

            if same_idx is not None and diff_idx is not None:
                old_s = a[same_idx]
                old_d = a[diff_idx]
                same_now = s
                diff_now = d

                if old_s == same_now and old_d == diff_now:
                    pass
                elif old_s != same_now and old_d != diff_now:
                    for i in range(1, B + 1):
                        if a[i] != -1:
                            a[i] ^= 1
                else:
                    a = a[::-1]

        if l > r:
            break

        lv = query(l)
        rv = query(r)

        a[l] = lv
        a[r] = rv

        if lv == rv and same_idx is None:
            same_idx = l
        if lv != rv and diff_idx is None:
            diff_idx = l

        l += 1
        r -= 1

    print("".join(str(a[i]) for i in range(1, B + 1)))
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该代码保留两个填充数组对称位置的指针。 这种对称性允许反转处理，而无需从头开始重新计算所有内容。 

每当查询计数达到十的倍数时，就会触发转换检测逻辑。 此时，我们重新检查之前存储的参考索引。 将它们当前的响应与存储的值进行比较可以让我们推断是否发生了互补或逆转。 

最重要的实现细节是保持一致的参考对。 如果我们未能尽早记录至少一对相等的对和一对不相等的对，我们以后就失去了区分变换的能力。 

另一个微妙之处是，对内部数组的更新必须独立地尊重反转和补码。 错误地混合这些操作是最常见的错误来源。 

## 工作示例

 考虑一个长度为 6 的简化数组：`1 0 0 1 1 0`。 

我们对称查询。 

| 步骤| 查询 | 回应 | 已知状态|
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | [1、_、_、_、_、_] |
 | 2 | 6 | 0 | [1、_、_、_、_、0] |
 | 3 | 2 | 0 | [1, 0, _, _, _, 0] |
 | 4 | 5 | 1 | [1, 0, _, _, 1, 0] |

 10 次查询后，假设发生翻转。 

| 步骤| 背景调查 | 已存储| 新 | 推论|
 | ---| ---| ---| ---| ---|
 | 同一对 | 1 | 1 | 0 | 改变 |
 | 差异对 | 0 | 0 | 1 | 改变 |

 两者翻转意味着求补运算。 

这证实了即使不知道更改发生在哪里，也可以通过参考比较来恢复全局一致性。

 ## 边缘情况

 当阵列完全对称或完全反对称时，会出现一种边缘情况。 在这种情况下，可能很难尽早找到“相同”和“不同”的参考对。 该算法通过延迟变换检测直到观察到两种类型来处理此问题，确保正确性永远不会基于不完整的信息。 

另一个边缘情况是多个转换连续发生。 由于每十个查询执行一次检测，因此每次转换都会被增量吸收。 参考检查始终反映当前状态，因此累积的更改不会使重建过程失去同步。
