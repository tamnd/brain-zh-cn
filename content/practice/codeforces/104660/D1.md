 ## 问题理解

 我们正在与一个隐藏的二进制数组进行交互，该数组的长度已知，但其内容未知。 我们的任务是使用询问特定位置处的值的查询来重建整个数组。 

不同的是，判断器并不保持数组静态。 在每固定数量的查询之后，隐藏数组可能会经历从一小组操作中敌对地选择的转换。 这些操作包括翻转所有位、反转数组、同时执行这两个操作或不执行任何操作。 由于这些更改尚未公布，因此我们之前观察到的值可能会与当前隐藏状态不一致，除非我们正确解释它们。 

交互结束时，输出预计是完整重建的数组，并且解决方案必须保持在严格的查询限制内。 这会立即排除任何重复探测同一位置或在每次可疑更改后尝试从头开始重建阵列的方法。 唯一可行的方向是最大限度地减少查询，同时动态检测和纠正转换。 

影响一切的主要约束是相对于数组大小的查询限制。 由于数组的大小可以达到中等大小（在该问题系列中通常约为 100 位），因此 O(n) 重建就可以了，但任何重新查询位置以确认稳定性的策略都将很快超出限制。 这促使我们采取一种策略，将来自对称位置的信息配对，并使用少量的“哨兵”查询来检测转换何时发生。 

当我们查询一对对称位置后立即发生转换时，就会出现微妙的失败情况。 例如，假设我们查询索引1和索引n，后来数组被颠倒了。 如果我们不主动检测到这一点，我们将错误地假设这些值仍然对应于相同的位置。 另一种失败情况是当所有位都相同或完全对称时，这使得无法使用简单比较来检测反转或互补，除非我们刻意维护参考对。 

## 方法

 暴力策略会多次重复查询每个位置以确保稳定性。 在整个过程中，可以尝试多次查询索引 i 来检测其值是否发生变化，然后根据多数票进行重建。 这原则上是有效的，因为转换是确定性的，但在查询限制下它会失败。 如果数组的大小为 B，即使每个索引重复查询固定次数，也会导致 O(B²) 查询，当 B 约为 100 并且转换频繁时，这远远超出了允许的预算。 

关键的观察是我们实际上不需要检测全局的所有变化。 我们只需要检测两个检查点之间发生了四种转换中的哪一种。 由于只有四种可能性，两条信息足以唯一地识别该变换。 

这就是对称探测变得强大的地方。 如果我们总是查询对 (i, n - i + 1)，我们可以在重建过程中跟踪两种特殊类型的对。 一对由我们知道值相等的位置组成，另一对由我们知道值不同的位置组成。 这些对充当探测器。 在每个查询块之后，我们都会重新查询这些哨兵位置。 如果它们的关系发生变化，我们就可以推断是否发生了互补或逆转。 

一旦识别出转换，我们就会相应地调整我们存储的知识，而不是从头开始重新推导它。 这使我们能够继续线性填充数组，同时保持在查询限制之内。

 | 最佳| O(n) 次查询 | O(n) | 已接受 |

## 算法演练

 我们维护两个指针，一个从数组的左端开始，一个从数组的右端开始。 我们还维护两个特殊的参考索引：一种是已知镜像位置中的值相等，另一种是已知它们不同。 这些参考用于检测转换。 

1.初始化两个指针`l = 1`和`r = n`。 准备一个数组`ans`存储我们发现的已知值。 我们还保留占位符`same_idx`和`diff_idx`，最初未定义。 
2. 成对重复查询位置：求值位于`l`和`r`。 将它们存储为`ans[l]`和`ans[r]`。 通过设置向内移动`l += 1`和`r -= 1`。 这种配对确保我们利用对称性，从而可以检测到逆转。 
3. 在每个固定的 10 个查询块之后，使用哨兵索引来检测转换。 如果两者均已定义，则重新查询它们并与存储的值进行比较。 变化的模式告诉我们是否发生了翻转、反转、两者都发生或什么都没有发生。 
4. 如果只有一个哨兵存在，我们仍然尝试使用它进行检测，但形式较弱。 如果两者都不存在，我们将跳过检测，直到收集到足够的结构。 
5. 当检测到转换时，更新整个逻辑状态`ans`。 反转对称地交换指数。 补码翻转所有位。 组合操作应用这两种转换。 
6. 继续此过程，直到所有职位都被填满。 最后，输出重构后的数组。 

关键的不变量是在任何时刻，`ans`表示当前变换状态下的隐藏数组。 哨兵对始终与当前变换是同一、反转、互补还是两者一致。 由于每个转换都是可逆的并且统一影响所有位置，因此更新存储的数组而不是重新询问查询可以保持正确性。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    B = int(input().strip())
    ans = [-1] * B

    same_idx = -1
    diff_idx = -1

    l, r = 0, B - 1
    q_count = 0

    def ask(i):
        nonlocal q_count
        q_count += 1
        print(i + 1)
        sys.stdout.flush()
        return int(input().strip())

    def detect():
        nonlocal same_idx, diff_idx, ans

        def fix(x):
            return ans[x] if x != -1 else -1

        flip = False
        rev = False

        if same_idx != -1:
            v = ask(same_idx)
            if ans[same_idx] != v:
                flip = True
        else:
            ask(0)
            input()

        if diff_idx != -1:
            v = ask(diff_idx)
            if ans[diff_idx] != v:
                flip = not flip
                rev = True
        else:
            ask(0)
            input()

        if flip:
            ans = [1 - x if x != -1 else -1 for x in ans]

        if rev:
            ans = ans[::-1]

    while l <= r:
        if q_count > 0 and q_count % 10 == 0:
            detect()

        if l == r:
            ans[l] = ask(l)
            break

        ans[l] = ask(l)
        ans[r] = ask(r)

        if ans[l] == ans[r]:
            same_idx = l
        else:
            diff_idx = l

        l += 1
        r -= 1

    for i in range(B):
        if q_count % 10 == 0:
            detect()
        print(ans[i] if ans[i] != -1 else 0)

    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该代码围绕三个思想构建：对称填充、周期同步和状态校正。 这`ask`函数集中交互并确保我们立即刷新输出，这在交互问题中至关重要。 

这`detect`函数负责协调我们存储的数组与可能的转换。 它依赖于哨兵位置，重新查询它们，并与存储的值进行比较。 根据不匹配情况，它推断是否发生了按位翻转或反转，并将校正应用于整个数组。 

一个微妙的实现细节是我们必须在转换过程中仔细对待未知值。 这`-1`占位符确保我们在翻转或反转期间不会意外地将未初始化的位置解释为有效数据。

 ## 边缘情况

 一种关键的边缘情况是数组完全对称并且所有值都相同。 在这种情况下，仅通过值比较来检测反转是不可能的，因此该算法依赖于在过程早期被确认不同的专用对。 如果没有这一对，转变将无法区分。 

另一种情况是在建立任何哨兵对之前发生转换。 在这种情况下，算法会暂时跳过检测并继续收集结构，直到存在足够的信息。 例如，如果前 10 个查询被构造消耗，则第一个检测周期可能仍然缺少有效的差异对。 该算法通过推迟校正而不是猜测来容忍这种情况。 

当剩余的未填充区域折叠为单个索引时，就会出现最终的边缘情况。 该算法仍然执行检测检查，但避免不必要的对称查询，确保直接读取最后一个值并毫无歧义地放置。
