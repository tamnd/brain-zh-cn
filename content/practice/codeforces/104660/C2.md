 ## 解决方案
 ## 问题理解

 我们有一组时间间隔，每个时间间隔代表必须分配给两个人中的一个的一项活动。 每个活动都有开始时间和结束时间，并且分配必须确保一个人永远不会被分配两个重叠的活动。 仅当一项活动在另一项活动开始之前完成时，同一个人才能兼容两项活动。 

任务是决定是否可以将每个间隔分配给两个人中的一个。 如果可能的话，我们必须输出一个字符串，其中每个字符对应于输入顺序中的一个间隔，为两个人使用两个不同的标签。 如果不可能，我们输出不存在有效的分配。 

输入结构是间隔列表，输出是每个间隔的标签。 关键的限制是，在任何时刻，每个人最多只能处理一个持续的时间间隔。 

从约束的角度来看，间隔的数量足够大，任何二次方法都会失败。 任何尝试检查所有间隔对或重复扫描每次分配冲突的解决方案都会降级为 O(n²)，当 n 约为 10⁵ 时，这太慢了。 这促使我们采用排序和恒定时间分配决策的贪婪策略。 

一些边缘情况很容易出错。 如果所有区间都重叠在一个公共点上，例如[1,4]、[2,5]、[3,6]，则存在三个区间但只有两个人，所以答案一定是不可能的。 一个天真的贪婪者如果不仔细跟踪可用性，可能会错误地覆盖作业或假设一个人可以采取两个重叠的时间间隔。 

当间隔在端点处接触时，会发生另一种微妙的情况。 例如，[1,3]和[3,5]不重叠，可以分配给同一个人。 将结束时间视为包含重叠的粗心实现会错误地拒绝有效的计划。 

## 方法

 蛮力方法会尝试将所有可能的间隔分配给两个人。 每个区间有两个选择，因此有 2ⁿ 分配。 对于每个作业，我们都会验证任何人是否有重叠的间隔，这本身就需要排序或成对检查。 即使进行了有效的检查，搜索空间也会呈指数增长，并且在输入非常小的情况下变得不可行。 

关键的观察结果是约束在时间上是局部的。 在任何时刻，只有当前活动的间隔很重要，而且我们只需要确保一次不超过两个间隔重叠，因为只有两个人可用。 这建议按时间顺序处理间隔并维护哪些人当前有空。 

通过按开始时间对间隔进行排序，我们可以确保在处理间隔时，所有可能发生冲突的较早间隔都已分配。 然后，我们贪婪地将间隔分配给任何可用的人。 如果两者都不可用，我们立即得出结论：分配是不可能的。 

这将问题从指数搜索减少为单遍分配，并记录两个可用时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2ⁿ·n) | O(2ⁿ·n) | O(n) | 太慢了|
 | 最优贪心 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### 步骤

1. 读取所有区间，同时保留其原始索引，因为输出必须遵循输入顺序而不是排序顺序。 
2. 按开始时间对间隔进行排序。 排序确保我们始终首先分配较早的开始间隔，因此我们永远不会做出阻止以前未见过的较早冲突的决定。 
3. 维护两个变量，代表每个人何时获得自由。 最初两者都在时间 0 可用。 
4. 按排序顺序迭代间隔。 对于每个时间间隔，检查第一个人在其开始时间或之前是否有空。 如果是，请将其分配给该人并将他们的下一个空闲时间更新到间隔结束时。 
5. 如果第一个人不在，请检查第二个人。 如果可用，请类似地分配它。 
6. 如果两个人都不空，请立即终止，因为此间隔与两个已分配的间隔重叠，从而无法进行有效分配。 
7. 处理完所有区间后，使用存储的分配按原始索引顺序重建答案字符串。 

### 为什么它有效

 核心不变量是，在扫描的每一步，两个跟踪的可用时间准确地代表所有处理的间隔中分配给每个人的最后一个间隔的结束时间。 因为我们通过增加开始时间进行处理，所以任何可能与当前时间间隔冲突的时间间隔都必须已经反映在这两个状态中。 如果两个人在一个时间间隔开始时都很忙，那么已经有两个重叠的时间间隔覆盖了该时间，因此在不违反约束的情况下无法分配第三个时间间隔。 这使得贪婪决策局部最优且全局安全。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    intervals = []
    for i in range(n):
        s, e = map(int, input().split())
        intervals.append((s, e, i))
    
    intervals.sort()
    
    freeC = 0
    freeJ = 0
    ans = [''] * n
    
    for s, e, i in intervals:
        if freeC <= s:
            ans[i] = 'C'
            freeC = e
        elif freeJ <= s:
            ans[i] = 'J'
            freeJ = e
        else:
            print("IMPOSSIBLE")
            return
    
    print("".join(ans))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该解决方案首先将原始索引附加到每个间隔，以便在按开始时间排序后，我们仍然可以重建所需的输出顺序。 排序至关重要，因为它将问题转化为按时间顺序排列的问题，每个时间间隔做出一次决策。 

变量`freeC`和`freeJ`跟踪每个人最早有空的时间。 处理一个时间间隔时，我们将其分配给第一个在时间间隔开始之前有空的人。 将可用性更新到间隔结束可确保未来的间隔正确遵循此分配。 

当两者都不可用时，立即发生故障的情况至关重要。 延迟此检查或稍后尝试重新分配会破坏正确性，因为排序顺序保证重叠冲突在当前步骤中已完全暴露。

 ## 边缘情况

 一个关键的边缘情况是间隔仅在端点处接触。 对于 [1,2]、[2,3]、[3,4] 等输入，算法必须将它们视为不重叠。 由于我们使用`<=`为了可用性，允许正好从前一个结束开始的间隔，并且同一个人可以处理所有间隔。 

另一种边缘情况是所有间隔在一个点重叠。 例如，[1,10]、[2,9]、[3,8]。 将前两个间隔分配给不同的人后，第三个间隔发现两个人在时间 3 都很忙，立即触发不可能。 该算法正确地检测到了这一点，因为`freeC`和`freeJ`超过开始时间。 

最后一个微妙的情况是未排序的输入，其中间隔以任意顺序给出。 排序是必不可少的，因为如果没有它，可用性跟踪就失去了意义，并且贪婪分配变得依赖于顺序，即使存在有效的调度也会产生错误的结果。
