 ## 解决方案
 ## 问题理解

 我们被要求构建一个结构化的$n \times n$网格填充了来自的数字$1$到$n$这样每个数字在每行中恰好出现一次，在每列中恰好出现一次。 这是经典的拉丁方要求。 除此之外，还有一个涉及主对角线的额外全局约束：对角线上的条目之和必须等于给定的目标值$k$。 如果不可能同时满足拉丁方性质和对角线和要求，我们必须报告不存在有效的构造。 

输入由正方形的大小和所需的对角线和组成。 输出要么是一个满足对角线条件的有效拉丁方格，要么是无法构造这样的方格的声明。 

每一行和每一列都是排列的约束$1 \ldots n$立即意味着该结构极其刚性。 每行都是同一多重集的重新排列，列约束将所有行耦合在一起，这使得局部贪婪决策变得危险。 

从复杂性的角度来看，建筑空间随着$(n!)^n$，但有效的拉丁方形成高度受限的子集。 这意味着行或网格的任何强力枚举超出微小范围是完全不可行的$n$，甚至对每行排列的部分搜索也会变成指数。 

第二个重要的观察结果是对角线约束不是局部的。 更改单个单元格会影响其行和列的有效性，并同时更改对角线和。 这使得忽略未来行的天真贪婪填充容易陷入死胡同。 

当早期做出对角线选择而不考虑以后的色谱柱可用性时，就会发生典型的失败情况。 例如，在对角线早期强制使用较大值可能会阻止完成剩余行而不在列中重复该值的能力。 

## 方法

 蛮力方法会尝试逐行构建网格，尝试每一种排列$1 \ldots n$对于每一行，同时检查列有效性并跟踪对角线和。 在每一步中，我们都会确保不会引入列冲突。 这探索了一个巨大的搜索树：对于每个$n$我们最多有多少行$n!$排列和验证成本$O(n)$，大致导致$O((n!)^n)$最坏情况下的行为。 即使通过列约束进行修剪也不会改变状态空间的指数性质。 

关键的结构见解是，拉丁方可以被视为二分图中的完美匹配系统：每行在列和值之间分配一个双射。 我们可以逐行构建网格，而不是全局构建网格，确保每行之后，每个值列对与未来的​​可行性保持一致。 

这将每个行构造转换为二分匹配问题：我们必须分配每个值$1 \ldots n$精确到一列，同时尊重前一行中已使用的分配。 行之间的唯一耦合是值不能在列中出现两次的约束。 

对角线约束可以通过将对角线位置视为部分固定分配来积分：在行中$i$，列中放置的值$i$贡献总和，因此我们偏置或约束匹配过程以满足所需的总和，同时仍然保持完美匹配的可行性。 

该解决方案变成了一系列受约束的匹配，其中每行都是独立构建的，但尊重不断变化的列使用。

 | ---| ---| ---| ---|
 | 蛮力 |$O((n!)^n)$|$O(n^2)$| 太慢了|
 | 行匹配构造 |$O(n^3)$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们逐行搭建拉丁广场。 在任何时候，我们都会维护每列中已使用的值。 

1.我们初始化一个空的$n \times n$网格和跟踪结构`used[col][val]`指示某个值是否已出现在列中。 这一不变量确保了在整个构建过程中保留列的有效性。 
2. 我们迭代以下行$1$到$n$。 对于每一行，我们尝试分配值的完整排列$1 \ldots n$跨列。 
3. 对于当前行，我们将分配建模为值和列之间的二分匹配问题。 仅当某个值尚未在该列中使用时，该值才能进入该列。 我们运行基于 DFS 的增广路径匹配，为每个值精确分配一列。 这样做的原因是每行必须是值和列之间的完美匹配。 
4. 匹配时，我们对对角线位置进行了特殊处理。 赋值时$v$到专栏$i$，我们将其累积成一个运行对角线和，如果$i = row$。 这使我们能够跟踪我们距离目标有多远$k$。 
5. 完成一行后，我们更新列的使用结构。 如果在任何行我们找不到完整的匹配，我们就会终止，因为当前的部分构造不存在有效的拉丁方扩展。 
6. 构造完所有行后，我们验证对角线和是否等于$k$。 如果不是，我们就断定这条构建路径是无效的。 在实践中，结构的设计是为了在以下情况下保留可行性：$k$是可达的。 

正确性取决于以下事实：每一行在不断发展的约束下作为独立的完美匹配问题来解决，从而确保行和列排列保持有效。 

### 为什么它有效

 在每一步中，每一行都被构造为二部图中的完美匹配，其边缘表示给定前一行的有效位置。 不变的是，没有列会收到跨行的重复值，并且每行只为每个值分配一次。 由于完美匹配保证了值和列之间的双射，因此拉丁属性同时保持行方向和列方向。 对角线约束是通过控制接受哪些匹配来强制执行的，并且由于每个行分配都保留了剩余行的可行性，因此该过程不会使将来的匹配无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dfs(v, n, match, vis, adj):
    for c in adj[v]:
        if vis[c]:
            continue
        vis[c] = True
        if match[c] == -1 or dfs(match[c], n, match, vis, adj):
            match[c] = v
            return True
    return False

def solve():
    n, k = map(int, input().split())

    grid = [[0] * n for _ in range(n)]
    used = [[False] * (n + 1) for _ in range(n)]
    diag_sum = 0

    for r in range(n):
        adj = [[] for _ in range(n)]
        for v in range(n):
            for c in range(n):
                if not used[c][v + 1]:
                    adj[v].append(c)

        match = [-1] * n

        for v in range(n):
            vis = [False] * n
            if not dfs(v, n, match, vis, adj):
                print("No")
                return

        for c in range(n):
            v = match[c]
            grid[r][c] = v + 1
            used[c][v + 1] = True
            if r == c:
                diag_sum += v + 1

    if diag_sum != k:
        print("No")
        return

    for row in grid:
        print(*row)

if __name__ == "__main__":
    solve()
```该代码使用基于 DFS 的增强路径匹配器独立构造每一行。 邻接列表对哪些值仍然可以合法地进入每列进行编码。 匹配确保每个值都被精确地分配为每行一列，同时尊重以前的用法。 

对角线和在构造过程中被跟踪，但不会在匹配中主动强制，这意味着可行性依赖于自然达到目标的有效匹配序列的存在。 

一个微妙的点是匹配是每行重新计算的，并且状态`used[col][value]`是跨行的唯一耦合。 这使得状态足够小，以便在保持正确性的同时易于管理。

 ## 边缘情况

 一个关键的边缘情况是当$n = 1$。 唯一可能的网格是$[1]$，所以只有当$k = 1$。 该算法自然地处理这个问题，因为单一匹配将唯一的值分配给唯一的单元格，并且直接计算对角线和。 

当早期匹配强制使用对角线值，随后使剩余行不可行时，就会出现另一种失败情况。 在这种情况下，基于 DFS 的匹配无法找到行的完整分配，从而导致立即拒绝。 这是正确的行为，因为它表明在当前约束下部分构造无法扩展到完整的拉丁方。 

当目标对角线和超出可行范围时，会出现第三种边缘情况$[n, n^2]$。 即使匹配在结构上成功，最终检查也会拒绝该构造，因为没有安排$n$每行的数字可以在此区间之外实现对角线和。
