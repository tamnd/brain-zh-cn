 ## 解决方案
 ## 问题理解

 该任务处理一串十进制数字，其中每个数字描述了我们在概念嵌套结构中的“深度”。 想象一下，我们不只是打印数字，而是用括号将它们括起来，以便当前活动的左括号数量与每个位置的数字值匹配。 

给你一个字符序列，每个字符来自`'0'`到`'9'`。 您必须生成另一个包含原始数字但带有附加数字的字符串`'('`和`')'`插入，以便当您从左到右扫描时，每个数字之前不匹配的左括号的数量等于该数字的值。 

因此，输出不是值的转换，而是结构编码：括号定义必须在每个位置精确跟踪数字流的动态深度。 

输入大小与字符串长度成线性关系，因此唯一可行的解​​决方案是线性或接近线性的。 如果仔细实施的话，任何从头开始重新计算每个字符嵌套的尝试在渐近方面都是可以接受的，但由于不可变性和重复串联，循环内重复的字符串重建将降级为二次行为。 

当数字急剧减少时，会出现微妙的边缘情况。 例如，考虑这样的输入`321`。 一种幼稚的方法可能只在需要时打开括号，但在打印下一个数字之前忘记关闭足够的层，从而产生无效的中间嵌套，例如在某个时刻有太多活动打开。 另一种常见的故障发生在前导零上，例如`0000`。 正确的输出必须完全不包含括号，但粗心的实现通常仍然会发出空对或不匹配的闭包。 

## 方法

 幼稚的思考问题的方式是独立对待每个立场。 对于每个数字，可以尝试通过再次扫描前缀并计算嵌套“应该”的内容来重建需要多少个括号，然后在打印数字之前发出所需的打开或关闭数量。 这在逻辑上是有效的，因为要求每个索引的本地一致性，但它的成本很高，因为每个步骤都可能重新扫描前缀或重复调整模拟堆栈。 在最坏的情况下，这会导致二次行为，因为对于每个角色，我们可以通过遍历先前的结构来重新计算深度。 

关键的观察是所需的结构完全由连续数字之间的差异决定。 我们永远不需要从头开始重新计算绝对深度。 相反，我们在从左到右扫描时保持当前深度。 当下一个数字大于当前深度时，我们只需添加左括号即可​​。 当它更小时，我们关闭括号。 如果相等，我们什么也不做。 这将全局约束转换为相邻字符之间的局部转换规则。 

这是有效的，因为括号结构在分段中是单调的：一旦我们增加深度，我们就会保持在该水平，直到减少强制关闭。 因此，整个结构简化为跟踪单个整数并在每一步发出最小的调整。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个位置的强力模拟 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 贪婪深度追踪| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时维护一个变量`depth`代表当前有多少个左括号处于活动状态。 

1. 初始化`depth = 0`和一个空的输出缓冲区。 
2. 对于每个角色`c`在字符串中，将其转换为整数`target`。 
3.如果`target > depth`, 附加`target - depth`左括号并增加`depth`到`target`。 这确保我们在放置数字之前建立足够的嵌套。 
4. 如果`target < depth`, 附加`depth - target`右括号并减少`depth`到`target`。 这可以安全地减少嵌套，以便当前数字与所需的深度相匹配。 
5. 附加数字本身。 
6. 处理完所有数字后，如果`depth > 0`，附加剩余的右括号以完全平衡结构。 

基本思想是，我们永远不会破坏处理每个数字后，左括号的数量等于该数字的不变式。 

### 为什么它有效

 在每个位置，算法强制活动嵌套深度等于正在写入的数字。 由于我们仅通过显式左括号或右括号来调整深度，并且每次调整都与连续目标之间的差异完全匹配，因此不会引入不必要的结构。 最后的清理步骤确保全局平衡。 由于在两个相邻所需状态之间的每个转换都是最佳处理的，因此没有替代安排可以减少括号的数量，同时仍然满足每个位置的深度约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    res = []
    depth = 0

    for ch in s:
        target = ord(ch) - ord('0')

        while depth < target:
            res.append('(')
            depth += 1

        while depth > target:
            res.append(')')
            depth -= 1

        res.append(ch)

    while depth > 0:
        res.append(')')
        depth -= 1

    print(''.join(res))

if __name__ == "__main__":
    solve()
```实施直接遵循深度跟踪策略。 两个 while 循环通过显式匹配嵌套差异来处理连续数字之间的转换。 使用列表进行输出累积可以避免重复字符串连接带来的二次行为。 最后一个循环保证所有打开的括号都正确关闭，当最后一个数字大于零时这是必要的。

 ## 边缘情况

 对于像这样的输入`0`，算法永远不会进入任一循环，并且输出仍然是纯数字流。 这证实了零深度被视为中性状态。 

对于递减序列，例如`210`，算法首先增加深度来匹配`2`，然后在移动到时立即关闭一个级别`1`，然后在达到时关闭所有剩余级别`0`。 这表明闭包纯粹是由相邻数字之间的差异驱动的，确保在转换之间不会存在剩余的嵌套。
