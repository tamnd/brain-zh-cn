 ## 问题理解

 我们正在开发一个网格，其中鲍勃和卡罗尔两个人从同一个单元出发，必须使用曼哈顿距离的最短路径到达各自的目的地。 最短路径意味着每一步都会将曼哈顿到目标的距离恰好减少一倍，因此在某些方向组合上的运动总是单调的。 

两名旅行者都可以共享部分旅程，这意味着他们可以站在同一个牢房里进行一些步行。 目标是最大限度地延长他们在相同单元上停留的时间，同时仍然使用最短的路线到达各自的目的地。 

每个测试都会在网格上给出三个点：共同起点、鲍勃的目的地和卡罗尔的目的地。 输出是可以同时属于两条最短路径的最大单元数。 

约束最多为 10^4 个测试用例，坐标最多为 10^8 个。 这立即排除了任何路径模拟。 每个测试用例的每个答案必须在恒定时间内计算，因为即使每个测试的 O(n) 也会太慢并且路径枚举是不可能的。 

一个常见的错误是假设两条路径始终可以重叠到其目的地之间的路段的中点。 当几何形状迫使早期发散时，例如当鲍勃的目标所在的方向从一开始就与卡罗尔的最佳方向发生冲突时，这种方法就会失败。 

## 方法

 一个蛮力的想法是尝试枚举从开始到 Bob 和 Carol 的所有最短路径，然后计算任何对的最长公共前缀。 网格中最短路径的数量随距离组合增长，大致按曼哈顿距离的二项式系数的顺序增长。 即使对于中等距离，这也是不可行的，我们还需要比较路径对，使该方法呈指数级增长。 

关键的观察结果是，曼哈顿几何中的最短路径是单调的：每一步，您只能独立地在 x 或 y 方向上靠近。 这将问题转化为对几何区域而不是离散路径的推理。 

我们不考虑单独的路径，而是考虑既属于从 A 到 B 的最短路径又属于从 A 到 C 的最短路径的所有单元的集合。当且仅当单元不将曼哈顿距离增加到超过最小可能距离时，单元才可用于到目标的最短路径。 这将问题转化为理解网格中重叠的单调矩形。 

只要单元格保持与两个目的地的最短路径约束兼容，当两个旅行者一起移动时就会发生最佳重叠。 一旦一个方向变得不相容，路径就必须分叉。 

这导致了基于点之间的曼哈顿距离的直接几何公式。

 ## 算法演练

 1. 计算所有相关点对之间的曼哈顿距离：从 A 到 B、A 到 C、B 到 C。这些距离充分描述了网格中的最短路径几何形状。 
2. 观察到，如果两个旅行者尽可能长时间地共享一条路径，他们实际上会从 A 一起移动，直到一个点，如果继续一起移动将迫使他们中的至少一个人采取非最短绕道。 这种差异完全取决于 B 和 C 相对于 A 的距离有多远。 
3. 最大共享路段对应于从A步行到B和C的最短路径重叠的区域。 这种重叠取决于它们的最短路径走廊相交的程度。 
4. 最终结果简化为一半数量：$$d(A,B) + d(A,C) - d(B,C)$$加 1，用整数除法处理网格单元计数。 该表达式测量在分离变得不可避免之前可以对齐多少路径。 
5. 返回每个测试用例的计算值。 

关键的推理步骤是，重叠是通过从 B 和 C 必须单独从 A 覆盖的组合距离中减去 B 和 C 之间的直接间隔来确定的。剩下的正是它们单调路线的共享部分。 

为什么它有效：曼哈顿几何中的最短路径表现得像单调链。 任何共享段本身必须是到两个目的地的最短路径前缀。 完全共享的唯一障碍是两个目标方向之间的几何分歧，并且这种分歧完全由距离之间的三角形不等式差距捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def manhattan(x1, y1, x2, y2):
    return abs(x1 - x2) + abs(y1 - y2)

def solve():
    t = int(input())
    for _ in range(t):
        ax, ay = map(int, input().split())
        bx, by = map(int, input().split())
        cx, cy = map(int, input().split())

        d_ab = manhattan(ax, ay, bx, by)
        d_ac = manhattan(ax, ay, cx, cy)
        d_bc = manhattan(bx, by, cx, cy)

        # maximum overlap of shortest paths
        ans = (d_ab + d_ac - d_bc) // 2 + 1
        print(ans)

if __name__ == "__main__":
    solve()
```该代码计算成对曼哈顿距离并直接应用导出的公式。 整数除法是安全的，因为在此几何设置中表达式的计算结果始终为整数。 决赛`+1`考虑对共享路径段中的单元而不是边缘进行计数。 

一个常见的实施陷阱是忘记答案计算的是单元格，而不是步骤。 这就是为什么不直接返回距离； 它们必须转换为共享顶点数。 

## 工作示例

 考虑第一个样本：

 A = (3,1), B = (1,3), C = (6,4)

 我们计算：

 | 数量 | 价值|
 | --- | --- |
 | d(A,B) | 4 |
 | d(A,C)| 6 |
 | d(B,C) | 6 |

 应用该公式得出：

 (4 + 6 - 6) // 2 + 1 = 3

 这符合这样的想法：两个旅行者可以在方向分歧之前一起移动一小段前缀。 

现在考虑第二种配置：

 A = (5,2)、B = (2,2)、C = (7,2)

 这里一切都位于同一条水平线上。 

| 数量 | 价值|
 | --- | --- |
 | d(A,B) | 3 |
 | d(A,C)| 2 |
 | d(B,C) | 5 |

 结果：

 (3 + 2 - 5) // 2 + 1 = 1

 他们只共享起始单元格，然后沿线向相反方向移动。 

这些示例表明，仅当 B 和 C 位于与 A 兼容的方向锥中时，才会发生完全重叠。

 ## 边缘情况

 当 B 和 C 位于穿过 A 的同一条直线上时，最佳共享路径就是它们从 A 开始的方向的重叠。该公式正确折叠，因为 d(B,C) 等于它们在相反方向上到 A 的距离之和，只留下共享的起始线段。 

当 B 和 C 位于与 A 垂直的方向时，任何朝向其中一个的移动都会立即增加与另一个的距离。 该表达式将共享段简化为一个单元格，仅表示起点。 

当所有三个点靠得很近时，例如坐标相差一个单位，曼哈顿距离可确保公式永远不会产生无效的负重叠，并且共享路径仅限于 A 的直接邻域。
