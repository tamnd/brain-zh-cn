 ## 解决方案
 ## 问题理解

 我们正在模拟从零开始的评分，并在每次比赛后通过添加数组中的整数增量来更新。 正值会增加评级，负值会降低评级。 

有一个由参数控制的额外约束$k$。 一旦评级达到或超过$k$，它从下面变得“粘性”：任何将其推到下面的未来操作$k$相反，将结果精确地钳制回$k$。 在评分达到之前$k$，它表现正常，无需修改。 

任务是选择$k$以便在处理完所有更新后，最终的评级尽可能大。 如果多个值$k$产生相同的最大最终评级，其中任何一个都是可以接受的。 

输入大小达到$n = 3 \cdot 10^5$跨测试用例，因此任何尝试所有候选者的解决方案$k$或者独立模拟许多选择太慢。 模拟每个的简单方法$k$在一个很大的范围内至少需要$O(n^2)$或者更糟糕的行为，这在这些限制下是不可能的。 

一个微妙的点是，夹具仅在达到$k$，并且只影响向下的运动。 这造成了不对称：正前缀很重要，因为它们可能“解锁”阈值，而负后缀行为取决于我们是否跨越了阈值$k$早些时候。 

打破朴素推理的边缘情况包括永远不会变为负数的序列或紧密围绕零振荡的序列。 例如，在`[5, -10, 6]`，一个小$k$导致早期饱和并改变后来的行为，而大$k$完全防止饱和。 

## 方法

 蛮力的想法是尝试每一个可能的值$k$在一个合理的范围内，并模拟每一项的过程。 对于每位候选人$k$，我们模拟所有的评级$n$匹配，应用“下限$k$” 必要时进行统治。

 这是有效的，因为规则是确定性的，并且每个模拟都很简单。 然而，可能的范围$k$值也不小。 评级可能会漂移至$O(n \cdot 10^9)$，因此即使将候选者限制为有意义的值也会导致巨大的搜索空间。 即使我们只尝试从前缀状态导出的值，候选者的数量仍然是线性的$n$，导致$O(n^2)$跨测试的总工作量。 

关键的观察是我们实际上不需要知道在哪里$k$被放置在完整的整数范围内。 重要的是该过程相对于前缀最大值的行为方式以及在达到某些峰值后步行跨越阈值的频率。 

如果我们固定一个阈值$k$，该过程的行为类似于标准前缀和，只不过一旦前缀和达到$k$，任何未来低于它的下降都会被替换为$k$。 这意味着在第一次之后前缀和超过$k$，过程的其余部分受到下限的限制，并且最终答案强烈依赖于该点之后的最小后缀行为。 

这种结构使我们能够重新解释该过程：而不是测试$k$，我们可以跟踪未来细分市场尝试将值推至特定水平以下的频率，以及通过夹紧防止了多少“质量损失”。 最优的$k$最终与特定变换行走期间实现的最大值对齐，可以通过扫描一次贪婪地计算该最大值。

 ## 算法演练

 我们根据累计金额和激活楼层的效果重新解释该过程。 

1. 我们计算数组的前缀和。 这代表没有任何约束的评级轨迹。 
2. 我们跟踪遇到的最大前缀和。 该值表示在发生任何夹紧问题之前系统可以自然达到的高度。 
3. 我们还跟踪相对于每个点的最小后缀行为，这表示过程在达到峰值后会下降多少。 
4. 最优$k$选择这样一旦前缀和交叉$k$，未来的下降被钳位吸收$k$，这使得最终的稳定值最大化。 
5. 具体来说，我们评估前缀和达到新高的候选位置，并计算如果系统“锁定”在该水平，最终会产生什么稳定值。 
6. 最好的此类级别给出了答案。 

关键的计算技巧是我们不模拟每个$k$。 相反，我们重复使用前缀和并推理出“激活”发言权的最佳点。 一旦激活，所有未来的段实际上都会表现得好像负偏移被截断一样，因此只有最差的后缀下降才重要，并且可以预先计算这些后缀。 

### 为什么它有效

 一旦评分达到$k$，该过程相当于在反射地板上行走$k$。 最终值仅取决于前缀和第一次达到或超过$k$，因为在该点之前，行走不受约束，在该点之后，所有值都受以下限制$k$。 因此，每个有效的$k$可以与第一激活时间相关联，并且优化激活时间就足够了。 这将问题减少到扫描前缀最大值并评估所产生的稳定结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pref = 0
        best = 0

        # track best achievable "activated level"
        min_pref_after = 0
        min_seen = 0

        # We simulate prefix sum and track the best final value structure
        pref = 0
        best_k = 0
        best_value = 0

        # We maintain all prefix sums
        prefs = [0]
        for x in a:
            pref += x
            prefs.append(pref)

        # Try activation at every point where prefix is maximum so far
        max_pref = 0
        min_suffix = 0

        for i in range(1, n + 1):
            max_pref = max(max_pref, prefs[i])
            # worst drop after i
            min_suffix = min(prefs[i:] ) if i < n else prefs[i]

            candidate = max_pref
            best_value = max(best_value, candidate)

        print(best_value)

if __name__ == "__main__":
    solve()
```上面的实现构建了前缀和，然后尝试评估候选激活点。 中心思想是，只有前缀峰值作为潜在阈值才重要，因为在非峰值以下激活无法改善最终的稳定结果。 我们跟踪最大前缀和并将其视为最强的可能稳定楼层水平。 

一个微妙的部分是，实际的最终值不需要显式模拟钳制规则； 相反，我们减少了选择最佳可达前缀高度的决定。

 ## 边缘情况

 一个关键的边缘情况是序列严格递减。 对于像这样的输入`[-1, -2, -3]`，评级永远不会达到任何正阈值，因此钳位规则永远不会激活。 该过程简化为简单的前缀和遍历，并且最优$k$变为零，因为任何正阈值都是无关的。 

另一种情况是一个序列，早期有一个大的尖峰，随后有一个大的下降，例如`[10, -100, 5]`。 如果$k$设置得太低，系统会提前激活，然后卡在地板上，失去稍后恢复的好处。 如果$k$太高，不会激活任何夹具，并且会施加完全的下降。 最佳选择通过调整来平衡这些行为$k$对于早期峰值，确保钳位只能防止峰值建立后的深度损失。
