 ## 解决方案
 ## 问题理解

 该游戏是在 2D 网格上简化的魁地奇模拟。 网格的每个单元格可以包含一名球员、一个球门、鬼飞球、游走球，或者是空的。 玩家属于红队或蓝队，可以在四个基本方向上移动。 鬼飞球可以由玩家携带和投掷。 当球员将鬼飞球击中对手球门时即可得分。 如果一名球员在自己的球门上得分，则对手得分。 游走球会消除与其共享一个单元的任何玩家，并且被淘汰的玩家会在该单元中掉落鬼飞球。 游戏由一系列动作组成，每个动作对应于一个移动或与球交互的实体。 

输入由网格尺寸和初始布局组成，后跟操作列表。 输出包括按时间顺序排列的所有评分和淘汰事件，以及最后的最终得分。 每个事件都标有触发该事件的操作的时间步长。 

这些约束使得直接模拟变得可行：网格最多有 99x99 个单元，每队最多 10 名玩家，步数上限为 10,000。 因为每个动作只影响直接单元格，也可能影响鬼飞球，所以我们可以在每个动作的 O(1) 时间内更新游戏状态，从而以足够快的速度进行 O(T) 操作的完整模拟。 

当携带鬼飞球的玩家被游走球淘汰时，就会出现一种微妙的边缘情况。 鬼飞球必须与游走球和被淘汰的球员一起留在牢房中。 另一个微妙之处是，如果多名玩家移动到游走球上，则可能会同时发生多次淘汰。 这些淘汰必须按玩家 ID 的排序顺序报告。 

## 方法

 一种简单的方法是字面模拟：维护实体网格，跟踪鬼飞球和游走球的位置，并通过更新位置和检查碰撞或目标来处理每个动作。 每个动作都是独立处理的，每次移动或投掷后，我们都会检查鬼飞球是否在球门上或游走球是否与球员重叠。 这种暴力方法的正确性来自于它对游戏规则的严格遵守。 

最坏情况下的操作计数约为 10,000 步乘以每步的检查次数。 由于网格最多为 99x99 并且玩家数量很少，因此每次检查（与游走球或球门碰撞）需要 O(1)。 这种朴素的模拟实际上是这个问题的最佳选择，因为约束很低，并且没有重复的子问题可供利用。 因此，关键的见解是直接模拟就足够了。 我们只需要确保更新以正确的顺序发生，并且多个同时发生的事件按指定排序。 

主要的微妙之处是当携带鬼飞球的玩家被淘汰时正确处理鬼飞球的状态，并确保事件按时间顺序排列。 在给定时间步对被淘汰的玩家进行排序是除了直接模拟之外唯一不明显的操作。

 ## 算法演练

1. 读取网格尺寸 N 和 M。将网格初始化为二维单元数组，每个单元包含一个实体列表。 初始化变量以跟踪所有玩家、鬼飞球和游走球（如果存在）的位置。 
2. 解析初始网格。 对于每个单元格，记录其中的内容。 如果它包含一名球员，则将他们的位置存储在以球员 ID 为键的字典中。 如果它包含鬼飞球或游走球，请存储它们的位置。 
3. 初始化红队和蓝队的计分器。 设置一个列表来存储事件。 
4. 按顺序处理T 个动作中的每一个。 对于每个操作，首先确定哪个实体正在执行操作以及操作是什么。 
5. 如果动作是移动（U、D、L、R），则更新实体的坐标并更新网格。 移动后，检查是否有玩家与游走球占据同一格子。 如果是，则将这些玩家标记为已淘汰并生成淘汰事件。 如果携带鬼飞球的玩家被淘汰，请将鬼飞球留在当前单元格中。 
6. 如果动作是接住鬼飞球，则更新玩家的状态以表明他们正在携带鬼飞球，并将鬼飞球从单元格中移走。 
7. 如果动作是投掷鬼飞球，则将其放置在玩家当前的单元格中，并将玩家标记为不再携带它。 
8. 每次操作后，检查鬼飞球是否位于目标单元格上。 如果是在对手的球门上，则将分数奖励给执行球员的球队。 如果是自己的球，则将分数判给对手。 生成目标事件并将鬼飞球重置到中心单元格。 
9. 处理完所有动作后，按顺序打印所有事件，然后以指定格式打印最终得分。 

在整个模拟过程中保持的不变性是网格和所有实体位置始终准确地反映当前状态。 每次动作后都会立即检测到碰撞和得分，并且处理顺序可确保通过对玩家 ID 进行排序来正确报告同时消除的情况。
