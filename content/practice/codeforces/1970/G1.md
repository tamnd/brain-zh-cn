 ## 解决方案
 ## 问题理解

 输入描述了由形成树的走廊连接的单元集合。 每个单元格都是一个节点，每个走廊都是一条无向边。 因为正好有$m = n - 1$边和图是相连的，结构是树。 

任务是将树分成恰好两个连接的节点组。 每个组必须仅使用该组内的节点保持内部连接。 拆分后，我们可以在两组之间添加一条走廊，并且该走廊有成本$c$。 此外，每个组贡献的成本等于其规模的平方。 如果两个组都有大小$x$和$y$，总成本变为：$$x^2 + y^2 + c$$因为总是需要一条新走廊。 

唯一真正的自由是选择如何通过删除一条现有边将树切割成两个连接的组件。 一旦删除该边，树就会分裂成两个子树。 

约束条件意味着$n$取决于$10^5$每个测试用例总计$n$还高达$10^5$，所以一个$O(n)$或者$O(n \log n)$需要每个测试用例解决方案。 任何重复尝试所有分区或重新计算子树属性的操作都会太慢。 

一个微妙的点是，每个有效分区都恰好对应于删除一条边。 无需考虑节点的任意子集； 连接性迫使分区成为子树。 

另一种边缘情况是树只有两个节点。 然后删除唯一的边会产生两个单例组件，这是唯一有效的分割。 任何方法都必须干净地处理这个问题。 

## 方法

 暴力方法会尝试删除每个边缘，然后重新计算两个结果组件的大小。 对于每个边缘去除，我们将运行 DFS 或 BFS 来计算组件大小并评估成本。 每次这样的遍历都是$O(n)$，并且有$O(n)$边缘，给予$O(n^2)$每个测试用例对于$10^5$节点。 

关键的观察是，删除树中的一条边总是会将其分成两棵子树，并且如果我们对树进行根操作，一侧的大小恰好等于以一个端点为根的子树的大小。 因此，我们不再重复重新计算组件大小，而是使用 DFS 一次计算所有子树大小。 

一旦子树大小已知，每条边都对应于产生大小分量的切割$sz$和$n - sz$。 该削减的成本变为：$$sz^2 + (n - sz)^2 + c$$我们简单地评估每个边的表达式并取最小值。 

这将问题简化为单个 DFS 加上边缘线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | DFS + 边缘评估 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将树以任意节点（通常为节点 1）作为根，并构建邻接表。 这修复了子树定义的方向。 
2. 运行 DFS 来计算每个子树的大小。 对于一个节点$u$，子树大小为：$$sz[u] = 1 + \sum sz[v]$$超过儿童$v$。 这准确地捕获了有根树中每个节点下面有多少个节点。 
3. 在进行 DFS 时或在第二遍中，考虑每条边$(u, v)$在哪里$v$是一个孩子$u$。 切割这条边将子树分开$v$从树的其余部分。 
4. 对于每个这样的边，计算两个分量大小：$sz[v]$和$n - sz[v]$。 评价：$$cost = sz[v]^2 + (n - sz[v])^2 + c$$5. 跟踪所有边缘上的最小值。 
6. 输出测试用例的最小值。 

### 为什么它有效

 将树分成两个连接组件的每个有效分区都是通过删除一条边来唯一定义的。 对树进行生根可确保每条边恰好对应一个子树大小。 DFS 保证每个子树大小只计算一次，因此每个分区只计算一次。 由于成本函数仅取决于组件尺寸并且添加的边缘成本是恒定的，因此最小化所有边缘涵盖了所有可能的有效解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m, c = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
        edges.append((u, v))

    parent = [0] * (n + 1)
    sz = [0] * (n + 1)
    order = []

    stack = [1]
    parent[1] = -1

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    for u in reversed(order):
        sz[u] = 1
        for v in g[u]:
            if v == parent[u]:
                continue
            sz[u] += sz[v]

    ans = float('inf')

    for u, v in edges:
        if parent[u] == v:
            s = sz[u]
        else:
            s = sz[v]

        ans = min(ans, s * s + (n - s) * (n - s) + c)

    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该解决方案首先构建树，然后使用迭代 DFS 构建父数组以避免递归深度问题。 子树大小按反向 DFS 顺序计算，因此子树先于父树处理。 

通过确定哪个端点是有根树中的子端点，每条边都被精确评估一次。 该端点直接定义子树大小。 

一个常见的陷阱是在不增加递归限制的情况下使用递归 DFS，这可能会在长链上失败。 另一个是忘记只有子端子树大小是有效的，而不是在不检查方向的情况下任意端点减法。

 ## 边缘情况

 一个关键的边缘情况是当树是一条简单路径时。 在这种情况下，每个边缘都会产生不同的分割尺寸，并且最佳切割往往位于中心附近。 基于 DFS 的子树计算仍然分配正确的大小，因为每个节点在根方向上恰好有一个子节点。 

另一种情况是星形树。 在中心生根会产生许多子树大小为 1 的子树。每次切割都会产生相同的分裂结构$(1, n-1)$，并且该算法可以正确地重复评估相同的成本，没有任何问题。 

为了$n=2$，DFS 分配一个子树大小为 1，并且唯一的边产生唯一的有效分区。 该公式仍然直接适用并产生正确的最小值。
