 ## 解决方案
 ## 问题理解

 我们得到一个代表监狱的无向图，其中顶点是牢房，边是现有的走廊。 我们必须将顶点划分为两组，以便当我们允许使用现有走廊并选择性地构建新走廊时，每组都会产生一个连通的子图。 然而，这两个组团必须通过一条走廊相互连接，并且该走廊也是最终结构的一部分。 

每个组称为一个复合体，其成本仅取决于其大小：如果一个复合体具有大小$k$，它贡献$k^2$到总成本。 此外，每条新建走廊的成本$c$，我们可能会在组内建造额外的走廊以确保连通性。 

因此，任务是选择将顶点划分为两个连接的组件，确保每一侧使用现有的和可选添加的边进行内部连接，并使用一条桥边连接两侧。 目标是最小化平方尺寸之和加上添加边的成本。 

关键的结构是，初始图可能已经有多个连通分量，并且允许我们自由添加边，但每条添加的边都有成本$c$，因此我们仅在需要连接所选分组时才添加边。 

这些限制意味着需要高度优化的解决方案。 总共有$n \le 10^5$和总计$m \le 5 \cdot 10^5$，任何尝试所有分区或模拟每个分区的连接的方法都是不可能的。 即使每个组件或每次切割的任何二次方都会失败。 该解决方案必须将问题简化为图压缩步骤，然后对组件进行近线性或线性时间计算。 

一个微妙的问题是，由于增加了边缘，连接变得灵活。 如果一个组是由多个原始连接组件组成的，我们必须付费才能连接它们，因此成本取决于每侧内部合并了多少个组件。 

另一种边缘情况是当图已经以某种方式断开连接时，使得有效的分割变得不可能。 例如，如果图有两个以上的连接组件，并且我们被迫使用单个桥的两个复合体，则某些配置在没有额外边的情况下无法连接，我们必须检测可行性。 

## 方法

 强力解释将尝试所有方法将顶点分成两组，检查两个导出子图是否可以连接，并计算所需添加边的成本。 即使检查固定分区的连通性也是昂贵的，因为我们必须考虑必须添加多少条边来连接每一边，这取决于每边从原始图继承了多少个连接组件。 

暴力破解的分区数为$2^n$，这立即是不可能的。 即使限制为平衡分区仍然会留下指数级的复杂性。 

关键的见解是将视角从原始图的顶点转移到连接的组件。 在每个连接的组件内部，我们已经具有完全的连接性，因此将组件拆分到两侧会迫使我们“切割”它，并且每一侧可能需要额外的边，具体取决于该组件包含的片段数量。 

然而，出现了更强大的简化：因为我们可以以成本自由添加边缘$c$，每边的内部结构仅取决于分配给它的原始连通分量的数量。 一旦一方获得$k$原始组件，我们可以使用连接它们$k-1$增加边缘，成本$(k-1)c$。 

因此，问题简化为将原始连接组件集划分为两组，最小化：$$(\sum a_i)^2 + (\sum b_i)^2 + c \cdot (\text{number of components merged within groups})$$在哪里$a_i$和$b_i$是分配给每一侧的组件尺寸。 

我们还必须确保两个复合体之间至少存在一条边。 这迫使至少有一个原始边缘交叉或一个已构建的边缘，因此我们通过允许单个桥梁来确保可行性。 

最终的结构将连接的组件划分为两个容器，其成本仅取决于大小和数量的总和。 这变成了组件上的类似背包的 DP，其中状态是分配给一侧的当前总和，并且我们隐式跟踪使用的组件的最小数量。 

一个关键的优化是我们只需要考虑组件的大小和数量，而不再需要考虑内部图结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 顶点的暴力分割 |$O(2^n)$|$O(n)$| 太慢了 |
 | DP 分量除以总和 |$O(n \cdot \text{components})$|$O(n)$| 已接受 |

 ## 算法演练

 1. 使用DFS或DSU计算原始图的所有连通分量，并记录它们的大小。 

这是有效的，因为在连接的组件内部，顶点已经是相互可达的，所以我们永远不需要再次推理内部可达性。 
2. 设元件尺寸为$s_1, s_2, \dots, s_k$， 在哪里$k$是组件的数量。 
3. 计算总和$S = \sum s_i = n$。 通过选择第一个复合体的组件子集来定义分区； 其余的形成第二个复合体。 
4. 对于任何子集，如果所选边具有总大小$x$，另一边有尺寸$S - x$，因此基本成本变为：$$x^2 + (S-x)^2$$5. 剩余成本是由于连接每侧内部的组件而产生的。 如果一侧包含$t$组件，我们需要$t-1$连接它们的边，因此总增加成本为：$$(k_1 - 1 + k_2 - 1)c = (k - 2)c$$每当两边都非空时。 
6. 因此，对于每个不空且不满的可行分量子集，我们计算：$$x^2 + (S-x)^2 + (k-2)c$$自从$k$是固定的，最后一项在所有有效的分割中都是恒定的。 
7. 现在，我们将问题简化为找到组件尺寸的子集，其总和$x$最小化$x^2 + (S-x)^2$。 这相当于使$x$尽可能接近$S/2$。 
8. 在组件尺寸上使用标准子集和DP$n$，跟踪可达到的金额。 
9. 在所有可达到的金额中$x$和$x \neq 0$和$x \neq S$，计算表达式的最小值。 

### 为什么它有效

 关键的不变量是每个有效的配置唯一对应于连接组件的分区。 一旦组件固定，内部连接成本仅取决于每侧放置的组件数量，而不取决于其结构。 自从连接以来$t$组件的成本总是准确的$(t-1)c$，与排列无关，所有结构复杂性都分解为每侧的计数组件。 剩余的优化纯粹是针对子集和，因此 DP 完全表征了所有可行的分区，而不会丢失或重复任何配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    vis = [False] * n
    comp = []

    sys.setrecursionlimit(10**7)

    def dfs(start):
        stack = [start]
        vis[start] = True
        size = 0
        while stack:
            u = stack.pop()
            size += 1
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        return size

    for i in range(n):
        if not vis[i]:
            comp.append(dfs(i))

    if len(comp) == 1:
        print(-1)
        return

    S = sum(comp)

    dp = {0}
    for s in comp:
        ndp = set(dp)
        for x in dp:
            ndp.add(x + s)
        dp = ndp

    best = float('inf')
    k = len(comp)

    for x in dp:
        if x == 0 or x == S:
            continue
        y = S - x
        cost = x * x + y * y + (k - 2) * c
        if cost < best:
            best = cost

    print(best if best != float('inf') else -1)

if __name__ == "__main__":
    solve()
```该解决方案首先构建图形并使用迭代 DFS 提取连接的组件，以避免递归深度问题。 每个组件的大小都会被存储，因为压缩后内部结构不再重要。 

如果图是全连接的，我们立即返回$-1$，因为任何分割都必然需要破坏组件，并且无法在不构建边缘的情况下满足恰好一座桥的约束。 

然后，我们使用基于集合的 DP 计算组件大小的所有可能的子集总和。 这实际上是一个超过组件大小的背包，这是有效的，因为所有组件的总和$n$超过测试用例是有界的。 

最后，我们评估每个可实现分区的二次成本函数并保持最小值。 

常数$(k-2)c$出现在每个有效的分割中，因此它不会影响哪个分割是最优的，但它仍然包含在最终成本中。 

## 工作示例

 ### 示例 1

 考虑一个包含大小组件的图表$[3, 2, 1]$， 所以$S = 6$。 

| 步骤| DP 状态（可达总和） |
 | --- | --- |
 | 3 后 | {0, 3} |
 | 2 之后 | {0, 2, 3, 5} |
 | 1 之后 | {0, 1, 2, 3, 4, 5, 6} |

 我们评估有效的分割：

 对于$x=1$： 成本$=1^2+5^2=26$为了$x=2$： 成本$=4+16=20$为了$x=3$： 成本$=9+9=18$为了$x=4$： 成本$=16+4=20$为了$x=5$： 成本$=25+1=26$最好的是$18$，以完美平衡的方式实现。 

这证实了该算法正在最小化与总和一半的偏差。

| 步骤| DP状态|
 | --- | --- |

 有效分割仅$x=5$：

成本$=25+25=50$这表明，当仅存在两个组件时，分割是强制的，并且算法正确地处理了灵活性的缺乏。

 ## 边缘情况

 一种重要的边缘情况是图已经完全连接。 在这种情况下，只有一个组件，任何有效的答案都需要将其拆分，这迫使至少建造一座桥梁。 该算法正确检测到这一点并输出$-1$，因为不存在现有组件的分区。 

另一种情况是所有顶点都是孤立的。 那么每个顶点都是它自己的组件，DP 必须处理所有子集和。 该算法仍然有效，因为每个顶点都成为大小为 1 的组件，并且子集和自然会探索所有分区。 

最后一种微妙的情况是组件高度不平衡，例如一个组件的尺寸$n-1$和许多单身人士。 DP 仍然正确地探索了分割小子集以最小化二次不平衡，这正是预期的优化目标。
