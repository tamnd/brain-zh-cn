 ## 解决方案
 ## 问题理解

 我们得到一个有效的括号序列，这意味着它包含相同数量的左括号和右括号，并且任何前缀中的余额都不会低于零。 在这个字符串中，最初应用了一种称为“平衡洗牌”的操作：字符串中的每个位置都在该字符之前用前缀balance进行注释，然后所有位置都通过增加balance来排序，通过首先采用较大的索引来打破平局。 按该排序顺序读取字符会产生一个新的有效括号序列。 

任务是扭转这个过程。 我们不是获取原始序列并生成其打乱后的版本，而是给出打乱后的结果，并且必须重建将生成它的唯一原始序列。 

关键的困难在于，洗牌丢弃了显式的位置结构，只保留了由前缀平衡引起的全局排序。 反转它需要重建与这些约束一致的排列。 

输入大小可以达到 500,000 个字符，这立即排除了任何二次重建策略，例如尝试所有排列或模拟重新插入。 任何解决方案都必须是线性或接近线性的，由于排序或优先级结构，最坏的情况下可能是 O(n log n)。 

一个微妙的点是，洗牌取决于原始序列的前缀平衡，而不是给定的。 因此我们无法直接从输入字符串计算这些余额。 相反，我们必须从平衡括号序列的结构特性间接推断它们。 

当许多头寸共享相同的前缀余额时，就会出现边缘情况。 在这种情况下，打破平局的规则至关重要：仓位按照原始指数递减的顺序排列。 即使平衡分组是正确的，忽略此二级排序的简单重建也会产生不正确的映射。 

## 方法

 直接的强力解释将尝试通过猜测输出中的哪个字符对应于输入中的哪个位置来重建原始序列。 人们可以想象模拟所有有效的平衡序列，应用随机播放，并检查哪个序列与给定的字符串匹配。 这在理论上是正确的，因为洗牌是双射，但长度为 n 的平衡括号序列的数量随着加泰罗尼亚数的增长而增长，加泰罗尼亚数以 n 为指数。 即使对于 n = 40，这也是不可行的，而对于 n = 500000 这是完全不可能的。 

关键的见解是将洗牌重新解释为不是对字符串的转换，而是对原始序列生成的事件的排序。 每个位置都贡献一个由其前缀余额和索引组成的对，而打乱序列就是这些对按字典顺序排序（余额升序，索引降序）。 

反转该过程意味着我们必须重建这些对的原始序列。 关键的观察是，虽然我们不直接知道原始余额，但我们确实知道任何有效括号序列的结构：每个“(”增加余额，每个“)”减少余额，并且余额的总路径形成戴克路径。 

洗牌通过增加原始 Dyck 路径中的前缀高度来对位置进行排序。 这相当于从最低高度到最高高度处理路径的节点，并且在每个级别内从右到左处理节点。 该结构对应于 Dyck 路径的树状分解，其中每个左括号定义一个子树区间。

因此，反演简化为重建 Dyck 路径，其“级别顺序访问”的多重集与给定序列匹配。 我们可以使用一堆活动段贪婪地做到这一点。 打乱序列中的每个字符告诉我们在原始序列中，在它之前必须存在多少个开括号，这唯一地限制了它的位置。 

更具体的观察方法是重建按（深度，-索引）排序的位置，但我们通过模拟从左到右使用打乱序列时必须存在多少不匹配的打开来推断深度，同时保持原始序列中可用槽的优先级结构。 

这导致了一个标准的构造：我们通过模拟逆排序顺序来预先计算每个字符必须去的位置，使用由原始索引键控的优先级队列，同时保持平衡可行性约束。

 ## 算法演练

 1. 计算给定的打乱字符串的前缀平衡。 这给出了混洗表示的深度剖面，它间接地按原始级别对分组进行编码。 
2. 对于每个位置，将其计算的深度与其索引配对。 这些对表示从 shuffle 定义继承的约束，其中较低深度的元素必须以排序的原始顺序出现在较早的位置。 
3. 通过增加深度对所有位置进行排序，并且在相同深度内，通过增加索引对所有位置进行排序。 这颠倒了原来的打破平局规则（使用递减索引），有效地重建了原来的访问顺序。 
4. 使用原始序列必须是有效 Dyck 路径这一事实，将字符分配到此重构顺序中的位置。 我们尽可能放置“(”，同时保持剩余后缀仍然可以平衡。
 5. 保留仍需要多少个开口支架的计数器。 在每个位置，确定放置“(”是否会违反完成平衡序列的能力；如果是，则放置“)”。 
6. 根据这些决策构建结果字符串。 该序列是恢复的原始序列。 

关键的限制是我们始终确保完成序列的可行性。 在任何前缀处，如果我们放置太多 ')'，我们就有破坏有效性的风险，因此贪婪规则尊重 '(' 的剩余容量。

 ### 为什么它有效

 洗牌按原始序列中的前缀高度对位置进行排序，这相当于在有根树表示中按 Dyck 路径的深度对节点进行排序。 每个深度级别在原始序列中形成连续的结构，并且通过递减索引进行二次排序确保每个级别内从右到左的遍历一致。 

反转此顺序可恢复 Dyck 路径的原始遍历顺序。 一旦重建了该顺序，则根据序列保持有效平衡路径的要求强制进行括号分配。 在每一步中，都有一个有效的选择来保留完成完整序列的能力，从而保证唯一性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # prefix balance of shuffled string
    bal = 0
    depth = []
    for c in s:
        depth.append(bal)
        if c == '(':
            bal += 1
        else:
            bal -= 1

    # reconstruct original order: sort by (depth asc, index asc)
    order = list(range(n))
    order.sort(key=lambda i: (depth[i], i))

    # build result
    res = [''] * n
    open_left = n // 2  # number of '(' needed

    # we decide greedily but respecting balance feasibility
    balance = 0
    for i in order:
        # try to place '(' if possible
        if open_left > 0 and balance + 1 <= n - (i + 1) - (open_left - 1):
            res[i] = '('
            balance += 1
            open_left -= 1
        else:
            res[i] = ')'
            balance -= 1

    print(''.join(res))

if __name__ == "__main__":
    solve()
```该代码首先计算给定的打乱字符串的前缀平衡。 这些值不是原始余额，而是充当级别指示器，定义随机排列字符的方式。 

排序步骤重构了洗牌排序规则的逆过程。 使用增加深度和增加索引可以恢复原始的结构顺序，因为洗牌是通过增加深度和减少索引进行排序的。 

然后，贪婪重建强制戴克路径的有效性。 变量`open_left`跟踪还有多少左括号可用。 循环内的条件确保放置“(”不会导致稍后无法完成序列。这是构造具有固定打开次数的平衡括号的标准可行性检查。

 ## 边缘情况

 一种边缘情况是打乱后的字符串中的所有字符对应的前缀余额非常低。 在这种情况下，排序将几乎所有索引在深度零处分组在一起，并且按索引打破平局决定一切。 重建仍然有效，因为贪婪的可行性检查迫使在需要的地方提前放置左括号。 

另一个边缘情况是完全嵌套的序列，例如`(((())))`，其中深度严格增加然后减少。 排序产生非常结构化的顺序，并且重建变得确定性且没有分支。 可行性条件确保关闭括号被推迟，直到放置了足够的空位。 

最后的边缘情况是交替结构，例如`()()()()`，其中深度振荡剧烈。 在这里，许多头寸共享相同的深度，并且索引排序成为主要结构。 该算法仍然可以正确重建，因为可行性（而不是局部结构）强制括号的正确配对。
