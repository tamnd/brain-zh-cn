 ## 解决方案
 ## 问题理解

 我们有一个源字符串`s1`，代表一份报纸的标题。 我们可以根据需要获取该标题的多个副本并将它们连接在一起。 从生成的长字符串中，我们可以删除任意字符，同时保持剩余字符的顺序。 

目标字符串`s2`必须作为串联标题的子序列出现。 任务是确定最小副本数`s1`需要构建`s2`。 如果某个字符`s2`从未出现在`s1`，这个任务是不可能完成的。 

该操作完全与子序列有关。 我们不会重新排列字符，只是跳过它们。 例如，如果`s1 = "abc"`和`s2 = "cab"`，一份副本是不够的，因为`"cab"`不是以下的子序列`"abc"`。 两份副本有效是因为`"cab"`是一个子序列`"abcabc"`。 

这些约束在很大程度上影响了解决方案。 长度为`s1`至多是`10^4`，它足够小以进行预处理。 长度为`s2`可以达到`10^6`，这意味着任何算法都会进行完整扫描`s1`对于每个字符`s2`会太慢了。 二次式解决方案，例如`O(|s1| * |s2|)`可能需要周围`10^10`最坏的情况下，两秒之内是不可能的。 目标复杂度应该接近线性`|s2|`，最多具有对数开销。 

一些边缘情况很容易被错误处理。 

考虑：```
s1 = "abc"
s2 = "xyz"
```正确答案是`-1`因为再多的串联也无法创建出从未出现过的字符`s1`。 粗心的贪婪实现可能会永远循环尝试匹配`'x'`。 

另一个棘手的情况是：```
s1 = "abc"
s2 = "cab"
```正确答案是`2`。 第一个副本提供`'c'`，但是到达字符串末尾后我们必须重新开始以获得`'a'`和`'b'`。 仅检查是否存在的实现`s2`是重复扫描的子序列，没有正确计数重置可能会输出`1`。 

重复的字符也很重要：```
s1 = "ab"
s2 = "bbbb"
```答案是`4`。 每个副本仅贡献一个`'b'`。 计算不同字符或频率而不是保持顺序的简单方法在这里会失败。 

当当前字符存在于`s1`，但不在当前位置之后：```
s1 = "abca"
s2 = "aa"
```答案是`1`，因为两者`'a'`可以在同一副本内匹配字符。 如果当前位置处理偏离一个，算法可能会在第一个副本之后错误地启动新副本`'a'`。 

## 方法

 最直接的方法是从字面上模拟该过程。 我们不断地扫描`s1`尝试匹配的字符`s2`为了。 每当我们到达终点时`s1`，我们开始另一个副本并继续匹配。 

这种暴力方法是正确的，因为它完全遵循后续的构建过程。 对于每一个角色`s2`，它在当前副本中搜索下一个可用的出现位置`s1`。 

问题是性能。 认为`s1`有长度`10^4`和`s2`有长度`10^6`。 在最坏的情况下，对于每个字符`s2`我们可以扫描几乎所有的`s1`。 这大约产生`10^10`人物对比，远远超出了时间限制。 

关键的观察结果是重复线性扫描会浪费工作。 每次我们问“字符下一次出现在哪里”`c`位置后`p`？”，我们从头开始重新计算答案。因为`s1`永远不会改变，我们应该对其进行一次预处理并快速回答这些查询。 

一个方便的结构是为每个字符存储它出现的位置的排序列表`s1`。 

例如：```
s1 = "abac"
```我们存储：```
a -> [0, 2]
b -> [1]
c -> [3]
```现在假设我们目前处于位置`1`并需要下一个`'a'`。 我们不是线性扫描，而是在内部进行二分搜索`[0, 2]`找到第一个大于的值`1`，即`2`。 

如果不存在这样的位置，则当前副本`s1`已经筋疲力尽了。 我们开始一个新的副本并获取该字符第一次出现的位置。 

这将昂贵的重复扫描转变为高效的对数查询。

 ## 算法演练

 1. 预处理`s1`通过存储每个字符的所有出现位置。 

对于每个索引`i`在`s1`, 追加`i`到对应的列表`s1[i]`。 
2. 加工前`s2`，验证每个字符`s2`出现在某处`s1`。 

如果缺少一个字符，则打印`-1`立即，因为没有任何数量的串联可以创建它。 
3. 从一份副本开始`s1`。 

维护一个变量`pos`表示活动副本内的当前位置。 初始设置`pos = -1`，这意味着我们还没有使用任何字符。 
4. 工艺特点`s2`从左到右。 

对于当前角色`c`，检索其排序的出现列表。 
5. 使用二分查找查找第一次出现的严格大于`pos`。 

这给出了当前副本内的下一个有效子序列位置。 
6. 如果存在这样的位置，则移动`pos`到该索引。 

我们成功地匹配了该角色，而无需另一份报纸。 
7. 如果不存在有效的事件，则启动新的副本`s1`。 

增加答案计数器，然后取第一次出现的`c`从它的列表和集合`pos`到那个值。 
8、处理完所有字符后，输出使用的份数。 

### 为什么它有效

 该算法总是在开始新副本之前尽可能多地消耗当前副本。 这种贪婪的选择是最优的，因为较早开始新副本永远不会在当前副本内创建额外的匹配机会。 

步步，`pos`代表当前报纸中最新匹配的位置。 二分查找选择最早可能的有效下一次出现。 选择最早出现的位置可以为未来的字符留下最大的剩余后缀，这只会有所帮助。 

每当之后不存在任何事件`pos`，当前副本内的每个子序列延续都是不可能的。 开始新的副本不仅仅是一种选择，而且是必要的。 

由于该算法仅在强制时启动新副本，因此副本总数最少。 

## Python 解决方案```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    s1 = input().strip()
    s2 = input().strip()

    positions = {}

    for i, ch in enumerate(s1):
        if ch not in positions:
            positions[ch] = []
        positions[ch].append(i)

    for ch in s2:
        if ch not in positions:
            print(-1)
            return

    ans = 1
    pos = -1

    for ch in s2:
        arr = positions[ch]

        idx = bisect_right(arr, pos)

        if idx == len(arr):
            ans += 1
            pos = arr[0]
        else:
            pos = arr[idx]

    print(ans)

solve()
```预处理步骤构建一个从字符到排序出现位置的字典。 由于我们扫描`s1`从左到右，列表会自动排序。 

不可能性检查发生在主循环之前。 这避免了匹配过程因丢失字符而反复失败的极端情况。 

变量`pos`跟踪当前副本中最新匹配的索引`s1`。 使用`-1`最初很方便，因为任何字符的第一次有效出现总是大于`-1`。 

关键的实现细节是使用`bisect_right`。 我们需要严格位于当前位置之后的第一次出现。 使用`bisect_left`会错误地允许多次重复使用相同的字符位置。 

当二分查找无法找到有效的下一个位置时，我们必须开始一个新的副本并使用该字符的第一次出现。 忘记重置`pos`正确的是，这是一个常见的错误。 

该算法从不显式地构造重复的副本`s1`。 它仅模拟它们之间的转换，即使答案很大，也能保持较小的内存使用量。

 ## 边缘情况

 考虑不可能的情况：```
s1 = "abc"
s2 = "xyz"
```在预处理期间，算法仅存储位置`'a'`,`'b'`， 和`'c'`。 检查时`s2`, 字符`'x'`字典中缺失，因此算法立即打印`-1`。 没有模拟发生。 

现在检查环绕案例：```
s1 = "abc"
s2 = "cab"
```算法首先匹配`'c'`在位置`2`。 下一个字符是`'a'`。 内部二分查找`[0]`对于大于的值`2`失败，因此算法开始一个新的副本并设置`pos = 0`。 然后`'b'`匹配位置`1`。 最终答案变成`2`。 

对于重复字符：```
s1 = "ab"
s2 = "bbbb"
```匹配第一个后`'b'`在位置`1`，以后每次搜索`'b'`在同一副本内失败，因为没有位置大于`1`。 该算法每次都正确地启动一个新副本，产生`4`。 

最后，考虑：```
s1 = "abca"
s2 = "aa"
```第一个`'a'`匹配位置`0`。 对于第二个`'a'`，二分查找找到位置`3`，它仍然在同一个副本中。 答案依然存在`1`。 这证实了当当前副本中稍后存在另一个有效事件时，算法不会过早重置。
