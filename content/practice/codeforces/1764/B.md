 ## 解决方案
 ## 问题理解

 我们从一组有限的正整数开始。 我们可以重复选择两个数字，用较大的数字减去较小的数字，如果结果尚不存在，则插入结果。 该过程一直持续到无法创建新号码为止。 

问题不在于单个操作序列，而在于如果我们以最佳可能的顺序选择操作，以最佳方式进行操作，则该集合的最终最大可能大小。 

一个关键的观察是集合只会增长，并且每个新元素都是两个现有元素的差异。 这立即将过程置于加法结构生成的世界中：我们正在限制减法规则下关闭该集合。 

约束足够大，任何操作模拟都是不可能的。 所有输入大小的总和高达 200000，因此每次测试我们必须接近线性或线性算数时间。 任何以幼稚的方式动态地重复插入和检查集合成员资格的方法都会因重复的差异生成而面临二次行为的风险。 

当集合已经与步骤 1 形成算术级数时，就会出现微妙的边缘情况。例如，如果 S = {1,2,3,4}，则每个减法都已保留在集合内部，因此不会发生扩展。 答案是 4。天真的方法可能会试图不断产生差异，并错误地认为增长总是可能的。 

另一种边缘情况是当集合具有较大的 gcd 结构时，例如 S = {6,10,14}。 差异很快就会缩小到 2 的倍数，并且只有与该结构一致的数字才会出现。 

## 方法

 蛮力的想法很简单。 将集合维护为哈希结构，重复尝试所有对 (x, y)，计算 x - y，如果是新的，则将其插入。 重复直到没有变化发生。 这是正确的，因为它直接遵循操作规则。 

然而，每次迭代都是 O(n²)，在新元素逐一出现的最坏情况下，迭代次数也可能是 O(n)。 这会导致立方行为，这是不可行的。 

关键的见解是该过程从根本上是由集合中的最小值控制的。 生成的每个新数字都是现有值的线性组合，并且所有可达值都位于该集合生成的加法子组中，限制在区间 [min(S), max(S)] 内。 

更精确的查看方法是通过减去最小元素来标准化集合。 经过这种转变，我们有效地生成了原始集合的所有差异，这相当于生成所有具有受可达性约束的正系数的整数线性组合。 闭包稳定为连续结构，其步长等于所有成对差异的 gcd。 

因此，该过程收敛于填充 min(S) + k·g 形式的所有值，其中 g 是元素之间所有差异的 gcd。 最终大小由最小值和最大值之间有多少个此类值决定。 

结束对比：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 最坏 O(n3) | O(n) | 太慢了|
 | 基于 GCD 的闭包 | O(n log A) | O(n log A) | O(1) 额外 | 已接受 |

 ## 算法演练

 最佳解决方案依赖于通过差异将问题简化为数论。

1. 计算集合的最小元素。 这充当锚点，因为所有生成的值都可以相对于它来表达。 
2. 计算所有差值 a[i] - a[0] 的 gcd。 这捕获了所有可达值的不变步长，因为减法保留了整除结构。 
3. 一旦知道了 gcd，过程的结束就是从最小元素开始，步长等于该 gcd 的算术级数。 
4. 计算该级数中有多少元素位于区间 [min, max] 内。 这给出了全闭集的最终大小。 

为什么它有效：每个操作 x - y 都保留了所有值都保留在由原始差异生成的加法组中的属性。 该群正是差的 gcd 倍数的集合。 由于没有任何操作可以产生该晶格之外的值，并且范围内的每个有效倍数都可以通过重复减法来构造，因此最终状态由该 gcd 结构唯一确定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        
        if n == 1:
            print(1)
            continue
        
        g = 0
        for i in range(1, n):
            g = math.gcd(g, a[i] - a[0])
        
        if g == 0:
            print(1)
            continue
        
        length = (a[-1] - a[0]) // g + 1
        print(length)

if __name__ == "__main__":
    solve()
```该实现首先对数组进行排序以安全地定义固定的参考最小值。 GCD 是针对相对于该最小值的所有差异进行累积的。 这避免了成对的 O(n²) 计算并保持每次测试的结构线性。 

一个常见的陷阱是忘记通过最小元素对差异进行标准化； 如果没有这个，gcd 计算可能仍然有效，但推理起来不太稳定。 另一个问题是处理退化情况，其中所有数字都相等，gcd 循环将保持为零。 

## 工作示例

 第一个例子：S = {1, 2}

 | 步骤| 设置| GCCD | 评论 |
 | --- | --- | --- | --- |
 | 初始化| {1,2} | 0 | 开始 |
 | 差异| {1,2} | 1 | 最大CD(1) |
 | 结果| {1,2} | 1 | 完整间隔|

 最终大小为 (2 - 1)/1 + 1 = 2。 

第二个例子：S = {5, 10, 25}

 | 步骤| 设置| GCCD | 评论 |
 | --- | --- | --- | --- |
 | 初始化| {5,10,25} | 0 | 开始 |
 | 差异| {5,10,25} | 5 | 最大CD(5,20) |
 | 关闭| 算术级数步骤 5 | 5 | 稳定 |

 我们得到的值是 5、10、15、20、25，所以答案是 5。 

这证实了结构塌陷成由 gcd 确定的均匀间距。

 ## 边缘情况

 如果所有数字都相同，则差异的 gcd 保持为零，答案立即为 1。算法通过零 gcd 防护正确检测到这一点。 

如果数字形成完美的算术级数，则每个差异都共享相同的 gcd，因此闭包不会扩展到现有元素之外，从而与公式完全匹配。 

如果值间隔很大但共享一个公约数结构，则 gcd 将它们简化为均匀格，并且该算法仅正确计算边界内的有效可达点。
