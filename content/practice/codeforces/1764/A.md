 ## 解决方案
 ## 问题理解

 我们得到一个数组并要求选择一个连续的段。 对于任何选定的段，我们计算两个量：其长度以及其中出现的不同值的数量。 段的分数是长度减去不同值的数量。 任务是找到使该分数最大化的任何部分。 

用更直观的术语来说，每个位置都会对段长度做出贡献，但每种不同的颜色在不同计数中只“支付一次”。 因此，重复出现一种颜色是有益的，而引入许多不同的颜色而不重复往往会损害分数。 

约束允许最多$10^5$每个测试用例的元素以及所有测试用例的总和也是$10^5$。 这立即排除了所有子阵列上的任何二次方法。 即使是天真的$O(n^2)$扫描所有段太慢。 每个测试用例的任何解决方案都必须基本上是线性的。 

这个问题的一个微妙之处是，最好的段不一定是整个数组，尽管乍一看这似乎很自然。 完整数组可以包含许多单次出现的值，每个值对分数没有任何积极贡献，并且会有效地降低结果。 专注于重复值的较小细分市场可以超越它。 

当所有元素都不同时，就会出现常见的边缘情况。 在这种情况下，每段长度$k$有分数$k-k=0$，因此每个单元素段都是最优的。 另一个边缘情况是当存在重复项但相距很远时，选择中间的所有内容可能会引入太多不同的元素并降低分数。 

## 方法

 暴力解决方案将枚举所有可能的对$(l, r)$，计算每个片段中不同元素的数量，并评估分数。 增量地维护不同计数是可能的，但仍然会导致$O(n^2)$细分和整体$O(n^2)$或者更糟糕的复杂性，这是不可接受的$10^5$。 

关键的观察是以揭示真正重要的内容的方式重写乐谱。 对于某个段，值在该段内第一次出现之后每次重复出现都会使分数增加 1。 同样，分数由片段包含的重复项数量决定。 单个出现是中性的，但相同值的多次出现是有益的。 

这改变了观点：我们并不是试图仔细平衡所有价值观，而是试图包含尽可能多的重复贡献。 如果一个值在数组中至少出现两次，则任何包含该值两次出现的段都已经保证了相对于纯粹不同段的非负增益。 

从这里开始，出现了一个关键的简化。 无需搜索所有段，只需选择多次出现的任何值并返回覆盖其两次出现的段即可。 该片段保证是最优的或并列最优，因为它已经捕获了至少一个重复贡献，而单元素或完全不同的片段不能超过该结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有子数组进行暴力破解 |$O(n^2)$|$O(1)$或者$O(n)$| 太慢了|
 | 第一次/最后一次出现重复值 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 扫描数组并存储每个值的第一个和最后一个位置。 这使我们能够检测一个值是否出现多次以及其极端出现的位置。 
2. 检查某个值是否至少出现两次。 如果没有值重复，则每个段都具有所有不同的元素，因此任何单个索引都会形成最佳答案。 
3. 如果存在重复值，请选择任何此类值。 设其第一次出现为$l$它的最后一次出现是$r$。 输出该段。 

我们可以安全地停止在任何重复值处的原因是，目标仅奖励重复出现的情况，并且任何包含两次出现的相同值的段都已经实现了比任何纯粹由不同元素组成的段更好的结构。 

### 为什么它有效

 片段的分数可以解释为“片段内出现了第一个之外的额外出现次数”。 如果包含两次出现，则出现两次的值至少会造成一次此类额外出现。 任何没有重复的段都没有任何积极贡献，因此以零为界。 一旦片段包含重复值，它就会与所有不同的片段竞争或更好，并且扩展片段不会使正确性失效，因为包含附加元素不会减少已经存在的重复贡献的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    first = {}
    last = {}
    
    for i, x in enumerate(a, 1):
        if x not in first:
            first[x] = i
        last[x] = i
    
    l, r = 1, 1
    found = False
    
    for x in first:
        if first[x] != last[x]:
            l, r = first[x], last[x]
            found = True
            break
    
    print(l, r)
```该解决方案依赖于在一次传递中记录每个值的第一次和最后一次出现。 这确保我们无需扫描子数组即可识别重复元素。 最后一个循环选择任何重复值并输出其极值位置。 如果不存在重复，则保留默认输出$1, 1$，这是有效的，因为所有单元素段的分数都是相等的。 

一个常见的实现陷阱是尝试计算每个段的不同计数或尝试动态优化间隔。 这是不必要的，因为目标的结构将问题分解为检测重复而不是在间隔内进行优化。 

## 工作示例

 考虑数组$[1, 3, 2, 2, 4]$。 第一次和最后一次出现的情况被跟踪为$1:(1,1)$,$3:(2,2)$,$2:(3,4)$,$4:(5,5)$。 价值$2$是唯一重复的，所以我们输出$3, 4$。 通过捕获重复项，这已经获得了积极的分数。 

现在考虑$[1, 2, 3, 4, 5]$。 每个值都只出现一次，因此不存在重复值。 算法输出$1, 1$。 任何单个索引都同样有效，因为所有段的得分都为零。 

一个更微妙的情况是$[2, 1, 2, 1]$。 这里两个$1$和$2$重复。 如果我们选择$1$，我们输出$2, 4$，如果我们选择$2$，我们输出$1, 3$。 两者都是有效的，因为两个段都包含至少一个重复值。 

这些例子表明，该算法并不尝试微调片段，而是依赖重复的存在作为唯一的改进来源。

 ## 边缘情况

 当所有元素都不同时，算法会回退到返回单个位置，因为没有值具有不同的第一次出现和最后一次出现。 例如，输入$[4, 7, 9]$产生$1, 1$，并且任何其他单个索引都同样有效，因为所有段的得分都为零。 

当多个值重复时，算法会在第一个检测到的值处停止。 用于输入$[5, 1, 5, 1]$，这两个值都是有效的锚点。 如果扫描选择$5$，我们输出$(1, 3)$; 如果它选择$1$，我们输出$(2, 4)$。 两者都达到相同的最佳分数，因此两者都是正确的。 

当重复值仅出现两次但被许多不同值包围时，该段仍然有效，因为至少一个重复值的存在保证了非负贡献，并且任何添加的不同元素不会使最优性失效。
