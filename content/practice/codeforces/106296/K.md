 ## 解决方案
 ## 问题理解

 该问题给出了隐藏的十进制数字序列。 在非交互式形式中，整个数字字符串可用作输入。 我们需要判断这个字符串中是否至少存在一个连续的部分，其数值可以被3整除。输出为`1`如果这样的子串存在并且`0`否则。 

重要的性质是能被 3 整除仅取决于数字之和。 当子串的数字和除以 3 后余数为零时，该子串可以被 3 整除。 

原始语句中字符串的长度很小，但预期的想法应该仍然可以扩展。 如果长度大约是`10^5`，检查每个子字符串的解决方案已经太慢了。 有大约`n^2`可能的子串，并且对于`n = 10^5`这大致意味着`10^10`检查，远远超出了正常的时间限制。 我们需要一个处理字符串一次的解决方案。 

棘手的情况来自于不是明显单位数字的子字符串。 例如：```
Input
2
12

Output
1
```数字`1`单独不能被 3 整除并且`2`单独不能被3整除，但子串`12`有数字和`3`，所以它有效。 仅检查单个数字的解决方案将会失败。 

另一种情况是：```
Input
3
111

Output
1
```单个数字不起作用，但整个字符串有总和`3`。 在未能找到一位数答案后停止的方法是不正确的。 

边界情况是：```
Input
3
124

Output
0
```每个位置的前缀和模 3 都不同，并且前缀本身没有余数为零，因此不存在有效的子串。 

## 方法

 暴力法是尝试每一个可能的子串，计算其数字和，并检查该和是否能被 3 整除。它是正确的，因为检查了每一个可能的候选串。 使用前缀和数组，每个子串检查可以在常数时间内完成，但仍然存在`O(n^2)`子串。 对于大输入，这变得太慢。 

关键的观察是我们不需要实际的和，只需要它们模 3 的余数。让`pref[i]`是第一个的总和`i`数字模 3。 子串的总和`l`到`r`是：`pref[r] - pref[l - 1]`如果两个前缀和具有相同的余数，则它们的差可以被 3 整除。该差对应于一个数字和可以被 3 整除的子串。 

这将问题转化为跟踪我们在从左到右扫描时是否之前见过每个余数。 当余数重复时，两个位置之间的部分是有效子串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 对于大输入来说太慢 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数字字符串并以前缀余数开头`0`。 这表示字符串开始之前的空前缀。 
2. 保留一个包含已出现的前缀余数的数组或集合。 最初，只有剩余部分`0`出现是因为空前缀的数字和为零。 
3. 从左到右遍历字符串。 将当前数字添加到运行总和中并对其进行模减`3`。 
4. 如果该余数之前已经出现过，则前一次出现的位置与当前位置之间的子串的数字和可整除`3`，所以答案是`1`。 
5. 否则，记录该余数并继续扫描。 
6. 如果处理整个字符串没有找到重复的余数，则输出`0`。 

为什么它有效：

 运行余数描述了以当前位置结尾的前缀的数字和。 每当相同的余数出现两次时，减去两个前缀和就会删除公共部分，并留下总和可被 3 整除的子字符串。由于在扫描过程中会检查每个可能的结束位置，因此算法会找到有效的子字符串（如果存在）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().split()
    if not data:
        return

    if len(data) == 1:
        s = data[0]
    else:
        s = data[1]

    seen = [False, False, False]
    seen[0] = True
    cur = 0

    for ch in s:
        cur = (cur + ord(ch) - ord('0')) % 3
        if seen[cur]:
            print(1)
            return
        seen[cur] = True

    print(0)

if __name__ == "__main__":
    solve()
```该代码仅存储三个可能的前缀余数，因此不需要前缀数组。 这`seen`array 就足够了，因为我们只关心余数是否出现，而不关心它出现在哪里。 

初始化与`seen[0] = True`处理从第一个数字开始的子字符串。 如果没有它，就会丢失一个数字和已经能被 3 整除的前缀。 

在每个数字相加后执行模运算，使运行值保持较小并避免不必要的整数增长。

 ## 边缘情况

 对于子串`12`，算法从余数开始`0`, 过程`1`并存储剩余部分`1`，然后处理`2`并得到余数`0`再次。 由于余数`0`已经看到，两个位置之间的子串是有效的，答案是`1`。 

对于字符串`111`，运行余数为`1`,`2`， 和`0`。 最后一个位置达到余数零，这意味着整个字符串有数字和`3`。 初始存储的零余数允许算法检测到这一点。 

对于像这样的字符串`124`，该算法在读取前两位数字后检测到重复的零余数，因为`1 + 2 = 3`。 这说明了为什么前缀余数捕获不是个位数的子字符串。
