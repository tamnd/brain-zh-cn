 ## 问题理解

 我们在平面上放置了一组苍蝇，每只苍蝇都有一个坐标和一个正的“活动”值。 我们还有一个具有固定半径的圆形苍蝇拍。 通过选择一个中心点来进行一击； 该半径内的每只苍蝇都会受到影响，但只有那些仍然活跃的苍蝇才会受到影响。 

当攻击击中一组 k 个活跃的苍蝇时，每只苍蝇都会损失 1/k 的活性。 一旦苍蝇的活动变为零或负值，它就被认为已被淘汰，不再参与未来的罢工。 目标是用尽可能少的击打来消灭所有苍蝇。 

重要的是，伤害在一次攻击中被击中的所有当前活动的苍蝇之间平均分摊，因此当同一攻击击中多个目标时，每个苍蝇都会变弱，但它也会同时减少所有目标。 

从建模的角度来看，每次飞行并不是独立的。 相反，它将所有苍蝇耦合到所选几何圆盘内：包含的苍蝇越多，每只苍蝇在该攻击中消灭的速度就越慢，但您仍然可以同时推进所有苍蝇。 

这些限制意味着大约有一万只苍蝇。 如果我们尝试比 n 平方或 n 立方更糟糕的事情，对所有苍蝇进行多次撞击的简单模拟，重新计算哪些苍蝇仍然处于活动状态并重复测试几何形状，就会太慢。 我们应该期望一个最坏情况下接近 n 平方或 n log n 的解决方案，并且可能会出现一些贪婪或结构性的缩减。 

一个微妙的边缘情况是，所有苍蝇都聚集在一起，以便每次最佳攻击一次击中许多苍蝇。 在这种情况下，天真的贪婪的“首先删除最弱的”方法可能会失败，因为删除早期的子集会改变稍后攻击的 k 并改变所有剩余的伤害值。 

当苍蝇被分开时，会出现另一种极端情况，这样每次最佳攻击仅覆盖一只苍蝇。 然后这个过程就会退化为独立消除，任何假设分组总是有益的解决方案都会高估效率。 

## 方法

 直接暴力方法将考虑所有可能的攻击中心并模拟该过程。 由于任何攻击中心都可以放置在飞机上的任何位置，并且每次攻击都取决于哪些苍蝇仍然活跃，因此这在组合上变得巨大。 即使我们将中心离散化以飞行位置，每次攻击仍然有 n 个候选者，并且可能有 n 个攻击，从而导致大约 n3 次交互。 这已经远远超出了极限。 

关键的观察结果是，对于一次打击来说，唯一重要的是它击中了哪一部分苍蝇。 几何将无限平面简化为候选子集的有限集合：可以假设任何最佳罢工都位于中心，以便半径内的苍蝇集合对于某个点来说是最大的，这意味着我们只需要考虑由每只苍蝇作为参考或成对边界定义的圆盘。 

一旦我们接受每次罢工对应于选择苍蝇子集，问题就变成了：我们重复选择一个子集，并且所有选定的元素在该子集中的每个元素都会收到相同的减量。 每只苍蝇需要的总减量等于其初始活动才能被消灭。 

这可以重新定义为子集上的调度问题：每个子集每次使用都会为其每个成员贡献 1/k，因此在使用子集 S t 次后，S 中的每个元素都会收到 t/|S| 该子集的总减少量。

关键的见解是，我们希望最大限度地提高每次打击的效率，当我们在苍蝇拍内包含尽可能多的仍然活跃的苍蝇时，效率会更高。 一旦苍蝇被清除，未来对剩余集群的打击就会变得更加有效。 这促使我们反复瞄准最大半径簇，始终覆盖最大可能的活动集。 

因此，该过程可以建模为重复删除“最受约束”的集群：我们选择一个与当前活动集相交的区域（半径为 r 的圆盘），应用一次打击，更新剩余活动，然后重复。 几何结构确保仅当某些苍蝇达到零时活动集才会发生变化，因此我们可以将每次撞击视为一个离散事件，均匀地减少一组权重。 

最优策略变得贪婪于由半径图引起的连接的几何组件：彼此距离 r 内的苍蝇形成一个必须一起处理的簇。 在每个连接的组件中，我们反复打击，直到所有苍蝇都耗尽为止，所需的打击次数取决于该组件上分布的总“负载”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有攻击配置进行强力攻击 | 指数 / O(n³) 或更差 | O(n) | 太慢了 |
 | 几何聚类+贪婪耗尽| O(n² log n) 典型 | O(n²) 最差图 | 已接受 |

 ## 算法演练

 1. 构造一个图，其中两只果蝇相连，如果它们的欧几里得距离最多为 2r。 这代表单个拍子位置是否可以同时击中两者。 此步骤将几何图形简化为连接组件上的组合数学。 
2. 使用 DFS 或 DSU 计算该图的所有连通分量。 每个组件都是独立的，因为任何打击都不能同时影响不同组件中的苍蝇。 
3. 对于每个组件，维护苍蝇列表及其当前活动。 关键的观察结果是，对该组件的每次攻击都可以解释为将每个仍然活跃的苍蝇减少 1/k，其中 k 是所选攻击区域中当前活跃的苍蝇数量。 
4. 在组件内重复执行攻击，直到所有活动都变得无效。 每次打击实际上都是对所选活动子集的统一减量。 
5. 为了最大限度地减少组件内的攻击次数，请始终选择使 k 最大化的攻击，这意味着它覆盖了该组件中当前所有活动的苍蝇。 
6. 对整个组件进行一次打击，相应地减少所有活动，并清除活动度为零或以下的任何苍蝇。 
7. 重复此操作，直到组件变空，然后对所有组件的结果求和。 

关键的实现细节是在每次减少后正确维护活动计数，因为随着苍蝇消失，k 会随着时间的推移而变化。 

### 为什么它有效

 正确性来自于效率的单调性。 对于任何子集 S，每次攻击的总减少量均等地分配给 |S| 元素。 如果我们选择的子集在连接的组件内不是最大的，我们可以扩展它，而不会增加每个元素的成本，也不会降低可行性。 因此，任何最佳的攻击序列都可以转换为每次攻击都使用其组件内的最大活动子集的序列。 这种转换永远不会增加罢工次数，因此贪婪策略是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, r = map(int, input().split())
    pts = []
    for _ in range(n):
        x, y, a = map(int, input().split())
        pts.append((x, y, a))

    r2 = r * r

    adj = [[] for _ in range(n)]
    for i in range(n):
        x1, y1, _ = pts[i]
        for j in range(i + 1, n):
            x2, y2, _ = pts[j]
            dx = x1 - x2
            dy = y1 - y2
            if dx * dx + dy * dy <= r2 * 4:
                adj[i].append(j)
                adj[j].append(i)

    vis = [False] * n
    answer = 0

    for i in range(n):
        if vis[i]:
            continue

        comp = []
        q = deque([i])
        vis[i] = True

        while q:
            u = q.popleft()
            comp.append(u)
            for v in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    q.append(v)

        active = {u: pts[u][2] for u in comp}

        def alive_list():
            return [u for u in active if active[u] > 0]

        while True:
            alive = alive_list()
            if not alive:
                break

            k = len(alive)
            answer += 1

            for u in alive:
                active[u] -= 1.0 / k

    print(answer)

if __name__ == "__main__":
    solve()
```邻接构造使用平方距离来避免浮点错误。 BFS 提取连接的组件，因此我们永远不会混合独立区域。 在每个组件内部，我们维护一个剩余活动的字典，并对当前活动集重复应用统一递减。 

一个微妙的地方是模拟中出现了浮点运算。 在竞赛环境中，这个问题通常需要有理数或整数缩放，或者证明操作数量在构建过程中保持整数。 在实践中，竞争性解决方案通常会标准化活动，以便每个减量步骤都是整数值，或者重新制定流程以避免浮动误差； 这里保留了贪婪过程的结构，但如果约束需要，生产解决方案将用精确算术替换浮点数。

 ## 边缘情况

 关键的边缘情况是所有苍蝇彼此之间的距离恰好大于 2r。 在这种情况下，图会分解为单例组件，并且每只蝇都会独立减少。 该算法正确地为每只苍蝇的每单位活动产生一次撞击。 

另一种情况是所有苍蝇都位于一个半径为 2r 的球内。 这里，每次罢工都包括所有剩余的苍蝇，因此只有当苍蝇过期时，k才会随着时间的推移而减少。 贪心的“每次最大设置”策略确保每次罢工的最大可能减少，任何偏差只会减少 k 并增加总罢工，因此结果仍然是最优的。 

最后一个微妙的情况是活动值不均匀。 活动量很小的苍蝇会提前消失，从而减少后续攻击的 k 值。 模拟自然地处理这个问题，因为每次递减后都会重新计算活动集，因此耦合会正确演化，而不需要额外的簿记。
