 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串`s`以及其上的固定间隔集合。 每个区间提取一个子串，所有提取的子串被连接起来形成一个新的字符串`t(s)`。 的结构`t(s)`由间隔固定，因此原始字符串的每个位置都会对最终连接中的多个位置做出贡献。 

每次更新后，一个位置`s`被翻转自`0`到`1`反之亦然。 每次翻转后，我们都可以重新排列`s`通过交换任意两个位置任意次数。 我们报告的成本是所需的最小交换次数，以便最终的串联`t(s)`在所有可能的排列中成为字典顺序最大的`s`。 

这里按字典顺序最大意味着我们想要`t(s)`尽可能大，这在二进制字符串中意味着使较早的字符`t(s)`作为`1`尽可能地，因为`1`占主导地位`0`在第一个不同的位置。 

重要的观察是我们永远不会改变`t(s)`，仅分配来自`s`进入位置`t(s)`由间隔引起。 各指标为`s`出现在一些位置`t(s)`，而多重性决定了该索引的价值。 

限制条件很大：`n, m, q ≤ 2⋅10^5`。 这排除了每个查询从头开始重新计算贡献，因为简单的重新计算至少会花费`O(nm)`或者`O(n)`每个查询都太慢。 我们需要一个支持点更新并维护全局加权摘要的结构。 

当间隔严重重叠时，就会出现一个微妙的问题。 一种幼稚的方法可能假设每个字符在每个间隔贡献一次，但贡献取决于包含每个索引的子字符串数量，而不是间隔以任意方式重叠的频率。 

## 方法

 蛮力法是重新计算每个位置的贡献`s`每次翻转后。 对于每个索引`i`，我们计算有多少个区间覆盖它，给出一个权重`w[i]`。 然后`t(s)`相当于多重集，其中位置`i`贡献`w[i]`的副本`s[i]`。 

使`t(s)`按字典顺序最大，我们希望所有可用`1`s 被放置在最高权重的位置`t(s)`。 由于交换除了计算其数量之外是免费的，因此真正的任务变成：给定权重和当前二进制值，计算交换的最小数量，以将当前排列转换为按权重排序的最佳排列。 

每个查询的所有权重的强力重新计算是`O(nm + qn)`，太大了。 

关键的见解是每个索引`i`线性且独立地贡献，最终结构仅取决于权重`w[i]`。 一旦我们预先计算出每个位置在所有间隔中出现的次数，问题就简化为在翻转下维护加权的位多重集。 

现在第二个想法：我们不重新计算所有内容，而是维护有多少个`1`s 存在于每个重量等级中。 由于最优排列总是放置`1`s 到最大的权重，我们只需要维护权重的排序结构并跟踪有多少`1`s 占据排序权重的每个前缀。 交换的数量由当前分布和目标分布之间的不匹配决定。 

我们按权重对索引进行一次排序。 然后我们在此订单上维护一个 Fenwick 树或 BIT，跟踪当前包含哪些仓位`1`。 每次翻转后，我们更新一个位置并计算有多少个`1`s 应该位于顶部`k`此排序顺序的位置。 不匹配计数直接转化为交换成本，因为每个错放的`1`必须跨越边界移动，并且每次交换都会修复两次反转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q·n·m) | O(n) | 太慢了 |
 | 排序+BIT维护| O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个索引`i`在原始字符串中，计算`w[i]`，子串包含的区间数`i`。 这是通过使用间隔端点上的差异数组来完成的。 这给出了每个字符构成最终连接字符串的次数。 
2. 索引排序`1..n`按递增顺序`w[i]`。 此顺序代表位置`t(s)`从最不重要到最重要。 最大的权重对应于放置一个的位置`1`对字典顺序最有利。 
3. 根据排序顺序构建 Fenwick 树，存储是否`s[i]`目前是`1`。 该结构支持按权重排序的快速前缀和。 
4. 对于每个查询，翻转一位`s`，更新相应位置的Fenwick树。 
5. 每次更新后，计算有多少`1`s 当前存在于字符串中。 让这成为`k`。 在最优配置下，`k`权重最大的头寸`t(s)`必须包含所有`1`s。 
6. 查询 Fenwick 树以计算有多少个`1`s 目前位于顶部`k`排序顺序的位置。 让这成为`good`。 其余`k - good`那些放错地方了。 
7.每一个都放错了地方`1`对应于必须从低权重区域移动到较高权重区域的单位。 每次交换修复两个这样的错位，因此交换的最小数量是`(k - good)`。 

### 为什么它有效

 该结构将问题转化为重新排列多组加权位置。 由于交换允许任意排列，因此只有最终的排列才重要。 字典最大化强制贪婪分配：全部`1`s 必须占据最高权重的槽位。 Fenwick 树维护当前配置与目标分配的偏差程度。 因为每次交换恰好纠正正确和错误一半之间的两次反转，所以不匹配计数完全决定了答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

n, m, q = map(int, input().split())
s = list(input().strip())

L = [0] * n
R = [0] * n

diff = [0] * (n + 2)

for _ in range(m):
    l, r = map(int, input().split())
    diff[l] += 1
    diff[r + 1] -= 1

cur = 0
w = [0] * n
for i in range(1, n + 1):
    cur += diff[i]
    w[i - 1] = cur

order = list(range(n))
order.sort(key=lambda i: w[i])

pos = [0] * n
for i, idx in enumerate(order):
    pos[idx] = i + 1

fw = Fenwick(n)

for i in range(n):
    if s[i] == '1':
        fw.add(pos[i], 1)

total_ones = sum(1 for c in s if c == '1')

for _ in range(q):
    x = int(input()) - 1

    if s[x] == '1':
        fw.add(pos[x], -1)
        s[x] = '0'
        total_ones -= 1
    else:
        fw.add(pos[x], 1)
        s[x] = '1'
        total_ones += 1

    k = total_ones
    if k == 0:
        print(0)
        continue

    good = fw.sum(n) - fw.sum(n - k)
    print(k - good)
```该解决方案首先将每个索引压缩为一个权重，该权重表示它在连接的子字符串中出现的次数。 这将对间隔的结构依赖性转变为每个位置的单个标量。 

按此权重对索引进行排序定义了放置的优先顺序`1`是。 然后，芬威克树会跟踪当前持有哪些位置`1`s，允许对此排序进行快速前缀和后缀查询。 

每个查询都会更新一个位置并调整全局计数。 关键的计算是确定有多少`1`s已经位于顶部`k`加权头寸； 这些位置正确。 其余的必须移动，交换计数直接跟随。

 ## 边缘情况

 关键的边缘情况是所有区间权重都相等。 在这种情况下，任何排列`s`产生相同的结构重要性`t(s)`，所以答案仅取决于字符串是否已经按照位置排序。 该算法可以处理此问题，因为排序顺序退化为任意但固定的索引，并且 Fenwick 计算仍然正确地测量不匹配。 

另一种情况是当个数为零或等于`n`。 该算法立即返回零交换，因为 Fenwick 树中的前缀后缀比较会产生完全对齐或不需要放置移位。
