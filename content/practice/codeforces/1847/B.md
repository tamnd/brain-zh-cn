 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，我们都从一个整数数组开始，并且可以将该数组拆分为连续的段。 每个元素必须恰好属于一个段。 

对于任何段，其值定义为其内部所有数字的按位与。 分区的总成本是这些段值的总和。 任务是找到一个使总成本最小化的分区，并且在实现最小成本的所有分区中，我们必须最大化段的数量。 

关键的困难在于，段的成本不是与元素相加的，而是通过按位与来依赖于所有元素，随着段的增长，它是单调递减的。 

这些约束强制采用线性或近线性解决方案。 所有测试用例的元素总数最多为 200,000 个，因此任何在嵌套循环内重复重新计算段 AND 的方法都会超时。 对每个测试用例的所有子阵列进行二次扫描也是不可能的，因为它会降级到大约$O(n^2)$在最坏的情况下。 

当许多元素相同或出现零时，就会出现微妙的边缘情况。 

例如，如果数组是`[0, 0, 0, 0]`，任何段的 AND 等于 0，因此每个分区的总成本为 0。然后要求纯粹是最大化段的数量，所以答案是 4。 

幼稚的方法可能会错误地尝试贪婪地扩展段，而 AND 不会增加，但会忽略当 AND 已经为 0 时，提前分割永远不会增加成本。 

另一个棘手的情况是当值共享公共位时，AND 会快速稳定。 例如`[7, 3, 1]`很快就会崩溃到 1，除此之外，扩展段也不再改变成本。 

## 方法

 暴力策略会尝试数组的每个可能的分区。 对于每个分区，它会计算每个段的 AND 并对它们求和，然后比较结果。 长度数组的分区数$n$是$2^{n-1}$，因为每个间隙都可以被切割或不被切割。 即使我们增量地计算段 AND，评估所有分区也是指数级的，并且即使对于$n = 30$。 

一个稍微好一点但仍然太慢的想法是动态编程。 让$dp[i]$是前缀的最佳结果$1..i$，并尝试所有先前的分割点$j < i$。 对于每一对，我们计算 AND$[j+1, i]$。 这产生$O(n^2)$每个测试用例的转换，这远远超出了限制。 

关键的观察结果是 AND 运算具有很强的单调性：一旦某个位在段的运行 AND 中变为零，它就永远不会回来。 这意味着当我们扩展一个段时，它的值只会减少或保持不变。 

这导致了关键的简化。 如果我们想最小化段AND的总和，我们应该使每个段的AND尽可能小。 当我们包含尽可能多的元素时，可以实现任何段的最小可能值，但需要权衡：合并段可能会减少段总数，但有可能进一步减少总和。 

重要的认识是，分割只有在不增加总和时才是有益的。 由于 AND 不会随着扩展而增加，因此我们唯一必须合并的时间是在扩展段时严格减少其 AND，从而有益地减少成本贡献。 

我们没有向前思考，而是颠倒了视角：我们想要找到可实现的最小总和。 事实证明，最小总和是通过采用贪婪分区来实现的，在该分区中，我们扩展一个段，直到它的 AND 停止以允许进一步降低成本的方式变化，并且当继续不会以有意义的方式进一步改进 AND 时，我们精确地进行切割。 

更具体地说，我们为当前段维护一个运行的 AND。 当我们扩展它时，一旦 AND 在所有剩余候选上变得稳定（意味着添加更多元素不能以影响最优性的方式进一步减少它），我们就会削减。 这种贪婪分割产生最小和，并且在所有此类最佳分割中，我们希望最大化段数，因此我们总是在不恶化段 AND 值的情况下尽早切割。 

这减少了从左到右扫描的问题，同时保持正在运行的 AND 并在我们确定可以安全切割时重新启动段。

 ## 算法演练

 1.初始化一个运行变量`cur`表示当前段和计数器的 AND`ans`对于段数。 我们从`cur = a[0]`和`ans = 1`。 这反映出数组至少可以是单个段。 
2. 从第二个元素开始从左到右迭代数组。 在每一步中，计算由新元素扩展的当前段的 AND：`new_cur = cur & a[i]`。 
3. 决定是否在该元素之前延伸或剪切。 如果扩展不会以有利于最小化总和的方式减少段值，则我们更愿意在此处进行削减。 在实践中，正确的条件简化为检查继续当前段是否仍然有用； 如果 AND 保持不变，且不会在减少未来捐款方面带来任何好处，我们将最终确定该部分。 
4. 当我们决定削减时，增加`ans`并重置`cur = a[i]`，开始一个新的段。 
5. 否则，我们通过设置来扩展当前段`cur = new_cur`。 
6. 继续此过程直到数组末尾。 

最终值`ans`是所有分区中实现段 AND 的最小可能总和的最大段数。 

### 为什么它有效

 一个段的 AND 只能在我们扩展它时保持不变或减少。 一旦段内的某个位变为零，就无法恢复，因此扩展段只会删除其贡献中的位。 因此，最佳策略完全取决于我们扫描时比特消失的速度。 任何早于必要的切割都有增加总和的风险，任何晚于必要的切割都会减少段的数量，而不会提高总和​​。 贪婪过程确保我们在进一步扩展不能提供严格更好的贡献结构（与最小和划分结构一致）时准确地进行切割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cur = a[0]
        ans = 1
        
        for i in range(1, n):
            new_cur = cur & a[i]
            
            if new_cur == cur:
                # extending does not change AND
                # we can safely start a new segment here
                ans += 1
                cur = a[i]
            else:
                cur = new_cur
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码为当前段维护一个运行 AND。 关键的想法是，当添加新元素不会改变 AND 时，我们处于这样的情况：该段已经相对于先前元素施加的位约束稳定下来。 在这种情况下，开始一个新的段会增加段的数量，而不会恶化任何贡献，这与最大化所有最佳解决方案中的段数量的第二个目标是一致的。 

当 AND 发生变化时，我们仍然处于丢失位的过程中，因此有必要扩展段，以避免过早切割并可能增加总成本。

 ## 边缘情况

 当所有元素都为零时，运行 AND 永远不会改变，因此算法立即在每个位置保持切割，产生最大数量的段。 用于输入`[0, 0, 0]`,`cur`开始于`0`，每一步都会触发`new_cur == cur`条件下，每次增加段计数。 

当所有元素都是相同的非零值时，例如`[5, 5, 5]`，AND 在每次扩展时保持不变。 每个元素都成为自己的分段，产生与最小总和一致的最大分段。 

当值导致快速 AND 崩溃时，例如`[7, 3, 1]`，运行的 AND 迅速降至零，在那之后，分段决策变得灵活，而不会影响成本。 该算法自然地生成与这些转换对齐的段，从而确保正确性，而无需显式跟踪位状态。
