 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一个可以减少其中一些元素的特殊操作。 对于任何选定的一组$k$不同的索引，我们对所选元素求和，取该总和的余数模$k$，然后减少最小的$y$元素除 1，其中$y$就是这个余数。 目标是在应用任意次操作后找到数组的最小可能总和，或者检测总和是否可以无限制地减少。 

数组可以很大，最大可达$10^6$每个测试用例的元素，值最多可达$10^9$。 我们必须考虑最多$10^4$测试用例，但所有测试的元素总数受以下限制$10^6$。 这迫使每个测试用例的解决方案基本上是线性的$n$， 自从$O(n^2)$或者$O(n \log n)$每个测试用例的方法可能是边缘性的，但如果仔细实施的话是可行的。 高元素值妨碍直接模拟操作。 

可能欺骗天真的方法的边缘情况包括所有元素都相等的数组、总和模数的数组$k$为零，并且我们可以重复选择子集以进行无限减少的数组。 例如，一个数组$[1, 2, 3, 4, 5, 6, 7, 8]$可以无限减少，因为总和模某些$k$永远不会为零，而$[3,3,3,3]$根本不能减少，因为任何选择的集合模$k$给出零余数。 

## 方法

 暴力方法会尝试所有可能的大小集$k$重复计算总和，计算余数，并减少相应的元素，直到没有操作更改数组。 这在原则上是正确的，但对于$n = 10^6$，可能的子集数量是天文数字，使得这种方法不可行。 

关键的观察结果是，该操作减少总和的能力完全取决于产生非零余数的所有子集大小的最大公约数 (GCD)。 如果存在任何子集大小$k$使得总和模$k$是非零并且数组足够大，我们可以无限减少。 在实践中，问题简化为检查数组元素的总和是否可以被其大小或其任何因子整除。 如果求和模$n$为零，则总和只能减小到某个最小值； 否则，它可能会无限期地下降。 对于不可能无限减少的数组，最小和是数组的和减去最大的和$n-1$可以在单个操作中减少的元素，归结为将数组的总和减去总和模的余数$n$。

 ## 算法演练

 1. 计算数组的总和。 这表示任何操作之前的当前总和。 
2. 检查数组长度是否$n$是 1。在这种情况下，我们永远无法减少总和，因为对单个元素的操作总是会产生$y = 0$。 返回总和。 
3. 检查数组的和是否能被整除$n$。 如果是，则存在一系列操作可以减少某些元素，但当所有元素达到总和的下限除法时最终会稳定下来$n$。 返回这笔金额。 
4. 如果总和不能被整除$n$，那么总和可以无限减少。 返回-1。 
5. 输出每个测试用例的计算结果。 

为何有效：该操作按所选子集大小的总和余数的比例减少元素。 当总和可以除以$n$，整个数组不存在余数，并且我们不能无限期地减少。 如果总和不能被数组长度整除，则重复运算总是可以产生非零余数，从而使总和无限制地减少。 这个不变量保证了所有测试用例的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        if n == 1:
            print(total)
        elif total % n == 0:
            print(total)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先读取测试用例的数量。 对于每个测试用例，它读取数组大小和元素。 计算数组的总和。 对于单元素数组，总和不能更改。 如果总和可以被长度整除，则不可能无限减少，并且我们打印总和。 否则，总和会无限减少，因此我们打印 -1。 快速 I/O 避免了大输入量的瓶颈。

 ## 边缘情况

 对于单元素数组，例如`[100]`，总和仍为 100，因为该运算无法有意义地应用。 对于除以长度有余数的数组，例如`[1,2,3]`，总和可以无限减少，因为我们总是可以选择子集来进一步减少总和。 对于所有元素相等且总和可被长度整除的数组，例如`[3,3,3,3]`，没有任何操作可以减少总和，并且算法正确地输出初始总和。 该实现直接检查这些条件，确保所有边缘情况的正确性。
