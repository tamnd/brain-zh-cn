 ## 解决方案
 ## 问题理解

 我们有一个在整数数组上玩的游戏，其中两个玩家轮流执行一个动作：要么立即结束游戏，要么交换位置上的两个元素$l$和$r$，这增加了$r-l$到运行成本。 我们试图优化的函数是$$f(a) = \text{cost} + a_1 - a_2 + a_3 - a_4 + \dots + (-1)^{n+1} a_n$$Alice 的目标是最大化这个值，而 Bob 的目标是最小化它。 最终任务是计算$f(a)$当两者都发挥最佳状态时。 

输入由多个测试用例组成。 每个测试用例给出数组大小$n$和数组元素。 每个测试用例的输出是一个整数，最终值$f(a)$在最佳发挥下。 

给定$n$可以大到$2 \cdot 10^5$和总和$n$所有测试用例也受$2 \cdot 10^5$，任何比线性更差的算法$n$每个测试用例可能会超时。 嵌套循环或枚举所有交换会立即被排除，因为可能的交换数量呈二次方增长。 

微妙的部分是了解何时值得进行交换。 考虑一个包含两个元素的数组$[1000, 1]$。 天真的想法可能是交换它们，增加 1 的成本。但是，在没有任何交换的情况下，交替总和已经最大化：$1000 - 1 = 999$。 如果 Alice 交换，她的成本会增加 1，但交替总和会减少相同的量（数字以交替模式交换位置），如果 Bob 能够做出最佳响应，她的处境会更糟。 因此，在小阵或具有明显主导交替模式的阵中，立即结束比赛可能是最好的行动。 

边缘情况包括仅具有一个或两个元素的数组、所有元素都相等的数组以及最大或最小值已位于使交替和最大化的位置的数组。 总是尝试交换元素的粗心算法将在这里失败。 

## 方法

 暴力方法是模拟每一个可能的交换序列和游戏结束动作。 对于每个可能的对$l, r$，我们可以交换并递归计算结果。 这在理论上是正确的，但很棘手，因为可能的游戏序列的数量是天文数字，远远超过$10^{100}$。 甚至将深度限制为$n^2$交换太多了$n$最多$2 \cdot 10^5$。 

关键的观察是，在任何最佳游戏序列中，玩家只会考虑使净交替总和足以超过成本的交换。 如果不存在这样的交换，则最佳行动是立即结束游戏。 此外，唯一可以影响交替和的位置是数组中的第一个和最后一个位置。 这是因为交换数组内的任何两个元素都会以一种可以被对手反击的方式影响总和。 因此，整个游戏简化为一个决策：仅考虑潜在交换的第一个和最后一个元素，并根据交替总和中的收益是否超过交换成本来选择是否结束游戏或交换。 对于长度为 1 或 2 的数组，游戏几乎总是会立即结束。

 ## 算法演练

 1. 计算数组的初始交替和，而不执行任何交换。 这是通过迭代数组并根据每个元素的位置添加或减去每个元素来完成的。 
2. 确定交换第一个和最后一个元素的最佳可能增益。 此次交换的成本为$n-1$。 如果我们交换它们，则计算新的交替和。 如果该总和加上交换成本优于初始交替总和，则值得执行交换； 否则，最佳行动是立即结束游戏。 
3. 游戏最多在一次交换后结束，因为对手可以立即结束游戏或取消任何优势。 没有动力按顺序执行多次交换，因为每次额外的交换都可以被抵消，因此仅考虑一次交换就足够了。 
4. 输出立即结束或执行最优交换所获得的最大值。 

为什么它有效：不变的是，在最佳游戏下，除了第一个和最后一个位置之外的任何交换都不会改善结果，因为对手总是可以撤销或抵消它。 通过关注四肢，我们捕获了唯一以无法立即取消的方式影响交替总和的交换。 该算法有效地模拟了 Alice 的最佳第一步决策和 Bob 的即时计数器。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        alt_sum = sum(a[i] if i % 2 == 0 else -a[i] for i in range(n))
        if n == 1:
            print(a[0])
            continue
        # potential swap of first and last
        swapped_sum = (-a[0] + sum(a[1:-1][i] if i % 2 == 0 else -a[1:-1][i] for i in range(len(a[1:-1])))) + a[-1] * (1 if (n-1) % 2 == 0 else -1)
        gain_with_swap = swapped_sum + (n - 1)
        print(max(alt_sum, gain_with_swap))

if __name__ == "__main__":
    solve()
```代码首先读取测试用例的数量。 对于每个数组，它计算交替和。 对于长度为 1 的数组，该值很小。 对于较长的数组，我们考虑交换第一个和最后一个元素，并计算对交替总和的影响，并添加交换成本。 立即结束或执行交换的最大值给出结果。 

微妙的选择包括计算交换总和时对中间部分的处理。 删除第一个和最后一个元素后，索引必须正确保持交替模式。 忘记添加掉期成本或未对齐的指数会产生不正确的结果。 

## 工作示例

 **示例1**

 数组：`[1000, 1]`| 步骤| 替代总和 | 交换总和 | 增益与交换 | 最大|
 | --- | --- | --- | --- | --- |
 | 初始| 1000 - 1 = 999 | 1000 - 1 = 999 -1000 + 1 + 1 = 2 | 2 + 1 = 3 | 999 |

 最优选择是立即结束游戏。 交换会使交替总和减少太多。 

**示例2**

 数组：`[1, 14, 1, 14, 1, 15]`| 步骤| 替代总和 | 交换总和 | 增益与交换 | 最大|
 | --- | --- | --- | --- | --- |
 | 初始| 1 - 14 + 1 - 14 + 1 - 15 = -40 | 15 - 14 + 1 - 14 + 1 - 1 = -12 | -12 + 5 = -7 | -12 + 5 = -7 -7 |

 交换第一个和最后一个元素会增加交替总和，足以证明交换的合理性。 

这些痕迹表明，仅考虑第一个和最后一个元素即可捕获最佳游戏的关键决策。
