 ## 解决方案
 ## 问题理解

 我们有一排`n`桩。 每堆包含`1`或者`2`石头，因为这是简单的版本并且`m ≤ 2`。 

游戏不会修改桩值。 玩家仅移除桩。 在任何时刻，当前堆都会从左到右重新索引，并且移动包括删除当前索引属于固定的好索引集的堆。 

爱丽丝先行动，并希望最终幸存的一堆价值尽可能大。 鲍勃希望它尽可能小。 

对于每种可能的桩值分配，我们都会以最佳方式玩游戏并获得最后剩余桩的值。 任务是将所有配置的值相加。 

首先值得注意的是，游戏机制仅取决于位置，而不取决于堆中写入的实际数字。 仅当我们评估最终的生存位置时，这些值才重要。 

约束条件`n ≤ 20`是关键。 游戏的状态可以用幸存位置的集合来表示，并且`2^20`大约是一百万。 该声明甚至保证总和`2^n`所有测试用例最多是`2^20`，这强烈建议使用位掩码动态编程解决方案。 

一个常见的错误是尝试直接计算哪个原始位置幸存。 该位置取决于最佳玩法并在每次重新索引后发生变化。 该游戏是动态变化序列的极小极大游戏，而不是简单的消除过程。 

考虑输入```
3 2
2
1 2
```如果桩是`[2,1,2]`，爱丽丝可以移除第二堆，留下`[2,2]`。 然后鲍勃必须移除第一堆，最终值为`2`。 任何尝试为游戏状态分配固定“生存位置”的方法都会错过这种交互。 

另一个微妙的情况是当`n = 1`。```
1 2
1
1
```根本没有任何动作。 唯一的一堆立即幸存。 Any DP that assumes at least one deletion would produce the wrong result.

 ## 方法

 最直接的暴力就是枚举所有`m^n`配置。 对于每种配置，我们可以在博弈树上运行极小极大搜索并确定最终值。 

为了`n = 20`，甚至配置数量已经`2^20 ≈ 10^6`，并且每种配置都需要解决一个游戏。 这太贵了。 

关键的观察是游戏仅比较桩值。 自从`m ≤ 2`, 每堆要么是`1`或者`2`。 

假设我们将配置编码为二进制序列：```
1 stone -> 0
2 stones -> 1
```现在该配置的最终答案是`0`或者`1`在这个二元世界里。 我们只需要知道Alice能否迫使最后幸存的一堆成为`1`。 

这将问题转化为二进制序列上的纯游戏。 

状态就是当前的二进制序列。 当一堆被移除时，一点就会消失。 自从`n ≤ 20`，每个长度的序列`ℓ`可以用位掩码表示`ℓ`位。 

状态的 minimax 值也是二进制的：```
0 = Bob can force the final bit to be 0
1 = Alice can force the final bit to be 1
```这导致了所有长度的所有掩码上的 DP。 

在我们知道长度之后-`n`掩码评估为`1`，计算配置变得容易。 每个二进制掩码都对应​​于一种配置，因为值仅`1`和`2`。 

最终堆值等于：```
1 + (game result bit)
```所以```
sum(final values)
=
(number of configurations)
+
(number of masks whose game result is 1)
```为了`m = 2`，配置数量为`2^n`。 

为了`m = 1`，每个配置都完全由 1 组成，所以答案很简单`1`。 

DP 一次性处理所有掩码，并保证总和`2^n`是有界的。 这产生了一个可接受的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 配置和游戏状态均呈指数增长 | 指数| 太慢了|
 | 最佳位掩码 DP | O(n·2^n) | O(n·2^n) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 ### 步骤 1

 处理特殊情况`m = 1`。 

每堆都包含一块石头，因此每个配置都是相同的，最终的答案总是`1`。 

### 步骤 2

 对于`m = 2`，将每个配置表示为二进制掩码。 

少量`i = 0`意味着该堆包含`1`。 

少量`i = 1`意味着该堆包含`2`。 

### 步骤 3

 为每个序列掩码定义一个 DP 值。`dp[mask]`代表Alice是否可以强制最后的幸存位`1`从那个状态。 

序列的长度由当前存储在掩码层中的位数决定。 

### 步骤 4

 初始化长度`1`。 

如果唯一剩下的位是`0`，结果是`0`。 

如果唯一剩下的位是`1`，结果是`1`。 

### 步骤 5

 工艺长度从`2`最多`n`。 

对于长度的掩模`ℓ`，确定轮到谁了。 

确切地`n - ℓ`删除已经发生了。 

如果`n - ℓ`是偶数，轮到爱丽丝了。 

如果`n - ℓ`奇怪的是，轮到鲍勃了。 

### 步骤 6

 生成每个合法的子状态。 

对于每一个好的指标`c`和`c ≤ ℓ`，删除`c`当前掩码中的第 - 位。 

这会产生一个长度的掩码`ℓ - 1`。 

### 步骤 7

 应用极小极大。 

如果轮到 Alice，则状态值是所有子值的或。 

爱丽丝只需要一步就能获胜。 

如果轮到 Bob，则状态值是所有子值的 AND。 

鲍勃选择了对爱丽丝来说最差的一步。 

### 步骤 8

 计算完所有长度的掩码后`n`,统计有多少个有DP值`1`。 

设这个数为`win`。 

答案是```
2^n + win
```取模`10^9 + 7`。 

### 为什么它有效

 一个状态的DP值正是该游戏位置的极小极大值。 

基本情况是正确的，因为当只剩下一堆时，最后一位就已经知道了。 

对于任何较大的国家来说，每一次法律行动都会产生一个较小的国家。 如果爱丽丝移动，她会选择最大化结果的孩子，这正是二元结果的“或”。 如果鲍勃移动，他会选择最小化结果的孩子，这正是二元结果的与。 

通过对序列长度的归纳，每个 DP 值都等于该状态的真实博弈论值。 

长度-`n`掩码评估为`1`恰好当相应的配置以 value 结束时`2`在最佳发挥下。 将此类掩模的数量添加到基线贡献中`1`从每个配置中给出所需的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        k = int(input())
        good = list(map(int, input().split()))

        if m == 1:
            print(1)
            continue

        dp = [None] * (n + 1)

        dp[1] = [0, 1]

        for length in range(2, n + 1):
            size = 1 << length
            cur = [0] * size

            alice_turn = ((n - length) & 1) == 0
            valid_good = [x for x in good if x <= length]

            for mask in range(size):
                if alice_turn:
                    val = 0
                    for pos in valid_good:
                        idx = pos - 1

                        low = mask & ((1 << idx) - 1)
                        high = mask >> (idx + 1)
                        child = low | (high << idx)

                        val |= dp[length - 1][child]
                        if val:
                            break
                    cur[mask] = val
                else:
                    val = 1
                    for pos in valid_good:
                        idx = pos - 1

                        low = mask & ((1 << idx) - 1)
                        high = mask >> (idx + 1)
                        child = low | (high << idx)

                        val &= dp[length - 1][child]
                        if not val:
                            break
                    cur[mask] = val

            dp[length] = cur

        win = sum(dp[n])
        ans = ((1 << n) + win) % MOD
        print(ans)

solve()
```DP 按序列长度组织。`dp[length][mask]`存储该精确序列的极小极大结果。 

用于删除一位的表达式是实现中最微妙的部分。 我们将掩码分为删除位置之前的位和删除位置之后的位。 上半部分右移一位并合并回来。 

另一个细节是转弯检测。 长度状态`length`正好出现在`n - length`删除。 由于爱丽丝先移动，因此该数字的奇偶性唯一确定轮到谁了。 

内存使用量仍然很小，因为存储的状态总数为```
2 + 4 + 8 + ... + 2^n
=
2^(n+1) - 2
```低于 200 万时`n = 20`。

 ## 边缘情况

 ### 只有一堆

 输入：```
1 2
1
1
```DP从长度开始`1`，因此不执行任何转换。 

这两个面具是：```
0 -> value 1
1 -> value 2
```答案是：```
1 + 2 = 3
```该算法自然地处理这个问题，因为基础层已经代表完成的游戏。 

### 所有桩都等于一

 输入：```
3 1
2
1 3
```只有一种配置：```
[1,1,1]
```无论游戏如何进行，最终的堆值为`1`。 

算法立即返回`1`什么时候`m = 1`，避免不必要的DP工作。 

### 随着序列缩小，好的索引会消失

 输入：```
3 2
2
1 3
```当当前长度变为`2`， 指数`3`不再有效。 

该实现显式地仅保留满足以下条件的良好索引：```
good_index <= current_length
```所以每个生成的动作在当前状态下都是合法的。 这避免了访问不存在的位置并且完全符合游戏规则。
