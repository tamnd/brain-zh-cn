 ## 解决方案
 ## 问题理解

 我们有一个序列`n`桩。 每堆石子的数量可以是任意整数`1`到`m`。 

游戏本身并不依赖于移动时的石头值。 玩家只能选择要删除的位置。 每次，当前序列都会被重新索引，并且玩家只能删除其索引属于固定的好索引集的位置。 爱丽丝首先移动并希望最后幸存的一堆石头有尽可能多的。 鲍勃想要相反的结果。 

对于桩值的一种特定配置，最佳游戏决定了单个幸存的原始位置。 设其值为`x`。 

任务不是解决一场游戏。 我们必须总结`x`在堆值的所有可能分配中，每个堆独立地选择一个值`[1,m]`。 

首先引人注目的是`n ≤ 20`。 大小的状态空间`2^n`是现实的，该声明甚至保证了`2^n`所有测试用例不超过`2^20`。 

第二个重要的界限是`m ≤ 10^6`。 Enumerating all values or all configurations is impossible. 有`m^n`配置，即使对于中等输入来说也是天文数字。 

游戏结构也很不寻常。 移动永远不取决于实际的桩值。 它们仅取决于当前的职位。 这表明游戏可以独立于数值进行分析，然后与计数参数相结合。 

一个常见的错误是尝试确定哪个原始位置幸存下来，然后计算该位置的配置。 不同的价值分配可以改变游戏过程中的最佳决策。 

考虑：```
n = 2
good = {1}
```唯一合法的举动会删除第一堆，因此第二堆始终会幸存。 答案很简单。 

现在考虑一个更大的游戏，爱丽丝可以在多个删除之间进行选择。 哪种移动是最佳取决于值。 生存位置并不是预先确定的。 

另一个微妙的情况是当`m = 1`。```
n = 20
m = 1
```每堆恰好包含一颗石头。 每个配置都有最终值`1`，与游戏无关。 答案很简单`1`。 

尝试使用阈值计数的解决方案仍然必须干净地处理此边界。 

## 方法

 让我们首先想象一下暴力解决方案。 

对于桩值的每种配置，我们模拟极小极大游戏并获得最终值。 然后我们对所有配置进行求和。 

有`m^n`配置。 即使是为了`n = 20`和`m = 2`，已经超过一百万个州。 对于硬版本来说，`m`达到一百万，所以暴力破解是完全没有希望的。 

关键的观察是游戏机制仅取决于值之间的比较。 

假设我们固定一个阈值`T`。 将每个桩值替换一点：```
0 if value < T
1 if value ≥ T
```现在问一个不同的问题：```
Can Alice force the final surviving pile to have bit 1?
```这不再是一个数值优化问题。 它变成了二进制序列上的纯粹的赢/输游戏。 

自从`n ≤ 20`，每个长度的二进制序列`n`可以表示为位掩码。 我们可以在 mask 上构建 minimax DP。 

一旦我们知道哪些面具对爱丽丝有利，我们就回到原来的问题。 

对于固定阈值`T`，每堆独立贡献：```
value < T      : T - 1 choices
value ≥ T      : m - T + 1 choices
```因此，对于包含`j`个，产生该掩码的原始配置的数量等于```
(T-1)^(n-j) · (m-T+1)^j
```如果爱丽丝能强行完成最后一点`1`从该掩码中，每个相应的配置都会对最终值至少为`T`。 

这将原始的优化问题转化为至少具有最终值的计数配置`T`。 

计算后```
F(T) = number of configurations whose final value is at least T
```我们使用标准恒等式恢复最终值的总和```
count(value = T) = F(T) - F(T+1)
```和```
answer = Σ T · count(value = T).
```指数部分仅取决于`n`，而大值`m`通过组合计数来处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(m^n · 游戏) | 巨大| 太慢了|
 | 最佳 | O(nk2^n + nm) | O(nk2^n + nm) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 ### 二进制掩码上的 DP

 对于二进制序列，定义：```
dp[len][mask][0]
```至于爱丽丝是否可以强制最后一位`1`。 

相似地，```
dp[len][mask][1]
```当轮到鲍勃时代表同样的问题。 

表示的序列为`mask`有长度`len`。 

### 过渡

 如果我们删除`p`-th 位置，我们得到一个更短的掩模。 

调用这个操作：```
delete(mask, p)
```爱丽丝希望至少有一步能够成功：```
dp[len][mask][0]
    = OR over legal deletions
      dp[len-1][new_mask][1]
```鲍勃希望爱丽丝的所有结果都失败，所以：```
dp[len][mask][1]
    = AND over legal deletions
      dp[len-1][new_mask][0]
```等价地，将 Bob 的状态初始化为`1`并反复取最小值。 

### 基本情况

 当只剩下一堆时：```
dp[1][0][0] = dp[1][0][1] = 0
dp[1][1][0] = dp[1][1][1] = 1
```剩下的部分本身就是答案。 

### 计算获胜面具

 构建长度 DP 后`n`，每个面具都带有```
dp[n][mask][0] = 1
```是获胜阈值配置。 

让```
cnt(mask) = number of ones in mask.
```我们只关心面具里有多少个。 

创造：```
sum[j]
```= 获胜面具的数量`j`那些。 

### 计算 F(T)

 对于阈值`T`:

 一个获胜的面具`j`对应于```
(T-1)^(n-j) · (m-T+1)^j
```原始配置。 

因此```
F(T)
=
Σ sum[j]
  · (T-1)^(n-j)
  · (m-T+1)^j
```### 恢复精确值

 我们知道：```
F(T) = count(final value ≥ T)
```所以：```
count(final value = T)
=
F(T) - F(T+1)
```最后：```
answer
=
Σ T · (F(T)-F(T+1))
```取模`10^9+7`。 

### 为什么它有效

 阈值变换准确地保留了决定最终值是否至少为所需的信息`T`。 

按位替换值后，最后一位`1`意味着最终堆值至少为`T`。 极小极大游戏仅取决于这些位，而不取决于确切的大小。 

DP正确计算出Alice是否可以强制生存`1`因为每个州都会考虑所有合法的删除，并根据轮到谁来交替使用 OR 和 AND。 

一旦获胜掩码已知，每个原始配置都会贡献`F(T)`正是在其阈值掩模获胜时。 每个掩码的分配计数仅取决于标记的位置数量`1`，得出上面的组合公式。 

因此`F(T)`恰好是至少具有最终值的配置数量`T`，并且伸缩转换重建最终值的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7
MAXN = 20

popcount = [0] * (1 << MAXN)
for i in range(1, 1 << MAXN):
    popcount[i] = popcount[i >> 1] + (i & 1)

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        k = int(input())
        good = [x - 1 for x in map(int, input().split())]

        if m == 1:
            print(1)
            continue

        dp_prev_a = [0, 1]
        dp_prev_b = [0, 1]

        for length in range(2, n + 1):
            size = 1 << length

            dp_a = [0] * size
            dp_b = [1] * size

            for mask in range(size):
                alice = 0
                bob = 1

                for p in good:
                    if p >= length:
                        break

                    low = mask & ((1 << p) - 1)
                    high = mask >> (p + 1)
                    nxt = low | (high << p)

                    alice |= dp_prev_b[nxt]
                    bob &= dp_prev_a[nxt]

                dp_a[mask] = alice
                dp_b[mask] = bob

            dp_prev_a = dp_a
            dp_prev_b = dp_b

        win_count = [0] * (n + 1)

        for mask in range(1 << n):
            if dp_prev_a[mask]:
                win_count[popcount[mask]] += 1

        ans_ge = [0] * (m + 2)

        for tval in range(1, m + 1):
            a = tval - 1
            b = m - tval + 1

            cur = 0
            for ones in range(n + 1):
                cur += (
                    pow(a, n - ones, MOD)
                    * pow(b, ones, MOD)
                    % MOD
                    * win_count[ones]
                )
                cur %= MOD

            ans_ge[tval] = cur

        answer = 0

        for tval in range(1, m + 1):
            exact = (ans_ge[tval] - ans_ge[tval + 1]) % MOD
            answer = (answer + tval * exact) % MOD

        print(answer)

solve()
```DP是通过增加序列长度来构建的。 转换会删除一个合法位置并将剩余位压缩为更短的掩码。 

两个数组对应轮到谁了。 Alice 使用逻辑或，因为她需要成功的一步。 鲍勃使用逻辑与，因为只有鲍勃选择的每一步仍然会成功，爱丽丝才会成功。 

游戏DP结束后，实际值就从问题中消失了。 我们只需要给定数量的获胜面具的数量。 这种压缩使得硬版本变得可行。 

最后的计数阶段评估每个阈值`T`并使用快速模幂进行组合计数。

 ## 边缘情况

 考虑：```
1
5 1
1
1
```每堆恰好包含一颗石头。 阈值计数将为每个配置产生相同的结果，因此实现立即返回`1`。 仅有一个有效配置，其最终值为`1`。 

考虑：```
1
1 5
1
1
```游戏永远不会开始，因为只有一堆存在。 DP 基本案例直接处理这个问题。 对于阈值`T`，正好有`5-T+1`有效值。 将得到的精确计数相加得出`15`。 

考虑：```
1
2 3
1
1
```唯一合法的举动会移除第一堆，因此第二堆总是会幸存。 DP发现只有第二位为的掩码`1`正在获胜。 然后计数阶段重建最终值的精确分布并产生`18`，匹配样本。
