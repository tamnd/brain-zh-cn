 ## 解决方案
 ## 问题理解

 我们得到了一个玩具，由以下部分组成`n`连接的部件`m`绳索。 每根绳子连接两个不同的部分，并且没有一对部分之间有多于一根绳子。 各部分`i`有相关的能源成本`v[i]`。 孩子一次取下一个零件。 移除一个部件的成本是移除时仍然存在的相邻部件的能量值之和。 我们的任务是确定孩子移除所有部件所需花费的最小总能量。 

输入大小适中，`n`最多 1000 个并且`m`最多 2000。这意味着 O(n^2) 解决方案是可行的，但任何 O(n!) 式的解决方案（例如尝试移除顺序的所有排列）是完全不切实际的。 我们需要一种算法来避免显式检查每个可能的序列。 当一个部件具有非常高的能量但与低能量部件连接时，就会出现不明显的边缘情况。 如果我们太早移除它，总成本就会不必要地增加。 当图表断开连接时，会出现另一种边缘情况：孤立组件中的各个部分仅在其组件内进行交互，简单的求和可能会错误计算贡献。 

例如，考虑三个具有值的部分`[1, 100, 1]`连接成一条线：`1-2-3`。 删除第 2 部分的第一成本`1+1 = 2`。 首先删除 1 或 3 个会导致`100`成本。 这里的最佳顺序是最后删除高能部分，这与天真的“首先删除最大的”策略相反。 

## 方法

 暴力解决方案将枚举所有`n!`移除订单，计算每个的成本，并返回最小值。 这是正确的，但即使对于`n = 10`。 和`n = 1000`，我们不能尝试这样做。 

关键的观察结果是，移除部件的成本仅取决于其当前的邻居。 如果一个部分具有高能量`v[i]`，当它仍然有许多具有高的邻居时将其删除`v[j]`很贵。 相反，首先移除低能量邻居会减少对未来移除的贡献。 这相当于“总是删除与剩余部分相连的最小可用部分”的贪婪想法，但我们必须将其概括为一个图：每根绳子都贡献`min(v[i], v[j])`正好一次达到总能量。 这是因为对于每根绳子，其两个端点中较小的一个将被删除，而另一个端点仍然存在，精确地添加`min(v[i], v[j])`到总成本。 因此，问题就简化为求和`min(v[i], v[j])`覆盖所有边缘。 

暴力破解会失败，因为它试图显式地计算序列。 认识到每条边仅贡献`min(v[i], v[j])`让我们在线性时间内计算关于边数的答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有排列）| O(n!) | O(n + m) | 太慢了 |
 | 贪婪边缘贡献 | O(米) | O(n + m) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`，零件数量和绳索数量，后面是数组`v`部分能量值。 
2. 初始化变量`total_energy`为零。 这将积累最小的能量。 
3. 迭代每个`m`绳索。 用于绳索连接部件`x`和`y`， 添加`min(v[x], v[y])`到`total_energy`。 

原因是每根绳索在移除序列期间仅贡献一次其最小端点值。 
4.处理完所有绳索后，打印`total_energy`。 该值表示移除所有部件所需的最小能量。 

工作原理：每根绳子通过其较小的端点都会对成本产生一次影响，因为该端点将被删除，而另一个端点仍然存在。 对所有边缘求和即可捕获总能量，而无需显式模拟去除序列。 不存在重复计数，并且每条边的贡献都是必要的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
v = list(map(int, input().split()))

total_energy = 0
for _ in range(m):
    x, y = map(int, input().split())
    total_energy += min(v[x-1], v[y-1])

print(total_energy)
```代码首先读取输入。 名单`v`是零索引的，所以当读取边缘时，我们减去 1`x`和`y`正确索引。 边缘上的循环直接累加`min`的两个连接部分。 除了存储数据之外，不需要额外的数据结构`v`数组和运行总计。

 最终的total_energy为40，与预期输出相符。 

对于示例 2，假设所有部分的值为 100 并且完全连接：

 | 步骤| 边缘| v[x-1] | v[x-1] v[y-1] | min(v[x-1], v[y-1]) | min(v[x-1], v[y-1]) | 总能量 |
 | --- | --- | --- | --- | --- | --- |
 | 每条边贡献 100 | - | - | - | - | 总和 = 边数 * 100 |

 这证实了算法正确处理统一值。

 | 测量| 复杂性 | 说明|

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    v = list(map(int, input().split()))
    total_energy = 0
    for _ in range(m):
        x, y = map(int, input().split())
        total_energy += min(v[x-1], v[y-1])
    return str(total_energy)

# provided samples
assert run("4 3\n10 20 30 40\n1 4\n1 2\n2 3\n") == "40", "sample 1"
assert run("3 3\n100 100 100\n1 2\n2 3\n1 3\n") == "300", "sample 2"

# custom cases
assert run("1 0\n5\n") == "0", "single part, no edges"

assert run("4 0\n5 6 7 8\n") == "0", "no edges"
assert run("5 4\n1 2 3 4 5\n1 2\n2 3\n3 4\n4 5\n") == "10", "chain of 5 nodes"

 ## 边缘情况

 当`m = 0`，算法正确返回 0，因为没有边缘，因此没有能量贡献。 例如，输入`1 0\n5\n`产生 0。当所有节点具有相等的值时，每条边只贡献该值一次。 例如，`3 3\n100 100 100\n1 2\n2 3\n1 3\n`结果总能量`300`，它与最小端点贡献的预期计数相匹配。 链、星形和断开连接的图都可以无缝处理，因为每条边都是独立处理的并且只做出贡献`min(v[i], v[j])`。
