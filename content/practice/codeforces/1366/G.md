 ## 解决方案
 ## 问题理解

 我们得到一个字符串`s`由小写字母和点组成。 如果我们从左到右处理这个字符串，每个字母都会被推入堆栈，每个点都会删除当前的顶部字符。 功能`f(s)`以字符串形式返回最终堆栈内容。 如果堆栈为空时出现点，则执行会崩溃。 

我们可以删除任意字符`s`，同时保留剩余字符的相对顺序。 我们的目标是删除尽可能少的字符，以便可以在不崩溃的情况下处理结果字符串，并且其最终堆栈内容准确无误`t`。 

查看问题的一种有用方法是将其视为堆栈操作序列的编辑问题。 字母对应于推送。 点对应于流行音乐。 我们必须选择一个操作子序列，其堆栈演化在目标字符串处结束`t`。 

长度为`s`可以达到 10000。任何显式探索字符子集的算法都是没有希望的。 即使是涉及所有位置的动态规划状态`s`所有可能的堆栈内容都会爆炸。 由于限制为 10000 个字符，我们的目标应该是大致`O(n²)`或更好。 官方解决方案运行在`O(|s||t|)`，这大约是`10^8`如果天真地实现，则处于最坏情况下的状态，因此我们需要更紧凑的状态表示和仔细的转换。 

一些边缘情况会使朴素的推理失败。 

考虑：```
s = "a."
t = ""
```字母和点相互抵消。 最佳答案是零删除。 仅尝试匹配最终结果中出现的字母的解决方案将错误地删除这两个字符。 

考虑：```
s = ".a"
t = "a"
```第一个点会崩溃。 由于禁止崩溃，因此必须删除该点。 答案是一。 仅仅检查最终堆栈内容是不够的。 

考虑：```
s = "ab.."
t = ""
```最终结果是空的，但是两次推送都是需要的，因为这些点需要去除一些东西。 将点视为独立删除会错过这种相互作用。 

关键的困难在于字母可能会保留到最终答案中，或者它们的存在可能只是为了稍后被某个选定的点删除。 

## 方法

 暴力解决方案将选择以下序列`s`，模拟出栈过程，检查结果是否等于`t`。 由于每个字符都可以保留或删除，因此有`2^|s|`子序列。 即使是为了`|s| = 100`，这已经不可能了。 

下一个自然的想法是动态规划。 扫描时`s`，我们想知道有多少`t`已经建成。 不幸的是，堆栈操作引入了另一个维度：可能仍然需要不属于最终答案的字母，因为未来的点需要弹出一些东西。 

解决这个问题的观察结果是，只有最终的堆栈内容才重要。 每个幸存的角色`t`必须对应于某个字母`s`。 不属于最终答案的字符的行为类似于临时堆栈元素，最终会被匹配的点删除。 

我们不是跟踪整个堆栈，而是跟踪有多少个字符`t`当前在堆栈中表示。 剩余的堆栈元素，那些不属于最终答案的元素，可以通过计数来总结。 

这导致了动态规划公式，其中每个状态描述：

 - 有多少个字符`t`已经匹配完毕，
 - 堆栈中当前存在多少个额外的临时字符。 

过渡结构非常紧凑，因为点总是删除最近添加的堆栈元素。 可以根据状态确定该元素是属于未来答案还是临时答案。 

生成的 DP 运行在`O(|s||t|)`时间并在限制范围内舒适地适应。

 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最佳DP | O( | s | |

 ## 算法演练

 让`m = |t|`。 

定义一个 DP 状态，其中`dp[j]`表示处理某些前缀后当前存在的临时堆栈字符的最大数量`s`，同时已经匹配第一个`j`的字符`t`。 

值为`-∞`意味着该状态是不可能的。 

我们处理`s`从左到右。 

1. 初始化`dp[0] = 0`。 

没有字符`t`尚未匹配，堆栈为空。 
2.当前字符为字母时`c`，创建一个新的DP数组。 

我们有两个选择。 

要么删除这封信，保持状态不变。 

或者保留它。 
3. 如果我们保留这封信并且`j < m`和`c == t[j]`，我们可以用它作为最终答案的下一个字符。 

匹配的前缀长度变为`j + 1`。 
4. 如果我们保留该字母但不使用它进行匹配，它就成为临时堆栈元素。 

临时计数加一。 
5、当前字符为点时，再次创建新的DP数组。 

我们可以删除该点并保持状态不变。 
6. 如果我们保留这个点，它一定会弹出一些东西。 

如果临时计数为正，我们删除一个临时元素。 
7. 否则，pop 必须删除最近匹配的字符`t`。 

这只有在以下情况下才可能实现：`j > 0`。 

匹配的前缀长度减一。 
8. 每个保留的字符都为所选子序列贡献一个字符。 

DP存储可以实现每种状态的最大保留字符数。 
9.处理完所有字符后，正是想要的状态`j = m`和临时计数`0`。 

保留字符的最大数量给出了最长的有效子序列。 
10.答案是$$|s| - \text{(maximum kept characters)}$$因为必须删除所有其他字符。 

### 为什么它有效

 每时每刻，堆栈都可以分为两部分。 底部部分对应最终字符串的前缀`t`。 顶部部分由临时字符组成，最终将被删除。 临时角色的确切身份并不重要，重要的是目前存在多少个角色。 

DP 不变量是状态完全捕获与未来决策相关的所有内容：匹配的前缀长度和临时元素的数量。 每个合法的堆栈操作都会像真实堆栈一样精确地转换这些数量。 由于每个字符都可以独立保留或删除，因此 DP 会探索所有有效的子序列。 最大化保留字符的数量会产生最长的有效子序列`t`，这相当于最小化删除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    m = len(t)

    NEG = -10**9

    dp = [NEG] * (m + 1)
    dp[0] = 0

    for ch in s:
        ndp = dp[:]

        if ch != '.':
            for j in range(m, -1, -1):
                if dp[j] < 0:
                    continue

                # keep as temporary character
                ndp[j] = max(ndp[j], dp[j] + 1)

                # use as next character of t
                if j < m and ch == t[j]:
                    ndp[j + 1] = max(ndp[j + 1], dp[j] + 1)

        else:
            for j in range(m + 1):
                if dp[j] < 0:
                    continue

                # keep dot and pop matched character
                if j > 0:
                    ndp[j - 1] = max(ndp[j - 1], dp[j] + 1)

            dp = ndp
            continue

        dp = ndp

    longest = dp[m]
    print(len(s) - longest)

if __name__ == "__main__":
    solve()
```实现直接遵循DP。`dp[j]`存储所有方法中保留的字符的最大数量，以达到准确的状态`j`的字符`t`当前在堆栈中表示。 

对于一个字母，我们可以删除它，保留它作为临时字符，或者将它作为下一个匹配的字符`t`。 保留一个字符会使子序列长度增加一。 

对于一个点，删除它会使状态保持不变。 保留它对应于弹出操作。 在压缩状态表示中，弹出操作会删除一个匹配的字符，这通过从`j`到`j - 1`。 

字母上的降序循环可防止新更新的状态在同一迭代期间被重复使用。 这是标准的 0/1 转换模式。 

最终的答案是从代表完整目标字符串的状态中获得的。 由于 DP 最大化了保留的字符数，因此从`|s|`给出最小删除数。

 ## 边缘情况

 考虑：```
s = ".a"
t = "a"
```第一个点将从空堆栈中弹出。 任何有效的解决方案都必须将其删除。 DP 绝不允许从状态进行弹出转换`j = 0`，所以唯一可行的路径是删除点并保留字母。 答案就变成了`1`。 

考虑：```
s = "ab.."
t = ""
```保留所有四个字符是有效的。 堆栈演变为：```
[]
[a]
[a,b]
[a]
[]
```DP 保留两个字母和两个点，实现子序列长度为 4。 答案是`0`。 

考虑：```
s = "a."
t = ""
```字母和点相互抵消。 尝试仅匹配最终字符的贪婪策略会删除这两个字符。 DP 认识到保留两个字符会产生更长的有效子序列，从而产生零删除。 

考虑：```
s = "aa"
t = "a"
```这两个字母中只有一个可以在最终的堆栈中保留下来。 DP 探索这两种可能性并将最大有效子序列长度保持为一。 答案是删除一处。
