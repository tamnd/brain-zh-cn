 ## 解决方案

 ## 问题理解

 我们面临一个资源管理问题，其中每个测试用例都描述两种材料：棍子和钻石。 用这些材料，我们可以制作两种不同的物品。 一件物品消耗两根棍子和一颗钻石，另一件消耗一根棍子和两颗钻石。 每一件制作的物品都可以以一个单位的利润出售，因此我们的任务是在不违反资源限制的情况下最大限度地增加我们可以建造的物品数量。 

重要的不是制作的顺序，而是我们选择每种类型的数量，以便总资源消耗保持在可用的木棍和钻石范围内。 每个精心制作的物品的价值都是独立的，因此目标简化为在资源限制下最大化有效 (2,1) 和 (1,2) 对的总数。 

约束允许最多 1000 个测试用例，每个测试用例最多包含 10^9 的值。 这立即排除了对组合的任何模拟或搜索。 任何试图枚举要构建多少铲子和剑的方法都会降低到每个测试用例的 O(a + b) 或更糟，这太慢了。 每个测试用例我们需要一个恒定时间公式。 

一个天真的但重要的陷阱是假设我们应该总是在一个方向上贪婪地使用所有资源，例如首先制造尽可能多的铲子。 例如，如果我们有 4 根棍子和 4 颗钻石，首先贪婪地拿铲子会产生一把铲子（2 根棍子，1 颗钻石），留下 2 根棍子和 3 颗钻石，然后可能会得到一把剑，总共 2 个，这是最优的。 但在其他发行版中，如果不仔细推理，贪婪的选择可能会产生误导。 

一个更微妙的边缘情况是资源高度不平衡。 例如，使用 1 根棍子和 10 颗钻石，即使钻石丰富，也无法制作任何物品，因为两种配方都需要至少一根棍子。 同样，10 根木棍和 1 颗钻石的产量也为零。 任何正确的解决方案都必须隐式地捕获这两种资源必须以平衡对的方式消耗。 

## 方法

 蛮力策略是尝试所有可能数量的铲子。 如果我们固定铲子的数量 x，那么我们会消耗 2x 棍子和 x 钻石，从而减少我们计算可以制造多少剑的资源，这将受到剩余棍子和钻石的限制。 我们会尝试从 0 到 min(a//2, b) 的所有 x，并计算最佳结果。 

这种方法是正确的，因为每个有效的解决方案都对应于 x 铲子和 y 剑的某种选择。 然而，在最坏的情况下 x 的范围可能达到 10^9，使得这种线性扫描不可行。 每次评估的时间复杂度为 O(1)，因此每个测试用例的总复杂度变为 O(min(a, b))，这对于 1000 次测试来说太慢了。 

关键的观察结果是，每个项目总共消耗三种资源，但比例不同。 铲子是 2 根棍子和 1 颗钻石，剑是 1 根棍子和 2 颗钻石。 这种对称性意味着每个制作的物品有效地“消耗”三个单位，但限制因素不是总资源，而是棍棒和钻石之间的平衡。 

如果我们从配对的角度考虑，每个项目都会消耗一个单位的更丰富资源两次，另一个消耗一次。 这表明答案受到总资源总量以及 a 和 b 之间不平衡的限制。 最佳构造将始终使用尽可能多的对，直到一种资源变得太小而无法支持进一步平衡的制作。

由此产生的结构是，如果资源完全平衡，则答案受到可制作物品总数的限制，即 (a + b) // 3，并且还以确保可行性的方式受到较小资源的限制。 更严格的约束是 (a + b) // 3 和 min(a, b) 之间的最小值，因为每个项目必须在所有配置中消耗至少一个单位的两种资源。 

我们得出了一个直接捕获这两个约束的恒定时间公式。

 | 最优贪心公式 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 最佳解决方案依赖于计算两个同时约束下的最大项目数：总消耗品三元组和资源平衡。 

1. 对于每个测试用例，读取木棍 a 和菱形 b 的数量。 这些定义了必须分布在两个制作配方中的可用资源。 
2. 如果我们忽略不平衡，计算可能的项目总数，即 (a + b) // 3. 这表示每个项目总共消耗恰好 3 个资源，因此即使是完美平衡的系统也不能超过此界限。 这给出了生产的绝对上限。 
3. 计算受稀缺资源限制的项目数量，即 min(a, b)。 每个项目至少需要两种资源的某种组合的一个单位，因此我们不能超过较小的资源池。 
4. 取这两个界限的最小值作为最终答案。 这确保我们尊重总消费限制以及棍子和钻石之间的平衡约束。 

### 为什么它有效

 每个精心制作的物品都会将组合资源池减少三个单位，因此任何解决方案都不能超过 (a + b) // 3。同时，每个物品必须总共消耗至少一个单位的两种资源，因为两种配方都包含两种成分。 这强制项目数量不能超过 a 和 b 中的较小者。 任何有效的构造都必须满足这两个约束，并且由于这两种项目类型允许灵活地重新分配不平衡性，因此始终可以实现这两个边界中较小的一个。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    print(min((a + b) // 3, min(a, b)))
```该解决方案独立处理每个测试用例并在恒定时间内计算两个量。 第一个是完美包装下的物品总数，通过将资源分组为三元组得出。 第二个是较小资源类型所施加的限制，确保木棍和钻石都不会超出可用性限制而被过度使用。 

最终的答案是这两个值中的最小值，这样既保证了可行性又保证了最优性。 

一个常见的错误是仅使用 (a + b) // 3，当一种资源稀缺时，这会高估答案。 另一个错误是只使用min(a,b)，忽略了即使两者平衡，总资源仍然可能不足的事实。

 ## 边缘情况

 一个关键的边缘情况是当一个资源为零时。 对于输入 1000000000 0，两个公式都会生成 min((a+b)//3, min(a,b)) = 0，从而正确防止任何手工操作。 优先考虑总和的天真贪婪方法可能会错误地假设许多项目都是可能的，但它忽略了每个食谱都需要这两种成分。 

另一种边缘情况是极端不平衡，例如 1 和 10。该公式给出 min(11//3, 1) = 1，这意味着只有一项是可能的。 跟踪执行确认在任何有效的第一个工艺之后，至少一个资源立即耗尽。 

最后，像 10^9 和 10^9 这样的对称大输入测试整数稳定性。 该公式简化为 2*10^9 // 3，可以安全地适合 Python 整数，并确保不会发生溢出或性能问题。
