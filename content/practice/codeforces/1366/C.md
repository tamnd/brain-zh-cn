 ## 解决方案
 ## 问题理解

 我们有一个二进制矩阵。 路径从左上角的单元格开始，到右下角的单元格结束，仅向右或向下移动。 

每条路径都访问从一开始就测量的每个“距离层”中的一个单元格。 如果单元格位于位置`(i, j)`，那么它的层是`i + j`如果我们使用从零开始的索引。 沿着任何路径，层都按递增顺序访问`0`到`n + m - 2`。 

我们希望每条可能的路径都能产生回文值序列。 我们可以翻转任何单元格`0`到`1`或来自`1`到`0`，目标是最小化更改的单元格数量。 

矩阵维数最多为`30 × 30`。 尽管可能有多达`200`测试用例，每个矩阵最多包含`900`细胞。 这立即表明任何解决方案`O(nm)`或者`O(nm log nm)`每个测试用例很容易足够快，而任何涉及路径枚举的事情都是不可能的。 

来自的路径数`(1,1)`到`(n,m)`是$$\binom{n+m-2}{n-1},$$即使对于中等尺寸，它也会变得巨大。 推理单个路径的直接方法是行不通的。 

当层与其自身配对时，会出现微妙的边缘情况。 

考虑：```
2 3
0 1 0
1 0 1
```这些层是：```
layer 0: (0,0)
layer 1: (0,1) (1,0)
layer 2: (0,2) (1,1)
layer 3: (1,2)
```层数`1`和`2`成对是因为它们到两端的距离相等。 我们只处理每对一次。 粗心的实现同时处理了这两种情况`(1,2)`和`(2,1)`会重复计算更改。 

另一个重要的情况是开始层和结束层。 

例如：```
2 2
0 1
1 1
```第一个和最后一个单元格永远不会包含在优化组中。 每条路总是从那里开始和结束。 层对`(0,2)`不得进行处理，因为这些层位于回文的最末端。 标准解决方案自然会跳过它们。 

当总路径长度为奇数时，第三个陷阱是中间层。 

例子：```
3 3
0 1 0
1 1 1
0 1 0
```层`2`是每条路径的精确中心。 回文对中心位置没有限制，因此该层的成本为零。 处理它会错误地添加翻转。 

## 方法

 思考该问题的一种强力方法是检查从左上角到右下角的每条路径，并强制沿该路径的序列是回文。 

这个推理是正确的，但是路径的数量呈指数增长。 对于一个`30 × 30`网格，计数为$$\binom{58}{29},$$这是一个天文数字。 即使生成所有路径也是不可能的。 

关键的观察是回文性仅取决于路径内的位置，而不取决于所采取的具体路线。 

每个单元格属于由下式确定的层$$d = i + j.$$同一层中的所有单元出现在访问它们的每条路径中的相同位置。 

假设路径位置在图层`d`。 它在回文中的镜像位置是在层$$(n+m-2)-d.$$为了使每条路径都是回文，层中的每个单元`d`以及层中的每个单元格$$(n+m-2)-d$$必须包含相同的值。 

为什么有必要？ 

从图层中选择任意单元格`d`以及来自其镜像层的任何单元。 存在一条穿过两者的路径。 它们的位置在该路径上变得对称，因此它们的值必须匹配。 

这意味着每一对镜像层形成一个独立的组。 这两层内的每个细胞最终都必须成为全部`0`或全部`1`。 

对于包含`z`零点和`o`的，最低成本很简单$$\min(z, o).$$我们要么将所有零翻转为一，要么将所有一翻转为零。 

由于不同的层对从不交互，因此我们独立地对这些成本进行求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 路径数量呈指数增长 | 指数| 太慢了 |
 | 最佳 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1.让`L = n + m - 2`，最大层索引。 
2. 按层对所有单元格进行分组`d = i + j`。 
3.对于每层索引`d`，其镜像层为`L - d`。 
4. 仅处理其中的对`d < L - d`。 这可以避免重复计算，并在镜像自身时自动跳过中间层。 
5.收集属于层的所有单元格`d`和层`L - d`。 
6. 计算有多少个值`0`以及有多少个`1`在这个联合组内。 
7. 使整个组相等的最便宜的方法是翻转少数值。 添加`min(zeros, ones)`到答案。 
8. 对每个镜像层对重复此操作。 
9. 输出累计答案。 

### 为什么它有效

 对于任意层`d`，路径中的每个对称位置对应于层`L-d`。 考虑第一层中的任何单元和第二层中的任何单元。 可以构建一条访问两个单元的路径，将它们放置在该路径的镜像位置。 

如果两个这样的单元格具有不同的值，则该路径将不是回文路径。 因此，两层联合中的每个单元都必须共享一个共同的值。 

一个镜像层对的约束不涉及任何其他对的单元。 每对都可以独立优化。 选择多数值可以最大限度地减少该组内的翻转，从而给出`min(zeros, ones)`变化。 将这些独立的最优成本相加即可得出全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        layers = [[] for _ in range(n + m - 1)]

        for i in range(n):
            for j in range(m):
                layers[i + j].append(a[i][j])

        L = n + m - 2
        ans = 0

        for d in range((L + 1) // 2):
            mirror = L - d

            zeros = 0
            ones = 0

            for x in layers[d]:
                if x == 0:
                    zeros += 1
                else:
                    ones += 1

            for x in layers[mirror]:
                if x == 0:
                    zeros += 1
                else:
                    ones += 1

            ans += min(zeros, ones)

        print(ans)

solve()
```第一部分构建层分解。 每个单元格具有相同的值`i + j`属于同一层。 

变量`L`是最后一层的索引。 层`d`与图层配对`L-d`。 

循环仅运行到中点。 这是最容易出错的细节。 什么时候`d`到达镜像自身的层时，不存在任何约束，并且必须忽略该层。 使用```
range((L + 1) // 2)
```准确处理有效的镜像对。 

对于每一对，代码都会对两层上的零和一进行计数。 由于最终组必须变得统一，因此最佳选择是保留已经更频繁出现的值。 

不存在溢出问题，因为网格最多包含`900`细胞。

 ## 边缘情况

 ### 中间层镜像自身

 输入：```
1
3 3
0 0 0
0 1 0
0 0 0
```层数为：```
0, 1, 2, 3, 4
```层`2`是中心。 该算法仅处理对`(0,4)`和`(1,3)`。 完全跳过中心层，产生答案`0`。 

包含中心层的解决方案会错误地计算一次翻转。 

### 重复计算镜像对

 输入：```
1
2 3
1 1 0
1 0 0
```有效对只有：```
(0,3)
(1,2)
```该算法在到达后半层之前停止。 每个约束组只贡献一次。 

所有层上的循环将处理`(1,2)`以及后来`(2,1)`，将答案加倍。 

### 开始和结束单元格不同

 输入：```
1
2 2
0 1
1 1
```层数：```
0 : [0]
1 : [1,1]
2 : [1]
```仅层对`(0,2)`很重要。 合并后的值为`[0,1]`，因此需要进行一项更改。 

该算法计算：```
zeros = 1
ones = 1
cost = 1
```和输出`1`，这是使每条路径成为回文路径所需的最少翻转次数。
