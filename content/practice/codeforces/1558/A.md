 ## 解决方案
 ## 问题理解

 我们只得到网球比赛的最终比赛统计数据：爱丽丝赢了`a`个人比赛，鲍里斯获胜`b`个人比赛。 我们不知道这些比赛的顺序，也不知道谁先发球。 我们所知道的是，每场比赛的服务都会严格交替。 

每个游戏都有一个指定的服务器。 如果服务器赢得了比赛，则视为保留； 如果接球手获胜，则获胜。 任务是确定整个比赛、比赛序列和初始服务器的所有有效重建中所有可能的中断总数。 

考虑输入的一种有用方法是，我们不是模拟一场固定的比赛，而是计算两个自由下结构上可能的结果：我们可以在保留计数的同时排列获胜者的顺序`a`和`b`，我们可以选择起始服务器。 每个有效的重建都会产生一些整数`k`，接收方获胜的比赛次数。 

输出是所有此类可实现值的集合`k`。 

这些约束允许最多 1000 个测试用例和总共 200000 个游戏。 这排除了任何试图枚举所有结果排列或模拟所有可能的逐场游戏分配的方法。 任何解决方案都必须将问题简化为每个测试用例的封闭形式表征，最好是在恒定时间内。 

当一名玩家赢得所有比赛时，就会出现一种微妙的边缘情况。 例如，如果`a = 0`和`b = 5`，根据发球模式，每场比赛对于 Borys 或 Alice 来说都必然是一次破发，但可实现的破发计数集仍然不是单一值，因为初始服务器选择会改变较强玩家发球的次数。 假设玩家之间对称的幼稚方法将错过这种对启动服务器的依赖。 

另一个陷阱是假设中断次数由下式唯一确定：`a`和`b`。 例如，`(2, 1)`允许具有不同中断计数（范围从 0 到 3）的多个有效序列，如示例中所示。 这已经表明答案是一个区间而不是单个计算值。 

## 方法

 如果我们尝试通过暴力解决问题，我们将枚举所有排列`a + b`游戏，为每个游戏分配一个获胜者，然后尝试启动服务器的两种选择。 对于每种安排，我们模拟交替服务器模式并计算接收者获胜的次数。 这立即变得不可行：即使忽略获胜者排列的指数数量，也存在与固定计数一致的指数数量的交错`a`和`b`。 

关键的观察是，唯一重要的结构是每个球员获胜时发球的次数。 除了确保计数匹配之外，获胜顺序不会影响可行性。 这场比赛可以看作是一个序列`n = a + b`从 Alice 或 Borys 开始的交替服务器游戏，我们可以自由选择获胜者的位置分配。 

休息次数就是获胜者与发球者不同的位置数。 如果我们固定起始服务器，那么每个位置都有一个固定的服务器身份，我们只决定Alice的胜利中有多少落在Alice发球位置上，有多少落在Borys发球位置上。 

这将问题简化为组合可行性范围问题：对于固定的起始服务器，获胜者和服务器之间的最小和最大匹配数是多少？ 极端情况是通过贪婪地将获胜者与有利或不利的发球位置对齐来实现的。 一旦我们计算出每个起始服务器的可能范围，两个间隔的并集就会给出最终答案。 

由于两种结构都是单调的，因此可实现的中断计数集形成连续间隔。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有序列进行暴力破解 | 指数| O(n) | 太慢了|
 | 通过服务对齐构建区间 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们表示`n = a + b`。 

1. 考虑Alice先发球的情况。 服务模式变得固定：Alice、Borys、Alice、Borys，等等。 计算有多少个 Alice 服务位置和 Borys 服务位置`n`游戏。 这些计数仅取决于奇偶校验`n`。 
2.计算Alice所服务的位置数，称之为`sa`，鲍里斯服务的地方，称之为`sb`。 如果爱丽丝先发球，那么`sa = (n + 1) // 2`和`sb = n // 2`。 如果鲍里斯先发球，则角色互换。 
3. 当胜利进入对手发球位置时，即发生破发。 对于爱丽丝获胜的情况，将其放置在鲍里斯发球的位置上会产生休息； 将它们放置在 Alice 服务槽中可以避免中断。 同样的对称性也适用于鲍里斯的胜利。 
4. 为了尽量减少固定发球的中断，我们最大化与自己的发球一致的获胜次数。 这相当于将尽可能多的 Alice 胜利分配给 Alice 服务槽位，并将尽可能多的 Bory 胜利分配给 Borys 服务槽位。 
5. 为了最大化休息时间，我们进行相反的调整：优先将胜利分配给对手发球位置，最多可达容量。 
6. 这会产生每个起始服务器的最小和最大中断计数。 每个选择都会给出一个可能值的区间。 
7. 最终答案是两个区间的并集（Alice-first 和 Borys-first）。 这些间隔重叠或接触，因此并集又是一个连续的间隔。 

### 为什么它有效

 对于固定的发球模式，每场比赛对破发计数的贡献仅取决于发球或接发球员是否为该位置分配了胜利。 唯一的全局限制是每个玩家有多少胜利，这转化为可以填补多少“好”或“坏”空位的容量限制。 贪婪分配是最优的，因为每次从有利位置到不利位置的胜利交换都会使中断计数恰好改变 1，并且位置之间不存在依赖关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        a, b = map(int, input().split())
        n = a + b

        def interval(first_alice: bool):
            if first_alice:
                sa = (n + 1) // 2
                sb = n // 2
            else:
                sa = n // 2
                sb = (n + 1) // 2

            # minimize breaks: fill own serve first
            min_breaks = max(0, a - sa) + max(0, b - sb)

            # maximize breaks: push wins to opponent serve
            min_own = min(a, sa) + min(b, sb)
            max_breaks = n - min_own

            return min_breaks, max_breaks

        l1, r1 = interval(True)
        l2, r2 = interval(False)

        L = min(l1, l2)
        R = max(r1, r2)

        res = list(range(L, R + 1))
        out.append(str(len(res)))
        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现将两个可能的起始条件分开，并为每个条件计算一个干净的极值范围。 关键细节是通过“错位”表达突破：我们不是直接跟踪突破，而是跟踪有多少胜利落在兼容的发球位置上。 

当一名玩家的胜场数多于其可用的发球位置时，最小计算会计算不可避免的不匹配情况。 最大计算通过计算可以正确对齐的胜利次数并从总游戏中减去来翻转视角。 

形成最终区间并集时必须小心，因为两种情况可能会重叠。 服用`min(l1, l2)`和`max(r1, r2)`之所以有效，是因为可行集是连续的，并且它们的并集也是连续的。

这表明每次休息计数都是可以实现的，因为获胜者之间的不平衡足够小，可以通过重新安排作业来吸收。 

### 示例 2：`a = 1, b = 1`这里`n = 2`。 

| 启动服务器| 萨| 某人 | 分钟休息时间| 最大休息时间 |
 | --- | --- | --- | --- | --- |
 | 爱丽丝| 1 | 1 | 0 | 2 |

这种情况强调，虽然区间计算是必要的，但内部奇偶校验约束可以删除对称配置中的中间值。

 ## 边缘情况

 当`a = 0`，所有胜利都属于鲍里斯。 唯一的灵活性来自服务顺序。 该算法根据发球者的起始位置将所有博里斯的胜利分配给发球或接球位置，从而产生完整的可能休息时间间隔。 计算正确地简化为比较`sb`和`b`，并且不会出现无效的负计数，因为`max(0, ...)`结构。 

什么时候`b = 0`，情况是对称的。 所有的胜利都是爱丽丝的，唯一的区别是这些胜利中有多少落在爱丽丝的发球位置上。 区间计算再次捕获两个极端，而不需要特殊的分支。 

什么时候`a = b`，两种服务模式都会产生相同的时隙分布。 该算法正确地合并两个相同的区间，防止重复计算，同时保留完整的可行范围。
