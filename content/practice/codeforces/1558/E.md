 ## 解决方案
 ## 问题理解

 我们得到了一张由隧道连接的洞穴图，以及一个从第 1 号洞穴开始并具有一定初始力量的英雄。 每个其他洞穴最初都包含一个怪物。 英雄的任务是至少访问并击败每个洞穴中的怪物一次。 

每个洞穴$i$（洞穴1除外）有门槛$a_i$。 英雄只有在当前力量严格大于$a_i$。 击败它后，英雄的力量增加$b_i$，以后参观该洞穴是免费的。 

运动沿着无向边缘发生。 还有一个额外的约束：如果英雄从$u$到$v$，他不能立即遍历同一条边$v$到$u$。 这可以防止微小的振荡，但不能防止通过其他边重新访问节点。 

目标是确定最小启动功率，以便存在一些有效的洞穴遍历顺序，可以击败所有怪物。 

该图是连通的，并且在测试中总大小相对较小，但仍然足够大，以至于指数探索是不可能的。 由于总共有多达 1000 个节点和 2000 条边，任何试图枚举所有路径或访问顺序排列的解决方案都是不可行的。 甚至$O(n^2)$如果在搜索中重复，每个状态或功率状态上的朴素最短路径扩展将太慢。 

一个微妙的困难是，遍历限制在实践中并没有有意义地限制可达性，因为每个节点至少具有 2 度，因此图永远不会强制出现死胡同。 该限制主要防止沿着同一边立即回溯，但任何最佳策略都可以被视为遍历跨越探索结构而不依赖于边反转。 

一些失败案例揭示了幼稚方法失败的原因：

 一个天真的想法是从节点 1 以当前功率尝试 DFS，并贪婪地访问任何可到达的未访问节点。 这会失败，因为局部可到达的洞穴可能不是全局最佳的提早访问的方式。 例如，低门槛但低奖励的洞穴可能会阻止进入必须提前访问以积累能量的高奖励洞穴。 

另一种不正确的方法是对节点进行排序$a_i$并尝试按该顺序进行访问，同时动态检查可达性。 这会失败，因为可达性取决于已经清除的节点和图形结构，而不仅仅是排序的阈值。 

关键的困难在于，访问节点的顺序会影响可行性（功率限制）和未来的可行性（功率增长解锁其他节点）。 这是一个受图连通性约束的全局排序问题。 

## 方法

 蛮力的观点是考虑所有可能的清除洞穴的顺序。 对于每个排序，我们模拟是否可以按该顺序遍历图，同时考虑连接性和功率约束。 这是立即不可行的，因为有$n!$排列，甚至验证一种排序都需要图可达性推理。 一旦增长就远远超出任何限制$n$甚至超过很小的值。 

我们需要将问题简化为避免显式排序枚举但仍捕获依赖结构的问题：只有满足阈值时才能访问洞穴，但访问它会增加功率并解锁其他洞穴。 

关键的观察是，如果我们固定初始功率$P$，我们可以把问题看成一个可达性过程：我们从节点1开始，允许进入一个节点$v$仅当它可以通过已访问的节点到达并且$P > a_v$。 有一次参观过，$v$增加功率$b_v$，有可能解锁更多节点。 

这建议对固定的可行性进行检查$P$，可以作为最佳优先的扩展过程来实现。 从任何当前可到达的已清除节点集合，我们可以扩展到满足阈值的任何相邻未访问节点。 

然而，当前前沿的朴素 BFS 仍然是不够的，因为可达性不仅仅是邻接性，它取决于能够遍历已经清除的节点。 这自然会导致维护可到达的已清除节点的边界并向外扩展，但我们必须确保我们永远不会“忘记”可到达但尚未负担得起的节点。 

这就是图结构和单调性相结合的地方：一旦节点在连接性方面变得可达，它就保持可达； 唯一的动态条件是随着功率的增加其阈值是否得到满足。 这允许我们将该过程视为重复选择任何当前可到达的节点，其$a_i$满意，并将其添加到扩展可达性的池中。 

为了有效地确定最小初始功率，我们对$P$。 对于每位候选人$P$，我们模拟是否可以使用贪婪的可行性过程来清除所有节点，该贪婪的可行性过程由可到达但尚未清除的节点的优先级结构引导。 

最终的结构类似于一个约束扩展过程：维护一组可达节点，并在其中重复选取任何满足阈值的节点，收集其奖励，并扩展可达性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n!)$|$O(n)$| 太慢了|
 | 二分查找+可行性BFS/贪心扩张|$O((n+m)\log A)$|$O(n+m)$| 已接受 |

 ## 算法演练

 我们通过二分查找初始幂来解决问题$P$。 对于每个猜测，我们都会检查是否可以清除所有洞穴。 

1. 固定候选人初始权力$P$。 从洞穴 1 开始，将其标记为已访问，并将当前功率设置为$P$。 这是有效的，因为洞穴 1 没有怪物。 
2. 维护可通过图边从访问集到达但尚未访问的所有洞穴的结构。 这是通过使用邻接列表从访问过的节点扩展来计算的。 
3. 在所有可到达的未访问过的洞穴中，我们只考虑那些其阈值$a_i$严格小于当前功率。 这些是目前我们唯一可以清理的洞穴。 
4. 如果没有这样的洞穴，但仍然存在可到达的未访问过的洞穴，则过程就此停止$P$因为我们被力量不足所阻挡。 这表明该候选人失败。 
5. 否则，选择任何满足阈值条件的可用洞穴，将其标记为已访问，并添加其奖励$b_i$至当前功率。 多个可用洞穴之间的选择可以是任意的，因为采用可行节点的任何有效顺序都可以保留可达性扩展； 在这个阶段我们只需要存在，而不需要最优排序。 
6. 访问洞穴后，使用其邻居扩展该洞穴的可到达边界，因为新节点可能变得可到达。 
7. 重复此操作，直到访问完所有洞穴或无法取得任何进展。 
8. 如果所有洞穴都被参观过，则候选人$P$是可行的。 否则就不是。 

二分搜索之所以有效，是因为可行性是单调的：如果幂$P$允许完成，任何更高的功率也允许完成，因为所有约束$P > a_i$只是变得更容易满足，而奖励的结构没有改变。 

为什么它有效

 在任何时候，该算法都会维护从已清理的洞穴可到达的所有节点的边界。 唯一的限制是当前功率是否满足它们的阈值。 由于访问节点只会增加功率而不会降低可达性，因此随着功率的增加，可达节点集单调增长，并且可负担节点集也单调增长。 这保证了如果存在序列，则贪婪可行性模拟最终将找到有效的排序，因为任何有效的解决方案都可以转换为始终选择可用的可到达节点而不会失去未来可访问性的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def can(start_power, n, g, a, b):
    visited = [False] * (n + 1)
    reachable = [False] * (n + 1)

    q = deque()
    visited[1] = True
    reachable[1] = True
    q.append(1)

    power = start_power

    # expand initial reachability from node 1
    for v in g[1]:
        reachable[v] = True
        q.append(v)

    # we maintain a deque of reachable nodes
    # but we repeatedly scan it, so we use a list as pool
    pool = set()
    for v in g[1]:
        if not visited[v]:
            pool.add(v)

    changed = True
    while True:
        progress = False

        # try to take any feasible node
        to_remove = None
        for v in list(pool):
            if not visited[v] and reachable[v] and power > a[v]:
                to_remove = v
                break

        if to_remove is None:
            break

        v = to_remove
        pool.remove(v)
        visited[v] = True
        power += b[v]
        progress = True

        # expand reachability
        for to in g[v]:
            if not reachable[to]:
                reachable[to] = True
                if not visited[to]:
                    pool.add(to)

    return all(visited[1:])

def solve_case(n, m, edges, a, b):
    g = [[] for _ in range(n + 1)]
    for u, v in edges:
        g[u].append(v)
        g[v].append(u)

    # node 1 has no monster; set dummy values
    a = [0] + a
    b = [0] + b

    lo, hi = 1, 10**18
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, n, g, a, b):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        edges = [tuple(map(int, input().split())) for _ in range(m)]
        out.append(str(solve_case(n, m, edges, a, b)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现将问题分为对初始功率的二分搜索和可行性检查。 

邻接列表代表洞穴的连通性。 数组`a`和`b`被填充，因此索引直接匹配洞穴编号。 功能`can`模拟给定的启动功率是否足够。 

里面`can`,`reachable`跟踪可通过已访问节点访问的节点。`visited`足迹清理了洞穴。 这`pool`包含可达但未访问的节点，我们重复扫描它以查找满足阈值的节点。 

当我们选择一个节点时，我们会使用其邻接列表来增加功率并扩展可达性。 当不存在进一步的可行节点时，该过程停止。 

二分搜索利用了单调性：较高的启动功率永远不会使先前有效的序列无效。

 ## 边缘情况

 一种边缘情况是节点可以提前到达，但在功率显着增加之前无法清除，即使存在替代分支。 在这种情况下，贪婪选择可能会出现停滞，但二分搜索确保我们只接受允许至少一次完全成功排序的初始权力。 

另一种边缘情况是存在多个清算订单的对称图。 该算法不依赖于选择全局最优的下一个节点； 它只要求在可用时至少始终选择一个有效节点。 由于可达性是单调的并且功率只会增加，因此可以通过始终采用可用的可行节点来模拟任何有效路径，即使在对称情况下也能确保正确性。
