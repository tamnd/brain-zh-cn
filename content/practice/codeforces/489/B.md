 ## 解决方案
 ## 问题理解

 我们有两组舞者。 每个男孩都有一个技能水平，每个女孩都有一个技能水平。 男孩和女孩只有在技能水平相差最多 1 时才可以配对。每个舞者最多可以属于一对。 

任务是形成尽可能多的有效的男孩女孩对。 

输入由两个数组组成。 第一个数组包含男孩的技能水平，第二个数组包含女孩的技能水平。 输出是技能差异至多为 1 的不相交对的最大数量。 

限制非常小。 两个组最多包含 100 名舞者，因此即使是二次算法也很容易足够快。 这意味着我们不需要复杂的匹配算法，例如 Hopcroft-Karp。 挑战在于识别允许简单贪婪解决方案的结构。 

一个常见的错误是按照原始输入顺序贪婪地配对舞者。 输入中舞者的顺序没有意义。 例如：```
boys  = [4, 1]
girls = [2, 3]
```正确答案是2，通过配对`(1,2)`和`(4,3)`。 对未排序数组进行从左到右的贪婪扫描可能只能找到一对。 

当几个舞者拥有相同的技能时，会发生另一个微妙的情况：```
boys  = [2, 2, 2]
girls = [1, 2, 3]
```正确答案是 3。任何总是选择第一个可用的兼容伙伴而不考虑排序的算法都可能会意外地阻止未来的匹配。 

第三种边缘情况是应该跳过看似有效的匹配，因为稍后存在更好的匹配：```
boys  = [1, 2]
girls = [2, 3]
```最佳答案是2.配对男孩`2`和女孩`2`第一叶男孩`1`无与伦比的。 配对`(1,2)`和`(2,3)`给出两对。 解决方案必须系统地避免此类冲突。 

## 方法

 看待问题最直接的方式就是将其视为二分匹配问题。 创建一个图表，其中每个男孩都与技能相差最多 1 的每个女孩相关联。然后找到最大匹配。 

这种方法是正确的，因为每个有效的配对都对应于图中的匹配。 对于最多 100 个男孩和 100 个女孩，标准增广路径算法可以在限制内轻松运行。 

然而，图表视角隐藏了一个重要的属性。 兼容性仅取决于技能的数值。 如果两个技能数组都已排序，则具有相似技能的舞者将按照排序顺序成为邻居。 

假设剩下的最小的男孩有技能`b`，剩下的最小的女孩有技能`g`。 

如果`|b - g| ≤ 1`，将它们配对总是安全的。 两位舞者都无法通过等待技能更弱的人来帮助创造更大的答案，因为不存在。 

如果`b < g - 1`，然后男孩`b`无法匹配当前的女孩或任何以后的女孩。 后来的女孩至少都有技能`g`，所以它们的区别是`b`甚至更大。 这孩子永远无法匹配，所以我们应该抛弃他。 

同样，如果`g < b - 1`，当前的女孩永远无法匹配，应该被丢弃。 

在对两个数组进行排序后，这一观察直接导致双指针贪婪算法。

 | --- | --- | --- | --- |
 | 暴力二分匹配| O((n+m)·n·m) | O(n·m) | 已接受 |
 | 排序+两个指针| O(n log n + m log m) | O(n log n + m log m) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 阅读男子技能阵和女子技能阵。 
2. 按非降序对两个数组进行排序。 

排序后，具有相似技能水平的舞者会出现在彼此附近，这使得局部决策在全局上是正确的。 
3.初始化两个指针，`i`对于男孩和`j`对于女孩来说，都是从 0 开始。 
4. 初始化`answer = 0`。 
5. 当两个指针都在其数组内时，比较当前技能。 
6.如果`abs(boys[i] - girls[j]) <= 1`，形成一对，递增`answer`，并推进两个指针。 

这对舞者是有效的，保留任何一个舞者为后来的舞伴并不能改善结果。 
7. 否则，如果`boys[i] < girls[j]`， 进步`i`。 

现在的男孩太弱了，无法与现在的女孩匹敌。 由于所有后来的女孩至少都一样强大，所以这个男孩永远不能参加任何未来的配对。 
8. 否则，提前`j`。 

对称地，当前的女孩太弱，无法与当前的男孩匹配，并且永远无法参加任何未来的配对。 
9. 当一个指针到达数组末尾时，停止并打印`answer`。 

### 为什么它有效

 在每一步中，算法都会检查最小的不匹配男孩和最小的不匹配女孩。 

当他们的技能相差最多 1 时，将他们配对并不能减少最优答案。 任何一位舞者的未来搭档的技能至少与当前候选人一样高，因此推迟比赛不能创造额外的机会。 

当一名舞者太弱而无法匹配另一名舞者时，该舞者无法匹配相反排序数组中任何后来的舞者。 丢弃它们不会造成任何损失，因为它们已经不可能配对。 

该算法永远不会删除仍然可以为最佳解决方案做出贡献的舞者。 每个决策都会保留未来可实现的最大数量的对。 通过对指针位置的归纳，最终的计数是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    boys = list(map(int, input().split()))

    m = int(input())
    girls = list(map(int, input().split()))

    boys.sort()
    girls.sort()

    i = 0
    j = 0
    ans = 0

    while i < n and j < m:
        if abs(boys[i] - girls[j]) <= 1:
            ans += 1
            i += 1
            j += 1
        elif boys[i] < girls[j]:
            i += 1
        else:
            j += 1

    print(ans)

if __name__ == "__main__":
    solve()
```第一部分读取输入并对两个技能数组进行排序。 排序是使贪心推理有效的关键预处理步骤。 

变量`i`和`j`总是指向最小的无与伦比的男孩和女孩。 当两组仍包含未经处理的舞者时，循环仍在继续。 

当当前的舞者兼容时，就形成一对，并且两个指针都向前移动。 由于每个舞者可能只属于一对，因此不应再次考虑任何一个舞者。 

当当前男孩的技能比当前女孩的技能小1以上时，仅推进男孩指针是正确的。 未来的女孩都会拥有更高的本事，所以现在的男孩已经没有剩余的机会了。 

对称表壳推进小指针。 

不存在溢出问题，因为所有值都很小。 通常导致错误的唯一实现细节是在运行两指针扫描之前忘记排序。

 ## 边缘情况

 考虑：```
1
1
1
2
```技能差异正好为1。算法比较`1`和`2`，看到`abs(1 - 2) = 1`，形成一对，并输出`1`。 任何使用的实现`< 1`而不是`<= 1`会错误输出`0`。 

考虑：```
2
4 1
2
2 3
```排序后：```
boys  = [1, 4]
girls = [2, 3]
```算法首先匹配`(1,2)`，然后匹配`(4,3)`，产生答案`2`。 如果不排序，贪婪扫描可能从`4`并输掉一场比赛。 

考虑：```
3
2 2 2
3
1 2 3
```该算法连续匹配所有三对。 重复的值不会造成特别的困难，因为指针总是在比赛结束后向前移动，从而防止任何舞者被使用两次。 

考虑：```
2
1 1
2
5 5
```第一个比较是`1`相对`5`。 由于男孩太弱，算法将男孩指针向前推进。 同样的情况又发生在第二个男孩身上。 没有形成对，输出是`0`。 这说明了为什么抛弃一个技术远远落后的舞者是安全的。
