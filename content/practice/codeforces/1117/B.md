 ## 解决方案
 ## 问题理解

 我们得到了一组表情，每个表情都有积极的幸福值。 我们可以使用固定次数的表情，但单个表情的连续重复次数不能超过给定的次数。 任务是在这些规则下最大化给予对手的总幸福感。 

正式地，我们有`n`表情，一个整数`m`允许的总使用量，以及一个整数`k`为连续使用限制。 每个表情都有一个幸福值`a_i`。 我们想要一个序列`m`表情的使用使得最多出现相同的表情`k`连续次数和总和`a_i`所有用途都得到最大化。 

界限给了我们`n`最多`2 * 10^5`和`m`最多`2 * 10^9`。 一个简单的解决方案迭代每个`m`单独使用是不可能的； 任何 O(m) 算法都会太慢。 这告诉我们，我们需要一个使用数学计算而不是实际序列模拟的解决方案。`a_i`最大可达 10^9，因此如果我们使用的语言没有任意精度整数，则需要小心使用整数运算以避免溢出。 

一个微妙的点是连续使用限制`k`。 简单地总是使用最大幸福感直到精疲力尽的天真方法将会失败，如果`m`大于`k`因为我们必须交织一些其他表情。 例如，如果最高幸福表情是 10，第二高幸福表情是 1，`m=5`， 和`k=2`，最优序列为`[10,10,1,10,10]`。 忽略`k`会产生`[10,10,10,10,10]`，这是无效的。 

另一个边缘情况是所有情绪都具有同等的幸福感。 这里，连续使用限制并不会降低总幸福感； 最佳顺序可以以任何顺序使用任何表情。 

## 方法

 暴力方法是重复选择最大可用表情，同时遵守连续使用限制。 我们将跟踪当前连续表情的计数，并在达到限制时切换到下一个最佳表情。 这适用于小型`m`和`n`，但与`m`达到 2*10^9 时，需要 O(m) 次操作，这远远超出了时间限制。 

关键的洞察力是注意重复的模式。 最优策略总是使用最大的表情`k`次，然后是第二大表情一次，然后重复此块。 设最大幸福值为`first`和第二大`second`。 每个完整的块都贡献`first*k + second`幸福有长度`k+1`。 我们可以计算有多少个完整的块适合`m`使用整数除法。 由于连续约束允许，完整块后的剩余用途用于最大表情。 这减少了模拟问题`m`仅使用两个最大的表情进行恒定时间算术计算的步骤。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(米) | O(1) | O(1) | 对于大 m 来说太慢 |
 | 最优（数学有两个最大）| O(n log n) 排序 + O(1) 算术 | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整数`n`,`m`， 和`k`。 然后读取数组`a`的幸福价值观。 
2. 排序`a`按非递减顺序。 这样可以轻松访问最大的两个值。 
3.让`first = a[-1]`（最大的表情）和`second = a[-2]`（第二大）。 
4. 计算完整块的数量`k+1`适合的情绪`m`用途：`blocks = m // (k+1)`。 每个区块都贡献`first*k + second`幸福。 
5. 计算剩余使用量：`remainder = m % (k+1)`。 这些都可以`first`表情，因为连续的限制在每个块之后都会重置。 
6. 计算总幸福感：`total = blocks * (first*k + second) + remainder * first`。 
7. 输出`total`。 

为什么有效：每个区块都在尊重连续限制的同时最大化幸福感。 使用最大表情超过`k`连续多次是被禁止的，并且使用任何小于块中第二大的表情都会降低总幸福感。 这保证了总和是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
a = list(map(int, input().split()))

a.sort()
first = a[-1]
second = a[-2]

blocks = m // (k + 1)
remainder = m % (k + 1)

total = blocks * (first * k + second) + remainder * first
print(total)
```该解决方案对数组进行排序以轻松识别两个最大值。 它使用整数除法和模数有效地计算完整的块和剩余的使用，避免了任何序列模拟的需要。 排序是唯一的 O(n log n) 步骤； 算术是常数时间。 我们使用快速 I/O 来确保大型设备的性能`n`。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    first = a[-1]
    second = a[-2]
    blocks = m // (k + 1)
    remainder = m % (k + 1)
    total = blocks * (first * k + second) + remainder * first
    return str(total)

# provided samples
assert run("6 9 2\n1 3 3 7 4 2\n") == "54", "sample 1"

# custom cases
assert run("3 5 1\n10 5 2\n") == "40", "alternating k=1"
assert run("2 10 3\n5 5\n") == "50", "all equal values"
assert run("5 8 2\n1 2 3 4 5\n") == "34", "general case"
assert run("2 1 1\n1000000000 1\n") == "1000000000", "minimal m=1"

 ## 边缘情况

 如果`k >= m`，连续的极限永远不会限制我们。 例如，`n=3, m=2, k=5, a=[1,2,3]`。 该算法计算`blocks=0`,`remainder=2`， 和`total=2*3=6`，这是正确的。
