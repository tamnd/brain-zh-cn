 ## 解决方案
 ## 问题理解

 我们在无限网格上有一个起点和一个目标点。 每天，环境都会根据固定的周期弦产生风向。 风使船在四个基本方向之一上移动一个单位。 这艘船并不是被动的：每天它也可以选择向四个方向之一移动或保持静止。 一天的最终运动是风和船舶选择的矢量和，因此每天都会贡献一个位移矢量，该矢量是两种效果的组合。 

任务是确定累积位移可以将船舶从起始坐标移动到目的地的最小天数。 如果没有任何船舶决策序列可以实现目标，则答案为-1。 

关键的困难在于风是周期性的，因此运动模式每 n 天重复一次，并且船舶的选择与这种重复的强迫函数相互作用。 

这些限制非常严格，以至于任何依赖于大时间范围内日复一日模拟的解决方案都是不可能的。 坐标达到10^9，因此所需的总位移也可能很大，但由于重复，我们可能需要考虑的风步数可能比n大得多。 这立即表明，在不进行结构优化的情况下，我们无法进行线性模拟，直到得到答案。 对给定天数的简单检查需要 O(days)，而对天数的二分搜索则需要快速的可行性检查。 

最危险的陷阱是假设 x 和 y 方向独立，而不仔细跟踪风补偿。 另一个微妙的问题是假设这艘船每天都能完全抵消风力； 这是错误的，因为风和船同时移动，因此随着时间的推移，取消并不总是在每个方向上完美，但在多天后，它变成了可达性约束，而不是每步取消问题。 

## 方法

 直接的暴力方法将尝试模拟船舶每天所有可能的运动顺序，并检查是否可以达到目标。 每天船的运动有五种选择，风向由弦决定。 这导致轨迹呈指数级增长，k 天后大约为 5^k，即使对于非常小的 k，这也是立即不可行的。 

一种更结构化的蛮力方法是模拟固定的天数，并通过选择最佳船舶动作来检查所有可能到达的累积位置。 然而，即使跟踪每天可达的状态也是不可能的，因为坐标是无界的，因此状态空间的增长不受限制。 

关键的观察结果是该问题在时间上是单调的。 如果船舶可以在 k 天之内到达目标，那么只需适当停留在原地，浪费额外的天数，它也可以在任意更长的天数内到达目标。 这种单调性表明二进制搜索答案。 

困难的部分变成检查固定的天数 k 是否足够。 在 k 天里，我们可以计算总风贡献，然后看看船舶是否可以使用自己的移动进行补偿。 在 k 天的时间里，船舶提供了一个向量，其 x 和 y 分量均在有限范围内，因为每天它都可以选择方向或保持静止。 可达性简化为检查在考虑风之后所需的位移是否位于可实现的校正范围内。 

k 天的风可以使用一个完整周期的前缀计数和余数来计算。 然后，对于每个 k，我们计算船舶单独所需的净排水量。 这艘船可以贡献曼哈顿范数最多为 k 的任何向量，因为每天它可以在任何方向上精确移动一个单位或保持静止，这意味着它可以花费 k 个步骤在 x 和 y 之间任意分配运动。

因此，可行性条件就变成了在使用k步单位移动减去风之后是否可以达到目标位移，这减少为曼哈顿距离检查。 

这将问题转化为对 k 进行二分搜索，每次检查进行 O(n) 预处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 指数| O(1) | O(1) | 太慢了 |
 | 二分查找+前缀风+距离检查| O(n log D) | O(n log D) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算串的一个完整周期内的风位移前缀和。 我们存储累积的 x 和 y 运动，以便我们可以快速查询任何段。 
2. 定义一个函数来计算 k 天的风位移。 我们将 k 分成完整周期和余数，使用前缀和来计算 O(1) 中的总风移。 
3. 对于候选 k，计算仅风会将船从初始位置移动到的位置。 
4. 计算应用风位移后到达目标所需的剩余矢量。 这是船舶必须使用其自己的运动选择产生的修正矢量。 
5. 检查船舶是否可以在 k 天内产生此修正。 由于每天允许曼哈顿距离移动一个单位，因此船舶可以实现任何曼哈顿距离至多为 k 的位移。 
6、如果要求的曼哈顿距离≤k，则k天可行； 否则就不是。 
7. 对从 0 到足够大的上限（通常为 2 * 10^14）的最小 k 进行二分搜索，或者从坐标限制加上风漂移边界导出。 

为什么它有效：

 风的贡献对于任何 k 都是完全确定的，并且与船舶决策无关，因此可以将其视为固定平移。 船舶每天对运动的控制形成一个以位移空间原点为中心、半径为 k 的曼哈顿球。 减去风之后，可行性就变成了几何遏制检查：所需的校正矢量是否位于曼哈顿球内部。 k 的单调性确保二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())
    n = int(input())
    s = input().strip()

    pref_x = [0] * (n + 1)
    pref_y = [0] * (n + 1)

    def move(c):
        if c == 'U':
            return 0, 1
        if c == 'D':
            return 0, -1
        if c == 'L':
            return -1, 0
        return 1, 0

    for i in range(n):
        dx, dy = move(s[i])
        pref_x[i + 1] = pref_x[i] + dx
        pref_y[i + 1] = pref_y[i] + dy

    total_cycle_x = pref_x[n]
    total_cycle_y = pref_y[n]

    def wind(k):
        full = k // n
        rem = k % n

        return (full * total_cycle_x + pref_x[rem],
                full * total_cycle_y + pref_y[rem])

    def ok(k):
        wx, wy = wind(k)
        tx = x2 - (x1 + wx)
        ty = y2 - (y1 + wy)
        return abs(tx) + abs(ty) <= k

    lo, hi = 0, 10**15
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将风向编码为单位向量并构建前缀和，以便可以立即评估风循环的任何前缀。 这避免了在可行性检查期间重复重新计算风的贡献。 

Wind 函数将 k 展开为完整循环和部分余数。 这是直接使用周期结构的地方：我们不模拟 k 步，而是重用预先计算的周期和。 

可行性检查首先隔离风的影响，相应地改变起始位置。 之后，剩下的任务就变成了曼哈顿几何中 k 单位移动下的纯可达性问题，从而简化为简单的距离测试。 

在 k 上应用二分搜索是因为可行性在时间上是单调的：一旦存在解决方案，添加更多天数永远不会使其失效。

 ### 示例 1

 输入：```
0 0
4 6
3
UUU
```我们计算风前缀：UUU 每个周期贡献 (0,3)。 

| k | 风 (wx, wy) | 必需（tx，ty）| |tx|+|ty| | 好的 |

 |---|---|---|---|---|

 | 3 | (0,3) | (4,3) | 7 | 没有|

 | 5 | (0,5) | (4,1) | 5 | 是的 |

 最小 k 为 5。这表明仅风就会显着向上推动，并且船舶必须花费其预算的一部分来校正 x 运动，并花费部分预算来校正多余的 y。 

### 示例 2

 输入：```
0 3
0 0
2
DD
```风每天都有向下的贡献。 

| k | 风 (wx, wy) | 必需（tx，ty）| |tx|+|ty| | 好的 |

 |---|---|---|---|---|

 | 2 | (0,-2) | (0,-2) | (0,-5) | (0,-5) | 5 | 没有|

 | 3 | (0,-3) | (0,-3) | (0,-6) | (0,-6) | 6 | 是的 |

 这表明，即使风已经朝目标移动，仍然可能需要额外的修正并在 k 中线性累积。

 ## 边缘情况

 一种极端情况是风反复直接远离目标。 在这种情况下，对于较小的 k，可行性条件不成立，因为所需的修正增长得快于可用的船舶运动。 该算法可以处理这个问题，因为风累积是通过循环和精确计算的，因此二分搜索永远不会错误地接受小 k。 

另一种极端情况是风在整个周期内自行消失。 例如，像这样的字符串`UDLR`每个周期产生零净漂移。 在这种情况下，风函数减少为仅余数贡献，并且解决方案正确地表现得像纯曼哈顿距离问题。 

第三种情况是，最佳策略需要在多个周期内将船舶运动与部分取消风相混合，而不是每天进行修正。 这是隐式处理的，因为模型从不假设每步取消； 它只限制总位移，因此任何交错策略自然都被曼哈顿边界覆盖。
