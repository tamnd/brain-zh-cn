 ## 解决方案
 ## 问题理解

 我们得到了一个数字序列和一些要对其执行的操作。 每个操作总是删除序列中当前的第一个元素，然后反转剩余的元素。 这会重复 k 次，并且我们必须在所有这些转换之后输出最终序列。 

思考该过程的一个有用方法是，阵列不断地从前面剥离，而其方向不断翻转。 每次删除后，剩余后缀的相对顺序会根据已经发生的反转次数而变化，这使得如果按字面意思进行直接模拟会变得昂贵。 

约束允许 n 最大为 100000，因此任何物理上反转数组 k 次或重复移动元素的方法都会太慢。 简单的模拟将执行最多 k 次移除，每次反转成本为 O(n)，给出 O(nk)，在最坏的情况下退化为 O(n^2)，并且是不可接受的。 

有两种微妙的边缘情况会暴露出幼稚的错误。 首先，如果 k 接近 n 减一，数组就会变得非常短，并且重复反转会快速改变头部和尾部，因此忘记正确更新索引的实现将会失败。 例如，对于输入 n = 5、k = 4、a = [1, 2, 3, 4, 5]，该过程应仅留下单个元素，但不正确的基于指针的模拟通常会由于交替方向错误而丢弃或重复元素。 

其次，如果此处不允许 k = 0，但通常考虑，或者如果 k = 1，则幼稚的实现可能会在删除之前而不是删除之后反转，这完全改变了结果。 例如，[1, 2, 3, 4]，k = 1 应该产生 [2, 3, 4]，而不是 [4, 3, 2]。 

核心难点在于序列不仅在缩小，而且以结构化的方式交替方向，我们可以在不修改数组本身的情况下进行跟踪。 

## 方法

 直接暴力方法实际上执行所描述的操作。 我们删除列表的第一个元素并反转其余元素，重复此 k 次。 如果使用双端队列，每次删除的时间复杂度为 O(1)，但剩余 n i 个元素的每次反转时间复杂度为 O(n i)，总共为 O(n + (n−1) + … + (n−k))，即 O(nk)。 当 k 很大时，输入大小会成二次方。 

关键的观察是我们实际上并不需要中间数组。 我们只需要知道在 k 次删除之后哪些元素仍然保留以及以什么顺序保留。 该操作交替读取剩余段的方向。 我们可以维护两个代表剩余数组当前左边界和右边界的指针，以及一个代表当前方向是正常还是反转的布尔标志，而不是模拟反转。 

每个操作都会根据方向从活动前沿删除一个元素。 如果我们处于正常方向，我们从左侧移除； 如果相反，我们从右侧删除。 移除后，我们翻转方向。 这消除了实际数组反转的任何需要。 

这将整个过程减少到 O(k) 次指针更新，并且由于 k < n ≤ 100000，因此非常高效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了 |
 | 带方向标志的两个指针 | O(k) | O(n) | 已接受 |

 ## 算法演练

 我们维护两个索引，l 从 0 开始，r 从 n − 1 开始，布尔变量 rev 最初为 false，意味着我们从左侧读取。

1. 初始化 l = 0 和 r = n − 1，并设置 rev = false。 这代表完整的活动段及其当前方向。 
2. 重复 k 次，并在每一步根据转速决定该段的哪一端是“前”。 如果 rev 为 false，则前面在 l 处，否则在 r 处。 这与所有隐式反转后的当前数组完全相同。 
3. 如果 rev 为 false，则将 l 加 1 以删除最左边的元素。 如果 rev 为 true，则将 r 减 1 以删除最右边的元素。 这模拟删除当前方向的第一个元素，而无需物理重新排列任何内容。 
4. 每次拆卸后翻转转速。 这捕获了反转剩余数组的效果。 我们不需要重新排列元素，而是简单地更改我们将哪一侧解释为正面。 
5、经过k次操作后，剩下的一段就是区间[l,r]。 最终方向由 rev 决定。 如果 rev 为 false，我们按升序输出从 l 到 r 的元素。 如果 rev 为真，我们按降序输出从 r 到 l 的元素。 

### 为什么它有效

 在任何时刻，剩余的数组都是仅限于连续段 [l, r] 的原始数组，但可能以相反的顺序查看，具体取决于发生了多少次反转。 每个操作都会删除该线段的一个端点并翻转方向的解释。 不变的是当前逻辑数组始终可表示为原始数组的连续切片加上方向标志。 由于删除和反转都保留了这种结构，因此除了全局翻转之外，没有任何操作会引入不连续性或对元素进行重新排序。 这保证了指针移动和单个布尔标志完全描述了演变的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

l, r = 0, n - 1
rev = False

for _ in range(k):
    if not rev:
        l += 1
    else:
        r -= 1
    rev = not rev

if not rev:
    res = a[l:r+1]
else:
    res = a[l:r+1][::-1]

print(*res)
```该实现保留两个边界 l 和 r 并根据当前方向更新它们。 布尔 rev 跟踪逻辑方向是否翻转。 经过 k 步后，我们提取剩余的片段。 唯一的微妙之处是最终的输出：如果方向反转，我们必须显式反转切片一次。 这可以避免在每一步都反转整个数组并保持解的线性。 

边界处理很简单，因为循环始终保证 l ≤ r，直到恰好完成 k 个删除。

 ## 边缘情况

 一种重要的边缘情况是 k 几乎删除整个数组。 考虑输入：

 n = 5, k = 4, a = [1, 2, 3, 4, 5]

 该过程应该只留下一个元素。 指针模拟进行如下：最初l = 0，r = 4。第一次移除从左边取1，因此l 变为1，rev 变为true。 第二个从右侧删除，r 变为 3。第三个从左侧删除，l 变为 2。第四个从右侧删除，r 变为 2。该段折叠为单个元素 [3]，这是正确输出的。 

另一个边缘情况是最小 k = 1：

 n = 4，k = 1，a = [1,2,3,4]

 我们从左边删除 1，留下 [2, 3, 4]，然后反转与最终输出无关，因为只完成了一步。 该算法与此完全匹配，因为它执行一个指针增量并翻转方向一次，产生 l = 1、r = 3 和 rev = true，但切片的最终反转会恢复正确的顺序。 

最后一个微妙的情况是最后一段已经处于相反方向。 例如：

 n = 3, k = 2, a = [7, 8, 9]

 经过两次操作后，该段为 [1, 1]，并且 rev 为 false 或 true，具体取决于奇偶校验。 该算法确保最终切片仅反转一次，避免重复的结构变化，否则会导致排序不一致。
