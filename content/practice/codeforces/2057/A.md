 ## 解决方案
 ## 问题理解

 我们被要求填写一张表格`n`行和`m`使用每个整数的列`0`到`n*m - 1`正好一次。 填充后，我们计算每行和每列的 MEX（最小排除非负整数）并对所有这些值求和。 任务是**最大化这个总和**。 

输入由多个测试用例组成，每个测试用例给出`n`和`m`。 每个测试用例的输出是一个数字，即所有行和列中 MEX 的最大可能总和。 

约束条件非常大（`1 ≤ n, m ≤ 10^9`），这意味着我们**无法显式构造表**。 任何涉及迭代每个单元的强力尝试都是不可能的。 我们需要一种直接起作用的公式化方法`n`和`m`。 

当其中一个维度为`1`。 例如，一个`1 x 1`表包含单个值`0`，所以 MEX 行是`1`MEX 列是`1`，给出总和`2`。 任何解决方案都必须正确处理这些琐碎但有限的情况。 

## 方法

 暴力方法将尝试枚举表中数字的所有排列，计算所有行和列 MEX 值，并选择给出最大总和的排列。 这在原则上是正确的，但不可行，因为细胞的数量最多可达`10^18`。 

关键的观察结果是，行长度的**最大行 MEX`m`是`m`**，因为一行包含`m`不同的数字从`0`。 类似地，最大列 MEX 的边界为`n`。 由于我们想要所有行 MEX 和所有列 MEX 的总和，因此目标是最大化两者。 

给定`n`行和`m`列，我们可以**不失一般性地假设**每行的 MEX 最多可以达到`min(m, n)`对于列也是如此。 为了使总和最大化，可以选择以下较大者`n`和`m`对于列和较小的行，给出一个简单的公式：$$\text{Maximum sum} = n + m$$此公式之所以有效，是因为您可以在整个表中以增量模式分配数字，从而实现 MEX 等于行中的行长度和列中的列长度，同时考虑可用的不同整数的数量。 这与所有提供的示例输出相匹配。

 | 蛮力 | O((n*m)!) | O(n*m) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取整数`n`和`m`。 
3. 计算 MEX 的最大和为`n + m`。 这是可行的，因为每行的 MEX 可以达到`m`并且每列可以达到`n`，但由于不同的数字，我们只能求和`n + m`。 
4. 打印每个测试用例的结果。 

为什么它有效：通过以增量顺序在网格中排列数字，从`0`并从左到右和从上到下（或类似的模式）填充，每行将包含`0`最多`m-1`某处，给 MEX`m`，每列将包含`0`最多`n-1`某处，给 MEX`n`。 因此总和是`n + m`。 这对于所有维度都是不变的，包括`1x1`和大桌子。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    print(n + m)
```该代码可以有效地读取输入`sys.stdin.readline`。 它计算出答案`O(1)`每个测试用例并且不使用额外的空间。 自从`n`和`m`可以达到`10^9`，我们避免构造数组。

def run(inp: str) -> str:

 ## 边缘情况

 对于一个`1x1`表，算法输出`1 + 1 = 2`。 该表包含`[0]`。 行 MEX 为 1，列 MEX 为 1，总和为 2。该公式工作正常。 

对于极端尺寸，例如`10^9 x 1`或者`1 x 10^9`，算法无需构建表即可正确处理这些值。 总和是`n + m`并且适合 Python 整数。 

对于方桌，公式`n + m`一致应用并避免过度计算 MEX 值，因为我们只计算行和列 MEX，而不计算单个单元格。 

这确保了所有有效输入的正确性。
