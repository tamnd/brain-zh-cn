 ## 解决方案
 ## 问题理解

 我们给出一个最多有 400 个顶点和最多 400 个边的连通无向图。 每条边都有一个正权重。 对于每个查询，我们给出两个顶点`a`和`b`，和一个数字`k`。 在所有可能的简单路径中`a`到`b`，我们考虑沿路径的边权重的多重集。 我们以非递增顺序对这些权重进行排序，并且在选择最佳可能路径后，我们需要排序列表中第 k 个元素的值。 

因此每个查询并不要求最短路径或最小生成树属性。 相反，我们可以选择端点之间的任何路径，并且我们正在尝试优化该路径的统计数据：其上的第 k 大边权重。 

困难来自于不同的路径有不同的长度和不同的权重分布。 具有许多中等边缘的路径可能比具有单个大边缘的路径更好，具体取决于 k。 

就以下方面而言，限制很小`n`和`m`，每个测试用例集的总数都限制为 400，但查询数量可以达到 300,000。 这立即排除了任何每个查询的图遍历或最短路径计算。 甚至`O(n^2)`每个查询都会太慢。 

唯一可行的方向是对图表进行大量预处理，从而允许在大致恒定或对数时间内回答每个查询。 

一个微妙的边缘条件是该问题保证从`a`到`b`至少有`k`边缘。 这可以防止 k 超过路径长度的未定义查询，但这也意味着我们必须考虑至少有 k 条边长的路径，因此简单的“最短路径”逻辑并不直接足够。 

## 方法

 直接方法将枚举之间的所有简单路径`a`和`b`，计算每条路径上的第 k 个最大边，并取所有路径上的最小值。 这在概念上是正确的，但完全不可行。 图中简单路径的数量可以呈指数级增长，即使在具有 400 个顶点的图中，这很快就会变得棘手。 

我们需要进行结构性改革。 关键的观察结果是，答案仅取决于我们可以沿着某条路径累积给定权重阈值的边数。 我们可以二分搜索答案值，而不是按顺序推理精确的边权重。 

确定候选人权重`x`。 假设我们只关心是否能找到一条路径`a`到`b`其中至少包含`k`至少有权重的边`x`。 如果存在这样的路径，则该路径上第 k 大的边权重至少为`x`。 否则它小于`x`。 

这将问题变成了单调可行性检查，这正是二分搜索所需要的。 然而，剩下的困难是我们必须针对许多查​​询有效地评估这种可行性。 

现在我们看看图的结构。 自从`n ≤ 400`，我们可以预处理所有顶点对的可达性信息以及由边权重引起的所有可能的阈值。 标准技巧是按权重对边进行排序，然后将它们增量添加到 DSU 中。 这样做的同时，我们可以保持连接性，并跟踪距离或边缘数量，从而使我们能够回答“最佳路径上存在多少条来自该阈值的边缘”。 

在简单版本中，我们利用了图很小且静态的事实。 我们根据边的数量对所有对最短路径进行预处理，并且还为每对维护有关边权重如何沿着最佳路径累积的信息。 更有效的方法是预先计算，对于每一对`(u, v)`，权重的最大边数至少`x`沿着任何路径，针对所有不同的体重水平`x`。 

因为边的数量很少，我们可以压缩权重，并为每个权重阈值构建一个仅包含≥阈值的边的图。 在这个子图上，我们根据边的数量计算所有对的最短路径，或者在仅限于连接的未加权意义上计算等效的最长路径（因为图很小且足够密集，我们可以根据阈值进行 BFS/DP）。 这给了我们一个表格：`best[u][v][i] = maximum number of edges on a path from u to v using edges of weight ≥ w_i`。 

然后每个查询减少为寻找最小索引`i`这样`best[a][b][i] ≥ k`。 这是对排序的不同权重的二分搜索。 

因为两者`n`和`m`最多为 400，并且不同权重最多为 400，这种预处理是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力路径 | 指数| O(n) | 太慢了|
 | 预计算阈值+BFS/DP+二分查找| O(n^3 + m n log m) | O(n^3 + m n log m) | O(n^2 m) | O(n^2 m) | 已接受 |

 ## 算法演练

 1. 提取所有不同的边权重并按降序对它们进行排序。 这些定义了过滤边缘的阈值。 
2. 对于每个阈值`w_i`，构建一个仅包含权重至少为的边的图`w_i`。 This creates a nested sequence of graphs, each one a subgraph of the previous. This nesting is crucial because it allows reuse of structure implicitly.
 3. 对于每个阈值图，计算一个矩阵`dist[i][u][v]`表示任意简单路径上的最大边数`u`到`v`仅使用该阈值图中的边。 由于循环是允许的，但无助于增加简单路径长度，因此我们有效地计算无向图中的最长简单路径长度，通过仔细处理，这可以减少为 BFS 树上的 BFS 或多源 BFS。 实际上，由于图很小，每个节点重复 BFS/DP 就足够了。 
4.跨阈值存储这些值，以便对于任何对`(u, v)`和阈值`i`，我们知道可用边的最大数量。 
5. 对于每个查询`(a, b, k)`，超过阈值的二分搜索。 对于中点阈值`i`，检查是否`dist[i][a][b] ≥ k`。 如果是，我们可以尝试更高的阈值； 否则我们必须走得更低。 
6. 输出仍然允许至少的最小阈值索引`k`某些路径上的边缘。 

### 为什么它有效

 核心不变量是阈值上的单调性。 如果存在使用边 ≥ 的路径`w_i`其中至少包含`k`边缘，那么相同的属性适用于任何较低的阈值`w_j ≤ w_i`，因为降低阈值只会增加更多的边，而不会减少可达性或最优路径中可用边的数量。 这种单调结构确保二分查找是有效的。 

第二个关键属性是，对于固定阈值，最大化边数方面的最佳路径是每对独立的，因此可以预先计算。 这在预处理后将查询与图结构完全解耦。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    edges = []
    weights = set()

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, w))
        weights.add(w)

    weights = sorted(weights, reverse=True)
    idx = {w:i for i, w in enumerate(weights)}
    T = len(weights)

    # adj per threshold
    adj = [[] for _ in range(T)]
    for u, v, w in edges:
        for i in range(idx[w] + 1):
            adj[i].append((u, v))

    # dist[t][u][v] = max number of edges from u to v in graph t
    dist = [[[0]*n for _ in range(n)] for _ in range(T)]

    for t in range(T):
        g = [[] for _ in range(n)]
        for u, v in adj[t]:
            g[u].append(v)
            g[v].append(u)

        for s in range(n):
            dp = [-1]*n
            dp[s] = 0
            stack = [s]
            while stack:
                x = stack.pop()
                for y in g[x]:
                    if dp[y] < dp[x] + 1:
                        dp[y] = dp[x] + 1
                        stack.append(y)
            dist[t][s] = dp

    for _ in range(q):
        a, b, k = map(int, input().split())
        a -= 1
        b -= 1

        lo, hi = 0, T - 1
        ans = T - 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if dist[mid][a][b] >= k:
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(weights[ans])

if __name__ == "__main__":
    solve()
```预处理构建了按权重阈值递减排序的图表层次结构。 对于每个阈值，我们构建一个邻接列表，其中仅包含满足该阈值的边。 然后，对于每个源节点，我们运行松弛式 DFS，更新每个其他节点可到达的最大边数。 这有效地计算了未加权图中的最长路径，这是有效的，因为重复访问只会增加计数，并且我们总是存储最佳可见值。 

然后，每个查询都在阈值上使用二分搜索。 关键细节是`dist[t][a][b]`是单调的`t`，这样我们就可以高效地搜索。 

## 工作示例

 我们追踪一个简化的案例来说明阈值行为。 

输入：```
1
4 3 1
1 2 5
2 3 2
3 4 1
1 4 2
```我们有权重`[5, 2, 1]`。 

| 阈值| 允许的边缘 | 距离[1][4] |
 | --- | --- | --- |
 | 5 | (1-2) | 无法到达 |
 | 2 | (1-2, 2-3) | 2 |
 | 1 | 所有边缘| 3 |

 询问`(1, 4, 2)`要求路径至少有 2 条边的最小阈值。 

二分查找：

 | 中| 阈值| 距离 | 有效 |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 | 是的 |
 | 0 | 5 | 信息 | 没有|

 答案是`2`。 

这演示了增加阈值如何限制路径并减少可实现的路径长度。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^3·T + q log T) | O(n^3·T + q log T) | 对于每个阈值，我们运行 n 个 BFS/DFS，每个 O(n^2) 处于密集邻接 |
 | 空间| O(n^2·T) | O(n^2·T) | 存储每个阈值的所有对最佳路径长度 |

 该界限是可以接受的，因为两者`n`和`m`最多 400 个，所以`T ≤ 400`，使得三次预处理在一定范围内可行，同时查询时间减少到对数。

 ## 边缘情况

 关键的边缘情况是最佳路径使用绕道将边数增加到 k 以上。 例如，在三角形图中，最短路径可能只有 1 条边，但通过另一个顶点的较长路径可以满足 k=2，即使它在经典最短路径意义上不是最优的。 预处理可以处理这个问题，因为 DFS 探索所有简单扩展并保留可到达的最大深度。 

另一种边缘情况是当存在具有相同端点但不同长度分布的多条路径时。 该算法始终存储每个阈值可实现的最大边缘计数，确保无论路径结构如何，都会考虑最佳可能的配置。
