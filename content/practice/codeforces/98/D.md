 **求解时间：** 1m 50s

 ## 解决方案
 ## 问题理解

 我们得到了一个带有三根柱子的河内塔变体，`n`圆盘堆放在第一根柱子上。 圆盘从下到上列出，与经典问题不同，多个圆盘可能具有相同的直径。 

一次移动仍然会在柱子之间恰好转移一个圆盘。 较大的磁盘永远不能放置在严格较小的磁盘之上。 允许相同直径的材料相互堆叠。 

目标不仅仅是将所有磁盘从支柱上移走`1`到柱子`3`，而且还保留其原始顺序。 如果两个相等的圆盘出现在位置`i < j`最初，然后从位置相同的磁盘`i`必须仍然保持在磁盘下方的位置`j`在最终配置中。 

输出必须包含尽可能少的移动次数，然后是一个最佳的移动序列。 

这些约束足够小，足以允许不同直径组的数量呈指数行为，但不允许磁盘总数呈指数行为。 我们有`n ≤ 20`，所以即使`2^20`状态是可控的，而任何阶乘或涉及所有塔状态的不受限制的 BFS 都会变得危险。 可能的汉诺塔配置数量增长得非常快，并且对配置进行简单的最短路径搜索是不现实的。 

关键的结构特性是直径相等的磁盘几乎就像可互换的块一样。 一旦我们了解了相等的磁盘如何影响递归，问题就会分解为有效深度更小的改进的 Hanoi 递归。 

一些边缘情况很容易被错误处理。 

假设所有磁盘都是相等的：```
3
1 1 1
```粗心的解决方案可能会认为答案仍然是`7`因为经典河内需要三个磁盘`2^3 - 1`移动。 但是相同的圆盘可以自由堆叠，因此我们可以简单地将每个圆盘直接从柱子上移动`1`到柱子`3`:```
3
1 3
1 3
1 3
```另一个微妙的情况是保持相等磁盘之间的顺序：```
3
2 2 2
```如果顺序不重要，则可以将堆栈视为单个对象，并在概念上一次性完成。 但移动仍然单独操作物理磁盘，并且最终顺序必须与初始顺序匹配。 最小值仍然准确`3`直接移动。 

一个更有趣的例子是：```
4
3 2 2 1
```中间的两个圆盘相等。 独立处理每个磁盘的简单递归给出`15`移动。 但相等的对可以更有效地一起转移，从而减少最佳答案。 

面临的挑战是在不打破排序限制的情况下准确识别相同的磁盘可以节省多少成本。 

## 方法

 蛮力视角是将每个合法的塔配置建模为图状态，并从初始排列到目标排列运行 BFS。 

这是可行的，因为每次移动都有相同的成本，所以 BFS 确实找到了最短序列。 每个状态记录了每个磁盘的支柱，可以直接检查合法性。 

问题在于状态计数。 即使只有`20`磁盘，最多有`3^20 ≈ 3.4 × 10^9`圆盘到柱子的分配。 大多数都是非法的，但合法的国家空间仍然是天文数字。 BFS是完全不可行的。 

经典的河内塔重现表明了一种更加结构化的方法。 在普通问题中，要移动最大的磁盘，必须首先移走每个较小的磁盘。 然后最大的圆盘移动一次，最后较小的圆盘在上面重建。 这给出：$T(n)=2T(n-1)+1$整个困难来自于磁盘大小的严格排序。 

现在考虑当几个连续的圆盘具有相同直径时会发生什么变化。 

假设顶部`k`所有磁盘共享相同的大小。 一旦它们上面的所有较小的磁盘都被移除，这些`k`相同的圆盘可以在目的地柱子处直接一个接一个地转移到彼此上。 他们不再需要在每次移动之间进行昂贵的递归重建。 

这完全改变了复发情况。 

让不同的直径组具有尺寸：```
c1, c2, ..., cm
```从最大直径到最小直径排序。 

如果我们已经知道如何最佳地移动所有较小的组，那么对于一组大小`c`:

 1. 将所有较小的团体移开。 
2、直接移动整个等径组，要求精确`c`移动。 
3. 将较小的组向后移动。 

所以递归式变为：$F(i)=2F(i+1)+c_i$这种重复是最佳的，因为当前组中的每个磁盘必须至少物理移动一次，并且每个较小的磁盘必须离开并稍后返回以解锁它们。 

构造部分几乎完全反映了经典的河内递归，只是相同的磁盘是连续传输的，而不是递归分离的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 BFS 遍历状态 | 状态数量呈指数增长，大致$O(3^n)$|$O(3^n)$| 太慢了|
 | 递归构造解|$O(M)$， 在哪里$M$是移动次数 |$O(n)$递归栈| 已接受 |

 这里`M`是最优步数本身，仍然可以达到`2^20 - 1`，但这大约只有一百万步，完全在限制范围内。 

## 算法演练

 1. 将圆盘压缩成直径相等的连续组。 

例如：```
5 5 3 3 3 1
```变为团体规模：```
[2, 3, 1]
```我们只关心每个不同直径贡献了多少个圆盘。 
2. 从最大直径到最小直径递归地处理分组。 

让`solve(i, from, to, aux)`从索引开始移动所有组`i`。 
3.如果`i`达到组数，停止。 

没有剩余的磁盘可以移动。 
4. 首先递归地将所有较小的组移开。 

称呼：```
solve(i + 1, from, aux, to)
```这将清除当前直径组上方的每个磁盘。 
5. 直接移动当前组中的每个磁盘`from`到`to`。 

由于该组中的所有圆盘具有相同的直径，因此它们可以自由地相互堆叠。 

如果组大小为`k`, 准确附加`k`相同的动作：```
from -> to
```6. 递归地重建顶部的较小组。 

称呼：```
solve(i + 1, aux, to, from)
```7. 收集所有动作并打印它们。 

### 为什么它有效

 递归保留了与经典河内相同的不变量。 

在移动直径组之前，每个较小的圆盘都会暂时重新定位到辅助柱上。 这保证了当前组被暴露。 由于组内的所有磁盘都是平等的，因此将一个磁盘移动到另一个磁盘上始终是合法的。 

当该组到达其目的地支柱后，较小的组将按照其原始的相对顺序在顶部重建。 

最优性源于必要性。 当前组中的每个磁盘必须至少移动一次。 在任何此类移动变得合法之前，必须删除所有较小的磁盘。 之后，那些较小的圆盘必须在最终排列中返回到该组的上方。 这会强制执行两个递归子问题，加上当前组中每个磁盘的一次移动，与算法使用的递归相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

moves = []

def solve(groups, idx, src, dst, aux):
    if idx == len(groups):
        return

    solve(groups, idx + 1, src, aux, dst)

    for _ in range(groups[idx]):
        moves.append((src, dst))

    solve(groups, idx + 1, aux, dst, src)

def main():
    n = int(input())
    d = list(map(int, input().split()))

    groups = []
    i = 0

    while i < n:
        j = i
        while j < n and d[j] == d[i]:
            j += 1
        groups.append(j - i)
        i = j

    solve(groups, 0, 1, 3, 2)

    print(len(moves))
    print("\n".join(f"{a} {b}" for a, b in moves))

if __name__ == "__main__":
    main()
```第一部分将连续的相等直径压缩为组大小。 这是核心的简化。 组内的个人身份不再重要，因为相同的磁盘可以自由堆叠，同时自动保持顺序。 

递归`solve`功能反映了经典的河内结构。 唯一的区别是中间阶段。 我们不移动一个最大的圆盘，而是直接移动整个等直径的块。 

递归调用的顺序至关重要。 第一个递归调用将较小的磁盘从源柱中清除。 第二个在目标堆栈顶部重建它们。 交换这些调用违反了合法性。 

一个常见的错误是试图在概念上将相同的磁盘移动到一起，而不是在物理上一个一个地移动。 该语句仍然要求每一步都恰好传输一个磁盘。 这就是循环附加的原因`groups[idx]`单独的动作。 

递归深度最多为不同直径值的数量，永远不会超过`20`，所以Python递归在这里是完全安全的。

 ## 边缘情况

 考虑：```
3
1 1 1
```groups 数组变为：```
[3]
```递归立即从支柱执行三个直接移动`1`到柱子`3`。 

输出：```
3
1 3
1 3
1 3
```这说明了为什么压缩相同直径是正确的。 组内不需要递归分离。 

现在考虑：```
4
4 4 3 3
```这些团体是：```
[2, 2]
```执行过程如下：

 1. 移动规模较小的组`2`到辅助柱。 
2.直接用两步移动较大的相等组。 
3. 将较小的组移回原处。 

递归给出：$F=2\cdot2+2=6$事实上，最佳解决方案恰好使用六步。 

最后，检查完全不同的情况：```
4
4 3 2 1
```这些团体变成：```
[1, 1, 1, 1]
```该算法精确地简化为普通河内并输出`15`移动。 这证实了当不存在相等直径时，广义递归保留了经典行为。
