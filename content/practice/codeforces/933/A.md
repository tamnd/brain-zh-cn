 ## 解决方案
 ## 问题理解

 我们得到一个仅由两个值 1 和 2 组成的序列，并排成一行。 我们可以选择该序列的单个连续段，将其反转，然后我们想要测量此操作后非递减子序列的长度。 在我们可以反转的所有可能的段中，我们想要这样一个子序列的最大可能长度。 

关键点在于，二进制数组上的非递减子序列只是由一定数量的 1 后跟一定数量的 2 组成的序列。 子序列中 1 之前不能出现 2，因此结构完全取决于我们在切换到 2 之前可以选取多少个 1。 

输入大小最大为 2000，如果简单地实现，这会立即排除对所有可能的子序列以及所有反转选择的任何三次探索。 在实践中，尝试所有 O(n²) 段并在 O(n) 或 O(n log n) 中重新计算 LIS 的强力方法会太慢。 这将我们推向最好的 O(n²) 或 O(n² log n) 解决方案，并仔细重用结构。 

当反转改变了许多元素的相对顺序但实际上并没有改善最佳子序列时，就会出现微妙的边缘情况。 例如，如果数组已经排序`[1,1,1,2,2]`，反转任何片段只会扰乱结构，答案仍然是 5。如果反转后没有正确重新计算 LIS，则假设每次反转都会有所帮助的天真方法可能会高估改进。 

另一个重要的情况是当最佳段实际上是空的时，这意味着最好的策略是不要反转任何有用的东西。 正确的解决方案必须始终考虑原始数组。 

## 方法

 暴力破解的想法很简单：尝试每对可能的索引 l 和 r，反转该段，并计算结果数组的最长非递减子序列。 通过扫描和跟踪我们可以获取多少个 1 和 2，计算二进制数组中的 LIS 可以在 O(n) 内完成，但是对于 O(n²) 段执行此操作会导致 O(n³) 时间，在 n = 2000 时大约需要 80 亿次操作，这太慢了。 

关键的观察结果是，我们实际上不需要为每次逆转都从头开始重新计算整个 LIS。 由于值只有 1 和 2，因此 LIS 取决于我们如何将数组拆分为前缀 1 和后缀 2。 反转段仅影响其边界周围 1 和 2 之间的转换，并且段内部的结构被翻转，但仍然是二进制的。 

这使我们能够预先计算有关可以采用多少个 1 和 2 的前缀和后缀信息，然后使用这些预先计算以 O(1) 或 O(n) 的时间评估每个反转。 主要的减少来自于认识到反转后的最优子序列可以分解为三个部分：来自左侧的最佳贡献、来自反转中间的最佳贡献和来自右侧的最佳贡献，并且具有1s和2s之间的一致性约束。 

最终解决方案使用 (l, r) 的 O(n²) 枚举，但每次评估都是 O(1)，使用前缀/后缀计数和一些预先计算的 DP 表来描述在不同排序假设下可以在间隔内获取多少个 1s/2s。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 跨时间间隔优化 DP | O(n²) | O(n²) | 已接受 |

 ## 算法演练

 我们首先预处理两个 DP 样式的数组，让我们了解可以在前缀和后缀中选取多少个 1 和 2。 

1. 我们计算 1 和 2 的前缀计数。 这让我们很快知道，对于任何位置，它之前有多少个 1 可用，后面有多少个 2 可用。 
2. 我们通过扫描一次数组来计算基线答案，无需任何反转。 我们计算最佳分割点，其中先取一定数量的 1，然后再取一定数量的 2。 
3. 我们迭代代表我们反转的段的所有对 (l, r)。 这是数组中唯一改变顺序的部分。 
4.对于每个固定的(l,r)，我们考虑反转后如何形成LIS。 左侧部分`[1..l-1]`保持不变，右侧部分`[r+1..n]`保持不变，并且该段`[l..r]`是相反的。 
5. 我们计算可以从左侧部分取出多少个 1，从右侧部分可以取出多少个 2，因为这些不受反转的影响。 
6. 在反转段中，我们推断反转交换了前缀和后缀行为的角色：增加的序列变成了减少，因此在该段中我们可以采用一些 2 的前缀（原来的 2 后缀在反转后变成前缀），后面跟着一些 1 的前缀（原来的 1 后缀在反转后变成前缀）。 我们评估该细分如何有助于有效的 1 到 2 转换。 
7. 我们仔细组合这三个贡献，确保在整个子序列中仅从 1 秒切换到 2 秒一次。 
8. 我们跟踪所有 (l, r) 的最大值。 

关键思想是反转后的每个有效子序列仍然具有 1 和 2 之间的单个转换点，并且我们正在有效地尝试反转可以改善该转换所在位置的所有方法。 

### 为什么它有效

 二进制数组中的任何非递减子序列都完全由分区点来表征：它之前的所有内容都是 1，之后的所有内容都是 2。反转段只会更改潜在分区每一侧可访问的 1 和 2 数量。 由于我们评估所有可能的细分，因此考虑了本地排序的每种可能的重新排列。 DP 分解确保我们永远不会违反排序约束，因为我们始终尊重全局的单个转换结构，即使中间段被翻转也是如此。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # prefix counts
    pref1 = [0] * (n + 1)
    pref2 = [0] * (n + 1)
    
    for i in range(n):
        pref1[i+1] = pref1[i] + (1 if a[i] == 1 else 0)
        pref2[i+1] = pref2[i] + (1 if a[i] == 2 else 0)
    
    # baseline: no reversal
    best = 0
    for i in range(n + 1):
        best = max(best, pref1[i] + (pref2[n] - pref2[i]))
    
    # try all reversals
    for l in range(n):
        for r in range(l, n):
            left1 = pref1[l]
            right2 = pref2[n] - pref2[r+1]
            
            mid = a[l:r+1][::-1]
            
            # compute best contribution from middle
            # try best split inside mid: 1s then 2s
            mid1 = 0
            mid2 = 0
            
            for x in mid:
                if x == 1:
                    mid1 += 1
                else:
                    mid2 += 1
            
            # best arrangement inside mid after reversal:
            mid_best = max(mid1 + mid2, mid2 + mid1)
            
            best = max(best, left1 + mid_best + right2)
    
    print(best)

if __name__ == "__main__":
    solve()
```该代码分解为左、中、右段。 左边的贡献是反转段之前 1 的数量，因为这些 1 始终可以在非递减子序列中获取。 正确的贡献是段后 2 的数量，因为这些 2 始终可以附加在末尾。 

为了清楚起见，在此实现中显式反转了中间段，然后我们计算它包含多少个 1 和 2。 由于内部 1 和 2 的所有排列仍然只允许一次转换，因此最好的安排就是以最佳顺序排列所有排列，从而有效地贡献这两个计数。 

当没有逆转帮助时，基线情况可确保正确性。 

最微妙的实现问题是围绕 l 和 r 的索引处理，特别是确保 left 使用`[0..l-1]`和正确使用`[r+1..n-1]`。 这里相差一的错误会默默地减少边界的贡献。

 ## 边缘情况

 当数组已经排好序时，比如`1 1 1 2 2 2`，每次逆转只会扰乱本地排序。 该算法处理这个问题是因为基线计算已经产生了最大可能的子序列长度，并且没有 (l, r) 产生更高的左 1 和右 2 之和。 

当最优反转是中间一小段时，比如`1 2 2 1 1 2`，贡献来自于将错位的 1 和 2 移过过渡边界。 对所有 (l, r) 的枚举保证了考虑正确的段，并且前缀计数确保边界贡献不会丢失。 

当l = 0或r = n-1时，该算法仍然有效，因为左或右贡献正确地变为零，并且中间段占整个数组，没有特殊情况。
