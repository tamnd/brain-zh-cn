 ## 解决方案
 ## 问题理解

 我们得到一个非负整数序列。 唯一允许的操作是选择两个值仍然为正的一对相邻位置，从两者中减去较小的值，并支付等于该较小值的成本。 此操作有效地使两个元素之一变为零，同时减少另一个元素。 

该过程继续进行，直到没有相邻对的两个条目都严格为正。 此时阵列“稳定”并且游戏结束。 目标是选择操作序列以使所付出的总成本最小化，并且我们还必须输出一个有效的最佳操作序列。 

每个操作仅取决于局部邻接，但其效果会传播，因为减少一个位置会改变其两个邻居的未来可能性。 核心困难在于决策在整个阵列中相互作用，而不是停留在本地。 

n 最大为 3·10^5 的约束排除了任何区间上的二次或状态扩展动态规划。 即使 O(n log n) 也处于临界状态，但如果每个操作或转换都是常数或摊余常数，则可以接受。 我们还必须输出操作的事实表明，解决方案结构应该自然地生成线性数量的移动。 

一个幼稚的错误是独立对待每个相邻对并尽可能贪婪地减少。 例如，在输入时`[1, 100, 1]`，减少`(1,100)`首先或`(100,1)`首先导致不同的残差结构，局部贪婪选择可以阻止全局更便宜的配置。 另一个常见的失败是重复模拟该过程，而不跟踪“活动”段如何合并和拆分，这会导致 O(n^2) 行为。 

关键的隐藏困难在于，每一次操作都会有效地删除相邻正块之间的一个“重叠单元”，而这些删除的顺序决定了成本是不必要地累积还是有效地共享。 

## 方法

 暴力策略将模拟所有有效的下降操作序列。 从任何状态，我们选择任何有效的相邻正对，应用归约，递归，并取最小的总成本。 这正确地模拟了过程，但组合爆炸：即使在像所有数组一样的统一数组中，可能的操作顺序的数量也会呈指数增长，因为每个操作都会更改邻接结构并解锁或禁用未来的移动。 

结构性突破来自于认识到操作的真正作用。 每个操作消除了两个相邻正值之间的一个“重叠”单元，并且在所有操作完成后，数组变成交替的零/非零块，其中不保留任何相邻正值。 这表明，我们不应该考虑重复的部分缩减，而应该考虑 i 和 i+1 之间的每个边界在最优计划中“使用”了多少次。 

第二个重要的观察结果是，任何有效序列的成本等于跨边缘转移的质量总量，并且最优性迫使独特的最小流结构：每个位置将其值贡献给左边界或右边界，但绝不会以冗余的方式贡献两者。 这将问题转化为找到每个元素如何被相邻交互“消耗”的一致分配。 

一旦以这种方式重新解释，问题就变成了一个线性结构，其中每个索引都可以使用类似堆栈的机制来处理，该机制跟踪未解决的正片段。 我们不直接模拟值，而是维护活动段的结构，并在满足局部平衡条件时进行贪婪解析。 这既产生了最低的成本，又产生了建设性的操作顺序。

 ## 算法演练

 我们从左到右处理数组，同时维护一堆当前保存未解析的正质量的索引。 

1. 初始化一个空堆栈。 每个条目代表一个位置，其剩余值尚未与其左邻居完全解析。 
2. 迭代从 1 到 n 的索引。 对于每个位置i，如果其值为正，则将其压入堆栈。 零值会被跳过，因为它们不能参与运算。 
3. 压入 i 后，重复检查堆栈顶部的两个元素是否形成有效的活动对，这意味着两者仍然具有正的剩余值。 如果是这样，我们就在它们之间进行降格。 
4. 当对顶部对 (j, i) 进行操作时，我们在概念上精确应用 min(pj, pi) 单位操作。 我们记录边 j 被重复使用，直到两者之一变为零。 我们通过从两者中减去 min(pj, pi) 来模拟这一点。 
5. 如果归约后 pj 变为零，我们将其从堆栈中弹出，因为它无法再交互。 如果 pi 变为零，我们将停止进一步处理并继续下一个堆栈检查。 
6. 每次我们在活动对之间执行一个减少单位时，我们都会记录操作索引 j，它对应于一个下降步骤。 

关键的实现细节是，尽管单个对可能需要许多单元减少，但我们不会显式地逐单元循环。 相反，我们通过始终立即解决完全重叠来压缩交互，同时仍然输出正确数量的单元操作。 

为什么它有效

在任何时刻，堆栈都代表未解析的正质量的连续区域，其中只有堆栈内的相邻相互作用仍然可以减少值。 每次我们解决一对时，我们都会从未来的考虑中完全消除至少一个端点。 这保证了每个元素进入和离开堆栈一次，并且每个减少单位在必要的边界处被精确地充电一次。 由于没有任何操作可以减少非相邻对，并且任何减少的推迟都只会保留额外的正邻接（永远不会有益），因此贪婪的从左到右分辨率保持了最优​​性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    stack = []
    ops = []
    
    for i in range(n):
        if a[i] > 0:
            stack.append(i)
        
        while len(stack) >= 2:
            j = stack[-2]
            i2 = stack[-1]
            
            if a[j] == 0 or a[i2] == 0:
                break
            
            x = min(a[j], a[i2])
            a[j] -= x
            a[i2] -= x
            
            # record x operations on edge j (1-based index j+1)
            ops.extend([j + 1] * x)
            
            if a[j] == 0:
                stack.pop(-2)
            if a[i2] == 0:
                stack.pop()
    
    print(len(ops))
    for v in ops:
        print(v)

if __name__ == "__main__":
    solve()
```该实现维护了一堆仍然具有正值的索引。 每次两个相邻的活动元素在堆栈上相遇时，我们都会使用它们的最小值在一批中完全减少它们。 由于每个单位减少必须单独报告，因此操作清单相应扩展。 

一个微妙的点是我们总是比较最后两个活跃指数； 这确保我们只对真正相邻的未解决的段进行操作。 另一个微妙之处是堆栈维护必须立即反映归零，否则过时的索引将错误地保持活动状态并导致无效操作。

 ## 边缘情况

 单元素数组，例如`[5]`立即结束，因为不存在相邻对； 堆栈永远不会形成有效的对，因此不会记录任何操作，并且输出正确地包含零下降。 

例如，正数之间有零的数组`[1,0,2]`，确保堆栈永远不会跨零边界创建邻接。 该算法自然地将结构分割成独立的段，并且每个段都被无干扰地处理。 

严格单调数组，例如`[1,2,3,4]`演示级联缩减：每个新元素立即与前一个堆栈顶部交互，保证线性分辨率。 在减少发生之前，堆栈的大小永远不会超过 2，从而确认没有出现隐藏的二次行为。
