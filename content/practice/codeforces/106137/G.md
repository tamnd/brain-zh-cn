 ## 解决方案
 ## 问题理解

 我们有一棵有根树，其根是顶点`1`。 每个顶点都有两种颜色之一：黑色或白色。 对于每个顶点，我们考虑从该顶点开始并包含该顶点的所有后代（包括顶点本身）的子树。 当子树内部黑色顶点的数量与白色顶点的数量完全相同时，该子树被称为平衡子树。 任务是计算有多少个顶点具有平衡子树。 

输入通过父指针描述树。 对于每个顶点`2`到`n`，我们得到它的父顶点，它始终是编号较小的顶点。 颜色字符串按顺序给出每个顶点的颜色。 

这些约束是解决方案需要基于单树遍历的主要原因。 所有测试用例的顶点总数最多为`2 * 10^5`，所以一个`O(n)`或者`O(n log n)`方法很舒服。 重复探索每个子树的解决方案会变得太慢，因为链状树可以使子树大小之和达到`O(n^2)`，这是周围`4 * 10^10`大投入的操作。 

关键边缘情况是由每个顶点局部的子树大小和颜色计数引起的。 

考虑一棵树，除了根之外还有一个顶点：```
2
1
BW
```根子树包含一个黑色和一个白色顶点，所以答案是`1`。 只检查叶子的粗心解决方案会错过根。 

另一种情况是：```
3
1 1
BBB
```每个子树只包含黑色顶点，所以答案是`0`。 仅将子树大小与颜色计数进行比较而忘记颜色贡献的解决方案将产生不正确的结果。 

最终的边界情况是一条链：```
4
1 2 3
BWBW
```子树从下到上包含：```
vertex 4: B
vertex 3: WB
vertex 2: BWB
vertex 1: BWBW
```仅顶点`1`和`3`是平衡的，所以答案是`2`。 在孩子之前处理父母的实现可能会使用不完整的信息并在这种结构上失败。 

## 方法

 直接的方法是从每个顶点开始 DFS。 在对选定顶点进行 DFS 期间，我们计算其子树中的黑色和白色顶点，并检查两个计数是否相等。 这是正确的，因为每个顶点都根据平衡子树的确切定义进行独立检查。 

问题是重复工作。 在一连串的`n`顶点，顶点的子树`1`有`n`顶点，顶点的子树`2`有`n-1`顶点等。 访问的顶点总数变为：```
n + (n - 1) + (n - 2) + ... + 1 = O(n^2)
```为了`n = 200000`，这已经远远超出了时限内可以运行的范围了。 

树结构给了我们一个更好的方式。 顶点的子树正是其子树的子树加上顶点本身的并集。 当我们处理完一个顶点的所有子节点时，我们已经知道计算该顶点的颜色平衡所需的一切。 

我们可以存储一个值，而不是存储两个单独的计数。 让黑人贡献力量`-1`和白色贡献`+1`。 当黑色和白色顶点的数量相等时，子树的总和为零。 后序 DFS 计算每个顶点的总和，并在总和变为零时递增答案。 

暴力方法之所以有效，是因为它重复重建每个子树的颜色计数。 观察到每个子树都是从已处理的子子树构建的，这让我们可以重用该信息并将问题简化为一次遍历。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 根据父数组构建子数组的邻接表。 每个顶点只需要访问其直接子节点，因为子树信息将从下向上收集。 
2. 从根开始运行 DFS。 在处理当前顶点之前，遍历必须完成所有子节点，因为当前子树取决于其后代的已计算值。 
3. 对于一个顶点`u`，开始平衡`+1`如果它是白色的并且`-1`如果是黑色的。 然后添加所有子顶点返回的余额。 
4. 将所有孩子合并后，检查是否平衡`u`为零。 如果是，则子树`u`包含相同数量的黑色和白色顶点，因此增加答案。 
5. 返回计算出的余额`u`给它的父级。 父级将使用该值作为其自己的子树计算的一部分。 

为什么它有效：

 不变量是 DFS 完成一个顶点后`u`，返回的值正是 的子树内白色和黑色顶点之间的差值`u`。 基本贡献为`u`代表它自己的颜色，每个孩子都贡献其子树已经正确的差异。 由于整个子树是顶点本身加上所有子子树，因此计算的总和是正确的。 当差值为零时，子树恰好是平衡的，因此每个平衡子树都会被计数一次，并且不会计算不平衡子树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        children = [[] for _ in range(n)]

        parents = list(map(int, input().split()))
        for i, p in enumerate(parents, start=1):
            children[p - 1].append(i)

        s = input().strip()

        ans = 0
        balance = [0] * n

        stack = [(0, 0)]
        order = []

        while stack:
            u, state = stack.pop()
            if state == 0:
                stack.append((u, 1))
                for v in children[u]:
                    stack.append((v, 0))
            else:
                order.append(u)

        for u in order:
            cur = 1 if s[u] == 'W' else -1
            for v in children[u]:
                cur += balance[v]

            balance[u] = cur
            if cur == 0:
                ans += 1

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入被转换为子邻接列表。 顶点内部从零开始编号，避免了遍历过程中重复减一。 

迭代 DFS 创建后序序列。 递归 DFS 也是可能的，但对于长链树来说，Python 递归深度太小。 显式堆栈模拟递归，同时安全地处理最大深度。 

这`order`列表包含添加所有后代后的顶点。 从左到右处理此列表可提供与后序 DFS 相同的效果。 当处理一个顶点时，每个子节点都已经有了最终的平衡。 

存储的值`balance[u]`是整个子树的色差。 使用`+1`和`-1`避免存储两个计数器并使平衡条件成为简单的零比较。

 ## 边缘情况

 对于最小的平衡情况：```
2
1
BW
```DFS首先处理顶点`2`。 其余额为`-1`，所以不计算在内。 根接收该值并添加自己的值`+1`，生产`0`。 答案就变成了`1`。 

对于每个顶点具有相同颜色的树：```
3
1 1
BBB
```每片叶子都会回归`-1`。 根结合了孩子和它自己的`-1`， 导致`-3`。 没有顶点达到平衡零，因此算法输出`0`。 

对于链条：```
4
1 2 3
BWBW
```遍历结束顶点`4`首先，然后`3`， 然后`2`， 然后`1`。 他们的余额是`-1`,`0`,`-1`， 和`0`分别。 答案是`2`，该示例证实该算法取决于在父处理之前准备好子结果。
