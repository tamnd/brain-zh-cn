 ## 解决方案
 ## 问题理解

 该任务围绕矩形网格构建，其中每个单元格要么贡献一些非负值，要么代表空地。 “湖”是通过对通过共享边（而不是对角线）连接的单元进行分组而形成的，并且属于同一有意义的区域（通常是非空单元）。 每个这样的区域都有一个通过将其内部所有数字相加而获得的总值。 目标是确定所有这些湖泊中最大的总价值。 

用图的术语来说，每个单元都可以看作一个节点，并且正交相邻单元之间存在边。 然后，网格变成一个隐式图，要求我们找到连接的组件并计算每个组件的权重。 

约束足够大，以至于不标记访问单元的简单重复洪水填充会太慢，因为每个单元最多必须处理一次。 跨多个搜索重新访问单元格的解决方案会降低网格大小的二次行为，这对于 10^6 个单元格等典型限制是不可接受的。 

一些边缘情况很容易被忽略。 一种是当网格仅包含空单元格时，其中不存在通常意义上的湖泊，并且答案应该为零。 

例如，像这样的网格：```
0 0
0 0
```产生的答案为 0，因为没有可累积的正区域。 

另一种情况是每个单元格都是单个连接湖的一部分：```
1 2
3 4
```在这里，整个网格形成一个组件，答案必须是 10。如果粗心地单独处理每个单元，则会错误地返回 4，从而无法正确合并连接。 

第三种微妙的情况是，当存在多个互不相连的湖泊时，只有最大的湖泊才重要，而不是它们的数量或结构。```
1 0 2
1 0 2
```这包含两个独立的湖，总和分别为 2 和 4，因此正确答案是 4。 

## 方法

 一种直接的方法是将每个像元视为湖泊的潜在起点，并在其非零且未被访问时对其进行洪水填充或深度优先搜索。 每次洪水填充都会探索所有可到达的单元格，并对它们的值进行求和。 

这是正确的，因为它尊重连通性：每个单元都属于一个最大连通组件，并且从该组件中任何未访问的单元开始的洪水填充将发现所有它。 

然而，如果在没有访问结构的情况下实现，则将从多个起点重复探索同一区域。 在全填充网格的最坏情况下，每个 DFS 可以遍历几乎整个网格，从而导致大约 O((nm)^2) 操作。 这远远超出了可行的限度。 

关键的观察结果是每个单元只需要处理一次。 一旦将其分配给组件，就绝不能重新访问它。 这将问题转化为网格上标准的连通组件遍历。 对访问数组使用 DFS 或 BFS 可确保单元数量的线性复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 无需访问即可暴力填充洪水 | O((纳米)^2) | O(1) | O(1) | 太慢了 |
 | 具有访问数组的网格 DFS/BFS | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 读取网格尺寸和网格值。 每个单元都被视为具有相关权重的节点。 
2. 维护一个布尔矩阵`visited`与网格大小相同。 这可以防止重新访问已经属于处理过的湖的细胞。 
3. 迭代网格中的每个单元格。 当某个单元格的值为零或已被访问时，请跳过它，因为它无法启动新湖或已被占用。 
4. 当遇到未访问的非零单元时，使用堆栈或队列从其开始泛洪填充。 用其值初始化运行总和。 这个总和代表了当前湖泊的总价值。 
5. 在洪水填充期间，弹出一个单元格，并检查其四个邻居。 对于每个邻居，如果它位于网格内、未访问且非零，则将其标记为已访问并将其值添加到运行总和中，然后将其推入堆栈或队列。 这确保我们一次就完全探索连接的组件。 
6. 洪水填充完成后，将计算出的总和与迄今为止看到的最佳答案进行比较，并保留最大值。 

正确性依赖于这样一个事实：每个连接的组件都从其一个单元格输入一次，并且遍历扩展到包括所有可到达的单元格，没有遗漏或重复。 

### 为什么它有效

 访问的数组强制将网格划分为不相交的探索区域。 每个洪水填充都在 4 方向邻接下的一个连接组件上运行。 由于邻接是对称的，因此从起始单元格可到达的任何单元格都必须是同一组件的一部分，并且该组件中的每个单元格都可以从其中的任何其他单元格到达。 这保证了遍历既不会泄漏到组件外部，也不会错过任何内部单元。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    visited = [[False] * m for _ in range(n)]
    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    best = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 0 or visited[i][j]:
                continue

            stack = [(i, j)]
            visited[i][j] = True
            current_sum = 0

            while stack:
                x, y = stack.pop()
                current_sum += grid[x][y]

                for dx, dy in directions:
                    nx, ny = x + dx, y + dy
                    if 0 <= nx < n and 0 <= ny < m:
                        if not visited[nx][ny] and grid[nx][ny] != 0:
                            visited[nx][ny] = True
                            stack.append((nx, ny))

            best = max(best, current_sum)

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案使用迭代 DFS 来避免大型网格中可能出现的递归深度问题。 这`visited`矩阵在节点被压入堆栈时更新，而不是在弹出时更新，这可以防止同一单元被多次插入。 

出栈时累加运行总和，推入时也可以累加； 只要每个单元格只计数一次，两者都是等效的。

 ## 边缘情况

 没有非零单元格的网格通过从不进入洪水填充循环来处理。 自从`best`初始化为零，输出保持为零，符合没有湖泊可供评估的想法。 

完全填充的网格被视为一个连接的组件。 该算法进入DFS一次并标记所有访问过的单元格，防止重复探索并确保线性运行时间而不是二次爆炸。 

具有交替零的高度分散的网格确保外部循环触发许多小型 DFS 调用，但每个调用都是每个单元的恒定摊销工作，因为每个单元都被分配给恰好一个组件并且永远不会重新访问。
