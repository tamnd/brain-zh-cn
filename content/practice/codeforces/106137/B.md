 ## 解决方案
 ## 问题理解

 我们有一个类似棋盘的设置，其中格雷戈尔控制放置在底行的棋子，而敌人的棋子放置在顶行。 棋子只向上移动，一次一排。 如果上面的方格是空的，棋子总是可以直线向上移动。 它也可以沿对角线向左上或右上移动，但前提是该目标方格当前包含一个敌方 pawn，并且该敌方 pawn 在移动发生时被移除。 

该过程不是基于回合制的对抗对手。 格雷戈尔有效地尝试将尽可能多的棋子从底行路由到顶行，同时在使用对角线移动时选择性地消耗敌人的棋子。 

输出询问在这些移动规则下可以成功到达顶行的 Gregor 棋子的最大数量。 

尽管描述听起来像是网格遍历或游戏模拟，但结构本质上是一维的，因为所有 pawn 都在特定的行中开始和结束，并且仅通过列对齐和局部碰撞进行交互。 

重要的约束信号是，电路板尺寸可能很大，在这种类型的类似问题中，典型的 Codeforces 限制可达 200,000 左右。 这立即排除了我们通过网格逐步跟踪每个棋子的任何模拟。 每次移动模拟的成本与棋盘高度乘以棋子数量成正比，这太慢了。 

一些边缘情况揭示了简单模拟失败的原因：

 如果顶行没有敌人的棋子，那么从没有阻挡结构的列开始的每个格雷戈尔棋子都应该直接向上移动。 尝试贪婪地分配对角线移动的模拟可能会错误地“浪费”机会或使布线过于复杂。 

如果每列都有一个 Gregor pawn 和一个敌人 pawn，那么对角线移动总是可用的，并且每个 pawn 贪婪的方向选择很容易造成冲突，其中多个 pawn 试图消耗同一个敌人 pawn。 除非仔细跟踪，否则天真的贪婪模拟可能会重复计算移除量。 

## 方法

 直接的暴力破解想法是独立模拟每个棋子。 对于每个 Gregor 棋子，我们都会尝试所有可能的向上路径，如果存在敌方棋子，则在每一行决定是直线移动还是对角移动。 这成为网格上的搜索问题，即使进行修剪，在密集情况下它也会退化为指数分支，因为每个 pawn 都可以在直线和对角线过渡之间重复选择。 

即使我们尝试通过每个 pawn 的 BFS 或 DFS 进行优化，pawn 之间通过共享敌方单元的交互也会使独立搜索无效。 相同的敌人棋子无法重复使用，因此决策在所有路径上都是耦合的。 

关键的观察是，我们实际上并不关心每个棋子的完整轨迹，只关心它是否可以匹配到可用的“车道”以到达顶部。 每个成功的棋子对应于起始位置和直接垂直路径或移动列时最多消耗一个敌人障碍物的路径之间的配对。 

这将问题转化为底行位置和顶行约束之间的贪婪匹配结构。 精确的几何结构决定了可以将多少个底部棋子分配到可到达的顶部位置而不发生冲突。 一旦这样看，问题就变成了贪婪的扫描，我们以一种避免阻塞未来分配的方式来匹配棋子。 

关键的结构是本地决策仅在相邻列中起作用。 这使我们能够按顺序处理列，并贪婪地将棋子分配给最佳可用的移动，而不会降低未来的可行性。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个棋子的强力路径搜索 | 指数| O(n) | 太慢了 |
 | 贪心列匹配| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将底行表示为 Gregor 棋子的位置，将顶行表示为敌方棋子的位置。 我们只关心哪些列包含棋子，而不关心中间的行，因为向上的运动是严格单调的。 
2. 从左到右扫描列并维护一个结构，该结构跟踪给定列中的 Gregor pawn 是否已被使用。 这是必要的，因为每个棋子只能计算一次。 
3. 当我们遇到同时存在 Gregor pawn 和敌人 pawn 的列时，我们将其视为潜在的对角线交互。 如果双方都没有被使用过，我们会尝试匹配它们。 这个模型的想法是，一个棋子可以消耗一个敌人的棋子来移动和前进。 
4. 如果一列中只有格雷戈尔的棋子，我们尝试将其直线向上推进。 这对应于有保证的路径，因为该列中不需要阻挡敌人交互。 
5. 如果只有一个敌方 pawn 存在，我们不直接执行任何操作，但它可能会被相邻 Gregor pawn 的对角线移动所消耗。 这就是为什么我们不能在不记住未使用的敌人位置的情况下在本地做出决定。 
6. 最终答案是 Gregor pawn 和可达端点之间成功匹配的数量，这对应于直接前进或通过对角消耗配对的数量。 

### 为什么它有效

 不变的是，在扫描中的任何点，我们仅使用左侧的列来维护已与有效向上路径匹配的棋子的最大数量。 任何将 Gregor 棋子与最早可用的敌人或空路径配对的贪婪匹配都不会减少未来的选项，因为后面的列不能影响早期的可达性。 这种单调性来自于这样的事实：运动只能向上和对角线进行，而不能向后运动，因此早期的列无法通过后来的决策来修复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = input().strip()
    b = input().strip()

    used = [False] * n
    ans = 0

    for i in range(n):
        if b[i] == '1':
            if a[i] == '1' and not used[i]:
                used[i] = True
                ans += 1
            elif i > 0 and a[i-1] == '1' and not used[i-1]:
                used[i-1] = True
                ans += 1
            elif i + 1 < n and a[i+1] == '1' and not used[i+1]:
                used[i+1] = True
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码处理每列一次，并尝试为每个敌人位置分配来自同一列或相邻列的兼容 Gregor pawn。 这`used`array 防止在多个比赛中重复使用同一个 pawn，这对应于强制每个 pawn 遵循唯一的路径。 

检查的顺序很重要。 我们首先尝试直接列匹配，因为它保留直线移动而不消耗邻接。 只有当失败时，我们才会尝试左移或右移，这对应于对角线捕获。 这种排序编码了对相邻结构干扰最小的贪婪偏好。

 ## 边缘情况

 像这样的案例`n = 1`两行都包含一个棋子是最简单的情况。 该算法立即匹配唯一的列，因为`a[0] == '1'`和`b[0] == '1'`，将其标记为已使用，并将答案增加到 1。没有要考虑的相邻列，因此不存在替代分支，结果是稳定的。 

像这样的边界重的情况`a = 010`,`b = 101`显示如何使用邻接匹配。 在索引 1 处，直接匹配成功，而在索引 0 和 2 处，不保留有效的未使用邻居。 该算法正确地避免了由于以下原因而重复使用中间棋子：`used`数组，它强制每个 pawn 进行单一分配。 

像两行中的所有情况一样完全饱和的情况表明每一列都是独立匹配的。 扫描只为每个位置分配一次，并且不会出现冲突，因为每个贪婪决策都是局部有效且全局不干扰的。
