 ## 解决方案
 ## 问题理解

 任务是从给定的正整数中删除最少位数，使剩余的数字形成一个能被 25 整除的数字。剩余数字的顺序必须保持不变，因为删除数字不允许重新排列数字。 答案是所需删除的最小数量，而不是所得的可整除数。 

当一个数字的最后两位数字是以下之一时，该数字正好可以被 25 整除`00`,`25`,`50`， 或者`75`。 此属性是关键，因为删除数字只会更改末尾出现的数字。 我们不需要尝试构建整个数字，而只需找出距离这四个结局之一有多近。 

输入是数字的十进制表示形式，因此重要的参数是其长度。 可以直接处理字符串，无需将其转换为整数。 这避免了值非常大的问题，并使算法与位数成比例。 如果长度很大，任何尝试许多可能的删除或生成许多候选数的方法很快就会变得不切实际。 线性扫描就足够了，因为每个数字只需要检查恒定的次数。 

一些边缘情况可能会破坏粗心的解决方案。 如果该号码已以有效对结尾，则无需删除。 例如，输入`100`有输出`0`， 因为`100`已经可以被 25 整除。总是删除至少一位数字的解决方案在这里会失败。 

数字在最后一对之前可以包含许多零。 例如，`1000`有输出`0`， 不是`2`，因为最后两位数字是`00`。 一种粗心的方法，只寻找`25`可能会错过有效的结局。 

有效对可能由必须删除的数字分隔。 例如，`71345`有输出`2`，因为去除`1`和`3`树叶`745`，其最后两位数字是`45`，所以这个例子还不够。 正确有用的例子是`71375`，其中删除`1`和`3`树叶`775`，并删除多余的`7`相反给出`75`，要求`3`删除。 仅搜索左侧第一个匹配数字的贪心方法可能会选择错误的出现并产生错误的答案。 

最小的投入也需要小心。 例如，`7`不能包含任何有效的结束对。 答案是必须删除的位数，直到除了结果数字的解释之外不再剩下任何数字。 此问题的标准解决方案将找到有效的两位数字结尾作为目标，并通过返回字符串的长度来处理不可能的情况。 

## 方法

 暴力破解的想法是尝试所有可能的被删除的数字组，保留剩下的数字，并检查结果数字是否能被 25 整除。这是正确的，因为它探索了每个可能的最终数字。 然而，一个长度为`n`有`2^n`可能的子序列，因此最坏的情况需要检查指数数量的候选者。 即使有几十位数字，这也变得太慢了。 

能被 25 整除的结构给出了更小的搜索空间。 最后两位数字完全决定了这个数字是否能被25整除，并且只有四种结局可能：`00`,`25`,`50`， 和`75`。 对于每个结尾，我们只需要在原始字符串中找到两个数字，在删除它们之间和后面的数字后，可以成为最后的两个数字。 

蛮力方法之所以有效，是因为它考虑了所有可能的最终数字，但会失败，因为大多数选择都是无关紧要的。 只有最后两位数字重要的观察结果让我们可以用对四个可能的数字对的搜索来代替对所有子序列的搜索。 我们可以从字符串的末尾开始扫描，找到每对的第二个数字，然后找到它前面的第一个数字。 删除的次数取决于第二个数字之后和两个选定数字之间有多少个数字。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 存储可被 25 整除的数字的四种可能的结尾：`00`,`25`,`50`， 和`75`。 
2. 对于每个结尾，从右到左搜索其第二个数字。 第二位数字必须成为答案的最后一位数字，因此选择尽可能靠右的位置可以最大限度地减少其后删除的数字。 
3. 找到第二位数字后，继续向左搜索结尾的第一位数字。 第一个数字必须出现在第二个数字之前，因为删除会保留原始顺序。 
4. 如果找到了结尾的两位数字，则计算删除数。 必须删除第二个所选数字之后的所有数字，并且也必须删除两个所选数字之间的所有数字。 
5. 取所有四个结局中删除次数最少的。 如果无法形成结局，则忽略它。 

这种贪心搜索有效的原因是，对于任何固定的结局，将任一选定的数字向右移动只能减少或保持删除的数量。 最右边可能的第二个数字留下要删除的最少尾随数字，最右边可能的第一个数字则留下最少要删除的中间数字。 

为什么它有效：

 每个有效的最终数字必须以四个允许的对之一结尾。 该算法检查每种可能的配对类型。 对于选定的数字对，它会找到保留最多数字的位置，同时保留所需的结尾，因为这两个数字都选择得尽可能靠右。 同一对的任何其他放置都会删除至少同样多的数字。 由于最优答案必须属于这四种情况之一，因此算法找到的最小值就是全局最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    patterns = ["00", "25", "50", "75"]
    ans = len(s)

    for p in patterns:
        second = -1
        for i in range(len(s) - 1, -1, -1):
            if s[i] == p[1]:
                second = i
                break

        if second == -1:
            continue

        first = -1
        for i in range(second - 1, -1, -1):
            if s[i] == p[0]:
                first = i
                break

        if first == -1:
            continue

        deletions = (len(s) - 1 - second) + (second - first - 1)
        ans = min(ans, deletions)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码独立检查四种可能的结局中的每一种。 外循环的大小是恒定的，因此总工作量仅由字符串的长度决定。 

对于每个结尾，第一次向后扫描会选择最后的数字。 从末尾开始搜索是必要的，因为尽可能将数字保留在右侧可以最大限度地减少删除的后缀数字。 第二次扫描在该位置之前开始，并找到该对的前面的数字。 

删除公式有两部分。`len(s) - 1 - second`计算所选最终数字之后的数字。`second - first - 1`计算两个选定数字之间的数字。 这些正是必须消失的数字，而所需的两个数字仍按顺序排列。 

该算法从不将输入转换为整数，因此它适用于非常大的字符串，而无需担心溢出。

 ## 边缘情况

 对于`100`，算法找到结局`00`。 第二个零在最后一个位置选择，第一个零在其前面选择，给出`(2 - 1) + 0 = 0`删除。 数量保持不变。 

为了`71375`，算法检查结尾`75`。 它找到了`5`在最后一个位置和最近的位置`7`在它之前。 它们之间的数字是`13`，并且没有尾随数字，因此删除的次数为`2`。 If a different valid pair were required by the search, the minimum among all patterns would still be chosen.

 为了`7`，由于数字不足，四个词尾都无法组成。 答案仍然是字符串长度的初始值，它表示删除所有可用的数字。 

为了`505050`，算法发现`50`紧接着字符串的末尾。 两个选定的数字已经位于正确的最终位置，因此它返回`0`。 这可以防止解决方案不必要地修改已经可以被 25 整除的数字。
