 ## 解决方案
 ## 问题理解

 我们维护一组动态的非负整数。 随着时间的推移，这个集合会发生变化：可以插入或删除数字，并且当集合按降序排序时，我们还可以删除当前排名在特定位置的元素。 

除了这个不断发展的集合之外，我们还从概念上跟踪每个十进制数字在当前集合中的所有数字中出现的频率。 对于从 0 到 9 的任何数字，我们可以统计它在所有活跃数字中出现的总次数。 这给出了一个固定的频率表，只要集合改变，该表就会改变。 

对于查询编号 k，我们定义仅取决于此频率表的分数 f(k)。 我们查看 k 中出现的每个数字，并且对于每个出现的数字，我们添加该数字的全局频率。 k 中的重复数字多次贡献。 查询要求这个分数，但前提是 k 当前在集合中； 否则答案为-1。 

关键的困难在于，数字集及其数字统计都是在线演变的，删除不仅是按值删除，而且是按顺序统计删除。 

限制最多可达 300,000 次操作。 这立即排除了每次查询从头开始重新计算数字计数的可能性，因为每次操作扫描所有数字将导致二次行为。 任何解决方案都必须增量地维护聚合信息并有效支持有序删除，这建议采用对数更新的结构，例如平衡二进制索引结构或有序集。 

当一个数字多次切换时，会出现微妙的边缘情况。 它对数字频率的贡献必须在插入时完全添加，并在删除时完全消除。 数字重复中会出现另一个棘手的情况：例如，数字 111 导致数字 1 出现 3 次，因此频率更新必须考虑多重性，而不仅仅是存在。 

第二个重要的边缘情况是第 k 大删除。 如果集合大小小于k，则必须完全忽略该操作； 否则我们必须通过排名而不是值来正确识别元​​素。 

## 方法

 直接方法将活动号码集存储在普通容器中。 对于每个查询 f(k)，我们扫描所有数字并动态重新计算数字频率。 这是正确的，但太慢了：每个查询可能花费 O(n) 位扫描，并且对于最多 3e5 个查询，这变得不可行。 

稍微好一点的蛮力可以维护集合并在需要时重新计算数字计数，但即使是增量重新计算仍然需要在每次更新时触及所有数字的所有数字。 由于每个数字最多可以有 10 位数字，因此每次操作完全重新计算的时间复杂度为 O(n log10 n)，仍然远远超出限制。 

关键的观察是数字计数与数字相加。 每个数字贡献一个固定的数字直方图。 如果我们维护一个全局数组 cnt[d] 来存储数字 d 在当前集合中出现的次数，那么 f(k) 就成为对 k 的数字进行基于查找的简单计算。 

这将问题转移到有效维护两件事上：具有快速插入、删除和 k 阶统计的动态数字集，以及每个插入或删除的数字可以 O（数字）更新的运行数字直方图。 

我们使用平衡结构解决顺序统计问题，例如使用二分搜索的排序列表或压缩坐标上的芬威克树。 由于值高达 2e9 并且有多达 3e5 个不同元素，因此坐标压缩加上 Fenwick 树或顺序统计树的工作时间为 O(log n)。 每次更新还会调整 O(10) 的数字计数，因为数字最多有 10 位数字。 

最终的结构保持了成员资格和数字贡献之间的一致性。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq·d) | O(n) | 太慢了|
 | 最优（有序集+数字频率）| O(q log n + q · d) | O(q log n + q · d) | O(n) | 已接受 |

 这里 d 最多为 10。 

## 算法演练

 我们维护一个按排序顺序存储所有活动数字的数据结构，以及一个全局数字频率数组 cnt[10]。 我们还需要支持切换成员资格和按级别删除。 

1. 首先，我们收集所有初始数字和切换查询中出现的所有数字，以便我们可以将值压缩到索引中。 这确保了我们可以在固定范围内使用芬威克树。 压缩是必要的，因为值最高可达 2e9。 
2. 在压缩索引上构建 Fenwick 树（或 BIT），其中每个位置存储该号码当前是否处于活动状态。 这允许我们查询前缀和并找到第 k 个活跃元素。 
3. 将 cnt[0..9] 初始化为零。 对于每个初始数字，我们将其插入结构中并将其数字贡献添加到 cnt 中。 这建立了正确的起始状态。 
4. 对于查询“+ k”，我们检查 k 当前是否处于活动状态。 如果是，我们将其删除； 否则我们插入它。 插入时，我们遍历 k 的数字并为每个数字出现增加 cnt[d] 。 删除时，我们以同样的方式递减。 
5. 对于查询“-k”，我们首先检查活动集大小是否至少为k。 如果没有，我们就忽略它。 否则，我们使用芬威克树来查找第 k 大元素的索引。 由于 Fenwick 自然支持第 k 个最小，因此我们通过查询 size - k + 1 进行转换。然后检索该值，将其删除，并更新数字频率。 
6. 对于查询“?k”，我们首先检查k是否处于活动状态。 如果不是，输出-1。 否则，通过迭代 k 的数字并对每个数字出现的 cnt[d] 求和来计算 f(k)。 

### 为什么它有效

 在任何时候，cnt[d] 都精确等于所有活动数字中数字 d 出现的总数。 每次插入都会添加数字的数字直方图，每次删除都会删除完全相同的直方图。 由于集合上的每个操作都通过 cnt 上的相应更新来镜像，因此不变量仍然为真。 因为 f(k) 纯粹定义为 cnt[d] 在 k 数字上的线性组合，所以一旦验证了成员资格，计算值始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def find_kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def digits(x):
    if x == 0:
        return [0]
    res = []
    while x:
        res.append(x % 10)
        x //= 10
    return res

n, q = map(int, input().split())
a = list(map(int, input().split()))

ops = []
vals = set(a)

for _ in range(q):
    line = input().split()
    ops.append(line)
    if len(line) == 2:
        vals.add(int(line[1]))

vals = sorted(vals)
idx = {v: i + 1 for i, v in enumerate(vals)}

fw = Fenwick(len(vals))
active = set()
cnt = [0] * 10

def add_num(x):
    if x in active:
        return
    active.add(x)
    fw.add(idx[x], 1)
    for d in digits(x):
        cnt[d] += 1

def remove_num(x):
    if x not in active:
        return
    active.remove(x)
    fw.add(idx[x], -1)
    for d in digits(x):
        cnt[d] -= 1

for x in a:
    add_num(x)

out = []

for op in ops:
    if op[0] == '+':
        x = int(op[1])
        if x in active:
            remove_num(x)
        else:
            add_num(x)

    elif op[0] == '-':
        k = int(op[1])
        size = fw.sum(len(vals))
        if k > size:
            continue
        target = size - k + 1
        idx_pos = fw.find_kth(target)
        x = vals[idx_pos - 1]
        remove_num(x)

    else:
        x = int(op[1])
        if x not in active:
            out.append("-1")
        else:
            res = 0
            for d in digits(x):
                res += cnt[d]
            out.append(str(res))

print("\n".join(out))
```芬威克树纯粹用于顺序统计。 活动集保持同步以允许 O(1) 成员资格检查。 仅当数字进入或离开活动集时，数字计数数组 cnt 才会更新，确保查询时间仅取决于 k 的数字长度。 

一个常见的错误是忘记切换查询必须删除现有的数字（如果它已经存在）。 另一个是更新每个查询的数字计数，而不是仅更新实际状态更改，这会损坏频率表。

 ## 边缘情况

 一个微妙的情况是多次切换相同的数字。 例如，从空开始，应用“+10”两次应该先插入，然后删除。 该实现在决定是否添加或删除之前显式检查成员资格，确保仅在状态更改时才修改数字计数。 

另一个边缘情况是当集合太小时按等级删除。 如果当前集合的大小为 2 并且我们收到“- 5”，则永远不会执行 Fenwick 查询，并且不会修改任何数字计数，从而保留 cnt 的正确性。 

最后，像 1111111111 这样的数字较多的数字强调多重性处理。 每次插入都会将 cnt[1] 更新 10，而删除则会减去相同的数量。 由于数字迭代与位数呈线性关系，因此即使是最坏情况的值也仍然有效。
