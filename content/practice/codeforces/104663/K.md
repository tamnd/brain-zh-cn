 ## 解决方案
 ## 问题理解

 我们得到一个表示正整数的十进制字符串。 从这个字符串中，我们考虑每个可能的连续子字符串，将其解释为一个数字，并计算这些子字符串中有多少个数字可以被 3 整除。 

每个子串都是通过选择数字串内的起始位置和结束位置来形成的。 任务是计算有多少个子字符串产生可被 3 整除的值。 

这些约束很重要，因为数字字符串长度可以大到$10^5$每个测试用例。 所有子字符串的直接枚举将生成大约$O(m^2)$子串，变成$10^{10}$在最坏的情况下，远远超出任何可行的限度。 这立即排除了任何独立构造和测试每个子字符串的方法。 

当字符串包含 0 等数字或重复数字时，会出现微妙的边缘情况。 例如，单个数字子字符串总是很小，带有前导零的子字符串不会改变整除性，但会影响依赖于整数解析和容易溢出的累积的简单数字转换方法。 

另一个重要的观察结果是，如果直接转换，大子字符串可能会超出标准整数限制。 例如，如果重复执行，即使是基于简单循环的解决方案中的 Python 风格的大整数，也无法在时间限制内安全地存储 100000 位数字。 

## 方法

 暴力解决方案迭代所有索引对$x \le y$，构建数字$f(x,y)$，并检查它是否能被 3 整除。整除性检查本身很便宜，因为当且仅当一个数字的数字之和能被 3 整除时，该数字才能被 3 整除。但是，即使进行了这种优化，从头开始计算每个子字符串的数字和仍然需要花费$O(m)$每个查询，导致$O(m^3)$如果天真地完成的话，总共，或者$O(m^2)$如果使用前缀和。 

即使改进版本也太慢了，因为$m^2$长度可达的子串$m$对于$10^5$。 

关键的观察结果是，能否被 3 整除仅取决于数字之和，而不取决于数字的顺序或位置权重。 这意味着每个子字符串对应于数字数组中某个范围的总和，并且我们正在计算有多少个范围的总和可被 3 整除。 

一旦我们将数字转换为模 3 的前缀和数组，问题就相当于计算具有相等值的前缀索引对。 每个这样的对定义一个子串，其数字和可被 3 整除。 

因此该问题简化为经典的前缀频率计数问题。

 ## 算法演练

 我们将数字字符串重写为整数数组。 我们维护一个以 3 为模的运行前缀和。 

1.初始化频率数组`cnt`大小为 3，其中`cnt[r]`存储有多少个前缀和有余数`r`模 3。我们从`cnt[0] = 1`因为空前缀的总和为 0。 
2. 从左到右迭代数字，同时保持运行总和模 3. 读取每个数字后，更新运行余数。 
3. 每当我们处于当前前缀余数的位置时`r`，每个之前也有余数的前缀`r`形成以当前位置结尾的有效子字符串。 我们添加`cnt[r]`到答案。 
4. 计数完毕后，递增`cnt[r]`在将来的匹配中包含当前前缀。 

每个步骤直接对应于隐式构造所有子字符串。 我们不显式生成子字符串，而是比较前缀状态。 

### 为什么它有效

 来自索引的子字符串$l$到$r$数字总和等于 prefixSum[r] 减去 prefixSum[l-1]。 当且仅当两个前缀和具有相同的模 3 值时，该和才能被 3 整除。因此，每个有效子串对应于一对相等的前缀余数，并且对子串进行计数就变成对这样的对进行计数。 该算法在处理字符串时仅枚举一次这些对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(m, s):
    cnt = [0, 0, 0]
    cnt[0] = 1

    cur = 0
    ans = 0

    for ch in s:
        cur = (cur + (ord(ch) - 48)) % 3
        ans += cnt[cur]
        cnt[cur] += 1

    return ans

def main():
    t = int(input())
    for _ in range(t):
        m, s = input().split()
        m = int(m)
        print(solve_one(m, s))

if __name__ == "__main__":
    main()
```该解决方案仅维护三个与前缀和模 3 相对应的计数器。运行余数逐位更新，避免任何整数溢出或子串构造。 

一个常见的陷阱是错误地重新计算每个子串的数字和，这会导致二次行为。 另一种是忘记了最初的`cnt[0] = 1`，它说明从索引 0 开始的子字符串。

 ## 边缘情况

 关键的边缘情况是完全由零组成的字符串。 每个子串的总和为零，因此每个子串都是有效的。 该算法可以正确处理这个问题，因为每个前缀余数都保持为 0，因此每个新前缀都与所有先前的前缀匹配，从而产生$m(m+1)/2$自然算数。 

另一个边缘情况是单位数字字符串。 算法初始化`cnt[0] = 1`，因此当该数字能被 3 整除时，它会被正确计为一个有效子串，否则为零。 这避免了任何特殊情况逻辑。 

第三种情况是交替数字，如“111111”。 这里，每个前缀和在模 3 空间中确定性地循环，并且重复的余数通过频率累积而不是位置推理来确保正确计数。
