 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中每个节点代表具有两个属性的水果：成本和营养价值。 树的排列方式是将一个节点指定为根，所有其他节点通过边连接，通过该根隐式形成父子关系。 

“购买操作”的工作原理就像将节点与其父连接断开一样。 当顾客选择一种水果时，卖家会切断直接将该水果与其父级连接的所有边，并且以该水果为根的整个断开的子树将成为购买的一部分。 如果该切割将下面的其他组件分开，这些组件也会自动出现，因此每次操作实际上都会购买过去连接在切割点的整个连接组件。 

客户可以执行多次此类操作，始终对上次砍伐后剩下的树进行操作。 每次操作都会从当前森林中删除整个子树状组件，该操作的成本是该组件中所有水果的成本总和，而收益是营养价值的总和。 

该查询询问：给定预算，通过选择一系列此类削减可以实现的最大总营养是多少，其中每个选定的组成部分必须全额支付，并且组成部分是不相交的，因为一旦删除它们就不再可用。 

这将问题转化为选择不相交的连接子树的集合（在有根树的意义上），每个子树的成本等于节点成本之和，价值等于节点养分之和，在背包预算下最大化价值。 关键限制是有效项不是任意子集，而是有根树中的子树。 

约束表明$n$和$q$达到 3000，而所有成本和预算也以 3000 为界。这立即暗示了伪多项式背包结构。 然而，树结构无法独立处理每个节点； 节点上的朴素子集 DP 是不可能的，因为有效性取决于层次结构。 

打破天真的思维的极端情况包括：

 线性链树。 如果我们将每个节点视为一个独立的项目，我们就会对重叠的前缀进行双重计数。 例如，在一个链中$1 \to 2 \to 3$，选择节点2处的子树已经包含节点3，因此单独选择节点3是无效的。 

一棵星形的树。 剪切子节点只会删除该子子树，但允许选择多个子节点，因此独立性仅在兄弟节点之间有效，而不是全局有效。 

一个小例子：

 输入：```
3 2 1 1
1 1
2 2
3 3
1 2
1 3
3
```正确的推理：我们可以选择节点 2 子树或节点 3 子树或两者，但决不能重叠节点。 天真的“选择最佳比率节点”方法会失败，因为结构很重要。 

主要困难是正确编码选择一个节点意味着可以选择其子树的任意组合，但是一旦我们决定从子树中获取什么，它就独立于其他兄弟节点。 

## 方法

 暴力方法将枚举每组有效的不相交子树。 想象的一种方法是为每个节点决定是否将其“激活”为切根，并确保没有激活的节点位于另一个激活的子树内。 对于每个有效的选择，我们都会计算总成本和营养，然后在预算范围内选择最好的。 

此类配置的数量呈指数级增长。 即使仅限于子树根，每个节点也有两种选择：要么将其整个子树作为一个单元，要么将选择推迟到子树。 当在树上扩展时，这会导致指数分支，因为在每个节点，我们决定如何在子组合之间分配预算。 

关键的观察是，每个子树的行为就像一个具有内部结构的背包项目：对于一个节点，我们在选择节点的整个子树作为一个项目或将其分解为其子子树内的选择之间分配预算。 这是一个经典的树DP背包合并问题。 

我们在每个节点定义 DP，在其中计算仅使用其子树可实现的所有可能的（成本、值）对，尊重树结构。 对于每个节点，我们从不采取任何内容的选项开始，然后使用背包卷积在最多 3000 的预算上迭代合并子 DP 状态。 

每个节点的 DP 是通过逐个合并子节点来计算的，将 DP 数组视为超出预算的背包。 当我们包含一个孩子时，我们将当前累积状态和该孩子的子树 DP 之间的预算分配结合起来。 处理完所有子节点后，我们可以选择将当前节点本身作为整个子树项（完整子树的成本和值）包含在内，或者保留分解选项。 

关键的简化是我们不需要跟踪任意的成本值对； 由于预算是有限的，我们将 DP 压缩到按成本索引的数组中。

 ## 算法演练

 我们把树扎根于$r$。 我们使用 DFS 自下而上计算子树 DP。 

1. 对于每个节点$u$,初始化一个DP数组`dp[u]`在哪里`dp[u][c]`是从子树中可获得的最大营养$u$总成本正好$c$。 我们从`dp[u][0] = 0`。 
2. 对以下子项运行 DFS$u$。 对于每个孩子$v$，我们首先计算`dp[v]`。 
3. 合并`dp[v]`进入`dp[u]`使用背包式卷积。 我们创建一个临时数组，并且对于当前状态和子状态之间的每个预算划分，我们组合值。 此步骤确保我们考虑跨独立子子树分配预算的所有方法。 
4. 合并所有子节点后，我们考虑以根为根的整个子树$u$作为单个项目。 它的成本是其子树中成本的总和，其价值是其子树中营养的总和。 我们更新`dp[u][cost[u]]`相应地，通过与全子树选择进行比较。 
5. 返回`dp[u]`给家长。 
6. 处理完根后，通过取最大值来回答每个查询`dp[r][c]`为所有人$c \leq \text{budget}$。 

我们明确允许“获取整个子树”选项的原因是，某些最佳解决方案不喜欢将子树分解为子决策，而是选择它作为单个购买单元。 

### 为什么它有效

 在每个节点$u$，DP 枚举了所有可行的方法来选择其后代中不相交的子树。 不变的是`dp[u]`表示仅使用以下节点的所有可实现的成本值组合$u$的子树而不违反不相交性。 合并过程保留子树之间的独立性，因为子树是不相交的。 可选的完整子树选择考虑了剪切操作，其中我们将子树作为单个购买。 由于每个有效的全局解决方案都可以唯一地分解为在每个子树边界处做出的选择，因此不会错过任何有效配置，并且不会引入无效重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n, m, r, q = map(int, input().split())

        cost = [0] * (n + 1)
        val = [0] * (n + 1)

        for i in range(1, n + 1):
            cost[i], val[i] = map(int, input().split())

        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            g[a].append(b)
            g[b].append(a)

        queries = list(map(int, input().split()))
        maxW = max(queries)

        parent = [0] * (n + 1)
        order = []

        stack = [r]
        parent[r] = -1

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                parent[v] = u
                stack.append(v)

        children = [[] for _ in range(n + 1)]
        for u in order:
            for v in g[u]:
                if v != parent[u]:
                    children[u].append(v)

        dp = [[-10**18] * (maxW + 1) for _ in range(n + 1)]

        for u in reversed(order):
            dp[u][0] = 0
            for v in children[u]:
                ndp = [-10**18] * (maxW + 1)
                for i in range(maxW + 1):
                    if dp[u][i] < 0:
                        continue
                    for j in range(maxW + 1 - i):
                        if dp[v][j] < 0:
                            continue
                        ndp[i + j] = max(ndp[i + j], dp[u][i] + dp[v][j])
                dp[u] = ndp

            if cost[u] <= maxW:
                for c in range(maxW, cost[u] - 1, -1):
                    dp[u][c] = max(dp[u][c], dp[u][c - cost[u]] + val[u])

        root_dp = dp[r]
        pref = [0] * (maxW + 1)
        best = 0
        for i in range(maxW + 1):
            best = max(best, root_dp[i])
            pref[i] = best

        print(f"Case {tc}:")
        for a in queries:
            print(pref[a])

if __name__ == "__main__":
    solve()
```该解决方案首先对树求根并构建一个显式的子列表。 这避免了 DP 期间家长的重复检查。 DP 以每个节点的完整背包数组的形式存储，除了零成本之外，均以负无穷大初始化。 

合并步骤在节点及其子节点之间使用三重循环背包卷积，确保考虑所有预算分割。 合并子节点后，我们允许将节点本身作为一个项目，反向更新 DP 以避免覆盖同一迭代中所需的状态。 

最后，构建一个前缀最大数组，以便可以在 O(1) 内回答每个查询。 

## 工作示例

 ### 示例 1

 考虑一棵有根的小树：```
1 is root
1 - 2
1 - 3
```成本和价值：

 | 节点| 成本| 价值|
 | ---| ---| ---|
 | 1 | 4 | 3 |
 | 2 | 2 | 2 |
 | 3 | 1 | 1 |

 预算=3

 我们首先处理叶子。 

对于节点 2：dp 允许 {0 cost，0 value} 和 {2 cost，2 value}。 

对于节点 3：dp 允许 {0,0} 和 {1,1}。 

在节点 1，我们合并子节点。 我们得到组合：

 | 成本| 价值|
 | ---| ---|
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 3 |

 我们不能采用节点 1 本身，因为成本为 4 > 预算。 

3 的答案是 3。 

这体现了兄弟姐妹的独立性：孩子们像背包里的物品一样组合在一起。 

### 示例 2

 链树：```
1 - 2 - 3
```成本和价值：

 | 节点| 成本| 价值|
 | ---| ---| ---|
 | 1 | 5 | 1 |
 | 2 | 3 | 5 |
 | 3 | 2 | 4 |

 预算=5

 在节点 3 处：dp = {(0,0), (2,4)}

 在节点 2：单独取 3 或与 3 组合，得到：

 | 成本| 价值|
 | ---| ---|
 | 0 | 0 |
 | 2 | 4 |
 | 3 | 5 |
 | 5 | 9 |

 在节点 1 处，我们无法获取完整子树（成本 10），因此预算 5 的最终答案是 9。 

这显示了子树合并如何自然地沿着链构建增加的背包状态。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * Q^2) | O(n * Q^2) | 合并子节点时，每个节点在预算上执行背包卷积，最多为 Q |
 | 空间| O(n * Q) | 每个节点的 DP 表超出预算状态 |

 限制条件限制了两者$n$和$Q$在 3000 时，使$nQ^2$如果仔细实现并使用无效状态的修剪，则处于边界状态，但在优化的 Python 下可以接受。 由于我们每个节点重复使用数组，因此内存占用量在限制范围内。

 ## 边缘情况

 单节点树测试 DP 是否正确允许将根作为唯一可用的项目。 算法初始化`dp[root][0] = 0`然后在预算允许的情况下考虑采用节点本身，立即产生正确的输出。 

深链强调合并顺序。 由于每个节点都依赖于其子节点，因此反转 DFS 顺序可确保在父节点合并子节点 DP 之前完全计算子节点 DP，从而保持累积背包状态的正确性。 

星形树证明孩子们保持独立。 每个子 DP 都单独合并，并且由于卷积在子级之间分配预算，因此不会发生重叠。
