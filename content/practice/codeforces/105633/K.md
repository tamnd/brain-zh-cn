 ## 解决方案
 ## 问题理解

 我们获得了一组候选时间段来安排两次单独的会议。 对于每个时间段，每位评委要么现场出席，要么仅远程参加。 如果法官至少在两个选定时间段之一出席现场，则该法官被视为“参加”会议。 任务是选择两个不同的时间段，以便至少其中一个时间段覆盖所有法官。 

在所有有效对中，我们更喜欢在两个选定时段现场出席的评委人数最多的对。 如果多个对达到相同的最大重叠，我们选择第一个时隙较早的对，如果仍然相等，则选择第二个时隙较早的对。 

关键结构是，每个时隙只是一个长度为 m 的二进制字符串，其中 m 是法官的数量，如果对于每个法官 j，两个字符串中至少有一个在位置 j 处具有 Y，则一对时隙有效。 

这些限制非常重要。 时隙的数量 n 最多可达 200,000，而判断者的数量 m 最多为 20。这立即表明任何严重依赖于 n 平方的算法都是不可能的，但任何将每个时隙视为一个小位掩码并对 2^m 或 m·n 进行大量工作的算法是合理的。 

对所有时隙对进行暴力破解将检查大约 n(n-1)/2 对，在最坏的情况下大约为 2×10^10，远远超出了限制。 

一个更微妙的问题是过滤的正确性。 如果只检查“某个判断被覆盖”或错误地最大化联合大小而不是强制完全覆盖，则很容易产生无效对。 

具体的边缘情况是不存在有效对时。 例如，如果所有时间段都错过了至少一个常见的裁判位置模式，使得每一对都未能覆盖某人，则正确的输出为“否”。简单的方法可能仍会输出最佳得分对而不验证覆盖范围。 

另一个微妙的情况是打破平局。 即使多个对有效并且具有相同的重叠，也必须选择最早的字典对，如果仅在严格更好的情况下更新答案，忽略相等之间的排序，则可能会被错误处理。 

## 方法

 蛮力的想法很简单。 我们尝试每一对时间段，检查它们是否一起涵盖了所有法官，如果是的话，计算有多少法官参加了现场的两次会议。 这是正确的，因为它直接强制定义中的两个条件。 然而，它需要检查 n² 对，并且对于每对，我们需要扫描 m 个判断，从而导致 O(n²m) 操作。 当 n = 200,000 时，这是完全不可行的。 

关键的观察结果是 m 非常小，最多为 20。这意味着每个时隙可以表示为 20 位的位掩码。 一对的覆盖范围变为等于完整掩码的按位“或”，而重叠变为按位“与”。 一旦我们转向这种表示，问题就变成了位掩码的组合，而不是原始字符串的组合。 

我们仍然无法直接迭代所有对。 诀窍是将相同的掩码分组并减少独特配置的搜索空间。 由于最多有 2^20 个可能的掩码，大约一百万个，我们可以为每个掩码维护最佳出现（最小索引）。 然后我们只考虑掩码的组合而不是单独的时隙。 

现在实际存在的不同掩模的数量最多为 n，但通常要小得多。 我们迭代不同掩码之间的所有掩码对。 对于每一对，我们检查它们的 OR 是否等于完整掩码，并计算 AND 大小作为重叠分数。 这在实践中显着减少了搜索，因为 m 很小并且位运算很快。 

优化之所以有效，是因为昂贵的维度是 n，而不是 m。 我们将 n 压缩为最多 2^m 个状态，然后对这些状态进行操作。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²·米) | O(1) | O(1) | 太慢了|
 | 位掩码 + 不同掩码上的配对 | O(U² m) 其中 U ≤ 2^m | O(2^m) | O(2^m) | 已接受 |

 ## 算法演练

 我们首先将每个时隙转换为长度为 m 的位掩码。 对于法官 j，如果字符是 Y，我们设置位 j。这给出了出勤率的紧凑表示。 

接下来，我们维护一个大小为 2^m 的数组 best_mask_index，并使用一个大值进行初始化。 对于每个时隙 i，我们计算其掩码并存储该掩码出现的最早索引。 我们总是保留最小的索引，因为平局决胜取决于最早的时间段。 

预处理后，我们将实际出现的所有掩码提取到候选列表中。 每个候选者都有其最佳代表指数。 

然后，我们迭代所有候选掩码对 (a, b)，仅当该掩码至少出现两次时才包括 a == b 的情况。 对于每一对，我们检查 a OR b 是否等于完整掩码（覆盖所有判断）。 如果没有，我们会跳过它，因为它违反了每个法官至少参加一次现场会议的要求。 

对于有效对，我们将重叠分数计算为 a AND b 中设置的位数。 我们将这个分数与当前的最佳分数进行比较，如果更大则更新答案。 如果分数相等，我们对这对索引应用字典顺序平局：较小的第一个索引获胜，如果相等，则较小的第二个索引获胜。 

完成所有对后，如果我们从未找到有效的对，我们输出否。否则我们输出最好的索引对。 

它为何有效与两个属性有关。 首先，每个时隙都由其位掩码完全表示，因此可行性仅取决于覆盖所有位的 OR。 其次，任何最佳解决方案仅取决于所选择的掩码，而不取决于它们的多重性，除非在两次选择相同掩码时确保两次不同的出现。 由于我们保留了最早的索引，因此我们正确地遵守了排序约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    full = (1 << m) - 1

    best_idx = [n + 1] * (1 << m)
    cnt = [0] * (1 << m)

    masks = []

    for i in range(1, n + 1):
        s = input().strip()
        mask = 0
        for j, ch in enumerate(s):
            if ch == 'Y':
                mask |= (1 << j)

        cnt[mask] += 1
        if best_idx[mask] == n + 1:
            best_idx[mask] = i
            masks.append(mask)

    INF = 10**18
    best_score = -1
    ans_i, ans_j = -1, -1

    for i in range(len(masks)):
        a = masks[i]
        for j in range(i, len(masks)):
            b = masks[j]

            if a == b and cnt[a] < 2:
                continue

            if (a | b) != full:
                continue

            score = (a & b).bit_count()

            i1 = best_idx[a]
            i2 = best_idx[b]
            if i1 > i2:
                i1, i2 = i2, i1

            if score > best_score or (score == best_score and (i1, i2) < (ans_i, ans_j)):
                best_score = score
                ans_i, ans_j = i1, i2

    if best_score == -1:
        print("No")
    else:
        print(ans_i, ans_j)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个调度行编码为位掩码。 完整的面具代表了所有现场出席的评委，因此任何有效的对都必须通过 OR 组合到该面具。 

我们跟踪每个掩码的计数和最早的索引。 该计数是必要的，以确保当两次选择相同的掩码时，至少有两个不同的时隙可用。 

掩码上的双循环仅在不同的掩码上运行，而不是在所有 n 个时隙上运行。 这是主要的减少。 在内部，我们通过 OR 检查强制可行性，并通过按位 AND 计算重叠。 

平局决胜是在更新期间使用索引的元组比较直接处理的，这符合优先选择较早时间段的要求。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(U²·米) | U 是不同掩码的数量，每对检查使用 m 位上的位操作 |
 | 空间| O(2^m) | O(2^m) | 存储计数和每个掩模的最佳索引|

 当 m ≤ 20 时，2^m 大约为一百万，但实际上 U 比这小得多。 该算法很容易满足约束条件，因为位操作是恒定时间的，并且主导因素是压缩状态上的可管理的对枚举。

 ## 边缘情况

 一种边缘情况是唯一有效的解决方案使用相同的掩码两次。 对于输入如：```
2 3
YYY
YYY
```该算法必须允许配对相同的掩码，但前提是 cnt[mask] ≥ 2。计数检查可确保这一点。 如果没有它，解决方案将错误地使用同一索引两次。 

另一种边缘情况是存在许多掩模但只有一对实现完全覆盖。 在这种情况下，评分步骤与大多数对无关，正确性完全取决于 OR 条件。 该算法在考虑重叠之前严格按照 OR 进行过滤。 

最后一个边缘情况是比分相同时的决胜局。 因为我们总是比较`(i1, i2)`按字典顺序，即使后来的对实现相同的重叠，最早的对也会被保留。
