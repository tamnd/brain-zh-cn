 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组和多个查询，每个查询指定该数组的一个连续段。 对于每个段，我们从概念上考虑其中的每对不同索引，并计算两个相应值的 gcd。 在所有这些成对 gcd 值中，我们需要最大可能值。 

阅读任务的另一种方法是，对于子数组，我们想要最大的整数，该整数可以作为从该子数组中选择的两个不同元素的 gcd 出现。 我们不会被要求输出哪对实现了它，只输出了值。 

这些约束使我们远离任何检查每个查询内的对的方法。 当 n 高达 100000，q 高达 100000 时，每个查询的直接 O(length²) 扫描将远远超出可行的范围，因为即使是单个最坏情况间隔也已经涉及大约 5e9 对。 即使每个查询的 O(n) 时间也很有限，任何解决方案都必须跨查询重用结构或预先计算全局关系。 

一个微妙的边缘情况是段中的所有元素都相等。 在这种情况下，每对的 gcd 都等于该值，因此答案就是该值。 另一个问题是所有值都是不同的素数。 那么每对都有 gcd 1，所以答案折叠为 1。任何假设 gcd 结构依赖于邻接或排序的方法都会在这里失败，因为对在区间内是任意的。 

## 方法

 蛮力视图从定义开始：对于每个查询间隔，枚举所有对 (i, j)，计算 gcd(a[i], a[j])，并取最大值。 这是正确的，因为它直接遵循问题的定义。 问题在于对的数量，它是间隔大小的二次方。 在大小为 100000 的最坏情况间隔中，这将变成 5e9 gcd 计算，每个计算本身都很重要，这远远超出了时间限制。 

要提高观察的关键是倒转观点。 我们不是要求最好的对，而是问什么值可以作为区间内的对的 gcd 出现。 当且仅当区间中至少存在两个可被 x 整除的元素时，数字 x 可以是两个值的 gcd。 在所有这样的x中，我们想要最大的。 

这将问题转化为整除性的频率问题：对于每个候选值 x，我们需要知道给定范围内有多少元素可以被 x 整除。 如果至少有两个，则 x 是可行的。 然后我们想要每个查询的最大可行 x。 

对值的限制（ai ≤ 100000）至关重要。 它们允许我们间接预先计算 x 的倍数的位置，或者等效地使用预处理结构来维护倍数的计数。 然后，每个查询都以降序对候选者 x 进行检查，但是每个查询天真地这样做仍然太慢。 

标准优化是为每个 x 预先计算可被 x 整除的元素出现位置的排序列表，然后通过二分搜索回答范围频率查询。 然而，在最坏的情况下，迭代每个查询的所有 x 仍然太大。 

更有效的结构是离线处理查询，并为每个 x 计算它可以作为候选答案的所有区间，但更简单的竞争性编程解决方案依赖于这样一个事实：我们可以根据值的实际出现次数对值进行分组，并使用类似筛子的累加将计数传播到除数，然后维护用于范围计数的数据结构。 

一种实用的方法是构建一个数组 pos[x] 存储所有索引 i，其中 a[i] 可被 x 整除。 然后对于查询 [l, r]，我们需要找到最大的 x，使得在 pos[x] 中，至少有两个索引位于 [l, r] 中。 这可以通过 pos[x] 中的二分查找来检查。

然后，我们从 maxA 向下迭代 x，并为每个 x 检查查询的可行性，但相反，我们颠倒角色：我们为每个 x 分配一个候选查询列表并处理它们，或者我们使用类似 Mo 或桶式检查。 给定约束条件，预期的解决方案通常是对所有多次出现进行预先计算，并通过预先计算的下一个出现结构或除数上的线段树来进行查询答案，但最简洁的概念解决方案是使用位置列表上的二分搜索对 x 进行离线检查。 

其核心思想是可分结构代替对枚举，距离频率代替成对gcd计算。

 | --- | --- | --- | --- |
 | 蛮力 | O(q·n²) | O(q·n²) | O(1) | O(1) | 太慢了|
 | 除数位置列表 + 二分查找 | O((n + q) · sqrt(A) · log n) | O((n + q) · sqrt(A) · log n) | O(n·sqrt(A)) | O(n·sqrt(A)) | 已接受 |

 ## 算法演练

 我们首先为每个值 x 到最大数组值预先计算出现可被 x 整除的元素的索引列表。 这是通过迭代数组位置并为每个值生成其除数来完成的，或者通过迭代 x 并通过筛式循环标记倍数来完成。 

一旦这些列表存在，每个列表都代表 x 可能对 gcd 对做出贡献的所有位置，因为任何 gcd 至少为 x 的对都必须具有可被 x 整除的两个元素。 

对于每个查询 [l, r]，我们从最大到最小 x 测试候选答案。 对于给定的 x，我们需要检查 pos[x] 中是否至少有两个元素位于 [l, r] 内部。 这是使用二分搜索完成的：我们找到第一个位置 ≥ l 和第一个位置 > r，并测量其中有多少个位置。 

我们返回满足条件的第一个 x（按降序排列）。 

### 为什么它有效

 如果 x 是某个对 (i, j) 的 gcd，则 a[i] 和 a[j] 都可以被 x 整除，这意味着两个索引必须出现在 pos[x] 中。 相反，如果 pos[x] 在查询区间内至少包含两个元素，则该区间内存在两个可被 x 整除的值，并且它们的 gcd 至少为 x，这意味着 x 可以作为候选答案。 由于我们按降序搜索，因此第一个有效的 x 保证是所有对中可能的最大 gcd。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXA = 100000

def build_positions(a):
    n = len(a)
    pos = [[] for _ in range(MAXA + 1)]
    for i, v in enumerate(a, start=1):
        # enumerate divisors of v
        d = 1
        while d * d <= v:
            if v % d == 0:
                pos[d].append(i)
                if d * d != v:
                    pos[v // d].append(i)
            d += 1
    return pos

def count_in_range(lst, l, r):
    # first index >= l
    lo, hi = 0, len(lst)
    while lo < hi:
        mid = (lo + hi) // 2
        if lst[mid] < l:
            lo = mid + 1
        else:
            hi = mid
    left = lo

    lo, hi = 0, len(lst)
    while lo < hi:
        mid = (lo + hi) // 2
        if lst[mid] <= r:
            lo = mid + 1
        else:
            hi = mid
    right = lo

    return right - left

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    pos = build_positions(a)

    queries = [tuple(map(int, input().split())) for _ in range(q)]

    # answer queries
    res = []
    for l, r in queries:
        ans = 1
        # try all possible gcd values descending
        for x in range(MAXA, 0, -1):
            lst = pos[x]
            if len(lst) < 2:
                continue
            if count_in_range(lst, l, r) >= 2:
                ans = x
                break
        res.append(str(ans))

    print("\n".join(res))

if __name__ == "__main__":
    main()
```该代码首先为每个除数值构建位置列表。 每个数组元素都会对其值的所有除数做出贡献，确保每个潜在的 gcd 候选者都有其以兼容形式出现的位置的记录。 

这`count_in_range`函数对排序列表执行两次二分搜索，以计算有多少个有效位置属于查询间隔。 这是将排序位置列表转换为范围频率查询的标准方法。 

主循环独立评估每个查询，从最大到最小扫描候选 gcd 值。 立即返回在间隔中至少出现两次的第一个值。 

一个微妙的点是我们存储除数的位置而不是存储原始值，因为 gcd 候选者必须除以两个元素。 这可以避免漏掉 gcd 小于任一元素的情况。 

## 工作示例

 考虑数组 (10, 20, 30, 40, 50, 60) 和完整区间 [1, 6]。 

我们关注大除数是否至少出现两次。 

| x| pos[x] | 中的位置 计入 [1,6] | 有效 |
 | --- | --- | --- | --- |
 | 60| [6] | 1 | 没有|
 | 30| [3, 6] | 2 | 是的 |
 | 20 | [2, 4] | 2 | 是的 |
 | 10 | 10 [1, 2, 3, 4, 5, 6] | 6 | 是的 |

 扫描首先遇到 30，因此答案是 30。这符合 gcd(30, 60) 是可实现的最大 gcd 对的想法。 

现在考虑数组 (13, 2, 35, 4, 13, 2, 5, 1, 7, 4) 和查询 [1, 4]。 

我们检查候选除数：

 | x| 区间内的位置 | 计数| 结果 |
 | --- | --- | --- | --- |
 | 35 | 35 [3] | 1 | 没有|
 | 13 | [1] | 1 | 没有|
 | 7 | [3] | 1 | 没有|
 | 5 | [3] | 1 | 没有|
 | 4 | [2, 4] | 2 | 是的 |

 遇到的第一个有效值是 4，因此答案是 4。这表明当不存在大的公约数时，算法自然会回退到较小的 gcd。

 ## 边缘情况

 临界边缘情况是最大值在间隔中仅出现一次。 例如，在最大数字为 100000 但只出现一次的区间中，算法正确地拒绝它，因为`pos[100000]`大小为 1。然后继续向下，直到找到至少出现两次的值。 

另一种情况是最佳 gcd 远小于任何单个元素，例如值 [6, 10, 15]。 最好的一对 gcd 是 (10, 15) 中的 5，即使 5 没有出现在数组中。 基于除数的位置列表正确捕获 5，因为 10 和 15 在预处理期间都贡献了 5，因此该算法仍然识别间隔中的两次出现。
