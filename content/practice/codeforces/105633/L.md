 ## 解决方案
 ## 问题理解

 我们得到了一系列按固定顺序排列的钞票。 每张钞票都有一个值，我们重复执行一个操作，选择当前剩余钞票的连续块，其总和符合特定的算术形式，完全删除该块，然后将剩余钞票压缩在一起，同时保留其原始顺序。 

如果一个块的总和可以写成，那么它是有效的$k \cdot d + r$， 在哪里$d$和$r$是问题的固定参数，$k$必须是非负整数。 每次我们移除这样的块时，我们获得的分数等于$k$。 只要我们能在当前序列中找到有效的连续块，我们就可以重复这个过程。 目标是最大化所有移除累积的总分。 

使问题变得微妙的关键是压缩步骤。 删除一个段后，剩余的元素变得相邻，这会改变未来连续段的外观。 这意味着我们不是简单地在具有独立结构的静态数组中选择不相交的间隔，而是以动态收缩的序列进行工作。 

限制允许最多 500 张纸币，面值最多为$10^8$。 如果子数组中的每个操作都不平凡，那么这会立即排除子数组上的任何三次或更高的方法，但仍然留有空间$O(n^2)$或者$O(n^3)$动态规划。 由于每个候选操作仅依赖于子数组和，因此前缀和结构足以在恒定时间内评估任何段，这强烈表明间隔或位置上的二次 DP。 

一个天真的错误是假设贪婪删除有效，总是采用当前最好的段。 这会失败，因为删除局部最优片段可能会破坏形成多个后续片段的能力。 

例如，考虑这样一种情况：尽早获取大段会产生高收益$k$但消除了稍后提取两个较小片段所需的结构，它们的组合$k$更大。 声明中的示例行为已经暗示了这种权衡。 

另一个微妙的失败案例来自于对压缩的误解。 移除后$[l, r]$，下一段不限于停留在附近$r$，因为顺序发生了变化，之前分离的部分变得相邻。 任何将阵列视为永久划分为独立区域的解决方案都将错过有效的转换。 

## 方法

 思考问题最直接的方法就是模拟过程。 在任何时刻，我们都有一个当前序列。 我们尝试每个可能的连续子数组，检查其总和是否匹配$k \cdot d + r$，删除它，然后递归。 这种蛮力探索所有有效删除序列。 它是正确的，因为它直接遵循流程定义。 

然而，这会组合爆炸。 即使对于固定的起始数组，也有$O(n^2)$第一个片段的选择，每次移除后结构都会再次发生变化，导致状态呈指数级增长。 即使记忆也并不简单，因为“状态”不仅仅是一个子集，而是一个有序序列，每次删除后都会改变形状。 

关键的观察是该过程不需要我们显式模拟中间压缩。 重要的是删除哪些段以及以什么顺序删除，因为压缩仅保留相对顺序。 任何有效的删除序列都可以看作是按照原始数组中出现的递增顺序选择不相交的段，其属性是在删除较早的段后，后面的段在压缩结构中仍然是连续的。 这相当于从左到右顺序选择片段，一旦我们在位置完成一个片段$r$，下一段必须在之后的某个位置开始$r$。 

这将问题简化为原始数组上的经典区间 DP：对于每个位置$i$，计算可达到的最佳分数$i$，在每一步我们要么跳过当前元素，要么选择一个从$i$并跳过它。 

我们使用前缀和预先计算所有子数组和，以便我们可以检查有效性并计算$k$在恒定的时间内。 这导致$O(n^2)$过渡结构。

 ## 算法演练

 我们在数组中的位置上定义一个动态编程函数。 

1. 计算前缀和，以便在常数时间内获得任意子数组和。 这是必要的，因为我们会反复测试一个段在$k \cdot d + r$健康）状况。 
2. 定义$dp[i]$作为从索引开始可获得的最大总分$i$在原始数组中，假设我们之前尚未处理过元素$i$。 这体现了我们始终使用当前压缩结构的后缀的想法。 
3. 设置$dp[n+1] = 0$，因为除了最后一个元素之外，没有什么需要处理的。 
4. 对于每个位置$i$从$n$下降到$1$，首先考虑跳过当前元素。 这对应于从不使用索引$i$在任何选定的段中，所以我们传播$dp[i] \ge dp[i+1]$。 
5.然后考虑每一个可能的部分$[i, j]$开始于$i$。 使用前缀和计算其总和。 如果$(\text{sum} - r) \ge 0$并可除以$d$，我们得到一个有效的乘数$k$。 这样的话，我们就可以拿下这个细分市场，赚取$k$，并继续从$j+1$, 贡献$k + dp[j+1]$。 
6. 在所有选择中取最大值$j$和跳过选项。 

这是有效的，因为每个有效的操作序列都对应于一系列不相交的段，按其起始位置的升序排列，并且每个这样的序列都由该 DP 的转换恰好表示一次。 

### 为什么它有效

 DP 保持不变式$dp[i]$表示从以下位置开始的后缀的最佳值$i$在未来所有可能的细分选择下。 职位上的任何决定$i$要么永久排除它，要么将其分配给从$i$。 一旦一段$[i, j]$被选中，未来的线段不能与它​​相交，剩下的问题就是从 开始的后缀$j+1$，它符合状态的定义。 压缩永远不会使这种分解无效，因为它仅删除选定的段并保留所有剩余元素的相对顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, d, r = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def get_sum(l, r_):
        return pref[r_ + 1] - pref[l]

    dp = [0] * (n + 2)

    for i in range(n, 0, -1):
        best = dp[i + 1]

        for j in range(i, n + 1):
            s = get_sum(i - 1, j - 1)
            if s >= r and (s - r) % d == 0:
                k = (s - r) // d
                best = max(best, k + dp[j + 1])

        dp[i] = best

    print(dp[1])

if __name__ == "__main__":
    solve()
```该实现是 DP 定义的直接翻译。 前缀和数组允许恒定时间子数组和计算，这对于保持双循环可行至关重要。 内部循环枚举从每个位置开始的线段的所有可能端点。 

一个微妙的点是包含跳跃过渡`dp[i + 1]`，这确保我们正确地模拟不在位置开始分段的选项$i$。 如果没有它，我们就会错误地强制每个位置属于某个细分市场。 

## 工作示例

 考虑样本，其中$n = 5$,$d = 5$,$r = 1$，数组是$[2, 2, 2, 4, 4]$。 

我们从右到左计算后缀 DP 值。 在每个位置，我们决定是跳过还是采用有效段。 

| 我| 选定的段 [i, j] | 总和| k | dp[j+1] | dp[j+1] 最佳 dp[i] |
 | ---| ---| ---| ---| ---| ---|
 | 5 | [5,5]| 4 | 无效| - | 0 |
 | 4 | [4,4]| 4 | 无效| - | 0 |
 | 3 | [3,4]| 6 | 1 | dp[5]=0 | dp[5]=0 1 |
 | 2 | [2,3]| 4 | 无效| - | 1 |
 | 1 | [1,3]| 6 | 1 | dp[4]=0 | dp[4]=0 2 |

 该跟踪显示了如何选择$[1,3]$以及后来$[3,4]$结构会产生多重贡献，而过早的选择会阻碍未来的发展。 

现在考虑第二个示例想法，其中较大的早期部分可以阻止进一步的收益。 如果我们采用消耗大部分数组的段，则未来的 dp 贡献就会消失，因为没有后缀可以提取额外的有效段。 

这表明了高即时性之间的权衡$k$并保留未来的结构。

 ## 边缘情况

 当没有子数组满足所需的模块化形式时，就会出现关键的边缘情况。 在这种情况下，每个 DP 状态都应该立即回退到跳过，在整个后缀中传播零。 该算法自然地处理这个问题，因为没有转换更新`best`超过`dp[i+1]`。 

另一种情况是唯一有效的段是整个剩余数组。 例如，如果整个数组的总和匹配$k \cdot d + r$，DP只会考虑$[1, n]$作为一个有效的跳转，产生一个单一的转换$dp[n+1]$，并且没有其他部分做出贡献。 当最佳解决方案恰好使用一次大移除时，这可以确保正确性。 

第三种微妙的情况是有效段严重重叠。 DP 正确地处理了这个问题，因为每个状态只考虑从当前索引开始的段，并且重叠的选择会通过未来的状态转换隐式解决，从而确保不会无效地重用已删除的索引。
