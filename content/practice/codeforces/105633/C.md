 ## 解决方案
 ## 问题理解

 我们给出了一组由候选无向道路连接的城市。 每个城市都有一个代表其重要性的权重。 其中，城市 1 是首都横滨。 我们必须选择一个道路子集，在所有城市之间形成一个连接的结构，并且这个结构必须是一棵树，这意味着任何两个城市之间都存在一条简单的路径。 

每条道路都有一个脆弱值。 如果所选树中的一条道路被破坏，树就会分裂成两个部分。 一些城市与首都脱节。 该事件的损害是与城市 1 失去连接的所有城市的重要性值的总和。每条道路的风险贡献是该损害与其脆弱性的乘积，总风险是所有选定树边的总和。 

任务是构建一个生成树，最小化总风险。 

这些约束促使我们在候选边的数量上寻求接近线性或 n log n 的解决方案，因为 n 高达 100000，m 高达 300000。任何尝试模拟每条边的移除或重复重新计算连接的方法都会太慢，因为在最坏的情况下它会导致至少 O(nm) 的行为。 

一个微妙的点是，一条边的“损坏”取决于该边的哪一侧包含最终树中的首都。 这使得边缘的成本取决于全局结构，而不仅仅是局部权重。 

一个天真的错误是认为我们可以选择权重等于 qj 或基于 p 的启发式的最小生成树。 这失败了，因为成本不是独立地按每个顶点或每条边相加； 它取决于相对于根的子树总和。 

例如，考虑一个简单的链 1 - 2 - 3，其中 p = [1, 100, 100]。 如果边 (2,3) 被切断，则仅丢失节点 3，但如果结构不同，则同一条边可能会隔离出更大的总和。 忽略此依赖性的天真的 MST 会选择相同的结构，而不管基于根的分区如何，这是不正确的。 

另一个陷阱是假设我们可以尽早贪婪地连接高权重城市。 节点的成本贡献取决于它是否位于每个边切割的首都侧，这只有在构建完整树后才能确定。 

## 方法

 关键的困难在于，每条边所贡献的成本与该边一侧的节点权重总和成正比，特别是当该边被删除时与资本断开的一侧。 

如果我们修复一棵树，每条边都会将树分成两个部分。 对于边 e，令 S 为不包含节点 1 的分量中 p 值的总和。该边贡献 S * q_e。 

强力方法将枚举所有生成树，计算每个生成树的子树总和，并评估总成本。 生成树的数量是指数级的，即使评估一棵树也是 O(n)，这使得这是不可行的。 

关键的观察是以分离节点贡献的方式重新解释成本。 我们不考虑每条边删除一棵子树，而是颠倒视角：除了根之外的每个节点都与树中的根仅相隔一条边。 该边缘正是“保护”节点免受根影响的边缘。 如果该边被删除，该节点就会断开连接，因此该边会支付该节点的权重。 

这提出了一个双重观点：每个节点的权重沿着从它到根的路径进行计算，但仅通过所选树中该路径上的最大脆弱边缘进行计算，因为该边缘是在故障情况下实际上首先将其切断的边缘。 

形式上，对于节点 v，其贡献是 p[v] 乘以所选树中从 1 到 v 的唯一路径上的最大边缘脆弱性。 这将问题转化为最小化 p[v] 乘以路径最大约束的节点的总和。

这种结构是逆克鲁斯卡尔过程的经典结构：我们希望连接节点，以便高权重节点尽早通过低脆弱性边连接，因为其路径上的任何高脆弱性边都会使它们的权重成倍增加。 

我们按 q 的升序处理边。 我们维护一个 DSU。 当一条边连接两个组件时，我们可以有效地确定一个组件中的所有节点现在通过最多 q 的脆弱边到达根。 增量成本是新连接到包含根的组件的节点的 p 值总和的 q 倍。 

我们通过隐式地将所有内容植根于节点 1 来确保正确性：我们只关心节点何时首次连接到节点 1 的组件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有树 | 指数| O(n) | 太慢了|
 | Kruskal 与 DSU + 根组件跟踪 | O(m log m α(n)) | O(m log m α(n)) | O(n) | 已接受 |

 ## 算法演练

 1. 通过增加脆弱性 q 对所有边进行排序。 这确保我们始终首先考虑最便宜的方式来连接组件。 
2. 初始化 DSU，其中每个城市都是其自己的组件。 维护一个标志，指示每个组件是否连接到首都（节点 1）。 
3. 还维护一个分量权重总和，它是每个 DSU 集中的 p 值之和。 
4. 最初，仅包含节点 1 的组件被标记为连接到首都。 
5. 按排序顺序处理边。 对于每条边 (u, v, q)，找到它们的 DSU 代表。 
6. 如果 u 和 v 已在同一组件中，请跳过它，因为它不会影响连接性或成本。 
7. 如果两个组件中正好有一个连接到首都，则将它们合并会导致一个先前无法访问的组件变得可访问。 成本增加 q 乘以尚未连接到资本的组件的总 p-sum。 
8. 合并两个 DSU 组件，更新它们的 p 值之和，并将所得组件标记为连接到资本（如果任一侧已连接）。 
9. 继续，直到处理完所有边缘。 累计成本就是答案。 

步骤 7 背后的原因是，当新组件通过漏洞 q 的边连接到根时，该边将成为连接时刻从节点 1 到该组件中每个节点的路径上的最高漏洞。 因此，该组件中的每个节点只支付 q * p[v] 一次。 

### 为什么它有效

 每个节点只贡献一次，此时它在 q 递增过程中首次连接到包含节点 1 的组件。 此时，启用连接的边是其到与此构造一致的任何有效树中的根的最终路径上的最大脆弱边。 由于边是按非递减顺序处理的，因此后面的边无法替代已连接节点的这一瓶颈。 这会将节点划分为不断增加的连接时间，并且每个节点的权重都会使用正确的限制边缘值进行一次计费。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def find(parent, x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(parent, size, comp_sum, connected, a, b):
    ra = find(parent, a)
    rb = find(parent, b)
    if ra == rb:
        return ra

    if size[ra] < size[rb]:
        ra, rb = rb, ra

    parent[rb] = ra
    size[ra] += size[rb]
    comp_sum[ra] += comp_sum[rb]
    connected[ra] = connected[ra] or connected[rb]
    return ra

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))

    edges = []
    for _ in range(m):
        u, v, q = map(int, input().split())
        edges.append((q, u - 1, v - 1))

    edges.sort()

    parent = list(range(n))
    size = [1] * n
    comp_sum = p[:]
    connected = [False] * n
    connected[0] = True

    ans = 0

    for q, u, v in edges:
        ru = find(parent, u)
        rv = find(parent, v)
        if ru == rv:
            continue

        if connected[ru] and not connected[rv]:
            ans += q * comp_sum[rv]
        elif connected[rv] and not connected[ru]:
            ans += q * comp_sum[ru]

        union(parent, size, comp_sum, connected, ru, rv)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于 DSU，该 DSU 跟踪每个组件的三条信息：按等级联合的大小、重要性值的总和以及它是否已连接到资本组件。 关键的决定发生在合并组件之前：如果恰好一侧连接到资本，那么整个相反的一侧就变得新可达，并且我们收取其总权重乘以当前边缘漏洞。 

一个微妙的实现细节是，我们必须在任何联合操作之前计算代表根，否则我们将失去“已连接”和“尚未连接”组件之间的区别。

| 步骤| 边缘 | 组件（根集）| 连接集 | 行动| 增加成本|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1-2,2 | {1}、{2}、{3} | {1} | 合并 1 和 2，新组件变为连接 | 2 * 2 = 4 | 2 * 2 = 4

 ## 边缘情况

 一种边缘情况是组件完全形成，但直到更晚的边缘才直接连接到首都。 在这种情况下，所有内部合并都不会产生任何成本，因为该组件尚未位于节点 1 的可达集中。该算法正确地延迟计费，直到出现到根组件的第一个桥，此时整个累积总和将被计费一次。 

当多个组件以相同的漏洞级别连接到资本时，会出现另一种边缘情况。 由于边是按非递减顺序处理的，因此每个合并都会独立触发其新附加组件的成本，并且相等 q 边之间的顺序并不重要，因为每个节点在其第一次附加时间只收取一次费用。 

最后一种情况是图几乎完整，但只有一个缺失的边阻碍了早期连接。 DSU 确保中间周期不会影响成本，因为冗余边缘永远不会合并不同的组件，从而防止重复计算。
