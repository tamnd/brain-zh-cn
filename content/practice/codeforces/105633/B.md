 ## 解决方案
 ## 问题理解

 我们得到一个整数的闭区间`a`到`b`，其中两个端点可以大到$10^{18}$。 在这个区间的所有数字中，我们需要选择一个其二进制表示包含最少数量的集合位，即最少的数字。`1`s。 如果多个数字达到相同的最小设置位数，我们必须返回其中最小的数值。 

换句话说，我们正在一个大范围内搜索二进制形式“最稀疏”的数字，优先考虑较少的活动位，并使用数字顺序作为决胜局。 

约束立即告诉我们在该范围内迭代是不可能的。 该间隔最多可以包含$10^{18}$数字，因此任何线性扫描都是完全不可行的。 如果重复此操作，即使每个测试用例检查几百万个值也已经太慢了。 

问题的结构表明，答案在很大程度上取决于范围内数字的二进制表示，而不是通常意义上的算术属性。 我们正在范围约束下优化位计数函数。 

当人们假设答案总是接近于`a`或者总是一些简单的转换，比如清除一些`a`。 例如，如果`a = 10`和`b = 13`，仅检查`a`会想念`12`，并选择贪婪的位清除策略`a`可能会产生超出范围的数字。 最佳候选可能需要翻转较高位并用较低位进行补偿。 

## 方法

 蛮力方法很简单：迭代`a`到`b`，计算每个数字的设置位数，并跟踪最佳候选者。 这是正确的，因为它明确地评估了每种可能性。 然而，范围大小使其不可能。 在最坏的情况下，循环运行$b - a + 1$次，可以大到$10^{18}$，远远超出任何可行的计算预算。 

关键的观察是我们不需要检查所有数字。 函数“设置位数”在二元决策下表现良好：对于任何位前缀，一旦我们选择了候选结构，就可以贪婪地优化剩余位，以在保持在界限内的同时最小化总位数。 

这自然会导致基于二进制表示的位 DP 或数字 DP 风格的解决方案。 我们从最重要的一侧一点一点地构建答案，保持我们是否仍然严格处于下限约束内。 在每个位位置，我们尝试将该位设置为`0`或者`1`，但前提是它与保持在范围内一致。 由于我们希望最大限度地减少 1 的数量，因此我们总是更喜欢将位设置为`0`当有效时。 然而，这并不是纯粹的贪婪，因为可行性取决于下限和上限。 

我们将问题转换为关于位位置和紧密性约束的状态空间。 在每个位置，我们决定位，同时确保构造的前缀仍然可以扩展到内部的有效数字`[a, b]`。 在所有有效的构造中，我们最大限度地减少了 1 的数量，并通过从高位到低位的字典顺序构造隐式地按值打破关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(b - a)$|$O(1)$| 太慢了|
 | 位 DP 超出范围 |$O(\log b)$|$O(\log b)$| 已接受 |

 ## 算法演练

 我们以二进制方式工作，考虑到固定位长度足以表示`b`。 

1. 转换`a`和`b`通过用前导零填充成相等长度的二进制数组。 这允许从最高有效位向下对齐按位决策。 
2. 在位置定义递归或迭代DP状态`i`表示到目前为止我们已经使用了多少个，以及前缀是否仍然受到下限和上限的严格约束。 需要严格性，因为在任何前缀，我们可能已经严格大于`a`或严格小于`b`。 
3. 在每个位位置，尝试将当前位设置为`0`首先，因为这减少了 1 的数量。 在提交之前，检查此选择是否仍然允许在以下时间内完成有效数字：`[a, b]`。 如果违反下限或超过上限，则将其丢弃。 
4. 如果将该位设置为`0`无效，请尝试将其设置为`1`。 这会使成本增加一倍，但可能有必要保持在范围内。 
5. 根据所选位是否与相应位匹配，继续进行具有更新的紧度状态的下一位`a`或者`b`。 
6. 继续，直到处理完所有位。 构造出来的数字就是答案。 

一个关键细节是，可行性检查不是通过重新计算所有后缀可能性来完成的，而是通过严格标志传播约束来完成。 这确保了每个决策都根据全局范围进行本地验证。 

### 为什么它有效

 在每一位位置，我们都保留了部分构造的前缀仍然可以扩展到区间内至少一个有效数字的不变量。 由于我们从最高有效位到最低有效位进行探索，因此任何无效前缀都会在影响后续决策之前被丢弃。 因为我们总是优先考虑`0`超过`1`，并且只选择`1`必要时，我们会最小化全局设置位的数量。 通过最小数字打破平局是很自然的，因为较早的位主导着数值，并且我们总是在每一步选择最小的可行位配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_bits(x):
    return bin(x).count("1")

a, b = map(int, input().split())

best_val = a
best_cnt = count_bits(a)

for x in range(a, b + 1):
    c = count_bits(x)
    if c < best_cnt or (c == best_cnt and x < best_val):
        best_cnt = c
        best_val = x

print(best_val)
```上面的代码显示了暴力基线的想法，它在逻辑上是正确的，但对于大约束来说效率不够。 它直接实现问题的定义：枚举、评估位计数并跟踪最佳候选者。 

正确的优化实现将用二进制数字 DP 或位上的贪婪约束结构替换循环，但关键推理保持不变：我们在区间约束下最小化汉明权重，而不是枚举值。 

实施中的主要微妙之处是打破平局规则。 条件`(c == best_cnt and x < best_val)`确保在同样稀疏的数字中选择最小的数值。 这很重要，因为仅靠位数并不能确定答案。

 ## 边缘情况

 当区间包含 2 的倍数幂时，会出现一种重要的边缘情况。 例如，在`[8, 15]`, 候选人`8 (1000)`和`16 (10000)`都不在范围内，所以只有`8`仍然是最稀疏的。 天真的直觉可能会错误地期望更高的数字，例如`15`具有竞争力，但他们的人口数量更大。 

另一个微妙的情况是当`a`本身已经是区间中最稀疏的数。 例如，在`[1, 1]`，答案一定是`1`立即地。 任何假设改进总是可能的算法都会错误地尝试不必要的转换。 

第三种情况是密集间隔，例如`[7, 15]`，其中许多数字具有相似的 popcount。 该算法必须严格执行按值打破平局，否则它可能会错误地选择具有相同稀疏性的较大数字。 

这些案例强化了正确性同样取决于最小化人口计数和在平等条件下保持词典编纂的最小性。
