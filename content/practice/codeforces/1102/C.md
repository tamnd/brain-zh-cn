 ## 解决方案
 ## 问题理解

 我们得到了一系列门，每扇门都有一个初始耐用性值。 你和对手交替移动非常多的回合，因此该过程有效地运行，直到双方的最佳策略稳定为止。 

轮到你时，你选择一扇门并对其造成固定数量的损坏`x`，降低其耐用性，但永远不会低于零。 轮到斯拉维克时，他选择一扇门并修复固定数量的门`y`，但不允许他修理已经完全损坏的门（耐久度为零）。 目标是从长远来看最大限度地增加最终完全损坏的门数量（耐用性恰好为零），而斯拉维克则试图最大限度地减少这个数量。 

关键输出是在双方最佳发挥下可以强制减少到零的门数。 

限制很小：最多 100 个门。 这立即表明 O(n²) 甚至 O(n² log n) 解决方案是可以接受的，但任何超过 10^100 圈的模拟都是不可能的。 真正的困难不是迭代，而是在对抗性游戏下独立推理一扇门。 

一个幼稚的错误是模拟转弯或尝试跨门交叉操作。 例如，人们可能认为我们必须模拟交替的损坏和修复，但由于回合数实际上是无限的，因此游戏变成了每扇门的稳态交互，而不是基于时间的模拟。 

第二个微妙的陷阱是假设门相互作用。 但事实并非如此：每一步都恰好触及一扇门，而最佳玩法则简化为决定在对手无限期地维持某扇门之前是否可以完全打破它。 

## 方法

 暴力解释将游戏模拟为一系列动作，并考虑双方玩家在每个回合中的所有可能选择。 每个状态将包括所有耐久性的向量以及轮到谁。 分支因子是`n`每一步，深度都是天文数字。 即使限制在一个很小的范围内，组合也会很快爆炸。 这使得完整的博弈树搜索变得不可能。 

关键的观察是每扇门都是独立的。 唯一的交互是间接的：两个玩家通过选择何时对门采取行动来争夺同一扇门。 由于游戏持续无限长的时间，每扇门都会减少为两人本地比赛：你试图将其减少到零，斯拉维克试图永远保持积极的状态。 

专注于具有初始耐用性的单门`a`。 你减少它`x`，他增加了`y`，但仅限于非零时。 如果你每个周期的有效伤害超过他的修复，你最终可以将其强制为零。 否则的话，他可以无限期地让它活下去。 

决定性的结构是你能否在修复动力稳定之前“完成”一扇门。 一旦耐久度变得足够小，单次攻击就可以杀死它（即 ≤ x），你就可以尝试进行最后一击。 对手唯一的防御就是将其保持在该阈值之上。 这成为每个交互周期的净进度之间的竞争条件。 

标准的减少是：一扇门是可杀死的，当且仅当在修理之后，你的下一次伤害仍然可以杀死它。 这导致了以下情况：

 我们考虑斯拉维克修复后能否一举将耐久度归零，意思是：`a - x + y ≤ x`在重复交互的意义上减少到更简单的基于阈值的检查。 已知结果简化为检查是否`a ≤ x`是否直接可杀，否则是否重复净减`x - y`是积极的并且足以最终进入杀伤范围。 

因此：

 如果`x > y`，每次你击球并且他修复时，你仍然取得净进步。 最终每扇门都可以强制归零，因此所有门都被计算在内。 

如果`x ≤ y`，修复取消或超过损坏，因此只有在第一个修复周期之前可以被杀死的门才能在防御阈值中幸存，即那些具有`a ≤ x`。 

这样可以对每扇门进行清晰的分类。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(10^100·n) | O(10^100·n) | O(n) | 不可能|
 | 每门分析检查 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立对待每一扇门，并决定在最佳发挥下是否可以完全减少到零。 

1.检查你的伤害是否超过Slavik的修复范围（`x > y`）。 

如果是，则每次系统循环时，无论是否尝试进行维修，门的耐用性都会随着时间的推移而下降。 这保证了所有门最终被毁坏。 
2.如果`x ≤ y`，那么斯拉维克就可以阻止长期进步。 在这种情况下，打破一扇门的唯一方法就是在维修周期能够维持它之前完成它。 
3. 对于每扇门，检查其初始耐久度是否足够小，足以在一次有效尝试中被杀死，这意味着`a_i ≤ x`。 
4. 计算有多少扇门满足步骤3中的条件，并输出该计数。 

### 为什么它有效

 每扇门上的过程可以被视为对单个值的重复竞争。 什么时候`x > y`，每个完整的相互作用周期都会严格降低耐久性，因此不存在稳定的正平衡。 什么时候`x ≤ y`，耐久度可以无限期地保持或增加，除非它已经在零的一击之内。 这创建了一个严格的阈值来区分全局可杀和不可杀状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, x, y = map(int, input().split())
a = list(map(int, input().split()))

if x > y:
    print(n)
else:
    ans = 0
    for v in a:
        if v <= x:
            ans += 1
    print(ans)
```代码首先读取参数并存储门耐用性列表。 然后它在关键的不平等上分支`x`和`y`。 什么时候`x > y`，我们直接输出`n`，因为每扇门都可以强制归零。 

否则，我们扫描每扇门并计算那些初始耐用性最多的门`x`，因为只有这些才能在斯拉维克的修复阻止进一步进展之前完成。 该循环是线性的并且不使用额外的内存。 

一个常见的实施错误是忘记决策仅取决于比较`x > y`，而不是移动顺序。 另一个是错误地模拟转弯，这是不必要的，而且速度太慢。 

## 工作示例

 ### 示例 1

 输入：```

2 3 1 3 4 2
```这里`x > y`，意味着每个周期都会产生净损害。 

| 步骤| 门推理|
 | --- | --- |
 | x 与 y | 3 > 2，净减少|
 | 结果| 所有门最终都达到 0 |

 输出是：```
6
```这表明长期漂移占主导地位，每扇门最终都会被摧毁。 

### 示例 2

 输入：```
5 2 3
1 2 3 4 5
```这里`x ≤ y`，所以只有立即杀死才重要。 

| 门| a_i | 检查 a_i ≤ x | 结果 |
 | --- | --- | --- | --- |
 | 1 | 1 | 是的 | 计算|
 | 2 | 2 | 是的 | 计算|
 | 3 | 3 | 没有| 未计算|
 | 4 | 4 | 没有| 未计算|
 | 5 | 5 | 没有| 未计算|

 输出：```
2
```这表明一旦修复占主导地位，只有已经很脆弱的门才能在稳定之前完成。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n, x, y = map(int, input().split())
    a = list(map(int, input().split()))

    if x > y:
        return str(n)
    return str(sum(v <= x for v in a))

# provided sample
assert run("6 3 2\n2 3 1 3 4 2\n") == "6"

# x <= y, mixed values
assert run("5 2 3\n1 2 3 4 5\n") == "2"

# all small, but x <= y
assert run("4 3 5\n1 2 3 4\n") == "3"

# all large, x <= y
assert run("4 2 5\n10 10 10 10\n") == "0"

# single element edge case
assert run("1 5 1\n4\n") == "1"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 | x > y 情况 | 全部 n | 全球胜利制度|
 | 混合值| 部分计数 | 阈值行为|
 | 全部大| 0 | 没有意外杀戮|
 | 单元素| 正确处理 | 边界正确性 |

 ## 边缘情况

 一个重要的边缘情况是当`x == y`。 在这种情况下，损坏与修复完全匹配，因此不可能长期减少。 例如：

 输入：```
3 2 2
1 2 3
```每次你减少一扇门时，Slavik 都会将其恢复到相同的值（如果它还不是零）。 算法正确输入`x <= y`分支，只计算门`a_i ≤ x`，它们是`1`和`2`。 

追踪：

 | 门| a_i | a_i ≤ x | 结果|
 | --- | --- | --- | --- |
 | 1 | 1 | 是的 | 计算|
 | 2 | 2 | 是的 | 计算|
 | 3 | 3 | 没有| 幸存|

 输出是`2`，匹配正确的策略限制，只有立即可完成的门才能被强制为零。
