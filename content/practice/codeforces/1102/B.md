 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并要求为每个位置分配 k 个标签之一，我们将其称为颜色。 每个位置必须接收一种颜色。 同时，从1到k的每种颜色在所有位置中必须至少出现一次。 

还有一项额外的结构限制。 如果我们只查看分配给固定颜色的位置，则这些位置中的所有值都必须成对不同。 换句话说，在每个颜色类别中，我们不允许重复相同的值。 

因此，任务是将索引分配到 k 组中，使得每个组都非空，并且每个组在数组值方面不包含重复项。 

约束 n ≤ 5000 和 k ≤ n 表明 O(n²) 解仍然可行。 任何立方的或涉及子集重复昂贵的重新计算的东西都将是边缘性的，但有时仍然会通过。 这是一个建设性的贪心问题，因此目标是找到稳定的分配而不是优化数值目标。 

当某个值非常频繁地出现时，就会出现第一个微妙的失败情况。 如果某个值出现超过 k 次，则任何有效的解决方案都必须将这些出现的地方放入不同的颜色中，因为颜色内的重复项是被禁止的。 这立即意味着一个下限​​：任何值的最大频率必须最多为 k，否则不存在着色。 

例如，如果 k = 2 并且数组为 [1, 1, 1]，则值 1 出现 3 次，从而强制这些位置使用三种不同的颜色，这是不可能的。 任何忽略频率的简单分配都会错误地产生颜色。 

另一种边缘情况是当 k 与不同值的数量相比较大时。 即使频率很好，我们仍然需要 k 个非空组。 即使我们可以避免冲突，这也迫使我们仔细分配颜色。 

## 方法

 暴力的观点是考虑按顺序分配颜色并尝试所有可能性。 在每个位置，我们可以选择 1 到 k 中不包含相同值的任何颜色。 这导致每一步的分支因子高达 k，并且保持有效性需要检查以前的分配。 在最坏的情况下，这会探索 kⁿ 种可能性，即使 n = 30 也是完全不可行的。 

关键的结构观察是冲突仅取决于平等的价值观。 不同的价值观永远不会相互作用。 因此，对于每个值，我们只需要确保其出现分布在不同的颜色中。 这建议将相同的值作为一个组来处理。 

现在考虑按值对索引进行排序。 分组后，我们以循环方式将每个值的出现次数分布在颜色 1 到 k 之间。 这保证了单一颜色中不会有重复的值，因为我们永远不会将相同的值分配给相同的颜色两次。 同时，如果我们确保使用 k 种颜色，我们可以通过仔细分配前 k 个不同的值来保证每种颜色非空。 

唯一剩下的问题是可行性。 如果任何值出现超过 k 次，我们就会立即失败。 否则，每个值都可以在没有内部冲突的情况下进行分配。 

为了确保使用所有 k 种颜色，我们可以在迭代排序元素时循环分配颜色，但我们必须确保所有颜色至少收到一种分配。 由于 n ≥ k 并且我们为所有元素分配颜色，因此我们可以简单地确保前 k 分配强制使用不同的颜色。

 | 贪心循环赋值 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们继续基于按值对索引进行排序的贪婪构造。

1. 按数组值对索引进行分组。 这使我们能够一起处理相同的价值观，这是必要的，因为冲突只会出现在相同的价值观中。 
2. 对于每个值组，检查其大小。 如果任何组的大小大于 k，则立即得出结论：不存在有效的着色。 这是因为我们将被迫重复使用具有相同值的颜色。 
3. 准备从 1 到 k 的可用颜色列表。 这些代表我们将循环使用的颜色。 
4. 通过迭代组为元素分配颜色。 在每个组内，从调色板中按顺序分配颜色，如果需要，可以环绕。 然而，由于组大小 ≤ k，我们永远不会在组内重复颜色。 
5. 分配完所有组后，确保每种颜色至少出现一次。 这自然是可以满足的，因为只要 n ≥ k，我们就在整个数组中为每种颜色分配至少一个元素，并且我们在分配过程中从不跳过颜色。 

重要的想法是，我们永远不会将相同的值分配给同一种颜色两次，并且我们永远不会留下任何未使用的颜色，因为分配会分布在整个调色板中。 

### 为什么它有效

 核心不变量是在处理每个值组之后，没有颜色包含该值的重复出现。 由于组按值不相交，因此后续步骤不会重新引入先前处理的值的冲突。 此外，由于我们以平衡循环方式分配颜色，因此每种颜色都会尽可能接收分配，从而防止 k ≤ n 时出现未使用的颜色。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    pos = {}
    for i, x in enumerate(a):
        pos.setdefault(x, []).append(i)
    
    # feasibility check
    for x in pos:
        if len(pos[x]) > k:
            print("NO")
            return
    
    res = [0] * n
    
    # assign colors
    color = 1
    for x in pos:
        for idx in pos[x]:
            res[idx] = color
            color += 1
            if color > k:
                color = 1
    
    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```该解决方案首先构建一个字典，将每个值映射到其位置。 这是强制执行必须一起检查相同值的重复项的约束所必需的。 

可行性检查至关重要：如果任何列表超过大小 k，我们会立即停止，因为没有任何分配可以避免在该组内重复颜色。 

着色步骤使用单个全局循环指针。 这确保我们在所有元素上尽可能均匀地分配颜色。 k 处的环绕确保我们重复使用颜色，但绝不会在大小最多为 k 的单个值组内重复使用。

 ### 示例 1

 输入：```
4 2
1 2 2 3
```我们对指数进行分组：

 | 价值| 职位 |
 | --- | --- |

 | 2 | [1, 2] |
 | 3 | [3] |

 我们循环分配颜色：

 | 步骤| 索引 | 价值| 彩色指针| 指定颜色 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 | 1 |

 | 3 | 2 | 2 | 1 | 1 |
 | 4 | 3 | 3 | 2 | 2 |

 最终着色为：```
1 2 1 2
```这表明重复的值 2 会变成不同的颜色。

```团体：

 | 步骤| 索引 | 价值| 颜色 |

```每种颜色至少出现一次，并且在每个值组内，颜色是不同的。

 ## 边缘情况

 当所有元素相同且 n > k 时，算法在频率检查时立即失败。 例如，输入 [5, 5, 5] 且 k = 2 会触发条件，因为值 5 出现了 3 次。 该检查会在任何分配开始之前检测到这一点，从而防止构造无效的循环着色。 

当所有元素都不同时，分组会生成单例列表。 循环赋值只是重复遍历颜色，但由于每个值都是唯一的，因此不会违反任何约束。 这个不变量的成立是微不足道的，因为没有重复项需要管理。
