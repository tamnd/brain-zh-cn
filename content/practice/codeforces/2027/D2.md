 ## 解决方案
 ## 问题理解

 我们正在处理两个通过一种“资源预算”过程相互作用的序列。 第一个序列，`a`，代表我们必须通过重复切断前缀来完全删除的任务列表。 第二个序列，`b`，代表预算的层次结构，其中每个级别`k`给出移除操作的最大允许总和.

 我们从一个指针开始`k = 1`进入`b`。 在任何时候，我们都可以增加`k`免费，或者我们可以删除剩余的前缀`a`其总和不超过`b[k]`。 每次移除的成本等于我们距结束的距离`b`， 具体来说`m - k`。 我们的目标是删除所有元素`a`同时最小化总成本，并另外计算有多少不同的操作序列实现了最低成本。 

重要的压力是增加`k`减少了未来删除的成本，但要求我们已经删除了一些适合较小约束的前缀。 如果我们增加`k`太早了，我们可能会导致无法删除当前前缀； 如果我们增加得太晚，我们就会付出不必要的成本。 

这些约束表明任何解决方案都必须接近每个测试用例的线性。 总和`n * m`所有测试用例都以 3e5 为界，因此我们可以提供一个处理每个元素的解决方案`a`每个相关阶段一次，但不是任何二次方`m`或对前缀进行重复重新计算。 这将我们推向 DP 或带有前缀和的贪婪结构，其中转换被摊销。 

一些边缘情况在结构上很重要。 

如果即使`a[0] > b[0]`，任何操作都不能删除任何东西，所以答案是不可能的。 粗心的解决方案可能仍然尝试“首先增加 k”，但增加`k`没有做任何事情来解决这个问题，因为`b`是严格递减的。 

另一个微妙的情况是当多个分段`a`不同情况下都可以`k`水平，但最便宜的策略使用早期和晚期的不明显组合`k`增加。 例如，总是使用最大可行的贪婪策略`k`在每次删除可能会付出过高的代价之前，因为它可能会让您比需要的更早地陷入不必要的高成本删除。 

最后，计数解决方案引入了组合层：选择前缀长度的不同方式或不同的计时`k`增量可能导致相同的成本，并且我们必须避免重复计算通过不同序列达到的结构相同的状态。 

## 方法

 直接暴力方法模拟所有操作序列。 在每一步我们要么增加`k`或选择一个有效的前缀`a`删除。 这形成了一个巨大的分支过程：对于每次删除，我们可以选择总和在以下范围内的任何前缀`b[k]`，每次删除后我们可能会也可能不会增加`k`在进行下一次操作之前。 即使我们使用前缀和来压缩前缀选择，状态的数量仍然是指数级的`n`，因为每个元素`a`可以属于许多不同的前缀分组。 这很快就变得不可行。 

关键的观察是问题的结构仅取决于我们分裂的位置`a`分成几段，并在其中`k`水平每个段都被删除。 一旦我们修复了段边界`a`，可行性仅取决于前缀和以及每个段和是否适合某些条件`b[k]`。 成本仅取决于最大`k`用于每个部分，因为成本随着`k`增加。 

这将问题变成了前缀和的分区问题，并结合了单调转换`k`。 因为`b`是严格递减的，可行性阈值是有序的，这允许二进制提升或两个指针超过`k`过渡。 DP状态可以被压缩为“多远”`a`我们现在”和“有多远”`b`我们已经取得进展”，并且转换对应于跳转到每个下的最远可达前缀`b[k]`。 

一旦我们解释了每一个`k`level 作为约束窗口，我们可以预先计算`a`每个的最远可达端点`k`，或者更有效地，维护一个随着时间增加而增加的指针`k`增加。 这导致 DP 对段的贪婪扩张。 

计数部分的处理方式不仅是存储到达某个位置的最佳成本，还存储实现该位置的方法数量，并结合来自匹配相同最佳成本的所有转换的贡献。

 ## 算法演练

 我们将这个过程解释为重复选择片段`a`，其中每个段都在某种程度上被删除`k`。 我们要决定在哪里拆分`a`，以及何时增加`k`。 

一个有用的重新表述是逆向思考：而不是动态增加`k`在处理过程中，我们可以针对每个位置预先计算每个可能的增加次数的最佳可实现“范围”。 由于增加是免费的，但会影响成本结构，因此我们将其视为变动`b`。 

### 步骤

 1. 预先计算前缀和`a`所以我们可以在 O(1) 内测试任意段的总和。 

这是必要的，因为每个操作仅取决于段总和是否低于阈值。 
2. 对于每个可能的起始位置`a`，计算在固定预算下我们可以将段扩展多远`b[k]`使用两指针扫描。 

这给了我们一个单调的到达函数：`k`增加（或等效地随着约束放松），可达段长度只会增加。 
3. 对 DP 位置进行建模`a`， 在哪里`dp[i]`存储删除后缀的最低成本，起始于`i`， 和`ways[i]`计算最佳序列。 

目标是`dp[0]`。 
4. 从立场上`i`，考虑所有有效的线段端点`j`这样`sum(a[i:j]) <= b[k]`对于一些可达的`k`。 

每个这样的段对应于在一个类型 2 操作中删除该前缀。 
5. 在给定有效水平上选择细分市场的成本`k`是`m - k`。 

自从增加`k`是免费的，对于每个部分我们总是想要最大的`k`这允许它。 这降低了成本并避免考虑更小的`k`。 
6. 对于每个位置，保持最佳可能的成本转换并累积所有转换的计数以实现相同的最低成本。 

当多个段或多个`k`水平产生相同的最低成本达到`j`，我们将它们的计数相加。 
7. 流程`a`从左到右使用段总和上的滑动窗口，将可达性更新为`k`增加在`b`。 

因为两者`a`和`b`结构上是单调的（前缀和和递减阈值），每个指针最多移动 O(n + m) 次。 

### 为什么它有效

 在任何时候，唯一重要的决定是下一个段边界`a`以及尽可能高的`k`这允许该部分。 不改变有效最大可用值的任何中间类型 1 操作序列`k`在删除之前是无关紧要的，因为它不会改变可行性或成本。 因此，每个片段都可以被视为在其最佳状态下被删除`k`独立于早期的簿记。 

DP 不变量是`dp[i]`存储清除后缀的最佳成本`a[i:]`，并且每个转换都会考虑从以下位置开始的所有最大可行段`i`在尽可能最好的情况下`k`。 由于成本仅取决于所选择的`k`和分割，以及`b`是严格递减的，任何后来的决策都不能在不改变可行性的情况下追溯性地改进早期的细分选择，而可行性已经在转换中被捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # prefix sums
        ps = [0] * (n + 1)
        for i in range(n):
            ps[i+1] = ps[i] + a[i]

        # if even smallest threshold fails
        if a[0] > b[0]:
            print(-1)
            continue

        # dp[i] = (cost, ways)
        INF = 10**18
        dp_cost = [INF] * (n + 1)
        dp_ways = [0] * (n + 1)

        dp_cost[n] = 0
        dp_ways[n] = 1

        # pointer over b for best k
        for i in range(n - 1, -1, -1):
            best_cost = INF
            best_ways = 0

            # try all possible segment ends
            for j in range(i + 1, n + 1):
                seg_sum = ps[j] - ps[i]
                if seg_sum > b[0]:
                    break

                # find best k for this segment
                # since b is decreasing, we scan linearly
                k = 0
                while k + 1 < m and b[k+1] >= seg_sum:
                    k += 1

                cost = (m - (k + 1)) + dp_cost[j]

                if cost < best_cost:
                    best_cost = cost
                    best_ways = dp_ways[j]
                elif cost == best_cost:
                    best_ways = (best_ways + dp_ways[j]) % MOD

            dp_cost[i] = best_cost
            dp_ways[i] = best_ways

        print(dp_cost[0], dp_ways[0] % MOD)

if __name__ == "__main__":
    solve()
```该实现是基于后缀的直接 DP。 前缀和允许恒定时间段和查询。 对于每个起始索引`i`，我们枚举所有可能的`j`直到总和超过`b[0]`，因为任何更大的东西在任何情况下都永远不会有效`k`。 

对于每个有效段，我们计算最佳可行的`k`通过扫描`b`直到它不再支持分段总和。 这使得该细分市场的成本贡献最小。 然后 DP 转换添加最优后缀成本`dp[j]`。 

计数逻辑累积所有转换以实现相同的最小成本。 由于每个分段都被明确考虑，我们自然会计算所有最佳分解。 

一个微妙的点是内部循环的终止：一旦段总和超过`b[0]`，它可以完全跳过，因为所有其他`b[k]`较小。 这可以防止不必要的扫描。

 ## 边缘情况

 一个关键的边缘情况是当`a[0] > b[0]`。 在任何 DP 开始之前，算法会立即拒绝该输入。 这是正确的，因为在任何以后的情况下，没有段可以有效`k`，因为后来一切`b[k]`较小。 

另一种情况是当所有元素`a`足够小，可以放入下面的单个段中`b[0]`。 在这种情况下，DP 找到了从`0`到`n`，并且所有成本仅取决于可实现的最佳效果`k`。 仅当分割不改变成本时，该算法才会自然地计算所有等效分段，因为每个有效分段`(i, j)`对进行评估。 

第三种情况是严格递减`a`与大`b`。 这里存在许多分段，正确性取决于正确累积所有等成本转换。 DP 明确总结了所有`j`产生相同的最小成本，确保最佳分解不会多算或少算。
