 ## 解决方案
 ## 问题理解

 我们有一个数组`a`必须完全删除。 在任何时刻我们都处于某个索引处`k`在数组中`b`，从`k = 1`。 

对于当前值`b[k]`，我们可以重复删除剩余数组中的一个非空前缀，其总和最多为`b[k]`。 每一个这样的移除成本`m - k`。 

我们也可能会增加`k`免费。 自从`b`严格递减、递增`k`使未来的删除更便宜，但也使允许的前缀和更小。 

任务是选择何时转向更大的值`k`以及如何将阵列拆分为可移动的前缀，以便整个阵列以最小的总成本消失。 

如果在某个时刻不存在有效的删除序列，我们必须输出`-1`。 

最重要的限制不是`n`或者`m`单独，但保证$$\sum (n \cdot m) \le 3 \cdot 10^5.$$这立即表明`O(nm)`动态规划解决方案是可以接受的。 每个测试用例的两个维度上的任何二次方仍然适合，因为所有测试用例的总工作量受以下限制：`3 · 10^5`。 

探索所有可能的删除序列的蛮力将是指数级的。 即使是为了`n = 50`，将数组分割成段的方法数量已经非常多了。 

一些边缘情况很容易被忽略。 

考虑```
a = [20]
b = [19, 18]
```第一个元素已超过最大可用限制。 任何情况下都无法删除`k`，所以答案是`-1`。 

考虑```
a = [5, 5]
b = [10, 1]
```搬迁至`k = 2`是免费的，但是没有元素可以被删除，因为`5 > 1`。 最优策略是保持在`k = 1`并以成本移除一切`1`。 

另一个微妙的情况是```
a = [4, 4, 4]
b = [8, 4]
```使用`k = 1`，我们可以删除`[4,4]`一起。 使用`k = 2`，每次操作成本较低，但一次只能删除一个元素。 最便宜的解决方案取决于平衡段大小与操作成本，因此仅基于当前成本或当前容量的贪婪选择是不够的。 

## 方法

 自然的蛮力是将这个过程视为重复选择两个动作之一。 

我们可以增加`k`，或者删除当前限制下的一些有效前缀。 由于每次删除都会改变剩余的数组，而每次增加都会改变未来的成本，因此状态数量呈指数增长。 数组的不同分段对应不同的执行路径。 

这种蛮力之所以正确，是因为它探索了每个有效的操作序列。 它失败的原因是这样的序列的数量变得天文数字。 

为了获得更快的解决方案，我们需要利用运算结构。 

观察一下，一旦我们决定使用某个索引执行删除`k`，我们应该删除以选定位置结尾的最长的可能前缀。 实际操作只关心移除的段和最多为`b[k]`。 

假设我们知道我们已经删除了第一个`i`的元素`a`。 如果我们使用价值`b[k]`对于下一个操作，那么下一个被删除的段可能会延伸到任意位置`j > i`令人满意$$prefix[j] - prefix[i] \le b[k].$$既然所有`a_i`为正，前缀和严格递增。 对于固定`(i,k)`有一个最大可到达位置。 每个较小的位置也是可以到达的。 

这将问题转化为动态规划问题。 

让`dp[k][i]`表示考虑第一个因素后所需的最小成本`k`的值`b`，与第一个`i`元素已被删除。 

来自一个州`(k,i)`我们有两种可能性。 

我们可以跳过`b[k]`完全并移至`(k+1,i)`免费。 

或者我们可以使用以下命令执行一次删除`b[k]`。 如果删除结束于位置`j`，转移成本为`(m-k)`。 

的积极性`a`让我们能够找到最远可达的地方`j`对前缀和使用二分搜索。 

因为`n · m`全局范围为`3 · 10^5`， 一个`O(nm)`DP速度够快。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳DP | O(纳米) | O(n) | 已接受 |

 ## 算法演练

 ### 1. 计算前缀和

 让$$pref[0]=0$$和$$pref[i]=a_1+\dots+a_i.$$由于所有元素都是正的，`pref`是严格增加的。 

### 2. 预先计算每个的可达性`k`对于每个值`b[k]`以及每一个位置`i`，找到最大的索引`reach[k][i]`这样$$pref[reach[k][i]] - pref[i] \le b[k].$$这正是从该位置之后立即开始的一次移除可以到达的最远位置`i`。 

由于前缀和已排序，因此二分查找给出了该位置。 

### 3.定义DP状态

 让$$dp[i]$$表示精确删除第一个的最小成本`i`处理某些前缀后的元素`b`价值观。 

最初```
dp[0] = 0
dp[i] = +∞ for i > 0
```因为还没有删除任何元素。 

### 4. 过程值`b`一一

 对于每个索引`k`:

 创建一个新数组`ndp`初始化为副本`dp`。 

这个副本代表跳过当前值`b[k]`。 

### 5. 使用`b[k]`用于搬迁

 对于每个职位`i`成本有限：

 接下来的运营成本$$m-k-1$$在从零开始的索引中。 

该操作可能会在之间的任何时间结束`i+1`和`reach[k][i]`。 

如果我们天真地更新所有这些位置，复杂性就会变成二次方。 

相反，通过差异式扫描执行范围最小更新。 

对于每个州`(i)`:```
all positions in [i+1 , reach[k][i]]
can receive dp[i] + cost
```处理完所有状态后，扫描辅助结构并应用最小值。 

这给出了当前的所有转换`k`在线性时间内。 

### 6. 替换`dp`经过`ndp`所有转换后使用`b[k]`应用后，继续使用下一个值`b`。 

### 7. 阅读答案

 全部处理完后`m`价值观：```
dp[n]
```是移除整个阵列的最小成本。 

如果仍为无穷大，则输出`-1`。 

### 为什么它有效

 对于每个值`b`，DP 考虑两种合法选择：要么完全忽略该容量，要么执行一项额外的删除，其段总和尊重该容量。 

每个有效的操作序列对应于一系列 DP 转换，因为每次移除都会选择一个起始位置、一个结束位置和一个值`k`。 

相反，每个 DP 转换都代表语句中的一个有效操作。 

可达性计算保证当所选段总和不超过当前限制时，恰好存在转换。 由于代表了所有可能的合法转换，并且 DP 保持其中成本最小，因此最终值恰好是可实现的最小总成本。 

## Python 解决方案```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

INF = 10**18

t = int(input())

for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    reach = [[0] * (n + 1) for _ in range(m)]

    for k in range(m):
        limit = b[k]
        for i in range(n):
            r = bisect_right(pref, pref[i] + limit) - 1
            reach[k][i] = r

    dp = [INF] * (n + 1)
    dp[0] = 0

    for k in range(m):
        cost = m - k - 1

        ndp = dp[:]

        add = [INF] * (n + 2)

        for i in range(n):
            if dp[i] == INF:
                continue

            l = i + 1
            r = reach[k][i]

            if l <= r:
                val = dp[i] + cost
                if val < add[l]:
                    add[l] = val

        cur = INF
        for pos in range(1, n + 1):
            cur = min(cur, add[pos])
            if cur < ndp[pos]:
                ndp[pos] = cur

        dp = ndp

    ans = dp[n]
    print(-1 if ans == INF else ans)
```第一部分构建前缀和。 因为所有的值`a`如果是正数，则前缀数组上的二分搜索可以正确找到最远的可移动端点。`reach[k][i]`准确存储一项操作使用的距离`b[k]`从位置开始时可能会延伸`i`。 

DP 存储每个删除的前缀长度的最小成本。 复印`dp`进入`ndp`实现跳过当前的选项`b[k]`。 

微妙的部分是有效地处理所有转换。 来自一个州`i`，连续区间内的每个位置都会收到相同的候选值。 我们不是单独更新每个端点，而是在间隔开始处插入值并在扫描期间传播最小值。 这使得每层的总工作量保持线性。 

所有成本都适合 64 位整数，但使用 Python 整数可以完全避免溢出问题。

def run(inp: str) -> str:

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pref = [0]
        for x in a:
            pref.append(pref[-1] + x)

        reach = [[0] * (n + 1) for _ in range(m)]

        for k in range(m):
            for i in range(n):
                reach[k][i] = bisect_right(
                    pref,
                    pref[i] + b[k]
                ) - 1

        dp = [INF] * (n + 1)
        dp[0] = 0

        for k in range(m):
            cost = m - k - 1
            ndp = dp[:]

                ndp[pos] = min(ndp[pos], cur)

            dp = ndp

        out.append(str(-1 if dp[n] == INF else dp[n]))

    return "\n".join(out)

 ## 边缘情况

 考虑```
1
1 2
20
19 18
```第一个元素超出了每个可用的限制。 在可达性计算过程中，每个`reach[k][0]`等于`0`。 没有位置转换`0`存在，所以`dp[1]`永远不会变得有限。 算法输出`-1`。 

考虑```
1
2 2
5 5
10 1
```和`b=10`，整个数组可能会立即被移除，代价是`1`。 搬迁至`b=1`首先会使移除变得不可能。 DP探索这两种可能性并保持最低有效成本，产生`1`。 

考虑```
1
3 2
4 4 4
8 4
```使用较大的限制，可以将前两个元素一起删除。 然后使用更便宜的限制删除剩余元素。 可达性区间正确捕获了两个路段选择，并且 DP 找到了最小成本`1`。 这验证了该解决方案并不依赖于始终采用最便宜或始终采用最大可用限制的贪婪选择。
