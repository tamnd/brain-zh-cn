 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个节点代表一个程序状态。 每个状态对变量执行以下三件事之一：`0`表示该变量被忽略。`1`意味着变量被赋予了新值。`2`表示该变量已被使用。 

如果一个状态属于至少一个具有以下结构的有向路径，则该状态被称为有趣的：

 该路径从分配状态开始，以使用状态结束，并且在开始分配之后，路径上没有其他分配。 

最后一个条件是问题的全部难度。 一旦出现第二个分配，旧值将被覆盖并不再相关。 

对于每个顶点，我们必须输出它是否可以位于这种类型的某些有效路径上。 

该图最多可以包含$10^5$顶点和$10^5$边缘。 这立即排除了任何尝试显式探索所有路径的算法。 在密集情况下，即使从每个分配节点独立运行 DFS 也会变得过于昂贵。 我们需要接近线性时间的东西，大致$O(n + m)$。 

该图也不保证是非循环的。 循环很重要，因为一旦我们进入一个可以从一个分配到达的区域而不触及另一个分配，该区域中的每个节点都可以无限期地保持有效。 

一些边缘情况很容易被错误处理。 

考虑这个图：```
1(assign) -> 2(assign) -> 3(use)
```输入：```
3 2
1 1 2
1 2
2 3
```正确答案是：```
0 1 1
```状态 1 并不有趣。 从 1 到使用节点的任何路径都会经过状态 2，状态 2 首先覆盖该值。 仅检查“可以到达使用节点”的粗心可达性解决方案会错误地标记状态 1。 

另一个微妙的情况是赋值节点本身也是唯一感兴趣的节点。```
1(assign) -> 2(ignore)
```输入：```
2 1
1 0
1 2
```正确输出：```
0 0
```从未达到使用状态，因此分配的值无关紧要。 

周期也需要小心：```
1(assign) -> 2(ignore) -> 3(ignore)
                  ^         |
                  |---------|
3 -> 4(use)
```所有四个节点都很有趣，因为在 1 处分配之后，我们可以在最终到达 4 之前循环任意多次。假设 DAG 结构的算法在这里失败。 

## 方法

 蛮力的想法很简单。 对于每个分配节点，执行图形遍历，每当遇到另一个分配节点时就会停止。 每个最终能够通向使用节点的被访问节点都属于有效路径。 

这是正确的，因为遍历完全模拟了原始值存在的所有路径。 问题是成本。 在最坏的情况下可能会出现$10^5$分配节点，每次遍历可能会扫描整个图。 复杂度变为$O(n(n+m))$，太大了。 

关键的观察是我们实际上并不关心哪个分配节点启动了该值。 我们只关心某个节点是否可以从某个分配到达而不跨越另一个分配，以及在另一个分配覆盖该值之前我们是否仍然可以从该节点到达使用状态。 

这建议在全球范围内传播信息，而不是反复重新启动搜索。 

如果变量的当前值仍然有效，我们将状态定义为“活动”。 从赋值节点开始，该值就变为活动状态。 遍历忽略或使用节点会保留它。 遍历另一个赋值会破坏旧值并开始一个新值。 

这将问题转化为带有障碍的图可达性问题。 

我们可以分两个阶段来解决。 

首先，我们从所有分配节点向前传播，但我们永远不会继续经过另一个分配节点。 每个被访问的节点都是可访问的，同时保留当前值。 

其次，在这些可到达的节点中，我们确定哪些节点可以在不跨越另一个分配的情况下到达使用节点。 这可以通过反转图并从所有使用节点向后传播，再次在分配边界处停止来完成。 

如果两个条件同时满足，则节点是有趣的。 

整个过程仅访问每条边恒定次数，从而给出线性复杂度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n(n+m))$|$O(n+m)$| 太慢了 |
 | 最佳|$O(n+m)$|$O(n+m)$| 已接受 |

 ## 算法演练

 1. 构建有向图及其逆图。 

从使用节点向后传播需要反向图。 
2. 从每个分配节点启动多源 BFS 或 DFS。 

这些节点代表值变得活跃的地方。 
3. 在此遍历期间，正常地穿过传出边，但不要从不同的分配节点继续。 

如果我们从赋值节点开始`s`，那么到达另一个赋值节点意味着那里的原始值被覆盖。 
4. 将每个访问过的节点标记为`from_assign`。 

这意味着可以在携带一些有效变量值的同时到达该节点。 
5. 开始另一个多源遍历，这次是从每个使用节点开始，但在反向图上。 

向后遍历回答了这个问题：“这个节点最终能导致使用状态吗？”
 6. 再次，在穿过赋值节点时停止传播。 

一旦我们通过另一个赋值，当前值就会发生变化，因此较早的状态不再对最终使用有贡献。 
7. 将每个访问过的节点标记为`to_use`。 

这意味着存在从节点到使用状态的路径，而无需首先覆盖该值。 
8. 对于每个节点，输出`1`如果两者都`from_assign[node]`和`to_use[node]`是真的。 否则输出`0`。 

### 为什么它有效

 当一个节点位于以赋值开始并以使用结束且没有中间赋值的路径上时，它才是有趣的。 

前向遍历标识在值被覆盖之前从某些分配可到达的所有节点。 

向后遍历识别在另一个分配出现之前仍然可以达到使用情况的所有节点。 

如果一个节点的两个条件都成立，那么我们可以将两个相应的路径段连接成一个有效的完整路径。 相反，如果一个节点属于有效路径，则它必须满足定义的两个属性。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    f = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        rg[b].append(a)

    from_assign = [False] * n
    q = deque()

    for i in range(n):
        if f[i] == 1:
            from_assign[i] = True
            q.append(i)

    while q:
        u = q.popleft()

        for v in g[u]:
            if from_assign[v]:
                continue

            from_assign[v] = True

            if f[v] != 1:
                q.append(v)

    to_use = [False] * n
    q = deque()

    for i in range(n):
        if f[i] == 2:
            to_use[i] = True
            q.append(i)

    while q:
        u = q.popleft()

        for v in rg[u]:
            if to_use[v]:
                continue

            to_use[v] = True

            if f[v] != 1:
                q.append(v)

    ans = []

    for i in range(n):
        ans.append('1' if from_assign[i] and to_use[i] else '0')

    print('\n'.join(ans))

solve()
```图和反向图都是必要的，因为这两种遍历回答了相反的可达性问题。 

第一个 BFS 同时从所有分配节点开始。 微妙的细节是，分配节点仍然标记为可达，但传播在那里停止，除非该节点本身是初始源。 此模型可以正确覆盖。 

第二个 BFS 在反转图上反映了相同的逻辑。 从使用节点开始向后走确定哪些状态最终可以对使用做出贡献。 

条件：```
if f[v] != 1:
    q.append(v)
```是两次遍历的临界线。 我们仍然将赋值节点标记为可达，因为赋值状态本身可能很有趣，但我们永远不会使用旧值继续超越它们。 

最终答案是两个可达性集的交集。

 ## 边缘情况

 再次考虑覆盖场景：```
3 2
1 1 2
1 2
2 3
```正向遍历从两个赋值节点开始。 

从节点 1 开始，遍历到达节点 2，但在那里停止，因为节点 2 是另一个分配。 旧的价值不能再继续下去。 

从节点2开始，遍历到达节点3。 

从节点 3 向后遍历到达节点 2，但无法继续经过节点 2 到达节点 1，因为节点 2 覆盖了该值。 

交叉点变成`{2,3}`仅，生产：```
0
1
1
```现在考虑循环示例：```
4 4
1 0 0 2
1 2
2 3
3 2
3 4
```从节点1开始的前向遍历进入2和3之间的循环，并标记两个节点可达。 由于两个节点都不是分配，因此传播正常继续。 

从节点 4 开始向后遍历，通过逆循环边到达节点 3，然后到达节点 2。 

所有节点都满足这两个条件，因此每个节点都被标记为有趣。 

最后，考虑一个有分配但没有用的图：```
3 2
1 0 0
1 2
2 3
```前向遍历标记从分配可到达的所有节点。 向后遍历不从任何节点开始，因为不存在使用状态。 

这`to_use`数组仍然完全错误，所以每个答案都变成`0`。 

这正确地捕捉到了这样一个事实：一个值只有在最终被使用时才重要。
