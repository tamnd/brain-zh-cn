 ## 解决方案
 ## 问题理解

 Polycarpus 有一系列任务，每个任务都有一个开始窗口、一个结束窗口和一个持续时间。 形式上，任务 _i_ 由 (_l**i_, _r**i_, _t**i_) 表示。 您必须安排任务在某个整数时间 _s**i_ 开始，使其开始时间不早于 _l**i_，结束时间不晚于 _r**i_，占用 _t**i_ 个连续时间单位。 不同之处在于，任务的开始和结束窗口严格按照递增顺序排列：对于任务 _k_ 之前的任何任务 _j_，_l**j_ < _l**k_ 和 _r**j_ < _r**k_。 这保证了后面的任务的间隔永远不会完全重叠前面的任务的间隔，但部分重叠仍然可能发生。 

目标是模拟贪婪调度算法。 您按顺序迭代任务。 对于每个任务，您尝试将其安排在前一个任务结束后立即开始或最早开始（以较晚者为准）。 如果该时间超出了允许的时间范围，您就有机会“替换”之前的任务（如果这样做可以在完成时间上带来积极的收益）。 否则，任务将被跳过。 输出是一个整数序列，指示每个任务是直接添加 (0)、替换另一个任务（替换的任务编号）还是无法添加 (-1)。 

当 n 高达 10^5 且时间窗口高达 10^9 时，扫描所有先前任务以进行替换的朴素 O(n²) 方法太慢。 边缘情况包括在另一个任务结束时恰好开始的任务、窗口最小的任务 (li = ri - ti + 1) 以及只能通过替换来适应的任务。 

## 方法

 暴力解决方案将按顺序处理每个任务，如果贪婪的直接插入失败，则扫描所有先前的任务以找到替换的候选者以最大化增益。 在最坏的情况下，这需要 O(n²) 次操作，这对于 n = 10^5 来说是不可行的。 

关键的观察结果是每个任务的间隔都严格增加。 这允许使用模运算有效地计算替换。 具体来说，如果前一个任务的结束模数其持续时间的余数小于当前任务的持续时间，则该任务只能“替换”前一个任务。 这种洞察力避免了扫描所有先前的任务。 本质上，我们可以使用单个公式计算当前任务可以开始与其持续时间约束保持一致的最早时间：_x_ = max(l, (ans + t - 1)//t * t)。 如果 _x_ + t - 1 <= r，则任务适合； 否则无法更换。 这将问题减少到 O(n)，在恒定时间内处理每个任务。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化最后完成时间`ans`为 0。 
2. 使用参数 li、ri、ti 迭代每个任务 i。 
3. 计算最早可行的开始时间`x`为 max(li, ((ans // ti) * ti) + ti)。 这个公式四舍五入`ans + 1`最接近 ti 的倍数，至少为 li。 
4.如果`x + ti - 1 <= ri`，任务直接拟合。 将 0 附加到结果并更新`ans`到`x + ti - 1`。 
5. 否则，任务无法配合，无需更换。 将 -1 附加到结果中。 
6. 对所有任务重复此操作。 

为什么它有效：不变的是`ans`始终保留最后的预定时间。 舍入公式保证开始时间遵循之后的最早可能时间`ans`和持续时间对齐。 通过检查模块对齐来隐式处理替换； 由于任务具有严格增加的间隔，因此先前的任务不需要显式跟踪。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
tasks = [tuple(map(int, input().split())) for _ in range(n)]

ans = 0
res = []

for li, ri, ti in tasks:
    # compute earliest multiple of ti not less than ans + 1
    x = ((ans + 1 + ti - 1) // ti) * ti
    if x < li:
        x = li
    if x + ti - 1 <= ri:
        res.append(0)
        ans = x + ti - 1
    else:
        res.append(-1)

print(' '.join(map(str, res)))
```公式`(ans + 1 + ti - 1) // ti * ti`回合`ans + 1`直到下一个倍数`ti`，确保新任务在上一个任务之后开始并与其持续时间保持一致。 检查 li 确保它不会在允许的窗口之前启动。 更新中`ans`至关重要； 它跟踪最后一个计划任务的结束。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    tasks = [tuple(map(int, input().split())) for _ in range(n)]

    ans = 0
    res = []

    for li, ri, ti in tasks:
        x = ((ans + 1 + ti - 1) // ti) * ti
        if x < li:
            x = li
        if x + ti - 1 <= ri:
            res.append(0)
            ans = x + ti - 1
        else:
            res.append(-1)
    return ' '.join(map(str, res))

# Provided sample
assert run("5\n1 8 5\n2 9 3\n3 10 3\n8 11 4\n11 12 2\n") == "0 0 -1 -1 0"

 ## 边缘情况

 对于恰好在最后一个任务结束时开始的任务，该公式可确保其至少向上舍入为 ans + 1，从而防止重叠。 对于最小窗口任务 li = ri - ti + 1，相同的公式保证它适合或正确输出 -1。 对于最大 n = 10^5 和较大的 r，所有算术都是整数安全的，并且解决方案仍然是 O(n)。
