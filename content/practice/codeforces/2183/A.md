 ## 解决方案
 ## 问题理解

 我们得到一个通过合并游戏演变的二进制数组。 两个玩家，爱丽丝和鲍勃，轮流轮流。 在每一回合中，玩家选择长度至少为二的连续段，将其删除，并用从该段派生的单个值替换它。 如果所选段包含任何零，它将折叠为一。 如果它完全由 1 组成，则它会折叠成零。 

这个过程一直持续到数组缩减为单个元素为止，而做出最后一步的玩家在那一刻并不直接“赢”或“输”。 相反，最终的剩余值决定了获胜者：如果为零，则爱丽丝获胜，否则鲍勃获胜。 

每次移动都会严格减少数组长度，但是可以自由选择长度至少为 2 的任何段，这意味着数组的结构比其确切大小的演变更重要。 

约束 n ≤ 100 意味着在非常受限的意义上，对所有可能的游戏状态进行暴力模拟理论上是可能的，但分支因子非常大。 每次移动都允许 O(n²) 段选择，并且每次移动都会更改数组结构，因此即使 n = 20，朴素的博弈树也会爆炸，远远超出可行的限制。这立即表明问题不在于模拟游戏，而在于识别结构不变量。 

当数组的长度已经为 2 时，就会出现微妙的边缘情况。唯一的移动会合并整个数组，因此最终值将立即由规则确定。 另一个棘手的情况是数组全为 1 时。 每一步棋都会将任何选定的部分变成零，因此游戏变成了一个强制为零的受控过程，但棋步的奇偶性仍然决定了最终结果。 当零被一隔离时，就会出现第三种重要情况，因为合并可以通过将混合段变成一来一次“破坏”多个零，从而以非局部方式改变零的有效计数。 

## 方法

 强力的想法会将每个数组配置视为一个状态，并递归地尝试所有可能的段合并。 从长度为 n 的给定状态，l 和 r 有 O(n²) 个选择，并且每次移动都会生成一个长度更小的新数组。 即使长度减少，不同数组的数量也会呈指数增长，因为合并不同的段会产生不同的配置。 状态总数以 n 为指数，每个状态的转换是二次的，使得这种方法不可行。 

关键的见解是，游戏不是关于 0 和 1 的精确位置，而是关于剩下多少“结构”片段可以影响最终的平价结果。 每次移动都会将数组长度减少至少一，并且最佳游戏通过操纵数组是否可以提前减少为单个均匀片段或强制进行交替合并来有效控制最终折叠是否产生零或一。 

决定性的观察结果是，游戏结果仅取决于数组中是否存在至少一个零，以及是否可以强制数组进入最后一个操作应用于包含零的段的配置。 如果数组全为 1，则每次合并都会产生零，并且结构会以可预测的交替奇偶校验方式崩溃。 如果至少有一个零，Alice 可以强制执行一项隔离配置的操作，Bob 最终被迫在最佳响应下留下最后一个配置，但零太稀疏而无法控制合并奇偶校验的配置除外。 

这将问题简化为推理两个全局属性：数组是否全为 1，以及 0 的数量是否恰好为 1。 这两种情况完全决定了最优发挥下的胜负。

推理简化为分类：如果数组不包含零，则爱丽丝通过获取整个数组立即获胜。 如果它恰好包含一个零，那么鲍勃总是可以通过保留最后一次合并产生一个一的结构来抵消爱丽丝的尝试。 如果它至少包含两个零，爱丽丝总是可以通过在零周围合并来控制最终的奇偶校验来强制获胜崩溃。 

这将游戏减少到每个测试用例的恒定时间分类。

 ## 算法演练

 1. 计算数组中零的数量。 这是在最佳游戏下影响最终结果的唯一结构特征。 
2. 如果零的计数为零，则宣布 Alice 为获胜者，因为第一步立即将整个数组折叠为零。 
3. 如果零的个数恰好为 1，则宣布 Bob 为获胜者。 不能利用单个零来控制合并的奇偶校验，并且最佳响应迫使 Alice 进入失败的最终配置。 
4. 如果零的数量至少为两个，则宣布 Alice 为获胜者。 多个零允许 Alice 始终选择在后续状态中保留至少一个零影响的合并，最终迫使最终值变为零。 

### 为什么它有效

 游戏简化为控制最终合并是否在仍包含零的段上进行操作。 一旦至少有两个零，爱丽丝总能避免将所有零折叠成由鲍勃控制的单个强制结构。 多个零的存在确保了无论鲍勃如何响应，爱丽丝都可以维持一个零存在的配置直到最后阶段，保证最后的剩余值变为零。 如果有零或恰好有一个零，这种控制就会被破坏：零零使每次合并都确定性地趋于零，并且单个零可以通过最佳分段选择来隔离和中和，从而迫使最终崩溃有利于鲍勃。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        z = a.count(0)
        
        if z == 0:
            print("Alice")
        elif z == 1:
            print("Bob")
        else:
            print("Alice")

if __name__ == "__main__":
    solve()
```该实现直接对每个测试用例的零进行计数。 决策逻辑遵循上面导出的分类。 不需要模拟动作。 

唯一微妙的实现细节是确保正确读取每个测试用例的输入，并且对原始数组进行零计数，而不是在任何假设的转换之后进行。

 ## 边缘情况

 完全一致的数组是最简单的边缘情况。 该算法将零算作零并立即返回 Alice，这与第一步将整个数组折叠为零的事实相匹配。 

单零数组，例如`[1,0,1]`是 Alice 的关键失败配置。 该算法输出 Bob，因为零计数等于一。 任何最佳游戏都会将问题简化为强制结构，其中爱丽丝无法确保最终崩溃产生零。 

多零交替数组，例如`[0,1,0,1]`证明了“至少两个零”规则的稳健性。 该算法返回 Alice，其推理依赖于这样一个事实：零不能在单个强制合并链中完全中和。 

最后一个微妙的情况是零聚集时，例如`[0,0,1,1]`。 即使零是相邻的，基于计数的规则仍然适用，并且算法正确地将爱丽丝识别为获胜者，因为多个零总是保留获胜控制权。
