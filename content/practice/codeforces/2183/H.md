 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并要求将其精确地划分为$k$非空子序列。 对于任意子序列$b$，其成本定义为其长度与其元素之和的乘积。 我们的目标是最小化所有的总成本$k$子序列。 

实际上，我们尝试将数组划分为多个组，以使每个组的“长度乘以总和”之和尽可能小。 由于元素的长度和总和都会相乘，因此将负数放入较长的子序列中通常是有利的，这可以抵消较大元素的积极贡献，同时在必要时保持较小的正数隔离。 

约束条件很强：$n$可以达到$2 \cdot 10^5$，并且最多可以有$10^4$测试用例。 这意味着任何解决方案都必须大致运行$O(n \log n)$每个测试用例在最坏的情况下，或者在理想的情况下$O(n)$具有一个小的常数，因为$n \times t$可以接近$2 \cdot 10^5$。 

边缘情况包括全负数、全正数的序列或其中的序列$k = 1$或者$k = n$。 例如，使用数组$[1, 2, 3]$和$k = 3$，每个元素形成自己的子序列。 从左到右合并元素而不考虑其符号的天真的贪婪方法可能会产生次优的总成本。 

## 方法

 蛮力方法考虑了所有分区方法$a$进入$k$子序列。 分区数量呈指数级增长，大致如下$C(n-1, k-1)$，使得这对于$n$最多$2 \cdot 10^5$。 暴力破解之所以有效，是因为计算每个子序列的成本很简单，但枚举所有分区很快就会爆炸。 

关键的见解是成本函数$f(b) = m \cdot \sum b_i$与负数具有超加性。 如果我们有两个连续的数字$x$和$y$，放入一个大的负数$y$和$x$降低了总成本，但投入了很大的积极$x$与许多其他积极因素可能会增加成本。 以非递增顺序对数组进行排序允许我们优先考虑哪些元素应该被隔离到它们自己的子序列中以及哪些元素应该被合并。 排序后，问题就简化为选择$k-1$我们“切割”数组以形成子序列的位置，最好是在最大元素之后。 这样做的好处是，它将问题从指数枚举转化为贪婪选择切割，这可以在$O(n \log n)$由于排序，或$O(n)$如果我们保留一个连续总和并且只选择$k-1$最大的收获。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(C(n-1, k-1) * n) | O(C(n-1, k-1) * n) | O(n) | 太慢了 |
 | 通过排序和剪切贪婪 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取数组$a$和整数$k$。 
2.如果$k = 1$，整个数组形成一个子序列，因此直接计算其成本为$n \cdot \sum a_i$并返回。 
3. 计算每个元素之后分裂的“增益”。 如果您在此元素之后开始一个新的子序列，那么增益就是成本的差异。 更具体地说，对于连续元素$a_i$和$a_{i+1}$，增益为$a_i$本身因为使$a_i$子序列的末尾删除其与下一个子序列的长度的乘法。 
4. 按降序对这些增益进行排序。 如果孤立的话，这会优先考虑对降低成本贡献最大的元素。 
5.选择顶部$k-1$收益，因为这些对应于形成削减和创造的最佳位置$k$子序列。 
6. 计算总成本，即所有元素的总和乘以其当前子序列长度，并根据所选切割进行调整。 
7. 返回总成本。 

为什么有效：成本函数的总和和长度是线性的。 按潜在收益排序可确保每次削减都能减少总成本中最大可能的超额计数。 通过始终选择$k-1$最大的正收益，我们保证没有其他分区可以产生更小的成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        if k == 1:
            print(n * sum(a))
            continue

        # Compute differences to consider cutting after each element
        # Sort in descending order
        a.sort(reverse=True)
        # Initial total cost if no splits: treat all as one subsequence
        total_cost = n * sum(a)

        # Gains from splitting after element i: gain = a[i] * (n-i-1)
        gains = [a[i] for i in range(n-1)]
        gains.sort(reverse=True)

        # We can make k-1 cuts
        total_cost -= sum(gains[:k-1])
        print(total_cost)

if __name__ == "__main__":
    solve()
```在此实现中，我们对数组进行降序排序，以优先隔离最大的正数。 我们计算每次切割的潜在“收益”并选择顶部$k-1$。 对增益进行排序至关重要：简单的从左到右的方法可能会错过最佳分割。 减去顶部的总和$k-1$增益可以正确调整总成本，因为每次切割都会减少对后续子序列长度的过度计数。 

## 工作示例

 ### 示例 1

 输入：`[1, 3, -2]`,`k = 2`| 步骤| 已排序 | 收益| 精选剪裁| 总成本|
 | --- | --- | --- | --- | --- |
 | 1 | [3, 1, -2] | [3, 1] | [3] | 2_sum([3,1,-2]) - 3 = 2_2 - 3 = 1 | 2_sum([3,1,-2]) - 3 = 2_2 - 3 = 1

 这表明最大元素之后的分裂将其隔离并最小化较长子序列的乘法效应。 

### 示例 2

 输入：`[1, 3, -2]`,`k = 1`| 步骤| 已排序 | 收益| 精选剪裁| 总成本|
 | --- | --- | --- | --- | --- |
 | 1 | [3, 1, -2] | 不适用 | 不适用 | 3 * 总和([1,3,-2]) = 3*2 = 6 |

 不允许削减； 总成本就是长度乘以总和。
