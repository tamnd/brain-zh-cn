 ## 解决方案
 ## 问题理解

 我们得到一个像素网格形式的图像，其中每个像素都有一个 RGB 颜色。 每种颜色都是 3D 整数空间中的一个点，坐标范围为 0 到 255。任务是将整个图像替换为单一 RGB 颜色，以便每个原始像素与所选颜色之间的总平方偏差尽可能小。 

形式上，每个像素贡献的成本等于 RGB 空间中其原始值和所选颜色之间的欧几里德距离的平方。 总损失是所有像素上的这些平方距离的总和。 我们需要选择一个 RGB 三元组来最小化这一总和。 

约束 n × m ≤ 100000 意味着我们最多处理十万个 3D 点。 任何尝试所有候选颜色或在所有像素之间执行成对比较的解决方案都会太慢。 我们应该期待一种解决方案，将所有内容减少到对数据的几次线性传递。 

一个微妙的问题是，如果我们不断地处理这个问题，最优的 RGB 值不一定是整数。 由于有效颜色必须是 [0, 255] 中的整数，因此我们需要小心处理舍入。 另一种边缘情况是当所有像素都相同时，答案显然应该是零损失，并且所选颜色必须与该像素完全匹配。 例如，仅尝试现有像素颜色作为候选颜色的简单方法仍然是正确的，但如果不是所有坐标都对齐，则可能会错过真正的最佳值。 

## 方法

 一个蛮力的想法是在 256 × 256 × 256 空间中尝试每种可能的 RGB 颜色，计算每种颜色的总平方损失，然后选择最好的。 这在概念上很简单，因为它直接遵循问题的定义。 然而，候选数量为 16,777,216，对于每个候选，我们将扫描多达 100,000 个像素，导致大约 10^12 次操作，这远远超出了任何合理的时间限制。 

我们可以改为分析成本函数的结构。 损失是平方项的总和，重要的是它跨维度分开。 总成本是三个独立一维问题的总和：一个用于 R，一个用于 G，一个用于 B。其中每个问题都将平方差之和最小化为单个选定值。 

对于单一维度，标准事实是平方误差的实值最小者是算术平均值。 这减少了从搜索所有颜色到计算每个通道平均值的问题。 由于我们仅限于整数，因此最佳整数选择必须接近平均值，并且检查其周围最接近的整数就足够了。 

这将问题简化为单个线性通道来计算总和，然后不断地工作来评估一些候选点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有颜色| O(256立方·纳米) | O(1) | O(1) | 太慢了|
 | 基于均值的优化 | O(n·m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 1.读取所有像素并累加通道总和

 我们迭代每个像素并提取其 R、G 和 B 值。 我们维持三个连续金额。 这将所有空间结构压缩为聚合统计数据，因为损失函数仅取决于距离，而不取决于位置。 

### 2. 计算每个通道的平均颜色

 处理完所有像素后，我们将每个总和除以像素数 N。这独立地给出了每个维度的平方误差的实值最小化值。 

### 3. 识别候选整数值

 由于有效的 RGB 值必须是整数，因此我们考虑每个平均值周围最接近的整数。 对于每个通道，这通常是下限（平均值）和上限（平均值），固定为 [0, 255]。 我们不需要更多的候选者，因为平方误差函数在每个坐标中都是凸的。 

### 4. 评估候选 RGB 值的所有组合

我们形成最多 2 × 2 × 2 = 8 种候选颜色。 对于每个候选者，我们计算所有像素的总平方距离。 这一步在像素数量上仍然是线性的，但是常数因子很小。 

### 5. 选择候选者中损失最小的

 我们保留最小的计算值作为答案。 

### 为什么它有效

 关键属性是平方欧几里得损失的可分离性。 目标是每个坐标中独立的凸二次函数的总和。 对于任何单个坐标，最佳实数解是平均值，并且任何整数解都必须位于它附近，因为当我们远离平均值时，函数单调增加。 仅检查均值周围的相邻整数可以保证我们包含全局离散最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse_rgb(s):
    r = int(s[0:3])
    g = int(s[4:7])
    b = int(s[8:11])
    return r, g, b

def calc_loss(pixels, x, y, z):
    total = 0
    for r, g, b in pixels:
        dr = r - x
        dg = g - y
        db = b - z
        total += dr * dr + dg * dg + db * db
    return total

def main():
    n, m = map(int, input().split())
    pixels = []
    
    sr = sg = sb = 0
    for _ in range(n):
        row = input().split()
        for s in row:
            r, g, b = parse_rgb(s)
            pixels.append((r, g, b))
            sr += r
            sg += g
            sb += b

    npx = len(pixels)

    mr = sr / npx
    mg = sg / npx
    mb = sb / npx

    def candidates(mean):
        c = [int(mean)]
        if mean - int(mean) > 1e-12:
            c.append(int(mean) + 1)
        return list(set(max(0, min(255, v)) for v in c))

    rc = candidates(mr)
    gc = candidates(mg)
    bc = candidates(mb)

    ans = float("inf")
    for r in rc:
        for g in gc:
            for b in bc:
                ans = min(ans, calc_loss(pixels, r, g, b))

    print(ans)

if __name__ == "__main__":
    main()
```该解决方案首先使用固定切片将每个像素字符串解析为整数，这是安全的，因为格式始终用零填充为每个通道三位数字。 我们存储所有像素，因为我们需要重新计算候选颜色的损失。 

我们计算每个通道的浮点平均值，然后生成它们周围的候选整数值。 小邻域就足够了，因为远离平均值会单调增加平方误差。 

最后，我们通过扫描所有像素并对距离平方求和来评估每个候选颜色。

 ## 边缘情况

 关键的边缘情况是所有像素都相同。 在这种情况下，平均值恰好等于像素值，并且算法崩溃为单个候选，产生零损失。 任何错误地强制双向舍入的实现仍然有效，但可能会引入不必要的候选者。 

另一种情况是均值正好位于两个整数之间的中间。 例如，如果通道平均值为 127.5，则必须检查 127 和 128。 该算法明确地包括两个邻居，确保不会错过最佳值。 

最后的边缘情况是极端倾斜，例如一个像素为 0，所有其他像素为 255。均值接近 255，候选生成正确地避免探索不相关的内部值，保持搜索效率，同时仍然捕获正确的边界解。
