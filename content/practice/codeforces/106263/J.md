 ## 问题理解

 我们给出了一个由平面上的直线段组成的几何道路网。 每个路段代表两个端点之间的双向道路，但“清扫”行为是有方向性的：当扫雪机沿着路段从一个端点行驶到另一个端点时，它只会清除该方向。 为了清除相反的方向，车辆必须在某个时刻反向穿过同一路段。 

车辆从其中一个路段的指定端点开始，并允许沿路段移动、反向移动以及在任何共享端点或交叉点处的路段之间切换。 所有线段形成一个单一的连接结构，并且任何一对线段最多相交于一个点，因此道路系统的行为就像嵌入平面中的平面图。 

任务是计算车辆必须行驶的最小总距离，以便每个路段至少在两个方向上经过一次。 该路径不需要返回起点，并且段可以与其他运动部分交错，只要最终在两个方向上访问每个段上的每个点即可。 

输入大小最多为 10,000 个段，因此任何尝试模拟遍历选择或搜索路线的解决方案都会太慢。 路径上的二次或状态空间将立即失败，如果正确理解关键结构，甚至依赖于配对边或求解欧拉轨迹变体的图优化技术也将是不必要的开销。 

一个微妙的点是，交叉点并不会降低遍历的要求。 即使两个段交叉，在清洁方面也不会产生共享的“边缘重用”效果，因为清洁仍然是按段方向定义的，而不是按几何覆盖路径定义的。 

一个天真的错误是认为这是一条访问所有边一次的最短路线，类似于旅行推销员或路线检查问题。 例如，当两个路段交叉时，人们可能会尝试找到一条巧妙的路线来“共享”它们之间的遍历。 然而，由于每个线段必须在两个方向上独立地遍历，因此共享不会减少所需的总遍历长度。 

例如，如果我们有两个线段交叉：

 输入：```
2
0 0 2 2
0 2 2 0
0 0
```每个线段都有固定的长度，无论我们如何遍历交叉点，每个线段仍然需要两次完整的遍历。 任何通过巧妙布线来降低成本的尝试最终仍将重新覆盖相同的几何距离。 

## 方法

 强力解释会将其视为几何图上的路线规划问题：枚举段上可能的遍历顺序，模拟沿边缘的移动，并跟踪每个段的哪些方向已被清理。 每个状态都需要对每个段的当前位置、方向和完整方向的位掩码进行编码。 

即使进行乐观修剪，这种方法也会立即爆炸。 当 n 达到 10,000 时，涉及边子集的状态数量呈指数级增长，即使扩展状态空间上的简化最短路径也需要至少 O(2^n) 或 O(n·2^n) 行为，这是完全不可行的。 

关键的观察结果是，问题在各个部分之间完全解耦。 唯一的要求是每个线段在每个方向上遍历一次。 不同路段之间不存在影响成本的耦合约束，因为转弯或切换路段在端点或交叉点处是自由的，并且遍历成本仅取决于路段长度。 

这意味着总成本只是所有所需遍历的总和。 每个线段的贡献正好是其欧几里得长度的两倍：每个方向各一次。 起始位置不会改变此要求，因为它不会消除遍历任何线段方向的需要。 

因此，整个问题简化为计算所有线段的总长度并将其加倍。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力搜索路线 | 指数| 指数| 太慢了|
 | 段长度总和 × 2 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取所有线段并计算其端点之间的欧氏距离。 每个部分都是独立的，因此我们将其视为对最终答案的独立贡献。 
2. 累加所有线段长度的总和。 这表示沿一个方向遍历每个线段一次所需的距离。 
3. 将总和乘以 2。这说明了每个路段必须双向遍历的要求，并且任何路径共享都无法减少这种必要性。 
4. 将结果值输出为具有足够精度的浮点数。 

### 为什么它有效

 每个线段恰好具有一个几何长度，并且清理规则强制每个线段恰好进行两次遍历，每个方向一次。 由于遍历成本是纯粹的度量且与方向无关，因此每个可行的解决方案必须包括每个段至少 2 × 长度。 

同时，可行性也是微不足道的：我们总是可以向前遍历每个线段，然后向后遍历它，使用交叉点或端点在线段之间移动，而不影响总距离。 由于除了沿线段行进之外，转换不会增加成本，因此所有所需遍历的总和既是下限又是可实现的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def main():
    n = int(input())
    total = 0.0

    segments = []
    for _ in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        dx = x1 - x2
        dy = y1 - y2
        total += math.hypot(dx, dy)

    start_x, start_y = map(int, input().split())

    print("{:.10f}".format(2 * total))

if __name__ == "__main__":
    main()
```该解决方案使用以下方法计算每个段的长度`math.hypot`，对于欧几里得距离来说是数值稳定的。 读取起点但不使用起点，因为它不会影响所需的总遍历成本。 

乘以 2 是核心步骤：它将双向清洁要求直接编码到成本模型中。

import sys, io
import math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    total = 0.0
    for _ in range(n):
        x1, y1, x2, y2 = map(int, sys.stdin.readline().split())
        total += math.hypot(x1 - x2, y1 - y2)
    sys.stdin.readline()
    return "{:.10f}".format(2 * total)

 ## 边缘情况

 零长度段是最简单的极端情况。 如果两个端点相同，则无论方向如何，其贡献都为零，因此加倍规则仍然会产生零，而不影响正确性。 

密集的交叉路口网络不会改变解决方案。 即使许多线段在共享点交叉，算法仍然会独立处理它们，因为遍历成本严格与线段长度相关，而不与路径如何通过几何交错相关。 

任意的起始位置也不影响答案。 尽管它保证起点位于某个线段的端点上，但它并不能消除在两个方向上遍历该线段的需要，因此初始位置没有提供特殊的优化机会。
