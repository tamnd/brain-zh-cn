 ## 解决方案
 ## 问题理解

 我们收到了许多独立的查询。 每个查询提供两个整数$a$和$b$，并且我们必须计算通过它们的质因数分解定义的值。 

任务是查看任一数字中出现的所有素数。 对于每个素数$p$，我们检查它是否整除两者$a$和$b$。 如果是的话，我们包括$p$在产品中只出现一次。 如果没有质数可以整除这两个数字，则答案定义为零。 否则，我们将所有这些公共素数相乘。 

因此，每个查询的输出与多重性无关，仅与素数是否共享有关。 重复的权力，如$p^k$或者$p^m$无关紧要超越存在$p$在两个因式分解中。 

约束很严格：最多$2 \cdot 10^5$查询，每个数字可以大到$2 \cdot 10^6$。 这立即排除了使用试除法将每个数字独立分解到其平方根，因为这会导致粗略的结果$2 \cdot 10^5 \cdot \sqrt{2 \cdot 10^6}$，太大了。 

经常出现的一个天真的想法是计算每个查询的两个数字的素数分解，然后与素数集相交。 这在时间压力下会失败，因为即使使用优化的试除法，跨 200k 查询的重复分解也太慢。 

另一个微妙的失败案例是重新计算两个数字的除数并动态检查素数。 例如，在类似的输入中$a = 999983$和$b = 999979$，都是素数，朴素分解对每个数字几乎持续进行工作，但仍然对每个查询重复大量检查。 

关键的结构问题是我们在有限范围内重复分解数字。 这强烈建议对所有主要信息进行一次预处理。 

## 方法

 蛮力方法计算质因数分解$a$和$b$对于每个查询，使用试除法。 提取每个数字的素数集后，我们计算它们的交集并将这些素数相乘。 

这是正确的，因为它直接遵循定义。 然而，每次分解成本高达$O(\sqrt{n})$，并与$n \le 2 \cdot 10^6$, 这是周围$1400$每个数字的操作。 每个查询有两个号码，最多$2 \cdot 10^5$查询，我们大致得出$5.6 \cdot 10^8$操作，速度太慢。 

关键的观察是我们不需要对每个查询进行完全分解。 我们只需要知道哪些素数可以整除一个数，并且可以为每个整数预先计算$2 \cdot 10^6$使用改良的筛子。 我们不存储完整的因式分解，而是仅存储不同质因数的无平方乘积。 然后，每个查询简化为计算这些转换值的最大公约数。 

如果我们定义$f(x)$作为不同质因数的乘积$x$，那么答案就变成了$\gcd(f(a), f(b))$。 这是有效的，因为每个素数贡献一次，并且 gcd 自然地选择公共素数，同时忽略重数。 

这会将每个查询转换为对预计算值的单个 gcd 操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（每个查询的因素）|$O(T \sqrt{n})$|$O(1)$额外 | 太慢了|
 | 筛分+gcd还原|$O(N \log \log N + T \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 1. 预先计算一个数组`spf`或者直接建一个数组`val`在哪里`val[x]`是不同质因数的乘积`x`。 这是通过对所有数字进行筛选来完成的$2 \cdot 10^6$。 当我们第一次遇到质数时$p$，我们将其乘以所有的倍数$p$，确保每个数字只收集每个素数一次。 
2. 对于每个整数$x$，确保每个素数仅贡献一次。 这意味着当迭代多个$p$，我们不会重复乘以更高的幂，例如$p^2$。 这可以通过标准筛来处理，每个基本素数仅传播一次素数。 
3. 预处理后，每个数字$x$被它的无平方表示取代$val[x]$。 
4. 对于每个查询$(a, b)$, 计算$g = \gcd(val[a], val[b])$。 
5. 如果$g = 1$，由于没有公共素因数，因此输出 0。 
6.否则输出$g$，它是所有共享素数的乘积。 

### 为什么它有效

 每个数字都可以唯一地表示为素数与指数的乘积，但我们丢弃指数并只保留素数是否出现。 筛子确保每个素数对其除法的每个倍数都贡献一次。 所以，$val[x]$是素数集除法的乘积$x$。 

两个这样的乘积的 gcd 准确地保留了在两个因式分解中出现的素数，因为不同素数的乘积的 gcd 对应于素数集的交集。 这可以确保正确性，而无需显式分解每个查询的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 2_000_000

val = [1] * (MAXN + 1)

# modified sieve: build square-free product of prime factors
for i in range(2, MAXN + 1):
    if val[i] == 1:  # i is prime (not yet marked)
        for j in range(i, MAXN + 1, i):
            val[j] *= i

T = int(input())
out = []

for _ in range(T):
    a, b = map(int, input().split())
    g = __import__("math").gcd(val[a], val[b])
    out.append(str(g if g > 1 else 0))

print("\n".join(out))
```预处理循环构建每个整数的转换表示。 条件`val[i] == 1`识别素数，因为合数已经乘以更小的素数。 然后，每个素数通过其倍数传播一次，确保每个数字仅累积不同的素数因子。 

然后，查询部分是恒定时间的，直到进行 gcd 操作。 最终转换为零处理不存在公共素数的特殊情况。 

这里的一个常见陷阱是忘记必须避免同一素数的重复乘法。 筛子结构通过只处理每个素数一次来自然地确保这一点。

## 测试用例```python
import sys, io
import math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXN = 2_000_000
    val = [1] * (MAXN + 1)

    for i in range(2, MAXN + 1):
        if val[i] == 1:
            for j in range(i, MAXN + 1, i):
                val[j] *= i

    T = int(input())
    out = []
    for _ in range(T):
        a, b = map(int, input().split())
        g = math.gcd(val[a], val[b])
        out.append(str(g if g > 1 else 0))
    return "\n".join(out)

def run(inp: str) -> str:
    return solve(inp)

# provided samples
assert run("1\n60 70\n") == "10"
assert run("1\n12 175\n") == "0"

# custom cases
assert run("1\n2 3\n") == "0"          # disjoint primes
assert run("1\n8 4\n") == "2"          # repeated powers should not matter
assert run("1\n30 105\n") == "15"      # multiple shared primes
assert run("3\n6 10\n12 18\n7 49\n") == "2\n6\n0"

 ## 边缘情况

 一个微妙的情况是当一个数字是纯幂时，例如$a = 64$和$b = 8$。 两者都是 2 的幂，所以正确答案是 2。筛子表示给出`val[64] = 2`和`val[8] = 2`，所以 gcd 为 2，符合预期。 

另一种情况是数字根本不共享素数，例如$a = 999983$和$b = 999979$，都是素数。 The representation becomes themselves, and gcd is 1, producing output 0.

A final case is when numbers contain repeated primes, such as$a = 72 = 2^3 \cdot 3^2$。 筛子将其压缩成`val[72] = 6`。 任何正确的解决方案都必须确保重复的乘法不会扭曲乘积，否则 gcd 会错误地对素数进行计数。
