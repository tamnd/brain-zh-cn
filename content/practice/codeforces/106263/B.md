 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每一个中，我们都会收到一个整数列表，代表一组石头的“魔力”。 对于每一对无序的不同宝石，我们计算它们的值的按位与，然后将所有对的结果相加。 

因此，该任务纯粹是组合性的：每一对都贡献一个由两个数字之间的共享设置位确定的值。 每个测试用例的输出是所有对的总和。 

关键的结构挑战是对的数量随 n 呈二次方增长。 当测试中 n 达到 200,000 时，对的数量约为 2×10^10，这立即排除了任何直接对枚举。 即使有多个测试用例，总 n 也可以达到 400,000，因此任何解决方案都必须接近线性或线性对数。 

朴素推理的一个微妙的失败案例是假设成对 AND 的行为类似于算术平均值，或者可以在不考虑位独立性的情况下进行聚合。 例如，如果所有数字都相同，则说`[7, 7, 7]`, 每对都贡献`7 & 7 = 7`，所以答案是`3 * 7 = 21`。 错误地计算每个元素而不是每个元素对的贡献的幼稚尝试很容易通过混合有序和无序对来过度计数或低估。 

另一个陷阱是忘记按位运算可以清楚地分解每个位，但前提是每个位都被独立处理。 任何试图在不进行逐位推理的情况下重建 AND 值的方法在大的约束下往往会崩溃。 

## 方法

 暴力解决方案将迭代所有对`(i, j)`和`i < j`并计算`(a[i] & a[j])`，累加结果。 这是正确的，因为它直接遵循问题的定义。 然而，它的成本与对的数量成正比，在最坏的情况下是`n(n-1)/2`。 和`n = 2 × 10^5`，这变得完全不可行。 

按位与的结构建议进行分解：我们可以独立地查看每个位的位置，而不是计算每对的完整值。 一点贡献`2^k`当且仅当该对中的两个数字都设置了该位时，才为该对的最终 AND 和。 这将问题从关于值的推理转变为关于位计数的推理。 

对于固定位`k`， 认为`cnt_k`数字已设置此位。 由这些形成的任何对`cnt_k`数字贡献`2^k`到答案。 这样的对的数量是`cnt_k * (cnt_k - 1) / 2`。 将所有位相加得出最终结果。 

这是可行的，因为按位与是在独立位位置上相加的，并且位之间不存在进位或交互。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 位计数 | O(n·31) | O(n·31) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例并使用每比特计数来计算答案。 

1. 初始化一个数组或循环结构来计算每个位包含多少个数字。 自从`a[i] ≤ 10^8`，我们只需要 30 以内的位。 
2. 对于数组中的每个数字，检查每个位的位置。 如果该位被设置，则增加相应的计数器。 这将构建一个频率表，其中包含每个位包含多少个数字。 
3. 对于每个位位置`k`，计算可以由具有该位集的数字形成多少对。 如果`cnt_k`数字包含位`k`，有效对的数量是`cnt_k * (cnt_k - 1) // 2`。 
4.每一对都做出贡献`2^k`到最后的总和。 将此贡献相乘并添加到答案中。 
5. 输出测试用例的累积结果。 

我们在计算频率之后对对进行计数的原因是，对的形成仅取决于具有位的数字集合中的成员资格，而不取决于与其他位的排序或交互。 

### 为什么它有效

 每对对每个位的最终总和都有独立的贡献，其中两个数字共享一个 1。如果我们固定一个位位置，则所有对的贡献完全取决于有多少个数字包含该位。 由于不同的位位置不会相互干扰，因此对各个位的贡献求和会在每个对位组合上重建所有对上的完整 AND 总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * 31  # enough for values up to 1e9

        for x in a:
            b = 0
            while x:
                if x & 1:
                    cnt[b] += 1
                x >>= 1
                b += 1

        ans = 0
        for k in range(31):
            c = cnt[k]
            if c > 1:
                ans += (c * (c - 1) // 2) * (1 << k)

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案使用每比特频率阵列`cnt`。 对于每个数字，我们使用位移位来分解它，而不是重复屏蔽每个位索引，这使实现简单并避免额外的开销。 

一个常见的实现错误是错误地迭代位并不小心地破坏性地移动原始数字。 在这里，我们使用移位循环重建位位置`x`，因此每个数字都被安全地消耗而不会影响其他数字。 

组合公式`c * (c - 1) // 2`必须以 64 位安全算术计算。 Python 自然地处理大整数，因此溢出不是问题。

该迹线表明，每个位都独立贡献，并且数字之间的重叠正确累积。

 ## 边缘情况

 单元素测试如`n = 1`暴露实现是否错误地假设至少存在一对。 在这种情况下，位计数可能不为零，但配对公式正确地得出零，因为`cnt * (cnt - 1) / 2`为零。 

对于像这样的输入`3 1 2 4`，每个数字都有不相交的位，因此每个 AND 都为零。 位计数方法将每个位计数恰好设置为 1，从而使每位产生零贡献，与预期结果相匹配。 

对于均匀数组，例如`5 5 5 5`，每个位出现四次，算法计数`6`每比特对，正确地再现了所有对具有相同且等于 5 的事实。
