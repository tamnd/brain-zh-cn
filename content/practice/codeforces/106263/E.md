 ## 解决方案
 ## 问题理解

 我们得到一个严格递增的整数序列。 从这个序列中，我们最多可以删除`k`元素，保留原始顺序的剩余子序列。 结果序列的值仅由两个连续剩余元素之间的最小差异确定。 如果剩余元素少于两个，则该值被视为无穷大。 

任务是选择要删除的元素，以便剩余序列中的最小相邻间隙变得尽可能大。 

核心困难在于删除元素会间接增加间隙，但我们受到可以执行的删除次数的限制。 每个选择都会影响所有未来的差距，因此局部决策很容易打破全局最优。 

约束允许最多`2 × 10^5`所有测试用例的总元素。 这立即排除了尝试所有子集甚至所有删除模式的任何解决方案，因为这会呈指数增长。 在最坏的情况下，即使每个测试用例都采用二次方法也会太慢。 

当尝试在没有目标间隙的情况下进行贪婪删除时，会出现微妙的失败情况。 例如，如果我们总是删除产生最小间隙的局部“坏”元素，我们可能会破坏一个在不同删除后允许更好的全局最小间隙的结构。 

另一种边缘情况发生时`k = 0`。 那么答案是由原始数组强制的，因此任何算法都必须正确处理不允许删除的情况，并且仍然输出有效的删除集。 

最后，当最优解保留的元素很少时，很容易错误地输出多于`k`除非构建与可行性密切相关，否则会被删除。 

## 方法

 暴力方法将尝试最多删除所获得的每个子集`k`元素。 对于每个子集，我们计算所有相邻差异并取最小值。 即使我们只考虑精确`n - k`保留的元素，选择它们的方式数量仍然是组合的，大致`O(n choose k)`，这远远超出了可行的范围。 

关键的观察是我们不需要直接决定删除哪些元素。 相反，我们翻转视角：假设我们确定了一个候选答案`x`，这意味着我们希望最终序列中的每个相邻对至少相差`x`。 现在的问题变成了检查我们是否可以选择一个满足这个约束的子序列，同时最多删除`k`元素。 

对于固定的`x`，我们可以通过始终采用最早的可能元素并跳过所有违反规则的内容来贪婪地构建最长的有效子序列`x`间隙要求。 这种贪婪的构造是最优的，因为一旦我们选择了一个元素，延迟下一个选择只会减少未来的选择。 

这将问题转化为单调可行性检查，从而可以进行二分搜索`x`。 如果有间隙`x`是可以实现的，那么任何更小的差距也是可以实现的，因为约束变得更弱。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 二分查找+贪心检查| O(n log A) | O(n log A) | O(n) | 已接受 |

 这里`A`是数组中值的范围。 

## 算法演练

 我们希望在删除限制下找到有效子序列中最大可能的最小间隙。 

1.我们对答案进行二分查找`x`，允许的最小相邻差异。 搜索范围是从`0`到`a[n-1] - a[0]`。 该范围涵盖所有可能的有意义的间隙，因为相邻差异不能超过整个跨度。 
2.对于固定的`x`，我们通过贪婪地构造子序列来检查可行性。 我们首先总是选择第一个元素。 
3. 我们从左到右扫描数组。 每当当前元素至少为`last_selected + x`，我们保留并更新`last_selected`。 否则，我们会跳过它，就像它被删除一样。 
4. 扫描后，我们计算保留了多少元素。 如果`kept >= n - k`， 然后`x`是可行的，因为如果需要，我们总是可以删除额外保留的元素，同时保持在删除预算之内。 
5. 使用二分查找，我们找到最大的可行值`x`。 
6. 我们使用这个最优值再次运行贪婪过程`x`，记录保留哪些索引。 
7.所有其他索引形成删除集。 我们输出它的大小和索引。 

### 为什么它有效

 贪心检查产生满足间隙约束的子序列的最大可能大小`x`。 任何有效的子序列都必须遵守相同的排序约束，并且选择较早的有效元素绝不会降低未来的可行性。 这使得贪婪解决方案对于固定`x`。 二分搜索是有效的，因为可行性是单调的`x`，所以一旦间隙不可能出现，所有更大的间隙也就不可能出现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def feasible(a, k, x):
    n = len(a)
    cnt = 1
    last = a[0]
    for i in range(1, n):
        if a[i] - last >= x:
            cnt += 1
            last = a[i]
    return cnt >= n - k

def build(a, x):
    n = len(a)
    keep = [False] * n
    last = a[0]
    keep[0] = True
    for i in range(1, n):
        if a[i] - last >= x:
            keep[i] = True
            last = a[i]
    return keep

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 0, a[-1] - a[0]

        while lo <= hi:
            mid = (lo + hi) // 2
            if feasible(a, k, mid):
                lo = mid + 1
            else:
                hi = mid - 1

        best = hi
        keep = build(a, best)

        delete_idx = []
        for i in range(n):
            if not keep[i]:
                delete_idx.append(i + 1)

        if len(delete_idx) > k:
            delete_idx = delete_idx[:k]

        print(len(delete_idx))
        if delete_idx:
            print(*delete_idx)
        else:
            print()

if __name__ == "__main__":
    solve()
```可行性函数计算在保持最小间隙的同时可以保留多少元素`x`。 构造函数重复相同的贪婪过程，但记录决策。 二分搜索确保我们最大化允许的最小间隙，并且最终的删除列表只是保留集合的补集。 

一个微妙的点是贪婪保留了最大可能的元素数量，因此如果它已经保留了超过`n - k`，我们仍然是安全的，因为我们可以删除少于`k`元素。 

## 工作示例

 考虑`a = [1, 4, 6, 10]`,`k = 1`。 

我们二分搜索寻找最佳的最小间隙。 

为了`x = 5`, 贪心选择`1`, 跳过`4`, 跳过`6`, 保持`10`，所以只保留 2 个元素。 自从`n - k = 3`，这是不可行的。 

为了`x = 3`, 贪心选择`1`, 保持`4`, 跳过`6`, 保持`10`，给出3个元素，这是可行的。 

现在我们最大化并找到`x = 3`。 

| 步骤| 索引 | 价值| 最后选择 | 保留？ | 计数|
 | ---| ---| ---| ---| ---| ---|
 | 开始| - | - | - | 1 保持在 1 | 1 |
 | 我=2 | 2 | 4 | 1 | 是的 | 2 |
 | 我=3 | 3 | 6 | 4 | 没有| 2 |
 | 我=4 | 4 | 10 | 10 4 | 是的 | 3 |

 最终删除的是索引`3`。 

这显示了贪婪过程如何强制执行最小间隙约束，同时仍然最大化剩余元素的数量。 

现在考虑`a = [2, 3, 7, 8, 15]`,`k = 2`。 

对于像这样的大间隙`x = 7`，我们保留`2, 8, 15`，这是可行的。 如果我们尝试`x = 8`，我们只保留`2, 15`，这不足以满足删除约束。 二分搜索确定最大的可行值。 

该迹线显示了缩小所需间隙如何减少可选择元素的数量，而可行性纯粹取决于我们是否仍然可以保留足够的元素。

 ## 边缘情况

 当`k = 0`，贪婪构造从不用于删除。 二分查找仍然可以正确评估可行性，但最终的删除列表必须为空。 该算法自然会处理这个问题，因为所有元素都保持标记为保留。 

什么时候`n - k = 1`，可行性条件变得微不足道，因为任何单个元素就足够了。 贪婪总是会返回至少一个元素，并且该算法正确地允许大`x`值，尽管最终答案无关紧要，因为不存在相邻差异。 

当最优解保留几乎所有元素时，贪婪仍然会产生所需大小的有效超集，我们只需截断至多`k`通过选择保留集的补集来进行删除。
