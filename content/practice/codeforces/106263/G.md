 ## 解决方案
 ## 问题理解

 我们有一个回合制游戏，是在一堆糖果上玩的。 两名玩家交替移动，第一个玩家总是先移动。 每次移动，当前玩家必须从堆中取出 1、3 或 4 颗糖果。 如果玩家开始回合但无法做出合法的移动，这意味着堆是空的或没有允许的移动符合剩余计数，则该玩家立即失败。 

每个测试用例都会给出初始糖果数量，我们需要确定哪个玩家在最佳玩法下获胜。 输出只是获胜玩家的名字：“Orange”代表第一个移动者，“ice”代表第二个移动者。 

这些约束允许最多 100000 个测试用例，n 的值最多为 1e9。 这立即排除了在直至 n 的整个范围内的任何每次测试动态编程。 即使是高达 1e9 的线性 DP 也是不可能的，甚至预计算高达 1e9 在时间和内存上也是不可行的。 该解决方案必须在一个小的预处理阶段后将每个查询减少到恒定时间或导出直接公式。 

有两种微妙的边缘情况常常打破天真的推理。 

首先，n = 0。第一个玩家没有动作，立即失败，所以答案一定是“冰”。 任何假设起始位置获胜的 DP 都会错误地将其标记为胜利，除非明确处理。 

其次，像 n = 2 这样的小值会暴露出不正确的贪婪思维。 从 2 颗糖果中，唯一的举动是拿走 1 颗，为对手留下 1 颗，该位置为下一位玩家获胜。 因此，2 对于当前玩家来说是失败的，即使它可能看起来对称或“小到足以获胜”。 

第三种结构边缘情况是允许的移动不像 {1,2} 那样对称。 3 和 4 的存在创建了周期性结构而不是简单的奇偶校验模式。 任何将游戏简化为“奇数胜，偶数败”的尝试都会立即失败，例如 n = 3 就是直接获胜，因为你可以拿走所有糖果。 

## 方法

 分析这场比赛最直接的就是标准公正的比赛DP。 让我们定义一个状态 dp[n]，如果当前玩家可以在剩余 n 颗糖果的情况下强制获胜，则该状态为 true。 从位置 n 开始，玩家尝试所有有效的移动：移除 1、3 或 4 个糖果，并在这些状态存在时转换到 dp[n-1]、dp[n-3] 和 dp[n-4]。 如果至少有一步棋导致对手输掉局面，则该局面为获胜局面。 

这种递推式是正确的，但计算到 n = 1e9 是不可能的。 即使我们只计算到像 1e7 这样的适度限制，测试用例的数量和内存需求也会变得太大。 

关键的观察是，这是一个具有固定移动集的减法游戏。 此类博弈通常在短前缀之后变得周期性，因为状态仅取决于少量先前值。 这里 dp[n] 仅取决于 dp[n-1]、dp[n-3] 和 dp[n-4]，因此状态空间是有界的，并且序列最终会重复。 

通过计算前几十个值的 dp，我们观察到重复模式。 事实上，亏损头寸会在周期 7 中重复出现。一旦识别出该周期，每个查询都会减少到计算 n 模 7 并检查固定的查找表。 

这将问题转化为 O(1) 预处理后每个查询的恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力 DP 高达 n | 每次测试 O(n) 或总共 O(max n) | O(n) | 太慢了|
 | 周期 DP + 模 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们首先计算 n 值较小时的获胜和失败状态，直到出现明显的循环。 我们定义一个布尔数组，其中 false 表示失败，true 表示获胜。

我们将 dp[0] 初始化为失败，因为没有糖果的玩家无法移动。 从那里，只要这些索引有效，我们就使用 i − 1、i − 3 和 i − 4 允许的转换迭代计算 dp[i]。 

当我们扩展表格时，我们寻找 dp 值模式中的重复。 一旦我们看到序列稳定为长度为 7 的重复周期，我们就停止预处理并记录周期。 

此时，我们构建一个大小为 7 的查找表，对 n mod 7 是否对应于获胜位置或失败位置进行编码。 

对于每个查询 n，我们计算 r = n mod 7。如果 dp_pattern[r] 指示获胜状态，我们输出“Orange”，否则我们输出“ice”。 

### 为什么它有效

 该游戏是一个具有有限移动集的有限减法游戏。 每个位置的状态仅取决于恒定数量的先前状态，因此 dp 值的序列在有限二进制字母表上形成线性递归。 这样的序列最终必定会变成周期性的。 一旦达到周期区域，dp[n] 的值仅取决于 n 以周期长度为模，因此减少 n 以发现的周期为模可以保留所有大值的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# Precompute DP until we see a cycle
moves = [1, 3, 4]
N = 50  # enough to observe periodicity

dp = [False] * (N + 1)
dp[0] = False

for i in range(1, N + 1):
    win = False
    for m in moves:
        if i - m >= 0 and not dp[i - m]:
            win = True
    dp[i] = win

# Observed cycle for this problem: period 7 starting early
# We extract pattern for mod 7
pattern = [dp[i] for i in range(7)]

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    if pattern[n % 7]:
        out.append("Orange")
    else:
        out.append("ice")

print("\n".join(out))
```该代码首先构建一个足以揭示游戏结构的小型 DP 表。 转换检查是否有任何有效的移动会导致失败状态； 如果是这样，那么当前的状态就是胜利。 

计算出足够的值后，我们直接读取 dp[i] modulo 7 的行为。恒定大小的模式数组存储每个残差类别是否获胜。 

然后，每个查询都简化为单个模运算和表查找。 这避免了对 n 的任何依赖。 

一个微妙的点是正确处理 dp[0]。 它必须被初始化为失败，因为当前玩家没有有效的动作。 所有其他状态都取决于此基本情况。 

## 工作示例

 考虑 n = 5、n = 6 和 n = 7。我们跟踪 DP 决策。 

### 跟踪示例

 | 我| i-1 | i-3 | i-4 | dp[i] 决定 |
 | ---| ---| ---| ---| ---|
 | 0 | - | - | - | 失去|
 | 1 | 0 | - | - | 获胜（取 1）|
 | 2 | 1 | - | - | 失去|
 | 3 | 2 | 0 | - | 获胜（取3）|
 | 4 | 3 | 1 | 0 | 赢 |
 | 5 | 4 | 2 | 1 | 赢 |

 当n = 2时，每一步都会导致对手获胜，因此对手正在失败。 对于 n = 4，立即取 4 获胜，使其获胜。 

现在考虑更大的值来显示周期性：

 | n | n 模 7 | 结果 |
 | ---| ---| ---|
 | 6 | 6 | 失去|
 | 7 | 0 | 失去|
 | 8 | 1 | 获胜|

 这证实了行为稳定为基于残留类别的重复模式。 

这些痕迹表明，游戏并不仅仅由奇偶校验来控制。 3 步和 4 步的可用性创造了获胜的跳跃，破坏了简单的模式，但仍然产生有界循环。

def run(inp: str) -> str:

 ## 边缘情况

 对于n = 0，算法直接分配ice，因为dp_pattern[0]为假。 这与不存在任何移动的事实相匹配，因此第一个玩家立即失败。 

对于 n = 2，残差类别导致失败状态。 追踪 DP 可以确认两种可能的结果（取 1）都为对手留下了获胜位置，因此正确的输出是ice。 

对于 n = 7，我们计算 r = 0。该模式将其标记为失败，因此ice 获胜。 尽管 7 允许多次移动，但每个选项都会导致一种可以最佳应对的状态。 

当 n = 8 时，r = 1，即获胜。 该算法输出橙色，这与第一个玩家可以通过进入失败的剩余类别来强制获胜的事实一致。
