 ## 解决方案
 ## 问题理解

 在原来的交互问题中，有一个隐藏的长度数组$2n+1$。 每个值来自$1$到$n$恰好出现两次，但有一个特殊值出现三次。 任务是识别包含该特殊值的三个位置。 

对于 hacks 中使用的非交互式版本，整个数组作为输入给出。 我们不再需要通过查询来重建任何东西。 我们只是接收数组，并且必须输出频率为 3 的值出现的三个索引。 

数组的长度是$2n+1$，以及所有的总和$n$测试文件的值最多为$2 \cdot 10^4$。 这意味着数组元素的总数大约只有$4 \cdot 10^4$。 任何线性或近线性解决方案都很容易足够快。 

主要的陷阱是记住我们需要的是位置，而不是价值本身。 例如，在```
1 2 1 3 2 1 3
```重复三次的值为`1`，但所需的答案是位置```
1 3 6
```打印值而不是索引的解决方案是不正确的。 

另一个容易犯的错误是在内部使用从零开始的索引，而在打印时忘记转换回从一开始的索引。 为了```
1 1 2 2 1
```正确答案是```
1 2 5
```不是```
0 1 4
```## 方法

 最直接的暴力想法是检查每个不同的值并计算它出现的次数。 由于值被限制在范围内$1 \ldots n$，我们可以重复扫描数组并找到频率等于 3 的值。 识别该值后，我们再次扫描并收集其位置。 

如果有$n$可能的值和数组长度是$2n+1$，该方法执行$O(n(2n+1)) = O(n^2)$工作。 

输入的结构提供了一个更简单的选项。 除了一个值恰好出现三次之外，每个值都恰好出现两次。 一张频率表立刻就揭示了特殊的价值。 

在读取数组时，我们计算每个数字的出现次数。 建立频数表后，恰好有一个值的频数为三。 第二次遍历数组收集其三个位置。 

这将运行时间减少到线性复杂度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 概念上太慢|
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 阅读$n$。 
2.读取长度的数组$2n+1$。 
3. 为数组中的所有值构建频率表。 
4. 找到频率等于 3 的唯一值。 
5. 再次扫描数组并记录该值出现的每个位置。 
6. 使用基于 1 的索引输出三个记录位置。 

### 为什么它有效

 该问题保证一个值恰好出现三次，而其他每个值恰好出现两次。 频率表唯一标识该值。 一旦知道了该值，包含该值的每个位置都属于答案。 由于它恰好出现了 3 次，因此收集到的位置正是所需的三个索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        target = None
        for x, cnt in freq.items():
            if cnt == 3:
                target = x
                break

        ans = []
        for i, x in enumerate(a, start=1):
            if x == target:
                ans.append(i)

        print(*ans)

solve()
```第一个循环构建频率表。 因为该语句保证恰好有一个值出现 3 次，所以搜索`cnt == 3`总是成功的。 

找到特殊值后，第二遍收集其位置。 致电给`enumerate(..., start=1)`很重要，因为该问题使用基于一的索引。 遗忘`start=1`是这里最常见的差一错误。 

该算法从不对数组执行嵌套扫描。 每个元素都会被处理固定次数。 

## 工作示例

 ### 示例 1

 输入：```
n = 2
a = [1, 1, 1, 2, 2]
```| 步骤| 行动| 结果 |
 | --- | --- | --- |
 | 1 | 计算频率 | 频率[1] = 3，频率[2] = 2 |
 | 2 | 查找频率 3 | 目标= 1 |
 | 3 | 收集职位| [1,2,3]|

 输出：```
1 2 3
```此示例显示了最简单的可能配置。 可以立即从频率表中找到特殊值。 

### 示例 2

 输入：```
n = 3
a = [2, 1, 3, 2, 1, 3, 2]
```| 步骤| 行动| 结果 |
 | --- | --- | --- |
 | 1 | 计算频率 | 频率[1] = 2，频率[2] = 3，频率[3] = 2 |
 | 2 | 查找频率 3 | 目标 = 2 |
 | 3 | 收集职位| [1,4,7]|

 输出：```
1 4 7
```此示例演示了这三个出现可以分布在数组中的任何位置。 频率表仍然可以立即识别它们。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n)$| 对长度数组进行两次线性遍历$2n+1$|
 | 空间|$O(n)$| 频率表最多存储$n$独特的价值观|

 总输入大小很小，$\sum n \le 2 \cdot 10^4$。 线性解决方案在限制范围内运行舒适。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        t = int(input())
        out = []

        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))

            freq = {}
            for x in a:
                freq[x] = freq.get(x, 0) + 1

            target = next(x for x, c in freq.items() if c == 3)

            pos = []
            for i, x in enumerate(a, start=1):
                if x == target:
                    pos.append(str(i))

            out.append(" ".join(pos))

        return "\n".join(out)

    return solve()

# minimum size

# triple value at scattered positions
assert run("1\n3\n2 1 3 2 1 3 2\n") == "1 4 7"

# triple value at end
assert run("1\n3\n1 2 1 2 3 3 3\n") == "5 6 7"

# multiple test cases
assert run(
    "2\n"
    "2\n1 2 1 2 1\n"
    "3\n2 2 3 1 3 1 2\n"
) == "1 3 5\n1 2 7"

 ## 边缘情况

 考虑最小的有效实例：```
n = 2
a = [1, 1, 1, 2, 2]
```频数表变为`{1: 3, 2: 2}`。 该算法选择`1`作为特殊值和输出位置`1 2 3`。 逻辑中没有任何内容依赖于更大的数组。 

考虑三个事件相距很远的情况：```
n = 3
a = [2, 1, 3, 2, 1, 3, 2]
```职位是`1`,`4`， 和`7`。 由于算法首先识别值，然后才收集位置，因此邻接性是无关紧要的。 

考虑三元组值为最大值的情况：```
n = 4
a = [1, 2, 1, 2, 3, 4, 3, 4, 4]
```频数表为```
1 -> 2
2 -> 2
3 -> 2
4 -> 3
```算法正确选择`4`和输出`6 8 9`。 实际数值并不重要，重要的是它的频率。
