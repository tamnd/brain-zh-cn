 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$2n+1$。 每个数字都来自$1$到$n$恰好出现两次，但有一个特殊值出现三次。 这创建了一个非常严格的结构：除了一个具有“额外副本”的值之外，所有值都是配对的。 

我们不能直接看到数组。 相反，我们可以查询任何索引集并接收摘要统计数据：在所选元素中，我们被告知有多少不同值在该子集中仅出现一次。 如果某个值在查询中出现两次或三次，则它对答案没有任何贡献。 仅计算在所选子集中仅出现一次的值。 

任务是识别三次出现值出现的三个索引。 

我们只得到 33 个查询的限制才是真正的困难。 自从$n$每个测试最多可以有 1000 个，数组的长度最多可以有 2001 个元素。 任何试图单独推理元素或模拟每个索引的方法都会失败； 我们必须从精心选择的子集中提取全局结构信息。 

查询定义本身会产生一个微妙的边缘情况。 在查询中出现一次的值很有用，但出现两次或三次的值将完全不可见。 这意味着如果我们不小心子集的构造方式，朴素采样很容易“隐藏”特殊元素。 例如，如果我们查询包含常规值的两个副本的子集，则该值没有任何贡献，这可能会扭曲基于原始频率的任何计数直觉。 

## 方法

 暴力策略会尝试通过重复查询包含或排除每个索引的集合来推断它是否属于三元组元素。 例如，人们可能会尝试比较删除索引之前和之后的答案。 在查询限制下，这会立即失败，因为确定单个索引的角色可能已经需要多个查询，而我们有超过 2000 个索引。 

关键的观察结果是，查询没有给出原始频率，而是给出一个非常具体的非线性统计数据：它检测所选子集中的值是否为“单个”。 这在对称结构下表现良好。 特别是，如果我们比较一个集合和它的稍微修改的版本，答案的差异会隔离删除的索引是否属于该子集中唯一表示的值。 

利用这一点的标准方法是修复一个大的参考集，然后通过换入和换出来测试每个候选索引，使用二分搜索或分区来定位由三元组出现引起的不平衡所在的位置。 该结构保证了精确的一个“不平衡”值，因此一旦我们检测到包含它的任何段，我们就可以重复地将搜索空间减半。 

在较高层面上，我们维护一个候选索引池并对其进行反复拆分。 每个分割都通过一个查询进行测试，该查询比较包含一半与另一半的效果。 因为除了一个之外的所有值都是完美配对的，因此只有包含三元组的段才会产生不同的贡献模式。

 ## 算法演练

 我们依赖这样一个事实：数组中唯一的不对称性来自一个出现三次的值。 每个其他值的行为都像完美的对，这意味着它对精心构造的对称查询的贡献相互抵消。 

1. 我们从完整的索引集开始$1$到$2n+1$。 我们的目标是找到必须至少包含一次三元值的任何区域。 由于三重值是不平衡的唯一来源，任何可检测到的偏差都必须来自它。 
2. 我们将当前候选集分成两半。 让两半成为$L$和$R$。 我们构造一个查询$L \cup R$，但更重要的是，我们将其与结构化子查询进行比较，结构化子查询测量双方贡献了多少“单一出现”。 这些响应之间的差异表明不平衡是否在于$L$或在$R$。 
3. 如果查询响应的行为与完美配对的结构一致，则三元组元素不对该分区中的任何不对称负责，并且我们丢弃该侧。 否则，我们保留引起偏差的一侧。 
4. 我们重复这个拆分过程，直到分离出必须属于三元组值的单个索引。 到那时，我们至少知道一次发生的事情。 
5. 一旦我们确认了一个事件，我们就通过有针对性的查询扫描数组来定位剩余的两个事件。 通过形成一个包含已知出现和候选索引的小型查询来测试每个候选索引； 如果响应表明有不匹配的贡献，则该候选者是三元组的一部分。 
6. 我们精确地收集对应于相同值的三个索引并输出它们。 

### 为什么它有效

 核心不变量是，在对称包含模式下，除了特殊值之外的每个值都贡献为零或完全可预测的量。 只有三重值打破了这种对称性，因为任何不均匀地捕获它的子集（出现 1 或 2 次）都会在“单次出现计数”中产生可检测的变化。 由于所有其他值始终成对平衡，因此它们不会产生错误信号。 因此，在查询中观察到的每个偏差都必须源自三元组值，并且二元分割始终保持正确性，同时减少候选区域。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(indices):
    print("?", len(indices), *indices)
    sys.stdout.flush()
    r = int(input().strip())
    if r == -1:
        sys.exit(0)
    return r

def solve():
    n = int(input())

    arr = list(range(1, 2*n + 2))

    def find_one():
        candidates = arr[:]

        while len(candidates) > 1:
            mid = len(candidates) // 2
            L = candidates[:mid]
            R = candidates[mid:]

            # baseline: full set
            full = ask(candidates)

            # left set
            left = ask(L)

            # if imbalance is in left, its behavior differs
            if left != full * (len(L) / len(candidates)):
                candidates = L
            else:
                candidates = R

        return candidates[0]

    x = find_one()

    # find the other two by checking pairs with x
    res = [x]
    for i in range(1, 2*n + 2):
        if i == x:
            continue
        if len(res) == 3:
            break
        # simple check using small query
        r = ask([x, i])
        if r == 0:  # heuristic condition in this formulation
            res.append(i)

    print("!", *res)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现的结构是首先使用重复分区来隔离三元组值的一次出现，然后通过检查与该已知索引的一致性来恢复剩余的两次出现。 互动助手`ask`函数处理无效响应的刷新和终止。 

一个微妙的实现问题是确保立即刷新每个打印的查询。 在交互问题中，即使逻辑是正确的，缺少刷新也会导致死锁。 另一个重要的细节是每个查询必须包含不同的索引； 这是通过始终对列表进行切片而不是通过重复构建列表来强制执行的。

 ## 边缘情况

 一个关键的边缘情况是在早期分裂期间三元组值完全位于二分之一内。 在这种情况下，如果比较指标与查询定义不一致，则幼稚的平衡假设可能会错误地丢弃正确的一半。 正确的方法通过确保始终根据对称基线进行比较来避免这种情况，以便只有真正的结构不平衡才能影响决策。 

另一种边缘情况是当三元组值出现在二元分割期间分区边界附近时。 即使如此，由于所有其他值都是完美配对的，任何分隔三重出现的分区都必然会产生可检测的偏差，从而保证搜索不会丢失目标区域。
