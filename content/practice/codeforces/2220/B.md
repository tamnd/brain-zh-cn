 ## 解决方案
 ## 问题理解

 我们被分配了从 1 到 n 的一排位置，每个位置都有一名志愿者看守。 Hector 从位置 0 开始，希望通过向左、向右移动一步或在每一秒结束时保持静止来到达位置 n+1。 

每个志愿者都有一个确定性演变的计时器。 在时间 x 处，位置 i 的值为 (a_i + x) mod m。 当该值为 0 时，位于位置 i 的志愿者仅主动观察赫克托。如果赫克托在计时器为 0 时在一秒开始时站在位置 i，他会立即被抓住。 

关键的困难在于赫克托可以左右移动，这意味着他不必被迫按顺序通过位置。 他可以推迟进度，等待安全时刻，甚至撤退到较早的位置以避免糟糕的时机。 

任务是确定是否存在任何移动序列，允许赫克托从位置 0 移动到位置 n+1，而不会在守卫计时器为零时处于守卫位置。 

约束很大：测试用例的总 n 最多为 2⋅10^5，m 最多为 10^9。 这立即排除了任何随时间的模拟或对（位置、时间）的状态空间搜索，因为时间可以任意大，并且运动选择会创建一个巨大的图表。 

状态 (i, t mod m) 上的朴素 BFS 是不可能的，因为时间维度是无界的，并且 m 太大而无法扩展。 

向左移动的能力会产生微妙的边缘情况。 许多不正确的贪婪方法假设赫克托必须按顺序传递位置，但向左移动可以用来使时间与位置约束“不同步”。 

例如，如果某个位置 i 变得不安全，而赫克托通常会以直线路径到达该位置，那么天真的解决方案可能会说“被阻止”，但在其他地方等待或振荡可以改变到达时间并避免糟糕的时刻。 

另一个棘手的情况是当 a_i 已经为零时。 那么位置 i 在时间 0 处是危险的。如果 Hector 无法延迟到达该位置直到与 i 的到达奇偶性一致的安全时间，则答案变为“否”，即使后面的位置是安全的。 

## 方法

 蛮力策略会尝试将赫克托的运动模拟为状态（位置、时间）的最短路径问题。 从每个状态，我们分为三个动作。 每次移动都会使时间增加 1，然后我们检查落在某个位置是否安全。 

这在原则上是正确的，因为它探索了所有可能的策略。 然而，时间是无限的，即使我们人为地限制时间，状态的数量也会变成 O(n·T)，其中 T 需要足够大才能表示有意义的循环。 由于 m 最大可达 10^9，因此任何合并时间模 m 的尝试仍然会产生 O(nm) 结构，这是不可能的。 

关键的观察是赫克托的移动仅取决于他在每个部分停留的时间以及是否可以在某个安全时间访问每个位置的奇偶性。 向左移动的能力意味着我们不会局限于单一的增长路径； 相反，每个位置 i 仅对 Hector 是否可以在时间 t 到达该位置施加约束，使得 (a_i + t) mod m ≠ 0。 

重写约束，如果 t ≠ -a_i (mod m)，位置 i 在时间 t 是安全的。 这意味着每个位置都禁止单个无限算术级数的时间。 

关键的见解是，Hector 总是可以选择通过在 i−1 和 i 之间跳跃来“延迟”到达位置 i，从而有效地将到达时间延迟任意数量的额外秒数。 因此，对于每个位置，重要的是是否存在任何时间 t ≥ base_time(i)，使得 t 避免在该位置处以 m 为模的禁止残差类，同时仍然允许前进。

这将问题简化为贪婪的可行性检查：我们模拟从左到右的移动，跟踪赫克托可以到达每个位置的最早时间。 如果我们遇到这样的情况：最早可能的到达时间被强制以一种不能进一步延迟的方式进入单个禁止同余类模 m 中，我们就会失败。 

该结构进一步简化：每个位置 i 恰好阻塞一次模 m。 由于 Hector 在进入 i 之前可以在位置 i−1 处任意等待，因此他可以选择任何到达时间 t ≥ current_time + 1。因此，只有当每个 t ≥ current_time + 1 满足 t ≠ bad_i (mod m) 时，位置 i 才是不可能的，而这永远不会成立。 因此，唯一真正的失败发生在 current_time + 1 已经恰好落在禁止时间上且 m = 1，但 m ≥ 2 时，因此不会发生直接阻塞。 

因此，真正的约束成为全局的：只有当两个连续的约束迫使跨位置的时序对齐发生不可避免的冲突时，冲突才有意义。 这导致了已知的简化：我们跟踪线性前向传递是否可能，检查我们是否总是可以在每个步骤选择非禁止的到达时间，这总是可能的，除非起始对齐强制整个链上不可能的同步。 

这归结为检查是否存在任何 i ，使得直线到达 i 违反约束，并且没有通过左移动的绕行可以足够地移动奇偶校验以同时避免所有约束。 在实践中，问题简化为检查直接路径在每个位置是否已经安全。 

因此，我们最终验证 Hector 是否可以简单地每秒向右移动，可能通过初始等待实现全局偏移，这会均匀地移动所有到达时间。 

我们仅通过检查是否存在移位 t0 来隐式测试所有可能的全局移位，使得对于每个 i，(t0 + i) mod m ≠ -a_i mod m。 这成为一个经典的禁止残基对齐问题，但由于每个 i 只有一个禁止残基，因此存在有效的移位，除非矛盾以结构化方式重叠，从而阻止任何一致的分配。 

这可以简化为检查同余的可行性，这最终简化为验证不存在强制冲突模式，并且这可以在 O(n) 内完成。

 ## 算法演练

 我们将问题重新解释为选择全局启动延迟 t0，之后 Hector 严格向右移动而无需重新访问位置。 在此视图下，Hector 在时间 t0 + i 到达位置 i。 

对于每个位置 i，我们计算禁止到达条件：

 t0 + i == -a_i (mod m)，重新排列为 t0 == (-a_i - i) mod m。 

这意味着每个位置都严格禁止 t0 模 m 的一个值。 如果存在避免所有这些禁止残基的 t0，Hector 就会成功。 

我们按如下方式进行。 

1. 计算每个位置 i 的禁止残基 r_i = (-a_i - i) mod m。 这是导致赫克托被困在位置 i 的确切开始延迟。 
2. 将所有 r_i 值插入到集合中。 
3.如果集合大小严格小于m，则至少存在一个有效的t0，因此Hector可以逃脱。 
4. 如果设定的大小等于m，那么每一个可能的t0都被至少一个位置禁止，因此逃逸是不可能的。 
5. 相应地输出YES 或NO。 

其有效的关键原因在于，Hector 的每个策略都可以转化为具有单个初始等待时间 t0 并随后连续向右移动的策略。 任何绕行或在中间等待只会影响 t0，而不影响约束结构，因为运动在时间上是一致的，并且每个位置对到达时间施加单个模块限制。 

### 为什么它有效

每个位置恰好为全局偏移 t0 贡献一个禁止残基类别。 赫克托的路径总是可以标准化为具有一些初始延迟的单调向右移动路径。 这种标准化保留了安全约束，因为只有到达时间很重要，而不是中间振荡。 因此，问题简化为检查禁止残数的并集是否覆盖整个模空间。 如果是这样，则启动延迟不起作用； 否则，至少一次延迟可以避免所有冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        seen = set()
        for i, ai in enumerate(a, start=1):
            r = (-ai - i) % m
            seen.add(r)
        
        # If we already cover all residues, impossible
        print("NO" if len(seen) == m else "YES")

if __name__ == "__main__":
    solve()
```该解决方案将整个运动问题简化为计算每个位置的模块化约束。 该循环计算每个守卫的禁止启动延迟，编码赫克托如果沿着直线增加的路径与该守卫发生碰撞的确切时刻。 

该集合收集所有不同的禁止偏移量。 如果所有模 m 的留数都被覆盖，则每个可能的启动延迟都会导致至少一次碰撞，从而使逃逸变得不可能。 否则，存在安全偏移。 

唯一微妙的实现细节是公式中小心的 1 索引，因为位置 i 对应于开始移动后的时间 i。 

## 工作示例

 ### 示例 1

 考虑：

 n = 3，m = 5

 a = [1, 0, 2]

 我们计算禁用残基。 

| 我| a_i | r_i = (-a_i - i) mod 5 | r_i = (-a_i - i) mod 5 | r_i = (-a_i - i) mod 5
 | --- | --- | --- |
 | 1 | 1 | (-2) 模 5 = 3 |
 | 2 | 0 | (-2) 模 5 = 3 |
 | 3 | 2 | (-5) 模 5 = 0 |

 禁止残基集合为{0, 3}。 由于并非所有模 5 的残基都被覆盖，因此存在有效的启动延迟。 答案是肯定的。 

这表明多个位置可以禁止相同的偏移，这就是为什么我们只关心覆盖范围，而不关心多重性。 

### 示例 2

 n = 2，m = 3

 a = [0, 0]

 | 我| a_i | r_i |
 | --- | --- | --- |
 | 1 | 0 | 2 |
 | 2 | 0 | 1 |

 禁止集是{1, 2}。 残基 0 仍然可用，因此选择 t0 = 0 可以避免这两种冲突。 赫克托逃脱。 

这证实了即使两个位置在时间 0 都是危险的，简单的转变也可以解决冲突。

 ## 边缘情况

 一种微妙的情况是许多位置产生相同的禁用残基。 例如，如果所有 a_i 都相等，则所有 r_i 都会折叠成一个小集合。 该算法可以正确处理这个问题，因为它只跟踪不同的残基，并且重复不会影响可行性。 

另一种情况是当 m 相对于 n 较小时。 如果 n ≥ m 并且残基不同，则该集合可以快速饱和并正确触发 NO。 这是通过设置大小检查自然处理的。 

最后一种情况是 m 较大且 n 较小时。 那么饱和是不可能的，答案总是肯定的，这符合直觉，即在选择全局延迟时有足够的自由度。
