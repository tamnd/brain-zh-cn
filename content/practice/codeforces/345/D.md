 ## 解决方案
 ## 问题理解

 我们有一个人际网络，其中每一对人要么双向认识，要么根本不认识。 这种关系被编码为大小的邻接矩阵$n \times n$，其中一个`1`意味着两个人将互相转发消息，并且`0`意味着他们不会。 

消息从人员 1 开始。每当有人第一次收到该消息时，他们会立即将其转发给与其连接的每个人。 这个过程就像洪水淹没了友谊图一样继续下去。 重要的规则是每个人仅在第一次收到消息时转发消息一次。 

我们是人$n$，我们不会进一步转发该消息。 任务是确定我们总共会收到多少次消息，这意味着有多少不同的人可以通过这个传播过程联系到我们。 

这从根本上来说是一个图可达性问题。 该图是无向的，最多有 50 个节点，因此即使相对昂贵的图遍历方法也是安全的。 输出是可以到达节点的不同节点的数量$n$通过从节点 1 开始的路径，不包括节点$n$本身。 

关键的微妙之处在于我们没有模拟多个独立的链或计数路径。 如果三个不同的路由最终带来来自同一个人的消息，则仍然只算作来自该人的一次接收。 重要的是可达性，而不是多样性。 

一个幼稚的错误是将这个过程解释为计算从 1 到 1 的路径$n$。 例如，在 4 个节点的全连接图中，有从 1 到 4 的多条不同路径，但每个发送者只收到一份副本，因此答案是 3，而不是更大的路径数。 

另一个错误是模拟传播而不标记访问过的节点。 如果不跟踪访问过的节点，该过程将重复地重新处理同一个人，导致概念意义上的过度计数甚至无限循环。 

限制条件$n \le 50$意味着两者$O(n^2)$邻接操作和完整的 DFS 或 BFS 都很简单。 甚至$O(n^3)$像弗洛伊德-沃歇尔这样的方法会起作用，但没有必要。 

## 方法

 暴力解释是完全按照描述来模拟消息传播。 我们从第一个人开始，重复扫描所有的人，只要存在连接就向前推送消息。 每次有新人收到消息时，我们都会再次扫描他们的联系。 这可以作为重复的松弛过程来实现，直到没有新节点被激活为止。 

这是正确的，因为它直接模仿传播过程，但其效率低下来自于为每个新激活的节点重复重新扫描整个邻接矩阵。 在最坏的情况下，每次激活都会触发$O(n)$扫描一下，有$O(n)$激活，给予$O(n^3)$直接实现中的行为，或者如果实施效率低下，情况会更糟。 

关键的观察是转发过程实际上是一个图的遍历。 一旦节点收到消息，它就会变得活跃一次，我们会探索它的所有邻居。 这正是深度优先搜索或广度优先搜索的作用。 路由的多重性并不重要，因为我们只关心一个节点是否可达，而不关心它有多少种方式可达。 

因此，我们将问题简化为在无向图中查找从节点 1 可到达的所有节点。 一旦我们计算出可达集，我们只需计算其中有多少节点也可以到达节点$n$，相当于从节点运行第二次可达性计算$n$，或等效地检查连接属性。 

一个更简单、更直接的解释是对称性：由于图是无向的，如果一个节点可以到达$n$在传播中，则$n$位于同一个连通分量中。 次数$n$接收到的消息正好是1的连通分量中能够到达的节点数$n$，这减少了对从 1 可到达且有路径到达的节点进行计数$n$。 在无向图中，这相当于包含 1 的连通分量与导致 1 的连通结构的交集中的节点$n$，简化为基于 BFS/DFS 的分类。 

在实践中，干净的解决方案是：计算从 1 可达的所有节点，并且对于每个这样的节点，检查它是否可以到达$n$。 自从$n \le 50$，每个候选者的 BFS/DFS 仍然很快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 |$O(n^3)$|$O(n^2)$| 太慢/不必要|
 | DFS/BFS 可达性 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 根据输入矩阵构建邻接列表，以便我们可以快速迭代每个节点的邻居。 这避免了重复扫描字符串。 
2. 从节点 1 开始运行 DFS 或 BFS，查找从该节点可到达的所有节点。 将其存储在布尔数组中`reach_from_1`。 这准确地捕获了接收该消息的人。 
3.对于每个节点$i$这样`reach_from_1[i]`为 true，则从以下位置开始运行第二个 DFS 或 BFS$i$检查节点是否$n$可以从以下位置到达$i$。 如果是，则节点$i$为答案贡献 1。 
4. 对所有此类节点求和$i$。 此计数代表有多少个不同的发件人最终可以生成一条消息到达您手中。 
5. 输出最终的和。 

我们执行第二次可达性检查的原因是从 1 可达性本身是不够的。 节点可能与 1 位于同一连接组件中，但仍然无法到达$n$如果我们考虑“首次转发”的方向性，则通过有效的传播路径。 第二次遍历确保我们只计算位于有效传播链上的节点，从而导致$n$。 

### 为什么它有效

 传播过程定义了由无向边引起但受首次激活约束的有向影响关系。 每个节点只转发消息一次，这意味着消息沿着连接组件内以 1 为根的生成树传播。 仅当节点被激活（从 1 可达）并且其激活可以影响时，该节点才会对我们的计数做出贡献$n$。 第二个可达性条件准确地捕获了该影响条件。 由于图很小且无向，可达性定义良好且稳定，因此基于 DFS 的表征与动态过程完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]

    adj = [[] for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if g[i][j] == '1':
                adj[i].append(j)

    # DFS from 0 (person 1)
    stack = [0]
    vis1 = [False] * n
    vis1[0] = True

    while stack:
        u = stack.pop()
        for v in adj[u]:
            if not vis1[v]:
                vis1[v] = True
                stack.append(v)

    def can_reach(start):
        stack = [start]
        vis = [False] * n
        vis[start] = True
        while stack:
            u = stack.pop()
            for v in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        return vis[n - 1]

    ans = 0
    for i in range(n):
        if vis1[i]:
            if can_reach(i):
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```邻接表构造将矩阵转换为支持直接邻居迭代的结构。 这很重要，因为即使约束很小，重复扫描 DFS 内的字符串也会增加不必要的开销。 

第一个 DFS 标记所有从人员 1 接收到消息的节点。第二个辅助函数测试给定节点是否仍然可以将影响传播到节点$n$，从该起点模拟相同的转发规则。 

最后的循环精确计算满足这两个条件的节点，确保我们只计算可以到达我们的有效消息源。

 ## 边缘情况

 一种边缘情况是当人$n$是完全孤立的。 在这种情况下，即使可以从人员 1 联系到许多人，但他们都不能满足第二个可达性条件，因此答案为零。 该算法自然地处理这个问题，因为`can_reach`对于节点来说，函数总是会失败$n$，防止任何增量。 

另一种边缘情况是图完全连接时。 那么从 1 可到达的每个节点也能够到达$n$。 第一个 DFS 标记所有节点，第二个 DFS 成功，产生$n-1$，这符合每个其他人都向您发送副本的想法。 

第三种边缘情况是当 1 和$n$已断开连接。 第一个 DFS 仍可能到达节点的子集，但这些节点都不会通过第二次可达性测试，因此结果再次为零。
