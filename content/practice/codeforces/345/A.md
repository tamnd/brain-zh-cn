 ## 解决方案
 ## 问题理解

 我们得到一个字符串，代表某个时间段内的 13 号星期五。 字符串中的每个字符都可以`"0"`对于正常的一天来说，`"1"`度过特别糟糕的一天，或者`"?"`用户无法回忆一天。 除此之外，我们还得到了一个概率`p`这代表了未知一天的可能性`"?"`实际上是糟糕的一天`"1"`。 

任务是计算所有星期五平均糟糕程度的预期值。 换句话说，我们想要代表每天糟糕情况的随机变量的平均值。 已知的日子贡献其确定性价值（`0`或者`1`），未知的日子贡献他们的期望值，这只是`p`因为每个`"?"`其行为类似于伯努利随机变量。 

该字符串的长度最多为 50 个字符，这非常小，因此我们在这里不受算法复杂性的限制。 我们只需要对字符串进行线性传递来计算预期总和，然后除以字符串的长度即可得到平均值。 

当字符串仅包含`"?"`人物。 例如，如果输入是`"???"`和`p = 0.6`，一个简单的实现可能会尝试生成所有可能的组合`0`和`1`对于未知数，但期望值可以直接计算为`3 * 0.6 / 3 = 0.6`。 另一个边缘情况是当`p`正是`0`或者`1`。 如果`p = 1`， 每一个`"?"`被视为`1`; 如果`p = 0`， 每一个`"?"`被视为`0`。 粗心的舍入实现也可能会产生`0.99999`而不是`1.00000`如果不小心的话。 

## 方法

 蛮力方法是枚举所有可能的替代品`"?"`并计算每个组合的平均不良度。 为了`n`未知数，有`2^n`组合，每个组合都需要一个`O(n)`平均计算。 这给出了`O(n * 2^n)`时间复杂度。 即使是为了`n = 50`，这变得天文数字般大（`~10^15`操作），这显然是不可行的。 

关键的见解是期望的线性。 独立随机变量之和的期望值是它们期望值的总和，无论变量之间的依赖性如何。 每个已知的日子都有其确定性`0`或者`1`，以及每个未知的日子`"?"`贡献`p`。 这将问题简化为通过字符串的单个线性传递来对这些值求和并除以长度。 不需要组合枚举，解是精确的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 2^n) | O(n * 2^n) | O(n) | 太慢了 |
 | 期望值/线性扫描| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取字符串`s`和概率`p`来自输入。`s`包含星期五和的历史`p`是未知的一天不好的可能性。 
2. 初始化变量`total_badness`到`0`。 这将累积所有日子的预期不良情况。 
3. 迭代每个字符`c`在`s`。 如果`c`是`"1"`， 添加`1`到`total_badness`因为这注定是糟糕的一天。 如果`c`是`"0"`， 添加`0`因为今天是美好的一天。 如果`c`是`"?"`， 添加`p`因为伯努利随机变量的期望值有概率`p`正是`p`。 
4. 循环结束后，通过除法计算预期平均值`total_badness`的长度`s`。 
5. 打印结果，精确到小数点后五位。 使用标准舍入规则以避免最后一位数字出现差一错误。 

为什么有效：期望的线性保证了将各个天的期望值相加可以得到准确的期望总和。 除以天数可以保留平均值的期望值。 治疗精度不受影响`"?"`作为`p`因为期望不需要生成实际的随机结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
p = float(input().strip())

total_badness = 0.0

for c in s:
    if c == '1':
        total_badness += 1.0
    elif c == '?':
        total_badness += p
    # '0' adds 0, so we do nothing

expected_average = total_badness / len(s)
print(f"{expected_average:.5f}")
```该解决方案使用读取输入`sys.stdin.readline`用于快速 I/O。 循环根据每个字符的含义来处理它。 我们将预期的坏度累积在浮点变量中，最后除以长度。 格式化为`:.5f`确保精确到小数点后五位，并根据标准规则进行四舍五入。 空箱子`"0"`是隐式处理的，因为加零不会影响总和。
