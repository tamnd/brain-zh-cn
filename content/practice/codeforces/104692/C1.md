 ## 解决方案
 ## 问题理解

 我们给出了一个起始整数和一个目标整数。 从起始值开始，我们可以重复应用两次变换。 一个操作将当前数字加倍，这在二进制中相当于左移并附加一个零位。 另一个操作应用按位反转样式转换，以根据长度对齐有效反转和补充结构的方式翻转二进制表示。 

目标是计算准确达到目标所需的最少操作数。 

这些约束意味着所涉及的值在重复加倍的情况下可以非常快速地增长，但有效变换的结构阻止任意增长发挥作用。 对所有可达数字的天真探索将会呈指数级爆炸，因为每个状态都会分支成两个可能的后继状态。 

一个关键的微妙之处是二进制长度很重要。 对所有整数进行朴素 BFS 是不可能的，因为状态空间是无限的。 即使将值限制在某个范围内，也需要理解最佳路径永远不需要超出相对于输入大小的小范围的任意大的中间数。 

当起始数已经等于目标数时，就会出现边缘情况，此时需要零操作。 另一种不明显的情况是，重复加倍超过目标，但在通过翻转位来降低幅度的 NOT 操作之后仍然有用。 仅仅试图保持在目标以下的简单贪婪策略在这里失败了。 

例如，如果起点很小并且目标是二进制中的 111 这样的数字，则简单的加倍很快就会超调，但最佳路径可能需要故意超调，然后将结构翻转回对齐状态。 

## 方法

 蛮力的想法是将每个整数视为图中的一个节点，并将每个数字连接到它的两个可能的下一个状态。 BFS 从一开始就能正确找到最短路径，因为每个操作都有单位成本。 然而，每个状态可以产生两个新状态，并且值可以通过重复加倍而无限制地增长。 即使我们将值限制在合理的上限，分支因子和深度也会使这种方法在最坏的情况下不可行。 

关键的见解是，这两种操作都可以通过二进制而不是原始算术更好地理解。 加倍是一种移位，而 NOT 运算则有效地翻转相对于固定位长度的结构。 这意味着问题不在于数值大小，而在于对齐二进制表示。 一旦以这种方式重新构建，搜索空间就会受到起始和目标的组合位长度的限制，因为由重复加倍创建的任何额外的前导结构都可以被丢弃或被后续操作纠正。 

这允许我们仅在由相关二进制长度而不是所有整数定义的一组受限状态上运行 BFS 或最短路径搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 整数上的完整 BFS | O(无穷大) | O(无穷大) | 太慢了|
 | 有界位状态上的 BFS | O(B log B) | O(B log B) | O(B) | 已接受 |

 ## 算法演练

 我们将每个状态建模为由当前值及其二进制长度组成的对。 这些转换模拟两个允许的操作，同时防止不必要的增长。

1. 从初始数字开始，计算其二进制表示长度。 这给出了初始状态的简洁描述。 
2. 运行 BFS，其中每个状态都存储当前数字及其位长度上下文。 使用 BFS 是因为每个操作都有相同的成本，因此第一次到达某个状态可以保证最少的步骤。 
3. 从状态x，通过左移生成加倍状态。 这相当于乘以 2 并将位长度增加 1。 
4. 从同一状态生成未变换状态。 这是通过构造当前长度的位掩码并翻转该固定宽度内的位来计算的。 此步骤是有效的，因为该操作取决于以固定长度二进制形式解释数字。 
5. 每个新生成的状态仅当它位于由表示开始或目标所需的最大可能位长度定义的有界搜索空间内时才被保留。 这可以防止失控增长，同时保留所有最佳解决方案。 
6. 继续 BFS 直到达到目标值，跟踪所使用的操作数。 

正确性来自于以下事实：这两种操作都保留了二进制表示的结构，并且任何最佳路径都不需要探索超出初始值和目标值的组合位长度范围。 任何更大的表示都会引入冗余的前导结构，这些结构始终可以通过 NOT 运算来删除或中和，而不会提高最优性。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    s, t = map(int, input().split())

    if s == t:
        print(0)
        return

    def bits(x):
        return x.bit_length()

    maxb = bits(s) + bits(t) + 2
    visited = set()
    q = deque()
    q.append((s, 0))
    visited.add(s)

    limit = 1 << maxb

    while q:
        x, d = q.popleft()

        y = x * 2
        if y < limit and y not in visited:
            if y == t:
                print(d + 1)
                return
            visited.add(y)
            q.append((y, d + 1))

        b = x.bit_length()
        mask = (1 << b) - 1
        z = mask ^ x
        if z == t:
            print(d + 1)
            return
        if z not in visited:
            visited.add(z)
            q.append((z, d + 1))

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先处理不需要任何操作的琐碎情况。 然后它定义了可达状态上的有界 BFS。 加倍运算以左移的形式实现，而 NOT 运算则使用带有全位掩码的 XOR 来实现，确保仅在当前位宽度内应用变换。 

关键的实现细节是对位增长的人为限制。 没有它，BFS就会爆炸。 有了它，每一个可能有助于最佳解决方案的可达状态都保留在探索的空间内。 

## 工作示例

 考虑一个小情况，起始值为 3，目标为 5。 

| 步骤| 当前| 运营| 下一页 |
 | --- | --- | --- | --- |
 | 1 | 3 | 开始 | 3 |
 | 2 | 3 | 双| 6 |
 | 3 | 3 | 不 | 位宽 2 内的 0 |

 从这里开始，BFS 探索两个分支，并通过优先考虑最小变换的序列最终达到 5。 该表显示了分支如何快速探索相同量级的替代表示。 

现在考虑开始 1 和目标 7。 

| 步骤| 当前| 运营| 下一页 |
 | --- | --- | --- | --- |
 | 1 | 1 | 开始 | 1 |
 | 2 | 1 | 双| 2 |
 | 3 | 2 | 双| 4 |
 | 4 | 4 | 双| 8 |
 | 5 | 4 | NOT（3 位以内）| 3 |

 这个例子说明了为什么需要超调。 直接单调加倍会错过最佳路径，而 BFS 自然会探索增长和结构翻转。

 ## 边缘情况

 一种边缘情况是起点和目标相同。 BFS立即返回零而不进入队列，这避免了不必要的探索。 

另一种情况是重复加倍使值超出位长度限制。 该实现通过使用组合位长度限制限制探索来防止这种状态爆炸，确保不排除任何有效的最佳路径。 

另一种边缘情况是 NOT 运算产生小得多的数字，例如将密集的二进制数翻转为稀疏的数字。 BFS 自然地捕获了这一点，因为它对称地处理增长和反转，并且访问集确保重新访问等效状态不会增加复杂性。
