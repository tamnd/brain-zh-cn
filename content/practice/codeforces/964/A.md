 ## 解决方案
 ## 问题理解

 我们正在研究整数的书写方法$n$作为正整数的非递增序列。 换句话说，我们打破了$n$当我们向右移动时，这些部分永远不会增加，并且所有部分都必须是正数。 这与以排序形式编写的标准整数分区相同。 

从每个这样的分区中，我们提取一个数字：有多少个初始元素等于第一个元素的计数。 如果分区以某个值开头$x$，然后我们数一下有多少次$x$在序列下降到下面之前从头开始连续出现$x$。 该计数称为重量。 

对于固定的$n$，存在许多不同的分区，每个分区产生一个权重。 任务不是计算分区数，而是计算所有分区中可实现的不同权重数$n$。 

输入只是一个整数$n$，输出是该权重可以取的不同值的数量。 

约束条件$n \le 10^9$立即排除任何分区枚举，甚至排除所有总和的部分 DP。 的分区数$n$超多项式增长，因此任何迭代分区的方法都是不可行的。 即使迭代所有可能的第一部分和它们下面的结构也必须避免，除非它折叠成对数或平方根结构。 

一个微妙的边缘情况是分区极度倾斜。 例如，$[n]$给出权重 1，同时$[1,1,\dots,1]$赋予重量$n$。 另一个不太明显的情况是中间权重可能不连续； 并非 1 到 1 之间的每个整数$n$对于小规模来说是必然可以实现的$n$，任务是计算不同的可实现值，而不是假设一个完整的区间。 

## 方法

 一个蛮力的想法是生成$n$，计算每个的权重，并收集不同的结果。 这在概念上很简单：递归地选择不超过前一部分的下一部分，直到总和达到$n$。 对于每个完整分区，计算有多少初始元素与第一个值匹配。 

这会立即失败，因为分区数$n$是指数的$\sqrt{n}$。 即使是为了$n = 50$，这已经产生了数百万个分区，并且对于$10^9$这是完全不可能的。 

关键的观察结果是权重仅取决于第一个相同值的块。 假设分区以 value 开始$x$, 重复$k$次。 然后我们有：$$n = kx + (\text{remainder})$$其中余数是剩余总和最多使用部分的划分$x$，并且它必须严格小于$x$（否则第一个块会更长）。 

关键的结构见解是对于固定权重$k$，当第一个块之后的所有内容都尽可能小时，就会出现最小可能的总和。 也就是说，我们取：$$[x, x, \dots, x, x-1, x-2, \dots, 1]$$和$k$的副本$x$。 这产生了该权重结构的最小总和。 

这将问题转化为可行性条件：对于每个可能的权重$k$，我们可以问是否存在一些$x$这样具有第一个块大小的分区$k$是可能的。 存在条件崩溃为涉及三角数的不等式，因为第一个块之后的“最紧”延续是最大递减序列。 

这导致了单调关系：$k$增加，所需的最低限度$n$大致长得像$k^2$。 因此，最大可行$k$的顺序是$\sqrt{n}$，并且所有有效权重形成从 1 到该最大值的连续范围。 

所以问题就简化为寻找最大的$k$这样：$$k(k+1)/2 \le n$$答案就是最大$k$。

 ## 算法演练

 我们将结构界限转化为直接计算。 

1. 观察重量$k$至少需要$k$第一个值的副本，之后剩余的序列必须严格减少或保持低于该值。 这迫使“形状成本”最小化，并与$k$。 
2. 表达给定重量的最小可能配置$k$。 当第一个值尽可能小同时仍允许$k$副本，有效地将序列打包成楼梯结构。 
3. 计算重量所需的最小总和$k$，这是三角数$k(k+1)/2$。 这对应于在第一个块下堆叠递减约束的行。 
4. 找到最大的$k$使得这个最小金额不超过$n$。 这是最大可行重量。 
5.输出这个$k$，因为所有较小的重量都可以通过放松结构来实现。 

### 为什么它有效

 关键的不变量是任何具有第一块权重的分区$k$必须至少包含$k$结构中的正整数，一旦第一个值固定，就会强制执行严格递减的余数。 这施加了相当于楼梯隔断高度的下限$k$。 三角形数捕获了此类楼梯的最小总和，以及任何额外的松弛$n$只能增加灵活性，绝不会降低可行性。 因此可行性仅取决于是否$n$超过了这个最小阈值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

k = 0
# find maximum k such that k*(k+1)//2 <= n
# can do O(sqrt(n)) loop or binary search; sqrt is enough for 1e9
while (k + 1) * (k + 2) // 2 <= n:
    k += 1

print(k)
```实现直接寻找不超过的最大三角数$n$。 循环增加$k$在维持病情的同时$k(k+1)/2 \le n$。 使用$(k+1)(k+2)/2$避免增量后重新计算并保持条件干净。 

除了标准整数解析之外不需要边缘处理，因为$n \ge 1$至少保证$k = 1$被认为是正确的。

 ## 边缘情况

 对于$n = 1$，唯一的分区是$[1]$，所以唯一的权重是 1。算法开始于$k = 0$, 检查$1 \le 1$，增加到 1，并在下一次三角检查失败后立即停止。 

为了$n = 6$，我们正好击中$3 \cdot 4 / 2 = 6$。 该算法正确地允许$k = 3$，表明精确的三角形数被包含为有效最大值，而不是被排除在外。 

为了$n = 7$，最低要求为$k = 4$是10，所以被拒绝。 算法正确地保持了$k = 3$，确认可行性仅在三角阈值处变化，而不是在它们之间变化。
