 ## 解决方案
 ## 问题理解

 我们得到一个索引从 1 到 n 的值数组。 从这个数组中，我们定义了一个完整的加权图，其中每对不同的索引 u 和 v 通过一条边连接。 该边的权重由两件事决定：较大的端点索引和出现在 u 和 v 之间（含）之间的最小数组值。 具体来说，对于 u < v，边权重取决于 v 和子数组 a[u..v] 中的最小值。 

一旦构建了该图，我们就考虑顶点之间的简单路径。 对于任何对 (u, v)，d(u, v) 被定义为从 u 开始到 v 结束的简单路径的最大可能总权重，其中路径长度是沿该路径的边权重之和。 任务是找到所有不同顶点对上 d(u, v) 的最大值。 

约束允许 n 最大为 10^6，因此任何二次甚至每对 n log n 的方法都是立即不可能的。 即使在所有时间间隔内进行一次 O(n^2) 扫描也已经太慢了。 这强烈表明该解决方案必须避免明确考虑所有对或所有路径，而是依赖于最佳路径行为的结构属性。 

一个微妙的困难是边缘权重不是局部的：它们取决于范围最小值。 这通常会导致错误，即人们假设图的行为就像具有独立边的简单加权完整图，而实际上权重跨区间紧密耦合。 另一个常见的陷阱是假设两个节点之间的最佳路径只是直接边，但这是无法保证的，因为多边路径可能会通过利用嵌套段上的最小值行为来积累更大的总权重。 

例如，在较小的情况下，直接边缘可能是适中的，因为间隔包含会减小最小值的小值，而精心选择的将间隔分解为更小的单调片段的路径可以避免该小值并增加总权重。 这种非本地交互正是必须处理的。 

## 方法

 直接的蛮力方法将为每对 (u, v) 计算段 a[u..v] 上的最小值，然后尝试探索完整图中 u 和 v 之间的所有简单路径。 即使将注意力限制在长度达到 n 的简单路径上，这也会变得具有爆炸性。 完整图中可能的简单路径的数量呈超指数增长，甚至评估单个路径的长度也是线性的。 在 n 甚至达到几十之前，这种方法显然是不可行的。 

关键的观察结果是，尽管图是完整的，但边缘结构完全由线段最小值控制。 这创建了一个自然的层次结构：只要值 a[k] 是某个区间中的最小值，它就会充当瓶颈，限制该区间内的边的行为方式。 任何位于所有值至少为 a[k] 的区域内的路径的边权重都会受到 a[k] 的统一影响。 

这建议将问题重新集中在每个索引 k 周围，作为分段的潜在“活跃最小值”。 对于固定的 k，我们可以查看最大连续段，其中 a[k] 是最小值，这意味着该段中的所有内容都至少具有 a[k] 值。 在这样的段内，包含 k 的任何子区间的最小值始终恰好是 a[k]。 这消除了边权重的模糊性，并将其转变为端点的确定性函数。 

一旦线段固定，累积路径权重的最佳方法是在线段上以递增的索引顺序遍历顶点，因为每条边都会贡献与其右端点相关的可预测数量。 这将路径优化转换为区间总和上的纯算术最大化。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有路径进行暴力破解 | 指数| O(n) | 太慢了|
 | 分段最小分解| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个索引 k，计算最左边出现严格小于 a[k] 的值的位置，以及最右边具有相同属性的位置。 这给出了最大间隔 [L[k], R[k]]，其中 a[k] 是最小值。 这样做的原因是，任何超出这些边界的扩展都会引入一个更小的元素，从而使 k 作为控制最小值无效。 
2.固定中心索引k并仅考虑段[L[k],R[k]]。 在该段内，每个包含 k 的子区间都具有恰好 a[k] 的最小值，因为该段中不存在更小的值。 
3. 在 [L[k], R[k]] 内，考虑构建一条以递增索引顺序访问顶点的简单路径。 这个选择很重要，因为每条边 (i, i+1) 的权重由 (i+1) 乘以 a[k] 确定，因为 [i, i+1] 上的最小值是 a[k]。 
4. 计算本次遍历的总贡献，即 a[k] 乘以用作右端点的索引之和：

 (L[k]+1) + (L[k]+2) + ... + R[k]。 该和可以使用算术级数的前缀和来表示。 
5. 评估每个 k 的该值并取最大值。 

核心思想是每个 k 定义一个“受控区域”，它控制所有区间最小值，并且在该区域内，最优路径变得确定性并且仅依赖于区间算术。 

### 为什么它有效

 有效段内的每个边权重仅取决于其右端点乘以段的最小值。 一旦我们限制到 a[k] 最小的最大区域，所有边的行为都与因子 a[k] 一致。 任何试图离开该区域的路径都会立即遇到一个较小的值，这将严格降低控制最小值并破坏最优结构。 因此，任何对的最佳可实现路径完全包含在这些最大最小段之一中，并且在这样的段内，升序遍历最大化累积的端点贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # 1-indexed padding for convenience
    a = [0] + a

    L = [0] * (n + 1)
    R = [0] * (n + 1)

    stack = []

    # previous strictly smaller
    for i in range(1, n + 1):
        while stack and a[stack[-1]] >= a[i]:
            stack.pop()
        L[i] = stack[-1] + 1 if stack else 1
        stack.append(i)

    stack.clear()

    # next strictly smaller
    for i in range(n, 0, -1):
        while stack and a[stack[-1]] > a[i]:
            stack.pop()
        R[i] = stack[-1] - 1 if stack else n
        stack.append(i)

    # prefix sums of indices
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + i

    def range_sum(l, r):
        return pref[r] - pref[l - 1]

    ans = 0

    for i in range(1, n + 1):
        l, r = L[i], R[i]
        if l <= i <= r:
            cost = a[i] * (range_sum(l + 1, r))
            ans = max(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先使用单调堆栈计算两侧最近的较小元素。 左边界是通过弹出不严格小于的元素来计算的，确保结果区间内的所有内容至少为 a[i]。 右边界是对称计算的。 

索引上的前缀和允许对任何段上的算术和进行恒定时间评估。 这是必要的，因为最终表达式取决于连续索引的求和。 

最后，对于每个位置，我们将其贡献计算为其值与其有效段中所有可能的右端点之和的乘积。 我们跟踪所有头寸的最大值。

 考虑一个小数组：

n = 5

 | 我| 一个[我] | L[i] | R[i] |
 | ---| ---| ---| ---|
 | 1 | 3 | 1 | 2 |

 | 3 | 4 | 3 | 4 |
 | 4 | 2 | 3 | 5 |
 | 5 | 5 | 5 | 5 |

 现在计算贡献：

 | 我| 段[左，右] | 总和 (L+1..R) | 价值|
 | ---| ---| ---| ---|
 | 1 | [1,2]| 2 | 3 * 2 = 6 | 3 * 2 = 6
 | 2 | [1,5]| 14 | 14 1 * 14 = 14 | 1 * 14 = 14 |

 | 4 | [3,5]| 9 | 2 * 9 = 18 | 2 * 9 = 18 |

 最大值为 18，在 i = 4 时实现。 

这显示了中等值的中间元素如何由于有效段宽而占据主导地位，即使它不是全局最大值。

 ## 边缘情况

 对于 n = 1，该图只有一个顶点且没有边，因此不存在路径，答案为 0。该算法会处理此问题，因为两个边界都会折叠到同一索引，从而产生零长度和。 

对于所有值都相等的数组，每个索引都将完整段 [1, n] 作为其有效范围。 该算法正确地为每个指标分配相同的贡献结构，最大值来自最大的算术和乘以该常数值。 

对于严格递减或递增的数组，每个元素的有效范围非常小，这可以确保不会形成不正确的大段。 单调堆栈边界正确地将段缩小到直接相邻的段，从而防止高估。
