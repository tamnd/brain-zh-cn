 ## 解决方案
 ## 问题理解

 我们正在模拟对一组标记为 1 到 N 的动态玩家的选择过程。最初，所有玩家都可用。 两位领导者轮流轮流。 在第一、第三、第五回合等，第一个领导者选择位置 a_k，这意味着他们会选择剩下的第 a_k 个最小的玩家。 在第二、第四、第六回合等，第二个领导者使用 b_k 执行相同的操作。 

关键的困难在于，每次选秀后，剩余的集合都会缩小，因此所有未来的指数都与更新后的未使用球员的有序列表相关。 任务是准确重建每一步所采用的玩家编号，并按照轮流顺序输出两位领导者的选择顺序。 

N 可以大到 4,000,000 的限制迫使我们远离任何重复扫描或从数组中删除的简单结构。 每次删除后线性移动或搜索剩余池的任何方法都会降级为二次行为并立即失败。 

使用 Python 列表实现“删除第 k 个元素”时会出现一个幼稚的错误。 即使索引是 O(1)，删除也是 O(N)，执行 N 次就会导致 O(N^2)。 对于 N = 4e6 这是完全不可行的。 

另一个微妙的失败来自于误解 a_k 和 b_k 是原始数组中的绝对索引。 他们不是。 它们始终引用当前的实时设置，因此任何预先计算位置或将序列视为静态的解决方案都会产生错误的选择。 

## 方法

 暴力模拟维护剩余玩家的有序列表。 在每一轮中，它都会找到第 k 个剩余元素并将其删除。 

这是正确的，因为它准确地反映了该过程，但每次删除都需要移动删除位置之后的所有元素。 在最坏的情况下，每次删除都是 O(N)，总工作量为 O(N^2)，这远远超出了限制。 

关键的观察是我们只需要有效地支持两个操作：找到第 k 个存活元素并删除它。 这是一个经典的订单统计问题。 我们没有密集地存储完整列表，而是维护一个结构来跟踪哪些位置仍然有效，并可以快速计算前缀中有多少个位置是活动的。 

布尔数组上的芬威克树（二叉索引树）或线段树工作得很好。 每个位置从 1（活着）开始。 第 k 个剩余元素是通过前缀和的二进制提升找到的：我们搜索使得前缀和 ≥ k 的最小索引。 一旦找到，我们将其标记为已删除并更新结构。 

这将每次转动减少到 O(log N)，这对于 N 高达 4e6 来说足够快了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力删除列表 | O(N^2) | O(N^2) | O(N) | 太慢了|
 | Fenwick / BIT 订单统计 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们按顺序处理轮次，在 [1, N] 范围内维护一棵 Fenwick 树，其中每个索引最初的值为 1。 

1. 初始化一棵大小为 N 的 Fenwick 树，其中每个位置都标记为 1，这意味着所有玩家最初都是可用的。 
2. 维护两个列表，每个领导者一个，按照选择的顺序记录所选的球员。 
3. 对于从 1 到 N/2 的 k，每次迭代执行两个操作。 
4. 第一个领导者的举动：读取a_k，然后使用芬威克树上的前缀和二分搜索找到第a_k个活着的玩家。 这给出了实际的玩家标签。 将其附加到第一个领导者的答案列表中，然后通过将该位置设置为 0 来更新树。 
5. 第二领导者的举动：读取b_k，在更新的结构上重复相同的过程，将结果附加到第二领导者的列表中，并将其删除。

每个步骤都取决于 Fenwick 树中的前缀和表示在给定索引之前剩余的玩家数量，因此我们可以重建第 k 个存活元素，而无需显式维护列表。 

### 为什么它有效

 在任何时候，芬威克树都会对玩家编码一个二进制指示器数组，其中 1 表示“仍然可用”。 到索引 i 的前缀总和表明 1 到 i 中存在多少个可用玩家。 找到剩余的第 k 个玩家相当于找到该累积计数达到 k 的最小索引。 由于每次删除都会正确更新结构，因此树代表当前活动集的不变量在整个过程中保持不变。 因此，每个查询都反映了剩余玩家的真实动态排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def build(self):
        for i in range(1, self.n + 1):
            self.bit[i] += 1
            j = i + (i & -i)
            if j <= self.n:
                self.bit[j] += self.bit[i]

    def update(self, i, delta):
        n = self.n
        while i <= n:
            self.bit[i] += delta
            i += i & -i

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    fw = Fenwick(n)
    fw.build()

    res1 = []
    res2 = []

    for i in range(n // 2):
        x = fw.kth(a[i])
        res1.append(x)
        fw.update(x, -1)

        y = fw.kth(b[i])
        res2.append(y)
        fw.update(y, -1)

    print(*res1)
    print(*res2)

if __name__ == "__main__":
    solve()
```芬威克树已初始化，以便每个玩家都在场。 构建步骤在线性时间内构建前缀结构，避免了初始化时的重复点更新。 

这`kth`函数对 Fenwick 树执行二元提升搜索。 它通过测试二次幂跳转来增量构造第 k 个存活元素的索引，同时确保前缀和不超过 k。 这避免了扫描整个阵列。 

每次我们识别出玩家索引时，我们都会立即使用以下方法将其删除`update(x, -1)`，确保后续查询反映更新后的集合。

 ## 边缘情况

 一个关键的边缘情况是当两个领导者重复请求第一个剩余元素时。 从 N = 4、a = [1,1]、b = [1,1] 开始，该过程始终删除当前最小的存活玩家。 

一步一步，活着从[1,2,3,4]开始。 第一个选择 1，第二个选择 2，然后剩余的 [3,4]，第一个选择 3，第二个选择 4。Fenwick 结构自然地处理这个问题，因为每次删除后，前缀和都会正确压缩，并且第 k 个查询总是相对于更新的集合而不是原始索引进行解析。
