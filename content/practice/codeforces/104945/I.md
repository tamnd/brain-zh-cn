 ## 解决方案
 ## 问题理解

 每个玩家掷多个独立的骰子，最终得分为其骰子所显示的所有面值的总和。 每个骰子都是公平的，但不同的骰子可能有不同的面数，因此每个骰子在不同的范围内贡献一个统一的整数。 

我们没有被要求以简单的方式计算两个总和的完整概率分布。 相反，我们必须比较两个概率：Alice 的总和严格大于 Bob 的概率，以及 Bob 的总和严格大于 Alice 的概率。 平局对两者都没有贡献。 

输入给出两个骰子大小的多重集。 Alice 的骰子由一个数组描述，其中每个值都是一个骰子的面数，Bob 的骰子也有类似的描述。 任务是确定哪个玩家更有可能拥有更大的总和。 

这些约束立即排除了任何直接概率卷积。 每个玩家最多可以拥有 100,000 个骰子，每个骰子最多可以有 10^9 面。 即使精确地计算单个分布也是不可能的，甚至对总和进行动态规划也是不可行的，因为总和的范围是巨大且不均匀的。 

一个更微妙的问题是，分布不仅很大，而且是均匀变量的不规则混合。 简单的方法可能会假设正态近似或均值比较，但这将是不正确的，因为排序概率取决于完整的分布形状，而不仅仅是期望。 

一个关键的边缘情况是当一个玩家的最低保证金额严格高于另一个玩家时。 例如，如果 Alice 有 8 个 4 面骰子，Bob 有 1 个 6 面骰子，则 Alice 的最小总和为 8，而 Bob 的最大总和为 6，从而使答案具有确定性。 任何忽略极端界限的概率推理在这里都会失败。 

当两个玩家拥有相同的多组时，就会出现另一种失败情况。 概率必须完全相等，因为两个分布是相同的，但如果实现不对称，简单的排序或不对称处理仍然可能产生有偏差的结果。 

## 方法

 暴力方法会尝试通过迭代卷积骰子分布来计算每个玩家总和的完整分布。 对于单个骰子，其侧面的分布是均匀的，并且在处理 k 个骰子之后，我们将维护所有可能总和的概率数组。 然而，即使添加几个骰子，可能的和的数量也会迅速增长，并且在添加许多骰子之后，骰子的数量会呈指数级增长。 对于多达 100,000 个骰子，这无论是在时间上还是在内存上都是完全不可行的。 

关键的见解是停止思考精确分布，而是对骰子结果的成对比较进行推理。 当比较两个和时，每个结果对应于从爱丽丝一侧的每个骰子中选择一张脸以及从鲍勃一侧的每个骰子中选择一张脸。 比较仅取决于爱丽丝的骰子和鲍勃的骰子之间所有可能的成对相互作用的多重集。 

这导致了一种简化：我们可以考虑每个个体的骰子如何为主导地位做出贡献，而不是跟踪总和。 面数越多的骰子更有可能产生更高的值，但效果与面数并不是线性的。 然而，关键的结构观察是，结果仅取决于骰子大小的相对顺序，而不取决于它们的绝对大小。 

如果我们对两个数组进行排序，我们可以将这个过程解释为比较单调结构中的贡献：较大边的骰子系统地向上移动概率质量。 这种比较简化为每个玩家在不同规模下拥有多少“强”骰子之间的平衡。 捕捉这一点的正确方法是处理两个排序列表并模拟质量如何跨阈值变化，从而有效地跟踪累积优势。

这将问题转化为对排序数组的线性扫描，其中我们保持运行平衡，反映爱丽丝或鲍勃在每个尺度上是否具有更多的“有效强度”。

 ## 算法演练

 1. 按非递减顺序对 Alice 的骰子大小进行排序，并对 Bob 进行同样的操作。 排序是必要的，因为在比较骰子的贡献时，只有骰子大小的相对顺序很重要。 
2. 初始化两个指针，一个用于 Alice 的最大剩余骰子，一个用于 Bob 的最大剩余骰子，并将余额变量设置为零。 余额将代表目前哪一方拥有更强的剩余高端贡献。 
3. 当任一玩家仍有剩余骰子时进行迭代。 在每一步中，比较当前剩余的最大骰子。 
4. 如果 Alice 当前最大的骰子比 Bob 的大，我们将其视为 Alice 在该规模上获得优势，并减少 Alice 的指针。 我们向上更新余额。 
5. 如果Bob当前的最大骰子更大，Bob获得相应的优势，我们减少Bob的指针，向下更新余额。 
6. 如果它们相等，则两者一起消耗，因为它们以相同的比例对称地贡献，并且我们移动两个指针而不改变平衡。 
7. 处理完所有骰子后，最终余额的符号决定了答案：正值表示 Alice 具有总体优势，负值表示 Bob 具有总体优势，零表示优势结构中完美平局。 

### 为什么它有效

 总和之间的比较仅取决于在结果的乘积空间的配对比较中爱丽丝的骰子超过鲍勃的骰子的频率。 排序按强度排列骰子，以便顶层的每个决策都反映最有影响力的剩余比较。 该过程保持单调不变量：在每一步，所有未处理的骰子都不比已处理的骰子强，因此解析最大的可用骰子可以正确确定概率质量移动的方向。 这确保了以后的配对不会推翻累积的优势标志。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))
    
    A.sort()
    B.sort()
    
    i = m - 1
    j = n - 1
    
    balance = 0
    
    while i >= 0 or j >= 0:
        if j < 0 or (i >= 0 and A[i] > B[j]):
            balance += 1
            i -= 1
        elif i < 0 or (j >= 0 and B[j] > A[i]):
            balance -= 1
            j -= 1
        else:
            i -= 1
            j -= 1
    
    if balance > 0:
        print("ALICE")
    elif balance < 0:
        print("BOB")
    else:
        print("TIED")

if __name__ == "__main__":
    solve()
```该实现依赖于对两个数组进行排序，以便始终首先比较最大的骰子。 两指针扫描确保我们在转向较小的骰子之前始终处理最重要的剩余贡献。 平衡变量对所有比较中累积的净优势进行编码，最终的符号决定获胜者。 

平等分支很重要，因为相同的骰子必须完全相互抵消。 如果没有这种情况，当多重集重叠时，算法将错误地偏向一侧。

 ## 边缘情况

 当两个玩家都有相同的骰子多重集合时，算法在双指针扫描期间重复匹配相同的元素。 每场比赛都会触发相等分支，在不改变平衡的情况下删除两个元素。 最终结果为零，完全按照要求生成 TIED。 

当一个玩家的最大骰子严格强于对手所有骰子时，循环总是首先从较强的一方消耗。 每次迭代都会在一个方向上一致地增加平衡，直到所有骰子都用完，从而匹配确定性优势。 

当数组在分布上仅略有不同但在排序上没有差异时，排序可确保比较始终将最强的与最强的剩余对齐。 这可以防止弱元素和强元素的意外配对，从而扭曲预期的主导结构。
