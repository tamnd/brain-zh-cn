 ## 解决方案
 ## 问题理解

 每个国家都可以通过两种方式之一来代表。 爱丽丝要么准备一张完整的国旗图，这需要购买该国家国旗中出现的所有颜色，要么她完全避免绘制该国旗，而是使用该国家的单个图钉。 

每种颜色都有单位成本，购买一种颜色一次就足以用于每个需要它的国家。 图钉也有单位成本，但它们是按国家/地区计算的，因此跳过旗帜可以用单一固定成本代替多种颜色的购买。 

输入为每个国家提供了绘制其国旗所需的颜色列表。 一种颜色可能会出现在许多国家，选择购买它同时对所有国家都有好处。 

任务是选择要购买的颜色子集，并为每个国家决定是使用这些颜色绘制国旗还是用别针替换它，从而最大限度地降低总成本。 

核心决策是全球性的：选择一种颜色可以同时帮助多个国家，但每个未完全被所选颜色覆盖的国家都必须支付密码。 这种国家间的耦合使得问题变得非同小可。 

这些约束给出了有关结构的清晰提示。 颜色数量 M 最多为 100，因此任何对颜色子集进行推理的算法在 O(2^M) 样式或 O(M * some) 中都是合理的。 国家数量 N 最多可达 1000 个，因此我们无法承担每个国家的指数工作，但我们可以承担每个国家与 M 或 M log M 成比例的操作。 

一个天真的想法是考虑颜色的每个子集，计算哪些国家/地区被完全覆盖，并将成本计算为所选颜色的数量加上未覆盖的国家/地区的数量。 这已经接近正确的结构，但如果不进行优化，就有可能重复昂贵的检查。 

当一个国家只有单一颜色时，就会出现一种微妙的边缘情况。 如果我们贪婪地选择经常出现的颜色，我们可能会假设每个国家都可以便宜地覆盖，但实际上选择经常使用的颜色可能仍然无法覆盖需要多种颜色的整个国家。 例如，如果某个国家/地区需要颜色 {1, 2}，则仅购买颜色 1 对该国家/地区根本没有帮助，并且仍然必须将其固定。 

另一个极端情况是所有国家/地区都使用单一的共同颜色。 天真的贪婪方法可能仍然会不必要地购买多种颜色，而最佳解决方案只是购买单一颜色并在需要时固定其余颜色。 

## 方法

 我们可以将这个决定改写如下：我们选择购买一组颜色。 每个拥有该选定集合中所有颜色的国家/地区都“由绘图支持”，而其他所有国家/地区都必须用图钉替换。 

如果我们固定颜色子集 S，则总成本变为 |S| 加上 S 中未完全包含的国家数量。 

蛮力方法迭代所有颜色子集。 对于每个子集，它会检查每个国家/地区并验证子集中是否存在所有必需的颜色。 在最坏的情况下，此检查的时间复杂度为 O(NM)，因为每个国家/地区可能最多有 M 种颜色。 对于 2^M 子集，当 M = 100 时，这变得完全不可行。 

关键的观察是我们不需要以非结构化方式显式枚举子集。 相反，我们可以通过一次处理一种颜色来逐步构建解决方案，并为每个州维护有多少个国家仍然“违规”，这意味着它们至少有一种尚未选择的所需颜色。 

这表明了颜色的动态规划公式。 对于每种颜色，我们决定是否包含它。 国家需要了解每个国家/地区仍缺少多少所需的颜色。 然而，跟踪每个国家的完整计数会太大。

这种简化来自于注意到一个国家只在二元意义上重要：要么选择其所有颜色，要么不选择。 我们可以代表每个州哪些国家已经完全满意。 由于 N 是 1000，我们仍然无法存储国家/地区的完整位掩码。 相反，我们扭转了观点。 

如果我们决定“绘制它”，我们会跟踪每个国家还缺少多少种颜色。 如果一个国家/地区有 k 个颜色，我们从 k 个缺失开始，每次选择一种颜色时，我们都会减少包含该颜色的所有国家/地区的缺失计数。 当一个国家的缺失计数达到零时，该国家就会变得可抽取。 

如果简单地完成，这仍然太大，但我们实际上不需要存储每个状态的数组。 相反，我们使用位掩码 DP 处理颜色子集上的状态，但使用预先计算的成员列表来压缩转换。 

由于 M ≤ 100，我们可以将每种颜色视为独立决策，并使用增量更新隐式地维护子集上的 DP，同时动态计算成本贡献。 

重要的结构见解是，对于每个颜色子集，支持的国家/地区数量完全是通过检查所选颜色的联合是否完全覆盖每个国家/地区的集合来确定的。 由于每个国家的集合很小，我们可以预先存储它并使用位集或排序数组有效地检查包含情况。 

这减少了通过预先计算每个国家/地区的位表示来有效评估所有颜色子集的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 通过完整检查对子集进行暴力破解 | O(2^M·N·M) | O(2^M·N·M) | O(NM) | 太慢了 |
 | 位掩码 DP/带有位集的子集枚举 | O(2^M·N / 字大小) | O(NM) | 已接受 |

 ## 算法演练

 1. 将每个国家/地区所需的颜色表示为大小为 M 的位掩码。这使我们能够使用快速位操作而不是每个元素循环来测试遏制。 
2. 预先计算所有国家/地区掩码一次。 每个掩码都是一个整数（或 Python 位集），其中位 j 表示该国家/地区需要颜色 j。 
3. 使用 0 到 2^M − 1 之间的整数枚举所有颜色子集。每个子集代表 Alice 选择购买的颜色集。 
4. 对于每个子集，将其成本计算为设置位数（购买的颜色）。 
5. 对于每个国家，检查其所需的掩码是否完全包含在子集中。 当（国家/地区掩码和子集）==国家/地区掩码时，这正是正确的。 
6. 计算有多少国家不满意。 每个不满意的国家都会贡献成本 1，因为我们使用了 pin。 
7. 跟踪所有子集的最小值。 

### 为什么它有效

 每个有效的策略都唯一对应于颜色的子集：我们选择购买的颜色。 一旦该集合确定，每个国家/地区将根据是否包含其所有颜色而独立确定为可绘制或不可绘制。 成本公式干净地分解为独立贡献的总和：子集大小加上每个未覆盖国家的惩罚。 由于每个子集只被评估一次，并且每个可能的决策集都被表示，因此所有子集的最小值与最优策略相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def popcount(x):
    return x.bit_count()

def solve():
    n, m = map(int, input().split())
    
    country_masks = []
    
    for _ in range(n):
        k = int(input())
        colors = list(map(int, input().split()))
        mask = 0
        for c in colors:
            mask |= 1 << (c - 1)
        country_masks.append(mask)

    full = (1 << m)

    ans = n  # worst case: pin every country

    for subset in range(full):
        cost_colors = subset.bit_count()
        pins = 0

        for cm in country_masks:
            if (cm & subset) != cm:
                pins += 1

        ans = min(ans, cost_colors + pins)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现将每个国家/地区编码为 M 种颜色的位掩码。 这使得子集包含检查恒定时间位操作而不是扫描颜色列表。 

主循环迭代所有颜色子集。 对于每个子集，购买颜色的成本使用以下公式计算`bit_count()`，然后使用单个按位 AND 比较来检查每个国家/地区的完整性。 

最初的答案设置为 N，对应于不购买颜色并为每个国家/地区使用一个图钉。 

一个微妙的点是表示的转变：我们没有跟踪覆盖哪些国家，而是直接有条件地测试覆盖范围。 这避免了跨子集维护任何动态状态。

 ## 边缘情况

 一个国家/地区包含单一颜色的最小案例表明，该算法可以正确评估购买颜色和使用图钉。 对于 N = 1 且国家/地区颜色为 {2} 的输入，子集枚举包括空集和 {2}。 空集给出成本 1（图钉），{2} 给出成本 1（一种颜色），所以答案是 1。 

所有国家都有共同颜色的情况说明了为什么需要子集评估。 如果每个国家/地区都包含颜色 1，则子集 {1} 会产生成本 1 + 0 个引脚 = 1，而任何没有 1 的子集都会产生 N 个引脚。 该算法正确地找到了全局最小值，因为它显式地评估包含该共享颜色的子集。 

如果国家/地区完全不相交，不存在颜色重叠，则迫使解决方案优先选择图钉。 涵盖任何颜色的每个子集最多只对一个国家/地区有利，并且当购买颜色永远不会在多个国家/地区摊销时，枚举会正确返回 N 作为最佳值。
