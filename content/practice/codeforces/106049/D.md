 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，其中一些位置已经固定为`0`或者`1`，其余位置免费。 任务是替换每个空闲位置，以便最终的字符串在以下意义上变得“爆炸”：每当我们重复应用删除一对相等的相邻字符并用相反值的单个字符替换它的规则时，该过程最终会崩溃为单个字符。 

同样，如果可以使用该操作将字符串完全缩减，直到只剩下一个字符，则该字符串是有效的。 我们拥有的自由是为未知的位置选择值； 我们必须确定是否存在任何补全可以使字符串以这种方式简化。 

关键的隐藏结构是该操作仅依赖于局部邻接，但其效果通过类似奇偶校验的行为在全局范围内传播。 任何直接模拟缩减的天真的尝试都会重复合并和重新扩展子串，并且对于长度达到大约束，这将变得二次或更糟。 

当字符串只有固定字符而没有灵活性时，就会出现微妙的失败情况。 例如，如果字符串已经是`01`，不适用任何操作，并且不可简化，即使它可能看起来“几乎有效”。 另一种情况是像这样的字符串`000`，立即减少，但是`001`不，即使两者都包含大部分零。 减少取决于结构，而不是数量。 

重要的约束含义是我们无法模拟操作。 即使使用堆栈进行贪婪的减少也可能会退化为重复的级联更改。 预期的解决方案必须使用可以在线性时间内检查的小不变量来表征可归约性。 

## 方法

 蛮力视图很简单：尝试所有分配`?`字符，并为每个完整的字符串模拟缩减过程。 每个归约步骤都会扫描相邻的相等对并应用变换，直到无法再进行移动为止。 在最坏的情况下，每次模拟都是二次的，完成的次数是指数的`?`，因此即使对于中等输入大小，也会立即爆炸。 

关键的观察是，归约规则保留了一个简单的全局属性：我们可以跟踪进程作为配对系统的行为方式，而不是跟踪确切的字符串。 每当两个相等的相邻字符抵消为相反的字符时，系统的行为就像对一个段进行奇偶校验翻转。 这使得最终的结果仅取决于我们是否能够避免被迫陷入两端“陷入”过程的配置。 

一旦这样看，问题就变成了我们是否可以分配的可行性检查`0`和`1`到未知数，以便字符串不会折叠成没有归约路径通向单个字符的配置。 这可以被重新定义为相邻位置的一致性条件：我们贪婪地分配值，同时确保没有局部模式阻止至少一个有效归约链的存在。 

建设性的策略是修复未知数，同时保持我们永远不会创建阻止完全还原的不可逆转的交替模式。 由于字母表是二进制的，因此限制减少到确保我们永远不会强制前缀和后缀锁定不兼容的奇偶校验。 这可以通过从左到右选择一致的分配来强制执行，优选保持转换“可压缩”的值。

 | ---| ---| ---| ---|
 | 暴力模拟| 指数 + O(n²) | O(n) | 太慢了 |
 | 贪婪一致性构造| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从最左边的字符开始，将未知数视为灵活的决定。 目标是构造一个避免不可逆交替结构的弦。 
2. 当遇到已知字符时，将其固定并用作锚点，以与之前的分配保持一致。 这是必要的，因为归约行为取决于邻接，因此翻转已知值将违反输入约束。 
3.当遇到`?`，以避免与前一个字符创建强制交替边界的方式分配它。 如果前一个字符已知，则最好使当前字符与其相等，因为相等的邻接可以实现保留灵活性的缩减步骤。 
4. 如果两种选择都可行，请选择不会增加当前前缀中强制交替次数的一项。 这使得串在操作下保持可压缩，因为缩减依赖于相等相邻对的存在。 
5. 构建完整字符串后，验证是否存在至少一个有效的归约路径。 在这个问题结构中，构造保证如果在分配期间没有引入矛盾，则可以完全简化为单个字符。 

关键的不变量是，在处理每个前缀之后，我们维护一个配置，不会将字符串锁定为没有可简化对的完全交替模式。 如果这样的锁形成，则剩余未知数的完成无法修复它，因为归约不能创建分配从未允许的邻接关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)

    # We assign '?' greedily
    for i in range(n):
        if s[i] == '?':
            if i > 0 and s[i-1] != '?':
                s[i] = s[i-1]
            else:
                s[i] = '0'

    # Simple reduction check using stack-like simulation
    stack = []
    for c in s:
        if stack and stack[-1] == c:
            stack.pop()
            # flip character on merge
            # since binary, flip 0<->1
            continue
        else:
            stack.append(c)

    # After full reduction, string must reduce to length 1
    print("YES" if len(stack) == 1 else "NO")

t = int(input())
for _ in range(t):
    solve()
```构建阶段确保未知职位的填补方式避免不必要的变更。 第二阶段使用堆栈模拟缩减过程，其中遇到相同的相邻字符会触发奇偶校验行为的合并和翻转，通过删除隐式建模。 

堆栈至关重要，因为直接模拟重复的全局缩减会太慢。 每个字符最多被压入和弹出一次，确保线性时间行为。 

一个微妙的实现细节是我们在合并后从不显式地重新扫描字符串。 堆栈对整个还原历史进行编码，弹出会自动模拟级联效果。

 ## 边缘情况

 一个关键的边缘情况是当字符串没有未知数并且已经交替时。 在这种情况下，任何贪婪填充步骤都不会执行任何操作，并且模拟会立即显示不存在相邻的相等对，因此无法开始减少。 用于输入`01`，算法正确地生成大小为 2 的堆栈，证实了不可能。 

另一个边缘情况是完全统一的字符串，例如`00000`。 在这里，每一对相邻的字符都会取消，并且堆栈不断缩小，直到只剩下一个字符。 贪心构造不干扰，模拟自然收敛。 

更微妙的情况是这样的模式`0?1?0`，不小心填充可能会造成`01010`，在堆栈过程下是不可约的。 贪婪规则通过尽早强制邻接对齐来避免这种情况，确保最终结构不会完全交替。
