 ## 解决方案
 ## 问题理解

 该游戏以块为单位构建括号序列。 爱丽丝控制着每一个奇怪的回合，包括最后一个，并且她的每个回合都精确地相加`a`括号。 鲍勃控制每个偶数回合并精确添加`b`括号。 在所有回合之后，只有当整个序列是常规括号序列时，爱丽丝才会获胜，这意味着每个前缀的左括号至少与右括号一样多，并且最终余额为零。 

黑客版本只要求我们决定爱丽丝应该选择扮演哪个玩家。 我们需要确定Alice是否有保证规则括号序列的策略，或者Bob是否总能阻止它。 限制很小，但预期的解决方案不是模拟。 策略必须针对对手的每一种可能的举动，因此检查可能的括号字符串将呈指数级增长。 单次移动中可能的字符串数量已经很大，因为一组括号可以有许多不同的排列。 

关键的困难在于常规的括号序列同时有两个要求。 左括号和右括号的最终数量必须匹配，并且每个前缀必须保持有效。 如果早期前缀变为负数，仅修复最终平衡的结构仍然可能失败。 

有两个重要的案例打破了朴素的解决方案。 考虑：```
1
3 2 4
```如果 Alice 尝试玩，她最多可以多使用两个左括号而不是右括号。 鲍勃可以用四个右括号来回答。 即使爱丽丝开始于`((', Bob can append `))))`，使前缀无效。 输出是：```
0
```只检查括号总数的粗心方法可能会错过这一点，因为爱丽丝仍然有最后一步。 

另一种情况是：```
1
3 4 2
```在这里，爱丽丝可以从四个左括号开始，鲍勃不能一次性消除所有安全裕度，而爱丽丝可以在最后一回合修复平衡。 输出是：```
1
```忽略转弯顺序而仅比较总计数的方法可能会做出错误的决定。 

## 方法

 暴力方式是想象玩家的每一种可能的选择以及他们可以放置的每一种可能的括号块。 对于每个完整的游戏，我们可以检查结果序列是否规则。 这是正确的，因为它直接遵循游戏的定义，但完全不切实际。 长度为 50 的棋步有大量可能的括号串，而游戏最多有 49 个回合，因此可能的游戏数量呈指数级增长。 

有用的观察来自于查看平衡而不是确切的顺序。 余额是左括号的数量减去右括号的数量。 常规序列决不能让该值变为负值。 

如果爱丽丝选择玩，她总是可以只从左括号开始。 此后，她想保持足够的正平衡，以便鲍勃不能使序列无效。 由于爱丽丝在鲍勃每次移动之后都会移动，并且也进行最后一步移动，因此只要她的块大小至少与鲍勃的块大小一样大，她就可以在鲍勃的攻击后恢复平衡。 

认为`a >= b`。 Bob 每次移动后，Bob 最多可以减少当前余额`b`。 然后爱丽丝可以添加`a`以恢复安全状态的方式打开括号或关闭括号。 她可以保持不变量，即每次爱丽丝移动后，余额恰好是`a`。 爱丽丝的最后一步可以关闭所有内容并以余额为零结束。 

如果`a < b`，Alice无法保证安全。 无论她第一步采取什么行动，鲍勃都可以选择仅包含右括号的块。 由于鲍勃的区块更大，他可以立即将余额减少到零以下。 一旦前缀失效，最终的序列就不能是正则的。 

整个问题归结为比较两个块的大小。

 ## 算法演练

 1. 阅读`n`,`a`， 和`b`对于每个测试用例。 的价值`n`不会影响决策，因为爱丽丝和鲍勃的权力之间的相同比较适用于每奇数轮。 
2. 比较`a`和`b`。 如果Alice的区块大小至少是Bob的区块大小，则Alice始终可以保持安全的正平衡，因此输出`1`。 
3. 如果Bob的块大小更大，则输出`0`因为Bob可以强制前缀余额变为负数。 

为什么它有效：

 Alice 策略背后的不变性是，每次 Alice 转动之后，序列都可以保持安全的正平衡。 鲍勃最强大的可能攻击是使他的块中的每个括号成为右括号，这会精确地减少平衡`b`。 爱丽丝的下一个区块只有在至少有大小的情况下才能补偿这种损失`b`。 什么时候`a >= b`，爱丽丝总能恢复。 什么时候`a < b`，Bob 可以使他的移动后的第一个前缀无效，因此 Alice 没有获胜策略。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        n, a, b = map(int, input().split())
        if a >= b:
            ans.append("1")
        else:
            ans.append("0")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案读取每个测试用例并仅使用两个块长度之间的关系。 不需要轮数，因为`n`总是奇怪的，这意味着爱丽丝总是有最后一步。 

比较使用`>=`而不是`>`。 什么时候`a`和`b`相等，Alice 可以在 Bob 移动后完全恢复平衡，因此相等是胜诉的情况。 

不涉及数组索引或模拟，这避免了任何差一问题。 算术值很小，但相同的逻辑也适用于更大的整数。

## 测试用例```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, a, b = map(int, input().split())
        out.append("1" if a >= b else "0")
    return "\n".join(out)

# samples
assert solution("""2
3 2 2
3 4 2
""") == """1
1""", "sample"

# minimum size
assert solution("""1

""") == "0", "minimum losing case"

# equal moves
assert solution("""1
49 50 50
""") == "1", "equal block sizes"

# large values
assert solution("""1
49 50 2
""") == "1", "alice much stronger"

# boundary where bob is slightly stronger

5 48 50
""") == "0", "bob stronger by two"

 ## 边缘情况

 对于失败的边缘情况：```
1
3 2 4
```爱丽丝的第一步最多只能创造平衡`2`仅放置左括号。 鲍勃可以用四个右括号来回答，从而将余额减少四个。 该前缀立即失效。 由于常规括号序列不能包含负前缀余额，Alice 无法恢复。 

对于同等大小的情况：```
1
3 4 4
```Alice 从四个左括号开始。 鲍勃可以将余额减少四，但爱丽丝的最后一步具有相同的大小，并且可以准确地恢复序列。 这个不变量仍然成立，因为爱丽丝的权力永远不低于鲍勃。 

对于最强的 Alice 情况：```
1
49 50 2
```鲍勃的每次移动只能消除两个单位的平衡，而爱丽丝可以恢复最多五十个括号。 Alice 有足够的控制力来保持序列在整个游戏中有效。
