 ## 解决方案

 ## 问题理解

 我们得到一个仅由加号和减号组成的字符串。 将其视为递增或递减运行值的一系列操作。 

语句中的过程反复尝试此运行值的不同起始值，从零开始并向上增加。 对于每个起始值，我们模拟从左到右遍历字符串。 每个字符通过加一或减一来更新当前值。 如果在任何时候该值变为负值，则模拟尝试立即失败，我们将移至下一个起始值。 如果我们设法处理整个字符串而不低于零，我们就会完全停止。 

还有一个柜台叫`res`每次模拟尝试的每一步都会增加 1，包括失败的模拟尝试。 所以`res`计算在所有起始值上执行了多少个字符处理步骤，直到我们最终找到一个使整个字符串的运行总和保持非负值的起始值。 

约束足够严格，直接模拟所有起始值是不可能的。 字符串长度达到 1e6 意味着即使重复多次的线性扫描也会导致二次行为。 任何依赖于根据初始值从头开始重新启动扫描的方法都将失败。 

一个微妙的边缘情况是字符串主要包含减号。 在这种情况下，即使初始值很大也会很快失败，但在达到成功之前仍然会贡献许多部分模拟。 另一个重要的边缘情况是从零开始时字符串永远不会低于零，这意味着我们在第一次完整扫描后立即停止。 

## 方法

 天真的方法遵循字面意思。 我们尝试`init = 0, 1, 2, ...`，模拟每一个的完整过程，并增量`res`对于处理的每个字符。 对于每个`init`，我们遍历字符串，直到完成或值变为负数。 

这是正确的，但速度非常慢。 在最坏的情况下，假设字符串都是减号。 开始于`init = 0`，我们在第一个字符处立即失败。 从`init = 1`，我们在第二个字符处失败，依此类推。 如果字符串有长度`n`，然后我们粗略地执行`1 + 2 + ... + n = O(n^2)`运营。 总共有`n`直到1e6，这是不可能的。 

关键的观察是，我们实际上并不对每个独立的模拟感兴趣。 重要的是当解释为 +1 和 -1 步时字符串的最低前缀和。 该最小前缀决定了起始值必须有多大才能在整个步行过程中幸存下来。 一旦我们知道了所需的起始值，我们就可以计算有多少次初始尝试完全或部分失败，并汇总它们的贡献，而无需模拟每个尝试。 

每次失败的尝试的行为都是可预测的：如果我们开始得太低，我们将到达前缀和低于起始偏移量的第一个位置。 我们在失败之前执行的步骤数仅取决于前缀最小值低于零的程度。 

而不是模拟每个`init`，我们跟踪运行前缀和及其最小值。 所有失败启动的总步数形成一个简单的算术结构：每个单位增加`init`将故障点后推一步，直至达到阈值。 

这将问题从重复模拟简化为使用前缀最小值和线性累加的单遍计算。

 ## 算法演练

 我们诠释`+`作为+1和`-`作为-1。 让我们在扫描一次字符串时计算前缀和。 

1. 保持运行值`cur`从0开始，还有一个变量`mn`存储最小值`cur`到目前为止所看到的。 如果我们从零开始，它会跟踪步行下降到零以下的距离。 每个角色都有更新`cur`，我们更新`mn = min(mn, cur)`。 
2.如果最小前缀值`mn`已经是非负数，字符串从 0 开始永远不会低于零。在这种情况下，该过程在一次完整扫描后立即停止，因此答案只是字符串的长度。 
3. 否则，字符串的最深下降为`-k`在哪里`k = -mn`。 这意味着任何小于的起始值`k`会在某个时刻失败，并且起始值`k`是第一个安全的。 
4. 对于每个起始值`init`从 0 到`k-1`，该过程失败。 每次这样的运行都准确地贡献`position_of_failure + 1`步骤。 对所有此类开始进行求和可简化为累积前缀贡献：每次前缀总和达到新的最低级别时，它都会贡献额外的失败步骤。 
5. 我们再次从概念上模拟：当前缀和下降到`-d`，这意味着一切开始于`d-1`至少到目前为止会失败。 我们在扫描时逐渐积累这些贡献。 
6. 最后，添加成功运行的成本。 成功的运行总是处理一次完整的字符串，从而贡献`n`步骤。 

关键的不变量是在处理第一个之后`i`字符，我们确切地知道有多少起始值在位置之前或之前已经失败`i`，并且每个这样的起始值恰好为全局贡献一个单位`res`每个步骤直到其失败点。 这让我们无需显式模拟即可汇总贡献。 

## 为什么它有效

 在任意前缀位置`i`，前缀和表示行走偏离零的距离。 深度的新最小值`-d`意味着我们发现所有起始值`0`到`d-1`此时就已经失败了。 这些启动中的每一个都为此前缀步骤贡献了一个操作计数，因为它们在失败之前都到达了该位置。 

这在前缀最小值和累积贡献之间创建了直接对应关系`res`。 由于每个前缀步骤对于每个活动起始值都只计算一次，因此扫描过程中这些贡献的总和与原始过程中模拟字符评估的总数相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    cur = 0
    mn = 0
    res = 0

    # contribution of failed starts
    for ch in s:
        res += 1  # this position is visited by all active starts at least once

        if ch == '+':
            cur += 1
        else:
            cur -= 1

        mn = min(mn, cur)

        # every time we hit a new deeper minimum, we effectively "activate"
        # one more failed starting value contribution
        if cur < 0:
            # all current valid starts contribute one extra visit here
            res += -cur

    # if never went below zero, only one full run is needed
    if mn >= 0:
        print(n)
        return

    # successful run contributes full length
    # failed contributions already accumulated in res; final adjustment:
    print(res + n)

t = int(input())
for _ in range(t):
    solve()
```该实现使用对字符串的单次传递。`cur`维护前缀和，同时`mn`跟踪达到的最低点，这决定了我们是否提前停止。 这`res`变量聚合了每步的贡献，对应于每个前缀位置有多少个起始值仍然“有效”。 最后，我们添加保证最终成功遍历。 

微妙的一点是我们从来没有显式地模拟不同的初始值。 相反，所有模拟的效果都被编码为在失败之前到达前缀位置的次数。

 ## 边缘情况

 对于单个负号，步行立即降至零以下`init = 0`，所以我们一步后失败并转向`init = 1`，成功了。 该算法捕获了这一点，因为前缀最小值变为`-1`，触发失败启动的聚合并添加最终成功的运行。 

对于像这样的字符串`++++`，前缀永远不会变成负数，所以`mn >= 0`。 算法返回`n`直接，符合只需要一次模拟的事实。 

对于像这样的字符串`----`，前缀最小值达到`-4`，意味着多个起始值在不同深度失败。 累积逻辑对每个前缀步骤进行多次计数，与仍处于活动状态的启动数量成比例，从而匹配流程的分层故障结构。
