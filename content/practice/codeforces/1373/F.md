 ## 解决方案
 ## 问题理解

 我们有一组城市围绕一个中心城市排列成一圈，每个城市有一定数量的家庭需要网络覆盖。 在每对相邻城市之间，可以安装一个网络站，每个站有其可以服务的最大家庭容量。 任务是确定是否存在将每个家庭分配到两个相邻站点之一的方式，使得没有站点超出其容量。 

输入以数组形式提供每个城市的家庭数量`a`以及作为数组的站的容量`b`。 各站`i`服务城市`i`和城市`(i + 1) % n`。 对于每个测试用例，如果所有家庭都可以在电站容量下覆盖，我们输出“是”，否则输出“否”。 

限制很严格。 和`n`最多`10^6`和总和`n`所有测试用例不超过`10^6`，我们负担不起二次复杂度的算法。 每个测试用例的操作必须大致呈线性`n`，所以我们需要一个`O(n)`或者`O(n log n)`解决方案。 可能会导致幼稚方法失败的边缘情况包括这样的情况：一个城市的家庭数量少于前一站所能提供的家庭数量，而导致另一个城市无法覆盖。 例如，如果一个车站的容量超过前一个城市所需的容量，但没有足够的容量供下一个城市使用，那么总是为前一个城市提供尽可能多的家庭服务的天真贪婪者可能会失败。 

## 方法

 蛮力方法是尝试每个站点的所有可能的家庭分布。 对于车站`i`，您可以迭代在城市之间分配家庭的所有方法`i`和`(i+1)`，递归检查后续站。 这原则上是正确的，但需要指数时间，因为每个城市都有多种分配选择。 即使有记忆，分支因子对于`n`最多`10^6`。 

关键的观察是我们可以以贪婪的方式顺序处理城市。 假设我们固定每个城市先使用前一个站点的剩余容量，然后再使用自己的站点。 那么当前站点必须处理的最小家庭数量取决于前一个站点贡献后剩余的家庭数量。 这减少了检查每个城市是否存在的问题`i`, 站总和`i-1`的剩余和车站`i`容量至少等于城市的家庭户数`i`。 如果在任何时候剩余需求超过当前车站容量，这是不可能的。 这是可行的，因为每个站点只能服务两个城市，而循环性质允许我们围绕圆圈传播剩余需求。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 贪婪传播 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从变量开始`prev_excess`追踪有多少家庭没有受到前一站的服务。 将其初始化为零。 
2. 遍历每个城市`i`从 0 到`n-1`。 计算当前站点必须处理的最小家庭数量：这是`max(a[i] - prev_excess, 0)`。 
3.如果该值超过容量`b[i]`当前站，打印 NO 并退出此测试用例。 这意味着当前的车站无法处理其所需的家庭。 
4. 否则，更新`prev_excess`到`b[i] - households_served_for_city_i`。 这是可以为下一个城市做出贡献的剩余能力。 
5. 由于城市形成一个圆圈，因此考虑最后一个城市之后的第一个城市来环绕。 如果算法完成时没有超出任何站容量，则打印 YES。 

这里的不变量是`prev_excess`始终表示前一站可应用于当前城市的剩余容量。 通过始终检查消耗先前容量后所需的最低家庭数量，我们确保没有车站超载并且所有家庭都得到考虑。 这个不变量保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        # Find the minimal excess from the previous station
        min_start = 0
        for i in range(n):
            prev = (i - 1 + n) % n
            a[i] = max(a[i] - b[prev], 0)
        
        if sum(a) <= sum(b):
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该解决方案首先计算每个城市在减去前一个站点的容量后必须由自己的站点提供服务的剩余家庭。 这些残差的总和不得超过所有站点容量的总和，否则计划失败。 循环索引`(i-1+n)%n`确保第一个城市正确计算最后一个站点的贡献。 这种方法避免了过度计数，并以最小的容量优雅地处理边缘情况。
