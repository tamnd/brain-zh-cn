 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串和两个玩家，他们交替地从中删除两个相邻的字符。 每次移动都会删除一个连续的对，因此字符串每轮都会缩小 2 个字符。 当玩家面对不存在相邻对的字符串时，玩家会立即失败，当字符串长度为 0 或 1 时，就会发生这种情况。 

关键问题不在于构建动作，而在于如果双方都做出最佳选择，则决定获胜者。 Alice 总是先移动，因此游戏完全取决于在字符串变得太短而无法继续之前总共可以进行多少次有效移动。 

对字符串长度的限制很小，最多100个，最多有1000个测试用例。 这意味着即使每个测试用例进行 O(n²) 模拟也是可以接受的，但问题的结构表明我们应该以每个字符串进行 O(n) 推理为目标。 

一个微妙的点是，除了是否存在着法之外，0 和 1 的精确排列对于长期游戏来说并不重要。 每次移动仅将长度减少 2，并且除了收缩字符串之外，没有任何移动会创建新的邻接约束。 因此，游戏从根本上讲是关于可以走多少步，而不是关于特定的模式。 

打破天真的思维的极端情况来自于过于关注结构而不是对等性。 

例如，考虑一个像这样的字符串`01`。 爱丽丝立即将其移除并获胜。 为了`1111`，Alice 移除一对，Bob 移除一对，Alice 没有动作。 为了`0011`，爱丽丝删除一对，留下`01`，然后鲍勃将其删除，留下空的。 然后爱丽丝没有动作，就输了。 这些例子表明，决定结果的是动作的平衡，而不是局部结构。 

一个常见的错误直觉是认为交替字符或分组很重要。 实际上，每次移动都会将长度减少 2，因此移动次数本质上是由可以删除多少个不相交的相邻对决定的，直到字符串变得太短为止。 

## 方法

 暴力方法可以完全模拟游戏状态。 在每一步中，玩家都会尝试删除所有可能的相邻对，递归地评估结果字符串，并确定是否有任何移动会导致对手失败。 这是对字符串的标准极小极大搜索。 

问题是州的数量增长得非常快。 即使长度为 20，分支因子也高达 19，并且状态会大量重复，但不会以结构化方式重复，除非在字符串上仔细设计记忆化。 对于长度达到 100 的情况，这种方法变得完全不可行。 

关键的观察结果是，每次移动总是将长度减少 2，并且除了缩小字符串之外，没有任何移动会改变与未来移动可用性相关的任何其他内容。 这意味着可能的移动总数仅取决于我们可以删除相邻对直到字符串长度变为 0 或 1 的次数。 

因此，游戏简化为计算总共有多少步，并检查爱丽丝是否做出了最后一步。 如果总移动次数为奇数，则爱丽丝获胜。 如果是偶数，则鲍勃获胜。 

我们甚至不需要显式地计算移动。 移动次数很简单`len(s) // 2`因为每次移动都会删除两个字符，并且没有任何移动取决于选择哪对来确定最终的移动计数。

 | --- | --- | --- | --- |
 | 蛮力（极小极大状态）| O(指数) | O(n) | 太慢了|
 | 最优（奇偶观察）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 该算法依赖于将游戏简化为简单的奇偶校验。 

1. 读取字符串并计算其长度。 字符的结构与最终决定无关，因此我们忽略实际内容。 
2. 确定可以进行多少次完整移动。 每次移动正好删除两个字符，因此移动次数是长度除以 2 的整数。 
3. 根据平价决定胜负。 如果移动次数为奇数，则爱丽丝将进行最后一步，而鲍勃则没有有效的移动。 如果是偶数，鲍勃将进行最后一步，而爱丽丝则失败。 
4. 如果 Alice 获胜则输出“DA”，否则输出“NET”。 

这种减少有效的原因是，除了将长度减少固定量之外，没有任何移动会改变可用结构的奇偶性。 不存在可以根据策略增加或减少移动总数的分支效应，因为无论选择哪一个相邻对，每次移动都会消耗两个字符。 

### 为什么它有效

 不变的是，在任何有效移动序列之后，剩余的字符串长度始终为`n - 2k`在哪里`k`是移动的次数。 当该值小于 2 时，游戏恰好结束。因此，可能的最大移动数固定为`n // 2`，独立于选择。 由于两个玩家都从 Alice 开始交替着棋，因此当且仅当 Alice 按此固定顺序完成最后一步时，Alice 才会获胜，这相当于`n // 2`很奇怪。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    moves = len(s) // 2
    if moves % 2 == 1:
        print("DA")
    else:
        print("NET")
```该代码读取每个测试用例并立即将其简化为长度计算。 唯一需要的计算是整数除以 2，这对应于可能的删除总数。 奇偶校验直接决定胜负。 

一个常见的错误是试图模拟删除或跟踪实际的对。 这是不必要的，因为游戏从不取决于哪一个特定的对被删除，只取决于在耗尽之前发生了多少次删除。 

## 工作示例

 ### 示例 1：`01`| 步骤| 字符串长度 | 已采取行动| 下一位玩家 |
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | 爱丽丝|
 | 1 | 0 | 1 | 鲍勃（不动）|

 爱丽丝只走了一步，这很奇怪，所以她赢了。 

这证实了对于长度 2，爱丽丝总是获胜，因为她采取了唯一可能的行动。 

### 示例 2：`0011`| 步骤| 字符串长度 | 已采取行动| 下一位玩家 |
 | --- | --- | --- | --- |
 | 0 | 4 | 0 | 爱丽丝|
 | 1 | 2 | 1 | 鲍勃 |
 | 2 | 0 | 2 | 爱丽丝（不动）|

 这里正好有 2 个动作。 鲍勃采取了第二步行动，让爱丽丝没有采取有效的行动。 由于移动次数是偶数，爱丽丝输了。 

这说明最终的结果只取决于删除总数是奇数还是偶数，而不取决于字符的排列。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        moves = len(s) // 2
        out.append("DA" if moves % 2 == 1 else "NET")
    return "\n".join(out)

# provided samples
assert run("3\n01\n1111\n0011\n") == "DA\nNET\nNET"

# minimum size
assert run("1\n1\n") == "NET"

# simple win
assert run("1\n00\n") == "DA"

# alternating pattern
assert run("1\n0101\n") == "NET"

# maximum-ish small test
assert run("1\n" + "01"*50 + "\n") == "NET"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1`|`NET`| 单角色，无动作 |
 |`00`|`DA`| 最小胜诉案例|
 |`0101`|`NET`| 偶数长度交替图案|
 |`01*50`|`NET`| 偶数结构更大，奇偶校验一致性|

 ## 边缘情况

 对于像这样的单个字符`0`，算法计算`len = 1`， 所以`moves = 0`，并输出“NET”。 这与爱丽丝没有立即有效的举动相匹配。 

对于像这样的一对`01`,`moves = 1`，这很奇怪，所以爱丽丝赢了。 在执行过程中，爱丽丝删除了唯一的一对，而鲍勃无法移动。 

对于像这样的字符串`1111`，算法计算`moves = 2`。 Alice 迈出第一步，Bob 迈出第二步，Alice 已经没有下一步了。 偶校验正确地预测爱丽丝会输。 

对于交替字符串，例如`010101`，只有长度很重要。 即使存在许多不同的移除顺序，该算法仍然会产生`moves = 3`，这意味着爱丽丝获胜，因为她得到了最后一步。
