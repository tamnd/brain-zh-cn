 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每种情况下，都有多个银行账户，每个账户都持有一定数量的资金。 我们可以使用固定的转账机制在账户之间转移资金：如果我们发起转账$x$仅来自一家银行的卢布$y$卢布到达目的地银行。 区别$x - y$实际上已经丢失了。 

这个过程可以在任何一对银行之间重复任意多次，目标不是将所有内容完美地整合到一个账户中，而是在所有可能的转账之后最大化最终存入单一最富有银行的金额。 

关键的困难是传输是有损的，除非$x = y$。 如果$x = y$，资金可以自由流动而不会丢失。 否则，每次传输都会泄漏值，因此重复移动少量数据可能与移动大数据块的行为不同。 

输入尺寸很大：最多$2 \cdot 10^5$所有测试用例的银行总数，最多$10^4$测试用例。 这立即排除了每次传输的任何二次或重复模拟。 任何解决方案都必须在每个测试用例的线性时间内工作。 

当贪婪地考虑将所有东西都转移到最大银行时，就会出现一个微妙的问题。 重复模拟任意对之间的传输的幼稚策略将在性能和正确性方面失败，因为它无法推理在重复的有损操作下从根本上可以保留多少价值。 

一个有用的小边缘情况是当所有$a_i$是平等的。 如果$x = y$，那么所有内容都可以合并，答案就是简单的求和。 如果$x > y$，重复转移会减少总质量，并且简单的模拟会错误地假设完全聚集是可能的。 

当有许多小银行和一家大银行时，就会出现另一种棘手的情况。 总是流入最大的银行看起来可能是最佳选择，但这取决于$x - y$，分割或间接转移有时比直接贪婪转移可以保留更多的价值。 这就是为什么解决方案必须依赖于结构不变量而不是逐步模拟。 

## 方法

 如果我们尝试直接模拟该过程，我们将重复选择两家银行并执行转账，并在每次操作后更新余额。 每次传输都会改变本地的值，我们会继续下去，直到看起来不可能有任何改进为止。 这种方法原则上是正确的，因为它准确地反映了规则，但可能的传输序列的数量增长得非常快。 即使对于单个测试用例，有意义的转移选择的数量也可以达到$O(n^2)$，并且每次传输可能会重复多次，使得该过程远远超出了时间限制。 

关键的观察是我们实际上不需要关心传输的确切顺序。 重要的是最终可以将多少价值集中到一家银行。 每次转移要么准确地保留价值（当$x = y$）或引入固定的效率损失。 这意味着系统的行为就像在固定转换率下重复聚合值。 

关键的见解是将所有资金视为大小的“可转换块”$x$，每个产生$y$移动时可用的输出。 如果我们想最大化一家银行的最终金额，我们实际上希望选择可以在所有银行中执行多少次此类转换操作，同时将所有内容集中到一个目的地。 

这将问题简化为计算有多少完整的$x$- 可以根据总质量和无法形成完整转移的剩余量来形成单位。 最佳策略最终是选择一家目标银行，并以最有效的方式将其他所有内容转移到其中，同时考虑每次操作的损失。 这种结构使我们能够仅根据总数导出贪心公式，而无需模拟转账。

 ## 算法演练

 1. 计算所有银行余额的总和。 这代表在考虑任何转移损失之前可能存在的最大金额。 
2. 观察一下，如果我们想以一家银行结束，则每笔转账到该银行都会有效地转换$x$单位从一个账户转入$y$另一个单位。 因此，每个“有用的传输步骤”都会使系统总价值降低$x - y$。 
3. 通过最大化我们可以避免的完全损失周期来实现最佳的最终价值。 这相当于最大化多少个完整的组大小$x$可以从总和中提取，同时了解每个组仅做出贡献$y$到最后的银行。 
4.让$S = \sum a_i$。 计算我们可以模拟多少个完整传输块：$k = S // x$，以及剩余的$r = S \% x$。 
5. 每个完整区块的贡献$y$到最后的积累，而剩下的$r$无法完成全部转让并直接贡献。 
6. 因此答案是$k \cdot y + r$，但我们还必须考虑到我们的目标是一家银行，因此我们将剩余部分解释为已经集中在最佳位置。 

### 为什么它有效

 系统只能通过替换操作来发展$x$货币单位集中在一个地方$y$另一个单位。 任何传输顺序都可以重新安排，以便所有传输都完整$x$首先执行 -size 的操作，银行的顺序并不影响存在多少个这样的完整操作。 这使得完整的总数$x$-阻止唯一有意义的数量控制损失。 由于每个最佳策略必须最大化已完成块的数量，同时保留剩余质量，因此上面导出的表达式捕获了所有可达到的最终配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())
        arr = list(map(int, input().split()))
        
        total = sum(arr)
        
        # number of full x-block conversions
        full = total // x
        rem = total % x
        
        # each full block contributes y, remainder stays as is
        print(full * y + rem)

if __name__ == "__main__":
    solve()
```该实现将整个系统减少为两个聚合量：总和及其相对于$x$。 这完全避免了任何每次传输模拟。 

唯一微妙的一点是确保整数除法应用于全局总和，而不是每个存储体的值。 任何将部门分配给个人的尝试$a_i$会错误地模拟部分转移并失去全局最优性。

 ## 边缘情况

 当$x = y$，转账是无损的，因此每一卢布都可以自由移动。 例如，输入：```
3 5 5
10 20 30
```总共产生 60 个，算法计算$60 // 5 = 12$，余数为 0，得到 60。这与重新分配期间没有值丢失的事实相符。 

什么时候$x$比所有的都大得多$a_i$，不可能完全转移。 例如：```
2 100 10
30 40
```总计为 70，因此答案为 70。该算法正确地将所有内容保留在余数项中。 

当价值分布在许多银行但总和固定时，结果保持不变，因为只有总数才重要。 例如：```
5 10 6
2 2 2 2 12
```给出与任何排列相同的总数，并且无论结构如何，计算始终产生相同的结果。
