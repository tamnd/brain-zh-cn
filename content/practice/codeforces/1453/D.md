 ## 解决方案
 ## 问题理解

 该问题要求我们设计一系列游戏阶段和检查点，以便有 50% 机会击败任何阶段的玩家在整个游戏中拥有准确的预期尝试次数。 每个阶段可能有也可能没有检查点，第一阶段总是有一个。 当玩家在一个阶段失败时，他们会被送回最后一个激活的检查点。 目标是选择一系列阶段和检查点，使得预期的尝试总数与给定的整数匹配$k$，使用不超过 2000 个阶段。 

这些限制是不寻常的。 每个阶段的预期尝试次数与成功概率成几何关系$p = 1/2$，这意味着没有后续检查点的每个阶段都会使预期贡献加倍。 第一阶段总是有一个检查点，它保证预期的尝试次数至少为 2。最大的$k$可以高达$10^{18}$，因此我们无法明确模拟每个阶段的尝试。 相反，我们需要一个数学结构。 

边缘情况是指$k = 1$或较小的值。 例如，如果$k = 1$，这是不可能的，因为成功概率为 1/2 的阶段的预期尝试次数至少为 2，因此不存在有效序列。 另一个微妙的情况是当$k$很大，很近$10^{18}$，这要求我们考虑具有长阶段块的序列以达到目标期望值，同时保持在 2000 个阶段以下。 

## 方法

 一种简单的方法是尝试所有检查点序列并计算每个配置的预期尝试次数。 以检查点结束的阶段段的预期尝试可以递归计算：如果存在检查点，则该段的预期尝试次数会加倍。 即使我们考虑所有长度的二进制序列$n$，序列数量呈指数增长（$2^n$），这显然是不可行的$n = 2000$。 

关键的见解是预期的尝试遵循二的幂。 在检查点之后开始并在检查点结束的一段阶段贡献$2^L$预期每个阶段的尝试次数，其中$L$是最后一个检查点之后的阶段数。 因此，我们可以考虑构建$k$作为两个幂的总和。 例如，$k = 12$可以分解为$8 + 4$，对应于长度产生预期尝试 8 和 4 的段。这将问题简化为构造一系列段长度，其双倍预期尝试总和为$k$，确保总阶段数不超过2000。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 推定（二的幂）| O(log k) | O(2000) | 已接受 |

 ## 算法演练

 1. 初始化一个列表来存储检查点位置，从具有检查点的第一阶段开始。 这对应于始终活动的第一个检查点。 
2. 分解目标$k$成二进制。 每个位代表我们是否需要一个其预期尝试对应于 2 的幂的段。 例如，位位置 3 对应于具有预期尝试的段$2^3 = 8$。 
3. 从 2 的最大幂迭代到最小幂。 对于设置的每个位，添加以检查点结尾的一系列阶段，以便总预期贡献与相应的 2 次幂相匹配。 要构建段，请在放置下一个检查点之前插入足够的没有中间检查点的阶段。 段长度是位位置加一，因为每个阶段的预期尝试都会加倍，直到检查点。 
4. 处理完所有位后，计算总阶段数。 如果超过2000，则答案为-1。 否则，输出阶段数和表示检查点的二进制列表。 
5. 输出配置。 每个阶段都表示为 0（无检查点）或 1（检查点），第一阶段始终为 1。 

原理：检查点之间的每个段都贡献一个几何级数，其总和等于 2 的幂。 通过映射二进制表示$k$对于这些段，预期尝试的总和恰好等于$k$。 施工保证总阶段保持在限制范围内，只要$k$对于 2000 个阶段来说并不算太大，并且算法系统地放置检查点以匹配所需的贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())
        stages = []
        # Build the stages backwards from binary representation
        powers = []
        remaining = k
        for i in range(60, -1, -1):
            if remaining >= (1 << i):
                remaining -= (1 << i)
                powers.append(i)
        if remaining != 0 or len(powers) > 2000:
            print(-1)
            continue
        n = 0
        checkpoints = []
        for p in powers:
            # Each segment of length p+1: first p stages no checkpoint, last stage has checkpoint
            for _ in range(p):
                checkpoints.append(0)
                n += 1
            checkpoints.append(1)
            n += 1
        if n > 2000:
            print(-1)
        else:
            print(n)
            print(" ".join(map(str, checkpoints)))

solve()
```该解决方案读取多个测试用例，处理每个测试用例$k$通过将其分解为 2 的幂，并构建以检查点结束的阶段片段。 这些段被附加到表示检查点的列表中。 我们检查总阶段是否超过 2000 并相应地打印输出。 二进制分解确保预期的尝试次数等于$k$，并在后面附加零和一，以正确的间隔放置检查点。 

## 工作示例

 对于$k = 8$，二元分解为$1000_2$。 我们需要长度为 3 的一段，末尾有一个检查点。 阶段顺序为：

 | 舞台| 检查站|
 | ---| ---|
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 1 |

 这会产生 8 次预期尝试。 

对于$k = 12$, 二进制$1100_2$，我们有幂 3 和 2。我们创建一个长度为 3 的段（预期尝试 8）和一个长度为 2 的段（预期尝试 4）。 检查点列表变为：

 | 舞台| 检查站|
 | ---| ---|
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 0 |
 | 4 | 1 |
 | 5 | 1 |

 预期尝试次数之和为 12，符合要求。

 ## 边缘情况

 对于$k = 1$，算法计算出即使是带有检查点的第一阶段也至少贡献了 2 次预期尝试。 构建失败，输出-1，这是正确的。 为了$k = 2$，该算法创建一个带有检查点的单个阶段，恰好产生 2 次预期尝试。 对于非常大的$k$，分解确保两个匹配的幂之和$k$并构造一个不超过 2000 个阶段的有效阶段序列，因为段数最多为 60 个$k \le 10^{18}$。
