 ## 解决方案
 ## 问题理解

 我们有一行$n$每个球上都写有一个整数。 我们可以重复执行的操作涉及选择集合中的两个相邻值$S$并根据它们的相对大小合并它们。 具体来说，对于当前集合$S$的指数，我们选择任何指数$l$这不是最大值，找到下一个索引$r$在$S$，然后根据值较大的一个将其合并到另一个中。 这些操作的目标是缩小$S$减少到单个元素。 对于每个前缀长度$i$，函数$f(i)$计算最终的单例索引有多少个$j$可以通过仔细执行这些合并来实现。 

在问题的简单版本中，$x = n$，所以对于每个测试用例我们只需要计算$f(n)$，即整个数组可能的最终元素的数量。 每个测试用例给出一个大小的数组$n$值高达$10^9$，并且所有测试用例的元素总数不超过$2 \cdot 10^5$。 这个界限告诉我们，任何比线性更差的算法$n$很可能会超过时间限制。 对所有可能的合并序列进行强力模拟是不可行的，因为合并相等元素的方法呈指数级增长。 

对于具有重复或递增值的数组，尝试每种选择的简单实现将会失败。 例如，在数组中`[1, 2, 2, 1]`，粗心的方法可能只会跟踪单个序列，但正确的答案应该考虑到由于相邻值相等而导致的多个选择。 

基本的边缘情况包括多个元素相等的数组、严格递增或递减的数组以及最小元素出现在多个位置的数组。 在这些情况下，天真的贪婪模拟可能会默默地少算或多算。 

## 方法

 蛮力方法将模拟每一个可能的选择$l$并跟踪所有可达集$S$。 对于尺寸前缀$i$， 有$i-1$合并操作，在每一步，如果两个元素相等，我们就有一个选择。 序列的数量随着相等元素的数量呈指数增长，因此即使对于中等程度的情况，这也很快变得不可行$n$。 

解锁更快解决方案的关键观察是我们不需要模拟每个序列。 如果我们从右向左看，能够存活到最后的位置集合取决于一个元素是否至少与其右侧所有元素的总和一样大。 换句话说，如果一个位置足够大，可以在最佳合并发生时“吸收”其右侧的所有元素，则该位置可以成为最终的单例。 这将问题简化为从末尾开始的线性扫描，维护运行的后缀和并计算元素满足所需阈值的位置。 

这一观察结果将问题从指数模拟转变为线性传递，在给定约束的情况下这是可以接受的。

 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$和数组`a`。 将后缀和变量初始化为零和空列表`can_survive`。 
2. 从最后一个元素迭代到第一个元素。 对于元素`a[i]`，检查它是否至少与当前后缀和一样大。 如果是，这个位置可以存活到最后，所以将它添加到`can_survive`。 
3. 通过添加更新后缀和`a[i]`。 这表示其左侧任何幸存元素必须吸收的总价值。 
4. 扫描数组后，得到长度`can_survive`是`f(n)`，实际幸存指数为`can_survive`本身。 
5. 打印每个测试用例的长度。 对于简单版本，这是唯一需要的输出。 

这样做的原因是合并是关联的并且仅取决于相对大小。 一个位置只有能够累积吸收其右侧的所有元素而不被移除，才能生存。 通过从右向左扫描并维护运行总和，我们确保精确考虑满足此要求的位置。 任何小于所需总和的元素在成为最终单例之前都将不可避免地被删除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        suffix_sum = 0
        can_survive = []
        
        # Scan from right to left
        for i in range(n-1, -1, -1):
            if a[i] >= suffix_sum:
                can_survive.append(i+1)  # 1-based index
            suffix_sum += a[i]
        
        print(len(can_survive))

if __name__ == "__main__":
    main()
```这`suffix_sum`代表任何幸存元素必须吸收的总价值。 将索引附加到`can_survive`相反的顺序可以确保我们正确地识别哪些位置可以是最终的单例。 我们为每个索引添加 1，以将基于 0 的 Python 索引转换为基于 1 的问题索引。 循环从`n-1`到`0`确保每个元素都能看到其前面所有元素的总和，从而捕获必要的不变量。
