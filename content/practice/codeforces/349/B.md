 ## 解决方案
 ## 问题理解

 伊戈尔想用有限的油漆在栅栏上画出尽可能多的数字。 1到9的每个数字都有特定的油漆成本，不能使用零。 输入由可用油漆总量组成$v$和一个由九个正整数组成的数组$a_1$通过$a_9$指示每个数字所需的油漆。 输出应该是伊戈尔用他的油漆供应所能形成的最大数量。 如果无法绘制任何数字，则输出为-1。 

约束条件给出$v$最多$10^6$油漆成本高达$10^5$。 这意味着我们不能天真地尝试所有可能的数字组合，因为可能有数百万个数字，并且尝试每个子集的成本将呈指数级增长。 我们必须以线性或近线性的方法为目标$v$。 

非明显的边缘情况包括最便宜的数字不是最大的情况。 例如，如果$v = 5$成本是$[5, 4, 3, 2, 1, 2, 3, 4, 5]$，一种天真的贪婪方法，在每一步中选择可承受的最大数字，可能会重复选择 5。 另一个边缘情况是当$v$小于任何数字的油漆成本，其结果应为 -1。 

## 方法

 暴力解决方案将尝试所有数字序列，将其绘制成本相加，然后选择最大数值。 虽然这在概念上是正确的，但序列的数量呈指数增长$v$除以最低油漆成本，可达数百万。 显式构造和比较所有数字在计算上是不可行的。 

关键的观察是，最大的数字是通过首先最大化数字的长度来实现的。 对于剩余的油漆，每个位置都应保留尽可能大的数字。 这将问题简化为首先计算我们可以使用最便宜的数字绘制的最大位数，然后如果剩余的油漆允许更昂贵的数字替换更便宜的数字，则从左到右迭代地升级数字。 这种方法利用了这样一个事实：一旦长度固定，通过将较高的数字放置在较高的位置，数值会增加得最多。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(9^(v/min_cost)) | O(9^(v/min_cost)) | O(v/min_cost) | 太慢了 |
 | 最佳 | O(n * 9) ≈ O(v) | O(v/min_cost) | 已接受 |

 ## 算法演练

 1. 确定最便宜的数字。 迭代成本数组并找到油漆成本最小的数字。 让这成为$d_\text{min}$有成本$c_\text{min}$。 
2. 计算仅使用最便宜的数字可以绘制的最大位数。 如果$v < c_\text{min}$，打印-1，因为无法绘制数字。 
3. 初始化一个长度等于最大位数的数组，完全用最便宜的数字填充。 减去$c_\text{min} \times \text{length}$从$v$计算剩余油漆。 
4. 从左到右迭代每个数字位置。 对于每个位置，尝试用不超过剩余油漆的最大可能数字替换当前数字。 具体来说，检查数字 9 到$d_\text{min}+1$。 如果更换数字需要花费$c$，确保$v + c_\text{min} \ge c$因为原始数字的成本$c_\text{min}$已经花掉了。 如果可行，执行更换并更新剩余的油漆。 
5. 处理完所有位置后，将结果数字作为字符串输出。 

为什么有效：该算法首先保证最大长度，这直接使数值在位数上最大化。 用较大的数字替换最左边的数字，同时尊重剩余的油漆，可确保在不减少长度的情况下获得最大的可能值。 这个不变量独立地适用于每个位置，因此全局数量是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

v = int(input())
costs = list(map(int, input().split()))

min_cost = min(costs)
min_digit = costs.index(min_cost) + 1

if v < min_cost:
    print(-1)
    sys.exit()

length = v // min_cost
v -= length * min_cost

number = [min_digit] * length

for i in range(length):
    for d in range(9, min_digit, -1):
        c = costs[d - 1]
        if v + min_cost >= c:
            number[i] = d
            v -= c - min_cost
            break

print(''.join(map(str, number)))
```第一部分读取输入并确定最便宜的数字。 然后，我们计算最大位数，确保准确跟踪剩余的油漆。 嵌套循环仔细地将数字从最大可行升级到最小​​可行，仅减去额外成本。 该算法正确处理可能进行多次升级的情况，并保证最左边的数字最大化。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(9 * v/min_cost) | O(9 * v/min_cost) | 我们可能会为每个数字位置尝试最多 9 次替换 |
 | 空间| O(v/min_cost) | 存储结果数字的数组 |

 给定$v ≤ 10^6$并且最小成本≥1，最多可以进行 10^6 次迭代，并且在 2 秒内完成。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    v = int(input())
    costs = list(map(int, input().split()))
    min_cost = min(costs)
    min_digit = costs.index(min_cost) + 1
    if v < min_cost:
        return "-1"
    length = v // min_cost
    v -= length * min_cost
    number = [min_digit] * length
    for i in range(length):
        for d in range(9, min_digit, -1):
            c = costs[d - 1]
            if v + min_cost >= c:
                number[i] = d
                v -= c - min_cost
                break
    return ''.join(map(str, number))

assert run("5\n5 4 3 2 1 2 3 4 5\n") == "55555", "sample 1"
assert run("10\n1 2 3 4 5 6 7 8 9\n") == "9111111111", "custom 1"
assert run("3\n5 5 5 5 5 5 5 5 5\n") == "-1", "custom 2"
assert run("15\n1 1 1 1 1 1 1 1 1\n") == "999999999999999", "custom 3"
assert run("7\n1 3 3 3 3 3 3 3 3\n") == "7111111", "custom 4"
