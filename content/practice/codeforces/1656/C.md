 ## 解决方案
 ## 问题理解

 我们得到一个非负整数数组。 在一次操作中，我们选择一个整数$x \ge 2$并同时替换每个元素$a_i$和$a_i \bmod x$。 

该操作可以应用任意次数，包括零次。 目标是确定是否有可能达到数组的每个元素都具有相同值的状态。 

数组长度可以大到$10^5$在单个测试用例中，所有测试用例的总长度最多为$2 \cdot 10^5$。 任何尝试模拟许多可能的 mod 操作或探索阵列状态的解决方案都会立即被排除。 我们需要一些接近线性或$O(n \log n)$每个测试用例。 

这个问题有趣的部分是理解模运算如何改变数字之间的关系。 该操作会同时应用于所有元素，因此我们无法独立操作单个值。 

一些边缘情况很容易被忽略。 

考虑：```
3
1 1 1
```答案是`YES`因为所有元素已经相等并且我们可以执行零操作。 

现在考虑：```
3
0 2 5
```答案是`YES`。 选择$x=2$给出：```
0 0 1
```然后选择$x=2$再次给出：```
0 0 1
```这并没有完成工作，而是选择$x=5$首先产生：```
0 2 0
```进而$x=2$给出：```
0 0 0
```诸如“如果有零则答案始终为否”之类的幼稚规则将会失败。 

关键的反例是：```
3
0 1 5
```答案是`NO`。 

零永远不会改变，因为$0 \bmod x = 0$。 价值$1$也永远不会改变，因为对于每一个$x \ge 2$,```
1 mod x = 1
```所以零和一永远不可能相等。 任何仅检查零是否存在的方法都会错过这一点。 

另一个重要案例是：```
4
5 9 17 5
```答案是`YES`。 

选择$x=4$给出：```
1 1 1 1
```尽管原始值有很大不同，但仔细选择模数可以立即使它们相等。 

## 方法

 蛮力思维会尝试搜索可能的值$x$，应用操作，并查看数组最终是否可以折叠成单个值。 

这是不现实的。 数字有多大$10^9$，因此有数十亿个可能的模数。 即使探索状态空间的一小部分也是不可能的。 更糟糕的是，不同的操作序列可能会导致不同的数组，从而创建一个巨大的搜索树。 

为了取得进步，我们需要了解哪些属性永远不会改变。 

关键的观察是数字 0 和 1 是特殊的。 

零是永久的。 无论我们选择什么模数，$$0 \bmod x = 0.$$1 也是永久的，因为每个允许的模数都满足$x \ge 2$， 所以$$1 \bmod x = 1.$$如果 0 和 1 同时出现在数组中，它们将永远保持不同。 达到所有元素都相等的数组变得不可能。 

现在假设数组包含零但不包含一。 

让$m$是数组中最小的正值。 自从$m \ge 2$，选择$x=m$每次出现都会变成$m$变成零，而较大的值变成该范围内的数字$[0,m-1]$。 重复这个想法最终会将所有正值降为零。 零的存在本身并不是问题。 唯一的问题是同时拥有 0 和 1。 

如果根本没有零怎么办？ 

让$m$为最小元素。 选择$x=m$使得每次出现$m$变为零。 由于之前没有零，因此如果原始数组没有一对连续值，则新数组将包含零，但不能包含一。 重复减少过程最终使一切变得平等。 

剩下的障碍是两个连续值的存在。 如果数组包含值$k$和$k+1$，那么经过足够的减少后，它们的行为与 0 和 1 完全相同。事实证明，这是唯一重要的事情。 

公认的解决方案非常简单：

 如果数组包含零，则它不能包含一。 

更一般地，排序后，如果任意两个相邻值恰好相差 1，则答案为`NO`。 

否则答案是`YES`。

 | ---| ---| ---| ---|
 | 蛮力状态搜索 | 指数| 指数| 太慢了|
 | 排序并检查连续值 | O(n log n) | O(n log n) | O(1) 额外（不包括排序）| 已接受 |

 ## 算法演练

 1. 读取数组。 
2. 对数组进行排序。 

排序将所有值按升序排列，从而可以轻松检测两个值是否仅相差 1。 
3. 检查数组中是否包含零。 
4. 如果存在 0，则扫描已排序的数组以查找 1。 

如果零和一都存在，则输出`NO`。 

零永远不会改变，一也永远不会改变，所以它们永远不可能相等。 
5. 如果不存在零，则按排序顺序扫描相邻元素。 

如果任何对正好相差 1，则输出`NO`。 

连续的值最终会产生与 0 和 1 相同的障碍。 
6. 如果前面的条件都没有触发，则输出`YES`。 

### 为什么它有效

 关键的不变量是，一旦值 0 和 1 一起出现，它们就永远不能合并。 零始终是零，一始终是一。 

如果数组已包含零，则将来的每个数组也将包含零。 因此，一个人的存在立即使目标变得不可能。 

当不存在零时，通过选择最小值作为模数，始终可以将其减小到零。 如果两个数字相差 1，这种归约最终会同时产生 0 和 1，从而产生不可能的配置。 相反，如果不存在连续的对，则重复减少可以将所有值驱动到相同的数字，而不会产生禁止的情况。 

因此，问题简化为检测数组是否包含禁止的连续对，并进行特殊处理，仅当存在零时才有意义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        if a[0] == 0:
            if 1 in a:
                print("NO")
            else:
                print("YES")
        else:
            ok = True
            for i in range(1, n):
                if a[i] - a[i - 1] == 1:
                    ok = False
                    break
            
            print("YES" if ok else "NO")

solve()
```第一步是对数组进行排序。 排序后，任何连续的值都会出现在彼此旁边，因此检查是否正好有 1 的差异就变成了简单的线性扫描。 

排序后，最小值很容易识别。 如果它为零，我们只需要知道数组中的任何位置是否存在 1。 使用`1 in a`足够有效，因为总输入大小受以下限制$2 \cdot 10^5$。 

当不存在零时，算法会检查每个相邻的对。 一旦发现相差一分之一，我们就知道答案是`NO`。 

不存在溢出问题，因为 Python 整数处理的值远大于问题限制。 唯一微妙的一点是记住重复是无害的。 零的差异不会产生任何障碍，因此只有恰好一的差异才重要。

 ## 边缘情况

 考虑：```
1
3
0 1 5
```排序后我们得到：```
0 1 5
```该算法看到 0 和 1 并立即输出`NO`。 

这是正确的，因为零始终保持零，而一始终保持一。 没有任何 mod 操作序列可以使它们相等。 

现在考虑：```
1
4
2 4 8 16
```排序后的数组没有改变。 相邻的差异是：```
2, 4 -> 2
4, 8 -> 4
8, 16 -> 8
```没有一个等于一，所以算法输出`YES`。 

没有连续值意味着可以在减少数量的同时避免禁止的 0 和 1 配置。 

最后考虑：```
1
5
0 2 2 10 20
```该数组包含零但不包含一。 算法输出`YES`。 

重复并不重要。 唯一接近零的危险值是一。 由于它不存在，所有正值最终都可以减少到零，使整个数组相等。
