 ## 解决方案
 ## 问题理解

 我们从一个整数数组开始。 在一个操作中，我们选择一个元素，将其从数组中删除，然后从每个剩余元素中减去它的值。 

恰好之后$n-1$操作后，只剩下一个数字。 问题是是否存在某种移除顺序，使最终剩余价值等于给定目标$k$。 

乍一看，这看起来像是一个模拟或状态搜索问题，因为每个操作都会更改所有剩余值。 可能的操作序列的数量是巨大的，大约$n!$，所以直接探索它们是不可能的。 

这些约束强烈暗示预期的解决方案要简单得多。 所有测试用例的数组元素总数最多为$2 \cdot 10^5$。 这允许诸如$O(n)$或者$O(n \log n)$，但是任何与总输入大小成二次方的东西都太昂贵了。 

棘手的部分是识别数组中的哪些信息真正重要。 天真的读者可能会关注数组的重复转换，但最终值结果仅取决于原始元素之间的差异。 

一种不明显的边缘情况是目标已出现在数组中。 

输入：```
1
2 17
17 0
```输出：```
YES
```只有两个元素，删除 0 会使 17 保持不变。 仅搜索等于的差值的解决方案$k$不同的转换状态之间可能会错过这个简单的情况。 

另一个微妙的情况是存在重复值时。 

输入：```
1
4 5
4 2 2 7
```输出：```
YES
```答案来自两人$(2,7)$，其差值为 5。重复项无关。 粗心的实现过早地删除重复项，然后错误地推理操作可能会产生错误的结果。 

负数也是可能的。 

输入：```
1
3 7
-5 2 9
```输出：```
YES
```自从$2 - (-5) = 7$，即使某些值为负数，答案也是正数。 任何假设所有数字都是非负数的解决方案都会失败。 

## 方法

 暴力方法会尝试所有可能的删除顺序。 对于每一步，我们选择剩余元素之一，更新所有其他元素，然后递归地继续。 

这种方法是正确的，因为它明确地探索了每一个法律序列。 问题在于可能性的数量。 和$n$元素有$n!$可能的移除令。 即使是为了$n=15$，这已经远远超出了实际的极限。 

为了找到更好的解决方案，让我们检查一下最终剩余值会发生什么情况。 

假设有两个元素$a$和$b$停留在某个时刻。 如果我们删除$a$，最终值变为$b-a$。 如果我们删除$b$，最终值变为$a-b$。 

关键的观察是每个操作序列最终都会产生两个原始数组元素之间的差异。 事实上，如果我们希望最终的值为$k$，必须存在两个原始元素，其差异恰好为$k$。 

为什么？ 考虑最后一次操作。 就在它之前，还剩下两个数字。 这两个数字本身可以通过之前的减法追溯到原始元素。 对于这个问题的编辑观察是，实现$k$相当于找到两个原始数$x$和$y$这样$y-x=k$。 

这完全消除了模拟操作的需要。 问题变成：

 该数组是否包含一对值，其差值恰好是$k$？ 

一旦以这种方式重新表述，哈希集就会立即解决问题。 对于每个值$x$，检查是否$x+k$也存在。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n!)$|$O(n)$| 太慢了|
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取数组并将所有值插入到哈希集中。 
2. 对于每个元素$x$在数组中，检查是否$x+k$存在于集合中。 
3. 如果存在这样的值，则输出`YES`。 

这对$(x, x+k)$完全有区别$k$，这正是所需要的条件。 
4、扫描整个数组后如果没有元素满足条件，则输出`NO`。 

### 为什么它有效

 关键的性质是操作过程可以产生$k$当且仅当存在两个差值等于的原始数组元素$k$。 

前进的方向是任何成功的序列最终都对应于两个原始值之间的差异。 相反的方向是如果两个元素$x$和$x+k$存在，我们可以安排操作，使最终值变为$(x+k)-x=k$。 

该算法准确地检查这个条件。 如果存在这样的一对，则返回`YES`; 否则它返回`NO`。 由于该条件既是必要又是充分的，因此该算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        s = set(a)

        found = False
        for x in a:
            if x + k in s:
                found = True
                break

        ans.append("YES" if found else "NO")

    sys.stdout.write("\n".join(ans))

solve()
```实现直接遵循算法。 

哈希集存储所有数组值，给出预期的$O(1)$会员资格检查。 对于每个元素$x$，我们测试是否$x+k$存在。 第一个成功的匹配就足以回答`YES`。 

使用一套很重要。 嵌套循环需要$O(n^2)$比较，这是不必要的。 总输入大小达到$2 \cdot 10^5$，所以线性处理是首选。 

Python 中不存在溢出问题，因为整数具有任意精度。 无论如何，这些值仍然在正常整数范围内。 

条件必须检查为`x + k in s`， 不是`abs(x - y) == k`。 该问题需要精确的差异$k$，编辑表征基于有序对$y - x = k$。

 ## 边缘情况

 考虑：```
1
2 17
17 0
```套装是`{17, 0}`。 什么时候`x = 0`，算法检查`0 + 17 = 17`，存在。 答案就变成了`YES`。 这可以正确处理尽可能小的数组大小。 

考虑：```
1
4 5
4 2 2 7
```套装是`{2, 4, 7}`。 什么时候`x = 2`，算法发现`7`在集合中并返回`YES`。 重复值不会影响正确性，因为条件仅取决于存在。 

考虑：```
1
3 7
-5 2 9
```套装是`{-5, 2, 9}`。 为了`x = -5`，算法检查`-5 + 7 = 2`，存在。 答案是`YES`。 负值不需要特殊处理，因为哈希集查找对于负整数和正整数的工作方式相同。 

考虑：```
1
5 3
8 8 8 8 8
```该套装仅包含`{8}`。 每项检查都会询问是否`11`存在。 事实并非如此，所以算法输出`NO`。 这证实了仅重复项不能产生 3 的差异。
