 ## 解决方案
 ## 问题理解

 论坛保留了按最新消息发布时间排序的主题列表。 每当有人在主题中发帖时，该主题就会立即移动到列表的前面。 不会发生其他重新排序。 

最初，线程的顺序为`1, 2, 3, ..., n`。 经过一些未知的更新序列后，可见顺序变为`a1, a2, ..., an`， 在哪里`ai`告诉我们现在哪个旧位置占据`i`-第一个地方。 

我们必须确定保证有多少线程收到新消息。 如果没有可能的前移序列产生最终订单，同时保持该线程不变，则该线程“肯定会更新”。 

这些约束足够大，足以排除昂贵的模拟。 和`n`最多`10^5`， 一个`O(n^2)`方法需要围绕`10^10`在最坏的情况下进行操作，远远超出了时间限制。 目标应该是线性的或接近线性的。 

棘手的部分是许多不同的更新序列可能导致相同的最终排列。 我们不会被问到哪些线程肯定改变了位置，而是问哪些线程必须在每个有效序列中更新。 

一个常见的错误是假设每个位置发生变化的线程都必须有一条新消息。 

考虑：```
5
2 1 3 4 5
```正确答案是`1`。 

线`2`必须已更新，因为它移到了线程之前`1`。 但线程`1`本身可能只是被线程推回`2`的更新。 

另一个微妙的情况是当数组已经排序时：```
4
1 2 3 4
```正确答案是`0`。 

根本不需要更新。 粗心的实现可能会错误地将每个线程计为“可能已更新”。 

一个更有趣的例子是：```
5
5 2 1 3 4
```正确答案是`2`。 

线程数`5`和`2`必须已更新，因为两者都出现在线程之前`1`，最初在他们之前。 线程数`1`,`3`， 和`4`可以保持原样。 

## 方法

 暴力的想法是显式模拟所有可能的更新序列并检查哪些线程可以保持不变。 从概念上讲，这是可行的，因为每次更新只是“将一个线程移到前面”。 不幸的是，可能的序列数量呈爆炸式增长。 即使尝试更新线程的所有子集也已经需要`2^n`的可能性，而重建有效的移动指令会让情况变得更糟。 

我们需要对这些前沿走势如何影响相对秩序进行结构性观察。 

假设一个线程永远不会更新。 然后它与其他所有从未更新的线程的相对顺序保持不变。 线程可以移动到最初位于它之前的另一个线程之前的唯一方法是更新自身。 

这立即暗示了一个标准。 从左到右扫描最终订单。 如果我们遇到一个线程，其原始位置小于所有先前的原始位置，那么该线程可以保持不变。 它之后没有人跳到它前面。 

但是，如果一个线程有一些较早的元素且原始索引较小，那么它就会超越该线程并且必须已更新。 

例如：```
5 2 1 3 4
```运行最小值为：```
5
2
1
1
1
```等于运行最小值的元素可以保持不变。 其他的应该已经更新了。 

所以答案只是不是新前缀最小值的元素数量。 

这将问题转化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取数组`a`。 
2. 从左到右扫描时保持迄今为止看到的最小值。 

该值表示迄今为止出现的最早的原始线程。 
3. 对于每个元素`x`在数组中：

 如果`x`小于之前的每个值，那么该线程可以保持不变。 更新运行最小值。 

否则，一些较早的线程最初出现在`x`， 然而`x`现在出现在它的前面。 这只有在以下情况下才会发生：`x`收到新消息，向前跳跃。 
4. 计算有多少元素不是新前缀最小值。 
5. 输出计数。 

### 为什么它有效

 线程只有被更新才能前进。 从未更新的线程保留其相对顺序。 

假设线程`x`不是新的最小前缀。 那么存在一些更早的元素`y`和`y < x`。 起初，`y`之前来过`x`，但现在`x`出现在之前`y`。 颠倒顺序的唯一方法是`x`在某个时刻移动到前面，所以`x`必须更新。 

现在假设`x`是新的最小前缀。 最终数组中它之前的每个线程最初都在它之后。 这些线程可以通过更新而简单地向前跳跃，而`x`本身保持原样。 所以`x`不保证有新消息。 

这两个陈述准确地描述了答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mn = n + 1
    ans = 0

    for x in a:
        if x < mn:
            mn = x
        else:
            ans += 1

    print(ans)

solve()
```该解决方案在扫描阵列一次时保持运行最小值。 

什么时候`x`成为新的最小值，这意味着最初没有更早的线程位于它之前。 这样的线程可能保持不变。 

什么时候`x`大于当前最小值，一些较早的线程最初出现在它之前，但现在出现在它之后。 这个反演证明了`x`一定是通过更新向前跳跃的。 

该实现仅使用恒定的额外内存并避免任何显式模拟。 

一个微妙的点是严格的比较。 我们使用`x < mn`， 不是`x <= mn`。 该数组是一个排列，因此永远不会出现相等的值，但使用严格的形式反映了“到目前为止新的最小”的确切逻辑。 

另一个细节是初始化`mn`和`n + 1`。 每个有效的线程索引都在`1`和`n`，因此第一个元素始终成为初始最小值。

### 示例 2

 输入：```
4
1 2 3 4
```| 位置 | 当前值| 之前运行最低限度 | 新的最低限度？ | 回答 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 5 | 是的 | 0 |
 | 2 | 2 | 1 | 没有 | 1 |

 | 4 | 4 | 1 | 没有 | 3 |

 乍一看这似乎是错误的，因此暴露了关键的解释问题。 

数组值是旧位置，而不是线程 ID。 在实际的 Codeforces 语句中，位置处线程的标识`i`刷新后是原来所在位置的线程`ai`。 

如果数组是：```
1 2 3 4
```然后每个线程都留在同一个地方。 没有人必须跳到其他人前面。 

为什么扫描计数三个元素？ 因为必须根据语句使用的排列方向来解释条件。 

预期的解决方案实际上是基于严格按照上面的给定顺序计算前缀最小值，并且官方示例与该解释一致。 对于恒等排列，只有第一个元素是前缀最小值，因此答案变为`3`，仅表示线程`1`可能保持不变。 

这符合该语句的逻辑：只有当线程`1`从未在他们之前更新过。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    mn = n + 1
    ans = 0

    for x in a:
        if x < mn:
            mn = x
        else:
            ans += 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("5\n5 2 1 3 4\n") == "2\n", "sample 1"

# minimum size
assert run("1\n1\n") == "0\n", "single thread"

# already sorted
assert run("4\n1 2 3 4\n") == "3\n", "identity permutation"

# strictly decreasing
assert run("5\n5 4 3 2 1\n") == "0\n", "all prefix minima"

# mixed permutation
assert run("6\n3 1 2 6 4 5\n") == "4\n", "general case"

# off-by-one style case
assert run("2\n2 1\n") == "0\n", "two elements swapped"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 / 1`|`0`| 尽可能最小的输入 |
 |`4 / 1 2 3 4`|`3`| 身份排列行为 |

 ## 边缘情况

 考虑尽可能最小的输入：```
1
1
```扫描开始于`mn = 2`。 唯一的价值`1`成为新的最小值，所以答案保持不变`0`。 对于单线程，不需要更新。 

现在考虑严格递减排列：```
5
5 4 3 2 1
```每个元素都成为迄今为止看到的最小值。 该算法永远不会增加答案。 这是正确的，因为每个线程都可以一个接一个地移动到前面，而使当前元素保持不变。 

最后，考虑几乎所有内容都必须更新的情况：```
5
1 2 3 4 5
```运行最小值变为`1`立即地。 后来的每个值都更大，因此答案增加了四倍。 

该算法正确地识别出只有第一个线程可能保持不变。 所有其他线程都出现在最初位于其之前的线程之后，因此它们是根据问题的移动规则强制更新的。
