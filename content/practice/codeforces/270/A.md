 ## 解决方案
 ## 问题理解

 我们被要求确定一个只能以固定角度 _a_ 制作栅栏角的机器人是否可以构造正多边形。 正多边形被定义为所有边和所有角都相等的封闭形状。 输入由多个测试用例组成，每个测试用例给出一个以度为单位的角度_a_。 如果存在每个内角恰好为 _a_ 的正多边形，则每个测试用例的输出为“YES”，否则为“NO”。 

具有_n_条边的正多边形的内角可以使用以下公式计算：$$\text{angle} = \frac{(n-2) \cdot 180}{n}$$这意味着对于给定的 _a_，我们需要找到一个满足以下条件的整数 _n ≥ 3_：$$a = \frac{(n-2) \cdot 180}{n} \quad \text{or equivalently} \quad n = \frac{360}{180 - a}$$约束很简单：0 < a < 180。测试用例的数量未指定，但我们可以假设典型的竞争性编程范围，因此每个测试用例必须在恒定时间内有效处理。 

当 _a_ 非常接近 0 或 180 时，就会出现边缘情况。例如，_a = 179_ 会表明是一个极高边的多边形，我们需要确保我们的整数检查能够正确检测整除性，而不会出现浮点错误。 另一个微妙之处是只有整数 _n ≥ 3_ 才算数； 小数边或 _n = 2_ 无效。 

## 方法

 简单的暴力破解会从 3 开始迭代所有可能的 _n_，计算相应的内角，并检查它是否与 _a_ 匹配。 这是可行的，因为我们需要考虑的最大整数 _n_ 受以下限制：$$n = \frac{360}{180 - a} \le 360$$因此，暴力法是正确的，但当我们可以分析解决问题时，就没有必要为每个测试用例迭代 360 次。 关键的见解是重新排列：$$n = \frac{360}{180 - a}$$问题简化为检查是否$360 / (180 - a)$是大于或等于 3 的整数。如果我们使用整数算术，这会消除任何循环和浮点舍入问题：我们只需要验证 360 是否能被 (180 - a) 整除以及所得商是否至少为 3。

 ## 算法演练

 1. 读取测试用例的数量_t_。 这告诉我们需要处理多少个角度。 
2. 对于每个测试用例，读取机器人可以形成的角度 _a_。 
3. 计算值`x = 180 - a`。 这表示多边形的外角，因为每个内角都是$180 - \text{external angle}$。 
4. 检查 360 是否能被整除`x`。 如果不是，则输出“NO”，因为整数边多边形不能具有该内角。 
5. 如果可整除，计算`n = 360 // x`。 验证 _n ≥ 3_，因为多边形必须至少有 3 条边。 
6、如果两个条件都满足，则输出“YES”； 否则，输出“NO”。 

该算法之所以有效，是因为任何多边形的外角总和恰好为 360 度。 检查 360 度是否能被外角整除，确保我们可以形成具有整数条边的封闭形状。 检查 _n ≥ 3_ 保证多边形有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a = int(input())
    x = 180 - a
    if x <= 0:
        print("NO")
        continue
    if 360 % x == 0 and 360 // x >= 3:
        print("YES")
    else:
        print("NO")
```该解决方案使用有效地读取输入`sys.stdin.readline`处理多个测试用例。 减法`x = 180 - a`直接计算外角。 我们立即消除无效的角度（`x <= 0`) 在执行整除性检查之前。 整数除法确保没有浮点舍入错误，否则可能会产生 120 或 179 度等角度的错误结果。

 ## 边缘情况

 对于像 179 度这样的角度，`x = 180 - 179 = 1`。 检查`360 % 1 == 0`是真的，但是`n = 360`大于 3，所以这似乎是可能的。 然而，我们必须接受它，因为 360 边形的多边形在几何上是有效的。 该解决方案处理`a`正确接近 0，拒绝负数或零`x`，确保没有建议无效的多边形。 为了`a = 0`或者`a >= 180`,`x <= 0`立即触发“NO”，防止出现无意义的多边形。
