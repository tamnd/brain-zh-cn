 ## 解决方案
 ## 问题理解

 我们获得了一个票据打印系统，其中有两台相同的机器，可用于生成报销单。 每台机器每次操作最多可生产一张票据，生产票据后，在冷却期内将无法使用票据。`a`分钟。 使用机器一次也会消耗`b`分钟的活跃工作时间。 关键的限制是，在任何时候，只能主动操作一台机器，这意味着即使两台机器都准备好了，我们也不能并行运行两台机器。 

对于每个测试用例，我们都会给出冷却时间`a`, 操作时间`b`，以及门票数量`n`。 任务是确定生产所有产品所需的最短总时间`n`门票。 

约束条件`n ≤ 10^9`立即排除每张票的任何模拟。 即使对每张票证进行对数或每个事件的模拟也太慢，因为我们可能有多达`10^5`测试用例。 必须在恒定时间内以封闭形式导出每个测试用例的解决方案。 

这个问题的一个微妙点是机器约束不是对称并行。 即使有两台机器，一次只能发生一项操作，这使得这更像是安排交替的冷却时间而不是并行处理。 一个天真的误解是假设两台机器意味着吞吐量加倍，这是不正确的，因为“一次只能使用一台机器”的限制。 

边缘情况出现时`a = 0`，当冷却时间消失并且该过程变得纯粹顺序时，并且当`a`相比之下非常大`b`，这使得同一台机器不可能在短时间内重复使用。 另一个重要的边缘情况是`n = 1`，其中只需要一次操作且冷却时间无关。 

## 方法

 蛮力方法将明确模拟时间。 我们维护当前时间，跟踪每台机器何时变得可用，并重复选择下一个可用机器来执行操作。 每张票后，我们将时间提前`b`，将该机器标记为不可用，直到`current_time + a`，并继续，直到所有门票都出完。 这是正确的，因为它直接对系统约束进行建模。 

然而，这种方法很快就会退化。 每个`n`票证需要更新机器状态并选择可用性，因此复杂度为`O(n)`每个测试用例。 和`n`最多`10^9`，这是不可能的。 

关键的观察结果是，系统实际上并不分支或依赖于上次操作时间之后的历史记录。 因为一次只能使用一台机器，所以唯一真正的决定是我们是否可以在完成之前的操作后立即重新使用机器，或者我们是否被迫等待冷却。 这创造了一个重​​复的模式：如果冷却时间很短，我们要么连续工作，要么如果冷却时间很大，我们被迫进入空闲间隙。 

该过程简化为两种情况的结构。 如果冷却时间`a`足够小，当我们完成一项操作并切换时，机器已经准备好，那么我们就永远不会等待。 否则，我们必须在一些操作之间插入空闲时间。 每个操作有效地花费`b`时间，但如果`a > b`，那么我们必须等待`a - b`在可以重用同一台机器之前，因为切换不允许并行执行。 

这将过程简化为线性时间表：总时间为`n * b`加上每当冷却时间超过执行时间时引入的额外空闲间隙。

 | --- | --- | --- | --- |
 | 暴力模拟| O(n) | O(1) | O(1) | 太慢了|
 | 推导公式| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将时间表建模为一系列`n`操作接连进行。 

1.从时间开始`0`。 每张票都需要准确`b`积极工作的分钟数，因此基准时间始终为`n * b`。 这说明了所有票证的强制处理时间。 
2.通过比较判断cooldown是否引入空闲时间`a`和`b`。 完成一项操作后，我们立即花费`b`时间，所以下一个操作开始`b`分钟后。 如果`a ≤ b`，那么当我们准备再次操作时，机器已经冷却下来了。 无需等待。 
3.如果`a > b`，则完成一次操作后，机器仍在冷却中进行额外的操作`(a - b)`几分钟后我们将开始下一个操作。 由于我们一次只能操作一台机器，因此我们无法使用第二台机器来隐藏这一差距。 这会在每次连续操作之间产生不可避免的空闲期。 
4.有`n - 1`之间的过渡`n`操作，所以我们添加`(n - 1) * max(0, a - b)`到总时间。 
5. 返回计算出的总计。 

### 为什么它有效

 调度完全由操作之间的连续依赖关系决定。 由于操作不能重叠，唯一可能的低效率来自于尝试重复使用机器时等待冷却。 系统永远不会积累额外的并行容量，因此每个间隙都是独立且相同的。 这使得该过程相当于一个线性链，其中每个边缘贡献`b`单独或`b + (a - b)`取决于冷却时间是否超过执行时间。 

由于除第一个操作之外的每个操作之前都恰好有一个转换，并且每个转换具有相同的结构，因此该公式与总累积时间完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, n = map(int, input().split())
    
    base = n * b
    idle = max(0, a - b) * (n - 1)
    
    print(base + idle)
```该实现直接将总时间分解为强制性工作和可选的空闲间隙。 乘法`n * b`累计制作每张票的成本。 期限`(n - 1)`反映第一个操作没有先前的冷却时间要求，因为没有先前的操作来阻止它。 这`max(0, a - b)`确保我们仅在冷却时间超过执行下一个操作所花费的时间时才添加空闲时间。 

一个常见的陷阱是忘记冷却时间与执行时间重叠。 如果`a ≤ b`，机器在我们完成之前或完成后立即可用，因此不存在额外的等待。

 ## 边缘情况

 当`a = 0`，系统完全没有冷却时间，因此每张票证都是连续处理的，没有任何延迟。 该公式正确减少，因为`max(0, a - b)`变为零，所以总时间就是`n * b`。 

什么时候`a = b`，机器在下一个操作开始时正好可用。 这创建了一个没有空闲时间的完美管道，这再次符合公式，因为`(a - b) = 0`。 

什么时候`a > b`，每次转换都会引入固定的延迟。 例如，与`a = 5, b = 2, n = 3`，第一个步骤之后的每个步骤都会产生 3 分钟的延迟。 时间表变得确定性和线性，并且该公式恰好解释了两个这样的转换。 

什么时候`n = 1`，根本没有过渡。 这`(n - 1)`因子正确消除任何闲置贡献，只留下单一运营成本`b`。
