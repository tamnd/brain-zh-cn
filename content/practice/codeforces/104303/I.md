 ## 解决方案
 ## 问题理解

 给定一个二进制字符串，其中每个位置要么是 0，要么是 1。我们最多可以将 k 个 0 更改为 1。 执行这些更改后，我们希望提取尽可能多的不相交段，其中每个段都是长度为 d 的连续块，完全由 1 组成。 

关键约束是所选线段不得重叠，因此如果我们从位置 i 开始获取线段，则不能将 i 到 i + d − 1 范围内的任何位置用于另一个线段。 我们试图在优化翻转到 k 个零后最大化此类段的数量。 

每个测试用例都是独立的，字符串长度最多为 2000，而 k 最多为 100，d 最多为 50。这立即表明，每个测试具有 O(n²k) 或 O(nk) 之类的解决方案是可以接受的，但如果优化不佳，n 中的任何三次方都将是边界。 

当贪婪策略过早地选择段而不考虑稍早或稍晚翻转少量零可以整体解锁更多段时，就会出现微妙的失败情况。 例如，如果 d = 3 并且字符串为 00111000，k = 2，则贪婪地修复第一个可能的段可能会消耗启用两个后续段（而不是一个）的翻转。 

另一个边缘情况是当 d = 1 时。那么每个位置都已经是一个有效的段，答案只是位置的数量加上可能的额外处理（取决于 k），尽管实际上翻转并不重要，因为翻转后零已经可以用作单长度段。 

最后，当 k = 0 时，我们只剩下计算存在多少个长度为 d 的不相交全 1 块，这纯粹是结构性的，需要对现有的 1 游程进行仔细分割。 

## 方法

 蛮力的想法是在翻转到 k 个零后尝试所有可能的选择分段的方法。 人们可以想象枚举要翻转的位置子集，然后贪婪地检查可以形成多少个长度为 d 的全 1 段。 即使对于一组固定的翻转，计数段也是线性的，但翻转选择的数量是组合的，大约是 O(n 选择 k)，这太大了。 

第二个强力细化是对位置、剩余翻转以及我们已经采取了多少段进行动态编程。 从位置 i 开始，我们要么跳过，如果可能的话开始一个段，或者在窗口内翻转零。 这已经朝着最优结构迈进，但如果天真的重新计算窗口成本，仍然存在 O(n²k) 或更糟的风险。 

关键的观察结果是问题的结构是基于区间的和局部的。 除了重叠约束之外，每个段都是独立的，并且长度为 d 的每个段都需要在该窗口内将一些数量的 0 转换为 1。 如果我们预先计算每个长度为 d 的窗口中零的数量，那么我们就确切地知道需要多少次翻转才能使该窗口有效。 

这将问题转化为选择不相交的区间，每个区间都有一个成本（内部零的数量）和一个预算 k。 我们希望在类似背包的约束下最大化间隔数量，但有一个额外的限制，即间隔不能重叠。 这表明对位置、剩余预算和细分数量进行动态规划。 

我们将 dp[i][j] 定义为使用最多 i 的前缀和 j 次翻转可以获取的最大有效段数。 从每个位置 i 开始，我们要么跳过它，要么如果 i ≥ d，我们尝试使用等于该窗口中零数量的成本形成以 i 结尾的段。 由于 n 很小（2000），我们可以使用滑动窗口和前缀和有效地计算转换。 

关键的改进是，我们不再重复重新计算零计数，而是维护零的前缀和，因此每个窗口成本为 O(1)，从而使总转换为 O(nk)。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 翻转的蛮力子集 | O(n^k·n) | O(n^k·n) | O(n) | 太慢了|
 | 窗口 DP 位置和翻转 | O(n·k) | O(n·k) | O(n·k) | O(n·k) | 已接受 |

 ## 算法演练

 我们通过构建一个前缀和数组来预处理字符串，其中 prefix[i] 计算 S[0..i−1] 中出现的零个数。 这使我们能够在恒定时间内计算任何段中零的数量。 

然后我们根据仓位和剩余的翻转构建 DP。 

1.初始化一个DP表，其中dp[i][j]表示我们可以使用前i个字符最多j个翻转形成的最大段数。 我们将所有值设置为一个非常负的数字，除了 dp[0][j] = 0（对于所有 j），因为零个字符我们有零个段。 
2. 从 0 到 n 迭代位置 i。 在每个位置，我们首先通过跳过当前字符向前传播值，这意味着对于所有 j，dp[i+1][j] 至少可以是 dp[i][j]。 这对应于不在 i 处开始段。 
3. 从每个位置 i 开始，如果我们有足够的长度来放置一个线段 (i + d ≤ n)，我们可以使用前缀和计算将 S[i..i+d−1] 转换为全 1 的成本。 该成本是该窗口中零的数量。 
4. 如果这个成本最多为 j，我们可以通过采用以 i+d−1 结尾的一个段从 dp[i][j] 转换到 dp[i+d][j − cost]。 我们用 dp[i][j] + 1 更新 dp[i+d][j − cost]。 
5. 对所有职位和所有翻转预算继续此过程，始终保持最知名的价值。 
6. 最终答案是所有 i 和 j 的 dp[i][j] 上的最大值。 

为什么它有效

 当获取分段时，DP 通过仅向前转换恰好 d 个位置来强制执行非重叠分段。 每个段决策都会消耗一个连续的块，并且不允许重用这些索引。 基于前缀的成本确保我们正确地计算每个候选片段需要多少次翻转。 由于每个有效解决方案都对应于此类片段选择的序列，并且每个此类序列都可以在 DP 中表示，因此永远不会排除最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    INF = -10**9

    for _ in range(T):
        k, d, S = input().split()
        k = int(k)
        n = len(S)

        # prefix sum of zeros
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + (S[i] == '0')

        dp = [[INF] * (k + 1) for _ in range(n + 1)]
        for j in range(k + 1):
            dp[0][j] = 0

        for i in range(n):
            for j in range(k + 1):
                if dp[i][j] == INF:
                    continue

                # skip position i
                if dp[i][j] > dp[i + 1][j]:
                    dp[i + 1][j] = dp[i][j]

                # take segment starting at i
                if i + d <= n:
                    cost = pref[i + d] - pref[i]
                    if cost <= j:
                        nj = j - cost
                        if dp[i + d][nj] < dp[i][j] + 1:
                            dp[i + d][nj] = dp[i][j] + 1

        ans = 0
        for i in range(n + 1):
            for j in range(k + 1):
                ans = max(ans, dp[i][j])

        print(ans)

if __name__ == "__main__":
    solve()
```该实现在很大程度上依赖于这样一个事实：我们可以通过位置和剩余翻转独立地索引 dp。 前缀数组至关重要，因为它可以避免重新计算每个候选窗口中零的数量，否则会将解决方案变成 O(n²k)。 

Skip 转换确保我们永远不会强制段开始，而 take 转换确保我们只放置有效的长度为 d 的块并将指针向前移动 d，从而保证不相交。

 考虑 S = 10111101，k = 2，d = 4。 

我们计算每个长度为 4 的窗口中的零计数：

 索引 0 窗口 1011 有 1 个零

 索引 1 窗口 0111 有 1 个零

 索引 2 窗口 1111 有 0 个零

 ## 边缘情况

 关键的边缘情况是 k = 0 时。在这种情况下，DP 的行为必须与对现有全 1 块进行计数完全相同。 例如，S = 11101111 且 d = 3 应该仅对已经完全有效而无需翻转的窗口进行计数。 DP 处理此问题是因为当 j = 0 时，禁止任何成本 > 0 的转换，因此只有零成本段能够生存。 

另一个边缘情况是重叠的窗户，它们单独看起来很有吸引力，但不能一起选择。 对于 S = 111111 和 d = 4，有多个从不同索引开始的有效窗口，但由于 dp[i+d] 跳转，选择一个会阻止其他窗口。 DP 在结构上强制不相交，因此它不会重复计算重叠的段。
