 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符组成的字符串`X`,`T`， 和`U`。 对于每个测试用例，我们需要计算有多少子字符串具有以下属性：`X`,`T`， 和`U`该子字符串内的字符全部相等。 

这里的子字符串是原始字符串的连续片段，因此我们有效地扫描每个可能的间隔并检查三种字符类型的平衡条件。 每个测试用例的输出是一个整数，表示存在多少个这样的平衡子串。 

约束条件`len(S) ≤ 10^4`每个测试用例最多`T = 100`案例表明总输入大小约为`10^6`最坏情况下的角色。 这已经排除了每个测试用例都是二次的任何解决方案，因为`O(n^2)`会导致大约`10^8`每个案例的操作次数最多`10^{10}`总体而言，太大了。 

一个微妙的边缘情况是当字符串非常倾斜时，例如`"XXXXXXXXXX"`。 长度为 3 的子串不可能是有效的，因为没有`T`或者`U`根本没有字符。 如果忽略字符分布，仅检查子字符串长度能否被 3 整除的简单方法将错误地计算许多子字符串。 

另一种边缘情况是字符均匀分布在模式中但未与固定块对齐，例如`"XTUXTU"`。 存在一些有效的子串，但它们不一定与任何周期结构对齐，因此如果不使用基于前缀的转换，则需要进行强力检查。 

## 方法

 一种直接的方法是枚举所有子字符串，并为每个子字符串计算出现次数`X`,`T`， 和`U`。 如果所有三个计数都相等，我们就增加答案。 这是正确的，因为它直接检查定义。 

然而，独立计算每个子串的频率会导致重新计算。 即使我们维护每个字符的前缀和，我们仍然有`O(1)`检查每个子字符串，但仍生成所有子字符串`O(n^2)`。 和`n = 10^4`，这变成了关于`10^8`每个测试用例都有子字符串，这太慢了。 

关键的观察是三个计数相等可以转化为两个差值相等。 如果我们跟踪计数之间的前缀差异，则当且仅当子字符串的端点在变换后的坐标系中共享相同的“状态”时，子字符串才具有相等的计数。 

定义前缀计数`cx[i]`,`ct[i]`,`cu[i]`。 对于一个子串`(l, r]`，平等意味着：`cx[r] - cx[l] = ct[r] - ct[l] = cu[r] - cu[l]`。 

重新排列给出：`cx[r] - ct[r] = cx[l] - ct[l]`和`cx[r] - cu[r] = cx[l] - cu[l]`。 

因此每个前缀位置都可以映射到一对值，有效子串对应于一对相等的状态。 计算子串变成计算相等前缀状态对，这可以使用频率图来完成。 

我们迭代字符串，维护前缀计数，并存储每个状态出现的频率。 每次我们重新访问一个状态时，我们都会将其之前的频率添加到答案中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n²) | 太慢了|
 | 前缀状态哈希 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将问题转化为计算相等前缀状态。 

1.维护三个运行计数器`cx`,`ct`,`cu`，最初为零。 这些代表我们到当前位置为止已经看到的每个角色的数量。 
2. 将每个前缀索引处的状态定义为`(cx - ct, cx - cu)`。 这将三计数相等条件压缩为两个值。 
3.使用字典`freq`它存储到目前为止每个状态发生的次数。 用状态初始化它`(0, 0)`频率为 1，表示字符串开始之前的空前缀。 
4. 从左到右扫描字符串。 对于每个字符，更新相应的计数器。 
5.更新位置后`i`，计算当前状态`(cx - ct, cx - cu)`。 
6. 添加`freq[state]`答案，因为相同状态的每个先前出现都会形成一个以`i`。 
7. 增量`freq[state]`1.

 关键的推理步骤是，每当两个前缀状态匹配时，它们之间的子串具有相同数量的`X`,`T`， 和`U`。 我们没有显式检查子字符串，而是计算平衡条件在前缀空间中对齐的频率。 

### 为什么它有效

 该算法依赖于每个前缀状态唯一编码字符计数之间的相对差异的不变量。 如果两个索引共享相同的状态，则减去它们的前缀计数可以消除所有差异，从而使它们之间的子字符串中的所有三个字符的计数相等。 相反，任何有效子串都必须在其端点产生相同的前缀状态，因此每个有效子串都被视为一对相等的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    
    for _ in range(T):
        s = input().strip()
        
        cx = ct = cu = 0
        freq = {(0, 0): 1}
        ans = 0
        
        for ch in s:
            if ch == 'X':
                cx += 1
            elif ch == 'T':
                ct += 1
            else:
                cu += 1
            
            state = (cx - ct, cx - cu)
            ans += freq.get(state, 0)
            freq[state] = freq.get(state, 0) + 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接遵循前缀状态思想。 计数器维护累积频率，字典`freq`存储每个状态出现的次数。 关键的一行是`ans += freq.get(state, 0)`，计算以当前位置结尾且满足相等条件的所有子字符串。 

初始化`freq = {(0, 0): 1}`确保从索引 0 开始的子字符串被正确计数，因为空前缀被视为有效的起始引用。 

在增加当前状态的频率之前必须小心更新答案。 如果颠倒过来，我们会多次错误地计算同一位置的空子串。

 ## 边缘情况

 关键的边缘情况是字符串仅包含一个或两个不同的字符。 例如，输入`"XXTTXX"`从来不包含`U`，因此没有子串可以满足相等的计数。 该算法自然地处理这个问题，因为状态`(cx - ct, cx - cu)`除了简单的情况之外，永远不会以同时平衡所有三个计数器的方式重复，所以`ans`保持为零。 

另一个边缘情况是完美平衡的串联，例如`"XTUXTU"`。 这里多个子串重叠并重用相同的前缀状态。 状态的每次重复都会针对所有先前出现的情况进行计数，因此自然会包含重叠的有效子字符串，而无需额外的逻辑。 

最后，单字符字符串，例如`"X"`或者`"T"`正确初始化，因为初始状态`(0,0)`仅当达到完全平衡时才匹配，而这种情况永远不会发生，因此输出为零。
