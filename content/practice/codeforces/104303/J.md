 ## 解决方案
 ## 问题理解

 我们有一群学生，每个学生都知道最多 60 个主题的子集。 有效团队是同时满足两个条件的任何学生子集：从 1 到 p 的每个主题至少由一名团队成员涵盖，并且对于每个主题，最多允许一名团队成员知道。 换句话说，对于每个主题，如果您查看所选的子集，该主题可以出现在零个或一个人的知识集中，但永远不会超过一个，同时仍然要求每个主题出现在团队中的某个位置。 

任务是计算有多少学生子集满足这些约束。 

最重要的结构后果是，每个主题的行为都像一个约束，禁止将两个都包含该主题的学生配对，同时还强制该主题在整体上至少出现一次。 由于每个学生由最多 60 位的子集表示，并且 n 最多为 42，因此自然搜索空间是所有学生的子集，即 2^42，已经有大约 4.4 万亿种可能性。 任何直接枚举子集的解决方案都是不可行的。 

当任何学生都不存在某个主题时，就会出现微妙的边缘情况。 在这种情况下，不存在有效的团队，因为无法满足覆盖范围要求。 例如，如果 p = 3 并且没有人知道主题 2，那么即使我们选择所有学生，主题 2 仍然未被覆盖，因此答案必须为零。 

当两个学生分享一个话题时，就会出现另一种失败模式。 朴素的子集计数仍将包括两者，但无论其他主题如何，此类子集都是无效的，因此修剪是必要的，而不是仅在最后进行检查。 

## 方法

 强力解决方案将迭代学生的所有子集，计算子集中主题的并集，并检查两个条件：并集必须包含所有 p 个主题，并且任何主题不得出现两次。 第二个条件可以通过维护每个子集的频率阵列或通过在构造期间跟踪重叠来检查。 即使使用位掩码，这仍然需要迭代 2^42 个子集，并且每个子集扫描多达 42 个学生或 60 位，导致复杂性远远超出可行的限制。 

关键的观察结果是，“两个选定的学生中没有主题出现”这一约束将每个有效团队变成了一个结构，其中选定的学生必须具有不相交的位掩码。 这意味着我们正在计算成对不相交集合的子集，其并集覆盖所有 p 位。 这是一个经典的不相交集打包问题。 

由于 n 只有 42 而 p 高达 60，因此学生的直接子集 DP 太大。 这个政权的标准伎俩是中间会面。 我们将学生分成最多 21 人的两半。每一半都可以独立枚举，并且我们为每个子集记录两条信息：它涵盖的主题的位掩码以及它是否内部有效（一半内没有重叠）。 

对于每一半，我们生成所有有效的子集并按覆盖范围掩码对它们进行分组。 两半的不相交条件变成一个简单的按位与约束：仅当 L & R = 0 时，才能组合具有掩码 L 的左子集和具有掩码 R 的右子集。覆盖要求变为 L | R = FULL_MASK。 

然后，计数减少为迭代所有有效的左状态并使用补码掩码匹配兼容的右状态。 预先计算正确掩码的频率可以实现快速聚合。

 ## 算法演练

 我们将学生分成左右两组，每组大约包含 n/2 人。

1. 将每个学生的知识集转换为 p 位的位掩码。 这允许使用位操作而不是每个主题循环进行快速并集和交集检查。 
2. 枚举左半部分的所有子集。 对于每个子集，我们构建其联合掩码并同时验证没有主题在子集中出现两次。 我们保持正在运行的掩码和“到目前为止有效”的状态； 如果新学生与当前掩码重叠，则该子集将被丢弃。 
3. 将每个有效的左子集掩码存储在频率表中。 如果多个子集产生相同的掩码，我们将它们一起计数，因为它们对于以后的匹配是无法区分的。 
4. 对右半部分重复相同的过程，生成有效右掩码的频率表。 
5. 对于每对掩码 (L, R)，其中 L 来自左表，R 来自右表，我们检查两个条件：L 和 R 必须为零，并且 L | R 必须为零。 R 必须等于完整的主题集。 当两者都成立时，对答案的贡献为 freqL[L] × freqR[R]。 
6. 将所有贡献相加并输出结果。 

我们可以独立组合两半的原因是，每一半内的有效性已经强制了该半内的不相交。 跨半冲突是使用按位 AND 显式处理的，因此合并步骤中不会存在无效重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def gen_half(arr, p):
    n = len(arr)
    res = {}
    for mask in range(1 << n):
        ok = True
        cur = 0
        for i in range(n):
            if mask >> i & 1:
                x = arr[i]
                if cur & x:
                    ok = False
                    break
                cur |= x
        if ok:
            res[cur] = res.get(cur, 0) + 1
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, p = map(int, input().split())
        full = (1 << p) - 1
        a = []
        for _ in range(n):
            tmp = list(map(int, input().split()))
            k = tmp[0]
            mask = 0
            for x in tmp[1:]:
                mask |= 1 << (x - 1)
            a.append(mask)

        mid = n // 2
        left = a[:mid]
        right = a[mid:]

        L = gen_half(left, p)
        R = gen_half(right, p)

        ans = 0
        for lm, lv in L.items():
            for rm, rv in R.items():
                if (lm & rm) == 0 and (lm | rm) == full:
                    ans += lv * rv

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个学生的知识编码为位掩码。 这将所有主题操作减少为 O(1) 位操作。 

功能`gen_half`枚举一半学生的所有子集。 对于每个子集掩码，它构建主题的并集并确保子集中不会发生重叠。 支票`cur & x`检测新学生是否共享子集中已存在的任何主题。 

每个有效子集将其生成的覆盖掩模贡献到频率字典中，因为多个子集可能产生相同的覆盖范围。 

生成两半后，最后一步检查兼容性。 条件`(lm & rm) == 0`强制两半之间的不相交，并且`(lm | rm) == full`强制全面覆盖所有主题。 

掩码上的嵌套迭代是可以接受的，因为每一半最多有 2^21 个子集。 

## 工作示例

 考虑一个 p = 3 和四名学生的小案例：

 由于取决于配对的重叠约束，学生 1 = {1}、学生 2 = {2}、学生 3 = {3}、学生 4 = {1,2} 在任何单独包含 1 或 2 的子集中都是无效的。 

分成左{1,2}和右{3,4}。 

### 左半枚举

 | 子集| 电流面膜| 有效 |
 | --- | --- | --- |
 | ∅ | 000 | 000 是的 |
 | {1} | 001| 是的 |
 | {2} | 010| 是的 |
 | {1,2} | 011| 是的 |
 | {4} | 011| 是（单项）|

 这会产生频率计数，例如掩码 011 出现两次。 

### 右半枚举

 | 子集| 电流面膜| 有效 |
 | --- | --- | --- |
 | ∅ | 000 | 000 是的 |
 | {3} | 100 | 100 是的 |
 | {4} | 011| 是的 |

 现在我们结合起来。 我们只接受并集为 111、交集为零的对。 所以左掩模 011 只能与右掩模 100 配对。 

该跟踪表明有效性完全是局部的，并且全局约束仅在合并时强制执行。

 ## 边缘情况

 如果所有学生都共享至少一个共同主题，则立即将答案强制为零，因为任何大小至少为 2 的子集都违反了“无重复主题”规则。 该算法自然地处理这个问题，因为在子集枚举期间，任何包含两个学生的对都会触发`cur & x != 0`，消除所有多元素子集。 

缺少主题的案例会导致`full`永远无法到达。 即使左右蒙版组合在一起没有重叠，`(lm | rm) == full`永远不会成立，因此累积的答案仍然为零。 

具有许多相同学生的情况是通过掩模图中的频率聚合来处理的。 尽管子集在组合上有所不同，但它们会折叠成相同的掩码，并在最终合并步骤中通过乘法正确计数。
