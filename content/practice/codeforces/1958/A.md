 ## 解决方案
 ## 问题理解

 我们被要求使用价值 1、3 和 5 的硬币构建一个精确的总和。对于每个目标金额 n，我们希望使用任意数量的 3 和 5 硬币精确支付 n，并且只有在不可避免时才被迫使用 1 硬币。 任务是最小化在这种分解中出现的 1 币数量。 

换句话说，假设我们首先尝试仅使用 3 和 5 来构建 n。 如果这是不可能的，我们可以使用 1 来“修复”余数。 每使用 1 个硬币就相当于在选择 3 个和 5 个硬币的某种组合后留下未覆盖的剩余部分。 

约束很小：n 最多为 100，并且最多有 100 个测试用例。 这意味着即使是二次或三次动态规划方法也能轻松地及时运行。 然而，问题的结构表明，比所有总和上的 DP 简单得多的东西是可能的。 

当贪婪的选择失败时，就会出现一个微妙的情况。 例如，对于n=8，使用单个5叶3，不需要1就可以覆盖，但使用两个3叶2，则需要两个1。 总是首先获取最大硬币的天真贪婪策略并不能可靠地最小化剩余的 1，因为就残差结构而言，5 并不总是比 3 的组合更好。 

当n很小时，会出现另一种边缘情况。 对于 n = 1 或 n = 2，3 和 5 的组合根本没有帮助，因此所有付款都必须使用 1 个硬币完成。 任何假设我们总是可以从 3 或 5 开始的方法都会在这里立即失败。 

## 方法

 暴力方法会尝试 3 个和 5 个硬币的所有组合。 对于每个 5 枚硬币和每个 3 枚硬币，我们检查是否可以使用 1 枚硬币形成剩余值。 对于固定的 n，可能性的数量是 O(n^2)，因为我们可能会尝试最多 n/5 个 5 个硬币的选择和 n/3 个 3 个硬币的选择。 对于每一对，我们计算剩余的硬币，并将其计为 1 硬币的数量。 这是正确的，因为它枚举了所有有效的分解。 

对于 n ≤ 100，这种方法已经足够小，但仍然没有必要。 关键的观察是我们永远不需要明确地将 1 个硬币视为决策变量。 一旦我们确定了使用 3 和 5 硬币的数量，1 硬币的数量就完全由余数决定。 因此，任务简化为最小化从 n 中减去 3x + 5y 后的余数。 

我们可以迭代我们使用了多少个 5 硬币，而不是尝试所有对。 对于每个选择，余数为 n 减 5y。 对于剩余部分，我们希望使用尽可能多的 3 来减少它，因为每个未使用的单位都会变成 1 个硬币。 唯一的微妙之处在于 3 个硬币以 3 为步长减少余数，因此使用 3 个硬币后的余数就是 (n - 5y) mod 3。 

这将问题转化为对 5 个硬币的可能计数的一维扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(n²) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | 每次测试 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取 n 作为目标总和。 
2. 尝试从 0 到 n // 5 的所有可能数量的 5 枚硬币。 
3. 对于 5 个硬币中的每个选择 y，计算剩余值 r = n - 5y。 
4. 从 r 开始，使用尽可能多的 3 个硬币。 使用 3 个硬币后剩下的就是 r % 3。 
5. 将此剩余部分解释为所需的 1 枚硬币的数量。 
6. 跟踪 y 的所有选择的最小剩余量。 

我们迭代 5 个币而不是 3 个币的原因纯粹是为了方便。 由于 5 较大，迭代次数较小，并且余数在模 3 下表现得干净。 

### 为什么它有效

对于任何 5 枚硬币的固定选择，必须以最佳方式使用 3 枚硬币：尽可能多地取出 3 总是能最大限度地减少剩余的未覆盖数量，因为用一枚 3 枚硬币替换 3 个 1 枚硬币永远不会增加 1 枚硬币的数量。 一旦 5 个硬币的数量固定，剩余的不同部分之间就没有相互作用，因此剩余总和的最佳结构是贪婪的和规范的。 因此，全局最优必须出现在每个 y 的这些局部最优选择中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    
    ans = n  # worst case: all 1-coins
    
    for y in range(n // 5 + 1):
        rem = n - 5 * y
        ans = min(ans, rem % 3)
    
    print(ans)
```该代码读取每个测试用例并用悲观情况初始化答案，其中每个单位都使用 1 个硬币支付。 然后它会枚举所有可能的 5 枚硬币的数量。 对于每个选择，它计算余数并使用 3 个硬币贪婪地减少它，只留下模 3 余数作为所需 1 个硬币的数量。 打印所有选择中的最小值。 

这里的一个常见错误是尝试将余数除以 3 并将其添加到答案中。 这将错误地计算 3 个硬币，而不是最小化 1 个硬币。 正确的观点是，3 枚硬币完全消除了大小为 3 的块，只留下残留物。 

## 工作示例

 我们跟踪 n = 7 和 n = 11 的计算。 

### 示例 1：n = 7

 | 5 枚硬币 (y) | 余数 r = n - 5y | r % 3 | 迄今为止最好的答案 |
 | --- | --- | --- | --- |
 | 0 | 7 | 1 | 1 |
 | 1 | 2 | 2 | 1 |

 最好的结果是 1，当使用零个 5 枚硬币和两个 3 枚硬币时获得，余数为 1。 

这证实了混合 5 个硬币并不总能改善余数，因为 5 引入的余数结构在模 3 下可能会更差。 

### 示例 2：n = 11

 | 5 枚硬币 (y) | 余数 r = n - 5y | r % 3 | 迄今为止最好的答案 |
 | --- | --- | --- | --- |
 | 0 | 11 | 11 2 | 2 |
 | 1 | 6 | 0 | 0 |
 | 2 | 1 | 1 | 0 |

 最佳选择是 y = 1，其中 11 − 5 = 6，它可以被 3 整除，从而导致零个 1 硬币。 

这显示了关键的权衡：使用 5 个硬币可以将余数与 3 的倍数完美对齐。

 ## 边缘情况

 对于 n = 1，没有有效的 3 或 5 个硬币，因此算法仅计算 y = 0。余数为 1，r % 3 = 1，正确生成一枚 1 硬币。 

对于n = 2，也会出现同样的情况：只有y = 0有效，余数为2，答案为2。 

对于 n = 3，循环包括 y = 0，给出余数 3，其中 r % 3 = 0，答案变为 0。即使 y = 1 不可能，但在 y = 0 时已找到正确的解。 

对于 n = 8，同时计算 y = 0 和 y = 1。 该算法比较余数 8（给出 2）和余数 3（给出 0），通过 5 + 3 正确选择零个 1 硬币。
