 ## 解决方案
 ## 问题理解

 时钟不是正常的连续显示，它的行为就像三种状态的重复循环。 每个周期都有长度$3k$秒。 在每个周期开始时，时钟显示水温，然后$k$几秒钟后它切换到空气温度，然后又过了几秒钟$k$秒它切换到显示实际时间。 在第三段之后，它再次重新开始相同的模式。 

所以时间线被分成这样的块：$0$到$k-1$时钟处于状态0，从$k$到$2k-1$它处于状态 1，并且从$2k$到$3k-1$它处于状态 2，显示时间。 这种模式无限重复。 

对于每个测试用例，我们都有一个时间$m$，我们就站在那一刻看表。 问题是我们需要等待多长时间才能到达时钟处于“时间显示”段的下一个时刻，这意味着我们想要下一个整数时间$t \ge m$这样$t \bmod 3k \in [2k, 3k)$，我们必须输出$t - m$。 

约束足够大，任何超过几秒的模拟都是不可能的。 和$t$最多$10^4$和$m$最多$10^9$，即使一次检查一秒也需要最多$10^{13}$在最坏的情况下进行操作，这远远超出了限制。 解决方案必须是每个测试用例的恒定时间。 

一个常见的错误来自于对边界行为的误解。 时钟精确地以倍数切换状态$k$，不在间隔期间。 例如，在某个时间$2k$，它立即开始显示时间，所以$2k$本身是有效的。 另一个微妙的情况是当$m$已经处于时间间隔内； 在这种情况下，答案为零，而不是该段的剩余长度。 

## 方法

 直接模拟方法会重复增加时间，从$m$直到到达间隔中的某个时刻$[2k, 3k)$模数$3k$。 这在概念上是正确的，因为它遵循时钟行为的精确定义。 然而，在最坏的情况下，如果$m$就在时间显示段结束后，我们可能会扫描几乎$2k$在进行下一个步骤之前。 自从$k$可以达到$10^8$，这变得完全不可行。 

关键的观察结果是系统是纯周期性的$3k$。 这意味着只有剩余的$m$模数$3k$很重要。 一旦我们知道我们在循环中的位置，答案就仅取决于到区间中下一个点的距离$[2k, 3k)$。 如果我们已经处于该区间内，那么我们就完成了。 否则，我们会跳转到$2k$根据位置在当前或下一个周期中。 

这将问题简化为模块化位置上的简单算术，而不是随着时间的推移进行模拟。

 | --- | --- | --- | --- |
 | 蛮力 |$O(k)$每次测试|$O(1)$| 太慢了 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算周期长度为$3k$。 这代表时钟状态的完整重复模式。 对该值取模，将无限时间线减少为一个有界区间。 
2. 计算$r = m \bmod (3k)$，它告诉我们当前时间位于重复周期内的哪个位置。 此步骤将无限时间轴压缩为单个周期，而不会丢失任何相关信息。 
3. 检查是否$r$已经处于时间显示间隔内$[2k, 3k)$。 如果是这样，时钟已经显示此刻的时间$m$，所以等待时间为零。 
4. 如果$r < 2k$，我们还是在水或空气中展示。 下一次时间显示从下一个周期时间段的开始处开始，该时间段对应于该值$2k$在当前周期中。 等待时间是$2k - r$。 
5. 如果$r \ge 2k$，我们位于时间显示段内，但根据具体位置可能会出现错误的解释。 然而，由于我们已经在步骤 3 中涵盖了有效区间，因此这种情况意味着我们处于时间段中并且答案为零。 

该结构确保我们只计算到下一个阈值的简单距离。 

### 为什么它有效

 关键的不变量是时钟状态仅取决于$t \bmod 3k$。 每一秒都唯一映射到固定长度周期内的一个位置，“时间显示”状态正是间隔$[2k, 3k)$。 因此，寻找下一个有效时刻就简化为寻找最小的时刻$t \ge m$使得它的余数位于该区间内。 由于残基重复每个循环，$m$已经有效，或者下一个有效时刻是第一个边界$2k$在当前或下一个周期。 没有其他结构可以产生更接近的有效时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k, m = map(int, input().split())
    
    cycle = 3 * k
    r = m % cycle
    
    if r >= 2 * k:
        print(0)
    else:
        print(2 * k - r)
```该解决方案使用模运算将时间压缩为单个周期。 变量`r`表示重复模式内的确切位置。 如果`r`已位于时间显示窗口中，无需等待。 否则，距离`2k`给出时钟再次开始显示时间的下一个时刻。 

一个微妙的点是正确地处理边界`2k`。 由于间隔在开始时包含在内，`r == 2k`必须产生零等待，这自然是由`>=`健康）状况。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        k, m = map(int, input().split())
        cycle = 3 * k
        r = m % cycle
        if r >= 2 * k:
            out.append("0")
        else:
            out.append(str(2 * k - r))
    return "\n".join(out)

 ## 边缘情况

 一种边缘情况是当$m$恰好是$3k$。 在这种情况下$r = 0$，这意味着我们正处于水温阶段循环的开始阶段。 该算法正确计算到的距离$2k$，即$2k$，匹配第一个时间显示时刻。 

另一个边缘情况是当$m = 2k$。 这里$r = 2k$，所以条件$r \ge 2k$触发且输出为零。 这与时钟恰好在那一刻开始显示时间的事实相符。 

第三种情况是当$m$就在时间段结束之前，例如$m = 3k - 1$。 模给出$r = 3k - 1$，仍在时间显示区间内，因此答案为零。 这证实了无论是否接近边界，位于区间内的任何位置都是足够的。
