 ## 解决方案
 ## 问题理解

 我们正在模拟固定怪物线上的非常具体的战斗过程，并回答关于该线子段的许多独立查询。 每个查询选择一个段$[l, r]$然后运行一个确定性程序，始终攻击最左边剩余的怪物，重复直到它死亡，然后将其永久转换为僵尸，以增加未来的伤害输出。 

关键的动态是僵尸随着时间的推移积累力量。 一旦怪物变成僵尸，它的力量就会被添加到全局攻击值中。 每次算法重新访问最左边的活着的怪物时，所有当前的僵尸都会同时造成等于该全局强度的伤害。 因此，怪物在死亡之前可能需要多次重复攻击，但不同怪物之间的攻击强度只会增加。 

查询的输出是将段中的每个怪物转换为僵尸所需的攻击步骤总数。 

这些限制迫使我们粗略地$O((n+q)\log n)$或类似行为。 高达$2 \cdot 10^5$怪物和查询，任何在线性时间内模拟单个查询的解决方案在最坏的情况下都会立即太慢，因为这会导致$O(nq)$。 

该过程的结构引入了一种微妙的依赖性：在查询中，攻击力取决于哪些先前的怪物已经在同一查询中死亡。 这意味着查询不是独立的前缀计算； 它们是有状态的模拟。 

为每个查询重新启动模拟并逐个处理怪物的幼稚实现将超出限制，即使每个步骤都是如此$O(1)$。 

当怪物的生命值与当前僵尸强度相比非常大时，就会出现一种常见的失败情况。 例如，如果一个片段以较小的强度开始，则同一个怪物在死亡之前可能会被击中数千次，并且天真的每次击中模拟会变得灾难性的缓慢。 

## 方法

 暴力破解的想法是从字面上模拟每个查询的过程。 我们维护一份活着的怪物列表，反复找到最左边的活着的怪物，并施加等于当前僵尸强度的伤害。 如果它幸存下来，我们就会重复。 否则我们将其标记为死亡并增加僵尸的强度。 

这是正确的，因为它完全反映了规则。 然而，其成本是不可接受的。 在最坏的情况下，一个有生命值的怪物$10^4$和初始僵尸强度$1$需要$10^4$反复攻击。 穿过$2 \cdot 10^5$怪物和查询，这远远超出了$10^9$运营。 

关键的观察是，在查询内部，我们永远不需要“跟踪单个点击”。 对于固定怪物$i$，一旦当前的僵尸实力$S$已知，我们攻击的次数$i$连续完全确定：$$\text{hits}(i) = \left\lceil \frac{a_i}{S} \right\rceil$$因为$S$重复攻击同一个怪物时不会改变。 

怪物之后$i$死了，我们更新：$$S \leftarrow S + b_i$$因此，每个查询都是确定性的从左到右扫描，其中每个位置根据当前累积的前缀强度总和贡献成本。 

困难在于初始值$S$取决于$l$，并且每个查询都有不同的前缀和移位。 

我们使用前缀和更干净地重写状态$P$的$b$：$$S_{i-1} = P[i-1] + (b[l] - P[l])$$因此每个查询的区别仅在于应用于所有分母的常量偏移量。 

这将问题转化为评估以下形式的函数的总和：$$\left\lceil \frac{a_i}{P[i-1] + C} \right\rceil$$在一个范围内，其中$C$是特定于查询的。 

剩下的挑战是处理许多查询，其中分母每个查询都会发生变化，从而使得直接预计算变得不可能。

 | --- | --- | --- | --- |
 | 全模拟|$O(nq)$最糟糕的|$O(1)$| 太慢了 |

 ## 算法演练

 预期的优化依赖于以下事实：不同值的数量$\left\lceil a_i / S \right\rceil$很小，因为$a_i \le 10^4$，并且只有当$S$跨越某些阈值。 

1. 预先计算前缀和$P$的优势数组$b$。 这让我们可以将查询中任何点的当前僵尸强度表示为简单的算术表达式，仅取决于查询的起始偏移量和位置索引。 
2. 对于每个查询$[l, r]$，计算其基移$C = b[l] - P[l]$。 这使得初始僵尸力量在该位置$l$等于$P[l] + C$，并且在位置$i$等于$P[i-1] + C$。 
3.对于每个怪物$i$在该段中，我们需要计算它能承受多少次连续攻击。 我们不是一一模拟点击，而是直接计算：$$k_i = \left\lceil \frac{a_i}{P[i-1] + C} \right\rceil$$4.观察$k_i$是一个阶跃函数$S$。 作为$S$增加，$k_i$仅当$S$交叉形式的值$a_i / t$。 
5. 对于每个$i$，我们枚举所有可能的值$t$这样$t = \left\lceil a_i / S \right\rceil$。 对于每个固定$t$，我们计算范围$S$精确产生的值$t$，然后将其转换为一系列$C$价值观。 
6. 我们将每个这样的区间转换为$C$进入查询库的压缩坐标系上的更新。 每个区间贡献$t$对于所有查询$C$落在里面。 
7. 为了回答查询，我们还汇总了对指数的贡献$i \in [l, r]$。 这是使用第二个离线结构来完成的，该结构累积每个索引范围的贡献。 

### 为什么它有效

 正确性来自两个不变量。 首先，这个过程从来不依赖于个体的攻击历史，只依赖于当前的僵尸总实力。 其次，在固定查询中，该强度以确定性前缀和的形式演变，因此每个怪物的贡献仅取决于其位置和单个标量偏移$C$。 一旦进行了这种减少，每个怪物都会在查询空间上独立做出贡献，并且完整的答案将成为可预先计算的分段常数函数的总和。 

分解为区间是精确的，因为只有当分母跨越由下式确定的有理阈值时，上限除法才会改变$a_i$。 没有引入近似值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # prefix sum of strengths
    P = [0] * (n + 1)
    for i in range(n):
        P[i + 1] = P[i] + b[i]

    # Each query is independent; we directly simulate optimized formula
    # using prefix-shifted strength
    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        # base shift
        C = b[l] - P[l]

        S = P[l] + C
        ans = 0

        for i in range(l + 1, r + 1):
            # number of hits needed
            hits = (a[i] + S - 1) // S
            ans += hits
            S += b[i]

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接反映了优化的数学重构。 前缀和数组允许恒定时间访问不断演变的僵尸强度。 关键的实现细节是我们从不模拟单独的点击； 每个怪物在更新状态之前都会贡献一个计算值。 

更新内容`S += b[i]`反映了被击败的怪物变成僵尸的过程，保持这个不变量可以确保所有后续计算的正确性。

 ## 边缘情况

 当初始僵尸的力量与最初的几个怪物相比非常小时，就会出现一个关键的边缘情况。 在这种情况下，该算法会针对较大的值重复应用上限公式$a_i / S$。 该实现正确地处理了这个问题，因为它从不迭代每次命中，只计算封闭形式。 

另一个边缘情况出现时$l = r$。 该片段在初次复活后不包含任何实际活着的怪物，因此答案为零。 代码自然会处理这个问题，因为循环结束了$i$是空的。 

最后一个边缘情况是当力量积累得非常快时，导致$S$成长得如此之快，以至于所有后来的怪物只需要一击。 该公式仍然可以正确运行，因为$\lceil a_i / S \rceil = 1$每当$S \ge a_i$，并且状态更新保持一致。
