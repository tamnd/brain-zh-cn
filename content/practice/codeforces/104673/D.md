 ## 解决方案
 ## 问题理解

 我们有一堆日记，由一串表示`+`和`-`，其中每个符号描述期刊封面的方向。 当给出字符串时，从上到下读取堆栈。 目标是重新排列堆栈，以便没有两个相邻的日志具有相同的符号，这意味着最终的字符串必须严格交替`+`和`-`。 

允许的操作是结构化的，但有效地提供了强大的转换。 我们可以从堆栈顶部删除一些前缀，然后从剩余的内容中取出一个连续的块，反转该块，最后将删除的前缀放回顶部。 关键的观察结果是，这允许在单个操作中反转堆栈的任何连续子字符串。 

由于反转是唯一真正的变化，因此问题变成了转换任务：使用最少数量的子字符串反转将初始二进制字符串转换为交替目标字符串。 

输入长度最大为$2 \cdot 10^5$，这会立即排除任何尝试所有子串或在二次时间内贪婪地模拟每个操作的解决方案。 我们需要一个线性或近线性的策略。 

一个微妙的点是，恰好有两个有效的目标配置：一个以`+`和一个开头`-`。 两者都是有效的交替模式，我们必须选择需要较少操作的一种。 

重要的边缘情况是小字符串和已经正确的字符串。 例如，输入`"+-"`已经满足条件，所以答案是零。 对于像这样的字符串`"++--"`，一种幼稚的方法可能会尝试贪婪地解决局部冲突并过度计算操作，即使中间段的单个反转会产生`"+-+-"`。 

## 方法

 强力视图是将每个状态视为一个字符串，并尝试所有可能的子字符串反转，对配置执行 BFS。 每个州都有$O(n^2)$邻居，即使是小深度的探索也变得不可行，因为可达字符串的数量呈爆炸性增长。 即使我们将自己限制在最佳路径上，状态空间也是$2^{2K}$，这是完全无法管理的。 

关键的见解是，我们并不是试图达到任意配置，而是两种固定交替模式之一。 这消除了对全局结构进行推理的需要。 相反，我们将当前字符串与目标进行比较，并关注不匹配的位置。 

如果我们仔细选择反转的端点，反转可以纠正单次移动中的两个边界不匹配。 直观上，只要两个位置相对于目标是错误的，我们就可以将它们配对并在一次逆转中修复它们。 这将问题简化为计算不匹配并以最佳方式配对它们。 每个操作最多可以消除两个不匹配，并且精心选择的反转总是可以在不破坏先前固定结构的情况下实现这种配对。 

这导致了一个简单的减少：计算两个交替目标中每一个目标的不匹配，并获得更好的结果。 答案是不匹配的数量除以二，四舍五入。

 ## 算法演练

 我们通过评估两个可能的交替目标并计算有多少个立场与每个目标不同来解决这个问题。 

1. 构造一个假设的目标字符串，开头为`+`，交替显示全长。 

这代表一种有效的最终配置。 
2. 将输入字符串与该目标进行比较，并计算有多少个索引不同。 

每个不同的位置代表当前相对于目标处于错误方向的日记。 
3. 计算该目标所需的操作数为`(mismatch_count + 1) // 2`。 

这是因为，当正确配对时，一次逆转可以修复两个不匹配的位置。 
4. 对以以下开头的目标重复相同的过程`-`。 
5. 返回两个计算结果之间的最小值。 

### 为什么它有效

 关键的特性是，除了通过反转配对之外，不匹配的头寸是独立的。 一次反转只能在其端点处有意义地“配对”修正，同时保持内部结构与目标模式一致。 由于每个操作最多可以修复两个不匹配，并且任何单个不匹配都需要至少一个操作，因此最佳策略相当于尽可能高效地配对不匹配。 尝试两种目标模式可确保我们不会偏向错误的起始奇偶校验。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    def cost(start_char):
        mismatches = 0
        cur = start_char
        for i in range(n):
            if s[i] != cur:
                mismatches += 1
            cur = '+' if cur == '-' else '-'
        return (mismatches + 1) // 2

    ans1 = cost('+')
    ans2 = cost('-')
    print(min(ans1, ans2))

if __name__ == "__main__":
    solve()
```该实现直接对两个候选交替模式进行编码。 辅助函数遍历字符串一次，维护每个位置的预期字符。 失配计数在单遍中累积，保持解的线性。 

表达式`(mismatches + 1) // 2`捕获配对参数：每个操作都可以解决两个不正确的位置，如果一个仍然未配对，则需要额外的操作。

 ## 边缘情况

 对于像这样的单字符字符串`"+"`，两个目标模式在交替规则截断之前都是有效的，并且不匹配计数为零，因此算法立即返回零。 

对于已经交替的字符串，例如`"+-+-+-"`，针对其中一个目标的不匹配计数为零，因此不需要任何操作，算法自然会选择该目标。 

对于像这样的统一字符串`"++++"`，两个目标每两个字符都会产生两个不匹配，从而导致两个总不匹配，从而导致一个操作，该操作对应于反转中间段以创建交替。
