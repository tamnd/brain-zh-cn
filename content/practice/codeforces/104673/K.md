 ## 解决方案
 ## 问题理解

 我们在平面上得到一组点，每个点代表一座必须访问一次的火山。 旅行者从任何选定的点开始，必须构建一条访问所有点并在最后访问的点结束的路径。 运动规则是有限制的：每次移动必须是向北、向南或向东。 无法向西移动，这迫使沿途的 x 坐标永远不会减少。 y 坐标可以自由上升或下降。 

旅程的成本是这些轴对齐移动路径的欧几里得网格总长度，这实际上意味着沿 x 或 y 的每个单位步骤都会对总距离做出贡献。 由于只允许轴对齐移动，因此问题减少到最小化总水平和垂直行程，同时确保访问所有点。 

约束的关键结构含义是，如果没有向西移动，x 坐标就像时间线一样。 一旦我们移动到更大的 x 值，我们就永远无法返回。 这立即表明任何有效的路线都有效地按 x 坐标的非递减顺序处理点，可能按相等的 x 值分组。 

对于多达 100,000 个点，任何尝试对子集进行排列或路径搜索的解决方案都是不可能的。 即使是直接比较点对的二次方法也会变得太慢。 我们被迫采取一种策略，通过 x 坐标压缩点并在线性或接近线性的时间内处理每个组。 

当多个点共享相同的 x 坐标时，会出现一个微妙的问题。 在这种情况下，我们可以在该垂直线内自由地重新排序访问，这可以极大地改变垂直旅行成本。 另一个重要的边缘情况是所有点都位于一条垂直线上。 那么根本就没有水平移动，问题就简化为寻找一条覆盖一条线上的一组 y 值的最短路径，这仅取决于它们的分布。 

## 方法

 自然的第一个尝试是考虑以任何顺序访问点，同时尊重无西约束。 人们可以想象尝试点的所有排列或尊重 x 递增的所有可能序列。 这很快就变得不可行，因为即使限制为 x 排序的顺序，仍然可以自由选择如何交错具有相同 x 的点以及如何在它们之间转换。 可能性的数量随着不同 x 值的列数呈指数增长。 

关键的观察结果是，对运动的限制使得几何形状在 x 上基本上是一维的。 一旦点按 x 坐标分组，路径必须以递增的 x 顺序穿过这些组，并且两个连续 x 值之间的每个水平过渡都是强制的。 这完全消除了水平方向上的组合自由度。 

剩下的问题是垂直的：在每个固定的 x 坐标组中，我们必须决定如何遍历所有 y 值，假设我们以某个 y 值（由前一组确定）进入该组并将其保留在某个选定的 y 值。 群体内部的最佳结构始终是“走到一个极端，然后扫到另一个极端”的模式，因为任何未达到极端的绕行都会浪费垂直距离，而无助于覆盖其他点。 

这将每个 x 组减少到一个小状态：我们只需要关心是否以最小 y 或最大 y 退出该组。 小组内的其他一切都更糟。 

蛮力方法仍然会尝试为每个组选择进入和退出行为的所有方法，从而导致组之间的指数分支。 优化认识到每个组仅贡献两个有意义的退出状态，从而允许从左到右的简单动态编程转换。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有访问订单 | O(N!) | O(N) | 太慢了|
 | 具有端点状态的排序 x 组上的 DP | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 1. 按 x 坐标对所有点进行分组，并按升序对不同的 x 值进行排序。 在每个组内，对 y 值进行排序并计算最小和最大 y。 

此步骤将平面转换为一系列垂直柱，每个柱由其垂直跨度概括。 
2. 对于每一列，预先计算其垂直范围并仅记住端点。 

除了通过最小值和最大值之外，列的内部点永远不会影响最佳转换。 
3. 定义一个动态编程状态，其中对于每一列，我们跟踪两种可能性：在其最小值 y 或最大值 y 处结束该列的遍历。 

这已经足够了，因为垂直集合的任何最佳遍历都可以安排在极限处完成，而不会增加成本。 
4. 考虑到我们可以从其中的任何位置开始，初始化第一列。 最佳策略是从一个极端遍历到另一个极端，成本等于列的垂直跨度，并在任一极端结束。 

由于没有先验约束，我们可以自由选择切入点以最小化内部成本。 
5. 从左到右处理列。 假设我们位于第 i 列，并且已知在第 i−1 列的任一极端结束的最佳成本。 
6. 当从第 i−1 列移动到第 i 列时，添加等于 x 坐标差的水平成本。 在此移动过程中 y 坐标保持不变，因此第 i 列的入口 y 正是所选的第 i−1 列的出口 y。 
7. 对于第 i 列中的每个可能条目 y（来自第 i−1 列的任一状态），计算遍历第 i 列中的所有点并以其最小值或最大值 y 结束的成本。 利用线段上的最佳遍历行为如下的事实：

 如果入口位于线段之外，我们将直接前往远端端点。 如果入口位于内部，我们必须从两端进入。 
8. 存储第 i 列的两个退出选择的最小成本并继续。 
9. 答案是最后一列中两个 DP 状态中的最小值。 

### 为什么它有效

 在任何列中，关于过去的唯一相关信息是我们到达的 y 坐标，关于未来的唯一相关信息是我们从哪个极端出发。 在一列内，所有点都位于一条垂直线上，因此访问它们的任何路径都可以重新排列为极端之间的单调扫描，而不会改变可行性。 这保证了将状态限制为最小和最大端点永远不会放弃最佳解决方案，因为任何非极端端点都可以转换为极端端点，而不会增加总距离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    
    pts.sort()
    
    cols = []
    i = 0
    while i < n:
        x = pts[i][0]
        ys = []
        while i < n and pts[i][0] == x:
            ys.append(pts[i][1])
            i += 1
        ys.sort()
        cols.append((x, ys[0], ys[-1]))
    
    m = len(cols)
    
    if m == 1:
        # single column: just cover vertical span
        return cols[0][2] - cols[0][1]
    
    # dp[i][0] = end at min y, dp[i][1] = end at max y
    x0, lo0, hi0 = cols[0]
    dp0 = [hi0 - lo0, hi0 - lo0]
    
    for i in range(1, m):
        x, lo, hi = cols[i]
        px, plo, phi = cols[i-1]
        dx = x - px
        
        ndp = [10**30, 10**30]
        
        for prev_end in (0, 1):
            prev_y = plo if prev_end == 0 else phi
            base = dp0[prev_end] + dx
            
            # enter at prev_y, traverse current column
            # compute cost to end at lo
            if prev_y <= lo:
                cost_lo = base + (hi - prev_y)
            elif prev_y >= hi:
                cost_lo = base + (prev_y - lo)
            else:
                cost_lo = base + (hi - lo) + min(prev_y - lo, hi - prev_y)
            
            # end at hi
            if prev_y <= lo:
                cost_hi = base + (hi - lo) + (lo - prev_y)
            elif prev_y >= hi:
                cost_hi = base + (prev_y - lo) + (hi - lo)
            else:
                cost_hi = base + (hi - lo) + min(prev_y - lo, hi - prev_y)
            
            ndp[0] = min(ndp[0], cost_lo)
            ndp[1] = min(ndp[1], cost_hi)
        
        dp0 = ndp
    
    print(min(dp0))

if __name__ == "__main__":
    solve()
```该实现首先将点压缩到按 x 坐标排序的垂直列中。 每列都减少到其最小值和最大值 y，因为可以在不存储单个点的情况下最优地重建所有内部结构。 

动态编程数组每列存储两个状态，对应于在列的底部或顶部结束。 对于每个转换，我们显式模拟在前一个出口 y 处进入下一列，添加水平距离，并计算在任一端点完成时扫描当前列的最佳方式。 

一个常见的微妙之处是条目 y 是由先前状态固定的，因此不能独立选择它。 另一个重要的一点是，两个 dp 转换都必须考虑之前的两个端点，因为最佳路径可能会在列之间切换方向。

 ## 边缘情况

 单个 x 坐标情况会导致整个 DP 崩溃。 该算法通过返回垂直跨度来显式处理它，因为没有水平移动，也不需要状态转换。 

当所有点共享相同的坐标时，最小值和最大值都会折叠为相同的值，因此所有 DP 状态始终保持为零，从而正确地产生零成本。 

当列在 x 中具有较大间隙时，水平贡献仍然会在每次转换时准确地累积一次，因为每个列转换恰好对应于一个向东移动段。
