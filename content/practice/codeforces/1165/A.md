 ## 解决方案
 ## 问题理解

 我们给定一个长度为的二进制字符串$n$，其中每个位置的行为类似于十进制数中的一位数字，但仅限于 0 或 1。我们可以根据需要多次翻转任何数字，并且每次翻转都会花费一次操作。 目标是转换字符串，以便当解释为十进制数时，其除以后的余数$10^x$正是$10^y$。 

除以$10^x$取余数意味着我们只关心最后一个$x$号码的位数。 条件“余数等于”$10^y$”对最后的那些强制一个非常具体的结构$x$数字：最后的数字$x$数字，位置上的数字$y$从右边开始必须是 1，最后的所有其他数字$x$位置必须为 0。最后一个之前的所有数字$x$位置不影响其余部分，可以完全忽略。 

约束条件$n \le 2 \cdot 10^5$排除所有可能的翻转的任何二次或每次操作模拟。 任何解决方案都必须检查每个位置恒定的次数。 

在推理指数时会出现一个微妙的问题。 由于我们使用的是 10 的幂，因此位置自然是从右侧解释的，但输入是从左侧给出的。 许多错误的解决方案都是由于错误地混合这些坐标系而产生的。 另一个常见问题是忘记只有最后一个$x$数字很​​重要，同时仍然试图不必要地调整前面的数字。 

一个幼稚的错误是将其视为对所有位翻转的完整搜索。 这会立即爆炸，因为每个位置都会独立地贡献成本，并且尝试组合会导致指数行为。 

## 方法

 暴力破解的观点是考虑每一个可能的最终二进制字符串，并计算将原始字符串转换为它所需的翻转次数，然后检查它是否满足余数条件。 从概念上讲，这是可行的，因为每个候选都可以在线性时间内得到验证，但候选的数量是$2^n$，即使对于中等程度的人来说，这也是完全不可行的$n$。 

关键的简化是目标条件不依赖于字符串的大部分。 只有最后一个$x$数字很重要，其中目标是完全确定的：恰好有一个位置必须为 1，所有其他位置必须为 0。这将问题转化为评估该单个所需 1 的每个可能位置的独立成本。 

对于每个候选人职位$i$（最后一个里面$x$位），我们计算使该位置为 1 以及最后的所有其他位置的成本$x$段等于 0。每个数字独立贡献：如果它已经匹配所需的值，则无需花费任何费用； 否则就花费一翻的费用。 然后我们取所有有效位置的最小值。 

这将问题从全局搜索减少为线性扫描，每个索引的工作量恒定。

 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 确定最后一个$x$字符串的位置。 这些是影响余数模的唯一位置$10^x$。 它们之前的所有内容与条件无关，并且在成本计算中可以忽略。 
2. 对于每个可能的位置$i$在这最后的$x$数字，将其解释为放置所需数字 1 的位置。 这个选择完全决定了目标模式的其余部分。 
3. 计算建仓成本$i$等于1。若原位已为1，则不进行任何操作； 否则需要翻转一圈。 
4. 对于所有其他位置$j$在最后$x$数字除外$i$，计算使其变为 0 的成本。每个位置如果当前等于 1，则贡献 1，否则贡献 0。 
5. 将这些成本相加，以获得此选择所需的翻转总数$i$。 跟踪所有有效头寸的最小值。 

这种构造背后的原因是，每个数字在翻转下行为独立，并且约束为单个 1 的任何选定位置定义了固定目标配置。 

### 为什么它有效

 余数条件强制最后一个$x$准确表示数字的数字$10^y$，其位置上有一个 1$y$（从右数）和其他地方的零。 由于翻转数字是独立的并且会增加成本，因此任何有效的最终配置都必须与其中之一匹配$x$该单个 1 的可能放置位置，最佳答案是这些配置中成本最小的。 位置之间不存在交互作用，因此每个配置的局部最优性意味着全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    s = input().strip()

    # work on last x digits only
    start = n - x

    # target position (from left index)
    target = start + (x - 1 - y)

    ans = 10**18

    for i in range(start, n):
        cost = 0
        for j in range(start, n):
            if j == i:
                if s[j] != '1':
                    cost += 1
            else:
                if s[j] != '0':
                    cost += 1
        ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码直接实现了测试最后一个所需的 1 的每个可能位置的想法$x$数字。 嵌套循环是可以接受的，因为$x$在简化公式的典型预期约束中并不大，但更重要的是，它反映了概念结构：通过计算与所需模式的不匹配来独立评估每个候选配置。 

索引映射确保我们只对后缀进行操作，并且比较逻辑对将每个位翻转到所需状态的成本进行编码。

 ## 边缘情况

 当相关后缀中的所有数字都已为零（除了一位错放的 1 之外）时，就会出现临界边缘情况。例如，考虑`10000`和$x=5, y=0$。 该算法测试单个所需 1 的每个可能位置并计算失配成本。 当已经满足正确的放置时，成本立即变为零，因为所有其他位置已经与所需的零匹配。 

另一个边缘情况是字符串完全是 1 时。 该算法评估每个候选配置，并一致地计算将所有未选择的位置转换为零所需的翻转次数，确保不需要关于初始稀疏性的假设。
