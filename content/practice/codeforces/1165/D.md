 ## 解决方案
 ## 问题理解

 我们给出了一个多重集，它应该表示某个未知整数的几乎所有除数$x$。 这里的“几乎全部”有一个精确的含义：该列表包含$x$除了$1$和$x$本身。 我们的任务是重建尽可能小的$x$可以准确地生成这个除​​数列表，或者确定不存在这样的整数。 

关键的困难是我们没有得到$x$直接，甚至不是完整的除数集。 我们只看到内因数，在配对下它必须是闭的：if$d \mid x$， 然后$\frac{x}{d} \mid x$同样，两者都应该出现在列表中，除非它们是 1 或$x$。 

限制很小：$n \le 300$每个查询和$t \le 25$。 这排除了对大量优化或高级数据结构的任何需要。 我们有能力进行排序、成对检查，​​甚至$O(n^2)$无需担心每个候选人的验证。 

对称性产生了一个微妙的问题。 天真的尝试可能会假设将最小值和最大值相乘给出$x$。 当除数结构不一致或不完整时，此操作会失败。 另一种失败情况是重复或缺失互补除数破坏了预期的配对。 

例如，如果输入是：```
3
2 3 4
```粗心的重建可能会猜测$x = 12$，但 12 有约数 {2, 3, 4, 6}，因此该列表不完整且不一致。 

另一种边缘情况是仅给出一个除数时：```
1
2
```这表明$x$可能是 4，因为它唯一的非平凡除数是 2。 

## 方法

 蛮力的想法是尝试所有可能的候选者$x$。 由于所有给定的数字必须整除$x$，自然上限$x$是列表中最小和最大元素的乘积，甚至是它们的 LCM 结构。 一个幼稚的策略是枚举所有候选者$10^6$并检查它们的除数集是否与删除 1 后的输入匹配$x$。 这很快就变得不可行，因为为每个候选生成除数的成本$O(\sqrt{x})$，并且在许多候选人身上重复，会导致最坏情况下的成本远远超出限制。 

关键的观察是完整的除数集$x$必须由对组成$(d, x/d)$。 由于我们给出了除端点之外的所有除数，因此我们可以重构$x$通过配对最小和最大的元素并检查一致性。 如果列表正确，则最小的除数必须与最大的除数配对，第二小的除数必须与第二大的除数配对，依此类推，所有除数都产生相同的乘积$x$。 

这将问题简化为排序和验证单个候选值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(10^6 \sqrt{x})$|$O(1)$| 太慢了 |
 | 配对检查 |$O(n \log n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对给定的除数列表进行排序。 需要排序，以便我们能够可靠地将最小与最大匹配。 
2. 计算候选值$x$作为最小和最大元素的乘积。 
3. 对于每个索引$i$，验证$d[i] \cdot d[n-1-i] = x$。 
4. 如果任何对不满足此条件，则列表不能来自有效数字，因此输出 -1。 
5. 如果所有对都匹配，则输出$x$。 

配对检查是中心约束：下面的每个除数$\sqrt{x}$必须对应于上面的唯一补码$\sqrt{x}$，并且它们的乘积必须等于$x$。 

### 为什么它有效

 任何整数的除数集对于乘法都是对称的$x$。 排序将这种对称性暴露为镜像位置。 如果输入正确，每个最小元素必须与产生相同产品的最大元素唯一配对$x$。 任何偏差都会破坏除数闭包属性，这意味着没有整数可以生成列表。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        d = list(map(int, input().split()))
        d.sort()

        x = d[0] * d[-1]

        ok = True
        for i in range(n // 2):
            if d[i] * d[n - 1 - i] != x:
                ok = False
                break

        if ok:
            print(x)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先对除数列表进行排序，以便补码对称对齐。 候选人$x$从最外面的对导出，因为有效的除数集必须满足$d_1 \cdot d_k = x$。 

然后循环验证每个镜像对的不变量。 一旦检测到不一致，提前退出可以防止不必要的计算。 

一个常见的陷阱是忘记每一对都必须产生相同的产品，而不仅仅是第一个和最后一个。 另一种方法是假设因式分解的唯一性，而不检查所有对之间的一致性。

 ## 边缘情况

 一个棘手的边缘情况是当配对结构中所有除数都相等但全局一致性失败时。 例如：```
3
2 3 4
```排序给出`2, 3, 4`，产生候选者$x = 8$。 配对检查立即失败，因为$3 \cdot 3 \neq 8$。 算法正确地拒绝了它。 

另一种情况是最小输入：```
1
k
```这里算法处理$x = k^2$，因为唯一的除数必须与其自身配对。 这符合列表排除 1 和$x$，在退化情况下留下一个内除数。
