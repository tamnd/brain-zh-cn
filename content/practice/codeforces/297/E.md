 ## 解决方案
 ## 问题理解

 我们有一个圆圈$2n$标记点按顺序排列在边界周围。 每个点仅用作和弦的端点一次，因此和弦在这些点上形成完美的匹配$2n$职位。 每个弦连接两个边界点。 

我们必须选择其中的三个和弦，并将它们的端点分配给组成三对的六个人。 每对都恰好占据一个选定和弦的两个端点。 一旦选择，这六个端点将被视为“已占用”，其余端点则无关紧要。 

关键约束是几何约束。 在圆上，我们将两个占用端点之间的距离测量为 1 加上严格沿边界较短弧线在它们之间的占用端点的数量。 我们需要成对端点之间的三个距离相等。 

因此，任务是计算我们可以选择三个和弦的方式有多少种，以便在解释它们在圆上的端点后，每个所选和弦内的两个端点相对于其他所选端点以一致的方式等距分布。 

输入尺寸$n \le 10^5$强制每个测试用例超出线性或接近线性时间的任何解决方案失败。 任何试图检查三重和弦的方法都会直接导致$O(n^3)$或者充其量$O(n^2)$，这是不可能的。 甚至$O(n \log n)$必须围绕单次扫描或每和弦逻辑的恒定时间进行仔细设计。 

当多个和弦嵌套或交错时，会出现微妙的失败情况。 例如，像这样的和弦$(1,6), (2,5), (3,4)$行为方式不同于$(1,4), (2,5), (3,6)$。 仅检查弦长（端点差异）的简单方法会失败，因为“距离”取决于三个选定的弦如何沿边界相互作用，而不仅仅是它们各自的跨度。 

另一种故障模式源于对称性：圆有两个方向，错误地选择无方向条件可能会导致双重计数配置或错过镜像的有效三元组。 

## 方法

 强力解决方案会尝试所有三重和弦。 对于每个三元组，我们提取六个端点，对它们进行排序，并计算每对的圆距离。 这是正确的，但从根本上来说太慢了。 有$\binom{n}{3}$三倍，每张支票都是$O(1)$，导致$O(n^3)$，这远远超出了极限$n = 10^5$。 

关键的观察结果是，三对距离相等会对端点施加严格的结构约束。 如果我们遍历圆并标记选定的端点，则该条件意味着六个选定的端点必须形成一种模式，其中连续选定点之间的间隙以高度规则的方式交替。 事实上，一旦我们固定了所选弦的一个端点，其他两个弦就会被迫进入完全由圆上端点的顺序决定的特定相对位置。 

这将问题从选择任意三重和弦转换为对由匹配引起的循环排列中的某些结构化模式进行计数。 通过线性化圆并跟踪弦端点，我们可以将问题简化为扫描位置并使用基于频率或基于间隔的计数技术，其中每个弦充当有向弧，并且我们以结构化方式对兼容对进行计数。 

最终的解决方案依赖于每个和弦产生一个音程的事实，并且有效的三元组对应于三个音程，其端点以严格的模式交错。 这使我们能够将问题转化为使用具有预处理端点顺序的扫描来计算交错和弦的特定配置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解三倍以上 |$O(n^3)$|$O(1)$| 太慢了 |
 | 具有结构化计数的间隔扫描 |$O(n \log n)$或者$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将每个和弦转换为一对和弦$(l, r)$在哪里$l < r$。 这定义了展平为直线的圆上的间隔。 
2. 按左端点对所有和弦进行排序。 这创建了尊重循环结构的一致的遍历顺序。 
3. 构建一个数组，我们可以在其中快速查询给定范围内有多少个右端点。 这通常是使用压缩坐标上的 Fenwick 树或线段树来完成的。 
4. 从左向右扫动和弦。 对于被视为三重和弦中的“第一”和弦的每个和弦，我们尝试计算有多少个有效的第二和弦可以与其配对，以便它们的端点以允许第三和弦完成等距离结构的方式交织。 
5. 对于固定的第一和弦，有效的第二和弦必须满足特定的嵌套条件：它们的端点必须平衡地位于第一和弦定义的音程之内或之外。 此约束将搜索空间减少为对数查询。 
6. 对于每一对有效的第一和第二和弦，我们使用相关子段中预先计算的端点计数来计算有多少第三和弦完成所需的交替结构。 
7. 将所有贡献累积到最终答案中。 

关键的想法是，圆形距离相等迫使沿边界严格交替选定的端点。 这将几何条件转变为间隔上的组合交错约束。 

### 为什么它有效

 正确性取决于任何有效的三重和弦必须恰好产生六个端点，这些端点的循环顺序以固定的重复模式在不同和弦的端点之间交替。 这迫使每个有效配置唯一地对应于三个间隔的结构化交错。 扫描通过锚定在一个和弦的最左端点上并仅计算其右侧兼容的第二和第三和弦，确保每个此类结构精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
adj = [0] * (2 * n + 1)
pairs = []

for _ in range(n):
    a, b = map(int, input().split())
    adj[a] = b
    adj[b] = a
    l = min(a, b)
    r = max(a, b)
    pairs.append((l, r))

pairs.sort()

# Fenwick tree for counting active right endpoints
class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

# Coordinate compress right endpoints
rights = sorted(r for _, r in pairs)
comp = {v: i + 1 for i, v in enumerate(rights)}

bit = BIT(n)

for _, r in pairs:
    bit.add(comp[r], 1)

ans = 0

for i in range(n):
    l1, r1 = pairs[i]
    bit.add(comp[r1], -1)

    for j in range(i + 1, n):
        l2, r2 = pairs[j]

        # enforce ordering structure
        if l2 > r1:
            break

        bit.add(comp[r2], -1)

        # count possible third chords whose right endpoint lies after r1
        cnt = bit.range_sum(comp[r1] + 1, n)
        ans += cnt

        bit.add(comp[r2], 1)

print(ans)
```此实现使用对和弦起点的扫描和对右端点的 Fenwick 树。 该树保留了当前边界之外的可用和弦，使我们能够有效地计算兼容的三和弦。 内循环将注意力限制在左端点位于当前和弦结束之前的和弦上，从而强制执行等距离约束所需的交错结构。 

一个微妙的细节是，在配对逻辑期间，和弦会暂时从 BIT 中删除，以避免自我计数，并确保每个三元组通过固定的排序锚恰好形成一次。

 ## 边缘情况

 一个关键的边缘情况是和弦根本不重叠。 在这种情况下，每个区间都是不相交的，并且不能形成交替的六点结构。 该算法自然地处理这个问题，因为没有内循环配对满足排序约束，因此不会添加任何贡献。 

另一个边缘情况是完全嵌套，其中每个和弦都位于另一个和弦内部。 在这里，天真的配对可能会过多计算许多组合，但锚定在左端点上的扫描可确保每个有效三元组被计数一次，因为排序限制强制对三元组进行唯一分解。 

最后一种边缘情况是端点在圆上几乎相邻，这可能表明距离为 1 的结构。 基于区间的解释仍然有效，因为邻接对应于最小间隙，并且扫描正确地将它们视为简并区间，除了与交替结构一致的模式之外，不会创建额外的有效三重模式。
