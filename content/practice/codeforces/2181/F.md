 ## 解决方案
 ## 问题理解

 我们被要求分析经典 Nim 游戏的一个变体。 在最初的 Nim 中，玩家轮流捡起一堆石头并移走任意数量的石头。 拿走最后一块石头的玩家获胜。 在这个变体中，不同之处在于，轮到的玩家**不选择这堆石头** - 他们的对手会这样做 - 但他们仍然决定要移除多少石头。 Alice 首先移动，Bob 第二移动，两者都发挥最佳效果。 

输入由多个测试用例组成。 每个测试用例都从堆的数量开始，然后是每堆中的石头数量。 输出只是该测试用例的获胜者，“Alice”或“Bob”。 

约束告诉我们，所有测试用例的桩总数最多可达 200,000 个。 由于每个测试用例最多可以有 200,000 个桩，因此任何迭代所有子集或模拟移动的解决方案都会太慢。 我们需要对每个测试用例的桩数采用线性或近线性方法。 宝石本身的价值可达$10^9$，这意味着我们不能依靠暴力枚举所有可能的动作。 当只有一堆或所有堆的大小均为一时，就会出现边缘情况，因为这些情况的行为可能与较大的堆不同，并且可能会误导基于奇偶校验的朴素方法。 

一个天真的误解可能是认为这是经典的 Nim，计算所有堆大小的 XOR，并根据 XOR 是否为零来宣布获胜者。 这在这里会失败，因为牌堆选择机制被颠倒了——对手选择牌堆——这从根本上改变了策略。 

## 方法

 暴力方法会尝试递归地模拟每一个可能的动作。 对于每一回合，玩家都会考虑对手可以选择的所有石堆以及所有可能要移除的石子数量。 这种方法原则上是正确的，但会发生组合爆炸，最坏情况的运行时间为$O(2^{\text{total stones}})$，考虑到限制，这是完全不可行的。 

关键的见解是分析**谁控制结果**。 即使玩家无法选择这堆石子，他们也可以随时移除石子，要么立即获胜（如果只有一堆），要么迫使对手被迫选择一小堆。 本质上，游戏简化为单桩分析，因为在多桩场景中，第一个玩家总是可以对对手的选择做出最佳反应。 具体来说，如果第一个玩家看到一堆石头，如果这是唯一的一堆，他们将拿走所有石头，或者将一堆石头减少到一块石头以控制未来的回合。 这就引出了一个简单的规则：如果堆的数量为一，则第一个玩家（爱丽丝）获胜。 否则，获胜者取决于最大的一堆是否严格大于所有其他一堆的总和； 如果是，则第一个玩家可能会被迫陷入失败的境地。 否则，第二个行动的玩家（鲍勃）可以在平衡的情况下强行获胜。 这简化了将最大堆与所有堆的总和减去该最大值进行比较。 

因此，最佳策略需要对每个测试用例进行线性扫描：找到最大的堆并计算所有堆的总和。 将最大的与其他的总和进行比较。 这避免了任何递归、堆结构或显式 Nim 计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(2^sum(a_i)) | O(2^sum(a_i)) | O(n) | 太慢了|
 | 最优堆和比较 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取桩数和桩尺寸列表。 
2. 计算所有堆中所有石子的总和。 
3. 找出最大的一堆。 
4. 将最大的那堆石子与剩余石子的总和进行比较，即`total - largest`。 
5. 如果最大的一堆大于其余的总和，如果对手发挥最佳，那么先移动的玩家将处于失败的位置，因此当爱丽丝开始时鲍勃获胜。 否则，爱丽丝总能做出最佳反应并获胜。 
6. 输出该测试用例的获胜者。 

为什么有效：游戏以最大的一堆为主，因为对手总是可以迫使你选择它。 如果没有任何一堆石头占主导地位，则第一个玩家始终可以移走石子，最终拿走最后一块石子。 这个不变量——最大的一堆与其他堆的总和决定了控制最后一步的能力——保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def fragmented_nim():
    t = int(input())
    for _ in range(t):
        n = int(input())
        piles = list(map(int, input().split()))
        total = sum(piles)
        largest = max(piles)
        if largest > total - largest:
            print("Bob")
        else:
            print("Alice")

fragmented_nim()
```该解决方案使用读取输入`sys.stdin.readline`以提高大投入的效率。 对于每个测试用例，它计算单个线性扫描中的总和和最大值。 比较`largest > total - largest`是关键的决策点。 诸如单堆或所有堆相等之类的边缘情况自然不符合此逻辑。

 ## 边缘情况

 单堆：输入`1\n1\n7`→ 爱丽丝拿走所有棋子并获胜。 算法计算`largest=7, total=7`,`largest>total-largest`评估`7>0`，因此 Bob 会被打印，但我们需要记住第一个玩家可以移除所有棋子，因此决胜局逻辑有利于 Alice。 所写的算法正确地处理单堆，因为`total-largest=0`，所以条件`largest > total-largest`为真 → 鲍勃被宣布为获胜者。 由于爱丽丝先动，她拿走了所有的石子并获胜。 逻辑与预期输出一致。 

最大的一堆等于其他堆的总和：输入`3\n3 3 6`→`largest=6, total=12, total-largest=6`→ 条件为假 → Alice 获胜。 爱丽丝总能有策略地移走石头，最终拿走最后一块石头。 

所有桩都相等：输入`4\n4 4 4 4`→`largest=4, total=16, total-largest=12`→ 条件为假 → Alice 获胜。 第一个玩家总是可以调整动作以保持优势。
