 ## 解决方案
 ## 问题理解

 每轮都会在循环的每个位置产生一个整数选择。 选择数字后，我们会查看循环上的每个相邻对，并在左端点严格大于右端点时向两个端点奖励一分。 在多轮中，连续顶点之间的每条边都会贡献一定次数，并且每次这样的贡献都会增加其两个端点的分数。 

从最终数据中，我们只得到每个顶点累积的总分。 任务是重建所需的最小轮数，以便存在一系列有效轮次恰好产生这些总数。 

这些约束迫使$O(n)$或者$O(n \log n)$每个测试用例的解决方案。 总和$n$跨测试是$5 \cdot 10^5$，因此在一次测试中任何二次解都是不可能的。 甚至$O(n \log n)$只有非常干净才可以接受； 每个测试用例的预期解决方案都是线性的。 

一种简单的方法是尝试模拟回合或贪婪地构建回合。 这很快就会失败，因为有效轮次的空间是指数级的：每一轮对应于选择值的排列，从而隐式地选择循环上一致的方向模式。 如果没有全局一致性检查，任何显式构建轮次或贪婪地分配每条边的尝试都将导致计数过多或违反可行性。 

当尝试独立处理每个边缘时，会出现第二个微妙的陷阱。 例如，在 4 周期中，如果我们尝试独立分配贡献，就好像每轮可以任意调度每条边一样，我们可能会生成一个配置，其中每条边都需要在同一轮中做出贡献。 这将迫使所有比较都围绕周期严格下降，这是不可能的。 

核心困难在于边不是独立的：每一轮都对应一个全局一致的排序，这禁止在该轮中同时选择所有边。 

## 方法

 暴力视图是将每一轮想象为选择循环边缘的子集，其中“左大于右”成立，然后将每个所需的边缘贡献分配给某一轮。 如果我们尝试一轮一轮地构建回合，我们将反复选择循环的有效方向并减去贡献。 这是正确的，但不可行，因为可能的方向数量是指数级的，决定如何在它们之间分配剩余需求就变成了组合。 

关键的结构观察是首先停止考虑轮数，而是计算每条边被使用的次数。 让$c_i$是其中边的轮数$i \to i+1$贡献一分。 然后每个顶点分数干净地分解为$$a_i = c_{i-1} + c_i.$$这将问题转化为寻找非负整数赋值$c_i$满足循环上的线性系统的边。 

一旦这样的序列$c$是固定的，我们将回合重新解释为将每条边的贡献分配到时隙中。 每轮对应于在边缘上选择 0/1 模式，其中 1 表示该轮中使用该边缘。 唯一的限制是，在有效的一轮中，我们不能同时将所有边设置为 1，因为这意味着严格的不平等循环。 

所以问题就变成了：分别拆分$c_i$进入$R$层，使得每一层至少有一个零。 这相当于说每轮最多使用$n-1$边缘，给出全局约束$$\sum c_i \le R(n-1).$$对于任意固定可行的$c$，所需的最小轮数为$$R = \max\left(\max_i c_i,\ \left\lceil \frac{\sum c_i}{n-1} \right\rceil \right).$$剩下的任务是了解哪些$c$分配是可能的。 从$a_i = c_{i-1} + c_i$，我们可以表达所有$c_i$就单个变量而言，比如说$c_1 = x$。 这使得所有约束都是线性的，给出了可行的区间$x$。 既然两者$\max c_i$和$\sum c_i$是分段线性的$x$，最优值出现在该区间的边界点或某个约束变得严格的点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解回合 | 指数| O(n) | 太慢了|
 | 边数减少+线性约束| 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先将顶点分数转换为边贡献。 

1.修复$c_1 = x$。 这个单一的值决定了所有其他值$c_i$通过重复$c_i = a_i - c_{i-1}$。 递归交替符号，因此每个$c_i$变为线性函数$x$。 
2. 计算所有$c_i$象征性地作为$c_i = s_i \cdot x + b_i$， 在哪里$s_i \in \{+1,-1\}$。 这种分离隔离了系统中唯一的自由度。 
3. 执行可行性$c_i \ge 0$为所有人$i$。 每个不等式要么成为下界，要么成为上限$x$，产生单个区间$[L, R]$。 该区间包含分数到边缘贡献的所有有效分解。 
4. 对于任何有效的$x$, 计算$\max c_i$和$\sum c_i$。 这些是区间上的线性或分段线性函数，因此我们只需要在关键点而不是连续地评估它们。 
5. 计算每个候选人所需的轮数$x$使用：$$R(x) = \max\left(\max_i c_i(x),\ \left\lceil \frac{\sum c_i(x)}{n-1} \right\rceil \right).$$6. 评估$R(x)$在可行区间的所有端点以及最大最大值的任何附加点$c_i$改变主导地位。 这些候选人的最低限度就是答案。 

### 为什么它有效

 到边变量的变换消除了顶点约束中的循环依赖性并公开了解的一维空间。 每个有效的构造都恰好对应于该区间中的一个点。 轮次的舍入条件很严格，因为每轮最多可以贡献$n-1$边，并且任何实现该界限的调度都可以通过将每一层构造为至少一个缺失边的有效循环排列方向来实现。 这使得界限既必要又充分，因此最小化可行$c$完全解决了原来的问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, a):
    if n == 2:
        # a1 = c1 + c2, a2 = c1 + c2 => all equal, c1=c2=a1/2
        # each round uses at most 1 edge, so answer is c1+c2 = a1
        return a[0]

    # Build alternating representation:
    # c1 = x
    # c2 = a2 - x
    # c3 = a3 - a2 + x
    # c4 = a4 - a3 + a2 - x ...
    s = [0] * n
    b = [0] * n

    s[0] = 1
    b[0] = 0
    s[1] = -1
    b[1] = a[1]

    for i in range(2, n):
        s[i] = -s[i-1]
        b[i] = a[i] - b[i-1]

    # feasibility bounds for x
    L = -10**30
    R = 10**30

    for i in range(n):
        if s[i] == 1:
            L = max(L, -b[i])
        else:
            R = min(R, b[i])

    # candidate x values: endpoints
    candidates = [L, R]

    def evaluate(x):
        mx = 0
        total = 0
        for i in range(n):
            ci = s[i] * x + b[i]
            if ci < 0:
                return None
            mx = max(mx, ci)
            total += ci
        r1 = mx
        r2 = (total + n - 2) // (n - 1)
        return max(r1, r2)

    ans = 10**30
    for x in candidates:
        val = evaluate(x)
        if val is not None:
            ans = min(ans, val)

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(solve_case(n, a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案首先将边缘贡献编码为锚定在单个自由参数上的线性递归。 这消除了循环依赖性并将搜索空间减少到有效值的区间。 该参数的可行性通过非负性导出的线性界限进行检查。 

一旦确定了有效的边分解，就可以使用两个独立的约束来计算轮数：任何边上的最大负载和每轮最多可以承载的全局容量约束$n-1$边缘。 

一个微妙的点是只需要检查可行区间的端点。 在区间内，最大边缘载荷和总和都呈线性或分段线性，并且它们的组合不能产生比边界处严格更好的值。 

## 工作示例

 考虑一个小循环，其中$n = 4$分数是：

 | 我| 一个[我] |
 | ---| ---|
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 4 |
 | 4 | 3 |

 我们根据以下方式计算边缘变量$x = c_1$。 

| 我| c[i] 表达式 |
 | ---| ---|
 | 1 | x|
 | 2 | 2-x|
 | 3 | 4 - 2 + x = x + 2 |
 | 4 | 3 - 4 + 2 - x = 1 - x |

 可行性要求所有表达式非负，给出$x \in [0,1]$。 

评估终点：

 在$x = 0$:$c = [0,2,2,1]$，总和 = 5，最大值 = 2，轮数 = max(2, ceil(5/3)) = 2。 

在$x = 1$:$c = [1,1,3,0]$，总和 = 5，最大值 = 3，轮数 = 3。 

所以答案是 2，在较低端点达到。 这表明最小化最大边缘负载可以主导平衡总和约束。

 ## 边缘情况

 当$n = 2$，循环退化为每轮使用两次的单边。 递归崩溃，解决方案简化为直接将两个顶点解释为相同的边数，因此答案等于共享值适当除以边贡献结构。 

当所有$a_i$相等时，交替循环会产生以单个可行配置为中心的对称区间。 任何不平衡都会增加最大边缘负载或总和要求，因此最佳位置是完美平衡的分配。 

当值急剧交替时，可行性区间会变紧，并且在强制执行非负性后只有一个端点保持有效。 这直接说明了为什么边界评估是足够的：内部点违反局部边缘约束或增加瓶颈边缘负载。
