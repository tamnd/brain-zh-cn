 ## 解决方案
 ## 问题理解

 棋盘是一个无向简单图。 移动不会删除顶点，而是删除边，并且下一个移动必须使用与紧邻其之前删除的边共享端点的边。 一条边只能使用一次，因为它在被选择后就会消失。 

重新解释游戏的一个有用方法是暂时忘记原始顶点。 创建一个新图，其顶点是原始边。 当对应的原始边共享端点时，准确连接两个新顶点。 这是原始图的**折线图**。 现在的游戏如下：第一个玩家选择线图的任何顶点，随后的每次移动都选择一个未使用的相邻顶点。 这是地理学的无向顶点版本。 如果第一个玩家能够选择初始顶点，那么第一个玩家就会获胜，这样最佳的游戏最终会让第二个玩家无法移动。 该游戏的匹配特征表明，当折线图具有完美匹配时，第二个玩家将从每个可能的起始顶点获胜。 

输入最多包含 (10^4) 个原始顶点和 (10^4) 个原始边。 官方限制为 2 秒和 512 MB。 直接构造线图已经很可疑，因为原始图中的单个高度顶点会创建一个包含其所有关联边的团。 对于 (10^4) 条边，该团可以包含近 (10^4) 个顶点和大约 (5\cdot10^7) 个邻接对。 更重要的是，暴力游戏搜索是指数级的或更差，因此预期的解决方案必须利用线图的结构而不是枚举游戏状态。 

有几种边缘情况暴露了常见的错误解释。 首先，**总**边数的奇偶性不够。 考虑```
4 2
1 2
3 4
```边总数为 2，但每个连通分量包含一条边。 两条边不相邻，因此第一个玩家选择其中一个后，第二个玩家就无法移动。 答案是`YES`。 仅检查解决方案`m % 2`会错误打印`NO`。 

其次，孤立的顶点没有影响。 为了```
4 1
1 2
```顶点 3 和 4 不能参与任何移动。 唯一的边形成折线图中的单顶点分量，因此 Arthur 立即获胜，答案是`YES`。 计算顶点而不是边，或者要求每个原始顶点都属于一个重要组件，会给出错误的结果。 

第三，具有偶数条边的连通分量会给出相反的结果。 为了```
4 3
1 2
1 3
1 4
```原来的3条边都是互相相邻的，所以折线图是(K_3)。 亚瑟选择一条边，他的对手选择另一条边，亚瑟选择最后一条，所以亚瑟获胜。 答案是`YES`。 仅基于每个连接组件都是连接这一事实的粗心论证会错过其边计数的奇偶校验。 

## 方法

 暴力方法是将当前已擦除的边和已擦除的边的集合视为完整的游戏状态。 对于每条合法的下一条边，递归地确定对手是否可以获胜，如果至少有一步导致对手失败，则宣布当前状态获胜。 这是正确的，因为游戏是有限的并且考虑了所有可能的延续。 

问题是连续的数量。 取一颗具有 (m) 边的原始星形。 星形的每两条边都有一个中心，所以它的线图是（K_m）。 选择第一条边后，任何剩余的边都是合法的，然后是之后的任何剩余边，依此类推。 因此，递归可以检查 (m!) 个不同播放序列的顺序。 当 (m) 接近 (10^4) 时，这是完全不可行的。 即使记忆化也不能使一般状态空间变得实用，因为状态本质上是已用边和当前边的子集，给出了 (O(m2^m)) 种可能的状态。 

关键的观察结果是，这个特定的无向游戏具有匹配的特征。 在无向顶点地理中，完美匹配的图为第二个玩家提供了简单的响应策略。 每当第一个玩家进入一个顶点时，第二个玩家就会以固定的完美匹配移动到其伙伴处。 相反，如果最大匹配留下一些未匹配的顶点，则第一个玩家可以从那里开始并使用匹配的边作为响应策略。 如果该策略由于在错误的时间到达不匹配的顶点而失败，则交替路径将是一条增广路径，与匹配的最大值相矛盾。 这就是无向顶点地理的标准匹配表征。 

我们的第一个玩家可以自由选择起始顶点。 因此，当第一个玩家具有完美匹配时，折线图就会输掉。 因此，我们只需要确定给定图的线图是否具有完美匹配。 

还有另一个结构简化。 考虑包含 (k) 条边的原始图的一个连通分量。 它的线图是连通的并且恰好有 (k) 个顶点。 具有偶数个顶点的连通线图始终具有完美匹配。 同样，具有偶数条边的每个连通图的边可以分成对，使得每对中的两条边共享一个顶点。 这是折线图的标准属性。 

反之亦然，因为完美匹配只能存在于具有偶数个顶点的图中。 因此，当原始图的连通分量的原始边数为偶数时，它会准确地生成线图的完美匹配分量。 

因此，整个游戏简化为一个非常简单的条件：当**原始图的每个连通分量包含偶数条边**时，亚瑟就输了。 如果至少一个连通分量具有奇数条边，则其线图分量具有奇数大小并且没有完美匹配，从而为 Arthur 提供了获胜的起始边。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | （O（米！））| (O(m)) 递归深度 | 太慢了|
 | 最佳 | (O(n+m)) | (O(n)) | (O(n)) | 已接受 |

 最优算法不需要构造线图，也不需要知道擦除边的实际获胜顺序。 它只需要每个连通分量中边数的奇偶性。 

## 算法演练

1. 使用不相交集并集结构构建原始图的连通分量。 对于每个输入边 ((u,v))，将 (u) 和 (v) 合并。 组件结构所需的唯一信息是哪个组件包含每条边。 
2. 所有合并完成后，再次扫描原始边缘。 对于边 ((u,v))，找到 (u) 的代表，它也是 (v) 的代表，并增加该分量的边计数。 在所有并集之后计算边可以避免对输入边出现顺序的任何依赖。 
3. 检查至少包含一条边的每个组件。 如果它的边数是奇数，则打印`YES`。 这样的组件会生成具有奇数个顶点的线图组件，因此该组件无法完美匹配。 亚瑟可以从中获得优势并拥有制胜策略。 
4. 如果每个非空组件都有偶数条边，则打印`NO`。 每个对应的线图组件都有偶数个顶点，因此具有完美匹配。 这些完美匹配的不相交联合是整个线图的完美匹配，因此第二个玩家可以使用匹配策略回答每个初始选择。 

### 为什么它有效

 中心不变量是原始图的连通分量与折线图的连通分量之间的对应关系。 当两条原始边属于同一连接组件时，它们可以通过一系列相邻的原始边精确地连接，因此游戏移动不能从一个原始组件跨越到另一个原始组件。 

在具有 (k) 条边的一个连通分量内，折线图具有 (k) 个顶点。 如果 (k) 是奇数，则它不能具有完美匹配，因此该组件上的自由启动无向地理游戏将为第一个玩家获胜。 如果(k)是偶数，则折线图具有完美匹配，因此第二个玩家总是可以沿着匹配边缘进行回复。 当每个非空原始组件具有偶数边数时，全局折线图具有完美匹配。 因此算法打印`YES`就在亚瑟有一个获胜的部分开始的时候。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    parent = list(range(n))
    size = [1] * n
    edges = []

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return

        if size[a] < size[b]:
            a, b = b, a

        parent[b] = a
        size[a] += size[b]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        union(u, v)

    edge_count = [0] * n

    for u, _ in edges:
        root = find(u)
        edge_count[root] += 1

    for v in range(n):
        if edge_count[v] % 2 == 1:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```第一个循环存储每条边并将其端点连接到 DSU 中。 路径压缩在`find`并按组件大小并集使总 DSU 对于这些约束有效地呈线性工作。 

第二个循环按最终组件代表对边进行计数。 使用第一个端点就足够了，因为每条边都已经联合，因此两个端点都属于同一个 DSU 组件。 我们特意在所有并集之后执行此计数。 如果在读取输入时完成，则最初可以将边缘分配给代表，然后将其合并到另一个组件中。 

最后的循环仅在具有非零计数的 DSU 代表处检查奇偶校验。 非代表的计数为零，因为每条边都是使用其最终代表来分配的。 孤立的顶点的计数也为零，这正确地使它们与游戏无关。 

Python 中不存在整数溢出问题，并且最大可能的组件数仅为 (10^4)。 索引立即从问题的从 1 开始的顶点转换为从 0 开始的 Python 数组，因此 DSU 正好有 (n) 个元素。

 ## 边缘情况

 对于断开连接的情况```
4 2
1 2
3 4
```DSU 生产两种组件。 第一个包含一条边，第二个也包含一条边，因此它们的计数为`1`和`1`。 该算法立即遇到奇数计数并打印`YES`。 这正是仅检查奇偶校验的情况`m`失败，因为 (1+1=2) 是偶数，而两个分量在其折线图中都没有完美匹配。 

对于孤立的顶点，考虑```
4 1
1 2
```DSU 创建一个组件，其中包含具有一条边的顶点 1 和 2，而顶点 3 和 4 保持隔离且边数为零。 非零分量具有奇数大小，因此算法打印`YES`。 零边缘分量并不重要，因为没有边缘可供选择，因此没有与它们相关的游戏位置。 

对于奇怪的明星```
4 3
1 2
1 3
1 4
```所有三个边都在一个组件中，因此边数为 3。折线图为 (K_3)。 亚瑟可以先擦除任何一条边，他的对手可以擦除剩余两条边中的一条，然后亚瑟擦除最后一条。 算法打印`YES`无需构造那个三角形。 

对于偶数明星```
5 4
1 2
1 3
1 4
1 5
```该组件包含四个边，并且每对边都是相邻的。 线图为(K_4)，其完美匹配可以将四个顶点配对成两对。 第二个玩家总是可以用其匹配的伙伴回答第一个玩家选择的边，因此 Arthur 输了并且算法打印`NO`。 

最危险的实施错误是在 DSU 完成合并组件之前对边缘进行计数。 例如，```
4 2
1 2
2 3
```首先将 1 与 2 连接，然后将 2 与 3 连接。两条边最终都属于一个分量，其计数为 2，所以答案是`NO`。 在输入处理期间对过时的代表进行计数可能会将临时组件 ID 之间的这两个边缘分开并产生错误的奇偶校验。 该解决方案通过存储边并仅在所有并集完成后对它们进行计数来避免这种情况。 

最终的边界情况是具有 (10^4) 个顶点和 (10^4) 个边的图。 从路径中获得连通结构```
1-2-3-...-10000
```有一个额外的边缘`1 3`。 它正好有 10000 条边，全部在一个连通分量中，因此分量奇偶校验是偶数，答案是`NO`。 DSU 使用与小图相同的线性结构处理整个实例，这就是解决方案在上限保持快速的原因。
