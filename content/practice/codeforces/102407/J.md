## 算法演练

 1. Создадим таблицу`dp`, 哥德`dp[a, b]`означает минимальное число ходов из состояния с числами`a`и`b`, предполагая`a <= b`。 Для всех состояний`(x, x)`сразу положим`dp[x, x] = 0`， потому что они уже являются конечными。 
2. Будем рассматривать пары в порядке возрастания разницы`d = b - a`。 Сначала обрабатываются пары с разницей`1`, затем с разницей`2`, и так далее до`1999`。 

Это правильный порядок, потому что любой полезный переход из пары с разными числами уменьшает разницу. Значит, когда мы считаем`dp[a][b]`， ответы всех возможных следующих состояний уже вычислены。 
3. Для текущих`a`и`b`вычислим геометрическое среднее с округлением вверх。 Сначала берём`r = isqrt(a*b)`。 埃斯利`r² < a*b`, 尤夫利奇瓦姆`r`на один。 Получаем точное значение`g = ceil(sqrt(a*b))`。 
4. Вычислим квадратичное среднее с округлением вниз как`q = isqrt((a² + b²) // 2)`。 

Здесь целочисленное деление внутри`isqrt`безопасно。 Для целого`S`выполняется`floor(sqrt(S / 2)) = floor(sqrt(floor(S / 2)))`。 
5. Рассмотрим четыре возможных изменения。 Если заменить`a`娜`g`, получим`(g, b)`。 Если заменить`b`娜`g`, получим`(a, g)`。 安那洛赫尼奇诺、 克瓦德拉提奇尼诺和 斯雷德尼埃 日`(q, b)`и`(a, q)`。 

Переход, который не меняет пару, пропускаем。 Например, для`(1, 2)`埃米姆`q = 1`, 和 замена первого числа на`q`奥斯塔夫利亚埃特`(1, 2)`без изменений。 
6. Среди всех полезных переходов возьмём минимальное значение`dp`следующего состояния и прибавим один ход。 Это и есть`dp[a][b]`。 
7. После обработки всех разностей ответом будет`dp[a][b]`для исходной пары。 

### 为什么它有效

 Инвариант алгоритма состоит в том, что перед вычислением`dp[a][b]`значения всех состояний, достижимых одним полезным ходом из`(a, b)`， уже известны。 Для`a < b`оба математических средних не выходят за пределы`[a, b]`。 Геометрическое среднее после округления вверх строго больше`a`以及其他`b`， если числа различны。 Квадратичное среднее после округления вниз может совпасть с`a`, но тогда замена меньшего числа является самопереходом 和 не может входить в оптимальный путь. Все остальные переходы уменьшают`b-a`。 

Следовательно, любой оптимальный путь из`(a, b)`сначала делает один из рассматриваемых переходов, затем продолжает оптимально из соответствующего меньшего состояния。 Формула динамики перебирает все такие первые ходы и выбирает лучший. Базовый случай`a=b`留言`0`, поэтому индукция по разнице доказывает правильность всех значений`dp`。 

## Python 解决方案```python
import sys
from math import isqrt
from array import array

input = sys.stdin.readline

MAX_N = 2000
SIZE = MAX_N + 1
INF = 65535

def solve(a, b):
    # dp[x * SIZE + y] stores the answer for (x, y).
    # uint16 is enough because the difference is at most 1999.
    dp = array('H', [0]) * (SIZE * SIZE)

    for diff in range(1, SIZE):
        for x in range(1, SIZE - diff):
            y = x + diff
            base = x * SIZE + y

            product = x * y
            g = isqrt(product)
            if g * g < product:
                g += 1

            q = isqrt((x * x + y * y) // 2)

            best = INF

            # Replace x by the geometric mean.
            if g != x:
                best = min(best, dp[g * SIZE + y] + 1)

            # Replace y by the geometric mean.
            if g != y:
                best = min(best, dp[x * SIZE + g] + 1)

            # Replace x by the quadratic mean.
            if q != x:
                best = min(best, dp[q * SIZE + y] + 1)

            # Replace y by the quadratic mean.
            if q != y:
                best = min(best, dp[x * SIZE + q] + 1)

            dp[base] = best

    return dp[a * SIZE + b]

def main():
    a, b = map(int, input().split())
    print(solve(a, b))

if __name__ == "__main__":
    main()

Цикл по`diff`начинается с единицы。 Все состояния с нулевой разницей уже имеют значение`0`， поскольку их числа равны。 Внутренний цикл перебирает все`x`, для которых`y = x + diff`не превышает`2000`。 

Для геометрического среднего нельзя просто взять`isqrt(product)`和 использовать его как ответ，потому что требуется округление вверх。 普罗夫卡`g * g < product`исправляет именно этот случай。 Если произведение является точным квадратом, корень не увеличивается。 

Для квадратичного среднего используется`(x*x + y*y) // 2`佩雷德`isqrt`。 Все числа здесь очень малы: даже при`x = y = 2000`西玛马·科瓦达拉托夫·拉夫纳`8 000 000`, поэтому переполнения в Python нет вообще. В C++ для таких ограничений также достаточно обычного 32-битного целого, хотя использование 64-битного типа остаётся хорошей привычкой。 

普罗夫基`g != x`,`g != y`,`q != x`и`q != y`нужны именно для исключения операций, которые оставляют состояние неизменным。 Самый показательный пример,`(1, 2)`, где квадратичное среднее равно`1`。 Приэтом переход`2 -> 1`совершенно корректен и даёт`(1, 1)`， поэтому проверять нужно не только само значение среднего， а то， какое число заменяется。

 ## 边缘情况

 Для`(5, 5)`алгоритм вообще не входит в цикл динамики для положительной разницы. Элемент`dp[5 * SIZE + 5]`изначально равен`0`、 поскольку равные пары являются базовыми состояниями。 Ответ для входа`5 5`拉文`0`。 Это защищает от ошибки, при которой программа сначала выполняет бессмысленный ход, хотя условие уже выполнено.

 Для`(1, 2)`杰奥米特·里奇科科耶·斯雷德涅·拉夫诺`ceil(sqrt(2)) = 2`, квадратичное среднее равно`floor(sqrt(5/2)) = 1`。 При обработке пары`(1, 2)`алгоритм рассматривает замену первого числа на`1`как самопереход 和 игнорирует её。 Замена второго числа на`1`при этом остаётся допустимой и даёт`(1, 1)`。 Ещё один вариант, замена первого числа на`2`, 达斯`(2, 2)`。 作品`dp[1][2] = 1`。 

Для`(1, 3)`杰奥米特·里奇科科耶·斯雷德涅·拉夫诺`2`, квадратичное среднее равно`2`, поэтому после первого полезного хода можно получить`(2, 3)`伊利`(1, 2)`。 Оба состояния имеют ответ`1`, поскольку из`(2, 3)`Кеометрическое среднее даёт`3`, а из`(1, 2)`Кеометрическое среднее даёт`2`。 Значит,`dp[1][3] = 2`。 

Для`(1999, 2000)`Кеометрическое среднее с округлением вверх равно`2000`, поскольку`sqrt(1999 * 2000)`梅尼埃`2000`和 больше`1999`。 Замена меньшего числа сразу даёт`(2000, 2000)`, поэтому ответ равен`1`。 Этот случай одновременно проверяет верхнюю границу входа 和 правильность именно потолочного округления。 

Для`(2000, 2000)`разность равна нулю, поэтому никаких вычислений средних не требуется. Таблица уже содержит ответ`0`，以及 возвращает его напрямую。 Это показывает，почему базовые состояния должны быть определены до обработки пар с положительной разницей。
