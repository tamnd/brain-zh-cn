 ## 解决方案
 ## 问题理解

 我们有一个 (n \times n) 网格，小丑位于单元格 ((a,b)) 处。 我们需要计算网格内与小丑的曼哈顿距离恰好为 (d) 的单元格。 

对于单元格 ((x,y))，条件是

 [
 |x-a|+|y-b|=d。 
]

 如果没有网格边界，这些单元格会在 ((a,b)) 周围形成菱形。 菱形有四个对角边，在不受限制的无限网格上，它恰好包含 (4d) 个单元格。 困难在于该钻石的某些部分可能位于 (n \times n) 房间之外。 

输入包含 (n,a,b,d)，其中 (n) 与 (10^{18}) 一样大。 答案本身也可以是 (10^{18}) 阶，因此实现需要能够轻松处理大于 32 位整数的值的整数算术。 Python 整数直接适合于此。 

(n) 的大小排除了对网格的迭代。 即使扫描所有 (n^2) 个单元格，在最大的情况下也需要最多 (10^{36}) 个检查。 与 (d) 成比例的方法也是不可能的，因为 (d) 可以独立达到 (10^{18})。 我们需要恒定的工作量，与 (n) 和 (d) 无关。 

在多种边界情况下，(4d) 等简单公式会失败。 例如，使用输入`5 1 1 2`，无限制菱形有八个单元，但房间内只有三个：((1,3))、((2,2)) 和 ((3,1))。 正确答案是`3`，因此盲目返回 (4d) 会计算房间外的细胞数。 

另一个微妙的例子是钻石角。 为了`3 2 2 1`，距离一的所有四个单元格都在房间内，所以答案是`4`。 如果我们独立计算四个对角边，则每条边都有两个端点，总数为八个。 四个菱形顶点中的每一个都属于两个相邻的边，因此只需将四个边长相加即可对每个顶点进行双重计数并产生`8`而不是`4`。 

当整颗钻石都在房间外面时，就会出现第三种情况。 为了`3 2 2 10`，任何单元格的曼哈顿距中心的距离都不能为 10，因为网格内的最大可能距离为 4。 正确答案是`0`。 任何假设理论钻石至少有一点幸存的解决方案都会在这里失败。 

## 方法

 直接的方法是检查房间的每个单元格 ((x,y)) 并测试是否 (|x-a|+|y-b|=d)。 它是正确的，因为它只检查每个可能的单元一次并直接应用曼哈顿距离的定义。 它最坏情况的运行时间是(O(n^2))，当(n=10^{18})时，它变成(10^{36})个单元格检查。 内存使用量可以保持不变（O(1)），但运行时间使该方法无法使用。 

我们可以通过查看方程的几何形状而不是单个单元格来做得更好。 等式

 [
 |x-a|+|y-b|=d
 ]

 描述了四个对角线段。 他们的端点是

 [
 (a-d,b),\quad (a,b+d),\quad (a+d,b),\quad (a,b-d)。 
]

 例如，从 ((a-d,b)) 到 ((a,b+d)) 的段可以参数化为

 [
 (x,y)=(a-d+k,b+k),\qquad 0\le k\le d。 
]

 每个整数 (k) 恰好给出菱形那一侧的一个网格单元。 其余三边结构相同，坐标变化符号相应调整。 

蛮力方法之所以有效，是因为它独立地考虑所有单元，但它会失败，因为单元太多。 观察到所需的集合仅由四个单调对角线段组成，这让我们可以用四个一维间隔代替巨大的二维搜索。 

对于这样一个段，我们不需要迭代 (k=0,1,\ldots,d)。 我们只需要确定 (k) 的哪些值将两个坐标保留在 ([1,n]) 内。 由于随着 (k) 的增加，每个坐标精确地改变 (+1) 或 (-1)，因此每个坐标限制只是允许的 (k) 值的区间。 将这些间隔相交即可得出恒定时间内线段上有效单元格的准确数量。 

最后还有一个细节。 相邻的菱形线段共享其端点，因此每当顶点本身位于房间内时，对四个剪裁线段求和就会对每个菱形顶点计数两次。 我们为每个这样的顶点减一。 房间外部的顶点无法在房间内部创建副本，因为这两个线段仅在该顶点处相交。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n^2)) | (O(1)) | (O(1)) | 太慢了|
 | 最佳 | (O(1)) | (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 将曼哈顿距离菱形的四个边中的每一个表示为参数化线段。 四个起点是 ((a-d,b))、((a,b+d))、((a+d,b)) 和 ((a,b-d))，每个线段沿四个对角线方向之一恰好移动 (d) 个单位步。 在应用房间边界之前，这恰好覆盖了曼哈顿距离 (d) 处的每个像元。 
2. 对于一个段，引入一个整数参数（k），其中（0\le k\le d）。 它的坐标具有以下形式

 [
 x=x_0+s_xk,\qquad y=y_0+s_yk,
 ]

 其中 (s_x,s_y) 分别为 (1) 或 (-1)。 每个有效整数 (k) 对应于该侧的一个单元格。 
3. 将条件 (1\le x\le n) 转换为 (k) 的区间。 如果(s_x=1)，那么

 [
 1-x_0\le k\le n-x_0。 
]

 如果(s_x=-1)，那么

 [
 x_0-n\le k\le x_0-1。 
]

 对 (y) 坐标执行相同的操作。 将两个坐标区间与原始区间 ([0,d]) 相交。 
4. 如果所得下限为 (L)，上限为 (R)，则当 (L\le R) 时，该段贡献 (R-L+1) 个单元，否则贡献为零。 这可以通过完全相同的计算来处理完全外部的段和部分剪切的段。 
5. 将所有四个部分的贡献相加。 这四个线段覆盖了整个曼哈顿距离菱形，但每个菱形顶点属于两个线段。 
6. 检查四个顶点 ((a-d,b))、((a,b+d))、((a+d,b)) 和 ((a,b-d))。 对于两个坐标位于 ([1,n]) 内部的每个顶点，从总和中减一。 这精确地消除了由两个相邻段创建的重复出现。 

### 为什么它有效

曼哈顿距离 (d) 处的每个像元都正好位于菱形的四个对角边之一上，除了位于两个相邻边上的四个菱形顶点之外。 每一侧的参数化只生成该一侧的每个整数单元一次。 区间交集准确地保留了坐标属于房间的那些生成的单元格。 因此，对四个裁剪段求和会对每个有效单元格计数一次，对每个有效菱形顶点计数两次。 为房间内的每个顶点减去一个可以精确地删除那些重复的计数，从而使每个所需的单元格都被精确地计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def segment_count(x0, y0, sx, sy, d, n):
    lo = 0
    hi = d

    if sx == 1:
        lo = max(lo, 1 - x0)
        hi = min(hi, n - x0)
    else:
        lo = max(lo, x0 - n)
        hi = min(hi, x0 - 1)

    if sy == 1:
        lo = max(lo, 1 - y0)
        hi = min(hi, n - y0)
    else:
        lo = max(lo, y0 - n)
        hi = min(hi, y0 - 1)

    if lo > hi:
        return 0
    return hi - lo + 1

def solve():
    n, a, b, d = map(int, input().split())

    segments = [
        (a - d, b, 1, 1),
        (a, b + d, 1, -1),
        (a + d, b, -1, -1),
        (a, b - d, -1, 1),
    ]

    answer = 0

    for x0, y0, sx, sy in segments:
        answer += segment_count(x0, y0, sx, sy, d, n)

    vertices = [
        (a - d, b),
        (a, b + d),
        (a + d, b),
        (a, b - d),
    ]

    for x, y in vertices:
        if 1 <= x <= n and 1 <= y <= n:
            answer -= 1

    print(answer)

if __name__ == "__main__":
    solve()
```这`segment_count`功能是解决方案的核心。 它从自然参数范围 (0\le k\le d) 开始，代表完整的钻石侧面。 然后，每个坐标根据网格边界缩小该范围。 

对于正方向，例如 (x=x_0+k)，下边界 (x\ge1) 给出 (k\ge1-x_0)，而上边界 (x\le n) 给出 (k\le n-x_0)。 对于负方向 (x=x_0-k)，不等式反转并给出 (k\ge x_0-n) 和 (k\le x_0-1)。 直接处理这些不等式可以避免根据小丑是否靠近房间的特定一侧而出现任何特殊情况。 

四个线段描述使用连续的菱形顶点。 它们的方向对是 ((1,1))、((1,-1))、((-1,-1)) 和 ((-1,1))，因此每条边都被遍历一次。 

顶点减法发生在所有四个段计数计算完毕之后。 仅当顶点本身位于房间内时，才会复制该顶点。 明确检查其坐标比尝试从相邻线段长度推断更安全。 

Python 中不存在溢出问题，因为它的整数具有任意精度。 在固定宽度整数类型的语言中，64 位有符号整数足以用于输入坐标和答案，因为答案不能超过房间中的单元格数量 (10^{36})，实际上距离环上的数字最多为 (4d)，即最多 (4\cdot10^{18})，因此根据语言需要无符号 64 位类型或足够宽的有符号类型。

 ## 边缘情况

 对于`5 1 1 2`，四个理论顶点是 ((-1,1))、((1,3))、((3,1)) 和 ((1,-1))。 只有中间的两个顶点在内部，而它们之间的对角线产生第三个有效点 ((2,2))。 片段裁剪恰好给出了三个单元格，并且在重复校正之前两个内部顶点各计数两次。 最终的答案是`3`。 

为了`3 2 2 1`，四个顶点是 ((1,2))、((2,3))、((3,2)) 和 ((2,1))。 每个段包含两个点，总共八个点。 四个顶点中的每一个都在房间内，因此删除了四个重复出现的顶点。 结果是`4`。 

为了`3 2 2 10`，每个理论顶点都位于房间之外，并且每个线段的允许 (k) 区间在与坐标限制相交后变为空。 所有四个线段贡献均为零，并且没有要减去的顶点。 结果是`0`。
