 ## 解决方案
 ## 问题理解

 我们有一个排序的税表。 每行包含一个马力边界`b_i`和税率`t_i`。 第一个边界始终为零，并且边界严格增加。 对于一辆有动力的车来说`q`，适用的汇率是从最后一个表行开始的汇率，其边界严格小于`q`。 最后还有一种特殊情况：如果`q`大于最大边界，则使用最后的速率。 

间隔的措辞有点不寻常，因此确切的端点很重要。 一行`i`适用于满足以下条件的权力`b_i < q <= b_{i+1}`。 因此，当`q`正好等于边界`b_i`，行的速率`i - 1`适用，而不是行上写的费率`i`。 由于每个查询的功率至少是`1`和`b_1 = 0`，总是有前一行作为精确的正边界。 

对于每个查询的汽车功率`q_j`，我们需要输出`q_j * t`， 在哪里`t`是这些规则选择的速率。 高达`100000`表行和`100000`查询，检查每个查询的每个表行可能需要最多`10^10`比较。 这远远超出了典型的比赛时间限制所能支持的范围。 我们需要利用边界已经严格排序的事实。 

尽管二分搜索实际上并不需要该属性，但比率也是非递减的。 关键属性是边界数组是有序的。 这让我们可以在对数时间中找到相关的间隔。 

有几种边界情况，看似合理的实现可能是错误的。 

考虑单个表行：```
1
0 10
1
100
```车子有电了`100`，大于最大边界。 因此，最后的汇率是`10`，所以答案是`1000`。 仅搜索在下一个边界结束的间隔并忘记最终溢出情况的解决方案可能无法分配任何速率。 

精确边界规则是另一个常见的错误来源：```
2
0 10
100 20
1
100
```正确的输出是：```
1000
```电源`100`不严格大于边界`100`，所以第二行不适用。 第一行适用于以下权力`(0, 100]`, 给予`100 * 10 = 1000`。 使用`bisect_right`直接选择第二行并错误地产生`2000`。 

刚好高于边界的查询必须使用新的速率：```
2
0 10
100 20
1
101
```正确的输出是：```
2020
```这里`101 > 100`，因此适用第二速率。 将上限视为包含错误一侧的实现可能会错误地保持第一个速率。 

最后，同等利率是完全有效的：```

```输出是：```

```即使速率本身从未改变，仍然必须正确搜索表边界。 

## 方法

 直接的解决方案是通过从头开始扫描税表来独立处理每个查询。 为了一个力量`q`，我们寻找至少是的第一个边界`q`。 如果该边界是`b_i`，适用的税率为`t_{i-1}`。 如果不存在这样的边界，则使用最后的速率。 

这种方法是正确的，因为该表描述了连续的间隔。 从最小边界开始向上移动，第一个边界满足`b_i >= q`恰好是包含以下内容的区间的上端点`q`。 因此，前一行提供了正确的速率。 

问题在于重复工作量。 查询可以迫使我们检查所有`n`行，并且这可能发生在每一行上`m`查询。 和`n = m = 100000`，最坏的情况是`100000 * 100000 = 10^10`表检查。 尽管每次扫描都很简单，但数百亿次操作并不实用。 

关键的观察结果是，表中所需的唯一信息是满足以下条件的第一个边界的位置：`b_i >= q`。 因为所有`b_i`严格递增，这正是二分搜索解决的搜索类型。 我们不是检查每一行，而是重复丢弃剩余边界范围的一半。 

蟒蛇的`bisect_left`直接表达所需的搜索。 它返回第一个索引`i`这样`b_i >= q`。 如果该索引存在，则正确率为`t_i`仅当`q`严格大于`b_i`，这不是我们想要的。 更方便的是，我们可以将结果解释为`q`在相等边界之前并使用前一行，即`t[i - 1]`。 如果插入位置为零，则查询将位于第一个边界之前，但这不会发生，因为查询为正且第一个边界为零。 

对于大于每个边界的查询，`bisect_left`回报`n`，所以前一行是`n - 1`，正是最后的速率。 因此，相同的公式可以处理最终间隔，而无需单独的特殊情况。 

暴力方法之所以有效，是因为它显式地发现了包含每个查询的区间，但是当从头开始为每辆车搜索相同的有序表时，它会失败。 通过观察边界已排序，我们可以用一次二分搜索替换每次线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(n) | 太慢了|
 | 二分查找 | O(n + m log n) | O(n + m log n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`表行并将边界存储在一个数组中，并将相应的比率存储在另一个数组中。 输入保证边界数组已经严格递增，因此不需要排序。 
2.对于每辆车的功率`q`， 履行`bisect_left(boundaries, q)`。 这会找到第一个大于或等于的边界`q`。 
3. 令返回的位置为`i`。 正确率是`rates[i - 1]`。 如果`q`正好等于`boundaries[i]`，以该边界结束的区间属于前一行，这正是我们使用的原因`i - 1`。 
4. 如果`q`大于每个边界，`bisect_left`回报`n`。 表达式`rates[i - 1]`然后变成`rates[n - 1]`，根据需要选择最终费率。 
5. 乘法`q`按所选速率并将结果附加到输出。 将所有答案累积起来并打印在一起，避免了不必要的输出操作。 

### 为什么它有效

 对于每个查询`q`， 让`i`是第一个索引`b_i >= q`。 如果存在这样的索引，则每个较早的边界都小于`q`， 所以`q`属于结束于的区间`b_i`。 该间隔被分配行中的速率`i - 1`, 给予`rates[i - 1]`。 如果不存在这样的索引，则每个表边界都小于`q`，因此问题明确指定了最终速率，这也是`rates[n - 1]`因为二分查找返回`n`。 因此，每个查询都准确地收到表中规定的税率，并将该税率乘以幂即可得出所需的税费。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())

    boundaries = [0] * n
    rates = [0] * n

    for i in range(n):
        boundaries[i], rates[i] = map(int, input().split())

    m = int(input())
    answers = []

    for _ in range(m):
        q = int(input())

        i = bisect_left(boundaries, q)
        rate = rates[i - 1]

        answers.append(str(q * rate))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```这两个数组完全按照输入中的显示方式保留表。 我们不需要存储对并对它们进行排序，因为该语句已经保证了边界的增加。`bisect_left`是关键的实施选择。 对于边界数组，例如`[0, 100, 150, 200]`并查询`150`，它返回索引`2`，因为索引`2`包含第一个大于或等于的值`150`。 使用`rates[1]`选择与间隔相关的速率`(100, 150]`，这是完全正确的。 

使用`bisect_right`将是一个相差一的错误。 对于同一个查询`150`，它将返回索引`3`，导致算法选择速率`(150, 200]`， 虽然`150`本身属于前面的区间。 

什么时候`q`大于最终边界，`bisect_left`回报`n`。 访问`rates[n - 1]`那么自然会选择最大速率，所以不需要特殊的分支。 

Python 整数具有任意精度，因此乘以幂和比率可达`10^9`不能溢出。 最大可能的乘积是`10^18`，由 Python 直接处理。

根据问题中规定的区间规则，`(150, 200]`应使用从以下位置开始的行的速率`150`，即`50`。 这意味着正确的二分搜索解释不仅仅是`rates[bisect_left(boundaries, q) - 1]`。 

正确的条件是找到严格小于的最大边界`q`。 那正是`bisect_left(boundaries, q) - 1`仅当`q`不等于边界。 什么时候`q`严格大于边界，则应用该边界的比率。 为了`152`,`bisect_left`回报`4`，因为第一个边界至少`152`是`200`， 和`rates[3]`是`75`，这又与样本发生冲突。 

这更仔细地揭示了实际的区间解释。 该样本确定行上的比率`i`申请的权力严格大于`b_i`且小于或等于`b_{i+1}`。 因此对于`152`， 排`150`给出率`50`，并且对于`170`， 排`150`还给出了率`50`。 

因此，正确的搜索是最大边界`b_i < q`，可以通过以下方式获得`bisect_left(boundaries, q) - 1`。 为了`152`，给出索引`2`，选择率`50`。 

对于完全相等，例如`q = 150`，最大边界严格小于`150`是`100`，所以选择的速率是`35`。 相同的搜索会自动处理这种情况。
