 ## 解决方案

 ## 问题理解

 我们正在处理一行整数，其中唯一允许的移动将两个相同的邻居合并为一个元素，并将其值增加一。 每次合并都会将数组缩短一个元素，并且新值可能会与其邻居创建进一步的合并。 

任务不是任意模拟合并，而是决定这个过程可以推进多远，以便最终的数组尽可能短。 合并的顺序很重要，因为合并两个值可能会稍后在数组的不同区域中解锁更高级别的合并。 

输入尺寸足够小，$n \le 500$，二次或三次动态规划解决方案是可行的。 如果仔细修剪的话，子数组上的任何指数仍然可以，但是对所有合并顺序进行简单的暴力模拟是不可行的，因为随着相邻相等对的出现和消失，可能的合并序列的数量会组合增长。 

当合并创建更高的值并跨越以前不相关的段时，贪婪思维的一个微妙的失败案例就会出现。 

例如，考虑`[1, 1, 2, 2]`。 天真的贪婪方法可能会首先合并左对以获得`[2, 2, 2]`，然后再次合并，最终剧烈崩溃。 但在更复杂的情况下，例如`[1, 1, 1, 1]`，从一侧盲目合并可以产生不同的中间结构，但所有最优策略都以单一值结束。 这表明仅靠地方决策是不够的； 我们需要长期的全球视野。 

关键的隐藏困难在于，一个段可以被压缩为单个值，也可以部分不合并，具体取决于它是否可以由较小的相等块递归地形成。 子段之间的交互是动态规划方法的动力。 

## 方法

 强力解释将模拟有效合并的每个可能的序列。 在每一步中，我们都会扫描相等的相邻对并选择其中一个进行分支。 每次合并后，阵列都会发生变化，并且会出现新的机会。 这形成了一个大的搜索树，其中每个状态可以生成多个下一个状态。 即使对于中等$n$，这会爆炸，因为每次合并都会将长度减少一，但会创建新的配置，从而导致指数行为。 

关键的观察结果是，最终状态仅取决于间隔如何折叠为单个值，而不取决于合并的确切顺序。 如果一个段可以完全缩减为一个数字，则该段的长度为 1； 否则，必须将其分割成更小的独立部分。 

这建议在间隔上定义 DP。 对于每个子数组，我们尝试确定它是否可以折叠为单个值，如果不能，则确定结果块的最小数量是多少。 困难在于，只有在重复压缩后可以将段分成具有相等结果值的两个可折叠部分时，它才可能折叠成单个值。 

这导致了一个结构，其中每个间隔要么：

 1. 保持拆分，合并子部分的最优解。 
2. 或者，如果递归合并后两半可以减少到相同的值，则合并为一个块。 

状态转换类似于带有值传播的区间 DP，我们不仅跟踪可行性，还跟踪最终的压缩值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 间隔 DP | O(n3) | O(n²) | 已接受 |

 ## 算法演练

 我们定义了间隔上的 DP 状态。 

让`dp[l][r]`表示子数组的最佳可能结果`a[l..r]`，其中每个状态存储间隔是否可以完全合并为单个值以及该值（如果可能），以及最终元素的最小数量。 

为了计算这个，我们评估长度增加的间隔。 

1. 初始化基本情况，其中`l == r`。 单个元素已经是不可约的，因此该段会自行折叠，长度为 1，值为`a[l]`。 
2. 对于每个间隔`[l, r]`，首先假设它不能完全合并，并将其答案初始化为尽可能分裂`k`，结合`dp[l][k] + dp[k+1][r]`。 这代表根本没有跨边界合并，只是内部优化。 
3.接下来，尝试完全崩溃`[l, r]`。 为此，我们需要找到一个分区点`k`使得两者`[l, k]`和`[k+1, r]`可以折叠成相同的最终值。 如果它们匹配，我们可以将这两个结果值合并为一个增加的值，进一步缩短间隔。 
4. 当两半崩溃到相等的值时，我们更新`[l, r]`可折叠成价值`v+1`。 这创造了级联机会，因为更高级别的合并依赖于较低级别的崩溃。 
5、最终答案是全范围内的最小dp值`[1, n]`，考虑它是完全塌陷还是部分分裂。 

### 为什么它有效

 关键的不变量是每个 DP 状态完全捕获其区间的所有可能的压缩表示：要么表示为不可约块的最小计数，要么表示为单个合并值（如果可能完全崩溃）。 因为任何有效的合并序列都必须遵守某个最后合并点的间隔边界，所以每个有效的解决方案都对应于 DP 转换中捕获的分区。 这确保了不会遗漏任何合并配置，并且不会错误地允许不可能的折叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # dp[l][r] = dictionary of {value: min_blocks}
    # meaning: interval can be reduced to 'value' using 'min_blocks' final segments
    dp = [[dict() for _ in range(n)] for _ in range(n)]

    for i in range(n):
        dp[i][i][a[i]] = 1

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1

            cur = {}

            for k in range(l, r):
                left = dp[l][k]
                right = dp[k + 1][r]

                for lv, lc in left.items():
                    for rv, rc in right.items():
                        if lv == rv:
                            val = lv + 1
                            if val not in cur or cur[val] > 1:
                                cur[val] = 1
                        else:
                            # cannot merge values, keep separate
                            # store as non-collapsed by tracking cost
                            pass

            # fallback: worst case, split fully
            best = float('inf')
            for k in range(l, r):
                best = min(best, sum(dp[l][k].values()) + sum(dp[k+1][r].values()))

            # store minimal representation
            dp[l][r][0] = best
            for v, c in cur.items():
                dp[l][r][v] = min(dp[l][r].get(v, float('inf')), 1)

    # answer is minimal blocks in dp[0][n-1]
    ans = float('inf')
    for v, c in dp[0][n-1].items():
        ans = min(ans, c)

    print(ans)

if __name__ == "__main__":
    solve()
```DP 表是根据不断增加的区间长度构建的，以便每个子区间在需要时都已得到解决。 嵌套循环结束`k`分割该段并组合所有可能的压缩结果。 

一个关键的微妙之处是我们必须跟踪一个区间是否折叠为单个值； 否则我们会丢失进一步合并所需的信息。 每个状态内的字典用于保存可能的结果值。 

最终的答案只是整个间隔内剩余段的最小数量。 

## 工作示例

 ### 示例 1

 输入：```
5
4 3 2 2 3
```我们跟踪子数组是否可以完全合并或仅部分合并。 

| 间隔 | 左分割| 右分割| 合并可能 | 结果 |
 | ---| ---| ---| ---| ---|
 | [2,3]| 2 | 2 | 是 → 3 | 崩溃|
 | [1,4]| 结合 [1,2] 和 [3,4] | 部分 | 是的 | 减少 |
 | [1,5]| 多次分割 | 最佳隔断| 部分 | 2 |

 关键的转变发生在中间`[2,3]`首先折叠，从而实现更高级别的合并，将最终长度减少到 2。 

这表明局部崩溃是更高级别合并的先决条件。

 输入：```

```| 间隔 | 运营| 结果 |

 | 决赛| 再次合并 | 2 |

 这证实了级联合并，其中中间压缩可以实现更高的值。

 ## 边缘情况

 对于像这样的输入`[x, x, x]`，算法必须确保合并前两个元素不会妨碍识别结果值可以再次与第三个元素合并（如果适用）。 正确的 DP 必须保留中间和最终的压缩状态； 否则它会错误地修复贪婪的合并顺序。 

对于交替模式，例如`[1,2,1,2]`，在任何阶段都不可能进行合并，并且 DP 必须避免错误地创建可合并状态。 这测试转换是否错误地假设不存在相等传播。
