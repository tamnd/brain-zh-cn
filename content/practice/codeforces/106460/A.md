 ## 解决方案
 ## 问题理解

 我们有两个字符串集合，每个字符串的大小$n$。 重新排列后，我们将它们按位置配对：第一个集合中的一个字符串与第二个集合中的一个字符串配对，并且每个字符串必须恰好使用一次。 

对于任何配对，两个字符串的“兼容性分数”被定义为其公共后缀的长度。 换句话说，我们从两个字符串的末尾查找，并计算在第一次不匹配之前有多少个连续匹配的字符。 

目标是对两个集合重新排序，以便当我们形成时$n$对，所有这些后缀匹配长度的总和尽可能大。 

每个字符串仅通过其配对做出贡献，因此问题实际上是在两个字符串多重集之间选择匹配，其中两个字符串之间的边权重是它们的后缀相似度。 

输入大小很大：每组中所有字符串的总长度达到$2 \cdot 10^5$。 这立即排除了尝试所有配对或天真地计算成对后缀匹配的任何解决方案。 一个完整的$O(n^2)$字符串的比较已经太大了，因为$n$可以达到$2 \cdot 10^5$总元素中。 

一种简单的方法可能会尝试计算所有成对后缀匹配，然后运行最大权重匹配。 这在计算和结构上都失败了，因为一般的匹配算法在这里太慢了。 

通过对字符串进行排序或在没有全局结构的情况下对局部相似的字符串进行配对，贪婪配对中出现了一种更微妙的故障模式。 一个简单的例子是，当许多字符串共享长后缀链时，贪婪配对过早地“消耗”了一个好的伙伴，从而阻止了以后更好的长匹配。 

## 方法

 暴力的观点是考虑在两个集合之间配对字符串的所有可能方法并计算总后缀相似度。 即使我们预先计算了所有成对后缀匹配$O(L)$每对，其中$L$是字符串长度，我们仍然面临$O(n^2)$成对，这远远超出了限制。 即使是二分匹配公式$n$每边带有加权边的节点变得不可行。 

关键的结构观察是后缀相似度不是任意权重，它完全取决于向后读取时两个字符串匹配的长度。 这建议反向处理字符串并按后缀结构对它们进行分组。 

如果我们反转所有字符串，问题就变成了最长公共前缀而不是后缀。 现在的任务是配对字符串以使总 LCP 最大化。 这正是可以用 trie 处理的结构类型。 

在基于反转字符串构建的特里树中，每个节点都对应一个前缀（它是原始字符串中的后缀）。 节点的深度表示后缀匹配的长度。 我们想要的是对字符串进行配对，以便尽可能多的对在字典树中尽可能深地“相遇”，因为更深的相遇点对总和贡献更大。 

中心思想是对 trie 进行自下而上的聚合：在每个节点，我们收集每一侧有多少个字符串通过它，一旦它们在该节点相遇，我们就会贪婪地匹配它们。 任何剩余的弦都会被向上推。 

这是有效的，因为在尽可能深的公共节点处匹配两个字符串可以最大化它们的贡献，并且延迟超出该节点的匹配不能改善它们的共享后缀。 

## 算法演练

 1. 反转两组中的每个字符串并将它们插入到 trie 中，跟踪第一组和第二组中有多少字符串在每个节点处结束或通过每个节点。 这将后缀匹配转换为前缀遍历。 
2. 对 trie 执行后序 DFS，以便子项在父项之前得到处理。 这确保我们首先解决更深层次后缀级别的匹配。 
3. 在每个节点，从来自其子节点的集合和以节点本身结尾的集合中收集“可用”字符串的数量。 这些表示至少共享此前缀的字符串。 
4. 通过将第一组中的一个与第二组中的一个配对，在此节点匹配尽可能多的字符串。 每个这样的对都将节点的当前深度贡献给答案。 
5. 配对后，如果两侧都有剩余字符串，则将其向上传播到父节点。 这些表示在此深度未找到具有足够长的公共后缀的匹配的字符串。 
6. 继续这个过程直到根，累积每个节点的贡献。 

正确性取决于最深可能节点的配对对该对产生最大贡献的事实。 一旦两个字符串在节点上可用，延迟它们与祖先的匹配将严格减少它们的贡献，因此立即匹配在本地和全局都是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "cnt1", "cnt2")
    def __init__(self):
        self.ch = {}
        self.cnt1 = 0
        self.cnt2 = 0

def add(root, s, typ):
    v = root
    for c in s:
        if c not in v.ch:
            v.ch[c] = Node()
        v = v.ch[c]
    if typ == 1:
        v.cnt1 += 1
    else:
        v.cnt2 += 1

def dfs(v, depth, ans):
    for nxt in v.ch.values():
        dfs(nxt, depth + 1, ans)
        v.cnt1 += nxt.cnt1
        v.cnt2 += nxt.cnt2

    m = min(v.cnt1, v.cnt2)
    ans[0] += m * depth
    v.cnt1 -= m
    v.cnt2 -= m

def main():
    n = int(input())
    root = Node()

    for _ in range(n):
        s = input().strip()[::-1]
        add(root, s, 1)

    for _ in range(n):
        s = input().strip()[::-1]
        add(root, s, 2)

    ans = [0]
    dfs(root, 0, ans)
    print(ans[0])

if __name__ == "__main__":
    main()
```trie 节点存储每组有多少个字符串通过它。 字符串的反转确保后缀对齐变成前缀遍历，因此深度直接测量后缀长度。 

DFS 从子项向上聚合计数。 匹配后的减法步骤确保一旦在节点处形成一对，它就不会错误地向上传播并被重用。 

一个微妙的实现细节是，在当前节点匹配之前，必须从子节点累积计数。 以相反的顺序进行操作将允许较浅的匹配覆盖较深的匹配。 

## 工作示例

 考虑一个包含两组的小案例：

 第一组：`["ab", "a"]`第二组：`["ab", "b"]`反转后：第一组变为`["ba", "a"]`，第二个变成`["ba", "b"]`。 

我们构建特里树并跟踪计数流程。 

在最深的节点对应`"ba"`，我们每一侧都有一个字符串，因此我们将它们与贡献 2 相匹配。剩余的`"a"`和`"b"`无法匹配超过深度 0 的内容。 

| 节点深度| cnt1 | cnt2 | 匹配| 贡献 |
 | ---| ---| ---| ---| ---|
 | 2 | 1 | 1 | 1 | 2 |
 | 1 | 1 | 1 | 0 | 0 |
 | 0 | 1 | 1 | 1 | 0 |

 该痕迹表明，深度匹配总是首先被获取，剩下的字符串自然会冒泡。 

现在考虑：

 第一组：`["abc", "ab"]`第二组：`["abc", "a"]`反转：

 第一：`["cba", "ba"]`第二：`["cba", "a"]`在深度 3 处，一对匹配贡献 3。其余的`"ba"`和`"a"`仅在深度 1 处相遇。 

| 深度| cnt1 | cnt2 | 匹配| 贡献 |
 | ---| ---| ---| ---| ---|
 | 3 | 1 | 1 | 1 | 3 |
 | 2 | 1 | 0 | 0 | 0 |
 | 1 | 1 | 1 | 1 | 1 |

 这演示了算法如何自然地将较弱的匹配延迟到更高的节点。

 ## 边缘情况

 当所有字符串都相同时，特里树中的每个节点都携带来自两个集合的相同计数。 该算法在最深节点重复匹配，确保每一对都贡献完整的字符串长度。 

当一组字符串包含其他字符串的前缀（反转后）时，匹配会发生在不同的深度。 DFS 确保首先解析更深的匹配，因此较短的字符串不会错误地消耗长匹配机会。 

当根本没有后缀匹配时，每个匹配仅发生在根部，贡献为零，这是正确处理的，因为深度为零并且所有配对都发生在顶部。
