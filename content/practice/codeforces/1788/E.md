 ## 解决方案
 ## 问题理解

 我们给定一个整数数组，并希望在其中选择几个段。 每个选定的线段必须具有非负和，并且不允许两个选定的线段重叠。 选择的分数就是所有选定细分所覆盖的位置总数，目标是最大化该分数。 

另一种看待它的方式是，我们尝试使用不相交的间隔覆盖尽可能多的索引，其中每个间隔都具有以数组值表示的“非负总质量”。 

约束条件$n \le 2 \cdot 10^5$立即排除任何尝试显式枚举段或子集的解决方案。 甚至$O(n^2)$区间的构造已经是边界，因为有$O(n^2)$可能的部分，天真地检查总和会促使我们$O(n^3)$。 

当正值之间分散有许多小的负值时，就会出现一个微妙的问题。 总是从每个位置开始获取最长非负段的天真贪婪可能会失败，因为扩展段可能会将稍微正的间隔变成负间隔，即使将其分成多个较小的有效段会产生更好的总覆盖长度。 

例如，考虑一个像这样的数组：```
[2, -1, 2, -1, 2]
```整个数组有总和$4$，因此它作为长度为 5 的单个段是有效的。但是，本地策略可能会根据前缀波动选择较短的段。 在其他情况下，过于激进的合并会失去稍后放置更多段的灵活性。 

核心困难在于，细分决策不是独立的：选择一个细分会改变剩余的可用内容，还会改变是否可以形成未来的细分。 

## 方法

 暴力方法将尝试生成每组可能的不相交线段，并检查每个线段是否具有非负和。 即使我们只限制有效的段，也有$O(n^2)$候选者，并在其中选择不相交的子集会导致指数复杂性。 这是完全不可行的。 

我们需要认识到“段和非负”条件与前缀和可以很好地相互作用。 如果我们定义前缀和$p[i]$，那么任意一段$[l, r]$有效，如果$p[r] \ge p[l-1]$。 这将每个有效段转换为两个前缀索引之间的关系，其中右端点的前缀值不小于左端点。 

现在关键的结构见解是每个段仅贡献其长度，而不贡献其总和。 这意味着如果我们修复一个正确的端点$r$，我们想在那里结束一个片段，我们只关心选择最早的可能$l$这样$p[l-1] \le p[r]$。 选择较早的$l$总是会增加长度，并且不会损害有效性。 

这将问题转化为前缀位置的动态规划。 在每个位置$r$，我们决定是否结束一个段$r$，如果我们这样做，我们希望最长的有效段在那里结束。 优化简化为将每个前缀值与不超过该前缀值的最小先前前缀重复配对。 

为了有效地维护这一点，我们从左到右处理前缀和并维护一个数据结构，该数据结构存储每个前缀和阈值可实现的最佳 DP 值。 由于前缀和是任意整数，因此我们压缩并使用单调结构，其行为类似于“迄今为止最好的前缀和”映射。 这导致了 DP，其中每个状态都使用单调的堆栈式结构在摊销常数时间内更新。 

关键的转变是位置决策$i$仅取决于具有前缀和的所有早期位置中的最佳可达状态$\le p[i]$，并且这个结构可以增量地维护。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n^2) | O(n^2) | 太慢了 |
 | 单调结构的前缀 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算前缀和$p[i]$， 在哪里$p[0] = 0$。 这会将段和转换为前缀值的差。 
2. 我们维护一个支持以下功能的结构： 给定前缀值$x$，快速检索前缀和为的所有先前前缀位置中的最佳 DP 值$\le x$。 这代表了开始以当前位置结束的段的最佳方式。 
3. 我们从左到右处理位置，并在前缀索引上维护 DP。 让$dp[i]$是使用最多位置的最大总覆盖长度$i$，段边界在前缀点处对齐。 
4. 各位置$i$，我们首先发扬$dp[i] = dp[i-1]$，这意味着我们不会在以下位置结束段$i$。 
5. 然后我们考虑在以下位置结束一个片段：$i$。 最好的起点是任何$j < i$这样$p[j] \le p[i]$，增益为$(i - j)$加上最佳 DP 最多$j$。 我们查询最好的这样$dp[j] - j$， 因为：$$dp[j] - j + i$$已经考虑了先前的覆盖范围加上新的段长度。 
6. 我们维护一个前缀和的数据结构，用于存储以下最大值$dp[j] - j$对于每个前缀和阈值。 加工时$i$，我们用当前状态更新它。 
7.最终答案是$dp[n]$。 

### 为什么它有效

 关键的不变量是对于任何前缀值$x$，该结构存储了最佳可实现值$dp[j] - j$所有职位中$j$其前缀和最多为$x$。 这已经足够了，因为任何有效的段结束于$i$必须从某个开始$j$满意的$p[j] \le p[i]$，并且在所有这些选择中，最大化的一个$dp[j] - j$最大化总增益。 

由于每个转换仅取决于前缀和和线性表达式$dp[j] - j$，未来的决策不会使先前存储的最佳候选无效。 前缀约束的单调性确保我们永远不需要以更精致的方式重新考虑旧状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix sums
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    # DP
    dp = [0] * (n + 1)

    # We maintain pairs (prefix_sum, best dp[j] - j up to this prefix constraint)
    # We'll compress prefix sums by sorting unique values
    vals = sorted(set(pref))

    from collections import defaultdict
    import bisect

    # best value for each compressed prefix threshold
    best = [-10**18] * len(vals)

    def get_idx(x):
        return bisect.bisect_right(vals, x) - 1

    def query(x):
        i = get_idx(x)
        return best[i] if i >= 0 else -10**18

    def update(x, val):
        i = get_idx(x)
        if i >= 0:
            best[i] = max(best[i], val)

    # initialize: j = 0
    update(pref[0], dp[0] - 0)

    for i in range(1, n + 1):
        dp[i] = dp[i - 1]

        # try ending segment at i
        best_start = query(pref[i])
        if best_start != -10**18:
            dp[i] = max(dp[i], best_start + i)

        # update structure with j = i
        update(pref[i], dp[i] - i)

    print(dp[n])

if __name__ == "__main__":
    solve()
```该代码首先将数组转换为前缀和，以便段有效性变成一个简单的不等式。 DP 阵列跟踪直到每个前缀位置的最佳总覆盖长度。 

该数据结构是通过压缩前缀和并维护每个前缀阈值的最佳值来实现的。 每个DP状态贡献一个候选值$dp[j] - j$，它表示在位置之后开始分段的利润有多大$j$。 

在每个位置，我们首先计算不放置在此结尾的线段的选项。 然后我们查询以当前索引结尾的段的所有有效起点。 最后，我们将当前状态插入到结构中，以便它可以作为未来段的开始。 

最微妙的部分是确保我们总是在计算后更新结构$dp[i]$，否则我们会错误地允许使用同一位置两次。

 ## 边缘情况

 一个重要的边缘情况是第一步之后所有前缀和均为负数。 在这种情况下，任何以较晚位置结束的段都不能从索引 0 开始，并且 DP 必须避免形成无效的负和段。 该算法会处理此问题，因为超过前缀阈值的查询不会返回有效的起始候选，因此只有“跳过”转换幸存。 

另一种情况是最优解由许多小段而不是一个大段组成。 对于这样的输入：```
[2, -1, 2, -1, 2]
```该算法正确地允许多次重置起始位置，因为每个前缀更新都会存储一个新的候选者$dp[i] - i$，使未来的细分能够从不同的最佳点开始而不会重叠。 

最后，当前缀和重复时，压缩可确保它们映射到相同的阈值桶，因此前后相同的前缀值会得到一致的处理，从而保持“$\le$” 有效性检查中使用的条件。
