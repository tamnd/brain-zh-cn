 ## 解决方案
 ## 问题理解

 我们有一个完全二叉树的高度`h`。 每个顶点可以存储一定数量的电子，并且查询逐渐向顶点添加更多电子。 

一个`decay`操作均匀地随机选择一个叶子，并删除从根到该叶子的路径上的每条边。 顶点本身保留，只有边消失。 删除这些边后，树分成几个连接的组件。 

对于每个连接的组件，我们计算其内部电子的总和。 这种衰减的潜力是所有连接分量中的最大分量之和。 对于每一个`decay`查询时，我们必须输出所有叶子节点上该最大值的期望值。 

该树在结构上是静态的，但顶点的权重随着时间的推移而变化。 

限制是这里真正的挑战。 高度最多为`30`，因此顶点总数可能大到`2^31 - 1`，这是不可能显式存储的。 同时还有多达`10^5`查询，因此每个查询必须在大致对数时间内处理。 任何迭代所有叶子或所有顶点的解决方案都会立即失败，因为仅叶子的数量就可以达到大约十亿。 

更新的稀疏性至关重要。 尽管概念树很大，但只有更新中提到的顶点才重要。 最多`10^5`顶点接收非零权重。 

有几种容易被忽略的边缘情况。 

假设所有电子都集中在根上：```
h = 2
add 1 100
decay
```每次衰变都会删除一条从根到叶的路径，但根会变得孤立，但仍然包含所有`100`电子。 答案总是`100`。 粗心的解决方案可能会错误地认为根组件消失了，因为它在一条路径上的所有传出边缘都被删除了。 

当重子树完好无损时，会出现另一个微妙的情况：```
h = 2
add 4 50
add 5 60
decay
```如果删除的路径经过右子树，则整个左子树保持连接并贡献`110`。 如果删除的路径经过左子树，则幸存的组件较小。 最大分量取决于哪一侧被破坏。 

第三个陷阱是组件之间的联系。 考虑：```
h = 1
add 2 10
add 3 10
decay
```潜力永远存在`10`， 不是`20`。 被删除的边将断开一个子节点与根的连接，因此两个叶子节点永远不会同时保持连接。 简单地对幸存子树权重求和的解决方案会过度计算。 

## 方法

 蛮力解释很简单。 对于每一个`decay`查询、枚举全部`2^h`树叶。 对于每个叶子，删除相应的根到叶子路径，计算连通分量，找到最大分量和，并对所有叶子求平均值。 

从概念上讲，这是可行的，因为衰减后的树结构完全由所选的叶子决定。 问题在于规模。 即使是为了`h = 30`，有超过十亿片叶子。 重新计算每一个组件是没有希望的。 

下一个改进是观察删除路径后连接的组件实际上是什么样子。 

摘一片叶子。 所选根到叶路径上的每个顶点都与其路径上的子节点断开连接，但每个顶点仍然使子树挂在其同级侧。 

对于路径：```
root -> left -> right -> ...
```由此产生的组件是：

 1. 路径上的单个顶点，仅向上连接，直到删除的边。 
2. 整个未受影响的同级子树从路径中分支出来。 

关键的实现是每个组件都对应于：

 1. 以路径顶点的某个兄弟节点为根的子树。 
2. 所选路径本身的前缀。 

这将问题转化为维护子树和并查询对数个候选者中的最大值。 

现在是决定性的洞察力。 

对于固定叶子，定义：

 -`sub[v]`作为子树内的总权重`v`。 
-`path_prefix`作为沿所选根到叶路径直至一定深度的权重总和。 

当删除路径上的边时，包含路径顶点的组件仅由路径顶点的连续前缀组成。 每个偏离路径的子树都保持完整。 

所以一片叶子的答案是：```
max(
    every sibling subtree attached to the path,
    every prefix sum of the path
)
```只有`O(h)`这样的候选人。 

但我们仍然无法迭代所有叶子。 

共享相同前缀的叶子结构现在变得很重要。 如果我们站在一个节点`v`，那么：

 - 左子树内的所有叶子的行为类似，
 - 右子树内的所有叶子的行为类似。 

这表明树上的分而治之 DP。 我们递归地计算每个子树下叶子的预期答案，同时携带迄今为止从祖先累积的最大分量值。 

因为只有更新的顶点才重要，所以我们只存储触摸节点及其祖先的信息。 此类节点的总数为`O(qh)`。 

最终的解决方案处理每个查询`O(h^2)`时间，这足够快`10^5`查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次衰减 O(2^h * h) | O(h) | 太慢了|
 | 最佳 | 每个查询 O(h^2) | O(qh) | 已接受 |

 ## 算法演练

 1. 仅存储曾经收到更新的顶点的电子计数。 

这棵树在概念上是巨大的，但只有更新的顶点及其祖先才能影响答案。 
2. 维护子树和`sub[v]`。 

添加时`e`电子到顶点`v`，向上朝根方向走并添加`e`到每个祖先的子树总和。 

这是有效的，因为每个祖先子树都包含`v`。 
3. 对于衰减查询，递归地评估预期潜力。 

递归表示选择随机叶子。 
4. 在每个节点`v`，维持两个值：

 -`up`，当前根到-的总权重`v`路径组件。 
-`best`，当前子树之外已保证的最大组件。 
5. 如果`v`是一片叶子，腐烂路径到此结束。 

这片叶子的潜力等于：```
max(best, up)
```因为路径组件本身可能是最大的幸存组件。 
6. 否则，分支为左子节点和右子节点。 

假设我们递归到左孩子：

 - 整个右子树完好无损，
 - 其分量和为`sub[right]`。 

因此新的累计最大值变为：```
max(best, sub[right])
```路径组件获得当前节点权重。 
7. 平均两个孩子的结果。 

每片叶子的可能性都是相等的，并且每个子树恰好包含其父树的一半叶子，因为树是完整的。 
8. 不需要记忆。 

每个衰减查询仅访问`O(h)`沿着递归分支的状态，以及`h ≤ 30`。 

### 为什么它有效

 每一条删除的边都位于一条从根到叶的路径上。 任何幸存的连接组件必须：

 - 完全留在从该路径分支的同级子树内，或者
 - 由路径本身上的顶点的连接前缀组成。 

递归准确地跟踪了这些可能性。`best`存储迄今为止遇到的最大的完整兄弟子树。`up`存储当前连接的路径组件。 当到达叶子时，这些类别之外不能存在其他组件，因此它们的最大值是该叶子的真正潜力。 

递归分支上的平均与叶子上的均匀分布相匹配，因为每个内部节点在其两个子节点之间均匀地分割叶子。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    h, q = map(int, input().split())

    val = defaultdict(int)
    sub = defaultdict(int)

    sys.setrecursionlimit(1 << 20)

    def dfs(v, depth, up, best):
        up += val[v]

        if depth == h:
            return float(max(up, best))

        left = v * 2
        right = v * 2 + 1

        left_best = max(best, sub[right])
        right_best = max(best, sub[left])

        a = dfs(left, depth + 1, up, left_best)
        b = dfs(right, depth + 1, up, right_best)

        return (a + b) * 0.5

    out = []

    for _ in range(q):
        parts = input().split()

        if parts[0] == "add":
            v = int(parts[1])
            e = int(parts[2])

            val[v] += e

            cur = v
            while cur:
                sub[cur] += e
                cur //= 2

        else:
            ans = dfs(1, 0, 0, 0)
            out.append(f"{ans:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```实现直接遵循递归解释。`val[v]`存储精确放置在顶点的电子`v`。`sub[v]`存储以 为根的子树总和`v`。 

期间`add`查询时，我们从更新的顶点向上走到根。 由于树的高度最多为`30`，这需要的时间可以忽略不计。 

递归函数`dfs`模拟随机衰减过程。`up`表示由所选路径的幸存前缀形成的连通分量。 每个递归步骤都会添加当前节点权重，因为当前节点仍与其上方的前缀保持连接。 

当下降到左子树时，删除所选路径上的边后，右子树将完全分离。 它的总贡献正好是`sub[right]`，因此它成为全局最大值的候选者。 

同样的逻辑对称地适用于右孩子。 

一个常见的实现错误是忘记子树组件保持完整。 我们永远不会从子树总和中进行部分减去，因为在每个深度仅删除一条边。 

另一个微妙的点是叶子处理。 在深度`h`，路径已经结束，所以剩下的候选者是：

 - 累积路径分量，
 - 之前看到的最好的分离子树。 

不存在进一步的分支。 

所有总和都可以安全地放入 Python 整数中，因为最坏的总和大约是`10^5 * 10^4 = 10^9`。

 ## 边缘情况

 考虑只有根有电子的情况：```
2 2
add 1 100
decay
```每次衰变都会删除一条向下的路径，但根本身仍然作为带电荷的孤立组件存在`100`。 

递归开始于`up = 0`。 从根本上来说：

 -`up`变成`100`。 
- 所有兄弟子树的总和是`0`。 

每个递归分支都到达一个叶子：

 -`up = 100`-`best = 0`算法输出`100`。 

现在检查断开的相等叶子：```
1 3
add 2 10
add 3 10
decay
```如果选择的叶子是`2`，右子树与总和一起生存`10`，而路径分量仅包含顶点`2`与总和`10`。 

最大值为`10`， 不是`20`。 

递归正确跟踪：

 -`best = 10`-`up = 10`并返回它们的最大值。 

最后，考虑一个深度幸存子树：```
2 3
add 4 50
add 5 60
decay
```当选定的叶子位于树的右半部分时，整个左子树完好无损，总和`110`。 

递归过渡到右子集：```
best = sub[left] = 110
```该值传播到叶子并成为这些分支的最终答案。 这正是为什么必须显式维护子树和而不是在本地重新计算的原因。
