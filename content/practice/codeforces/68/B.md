 **标签：** 二分查找
 **求解时间：** 7m 4s

 ## 解决方案
 ## 问题理解

 我们有几个蓄电池，每个蓄电池都存储一定量的能量。 我们可以在它们之间转移能量，但每次转移都会浪费固定百分比。 如果我们发送`x`来自一个累加器的单位，发送者将失去所有`x`，而接收器只获得`x * (100 - k) / 100`。 

目标是使每个累加器包含相同的最终能量，并且我们希望该共同值尽可能大。 

输入给出了累加器的数量、传输过程中的损失百分比以及初始能量值。 输出是在任何传输序列之后可实现的最大相等能量水平。 

约束足够小，我们可以重复扫描整个数组。 最多有`10^4`累加器，每个值最多`1000`。 如果重复多次，对所有对进行二次模拟仍然存在风险，尤其是涉及浮点精度时。 解决方案围绕`O(n log precision)`在2秒的限制内是完全安全的。 

棘手的部分是能量不守恒。 每次转移都会破坏一些数量。 粗心的解决方案可能会直接对所有值进行平均，但这仅在以下情况下有效：`k = 0`。 

考虑这个例子：```
2 50
10 0
```平均值是`5`，但我们不能使两个累加器等于`5`。 给空的累加器`5`，我们必须发送`10`，因为一半丢失了。 那么第一个累加器就变成了`0`。 最好的答案是`10 / (1 + 2) = 3.333...`， 不是`5`。 

另一个微妙的情况是当所有累加器已经具有相同的值时：```
4 30
7 7 7 7
```答案正是`7`。 不需要传输，因此不会损失能量。 始终假设发生传输的解决方案可能会错误地减少答案。 

另一种危险的情况是高损失率：```
3 99
100 0 0
```仅有的`1%`转移的能量得以幸存。 大部分能量在重新分配过程中消失，因此答案变得很小。 整数运算或精度不足很容易产生错误的结果。 

## 方法

 思考问题的一种强力方法是猜测目标值`T`，然后显式模拟累加器之间的传输。 以上任何累加器`T`充当捐赠者，以及以下任何累积者`T`充当接收器。 

假设累加器有`a[i] > T`。 它可以赠送`a[i] - T`单位。 由于转移会损失能量，因此为他人贡献的实际有用量仅为：```
(a[i] - T) * (100 - k) / 100
```如果`a[i] < T`，那么它正好需要`T - a[i]`单位。 

如果可用捐赠的总能量至少等于所需的总能量，则`T`是可以实现的。 

暴力破解的难度来自于寻找最大可能`T`。 我们处理的是实数，而不是整数，因此检查每个候选者是不可能的。 即使尝试许多离散值也会失败，因为正确的答案可能是不合理的。 

关键的观察是单调性。 

如果某个目标值`T`是可以实现的，那么每一个更小的目标也是可以实现的。 我们总是可以提前停止转移。 另一方面，如果`T`是不可能的，任何更大的值也是不可能的。 

这将问题变成了对答案的经典二分搜索。 

For a candidate`mid`，我们计算：```
extra = total usable energy from donors
need = total missing energy from receivers
```如果`extra >= need`， 然后`mid`是可行的，我们尝试更大的值。 否则我们尝试较小的值。 

每个可行性检查都是线性的`n`，二分查找需要大约 100 次迭代才能获得出色的浮点精度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 不可能超过连续值 | O(1) | O(1) | 不实用|
 | 最佳 | O(n 对数精度) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取累加器的个数`n`, 损失百分比`k`，和数组`a`。 
2. 设置二分查找范围。 

最小可能的答案是`0`。 最大可能的答案是`max(a)`，因为累加器最终得到的能量不会超过最大初始值。 
3.对目标值反复进行二分查找`mid`。 

我们执行大约 100 次迭代，这对于`1e-6`精确。 
4. 对于每个累加器：

 如果`a[i] > mid`，计算损失后可以贡献多少有用能量：```
(a[i] - mid) * (100 - k) / 100
```将其添加到`extra`。 
5. 如果`a[i] < mid`，计算它需要多少能量：```
mid - a[i]
```将其添加到`need`。 
6.处理完所有累加器后，进行比较`extra`和`need`。 

如果`extra >= need`， 然后`mid`是可以实现的，所以将左边界向上移动。 

否则，将右边界向下移动。 
7. 二分查找结束后，输出左边界。 

### 为什么它有效

 对于固定目标`T`，上面的每个累加器`T`可以安全地减少自身`T`。 由于传输损失，只有一小部分被移除的能量可以在其他地方使用。 下面的每个累加器`T`准确地要求`T - a[i]`可用能量。 

如果捐赠的可用能源总量可以覆盖所有赤字，那么我们可以重新分配能源以实现`T`。 否则，由于剩余的可转移能源总量不足，任何重新分配策略都无法成功。 

可行性条件是单调的。 较小的目标总是需要较少的能量，而较大的目标则需要更多的能量。 二分查找正确找到最大的可行目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

loss_factor = (100 - k) / 100.0

left = 0.0
right = max(a)

for _ in range(100):
    mid = (left + right) / 2.0

    extra = 0.0
    need = 0.0

    for x in a:
        if x > mid:
            extra += (x - mid) * loss_factor
        else:
            need += mid - x

    if extra >= need:
        left = mid
    else:
        right = mid

print(f"{left:.9f}")
```二分查找直接对浮点值进行操作，因为答案不一定是整数。 

变量`loss_factor`代表在转移过程中幸存下来的能量的比例。 预先计算它可以避免在循环内重复相同的除法。 

可行性检查将累加器分为捐赠者和接收者。 由于损失，捐助者贡献的能源减少，而接收者则要求全额赤字。 

比较使用`extra >= need`。 平等很重要，因为确切的可行性仍然应该使答案向上。 

无论间隔大小如何，循环都会运行 100 次迭代。 这是浮点二分搜索的常见竞争编程技术。 由于每次迭代将间隔减半，因此 100 轮提供的精度远高于所需的精度。 

小数点后 9 位安全打印满足`1e-6`错误要求。

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    loss_factor = (100 - k) / 100.0

    left = 0.0
    right = max(a)

    for _ in range(100):
        mid = (left + right) / 2.0

        extra = 0.0
        need = 0.0

        for x in a:
            if x > mid:
                extra += (x - mid) * loss_factor
            else:
                need += mid - x

        if extra >= need:
            left = mid
        else:
            right = mid

    print(f"{left:.9f}")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("3 50\n4 2 1\n") == "2.000000000", "sample 1"

# minimum size
assert run("1 30\n7\n") == "7.000000000", "single accumulator"

# all equal
assert run("4 80\n5 5 5 5\n") == "5.000000000", "already balanced"

# no transfer loss
res = float(run("2 0\n10 0\n"))
assert abs(res - 5.0) < 1e-6, "average when k = 0"

 ## 边缘情况

 考虑传输损耗导致无法求平均值的情况：```
2 50
10 0
```假设算法检查`mid = 5`。 

第一个累加器可以捐赠：```
(10 - 5) * 0.5 = 2.5
```第二个累加器需要：```
5 - 0 = 5
```自从`2.5 < 5`，目标是不可能实现的。 二分查找向下移动。 最终收敛到大约`3.333333333`。 

这说明了为什么一旦传输破坏了能量，原始平均就会失败。 

现在考虑一个已经平衡的设置：```
4 30
7 7 7 7
```为了`mid = 7`：

 | 蓄能器| 贡献 | 需要|
 | ---| ---| ---|
 | 7 | 0 | 0 |
 | 7 | 0 | 0 |
 | 7 | 0 | 0 |
 | 7 | 0 | 0 |

 两个总数仍然为零，因此目标是可行的。 

该算法正确地识别出不需要传输，这意味着没有能量损失。 

最后，考虑极高的损失：```
3 99
100 0 0
```如果我们测试`mid = 1`：

 捐助者捐款：```
(100 - 1) * 0.01 = 0.99
```接收者需要：```
1 + 1 = 2
```目标立即失败。 

二分查找不断缩小，直到可行值变得粗略`0.4975`。 

此案例证实该算法在将可传输能量与需求进行比较之前正确应用了损耗因子。
