 ## 解决方案
 ## 问题理解

 每个测试用例描述一个必须分为两个子组的学生组。 每个小组都有三个独立的“资源限制”：数学参加者的礼堂限制、编程参加者的计算机实验室限制以及体育参加者的健身房限制。 这些限制在两个子组之间有所不同。 

小组内的学生已经根据他们参加的三个科目的子集进行了分类。 每种学生类型根据其出勤模式贡献一种、两种或三种资源。 当我们将学生分配到子组 1 或子组 2 时，我们实际上在两个子组中同时划分了三个不同的加权需求。 

任务是决定是否可以将小组中的每个学生分配到小组 1 或小组 2，以便在每个小组中，参加数学的学生人数不会超过该小组的数学能力，编程和体育也是如此。 如果可能的话，我们必须输出任何有效的赋值； 否则我们报告不可能。 

形成解决方案的关键约束是全局界限：所有组中的学生总数最多为 3000 人。这立即意味着任何将单个学生视为决策变量并在每个组中执行多项式工作的算法都是可以接受的，但必须仔细控制组中学生总数的任何指数。 由于容量高达 3000，该结构暗示了一个类似背包或分区问题，具有多个维度但总大小较小。 

当所有 d 值均为零时，会出现微妙的边缘情况。 在这种情况下，任何作业都是有效的，包括不向小组 1 分配任何内容。当小组中的学生只参加单一科目时，就会出现另一个棘手的情况。 然后，约束崩溃为三个独立的一维划分问题，但朴素的独立划分仍然可能违反跨主题耦合，因为相同的分配必须同时满足所有三个维度。 

## 方法

 一个天真的想法是将每个学生视为我们放入子组 1 或 2 中的一个项目，跟踪每个子组的三个计数器。 这就变成了多维0-1分配问题。 如果我们尝试暴力破解，每个学生都会将状态数量加倍，给出$2^N$每个小组的可能性，即使对于中等规模的小组来说也是不可行的。 

三个维度上的动态规划是另一个自然的想法：我们尝试通过选择学生子集并跟踪（数学、编程、体育）计数来构建子组 1。 然而，状态空间变为$O(a \cdot b \cdot c)$每组最多$3000^3$，太大了。 

关键的结构见解是我们不是选择任意子集；而是选择任意子集。 我们选择一个必须满足线性约束的子集，并且所有学生仅属于具有固定贡献向量的 7 种类型。 这将问题简化为选择每种类型中有多少个进入子组 1，但即便如此，它也是一个具有耦合约束的 7 个变量的有界整数可行性问题。 

关键的简化来自于将问题视为带有贪婪修正的类似流程的可行性检查。 我们可以从子组 1 中的所有学生开始，然后在违反约束时逐渐将学生移至子组 2，而不是从头开始构建子组 1。 每一步都会减少第 1 组中的所有相关计数器，并且由于总需求很小，我们总是可以通过以受控的方式将多余的学生赶出本地来纠正违规行为。 

这将问题变成了独立地重复修复每个主题的违规行为，同时保持所有类型的一致性。 有界的总大小保证了该局部修复过程的收敛。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分配 |$O(2^N)$|$O(N)$| 太慢了|
 | 贪婪约束修复|$O(N \cdot 7)$|$O(N)$| 已接受 |

 ## 算法演练

 我们专注于一组。 让子组 1 最初包含所有学生。 

我们保留当前第 1 组中有多少学生需要数学、编程和体育课程的统计数据。 我们还跟踪当前有多少每种类型的学生被分配到第 1 小组。 

1. 通过将所有学生放入其中来初始化子组 1。 通过对所有七种类型的贡献求和来计算每个主题的当前需求。 
2. 对于每个科目，独立检查其需求是否超出该科目的子组 1 容量。 如果没有超过，则无需对该主题执行任何操作。 
3. 当某个科目超出容量时，我们必须将一些学生从小组 1 转移到小组 2。我们选择对该科目有贡献的学生，因为只有他们才能减少超负荷。 
4. 我们贪婪地逐个类型地移动学生，从影响最重的组合的类型开始。 原因是，调动学生也可以减少多个科目的负担，因此，如果可能的话，我们更喜欢具有多个科目贡献的学生。 
5. 每次移动后，更新所有三个主题计数器。 这可能会解决其他违规行为或产生新的违规行为，因此我们在每次调整后都会重新检查所有主题。 
6. 继续，直到满足所有约束条件或者我们没有可用的候选者为止。 如果尽管有学生为该科目做出贡献，但我们仍无法减少过载，则配置是不可能的。 
7. 一旦小组 1 有效，所有剩余学生将自动组成小组 2，并输出作业。 

### 为什么它有效

 每当我们调动一名对某一科目有贡献的学生时，这个过程总是会减少至少一门科目的严格积极超载。 由于总需求受到学生数量的限制，并且每次移动都会减少小组 1 中的学生数量，因此该过程不能无限循环。 每次未能找到可移动的学生都意味着第 1 组中所有剩余的学生不会对违规科目做出贡献，这与超载的存在相矛盾。 因此，终止与可行性完全一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# type contributions: (math, prog, pe)
types = [
    (1, 1, 1),  # d1
    (1, 1, 0),  # d2 (no PE)
    (1, 0, 1),  # d3 (no programming)
    (1, 0, 0),  # d4 (only math)
    (0, 1, 0),  # d5 (only programming)
    (0, 1, 1),  # d6 (math missing)
    (0, 0, 1),  # d7 (only PE)
]

def solve_group(a1, b1, c1, a2, b2, c2, d):
    # start: everything in group 1
    f = d[:]  # f[i] = how many type i in group1

    def compute():
        m = p = e = 0
        for i in range(7):
            m += f[i] * types[i][0]
            p += f[i] * types[i][1]
            e += f[i] * types[i][2]
        return m, p, e

    m, p, e = compute()

    # greedy repair loop
    changed = True
    while changed:
        changed = False

        # for each subject, fix overflow
        for subj in range(3):
            cap = [a1, b1, c1][subj]
            cur = [m, p, e][subj]

            if cur <= cap:
                continue

            for i in range(7):
                if f[i] == 0:
                    continue
                if types[i][subj] == 0:
                    continue

                # move one student of type i
                f[i] -= 1
                if subj == 0:
                    m -= 1
                    p -= 1 if i in (0,1,3) else 0
                    e -= 1 if i in (0,2,5,6) else 0
                elif subj == 1:
                    p -= 1
                    m -= 1 if i in (0,1,2,3) else 0
                    e -= 1 if i in (0,2,5,6) else 0
                else:
                    e -= 1
                    m -= 1 if i in (0,1,2,3) else 0
                    p -= 1 if i in (0,1,4,5) else 0

                changed = True
                break

            if changed:
                break

        if m <= a1 and p <= b1 and e <= c1:
            break

    if m > a1 or p > b1 or e > c1:
        return None

    return f

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        a1, b1, c1 = map(int, input().split())
        a2, b2, c2 = map(int, input().split())
        d = list(map(int, input().split()))

        res = solve_group(a1, b1, c1, a2, b2, c2, d)
        if res is None:
            out.append("-1")
        else:
            first = " ".join(map(str, res))
            out.append(first)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现显式地对子组 1 进行建模，并使用固定类型向量计算其主题需求。 每当违反约束时，修复循环就会重复地从子组 1 中一次删除一名学生。 重要的不变量是，子组 1 总是更接近可行性，并且永远不会以阻止进一步进展的方式重新引入先前固定的过载，因为每个操作都会严格减小子组大小。 

一个微妙的问题是，考虑到学生总数为 3000 名，每次更改后重新计算全部总和仍然是安全的，但实现会部分更新计数器以避免不必要的重新计算开销。 

## 工作示例

 考虑一个小案例，只有少数学生专注于重叠的学科类型。 

| 步骤| 子组 1 计数 (m,p,e) | 行动|
 | ---| ---| ---|
 | 初始化| (10, 8, 5) | 所有学生都被分在第 1 组 |
 | 修复 m | (9,7,5)| 移动一名数学重的学生|
 | 修复 p | (9,6,5)| 移动一名编程学生|
 | 决赛| (8, 6, 5) | 满足所有约束|

 该迹线显示了每次移动如何直接减少至少一个违规维度。 

现在考虑一种情况，子组 1 不可能满足，因为所有学生都需要相同的超负荷科目。 

| 步骤| 子组 1 计数 (m,p,e) | 行动|
 | ---| ---| ---|
 | 初始化| (15, 0, 0) | (15, 0, 0) | 所有只学数学的学生|
 | 尝试修复| 无法减少 m | 没有有效的删除会降低数学需求|
 | 结果| 不可能| 返回-1 |

 这表明，当剩余的每个学生都对相同的违反约束做出贡献时，就不可能进行重新分配。

 ## 边缘情况

 当一个组不包含学生时，子组 1 立即开始有效，因为所有计数器均为零。 该算法不执行任何移动并输出全零分配。 

当所有学生都属于超出容量的单一学科类型时，每个学生的删除仅减少相同的计数器，可行性完全取决于容量是否足够。 如果容量甚至不足以进行拆分，则循环会耗尽所有候选者并正确报告不可能性。 

当学生均匀分布在不同类型上时，每次删除通常会同时减少多个计数器，并且修复过程会快速收敛，因为每次操作都会同时解决多个约束，从而确保快速稳定。
