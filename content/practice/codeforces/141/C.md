 ## 解决方案
 ## 问题理解

 每个人都记住一个数字，即队列中有多少个更高的人站在他们前面。 我们不再知道原始顺序或实际高度。 任务是重建任何有效的队列顺序以及满足每个人记忆值的高度。 

假设一个人有价值`a = 2`。 这意味着他们之前的两个人的身高必须严格更高。 同等身高的人不算。 

有趣的是，实际高度并不固定。 只要相对比较产生所需的计数，我们就可以自由地指定任何正整数作为高度。 

约束条件`n ≤ 3000`对于二次算法来说足够小。 一个`O(n^2)`在最坏的情况下，解决方案执行大约 900 万次操作，这在 Python 中已经足够快了。 立方方法变得危险，因为`3000^3`270亿次运算，2秒内完全不可能。 

主要困难在于记住的值取决于相对高度排序，而不是直接取决于位置。 贪婪地把人们从左到右排列的幼稚尝试很容易在以后陷入困境。 

考虑这个例子：```
3
a 0
b 1
c 0
```粗心的贪婪策略可能会导致`a`首先因为`a=0`， 然后`c`，则无法放置`b`。 但正确的安排是存在的：```
a 2
b 1
c 2
```仅此`a`比`b`并站在他面前。 

另一个微妙的情况是不可能检测。```
2
a 1
b 1
```谁先站起来，前面就有零个人，所以他们不能要求前面有一个更高的人。 不存在解决方案。 

等高是错误的另一个来源。 由于只有严格较高的人才被计数，因此两个人可能具有相同的身高，而不会影响彼此的计数。 

例子：```
3
a 0
b 0
c 1
```有效的分配是：```
a 2
b 2
c 1
```两个都`a`和`b`比`c`，但他们并不比对方高。 

## 方法

 暴力方法会尝试人的每一种排列，并检查是否存在某种高度分配。 即使检查单个排列也很重要，因为我们必须验证之前的较高计数。 由于有`n!`排列，这甚至变得无用`n = 15`。 

我们需要利用隐藏在条件中的结构。 

假设我们按照身高递增的顺序处理人。 当我们放置一个人时，所有先前处理的人都较矮或相等，因此它们不会影响该人之前较高的人的计数。 唯一重要的是那些稍后将被处理的人，即更高的人。 

这很好地扭转了观点。 

想象一下我们对人们进行排序`a`。 一个体型较大的人`a`在他们之前肯定有更多更高的人，所以他们通常需要相对于更高的人显得更靠右。 

关键的观察是：

 如果我们处理人员的数量不断增加`a`，那么当放置一个有价值的人时`a`，他们必须占据位置`a`在当前构建的序列中。 

为什么这有效？ 

在那一刻，序列中的每个人都较短或相等。 未来的插入对应于更高的人。 如果当前人员插入到索引处`a`， 确切地`a`未来更高的人可以稍后出现在他们面前。 

这将问题转化为建设性的插入过程。 

我们对人员进行排序`a`，并在索引处重复插入每个人`a`在当前列表中。 

如果在任何时候`a`超过当前列表大小，无法配置。 

构建订单后，我们分配高度。 既然人与人平等`a`可以共享相同的高度，我们按相等的组压缩高度`a`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n²) | O(n!·n²) | O(n) | 太慢了 |
 | 最佳 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1.将所有人配对阅读`(name, a)`。 
2. 按升序对人员进行排序`a`。 

较小`a`价值观更容易被放在首位，因为它们需要更少的高个子。 
3. 维护一个代表正在构建的队列的列表。 
4. 对于按排序顺序的每个人：

 1. 设所需数量为`a`。 
2.如果`a`大于当前队列长度，则不存在有效位置。 打印`-1`。 
3. 否则插入索引处的人`a`。 

在索引处插入`a`保证准确地说`a`未来更高的人可能会排在这个人之前。 
5. 队列顺序最终确定后，分配高度。 

有相同情况的人`a`可以得到相同的高度，因为他们不应该算对方更高。 
6. 从左到右遍历最终队列。 

1.从身高开始`1`。 
2. 每当当前人`a`与前一个人不同`a`，增加高度。 
3. 存储指定的高度。 
7. 输出队列顺序和高度。 

### 为什么它有效

 不变的是，当处理一个有价值的人时`a`，已经排在队列中的每个人都不比他们高。 未来插入的人对应于更高的人。 

通过在索引处插入当前人员`a`， 确切地`a`他们之前的职位仍然可供未来更高的人使用。 每个后来处理的人都有`a' ≥ a`，因此它们被分配更大或相等的高度。 只有严格意义上的更高的高度才重要，并且同等——`a`群体的身高相同。 

因此，每个人最终都会遇到所需数量的更高的人。 

如果在某个步骤`a`超过当前队列大小，该人之前没有足够的位置可供未来更高的人使用，因此不存在解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    people = []
    for _ in range(n):
        name, a = input().split()
        people.append((name, int(a)))
    
    people.sort(key=lambda x: x[1])
    
    queue = []
    
    for name, a in people:
        if a > len(queue):
            print(-1)
            return
        
        queue.insert(a, (name, a))
    
    heights = {}
    current_height = 1
    
    for i, (name, a) in enumerate(queue):
        if i > 0 and a != queue[i - 1][1]:
            current_height += 1
        
        heights[name] = current_height
    
    for name, a in queue:
        print(name, heights[name])

solve()
```第一阶段根据人们记住的价值观对他们进行分类。 这个顺序很重要，因为我们将后来插入的人解释为更高的人。 

名单`queue`存储部分重建的顺序。 Python列表插入是`O(n)`，这是可以接受的`n ≤ 3000`。 

不可能性条件很微妙。 如果`a > len(queue)`，那么即使未来的每个人都更高，在这个人之前也没有足够的位置。 施工必须立即停止。 

高度分配比乍一看更简单。 只有相对比较才重要。 具有相同特征的人`a`值可以安全地共享相同的高度，因为它们不应该互相算作更高。 

该代码仅在以下情况下增加高度：`a`变化。 由于最终队列在结构上已经有效，因此这种压缩的高度分配保留了所有所需的计数。 

一个常见的错误是严格分配每个人的身高。 这错误地等于`a`人们互相算对方更高。

 ## 边缘情况

 考虑不可能的配置：```
2
a 1
b 1
```处理顺序保持不变。 当队列为空时，第一个人需要在索引 1 处插入。 自从`1 > 0`，算法立即报告`-1`。 

这是正确的，因为任何队列中的第一个位置之前都没有人。 

现在考虑相等的值：```
4
a 0
b 0
c 0
d 0
```每次插入都发生在位置 0：```
[d, c, b, a]
```所有人的身高都是相同的。 没有人比他们更高，所以每一次计数都令人满意。 

最后，考虑边界插入：```
4
a 0
b 1
c 2
d 3
```插入顺序：```
[a]
[a, b]
[a, b, c]
[a, b, c, d]
```每个人都按照当前队列大小精确插入，这意味着他们会到达末尾。 这验证了`a == len(queue)`是有效的，而只有严格更大的值是不可能的。
