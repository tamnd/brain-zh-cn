[CF 198B - 在墙上跳跃](https://codeforces.com/problemset/problem/198/B)

 **标签：**最短路径
 **求解时间：** 1m 37s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有两个垂直的墙，每个墙都由一个长度的字符串表示`n`。 位置`i`挂在墙上要么是安全的（`-`) 或被阻止 (`X`）。 忍者从位置开始`0`左墙的。 

每一秒他都可能移动到以下三个位置之一：

 1. 同一面墙上朝上的一个牢房。 
2. 同一面墙上向下有一个牢房。 
3.对面的墙，`k`细胞更高。 

超越位置`n - 1`意味着立即逃离峡谷。 

复杂的是水位上升。 时`t`, 所有有索引的位置`<= t - 1`已经被淹没了。 制作完成后`t`第二次移动，水再次上升。 一个位置只有在尚未被淹没时才可用。 

任务是确定是否有可能逃脱。 

墙高可达`100000`，这会立即排除任何指数搜索。 即使是二次算法也需要大约`10^10`最坏情况下的操作，远远超出极限。 我们需要接近线性时间的东西。 

问题最微妙的部分是运动和时间之间的相互作用。 在不同时间到达相同位置并不等同，因为水不断移动较低的位置。 

考虑：```
3 1
---
---
```正确答案是`YES`。 从位置`0`，跳到另一面墙的位置`1`，然后再次跳出墙外。 

仅检查墙壁障碍物而忽略时间的粗心实现在这里是可行的，但在唯一路径需要访问已经被淹没的位置的情况下，同样的错误会失败。 

另一个容易犯的错误是允许移动到已经在水下的位置。```
4 2
----
----
```假设我们在位置`2`在某个时间`3`。 位置`1`已经被淹没了，因此即使标记为安全，前往该处也是非法的。 

正确的条件不仅仅是“在界内且不受阻挡”。 目的地索引还必须严格大于当前时间。 

第三个陷阱是跳跃逃跑。```
5 3
-----
-----
```从位置`3`, 跳跃落在位置`6`，位于墙外。 忍者立即逃跑。 某些实现错误地拒绝目标索引超过的移动`n - 1`，缺少有效的转义。 

## 方法

 蛮力的想法是对每一个可能的动作序列进行建模。 在每个州，我们都会尝试向上、向下、跳跃。 由于可以通过许多不同的路径重新访问相同的位置，因此移动序列的数量随着时间呈指数增长。 即使对于中等的墙壁高度，这也是不可行的。 

关键的观察结果是游戏自然地形成了一个图表。 状态完全由两条信息决定：我们在哪堵墙上以及我们占据哪个位置。 时间不需要单独存储，因为每次移动只花费一秒钟。 在广度优先搜索中，距起点的距离恰好是我们到达某个状态时所经过的时间。 

一旦我们知道了一个状态的到达时间，我们就可以决定一个移动是否合法。 目的地位置必须是安全的、未被访问过的，并且在到达时仍然高于水面。 

这将问题转化为最多的最短路径搜索`2n`州。 每个状态最多有三个出边，因此可以在线性时间内探索整个图。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最优 BFS | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 存放两根墙绳。 
2. 将状态表示为`(wall, position)`在哪里`wall`是`0`对于左墙和`1`对于右墙。 
3. 启动BFS`(0, 0)`在某个时间`0`。 
4. 当一个状态`(wall, pos)`从队列中移除，其BFS距离为当前时间`t`。 
5. 生成三种可能的移动：

 -`(wall, pos + 1)`-`(wall, pos - 1)`-`(1 - wall, pos + k)`6. 如果任意目标索引至少为`n`，忍者立即逃脱，我们打印`YES`。 
7. 对于墙内目的地：

 - 电池必须安全（`'-'`）。 
- 该状态之前不得被访问过。 
- 目标索引必须严格大于`t + 1`。 

最后一个条件模拟了水。 进行下一步动作后，时间变为`t + 1`。 最多有索引的任意位置`t + 1`已经被淹了，无法占用。 
8. 每个有效的目的地都被添加到BFS队列中并带有距离`t + 1`。 
9. 如果BFS完成且没有转义，则打印`NO`。 

### 为什么它有效

 BFS 按经过时间的递增顺序探索状态。 当第一次访问某个州时，我们会找到该州的最早可能到达时间。 

用水限制仅取决于抵达时间。 如果某个位置在最早到达时间到达时不安全，那么稍后到达也无济于事，因为水位只会上升。 由于这种单调属性，访问每个状态一次就足够了。 

每个合法的移动序列都对应于 BFS 探索的路径，每个 BFS 转换都对应于游戏中的合法移动。 当移动离开墙壁时，会准确地报告逃逸，因此算法会返回`YES`当且仅当存在有效的逃生路径时。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    walls = [input().strip(), input().strip()]

    visited = [[False] * n for _ in range(2)]
    visited[0][0] = True

    q = deque()
    q.append((0, 0, 0))  # wall, position, time

    while q:
        wall, pos, t = q.popleft()

        moves = [
            (wall, pos + 1),
            (wall, pos - 1),
            (1 - wall, pos + k)
        ]

        for nw, np in moves:
            if np >= n:
                print("YES")
                return

            if np < 0:
                continue

            if np <= t + 1:
                continue

            if walls[nw][np] == 'X':
                continue

            if visited[nw][np]:
                continue

            visited[nw][np] = True
            q.append((nw, np, t + 1))

    print("NO")

solve()
```队列存储当前的墙、位置和经过的时间。 BFS 保证状态按照时间递增顺序进行处理。 

条件`np <= t + 1`是解决方案中最重要的一行。 我们正在考虑一秒钟后到达的移动。 此时最多有指数持仓`t + 1`已经消失在水下，所以这种行为是非法的。 

在验证障碍物之前会检查逃生，因为离开墙壁会立即赢得游戏。 无论那里存在什么，超越顶部的跳跃都会成功。 

已访问数组可防止重新访问状态。 由于 BFS 会尽可能早地到达每个状态，因此较晚到达的状态不会产生任何优势。

 ## 边缘情况

 考虑尽可能最小的峡谷：```
1 1
-
-
```BFS 开始于`(0,0)`。 跳跃动作目标位置`1`，位于墙外。 算法检查`np >= n`首先并立即返回`YES`。 这可以正确处理即时转义。 

考虑向下移动将进入被淹没区域的情况：```
4 2
----
----
```假设BFS到达位置`3`在某个时间`2`。 向下移动将目标位置`2`。 到达时间将是`3`，以及条件`np <= t + 1`变成`2 <= 3`，因此该移动被拒绝。 该算法不允许站在水下的单元格上。 

考虑离开峡谷的跳跃：```
5 3
-----
-----
```处于位置的状态`3`生成跳转到的位置`6`。 自从`6 >= 5`，立即检测到逃逸。 不尝试进行墙查找，从而避免出界错误并正确建模游戏规则。 

最后，考虑稍后重新访问状态：```
6 2
------
------
```可以通过多条路线到达某个位置。 BFS 尽早访问它并标记它已访问。 任何后来到达的人都将面临相同或更高的水位，永远不会创造新的机会。 被访问的数组安全地删除了多余的探索，同时保留了正确性。
