 ## 解决方案
 ## 问题理解

 我们给定一个正整数`n`。 对于任何选定的正整数`m`，我们看一下函数`f(m, i)`对于每个除数候选者`i`从`1`到`n`。 该功能贡献`1`正好在划分时`m`经过`i`留下余数`1`，否则有贡献`0`。 

任务是选择一个`m`最大化成功值的总数`i`，并打印所选的`m`和最高分。 输入包含多个独立值`n`。 

主要困难来自于尺寸`n`。 可以达到`10^9`，因此迭代所有可能的`i`对于每个测试用例最多需要`10^12`跨所有测试的操作，这是不可能的。 我们需要找到一种避免扫描范围的数学结构。 

要考虑的关键情况是较小的值`n`和限制`m`。 例如，当`n = 1`，没有有效的余数`1`因为`m mod 1`总是`0`，所以答案一定有分数`0`。 假设每个值的解决方案`1`到`n`能满足就失败在这里。 

另一个重要的情况是当`n`大于允许的最大值可以处理的`m`。 例如，所有数字的最小公倍数`100`已经比`10^18`。 直接构建使用`lcm(1, n)`会违反限制`m`。 

## 方法

 一个简单的方法是尝试一切可能的方法`m`并计算有多少个值`i`满足`m mod i = 1`。 这是不切实际的，因为可能的范围`m`是巨大的，甚至检查所有`i`对于一名候选人来说已经花费了`O(n)`。 

更好的方法是扭转这种情况。 等式`m mod i = 1`意味着`m - 1`可以整除`i`。 如果我们定义`x = m - 1`，问题就变成了寻找一个数`x`使得尽可能多的值`i`在`[1, n]`尽可能划分`x`。 

让许多数字相除的自然方法`x`就是取它们的最小公倍数。 如果`x`等于`lcm(1, 2, ..., k)`，然后每个数字`1`到`k`划分`x`，所以选择`m = x + 1`给出的分数为`k - 1`因为`i = 1`从不贡献。 

剩下的问题是有多大`k`可以。 的价值`m`不得超过`10^18`，因此我们反复扩展最小公倍数，同时使其保持在该限制内。 在该值超过限制之前，只有几种可能的扩展。 对于给定的`n`，我们取最大的可用值`k`不大于`n`。 

这是最佳的原因是，如果一个数字`x`让一组值除以它，那么这些值的最小公倍数也必须除以`x`。 由于最小公倍数不能超过`10^18 - 1`，没有解决方案可以使更多的连续值相除`x`比我们最大可能的前缀。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个候选人 O(n) | O(1) | O(1) | 太慢了 |
 | 最佳 | 每个测试用例 O(log(10^18)) | O(log(10^18)) | O(log(10^18)) | 已接受 |

 ## 算法演练

 1. 预先计算适合内部的最小公倍数的最大前缀`10^18`。 开始于`lcm(1) = 1`并在该值不超出允许的限制的情况下继续乘以下一个整数。 结果列表包含每个有用的前缀长度。 
2.对于每个测试用例，找到最大的前缀长度`k`从预先计算的列表中，这样`k <= n`。 这是可以整除的连续值的最大数量`m - 1`。 
3.让`x`是`lcm(1, 2, ..., k)`来自预先计算的值。 输出`m = x + 1`。 
4. 分数为`k - 1`什么时候`k`至少是`1`，因为所有值都来自`2`通过`k`满足条件和值`1`从来没有。 

为什么有效：选择的值`m`有`m - 1`可被任意数字整除`k`，因此它的得分为`k - 1`。 任何更好的答案都需要更多的数字`2`继续划分`m - 1`，这将迫使这些数字的最小公倍数大于我们预先计算的最大可能值。 这将与限制相矛盾`m`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LIMIT = 10**18 - 1

lcm_values = [1]
cur = 1
k = 1

while True:
    nxt = cur * (k + 1)
    if nxt > LIMIT:
        break
    cur = nxt
    k += 1
    lcm_values.append(cur)

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())

        k = 1
        for i in range(len(lcm_values)):
            if i + 1 > n:
                break
            k = i + 1

        m = lcm_values[k - 1] + 1
        ans.append(f"{m} {k - 1}")

    print("\n".join(ans))

solve()
```预计算一次构建所有可能的最小公倍数前缀。 循环很快停止，因为最小公倍数增长得非常快并且通过`10^18`仅仅走了几十步之后。 

对于每个测试用例，变量`k`存储最大可用前缀长度。 由于预先计算的列表很小，因此扫描它实际上是恒定的时间。 答案是直接使用存储的最小公倍数，而不是重新计算它，这样可以避免溢出和不必要的工作。 

输出值为`lcm + 1`因为原始条件大约是`m`，而整除性更容易推理使用`m - 1`。 在末尾加一即可恢复所需的值。

 对于`n = 3`，有用的前缀是：

 算法输出`7 2`。 这里`7 mod 2 = 1`和`7 mod 3 = 1`，因此两个值成功。 价值`1`无法成功。 

为了`n = 5`，前缀可以扩展到五个数字：

 | 步骤| k | lcm(1..k) | 米 | 分数 |

 | 初始| 1 | 1 | 2 | 0 |

 | 延伸| 3 | 6 | 7 | 2 |
 | 延伸| 4 | 12 | 12 13 | 3 |
 | 延伸| 5 | 60| 61 | 61 4 |

 ## 边缘情况

 对于`n = 1`，算法选择`k = 1`和输出`m = 2`。 唯一检查的值是`1`， 和`2 mod 1`是`0`，所以分数是正确的`0`。 

对于较大的值，例如`n = 10^9`，完整的最小公倍数达到`n`不可能符合限制。 算法在最大有效前缀处停止，即`43`，并使用`lcm(1..43) + 1`。 每个值来自`2`到`43`有效，但不能强制使用更大的前缀，因为它的最小公倍数将超过允许的最大值`m - 1`。 

对于恰好位于最小公倍数边界的值，例如`n = 5`，该算法包含新值，因为`lcm(1..5)`仍然适合。 缺少此边界将给出较小的分数，这就是前缀搜索包含相等性的原因。
