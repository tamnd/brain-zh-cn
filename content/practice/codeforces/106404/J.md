 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，都有一个表示元素“权重”或“高度”的整数值的集合，以及一个阈值$k$。 

我们可以从这个集合中丢弃任何元素子集。 之后，我们可以随意对剩余​​元素进行重新排序。 目标是排列选定的子集，以便最终序列中的每对连续元素最多相差$k$。 

任务是尽量减少我们删除的元素数量，以便这样的安排成为可能。 

重新表述需求的一个有用方法是，在对保留的元素进行排序后，我们希望能够对它们进行排序，以便连续值之间不会发生大的“跳跃”。 由于我们可以任意排列，因此我们真正尝试构建的结构是一条链，其中每一步最多移动$k$，但我们并不被迫使用排序邻接； 我们只需要某种排序的存在。 

输入大小限制总共很大，最多$2 \cdot 10^5$所有测试用例中的元素。 这立即排除了任何二次策略，例如检查所有子集或所有成对转换。 甚至$O(n \log n)$仅当总数总体上保持线性对数时，每个测试用例才是可接受的，这促使我们进行排序和贪婪扫描而不是组合选择。 

微妙的边缘情况来自重复和宽间隔的值。 如果所有数字都相同，则任何子集都有效，因此答案是零移除。 如果值极其分散并且$k$很小，我们能做的最好的通常是单个元素，因为在有效链中没有两个元素可以相邻。 

当值形成多个由稍大于$k$。 例如，如果我们有$[1, 2, 3, 10, 11, 12]$和$k = 2$，我们可以完全采用这两个簇，但不能混合它们。 一种假设我们必须按排序顺序选择单个连续段的简单方法会错误地丢弃太多元素，因为该结构不一定是一个间隔，而是可能是多个兼容的块。 

## 方法

 强力解决方案将尝试考虑元素的所有子集，并针对每个子集尝试决定是否可以对其进行排序，以便相邻差异保持在$k$。 即使进行了修剪，这本质上还是探索了$2^n$子集，验证每个子集至少需要排序或检查邻接可行性，导致类似的情况$O(2^n \cdot n \log n)$。 即使对于$n = 30$，更不用说$2 \cdot 10^5$。 

关键的简化来自对数组的排序。 一旦元素被排序，“我们可以任意重新排序”的约束就不再是关于排列，而是更多关于选择一个子序列，其中连续选择的值在排序顺序上相距不太远。 原因是如果两个选定的元素相差超过$k$，那么无论我们如何排列，它们都不能在有效链中相邻，而不在中间的某个地方引入更大的间隙。 任何可以桥接它们的中间元素都必须位于$k$，它必须来自同一排序区域。 

这将问题简化为识别可以通过最多 size 的步长连接的最大子集$k$当沿着排序数组行走时。 换句话说，我们想要最大的链，其中按排序顺序连续选择的元素最多相差$k$，但只要保持连接性，我们就可以跳过元素。 

更精确的看待它的方法是将排序数组视为定义索引之间的边$i < j$如果$a[j] - a[i] \le k$。 我们想要可以使用这些边将最大的顶点集排列成路径。 由于边尊重值空间中的顺序，因此最佳结构会分解为采用最长的“间隔连接”分量，这可以使用滑动窗口找到。 

一旦排序，最优子集对应于可以被窗口覆盖的最大元素组，其中最大值减去最小值至多是某个可链接结构$k$。 贪婪的洞察力是，如果我们固定一个起点，我们会尽可能地延伸，同时保持每个下一步都在范围内$k$先前选择的元素，按排序顺序意味着我们永远不会通过在有效区域内跳过来获得任何东西。 

因此，问题就相当于找到最大的子集，我们可以按排序顺序遍历该子集，并始终将连续选择的元素保持在距离内$k$。 这是一个经典的两指针扩展。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 排序+两个指针贪婪 |$O(n \log n)$|$O(1)$或者$O(n)$| 已接受 |

 ## 算法演练

 1. 对数组进行非降序排序。 排序是必要的，以便可以使用局部差异而不是任意排列来推理任何有效的邻接结构。 
2. 使用两指针窗口，其中左指针标记候选段的开始，右指针向前扩展。 
3. 对于每个左指针位置，尽可能远地移动右指针，同时保持每个步骤都可以是有效链的一部分。 具体来说，确保所选子集中的连续元素最多可以相差$k$，以排序形式允许连续扩展，直到出现中断。 
4. 跟踪任何此类有效窗口的最大尺寸。 这代表了我们可以保留而无需删除的最大元素数量。 
5. 测试用例的答案是元素总数减去可实现的最大大小。 

这足够的原因是，最佳窗口之外的每个元素在任何最佳排列中实际上都是“不可用”的，因为它无法在不违反以下原则的情况下连接到最大的可行链中：$k$-某些邻接处的差异约束。 

### 为什么它有效

 关键的不变量是，在任何候选窗口内，所有元素都可以连接成有效的序列，而不需要窗口外的元素。 由于数组是有序的，任何时候我们遇到的间隙大于$k$，该间隙充当硬分离：左侧的任何元素都不能直接连接到间隙之外的元素，而无需通过中间值，这些中间值已经包含在最大窗口内（如果存在）。 因此，每个最大窗口在隐式图中定义了一个独立的连通分量，其中边存在于距离最远的值之间$k$，最优解是保留最大的分量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        
        l = 0
        best = 1
        
        for r in range(n):
            while l < r and a[r] - a[l] > k:
                l += 1
            best = max(best, r - l + 1)
        
        print(n - best)

if __name__ == "__main__":
    solve()
```排序步骤是将问题从全局排列问题转换为局部邻接约束问题。 两指针循环维护一个滑动窗口，其中所有元素在以下方面保持相互兼容：$k$-间隙规则。 

条件`a[r] - a[l] > k`是强制执行段有效性的唯一位置。 因为数组是排序的，一旦给定的条件不成立`l`，增加`r`不移动就无法修复它`l`向前，这证明了左指针的贪婪前进是合理的。 

最后的减法`n - best`将“保留最大有效子集”公式转换为所需的“删除最小元素”输出。

 ## 边缘情况

 当所有元素都相同时，排序窗口永远不会中断，因为每个差异都为零。 该算法不断将窗口扩展至最大尺寸，结果变为零移除，这与任何排序都是有效的事实相匹配。 

当数组严格递增但步长总是超过$k$，每个元素形成其自己的独立组件。 滑动窗口永远不会超过尺寸一，所以`best = 1`答案就变成了$n-1$，反映只能保留单个元素。 

当两个密集簇之间的间隙大于$k$，算法自然地将它们分割成单独的窗口。 每个簇都是独立评估的，只有最大的簇才对`best`，这符合不可能存在跨集群邻接的事实。
