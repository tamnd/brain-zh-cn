 ## 解决方案
 ## 问题理解

 我们得到了一张由加权无向桥连接的岛屿图。 穿过桥梁所需的时间等于其重量，因此通常意义上的旅行受最短路径距离的控制。 

每个岛屿的火山喷发也都有一个“最后期限”。 火山爆发的那一刻，该岛的所有桥梁都会被摧毁，这意味着该岛将无法用于在那一刻之后的任何进一步穿越。 

同时发生第二个过程：熔岩开始通过相同的加权图从已经燃烧的岛屿扩散，也将边缘权重作为传播时间。 如果熔岩在喷发时间之前到达岛屿，则该岛会在熔岩到达时刻更早燃烧。 否则它会在喷发时准确燃烧。 

一个关键规则是，准确到达燃烧时刻仍然有效。 你可以在岛屿燃烧时进入岛屿，并仍然将其用作踏脚石。 

任务是确定是否存在从节点 1 到节点 n 的路径，使得每个访问过的岛屿的到达时间永远不会严格大于该岛的燃烧时间。 

约束结构足够大，任何解决方案都必须接近 m 的线性算数，因为在测试中 n 和 m 之和约为 1e5。 这立即排除了诸如重新计算每个约束的最短路径或对每个节点执行重复的 BFS 之类的任何事情。 单一的 Dijkstra 式传递或仔细管理的可行性二分搜索是唯一现实的候选者。 

一些边缘情况很容易处理不当。 

当一条路径仅因为我们正好到达燃烧时间而可行时，就会出现一种故障模式。 例如，如果一个岛屿在时间 5 燃烧并且我们在时间 5 到达，那仍然是允许的。 任何严格的不平等检查都会错误地阻止有效的路由。 

另一种微妙的情况发生在熔岩在喷发时间之前烧毁岛屿时。 有效期限不仅仅是 ai，而是 ai 与距任何初始燃烧源的最短路径距离（模型中隐含的）之间的最小值。 一种仅检查人工智能的幼稚方法可能会高估安全性并接受无效路径。 

最后，多条路径可能在不同时间到达一个岛屿，只有最早到达的路径对未来的扩展才重要。 不跟踪最知名到达时间的非 Dijkstra 贪婪步行可能会错过早期绕行但解锁较晚捷径的有效路线。 

## 方法

 思考这个问题的强力方法是模拟一段时间内的可达性。 对于每个时刻，我们都可以在图表中同时传播羊和熔岩，更新哪些岛屿仍然可用。 每个遍历步骤都需要在节点随时间消失的动态收缩图下重新计算最短到达时间。 

正确性在概念上很简单：我们直接模拟规则。 问题在于复杂性。 每个事件（熔岩到达或喷发）都会影响许多边，并且重新计算可达性会反复退化为 O(nm log m) 或更糟，具体取决于实现。 边缘多达 1e5，这远远超出了限制。 

关键的观察是我们实际上并不需要连续模拟时间。 对可行性唯一重要的是是否存在从 1 到 n 的路径，使得对于路径上的每个节点 v，到达时间 dist[v] 至多是其有效燃烧时间。 这将问题转化为约束最短路径问题。

如果我们从节点 1 运行 Dijkstra，我们会计算到达每个节点的最早可能到达时间，忽略火山约束。 然后我们简单地执行一个修剪规则：只有当候选到达时间不超过 v 的燃烧时间时，我们才允许将边缘放松到 v 中。 如果无法在截止日期内到达某个节点，则该节点将被有效地从考虑中删除。 

这是可行的，因为最短到达时间是单调的：一旦我们知道可以到达节点的最早时间，任何晚到达的可行性都会变得更差。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解时间模拟 | O(nm log m) | O(n + m) | 太慢了|
 | Dijkstra 与截止日期修剪 | O(m log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们计算每个岛屿的有效燃烧时间，然后运行约束最短路径搜索。 

1. 对于每个岛屿，将其燃烧时间视为给定的。 这代表着它可以安全地用作中间节点的最后时刻。 
2. 从节点 1 运行标准 Dijkstra，其中距离数组表示最早到达时间。 
3. 初始化distance[1] = 0并将其推入优先级队列。 
4.当提取当前时间t的节点u时，如果我们已经找到了u的更好到达时间，则忽略它。 这是标准的 Dijkstra 行为。 
5. 对于通过边权重 w 可到达的每个邻居 v，计算候选时间 t + w。 
6. 如果 t + w 严格大于 burn[v]，则完全跳过此转换。 这强制我们在节点变得不可用后永远不会进入该节点。 
7. 否则，如果 t + w 小于其当前值，则放宽 dist[v]，并将其推入优先级队列。 
8. 算法结束后，检查dist[n]是否有限。 如果是，则输出YES，否则输出NO。 

这足够的原因是我们有效地搜索所有路径，但只修剪那些在我们进入节点时违反硬可行性约束的路径。 任何有效路径都必须遵守每个前缀的这些约束，因此它将仍然可用于 Dijkstra 的松弛过程。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for _ in range(m):
            x, y, w = map(int, input().split())
            x -= 1
            y -= 1
            g[x].append((y, w))
            g[y].append((x, w))

        dist = [INF] * n
        dist[0] = 0

        pq = [(0, 0)]

        while pq:
            tcur, u = heapq.heappop(pq)
            if tcur != dist[u]:
                continue
            if tcur > a[u]:
                continue

            for v, w in g[u]:
                nt = tcur + w
                if nt <= a[v] and nt < dist[v]:
                    dist[v] = nt
                    heapq.heappush(pq, (nt, v))

        print("YES" if dist[n - 1] < INF else "NO")

if __name__ == "__main__":
    solve()
```核心实现是一个标准的 Dijkstra 循环，带有一个额外的约束检查：我们拒绝放松在节点燃烧时间之后到达的边缘。 弹出步骤中的第二个修剪条件很重要，因为优先级队列可能仍然包含由于超出截止日期而变得无效的条目。 

一个常见的错误是忘记节点可以在大于其截止时间的时间弹出，即使它之前已插入。 这就是为什么我们在探索邻居之前明确丢弃这些状态。

 ## 边缘情况

 一种边缘情况是，节点在其燃烧时间正好可以到达，但只能通过较长的替代路径，如果使用严格的不等式，该路径通常会被拒绝。 例如，如果一个节点的燃烧时间为 10，并且有两条路径在时间 10 和 11 到达该节点，则只有第一个路径有效。 该算法处理这个问题是因为它使用了`<=`放松边缘时的条件，允许相等但排除溢出。 

另一种情况是起始节点本身的燃烧时间非常短。 如果 a1 为 0，则唯一有效的初始状态是到达时间 0，并且必须立即根据该约束检查任何传出边缘。 优先级队列逻辑确保我们仍然处理节点 1，但任何违反其约束的邻居都会被提前丢弃。 

第三种微妙的情况是，当一个节点被多次插入优先级队列时，插入的时间不同，有的有效，有的无效。 支票`if d != dist[u]`防止处理过时的条目，以及额外的`d > a[u]`检查可防止扩展同时失效的节点。
