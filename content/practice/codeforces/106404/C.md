 ## 解决方案
 ## 问题理解

 该问题将一个国家建模为一棵城市树。 每个城市都以零功率开始。 一颗流星可以撞击一座城市一次，当它着陆时，它会给该城市带来初始能量，撞击时间后每秒减少一能量。 查询询问两个城市之间的唯一路径上每个城市当前存在的总功率。 简单版本的限制足够小，$n \le 2000$和$q \le 5000$，它允许对于硬版本来说太慢的解决方案。 

输入首先给出树结构，然后给出事件序列。 1 类事件记录流星在特定时间降落在一座城市。 类型 2 事件要求特定时间路径上的功率总和。 具有相同时间戳的事件需要在回答该时间戳的路径查询之前应用流星着陆。 输出是每个类型 2 事件的路径总和。 

的小值$n$与硬版相比，策略有所改变。 只有2000个城市，使用树遍历扫描路径的成本最多$O(n)$。 由于只有 5000 个查询，大约一千万个城市访问就足够了，这在 Python 中很容易管理。 这里不需要涉及重树数据结构的方法。 

主要的边缘情况来自时间处理。 恰好在查询时间着陆的流星已经贡献了其全部初始能量。 例如：```
3
1 2
2 3
2
1 5 2 10
2 5 1 3
```正确的输出是：```
10
```一个粗心的实现，仅在以下情况下激活流星`query_time > meteor_time`会错过流星，因为两次时间相等。 

另一个容易犯的错误是让流星影响查询路径之外的城市。 例如：```
3
1 2
2 3
2
1 1 1 7
2 1 3
```正确的输出是：```
7
```城市 1 处的流星有所贡献，因为城市 1 位于路径上。 对全球所有活跃流星进行求和的解决方案还将计算与当前路径无关的流星。 

负值也需要保留。 例如：```
1
1
2
1 0 1 0
2 10 1 1
```正确的输出是：```
-10
```流星不断失去能量，即使它的值变成负值。 将贡献限制为零会产生错误的答案。 

## 方法

 直接的做法是按时间顺序处理事件并维护已经降落的流星。 对于每个路径查询，我们都会遍历树路径并计算在那里找到的每个流星的当前贡献。 这是正确的，因为每个城市的力量仅取决于该城市的流星是否降落以及当前时间。 

第一次尝试可能会重新计算每个查询的所有城市权力。 在最坏的情况下，这会影响到所有人$n$每个查询的城市，给出$O(nq)$运营。 在给定的范围内，这大约是$10^7$操作，这是可以接受的。 同样的想法可以被视为强力树解决方案：不需要优化路径查询，因为约束有意使工作量保持较小。 

关键的简化是流星的公式。 如果一颗流星在某个时间降落$t_0$有价值$v$，那么在某个时间$t$其贡献是：$$v-(t-t_0)=(v+t_0)-t$$对于单次查询来说，当前时间是固定的，所以我们只需要知道路径上哪些城市有流星即可。 树DFS可以直接收集路径和，而不需要维护任何复杂的数据结构。 

暴力破解之所以有效，是因为简单版本使树和查询计数都保持在较小的水平。 在两个值都变大的硬版本上它会失败，因为走大路径数千次会变得太昂贵。 观察到简单的约束允许直接遍历，这让我们可以保持实现的简单性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(n) | 已接受 |
 | 最佳| O(nq) | O(n) | 简易版已接受 |

 ## 算法演练

 1. 读取树并存储其邻接表。 该树在任意两个城市之间只有一条简单路径，因此 DFS 足以恢复该路径上的城市。 
2. 按时间戳对所有查询进行排序。 当多个查询共享时间戳时，请将流星事件放在路径查询之前。 这符合流星到达时间的规则$t$此时已针对查询处于活动状态$t$。 
3. 为收到流星的城市维护两个数组。 一间店$v+t_0$，流星贡献的恒定部分，以及其他商店当前城市是否有流星。 
4. 对于流星查询，通过保存其值和降落时间来激活相应的城市。 每个城市最多更新一次，因此不需要删除逻辑。 
5. 对于路径查询，从起始城市运行DFS，直到找到目的地。 在展开递归的同时，添加该路径上每个城市的贡献。 对于城市中活跃的流星$x$， 添加：$$(v_x+t_x)-t$$在哪里$t$是查询时间。 

1. 按照原始查询顺序打印答案。 排序仅在内部使用以正确模拟时间。 

该算法背后的不变性是在处理任何查询之前$t$, 每一颗流星着陆时间最多$t$已经被激活了，未来流星还没有被激活。 路径查询仅访问所请求路径上的城市，因此它精确地总结了属于该路径的活跃贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    q = int(input())
    queries = []

    for i in range(q):
        data = list(map(int, input().split()))
        queries.append((data[1], 0 if data[0] == 1 else 1, i, data))

    queries.sort()

    active = [False] * n
    base = [0] * n
    ans = [0] * q

    def get_path_sum(start, target, time):
        stack = [(start, -1, 0)]
        parent = [-1] * n
        order = []

        while stack:
            node, par, state = stack.pop()
            if state == 0:
                parent[node] = par
                order.append(node)
                if node == target:
                    break
                for nxt in graph[node]:
                    if nxt != par:
                        stack.append((nxt, node, 0))

        cur = target
        total = 0
        while cur != -1:
            if active[cur]:
                total += base[cur] - time
            if cur == start:
                break
            cur = parent[cur]

        return total

    for time, _, _, data in queries:
        if data[0] == 1:
            _, t, x, val = data
            x -= 1
            active[x] = True
            base[x] = t + val
        else:
            _, t, a, b = data
            a -= 1
            b -= 1
            ans[_] = get_path_sum(a, b, t)

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```邻接表存储具有从零开始的索引的树，使遍历变得简单。 这`active`数组记录一个城市是否收到过流星，以及`base`存储转换后的值$v+t_0$。 这避免了为每个查询重新计算登陆时间调整。 

查询按时间排序。 排序元组中的第二个元素将相同时间戳的流星查询放在路径查询之前。 此顺序是必需的，因为流星着陆的时间$t$及时立即贡献$t$。 

路径搜索使用 DFS 堆栈来构建父信息，直到到达目的地。 到达目标后，代码将通过父指针向后行走，并仅累积该路径上的城市。 起始节点处的停止条件可防止意外添加不相关的分支。 

Python 整数会自动处理可能的大总和，因此不需要特殊的溢出处理。

 ## 边缘情况

 对于时间戳相等的情况：```
2
1 2
2
1 5 2 10
2 5 1 2
```首先处理流星查询，因为两个事件都发生在时间 5。存储的值为$10+5=15$，并且路径包含城市 2，所以答案是$15-5=10$。 该算法会处理此问题，因为排序同时将类型 1 查询置于类型 2 查询之前。 

对于路径过滤的情况：```
3
1 2
2 3
2
1 1 1 7
2 1 3
```1号城市的流星有贡献$7$在时间 1。从 1 到 3 的路径是$1 \rightarrow 2 \rightarrow 3$，所以它包括流星。 如果查询是从城市 2 到城市 3，则贡献将为零，因为城市 1 不在该路径上。 DFS 父重建确保仅计算路径城市。 

对于负衰减：```
1
2
2
1 0 1 0
2 10 1 1
```流星的基值为零。 在时间 10 时，其贡献为$0-10=-10$。 该代码直接计算该表达式并且从不应用下限，因此它返回所需的负结果。
