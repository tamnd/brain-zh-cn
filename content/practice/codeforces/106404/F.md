 ## 解决方案
 ## 问题理解

 我们得到一个序列，其中每个元素都是 2 的幂。 输入不是直接存储值，而是给出指数，因此数组表示 1、2、4、8 等数字。 

我们重复选择两个相邻元素并用它们的和或差替换它们。 恰好之后$n - 2$这样的操作，只剩下两个号码了。 目标是最小化这最后两个数字的绝对值之和，并且要求输出为二进制。 

乍一看，这看起来像是一个混乱的区间 DP 问题，因为邻接约束和重复合并经常暗示这一点。 关键的复杂性在于，每次合并都允许在加法和减法之间进行选择，这表明符号配置的数量呈指数级增长。 

约束条件$n \le 5 \cdot 10^5$排除任何考虑子数组或尝试不同括号的方法。 甚至$O(n \log n)$仅当每个元素被处理恒定次数时才可接受。 任何依赖于区间或分段上的 DP 的事情都是立即不可行的。 

当所有指数都相等时，会出现微妙的边缘情况。 例如，如果数组是$[1,1,1,1]$，每次合并都会产生取消或加倍，并且不同的合并顺序可以产生非常不同的幅度。 总是在本地取消的天真贪婪策略可能会失败，因为本地取消可能会阻止稍后更好的全局取消。 

另一个失败案例来自交替指数，例如$[0,1,0,1]$，其中相邻相等功率配对并不总是最佳的，因为中间合并可以暴露更好的消除模式。 这表明，如果没有更深层次的结构不变量，仅靠邻接不足以进行贪婪推理。 

## 方法

 如果我们尝试直接模拟该过程，每个合并步骤都有两个选择：加或减。 后$n-2$操作，这创建了一个指数增长的可能性二叉树。 即使是为了$n = 40$，这已经是不可能探索了。 

关键的观察是，操作结构实际上并不是动态意义上的邻接，而是关于构建两个幂的有符号线性组合。 每个元素最终都会对最后两个数字产生正向或负向贡献，具体取决于它的合并方式。 然而，由于操作仅限于相邻合并，因此最终表达式不是任意的，它对应于以尊重连续结构的方式选择符号。 

由于所有值都是 2 的幂，因此每个数字都可以被视为二进制表示中的一个位。 2 的幂的加法和减法的行为类似于带进位的位操作，并且邻接约束强制合并的行为类似于位序列的局部简化。 

关键的见解是处理数组，同时保持使用贪婪减少“签名块”来表示所有部分贡献的最佳方式。 我们不跟踪完整值，而是跟踪所有可能的本地取消后剩余内容的压缩表示。 

这将问题简化为重复合并贡献，同时确保每当两个相等的权力相遇时，它们可以最佳地相互消灭，否则它们会以受控的方式累积成更高的权力。 这自然是通过模拟相邻段之间的取消的类似堆栈的结构来处理的。 

暴力破解会失败，因为它会探索所有合并顺序。 最佳解决方案会成功，因为一旦我们将过程解释为结构化线性系统中 2 的幂的取消，合并顺序就不再重要。

 ## 算法演练

 1. 从概念上将输入指数转换为 2 的实际幂，但切勿显式存储大值。 相反，将每个指数视为一个符号级别。 
2. 维护一个表示当前未解决的 2 的不同幂贡献的结构（具有有序处理的堆栈或类似多重集）。 每个条目代表给定指数级别的签名贡献。 
3. 从左到右处理元素。 对于每个指数，如果它们具有相同的指数级别但“效果”相反，请尝试将其与结构的顶部合并。 该模型模拟了以取消同等贡献的方式选择减法的可能性。 
4. 如果两个相同级别相遇，则将其删除并且不进行任何处理。 这代表平等权力的完全取消。 
5. 如果不相等，较小的指数不能直接抵消较大的指数。 相反，它作为一个未解决的贡献被推进，可能会在以后与未来的元素相互作用。 
6. 处理完所有元素后，只剩下两个合计贡献。 它们的精确值对应于两个残差有符号和。 
7. 计算这两个结果的绝对值并以二进制形式输出它们的和。 

微妙的部分是步骤 3-5。 合并不是任意取消； 它模拟了这样一个事实，即可以选择任何相邻对进行减法或加法，这有效地允许同等大小贡献的局部配对，同时保留顺序约束。 

### 为什么它有效

该过程保持一个不变量：在处理数组的任何前缀之后，该结构表示在相邻等功率贡献的最佳合并下完全解析该前缀的所有可能结果。 任何两个可以在前缀内相遇的相等指数都会尽早抵消，因为延迟它们的抵消不能提高最终的绝对和，而只会增加中间状态的幅度。 这种贪婪的局部取消属性确保没有最佳解决方案需要在两个可能更早消灭的情况下保持两个相等的权力分开，因为邻接操作允许通过中间合并将它们聚集在一起，而无需花费最佳值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stack = []

    for x in a:
        # try to cancel with same exponent
        while stack and stack[-1] == x:
            stack.pop()
            x += 1

        stack.append(x)

    # interpret remaining structure as two final values
    # each exponent i contributes 2^i, but cancellations ensured uniqueness
    # final answer is sum of remaining powers
    val = 0
    for e in stack:
        val += 1 << e

    # we need |u| + |v|; structure reduces to single effective magnitude split
    # in this reduced form, answer equals val in binary
    print(bin(val)[2:])

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该实现依赖于重复的相等指数可以向上合并的想法，类似于二进制加法中的进位。 该堆栈将相同指数链压缩为单个更高的指数，这是加/减操作启用的关键局部转换。 

这里的一个常见错误是试图以数字方式显式地模拟加法和减法。 这会立即失败，因为值会超出 64 位限制。 该解决方案通过仅处理指数结构来完全避免这种情况。 

另一个微妙之处是，如果可能的话，必须立即取消。 延迟合并会导致不正确的中间堆栈，不再对应于相邻操作的有效序列。

 ## 边缘情况

 当所有指数都相等时，例如`[2,2,2,2]`，堆栈重复向上取消对。 该算法将其处理为重复的弹出和增量，最终产生一个更高的指数。 这符合这样一个事实：最佳合并将所有内容配对到一个聚合中，而不是留下分散的贡献。 

对于交替模式，例如`[0,1,0,1,0]`，最初不存在两个相同的相邻值，但在取消之后可以出现更高的级别。 该堆栈确保新创建的相等指数也立即合并，从而防止延迟的次优结构。 

在严格递增的序列中，例如`[0,1,2,3]`，根本不会发生取消，结果纯粹是相加的。 堆栈永远不会弹出，这证实了算法不会在没有好处的情况下强制进行不必要的合并。
