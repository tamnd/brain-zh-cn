 ## 解决方案
 ## 问题理解

 我们从一个由小写字母组成的字符串开始。 每个字母都不是静态的：它根据大小为 26 的固定替换表扩展为另一个字符串。如果一个字符是`x`，它被字符串替换`p_x`。 该操作的一个应用程序会同时替换当前字符串中的每个字符。 

重复这个变换后`k`有时，字符串可能会变得非常大。 我们没有构造它，而是被问到一个更具体的问题：位置上的字符是什么`i`（1-索引）在最终扩展字符串中？ 

关键的难点是两者`k`和`i`可以很大。 索引可以大到 10^18，这使得任何显式构建字符串的方法都不可能。 即使跟踪完整的字符串长度也是不可行的，因为它会随着每个转换步骤呈指数增长。 

完全模拟每次扩展的幼稚方法很快就会失败。 即使每个字母最多扩展到 10 个字符，经过 20 个步骤后，字符串的大小已经超过 10^20，并且如果不构造索引，就不可能对其进行索引。 

当扩展产生空字符串或短字符串时，会出现微妙的边缘情况。 假设每个字符均匀增长或尝试维护前缀和而不仔细传播结构的粗心方法可能会破坏诸如重复映射到单个字符的字母等情况，从而创建没有分支的长链。 

例如，如果`a -> b`,`b -> c`,`c -> c`，然后经过许多步骤后，整个字符串会折叠成一个重复的字符。 即使答案是由单个依赖链确定的，基于扩展的简单模拟仍可能不必要地尝试重建完整的中间字符串。 

## 方法

 核心问题是该转换定义了字符的定向重写系统。 每个字母变成一个字符串，该字符串定义索引如何向前传播。 

暴力方法直接在每个之后构造完整的字符串`k`转变。 每个步骤都会通过其扩展来替换每个字符。 如果 k 步后的总长度为 N，则每次转换的成本为 O(N)，并且 N 本身呈乘法增长。 即使在最小的限制下，这也会很快超出可行性。 核心原因是，即使查询只需要一个位置，我们也会重复重新计算整个字符串。 

关键的观察是我们永远不需要完整的字符串。 我们只需要知道位置如何通过变换向后映射。 我们不是向前扩展，而是跟踪最终字符串中的索引如何源自较早的字符串。 

如果我们知道，对于每个角色`c`，t步后扩展的长度，我们可以决定哪个字符贡献第i个位置。 一旦我们确定了它来自哪个字符，我们就减去前缀偏移量并继续递归执行上一步。 

这表明了反向模拟：我们不构建字符串，而是维护一个函数`len[c][t]`描述字符的扩展多长时间`c`成为之后`t`步骤。 然后，为了回答查询，我们从步骤`k`下降到 0，每次选择正确的子段。 

计算`len[c][t]`，我们使用动态规划。 在步骤 0，每个字符的长度为 1。对于转换，长度为`c`在步骤 t 是字符长度的总和`p_c`在步骤t-1。 自从`k`最大可达 10^4，我们迭代计算这些值。 

一旦长度已知，回答查询就变成了确定性下降：在每一步，我们都定位扩展中的哪个字符包含位置`i`，然后更新`i`因此。

 ## 算法演练

 我们将解决方案分为扩展长度的预处理和查询遍历。 

1. 预先计算一个表`len[c][t]`， 在哪里`len[c][t]`是扩展字符得到的字符串长度`c`确切地`t`次。 我们初始化`len[c][0] = 1`因为在第 0 步，每个字母都是它自己。 这构成了我们递归的基本情况。 
2. 对于每一步`t`从 1 到`k`, 计算`len[c][t]`通过迭代中的字符`p_c`。 对于每个角色`x`在`p_c`，我们添加`len[x][t-1]`。 这是有效的，因为一个转换取代了`c`和`p_c`，并且该字符串中的每个符号根据先前的步长独立扩展。 
3. 回答询问`(s, k, i)`，我们首先从概念上开始于步骤`k`和位置`i`在初始字符串的扩展内`s`。 
4. 我们迭代的字符`s`，将每个视为一个块，其大小为`len[c][k]`。 我们找到第一个块`i`瀑布。 一旦确定，我们减去早期块的大小并专注于该字符。 这将问题简化为在单个字符的扩展中寻找答案。 
5. 现在我们重复模拟单个角色从step的下降`k`到步骤 0。在步骤`t`，我们看`p_c`并确定哪个字符的扩展包含位置`i`在级别上使用预先计算的长度`t-1`。 我们减去前缀和，直到找到正确的子项，然后在步骤中继续该子项`t-1`。 
6. 什么时候`t`到达 0 时，我们就到达了一个基本字符，这就是答案。 

### 为什么它有效

 在每个递归级别，我们都保持以下不变式：`i`指特定字符扩展内特定深度的有效位置。 DP表保证每一步的段长度都是正确的，因此前缀减法总是选择正确的子树。 由于每个变换都是不相交的扩展串联，因此位置映射是明确定义的并且绝不会含糊不清。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    while True:
        line = input().strip()
        if not line:
            return
        parts = line.split()
        if not parts:
            continue

        s = parts[0]
        k = int(parts[1])
        i = int(parts[2])

        p = [input().strip() for _ in range(26)]

        # dp[c][t] = length after t expansions
        dp = [[0] * (k + 1) for _ in range(26)]

        for c in range(26):
            dp[c][0] = 1

        for t in range(1, k + 1):
            for c in range(26):
                total = 0
                for ch in p[c]:
                    total += dp[ord(ch) - 97][t - 1]
                    if total > 10**18:
                        total = 10**18
                dp[c][t] = total

        # find starting character at level k
        cur_i = i
        cur_t = k

        # reduce from initial string s
        for ch in s:
            c = ord(ch) - 97
            if cur_i > dp[c][cur_t]:
                cur_i -= dp[c][cur_t]
            else:
                cur = c
                break

        # descend
        while cur_t > 0:
            for ch in p[cur]:
                nxt = ord(ch) - 97
                if cur_i > dp[nxt][cur_t - 1]:
                    cur_i -= dp[nxt][cur_t - 1]
                else:
                    cur = nxt
                    cur_t -= 1
                    break

        print(chr(cur + 97))

if __name__ == "__main__":
    solve()
```第一阶段构建一个 DP 表，其中每行对应一个字母，每列对应所应用的转换数量。 10^18 处的饱和度是防止溢出的实际保障，因为我们只需要与 i 进行比较，而不是精确的巨大值。 

初始循环结束`s`将问题从多字符字符串折叠为具有调整后的索引的单个起始字符。 第二个循环执行变换树的实际逆遍历，使用前缀减法来决定哪个分支包含目标位置。 

关键的实现细节是始终使用正确的深度`cur_t - 1`检查儿童时。 DP 级别和遍历级别之间的任何不匹配都会立即破坏正确性。

 ## 边缘情况

 一种脆弱的情况是查询索引恰好落在初始字符串中两个扩展字符之间的边界上。 认为`s = "ab"`， 和`a`扩展到长度 3 并且`b`最后一步长度为 2，并且`i = 3`。 该算法首先检查`a`，看到`i`在它的块内，并且正确地不会减去它。 如果相反`i = 4`，它减去全长`a`并继续在里面`b`。 这种边界处理完全取决于严格的`>`前缀减法中的比较。 

另一种情况是深度单字符链，例如`a -> b -> c -> c`。 即使在大`k`，DP 表稳定，并且遍历简单地遵循确定性的指针链。 该算法从不需要扩展字符串，只需通过递减的级别重复解析单个索引。 

第三个案例非常大`i`。 由于我们将 DP 值限制为 10^18，因此比较仍然有效。 即使实际扩展超出了该上限，正确性仍然保留，因为我们只需要知道是否`i`位于段内部或外部，而不是其超出阈值的确切大小。
