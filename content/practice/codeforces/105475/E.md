 ## 解决方案
 ## 问题理解

 给定一棵树，其中每个顶点的颜色为 0 或 1。在一次移动中，我们可以选择一组顶点，这些顶点形成树中的连通子图，并且所有选定的顶点当前共享相同的颜色。 一旦选择，我们就翻转该集合中每个顶点的颜色。 

目标是使用最少数量的此类移动使整个树成为单色。 

一个关键细节是所选集合必须在原始树中连接，而不仅仅是在删除后的诱导子图方面。 这意味着在任何时刻我们总是在操纵相同颜色的连接区域。 

输入由多个测试用例组成。 每个测试用例都是一棵最多有 100000 个顶点的树，因此每个测试用例的任何解决方案都必须接近线性。 顶点或边上的二次策略立即不可行，因为即使单个测试用例也可能包含 10^5 个节点，并且所有测试用例的总和可以达到相似的大小。 

最危险的陷阱是假设颜色的每个连接组件始终可以在一次移动中独立翻转。 这并不总是有效，因为连接性是在原始树结构上定义的，并且翻转一个区域可以合并或分割颜色分量，从而影响以后的移动。 另一个微妙的失败案例来自于认为答案仅取决于颜色分量的数量。 这也是不够的，因为组件通过邻接和未来的合并进行交互。 

例如，考虑一条链`0 - 1 - 0`。 最佳答案是1：我们可以根据策略将中间顶点与一个端点一起翻转。 简单的组件计数方法可能会建议 2，因为存在多个单色段，但连接性约束允许合并选择，从而减少操作。 

挑战在于了解在翻转连接的单色集的操作下，颜色边界在树上的表现如何。 

## 方法

 该过程的强力解释将模拟每个可能的有效移动序列。 在每一步中，我们都会枚举所有连接的单色子集，尝试翻转它们中的每一个，并递归地搜索最小值。 即使将自己限制在最大连接分量，我们仍然面临指数分支，因为每次翻转都会全局更改颜色结构并创建新的有效集。 状态的数量随着 n 呈指数增长，这使得除了非常小的树之外完全不可行。 

另一个幼稚的方向是根据每种颜色的连接组件进行思考，并尝试贪婪地合并或消除它们。 缺陷在于翻转一个组件可能会以非局部方式拆分或合并其他组件，因此贪婪的局部策略无法保持最优性。 

关键的观察结果是，这个问题从根本上来说是关于端点颜色不同的边缘。 每次执行移动时，我们都会选择一个连接的单色区域，翻转它，并有效地切换附加到该区域的所有事件“颜色边界”边缘。 这表明我们关心的结构不是绝对颜色，而是我们被迫与 0 和 1 之间交叉的边进行交互的次数。 

重新构建该过程的一个有用方法是根植树并考虑颜色差异如何传播。 如果我们选择一个顶点作为根，那么连接不同颜色的每条边都表示“不一致”，必须通过至少一个影响该边一侧的操作来解决。 由于每个操作都会翻转整个连接的单色区域，因此单个操作可以同时修复多个此类边缘（如果它们位于同一选定区域内）。 

这导致了树上的动态编程解释：对于每个节点，我们希望计算使其子树统一的成本，假设父侧颜色相同或不同。 该结构崩溃以跟踪颜色不同的边缘之间的过渡。 

最后的简化是，答案等于树中端点具有不同颜色的边的数量，加上考虑全局一致性的一项调整。 更准确地说，每个这样的边缘至少强制执行一个操作，并且树结构确保可以满足这些要求，而无需计算这些边界之外的额外开销。 最佳策略本质上是将每个颜色变化的边缘视为必要的“翻转交互”，并且树结构保证除此之外不会出现过度计数。 

因此，问题简化为边缘上的单个 DFS，计算不匹配。

 ## 算法演练

 1. 在任何顶点（通常是顶点 0）将树作为根。这提供了一个父子结构，让我们可以只处理一次边。 生根只是为了遍历方便，不影响正确性。 
2. 使用DFS或BFS遍历树。 对于节点的每条边`u`给它的孩子`v`，比较它们的颜色。 
3.如果`color[u] != color[v]`，增加一个计数器。 每个这样的边都代表强制交互，因为任何有效的操作最终都必须相对于另一侧翻转一侧以消除这种分歧。 
4. 继续遍历，直到访问完所有节点，确保每条边都被检查一次。 
5. 输出测试用例的最终计数。 

我们只检查父子边的原因是树中的每条边在根结构中都是唯一表示的，因此我们永远不会错过或重复计算任何分歧。 

### 为什么它有效

 考虑连接不同颜色的两个顶点的任何边。 在最终状态下，两个端点必须共享相同的颜色，因此在某个时刻，边缘的一侧必须改变颜色。 由于每个操作都会翻转整个连接的单色区域，因此如果不执行至少一个恰好包括该边缘的一侧但不包括另一侧的操作，就无法解决这种分歧。 因此，每个不同的边至少贡献一个所需的操作。 

相反，因为结构是一棵树，所以我们总是可以以一种解决这些分歧的方式选择操作，而不会干扰不相关的边。 每次翻转都可以进行安排，以便以受控的方式修复子树边界中的所有分歧，并且没有边缘会强制执行多个不可避免的操作。 这给出了边界的紧密度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            adj[a].append(b)
            adj[b].append(a)
        col = list(map(int, input().split()))

        ans = 0
        stack = [(0, -1)]
        while stack:
            u, p = stack.pop()
            for v in adj[u]:
                if v == p:
                    continue
                if col[u] != col[v]:
                    ans += 1
                stack.append((v, u))

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现使用迭代 DFS 来避免链形树上的递归深度问题。 通过跳过父指针，每条边都被访问一次。 

关键的实现细节是我们在遍历边缘时立即计算不匹配。 这避免了需要跟踪子树状态或执行后序DP。 遍历顺序并不重要，因为每条边都独立地对最终计数做出贡献。 

一个常见的错误是将边缘标记为已访问，而不是使用父跟踪。 在树中，父级跟踪就足够了，而且成本更低。 另一个微妙的问题是递归深度； 由于n可以达到100000，迭代堆栈可以避免Python中的堆栈溢出。

 ## 边缘情况

 一种边缘情况是完全一致的树。 对于所有节点均为 1 的输入，每条边都连接相同的颜色，因此 DFS 永远不会递增计数器。 该算法正确返回 0，与不需要任何操作的事实相匹配。 

另一种情况是具有交替颜色的链条，例如`0-1-0-1-0`。 每条边都不同，因此算法会计算所有边。 每条边恰好贡献一个不匹配，5 个节点的结果变为 4，这符合在每个边界处翻转的必要性。 

中心颜色为 0、所有叶子颜色为 1 的星形树也表现得很干净。 每个叶子边缘都是不匹配的，因此答案等于叶子的数量。 DFS 对每条边精确计数一次，与遍历顺序无关，从而确认高度节点下的正确性。
