 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组点，每个点最初持有一只鸡。 如果我们可以使用一系列跳跃从一个位置移动到另一个位置，则两只鸡被认为是相连的，其中每次跳跃必须严格短于选定的值$k$。 换句话说，如果两个位置在距离内$k$，我们可以将它们视为直接连接，并且连接通过中间位置是传递的。 

这会将位置集转换为一个图形，其中距离小于的任何点对之间都存在边$k$。 作为$k$增长，出现更多边，组件合并，并且组件内可达对的数量增加。 

对于每个测试用例，我们被要求找到最小值$k$这样在这些连接的组件中可以相互到达的鸡对总数至少为$a$。 

这些限制迫使我们走向$O(n \log n)$或者$O(n \log \text{range})$每个测试用例的方法。 和$n$最多$10^5$，任何对所有对的二次推理或连接的重复重新计算都太慢，因为它需要最多$10^{10}$最坏情况下的距离检查。 

一个微妙的一点是，连通性不仅仅涉及直接距离。 即使两个点相距很远，如果存在中间点链，它们仍然可能属于同一个组件。 一个天真的错误是只计算直接距离小于的对$k$，这低估了可达对的数量。 

当所有点都非常接近时，就会出现另一种边缘情况。 例如，如果位置是$[1,2,3,4]$和$k=3$，然后整个集合成为一个组件，产生所有$\binom{4}{2}=6$对，尽管并非所有对的距离都直接小于 3。 任何解决方案都必须正确考虑传递闭包。 

## 方法

 关键的观察是在一维中，对位置进行排序完全决定了连接结构。 排序后，组件唯一可以“中断”的地方是连续点之间的间隙。 

如果我们固定一个值$k$，那么距离小于的任意两个连续点$k$属于同一个组件链，任意间隙尺寸至少$k$将生产线分成单独的组件。 这减少了从任意图连接到通过对相邻差异进行阈值分组的问题。 

一旦组件形成，计算每个组件内的可达对就很简单：大小的组件$s$贡献$\frac{s(s-1)}{2}$对。 

所以对于一个固定的$k$，我们可以计算排序后线性时间内有效对的数量。 剩下的任务是找到最小值$k$使得该值至少达到$a$。 自从增加$k$仅合并组件并单调增加对的数量，二分搜索$k$是有效的。 

蛮力的想法会尝试所有可能的方法$k$0 到 之间的值$10^9$，并为每个值重新计算组件和对计数$O(n)$。 这导致$O(n \cdot 10^9)$，这是不可能的。 二分搜索将求值次数减少到 30 左右，从而提供了有效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \cdot \max x)$|$O(n)$| 太慢了|
 | 最优（排序+二分查找）|$O(n \log n + n \log \max x)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对位置数组进行排序，以便邻接对应于沿线增加的距离。 这确保任何有效路径必须通过连续的索引。 
2. 定义函数`count_pairs(k)`计算当允许的最大跳跃为时存在多少个朋友对$k$。 该函数处理排序后的数组，并在连续点之间的间隙至少为$k$。 每次组件结束时，其贡献都会添加为$s(s-1)/2$， 在哪里$s$是元件尺寸。 
3. 使用二分查找$k$，搜索空间从 0 到端点之间的最大距离。 对于每个中点$k$, 计算`count_pairs(k)`。 
4. 如果`count_pairs(k)`至少是$a$，我们尝试较小的值，因为我们想要最小有效阈值。 Otherwise, we increase$k$合并更多组件。 
5、二分查找完成后，左边界最小$k$即满足条件。 

步骤 2 正确的关键原因是，在排序数组中，任何连接链都必须经过相邻点，因此组件正是最大段，其中相邻间隙低于$k$。 

### 为什么它有效

 排序的结构将问题转化为路径图的边缘阈值化。 对于固定的$k$，边缘仅存在于间隙小于的连续点之间$k$，这完全决定了连通性。 任何非连续连接都必须已经由此类边的序列所隐含，因此除了相邻比较之外，没有其他边会改变组件结构。 由于组件大小唯一地决定了可达对的数量，并且该数量随着$k$，二分查找正确地隔离了最小可行阈值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_pairs(x, k):
    n = len(x)
    total = 0
    size = 1

    for i in range(1, n):
        if x[i] - x[i - 1] < k:
            size += 1
        else:
            total += size * (size - 1) // 2
            size = 1

    total += size * (size - 1) // 2
    return total

def solve_case(n, a, x):
    x.sort()

    lo, hi = 0, x[-1] - x[0] + 1

    while lo < hi:
        mid = (lo + hi) // 2
        if count_pairs(x, mid) >= a:
            hi = mid
        else:
            lo = mid + 1

    return lo

def main():
    t = int(input())
    for _ in range(t):
        n, a = map(int, input().split())
        x = list(map(int, input().split()))
        print(solve_case(n, a, x))

if __name__ == "__main__":
    main()
```该解决方案首先依赖于排序，因为未排序的输入会错误地将不相关的点视为线结构中的相邻点。 这`count_pairs`函数会仔细累积组件大小，并在出现足够大的间隙时刷新每个段。 

一个常见的实现错误是忘记在循环后添加最后一个组件，这会低估对的数量。 另一个微妙的问题是使用`<= k`而不是`< k`在连通状态下； 该问题定义了严格的不平等，因此阈值检查必须完全匹配。 

选择二分搜索范围，以便`hi`作为连接所有点的上限始终有效。 使用`x[-1] - x[0] + 1`保证即使是最大可能的间隙条件也被安全地包括在内。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, a = 2
x = [1, 2, 4]
```我们二分查找一遍$k$。 排序数组已经给出。 

| k | 组件| 尺寸 | 对数 |
 | ---| ---| ---| ---|
 | 0 | [1]、[2]、[4] | 1,1,1 | 0 |
 | 1 | [1,2],[4] | 2,1 | 1 |
 | 2 | [1,2,4]| 3 | 3 |

 我们至少需要 2 对。 在$k=1$，我们只有 1 对，这是不够的。 在$k=2$，我们得到3对，满足要求，所以答案是2。 

该跟踪表明，连接性是通过合并相邻间隙来驱动的，并且一旦允许单个间隙，组件就可以传递扩展。

 ## 边缘情况

 对于不允许跳转的配置，例如`x = [5, 20, 100]`和$k = 0$，每个点都形成自己的组成部分。 该算法处理每个间隙，发现所有差异都超过或等于$k$，并刷新单例组件，产生零对，这是正确的。 

对于像这样的完全连接的情况`x = [1, 2, 3, 4]`具有足够大的$k$，循环永远不会触发拆分，因此最终的刷新会生成大小为 4 的单个组件并返回 6 对。 这证实了最后一个组件的处理是至关重要的。 

对于紧密集群但未完全连接的情况，例如`x = [1, 3, 6, 10]`，正确性完全取决于每个相邻差值是否低于$k$。 一旦间隙超过阈值，算法就会正确隔离组件，确保连接性永远不会被高估。
