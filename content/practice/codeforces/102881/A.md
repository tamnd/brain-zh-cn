 ## 解决方案
 ## 问题理解

 我们需要找到字符串中可以从左到右遍历并用于收集字母的最短连续部分`A`,`B`,`C`, ...,`Z`为了。 所选部分不需要直接等于字母表。 允许使用额外的字符，只要其中存在一个子序列，该子序列恰好是按升序排列的字母表。 

每个测试用例给出一串大写英文字母。 答案是其字符包含完整字母表作为子序列的子字符串的最小长度。 输入保证这样的子字符串存在。 

字符串的长度最多为 777，测试用例的数量最多为 44。这些限制足够小，可以实现二次解。 如果检查有效，则尝试每个子字符串并仔细检查它的解决方案是可以接受的。 立方方法仍然存在风险，因为在最坏的情况下 777³ 的运算量接近 5 亿次。 

主要的边缘情况是由字母的额外副本和包含每个字符但不按所需顺序的子字符串引起的。 

例如，考虑：```
1
26
ABCDEFGHIJKLMNOPQRSTUVWXYZ
```答案是：```
26
```一个粗心的实现，只计算每个字母是否出现，在这里是可行的，但这个想法在顺序错误的字符串上失败了。 

例如：```
1
26
ZYXWVUTSRQPONMLKJIHGFEDCBA
```此输入的答案无效，因为无法形成字母表子序列。 基于频率的方法会错误地认为每个所需的字符都存在。 

另一个棘手的情况是当较短的窗口隐藏在较大的有效区域内时。 

例子：```
1
29
XXXABCDEFGHIJKLMNOPQRSTUVWXYZ
```答案是：```
26
```找到第一个有效子字符串并且从不缩小它的解决方案将输出 29，从而缺少最佳答案。 

## 方法

 直接的方法是尝试每一个可能的子串。 对于每个起始位置，我们一次扩展结束位置一个字符，并检查当前子字符串是否包含字母表作为子序列。 如果是，我们记录它的长度并继续搜索更小的长度。 

这种方法是正确的，因为每个可能的答案都是某个子字符串，并且我们显式地检查所有这些子字符串。 昂贵的部分是检查过程。 有 O(n²) 个子串，如果每次检查都扫描子串，最坏的情况变为 O(n³)。 当 n = 777 时，这大约是 4.7 亿个字符检查，这是不必要的。 

关键的观察是我们需要的属性是单调的。 如果子串包含`ABCDEFGHIJKLMNOPQRSTUVWXYZ`作为子序列，添加更多字符不能使该属性为假。 有效窗口在展开时保持有效。 这允许我们使用滑动窗口。 

我们保留两个描述当前窗口的指针。 我们扩展右侧直到窗口变得有效。 一旦有效，从左侧删除字符只能使其变短，因此我们在属性保持 true 的情况下反复从左侧缩小。 这会找到以当前右指针结束的最短有效窗口。 

剩下的问题是如何快速测试有效性。 由于所需的子序列只有26个字符，因此我们可以存储匹配所需的最新信息。 对于当前窗口，我们扫描它并贪婪地匹配下一个所需的字母。 窗口大小最多为 777，因此此检查很便宜。 另一种实现可以维护更多状态，但简单版本已经足够快了。 

蛮力方法之所以有效，是因为它会检查每个候选人。 它失败了，因为它在重叠的子字符串上重复了类似的工作。 滑动窗口通过利用可以安全地从左侧缩短有效窗口的事实来避免这种重复。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 在最坏的情况下太慢|
 | 滑动窗 | O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从一个空窗口开始，将两个指针放在字符串的开头。 当前窗口代表我们正在测试的字符串部分。 
2. 向前移动右指针并将新字符包含在窗口中。 每次展开后，检查当前窗口是否包含字母表作为子序列。 扩展是必要的，因为在我们找到有效窗口之前不可能出现更短的窗口。 
3. 当窗口有效时，用当前长度更新答案。 这记录了以此右指针结束的最佳解决方案。 
4. 在窗口保持有效的情况下向前移动左指针。 每次成功的删除都会创建一个较小的有效子字符串，因此也必须予以考虑。 
5. 继续，直到右指针到达字符串末尾。 最小的记录窗口就是答案。 

为什么它有效：

 该算法保持了这样的不变性：每次窗口有效时，它都是收缩阶段后结束于当前右边界的最小有效窗口。 任何最佳答案都有一些正确的边界。 当算法到达该边界时，它会扩展到足以变得有效，然后从左侧删除所有不必要的字符。 因为考虑了所有可能的右边界，所以找到了全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def valid(s, l, r):
    need = 0
    for i in range(l, r + 1):
        if s[i] == chr(ord('A') + need):
            need += 1
            if need == 26:
                return True
    return False

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        left = 0
        best = n

        for right in range(n):
            while left <= right and valid(s, left, right):
                best = min(best, right - left + 1)
                left += 1

        ans.append(str(best))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`valid`函数检查当前子字符串是否可以产生字母表。 它贪婪地搜索下一个所需的字母。 一旦找到所有 26 个字母，该函数就会立即返回，因为进一步的扫描无法更改结果。 

主循环控制滑动窗口。 右指针始终向前移动，添加更多字符。 左指针只有在窗口有效后才会向前移动，因此每个位置都会按顺序处理，不会向后移动。 

收缩环中的边界条件很重要。 我们必须允许测试单字符窗口，所以条件是`left <= right`。 答案初始化为`n`因为根据问题保证，整个字符串始终是有效的上限。

 ## 边缘情况

 对于反向字母表，该算法永远不会将窗口标记为有效，因为贪婪匹配顺序无法从`A`到`B`以及以后。 仅频率解决方案在这里会失败，因为它忽略了排序。 

对于答案之前包含不必要字符的字符串，算法会扩展直到找到字母表，然后立即测试删除这些字符。 这正是滑动窗口不会停在第一个有效子串处的原因。 

对于包含多个可能的字母子序列的字符串，贪心有效性检查就足够了，因为我们只需要存在性。 下一个所需字母的最早出现总是为后面的字母留下最多的剩余空间，因此找到一个完整的子序列证明该窗口是有效的。 

您可以通过替换有效性检查，同时保持相同的收缩窗口推理，使这种编辑风格适应其他子序列窗口问题。
