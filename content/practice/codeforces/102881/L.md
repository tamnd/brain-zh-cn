 ## 解决方案
 ## 问题理解

 该问题描述了所有可能的随机过程`n`位数字。 我们从一个值开始`x = 0`。 每一步都是随机的`n`位数`r`被统一选择并异或为`x`。 游戏第一次停止`x`初始状态后再次变为零。 我们需要移动次数平方的期望值。 最初的问题来自 Codeforces Gym 102881L。 

输入包含多个值`n`， 在哪里`n`可以大到`10^9`。 这立即排除了任何迭代位、状态或值的方法`0`到`2^n`。 即使是线性算法`n`对于最大的输入来说太慢，因此解决方案必须将数学简化为恒定数量的模幂运算。 

棘手的部分不是实现，而是正确理解概率分布。 一个常见的错误是将后面的位置视为依赖于先前的 XOR 值。 另一个错误是忘记第一步可以立即归零。 

为了`n = 1`，答案是`2`。 可能的动作正在选择`0`或者`1`。 第一步立即以概率返回`1/2`，否则下一步必须返回。 假设第一步无法完成的粗心公式会给出错误的期望。 

为了`n = 2`，答案是`28`。 状态空间包含四个值。 第一步有概率`1/4`立即完成。 在任何失败的移动之后，下一个位置再次均匀随机，因此该过程的行为就像具有成功概率的重复独立试验`1/4`。 

## 方法

 直接模拟将尝试对所有可能的 XOR 状态进行建模。 有`2^n`的可能值`x`，因此基于状态的动态编程方法将需要指数级的内存和时间。 例如，与`n = 60`，状态的数量已经远远超出了任何程序可以存储的范围。 

第二个强力想法是多次模拟随机过程并估计期望。 这是不可接受的，因为输出需要精确的模值`10^9 + 7`，随机模拟并不能保证正确答案。 

关键的观察是异或与均匀随机`n`位值会破坏所有先前的信息。 每次移动后，结果`x`均匀分布在`2^n`可能的值。 当前举措之前的历史并不重要。 

让`N = 2^n`。 每一步都有概率`1/N`产生零。 一次移动失败后，同样的情况会再次出现，因此移动次数遵循成功概率的几何分布`p = 1/N`。 

对于计算第一次成功之前的试验次数的几何随机变量，二阶矩为：`E(m^2) = (2 - p) / p^2`替代`p = 1/N`给出：`E(m^2) = (2 - 1/N) * N^2`简化为：`E(m^2) = 2N^2 - N`自从`N = 2^n`，答案就变成：`2^(2n + 1) - 2^n`只需要模幂运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 最佳| O(log n) | O(1) | O(1) | 已接受 |

2. 计算`a = 2^n mod (10^9 + 7)`使用快速求幂。 

该值表示 XOR 状态空间的大小以所需答案模数为模。 
3. 计算`b = 2^(2n + 1) mod (10^9 + 7)`。 

预期的平方是`2^(2n + 1) - 2^n`，所以这是公式的第一项。 
4. 输出`(b - a) mod (10^9 + 7)`。 

模减法可能会变成负数，因此语言实现必须对其进行规范化。 

为什么它有效：

 解决方案背后的不变性是，每次移动后，无论之前的值如何`x`，新值均匀分布在所有`2^n`州。 因此，每一步都有相同的概率结束游戏，并且每一次失败的一步都会使进程处于完全相同的概率情况。 这给出了一个几何分布，其二阶矩直接产生所需的公式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        first = pow(2, n, MOD)
        second = pow(2, 2 * n + 1, MOD)
        ans.append(str((second - first) % MOD))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该代码使用 Python 内置的模幂运算，因为它可以处理巨大的指数`2n + 1`有效地进行二进制求幂。 

变量`first`商店`2^n`，这是可能的 XOR 状态的数量。 变量`second`存储术语`2^(2n+1)`。 最终的减法直接从导出的表达式得出。 

Python 中不存在溢出问题，并且模幂使计算量保持较小。 唯一可能的错误是使用`2 ** n`直接，这将尝试创建一个具有数十亿位的数字。 

## 工作示例

 对于`n = 2`，状态空间大小为`2^2 = 4`。 

| 步骤| n | 2^n | 2^n | 2^(2n+1) | 2^(2n+1) | 回答 |
 | --- | --- | --- | --- | --- |
 | 计算幂| 2 | 4 | 32 | 32 32 - 4 = 28 | 32 - 4 = 28

 这证实了小状态空间的公式，其中该过程也可以手动推理。 

为了`n = 3`，状态空间大小为`2^3 = 8`。 

| 步骤| n | 2^n | 2^n | 2^(2n+1) | 2^(2n+1) | 回答 |
 | --- | --- | --- | --- | --- |
 | 计算幂| 3 | 8 | 128 | 128 128 - 8 = 120 |

 第二个例子表明，答案随着可能状态的数量呈二次方增长，而不是与位数呈线性增长。

 | 测量 | 复杂性 | 说明|

import io

MOD = 10**9 + 7

def solution(inp):
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    t = int(input())
    out = []

 ## 边缘情况

 对于`n = 1`，算法计算：`2^(3) - 2^(1) = 8 - 2 = 6`这不是最终的整数期望，因为答案是对问题公式取模。 重新检查公式得出：`2^(2n+1) - 2^n = 2^3 - 2 = 6`对于一位来说，期望的平方确实是`6`。 最小的情况很有用，因为它揭示了实现是否错误地假设第一步无法结束游戏。 

为了`n = 2`，计算为：`2^(5) - 2^2 = 32 - 4 = 28`该算法将每次移动视为具有相同的成功概率，这是有效的，因为与随机值的异或总是创建均匀分布。 

对于非常大的`n`， 例如`1000000000`，该算法从不构造`2^n`。 它仅执行模幂运算，因此尽管存在大量可能的异或状态，但执行时间仍然很短。
