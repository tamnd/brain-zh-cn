 ## 解决方案
 # 问题理解

 我们得到一个连接的加权图和一个正值数组`s`。 任务是找到最小的索引顶点`x`使得每个顶点写入的值恰好是距`x`到那个顶点。 特殊条件是入住`x`不被视为有效的零长度路径，因此该值`x`它本身是起始和结束于的最短非空闭合步行的长度`x`。 该图具有正边权重，没有平行边或自环。 

限制足够大，不可能尝试每个顶点作为可能的起点。 高达`2 * 10^5`顶点和边，单个 Dijkstra 运行是可以接受的，但是从每个顶点运行一次将需要大约`O(n * (n + m) log n)`操作，这远远超出了可用时间。 该解决方案需要同时提取有关所有可能的起始顶点的信息。 

问题的不寻常部分是存储在源顶点的值。 在正常的最短路径数组中，源将包含`0`。 这里它包含在该顶点开始和结束的最短正循环。 在具有正权重的无向图中，该值是入射到该顶点的最小边权重的两倍，因为最便宜的闭合游走可以穿过最轻的相邻边并立即返回。 

一个常见的错误是接受与所有其他顶点具有正确距离的顶点，但忘记验证其自身的值。 例如：```
3 2
4 2 2
1 2 2
2 3 2
```正确的输出是`2`。 顶点`2`到达顶点`1`和`3`在距离上`2`，其最短非空回程也是`4`。 仅检查到其他顶点的距离的粗心解决方案可能会错误地接受顶点`1`或者`3`，因为它们到某些顶点的向外距离相同，但它们的自距离应该是`4`， 不是`2`。 

当多个顶点可以满足数组时，会出现另一种边缘情况。 该问题要求最小的索引。 例如：```
4 4
6 3 6 6
1 3 6
1 2 3
3 2 3
4 2 3
```正确的输出是`1`。 几个距离关系看起来是对称的，但只需要打印最小的有效索引。 

最后一个陷阱是不可能的距离阵列。 例如：```
3 3
1 5 5
1 2 2
2 3 2
1 3 10
```输出是`-1`。 这些值声称可以用比图实际允许的距离更小的距离到达某个顶点，因此没有起始顶点可以生成数组。 

## 方法

 最简单的方法是测试每个顶点作为可能的原点。 对于选定的顶点`x`，我们将从`x`，将所有计算出的距离与`s`，并另外验证特殊值`s[x]`匹配最短的非空封闭步行`x`。 这是正确的，因为它直接检查定义。 然而，最坏的情况表现`n`迪杰斯特拉奔跑。 和`n`和`m`都在周围`200000`，这大致变成`200000 * 400000 log(200000)`操作，这是不可行的。 

关键的观察结果是可以从新的人工顶点查看整个阵列。 创建虚拟顶点`z`并将其连接到每个原始顶点`i`具有重量优势`s[i]`。 如果数组对于某些源有效`x`，那么最短距离`z`到每个顶点都是`s[i]`。 直接边给出了这个距离，并且使用原始图边的任何路径都不能更短，因为标签已经表现得像最短距离。 

剩下的问题是哪个顶点可能是真正的源。 对于有效来源`x`，人工边缘`z -> x`不是到达的唯一途径`x`有距离`s[x]`。 我们可以从`z`到其他某个顶点`u`, 支付`s[u]`，然后遍历原始图回到`x`。 这对应于从`x`。 

因此，我们运行一个多源 Dijkstra，其中每个顶点最初都充当具有距离的源`s[i]`。 在此过程中，我们保持到达每个顶点的两个最佳距离，但这两个距离必须来自不同的起始顶点。 顶点的第二佳来源`i`告诉我们是否存在一条长度精确的路径`s[i]`这并不是从人工边缘开始`i`。 如果存在的话，`i`是一个可能的答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n(n + m) log n) | O(n(n + m) log n) | O(n + m) | 太慢了 |
 | 最佳| O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 将每个原始顶点初始化为多源 Dijkstra 中的源。 顶点`i`从距离开始`s[i]`和源标识符`i`。 这模拟添加虚拟顶点而不显式存储它。 
2. 在 Dijkstra 期间，保持每个顶点的最佳距离和次佳距离，其中两个存储的条目必须具有不同的源标识符。 我们只关心两个不同的起源，因为第一个起源可能只是直接的人工边缘。 
3. 正常松弛图形边缘。 当路径到达顶点时，根据源标识符是否已存在来更新其最佳条目或第二最佳条目。 
4. Dijkstra 完成后，按升序检查每个顶点。 第一个条件是到达顶点的最佳距离必须等于`s[i]`。 如果存在更小的距离，则给定数组不能表示任何最短路径树。 
5. 第二个条件是第二最佳距离也必须等于`s[i]`。 这意味着可以使用相同的值到达顶点，而无需使用自身作为人工起点，这正是返回源所需的非空路径。 
6. 输出满足两个条件的第一个顶点。 如果不存在则输出`-1`。 

为什么它有效：

 多源 Dijkstra 计算从概念上附加到每个顶点的虚拟源的最短路径。 有效的距离数组意味着每个顶点必须将其直接人工距离保持为尽可能短的距离。 唯一特殊的顶点是真实源，因为它的直接人工边代表禁止的零移动路径。 来自另一个源的等长路径的存在证明了该值可以通过在原始图中实际行走来生成。 因此，第二最佳距离标准准确地识别了可能的原始源。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, w))
        graph[v].append((u, w))

    INF = 10**30

    best_d = [INF] * n
    best_o = [-1] * n
    second_d = [INF] * n
    second_o = [-1] * n

    heap = []

    for i, x in enumerate(s):
        best_d[i] = x
        best_o[i] = i
        heapq.heappush(heap, (x, i, i))

    def update(v, d, o):
        if best_o[v] == o:
            if d < best_d[v]:
                best_d[v] = d
                return True
            return False

        if second_o[v] == o:
            if d < second_d[v]:
                second_d[v] = d
                return True
            return False

        if d < best_d[v]:
            second_d[v] = best_d[v]
            second_o[v] = best_o[v]
            best_d[v] = d
            best_o[v] = o
            return True

        if d < second_d[v]:
            second_d[v] = d
            second_o[v] = o
            return True

        return False

    while heap:
        d, v, o = heapq.heappop(heap)

        if d != best_d[v] and d != second_d[v]:
            continue

        for u, w in graph[v]:
            nd = d + w
            if update(u, nd, o):
                heapq.heappush(heap, (nd, u, o))

    for i in range(n):
        if best_d[i] != s[i]:
            print(-1)
            return

    for i in range(n):
        if second_d[i] == s[i]:
            print(i + 1)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```初始化代替了虚拟节点的构建。 而不是显式添加`z`，每个顶点的起始距离等于将其连接到的边`z`。 

这`update`功能是实现的核心。 它仅保留具有不同起始顶点的两条最小路径。 保留来自同一来源的两个条目不会有帮助，因为第二条路径必须代表不同的人工边缘。 

Dijkstra 松弛通过 Python 的普通整数类型使用 64 位样式整数。 这很重要，因为路径长度可以达到大约`2 * 10^14`。 需要进行过时堆检查，因为改进后一个顶点可能有多个过时的条目。 

最终扫描故意按递增索引顺序进行。 第一个有效顶点自动成为最小的索引答案。 

## 工作示例

 对于第一个样本：```
4 4
6 3 6 6
1 3 6
1 2 3
3 2 3
4 2 3
```重要的 Dijkstra 状态是：

 | 顶点| 初始来源 | 最佳距离 | 第二来源| 第二距离 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 6 | 2 | 6 |
 | 2 | 2 | 3 | 1 | 6 |
 | 3 | 3 | 6 | 1 | 6 |
 | 4 | 4 | 6 | 1 | 6 |

 顶点`1`有第二条路径长度`6`，所以它是有效的。 这是第一个有效索引，答案是`1`。 

此示例说明了为什么需要第二短源。 直接的人工边缘不足以证明顶点是隐藏原点。 

对于第三个样本：```
5 6
8 4 4 8 6
1 2 4
1 3 4
2 4 4
3 4 4
1 5 3
5 3 2
```这些州是：

 | 顶点| 最佳距离 | 第二距离 |
 | --- | --- | --- |
 | 1 | 4 | 8 |
 | 2 | 4 | 8 |
 | 3 | 4 | 8 |
 | 4 | 8 | 8 |
 | 5 | 6 | 10 | 10

 仅顶点`4`所需的第二条路径等于其值。 

该痕迹展示了特殊的自我距离规则。 顶点`4`不是用零距离来标识，而是用另一条长度最短的路线来标识`8`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O((n + m) log n) | O((n + m) log n) | 在一个多源 Dijkstra 过程中，每条图边都会松弛。 |
 | 空间| O(n + m) | 存储图和每个顶点的两个最佳状态。 |

 约束允许单次 Dijkstra 遍历，因为顶点和边的数量最多约为`200000`。 内存使用量保持线性，完全符合限制。

 ## 边缘情况

 对于无效的单顶点情况：```
1 0
1
```没有边，也不可能在唯一的顶点处开始和结束的非空行走。 该算法初始化顶点但从不创建第二个源路径，因此它可以正确打印`-1`。 

对于位于行中间的源：```
3 2
4 2 4
1 2 2
2 3 2
```多源进程找到该顶点`2`有距离`2`到两个邻居和另一条长度的路线`4`回到自身。 它的第二最佳距离恰好是`4`，所以被接受。 

对于不可能数组：```
3 3
1 5 5
1 2 2
2 3 2
1 3 10
```图本身在某些顶点之间提供了比给定值允许的更短的路径。 Dijkstra 计算出的最佳距离变得小于相应的距离`s`值，因此第一个验证步骤会拒绝整个数组。 

对于多个候选者的情况：```
4 4
6 3 6 6
1 3 6
1 2 3
3 2 3
4 2 3
```多个顶点接收等长路径，但从索引扫描`1`向上返回所需的最小有效源。
