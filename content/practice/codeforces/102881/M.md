 ## 解决方案
 ## 问题理解

 该序列以所有整数开始`1`最多`n`。 每个整数都被其十进制数字之和代替，任务是找到数字和严格递增的最长子序列的长度。 子序列必须保持数字的原始顺序，因此我们不能重新排列数字和。 

困难来自于规模`n`。 该数字最多可以包含`100000`数字，所以即使读取所有数字`1`到`n`是不可能的。 与可用输入大小相比，任何依赖于迭代序列的方法都具有指数规模。 我们需要一种直接作用于十进制表示的方法`n`。 

一个有用的观察是，答案不能大于出现的最大数字和，因为变换序列中的所有值都是正整数，并且它们的严格递增序列最多可以包含每个值出现一次。 

反方向是关键。 如果最大可能的数字和是`m`，那么可以选择数字和为`1, 2, 3, ..., m`按这个顺序。 数字和的序列自然包含这些递增的值，因为可以通过从左到右递增数字来构造具有较大数字和的数字。 因此，LIS 长度恰好是任意数字可实现的最大数字和`1`到`n`。 

边缘情况都与最大数字和计算有关。 例如，当输入为：```
10
```各数字之和为：```
1 2 3 4 5 6 7 8 9 1
```正确的输出是：```
9
```粗心的解决方案可能会使用以下数字和`n`本身和输出`1`，它忽略了较小的数字，例如`9`具有更大的数字和。 

另一种情况是：```
100
```最大位数和仍为`18`，通过实现`99`。 数量`100`有数字和`1`，因此仅查看最后一个数字会给出错误的结果。 

对于多位数的数字，例如：```
777
```最大数字和不是`21`, 的数字和`777`。 最好的数字是`699`，其数字和为`24`，给出答案：```
24
```## 方法

 直接的方法是生成每个数字`1`到`n`，计算其数字和，并运行标准最长递增子序列算法。 这是可行的，因为 LIS 仅取决于数字和的顺序，而不取决于原始数字。 问题是`n`可以有`100000`位，因此生成的值的数量不可能大。 甚至一个`O(n log n)`LIS 实施无法启动`n`它本身无法容纳在正常的记忆中。 

重要的减少是我们不需要整个序列。 答案仅取决于出现的最大数字和。 一旦知道该值，就可以将每个较小的正数字和放在有效的递增子序列中的前面。 问题变成了数字操作问题：找到所有不超过给定大整数的整数中的最大数字和。 

为了在上限下最大化数字和，我们应该使数字尽可能大，同时使后面的数字尽可能大。 如果前缀变得小于`n`，后面的每一个数字都可以变成`9`。 这给出了通常的贪婪候选者：保持数字不变，或者减少一位非零数字并将所有后续数字替换为`9`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 太慢了 |
 | 最佳| O(k) | O(1) | O(1) | 已接受 |

 这里，`k`是数字的个数`n`。 

## 算法演练

 1. 将数字作为字符串读取，因为它可以包含`100000`数字并且不能适合内置整数类型。 
2. 计算原数的数字和。 这是一位候选人，因为`n`其本身可能具有最大数字和。 
3. 尝试将每个非零数字减少一次。 减少仓位后`i`，其后的所有数字应变为`9`因为这会产生小于的最大可能数字`n`与所选的前缀。 
4. 保留所有这些候选者中最大的数字和。 这个值就是答案。 

为什么它有效：

 让`M`是以下数字中的最大数字和`1`到`n`。 每个变换后的值都属于该范围`1`到`M`，因此递增子序列的长度不能大于`M`。 

对于下界，考虑任意数字和`x`从`1`到`M`。 最大数字和的贪心构造表明，可以通过按递增数字顺序的数字来达到最大的所有值。 取这些数字给出一个带有数字和的子序列`1,2,...,M`。 LIS 长度至少为`M`，上限表示最多是`M`，所以答案正是`M`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    digits = list(map(int, s))
    n = len(digits)

    ans = sum(digits)

    for i in range(n):
        if digits[i] == 0:
            continue

        cur = sum(digits[:i]) + (digits[i] - 1) + 9 * (n - i - 1)
        ans = max(ans, cur)

    print(ans)

if __name__ == "__main__":
    solve()
```输入存储为字符串，因为普通整数类型无法表示值`100000`数字。 初始候选者是`n`本身。 

该循环考虑了每个可以使数字变小的位置。 将该数字减一使前缀保持有效，并用`9`s 给出具有较小前缀的所有数字的最大可能数字和。 所有候选值中的最大值是所需的 LIS 长度。 

不存在溢出问题，因为答案最多只是`100000`位数，所以最多是`900000`。 该实现避免创建修改后的字符串，并且仅使用运行总和。

 该算法仅扫描输入字符串固定次数。 和`100000`数字，这很容易满足时间和内存的限制。 

## 测试用例```python
import sys
import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()

    digits = list(map(int, s))
    n = len(digits)

    ans = sum(digits)

    for i in range(n):
        if digits[i] != 0:
            ans = max(ans, sum(digits[:i]) + digits[i] - 1 + 9 * (n - i - 1))

    sys.stdin = old_stdin
    return str(ans) + "\n"

assert solve_case("1\n") == "1\n", "minimum input"
assert solve_case("100000\n") == "27\n", "large boundary pattern"
assert solve_case("99999\n") == "45\n", "all digits equal to maximum"
assert solve_case("101\n") == "10\n", "off by one around zeros"

 ## 边缘情况

 对于`10`，算法检查原始数字和以及减少第一位数字形成的候选数字。 原文给出`1`，同时改变`10`进入`9`给出数字和`9`，所以答案是`9`。 

为了`100`，原来的数字只贡献`1`。 减少第一位数字创建`099`，这代表`99`, 带数字和`18`。 该算法找到该候选者并返回`18`。 

为了`777`，原数字和为`21`。 减少第一位数字创建`699`，其数字和为`24`。 该算法检测到这更好并输出`24`。 

对于诸如`101`，减少第一位数字给出`99`， 不是`100`，因为所有后续数字都变为`9`。 这避免了在最大化数字和的同时错误地处理前导零的常见错误。
