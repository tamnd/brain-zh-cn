 ## 解决方案
 ## 问题理解

 我们需要构造一个长度的字符串`n`尽可能少地使用不同的小写字母。 

问题是该字符串必须对于**每个可能的网格形状**（其行优先遍历生成该字符串）保持有效。 如果`n = r × c`，那么该字符串可以解释为`r × c`网格。 对于每一个因式分解`n`，生成的网格中不能有包含相同字符的相邻单元格对。 

在行优先顺序中，水平邻居对应于不同的位置`1`在一行内，而垂直邻居对应于不同的位置`c`。 

假设我们构建一个字符串`s`。 对于每个除数`c`的`n`，我们必须保证：

 -`s[i] != s[i+1]`每当职位`i`和`i+1`躺在同一排。 
-`s[i] != s[i+c]`每当两个位置都存在时。 

输入最多包含`10^4`测试用例，但所有的总和`n`值最多是`10^6`。 这意味着`O(n)`每个测试用例的构造完全没问题，而涉及检查所有可能的字符串或所有可能的网格颜色的任何事情都非常昂贵。 

棘手的部分不是构造有效的字符串。 棘手的部分是证明它使用尽可能少的不同字符。 

考虑`n = 6`。 一个天真的交替字符串`"ababab"`仅使用两个字母。 它适用于`1 × 6`网格和一个`6 × 1`网格。 然而，对于一个`2 × 3`网格中的第一个和第四个字符成为垂直邻居：```
a b a
b a b
```包含第一个和第四个字符的单元格都是`'a'`，创建无效邻接。 

另一个微妙的情况是当`n`是素数。 为了`n = 5`，唯一可能的网格宽度是`1`和`5`。 除距离外，没有垂直邻接约束`5`，字符串内部不存在。 两个字母就足够了：```
ababa
```始终使用许多字母的解决方案是有效的，但不是最佳的。 

关键的观察是字母的最小数量取决于`n`。 

## 方法

 蛮力观点首先是有用的。 

假设我们决定使用`k`字母并尝试所有可能的长度字符串`n`。 对于每个字符串，我们可以检查每个除数`c`的`n`并验证距离处的位置`1`和距离`c`绝不包含相同的字符。 这是正确的，因为它直接测试定义。 

问题在于搜索空间。 即使只有两个字母`2^n`字符串。 为了`n`最多`10^6`，穷举搜索是完全不可能的。 

邻接约束的结构提出了不同的观点。 

假设我们生成一个周期字符串```
abcabcabcabc...
```有时期`k`。 

当两个位置的索引相差多个时，它们包含完全相同的字母`k`。 

现在看任何除数`c`的`n`。 

如果有一定距离就会出现垂直冲突`c`是的倍数`k`，因为那时```
s[i] = s[i+c].
```因此我们需要一个时期`k`使得**没有除数`n`大于 1 可以被整除`k`**。 

实现这一目标的最简单方法是选择`k`作为大于的最小正整数`1`这**不**划分`n`。 

然后：

 - 每个较小的数字都可以除`n`。 
- 自从`k`本身并不分裂`n`, 没有除数`n`可以是以下的倍数`k`。 否则`k`也会分`n`。 

这立即消除了所有垂直冲突。 

横向冲突也是不可能的，因为相邻位置不同`1`，以及一段长度内的连续字符`k ≥ 2`总是不同的。 

为什么这是最佳的？ 

如果我们使用少于`k`不同的字母，例如`m < k`，那么根据定义`k`，每个小于`k`划分`n`。 尤其，`m`划分`n`。 

任何字符串仅使用`m`字母必须重复一些字母`m`周期构造中的位置和除数`m`创建一个禁止的垂直距离。 更正式地说，可以证明少于`k`字母不能同时满足所有约数。 

因此，不同字母的最小数量恰好是大于的最小整数`1`不分裂`n`。 

找到这个值后，我们只需循环写入字母即可：```
a b c ... (k letters) a b c ...
```并截断长度`n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(kⁿ) 或更差 | 指数| 太慢了 |
 | 最佳 | O(n + k) | O(n) | 已接受 |

 ## 算法演练

 1. 找到最小的整数`k ≥ 2`这样`n % k != 0`。 
2. 使用第一个`k`小写字母：```
a, b, c, ...
```3.构造长度答案`n`通过放置角色```
chr(ord('a') + (i % k))
```在位置`i`。 
4. 输出结果字符串。 

为什么步骤 1 给出最少字母数？ 

每个小于的整数`k`划分`n`。 如果我们尝试使用少于`k`不同的字符，这些除数之一会在禁止的距离处创建不可避免的相等字符位置。 准确选择`k`避免了这种情况，因为没有除数`n`可以是以下的倍数`k`。 

### 为什么它有效

 构造的字符串有句点`k`。 仅当两个位置的距离是 的倍数时才包含相同的字符`k`。 

对于任何网格宽度`c`划分`n`，垂直冲突需要`c`是 的倍数`k`。 那不可能发生，因为`k`不分开`n`，而每个除数`c`的`n`做。 

横向冲突对应于距离`1`。 自从`k ≥ 2`，相邻位置总是收到不同的字母。 

因此，每种可能的网格解释都是好的。 

为了最优性，每个小于`k`划分`n`。 任何解决方案使用少于`k`不同的字母需要满足与这些除数之一相关的约束，这是不可能的。 因此`k`是可实现的最小不同字符数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())

        k = 2
        while n % k == 0:
            k += 1

        s = []
        for i in range(n):
            s.append(chr(ord('a') + (i % k)))

        ans.append(''.join(s))

    sys.stdout.write('\n'.join(ans))

if __name__ == "__main__":
    solve()
```第一个循环搜索大于不能整除的最小整数`n`。 该值始终最多约为`log₂(n) + 1`，因为如果`2,3,4,...,k-1`全部分开`n`， 然后`n`已经是巨大的了。 实际上，循环只执行几次。 

获得后`k`，字符串是循环生成的。 位置`i`收到对应的信件`i mod k`，创建一个恰好的时期`k`。 

有一个实施细节值得注意。 我们永远不需要明确地测试网格形状。 数论论证保证了每个除数的正确性`n`，因此构造周期串就足够了。

 ## 边缘情况

 对于`n = 1`，唯一可能的网格包含单个单元格。 算法检查`k = 2`，发现`2`不分开`1`，并构建`"a"`。 一种独特的性格显然是最佳的。 

为了`n = 2`，搜索发现`k = 3`因为`2`划分`2`但`3`没有。 输出是`"ab"`。 仅使用一个字符会产生`"aa"`，这对于`1 × 2`网格，因为相邻的单元格会匹配。 

对于质数，例如`n = 13`，第一个测试已经成功，因为`13 % 2 = 1`。 该算法输出：```
ababababababa
```仅使用两个字母。 由于唯一的除数是`1`和`13`，不存在垂直约束，两个字母是最佳的。 

对于高度复合数，例如`n = 60`，算法测试：```
2, 3, 4, 5, 6
```所有这些都划分`60`，然后停在`7`。 输出在一个循环中恰好使用了七个字母。 任何较小的字母大小都对应于数字除法`60`，这将创建一个禁止的网格邻接。
