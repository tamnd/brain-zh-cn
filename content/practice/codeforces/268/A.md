 ## 解决方案
 ## 问题理解

 我们在足球锦标赛中获得了所有球队的统一颜色。 每支球队都有主场颜色和客场颜色。 

每对不同的有序球队只进行一场比赛，其中一支球队作为东道主，另一支球队作为客队。 一般情况下，主人穿主场服，客人穿客场服。 

唯一的特殊情况发生在主队的主场颜色与客队的客场颜色完全相同时。 在这种情况下，主持人会更换并穿上其客场制服。 

任务是计算整个锦标赛期间有多少场比赛触发了此切换。 

输入提供每个球队的主场和客场颜色。 输出是一个整数，即主机磨损制服的比赛总数。 

限制非常小。 最多有 30 支球队，因此可能的主客对总数最多为：$$30 \cdot 29 = 870$$即使直接检查每一个可能的匹配也足够快。 不需要复杂的数据结构或优化。 

一个常见的错误是考虑无序的团队对。 锦标赛包含有序比赛。 如果 A 队主场迎战 B 队，B 队主场迎战 A 队，则这是两场不同的比赛，必须单独考虑。 

考虑这个例子：```
2
1 2
2 1
```有两场比赛：

 第 1 队主场迎战第 2 队：

 主人回家=1，客人离开=1，发生切换。 

第 2 队主场迎战第 1 队：

 主人回家=2，客人离开=2，发生切换。 

正确答案是：```
2
```仅检查每对一次的解决方案将错误地返回 1。 

另一个微妙的情况是几支球队共享相同的主场颜色。```
3
1 2
1 3
4 1
```球队 1 和球队 2 的主场颜色均为 1。球队 3 的客场颜色为 1。 

球队 3 对阵球队 1 以及球队 3 对阵球队 2 的比赛都有助于回答这个问题。 我们必须独立计算每个有效的主客组合。 

正确答案是：```
2
```## 方法

 最直接的方法是模拟每个可能匹配的条件。 

对于每个团队$i$担任主持人和每个不同的团队$j$作为客人，我们检查是否：$$home_i = away_j$$如果颜色匹配，主持人会更换制服，我们会增加答案。 

这种方法是正确的，因为问题定义仅取决于主人的主场颜色和客人的客场颜色。 每场比赛都可以独立评估。 

最坏的情况有30个团队，所以我们最多执行：$$30 \cdot 29 = 870$$比较。 那是很小的。 

还有一种计数解释。 每次出现的主场颜色都可以与每次出现的客场颜色相同值相匹配。 人们可以计算颜色频率并将它们相乘。 这也是可行的，但考虑到小的限制，这是不必要的。 

暴力解决方案对于这个问题来说已经是最佳的，因为输入大小非常小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受 |
 | 频率计数 | O(n + C) | O(C)| 已接受 |

 这里$C$是可能的颜色数量。 自从$n \le 30$，更简单的二次解是自然的选择。 

## 算法演练

 1.读取队伍数量。 
2. 将每个球队的主场颜色和客场颜色存储在列表中。 
3. 初始化`answer = 0`。 
4. 对于每个团队`i`，将其视为主机。 
5. 对于每个团队`j`，将其视为客人。 
6. 跳过以下情况`i == j`，因为团队从不自己比赛。 
7. 检查主人的主场颜色是否与客人的客场颜色相同。 
8. 如果相等，则递增`answer`减一是因为东道主必须换上客场队服。 
9. 处理完所有对后，打印`answer`。 

### 为什么它有效

 锦标赛包含每对不同球队的一场比赛。 该算法精确地检查这些对。 

对于特定的比赛`(i, j)`，问题指出当且仅当主人的主场颜色等于客人的客场颜色时，主人才会更换制服。 该算法会精确检查此条件，并在匹配对答案有贡献时精确地添加一个。 

由于每场比赛都只检查一次，因此最终的计数正是主队穿着客场球衣的比赛场数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
teams = [tuple(map(int, input().split())) for _ in range(n)]

answer = 0

for i in range(n):
    home_i = teams[i][0]

    for j in range(n):
        if i == j:
            continue

        away_j = teams[j][1]

        if home_i == away_j:
            answer += 1

print(answer)
```第一部分读取并存储所有统一颜色。 每个条目包含`(home_color, away_color)`。 

嵌套循环枚举每个有序的主客对。 条件`i == j`被跳过，因为没有球队与自己比赛。 

关键的比较是：```
home_i == away_j
```这直接符合声明中的规则。 每当它为真时，当前匹配对答案的贡献恰好为 1。 

不需要对重复颜色进行特殊处理。 如果几支球队的颜色相同，那么每个有效的比赛自然都会被循环计数。 

整数溢出是不可能的，因为最大答案是$30 \cdot 29 = 870$。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    teams = [tuple(map(int, input().split())) for _ in range(n)]

    ans = 0

    for i in range(n):
        for j in range(n):
            if i != j and teams[i][0] == teams[j][1]:
                ans += 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3\n1 2\n2 4\n3 4\n") == "1", "sample 1"

# minimum size, no match
assert run("2\n1 2\n3 4\n") == "0", "minimum case"

# two matches because games are ordered
assert run("2\n1 2\n2 1\n") == "2", "ordered matches"

# multiple hosts matching same away color
assert run("3\n1 2\n1 3\n4 1\n") == "2", "duplicate home colors"

# all possible ordered matches contribute
assert run("3\n1 2\n2 1\n1 2\n") == "4", "multiple contributions"

 ### 有序的比赛很重要

 输入：```
2

 | 主持人| 访客| 状况 |
 | --- | --- | --- |
 | 1 | 2 | 1 = 1 |
 | 2 | 1 | 2 = 2 |

 两场比赛都有贡献。 

输出：```
2
```仅考虑每对一次的解决方案将错误地仅计算一场比赛。 

### 多个团队共享一种颜色

 输入：```
3

4 1
```该算法发现：

 | 主持人| 访客| 状况 |
 | --- | --- | --- |
 | 1 | 3 | 1 = 1 |
 | 2 | 3 | 1 = 1 |

 两支不同的主队搭配相同的客场颜色。 

输出：```
2
```嵌套循环方法自然会计算这两种情况的出现。 

### 没有匹配的颜色

 输入：```
3

```每次比较都会失败，因为没有主场颜色显示为另一支球队的客场颜色。 

输出：```

```该算法根本不会增加计数器，从而产生正确的结果。
