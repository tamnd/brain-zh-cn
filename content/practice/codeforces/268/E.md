 ## 解决方案
 ## 问题理解

 每首歌都有两个属性。 它的长度是`l`，并且马瑙有概率独立喜欢它`p`。 

当第一次播放一首歌曲时，会发生以下两种情况之一。 

如果他喜欢，这首歌就会被添加到记忆歌曲集中。 

如果他不喜欢，他会立即将所有记住的歌曲重放一次。 

记住的歌曲正是之前处理的所有歌曲中最喜欢的歌曲。 一旦一首歌被喜欢，它就会永远被喜欢。 

我们可以按任何顺序排列歌曲。 在所有排列中，我们必须最大化预期的总收听时间。 

输入最多包含 50,000 首歌曲。 二次算法大约需要 25 亿对交互，这远远超出了限制。 解必须接近`O(n log n)`。 

主要的困难是歌曲的贡献取决于哪些歌曲出现在它之前。 由于将来不喜欢的歌曲，一首歌可以重播多次，因此局部贪婪选择不会立即明显。 

一些边缘情况很容易被错误处理。 

考虑一首从未被喜欢过的歌曲：```
1
100 0
```预期收听时间正好是`100`。 没有记住的歌曲，因此不会发生重播。 任何盲目乘以概率而不进行处理的公式`p = 0`正确可能会产生错误的额外贡献。 

考虑一首总是很受欢迎的歌曲：```
1
100 100
```答案也是`100`。 该歌曲播放一次后就不会再播放，因为没有后来的歌曲。 有些推导意外地计算了自交互并获得了更大的值。 

另一种微妙的情况是当一个概率为零时：```
2
100 100
200 0
```如果第一首歌曲放在第二首歌曲之前，则总收听时间为```
100 + 200 + 100 = 400
```因为第二首歌肯定不受欢迎，并会触发第一首歌的重播。 

如果顺序颠倒，则总数仅为```
200 + 100 = 300
```因此，即使一个概率是确定性的，排序也很重要。 

## 方法

 暴力解决方案将尝试歌曲的每种排列，计算其预期收听时间，并保留最大值。 

对于固定排列，可以根据概率公式计算期望。 不幸的是有`n!`排列。 即使是为了`n = 15`这已经是无望了，而实际的极限是`50,000`。 

关键的观察结果是期望是线性的。 我们可以计算成对歌曲之间每次交互的预期贡献，而不是考虑完整的执行。 

假设歌曲`i`出现在歌曲之前`j`。 

歌曲`i`当歌曲重播时`j`不喜欢，但仅限于歌曲`i`之前就喜欢过。 

该事件发生的概率是$$P(i\text{ liked}) \cdot P(j\text{ disliked})$$这等于$$\frac{p_i}{100}\left(1-\frac{p_j}{100}\right).$$每当发生这种情况时，都会额外`l_i`秒听。 

所以每一对订购的`(i,j)`和`i`前`j`贡献$$l_i \cdot \frac{p_i}{100}\left(1-\frac{p_j}{100}\right)$$到预期。 

无论顺序如何，每首歌曲第一次播放的预期持续时间始终只计算一次：$$\sum l_i.$$因此优化问题变为：$$\sum l_i + \sum_{i<j} l_i \cdot \frac{p_i}{100} \left(1-\frac{p_j}{100}\right).$$常数项不依赖于排列。 只有成对的术语才重要。 

每当一个目标可以写成成对贡献的总和时，交换论证通常是正确的工具。 我们比较两首相邻的歌曲并确定哪个顺序更好。 这会产生一个排序标准，并将问题简化为一次排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n! · n)`|`O(n)`| 太慢了 |
 | 最佳 |`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 ### 推导排序规则

 考虑两首歌`A`和`B`。 

让$$a=l_A,\quad x=\frac{p_A}{100}$$和$$b=l_B,\quad y=\frac{p_B}{100}.$$只有当我们交换它们时，它们之间的相互作用才会发生变化。 

如果`A`出现在之前`B`，这对贡献$$a x (1-y).$$如果`B`出现在之前`A`，这对贡献$$b y (1-x).$$我们想要`A`前`B`什么时候$$a x (1-y) > b y (1-x).$$乘以`100^2`为了避免分数给出$$a p_A (100-p_B) > b p_B (100-p_A).$$这是两首歌之间完整的比较规则。 

### 步骤

 1. 朗读所有歌曲。 
2.使用比较器对歌曲进行排序$$l_i p_i (100-p_j) > l_j p_j (100-p_i).$$如果这个不等式成立，歌曲`i`必须出现在歌曲之前`j`。 

1. 排序后，计算期望。 
2. 维护$$S=\sum_{\text{processed}} l_i \cdot \frac{p_i}{100}.$$

`S`表示在所有先前处理的歌曲之后记住的歌曲的预期总长度。 

1. 从左到右处理歌曲。 
2.添加歌曲自己的首播，即`l_i`，到答案。 
3.当前歌曲有概率不喜欢$$1-\frac{p_i}{100}.$$如果发生这种情况，所有记住的歌曲都会重播。 他们的预期总长度恰好是`S`。 

添加$$S\left(1-\frac{p_i}{100}\right)$$到答案。 

1. 更新$$S \leftarrow S + l_i\frac{p_i}{100}.$$1.输出最终的期望。 

### 为什么它有效

 成对目标是相加的。 对于任意两首相邻歌曲，两个可能顺序之间的贡献差异仅取决于这两首歌曲：$$a p_A (100-p_B) - b p_B (100-p_A).$$每当该值为正数时，将`A`前`B`增加期望。 这定义了有效的成对排序关系。 根据该关系进行排序可确保删除每个相邻的反转。 根据标准交换论证，没有进一步的交换可以改善排列，因此得到的排列是最优的。 

期望计算也是正确的，因为期望的线性允许我们用其期望的总长度替换随机的记忆歌曲集`S`。 每首歌曲独立贡献`l_i p_i/100`达到预期的记忆长度。 

## Python 解决方案```python
import sys
from functools import cmp_to_key

input = sys.stdin.readline

def solve():
    n = int(input())
    songs = []

    for _ in range(n):
        l, p = map(int, input().split())
        songs.append((l, p))

    def cmp(a, b):
        l1, p1 = a
        l2, p2 = b

        left = l1 * p1 * (100 - p2)
        right = l2 * p2 * (100 - p1)

        if left > right:
            return -1
        if left < right:
            return 1
        return 0

    songs.sort(key=cmp_to_key(cmp))

    ans = 0.0
    remembered = 0.0

    for l, p in songs:
        prob = p / 100.0

        ans += l
        ans += remembered * (1.0 - prob)

        remembered += l * prob

    print("{:.12f}".format(ans))

if __name__ == "__main__":
    solve()
```比较器是解决方案的核心。 它直接来自比较一对歌曲的两种可能的顺序。 使用交叉乘法可以避免排序期间的浮点精度问题。 

变量`remembered`存储已记住的歌曲的预期总长度。 它不是一次执行期间的实际随机长度。 根据期望的线性，仅跟踪期望值就足够了。 

答案是逐步积累的。 每首歌曲都有自己的初始播放长度。 那么，以概率`1 - p/100`，它会导致所有记住的歌曲被重播。 这些歌曲的预期长度正是`remembered`。 

比较器内的所有算术都使用整数。 最大值约为$$1000 \cdot 100 \cdot 100 = 10^7,$$与 Python 的整数范围相比，这是很小的。

 ## 边缘情况

 ### 从来不喜欢的歌

 输入：```
1
100 0
```排序顺序不变。 最初`remembered = 0`。 

该歌曲贡献`100`第一次演出。 自从`remembered`为零，则重放项也为零。 答案正是`100`。 

### 一直很喜欢的歌

 输入：```
1
100 100
```该歌曲贡献`100`。 重播概率为零，因此没有添加任何额外内容。 然后`remembered`变成`100`，但是没有后来的歌曲了。 结果依然`100`。 

### 确定性喜欢之后确定性不喜欢

 输入：```
2
100 100
200 0
```比较者在第二首歌曲之前更喜欢第一首歌曲，因为$$100 \cdot 100 \cdot 100 > 200 \cdot 0 \cdot 0.$$处理完第一首歌曲后，`remembered = 100`。 

第二首歌肯定不受欢迎，所以它的重播贡献正好是`100`。 

最终的答案是$$100 + 200 + 100 = 400.$$这证实了该算法正确地处理了两个极端的概率，并通过排序规则正确地利用了重放机会。
