 ## 解决方案
 ## 问题理解

 有一个隐藏的顺序`n`按钮。 仅当按钮是该顺序中的下一个正确按钮时，该按钮才会保持按下状态。 如果在任何时候我们按下了错误的按钮，之前按下的每个按钮都会弹出，我们必须从头开始重新构建序列。 

马瑙不知道顺序，但他可以观察按钮是否保持按下状态或者锁是否重置。 他总是选择尽量减少所需按压次数的动作。 我们必须计算最坏可能的隐藏排序所需的按钮按下次数。 

输入包含单个整数`n`，按钮的数量。 输出是马瑙使用最佳策略时可能需要的最大按压次数。 

约束很小，`n ≤ 2000`。 甚至一个`O(n²)`该解决方案仅执行大约四百万次操作，这在限制范围内是微不足道的。 无需高级优化。 挑战在于识别计数公式。 

一个常见的错误是只计算失败的尝试，而忘记了成功的按下也会消耗按钮的按下次数。 

考虑：```
n = 2
```答案是`3`， 不是`2`。 

在最坏的情况下，马纳奥首先尝试了错误的按钮。 然后他就知道正确的第一个按钮。 按下成功后，他还得按下第二个按钮才能开锁。 

另一个容易犯的错误是假设每个阶段都需要测试所有剩余的按钮。 

考虑：```
n = 3
```一旦知道前两个按钮并保持按下状态，就会自动确定最后一个按钮。 无需测试。 正确答案是`7`， 不是`9`。 

边缘情况`n = 1`也很重要。```
1
```输出：```
1
```只有一个按钮，因此只需按一下即可打开锁。 

## 方法

 思考问题最直接的方法就是模拟马瑙如何发现序列。 

假设他已经知道第一个`k - 1`序列的按钮。 去发现`k`-th 按钮，有`n - k + 1`剩余候选按钮。 

在最坏的情况下，正确的按钮是他尝试的最后一个候选按钮。 

对于每一个错误的候选者，他必须首先重建已知长度的前缀`k - 1`，然后做出错误的尝试。 那成本`k`按下。 

在所有错误的候选者都失败后，他最后一次重建了前缀并按下了正确的按钮。 

强力模拟可以明确地为每个位置添加这些成本。 自从`n ≤ 2000`，即使这个计数过程也足够快。 困难在于干净地表达总数。 

关键的观察是对于位置`k`，正好有`n - k`错误的候选人。 

每个错误的候选人都会付出代价`k`按：```
(k - 1) presses to rebuild the prefix
+ 1 press for the wrong button
= k
```因此位置的总贡献`k`是：```
k · (n - k)
```在发现除最后一个位置之外的所有位置之后，锁仍然需要成功构建完整序列。 这有助于`n`更多的压力。 

总结一切得出：```
answer = n + Σ k(n - k)
         for k = 1..n-1
```这已经足够高效了。 我们可以直接计算总和`O(n)`时间。

 | --- | --- | --- | --- |
 | 暴力模拟发现过程 | O(n²) | O(1) | O(1) | 已接受 |
 | 数学计数公式| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`。 
2. 初始化答案`n`。 

这些是整个序列最终成功构建的压力机。 
3. 对于每个位置`k`从`1`到`n - 1`， 添加`k × (n - k)`。 

有`n - k`不正确的候选人`k`第-个位置。 每个错误的候选人都会付出代价`k`因为在测试之前必须重建已知前缀。 
4. 输出累计答案。 

### 为什么它有效

 当确定`k`第 -th 按钮，准确地说`n - k`按钮不正确。 在最坏的情况下，在找到正确的之前，所有这些都经过测试。 

每一个这样失败的测试都需要重建已知的长度前缀`k - 1`然后按错一个按钮，总成本为`k`按下。 

数量`k(n - k)`精确计算所有故障的总成本，同时发现`k`第-个位置。 将所有位置的总和计算为每次失败的尝试一次。 最后，在知道所有位置后，成功执行完整序列需要`n`按下。 没有任何按下操作被忽略，也没有任何按下操作被计算两次，因此该公式产生了准确的最坏情况下的按钮按下次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = n
    for k in range(1, n):
        ans += k * (n - k)

    print(ans)

solve()
```变量`ans`开始于`n`，代表最终成功的打开尝试。 

循环处理位置`1`通过`n - 1`。 对于每个位置`k`， 有`n - k`剩下错误的候选人。 每个失败的候选人成本`k`按下，所以我们添加`k * (n - k)`。 

最终立场不需要发现阶段。 一旦第一个`n - 1`按钮是已知的，最后一个按钮是强制的。 这就是为什么循环停止在`n - 1`。 

在 Python 中，整数溢出不是问题。 即使是为了`n = 2000`，答案只有几十亿左右。

ans = 1

### 边缘情况 2：自动知道最终位置

 输入：```
2
```执行：

 | k | 添加| 回答 |
 | --- | --- | --- |
 | 初始| - | 2 |
 | 1 | 1 | 3 |

 识别出第一个按钮后，将自动确定第二个按钮，因为它是唯一剩余的按钮。 该算法通过不增加位置的发现成本来正确捕获这一点`n`。 

### 边缘情况 3：前缀重建成本更大

 输入：```
4
```执行：

 | k | 添加| 回答 |
 | --- | --- | --- |
 | 初始| - | 4 |
 | 1 | 3 | 7 |
 | 2 | 4 | 11 | 11
 | 3 | 3 | 14 | 14

 当搜索第三个按钮时，每次失败的尝试都需要首先重建两个已知的按钮。 因素`k`在`k(n-k)`准确地说明了这项额外工作，防止计数不足。
