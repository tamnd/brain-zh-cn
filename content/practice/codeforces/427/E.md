 ## 解决方案
 ## 问题理解

 所有罪犯都站在x轴上，我们必须为警察局选择一个整数坐标。 巡逻车从车站出发，拜访一些罪犯，将他们带回车站，然后重复，直到所有人被捕。 每次行程最多可携带`m`罪犯。 

一次旅行的距离成本很简单。 如果该行程中拜访的最远的罪犯位于远处`d`从车站出发，车必须从车站到那个点再回来，所以行程费用`2d`。 

真正的问题是如何将犯罪分子分成行程以及将站点放置在哪里以使总行程距离最小。 

位置已经排好了。 最多可以有`10^6`犯罪分子，这立即排除了任何二次方。 甚至`O(n log n)`对于这个输入大小已经接近Python中的实际限制，因此预期的解决方案在排序后应该基本上是线性的，我们很幸运，因为输入已经排序了。 

一个常见的错误是认为最佳站点位置始终是中间位置。 当每个罪犯单独运送时，这是正确的，但在这里是错误的，因为汽车可以在一次旅行中将多名罪犯聚集在一起。 

考虑：```
n = 4, m = 2
positions = [0, 1, 100, 101]
```如果我们将车站放置在中线附近，大约`50`，双方都变得昂贵。 最佳解决方案实际上是在一个集群附近，因为行程是由每批中最远的罪犯负责的。 

当车站两侧都有犯罪分子时，就会出现另一个容易出现的错误。 向左和向右的行程是独立的。 单次行程无法有效地结合两个方向，因为无论如何汽车都需要再次穿过车站。 

例如：```
n = 3, m = 2
positions = [-10, -9, 100]
```如果车站位于`0`，最优方案为：

 - 一次旅行`100`， 成本`200`- 一次旅行`-10`和`-9`， 成本`20`全部的`220`。 

试图将左右罪犯合二为一，只会增加距离。 

另一个微妙的情况发生在车站恰好建在一些犯罪分子所在的地方。```
n = 5, m = 2
positions = [1, 1, 1, 10, 10]
```建筑于`1`零路费即刻抓获三名犯罪分子。 只有两个罪犯`10`需要交通。 

如果实施不慎，仍将车站内的犯罪分子计入交通成本，则会多算。 

## 方法

 蛮力的想法很简单。 由于车站必须放置在某个整数坐标处，因此我们可以尝试每个候选位置，计算该车站的最佳运输成本，并取最小值。 

假设电台固定在`x`。 

左边的所有罪犯`x`可以独立处理犯罪分子的权利。 一方面，最优策略是贪婪的：总是在一次旅行中将剩下的最远的罪犯一起带走，因为旅行成本仅取决于到达的最远距离。 

例如，如果一侧的距离为：```
1 3 5 8 10
```和`m = 2`，则最优分组为：```
(10, 8), (5, 3), (1)
```费用：```
2 * (10 + 5 + 1)
```不是：```
2 * (10 + 8 + 5)
```因为一旦我们已经远行`10`, 采取`8`在一起是免费的。 

因此，对于固定站，我们可以在线性时间内贪婪地计算答案。 

问题在于候选站的数量。 坐标可能达到`10^9`，所以暴力破解整数位置是不可能的。 即使仅限于犯罪坐标仍然给出`O(n^2)`总工作量，对于`10^6`元素。 

关键的观察结果是成本函数是凸的。 

将测站稍微向右移动会减少右侧距离，但会增加左侧距离。 由于行程按排序顺序贪婪地分组，因此总成本的斜率单调变化。 这会在站点坐标上创建一个离散凸函数。 

凸性意味着我们可以对站点位置使用三元搜索。 

更好的是，评估一个职位可以在`O(n / m)`而不是`O(n)`如果我们直接跳过成群结队的罪犯。 

由此产生的复杂性变得足够高效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O((n / m) log C) | O(1) | O(1) | 已接受 |

 这里`C`是坐标范围，大致`2 * 10^9`。 

## 算法演练

 1. 选择候选站位`x`。 
2. 将罪犯分为以下几类：`x`和那些权利`x`。 

犯罪分子恰好在`x`不需要交通，也不贡献任何东西。 
3. 处理左侧。 

距车站的距离为：```
x - position
```因为位置是排序的，最远的罪犯是最左边的。 

最优策略是对剩下的最远的进行分组`m`犯罪分子一趟。 

如果左侧的索引是：```
l, l+1, ..., r
```然后我们添加：```
2 * (x - positions[i])
```对于每一个`i`采取的步骤为`m`从最远的一侧。 
4. 右侧同样处理。 

最远的罪犯是最右边的。 

我们再次按人数分组`m`从最远的一侧开始并添加：```
2 * (positions[i] - x)
```5. 两边相加即为站位总成本`x`。 
6. 由于成本函数是凸函数，因此执行三元搜索`x`。 

我们比较中间两个点的成本并丢弃最差的一侧。 
7. 当搜索区间变小时，暴力破解区间内所有剩余的整数坐标并输出最小值。 

### 为什么它有效

 对于固定站点，贪婪分组是最优的，因为一次旅行成本仅取决于访问过的最远的犯罪分子。 一旦行程已经达到距离`d`，将任何其他罪犯带到比`d`不增加额外的行驶距离。 因此，每次旅行都应该首先捕获距离最远的犯罪分子。 

总成本作为站点位置的函数是凸的。 将站点向右移动会减少右侧组贡献的成本并增加左侧组贡献的成本。 每组贡献一个绝对值线性项，并且凸函数的和保持凸。 三元搜索对此类函数有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    def cost(x):
        res = 0

        # left side
        i = 0
        while i < n and a[i] < x:
            i += 1

        j = 0
        while j < i:
            res += 2 * (x - a[j])
            j += m

        # right side
        j = n - 1
        while j >= i and a[j] > x:
            j -= 1

        k = n - 1
        while k > j:
            res += 2 * (a[k] - x)
            k -= m

        return res

    lo = -10**9
    hi = 10**9

    while hi - lo > 5:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3

        if cost(m1) <= cost(m2):
            hi = m2
        else:
            lo = m1

    ans = 10**30

    for x in range(lo, hi + 1):
        ans = min(ans, cost(x))

    print(ans)

solve()
```这`cost(x)`函数直接实现贪婪批处理逻辑。 

在左侧，犯罪分子已经按照距离车站最远到最近的顺序进行排序。 每一个`m`第 - 个罪犯确定一次行程成本，因为该罪犯是其批次中距离最远的成员。 

认为：```
positions = [-10, -8, -3, -1]
x = 0
m = 2
```批次为：```
(-10, -8)
(-3, -1)
```仅有的`-10`和`-3`确定行程距离，所以我们逐步`m`。 

右侧与阵列末端对称。 

三元搜索使用整数坐标。 在足够缩小间隔后，我们对剩余的几个坐标进行暴力破解，因为离散凸函数可能具有平坦区域。 

所有算术都使用 Python 整数，它可以安全地处理最大可能的答案。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n / m) log C) | 每次成本评估每批次处理一名罪犯，三元搜索执行对数多次评估 |
 | 空间| O(1) | O(1) | 仅使用了几个变量 |

 坐标范围约为`2 * 10^9`，因此三元搜索执行大约 40 次迭代。 每次评估都会有效地扫描分组的犯罪分子，即使对于`10^6`罪犯。

 ## 边缘情况

 考虑所有犯罪分子已经站在同一坐标上。```
5 3
10 10 10 10 10
```该算法评估站点位置`10`。 

左右扫描都变成空的，因为没有犯罪分子满足`< x`或者`> x`。 

总成本保持不变`0`，这是正确的，因为每个人都会立即被捕。 

现在考虑一下双方的罪犯。```
4 2
-100 -1 1 100
```在车站`0`，算法形式为：

 剩余批次：```
(-100, -1)
```正确批次：```
(100, 1)
```全部的：```
2 * 100 + 2 * 100 = 400
```两侧是独立处理的，这是最佳选择，因为穿过车站没有任何优势。 

最后，考虑不完整的最终批次。```
5 2
1 2 3 4 100
```右侧组是：```
(100, 4)
(3, 2)
(1)
```该算法仅对每批中最远的成员正确收费：```
2 * 100 + 2 * 3 + 2 * 1
```一个常见的差一错误是忘记最后一部分批次仍然需要一次。
