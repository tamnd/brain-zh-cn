 ## 解决方案
 ## 问题理解

 我们有一排囚犯，每个囚犯都有一个犯罪严重程度值。 我们必须准确选择`c`连续的囚犯转移。 所选分段内的每个囚犯最多必须有严重程度`t`。 

任务只是计算有多少个连续的长度段`c`满足这个限制。 

输入给出了囚犯的数量、允许的最大严重程度以及所需的段长度。 然后我们收到严重性数组。 输出是一个整数，即有效连续段的数量。 

这些限制立即排除了昂贵的方法。 囚犯人数可达`2 * 10^5`，这意味着`O(n^2)`算法将大致执行`4 * 10^10`最坏情况下的操作，远远超出了1秒问题的极限。 我们需要一些线性或接近线性的东西。 

值本身可以大到`10^9`，但这并不重要，因为除了与`t`。 

有几种容易被忽略的边缘情况。 

一个常见的错误是忘记段必须是连续的。 例如：```
5 3 2
1 5 2 3 1
```有效的段是：

 -`[2,3]`-`[3,1]`答案是`2`， 不是`4`。 一个粗心的解决方案可能会最多计算出所有有价值的囚犯`3`并尝试将它们形成组合，这忽略了连续的要求。 

当一个坏囚犯将阵列分成独立的区域时，就会发生另一个微妙的情况。```
7 2 3
1 2 1 5 1 1 1
```来自一个有效段的前三名囚犯。 最后三名囚犯来自另一个。 任意线段穿过`5`无效。 正确答案是`2`。 

当有效块长度恰好等于时，经常会出现差一错误`c`。```
4 3 4
1 2 3 1
```整个数组都是有效的，所以答案是`1`。 一些实现不正确地使用`length - c`而不是`length - c + 1`。 

另一个重要的边缘情况是没有囚犯满足限制。```
5 1 2
3 4 5 6 7
```没有段有效，所以答案是`0`。 

## 方法

 蛮力方法很简单。 我们检查每个连续的长度段`c`，然后检查该段内的所有值是否最多`t`。 

有`n - c + 1`可能的片段。 检查一个段需要`O(c)`时间，因此总复杂度变为`O((n - c + 1) * c)`。 最坏的情况下，双方`n`和`c`可以是关于`2 * 10^5`，大致给出`4 * 10^10`运营。 这太慢了。 

暴力破解之所以有效，是因为段的条件很简单：其中的每个元素都必须满足一个限制。 问题在于相邻的段严重重叠，但暴力破解会反复重新检查相同的元素。 

关键的观察结果是，无效囚犯将阵列完全分成独立的有效区域。 假设我们扫描数组并仅关注连续的延伸，其中每个值最多`t`。 

例如：```
1 2 1 5 1 1 1
```价值`5`将数组分解为：```
[1 2 1]   and   [1 1 1]
```在长度有效的块内`L`，每个长度连续的子数组`c`自动有效。 这样的子数组的数量是：```
L - c + 1
```假如`L >= c`。 

这将问题转化为计算最大有效块的长度。 

我们在数组中扫描一次，同时保持连续可接受囚犯的当前长度。 当我们遇到大于的值时`t`，当前块结束，我们添加它的贡献。 

这给出了线性`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n × c) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化答案变量`ans = 0`。 
2. 维护计数器`length`表示当前连续块，其中所有严重性最多`t`。 
3. 从左到右遍历数组。 
4. 如果当前严重程度最多为`t`, 增量`length`因为有效块还在继续。 
5. 如果当前严重性大于`t`，当前有效块结束。 

如果`length >= c`，那么这个块贡献`length - c + 1`有效段。 

将此值添加到答案中，然后重置`length = 0`。 
6. 遍历完成后，同样处理最后一个块。 

此步骤是必要的，因为数组可能在仍在有效块内时结束。 
7. 打印累计答案。 

### 为什么它有效

 该算法保持不变式`length`始终等于仅由可接受的囚犯组成的当前最大后缀的大小。 

每当我们遇到无效囚犯时，任何有效段都不能越过该位置。 这意味着每个有效段必须完全位于一个有效块内。 对于一个长度的块`L`，每个连续窗口的大小`c`是有效的，并且这样的窗口的数量正好是`L - c + 1`。 

由于该算法只处理每个有效块一次并计算所有长度 -`c`在其中的窗口中，每个有效段都被计数一次且仅一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, t, c = map(int, input().split())
a = list(map(int, input().split()))

ans = 0
length = 0

for x in a:
    if x <= t:
        length += 1
    else:
        if length >= c:
            ans += length - c + 1
        length = 0

if length >= c:
    ans += length - c + 1

print(ans)
```实现直接遵循块计数思想。 

变量`length`存储当前连续有效区域的大小。 每次我们读取的值不超过`t`，我们将区域扩展一。 

当一个值超过`t`，我们知道当前区域已经结束。 如果它的大小至少为`c`，那么它包含有效的窗口。 窗口数量为`length - c + 1`。 

决赛`if`循环之后很容易忘记。 如果没有它，任何以最后一个元素结尾的有效块都不会被计算在内。 

所有计算都适合 Python 整数。 即使在最大的情况下，答案也最多是`n`。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, t, c = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0
    length = 0

    for x in a:
        if x <= t:
            length += 1
        else:
            if length >= c:
                ans += length - c + 1
            length = 0

    if length >= c:
        ans += length - c + 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("4 3 3\n2 3 1 1\n") == "2", "sample 1"

# minimum size
assert run("1 5 1\n3\n") == "1", "single valid prisoner"

 ## 边缘情况

 考虑一个坏囚犯分裂数组的情况：```
7 2 3
1 2 1 5 1 1 1
```扫描构建一个有效的长度块`3`，然后遇到`5`。 自从`5 > 2`，算法添加：```
3 - 3 + 1 = 1
```然后它将块长度重置为零并重新开始计数。 最终的块也有长度`3`，贡献另一个`1`。 总计变为`2`。 

现在考虑精确边界情况：```
4 3 4
1 2 3 1
```整个数组形成一个有效的长度块`4`。 自从`length == c`，公式给出：```
4 - 4 + 1 = 1
```这正确地计算了由整个数组组成的单个有效段。 

最后，考虑一个完全无效的数组：```
5 1 2
3 4 5 6 7
```每个值都超过`t`，所以算法反复重置`length`为零。 没有块达到大小`2`，所以答案仍然是`0`。
