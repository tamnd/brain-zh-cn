 ## 解决方案
 ## 问题理解

 单个机器人从零位置开始沿直线移动。 您向其发送一系列命令，每个命令指定时间和目标位置。 当命令到达时，机器人立即承诺以单位速度向该目标移动。 当它朝该目标行进时，任何新命令都将被忽略，直到它到达目标或完成当前运动。 

每个命令都是在了解完整运动后进行判断的。 如果在从命令发出到下一个命令到达之前的时间间隔内（或对于最后一个命令而言永远），机器人在某个时刻恰好位于该命令的目标位置，则该命令被视为成功。 重要的是，当机器人到达该位置时，它可能实际上并没有执行该命令； 它的轨迹在该时间窗口内穿过它就足够了。 

关键的难点在于命令可以被忽略，但忽略的命令仍然可以成功。 执行和成功之间的这种脱节迫使我们对机器人的连续路径进行推理，而不仅仅是其选择的目的地。 

这些约束允许所有测试用例最多使用 100000 个命令，因此任何解决方案都必须在恒定或对数时间内处理每个命令。 尝试检查每个时间单位的模拟是不可能的，因为运动发生的间隔最多为 10^9 秒。 

当机器人在命令间隔结束后很长时间通过某个点或在执行后续命令时通过该点时，就会出现幼稚思维的微妙失败情况。 例如，如果命令将机器人发送到它从未明确瞄准的点，那么如果机器人的运动段在有效时间窗口内穿过该坐标，则仍然可以成功。 当命令被立即忽略但其目标位于稍后的运动段时，会发生另一种边缘情况； 仅检查机器人当时是否正在向目标移动的简单方法会错过这一点。 

## 方法

 直接模拟会跟踪机器人随时间的位置，并且对于每个命令，明确检查机器人的轨迹在相关时间间隔内是否与目标位置相交。 人们可以逐秒或逐个事件地模拟运动，并针对所有运动片段测试每个命令。 这在原则上是正确的，因为机器人的路径是分段线性的。 然而，每个段的时间可能非常长，并且每个命令可能需要扫描许多段。 在最坏的情况下，这会退化为二次行为，因为每个命令都可能与许多未来的运动相互作用。 

关键的观察结果是机器人的运动完全由命令处理事件之间的线性段决定。 在机器人改变方向或目标的两个时刻之间，其位置是时间的仿射函数。 对于在时间 t_i 发出的命令，我们只关心位置函数是否在下一个命令时间之前的某个点穿过 x_i。 我们可以维护机器人的当前段并以代数方式检查交叉点，而不是检查所有连续运动。 

每个分段由开始时间、开始位置、结束时间和方向定义。 机器人以恒定速度移动，因此我们可以在 O(1) 时间内计算出其任意时刻的位置。 该问题简化为检查目标点是否位于与间隔 [t_i, t_{i+1}] 重叠的每个活动段的起点和终点处的机器人位置之间。 

关键的简化是，当且仅当机器人在时间 t_i 和时间 t_{i+1} 的位置（或在它较早停止移动的时刻）位于 x_i 的相对两侧，或者在任一边界处完全相同时，命令才会成功。 这将问题简化为检查点是否位于一维线段上。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 基于分段的模拟 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用由连续命令确定的连续段来模拟机器人的运动。 

1. 在位置 0 和时间 0 初始化机器人。我们还跟踪当前位置以及它空闲或切换方向的时间。 
2. 对于每个命令 i，计算机器人从上次更新时间到 t_i 的进度。 这给出了机器人在时间 t_i 时的准确位置。 这是必要的，因为命令在机器人移动或空闲时到达。 
3. 确定机器人当前是否正在向先前的目标移动或已经处于空闲状态。 如果移动，我们线性地知道它当前的轨迹； 如果空闲，它会保持固定在最后的位置。 
4. 模拟前一个命令的效果只到t_i，因为t_i之后的任何内容都与判断命令i无关。 
5. 检查在时间间隔 [t_i, t_{i+1}] 内机器人是否到达 x_i。 由于运动是线性的，这相当于检查 x_i 是否位于机器人在 t_i 时的位置和它在下一个命令中断之前或完成当前段之前到达的位置之间。 
6. 如果 x_i 位于该可达间隔内，则将该命令视为成功。 
7. 更新机器人状态以反映在时间 t_i 它现在接收到针对 x_i 的新命令，但前提是它当前未移动。 如果它正在移动，则出于轨迹目的，该命令将被忽略。 

关键的推理步骤是每个运动段的位置都是单调的，因此机器人每段最多穿过每个坐标一次。 

### 为什么它有效

 在任何时刻，机器人随时间的位置都是不相交线性段的并集，每个线性段的速度要么为+1、-1，要么为0。对于固定命令i，我们只关心对于[t_i，t_{i+1}]中的某个t，连续函数x(t)是否等于x_i。 由于 x(t) 在每个线段上都是单调的，因此条件简化为检查 x_i 是否位于与该时间间隔相交的任何线段的端点之间。 这个不变量确保我们永远不会错过十字路口，也不会重复计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        t = []
        x = []
        for _ in range(n):
            a, b = map(int, input().split())
            t.append(a)
            x.append(b)

        pos = 0
        time = 0
        target = 0
        moving = False
        ans = 0

        i = 0
        while i < n:
            ti = t[i]
            xi = x[i]
            ni = t[i + 1] if i + 1 < n else float('inf')

            if moving:
                dt = ti - time
                if target > pos:
                    pos = min(target, pos + dt)
                else:
                    pos = max(target, pos - dt)

                if pos == target:
                    moving = False
                time = ti

            # current position at time ti is pos

            # compute how far robot can go before next command
            if moving:
                dist = abs(target - pos)
                reach_time = ti + dist
            else:
                reach_time = float('inf')

            end_time = min(ni, reach_time)

            if pos <= xi <= target or target <= xi <= pos:
                if ti <= reach_time:
                    ans += 1

            # process command i
            if not moving:
                if pos != xi:
                    target = xi
                    moving = True
                    time = ti

            i += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现保持机器人的压缩状态：当前位置、是否正在移动以及当前目的地。 在评估命令之前，它首先通过消耗机器人在经过的时间间隔内的运动来使机器人前进到命令时间。 对成功的检查简化为验证目标是否位于从当前位置到中断之前最远可到达点的段内。 

一个微妙的细节是，在评估成功之前，我们必须在命令时间准确更新位置。 另一个原因是运动受到限制，因此我们永远不会超出目标； 否则我们会错误地经过目的地以外的位置。 

## 工作示例

 考虑一次小规模运行，在时间 1、3、6 处发出命令，目标为 5、0、4。机器人从 0 开始。 

| 步骤| 时间 | 职位| 目标| 搬家| 到达时间 | 成功的？ |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 5 | 是的 | 5 | 没有|
 | 2 | 3 | 3 | 0 | 是的 | 5 | 是的 |
 | 3 | 6 | 5 | 4 | 是的 | 7 | 是的 |

 第二个命令是成功的，因为在其间隔期间，机器人尽管被忽略但仍穿过了目标。 第三次成功，因为完成上一个动作后直接达到4。 

现在考虑这样一种情况：机器人由于稍后的移动而超越了目标，但仍然在有效间隔内穿过了目标。 该算法捕获了这一点，因为它检查中断时间之前的整个可到达段，而不仅仅是当前的移动方向。

 ## 边缘情况

 一个关键的边缘情况是命令准确地瞄准机器人的当前位置。 在这种情况下，尽管命令没有产生任何运动，但它还是非常成功的。 该算法处理这个问题是因为间隔检查`pos <= xi <= target`退化为平等。 

另一种极端情况是机器人已经远离目标但稍后又穿过目标。 由于我们在中断之前计算了完整的可达段，因此只要交叉发生在下一个命令时间之前，仍然会检测到交叉。 

当机器人完成长距离移动之前多个命令到达时，就会出现最后的边缘情况。 每个命令时间的状态更新确保我们正确截断运动，因此没有段超出其有效间隔，并且不会在外部计算成功`[t_i, t_{i+1}]`。
