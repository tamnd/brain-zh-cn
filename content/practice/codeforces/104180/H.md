 ## 解决方案
 ## 问题理解

 我们有一个非常大的矩形画布，概念上是一个坐标高达$10^9 \times 10^9$。 在此画布上，鲍勃已经绘制了几个轴对齐的矩形。 这些矩形彼此不重叠，因此每个绘制的单元最多属于一个矩形。 

画作完成后，一组垂直的柱子被雨水冲走了。 每个清洗的列都会删除其列索引与给定值之一匹配的每个已绘制单元格。 任务是计算删除位于这些已清洗列中的所有已绘制单元格后剩余多少已绘制单元格。 

输入由左下角和右上角描述的非重叠矩形以及被破坏的列索引列表组成。 输出是删除这些列中的所有绘制单元后剩余的总绘制区域。 

约束允许最多$2 \cdot 10^5$矩形和$2 \cdot 10^5$洗过的列，而坐标可以大到$10^9$。 这立即排除了任何基于网格的模拟。 即使显式存储每个单元或每个列的信息也是不可能的。 任何有效的解决方案都必须将问题简化为按间隔或聚合计数进行操作，最好是在$O((N + M) \log N)$或者$O(N + M)$。 

一个微妙的点是矩形是不相交的。 这消除了跨重叠形状的坐标压缩的需要，并保证每个矩形的贡献可以独立计算并安全地求和。 

边缘情况源于列与矩形的交互方式：

 实践中可能会出现零宽度的矩形，如果$c_1 = c_2$，表示单列条带。 如果该柱被清洗，整个矩形就会消失。 

示例：

 输入：```
1 1
3 1 3 5
3
```输出：```
0
```如果在不考虑简并矩形的情况下假设正宽度，则天真的每个单元格解释可能仍然会错误地计算它。 

另一个边缘情况是没有洗涤的列与任何矩形相交。 答案应该等于矩形面积的总和。 

例子：```
1 2
1 1 3 3
10
20
```输出：```
9
```最后，如果许多矩形重叠相同的列范围但在空间上不相交，我们必须避免重复计算，这是由问题陈述保证的，但如果不小心按列进行处理，很容易意外地重新引入。 

## 方法

 直接的方法是将每个矩形扩展为单位单元并减去洗涤的列。 这立即是不可行的。 单个矩形最多可以覆盖$10^{18}$在最坏的情况下，单元格，甚至迭代每个矩形的列也会降级为$O(N \cdot \text{width})$。 

更好的第一个观察是清洗仅影响列，而不影响行。 在给定的矩形内，每列的高度都精确地贡献给总绘制区域。 因此，每个矩形都可以看作是其垂直高度的贡献，均匀地应用于其列间隔$[c_1, c_2]$。 问题变成：对于每个矩形，计算其有多少列不在删除的集合中，并乘以其高度。 

剩下的困难是删除的列集很大并且是任意的。 检查每列的成员资格太慢。 相反，我们对删除的列进行排序，并使用二分搜索或指针扫描来计算矩形间隔和删除的集合之间的交集。 

由于矩形不重叠，因此我们可以独立处理每个矩形。 对于每个矩形，我们使用排序数组上的二分搜索来计算其水平范围内有多少已删除的列。 从总宽度中减去这个值就得到了幸存的列。 

这减少了排序问题$M$专栏和回答$N$范围计数查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（细胞/列模拟）|$O(N \cdot W)$|$O(W)$| 太慢了|
 | 最优（排序+每个矩形的二分搜索）|$O((N+M)\log M)$|$O(M)$| 已接受 |

 ## 算法演练

 我们将问题转化为计算每个矩形内剩余多少“好”列。 

1. 读取所有已清洗的列索引并对它们进行排序。 排序是必要的，因此我们可以使用二分搜索有效地计算任意区间中有多少个。 如果不排序，每个查询都需要扫描所有列。 
2. 将最终答案初始化为零。 我们将独立累积每个矩形的贡献，因为它们不重叠。 
3. 对于每个矩形，计算其垂直高度：$r_2 - r_1 + 1$。 这表示每个有效列在该矩形中的贡献量。 
4. 确定矩形水平跨度内的总列数，即$c_2 - c_1 + 1$。 
5. 使用二分查找来计算有多少个已清洗的列$[c_1, c_2]$。 这是通过查找第一个索引来完成的$\ge c_1$和第一个索引$> c_2$，并减去两个位置。 
6. 从总列中减去清洗的列以获得矩形内的幸存列。 
7. 将剩余列乘以矩形高度并添加到答案中。 

每个矩形都是独立处理的，因此我们永远不会冒重复计算或区域之间干扰的风险。 

### 为什么它有效

 关键的结构特性是矩形不重叠，这使得面积可累加。 每个矩形提供一个矩形的细胞块，并且洗涤独立地作用在柱上，均匀地去除所有矩形上的整个垂直切片。 这意味着单元格的生存仅取决于其列索引，而不取决于它属于哪个矩形。 因此，可以通过将移除的列的全局集合投影到其间隔并按高度缩放来评估每个矩形。 二分搜索步骤精确计算该投影大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    rects = []
    for _ in range(n):
        r1, c1, r2, c2 = map(int, input().split())
        rects.append((r1, c1, r2, c2))
    
    washed = [int(input()) for _ in range(m)]
    washed.sort()
    
    import bisect
    
    ans = 0
    
    for r1, c1, r2, c2 in rects:
        height = r2 - r1 + 1
        total_cols = c2 - c1 + 1
        
        left = bisect.bisect_left(washed, c1)
        right = bisect.bisect_right(washed, c2)
        
        bad_cols = right - left
        good_cols = total_cols - bad_cols
        
        if good_cols > 0:
            ans += good_cols * height
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对所有已清洗的列进行排序，以便我们可以有效地查询范围。 对于每个矩形，我们根据高度和宽度计算其几何贡献。 二等分操作精确地隔离了有多少洗过的列落入矩形的水平间隔。 减去这些就得出幸存的柱数，乘以高度将柱数转换为面积。 

一个常见的错误是忘记每一列贡献整个高度，而不仅仅是单个单元格。 另一个是错误计算间隔边界，特别是因为两个端点都包含在内。 使用`bisect_left`和`bisect_right`正确确保包含范围计数，无需手动逐一调整。

 ## 边缘情况

 关键的边缘情况是退化为单列的矩形。 例如：

 输入：```
1 1
2 7 5 7
7
```该矩形的高度为 4，宽度为 1。清洗后的柱子与它完全匹配。 二分查找发现其中有一个坏列$[7,7]$，使好的列为零，贡献也变为零。 这证实了宽度一间隔的正确性。 

当清洗的列完全位于所有矩形之外时，会出现另一种边缘情况：

 输入：```
1 2
1 1 3 3
10
20
```二分搜索返回矩形间隔的零坏列$[1,3]$，因此保留了整个区域。 该算法自然地处理这个问题，无需特殊的外壳。 

最后一个微妙的情况是多个具有不相交水平间隔但共享洗涤列的矩形。 由于每个矩形独立查询相同的排序数组，因此不存在干扰或重复计算，并且每个贡献都严格在其自己的范围内计算。
