 ## 解决方案
 ## 问题理解

 我们得到第一天收集的雨水的起始量，用整数表示$i$。 这个值决定了本周剩余时间的一切。 从第二天到第七天，雨量稳步增加：每天增加相同的增量$x$， 在哪里$x$计算为数字之和$i$。 总共 7 天，我们需要计算累计收集的水量。 

重新解释问题的一个有用方法是将其视为简单的算术序列。 第一项是$i$，并且每个下一项增加$x$。 所以序列看起来像：$i, i + x, i + 2x, \dots, i + 6x$。 任务是对所有这些项求和。 

约束很小，有$i \leq 10^5$，因此计算数字和并执行恒定数量的算术运算在性能方面是微不足道的。 即使每个测试用例的完全直接计算也是恒定时间。 

由于数字和的行为方式，边缘情况很微妙但很重要。 

一种边缘情况是$i = 0$。 数字和是$0$，因此所有 7 天的产量为零。 仅当数字和逻辑强大时，假设正数或忽略前导零行为的幼稚实现仍然可以正确处理它。 

另一个边缘情况是当$i$例如，有尾随零$i = 10000$。 数字和是$1$，不受零的影响，因此增量很小，但序列仍然正确增长。 错误通常来自于错误地将增量解释为“附加数字”而不是数字之和。 

最后，由于序列长度是固定的（7 个术语），因此在 Python 中不存在溢出的危险，但在更严格的语言中，使用大型算术的简单累加可能需要小心。 

## 方法

 蛮力的想法很简单。 我们计算数字和$x$，然后明确模拟这 7 天。 开始于$i$，我们反复添加$x$并累计总数。 这是正确的，因为它准确地反映了问题中描述的过程。 

由于只有 7 天，因此每个测试用例的这种方法的成本是恒定的。 即使我们重新计算数字和或重复执行算术，复杂性仍然受到固定常数的限制。 然而，更普遍的低效率在于忽略结构：序列是算术的，因此可以以封闭形式进行求和而不是迭代累加。 

关键的观察是该序列是第一项的算术级数$i$, 上学期$i + 6x$，总共 7 项。 等差数列的总和为：$$\text{sum} = \frac{7}{2} \cdot (2i + 6x)$$这将一切简化为计算一次数字和并应用直接公式。 

这将问题转化为纯算术问题。

 ## 算法演练

 1.读取整数$i$来自输入。 这是序列的基值，它定义了整个进程。 
2. 计算$x$, 的数字之和$i$。 该值充当固定的每日增量，因此正确性完全取决于正确提取数字。 
3. 认识到 7 个每日值形成一个等差数列，从$i$具有共同差异$x$。 
4. 使用等差数列公式计算总和：$$S = \frac{7}{2} \cdot (2i + 6x)$$这可以避免在 7 天内进行迭代，同时保持精确的等价性。 
5、输出$S$。 

### 为什么它有效

 每日值的构造保证了线性进展，因为每天仅取决于从输入导出的固定加性常数。 一次$x$是固定的，每一项都唯一确定为$a_k = i + kx$。 对这些项求和相当于对算术序列求和，并且封闭式公式在代数上与直接累加相同。 由于没有中间步骤修改$x$，结构在所有七个任期内保持稳定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

i = int(input().strip())

x = sum(int(c) for c in str(i))

# arithmetic series: i + (i+x) + ... + (i+6x)
# sum = 7/2 * (2i + 6x) = 7 * (2i + 6x) / 2
total = 7 * (2 * i + 6 * x) // 2

print(total)
```该解决方案读取输入并立即通过将整数转换为字符串并对字符求和来计算数字和。 这对于包括零在内的所有输入都是安全的，因为`"0"`产生正确的数字和为零。 

关键的实现细节是避免浮点运算。 尽管该公式涉及除以 2，但表达式始终为偶数，因此整数除法是安全的。 将其写为`7 * (2 * i + 6 * x) // 2`确保精确的整数输出。

 ## 边缘情况

 用于输入`0`，数字和为`0`，因此序列在所有 7 天中始终为零。 该算法计算$x = 0$，导致：$S = \frac{7}{2}(0) = 0$，它与预期输出完全匹配。 

用于输入`10000`，数字和为`1`。 序列变为：$10000, 10001, 10002, 10003, 10004, 10005, 10006$。 

该算法计算：$S = 7(20000 + 6)/2 = 70003$，与直接求和匹配。 

用于输入`99`，数字和为`18`。 序列增长得更快，但算术公式仍然适用不变。 每一项仅由固定增量决定，因此没有任何步长偏离算术级数定义。
