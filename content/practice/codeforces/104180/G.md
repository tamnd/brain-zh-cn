 ## 解决方案
 ## 问题理解

 我们得到了一系列独立的遭遇，每个遭遇都对应于田野中的一朵玫瑰。 当罗斯选择一朵玫瑰时，她会触发一个本地“追逐场景”，其中涉及相对于该玫瑰生成的怪物。 安全完成那次遭遇后，世界重置，所有玫瑰再次可用，但她会花费一些能量，具体取决于她如何处理那次遭遇。 

每朵玫瑰由两个参数描述。 第一个是与玫瑰的距离比例，定义怪物出现的位置以及它的运动如何受到限制。 第二个是速度倍增器，决定怪物与罗斯相比的移动速度。 

对于每一朵玫瑰，玫瑰必须决定她是否可以廉价地应对这次遭遇，或者是否必须花费精力使用特殊的循环运行策略来确保逃脱。 每次遭遇都会贡献零能量成本或从追逐的几何形状导出的正整数能量成本。 目标是选择一个玫瑰顺序及其子集，使消耗的总能量不超过 E，同时最大化她完成的遭遇次数。 

关键的结构点是遭遇是独立的：完成一朵玫瑰后，一切都会重置。 这消除了任何订购依赖性的需要，并减少了选择成本低于预算的项目的问题。 

N 到 500 以及 E 到 100000 的约束表明 O(NE) 动态规划解决方案是可行的，但结构甚至更简单：每朵玫瑰有效地减少到一个小的离散成本，因此贪婪选择就足够了。 

当怪物不比罗斯快时，就会出现微妙的边缘情况。 那样的话，罗丝总能在不消耗能量的情况下逃脱，所以成本贡献就变成了零。 如果一个天真的实现假设每朵玫瑰总是需要能量，它就会错误地低估。 

另一个陷阱是将循环转义选项误解为持续依赖于参数 r_i 的选项。 正确的解释将连续的几何形状折叠成离散的决定：要么不需要能量，要么固定的能量单位就足够了。 

## 方法

 蛮力的想法是模拟每一个可能的玫瑰子集，并检查它们的总能量成本是否保持在 E 范围内。由于每朵玫瑰都可以被拿走或跳过，这会导致 2^N 种可能性。 即使N=500，这也是完全不可行的，超过了天文数字的运算次数。 

一种更加结构化的方法来自于观察每朵玫瑰都是独立的，并且为总能源预算贡献固定成本。 一旦我们将每朵玫瑰减少为成本价值对，问题就变成在背包约束下选择尽可能多的物品。 然而，与成本差异很大的经典背包不同，这里每一朵玫瑰都只分解为两种可能的成本：零或一个能量单位。 

这立即简化了优化。 所有零成本的玫瑰都应该被采摘，因为它们不会影响预算。 之后，唯一的限制因素就是能容纳多少朵一费玫瑰，这直接受剩余能量的限制。 

这将问题从组合搜索转变为简单的计数和贪婪分配问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集枚举| O(2^N) | O(2^N) | O(N) | 太慢了|
 | 降低成本+贪婪选择 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们根据玫瑰是否需要使用特殊的逃生策略，将每朵玫瑰重新解释为具有能量成本。 

## 算法演练

1.对于每朵玫瑰，判断玫瑰是否能够在不消耗能量的情况下逃脱。 如果怪物严格来说不比罗斯快，那么遭遇就不需要能量。 
2. 将成本分配给此类玫瑰，因为它们始终是安全的。 
3. 将成本 1 分配给所有剩余的玫瑰，表示它们需要 1 单位的能量才能安全处理。 
4. 计算有多少朵成本为 0 的玫瑰。 这些都可以立即服用，不会影响能量。 
5. 从玫瑰总数中减去该计数，仅留下成本 1 朵玫瑰作为候选。 
6. 从这些花费的 1 朵玫瑰中，根据剩余能量 E 取尽可能多的玫瑰。 
7. 最终答案是所有成本0玫瑰加上预算内选择的成本1玫瑰的数量之和。 

这种排序有效的原因是成本 0 的项目严格占主导地位，并且永远不会干扰预算，因此延迟它们只会不必要地减少总数。 

### 为什么它有效

 关键的不变量是每朵玫瑰都独立贡献，并且具有固定的最小能量需求，不依赖于选择的顺序。 由于能量仅以整数单位消耗，并且完成后玫瑰之间没有相互作用，因此问题简化为在线性预算约束下最大化计数。 任何最佳策略必须首先包括所有零成本项目，然后贪婪地包括单位成本项目，直到预算耗尽，因为单位成本项目的子集没有比相同大小的任何其他子集提供任何优势。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, E = map(int, input().split())
    
    free = 0
    cost_one = 0
    
    for _ in range(n):
        r, k = input().split()
        r = float(r)
        k = float(k)
        
        # If monster is not faster, no energy needed
        if k <= 1.0:
            free += 1
        else:
            cost_one += 1
    
    # take all free ones
    ans = free
    
    # use remaining energy for cost-one roses
    ans += min(cost_one, E)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案一次读取所有玫瑰并将它们分类到两个桶中。 与 1.0 的浮点比较是关键的简化：它捕获怪物是否成为需要能量消耗的威胁。 

最后的贪婪步骤就是简单地拿走所有免费的玫瑰，然后用昂贵的玫瑰填充剩余的能量容量。

 ## 边缘情况

 当所有玫瑰的 k_i ≤ 1 时，每次相遇的能量为零。 在这种情况下，算法将每个项目分类为免费并立即返回 N，这与从未使用过预算约束的事实相匹配。 

当所有玫瑰k_i > 1且E较小时，只能取E玫瑰。 该算法通过使用 min(cost_one, E) 限制选择来直接强制执行此操作，确保不会过度使用能量。 

当E=0时，即使可能有很多玫瑰，也只能拿免费的。 该算法自然会处理这个问题，因为第二项变为零，并且只有免费的玫瑰才能得出答案。
