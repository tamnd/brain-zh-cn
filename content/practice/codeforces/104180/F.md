 ## 解决方案
 ## 问题理解

 我们正在模拟整数的确定性下降过程。 对于从 1 到给定限制的每个起始高度$H$，我们释放一个“雨滴”。 每个雨滴以离散的一秒为单位向下移动。 在一秒内，高度减少了当前高度的质因数总数，并以重数计算。 例如，12 贡献 3，因为$12 = 2^2 \cdot 3$，因此它会在一秒钟内失去 3 个单位的高度。 重复该过程，直到高度达到 1，该高度被视为地面并终止对该雨滴的模拟。 我们按顺序处理高度，等待每次下降完成后再开始下一次下降，并且我们需要所有起始高度的总秒数。 

核心输入只是最大起始高度$H$。 输出是起始值的所有单独下降时间的总和$1, 2, \dots, H$。 

约束条件$H \le 4 \cdot 10^6$排除任何通过每步进行新的分解来独立模拟每个起始值的情况。 对整个过程的简单模拟会重复对数字进行因子分解并重复减去值，从而导致最坏情况的行为$O(H \sqrt{H})$或者更糟，远远超过一秒。 

一个微妙的问题是“移动量”取决于素数因子的多重性，而不是不同素数。 将其与计算不同素数相混淆会产生错误的转换。 例如，12 会错误地移动 2 而不是 3，这会改变整个轨迹和总时间。 

另一个问题是在模拟过程中从头开始重新计算因子计数。 即使每个数字的因式分解是$O(\log n)$平均而言，乘以多达 400 万个州会使这个速度变得太慢。 

## 方法

 每个起始高度的直接模拟在概念上是简单的。 对于给定高度$x$，我们重复计算它的素因数和$\Omega(x)$，然后设置$x := x - \Omega(x)$，累积时间直至$x = 1$。 为所有人做这件事$x \le H$准确地产生答案。 正确性很明显，因为它反映了流程定义。 

瓶颈在于重新计算$\Omega(x)$反复。 即使我们预先计算$\Omega(x)$为所有人$x$使用筛子，我们仍然需要模拟每个起始值的转换。 关键的观察是，每个状态转换仅取决于较小的值：当我们处于高度时$x$，我们跳到$x - \Omega(x)$，它严格较小，因为$\Omega(x) \ge 1$为了$x \ge 2$。 这创建了对整数的自然依赖 DAG。 

这意味着我们可以按高度递增的顺序计算答案。 如果我们已经从所有较小的值中知道所需的时间，那么从$x$只是 1 加上距下一个位置的时间。 这将问题转换为线性状态空间上的动态规划计算，其中的转换由预先计算的函数定义$\Omega(x)$。 

我们首先预先计算$\Omega(x)$为所有人$x \le H$使用改进的筛子来积累多重质因子。 然后我们计算一个 DP 数组，其中每个条目仅依赖于先前计算的条目。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(H \cdot \text{steps} \cdot \log H)$|$O(1)$| 太慢了|
 | 筛分 + DP |$O(H)$|$O(H)$| 已接受 |

 ## 算法演练

 ### 预计算素数因子计数

 1. 创建数组`omega`尺寸的$H+1$，初始化为零。 
2. 对于每个整数$p$从 2 到$H$，如果尚未标记，则将其视为素数。 
3. 对于每一个倍数$k$的$p$, 增量`omega[k]`除以1，并通过筛子结构继续隐式除法。 
4. 处理完所有素数后，`omega[x]`等于质因数的总数$x$以重数来计算。 

这是有效的，因为每次我们遇到素数时$p$，每个倍数在其因式分解中恰好贡献了该素数的一个副本。 

### 跨越高度的动态规划

 1. 创建数组`dp`尺寸的$H+1$， 在哪里`dp[x]`表示从高度开始下降的时间$x$达到 1。 
2. 设置`dp[1] = 0`因为从地面开始的下降已经完成。 
3.对于每一个$x$从 2 到$H$，计算下一个位置为$nx = x - \omega[x]$。 
4. 定义`dp[x] = dp[nx] + 1`。 

这种排序有效的原因是$nx < x$， 所以`dp[nx]`处理时总是已经计算过$x$。 

###最终积累

 1. 总和`dp[x]`为了$x = 1$到$H$，对应于顺序滴下所有雨滴的总时间。 

### 为什么它有效

 DP 依赖于严格的递减过渡：每个高度一步都会移动到一个严格较小的高度。 这保证了计算时`dp[x]`，所有可到达的状态$x$已经解决了。 每个`dp[x]`表示遵循确定性规则达到 1 所需的确切转换次数，因此对所有起始高度进行求和可以正确聚合总运行时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    H = int(input().strip())
    
    omega = [0] * (H + 1)
    
    for i in range(2, H + 1):
        if omega[i] == 0:
            for j in range(i, H + 1, i):
                x = j
                while x % i == 0:
                    omega[j] += 1
                    x //= i
    
    dp = [0] * (H + 1)
    total = 0
    
    for i in range(2, H + 1):
        nxt = i - omega[i]
        dp[i] = dp[nxt] + 1
        total += dp[i]
    
    print(total)

if __name__ == "__main__":
    solve()
```第一个循环构造函数$\omega(x)$，具有多重性的质因数的数量，使用类似筛子的方法。 对于每个素数$i$，我们扫描它的倍数并反复除以$i$，累计多少次$i$出现在每个数字中。 

然后 DP 循环按升序构建答案。 由于每次转换都会达到一个严格较小的数字，`dp[nxt]`保证已经计算出来。 我们还逐步积累答案，而不是单独存储所有内容。 

一个常见的陷阱是忘记我们需要多样性，这就是为什么我们反复划分`x`在内循环中，而不是简单地每个素数递增一次。

 ## 边缘情况

 对于$H = 1$，DP 循环永远不会运行，答案为零，这与没有发生雨滴运动的解释相匹配。 该算法清楚地处理了这个问题，因为数组已初始化并且累加循环从 2 开始。 

对于像这样的素数$H = p$，我们得到$\omega(p) = 1$，所以过渡总是到$p-1$。 DP 确保素数仅依赖于已计算的复合值或更小的值，因此不会发生循环。 

对于 2 的幂（例如 16），我们得到长链，例如$16 \to 12 \to 9 \to 7 \to 6 \to 4 \to 2 \to 1$。 DP 正确地处理了这个问题，因为每一步都会严格减少索引，从而保证终止并正确累积先前计算的状态。
