 ## 解决方案
 ## 问题理解

 我们得到了阿尔贝托按固定顺序饮用的一系列能量饮料。 每喝一杯都会贡献一定量的能量，一旦他开始喝一杯，他就会在继续之前完全消耗掉它。 这些能量会在同样固定的锻炼结构内累积并消耗在俯卧撑上。 

单一锻炼“组”包括进行俯卧撑，并增加能量消耗。 第一个俯卧撑消耗 1 个单位的能量，第二个俯卧撑消耗 2 个单位的能量，依此类推，直到 M 个俯卧撑，其中第 k 个俯卧撑消耗 k 个能量。 阿尔贝托必须完成整组才能算数，如果在任何时候他无法承担当前组中的下一个俯卧撑，则该组被视为失败并立即停止。 完成全套后，他的能量重置为零。 

任务是确定在按顺序消耗的饮料能量耗尽之前他可以完成多少组。 

从约束中观察到的关键是，N 可以达到 100000，M 可以达到 1000。这意味着直接按单位能量模拟每次俯卧撑的解决方案在最坏的情况下会太慢，因为这会降低到大约 O(NM) 或更糟。 然而，N 很大，而 M 相对较小，这暗示每杯饮料或每组记账的 O(1) 或 O(M) 摊销工作是可以接受的。 

一个幼稚的错误是在逐渐消耗能量饮料的同时逐一模拟每个俯卧撑。 另一个微妙的陷阱是在部分消耗点之间错误地重置能量，尤其是当一杯饮料恰好在一组边界处喝完时。 

朴素俯卧撑模拟的具体失败案例：

 输入：```
1 3
10
```粗心的模拟可能会反复减少每次俯卧撑的能量，并且无法认识到完整的三角形成本 1 + 2 + 3 = 6 完全适合，然后 4 剩余的能量无法开始新的一组（再次需要 1+2+3，但每组重置）。 正确的输出是 1。任何在整组后未正确重置或对饮料的部分进度处理不当的实现都可能很容易错误计数。 

另一个边缘情况：

 输入：```
2 3
3 3
```这里每杯饮料都很小，但加在一起正好可以喝一整套。 一种贪婪的方法是“过早重置”每杯而不是每组，会错误地生成 0 或 2，具体取决于实现细节。 

## 方法

 暴力方法是完全按照描述来模拟 Alberto 的整个过程。 我们保持当前的能量，迭代饮料，对于每个能量单位，我们依次模拟俯卧撑。 对于每组，我们跟踪下一个所需的成本 k，相应地减少能量，并增加 k 直到我们完成该组或失败。 如果我们在比赛中失败，我们就会完全停止。 这是正确的，因为它准确地反映了问题定义。 

然而，这种模拟可能会变得昂贵，因为每个能量单位可能对应于多次俯卧撑尝试，并且每组需要总计最多 M 个俯卧撑。 在最坏的情况下，N 很大，M 为 1000，导致大约 O(NM) 或更差的行为，特别是当能量值很大并且每次俯卧撑重复处理时。 

关键的见解是每组都有固定的总能量需求：1 + 2 + … + M = M(M+1)/2。 这将每组减少为单个阈值检查，而不是增量模拟。 我们不是模拟俯卧撑，而是从饮料中积累能量，直到达到或超过这个阈值。 每次达到目标时，我们都会数一整组并精确减去所需的数量，将能量重置为零。 

这就将问题转化为反复积累能量，直到达到固定目标，然后重新设置，这是标准的贪婪积累模式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(N·M) | O(1) | O(1) | 太慢了|
 | 贪婪阈值积累| O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 设 S = M(M+1)/2，即全套动作所需的总能量。 

1. 在开始时计算一次S。 这代表了在不模拟单个俯卧撑的情况下完成一组俯卧撑的全部成本。 
2. 初始化 current_energy = 0 和 Completed_sets = 0。 
3. 迭代每个能量饮料值 E[i]。 
4. 将 E[i] 添加到 current_energy，因为 Alberto 按顺序喝完了饮料。 
5. 当current_energy至少为S时，从current_energy中减去S并增加completed_sets。 

这代表使用累积的能量完成一组或多组全套。 
6. 继续，直到所有饮料都加工完毕。 
7. 输出completed_sets。 

重要的推理步骤是将每个集合视为固定的“能量检查点”。 一旦积累了足够的能量，如果一大杯饮料使总能量远远超过 S，则可以一步完成多组。 

### 为什么它有效

 每组都是独立的，因为完成后能量重置为零。 这意味着一组中的部分进展不会延续。 因此，系统的行为就像使用传入的水块（饮料）重复填充一桶容量为 S 的水。 每次桶装满时，我们都会计算一次完成并将其清空。 由于集合内的能源使用严格增加但具有确定性，因此其总成本是固定的并且与能源如何到达无关。 这使得贪婪积累变得精确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    N, M = map(int, input().split())
    E = list(map(int, input().split()))

    target = M * (M + 1) // 2
    energy = 0
    sets = 0

    for x in E:
        energy += x
        while energy >= target:
            energy -= target
            sets += 1

    print(sets)

if __name__ == "__main__":
    main()
```该解决方案仅依赖于维护两个变量：当前累积能量和完成组数。 三角数预先计算一次，避免重复求和。 内部 while 循环可能看起来令人担忧，但目标的每次减法都对应于一个完成的集合，因此在整个执行过程中，它运行的次数最多与完成的集合的数量相同，使其摊销呈线性。 

一个常见的实现错误是在减去目标时使用单个 if 而不是 while 。 当一次大杯饮料完成多组时，这种方法就会失败。

 ## 边缘情况

 一个关键的边缘情况是单杯饮料含有足够的能量来完成多组。 例如：

 输入：```
1 4
100
```这里 M = 4，所以 S = 10。从 100 能量开始，算法重复减去 10，产生 10 个完整集合，留下 0 余数。 while 循环可以正确处理这个问题，而基于 if 的实现只会计算一组并留下不正确的剩余能量。 

另一种边缘情况是能量与阈值完全匹配时：

 输入：```
2 3
3 3
```S = 6。第一次饮用后，能量为 3。第二次后，能量变为 6，这恰好触发一组并重置为 0。比较中的任何差一错误（使用 > 而不是 >=）都会错误地无法计算该组。
