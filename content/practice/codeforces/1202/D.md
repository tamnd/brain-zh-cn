 ## 解决方案
 ## 问题理解

 我们被要求构造一个仅由数字 1、3 和 7 组成的字符串，以便一个非常特定的模式作为子序列出现指定的次数。 该模式是序列“1 后跟 3 后跟 3 后跟 7”，我们必须确保形成该模式的字符串中选择索引的方式总数恰好是给定的数字$n$。 

这里的子序列意味着我们可以在不改变顺序的情况下从字符串中删除字符，并且我们对形成模式 1、3、3、7 的每个不同的索引选择进行计数。 

输入由最多 10 个独立查询组成，每个查询给出一个目标计数$n$最多$10^9$。 对于每个查询，我们必须输出最多长度的任何有效字符串$10^5$这准确地实现了 1337 类型的许多子序列。 

对值的约束$n$是关键难点。 在生成过程中明确“计算子序列”的直接构造会太慢，因为简单的计数涉及跟踪许多重叠选择的组合贡献。 

当字符串包含很少的 1 或 7 时，就会出现微妙的边缘情况。 例如，如果没有 1，则答案一定是 0，但是$n$总是至少为 1，因此每个有效的结构必须至少包含一个 1 和一个 7。类似地，即使所有数字都存在，以错误的顺序放置数字也会默默地消除所有有效子序列。 

另一种失败模式来自假设贡献独立性：插入额外的 3 不仅仅会线性缩放计数，因为每对 1-7 都会与选择其间的两个 3 的方式数量相乘地相互作用。 

## 方法

 一个蛮力的想法是尝试为每个候选者使用动态编程生成字符串并计算子序列。 对于固定长度的字符串$m$，可以计算 1337 个子序列$O(m)$通过维护部分模式的计数：到目前为止 1 的数量、13 的数量、133 的数量和 1337 的数量。 但是，如果我们尝试搜索长度达到的所有字符串$10^5$，可能性的数量是$3^{100000}$，这是完全不可行的。 

即使是增量构建字符串并跟踪 DP 状态的更结构化的暴力，仍然呈指数级分支。 核心问题是我们正在尝试_设计_具有特定组合输出的字符串，而不仅仅是评估一个。 

关键的观察结果是子序列 1337 的结构是乘法的并且可以通过块构造来控制。 如果我们固定 1 和 7 的相对顺序，并将所有 3 放在它们之间的一个块中，子序列的数量就变成一个简单的组合值：选择任何 1 和任何 7，乘以在它们之间选择两个 3。 这减少了使用组合构建块构造整数的问题。 

更准确地说，如果我们将字符串排列为：

 1 后跟 k 个副本 3 后跟 7，

 那么每个子序列1337都是通过在k中选取单个1、单个7和任意两个3来形成的。 这有助于$\binom{k}{2}$。 这为我们提供了一种使用三角形数字表示数字的可控方法。 通过组合多个适当分开的块，我们可以表达任何$n$作为二项式贡献的总和，可以贪婪地构建。 

这减少了分解任务$n$转化为形式的值$\binom{k}{2}$，每个都可以用短字符串块表示，同时确保总长度保持在限制范围内。

 ## 算法演练

 我们通过分解目标计数来构建字符串$n$转化为三角形数的贡献。 

1. 从可以贡献 1337 形式的子序列的最大可能块开始。 

我们观察到像这样的结构`1 + k 3s + 7`准确贡献$\binom{k}{2}$子序列，因为每个有效子序列必须选择单个 1、单个 7 以及 k 个中间 3 中的任意两个位置。 

这很重要，因为它将组合计数问题转变为从多重集中选择对。 
2. 选择最大的$k$这样$\binom{k}{2} \le n$。 

这是一个贪婪的步骤：我们希望快速减少剩余部分，同时保持较小的构造尺寸。 
3. 减法$\binom{k}{2}$从$n$，并附加块：

 首先是 1，然后是 3 的 k 个副本，然后是 7。 

该块贡献的数量恰好等于我们减去的数量，因此它占总计数的不相交部分。 
4. 重复直到$n = 0$。 

每次迭代都会删除一大块，并且值$k$减少为$n$缩小，确保终止$O(\sqrt{n})$步骤。 
5. 按顺序连接所有块。 

块的排序不会产生交叉交互，因为每个 1337 子序列必须在单个块内恰好使用一个 1 和一个 7； 块通过构造被隔离。 

### 为什么它有效

 核心不变量是每个构造的块都是独立的：每个子序列 1337 完全在单个块内形成，因为没有有效的子序列可以将一个块中的 1 与另一个块中的 7 混合而不破坏 3 的所需顺序。 由于每个块都有自己独特的 1 和 7 边界，因此任何有效的子序列都必须选择同一块内的两个端点，从而强制独立。 

因此，子序列的总数是每个块的贡献之和，每个块的贡献等于一个二项式系数。 贪婪分解保证这些系数的总和恰好为$n$，所以最终的字符串恰好具有所需数量的子序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build(n):
    res = []
    while n > 0:
        k = 1
        while (k + 1) * k // 2 <= n:
            k += 1
        res.append("1" + "3" * k + "7")
        n -= k * (k - 1) // 2
    return "".join(res)

t = int(input())
for _ in range(t):
    n = int(input())
    print(build(n))
```该代码在每一步都会贪婪地构建尽可能大的块。 内循环求最大值$k$这样$\binom{k}{2}$不超过剩余的$n$。 一旦选择，该块就会被附加，并从剩余目标中删除贡献。 

一个微妙的实现细节是三角数使用$k(k-1)/2$， 不是$k(k+1)/2$，因为我们从 k 个位置中选择两个 3。

 ## 边缘情况

 最小的情况是$n = 1$。 该算法选择$k = 2$， 自从$\binom{2}{2} = 1$，产生区块`1337`。 所有子序列都被迫选择两个 3，因此恰好存在一个有效子序列。 

对于更大的值，例如$n = 6$，算法选择$k = 4$因为$\binom{4}{2} = 6$。 这会产生一个块`1 3333 7`。 每个有效子序列对应于在四个 3 中选择任意一对位置，恰好给出 6 种组合。 

对于需要多个块的情况，例如$n = 10$，第一步选择$k = 4$贡献 6，剩下 4。然后$k = 3$贡献3，留下1，最后$k = 2$贡献 1. 每个块都是独立的，因此不会出现跨块子序列，并且总和保持精确。
