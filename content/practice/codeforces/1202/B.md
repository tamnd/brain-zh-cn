 ## 解决方案
 ## 问题理解

 我们得到一个很长的十进制字符串，它是由一个非常简单的计数器过程的输出子序列生成的。 计数器始终从零值开始。 在每一步中，它都会打印当前值的最后一位数字，然后将该值增加 x 或 y，其中 x 和 y 是从 0 到 9 的固定数字。永远重复此操作会生成无限的数字流，但只有其中一些数字记录在我们看到的最终字符串中。 

我们的任务是考虑从 0 到 9 的每个有序对 (x, y)，并决定必须将多少位数字插入到给定字符串中，以便可以通过从该 (x, y) 过程的有效计数器输出中删除一些数字来获得该字符串。 插入对应于原始生成流中丢失的数字。 

因此，对于每一对，我们实际上是在问：如果我们尝试将给定字符串对齐为有效输出的子序列，那么我们被迫“跳过”的计数器发出的最小数字是多少？ 

输入字符串可能非常大，最多可达 200 万个字符，这会立即排除任何尝试在完整生成的序列上以简单的方式独立模拟每个 (x, y) 计数器的解决方案。 有 100 个可能的对，因此即使每对进行线性模拟也可能面临数亿次操作的风险，并且字符串上的任何二次行为都是不可能的。 

一个微妙的问题来自于这个过程不是确定性的。 对于任何值，+x 和+y 转换都是可能的，因此生成的序列不是唯一的。 我们可以选择最适合输入字符串的操作顺序。 

幼稚的方法通常会在两个方面失败。 首先，贪婪地匹配字符串的字符而不记住未来的后果可能会陷入存在更好的对齐但不再可达的状态。 其次，通过完全重新计算独立处理每个（x，y）会导致运行时间不可行。 

## 方法

 直接模拟的观点是将状态视为当前计数器值模 10，因为只打印最后一位数字。 从数字状态 v，该过程打印 v，然后移动到 (v + x) mod 10 或 (v + y) mod 10。这在 10 个节点上形成一个有向图。 

我们还需要将此生成的流与给定的字符串作为子序列对齐。 每当生成的数字与下一个需要的字符匹配时，我们就可以选择使用它； 否则，我们将其视为对字符串的插入。 

蛮力策略将明确探索在匹配字符串时遍历该图的所有方法。 这自然会导致由该对（当前数字，字符串中的位置）定义的状态。 每个状态都可以通过两种方式转换，我们可以根据相等性来匹配或跳过字符。 

这将创建一个具有大约 10 × n 状态的图。 每个状态有两个转换，因此每个 (x, y) 的转换总数约为 20n 个。 由于有 100 对，在最坏的情况下这大约是 2 × 10^8 转换，这是边界，但如果使用简单循环仔细实现并且没有开销，那么在优化的 Python 中仍然可以接受。 

使这一点可行的关键观察是字符串位置总是向前移动，而不是向后移动。 这可以防止第二维中的循环，并保证我们永远不会以创建无限处理的方式重新访问相同的（数字，位置）对。 该结构本质上是字符串位置上的分层图。 

因此，我们不考虑任意最短路径，而是将其视为分层动态过程，其中每一层对应于字符串的前缀，并且转换仅在该层结构中向前移动。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全路径模拟 | 指数| 指数| 太慢了 |
 | DP over（数字，位置）| O(100·n) | O(100·n) | O(n) | 已接受 |

 ## 算法演练

 对于固定对 (x, y)，我们使用动态编程模拟计数器如何与字符串对齐，这些状态跟踪当前数字以及字符串的匹配量。 

1. 我们定义一个状态为(v, i)，其中v是计数器值当前的最后一位，i是字符串中已经匹配到的字符数。 
2. 我们从 (0, 0) 开始，因为计数器从值 0 开始，而且我们还没有匹配任何字符。 
3. 从状态 (v, i) 开始，计数器发出数字 d = v。然后我们考虑该数字是否与下一个所需字符 s[i] 匹配。 
4. 如果 d 等于 s[i]，我们可以移动到 i + 1，而无需付出任何代价。 如果不匹配，我们将其视为对字符串的插入，并支付成本 1，同时保持 i 不变。 
5. 处理匹配决策后，我们通过将 x 或 y 添加到 v 模 10 来转换计数器状态，给出两个可能的下一个数字状态。 
6. 我们在所有可达状态上使用类似队列的传播来继续此过程，确保每当我们为给定 (v, i) 达到更好的配置时，我们都会更新它。 
7. (x, y) 的最终答案是 i 等于字符串全长的所有状态中的最小成本。 

它起作用的原因来自于每个状态 (v, i) 表示某些生成序列的前缀与输入字符串的前缀之间的有效对齐的不变性。 每个转换完全对应于消耗生成的数字或跳过它，并且没有转换违反任一序列的顺序。 由于探索了 x 和 y 转换的所有可能选择，因此可以达到任何有效的对齐方式，并且 DP 始终保持其中的最佳成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(x, y, s):
    n = len(s)
    INF = 10**18

    dist = [[INF] * (n + 1) for _ in range(10)]
    dist[0][0] = 0

    from collections import deque
    dq = deque()
    dq.append((0, 0))

    while dq:
        v, i = dq.popleft()
        cur = dist[v][i]
        if i == n:
            continue

        d = v
        ni = i
        if i < n and s[i] == str(d):
            ni = i + 1
            cost = cur
        else:
            cost = cur + 1

        for nv in ((v + x) % 10, (v + y) % 10):
            if cost < dist[nv][ni]:
                dist[nv][ni] = cost
                dq.append((nv, ni))

    ans = min(dist[v][n] for v in range(10))
    return -1 if ans == INF else ans

def main():
    s = input().strip()
    res = [[0] * 10 for _ in range(10)]

    for x in range(10):
        for y in range(10):
            res[x][y] = solve_case(x, y, s)

    for i in range(10):
        print(*res[i])

if __name__ == "__main__":
    main()
```核心实现保留数字状态的 2D 距离表以及已匹配的字符串数量。 每次转换都会更新数字和匹配的前缀长度。 仅当发出的数字与下一个所需字符不匹配时，成本才会累积，这直接对输入字符串中的插入进行建模。 

下一个状态 (v + x) 和 (v + y) 的循环捕获计数器的不确定性选择。 该队列确保我们以成本变化的递增顺序传播改进，即使转换是统一的，也有效地表现得像 0-1 BFS 风格松弛。 

最后一步以完全匹配长度扫描所有数字状态，因为计数器在消耗整个字符串后可能以任何数字结束。 

## 工作示例

 考虑像 s = "0840" 这样的短字符串和固定对 (x, y) = (4, 3)。 我们将状态跟踪为（v，i，成本）。 

| 步骤| 状态 (v, i) | 发射数字 | 比赛结果 | 成本| 接下来的状态 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (0, 0) | (0, 0) | 0 | 比赛| 0 | (4, 1), (3, 1) |
 | 2 | (4, 1) | 4 | 不匹配| 1 | (8, 1), (7, 1) | (8, 1), (7, 1) |
 | 3 | (8, 1) | 8 | 比赛| 1 | (2, 2), (1, 2) | (2, 2), (1, 2) |

 该跟踪显示了匹配如何提高索引，而不匹配则如何增加插入成本。 

现在考虑 x = y = 2 且 s =“0840”的情况。 该图变得确定性，但我们仍然允许跳过。 

| 步骤| 状态 (v, i) | 发射数字| 比赛结果 | 成本|
 | --- | --- | --- | --- | --- |
 | 1 | (0, 0) | (0, 0) | 0 | 比赛| 0 |
 | 2 | (2, 1) | 2 | 不匹配| 1 |
 | 3 | (4, 1) | 4 | 不匹配| 2 |

 这表明即使结构固定，DP 仍然跟踪最佳的跳过决策。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    n = len(s)
    INF = 10**18

    def solve_case(x, y):

        dist[0][0] = 0

        dq = deque([(0, 0)])

        while dq:
            v, i = dq.popleft()

            if i == n:

            d = v
            ni = i + 1 if i < n and s[i] == str(d) else i
            cost = cur + (0 if ni != i + 1 else 0)  # simplified check

                if ncost < dist[nv][ni]:
                    dist[nv][ni] = ncost
                    dq.append((nv, ni))

        ans = min(dist[v][n] for v in range(10))
        return -1 if ans == INF else ans

    res = [[solve_case(x, y) for y in range(10)] for x in range(10)]
    return "\n".join(" ".join(map(str, row)) for row in res)

 ## 边缘情况

 对于由单个字符组成的字符串，例如`"0"`，DP 从 (0, 0) 开始，立即匹配，无需任何转换。 任何允许在一个循环中保持在数字 0 的对 (x, y) 将产生成本 0，而其他对则需要至少一次插入。 该算法可以正确处理此问题，因为所有不匹配都会在第一次状态转换时立即进行计数。 

对于像这样的字符串`"999999"`，许多转换在早期步骤中会不匹配，但 DP 仍然跟踪最佳对齐，因为每个状态独立地累积插入成本。 该算法从不假设早期的不匹配在全局上都是不好的，它只沿着有效路径聚合局部惩罚。
