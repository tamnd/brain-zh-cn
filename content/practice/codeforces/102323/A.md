 ## 解决方案
 ## 问题理解

 任务是检查多个名称并确定每个名称包含的元音是否多于辅音。 唯一的元音是五个小写字母`a`,`e`,`i`,`o`， 和`u`。 其他所有小写字母都是辅音。 

对于每个名称，程序必须准确地再现所读取的名称，然后打印`1`如果它的元音数量严格大于它的辅音数量，并且`0`否则。 原来的UCF本地编程竞赛声明指定有`n`名称，每个名称包含 1 到 20 个小写字母，输出由原始名称和相应的决策组成。 

最大名称长度仅为 20，因此即使是简单的扫描也足够快。 线性扫描对每个名称最多执行 20 个字符检查。 通过根据所有五个可能的元音检查字符的自然实现，每个名称最多 100 次简单比较。 即使名称的数量很大，这里也没有理由考虑二次或指数算法。 

比较必须严格。 例如，输入```
1
ab
```包含一个元音和一个辅音，所以正确的输出是```
ab
0
```粗心的实现使用`vowels >= consonants`会错误打印`1`。 

另一个边缘情况是名称不包含元音。 为了```
1
bcdf
```元音计数为零，辅音计数为 4，因此输出为```
bcdf
0
```初始化答案的实现`1`只有在找到元音后才更改它可能会弄错这种情况。 

相反的极端也很重要。 为了```
1
aeiou
```所有五个字符都是元音，所以正确的输出是```
aeiou
1
```程序应该计算每次出现的次数，而不仅仅是确定名称是否至少包含一个元音。 

## 方法

 最直接的方法是检查每个名字中的每个字符并确定它是否是其中之一`a`,`e`,`i`,`o`， 或者`u`。 我们维护一个元音计数器，并在当前字符是元音时递增它。 由于名称长度最多为 20，因此显式比较每个字符与所有五个元音的最坏情况是`5 * 20 = 100`一个名字的字符比较。 因此总工作量为`O(5n)`，这简化为`O(n)`对于长度的名称`n`。 这种方法已经完全符合竞赛指定的一秒限制和 256 MB 内存限制。 

一个稍微简洁的版本观察到，五个元音的固定集合中的成员资格可以直接用字符串表示，例如`"aeiou"`。 然后`ch in "aeiou"`回答当前字符是否为元音，而扫描本身保持线性。 重要的结构是每个角色都独立地对答案做出贡献。 相邻字符之间没有交互，因此没有理由构建子字符串、对名称进行排序或执行重复搜索。 

蛮力版本和最优版本具有相同的渐近复杂度，因为可能的元音字母表具有恒定的大小。 优化主要是减少不必要的常量工作，以及底层操作的表达更加清晰。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(5n) = O(n) | O(1) | O(1) | 已接受 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 在给定的约束下，不存在真正太慢的暴力算法。 即使是五次比较的版本也仅对最长的名称执行 100 次元音比较。 说它太慢就会夸大其限制。 一次性成员资格检查更可取，因为它直接对问题进行建模并避免了不必要的因子 5。 

## 算法演练

 1. 读出名字的数量，`t`，因为输入包含多个独立的案例。 
2. 对于每个名字，初始化`vowels`为零。 计数器准确地表示到目前为止已处理的属于元音集的字符数。 
3. 从左到右扫描姓名。 对于每个字符，测试它是否属于`"aeiou"`。 如果是，则增加`vowels`; 否则保持计数器不变，因为该字符是辅音。 
4. 扫描完整姓名后，其辅音数为`len(name) - vowels`。 比较这两个计数即可确定所需的结果。 
5. 先打印原名，再打印`1`什么时候`vowels > len(name) - vowels`， 和`0`否则。 严格的`>`比较可以正确处理相等计数的情况。 

### 为什么它有效

 处理完名称的任何前缀后，`vowels`正是该前缀中元音字符的数量。 每个字符都会被分类一次，所以当扫描结束时，`vowels`等于整个名字中元音的总数。 由于每个字符要么是元音要么是辅音，所以剩下的`len(name) - vowels`字符正是辅音。 因此最终的比较打印`1`正是当元音的数量大于辅音的数量时。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        name = input().strip()

        vowels = 0
        for ch in name:
            if ch in "aeiou":
                vowels += 1

        consonants = len(name) - vowels

        print(name)
        print(1 if vowels > consonants else 0)

if __name__ == "__main__":
    solve()
```第一行给出了独立名称的数量，因此外循环准确处理`t`案例。 致电给`strip()`删除由产生的换行符`input()`同时保留名称的实际小写字母。 

内部循环实现算法演练步骤 3 中的扫描。表达式`ch in "aeiou"`就足够了，因为该语句将名称限制为小写字母。 无需处理大写元音或标点符号。 

计算元音后，从名称长度中减去辅音计数，无需第二次扫描。 最终比较使用`>`而不是`>=`，这是严格区分更多元音和相同数量元音的边界条件。 

Python 中不存在整数溢出问题，并且该算法仅存储当前名称和一个整数计数器。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每个名字 O(L) | 长度名称的每个字符`L`检查一次，并且元音集具有恒定的大小。 |
 | 空间| O(1) 辅助 | 除了输入字符串本身之外，只需要元音计数器和一些标量变量。 |

 和`L <= 20`，每个名称最多需要 20 次迭代。 即使是显式的五向元音比较也只需要对最大可能名称进行 100 个字符比较，因此该解决方案远远低于可用的一秒时间限制。 与 256 MB 限制相比，内存使用量也可以忽略不计。

 ## 边缘情况

 对于严格的比较边界，请考虑精确的输入```
1
ab
```该算法开始于`vowels = 0`。 上面写着`a`，将计数器增加到`1`，然后读取`b`并将其保留在`1`。 该名称的长度为二，所以`consonants = 2 - 1 = 1`。 自从`1 > 1`为假，输出为```
ab
0
```这抓住了将平等视为成功案例的常见错误。 

对于没有元音的名字，请考虑```
1
bcdf
```每个角色都未能通过会员测试，所以`vowels`保持为零。 辅音计数变为`4 - 0 = 4`，以及比较`0 > 4`是假的。 输出是```
bcdf
0
```在这种情况下，计数器不需要进行特殊校正。 

对于仅包含元音的名称，请考虑```
1
aeiou
```这五个字符中的每一个都属于元音集，因此计数器达到 5。 辅音数是`5 - 5 = 0`， 和`5 > 0`是真的。 输出是```
aeiou
1
```该算法将重复出现的次数计为单独的元音，这是必需的。 例如，最大长度名称```
1
aaaaaaaaaaaaaaaaaaaa
```包含二十个元音出现。 计数器达到二十，辅音计数为零，程序打印`1`。 

最后，输入可能包含几个具有完全不同特征的名称。 每次迭代都会创造一个新的`vowels`计数器，因此一个名称的信息不会泄漏到下一个名称。 这就是为什么输入如```
3
a
bc
ae
```产生```
a
1
bc
0
ae
1
```按名称重置是正确性不变量的一部分：计数器始终仅描述当前名称。
