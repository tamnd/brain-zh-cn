 ## 解决方案
 ## 问题理解

 我们给出了建议的微波炉烹饪时间`MM:SS`形式和百分比`p`。 Chris is allowed to choose any integer number of seconds whose distance from the recommended time is at most`p`建议时间的百分比。 在所有这些候选时间中，他希望数字序列最快的一个进入。 

微波炉不需要最后两位数字来形成有效的秒数。 如果我们按`190`，微波将其解释为`1:90`，其总持续时间与 2 分 30 秒相同。 因此，候选者最好用其总秒数的十进制数字来表示。 例如，88 表示`0:88`，即 1 分 28 秒。 

输入数字需要一点时间。 从一个数字移动到另一个数字需要花费一些时间，而再次按下同一数字则不需要移动。 因此，对于一个数字字符串`d1 d2 ... dk`，其成本为`k + number of positions i where di != d(i+1)`。 

输入包含`n`食品。 对于每个项目，建议的时间为分钟`00`通过`20`，其秒数是其中之一`00`,`15`,`30`， 或者`45`。 建议时间至少为 15 秒，同时`p`介于 2 和 10 之间。这些限制使得搜索空间变得非常小。 即使是最大的推荐（20 分钟），也只有 240 整数秒的 10% 范围，因此直接检查每个候选者很容易足够快。 原始竞赛声明给出了这些精确的界限，并指定使用实际满足百分比条件的整数秒来解释百分比间隔。 

有几个细节可能会导致原本简单的实现出现错误。 

例如，考虑：```
1
01:30
4
```建议的时间为 90 秒，因此允许的范围为 87 到 93 秒。 答案是`88`， 不是`01:28`。 顺序`88`只需两分钟，而微波炉本身会将这些数字转换为 1 分 28 秒。 

百分比端点也必须按正确的方向舍入。 为了：```
1
00:15
10
```数学间隔是 13.5 到 16.5 秒。 由于只允许整数秒，因此有效候选数为 14、15 和 16，因此答案为`15`。 包含 13 或 17 会错误地扩大候选集。 

第三种边缘情况是所选时间不必低于 60 秒。对于：```
1
00:30
10
```有效范围是 27 到 33 秒，并且`33`是最优的，因为按两次相同的数字只需要两分钟。 微波炉解读`33`通常为 33 秒，但同样的原理也允许诸如`88`。 

最后，最快的进入不一定是最接近推荐的候选人。 为了：```
1
06:00
8
```有效间隔为 331 到 388 秒。 顺序`555`只需要三分钟，因此它击败了诸如`600`，尽管 600 秒正是建议的时间。 实际持续时间`555`是5分55秒。 

## 方法

 直接的方法是枚举允许间隔内的每个整数秒数。 对于每个候选者，将整数转换为其十进制表示形式并计算其进入成本。 保留成本最小的候选者，当两个候选者成本相等时，保留与推荐秒数绝对距离较小的候选者。 

这种蛮力方法已经足够了，因为约束使间隔很小。 建议的最长持续时间为 20 分钟或 1200 秒。 和`p = 10`，该区间最多可以包含 241 个整数值，从 1080 到 1320。计算每个候选的成本最多检查四位数字，因此一个测试用例只需要大约 1000 个基本操作。 即使输入包含大量测试用例，这个值也很小。 

成本计算背后还有一个有用的结构观察。 总成本仅取决于我们键入时数字更改的次数。 每个数字总是需要按一次按键，并且每次转换到不同的数字都需要一次移动。 因此，我们不需要模拟手指位置或对键盘几何形状进行建模。 成本可以直接从十进制字符串计算出来。 

暴力搜索之所以有效，是因为候选区间很小。 在这些限制下，更复杂的优化只会使实施变得更加困难，而不会提供实际的好处。 关键的减少只是将建议的时间转换为秒，计算精确的整数间隔，并检查该间隔内的每个候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(R log R) | O(R log R) | O(log R) | 已接受 |
 | 最佳| O(R log R) | O(R log R) | O(log R) | 已接受 |

 这里`R`是允许间隔内的整数秒数，在这个问题中`R <= 241`。 由于每个候选者最多有四位小数，因此这实际上是每个测试用例的恒定时间。 

## 算法演练

 1. 转换推荐`MM:SS`值转换为单个整数`target = 60 * MM + SS`。 完全在几秒钟内完成工作，避免了必须分别处理分钟和秒的边界。 
2. 使用整数运算计算最小有效候选值。 下端点是`ceil(target * (100 - p) / 100)`。 

对于正整数，可以计算为`(x + 99) // 100`， 在哪里`x = target * (100 - p)`。 
3. 计算最大有效候选者为`floor(target * (100 + p) / 100)`。 

整数除法直接给出了这一点。 
4. 迭代每个整数`t`从下端点到上端点。 该循环中的每个值都是合法建议的烹饪时间，并且不会跳过任何合法时间。 
5. 转换`t`到`str(t)`并计算其进入成本。 从数字开始，因为每个数字都需要按一次。 然后为每对相邻的不同数字添加一个，因为在不同按钮之间移动会花费额外的时间。 
6. 将当前候选者与迄今为止找到的最佳候选者进行比较。 如果候选人的进入成本较小，那么候选人就更好。 如果成本相同，比较`abs(t - target)`并且更喜欢接近推荐的候选人。 
7. 输出所选候选者的小数位数。 我们输出数字本身，而不插入冒号或前导零，因为这些不是克里斯需要按下的按钮。 

不变的是，在处理每个候选者之后`t`，存储的答案是迄今为止根据问题的精确两级排序处理的所有候选中的最佳候选：首先是最小进入成本，然后是与推荐的最小距离。 由于循环最终处理每个有效的候选整数，因此最终存储的答案是唯一的所需答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def entry_cost(t):
    s = str(t)
    cost = len(s)

    for i in range(1, len(s)):
        if s[i] != s[i - 1]:
            cost += 1

    return cost

def solve():
    n = int(input())
    out = []

    for case in range(1, n + 1):
        time_str = input().strip()
        p = int(input())

        minutes = int(time_str[:2])
        seconds = int(time_str[3:])
        target = minutes * 60 + seconds

        low_num = target * (100 - p)
        high_num = target * (100 + p)

        low = (low_num + 99) // 100
        high = high_num // 100

        best_time = None
        best_cost = 10**9
        best_dist = 10**9

        for t in range(low, high + 1):
            cost = entry_cost(t)
            dist = abs(t - target)

            if cost < best_cost or (cost == best_cost and dist < best_dist):
                best_time = t
                best_cost = cost
                best_dist = dist

        out.append(f"Case #{case}: {best_time}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一部分`solve`转换五字符`MM:SS`表示为秒。 由于输入格式是固定的，`time_str[:2]`给出分钟数和`time_str[3:]`给出秒数。 

的表达式为`low`和`high`故意避免浮点运算。 例如，如果数学下限为 13.5，`(13 * 100 + 99) // 100`式整数上限算术给出 14。浮点算术是不必要的，并且可能引入边界错误。`entry_cost`开始于`len(s)`因为每个数字都必须按下。 然后它检查相邻的数字。 一个过渡，例如`5 -> 5`不需要移动，同时`5 -> 6`需要一次移动，因此每个不相等的相邻对恰好贡献一次。 

比较条件直接编码所需的优先级。 首先考虑进入成本。 仅当进入成本相同时，与建议时间的距离才重要。 使用`<`对于距离比较就足够了，因为该语句保证了最终答案是唯一的。 

没有必要对候选者进行标准化，例如`88`进入`01:28`。 候选者是按下按钮的顺序，因此正确的输出是`88`。 Python 整数自然也避免了任何溢出问题，尽管这里的实际值只有几千左右。

 ## 边缘情况

 对于最低建议，请考虑：```
1
00:15
2
```目标是15秒。 下界是`ceil(14.7) = 15`，而上限是`floor(15.3) = 15`。 因此该循环仅检查`15`，答案是`15`。 这可以防止实现由于浮点截断或不正确的取整运算而意外接受 14 秒。 

对于重复数字的候选者，请考虑：```
1
00:30
10
```有效范围为 27 到 33。`33`有两次按下且没有移动，成本为 2。其他每个候选者都有两个不同的数字，成本为 3。算法选择`33`到达该值后立即执行，无论 30 秒更接近建议值。 

对于显示秒数超过 59 的候选者，请考虑：```
1
01:30
4
```范围是 87 到 93。`88`由按下的两个数字表示`8`和`8`，所以它的成本是 2。微波炉将这些数字解释为 88 秒，相当于 1 分 28 秒。 算法保持`88`作为答案并且不尝试将其转换为`01:28`。 

对于尽可能最大的建议，请考虑：```
1
20:00
10
```目标为 1200 秒，范围为 1080 到 1320。`1111`位于这个区间内，并且只需要 4 个时刻，因为所有四个数字都是相同的。 没有三位数候选值是有效的，因为低于 1000 的每个值都在区间之外，而四位数数字的成本不能低于 4。因此`1111`是最优的，并且实现通过普通枚举找到它。
