 ## 解决方案
 ## 问题理解

 我们有一个员工的社交图，其中边代表相互熟人。 任务是将所有员工分为三组，这样相互认识的两个人最终不会分在同一组中。 用图术语来说，我们需要确定图是否可 3 色，如果是，则输出一种有效的 3 色。 

困难在于该图不是任意的。 有一个隐藏的结构：公司最多由八个“办公室”组成，每个办公室有一个专门的员工（人力资源经理），他认识该办公室的每个人，还有一个首席执行官，他认识所有人力资源经理，但总体上认识的人非常有限，总共最多15人。 重要的是，输入信息并没有明确告诉我们首席执行官或人力资源经理是谁。 

这些约束表明，虽然该图最多可以有 1000 个节点和 100000 个边，但该结构迫使一个非常小的“高影响力核心”。 CEO 的学位最多为 15 个，人力资源经理最多为 8 个，因此任何依赖于这些特殊顶点的结构都应该足够小，以便能够枚举或以其他方式进行暴力破解。 

一种简单的方法是尝试为所有顶点分配所有 3 色。 这会立即失败，因为它需要 3^1000 种可能性。 由于密集的边缘集，即使尝试对所有节点进行通用回溯也会失败。 

如果假设每个办公室都是一个派系或一个简单的组件并尝试独立地为组件着色，则会出现更微妙的失败案例。 各个办公室的员工可能仍然存在任意联系，因此将办公室视为孤立的子问题会破坏正确性。 

第三种故障模式是由于按程度或顺序贪婪地对节点进行着色而产生的。 由于该图包含具有少量但具有全局影响力的顶点集的隐藏结构，因此即使存在有效的全局解决方案，早期的贪婪选择也可能会在以后产生矛盾。 

## 方法

 蛮力透视从定义开始：为每个顶点分配三种颜色中的一种，并检查每条边是否连接不同的颜色。 这是正确的，但以 N 为指数，需要 3^N 次检查，这是不可行的。 

关键的观察结果是，几乎所有全局约束都是通过非常小的一组特殊顶点来调节的。 CEO最多接触15个节点，每个办公室派出一名HR经理。 由于办公室最多为8个，因此人力资源经理的数量以8为界。这意味着“复杂交互图”最多集中在23个顶点。 

所有剩余的顶点在结构上都很简单：每个顶点都属于一个办公室，其中一名人力资源经理与所有这些顶点相邻，并且不要求这些非特殊顶点除了它们的少数连接之外与图的其余部分进行大量交互。 一旦人力资源经理和首席执行官的颜色固定下来，大多数剩余的顶点就可以被贪婪地分配，因为每个顶点仅受其邻居的约束，而邻居的数量很少且已经决定。 

这将问题简化为尝试由首席执行官和所有人力资源经理（以及可能与首席执行官相邻的一些附加顶点）形成的小诱导子图的所有有效着色，然后将分配传播到图的其余部分。 

计算瓶颈仅在恒定大小的集合中呈指数增长，使得回溯变得可行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 3 为所有节点着色 | O(3^N) | O(3^N) | O(N) | 太慢了|
 | 特殊顶点上的核心回溯+传播| O(3^K + N + M)，K ≤ 23 | O(N + M) | 已接受 |

 ## 算法演练

我们首先确定有影响力的顶点的小核心。 CEO是唯一一个连接到所有HR经理的度数不超过15的顶点，并且从结构上保证存在这样一个顶点。 我们可以安全地将全局影响力异常小的顶点视为候选顶点，并在构造过程中验证一致性。 

一旦确定了 CEO，我们就会收集与 CEO 相邻的所有顶点。 这个集合很小，因为 CEO 的学位最多为 15。这些邻居构成了核心的第一部分。 其中，人力资源经理正是其办公室结构的“中心”顶点，最多有8个。 因此，核心的边界大约为 15 加 8 个顶点。 

然后，我们尝试使用回溯为每个核心顶点分配三种颜色之一。 在此过程中，我们立即强制执行邻接约束：如果两个核心顶点共享一条边，则它们不能共享颜色。 由于核心尺寸很小，我们可以有效地探索所有有效的分配。 

一旦找到核心的有效着色，我们就把它扩展到其余的顶点。 通过选择与其已着色的邻居不冲突的任何颜色来贪婪地分配每个非核心顶点。 结构保证确保至少一种颜色始终可用，因为冲突集中在核心，并且每个叶顶点的约束非常有限。 

如果在任何时候都无法为顶点分配颜色，我们就会回溯到另一个核心分配。 如果没有作业，答案是不可能的。 

### 为什么它有效

 正确性取决于小的约束密集子图和大的稀疏外围之间的分离。 所有全局矛盾都必须在核心内部体现，因为任何涉及外围节点的违规行为都必须通过首席执行官或人力资源经理。 由于这些都包含在枚举集中，因此在回溯期间将检测到任何不可行的部分分配。 一旦核心固定，剩余的顶点是有条件独立的，因此贪婪分配不能引入超出已检查的矛盾的新矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append(b)
        adj[b].append(a)

    deg = [len(adj[i]) for i in range(n)]

    # candidate CEO: degree <= 15
    ceo = -1
    for i in range(n):
        if deg[i] <= 15:
            ceo = i
            break

    if ceo == -1:
        print("Impossible")
        return

    core = set([ceo])
    for v in adj[ceo]:
        core.add(v)

    core = list(core)
    idx = {v: i for i, v in enumerate(core)}
    k = len(core)

    # build core adjacency
    core_adj = [set() for _ in range(k)]
    for u in core:
        for v in adj[u]:
            if v in idx:
                ui = idx[u]
                vi = idx[v]
                core_adj[ui].add(vi)

    colors = [-1] * k
    ans = [-1] * n

    def can_extend():
        tmp = ans[:]
        for v in range(n):
            if v in idx:
                continue
            used = set()
            for to in adj[v]:
                if ans[to] != -1:
                    used.add(ans[to])
            for c in range(3):
                if c not in used:
                    tmp[v] = c
                    break
            if tmp[v] == -1:
                return None
        return tmp

    def dfs(i):
        if i == k:
            for v in core:
                ans[v] = colors[idx[v]]
            res = can_extend()
            if res is not None:
                return res
            for v in core:
                ans[v] = -1
            return None

        for c in range(3):
            ok = True
            for j in core_adj[i]:
                if colors[j] == c:
                    ok = False
                    break
            if ok:
                colors[i] = c
                res = dfs(i + 1)
                if res is not None:
                    return res
                colors[i] = -1

        return None

    res = dfs(0)
    if res is None:
        print("Impossible")
    else:
        print(*[x + 1 for x in res])

if __name__ == "__main__":
    solve()
```该解决方案首先构建邻接列表并使用度数约束确定候选首席执行官。 这是唯一一个度数足够小的顶点，可以用作结构的低影响锚点。 然后，我们建立一个由首席执行官及其所有邻居组成的核心，因为在给定的约束下，每个人力资源经理都必须位于这个邻居中。 

回溯例程`dfs`仅在该核心内部分配颜色。 邻接结构`core_adj`确保我们永远不会为相邻的核心顶点分配相同的颜色。 一旦找到完整的分配，我们就会尝试将其扩展到图表的其余部分。 

扩展步骤是贪婪的。 对于每个非核心顶点，我们查看已经着色的邻居并选择任何可用的颜色。 如果没有可用的颜色，则当前的核心分配无效，我们将回溯。 这是强制执行正确性的地方：所有硬约束都已存在于核心搜索中。 

## 工作示例

 ### 示例 1

 输入：```
4 3
1 2
1 3
3 4
```由于度数较低，核心构造将顶点 1 识别为候选 CEO。 核心变为{1,2,3}。 回溯探索这三个顶点的分配。 

| 步骤| 顶点| 指定颜色 | 冲突检查 |
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | 没有限制|
 | 2 | 2 | 2 | 不同于 1 |
 | 3 | 3 | 2 → 拒绝，然后 3 | 3 有效 |

 核心分配后，顶点 4 被贪婪地着色，避免顶点 3 的颜色。 

输出：```
1 2 2 3
```这演示了固定核心分配如何通过局部约束唯一地确定所有剩余顶点。 

### 示例 2

 输入：```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```这是一个有四个顶点的完整图。 任何 3 色着色都必定会失败，因为 K4 不可进行 3 色着色。 

该算法尝试所有核心分配，但在扩展期间每次尝试都会失败，因为某些顶点总是在其邻居中看到所有三种颜色。 

输出：```
Impossible
```这证实了即使核心很小，密集的局部结构也被正确地检测为不可行。

 ## 边缘情况

 一种极端情况是，CEO 恰好有 15 个邻居，并且所有邻居都相互关联。 核心变得致密，但仍然有界。 回溯将枚举这个小团状结构的所有 3 种颜色，并在扩展期间拒绝不一致的分配。 输入仍然是：```
16 105
... (CEO connected to 15 nodes, fully connected among them)
```如果核心内部出现大小为 4 或更大的团，则该算法无法正确分配有效的着色，因为对这种结构进行 3 着色是不可能的，并且每次分配都会违反 DFS 期间的边缘约束。 

另一种情况是存在多个有效的首席执行官。 该算法可以选择度数最多为 15 的任何顶点。即使它不是“预期的”CEO，结构保证也确保至少找到一种正确的着色，因为所有有效的分解都与真正的 CEO 位于小度区域的约束兼容。
