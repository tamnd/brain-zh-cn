 ## 解决方案
 ## 问题理解

 我们正在处理一个由三个旋转部件组成的系统。 每个组件在圆形刻度上都有一个位置，每次完整旋转都会在固定的步数后将其返回到起点。 不同的是，我们不直接选择每个组件旋转的程度。 相反，我们执行的操作中，每个操作将三个组件中的两个精确旋转一步，而第三个组件保持不变。 

每个组件都有一个初始偏移量，并且每个组件都有自己的模数，这意味着它的最终位置是以其自己的周期长度为模来评估的。 执行一定数量的操作后，我们希望所有三个组件都与固定的参考方向对齐。 

如果我们从簿记的角度来看这个过程，每项操作都会贡献两个部分，而其中一个部分则保持不变。 经过多次操作，这会生成三个非负整数，每个组件一个，描述该组件未被选择的次数。 这些派生计数必须同时满足三个模数约束。 目标是最小化操作总数，这相当于最小化这些派生计数的线性组合。 

对输入大小的限制非常严格，以至于对三个变量的自然状态空间进行任何三次探索都是不可行的。 除非每个状态转换都是恒定时间，否则即使对所有变量对进行二次探索也会变得边缘化。 这表明该解决方案必须利用模块化系统中的结构，而不是直接模拟操作。 

如果人们假设这三个同余式可以独立求解，就会出现一种微妙的失败情况。 例如，为两个变量选择有效值，然后强制第三个变量独立地中断，因为第三个变量同时参与所有三个方程。 另一个常见的陷阱是将系统视为纯粹的模块化系统而不强制执行非负性，这会导致与负操作计数相对应的有效模块化解决方案。 

## 方法

 蛮力观点从操作定义开始。 每个步骤都会在三个组件中选择一对，因此在 S 个步骤之后，我们有三个计数器来描述每对被选择的次数。 由此，我们得出每个组件未被选择的次数，这些直接出现在模块化约束中。 一个简单的解决方案将枚举三对之间所有可能的操作分布，直到某个合理的界限，并检查结果配置是否满足所有约束。 

这很快就变得不可行，因为自然搜索空间像模数范围的立方一样增长。 即使我们将每个变量限制为最多 2000 个，三元组的数量也有数十亿的数量级，并且每次检查都涉及模运算。 

关键的结构观察是，一旦根据每对层被选择的次数重写，系统在三个变量中是线性的。 如果我们将选择对 (0,1)、(0,2) 和 (1,2) 的计数表示为 a、b 和 c，则每个约束都成为 a、b 和 c 中的线性同余。 这将问题转化为在模约束下寻找小型线性系统的非负整数解，目标是最小化 a + b + c。 

重要的减少是，一旦我们固定了两个变量，第三个变量就被确定为三个同时同余的模块化系统。 我们不探索所有三元组，而是仅探索对，并使用构造性中国余数计算来计算第三个变量的可行性和最小完成度。

 ## 算法演练

 我们根据与选择每对层相对应的操作计数 a、b、c 来重写问题。 这消除了通过 t 值的间接表示并给出了直接线性系统。 

1.表达各层操作的效果。 每个对操作都为两层贡献 +1，因此每个约束变成 a、b 和 c 中的线性表达式，系数为 2、1 和 1，具体取决于参与情况。 此步骤至关重要，因为它消除了“选择”层和“未选择”层之间的不对称性，并给出了对称线性系统。 
2. 将每个模条件转换为 a、b、c 中线性表达式的同余式。 每个方程都成为以相应循环长度为模的线性剩余条件。 这会产生三个独立的模块化约束，但都针对相同的变量。 
3. 固定a和b的值。 一旦选择了 a 和 b，每个方程就成为对 c 的直接约束。 每个约束的形式为 c == value modulo yi。 这将问题从三个自由度减少到一个，但具有三个同时同余。 
4. 使用逐步中国余数结构求解 c。 如果可能的话，我们将前两个同余组合成一个残基类，然后与第三个同余合并。 在每次合并时，我们要么检测不一致，要么以所涉及模数的最小公倍数为模获得唯一的残基类。 
5. 找到 c 的有效残基类别后，选择最小的非负代表。 这给出了固定 (a, b) 对的最小可行 c，这是必要的，因为目标在 c 中是单调的。 
6. 计算总成本 a + b + c 并跟踪所有对 (a, b) 的最小值。 搜索范围可以安全地受最大模数限制，因为 a 或 b 的任何较大变化只会增加目标，而不会以有意义的方式提高可行性。 

### 为什么它有效

 该变换保留了所有可行的解决方案，因为每个原始步骤都线性且独立地贡献于三个导出变量 a、b 和 c。 每个有效的操作序列恰好对应一个三元组（a、b、c），反之亦然。 这些约束是纯线性同余的，因此可行性仅取决于残差类别，而不取决于超出非负性要求的绝对量值。 通过固定两个变量并通过 CRT 重建第三个变量，我们将所有残差一致的结构精确地枚举一次，确保不会遗漏任何可行的解决方案，也不会计算无效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ext_gcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x, y = ext_gcd(b, a % b)
    return g, y, x - (a // b) * y

def mod_inv(a, mod):
    g, x, _ = ext_gcd(a, mod)
    if g != 1:
        return None
    return x % mod

def crt_pair(r1, m1, r2, m2):
    g, p, q = ext_gcd(m1, m2)
    diff = r2 - r1
    if diff % g != 0:
        return None, None
    lcm = m1 // g * m2
    step = m2 // g
    x = (diff // g) * p % (m2 // g)
    res = (r1 + m1 * x) % lcm
    return res, lcm

def solve_case(x, y):
    r = [(-x[i]) % y[i] for i in range(3)]
    ans = 10**30

    maxv = max(y)

    for a in range(maxv + 1):
        for b in range(maxv + 1):
            ok = True

            c1_r, c1_m = (r[0] - 2 * a - b) % y[0], y[0]
            c2_r, c2_m = (r[1] - a - 2 * b) % y[1], y[1]
            c3_r, c3_m = (r[2] - a - b) % y[2], y[2]

            c, m = c1_r, c1_m

            c, m2 = crt_pair(c, m, c2_r, c2_m)
            if c is None:
                continue
            c, m3 = crt_pair(c, m2, c3_r, c3_m)
            if c is None:
                continue

            if c < 0:
                c += ((-c) // m3 + 1) * m3

            ans = min(ans, a + b + c)

    return -1 if ans == 10**30 else ans

def main():
    t = int(input())
    for _ in range(t):
        x0, x1, x2, y0, y1, y2 = map(int, input().split())
        print(solve_case([x0, x1, x2], [y0, y1, y2]))

if __name__ == "__main__":
    main()
```该实现首先将每个目标比对转换为残差要求。 嵌套循环枚举 a 和 b 的可能值，它们表示每对层被选择的次数。 对于每一对，我们导出对 c 的隐含约束，并使用基于标准扩展欧几里德的 CRT 例程将它们合并。 如果系统在任何时候不一致，则 (a, b) 对将被丢弃。 

CRT例程是最微妙的部分。 它确保当两个模块约束重叠时，我们可以正确计算可行性和组合模量。 最后的标准化步骤确保 c 被视为最小的非负代表，因为较大的值只会使目标恶化。 

## 工作示例

 考虑一个小型配置，其中所有模数都相等并且初始偏移很小。 这有助于说明约束如何在三个方程中对称地相互作用。 

让我们考虑 y = [3, 3, 3] 且 x = [1, 2, 0] 的情况。 我们计算留数 r = [2, 1, 0]。 对于固定的 (a, b)，每个方程都会对 c 产生线性限制。 CRT 要么比对所有三个残基类别，要么立即拒绝该对。 例如，a = 0, b = 0 得到 c == 2 mod 3, c == 1 mod 3，这是不一致的，因此被丢弃。 尝试 a = 1、b = 0 会移动残基，并可能根据线性偏移如何相互作用来对齐所有三个约束。 

现在考虑第二种情况，其中一个模数远小于其他模数，例如 y = [2, 5, 7]。 这强调了 CRT 合并逻辑。 对于每个 (a, b)，前两个同余通常合并为模 10 的留数，然后与模 7 协调。这演示了中间模如何增长以及为什么需要扩展 gcd 来处理非互质情况。

 ## 边缘情况

 当模块化约束单独可满足但联合不一致时，就会出现关键的边缘情况。 例如，c 的每个同余式可能有独立的解，但它们的组合交集为空。 在这种情况下，CRT 合并会提前失败，并且算法会正确跳过该 (a, b) 对。 这可以防止将部分可行性错误地计算为有效配置。 

另一个微妙的情况是当 CRT 计算出的 c 为负时。 该实现明确地将其标准化为最小非负代表，因为目标函数取决于绝对量值，而不仅仅是残差类别。 

当所有模数相等且初始偏移对称时，出现最终边缘情况。 这里，许多 (a, b) 对对 c 产生相同的约束。 如果不小心最小化，人们可能会多算或错过真正的最小值。 (a, b) 上的完整枚举确保仍然可以达到最佳对称配置。
