 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中每个节点代表一个文件夹。 文件夹 1 固定为根文件夹，其他每个文件夹只有一个父文件夹。 所以结构是目录的层次结构。 

允许的操作是“剪切”：您获取一个文件夹并将其移动到另一个文件夹下，但限制是您不能将文件夹移动到其自身或其任何后代中。 执行一定数量的此类移动后，我们希望最终的树满足结构约束：每个文件夹最多可以有一个直接子文件夹。 

因此，目标配置是一棵有根树，其中每个节点的出度最多为 1。 任务是尽量减少达到这种配置所需的移动操作次数。 

约束 n ≤ 100000 立即排除任何重复模拟重新连接节点或探索所有可能的重新父子关系选择的解决方案。 任何以嵌套方式考虑节点对的方法都会失败。 该结构是静态输入，因此我们必须从初始树中提取一些全局组合属性。 

一个关键的边缘情况是当树已经是一个简单的链时。 在这种情况下，每个节点最多已有一个子节点，因此不需要移动。 任何正确的解决方案都必须在此处返回 0，而不尝试进一步“改进”结构。 

另一个边缘情况是一棵以 1 为根的星形树，其中节点 1 有 n−1 个子节点。 在这里，每片叶子都很好，但根严重违反了约束。 正确的答案应该反映出我们需要重新分配子节点，以便没有一个节点最终拥有多个子节点，这会强制进行多次切割。 

一个天真的错误是假设我们可以简单地计算具有多个子节点的节点，然后每个节点减去一个。 这是失败的，因为移动一个孩子会动态地改变学位结构并影响未来的决策。 

## 方法

 直接模拟视图将尝试重复选取具有太多子节点的节点，并将其一些子树移动到其他地方，直到所有节点的度数最多为 1。 每次移动都会改变树结构，因此我们需要维护动态的父子关系并重新计算度数。 在最坏的情况下，每次移动仅修复一个子边，并且有 n 个节点具有潜在的大分支，从而导致 O(n^2) 行为。 

这种方法在概念上是有效的，因为它直接强制执行约束，但它在计算上失败，因为每个操作都可能触发树上的级联更新。 

关键的观察是我们并没有真正尝试仔细选择目的地。 我们只关心要淘汰多少“多余的孩子”。 每个节点最多可以拥有一个子节点； 来自该节点的所有其他传出边缘必须被“剪切”并移动到其他地方。 目标约束不会更改所需剪切的计数，因为任何有效目标仍然保留源减少其子计数的要求。 

因此，问题归结为计算每个节点有多少个子节点超过一个。 每个具有 d 度的节点贡献 max(0, d−1) 所需的切割。 直觉是，我们总是可以在不增加操作数量的情况下将剪切子节点重新路由到有效的地方，因为在其子树之外总是至少有一个有效目标（根结构确保树上的连接性和足够的空闲位置）。 

因此，整个问题就分解为一个简单的度数计算任务。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 模拟切割| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 度计数 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从父数组构建树并计算每个节点的子节点数量。

1. 读取从 2 到 n 的每个节点的父节点并构造一个子列表或简单地为每个节点维护一个度数计数器。 这捕获每个文件夹最初有多少个直接子文件夹。 
2. 对于每个节点，计算它有多少个子节点。 如果一个节点有 d 个子节点，则只要 d > 1，它就会违反约束。 
3. 对于每个节点，将 max(0, d − 1) 添加到答案中。 这表示必须从该节点中删除才能将其度数减少到最多 1 的子节点数。 
4. 输出所有节点的总和。 

我们减一的原因是每个节点只允许保留一个子节点而不违反最终条件，因此只有多余的子节点需要削减。 

### 为什么它有效

 每个节点独立地贡献无法保留在最终结构中的剩余传出边。 任何有效的最终配置都必须将每个节点的出度减少到最多 1，因此具有 d 个子节点的每个节点必须失去至少 d−1 条边。 这些损失与削减操作完全对应。 

从一次修复多个违规的意义上来说，没有任何切割是“浪费”的，因为每次切割仅从超出容量的节点中删除一个子边缘。 因此，所有局部过量的总和既是下限又是可实现的，因为我们始终可以以保持有效性而不增加所需操作的方式重新附加已删除的节点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    if n == 1:
        print(0)
        return

    children = [0] * (n + 1)

    arr = list(map(int, input().split()))
    for p in arr:
        children[p] += 1

    ans = 0
    for i in range(1, n + 1):
        if children[i] > 1:
            ans += children[i] - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现完全由计算子频率来驱动。 数组`children`将出度存储在有根树中。 父数组上的循环以线性时间构建它。 

唯一的微妙之处在于处理 n = 1 的情况，其中没有父母可供阅读，答案必须为零。 其他一切都直接从学位论证中得出。 

一个常见的实现错误是尝试按 DFS 顺序处理节点或模拟实际的重新连接。 这是不必要的，因为最终条件仅取决于程度，而不取决于移动后的结构。

 ## 边缘情况

 单节点树测试实现是否安全地避免读取父数据并正确返回零。 

完全星形的树测试解决方案是否正确地计算根部多余的子项，而不尝试重新分配逻辑。 

长链测试只有一个子节点的节点不会受到惩罚，因为约束已经在各处得到满足。 

其中每一个都由相同的度数计数逻辑直接处理。 该算法不依赖于直接子计数之外的结构，因此所有配置一致地减少到相同的本地计算。
