 ## 解决方案
 ## 问题理解

 我们正在模拟一系列战斗，其中每场战斗都包括与一小群相同的怪物战斗。 每个怪物都有固定的生命值，每次攻击都会使所选怪物的生命值减少一分。 每次攻击后，所有还活着的怪物都会立即攻击玩家一次，因此该时刻的伤害等于尚未完全杀死的怪物数量。 

只有当该组中的所有怪物都死亡时，战斗才会结束。 当下一场战斗开始时，攻击过程会重置，即玩家再次首先攻击，但护盾生命值会持续延续。 

还有一个额外的变化：一些攻击位置被助手标记为特殊。 如果怪物在特殊攻击中被杀死，玩家会立即获得一次额外的攻击，有效地缩短了战斗的时间。 

目标是选择如何在怪物之间分配攻击，以使护盾受到的总伤害最小化，并确定最终剩余的护盾值或报告它在某个时刻下降到零或更低。 

约束已经揭示了解决方案的结构。 战斗多达十万场，但每场战斗最多有一百只怪物，每只怪物最多需要二十次命中。 这有力地表明，单场战斗的内部结构可以通过分析计算，而不是在所有战斗中的单独攻击层面上天真地模拟。 特殊位置的数量很少，最多 2000 个索引，总共最多 20 个，这表明只有极少数“事件”真正对优化重要。 

简单的模拟将明确处理所有战斗中的每次攻击，更新每个怪物的生命值并重新计算存活数。 在最坏的情况下，这相当于攻击总数的数量级，可以达到 100,000 乘以 100 乘以 20，这个数字太大了。 

如果我们在不了解结构的情况下试图在战斗中贪婪地切换目标，就会出现一个更微妙的问题。 例如，当怪物死亡时，以循环方式攻击不同的怪物会发生变化，但与在此模型中一次只专注于一个怪物相比，它实际上并不会减少总伤害，因为伤害仅取决于有多少怪物还活着，而不取决于哪个特定怪物被击中。 

## 方法

 蛮力视角就是从字面上模拟整个过程。 对于每次攻击，我们选择一个怪物，降低其生命值，检查它是否死亡，然后计算有多少怪物还活着并累积伤害。 从概念上讲，这是可行的，但每次攻击都需要更新状态，总共可以有多达两千万次攻击，在一秒的限制下太慢了。 

关键的结构观察是战斗中的所有怪物都是相同的，并且每个活着的怪物每次攻击都会造成相同的伤害。 唯一重要的是随着时间的推移有多少怪物还活着，而不是我们击中了哪个特定的怪物。 这将单场战斗中的问题分解为确定性的序列：只要我们尽可能地尽量减少伤害，我们总是会在转移到下一个怪物之前完全解决一个怪物，因为这样做可以尽快减少攻击者的数量。 

一旦这个结构被修复，每个怪物都会在其生命周期内造成可预测的伤害。 唯一剩下的自由是攻击指数如何与特殊助手位置保持一致，因为它们可以创建额外的攻击，有效地跳过时间步骤并消除一个伤害事件。

所以问题就变成了：计算连续杀死怪物的固定基线伤害，然后根据可以触发额外攻击的位置添加修正。 每个有效的触发对应于精确地以特殊攻击指数杀死怪物，并且每个此类事件都会节省已知数量的未来伤害。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全面模拟所有攻击 | O(总攻击次数) | O(1) | O(1) | 太慢了 |
 | 每场战斗封闭形式+事件优化 | O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每场战斗，同时跟踪当前的护盾值。 

首先，我们计算假设没有激活助手的战斗的总伤害。 由于怪物是相同的，并且最佳玩法会一一杀死它们，因此第 k 个怪物在 B 次完整攻击中保持存活，而在杀死阶段开始时仍然有 (aᵢ − k + 1) 个怪物活着。 这使得每个怪物的伤害贡献完全确定。 

其次，我们观察到战斗中的攻击时间线是固定的：每个怪物恰好需要 B 次连续攻击才能杀死，因此第 k 次杀死发生在该战斗中的攻击次数 k × B 处。 这消除了调度中的所有组合自由。 

第三，我们扫描这些击杀时刻，检查相应的全局攻击索引是否被标记为辅助位置。 如果位置被标记，那么在那一刻杀死怪物会立即产生额外攻击。 

第四，每次这样的额外攻击都会从战斗中删除一个未来的时间步。 在激活时，在第 k 次杀死后仍有 (aᵢ − k) 个怪物仍然活着，因此跳过下一个时间步骤可以避免那么多的传入伤害点。 我们将此记录为一项福利。 

第五，我们收集所有战斗中的所有收益。 由于辅助激活的总数最多为 20 个，因此我们只是将它们全部相加，因为它们之间不存在有意义的冲突。 

最后，我们从基线伤害中减去保存的总伤害，并检查结果是否使护盾保持严格为正值。 

关键的不变量是，在每次战斗中，杀死 k 次后存活的怪物数量完全决定了下一步的伤害以及当时触发的任何额外攻击的价值。 由于在最佳玩法下杀戮时间是固定的，因此每个决定都简化为选择哪些固定时刻激活辅助效果。 后来的选择不能改变早期的杀伤位置，因此计算出的基线和修正始终保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    # precompute helper positions
    help_pos = set(i + 1 for i, x in enumerate(b) if x == 1)
    
    total_damage = 0
    total_save = 0
    
    for monsters in a:
        # baseline damage for one battle:
        # sum_{k=1..a} B * (a - k + 1)
        total_damage += B * monsters * (monsters + 1) // 2
        
        # check kill moments
        for k in range(1, monsters + 1):
            t = k * B
            if t in help_pos:
                # after killing k-th monster, remaining is (monsters - k)
                total_save += (monsters - k)
    
    if A - (total_damage - total_save) <= 0:
        print("LOSE")
    else:
        print(A - (total_damage - total_save))

if __name__ == "__main__":
    solve()
```该解决方案首先将辅助攻击索引编码为一组以进行恒定时间查找。 然后，它利用每个怪物在其生命周期内贡献线性递减的伤害量的事实，计算每场战斗的封闭形式伤害，而无需模拟。 

对于由 k × B 标识的每个潜在杀戮时刻，它会检查该时刻是否特殊。 如果是这样，它会添加由于跳过下一个时间步骤而避免的确切损坏量。 

最终的护盾值在最后计算一次，并且简单的阈值检查确定玩家是否生存。

 ## 边缘情况

 一个微妙的情况是，辅助触发发生在击杀时刻，击杀后没有怪物留下。 在这种情况下，保存的值变为零，因为没有未来的损坏可以跳过。 该算法自然地处理这个问题，因为 (aᵢ − k) 变为零。 

另一种情况是当帮手位置超过战斗中的攻击次数时。 由于 t = k × B 可能永远不会达到这些索引，因此这些条目将被简单地忽略，并且不会触发无效的内存或逻辑。 

最后一种情况是所有助手在战斗早期触发集群。 这可以最大限度地节省资金，因为早期击杀对应的剩余怪物数量较多，并且该公式通过直接使用 (aᵢ − k) 正确地捕获了这一点，而无需任何近似。
