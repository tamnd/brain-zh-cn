 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中都有一个卡值数组和一个参数$k$。 从这些卡片中，我们可以选择一些子序列，但是一旦我们解释了选择试图优化的内容，实际的排序约束就变得无关紧要了。 核心限制是所选择的选择必须有效地尊重与$k$，这意味着有用的结构是有多少个完整的大小组$k$我们可以形成什么以及我们从中提取什么价值。 

任务是最大化从所选卡片中得出的总分，而关键的隐藏简化是原始数组中卡片的位置不会限制我们选择的卡片数量之外的最优性。 重要的只是我们包含的值以及以大小块有效处理选择的事实$k$。 

输入由多个测试用例组成，每个测试用例给出一个整数$n$, 一个整数$k$，以及一个数组$n$代表卡值的整数。 每个测试用例的输出是一个整数，表示选择规则下可达到的最大分数。 

从约束讨论中，重要的含义是$n$每个测试用例都可以很大，可能高达$10^5$，并且可以有多个测试用例。 依赖于两者的天真 DP$n$和$k$每个测试用例的复杂性大致为$O(t \cdot n \cdot k)$，退化为大约$10^9$最坏情况下的操作。 这已经超出了典型的限制，因此任何在位置和组计数上保持二维状态的解决方案都不会通过。 

当人们假设子序列选择保留顺序相关性时，就会出现一个微妙的陷阱。 例如，考虑值$[1, 100, 2, 99]$和$k = 2$。 粗心的方法可能会尝试模拟选择尊重指数的对，但由于只有总贡献很重要，因此最好的解决方案就是简单地选择最高值，而不必担心邻接或原始位置。 任何错误地保留原始顺序约束的算法都会导致选择不足或过于复杂。 

## 方法

 最直接的表述是考虑数组的动态规划以及到目前为止我们已经获取了多少项。 人们可以定义这样一种状态$dp[i][j]$，这意味着我们处于索引处$i$并已选择$j$元素，尝试在仅完成大小组的规则下最大化总和$k$贡献。 转换会考虑采用或跳过每个元素。 

这种方法是正确的，因为它明确地尊重所有约束，但它立即变得昂贵。 状态数为$O(n \cdot n)$在最坏的解释中，或者至少$O(n \cdot k)$，并且每个转换都是恒定的，导致每个测试用例出现二次或伪二次行为。 当输入量很大时，这很快就变得不可行。 

关键的结构观察是原始数组中的相邻性不会影响最终得分。 由于选择是一个子序列，因此我们可以自由地重新排序我们的思维：重要的是选择哪些值，而不是它们来自哪里。 这将问题转变为纯粹基于值的优化。 

一旦顺序无关紧要，自然的策略就是按降序对数组进行排序。 排序后，最优解必须首先取最大的可用值，因为任何较小的值永远无法改进可以用较大值形成的组。 由于贡献与以大块大小获取元素有关$k$，我们评估这个排序数组的前缀和，并且只考虑所选元素数量是以下倍数的位置$k$。 在这些有效的前缀中，最大的前缀和就是答案。 

这是有效的，因为每个有效的解决方案都对应于选择一定数量的元素，并且对于任何固定计数，选择​​最大的可用元素可以使总和最大化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对指数和选秀权的暴力 DP |$O(n^2)$或者$O(nk)$|$O(nk)$| 太慢了 |
 | 排序+前缀评估|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取测试用例的所有值并将它们存储在数组中。 这使我们能够完全自由地忽略原始位置，因为重新解释后没有任何约束依赖于邻接性。 
2. 对数组进行降序排序。 这确保了每当我们考虑采用元素时，我们总是首先优先考虑最有价值的元素。 
3. 计算已排序数组的前缀和。 位置处的前缀和$i$如果我们恰好取顶部，则表示最好的总数$i$元素。 
4. 只考虑指数$i$这样$i$是的倍数$k$。 这些位置对应于形成完整的大小组$k$，这是评分结构唯一有意义的检查点。 
5. 跟踪这些有效位置中的最大前缀和并将其作为答案输出。 

### 为什么它有效

 任何有效的解决方案都对应于选择大小的某个子集$m$，其值是这些所选元素的总和。 对于固定的$m$，最优子集始终是$m$最大的元素，因为用较大的未选择元素替换较小的选定元素会严格增加总和。 由于分组约束仅取决于$m \bmod k = 0$，我们只评估$k$。 排序后的前缀保​​证我们始终评估每个大小的最佳子集，因此在这些候选者中选取最好的可以得到全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        prefix = 0
        best = 0
        
        for i in range(n):
            prefix += a[i]
            if (i + 1) % k == 0:
                best = max(best, prefix)
        
        print(best)

if __name__ == "__main__":
    solve()
```该解决方案首先按降序对数组进行排序，以便每个前缀代表给定大小的最佳可能选择。 前缀总和变量累积所选卡片的运行总数。 

关键的实施细节是检查`(i + 1) % k == 0`。 由于Python使用从零开始的索引，长度的前缀$i+1$当它形成的倍数时是完整的$k$。 只有在这些点上，分组约束才允许我们评估有效的配置。 

变量`best`跟踪所有有效前缀长度中的最大总和。 我们将其初始化为零，因为如果可能存在负值或者约束允许空选择，则不采用任何元素始终是有效基线。

 ## 边缘情况

 一个关键的边缘情况是所有值都为负时。 例如，考虑：```
1
3 2
-1 -2 -3
```排序后我们得到$[-1, -2, -3]$。 前缀和是$-1, -3, -6$。 只有长度为 2 的前缀有效，因为$2$是唯一的倍数$k$小于或等于$n$，其总和为$-3$。 然而，根据解释，可能隐式允许选择任何内容，因此算法初始化`best = 0`，确保答案不会变为负数。 

另一个边缘情况是当$n < k$。 在这种情况下，除了空选择之外，不存在有效的前缀，因此结果仍然是 0。排序和扫描自然会处理这个问题，因为没有索引满足`(i+1) % k == 0`，离开`best`不变。
