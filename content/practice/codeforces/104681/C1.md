 ## 解决方案
 ## 问题理解

 该任务围绕构建一个数组，该数组在非常具体的排序过程下产生规定的“排序成本”。 我们没有得到一个数组并要求模拟该过程，而是得到了所需的最终成本，并且必须构建实现它的前 N ​​个正整数的任何排列，或者确定这是不可能的。 

定义成本的过程如下。 从左侧开始，在每个位置 i 处，查看从 i 开始的后缀，找到该后缀中的最小值，然后反转 i 和该最小值位置之间的线段。 每次操作的成本是反转段的长度。 重复此操作直到数组被完全处理为止会产生总成本，而这个总成本就是我们必须匹配的。 

输入给出 N（排列的大小）和 C（目标成本）。 输出是 1 到 N 的任意排列，在此过程下精确地产生成本 C。 

约束结构至关重要。 每一步的成本至少为 1，最多为正在处理的数组段的剩余长度。 这立即意味着最小可能的总成本为 N − 1，这是当最小元素始终已经位于当前位置时实现的。 当每一步反转最大可能的后缀时，就会出现最大成本，根据索引约定给出 N(N+1)/2 − 1 附近的二次上限。 这甚至在建造任何东西之前就限制了目标成本的可行性。 

当假设范围内的所有成本都可以实现而无需构建显式排列时，就会出现天真的错误。 例如，如果 N = 4 且 C = 2，贪婪的“保持数组排序”方法将始终产生成本 3，因为每个步骤仍然执行至少一个操作。 如果试图局部调整元素而不考虑早期反转如何限制后来的位置，则会出现另一种失败模式。 由于每个操作都会永久地重塑后缀，因此局部修复可能会破坏先前满足的成本贡献。 

另一个微妙的问题是假设构造的单调性。 如果部分前缀在一定成本下看起来已经有效，则任意扩展它并不能保持可行性，因为以后的反转取决于全局排序，而不仅仅是前缀结构。 

## 方法

 蛮力方法的结构很简单。 我们生成 1 到 N 的每个排列，模拟每个排列的翻转过程，计算其总成本，并检查它是否与目标 C 匹配。如果找到匹配，我们立即输出该排列。 

这是有效的，因为问题定义是完全确定性的：每个排列都恰好映射到一个成本。 然而，排列的数量按 N 阶乘增长！ 由于重复的最小搜索和反转，在最坏的情况下每次模拟的成本为 O(N^2)。 即使对于中等大的 N，这也很快变得不可行。 

关键的观察结果是，在 C1 版本中，N 足够小，以至于穷举搜索实际上在限制范围内是可以接受的。 不需要高级的建设性推理或优化。 由于搜索空间本身很小，因此不需要对过程的结构进行解析反转。 

因此，该解决方案减少了生成排列、计算成本和选择有效排列的过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（烫发+模拟）| O(N!·N^2) | O(N!·N^2) | O(N) | 接受小N|
 | 最优（同样的想法，早点停止）| O(N!·N^2) | O(N!·N^2) | O(N) | 已接受 |

 ## 算法演练

 我们依靠系统枚举，一旦找到有效的排列就会提前终止。 

1. 按字典顺序生成从 1 到 N 的数字排列。

字典顺序的原因很简单，就是一致性以及一旦遇到有效配置就能够提前停止。 
2. 对于每个排列，从左到右模拟Reversart 过程。 

在步骤 i 中，找到从 i 开始的后缀中的最小元素。 这决定了反转将持续多远。 
3. 将线段从 i 反转到步骤 2 中找到的最小元素的位置。 

此操作直接对排序规则进行建模，并确保数组完全按照定义演化。 
4. 添加该步骤的成本，即反转段的长度。 
5. 继续直到到达数组末尾，累加总成本。 
6. 如果最终成本等于C，则立即输出排列并终止搜索。 
7. 如果穷尽所有候选后没有排列匹配，则输出-1。 

### 为什么它有效

 每个排列恰好对应一个确定性成本，因为该过程是完全指定的并且不会分支。 因此，枚举所有排列涵盖了可能结果的整个空间。 由于我们根据成本函数的确切定义来测试每个候选者，因此任何有效的解决方案都必须在枚举过程中出现（如果存在）。 提前终止不会跳过潜在的答案，因为排列是详尽且独立的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import permutations

def reversort_cost(arr):
    a = arr[:]
    n = len(a)
    cost = 0

    for i in range(n - 1):
        j = i + min(range(i, n), key=lambda k: a[k])
        a[i:j+1] = reversed(a[i:j+1])
        cost += (j - i + 1)

    return cost

def solve():
    n, c = map(int, input().split())

    for p in permutations(range(1, n + 1)):
        if reversort_cost(list(p)) == c:
            print(*p)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```实现的核心是`reversort_cost`函数，它忠实地再现了问题中描述的过程。 关键细节是正确找到后缀中最小元素的索引； 这是使用线性扫描完成的`min(range(...), key=...)`，对于小约束来说简单且稳健。 

排列循环是故意的暴力。 一旦找到有效的配置，该函数就会立即退出，避免不必要的计算。 该表示使用来自的元组`itertools.permutations`，然后将其转换为列表以进行就地反转。 

## 工作示例

 考虑一个 N = 3 的小例子。 

令 C = 4。 

我们列举排列：

 | 排列| 分步成本| 总计 |
 | --- | --- | --- |
 | 1 2 3 | 1 2 3 0 + 0 | 2 |
 | 1 3 2 | 1 3 2 0 + 1 | 3 |
 | 2 1 3 | 2 1 3 1 + 1 | 2 |
 | 2 3 1 | 2 3 1 1 + 2 | 3 |
 | 3 1 2 | 3 1 2 2 + 1 | 3 |
 | 3 2 1 | 3 2 1 2 + 2 | 4 |

 最后的排列匹配 C = 4，因此它是有效的。 

该迹线表明，不同的排列产生不同的成本模式，并且从排列到成本的映射不是以简单单调方式单射的，但仍然是完全可枚举的。 

现在考虑 N = 4 和 C = 3。最小可能成本为 3，这是在阵列已针对最小反转进行最佳排列时实现的。 像 1 2 3 4 这样的排列将立即产生成本 3，因为每一步都会找到已经存在的最小值。 

| 排列| 成本|
 | --- | --- |
 | 1 2 3 4 | 1 2 3 4 3 |

 这证实了 C 等于最小成本的边界情况对应于已经排序的数组。

import sys, io
from itertools import permutations

def reversort_cost(arr):
    a = arr[:]
    n = len(a)
    cost = 0
    for i in range(n - 1):
        j = i + min(range(i, n), key=lambda k: a[k])
        a[i:j+1] = reversed(a[i:j+1])
        cost += (j - i + 1)

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, c = map(int, input().split())

    for p in permutations(range(1, n + 1)):
        if reversort_cost(list(p)) == c:

    return "-1"

 ## 边缘情况

 当 N = 1 时，会出现一种边缘情况。排列很简单 [1]，并且由于不执行任何操作，因此成本始终为 0。 该算法可以正确处理这一问题，因为排列生成器仅产生一个候选，并且成本检查仅在 C = 0 时成功。 

另一种情况是当 C 小于 N − 1 时。由于每个有效的 Reversort 运行恰好执行 N − 1 个操作，每个操作至少贡献 1 的成本，因此这种情况会立即使所有排列失败。 暴力循环耗尽所有候选者并返回 -1，这符合不可能条件。 

当 C 最大时出现最终边界情况。 在这种情况下，严格递减的排列在每一步都会产生最大可能的逆转。 模拟会自然地计算这一点，因为每个后缀最小值始终位于最右侧，导致每次迭代时出现最大长度反转，并且成本与理论上限相匹配。
