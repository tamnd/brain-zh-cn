 ## 解决方案
 ## 问题理解

 当我们只能通过称为中值查询的特殊交互操作来比较元素时，此问题中的任务围绕重建元素的相对顺序。 我们只知道哪一个位于中间，而不是直接知道三个元素中哪一个最小或最大。 使用这个受限比较原语，我们必须推导出隐藏排列的完整排序。 

从输入端来看，唯一明确的信息是排列的大小。 未给出实际值或顺序。 获取信息的唯一方法是查询索引三元组，接收隐藏顺序中三元组中的中间元素的索引。 输出是按隐藏值升序排列的索引的最终排列。 

塑造解决方案的关键约束是允许的查询数量。 由于每个查询都是涉及三个元素的交互式比较，因此我们只能提供线性或近线性数量的元素。 任何试图通过简单的成对比较来模拟排序的方法都会立即变得不可行，因为它需要二次查询，这远远超出了大约 10^4 或 10^5 元素的典型限制。 

当最初的几个元素选择不当时，就会出现微妙的边缘情况，如果算法没有仔细维护一致的排序结构，就会导致不明确的插入位置。 例如，如果我们从错误的初始排序假设开始，并根据不一致的比较插入元素，则即使局部比较看起来正确，整个结构也可能变得无效。 当使用中值响应而不确保共享两个元素的三元组之间的比较一致时，会出现另一种边缘情况，这可能会导致朴素实现中的矛盾。 

## 方法

 暴力方法会尝试通过使用中值查询间接比较每对元素来恢复排列。 人们可以尝试通过重复询问涉及固定参考元素的三元组的中位数来推断成对排序。 这最终允许重建所有成对关系，但在最坏的情况下需要 θ(n²) 查询，因为每对必须通过多个中值检查来解析。 一旦 n 增长超过几千，这立即超出允许的查询预算。 

关键的见解是中值查询足够强大来模拟比较，但它们应该用于将元素插入到不断增长的排序结构中，而不是重建所有成对关系。 我们没有尝试确定顺序关系的完整图，而是维护当前的排序序列，并使用从中值查询导出的类似二进制的决策将每个新元素插入到正确的位置。 

这样做的原因是，知道 (a, b, c) 的中位数可以告诉我们新元素是否位于两个已经排序的元素之间，这正是插入排序或二进制插入所需的信息。 每个查询都会消除大部分可能的位置，从而将每次插入的搜索成本从线性降低到对数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最优（使用中值查询增量插入）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们逐步构建排列，维护一个始终根据隐藏顺序排序的列表。 

1. 首先任意放置前两个元素，并使用带有第三个虚拟值的单个中值查询或直接初始化和修复以后的比较来解决它们的顺序。 这建立了有效的基本排序。 
2. 维护一个排序列表`ord`包含已按正确顺序放置的元素。 
3. 对于每个新元素`x`，确定其位置`ord`使用二分搜索风格的过程。 我们比较`x`与当前间隔的中点，但由于我们无法直接比较对，因此我们使用以下形式的中值查询（左边界，右边界，x）。 返回的中位数告诉我们是否`x`位于两个边界元素之间或外部。 
4. 如果 (l, r, x) 的中位数为 l，则 x 位于 l 的左侧。 如果是 r，则 x 位于 r 的右侧。 如果是x，则x位于l和r之间。 这个单一查询使我们能够消除一半的搜索空间。 
5. 继续此缩小过程，直到找到准确的插入位置。 
6. 将 x 插入已排序列表中的确定位置，然后继续处理下一个元素。 

核心思想是每个查询给出 x 相对于两个已知锚点的位置的几何约束。 这将插入转换为全序结构上的对数搜索问题。 

### 为什么它有效

 每一步都会列出清单`ord`与隐藏全序一致。 中值查询保证三个元素之间正确的三元关系，并且由于现有端点始终反映正确的顺序，因此每个查询都正确划分有效插入区域。 不变的是`ord`每次插入后仍按真正的隐藏顺序排序。 由于每个新元素仅在消除所有冲突间隔后才放置，因此永远不会引入反转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# NOTE: This is a standard interactive median sort template.
# In Codeforces interactive problems, print flushing is required.
# Here we assume a helper function query(a, b, c) exists conceptually.

def solve():
    n = int(input())

    def query(a, b, c):
        print(a, b, c, flush=True)
        return int(input())

    ord_list = [1, 2]

    # ensure first two are ordered
    if query(1, 2, 3) == 2:
        ord_list = [2, 1]

    for x in range(3, n + 1):
        lo, hi = 0, len(ord_list)

        # binary insertion using median queries
        while hi - lo > 1:
            mid = (lo + hi) // 2
            l = ord_list[mid - 1]
            r = ord_list[mid]

            res = query(l, r, x)

            if res == x:
                lo, hi = mid - 1, mid + 1
                break
            elif res == l:
                hi = mid
            else:
                lo = mid

        ord_list.insert(hi, x)

    print(*ord_list, flush=True)

if __name__ == "__main__":
    solve()
```该解决方案维护一个动态排序的列表，并使用中值查询来替代直接比较。 功能`query(l, r, x)`是取代比较器的核心工具。 如果中位数是`x`，它位于`l`和`r`，它立即识别正确的插入区域。 否则，响应会告诉您是否`x`位于间隔的左侧或右侧，从而缩小搜索空间。 

对前几个元素的初始处理确保我们从有效的排序种子开始。 算法的其余部分取决于一致的边界比较。 

一个微妙的实现细节是在每次查询后刷新输出。 缺少这一点会导致交互环境中的僵局。 另一个微妙的问题是正确解释中值响应，因为更新中存在相差一的错误`lo`和`hi`可以破坏排序的不变量。 

## 工作示例

 考虑一个大小为 5 的小隐藏排列。假设真实顺序是`[3, 1, 5, 2, 4]`。 

我们从`ord_list = [1, 2]`初始化后。 

### 插入 3

 | 步骤| 我| r | 查询（l，r，3）| 行动| 订单列表 |
 | --- | --- | --- | --- | --- | --- |
 | 初始化| 1 | 2 | 1（或 2，取决于订单）| 确定位置| [1,2]|

 假设查询返回 3 是 2 的右边，因此我们在末尾插入。 

结果：`[1, 2, 3]`这证实了边界扩展可以正确处理大于所有当前元素的元素。 

### 插入 5

 我们与列表的边界进行比较。 

| 步骤| 我| r | 中位数| 决定| 订单列表 |
 | --- | --- | --- | --- | --- | --- |
 | 检查| 1 | 3 | 3 | 向右移动| [1,2,3]|
 | 检查| 2 | 3 | 3 | 向右移动| [1,2,3]|

 我们得出结论 5 大于所有元素，插入到末尾。 

结果：`[1, 2, 3, 5]`这证明了插入区域的单调变窄。

 ## 边缘情况

 一个关键的边缘情况是，如果初始排序未标准化，则第一次比较会给出不一致的印象。 例如，如果在插入开始之前元素 1 和 2 的排序不正确，则每次后续插入都可能将元素放置到错误的相对区域中。 该算法通过显式查询涉及 3 的初始三元组来避免这种情况。 

当新元素相对于所有现有元素非常小或非常大时，就会出现另一种边缘情况。 在这种情况下，二分查找必须正确收敛到边界。 使用中位数（l，r，x）可确保如果x位于当前区间之外，则它将始终被推向正确的末端而不会产生歧义。 

最后，当搜索间隔折叠到相邻元素时，会出现一种微妙的情况。 如果更新规则相差 1，则算法可能会将 x 插入到从未与 x 进行显式比较的邻居之间的错误位置。 每个插入都根据边界对进行验证的不变性可以防止这种情况发生。
