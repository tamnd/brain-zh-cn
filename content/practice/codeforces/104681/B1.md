 ## 解决方案
 ## 问题理解

 我们得到一个表示符号序列的单个字符串，其中每个位置要么是固定字母，要么是未知占位符。 固定字母有两种类型，将它们视为两个字符，未知字母可以用这两个字符中的任何一个来替换。 在决定如何替换每个未知数之后，我们通过扫描相邻对并在该对从一种字符类型更改为另一种字符类型时收取成本来评估结果字符串，根据变化的方向有两种不同的成本。 

更具体地说，最终的字符串对每次出现一个特定的相邻转换都会有一个惩罚，而对于反向转换则有另一个惩罚。 任务是为所有未知职位选择替代者，以使总过渡成本最小化。 

输入由一个测试用例组成，其中包含一个字符串和两个整数，描述两个可能的相邻转换的惩罚。 输出是一个整数，是最优替换所有未知数后可实现的最小成本。 

问题的结构立即表明局部决策会影响全局成本，但影响方式有限：成本仅取决于相邻对，而不取决于远程交互。 这意味着一旦我们将一个角色固定在某个位置，它的效果只能在两个地方感受到，即它的左邻居和右邻居。 

如果字符串长度约为一万或更多，则任何尝试所有未知数分配的解决方案都是不可能的，因为每个未知数都会使搜索空间加倍。 在典型的时间限制下，即使对每个作业进行三次或二次检查也会失败。 这迫使我们将字符串视为一个顺序决策过程而不是组合决策过程。 

一些边缘情况值得尽早隔离。 如果字符串不包含未知数，则答案只是转换的单个线性扫描。 如果字符串完全由未知数组成，一个天真的想法是尝试所有$2^n$作业，但即使像 40 这样的小长度也已经使这变得不可行。 另一个微妙的情况是，当未知数在固定字符之间隔离时，例如像 C???J 这样的模式，其中端点强制采用受约束的结构，如果过早提交而不考虑未来的转换，天真的贪婪填充可能会错误处理。 

## 方法

 蛮力方法是将每个未知位置视为二元选择。 对于字符串的每次分配，我们通过扫描相邻对并在发生转换时对惩罚求和来计算总成本。 这是正确的，因为它准确地评估了问题所定义的内容。 然而，如果有$k$位置未知，这需要$2^k$作业和每次评估成本$O(n)$，给出总复杂度$O(n \cdot 2^k)$。 即使对于中等程度的人来说，这种增长也会呈爆炸式增长$k$。 

关键的观察是成本函数没有超出前一个字符的记忆。 一旦我们决定了位置上的符号$i$，唯一的未来依赖是它如何与位置相互作用$i+1$。 这将问题转化为顺序优化，我们只需要记住最后选择的字符。 

这自然会导致对位置和最后一个角色选择的动态规划公式。 在每个位置，如果我们以任一字符类型结束于该位置，我们会跟踪可实现的最小成本。 当我们遇到固定字符时，转换就会受到限制。 当我们遇到未知数时，两种转变都是允许的。 每一步只考虑从前一个状态延伸，因此整个计算变得线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot 2^k)$|$O(n)$| 太慢了|
 | 动态规划|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将问题视为从左到右构建字符串，同时保持以两种字符状态结束的最佳可能成本。 

1. 初始化两个值，表示处理以每个可能的字符结尾的前缀的最小成本。 一开始，没有固定的字符，因此两个状态都设置为零，表示“尚未使用”。 
2. 从左到右迭代字符串。 在每个位置，我们计算一对新的成本，以在此位置的每种字符类型结束。 
3. 如果当前字符是固定的，我们只允许转换到该字符。 我们计算来自任一先前状态的成本，如果前一个字符与当前字符不同，则增加惩罚。 
4. 如果当前字符未知，我们会独立评估这两种可能性。 对于每个可能的分配，我们再次考虑之前的状态并选择导致该分配的最小成本路径。 
5. 处理完位置后，我们用新计算的状态替换旧状态并继续。 
6. 完成字符串后，答案是两个结束状态中的最小值。 

关键思想是，在每一步中，我们都将所有可能的历史压缩为两个数字，因为有关过去的所有相关信息仅编码在最后一个字符中。 

### 为什么它有效

 正确性依赖于以下事实：任何位置的成本贡献仅取决于其紧邻的左邻居。 这创建了一个最佳的子结构：一旦我们确定了到达位置的最佳成本$i$对于给定的最后一个字符，任何后来的决定都不能追溯性地改善或恶化早期的过渡。 因此，任何全局最优分配都必须包含每个位置-状态对的最优前缀，并且 DP 永远不会丢弃可能导致更好的完整解决方案的前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    x, y = map(int, input().split())

    INF = 10**18

    # dp[C], dp[J]
    dpC, dpJ = 0, 0

    first = True

    for ch in s:
        newC, newJ = INF, INF

        if ch == 'C' or ch == '?':
            # place C here
            costC = min(
                dpC,
                dpJ + y  # J -> C transition
            )
            newC = min(newC, costC)

        if ch == 'J' or ch == '?':
            # place J here
            costJ = min(
                dpJ,
                dpC + x  # C -> J transition
            )
            newJ = min(newJ, costJ)

        dpC, dpJ = newC, newJ

    print(min(dpC, dpJ))

if __name__ == "__main__":
    solve()
```该实现仅保留两种滚动 DP 状态，一种用于以 C 结束已处理的前缀，另一种用于以 J 结束。在每个字符处，我们通过考虑是保持在同一字符还是从另一个字符切换来更新这些状态，并在切换方向时添加适当的转换成本。 

一个微妙的点是，我们永远不需要显式跟踪我们是否位于第一个字符，因为两个初始状态都为零，并且在前一个字符存在之前不会添加任何转换成本。 这是有效的，因为第一个字符不贡献任何邻接成本。

此跟踪显示了 DP 如何延迟决策，直到转换使成本结构变得清晰。

 ## 边缘情况

 完全未知的字符串说明了贪婪赋值失败的原因。 如果我们有`????`在成本相同的情况下，贪婪策略可能会提前更换角色，从而产生不必要的转换，而 DP 始终保持两个状态一致并避免过早承诺。 

具有交替固定字符的字符串，例如`CJCJ`迫使每一个相邻的对都贡献成本。 DP 无法避免这里的过渡，并且正确地累积了所有惩罚，表明它尊重强制结构而不是试图人为地平滑它。 

单字符输入确认当邻接不存在时不会添加任何转换成本。 DP 正确初始化两个状态并返回零，无需特殊大小写。
