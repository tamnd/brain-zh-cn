 ## 解决方案
 ## 问题理解

 任务是构建从 1 到 n 的数字排列，以便当对其应用名为 Reversart 的特定确定性过程时，该过程的总成本恰好是给定值 C。如果不存在这样的排列，我们必须报告不可能性。 

Reversort 过程的工作原理是反复将最小的剩余元素固定到正确的位置。 在步骤 i，我们查看从 i 开始的子数组，找到该后缀中的最小元素，并将段从 i 反转到该最小值的位置。 此步骤的成本是反转段的长度。 总成本是这些步骤成本的总和。 

输入给出 n（排列的长度）和 C（所需的总成本）。 输出必须是从 1 到 n 的任意排列，该排列在翻转条件下精确地产生该成本，或者是指示不存在此类排列的标记。 

此问题的典型 Codeforces 版本所隐含的约束允许 n 达到大约 100 或几千。 这立即表明以 O(n^2) 构建排列是可以接受的，但任何涉及阶乘探索或强力排列测试的内容都是不可接受的。 

一些边缘情况决定了正确性。 如果n = 1，唯一的排列是[1]，其成本为0。如果C太小，特别是小于n-1，则这是不可能的，因为Reversart的每一步都必须成本至少为1。如果C太大，超过最大可实现成本（当每次反转跨越尽可能远时发生），构造也是不可能的。 

例如，当 n = 4 时，最小成本为 3，最大成本为 10。如果 C = 2，则任何排列都不起作用，因为即使是最有效的排列也已花费 3。如果 C = 10，我们需要一个在每一步都强制进行最大长度反转的排列。 

生成排列并模拟Reversart 的简单方法将在超过非常小的n 时立即失败，因为有n！ 候选人。 即使 n = 10，这也是不可行的。 

## 方法

 蛮力的想法很简单。 我们生成 1 到 n 的每一种排列，对每一种排列运行 Reversort 过程，计算其成本，并检查它是否与 C 匹配。这是正确的，因为它详尽地检查了所有可能性。 然而，它执行 n! 排列，每次模拟的成本为 O(n)，导致 O(n · n!) 次运算，一旦 n 超过 10 左右，运算就变得不可用。 

关键的观察是我们不需要向前模拟Reversart。 相反，我们可以通过控制每一步的成本贡献来向后构建排列。 在Reversart 的第i 步，成本完全取决于最小元素距位置i 的距离。 该距离可以在有限的范围内选择，并且每个选择独立地贡献于总成本预算。 

这将问题转化为在位置上分配总“额外成本”，其中每个位置 i 最多可以贡献 n - i 额外成本。 一旦我们从左到右贪婪地决定了这些贡献，我们就可以通过放置元素来直接构建排列，以便每一步都强制达到所需的反转长度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·n!) | O(n·n!) | O(n) | 太慢了|
 | 贪心建设| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们重新解释所需的成本。 Reversort 的成本至少为 n-1，因为 n-1 个步骤中的每一步的最小成本为 1。成本的剩余部分 C-(n-1) 是我们必须在步骤之间分配的额外成本。 

在第 i 步，我们可以将反转“拉伸”最多 n - i 个位置，这会带来额外的成本。 施工工作是通过从第一个位置开始确定这些延伸段来进行的。

1. 计算最小和最大可能成本。 最小值为 n - 1，最大值为 n(n + 1)/2 - 1。如果 C 在此区间之外，则任何排列都无法满足要求。 
2. 令剩余 = C - (n - 1)。 这代表我们仍然需要跨步骤分配多少额外的反转长度。 
3. 从有序列表 [1, 2, ..., n] 开始。 这个列表将通过受控反转转化为最终的排列。 
4. 对于从 1 到 n-1 的每个位置 i，决定我们将反转延伸多远。 最大可能的扩展是 n - i。 我们选择扩展 x = min(n - i, 剩余)。 这确保了我们永远不会超出这个位置的可能范围，同时仍然尝试尽早消耗尽可能多的剩余成本。 选择x后，我们将剩余量减少x。 
5. 执行从位置 i 到 i + x 的反转。 这强制将此步骤的最小元素推得足够远以贡献成本 x + 1。 
6. 继续直到倒数第二个位置。 最终，阵法完全确定。 

它为何有效取决于一个简单的守恒特性。 每个位置 i 贡献的成本为 1 加上我们选择推动所选最小元素的距离。 该算法确保将每个单位的额外成本分配给仍然可行的某个步骤，并且贪婪地耗尽早期位置的津贴永远不会阻止未来的可行性，因为后面的位置具有严格较小的最大容量。 这创建了一个单调的分配空间，其中贪婪打包是安全的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())

    min_cost = n - 1
    max_cost = n * (n + 1) // 2 - 1

    if c < min_cost or c > max_cost:
        print("IMPOSSIBLE")
        return

    remaining = c - min_cost
    a = list(range(1, n + 1))

    for i in range(n - 1):
        max_add = n - i - 1
        x = min(max_add, remaining)
        remaining -= x

        j = i + x
        a[i:j + 1] = reversed(a[i:j + 1])

    print(*a)

if __name__ == "__main__":
    solve()
```该解决方案首先使用已知的Reversart 成本范围来检查可行性。 然后它逐步构建排列。 关键的实现细节是反转段以从零开始的索引表示，因此范围`a[i:j+1]`正确包含端点。 变量`x`表示我们将当前元素推入多远，它受到剩余预算和数组末尾的限制。 

一个常见的错误是在计算位置 i 处的最大延伸时进行了差一处理。 正确的界限是 n - i - 1，因为从索引 i 开始，最远的索引是 n - 1。

 ## 边缘情况

 当 n = 1 时，循环永远不会运行，唯一有效的成本为 0。算法立即检查边界并打印单元素排列。 

当 C 等于最大可能成本时，第一步消耗尽可能多的扩展，在单遍中生成完全反转的数组。 对于n = 4和C = 10，第一次迭代选择x = 3，反转整个数组，并且没有剩余成本。 

当C低于n-1时，例如n = 5且C = 3，可行性检查会立即拒绝，因为即使是最小的Reversart过程也需要4个成本单位，从而无法进行任何施工。
