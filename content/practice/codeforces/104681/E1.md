 ## 解决方案
 ## 问题理解

 我们得到一个大型二进制表，描述一组参与者如何回答大量问题。 每一行对应一个参与者，每一列对应一个问题。 如果参与者答对了该问题，则单元格为 1，否则为 0。 

在所有参与者中，只有一个人的行为与其他人不同。 其余的遵循自然模式，其中一些问题本质上比其他问题更容易，而一些参与者比其他人更强，因此正确性受到行和列结构的影响。 特殊参与者忽略了这种结构：就问题难度而言，他们的正确性本质上是随机的，因为他们有时“正常解决”，有时表现得好像他们总是知道答案，每个问题都是独立的。 

任务是仅使用答案矩阵来识别该异常参与者。 

输入量足够大，任何直接将每对玩家与每对问题进行比较的方法都变得不可行。 大约有 100 名参与者和 10000 个问题，即使是针对问题的三次或密集二次方法也已经太慢了。 该结构表明我们必须将每个问题和每个玩家的信息压缩为一个小的统计数据，然后使用这些摘要来比较玩家。 

简单的实现可能会尝试明确地对每个参与者的技能进行建模，或者计算每对玩家和每个问题子集之间的相关性。 这很快就会变得不稳定且缓慢。 

如果我们只比较总分，就会出现微妙的失败案例。 例如，假设两个玩家都正确回答了 5000 个问题。 一种是强而一致的，另一种是随机的，但恰好具有相似的完全正确性。 纯粹的总数无法区分它们。 如果我们只比较行方向方差而不考虑问题难度，就会出现另一个失败：如果我们不按列效应进行标准化，强玩家和随机玩家可能仍然看起来相似。 

## 方法

 蛮力的想法是直接测量每个玩家与数据集的“自然结构”的匹配程度。 一种方法是尝试将所有可能的问题分为简单组和困难组，并评估每个玩家在这些分区中的表现。 对于每个候选分区，我们可以计算两组玩家的成功率差异有多大。 这在原则上是正确的，因为作弊者与难度无关，而真正的玩家却如此。 

然而，问题的可能分区数量与列数呈指数关系。 即使将我们限制在平衡分裂上，我们仍然面临着巨大的组合搜索空间。 10000个问题，这是完全不可能的。 

关键的见解是我们实际上并不需要完美地发现真正的难度结构。 我们只需要一个粗略的代理来区分简单的问题和困难的问题。 如果我们可以根据数据本身估计问题难度，那么我们就可以比较每个玩家在简单问题和困难问题上的表现。 

问题难度的自然估计是正确回答问题的玩家比例。 许多玩家解决的问题可能很简单； 少数人解决的问题可能很难。 这让我们在不了解任何真正技能的情况下对问题进行了全局排序。 

一旦问题按照估计的难度排序，就可以测试每个玩家的表现是否在该范围内发生有意义的变化。 真正的玩家往往在较简单的问题上做得更好，在较难的问题上做得较差，从而与难度形成正相关。 异常参与者在难度方面是随机的，在简单问题和困难问题之间几乎没有任何区别。

这将问题简化为根据两组汇总的问题计算每个玩家的单个分数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区搜索| 指数| O(纳米) | 太慢了|
 | 难度排序+拆分比较 | O(nm log m) | O(纳米) | 已接受 |

 ## 算法演练

 我们将原始矩阵转换为一个信号，该信号捕获每个参与者与问题难度的匹配程度。 

1. 通过对每列求和并除以参与者数量来计算每个问题的正确率。 这给出了每个问题的简单程度的数字估计。 这个想法是，更简单的问题解决得更频繁，因此它们的列总和更高。 
2. 按照估计的难度从最简单到最难对所有问题进行排序。 这创建了一个近似隐藏难度结构的全局排序，即使我们从未明确地对技能进行建模。 
3. 将排序后的问题分成两半。 前半部分代表较简单的问题，后半部分代表较难的问题。 这种粗略的分割就足够了，因为我们只需要定向信号，而不是精确的校准。 
4. 对于每个参与者，分别计算他们在简单一半和困难一半上的成功率。 这为每个参与者提供了两个值：一个描述他们在简单问题上的表现，另一个描述他们在困难问题上的表现。 
5. 计算每个参与者这两个比率之间的差异。 普通参与者往往会产生积极的差异，因为他们更有可能在更简单的问题上取得成功。 异常参与者的差异往往接近于零，因为他们的正确性与难度无关。 
6. 选择差异绝对值最小的参与者。 

核心思想是我们正在衡量问题难度方面与单调行为的偏差。 

### 为什么它有效

 正确性矩阵包含一个隐藏结构：问题难度会导致正常参与者表现的单调趋势。 即使不知道真实的技能值，按列平均值也很有可能保留这种排序，因为它聚合了许多独立的伯努利结果。 

对于普通参与者来说，正确概率随着问题的容易程度而增加，因此他们的二分之一差异集中在远离零的地方。 对于异常参与者来说，正确性与问题身份无关，因此两半的预期成功率基本上相同。 这使得他们的差异集中在零附近，将他们与其他人区分开来。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = 100
    m = 10000
    
    a = [input().strip() for _ in range(n)]
    
    col_sum = [0] * m
    for i in range(n):
        row = a[i]
        for j, ch in enumerate(row):
            col_sum[j] += (ch == '1')
    
    idx = list(range(m))
    idx.sort(key=lambda j: col_sum[j])
    
    half = m // 2
    easy = idx[:half]
    hard = idx[half:]
    
    best_player = -1
    best_score = 10**18
    
    for i in range(n):
        row = a[i]
        
        easy_cnt = 0
        hard_cnt = 0
        
        for j in easy:
            if row[j] == '1':
                easy_cnt += 1
        
        for j in hard:
            if row[j] == '1':
                hard_cnt += 1
        
        easy_rate = easy_cnt / len(easy)
        hard_rate = hard_cnt / len(hard)
        
        diff = abs(hard_rate - easy_rate)
        
        if diff < best_score:
            best_score = diff
            best_player = i + 1
    
    print(best_player)

if __name__ == "__main__":
    solve()
```该实现直接反映了算法。 列总和用于近似难度，排序产生稳定的顺序。 然后通过扫描两个半场来评估每个球员。 唯一微妙的部分是确保除法以浮点形式完成； 整数除法会消除玩家之间的区别。 

索引也很重要：玩家在输出中索引为 1，因此我们存储`i + 1`当跟踪最佳候选人时。

### 示例 2

 如果所有玩家的总分相同，但在简单问题和困难问题上的分布不同，算法仍然会区分他们，因为分割取决于列结构，而不是行总计。 

这表明原始评分平等并不意味着难度分层下的类似行为。

 ## 边缘情况

 当许多问题的列总和几乎相同时，就会出现微妙的边缘情况。 在这种情况下，排序顺序有噪声，但算法仍然有效，因为只需要粗略分割。 即使有些问题在半场之间被错误分类，作弊者对半场之间的预期平等仍然保持稳定，而真正的玩家仍然表现出方向性偏差。 

当一个强大的玩家在困难中表现异常一致时，就会出现另一种边缘情况，这可能会模仿作弊者。 然而，由于潜在的生成过程，即使是强大的玩家也会与难度保持一定的相关性，因此他们的易难差距在预期中仍然不为零。 

最后，如果数据集很小或极度不平衡，列平均值就会变得不太可靠。 在这种情况下，分离会减弱，但预期的约束假设有足够的数据来实现大数定律效应，以稳定排序。
