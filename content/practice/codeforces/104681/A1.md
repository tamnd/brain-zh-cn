 ## 解决方案
 ## 问题理解

 我们给出了一个整数序列，它形成了大小的排列$n$。 任务是模拟一个确定性过程，通过定位剩余后缀中的最小元素并反转将其带到正确位置的段，从左到右重复“固定”数组。 

更具体地说，从第一个位置开始，在每一步中，我们都会查看从当前索引开始的子数组，找到该后缀中的最小元素所在的位置，反转整个段，并累积等于我们反转的段长度的成本。 最终的答案是处理除最后一个位置之外的所有位置后的总成本。 

输入大小约束意味着数组可以足够大，以至于必须仔细处理在每个步骤中通过扫描和反转来重复搜索最小值的情况。 扫描和反转的简单实现已经是每步线性的，导致总体上二次行为。 只有在以下情况下这仍然是可以接受的：$n$就在附近$10^3$，但超出此范围就会失败。 问题的结构在操作上故意简单，但重复的后缀最小查询决定了性能瓶颈。 

一些边缘情况对于正确性很重要。 如果数组已经排序，则每一步都会选择当前元素作为最小值，并且不会发生有意义的反转，但成本仍然会随着琐碎段的长度而累积。 例如，对于输入`[1, 2, 3]`，即使数组没有明显改变，每个步骤仍然会产生成本。 

另一个微妙的情况是最小元素已经位于当前位置。 粗心的实现可能会跳过反转或跳过增加成本，但正确的行为仍然包括反转长度为 1 的段，从而贡献 1 的成本。 

## 方法

 暴力模拟完全遵循所描述的过程。 对于每个位置$i$，我们扫描后缀$i \ldots n$要找到最小元素的索引，请反转子数组$i$到该索引，并将段长度添加到答案中。 每一步都需要线性扫描，有$n$步骤，因此总复杂度变为$O(n^2)$。 这适用于当$n$很小，但很快就会变得太慢$n$增长超过几千。 

关键的观察是该问题不需要维护任何高级数据结构来进行动态更新。 尽管数组因反转而发生变化，但我们在每一步中唯一关心的是剩余后缀中最小值的位置。 由于该过程是固定且连续的，因此我们仍然可以直接以每步的线性时间进行模拟，而无需对此版本进行优化，因为对于预期的子任务 A1 来说，约束足够小。 

因此，最佳解决方案是相同的模拟，通过仔细的切片或就地反转来干净地实现。

 ## 算法演练

 ## 算法演练

 1. 首先将运行总成本初始化为零。 这将累积每个反转步骤的成本。 
2. 从第一个位置到倒数第二个位置迭代数组。 在每个索引处$i$，我们试图在最终的排序顺序中放置该位置的正确元素。 
3. 对于当前索引$i$,扫描后缀$i \ldots n-1$找到位置$j$的最小元素。 此步骤标识应移动到位的元素$i$根据Reversart规则。 
4. 将成本贡献计算为$j - i + 1$，因为这是被反转的段的长度。 将此值添加到总成本中。 
5. 反转子数组$i$到$j$到位。 这确保了最小元素现在正确放置在索引处$i$，保留之前位置的不变量$i$已经固定了。 

处理完所有索引后，返回累计成本。 

### 为什么它有效

 每一步$i$，该算法确保前缀$[0, i]$排序是指它按顺序包含正确的最小剩余元素。 反转操作不是任意的； 这是唯一将最小元素移动到位置的操作$i$并保留后续步骤所需的相对顺序。 因为每一步都严格固定一个位置并且不会干扰之前的固定位置，所以该过程必须准确地终止$n-1$步骤与完全排序的数组。 成本由所选的段长度唯一确定，因此累加的总和是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    total = 0
    
    for i in range(n - 1):
        j = i
        for k in range(i, n):
            if a[k] < a[j]:
                j = k
        
        total += (j - i + 1)
        a[i:j+1] = reversed(a[i:j+1])
    
    print(total)

if __name__ == "__main__":
    solve()
```实现完全遵循算法。 外环将每个位置一一固定。 内循环查找剩余后缀中的最小元素。 切片反转`a[i:j+1] = reversed(...)`直接执行所需的操作并安全地处理所有情况，包括当`i == j`，其中段长度为 1，数组保持不变，但仍会增加成本。 

一个常见的陷阱是当最小值已经到位时忘记包括成本`i`。 该代码通过始终添加来避免这种情况`j - i + 1`无论反转是否具有视觉意义。

 ## 边缘情况

 对于像这样的单元素数组`[1]`，循环不会执行，因此总成本保持为零。 这是正确的，因为没有要反转的段。 

对于已经排序的数组，例如`[1, 2, 3, 4]`，每一步都选择当前索引作为最小值。 即使没有发生明显的变化，每次反转的长度都是 1，因此成本累积为$n - 1$。 该算法正确地包含了这些贡献，因为它永远不会跳过反转步骤。 

对于反转数组，例如`[4, 3, 2, 1]`，每一步都会从末端向前拉下一个最小的元素，从而产生最大的移动量。 该实现仍然可以正确处理这个问题，因为它总是重新计算当前后缀的最小值，而不是依赖于过时的结构。
