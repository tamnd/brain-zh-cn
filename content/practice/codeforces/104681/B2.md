 ## 解决方案
 ## 问题理解

 我们得到一个由三种字符组成的字符串：`C`,`J`， 和`?`。 该字符串表示位置序列，每个位置必须分配给`C`或者`J`， 在哪里`?`职位尚未确定，可以自由选择。 

每次最终字符串切换都会产生相关成本`C`到`J`或来自`J`到`C`。 此外，更换一个`?`任一字母都会影响最终出现的此类开关的数量，因此目标是分配每个`?`以最佳方式最小化最终完全解析字符串的总转换成本。 

更具体地说，替换所有之后`?`，我们从左到右扫描，并在两个相邻字符不同时支付费用。 成本为`CJ`过渡是`X`，以及成本`JC`过渡是`Y`。 

任务是为所有未知位置选择替代品，以使最终的总成本尽可能小。 

输入大小意味着我们可能必须处理长字符串，每个测试用例可能需要处理很大的线性大小。 这立即排除了尝试所有分配的任何方法`?`，因为每个`?`搜索空间加倍并导致指数行为。 如果字符串长度达到数十万，即使是对位置对的二次动态规划也会太慢。 

当出现一个微妙的问题时`?`出现在长的连续块中。 例如，考虑：```
C???J
X = 5, Y = 2
```像“填满所有”这样的贪婪决定`?`与最近的已知邻居”可能会失败，因为它忽略了最佳全局选择可能取决于我们是想在边界创建单个转换还是在内部避免多个转换。

 另一个棘手的情况是当字符串以以下形式开始或结束时`?`， 例如：```
???CJ
```仅优化未知块内的局部转换的简单方法可能会忽略第一个块可以完全与右边界对齐以避免额外转换的事实。 

这些问题表明局部贪婪决策是不够的； 每个位置的选择以结构化的方式取决于前一个角色。 

## 方法

 蛮力的想法很简单：对待每一个`?`作为任一`C`或者`J`，生成所有可能的字符串，计算每个字符串的转换成本，并取最小值。 这是正确的，因为它探索了完整的解决方案空间而不进行近似。 

然而，如果有`k`问号，这会产生`2^k`配置。 即使是为了`k = 30`，这已经超过了十亿种可能性，并且在典型的约束条件下`k`如果可以与整个字符串长度成正比，则这种方法变得不可能。 

关键的观察结果是，成本仅取决于相邻对，这意味着决策从左到右线性传播。 在每个位置，唯一相关的状态是之前选择的角色是什么。 这将全局结构简化为一个小的状态转换问题。 

我们不是尝试所有分配，而是在两种可能性下维持每个位置的最小成本：当前角色是`C`或者`J`。 当我们处理一个已知的字符时，状态是固定的。 当我们处理一个`?`，我们考虑这两个选项并向前传播最佳成本。 这将问题转化为字符串上的简单动态规划。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^k·n) | O(2^k·n) | O(n) | 太慢了|
 | DP 超过各州 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时跟踪当前位置以以下结尾的最小成本`C`或结束于`J`。 

1.初始化两个变量`dpC`和`dpJ`如果最后一个字符是，表示到当前位置的最小成本`C`或者`J`分别。 最初将它们设置为无穷大，除了单独处理的第一个位置。 
2. 对于第一个字符，如果是固定的(`C`或者`J`），我们将成本 0 分配给该状态，将无穷大分配给另一个状态。 如果是的话`?`，我们允许两种状态的成本均为 0。 
3. 对于每个下一个字符，计算新值`nextC`和`nextJ`。 如果当前字符是`C`， 然后`nextC`是从先前延伸的最小值`C`（无额外费用）和之前的`J`（增加成本`Y`因为`J -> C`）。 如果角色是`J`，对称逻辑适用于成本`X`为了`C -> J`。 如果角色是`?`，我们评估这两种可能性，就好像它可以是`C`或者`J`并采取最好的。 
4.处理完字符后，更新`dpC = nextC`和`dpJ = nextJ`。 
5.最终答案是`min(dpC, dpJ)`。 

重要的细节是，当角色在相邻位置之间变化时，我们总是考虑转换成本。 DP 状态确保我们永远不会忘记之前的角色选择。 

### 为什么它有效

 DP 状态捕获影响未来决策的所有信息：只有最后选择的字符对未来的转换成本很重要。 任何两个以相同的最后一个字符结尾并且具有不同的内部历史的部分解决方案对于未来的决策都是等效的，除了它们的累积成本之外。 因此，仅保留每个结束字符的最小成本可以保持最优性。 这是一个标准的最佳子结构参数：前缀与固定最后一个字符相结合的最佳解决方案始终可以最佳地扩展，而无需重新考虑早期的结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    X, Y = map(int, input().split())
    s = input().strip()
    
    dpC, dpJ = INF, INF
    
    # initialize first character
    if s[0] == 'C':
        dpC, dpJ = 0, INF
    elif s[0] == 'J':
        dpC, dpJ = INF, 0
    else:
        dpC, dpJ = 0, 0
    
    for i in range(1, len(s)):
        c = s[i]
        nextC, nextJ = INF, INF
        
        if c == 'C' or c == '?':
            # end in C
            nextC = min(
                dpC,          # C -> C
                dpJ + Y       # J -> C
            )
        
        if c == 'J' or c == '?':
            # end in J
            nextJ = min(
                dpJ,          # J -> J
                dpC + X       # C -> J
            )
        
        dpC, dpJ = nextC, nextJ
    
    return min(dpC, dpJ)

def main():
    t = int(input())
    for i in range(t):
        print(solve())

if __name__ == "__main__":
    print(main())
```DP 是迭代实现的，每个测试用例仅保留两个标量。 初始化步骤至关重要，因为`?`一开始允许两个状态而不受惩罚。 

一个常见的实施错误是忘记转换取决于方向：`C -> J`使用成本`X`， 尽管`J -> C`使用成本`Y`。 即使 DP 结构保持正确，默默地交换这些也会产生错误的答案。

 ## 边缘情况

 前导或尾随块`?`由 DP 自然处理，因为当第一个字符未知时，最初允许两种状态。 对于像这样的输入`???C`，DP 以两个状态的零成本开始，并且强制`C`最后正确地折叠状态，仅累积必要的转换。 

具有交替高和低转换成本的字符串不会破坏算法，因为每个步骤总是显式地考虑两个方向。 即使一个方向的成本要低得多，DP 仍然保留替代状态，直到它被证明更糟糕。 

单字符字符串或完全未知的字符串没有转换，并且 DP 正确返回零，因为不存在相邻对。
