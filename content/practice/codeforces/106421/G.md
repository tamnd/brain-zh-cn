 ## 解决方案
 ## 问题理解

 该问题要求我们查看打孔计时的每个连续片段，并确定其平均计时是否在可接受的窗口内。 该数组包含每次尝试的记录时间，并且我们需要其平均值至少为的非空连续组的总数`a`并且至多`b`。 

这些限制使主要挑战变得清晰。 最多可以有`2 * 10^5`尝试，因此直接检查每个段是不可能的。 有大约`n^2 / 2`连续的段，大致达到`2 * 10^10`什么时候`n`很大。 二次算法无法适应时间限制。 我们需要一个接近的解决方案`O(n log n)`因为对于这个输入大小来说，这只提供了几百万次操作。 

棘手的部分来自平均值。 具有分数平均值的段仍然可以满足条件，因此直接比较整数和是不够的。 例如，该段`[3, 4]`有平均数`3.5`。 如果允许的范围是`[3, 4]`，答案必须包含它。 使用整数算术除法的解决方案可能会错误地将平均值视为`3`。 

另一种边缘情况是平均值恰好位于边界上。 对于输入：```
3 5 5
5 5 4
```正确的输出是`3`，因为有效段是`[5]`,`[5]`， 和`[5,5]`。 使用严格比较而不是允许相等的解决方案会错过这些情况。 

第二个边界问题出现在上侧。 对于输入：```
2 1 3
1 3
```该段`[1,3]`有平均数`2`，所以它是有效的，答案是`3`。 上限必须被处理为“大于`b`无效”，而不是“大于或等于`b`无效”。

 ## 方法

 直接的方法是枚举每个起始位置和结束位置，计算该段的总和，除以其长度，然后检查平均值是否属于该区间。 前缀和将查找段和的成本降低到`O(1)`，但仍有`O(n^2)`段。 在最坏的情况下`n = 200000`，这意味着大约有 200 亿张支票，远远超出了可用时间。 

有用的观察是平均条件可以在不除法的情况下重写。 对于具有值的段`x1, x2, ..., xk`，条件```
(x1 + x2 + ... + xk) / k >= c
```相当于```
(x1 - c) + (x2 - c) + ... + (xk - c) >= 0
```现在的问题是用非负的变换后的和来计算子数组。 

我们可以将所需的间隔分为两个更简单的计数：```
average in [a, b]
=
average >= a
-
average > b
```第一个计数使用变换`x[i] - a`并要求子数组的总和至少为零。 第二种用途`x[i] - b`并要求子数组的总和严格大于零。 

对于任一版本，让`pref[i]`是转换后的数组的前缀和。 一个子数组`(l, r]`在以下情况下具有有效总和：```
pref[r] - pref[l] >= 0
```这意味着：```
pref[r] >= pref[l]
```所以从左到右扫描数组时，我们只需要知道前面有多少个前缀和小于或等于当前的前缀和即可。 这是一个订单统计计数问题。 坐标压缩和 Fenwick 树让我们可以将这些计数保存在`O(log n)`每个前缀的时间。 

暴力方法之所以有效，是因为它准确地检查了我们需要的条件，但它失败了，因为它对太多段重复了几乎相同的工作。 前缀和变换消除了单独检查段的需要，并且芬威克树有效地计算所有有效的前缀对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 定义一个辅助函数，用于计算有多少子数组的平均值至少为选定值`c`。 减去`c`从每个元素并计算变换后总和为非负数的子数组。 这将平均比较问题转换为前缀比较问题。 
2. 构建转换后的前缀和。 从前缀和开始`0`在数组开始之前。 每个新前缀代表迄今为止处理的元素的总转换值。 
3. 坐标压缩所有前缀和。 前缀和可以是负数，也可以很大，因此压缩让 Fenwick 树存储它们的相对顺序而不是它们的实际值。 
4. 从左到右扫描前缀和。 对于当前前缀`p`，计算有多少个较早的前缀满足`previous <= p`。 每个这样的对都会创建一个子数组，其变换后的总和至少为零。 将计数添加到答案中并插入`p`进入芬威克树。 
5. 计算平均值大于的子数组的数量`b`。 这几乎是相同的过程，除了我们需要`previous < p`因为变换后的总和必须严格为正。 
6. 从第一个计数中减去第二个计数。 其余的段恰好是平均值介于`a`和`b`。 

该算法背后的不变性是，在处理前缀后，芬威克树准确地包含所有早期的前缀和及其频率。 以当前位置结尾的每个可能的子数组都对应于一个较早的前缀。 树查询精确地统计当前段满足变换后的不等式的前缀，因此每个有效段都被统计一次，并且排除每个无效段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i:
            res += self.bit[i]
            i -= i & -i
        return res

def count_average_condition(arr, c, strict):
    pref = [0]
    cur = 0
    for x in arr:
        cur += x - c
        pref.append(cur)

    vals = sorted(set(pref))
    index = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(len(vals))
    ans = 0

    fw.add(index[0], 1)

    for i in range(1, len(pref)):
        pos = index[pref[i]]
        if strict:
            ans += fw.sum(pos - 1)
        else:
            ans += fw.sum(pos)
        fw.add(pos, 1)

    return ans

def solve():
    n, a, b = map(int, input().split())
    arr = list(map(int, input().split()))

    at_least_a = count_average_condition(arr, a, False)
    greater_than_b = count_average_condition(arr, b, True)

    print(at_least_a - greater_than_b)

if __name__ == "__main__":
    solve()
```芬威克树存储前缀和的频率而不是它们的值。 这`add`操作在使用当前前缀进行计数后插入当前前缀，防止意外计数空段。 

第一次致电`count_average_condition`允许相等，因此它查询值最多为当前前缀的先前前缀的数量。 第二次调用需要严格正变换的总和，因此它只计算之前严格较小的前缀。 

Python 整数会自动处理潜在的大答案。 答案可以与子数组的数量一样大，大约`n * (n + 1) / 2`，它比 32 位整数大得多。 

## 工作示例

 对于样本：```
6 7 9
3 4 7 8 9 9
```通过减去上面平均值的子数组来计算有效子数组`9`从那些至少具有平均水平的人中`7`。 

| 步骤| a=7 的当前前缀 | 以前的前缀计数 | 运行计数 |
 | ---| ---| ---| ---|
 | 开始| 0 | 插入 0 | 0 |
 | 1 | -4 | 0 | 0 |
 | 2 | -7 | 0 | 0 |
 | 3 | -7 | 2 | 2 |
 | 4 | -6 | 3 | 5 |
 | 5 | -4 | 4 | 9 |
 | 6 | -2 | 6 | 15 | 15

 第一遍计算所有段的平均值至少`7`。 第二遍删除平均值大于的段`9`，留下所需答案`12`。 

第二个例子：```
3 5 5
5 5 4
```对于下限和上限，只有精确的平均值才重要。 

| 步骤| 减去 5 后的前缀 | 具有有效关系的先前前缀 | 添加计数 |
 | ---| ---| ---| ---|
 | 开始| 0 | 插入 0 | 0 |
 | 1 | 0 | 1 | 1 |
 | 2 | 0 | 2 | 2 |
 | 3 | -1 | 0 | 0 |

 第一个计数给出了所有段的平均值至少`5`，第二个删除平均值大于的所有段`5`。 剩下的答案是`3`，将三个段与平均值完全匹配`5`。

import sys
import io

def solve_case(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            r = 0
            while i:
                r += self.bit[i]
                i -= i & -i
            return r

    def count(arr, c, strict):
        p = [0]
        s = 0
        for x in arr:
            s += x - c
            p.append(s)

        vals = sorted(set(p))
        mp = {x: i + 1 for i, x in enumerate(vals)}
        fw = Fenwick(len(vals))
        fw.add(mp[0], 1)
        ans = 0

        for x in p[1:]:
            pos = mp[x]
            ans += fw.sum(pos - 1 if strict else pos)
            fw.add(pos, 1)

        return ans

    n, a, b = map(int, input().split())
    arr = list(map(int, input().split()))
    return str(count(arr, a, False) - count(arr, b, True)) + "\n"

 ## 边缘情况

 对于精确边界情况：```
3 5 5
5 5 4
```转换后的值`c = 5`是`0, 0, -1`。 前缀和变为`0, 0, 0, -1`。 在第一遍中计算的前缀和相等，因此`[5]`,`[5]`， 和`[5,5]`都包括在内。 严格的第二遍仅删除平均值以上的片段`5`，其中没有。 

对于分数平均情况：```
2 1 3
1 3
```整个段有总和`4`和长度`2`，给出平均值`2`。 变换后的数组为`c = 1`是`[0, 2]`，因此前缀比较将整个段识别为有效。 上限通过`c = 3`不会删除它，因为其变换后的总和为负。 

对于所有相等的值：```
5 10 10
10 10 10 10 10
```每个可能的子数组都有平均值`10`。 第一遍计算全部`15`子数组，第二遍计数为零，因为没有段的平均值大于`10`。 最终答案依然存在`15`，这证实了平等被正确处理。
