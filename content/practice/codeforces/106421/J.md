 ## 解决方案
 ## 问题理解

 我们有一组房屋，每栋房屋都有一个整数值。 我们需要在所有房屋之间建立一个连接的网络，准确地使用`n - 1`桥，意味着最终的结构是生成树。 

爱丽丝为两座房子之间的每一个可能的桥分配一个等于两个数字的最大公约数的值。 她的目标是选择桥接值之和最大的生成树。 

鲍勃使用不同的分数。 桥的值是两个数字的平方的gcd，即原始gcd的平方。 他想要一棵生成树，其中最弱的桥尽可能坚固。 换句话说，他想要最大化所选树中的最小边值。 

输入给出每栋房子的编号。 输出要求 Alice 的最大总分和 Bob 的最大可能最低分。 

房屋数量可达`200000`，而值可以大到`1000000`。 对所有房屋对的二次方法将需要大约`4 * 10^10`比较，这是不可能的。 即使生成每个可能的桥也太昂贵，因此解决方案必须利用 gcd 仅取决于整除性这一事实。 的最大值范围`10^6`表明迭代除数和倍数是预期的方向。 

有少数情况很容易处理不当。 如果所有数字都相等，则每个桥具有相同的 gcd，并且答案应使用该值。 例如，输入`3`有价值观`5 5 5`给出输出`10 25`因为爱丽丝得到了重量的两个边缘`5`鲍勃可以让每条边都有价值`25`。 仅查找具有不同值的对的粗心实现可能会在这里失败。 

另一个棘手的情况是只有一小群人共享一个大因素。 用于输入`4`有价值观`6 10 15 7`，最好的Alice树不能使用gcd`5`或者`3`对于所有边，因为顶点`7`已与该组断开连接。 答案是`3 1`。 简单地选择任何对中出现的最大公约数的方法会错误地高估结果。 

最后的边缘情况是最佳瓶颈值为`1`。 用于输入`3`有价值观`2 3 5`, 每对都有 gcd`1`，所以鲍勃的答案是`1`。 仅查看重复的质因数会忽略通过 gcd 仍然始终存在连通树`1`。 

## 方法

 解决 Alice 部分的强力方法是将问题视为最大生成树问题。 我们可以创建一个完整的图，其中每对房屋都有一条由其 gcd 加权的边，然后按降序运行 Kruskal 算法。 这是正确的，因为当边从大到小处理时，克鲁斯卡尔算法总是找到最大生成树。 

问题在于图表本身。 有`n * (n - 1) / 2`可能的边缘。 和`n = 200000`，这大约是 200 亿条边。 对它们进行计算和排序远远超出了可用时间。 

关键的观察结果是 gcd 值`d`只出现在全部能被整除的数字之间`d`。 而不是问哪些对有gcd`d`，我们可以询问哪些房屋是以下的倍数`d`。 当处理值从大到小时，所有 gcd 至少为当前值的桥都已被考虑。 连接当前除数的所有倍数模拟添加该权重的所有边，而无需显式创建它们。 

对于固定除数`d`，所有房屋都可以整除`d`组成一个小组。 如果我们将它们全部连接到一个代表，则每个成功的联合对应于一个具有权重的 Kruskal 边`d`。 成功并集的数量正是在此权重下添加的边的数量。 

鲍勃的问题使用相同的顺序，因为平方保留了顺序。 具有较大 gcd 的桥总是具有较大的平方 gcd。 在同样的下降过程中，使整个图连通的第一个除数是最大可能的最小gcd。 将该值平方即可给出鲍勃的答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n² log n²) | O(n² log n²) | O(n²) | 太慢了|
 | 最佳| O(A log A + n * 除数数(A)) | O(A + n) | 已接受 |

 这里`A`是最大可能值，`1000000`在这个问题中。 

## 算法演练

 1. 计算每个值出现的次数并存储具有每个值的房屋的索引。 我们需要实际的指数，因为联合查找结构适用于房屋，而不是价值。 
2. 处理每个除数`d`从`1000000`下降到`1`。 对于每一个倍数`d`，访问所有价值等于该倍数的房屋。 所有这些房子都由边连接，其 gcd 至少为`d`。 
3. 在访问过的房屋中选择一栋有代表性的房屋，并将所有其他访问过的房屋与其合并。 每一次成功的联合都意味着我们增加了一座价值桥梁`d`在克鲁斯卡尔的过程中，所以添加`d`爱丽丝的回答。 
4. 完成除数的所有并集后，检查所有房屋现在是否都在一个组件中。 发生这种情况的第一个除数是 Bob 的最大可能最小 gcd。 存储它的正方形。 
5. 打印Alice的累计值和Bob的存储值。 

该算法背后的不变量是在处理除数之前`d`，并集查找结构准确地表示了所有 gcd 大于的桥所创建的连接`d`。 当我们合并所有的倍数时`d`，我们添加每个可能有 gcd 的连接`d`。 这与 Kruskal 的排序相匹配，因此每次成功的合并都恰好贡献了最大生成树中的一个选定边。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    MAXV = max(a)

    buckets = [[] for _ in range(MAXV + 1)]
    for i, x in enumerate(a):
        buckets[x].append(i)

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    components = n

    def union(x, y):
        nonlocal components
        x = find(x)
        y = find(y)
        if x == y:
            return False
        if size[x] < size[y]:
            x, y = y, x
        parent[y] = x
        size[x] += size[y]
        components -= 1
        return True

    ans_a = 0
    ans_b = 1

    for d in range(MAXV, 0, -1):
        rep = -1
        for m in range(d, MAXV + 1, d):
            for v in buckets[m]:
                if rep == -1:
                    rep = v
                else:
                    if union(rep, v):
                        ans_a += d
        if components == 1:
            ans_b = d * d
            break

    print(ans_a, ans_b)

if __name__ == "__main__":
    solve()
```Buckets 数组按房屋的值对房屋进行分组。 这避免了在检查除数时重复扫描所有房屋。 总访问次数与每个值的除数数量相关，最高可达 100 万的值仍然可以管理。 

并集查找操作是 Kruskal 模拟的核心。 路径压缩和按大小合并使每个操作的时间几乎恒定。 变量`components`一旦图形连接起来，我们就可以立即检测鲍勃的答案。 

循环向下，因为最大生成树需要首先处理大的边权重。 如果它向上，较小的 gcd 值将已经连接组件，并且对 Alice 答案的贡献将是错误的。 

Bob 的值存储为`d * d`因为桥牌分数是平方的gcd，等于原gcd的平方。

 ## 边缘情况

 当所有值都相同时，每个房屋都可以通过相同的 gcd 连接。 用于输入`3`和价值观`5 5 5`，算法处理除数`5`，立即合并所有房屋，增加两条边的权重`5`，并将鲍勃的答案设置为`25`。 

当大除数仅出现在图的部分区域时，它不可能是最终瓶颈。 用于输入`4`有价值观`6 10 15 7`, 除数`5`仅连接`10`和`15`, 和除数`3`仅连接`6`和`15`。 连接每个人的第一个除数是`1`，所以鲍勃的答案是`1`。 

当每对都有 gcd 时`1`，下降过程达到除数`1`并在那里合并整个图。 用于输入`3`有价值观`2 3 5`, Alice 收到两条边的值`1`鲍勃收到`1`，这自然由最终除数检查来处理。
