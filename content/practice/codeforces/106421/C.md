 ## 解决方案
 ## 问题理解

 我们有两支有序的赛车队。 每个团队都有一个声望级别列表，我们需要通过从两个列表中选取赛车手来建立一个团队，同时保持每个团队内部的原始顺序。 输出不是合并的声望序列本身，而是创建它的选择：每个角色告诉下一个赛车手是来自 A 队还是 B 队。 

目标是使最终的声望序列按字典顺序最小。 由于较小的声望数字意味着更有声望的赛车手，因此当尽早放置较小的数字时，序列被认为更好。 

简单版本有`k = n + m`，每个赛车手都有独特的声望等级。 这种独特性是关键的约束。 参赛者总数可以达到`400000`，因此重复扫描剩余赛车或尝试所有可能的交错的算法将执行太多操作。 我们需要一个线性解决方案，其中每个赛车手仅被处理恒定的次数。 

一个常见的错误是考虑未来的立场而不是当前的选择。 例如，考虑：```
n = 2, m = 2
A = [1, 4]
B = [2, 3]
```正确的输出是：```
AABB
```因为合并后的序列变成`[1,2,3,4]`。 因为看到 B 还剩下两个小值而从 B 中选择的策略已经失败了，因为第一个元素将变成`2`而不是`1`。 

另一个边缘情况是当一支球队的赛车手用完时：```
n = 2, m = 1
A = [2, 3]
B = [1]
```正确的输出是：```
BAA
```服用后`1`B队只剩下A队了。 假设两个当前位置始终存在的粗心实现可能会访问无效索引或无法附加剩余的赛车手。 

最后一个重要的情况已经由约束处理，但它解释了为什么简单版本更简单：```
n = 2, m = 2
A = [1, 2]
B = [1, 3]
```如果允许重复的声望级别，仅比较当前的赛车手并不总是能做出正确的决定，因为相等的值需要更深入地研究剩余的后缀。 简单版本消除了这个问题，因为每个声望级别只出现一次。 

## 方法

 蛮力方法是生成两支球队的每一种可能的有效交错，计算所得的声望序列，并保留字典顺序上最小的一个。 这是正确的，因为它直接检查每个可能的答案。 然而，交错的数量是巨大的。 选择哪个`n`位置属于A队`n+m`位置给出`C(n+m,n)`的可能性。 即使对于几十名赛车手来说，这也是不可能的，而对于数十万赛车手来说，这也是遥不可及的。 

简单版本的结构提供了更简单的方法。 在任何时候，合并团队中的下一位赛车手必须是 A 队的当前赛车手或 B 队的当前赛车手。由于所有声望级别都是不同的，因此这两个值不能相等。 必须选择较小的一个，因为两个可能答案不同的第一个位置决定了哪个序列按字典顺序更小。 

蛮力方法之所以有效，是因为它探索了每一个选择，但却失败了，因为选择空间呈指数增长。 第一个不同的位置完全决定了比较的观察结果让我们贪婪地做出每个决定并立即放弃所有更糟糕的选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n+m,n) * (n+m)) | O(C(n+m,n) * (n+m)) | O(n+m) | 太慢了|
 | 最佳| O(n+m) | 除了输出 | O(1) 已接受 |

 ## 算法演练

 1. 保留两个指针，一个指向 A 队中下一个未使用的赛车手，一个指向 B 队中下一个未使用的赛车手。 
2. 虽然两支球队仍然都有可用的赛车手，但比较两支球队目前的声望水平。 附加`A`如果 A 队的赛车手的值较小，则附加`B`。 这使得体型最小的赛车手处于最早的未定位置。 
3. 当一队没有剩余选手时，追加另一队剩余的选择。 不再需要做出决定，因为所有剩余的赛车手都必须出现。 
4. 打印构建的序列`A`和`B`人物。 

为什么有效：在答案中的每个位置，唯一可能的下一个元素是当前的两名赛车手。 如果我们选择较大的一个，则替代序列在该精确位置立即具有较小的值，因此我们的选择不能是字典顺序上最小的。 因为每个选择都保留了两个团队的原始顺序，所以重复做出最小的可用选择会产生全局最小的有效合并。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    i = 0
    j = 0
    ans = []

    while i < n and j < m:
        if a[i] < b[j]:
            ans.append('A')
            i += 1
        else:
            ans.append('B')
            j += 1

    while i < n:
        ans.append('A')
        i += 1

    while j < m:
        ans.append('B')
        j += 1

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```代码直接遵循贪心过程。 变量`i`和`j`始终参考各自团队中下一个未使用的赛车手。 第一个循环处理唯一有趣的情况，其中两种选择都可用。 

第二个和第三个循环是分开的，因为一侧耗尽后，无需执行比较。 这也避免了尝试访问时出现的边界错误`a[i]`或者`b[j]`到达列表末尾后。 

的价值`k`被读取是因为它属于输入格式，但在easy版本中不需要。 事实是`k = n + m`保证所有声望值都是唯一的，这正是贪婪比较所使用的属性。 

## 工作示例

 考虑：```
3 2 5
1 4 5
2 3
```踪迹是：

 | 步骤| A队指针| B 队指针 | 当前A | 当前 B | 选择| 回答 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | 0 | 0 | 1 | 2 | 一个 | 一个 |
 | 2 | 1 | 0 | 4 | 2 | 乙| AB |
 | 3 | 1 | 1 | 4 | 3 | 乙| ABB|
 | 4 | 1 | 2 | 4 | 无 | 一个 | 阿巴 |
 | 5 | 2 | 2 | 5 | 无 | 一个 | 阿巴 |

 结果是`ABBAA`，创建合并的声望序列`[1,2,3,4,5]`。 这表明，一旦一侧为空，答案的其余部分就会被强制。 

另一个例子：```
2 3 5
2 5
1 3 4
```踪迹是：

 | 步骤| A队指针| B 队指针 | 当前A | 当前 B | 选择| 回答 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | 0 | 0 | 2 | 1 | 乙| 乙|
 | 2 | 0 | 1 | 2 | 3 | 一个 | 学士 |

 | 4 | 1 | 2 | 5 | 4 | 乙| 巴布 |
 | 5 | 1 | 3 | 5 | 无 | 一个 | 巴巴|

 输出是`BABBA`。 该算法总是选择当前可用的最小声望级别，产生`[1,2,3,4,5]`。

 ## 边缘情况

 对于第一个边缘情况：```
2 2 4
1 4
2 3
```算法比较`1`和`2`，选择`A`，然后比较`4`和`2`，选择`B`，然后比较`4`和`3`，选择`B`，最后附加剩余的`A`。 输出是`ABBA`。 贪心的决定是正确的，因为选择`B`首先将使合并序列开始于`2`，这比开始时更糟糕`1`。 

对于精疲力尽的团队情况：```
2 1 3
2 3
1
```第一个比较选择`B`因为`1`小于`2`。 B 队此时已空，因此算法将添加 A 队剩余的两名赛车手。 输出是`BAA`，合并后的序列为`[1,2,3]`。 

对于较难版本中出现的重复值情况：```
2 2 3
1 2
1 3
```仅比较当前值是不够的，因为两个选择都以`1`。 简单版本避免了这种歧义，因为所有值都是唯一的，仅允许当前比较来确定正确的决策。
