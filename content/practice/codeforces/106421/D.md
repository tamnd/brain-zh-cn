 ## 解决方案
 ## 问题理解

 该问题给出了两个长度相等的字符串。 第一个字符串是我们可以修改的字符串，第二个字符串描述了我们最终需要的多组字符。 我们可以替换第一个字符串中的字符，其中一次替换将一个位置精确地更改为任何其他字符。 在使用最少的替换次数使第一个字符串成为目标字符串的变位词的所有方法中，我们必须输出按字典顺序最小的结果字符串。 

输入大小很大：字符串最多可以包含$10^5$人物。 这立即排除了尝试排列、生成字谜词或比较每个可能的转换字符串。 任何解决方案都必须以每个字符的少量恒定工作量来处理字符串，这指向线性或接近线性的复杂性。 

关键的边缘情况来自“相同字母”和“相同位置”之间的差异。 例如，如果输入是：```
ABA
CBA
```答案是：```
1
ABC
```粗心的解决方案可能只会按位置计算不匹配并产生`CBA`更换一次后。 这不符合字典顺序的要求。 最终的字符串可以重新排列目标字母，因此我们应该保留尽可能多的有用的现有字符，然后选择尽可能小的排列。 

另一个棘手的情况是当有重复的字母时：```
AAAA
AAAB
```正确的输出是：```
1
AAAB
```将每个字符视为唯一的解决方案可能会认为需要三个替换，因为字符串在多个位置不同。 正确的方法是比较频率。 

最后一种边缘情况是字符串已经是字谜词时：```
BCA
ABC
```答案是：```
0
ABC
```不需要替换，但我们仍然需要将现有字符重新排序为字典顺序上尽可能小的字谜。 

## 方法

 蛮力方法是尝试目标字符串的所有可能的字谜，检查有多少位置与源字符串不同，并保留最佳候选。 这是正确的，因为它检查了每一种可能的最终安排。 问题是一个长度的字符串$n$最多可以有$n!$排列。 即使对于几十个字符，这也是不可能的，并且$10^5$字符它远不接近可行。 

更好的方向来自于观察替代品的实际作用。 原始字符串中的每个位置可以保留其字符，也可以更改。 为了尽量减少替换，我们希望保留尽可能多的现有字符。 这意味着我们只需要知道两个字符串中每个字母存在多少个副本。 

假设源有五个副本`A`并且目标需要三份。 其中两个`A`字符是额外的，必须更改。 另一方面，如果目标需要更多`A`字符比源有，我们需要替换来创建丢失的副本。 替换总数正好是频率无法匹配的字符数。 

在知道最小替换次数后，我们仍然需要字典顺序最小的最终字符串。 尽可能小的字符应该尽早出现。 我们可以从左到右贪婪地扫描位置。 在每个位置，如果当前字符可以保留，同时仍然满足剩余频率要求，我们保留它。 否则我们用最小的可用字符替换它。 

这种贪婪选择起作用的原因是字典顺序是由两个字符串不同的第一个位置决定的。 使最早的位置尽可能小总是主导任何后续的改进。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳| O(26n) | O(26n) | O(26) | 已接受 |

 ## 算法演练

 1. 统计源字符串和目标字符串中每个字符的出现频率。 字母表是固定的，所以我们只需要一个大小为 26 的数组。 
2. 计算可以保留源中的多少个字符。 对于每个字母，可用副本的数量是其在源和目标中出现频率的最小值。 来自源头的其他一切最终都必须被替换。 
3. 从左到右扫描源字符串。 保留仍必须出现在答案中的剩余字符数。 在看当前位置时，首先尽量保持其原有的性格。 
4. 仅当目标中可用字符的副本数量仍多于答案中已固定的数量时，保留该字符才有效。 如果不再需要该角色，请将其替换。 
5. 如果当前字符无法保留，则选择剩余目标计数为正数的最小字母放置到该位置。 减少其剩余计数。 

为什么它有效：该算法总是尽可能保留一个字符，因此替换的数量不能超过必要的数量。 一旦我们决定替换一个位置，选择最小的可用字符就会给出尽可能小的前缀。 由于在考虑后面的位置之前对每个较早的位置进行优化，因此最终的字符串是所有最佳答案中按字典顺序排列的最小字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    src = [0] * 26
    need = [0] * 26

    for c in s:
        src[ord(c) - 65] += 1
    for c in t:
        need[ord(c) - 65] += 1

    keep = [min(src[i], need[i]) for i in range(26)]

    ans = []
    remain = need[:]

    for c in s:
        x = ord(c) - 65
        if keep[x] > 0:
            ans.append(c)
            keep[x] -= 1
            remain[x] -= 1
        else:
            for y in range(26):
                if remain[y] > 0:
                    ans.append(chr(y + 65))
                    remain[y] -= 1
                    break

    print(sum(1 for i in range(len(s)) if s[i] != ans[i]))
    print("".join(ans))

if __name__ == "__main__":
    solve()
```第一部分构建频率表。 由于只有 26 个大写字母，因此每个字符的计数需要持续不断的工作。 

这`keep`数组存储我们可以保留每个字符的多少个副本。 在从左到右的构造过程中，保留的字符消耗一个可用的保留副本和一个所需的目标副本。 

替换分支搜索自`A`到`Z`。 搜索仅超过 26 个字母，因此即使它嵌套在主循环内，总复杂度仍保持线性。 最后通过将原始字符串与构造的答案进行比较来计算替换计数。 

边界条件自然得到处理。 如果某个字符已经正确且需要，则保留该字符。 如果角色的所有副本都已被使用，则永远不会再次选择该角色。 不存在产生过多副本的风险，因为每次放置都会降低剩余的目标频率。 

## 工作示例

 考虑：```
ABA
CBA
```频率表明`A`和`B`可以保留，同时`C`必须被创建。 

| 职位| 当前角色 | 保留？ | 剩余目标 |
 | ---| ---| ---| ---|
 | 1 | 一个 | 是的 | 乙：1，丙：1 |
 | 2 | 乙| 是的 | C：1 |
 | 3 | 一个 | 没有 | C：1 |

 最后的位置不能保留为`A`因为目标没有多余的`A`。 最小的可用字符是`C`。 

结果是：```
ABC
```仅需一名更换。 

另一个例子：```
CDBABC
ADCABD
```首先保留有用的字符。 

| 职位| 当前角色 | 行动| 答案前缀 |
 | ---| ---| ---| ---|
 | 1 | C | 替换为 A | 一个 |
 | 2 | d | 保留| 广告 |
 | 3 | 乙| 保留| 亚行 |
 | 4 | 一个 | 保留| 阿德巴 |
 | 5 | 乙| 保留| 阿德巴布 |
 | 6 | C | 保留| 亚行ABC |

 该结构保留了尽可能多的字符，并使第一个不同的位置尽可能小。

 ## 边缘情况

 对于这个案例：```
ABA
CBA
```算法保持`A`和`B`因为它们是目标所需要的。 在最后一个位置，剩余的目标频率仅包含`C`，所以强制替换。 结果的更改数量尽可能最少，并且按字典顺序排列也是最小的。 

为了：```
AAAA
AAAB
```来源太多了`A`人物。 前三个位置可以保留为`A`，但最后的额外`A`必须成为`B`。 频率数组可防止算法保留导致目标无法满足的特征。 

为了：```
BCA
ABC
```所有字母均已达到所需数量。 不执行任何替换，贪婪构造保留可用字符，同时产生尽可能小的排序。 最终答案变成`ABC`零操作。
