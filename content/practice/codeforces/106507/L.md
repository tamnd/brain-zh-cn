 ## 解决方案
 ## 问题理解

 任务是重建一系列范围添加。 我们从一个零数组开始。 一个操作选择一个连续的段，并将该段内的每个元素加一。 经过一些未知数量的此类操作后，我们得到了最终的数组，并且必须输出可能产生该数组的最小操作数以及所使用的段。 

关键对象不是数组值本身，而是值在相邻位置之间如何变化。 对于数组`a`，定义差异数组：`d[i] = a[i] - a[i - 1]`和`a[0] = 0`，并添加一个虚拟元素`a[n + 1] = 0`所以最后一个差异被包括在内。 对段的单个操作`[l, r]`通过添加来更改此差异数组`1`在位置`l`并减去`1`在位置`r + 1`。 换句话说，每个操作都会在差异数组中创建一个正变化和一个负变化。 

输入长度可以大到`100000`。 任何重复模拟对数组应用操作或搜索可能的段的方法都会太慢，因为它可能需要二次工作。 我们需要线性或近线性的结构。 

一些边缘情况很容易被忽略。 如果整个数组具有相同的正值，例如：```
3
2 2 2
```答案不是对单个元素进行三个操作。 正确答案是一项操作：```
1
1 3
```因为一个段覆盖了整个数组。 

另一个棘手的情况是数组中有零时：```
5
1 0 1 0 1
```正确答案是三个操作：```
3
1 1
3 3
5 5
```如果粗心的解决方案试图将每个正值段延伸到下一个更大的值，则可能会意外覆盖必须保持为零的位置。 

第三种边界情况是数组的末尾：```
4
1 1 1 1
```正确答案是一项操作：```
1
1 4
```最后减回零发生在数组之后，所以虚拟位置`n + 1`必须处理。 忽略它会留下不匹配的增量。 

## 方法

 一种直接的方法是考虑每个可能的段并重复应用增量，直到达到目标数组。 这是正确的，因为每个操作都可以被精确地模拟，但它没有给出有用的结构。 在最坏的情况下，数组的长度`100000`周围的价值观`100000`可能需要数十亿个单独的元素更新，这远远超出了可用时间。 

有用的观察来自于观察差异。 每个范围增量从一个位置开始，并在另一个位置后立即停止影响数组。 这意味着差异数组唯一发生变化的地方是开始和结束边界。 

假设差异数组具有正值`d[i] = 3`。 这意味着另外三个段需要从位置开始`i`比结束那里。 同样，负值意味着许多活动段必须在该位置之前完成。 最少的操作次数恰好是正差值的总数，因为每一次操作只能贡献一个起点。 

构造简单。 从左到右扫描。 每当出现积极的差异时，就创建许多新的段开始。 每当出现负差异时，关闭许多当前打开的段。 前缀差异之和始终是当前数组值，因此它永远不会为负。 因此，我们总是有足够的开放段来关闭。 

暴力方法尝试通过修改数组来发现段。 最佳方法直接从段的边界发现相同的信息。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(操作数 × n) | O(1) | O(1) | 太慢了|
 | 最佳| O(n + 答案) | O（答案）| 已接受 |

 ## 算法演练

 1. 计算差值数组。 将第一个位置之前的元素和最后一个位置之后的元素视为零。 这使得每个范围操作恰好对应于一个正边界和一个负边界。 
2. 从左到右扫描差异数组。 什么时候`d[i]`为正，则添加`d[i]`职位副本`i`到当前打开的段开始列表。 这些是必须从这里开始的操作。 
3. 什么时候`d[i]`为负数，删除`-d[i]`从列表开始，并将每个删除的开始与结束位置配对`i - 1`。 该对表示的操作是从该开始到`i - 1`。 
4. 输出所有生成的段。 段的数量是差值数组中正贡献的数量，这是最小的。 

这种构造是最佳的原因是每个操作都必须在差异数组中恰好创建一个正边界。 如果总的正差是`x`，没有解决方案可以使用少于`x`运营。 该算法准确地创建了`x`操作，因此达到下限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    diff = []
    prev = 0
    for x in a:
        diff.append(x - prev)
        prev = x
    diff.append(-prev)

    starts = []
    ans = []

    for i, x in enumerate(diff, start=1):
        if x > 0:
            for _ in range(x):
                starts.append(i)
        elif x < 0:
            for _ in range(-x):
                l = starts.pop()
                ans.append((l, i - 1))

    print(len(ans))
    for l, r in ans:
        print(l, r)

if __name__ == "__main__":
    solve()
```第一部分构建差异数组。 额外的最终值`-prev`表示从最后一个元素回到零的过渡。 如果没有这个位置，到达数组末尾的段将永远不会被关闭。 

这`starts`list 存储段已开始但尚未结束的位置。 当发现负差时，代码将准确弹出所需的启动次数。 任何顺序都有效，因为操作是独立的，因此使用最近的启动是一个方便的实施选择。 

输出计数自动最小，因为每个存储的开始都对应于一个不可避免的操作。 施工过程中没有添加额外的操作。 

指数使用`enumerate(..., start=1)`因为该问题使用基于一的索引。 正确的端点是`i - 1`，因为位置的负差`i`表示该段在该位置之前立即停止。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + 答案) | 每个数组位置都会处理一次，并且每个生成的段都会创建和关闭一次。 |

 ## 边缘情况

 对于常数正数组：```
3
2 2 2
```差异数组为：`[2, 0, 0, -2]`该算法在位置打开两个段`1`，然后在虚拟结束位置关闭两者`4`。 输出是两个副本`[1,3]`。 需要进行两次操作，因为每次操作只能贡献一个高度单位。 

对于包含零间隙的数组：```
5
1 0 1 0 1
```差异在正值和负值之间交替变化。 每个正差异都会打开一个段，而接下来的负差异会立即关闭它。 生成的操作正是单元素段`[1,1]`,`[3,3]`， 和`[5,5]`。 

对于以正值结尾的数组：```
4
1 1 1 1
```差异数组为：`[1,0,0,0,-1]`最后一个负值来自数组后面的虚拟零。 该算法保持段打开直到该点并输出`[1,4]`，正确处理右边界。
