 ## 解决方案
 ## 问题理解

 我们有一个`n x n`细胞板。 每个单元格要么处于活动状态（`1`) 或被阻止 (`0`）。 允许在侧相邻小区之间移动，并且只能访问活动小区。 每次更新后，一个单元格都会改变状态，我们必须决定左上角的单元格是否仍然可以到达右下角的单元格。 

困难不仅仅在于动态更新。 输入查询使用之前的答案进行加密。 输入中给出的坐标根据最后一个进行移动`num`答案，因此我们无法重新排序查询或离线处理它们。 在知道确切的下一次更新之前，我们必须回答每个状态。 

棋盘尺寸足够大，存储具有 400 万个顶点的图已经很昂贵，但更新次数只有 2000。这意味着每次更新后的全图算法太慢，而仔细优化的遍历可以工作。 朴素的 BFS 触及一切`n^2`每次查询后的单元格，给出`O(qn^2)`，在最大限制下约为 80 亿个小区访问。 

重要的边缘情况是断开唯一可能的走廊的单元以及起始或结束单元被阻塞的情况。 例如：```
1
0
1 1
0 0
```翻转后，唯一的单元格变得活跃，所以答案是`YES`。 仅检查邻居而不处理单单元网格情况的实现将会失败。 

另一种情况是：```
2
11
10
1 1
0 0
```右下角的单元格最初被阻止，因此在任何不相关的翻转之后，答案必须保留`NO`直到该单元格变得活跃。 仅跟踪起始区域是否扩展的代码可能会意外报告成功而不检查目标。 

## 方法

 最简单的解决方案是运行 BFS`(1,1)`每次翻转后。 很容易证明它是正确的，因为 BFS 精确地计算了起始单元的连通分量。 问题在于重复工作量。 和`q = 2000`和`n = 2000`，最坏情况的表现约为`2000 * 2000 * 2000 = 8 * 10^9`细胞检查。 

改变问题的观察是，网格的大小是固定的，行数只有 2000。我们不是将单个单元格存储在 BFS 队列中，而是将当前可达区域的每一行存储为一个位集。 Python 整数的行为已经类似于紧凑的位数组，因此水平扩展变成了一些位操作。 每个 BFS 层使用整数移位一次处理所有行。 

优化后的方法仍然执行图遍历，但常数因子要小得多。 一行 2000 个单元格由一个整数表示，整个洪水填充大约需要`n`每层的整数运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力 BFS |`O(q * n^2)`|`O(n^2)`| 太慢了|
 | 比特集 BFS |`O(q * n * d)`在哪里`d`是扩展轮数 |`O(n)`| 接受给定的限制 |

 ## 算法演练

 1. 将每个网格行存储为整数位掩码。 少量`j`行数`i`告诉细胞是否`(i, j)`是活跃的。 
2. 使用之前的答案解码当前查询。 最后一个`num`答案保存为二进制值，其中`YES`代表为`1`。 
3. 通过切换相应行整数中的位来翻转已解码的单元。 
4. 使用位集运行洪水填充。 保留一个数组`reach`， 在哪里`reach[i]`包含行中可到达的所有列`i`。 
5. 开始时只`(0, 0)`如果该单元格处于活动状态，则可以访问。 
6. 重复展开每一行。 可能的新单元格来自上一行、下一行以及左移和右移的同一行。 将结果与该行的活动单元格相交。 
7. 当迭代没有产生新的可达单元时停止。 当最后一行包含最后一位时，就可以到达目的地。 

为什么它有效：

 不变的是，在每轮扩展之后，`reach`仅包含使用长度最多为当前轮数的路径从一开始即可到达的单元格。 使用四个可能的方向进行扩展会添加每个有效的下一步，并且与网格相交会删除阻塞的单元格。 当没有新的单元出现时，可达组件就完成了，因此检查目标位会给出正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = []
    for _ in range(n):
        s = input().strip()
        mask = 0
        for i, c in enumerate(s):
            if c == '1':
                mask |= 1 << i
        grid.append(mask)

    q, num = map(int, input().split())

    decode = []
    for _ in range(1 << num):
        u, v = map(int, input().split())
        decode.append((u, v))

    ans_bits = 0
    answers = []
    last_mask = (1 << num) - 1

    def reachable():
        if (grid[0] & 1) == 0:
            return False

        reach = [0] * n
        reach[0] = 1

        while True:
            changed = False
            nxt = [0] * n

            for i in range(n):
                cur = reach[i]

                if i:
                    cur |= reach[i - 1]
                if i + 1 < n:
                    cur |= reach[i + 1]

                cur |= (reach[i] << 1)
                cur |= (reach[i] >> 1)

                cur &= grid[i]

                nxt[i] = cur
                if cur != reach[i]:
                    changed = True

            reach = nxt

            if not changed:
                return (reach[n - 1] >> (n - 1)) & 1 == 1

    out = []

    for _ in range(q):
        x, y = map(int, input().split())

        val = ans_bits
        ux, vy = decode[val]

        x += ux
        y += vy

        if x > n:
            x -= n
        if y > n:
            y -= n

        x -= 1
        y -= 1

        grid[x] ^= 1 << y

        ok = reachable()

        if ok:
            out.append("YES")
            bit = 1
        else:
            out.append("NO")
            bit = 0

        ans_bits = ((ans_bits << 1) | bit) & last_mask

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```网格表示是第一个重要的实现细节。 使用字符串会使每次更新和每次遍历都变得昂贵，而整数位掩码让 Python 在本机整数算术中执行许多单元操作。 

解码步骤只保留最后一个`num`答案。 掩码操作删除较旧的位，与语句的滚动二进制表示相匹配。 

洪水填充故意创造了一个新的`n`每轮的元素数组。 这避免了将当前轮中发现的单元与之前存在的单元混合，这会破坏 BFS 式不变量。 

目的地检查使用从零开始的坐标，因此最终的单元格是位`n-1`在行中`n-1`。 这是差一错误的常见来源。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(q * n * d)`| 每个扩展轮使用位操作处理每一行|

 ## 边缘情况

 当`n = 1`，算法用唯一的单元格初始化可达掩码。 最终的目的地检查读取相同的位，因此答案自然变成该单元是否处于活动状态。 

当目的地被阻塞时，最终位置的位永远不会插入到`reach`，因为每个扩展步骤都被活性细胞掩盖。 因此最终检查返回`NO`。 

当翻转删除两个大区域之间的唯一连接时，下一个洪水填充将从头开始重新计算可到达的组件。 它不依赖于以前的连接信息，因此删除后无法保留过时的路径。
