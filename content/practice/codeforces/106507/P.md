 ## 解决方案
 ## 问题理解

 我们得到了一系列塔的高度。 想象一下，每次我们遇到严格大于所有先前值的新最大值时，从左侧扫描并记录。 这些记录的值形成一个序列`L(h)`。 如果我们从右侧进行相同的扫描，我们会得到另一个序列`R(h)`由从右向左遍历时的新最大值组成。 

例如，在一个序列中，`L(h)`捕捉“左侧天际线”`R(h)`捕捉“正确的天际线”。 

任务不是计算这些天际线。 相反，我们必须计算原始数组有多少个子序列产生与完整数组完全相同的两个天际线集。 

子序列是通过删除元素同时保持顺序而形成的。 如果两个子序列使用不同的索引，即使结果值相同，它们也是不同的。 

因此，约束是结构性的：删除元素后，子序列必须保留左侧和右侧的极值可见性模式，与原始序列完全相同。 

这些约束意味着答案必须在测试用例中最多 3×10^5 个总元素上计算，因此任何枚举子序列甚至处理每个元素选择对的解决方案都是不可能的。 单个测试用例中的任何二次方都已经立即失败。 

隐藏的困难是条件不是本地的。 删除一个元素可以从两个方向改变未来的“历史新高”，因此天真的贪婪删除会默默地失败。 

一些具体的故障模式有助于说明这一点。 

如果我们采取`[1, 3, 2]`，左侧天际线是`{1, 3}`。 去除`2`保持天际线不变。 但在`[1, 2, 3]`，去除`2`没有任何改变。 然而在`[3, 1, 2]`，去除`1`更改哪些元素从右侧变为可见最大值。 像“可以删除非最大元素”这样的天真的规则会失败，因为“非最大”取决于方向。 

另一个微妙的情况是重复值。 在`[2, 2, 2]`，只有第一个`2`有助于`L`，但是删除或保留重复项的子序列可能会也可能不会保留相等条件，具体取决于严格最大值比较中关系的解释方式。 将相等的值视为可互换的粗心解决方案会破坏正确性。 

## 方法

 蛮力的想法很简单：枚举每个子序列，计算其左右可见最大值集，将它们与原始数组进行比较，并计算匹配项。 

对于长度的数组`n`， 有`2^n`子序列。 对于每个子序列，计算`L`和`R`成本`O(n)`在最坏的情况下。 这导致`O(n·2^n)`操作，这甚至是不可能的`n = 30`。 

关键的观察是`L(h)`和`R(h)`仅取决于破纪录最大值的位置，而不取决于中间值。 一旦我们修复了原始数组的全局最大值结构，任何有效的子序列都必须保留从两端扫描时新最大值出现的确切位置。 

这将问题变成了组合计数任务：在原始数组中的连续“临界最大值”之间，除了排序约束之外，元素是不相关的，并且每个这样的元素都可以被包含或排除，而不会影响可见性，只要它不在任一方向上引入新的最大值即可。 

这种结构导致分解，其中每个非关键元素贡献二元选择，但仅在周围最大间隔定义的约束下进行。 该解决方案简化为在连续的左/右最大边界之间对元素进行分组，并将每个段的独立贡献相乘，并仔细处理元素受到两个方向约束的重叠。 

最终结果成为全局最大骨架下分段计数的乘积，这就是为什么可以在每个测试用例的线性时间内评估解决方案的原因。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们根据原始数组的左右记录最大值重建其结构。 

1. 计算`Lmax`作为从左到右扫描时显示为新最大值的值序列。 这些是数组的“左可见锚”。 

这些元素被迫出现在任何有效的子序列中，因为删除它们会立即改变`L`。 
2. 计算`Rmax`类似地，从右向左扫描。 这些就是“右眼可见的锚”。 
3. 标记数组中属于任一索引的每个索引`Lmax`或者`Rmax`作为关键位置。 这些元素构成了任何有效子序列的主干，因为它们定义了我们必须保留的确切天际线结构。 
4. 将数组分成连续关键位置之间的段。 在每个分段内，所有元素都严格受到两侧相邻最大值的限制，这意味着它们不能影响任何天际线，除非它们成为新记录，这是被禁止的。 
5. 对于每个路段，计算在不违反天际线约束的情况下可以独立选择多少个元素。 每个这样的元素实际上都是可选的，贡献因子为 2，因为包含或排除它不会更改任何前缀或后缀最大值。 
6. 将所有部分的贡献乘以 998244353 模。 

### 为什么它有效

 不变的是任何有效子序列的前缀最大值和后缀最大值的集合必须与原始数组的前缀最大值和后缀最大值的集合完全匹配。 这迫使所有破纪录的元素仍然存在，因为删除其中任何一个都会改变引入时看到的最大值。 

一旦这些锚点被固定，每个其他元素都严格低于至少一个相邻的边界最大值，这意味着无论包含如何，它都不能在任一方向上引入新记录。 因此，它的包含仅影响多样性，而不影响可见性结构。 

由于分段由固定最大值分隔，因此不同分段内的选择不会相互作用，这使得最终计数在分段之间相乘。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # compute left maxima
        left_max = [False] * n
        cur = -1
        for i in range(n):
            if a[i] > cur:
                left_max[i] = True
                cur = a[i]

        # compute right maxima
        right_max = [False] * n
        cur = -1
        for i in range(n - 1, -1, -1):
            if a[i] > cur:
                right_max[i] = True
                cur = a[i]

        critical = [left_max[i] or right_max[i] for i in range(n)]

        ans = 1
        i = 0
        while i < n:
            if critical[i]:
                i += 1
                continue

            j = i
            while j < n and not critical[j]:
                j += 1

            length = j - i
            ans = (ans * pow(2, length, MOD)) % MOD
            i = j

        print(ans)

if __name__ == "__main__":
    solve()
```该实现将阵列分为关键区域和非关键区域。 第一遍计算左右天际线约束所需的位置。 第二遍将非关键元素分组为连续的块，并对每个块乘以 2 的幂。 

唯一微妙的一点是在构建最大值时使用严格比较。 平等不会创建新的可见塔，因此只有严格更大的值才能更新天际线。

 | 1 | 3 | 4 | 是的 |
 | 2 | - | - | 没有|
 | 3 | 4 | 4 | 是的 |
 | 4 | - | - | 没有|

 我们得到两个非关键的单元素段：`[1]`和`[2]`。 

每个贡献因子都是 2，所以答案是 4。 

这证明了天际线锚点之间内部元素的独立性。 

### 示例 2

 输入：`[1, 2, 3, 2, 1]`| 步骤| 左最大值 | 右极大值 | 关键|
 | --- | --- | --- | --- |

 所有元素都很关键，因此不存在任何段。 答案是1。 

这显示了一个完全约束的数组，其中每个元素都是天际线定义的一部分。

 ## 边缘情况

 单元素数组始终是完全关键的，因为该元素同时是左和右最大值。 该算法在两次扫描中都正确地将其标记为关键，产生答案 1。 

在严格递增的数组中，每个元素都成为左最大值，因此每个位置都很关键，并且没有段提供选择。 该算法正确地生成 1，与删除任何元素发生变化的事实相匹配`L(h)`。 

在具有重复项的数组中，只有第一次出现的最大值才会对天际线结构产生影响。 因为算法使用了严格的`>`比较时，重复项不会重置最大值，确保重复值下的正确性。
