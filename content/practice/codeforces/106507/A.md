 ## 问题理解

 该任务定义了整数的简单数值转换。 对于任意整数$y$，考虑其数字之和，表示为$d(y)$。 一个数字$y$被认为与给定整数兼容$x$如果减去数字和$y$准确地产生$x$， 意义$y - d(y) = x$。 

对于每个查询值$x$，我们被要求计算有多少个整数$y$满足这个关系。 

关键的观察是$y$声明中没有明确限制在一个小范围内。 然而，与数字本身相比，数字总和的增长非常缓慢。 如果$y$有$k$数字，那么$d(y) \le 9k$， 所以$y - d(y)$非常接近$y$。 这立即意味着对于固定的$x$， 有效的$y$值必须位于上方的狭窄窗口内$x$，大致在$x + 1$到$x + 9 \cdot \text{digits}(x)$。 

这种结构至关重要：不是搜索所有整数，而是每个测试用例将候选值折叠成最多几十个值。 

一种简单的方法是从$x$并检查条件直到值变得太大。 这已经暗示了效率，但更重要的是，我们可以紧密地绑定搜索。 

一些边缘情况对于理解正确性很重要。 

一种情况是当$x = 1$。 方程变为$y - d(y) = 1$。 尝试较小的值表明不存在解决方案，因为最小可能的数字校正相对于偏移量已经太大。 例如，$y = 2$给出$2 - 2 = 0$， 和$y = 10$给出$10 - 1 = 9$，完全跳过1。 

另一个微妙的情况是当$x$很大并且以许多零结尾，例如$998244360$。 在这里，有效$y$值仍然紧密地聚集在一起，并且解决方案仅取决于在最后一位添加一位数字，这就是为什么答案通常恰好为 10。 

## 方法

 暴力解释是：对于每个$x$，尝试增加值$y$，计算数字和，并计算匹配项。 这是正确的，因为每个候选都被直接测试，但搜索空间在概念上是无限的。 

然而，函数的结构$f(y) = y - d(y)$使其几乎单调，局部偏差很小。 增加$y$增加$f(y)$，但数字进位有时会减少数字总和，从而创建小群的解决方案而不是广泛传播的解决方案。 

关键的见解是在本地反转条件。 而不是扫描全部$y$，我们表示$y$作为$x + k$，并重写方程：$$x + k - d(x + k) = x \Rightarrow k = d(x + k)$$所以偏移量$k$必须等于数字和$x + k$。 由于数字和最多为$9$乘以位数，$k$受一个相对于的小常数的限制$x$。 这意味着我们只需要测试上面的一个小范围$x$，在实践中通常最多为 100 个值。 

蛮力退化为每个测试用例的恒定大小检查，这对于大输入大小来说已经足够了。

 ## 算法演练

 我们重新表述方程，这样就不用搜索所有$y$，我们搜索上面的小偏移量$x$。 

1. 阅读$x$。 我们将候选答案视为以下形式的数字$y = x + k$。 
2. 尝试所有值$k$在一个小的固定范围内，例如从 0 到 100。 

上限来自这样一个事实：9 位数字的数字总和永远不会超过几十个。 
3. 对于每个$k$, 计算$y = x + k$。 
4. 计算数字和$d(y)$。 
5. 检查是否$y - d(y) = x$。 如果成立，则数此$y$。 
6. 输出本次的总计数$x$。 

我们只需要一个有界范围的原因是如果$k$变大，那么$d(x + k) \le 9 \cdot \text{digits}(x + k)$，呈对数增长，同时$k$线性增长。 最终平等$k = d(x+k)$变得不可能。 

### 为什么它有效

 正确性取决于任何有效的解决方案必须满足$k = d(x+k)$。 一个数的数字和$m$最多有位数$9m$， 所以$k$不能超过与数字位数相关的小常数$x$。 这保证了所有解都位于上面的一个紧凑区间内$x$，并且限制搜索不会漏掉任何有效的候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(n: int) -> int:
    s = 0
    while n:
        s += n % 10
        n //= 10
    return s

t = int(input())
for _ in range(t):
    x = int(input())
    ans = 0

    for k in range(0, 200):
        y = x + k
        if y - digit_sum(y) == x:
            ans += 1

    print(ans)
```数字求和函数保持迭代以避免字符串转换的开销。 主循环使用保守的界限 200，它安全地覆盖了最大输入大小的所有可能的进位和数字和交互。 

重要的实现细节是我们不试图在数学上严格限制上限。 任何大于 90 的常数都可以，因为 10 位数字的最大数字和是 90。

 ## 边缘情况

 对于$x = 1$，算法检查$y$从 1 向上。 每个候选人都失败了$y - d(y) = 1$，并且循环正确地产生零。 关键的一点是，尽管$y = 10$引入数字进位，数字和调整仍然太大，无法满足相等性。 

对于像这样的值$x = 998244360$，只有当$y$通过增加最后一个数字块同时保持数字和对齐来形成。 小循环$k$准确捕获这十个值，因为只有最后一位数字会按受控量更改数字总和。
