 ## 问题理解

 给定一个以十进制形式书写的整数，我们必须决定是否可以通过重复将三个固定构建块之一彼此相邻来构造它：`1`,`14`， 和`144`。 该数字必须精确形成，没有多余的数字，也不能重新排列，只能将这些允许的模式串联起来。 

这将任务变相变成了字符串构造问题。 尽管输入是最大 10^9 的整数，但真正重要的是它的十进制表示形式，因为串联是在数字级别定义的。 

约束条件`n ≤ 10^9`表示输入最多 10 位数字。 这立即排除了对重型数据结构或指数搜索的任何需要。 任何以位数线性处理数字的解决方案，甚至尝试小的有界搜索，都将足够快。 

当考虑贪婪解析时，一些边缘情况会自然出现。 一种失败模式是独立解释数字。 例如，治疗`144`作为`1 + 4 + 4`会错误地表明许多无效数字是有效的。 另一个问题是贪婪的模糊性。 例如，在像这样的字符串中`14144`，选择`1 | 4 | 1 | 4 | 4`无效，但存在正确的分段`14 | 144`。 天真地从左到右贪婪地选择最小单位会破坏正确性。 

我们还需要小心前缀冲突。 模式重叠：`1`是一个前缀`14`， 和`14`是一个前缀`144`。 这意味着总是采用最短匹配的天真贪婪方法可能会陷入困境，而更加结构化的贪婪策略必须首先选择较长的匹配。 

## 方法

 暴力方法会尝试所有可能的方法将数字字符串分割成段，每个段是`1`,`14`， 或者`144`。 在每个位置，最多可以有三个选择，从而导致分支递归。 在最坏的情况下，这会变成位数的指数，大约为 O(3^d)，其中 d 是数字的长度。 

从概念上讲，这是可行的，因为它直接探索每个有效的分解，但即使对于 10 位数字，它也变得不可行，因为状态数量快速增长并且许多路径重叠。 

关键的观察结果是该结构受到高度限制：每个有效段都以以下任一开头`1`，然后可选地扩展到`14`，并且进一步可选地`144`。 这种嵌套结构意味着每当我们看到`1`，我们应该始终尝试首先使用最长的有效模式。 如果失败，我们会通过拒绝整个配置来隐式回溯。 

这将问题变成了从左到右贪婪匹配的单个线性扫描，总是尝试匹配`144`首先，然后`14`， 然后`1`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3^d) | O(3^d) | O(d) | 太慢了 |
 | 最优贪心扫描| O(d) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将数字转换为字符串，以便我们可以按顺序检查数字。 直接处理数字是必要的，因为模式是在连续数字上定义的，而不是算术属性。 
2. 从最左边的数字开始扫描。 维护索引`i`跟踪我们当前的位置。 
3. 在每个位置，检查从以下位置开始的子串是否为`i`开始于`144`。 如果是，则消耗三个角色并移动`i`前进 3。这个选择是正确的，因为`144`是最具体和限制性最强的模式，使用它可以防止意外分割有效结构。 
4. 如果`144`不可用，检查子字符串是否以以下开头`14`。 如果是，则消耗两个字符并前进`i`2. 这一步确保我们仍然优先考虑较长的有效块而不是较短的有效块。 
5. 如果两者都不是`144`也不`14`match，检查当前字符是否为`1`。 如果是这样，将其作为单个块使用并前进`i`1.
 6. 如果这三个条件在任何位置都不成立，则构造失败并且该数字不是有效的幻数。 
7. 如果扫描恰好在字符串末尾完成，则该数字有效。 

### 为什么它有效

 正确性取决于有效模式的嵌套结构：每个有效数字都是标记的串联，其中每个标记以`1`，并且较长的标记扩展了较短的标记（`1 ⊂ 14 ⊂ 144`）。 由于这种遏制，只要有较长的匹配可用，选择它就不会阻止可能以较短前缀开头的有效解决方案。 如果存在解决方案，则贪婪扫描永远不会过早地丢弃它，并且任何匹配失败都意味着该位置不存在有效的分段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

i = 0
n = len(s)

ok = True

while i < n:
    if i + 3 <= n and s[i:i+3] == "144":
        i += 3
    elif i + 2 <= n and s[i:i+2] == "14":
        i += 2
    elif s[i] == "1":
        i += 1
    else:
        ok = False
        break

print("YES" if ok and i == n else "NO")
```该代码准确地反映了贪婪策略。 检查的顺序至关重要：`144`之前必须进行测试`14`， 和`14`前`1`，否则我们将面临消耗前缀的风险，该前缀会阻止稍后匹配更长的有效块。 

最终条件`i == n`确保我们消耗了整个字符串，没有剩余的数字，这是必要的，因为部分解析是不够的。

 ## 边缘情况

 当贪婪决策看似可以互换但实际上却不然时，就会出现一种微妙的边缘情况。 考虑`14144`。 

如果我们处理它：

 开始于`1`， 然后`41...`除非我们仔细对齐片段，否则就会出现问题。 正确的分解是`14 | 144`。 该算法通过始终尝试来确保这一点`144`和`14`在回落到之前`1`。 

逐步：

 输入：`14144`我们检查：

 当 i=0 时，`14`匹配，所以我们消费`14`。 

当 i=2 时，子串为`144`，所以我们消费`144`。 

当 i=5 时，我们就完成了。 

这表明贪婪排序可以防止过早的碎片，并保证只要存在碎片就可以进行有效的分解。
