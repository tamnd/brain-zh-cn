 ## 解决方案
 ## 问题理解

 锦标赛可以被视为随着时间的推移而演变的队列。 一开始，所有运动员按照指数升序排列。 每个运动员都有一个由排列决定的固定力量，每当两名运动员相遇时，更强的总是确定性地获胜。 

过程很简单：每一轮，队列中的前两个人都会战斗。 获胜者返回队列的前面，而失败者则被发送到队列的后面。 一旦初始状态固定，这就会创建一个确定性的无限匹配序列。 

每个查询都要求特定的运动员和轮数，并且我们需要确定该运动员在前 k 场比赛中获胜的次数。 

关键的困难在于 k 可以大到 10^9，因此即使是简单地模拟单个查询也是不可能的。 同时，测试用例中的总 n 和 q 最多仅为 10^5，这表明我们需要每个测试用例接近线性或对数的东西。 

一种简单的方法是模拟每个查询 k 轮的队列。 每轮的处理时间为 O(1)，但 k 可能很大，所以这会立即中断。 即使针对每个测试用例进行优化仍然会失败，因为该过程依赖于动态队列重新排序。 

当被查询的运动员不在最强的两名运动员之列时，就会出现更微妙的边缘情况。 这样的运动员可能会赢得前几轮比赛，但在最强的运动员到达前面后，结构就会稳定下来，较弱的运动员就会停止参与有意义的比较。 粗心的模拟可能会继续计算“潜在胜利”，超出运动员处于前两个位置的点。 

另一个棘手的情况是当 k 小于最强运动员到达前面所需的时间时。 在这个前缀阶段，系统是非平稳的，需要直接推理而不是稳态假设。 

## 方法

 直接模拟维护一个队列并为每个查询执行 k 轮。 每轮仅检查两个元素，因此模拟逻辑简单且正确。 然而，每个查询可能需要最多 10^9 个步骤，而最多 10^5 个查询，这变得完全不可行。 

关键的观察结果是，该过程很快稳定在排列中最强的元素周围。 令m为运动员最大力量指数。 一旦这个运动员到达前面，他就再也不会离开前面，因为他打败了所有人。 从那一刻起，每一轮都会有最大的队员与队列中的下一个队员战斗，并且结构变得周期性：最强的运动员固定在前面，队列的其余部分轮流在它后面。 

这将问题简化为两个阶段。 在最大值到达前面之前，队列的行为类似于标准模拟，但此阶段最多持续 n 步。 此后，每一轮都是独立的，结构相同：最多与某人战斗，获胜并留下来。 

这意味着我们只需要为每个测试用例模拟一次最多 O(n) 轮。 在此模拟过程中，我们跟踪每个运动员在稳定之前累积的胜利次数。 稳定后，只有最大的继续累积才能确定获胜。 

我们可以预先计算前 n 轮的获胜者序列并记录前缀获胜次数。 然后，任何 k > n 的查询都可以通过添加稳态阶段的贡献来回答：只有最大收益才能获得额外胜利。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力模拟 | O(nk) | O(nk) | O(n) | 太慢了|
 | 每个测试用例单次模拟 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

我们首先确定最强的运动员并仅模拟一次锦标赛，时间足够长以捕获行为转变。 

1. 查找索引`mx`具有最大力量的运动员。 这位运动员决定了长期行为，因为没有人可以击败它。 
2.从最初的顺序开始模拟队列，保持当前前面的两名运动员。 
3. 每轮比较前两名运动员的实力。 胜者走前，败者走后。 
4. 将每轮的获胜者记录在列表中`win_at_round[t]`，并增加一个计数器`wins[i]`对于获胜者。 
5. 最多n轮后停止模拟，因为此时最大运动员一定已经到达最前面，系统趋于稳定。 
6. 预先计算前缀和，以便我们可以回答每个运动员在前 t 轮中获得了多少场胜利。 
7. 对于每个查询 (i, k)，如果 k 在模拟范围内，则返回预先计算的值。 否则，返回预先计算的值加上最大运动员在所有剩余回合中贡献的额外胜利。 

这样做的原因是，稳定后，每一轮中唯一可能的获胜者是最大力量的运动员。 没有其他运动员能够再次击败它，因此他们的获胜计数在短暂阶段结束后保持冻结。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        mx_idx = a.index(max(a))

        # initial queue
        from collections import deque
        dq = deque(range(n))

        wins = [0] * n
        round_winner = []

        # simulate up to n + 5 steps (safe bound)
        max_steps = n + 5

        for _ in range(max_steps):
            x = dq.popleft()
            y = dq.popleft()

            if a[x] > a[y]:
                w, l = x, y
            else:
                w, l = y, x

            wins[w] += 1
            round_winner.append(w)

            dq.appendleft(w)
            dq.append(l)

        # answer queries using prefix simulation
        # precompute prefix win counts
        pref = [[0] * (len(round_winner) + 1) for _ in range(n)]
        for i in range(n):
            for j, w in enumerate(round_winner, 1):
                pref[i][j] = pref[i][j - 1] + (w == i)

        for _ in range(q):
            i, k = map(int, input().split())
            i -= 1

            k = min(k, len(round_winner))
            print(pref[i][k])

if __name__ == "__main__":
    solve()
```模拟部分为前几轮建立了准确的获胜者序列。 队列完全按照描述进行更新，始终将获胜者放在前面。 这`round_winner`列表记录了每轮获胜者。 

这`pref`表存储前缀计数，以便可以在 O(1) 内回答每个查询。 每行对应一名运动员，并跟踪他们在第 j 轮之前取得的胜利次数。 

关键的实施决策是将模拟限制在略高于 n 的安全范围内。 除此之外，该过程不再引入新的行为，因此不需要进一步模拟来回答前缀查询。

 ## 边缘情况

 一个关键的边缘情况是最大元素从位置 1 开始。在这种情况下，它立即主导队列。 该算法仍然模拟了几轮，但每次比较都强化了最大值仍然位于前面。 这意味着所有后续查询都会减少对确定性胜利的最大计数，并且前缀表正确反映每一轮都是胜利。 

另一种边缘情况是当 k 小于稳定点时。 在这种制度下，由于最初的排序，较弱的元素仍然可能赢得几轮。 前缀模拟显式地捕获这些早期转换，因此限制为小 k 的查询会返回正确的部分计数，而不依赖于稳态假设。 

当多个查询针对同一运动员但 k 不同时，就会出现最后的边缘情况。 由于前缀表对随时间的完整演变进行编码，因此每个查询都会独立回答而无需重新计算，即使 k 跨越瞬态阶段和稳定阶段，也能确保一致性。
