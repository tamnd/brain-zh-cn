 ## 解决方案
 ## 问题理解

 我们得到了多组动漫交易卡，其中每张卡都有一个称为怪异数字的整数标签。 Midoriya 希望最终得到一个非常具体的最终集合：它必须恰好包含从 1 到某个值 K 的每个整数的一个副本，没有间隙，也没有多余的内容。 他可以使用两种操作来修改他的收藏：他可以以成本 A 将任何现有卡牌交易到任何其他卡牌，或者他可以以成本 B 直接购买任何卡牌。荷官对所有怪异号码有无限的供应，因此供应永远不会受到限制。 

重要的是，最终的收集不是任意的。 它必须是从 1 开始的完美整数前缀集。这意味着最终状态完全由选择 K 决定，然后确保从 1 到 K 的每个数字都恰好出现一次。 

输入大小N可以大到100000，奇数的值高达1e6。 这排除了任何试图模拟所有转换或显式尝试所有卡片子集的解决方案。 任何 O(N^2) 或更差的方法都会立即失败。 即使 O(NK) 也是不可能的，因为 K 可能很大。 

一个微妙的困难是存在重复和不相关的卡片。 有些卡很有用，因为它们已经匹配所需的数字，而其他卡可能更好地通过交易替换或完全忽略。 另一个棘手的方面是确定将现有卡换成所需号码或直接购买是否更便宜。 该决定仅取决于 A 和 B，但它与我们已有的数字数量相互作用。 

一个常见的错误是认为拥有一张具有给定怪异编号的卡总是可以节省成本。 这是错误的，因为如果交易成本很高，那么直接购买相同的数量可能仍然更便宜。 另一个失败案例是假设我们应该始终最大化 K。增加 K 会增加所需的购买量，因此最佳 K 不一定是可实现的最大值。 

## 方法

 蛮力的想法很简单：对于每个可能的 K，我们尝试构建集合 {1, 2, ..., K}。 对于每个 K，我们计算当前集合中已存在这些数字的数量。 假设我们已经有 x 个。 剩余的 K − x 数字必须通过交易或购买来创建。 对于每个缺失的数字，我们选择两个操作中更便宜的一个，因此每个操作的成本为 min(A, B)。 这给出了该 K 的总成本。 

这是正确的，因为每个所需的数字都是独立的：一旦我们决定 K，每个缺失值都可以单独修复。 然而，尝试所有 K 直到 1e6 太慢。 对于每个 K，我们将扫描数组或维护频率计数，导致大约 O(N maxC) 或更糟，这远远超出了限制。 

关键的观察是我们只关心前 K 个数字中有多少已经存在。 如果我们预处理所有怪异数的频率，我们就可以有效地计算前缀覆盖率。 然后我们可以在一次线性扫描中评估所有可能的值，累积已经拥有的所需数字的数量。 

设 CostPerFix = min(A, B)。 对于给定的 K，成本为 (K − have[K]) * costPerFix。 唯一缺少的因素是计算 have[K]，即多重集中 [1, K] 内的不同值的数量。 一旦我们有了频率数组或设置标记，我们就可以维护存在的前缀和。 

因此，问题简化为从 1 到输入中出现的最大可能值扫描 K，维护 1..K 中已经存在的数量，并计算每一步的成本。

 | --- | --- | --- | --- |

 ## 算法演练

 ## 算法演练

1. 使用频率数组或布尔存在数组来计算已存在的怪异数。 这允许恒定时间检查所需号码是否已被拥有。 
2. 计算 costPerFix 作为 A 和 B 的最小值。这代表转换或获取任何单个丢失卡的最便宜的方法，因为每个丢失的号码都可以独立处理。 
3. 在可能的怪异数字范围内构建存在数组。 将每个 c_i 标记为存在，但只关心它是否至少存在一次，因为除了第一次出现之外，重复项没有帮助。 
4. 从 1 向上迭代 K，保持 1..K 中已经存在的数字的运行计数。 当我们达到值 i 时，如果存在[i]为真，则增量有。 这确保了始终代表当前前缀满足的要求的数量。 
5. 对于每个 K = i，将成本计算为 (i − have) * costPerFix。 这是因为 i 是所需卡的数量，have 是已经可用的卡的数量，所以区别在于必须构造什么。 
6. 跟踪所有 K 的最小成本。答案是选择小 K（更少的所需牌）和大 K（更多可用的匹配）之间的最佳权衡。 
7. 返回获得的最小值。 

### 为什么它有效

 在任何固定的 K 处，问题的结构都会强制进行确定性分解：1..K 中的每个所需数字要么已经存在，要么缺失。 现有卡无需付费。 丢失卡片是独立的决定，每张卡片都可以通过交易或购买来获得最佳满足。 不同数字之间不存在耦合，因为操作不会跨值交互。 因此，成本函数仅取决于缺失元素的数量，而不取决于它们的身份。 这使得前缀评估足以探索所有有效的 K。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, A, B = map(int, input().split())
    arr = list(map(int, input().split()))

    maxv = max(arr) if arr else 0
    maxv = max(maxv, n)

    present = [0] * (maxv + 2)
    for x in arr:
        if x <= maxv:
            present[x] = 1

    cost = min(A, B)

    have = 0
    ans = 10**18

    for k in range(1, maxv + 1):
        if present[k]:
            have += 1
        need = k - have
        ans = min(ans, need * cost)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将问题压缩到包含所有相关怪异数的存在数组中。 使用布尔标记可以避免重复计算重复项，因为拥有同一数字的多个副本无助于满足更多要求。 

该变量跟踪当前 K 之前已满足的所需数字数量。每个步骤都会增量更新此值，避免重新计算。 成本计算直接根据每个缺失数字的成本相同的固定金额的观察得出。 

一个微妙的点是选择 K 的上限。达到 max(arr) 就足够了，因为任何大于最大现有值的 K 只会增加所需的元素，而不增加可用的元素，使得成本单调不减少超出该点。

 ## 边缘情况

 一个关键的边缘情况是所有卡片都是单个怪异数字的重复。 在这种情况下，只有 K = 1 才能带来任何好处，并且每个更大的 K 都需要完整构建。 该算法可以处理此问题，因为 has 仅增加一次，并且随着 K 的增长，所有缺失值都会正确计数。 

当 A 等于 B 时，会出现另一种边缘情况。这里，交易和购买是等效的，解决方案简化为简单地计算缺失值。 该算法仍然有效，因为 costPerFix 不依赖于结构。 

最后的边缘情况是当最大怪异数远大于 N 时。扫描仍然可以正确处理稀疏存在，因为只有现有值增量具有，而其他所有因素都会线性影响成本。
