 ## 解决方案
 ## 问题理解

 我们得到了三个独立的序列，每个序列代表墙的截面高度。 每面墙都有相同数量的部分，但顺序与任务无关。 重要的是每面墙上至少出现一次的高度。 

目标是找到同时出现在所有三堵墙中的最大高度值。 换句话说，我们正在搜索第一个数组中某处、第二个数组中某处和第三个数组中某处存在的值，并且在所有这些值中我们想要最大的值。 如果不存在这样的值，则答案定义为 -1。 

约束允许每面墙最多有 100000 个元素，每个高度最多为 100000。这立即排除了直接比较每对或每三个元素的任何方法。 在最坏的情况下，三次甚至二次策略将涉及多达 10^10 次运算，这远远超出了 Python 2 秒内所能容纳的范围。 即使对每个数组进行排序也很好，但如果重复执行，对 Python 列表进行重复扫描或嵌套成员资格检查会变得太慢。 

主要的微妙之处在于，重复并不重要，超越了存在。 如果某个高度在一堵墙上出现多次，它仍然只提供一个逻辑存在。 另一个边缘情况是交叉点为空时。 例如，如果三个数组不相交，如 [1]、[2]、[3]，则正确的输出为 -1，并且如果不小心，任何将候选答案初始化为 0 的实现都将错误地返回 0。 

## 方法

 一种直接的方法是将其视为成员交叉问题。 对于第一面墙上的每个值，我们可以检查它是否出现在第二面和第三面墙上。 这是正确的，因为它明确地测试了所有三个集合中的存在条件。 然而，列表中的简单成员资格检查成本为 O(n)，因此对于第一个数组中最多 n 个元素中的每个元素，我们可能会扫描两个附加数组。 这导致每个测试用例的行为为 O(n^2)，在最坏的情况下约为 10^10 次操作，这太慢了。 

关键的观察是我们不需要位置信息或多重性，只需要一个值是否存在。 这允许我们将每个数组转换为一组不同的值。 一旦我们这样做了，检查成员资格的平均时间就变成了 O(1)。 然后，问题简化为计算三个集合的交集并从结果中选择最大元素。 由于值的界限为 100000，我们也可以直接使用布尔数组来标记存在，但集合交集更简单且足够快。 

暴力方法在概念上是有效的，因为它直接测试所有候选者，但由于重复的线性扫描而在时间限制下失败。 基于集合的方法将每个成员资格检查减少到恒定时间，将问题转化为对每个集合最多 n 个值的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 使用集合| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 读取代表墙部分的三个数组。 值的顺序无关紧要，因此我们只关注存在。 
2. 将每个数组转换为一个集合。 这会删除重复项并准备快速的成员资格检查。 此步骤确保未来查找墙中是否存在的平均时间复杂度为 O(1)。 
3. 迭代三组中最小的一组，因为任何有效的公共高度也必须出现在那里。 对于每个候选值，检查它是否存在于其他两个集合中。 
4. 维护一个变量来跟踪迄今为止找到的最大有效高度。 每次我们找到所有三个集合中存在的值时，我们都会将其与当前最大值进行比较，如果更大则更新它。 
5.检查完所有候选后，输出找到的最大值。 如果没有值曾经有效，则输出 -1。 

为什么有效：该算法依赖于这样一个事实：每个有效答案都必须属于三个集合的交集。 通过将搜索空间限制为一组并验证其他组中的成员资格，我们可以确保完整性而不会遗漏任何候选者。 保持的不变量是，在任何点，当前最佳值是迄今为止看到的所有交集元素中的最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
m = list(map(int, input().split()))
r = list(map(int, input().split()))
s = list(map(int, input().split()))

set_m = set(m)
set_r = set(r)
set_s = set(s)

ans = -1

for x in set_m:
    if x in set_r and x in set_s:
        if x > ans:
            ans = x

print(ans)
```该解决方案读取三个数组并立即将它们转换为集合，因为只有存在才重要。 循环结束`set_m`确保我们只考虑一次不同的候选身高。 每个会员测试针对`set_r`和`set_s`以平均恒定时间运行，这使解决方案总体保持线性。 答案变量从 -1 开始，以正确处理不存在交集的情况。 

一个常见的错误是迭代原始数组而不是集合，这可能导致冗余检查。 另一个微妙的问题是初始化`ans`为 0，如果变体问题中所有值均为负值，则这是不正确的，但这里它是安全的，只是因为问题保证了正高度； 尽管如此，-1 仍然是“无交叉点”的正确标记。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    m = list(map(int, input().split()))
    r = list(map(int, input().split()))
    s = list(map(int, input().split()))

    set_m = set(m)
    set_r = set(r)
    set_s = set(s)

    ans = -1
    for x in set_m:
        if x in set_r and x in set_s:
            ans = max(ans, x)

    return str(ans)

 ## 边缘情况

 一种边缘情况是根本没有共同价值。 例如：```
3
1 2 3
4 5 6
7 8 9
```转换为集合后，没有任何元素`set_m`都出现在`set_r`和`set_s`。 循环永远不会更新`ans`，所以它仍然是-1，这是正确的。 

另一种情况是所有数组都包含相同的重复值：```
3
5 5 5
5 5 5
5 5 5
```所有集合都变成`{5}`。 循环检查 5，确认它存在于其他集合中，然后更新`ans`到 5。不存在其他值，因此输出仍为 5。 

最后一个微妙的情况是重复项与单个有效交集值混合，例如：```
5
1 1 1 2 2
3 2 2 2 4
2 5 6 2 7
```在这里，只有 2 个是常见的。 即使它出现多次，集合转换也确保它被计算一次，并且算法正确返回 2。
