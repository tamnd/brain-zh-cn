 ## 解决方案
 ## 问题理解

 我们得到了三堆筹码。 在每次移动中，玩家可以从一堆筹码中取出筹码，选择任意正数，直到该堆中剩余的筹码，或者同时从所有三堆筹码中取出筹码，选择一个正数，直到当前最小的筹码堆大小，然后从每堆中删除该数量的筹码。 

两名玩家交替移动，从 Light 开始，获得最后筹码的玩家获胜。 任务是判断起始玩家是否从初始配置中强制获胜。 

游戏的状态完全由桩大小的三倍决定，因此我们正在处理有限公正的组合游戏。 每一步都会严格减少筹码总数，因此游戏肯定会终止。 约束很小，每个桩的大小最多为 50，因此只有 51³ 种可能的状态，这对于完整的状态空间分析来说足够小。 

当所有桩都为零时，会出现微妙的边缘情况。 在这种情况下，无法移动，因此起始玩家立即失败。 另一个角落是只有一堆非零时。 在这种情况下，游戏会退化为单个堆上的简单外卖游戏，其中“拿走所有三堆”移动实际上相当于从唯一的非零堆中拿走，但在状态转换中仍然必须仔细考虑。 天真的贪婪解释在这里可能会失败，因为同时采取选项以改变最佳游戏决策的方式将牌堆结合起来。 

## 方法

 蛮力思想是对待每个状态`(a, b, c)`作为游戏图中的一个节点，并使用递归计算它是赢还是输。 从任何状态，我们枚举所有有效的移动：对于每个桩，我们可以将其减少任何正数，此外，我们可以同时将所有三个桩减少任意数量，直至最小桩大小。 如果一个州至少有一项举措导致该州失败，则该州获胜。 

这种方法是正确的，因为它直接遵循公正游戏中获胜位置的定义。 然而，如果没有记忆，它会通过不同的移动序列重复重新计算相同的状态，从而导致指数爆炸。 尽管状态空间很小，朴素递归仍然探索移动序列的指数树。 

关键的观察结果是不同状态的数量只有大约 130,000 个。 每次转换都会严格减少堆的总和，因此我们可以使用记忆 DFS 或自下而上的 DP 按总筹码的递增顺序安全地计算结果。 这将问题转化为有向无环图上的标准向后归纳。 

一旦我们计算出所有状态，回答查询就只是查找`(a, b, c)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 无需记忆的暴力 DFS | 指数| O(1) 额外 | 太慢了 |
 | 具有状态记忆功能的 DP | O(n3) | O(n3) | 已接受 |

 ## 算法演练

 ## 步骤1：定义游戏状态

 我们用以下方式表示每个配置`(a, b, c)`。 每个代表三堆中剩余的筹码。 目标是确定该状态是否对当前玩家有利。 

## 步骤 2：基本情况

 如果所有桩都为零，则该状态将失败，因为不可能进行任何移动。 这为递归提供了终止锚点。 

## 步骤 3：生成单桩动作

 来自`(a, b, c)`，我们可以选择任何非零的桩并删除`1`及其全部价值。 任何结果状态都是有效的下一个状态。 这些动作代表独立应用于每一堆的标准减法游戏转换。 

## 步骤 4：生成同时移动

 我们计算`m = min(a, b, c)`。 对于任何`1 ≤ x ≤ m`，我们可以移动到`(a-x, b-x, c-x)`。 这一举动将所有桩结合在一起，并在状态图中引入对角线转换，这是与独立桩游戏的主要偏差。 

## 步骤5：评估获胜条件

 如果存在至少一个导致失败状态的举动，则该状态获胜。 如果所有的动作都导致获胜状态，那么当前状态就是失败。 

## 第 6 步：记住结果

 我们存储每个的计算结果`(a, b, c)`这样每个状态都会被评估一次。 这确保了状态空间上的线性时间遍历而不是指数重新计算。 

### 为什么它有效

 每一步都会严格减少总和`a + b + c`，因此当按此总和排序时，状态图是非循环的。 这保证了递归计算始终达到基本情况。 获胜/失败分类遵循公平游戏的标准极小极大原则：当所有传出动作都进入获胜状态时，状态恰好处于失败状态，如果至少有一个动作进入失败状态，则获胜。 由于所有状态最终都会还原为最终状态`(0,0,0)`，递归为每个配置分配一致的标签，没有矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from functools import lru_cache

@lru_cache(None)
def win(a, b, c):
    if a == 0 and b == 0 and c == 0:
        return False

    # single pile moves
    if any(not win(a - x, b, c) for x in range(1, a + 1)):
        return True
    if any(not win(a, b - x, c) for x in range(1, b + 1)):
        return True
    if any(not win(a, b, c - x) for x in range(1, c + 1)):
        return True

    # simultaneous move
    m = min(a, b, c)
    if any(not win(a - x, b - x, c - x) for x in range(1, m + 1)):
        return True

    return False

a, b, c = map(int, input().split())
print("Yes" if win(a, b, c) else "No")
```该实现直接镜像状态转换图。 这`lru_cache`确保每个三元组被评估一次，防止指数重新计算。 递归检查所有可能的移动并应用极小极大规则。 

一个常见的微妙之处是我们明确列举了所有可能的减少，而不仅仅是完全删除一堆。 这是必要的，因为部分删除可能会改变未来对对角线移动的访问，并且跳过它们会错误地修剪有效的获胜转换。

 ## 边缘情况

 ### 所有桩数为零

 输入`(0,0,0)`由基本情况直接处理。 该函数立即返回`False`，意味着失败。 这与不存在合法举动的事实相符。 

### 只有一堆非零值

 对于`(0,0,k)`，只有第三堆移动可用。 递归将其减少为`(0,0,0)`一举一动，使国家获胜。 该实现正确地捕获了这一点，因为单桩移动循环包括从 1 到`k`。 

### 平等桩可实现对角优势

 在像这样的州`(2,2,2)`，对角线移动与单桩减少竞争。 该算法评估两者，并且存在`(1,1,1)`或者`(2,2,2)`风格缩减可确保检测到任何导致失败状态的移动。 记忆递归保证这些比较得到一致的解决，因为较小的状态首先通过缓存和递减总和来计算。
