 ## 解决方案
 ## 问题理解

 我们得到一排怪物，每个怪物都有一个整数力量值。 我们想要选择这些怪物的连续块并计算它们的力量总和。 在所有可能的连续块中，我们需要总和尽可能大的一个，然后输出该总和。 

输入只是一个整数序列。 每个整数可以是正数、负数或零。 有效的选择是从索引 i 到 j 的任何区间，其得分是该区间中元素的总和。 任务是找到所有这些间隔内的最大可能得分。 

约束允许最多 100000 个元素，值的大小最多为 10^9。 这立即排除了任何显式尝试所有子数组的解决方案。 一个简单的 O(n^2) 枚举在最坏的情况下已经计算了大约 50 亿个间隔，如果每个间隔都需要 O(n) 求和，那么它就变成了 O(n^3)，这远远超出了时间限制。 在 Python 中，即使 O(n^2) 也太慢了，不到 1 秒。 

一个微妙的点是处理所有数字都是负数的情况。 一种常见的错误方法是假设我们可以选择一个空子数组，从而返回 0。 该问题不允许出现空子数组，因此我们必须至少选择一个元素。 例如，对于输入`[-5, -2, -8]`，正确答案是`-2`， 不是`0`。 

另一个边缘情况是单元素数组。 为了`[7]`，答案是`7`，任何不小心将最佳总和初始化为 0 的逻辑都会在这里失败。 

## 方法

 蛮力的想法很简单：考虑每个可能的起始索引，将其扩展到每个可能的结束索引，计算总和并跟踪最大值。 这是正确的，因为每个连续子数组都被显式求值。 然而，成本来自于反复重新计算总和。 大约有 n(n+1)/2 个子数组，即使使用增量求和，这也是 O(n^2) 操作，这对于 100000 个元素来说太慢了。 

关键的观察结果是，当从左到右扫描时，结束于位置 i 的最佳子阵列要么扩展结束于 i−1 的最佳子阵列，要么从 i 开始。 如果运行总和变为负数，保留它只会使未来的总和变得更糟，因为它将从任何扩展中减去。 这减少了在每个位置维持单一运行最佳结局的问题。 

这是 Kadane 思想的精髓：我们将所有以每个索引结尾的子数组选择压缩为单个状态，而不是探索所有分区。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 最佳（Kadane）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护两个值：以当前位置结束的最佳总和，以及迄今为止看到的最佳总体答案。 

1. 使用数组的第一个元素初始化当前运行总和和全局最佳答案。 即使所有值都是负数，这也确保了正确性。 
2. 对于每个下一个元素 p[i]，决定是扩展前一个子数组还是在 i 处开始一个新子数组。 我们将新的运行总和计算为 p[i] 和 current_sum + p[i] 中的最大值。 这个选择反映了之前的积累是有益的还是有害的。 
3. 将全局最佳答案更新为其自身与新运行总和的最大值。 这确保我们记录数组中任何位置看到的最佳子数组，而不仅仅是那些以最后一个索引结尾的子数组。 
4. 继续直到数组末尾，输出全局最佳答案。 

核心决策发生在每个索引处：如果先前的总和为负数，则将其添加到当前元素只会减少结果，因此重新启动是最佳选择。 如果是正数，则延长总和可以提高。 

### 为什么它有效

 在每个索引 i 处，算法都保持当前运行总和是必须恰好在 i 处结束的最大可能子数组总和的不变式。 任何以 i 结尾的子数组要么来自扩展以 i−1 结尾的子数组，要么来自于从 i 开始的新子数组。 由于两种可能性都被明确比较，因此不会错过任何有效的候选者。 全局最大值跟踪所有端点中最好的，因此一旦扫描完成，它必须等于整个数组中的最佳子数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

cur = a[0]
best = a[0]

for i in range(1, n):
    cur = max(a[i], cur + a[i])
    best = max(best, cur)

print(best)
```该实现直接反映了前面描述的状态转换。`cur`存储以当前位置结束的最佳子数组和，而`best`跟踪全局最优值。 初始化两者`a[0]`避免对全负数组的错误处理。 

关键细节是更新的顺序：我们必须计算新的`cur`更新前`best`， 自从`best`取决于以 i 结尾的更新子数组。 另一个微妙之处是初始化，它不能默认为 0。

 ## 边缘情况

 对于像这样的单元素数组`[5]`，算法初始化`cur`和`best`到 5 并立即返回。 不需要迭代，并且由于只有一个可能的子数组，因此不变量通常成立。 

对于像这样的全负数组`[-5, -2, -8]`，运行总和会在每个元素处重复重新开始，因为扩展只会减少值。 踪迹是`cur = -5, -2, -8`和`best = -2`，正确选择负数最小的元素。 这表明，当较长的子数组有害时，该算法不会错误地选择较长的子数组。
