 ## 解决方案
 ## 问题理解

 我们得到一串数字，它是通过依次写出三轮比赛的分数而形成的，没有任何分隔符。 

原来正好有三个非负整数。 每个整数都没有前导零，除了数字`0`本身是允许的。 每轮得分最多为`1,000,000`。 

三个数字之间的分隔符丢失了。 我们的任务是通过产生有效的三重轮分数并最大化它们的总和的方式来恢复它们。 如果不存在有效的分割，我们必须打印`-1`。 

字符串长度最多为 30。这是关键的观察结果。 尽管数字本身在解释为子字符串时可能很大，但字符串却非常短。 长度为 30 意味着只有少数位置可以插入两个分隔符。 

分数不能超过`1,000,000`，最多有 7 位数字。 这个限制比字符串长度限制要强得多。 任何有效部分必须最多包含 7 位数字，否则其值会自动太大。 

一些边缘情况很容易破坏粗心的实现。 

考虑：```
1000
```有效的分割是`1 | 0 | 0`，但这会留下一个额外的数字。 使用所有数字的唯一方法是`10 | 0 | 0`，其总和为`10`。 任何解决方案都必须确保所有字符恰好属于三个数字之一。 

考虑：```
009
```可能的三部分拆分是：```
0 | 0 | 9
0 | 09 | ...
00 | ...
```子串`"09"`有一个前导零和`"00"`也有一个前导零。 不存在有效的分割，所以答案是`-1`。 

考虑：```
10000011000001
```拆分例如：```
1000001 | 1000001 | 0
```完全按照允许的限制使用值。 界限是包容性的，所以`1,000,000`是允许的，但是`1,000,001`不是。 

考虑：```
123456789012345678901234567890
```该字符串比七位数字的三倍长得多。 由于每个有效分数最多为七位数，因此三个分数加起来最多可达二十一位。 长度为 30 的字符串永远无法拆分为三个有效分数，因此答案是立即的`-1`。 

## 方法

 最直接的想法就是想尽一切办法放置两个分隔符。 

如果第一个分隔符位于位置之后`i`第二个分隔符位于位置之后`j`，那么这三个数是：```
s[0:i]
s[i:j]
s[j:n]
```对于每个分割，我们验证三个条件。 每个部分都必须非空。 任何部分都不能包含前导零，除非其长度恰好为 1。 其数值不得超过`1,000,000`。 

每当分割有效时，我们就计算总和并保留最大值。 

真正简单的蛮力会生成所有可能的子串三元组并检查它们。 当字符串长度最多为 30 时，只有大约```
30 * 30 = 900
```分隔符位置的选择。 即使在解析数字之后，这也是很小的。 

关键的观察是，约束是如此之小，以至于这种蛮力已经是最优的。 不需要动态规划、贪婪方法或复杂的修剪。 整个问题是关于正确验证候选分割。 

我们可以通过注意到有效数字最多有七位数字来使实现稍微干净一些，但即使不使用这一事实，检查所有分隔符对也足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有分割位置进行暴力破解 | O(n²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取数字串`s`并设其长度为`n`。 
2. 初始化`best = -1`。 
3. 枚举第一个数字的结束位置。 随它去`i`， 在哪里`1 ≤ i < n`。 
4. 枚举第二个数字的结束位置。 随它去`j`， 在哪里`i + 1 ≤ j < n`。 
5. 提取三个子字符串：```
a = s[:i]
b = s[i:j]
c = s[j:]
```6. 检查每个子串是否代表合法分数。 

如果满足以下条件，子字符串是合法的：

 - 它的长度至少为1。 
- 如果其长度大于1，则不以`'0'`。 
- 其数值最多为`1,000,000`。 
7. 如果三个子串中有任何一个是非法的，则丢弃此分割并继续。 
8. 否则，将所有三个子字符串转换为整数，计算它们的总和，然后更新：```
best = max(best, a + b + c)
```9. 测试完所有分隔符对后，打印`best`。 

### 为什么它有效

 原始游戏分数的每个有效重建都恰好对应于一对分隔符位置。 该算法枚举了每个可能的对，因此不会错过任何有效的重建。 

对于每个候选分割，验证会严格检查语句中给出的规则：三个非空数字、无前导零和最多值`1,000,000`。 任何通过这些检查的拆分都是合法的重建，任何未通过这些检查的拆分都是非法的。 

由于该算法评估每次合法重建的总和并保留最大值，因此最终值存储在`best`正是可达到的最大总分。 如果不存在法律重建，`best`遗迹`-1`，这是所需的输出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LIMIT = 1000000

s = input().strip()
n = len(s)

best = -1

for i in range(1, n):
    for j in range(i + 1, n):
        parts = (s[:i], s[i:j], s[j:])
        values = []
        ok = True

        for p in parts:
            if len(p) > 1 and p[0] == '0':
                ok = False
                break

            v = int(p)
            if v > LIMIT:
                ok = False
                break

            values.append(v)

        if ok:
            best = max(best, sum(values))

print(best)
```外部两个循环枚举两个分隔符的所有可能位置。 由于分离器必须恰好产生三个非空部分，`i`开始于`1`和`j`开始于`i + 1`。 

验证逻辑直接遵循该语句。 像这样的子串`"0"`是合法的，同时`"00"`和`"09"`不是。 支票```
len(p) > 1 and p[0] == '0'
```准确地捕捉到了这个规则。 

之后，子字符串被转换为整数并与`1,000,000`。 Python 整数具有任意精度，因此不存在溢出问题。 

每当分割有效时，就会将其总和与当前最佳答案进行比较。 如果没有找到有效的分割，`best`遗迹`-1`，它自然会处理不可能的输入。

 ## 边缘情况

 考虑输入：```
009
```候选人分裂`0 | 0 | 9`仅当分隔符恰好生成这些子字符串时才有效。 对于其他可能性，子字符串例如`"00"`或者`"09"`出现。 验证步骤拒绝任何长度超过 1 并以以下内容开头的子字符串`'0'`。 由于每一个可能的分裂都会失败，`best`遗迹`-1`。 

考虑：```
100000110000010
```一种候选人分裂是：```
1000001 | 1000000 | 10
```第一个值超出限制并被拒绝。 另一次分裂可能会产生：```
1000000 | 1000000 | 10
```这是被接受的，因为该限制是包含在内的。 该算法将解析的整数直接与`1,000,000`，因此边界处理正确。 

考虑：```
123456789012345678901234567890
```任何分割成三个非空部分必须至少留下一个部分超过七位数字。 任何超过七位数的数字都超过`1,000,000`，因此每个分割都无法通过值检查。 算法系统地验证所有可能性并正确返回`-1`。 

考虑：```
111
```这是可以形成三个非空数字的最短字符串。 唯一的区别是：```
1 | 1 | 1
```循环仍然正确地检查它，因为`i = 1`和`j = 2`是有效的分隔符位置。 结果总和是`3`，这成为答案。
