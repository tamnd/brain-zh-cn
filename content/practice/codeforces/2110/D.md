 ## 解决方案
 ## 问题理解

 我们被要求引导机器人通过一系列检查站。 每个检查点都有一定数量的电池可供机器人收集，并且有单向通道连接一些检查点。 每条通道都需要机器人携带至少一定数量的电池才能穿越。 机器人从第一个检查点开始时电池电量为零，并希望以尽可能少的电池到达最后一个检查点。 在每个检查点，机器人都可以拾取那里可用的任意数量的电池，并且之前收集的所有电池在每个检查点都会完全充电。 

挑战在于计算机器人在到达最终检查点或报告不可能到达最终检查点时可以拥有的最小电池数量。 

约束表明检查点的数量$n$可以达到$2 \cdot 10^5$和通道数$m$可以达到$3 \cdot 10^5$，而总和$n$和总和$m$所有测试用例都在这些范围内。 这排除了任何尝试枚举所有路径或执行任何操作的简单解决方案$O(n^2)$通道上的操作。 我们必须以大致线性的目标为目标$n + m$或者涉及对数开销，例如$O((n+m) \log n)$。 

边缘情况出现在某些路径需要的电池数量超过机器人所能收集的电池数量的情况下。 例如，如果第一个检查点的电池电量为零，而第一个外出通道需要一块电池，则机器人无法移动。 当存在通往具有不同电池数量的检查点的多条路径时，会发生另一种微妙的情况，其中尽早获取更多电池可能会允许稍后通过要求较高的通道。 对这些选项管理不当很容易导致错误的答案。 

## 方法

 暴力方法是考虑从检查点 1 到检查点的每条路径$n$，跟踪机器人沿每条路径携带的电池数量。 在每个检查点，您可以尝试使用所有可能数量的电池，然后递归或迭代地探索每个传出通道。 这种方法原则上是正确的，但路径数量呈指数增长$n$和$m$。 即使通过检查点和电池计数进行记忆，电池计数本身的范围也高达$10^9$，使得状态空间变得棘手。 

关键的见解是，问题可以简化为对最小最终电池数量的二分搜索并结合可行性检查。 如果我们确定电池的目标数量$B$在最后一个检查点，我们可以检查是否可以到达检查点$n$同时从不携带超过$B$随时电池。 可行性检查可以使用受 Dijkstra 启发的贪婪方法来执行：在每个检查点，跟踪机器人可以拥有的最大电池数量，同时仍然尊重通过要求。 因为这些段落只向前推进（$s_i < t_i$），该图是非循环的，允许从检查点 1 到检查点的动态编程传播$n$按线性顺序。 这确保了二分搜索有效地收敛到最小可行的最终电池计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n * 最大(b_i)) | 太慢了|
 | 最优（二分查找+DP/可行性）| O((n+m) log S) | O(n + m) | 已接受 |

 这里$S$是沿路径的所有电池的总和或最大值$w_i$，它限制了二分搜索范围。 

## 算法演练

 1. 读取多个测试用例的输入。 对于每个测试用例，解析检查点的数量$n$, 通道数$m$，电池阵列$b$，以及段落列表$(s_i, t_i, w_i)$。 
2. 对可能的最终电池数量定义二分搜索$B$。 下限是 0，上限是超出任何单一路径要求的某个大数，例如，$10^{15}$。 
3. 对候选人进行可行性检查$B$。 从检查点 1 开始，电池电量达到$B$。 按拓扑顺序或使用队列在图中传播。 在每个检查点，计算机器人在每次外出通道上可以携带的最大电池，且不超过$B$并且在满足通过要求的同时$w_i$。 
4. 对于从检查点出发的每一段通道$u$到检查站$v$有要求$w$，检查机器人是否可以到达$u$至少有$w$电池。 如果是，则计算新电池数量$v$作为最小值$B$以及电池总和$u$以及在以下位置收集的任何电池$v$。 如果这大于之前记录的任何电池计数$v$，更新并添加$v$到队列中。 
5.传播后，检查是否有checkpoint$n$可行的电池数量不超过$B$。 如果是，则候选人$B$是可行的； 如果没有，那就太低了。 
6. 二分搜索根据可行性调整搜索范围。 收敛后，如果不可行$B$存在，返回-1； 否则，返回最小值$B$成立。 

工作原理：机器人在每个检查点的电池状态都是单调的：收集更多的电池永远不会导致无法到达终点，而更少的电池可能会堵塞一些通道。 二分查找利用了这种单调性。 因为该图是非循环的，并且我们在每个节点传播最大电池，所以我们不会错过任何最佳路径。 不变的是，在开始处理每个检查点时，我们知道机器人可以为当前候选者拥有的最大电池$B$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        b = list(map(int, input().split()))
        edges = [[] for _ in range(n)]
        for _ in range(m):
            s, t_, w = map(int, input().split())
            edges[s-1].append((t-1, w))

        left, right = 0, 10**15
        answer = -1

        def can_reach(final_battery):
            max_batt = [-1]*n
            max_batt[0] = min(b[0], final_battery)
            queue = deque([0])
            while queue:
                u = queue.popleft()
                for v, w in edges[u]:
                    if max_batt[u] < w:
                        continue
                    new_batt = min(final_battery, max_batt[u] + b[v])
                    if new_batt > max_batt[v]:
                        max_batt[v] = new_batt
                        queue.append(v)
            return max_batt[-1] != -1

        while left <= right:
            mid = (left + right) // 2
            if can_reach(mid):
                answer = mid
                right = mid - 1
            else:
                left = mid + 1

        print(answer)

if __name__ == "__main__":
    solve()
```该解决方案读取多个测试用例，构建图表，并对最小可行的最终电池数量执行二分搜索。 这`can_reach`函数使用队列执行类似 BFS 的传播。 的选择`max_batt`确保我们不会不必要地重新访问检查站。 使用`min(final_battery, max_batt[u] + b[v])`确保我们永远不会超过候选人`B`。 这在尊重段落要求的同时保持了正确性。
