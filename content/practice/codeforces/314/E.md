 ## 解决方案
 ## 问题理解

 几何描述隐藏了更简单的组合结构。 

取一对点$(l,0)$和$(r,0)$， 和$l<r$。 左端点用小写字母标记，右端点用相应的大写字母标记。 

如果两对交叉，则它们的正方形相交。 如果一对完全位于另一对内，则相应的方块完全位于较大的方块内，并且它们不接触。 有效的配对与正确嵌套或不相交的括号对完全相同。 该结构与具有 25 种括号类型的正确括号序列相同。 

Petya 删除后：

 - 每个可见的小写字母肯定是已知类型的左括号。 
- 每个大写字母都消失了。 
- 每一个`?`可能是：

 - 已擦除的左括号，其类型未知，或者
 - 删除的右括号。 

我们必须计算有多少个完整的正确括号序列可以产生给定的字符串。 

长度可以达到$10^5$，这立即排除了经典括号 DP 状态，例如`dp[position][balance]`。 二次算法需要大约$10^{10}$操作并且是不可能的。 

需要更微妙的观察。 

考虑一个位置包含`?`。 

如果我们确定它是左括号，则可以稍后选择它的类型。 如果它是右括号，则其类型已被堆栈顶部不匹配的左括号强制。 一旦知道了开局边，匹配的闭局边就没有独立的选择。 

这意味着组合困难根本与括号类型无关。 首先，假设只有一种括号类型，我们计算有效的开盘/收盘位置。 之后，我们乘以将类型分配给未知空缺的方法数量。 

几个容易被忽视的案例：

 如果$n$很奇怪，完美的配对是不可能的。 

例子：```
3
???
```答案是`0`。 

如果已经有超过$n/2$可见的小写字母，我们无法容纳所需数量的左括号。 

例子：```
4
abcd
```四个位置都是强制空缺，所以答案是`0`。 

另一个微妙的情况是前缀包含太多右括号。 

例子：```
4
?a??
```第一个`?`不能选择作为右括号，因为正确的括号序列可能永远不会比任何前缀中的开括号多。 

DP 边界自动消除此类状态。 

## 方法

 最直接的想法是标准括号序列DP。 

让`dp[i][bal]`是处理第一个之后的路数`i`当前堆栈大小的位置`bal`。 

可见的字母总是会增加平衡。 一个`?`可以增加或减少它。 

这是正确的，但余额可以大到$n$。 和$n=10^5$，状态空间变为$O(n^2)$，远远超出了极限。 

关键的观察结果是，每个可见的小写字母都已知是左括号。 唯一的决定是在`?`职位。 

不存储当前余额，而是存储到目前为止已放置的右括号数量。 

让$m=n/2$，任何有效序列中右括号的总数。 

加工后位置$i$：

 - 至多$\lfloor i/2 \rfloor$可以出现结束词，否则某些前缀将包含比开头更多的结束词；
 - 至少$i-m$平仓必须已经出现，否则将没有足够的剩余仓位来准确达到$m$年底关闭。 

这些界限出人意料地严格。 它们将有效 DP 范围缩小到狭窄的对角线带。 将所有位置的宽度相加仅给出$O(n)$总工作量。 

在计算有效的开始/结束布局后，每个未知的开始括号都会贡献一个因子$25$，因为它的类型可以是任何小写字母，除了`x`。 然后由匹配结构强制关闭括号类型。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力 DP 平衡 |$O(n^2)$|$O(n)$或者$O(n^2)$| 太慢了 |
 | 关闭次数的最优 DP |$O(n)$摊销|$O(n)$| 已接受 |

 ## 算法演练

 1.如果$n$为奇数，输出`0`。 
2.让$m=n/2$。 任何有效序列必须准确包含$m$开口和$m$关闭。 
3. 计算已经存在的可见小写字母数量。 调用这个值`fixed_open`。 
4.让`dp[j]`是在精确放置时处理当前前缀的方法数`j`右括号。 
5. 初始化`dp[0] = 1`。 
6. 从左到右处理位置。 
7. 如果当前字符是可见的小写字母，则强制为左括号。 不需要 DP 转换。 
8. 如果当前字符是`?`，它可能变成：

 - 一个左括号，
 - 或右括号。 

选择它作为右括号会使右括号的数量增加 1：```
dp[j] += dp[j-1]
```更新按降序执行`j`。 
9. 更新时只考虑```
i - m <= j <= floor(i/2)
```在哪里`i`是当前从 1 开始的位置。 

上限保证前缀有效性。 下限保证有足够的剩余位置来准确到达`m`关闭。 
10. 所有位置处理完毕后，`dp[m]`等于假设只有一种括号类型的有效打开/关闭布局的数量。 
11.来自的空缺数量`?`职位是```
m - fixed_open
```1. 乘以```
25^(m - fixed_open)
```因为每个这样的空缺都可以选择 25 个允许的字母中的任何一个。 

1.输出结果取模$2^{32}$。 

### 为什么它有效

 DP 仅计算右括号的位置。 

长度有效的括号序列$n$恰好包含$m$关闭。 对于每个前缀，结束的数量永远不会超过开始的数量，这相当于$j \le i/2$。 下界$j \ge i-m$保证剩余的后缀仍然可以提供足够的结束语来准确地结束$m$。 

每个有效的打开/关闭排列都对应于一个合法的嵌套结构。 一旦开始位置固定，每个结束括号类型都由它匹配的开始括号决定。 唯一剩下的自由是选择源自一个的每个开口的类型`?`，给出一个因子$25$根据这样的开口。 

因此，DP 对所有有效结构只计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1 << 32

def solve():
    n = int(input())
    s = input().strip()

    if n & 1:
        print(0)
        return

    m = n // 2

    dp = [0] * (m + 1)
    dp[0] = 1

    fixed_open = 0

    for i, ch in enumerate(s, 1):
        if ch == '?':
            lo = max(1, i - m)
            hi = min(m, i // 2)

            for j in range(hi, lo - 1, -1):
                dp[j] = (dp[j] + dp[j - 1]) & 0xFFFFFFFF
        else:
            fixed_open += 1

    ans = dp[m]

    for _ in range(m - fixed_open):
        ans = (ans * 25) & 0xFFFFFFFF

    print(ans)

solve()
```数组`dp[j]`存储仅按迄今为止使用的结账数量索引的计数。 可见的小写字母不会改变此计数，因为它被迫成为左括号。 

对于一个`?`, 现有值`dp[j]`已经代表选择它作为左括号。 添加`dp[j-1]`对应于选择它作为右括号。 

降序迭代顺序是必不可少的。 它可以防止在当前位置创建的值在同一更新期间再次重复使用。 

模数是$2^{32}$。 使用```
x & 0xFFFFFFFF
```相当于对结果取模$2^{32}$每次操作后。

 ## 边缘情况

 考虑：```
3
???
```该算法立即检测到$n$是奇数并返回`0`。 不存在有效的配对。 

考虑：```
4
abcd
```四个位置均为强制空缺。 我们正好需要两次开仓和两次平仓，但没有可用于平仓的仓位。 DP 从未达到状态`dp[2]`，所以答案是`0`。 

考虑：```
4
?a??
```在第一个位置，选择右括号将创建一个结尾数多于开头数的前缀。 界限```
j <= floor(i/2)
```自动删除该状态。 只有前缀有效的配置才能生存，并且最终答案精确计算合法的括号序列。
