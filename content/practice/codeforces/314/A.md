 ## 解决方案
 ## 问题理解

 参与者按最终排名顺序列出。 参加者`i`有评级`a[i]`。 

对于尺寸的桌子`m`，如果参与者当前占据位置`p`，他的评级变化是$$d = \sum_{\text{participants before him}} a_j (pos_j-1)     - a_i (p-1)(m-p)$$在原始陈述中直接给出了这个公式。 复杂的是该表是动态的。 

每当有参与者存在时`d < k`，所有此类参与者中当前排名最好的参与者将被删除。 移除后，位置被压缩，所有`d`值被重新计算。 我们必须输出所有被删除的参与者的原始索引，按照它们消失的顺序。 

约束条件`n ≤ 2·10^5`立即排除任何重复重新计算所有评级变化的模拟。 甚至一个`O(n^2)`解决方案将执行大约`4·10^10`最坏情况下的操作。 

棘手的部分是移除会改变位置，因此参与者的价值`d`不是固定的。 一个幼稚的实现可以很容易地删除错误的参与者，因为它评估`d`使用过时的职位。 

考虑：```
5 0
5 3 4 1 2
```首先移除参与者 2。 之后，参与者 3 继续前进，并且必须使用新的位置重新计算他​​的评级变化。 始终使用原始表会产生错误的顺序。 

当参与者当前安全时会发生另一种微妙的情况。```
3 0
10 1 10
```如果我们到达参与者 2 时没有将其移除，则稍后的移除将无法使他的`d`较小。 重复访问早期参与者的解决方案是做不必要的工作。 

的价值`k`也可以是负数。 持有负面评价的参与者`d`不会自动删除。 条件严格`d < k`。 

## 方法

 暴力模拟按照字面意思进行。 重复计算每个参与者的当前`d`，找到第一个`d < k`，将其移走，压缩桌子，然后重复。 

这是正确的，因为它准确地再现了该过程。 不幸的是，单次重新计算已经花费了`O(n)`，并且可以有`O(n)`搬迁。 总复杂度变为`O(n^2)`，这对于`n = 200000`。 

关键的观察结果是，根据原始索引，删除总是从左到右发生。 

假设参与者`i`目前尚存。 如果删除了他之后的某个参与者，则之后的人数`i`减少。 看看公式，$$d_i = \text{constant} - a_i (p_i-1)(m-p_i),$$因素`(m-p_i)`变小。 因为它乘以一个负号，`d_i`只能增加。 

所以一旦参与者`i`达到这样的状态`d_i ≥ k`，未来的除名永远不会使他再次符合资格。 

这意味着当我们从左到右扫描参与者时，参与者的决定`i`仅取决于之前已经发生的删除`i`。 如果`d_i < k`，他必须立即被除掉。 如果`d_i ≥ k`，他永远活下去。 

这将动态过程转变为单个线性扫描。 

让`r`是当前索引之前删除的参与者数量`i`。 

参与者的当前位置`i`是$$p = i-r.$$当前表大小为$$m = n-r.$$在之前幸存的参与者中`i`，位置正好是`1,2,\dots,p-1`。 

如果我们维持$$S=\sum_{\text{surviving } j<i} a_j (pos_j-1),$$然后$$d_i = S - a_i (p-1)(m-p).$$评估所需的一切`d_i`可用于`O(1)`时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化`removed = 0`。 
2. 维护`S`，总和`a_j * (current_position_j - 1)`超过所有已处理的幸存参与者。 
3. 按照参与者的原始顺序从左到右处理参与者。 
4. 参加者`i`，计算他当前的位置：$$p = i - removed.$$当前表大小为：$$m = n - removed.$$5. 计算$$d = S - a_i (p-1)(m-p).$$这正是应用于当前动态表的评级变化公式。 
6.如果`d < k`，删除该参与者。 

增加`removed`并将其原始索引存储在答案中。 

不要添加任何东西`S`，因为删除的参与者不会出现在以后的计算中。 
7. 否则，参与者将幸存。 

添加$$a_i (p-1)$$到`S`，因为该参与者对每个后来的幸存者公式的第一项做出了贡献。 
8. 继续，直到处理完所有参与者。 

### 为什么它有效

 当参与者经过索引`i`被移除后，该值`(m-p_i)`减少，而其他一切都在`d_i`保持不变。 因此，`d_i`永远不会减少。 

所以如果参与者`i`满足`d_i ≥ k`在我们处理他的那一刻，他以后将永远不会被移除。 相反，如果`d_i < k`，规则要求立即将他移除，因为在他之前的每个可移除参与者都已被处理。 

因此，扫描会重现与声明中描述的动态过程完全相同的删除序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    removed = 0
    s = 0
    ans = []

    for i in range(1, n + 1):
        ai = a[i - 1]

        p = i - removed
        m = n - removed

        d = s - ai * (p - 1) * (m - p)

        if d < k:
            removed += 1
            ans.append(str(i))
        else:
            s += ai * (p - 1)

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```变量`removed`追踪有多少早期参与者已经消失。 从这个数字我们可以恢复当前位置`p`和当前表的大小`m`。 

变量`s`存储公式的第一项。 只有幸存的参与者才能做出贡献。 当参与者被删除时，跳过更新`s`是必不可少的。 添加他的贡献会错误地允许被删除的参与者影响以后的计算。 

所有算术都是用 Python 整数完成的。 中间值大致可以达到$$10^9 \cdot 2\cdot10^5 \cdot 2\cdot10^5,$$这远远超出了 32 位范围。 Python 会自动处理这个问题。 

操作顺序也很重要。 我们必须评估`d`在决定参与者是否生存之前。 更新中`s`首先会错误地让参与者参与他自己的评级变化计算。

 ## 边缘情况

 考虑尽可能最小的输入：```
1 0
100
```唯一的参与者有`p = 1`， 所以`(p-1) = 0`和`d = 0`。 自从`0 < 0`是假的，没有人被删除。 该算法没有输出任何内容，这是正确的。 

考虑一个参与者幸存下来并随后被移除的情况：```
4 0
10 1 10 1
```参与者 4 消失后，参与者 3 可能看起来很危险，但移除他身后的人只会减少危险`(m-p)`。 他的`d`只能增加。 该算法处理他一次，就不会再访问他，这与公式的数学行为相匹配。 

考虑一个全相等的数组：```
4 0
1 1 1 1
```扫描使用以下命令计算每次移除后的当前位置`p = i - removed`。 这正是许多错误解决方案失败的地方。 使用原始位置会产生不正确的结果`d`第一次删除后的值。 所维护的`removed`counter 保证压缩位置始终正确。
