 ## 解决方案
 ## 问题理解

 我们有一系列的日子，每天都有购买咖啡的基本成本。 我们还获得了一系列优惠券。 每张优惠券都有截止日期和折扣值。 如果优惠券在截止日期或之前使用，则当天咖啡的成本会减少固定金额。 每张优惠券最多可使用一次，每天最多可使用一张优惠券。 

决定不是每天都买咖啡。 相反，必须恰好选择 k 天，并且在这些选定的日子里我们支付（可能是折扣的）价格。 目标是最小化所选 k 天的总成本，如果折扣占主导地位，结果可能是负数。 

关键的困难在于优惠券分配和日期选择相互作用。 优惠券仅在分配给我们决定购买咖啡的日子时才有价值，并且我们希望将更强的优惠券分配给昂贵或精心挑选的日子。 

限制很大，最多有10万天和20万张优惠券。 这排除了尝试所有天数子集或所有优惠券分配的任何解决方案。 如果需要反复重新处理全局状态，即使每天天真地对作业进行排序也会太慢。 我们需要更接近 O(n log n) 或 O((n + m) log n) 的东西。 

一个天真的陷阱是首先选择 k 个最便宜的日子，然后贪婪地分配优惠券。 这失败了，因为优惠券可能在稍后选择的价格适中的日子更有价值，并且选择本身应该取决于可用的折扣。 

另一个微妙的失败案例是每天单独处理优惠券。 由于每张优惠券只能使用一次，因此需要全球协调。 

## 方法

 强力视图是尝试 k 天的每个子集，并为每个子集尝试所有有效的优惠券分配。 即使我们固定了子集，最优分配优惠券也是时间限制下优惠券与所选日期之间的匹配问题，这仍然很复杂。 子集的数量为 C(n, k)，即使对于较小的 n，这也是不可行的。 这种方法在 n 超过 30 左右后立即爆炸。 

主要的结构观察是，如果我们将优惠券解释为可以在排序结构中贪婪分配的“资源”，则可以独立于确切的优惠券分配来决定日期选择。 我们可以反向思考：对于每一天，我们决定它是否应该成为所选集合的一部分，但我们保留 k 个调整成本的最佳可能集合，而不是首先选择哪 k 天。 

一个有用的重构是按索引升序处理天数，并维护当前可用优惠券的候选福利池。 截止日期为 r 的优惠券在 r 之前的所有天都可用，因此当我们在第 i 天时，所有 r ≥ i 的优惠券都符合资格。 

对于任何固定的选定日期集，最佳策略是将最大的可用折扣分配给具有最大基本成本的选定日期。 这是一个经典的交换论点：将较小的折扣换成更昂贵的一天不会使总体情况恶化。 

这导致了一种贪婪的结构：在每个所选日期分配一张最佳可用优惠券后，我们希望选择最终成本最小的 k 天。 由于优惠券是全球资源，我们将它们维护在按折扣排序的结构中，并在截止日期前激活它们。 然后，我们模拟选择日期，同时保持可实现的最佳改进。 

这个问题简化为随着时间的推移动态维护最佳的 k 个节省决策，这可以使用多重集或堆拆分为已使用和未使用的部分来处理，确保我们始终选择最有利的组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集+赋值| O(C(n,k) · k log k) | O(C(n,k) · k log k) | O(k) | 太慢了 |
 | 排序激活 + 堆的贪婪 | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

我们将每张优惠券转换为可在截止日期前最多选定的一天使用的价值。 我们处理从 1 到 n 的天数，同时维护哪些优惠券可用。 

我们维护两个堆。 一个堆存储按优惠值排序的当前可用优惠券，另一个结构跟踪实际分配了哪些优惠券。 

我们还根据调整后的成本维持当前 k 天的最佳选择。 

该算法进行如下。 

1. 按截止时间升序对所有优惠券进行排序。 这使我们能够随着时间的推移逐步激活它们。 
2. 迭代从 1 到 n 的天数，每当到达第 i 天时，将截止日期等于 i 的所有优惠券插入由折扣键控的最大堆中。 这确保我们随时知道最好的可用优惠券。 
3. 对于每一天 i，计算其基本成本 a[i] 作为对最终答案的候选贡献。 
4. 我们维护 k 个选定天的类似多重集的结构。 当考虑第 i 天时，我们从概念上决定是否将其包含在所选的 k 天中。 如果我们包含它，我们会为其分配当前可用的最佳优惠券（如果有），从而降低其成本。 
5. 为了强制每张优惠券最多使用一次，一旦将优惠券分配给选定的日期，就会将其从可用池中删除。 
6. 如果我们超过 k 个所选天，我们会从选择中删除最差的（折扣后成本最高）天，确保我们始终保留迄今为止看到的最佳 k 个结果。 
7. 处理完所有天后，所选调整成本的总和就是答案。 

微妙的想法是我们从不提前修复子集。 相反，我们在贪婪优惠券分配下不断维护大小 k 的最佳子集，并动态修剪主导选择。 

### 为什么它有效

 在扫描过程中的任何一点，我们都保持不变，即在选择处理天数的某些子集并分配可用优惠券的所有方法中，我们的结构保持 k 最小可能的最终成本。 交换参数保证，如果使用优惠券，将其分配给更昂贵的所选日期不会使结果恶化，因此贪婪地将最大折扣与当前选择的最昂贵候选配对可以保持最优性。 任何最佳解决方案都可以转换为这种贪婪结构，而不会增加成本，因为优惠券分配可以按照所选日期的排序顺序进行交换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    coupons = [[] for _ in range(n + 1)]
    for _ in range(m):
        r, w = map(int, input().split())
        coupons[r].append(w)
    
    k = int(input())
    
    # max-heap of available coupons (store negative for min-heap simulation)
    import heapq
    available = []
    
    # we will store chosen adjusted costs
    chosen = []
    
    def push_choice(val):
        heapq.heappush(chosen, -val)
    
    def current_sum():
        return -sum(chosen)
    
    for i in range(n):
        # activate coupons ending at day i
        for w in coupons[i + 1]:
            heapq.heappush(available, -w)
        
        # base cost of choosing day i
        cost = a[i]
        
        # assign best available coupon if exists
        if available:
            best_discount = -heapq.heappop(available)
            cost -= best_discount
        
        push_choice(cost)
        
        if len(chosen) > k:
            heapq.heappop(chosen)
    
    # sum of k best (stored as negative heap values)
    print(-sum(chosen))

if __name__ == "__main__":
    solve()
```该代码按顺序处理天并在截止日期前激活优惠券。 可用堆总是存储当前仍然可以应用的所有优惠券，并且我们在考虑某一天时贪婪地采取最好的折扣。 

这`chosen`堆用于维护所有处理日中 k 个最小的最终成本。 由于我们推送负值，它表现为所选成本的最大堆，允许我们在超过 k 时删除最差的候选者。 

一个微妙的点是，每张优惠券在弹出时只会被消耗一次`available`，确保不重复使用。 另一个是我们总是每天最多分配一张优惠券，在评估一天时只弹出一次。

 ## 边缘情况

 一个关键的边缘情况是所有优惠券提前过期但 k 很大。 该算法仍然立即激活它们并贪婪地应用它们，确保早期捕获所有折扣潜力。 如果一个幼稚的解决方案试图推迟分配，它就会失去这些优惠券。 

另一种情况是，当优惠券与基本价格相比非常大时，可能会导致成本为负。 堆方法正确地允许负值进入所选集合，并且由于我们正在最小化总成本，因此只要它们改进了 k-best 结构，负贡献就是有益的并被保留。 

最后一种情况是许多小优惠券与一张非常大的优惠券竞争。 贪婪选择确保首先使用大优惠券，因为它会产生最佳的立即减少，并且一旦进入所选集合就锁定分配的结构会阻止任何随后释放它的替换。
