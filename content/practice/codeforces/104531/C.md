 ## 解决方案
 ## 问题理解

 我们得到一棵无向树，其中一些节点可能包含仓鼠。 每只仓鼠都不是静止的，它会永远移动。 每秒它都会走到一个相邻节点，但不允许立即沿着它刚刚使用的同一条边返回，除非它经过叶节点，在这种情况下它允许反转一次。 这创建了一种约束行走，防止内部顶点上的轻微来回振荡。 

我们可以在选定的一组顶点上放置捕鼠器。 如果仓鼠落在任何包含陷阱的顶点上，就会被抓住。 由于我们无法控制初始位置或运动，因此我们必须保证每一种可能的仓鼠轨迹最终都会击中至少一个陷阱。 

输出是我们必须放置陷阱的最小顶点数，以便最终拦截每条可能的仓鼠路径。 

高达 100000 的约束 n 强制任何解在节点数量上呈线性或接近线性。 任何尝试模拟运动、枚举路径或考虑所有起始状态的操作都会立即失败，因为树中可能行走的数量呈指数增长。 

这个问题的一个微妙之处是仓鼠在叶子上的行为有所不同。 在叶子上，它们可以反转方向，这使得叶子就像“反射点”而不是死胡同。 这正是基于简单路径覆盖的天真的直觉变得不正确的原因。 

一个典型的失败案例来自于假设每片叶子都必须“本地保护”。 例如，在一棵星形树中，一个中心连接到许多叶子，一种天真的方法可能会尝试在叶子上放置陷阱，但正确的答案是将陷阱放置在中心，因为叶子之间的每个运动都必须经过它。 任何仅在叶子周围进行局部推理的方法都会忽略这种全局瓶颈结构。 

## 方法

 暴力方法会尝试从每个节点开始推理每个可能的仓鼠轨迹。 人们可以想象从每个起始顶点模拟一只仓鼠，探索所有可能的移动，同时遵守“除非在叶子处否则不立即回溯”规则，并检查哪些节点不可避免地被访问。 然后，我们将尝试选择与所有此类轨迹相交的最小陷阱节点集。 这很快就会变成一个巨大的状态空间问题，因为每个状态不仅取决于当前顶点，还取决于先前的边缘方向，从而有效地使状态空间加倍。 即使进行了修剪，树中不同行走的数量也会随着深度呈指数级增长，因此这种方法是不可行的。 

关键的见解是我们实际上不需要跟踪单个仓鼠的路径。 相反，我们应该推断哪些顶点是所有有效的无限或任意延伸的行走不可避免的“接合点”。 由于运动规则仅限制立即回溯，因此仓鼠基本上执行非回溯行走（除了树叶处）。 这种行走的行为就像沿着树的“核心结构”进行遍历，任何顶点的删除都会以隔离所有叶到叶路径的方式断开树的连接，变得至关重要。 

如果我们从覆盖范围的角度考虑，则仅在位于连接叶子的所有可能“可逆路径”上的顶点处才需要陷阱。 不分支的内部路径不需要多个陷阱，因为进入走廊的仓鼠必须穿过相同的关节结构，无论方向如何。

这将问题简化为识别覆盖非回溯运动下所有叶到叶遍历的最小顶点集。 关键的观察是，只有连接不同“逃逸方向”的顶点才是重要的。 在树中，这些正是位于去除 2 度节点的直链后获得的简化结构上的分支点。 

一旦我们压缩了所有2度节点的最大链，我们就得到了一个更简单的树，其中所有内部节点的度数不等于2。在这个简化的树中，每条边代表一条强制走廊，每个内部节点都是多个独立方向的强制交叉点。 答案变成了阻止所有无限有效行走所需的基本连接点顶点的数量，这对应于在简化结构中选择度数至少为 3 的所有顶点，因为在不同分支之间移动的任何仓鼠都必须经过其中之一。

 ## 算法演练

 1. 构建树的邻接表并计算所有顶点的度数。 这给出了局部分支结构，这是识别不可避免的遍历点所需的唯一信息。 
2. 识别度数至少为 3 的顶点。这些顶点代表仓鼠有多个不同方向继续行走而不会立即倒车的分支点。 
3. 计算所有这样的顶点。 其中每一个都充当必要的拦截点，因为在不同子树之间切换的任何移动都必须经过其中之一。 
4. 返回此计数作为答案。 

### 为什么它有效

 关键的不变量是，在不同的叶到叶区域之间转换的任何有效的仓鼠运动必须经过至少三个不同方向相交的顶点。 1 阶顶点仅反映运动，2 阶顶点仅形成线性走廊，仓鼠无法在其中创建分支行为。 只有 3 度或更多度的顶点才能创建真正的选择点，其中来自树的不同部分的路径合并或分叉。 由于树的不同部分之间的每次重要遍历都必须经过至少一个这样的顶点，因此将陷阱精确地放置在这些顶点上可以保证拦截所有可能的长期行为，并且没有更小的集合可以覆盖所有此类不可避免的交叉点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    deg = [0] * (n + 1)

    for _ in range(n - 1):
        u, v = map(int, input().split())
        deg[u] += 1
        deg[v] += 1

    ans = 0
    for i in range(1, n + 1):
        if deg[i] >= 3:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```实现完全依赖于度数计数。 邻接结构没有显式存储，因为只有度数对于识别分支顶点很重要。 边缘上的循环在 O(n) 中构建度数，最终扫描计算答案。 

一个常见的实施错误是错误地包含 2 度节点。 这些节点位于简单的链上，不会引入分支选择，因此对它们进行计数会高估答案。 另一个微妙的问题是忘记了 n=1 或 n=2 的树没有 3 度节点，因此正确的输出为零。

 ## 边缘情况

 单节点树是自然处理的，因为没有节点的度数≥3，所以答案为零。 

简单的路径也很简单。 每个节点的度数最多为 2，因此不会放置陷阱。 该算法扫描度数并正确返回零。 

在星形树中，中心的度数为 n−1，并且被计数一次。 叶子之间的每条路径都必须经过它，因此算法正确地放置了一个陷阱。 

在完整的二元分支结构中，根据构造，只有根通常达到 3 级或更高，并且算法仍然只计算那些真正的分支连接点，避免沿链过度计数。
