 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列，并且可以任意对它们重新排序。 对于任何选定的排序，我们通过将每个位置 i 与放置在那里的值配对并取两者的按位异或，然后将所有位置的这些值相加来计算分数。 

形式上，如果 p 是长度为 n 的排列，则分数是 p[i] XOR i 的所有位置 i 的总和。 任务是构建获得最大可能分数的任何排列。 

输入由多个独立的测试用例组成，每个测试用例给出一个值n。 对于每一个，我们必须输出一个大小为 n 的有效排列，以最大化该异或和。 

n 最多为 10^5 的约束以及最多 10^5 个测试用例迫使我们远离任何二次方，甚至如果天真地完成每个测试用例 n log n 。 对所有排列的直接评估需要阶乘时间并且立即不可能。 即使是模拟局部改进的贪婪交换策略也无法在组合输入规模下生存。 

微妙的边缘情况来自较小的 n 值，其中关于位模式的直觉可能会产生误导。 对于 n = 1，只有排列是 [1]，所以答案很简单。 对于 n = 2，两种排列给出相同的分数，因为 1 XOR 1 + 2 XOR 2 等于 0，并且 1 XOR 2 + 2 XOR 1 也等于 0。对于较大的 n，该结构变得有意义，因为较高位主导 XOR 贡献，并且相对于索引的数字排列决定了高位被激活的频率。 

## 方法

 强力解决方案将枚举所有排列，计算每个排列的异或和，并跟踪最大值。 这是可行的，因为每个排列的分数可以以 O(n) 的形式进行评估，因此正确性很简单。 问题在于规模。 有n个！ 排列，即使对于 n = 10，这也已经太大了，而这里的 n 高达 10^5，使得暴力破解完全不可行。 

关键的观察结果是该函数的每位都是可分离的。 每个位对总和的贡献独立，具体取决于该位在 i 和 p[i] 之间是否不同。 当 i 和 p[i] 的位值不同时，一位恰好为 XOR 贡献 1。 因此，对于每一位，我们都在有效地尝试最大化索​​引和分配值之间发生的不匹配数量。 

这将问题转化为构造一个排列，同时最大化所有位位置上的按位不匹配。 最佳策略是以翻转尽可能多的高位的方式对索引和值进行配对，而实现这一点的结构是范围内的按位补配对。 

具体来说，如果我们考虑二进制数直到 n 的最高位，那么利用固定索引最大化 XOR 的最佳方法是为其分配一个尽可能在二进制空间中的值。 这导致将 i 与值 j 配对，使得 i XOR j 局部最大化，这全局对应于将每个数字映射到其按位补码，限制为包含 n 的最小二次方块。 

出现了直接构造：在两个块的最高幂内工作，将每个索引 i 映射到（掩码 XOR i），其中掩码是最大的全 1 值，其位长度与 n 减 1 相同。完整块之外的值通过保持固定或在剩余范围内调整来处理。 

这会产生一种排列，首先最大化最高有效位的位翻转，这在总和中占主导地位。

 ## 算法演练

 我们直接使用当前位长度 n 内的按位补逻辑构造排列。

1. 计算大于n的最小二的幂，称之为m。 我们将掩码定义为 m − 1，它是一个二进制数，所有位都设置为 n 所需的最高位。 该掩码代表我们想要操作的完整位空间。 
2. 对于从 1 到 n 的每个数字 i，计算候选值 j = 掩码 XOR i。 该值是掩码宽度内 i 的按位补码，这保证了二进制表示的最大分离。 选择此步骤是因为当位不同时 XOR 最大化。 
3. 如果 j 在有效范围 [1, n] 内且尚未分配，则分配 p[i] = j。 这确保我们在尝试强制执行最大异或配对时保持有效的排列。 
4. 如果 j 无效或已使用，则指定 p[i] = i 作为后备。 这在不破坏约束的情况下保留了排列有效性。 
5. 输出结果数组。 

贪婪配对之所以有效，是因为补码映射是对合：应用两次会返回原始数字。 这意味着有效的配对是自然形成的，并且每个作业要么完成一对，要么安全地回退。 

### 为什么它有效

 该构造首先尝试使最高可能位位置处的位差最大化。 由于异或和由较高位主导，因此将数字与其在有效位宽度内的按位补码配对可以最大化每对的贡献。 对合性质确保只要 i 及其补码都在范围内，它们就会形成不相交的对，从而防止冲突并保证有效的排列。 仅当 n 不是 2 的完整幂块时，才会出现任何剩余元素，并且这些元素无法配对以在不破坏有效性的情况下提高更高位的贡献，因此在约束下修复它们是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        m = 1
        while m <= n:
            m <<= 1
        mask = m - 1

        p = [-1] * (n + 1)
        used = [False] * (n + 1)

        for i in range(1, n + 1):
            if p[i] != -1:
                continue
            j = mask ^ i
            if 1 <= j <= n and p[j] == -1:
                p[i] = j
                p[j] = i
            else:
                p[i] = i

        print(*p[1:])

if __name__ == "__main__":
    solve()
```该实现首先确定覆盖 n 以内所有值的二进制掩码。 然后它会迭代每个位置并尝试将其与该掩码下的补码进行配对。 支票`p[j] == -1`确保每个数字仅使用一次。 如果无法配对，则将该元件固定到位。 

一个微妙的点是，我们必须按顺序迭代，并且仅在一对的两端都未使用时才进行分配。 否则，我们将面临覆盖早期决策并破坏排列有效性的风险。

 ## 边缘情况

 对于 n = 1，算法将 mask 设置为 1 并尝试配对，但 i = 1 映射到 j = 0，这是无效的，因此 p[1] = 1。输出是正确的，因为没有替代排列。 

对于 n = 2，掩码为 3。对于 i = 1，j = 2，因此我们分配 p[1] = 2 且 p[2] = 1。这表明，当范围允许时，配对机制可以正确形成完整交换。 

对于 n = 3，掩码为 3。配对给出 (1,2) 并将 3 固定，这与最佳结构匹配，因为 3 在范围内没有有效的补集。
