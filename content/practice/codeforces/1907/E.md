 ## 解决方案
 ## 问题理解

 我们需要计算非负整数的有序三元组$(a,b,c)$其总和恰好是$n$。 不寻常的部分是数字和条件：$$\text{digsum}(a)+\text{digsum}(b)+\text{digsum}(c)=\text{digsum}(n).$$仅当两个条件都成立时才算三元组。 由于顺序很重要，$(1,2,3)$和$(3,2,1)$是不同的三元组。 

的价值$n$可以大到$10^7$，并且可以有$10^4$测试用例。 任何迭代可能值的算法$a$,$b$， 和$c$立刻就不可能了。 甚至迭代所有对$(a,b)$需要大约$10^{14}$最坏情况下的操作。 

关键的限制不是尺寸$n$，但事实是$n$最多有 8 位小数。 这强烈表明答案取决于逐位的十进制表示形式，而不是数值本身。 

有一些边缘情况很容易误导简单的解决方案。 

为了$n=0$，唯一有效的三元组是$(0,0,0)$。 答案是$1$。 假设每个数字都有多种可能性的公式将错误地返回更大的值。 

为了$n=10$，有效的三元组并非全部解$a+b+c=10$。 例如，$(5,5,0)$有数字和$5+5+0=10$， 尽管$\text{digsum}(10)=1$，所以无效。 进行操作很重要。 

为了$n=10000000$，大多数数字为零。 粗心的数字 DP 可能会意外地允许位置之间的进位并计算出许多额外的配置。 正确答案只有$3$，对应于将整个值恰好放入三个数字之一。 

## 方法

 暴力解决方案将枚举所有三元组$(a,b,c)$和$a+b+c=n$，然后检查数字和条件。 自从$c$是由$a$和$b$，这大约需要$$\sum_{a=0}^{n}(n-a+1)=O(n^2)$$州。 

为了$n=10^7$，即周围$10^{14}$迭代，完全不可行。 

关键的观察来自于小数加法的标准属性。 每当发生进位时，数字和的总和就会减少数倍$9$。 

对于任何非负整数，$$\text{digsum}(x)+\text{digsum}(y)-\text{digsum}(x+y)$$等于$9$乘法过程中产生的进位数。 

如此反复应用，$$\text{digsum}(a)+\text{digsum}(b)+\text{digsum}(c)-\text{digsum}(n)$$是$9$乘以三个数字相加时发生的进位总数。 

我们的条件要求这个差异恰好为零。 由于进位只能使左侧变大，所以唯一的可能是**任何地方都没有进位发生**。 

这完全改变了问题。 我们考虑的不是数字，而是数字。 

假设一个数字$n$是$d$。 由于不允许进位，所以对应的数字$x,y,z$的$a,b,c$必须满足$$x+y+z=d.$$不同的数字位置变得独立。 有效三元组的数量只是每个数字的数字三元组数量的乘积$n$。 

对于固定数字$d$，我们需要的非负解的数量$$x+y+z=d.$$自从$d\le 9$，数字界限$x,y,z\le 9$就自动满足了。 

通过星星和酒吧，$$\#(x+y+z=d)=\binom{d+2}{2}.$$每个数字独立贡献，所以最终答案是$$\prod_{\text{digits } d \text{ of } n} \binom{d+2}{2}.$$| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 最佳 |$O(\text{digits}(n))$|$O(1)$| 已接受 |

 ## 算法演练

 1. 预先计算值$$f[d]=\binom{d+2}{2}$$对于数字$d=0$通过$9$。 
2. 对于每个测试用例，转换$n$到它的十进制表示形式。 
3. 将答案初始化为$1$。 
4. 处理每个数字$d$的$n$。 
5. 将答案乘以$f[d]$。 

这计算所有数字三元组$(x,y,z)$其总和等于$d$在那个位置。 
6. 处理完所有数字后，输出乘积。 

### 为什么它有效

 数字和条件相当于说加法过程中不发生进位$a+b+c=n$。 即使出现 1 个进位，数量$$\text{digsum}(a)+\text{digsum}(b)+\text{digsum}(c)$$变得严格大于$\text{digsum}(n)$的倍数$9$。 

当没有进位时，每个小数位是独立的。 在数字位置，其中$n$包含数字$d$，选择的数字$a$,$b$， 和$c$只需要满足$x+y+z=d$。 这样的三元组的数量是$\binom{d+2}{2}$。 由于不同位置的选择不会相互作用，因此乘法原理给出了所有数字的乘积。 因此，每个有效的三元组都被精确地计数一次，并且每个计数的配置都会产生一个有效的三元组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# f[d] = C(d + 2, 2)
ways = [(d + 2) * (d + 1) // 2 for d in range(10)]

t = int(input())

for _ in range(t):
    n = input().strip()

    ans = 1
    for ch in n:
        ans *= ways[ord(ch) - ord('0')]

    print(ans)
```数组`ways`存储非负解的数量$x+y+z=d$对于每个数字$d$。 自从$d\le 9$，星条公式直接适用。 

对于每个测试用例，我们将数字读取为字符串。 这避免了通过除法重复提取数字，并且自然地处理高达$10^7$。 

答案开始于$1$。 每个数字贡献一个独立的乘法因子，所以我们乘以`ways[d]`对于每个数字。 

Python 整数会自动扩展为任意大小，这很有用，因为诸如此类的答案$9999999$超过 32 位和 64 位限制。

 ## 边缘情况

 考虑输入：```
1
0
```该算法处理单个数字$0$。 其贡献是$$\binom{2}{2}=1.$$最终的答案是$1$，对应唯一的三元组$(0,0,0)$。 

考虑输入：```
1
10
```数字是$1$和$0$。 他们的贡献是$3$和$1$。$$3 \times 1 = 3.$$有效的三元组恰好是$(10,0,0)$,$(0,10,0)$， 和$(0,0,10)$。 任何三元组，例如$(5,5,0)$在个位创建进位并违反数字和条件。 该算法会自动排除它，因为它只计算无进位数字分配。 

考虑输入：```
1
10000000
```数字贡献为$$3 \times 1 \times 1 \times 1 \times 1 \times 1 \times 1 \times 1 = 3.$$只有一个数字可以包含前导$1$，而其他两个必须为零。 算法正确返回$3$。 

考虑输入：```
1
9999999
```每个数字都有贡献$$\binom{11}{2}=55.$$答案就变成了$$55^7=1522435234375.$$这会检查实现是否正确处理非常大的答案，并依赖于 Python 的任意精度整数而不是固定宽度算术。
