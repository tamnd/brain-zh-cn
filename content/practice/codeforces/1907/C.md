 ## 问题理解

 给定一串小写字母，如果相邻字母不同，我们可以重复删除它们。 目标是将字符串减少到尽可能的最小长度。 输入由多个测试用例组成，每个测试用例最多包含 200,000 个字符的字符串，并且所有测试用例的总长度不超过 200,000。 

这意味着我们的解决方案在每个字符串的长度上必须是线性的，因为任何二次方法都可以执行$n^2 \approx 4 \cdot 10^{10}$最坏情况下的操作，远远超出了1秒的时间限制。 每次删除仅影响相邻字符，因此该问题具有很强的局部属性，建议采用贪婪或基于堆栈的方法。 

边缘情况包括已经由重复字符组成的字符串、具有交替字符的字符串以及长度为 1 或 2 的非常短的字符串。例如，字符串`"aa"`根本无法减少，产生的最小长度为 2，而`"ab"`可以完全删除，导致 0。以任意顺序删除字符的粗心实现可能无法达到最小值，因为删除的顺序会影响保留的字母。 

## 方法

 暴力方法会从左到右重复扫描字符串，删除遇到的第一对不同的相邻字符，然后重新启动。 这个过程是正确的，因为每个允许的操作都会将字符串减少两个字符，但它非常慢：每次传递都可以$O(n)$并且可能最多有$O(n/2)$删除，产生最坏情况的复杂性$O(n^2)$。 为了$n = 2 \cdot 10^5$，这太慢了。 

最佳方法的关键见解是注意删除操作仅取决于扫描字符串时最后一个不匹配的字符。 这自然会导致基于堆栈的贪婪解决方案：从左到右遍历字符串，将字符推入堆栈。 当当前字符与堆栈顶部不同时，它们形成可移动的对，因此弹出顶部而不是压入。 这确保了在可能的情况下立即应用每对删除，并且最终的堆栈长度表示最小字符串长度。 

暴力破解之所以有效，是因为它只删除有效的对，但当字符串由于重复重新扫描而很长时，就会失败。 我们可以维护一个堆栈来处理本地决策，从而将时间复杂度降低到$O(n)$因为每个字符最多被压入和弹出一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 基于堆栈的优化 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化一个空堆栈。 这将存储尚未删除的字符。 
2. 迭代每个字符`c`在字符串中。 
3.如果栈不为空且栈顶字符与`c`，弹出堆栈。 这表示删除相邻的对。 
4. 否则，推`c`到堆栈上。 这意味着`c`无法与前一个字符一起删除。 
5. 遍历字符串后，堆栈包含所有无法配对并删除的字符。 字符串的最小长度就是堆栈的大小。 

工作原理：在每一步中，堆栈都会为字符串的前缀维护一个正确的部分解决方案。 每次弹出对应于相邻不同字符的有效删除，并且不会丢失任何对，因为堆栈仅与最近的不匹配字符进行比较。 由于移除是局部的并且独立于邻接之外，因此这种贪婪的选择是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    stack = []
    for c in s:
        if stack and stack[-1] != c:
            stack.pop()
        else:
            stack.append(c)
    print(len(stack))
```说明：我们使用快速 I/O 来处理大输入。 如果每个字符无法与顶部形成可移动的对，则将其推入堆栈。 为每个测试用例打印堆栈的最终长度。 使用`strip()`确保没有换行符干扰字符比较。 由于在弹出之前正确检查了空堆栈，因此可以避免边界问题。
