 ## 解决方案
 ## 问题理解

 我们得到一个数组，并且只允许使用两个严格的全局操作来修改它。 一个操作将数组向右旋转一个位置，将最后一个元素移动到前面。 另一个操作反转整个数组。 目标是使用尽可能少的操作将数组转换为非递减序列，或者确定这些操作的任何序列都无法实现排序数组。 

一个关键的观察结果是，这两种操作都不会更改元素的多重集，因此排序只是重新排列位置。 然而，允许的移动不会产生任意排列。 它们仅生成原始数组或其反向旋转的数组。 这已经暗示了一个强大的结构限制：可达状态最多形成 2n 个不同的配置。 

约束条件很大，测试用例总数高达 200000 个。任何模拟操作序列或尝试对状态进行 BFS 的解决方案都是立即不可能的。 在最坏的情况下，即使每个测试用例的 O(n^2) 也会太慢。 

当数组已经排序或在反转后变得排序时，会出现微妙的边缘情况。 另一个棘手的情况是所有元素都相等。 在这种情况下，这两个操作仍然会更改数组状态，但数组始终是排序的，并且答案必须为零。 

更危险的失败情况是假设每个数组都可以单独通过旋转进行排序。 例如，[3, 1, 2] 没有旋转使其排序，并且反转也没有帮助，因为它变成了 [2, 1, 3]，这也不能循环排序为非递减顺序。 

## 方法

 蛮力的想法是通过重复应用移位和反向操作来探索所有可到达的状态。 由于每个状态可以再生成两个状态，因此这成为一个最多具有 2n 个节点的图，但状态之间的转换并不能保证降低复杂性。 事实上，如果我们明确地处理操作序列，搜索空间会随着操作长度呈指数级爆炸。 

关键的结构见解是移位产生循环旋转，并且反向翻转遍历的方向。 因此，每个可达数组要么是原始数组的旋转，要么是反转数组的旋转。 不可能有其他排列，因为这两种操作都保留邻接结构直到循环旋转和反转。 

因此，问题简化为检查线性阵列及其反转版本的所有旋转。 对于每个候选排列，我们检查它是否已排序。 如果是，我们计算需要多少次移位才能达到它，并且可以选择使用一个反向操作。 

答案是以下各项中的最小值：

 - 原始数组的旋转
 - 反转数组的旋转加上一次反转成本

 如果没有旋转产生排序数组，则答案为 -1。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 旋转检查| 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将问题转换为检查两个数组的循环移位：原始版本和反转版本。

1. 将数组与其自身连接起来。 这允许我们将所有旋转表示为长度为 n 的连续子数组。 这避免了显式旋转模拟。 
2. 预先计算此双倍数组中任何大小为 n 的窗口是否按非降序排序。 我们通过跟踪窗口内相邻反转的数量来做到这一点。 
3. 对于原始数组，在加倍数组上滑动大小为 n 的窗口并检测有效的排序旋转。 每个有效窗口对应一个旋转。 所需的移位次数由该窗口的起始索引确定。 
4. 对反转的数组重复相同的过程。 这说明了在旋转之前只需要一次反转操作的解决方案。 
5. 答案是所有有效配置中的最少操作次数。 如果数组已经排序，则答案为零。 

### 为什么它有效

 允许的操作精确生成数组索引的二面体群：旋转形成循环群，反转引入反射。 任何可达配置要么是原始序列的旋转，要么是其反转版本的旋转。 因此，枚举这两个族涵盖了所有可能性，并检查它们之间的排序性保证了最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    
    def best(arr):
        b = arr + arr
        
        bad = 0
        for i in range(n - 1):
            if b[i] > b[i + 1]:
                bad += 1
        
        res = float('inf')
        
        for i in range(n):
            if i > 0:
                if b[i - 1] > b[i]:
                    bad -= 1
                if b[i + n - 2] > b[i + n - 1]:
                    bad += 1
            
            if bad == 0:
                res = min(res, i)
        
        return res
    
    ans = best(a)
    ans_rev = best(a[::-1])
    
    if ans == float('inf') and ans_rev == float('inf'):
        return -1
    
    res = float('inf')
    if ans != float('inf'):
        res = min(res, ans)
    if ans_rev != float('inf'):
        res = min(res, ans_rev + 1)
    
    return res

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(solve_case(a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```功能`best`计算从固定方向获得排序数组所需的最小移位数。 加倍技巧确保每次旋转对应于长度为 n 的窗口。 

我们跟踪窗口内的“坏相邻对”，而不是每次都重新检查整个段。 当窗口滑动一个位置时，只有两个邻接关系发生变化，因此我们以 O(1) 的时间更新计数。 

最终答案对比了两种情况：直接旋转原数组或者先反转再旋转。 逆转算作一项操作成本。

 ## 边缘情况

 一个微妙的情况是数组已经非递减但不是严格递增。 该算法仍必须将其视为有效而不执行任何操作。 由于滑动窗口在索引零处检测到完全排序的窗口，因此它正确地返回零。 

当多个相等的值创建许多有效的旋转时，会出现另一种边缘情况。 滑动窗口方法仍然有效，因为相等不会导致“坏”反转，因此所有相等的段始终被视为已排序。
