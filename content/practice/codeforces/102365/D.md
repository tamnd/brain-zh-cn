 ## 解决方案
 ## 问题理解

 我们有编号从 1 到 (N) 的行星，而节日正好在其中的一颗上。 Astrodavid 从行星 1 开始。跳跃 (d>0) 个行星的成本为 (f_d)，而跳跃 (d<0) 个行星的成本为 (f_d)，其中输入给出了最多 (J) 的每个位移的成本。 

每次着陆后，阿斯特罗戴维都可以询问方向。 答案告诉他隐藏的节日星球是否小于他当前的星球，等于它，或者大于它。 目标是自适应地选择跳跃，以便最终到达每个可能的节日地点，同时最小化所有可能地点消耗的最大总燃料。 

思考信息的有用方法是将其视为一个区间。 一旦我们查询了某个行星（p），一个表示节日较高的响应将可能的行星限制为后缀，而较低的响应将它们限制为前缀。 因此，该策略是一个决策树，其节点是被查询的行星，但额外的复杂性是在两个查询之间移动具有与方向相关的成本。 

官方的约束有(2\le N\le4000)和(1\le J\le N/2)。 三次动态程序已经需要大约 (4000^3=64) 十亿次基本转换，远远超出一秒的限制。 预期的解决方案必须保持在 (O(N^2)) 左右。 跳转成本最多为 (10^4)，因此总答案可以轻松地适合 64 位整数，尽管 Python 整数消除了任何溢出问题。 

有两个容易犯的边界错误。 首先，行星 1 已经被免费查询。 例如，与```
2 1
7
3
```答案是 7，而不是 0，因为节日可能在 2 号行星上，唯一可能的跳跃是 (+1)。 其次，第一个有用间隔包含行星 2 到 (N)，而不是行星 1 到 (N)，因为行星 1 已经被检查过。 

一个更微妙的问题是，最佳策略不必单调地走向节日。 例如，```
4 2
100 0
0 0
```允许使用零燃料的序列 (1\to3\to2\to4)。 从 3 到 2 的跳跃远离已知高于 3 的节日，但它使船处于最终跳跃到 4 的位置。 任何假设每次跳跃都必须朝着目标移动的解决方案都是不正确的。 

## 方法

 直接区间动态程序是自然的起点。 假设当前可能的行星形成一个区间，而飞船就位于该区间的一端之外。 如果我们选择该区间的第 (k) 个行星作为下一个查询，则一个答案留下 (k-1) 个候选，另一个答案留下剩余的候选。 跳跃后所需的燃料是这两个分支的最大需求。 

如果移动到下一个查询的成本已知，这会给出正确的极小极大递归。 困难在于，阿斯特罗达维德可能会在方向已知的情况下进行几次跳跃，而这些跳跃纯粹是为了重新定位飞船。 上一节中的示例说明了为什么忽略这种重新定位会产生错误的答案。 

关键的观察结果是，在下一次有用的比较之前进行的一系列跳跃可以被压缩为其最小可能的燃料成本。 成本仅取决于位移，因此这个重新定位问题本身就是一维平移不变图上的最短路径问题。 一旦知道了这些有效的移动成本，搜索部分就变成了区间极小极大 DP。 

对于净位移 (d)，令 (g_d) 为移动恰好 (d) 个行星所需的最小燃料，允许任意中间跳跃。 仅需要与单个有用查询相关的位移。 我们通过从 (-J) 到 (J) 的位移的最短路径计算来计算这些有效成本。 从位移 (x) 到 (x+i) 的转换成本为 (f_i)。 

由此产生的有效成本让间隔 DP 将整个重新定位序列视为一个动作。 然后搜索循环只需要考虑进行下一次比较的位置。 

强力间隔 DP 将检查每个间隔的每个可能的分割，给出 (O(N^3)) 时间。 计算有效成本后，优化公式具有 (O(NJ)) 次搜索转换，并且 (J\le N/2)，因此为 (O(N^2))。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力间隔 DP | (O(N^3)) | (O(N^2)) | 太慢了 |
 | 有效移动成本+间隔DP| (O(NJ+J^2)) | (O(N+J)) | 已接受 |

 ## 算法演练

 1. 构建位移状态 (-J,-J+1,\ldots,J) 上的定向运动图。 从状态 (x)，(i) 的跳跃移动到 (x+i)，前提是所产生的位移保持在所考虑的范围内，并且成本为 (f_i)。 从位移 0 开始运行最短路径计算。生成的到位移 (d) 的距离是实现净位移 (d) 的最便宜的方法。 
2. 从这些最短路径距离中提取有效的向上和向下移动成本。 有用的查询到达 (d) 个行星到右侧的成本 (g_d)，而查询 (d) 个行星到左侧的成本 (g_{-d})。 
3. 将 (L[m]) 定义为当飞船紧邻候选行星左侧时，在 (m) 个连续候选行星中定位节日所需的最低最坏情况燃料。 当船紧邻其右侧时，对称地定义 (R[m])。 空间隔的值为零。 
4. 要计算 (L[m])，请选择下一个查询的行星作为左起第 (k) 个候选行星。 达到它的成本是(g_k)。 如果节日位于该行星下方，则还剩下 (k-1) 个候选者，并且飞船就在他们的右侧，给出成本 (R[k-1])。 如果节日在它上面，则有 (m-k) 个候选者，并且船就在他们的左边，给出成本 (L[m-k])。 最差的分支花费这两个值中的最大值。 
5. 对每个可行的 (k) 取最小值。 因此

 \min_{1\le k\le\min(J,m)}
 \左(
 g_k+\max(R[k-1],L[m-k])
 \右）。 
]

1. 对称计算(R[m])。 如果从右边数第（k）颗行星，则跳跃成本为（g_{-k}）。 较低的节日让 (m-k) 名候选人的船在他们的右侧，而较高的节日让 (k-1) 名候选人的船在他们的左边。 因此

 \min_{1\le k\le\min(J,m)}
 \左(
 g_{-k}+\max(R[m-k],L[k-1])
 \右）。 
]

 1. 众所周知，1 号行星在消耗任何燃料之前都会进行检查。 如果节日到了，我们就结束了。 否则，剩下的候选行星是行星 2 到 (N)，而飞船就在它们的左边。 因此所需的初始燃料为(L[N-1])。 

### 为什么它有效

 对于每个间隔，DP 都会考虑可以进行下一次信息比较的每个可能的行星。 方向响应将剩余的候选者精确地划分为两个较小的区间，并且对手可以强制哪个分支需要更多的燃料，这解释了每次转换中的最大值。 信息比较之间的重新定位被压缩为尽可能短的移动成本，因此用其有效位移成本替换这样的序列不会丢失任何策略。 由于每个可能的下一个比较和每个结果分支都由递归表示，因此所有选择的最小值恰好是最小最坏情况燃料需求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def shortest_displacement_cost(up, down, J):
    size = 2 * J + 1
    offset = J

    dist = [INF] * size
    used = [False] * size
    dist[offset] = 0

    for _ in range(size):
        u = -1
        best = INF

        for i in range(size):
            if not used[i] and dist[i] < best:
                best = dist[i]
                u = i

        if u == -1:
            break

        used[u] = True
        pos = u - offset

        lo = max(-J, pos - J)
        hi = min(J, pos + J)

        for nxt in range(lo, hi + 1):
            if nxt == pos:
                continue

            d = nxt - pos
            if d > 0:
                w = up[d - 1]
            else:
                w = down[-d - 1]

            v = nxt + offset
            nd = best + w
            if nd < dist[v]:
                dist[v] = nd

    return dist

def solve():
    N, J = map(int, input().split())
    up = list(map(int, input().split()))
    down = list(map(int, input().split()))

    dist = shortest_displacement_cost(up, down, J)
    offset = J

    effective_up = [INF] * (J + 1)
    effective_down = [INF] * (J + 1)

    for d in range(1, J + 1):
        effective_up[d] = dist[offset + d]
        effective_down[d] = dist[offset - d]

    left = [0] * N
    right = [0] * N

    for m in range(1, N):
        best_left = INF
        limit = min(J, m)

        for k in range(1, limit + 1):
            cost = effective_up[k]
            branch = max(right[k - 1], left[m - k])
            value = cost + branch
            if value < best_left:
                best_left = value

        left[m] = best_left

        best_right = INF

        for k in range(1, limit + 1):
            cost = effective_down[k]
            branch = max(right[m - k], left[k - 1])
            value = cost + branch
            if value < best_right:
                best_right = value

        right[m] = best_right

    print(left[N - 1])

if __name__ == "__main__":
    solve()
```代码的第一部分构造位移图。 位移状态表示船舶距离有用的比较序列开始的位置有多远。 每次合法的跳跃最多会改变排量 (J)，并具有相应的输入燃料成本。 

密集 Dijkstra 实现是合适的，因为只有 (2J+1) 个位移状态。 对于 (J\le2000)，最多有 4001 个状态，并且放宽所有可能的跳跃长度给出 (O(J^2)) 工作。 

两个有效成本数组包含每个净位移的最便宜成本。 它们允许间隔 DP 忽略重新定位序列的内部细节。 

数组`left`和`right`存储两个间隔方向。 他们的零条目代表一个已经确定的节日，因此没有剩余候选者的分支贡献零燃料。 

循环结束`m`正在增加，因为每个转换仅涉及小于`m`候选人。 循环结束`k`停在`J`，因为通过大于跳跃功率的单次跳跃无法达到有用的查询。 

最终的答案是`left[N - 1]`，而不是`left[N]`，因为在消耗任何燃料之前，行星 1 会被免费查询。 

Python 整数具有任意精度，因此大哨兵值和累积燃料值不会溢出。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(J^2+NJ)) | 密集最短路径使用 (O(J^2))，并且间隔 DP 对每个 (N) 间隔大小最多检查 (J) 个分割。 |

 ## 边缘情况

 最小尺寸的情况下只有两颗行星。 和```
2 1
7
3
```立即检查行星 1。 如果节日不在那里，那么它一定在行星 2 上，唯一可能的跳跃是 (+1)，花费 7。算法从`left[0] = right[0] = 0`，计算`left[1] = 7`，并打印`left[1]`。 

同等成本会产生对称问题。 和```
5 2
5 5
5 5
```最好的策略可以重复分割剩余的间隔，同时每次有效的跳跃支付 5 美元。 计算出的答案是 15。由于两个移动方向具有相同的成本，因此左右 DP 阵列的演化相同。 

零成本移动是另一个有用的边界条件。 和```
4 2
0 0
0 0
```每一次合法的跳跃都是免费的。 DP 通过每个间隔大小传播零，因此`left[3]`为零，最终答案也为零。 

不对称的情况是实现保持的原因`left`和`right`分别地。 向下跳跃可能比向上跳跃便宜得多，因此在查询之后，两个方向分支可能具有非常不同的成本。 递归总是选择两个分支要求中的最大值，因为隐藏的节日可以位于任一分支中。 

最后，必须独立于间隔大小来强制执行跳跃限制。 当一个区间包含少于 (J) 个候选者时，只有这些候选者可以作为下一个信息查询到达。 当它包含多于（J）个候选者时，从当前边界一跳最多可以考虑（J）个位置。 这`min(J, m)`limit 可以处理这两种情况，而不会出现差一错误。
