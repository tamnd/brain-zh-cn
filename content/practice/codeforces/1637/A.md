 ## 解决方案
 ## 问题理解

 我们有一个数组，并且被迫只执行一项操作。 我们选择一个将数组分成两个非空部分的位置。 然后我们分别对左部分和右部分进行排序。 问题是是否存在某些分割，导致最终的整个数组仍未排序。 

对于每个测试用例，我们必须回答`"YES"`如果至少一次分割产生一个未排序的数组，并且`"NO"`如果每个可能的分割都会产生一个全局排序的数组。 

所有测试用例的元素总数仅为$10^4$，因此即使是二次算法也能轻松地满足限制。 这意味着性能并不是这里真正的挑战。 困难在于识别隐藏在操作内部的结构。 

一个容易犯的错误是认为分别对两个部分进行排序总是会产生一个排序数组。 考虑```
3
2 2 1
```选择第一个元素后的分割给出```
[2] + [2,1]
```对每一面进行排序后：```
[2] + [1,2]
```这变成```
[2,1,2]
```并且没有排序。 正确答案是`"YES"`。 

另一种可能误导粗心解决方案的情况是已经排序的数组：```
5
1 2 2 4 4
```无论我们在哪里拆分，左侧的最大元素永远不会超过右侧的最小元素。 每个结果数组都保持排序，所以答案是`"NO"`。 

重复的内容也值得关注。 例如，```
4
1 3 3 2
```在第三个元素之后拆分给出```
[1,3,3] + [2]
```排序后，没有任何变化：```
[1,3,3,2]
```这仍然是未排序的。 相同的值是无害的，只有严格的反转才重要。 

## 方法

 直接方法会尝试所有可能的拆分。 对于每个位置，我们独立地对前缀和后缀进行排序，将它们连接起来，并检查整个数组是否已排序。 有$n-1$可能的分裂点，每次尝试都会执行两种排序和一次线性检查。 最坏的情况大概是$O(n^2 \log n)$。 和$n\le10^4$，这仍然会通过，但它执行的工作比必要的多得多。 

蛮力起作用的原因是，在对每个部分进行排序后，唯一可能保留无序的地方是两个部分之间的边界。 在每件作品中，一切都已排序。 

假设我们在位置后分割$i$。 排序后，左侧以最大元素结束，右侧以最小元素开始。 整个数组恰好在以下时间排序：$$\max(\text{left}) \le \min(\text{right})$$如果相反$$\max(\text{left}) > \min(\text{right}),$$那么这两个边界元素会产生反转，并且最终的数组未排序。 

现在观察一些更简单的事情。 如果原始数组包含任何反转$a_i>a_j$和$i<j$，然后在这些位置之间进行分割，将较大的值放在左半部分，将较小的值放在右半部分。 内部排序后，左半部分仍然包含较大的值作为其最大值的一部分，右半部分仍然包含较小的值作为其最小值的一部分，因此边界保持反转。 

这意味着答案是`"YES"`恰好当原始数组本身未排序时。

 ## 算法演练

 1. 读取数组。 
2. 从左到右扫描相邻对，因为非递减数组必须满足$a_i\le a_{i+1}$到处。 
3. 如果某些相邻对满足$a_i>a_{i+1}$，数组已包含反转。 输出`"YES"`。 

单个相邻反转就足够了，因为选择这两个元素之间的分割会使左侧最大值大于右侧最小值。 

1. 如果不存在这样的对，则数组已按非降序排序。 输出`"NO"`。 

### 为什么它有效

 对任何前缀和后缀进行独立排序后，排序数组仍保持排序状态。 相反，如果原始数组包含反转，则还必须存在相邻反转。 在这两个元素之间进行分割，较大的值位于左半部分，较小的值位于右半部分。 对每一边进行排序并不能消除这种跨界反转。 因此该操作会产生一个未排序的数组。 这两个事实完全说明了答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ok = False
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            ok = True
            break

    print("YES" if ok else "NO")
```对相邻元素的循环就足够了，因为每个未排序的数组都包含至少一个相邻的反转。 一旦找到这样的一对，我们就可以立即停止，因为一个证人就足够了。 

该实现避免了不必要的排序，并且仅使用恒定的额外内存。 边界条件很简单，因为循环从`0`到`n-2`， 制作`a[i+1]`始终有效。
