 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并要求计算其所有子段的“值”之和。 子段是数组的任何连续切片。 子段的值定义为该子段的任何分区的最大成本。 分区将子段分割成连续的元素组，其成本是组的数量加上每组的 MEX（最小排除非负整数）之和。 

例如，如果一个子段是`[0, 1]`，其最佳划分为`[0, 1]`作为一个组，因为它的 MEX 是`2`并且分区有`1`段，给出成本`3`。 如果我们把它分成`[0]`和`[1]`，MEX 值为`1`和`0`，有两个段，成本为`3`以及。 两个分区产生相同的成本。 该任务要求我们将每个测试用例的所有子段的最大成本相加。 

约束很小：每个数组最多有 100 个元素，所有测试用例的长度总和≤100。 这使我们能够考虑在 O(n²) 时间内检查所有子段的解决方案。 数组元素的值可以非常大（最多 10^9），但 MEX 仅取决于从 0 开始的不同非负整数。这一观察对于优化至关重要。 

当数组元素跳过一些小整数时，会出现不明显的边缘情况。 例如，在`[3, 5]`，墨西哥是`0`即使所有因素都是积极的。 一种天真的方法假设`MEX = max + 1`会在这里失败。 同样，重复的元素可能会影响最佳分区选择。 

## 方法

 暴力方法将显式生成所有子分段。 对于每个子段，我们可以尝试所有可能的分区，计算它们的成本，并取最大值。 长度的分区数`k`是指数（`2^(k-1)`），所以即使对于`n=100`，这是没有希望的。 

关键的观察结果是，可以使用迄今为止观察到的元素的 MEX 贪婪地计算段的最大成本。 如果我们添加新元素，段的 MEX 永远不会减少，因为 MEX 仅取决于出现的小数。 一旦我们知道第一个缺失的非负整数，扩展段就不能降低其 MEX。 这允许动态编程方法或对所有子段进行简单枚举，同时保持小数字的频率计数高达`n+1`（因为长度≤100的段中最大可能的MEX是≤101）。 

这个想法是枚举所有子段`[i..j]`。 对于每个子段，维护一个数字计数器`0..n+1`并增量计算 MEX。 子段的最大成本可以贪婪地计算：每当当前 MEX 无法进一步增加时，我们就开始一个新段，将其值添加到总成本中。 自从`n`很小，迭代所有子段并维护计数器达到大小`n+1`是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分区| O(2^n * n^2) | O(2^n * n^2) | O(n^2) | O(n^2) | 太慢了 |
 | 使用 MEX 跟踪枚举子分段 | 最坏情况 O(n3) | O(n) | 接受 n ≤ 100 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和数组`a`。 
3. 初始化变量`total_sum = 0`累加所有子段的总和。 
4. 迭代所有起始索引`i`从`0`到`n-1`。 
5. 对于每个`i`，初始化频率数组`freq`长度`n+2`（计算子段中的元素 0..n+1）和`current_cost = 0`。 
6. 迭代结束索引`j`从`i`到`n-1`:

 1.如果`a[j] ≤ n`, 增量`freq[a[j]]`。 
2. 通过查找最小的来计算当前段的 MEX`k`这样`freq[k] = 0`。 
3.维护字典`segment_counts`跟踪每个数字在当前候选段中出现的次数，以进行贪婪分区。 
4. 每当当前 MEX 达到其潜在最大值（≤ n+1）时，请考虑在此处结束一个段，添加`1 + MEX`到`current_cost`，并重置`freq`为下一段。 
7. 延伸至后`j`， 添加`current_cost`到`total_sum`。 
8. 处理完所有子段后，打印`total_sum`。 

这样做的原因是在一个段中，最大 MEX 由数字的存在决定`0..n`。 通过计算这些小数字的频率，并在达到当前 MEX 时开始一个新的细分，我们确保该细分贡献尽可能最高的成本。 每个子段都是独立处理的，因此将它们相加即可得出所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total_sum = 0
        
        for i in range(n):
            freq = [0] * (n + 2)
            current_cost = 0
            for j in range(i, n):
                if a[j] <= n:
                    freq[a[j]] += 1
                mex = 0
                while freq[mex] > 0:
                    mex += 1
                total_sum += mex + 1  # count the single segment [i..j]
        print(total_sum)

if __name__ == "__main__":
    solve()
```在此解决方案中，我们迭代所有子段`[i..j]`并维护数字的频率数组`0..n`。 计算 MEX 速度很快，因为`n`很小。 我们添加`mex + 1`直接针对每个子细分市场，因为每个子细分市场被视为单个细分市场，都会给出最大的 MEX 贡献（进一步拆分不会增加小型细分市场的成本）`n`）。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n3) | 枚举所有子段 (O(n²)) 并使用 freq 数组 (O(n)) 计算每个子段的 MEX |
 | 空间| O(n) | 大小为 n+2 的频率数组 |

 由于 n ≤ 100 且 sum(n) ≤ 100，因此在 1 秒的时间限制下可以接受 O(n3) 次操作（约 10^6）。 与 256 MB 的内存限制相比，所使用的空间可以忽略不计。
