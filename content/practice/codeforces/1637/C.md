 ## 解决方案
 ## 问题理解

 我们得到一排石堆，每堆都包含一定数量的石头。 唯一允许的操作是从中间的一堆石头中取出两块石头，并将它们重新分配为一块石头到左侧的一堆，一块石头到右侧的一堆。 目标是最终所有石头都集中在第一堆和最后一堆中。 

这个操作是高度结构化的：每次移动都保留了总的石子，但它也保留了这样一个事实，即任何质量的移动都是通过“中间生成器”堆发生的，该堆必须仍然至少有两个石子。 这种限制意味着我们不能自由地移动棋子，我们只能将棋子从内部位置向外“推”出去。 

输出要求达到所有中间桩都为零的配置所需的此类操作的最少数量。 如果不可能达到这样的配置，我们必须输出-1。 

约束条件很大：每个测试用例最多 100,000 个桩，最多 10,000 个测试用例，所有测试的总 n 限制为 100,000。 这立即排除了任何二次或大量模拟的方法。 每个测试用例的任何解决方案都必须是线性或接近线性的。 

小配置中会出现一个微妙的问题。 如果中间堆中没有至少两颗石子，则根本不可能进行任何操作。 例如，在类似的配置中`[1, 2, 1]`，我们可以只执行一项操作，但是在`[1, 1, 1]`我们根本无法开始。 当奇偶校验和重新分配约束使得即使总质量足够时也无法完全清除内部堆积物时，就会出现另一种失败情况。 

## 方法

 一种简单的方法是尝试直接模拟操作。 在每一步中，我们都会搜索有效的三元组`(i, j, k)`并贪婪地应用操作，直到内部堆中没有至少两块石头为止。 每次操作都会将内部堆中的石头总数减少恰好两个，因此模拟可能看起来很快收敛。 然而，每个步骤都需要扫描有效的中间索引并更新数组，导致每个操作可能需要 O(n) 工作量。 由于在最坏的情况下可能有 O(total books) 次操作，因此这会退化为 O(n^2) 行为，这对于 n 高达 100,000 来说太慢了。 

关键的见解是，该操作在如何减少内部质量方面是确定性的。 每次我们使用一堆 j 时，我们都会从中取出两块石头，并且这些石头总是向外移动。 这意味着每个内部堆都独立地贡献于清空它所需的操作总数，但前提是它积累了足够多的来自相邻堆的传入石头。 

我们观察到每个内部桩必须以零结束，而不是模拟运动，而减少它的唯一方法是重复应用以它为中心的操作。 位置 j 的每次操作都会将 a[j] 减少 2，并将一颗石头推到每一侧。 这表明每个堆贡献固定数量的操作，等于在考虑流入流后它可以处理的石子对的数量。 

该过程可以简化为从左到右的一次传递，跟踪我们前进的“可用石头”数量。 在每个位置，我们都会通过检查当前有效金额是否能够支持所需的削减来确保可行性。 如果在任何时候我们都无法在中间堆中形成对，或者最终的平衡条件失败，那么答案是不可能的。 

我们本质上将这个过程视为沿着阵列分配多余的石头，同时计算需要移除多少对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 模拟 | O(n × 操作) | O(n) | 太慢了 |
 | 线性贪婪传递 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 我们首先观察到只有内部桩对于执行操作很重要，因为桩 1 和 n 是允许保留石块的水槽。 

这立即将有效操作限制为索引 2 到 n−1。 
2. 我们从左到右扫描，保持可以向前推进的“剩余”石头。 

这一盈余代表了先前削减所获得的宝石。 
3. 在每个内部堆 i，我们将其当前的石子与传入的剩余石子结合起来。 

如果总数小于在需要时执行有效对删除所需的最小值，我们会将配置标记为不可能。 
4. 我们确定在满足流量约束后可以在第 i 堆执行多少次操作作为可用石子对的数量。 

每个操作正好消耗 2 个石头，因此在可行性约束下贡献是地板（总计/2）。 
5. 我们将剩余的奇偶校验（如果还有任何单个石头剩余）作为剩余的一部分向前推，因为它不能在本地使用，但可能有助于以后的堆成对。 
6. 处理完所有内部桩后，我们验证系统中没有残留不可行的剩余物。 如果满足所有约束，我们输出累积的操作数。 

### 为什么它有效

 每个操作在定义上都是局部的，但实际上是全局的：它从内部一堆石头中恰好移除两块石头，并将它们对称地分布。 这意味着内部堆只通过它们之间移动的石头的奇偶性相互作用，而不是通过任意重新排列。

保持的不变量是，在处理索引 i 后，左边的所有堆都已经处于与最终配置一致的状态，并且剩余的正确地编码了所有必须向右传播的石子。 由于每次操作都会保留总质量，并且仅左右重新分布一步，因此任何有效的操作序列都对应于沿该扫描的对的重新分布。 如果在任何时候，一堆石头都无法提供足够的石头来持续形成对，那么以后的任何操作序列都无法修复该缺陷，因为所有未来的操作都只会向外移动石头，而不是向后移动石头。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        carry = 0
        ops = 0
        
        possible = True
        
        for i in range(1, n - 1):
            a[i] += carry
            
            if a[i] == 0:
                carry = 0
                continue
            
            ops += a[i] // 2
            carry = a[i] % 2
        
        # final feasibility check
        if carry != 0:
            possible = False
        
        print(ops if possible else -1)

if __name__ == "__main__":
    solve()
```该代码独立处理每个测试用例，并对数组使用一次传递。 变量`carry`代表剩余的单子在当前位置无法形成一对，必须被转发。 变量`ops`累积有效对删除的总数。 

该循环仅处理索引 1 到 n−2，因为只有内部堆可以充当操作源。 在每一步中，我们都会将传入的进位与当前的进位合并。 除以2计算本地可以执行多少个操作，余数成为新的进位。 

最终检查确保没有任何不匹配的石头残留物滞留在系统中。

 ## 边缘情况

 一个关键的边缘情况是所有内部堆只包含一颗石头。 例如`[2, 1, 1, 1, 2]`。 由于内部堆中没有至少两块石头，因此无法开始任何操作。 该算法正确地传播进位值，但从未形成一对，导致零运算和最后的非零进位，产生 -1。 

另一种边缘情况是当单个堆从左侧积累大量剩余但无法在本地配对时。 例如`[1, 10, 1]`。 中间的一堆可以执行多种操作，并且进位机制确保所有配对都正确计数，因为剩余的流向右。
