 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times m$矩形网格，并且必须用 0 或 1 填充每个单元格。如果单元格属于最大相等值组的一部分，并且仅允许在侧相邻单元格之间移动，则该单元格属于连通分量。 仅当两个单元通过具有相同值的路径连接时，它们才属于同一组件。 

任务是构建最多使用这两个符号并且恰好具有$k$连接的组件总数。 

约束允许网格达到最大尺寸$1000 \times 1000$，因此构造必须与单元数量呈线性关系。 每个单元的操作或每次修改的重复洪水填充的任何二次方都会立即变得太慢。 

一个关键的微妙之处在于，组件是通过这两个值进行全局计数的。 像用 0 填充所有内容然后尝试在本地“添加组件”这样简单的方法会失败，因为修改一个区域可能会通过邻接效应无意中合并或分裂远处的结构。 

一个重要的边缘情况是当$k = 1$。 这很简单：整个网格必须填充一个值。 

另一个边缘情况是当$k = n \cdot m$。 这要求每个单元格都是其自己的组件，这只有在没有两个相邻单元格共享相同值的情况下才有可能。 

第三种不太明显的情况是，当一个构造创建了孤立的单元，但意外地通过构造中稍后形成的一系列相同值的邻居将它们连接起来时。 这是贪婪局部着色策略的主要失败模式。 

## 方法

 一个蛮力的想法是将网格视为一个图形，并尝试逐个单元格地分配值，在每次分配后运行洪水填充以跟踪连接组件的数量。 虽然如果它探索了所有可能性，那么总是会给出正确的答案，但每一步都会花费成本$O(nm)$，并且有$nm$步骤，导致$O(n^2 m^2)$，这远远超出了极限。 

关键的观察是我们实际上不需要搜索。 我们只需要一个组件易于控制的基本配置，然后一种受控的方式来逐个合并组件。 

一个非常有用的起点是棋盘图案。 如果我们设置$a[i][j] = (i + j) \bmod 2$，则没有两个相邻单元格是相等的。 每个单元格都是其自己的连接组件，因此组件总数恰好是$n \cdot m$，这是可能的最大值。 

从这个最大值开始，任务就变成了纯粹的受控减少$n \cdot m$组件减少到$k$。 每次我们强制两个相邻的单元格变得相等时，我们就会将两个分量恰好合并为一个，从而将总计数减一。 如果我们准确执行$n \cdot m - k$这样合并，我们就达到了目标。 

网格图的结构保证有足够的邻接边来支持所有所需的合并，因为网格的任何生成树都已经提供了$nm - 1$独立的合并操作。 棋盘初始化确保合并在应用时是干净的本地操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 使用洪水填充进行强力搜索 |$O((nm)^2)$|$O(nm)$| 太慢了|
 | 棋盘+受控合并|$O(nm)$|$O(nm)$| 已接受 |

 ## 算法演练

 我们在保持当前有效网格的同时逐步构建答案。 

1. 使用棋盘图案初始化网格，其中$grid[i][j] = (i + j) \bmod 2$。 这保证了最初每个细胞都会形成自己的连接组件，所以我们从$n \cdot m$成分。 
2. 维护计数器`components = n * m`。 
3. 按行优先顺序遍历网格。 对于每个单元格，只有当我们仍然有超过$k$。 
4. 对于一个单元格$(i, j)$，如果我们决定合并，我们会强制它采用一个已处理的邻居的值，通常是左侧单元格$(i, j-1)$如果存在，否则上单元格$(i-1, j)$。 这在两个先前独立的组件之间创建了有意的连接。 
5. 分配新值后，减少`components`1，因为正好有两个组件合并为一个。 
6. 停止应用合并一次`components == k`，并保持棋盘图案中所有剩余单元格不变。 

我们总是与先前处理过的邻居合并的原因是，它可以防止意外创建合并循环，这些循环可能会在网格中不可预测地传播。 

### 为什么它有效

 棋盘网格确保在任何修改之前，每个单元都是隔离的。 每个合并操作对于每个选定的单元都只应用一次，并且仅连接之前不相交的两个组件。 由于每次合并都对应于在网格上添加生成森林的一个边缘，因此该过程会准确地构建一个森林$k$连接的组件。 

不会发生意外的合并，因为我们永远不会分配一个值来在两个已经相等值的区域之间创建新的邻接关系，除非通过在该步骤中应用的显式合并操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    grid = [[(i + j) & 1 for j in range(m)] for i in range(n)]
    
    components = n * m
    
    for i in range(n):
        for j in range(m):
            if components == k:
                break
            if i == 0 and j == 0:
                continue
            
            # try to merge this cell with a processed neighbor
            if j > 0:
                grid[i][j] = grid[i][j - 1]
            else:
                grid[i][j] = grid[i - 1][j]
            
            components -= 1
        if components == k:
            break
    
    print("YES")
    for row in grid:
        print("".join(map(str, row)))

if __name__ == "__main__":
    solve()
```实现首先构建棋盘，这是最大分解状态。 遍历顺序很重要，因为我们只合并到已经访问过的邻居中，从而确保分配的一致性。 

停止条件很重要：一旦我们准确地到达$k$组件，我们不能执行进一步的合并，否则我们会过度调整并失去对最终结构的控制。 

转换步骤`grid[i][j] = grid[i][j - 1]`或来自上单元格是真正减少组件数量的唯一操作。

 ## 边缘情况

 对于$k = 1$，该算法从棋盘开始，但立即执行合并，直到所有组件折叠成单个连接区域。 每次合并只是在相邻的处理单元之间传播相等性，最终产生统一的网格。 

为了$k = n \cdot m$，根本不执行合并，因为初始棋盘已经提供了最大数量的组件。 由于停止条件，遍历循环立即退出。 

对于非常薄的网格，例如$1 \times m$或者$n \times 1$，棋盘仍然正确地交替值，并且每个合并操作都会减少严格线性链中的组件，而不会创建意外的合并，因为邻接是一维的。
