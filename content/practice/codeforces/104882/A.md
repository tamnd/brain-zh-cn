 ## 解决方案
 ## 问题理解

 我们正在计算整数对$(a, b)$满足简单的线性约束：它们的总和固定为给定值$n$，并且两个数字必须位于以零为中心的对称区间内。 区间定义为$p$： 两个都$a$和$b$必须介于$-10^p$和$10^p$，包含在内。 

所以任务不是独立地在二维中搜索对。 一次$a$被选择，$b$被迫成为$n - a$。 唯一的问题是有多少个整数值$a$两者都保留$a$和$n-a$在允许的范围内。 

输入只是两个整数，一个定义目标总和，另一个定义允许值的大小。 输出是有效整数选择的数量$a$，它直接对应于有效对。 

就结构复杂性而言，约束非常小：$p \le 9$，所以界限最多是$10^9$。 这意味着有效范围最多始终是一个连续的大小区间$2 \cdot 10^9 + 1$，因此任何枚举所有可能值的解决方案$a$已经处于临界状态，但在最坏的情况下仍然可行，尽管没有必要。 

当一个人试图独立选择时，就会出现一种幼稚的错误$a$和$b$然后按总和进行过滤，有效地重复计算实际上是一维的结构。 另一个常见的错误是忘记必须同时对两个变量强制执行两个边界。 

当间隔太紧以至于不存在解时，就会出现具体的边缘情况。 例如，如果$n = 25$和$p = 1$，范围是$[-10, 10]$。 该范围内的两个数字之和不能等于 25，因此答案必须为 0。任何仅检查约束一侧的方法都会错误地报告正计数。 

## 方法

 暴力解释很简单：迭代所有可能的整数$a$在允许的范围内，计算$b = n - a$，并检查是否$b$也属于同一范围。 每个有效$a$贡献一对有效的。 这是正确的，因为每个有效对都对应于一个选择$a$。 

这种方法的问题是搜索空间的大小。 范围为$a$有长度$2 \cdot 10^p + 1$，这对于$p = 9$是关于$2 \cdot 10^9$。 这远远超出了一秒内可以迭代的范围。 

关键的观察结果是约束减少为相交的两个区间。 从$a \in [-10^p, 10^p]$，我们还需要$n - a \in [-10^p, 10^p]$，它重新排列成另一个区间约束$a$:$a \in [n - 10^p, n + 10^p]$。 如此有效$a$值位于两个区间的交集处：$$[-10^p, 10^p] \cap [n - 10^p, n + 10^p]$$一旦问题变成区间交集，答案就是该交集的整数长度。

 ## 算法演练

 1. 计算界限$M = 10^p$。 这定义了两个变量的允许范围。 整个问题都受到这个单一值的限制。 
2. 转换条件$a \in [-M, M]$直接进入第一个区间$I_1 = [-M, M]$。 
3. 重写条件$b = n - a \in [-M, M]$成为约束$a$。 

这变成：$$-M \le n - a \le M$$这相当于：$$n - M \le a \le n + M$$给出第二个间隔$I_2 = [n - M, n + M]$。 
4. 计算这两个区间的交集。 左边界为：$$L = \max(-M, n - M)$$右边界是：$$R = \min(M, n + M)$$5. 如果$L > R$，区间不重叠且无效$a$存在，所以答案为0。 
6. 否则，交集中整数值的个数为$R - L + 1$，这就是最终的答案。 

### 为什么它有效

 每个有效对$(a, b)$唯一确定的是$a$，以及约束条件$a$正是两者的要求$a$和$n-a$位于固定区间内。 这转化为两个独立的区间约束$a$。 它们的交集精确地捕获了可行集，没有过量计数或遗漏。 该计算将原来的二变量约束系统简化为单个区间计数问题，保留所有有效解并通过构造排除所有无效解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())
    M = 10 ** p

    L = max(-M, n - M)
    R = min(M, n + M)

    if L > R:
        print(0)
    else:
        print(R - L + 1)

if __name__ == "__main__":
    solve()
```该解决方案计算最大允许范围$a$在这两个约束下，直接计算有多少个整数位于重叠区域。 关键的实现细节是对称计算两个边界并应用简单的最大最小交集。 最终计数中出现差一风险； 整数区间的包容性需要加 1$R - L$。
