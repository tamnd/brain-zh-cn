 ## 解决方案
 ## 问题理解

 我们正在构建一个由单位块组成的方形目标，其中边长是偶数$x$。 正方形的颜色不均匀。 相反，它由同心方形“环”组成。 最外面的环有一种颜色，下一个环有相反的颜色，这种交替向内持续，直到中心。 

每个环只有一个细胞厚。 所以对于给定的$x \times x$正方形，环数为$x / 2$。 外环是最大的正方形边框，每个内环都是剥去前一个边框得到的更小的正方形。 

关键的制约因素是红羊毛数量有限。 我们被告知我们有$n$红色块，我们想要最大化边长$x$使得这种交替环结构所需的红细胞数量不超过$n$。 

输入给出$n$，输出为最大偶数$x$使得所述目标中的红细胞数量最多为$n$。 

约束条件$4 \le n \le 1000$意味着搜索空间足够小，甚至可以直接模拟所有可能的情况$x$将是可行的。 然而，该图案的结构允许直接计算红细胞的数量。 

一个微妙的边缘情况是外环的颜色在语句中没有固定，但对于最大化来说并不重要。 如果外圈是红色，则红色使用量最大化； 如果是白色，则尽量减少红色的使用。 因为我们想要最大可能$x$最多可以组成$n$红色块，我们假设红色消耗的最坏情况，即红色从外层开始。 

另一个微妙之处是环是离散的。 对于小$x$，如果我们假设比例面积而不是计算完整的方形壳，手动直觉可能会失败。 

例如，当$x = 4$，有两个环。 如果外圈是红色的，说明已经消耗了$16 - 4 = 12$细胞，由于内部$2 \times 2$正方形是白色的。 任何将环视为连续层或平均颜色的近似方法在这里都会失败。 

## 方法

 直接的方法是尝试所有偶数边长$x = 2, 4, 6, \dots$并计算每个红细胞需要多少个。 对于每个$x$，我们模拟同心环。 每个环根据其颜色贡献其整个周边面积（实际上是整个正方形面积减去内部正方形）。 将这些相加得出红色的用法。 

对于每位候选人$x$，这个计算成本$O(x^2)$，因为我们可能会标记或计算正方形中的每个单元格。 在所有候选人中，最多$x \approx \sqrt{n}$规模，对于给定的约束，这仍然很小，但这是不必要的。 

关键的观察结果是该模式是完全确定性的并且可以分析地表达。 每个环都有边长$x, x-2, x-4, \dots$。 边环中的单元数$s$是：$$s^2 - (s-2)^2 = 4s - 4$$如果我们假设最外层的环是红色的，那么红色单元格是从最大的环开始的交替环的总和。 这将问题简化为计算递减算术序列上的简单交替和。 

我们不模拟几何结构，而是直接计算存在多少红色层并对它们的贡献求和。 自从$n \le 1000$，我们还可以安全地预先计算所有的值，甚至$x$最多可达数百个。 

核心改进是用层大小的算术代替几何。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 |$O(x^2)$每张支票 |$O(1)$| 太慢了|
 | 层算术计算|$O(x)$每次检查或预计算 |$O(1)$| 已接受 |

 ## 算法演练

 1. 迭代候选边长$x$，从 2 开始增加 2，因为只有偶数大小才有效。 我们测试每个$x$作为一个潜在的答案。 
2. 对于每个$x$，计算环数，即$x / 2$。 每个环对应边的一个方形边框$s = x, x-2, x-4, \dots, 2$。 
3. 使用恒等式计算每个环的大小$s^2 - (s-2)^2 = 4s - 4$。 这避免了显式构建网格并直接计算属于该环的单元格数量。 
4. 从最外环开始交替指定颜色为红色。 将每个其他环的大小（序列中的位置 0、2、4 等）相加。 这给出了红色的总用量$x$。 
5. 如果计算出的红色用量小于或等于$n$，更新最佳答案$x$。 否则，如果需要，请尽早停止，因为较大$x$只会增加总面积，从而增加红色的使用量。 

### 为什么它有效

 关键的不变量是分解为环将正方形划分为不相交的单元组，其大小仅取决于其边长。 每个有效的颜色完全由交替这些环决定，因此红细胞计数仅取决于$x$，不涉及任何内部安排。 由于几何形状和着色都是固定且确定的，因此计算环贡献可以准确地重建红细胞的真实数量，而无需近似。 总面积单调增长$x$确保一旦尺寸超过$n$，所有较大的尺寸也会超过它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def red_needed(x):
    total = 0
    color_red = True
    s = x
    while s > 0:
        ring = s * s - (s - 2) * (s - 2) if s > 2 else 4
        # simpler: ring = 4*s - 4 for s > 2, and 4 for s = 2
        if color_red:
            total += ring
        color_red = not color_red
        s -= 2
    return total

n = int(input().strip())

ans = 0
x = 2
while True:
    need = red_needed(x)
    if need <= n:
        ans = x
    else:
        break
    x += 2

print(ans)
```功能`red_needed`计算固定的红细胞数量$x$通过迭代环边长度。 每次迭代都会从当前正方形大小中减去 2，从而向内移动到下一层。 

交替布尔值`color_red`确保我们从外环开始正确地模拟颜色交替。 仅当当前环为红色时才会进行累积。 

主循环递增$x$2 并在所需的红细胞超过时停止$n$，依赖于构造的单调性。 

## 工作示例

 ### 示例 1：$n = 4$我们甚至测试$x$。 

| x| 戒指| 红色计算| 红总| 有效|
 | ---| ---| ---| ---| ---|
 | 2 | 1 | 4 | 4 | 是的 |
 | 4 | 2 | 16 - 4 = 12（仅限外红色）| 12 | 12 没有 |

 为了$x = 2$，只有一个尺寸的环$2 \times 2$，因此红色用量为 4。对于$x = 4$，外环已经超出预算，所以答案是2。 

### 示例 2：$n = 20$| x| 戒指| 红色层| 红总| 有效|
 | ---| ---| ---| ---| ---|
 | 2 | 1 | 2×2 | 4 | 是的 |
 | 4 | 2 | 仅限 4×4 | 12 | 12 是的 |
 | 6 | 3 | 6×6 + 2×2 | 36 + 4 = 40 | 没有 |

 在这里我们看到$x = 6$，红色要求显着跳跃，因为外部$6 \times 6$环占主导地位。 最大有效$x$是 4。 

这些痕迹表明增长不是线性的$x$，但取决于方层积累。

 ## 边缘情况

 一种边缘情况是最小的输入，其中仅$x = 2$是有效的。 为了$n = 4$，算法评估$x = 2$，接受它，然后尝试$x = 4$，发现超出预算，并正确返回2。 

另一个边缘情况是当$n$足够大，可以由多个层贡献。 为了$n = 1000$，算法继续增加$x$直至累计红色面积超过限制。 由于每个步骤都会重新计算精确的环和，因此不存在累积浮动误差或误算部分层的风险。 

第三种情况是过渡点，添加新的外环会导致红色使用量大幅跃升。 这是自然处理的，因为每个$x$是从头开始独立评估的，因此不会延续之前的近似值。
