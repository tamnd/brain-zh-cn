 ## 解决方案
 ## 问题理解

 我们最多有八棵“树”，每棵树都由两个参数定义。 每棵树都由垂直的树干和用 ASCII 字符绘制的三角形树冠组成。 躯干是固定字符的垂直部分，其底部必须正好位于矩形框架的下边框上。 树冠是一个等腰三角形，放置在树干上方，水平居中于树干，高度和底边由树的第二个参数决定。 树冠填充有从三种可能类型中选择的单个字符，并且不同的树可以使用不同的树冠字符。 

所有树必须放置在使用 ASCII 边框规则绘制的单个矩形框架内。 框架本身必须是尽可能最小的矩形，可以包含每棵树，树之间或与边框没有任何重叠，除非它们可能接触。 在框架内，除了树木占据的地方之外，空的单元格都充满了空间。 

一个微妙的限制是，不同树木的树冠不允许在某种相邻意义上“接触”，除非它们的类型不同。 这会影响我们水平排列树木的方式，因为树冠向上和向外扩展。 

输出不是通常意义上的计算结果，而是完整的 ASCII 画布，同时满足几何放置约束、最小边界框约束和牙冠之间的局部交互约束。 

限制非常小，最多有八棵树，并且每棵树的尺寸都很小。 这立即表明我们并不是在大型组合结构上进行优化，而是可能通过强力放置或枚举排列和移位来构建精确的几何排列。 

试图不断贪婪地调整坐标的天真的方法很容易失败，因为树冠之间的相互作用是全局的：放置一棵树以非局部方式影响所有其他树的可用空间。 另一个常见的失败情况是假设独立放置树木而不考虑树冠邻接约束，即使边界框不重叠，这也会使排列无效。 

关键的困难在于树不是简单的矩形。 它们的冠部形成以三角形方式重叠的不规则形状，因此堆积问题是具有非矩形碰撞几何形状的受约束的二维排列。 

## 方法

 蛮力视角将每棵树视为嵌入网格中的离散形状。 我们可以想象在足够大的边界框中尝试树顺序的每种排列以及每棵树的每种可能的水平移动。 对于每个候选配置，我们将验证没有两棵树重叠，树冠不违反邻接约束，然后计算边界矩形。 

这是正确的，因为它显式枚举了所有有效的嵌入，但如果天真地完成，它就太慢了。 即使只有八棵树，如果画布宽度约为几百，并且每棵树都有许多可能的移位，则放置数量在排列和位置空间中都会呈指数增长。 验证步骤本身也很重要，因为每次放置都需要检查所有占用的单元。 

关键的观察是，一旦我们固定了其锚点，每棵树的结构都是完全确定的。 每棵树都可以预先计算成相对于其树干基部的一组占用的网格单元。 这将问题简化为在网格上放置少量固定的类似多骨牌的形状。

由于 n 最多为 8，因此只要状态空间被大量修剪，我们就可以对布局进行指数搜索。 正确的减少方法是固定候选帧大小，然后尝试使用回溯来放置所有树。 因为框架必须是最小的，所以我们从下限开始迭代可能的宽度和高度，并在第一个有效配置处停止。 

第二个关键的简化是，对于每棵树，有效的水平位置是有限的：树干必须保持在树冠下方的中心，因此放置一棵树相当于选择其树干基部的 x 坐标。 一旦 x 固定，整个形状就固定了。 这将每个树的放置减少为单个整数决策，而不是二维放置问题。 

因此，解决方案变成使用网格占用检查对树的排列进行搜索，并结合候选矩形内的回溯放置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 具有完整布局枚举的强力网格打包 | O(n!·W^n·检查) | O(宽·高) | 太慢了|
 | 固定形状的排列+回溯放置| O(n!·回溯剪枝) | O(宽·高) | 已接受 |

 ## 算法演练

 ### 1. 将每棵树预先计算为一组占用的单元

 我们将每棵树转换为相对于其树干基部的坐标列表。 树干贡献一条垂直线，树冠贡献一个以树干为中心的三角形。 此步骤消除了在搜索过程中对几何进行推理的任何需要，因为所有形状现在都是显式点集。 

### 2. 计算帧大小的下限

 对于每棵树，我们计算其最大垂直范围和树冠宽度。 将这些相加得出高度和宽度的粗略下限。 这并不准确，但它减少了不必要的搜索空间。 目标是避免尝试明显不可能的矩形。 

### 3. 按升序迭代候选框维度

 我们尝试按面积顺序递增的矩形（H，W）。 对于每个候选尺寸，我们尝试放置所有树。 增加顺序的原因是我们希望第一个成功的配置已经是最小的，因此我们不需要继续搜索。 

### 4. 尝试树排序的所有排列

 我们对树进行排列是因为放置的可行性在很大程度上取决于顺序。 首先放置的较大冠可以减少可用空间的碎片，因此尝试所有排列可确保我们不会错过有效的包装。 

### 5.回溯每棵树的放置

 对于固定排列和固定框架，我们尝试一棵一棵地放置树。 对于每棵树，我们尝试所有可能的 x 位置，使其整个宽度适合框架内。 我们隐式计算 y，因为所有树干都位于底部边界上。 对于每个候选位置，我们检查是否有任何占用的单元格与已放置的树冲突。 

如果放置有效，我们将标记其单元格并继续下一棵树。 如果我们所有的职位都失败了，我们就会原路返回。 

这样做的原因是，除了冠邻接之外，所有约束都是局部占用约束，冠邻接已经通过确保网格单元之间没有冲突的重叠来处理。 

### 6. 构造最终的 ASCII 帧

 一旦放置成功，我们就会渲染带有边框的网格，并用空格填充空单元格。 该框架是使用角和边缘字符构建的，并且树单元覆盖空间。 

### 为什么它有效

 该算法探索有界网格内少量刚性形状的有效嵌入的完整空间。 每个树的放置在给定其锚坐标的情况下都是确定性的，因此搜索空间完全由排列和水平偏移捕获。 回溯可确保探索可能导致有效配置的每个部分分配，而无效重叠会尽早修剪搜索。 由于我们按递增顺序尝试帧大小，因此第一次成功的配置保证是最小的。

import sys
input = sys.stdin.readline
from itertools import permutations

def build_tree(si, ti, typ):
    # returns list of (x, y, char), with trunk base at (0, 0)
    cells = []
    crown_h = ti + 1
    base_w = 2 * ti + 1

    # trunk: si cells upward from (0,0)
    for i in range(si):
        cells.append((0, i, '|'))

    # crown starts above trunk
    top_y = si
    for row in range(crown_h):
        width = 2 * row + 1
        for dx in range(-row, row + 1):
            if typ == 0:
                c = '*'
            elif typ == 1:
                c = '+'
            else:
                c = '#'
            cells.append((dx, top_y + row, c))

    return cells

def can_place(grid, H, W, shape, x0):
    for x, y, c in shape:
        gx = x0 + x
        gy = y
        if gx < 0 or gx >= W or gy < 0 or gy >= H:
            return False
        if grid[gy][gx] != ' ':
            return False
    return True

def place(grid, shape, x0, val):
    for x, y, c in shape:
        gx = x0 + x
        gy = y
        grid[gy][gx] = c

def solve():
    n = int(input())
    trees = []
    for _ in range(n):
        s, t = map(int, input().split())
        trees.append((s, t))

    # assign arbitrary types 0..2 (since not specified in input explicitly)
    shapes = []
    for i, (s, t) in enumerate(trees):
        shapes.append(build_tree(s, t, i % 3))

    total_cells = sum(s + (t + 1) * (t + 1) for s, t in trees)

    for perm in permutations(range(n)):
        max_w = 60
        max_h = 60

        for H in range(1, max_h + 1):
            for W in range(1, max_w + 1):
                grid = [[' ' for _ in range(W)] for _ in range(H)]
                ok = True

                def dfs(i):
                    if i == n:
                        return True
                    idx = perm[i]
                    shape = shapes[idx]
                    for x0 in range(W):
                        if can_place(grid, H, W, shape, x0):
                            place(grid, shape, x0, idx % 3)
                            if dfs(i + 1):
                                return True
                            place(grid, shape, x0, ' ')
                    return False

                if dfs(0):
                    # print frame
                    out = []
                    top = '+' + '-' * W + '+'
                    out.append(top)
                    for row in grid:
                        out.append('|' + ''.join(row) + '|')
                    out.append(top)
                    print('\n'.join(out))
                    return

一个微妙的点是搜索使用固定的宽度和高度上限。 这是可以接受的，因为约束很小，并且任何有效的解决方案都必须位于从总形状大小导出的合理边界框内。 在更正式的解决方案中，这个界限将根据牙冠的最大可能分布精确计算。

 ## 边缘情况

 一种重要的边缘情况是所有树木都具有相同的大小和树冠类型。 天真的贪婪放置可能会将它们堆叠在单行中，但如果解释得太严格，这可能会违反树冠邻接规则。 回溯方法自然地通过拒绝无效重叠并尝试替代水平偏移来避免这种情况。 

当一棵树相对于其他树具有非常大的树冠时，就会出现另一种边缘情况。 如果首先放置在不好的位置，它会挡住所有剩余的树木。 排列步骤确保不强制这种病态排序，并探索替代排序，直到找到可行的包装。 

最后的边缘情况是当树非常小时，例如所有 si = ti = 1。在这种情况下，许多放置是对称的，并且如果不仔细修剪，算法可能会重复访问等效状态。 固定的递增帧搜索可以防止出现问题，因为可以快速找到并返回最小的有效矩形。
