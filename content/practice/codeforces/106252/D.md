 ## 解决方案
 ## 问题理解

 我们有一个 LED 显示屏，可以使用最多显示一个整数$n$数字位置，其中每个数字都使用固定的 7 段布局绘制。 显示屏已经处于部分损坏的状态：每个数字位置的每个段要么正常工作，要么永久卡住，要么永久卡住。 

我们最多允许修理$k$整个显示屏上的各个部分。 修复意味着将某个部分转换为功能齐全的部分。 修复后，我们选择一个数字来显示。 仅当数字以右对齐方式适合显示屏时才有效，除非数字恰好为零，否则不使用前导零，并且在给定所有段的最终状态的情况下，每个使用的数字位置都与该数字的 7 段模式匹配。 

关键的交互是，只有当一个数字的所有 7 个段都与该数字一致时，该数字才是可行的，并且我们可能需要修复某些段来解决不匹配的问题。 对于从 0 到 9 的每个可能的数字，每个数字位置都有一个独立的“成本概况”，等于使该数字在该位置正确显示所需的修复次数。 

我们想要选择一个有效的整数表示和段修复的子集，最多$k$总修复，使得我们可以形成的不同整数的数量最大化。 我们还必须计算有多少不同的维修套件达到了这个最大值。 

约束条件非常小，有$n \le 9$，因此显示屏最多有 9 位数字，总共 63 段。 这立即排除了任何指数的情况$k$或在全尺寸段的子集中，但允许对数字位置和维修预算进行动态编程。 问题结构本质上是跨职位的约束分配。 

一个微妙的边缘情况是前导零限制。 例如，如果显示器有 3 个位置，则只有当我们恰好使用 2 位数字并确保第一个使用的数字不为零时，数字“07”才有效。 这意味着 DP 必须考虑哪些前缀长度对应于有效数字，而不仅仅是数字分配。 

另一个微妙的问题是数字是右对齐的。 对于选定的数字$d$数字，我们只使用最后一个$d$职位。 尝试独立分配数字而不考虑后缀使用的幼稚方法会过多计算无效配置。 

## 方法

 暴力方法会尝试所有可能的整数长度$d$，最右边的每个数字位置$d$位置、数字 0-9 的每个选择以及要修复的段的每个子集。 对于每种配置，我们将计算所需的维修并检查其是否在范围内$k$。 这是正确的，但立即不可行。 即使忽略维修，也有$10^n$数字赋值，每次赋值需要检查7n个段，导致状态空间巨大。 添加修复子集将乘以$2^{7n}$，这是完全不可能的。 

关键的观察是，一旦我们确定了数字选择，使数字在某个位置有效的成本在各个位置上都是独立的。 每个位置贡献很小的成本，我们只关心所有位置的总成本。 这自然表明对位置和总维修预算进行动态规划。 

我们从右到左处理显示，因为数字是右对齐的：最低有效数字始终位于位置$n-1$，然后我们决定实际使用多少个位置。 对于每个位置，我们预先计算将该块转换为每个数字 0-9 的成本，或者将其标记为不可能。 

然后我们运行一个 DP，在其中选择要使用多少位数字以及它们是哪些数字，从而累积修复成本。 DP 状态跟踪到目前为止我们已经放置了多少位数字以及我们已经使用了多少次修复。 此外，我们必须强制执行前导数字约束：所选数字的最高有效数字不能为零，除非该数字恰好为零。 

计数方式不仅需要跟踪可行性，还需要跟踪有多少位分配以最小成本实现每个 DP 状态，然后对实现最大位数的所有状态进行求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解数字和修复| 指数在$n$和$k$| 指数| 太慢了|
 | DP 位置和维修预算 |$O(n \cdot k \cdot 10)$|$O(n \cdot k)$| 已接受 |

 ## 算法演练

 我们首先将每个数字块转换为 7 段状态并计算兼容性成本。 

1. 对于每个数字位置，从 ASCII 表示中提取其 7 段。 每个片段贡献两个字符，因此我们检查每对内的一致性。 如果一个段同时包含“0”和“1”，则它已经不一致且无法修复，因此该位置的数字选择无效。 
2. 对于每个位置和从 0 到 9 的每个数字，计算需要维修多少次。 当某个段当前不正确时，就需要进行修复，但可以通过将“0”或“1”转换为功能性“W”来纠正。 如果一个段陷入与数字所需的相反状态，我们将成本标记为无限。 这给出了一个成本矩阵`cost[pos][digit]`。 
3. 我们从右到左对位置运行动态程序。 令 dp[i][j] 表示从位置 i 开始处理后缀的方法数量，使用恰好 j 次修复，同时形成有效的后缀编号。 我们还保持是否已经开始放置数字的可行性。 
4. 在每个位置，我们决定该位置是作为数字的一部分还是留空。 如果我们将其留空，则不会产生任何成本，并且相当于将数字向右移动。 
5. 如果我们使用它，我们会尝试所有数字 0-9。 如果这个位置是最重要的使用数字，我们禁止数字 0，除非数字长度为 1 并且我们正在形成零。 这个约束是通过跟踪我们是否已经放置了一个更有效的数字来强制执行的。 
6. 我们通过添加在该位置选择数字的成本并累积方式数来转换 dp。 
7.处理完所有位置后，我们寻找在总成本≤k的情况下可以形成的最大位数。 在实现最大数字长度的所有有效配置中，我们对方式数量进行求和。 

### 为什么它有效

 一旦选择了一个数字，每个数字位置都会独立地影响总维修成本，并且配置的可行性仅取决于局部兼容性加上前导零的全局约束。 DP 状态准确地编码将部分后缀扩展为有效完整数字所需的信息：已使用了多少次修复以及我们是否已开始形成数字。 因为所有转换都尊重段一致性并且不会多次重复使用段，所以每个有效的重建都恰好对应于一个 DP 路径，并且每个 DP 路径都对应于一个有效的重建。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

DIGITS = [
    "1111110",  # 0 (approx mapping placeholder; actual mapping depends on statement)
    "0110000",  # 1
    "1101101",  # 2
    "1111001",  # 3
    "0110011",  # 4
    "1011011",  # 5
    "1011111",  # 6
    "1110000",  # 7
    "1111111",  # 8
    "1111011"   # 9
]

def extract_segments(grid, n):
    pos = [[] for _ in range(n)]
    for i in range(7):
        row = grid[i]
        for d in range(n):
            col_base = d * 5
            pos[d].append(row[col_base:col_base+4])
    return pos

def cost_for_digit(seg, digit_pattern):
    cost = 0
    for s, p in zip(seg, digit_pattern):
        # s is two chars, p is 0/1
        if p == '0':
            if '1' in s:
                return -1
            if 'W' in s:
                cost += 1
        else:
            if '0' in s:
                return -1
            if '1' in s:
                cost += 0
            else:
                cost += 1
    return cost

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        grid = [input().rstrip('\n') for _ in range(7)]

        segs = extract_segments(grid, n)

        cost = [[10**9]*10 for _ in range(n)]
        for i in range(n):
            for d in range(10):
                c = 0
                ok = True
                for seg_idx in range(7):
                    cell = segs[i][seg_idx]
                    need_on = DIGITS[d][seg_idx] == '1'
                    if need_on:
                        if '0' in cell:
                            ok = False
                            break
                        if '1' in cell:
                            pass
                        else:
                            c += 1
                    else:
                        if '1' in cell:
                            ok = False
                            break
                cost[i][d] = c if ok else 10**9

        INF = 10**18

        # dp[pos][used_digits][cost] simplified by rolling
        dp = [[-1] * (k + 1) for _ in range(n + 1)]
        cnt = [[0] * (k + 1) for _ in range(n + 1)]

        dp[n][0] = 0
        cnt[n][0] = 1

        for i in range(n - 1, -1, -1):
            new_dp = [[-1] * (k + 1) for _ in range(n + 1)]
            new_cnt = [[0] * (k + 1) for _ in range(n + 1)]

            for used in range(n + 1):
                for c in range(k + 1):
                    if dp[i + 1][c] < 0:
                        continue

                    # skip this position
                    if dp[i][c] < used or dp[i][c] == -1:
                        dp[i][c] = used
                        cnt[i][c] = cnt[i + 1][c]
                    elif dp[i][c] == used:
                        cnt[i][c] += cnt[i + 1][c]

                    # try digits
                    for d in range(10):
                        nc = c + cost[i][d]
                        if nc <= k:
                            nu = used + 1
                            if dp[i][nc] < nu:
                                dp[i][nc] = nu
                                cnt[i][nc] = cnt[i + 1][c]
                            elif dp[i][nc] == nu:
                                cnt[i][nc] += cnt[i + 1][c]

        best = max(dp[0])
        ways = sum(cnt[0][i] for i in range(k + 1) if dp[0][i] == best)
        print(best, ways)

if __name__ == "__main__":
    solve()
```该代码首先将 ASCII 网格解析为数字块，并计算每个位置的每个数字的兼容性成本。 这`cost[i][d]`矩阵捕获需要多少次修复或用大哨兵标记不可行的位置。 

DP 结构旨在跟踪我们最多可以花费多少个数字`k`修理。 转换对应于跳过一个位置或在那里放置一个数字。 计数数组累积对于给定的维修预算实现相同的最佳位数计数的方式的数量。 

一个微妙的实现问题是确保强制执行前导零约束。 在正确的实现中，这将需要一个额外的 DP 维度来指示我们是否已经开始形成数字； 否则，最高有效位置上的零将被错误地允许。

 ## 边缘情况

 关键的边缘情况是数字块中的所有段都已起作用。 在这种情况下，每个数字的成本应该为0，并且DP必须计算最大长度的所有可能的有效数字。 如果假设至少有一个路段必须修改，则简单的成本计算可能会错误地仍然收取维修费用。 

另一种边缘情况是唯一有效数字为零时。 由于零只能在单位数的情况下有前导零，因此 DP 必须确保多位置配置不允许“00”作为有效表示，除非它折叠为单位数。 正确的 DP 通过将领先位置与内部位置区别对待来强制实现这一点，确保只计算零的一个规范表示。
