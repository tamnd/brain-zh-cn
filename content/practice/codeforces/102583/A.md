 ## 解决方案
 ## 问题理解

 我们有一群高度已知的生物。 摄影师希望将它们分成尽可能少的照片。 一张照片可以包含一个、两个或三个生物，但允许的高度差异取决于照片中生物的数量。 

对于两个生物，它们的身高差异不得超过 20。对于三个生物，它们中最矮和最高的差异不得超过 10。单个生物始终可以单独拍摄。 

输入包含生物的数量及其高度。 任务是输出最少数量的照片，使每个人都包含一次。 

生物的数量最多为 1000 个，每个高度在 100 到 1000 之间。这意味着 O(n^2) 解决方案仍然可以接受，因为一百万次操作很小，但我们仍然应该寻找更简单的结构，因为问题具有排序属性。 对所有可能的分组进行强力搜索是不可能的，因为划分 1000 个生物的方法数量增长得非常快。 

重要的边缘情况来自两个和三个生物的限制之间的差异。 即使其中的每一对看起来都可以接受，三人一组也可能是无效的。 例如：```
3
100 110 120
```正确答案是2。这三个生物不能共享一张照片，因为总高度范围是20，但是两对100和110、110和120可以各自一起拍摄。 

另一种情况是只有两个生物足够接近时：```
3
100 115 200
```正确答案是 2。粗心的解决方案仅检查最小和最大高度差是否足够小，可能会错误地拒绝 100 和 115 对并产生 3 张照片。 

最后的边界情况是所有生物具有相同的高度：```
4
500 500 500 500
```正确答案是 2，因为每三个一组都是有效的，但一张照片不能包含四个生物。 

## 方法

 一种直接的方法是尝试各种可能的方法将生物分为一、二、三组，检查每个组是否满足拍照规则。 这种方法是正确的，因为它会检查每种可能的排列并选择最少数量的照片。 然而，分区的数量是巨大的。 即使只有 1000 种生物，探索所有群体也远远超出了可行的极限。 

有用的观察来自于只有高度差异才重要的事实。 对高度进行排序后，距离足够近的生物将出现在彼此旁边。 将一个矮小的生物与一个高得多的生物放在一起而让附近的生物单独放置并没有任何优势。 

排序后，问题就变成了前缀上的动态规划问题。 令 dp[i] 为第 i 个排序生物所需的最少照片数。 当将生物 i 视为前缀中的最后一个生物时，只有三种可能的结局：最后一张照片包含一个生物、两个生物或三个生物。 这是唯一的情况，因为一张照片不能包含三个以上的生物。 

转换检查最后两个或最后三个排序高度是否满足所需的限制。 在有效选择中取最小值即可给出最佳答案。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了|
 | 排序后的动态规划 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按非降序对所有高度进行排序。 排序后，任何有效的多个生物组都可以被视为一个连续的片段，因为将高度相近的生物分开而将较远的生物分组并不能增加照片的数量。 
2. 创建一个动态编程数组，其中 dp[i] 表示按排序顺序排列的前 i 个生物所需的最少照片数。 
3. 将 dp[0] 初始化为 0，因为没有生物不需要照片。 
4. 对于从1到n的每个位置i，首先考虑单独拿走第i个生物。 这给出了转换 dp[i] = dp[i - 1] + 1。 
5. 如果最后两个生物形成有效对，则使用 dp[i - 2] + 1 更新 dp[i]。当它们的高度差最多为 20 时，该对有效。 
6. 如果最后三个生物形成一个有效的组，则使用 dp[i - 3] + 1 更新 dp[i]。当这三个高度中最大和最小的差值最多为 10 时，三元组有效。 
7. 值 dp[n] 就是答案，因为它描述了所有已排序生物所需的最少照片数量。 

为什么它有效：

 动态编程状态考虑了形成最终照片的所有可能方式。 对于前 i 个生物的任何最佳解决方案都必须以最终照片中的一个、两个或三个生物结束。 删除最终照片会留下较小前缀的最佳解决方案，因为否则我们可以用更好的照片替换它并改进原始解决方案。 转换精确地测试了这些可能的结局，因此 dp[i] 始终存储真实的最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    inf = 10**9
    dp = [inf] * (n + 1)
    dp[0] = 0

    for i in range(1, n + 1):
        dp[i] = dp[i - 1] + 1

        if i >= 2 and a[i - 1] - a[i - 2] <= 20:
            dp[i] = min(dp[i], dp[i - 2] + 1)

        if i >= 3 and a[i - 1] - a[i - 3] <= 10:
            dp[i] = min(dp[i], dp[i - 3] + 1)

    print(dp[n])

if __name__ == "__main__":
    solve()
```排序步骤将相似的高度彼此相邻，这允许动态编程转换仅检查最后几个生物。 如果不进行排序，有效的组可能会分布在整个数组中，并且局部转换不会代表所有可能性。 

该数组的大小为 n + 1，因为 dp[0] 表示空前缀。 对对和三元组的检查使用 i 作为已处理生物的计数，因此最后处理的索引是 i - 1。条件仔细使用这些索引以避免访问数组开头之前的元素。 

单个生物转换始终可用，因此每个状态都会收到一个初始有效值。 成对和三重过渡仅在满足其高度限制时才会提高该值。

 ## 边缘情况

 对于这个案例：```
3
100 110 120
```排序什么也不做。 三重转换检查范围 120 - 100，即 20，因此三人组被拒绝。 对转换接受 100 和 110，给出两张照片。 该算法返回 2。 

对于这个案例：```
3
100 115 200
```排序后的数组为 100, 115, 200。前两个生物的配对有效，因为差异为 15。最后一个生物不能加入任何一组，因为差异太大。 前两个生物的动态编程值变为 1，添加第三个生物后动态编程值变为 2，从而给出正确的结果。 

对于这个案例：```
4
500 500 500 500
```每个可能的配对和三次检查都会成功。 最好的安排是一个三重生物和一个单一生物，因为规则限制每张照片最多只能有三个生物。 动态规划转换发现 dp[3] = 1，然后 dp[4] = 2，这是最优的。
