 ## 解决方案
 ## 问题理解

 每个学生的试卷都被编码为一个整数。 该整数的二进制表示记录了学生的答案，带有`1`意味着该问题的答案是正确的并且`0`意味着它是不正确的。 任务是确定每个学生正确答案的数量，因此对于每个值`A_i`我们需要的数量`1`其二进制表示形式中的位。 

例如，`5`是`101`是二进制的，所以它包含两个`1`位和相应的学生收到`2`标记。 相似地，`8`是`1000`，所以它的答案是`1`。 

一个测试用例的学生人数可以达到`10^5`，每张编码纸可以大到`10^9`。 自从`10^9 < 2^30`，每个数字最多有 30 个相关的二进制位。 每位执行恒定工作量的方法已经在以下方面有效地线性化：`N`，因为它最多执行大约三百万位操作`10^5`学生。 比较每对学生的方法需要大约`10^10`进行比较，立即发现不合适。 由于输入包含多个测试用例，因此直接使用 Python 的整数位运算比显式模拟位更可取。 

在一些小情况下，实施可能会出错。 最小的有效论文是`1`，其二进制形式为`1`，所以答案是`1`。 意外开始从位置检查位的实现`1`而不是位置`0`会错误地产生零。 

另一个边界情况是二的幂。 例如，输入```
1
4
1 2 4 8
```必须产生```
1 1 1 1
```每个 2 的幂都有一个设置位。 尝试根据数字的大小而不是其二进制表示来推断标记数量的代码很容易出错。 

相反的情况是具有多个设置位的数字。 为了```
1
1
7
```输出是```
3
```因为`7 = 111₂`。 一个常见的错误是计算二进制数字的数量而不是数字的数量`1`数字，这也适用于`7`但对于诸如以下的值失败`8`，其中正确答案是`1`而二进制长度是`4`。 

最后，上限很重要，因为`10^9`不是一个特殊的二进制值。 它的答案是其普通二进制表示形式中设置的位数，Python 整数直接处理该值而不会溢出。 

## 方法

 直接的方法是检查每个学生人数的二进制表示并计算其数量`1`位。 在不构造字符串的情况下执行此操作的一种方法是重复检查最低有效位`x & 1`，将其添加到答案中，然后移动`x`就一个位置。 该方法是正确的，因为每次迭代都恰好删除一个二进制数字，并且每个原始数字`1`只对计数贡献一次。 

由于每`A_i`至多是`10^9`，一个数字最多需要 30 次迭代。 为了`N = 10^5`，这最多意味着`3 × 10^6`对一个测试用例进行位检查。 这并不是渐近坏的，但 Python 可以使用其内置整数运算更有效地执行相同的运算`int.bit_count()`，它以优化的本机代码执行 popcount。 

关键的观察是所需的标记正是该整数的人口计数。 学生之间没有互动，也不需要自己重构问题。 每个`A_i`可以独立处理，并且`A_i.bit_count()`直接返回其二进制表示形式的设置位数。 

暴力方法之所以有效，是因为位数是有界的，但它仍然在 Python 中对每个数字的每一位执行循环。 观察到答案恰好是一个整数 popcount，让我们可以将每个学生的工作量减少到一个优化操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N log A) | O(N log A) | O(1) 辅助 | 已接受，但不必要的 Python 级循环 |
 | 最佳| 位复杂度为 O(N log A)，每个整数具有本机 popcount | 存储输入/输出 | O(N) 已接受 |

 这里`A`表示最大编码纸张值。 和`A ≤ 10^9`,`log A`最多约为 30。最佳版本的实际优点是位计数本身是由 Python 的整数机制而不是显式的 Python 循环实现的。 

## 算法演练

 1.读取测试用例的数量并独立处理每个测试用例。 每个学生的结果仅取决于该学生的编码论文，因此测试用例之间不需要共享状态。 
2. 阅读`N`将试卷编码到数组中。 这些值本身已经是计算分数所需的完整信息。 
3. 对于每个值`x`, 计算`x.bit_count()`。 这将准确返回包含的位置数`1`在二进制表示中`x`。 
4. 按照学生在输入中出现的顺序存储结果计数。 保留此顺序是必要的，因为输出逐个位置对应于输入数组。 
5. 在一行上打印当前测试用例的所有计数。 

### 为什么它有效

 对于任意正整数`x`，其二进制表示形式对于整数表示的每个问题都包含一个二进制数字。 正确答案对应于`1`，所以学生的分数正是`1`数字。 蟒蛇的`x.bit_count()`返回精确的数量。 由于该操作是独立应用于每个`A_i`，每个输出值都是相应学生的正确分数，并且保留输入顺序将保留所需的学生顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = [x.bit_count() for x in a]
        print(*ans)

if __name__ == "__main__":
    solve()
```第一行`solve`读取测试用例的数量。 然后，外循环隔离每个检查的处理。 

对于每个测试用例，`map(int, input().split())`将编码后的论文转换为 Python 整数。 列表理解适用`bit_count()`独立于每个值并以完全相同的顺序生成标记。 

不需要对二的幂、具有许多设置位的数字或上限进行特殊处理`10^9`。 Python 的任意精度整数也意味着不存在整数溢出问题。 

该代码假设输入遵循规定的格式，其中所有`N`测试用例的值出现在下一行。 对于给定的问题来说这已经足够了。 输出是用生成的`print(*ans)`，它在答案之间放置空格并正确结束该行。 

## 工作示例

 对于样本的第一个测试用例，输入值为`1, 2, 3, 4, 5`。 重要的状态是当前整数及其二进制表示形式。 

| 学生| 价值| 二进制 |`bit_count()`| 标记 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 |`1`| 1 | 1 |
 | 2 | 2 |`10`| 1 | 1 |
 | 3 | 3 |`11`| 2 | 2 |
 | 4 | 4 |`100`| 1 | 1 |
 | 5 | 5 |`101`| 2 | 2 |

 结果行是`1 1 2 1 2`。 这表明该值本身只是答案的编码，只有其设置的位才重要。 

对于第二个测试用例，这些值是 2 的幂。 

| 学生| 价值| 二进制 |`bit_count()`| 标记 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 |`10`| 1 | 1 |
 | 2 | 4 |`100`| 1 | 1 |
 | 3 | 8 |`1000`| 1 | 1 |
 | 4 | 16 | 16`10000`| 1 | 1 |

 输出是`1 1 1 1`。 这是一种有用的边界跟踪，因为尽管二进制表示具有不同的长度，但每个值都恰好有一个设置位。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N log A) 位复杂度 | 每个值最多有`log₂(A) + 1`二进制数字，每个数字都计算一次 |
 | 空间| O(N) | 输入数组和输出数组包含`N`整数 |

 和`A ≤ 10^9`，每个数字最多有 30 个二进制数字。 因此，工作量随学生数量线性增长，常数因子非常小。 该实现使用原生`bit_count()`操作，因此它避免了对这 30 位的 Python 级循环。 内存使用量也轻松低于 256 MB`N = 10^5`。 

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(" ".join(str(x.bit_count()) for x in a))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

# Provided sample
assert run(
    """2
5
1 2 3 4 5
4
2 4 8 16
"""
) == """1 1 2 1 2
1 1 1 1
""", "sample 1"

# Minimum-size case
assert run(
    """1
1
1
"""
) == """1
""", "minimum-size input"

# All values equal
assert run(
    """1
5
15 15 15 15 15
"""
) == """4 4 4 4 4
""", "all-equal values"

# Boundary values, including the largest allowed value
assert run(
    """1
6
1 2 3 4 5 1000000000
"""
) == """1 1 2 1 2 13
""", "boundary values"

# Maximum-size case
max_n = 100000
inp = "1\n" + str(max_n) + "\n" + ("1 " * (max_n - 1)) + "1\n"
expected = " ".join(["1"] * max_n) + "\n"

assert run(inp) == expected, "maximum-size input"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 / 1 / 1`|`1`| 最小有效输入和尽可能最低的编码纸 |

 |`1 2 3 4 5 1000000000`|`1 1 2 1 2 13`| 二的幂、相邻值和最大数值边界 |

 ## 边缘情况

 最小值`1`表示为`1₂`，所以输入```
1
1
1
```产生```
1
```该算法调用`1.bit_count()`，返回`1`。 输入约束中没有零值，因此不需要处理空的二进制表示。 

2 的幂恰好包含一个设置位。 例如，```
1
4
1 2 4 8
```给出```
1 1 1 1
```这些值具有不同的二进制长度，但每种表示都包含一个`1`。 这捕获了意外计算二进制数字而不是设置位的实现。 

具有连续设置位的值执行表示的另一侧。 为了```
1
1
15
```我们有`15 = 1111₂`，所以答案是```
4
```电话`15.bit_count()`直接计算所有四个设定位置。 

最大允许值也不需要特殊的算术。 为了```
1
1
1000000000
```二进制表示包含 13 个设置位，因此输出为```
13
```Python 准确地处理这个值，并且`bit_count()`工作时没有任何溢出或有符号整数问题。 

最后，一个测试用例包含`100000`学生检查算法的规模。 如果每张纸都是`1`，每个答案都是`1`，因此输出包含`100000`那些。 每个学生都是独立处理的，算法不会意外合并相邻值或丢失顺序。
