 ## 解决方案
 ## 问题理解

 比赛结果仅取决于最终进球数。 对于每个测试用例，`X`是巴沙尔队的进球数，`Y`是滨田队的得分。 任务是比较这两个整数并打印`Bashar`什么时候`X`较大，`Hamada`什么时候`Y`更大，并且`Iskandar`当它们相等时。 

原始故事包含许多有关球员、伤病、换人和比赛持续时间的详细信息，但这些值都不会影响所请求的结果。 一旦提供了两个最终分数，整个问题就简化为一次比较。 

每个分数都介于`0`和`100000`，因此这些值很适合标准整数类型。 更重要的是，这个范围根本不需要探索。 即使有很多测试用例，每个用例执行恒定工作量的解决方案也很容易满足 1 秒的限制。 一种花费的方法`O(100000)`对每个测试用例的操作已经不必要地昂贵，而分数范围内的任何二次方都是完全不合适的。 

在一些简单的情况下，实施可能会出错。 当巴沙尔有更多目标时，比如```
1
6 2
```正确的输出是`Bashar`。 仅检查分数是否相等的粗心实现可能会错误地将每次非平局视为相同的结果。 

当滨田有更多目标时，例如```
1
1 5
```正确的输出是`Hamada`。 颠倒比较会默默地产生错误的获胜者。 

平等的情况也很重要：```
1
3 3
```正确的输出是`Iskandar`。 一个实现仅使用`if X > Y`和`else`会错误打印`Hamada`，因为相等性必须单独处理。 

最后，零分对于任何一支球队来说都是有效的。 为了```
1
0 0
```结果是`Iskandar`，因此比较必须在不假设任何一支球队至少得分一次的情况下进行。 

## 方法

 一种刻意的暴力方法可以逐一检查分数值，并尝试通过扫描可能的范围来确定两个给定分数中哪一个更大。`0`到`100000`。 这最终给出了正确的答案，因为每个有效分数都在该范围内，但它完全忽略了两个实际值已经可用的事实。 在最坏的情况下，这会执行`100001`一个测试用例的迭代。 如果有`100000`测试用例，这将达到大约`10^10`迭代次数，这远远超出了 1 秒的限制。 

暴力破解之所以有效，是因为它最终会遇到相关的分值，但会失败，因为它花时间探索与答案无关的值。 关键的观察是确定获胜者根本不需要搜索。 两个给定分数之间的关系已经是完整的答案：越大则球队获胜，越小则另一队获胜，相等则意味着平局。 

因此，每个测试用例都需要一次比较和一个输出决策。 这将工作量从依赖于分数范围减少到每个测试用例的恒定量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(T * 100000)`|`O(1)`| 太慢而且没必要 |
 | 最佳|`O(T)`|`O(T)`对于收集的输出| 已接受 |

 ## 算法演练

 1.读取测试用例数量`T`。 以下每个测试用例都包含两支球队的最终得分。 
2. 对于每个测试用例，请阅读`X`和`Y`。 无需模拟足球比赛，因为输入已经给出了计分过程的最终结果。 
3.比较`X`和`Y`。 如果`X > Y`，巴沙尔队的目标更多，所以答案是`Bashar`。 
4. 如果`X < Y`，滨田队的目标更多，所以答案是`Hamada`。 
5. 如果两个分数都不大，则它们必须相等。 在这种情况下，打印`Iskandar`。 
6. 存储每个答案并在处理输入后打印所有答案。 收集字符串也避免了重复调用`print`对于每个单独的测试用例。 

### 为什么它有效

 对于每个测试用例，之间恰好存在三种互斥关系之一`X`和`Y`：`X > Y`,`X < Y`， 或者`X = Y`。 该算法将这三种可能性直接映射到三个所需的结果，`Bashar`,`Hamada`， 和`Iskandar`。 由于获胜者仅由最终得分较高者决定，因此所选结果始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        x, y = map(int, input().split())

        if x > y:
            answers.append("Bashar")
        elif x < y:
            answers.append("Hamada")
        else:
            answers.append("Iskandar")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```第一行写着`T`，它准确地告诉程序有多少个分数对。 然后循环一次处理一个完整的匹配结果。 

三路`if`结构体直接实现算法。 严格的比较决定了两个可能的获胜者，而最终的结果`else`代表平等。 不需要对零或最大分数进行特殊处理，因为普通整数比较已经正确处理两个边界。 

分数最多是`100000`，所以整数溢出在 Python 中不是一个问题。 事实上，该程序根本不会对分数进行算术运算，而只是进行比较。 

答案累积在一个列表中，并在末尾用换行符连接。 当测试用例数量很大时，这可以保持输出处理的效率。 

## 工作示例

 考虑示例 1 中的前两个测试用例。 

| 测试案例|`X`|`Y`| 比较| 回答 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 5 |`1 < 5`|`Hamada`|
 | 2 | 2 | 0 |`2 > 0`|`Bashar`|

 在第一场比赛中，滨田对巴沙尔的进球有五个进球，因此第二个分支产生`Hamada`。 对于第二场比赛，巴沙尔有两个进球，而哈马达没有进球，因此第一个分支产生`Bashar`。 这些案例展示了比较的两个方向。 

示例 1 中的相等情况给出了另一个有用的线索。 

| 测试案例|`X`|`Y`| 比较| 回答 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 |`0 == 0`|`Iskandar`|
 | 2 | 3 | 3 |`3 == 3`|`Iskandar`|

 任何一行的严格比较都不会成功。 算法达到相等情况并输出`Iskandar`。 这证实了按照要求，零零分和正平局的处理方式相同。 

样本 1 的最后两行既练习了较大分数边界方向，又练习了另一个普通胜利。 

| 测试案例|`X`|`Y`| 比较| 回答 |
 | --- | --- | --- | --- | --- |
 | 1 | 6 | 2 |`6 > 2`|`Bashar`|
 | 2 | 2 | 0 |`2 > 0`|`Bashar`|

 每行的不变量是答案仅由两个当前分数的排序决定。 其他测试用例的信息不会影响当前的决策。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(T)`| 每个测试用例执行一次比较和不断的额外工作 |
 | 空间|`O(T)`| 输出字符串在打印之前被存储 |

 分数限制为`100000`不会影响运行时间，因为算法从不迭代可能的分数。 即使有大量测试用例，每个用例也只需要进行一次恒定时间比较，这完全符合 1 秒的限制。 内存使用量也很小，因为每个测试用例仅提供一个短输出字符串。

import sys

def solve():

    t = int(input())
    answers = []

    for _ in range(t):

        if x > y:
            answers.append("Bashar")

            answers.append("Hamada")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 边缘情况

 对于相同的分数，请考虑输入```
1
3 3
```该算法首先检查`3 > 3`，这是假的，然后检查`3 < 3`，这也是假的。 剩下的可能性是相等的，所以输出`Iskandar`。 同样的推理适用于`0 0`和`100000 100000`。 

对于一侧的零分，请考虑```
1
0 7
```第一个比较，`0 > 7`，为假。 第二个比较，`0 < 7`，为 true，因此输出为`Hamada`。 没有特殊的零情况，因为零在整数比较下表现正常。 

反过来的情况是```
1
7 0
```这里`7 > 0`为 true，因此输出为`Bashar`。 测试两者`0 7`和`7 0`捕获意外交换两个输入变量或获胜者名称的实现。 

在上边界处，```
1
100000 99999
```给出`Bashar`， 尽管```
1
99999 100000
```给出`Hamada`。 该算法执行与较小值相同的两次比较，因此在`100000`。 

中心边缘情况是相等，因为像这样的两个分支实现`if X > Y: Bashar else: Hamada`将平等视为滨田的胜利。 明确的第三个结果是将正确的解决方案与常见错误区分开来的。
