 ## 解决方案
 ## 问题理解

 比赛结果仅取决于最终进球数。 对于每个测试用例，`X`是巴沙尔队的进球数，`Y`是滨田队的得分。 我们需要比较这两个整数并打印获胜球队的名称，或者`Iskandar`当分数相等时。 

有关球员、伤病、换人和比赛时间的故事不影响计算。 一旦知道最终分数，每种可能的结果都恰好属于以下三种情况之一：`X > Y`,`X < Y`， 或者`X == Y`。 

的价值观`X`和`Y`至多是`10^5`，因此即使对一个测试用例进行线性扫描也是很便宜的。 然而，没有理由扫描任何东西，因为答案是通过一次比较确定的。 和`T`测试用例，一个`O(T)`解决方案在每种情况下仅执行恒定量的工作，这很容易在 1 秒的限制内。 任何执行与分数本身成正比的工作的方法都是不必要的，并且两个分数上的嵌套过程可以大致达到`10^10`对单个对进行操作，这显然是不合适的。 

有一些简单的情况可能会暴露粗心的实现。 如果分数相同，结果一定是`Iskandar`。 例如，输入`3 3`产生`Iskandar`; 使用`>=`因为巴沙尔的胜利会错误地打印`Bashar`。 如果巴沙尔得分为零，而哈马达得分更高，例如`0 1`，结果是`Hamada`; 将零视为特殊获胜值的代码是错误的。 反向边界情况，`1 0`，必须产生`Bashar`。 最后，`0 0`是平局并且必须产生`Iskandar`，因此必须显式检查相等性或通过比较结构正确表示。 

## 方法

 暴力方法可以通过在一支球队的计数中重复添加一个进球并最终比较结果值来模拟得分差异。 例如，判断是否`X`大于`Y`，可以反复从两个分数中删除一球，直到一球归零。 这是正确的，因为每个配对删除都会保留较大的原始分数。 然而，在最坏的情况下`X = 100000`和`Y = 99999`，这几乎执行`100000`一个测试用例的迭代。 在大量测试用例中，不必要的工作可能会变得很重要，即使实际答案只需要一次比较。 更极端的嵌套模拟可以执行高达`10^10`操作，远远超出了时间限制。 

关键的观察结果是，输入已经包含确定获胜者所需的确切数量。 没有要重建的隐藏状态，也没有要模拟的目标序列。 比较两个最终分数可以直接完整地表征结果。 暴力破解之所以有效，是因为它最终发现了两个数字之间的顺序，但通过比较运算符已经可以立即获得该顺序。 

因此最优解为`X`和`Y`，比较一次，并打印相应的结果。 每个测试用例都需要恒定的时间，给出`O(T)`总时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(T × 最大(X, Y)) | O(1) | O(1) | 不必要的缓慢 |
 | 最佳| O(T)| O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`T`，因为必须对每场比赛独立执行相同的比较。 
2. 对于每个测试用例，请阅读`X`和`Y`，代表巴沙尔队和哈马达队的最终目标。 
3.如果`X > Y`， 打印`Bashar`。 巴沙尔队的进球严格来说更多，所以是胜利者。 
4. 否则，如果`X < Y`， 打印`Hamada`。 前面的条件已经排除了巴沙尔获胜的可能性，而哈马达严格来说进球更多。 
5. 否则，两个分数相等，因此打印`Iskandar`。 这涵盖了诸如`0 0`和`3 3`。 

为什么它有效：在每个测试用例中，`X`和`Y`保留最终分数。 正是其中之一`X > Y`,`X < Y`， 或者`X == Y`对于两个整数都成立。 该算法将这三种互斥情况中的每一种分配给其所需的输出，因此它不会产生不正确的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    x, y = map(int, input().split())

    if x > y:
        print("Bashar")
    elif x < y:
        print("Hamada")
    else:
        print("Iskandar")
```第一行写着`T`，它精确控制需要处理的分数对的数量。 使用`sys.stdin.readline`提供快速输入，同时保持实施简单。 

在循环内部，`x`和`y`被解析为整数。 对于这些约束，Python 整数不存在溢出问题，并且这些值远低于任何实际的整数限制。 

比较顺序处理分数之间的三种可能的关系。 相等的情况被放在最后，因为如果严格的不等式都不成立，那么唯一剩下的可能性是`x == y`。 不存在差一的问题，因为该问题仅询问最终整数分数的排序。 

每个结果都会立即打印，因此无需将所有测试用例或所有答案存储在内存中。 

## 工作示例

 对于第一个示例，请考虑前三个测试用例。 

| 测试案例|`x`|`y`| 比较| 输出|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 5 |`1 < 5`|`Hamada`|
 | 2 | 2 | 0 |`2 > 0`|`Bashar`|
 | 3 | 0 | 0 |`0 == 0`|`Iskandar`|

 第一种情况确认分数较小者输。 第二个练习是一个团队没有目标的边界。 第三个确认平等采用平局分支，而不是任一获胜分支。 

对于其余示例案例：

 | 测试案例|`x`|`y`| 比较| 输出|
 | ---| ---| ---| ---| ---|
 | 4 | 3 | 3 |`3 == 3`|`Iskandar`|
 | 5 | 6 | 2 |`6 > 2`|`Bashar`|

 第四种情况表明平局的处理与实际得分值无关。 第五个确认了巴沙尔得分较大时的普通获胜情况。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(T)| 每个测试用例都需要一次恒定时间比较。 |
 | 空间| O(1) | O(1) | 仅存储当前的分数对和循环状态。 |

 该解决方案为每个测试用例执行少量恒定的工作。 即使最大可能得分值为`10^5`，分数的大小对运行时间没有影响，因为算法从不迭代目标本身。 内存使用量也是恒定的并且完全低于 256 MB 限制。

def solve():
    input = sys.stdin.readline

    t = int(input())

    for _ in range(t):
        x, y = map(int, input().split())

        if x > y:
            print("Bashar")

    old_stdout = sys.stdout

 ## 边缘情况

 第一个不明显的情况是平局。 用于输入`3 3`，算法首先检查`3 > 3`，这是假的，然后检查`3 < 3`，这也是假的。 已经进入决赛了`else`分支和打印`Iskandar`。 同样的推理适用于`0 0`，所以零不需要单独的特殊情况。 

第二种情况是巴沙尔没有进球，而哈马达有进球。 用于输入`0 1`,`x > y`是假的并且`x < y`是真的，所以算法打印`Hamada`。 这证实了零被视为普通分数。 

情况相反，输入`1 0`，到达第一个分支，因为`1 > 0`, 生产`Bashar`。 不需要对下限进行特殊处理。 

在上边界处，输入`100000 99999`产生`Bashar`因为第一个比较是正确的。 输入`99999 100000`产生`Hamada`， 和`100000 100000`产生`Iskandar`。 这些案例表明，该算法在最大允许值和等式边界附近保持正确。
