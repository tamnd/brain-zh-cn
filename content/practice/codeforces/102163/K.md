 ## 解决方案
 ## 问题理解

 我们有一个数组`A`代表排成一排的学生盘子里的披萨片。 Masaoud 必须选择该数组的一个连续段，这意味着他选择某个左端点`l`和右端点`r`，并偷走每一片`A[l..r]`。 我们需要计算有多少个不同的连续段的总和严格小于`X`。 

“严格”这个词很重要。 其总和恰好为的段`X`无效。 由于每`A[i]`是正数，延长一段只能增加其总和。 这种单调性使得线性时间解决方案成为可能。 

和`N`一样大`10^5`，检查每对端点已经太昂贵了。 有`N(N+1)/2`连续的段，大约是`5 * 10^9`什么时候`N = 10^5`。 单独检查每个段的解决方案无法满足 1 秒的时间限制。 我们需要一个接近的算法`O(N)`每个测试用例。 的价值观`A[i]`和`X`可以达到`10^9`，答案可以是`5 * 10^9`，因此实现还需要能够存储大于 32 位整数的值的整数类型。 Python 整数自然地处理这个问题。 

一个常见的边界错误是将总和视为等于`X`为有效。 例如，与`N = 1`,`X = 4`， 和`A = [4]`，唯一有总和的段`4`，所以答案是`0`， 不是`1`。 条件是`sum < X`， 不是`sum <= X`。 

另一个错误是忘记单个元素已经可以使窗口无效。 为了`N = 2`,`X = 3`， 和`A = [5, 1]`， 两者都不`[5]`也不`[5, 1]`是有效的，同时`[1]`是有效的，所以答案是`1`。 滑动窗口实现必须重复移动其左端点，直到当前总和再次有效。 

第三个问题是假设答案适合 32 位整数。 和`N = 100000`,`X = 100001`，以及每一个`A[i] = 1`，每个非空连续段都是有效的。 答案是`100000 * 100001 / 2 = 5,000,050,000`，大于`2^32`仅略低于它，但已经远远超出了有符号的 32 位范围。 

## 方法

 直接的解决方案是枚举每对可能的端点。 对于每个起始位置`l`，我们可以扩展`r`从`l`通过`N - 1`，维持当前总和，并在总和小于时增加答案`X`。 这是正确的，因为每个非空连续段都恰好有一对端点，因此每个有效段都被计数一次。 

即使我们维持运行总和而不是从头开始重新计算，仍然有`N(N+1)/2`端点对。 为了`N = 10^5`， 那是`5,000,050,000`最坏情况下的段检查。 这远远超出了 1 秒的限制。 

蛮力方法之所以有效，是因为它明确地检查了每个候选片段。 它失败了，因为候选人太多。 关键的观察结果是所有数组值都是正数。 假设当前窗口的总和小于`X`。 如果我们延长它的右端点，总和只会增加。 相反，如果窗口变得太大，将其左端点向右移动只能减少总和。 

这意味着我们可以为每个右端点维护一个有效的滑动窗口。 对于固定的右端点`r`， 让`l`是最小的左端点，使得`A[l..r]`总和小于`X`。 因为所有值都是正数，所以每个段都以`r`并从任何地方开始`l`通过`r`也是有效的。 正好有`r - l + 1`这样的细分市场。 

我们可以找到这个最小的有效值`l`只要当前总和至少为，就向前移动左指针`X`。 每个元素进入窗口一次，最多离开窗口一次，因此指针移动的总数是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了|
 | 滑动窗 | O(N) | 输入数组的 O(N) | 已接受 |

 ## 算法演练

 1. 两个指针都从数组的开头开始，所以`left = 0`，并保留`current_sum = 0`和`answer = 0`。 
2. 移动`right`从`0`到`N - 1`。 添加`A[right]`到`current_sum`，因为新的右端点意味着该元素现在属于当前窗口。 
3.同时`current_sum >= X`， 移动`left`向前和减去`A[left]`从`current_sum`增加之前`left`。 该循环是必要的，因为一次删除可能不足以使总和严格小于`X`。 
4. 循环结束后，当前窗口`A[left..right]`总和小于`X`。 由于所有元素都是正数，因此每个段都以`right`其左端点在`left`和`right`总和也小于`X`。 
5. 添加`right - left + 1`到`answer`。 这会精确计算以当前位置结束的有效段。 
6. 重复直到所有可能的右端点都被处理完，然后输出`answer`。 

### 为什么它有效

 每次迭代后，`left`是当前窗口的最小索引`A[left..right]`总和严格小于`X`。 任何结束于`right`并开始之前`left`包含当前有效窗口加上至少一个附加正元素，因此其总和至少为`X`并且它不可能是有效的。 每个段开始于`left`或稍后是有效窗口的子段，因此具有更小的或相等的正和，因此它是有效的。 因此确切地说`right - left + 1`有效段结束于`right`。 

因为`right`只会向前移动并且`left`也只向前移动，不会多次向滑动窗口添加或删除元素。 因此，该算法在线性时间内处理整个数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        left = 0
        current_sum = 0
        answer = 0

        for right in range(n):
            current_sum += a[right]

            while current_sum >= x:
                current_sum -= a[left]
                left += 1

            answer += right - left + 1

        print(answer)

if __name__ == "__main__":
    solve()
```每个测试用例读取一次输入，并存储数组，以便当窗口变得太大时，左指针可以减去元素。 主循环直接对应于算法的右指针步骤。 

这`while current_sum >= x`条件使用`>=`，而不是`>`，因为总和恰好等于`X`无效。 循环结束后，不变量为`current_sum < x`。 

表达式`right - left + 1`计算结束于的有效段的可能起始位置`right`。 两个端点都包含在内，因此`+1`是必要的。 例如，如果`left == right`，只有一个段，即位于`right`。 

当答案达到数十亿时，Python 的整数类型可以避免溢出。 在具有固定宽度整数类型的语言中，答案应存储在 64 位整数中。

 ## 边缘情况

 当段和正好是`X`，必须将其排除。 考虑`N = 1`,`X = 4`， 和`A = [4]`。 该算法添加`4`，看到`current_sum >= X`，去除`A[0]`，并取得进展`left`到`1`。 当前窗口是空的，所以`right - left + 1 = 0`。 输出是`0`，它正确地处理了严格的不等式。 

当一个元素大于`X`，算法可能会移动`left`超出当前的`right`。 为了`N = 3`,`X = 4`， 和`A = [1, 5, 1]`, 处理后`1`答案是`1`。 添加后`5`，总和是`6`，所以算法删除了`1`，离开`5`，然后删除`5`，留下一个空窗口`left = 2`。 没有以索引结尾的段`1`是有效的。 添加最后的后`1`，窗口仅包含该元素，因此又计算了一个段。 最终的答案是`2`，对应于`[1]`在每一端。 

一个重要的答案是另一种情况，它可以悄悄地破坏使用 32 位整数的实现。 和`100000`元素全部等于`1`和`X = 100001`，最大可能的段和是`100000`，因此每个非空段都是有效的。 该算法添加`1 + 2 + ... + 100000`，得到`5,000,050,000`。 Python 存储这个值不会溢出，并且测试确认即使在最大范围内计数表达式也是正确的。 

最后，当所有元素都为正时，滑动窗口的单调性得到保证。 例如，与`A = [2,2,2,2]`和`X = 10`，每个段的总和如下`10`， 所以`left`从不移动。 在每个右端点，算法添加`1`， 然后`2`， 然后`3`， 然后`4`, 给予`10`有效段总数。 这证明了核心不变量：一旦窗口有效，该窗口的每个后缀也有效，因为删除正元素不能增加其总和。
