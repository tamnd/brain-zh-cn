 ## 解决方案
 ## 问题理解

 我们有一系列披萨数量，其中`A[i]`是切片的数量`i`第-个学生的盘子。 Masaoud 必须选择这个数组的一个非空的连续段，即一组连续的学生，并且所选值的总和必须严格小于`X`。 

任务是计算总和小于的每个连续子数组`X`。 不同的位置定义不同的组，因此即使不同位置的相同值也代表不同的选择。 

约束足够大，足以排除直接检查每个子数组的可能性。 和`N = 10^5`， 有`N(N+1)/2`，或关于`5 * 10^9`，最坏情况下可能的连续组。 即使是 O(N²) 算法也远远超出 1 秒的时间限制可以处理的范围。 数组中的正值是允许在线性时间内解决问题的关键结构属性。 

有几种边界情况可能会暴露粗心的实现。 一、条件严格`< X`， 不是`<= X`。 例如，与`N = 1`,`X = 4`， 和`A = [4]`，正确的输出是`0`，因为唯一的子数组的和正好`4`。 一个实现使用`sum <= X`会错误地计算它。 

第二种情况是每个元素都已经太大了。 为了`N = 3`,`X = 5`， 和`A = [5, 6, 7]`，答案是`0`。 滑动窗口实现必须删除元素，直到当前总和低于`X`在计算任何东西之前。 

第三种情况是整个数组有效。 为了`N = 3`,`X = 10`， 和`A = [1, 2, 3]`，每个非空子数组的总和如下`10`，所以答案是`6`。 计数必须包括每个可能长度的子数组，而不仅仅是单个元素。 

最后，答案本身可能比`N`。 和`N = 10^5`并且足够大`X`，每个子数组都是有效的，给出`10^5 * 100001 / 2 = 5,000,050,000`有效组。 Python 整数自然地处理这个问题，而使用 32 位整数的语言会溢出。 

## 方法

 直接的方法是枚举每个可能的起始位置和每个可能的结束位置，计算该子数组的总和，并在总和小于时增加答案`X`。 有`N(N+1)/2`子数组。 如果通过扩展右端点并添加一个元素来计算每个和，则总工作量为 O(N²)，大约为`5 * 10^9`迭代时`N = 10^5`。 前缀和可以使每个子数组的和为 O(1)，但仍然有 O(N²) 对端点，因此整体复杂度仍然是二次的。 

蛮力方法之所以有效，是因为每个连续组都只被考虑一次。 问题在于，它花费时间考虑可以从已经检查的组中推断出其有效性的组。 

关键的观察来自于这样一个事实：每个`A[i]`是积极的。 假设我们修复了一个右端点`r`并考虑以以下结尾的子数组`r`。 当我们将它们的左端点向左移动时，它们的总和只会增加。 一旦特定的左端点产生至少为`X`，每个较早的左端点也将至少产生一个总和`X`。 

这种单调行为允许两指针滑动窗口。 维护一个窗口`[left, right]`其总和严格小于`X`。 什么时候`right`前进，新元素增加总和。 如果总和达到或超过`X`， 移动`left`向前并减去删除的值，直到窗口再次有效。 

一次`[left, right]`有效，每个子数组结束于`right`并从任何地方开始`left`通过`right`也是有效的。 正好有`right - left + 1`这样的子数组。 添加该数字会计算以当前位置结束的所有有效组，而无需显式枚举它们。 

数组的积极性才是让人感动的原因`left`安全的。 删除元素只能减少总和，扩展右端点只能增加总和。 如果允许负值，这种单调关系就会消失，并且相同的滑动窗口参数将不再有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 最优滑动窗口 | O(N) | O(1) 辅助空间 | 已接受 |

 ## 算法演练

 1. 设置`left = 0`,`current_sum = 0`， 和`answer = 0`。 指针`left`将表示仍然可以生成以当前右端点结束的有效子数组的最小起始位置。 
2. 移动`right`从`0`通过`N - 1`。 添加`A[right]`到`current_sum`，因为当前窗口刚刚扩展以包括新学生。 
3.同时`current_sum >= X`， 消除`A[left]`从`current_sum`和增量`left`。 窗口必须严格小于`X`，所以等于`X`也无效。 因为每个数组值都是正数，所以移动`left`向前只能减少总和，因此最终窗口变得有效，除非甚至是单个元素`A[right]`至少是`X`。 
4. 循环结束后，`[left, right]`总和严格小于`X`。 每个起始位置从`left`通过`right`给出另一个结束于的有效子数组`right`。 因此添加`right - left + 1`到`answer`。 
5. 重复，直到处理完所有可能的右端点。 打印`answer`对于测试用例。 

### 为什么它有效

 不变的是，在收缩阶段之后，`current_sum`是`[left, right]`并且严格小于`X`，而每个子数组都以`right`其起始位置在之前`left`至少有总和`X`。 

什么时候`right`是固定的，从左侧删除元素会使总和更小，因为所有值都是正数。 因此第一个有效的`left`将所有可能的起始位置分为两组：来自`0`通过`left - 1`无效，而来自的位置`left`通过`right`是有效的。 正好有`right - left + 1`有效的选择，因此添加到答案中的金额是准确的。 

每个指针仅向前移动。 右指针移动`N`次，虽然内部循环看起来执行了许多操作，`left`最多也动`N`遍及整个测试用例的次数。 这给出了线性的总功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        left = 0
        current_sum = 0
        answer = 0

        for right in range(n):
            current_sum += a[right]

            while current_sum >= x and left <= right:
                current_sum -= a[left]
                left += 1

            answer += right - left + 1

        print(answer)

if __name__ == "__main__":
    solve()
```输入部分读取测试用例的数量，然后读取每个用例的数组。 存储数组很方便，因为左指针可能需要减去之前添加的值。 

主循环通过添加来扩展窗口`a[right]`。 这`while`条件使用`>= x`，而不是`> x`，因为所需条件严格小于`X`。 

如果新添加的元素本身至少是`X`，收缩循环最终也会删除该元素。 之后`left`变成`right + 1`,`current_sum`变为零，并且`right - left + 1`为零。 这正确地计算出以该位置结尾的有效子数组。 

答案仅在窗口有效后更新。 表达式`right - left + 1`计算有效范围内所有可能的起始位置`[left, right]`。 

Python 整数具有任意精度，因此答案可以安全地超过 32 位整数范围。 事实上，与`N = 10^5`，最大答案是`5,000,050,000`。 

操作顺序也很重要。 我们首先添加新的右端点，然后收缩直到满足严格的不等式，然后才计算有效的开始。 收缩之前的计数将包括无效的子数组。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每个测试用例 O(N) |`right`从左向右移动一次，并且`left`最多也向前移动`N`次 |
 | 空间| O(N) | 数组被存储； 滑动窗口状态本身使用 O(1) 辅助空间 |

 在所有测试用例中，时间为 O(`N`），当前测试用例的存储数组空间为 O(N)。 和`N`最多`10^5`，该算法仅对每个元素执行恒定数量的操作，并且完全符合限制。 在最坏的情况下，最初的二次方法将需要数十亿次运算。

## 边缘情况

 对于严格不等式的情况，请考虑：```
1
1 4
4
```该算法添加`4`，看到`current_sum >= X`，并删除唯一的元素。 结果窗口是空的，所以`right - left + 1 = 0`。 输出是`0`，完全按照要求。 一个实现使用`while current_sum > X`会错误地计算这个子数组。 

对于每个元素都无效的情况，请考虑：```
1
3 5
5 6 7
```在`right = 0`，总和是`5`，因此该元素被删除并且贡献为零。 在`right = 1`，同样的情况发生在`6`，并且在`right = 2`它发生在`7`。 最终的答案是`0`。 空窗口是有效的内部状态，因为问题要求非空组，并且零贡献正确地排除了它。 

对于每个子数组都有效的情况，请考虑：```
1
3 10
1 2 3
```窗口永远不需要缩小。 在三个右端点，算法贡献`1`,`2`， 和`3`，生产`6`。 这些贡献对应于在每个相应位置结束的所有子数组。 

对于大答案的情况，考虑一系列`100000`与`X = 10^12`。 因为即使整个数组也只有和`100000`，不会发生收缩。 在索引处`r`， 确切地`r + 1`结尾的子数组是有效的，所以总数是`1 + 2 + ... + 100000 = 5,000,050,000`。 

Python 存储该值不会溢出，并且该算法仍然只执行 O(N) 工作。
