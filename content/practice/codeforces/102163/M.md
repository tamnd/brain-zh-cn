 ## 解决方案
 ## 问题理解

 对于每个测试用例，我们比较两种形式的工资 (B_1^{P_1}) 和 (B_2^{P_2})。 第一对描述原始工资，第二对描述新工资。 我们需要打印`Congrats`当新的工资更大时，`HaHa`当它更小时，并且`Lazy`当两个人的工资完全相等时。 

底数和指数的值都可以达到(10^6)。 直接构造(B^P)是不现实的。 即使 (2^{10^6}) 也有大约 300,000 个小数位，因此普通的大整数求幂需要操作数十万位数字才能进行单次比较。 由于有多个测试用例和 3 秒的限制，这种方法远远超出了我们想要的。 

有用的变换是

 [
 B^P = e^{P\ln B}。 
]

 由于指数函数是严格递增的，因此比较两个正幂相当于比较它们的对数：

 [
 B_1^{P_1} < B_2^{P_2}
 \当且仅当
 P_1\ln B_1 < P_2\ln B_2。 
]

 这将大量的整数比较变成了一些浮点运算。 

在取对数之前必须区分几种边缘情况。 如果底数为零并且其指数为正，则该值为零。 例如，```
1
0 5 2 3
```有工资 (0^5=0) 和 (2^3=8)，所以答案是`Congrats`。 呼唤`log(0)`将无效。 

每当底数为正时，零指数就会产生值 1。 例如，```
1
7 0 1 5
```将 (7^0=1) 与 (1^5=1) 进行比较，所以答案是`Lazy`。 将零指数视为使整个表达式为零的粗心实现将是错误的。 

输入保证排除了每个薪资表达式的 (0^0)，因此我们不需要为其分配特殊的数学含义。 例如，这对`(0, 0)`不能作为任一薪水的完整描述出现。 

最后，等幂可以有不同的底数和指数。 例如，```
1
2 4 4 2
```比较 (2^4) 和 (4^2)，两者都等于 16。单独比较底数或指数会失败，而比较 (P\ln B) 可以正确识别相等性。 

## 方法

 直接的方法是计算两个幂并进行比较。 这在数学上很简单，因为我们计算的值正是两个工资。 问题在于它们的大小。 对于 (B=10^6) 和 (P=10^6)，结果数字在最极端的粗略范围内包含大约 (6\cdot10^6\log_{10}10) 位数字，甚至更小的示例 (2^{10^6}) 也已经超过 300,000 位数字。 当我们只需要它们的顺序时，计算和存储这些整数是不必要的工作。 最坏的情况可能需要每个测试用例进行数十万或数百万的数字运算，而不是恒定的算术量。 

关键的观察结果是对数保留正数的顺序。 不计算 (B^P)，而是取其自然对数：

 [
 \ln(B^P)=P\ln B.
 ]

 现在，两个工资都可以用普通浮点数表示，其大小最多约为 (10^6\ln(10^6))，大约为 (1.4\cdot10^7)。 比较变成每个测试用例的恒定时间。 

强力方法之所以有效，是因为求幂可以给出精确的工资，但它会失败，因为这些工资可能包含大量数字。 对数观察根本不需要构造它们。 唯一不能通过此变换的值是零，因此在对数比较之前单独处理零基。 

当两个对数值在数学上相等时，浮点运算还会引入一个微妙的问题。 例如，(2^4) 和 (4^2) 都应该产生`Lazy`，但它们的浮点对数表达式可能会存在微小的舍入误差。 因此，我们将足够小的差异视为平等。 官方风格的解决方案对此比较使用了较小的容差。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 取决于 (B^P) 中的位数，每个测试用例可能有数十万次数字运算 | 可能有数十万位数字 | 太慢/不切实际|
 | 最佳| 每个测试用例 (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取(B_1,P_1,B_2,P_2)。 每对代表一个工资，因此第一对是旧工资，第二对是新工资。 
2. 检查任一基数是否为零。 有效的零基表达式必须具有正指数，因为输入保证排除了 (0^0)。 这样的工资简直就是零。 

如果两个基数都为零，则两个工资都为零，答案是`Lazy`。 如果只有第一个基数为零，则旧工资为零，新工资为正，所以答案是`Congrats`。 如果只有第二个基数为零，则新工资为零，旧工资为正，所以答案是`HaHa`。 
3. 当两个碱基均为正时，计算

 [
 x_1=P_1\ln B_1,\qquad x_2=P_2\ln B_2。 
]

 这是两个工资的对数。 零的指数自然给出 (x=0)，对应于一的工资。 
4. 比较 (x_1) 和 (x_2)。 如果它们的差异在很小的公差范围内，则打印`Lazy`，因为差异足够小，可以通过浮点舍入来解释。 
5. 否则，如果(x_1<x_2)，新的工资更大，所以打印`Congrats`。 如果(x_1>x_2)，新的工资较小，所以打印`HaHa`。 

该算法背后的不变性是，在去除零个案例后，每个工资都是正数，并且对数严格递增。 因此，符号为

 [
 P_2\ln B_2-P_1\ln B_1
 ]

 正是新旧工资差异的标志。 容差仅考虑用于表示对数的有限精度。 无需构建实际薪资值。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

EPS = 1e-10

def solve_case(b1, p1, b2, p2):
    # A valid zero-base expression must have a positive exponent,
    # because 0^0 is excluded by the input guarantee.
    if b1 == 0 or b2 == 0:
        if b1 == b2:
            return "Lazy"
        if b1 == 0:
            return "Congrats"
        return "HaHa"

    # For positive bases:
    # log(B^P) = P * log(B)
    x1 = p1 * math.log(b1)
    x2 = p2 * math.log(b2)

    if abs(x1 - x2) <= EPS:
        return "Lazy"
    if x1 < x2:
        return "Congrats"
    return "HaHa"

def main():
    t = int(input())
    ans = []

    for _ in range(t):
        b1, p1, b2, p2 = map(int, input().split())
        ans.append(solve_case(b1, p1, b2, p2))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```这`solve_case`函数首先处理零基，因为`math.log(0)`未定义。 问题保证意味着如果底数为零，则其对应的指数为正，因此表达式肯定为零。 

一旦两个碱基均为阳性，`math.log(b)`被定义。 乘以指数即可得到相应工资的对数。 这也可以在没有特殊分支的情况下处理指数零：`p * log(b)`变为零，即 (\log(1))。 

比较使用`EPS`而不是测试`x1 == x2`。 浮点对数是近似值，因此数学上相等的表达式（例如 (2^4) 和 (4^2)）可能会产生最后几位不同的值。 直接相等测试可能会错误地打印`Congrats`或者`HaHa`。 

Python 中不存在整数溢出问题，因为整数具有任意精度，但解决方案无论如何都不会构造巨大的幂。 最大的中间对数值只有(10^7)量级，很容易用Python浮点数表示。 

## 工作示例

 对于第一个示例，一起考虑三个测试用例。 

| 测试案例| (B_1) | (P_1) | (B_2) | (P_2) | (x_1=P_1\ln B_1) | (x_1=P_1\ln B_1) | (x_2=P_2\ln B_2) | (x_2=P_2\ln B_2) | 结果 |
 | --- | --- | --- | --- | --- | --- | --- | --- |

 | 3 | 2 | 4 | 4 | 2 | (4\ln2) | (4\ln2) | (2\ln4=4\ln2) |`Lazy`|

 第一种情况，新的工资是（4^2=16），而旧的工资是（2^3=8），所以`Congrats`是正确的。 在第二种情况下，(2^2=4) 小于 (3)，产生`HaHa`。 第三种情况是平等权力的情况，即基数不同但工资相同。 

对于第二条迹线，考虑零基数情况和指数零情况：```
2
0 7 3 2

```| 测试案例| 零基础处理| (x_1) | (x_1) | (x_2) | (x_2) | 结果 |
 | --- | --- | --- | --- | --- |

 第一个案例从未调用过`log(0)`。 它立即识别出新工资为正，而旧工资为零。 第二种情况表明，零的指数自然由对数值零表示，并且(1^5)也具有对数值零。

 ## 边缘情况

 零底绝对不能达到对数计算。 为了```
1
0 5 2 3
```该算法看到`b1 == 0`立即地。 自从`b2`非零，第一个工资为零，第二个工资为正。 它返回`Congrats`不评估任一对数。 颠倒基地，```
1
2 3 0 5
```使新工资为零，因此同一分支返回`HaHa`。 

零指数是幼稚实现可能出错的另一个地方。 为了```
1
7 0 1 5
```两个底数均为正，因此使用对数路径。 第一个工资对数是

 [
 0\cdot\ln7=0,
 ]

 第二个是

 [
 5\cdot\ln1=0。 
]

 它们的差异为零，因此输出为`Lazy`，匹配 (7^0=1^5=1)。 

不同的基数仍然可以代表相同的工资。 为了```
1
2 4 4 2
```该算法计算

 [
 x_1=4\ln2
 ]

 和

 [
 x_2=2\ln4=2(2\ln2)=4\ln2。 
]

 两个浮点值在舍入前相等，因此基于容差的比较会产生`Lazy`。 这就是为什么仅检查底数或指数是否匹配是不够的。 

上限也是使用对数的主要原因。 为了```
1
1000000 1000000 999999 1000000
```实际工资太大，无法直接构建。 该算法仅计算

 [
 10^6\ln(10^6)
 ]

 和

 [
 10^6\ln(999999),
 ]

 这是普通的浮点值。 由于第一个较大，所以新的工资较小，产量为`HaHa`。 

输入保证消除了其他不明确的 (0^0) 情况。 一个测试，例如```
1
0 0 2 3
```不是此问题的有效输入，因此实现不需要为其发明约定。 因此，零处理可以依赖于每个零基工资都恰好为零。
