 ## 解决方案
 # 问题理解

 我们在整数坐标平面上有水平线段和垂直线段的集合。 水平线段由其两个 x 端点及其固定 y 坐标描述。 垂直线段由其两个 y 端点及其固定的 x 坐标描述。 

选择一个水平线段和一个垂直线段仅在它们相交时才会给出加号。 在它们的交点处，水平段贡献左臂和右臂，而垂直段贡献向下臂和向上臂。 该加号的值是这四个臂长中最短的一个。 

对于水平段`[x1, x2]`在高处`y`，与 x 相交，水平贡献为`min(x - x1, x2 - x)`。 

对于垂直段`[y1, y2]`在坐标 x 处，与高度 y 相交，垂直贡献为`min(y - y1, y2 - y)`。 

答案是每个有效交点上所有四个量的最小值的最大可能值。 

高达`10^5`水平和`10^5`垂直段，检查每对需要最多`10^10`交叉点。 二次方法远远超出了一秒限制所能处理的范围。 坐标也受`10^5`，这使得坐标范围内的对数数据结构变得实用。 

有几种边界情况很容易破坏粗心的实现。 首先，交叉点可能恰好发生在端点处。 例如，```

```两条线段相交于`(1, 2)`，所以最短的臂有长度`0`，答案是`0`。 使用严格不等式而不是包容性交集条件的实现可能会错误地报告不存在交集。 

第二个问题是片段可能太短而无法支持所请求的答案。 例如，```

```线段相交于`(2, 2)`，但水平线段只有长度`1`，所以长度没有加号`1`是可能的。 答案是`0`。 在长度可行性检查期间`1`，水平段必须被丢弃，因为它至少需要总长度`2`。 

第三种边界情况是反转端点。 尽管该语句描述了起始坐标和结束坐标，但稳健的实现不应依赖于它们的顺序。 例如，```

```标准化两个线段后，它们相交于`(3, 3)`答案是`2`。 

# 方法

 直接方法将每个水平段和每个垂直段一起考虑。 对于每一对，我们测试它们的 x 和 y 坐标是否落在相应的区间内。 如果它们相交，我们计算四个臂长并更新答案。 这是正确的，因为每个可能的加号都是由一个水平线段和一个垂直线段确定的，因此检查每一对都不会错过最佳值。 

问题是对的数量。 和`N = M = 10^5`, 可以有`N * M = 10^10`对。 即使对每对进行恒定时间检查也太慢了，因此我们需要避免枚举交叉点。 

关键的观察是答案可以被测试而不是直接构建。 假设我们问一个加号的长度是否至少`d`存在。 对于水平段`[x1, x2]`，交点 x 坐标必须满足`x1 + d <= x <= x2 - d`。 

因此水平线段只能通过其缩小的间隔参与`[x1 + d, x2 - d]`，并且只有当`x2 - x1 >= 2d`。 

同样，垂直线段`[y1, y2]`仅当`y1 + d <= y <= y2 - d`。 

所以问题是固定的`d`变成寻找一个水平段，其减小的 x 间隔包含某个可用垂直段的 x 坐标，而水平段的 y 坐标位于该垂直段的减小的 y 间隔内。 

这可以通过从左向右扫动来处理。 按 x 对垂直线段进行排序。 当我们到达 x 处的垂直线段时，减少左端点最多为 x 的每个水平线段都会变为活动状态。 水平线段保持活动状态，直到其缩小的右端点变得小于 x。 

剩下的唯一问题是如何询问活动水平段的 y 坐标是否位于垂直段的缩小 y 间隔内。 由于每个活动水平线在其 y 坐标上贡献一个点，因此 Fenwick 树可以维护每个 y 处存在多少个活动水平线。 然后，范围总和告诉我们是否至少有一个活动水平线位于所需的 y 间隔内。 

谓词是单调的。 如果长度的加号`d`存在，则每个较小长度的加号也存在。 因此，我们可以二分搜索最大可行的`d`。 

蛮力之所以有效，是因为每个候选人都被明确检查，但因为配对太多而失败。 固定答案独立地减少每个线段的观察结果使我们能够将二维相交问题转化为芬威克树的一维扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(NM)`|`O(N + M)`| 太慢了 |
 | 最佳|`O((N + M) log C log C)`|`O(N + M + C)`| 已接受 |

 这里`C <= 10^5`是坐标极限。 一个对数来自对答案的二分搜索，另一个对数来自芬威克树运算。 

# 算法演练

 1. 标准化每个段，使其第一个端点不大于第二个端点。 将水平线段存储为`(x1, x2, y)`和垂直线段`(y1, y2, x)`。 
2. 对水平线段进行一次排序`x1`，对它们进行一次排序`x2`，并对垂直线段进行一次排序`x`。 这些顺序对于每个二分搜索值仍然有效，因为添加或减去相同的值`d`不改变顺序。 
3.二分查找答案`d`。 对于候选人`d`，水平段仅在以下情况下才可用`x2 - x1 >= 2d`。 其可能的交点x坐标形式`[x1 + d, x2 - d]`。 仅当满足以下条件时，垂直段才可用`y2 - y1 >= 2d`，具有可能的交点 y 坐标`[y1 + d, y2 - d]`。 
4. 按 x 递增顺序扫描可用的垂直段。 维护一棵由 y 索引的 Fenwick 树。 当当前垂直线段的坐标为 x 时，添加每个水平线段，其`x1 + d <= x`。 这样的水平段在其左侧有足够的空间，至少可以提供一个手臂的长度`d`。 
5. 删除所有水平线段`x2 - d < x`。 这样的一段不能再提供右臂的长度`d`在当前的 x 处。 严格的`<`至关重要，因为相等意味着右臂的长度正好`d`，这是有效的。 
6.查询Fenwick树`[y1 + d, y2 - d]`。 正范围总和意味着某些活动水平段的 y 坐标位于有效垂直范围内。 该水平线段和当前垂直线段形成一个加号，其四个臂至少都是`d`，所以检查成功。 
7. 如果检查成功，则将二分查找下限向上移动。 否则，将上限向下移动。 最大的成功价值就是答案。 

### 为什么它有效

 对于固定的`d`，在扫描中精确地表示水平线段，同时可以选择其 x 坐标，以便两个水平臂的长度至少`d`。 因此，活动水平段相当于条件`x1 + d <= x <= x2 - d`。 

在坐标为 x 的垂直线段处，芬威克树恰好包含满足该水平条件的所有水平线段的 y 坐标。 查询`[y1 + d, y2 - d]`另外还强制执行垂直臂条件。 因此，当存在一个其四个臂至少都是的交集时，查询恰好成功`d`。 

可行性谓词是单调的，因为减少`d`仅放宽了所需的距离。 因此，二分查找找到最大的可行长度。

```输入阶段首先对端点进行归一化。 这避免了以后的每个操作都处理两个可能的方向。 

三个排序数组是扫描的核心。 排序依据`x1`让算法按照水平线符合条件的确切顺序添加水平线。 排序依据`x2`当它们的右端点太接近当前的 x 坐标时，让它删除它们。 垂直数组按 x 排序，因为扫描本身从左向右移动。 

对于候选人`d`，条件`x1 + d <= x`决定插入。 条件`x2 - d < x`决定去除。 第二个比较是严格的，因为`x2 - d == x`给出右臂`d`，它必须保持有效。 

Fenwick 树存储计数而不是布尔值。 多个水平线段可以具有相同的 y 坐标，因此删除一个线段不得意外删除另一线段。 计数自然地处理重合的 y 值。 

范围查询使用`prefix(high_y) - prefix(low_y - 1)`,

 这是标准的包含 Fenwick 范围总和。 这也处理有效 y 间隔仅包含一个坐标的情况。 

Python 整数不会溢出，因此所有坐标算术都是安全的。 最大的相关坐标只有`10^5`，而二分搜索乘法`2 * d`也很小。
