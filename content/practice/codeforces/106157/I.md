 ## 解决方案
 ## 问题理解

 任务是为单个无符号整数选择存储单元的大小。 系统知道将存储的最大值，并且它希望保留遵循硬件规则的位数：位数本身必须是 2 的幂。 因此，有效的存储大小为 1、2、4、8、16、32、64 等。 

输入是一个整数，表示必须适合内存的最大值。 输出是可以存储该值的最小有效位大小，后跟正确的单数或复数措辞。 

一个存储单元`b`位可以表示来自的值`0`到`2^b - 1`。 因为输入可以大到`10^18`，必须找到答案，而无需迭代所有可能的值直至输入。 任何与工作成正比的方法`n`在最坏的情况下，将需要大约 100 亿次操作，这远远超出了正常竞赛时间限制所允许的范围。 我们只需要检查一小组可能的位大小。 

边缘情况来自两种存储大小之间的边界。 例如，输入`1`必须产生`1 bit`，因为一位可以存储值`0`和`1`。 从两位开始检查的解决方案将错误地输出`2 bits`。 

另一种边界情况是正好等于存储容量减一的值。 用于输入`255`，正确的输出是`8 bits`，因为八位存储来自`0`通过`255`。 一个粗心的解决方案，检查是否`n < 255`而不是`n <= 255`会错误地移动到`16 bits`。 

另一个重要的情况是当该值仅超过 2 的幂边界一倍时。 用于输入`256`，八位已经不够了，因为它们的最大值是`255`。 答案就变成了`16 bits`。 

## 方法

 一种直接的方法是从 1 开始尝试所有可能的位数，并测试那么多位是否可以存储给定值。 检查候选尺寸`b`简单地说就是是否`2^b - 1`至少是所需的最大值。 此方法是正确的，因为它按递增顺序检查大小并在第一个有效大小处停止。 

这种方法的问题取决于候选人是如何产生的。 如果我们想象检查每个可能的位计数`1`直到输入值，最坏情况输入接近`10^18`需要大约`10^18`检查，这是不可能的。 有用的观察是只允许二的幂作为答案。 在超过最大可能输入之前，只有少数这样的值。 我们可以反复将当前答案加倍，直到容量足够大。 

暴力破解的想法之所以有效，是因为答案是第一个有效的大小。 通过观察有效尺寸形成一个微小的几何序列，我们可以跳过它们之间的所有无效尺寸。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从存储大小开始`1`少量。 这是尽可能小的分配，必须予以考虑，因为可以容纳的数量非常少。 
2. 检查该位数是否可以存储所需的最大值。 尺寸为`bits`工作时`2^bits - 1`至少是输入值。 
3. 如果当前尺寸太小，请将其加倍。 这将移动到下一个有效的存储大小，因为所有允许的大小都是 2 的幂。 
4. 继续，直到容量足够大。 第一个有效的尺寸就是所需的答案。 
5. 使用正确的后缀打印尺寸。 唯一的特殊情况是`1`，其中输出应包含`bit`; 所有其他尺寸都使用`bits`。 

为什么有效：该算法仅考虑有效的存储大小，并按升序检查它们。 由于答案被定义为最小的有效尺寸，因此容量达到要求值的第一个尺寸必定是最优选择。 没有跳过的值可能是更好的答案，因为所有跳过的值都不允许存储大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    bits = 1
    while (1 << bits) - 1 < n:
        bits *= 2

    if bits == 1:
        print("1 bit")
    else:
        print(f"{bits} bits")

if __name__ == "__main__":
    solve()
```变量`bits`存储当前分配的位数。 它开始于`1`因为一位存储是一种有效的可能性。 

循环条件检查当前存储大小可表示的最大值。 表达式`(1 << bits) - 1`正是`2^bits - 1`，它避免了浮点计算并将所有运算保留为整数运算。 

乘法`bits`两个是关键的一步。 答案不允许是任意数字，例如`5`或者`12`，因此增加 1 会浪费时间检查无效候选者。 直接在有效存储大小之间加倍跳转。 

最终条件处理唯一的语法异常。 存储大小`1`使用单数形式，而所有较大的尺寸都使用复数形式。

 ## 边缘情况

 对于输入：```
1
```该算法开始于`bits = 1`。 容量计算给出`2^1 - 1 = 1`，这已经足够了，因此跳过循环。 输出是`1 bit`，正确处理单数形式。 

对于输入：```
255
```算法测试`8`位并发现`2^8 - 1 = 255`。 由于比较是包容性的，因此该值完全符合并且答案仍然存在`8 bits`。 

对于输入：```
256
```算法发现`8`位提供容量`255`，这是不够的。 它的大小加倍为`16`，其中容量为`65535`，和输出`16 bits`。 

对于输入：```
1100586419201
```该算法不断将允许的存储大小加倍。 值来自`1`通过`32`位不能代表输入，而`64`比特运河。 由于每个较小的有效大小都会首先被拒绝，因此结果保证是最小的。
