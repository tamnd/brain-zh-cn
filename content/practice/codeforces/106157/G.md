 ## 解决方案
 ## 问题理解

 查理有`n`比赛前几天。 

当他新鲜的时候，他就会获得`a`每天的技能点，但仅限于第一个`x`重置后的连续工作日。 如果他继续努力超越这些`x`日子里，他变得疲惫，收获只有`b`每天的技能点，其中`a ≥ b`。 

他随时都可能开始休息。 休息时间正好持续`y`连续几天并且不提供技能点。 休息结束后，查理又恢复了活力，可以再次享受`x`增益天数`a`。 目标是最大化在可用的技能点上收集的总技能点`n`天。 

约束是问题的关键部分。 两个都`n`其他参数可以大到`10^9`，并且可能最多有`10^4`测试用例。 任何日复一日的模拟都是不可能的。 该解决方案必须基于每个测试用例以恒定时间运行的封闭式优化。 

一个微妙的一点是，休息并不总是有用的。 如果休息所花费的技能多于新时期恢复的技能，那么最佳策略可能就是根本不休息。 

另一个容易犯的错误是假设每个新鲜期都应该被充分利用。 接近日程结束时，可能没有足够的剩余天数来消耗所有`x`新鲜的日子，所以最后的部分必须小心处理。 

考虑：```
n = 5, a = 4, b = 1, x = 3, y = 1
```工作五天可以得到：```
4 + 4 + 4 + 1 + 1 = 14
```第三天后休息一下可以得到：```
4 + 4 + 4 + 0 + 4 = 16
```这次休息是值得的，因为它用疲惫的一天换来了新鲜的一天。 

现在考虑：```
n = 10, a = 6, b = 5, x = 1, y = 5
```休息需要五天才能恢复一天的高价值。 继续工作会好很多。 

## 方法

 蛮力的观点是尝试每一个可能的休息位置。 每个时间表都由由休息时间分隔的工作部分组成。 一段长度的增益`L`是```
a * min(L, x) + b * max(0, L - x)
```这个公式是正确的，但是可能的中断位置的数量呈指数增长，即使对于中等值也变得毫无希望`n`。 

重要的观察是，只有休息的次数才重要。 

假设我们正好取`m`休息。 

这些休息会消耗`m * y`天，离开```
W = n - m * y
```工作日。 

高于疲劳率的总奖金来自新鲜的日子。 每个工作日至少值得`b`。 新鲜的一天会带来额外的收获```
a - b
```奖金。 

和`m`休息，有`m + 1`工作部分。 每个段最多可以贡献`x`新鲜天数，因此新鲜天数总数不能超过```
(m + 1) * x
```并且也不能超过工作日数`W`。 

因此：```
fresh_days = min(W, (m + 1) * x)
```总增益变为```
b * W + (a - b) * fresh_days
```或者```
G(m) = b * (n - m y)
     + (a - b) * min(n - m y, (m + 1) x)
```现在问题变成了一维优化。 

有两个区域。 

什么时候```
n - m y > (m + 1) x
```所有新鲜槽位均已充分利用。 然后```
G(m)
= b n + (a - b) x + m((a - b)x - by)
```这是线性的`m`。 

什么时候```
n - m y ≤ (m + 1) x
```每个工作日都是新鲜的，所以```
G(m) = a(n - m y)
```其减少为`m`增加。 

线性函数后跟递减函数意味着最优值只能出现在边界点之一。 我们可以在常数时间内直接计算这些。

 ## 算法演练

 1.如果`n ≤ x`，每一个可用的日子都可以在最初的新鲜期中度过。 答案很简单：```
a * n
```2. 计算```
m0 = ceil((n - x) / (x + y))
```这是每个剩余工作日都能保持新鲜感的最少休息时间。 
3. 评估第一个候选者：```
G2 = a * (n - m0 * y)
```这对应于所有工作日都是新鲜的第二个区域。 
4. 计算```
c = (a - b) * x - b * y
```这是通过添加一个完整的周期获得的利润，其中包括`x`新鲜的日子和`y`休息日。 
5. 如果`c ≤ 0`，线性区域逐渐减小，因此其最佳点是`m = 0`。 
6.如果`c > 0`，线性区域不断增加，所以它的最佳点就是最大有效点`m`在进入第二个区域之前：```
m1 = m0 - 1
```7. 评估```
G1 = G(m1)
```或者`G(0)`什么时候`c ≤ 0`。 
8. 答案是```
max(G1, G2)
```### 为什么它有效

 对于固定数量的休息，最佳安排完全取决于存在多少个工作段。 每个段最多贡献`x`新鲜天数，所以新鲜天数的总数正好是`min(W, (m + 1)x)`。 

这将整个问题简化为单个整数的函数`m`。 当新鲜产能完全饱和时，该函数是线性的，一旦每个工作日已经新鲜，该函数就会变成一条递减线。 由于函数只有一个转变点，因此最大值必须出现在第一条线的最佳点或第二条线的第一个点。 评估这些候选人就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, a, b, x, y = map(int, input().split())

        if n <= x:
            print(a * n)
            continue

        m0 = (n - x + (x + y) - 1) // (x + y)

        ans = a * (n - m0 * y)

        c = (a - b) * x - b * y

        if c <= 0:
            m = 0
        else:
            m = m0 - 1

        w = n - m * y
        g = b * w + (a - b) * min(w, (m + 1) * x)

        ans = max(ans, g)

        print(ans)

solve()
```第一个分支处理简单的情况，其中初始新鲜期已经涵盖所有可用天数。`m0`是总新鲜容量足够大以覆盖每个工作日的第一个休息计数。 用上限除法计算它是实现中最微妙的部分。 

变量`c`衡量增加另一个完整的新鲜周期是否有利可图。 如果无利可图，则线性区域中的最佳点立即位于`m = 0`。 否则，线性区域会增加到其边界，因此我们评估过渡之前的最后一个有效点。 

所有算术都适合 64 位整数，但 Python 的任意精度整数甚至消除了这种担忧。

 ## 边缘情况

 考虑：```
1
1 10 5 7 3
```自从`n ≤ x`，查理永远不会感到疲倦。 该算法立即返回：```
10 × 1 = 10
```不需要与中断相关的逻辑。 

考虑：```
1
10 5 5 3 2
```新鲜的日子和疲惫的日子具有相同的价值。 循环利润为负，因为中断只会浪费时间。 该算法选择`m = 0`，生产：```
10 × 5 = 50
```这是最佳的。 

考虑：```
1
5 4 1 3 1
```转变点正好发生在一次断裂处。 该算法评估边界的两侧：```
G(0) = 14
G(1) = 16
```并选择`16`，正确处理最佳策略从连续工作转变为使用重置的点。
