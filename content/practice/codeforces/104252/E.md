 ## 解决方案
 ## 问题理解

 我们有一个 1×N 的棋盘和一组分段图块，从 1 到 N 的每个长度都有一个。最初，长度为 K 的单个图块已经放置在棋盘上的某个位置，在其左侧留下了 E 个空单元格。 该放置固定了占用的间隔，并且还隐式地固定了放置的图块两侧剩余的可用空间。 

初始配置完成后，我们可以放置剩余图块的任何子集。 每个图块都是整数长度的连续段，它必须完全位于棋盘内，并且图块不能重叠。 目标是最大化被覆盖的单元格的总数，这相当于在最佳放置图块后最小化未被覆盖的单元格的数量。 

关键的观察结果是，棋盘是一条线，因此任何最佳解决方案的结构完全取决于我们如何将段打包到剩余的可用空间中，而不是由任何空间排列复杂性决定。 每个图块只是一个长度，放置相当于将可用的空白空间划分为不相交的间隔，其长度必须与所选图块大小相匹配。 

约束很小，N 最大为 1000。这立即排除了对图块或位置的任何指数子集枚举，因为这将达到 2^1000 或 N！，两者都远远超出了可行性。 O(N^2) 或 O(N^2 log N) 方法是可以接受的，甚至 O(N^3) 也可能通过，但没有必要。 

当初始 K-tile 靠近边界时，特别是当 E 等于 0 或 E 接近 NK 时，会出现微妙的边缘情况。 例如，如果 N = 6、K = 2 和 E = 2，则图块占据单元格 3 到 4，留下两个大小为 2 和 2 的空闲段。将棋盘视为大小为 N−K 的单个连续空闲段的简单方法会错误地合并这两个区域并高估打包能力，因为图块无法跳过固定块。 

另一个极端情况是当 K = 1 时。初始图块很简单，但它仍然将棋盘分割成大小为 E 和 N−E−1 的两部分，并且忘记分割会导致错误的贪婪打包决策。 

## 方法

 蛮力的想法是尝试所有可用图块的子集以及将它们放入空闲单元的所有方法。 对于每个子集，我们还需要决定排序和定位，本质上是解决线路上的打包问题。 即使我们固定一个顺序，检查子集是否适合也需要模拟放置，而子集的数量本身就是 2^N，这已经主导了任何可能的计算预算。 

蛮力的失败来自于独立处理每个图块以及将每个放置决策视为组合。 一旦我们停止考虑位置，而是考虑每段的总长度，结构就变得易于管理。 

关键的观察是，在放置初始 K 长度的块之后，板被分成至多两个独立的自由段：大小为 E 的左段和大小为 N−K−E 的右段。 瓷砖不能穿过固定块，因此任何有效的放置都会分解为两个独立的背包式问题。 每条边都可以单独处理：我们选择图块长度的子集，并将每个选定的图块完全分配给左段或右段。 

因此，问题简化为将图块长度分配到两个容量为 E 和 N−K−E 的容器中，以最大化总使用长度。 由于每个图块在使用时都会贡献其完整长度，因此我们希望最大化所选不同整数的总和，并限制所选数字可以在两个容器之间任意分割。 

这成为基于切片大小和两种容量的经典分区 DP。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 + 展示位置 | O(2^N·N) | O(2^N·N) | O(N) | 太慢了 |
 | 二维背包DP | O(N·E·(N−K−E)) ~ O(N^3) 最坏情况 | O(E·R) | 已接受 |

 ## 算法演练

 我们将左侧容量表示为 L = E，将右侧容量表示为 R = N − K − E。 

我们处理从 1 到 N 的图块大小，跳过 K，因为它已被使用。 

1. 我们定义一个 DP 状态 dp[i][l][r]，它表示我们可以使用从 1 到 i 的图块放置的最大总长度，同时最多填充左侧的 l 个单元格和右侧的 r 个单元格。 这直接编码了每个图块必须完全位于一侧或不被使用的约束。 
2. 对于每个长度为 i 的图块，我们考虑三种可能性。 我们跳过它，如果 l ≥ i，则将其放在左侧，如果 r ≥ i，则将其放在右侧。 每个选择都保留了可行性，因为图块是不可分割的且不能重叠。 
3. 我们通过应用这三个选项从 dp[i−1] 转换到 dp[i]，确保每个图块最多使用一次。 
4. 答案是所有有效 l ≤ L 和 r ≤ R 上的最大 dp[N][l][r]，这对应于最大化总覆盖长度。 

这样做的原因是，每个有效的位置都完全对应于将每个图块分配给左段、右段或不使用它的选择。 由固定 K-tile 引起的分割保证了左右之间的独立性，因此没有解决方案需要两侧之间的交互。 DP 会穷尽所有此类分配，而不会重复计算或丢失配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K, E = map(int, input().split())

    L = E
    R = N - K - E

    # dp[l][r] = best sum achievable
    dp = [[0] * (R + 1) for _ in range(L + 1)]

    for i in range(1, N + 1):
        if i == K:
            continue

        for l in range(L, -1, -1):
            for r in range(R, -1, -1):
                best = dp[l][r]

                if l >= i:
                    best = max(best, dp[l - i][r] + i)
                if r >= i:
                    best = max(best, dp[l][r - i] + i)

                dp[l][r] = best

    print((L + R) - max(max(row) for row in dp))

if __name__ == "__main__":
    solve()
```该实现将 DP 压缩到二维，因为我们只需要图块处理的先前状态，以相反的顺序更新以避免覆盖同一迭代中仍然需要的状态。 l 和 r 上的反向迭代至关重要，因为它确保每个图块最多使用一次，模拟二维中的 0-1 背包行为。 

最终答案是总可用空间减去可实现的最佳填充空间。 

## 工作示例

 考虑 N = 6、K = 2、E = 2。然后 L = 2 且 R = 2，可用图块为 {1, 3, 4, 5, 6}。 

我们从概念上跟踪一小部分 DP 更新。 

| 步骤（图块 i）| 考虑采取的行动| dp[2][2] 值 |
 | --- | --- | --- |
 | 开始 | 没有瓷砖| 0 |
 | 我 = 1 | 向左或向右放置| 1 |
 | 我 = 3 | 两边都装不下 | 1 |
 | 我 = 4 | 无法适应| 1 |
 | 我 = 5 | 无法适应| 1 |
 | 我 = 6 | 无法适应| 1 |

 最佳总填充为 1，因此自由空间上的空单元 = 4 − 1 = 3 加上隐式结构调整产生与段分割一致的最终最小空配置。 

现在考虑 N = 5、K = 1、E = 1。然后 L = 1 且 R = 3，图块为 {2, 3, 4, 5}。 

| 步骤| 行动| dp[1][3] | dp[1][3] |
 | --- | --- | --- |
 | 开始 | 无 | 0 |
 | 我 = 2 | 放在右边| 2 |
 | 我 = 3 | 放在右边| 3 |
 | 我 = 4 | 无法适应左/右| 3 |
 | 我 = 5 | 无法适应 | 3 |

 这表明较大的瓷砖在包装中占主导地位，而较小的剩余容量一旦饱和就变得无关紧要。 

这些痕迹表明，每个图块都是独立分配的，并且 DP 无需排序假设即可累积最佳打包。

 ## 边缘情况

 当E = 0时，左侧部分完全消失。 在这种情况下，L = 0，所有图块只能移动到右侧。 DP 退化为超过 R 容量的标准 0-1 背包。 该实现会处理此问题，因为 dp 变为一维行，并且 l 上的循环仅在 l = 0 时迭代，因此不会发生无效转换。 

当 N − K − E = 0 时，右侧线段消失，出现对称情况。 只能向左放置，并且 DP 正确地将所有图块限制在左侧尺寸。 

当K=N时，除了单个放置的牌外，没有剩余的牌，并且L和R都为零。 DP 保持单个单元 dp[0][0] = 0，正确产生零附加覆盖范围。
