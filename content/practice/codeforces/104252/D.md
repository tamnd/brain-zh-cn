 ## 解决方案
 ## 问题理解

 贝拉每天往返于两个固定地点：家庭和工作场所。 她每天正好坐两趟公交车，一趟从家到工作地点，另一趟从工作地点返回家。 在每个地点，她可能会存放一定数量的雨伞。 

每次出行前，她都会检查该次特定骑行的天气。 天气要么下雨，要么不下雨。 她的决定并不纯粹基于天气：她遵循一条规则，有时即使不下雨，她也必须带伞。 

决策过程由两个想法驱动。 如果旅途中下雨，她总是带伞。 如果不下雨，如果目的地目前没有存放雨伞，她只携带一把，因此她避免让一个地方完全空着。 每当她携带雨伞时，雨伞就会从她当前的位置移动到目的地。 如果她不带雨伞，雨伞的分配不会改变。 

任务是模拟所有 2N 次旅行，从 Bella 在家开始，给定在家和工作时的初始雨伞数量，并输出每次旅行她是否带伞。 

约束很小：N 最多为 10^4，每个模拟步骤为 O(1)，因此超过 2N 个步骤的线性模拟很容易满足限制。 这也意味着任何涉及重新计算或跨行程扫描的解决方案都是不必要的。 

如果人们认为只在下雨时才带伞，就会出现一种微妙的失败情况。 例如，如果天气干燥但目的地有零把雨伞，贝拉仍然会移动一把，这会改变未来的决定。 另一个边缘情况是，当两个位置的一侧都以零伞开始时：第一次干行程即使没有下雨也会强制转移，从而防止以后的无效状态。 忽略“目的地为空”规则的幼稚方法将很快偏离正确的状态。 

## 方法

 幼稚的观点是独立对待每次旅行：查看天气，仅根据下雨情况决定是否带伞。 这适用于“下雨就带伞”的规则，但当涉及到无雨的旅行时，它会立即失效，因为该系统取决于家庭和工作之间不断变化的雨伞分布。 每个决策都会修改未来的状态，因此独立性假设失败。 

一个强力但正确的解释将准确地模拟该声明所描述的内容：维护两个地点的雨伞数量，并在每次旅行后更新它们。 每次出行都要检查是否下雨，或者目的地是否有零把雨伞。 如果任一条件成立，则将一把雨伞从当前位置移动到目的地，并标记贝拉携带雨伞。 这本质上是顺序的，因为每一步都会改变下一个状态。 

没有更快的渐近改进可用，因为每次行程都取决于先前行程产生的确切状态。 然而，结构足够简单，暴力模拟已经是最佳的。 关键的观察结果是，所有必需的信息都包含在两个确定性演化的整数中，因此不需要额外的数据结构或预处理。

 ## 算法演练

 我们逐步模拟系统，同时跟踪两个值：家里的雨伞和工作的雨伞。 我们还追踪贝拉的当前位置。

1.在家初始化Bella。 设 home = H，work = W。当前位置是家。 
2. 每天处理第一次从家到工作地点的行程，然后处理第二次从工作地点到家的行程。 
3. 对于每次行程，根据当前位置确定目的地。 如果贝拉在家，目的地就是工作；如果贝拉在家，目的地就是工作； 否则，目的地就是家。 
4. 查看本次旅行的天气情况。 如果下雨，贝拉必须带伞。 如果不下雨，只有当目的地当前有零把雨伞时，她才会带一把。 

这条规则确保她永远不会到达一个没有至少一把雨伞的地方，以备将来可能需要的情况使用。 
5. 如果贝拉决定带雨伞，则减少她当前位置的计数并增加目的地的计数。 该模型在旅途中实际携带雨伞。 
6. 如果她带了雨伞，则输出“Y”，否则输出“N”。 
7. 每次旅行后翻转贝拉的当前位置，因为她总是在家庭和工作之间移动。 

### 为什么它有效

 系统的状态由三个变量完整描述：家里的雨伞、工作的雨伞和贝拉的当前位置。 每次转换仅取决于当前状态和下一个天气条件。 由于每个动作都与问题规则一致地更新状态，因此模拟保留了计数始终反映每次旅行后雨伞的真实分布的不变量。 由于未来的决策不依赖于除此状态之外的任何事物，因此按顺序逐步执行时间可以保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, h, w = map(int, input().split())
    
    home = h
    work = w
    at_home = True  # True = home, False = work
    
    out = []
    
    for _ in range(n):
        s = input().strip()
        
        for i in range(2):
            rain = s[i]
            
            if at_home:
                cur = home
                dest = work
            else:
                cur = work
                dest = home
            
            take = False
            if rain == 'Y' or dest == 0:
                take = True
            
            if take:
                if at_home:
                    home -= 1
                    work += 1
                else:
                    work -= 1
                    home += 1
                out.append('Y')
            else:
                out.append('N')
            
            at_home = not at_home
    
    # print grouped by day
    for i in range(0, len(out), 2):
        print(out[i] + out[i+1])

if __name__ == "__main__":
    solve()
```实现直接遵循模拟。 布尔值`at_home`跟踪贝拉的位置，确保我们始终知道当前行程的方向。 关键决策线是条件`rain == 'Y' or dest == 0`，它对问题的两条规则进行编码。 更新步骤在位置之间精确移动一把伞，从而保留总数。 

输出被收集在一个平面列表中，然后每天成对打印以匹配所需的格式。 

一个常见的错误是忘记在每次行程后翻转位置，或者错误地仅更新目的地而不减少源。 两者都会违反保护伞守恒定律并导致后来状态不一致。

 ## 边缘情况

 一种极端情况是一个地点从零把雨伞开始。 在这种情况下，即使没有下雨，第一次离开其他地点几乎总是会触发强制转移。 模拟自然地处理这个问题，因为条件`dest == 0`变为真，因此算法立即移动雨伞，确保状态变得平衡。 

另一种情况是下雨和无雨交替，导致雨伞在不同地点之间摆动。 逐步模拟可确保正确性，因为每次行程都会在做出下一个决定之前更新确切的位置计数。 

最后一种情况是雨伞在一侧堆积过多。 即便如此，该规则仅取决于目的地是否为零或正在下雨，因此大量计数不会改变复杂性或正确性。 无论大小如何，该算法都继续应用相同的恒定时间转换规则。
