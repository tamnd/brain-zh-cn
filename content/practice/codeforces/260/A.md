 ## 解决方案
 ## 问题理解

 我们从一个数字开始`a`。 我们想精确地扩展它`n`次。 

单个分机意味着在当前号码的右侧附加一位十进制数字。 该数字可以是以下任意数字`0`到`9`，但是附加它之后，结果数字必须能被整除`b`。 

准确执行此操作后`n`次，我们必须输出最终的数字。 如果在任何步骤中都没有可以附加的数字，同时保持整除性`b`，然后过程停止，答案是`-1`。 

约束条件很小，对于`a`和`b`， 但`n`可以大到`100000`。 这立即告诉我们，任何对整个不断增长的数字执行昂贵算术的算法都是危险的，因为数字本身最终可能包含超过 100000 位数字。 我们需要一种方法，其每个附加​​数字的工作量是恒定的或几乎恒定的。 

一个微妙的点是，整除条件必须在每次扩展之后都成立，而不仅仅是在最后。 例如：```
a = 1, b = 11, n = 2
```如果我们任意附加数字并且只检查最终数字，我们可能会创建无效的中间状态。 操作本身需要每一步的可分性。 

另一个容易犯的错误是假设如果一次扩展是可能的，那么未来所有的扩展都是可能的。 考虑：```
a = 1, b = 2, n = 1
```追加`0`给出`10`，有效。 

但对于```
a = 1, b = 11, n = 1
```没有数字`d`这样`1d`可以整除`11`，所以正确答案是：```
-1
```粗心的实施无论如何都会继续下去，这是错误的。 

关于后续步骤还有一个重要的观察结果。 一旦我们找到一个可以被整除的数字`b`，附加一个`0`仅当以下情况时才保持整除性`10`兼容于`b`。 一般来说，附加`0`不保持可分性。 例如：```
12 % 3 = 0
120 % 3 = 0
```但```
14 % 7 = 0
140 % 7 = 0
```仅因特定除数而起作用。 我们必须仔细推理第一次成功延期后会发生什么。 

## 方法

 最直接的方法是完全按照描述模拟该过程。 在每一步中，尝试所有十个可能的数字。 对于每个数字，构造新数字并检查它是否可以被整除`b`。 如果某个数字有效，请将其附加并继续。 

该逻辑是正确的，因为它确实遵循操作的定义。 问题是这个数字很快就会变得巨大。 后`100000`扩展名，它可能包含超过`100000`数字。 重复构建和划分这些数字的成本太高了。 

关键的观察是整除性仅取决于余数模`b`。 

假设当前号码是`x`。 追加数字`d`创造```
x' = 10x + d
```我们需要```
(10x + d) % b = 0
```当前值`x`本身并不重要。 仅有的`x % b`很重要。 

一开始，我们知道剩下的`a`模数`b`。 我们尝试数字`0`通过`9`并寻找一个使```
(10 * remainder + d) % b == 0
```如果存在这样的数字，则新形成的数字可以被`b`。 

现在是关键的简化。 第一次成功扩展后，当前号码可以被`b`，所以它的余数变为`0`。 

从那时起，未来的每一步都从余数开始`0`。 我们只需要一个数字`d`满意的```
d % b = 0
```自从`0`总是这样的数字，附加`0`一旦我们已经有了一个可整除的数字，它就永远有效。 

因此，整个问题简化为找到一个数字，使第一个扩展可以整除`b`。 如果不存在这样的数字，则答案是`-1`。 否则，将该数字附加一次，然后附加`n - 1`零。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 对越来越大的整数进行 O(10n) 算术 | O(n) | 太慢了 |
 | 最佳 | O(10 + n) | O(10 + n) | 输出字符串 | O(n) 已接受 |

 ## 算法演练

 1. 计算`r = a % b`。 
2. 尝试每个数字`d`从`0`到`9`。 
3. 检查是否`(r * 10 + d) % b == 0`。 
4. 如果没有数字满足条件，则输出`-1`。 
5. 否则，设第一个有效数字为`d`。 
6. 将答案形成为十进制表示形式`a`，后面跟数字`d`。 
7. 准确附加`n - 1`零。 
8. 输出结果字符串。 

第 7 步起作用的原因是，在附加第一个有效数字后，当前数字可以被整除`b`。 其余数为模`b`现在为零。 附加零会产生```
10 * current
```其余数仍然为零，因为```
(10 * 0) % b = 0
```当使用当前余数表示时。 

### 为什么它有效

 让`r = a % b`。 

第一个附加数字必须满足```
(10r + d) % b = 0
```因为附加`d`将数字转换为`10a + d`，和模余数`b`由该表达式保留。 

如果没有数字`0`到`9`满足方程，第一个操作是不可能的，所以答案一定是`-1`。 

如果一个数字`d`满足它，则新数可被整除`b`。 它的余数变为零。 后来的每个扩展都会附加数字`0`。 从余数零开始，下一个余数是```
(10 * 0 + 0) % b = 0.
```其余部分永远不会再改变。 每个中间数都可以被整除`b`，因此所有必需的操作都是有效的。 构造的数字正是之后的结果`n`扩展。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, n = map(int, input().split())

    r = a % b

    for d in range(10):
        if (r * 10 + d) % b == 0:
            ans = str(a) + str(d) + "0" * (n - 1)
            print(ans)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```第一部分计算余数`a`模数`b`。 这是确定是否可以成功附加数字所需的唯一信息。 

数字循环`0`通过`9`搜索有效的第一个扩展。 只有十种可能性，所以这个搜索是常数时间。 

一旦找到有效数字，答案就会被构建为字符串。 使用字符串很重要，因为最终数字可能包含超过 100000 位数字。 将其存储为整数是不必要的且效率低下。 

表达式`"0" * (n - 1)`准确附加剩余的扩展名。 什么时候`n = 1`，这变成一个空字符串，它只正确地生成一个附加数字。 

如果循环结束时没有找到有效数字，则无法执行第一个操作，正确答案是`-1`。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline

 ## 边缘情况

 ### No valid first digit

 输入：```
1 11 1
```余数为：```
1 % 11 = 1
```该算法检查所有数字：```
(10 + d) % 11
```为了`d = 0..9`。 

没有一个产生零。 由于第一个操作无法执行，算法立即输出：```
-1
```与流程的定义相匹配。 

### 只需要一个扩展名

 输入：```
12 3 1
```余数为零。 

数字`0`立即满足：```
(0 * 10 + 0) % 3 = 0
```答案变成：```
120
```没有附加额外的零，因为`n - 1 = 0`。 

### 非常大的n

 输入：```
1 1 100000
```第一个有效数字是`0`。 

该算法构造：```
10 + 99999 zeros
```无需对巨大的数字执行任何昂贵的算术。 运行时间随着输出大小线性增长，这是最优的，因为输出本身包含 100001 个数字。 

### 有效的第一个数字不为零

 输入：```
5 7 2
```余数为：```
5
```该算法测试数字直到：```
(5 * 10 + 6) % 7 = 56 % 7 = 0
```它选择数字`6`，生产`56`。 附加一个额外的零，给出：```
560
```每个中间数都满足整除性要求，因此构造有效。
