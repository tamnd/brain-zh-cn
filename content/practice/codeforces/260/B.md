 **标签：** 暴力破解、实现、字符串
 **求解时间：** 2m 10s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 输入是一个仅由数字和字符组成的长字符串`-`。 该字符串内的某个位置可能有许多看起来像日期的子字符串，完全写为`dd-mm-yyyy`。 

我们的任务是找到最常作为此类子字符串出现的有效日期。 有效日期必须满足三个条件：

 首先，格式必须恰好是两位数的日、两位数的月和四位数的年，并用连字符分隔。 

其次，年份必须是其中之一`2013`,`2014`， 或者`2015`。 

第三，该日期必须在给定月份内有效。 由于这些年份都不是闰年，因此 2 月有 28 天。 

答案保证存在并且是唯一的。 

字符串长度最多为`10^5`。 表示日期的子字符串始终具有长度`10`，所以最多有大约`10^5`待审查的候选人职位。 这立即表明扫描所有可能的长度为 10 的子串是可行的。 任何试图将每个候选者与其他候选者进行比较的解决方案都会倾向于二次行为并且变得太慢。 

微妙的部分是，子字符串在语法上可能看起来像日期，但实际上是无效的。 例如：```
31-02-2013
```这符合模式`dd-mm-yyyy`，但二月从来没有31天，所以一定不能算在内。 

另一个容易犯的错误是接受不完全使用两位数字表示日和月的日期。 考虑：```
1-01-2013
```这不是有效的事件，因为所需的格式正好是十个字符长。 仅有的：```
01-01-2013
```很重要。 

第三个陷阱是特定于月份的日期限制。 例如：```
31-04-2014
```四月只有30天。 仅检查的解决方案`1 <= day <= 31`会错误地计算它。 

最后，允许重叠出现。 在字符串中```
0012-10-2012-10-2012
```不同的起始位置可以产生有效的日期子字符串。 我们必须独立检查每个长度为 10 的窗口。 

## 方法

 一种蛮力的想法是生成 2013 年至 2015 年之间的每个有效日期，并在整个预言中搜索每个日期。 

该范围内只有大约一千个有效日期，因此正确性很简单。 对于每个日期，计算其字符串表示在预言中出现的次数并保留最大值。 

问题是运行时间。 预言可以包含`10^5`人物。 独立搜索大约 1000 个日期会导致大约`10^8`最坏情况下的字符操作，这是不必要的昂贵。 

问题的结构表明要扭转这个过程。 

我们可以问“每个长度为 10 的子字符串代表什么日期？”，而不是问“每个有效日期出现了多少次？”

 每个有效的出现必须恰好占据十个字符：```
dd-mm-yyyy
```只有`n - 9`这样的窗口在整个字符串中。 对于每个窗口，我们可以检查它是否形成有效的日期。 如果是这样，我们会增加该日期的频率。 

这将问题转化为预言的单一线性扫描。 每个位置都被处理一次，有效性检查需要恒定的时间，并且哈希图存储频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(1000·n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(k) | 已接受 |

 这里`k`是遇到的不同有效日期的数量，最多是 2013 年到 2015 年之间的有效日期数量。 

## 算法演练

 1. 阅读预言串。 
2. 准备一个包含每个月天数的数组：```
[31,28,31,30,31,30,31,31,30,31,30,31]
```由于 2013 年至 2015 年不是闰年，因此 2 月始终有 28 天。 
3. 迭代每个起始位置`i`这样就存在长度为 10 的子串。 
4.提取子串`s[i:i+10]`。 
5. 检查位置2和5是否包含连字符。 

如果不匹配，则子字符串无法匹配所需的格式。 
6.解析：

 - 人物的一天`[0:2]`- 人物月份`[3:5]`- 人物年份`[6:10]`如果解析失败，则丢弃该子字符串。 
7. 验证日期：

 - 年份介于 2013 年至 2015 年之间
 - 月份介于 1 和 12 之间
 - 天至少为 1
 - 天数不超过该月的天数
 8. 如果日期有效，则使用原始子字符串作为键来增加其在哈希映射中的计数。 
9. 跟踪迄今为止出现频率最高的日期。 
10. 处理完所有窗口后，输出计数最大的日期。 

### 为什么它有效

 预言中的每个有效出现恰好占据十个连续字符，并且必须由某个长度为 10 的窗口表示。 该算法对每个这样的窗口只检查一次。 

仅当子字符串通过所有有效性检查时，它才会对频率图做出贡献，因此每个计数的出现都对应于正确的日期。 相反，每个正确的日期出现都会显示为检查的窗口之一，并将被计数。 

因此，频率图存储每个有效日期的准确出现次数。 由于启示日期被定义为具有最大频率的唯一有效日期，因此选择具有最大计数的键会产生正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    days_in_month = [31, 28, 31, 30, 31, 30,
                     31, 31, 30, 31, 30, 31]

    freq = {}
    best_date = ""
    best_count = 0

    for i in range(len(s) - 9):
        cur = s[i:i + 10]

        if cur[2] != '-' or cur[5] != '-':
            continue

        try:
            day = int(cur[0:2])
            month = int(cur[3:5])
            year = int(cur[6:10])
        except ValueError:
            continue

        if not (2013 <= year <= 2015):
            continue

        if not (1 <= month <= 12):
            continue

        if not (1 <= day <= days_in_month[month - 1]):
            continue

        freq[cur] = freq.get(cur, 0) + 1

        if freq[cur] > best_count:
            best_count = freq[cur]
            best_date = cur

    print(best_date)

if __name__ == "__main__":
    solve()
```扫描会检查每个可能的长度为 10 的窗口，因为任何有效的日期出现都必须恰好占用 10 个字符。 

连字符检查在解析整数之前执行。 这可以快速拒绝大多数无效窗口并避免不必要的转换。 

月份有效性检查在索引之前进行`days_in_month[month - 1]`。 当月份超出范围时，反转此顺序可能会导致访问无效索引的风险`1..12`。 

原始子字符串用作字典键。 由于日期始终存储在规范中`dd-mm-yyyy`格式，相同的日期总是产生相同的密钥。 

运行最大值在扫描期间更新，避免第二次遍历频率图。

 ## 边缘情况

 考虑：```
31-02-2013
```子串有正确的`dd-mm-yyyy`结构。 该算法解析日`31`， 月`2`，和年份`2013`。 该月有效，但二月只允许`28`天。 条件```
day <= days_in_month[month - 1]
```失败，因此子字符串被丢弃并且永远不会被计算在内。 

考虑：```
31-04-2014
```四月有`30`天。 该算法计算`days_in_month[3] = 30`，检测到`31 > 30`，并拒绝该日期。 这可以防止计算语法正确但不可能的日历日期。 

考虑：```
1-01-2013
```该字符串只有九个字符长。 由于该算法仅检查长度为 10 的窗口，因此它永远不会将此视为候选日期。 所需的格式要求日期和月份都恰好是两位数字。 

考虑：```
13-12-2013-12-2013
```子串`13-12-2013`出现在开头，由于重叠，另一次出现稍后开始。 由于算法独立检查每个起始位置，因此两次出现都会正确计数。 重叠匹配不需要特殊处理。
