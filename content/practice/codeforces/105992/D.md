 ## 解决方案
 ## 问题理解

 给定两个非负整数`a`和`b`，和一个目标对`x`和`y`。 两个玩家交替轮流，第一个玩家 (gsh) 尝试将当前状态准确地转换为`(x, y)`在有限的移动次数内，而对手（AI）试图阻止这种情况发生。 

轮到 gsh 时，他可以使用任意掩码使用按位运算来准确修改两个数字之一`v`。 他可以替换`a`和`a & v`或更换`b`和`b | v`。 轮到人工智能时，角色在精神上是镜像的，但在效果上却相反：人工智能可以设置`a := a | v`或者`b := b & v`。 

关键细节是`v`在范围内完全自由`0 ≤ v < 2^60`，因此在一次移动中，玩家可以独立决定他们想要强制执行的最终位模式，只要它可以通过带有某个掩码的单个 AND 或 OR 操作来实现。 

游戏原则上是无限的，但如果在移动后的任何时刻状态变得完全一致，则 gsh 立即获胜`(x, y)`。 否则人工智能获胜。 

约束允许最多`T = 10^5`独立游戏，价值高达`2^60`。 这立即表明任何解决方案都必须是每个测试用例的恒定时间，因为即使每个测试用例的对数因子也将处于典型限制的边缘。 

幼稚的解释可能会建议模拟游戏或推理位操作序列。 然而，这是不可能的，因为分支因子很大并且状态数量实际上是`2^120`。 即使是位掩码上的受限 BFS 也是完全不可行的。 

当初始状态已经等于目标时，会出现微妙的边缘情况。 那样的话，gsh无需任何动作就立即获胜。 当只有其中一个时，就会发生另一种不平凡的情况`a`或者`b`匹配其目标，另一个可以独立调整，因为 OR 和 AND 运算可以积极地覆盖位。 在单个操作可以直接跳转到目标配置的情况下，任何仅推理“增加”或“减少”值而没有位级结构的解决方案都将失败。 

## 方法

 蛮力模型将对待每个状态`(a, b)`作为一个节点，每个玩家的每个操作作为转换。 从任何节点，gsh 都可以通过选择掩码移动到任何可达的状态`v`，人工智能可以以互补的方式做同样的事情。 这将创建一个巨大的交替图，其中边对应于按位变换。 

虽然这个模型是正确的，但它不可用。 即使忽略无限视界，不同状态的数量也是`2^60 × 2^60`，并且由于任意的原因，每个状态都有有效的指数输出选择`v`。 任何基于搜索的方法都会立即失败。 

关键的观察是，游戏实际上并不是关于移动序列，而是关于比特的可控性。 每个操作都允许一个玩家在一个方向上对单个变量强制执行单调行为：AND 只能清除位，OR 只能设置位。 对手在另一个变量上总是有相反的极性。 

这种对称性意味着游戏简化为检查在比特强制的对抗性交替下是否可以达到目标配置。 我们不跟踪转弯，而是提出一个更简单的问题：对于独立的每个位位置， gsh 能否确保`(a, b)`可以开车去`(x, y)`人工智能无法永久阻止它吗？ 

一个关键的简化是，每次移动都可以完全覆盖一个变量中选定的位模式。 例如，`a := a & v`让 gsh 独立决定哪些位`a`必须变为零。 同样，人工智能可以强制`a`使用 OR 将结果变为 1。 因此，每个位的行为就像一个两人控制系统，其中一个玩家试图将其固定为所需的值，而另一个玩家可以尝试反对它，但只能沿相反的单调方向。 

由此，游戏崩溃为检查是否存在所需目标与不可避免的对抗性强制约束相冲突的任何位。 这将问题简化为直接按位可行性检查而不是游戏模拟。

 ## 算法演练

 我们独立处理每个测试用例并一点一点地推理。 

1. 对于0到59的每个位位置，提取对应的位`a`,`b`,`x`， 和`y`。 这将游戏隔离为每位独立的二进制决策，因为“与”和“或”不会跨位置混合位。 
2. 对于固定位，观察每个玩家可以强制执行的内容。 gsh 可以使用 AND on`a`强制一位为 0，或`b`强制一位为 1。AI 可以做相反的事情：OR on`a`可以强制一位为 1，并且 AND 开启`b`可以将位强制为 0。这意味着每个变量都具有双向强制压力，具体取决于对其应用的操作。 
3. 考虑一下目标需要的地方`x_bit = 1`但最初的`a_bit = 0`。 创造1的唯一方法`a`是通过AI的OR运算，而不是gsh的AND。 然而，gsh 永远不能直接设置 1`a`，所以达到这个位取决于能否阻止AI永久维持阻塞配置。 这就产生了一个限制：gsh 只能依赖可以到达的位，而不需要在对抗性控制下直接“设置为 1”操作。 
4. 同样，如果`y_bit = 0`但`b_bit = 1`，gsh必须能够强制清除`b`，但人工智能可以通过使用 AND 来抵消`b`仅当它处于最佳状态时。 这引入了对称约束。 
5. 关键的减少是，一个位是可行的，除非它位于两个参与者可以无限期地维持该位上的矛盾的配置中。 具体来说，只有当 gsh 被迫依赖位翻转时，可行性才会失败，而对手可以通过选择相反的单调操作来永久阻止这种翻转。 
6. 检查所有位后，如果没有发现不可能的位配置，gsh 可以强制收敛到`(x, y)`，否则答案是`No`。 

### 为什么它有效

 每个位在单调运算下独立演化：OR 只能向 1 移动一点，AND 只能向 0 移动一点。由于双方都可以应用两个方向，但变量不同，所以唯一真正的障碍来自于实现目标需要向对手可以永久主导的方向稍微逆转的情况。 这将游戏简化为检查在对抗性控制下是否有任何位需要禁止方向。 如果不存在此类冲突，则重复应用正确的操作最终会将所有位与目标对齐。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        a, b, x, y = map(int, input().split())

        # Key observation: each bit can be analyzed independently.
        # We check whether any bit creates an irreversible conflict.

        ok = True

        for i in range(60):
            abit = (a >> i) & 1
            bbit = (b >> i) & 1
            xbit = (x >> i) & 1
            ybit = (y >> i) & 1

            # For a bit in a:
            # If we need xbit = 1 but start from abit = 0,
            # it requires OR pressure; similarly, AI can enforce 1s on a.
            # The conflict arises only when both directions are adversarially locked.
            if xbit == 1 and abit == 0:
                # cannot be reliably created under opposing OR pressure structure
                ok = False

            # For a bit in b:
            # If we need ybit = 0 but start from bbit = 1,
            # it requires AND pressure; AI can resist via AND/OR symmetry.
            if ybit == 0 and bbit == 1:
                ok = False

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```该解决方案对位进行循环，因为操作是按位且每个位置独立的。 对于每个测试用例，它都会检查任何所需的转换是否会迫使比特朝着在对抗性交替下无法保证的方向移动。 循环内的条件对 OR 和 AND 对称性隐含的不可逆约束进行编码。 

提前退出标志`ok`确保每个测试用例持续工作。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        a, b, x, y = map(int, input().split())

        ok = True
        for i in range(60):
            abit = (a >> i) & 1
            bbit = (b >> i) & 1
            xbit = (x >> i) & 1
            ybit = (y >> i) & 1

            if xbit == 1 and abit == 0:
                ok = False
            if ybit == 0 and bbit == 1:
                ok = False

        out.append("Yes" if ok else "No")

    return "\n".join(out)

 ## 边缘情况

 一种边缘情况是初始状态已经与目标匹配。 在这种情况下，每个位检查都会立即通过，因为没有触发不匹配条件。 算法返回`Yes`无需推理未来的行动。 

另一种情况是仅当`a`有所不同，但所有必需的更改都是位清除的。 例如，`a = 1111`,`x = 0000`。 每个不同的位都满足安全转换，因为 AND 总是可以清除位，因此在迭代期间不会出现禁止条件。 

一个对比的情况是当解决方案需要设置一点时`a`最初为 0。例如，`a = 0`,`x = 1`。 检查立即标记这一点，算法输出`No`，反映出在对抗性 OR 控制对称性下不能保证这种创建。 

最后，两个变量都需要混合切换的情况是每个比特独立处理的，确保不会错误地假设跨比特干扰。
