 ## 解决方案
 ## 问题理解

 我们得到一个整数`x`，代表适用于固定基本成本的百分比税或附加费。 基本成本始终为 50 单位。 最终支付的金额是基本成本加上该基本成本的额外百分比。 

具体来说，附加费的计算方式为`50 × x / 100`，总付款为`50 + 50 × x / 100`。 输出格式要求将此最终值打印为四舍五入到小数点后三位数字的十进制数，并以字符串为前缀`Vivo`。 

就算法复杂性而言，输入大小是微不足道的，因为只有一个整数和常数时间算术计算。 虽然`x`可以大到 19,198,100，在浮点或缩放整数算术中计算仍然安全。 唯一的微妙之处在于正确的舍入和格式。 

主要的边缘情况来自格式化而不是计算。 什么时候`x = 0`，结果应该准确地保持不变`50.000`。 什么时候`x`很大，结果可以达到近百万，但仍然适合标准双精度。 另一个边缘情况是适当的舍入：像这样的值`x = 1`生产`50.5`，必须打印为`50.500`， 不是`50.5`或者`50.5000`。 

如果使用整数除法，粗心的实现也可能会丢失精度，例如计算`50 * x // 100`，这将完全丢弃小数贡献并打破舍入。 

## 方法

 强力解释将尝试使用整数算术一步步直接模拟百分比计算。 人们可能会尝试将额外费用计算为`(50 * x) / 100`使用整数除法。 这已经接近最佳，但如果地板除法不正确，它会默默地截断而不是保留小数。 另一个天真的想法是将所有内容都转换为浮点数而不考虑精度控制，然后打印原始结果，这可能会根据格式默认值而导致舍入行为不一致。 

关键的观察结果是该公式是单个线性表达式。 没有迭代，没有条件结构，多个输入之间没有依赖关系。 这减少了评估常数时间算术表达式并正确格式化输出的问题。 由于 Python 中的浮点算术足以满足这种规模，因此唯一真正的要求是确保格式化步骤强制四舍五入到小数点后三位。

 ## 算法演练

 我们直接根据问题的定义计算结果并仔细控制格式。 

1.读取整数`x`来自输入。 这是适用于 50 基本成本的百分比。 
2. 计算百分比的乘数效应为`x / 100.0`。 此处使用浮点除法至关重要，因为整数除法会丢弃小数部分。 
3. 将基本成本 50 乘以该乘数即可获得附加费用。 这代表了应用于基础的精确比例附加费。 
4. 将基本成本 50 添加到计算出的附加费用中以获得最终金额。 
5. 使用定点格式对结果进行格式化，精确到小数点后三位。 此步骤强制执行输出规范所需的舍入规则。 
6. 打印前缀为的结果`Vivo `。 

### 为什么它有效

 该计算是线性函数的直接评估`x`。 由于每个变换都保留与原始公式的等价性`50 × (1 + x / 100)`，算法不能偏离预期值。 唯一潜在的差异来源是数字表示，并且使用标准浮点算术与受控格式相结合可确保最终打印值与所需的舍入语义相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x = int(input().strip())

base = 50.0
total = base + base * (x / 100.0)

print(f"Vivo {total:.3f}")
```该解决方案读取单个整数并立即在恒定时间内计算公式。 基值显式写为浮点数，以确保整个表达式保留在浮点空间中，避免意外的整数截断。 

格式化字符串`:.3f`至关重要，因为它强制舍入和固定宽度小数输出。 如果没有它，Python 可能会打印可变数量的小数位数，这将无法满足输出要求。

 ## 边缘情况

 一种边缘情况是当`x = 0`。 计算变为`50 + 0`，并且输出仍必须包含三位小数。 该算法产生`50.0`，并且格式化将其正确转换为`50.000`。 

另一个边缘情况是小比例，例如`x = 1`，其中结果是`50.5`。 如果没有明确的格式，这可能会打印为`50.5`，这将违反所需的固定精度。 该算法确保`50.500`被打印。 

像这样一个大值`x = 19198100`产生一个大的中间结果`50 × (1 + 191981.0) = 9,599,050.0`。 这仍然安全地适合浮点范围，并且格式保持稳定。
