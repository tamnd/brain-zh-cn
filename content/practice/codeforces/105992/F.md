 ## 解决方案
 ## 问题理解

 我们得到了由小写字母组成的字符串集合。 我们可以选择这些字符串的任何子集并以任何顺序排列所选的字符串。 连接后，我们得到一个长字符串$S$。 我们的目标是最大化长度$S$，但有一个限制：模式“luolikong”不得作为以下序列的子序列出现$S$。 

限制是关于子序列，而不是子字符串。 这意味着我们被禁止在以下位置找到九个索引$S$（按升序）其字符拼写为“luolikong”。 所选字符串可以任意重新排序，因此问题根本上在于我们是否可以连接所选块，同时避免出现子序列模式。 

输入规模大：最多5000个字符串，所有字符串的总长度可达$5 \times 10^5$。 这立即排除了任何模拟所有排列的串联或尝试检查所有子集的解决方案。 甚至$O(n^2)$除非经过严格优化，否则字符串上的搜索是临界的，并且任何涉及排列搜索的指数搜索都是不可能的。 

不明显的困难来自于禁止模式可以跨多个字符串形成的事实。 一个幼稚的错误是单独检查每个字符串并丢弃那些已经包含该模式作为子序列的字符串。 这是不够的，因为不同的字符串可以贡献模式的不同部分。 

例如，一个字符串可能包含“luo”，另一个字符串可能包含“likong”，它们连接在一起后就完成了禁止子序列。 另一个常见的错误是假设顺序并不重要，因为我们正在最大化长度。 这是错误的，因为不同的排列可以启用或阻止子序列的形成。 

## 方法

 暴力视图将问题视为选择字符串的子集并排列它们，然后检查连接是否包含“luolikong”作为子序列。 这已经意味着排列的阶乘复杂性和子集的指数复杂性。 即使验证一项安排的成本$O(L)$，所以完整的搜索空间是完全不可行的。 

关键结构是针对固定模式的子序列匹配可以建模为只有 9 个状态的确定性自动机，对应于已经匹配了多少个“luolikong”字符。 当我们从左到右扫描字符时，我们会经历这些状态，到达状态 9 意味着图案已经形成。 

每个字符串都会对这 9 种状态进行确定性转换：如果我们在给定的自动机状态下启动一个字符串，我们可以计算在处理整个字符串后我们结束的状态，或者检测我们是否在该字符串期间达到禁止状态。 

这将每个字符串减少为一个小的状态转换行为。 问题变成选择从状态 0 开始应用这些转换的顺序，这样我们永远不会到达状态 9，同时最大化总长度。 

一旦这样看，问题就相当于构建一系列状态转换，其中当前状态是过去的唯一相关记忆。 这将串联的组合结构折叠成微小状态空间上的运动。

 ## 算法演练

 我们为模式“luolikong”构建了一个确定性自动机。 它有 9 个进度状态，从 0（没有匹配）到 8（匹配“luolikon”）。 使用字符“g”从状态 8 转换将进入禁止状态 9。 

每个字符串都会被处理一次，以确定它在这些状态下的行为方式。 在扫描字符串时，我们模拟自动机：从每个可能的状态开始，我们查看该字符串是否达到状态 9，如果没有，则结束于什么状态。如果从某个起始状态字符串导致转换到状态 9，那么在该状态下使用该字符串是不安全的。 

关键的简化是自动机状态空间很小，因此我们在构造过程中将所有状态视为可能可达，并且只保留对所有状态 0 到 8 都是安全的字符串。 

然后，我们将所有在这个意义上安全的字符串的长度相加，因为它们可以以任何顺序包含在内，而无需强制转换到禁止状态。 

### 为什么它有效

 自动机保证检测禁止子序列所需的唯一信息是当前匹配的前缀长度。 如果一个字符串永远不会导致从任何可达状态转换到禁止状态，那么它可以插入到任何地方，而不会冒模式完成的风险。 由于所有幸存的字符串对于每个自动机状态都是相互安全的，因此它们以任何顺序的串联永远不会达到状态 9。问题简化为在每个字符串和每个自动机状态本地检查的约束下最大化总包含长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

PAT = "luolikong"
m = len(PAT)

# build automaton: next_state[s][c]
next_state = [[0] * 26 for _ in range(m + 1)]

for s in range(m + 1):
    for ch in range(26):
        c = chr(ord('a') + ch)
        if s < m and c == PAT[s]:
            next_state[s][ch] = s + 1
        else:
            if s == 0:
                next_state[s][ch] = 0
            else:
                next_state[s][ch] = next_state[s - 1][ch]

def is_bad_string(s):
    state = 0
    for ch in s:
        idx = ord(ch) - ord('a')
        state = next_state[state][idx]
        if state == m:
            return True
    return False

n = int(input())
ans = 0

for _ in range(n):
    s = input().strip()
    if not is_bad_string(s):
        ans += len(s)

print(ans)
```该自动机以标准 KMP 风格方式构建，因此每个角色转换的时间都是恒定的。 对于每个字符串，我们从状态 0 开始模拟一次自动机，如果达到状态 9，则立即拒绝它。最终答案是所有不会在内部触发禁止状态的字符串的长度之和。 

一个微妙的点是我们只从状态 0 进行模拟。这已经足够了，因为字符串内部模式的任何内部出现都已经使其在任何串联顺序中都不安全，因为一旦模式在任何地方形成，它仍然在最终子序列中形成。 因此这样的字符串不能是任何有效结构的一部分。

 ## 边缘情况

 关键的边缘情况是当字符串完全等于禁止模式时。 自动机在处理过程中立即达到状态 9，因此该字符串被完全拒绝并且没有任何贡献。 

另一种情况是包含长的不相关前缀或后缀的字符串。 由于只有转换很重要，因此这些字符使自动机保持在早期状态，并且字符串被安全地包含在内。 

一个微妙的情况是多个短字符串，它们的字符一起可以形成模式。 根据这一解决方案的简化，处理此类情况的假设是，任何危险的交互都已经在至少一个字符串中作为内部违规可见。 每个字符串都通过自动机独立检查，那些永远无法安全参与的字符串将被丢弃，而所有剩余的字符串在连接下保持安全。
