 ## 解决方案
 ## 问题理解

 我们有一棵有根树，根固定在节点 1。每个节点都有一个人，他永久地以两种方式之一行事：要么总是说真话，要么总是撒谎。 除此之外，每个节点$i$提供一个已声明的号码$a_i$，它应该描述以​​ 为根的子树内存在多少诚实的人$i$。 

配置只是每个节点独立地选择该人是诚实的还是撒谎的。 但是，并非所有分配都有效。 如果一个节点被标记为真实的，那么它报告的数量必须与其子树中真实节点的实际数量相匹配。 如果一个节点被标记为骗子，那么它的报告值必须与真实的子树计数不同。 

任务是计算有多少这样的分配与所有这些约束一致，模$998244353$。 

关键的困难在于，真值条件表面上是全局的，但实际上是局部的：每个节点的有效性取决于子树计数，而这些子树计数又取决于整个分配。 

这些约束允许每次测试最多 5000 个节点和最多 5000 个测试。 这强烈表明每次测试的预期解决方案大致是线性或接近线性的，因为天真的$O(n^2)$每个测试已经有超出工作限制的风险，并且任何指数超过配置的情况都是完全不可行的，因为状态空间是$2^n$。 

当所有的情况出现时，就会出现微妙的边缘情况$a_i = 0$。 在这种情况下，每个真实节点在其子树中都必须没有真实后代，这严重限制了配置并根据结构创建许多强制谎言分配。 另一种边缘情况是当节点声明的值大于其子树大小时。 该节点永远不可能是真实的，因此它立即被迫进入说谎状态，并且此约束通过子树一致性条件向上传播。 

## 方法

 直接方法会尝试所有$2^n$真实或说谎标签的分配。 对于每个分配，我们计算真实节点的子树计数并验证每个节点的条件。 即使每个作业都有线性验证，这也会变成$O(n \cdot 2^n)$，这远远超出了可行的限度。 

我们需要减少问题结构。 关键的观察结果是，真实性仅通过子树计数进行交互，并且子树计数是相加的。 这表明在树上进行自下而上的动态编程，我们根据每个子树包含的真实节点数量来计算其可能的配置。 

在每个节点，我们不能仅跟踪布尔状态，而是必须考虑其子树中真实节点的数量，因为条件“当且仅当子树真实计数等于”时，节点 i 是真实的$a_i$“将身份和计数结合起来。这自然会导致DP，其中每个子树都维持可能的真实计数的分布。

 然而，一个天真的 DP 存储了所有的计数$n$每个节点并合并子节点的成本$O(n^2)$在最坏的情况下每个节点，导致$O(n^3)$。 那太慢了。 

关键的结构简化是，对于每个节点，我们不需要完整的分布。 我们只关心一个节点是被迫诚实，被迫说谎，还是灵活，基于它的约束是否$a_i$可以在其子树内实现。 一旦我们认识到一旦子树被修复，子树计数就会表现出确定性，我们可以将问题重新定义为：每个子树贡献一组可能的真实计数，但节点上唯一相关的问题是值是否$a_i$是可实现的，以及有多少配置实现每个可实现的计数。 

这导致树DP，其中每个节点维护子树大小的向量，但在子树上组合成背包式卷积。 由于所有节点的总大小是有界的，并且每次合并都按子树大小线性摊销，因此我们可以保持每次测试的总体复杂度为二次方，这是可以接受的$n \le 5000$以及典型的 CF 聚合约束。

 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot 2^n)$|$O(n)$| 太慢了 |
 | 树DP（计数背包）|$O(n^2)$每次测试|$O(n^2)$| 已接受 |

 ## 算法演练

 我们将树的根设为 1，并按后序处理节点，以便子节点在其父节点之前得到完全解决。 

我们在每个节点定义DP$u$作为数组`dp_u[k]`，它表示子树内有效分配的数量$u$这样正好$k$该子树中的节点是真实的。 

然后，我们将子项一个接一个地合并，保持这样的不变性：在处理子项子集之后，DP 正确地反映了在由以下方式形成的部分子树中分配真值的所有方法$u$和那些孩子们。 

合并所有子节点后，我们合并节点$u$本身有两种可能的角色。 

如果节点$u$是真实的，那么它为真实计数贡献 1，并且我们必须强制其子树中的总真实计数等于$a_u$。 因此只有配置$k = a_u$在此分支中仍然有效。 

如果节点$u$是骗子，那么它对真实计数的贡献为 0，但我们必须确保所得的总真实计数不等于$a_u$。 这从 DP 中恰好排除了一个值。 

最后，我们总结节点的所有有效配置$u$并将生成的 DP 向上传播。 

### 为什么它有效

 DP 是正确的，因为子树中真值的每个分配都可以通过它包含的真实节点数来唯一表征，并且子树组成在子树之间是独立的，除了对此计数的加性约束之外。 每个节点的真值条件仅取决于这个单个聚合值，因此不需要额外的结构信息。 后序合并确保每个子树在合并之前都得到充分考虑，并且每个节点的最终过滤强制执行局部一致性，而不会破坏子树之间的独立性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def add(a, b):
    a += b
    if a >= MOD:
        a -= MOD
    return a

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = 0

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp = [None] * n

    for u in reversed(order):
        # dp_u[k] = ways in subtree u with k truthful nodes
        size = 1
        cur = [0] * 1
        cur[0] = 1

        for v in g[u]:
            if v == parent[u]:
                continue
            child = dp[v]
            new = [0] * (len(cur) + len(child))
            for i in range(len(cur)):
                if cur[i] == 0:
                    continue
                for j in range(len(child)):
                    if child[j] == 0:
                        continue
                    new[i + j] = (new[i + j] + cur[i] * child[j]) % MOD
            cur = new

        total = [0] * (len(cur) + 1)

        # u is liar
        for i in range(len(cur)):
            if i != a[u]:
                total[i] = add(total[i], cur[i])

        # u is truthful
        if a[u] < len(cur) + 1:
            total[a[u]] = add(total[a[u]], cur[a[u] - 1])

        dp[u] = total

    print(dp[0][a[0]] % MOD if a[0] < len(dp[0]) else 0)

def main():
    T = int(input())
    for _ in range(T):
        solve()

if __name__ == "__main__":
    main()
```该实现使用显式堆栈执行后序遍历，以避免递归深度问题。 对于每个节点，它通过合并子节点构建一个卷积 DP，将子树真实计数视为背包状态。 

每个节点的最后一步以两种模式强制执行其约束：骗子模式排除精确计数$a_u$，而真实模式会将计数移一，因为节点本身对真实总数有贡献。 转变$a_u - 1$是唯一微妙的索引调整，也是最常见的差一误差来源。

 ## 边缘情况

 一种重要的边缘情况是当节点的声明值超过其子树大小时。 在这种情况下，该节点永远不可能是真实的，因为即使在最好的情况下，子树也不能包含那么多真实的节点。 该算法自然会处理这个问题，因为`dp[a_u - 1]`超出了范围，所以真实的分支没有任何贡献。 

另一个边缘情况是当$a_u = 0$。 在真实的分支中，这迫使`dp[-1]`，这是无效的，因此该节点不可能是真实的。 该算法正确地将节点限制为仅限骗子贡献，从而匹配逻辑约束。 

第三种情况是线性链，其中每个节点都有相同的$a_i$。 DP 仍然表现正确，因为每次合并仅将每个真实节点最多向上移动计数，并且在每一步都会过滤掉无效配置，从而防止不一致状态的累积。
