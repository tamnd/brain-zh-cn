 ## 解决方案
 ## 问题理解

 我们得到一个无向简单图，其中每条边都标记为白色或黑色。 当我们忽略颜色时，图形是连通的。 

通过一项操作，我们可以选择图中的任何简单循环，但限制是该循环必须至少包含一个白边。 选择这样的循环后，该循环上的每个边缘都会永久变黑。 我们可以随时停下来，我们不需要把所有的边都变成黑色。 

任务是确定我们最多可以执行多少个这样的操作。 

根据输入约束，所有测试用例的顶点总数最多为 2 × 10^5，边总数最多为 3 × 10^5。 这立即排除了任何尝试枚举循环或通过每个操作进行完整图形遍历来重复搜索循环的方法。 即使每个测试用例是二次的，也太慢了，甚至每个操作的 O(m log n) 也是不安全的，因为在最坏的情况下操作数量并不小。 

一个微妙的方面是，如果多个白边位于同一选定周期，则操作可以一次删除多个白边。 这创建了非局部交互：选择一个循环对于每个边缘来说并不独立，因为不同的白色边缘可以在单个循环内耦合。 

一种故障模式出现在所有三个边缘均为白色的三角形中。 图中只有一个简单的循环，因此最好的操作被迫一次获取所有三个边，只产生一个操作。 天真的“计算白边”方法会错误地返回三。 

当图已经是一棵树时，就会出现另一个极端情况。 根本没有循环，所以即使边缘是白色也无法进行操作。 任何假设每个白边至少贡献一次操作的解决方案都会立即失败。 

## 方法

 暴力策略可以模拟这个过程。 在每一步中，我们都会搜索包含至少一个白色边缘的任何简单循环，通过将其边缘涂成黑色来删除它，然后重复。 找到一个循环并验证其有效性至少需要 DFS 或 BFS，并且重复此操作最多 O(m) 次会导致最坏情况下的 O(m(n + m)) 行为，这远远超出了限制。 

关键的观察结果是，该操作不依赖于循环存在的边缘颜色，仅依赖于底层图中循环的结构。 颜色仅在每个选定的循环必须包含至少一个白色边缘的限制中才重要，但是一旦我们决定使用一个循环，它的所有边缘都会被吸收为黑色。 

这建议考虑白边如何分布在图的循环空间上。 每个操作有效地“消耗”一个涉及至少一个白边的独立周期。 如果多个白边位于相同的基本循环结构上，则它们可能被迫一起被移除，这减少了可实现的操作的数量。 

关键的简化是隔离仅由白色边缘形成的结构。 黑色边缘可以被视为背景连接，但它们并不限制我们可以从白色边缘提取多少个独立循环。 事实证明，答案仅取决于由白边形成的子图中存在多少个独立循环。 

该数量正是白边子图的圈数，可以通过白边数减去顶点数加上该白子图中连通分量的数量来计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力循环模拟| O(m(n + m)) | O(m(n + m)) | O(n + m) | 太慢了 |
 | 白色子图的圈数 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们只关注由白色边缘组成的子图。 让它有V个顶点（考虑所有原始顶点）和E条白边。

1. 仅使用白边构建图表。 我们完全忽略黑边，因为它们不影响我们正在计算的独立循环结构。 
2. 运行图遍历（DFS 或 BFS）来计算该白边图中的连通分量的数量。 每个连接的组件代表一个区域，其中循环可以独立于其他区域而存在。 
3.读取输入时直接计算白边E的数量。 
4. 将答案计算为 E - V + C，其中 C 是白边图中连通分量的数量。 

出现这种组合的原因是，在每个连通分量中，独立循环的数量等于边减去顶点加一。 将这些成分相加就得到了全局公式。 

### 为什么它有效

 在任何连接的组件内，每个树边都不提供循环自由度，而生成树之外的每个额外边都恰好创建一个独立的循环。 任何操作都会删除一个周期的结构，该结构必须包含至少一个白边。 由于我们完全在白边子图内进行操作，因此每个独立循环恰好对应于一个可实现的操作，并且任何循环分解都不能超过此计数，因为它受到循环空间维度的限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        adj = [[] for _ in range(n + 1)]
        edges = []

        white_edges = 0

        for _ in range(m):
            u, v, col = map(int, input().split())
            if col == 0:
                adj[u].append(v)
                adj[v].append(u)
                edges.append((u, v))
                white_edges += 1

        visited = [False] * (n + 1)

        components = 0

        for i in range(1, n + 1):
            if not visited[i]:
                stack = [i]
                visited[i] = True
                touched = False

                while stack:
                    u = stack.pop()
                    for v in adj[u]:
                        if not visited[v]:
                            visited[v] = True
                            stack.append(v)
                components += 1

        # We use all vertices in formula; isolated vertices are components of size 1
        # but they contribute correctly when included in C.
        ans = white_edges - n + components
        print(ans)

if __name__ == "__main__":
    solve()
```该实现读取每个测试用例，构建白边的邻接列表，并使用迭代 DFS 计算连接的组件以避免递归深度问题。 最终公式结合了白边总数、顶点数和连通分量数。 

一个微妙的点是，在计算 C 时，孤立的顶点仍然必须被计为组件，因为它们确保公式与完整的顶点集保持一致。 这就是为什么遍历所有顶点，而不仅仅是那些与白边相关的顶点。

这表明重叠循环不会将答案增加到循环空间维度之外。

 ## 边缘情况

 具有所有白色边缘的树展示了最重要的约束：由于没有循环，该算法产生 E - V + C = 0。DFS 正确计算每个连接的组件，并且因为 C = 1 和 E = V - 1，所以表达式抵消为零。 

所有边均为白色的全循环图显示相反的行为。 生成树之外的每一条额外边都只贡献一次操作，并且基于 DFS 的组件计数可确保正确减去冗余结构。 

具有孤立顶点的图也表现正确，因为它们被计入连通分量总数中，从而保留了每个顶点参与圈计算的不变性，即使它没有白边。
