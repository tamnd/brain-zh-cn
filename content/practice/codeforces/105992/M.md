 ## 解决方案
 ## 问题理解

 我们得到一个数组$n$魔法球，全部从零开始。 目标是将它们转换为目标数组$a$，其中每个位置$i$必须恰好结束于$a_i$。 

可以进行两种操作。 第一个操作是点增量：选择任何单个索引并将其值增加一，支付固定成本$x$。 第二个操作是范围加倍：选择任意间隔$[l, r]$并将其中的每个值乘以二，支付固定成本$y$。 

任务是以最小的总成本从零开始达到目标配置。 

塑造解决方案的关键约束是$n \le 3 \cdot 10^5$和$a_i \le 10^9$。 这立即表明任何二次方$n$太慢了，而涉及值本身的运算应该在对数层中处理，最自然地通过二进制表示。 由于值的边界为$10^9$，每个数字最多有 30 位，因此任何按位处理数组的解决方案都是可行的。 

一个微妙的方面是，加倍操作作用于整个段，而不是单个元素。 这引入了位置之间的相互作用，因为一次加倍可以同时影响许多元素。 忽略这种耦合的天真的每元素贪婪方法并不是立即合理的。 

如果我们假设每个元素都是独立的，就会出现一种失败情况。 假设两个相邻元素受益于共享加倍，但我们分别支付增量成本； 贪婪的每个索引决策可能会错过共享结构。 

例如，如果$x$很大并且$y$很小，显然使用范围加倍更好，但该决定不是每个元素局部的，因为一次加倍有利于整个段。 

另一个失败的情况是假设我们必须显式地向前模拟操作。 由于值在加倍的情况下会呈指数增长，因此即使对于很小的输入，由于重复操作，模拟也会很快变得不可行。 

## 方法

 蛮力的想法是从零开始构建数组，尝试所有操作序列。 每个操作要么增加一个位置，要么加倍一个段。 即使将我们限制在合理的序列中，分支因素也是巨大的：在每一步我们都可以选择$O(n^2)$段或$n$点运算，所需的步骤数取决于所有二进制表示的数字之和$a_i$。 这导致指数搜索空间完全不可行。 

关键的观察是这两个操作都与二进制表示干净地交互。 点增量对应于每次设置一个单位的低级别贡献，而加倍操作则将所有贡献提高一位。 这表明一点一点地处理构造。 

我们不是从零开始思考，而是考虑最终数字的每一位是如何形成的。 每次加倍都会有效地将整个构建的结构向上移动一位。 在位级别$k$，我们只需要决定一个贡献是直接使用增量构建还是通过加倍从前一个级别继承。 

这将问题转换为基于位的分层 DP，其中每一层仅取决于前一层和每个元素的本地选择。

 ## 算法演练

 我们从最低有效位向上处理二进制表示。 让$dp[i]$表示迄今为止为指数累积的最小成本贡献$i$处理低位后。 

在每个位级别$k$，我们看看是否$k$第 位$a_i$是0或1。 

1. 初始化$dp[i] = 0$对于所有索引，因为在处理任何位之前不会产生任何成本。 
2. 对于每个位位置$k$从 0 到 30，提取$b_i$， 这$k$第 位$a_i$。 这表示该位是否必须出现在最终值中。 
3. 对于每个索引$i$，考虑两种方法来获得该位级别的贡献。 

一种方法是使用点增量直接构建位。 如果$b_i = 1$，这花费了$x$; 如果$b_i = 0$，不花钱。 

另一种方法是重用我们在先前位级别构建的内容并应用加倍效果。 如果我们将之前的结构向上推进，我们将支付$y$每个元素一次，以反映影响包含该元素的段的加倍操作的使用。 这有效地向上传播较低位。 
4. 将 DP 转换更新为：$$dp[i] = \min(x \cdot b_i,\ dp[i] + y)$$这捕获了从头开始重建位或通过加倍从先前层继承它之间的决定。 
5. 处理完所有位后，最终的答案就是$dp[i]$综合所有指数。 

这样做的原因是，一旦我们修复了先前位的传播方式，每个位层都是独立的。 除了通过附加成本之外，加倍不会混合不同索引之间的位，其效果纯粹是向上移动先前构建的结构。 DP 不变量是处理位后$k$,$dp[i]$表示实现比特前缀贡献的最小成本$k$对于索引$i$，考虑每个位是直接构造还是通过加倍继承的所有选择。 由于这两种操作在每一层的每个元素的贡献上都是线性的，因此索引之间的耦合不会超出附加成本，因此每个元素的最小化是有效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    a = list(map(int, input().split()))
    
    dp = [0] * n
    
    for k in range(31):
        cost_direct = []
        for i in range(n):
            bit = (a[i] >> k) & 1
            cost_direct.append(x * bit)
        
        for i in range(n):
            dp[i] = min(cost_direct[i], dp[i] + y)
    
    print(sum(dp))

if __name__ == "__main__":
    solve()
```该实现在索引上保留单个 DP 数组。 在每个位级别，我们使用增量计算形成该位的直接成本，并将其与使用加倍操作扩展先前的构造进行比较。 更新是就地完成的，因为每个级别仅取决于先前的 DP 状态。 

一个常见的陷阱是尝试将加倍视为仅影响位为 1 的索引。实际上，加倍会传播已经构造的任何内容，因此即使零位仍然可以通过$dp[i] + y$过渡。 

另一个微妙之处是我们从不显式模拟值。 DP 跟踪成本结构，而不是实际数值，这避免了溢出并保持计算线性$n \log A$。 

## 工作示例

 考虑数组$a = [1, 1]$， 和$x = 1, y = 1$。 

在位 0 处，两个元素都具有位 1。每个元素的直接成本均为 1。 自从$dp$从0开始，我们比较$1$相对$0 + 1$，所以两个选项都是相等的并且$dp = [1, 1]$。 

在较高位，所有值均为零，因此 DP 不会进一步增加。 最终答案是2。 

现在考虑$a = [2, 3]$和$x = 2, y = 1$。 

| 位| 我| 位值| 直接成本| dp 之前 | dp 之后 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | 0 | 0 |
 | 0 | 1 | 1 | 2 | 0 | 1 |
 | 1 | 0 | 1 | 2 | 0 | 1 |
 | 1 | 1 | 1 | 2 | 1 | 2 |

 在位 1 处，两个元素都可以直接以成本 2 构建，也可以从上一级别继承，成本增加一倍。 DP 正确地累积了每个元素更便宜的选项。 

该轨迹显示了算法如何逐渐构建较高位，同时保留较低位的最佳成本结构。

 ## 边缘情况

 一种边缘情况是当所有$a_i = 0$。 该算法处理所有位，但每个位贡献为零，因此$dp[i]$始终保持为零。 这证实了永远不会引入不必要的操作。 

另一种情况是单个大值，例如$a = [2^{30} - 1]$。 DP 迭代所有位，并且在每个级别要么支付增量成本，要么携带先前的成本。 由于每个位都是独立处理的，因此递归确保了最小累积而不会溢出。 

第三种情况是当$y = 0$，使免费加倍。 递归立即更喜欢通过传播$dp[i] + y$，因此所有结构都是向上继承的，有效地将解决方案压缩为单个构造过程。 

最后一种情况是当$x = 0$，使增量免费。 然后直接构建在每一位上都占主导地位，并且DP始终选择直接分支，从而导致总成本为零。
