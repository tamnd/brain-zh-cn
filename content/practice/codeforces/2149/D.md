 ## 解决方案
 ## 问题理解

 我们得到一个仅由两个符号组成的二进制字符串，`a`和`b`。 我们可以交换相邻的字符，因此任何操作本质上都是对两个邻居进行冒泡排序的一步。 

目标不是对字符串进行完全排序，而是达到较弱的结构条件：经过一些交换后，我们必须能够选择其中一个字符，例如`a`或者`b`，并使该所选字符的所有出现都恰好形成最终字符串中的一个连续段。 另一个字符可以分成两部分，一个位于所选块的左侧，一个位于右侧。 

所以我们并没有强制执行完全的单调顺序。 我们只是强制一种类型不会出现在多个单独的组中。 

每次交换成本为 1，我们希望交换的次数最少。 

约束条件很大：所有测试用例的总长度最多可达 200,000 个。 这立即排除了交换或检查所有中间状态的任何二次模拟。 任何重复模拟交换或天真的尝试所有可能的目标配置的操作都会超时。 

当字符串频繁交替时，会出现微妙的失败情况，例如`ababababa`。 在这种情况下，“修复最近的不匹配”的贪婪本地交换看起来很合理，但并不能全局最小化将字符类型合并到一个块中所需的交叉数量。 成本取决于所选字符出现之间的全局反转，而不是局部邻接。 

## 方法

 直接方法将分别尝试两种可能性：强制所有`a`将字符放入一个连续的块中，或者强制所有字符`b`将字符放入一个连续的块中。 对于每个目标，我们将模拟交换，直到达到有效性，也许会贪婪地向内移动放错位置的字符。 

这在正确性意义上是有效的，因为相邻的交换让我们可以任意重新排列，但问题是成本。 在最坏的情况下，每次交换仅通过一次反转来减少无序性，并在长度上显式地模拟这一点`n`导致二次行为。 

关键的见解是停止从运营角度思考，而是从交叉角度思考。 当我们选择一个角色时，说`a`，我们正在有效地决定所有`a`字符必须分组。 每一个`a`被“分开”的是`b`字符贡献的成本等于多少`b`它必须通过的字符才能加入其最终块。 每次交换恰好删除了不同字符之间的一个反转，因此答案变成了最佳排列下所选字符与另一个字符之间的反转次数。 

现在是结构简化。 如果我们解决这一切`a`必须形成一个块，然后每个`b`要么完全位于该块的左侧，要么完全位于该块的右侧。 这意味着我们正在字符串中选择一个分割点：剩下的一切都是`b`，然后是一个块`a`，然后剩余`b`。 任何偏离此结构的成本都等于必须跨越边界才能到达其一侧的角色数量。 

因此，对于固定的分割位置，我们可以计算有多少`a`错位到左边了，有多少个`b`错位在右侧。 这给出了该拆分的成本。 我们对每一个可能的分割都这样做，并取最小值。 我们重复相同的逻辑交换角色`a`和`b`。 

最佳答案是这两种对称情况中的最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力交换模拟| O(n²) | O(1) | O(1) | 太慢了 |
 | 基于前缀的分割评估 | 每次测试 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们描述了当我们决定时计算所需的最小交换的过程`a`形成单个连续块。 

1. 统计总数`a`字符串中的字符。 这告诉我们决赛的长度`a`堵塞。 
2. 预先计算多少个前缀和`a`字符出现在每个索引处。 这允许恒定时间查询有多少`a`位于切口的左侧。 
3. 对于每个可能的区间，其中`a`块可以坐下，我们想象字符串分成三部分：左侧，中间`a`块，右侧。 
4. 对于固定起始位置`l`的块，计算有多少`a`字符当前位于块之外。 这些是必须向内移动的人。 
5. 放置方块的成本`l`到`l + total_a - 1`可以使用前缀和来计算：

 左侧应该只包含`b`，所以所有`a`左边的都是错误的

 右侧也应该只包含`b`，所以所有`a`对的都是错的。 
6. 取块中所有有效位置的最小值。 
7. 交换角色后重复相同的计算（`b`成为目标块字符）。 
8. 返回两个结果中的最小值。 

### 为什么它有效

 每次交换恰好解决了一个之间的一个反转`a`和一个`b`。 当我们修复目标配置时，所需交换的数量等于必须跨入其最终一侧的字符之间的此类反转数量。 可能的块位置上的滑动窗口枚举了所有结构上有效的最终配置，并且前缀和确保我们在每次反转时准确地计算一次错误位置的字符。 这保证了我们计算将字符串转换为任何有效的单块排列所需的相邻交换的真实最小数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cost(s, ch):
    n = len(s)
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (s[i] == ch)
    
    total = pref[n]
    if total == 0:
        return 0
    
    best = float('inf')
    
    for l in range(n - total + 1):
        r = l + total
        
        left_bad = pref[l]
        right_bad = pref[n] - pref[r]
        
        best = min(best, left_bad + right_bad)
    
    return best

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        ans = min(cost(s, 'a'), cost(s, 'b'))
        print(ans)

if __name__ == "__main__":
    solve()
```功能`cost`评估当一个字符被强制进入单个连续片段时的最佳成本。 前缀数组计算该字符在每个位置出现的次数，这允许快速计算有多少次出现在任何选定的窗口之外。 

循环结束`l`表示连续块的所有可能的放置。 对于每次放置，块外所选字符的元素必须跨越边界，并且每个此类错位字符恰好对应于最佳重新排列中所需的一个交换。 

我们独立计算两个角色选择，因为`a`或者`b`可能是形成最后一个块的那个。

 ## 边缘情况

 像这样的单字符字符串`a`或者`b`为块放置生成一个空循环范围。 成本函数立即返回 0，因为该字符的总数不是 0 就是 1，因此不需要移动。 

完全统一的字符串，例如`aaaaa`总计数等于`n`，所以唯一有效的窗口是整个字符串本身。 左右不匹配均为零，算法正确返回 0，而无需扫描有意义的替代项。 

高度交替的字符串，例如`ababab`行使全方位的区块位置。 对于每个位置，前缀和确保我们正确地计算所选段之外的字符，并且最小值稳定在巩固一种字符类型所需的真实反转数量。
