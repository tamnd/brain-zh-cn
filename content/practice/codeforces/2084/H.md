 ## 解决方案
 ## 问题理解

 我们从一个二进制字符串开始，并重复应用基于长度为 3 的窗口的删除规则。 

对于二元三元组，中位数就是多数值。 选择窗口后，我们删除从窗口左端点开始的后缀中第一次出现的多数值。 

只要最终长度至少为 2，该过程就可以随时停止。 我们被要求计算有多少个“不同的二进制字符串”可以作为某些有效操作序列的结果出现。 

第一个观察结果是，相等位的确切位置并不重要。 重要的是分解为等值的最大游程。 例如```
0011100011
```变成```
[2,3,3,2]
```其中每个数字是最大块的长度。 

所有测试用例的总长度最多为`2 · 10^6`，所以任何二次算法都是不可能的。 甚至一个`O(n log n)`解决方案已经使用了可用预算的很大一部分。 预期的解决方案与运行次数呈线性关系。 

危险的情况是那些运行次数很少的情况。 

对于仅包含一次运行的字符串，例如```
11111
```每个操作只是删除一个`1`。 得到的字符串正是长度`2,3,4,5`，给出答案`4`。 假设至少存在一种替代的解决方案将在这里失败。 

对于两次运行，例如```
000111
```唯一的自由是每次运行中有多少符号可以生存。 答案成为两个游程长度的乘积。 需要特殊处理。 

## 方法

 暴力搜索将每个可到达的字符串视为一个状态。 从每个状态，我们尝试每个有效窗口并递归生成所有可能的后代。 

这是正确的，因为它确实探索了可达性图。 不幸的是，州的数量呈指数级增长。 即使对于长度为几十的字符串，搜索也变得毫无希望。 

关键的结构观察是该操作永远不会创造新值。 它只会缩短现有的运行时间。 将字符串压缩为游程长度后```
a1, a2, ..., am
```整个问题变成了游程长度的计数问题。 

对删除规则的仔细分析表明，运行只能与压缩表示中具有相同奇偶校验的运行交互。 这将可达性关系转变为运行索引之间的单调匹配过程。 生成的动态编程状态仅取决于运行分解，而不取决于原始字符串位置。 

这个DP的直接实现是`O(m²)`。 关键转变反复要求控制表单数量的下一次运行```
a[i] - floor(i/2)
```这表明单调结构。 通过从右到左处理运行并维护单调堆栈，所有昂贵的转换都可以压缩为区间加法。 然后 DP 变为线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力可达性| 指数| 指数| 太慢了|
 | 游程 DP + 单调堆栈 | O(米) | O(米) | 已接受 |

 ## 算法演练

 ### 运行压缩

 将二进制字符串转换为最大相等段的长度。 

例如，```
001000111
```变成```
[2,1,3,3]
```设运行次数为`m`。 

### 特殊情况

 1.如果`m = 1`，答案是`n - 1`。 
2.如果`m = 2`，答案是`a[1] · a[2]`。 

这些情况对应于上面讨论的简并结构。 

### 构建下一个主导运行

 1. 分别对每个奇偶校验，从右到左处理索引。 
2. 维护一个按顺序排列的单调堆栈```
a[i] - floor(i/2)
```1.让`nxt[i]`是稍后在相同奇偶校验上运行的第一个，其值主导当前奇偶校验。 

这正是官方实现中使用的结构。 

### 动态规划

 1.让`f[i]`表示运行活动边界的可达压缩状态的数量`i`。 
2. 差异数组值`d[i]`用于执行由许多相同的转换产生的区间加法。 
3. 处理运行时`i`，将其贡献传播到所有可到达的后续运行。 单调堆栈链接压缩了原本是平方数的转换。 
4. 剩余后缀具有正确奇偶性的每个州都有助于答案。 
5. 将累积计数乘以最后一次运行的大小，因为最后一次运行独立地影响压缩状态表示的具体字符串的数量。 

### 两个方向

 1. 在原运行阵列上执行一次DP。 
2. 删除第一个游程并将新的第一个游程长度替换为`1`。 
3. 将两个结果取模相加`10^9 + 7`。 

这解释了左边界在删除过程中可能表现的两种可能的方式。 官方解决方案精确计算这两个 DP 评估并将它们相加。 

### 为什么它有效

 游程压缩后，每个可到达的字符串仅由每次游程缩短的程度决定。 删除规则保留游程的交替模式，仅更改其长度。 DP 列举了所有可行的缩短模式。 

数量```
a[i] - floor(i/2)
```在同等奇偶性的运行之间产生主导顺序。 任何跨越主导运行的过渡都可以与第一个主导运行的过渡合并。 单调堆栈准确记录了这些信息，允许间隔聚合而不会丢失任何可达状态。 由于每个有效的缩短模式都被计数一次且仅一次，因此 DP 计数等于不同的可获得的二进制字符串的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve_case(s):
    n = len(s)

    a = []
    i = 0
    while i < n:
        j = i
        while j + 1 < n and s[j + 1] == s[i]:
            j += 1
        a.append(j - i + 1)
        i = j + 1

    m0 = len(a)

    if m0 == 1:
        return n - 1

    if m0 == 2:
        return a[0] * a[1] % MOD

    def calc(arr):
        m = len(arr) - 1  # 1-indexed

        nxt = [0] * (m + 1)
        stk = []

        for start in (m if m & 1 else m - 1,
                      m - 1 if m & 1 else m):

            stk.clear()
            for i in range(start, 0, -2):
                cur = arr[i] - i // 2
                while stk and arr[stk[-1]] - stk[-1] // 2 < cur:
                    stk.pop()
                nxt[i] = stk[-1] if stk else 0
                stk.append(i)

        f = [0] * (m + 3)
        d = [0] * (m + 3)

        f[1] = arr[1]
        for i in range(3, m, 2):
            f[i] = 1

        ans = 0

        for i in range(1, m):
            if i >= 3:
                d[i] = (d[i] + d[i - 2]) % MOD

            f[i] = (f[i] + d[i]) % MOD

            j = i + 1
            x = 0

            while j < m:
                k = nxt[j] if nxt[j] else m

                f[j] = (f[j] + f[i] * (arr[j] - x)) % MOD

                x = arr[j] + (k - j) // 2 - 1

                d[j + 2] = (d[j + 2] + f[i]) % MOD
                d[k] = (d[k] - f[i]) % MOD

                j = k

            if ((m - i) & 1):
                ans = (ans + f[i]) % MOD

        return ans * arr[m] % MOD

    arr = [0] + a

    ans = calc(arr)

    b = [0] + a[1:]
    b[1] = 1

    ans = (ans + calc(b)) % MOD
    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()
        out.append(str(solve_case(s)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```实现遵循官方线性解决方案结构。 运行压缩阶段将二进制字符串转换为其最大段。 一次和两次运行的特殊情况会立即处理，因为它们的计数公式是封闭形式。 

单调堆栈结构计算`nxt[i]`分别为每个奇偶校验。 这一点至关重要。 混合奇数和偶数索引会破坏优势属性并导致不正确的转换。 

DP使用差分数组。 更新内容```
d[l] += value
d[r] -= value
```表示适用于整个奇偶校验子序列的贡献。 忘记仅沿着匹配的奇偶校验位置传播前缀累积是错误的常见来源。 

所有算术均以模进行`10^9 + 7`。

 ## 边缘情况

 考虑```
3
111
```运行分解为`[3]`。 每次操作都会删除一个`1`，并且唯一可获得的最终字符串的长度为二。 算法立即返回`n - 1 = 2`，匹配两个可获得的长度`{2,3}`。 

考虑```
6
000111
```分解为`[3,3]`。 任何可到达的字符串仅取决于剩余的零和一的数量。 有`3 · 3 = 9`可能性，正是两次运行公式返回的值。 

考虑```
5
01010
```每次运行的长度都是一。 幼稚的推理通常假设存在很少的结果，因为没有任何运行可以缩短很多。 DP 通过基于奇偶校验的转换正确处理此配置，并对每个可到达的压缩状态精确计数一次。
