 ## 解决方案
 ## 问题理解

 我们有两个玩家，水母和水母，每个人都有一些青苹果。 水母有`n`值存储在数组中的苹果`a`，而水母有`m`值存储在数组中的苹果`b`。 他们玩游戏是为了`k`回合。 在奇数轮中，水母可能会将她的一个苹果与水母的一个交换，或者什么也不做。 在偶数轮中，水母可能会进行类似的交换。 两者都以最佳方式发挥其苹果价值的总和。 目标是计算水母的苹果的总和`k`回合。 

约束条件告诉我们`n`和`m`很小（最多 50 个），但是`k`可能很大（最多 10^9）。 这立即表明模拟每一轮是不可能的。 相反，我们需要一个识别_有效掉期_的解决方案，因为在某个点之后，进一步的回合将不再改变总和。 

边缘情况来自这样的情况：一名玩家只有一个苹果，`k`非常大，或者最好的苹果已经在正确的人手中。 例如，如果水母有`[10]`水母有`[1]`和`k = 1000`，她永远不会交换，因为她无法增加她的金额。 盲目模拟交换的幼稚方法`k`如果错误计算停止条件，迭代将产生过多的运行时间或不正确的结果。 

## 方法

 蛮力方法很简单：对于每一轮，确定当前玩家的最佳交换，如果它增加了他们的总和，则执行它，并对所有玩家重复`k`回合。 这是正确的，因为游戏是回合制的，并且双方玩家都贪婪地行动。 然而，如果`k`高达 10^9，即使`n, m ≤ 50`，模拟`k`回合是不可能的。 

关键的观察是，没有玩家会交换苹果，除非它“严格提高”他们的总和。 这意味着我们最多只需要考虑`min(n, m)`每个玩家交换：水母只想用水母最大的苹果替换她最小的苹果，而水母会做相反的事情。 一旦最小的水母大于最大的水母，进一步的交换就没有好处了。 因此，有效的互换数量受以下限制：`min(n, m, k)`， 不是`k`。 

因此，最佳方法是：

 1. 将水母的苹果按升序排序，将水母的苹果按降序排序。 
2. 将相应元素（最小的水母与最大的水母）交换为`i = 0`到`min(n, m, k) - 1`。 
3. 一旦交换不会增加 Jellyfish 的总和，就停止。 

这将问题从潜在的数十亿次操作减少到每个测试用例最多 50 次交换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k * n * m) | O(n + m) | 太慢了 |
 | 最佳 | O(n log n + m log m) | O(n log n + m log m) | O(n + m) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，请阅读`n, m, k`和苹果数组`a`和`b`。 
2. 对 Jellyfish 的数组进行排序`a`按升序排列。 这使得最小的苹果很容易找到以进行潜在的交换。 
3. 对Gellyfish的数组进行排序`b`按降序排列。 这暴露了他拥有的最大的苹果，这些苹果是水母要吃的候选者。 
4. 计算`swap_count = min(n, m, k)`。 我们不能交换比任何一个玩家拥有的更多的苹果，并且不需要考虑更多`k`回合。 
5. 迭代自`i = 0`到`swap_count - 1`： 比较`a[i]`和`b[i]`。 如果`b[i] > a[i]`，交换它们。 如果没有，请尽早休息，因为进一步的交换无法提高 Jellyfish 的总和。 
6. 计算并打印 Jellyfish 最终数组的总和`a`。 

为什么有效：在每一步中，水母总是考虑她最不值钱的苹果和水母最有价值的苹果。 按这个顺序交换可以保证她贪婪地最大化她的总和。 因为 Gellyfish 会做出最佳响应，所以排序的交换序列已经考虑了最坏情况的反作用，因为任何有利于 Gellyfish 的交换都已经被排序的选择隐式阻止了。 一旦最小的水母超过最大的水母，就不可能再进行交换，从而建立停止条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort(reverse=True)
        
        swap_count = min(n, m, k)
        for i in range(swap_count):
            if a[i] < b[i]:
                a[i], b[i] = b[i], a[i]
            else:
                break
        
        print(sum(a))

if __name__ == "__main__":
    solve()
```该代码首先使用以下命令有效地读取多个测试用例`sys.stdin.readline`。 排序可确保交换是最佳的，而无需模拟每一轮。 早期的`break`确保如果 Jellyfish 无法进一步提高其总和，我们不会进行不必要的交换。`sum(a)`为了提高效率，每个测试用例仅计算一次。
