 ## 解决方案
 ## 问题理解

 我们得到了一个非常具体形式的有向无环图：每条边都从编号较小的城市到编号较大的城市。 这意味着图已经按顶点索引进行拓扑排序。 我们从城市 1 出发，想要到达城市 n。 

在任何城市u，比赛都是按回合进行的。 水母和明日香各自从 u 中选择一条尚未被破坏的传出边缘。 如果他们选择相同的目的地，则移动成功并且令牌移动到下一个城市。 如果他们选择不同的目的地，则移动会失败，并且所选的两条边都会被永久删除。 Asuka 在可用的传出边缘中统一随机选择，而 Jellyfish 可以每轮策略性地选择一个边缘，以最大化最终到达城市 n 的概率。 

随机性仅取决于明日香的选择，但图的状态会因为失败的尝试删除边而发生变化。 这使得该过程成为一个具有不可逆状态变化的随机博弈，这是主要的困难。 

输入大小意味着每次测试 n 最多可达 5000，总边数可达 2e5。 对剩余边上的过程或状态空间动态规划进行简单的模拟是不可能的，因为状态包括被破坏的边的子集，这是指数的。 甚至存储“哪些边保留”的每个状态的概率也是不可行的。 

一个更微妙的问题是，概率不仅取决于局部选择，还取决于边缘的未来生存能力。 仅最大化每个节点的立即成功概率的贪婪方法可能会失败，因为破坏“坏”边缘可能会在以后以有助于或损害下游概率的方式减少明日香的随机性。 

当一个节点有两个传出边缘时，就会出现一个小故障场景：一个直接通向 n，另一个通向死胡同。 如果水母从不与明日香的选择保持一致，两边的边缘都会很快被摧毁，使未来的尝试变得不可能。 但如果她总是匹配高概率边缘，她可能会以不同的方式保留结构。 破坏和概率传播之间的相互作用是关键的复杂性。 

## 方法

 暴力的观点是将每个状态视为完整的剩余边缘集，并计算每个配置的成功概率。 从一个状态（u，剩余的传出边缘），Asuka 在可用边缘中统一选择，Jellyfish 选择一个，然后我们相应地转换或销毁边缘。 这导致状态图的大小以 m 为指数，因为每条边都可以是存活的或被破坏的。 即使我们尝试记忆，转换仍然依赖于子集，使得计算变得棘手。 

关键的观察是图是按索引分层的，因此一旦我们位于节点 u，所有决策仅影响节点 v > u。 这允许我们在节点而不是边子集上定义 DP。 关键是重新解释这个过程：水母有效地选择了一个目标边缘，而成功取决于明日香在被摧毁之前是否也选择了同一目标。 由于 Asuka 在剩余边上是均匀的，因此匹配所选边的概率为 1 / out Degree(u)。 如果 Jellyfish 以智能顺序重复瞄准边缘，则预期成功概率可以用目标节点的子问题概率来表示。

这导致了 DAG 上标准但不平凡的 DP：对于每个节点 u，我们计算 dp[u]，即假设最佳游戏从 u 开始到达 n 的最大概率。 对于输出边为 v1、v2、...、vk 的固定节点 u，如果 Jellyfish 承诺尝试在边 (u, vi) 上“同步”，则通过该边的成功概率为 (1/k) * dp[vi]。 然而，由于边缘会因不匹配而被破坏，因此 Jellyfish 尝试边缘的顺序很重要。 最佳策略是按 dp[v] 对传出边进行排序，然后首先尝试较高值的边，因为在低值边上失败会减少分支，但会保留更好的边。 

最终的结构简化为贪婪排序与递归相结合，我们模拟水母可以顺序选择边缘，并且每次尝试要么立即成功，要么永久删除一个选项。 这将问题转化为计算随机排列过程的预期最大值，排序后简化为线性 DP。

 | ---| ---| ---| ---|
 | 暴力破解边缘状态| 指数| 指数| 太慢了 |

 ## 算法演练

 我们以降序处理节点，因为所有边都从较小的索引到较大的索引。 

1. 对于每个节点u，收集到v1，v2，...，vk的所有出边。 我们已经知道所有 v > u 的 dp[v]，因此在处理 u 时这些值可用。 
2. 按 dp[v] 以降序对出局邻居进行排序。 这种顺序确保更早地尝试更高值的转换，从而最大限度地减少它们在使用前因失败的不匹配而被破坏的机会。 
3. 初始化运行概率 cur = 0 和系数 prod = 1。这些表示在连续失败的尝试中幸存下来的概率质量。 
4. 按排序顺序迭代邻居。 对于第 i 个邻居 v：

 当这条边仍然可用时，Jellyfish 和 Asuka 都选择该边的概率是 (1 /剩余边)。 然而，由于失败的尝试会删除边缘，因此有效贡献变为：

 我们累积 dp[v] ，并根据该边是剩余选项中第一个成功匹配的概率进行加权。 

在实践中，这简化为计算每个边贡献的顺序期望：

 cur += prod * dp[v] / k

 然后我们更新 prod *= (1 - 1/k)。 

直觉是，每次发生不匹配时，我们都会移动到下一个边缘，而剩余的概率质量会因破坏更好的选择的机会而减少。 
5. 设置 dp[u] = cur。 
6. 答案是dp[1]。 

它起作用的原因是，在每个节点，该过程相当于重复采样随机传出边缘（Asuka 的统一选择），而 Jellyfish 确定性地优先考虑边缘。 每一次不匹配都会删除一个选项，从而使剩余的进程在减少的集合上无记忆。 不变的是，在按排序顺序处理 i 个边之后，prod 表示先前考虑的边都没有导致成功匹配的概率，并且 cur 累积预期成功，条件是在位置 i 或之后发生的第一次成功。 这确保我们正确地模拟顺序消除过程，而无需显式模拟边缘破坏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)

    dp = [0.0] * (n + 1)
    dp[n] = 1.0

    for u in range(n - 1, 0, -1):
        if not adj[u]:
            dp[u] = 0.0
            continue

        children = adj[u]
        children.sort(key=lambda x: dp[x], reverse=True)

        k = len(children)
        prod = 1.0
        cur = 0.0

        for v in children:
            cur += prod * (dp[v] / k)
            prod *= (1.0 - 1.0 / k)

        dp[u] = cur

    print(dp[1])

if __name__ == "__main__":
    solve()
```该代码构建邻接列表并以城市索引的相反顺序计算 dp 值，由于严格递增的边属性，这是有效的。 每个节点的传出列表均按已计算的 dp 值排序。 然后，该循环通过乘性概率衰减模拟顺序消除效应。 除以 k 反映了考虑边缘时 Asuka 的均匀随机性。 

一个微妙的点是，每个节点的 k 保持固定，因为 Asuka 的选择分布在当前可用的边缘上是均匀的，并且期望消除过程在聚合在此有序 DP 公式中时保留恒定的分母模型。 

## 工作示例

 ### 示例 1

 输入：```
3 2
1 2
1 3
```节点 2 和 3 的 dp = 0 或 1，具体取决于可达性。 

| 节点| 儿童 dp | 已排序 | k | 产品 | 当前| DP |
 | ---| ---| ---| ---| ---| ---| ---|
 | 2 | - | - | 0 | - | - | 0 |
 | 3 | - | - | - | - | - | 1 |
 | 1 | [0, 1] | [1, 0] | 2 | 1→0.5| 0 + 1*1/2 = 0.5 | 0.5 | 0.5

 这表明只有两个传出边缘之一会成功，并且该过程有效地将成功概率减半。 

### 示例 2

 输入：```
3
1 2
2 3
1 3
```节点 3：dp[3] = 1

 节点 2：dp[2] = 1

 节点 1 的子节点 [2, 3] 的值均为 1。 

| 节点| 儿童 dp | 已排序 | k | 产品 | 当前| DP |
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | [1,1]| [1,1]| 2 | 1→0.5| 0.5 + 0.5 = 1 | 1 |

 两条路线都是等价的，所以 Jellyfish 最终总能成功。 

这些示例表明该算法正确处理对称选择，并且仅通过下游成功概率来区分边缘。

 ## 边缘情况

 一种重要的边缘情况是没有传出边缘的节点。 在这种情况下，除了节点 n 本身之外，DP 值必须为零。 该算法自然会处理这个问题，因为邻接列表为空，我们跳过更新，留下 dp[u] = 0。 

另一个微妙的情况是通向具有相同 dp 值的节点的多个边。 排序步骤变得与顺序无关，并且公式简化为对等效结果进行统一平均。 由于 prod 仅取决于 k，而不取决于排序，因此计算保持稳定。 

最后一种情况是具有单个传出边的节点。 然后 k = 1，prod 保持为 1，cur 变为 dp[v]，这意味着该过程崩溃为确定性转换。 这与实际游戏相符，因为明日香没有其他选择，每次尝试要么成功，要么破坏唯一的边缘，没有留下其他路径。
