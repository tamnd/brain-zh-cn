 ## 解决方案
 ## 问题理解

 我们正在与一群怪物作战。 每个怪物都有生命值和力量值。 

杰诺斯反复进行攻击。 如果当前攻击强度为`k`，每个还活着的怪物都会失败`k`健康同时进行。 那次攻击之后，我们看看还活着的怪物。 其中，求最小功率值。 减去该最小功率`k`，降低所有未来攻击的强度。 

这个过程一直持续到所有怪物都死为止，这意味着答案是`"YES"`，或者当某些怪物还活着时，攻击强度变为非正数，这意味着答案是`"NO"`。 

输入给出了多个测试用例。 对于每个测试用例，我们知道初始攻击强度`k`，每个怪物的生命值，以及每个怪物的力量。 我们必须确定最终是否能够消灭所有怪物。 

约束是指导解决方案的首要因素。 单个生命值或力量可以大到`10^9`， 和`k`还可以`10^9`。 逐一模拟攻击是不可能的，因为在所有怪物死亡之前可能会有数十亿次攻击。 所有测试用例中的怪物总数仅为`2·10^5`，这强烈表明解决方案应该花费大约`O(n log n)`或者`O(n)`每个测试用例的工作。 

当多个怪物在同一次攻击中死亡时，会出现微妙的边缘情况。 攻击后的最弱的活着的怪物可能与攻击前的最弱的怪物完全不同。 

考虑：```
n = 2, k = 5
h = [5, 100]
p = [1, 100]
```第一次攻击后，第一个怪物立即死亡。 下次减少必须使用电力`100`，不是功率`1`，因为现存最弱的怪物现在拥有了力量`100`。 

另一个容易犯的错误是直接模拟健康值。 健康值可以大到`10^9`，因此反复减去每个怪物的伤害会太慢。 

第三个陷阱是假设怪物应该按生命值进行处理。 威力值决定了未来攻击减弱的速度，因此仅按健康状况排序会丢失关键信息。 

例如：```
h = [10, 20]
p = [100, 1]
```低功率怪物具有战略重要性，因为较晚杀死它可以使攻击强度保持在更长的时间内。 

## 方法

 暴力模拟会重复执行攻击。 在每次攻击期间，我们会减去每个活着的怪物的当前伤害，确定哪些怪物还活着，找到其中的最小力量，减少`k`，然后继续。 

这是正确的，因为它直接遵循规则。 不幸的是，攻击的数量不受限制`n`。 攻击强度和生命值可以达到`10^9`，因此该过程可能需要大量迭代。 即使每次攻击只花费`O(n)`，总的工作是完全不可行的。 

关键的观察是，只有怪物死亡的时刻才真正重要。 

让`damage`表示到目前为止对每个怪物造成的总伤害。 怪物死一次`damage ≥ h_i`。 

假设我们知道当前的累积伤害`damage`。 然后每个怪物`h_i ≤ damage`已经死了。 剩下的怪物中，力量最小的决定了下一次攻击后攻击力会减少多少。 

这建议按健康状况对怪物进行排序。 一旦排序，我们就可以有效地确定哪些怪物已经随着总累积伤害的增长而死亡。 

第二个观察是，我们只需要知道生命值仍大于当前累积伤害的怪物中的最小力量。 这可以用后缀最小数组来维护。 

按健康状况排序后：```
(h1,p1), (h2,p2), ...
```定义```
suf[i] = min power among monsters i..n-1
```如果所有怪物的指数小于`ptr`死了，那么最弱的活着的怪物就有力量`suf[ptr]`。 

现在这个过程变得非常紧凑：

 我们维持总累积伤害`damage`。 

每次迭代都会增加当前的攻击强度`k`到`damage`。 

我们将指针移过每个目前生命值最多的怪物`damage`。 

如果所有怪物都死了，回答`"YES"`。 

否则，最弱的生存力量是`suf[ptr]`，所以我们减少`k`那个数量。 

迭代次数最多为`n`，因为每次迭代要么杀死至少一个新怪物，要么使`k`非积极的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 无限制、潜在数十亿次攻击 | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个怪物的生命值和力量配对`(h_i, p_i)`。 
2.按生命值对怪物进行排序。 
3. 构建后缀最小幂数组。 对于每个职位`i`,`suf[i]`储存怪物中最小的力量`i`到最后。 
4.初始化：

 -`damage = 0`-`ptr = 0`5. 虽然`k > 0`：

 1.将当前攻击强度与总伤害相加：`damage += k`。 
2. 移动`ptr`前进同时`health[ptr] ≤ damage`。 

这些怪物已经死了。 
3.如果`ptr == n`，所有怪物都死了。 输出`"YES"`。 
4. 否则，最弱的幸存怪物拥有力量`suf[ptr]`。 降低攻击强度：`k -= suf[ptr]`。 
6. 如果循环结束是因为`k ≤ 0`并且有些怪物还活着，输出`"NO"`。 

### 为什么它有效

 多次攻击后的累计伤害正好是每个怪物生命值减去的总和。 当怪物的生命值超过此累积伤害时，怪物就处于存活状态。 

在任何时刻，未来攻击强度的降低只取决于活着的怪物中的最小力量。 按生命值排序后，活着的怪物总是形成数组的后缀，因为生命值较小的每个怪物不晚于生命值较大的怪物死亡。 

后缀最小数组给出了恒定时间内所有活着的怪物中最小的力量。 每次迭代都精确地再现与原始过程相同的状态转换，但不跟踪个体健康值。 由于模拟在数学上保持相同，因此算法产生与原始游戏相同的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, k = map(int, input().split())
        h = list(map(int, input().split()))
        p = list(map(int, input().split()))

        monsters = sorted(zip(h, p))

        suf = [0] * n
        suf[-1] = monsters[-1][1]

        for i in range(n - 2, -1, -1):
            suf[i] = min(suf[i + 1], monsters[i][1])

        damage = 0
        ptr = 0
        cur_k = k

        while cur_k > 0:
            damage += cur_k

            while ptr < n and monsters[ptr][0] <= damage:
                ptr += 1

            if ptr == n:
                answers.append("YES")
                break

            cur_k -= suf[ptr]
        else:
            answers.append("NO")

    sys.stdout.write("\n".join(answers))

solve()
```排序步骤创建怪物可以消失的顺序。 一旦总累积伤害达到怪物的生命值，该怪物就永远死亡，因此活着的怪物总是占据排序数组的后缀。 

后缀最小数组是关键的优化。 如果没有它，每次迭代都需要扫描所有幸存的怪物以找到最弱的力量。 有了它，最弱的生存力量立马可用。 

指针`ptr`只会前进。 每个怪物都会被跳过一次，总共`O(n)`指针在整个测试用例中的移动。 

使用`damage`不是单独更新每个健康状况，而是避免处理大到的值`10^9`重复并保持模拟效率。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |

 ## 边缘情况

 考虑所有怪物都具有相同生命值的情况：```
1
3 5
5 5 5
1 2 3
```第一次攻击后，累计伤害变为5。所有怪物同时死亡，指针直接移动到`n`，算法输出`"YES"`。 一次更新一个怪物的解决方案可能会在所有人都死后意外地应用额外的功率降低。 

考虑攻击强度恰好为零的情况：```
1
1 4
5
4
```第一次攻击后，累积伤害为 4，怪物仍存活。 最弱的活着力量是4，所以攻击强度变成0。循环停止，答案是`"NO"`。 该算法在进行下一次攻击之前正确检查怪物是否死亡。 

考虑一个迭代中多个怪物死亡的情况：```
1
4 10
3 4 5 100
1 1 1 1
```累积伤害立即变为10，杀死前三只怪物。 指针一次跳过所有三个。 活动集仍然是排序顺序的后缀，这正是使后缀最小技术有效的属性。
