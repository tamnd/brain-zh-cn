 ## 解决方案
 ## 问题理解

 我们有一个整数数组。 操作允许我们选择任意两个位置和一个位索引，然后在两个数字之间交换该位的值。 

关键的细节是位位置在交换期间是固定的。 我们可以移动一个`1`位从一个数字到另一个数字，但仅限于同一位位置。 例如，位置 3 中的位永远不能成为位置 2 中的位。 

目标是在执行任意数量的此类操作后最大化数组中最大和最小元素之间的差异。 

数组大小最多为 512，并且每个值都低于 1024。由于 1024 是$2^{10}$，每个数字仅包含 10 个相关位位置。 小位宽强烈表明逐位推理比模拟操作更有用。 

一个常见的错误是认为交换可以保留每个数字的价值。 他们没有。 例如：```
2
4 3
```二进制形式是`100`和`011`。 交换位 2 产生：```
000 = 0
111 = 7
```数字发生巨大变化。 

另一个容易犯的错误是将不同的位位置视为相互作用。 他们是完全独立的。 例如：```
3
1 2 4
```每个位位置恰好有一个`1`。 没有任何操作可以移动`1`从一个位置到另一个位置。 我们能做的最好的事情就是收集所有现有的`1`位转换为一个数字，产生`7`，并保留另一个数字作为`0`。 答案是`7`。 

第三种边缘情况是所有数字都相同：```
4
5 5 5 5
```每个位位置要么包含全零，要么包含全1。 交换位不会改变什么，所以答案仍然存在`0`。 

## 方法

 蛮力思维首先会询问哪些状态是可以到达的。 我们可以重复执行位交换，生成新数组并搜索最大可能值`max(a) - min(a)`。 

这在原则上是正确的，因为每一个合法的操作都是经过探索的。 问题是状态空间立即爆炸。 即使对于单个操作也有$O(n^2 \cdot 10)$选择。 操作序列创建了大量可到达的数组，使得显式搜索完全不可行。 

关键的观察是位位置是独立的。 

考虑一个固定的位位置$b$。 假设准确地说$k$数字当前包含`1`在那个位置。 交换位只会重新排列这些位$k$数组位置中的一个。 该位位置的总计数永远不会改变。 

这意味着对于每个位位置，我们只关心存在多少个位，而不关心它们当前所在的位置。 

现在考虑最大化：```
max(a) - min(a)
```为了使这种差异尽可能大，我们希望一个数字尽可能大，而另一个数字尽可能小。 

对于每个位位置：

 如果至少有一个`1`如果存在于该位置，我们可以将其中一个移动到未来的最大元素中。 

如果不是所有数字都包含`1`在那个位置，那么某个元素可以有一个`0`在那里，这有助于创建未来的最小元素。 

自从$n \ge 3$，每当一个位位置至少包含一个`1`，我们总是可以放置一个`1`到最大元素和`0`同时进入最小元素。 

因此，每个位位置都会独立地影响最终的差异：

 如果一位位置至少出现在一个数字中，则它贡献其全部值$2^b$到答案。 

这正是整个数组中按位或的定义。 

所以答案很简单：```
a1 OR a2 OR ... OR an
```还有另一种方法可以看到相同的结果。 让：```
M = OR of all elements
```我们可以收集一切可用的`1`钻研一个元素，创造价值`M`。 

对于最小元素，所有数字中不存在的每一位都可以`0`。 自从$n \ge 3$，我们可以选择不同的元素来保存这些位。 最小可驱动至`0`。 

因此：```
max(a) - min(a) = M - 0 = M
```| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数状态空间| 指数| 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化累加器`ans = 0`。 
2. 迭代数组中的所有数字。 
3. 更新`ans |= value`对于每个元素。 

这会收集数组中至少出现一次的每个位位置。 
4.处理完整个数组后，输出`ans`。 

这样做的原因是每个位的位置都可以独立地重新排列。 数组中某处存在的任何位都可以分配给未来的最大元素。 由于最小元素可以同时避免接收该位，因此该位的完整值会影响最终的差值。 

### 为什么它有效

 对于每一位位置$b$，令其值为$2^b$。 

如果没有元素包含该位，则它永远不会出现在任何地方，因此它的贡献为零。 

如果至少有一个元素包含该位，则该位置的个数为正。 通过在数组元素之间交换位，我们可以将其中之一放入选择为最大值的元素中。 同时，因为$n \ge 3$，我们可以在该位置保留另一个带零的元素，并将其用作最小候选。 

因此，至少出现一次的每一位都准确贡献$2^b$到可实现的差异。 将所有位位置上的这些贡献相加得出数组的按位或，这正是答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    for x in a:
        ans |= x

    print(ans)
```由于数学观察消除了所有模拟，因此实现非常小。 

变量`ans`存储数组的运行按位或。 每次我们处理一个数字时，该数字中存在的所有位都会出现在`ans`。 

扫描完整个阵列后，`ans`恰好包含在数组中任何位置至少出现一次的位位置集。 上面的证明表明该值等于可实现的最大差异。 

不存在棘手的边界条件。 这些数字很小，Python 整数可以轻松处理它们，并且答案很适合正常整数范围。

import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0
        for x in a:
            ans |= x

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

 ## 边缘情况

 ### 所有值都相等

 输入：```
1
4
5 5 5 5
```该算法计算：```
5 OR 5 OR 5 OR 5 = 5
```输出：```
5
```每个位位置要么存在于所有数字中，要么不存在于所有数字中。 没有交换会改变任何事情。 可实现的最大差异正好是 5，与 OR 匹配。 

### 每个有用的位都以不同的数字出现

 输入：```
1
3
1 2 4
```运行 OR 变为：```
1 -> 3 -> 7
```输出：```
7
```尽管没有一个元素最初包含多个位，但交换允许将所有三个位收集到一个数字中。 仅查看当前最大值的解决方案会错误地错过这种可能性。 

### 零的存在

 输入：```
1
3
1023 0 0
```运行 OR 是：```
1023
```输出：```
1023
```每个位的位置都已经存在于某个地方，所以它们都对答案有贡献。 现有的零可以作为最小元素，给出全部可能的差异。 

### 任何地方都不存在任何位

 输入：```
1
3
0 0 0
```运行或保持：```
0
```输出：```
0
```由于没有`1`位在任何位置，任何操作都不能创建位。 答案必须保持为零，算法会正确返回该值。
