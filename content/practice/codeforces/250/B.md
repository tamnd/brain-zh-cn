 ## 解决方案
 ## 问题理解

 完整形式的 IPv6 地址是由八个块组成的固定结构。 每个块代表 16 位，并精确地写入四个十六进制字符，必要时包括前导零。 这些块由冒号分隔，因此完全扩展的地址始终具有相同的长度模式，并且始终包含七个冒号。 

我们收到的输入是此类地址的缩写版本。 可能已经应用了两次独立的压缩。 首先，在每个块中，前导零可能已被删除，因此像这样的块`00ea`可能显示为`ea`。 其次，全为零的单个连续块可能已被双冒号替换`::`，代表一个或多个全零块。 重要的是，这个替换每个地址只能使用一次。 

任务是重建原始的完整八块表示。 这意味着我们必须恢复丢失的零块`::`并通过添加前导零将每个块恢复为恰好四个十六进制数字。 

限制很小，最多有 100 个地址，因此即使是简单的解析方法也很容易足够快。 主要的困难不是性能，而是处理模糊结构的正确性`::`，特别是区分被省略的零块属于哪里以及有多少个。 

一些边缘情况往往会破坏简单的解决方案。 如果输入正好是`::`，它代表八个零块，许多实现错误地将其视为空块或单个块。 如果`::`出现在开头或结尾时，分割的一侧变为空，这仍然必须正确解释。 另一个微妙的情况是确保扩展时`::`，无论周围出现多少个显式块，块的总数恰好变为八个，而不是更多或更少。 

## 方法

 完整的 IPv6 扩展问题主要是关于反转有损编码。 一个蛮力的想法是为每个尝试所有可能的零块放置`::`并验证哪个重建恰好产生八个块并匹配可见部分。 这将涉及到将字符串拆分`::`，猜测压缩了多少个零块，并检查一致性。 虽然概念上很简单，但它引入了不必要的组合推理，即使结构实际上唯一地确定了答案。 

关键的观察结果是，非`::`块已经固定。 一旦我们在以下位置分割字符串`::`，丢失块的数量完全取决于已经存在的块的数量。 由于最终地址必须恰好包含八个块，因此插入的零块的数量就是`8 - (left_blocks + right_blocks)`。 

这消除了任何歧义。 我们不再搜索，我们只计算需要多少个零块并将它们插入到正确的位置。 

重建八个块的完整列表后，每个块通过用前导零填充独立地扩展为四个十六进制数字。 此阶段块之间没有交互。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力猜测零放置 | O(指数每`::`) | O(1) | O(1) | 太慢/不必要|
 | 直接解析重构 | 每个地址 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个地址。 

1.检查字符串中是否包含`::`。 如果没有，则该地址已经明确列出了所有八个块。 我们只需要分割`:`并将每个块填充为四个字符。 
2.如果`::`存在，将字符串分成两部分：之前的所有内容`::`以及之后的一切。 每个部分可能是空的。 
3. 将两部分分开`:`到块列表中。 空部分会产生空列表，这对于前导或尾随等情况很重要`::`。 
4. 计算两个列表中已经存在的块数量。 让这成为`k`。 
5. 计算必须插入多少个零块`z = 8 - k`。 该值始终为非负数，因为保证输入有效。 
6. 将完整的块列表构造为：左块，然后`z`零块，然后是右块。 零块表示为`"0"`或空字符串，但将在下一步中标准化。 
7. 使用零填充将每个块转换为 4 个字符的十六进制字符串。 对于原始块和插入块都是统一执行的。 
8. 使用冒号连接所有八个块以形成最终的扩展 IPv6 地址。 

正确性来自于整个结构尺寸是固定的这一事实。 一旦我们知道明确存在多少个块，其余的必须是由以下引入的零块`::`，并且除了单个间隙之外，它们的放置没有自由度。 

保持的不变性是，在步骤 6 之后，构造的块列表始终具有由原始值或推断的零块填充的正好八个逻辑位置。 步骤 7 中的填充仅更改格式，而不更改结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def expand_ipv6(s: str) -> str:
    if "::" in s:
        left, right = s.split("::")

        left_blocks = left.split(":") if left else []
        right_blocks = right.split(":") if right else []

        # remove empty strings caused by edge cases like ":" splitting artifacts
        left_blocks = [b for b in left_blocks if b]
        right_blocks = [b for b in right_blocks if b]

        k = len(left_blocks) + len(right_blocks)
        z = 8 - k

        blocks = left_blocks + (["0"] * z) + right_blocks
    else:
        blocks = s.split(":")

    # pad each block to 4 hex digits
    res = []
    for b in blocks:
        res.append(b.zfill(4))

    return ":".join(res)

def main():
    n = int(input())
    out = []
    for _ in range(n):
        s = input().strip()
        out.append(expand_ipv6(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现直接反映了重建逻辑。 最微妙的部分是处理`::`当它出现在字符串的开头或结尾时，它是正确的，因为分割会产生空字符串，不能将其视为真正的块。 使用过滤可确保我们在确定丢失了多少个零块时仅计算实际的十六进制标记。 

填充步骤为`zfill(4)`就足够了，因为压缩后每个块都保证是有效的十六进制且最多四个字符长。 

## 工作示例

 ### 示例 1：`a56f::0124:0001:0000:1234:0ff0`我们分道扬镳`::`，给左=`a56f`，对=`0124:0001:0000:1234:0ff0`。 

| 步骤| 左块| 右块 | k | z | 最后的块|
 | --- | --- | --- | --- | --- | --- |
 | 解析 | [a56f] | [0124, 0001, 0000, 1234, 0ff0] | 6 | 2 | [a56f, 0, 0, 0124, 0001, 0000, 1234, 0ff0] |

 铺垫后，`a56f`变成`a56f`，零变为`0000`，其余保持正常化。 结果符合八个块的要求。 

这证实了计算的间隙大小正确地恢复了丢失的结构。 

### 示例 2：`::`这里整个地址被压缩。 

| 步骤| 左块| 右块 | k | z | 最后的块|
 | --- | --- | --- | --- | --- | --- |
 | 解析 | []| []| 0 | 8 | [0,0,0,0,0,0,0,0] |

 填充后，每个块都变成`0000`，产生完全为零的 IPv6 地址。 

这表明空分割正确地转换为零长度列表，并且该算法自然地填充了整个结构。

 ## 边缘情况

 对于输入`::`，该算法分为空的左列表和右列表。 计算出的丢失块计数变为八，因此插入了八个零块。 padding后全部变成`0000`，生成有效的完整 IPv6 地址。 

为了`::1:2:3:4:5:6:7`，左侧是空的，右侧包含七个块。 该算法在开始时插入一个零块，确保总数达到八个块。 然后填充会产生正确的完整表示。 

为了`1:2:3:4:5:6:7::`，则情况相反：右侧为空，并在末尾附加一个零块。 这表明，放置`::`自然地确定零是插入在开头还是末尾，无需特殊的大小写。
