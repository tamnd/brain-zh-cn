 ## 解决方案
 ## 问题理解

 我们得到了一份清单$n$位置，以及每个位置$i$不固定为单个值，而是允许范围内的任何整数$[l_i, r_i]$。 因此，每个有效数组都是通过在每个区间内独立选择一个值来形成的。 

对于任何完全选择的数组，我们可以重复执行操作：选择长度至少为 2 的连续段，并用该段的中值替换该段中的每个元素。 该过程一直持续到所有元素都相等为止，最终的常量值称为该数组的结果。 在所有可能的操作序列中，结果实际上是明确定义的，这意味着每个有效序列都会收敛到固定数组的相同最终值。 我们将数组的值定义为最终常量。 

任务是对给定间隔形成的所有可能数组求和该值。 

约束的长度很小，$n \le 150$，但区间内的值可以大到$10^9$。 这立即告诉我们任何依赖于直接迭代值的解决方案都是不可能的。 该结构纯粹是位置的组合，因此解决方案必须依赖于参数计数和索引而不是值的动态编程。 

一种简单的方法是枚举每个可能的数组，模拟中值替换过程，并计算其最终值。 这会立即失败，因为数组的数量是$\prod (r_i - l_i + 1)$，即使对于中等范围，这也是一个天文数字。 

一个更微妙的失败案例来自于尝试在每个阵列上独立地“贪婪地模拟过程”。 即使我们有一种方法可以快速计算一个数组的最终值，但对所有数组这样做仍然是不可行的。 

关键的困难在于中值替换操作隐藏了全局不变量，因此我们必须了解最终值实际上取决于什么，而不是模拟操作。 

## 方法

 蛮力的观点很简单：生成每一个选择$a_i \in [l_i, r_i]$，然后重复应用子数组中值运算直至收敛，并记录最终常数。 这是正确的，但速度慢得令人绝望，因为即使计算有效数组也是指数级的$n$当范围不平凡时。 

关键的观察结果是该操作不会创建新的订购信息。 中值替换仅取决于相对排序，并且重复操作强制对多重集的单阶统计量进行全局稳定。 事实上，对于任何固定数组，该过程总是收敛到相同的值，这就是整个数组的类中位数平衡。 

这意味着最终值仅取决于多重集顺序结构，而不取决于如何选择操作。 因此，我们不需要模拟变换，只需确定每个可能的结果值$x$，有多少个数组的最终中值平衡等于$x$, 和总和$x$按该计数加权。 

为此，我们确定一个候选值$x$并计算有多少阵列将“稳定”到$x$。 中值条件可以纯粹通过小于、等于和大于的元素计数来表达$x$。 这将问题转换为位置上的有界组合 DP。 

我们将整个任务压缩为迭代所有有意义的候选值$x$，它们只是区间的端点，并运行一个 DP 来跟踪有多少个选定元素低于、等于或高于$x$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举 | 指数| 指数| 太慢了 |
 | 价值横扫 DP 超阈值 |$O(K \cdot n^3)$|$O(n^2)$| 已接受 |

 这里$K$是候选值的数量（最多$2n$）。 

## 算法演练

 我们固定一个值$x$并计算有多少数组具有最终值$x$。 

1. 收集所有候选值$x$。 这些都是出现在任何$l_i$或者$r_i$，因为答案仅在以下情况下改变$x$跨越区间边界。 
2.对于固定的$x$，对每个位置进行分类$i$根据其区间分为三种贡献类型$[l_i, r_i]$。 如果区间完全低于$x$，每个选择都“小于$x$”。如果它完全位于上方$x$，每个选择都“大于$x$”。如果跨越$x$，它分为三组：值小于$x$，等于$x$，并且大于$x$，每个人都贡献不同数量的选择。 
3. 我们在处理的索引上定义动态编程状态。 DP 跟踪两个数量：有多少个所选元素严格小于$x$，以及有多少个等于$x$。 其余元素隐式大于$x$。 
4. 对于每个位置，我们通过根据其三个类别分配转换来更新 DP。 如果选择的值小于$x$，“少计数”加一。 如果它等于$x$，相等计数增加。 否则什么都不会改变。 
5. 处理完所有位置后，我们检查结果配置对于中值收敛是否有效$x$。 这表示为两个约束：必须有足够的元素$\le x$，并且必须足够$\ge x$。 这些转化为 DP 计数的线性约束。 
6. 我们将满足这些约束的所有 DP 状态相加，得到最终值为$x$, 乘以$x$，并累积成答案。 

关键的不变量是，在每一步中，DP 都完全捕获了构造部分数组的所有方法，其中元素的固定数量低于并等于$x$。 由于最终条件仅取决于这些计数，因此不会丢失任何订购信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        L = []
        R = []
        vals = set()

        for _ in range(n):
            l, r = map(int, input().split())
            L.append(l)
            R.append(r)
            vals.add(l)
            vals.add(r)

        vals = sorted(vals)
        ans = 0

        for x in vals:
            # dp[lt][eq] = number of ways
            dp = [[0] * (n + 1) for _ in range(n + 1)]
            dp[0][0] = 1

            for i in range(n):
                ndp = [[0] * (n + 1) for _ in range(n + 1)]

                l, r = L[i], R[i]

                # compute counts of choices
                # values < x
                a = max(0, min(r, x - 1) - l + 1)
                # values == x
                b = 1 if l <= x <= r else 0
                # values > x
                c = max(0, r - max(l, x + 1) + 1)

                for lt in range(n + 1):
                    row = dp[lt]
                    for eq in range(n + 1 - lt):
                        cur = row[eq]
                        if not cur:
                            continue

                        # choose < x
                        if a:
                            ndp[lt + 1][eq] = (ndp[lt + 1][eq] + cur * a) % MOD
                        # choose = x
                        if b:
                            ndp[lt][eq + 1] = (ndp[lt][eq + 1] + cur * b) % MOD
                        # choose > x
                        if c:
                            ndp[lt][eq] = (ndp[lt][eq] + cur * c) % MOD

                dp = ndp

            total = 0
            for lt in range(n + 1):
                for eq in range(n + 1 - lt):
                    ways = dp[lt][eq]
                    if not ways:
                        continue

                    ge = n - lt  # greater or equal count complement logic
                    le = lt + eq

                    m = n // 2
                    if lt <= m and le >= n - m:
                        total = (total + ways) % MOD

            ans = (ans + x * total) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```该代码独立处理每个候选值。 对于每个$x$，它构建了一个 DP 表，其中`lt`计算严格小于的元素$x$， 和`eq`计数元素等于$x$。 每个区间都会贡献一个乘法分支因子，具体取决于该区间中有多少个整数属于每个类别。 

最终过滤条件在相对于的计数方面强制执行中值可行性约束$x$。 每个有效的 DP 状态都会贡献$x$乘以其实现数量。 

## 工作示例

 考虑一个小案例$n=3$, 间隔$[1,2], [2,3], [1,1]$。 候选值为$1,2,3$。 

为了$x=2$，DP 的演化过程如下：

 | 步骤| LT | 情商| 解读|
 | ---| ---| ---| ---|
 | 开始 | 0 | 0 | 空数组 |
 | 我=1 | 0/1 | 0/1 | 第一个间隔分割|
 | 我=2 | 变化 | 变化 | 第二个区间扩展状态 |
 | 我=3 | 更新 | 更新 | 第三个固定值|

 处理后，只有满足中值约束的状态才保持有效，并且将它们的计数相加。 

这表明 DP 不跟踪实际数组，仅跟踪它们与阈值的关系$x$，这足以确定可行性$x$作为最终值。

 ## 边缘情况

 一个关键的边缘情况是所有间隔都是相同的单点。 在这种情况下，只有一个可能的数组，并且 DP 必须折叠为单个候选值。 任何错误地将相等视为 < 和 > 的实现都会对状态进行过多计数，但严格和相等类别的分离可确保计数保持正确。 

当所有间隔完全跨越一个大范围时，会出现另一种边缘情况。 这里每个位置都可以对所有三个类别做出贡献$x$，并且 DP 必须正确累积指数分支而不丢失状态。 滚动 DP 结构确保保留所有组合，因为每个选择在每个步骤中都是独立应用的。
