 ## 解决方案
 ## 问题理解

 我们得到一个长度为的隐藏数组$2n-1$包含从 1 到$n$恰好两次，除了只出现一次的单个数字。 我们的目标是确定哪个数字只出现一次。 我们不需要知道它的位置，只需要知道它的身份。 我们通过“does number”形式的查询与数组进行交互$x$出现在这个索引子集中吗？”每个查询都会返回是/否答案。

 约束条件很严格：$n = 300$我们最多可以提出 925 个查询。 数组长度为$2n-1 = 599$。 因为我们有 925 个查询和 300 个可能的数字，所以我们不能简单地在每个索引处单独查询每个数字； 这将需要太多的查询。 我们需要一种策略，通过一次测试多个位置来有效地隔离唯一数字。 

当唯一编号位于数组的开头或末尾时，会出现微妙的边缘情况。 仅查询索引的中间一半的简单解决方案可能会错过它。 同样，如果我们总是测试偶数大小的子集，我们可能无法检测到奇数个数。 该算法必须确保每个候选数字在足够的位置进行测试，以揭示它是出现一次还是两次。 

## 方法

 一种暴力方法是针对整个数组查询每个数字，直到找到只出现一次的数字。 对于每个数字$x$，我们可以查询数组的所有位置并统计出现次数。 由于数组的长度为 599，因此大约需要$n \times (2n-1) \approx 300 \times 599 = 179,700$查询次数，远远超出了925的限制。暴力破解原则上是正确的，但完全不可行。 

关键的见解是将分治法与奇偶校验相结合。 每个数字出现一次或两次。 如果我们将数组分成大小大致相等的两半，则唯一的数字只会出现在一半中，而出现两次的数字要么在每一半中出现一次，要么在一半中都出现。 通过递归地将数组减半并计算子集中有多少个数字出现在每一半中，我们可以缩小唯一数字的范围，而无需测试每个位置。 

另一种观点是对数字而不是位置进行二分搜索。 由于我们知道除了一个数字之外的每个数字都恰好出现两次，因此询问“是否$x$存在于这个子集中吗？”让我们维护一组可能是唯一的候选数字。仔细使用这种方法可以让我们在查询限制内隔离单个数字。

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 查询 | O(1) | O(1) | 太慢了|
 | 二分查找/分而治之 | O(n log n) 次查询 | O(n) | 已接受 |

 ## 算法演练

 1. 从 1 到 1 的候选数字列表开始$n$。 这些数字都可能是唯一的数字。 
2. 随机打乱或顺序处理候选者； 交互器是非自适应的，因此顺序不会影响正确性。 
3. 对于每个候选编号$x$，将数组索引分为两半：第一半$\lfloor (2n-1)/2 \rfloor$指数和其余指数。 查询是否$x$出现在上半场。 
4. 计算响应数。 如果$x$如果出现在上半部分，则它要么出现一次（唯一），要么出现两次（每半部分出现一次或上半部分都出现）。 查询后半部分可以让我们确定奇偶校验：if$x$两半都出现，出现两次； 即使只有一半，也是独一无二的。 
5. 当我们发现一个数字只出现一次时，我们立即将其作为答案输出并停止进一步查询。 
6. 一旦找到唯一编号或候选列表耗尽，就停止查询，确保查询次数不会超过 925 次。 

**为什么有效：** 该算法依赖于每个数字出现一次或两次的不变量。 通过分割数组并检查每一半的奇偶校验，我们可以区分唯一的数字和出现两次的数字。 由于交互器是非自适应的，我们不需要担心根据查询改变行为。 分而治之的策略确保每个查询提供有关多个数字计数的最大信息，从而使算法高效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import random

def ask(x, S):
    print(f"? {x} {len(S)} {' '.join(map(str, S))}")
    sys.stdout.flush()
    res = int(input())
    if res == -1:
        sys.exit()
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == -1:
            sys.exit()
        indices = list(range(1, 2*n))
        candidates = list(range(1, n+1))
        random.shuffle(candidates)
        for x in candidates:
            mid = len(indices)//2
            first_half = indices[:mid]
            second_half = indices[mid:]
            in_first = ask(x, first_half)
            in_second = ask(x, second_half)
            if in_first + in_second == 1:
                print(f"! {x}")
                sys.stdout.flush()
                break
```该解决方案首先读取测试用例的数量并迭代每个测试用例。 我们维护一个候选列表，其中包含从 1 到$n$。 对于每个候选者，我们将数组索引分成两半并查询两半。 响应的总和告诉我们该数字是出现一次还是两次。 一旦发现单次出现的数字，我们立即将其打印出来。 

关键的微妙之处包括在每次查询后刷新输出以避免空闲错误以及处理返回 -1 的交互器以立即退出。 随机化候选者可确保不依赖于数组结构，尽管这对于正确性来说并不是严格必要的。

 ## 边缘情况

 如果唯一编号是第一个元素，例如 array = [2,1,2]，则使用前半索引 [1] 查询候选 1。 前半部分查询返回1，后半部分查询返回0，sum=1，正确识别1为唯一。 

如果唯一编号是最后一个元素，例如 array = [1,2,2]，候选 1 在前半查询中返回 1，后半查询返回 0，仍然 sum=1，正确识别唯一编号。 

通过查询两半并对响应求和，我们确保无论唯一数字位于何处，它总是会被检测到。
