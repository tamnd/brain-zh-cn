 ## 解决方案
 ## 问题理解

 我们被要求分析这样一种情况：两个玩家，爱丽丝和鲍勃，依次从商店挑选物品。 从我们的角度来看，每个对象都有一个价值，每个玩家都有自己的偏好顺序。 轮到他们时，玩家总是会选择仍然可用的最喜欢的对象。 最后，爱丽丝将拥有她购买的物品的子集，任务是根据我们的估价计算她可以获得的物品价值的最大总和。 

输入为我们提供了多个测试用例。 每个测试用例指定对象的数量、它们的值、Alice 和 Bob 的偏好顺序。 每个测试用例的输出都是一个整数：Alice 可以在所有有效购买序列中获得的最大总和。 

限制很严格。`n`每个测试用例最多可以达到 2×10^5，所有测试用例的总和也达到 2×10^5。 这排除了每个测试用例比大约 O(n log n) 更糟糕的任何解决方案。 模拟 Alice 和 Bob 选择的每种可能的交错的朴素暴力是完全不可行的，因为可以获取对象的方式数量随 n 呈阶乘增长。 

不明显的边缘情况包括 Alice 的最高偏好全部为低值或负值、Bob 选择可能阻碍她的对象或所有值均为负值的序列。 例如，如果`v = [-5, -10, 1]`,`a = [3,1,2]`,`b = [1,2,3]`，Alice 应该只选择对象 3 以使总和最大化。 一种粗心贪婪的方法假设她总是首先得到她的最高优先选择，可能会做出不同的选择并给出较低的总和。 

## 方法

 蛮力方法在概念上很简单。 对于每个测试用例，您可以生成所有可能的购买顺序，模拟 Alice 和 Bob 的回合，并跟踪 Alice 最终获得的对象的值总和。 这是有效的，因为它忠实地模拟了每个场景，但它是 O(n!)，对于 n 高达 2×10^5 来说太慢了。 

关键的洞察力来自逆向思维。 请注意，与模拟所有序列不同，对爱丽丝的总和重要的唯一决定是她可以在鲍勃拿走她喜欢的物品之前拿走它们的时刻。 每个对象都可以通过 Alice 或 Bob 最早选择的对象来表征。 如果鲍勃比爱丽丝早选择一件物品，她就无法得到它。 如果爱丽丝先选择，她最终总是可以选择的。 

我们可以使用动态规划对 Alice 的偏好列表中的子集或位置进行建模。 让我们定义一下`dp[i]`如果爱丽丝只考虑她的顶部，她可以获得的最大总和`i`首选项目。 当我们处理她的时候`i`-th 偏好，我们决定鲍勃是否会在她之前接受它。 这将问题简化为按照 Alice 偏好的顺序进行线性扫描，跟踪哪些对象仍然可用。 使用一个数组来标记Bob最早选择的对象，我们可以快速判断一个对象对于Alice来说是否安全，并相应地累积最大和。 这将每个测试用例的复杂性降低到 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个对象，记录其在 Bob 偏好列表中的位置。 这使我们能够准确地知道鲍勃相对于爱丽丝的选择何时会选择它。 
2. 按顺序迭代 Alice 的偏好列表。 对于每个对象，检查其在 Bob 列表中的位置。 
3. 为 Bob 获取对象的最早索引维护一个运行变量。 如果 Bob 的索引位于 Alice 序列中当前选择之前，则跳过该对象，因为 Bob 会选择它。 
4. 否则，将对象的值添加到累积和中。 
5. 在迭代结束时返回总和，它表示 Alice 在该测试用例中可以获得的最大总和。 

保持的不变性是，在迭代中的任何点，我们都准确地考虑到了 Alice 在 Bob 阻止之前可以安全挑选的所有对象。 这保证了不会错过任何可能的更高总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        v = list(map(int, input().split()))
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        # 0-based indexing
        a = [x-1 for x in a]
        b = [x-1 for x in b]
        
        # Position map: where does Bob pick each object
        pos_bob = [0]*n
        for idx, obj in enumerate(b):
            pos_bob[obj] = idx
        
        # Track the maximum sum Alice can get
        max_sum = 0
        # Current earliest Bob's pick that can block Alice
        min_bob_pos = n
        for obj in reversed(a):
            if pos_bob[obj] < min_bob_pos:
                max_sum += v[obj]
                min_bob_pos = pos_bob[obj]
        
        print(max_sum)

if __name__ == "__main__":
    solve()
```该解决方案首先将首选项列表转换为基于 0 的索引。 它为 Bob 创建了一个位置图，这样我们就可以快速检查他是否会在 Alice 之前选择一个对象。 通过反向迭代 Alice 的列表，我们确保选择她可以安全获取的对象，而不会被 Bob 阻止。 更新中`min_bob_pos`确保我们只为爱丽丝可以保护的物品积累价值。
