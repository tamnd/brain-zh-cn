 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，需要计算有多少个连续的子数组是“神奇的”。 当子数组的最小值等于最大值时，它是神奇的。 

仅当子数组内的每个元素都相同时，最小值和最大值才能相等。 这一观察完全改变了问题。 我们不考虑任意子数组，而只关心相同数量的连续块。 

例如，在数组中：```
2 1 1 4
```连续的等值块是：```
[2]
[1 1]
[4]
```每个单元素子数组都是神奇的，而块`[1 1]`也贡献了子数组`[1, 1]`长度为2。 

数组长度可以大到$10^5$。 检查每个子数组的二次算法将粗略地检查：$$\frac{n(n+1)}{2}$$子数组，变成关于$5 \times 10^9$什么时候$n = 10^5$。 这远远超出了 2 秒的限制。 

这些约束强烈表明我们需要一个线性或近线性的解决方案。 

有一些容易被忽略的边缘情况。 

考虑一个所有元素都不同的数组：```
5
1 2 3 4 5
```正确答案是`5`，因为只有单元素子数组符合条件。 如果只检查端点，粗心的实现可能会意外地计算更长的范围。 

现在考虑一个所有元素都相等的数组：```
4
7 7 7 7
```每个子数组都是神奇的。 答案是：$$\frac{4 \cdot 5}{2} = 10$$有缺陷的实现可能只对最大相等段进行一次计数，而不是对其中的所有子数组进行计数。 

另一个微妙的情况是当相同的块出现多次时：```
6
1 1 2 2 2 1
```最后一个`1`不与第一个块连接`1`s 因为子数组必须是连续的。 正确的答案来自于独立对待每个相等的段：```
2 + 6 + 1 = 9
```在哪里：$$\frac{2 \cdot 3}{2} = 3$$对于第一个块，$$\frac{3 \cdot 4}{2} = 6$$对于中间块，

 和$$1$$对于最后一个元素。 

## 方法

 蛮力的想法很简单。 枚举每个可能的子数组，计算其最小值和最大值，如果相等则计数。 

对于子数组`a[l:r]`，条件：```
min(a[l:r]) == max(a[l:r])
```意味着所有元素都是相同的。 

一个简单的实现将使用三个嵌套操作：

 1. 选择左端点。 
2. 选择正确的端点。 
3. 扫描子数组以计算最小值和最大值。 

那成本$O(n^3)$。 

即使我们逐步优化最小值和最大值，我们仍然会检查所有$O(n^2)$子数组。 和$10^5$元素，这仍然太慢了。 

关键的观察是，当且仅当子数组中的每个元素都相等时，子数组才是神奇的。 

这意味着神奇的子数组永远不会在不同的值之间交叉。 它们完全存在于连续的相同数字中。 

假设我们有一个长度为$k$:```
x x x x ... x
```该块内的每个子数组都是神奇的。 

length- 内的子数组数量$k$段是：$$\frac{k(k+1)}{2}$$因为：

 - 有$k$长度为 1 的子数组，
 -$k-1$长度为2，
 -$k-2$长度为3，
 - 等等。 

所以整个问题简化为：

 1. 找出最大连续相等线段的长度。 
2. 总和$\frac{k(k+1)}{2}$覆盖所有细分市场。 

我们可以在跟踪当前段长度的同时扫描一次数组。 这给出了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n2) 到 O(n3) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数组大小和数组本身。 
2. 将答案变量初始化为`0`。 
3. 开始从左到右扫描数组，同时保持当前块的长度相等。 
4. 将当前块长度设置为`1`对于第一个元素。 
5. 对于每个下一个元素：

 1. 如果等于前一个元素，则通过增加长度来扩展当前块。 
2. 否则，前一个区块已经结束。 添加：$$\frac{len \cdot (len + 1)}{2}$$到答案，然后开始一个新的长度块`1`。 

该公式对完全位于该等值段内的所有子数组进行计数。 

1. 循环结束后，添加最后一个块的贡献，因为当我们仍在段内时数组可能会结束。 
2. 打印总答案。 

### 为什么它有效

 每个神奇的子数组都完全由相等的值组成。 这样的子数组必须完全位于一个最大连续相等的段内。 

对于一段长度$k$，其中每一个可能的连续子数组都是神奇的，并且恰好有：$$\frac{k(k+1)}{2}$$其中。 

该算法将数组划分为最大相等的段，并对每个段内的所有子数组进行一次计数。 没有遗漏神奇的子数组，也没有计算无效的子数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = 0
length = 1

for i in range(1, n):
    if a[i] == a[i - 1]:
        length += 1
    else:
        ans += length * (length + 1) // 2
        length = 1

ans += length * (length + 1) // 2

print(ans)
```The program keeps track of the current contiguous segment of equal values.

 变量`length`存储当前段的大小。 每当下一个值与前一个值匹配时，我们就扩展该段。 否则，该段结束，我们添加其贡献。 

公式：$$\frac{k(k+1)}{2}$$实现为：```
length * (length + 1) // 2
```整数除法是必要的，因为结果必须保持整数。 

循环后的最后添加很容易被忘记。 没有它，最后一段永远不会对答案做出贡献。 

该解决方案仅使用恒定的额外内存并扫描一次数组。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    length = 1

    for i in range(1, n):
        if a[i] == a[i - 1]:
            length += 1
        else:
            ans += length * (length + 1) // 2

    ans += length * (length + 1) // 2

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

 ## 边缘情况

 考虑每个值都不同的情况：```
5
1 2 3 4 5
```该算法创建五个长度为 1 的独立段。 

他们的贡献是：```
1 + 1 + 1 + 1 + 1 = 5
```不再对子数组进行计数，因为只要值发生变化，段就会立即中断。 

现在考虑一个所有值都相等的数组：```
4
7 7 7 7
```扫描永远不会中断该段。 在最后：```
length = 4
```该算法添加：$$\frac{4 \cdot 5}{2} = 10$$它匹配所有可能子数组的总数。 

最后，考虑分离的相等块：```
6
1 1 2 2 2 1
```该算法处理：```
[1 1]
[2 2 2]
[1]
```独立。 

第一个和最后一个`1`永远不会合并，因为`2`s 破坏连续性。 这正确地防止了对无效子数组的计数，例如：```
1 1 2 2 2 1
^           ^
```这并不神奇。
