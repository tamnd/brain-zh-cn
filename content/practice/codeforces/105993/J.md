 ## 解决方案
 ## 问题理解

 在 Codeforces 105993J 中，画布是一个无限网格。 一些像素已经着色，我们希望使用尽可能少的新着色操作使给定矩形的每个单元都着色。 可以通过对地面行上的任何单元格进行着色来创建新像素`y = 1`，或者从一个已经着色的像素传播到它的四个邻居之一。 

目标矩形由其水平间隔定义`[X1, X2]`和垂直间隔`[Y2, Y1]`。 输入最多可达`100000`已经着色的像素。 坐标可以大到`10^9`，因此构建网格或模拟传播是不可能的。 对于一秒的时间，预期的解决方案必须与给定像素的数量接近线性。 

关键的困难在于矩形可能很大，但只有现有的像素才重要。 矩形本身的面积可达`10^18`，因此我们必须推断出有多少单元格已经空闲，以及需要在矩形之外添加多少单元格才能连接到矩形。 

一些边缘情况很容易被忽略。 如果一个像素已经在矩形内部，则它可以节省一次操作，因为它永远不需要创建。 

例如：```
1
3 4 3 3
3 4
```该矩形包含一个单元格，并且该单元格已经着色。 答案是：```
0
```仅搜索进入矩形的方法的解决方案可能会错误地添加一个操作。 

另一种情况是现有像素从外部接触矩形。 

例子：```
1
3 4 3 3
3 5
```现有像素位于矩形的正上方。 我们可以传播一次`(3,4)`。 答案是：```
1
```新像素位于矩形内部，因此它已被算作缺失的矩形单元之一。 将连接计算为额外操作会给出错误的结果。 

最后一个棘手的情况是没有现有像素。 

例子：```
0
4 4 4 4
```唯一需要的细胞是`(4,4)`。 我们必须着色`(4,1)`,`(4,2)`,`(4,3)`， 和`(4,4)`，所以答案是：```
4
```地面操作创建第一个像素，随后的每个像素都是扩展。 

## 方法

 一个简单的方法是模拟增长。 我们可以尝试每一个可能的地面位置，从每个现有像素展开，并计算有多少细胞变成彩色。 这是正确的，因为它确实模拟了允许的操作。 问题是矩形可能包含最多`10^18`细胞，所以即使接触每个细胞一次也是不可能的。 

有用的观察结果是，矩形内每个缺失的单元格最终都必须通过某种操作来着色。 没有办法支付费用。 唯一可能的优化是在传播到达矩形之前减少矩形外部着色的额外单元格的数量。 

如果矩形内已经有一个彩色像素，则无需任何外部工作即可填充整个矩形。 如果我们外面有一个彩色像素，我们只需将它连接到矩形即可。 最便宜的连接是到矩形的最短曼哈顿路径。 对于最初着色的像素，该路径的最后一步进入矩形，因此只有最后一步之前的单元格是额外的。 

地面行的工作原理略有不同。 地面操作会创建一个新的彩色像素，因此从地面位置到矩形的所有单元格都会做出贡献。 最佳地面位置始终与矩形水平对齐，这会产生额外的成本`Y2 - 1`。 

答案是矩形中缺失单元的数量加上最小的额外连接成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(矩形面积) | O(矩形面积) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个最初着色的像素存储在一个集合中。 该集合避免了对重复像素进行两次计数，并让我们计算目标矩形内有多少已着色的单元格。 
2. 计算矩形面积为`(X2 - X1 + 1) * (Y1 - Y2 + 1)`。 减去矩形内现有像素的数量。 这些是仍需要着色的细胞。 
3. 初始化与地面操作的最佳额外连接成本。 选择直接位于矩形任何列下方的地面单元格需要对该列中矩形下方的所有单元格进行着色。 
4. 对于矩形外部的每个现有像素，计算其到矩形最近单元的曼哈顿距离。 如果距离为零，则该像素已经在内部。 否则，最后一步进入矩形，因此外部额外的单元格数量为`distance - 1`。 
5. 将最小额外连接成本与缺失矩形单元的数量相加。 这是新像素的最小总数。 

为什么有效：每个解决方案都必须为每个缺失的矩形单元格着色，因为没有任何操作可以在不付费的情况下为单元格着色。 剩下的唯一选择是如何将第一个彩色像素放入矩形中。 该算法检查这种连接的每个可能的来源，包括所有初始像素和接地行。 与源的最短可能连接是曼哈顿路径，该算法精确计算该路径上位于矩形之外的单元格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    X1, Y1, X2, Y2 = map(int, input().split())

    inside = 0
    seen = set()
    points = []

    for _ in range(n):
        x, y = map(int, input().split())
        if (x, y) not in seen:
            seen.add((x, y))
            points.append((x, y))
            if X1 <= x <= X2 and Y2 <= y <= Y1:
                inside += 1

    area = (X2 - X1 + 1) * (Y1 - Y2 + 1)
    answer = area - inside

    extra = Y2 - 1

    for x, y in points:
        if X1 <= x <= X2 and Y2 <= y <= Y1:
            continue

        if x < X1:
            dx = X1 - x
        elif x > X2:
            dx = x - X2
        else:
            dx = 0

        if y < Y2:
            dy = Y2 - y
        elif y > Y1:
            dy = y - Y1
        else:
            dy = 0

        dist = dx + dy
        extra = min(extra, dist - 1)

    print(answer + extra)

if __name__ == "__main__":
    solve()
```该代码首先删除重复项，因为一个像素只能着色一次。 变量`answer`存储填充矩形本身不可避免的成本。 

变量`extra`从使用地面行的成本开始。 对于每个现有像素，代码计算到矩形的曼哈顿距离。 当像素的列已经位于矩形内部时，水平距离为零，垂直方向也是如此。 

减一是微妙的部分。 路径的最后一步落在矩形内，并且该单元格已包含在缺失的矩形计数中。 只有前面的单元格是额外的操作。 

所有算术都使用Python整数，因此大坐标范围和矩形区域不会溢出。

 ## 边缘情况

 当像素已位于矩形内时，算法会将其从缺失单元格计数中排除。 对于输入：```
1
3 4 3 3
3 4
```面积为 1，内部计数为 1，因此基本成本为零。 连接成本并不重要，因为目标已经满足。 

当像素直接位于矩形外部时，曼哈顿距离为 1。 该算法减一并得到零个额外单元格。 缺失的矩形单元本身通过扩展操作着色，并且已经包含在基本成本中。 

对于距离地面较远的矩形，如：```
0
4 4 4 4
```地面成本是`Y2 - 1 = 3`。 该矩形缺少一个单元格，给出`1 + 3 = 4`。 这与从地面到目标的垂直柱的实际着色顺序相匹配。
