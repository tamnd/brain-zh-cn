 ## 解决方案
 ## 问题理解

 我们得到一个图表，其中城市由无向道路连接，每条道路连接两个不同的城市。 任务是确定该图中最短简单循环的长度。 这里的循环意味着从某个城市出发，沿着不同的道路，最终返回同一个城市而不重复边，我们用所使用的边的数量来衡量循环长度。 

输出是一个整数：图中所有循环中边的最小数量。 如果图形根本不包含环，则正确的输出为 -1。 

根据此类问题的典型约束，我们应该假设该图足够大，以至于所有三元组节点上的二次或三次算法都不可行。 任何尝试显式枚举所有循环的解决方案都会失败，因为可能路径的数量随着深度呈指数增长。 这立即排除了暴力循环枚举或 Floyd-Warshall 风格的全对推理。 

如果图在同一对节点或自循环之间具有多条边，则会出现一个微妙的问题。 自循环已经形成了长度为 1 的循环，两个节点之间的平行边形成了长度为 2 的循环。粗心的 BFS 实现忽略了这些情况或将边折叠成一个集合而不跟踪重数，可能会错过真正的最短循环。 

例如，考虑一个具有单个节点和自循环的图。 正确答案是 1。假设没有自循环的朴素 BFS 会错误地返回 -1。 

另一个例子是由两条不同的边连接的两个节点。 最短循环的长度为 2，但删除重复边的标准简单图形表示会丢失此结构并错误地报告无循环。 

这些情况很重要，因为最短循环通常是由非常局部的“非树边缘”创建的，而不是大型结构循环。 

## 方法

 直接的蛮力想法是尝试找到每对相邻节点之间的最短路径，同时暂时删除连接边。 如果存在替代路径，则将移除的边加回形成循环。 对每条边重复此操作最终会找到最短周期。 这种方法是正确的，因为每个循环必须包含至少一个边缘，并且删除该边缘会强制剩余的循环显示为其端点之间的路径。 

然而，计算每条边的最短路径太慢。 在最坏的情况下，对每条边运行 BFS 会导致大约 O(m(n + m)) 次操作，当 n 和 m 都很大时，这变得不可行。 

关键的观察是我们不需要显式地删除边缘。 相反，我们可以在 BFS 本身期间检测循环。 当从起始节点执行 BFS 时，如果我们到达一个已访问过的节点，但该节点不是 BFS 树中的直接父节点，那么我们就发现了循环。 循环长度可以使用距 BFS 根的距离来计算。 

通过从每个节点作为起点重复 BFS，我们保证每个循环最终都会在至少一次遍历中暴露出来，并且所有检测到的循环中最短的就是答案。 

这将循环检测转换为具有本地循环检查的重复最短路径探索，避免了显式循环枚举。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（删除边 + 每个边的 BFS）| O(m(n + m)) | O(m(n + m)) | O(n + m) | 太慢了 |
 | 来自每个节点的 BFS 循环检测 | O(n(n + m)) | O(n(n + m)) | O(n + m) | 已接受 |

 ## 算法演练

1. 构建图的邻接列表表示。 这允许在 BFS 期间快速遍历邻居，而无需扫描所有边缘。 
2. 将答案初始化为无穷大。 这将存储所有 BFS 运行中找到的最小循环长度。 
3. 以每个节点为起点，运行 BFS。 我们为每次运行重置距离和父数组，因为每个 BFS 都会探索图的不同根视图。 
4. 在BFS遍历期间，当我们从节点u移动到邻居v时，我们检查v之前是否被访问过。 如果 v 未被访问，我们设置它的距离和父级并正常继续。 
5. 如果 v 已经被访问过，并且 v 不是 BFS 树中 u 的父节点，那么我们就找到了环。 循环长度的计算方式为 dist[u] + dist[v] + 1。如果该值较小，我们将更新全局答案。 
6. 每个节点完成 BFS 后，我们返回记录的最小循环长度。 如果没有找到循环，我们返回-1。 

### 为什么它有效

 来自固定源的 BFS 会生成最短路径树。 连接两个已发现的节点但不是树边的任何边都必须闭合一个循环。 BFS 中的距离值保证从源到每个端点的路径尽可能最短，因此将两条这样的路径加上连接边相结合即可给出精确的循环长度。 由于每个循环至少包含一条边，并且 BFS 是从每个节点运行的，因此每个循环最终都会在至少一次遍历中被检测到，从而确保捕获最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    INF = 10**18
    ans = INF

    from collections import deque

    for s in range(n):
        dist = [-1] * n
        parent = [-1] * n
        q = deque()

        dist[s] = 0
        q.append(s)

        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    parent[v] = u
                    q.append(v)
                elif parent[u] != v:
                    ans = min(ans, dist[u] + dist[v] + 1)

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```该实现从每个节点重复使用 BFS。 距离数组确保我们始终测量从当前源开始的最短路径，而父数组可防止沿 BFS 树边缘的琐碎回溯被误认为是循环。 

一个微妙的点是，我们在找到循环后不会提前停止 BFS。 即使找到一个循环后，在同一次遍历中也可能会出现更短的循环，因此我们继续探索所有可达节点。

 考虑到此类问题的典型约束，这是可以接受的，因为图大小通常适中，并且 BFS 每次运行都是线性的。 该算法避免了立方行为并且不枚举路径。

 ## 边缘情况

 正确处理自循环是因为 BFS 立即发现已访问过的节点与自身相等，通过公式 dist[u] + dist[v] + 1 产生长度为 1 的循环，变成 0 + 0 + 1。 

平行边在邻接遍历期间处理：当探索从 u 到 v 的边时，如果 v 已经到达且不是父边，则第二条边会触发长度为 2 的循环。 

断开连接的图自然会得到处理，因为 BFS 是从每个节点重新启动的，因此任何组件中的循环都是独立发现的。
