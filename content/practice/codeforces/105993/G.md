 ## 解决方案
 ## 问题理解

 我们正在使用两个相同尺寸的二进制网格。 一个网格被固定为目标配置，而另一个网格开始时完全为空。 修改空网格的唯一方法是通过一次操作，该操作触及一个选定的单元格，同时引起网格其余部分的结构变化。 

每个操作都会将所选单元格从 0 翻转到 1 或从 1 翻转到 0，然后对除包含该所选单元格的行之外的每一行应用循环右移。 重复此操作多次，我们必须将最初的空网格精确地转换为目标网格。 

任务不仅是决定这是否可行，而且是构建一系列操作，以使用最少的移动次数实现目标。 

关键的困难在于每次操作都会产生全局副作用。 尽管我们只显式修改一个单元格，但大多数行都会右移，这意味着任何先前设置的模式都可以在后续操作后水平移动。 这使得问题感觉像是网格构建和跨行排列控制的混合。 

这些约束允许网格最大为 1000 x 1000，测试用例的总网格大小也以 1000 x 1000 为界。这排除了任何试图在整个网格上简单地模拟每个操作的方法，因为单个操作将花费 O(M) 来移动行，并且在最坏的情况下最多 10^6 次操作已经太慢了。 我们被推向一种结构，其中每个单元最多被处理一次或以严格控制的模式被处理。 

一些边缘情况很容易处理不当。 

具有单个单元格的网格很简单，但它暴露了实现是否正确处理零操作。 例如，“0”的 1×1 目标需要输出 0，任何通过操作“修复”它的尝试都会错误地翻转它。 

单行网格的行为有所不同，因为没有“其他行”需要移动。 在这种情况下，每个操作仅翻转一个单元，因此问题简化为独立的位固定。 假设移动总是发生的天真的解决方案会错误地过度计算或模拟不存在的运动。 

具有多行但单列的情况也有不同的行为，因为移位没有明显的效果，但操作仍然翻转选定的单元格。 忽视这种退化会导致对国家如何演变的错误推理。 

## 方法

 直接的强力解释是逐个状态地模拟过程。 从当前网格中，我们选择一个单元格，翻转它，然后对所有其他行应用循环移位，并递归直到网格与目标匹配。 这在原则上是正确的，因为它准确地反映了操作的定义。 然而，由于行移位，每个步骤都会修改 O(N·M) 个单元，并且分支因子是 O(N·M) 个可能的移动。 即使探索这个空间的一小部分也会呈指数级增长，这使得它在非常小的网格之外是不可行的。 

重要的观察结果是行移位是确定性的且均匀的。 每次操作，除了一行之外的每一行都向右移动一个位置。 这意味着在 k 次操作之后，每一行实际上都已向右旋转 k 次，除非该行被选为枢轴并暂时“重置”该步骤的移位。 我们可以考虑相对对齐，而不是跟踪完整的网格状态：当我们决定修复单元格 (i, j) 时，我们可以在 i 行对齐时选择操作，以便 j 列当前在累积移位下处于“活动”状态。

这将问题转化为位置的调度问题。 如果我们仔细决定顺序，则可以独立处理每一行，因为移位仅影响相对列位置，而不影响在受控扫描中纠正奇偶校验的能力。 最佳结构是逐行处理，同时保持一致的旋转状态，以保证每个单元格在正确的列位置时准确固定。 

关键的简化是我们不需要模拟任意交错。 每行从左到右的贪婪扫描，再加上保持每行的有效旋转偏移量，足以确保我们始终可以决定单元格在与目标位置对齐时是否需要翻转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 指数| O(N·M) | 太慢了 |
 | 具有旋转跟踪功能的行式建设性扫描 | O(N·M) | O(N·M) | 已接受 |

 ## 算法演练

 我们为每行维护一个概念性的旋转偏移量，表示相对于其原始状态已对该行应用了多少循环移位。 核心思想是我们总是逐行决定操作，并且在每一行中我们以固定的逻辑顺序遍历列，使用偏移量来解释当前哪个实际单元格与每个目标列对齐。 

1. 将所有行初始化为空并将其旋转偏移设置为零。 空网格对应于全零，并且尚未旋转任何行。 
2. 从上到下处理行。 修复行顺序的原因是，一旦我们决定对一行进行操作，我们就可以避免由于其他行的后续移位而重新引入不一致。 
3. 对于当前行，从左到右扫描列。 在逻辑列 j 处，计算应用该行的当前旋转偏移量后的实际列位置。 这告诉我们进化网格中的哪个单元对应于目标位置。 
4. 如果目标网格在该位置需要 1，我们将执行选择该行和计算列的操作。 这会在单元与目标配置对齐的同时将单元翻转到正确的状态。 
5. 每次操作后，通过将偏移量加一来隐式更新所有其他行的旋转状态。 我们不是进行物理转移，而是将其作为全局转移计数器进行跟踪并相应地调整比较。 
6. 继续，直到处理完该行中的所有单元格，然后移至下一行。 每行一旦完成就会被有效锁定，因为进一步的操作总是以受控方式应用，从而保留已经匹配的结构。 

中心不变量是，在处理行 i 之前的任何时刻，i 上面的所有行都已经在各自的旋转偏移下匹配其目标配置。 处理第 i 行时，当前偏移量可确保我们看到该行的一致循环视图，并且每个决策都是在目标 1 与活动列对齐时准确做出的。 由于每个操作仅以可预测的方式改变相对对齐，因此先前固定的行在其不断变化的偏移下保持与其目标一致。 这可以防止早期的工作因后续操作而失效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        ops = []
        # rotation offset for each row (logical right shifts applied)
        shift = 0

        # We process row by row
        for i in range(n):
            # current row's effective shift relative to target
            row_shift = 0

            for j in range(m):
                # actual column in original grid after shifts
                col = (j - row_shift) % m

                # We want to decide if we need a flip operation
                if grid[i][j] == '1':
                    # perform operation at (i, col)
                    ops.append((i + 1, col + 1))

                    # after operation, all other rows shift right by 1
                    shift = (shift + 1) % m

                    # this row effectively cancels shift because it is chosen
                    row_shift = shift

        print(len(ops))
        for r, c in ops:
            print(r, c)

if __name__ == "__main__":
    solve()
```该实现保留一个全局移位计数器，表示应用于所有非选定行的累积右旋转。 当我们选择第 i 行中的一个单元格时，该行将被排除在移位之外，因此我们在操作后将其本地视图同步回全局状态。 

最微妙的部分是确保索引的一致性。 操作中使用的列必须反映当前的对齐方式，而不是原始的静态网格位置。 混合这两种视图是此类构造问题中产生相差一错误的典型来源。

 考虑一个简单的情况，单行长度为 3，目标为“101”。

 该跟踪显示，移位仅影响每次操作后列对齐方式的变化，而不影响存储完整的网格状态。

 目标：```
101
010

| 步骤| 行| j | 班次 | 行动|

 这演示了相同的全局移位如何为每行创建不同的有效列映射，这正是构造所利用的。

 ## 边缘情况

 1×1 网格揭示了实现是否尊重不需要任何操作。 由于没有任何转变会影响任何东西，所以正确的答案就是零操作，任何应用该操作的尝试都会立即破坏目标。 

单行网格是另一种退化情况。 没有“其他行”需要移动，因此状态永远不会旋转。 该算法仍然有效，因为移位变得无关紧要，但是总是增加全局移位的粗心实现会错误地错位索引并产生错误的翻转。 

除单个孤立值外所有值均为零的网格测试算法是否避免级联不必要的操作。 由于每次翻转都会触发一次转变，过于急切的策略会累积不需要的转变并导致未来的运营错位。 逐行扫描避免了这种情况，因为它仅在遇到所需的转换时才起作用，从而使操作数量保持最少。
