 ## 解决方案
 ## 问题理解

 每个护身符都是一个`2 x 2`充满数字的正方形`1`到`6`。 我们可以将其视为四个单元格：```
a b
c d
```如果两个护身符可以旋转到另一个护身符中，则它们属于同一堆。 禁止翻转，只能旋转`90°`,`180°`， 或者`270°`是允许的。 

输入会给出几个护身符。 每个护身符都写成两个长度的字符串`2`，并且连续的护身符之间有一条分隔线`"**"`。 任务是计算出现了多少种不同的旋转模式。 

限制很小。 最多有`1000`护身符，每个护身符只包含四个值。 甚至一个`O(n²)`比较方法可以在限制内轻松运行，因为`1000² = 1,000,000`配对检查，每次检查仅检查四个单元格。 尽管如此，如果我们将每个护身符简化为唯一的规范表示并将这些表示存储在一个集合中，问题就会变得更加清晰。 

棘手的部分是正确处理旋转。 一个常见的错误是仅比较原始方向。 例如：```
12
34
```和```
31
42
```实际上是相同的护身符，因为顺时针旋转第一个护身符会得到第二个护身符。 

当多次旋转产生相同的排列时，会出现另一种微妙的情况。 考虑：```
11
11
```每次旋转都是相同的。 尝试计算不同旋转而不是不同护身符的粗心实现可能会意外地过度计数。 

错误的另一个来源是读取分隔线。 最后的护身符没有`"**"`之后。 在每个护身符之后盲目读取分隔符的代码可能会意外消耗下一个测试输入的一部分或错误地命中 EOF。 

## 方法

 最直接的解决办法就是暴力破解。 对于每个护身符，将其与之前见过的所有护身符堆进行比较。 要测试两个护身符是否等效，请生成一个护身符的所有四个旋转，并检查其中任何一个是否与另一个匹配。 

这是可行的，因为旋转等价正是问题所要求的。 每次比较都会花费恒定的时间，因为护身符总是有四个单元。 和`n = 1000`，最坏的情况执行大约一百万次比较，这仍然可以接受。 

暴力方法的弱点不在于性能，而在于结构。 我们反复重新计算旋转并反复比较相同的模式。 如果我们为每个护身符指定一个规范形式，问题就会变得更加清晰。 

关键的观察结果是同一护身符的所有旋转都属于一个等价类。 如果我们生成四个旋转并选择字典顺序最小的表示，那么同一类中的每个护身符将产生完全相同的规范字符串。 

例如：```
12
34
```产生这些旋转：```
1234
3142
4321
2413
```最小的字符串是`"1234"`。 该护身符的任何旋转版本也会生成相同的四个字符串，因此其最小值仍然是`"1234"`。 

一旦每个护身符都转换成其规范形式，问题就减少到计算不同的字符串。 集合可以自然地处理这个问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 已接受 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取护身符的数量。 
2. 对于每个护身符，读取其两行并提取四位数字：```
a b
c d
```3. 生成所有四个旋转。 

轮换是：

 原文：```
a b
c d
```90°：```
c a
d b
```180°：```
d c
b a
```270°：```
b d
a c
```4.将每次旋转转换为长度的字符串`4`。 

例如：```
a b
c d
```变成`"abcd"`。 
5. 选择字典顺序最小的旋转字符串。 

这成为护身符的规范代表。 每个旋转等效的护身符都会产生相同的规范字符串。 
6. 将规范字符串插入集合中。 

集合会自动删除重复项，因此相同的等价类会合并为一个条目。 
7. 处理完所有护身符后，打印该套装的尺寸。 

为什么它有效：

 护身符的每个有效旋转都会出现在四个生成的配置中。 当两个护身符的旋转组相同时，它们在旋转上完全等效。 由于我们总是选择最小的旋转字符串作为规范形式，因此所有等效护身符映射到相同的值，而非等效护身符映射到不同的值。 集合大小恰好是不同桩的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

seen = set()

for i in range(n):
    r1 = input().strip()
    r2 = input().strip()

    a, b = r1[0], r1[1]
    c, d = r2[0], r2[1]

    rotations = [
        a + b + c + d,
        c + a + d + b,
        d + c + b + a,
        b + d + a + c
    ]

    seen.add(min(rotations))

    if i != n - 1:
        input()

print(len(seen))
```该程序以标准化形式存储每个护身符。 

四个变量`a`,`b`,`c`， 和`d`代表正方形：```
a b
c d
```这`rotations`list 明确构造了四种可能的方向。 由于护身符大小是固定的，因此直接编写变换比使用矩阵旋转代码更简单且不易出错。 

致电给`min(rotations)`选择规范表示。 字典顺序比较很自然，因为所有字符串都具有相同的长度。 

分隔线`"**"`仅在护身符之间跳过。 条件：```
if i != n - 1:
    input()
```避免在最后一个护身符之后读取超过输入末尾的内容。 

套装`seen`每个等价类存储一个代表。 它的最终大小就是桩的数量。

 ## 边缘情况

 考虑一下这两个护身符：```
2
12
34
**
31
42
```第一个护身符顺时针旋转到第二个护身符。 该算法为两者生成所有四种旋转并选择相同的规范形式`"1234"`。 由于两者都将相同的字符串插入到集合中，因此最终答案是：```
1
```这证实了旋转等效性已正确处理。 

现在考虑一个对称的护身符：```
1
11
11
```所有四个旋转都是相同的：```
1111
```规范形式仍然存在`"1111"`。 该算法不会意外地分别对多个旋转进行计数，因为它只存储一次最小表示。 

最后，考虑一个看起来相似但旋转不等价的情况：```
2
12
21
**
21
12
```第一个护身符产生旋转：```
1221, 2112, 1221, 2112
```它的规范形式是`"1221"`。 

第二个产生：```
2112, 1221, 2112, 1221
```实际上这些是等价的，所以答案是`1`。 

一个真正不同的例子是：```
2
12
34
**
21
43
```第一个规范形式是`"1234"`，而第二个是`"1324"`。 由于规范形式不同，集合大小变为`2`。 

这证实了该算法正确区分非等价排列。
