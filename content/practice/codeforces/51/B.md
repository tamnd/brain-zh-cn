 ## 解决方案
 ## 问题理解

 我们得到一个表示简化 HTML 表语言的字符串。 该语言仅包含三种标签：`<table>`,`<tr>`， 和`<td>`，以及它们匹配的结束标签。 表格包含行，每行包含单元格，单元格要么为空，要么包含另一个完整的表格。 

任务是查找文档中出现的每个表格（包括嵌套表格）内的直接单元格数量。 对于每个表，我们计算有多少`<td>...</td>`元素直接属于该表，而不属于嵌套在其单元格内的表。 收集所有计数后，我们按非递减顺序打印它们。 

输入长度最多为 5000 个字符。 对于线性或二次算法来说，这已经足够小了，但如果不小心实现，大子串的递归重新解析仍然会变得昂贵。 立方解析器已经很危险了，因为 5000 立方次操作远远超出了时间限制。 带有堆栈的干净单通道解析器很容易满足约束条件。 

语法保证输入有效，因此我们永远不需要从格式错误的标签中恢复。 每个开始标记都有一个匹配的结束标记，并且嵌套始终正确。 

问题的一个微妙部分是区分直接单元格和属于嵌套表的单元格。 

考虑这个输入：```
<table><tr><td><table><tr><td></td></tr></table></td></tr></table>
```即使嵌套表内存在另一个单元格，外部表也只有一个单元格。 正确的输出是：```
1 1
```一个简单的计数器，只计算所有`<td>`表范围内的标签会错误地报告`2`对于外表。 

另一个容易犯的错误是忘记桌子不一定是矩形的。 

例子：```
<table><tr><td></td><td></td></tr><tr><td></td></tr></table>
```该表共有三个单元格，而不是四个。 行可以具有不同的长度。 

第三个陷阱是逐行处理输入，而不是首先连接所有行。 该语句明确允许任意换行。 

例如：```
<table><tr>
<td></td>
</tr></table>
```这些行一起形成一个有效的字符串。 独立处理行会破坏解析器。 

## 方法

 最直接的方法是独立解析每个表。 每当我们遇到一个`<table>`，我们寻找它的匹配`</table>`，提取该子字符串，并计算有多少个直接`<td>`标签属于它。 为了避免计算嵌套表的单元格，我们在扫描子字符串时需要另一个嵌套计数器。 

这在逻辑上是可行的，但它会重复工作很多次。 在最坏的情况下，深层嵌套的表迫使我们重新扫描每个表的几乎整个剩余字符串。 如果嵌套深度为`n`，总工作量大致变为：```
n + (n - 1) + (n - 2) + ...
```这是二次的。 

长度为 5000，即使`O(n²)`可能会通过，但实现会变得混乱，因为我们反复搜索匹配的标签并反复遍历相同的区域。 

语法的结构给了我们一个更清晰的想法。 每个标签都以正确的嵌套顺序出现，就像括号一样。 这意味着我们可以使用堆栈从左到右处理一次字符串。 

关键的观察结果是，当我们关闭该表时，该表的单元格计数就会被准确地知道。 每一个直接`<td>`当表处于活动状态时遇到的属于它。 嵌套表不会干扰，因为它们是由更深的堆栈级别处理的。 

因此，我们不重新解析子字符串，而是维护一堆当前打开的表。 当我们看到`<table>`，我们创建一个新的计数器。 当我们看到`<td>`，我们增加当前表的计数器。 当我们看到`</table>`，我们最终确定该表并存储其计数。 

这将问题转化为简单的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 已被接受但效率低下|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取所有输入行并将它们连接成一个字符串。 

该语法忽略行边界，因此解析器必须对组合字符串进行操作。 
2. 从左到右扫描字符串。 

每个有意义的标记都是一个完整的标签，例如`<table>`或者`</td>`。 由于标签集很小且固定，我们可以使用字符串前缀检查来识别标签。 
3. 维护一个堆栈，其中每个元素存储打开表的当前直接单元格数。 

堆栈的顶部始终代表我们当前所在的表。 
4、遇到时`<table>`， 推`0`到堆栈上。 

新表以迄今为止计数为零的单元格开始。 
5、遇到时`<td>`，增加栈顶元素。 

每一个`<td>`直接属于当前活动表。 即使此单元格稍后包含另一个表，它仍然是当前表的一个直接单元格。 
6. 忽略`<tr>`,`</tr>`， 和`</td>`。 

它们影响结构有效性，但不会改变细胞计数。 
7、遇到时`</table>`，从堆栈中弹出顶部值并将其附加到答案列表中。 

此时，表格已完全处理，因此其直接单元格计数是最终的。 
8. 扫描完成后，对收集的计数进行排序。 
9. 打印计数，并用空格分隔。 

### 为什么它有效

 在扫描过程中的任何位置，堆栈都准确地表示当前打开的表从最外层到最内层的链。 每一个`<td>`标签属于最里面的打开表，因为语法只允许单元格位于当前表的行内。 嵌套表创建新的堆栈级别，因此它们的单元格永远不会影响父计数器。 什么时候`</table>`出现时，该表的所有内容都已被处理，这意味着存储的计数器是完整且正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = "".join(line.strip() for line in sys.stdin)

    stack = []
    ans = []

    i = 0
    n = len(s)

    while i < n:
        if s.startswith("<table>", i):
            stack.append(0)
            i += 7

        elif s.startswith("</table>", i):
            ans.append(stack.pop())
            i += 8

        elif s.startswith("<td>", i):
            stack[-1] += 1
            i += 4

        elif s.startswith("</td>", i):
            i += 5

        elif s.startswith("<tr>", i):
            i += 4

        elif s.startswith("</tr>", i):
            i += 5

    ans.sort()
    print(*ans)

if __name__ == "__main__":
    solve()
```第一步将所有输入行连接成一个连续的字符串。 使用`strip()`删除换行符，同时保留实际标记。 

解析器使用单个索引`i`。 由于每个有效标记都有固定的长度，因此我们可以在匹配标签后立即前进指针。 

堆栈为每个打开的表存储一个整数。 当新表开始时，我们推送`0`。 每一个`<td>`仅增加顶部元素，因为直接所有权始终属于当前表。 

条件的顺序有点重要，因为`<table>`和`</table>`共享前缀。 在关闭标签之前检查开始标签可以保持匹配明确。 

我们完全忽略行标签，因为它们不会影响所需的答案。 它们唯一的作用是加强语法有效性，该声明已经保证了这一点。 

当一个表关闭时，它的计数器就完成了，所以我们将它弹出并保存到`ans`。 

最后，排序产生所需的非递减顺序。

 ## 边缘情况

 再次考虑嵌套表的情况：```
<table><tr><td><table><tr><td></td></tr></table></td></tr></table>
```从外表计数器开始执行`[0]`。 第一个`<td>`将其更改为`[1]`。 当内表启动时，栈变成`[1, 0]`。 内部`<td>`仅增加顶层，产生`[1, 1]`。 关闭内表后，答案列表包含`[1]`，外部计数器保持不变。 关闭外表会添加另一个`1`。 最终排序后的输出为：```
1 1
```这证实了嵌套细胞永远不会泄漏到父代计数中。 

现在考虑一个非矩形的桌子：```
<table><tr><td></td><td></td></tr><tr><td></td></tr></table>
```解析器遇到三个`<td>`当同一个表处于活动状态时标记，因此其计数器演变为：```
0 -> 1 -> 2 -> 3
```行对于计数并不重要。 最终输出是：```
3
```这避免了假设所有行具有相同宽度的常见错误。 

最后，考虑多行输入：```
<table><tr>
<td></td>
</tr></table>
```该算法首先将所有剥离行连接成：```
<table><tr><td></td></tr></table>
```之后，解析正常进行并产生：```
1
```如果没有串联，解析器将错误地将换行符边界视为有意义的结构。
