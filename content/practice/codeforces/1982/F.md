 ## 解决方案
 ## 问题理解

 我们得到一个通过点更新随时间变化的数组。 每次更改之后，我们必须回答有关数组的结构问题：最短的连续段是什么，如果我们仅对该段进行排序，则整个数组将按非递减顺序排序。 

关键思想是我们并不试图对数组进行完全排序。 相反，我们试图确定包含所有反转的最小“损坏间隔”，通过仅对该间隔进行排序来修复整个数组。 

每个查询都会更改一个位置，每次更改后我们都必须从头开始高效地重新计算这个最小段。 

这些限制迫使我们进行仔细的设计。 数组长度和更新次数总共都达到5e5。 任何在每个查询的线性时间内重新计算排序或扫描的解决方案在最坏的情况下都会导致大约 2.5e11 次操作，这远远超出了可行的限制。 这会立即排除每个查询排序、反转的完全重新计算或嵌套扫描。 

当数组已经排序时，会出现微妙的边缘情况。 在这种情况下，答案必须是-1 -1。 一种总是返回像 [1,1] 或 [l,l] 这样的片段的天真的区间检测方法在这里失败了，因为它错误地假设至少一个位置必须是“固定的”。 另一个棘手的情况是，更新是本地的，但其影响会在全球范围内传播。 例如，在像 [1,2,3,4,5] 这样的几乎排序的数组中，将中间更改为 0 会导致左边界一直移位到索引 1，并且未来的答案取决于全局排序，而不是局部更改。 

## 方法

 暴力解决方案通过扫描数组并找到违反排序属性的第一个和最后一个位置，在每次更新后重新计算答案。 还可以模拟对每个可能的子数组进行排序并检查它是否修复了数组。 从概念上讲，这是可行的，因为对子数组进行排序会删除其中的所有反转，剩下的问题是边界反转是否仍然存在。 然而，尝试所有子数组是二次的，甚至扫描每个查询也是线性的，导致 O(nq)，这太慢了。 

关键的观察结果是，最佳段完全由数组反转的全局结构决定。 如果我们想象数组的排序版本，最小段必须覆盖相对于正确排序区域“不合适”的所有索引。 更具体地说，我们需要最小的 l 使得 l 左边的所有内容都已经与排序顺序一致，并且需要最大的 r 使得 r 右边的所有内容也一致。 

这可以重新构建为对订单统计信息的查询：我们需要找到数组与其排序结构不同的第一个和最后一个位置，但我们必须在更新时动态维护它。 

关键的结构见解是，答案由两件事决定：前缀条件，即 l 之前不应出现反转；后缀条件，即 r 之后不应出现反转。 可以使用有效维护本地排序约束的有序数据结构来跟踪这些。 

实现此目的的标准方法是将所有索引维护在以值和索引为键的平衡结构中，使我们能够快速找到违反排序顺序的位置。 边界由前驱关系中断的第一个位置和最后一个这样的位置确定。 

通过合适的有序集或线段树来保持局部顺序一致性，每次更新仅影响比较的一小部分邻域，但查询全局极值可以在对数时间内完成。

 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(n) | 太慢了 |
 | 最优（有序结构/线段树）| O((n+q) log n) | O((n+q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护数组和一个结构，用于跟踪顺序属性 a[i] <= a[i+1] 成立或失败的位置。 

1. 构建一个辅助数组 diff，其中如果 a[i] <= a[i+1]，则 diff[i] = 1，否则为 0。这对数组是否在每个边界处进行本地排序进行编码。 
2. 维护一个数据结构，支持在单个位置发生变化时更新 diff。 当 a[i] 更新时，只有 diff[i-1] 和 diff[i] 可以改变，因为只有相邻的比较受到影响。 这是关键的地方属性。 
3. 为了回答查询，我们需要最小的 l 以便在 l 处或之前存在违规，以及最大的 r 以便在 r 处或之后存在违规。 同样，我们需要覆盖所有索引 i 的最小区间，其中 diff[i] = 0。 
4. 维护一个存储所有索引 i（其中 diff[i] = 0）的结构，例如排序集。 左边界源自该集合中的最小索引，右边界源自最大索引加一。 
5. 如果集合为空，则数组已排序，我们返回 -1 -1。 
6. 对于每次更新，最多调整两个差异条目，相应地更新集合，然后从集合的极值重新计算答案。 

微妙的一点是，我们返回的段并不是直接的 diff 间隔，而是从它派生出来的。 如果第一个违规发生在 i 处，则排序段必须从 i 处或之前开始，右侧也类似。 

### 为什么它有效

 当且仅当所有反转完全位于该子数组内时，修复子数组后数组才会排序。 任何反转都会由 diff 中的一对相邻违规见证，因此覆盖 diff 中的所有零条目相当于覆盖所有反转。 由于对段进行排序会删除完全包含在其中的所有反转，并且不会影响外部元素，因此最小有效段恰好是包含每个违规边界的最小间隔。 这确保了排序后没有反转跨越边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    bad = set()

    def add(i):
        if 0 <= i < n - 1:
            if a[i] > a[i + 1]:
                bad.add(i)

    for i in range(n - 1):
        add(i)

    def answer():
        if not bad:
            return "-1 -1"
        l = min(bad) + 1
        r = max(bad) + 1
        return f"{l} {r}"

    out = []
    out.append(answer())

    for _ in range(q):
        pos, val = map(int, input().split())
        pos -= 1

        a[pos] = val

        for i in (pos - 1, pos):
            if 0 <= i < n - 1:
                if i in bad:
                    if not (a[i] > a[i + 1]):
                        bad.remove(i)
                else:
                    if a[i] > a[i + 1]:
                        bad.add(i)

        out.append(answer())

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案依赖于仅维护定义局部无序的相邻比较。 当一个值发生变化时，只有它的两个邻居可以重新变得无效或再次变得有效，因此我们最多更新集合中的两个条目。 

答案直接从违规集中的极值指数得出。 从边界索引 i 转换为数组索引需要移位 +1，因为 diff[i] 对应于 a[i] 和 a[i+1]。

 ## 边缘情况

 完全排序的数组保持稳定，直到更新引入严格反转。 在这种情况下，只有两个相邻的比较变得无效，并且算法正确地将这些索引插入到坏集合中，从而生成一个足以覆盖它们的最小段。 

当多次更新逐渐形成广泛的无序时，例如在数组中重复插入递减的值，坏集就会扩大，返回的间隔也会相应增加。 每次更新仅涉及局部比较，但极值索引仍然正确捕获全局受影响区域，因为任何反转都必须由至少一个相邻违规见证。
