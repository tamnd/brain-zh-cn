 ## 解决方案
 ## 问题理解

 我们被要求模拟一个游戏，其中一副纸牌按特定顺序排列。 每张卡片上都有一个正整数。 叶戈尔每轮从牌堆顶部取出非零张牌，如果取出的牌的总和在给定范围内，则该轮获胜$[l, r]$。 任务是最大化获胜的回合总数，但不要求获胜回合连续发生。 输入给出多个独立的测试用例，每个测试用例指定卡的数量、目标范围和卡值的顺序。 每个测试用例的输出都是一个整数：获胜回合的最大数量。 

约束允许最多$10^5$每个测试用例的卡片，以及总和$n$所有测试用例的总和是$2 \cdot 10^5$。 这排除了$O(n^2)$解决方案，因为每轮迭代所有可能的连续子数组将导致超过$10^{10}$运营。 每张卡牌的价值和范围$l, r$可以达到$10^9$，因此我们必须小心处理整数和，而不依赖于假设小数字的数组索引技巧。 

边缘情况包括所有卡片都太大而无法放入的序列$[l, r]$单独地，单个卡已经满足范围的序列，以及必须将多个小卡分组才能达到范围的序列。 例如，用卡`[1, 2, 1]`和范围`[3, 3]`，我们不能拿任何一张牌，但将前两张牌的总和为 3，即为获胜回合。 总是拿最上面的牌并检查它是否获胜的天真贪婪的方法可能会错过组合小牌的机会。 

## 方法

 暴力方法是检查剩余牌组的每个可能的前缀，以找到获胜范围内的连续总和。 虽然这是正确的，但它需要$O(n^2)$每个测试用例，因为在最坏的情况下，我们可能必须在每一步检查所有可能的前缀长度。 和$n$最多$10^5$，这太慢了。 

关键的观察结果是，问题简化为计算总和落在以下范围内的前缀数量：$[l, r]$。 考虑前缀和数组$S$在哪里$S_i = a_1 + a_2 + ... + a_i$。 每轮对应于选择前缀的开始和结束索引，使得总和在$[l, r]$。 由于叶戈尔必须始终从顶部拿牌，因此每轮从剩余的第一张牌开始。 因此，我们只需要为每个位置找到从当前卡牌开始的最短前缀。$[l, r]$。 第一个的总和$k$卡是$S_k$，所以问题就变成了寻找最大的$k$这样$S_k - S_{prev}$在于$[l, r]$， 在哪里$S_{prev}$是之前移除的所有牌的总和。 对前缀和使用两指针技术允许我们在线性时间内计算它。 

另一个见解是，由于卡牌价值为正，随着我们加入更多卡牌，总金额会严格增加。 这确保了两指针方法总是会找到满足范围的最小长度前缀而无需回溯，因为任何较大的前缀也严格更大并且可以顺序检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 前缀和上的两指针 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$,$l$,$r$，以及卡值数组$a$。 初始化前缀和数组$S$和$S_0 = 0$和$S_i = S_{i-1} + a_i$。 这使我们能够计算中任何顶部片段的总和$O(1)$作为$S[j] - S[i-1]$。 
2. 初始化计数器`wins = 0`和一个指针`start = 0`，表示这副牌中剩余的第一张牌的位置。 
3.使用指针`end`迭代前缀和`start + 1`最多`n`。 对于每个`end`, 计算`sum_segment = S[end] - S[start]`。 
4. 如果`sum_segment`超过`r`，这一轮我们不能拿更多的牌，所以增加`start`直到`sum_segment <= r`或者`start = end`。 这是有效的，因为所有卡的面值都是正值； 添加更多卡片只会增加总和。 
5. 如果`sum_segment`至少是`l`并且至多`r`，这算作获胜回合。 增量`wins`并移动`start`到`end`用下一张牌开始下一轮。 
6. 重复此操作，直至处理完所有卡片。 输出`wins`对于这个测试用例。 

为什么它有效：该算法保持了以下不变式：`start`总是指向第一张未收集的牌，并且`end`单调增长。 由于卡面值为正数，因此总和为`start`到`end`增加与`end`。 两个指针确保我们有效地跳过太小或太大的段。 每张卡最多被访问两次（一次是`start`有一次`end`），保证每个测试用例的线性时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = list(map(int, input().split()))
        
        wins = 0
        start = 0
        prefix_sum = [0]*(n+1)
        for i in range(n):
            prefix_sum[i+1] = prefix_sum[i] + a[i]
        
        end = 1
        while start < n:
            while end <= n and prefix_sum[end] - prefix_sum[start] < l:
                end += 1
            if end <= n and prefix_sum[end] - prefix_sum[start] <= r:
                wins += 1
                start = end
                end = start + 1
            else:
                start += 1
                if end <= start:
                    end = start + 1
        print(wins)

if __name__ == "__main__":
    solve()
```该代码初始化前缀和以快速计算段和。`start`标记第一张未收集的牌，同时`end`搜索总和在获胜范围内的最短线段。 我们递增`wins`当某个段符合条件并移动时`start`到`end`开始下一轮。 嵌套循环永远不会回溯，因为所有值都是正数，因此每个索引都是线性处理的。 

## 工作示例

 **样品1：**

 输入：`5 3 10`有卡`[2, 1, 11, 3, 7]`| 开始 | 结束 | 总和段 | 胜利|
 | --- | --- | --- | --- |
 | 0 | 1 | 2 | 0 |
 | 0 | 2 | 3 | 1（拿前两张牌）|
 | 开始 → 2 | 结束= 3 | 11 | 11 1 |
 | 开始 → 3 | 结束 = 4 | 3 | 2（取3）|
 | 开始 → 4 | 结束 = 5 | 7 | 3（取7）|

 **样本2：**

 输入：`10 1 5`有卡`[17, 8, 12, 11, 7, 11, 21, 13, 10, 8]`| 开始 | 结束 | 总和段 | 胜利|
 | --- | --- | --- | --- |
 | 0 | 1 | 17 | 17 太大|
 | 开始 → 1 | 结束 = 2 | 8 | 太大|
 | ... | ... | ... | 0 |

 没有段适合`[1,5]`， 所以`wins = 0`。 

这些痕迹表明，两指针方法可以正确识别获胜回合并跳过不合适的片段，而不会丢失组合。
