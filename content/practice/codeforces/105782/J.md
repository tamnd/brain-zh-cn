 ## 解决方案
 ## 问题理解

 我们有一个系统，其中“花”从原点开始$d$维整数网格。 时间以离散的步骤进行，在每一步，花朵都会通过沿着其中一个坐标轴移动一个单位来扩展其形状。 每次移动也会选择一个方向，这意味着沿着选定的轴，增长可以是正的，也可以是负的。 

所以一个完整的演变$t$秒相当于一个序列$t$带符号的轴选择。 每一步都会选择其中一个$d$协调并决定是增加还是减少。 如果在任何时间步选择的轴或方向不同，则认为两个演化是不同的。 

输出询问此后有效序列的数量$t$步数，模数$998244353$。 

限制条件$d, t \le 2 \cdot 10^5$立即排除任何显式枚举序列的解释。 朴素的指数视图会将每一步视为$2d$选项，导致$(2d)^t$，即使对于微小的输入，这也远远超出了计算范围。 任何有效的解决方案都必须将这些序列的结构压缩为可以有效评估的闭合组合形式或卷积。 

一种微妙的极端情况是$t = 0$。 在这种情况下，无论维度如何，都只有一种有效的演化，即空序列。 另一个边缘情况是$d = 1$，其中每一步都被迫在唯一的轴上，但仍然有两个方向选择； 天真的“选择轴，然后独立地选择方向”的推理仍然必须干净地处理这个问题，而无需稍后使用特殊的外壳。 

一个更具结构性的陷阱来自于将“最终位移”与“序列同一性”混淆。 两个序列可以落在相同的最终坐标处，但如果它们在任何中间步骤不同，则仍然不同，因此问题不是计算网格中的端点，而是计算标记的步骤序列。 

## 方法

 直接强力方法将构造每个可能的长度序列$t$，并为每个步骤选择以下之一$d$轴和两个方向之一。 这正好给出了$2d$每一步的选择，所以序列的总数是$(2d)^t$。 根据问题的定义，这是正确的，因为每个选择都会产生不同的序列，并且没有其他约束，例如自相交或禁止状态。 

问题是，这已经是未简化形式的最终答案，并且计算模幂是微不足道的，所以如果问题确实如此，那么对于 Codeforces 设置来说就太容易了。 关键的隐藏结构是方向对称与轴选择相互作用，并且预期的解释根据每个坐标被选择的次数对序列进行分组，而不是独立处理每个带符号的移动。 

如果我们通过分离轴选择和符号选择来重新解释序列，那么该过程就变成选择长度-$t$序列结束$d$标签，并为每个事件独立分配一个符号。 分配轴使用的方式有多项式：if axis$i$被使用$c_i$次，则实现分布的序列数为$$\binom{t}{c_1, c_2, \dots, c_d} \cdot 2^t.$$总结所有组成$t$进入$d$部分通过多项式定理折叠成$(d)^t$，并且重新引入独立符号选择给出总共$(2d)^t$。 因此，问题归结为快速模幂而不是任何组合 DP。 

关键的见解是认识到每个步骤都是独立的，并且在固定大小的字母表上相同分布$2d$。 整个几何解释是一种干扰； 步骤之间不存在状态耦合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举|$O((2d)^t)$|$O(t)$递归深度 | 太慢了 |
 | 组合减少+快速功率|$O(\log t)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 将每个步骤解释为从一组尺寸中独立选择$2d$，其中每个轴贡献两个方向变量。 这将几何过程重新构建为独立事件的纯粹计数问题。 
2. 计算有效序列的总数为$(2d)^t$。 这是因为每个$t$步骤具有相同的无限制选择。 
3. 使用模幂计算模下的幂$998244353$，因为直接求幂是不可行的$t$很大。 
4. 返回结果。 

重新公式化后剩下的唯一计算任务是快速求幂，这可以在$O(\log t)$当设置指数的当前位时，重复对底数进行平方并相乘。 

### 为什么它有效

 正确性来自于步骤的独立性。 在每个时刻，系统的状态并不约束未来的选择，因此有效序列的集合正是$t$尺寸相同的选择集$2d$。 序列和长度之间的任何双射$t$字母表大小的字符串$2d$保留计数，因此求幂可以准确地捕获总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def main():
    d, t = map(int, input().split())
    base = (2 * d) % MOD
    print(mod_pow(base, t))

if __name__ == "__main__":
    main()
```该解决方案将一切简化为计算模指数。 乘以 2 反映了每个轴上两个可能的方向，乘以$d$考虑轴选择。 

主要实现细节是确保在每一步应用模乘法以避免溢出，并且求幂是迭代而不是递归完成的，以保持恒定的内存使用量。

 ## 边缘情况

 对于$t = 0$，算法计算$(2d)^0 = 1$，匹配单空进化。 求幂例程无需进入乘法循环即可正确返回 1。 

为了$d = 1$，底数变为2，所以答案是$2^t$。 这对应于每步有两个方向选择的单轴，并且计算在没有特殊外壳的情况下保持稳定。 

对于较大的值，例如$d = t = 2 \cdot 10^5$，模幂确保计算保持在对数时间内。 该算法从不构造超出模数的中间值，因此始终避免溢出。
