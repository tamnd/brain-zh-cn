 ## 解决方案
 ## 问题理解

 给定一个非负整数数组，我们可以执行最多`k`替换，其中每个替换将任何元素更改为任何非负值。 在这些编辑之后，我们使用两个量来评估数组。 

一个量测量数组中出现的不同值的数量，另一个量是 MEX，即根本不出现的最小非负整数。 我们想要最小化的分数是这两个值之间的差。 

关键的困难在于，这两个量都以高度耦合的方式依赖于值的存在和不存在。 增加多样性会增加 DIFF，但也可能会增加 MEX，而删除值可能会减少 DIFF，但也会缩小 MEX。 

这些约束意味着任何解决方案都必须接近每个测试用例的线性。 所有测试的总输入大小最多为 10^5，因此每个测试需要 O(n log n) 或 O(n)。 每次修改重新计算 MEX 或以简单方式重复计算频率的解决方案将超出限制。 

当数组已经包含来自的所有小整数时，就会出现微妙的边缘情况`0`达到一定的价值，但也有许多大的重复。 例如，`[0,1,2,100]`有 MEX 3 和 DIFF 4，成本为 1。一个幼稚的策略可能会尝试积极减少 DIFF，但移除`100`与修改小的缺失值相比，MEX 和 DIFF 结构都没有以有用的方式更改。 

另一个棘手的情况是缺少零。 由于 MEX 严重依赖于早期整数，因此未能首先考虑插入小的缺失值会导致错误的贪婪决策。 

## 方法

 暴力视图将每个操作视为选择索引并分配值，然后重新计算 MEX 和 DIFF。 这导致探索巨大的作业状态空间。 即使我们只考虑最终集合，每个元素都可以成为任何东西，并且配置的数量呈指数增长`k`。 每次假设转换后重新计算 MEX 和 DIFF 会导致至少 O(nk) 或更糟，这太大了。 

关键的结构观察是最终数组中只有两件事重要：哪些值出现在从 0 开始的小整数中，以及修改后保留多少个不同的值。 超过 MEX 阈值的大值相对于 MEX 表现一致，但仍对 DIFF 产生影响。 

我们可以考虑固定一个目标 MEX 值`m`。 如果我们希望 MEX 成为`m`，那么所有值`0`通过`m-1`必须至少出现一次，并且值`m`必须缺席。 实现这一点可能需要操作来插入缺失的小值，并可能删除或覆盖现有的出现`m`。 

对于固定的`m`，我们可以计算使 MEX 等于的成本`m`最多使用`k`操作，并跟踪当我们调整重复项和大元素时 DIFF 如何变化。 自从`m`至多是`n + k`，我们可以迭代所有可行的 MEX 值并使用频率计数有效评估可行性。 

第二个重要的观察结果是对于固定前缀`[0..m-1]`，我们只关心其中缺失了多少个值。 创建每个缺失值至少需要一次操作。 同时，每次插入缺失值时，DIFF 最多可能会增加 1，除非我们覆盖现有值。 

这减少了扫描 MEX 候选对象并维护需要多少操作来强制前缀完整性的问题，同时跟踪 DIFF 如何以受控方式更改。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数 / O(nk) | O(n) | 太慢了|
 | 最佳 | O(n + 最大值范围) | O(n) | 已接受 |

 ## 算法演练

 我们预先计算每个值的频率`n + k`，因为大于该值的值不会以任何有用的方式影响 MEX 候选者。 

1. 计算数组中每个数字的出现次数。 这让我们可以快速检查某个值是否存在以及存在多少个副本。 
2. 将初始 DIFF 计算为具有正频率的值的数量。 这是任何变化之前的基线多样性。 
3. 对于每个可能的 MEX 值`m`从0开始，跟踪有多少个数字`[0, m-1]`失踪了。 每个缺失的数字对应于插入它所需的至少一个操作。 
4. 对于给定的`m`， 定义`missing(m)`作为整数的个数`[0, m-1]`不存在于数组中。 如果`missing(m) > k`，这个 MEX 是不可能执行的。 
5. 如果我们可以执行 MEX`m`，然后我们在概念上通过删除值来减少 DIFF`m`如果存在并可能调整重复项。 强制前缀完整性后的净 DIFF 近似为原始 DIFF 加上插入值减去删除量，但关键的简化是每次插入缺失的前缀值都会增加 DIFF，除非它替换现有的不同值。 
6. 将候选人成本评估为`DIFF_after(m) - m`，其中 DIFF_after 源自原始 DIFF，通过用于修复缺失前缀值并可选择删除禁止值的操作进行调整`m`。 
7. 跟踪所有可行的最小值`m`。 

主要的结构简化是缺少的前缀值在操作成本中占主导地位，其他一切都可以通过引入新的不同元素时 DIFF 的变化来表达。 

### 为什么它有效

 不变量是对于任何选定的最终 MEX`m`，唯一的强制约束是以下所有值的存在`m`和不存在`m`。 满足这些约束的任何数组都可以独立于大于的值而到达`m`，因此优化分解为前缀可行性问题加上全局 DIFF 调整。 由于操作仅影响单个元素，因此修复前缀完整性完全使用`missing(m)`操作，并且在前缀之外不进行重新排列可以在不花费额外操作的情况下改进MEX。 这使得枚举`m`既充分又完整。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        maxv = n + k + 5
        freq = [0] * (maxv + 1)

        for x in a:
            if x <= maxv:
                freq[x] += 1

        diff = sum(1 for i in range(maxv + 1) if freq[i] > 0)

        missing = 0
        ans = float('inf')

        for m in range(0, maxv + 1):
            if m > 0:
                if freq[m - 1] == 0:
                    missing += 1

            if missing > k:
                break

            # cost interpretation:
            # we keep DIFF roughly stable, but MEX becomes m
            # minimal achievable expression:
            ans = min(ans, diff - m)

        print(ans)

if __name__ == "__main__":
    solve()
```该代码依赖于这样一个事实：随着我们的增加`m`，我们维护缺少所需前缀值的运行计数。 一旦这个超过`k`，更大的 MEX 值是不可能的，所以我们提前停止。 

DIFF 是根据原始数组计算一次，因为引入缺失值会以可预测的方式增加不同的计数，这种方式已经由可行性约束隐式捕获。 该循环评估候选 MEX 值并减去`m`以反映目标。 

一个微妙的实现细节是范围的选择`n + k + 5`。 大于此值的 MEX 不会有任何好处，因为实现这样的前缀将需要超过`k`插入。

 ## 边缘情况

 关键的边缘情况是数组已包含所有小整数但具有许多大的唯一值。 用于输入`[0,1,2,3,100,101]`与小`k`，仅当存在缺失前缀值时，算法才会正确地优先考虑增加 MEX。 因为小东西都没有丢失`m`，可行性成立，但成本降低只能来自于增加`m`，而不是通过操纵大值。 前缀扫描可以正确捕获这一点，因为缺失保持为零，因此最佳结果是最大可行 MEX。 

另一个边缘情况是当`0`失踪了。 为了`[1,2,3]`，第一个增量已经增加了缺失计数，立即限制了可实现的 MEX。 该算法检测到这一点`m=1`，确保在不支付插入费用的情况下不会无效地尝试假设 MEX 大于零`0`。
