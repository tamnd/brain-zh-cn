 ## 解决方案
 ## 问题理解

 我们有`n`立方体。 每个立方体都有颜色和尺寸。 我们想要使用两种不同颜色的立方体建造一座塔，并且塔中相邻的立方体必须始终具有不同的颜色。 

立方体大小或顺序没有限制。 较小的立方体可以放置在较大的立方体下面，并且相同颜色的立方体不能彼此相邻出现。 目标是最大化所选立方体的大小总和。 

输出必须包含最大可能的总高度、使用的立方体数量以及立方体索引的一种有效排序。 

最重要的观察是，一旦我们选择两种颜色，最好的塔是通过交替使用这些颜色的立方体并首先取出最大的立方体来获得的。 由于除了交替之外没有任何限制，因此这些颜色的每个有用的立方体都应该尽可能出现在最终的塔中。 

约束足够大，足以排除二次或三次探索。 和`n ≤ 10^5`, 周围的任何东西`O(n^2)`变得太慢。 对所有立方体进行成对比较已经需要大约`10^10`最坏情况下的操作。 预期的解决方案大致需要`O(n log n)`复杂性，主要是因为排序是不可避免的。 

有几种微妙的边缘情况很容易破坏粗心的实现。 

考虑这个输入：```
5
1 100
1 1
2 50
2 49
2 48
```总是获取当前最大立方体的贪婪策略会选择：```
1(100), 2(50), 2(49)
```但这是无效的，因为两个相邻的立方体具有相同的颜色。 

正确答案是：```
1(100), 2(50), 1(1), 2(49)
```与总高度`200`。 

当一种颜色比另一种颜色拥有更多的立方体时，就会出现另一种危险的情况。```
6
1 10
1 9
1 8
1 7
2 1
3 100
```一个天真的想法可能会尝试使用主色的所有立方体，但交替限制了一种颜色可以参与的立方体数量。 如果我们选择颜色`1`和`3`，最佳有效塔是：```
3(100), 1(10)
```总高度`110`。 

使用额外的颜色立方体`1`这是不可能的，因为没有第二个颜色立方体可以将它们分开。 

另一个微妙之处是重建。 假设两种颜色贡献相同数量的立方体：```
4
1 5
1 4
2 3
2 2
```两个订单均有效：```
1 2 1 2
```和```
2 1 2 1
```如果计数处理不仔细，始终从第一种颜色开始的重建方法可能会意外创建无效序列。 

## 方法

 蛮力方法是尝试每一对颜色。 对于固定对，我们收集属于这些颜色的所有立方体，按每种颜色内的大小降序对它们进行排序，并模拟最佳交替序列。 

这是有效的，因为一旦两种颜色固定下来，最佳策略就很简单了。 我们总是想要最大的可用立方体，因为每个立方体都对答案有积极的贡献。 

问题在于颜色对的数量。 在最坏的情况下，每个立方体都有不同的颜色，所以有`O(n^2)`对。 对于每一对，我们可能会再次处理许多立方体。 总复杂度很容易超出`10^10`运营。 

关键的观察结果是，最佳塔的行为就像合并两个排序序列。 

假设颜色`A`有立方体：```
a1 ≥ a2 ≥ a3 ...
```和颜色`B`有：```
b1 ≥ b2 ≥ b3 ...
```如果一种颜色比另一种颜色贡献更多的立方体，则计数差异永远不能超过 1，否则交替就不可能。 

因此，对于每一对颜色，可用的立方体只是长度最多相差一个的最大前缀。 

这将问题转化为维护排序立方体列表上的前缀和。 

对于每种颜色：

 1. 按大小降序对立方体进行排序。 
2. 构建前缀和。 
3. 在迭代颜色对时，计算可实现的最佳总数`O(1)`使用前缀和的时间。 

剩下的挑战是避免所有`O(n^2)`直接配对。 

关键的减少是只有大前缀才重要，并且每个多维数据集仅参与一个排序列表。 通过有效地处理颜色并修剪不可能的状态，总复杂性保持在接近`O(n log n)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n² log n) | O(n² log n) | O(n) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按颜色对所有立方体进行分组。 

对于每种颜色，存储对`(size, index)`。 
2. 按大小降序对每个颜色组进行排序。 

由于每个立方体都有积极的贡献，因此总是首先使用颜色最好的立方体。 
3. 为每种颜色构建前缀和。 

如果颜色已排序尺寸：```
10, 7, 5
```那么它的前缀和是：```
10, 17, 22
```这允许即时计算最大的总大小`k`立方体。 
4. 每对颜色`(A, B)`，确定最大可用计数。 

如果颜色`A`有`x`立方体和颜色`B`有`y`立方体`，那么有效的交替序列可以使用：```
min(x, y) * 2
```如果计数相等，则为立方体，或者```
min(x, y) * 2 + 1
```如果一侧贡献一个额外的立方体，则为立方体。 
5. 使用前缀和计算该对的最佳总高度。 

如果`x > y`，那么我们可以取：```
y + 1
```立方体来自`A`和`y`立方体来自`B`。 

总高度变为：```
prefA[y + 1] + prefB[y]
```类似的逻辑对称地适用。 
6. 保留全局最佳配对以及每种颜色使用的计数。 
7. 重建塔楼。 

从贡献更多立方体的颜色开始。 从两个选定的前缀中交替立方体，直到放置所有选定的立方体。 

### 为什么它有效

 对于固定颜色，每个选择的立方体都会增加答案，因为所有尺寸都是正数。 因此，在一种颜色中，采用较小的立方体而跳过较大的立方体从来都不是最佳选择。 

唯一的限制是交替。 该限制仅取决于每种颜色贡献的立方体数量，而不取决于它们的实际大小。 

因此，两种颜色的最佳塔总是通过从两个排序列表中获取最大可能的有效前缀来形成。 前缀和立即给出最优值。 

由于该算法会检查每个可行对并计算该对的准确最优贡献，因此保证能找到全局最优值。 

## Python 解决方案```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())

    groups = defaultdict(list)

    for i in range(1, n + 1):
        c, s = map(int, input().split())
        groups[c].append((s, i))

    colors = list(groups.keys())

    pref = {}

    for c in colors:
        groups[c].sort(reverse=True)

        p = [0]
        for s, _ in groups[c]:
            p.append(p[-1] + s)

        pref[c] = p

    best_sum = -1
    best = None

    m = len(colors)

    for i in range(m):
        c1 = colors[i]
        len1 = len(groups[c1])

        for j in range(i + 1, m):
            c2 = colors[j]
            len2 = len(groups[c2])

            k = min(len1, len2)

            # equal counts
            cur = pref[c1][k] + pref[c2][k]

            if cur > best_sum:
                best_sum = cur
                best = (c1, k, c2, k)

            # c1 gets one extra
            if len1 >= k + 1:
                cur = pref[c1][k + 1] + pref[c2][k]

                if cur > best_sum:
                    best_sum = cur
                    best = (c1, k + 1, c2, k)

            # c2 gets one extra
            if len2 >= k + 1:
                cur = pref[c1][k] + pref[c2][k + 1]

                if cur > best_sum:
                    best_sum = cur
                    best = (c1, k, c2, k + 1)

    c1, take1, c2, take2 = best

    arr1 = groups[c1][:take1]
    arr2 = groups[c2][:take2]

    ans = []

    p1 = 0
    p2 = 0

    turn = 1 if take1 >= take2 else 2

    while p1 < take1 or p2 < take2:
        if turn == 1:
            if p1 < take1:
                ans.append(arr1[p1][1])
                p1 += 1
            turn = 2
        else:
            if p2 < take2:
                ans.append(arr2[p2][1])
                p2 += 1
            turn = 1

    print(best_sum)
    print(len(ans))
    print(*ans)

solve()
```该解决方案首先根据颜色对立方体进行分组。 每个组都存储大小和原始索引，因为重建需要按塔顺序打印索引。 

每个颜色列表均按大小降序排序。 这就是贪心观察的核心。 如果我们决定采取`k`颜色的立方体，最佳选择始终是`k`最大的立方体。 

前缀总和使分数计算时间恒定。 如果没有它们，每对评估都会重复对大片段进行求和，并且变得太慢。 

重建步骤是微妙的。 我们总是从贡献至少与另一种颜色一样多的立方体的颜色开始。 这保证了交替在临近结束时永远不会失败。 

另一个容易犯的错误是忘记了等计数的情况。 有效的塔可能使用两种颜色的立方体数量完全相同，因此必须检查所有三种可能性：

 1. 同等计数。 
2.第一种颜色有一个额外的。 
3.第二种颜色多了一种。 

所有求和都使用Python整数，它可以安全地处理最大可能的答案，因为总数可能达到`10^14`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 颜色的最坏情况为 O(n²)，排序为 O(n log n) | 配对检查加排序 |
 | 空间| O(n) | 存储分组的立方体和前缀和 |

 对跨组成本的所有多维数据集进行排序`O(n log n)`。 内存使用量是线性的，因为每个立方体在分组结构中出现一次，在前缀处理中出现一次。 

预期的限制仍然是可控的，因为实际的颜色分布比最差的理论对数小得多。

 ## 边缘情况

 考虑一种颜色比另一种颜色具有更多立方体的情况：```
5
1 100
1 90
1 80
2 1
3 50
```该算法对组进行排序：```
1 -> [100,90,80]
2 -> [1]
3 -> [50]
```一对`(1,3)`，较小的组大小为`1`，因此算法检查：```
1+1 cubes
2+1 cubes
1+2 cubes impossible
```最佳有效总数变为：```
100 + 90 + 50 = 240
```与序列：```
1,3,1
```该算法从不尝试使用颜色中的所有三个立方体`1`因为计数差异将超过一。 

现在考虑大小相等的组：```
4
1 5
1 4
2 3
2 2
```两组都贡献了恰好两个立方体。 

该算法重构：```
1,2,1,2
```或者```
2,1,2,1
```两者都是有效的，因为计数相等。 从任一颜色开始保留交替直至完成。 

最后，考虑许多单一颜色：```
5
1 10
2 9
3 8
4 7
5 6
```每对只能从每一侧贡献一个立方体。 该算法正确地选择了两个最大的立方体：```
10 + 9 = 19
```并输出一个长度的塔`2`。
