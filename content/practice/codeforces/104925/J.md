 ## 解决方案
 ## 问题理解

 我们不断地与一群“任务提供者”互动，这些“任务提供者”被称为“杀手大师”。 每个大师都有固定的任务列表。 任务具有频率权重、持续时间和每分钟 XP 率。 

每次我们拜访大师时，我们都可以永久丢弃最多`b`在对任何内容进行采样之前，先了解其任务。 之后，主人以与其频率权重成比例的概率随机选择剩余的一项任务。 我们要么完成任务，要么跳过它。 完成给我们`c`杀手点，跳过成本`s`点。 我们可以根据目前的分数来决定是否跳过，但绝不允许负数。 

我们的目标是在重复访问中选择一个长期策略，最大化每单位时间获得的预期 XP 的渐近比率。 声明中的极限定义将其形式化为无限范围的平均奖励过程：我们只关心稳态效率，而不是短期收益。 

这些限制意味着我们只能承受总输入大小的大致线性处理，因为所有主机的任务总数最多为`3 · 10^4`。 这排除了任何模拟长时间随机游戏或考虑超出每个主机的小型局部优化的组合子集的方法。 在最坏的情况下，每个主机的任何二次方都已经太大了。 

一个微妙的边缘情况来自于跳跃和点之间的相互作用。 一个幼稚的解决方案可能假设我们总是可以接受任务并完全忽略分数，但是当低 XP 任务频繁出现并迫使低效的时间积累时，这种情况就会破裂。 另一种失败模式是忽略阻塞任务改变概率分布这一事实，这直接影响预期 XP 和预期时间。 

如果我们有一位大师负责一项极低价值的任务和许多高价值的任务，就会出现一个具体的陷阱。 如果我们未能使用允许的阻塞，低价值任务可能会主导概率质量并急剧降低平均值，即使完全删除它会提高预期比率。 

## 方法

 问题的暴力视图将尝试模拟完整的过程：在每一步选择一个主控，选择一个阻塞集，模拟任务选择，并根据当前点决定是否跳过。 这立即变得棘手，因为状态空间包括当前点和任务结果的随机历史。 即使忽略点约束，枚举跨主机的所有阻塞子集也会给出指数分支`b`。 

关键的简化是分离两层决策。 第一个是每个主机本地的：如何在采样之前选择要阻止的最佳任务集。 第二个是全局的：长远来看去拜访哪位大师。 目标的渐近性质消除了对瞬态点平衡的任何依赖，并且系统成为预期奖励率的稳态优化。 

对于固定的主节点，一旦选择了阻塞，任务选择就变成了剩余任务的加权平均值。 因此，大师的贡献取决于移除最多后每单位时间可达到的最佳预期 XP`b`任务。 

关键的观察是，只有当某项任务“比平均水平更差”时，删除该任务才能提高预期比率。 这导致了一个单调的结构：对于每个master，我们想要丢弃最多`b`对预期效率指标贡献最低的任务。 在此修剪之后，剩余的任务为该主机定义单个确定性期望值。 

跳过/点系统充当长期预算约束，不会影响稳定状态下哪个主机是最佳的。 在极限情况下，最佳策略在最佳阻塞后重复使用每分钟可达到的最高预期 XP 的主服务器。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全随机模拟 | 指数| 大状态空间| 太慢了 |
 | 每个主机的修剪和平均 | O(总 mi log mi) | O(总英里) | 已接受 |

 ## 算法演练

 ### 1. 计算每个 master 内每个任务的效率

 对于每项任务，将其内在价值计算为每分钟 XP，因为时间是目标中的自然标准化尺度。 这给出了同一主控中跨任务的可比分数。 

此步骤有效的原因是，在单个 master 中，概率与固定权重成正比，因此预期 XP 和预期时间都成为任务的加权和。 

### 2. 按贡献度的增加对每个 master 内的任务进行排序

 对于每个master，按照其效率贡献对其任务进行排序。 

这种排序使我们能够推断出哪些任务对预期比率有害。 低效率任务在包含时会降低加权平均值，因此它们是删除的自然候选者。 

### 3. 尝试所有有效的修剪大小，直到 b

 对于每个大师，考虑保留最好的`mi - k`任务`k`从`0`到`b`，尊重必须保留至少一项任务。 对于每个选择，计算：

 每单位时间的预期 XP =（频率加权 XP 率之和）/（频率加权时间之和）

 该结构确保排序后，可以使用前缀和来评估每个候选者，因此每个案例在预处理后都会在恒定时间内计算。 

直觉是，最佳阻塞始终是“采用最佳任务的前缀”，因为任何非连续删除只会用期望的更好任务替换更差的任务，而无法提高比率。 

### 4.选择每个master的最佳配置

 对于每个主站，在所有允许的阻塞中获取每分钟可达到的最大预期 XP。 

这将每个主设备减少到一个数字：在最佳利用阻塞功率的情况下实现最佳效率。 

### 5.整体选择最好的master

 由于长期游戏由稳态行为主导，因此最佳全局策略是始终使用可实现的最高效率的大师。 

积分制度不会在极限内改变此排名； 它仅强制在有限前缀期间跳过决策的可行性，这些前缀在渐近比率中消失。 

### 为什么它有效

 该算法将重复的随机控制过程减少为每个主控的独立优化，因为奖励和时间在期望中都是线性的。 分块引入了离散选择层，但其效果是单调的：删除低效率任务严格增加或保持预期比率。 这创建了一个凸状结构，其中最优值位于通过删除最差任务定义的边界上。 效率的渐近定义消除了瞬态点约束，只留下稳态平均值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    b, c, s = map(int, input().split())
    n = int(input())

    best = 0.0

    for _ in range(n):
        m = int(input())
        tasks = []
        for _ in range(m):
            f, t, e = map(int, input().split())
            tasks.append((e, f, t))

        tasks.sort()  # increasing efficiency

        pref_f = [0]
        pref_ft = [0]
        pref_fe = [0]

        for e, f, t in tasks:
            pref_f.append(pref_f[-1] + f)
            pref_ft.append(pref_ft[-1] + f * t)
            pref_fe.append(pref_fe[-1] + f * e * t)

        # we keep suffix of size m-k, where k <= b
        for k in range(min(b, m - 1) + 1):
            # remove k worst = first k after sorting
            idx = m - k

            total_f = pref_f[idx]
            total_ft = pref_ft[idx]
            total_fet = pref_fe[idx]

            if total_ft > 0:
                ratio = total_fet / total_ft
                if ratio > best:
                    best = ratio

    print(f"{best:.12f}")

if __name__ == "__main__":
    solve()
```该代码将每个主节点压缩为排序任务的前缀和。 计算出的比率是按频率加权时间标准化后每分钟的预期 XP。 循环结束`k`对允许的阻塞预算进行编码。 

一个微妙的实现点是使用频率加权聚合。 由于选择概率与`f`，所有期望减少到加权总和`f`，并且分子和分母都共享此权重，从而无需显式模拟概率即可进行干净的比率计算。

 ## 边缘情况

 当主设备恰好具有`b+1`任务，其中一项任务明显比所有其他任务差。 在这种情况下，算法必须删除该单个异常值才能实现最佳比率。 前缀和评估确保通过考虑来明确测试`k = 1`，这直接对应于排序后删除最差的任务。 

另一种情况是所有任务都相同。 这里每个阻塞选择都会产生相同的比率，因此所有候选者都会崩溃到相同的值。 该算法自然地处理这个问题，因为前缀比率保持不变，无论`k`。 

最后一种情况是阻塞预算超过可用任务减一。 必须保留至少一项任务的约束是通过限制来强制执行的`k`到`m - 1`，防止退化空分布。
