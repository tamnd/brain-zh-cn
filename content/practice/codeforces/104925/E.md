 ## 解决方案
 ## 问题理解

 我们得到一个数字$n$，对于每个测试，我们必须构造两个正整数$a$和$b$（以下均$2^{60}$）或报告不存在这样的对。 

所需的条件以强制进位和位取消相互作用的方式混合加法和按位异或。 双方不仅取决于价值观$a$和$b$，而且还涉及它们的二进制表示如何与$n$。 这不是一个纯粹的代数恒等问题，而是一个二进制加法的约束系统，其中进位的传播方式与异或不同。 

输入大小最多允许$10^5$查询，因此每个测试必须在基本恒定或对数时间内处理，其位长度为$n$，最多为 60 位。 任何完全模拟算术或天真的尝试候选对的方法都是立即不可行的，因为即使每次测试的小搜索也会超出限制。 

出现微妙的边缘情况时$n$很小或者具有稀疏的二进制表示。 在这种情况下，粗心的贪婪构造常常会意外地引入破坏平等性的进位。 例如，如果一种方法假设加法的行为类似于 XOR，则只要存在重叠位，该方法就会失败，因为即使较低位匹配，进位也会传播到较高位置并破坏相等性。 

另一个常见的陷阱是假设对称性，例如尝试$a=b$或强迫$a$和$b$线性依赖于$n$。 因为表情混合$a+b$,$n+b$，以及不同位置的 XOR，对称性在变换中无法幸存。 

## 方法

 暴力尝试会尝试所有对$(a,b)$达到一定范围并直接检查条件。 即使我们限制$a,b < 2^{20}$，这已经产生了$10^{12}$的可能性，这是完全不可行的。 主要瓶颈是每次评估都涉及整数加法和异或，因此除非我们了解进位的结构，否则没有任何意义的修剪。 

关键的观察是该方程从根本上是对二进制进位的约束。 XOR 的行为类似于没有进位的加法，而加法则引入了相邻位之间的依赖性。 同时控制双方的唯一方法是确保所有出现的加法都像异或一样，这意味着涉及的每个和都必须避免进位传播。 

这减少了构建问题$a$和$b$使得三个总和以一致的方式免进位：$a+b$,$n+b$，以及它们与 XOR 表达式的交互。 在全球范围内强制执行此操作的唯一可行方法是将位范围分开$a$,$b$， 和$n$这样就不会发生重叠触发进位。 一旦数字位于不相交的位区域中，加法就变成了 XOR，并且方程简化为 XOR 上的线性恒等式，这可以通过仔细放置位来满足。

 ## 算法演练

 施工依赖于放置$a$和$b$相对于高的、不重叠的位位置$n$，确保不涉及添加$n$创建携带。 

1. 对于每个测试用例，检查最高设置位$n$。 设这个位置为$k$。 我们将构建远高于此范围的数字，以便$n$从不与它们的较低算术结构交互。 
2. 选择两个严格大于的不同位位置$k+2$， 说$p$和$p+1$。 这保证了$a$,$b$， 和$n$在二进制中具有不相交的支持。 
3. 设置$a = 2^p$和$b = 2^{p+1}$。 因为这些是没有重叠的单位数，所以两者$a+b$和$n+b$在本地算术中表现得像异或。 
4. 在这种分离假设下评估双方。 由于涉及这些数字的每个运算中的加法都是无进位的，因此将所有加法替换为 XOR，并将两边简化为 XOR 表达式。 
5. 输出构建的对。 

这样做的原因是我们迫使算术系统进入一种状态，其中加法和异或在与方程相关的任何地方都一致。 一旦进位被全局消除，原来的非线性约束就会崩溃为纯按位线性关系。 

### 为什么它有效

 核心不变量是相加的两个数字不会共享公共设置位。 这保证了每次加法都等价于 XOR，这意味着问题的代数变成了 GF(2) 上的向量空间。 在该空间中，等式两边都简化为相同的 XOR 组合$a$,$b$， 和$n$，所以平等通过构造成立。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        # find a bit safely above n
        k = 0
        while (1 << k) <= n:
            k += 1

        p = k + 2
        a = 1 << p
        b = 1 << (p + 1)

        print(a, b)

if __name__ == "__main__":
    solve()
```实施直接跟随构造。 唯一重要的部分是选择上面的位位置$n$。 我们计算最小的$k$这样$2^k > n$，然后进一步移位以保证分离，即使在带有进位边界的加法下也是如此。 

每个测试都是在恒定时间内独立处理的。 

## 工作示例

 考虑两个说明性的输入。 

为了$n = 5$，最高位为$2^2$，所以我们选择$p = 4$。 算法输出$a = 16$,$b = 32$。 由于两者都高于位范围$n$，任何地方都不会发生进位交互。 

| 步骤| 一个 | 乙| n | a+b 行为 | n+b 行为 |
 | --- | --- | --- | --- | --- | --- |
 | 建筑 | 16 | 16 32 | 32 5 | 异或| 异或|

 这表明所有算术都分解为按位运算，因此双方的计算结果一致。 

对于一个更大的例子$n = 13$，最高位为$8$，所以我们再次选择$p = 4$或更高，给出相同的结构分离。 确切的数值有所不同，但推理仍然相同：$n$从不与构造的位交互。

def run(inp: str) -> str:

 ## 边缘情况

 最微妙的情况是当$n$本身是 2 的幂或非常接近 2 的幂。 在这种情况下，幼稚的构造通常会放置$a$或者$b$太接近$n$，造成隐藏进位。 

例如，如果$n = 8$，一个粗心的选择，比如$a = 8$,$b = 1$创建进位链$a+b$和$n+b$，使 XOR 假设无效。 该结构通过移动两者来完全避免这种情况$a$和$b$远远超出了最高位$n$，保证不可能有二进制重叠。 

另一个微妙的情况是当$n$已设置所有低位，例如$n = 7$。 在这里，即使添加小数字也会触发长进位传播。 该算法通过根本不与这些位交互来回避这个问题，从而使内部结构$n$无关紧要。
