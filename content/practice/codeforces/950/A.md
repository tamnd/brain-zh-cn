 ## 解决方案
 ## 问题理解

 在一次训练中，我们分为三组球员：只能使用左手的人、只能使用右手的人以及可以分配到任意一只手的双手灵巧的球员。 教练希望建立一支规模均匀的球队，使得球队中有一半人用左手打球，另一半人用右手打球。 

每个左撇子球员只能为左侧做出贡献，每个右手球员只能为右侧做出贡献，而每个双手灵巧的球员可以根据有助于平衡团队的方式分配到任一侧。 

任务是最大化这样一个平衡团队中的玩家总数。 

所有计数最多为 100 的约束意味着该解决方案不需要高级数据结构或超出恒定时间算术推理的优化。 任何达到 O(1) 或 O(n) 的解决方案都足够了。 

一个关键的微妙之处在于，灵巧的玩家不仅仅是额外的参与者，他们还是可以在双方之间分配的灵活资源。 一个天真的错误是将它们视为仅添加到较小一侧的单个池，而没有考虑到平衡后，剩余的灵巧玩家仍然可以成对贡献以平均增加两侧。 

当所有不平衡问题尚未完全解决但双手灵巧的玩家仍然可用时，就会出现常见的失败情况。 

例如，考虑：

 输入：```
1 10 3
```如果我们只是贪婪地“修复不平衡”，我们可能会将所有 3 个左右手玩家都分配到左侧，得到 4 个左手和 10 个右手，这仍然无法形成大于 8 人的平衡团队。正确的推理必须考虑到部分平衡后，剩下的左右手玩家仍然可以配对。 

另一个边缘情况是根本没有左或右玩家时：

 输入：```
0 0 5
```正确答案是 4，而不是 5，因为必须移除一名球员才能保持相等的半场。 

这些案例表明，该结构首先是由平衡驱动，然后是配对。 

## 方法

 一个蛮力的想法是尝试从 0 到 2(l + r + a) 的所有可能的均匀团队规模，并检查我们是否可以使用可用的玩家准确分配一半左半右。 对于每个候选大小 2k，我们将尝试分配 k 个左槽和 k 个右槽，通过检查灵巧的玩家是否可以弥补缺陷来验证可行性。 这很快就会变得低效，因为对于每个 k，我们都会模拟分配，导致大约 O(n^2) 的行为，即使对于 n ≤ 100，这也是不必要的。 

关键的观察是该结构是贪婪的但可分解的。 我们首先使用强制分配：只左手和只右手的玩家自然会为各自的一方做出贡献。 唯一的灵活性在于双手灵巧的玩家。 他们的角色分为两个阶段：首先，他们解决左右计数之间的不平衡问题，然后任何剩余的双手灵巧的玩家只能对称配对使用，因为任何单个不成对的双手灵巧的分配都会打破平衡。 

这将问题简化为直接计算：通过首先均衡两侧，然后相等地扩展两侧来构建尽可能大的平衡对计数。

 ## 算法演练

 我们计算最大可能的配对数 k，其中最终团队规模为 2k。 

1. 将初始保证对计算为仅左玩家和仅右玩家的最小值。 这提供了一个基线平衡结构，不需要双手灵巧的玩家。 此时，一侧可能仍有未使用的容量。 
2. 计算该基线配对后两侧之间的不平衡度。 这种不平衡代表需要多少灵巧的玩家来平衡双方，以便进一步的对称扩张成为可能。 不平衡的方向并不重要，重要的是其大小。 
3. 使用双手灵巧的玩家来尽可能减少这种不平衡。 这里使用的每个灵巧的玩家都会将较小的一侧加一，而不影响较大的一侧。 这是唯一无需配对使用即可改变平衡的操作。 
4. 尽可能平衡后，要么双方变得平等，要么双手灵巧的玩家耗尽。 剩下的双手灵巧的玩家现在必须成对使用，因为分配给每一方的一个玩家可以保持平衡。 每个这样的对都会使团队规模增加 2，这意味着 k 增加 1。 
5. 最终答案是所得 k 的两倍。 

### 为什么它有效

 在每个阶段，我们都保持团队双方规模相等的不变性。 团队的任何有效扩展都必须保持这种平等。 双手灵巧的玩家是唯一可以解决不平衡问题或同时扩大双方规模的资源。 一旦不平衡被最小化，只有对称使用仍然是最佳的，因为不对称使用会重新引入不平衡并浪费潜在的对。 

这种结构确保了双手分配的重新安排不会产生比计算值更大的平衡团队。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    l, r, a = map(int, input().split())

    k = min(l, r)

    diff = abs(l - r)

    t = min(a, diff)
    k += t
    a -= t

    k += a // 2

    print(2 * k)

if __name__ == "__main__":
    solve()
```该解决方案首先锁定严格限制玩家的保证比赛。 然后，它使用灵巧的玩家来减少不平衡，因为这是实现进一步对称增长的唯一方法。 最后，任何剩余的双手灵巧的玩家都会成对消耗，每对都平等地增加双方的收益。 

一个微妙的实现点是整数除以 2 必须仅在不平衡解决之后应用。 提前这样做会在系统平衡之前错误地假设对称性。

 ## 边缘情况

 当根本没有玩家时，算法立即得出 k = 0，因为 min(l, r) 和所有后续贡献都为零。 这确保输出为 0，这是唯一有效的偶数团队规模。 

当系统已经平衡且l等于r时，不平衡为零，因此所有灵巧的玩家立即成对使用。 这直接扩大了团队，没有任何中间修正阶段。 

当双手灵巧的玩家少于不平衡状态时，只能实现部分平衡。 该算法正确地停止在 a 耗尽的点，留下仍然不相等的配置，因此在该点之后仅不允许对称配对，从而防止无效的高估。
