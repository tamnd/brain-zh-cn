[LeetCode 582 题](https://leetcode.com/problems/kill-process/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、树、深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题将操作系统中的进程建模为树结构。 每个进程只有一个父进程，但根进程除外，它没有父进程，由`ppid[i] = 0`。 

输入通过两个并行数组给出：

 -`pid[i]`代表进程的ID
 -`ppid[i]`表示同一进程的父进程ID

 这些数组一起描述了一个有根树，其中每个节点都是一个进程。 

当一个进程被杀死时，它的所有后代也必须被杀死。 这意味着如果我们删除树中的一个节点，则其子树中的每个节点也必须包含在结果中。 

任务是返回所有在给定的情况下将终止的进程ID`kill`进程被杀死。 输出顺序并不重要。 

例如，假设我们有：```
pid  = [1,3,10,5]
ppid = [3,0,5,3]
```这代表以下层次结构：```
3
├── 1
└── 5
    └── 10
```如果我们杀死进程`5`，然后处理`10`也必须被杀死，因为它是`5`。 

约束条件很重要：

 -`n`可以大到`5 * 10^4`- 进程ID是唯一的
 - 每个进程都有一个父进程
 - 输入始终形成有效的有根树
 - 的`kill`进程始终存在

 这些限制告诉我们几件事：

 - 我们需要一个接近线性时间的算法
 - 重复扫描阵列可能会太慢
 - 适当的树遍历技术，例如DFS或BFS
 - 我们应该将输入预处理为支持快速子查找的结构

 一些边缘情况很重要：

 - 杀死根进程，这应该杀死所有进程
 - 杀死一个叶节点，它应该只返回该节点
 - 形状像长链的树，可以强调递归DFS深度
 - 具有许多直接子进程的进程
 - 尽可能最小的输入，仅存在一个进程

 该问题保证输入有效，因此我们不需要处理循环或断开的组件。 

## 方法

 ### 蛮力方法

 一个天真的解决方案会重复扫描整个`ppid`数组来查找被杀死进程的子进程。 

例如：

 1. 从`kill`过程
 2. 扫描所有进程以查找其子进程
 3. 将这些子项添加到结果中
 4. 对于每个发现的子项，再次扫描数组以找到其子项
 5. 继续，直到找不到更多的后代

 这是有效的，因为每个后代最终都是通过重复的父子匹配而被发现的。 

然而，这种方法效率低下，因为每次处理一个节点时，我们都可能再次扫描整个数组。 在最坏的情况下，这会变成二次方。 

如果有`n`过程和树是倾斜的，我们可以执行`O(n)`扫描`O(n)`节点，导致`O(n^2)`时间复杂度。 

高达`50,000`进程，这可能会变得太慢。 

### 最佳方法

 关键的观察是输入自然地描述了一棵树，但数组的组织方式不是为了高效遍历。 

重要的优化是首先构建邻接表：```
parent -> list of children
```一旦我们有了这个结构，我们就可以有效地遍历以`kill`。 

这将问题转化为标准的树遍历问题。 

我们可以使用：

 - 深度优先搜索（DFS）
 - 广度优先搜索（BFS）

 两者工作得同样好，因为输出顺序并不重要。 

算法变为：

 1. 构建父进程到子进程的哈希图
 2.开始遍历`kill`3.拜访每一个可到达的后代
 4. 将访问过的进程添加到答案中

 由于每个节点和边仅处理一次，因此复杂度变为线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复扫描整个数组以查找子项 |
 | 最佳 | O(n) | O(n) | 构建邻接表并遍历子树一次 |

 ## 算法演练

 1. 创建一个名为的哈希图`children_map`其中每个键是一个父进程 ID，值是其子进程 ID 的列表。 

此预处理步骤将原始数组转换为有效的树表示。 如果没有这种结构，查找子项就需要重复扫描整个输入。 
2. 迭代`pid`和`ppid`同时阵列。 

对于每个进程：

 -`parent = ppid[i]`-`child = pid[i]`将子项添加到父项列表中`children_map`。 

完成此步骤后，我们可以立即检索任何进程的所有子进程。 
3. 初始化一个遍历结构。 

我们可以使用：

 - DFS 堆栈
 - BFS 的队列

 在此解决方案中，我们使用堆栈，因为它简单且高效。 
4. 按下`kill`进程入栈。 

这代表子树遍历的起点。 
5. 当堆栈不为空时：

 1. 从堆栈中弹出一个进程
 2.添加到结果列表中
 3. 从中检索其所有子项`children_map`4. 将这些孩子推入堆栈

 这保证了我们最终会访问被杀死进程的每个后代。 
6. 遍历结束后返回结果列表。 

此时，子树中的每个进程都以`kill`已收集。 

### 为什么它有效

 该算法之所以有效，是因为进程层次结构形成了一棵树。 每一个后代`kill`通过重复的父子遍历可以到达`kill`。 

邻接表保证了对子节点的高效访问，DFS 遍历保证了子树中的每个节点都被访问一次。 

由于杀死一个进程会递归地杀死所有后代，因此子树的根位于`kill`正是我们必须返回的进程集。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def killProcess(self, pid: List[int], ppid: List[int], kill: int) -> List[int]:
        children_map = defaultdict(list)

        # Build parent -> children mapping
        for child, parent in zip(pid, ppid):
            children_map[parent].append(child)

        result = []
        stack = [kill]

        # DFS traversal
        while stack:
            current = stack.pop()
            result.append(current)

            for child in children_map[current]:
                stack.append(child)

        return result
```实现首先使用构造邻接表`defaultdict(list)`。 这使我们能够有效地存储每个父进程的所有子进程。 

循环：```python
for child, parent in zip(pid, ppid):
```将输入数组中的相应元素配对并构建树表示。 

预处理后，算法使用堆栈执行迭代 DFS。 

堆栈开始于`kill`处理，因为这是我们需要删除的子树的根。 

在遍历循环内部：```python
current = stack.pop()
```检索下一个要处理的进程。 

我们立即将其添加到结果中，因为任何访问的节点都代表一个将被杀死的进程。 

然后我们检索当前进程的所有子进程并将它们推入堆栈以供将来处理。 

遍历将继续，直到没有可到达的后代为止。 

最后返回结果列表。 

使用迭代 DFS 代替递归 DFS 可以避免非常深的树的递归深度问题。 

## 解决方案```go
func killProcess(pid []int, ppid []int, kill int) []int {
	childrenMap := make(map[int][]int)

	// Build parent -> children mapping
	for i := 0; i < len(pid); i++ {
		parent := ppid[i]
		child := pid[i]

		childrenMap[parent] = append(childrenMap[parent], child)
	}

	result := []int{}
	stack := []int{kill}

	// DFS traversal
	for len(stack) > 0 {
		// Pop from stack
		n := len(stack) - 1
		current := stack[n]
		stack = stack[:n]

		result = append(result, current)

		for _, child := range childrenMap[current] {
			stack = append(stack, child)
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

邻接表是使用以下方法实现的：```go
map[int][]int
```它将每个父进程 ID 映射到子进程 ID 的切片。 

DFS堆栈是使用切片来实现的。 从切片末尾弹出可提供高效的堆栈行为。 

与 Python 的一个区别是 Go 没有内置的`defaultdict`，因此附加到不存在的映射键依赖于 Go 的切片零值行为。 

另一个区别是堆栈弹出期间的显式切片操作：```go
stack = stack[:n]
```这将在检索后删除最后一个元素。 

不存在整数溢出问题，因为进程 ID 的边界是`5 * 10^4`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个进程被添加到邻接表一次并被访问一次 |
 | 空间| O(n) | 邻接表、堆栈和结果表都最多可以存储 n 个进程 |

 预处理步骤迭代输入数组一次，这会花费`O(n)`。 

DFS 遍历也最多访问每个进程一次，贡献另一个进程`O(n)`。 

由于这些操作是连续的而不是嵌套的，因此总复杂度保持线性。 

邻接表存储了所有的父子关系，要求`O(n)`空间。 遍历堆栈和结果列表也可以增长到一定大小`n`在最坏的情况下。

 ## 边缘情况

 当被杀死的进程是树的根时，就会出现一种重要的边缘情况。 在这种情况下，系统中的每个进程都应该终止，因为所有节点都是根的后代。 有缺陷的实现可能会意外地忽略更深的后代或提前停止遍历。 DFS 遍历正确地访问了整个树，因为它会一直持续到堆栈变空为止。 

另一个重要的边缘情况是杀死叶节点。 叶子没有子节点，因此答案应仅包含节点本身。 某些实现错误地假设每个节点都有子节点，并且可能会尝试无效的查找。 使用`defaultdict(list)`Python 和 Go 中的零值切片可确保将丢失的子列表作为空集合安全处理。 

深链状树是另一个关键案例。 考虑这样的结构：```
1 -> 2 -> 3 -> 4 -> 5
```如果使用递归 DFS，在某些语言中，极深的树可能会面临堆栈溢出的风险。 迭代 DFS 实现通过使用显式堆栈数据结构完全避免了递归，从而使其对于最大约束大小是安全的。 

另一个微妙的边缘情况是无序输入。 这`pid`和`ppid`不保证数组按层次顺序出现。 这是一个幼稚的实现，假设父母出现在孩子可能失败之前。 独立于排序构建邻接表可以保证正确性，无论输入排列如何。
