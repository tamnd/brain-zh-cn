[LeetCode 540 题](https://leetcode.com/problems/single-element-in-a-sorted-array/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个排序的整数数组，其中每个值都恰好出现两次，除了一个仅出现一次的值。 我们的任务是找到这种独特的价值。 

重要的细节是数组已经排序。 由于重复项在排序数组中相邻出现，因此每个重复的数字形成一对相邻元素。 只有一个数字打破了这种配对模式。 

例如，在数组中：```
[1,1,2,3,3,4,4,8,8]
```数字`1`,`3`,`4`， 和`8`全部出现在相邻对中，而`2`仅出现一次。 

该问题还需要解决方案运行在`O(log n)`时间和`O(1)`额外的空间。 这个限制非常重要，因为它排除了直接的线性扫描和哈希图解决方案。 线性扫描需要`O(n)`时间，不满足对数时间要求。 

这些约束告诉我们一些有用的信息：

 - 数组长度可以大到`10^5`，所以效率很重要。 
- 保证数组恰好包含一个不重复的元素。 
- 每个其他元素恰好出现两次。 
- 数组已排序，强烈建议二分查找。 

一些边缘情况很重要：

 - 唯一元素可以出现在数组的开头。 
- 唯一元素可能出现在数组的末尾。 
- 数组只能包含一个元素。 
- 独特的元素可能出现在中间的某个地方并破坏正常的配对结构。 

在检查邻居时，尤其是在数组的开头或结尾附近，幼稚的实现很容易犯越界错误。 谨慎的索引处理是必要的。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是扫描数组并成对检查元素。 

由于数组已排序并且重复项连续出现，因此我们可以一次在数组中移动两个元素。 如果一对匹配，我们继续。 如果我们找到一个与其邻居不匹配的元素，则该元素就是答案。 

例如：```
[1,1,2,3,3]
```- 比较`1`和`1`, 有效对
 - 比较`2`和`3`, 不匹配
 - 因此`2`是独特的元素

 这种方法是正确的，因为每个重复元素必须出现在排序数组中其对的旁边。 此模式中断的第一个位置标识单个元素。 

然而，该方法需要线性扫描阵列，导致`O(n)`时间复杂度，违反了问题要求`O(log n)`时间。 

### 最佳二分搜索方法

 关键的观察结果是排序的重复结构遵循可预测的索引模式。 

在单个元素出现之前：

 - 每对的第一次出现出现在偶数索引处。 
- 第二次出现出现在奇数索引处。 

例子：```
Index: 0 1 2 3 4 5
Value: 1 1 2 2 3 3
```注意：

-`1`从索引开始`0`-`2`从索引开始`2`-`3`从索引开始`4`所有对的起始都是偶数。 

单个元素出现后，这种模式发生变化：```
Index: 0 1 2 3 4 5 6
Value: 1 1 2 3 3 4 4
```现在：

-`3`从索引开始`3`-`4`从索引开始`5`这对起始位置变得奇数。 

这种转变允许我们使用二分搜索。 通过检查配对模式在中点是否仍然正确，我们可以确定哪一侧包含单个元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 顺序扫描数组并比较相邻元素 |
 | 最佳| O(log n) | O(1) | O(1) | 使用二分搜索和索引奇偶校验属性 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`，表示当前二分查找范围。 

最初：```
left = 0
right = len(nums) - 1
```2. 继续二分查找，同时`left < right`。 

搜索空间缩小，直到只剩下一个索引。 
3. 计算中点：```
mid = (left + right) // 2
```4. 确保`mid`是均匀的。 

由于货币对通常从偶数索引开始，因此我们想要比较潜在的货币对起始位置。 

如果`mid`为奇数，减一：```
if mid % 2 == 1:
    mid -= 1
```5. 比较`nums[mid]`和`nums[mid + 1]`。 

有两种可能：

 - 如果它们相等，则到目前为止的所有对都正确对齐。 单个元素必须位于右侧。 
- 如果不相等，则配对结构已被破坏，因此单个元素位于左侧，包括`mid`。 
6. 相应地更新搜索边界。 

如果该对匹配：```
left = mid + 2
```否则：```
right = mid
```7. 最终，`left`和`right`收敛到同一个索引。 

该索引包含单个非重复元素。 
8. 返回`nums[left]`。 

### 为什么它有效

 该算法依赖于有效对在单个元素出现之前从偶数索引开始的不变量。 一旦遇到单个元素，配对对齐就会移动一个位置。 

通过强迫`mid`保持均匀并检查是否`nums[mid]`等于`nums[mid + 1]`，我们可以确定中断是发生在之前还是之后`mid`。 每次迭代将剩余搜索空间减半，保证对数时间复杂度。 

## Python 解决方案```python
from typing import List

class Solution:
    def singleNonDuplicate(self, nums: List[int]) -> int:
        left = 0
        right = len(nums) - 1

        while left < right:
            mid = (left + right) // 2

            if mid % 2 == 1:
                mid -= 1

            if nums[mid] == nums[mid + 1]:
                left = mid + 2
            else:
                right = mid

        return nums[left]
```实现首先初始化二分搜索边界。 循环继续，直到只剩下一个候选索引。 

在循环内部，通常计算中点。 由于有效的重复对应从偶数索引开始，因此代码通过减一来调整奇数中点值。 这保证了总是在一对的预期第一个和第二个元素之间进行比较。 

之间的比较`nums[mid]`和`nums[mid + 1]`确定配对结构是否保持完整。 

如果该对匹配，则单个元素必须位于更右侧，因为该对之前（包括该对）的所有内容都是有效的。 因此，左边界向前移动了两个位置。 

如果该对不匹配，则中断已经发生，这意味着单个元素位于或之前`mid`。 右边界也会相应更新。 

当循环结束时，两个指针都指向单个非重复元素。 

## 解决方案```go
func singleNonDuplicate(nums []int) int {
    left := 0
    right := len(nums) - 1

    for left < right {
        mid := (left + right) / 2

        if mid%2 == 1 {
            mid--
        }

        if nums[mid] == nums[mid+1] {
            left = mid + 2
        } else {
            right = mid
        }
    }

    return nums[left]
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 Go切片直接使用，无需额外分配内存，保留`O(1)`空间复杂度。 

对于整数溢出没有特别的担忧，因为问题约束对于标准整数算术来说足够小。 该实现还可以安全地访问`nums[mid + 1]`因为循环结构保证了`mid`永远不会成为最终索引。

 ## 边缘情况

 当数组仅包含一个元素时，会出现一种重要的边缘情况。 在这种情况下，单一值就是简单的答案。 该实现自然地处理了这个问题，因为二分搜索循环永远不会在以下情况下执行：`left == right`最初。 

当唯一元素出现在数组开头时，会出现另一个重要的边缘情况。 这种情况可能会暴露关于配对对齐的错误假设。 例如：```
[1,2,2,3,3]
```该算法正确地检测到第一个配对结构已经被破坏，并将搜索范围缩小到左侧。 

当唯一元素出现在数组末尾时，会出现第三种重要的边缘情况：```
[1,1,2,2,3]
```在检查接近末尾的邻居时，某些实现会错误地访问超出范围的索引。 该解决方案避免了该问题，因为`mid`始终调整为偶数索引并与`mid + 1`。 

另一个微妙的边缘情况涉及在二分搜索期间保持正确的奇偶校验。 如果中点未调整为偶数索引，则可能会与错误的伙伴元素进行比较，从而产生错误的结果。 显式奇偶校验校正可确保比较始终与预期的对边界对齐。
