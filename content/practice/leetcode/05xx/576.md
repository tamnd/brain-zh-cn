[LeetCode 576 题](https://leetcode.com/problems/out-of-boundary-paths/)

 **难度：** 🟡 中等
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算一个球在有限的移动次数内有多少种不同的方式离开网格的边界。 

我们给出了一个尺寸的网格`m x n`， 在哪里：

-`m`是行数
 -`n`是列数
 - 球从指定位置开始`(startRow, startColumn)`- 一步操作中，球可以移动：

 - 向上
 - 向下
 - 左
 - 右

 允许球越过网格的边界。 一旦它离开网格，这条路径就被认为是成功的，并有助于得出最终的答案。 

关键细节是我们最多可以使用**`maxMove`移动。 这意味着如果球在任意次数的移动中离开网格，则路径计数`1`最多`maxMove`。 

答案可能会变得非常大，因为每个位置的每一步都可以分为四个可能的方向。 因此，该问题需要返回模数答案：$10^9 + 7$约束条件很重要：

 -`m, n <= 50`-`maxMove <= 50`强力递归探索将生成：$4^{	ext{maxMove}}$可能的路径，当`maxMove = 50`。 

这立即表明许多子问题重复出现。 例如，以相同的剩余移动到达相同的单元将始终产生相同数量的未来逃生路径。 这种重叠结构使其成为一个经典的动态规划问题。 

一些边缘情况很重要：

 -`maxMove = 0`，不允许移动，所以答案一定是`0`- 从边界附近开始会产生许多直接的逃生路径
 - 非常小的网格，例如`1 x 1`原因几乎在各个方向都存在
 - 大量的移动次数会产生巨大的数字，因此必须一致地应用模算术
 - 重新访问单元格不得导致重复重新计算

 ## 方法

 ### 暴力递归搜索

 最直接的方法是递归地探索每一个可能的动作序列。 

从每个位置，我们尝试所有四个方向：

 - 向上
 - 向下
 - 左
 - 右

 如果移动离开网格，我们就算一条成功的路径。 

如果移动仍在网格内并且我们仍然有剩余的移动，我们将继续递归。 

这种方法是正确的，因为它明确地探索了球可以采取的每条有效路径。 

然而，它的效率极低。 递归树每次移动都会有四种分支，产生指数数量的状态。 

最坏情况的复杂度是：$O(4^{	ext{maxMove}})$这对于`maxMove = 50`。 

主要问题是重复计算。 相同状态：

 - 当前行
 - 当前列
 - 剩余步数

 可以通过许多不同的路径到达，但是暴力解决方案每次都会重新计算它。 

### 最优动态规划

 关键的见解是，一个国家的未来结果仅取决于：

 - 当前位置
 - 剩余移动次数

 如果我们已经知道逃生路径的数量`(row, col, remainingMoves)`，我们应该重用该结果而不是重新计算它。 

这自然会导致带有记忆的动态编程。 

对于每个州：`dp(row, col, movesRemaining)`我们计算：

 -`1`如果移动退出网格
 - 否则为所有四个递归方向的总和

 每个独特的状态都会被解决一次并被缓存。 

自：

 - 最多有`50 * 50 * 50`州
 - 每个状态恰好探索 4 个方向

 该解决方案变得足够有效。

 ## 算法演练

 1.定义递归函数`dfs(row, col, movesLeft)`。 

该函数返回球可以离开网格的方式数，从`(row, col)`和`movesLeft`其余的。 
2. 首先处理边界条件。 

如果`(row, col)`位于网格之外，我们已经成功退出边界，所以返回`1`。 
3. 处理移动耗尽情况。 

如果`movesLeft == 0`并且球仍在网格内，无法进一步移动，因此返回`0`。 
4. 检查该状态是否已被计算。 

由于许多路径可以重新访问相同的状态，因此记忆可以避免重复工作。 
5. 探索所有四个方向。 

对于每个动作：

 - 向上
 - 向下
 - 左
 - 右

 递归计算剩余移动少一步的逃生路径的数量。 
6. 对所有递归结果求和。 

因为数字可能会变得非常大，所以应用模`10^9 + 7`添加后。 
7. 将计算结果存储在记忆缓存中。 

这确保了将来对相同状态的调用立即返回。 
8. 开始递归`(startRow, startColumn, maxMove)`。 

### 为什么它有效

 该算法之所以有效，是因为每条有效路径都可以分解为更小的子问题。 从任何单元格开始，逃生路径的总数等于一次移动后来自其相邻单元格的逃生路径的总和。 记忆化保证每个状态只解决一次，而递归则确保计算每个可能的有效路径。 

## Python 解决方案```python
class Solution:
    def findPaths(
        self,
        m: int,
        n: int,
        maxMove: int,
        startRow: int,
        startColumn: int
    ) -> int:
        MOD = 10**9 + 7

        memo = {}

        directions = [
            (-1, 0),  # up
            (1, 0),   # down
            (0, -1),  # left
            (0, 1)    # right
        ]

        def dfs(row: int, col: int, moves_left: int) -> int:
            if row < 0 or row >= m or col < 0 or col >= n:
                return 1

            if moves_left == 0:
                return 0

            state = (row, col, moves_left)

            if state in memo:
                return memo[state]

            total_paths = 0

            for dr, dc in directions:
                next_row = row + dr
                next_col = col + dc

                total_paths += dfs(
                    next_row,
                    next_col,
                    moves_left - 1
                )

                total_paths %= MOD

            memo[state] = total_paths

            return total_paths

        return dfs(startRow, startColumn, maxMove)
```实现首先定义模常数和四个移动方向。 

这`memo`字典存储先前计算的状态。 每个键都是一个元组：```python
(row, col, moves_left)
```这唯一地标识了一个子问题。 

递归`dfs`函数首先检查球是否已经离开网格。 如果是，则返回`1`因为这条路成功逃脱了。 

如果没有剩余动作并且球仍在网格内，则函数返回`0`。 

在执行任何递归工作之前，该函数会检查当前状态是否已被计算。 如果有，则立即返回缓存的值。 

递归循环探索所有四个相邻位置。 将每个递归结果添加到`total_paths`，模运算可防止溢出。 

最后将结果存储在`memo`然后回来了。 

## 解决方案```go
func findPaths(m int, n int, maxMove int, startRow int, startColumn int) int {
	const MOD int = 1000000007

	type State struct {
		row   int
		col   int
		moves int
	}

	memo := make(map[State]int)

	directions := [][]int{
		{-1, 0},
		{1, 0},
		{0, -1},
		{0, 1},
	}

	var dfs func(int, int, int) int

	dfs = func(row int, col int, movesLeft int) int {
		if row < 0 || row >= m || col < 0 || col >= n {
			return 1
		}

		if movesLeft == 0 {
			return 0
		}

		state := State{row, col, movesLeft}

		if value, exists := memo[state]; exists {
			return value
		}

		totalPaths := 0

		for _, dir := range directions {
			nextRow := row + dir[0]
			nextCol := col + dir[1]

			totalPaths += dfs(nextRow, nextCol, movesLeft-1)
			totalPaths %= MOD
		}

		memo[state] = totalPaths

		return totalPaths
	}

	return dfs(startRow, startColumn, maxMove)
}
```Go 解决方案遵循与 Python 版本相同的递归记忆动态编程策略。 

定制`State`struct 被用作记忆键，因为 Go 映射需要可比较的键类型。 

递归函数是使用函数变量声明的，因此它可以递归地引用自身。 

每次加法后应用模运算以避免整数溢出。 

与 Python 不同，Go 没有内置的元组键，因此该结构干净而高效地满足了该目的。

 ## 边缘情况

 ### 零允许移动

 如果`maxMove = 0`，球根本无法移动。 即使起始位置与边界相邻，答案仍然必须是`0`因为退出至少需要一步。 

本案直接由以下人员处理：```
if moves_left == 0:
    return 0
```### 单细胞网格

 一个`1 x 1`网格是一个特殊的场景，因为每个可能的方向都会立即离开网格。 

例如：```
m = 1
n = 1
maxMove = 1
```所有四个方向都会成功退出，所以答案是`4`。 

This can expose bugs in boundary checking if out of bounds detection is implemented incorrectly.

 ### 大量移动计数

 与`maxMove = 50`，可能的路径数量增长得非常快。 

如果没有记忆，递归解决方案就变得不可行。 

此外，结果可能超出正常的整数范围，这就是为什么在每次加法之后应用模运算的原因：```
total_paths %= MOD
```即使对于非常大的计数，这也保证了正确性。
