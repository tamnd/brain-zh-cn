[LeetCode 555 题](https://leetcode.com/problems/split-concatenated-strings/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、贪婪

 ## 解决方案

 ## 问题理解

 问题给出了一个字符串数组，我们必须将它们排列成循环连接，同时保留字符串的原始顺序。 对于每个单独的字符串，我们可以将其保持原样，也可以在将其加入循环之前反转它。 

构造完这个环形弦后，我们可以在任意位置切断循环，将其转换为正常的线性弦。 在每种可能的配置中，我们必须返回字典顺序最大的结果字符串。 

重要的细节是有两个独立的选择：

 1. 对于每个字符串，选择原始版本或反转版本。 
2. 在循环串联中的某处选择剪切位置。 

输出是在做出最佳选择后可获得的最大词典字符串。 

例如，假设我们有：```
["abc", "xyz"]
```我们可以反转任一字符串：```
abc or cba
xyz or zyx
```一个有效的循环是：```
cbazyx
```因为绳子是圆形的，所以我们可以在任何地方切割它。 切割前`'z'`给出：```
zyxcba
```事实证明这是最大的可能答案。 

约束条件极其重要：

 - 最多 1000 个字符串
 - 所有字符串的总长度最多为 1000

 这意味着数据总量相对较小。 总字符数具有二次复杂度的算法是可以接受的。 然而，生成每一种可能的反转组合仍然太昂贵，因为有`2^n`反转配置。 

一些边缘情况很重要：

 - 单个字符串输入，其中答案只是字符串及其相反的更好者。 
- 其逆序在字典顺序上相同的字符串，例如`"aaa"`。 
- 最佳切割发生在字符串中间而不是边界的情况。 
- 反转局部较小的字符串在旋转后会产生全局较大的结果的情况。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的反转配置。 

为了`n`字符串，每个字符串有两种选择：

 - 原创
 - 逆转

 这创造了`2^n`总组合。 

对于每个组合：

 1. 构造循环字符串。 
2. 尝试每一个可能的切割位置。 
3. 生成结果线性字符串。 
4. 保留字典顺序最大的答案。 

这种方法是正确的，因为它明确枚举了每个有效配置和每个可能的剪切。 

然而，它太慢了。 即使只有1000根弦，`2^1000`配置无法一一列举。 

### 关键见解

 关键的观察是，对于每个字符串，我们只需要字典顺序上较大的版本：

 - 原始字符串
 - 它的相反

 为什么？ 

假设一个字符串贡献了最终答案中不在起始位置的部分。 在词典比较中，先字占后字。 因此，对于所有非起始字符串，选择字典顺序较大的方向始终是最佳的。 

唯一需要特殊处理的字符串是包含剪切位置的字符串，因为答案可能从该字符串的中间开始。 

所以策略就变成了：

 1. 将每个字符串预处理为按字典顺序排列的较大方向。 
2. 对于每个字符串：

 - 将其视为起始字符串。 
- 尝试该字符串的两个方向。 
- 尝试其中的每个切割位置。 
3. 构建候选答案并更新最佳结果。 

这大大减少了搜索。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × L^2) | O(2^n × L^2) | O(L) | 枚举每一个逆转组合和每一次切割 |

 这里，`L`是所有字符串的字符总数。 

## 算法演练

 ### 第 1 步：标准化每个字符串

 对于数组中的每个字符串：

 - 计算其相反数。 
- 保留字典中较大的那个。 

例如：```
"abc" -> "cba"
"xyz" -> "zyx"
```这是有效的，因为任何不包含剪切的字符串都应该贡献其最佳可能的排序。 

### 步骤 2：迭代每个可能的起始字符串

 每个字符串可能包含剪切位置。 

假设索引`i`被选为起始字符串。 

我们必须考虑这两点：

 - 标准化版本
 - 反向版本

 因为最佳切割可能需要任一方向。 

### 步骤 3：尝试当前字符串内的每个剪切位置

 如果当前候选字符串是：```
current
```然后每个位置`k`里面`current`可能成为最终答案的开始。 

结果字符串变为：```
current[k:] +
remaining_strings +
current[:k]
```在哪里`remaining_strings`按循环顺序附加。 

### 步骤 4：构建候选字符串

 候选人被构造为：

 1.当前字符串剪切后的后缀。 
2. 所有后续的标准化字符串。 
3. 所有先前的标准化字符串。 
4. 当前字符串在剪切前的前缀。 

这模拟了在位置切割循环`k`。 

### 第 5 步：更新最佳答案

 将生成的候选答案与当前最佳答案进行比较。 

如果候选人的字典顺序更大，请更新答案。 

### 为什么它有效

 关键的不变量是，除了包含剪切的字符串之外的每个字符串都应始终使用其字典顺序的最大方向。 任何较小的方向只会使最终结果中稍后出现的字符变得更糟。 

唯一的不确定性来自于发生剪切的字符串，因为答案开始于字符串内部。 通过详尽地尝试该字符串的每个位置和两个方向，该算法探索每个有意义的候选者，同时避免反转组合的指数爆炸。 

## Python 解决方案```python
from typing import List

class Solution:
    def splitLoopedString(self, strs: List[str]) -> str:
        # Normalize each string to its lexicographically larger form
        normalized = [max(s, s[::-1]) for s in strs]

        best = ""

        for i, original in enumerate(strs):
            # Try both orientations for the current string
            for current in [original, original[::-1]]:
                for cut in range(len(current)):
                    candidate = []

                    # Start from the cut position
                    candidate.append(current[cut:])

                    # Add strings after current
                    for j in range(i + 1, len(strs)):
                        candidate.append(normalized[j])

                    # Add strings before current
                    for j in range(i):
                        candidate.append(normalized[j])

                    # Add remaining prefix of current
                    candidate.append(current[:cut])

                    candidate_string = "".join(candidate)

                    if candidate_string > best:
                        best = candidate_string

        return best
```该实现首先将每个字符串预处理为按字典顺序排列的较大方向。 此步骤大大减少了搜索空间，因为所有非起始字符串应始终贡献其最大可能值。 

外循环选择哪个字符串包含剪切位置。 对于该字符串，算法显式检查原始方向和反向方向，因为剪切可能会改变最佳方向。 

内部循环迭代当前字符串内的每个可能的剪切索引。 对于每次切割：

 - 剪切后的后缀成为开头。 
- 所有剩余的标准化字符串均按循环顺序附加。 
- 剪切前的前缀附加在末尾。 

每个构建的候选者都会按字典顺序与迄今为止找到的最佳答案进行比较。 

因为总输入长度最多为1000，所以直接构造这些候选字符串就足够高效了。 

## 解决方案```go
package main

func splitLoopedString(strs []string) string {
	normalized := make([]string, len(strs))

	for i, s := range strs {
		rev := reverse(s)
		if rev > s {
			normalized[i] = rev
		} else {
			normalized[i] = s
		}
	}

	best := ""

	for i, s := range strs {
		candidates := []string{s, reverse(s)}

		for _, current := range candidates {
			for cut := 0; cut < len(current); cut++ {
				candidate := current[cut:]

				for j := i + 1; j < len(strs); j++ {
					candidate += normalized[j]
				}

				for j := 0; j < i; j++ {
					candidate += normalized[j]
				}

				candidate += current[:cut]

				if candidate > best {
					best = candidate
				}
			}
		}
	}

	return best
}

func reverse(s string) string {
	chars := []byte(s)

	left := 0
	right := len(chars) - 1

	for left < right {
		chars[left], chars[right] = chars[right], chars[left]
		left++
		right--
	}

	return string(chars)
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 主要区别是使用字节片手动反转字符串。 

Go 字符串是不可变的，因此反转需要将字符串转换为可变字节切片，交换字符，然后转换回字符串。 

由于该问题仅保证小写英文字母，因此基于字节的反转是完全安全的。

 ## 边缘情况

 ### 单字符串输入

 当仅存在一个字符串时，循环完全由该字符串组成。 该算法仍然必须考虑两个方向和每个切割位置。 有缺陷的实现可能只是返回字符串及其反向之间按字典顺序排列的较大者，但最好的答案可能来自切割后的旋转。 

该实现正确地处理了这个问题，因为它仍然迭代每个剪切位置。 

### 最佳切割发生在字符串内部

 一个常见的错误是假设切割仅发生在琴弦之间。 实际上，剪切可能发生在任何角色位置。 

例如：```
["abc", "xyz"]
```最佳答案从中间开始`"zyx"`。 

该实现显式地迭代每个候选字符串内的每个索引，确保不会错过任何有效的旋转。 

### 反向选择改变全局最优

 有时，局部看起来较小的字符串在旋转时会产生更大的整体结果。 

例如：```
"abc" -> "cba"
```该算法通过始终尝试包含剪切的字符串的两个方向来处理此问题，同时贪婪地将所有其他字符串固定为其字典顺序的最大方向。 

这保证了考虑全局最优结果。
