[LeetCode 517 题](https://leetcode.com/problems/super-washing-machines/)

 **难度：** 🔴难
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一系列洗衣机，其中每台机器都包含一定数量的衣服。 在一步操作中，我们可以选择机器的任何子集，并且每台选定的机器都可以同时将一件衣服传递到其相邻机器之一。 

目标是使用最少的操作次数使每台洗衣机容纳相同数量的衣服。 如果无法均匀分配衣服，我们必须返回`-1`。 

输入数组`machines`代表每台洗衣机从左到右的衣服数量。 例如：```
machines = [1,0,5]
```意思是：

 - 机器 0 有 1 件衣服
 - 机器 1 有 0 件衣服
 - 机器2有5件衣服

 输出是一个整数，表示平衡所有机器所需的最小移动次数。 

关键细节是，在一次移动过程中，多台机器可以同时传送衣服。 这意味着我们不会独立计算个人着装变动。 相反，我们计算同步传输轮数。 

约束条件很重要：

 -`1 <= n <= 10^4`-`0 <= machines[i] <= 10^5`这些限制告诉我们：

 - 我们不能天真地模拟每一个可能的动作。 
- 我们需要一种接近线性时间的算法。 
- 由于礼服总数可能会变大，因此需要仔细推理。 

一个重要的观察结果是，只有当衣服总数能除以机器数量时，平衡才有可能。 

例如：```
machines = [0,2,0]
total = 2
n = 3
```自从`2 % 3 != 0`，平均分配是不可能的。 

重要的边缘情况包括：

 - 一台机器，已经平衡。 
- 所有机器已经平等。 
- 由于总数不能被整除而无法平衡的情况`n`。 
- 大量不平衡集中在一台机器上。 
- 服装必须经过许多中间机器的链条。 

## 方法

 ### 蛮力方法

 蛮力策略将明确模拟重新分配过程。 

在每一步中，我们都可以识别出有多余衣服的机器，并将衣服转移到有缺陷的相邻机器。 我们将继续下去，直到所有机器都达到平衡。 

这种方法在概念上是正确的，因为它模仿了问题中描述的实际过程。 然而，它很快就会变得低效，因为：

 - 每一步可能有多种可能的转移选择。 
- 衣服可能需要长距离移动。 
- 单独模拟每个动作可能需要大量时间。 

在最坏的情况下，移动和状态转换的数量可能会变得非常大。 根据实现的不同，直接模拟可能会接近二次甚至指数行为。 

给定`n = 10^4`，这样的方法是不可行的。 

### 最佳方法的关键见解

 最佳解决方案来自于理解流量平衡而不是模拟移动。 

假设每台机器最终都应该包含：```
target = total_dresses / n
```对于每台机器：```
difference = machines[i] - target
```- 正差意味着机器必须送出衣服。 
- 负差值意味着机器必须收到衣服。 

更深入的见解是，不平衡会跨机器边界传播。 

定义运行余额：```
prefix_balance += machines[i] - target
```该值表示有多少件衣服必须流过机器之间的边界`i`和机器`i + 1`。 

有两个数量很重要：

 1. 运行余额的绝对值。 

这测量了有多少件衣服必须通过边界。 
2.机器的局部剩余。 

一台有大量剩余的机器可能需要多次移动，因为它每次只能发送一件衣服。 

因此答案是：```
max(
    abs(prefix_balance),
    machines[i] - target
)
```接管所有机器。 

这导致了线性时间贪婪解决方案。

 ## 算法演练

 1. 计算所有机器上的衣服总数。 

这决定了平衡是否可能。 
2. 检查整除性。 

如果`total % n != 0`， 返回`-1`。 

平等分配要求每台机器最终得到完全相同数量的衣服。 
3. 计算每台机器的目标服装数量。```
target = total // n
```4.初始化两个变量：

 -`running_balance = 0`-`answer = 0`运行平衡跟踪跨边界的净服装流量。 
5. 迭代每台机器。 

对于每台机器：```
difference = machines[i] - target
```这告诉我们这台机器必须赠送或接收多少件衣服。 
6. 更新运行余额。```
running_balance += difference
```如果运行平衡为正，则额外的衣服必须向右移动。 

如果为负，则衣服必须向左移动。 
7.更新答案。 

在每个位置：```
answer = max(
    answer,
    abs(running_balance),
    difference
)
```我们考虑两者：

 - 通过边界的流量
 - 机器的本地发送能力
 8. 返回最终答案。 

### 为什么它有效

 运行平衡代表了必须跨越边界才能实现全局平衡的礼服的确切数量。 由于每次移动只能从机器中穿过一件衣服，因此所需的移动次数必须至少为最大边界流。 

同样，如果一台机器有剩余`k`，它至少需要`k`因为每次移动只能发送一件衣服。 

该算法计算所有机器和所有边界施加的最严格下界。 该界限是可以实现的，因此它是最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMinMoves(self, machines: List[int]) -> int:
        total_dresses = sum(machines)
        num_machines = len(machines)

        if total_dresses % num_machines != 0:
            return -1

        target = total_dresses // num_machines

        running_balance = 0
        minimum_moves = 0

        for dresses in machines:
            difference = dresses - target
            running_balance += difference

            minimum_moves = max(
                minimum_moves,
                abs(running_balance),
                difference
            )

        return minimum_moves
```该实现首先计算衣服的总数并验证是否可以平均分配。 如果总数不能在所有机器之间平均分配，则该函数立即返回`-1`。 

接下来，算法计算每台机器应包含的目标衣服数量。 

变量`running_balance`当我们从左到右扫描时，跟踪有多少件衣服必须穿过当前边界。 正平衡意味着多余的衣服必须继续向右移动。 负余额意味着左侧仍然需要右侧的衣服。 

对于每台机器，我们计算：```python
difference = dresses - target
```该值衡量当地盈余或赤字。 

最终答案使用三个量进行更新：

 - 当前答案
 - 绝对运行平衡
 - 当地盈余

 这些值中的最大值决定了所需的最小移动次数。 

由于该算法仅扫描数组一次，因此它在线性时间内高效运行。 

## 解决方案```go
func findMinMoves(machines []int) int {
    totalDresses := 0
    numMachines := len(machines)

    for _, dresses := range machines {
        totalDresses += dresses
    }

    if totalDresses%numMachines != 0 {
        return -1
    }

    target := totalDresses / numMachines

    runningBalance := 0
    minimumMoves := 0

    for _, dresses := range machines {
        difference := dresses - target
        runningBalance += difference

        minimumMoves = max(
            minimumMoves,
            max(abs(runningBalance), difference),
        )
    }

    return minimumMoves
}

func abs(x int) int {
    if x < 0 {
        return -x
    }
    return x
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

一个区别是 Go 不提供内置的`abs`或者`max`整数函数，因此辅助函数是手动实现的。 

Go 中的切片的行为类似于动态数组，因此迭代`machines`很简单使用`range`。 

整数溢出在这里不是问题，因为约束保持在 Go 的标准整数范围内。

 ## 边缘情况

 一种重要的边缘情况是不可能实现平衡，因为衣服总数无法除以机器数量。 幼稚的实现可能仍会尝试重新分配并产生错误的答案。 该实现通过立即检查整除性并返回来避免这种情况`-1`在进行任何进一步处理之前。 

另一个重要的情况是所有机器都已经平衡。 例如：```
[5,5,5,5]
```在这种情况下，每台机器已经包含了目标数量的衣服。 运行余额始终保持为零，算法正确返回`0`。 

当一台机器有大量剩余时，就会出现第三种微妙的边缘情况。 例如：```
[100000,0,0,0]
```尽管衣服可以同时移动，但一台机器每次移动只能发送一件衣服。 该算法使用局部剩余项正确地解释了这一点：```
difference = machines[i] - target
```如果没有此检查，实现可能会低估所需的移动次数。 

另一个棘手的情况涉及跨边界的巨大累积不平衡。 即使没有一台机器有大量剩余，许多衣服可能仍然需要跨越同一个边界。 运行平衡捕获了这一确切要求，确保算法正确处理长距离重新分配链。
