 **难度：** 🟡 中等
 **主题：** 数组、哈希表、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们在二进制数组中找到**连续子数组的最大长度**，其中`0`沙`1`s 相等。 

连续子数组意味着元素必须连续出现在原始数组中。 我们不允许重新排列元素或跳过索引。 目标是检查所有可能的连续段并确定哪一个包含相同数量的`0`和`1`，然后返回最长的该段的长度。 

输入是一个二进制数组`nums`，意味着每个元素都是`0`或者`1`。 输出是一个整数，表示最长有效连续子数组的长度。 

例如：

 - 在`[0,1]`，整个数组有一个`0`和一个`1`，所以答案是`2`。 
- 在`[0,1,0]`，完整数组有两个`0`s 和一`1`，这是不平衡的。 然而，`[0,1]`和`[1,0]`是平衡的，所以最大长度是`2`。 

约束条件很重要：

 -`1 <= nums.length <= 10^5`- 每个值都是`0`或者`1`输入大小可以大到`100,000`，它立即告诉我们`O(n²)`或者`O(n³)`解决方案可能会太慢。 我们需要一个在大致线性时间内运行的算法，理想情况下`O(n)`。 

有几个重要的边缘情况需要预先考虑。 一个数组只包含`0`或仅`1`s 永远无法形成有效的平衡子数组，因此结果应该是`0`。 非常小的数组，比如length`1`，也不能包含相同数量的`0`和`1`。 当最长的有效子数组从索引处开始时，会发生另一种微妙的情况`0`，这需要在执行中谨慎处理，避免一错再错。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是检查每个可能的连续子数组并计算有多少个`0`沙`1`它包含。 

我们可以使用两个嵌套循环。 外循环选择起始索引，内循环扩展结束索引。 对于每个子数组，我们计算`0`沙`1`s 并检查它们是否相等。 如果是，我们会更新最大长度。 

这种方法是正确的，因为它显式地评估每个连续的子数组，保证最终找到最长的有效子数组。 

然而，对于给定的约束来说它太慢了。 有`O(n²)`子数组，并且计算每个子数组内的元素可以采取`O(n)`时间，导致`O(n³)`复杂。 即使使用前缀和来减少计数`O(1)`，该算法仍然需要`O(n²)`时间，这对于`n = 10^5`。 

### 最优方法，前缀和与哈希图

 关键的观察是我们实际上不需要计算`0`沙`1`分别。 

相反，我们可以转变问题：

 - 治疗`0`作为`-1`- 对待`1`作为`+1`现在，只要子数组具有相同数量的`0`沙`1`s，其累计和变为`0`。 

为什么这有效？ 

假设一个子数组包含：

 -`k`一个 → 贡献`+k`-`k`零→贡献`-k`总计变为：`(+k) + (-k) = 0`这将问题转化为寻找**和为零的最长子数组**。 

我们可以使用前缀和和哈希图有效地解决这个问题。 

如果相同的累积和出现在两个不同的索引处，则这些索引之间的元素之和必须为零。 

例如：```
Prefix sum at i = 3 → 2
Prefix sum at j = 8 → 2
```这意味着子数组`(i+1 ... j)`有总和`0`， 因为：```
prefix[j] - prefix[i] = 0
```我们将每个前缀和的**第一次出现**存储在哈希映射中。 当我们再次看到相同的总和时，我们计算索引之间的距离并更新最大长度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或 O(n³) | O(1) | O(1) | 显式检查每个子数组 |
 | 最佳| O(n) | O(n) | 使用前缀和和哈希图查找重复余额 |

 ## 算法演练

 1. 初始化一个哈希图来存储每个累积余额的**首次出现索引**。 

我们从以下开始：```
{0: -1}
```这很重要，因为它处理有效子数组从索引开始的情况`0`。 平衡为`0`在概念上处理任何元素之前位于索引处`-1`。 
2.初始化两个变量：

 -`balance = 0`-`max_length = 0`这`balance`跟踪之间的累积差异`1`沙`0`s。 
3. 从左到右遍历数组。 

在每个索引处：

 - 如果`nums[i] == 1`， 添加`1`到平衡。 
- 如果`nums[i] == 0`, 减去`1`来自余额。 
4. 检查此余额以前是否见过。 

如果哈希映射中已经存在余额，则意味着前一个出现的子数组与当前索引之间的子数组具有相同的数量`0`沙`1`s。 

计算：```
current_length = current_index - first_occurrence_index
```然后更新最大长度。 
5. 如果以前从未见过该余额，则存储其索引。 

我们只存储**第一次出现**，因为较早的索引会产生更长的子数组。 
6. 继续，直到处理完整个数组。 
7. 返回`max_length`。 

### 为什么它有效

 该算法依赖于前缀和不变量。 如果两个指数的累计余额相同，则这些指数之间元素的净贡献为零。 自从`0`贡献`-1`和`1`贡献`+1`，净和为零意味着相等的数量`0`沙`1`s。 通过存储每个余额最早出现的时间，我们最大化了有效子数组的长度。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaxLength(self, nums: List[int]) -> int:
        first_occurrence = {0: -1}
        balance = 0
        max_length = 0

        for index, num in enumerate(nums):
            if num == 1:
                balance += 1
            else:
                balance -= 1

            if balance in first_occurrence:
                current_length = index - first_occurrence[balance]
                max_length = max(max_length, current_length)
            else:
                first_occurrence[balance] = index

        return max_length
```实现首先创建一个名为的字典`first_occurrence`，它存储每个余额出现的最早索引。 条目`{0: -1}`已预加载，以便从索引开始的子数组`0`自然地处理。 

变量`balance`跟踪之间的运行差异`1`沙`0`s。 每当我们遇到一个`1`，我们增加平衡，每当我们遇到`0`，我们减少它。 

对于每个索引，我们检查当前余额之前是否出现过。 如果有，则较早索引和当前索引之间的段包含相同数量的`0`沙`1`s。 我们计算它的长度并更新`max_length`。 

如果余额是新的，我们存储其索引。 重要的是，我们只记录第一次出现，因为较早的索引会产生更长的子数组。 

最后，我们返回找到的最大长度。 

## 解决方案```go
func findMaxLength(nums []int) int {
	firstOccurrence := map[int]int{
		0: -1,
	}

	balance := 0
	maxLength := 0

	for index, num := range nums {
		if num == 1 {
			balance++
		} else {
			balance--
		}

		if firstIndex, exists := firstOccurrence[balance]; exists {
			currentLength := index - firstIndex
			if currentLength > maxLength {
				maxLength = currentLength
			}
		} else {
			firstOccurrence[balance] = index
		}
	}

	return maxLength
}
```Go 实现遵循与 Python 版本相同的算法结构。 一个`map[int]int`用于存储每个余额的第一次出现。 Go 地图需要使用显式的存在检查`value, exists := map[key]`图案。 

这里不用担心整数溢出，因为余额只能在`-n`和`n`，这完全在 Go 的整数限制内`n <= 10^5`。 

与 Python 不同，Go 不区分`nil`和空切片在这里很重要，因为问题保证输入中至少有一个元素。

 ## 边缘情况

 ### 没有有效子数组的数组

 一个数组只包含`0`或仅`1`s 不可能包含相同数量的两个值。 如果前缀和处理不正确，幼稚的实现可能会意外返回非零值。 此实现正确返回`0`因为重复的平衡不会产生有效的长度。 

### 从索引零开始的有效子数组

 错误的常见来源是忘记处理从第一个索引开始的子数组。 例如，`[0,1]`应该返回`2`。 无需初始化哈希图`{0: -1}`，算法会错过这种情况。 实现明确包含此设置以确保正确的行为。 

### 同一余额多次出现

 有时，同一个余额会出现多次。 例如，在`[0,1,0,1]`， 平衡`0`反复出现。 一个错误是覆盖哈希映射中最早的索引，这会减少可能的子数组长度。 该实现通过仅存储每个余额的**第一次出现**来避免这种情况，保证考虑最大可能的距离。 

### 非常大的输入

 自从`nums.length`可以达到`100,000`，二次解将会超时。 此实现可以有效地处理大型输入，因为它仅执行一次数组传递并使用恒定时间哈希映射操作，使其可扩展到问题限制。
