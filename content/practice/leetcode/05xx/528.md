 **难度：** 🟡 中等
 **主题：** 数组、数学、二分查找、前缀和、随机

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个支持**加权随机采样**的数据结构。 

给你一个数组`w`，其中每个元素代表索引的 **权重**。 选择概率取决于其权重，而不是以相同的概率选择每个指标。 

例如：

 - 如果`w = [1, 3]`- 总重量 =`1 + 3 = 4`- 指数`0`应该以概率选择`1/4`- 指数`1`应该以概率选择`3/4`挑战在于实施该方法`pickIndex()`这样重复的呼叫在统计上就遵循这些概率。 

换句话说，我们需要模拟一个概率分布，其中较大的权重使得索引更有可能被选择。 

输入包括：

 - 构造函数`Solution(w)`初始化数据结构。 
- 一个方法`pickIndex()`返回一个有效索引`[0, len(w) - 1]`。 

关键要求是选择必须是**随机但加权**。 

这些约束给了我们关于效率的重要提示：

 -`w.length <= 10^4`-`pickIndex()`最多被调用`10^4`次
 -`w[i] <= 10^5`自从`pickIndex()`可能会被调用很多次，每次调用都从头开始重新计算概率是低效的。 我们应该在初始化时对信息进行一次预处理，使每次查询都高效。 

一个重要的观察结果是，所有权重都是**正整数**，这意味着每个索引总是有非零的被选择概率。 这消除了涉及零概率区间的极端情况。 

一些可能导致简单实施失败的边缘情况包括：

 - 单元素数组，例如`[1]`，其中唯一有效的答案是`0`。 
- 分布非常不均匀，例如`[1, 100000]`，其中一个索引应主导概率空间。 
- 重复调用的大型数组`pickIndex()`，其中较差的性能会变得明显。 

该问题保证了有效的正权重，因此我们不需要处理负值或空数组。 

## 方法

 ### 蛮力方法

 一种简单的方法是显式构建一个加权池。 

对于每个索引`i`，将其插入到辅助列表中`w[i]`次。 

例如：```
w = [1, 3]

Expanded array:
[0, 1, 1, 1]
```然后`pickIndex()`只需在此扩展数组中选择一个随机位置。 

这是有效的，因为频率直接对应于概率：

 - 索引`0`出现一次
 - 索引`1`出现三次

 因此，索引`1`被选择的次数是原来的三倍。 

尽管正确，但当权重很大时，这种方法就变得不切实际。 

例如：```
w = [100000, 100000]
```扩展后的数组需要`200000`元素。 

自从：```
sum(w) can be as large as 10^9
```这个解决方案太占用内存了。 

### 关键见解

 我们可以将权重视为**数轴上的范围**，而不是物理扩展加权数组。 

认为：```
w = [1, 3, 2]
```我们创建前缀和：```
[1, 4, 6]
```这表示间隔：

 | 索引 | 范围 |
 | --- | --- |
 | 0 | [1] |
 | 1 | [2,4]|
 | 2 | [5,6]|

 现在想象一下生成一个随机整数：```
target ∈ [1, totalWeight]
```如果：```
target = 3
```然后它位于索引内`1`的范围。 

问题变成：

 > 查找第一个前缀和大于等于`target`。 

由于前缀和已排序，因此我们可以使用**二分搜索**。 

这给出：

 - 预处理：`O(n)`- 每个查询：`O(log n)`这更有效率。

 ## 算法演练

 ### 最优算法：前缀求和+二分查找

 1. 在初始化期间，计算**前缀和数组**。 

每个位置存储直到该索引的权重的累积和。 

例子：```
w = [1, 3, 2]

prefix = [1, 4, 6]
```这会将权重转换为可搜索的区间。 
2. 存储总重量。 

最后一个前缀和等于总概率质量：```
total = 6
```3. 什么时候`pickIndex()`被调用，生成一个包含范围内的随机整数：```
[1, total]
```该范围内的每个数字代表一个概率槽。 
4. 使用二分查找查找第一个大于或等于随机数的前缀和。 

例子：```
target = 5
prefix = [1, 4, 6]
```二分查找发现：```
6 >= 5
```对应索引`2`。 
5. 返回该索引。 

由于间隔与权重大小成正比，因此较大的权重会占用更多的随机数槽，因此会更频繁地被选择。 

### 为什么它有效

 前缀和数组划分范围`[1, totalWeight]`分成长度等于其权重的连续间隔。 

如果索引`i`有重量`w[i]`，那么它恰好拥有`w[i]`概率空间中的整数。 由于每个随机数的可能性相同，因此落在索引内的概率`i`的间隔为：$$\frac{w[i]}{\text{sum}(w)}$$二分查找正确地识别出哪个区间包含随机数，保证了所需的加权概率分布。 

## Python 解决方案```python
from typing import List
import random
import bisect

class Solution:

    def __init__(self, w: List[int]):
        self.prefix_sums = []
        running_sum = 0

        for weight in w:
            running_sum += weight
            self.prefix_sums.append(running_sum)

        self.total_weight = running_sum

    def pickIndex(self) -> int:
        target = random.randint(1, self.total_weight)

        return bisect.bisect_left(self.prefix_sums, target)

# Your Solution object will be instantiated and called as such:
# obj = Solution(w)
# param_1 = obj.pickIndex()
```构造函数通过计算前缀和来预处理输入数组。 维护运行累积总计，并将每个累积值附加到`self.prefix_sums`。 

例如：```python
w = [1, 3, 2]
```变成：```python
prefix_sums = [1, 4, 6]
```变量`self.total_weight`存储最大可能的随机数。 

里面`pickIndex()`，我们生成一个均匀随机整数`1`和`total_weight`。 该随机值表示加权概率空间中的位置。 

然后我们使用`bisect_left()`找到第一个大于或等于目标的前缀和。 由于前缀和数组已排序，因此二分查找的运行时间为对数。 

例如：```python
prefix = [1, 4, 6]
target = 4
```二分查找返回索引`1`，对应于区间`[2,4]`。 

## 解决方案```go
package main

import (
	"math/rand"
	"sort"
)

type Solution struct {
	prefixSums []int
	totalWeight int
}

func Constructor(w []int) Solution {
	prefixSums := make([]int, len(w))
	runningSum := 0

	for i, weight := range w {
		runningSum += weight
		prefixSums[i] = runningSum
	}

	return Solution{
		prefixSums: prefixSums,
		totalWeight: runningSum,
	}
}

func (this *Solution) PickIndex() int {
	target := rand.Intn(this.totalWeight) + 1

	index := sort.Search(len(this.prefixSums), func(i int) bool {
		return this.prefixSums[i] >= target
	})

	return index
}

/**
 * Your Solution object will be instantiated and called as such:
 * obj := Constructor(w);
 * param_1 := obj.PickIndex();
 */
```Go 实现遵循相同的想法，但使用 Go 标准库实用程序。 

而不是Python的`bisect_left`, Go 使用`sort.Search`，它对索引执行二分搜索。 回调函数检查前缀和是否位于位置`i`足够大以包含随机目标。 

随机数生成略有不同：```go
rand.Intn(totalWeight) + 1
```这会产生一个包含范围内的数字：```go
[1, totalWeight]
```与 Python 实现相匹配。 

使用 Go 切片代替 Python 列表，并且整数是安全的，因为最大总权重：```go
10^4 × 10^5 = 10^9
```很适合 Go 的整数范围。

### 示例 2

 输入：```
w = [1, 3]
```#### 初始化

 | 步骤| 重量 | 运行总和 | 前缀和 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | [1] |
 | 2 | 3 | 4 | [1, 4] |

 最终状态：```
prefix_sums = [1, 4]
total_weight = 4
```概率区间：

 | 索引 | 重量 | 间隔 |
 | --- | --- | --- |
 | 0 | 1 | [1] |
 | 1 | 3 | [2,4]|

 认为：```
target = 3
```二分查找进行：

 | 左| 对| 中| 前缀[中] | 决定|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 1 | 向右移动 |
 | 1 | 1 | 1 | 4 | 发现 |

 结果：```
return 1
```如果：```
target = 1
```然后索引`0`被选中。 

因为索引`1`拥有三个概率槽，而索引`0`仅拥有一个，重复调用自然会接近预期概率：```
P(0) = 1/4
P(1) = 3/4
```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n)`初始化，`O(log n)`每`pickIndex()`| 前缀和构建一次，二分查找是对数 |
 | 空间|`O(n)`| 存储前缀和数组 |

 预处理步骤扫描输入数组一次以计算累积和，需要线性时间。 每次致电`pickIndex()`对前缀和执行二分搜索，将查找时间减少到对数复杂度。 由于我们为每个元素存储一个前缀和，因此额外的内存使用量是线性的。

 ## 边缘情况

 ### 单元素数组

 像这样的案例：```
w = [1]
```如果二分搜索假设存在多个元素，则可能会暴露索引错误。 由于只有一个有效区间，因此每个随机数都必须映射到索引`0`。 

我们的实现自然地处理了这个问题，因为前缀和数组变为：```
[1]
```并且二分查找总是返回`0`。 

### 权重极度倾斜

 考虑：```
w = [1, 100000]
```幼稚的实现可能会出现溢出或概率错误。 

我们的区间表示完全避免了这个问题：```
prefix = [1, 100001]
```第二个索引仅拥有大部分概率空间，因此按预期更频繁地选择它。 

### 大量通话

 自从`pickIndex()`可能会被召集到`10^4`次，重复重新计算累积权重会浪费时间。 

通过在构造函数中对前缀和进行一次预处理，每个查询都变成了高效的二分搜索：```
O(log n)
```即使在最大限制下，这也能确保强大的性能。
