 # LeetCode 556 - 下一个更大元素 III

 ## 问题理解

 这个问题要求我们找到严格大于给定整数的最小整数`n`，同时使用与`n`。 

换句话说，我们可以重新排列号码的数字，但不能添加或删除数字。 在所有可能产生更大数字的重新排列中，我们必须返回最小的有效数字。 

例如，如果`n = 12`，可能的重新排列是：

 -`12`-`21`唯一大于的数`12`是`21`，所以答案是`21`。 

如果`n = 21`，重新排列为：

 -`21`-`12`两个重排都不大于`21`，所以答案是`-1`。 

该问题还引入了一个重要的限制：结果数必须适合有符号的 32 位整数。 这意味着最终答案必须小于或等于：```
2^31 - 1 = 2147483647
```如果存在有效的较大排列但超出此限制，我们必须返回`-1`。 

输入大小相对较小，因为最大可能的整数最多为 10 位。 这意味着我们不需要极其先进的优化，但我们仍然需要一个高效、干净的解决方案。 

一些边缘情况很重要：

 - 数字可能已经按降序排列，例如`321`，意味着不存在更大的排列。 
- 数字可能重复，例如`115`。 
- 下一个排列可能会溢出 32 位整数范围。 
- 非常小的输入，例如个位数，总是返回`-1`。 
- 正确答案必须是最小的较大排列，而不仅仅是任何较大的排列。 

这个问题本质上是要求数字的“下一个字典顺序排列”。 

## 方法

 ### 蛮力方法

 暴力解决方案将生成所有可能的数字排列，将每个排列转换为整数，过滤掉大于的值`n`，然后返回其中的最小值。 

这种方法是正确的，因为它彻底检查了所有可能的数字排列。 如果存在更大的排列，算法最终会找到它。 

然而，排列的数量随着位数的增加呈阶乘增长。 如果号码有 10 位，则最多可以有：```
10! = 3,628,800
```可能的排列。 

生成所有排列，尤其是重复数字的排列，变得非常低效。 对这些排列进行排序和过滤进一步增加了成本。 尽管输入大小有限，但这种方法的成本不必要地昂贵。 

### 最佳方法

 关键的观察是我们不需要生成每个排列。 我们只需要按字典顺序排列下一个更大的排列。 

这正是经典的“下一个排列”算法。 

这个想法之所以有效，是因为数字序列的字典顺序直接对应于具有相同长度的数字的数字顺序。 

该算法找到从右侧开始数字停止减少的第一个位置。 该位置确定了我们可以在哪里制作稍大的数字。 

然后我们：

 1. 将该数字与最小的较大数字交换到其右侧。 
2. 反转该位置后面的后缀，使其尽可能小。 

这保证了我们生产出比原始数量大的最小数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(d! × d) | O(d! × d) | 生成数字的所有排列 |
 | 最佳| O(d) | O(d) | 使用下一个排列算法 |
 | | | | |

 这里，`d`是位数。 

## 算法演练

 ### 最优算法

 1. 将整数转换为数字列表。 

使用可变列表使交换和反转比直接操作整数更容易。 
2. 从右向左遍历数字，找到主元索引。 

我们寻找第一个索引`i`在哪里：```
digits[i] < digits[i + 1]
```这标识了降序顺序中断的点。 

该索引右侧的所有内容都已按降序排列，这意味着它是当前该后缀的最大可能排列。 
3. 如果不存在这样的主元，则返回`-1`。 

如果整个数字按降序排列，则不可能有更大的排列。 

例子：```
54321
```4. 找到枢轴右侧比枢轴数字大的最小数字。 

我们从末尾向枢轴扫描，因为后缀是下降的。 第一个比主元大的数字是正确的选择。 
5. 将枢轴数字与较大的数字交换。 

这将创建一个比原始数字更大的数字。 
6. 反转枢轴索引后的后缀。 

在交换之前，后缀是降序的。 交换后，反转它会产生剩余数字的最小可能顺序。 

此步骤保证结果是最小的有效较大数。 
7. 将数字列表转换回整数。 
8. 检查是否有 32 位溢出。 

如果结果超过`2147483647`， 返回`-1`。 
9. 否则，返回结果。 

### 为什么它有效

 该算法之所以有效，是因为它以尽可能最小的方式修改数字，但仍会增加其值。 

枢轴确定了可能增加的最右边位置。 与下一个较大的数字交换会在该位置产生最小的增量。 反转后缀然后最小化枢轴之后的所有内容。 

这种组合保证了结果数是紧邻的下一个排列，它恰好是使用相同数字的最小的较大整数。 

## Python 解决方案```python
class Solution:
    def nextGreaterElement(self, n: int) -> int:
        digits = list(str(n))
        length = len(digits)

        # Step 1: Find pivot
        pivot = length - 2

        while pivot >= 0 and digits[pivot] >= digits[pivot + 1]:
            pivot -= 1

        # No next permutation exists
        if pivot < 0:
            return -1

        # Step 2: Find smallest larger digit from the right
        swap_index = length - 1

        while digits[swap_index] <= digits[pivot]:
            swap_index -= 1

        # Step 3: Swap
        digits[pivot], digits[swap_index] = (
            digits[swap_index],
            digits[pivot],
        )

        # Step 4: Reverse suffix
        digits[pivot + 1:] = reversed(digits[pivot + 1:])

        result = int("".join(digits))

        # Step 5: Check 32-bit integer limit
        if result > 2**31 - 1:
            return -1

        return result
```实现首先将数字转换为字符列表，以便可以有效地修改各个数字。 

第一个循环从右到左搜索枢轴索引。 这标识了可以增加的第一个数字，同时仍然产生有效的下一个排列。 

如果没有找到枢轴，则数字完全降序，因此函数立即返回`-1`。 

第二个循环通过从右侧扫描来找到比枢轴数字大的最小数字。 由于后缀是降序的，因此遇到的第一个有效数字是最佳选择。 

交换后，将后缀反转，将其转换为升序。 这确保了所得的数字是尽可能最小的较大排列。 

最后，这些数字被连接回一个整数，并且溢出检查确保符合 32 位有符号整数约束。 

## 解决方案```go
func nextGreaterElement(n int) int {
	digits := []byte(strconv.Itoa(n))
	length := len(digits)

	// Step 1: Find pivot
	pivot := length - 2

	for pivot >= 0 && digits[pivot] >= digits[pivot+1] {
		pivot--
	}

	// No next permutation exists
	if pivot < 0 {
		return -1
	}

	// Step 2: Find smallest larger digit
	swapIndex := length - 1

	for digits[swapIndex] <= digits[pivot] {
		swapIndex--
	}

	// Step 3: Swap
	digits[pivot], digits[swapIndex] =
		digits[swapIndex], digits[pivot]

	// Step 4: Reverse suffix
	left := pivot + 1
	right := length - 1

	for left < right {
		digits[left], digits[right] =
			digits[right], digits[left]

		left++
		right--
	}

	result, _ := strconv.Atoi(string(digits))

	// Step 5: Check 32-bit integer limit
	if result > math.MaxInt32 {
		return -1
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑，但存在一些特定于语言的差异。 

Go 字符串是不可变的，因此数字被转换为`[]byte`切片以进行有效的就地修改。 

后缀反转不是Python的切片和反转，而是使用两个指针手动实现。 

Go 还需要使用以下方法在字符串和整数之间进行显式转换`strconv`包裹。 

溢出检查使用`math.MaxInt32`，与硬编码值相比，这提高了可读性。

 该算法对数字执行多次线性扫描：

 - 一次扫描即可找到枢轴

 ## 边缘情况

 当数字已经按降序排列时，就会出现一种重要的边缘情况。 例如，`54321`没有更大的排列，因为它已经是这些数字的最大可能排列。 幼稚的实现可能仍会尝试交换并意外地产生无效结果。 该算法通过搜索主元索引来处理这个问题。 如果不存在pivot，则立即返回`-1`。 

另一个棘手的情况涉及重复的数字，例如`115`。 如果算法只是选择任何较大的数字而不是最小的较大数字，则重复的值很容易导致错误的交换。 该实现正确地从右侧扫描并选择大于主元的第一个数字，这保证了下一次排列所需的最小增加。 

溢出处理也很关键。 考虑`1999999999`。 存在更大的排列，但生成的数字超出了 32 位有符号整数限制。 如果没有溢出检查，算法将错误地返回无效答案。 该实现显式地将结果与`2^31 - 1`并返回`-1`如果该值太大。 

最后一个边缘情况是单位数字输入。 像这样的数字`7`无法产生更大的排列，因为只有一种可能的排列。 在这种情况下枢轴搜索自然会失败，并且算法正确返回`-1`。
