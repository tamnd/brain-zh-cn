 ## 解决方案

 ## 问题理解

 该问题要求我们计算数组中有多少个唯一的整数对的绝对差等于`k`。 

在以下情况下，一对被视为有效：

 - 这两个元素来自不同的索引。 
- 两个值之间的绝对差恰好是`k`。 

重要的细节是我们只计算唯一的对。 这意味着数组中的重复值不应导致同一对被多次计数。 

例如，在：```
nums = [3,1,4,1,5], k = 2
```这对`(1,3)`出现多次，因为出现了两次`1`，但仍然应该只计算一次。 

输入包括：

 - 整数数组`nums`- 一个整数`k`输出是一个整数，表示不同的 k-diff 对的数量。 

限制条件相对温和：

 -`nums.length <= 10^4`- 值可以为负数
 -`k`可以为零

 这些限制告诉我们，`O(n^2)`对于较小的输入，暴力解决方案可能会在某些语言中通过，但这并不理想。 该问题显然需要使用散列、排序或两个指针的更有效的方法。 

一些边缘情况很重要：

 -`k = 0`，我们正在寻找重复的数字
 - 具有许多重复项的数组
 - 负数
 - 空或单元素有效场景
 - 仍然安全地适合整数范围的大值

 一个特别重要的观察结果是`k`保证为非负数。 由于该问题使用绝对差，负数`k`无论如何都没有意义。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每一个可能的索引对`(i, j)`在哪里`i != j`。 

对于每对：

 1. 计算`abs(nums[i] - nums[j])`2. 如果差值等于`k`，将这对存储在一个集合中以避免重复

 因为`(1,3)`和`(3,1)`表示相同的逻辑对，我们会在存储之前对该对进行标准化，通常通过存储`(min(a,b), max(a,b))`。 

这种方法是正确的，因为它显式检查所有有效组合。 然而，它的效率很低，因为有`O(n^2)`可能的对。 

和`n = 10^4`，这可能会导致大约 1 亿次比较，这是不必要的昂贵。 

### 最优方法，哈希集/频率图

 关键的见解是对于一个数字`x`，我们只需要知道是否`x + k`存在。 

我们可以使用散列进行恒定时间查找，而不是比较每一对。 

有两种不同的情况：

 - 当`k > 0`，我们计算不同的值`x`在哪里`x + k`存在。 
- 什么时候`k == 0`，我们计算出现多次的数字。 

频率图是理想的选择，因为：

 - 它提供恒定时间的存在检查
 - 它自然地跟踪重复计数
 - 避免重复配对计数

 这将时间复杂度降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 检查每一对并使用一组来确保唯一性 |
 | 最佳| O(n) | O(n) | 使用哈希图进行频率计数和快速查找 |

 ## 算法演练

 ### 最优哈希图算法

 1. 首先，创建数组中所有数字的频率图。 

频率图使我们能够：

 - 快速判断某个值是否存在
 - 了解某个值出现了多少次

 例如：```
nums = [1,3,1,5,4]
```产生：```
{
    1: 2,
    3: 1,
    5: 1,
    4: 1
}
```2. 初始化一个计数器变量，名为`pairs`。 

该变量将存储唯一 k-diff 对的数量。 
3. 处理情况`k == 0`。 

什么时候`k`为零，我们正在寻找像这样的对`(x, x)`。 

由于索引必须不同，因此数字必须至少出现两次。 

对于频率图中的每个数字：

 - 如果其频率大于 1，则增加答案。 
4. 处理以下情况`k > 0`。 

对于每个唯一的号码`x`在频率图中：

 - 检查是否`x + k`存在于地图中。 
- 如果是，则增加答案。 

这是有效的，因为每个唯一的起始值恰好贡献一对唯一的值。 
5. 返回最终计数。 

### 为什么它有效

 该算法之所以有效，是因为每个唯一的 k-diff 对都可以表示为`(x, x + k)`。 

为了`k > 0`，迭代唯一的数字可确保每对都被精确计数一次。 

为了`k == 0`，仅当一个数字出现多次时才存在有效对。 

哈希映射保证了有效的存在检查，同时自然地消除了重复计数。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def findPairs(self, nums: List[int], k: int) -> int:
        frequency = Counter(nums)
        pairs = 0

        if k == 0:
            for count in frequency.values():
                if count > 1:
                    pairs += 1
        else:
            for number in frequency:
                if number + k in frequency:
                    pairs += 1

        return pairs
```实现首先构建一个`Counter`，这是一个存储元素频率的专用哈希图。 

变量`pairs`跟踪有效唯一对的总数。 

然后逻辑分为两个分支。 

什么时候`k == 0`，我们搜索重复的数字。 每个频率大于 1 的数字恰好贡献一对有效的数字。 

什么时候`k > 0`，我们迭代每个唯一的数字并检查是否`number + k`存在于频率图中。 如果是，我们就找到了一个有效的唯一对。 

由于迭代仅在唯一键上发生，因此永远不会对重复对进行多次计数。 

## 解决方案```go
func findPairs(nums []int, k int) int {
	frequency := make(map[int]int)

	for _, num := range nums {
		frequency[num]++
	}

	pairs := 0

	if k == 0 {
		for _, count := range frequency {
			if count > 1 {
				pairs++
			}
		}
	} else {
		for number := range frequency {
			if _, exists := frequency[number+k]; exists {
				pairs++
			}
		}
	}

	return pairs
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个`map[int]int`用来代替Python的`Counter`。 

Go 映射在查找期间返回两个值：```go
value, exists := map[key]
```我们只关心键是否存在，因此使用忽略该值`_`。 

由于约束完全在 Go 的整数范围内，因此整数溢出在这里不是问题。

 ## 边缘情况

 ### 案例 1,`k == 0`这是问题中最重要的特殊情况。 

通常，我们搜索精确分隔的数字`k`。 然而，当`k`为零，有效对由相同的值组成。 

幼稚的实现可能会错误地分别计算每个重复出现的情况。 例如：```
[1,1,1,1]
```应该只产生一对独特的`(1,1)`。 

该实现通过计算有多少数字出现多次而不是计算索引组合来正确处理此问题。 

### 情况 2，重复值`k > 0`考虑：```
nums = [1,1,1,3,3]
k = 2
```这对`(1,3)`如果我们考虑索引，则存在很多次，但问题只需要唯一的值对。 

暴力实现很容易导致计数过高。 

哈希映射方法避免了这个问题，因为它仅通过频率映射中的唯一键进行迭代。 

### 情况 3，负数

 该数组可以包含负整数：```
nums = [-3,-2,-1]
k = 1
```有效对是：```
(-3,-2), (-2,-1)
```该算法自然适用于负值，因为哈希映射支持负键，无需任何特殊处理。 

### 情况 4，无有效对

 某些数组不包含有效差异：```
nums = [1,5,9]
k = 2
```执行正确返回`0`因为没有`number + k`值存在于频率图中。 

### 情况 5，单元素数组

 单个元素永远无法形成有效的对，因为索引必须不同。 

例如：```
nums = [10]
k = 0
```回报`0`。 

该实现自然地处理了这个问题，因为没有频率超过 1 并且不存在互补值。
