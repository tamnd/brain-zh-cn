[LeetCode 第 591 题](https://leetcode.com/problems/tag-validator/)

 **难度：** 🔴难
 **主题：** 字符串、堆栈

 ## 解决方案

 ## 问题理解

 此问题要求我们根据自定义的类似 XML 的语法来验证给定的字符串是否表示结构正确的代码片段。 乍一看，它类似于解析 HTML 或 XML 标签，但验证规则更严格、更专业。 

输入是单个字符串`code`，其中可能包含开始标记、结束标记、CDATA 部分和纯文本。 我们的目标是回归`true`如果整个字符串根据所有规则形成有效的片段，否则返回`false`。 

最重要的要求是整个字符串必须恰好包含在一个有效的根标记内。 这意味着像这样的字符串`<A></A>`有效，但根标记之外的纯文本或多个顶级标记会使输入无效。 

有效的标签具有以下形式：```
<TAG_NAME>content</TAG_NAME>
```其中：

 - 开始和结束标签名称必须匹配。 
- 标签名称只能包含大写英文字母。 
- 标签名称长度必须介于`1`和`9`。 

标签内的内容可以包含：

 - 嵌套有效标签
 - CDATA块
 - 任意字符

 但是，内容不能包含格式错误的标签语法、不匹配的标签语法`<`、无效的标签名称或不正确的嵌套标签。 

CDATA 部分值得特别关注。 CDATA 块的形式为：```
<![CDATA[anything]]>
```在 CDATA 内部，绝对没有任何内容被解析为标签。 即使无效的类似 XML 的内容也必须被视为纯文本。 解析器必须在第一次出现时停止`]]>`。 

限制相对较小：

 -`1 <= code.length <= 500`由于输入大小仅限于 500 个字符，因此即使是相当昂贵的解析方法也可以工作。 然而，由于围绕嵌套、格式错误的语法和 CDATA 处理的许多边缘情况，正确性比效率更具挑战性。 

一些棘手的情况可能会破坏简单的实现：

 - 根标签之外的文本，例如`<A></A>text`，必须拒绝。 
- 不正确的嵌套，如`<A><B></A></B>`无效。 
- 无效的标签名称，例如`<abc>`或者`<ABCDEFGHIJK>`一定会失败。 
- CDATA 部分只能出现在开放标记内。 
- 一只流浪者`<`没有匹配的`>`使输入无效。 
- 必须小心处理空堆栈情况，例如结束标签出现在任何开始标签之前。 

该问题保证输入只包含有限的字符集，但不能保证结构的正确性。 这意味着解析器必须显式验证每个规则。 

## 方法

 ### 蛮力方法

 暴力解决方案将通过重复扫描子字符串并尝试匹配有效的开始和结束标签来尝试递归解析。 对于每个开始标签，我们可以向前搜索可能匹配的结束标签，递归地验证嵌套内容。 

这在概念上是有效的，因为该结构类似于递归语法分析。 每当我们遇到一个标签时，我们都会递归地验证其内容，直到找到相应的结束标签。 

然而，困难来自于模糊性和反复的重新扫描。 嵌套标签和 CDATA 块迫使我们重复搜索字符串的重叠区域。 在病理情况下，这可能会导致重复工作和低效的子串处理。 

更重要的是，由于嵌套规则和格式错误的输入，正确实现递归回溯变得极其容易出错。 

### 最佳解决方案的关键见解

 关键的观察结果是，输入自然地表现得像具有嵌套范围的结构化语言。 每当我们遇到开始标签时，我们就会进入一个新的嵌套上下文。 每当我们遇到结束标签时，我们就会离开当前上下文。 

这种模式强烈建议使用**堆栈**。 

堆栈跟踪当前打开的标签。 当我们遇到：

 - 一个开始标签，我们将它压入堆栈。 
- 结束标记，我们验证它与堆栈顶部匹配并将其弹出。 
- CDATA 部分，我们完全跳过它，因为它不能被解析。 
——朴素的人物，我们只是简单的前行。 

另一项关键规则是整个代码段必须包含在一个有效的根标记中。 我们通过确保：

 1. 解析从开始标签开始。 
2. 在到达字符串末尾之前，堆栈永远不会变空。 
3. 堆栈在末尾处为空。 

这为我们提供了一个干净的单遍解析器。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 嵌套子字符串的递归重新扫描 |
 | 最佳 | O(n) | O(n) | 使用堆栈进行单遍解析 |

 ## 算法演练

 1.初始化一个空栈和一个索引指针`i = 0`。 
2. Traverse the string while`i < len(code)`。 
3. 在处理之前，在我们还没有开始解析时检查堆栈是否为空。 如果栈在到达末尾之前变空，则说明内容存在于根标签之外，这是无效的。 
4.如果我们遇到`<![CDATA[`, validate that:

 - 我们位于开放标签内，这意味着堆栈不为空。 
- 我们可以找到终止`]]>`。 

如果任一条件失败，则返回`false`。 

否则，跳过整个 CDATA 块而不解析其内容。 
5.如果我们遇到结束标签`</TAG>`：

 - 寻找下一个`>`。 
- 提取标签名称。 
- 验证标签名称格式。 
- 确保堆栈不为空。 
- 验证标签与当前堆栈顶部匹配。 
- 弹出标签。 

如果任何条件不满足，则返回`false`。 
6.如果我们遇到开始标签`<TAG>`：

 - 寻找下一个`>`。 
- 提取标签名称。 
- 验证：

 - 长度介于`1`和`9`- 仅包含大写字母
 - 将标签推入堆栈。 
7. 如果遇到普通字符，只需向前移动一个字符即可。 
8.处理完整个字符串后，返回`true`仅当堆栈为空时。 

### 为什么它有效

 正确性来自堆栈不变式：

 **堆栈始终按嵌套顺序准确包含当前打开的标签。**

 每当我们打开一个标签时，我们都会推送它。 每当我们关闭一个标签时，我们必须关闭最近打开的不匹配的标签，这正是堆栈顶部。 这自然会强制执行正确的嵌套。 

CDATA 处理之所以有效，是因为我们故意跳过其中的解析，以满足 CDATA 内容必须被视为原始文本的问题要求。 

根标记约束得到保证，因为堆栈在到达字符串末尾之前不能变空。 

## Python 解决方案```python
class Solution:
    def isValid(self, code: str) -> bool:
        def is_valid_tag(tag_name: str) -> bool:
            return (
                1 <= len(tag_name) <= 9
                and all("A" <= ch <= "Z" for ch in tag_name)
            )

        stack: list[str] = []
        index = 0
        n = len(code)

        while index < n:
            # No content allowed outside root tag
            if index > 0 and not stack:
                return False

            # CDATA section
            if code.startswith("<![CDATA[", index):
                if not stack:
                    return False

                cdata_end = code.find("]]>", index)
                if cdata_end == -1:
                    return False

                index = cdata_end + 3

            # End tag
            elif code.startswith("</", index):
                tag_end = code.find(">", index)
                if tag_end == -1:
                    return False

                tag_name = code[index + 2 : tag_end]

                if not is_valid_tag(tag_name):
                    return False

                if not stack or stack[-1] != tag_name:
                    return False

                stack.pop()
                index = tag_end + 1

            # Start tag
            elif code[index] == "<":
                tag_end = code.find(">", index)
                if tag_end == -1:
                    return False

                tag_name = code[index + 1 : tag_end]

                if not is_valid_tag(tag_name):
                    return False

                stack.append(tag_name)
                index = tag_end + 1

            # Regular text
            else:
                index += 1

        return len(stack) == 0
```实现从辅助函数开始`is_valid_tag()`，这确保标签名称遵循问题规则。 有效标签必须仅包含大写字母且长度介于`1`和`9`。 

堆栈跟踪当前打开的标签。 当我们扫描字符串时，解析器首先检查 CDATA，因为它以`<`，并且错误地将其视为普通标签会破坏解析。 

对于结束标签，我们验证标签名称与堆栈顶部匹配。 这可以强制执行正确的嵌套并防止无效的结构，例如：```python
<A><B></A></B>
```通过在到达末尾之前检查堆栈是否变空来处理根标记限制。 如果是，则说明有效根标记之外存在其他内容。 

最后，我们返回`true`仅当每个打开的标签都已正确关闭时。 

## 解决方案```go
func isValid(code string) bool {
	isValidTag := func(tag string) bool {
		if len(tag) < 1 || len(tag) > 9 {
			return false
		}

		for _, ch := range tag {
			if ch < 'A' || ch > 'Z' {
				return false
			}
		}

		return true
	}

	stack := []string{}
	n := len(code)
	index := 0

	for index < n {
		if index > 0 && len(stack) == 0 {
			return false
		}

		// CDATA
		if index+9 <= n && code[index:index+9] == "<![CDATA[" {
			if len(stack) == 0 {
				return false
			}

			cdataEnd := indexOf(code, "]]>", index)
			if cdataEnd == -1 {
				return false
			}

			index = cdataEnd + 3

		} else if index+2 <= n && code[index:index+2] == "</" {
			// End tag
			tagEnd := indexOf(code, ">", index)
			if tagEnd == -1 {
				return false
			}

			tagName := code[index+2 : tagEnd]

			if !isValidTag(tagName) {
				return false
			}

			if len(stack) == 0 || stack[len(stack)-1] != tagName {
				return false
			}

			stack = stack[:len(stack)-1]
			index = tagEnd + 1

		} else if code[index] == '<' {
			// Start tag
			tagEnd := indexOf(code, ">", index)
			if tagEnd == -1 {
				return false
			}

			tagName := code[index+1 : tagEnd]

			if !isValidTag(tagName) {
				return false
			}

			stack = append(stack, tagName)
			index = tagEnd + 1

		} else {
			index++
		}
	}

	return len(stack) == 0
}

func indexOf(s, target string, start int) int {
	for i := start; i <= len(s)-len(target); i++ {
		if s[i:i+len(target)] == target {
			return i
		}
	}
	return -1
}
```Go 实现遵循与 Python 相同的逻辑，但使用切片来模拟堆栈。 由于 Go 不像 Python 那样提供带有起始索引语义的内置字符串搜索`find()`，我们实现一个助手`indexOf()`功能。 

Go 字符串是字节索引的，这在这里是安全的，因为问题只保证 ASCII 字符。 不存在整数溢出问题，因为最大输入长度仅为`500`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符最多被处理固定次数 |
 | 空间| O(n) | 最坏情况下堆栈可能存储所有嵌套标签 |

 虽然我们使用字符串搜索`>`和`]]>`，在解析过程中每个字符都会被有效访问恒定次数。 自从`n <= 500`，性能很容易就足够了。 堆栈深度受到标签嵌套级别的限制，在最坏的情况下可以与输入长度成正比。

 ## 边缘情况

 ### 根标签之外的内容

 一个微妙但重要的边缘情况是有效内容存在于根标记之外，例如：```
<A></A>extra
```天真的解析器可能会错误地接受这一点，因为标签本身是有效的。 但是，该问题需要将整个代码片段包装在单个闭合标签中。 我们的实现通过立即拒绝堆栈在到达字符串末尾之前变空的情况来处理此问题。 

### 无效的标签名称

 另一个棘手的情况涉及格式错误的标签名称：```
<abc></abc>
```或者```
<ABCDEFGHIJ></ABCDEFGHIJ>
```第一个违反了仅大写规则，而第二个超出了最大长度`9`。 我们的辅助函数会在允许标签进入堆栈之前验证这两个条件。 

### 不正确的嵌套

 不正确的嵌套通常会导致递归实现中出现错误：```
<A><B></A></B>
```即使两个标签都存在，关闭顺序也是错误的。 由于堆栈自然地强制执行最后打开先关闭的行为，因此我们的实现通过检查堆栈顶部的结束标记来正确检测这种不匹配。 

### CDATA 误解

 CDATA 内容绝不能被解析为标签。 例如：```
<A><![CDATA[<invalid></invalid>]]></A>
```CDATA 内的无效标签应该无关紧要。 我们的实现明确地跳过所有内容，直到第一个`]]>`，防止意外解析内部内容。
