 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少种整数的排列`1`到`n`满足特殊的可分性条件。 

排列是所有数字的排列`1`到`n`其中每个数字都只出现一次。 例如，当`n = 3`，可能的排列包括`[1,2,3]`,`[2,1,3]`,`[3,2,1]`， 等等。 

如果对于每个位置，排列被认为是一种美丽的排列`i`使用基于 1 的索引，至少满足以下条件之一：

 -`perm[i] % i == 0`-`i % perm[i] == 0`换句话说，放置在位置的数字`i`必须整除索引或可被索引整除。 

输入是单个整数`n`，输出是有效的漂亮排列的总数。 

约束条件`1 <= n <= 15`非常重要。 生成所有排列的简单解决方案需要检查：$$15! = 1,307,674,368,000$$可能的安排，对于暴力枚举来说太大了。 

这一限制强烈表明我们需要更智能的搜索策略，通常涉及：

 - 回溯
 - 动态规划
 - 位掩码
 - 状态修剪

 的小上界`15`还暗示位掩码动态编程是实用的，因为长度为 15 的位掩码非常适合整数。 

一些边缘情况很重要：

 -`n = 1`是最小的可能输入，并且唯一的排列是平凡有效的。 
- 某些位置的有效数字很少，因此低效地选择值可能会产生不必要的分支。 
- 由于每个数字只能使用一次，因此我们必须在递归过程中仔细跟踪使用状态。 
- 必须避免重复计数，这意味着每个有效排列都应该只计数一次。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个数字的排列`1`到`n`，然后检查每个排列是否满足美丽排列条件。 

对于每个排列：

 1. 迭代每个索引`i`。 
2. 检查是否：

 -`perm[i] % i == 0`， 或者
-`i % perm[i] == 0`3. 如果所有位置都满足条件，则增加答案。 

这种方法是正确的，因为它详尽地检查了每一种可能的排列，并准确地计算出满足规则的排列。 

然而，运行时间非常昂贵。 有`n!`排列，并且每个排列需要`O(n)`验证工作。 

为了`n = 15`，这变得完全不可行。 

### 使用位掩码优化回溯

 关键的观察结果是许多部分排列很早就变得无效。 

我们可以按位置构建排列，而不是首先生成完整的排列：

 - 在位置`pos`，仅尝试满足该位置可整除条件的数字。 
- 跳过已使用的号码。 
- 当没有有效选择时立即回溯。 

这极大地减少了搜索空间。 

我们可以使用位掩码进一步优化：

 - 每一位代表一个数字是否已被使用。 
- 位运算速度极快。 
- 递归状态变得紧凑且高效。 

因为`n <= 15`，一个15位整数足以表示所有使用状态。 

如果需要，我们还可以记忆状态，但即使是带有修剪的标准回溯也能很好地解决这个问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n) | O(n! × n) | O(n) | 生成所有排列并验证每个 |
 | 最佳| 大约 O(n × 2^n) | O(2^n) | O(2^n) | 使用修剪和位掩码 DP 进行回溯 |

 ## 算法演练

 ### 最优回溯+位掩码算法

 1. 从位置开始`1`。 

我们逐步建立这种安排。 在每个递归步骤中，我们决定在当前位置放置哪个数字。 
2. 维护代表已用数字的位掩码。 

如果位`k`已设置，则编号`k + 1`已经被放置在安排中的某个地方。 
3. 对于当前位置`pos`，迭代所有候选数`1`到`n`。 

每个数字都会检查两个条件：

 - 尚未使用。 
- 它满足：$$num \% pos == 0 \quad \text{or} \quad pos \% num == 0$$4. 如果号码有效：

 - 将其标记为位掩码中使用的。 
- 递归求解`pos + 1`。 
5. 什么时候`pos > n`，完整有效的排列已经构建完成。 

返回`1`来算一下这个安排。 
6. 对所有递归分支返回的计数求和。 
7. 使用记忆来避免重新计算状态。 

由于状态完全由以下因素决定：

 - 当前位置
 - 当前位掩码

 我们可以缓存重复状态的结果。 

### 为什么它有效

 该算法系统地探索每一个有效的排列，同时立即修剪无效的部分配置。 

在每个递归步骤中，仅考虑满足整除规则的数字。 由于每个数字仅使用一次并且探索每个有效分支，因此该算法对所有漂亮的排列仅计数一次。 

记忆化保证相同的状态仅计算一次，从而减少指数重新计算。 

## Python 解决方案```python
class Solution:
    def countArrangement(self, n: int) -> int:
        memo = {}

        def backtrack(position: int, used_mask: int) -> int:
            if position > n:
                return 1

            if (position, used_mask) in memo:
                return memo[(position, used_mask)]

            total = 0

            for num in range(1, n + 1):
                bit = 1 << (num - 1)

                # Skip already used numbers
                if used_mask & bit:
                    continue

                # Check beautiful arrangement condition
                if num % position == 0 or position % num == 0:
                    total += backtrack(
                        position + 1,
                        used_mask | bit
                    )

            memo[(position, used_mask)] = total
            return total

        return backtrack(1, 0)
```实现遵循前面描述的递归策略。 

这`backtrack`函数表示从特定位置和使用状态开始可以形成的有效排列的数量。 

基本情况发生在`position > n`。 这意味着所有职位都已成功填补，因此我们返回`1`计算一个有效的排列。 

这`used_mask`整数跟踪哪些数字已经放置在排列中。 位操作允许恒定时间的检查和更新。 

对于每个递归调用：

 - 我们迭代数字`1`到`n`。 
- 跳过已使用的号码。 
- 检查整除条件是否成立。 
- 使用更新后的掩码进行递归。 

记忆化存储先前计算的状态以避免冗余工作。 由于许多递归路径都达到相同的`(position, used_mask)`配对后，缓存可显着提高性能。 

## 解决方案```go
func countArrangement(n int) int {
    memo := make(map[[2]int]int)

    var backtrack func(position int, usedMask int) int

    backtrack = func(position int, usedMask int) int {
        if position > n {
            return 1
        }

        key := [2]int{position, usedMask}

        if value, exists := memo[key]; exists {
            return value
        }

        total := 0

        for num := 1; num <= n; num++ {
            bit := 1 << (num - 1)

            // Skip already used numbers
            if usedMask&bit != 0 {
                continue
            }

            // Check beautiful arrangement condition
            if num%position == 0 || position%num == 0 {
                total += backtrack(
                    position+1,
                    usedMask|bit,
                )
            }
        }

        memo[key] = total
        return total
    }

    return backtrack(1, 0)
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用固定大小的数组，而不是使用 Python 元组来存储键`[2]int`包含：

 - 当前位置
 - 当前位掩码

 Go 没有 Python 的自动记忆结构，因此我们显式地使用映射。 

位操作在两种语言中的行为相似，并且整数溢出不是问题，因为漂亮的排列数量`n <= 15`舒适地放入 Go 中`int`。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 大约 O(n × 2^n) | 每个位掩码状态均处理一次 |
 | 空间| O(2^n) | O(2^n) | 记忆表存储状态|

 可能的位掩码状态总数为`2^n`。 对于每个状态，我们可以迭代最多`n`候选人编号。 

因此，运行时间大约为：$$O(n \times 2^n)$$这比阶乘复杂度要好得多。 

记忆表为每个可达状态存储一个条目，要求`O(2^n)`记忆。 

递归栈深度最多为`n`。

 ## 边缘情况

 ### 边缘情况 1：最小输入

 当`n = 1`，只有一种可能的安排：`[1]`。 

有缺陷的实现可能会错误地处理递归基本情况并返回`0`而不是`1`。 

这个实现正确地处理了这种情况，因为当`position > n`，它返回`1`，表示一个有效的已完成排列。 

### 边缘情况 2：重复使用数字

 一个常见的错误是忘记跟踪哪些号码已被使用。 

例如，如果`n = 3`，不正确的实现可能会产生无效的安排，例如`[1,1,2]`。 

位掩码保证了唯一性，因为在选择之前会检查每个数字的位。 

### 边缘情况 3：整除方向不正确

 另一个常见的错误是仅检查：```
num % position == 0
```同时忘记了第二个条件：```
position % num == 0
```两个方向都是必要的。 

例如：

 - 在位置`2`， 数字`1`有效，因为：$$2 \% 1 == 0$$虽然：$$1 \% 2 \ne 0$$该实现显式检查这两个条件。 

### 边缘情况 4：接近约束极限的大输入

 对于`n = 15`，在没有修剪或记忆的情况下，搜索空间是巨大的。 

简单的阶乘解决方案会严重超时。 

记忆位掩码解决方案有效地减少了重复计算并轻松处理最大约束。
