[LeetCode 第 568 题](https://leetcode.com/problems/maximum-vacation-days/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大化假期总天数`k`之间旅行期间的几周`n`受到特定航班限制的城市。 

我们从城市开始`0`每周一早上`0`。 每个星期一早上，我们可能会留在当前城市，或者如果有直飞航班，则乘坐一趟航班飞往另一个城市。 当周到达某个城市后，我们将获得以下指定的假期天数：`days[city][week]`。 

输入包含两个矩阵：

 -`flights[i][j]`表示我们是否可以从城市直飞`i`到城市`j`。 
-`days[i][w]`表示如果我们花一周时间我们可以享受多少天假期`w`在城市`i`。 

目标是计算所有周内可实现的最大总假期天数。 

约束条件很重要：

 -`n <= 100`-`k <= 100`对所有可能的旅行时间表进行简单的蛮力搜索将会呈指数级增长，因为每周可能涉及多个城市选择。 由于两个维度最多为 100，这强烈表明需要多项式时间动态规划解决方案。 

一个重要的细节是，始终允许留在同一个城市，即使`flights[i][i] == 0`。 航班矩阵仅代表不同城市之间的实际航班。 

另一个微妙之处是，航班发生在周一早上，然后才计算该周的假期。 这意味着，如果我们在一周之初飞往某个城市，我们会立即获得该城市该周的假期。 

几种边缘情况很容易导致错误：

 - 根本没有航班，这意味着我们被困在城市里`0`。 
- 从起始城市无法到达的城市。 
- 需要暂时减少休假天数的最佳时间表，以开启更好的未来几周。 
- 呆在原地比飞行更好的情况。 
- 所有城市提供优惠的周`0`假期天。 

该问题保证了有效的矩阵维度和二进制飞行条目，因此我们不需要验证输入结构。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试了所有可能的城市序列`k`几周。 

每周，我们都会从当前城市考虑所有可到达的城市，包括留在当前城市的城市。 我们递归地探索每一个可能的旅行时间表并计算累积的总假期天数。 

这种方法是正确的，因为它明确枚举了每条有效路径并选择最大总数。 

然而，它太慢了。 在最坏的情况下，每个城市都可以到达其他所有城市，大约为`n`每周的选择。 计划总数变为：$$O(n^k)$$和`n = 100`和`k = 100`，这是完全不可行的。 

### 动态规划洞察

 关键的观察结果是该问题具有重叠的子问题。 

假设我们知道：

 - 本周
 - 那周初我们所在的城市

 那么无论我们如何到达那里，该状态的最佳未来结果总是相同的。 

这自然会导致动态规划。 

我们定义：$$dp[week][city]$$作为完成后可获得的最长假期天数`week`结束于`city`。 

每周，我们都会从所有以前可到达的城市过渡到所有当前可到达的城市。 

由于每个状态仅取决于前一周，因此我们可以优化空间以仅使用一个维度。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^k) | O(n^k) | O(k) 递归堆栈 | 尝试所有可能的旅行安排 |
 | 最优动态规划| O(k * n^2) | O(k * n^2) | O(n) | 每周计算每个城市的最佳可实现价值 |

 ## 算法演练

 1.初始化一个大小为DP的数组`n`。 

价值`dp[city]`表示当前在上周之后可实现的最长假期天数`city`。 

最初只有城市`0`是可达的，所以：```
dp[0] = 0
dp[other] = -1
```我们使用`-1`代表无法到达的状态。 
2. 一周一周地处理。 

每周创建一个名为的新数组`next_dp`。 

该数组存储本周结束后的最佳假期总数。 
3. 对于上周可到达的每个城市，尝试所有有效的移动。 

从城市出发`from_city`，我们可以：

 - 留在同一个城市
 - 飞往任何城市`to_city`在哪里`flights[from_city][to_city] == 1`4. 更新目的地城市的最佳价值。 

如果我们可以从`from_city`到`to_city`， 然后：```
next_dp[to_city] =
    max(next_dp[to_city],
        dp[from_city] + days[to_city][week])
```我们添加目的地城市的假期天数，因为我们本周在那里度过。 
5. 更换旧的 DP 阵列。 

处理完本周的所有转换后：```
dp = next_dp
```6. 继续，直到处理完所有周。 
7. 返回中的最大值`dp`。 

最后一周之后，每个参赛作品都代表了在该城市结束时可达到的最佳总成绩。 

### 为什么它有效

 DP 不变量为：

 > 加工后一周`w`,`dp[city]`存储一周结束时可实现的最长假期天数`w`在`city`。 

每个有效的时间表都必须在一周内从某个城市转移`w - 1`一周内可到达的城市`w`。 该算法会评估所有此类转变，并仅保留每个目的地城市的最佳总数。 

因为考虑了所有可达状态并且最优子结构成立，所以最终的最大值保证是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxVacationDays(self, flights: List[List[int]], days: List[List[int]]) -> int:
        n = len(flights)
        k = len(days[0])

        dp = [-1] * n
        dp[0] = 0

        for week in range(k):
            next_dp = [-1] * n

            for from_city in range(n):
                if dp[from_city] == -1:
                    continue

                for to_city in range(n):
                    if from_city == to_city or flights[from_city][to_city] == 1:
                        next_dp[to_city] = max(
                            next_dp[to_city],
                            dp[from_city] + days[to_city][week]
                        )

            dp = next_dp

        return max(dp)
```实现首先初始化 DP 数组。 唯一城市`0`在任何几周开始之前都可以到达，因此所有其他城市都被标记为无法到达`-1`。 

我们每周都会创造一个新鲜的`next_dp`大批。 这可以防止本周的更新干扰仍在处理的转换。 

外循环迭代所有可能的源城市。 如果某个城市无法到达，我们会立即跳过它。 

内循环检查所有目的地城市。 如果满足以下条件，则转换有效：

 - 我们住在同一个城市
 - 或有航班

 只要存在有效的过渡，我们就会更新目的地城市的最佳可实现假期总数。 

处理完本周的所有转换后，我们替换`dp`和`next_dp`。 

最后，我们返回所有结束城市中最大的可实现值。 

## 解决方案```go
func maxVacationDays(flights [][]int, days [][]int) int {
	n := len(flights)
	k := len(days[0])

	dp := make([]int, n)

	for i := 1; i < n; i++ {
		dp[i] = -1
	}

	for week := 0; week < k; week++ {
		nextDP := make([]int, n)

		for i := 0; i < n; i++ {
			nextDP[i] = -1
		}

		for fromCity := 0; fromCity < n; fromCity++ {
			if dp[fromCity] == -1 {
				continue
			}

			for toCity := 0; toCity < n; toCity++ {
				if fromCity == toCity || flights[fromCity][toCity] == 1 {
					candidate := dp[fromCity] + days[toCity][week]

					if candidate > nextDP[toCity] {
						nextDP[toCity] = candidate
					}
				}
			}
		}

		dp = nextDP
	}

	answer := 0

	for _, value := range dp {
		if value > answer {
			answer = value
		}
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 

由于 Go 切片默认为`0`，我们显式地初始化不可达状态`-1`。 

Go 没有提供内置的`max`函数用于整数，因此我们在赋值之前使用简单的比较。 

整数溢出不是问题，因为最大可能的答案是：```go
100 weeks * 7 days = 700
```它很容易符合 Go 的整数范围。

 ## 边缘情况

 当任何城市之间没有航班时，就会出现一种重要的边缘情况。 天真的实现可能会错误地假设旅行总是可能的，或者忘记无法到达的城市应该保持无效。 DP 解决方案通过初始化不可到达的状态来安全地处理这个问题`-1`并且永远不会从它们转变。 

另一个关键的边缘情况是单城市场景。 自从`flights[0][0]`总是`0`，不正确的实施可能会意外地阻止留在同一个城市。 该解决方案明确允许转换，其中`from_city == to_city`，确保停留始终合法。 

更微妙的边缘情况涉及未来的优化。 有时，最好的直接选择并不是全局最优的。 例如，本周减少休假天数可能会允许您稍后进入具有非常大奖励的城市。 贪婪方法在这里失败了，因为它们只在本地进行优化。 DP 解决方案每周正确评估所有可能的可达状态，保证全局最优。 

当某些城市提供极高的假期但无法从城市到达时，就会出现另一种棘手的情况`0`。 有缺陷的实现可能会意外地将它们包含在计算中。 因为该算法仅从之前可达的状态进行转换，所以不可达的城市永远不会污染 DP 表。
