 # LeetCode 506 - 相对排名

 ## 问题理解

 问题给了我们一个名为`score`，其中每个元素代表运动员在比赛中获得的分数。 每个运动员都有一个独特的分数，这意味着在确定排名时无需担心任何联系。 

我们需要根据得分顺序来确定每个运动员的名次。 得分最高的运动员获得第一名，得分第二高的运动员获得第二名，依此类推。 

输出必须保留运动员的原始顺序。 这是一个重要的细节。 我们并不是简单地按排序顺序返回排名。 相反，对于每个原始索引`i`，我们必须将该运动员的排名字符串放入`answer[i]`。 

前三名运动员将获得特殊标签：

 - 第一名获得`"Gold Medal"`- 第二名获得`"Silver Medal"`- 第三名获得`"Bronze Medal"`第三名之后的每个运动员都会以字符串形式收到他们的数字排名，例如`"4"`或者`"5"`。 

限制相对较小：

 -`1 <= n <= 10^4`- 分数是独一无二的
 - 分数可以大到`10^6`自从`n`至多是`10^4`， 一个`O(n log n)`排序解决方案是完全可以接受的。 二次方`O(n^2)`该方法可能仍然适用于某些输入，但当排序提供更干净、更快的解决方案时，它效率低下且不必要。 

一些边缘情况很重要：

 - A single athlete should receive`"Gold Medal"`- 恰好有两到三名运动员应该正确地仅获得适用的奖牌
 - 分数可能已经按升序或降序排序
 - 非常大的分值并不重要，因为只有相对顺序才重要
 - 由于分数保证是唯一的，因此我们永远不需要平局处理逻辑

 ## 方法

 ### 蛮力方法

 一个简单的方法是独立确定每个运动员的排名。 

对于每位运动员，我们将他们的得分与其他运动员的得分进行比较，并计算有多少运动员得分更高。 如果恰好有零个运动员得分较高，则该运动员排名第一。 如果一名运动员得分较高，则该运动员排名第二，依此类推。 

确定排名编号后，我们将前三个排名转换为奖牌字符串，其余排名使用数字字符串。 

这种方法之所以有效，是因为计算有多少分数超过当前分数可以直接确定排名。 

然而，该方法需要嵌套循环。 对于每一位运动员，我们都会再次扫描整个数组。 这导致`O(n^2)`时间复杂度，当排序可以更有效地解决问题时，这是不必要的。 

### 最佳方法

 关键的观察是排名完全由分数排序决定。 

如果我们按得分降序对运动员进行排序，则：

 - 索引`0`在排序列表中是第一位
 - 索引`1`是第二名
 - 索引`2`是第三名
 - 索引`i`对应于放置`i + 1`为了保留原始排序，我们在排序之前存储分数及其原始索引。 排序后，我们分配正确的排名字符串并将其放入结果数组中运动员的原始索引处。 

排序将问题从重复比较减少到单个排序操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 将每位运动员与其他运动员进行比较 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 按分数对运动员进行排序并有效分配排名 |

 ## 算法演练

 1. 创建一个包含每个运动员得分和原始指数的配对列表。 

我们需要原始索引，因为最终答案必须与输入顺序匹配。 一对像`(score, index)`允许我们按分数排序，同时仍然知道运动员在结果数组中的位置。 
2. 按分数降序对配对进行排序。 

排序后：

 - 排序列表中的第一位运动员得分最高
 - 第二名运动员得分第二高
 - 等等

 这直接给了我们放置订单。 
3. 创建一个size的结果数组`n`。 

This array will store the final rank strings.
 4. Traverse the sorted list.

 For each athlete in sorted order:

 - 排名`0`得到`"Gold Medal"`- 排名`1`得到`"Silver Medal"`- 排名`2`得到`"Bronze Medal"`- 任何其他等级都会得到字符串版本`rank + 1`5. 将排名字符串放入结果数组中运动员的原始索引中。 

这将恢复问题所需的原始顺序。 
6. 返回结果数组。 

### 为什么它有效

 按分数降序对运动员进行排序可以保证他们在排序列表中的位置与他们的比赛名次完全匹配。 由于所有分数都是唯一的，因此排序位置和排名之间存在一对一的映射。 通过存储原始索引，我们可以分配排名，同时仍按原始输入顺序重建答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findRelativeRanks(self, score: List[int]) -> List[str]:
        n = len(score)

        # Store score along with original index
        athletes = [(score_value, index) for index, score_value in enumerate(score)]

        # Sort by score in descending order
        athletes.sort(reverse=True)

        result = [""] * n

        for rank, (_, original_index) in enumerate(athletes):
            if rank == 0:
                result[original_index] = "Gold Medal"
            elif rank == 1:
                result[original_index] = "Silver Medal"
            elif rank == 2:
                result[original_index] = "Bronze Medal"
            else:
                result[original_index] = str(rank + 1)

        return result
```实现首先使用将每个分数与其原始索引配对`enumerate`。 这是必要的，因为排序会改变运动员的顺序，但最终答案必须保留原始顺序。 

然后列表按降序排序。 由于默认情况下元组按其第一个元素进行比较，因此分数会自动确定排序。 

结果数组用空字符串初始化。 当我们迭代排序的运动员时，循环索引代表运动员的位置：

 -`0`意味着第一名
 -`1`意味着第二名
 -`2`意思是第三名

 我们为前三名位置分配适当的奖牌串。 对于所有剩余位置，我们将位置编号转换为字符串。 

最后，我们将排名字符串存储在运动员的原始索引处，并返回完整的结果数组。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
)

func findRelativeRanks(score []int) []string {
	n := len(score)

	type Athlete struct {
		score int
		index int
	}

	athletes := make([]Athlete, n)

	for i, s := range score {
		athletes[i] = Athlete{
			score: s,
			index: i,
		}
	}

	sort.Slice(athletes, func(i, j int) bool {
		return athletes[i].score > athletes[j].score
	})

	result := make([]string, n)

	for rank, athlete := range athletes {
		if rank == 0 {
			result[athlete.index] = "Gold Medal"
		} else if rank == 1 {
			result[athlete.index] = "Silver Medal"
		} else if rank == 2 {
			result[athlete.index] = "Bronze Medal"
		} else {
			result[athlete.index] = strconv.Itoa(rank + 1)
		}
	}

	return result
}
```Go 解决方案遵循与 Python 实现相同的逻辑，但使用自定义`Athlete`结构体来存储分数和原始索引。 

Go 不像 Python 那样提供内置的元组支持，因此结构体使代码更清晰、更易于维护。 

排序是用`sort.Slice`，使用自定义比较函数进行降序排列。 

使用以下方法将数字位置转换为字符串`strconv.Itoa`。 

由于 Go 中的切片是数组上动态大小的视图，因此结果切片使用长度进行初始化`n`在作业开始之前。

 ## 边缘情况

 一个重要的边缘情况是输入仅包含一名运动员。 在这种情况下，该运动员必须接受`"Gold Medal"`。 粗心的实施可能会假设至少存在三名运动员，并错误地尝试分配银牌或铜牌。 当前的实现自然地处理了这个问题，因为排序循环分配了第一个运动员排名`0`，它直接映射到`"Gold Medal"`。 

另一个重要的情况发生在只有两到三名运动员的情况下。 该算法必须仅正确分配实际适用的奖牌。 例如，如果有两名运动员，则不应分配铜牌。 由于实施检查使用明确的条件按顺序排名，因此只有现有运动员才能获得奖牌。 

升序输入也是常见的错误来源。 例如，`[1,2,3,4]`将最高分放在原始数组的末尾。 如果实现在排序之前忘记保留原始索引，则输出顺序将变得不正确。 通过存储`(score, original_index)`对，算法按原始输入顺序正确重建答案。 

最后一个微妙的边缘情况涉及非常大的分值。 由于排名仅取决于相对顺序，而不取决于算术运算，因此大数字不会造成溢出或精度问题。 该算法只是直接对值进行排序和比较。
