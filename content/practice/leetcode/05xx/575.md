[LeetCode 第 575 题](https://leetcode.com/problems/distribute-candies/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大化爱丽丝可以吃的不同糖果类型的数量，同时严格限制她可以吃的糖果数量。 

我们得到一个整数数组`candyType`，其中每个元素代表糖果的类型。 多个糖果可以共享相同的类型值。 糖果总数为`n`，并且该问题保证`n`总是均匀的。 

医生只允许爱丽丝吃东西`n / 2`糖果。 爱丽丝想要尽可能多的品种，这意味着她想要最大化她选择吃的糖果中不同糖果类型的数量。 

关键观察是爱丽丝最多可以吃`n / 2`糖果总数，所以即使有很多独特的糖果类型可用，她也不能吃超过`n / 2`不同的类型，因为每种不同的类型都需要至少一个糖果槽。 

同时，如果少于`n / 2`整个系列中独特的糖果类型，那么答案就是可用的独特类型的数量。 

因此，答案是：

 - 独特糖果类型的数量
 - 上限为`n / 2`数学上：```
answer = min(number_of_unique_types, n / 2)
```限制从小到中等：

 -`2 <= n <= 10^4`- 糖果值可能为负值或正值
 -`n`总是均匀的

 自从`n`仅取决于`10^4`，线性或近线性解是完全可以接受的。 

一些重要的边缘情况包括：

 - 所有糖果都是同一类型，例如`[6,6,6,6]`- 每个糖果都是不同的类型
 - 独特类型的数量小于`n / 2`- 独特类型的数量大于`n / 2`- 糖果类型值为负

 该问题保证数组非空并且`n`是偶数，所以我们不需要对无效的输入大小进行特殊处理。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试每个可能的大小子集`n / 2`，然后计算每个子集中出现了多少种不同的糖果类型。 所有子集中的最大不同计数就是答案。 

这种方法是正确的，因为它明确地检查了 Alice 可以做出的每一个有效选择。 然而，这在计算上是不可行的。 

如果有`n`糖果，大小子集的数量`n / 2`是：```
C(n, n/2)
```即使对于中等值，该值也会呈指数增长并且变得巨大`n`。 

例如：```
C(30,15) = 155,117,520
```尝试所有组合会太慢。 

### 最佳方法

 重要的见解是我们实际上不需要确定爱丽丝吃了哪些糖果。 我们只需要知道不同类型的最大可能数量。 

有两个限制因素：

 1.爱丽丝只能吃东西`n / 2`糖果总数。 
2.爱丽丝不能吃比实际存在的更多的不同类型。 

所以如果：

 - 有`k`独特的糖果类型
 - 爱丽丝可以吃东西`n / 2`糖果

 那么她可以吃的最大不同类型是：```
min(k, n / 2)
```哈希集在这里是理想的选择，因为它自动仅存储唯一值。 

我们：

 1. 将所有糖果类型放入一个集合中
 2. 计算唯一类型的数量
 3. 返回以下最小值：

 - 唯一计数
 -`n / 2`这给出了一个干净的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(C(n, n/2) * n) | O(C(n, n/2) * n) | O(n) | 尝试所有可能的糖果选择 |
 | 最佳 | O(n) | O(n) | 使用哈希集来计算独特的糖果类型 |

 ## 算法演练

 1. 计算爱丽丝可以吃多少糖果。 

由于糖果总数为`n`，爱丽丝可以吃：```
n / 2
```糖果。 
2. 创建一个包含所有糖果类型的哈希集。 

哈希集会自动删除重复项，因此在插入所有值后，哈希集的大小等于不同糖果类型的数量。 
3. 计算独特糖果类型的数量。 

这很简单：```
len(unique_types)
```在Python中，或者`len(map)`在围棋中。 
4. 返回以下值之间的较小值：

 - 独特类型的数量
 - 允许的糖果数量

 爱丽丝不能吃超过`n / 2`糖果总数，所以即使有更多独特类型可用，她也会受到她可以消耗的糖果数量的限制。 

### 为什么它有效

 该算法之所以有效，是因为每种不同的糖果类型都需要至少吃一种糖果。 因此，爱丽丝吃的永远不能超过`n / 2`不同的类型。 

同时，爱丽丝也不能吃比集合中实际存在的种类更多的不同种类的食物。 

所以真正的最大值必须是以下较小者：

 - 独特糖果类型总数
 - 允许的糖果数量

 这样就保证了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def distributeCandies(self, candyType: List[int]) -> int:
        unique_types = set(candyType)
        max_allowed = len(candyType) // 2

        return min(len(unique_types), max_allowed)
```由于Python内置的，所以实现非常紧凑`set`type直接支持我们需要的操作。 

首先，我们将输入数组转换为集合。 这会自动删除重复的糖果类型。 

接下来，我们计算允许 Alice 吃多少糖果，这是数组长度的一半。 

最后，我们返回以下值之间较小的值：

 - 独特糖果类型的数量
 - 爱丽丝可以吃的最大糖果数量

 这直接符合之前得出的数学观察结果。 

## 解决方案```go
func distributeCandies(candyType []int) int {
    uniqueTypes := make(map[int]bool)

    for _, candy := range candyType {
        uniqueTypes[candy] = true
    }

    maxAllowed := len(candyType) / 2
    uniqueCount := len(uniqueTypes)

    if uniqueCount < maxAllowed {
        return uniqueCount
    }

    return maxAllowed
}
```Go版本使用map来模拟哈希集，因为Go没有提供内置的集合类型。 

映射键代表糖果类型，布尔值是占位符。 

将所有糖果类型插入到地图后，键的数量等于唯一糖果类型的数量。 

与 Python 不同，Go 没有内置的`min`函数用于整数，因此我们使用简单的条件检查来返回较小的值。

 ## 边缘情况

 当所有糖果都是同一类型时，就会出现一种重要的边缘情况。 例如：```
[6,6,6,6]
```爱丽丝可能会吃两颗糖果，但只有一种不同的类型可用。 有错误的解决方案可能会错误地返回`2`假设爱丽丝总能吃东西`n / 2`独特的糖果。 我们的实现正确地处理了这个问题，因为设置的大小是`1`，我们返回之间的最小值`1`和`2`。 

另一个重要的情况是每种糖果都是独一无二的。 例如：```
[1,2,3,4,5,6]
```有六种不同的类型，但爱丽丝可能只吃三种糖果。 幼稚的实现可能会错误地返回所有六种唯一类型。 我们的解决方案正确地将答案限制在`n / 2`。 

第三种边缘情况涉及负糖果类型值。 约束允许的值来自`-10^5`到`10^5`。 一些不正确的实现可能会假设糖果类型是非负的并尝试数组索引。 我们的解决方案使用哈希集，因此负值可以自然地工作，无需任何特殊处理。 

最后的边缘情况是最小输入大小：```
[1,2]
```爱丽丝可能只吃一颗糖果。 尽管有两种不同的类型，但答案一定是`1`。 公式`min(unique_types, n / 2)`正确且一致地处理这个问题。
