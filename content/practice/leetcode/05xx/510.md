[LeetCode 510 题](https://leetcode.com/problems/inorder-successor-in-bst-ii/)

 **难度：** 🟡 中等
 **主题：** 树、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们在二叉搜索树（缩写为 BST）内查找给定节点的有序后继节点。 与问题的经典版本不同，我们无法访问树的根。 相反，我们只得到一个指向特定节点的指针，并且每个节点都包含对其父节点的引用。 

节点的有序后继节点是在 BST 的有序遍历过程中出现的下一个节点。 回想一下，中序遍历按以下顺序访问节点：

 1. 左子树
 2. 当前节点
 3. 右子树

 由于该树是 BST，因此中序遍历会按排序顺序生成值。 因此，节点的后继节点就是具有大于当前节点值的最小值的节点。 

输入由指向树中单个节点的指针组成。 输出应该是另一个`Node`代表后继者的对象。 如果不存在后继者，该函数应该返回`null`在 Go 或`None`在Python中。 

约束告诉我们树最多可以包含`10^4`节点，它足够大，如果存在更有针对性的解决方案，我们应该避免不必要地遍历整个树。 该问题还保证所有节点值都是唯一的，这简化了比较并确保只有一个有效的后继者。 

重要的观察是每个节点都有一个`parent`指针。 这显着改变了问题的性质，因为我们可以在树中向上移动而不需要根。 

一些边缘情况很重要：

 - 给定的节点可能是 BST 中的最大值，这意味着不存在后继节点。 
- 该节点可能有一个右子树，在这种情况下，后继节点位于该子树内的某个位置。 
- 该节点可能没有右子树，迫使我们通过父指针向上移动。 
- 一棵树可能只包含一个节点。 
- 继承人可能是直系父母或更高的祖先。 

如果幼稚的实现不能正确识别当前节点位于左子树中的第一个祖先，那么当通过父指针向上爬时，它很容易失败。 

## 方法

 ### 蛮力方法

 暴力解法重构BST的遍历顺序，然后找到紧随目标节点之后出现的节点。 

由于我们没有直接得到根，因此第一步是使用父指针向上爬，直到到达根。 一旦我们有了根，我们就会对树执行完整的有序遍历，并将所有访问过的节点存储在列表中。 之后，我们扫描列表以找到目标节点，如果存在则返回下一个元素。 

这种方法是正确的，因为 BST 的中序遍历总是会产生按排序顺序的节点。 因此，遍历顺序中的下一个节点正是中序后继节点。 

然而，这种方法效率低下，因为它会遍历整个树，即使后继节点通常可以在目标节点附近本地找到。 

### 最佳方法

 最佳解决方案将 BST 属性与父指针结合使用。 

有两个关键案例：

 1. 该节点有右子节点。 
2. 该节点没有右子节点。 

如果该节点有右子树，则后继节点必须是该右子树中最左边的节点。 这是可行的，因为后继节点是大于当前节点的最小值。 

如果该节点没有右子树，那么我们通过父指针向上移动，直到找到当前节点位于祖先左子树中的祖先。 那个祖先就是继承人。 

重要的见解是向上移动会跳过已经小于或等于当前节点的节点。 大于当前节点的第一个祖先正是排序顺序中的下一个节点。 

这种方法避免了遍历树的不相关部分，并且工作时间与树的高度成正比。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 执行完整的中序遍历并存储所有节点 |
 | 最佳| O(h) | O(1) | O(1) | 直接使用BST结构和父指针 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 检查当前节点是否有右孩子。 

如果存在右子树，则后继者必定位于其中。 具体来说，我们向右移动一步，然后继续向左移动，直到不再存在左子节点。 最终到达的节点是比当前节点大的最小值。 
2. 如果不存在右孩子，则开始使用父指针向上移动。 

在这种情况下，当前节点子树中的每个节点在中序遍历过程中都已被访问过。 因此，继承人必定是祖先。 
3. 当当前节点是其父节点的右子节点时，继续向上爬。 

如果我们从右子树向上移动，则意味着父树及其左子树已按遍历顺序较早被访问过，因此它们不能成为后继树。 
4. 出现以下情况时停止：

 - 我们到达一个父节点，其中当前节点是左子节点。 
- 我们没有祖先了。 
5. 如果存在这样的父级，则将其返回。 

该父节点是向上移动时遇到的第一个较大节点，使其成为中序遍历中的下一个节点。 
6. 如果不存在这样的父对象，则返回`None`或者`nil`。 

这意味着原始节点是 BST 中的最大元素，因此没有后继节点。 

### 为什么它有效

 该算法依赖于 BST 的排序保证和中序遍历的结构。 

如果一个节点有右子树，那么当前节点之后访问的下一个节点必须是该右子树内的最小节点，即最左后代。 

如果一个节点没有右子树，则向上遍历，直到到达尚未访问过的祖先。 当前节点位于左子树中的第一个祖先正是遍历顺序中的下一个节点。 

由于这是有序遍历中仅有的两个可能的遍历转换，因此算法始终返回正确的后继。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None
        self.parent = None
"""

from typing import Optional

class Solution:
    def inorderSuccessor(self, node: 'Node') -> 'Optional[Node]':
        # Case 1: Node has a right subtree
        if node.right:
            current = node.right

            while current.left:
                current = current.left

            return current

        # Case 2: Move upward until node becomes a left child
        current = node

        while current.parent and current == current.parent.right:
            current = current.parent

        return current.parent
```该实现直接反映了前面描述的算法。 

第一部分检查节点是否有右子节点。 如果是，则代码移至右子树并重复跟踪左指针。 返回最左边的节点，因为它是比原始节点大的最小节点。 

第二部分处理不存在右子树的情况。 变量`current`从目标节点开始，通过父节点指针向上爬。 虽然当前节点是右子节点，但我们继续向上移动，因为这些祖先已经在有序遍历中被访问过。 

一旦我们找到当前节点是左子节点的父节点，该父节点就成为后继节点。 如果我们到达树的顶部而没有找到这样的父节点，则该节点没有后继节点，因此该方法返回`None`。 

该实现仅使用恒定的额外空间，因为它仅存储几个指针变量。 

## 解决方案```go
/**
 * Definition for Node.
 * type Node struct {
 *     Val int
 *     Left *Node
 *     Right *Node
 *     Parent *Node
 * }
 */

func inorderSuccessor(node *Node) *Node {
    // Case 1: Right subtree exists
    if node.Right != nil {
        current := node.Right

        for current.Left != nil {
            current = current.Left
        }

        return current
    }

    // Case 2: Move upward through parents
    current := node

    for current.Parent != nil && current == current.Parent.Right {
        current = current.Parent
    }

    return current.Parent
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要的语言特定差异是使用`nil`而不是`None`。 

指针比较很简单，因为节点表示为指针。 循环条件也与 Python 几乎相同。 由于 Go 不像 Python 那样支持可选类型，因此返回`nil`自然代表后继无人。 

不需要对整数溢出进行特殊处理，因为该算法从不对节点值执行算术运算。 

## 工作示例

 ### 示例 1

 树：```
    2
   / \
  1   3
```输入：`node = 1`该节点没有右子节点，因此我们向上移动。 

| 步骤| 当前节点| 家长 | 行动|
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 节点是父节点的左子节点 |
 | 2 | 1 | 2 | 返回父|

 结果：`2`的继任者`1`是`2`。 

### 示例 2

 树：```
        5
       / \
      3   6
     / \
    2   4
   /
  1
```输入：`node = 6`该节点没有右子节点，因此我们向上移动。 

| 步骤| 当前节点| 家长 | 行动|
 | --- | --- | --- | --- |
 | 1 | 6 | 5 | 当前节点是右子节点 |
 | 2 | 5 | 空 | 继续向上|
 | 3 | 5 | 空 | 没有找到祖先|

 结果：`null`自从`6`是 BST 中的最大值，它没有后继。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(h) | 沿树高至多一次向下遍历和一次向上遍历 |
 | 空间| O(1) | O(1) | 仅使用了很少的指针变量|

 该算法永远不会访问超过树的高度。 在最坏的情况下，倾斜树的行为类似于链表，产生`O(n)`时间。 在平衡 BST 中，高度为`O(log n)`。 

空间复杂度保持不变，因为该算法使用迭代遍历，没有递归或辅助数据结构。

class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None
        self.parent = None

class Solution:
    def inorderSuccessor(self, node):
        if node.right:
            current = node.right

            while current.left:
                current = current.left

            return current

        current = node

        while current.parent and current == current.parent.right:
            current = current.parent

        return current.parent

def connect(parent, left=None, right=None):
    parent.left = left
    parent.right = right

    if left:
        left.parent = parent

    if right:
        right.parent = parent

sol = Solution()

# Example 1

n2 = Node(2)
n3 = Node(3)

 ## 边缘情况

 当目标节点是 BST 中的最大元素时，就会出现一种重要的边缘情况。 在这种情况下，树中没有更大的值，所以正确答案是`None`或者`nil`。 有缺陷的实现可能会无限期地继续向上遍历或错误地返回根。 该算法通过向上爬直到父级成为`None`。 

当节点具有包含多个左后代的右子树时，会发生另一种棘手的情况。 继承人不一定是直系右子女。 相反，它是右子树内最左边的节点。 该实现显式地继续向左移动，直到不再有左子节点存在。 

当继任者位于祖先而不是后代中时，就会出现第三种重要的边缘情况。 例如，如果节点没有右子节点并且深深嵌套在左子树内，则算法必须正确识别该节点位于左分支中的第一个祖先。 向上遍历循环通过跳过当前节点是右子节点的祖先来确保这一点。 

最后的边缘情况是单节点树。 由于该节点既没有子节点也没有祖先节点，因此该函数应该返回`None`。 该实现自然会处理这个问题，因为两种遍历情况都会立即终止而没有找到后继者。
