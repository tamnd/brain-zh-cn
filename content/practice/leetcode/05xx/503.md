[LeetCode 503 题](https://leetcode.com/problems/next-greater-element-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 问题给了我们一个**圆形数组**`nums`，对于每个元素，我们必须找到**下一个更大的元素**。 短语“下一个更大的元素”表示在数组中向前移动时遇到的第一个严格大于当前数字的值。 

关键的复杂之处在于该阵列是**圆形**。 通常，当搜索下一个更大的元素时，我们只会向右移动。 在这里，如果我们到达数组的末尾，我们就会回到开头并继续搜索，直到找到更大的数字或返回到原始位置。 

例如，考虑`nums = [1,2,1]`。 

第一个`1`发现`2`紧邻它的右边，所以它的答案是`2`。 

这`2`在循环遍历的任何地方都没有更大的值，所以它的答案是`-1`。 

最后一个`1`兜兜转转最终相遇`2`，所以它的答案也是`2`。 

输入是一个整数数组`nums`， 在哪里：

-`nums.length`范围从`1`到`10^4`- 每个值都可以是负数并且可以小到`-10^9`或大至`10^9`数组大小限制尤为重要。 检查每个数字的每个可能的下一个元素的解决方案将花费二次时间，`O(n²)`，当`n = 10^4`。 因此，我们需要一种更有效的方法。 

立即识别几个边缘情况很重要：

 - **单元素数组**，例如`[5]`，永远不可能有更大的下一个元素，所以答案一定是`[-1]`。 
- **所有元素都相等**的数组，例如`[3,3,3]`，应该返回所有`-1`s 因为不存在严格更大的元素。 
- **严格递减数组**，例如`[5,4,3,2,1]`，几乎每个元素都需要循环遍历。 
- 具有**重复值**的数组可能会很棘手，因为我们正在寻找一个**严格更大的**元素，而不是相等的元素。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是独立处理每个元素。 

对于每个索引`i`，我们模拟在圆形数组中向前移动并逐个检查元素，直到：

 1. 我们发现一个数大于`nums[i]`2.我们返回到原始索引，这意味着不存在更大的数字

 由于数组是循环的，我们可以使用模运算：```
next_index = (i + step) % n
```这保证了遍历在必要时回绕到开头。 

这种方法是正确的，因为它直接遵循问题定义。 对于每个元素，我们显式搜索按遍历顺序遇到的第一个较大值。 

然而，这种方法效率低下。 在最坏的情况下，每个元素都可能扫描几乎整个数组。 对于长度的数组`n`，这会产生`O(n²)`时间复杂度，对于较大的输入来说太慢了。 

### 最优方法，单调堆栈

 关键的观察结果是，在暴力解决方案中发生了许多重复比较。 

我们可以以**重用以前的工作**的方式处理数组，而不是独立搜索每个元素。 

我们使用**单调递减堆栈**来跟踪尚未找到下一个更大元素的索引。 

这个想法是这样的：

 处理数字时，如果它大于堆栈顶部表示的元素，则它成为该索引的下一个更大元素。 

因为数组是圆形的，所以我们模拟遍历它**两次**。 迭代`2 * n`times 确保每个元素都有机会查看数组末尾并环绕。 

堆栈保持**单调递减**，这意味着堆栈索引表示的值按降序存储。 每当出现较大的值时，就会立即解析较小的元素。 

这消除了冗余扫描并将时间复杂度降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个元素的每个下一个位置 |
 | 最佳| O(n) | O(n) | 带循环模拟的单调递减堆栈 |

 ## 算法演练

 ### 使用单调堆栈的最优算法

 1.初始化一个大小为answer的数组`n`充满`-1`。 

我们最初假设不存在更大的元素。 如果我们稍后找到一个，我们就会覆盖该值。 
2. 创建一个空堆栈。 

我们不存储值，而是存储**索引**。 索引允许我们访问原始数字并直接更新结果数组。 
3.遍历数组`2 * n`次。 

由于阵列是圆形的，单次通过是不够的。 迭代两次模拟自然环绕。 

在每次迭代时：```
current_index = i % n
current_value = nums[current_index]
```4. 当堆栈不为空且当前值大于堆栈顶部索引表示的元素时，解析待处理的答案。 

这意味着：```
nums[stack[-1]] < current_value
```当前值是该索引遇到的第一个较大数字，因此：```
result[stack.pop()] = current_value
```5. 仅在第一遍期间，将索引推入堆栈。 

我们仅在以下情况下添加索引`i < n`。 

这可以避免重复的条目，因为第二次遍历只是为了模拟循环查找。 
6. 继续直到所有迭代完成。 

仍在堆栈中的任何索引从未找到更大的元素，因此其答案仍然存在`-1`。 

### 为什么它有效

 关键的不变量是堆栈总是存储尚未找到下一个更大元素的索引，并且它们对应的值保持降序排列。 

每当出现较大的值时，它会立即解析在堆栈顶部等待的所有较小元素。 由于每个索引都被压入一次并弹出一次，因此每个元素都会得到有效处理，同时仍然保留正确的遍历顺序。 第二遍通过允许数组末尾附近的元素搜索开头来保证循环行为。 

## Python 解决方案```python
from typing import List

class Solution:
    def nextGreaterElements(self, nums: List[int]) -> List[int]:
        n = len(nums)
        result = [-1] * n
        stack = []

        for i in range(2 * n):
            current_index = i % n
            current_value = nums[current_index]

            while stack and nums[stack[-1]] < current_value:
                index = stack.pop()
                result[index] = current_value

            if i < n:
                stack.append(current_index)

        return result
```实现首先创建一个结果数组，其中填充`-1`，它表示默认假设不存在更大的元素。 

堆栈存储未解析的索引。 我们故意存储索引而不是值，因为索引让我们既可以与原始数组进行比较，又可以更新其中的正确位置`result`。 

循环运行时间为`2 * n`迭代来模拟循环遍历。 模算术将双倍迭代转换为有效的数组位置。 

在循环内部，`while`条件检查当前值是否可以解析堆栈中挂起的较小元素。 如果是这样，我们会重复弹出索引并分配它们的下一个更大的值。 

我们只在第一次传递期间推送索引，因为每个索引应该在堆栈中恰好出现一次。 第二遍的存在只是为了帮助未解决的元素通过环绕遍历找到答案。 

最后，该方法返回填充的结果数组。 

## 解决方案```go
func nextGreaterElements(nums []int) []int {
	n := len(nums)
	result := make([]int, n)

	for i := range result {
		result[i] = -1
	}

	stack := []int{}

	for i := 0; i < 2*n; i++ {
		currentIndex := i % n
		currentValue := nums[currentIndex]

		for len(stack) > 0 &&
			nums[stack[len(stack)-1]] < currentValue {

			index := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			result[index] = currentValue
		}

		if i < n {
			stack = append(stack, currentIndex)
		}
	}

	return result
}
```Go 的实现与 Python 的逻辑非常相似。 

由于 Go 切片是用零值初始化的，因此我们显式填充`result`和`-1`。 堆栈被实现为索引切片，其中切片的末尾充当堆栈顶部。 

弹出是通过切片完成的：```go
stack = stack[:len(stack)-1]
```Go 整数可以安全地处理问题约束，因为值在`±10^9`，很容易符合标准`int`在现代系统上键入。

 | --- | --- | --- |

 ## 边缘情况

 ### 单元素数组

 仅包含一个元素的数组，例如`[7]`，如果循环遍历处理不仔细的话很容易导致bug。 幼稚的实现可能会意外地将元素与其自身进行比较，并错误地得出结论：它是下一个更大的值。 我们的实现避免了这个问题，因为没有任何值严格大于，因此堆栈条目仍然未解析，并且默认值`-1`保持不变。 

### 所有元素都相等

 考虑`[4,4,4]`。 由于该问题需要一个**严格更大**的数字，因此相等的值不符合条件。 一个常见的错误是不小心使用`<=`而不是`<`比较堆栈元素时。 我们的实现使用：```
nums[stack[-1]] < current_value
```这保证只有严格更大的数量才能解析挂起的元素。 

### 严格递减数组

 输入如`[5,4,3,2,1]`具有挑战性，因为大多数元素在第一次通过时无法在其右侧找到更大的值。 如果没有适当的循环处理，算法将错误地返回所有`-1`是。 第二次遍历通过允许较小的元素环绕并发现来解决这个问题`5`， 尽管`5`本身正确地保留`-1`。 

### 重复峰

 数组就像`[2,1,2]`可以暴露涉及重复最大值的逻辑错误。 第一个`2`不应该使用第二个`2`作为其下一个更大的元素，因为相等不重要。 只有严格大于的值才符合条件。 单调堆栈逻辑正确地保留未解析的索引，直到出现真正更大的数字，或者将它们保留为`-1`如果不存在。
