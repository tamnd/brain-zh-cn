 # LeetCode 546，删除框

 ## 问题理解

 问题给了我们一个名为`boxes`，其中每个整数代表盒子的颜色。 我们可能会重复删除具有相同颜色的相邻框组。 如果我们删除一个包含`k`盒子，我们赚`k * k`点。 

重要的细节是移除盒子会改变数组的结构。 移除中间框后，先前分离的框可能会变得相邻。 这意味着我们删除组的顺序非常重要。 

目标是在所有盒子被移除后最大化总分。 

例如，假设我们有：```
[1,3,2,2,2,3,4,3,1]
```如果我们删除三个相邻的`2`首先，我们获得`3 * 3 = 9`点。 当它们消失后，剩下的数组变成：```
[1,3,3,4,3,1]
```现在出现了更多的机会，因为一些相同的颜色变得更加接近。 

约束条件很重要：

 -`1 <= boxes.length <= 100`-`1 <= boxes[i] <= 100`对于所有可能的删除序列的强力枚举来说，100 的数组大小太大。 删除群体的不同方法的数量呈爆炸式增长，因为每次删除都会改变未来的可能性。 

这立即表明我们需要带有记忆功能的动态编程。 

一些边缘情况尤其重要：

 - 仅包含一种颜色的数组，其中一次删除所有颜色是最佳选择。 
- 相同颜色被其他颜色分隔的数组。 
- 具有交替颜色的数组，稍后合并相等的值可能会产生更高的分数。 
- 非常小的数组，例如长度为 1。 
- 首先删除较小的组允许稍后合并更大的组的情况。 

主要挑战是局部最优的移动通常不是全局最优的。 

## 方法

 ### 蛮力方法

 强力解决方案将在每一步递归地尝试每个可能的可移动组。 

At any point:

 1. 找到每个连续的等值段。 
2. Remove one segment.
 3. 递归求解剩余数组。 
4. 返回所有选项中的最高分。 

这种方法是正确的，因为它探索了所有可能的移除顺序。 最终，它发现了最佳序列。 

然而，它太慢了。 每次删除都会创建一个新的阵列配置，并且可能的序列数量呈指数增长。 由于数组长度可以达到100，暴力破解变得完全不切实际。 

核心问题是子问题重叠。 相同的剩余配置在递归过程中重复出现。 

### 最佳解决方案的关键见解

 这个问题的困难部分在于，延迟删除一些框可能是有益的，以便它们稍后可以与匹配的框合并。 

考虑：```
[1, 2, 1]
```如果我们删除第一个`1`立即：

 - 删除`1`，增益 1
 - 删除`2`，增益 1
 - 删除`1`，增益 1
 - 总计 = 3

 但如果我们删除`2`第一：

 - 删除`2`，增益 1
 - 数组变成`[1,1]`- 删除两者`1`在一起，获得 4
 - 总计 = 5

 这意味着 DP 状态不仅必须记住当前的子数组，还必须记住有多少个等色框已经分组到一侧。 

标准解使用 3D 动态规划状态：```
dp(left, right, count)
```这意味着：

 - 我们正在求解子数组`boxes[left:right+1]`- 已经有`count`额外的盒子等于`boxes[left]`附在左侧

 这个附加参数是解决问题的关键见解。

 ## 算法演练

 ### 最优动态规划策略

 我们定义：```
dp(left, right, count)
```在哪里：

-`left`和`right`定义当前间隔
 -`count`代表有多少个额外的盒子等于`boxes[left]`被分组在一起`boxes[left]`The function returns the maximum score obtainable from this interval.

 ### 逐步过程

 1. 定义递归状态。 

我们解决子数组的问题`boxes[left:right+1]`。 参数`count`跟踪匹配的附加框`boxes[left]`从区间外部合并的。 

这是必要的，因为较大的群体会产生不成比例的较大分数。 
2. 处理基本情况。 

如果：```
left > right
```那么就没有剩下的盒子了，所以分数是 0。 
3. 在开始处压缩连续的相等框。 

假设我们有：```
[2,2,2,3,...]
```我们没有单独处理它们，而是立即将它们合并到进位计数中。 

例如：```
dp(left, right, count)
```变成：```
dp(newLeft, right, count + mergedCount)
```这种优化减少了重复状态。 
4. 计算直接移除选项。 

一种可能性是立即删除当前组。 

如果当前合并组大小为：```
count + 1
```然后删除它给出：```
(count + 1)^2
```加上剩余时间间隔的最佳分数。 
5. 稍后尝试与匹配的框合并。 

我们扫描区间寻找以下位置：```
boxes[mid] == boxes[left]
```如果存在这样的职位，我们可以：

 - 首先删除他们之间的所有东西
 - 然后将匹配的框合并成一个更大的组

 这通常会产生更好的分数。 
6. 取最大结果。 

DP 状态返回以下各项中的最佳分数：

 - 立即删除
 - 延迟删除以稍后合并
 7. 记住结果。 

由于许多递归调用重复相同的状态，因此记忆可以避免重新计算。 

### 为什么它有效

 该算法之所以有效，是因为一个区间的每个最佳策略最终都必须为领先群体选择两种可能性之一：

 - 立即将其删除
 - 稍后将其与匹配的框合并

 DP 详尽地探索了这两种可能性，而记忆则保证了每个独特的状态仅被解决一次。 进位参数保留了做出最佳未来决策所需的所有信息，因此递归始终计算真正的最佳分数。 

## Python 解决方案```python
from functools import lru_cache
from typing import List

class Solution:
    def removeBoxes(self, boxes: List[int]) -> int:
        n = len(boxes)

        @lru_cache(None)
        def dp(left: int, right: int, count: int) -> int:
            if left > right:
                return 0

            # Merge consecutive equal boxes
            while left < right and boxes[left] == boxes[left + 1]:
                left += 1
                count += 1

            # Option 1:
            # Remove current group immediately
            best = (count + 1) * (count + 1) + dp(left + 1, right, 0)

            # Option 2:
            # Merge with future matching boxes
            for mid in range(left + 1, right + 1):
                if boxes[mid] == boxes[left]:
                    score = (
                        dp(left + 1, mid - 1, 0)
                        + dp(mid, right, count + 1)
                    )
                    best = max(best, score)

            return best

        return dp(0, n - 1, 0)
```其实现直接遵循递归区间DP结构。 

这`dp(left, right, count)`函数表示区间的最佳答案，同时带有额外的匹配框。 

第一个`while`循环压缩连续的相等值。 这是一项重要的优化，因为连续的相等框应始终被视为一个更大的组。 

变量`best`首先存储立即删除当前组所获得的分数。 

然后循环搜索未来的匹配框。 每当找到匹配的颜色时，算法都会首先删除中间部分，以便匹配组可以合并。 

记忆通过`@lru_cache(None)`确保每个状态仅计算一次。 

最后，解决方案从整个数组开始，不带进位：```python
dp(0, n - 1, 0)
```## 解决方案```go
func removeBoxes(boxes []int) int {
	n := len(boxes)

	memo := make(map[[3]int]int)

	var dp func(int, int, int) int

	dp = func(left, right, count int) int {
		if left > right {
			return 0
		}

		key := [3]int{left, right, count}

		if val, exists := memo[key]; exists {
			return val
		}

		originalLeft := left
		originalCount := count

		// Merge consecutive equal boxes
		for left < right && boxes[left] == boxes[left+1] {
			left++
			count++
		}

		// Remove current group immediately
		best := (count+1)*(count+1) + dp(left+1, right, 0)

		// Try merging with future matching boxes
		for mid := left + 1; mid <= right; mid++ {
			if boxes[mid] == boxes[left] {
				score := dp(left+1, mid-1, 0) +
					dp(mid, right, count+1)

				if score > best {
					best = score
				}
			}
		}

		memo[[3]int{originalLeft, right, originalCount}] = best

		return best
	}

	return dp(0, n-1, 0)
}
```Go 版本使用`map[[3]int]int`作为记忆结构，因为 Go 没有像 Python 那样提供内置的记忆装饰器`lru_cache`。 

递归逻辑在其他方面是相同的。 

Go 切片是对数组的轻量级引用，因此传递`boxes`递归调用是高效的。 

整数溢出不是问题，因为最大分数受以下限制：```go
100 * 100 = 10000
```很容易适合 Go 的`int`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^4) | O(n^4) | 有 O(n^3) 个状态，每个状态可以扫描 O(n) 个位置 |
 | 空间| O(n^3) | O(n^3) | 记忆表存储所有 DP 状态 |

 DP状态由三个维度组成：

 -`left`-`right`-`count`每个最多可以变化`n`，生产`O(n^3)`州。 

对于每个状态，我们可以扫描区间寻找匹配的颜色，这会花费`O(n)`时间。 

因此，总复杂度变为：```
O(n^4)
```这是可以接受的`n <= 100`。

 ## 边缘情况

 ### 单盒

 单个元素数组是最小的有效输入。 有缺陷的实现可能会意外地递归到无效范围或错误处理基本情况。 

例如：```
[1]
```该实现正确处理了这个问题，因为：```
(left > right)
```对于空间隔返回 0，单个框贡献：```
(0 + 1)^2 = 1
```### 所有盒子都有相同的颜色

 考虑：```
[2,2,2,2]
```显然，最佳策略是立即删除所有内容：```
4^2 = 16
```如果没有连续压缩优化，DP 将生成许多冗余状态。 该实现通过立即合并相邻的相等值来避免这种情况`while`环形。 

### 相同的颜色被其他颜色分开

 这是最重要的边缘情况。 

例子：```
[1,2,1]
```删除第一个可用组的贪心算法将会失败。 

正确的解决方案是去掉中间的`2`首先所以两个`1`s 变得相邻。 

这`count`DP状态中的参数是专门为处理这种情况而设计的。 它允许递归记住推迟的组，然后将它们合并为更大的评分删除。
