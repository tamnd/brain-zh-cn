[LeetCode 508 题](https://leetcode.com/problems/most-frequent-subtree-sum/)

 **难度：** 🟡 中等
 **主题：** 哈希表、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们计算二叉树中每个节点的子树和，然后确定哪个子树和出现最频繁。 

以节点为根的子树包括该节点及其所有后代。 子树总和只是该子树中包含的每个值的总和。 

例如，考虑树：```
    5
   / \
  2  -3
```子树总和为：

 - 节点`2`→ 总和 =`2`- 节点`-3`→ 总和 =`-3`- 节点`5`→ 总和 =`5 + 2 + (-3) = 4`每个总和只出现一次，因此返回所有三个值。 

输入是二叉树的根节点。 输出是一个整数列表，表示出现频率最高的所有子树总和。 

这些约束告诉我们一些重要的事情：

 - 树最多可以包含`10^4`节点。 
- 节点值可能为负。 
- 保证树至少包含一个节点。 

由于树可能很大，低效的重复计算将变得昂贵。 比线性或近线性时间更差的算法可能会在上限上挣扎。 

一些边缘情况很重要：

 - 一棵只有一个节点的树。 
- 以相同频率出现的多个子树和。 
- 负子树和。 
- 由对称或重复结构引起的重复子树和。 
- 高度倾斜的树，类似于链表。 

幼稚的实现可能会重复地重新计算重叠子树的子树总和，从而导致不必要的工作。 

## 方法

 ### 蛮力方法

 一种简单的方法是独立计算每个节点的子树和。 

对于每个节点：

 1. 递归计算其整个子树的和。 
2. 将该总和存储在频率图中。 
3. 对树中的每个节点重复该过程。 

问题在于子树计算严重重叠。 假设我们计算父节点的子树和。 它的计算已经包括所有后代的总和。 如果我们稍后再次从头开始计算这些后代的子树总和，则会重复访问相同的节点。 

在最坏的情况下，例如倾斜的树，这会导致二次复杂度。 

这种方法是正确的，因为每个子树总和最终都会被计算和计数，但由于冗余的遍历工作，效率很低。 

### 最佳方法

 关键的观察是子树和可以自然地使用后序深度优先遍历来计算。 

子树总和取决于：

 - 左子树总和，
 - 右子树总和，
 - 当前节点值。 

这意味着我们应该在处理父级之前处理子级。 

使用单个 DFS 遍历：

 1. 递归计算左子树和。 
2. 递归计算右子树和。 
3. 将它们与当前节点值相结合。 
4. 将结果总和记录在哈希图中。 

因为每个节点只处理一次，所以我们完全避免了冗余计算。 

哈希图非常适合跟踪频率，因为子树和可能为负、很大或任意重复。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复重新计算子树和 |
 | 最佳| O(n) | O(n) | 单后序DFS遍历|

 ## 算法演练

 1. 创建一个哈希图来存储子树和频率。 

键是子树的总和，值是总和出现的次数。 我们需要快速插入和查找，这使得哈希映射成为自然的选择。 
2. 初始化一个变量来跟踪迄今为止看到的最大频率。 

在计算子树总和时，我们不断更新该值，以便知道哪些总和当前最频繁。 
3. 执行后序DFS 遍历。 

后序遍历至关重要，因为节点的子树和取决于其子节点的和。 我们必须在计算父项总和之前计算子项总和。 
4. 对于每个节点，递归计算左子树和。 

如果左边的孩子是`None`，其贡献为`0`。 
5. 递归计算右子树和。 

同样，缺失的右孩子也有贡献`0`。 
6. 计算当前子树之和。 

公式为：$\text{sum} = \text{node.val} + \text{leftSum} + \text{rightSum}$7.更新频率图。 

增加计算的子树总和的计数。 
8. 如果需要，更新最大频率。 

如果此子树总和现在比之前的总和出现得更频繁，则更新最大频率跟踪器。 
9. 将子树和向上返回给父调用。 

这允许父节点有效地构建自己的子树和。 
10. DFS 完成后，迭代频率图。 

收集频率等于最大频率的每个子树和。 
11. 返回结果列表。 

### 为什么它有效

 该算法之所以有效，是因为每个子树总和在后序遍历期间只计算一次。 当处理一个节点时，算法已经知道其左子树和右子树的确切和，因此当前子树和被正确计算。 

由于每个子树和都被插入频率图中一次，因此频率计数是准确的。 最后，选择具有最大频率的所有和可以保证正确的答案。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, List
from collections import defaultdict

class Solution:
    def findFrequentTreeSum(self, root: Optional[TreeNode]) -> List[int]:
        frequency = defaultdict(int)
        max_frequency = 0

        def dfs(node: Optional[TreeNode]) -> int:
            nonlocal max_frequency

            if not node:
                return 0

            left_sum = dfs(node.left)
            right_sum = dfs(node.right)

            current_sum = node.val + left_sum + right_sum

            frequency[current_sum] += 1
            max_frequency = max(max_frequency, frequency[current_sum])

            return current_sum

        dfs(root)

        result = []

        for subtree_sum, count in frequency.items():
            if count == max_frequency:
                result.append(subtree_sum)

        return result
```该实现直接遵循后序DFS策略。 

这`frequency`字典存储每个子树和出现的次数。 这`max_frequency`变量跟踪遍历过程中遇到的最高出现次数。 

嵌套的`dfs`函数递归计算子树总和。 基本情况返回`0`对于空节点，这简化了递归公式并避免了对丢失子节点的特殊处理。 

对于每个节点，函数：

 1. 计算左子树和。 
2. 计算右子树和。 
3. 将它们与当前节点值组合。 
4.更新频率图。 
5. 更新最大频率。 
6. 向上返回子树和。 

遍历结束后，最后的循环收集所有频率与最大频率匹配的子树和。 

该解决方案很简洁，因为 DFS 自然地对子树计算进行建模。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func findFrequentTreeSum(root *TreeNode) []int {
    frequency := make(map[int]int)
    maxFrequency := 0

    var dfs func(node *TreeNode) int

    dfs = func(node *TreeNode) int {
        if node == nil {
            return 0
        }

        leftSum := dfs(node.Left)
        rightSum := dfs(node.Right)

        currentSum := node.Val + leftSum + rightSum

        frequency[currentSum]++

        if frequency[currentSum] > maxFrequency {
            maxFrequency = frequency[currentSum]
        }

        return currentSum
    }

    dfs(root)

    result := []int{}

    for subtreeSum, count := range frequency {
        if count == maxFrequency {
            result = append(result, subtreeSum)
        }
    }

    return result
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用一个`map[int]int`用于频率跟踪而不是 Python`defaultdict`。 

递归 DFS 被实现为分配给变量的闭包。 空节点表示为`nil`。 

The result is accumulated using a slice. 由于 Go 以任意顺序映射返回键，因此返回的切片顺序是未指定的，这是可以接受的，因为问题允许任何顺序。 

Integer overflow is not an issue under the given constraints because the maximum possible subtree sum remains within Go's`int`范围。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 频率图和递归堆栈最多可以存储 n 个元素 |

 DFS遍历每一个节点都处理一次，遍历中的每一个操作都是常数时间。 因此，总运行时间与节点数量呈线性关系。 

频率图最多可以包含`n`唯一的子树和。 此外，递归堆栈可以增长到`O(n)`在最坏的情况下，对于高度倾斜的树。

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树是最小的有效输入。 有缺陷的实现可能会错误地假设子项的存在或无法正确初始化频率跟踪。 

该实现自然地处理了这个问题，因为 null 子节点贡献了`0`，因此子树的总和就变成了节点的值。 

### 等频多重求和

 该问题允许存在联系，这意味着多个子树和可能同样频繁地出现。 一个常见的错误是仅返回一个值而不是所有最大频率总和。 

该实现通过在遍历后扫描频率图并收集计数等于最大频率的每个总和来避免这种情况。 

### 高度倾斜的树

 树可能会退化为链表形状，导致递归深度随着节点数量线性增长。 

该算法仍然可以正常工作，因为每个节点都被访问一次，尽管递归堆栈的使用变得`O(n)`在最坏的情况下。 

### 负值

 子树总和可能会变为负数，因为节点值本身可能为负数。 一些不正确的实现假设总和是非负的，并使用数组索引而不是哈希映射。 

使用哈希映射允许任意整数和，包括负值，而无需任何特殊处理。
