 ## 解决方案

 ## 问题理解

 问题给出了一个数组`nums`含有`2n`整数。 我们的任务是将这些整数精确地划分为`n`对。 对于每对`(ai, bi)`，我们取较小的值，`min(ai, bi)`。 计算出每对的最小值后，我们将所有这些最小值相加。 

目标是排列配对以使最终的总和尽可能大。 

例如，假设我们有：```
[1, 4, 3, 2]
```我们需要形成两对，因为数组长度是`4 = 2 * 2`。 

一种可能的配对是：```
(1, 4), (2, 3)
```最小值为：```
1 and 2
```总数变为：```
1 + 2 = 3
```但是，如果我们改为配对：```
(1, 2), (3, 4)
```最小值为：```
1 and 3
```这给出：```
1 + 3 = 4
```这个更大，所以它是最佳答案。 

约束条件很重要：

 -`nums.length == 2 * n`-`1 <= n <= 10^4`-`-10^4 <= nums[i] <= 10^4`该数组最多可以包含`20,000`元素，它足够大，以至于指数或阶乘解决方案完全不切实际。 由于值的范围介于`-10^4`和`10^4`，尽管标准排序已经足够高效，但基于计数排序的解决方案也是可能的。 

输入保证数组长度始终是偶数，因此我们永远不需要担心不匹配的元素。 该数组可能包含：

 - 重复值
 - 负数
 - 所有相同的值
 - 非常大或非常小的有效整数

 如果尝试所有可能的配对，简单的实现可能会失败，因为配对组合的数量增长得非常快。 

## 方法

 ### 蛮力方法

 蛮力的想法是生成所有可能的方式来配对数字。 对于每个配对安排，我们计算：```
min(pair1) + min(pair2) + ...
```并保持最大结果。 

这种方法是正确的，因为它探索了每一种可能的有效分组，因此最终必须找到最佳答案。 

然而，可能的配对数量是巨大的。 对于长度的数组`2n`，划分成对的方法数量呈阶乘增长。 即使对于中等大小的输入，这在计算上也是不可能的。 

例如：

 - 10个号码，配对的数量已经非常多了。 
- 20000个数字，暴力破解是完全行不通的。 

我们需要更有效的观察。 

### 最优贪心法

 关键的见解是，对数组进行排序后，最佳策略是将相邻元素配对。 

假设排序后的数组为：```
a0 <= a1 <= a2 <= a3 <= ...
```如果我们将相邻的数字配对：```
(a0, a1), (a2, a3), ...
```那么每对的最小值就是：```
a0 + a2 + a4 + ...
```为什么这是最佳的？ 

每对中较小的数字决定了对总和的贡献。 为了最大化总数，我们希望较小的数字尽可能大。 将小数配对在一起可以防止大数被“浪费”，因为配对中的较大元素与小数相同。 

排序确保数字有序，而配对邻居可以最小化每对内部的间隙，从而最大化较小元素的总和。

 | --- | --- | --- | --- |
 | 蛮力 | O((2n)!) | O((2n)!) | O(n) | 尝试每一种可能的配对安排 |

 ## 算法演练

 ### 最优贪心算法

 1. 按非降序对数组进行排序。 

排序将较小的数字放在一起，将较大的数字放在一起。 这种排序是贪婪策略的基础。 
2. 初始化变量`total`到`0`。 

该变量将存储每对最小值的总和。 
3. 遍历排序后的数组，步长为`2`。 

由于相邻元素形成每对，因此每对的第一个元素出现在索引处：```
0, 2, 4, 6, ...
```4. 将每个偶数索引处的元素添加到`total`。 

在已排序的相邻对中：```
nums[i] <= nums[i + 1]
```所以这对中的最小值总是`nums[i]`。 
5. 返回`total`。 

处理完所有对后，`total`包含最大可能的总和。 

### 为什么它有效

 排序后，每个相邻对的差异尽可能最小。 如果一个小数字与一个大得多的数字配对，则较大的数字不会对总和做出贡献，因为只有最小值才重要。 将相邻元素配对可以防止浪费大值，并最大化每对较小元素的贡献。 

这种贪心的安排保证了最优的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def arrayPairSum(self, nums: List[int]) -> int:
        nums.sort()

        total = 0

        for i in range(0, len(nums), 2):
            total += nums[i]

        return total
```实现首先对数组进行排序。 一旦排序，每对相邻元素都代表最佳配对排列。 

变量`total`积累答案。 循环增量为`2`因为每次迭代都会处理一对。 由于数组已排序，因此索引处的元素`i`始终是该对中较小的值`(nums[i], nums[i + 1])`。 

最后，该方法返回累积和。 

## 解决方案```go
package main

import "sort"

func arrayPairSum(nums []int) int {
	sort.Ints(nums)

	total := 0

	for i := 0; i < len(nums); i += 2 {
		total += nums[i]
	}

	return total
}
```Go 实现遵循与 Python 版本相同的逻辑。 这`sort.Ints()`函数按升序对切片进行排序。 

Go 切片是数组的动态视图，因此排序会直接修改原始切片。 整数溢出在这里不是一个问题，因为最大可能的答案完全适合 Go 的范围`int`范围。 

循环增量为`2`以便仅将每个相邻对的第一个元素添加到结果中。

 ## 边缘情况

 一种重要的边缘情况是最小有效输入大小。 当数组仅包含两个元素时，恰好存在一对可能的元素。 某些实现错误地假设多次迭代或尝试不必要的逻辑。 该解决方案可以自然地处理这种情况，因为循环只执行一次。 

另一个重要的情况涉及负数。 由于目标仍然是最大化最小值之和，因此即使值为负数排序也保持正确。 例如：```
[-4, -3, -2, -1]
```变成：```
(-4, -3), (-2, -1)
```其产生：```
-4 + -2 = -6
```该实现可以正常工作，因为无论符号如何，排序都会保留最佳邻接属性。 

第三个重要的边缘情况是重复值。 数组如：```
[5,5,5,5]
```有时会暴露配对假设或索引错误。 由于每一对都有相同的元素，因此每种排列都会产生相同的答案。 该算法仍然可以正常工作，因为相邻配对仍然有效。 

另一个微妙的情况是已经排序或反向排序的输入。 某些实现意外地依赖于原始排序或执行不正确的交换。 由于此解决方案明确首先排序，因此输入的初始排列并不重要。
