[LeetCode 584 题](https://leetcode.com/problems/find-customer-referee/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个`Customer`具有三列的表：`id`,`name`， 和`referee_id`。 每行代表一个客户，他们的唯一标识符（`id`)、他们的名字，以及可选的`id`推荐他们的客户。 一个`null`值在`referee_id`表明该客户没有被任何人推荐。 

任务是识别满足以下两个条件之一的所有客户：要么他们是由某个客户推荐的，而该客户的推荐人是`id`不是 2**，或者他们**根本没有被任何人推荐**（`referee_id`是`null`）。 结果应作为具有单列的表返回，`name`，并且顺序无关紧要。 

重要的限制包括`id`每个客户都是独一无二的，并且无法保证客户总数，但考虑到“简单”难度，我们可以假设`O(n)`解决方案是可以接受的。 关键边缘案例涉及由以下人士推荐的客户`id = 2`（应排除），客户`referee_id`作为`null`，以及表为空的可能性。 

## 方法

 蛮力方法是迭代所有行`Customer`表，检查每个客户是否`referee_id`是`null`或不等于2，然后手动收集他们的名字。 这种方法之所以有效，是因为它明确地评估了每个客户的问题情况。 然而，在 SQL 中，如果表大小增长，使用多个联接或子查询编写此操作可能会变得冗长且效率较低。 

最佳方法是利用单个 SQL 查询`WHERE`根据两个条件直接过滤客户的条件：`referee_id != 2`或者`referee_id IS NULL`。 这消除了不必要的复杂性，并以最少的计算有效地检索所需的结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 迭代所有客户并逐行应用条件检查 |
 | 最佳 | O(n) | O(n) | 单个 SQL 查询`WHERE`子句过滤依据`referee_id != 2`或者`referee_id IS NULL`|

 ## 算法演练

 1. 首先检查`Customer`表逐行。 
2. 对于每个客户，检查是否`referee_id`是`null`（未提及）或不同于 2 的数字（由客户 2 以外的其他人提及）。 
3. 如果客户满足任一条件，请选择他们的`name`并将其包含在结果集中。 
4. 继续此过程，直到评估完所有行。 
5. 以表格形式返回结果名称列表。 由于顺序并不重要，因此无需排序。 

为什么它有效：通过直接应用两个条件`WHERE`条款，我们保证只有未经推荐或由其他人推荐的客户`id = 2`被选中。 这保留了问题的逻辑约束并确保了正确性。 

## Python 解决方案```python
# SQL problem; Python simulation using SQLite for demonstration
import sqlite3
from typing import List

def find_customers_referee(cursor: sqlite3.Cursor) -> List[str]:
    query = """
    SELECT name
    FROM Customer
    WHERE referee_id IS NULL OR referee_id != 2
    """
    cursor.execute(query)
    results = cursor.fetchall()
    return [row[0] for row in results]
```在此 Python 解决方案中，我们连接到 SQLite 数据库并执行单个查询。 查询直接表达了问题中的两个条件：`referee_id IS NULL`捕获未经任何人推荐的客户，并且`referee_id != 2`捕获除客户 2 之外的任何人推荐的客户。`fetchall()`函数检索所有匹配的行，列表推导式提取`name`最终输出的列。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func findCustomersReferee(db *sql.DB) ([]string, error) {
    query := `
    SELECT name
    FROM Customer
    WHERE referee_id IS NULL OR referee_id != 2
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var result []string
    for rows.Next() {
        var name string
        if err := rows.Scan(&name); err != nil {
            return nil, err
        }
        result = append(result, name)
    }
    return result, nil
}
```在 Go 中，我们使用以下命令查询数据库`db.Query`，迭代结果行，并附加每个有效的行`name`到一片。 Go 需要显式处理`nil`和错误传播，这就是为什么我们在每个步骤中检查错误并推迟行的关闭以确保资源得到清理的原因。

 ## 边缘情况

 一种重要的边缘情况是所有客户都由`id = 2`。 在这种情况下，结果应该为空。 这是正确处理的，因为`WHERE`条款明确排除`referee_id = 2`。 

另一个边缘情况是当所有客户都有`null`作为`referee_id`。 该算法正确地包含它们，因为`referee_id IS NULL`每行的计算结果都为 true。 

第三种边缘情况是只有一个客户的表，要么被 2 引用，要么被另一个客户引用，要么未被引用。 每个场景都由相同的条件逻辑正确处理，不需要额外的检查。 这确保最小或极端的输入不会破坏查询。
