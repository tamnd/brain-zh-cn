 ## 解决方案

 ## 问题理解

 该问题要求我们计算 n 叉树的最大深度。 N 叉树是每个节点可以有零个或多个子节点的树，这与每个节点最多有两个子节点的二叉树不同。 

树的深度定义为从根节点到任意叶节点的最长路径上的节点数。 叶节点是没有子节点的节点。 

给定树的根节点，我们必须返回一个表示最大深度的整数。 

例如，考虑树：```
        1
     /  |  \
    3   2   4
   / \
  5   6
```从根到叶子的最长路径是：```
1 -> 3 -> 5
```该路径包含 3 个节点，因此最大深度为`3`。 

问题陈述中显示的输入序列化使用级别顺序遍历`null`分隔符来指示子组。 然而，在LeetCode上解决问题时，我们不需要自己解析这个序列化。 我们直接给出所构造树的根节点。 

这些约束告诉我们一些重要的事情：

 - 树最多可以包含`10^4`节点。 
- 深度可以大到`1000`。 

这意味着该算法必须足够高效，能够处理数千个节点，而无需进行不必要的重复工作。 

一些边缘情况很重要：

 - 树可能是空的，这意味着`root`是`None`或者`nil`。 
- 树可能只包含一个节点。 
- 树可能高度不平衡，形成深度链`1000`。 
- 一些节点可能有很多子节点，而另一些节点则没有。 

正确的解决方案必须安全有效地处理所有这些场景。 

## 方法

 一个蛮力的想法是独立地重复计算每个子树的深度。 对于每个节点，我们可以递归地计算每个子子树的深度并比较它们，但如果不仔细组织，这可能会导致同一子树多次重复计算。 

虽然这最终会产生正确的答案，但效率很低，因为可能会重复遍历相同的分支。 在最坏的情况下，时间复杂度可能会显着大于所需的值。 

最佳解决方案的关键观察是节点的深度仅取决于其子节点之间的最大深度。 

对于任意节点：

 - 如果它没有孩子，它的深度是`1`。 
- 否则，其深度为：```
1 + maximum depth among all children
```这自然意味着深度优先搜索遍历。 我们递归地计算每个子节点的深度一次，然后使用这些结果来计算当前节点的深度。 

由于每个节点只被访问一次，因此该解决方案是最优的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(H) | 多次重新计算子树深度 |
 | 最优 DFS | O(N) | O(H) | 恰好访问每个节点一次 |

 这里：

-`N`是节点数
 -`H`是树的高度

 ## 算法演练

 ### 递归深度优先搜索

 1. 从根节点开始。 

根代表树的顶部。 如果根是`None`，树是空的，所以最大深度是`0`。 
2. 检查当前节点是否有子节点。 

如果一个节点没有子节点，则它是叶节点。 一片叶子贡献的深度为`1`因为路径只包含节点本身。 
3. 递归计算每个孩子的深度。 

对于每个子节点，再次调用相同的函数。 这将大问题分解为较小的子问题。 
4. 跟踪最大子深度。 

在所有子树中，我们只关心最深的一棵，因为问题要求最长的根到叶路径。 
5. 添加`1`对于当前节点。 

一旦知道最深的子深度，就将当前节点本身包含在路径长度中。 
6. 将计算出的深度向上返回。 

每个递归调用都会将其子树的最大深度返回给其父级。 

### 为什么它有效

 该算法之所以有效，是因为每个子树在其父节点计算自己的深度之前都已正确求解。 这是一个经典的递归树属性。 

对于每个节点：```
depth(node) = 1 + max(depth(child))
```由于叶节点正确返回`1`，并且每个父级都建立在正确的子级答案的基础上，递归保证根最终接收到整个树的正确最大深度。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, val: Optional[int] = None, children: Optional[List['Node']] = None):
        self.val = val
        self.children = children
"""

from typing import List, Optional

class Solution:
    def maxDepth(self, root: 'Node') -> int:
        if root is None:
            return 0

        if not root.children:
            return 1

        max_child_depth = 0

        for child in root.children:
            child_depth = self.maxDepth(child)
            max_child_depth = max(max_child_depth, child_depth)

        return 1 + max_child_depth
```实现首先处理空树的情况。 如果`root`是`None`，没有节点，所以深度是`0`。 

接下来，代码检查当前节点是否有子节点。 如果不是，则该节点是叶节点，贡献深度为`1`。 

变量`max_child_depth`存储所有子树中发现的最大子树深度。 该循环迭代每个子级并递归计算其深度。 

对于每个孩子：```python
child_depth = self.maxDepth(child)
```这递归地解决了子子树的相同问题。 

使用以下方式跟踪最大值：```python
max(max_child_depth, child_depth)
```最后，算法返回：```python
1 + max_child_depth
```额外的`1`占当前节点本身。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Children []*Node
 * }
 */

func maxDepth(root *Node) int {
    if root == nil {
        return 0
    }

    if len(root.Children) == 0 {
        return 1
    }

    maxChildDepth := 0

    for _, child := range root.Children {
        childDepth := maxDepth(child)

        if childDepth > maxChildDepth {
            maxChildDepth = childDepth
        }
    }

    return 1 + maxChildDepth
}
```Go 实现遵循与 Python 版本相同的递归结构。 

主要区别在于 Go 如何处理缺失值和集合：

 - Go 使用`nil`而不是`None`- 子节点存储在切片中：`[]*Node`- 使用以下命令检查子切片的长度`len(root.Children)`Go 没有提供内置的`max()`函数用于整数，因此比较是使用手动编写的`if`陈述。 

由于最大深度最多为`1000`，整数溢出在 Go 中不是一个问题。

 ## 边缘情况

 ### 空树

 当出现空树时`root`是`None`或者`nil`。 这种情况很容易被忽视，因为递归通常假设至少存在一个节点。 

如果没有显式处理这种情况，实现可能会尝试访问`root.children`，导致运行时错误。 

该解决方案通过立即返回来安全地处理这个问题：```
if root is None:
    return 0
```这正确地表示空树有深度`0`。 

### 单节点树

 仅包含根节点的树是另一个重要的边缘情况。 由于根没有子节点，因此它也是叶节点。 

有错误的实现可能会错误地返回`0`如果它只计算边而不计算节点。 

解决方案正确返回`1`因为该路径只包含一个节点。 

### 高度不平衡的树

 一棵 n 叉树可以退化为一个链表，其中每个节点只有一个子节点。 

例子：```
1 -> 2 -> 3 -> 4 -> 5
```这强调了递归深度并确保算法正确遵循单个深层分支。 

该实现自然地处理了这一问题，因为每个递归调用只处理一个子节点，直到到达叶节点。 

### 具有空子列表的节点

 某些实现错误地假设每个节点都有子节点。 

在这个问题中，叶子节点可能有：```
children = []
```该解决方案安全地检查：```
if not root.children:
```这对于空列表可以正确工作并正确识别叶节点。
