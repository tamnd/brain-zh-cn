 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`m x n`二元矩阵，其中每个单元格包含`0`或者`1`。 对于矩阵中的每个单元格，我们必须计算到包含以下内容的最近单元格的距离：`0`。 

距离是使用仅具有四个方向的曼哈顿运动来测量的：上、下、左、右。 从一个单元移动到相邻单元的成本`1`。 

如果单元格已经包含`0`，那么它的答案自然是`0`因为最接近的零是单元格本身。 对于含有`1`，我们必须确定需要多少次移动才能达到最接近的零。 

例如，考虑这个矩阵：```
0 0 0
0 1 0
0 0 0
```中心单元包含`1`，并且它与零相邻，所以它的距离是`1`。 

约束条件很重要：

 -`1 <= m * n <= 10^4`- 每个单元格要么`0`或者`1`- 至少有一个`0`细胞总数最多为`10^4`，这意味着我们应该瞄准接近线性时间的算法，`O(m * n)`。 对每个单元进行低效的重复搜索可能会变得太慢。 

一些重要的边缘情况立即脱颖而出：

 - 仅包含零的矩阵，每个答案都应保持为零。 
- 一个矩阵，其中许多值都远离最近的零。 
- 单行或单列矩阵。 
- 大型连接区域，天真的重复搜索会多次重新访问相同的单元格。 
- 该问题保证至少存在一个零，因此每个单元格总是有一个有效的答案。 

## 方法

 ### 蛮力方法

 最直接的想法是独立处理每个细胞。 

对于每个包含`1`，我们可以向外运行广度优先搜索，直到遇到`0`。 由于 BFS 逐层探索，找到的第一个零给出了最短距离。 

这是正确的，因为 BFS 保证了未加权网格中的最短路径。 

然而，这种方法效率非常低，因为我们对许多单元重复几乎相同的搜索。 如果矩阵大部分包含 1，则每个 BFS 可能会一次又一次地探索矩阵的很大一部分。 

假设有`m * n`单元格，每个 BFS 最多可以访问`m * n`细胞。 总复杂度变为：```
O((m * n)^2)
```这对于约束限制来说太慢了。 

### 最优方法，多源 BFS

 关键的见解是，不要从每个`1`，我们可以扭转视角。 

我们已经知道每个零单元格的距离：```
distance = 0
```因此，我们可以同时从所有零单元开始并向外扩展，而不是从 1 向 0 搜索。 

这称为多源 BFS。 

BFS 边界同时从零开始逐级扩展。 第一次`1`到达单元格必须通过尽可能最短的路径到达零。 

这是可行的，因为 BFS 按距离递增的顺序进行探索。 

该算法变得非常高效，因为每个单元最多被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((m * n)^2) | O((m * n)^2) | O(m * n) | 分别从每个单元运行 BFS |
 | 最佳| O(m * n) | O(m * n) | 从零开始的多源BFS |

 ## 算法演练

 1. 创建一个结果矩阵来存储距离。 

我们用大值（例如无穷大）初始化所有单元格，包含以下内容的单元格除外：`0`。 
2. 将所有零单元推入队列。 

每个零单元格都成为 BFS 起点，因为它们的距离已知为`0`。 
3. 开始 BFS 处理。 

当队列不为空时：

 - 拆下前面的电池。 
- 检查其四个相邻单元格。 
- 如果通过当前单元访问邻居产生较小的距离，则更新它并将该邻居推入队列。 
4、逐级拓展。 

BFS 自然地按照距离递增的顺序处理单元。 这保证了当我们第一次为单元分配距离时，它是到零的最短可能距离。 
5. 继续，直到队列为空。 

一旦 BFS 完成，每个单元格都包含到最接近的零的最小距离。 

### 为什么它有效

 BFS 在未加权图中按照最短路径长度的顺序探索节点。 该矩阵可以被视为一个图，其中每个单元与其四个邻居相连。 

由于所有零单元最初都以距离插入到队列中`0`，BFS波从每个零点同时向外扩展。 因此，第一次到达单元格必须对应于从任意零开始的最短可能路径。 

由于每次更新仅在找到较短距离时发生，因此最终矩阵包含正确的最小距离。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def updateMatrix(self, mat: List[List[int]]) -> List[List[int]]:
        rows = len(mat)
        cols = len(mat[0])

        distances = [[float("inf")] * cols for _ in range(rows)]
        queue = deque()

        # Initialize all zero cells
        for r in range(rows):
            for c in range(cols):
                if mat[r][c] == 0:
                    distances[r][c] = 0
                    queue.append((r, c))

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        # Multi-source BFS
        while queue:
            row, col = queue.popleft()

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    0 <= new_row < rows
                    and 0 <= new_col < cols
                    and distances[new_row][new_col] > distances[row][col] + 1
                ):
                    distances[new_row][new_col] = distances[row][col] + 1
                    queue.append((new_row, new_col))

        return distances
```实现首先创建一个初始化为无穷大的距离矩阵。 这代表尚未发现最短距离的细胞。 

接下来，将每个零单元插入 BFS 队列并分配距离`0`。 这些单元格充当同时 BFS 起点。 

这`directions`array 通过对四种可能的运动进行编码来简化邻居遍历。 

BFS 循环反复从队列中删除单元并检查其邻居。 如果可以用比之前记录的更短的距离到达邻居，则更新距离并将邻居添加到队列中。 

由于 BFS 按距离递增的顺序处理单元格，因此每次更新都会从最近的零向外传播正确的最短距离。 

最后，返回完整的距离矩阵。 

## 解决方案```go
func updateMatrix(mat [][]int) [][]int {
	rows := len(mat)
	cols := len(mat[0])

	distances := make([][]int, rows)

	for r := 0; r < rows; r++ {
		distances[r] = make([]int, cols)

		for c := 0; c < cols; c++ {
			distances[r][c] = 1 << 30
		}
	}

	type Cell struct {
		row int
		col int
	}

	queue := []Cell{}

	// Initialize all zero cells
	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			if mat[r][c] == 0 {
				distances[r][c] = 0
				queue = append(queue, Cell{r, c})
			}
		}
	}

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	front := 0

	// Multi-source BFS
	for front < len(queue) {
		current := queue[front]
		front++

		for _, dir := range directions {
			newRow := current.row + dir[0]
			newCol := current.col + dir[1]

			if newRow >= 0 &&
				newRow < rows &&
				newCol >= 0 &&
				newCol < cols &&
				distances[newRow][newCol] > distances[current.row][current.col]+1 {

				distances[newRow][newCol] =
					distances[current.row][current.col] + 1

				queue = append(queue, Cell{newRow, newCol})
			}
		}
	}

	return distances
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但有一些特定于语言的细节值得注意。 

Go没有提供内置的双端队列结构，因此队列是使用切片和a来实现的`front`指数。 这避免了昂贵的切片移位操作。 

该解决方案不是使用无穷大，而是使用非常大的整数值来初始化距离`1 << 30`。 

一个小`Cell`struct 提高了在队列中存储行和列坐标时的可读性。

 ## 边缘情况

 一种重要的边缘情况是仅包含零的矩阵。 有缺陷的实现可能仍会尝试不必要的 BFS 更新或意外覆盖有效距离。 在这个解决方案中，每个零都用距离初始化`0`，并且没有邻居更新可以改善这些值，因此矩阵保持不变。 

另一个重要的情况是单行或单列矩阵。 一些实现错误地假设两个维度都大于一，导致邻居遍历期间出现索引错误。 该解决方案在访问邻居之前仔细检查边界，因此窄矩阵可以正常工作。 

第三个临界边缘情况是存在多个零并且可以从不同方向到达单元格时。 幼稚的 DFS 方法可能会首先错误地记录较长的路径，并且以后不再对其进行改进。 多源 BFS 避免了这个问题，因为单元格是按照距离递增的顺序进行探索的，保证了发现的第一个有效距离是最佳的。 

当一个大的连通区域远离任何零时，最后一个微妙的情况就会发生。 重复的独立搜索将变得极其低效。 多源 BFS 解决方案可以有效地处理此问题，因为无论有多少路径可以到达每个单元，每个单元都只处理一次。
