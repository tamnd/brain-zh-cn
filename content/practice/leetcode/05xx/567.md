[LeetCode 567 题](https://leetcode.com/problems/permutation-in-string/)

 **难度：** 🟡 中等
 **主题：** 哈希表、两个指针、字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定是否有任何排列`s1`显示为内部的连续子字符串`s2`。 

排列意味着字符被重新排列，但每个字符的频率保持不变。 例如，排列`"ab"`是`"ab"`和`"ba"`。 如果其中任何一个出现在内部某处`s2`，那么答案就是`true`。 

重要的细节是子字符串`s2`必须是连续的。 我们并不是在寻找可以跳过字符的子序列。 

输入由两个小写英文字符串组成：

 -`s1`，我们想要找到其排列的模式
 -`s2`，我们搜索的较大字符串

 预期输出是：

 -`true`如果某个子串`s2`具有完全相同的字符频率`s1`-`false`否则

 约束条件很重要：

 - 两个字符串的长度可达`10^4`- 仅使用小写英文字母

 生成所有排列的强力解决方案`s1`对于较大的输入是不可能的，因为排列的数量呈阶乘增长。 即使低效地检查每个子字符串也可能变得太慢。 

小写英文字母约束非常有用，因为它意味着只有 26 个可能的字符。 这允许我们使用固定大小的频率数组而不是昂贵的动态哈希图。 

一些边缘情况很重要：

 - 如果`s1`长于`s2`，答案必须立即是`false`- 例如，重复的字符很重要`"aab"`不同于`"ab"`- 有效的排列可以出现在任意位置`s2`- 匹配子串的长度必须与`s1`## 方法

 ### 蛮力方法

 一个简单的方法是检查每个子串`s2`其长度等于`len(s1)`。 

对于每个子字符串，我们可以计算字符频率并将其与`s1`。 如果计数匹配，则子串是以下排列`s1`。 

例如：

-`s1 = "ab"`-`s2 = "eidbaooo"`我们将检查：

 -`"ei"`-`"id"`-`"db"`-`"ba"`-`"ao"`-`"oo"`-`"oo"`当我们到达`"ba"`，其字符频率匹配`"ab"`，所以我们返回`true`。 

这种方法是正确的，因为每个可能的候选子串都会被检查。 然而，重新计算每个子串的频率是低效的。 

如果：

-`n = len(s2)`-`m = len(s1)`然后对于每个大约`n - m + 1`子串，我们花费`O(m)`计算字符的时间。 这导致`O(n * m)`时间复杂度。 

字符串可达`10^4`，这可能会变得昂贵。 

### 最优方法，滑动窗口

 关键的观察是所有候选子串具有相同的长度，即`len(s1)`。 

我们可以维护一个大小的滑动窗口，而不是从头开始重新计算每个子字符串的字符频率`len(s1)`超过`s2`。 

当窗口移动时：

 - 一名角色进入窗口
 - 一名角色离开窗口

 我们增量更新频率计数，而不是每次都重建它们。 

由于只涉及小写英文字母，因此我们可以将频率存储在大小为 26 的数组中。比较两个频率数组需要恒定的时间，因为大小是固定的。 

这将解决方案转变为高效的滑动窗口算法。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 重新计算每个子串的频率 |
 | 最佳 | O(n) | O(1) | O(1) | 使用具有固定大小频率数组的滑动窗口 |

 ## 算法演练

 1.首先检查是否`s1`长于`s2`。 

如果是，那么里面不可能有任何排列`s2`，所以我们立即返回`false`。 
2. 创建两个大小为 26 的频率数组。 

一个数组存储字符数`s1`，其他商店计入当前滑动窗口`s2`。 

由于所有字符都是小写英文字母，因此每个索引对应一个字符：

 - 索引`0`代表`'a'`- 指数`1`代表`'b'`- 等等
 3. 填充第一个窗口的两个频率数组。 

计数：

 - 中的所有字符`s1`- 第一个`len(s1)`中的字符`s2`4. 比较两个频率阵列。 

如果它们相等，则第一个窗口本身就是一个有效的排列，因此返回`true`。 
5. 开始滑动窗户`s2`。 

对于每个步骤：

 - 添加进入窗口的新角色
 - 删除离开窗口的旧角色

 这使窗口大小保持固定。 
6. 更新窗口频率后，再次比较两个数组。 

如果它们匹配，则当前窗口包含以下排列`s1`。 
7. 如果处理整个字符串没有找到匹配项，则返回`false`。 

### 为什么它有效

 该算法保持了滑动窗口始终表示的子串的不变量`s2`与完全相同的长度`s1`。 

子串是一个排列`s1`当且仅当两个字符串包含相同的字符频率时。 

由于每当窗口移动时窗口频率都会正确更新，因此每个候选子串都会被检查一次。 因此，该算法可以正确识别是否存在排列。 

## Python 解决方案```python
class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        if len(s1) > len(s2):
            return False

        target_count = [0] * 26
        window_count = [0] * 26

        window_size = len(s1)

        for i in range(window_size):
            target_count[ord(s1[i]) - ord('a')] += 1
            window_count[ord(s2[i]) - ord('a')] += 1

        if target_count == window_count:
            return True

        for right in range(window_size, len(s2)):
            add_index = ord(s2[right]) - ord('a')
            remove_index = ord(s2[right - window_size]) - ord('a')

            window_count[add_index] += 1
            window_count[remove_index] -= 1

            if target_count == window_count:
                return True

        return False
```实施从早期拒绝检查开始。 如果`s1`长于`s2`，不能存在有效的子字符串。 

然后创建两个长度为 26 的数组。 这些数组存储以下字符的频率：

 -`s1`- 当前的滑动窗口`s2`第一个循环使用第一个窗口初始化两个数组`s2`。 

初始化后，算法会比较数组。 如果它们已经匹配，则立即得到答案`true`。 

然后主滑动窗口循环从索引开始`window_size`并移动通过`s2`。 

对于每次迭代：

 - 一个字符被添加到窗口中
 - 从左侧删除一个字符

 这可以保持窗口大小恒定，同时有效地更新频率。 

最后，每次更新后，算法都会检查频率数组是否匹配。 如果是，则当前窗口是有效排列。 

如果处理完所有窗口后未找到匹配项，则该方法返回`false`。 

## 解决方案```go
func checkInclusion(s1 string, s2 string) bool {
    if len(s1) > len(s2) {
        return false
    }

    targetCount := make([]int, 26)
    windowCount := make([]int, 26)

    windowSize := len(s1)

    for i := 0; i < windowSize; i++ {
        targetCount[s1[i]-'a']++
        windowCount[s2[i]-'a']++
    }

    if equalCounts(targetCount, windowCount) {
        return true
    }

    for right := windowSize; right < len(s2); right++ {
        windowCount[s2[right]-'a']++
        windowCount[s2[right-windowSize]-'a']--

        if equalCounts(targetCount, windowCount) {
            return true
        }
    }

    return false
}

func equalCounts(a []int, b []int) bool {
    for i := 0; i < 26; i++ {
        if a[i] != b[i] {
            return false
        }
    }

    return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是，Go 不支持以与 Python 比较列表相同的便捷方式对切片进行直接数组相等性检查。 因此，需要一个辅助函数`equalCounts`用于逐个元素比较两个频率数组。 

字符索引也略有不同。 在 Go 中，字符作为字节进行访问，因此表达式如下`s1[i] - 'a'`直接产生指数`0`到`25`。 

不需要对整数溢出进行特殊处理，因为最大频率计数受字符串长度限制，最多为`10^4`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`s1`长于`s2`。 在这种情况下，没有子串`s2`可能有相同的长度`s1`，所以答案一定是`false`。 幼稚的实现可能仍然尝试滑动窗口操作并产生不正确的索引行为。 该实现会立即处理此问题并提前返回。 

另一个重要的边缘情况涉及重复的字符。 例如，`s1 = "aab"`正好需要两个`'a'`人物和一个`'b'`。 仅检查字符存在而不检查确切频率的错误实现会错误地接受子字符串，例如`"abc"`。 频率数组方法可以正确跟踪每个字符的精确计数。 

当有效排列出现在最开始或最后的时候，就会出现第三种边缘情况。`s2`。 某些实现错误地初始化第一个窗口或过早停止滑动过程。 该解决方案在滑动之前显式检查初始窗口并继续处理，直到检查最终可能的窗口。 

另一个微妙的情况是所有字符都相同，例如`s1 = "aa"`和`s2 = "aaa"`。 该算法仍然可以正常工作，因为频率数组准确地捕获重复计数，并且滑动窗口更新在字符进入和离开窗口时保持正确的计数。
