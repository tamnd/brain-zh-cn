[LeetCode 552 题](https://leetcode.com/problems/student-attendance-record-ii/)

 **难度：** 🔴难
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 问题要求我们统计有多少条长度的考勤记录`n`满足两项奖励资格规则。 

每条考勤记录都是由三个可能的字符组成的字符串：

 -`'P'`表示该学生在场。 
-`'A'`意味着该学生缺席。 
-`'L'`意味着该学生迟到了。 

仅当满足以下条件时，记录才被视为有效：

 1. 总数`'A'`个字符严格小于 2 个，这意味着整个字符串中最多可以有 1 个字符缺失。 
2. 记录中不包含连续的三个`'L'`人物。 

我们给定一个整数`n`，代表天数，我们必须返回长度为有效考勤记录的条数`n`。 

由于答案可能变得非常大，我们返回结果模`10^9 + 7`。 

约束条件`1 <= n <= 10^5`非常重要。 暴力方法会考虑所有可能的长度字符串`n`。 由于每个位置都有三个选择，因此有`3^n`总的可能性。 即使对于中等值`n`，这变得不可能大。 因此，我们需要一种动态编程解决方案，可以增量构建答案，同时避免重新计算。 

重要的边缘情况包括非常小的值，例如`n = 1`，其中每个单字符字符串都是有效的，并且必须仔细排除重复的晚序列或多次缺失的较大值。 另一个棘手的场景是正确处理会创建的转换`"LLL"`或第二个`'A'`。 

## 方法

 ### 蛮力

 一种简单的方法是生成每个可能的长度的出勤字符串`n`并检查其是否满足规则。 

对于每个职位，我们可以选择：

 -`'P'`-`'A'`-`'L'`这会产生`3^n`总字符串。 对于每个生成的字符串，我们计算缺席的次数并检查是否`"LLL"`出现在任何地方。 

这种方法是正确的，因为它明确地检查了每条可能的考勤记录并过滤掉无效的考勤记录。 然而，对于限制而言，它太慢了。 什么时候`n = 100000`，即使存储所有可能性也是不可能的。 

### 关键见解

 重要的观察是，部分出勤记录的有效性仅取决于少量信息：

 - 到目前为止，已经使用了多少缺席次数`0`或者`1`- 当前存在多少个连续迟到的天数`0`,`1`， 或者`2`我们不需要完整的字符串历史记录。 

这自然会导致动态规划。 

我们基于以下条件定义 DP 状态：

 - 当前处理长度
 - 使用的缺勤次数
 - 当前连续迟到

 在每一步中，我们都尝试附加：

 -`'P'`，重置后期连胜
 -`'A'`，仅当尚未使用缺勤时
 -`'L'`，仅当当前的后期连胜小于 2 时

 因为只有`2 * 3 = 6`每个位置都有有意义的状态，解决方案变得非常有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(3^n * n) | O(3^n * n) | O(n) | 生成所有可能的字符串并验证它 |
 | 最优动态规划| O(n) | O(1) | O(1) | 仅跟踪缺勤次数和迟到次数 |

 ## 算法演练

 ### 动态规划状态

 我们定义：`dp[a][l]`在哪里：

-`a`是迄今为止使用的缺勤次数，或者`0`或者`1`-`l`是当前连续迟到的情况，`0`,`1`， 或者`2`存储的值是当前处于该状态的有效序列的数量。 

### 分步过程

 1. 初始化DP表。 

一开始，在处理任何字符之前，我们只有一个空序列：

 -`0`缺勤
 -`0`连续迟到几天

 所以：```
dp[0][0] = 1
```2. 一天一天地处理。 

对于每个现有状态，我们尝试附加一个附加字符。 
3. 追加`'P'`。 

追加`'P'`始终有效。 

它不会增加缺勤次数，并将迟到的连续缺勤重置为`0`。 

过渡：```
next_dp[a][0] += dp[a][l]
```4. 追加`'A'`。 

我们只能追加`'A'`如果我们还没有使用缺席。 

这将缺勤计数增加到`1`并重置后期连胜。 

过渡：```
next_dp[1][0] += dp[0][l]
```5. 追加`'L'`。 

我们只能追加`'L'`如果当前的后期连续少于`2`。 

这将后期连胜增加一分。 

过渡：```
next_dp[a][l + 1] += dp[a][l]
```6. 用新计算的 DP 表替换旧的 DP 表。 

处理完当天的所有状态后，新表将成为当前状态。 
7. 重复直到所有`n`位置已处理。 
8. 对所有有效状态求和。 

每个剩余的状态都代表一个有效的出勤序列，因此我们将它们全部加在一起。 

### 为什么它有效

 DP 状态准确捕获确定未来添加是否仍然有效所需的信息。 奖励规则仅取决于：

 - 到目前为止缺勤总数
 - 当前连续迟到

 其他历史信息都不重要。 由于每个有效序列都会正确转换到未来的有效状态，并且排除每个无效转换，因此 DP 将所有有效出勤记录恰好枚举一次。 

## Python 解决方案```python
class Solution:
    def checkRecord(self, n: int) -> int:
        MOD = 10**9 + 7

        # dp[absences][late_streak]
        dp = [[0] * 3 for _ in range(2)]
        dp[0][0] = 1

        for _ in range(n):
            next_dp = [[0] * 3 for _ in range(2)]

            for absences in range(2):
                for late_streak in range(3):
                    current = dp[absences][late_streak]

                    if current == 0:
                        continue

                    # Add 'P'
                    next_dp[absences][0] = (
                        next_dp[absences][0] + current
                    ) % MOD

                    # Add 'A'
                    if absences == 0:
                        next_dp[1][0] = (
                            next_dp[1][0] + current
                        ) % MOD

                    # Add 'L'
                    if late_streak < 2:
                        next_dp[absences][late_streak + 1] = (
                            next_dp[absences][late_streak + 1] + current
                        ) % MOD

            dp = next_dp

        result = 0

        for absences in range(2):
            for late_streak in range(3):
                result = (result + dp[absences][late_streak]) % MOD

        return result
```实施首先创建一个`2 x 3`DP 表。 第一个维度表示已使用的缺席次数，第二个维度跟踪当前连续迟到的情况。 

初始状态对应于空序列。 

我们每天都会创建一个新的 DP 表，名为`next_dp`。 这可以防止更新干扰当前迭代中仍需要处理的状态。 

对于每个有效状态，我们尝试三种转换：

 - 追加`'P'`- 追加`'A'`- 追加`'L'`每次转换都会更新适当的未来状态，同时应用模运算以避免整数溢出。 

在每次迭代结束时，`dp`变成`next_dp`。 

最后，我们对所有状态求和，因为每个剩余状态都对应于有效的出勤记录。 

## 解决方案```go
func checkRecord(n int) int {
	const MOD int = 1000000007

	dp := [2][3]int{}
	dp[0][0] = 1

	for i := 0; i < n; i++ {
		nextDP := [2][3]int{}

		for absences := 0; absences < 2; absences++ {
			for lateStreak := 0; lateStreak < 3; lateStreak++ {
				current := dp[absences][lateStreak]

				if current == 0 {
					continue
				}

				// Add 'P'
				nextDP[absences][0] =
					(nextDP[absences][0] + current) % MOD

				// Add 'A'
				if absences == 0 {
					nextDP[1][0] =
						(nextDP[1][0] + current) % MOD
				}

				// Add 'L'
				if lateStreak < 2 {
					nextDP[absences][lateStreak+1] =
						(nextDP[absences][lateStreak+1] + current) % MOD
				}
			}
		}

		dp = nextDP
	}

	result := 0

	for absences := 0; absences < 2; absences++ {
		for lateStreak := 0; lateStreak < 3; lateStreak++ {
			result = (result + dp[absences][lateStreak]) % MOD
		}
	}

	return result
}
```Go 实现密切反映了 Python 逻辑。 它使用固定大小的数组而不是嵌套列表，因为 DP 维度在编译时已知。 

每次更新后都会执行模运算以防止溢出。 Go 整数就足够了，因为中间值总是按模减少`10^9 + 7`。 

与 Python 不同，Go 不方便地支持动态调整大小，因此固定数组使实现更干净、更高效。

 ## 边缘情况

 一个重要的边缘情况是`n = 1`。 只有一天，每个单字符串都是有效的，因为任何字符串都不能包含两次缺勤或连续三天迟到。 有缺陷的实现可能会意外地错误处理初始化或转换并返回错误的计数。 DP 初始化为`dp[0][0] = 1`正确处理本案。 

另一个重要的边缘情况涉及会创建连续三天迟到的序列。 例如，当当前的后期连胜已经是`2`，添加另一个`'L'`必须禁止。 实施明确检查`late_streak < 2`在允许转换之前，防止无效序列，例如`"LLL"`。 

第三个棘手的边缘情况是处理第二次缺席。 一旦序列已经包含一个`'A'`，添加另一个缺席将违反规则。 该实现仅允许`'A'`转变时`absences == 0`，确保没有一个状态包含一次以上的缺席。 

最后一个考虑因素是非常大的值`n`， 尤其`n = 100000`。 没有记忆的递归解决方案会溢出调用堆栈或超时。 迭代 DP 方法完全避免了递归，并且仅使用常量内存，使其对于最大输入而言安全且高效。
