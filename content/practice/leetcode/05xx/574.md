 # LeetCode 574 - 获胜候选人

 ## 问题理解

 本题提供了两个数据库表，`Candidate`和`Vote`，并要求我们确定哪位候选人赢得了选举。 

这`Candidate`表存储有关每个候选人的信息。 每个候选人都有一个唯一的整数`id`以及相应的`name`。 

这`Vote`表存储投票结果。 每行代表一次投票，并且`candidateId`专栏告诉我们哪位候选人获得了该选票。 由于每一行恰好对应一票，因此候选人 ID 出现在列表中的次数`Vote`表等于该候选人获得的选票总数。 

目标是返回得票最多的候选人的名字。 

该问题保证只有一个赢家。 这种保证很重要，因为它消除了处理关系的需要。 我们永远不需要返回多个候选人或应用打破平局的规则。 

输入有效地表示：

 - 从候选人 ID 到候选人姓名的映射
 - 参考候选人 ID 的选票集合

 预期输出是包含获胜者姓名的单行表。 

幼稚的实现可能会难以单独重复计算每个候选人的选票，尤其是在票数很大的情况下。 然而，SQL聚合函数是专门为这种计数操作而设计的。 

重要的边缘情况包括：

 - 获得所有选票的候选人
 - 获得零票的候选人
 - 仅存在一名候选人
 - 选票分布极不均匀

 获胜者的唯一性保证简化了查询，因为我们可以安全地使用`LIMIT 1`按票数排序后。 

## 方法

 ### 蛮力方法

 暴力解决方案将逐一检查每个候选对象并计算候选对象中有多少行。`Vote`表引用该候选人。 

从概念上讲，该过程如下所示：

 1. 迭代每个候选者
 2. 对于每个候选人，扫描整个`Vote`表
 3. 统计匹配票数
 4. 跟踪计数最多的候选者

 这种方法是正确的，因为它明确计算了每个候选人的总票数。 然而，它的效率很低，因为`Vote`表被重复扫描。 

如果有`C`候选人和`V`投票，总工作量变为`O(C × V)`。 

### 最佳方法

 关键的观察结果是 SQL 数据库提供了聚合操作，可以有效地对分组记录进行计数。 

我们可以：

 1. 分组投票`candidateId`2. 统计各组的票数
 3. 按投票数降序对组进行排序
 4. 选择最佳候选人
 5. 加入`Candidate`用于检索候选人姓名的表

 这种方法利用 SQL 的优化分组和排序机制，避免重复扫描`Vote`桌子。

 ## 算法演练

 ### 最优 SQL 算法

 1. 从`Vote`表，因为它包含所有投票信息。 
2. 将行分组依据`candidateId`。 这将为每位收到选票的候选人创建一个组。 
3. 使用`COUNT(*)`聚合函数来计算每个候选人有多少票。 
4. 按得票数降序对分组结果进行排序`ORDER BY COUNT(*) DESC`。 
5. 由于该问题保证只有一个获胜者，因此仅选择第一行`LIMIT 1`。 
6. 加入胜利者行列`candidateId`与`Candidate`表来检索候选人的姓名，而不是仅返回数字 ID。 
7. 返回生成的候选人姓名。 

### 为什么它有效

 分组依据`candidateId`确保同一候选人的所有选票都收集在一起。 计算每组中的行即可得出该候选人收到的确切票数。 按降序排序可确保总票数最高的候选人首先出现。 由于该问题保证了唯一的获胜者，因此选择第一个结果始终会返回正确的候选者。 

## Python 解决方案

 尽管这是一个数据库问题并且 LeetCode 需要 SQL 查询，但以下 Python 示例以编程方式演示了相同的逻辑。```python
from collections import Counter
from typing import List, Dict

class Solution:
    def winningCandidate(
        self,
        candidates: List[Dict[str, object]],
        votes: List[Dict[str, int]]
    ) -> str:
        vote_counts = Counter()

        for vote in votes:
            candidate_id = vote["candidateId"]
            vote_counts[candidate_id] += 1

        winning_candidate_id = max(
            vote_counts,
            key=vote_counts.get
        )

        candidate_map = {
            candidate["id"]: candidate["name"]
            for candidate in candidates
        }

        return candidate_map[winning_candidate_id]
```实施首先使用`Counter`目的。 每次投票都会增加相应的计数`candidateId`。 

所有投票处理完毕后，`max`函数识别得票数最多的候选人 ID。 

然后建立一个字典来将候选 ID 映射到候选名称。 这模拟了SQL之间的连接操作`Vote`和`Candidate`表。 

最后，返回获胜候选人的姓名。 

## 解决方案```go
package main

type Candidate struct {
	Id   int
	Name string
}

type Vote struct {
	Id          int
	CandidateId int
}

func winningCandidate(
	candidates []Candidate,
	votes []Vote,
) string {

	voteCounts := make(map[int]int)

	for _, vote := range votes {
		voteCounts[vote.CandidateId]++
	}

	winningCandidateId := -1
	maxVotes := -1

	for candidateId, count := range voteCounts {
		if count > maxVotes {
			maxVotes = count
			winningCandidateId = candidateId
		}
	}

	candidateMap := make(map[int]string)

	for _, candidate := range candidates {
		candidateMap[candidate.Id] = candidate.Name
	}

	return candidateMap[winningCandidateId]
}
```Go 实现遵循与 Python 解决方案相同的逻辑结构。 使用地图代替Python`Counter`存储投票频率。 

Go 需要显式变量初始化，所以`winningCandidateId`和`maxVotes`都是手动初始化的。 

候选查找表是使用另一个从候选 ID 到候选名称的映射来实现的。 

与 Python 字典不同，Go 映射在键不存在时返回零值，但问题保证了有效的外键关系，因此每次投票总是引用有效的候选者。 

## SQL 解决方案```sql
SELECT c.name
FROM Candidate c
JOIN Vote v
    ON c.id = v.candidateId
GROUP BY c.id, c.name
ORDER BY COUNT(*) DESC
LIMIT 1;
```此查询将候选人与选票连接起来，按候选人对行进行分组，计算每个候选人的票数，按票数降序对候选人进行排序，并返回最高的结果。

 ## 边缘情况

 ### 零票候选人

 一些候选人可能存在于`Candidate`表但从未出现在`Vote`桌子。 有缺陷的实现可能会意外地将它们包含在错误的计数中或错误地处理丢失的条目。 该解决方案可以正确处理此问题，因为投票计数仅根据`Vote`桌子。 

### 仅存在一名候选人

 如果只有一名候选人，则每张选票都必然属于该候选人。 某些实现错误地假设存在多个候选者，并且在计算最大值时可能会失败。 当前的实现自然有效，因为默认情况下单个候选者成为最大值。 

### 非连续候选 ID

 不保证候选 ID 是连续的或有序的。 直接使用数组索引的解决方案可能会失败或浪费内存。 该实现使用散列映射来代替，因此可以正确处理稀疏或不规则的 ID。 

### 非常大的票数

 如果`Vote`表很大，重复扫描每个候选表会变得低效。 优化的解决方案通过仅处理一次投票并逐步聚合计数来避免此问题。
