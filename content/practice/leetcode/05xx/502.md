[LeetCode 502 题](https://leetcode.com/problems/ipo/)

 **难度：** 🔴难
 **主题：** 数组、贪婪、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题描述了这样一种情况：我们在 IPO 之前投资项目的机会有限。 每个项目都有两个属性：

 -`profits[i]`，完成项目后获得的资本金额
 -`capital[i]`, 启动项目所需的最低资金额

 我们还得到：

 -`k`，我们可以完成的最大项目数量
 -`w`，我们目前拥有的初始资本金额

 目标是最多选择`k`不同的项目，以便最终的资本数额尽可能大。 

一个非常重要的细节是，完成一个项目会立即增加我们的可用资本。 这意味着项目选择的顺序很重要。 最初无法启动的项目可能会在完成一个有利可图的早期项目后变得可用。 

输入尺寸很大：

 -`n`可以达到`100000`-`k`也可以达到`100000`这些限制立即排除了指数或二次方法。 任何重复扫描另一个循环内的所有项目的解决方案都可能会超时。 

该问题保证最终答案符合 32 位有符号整数，因此标准整数算术就足够了。 

一些边缘情况很重要：

 - 我们最初可能无法负担任何项目。 
- 某些项目可能利润为零。 
-`k`可能大于项目数量。 
- 多个项目可能需要相同的资金。 
- 多个项目可能有相同的利润。 
- 只顾眼前利益而不考虑承受能力的贪婪选择可能会失败。 

核心挑战是同时平衡两件事：

 - 目前哪些项目可以负担得起
 - 经济实惠的项目中，哪一个利润最大

 ## 方法

 ### 蛮力方法

 一个简单的解决方案将尝试最多的所有可能组合`k`项目并计算最大可实现资本。 

在每一步中，我们都会：

 1. 查看所有未使用的项目。 
2. 寻找资金需求小于或等于当前资金的项目。 
3. 递归地尝试下一个可能的项目。 
4. 跟踪最佳最终资本。 

这种方法是正确的，因为它探索了项目选择的每个有效序列。 然而，这在计算上是不可行的。 

在最坏的情况下，可能的项目序列的数量呈指数级增长。 即使进行修剪，搜索空间也会变得巨大`n = 100000`。 

另一种稍微改进的蛮力方法会重复扫描所有项目，以找到最实惠的项目。 那还是要花钱的`O(k * n)`，当两个值都很大时，速度太慢。 

### 关键见解

 在每一步中，我们只关心两件事：

 - 目前哪些项目可以负担得起
 - 在这些负担得起的项目中，哪个项目利润最大

 这自然意味着两个操作：

 1. 有效地添加随着资本增长而变得负担得起的项目
 2.高效检索利润最高的可承受项目

 为了有效地支持这些：

 - 按所需资金对项目进行排序
 - 使用最大堆来存储当前可负担项目的利润

 排序后的列表使我们能够按所需资本的升序处理项目。 随着我们的资本增加，我们将新的负担得起的项目移入堆中。 

堆确保我们始终选择最有利可图的可用项目`O(log n)`时间。 

排序和优先级队列的这种组合提供了有效的贪婪解决方案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) 或 O(k * n) | O(n) | 探索许多项目组合或重复扫描所有项目 |

 ## 算法演练

 1. 将每个项目的资本要求和利润合并为一对。 

这样可以轻松地对项目进行排序和一起处理。 每个项目变成：```
(required_capital, profit)
```2. 按所需资金升序对所有项目进行排序。 

这使我们能够有效地确定随着我们当前资本的增加哪些项目变得负担得起。 
3. 创建一个最大堆来存储可负担项目的利润。 

蟒蛇的`heapq`默认情况下是最小堆，因此我们存储负利润来模拟最大堆。 

堆代表了我们当前可以负担的所有项目。 
4. 维护已排序项目列表的指针。 

该指针跟踪哪些项目已添加到堆中。 
5、最多重复一次`k`次。 

每一次迭代都代表选择一个项目。 
6. 将所有新的可负担项目添加到堆中。 

当当前项目的资金需求小于或等于我们当前的资金时：

 - 将其利润推入堆中
 - 向前移动指针

 此步骤确保堆始终包含我们当前可以负担的每个项目。 
7. 如果堆是空的，尽早停止。 

空堆意味着没有剩下可负担得起的项目。 既然我们不能再增加资本，就不可能取得进一步的进展。 
8. 从堆中提取最赚钱的项目。 

这种贪婪的选择使当前步骤的资本增长最大化。 
9. 将选定的利润添加到当前资本中。 

完成项目会增加可用资本，有可能在未来的迭代中解锁更多项目。 
10.最多完成后`k`项目，返还最终资金。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 堆始终包含一组当前可负担但尚未选择的项目。 

在每一步中，选择最有利可图的可负担项目是最佳选择，因为额外的资本只会增加未来的机会。 更大的流动资金永远不会减少我们以后可能选择的项目集。 

因此，在每一步贪婪地最大化资本增长都会导致全局最优结果。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def findMaximizedCapital(
        self,
        k: int,
        w: int,
        profits: List[int],
        capital: List[int]
    ) -> int:
        
        projects = list(zip(capital, profits))
        projects.sort()
        
        max_heap = []
        project_index = 0
        n = len(projects)
        
        for _ in range(k):
            
            while (
                project_index < n and
                projects[project_index][0] <= w
            ):
                required_capital, profit = projects[project_index]
                
                heapq.heappush(max_heap, -profit)
                project_index += 1
            
            if not max_heap:
                break
            
            w += -heapq.heappop(max_heap)
        
        return w
```实施首先是根据所需资金对项目进行组合和排序。 这一预处理步骤确保我们能够随着资本的增长而有效地识别新的负担得起的项目。 

这`max_heap`存储当前所有可负担项目的利润。 自从Python的`heapq`仅支持最小堆，利润以负值插入。 

这`project_index`指针阻止我们重复扫描整个项目列表。 每个项目只处理一次，并且仅在可以承受时才插入堆中。 

在主循环内，我们首先将每个新的可负担项目推入堆中。 之后，如果堆为空，我们就知道没有可以执行的项目，因此我们提前终止。 

否则，我们会推出最赚钱的项目并将其利润添加到我们的资本中。 这增强了我们资助未来项目的能力。 

该过程最多重复`k`次。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

func findMaximizedCapital(
	k int,
	w int,
	profits []int,
	capital []int,
) int {

	n := len(profits)

	projects := make([][2]int, n)

	for i := 0; i < n; i++ {
		projects[i] = [2]int{capital[i], profits[i]}
	}

	sort.Slice(projects, func(i, j int) bool {
		return projects[i][0] < projects[j][0]
	})

	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	projectIndex := 0

	for i := 0; i < k; i++ {

		for projectIndex < n &&
			projects[projectIndex][0] <= w {

			heap.Push(maxHeap, projects[projectIndex][1])
			projectIndex++
		}

		if maxHeap.Len() == 0 {
			break
		}

		w += heap.Pop(maxHeap).(int)
	}

	return w
}
```Go 解决方案遵循与 Python 版本相同的算法结构。 主要区别在于 Go 需要显式实现`heap.Interface`。 

习俗`MaxHeap`反转比较`Less`方法，使标准库堆的行为类似于最大堆。 

Go 切片是动态的，因此堆插入和删除可以通过接口方法自然地进行。 

整数溢出不是问题，因为该问题保证答案适合 32 位有符号整数。

 ## 边缘情况

 当一开始没有项目可供负担时，就会出现一种重要的边缘情况。 例如，如果`w = 0`每个项目至少需要`1`资本，堆从未收到任何项目。 幼稚的实现可能会继续不必要的循环或尝试从空堆中弹出。 该解决方案显式检查堆是否为空并提前终止。 

另一个微妙的边缘情况涉及`k`大于项目数量。 由于该问题允许完成“最多”`k`项目，一旦没有项目剩余，算法必须自然停止。 堆空检查可以正确处理这个问题，而不需要特殊的逻辑。 

零利润的项目也可能很棘手。 天真的贪婪策略可能会错误地忽略它们或错误地处理堆排序。 此实施通常处理零利润项目。 如果它们解锁未来有利可图的项目，它们可能仍然有用，尽管在这个特定问题中，利润只会直接增加资本。 

进一步的边缘情况涉及只有在早期选择后项目才变得负担得起。 这是问题的核心挑战。 排序的项目列表和增量堆插入确保每个新的可负担项目在可用时得到准确考虑。
