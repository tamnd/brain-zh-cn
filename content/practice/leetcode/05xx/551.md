 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`其中每个字符代表学生一天的出勤记录。 只有三个可能的字符：

 -`'A'`意味着该学生缺席。 
-`'L'`意味着该学生迟到了。 
-`'P'`表示该学生在场。 

我们必须确定学生是否有资格获得全勤奖。 仅当满足以下两个条件时，学生才有资格：

 1. 缺勤总人数（`'A'`) 严格小于 2，这意味着最多可以有 1 次缺席。 
2. 学生从未连续迟到 3 天或以上（`'L'`）。 

输入是一个长度范围从 1 到 1000 的单个字符串。这个约束足够小，即使是简单的线性扫描也足够快。 由于我们只需要检查两个简单的条件，因此不需要任何高级的数据结构或算法。 

预期输出是一个布尔值：

 - 返回`true`如果出勤记录满足这两个条件。 
- 返回`false`否则。 

在实施之前考虑一些边缘情况很重要。 一名学生可能只有一次缺勤，这是允许的，但两次缺席应该立即导致检查失败。 另一个重要的案例是连续迟到。 连续两`'L'`字符是可以接受的，但是三个连续的`'L'`字符使记录无效。 无效序列也可能出现在字符串的开头、中间或结尾，因此算法必须在整个扫描过程中正确跟踪连续迟到。 

因为输入保证只包含`'A'`,`'L'`， 和`'P'`，我们不需要验证字符或处理格式错误的输入。 

## 方法

 ### 蛮力方法

 强力解决方案将明确计算缺席数并重复检查长度为 3 的每个可能的子字符串以查看其是否等于`"LLL"`。 

该算法的工作原理如下：

 1.遍历字符串一次，统计有多少个`'A'`字符出现。 
2. 再次遍历，检查每个长度为3的子串。 
3. 如果任意子串等于`"LLL"`， 返回`false`。 
4. 否则，如果缺席次数小于2，则返回`true`。 

这种方法是正确的，因为它直接检查问题陈述中定义的两条规则。 但是，它对字符串执行多次传递并重复创建子字符串，这是不必要的。 

尽管约束足够小，该解决方案仍然可以通过，但我们可以使用更干净的单通道解决方案做得更好。 

### 最佳方法

 关键的观察是，我们可以在从左到右扫描一次字符串时同时验证这两个条件。 

我们维持：

 - 总缺勤计数器。 
- 当前连续迟到天数的计数器。 

当我们处理每个字符时：

 - 如果我们看到`'A'`，增加缺席计数。 
- 如果我们看到`'L'`，增加连续迟到计数器。 
- 如果我们看到`'P'`或者`'A'`，重置后期连续，因为连续序列被破坏。 

在任何一点：

 - 如果缺席人数达到2，我们可以立即返回`false`。 
- 如果后期连胜达到3次，我们可以立即返回`false`。 

如果我们在不违反任何一个条件的情况下完成扫描，则记录有效。 

这可以有效地工作，因为每个字符都被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 多次扫描和重复的子字符串检查 |
 | 最佳 | O(n) | O(1) | O(1) | 单次通过同时跟踪缺勤和迟到|

 ## 算法演练

 1.初始化两个变量：

 -`absence_count = 0`-`late_streak = 0`第一个变量跟踪学生缺勤的次数。 第二个变量跟踪当前正在处理的连续迟到天数。 
2. 一次遍历字符串一个字符。 

每个字符代表一天的出勤情况。 
3. 如果当前字符是`'A'`：

 - 增量`absence_count`。 
- 重置`late_streak`至 0。 

我们重置了连续迟到的记录，因为缺席打破了连续几天的迟到序列。 
4. 如果当前字符是`'L'`：

 - 增量`late_streak`。 

由于该学生再次迟到，连续的迟到序列仍在继续。 
5. 如果当前字符是`'P'`：

- 重置`late_streak`至 0。 

出现在场将打破任何持续迟到的记录。 
6. 更新计数器后，检查故障情况：

 - 如果`absence_count >= 2`， 返回`False`。 
- 如果`late_streak >= 3`， 返回`False`。 

我们可以提前终止，因为记录已经无效。 
7. 如果循环完成而没有触发任何失败条件，则返回`True`。 

### 为什么它有效

 该算法在扫描期间保持两个不变量：

 -`absence_count`始终等于迄今为止缺席的总数。 
-`late_streak`始终等于连续尾随的数量`'L'`以当前位置结尾的字符。 

由于这些值在每个字符后都会正确更新，因此算法会立即检测到任何规则违规。 如果遍历结束没有发生违规，则考勤记录满足两个要求。 

## Python 解决方案```python
class Solution:
    def checkRecord(self, s: str) -> bool:
        absence_count = 0
        late_streak = 0

        for ch in s:
            if ch == 'A':
                absence_count += 1
                late_streak = 0
            elif ch == 'L':
                late_streak += 1
            else:
                late_streak = 0

            if absence_count >= 2:
                return False

            if late_streak >= 3:
                return False

        return True
```该实现紧密遵循前面描述的算法。 在循环开始之前初始化两个整数计数器。 

在循环内部，当前字符决定计数器如何变化：

 -`'A'`增加缺席次数并重置迟到的连胜。 
-`'L'`延续了目前的后期连胜。 
-`'P'`由于连续序列结束，因此重置迟到的连续序列。 

更新计数器后，代码立即检查是否违反了任一规则。 提前终止可以提高效率，因为一旦知道答案，算法就不会继续处理。 

如果循环成功完成，函数返回`True`，表示出勤记录满足这两个条件。 

## 解决方案```go
func checkRecord(s string) bool {
    absenceCount := 0
    lateStreak := 0

    for _, ch := range s {
        if ch == 'A' {
            absenceCount++
            lateStreak = 0
        } else if ch == 'L' {
            lateStreak++
        } else {
            lateStreak = 0
        }

        if absenceCount >= 2 {
            return false
        }

        if lateStreak >= 3 {
            return false
        }
    }

    return true
}
```Go 实现与 Python 版本几乎相同。 主要区别在于语法。 

Go 使用 a 迭代字符串`for range`循环，其中`ch`是一个符文。 由于输入仅包含 ASCII 字符，因此与`'A'`,`'L'`， 和`'P'`很简单。 

不需要对空字符串进行特殊处理，因为该问题保证字符串长度至少为 1。

 ## 边缘情况

 一个重要的边缘情况是只有一次缺席的记录，例如`"PPA"`。 由于该条件要求缺勤次数严格少于 2 次，因此 1 次缺勤仍然有效。 一个常见的错误是使用了错误的比较运算符并拒绝只有一个缺失的记录。 实施正确地检查`absence_count >= 2`。 

另一个重要的边缘情况是当晚条纹出现在字符串的最末端时，例如`"PPALLL"`。 某些实现错误地过早重置了条纹或未能检查最终序列。 该解决方案会在每个字符之后立即检查后期条纹，因此尾随`"LLL"`被正确检测到。 

第三种边缘情况是后期序列被打断，例如`"LLPLL"`。 虽然总共有四个`'L'`字符，它们不是连续的。 实施重置`late_streak`每当遇到`'P'`或者`'A'`，确保只计算连续迟到的天数。 

第四种微妙的边缘情况是两条规则几乎同时被违反，例如`"ALLL"`。 缺席计数仍然有效，因为只有一个`'A'`，但后期连胜达到了三场。 该算法独立跟踪这两个条件并正确返回`False`一旦后期连胜无效。
