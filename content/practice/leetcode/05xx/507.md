 **难度：** 🟢简单
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 这个问题要求我们判断给定的正整数是否`num`是一个**完美数**。 

完美数被定义为一个数，其**正除数之和（不包括该数本身**）等于该数。 换句话说，我们必须找到所有能整除的整数`num`均匀地排除`num`，将它们相加，并检查该和是否等于原始数字。 

例如，考虑`28`:

 -`1`划分`28`-`2`划分`28`-`4`划分`28`-`7`划分`28`-`14`划分`28`这些除数的总和是：`1 + 2 + 4 + 7 + 14 = 28`由于总和等于数字本身，`28`是一个完全数。 

输入由单个整数组成`num`，输出应该是：

 -`true`如果`num`是一个完全数
 -`false`否则

 约束条件告诉我们：

 -`1 <= num <= 10^8`这个上限很重要。 一个简单的解决方案，检查来自的每个数字`1`到`num - 1`最多需要`10^8`在最坏的情况下进行操作，效率很低。 我们需要更好的方法。 

一个重要的数学观察是除数成**成对**出现。 例如，对于`28`:

 -`2 × 14 = 28`-`4 × 7 = 28`如果我们找到一个除数，我们就会自动知道另一个除数。 这允许我们仅检查最多`√num`，这显着提高了性能。 

一些边缘情况值得关注：

 -`num = 1`不是一个完全数，因为它没有除自身之外的正因数，所以总和是`0`， 不是`1`。 
- 完美平方需要小心处理，以避免计算平方根两次。 
- 小的非完美数字，例如`2`或者`7`应该正确返回`false`。 

## 方法

 ### 蛮力方法

 最直接的方法是迭代每个整数`1`到`num - 1`，检查是否可除`num`，如果是的话，将其添加到运行总和中。 

这是有效的，因为它显式地计算所有真除数的总和。 如果最终总和等于`num`，那么这个数就完美了。 

然而，这种方法效率低下。 在最坏的情况下，我们几乎检查`10^8`考虑到问题的限制，这不必要地昂贵。 

### 最佳解决方案的关键见解

 关键的数学见解是除数以**互补对**的形式出现。 

如果`d`划分`num`， 然后`num / d`还必须分`num`。 

例如，与`28`:

 - 求除数`2`自动给出除数`14`- 求除数`4`自动给出除数`7`这意味着我们只需要搜索`√num`。 

我们初始化除数和`1`， 自从`1`对于大于的数字始终是真除数`1`。 那么对于每个除数`d`之间`2`和`√num`：

- 添加`d`- 添加`num // d`如果`d * d == num`，我们只添加除数一次，因为两个值相同。 

这将时间复杂度从 **O(n)** 降低到 **O(√n)**。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 检查每个数字`1`到`num - 1`|
 | 最佳| O(√n) | O(√n) | O(1) | O(1) | 使用除数配对来减少工作 |

 ## 算法演练

 1. **处理特殊情况`1`**

自从`1`没有真因数，不可能是完美数。 返回`false`立即地。 
2. **初始化除数和**

 开始于`divisor_sum = 1`因为`1`对于任何大于的数字始终是有效除数`1`。 
3. **迭代自`2`到`√num`**

 我们只需要检查除数到平方根，因为每个除数都大于`√num`有一个匹配的较小除数。 
4. **检查整除性**

 对于每个候选除数`d`，检查是否`num % d == 0`。 如果属实的话，`d`是一个除数。 
5. **将该对中的两个除数相加**

 添加`d`到总和。 然后计算配对除数：```
paired_divisor = num // d
```如果`d`和`paired_divisor`不同，则将两者相加。 
6. **避免重复计算完美平方**

 当`d * d == num`，除数对实际上是相同的数字。 仅添加一次。 
7. **将总和与原始数字进行比较**

 处理完所有除数后，返回是否`divisor_sum == num`。 

### 为什么它有效

 该算法之所以有效，是因为数字的每个除数都出现在周围的唯一对中`√num`。 通过仅迭代到平方根并将两个除数加在一起，我们将每个真除数恰好计算一次。 对完全平方数的特殊处理可确保除数不会被计算两次。 因此，计算出的和正是所有真因数的和，这保证了正确性。 

## Python 解决方案```python
class Solution:
    def checkPerfectNumber(self, num: int) -> bool:
        if num == 1:
            return False

        divisor_sum = 1
        divisor = 2

        while divisor * divisor <= num:
            if num % divisor == 0:
                divisor_sum += divisor

                paired_divisor = num // divisor
                if paired_divisor != divisor:
                    divisor_sum += paired_divisor

            divisor += 1

        return divisor_sum == num
```实现首先处理特殊情况，其中`num == 1`， 自从`1`不可能是完美的。 

我们初始化`divisor_sum`到`1`因为每个大于的整数`1`有`1`作为真除数。 然后我们从以下位置开始迭代可能的除数`2`。 

循环条件：```python
divisor * divisor <= num
```确保我们只搜索`√num`。 

每当我们找到一个除数时，我们都会将其添加到运行总计中，并使用整数除法计算其配对除数。 如果配对除数与当前除数不同，我们也会将其相加。 这可以防止在以下情况下重复计算`num`是一个完美的正方形。 

最后，该函数将累积除数和与`num`并返回结果。 

## 解决方案```go
func checkPerfectNumber(num int) bool {
    if num == 1 {
        return false
    }

    divisorSum := 1

    for divisor := 2; divisor*divisor <= num; divisor++ {
        if num%divisor == 0 {
            divisorSum += divisor

            pairedDivisor := num / divisor
            if pairedDivisor != divisor {
                divisorSum += pairedDivisor
            }
        }
    }

    return divisorSum == num
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

由于 Go 使用显式变量声明，我们定义`divisorSum`作为整数并使用标准`for`循环迭代。 整数除法自然地使用`/`因为两个操作数都是整数。 

整数溢出在这里不是一个问题，因为`num ≤ 10^8`，除数和仍然在 Go 的范围内`int`范围。

 ## 边缘情况

 ### 输入`1`数量`1`是错误的常见来源，因为许多实现使用以下方式初始化除数和`1`。 如果我们不小心，算法可能会错误地分类`1`一样完美。 

我们的实现通过立即返回来明确处理这个问题`false`什么时候`num == 1`。 

### 完全平方数

 数字如`16`或者`25`需要仔细处理，因为平方根除数只出现一次。 

例如：```
16 = 4 × 4
```如果我们盲目地将每对中的两个除数相加，我们就会计算`4`两次。 该实现通过以下方式防止这种情况发生：```
if paired_divisor != divisor:
```这样就保证了正确性。 

### 质数

 素数，例如`7`或者`13`只有一个真因数，`1`。 

幼稚的实现可能会意外地假设每个除数搜索都会找到多个因子。 我们的解决方案自然可以处理素数，因为在它们之间找不到约数`2`和`√num`，将总和保留为`1`，它正确返回`false`。
