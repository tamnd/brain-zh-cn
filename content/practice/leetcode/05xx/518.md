[LeetCode 518 题](https://leetcode.com/problems/coin-change-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算可以达到目标金额的硬币的**不同组合的数量**。 我们得到一个数组`coins`，其中每个值代表一个硬币面额和一个整数`amount`，它代表我们想要形成的目标总和。 

重要的细节是我们计算的是**组合**，而不是排列。 这意味着硬币的顺序**不**重要。 例如，如果`amount = 5`和`coins = [1,2,5]`， 然后`2 + 2 + 1`和`1 + 2 + 2`被视为**相同的组合**，而不是不同的组合。 

我们还被告知，每种硬币面额的**无限供应**。 这意味着任何硬币都可以根据需要多次使用。 

输入包括：

 -`amount`, 整数目标值
 -`coins`，一系列独特的硬币面额

 预期输出是一个整数，表示总和恰好等于的唯一组合的数量`amount`。 如果不存在有效组合，我们返回`0`。 

这些约束为选择有效的解决方案提供了有用的指导：

 -`amount <= 5000`-`coins.length <= 300`探索每种可能性的强力递归解决方案很快就会变得不可行，因为组合的数量呈指数级增长。 自从`amount`适度大，这强烈建议采用**动态规划**方法。 

应预先考虑几个重要的边缘情况。 

如果`amount = 0`，恰好有**一个有效组合**，根本不选择任何硬币。 这经常会导致实施失败，因为很多人错误地返回`0`。 

如果没有组合可以产生目标量，例如`amount = 3`和`coins = [2]`，答案一定是`0`。 

如果只有一种硬币面额，算法必须正确确定重复使用该硬币是否可以准确地达到目标。 

该问题还保证了硬币面额的唯一性，从而简化了重复计数的处理。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是递归地尝试各种可能的方法来形成金额。 

对于每个币种指数，我们有两种选择：

 1.再次使用当前的硬币，因为硬币是无限的。 
2. 跳过当前硬币并转到下一个面额。 

递归继续直到：

 - 剩余金额变为`0`，这意味着我们找到了一个有效的组合。 
- 剩余金额变为负数，表示该路径无效。 
- 我们在到达之前就用完了金币`0`。 

这种方法是正确的，因为它系统地探索了每一种有效的可能性。 然而，许多重叠的子问题反复出现。 例如，不同的递归路径可能会反复询问“我们可以通过多少种方法来获得金额”`3`使用从索引开始的硬币`2`？”

 如果没有记忆，相同的计算会被重新计算多次，导致运行时间呈指数增长。 

### 最佳解决方案的关键见解

 关键的观察结果是，这个问题具有**重叠子问题**和**最优子结构**，使其成为动态规划的绝佳候选者。 

我们可以定义一个动态编程状态，其中：`dp[x]`= 赚取金额的方式数量`x`。 

最初，只有一种方法可以赚钱`0`，通过选择无硬币：```
dp[0] = 1
```我们一次处理一枚硬币。 对于每种代币，我们都会更新所有可达到的金额。 

关键的技巧是**迭代的顺序**。 

我们首先迭代硬币，然后按递增顺序迭代金额。 这可确保组合仅计算一次。 

例如，在处理硬币时`2`，我们只扩展使用早期硬币已经构建的组合。 这可以防止对同一组合的重新排序版本进行计数。 

我们可以优化空间并使用 **1D DP 数组**，而不是存储完整的 2D 表。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(金额 + n)) | O（金额）| 递归探索所有可能性，重复计算过多 |
 | 最优动态规划| O(数量 × n) | O（金额）| 使用自下而上的DP来有效地计算组合 |

 在哪里`n`是硬币面额的数量。 

## 算法演练

 ### 最优动态规划算法

 1.创建一个大小为DP的数组`amount + 1`。 

我们使用`dp[i]`表示形成金额的方式数`i`。 

最初，所有值都是`0`因为我们还没有找到任何方法。 
2. 设置基本情况。 

我们初始化：```
dp[0] = 1
```这代表了创建金额的一种有效方式`0`，选择没有硬币。 
3. 一次处理一枚硬币。 

对于每一枚硬币`coins`，我们迭代从硬币价值到`amount`。 

我们从硬币的价值开始，因为较小的金额不能包含该硬币。 
4. 更新DP阵列。 

对于每个金额`current_amount`， 更新：```
dp[current_amount] += dp[current_amount - coin]
```这意味着：

-`dp[current_amount - coin]`告诉我们有多少种方法可以产生剩余价值。 
- 通过添加当前的硬币，所有这些方式都成为有效的方式`current_amount`。 
5. 继续，直到处理完所有硬币。 

由于硬币是按顺序处理的，因此可以在不引入重复排序的情况下构建组合。 
6. 返回`dp[amount]`。 

该值包含唯一组合的总数。 

### 为什么它有效

 正确性来自一个重要的不变量：

 处理完第一条后`k`硬币,`dp[x]`存储形成金额的组合数量`x`仅使用那些`k`硬币。 

当我们处理新硬币时，我们通过添加该硬币来扩展以前的有效组合。 由于每个硬币仅按外部顺序处理一次，因此会以一致的顺序生成组合，从而防止因重新排列而导致重复。 

## Python 解决方案```python
from typing import List

class Solution:
    def change(self, amount: int, coins: List[int]) -> int:
        dp = [0] * (amount + 1)
        dp[0] = 1

        for coin in coins:
            for current_amount in range(coin, amount + 1):
                dp[current_amount] += dp[current_amount - coin]

        return dp[amount]
```实现首先创建一个名为的动态编程数组`dp`。 每个索引代表一个金额，该索引处的值存储有多少种组合可以产生该金额。 

基本情况`dp[0] = 1`是必不可少的。 它确定只有一种方法可以赚钱`0`。 

外循环遍历每个硬币面额。 这种排序至关重要，因为它可以防止对同一组合的不同排列进行计数。 

内循环从币值开始，向上移动到目标金额。 对于每个金额，我们通过在添加当前硬币之前添加可以形成剩余金额的组合来更新方式数量。 

最后算法返回`dp[amount]`，其中包含有效组合的总数。 

## 解决方案```go
func change(amount int, coins []int) int {
	dp := make([]int, amount+1)
	dp[0] = 1

	for _, coin := range coins {
		for currentAmount := coin; currentAmount <= amount; currentAmount++ {
			dp[currentAmount] += dp[currentAmount-coin]
		}
	}

	return dp[amount]
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 使用切片而不是列表来存储动态编程值。 

Go 自动用零值初始化切片，因此除了设置之外不需要手动初始化`dp[0] = 1`。 

关于整数溢出没有特别的问题，因为该问题保证结果适合有符号的 32 位整数。 去的`int`type 足以满足此约束。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`amount = 0`。 这种情况很容易误处理，因为某些实现错误地返回`0`。 事实上，只有一种有效的组合，即不选择硬币。 该实现通过初始化正确处理这个问题`dp[0] = 1`。 

另一个棘手的情况是不存在有效的组合。 例如，`amount = 3`和`coins = [2]`无法产生目标。 由于在动态规划期间无法到达的金额永远不会收到更新，`dp[3]`遗迹`0`，已正确返回。 

当只有一种硬币面额时，就会发生第三种重要情况。 例如，`amount = 10`和`coins = [10]`应该返回`1`， 尽管`amount = 9`和`coins = [10]`应该返回`0`。 该算法自然可以处理这两种情况，因为只有当硬币价值符合当前金额时才会发生更新。 

另一个微妙的边缘情况涉及避免重复计数。 例如，`2 + 1 + 1 + 1`和`1 + 2 + 1 + 1`应算作相同的组合。 在外循环中处理硬币可确保按固定顺序构造组合，从而防止排列计数过多。
