 ## 解决方案

 ## 问题理解

 该问题给出 2D 坐标系中的四个点，并询问这四个点是否形成一个有效的正方形。 这些点不以任何保证的顺序提供，这意味着我们不能假设相邻点或对角相对的点已经正确分组。 

正方形必须同时满足两个几何属性。 首先，所有四个边必须具有相同的正长度。 其次，所有四个内角必须正好为 90 度。 由于这些点可以按任意顺序出现，因此面临的挑战是确定这四个点的某种排列是否满足这些条件。 

每个点都表示为一对整数`[x, y]`。 坐标可以是负值、正值或零。 该函数应该返回`true`如果四个点可以组成一个正方形，否则返回`false`。 

约束非常小，只涉及四个点，因此性能实际上并不受输入大小的限制。 然而，该问题仍然需要仔细的几何推理以避免错误的分类。 在检查距离或角度时，浮点运算可能会引入精度问题，因此基于整数的方法更好。 

一些边缘情况很重要：

 - 多个点可能重叠，产生零长度边。 
- 这些点可以形成矩形，但不能形成正方形。 
- 这些点可以形成等边但非直角的菱形。 
- 这些点可以共线。 
- 分数可能已经以随机顺序给出。 

正确的解决方案必须可靠地处理所有这些情况。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试这四个点的所有可能的排序，并检查该排序是否形成正方形。 

对于任何选定的订购：

 - 四个连续边必须具有相等的非零长度。 
- 两条对角线的长度必须相等。 
- 相邻边必须垂直。 

由于只有四点，所以有`4! = 24`可能的排列。 对于每个排列，我们可以计算距离并验证平方条件。 

这种方法是正确的，因为每种可能的安排都会被检查。 如果任何排序形成一个正方形，算法最终会找到它。 

然而，这种方法不必要地复杂。 尽管 24 种排列仍然是常数时间，但实现变得冗长且容易出错。 我们可以得出更清晰的几何观察结果，完全避免排列检查。 

### 最佳方法

 关键的几何见解是正方形具有：

 - 四个边长相等
 - 两条对角线长度相等
 - 对角线长度大于边长

 如果我们计算四个点之间的所有成对距离，则总共有六个距离：

 - 四边距
 - 两个对角线距离

 对于有效的正方形：

 - 四个最小距离必须等于且大于零
 - 两个最大距离必须相等

 这一观察结果完全消除了确定点排序的需要。 

我们使用平方距离而不是实际的欧几里德距离。 由于平方根保留排序，因此比较平方距离就足够了，并且避免了浮点运算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(1) | O(1) | O(1) | O(1) | 尝试所有 24 种排列并验证平方属性 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用成对距离频率属性 |

 ## 算法演练

 1. 将所有四个点存储在一个列表中，以便统一处理。 
2. 计算每对点之间的平方距离。 由于有四个点，因此正好有六个唯一对。 
3. 对于每对`(a, b)`，计算：$d=(x_1-x_2)^2+(y_1-y_2)^2$使用平方距离可以避免浮点精度问题，并且足以进行相等比较。 
4. 将所有六个平方距离插入列表中。 
5. 对距离列表进行排序。 排序后：

 - 前四个值应代表四个边。 
- 最后两个值应代表对角线。 
6. 验证最小距离是否大于零。 这确保没有两点重叠。 
7. 检查前四个距离是否相等。 这证实了所有边都具有相同的长度。 
8. 检查最后两个距离是否相等。 这证实了两条对角线具有相同的长度。 
9. 如果所有条件都通过，则返回`true`。 否则，返回`false`。 

### 为什么它有效

 正方形在其六对距离中唯一地产生四个相等的边长和两条相等的对角线。 没有其他四边形既满足这种精确模式，又具有非零边长。 对六个距离进行排序使我们能够将边与对角线分开，而无需明确确定点的顺序。 

## Python 解决方案```python
from typing import List

class Solution:
    def validSquare(
        self,
        p1: List[int],
        p2: List[int],
        p3: List[int],
        p4: List[int]
    ) -> bool:

        def squared_distance(a: List[int], b: List[int]) -> int:
            dx = a[0] - b[0]
            dy = a[1] - b[1]
            return dx * dx + dy * dy

        points = [p1, p2, p3, p4]
        distances = []

        for i in range(4):
            for j in range(i + 1, 4):
                distances.append(
                    squared_distance(points[i], points[j])
                )

        distances.sort()

        return (
            distances[0] > 0 and
            distances[0] == distances[1] ==
            distances[2] == distances[3] and
            distances[4] == distances[5]
        )
```实现首先定义一个辅助函数来计算两点之间的平方欧几里德距离。 这可以保持主要逻辑清晰并避免重复代码。 

所有四个点都存储在一个列表中，因此我们可以系统地迭代它们。 嵌套循环生成所有六个唯一点对。 

每个平方距离都附加到`distances`列表。 收集所有距离后，对列表进行排序，以便四个边长自然出现在两个对角线长度之前。 

最终的返回语句直接执行所有验证检查：

 -`distances[0] > 0`防止重叠点
 - 前四个相等的值确认相等的边长
 - 最后两个相等的值确认相等的对角线

 如果每个条件都成立，则这些点形成一个有效的正方形。 

## 解决方案```go
func validSquare(p1 []int, p2 []int, p3 []int, p4 []int) bool {

	squaredDistance := func(a []int, b []int) int {
		dx := a[0] - b[0]
		dy := a[1] - b[1]
		return dx*dx + dy*dy
	}

	points := [][]int{p1, p2, p3, p4}
	distances := make([]int, 0, 6)

	for i := 0; i < 4; i++ {
		for j := i + 1; j < 4; j++ {
			distances = append(
				distances,
				squaredDistance(points[i], points[j]),
			)
		}
	}

	sort.Ints(distances)

	return distances[0] > 0 &&
		distances[0] == distances[1] &&
		distances[1] == distances[2] &&
		distances[2] == distances[3] &&
		distances[4] == distances[5]
}
```Go 的实现与 Python 解决方案非常相似。 闭包用于平方距离辅助函数。 

切片用于存储点和计算的距离。 由于恰好生成了 6 个距离，因此用容量 6 初始化距离切片以避免不必要的重新分配。 

Go 整数运算在这里是安全的，因为坐标值被限制为`10^4`，因此平方距离仍然在 32 位有符号整数的范围内。

 ## 边缘情况

 ### 重复点

 最常见的错误之一是忘记拒绝重叠点。 如果两个点相同，则边长为零。 仅检查距离相等的简单实现可能会错误地将此类形状分类为正方形。 

此实现明确检查：```
distances[0] > 0
```由于最小距离对应于边长，这保证了每条边都有正长度。 

### 矩形但不是正方形

 矩形具有相等的对角线和直角，但相邻边不相等，除非它是特定的正方形。 一些不正确的解决方案仅验证对角线相等性和垂直性。 

成对距离方法避免了这个问题，因为矩形会产生两个不同的边长。 排序后，前四个距离不会全部匹配，导致算法返回`false`。 

### 旋转方块

 正方形可能会出现相对于坐标轴旋转的情况。 假设水平和垂直边缘的解决方案可能会在这些输入上失败。 

此实现完全与方向无关，因为它仅依赖于点之间的距离。 旋转时距离保持不变，因此旋转的方块处理自然且正确。
