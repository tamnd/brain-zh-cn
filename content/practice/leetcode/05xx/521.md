[LeetCode 521 题](https://leetcode.com/problems/longest-uncommon-subsequence-i/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们找到两个字符串之间的**最长不常见子序列**的长度**`a`和`b`。 

为了清楚地理解这个问题，我们首先需要理解**不常见子序列**意味着什么。 子序列是可以通过删除零个或多个字符而不改变剩余字符的相对顺序从字符串中获得的字符序列。 例如，`"ace"`是一个子序列`"abcde"`。 

不常见的子序列是出现在两个字符串的**恰好一个**中的子序列。 换句话说，我们希望一个字符串可以形成为一个输入字符串的子序列，但**不能**形成为另一个输入字符串的子序列。 

目标是返回这种不常见子序列的**最大可能长度**。 如果不存在不常见的子序列，我们返回`-1`。 

输入由两个小写英文字符串组成，`a`和`b`，每个长度之间`1`和`100`。 由于字符串非常短，即使有些低效的解决方案也可以工作，但有一个优雅的观察结果可以得出极其简单的最佳解决方案。 

关键的挑战是认识“最长”的不常见子序列可能是什么。 一个天真的解释可能建议生成所有子序列并比较它们，但这很快就会变得昂贵，因为每个长度的字符串`n`有`2^n`子序列。 

预先识别一些边缘情况很重要：

 - 如果两个字符串**完全相等**，则其中一个字符串的每个子序列也是另一个字符串的子序列。 在这种情况下，不存在不常见的子序列，所以答案是`-1`。 
- 如果字符串**不同但长度相同**，则整个较长字符串本身自动成为不常见子序列，因为相同长度的字符串不能是彼此的子序列，除非它们相等。 
- 如果字符串具有**不同的长度**，则较长的字符串本身一定是不常见的子序列，因为较短的字符串不能包含较长的字符串作为子序列。 

## 方法

 ### 蛮力方法

 强力解决方案将生成两个字符串的**所有可能的子序列**并比较它们。 

我们可以枚举每个子序列`a`，检查是否不存在`b`，并跟踪最长的有效候选者。 然后我们会对子序列重复相同的过程`b`。 

为了验证候选子序列是否属于另一个字符串，我们可以使用两指针子序列检查。 由于每个字符串的长度`n`有`2^n`子序列，这很快就会变得昂贵。 

例如，如果一个字符串的长度`100`， 有`2^100`可能的子序列，这是一个天文数字。 尽管限制很小，但暴力破解是完全不切实际的。 

蛮力方法是正确的，因为它显式地检查每个可能的不常见子序列并选择最长的有效子序列。 然而，其指数级的复杂性使其不可行。 

### 最佳方法的关键见解

 关键的观察出人意料地简单：

 如果两个字符串**不相等**，那么答案始终是**较长字符串**的长度。 

为什么这有效？ 

假设字符串不同。 

- 如果一个字符串较长，则整个较长字符串本身不可能是较短字符串的子序列。 因此，它自动成为一个不常见的子序列，并且由于它是整个字符串，因此它也是最长的候选序列。 
- 如果字符串具有相同的长度但不同，则两个字符串都不能是另一个字符串的子序列，除非它们相同。 因此，整个字符串本身就会成为不常见的子序列。 

唯一不存在不常见子序列的情况是字符串**完全相等**。 在这种情况下，一个字符串的每个子序列也会出现在另一个字符串中。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(n+m) × 最大(n,m)) | O(2^(n+m)) | O(2^(n+m)) | 生成所有子序列并比较它们 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 基于相等和长度的简单比较 |

 ## 算法演练

 ### 最优算法

 1.比较两个输入字符串`a`和`b`。 

我们首先判断字符串是否完全相同。 此检查至关重要，因为相同的字符串共享所有子序列。 
2.如果`a == b`， 返回`-1`。 

由于字符串是相同的，因此每个子序列`a`也是一个子序列`b`，反之亦然。 因此，不存在不常见的子序列。 
3.否则返回`max(len(a), len(b))`。 

如果字符串不同，则较长的字符串本身一定是不常见的子序列。 如果它们具有相同的长度但不同，则任一完整字符串都将用作不常见的子序列。 

### 为什么它有效

 正确性依赖于子序列的一个简单属性：

 如果两个字符串相同，则一个字符串只能是具有相同长度的另一个字符串的子序列。 此外，较长的字符串永远不可能是较短字符串的子序列。 

因此，当`a != b`，至少有一个完整的字符串保证是一个不常见的子序列，并且选择较长的字符串给出最大可能的长度。 如果`a == b`, no uncommon subsequence exists.

 ## Python 解决方案```python
class Solution:
    def findLUSlength(self, a: str, b: str) -> int:
        if a == b:
            return -1

        return max(len(a), len(b))
```该实现遵循最优算法的精确逻辑。 

第一个条件检查两个字符串是否相同。 如果是，函数立即返回`-1`因为不存在不常见的子序列。 

如果字符串不同，该函数将返回两个长度中较大的一个。 这是有效的，因为较长的字符串本身保证是一个不常见的子序列。 当两个字符串长度相等但不同时，`max(len(a), len(b))`只是返回共享长度。 

实现很简洁，因为关键见解消除了对子序列生成或比较逻辑的需要。 

## 解决方案```go
func findLUSlength(a string, b string) int {
    if a == b {
        return -1
    }

    if len(a) > len(b) {
        return len(a)
    }

    return len(b)
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有提供内置的`max`旧标准库版本中的整数函数，我们使用手动比较长度`if`陈述。 

不用担心整数溢出，因为最大字符串长度仅为`100`。 由于问题限制，空字符串是不可能的，但如果出现空字符串，实现仍然会正确运行。

 ## 边缘情况

 ### 相同的字符串

 当`a`和`b`完全相同，一个字符串中的每个子序列自动存在于另一个字符串中。 幼稚的实现可能会错误地返回字符串长度，因为它看到有效的子序列候选者，但这是不正确的。 实施明确检查`a == b`首先并返回`-1`。 

### 不同的长度

 如果一个字符串比另一个字符串长，则保证整个较长的字符串不会作为子序列放入较短的字符串中。 有缺陷的解决方案可能会尝试不必要地比较子序列，从而使逻辑变得过于复杂。 该实现通过直接返回较长的长度来正确处理此问题。 

### 长度相同但字符串不同

 这种情况可能不直观。 两个长度相等的字符串可能看起来很相似，但如果它们甚至有一个字符不同，则两个完整字符串都不能是另一个的子序列。 幼稚的实现可能会错误地尝试逐个字符匹配并错过这种洞察力。 该解决方案通过在字符串不相等时返回共享长度来自然地处理这个问题。
