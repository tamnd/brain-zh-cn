 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、设计、哈希函数

 ## 解决方案

 ## 问题理解

 该问题要求我们实现一个 URL 缩短服务，类似于 TinyURL。 给定一个长 URL，我们的系统应该生成一个短的、唯一的 URL，映射回原始 URL。 当短URL被访问时，系统应该返回原来的长URL。 本质上，我们需要长 URL 和短 URL 之间的可逆映射。 

输入始终是长度在 1 到 10,000 个字符之间的有效 URL。 输出是一个很小的 ​​URL，可以解码回原始 URL。 短 URL 不要求人类可读、跨多个实例全局唯一或确定性。 关键是每个编码的 URL 都可以正确解码，这使我们能够专注于内部映射而不是跨系统的哈希冲突。 

重要的边缘情况包括重复编码相同的 URL、极长的 URL，以及处理多个不同的 URL（如果使用朴素哈希，这些 URL 可能会被编码到相同的短 URL 中）。 该问题保证了`decode`函数只会使用之前生成的 URL 来调用`encode`。 

## 方法

 强力方法是为每个 URL 分配一个唯一标识符，例如顺序整数或直接哈希。 我们可以将映射存储在哈希表中（Python 中的字典或 Go 中的映射）。 每次编码时，我们都会将ID附加到固定的域中，例如`http://tinyurl.com/{id}`。 这是正确的，因为哈希表确保长 URL 和短 URL 之间的双射。 

更优化的解决方案通过为每个 URL 生成一个短的、固定长度的字母数字字符串来避免冲突。 我们可以使用计数器的 Base62 编码或随机字符串来完成此操作。 使用 base62 可确保短 URL 紧凑，同时允许存在大量唯一 URL。 哈希表仍然存储用于解码的映射。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次编码/解码 O(1) | O(n) | 简单的计数器或哈希表映射，如果使用计数器则无冲突 |
 | 最佳| 每次编码/解码 O(1) | O(n) | 使用哈希映射和随机/base62 短密钥来实现紧凑的 URL，最大限度地减少冲突 |

 ## 算法演练

 1. 初始化一个哈希映射来存储从短键到长 URL 的映射。 
2. 初始化计数器以生成唯一 ID 或使用随机字符串生成器。 
3. 对于编码，生成唯一的短密钥（递增计数器或使用随机字符串）。 将此键与长 URL 的映射存储在哈希映射中。 
4. 通过将密钥附加到基本域来构造短 URL，例如，`http://tinyurl.com/{key}`。 
5. 为了解码，从短 URL 中提取密钥。 
6. 在哈希映射中查找键以检索原始长 URL。 

工作原理：通过存储从短键到长 URL 的映射，我们确保每个编码的 URL 都可以被准确解码一次。 哈希映射为编码和解码提供 O(1) 访问，并且生成的密钥是唯一的，因此不会发生冲突。 

## Python 解决方案```python
import random
import string

class Codec:
    def __init__(self):
        self.url_map = {}
        self.base_url = "http://tinyurl.com/"
        self.chars = string.ascii_letters + string.digits

    def _generate_key(self, length: int = 6) -> str:
        """Generates a random 6-character alphanumeric string"""
        return ''.join(random.choice(self.chars) for _ in range(length))

    def encode(self, longUrl: str) -> str:
        """Encodes a URL to a shortened URL."""
        key = self._generate_key()
        # Ensure uniqueness
        while key in self.url_map:
            key = self._generate_key()
        self.url_map[key] = longUrl
        return self.base_url + key

    def decode(self, shortUrl: str) -> str:
        """Decodes a shortened URL to its original URL."""
        key = shortUrl.replace(self.base_url, "")
        return self.url_map.get(key, "")
```Python 实现使用哈希映射（`url_map`）来存储从短键到原始 URL 的映射。`_generate_key`生成一个随机的 6 个字符的字母数字字符串。 编码时，我们生成一个唯一的密钥并将其存储在映射中。 解码只是从短 URL 中提取密钥并检索相应的长 URL。 

## 解决方案```go
package main

import (
	"math/rand"
	"time"
)

type Codec struct {
	urlMap   map[string]string
	baseURL  string
	chars    string
	randSrc  *rand.Rand
}

func Constructor() Codec {
	return Codec{
		urlMap:  make(map[string]string),
		baseURL: "http://tinyurl.com/",
		chars:   "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789",
		randSrc: rand.New(rand.NewSource(time.Now().UnixNano())),
	}
}

func (c *Codec) generateKey(length int) string {
	key := make([]byte, length)
	for i := 0; i < length; i++ {
		key[i] = c.chars[c.randSrc.Intn(len(c.chars))]
	}
	return string(key)
}

func (c *Codec) encode(longUrl string) string {
	key := c.generateKey(6)
	for {
		if _, exists := c.urlMap[key]; !exists {
			break
		}
		key = c.generateKey(6)
	}
	c.urlMap[key] = longUrl
	return c.baseURL + key
}

func (c *Codec) decode(shortUrl string) string {
	key := shortUrl[len(c.baseURL):]
	return c.urlMap[key]
}
```在 Go 中，我们显式管理随机源（`randSrc`）以避免重新播种问题。 逻辑镜像 Python：生成随机密钥，确保唯一性，存储在映射中，然后检索进行解码。

 ## 边缘情况

 一种重要的边缘情况是对同一 URL 进行重复编码。 如果实现天真地重用密钥或不为每次调用生成唯一密钥，则重复编码可能会覆盖以前的条目。 在我们的实现中，每种编码都会生成一个新的随机密钥，以确保唯一性。 

另一个极端情况是 URL 极长，最多 10,000 个字符。 我们的解决方案将 URL 存储在内存中，而不进行截断或修改，因此它可以正确处理长 URL，而不会溢出或损坏。 

第三种边缘情况是解码从未生成的短 URL。 虽然问题保证了`decode`只会使用有效的短 URL 来调用，一个健壮的实现应该优雅地处理无效的密钥。 如果找不到键，Python 解决方案将返回一个空字符串，而 Go 解决方案会隐式返回字符串的零值，该值也是空的。
