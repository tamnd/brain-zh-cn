[LeetCode 523 题](https://leetcode.com/problems/continuous-subarray-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们判断一个数组是否包含一个**连续子数组**，其总和是`k`，同时还满足一个重要的约束：子数组必须包含**至少两个元素**。 

简单来说，我们需要找出是否存在某个连续的段`nums`，长度`>= 2`，这样：$$\text{subarray sum} \bmod k = 0$$这意味着总和必须除以`k`。 

输入包括：

 -`nums`，一个整数数组
 -`k`, 一个正整数

 输出是一个布尔值：

 - 返回`true`如果至少存在一个有效的子数组。 
- 返回`false`否则。 

一个关键细节是子数组必须是**连续的**。 我们不能任意选择元素。 另一个重要的注意事项是`0`总是被认为是的倍数`k`，表示子数组和`0`是有效的。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 个体值可能非常大，最多可达`10^9`- 总金额可以接近`2^31 - 1`这些限制立即表明`O(n²)`解决方案可能会太慢。 和`10^5`元素，检查每个可能的子数组在最坏的情况下将涉及数十亿次操作。 

一些边缘情况很容易导致简单的实现失败：

 - 有效的子数组可以从索引开始`0`。 
- 连续的零，例如`[0,0]`，应该返回`true`因为他们的总和是`0`，它可以被每个整除`k`。 
- 我们必须强制执行最小子数组长度`2`。 
- 非常大的数字需要避免重复范围求和。 

因为`k >= 1`，我们不需要处理被零除的情况。 

## 方法

 ### 蛮力方法

 暴力方法是检查每个可能的长度至少为连续的子数组`2`。 

对于每个起始索引`i`，我们将子数组扩展到每个结束索引`j > i`，计算总和，并检查是否：$$\text{sum} \bmod k = 0$$一个简单的实现将重复计算子数组和，这会导致`O(n³)`复杂。 即使使用前缀和在常数时间内计算子数组和，我们仍然需要检查每一对`(i, j)`， 导致`O(n²)`时间。 

这种方法是正确的，因为它显式地检查每个可能的候选子数组。 但是，对于大小的数组来说，它变得太慢`10^5`。 

### 最佳解决方案的关键见解

 关键的观察来自模运算。 

认为：$$prefixSum[j] \bmod k = prefixSum[i] \bmod k$$然后：$$(prefixSum[j] - prefixSum[i]) \bmod k = 0$$这意味着这些索引之间的子数组的总和可以整除`k`。 

我们不需要检查所有子数组，只需要跟踪前缀和模的**余数`k`**。 

如果稍后再次出现相同的余数，则这两个位置之间的数字形成一个有效的子数组，可整除`k`。 

我们使用哈希映射来存储每个余数的**第一次出现**。 存储第一次出现很重要，因为它最大化了可能的子数组长度并有助于满足最小长度要求。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查所有可能的子数组 |
 | 最佳| O(n) | O(min(n,k)) | 使用前缀和余数和哈希映射 |

 ## 算法演练

 ### 使用前缀和模的最优算法

 1. 初始化一个哈希映射，用于存储**每个余数出现的第一个索引**。 

我们从以下开始：```
{0: -1}
```这处理有效子数组从索引开始的情况`0`。 如果前缀和本身可以被`k`， 然后：```
currentIndex - (-1) >= 2
```可以验证长度要求。 
2. 初始化运行前缀和变量。 

当我们迭代数组时，我们不断累积值。 
3. 对于每个数字`nums`，更新运行总和。 

在索引处`i`:```
prefixSum += nums[i]
```4. 计算模余数`k`。```
remainder = prefixSum % k
```余数确定我们之前是否见过等效的前缀状态。 
5. 检查该余数以前是否出现过。 

如果它存在于哈希映射中，我们发现：```
prefixSum[i] % k == prefixSum[previousIndex] % k
```因此，这些索引之间的子数组的总和可除以`k`。 
6. 验证子数组长度。 

我们只返回`true`如果：```
i - previousIndex >= 2
```因为该问题至少需要两个元素。 
7. 否则，如果之前未出现过，则存储剩余部分。 

我们只存储**第一次出现**，因为较早的索引最大化了可能的子数组长度。 
8. 如果我们完成迭代而没有找到有效的子数组，则返回`false`。 

### 为什么它有效

 该算法依赖于数学不变量：

 如果两个前缀和除以后余数相同`k`，它们的差必须能被整除`k`。 

正式：$$A \bmod k = B \bmod k$$意味着：$$(A - B) \bmod k = 0$$由于子数组和等于两个前缀和的差，重复余数保证子数组和可整除`k`。 哈希映射确保我们可以在每个元素的恒定时间内检测到这一点。 

## Python 解决方案```python
from typing import List

class Solution:
    def checkSubarraySum(self, nums: List[int], k: int) -> bool:
        remainder_to_index = {0: -1}
        prefix_sum = 0

        for index, num in enumerate(nums):
            prefix_sum += num
            remainder = prefix_sum % k

            if remainder in remainder_to_index:
                previous_index = remainder_to_index[remainder]

                if index - previous_index >= 2:
                    return True
            else:
                remainder_to_index[remainder] = index

        return False
```实现直接遵循算法。 

我们首先创建`remainder_to_index`，将余数映射到它们出现的最早索引的字典。 正在初始化`{0: -1}`至关重要，因为它可以检测从索引开始的有效子数组`0`。 

变量`prefix_sum`当我们迭代数组时跟踪累积和。 

对于每个元素，我们更新前缀和并计算其余数模`k`。 如果这个余数之前出现过，我们检索前一个索引并检查索引之间的距离是否至少为`2`。 

如果满足长度要求，我们立即返回`True`。 

如果余数从未见过，我们存储它的索引。 我们有意避免更新现有条目，因为我们想要最早的索引，这给出了最长的可能有效子数组。 

如果遍历数组后没有找到有效的子数组，则函数返回`False`。 

## 解决方案```go
func checkSubarraySum(nums []int, k int) bool {
	remainderToIndex := map[int]int{
		0: -1,
	}

	prefixSum := 0

	for index, num := range nums {
		prefixSum += num
		remainder := prefixSum % k

		if previousIndex, exists := remainderToIndex[remainder]; exists {
			if index-previousIndex >= 2 {
				return true
			}
		} else {
			remainderToIndex[remainder] = index
		}
	}

	return false
}
```Go 实现密切反映了 Python 逻辑。 

Go 映射用于恒定时间余数查找。 初始化：```go
map[int]int{0: -1}
```与 Python 中的用途相同，处理从索引开始的子数组`0`。 

由于 Go 整数对于该问题的约束来说足够大，因此整数溢出不是问题。 输入保证总和不超过`2^31 - 1`。 

与 Python 字典不同，Go 映射返回一个额外的布尔值（`exists`) 来指示密钥是否存在。 这可以避免余数映射到索引时出现歧义`0`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个元素被处理一次 |
 | 空间| O(min(n,k)) | 每个唯一剩余项最多一个条目 |

 该算法只扫描一次数组，每次哈希图操作都是平均的`O(1)`，导致线性时间复杂度。 

空间复杂度取决于出现多少个不同的余数。 由于余数范围为`0`到`k - 1`，哈希映射最多可以包含`min(n, k)`条目。

 ## 边缘情况

 ### 连续零

 像这样的数组：```
[0, 0]
```很容易在幼稚的实现中导致错误。 自从`0`可以被每一个整除`k`，这应该返回`True`。 

我们的实现自然地处理了这个问题。 处理完第二个零后，剩下余数`0`，它已经存在于哈希映射的索引处`-1`。 距离变为`2`，满足长度条件。 

### 从索引零开始的有效子数组

 考虑：```
[6, 6]
```和`k = 6`。 

前缀本身的总和可以被整除`k`。 没有初始化：```
{0: -1}
```我们会错过这种情况，因为不会有更早的匹配余数。 

哨兵值`-1`在数组开始之前有效地表示一个空前缀。 

### 匹配余数但长度无效

 考虑：```
[23, 2, 6]
```和`k = 6`。 

在某一时刻，相同的余数再次出现，但索引之间的距离可能仅为`1`。 粗心的实现可能会错误地返回`True`。 

我们的实现明确检查：```
index - previous_index >= 2
```它保证子数组至少包含两个元素。 

### 大输入量

 自从`n`可以达到`100000`，嵌套循环会超时。 

哈希映射方法对每个元素处理一次，确保线性时间复杂度，并且即使在最大输入大小下也能保持高效。
