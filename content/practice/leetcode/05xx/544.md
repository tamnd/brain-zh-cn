[LeetCode 544 题](https://leetcode.com/problems/output-contest-matches/)

 **难度：** 🟡 中等
 **主题：** 字符串、递归、模拟

 ## 解决方案

 ## 问题理解

 该问题要求我们模拟季后赛分组的结构。 我们被给予`n`团队，编号为`1`到`n`，其中较小的数字代表较强的团队。 比赛配对规则是固定的：每轮比赛中，剩余最强的球队必须对阵剩余最弱的球队。 

输出并不是锦标赛的获胜者。 相反，我们必须返回整个竞赛结构的字符串表示形式。 每个匹配项均使用括号和逗号表示。 例如，如果团队`1`玩团队`8`，该匹配表示为`(1,8)`。 

每轮结束后，获胜者都会在概念上晋级，但我们不需要确定实际的获胜者。 我们只需要保留锦标赛结构即可。 这意味着之前的比赛字符串将成为下一轮的参与者。 

例如，当`n = 4`：

 - 第一轮：

 -`(1,4)`-`(2,3)`- 第二轮：

 -`((1,4),(2,3))`最终的输出是完整的嵌套表示。 

约束条件规定：

 -`n == 2^x`-`1 <= x <= 12`这意味着：

-`n`始终是二的幂。 
- 的最大值`n`是`4096`。 

因为团队数量相对较少，所以我们不需要非常高级的优化。 直接模拟就足够有效了。 

一个重要的保证是比赛每轮参赛人数始终为偶数。 自从`n`是二的幂，配对可以干净地继续，直到只剩下最后一场比赛。 

一些边缘情况很重要：

 - 最小可能的输入是`n = 2`，答案很简单`(1,2)`。 
- 大值，例如`n = 4096`创建深度嵌套的字符串，因此应小心处理字符串构造。 
- 不正确的配对顺序是一个常见的错误。 我们必须始终将每轮中最左边的剩余团队与最右边的剩余团队配对。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试使用递归树构造和重复字符串连接来显式模拟每一轮。 一种可能的实现是构建一个实际的二叉锦标赛树，其中每个节点存储其左子节点和右子节点，然后执行遍历以生成最终字符串。 

这是有效的，因为每一轮都会将成对的团队组合成更大的比赛结构，直到保留单个根节点。 

然而，构建完整的树结构会带来不必要的开销。 我们实际上不需要单独的树表示，因为所需的输出已经自然地形成了我们需要的结构。 

重复的递归遍历和额外的对象分配使解决方案变得不必要的复杂。 

### 最佳方法

 关键的观察结果是，可以仅使用字符串迭代地构建锦标赛结构。 

最初，每个团队都表示为自己的字符串：```
["1", "2", "3", ..., "n"]
```每轮：

 - 将第一个和最后一个条目配对。 
- 将第二个和倒数第二个条目配对。 
- 继续向内。 
- 用新的组合字符串替换每对：```
"(" + left + "," + right + ")"
```一轮结束后，参赛人数减少一半。 

这一过程持续进行，直到只剩下一根绳子。 

这样做的原因是每一轮都保留了问题陈述所需的确切锦标赛结构。 生成的嵌套字符串直接代表季后赛括号。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n log n) | O(n log n) | 构建明确的递归锦标赛结构 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 逐轮迭代地组合匹配字符串 |

 ## 算法演练

 1. 创建代表所有团队的字符串数组。 

例如，如果`n = 8`：```
["1", "2", "3", "4", "5", "6", "7", "8"]
```我们使用字符串是因为最终结果是嵌套的字符串表达式。 
2. 当剩余一支以上球队时，处理一轮锦标赛。 

每一轮将条目数量减少一半。 
3. 使用两个指针，一个在开头，一个在结尾。 

左边的指针代表剩余最强的球队。 

右边的指针代表剩下的最弱的球队。 
4. 将团队配对。 

构造一个新字符串：```
"(" + leftTeam + "," + rightTeam + ")"
```例如：```
"(1,8)"
```5. 将所有新形成的匹配字符串存储在新数组中。 

处理完所有对后，用新数组替换旧数组。 
6. 重复此操作，直到只剩下一根绳子。 

最后的字符串是完整的锦标赛括号。 

### 为什么它有效

 该算法保持一个不变量：在每一轮之后，数组包含所有幸存锦标赛分支的正确格式的匹配结构。 

由于每轮总是将最强的剩余条目与最弱的剩余条目配对，因此该算法完全符合所需的季后赛规则。 反复减少数组可以保证最终剩余的字符串代表完整的锦标赛结构。 

## Python 解决方案```python
class Solution:
    def findContestMatch(self, n: int) -> str:
        teams = [str(i) for i in range(1, n + 1)]

        while len(teams) > 1:
            next_round = []

            left = 0
            right = len(teams) - 1

            while left < right:
                match = f"({teams[left]},{teams[right]})"
                next_round.append(match)

                left += 1
                right -= 1

            teams = next_round

        return teams[0]
```实现首先将所有团队编号转换为字符串。 这简化了以后的连接，因为每一轮都会产生更大的字符串表达式。 

外层`while`循环模拟锦标赛回合。 只要还有不止一名参赛者，就必须进行另一轮比赛。 

在每一轮中，使用两个指针：

 -`left`从数组的开头开始。 
-`right`从最后开始。 

这些指针确保我们始终将最强的剩余团队与最弱的剩余团队配对。 

对于每一对，我们创建一个格式化的匹配字符串并将其附加到`next_round`。 

处理完所有对后，`teams`被替换为`next_round`，将参与者数量减少一半。 

最终，只剩下一个完全嵌套的匹配字符串，该字符串作为答案返回。 

## 解决方案```go
import "strconv"

func findContestMatch(n int) string {
    teams := make([]string, n)

    for i := 0; i < n; i++ {
        teams[i] = strconv.Itoa(i + 1)
    }

    for len(teams) > 1 {
        nextRound := []string{}

        left := 0
        right := len(teams) - 1

        for left < right {
            match := "(" + teams[left] + "," + teams[right] + ")"
            nextRound = append(nextRound, match)

            left++
            right--
        }

        teams = nextRound
    }

    return teams[0]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是整数必须使用显式转换为字符串`strconv.Itoa`。 

切片用于存储当前回合的参与者和下一轮生成的比赛。 由于 Go 字符串是不可变的，因此连接会像 Python 一样创建新字符串。 

由于约束很小，因此不存在整数溢出问题。

 ## 边缘情况

 ### 最小输入大小

 最小的有效输入是`n = 2`。 在这种情况下，只有一个匹配，并且除了一对之外没有递归嵌套。 

有缺陷的实现可能会错误地进入另一轮或错误地处理索引。 该解决方案可以自然地处理它，因为第一轮立即将数组减少为一个元素。 

### 深度嵌套的锦标赛字符串

 对于较大的值，例如`n = 4096`，结果字符串变得非常深嵌套并且非常大。 

过度复制或树遍历的低效递归实现可能会变得不必要的缓慢或占用大量内存。 迭代方法避免了递归深度问题并逐层构造括号。 

### 配对顺序不正确

 最容易犯的错误之一是将相邻的球队配对，而不是最强与最弱的球队。 

例如，错误地生成：```
(1,2),(3,4)
```而不是：```
(1,4),(2,3)
```会违反比赛规则。 

使用两个指针可以保证最左边和最右边的剩余参与者在每一轮中始终正确配对。
