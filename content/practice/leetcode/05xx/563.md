[LeetCode 563 题](https://leetcode.com/problems/binary-tree-tilt/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们计算整个二叉树的总倾斜度。 树中的每个节点都有自己的倾斜度，最终的答案是所有单个节点倾斜度的总和。 

节点的倾斜定义为以下各项之间的绝对差：

 - 其左子树中所有值的总和
 - 其右子树中所有值的总和

 如果子树不存在，则考虑其总和`0`。 

例如，假设一个节点有：

 - 左子树总和 = 8
 - 右子树总和 = 3

 那么节点的倾斜度为：$|8-3|=5$输入是二叉树的根。 每个节点包含：

 - 整数值
 - 左子指针
 - 右子指针

 输出是一个整数，表示树中所有节点的倾斜总和。 

约束告诉我们树最多可以包含`10^4`节点。 该值足够大，以至于低效的重复遍历可能会变得昂贵。 由于节点值可能为负，子树和也可能变为负，因此算法必须正确处理有符号算术。 

一些边缘情况很重要：

 - 应该返回一棵空树`0`- 单节点树有倾斜`0`，因为两个子树和都是`0`- 只有左子树或只有右子树的树会产生高度不平衡的结构
 - 如果不仔细处理绝对差值，负值可能会产生意外的子树和

 该问题保证输入是有效的二叉树，因此我们不需要验证结构的正确性。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是独立计算每个节点的倾斜度。 

对于每个节点：

 1. 计算左子树的和
 2. 计算右子树的和
 3.取绝对差
 4. 将结果添加到全局总计中

 问题在于子树总和被重新计算多次。 

考虑一棵倾斜的树：```
1
 \
  2
   \
    3
     \
      4
```计算节点倾斜时`1`，我们几乎遍历了整棵树。 那么在计算节点的倾斜度时`2`，我们再次遍历剩余树的大部分，依此类推。 

这种重复的工作导致时间复杂度降级为`O(n^2)`在最坏的情况下。 

虽然这种方法是正确的，但对于大树来说效率很低。 

### 最佳方法

 关键的观察是，在计算节点的倾斜时，我们已经需要其左右子树的总和。 

我们可以使用后序遍历来计算一次子树总和，而不是重复地重新计算子树总和。 

后序遍历按以下顺序处理节点：

 1. 左子树
 2. 右子树
 3.当前节点

 这个顺序是完美的，因为当我们处理节点时，我们已经知道：

 - 左子树的总和
 - 右子树的总和

 所以我们可以：

 1. 立即计算节点的倾斜度
 2. 将其添加到运行总计中
 3. 将子树和向上返回给父级

 这消除了冗余工作并给出了线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 重复重新计算子树和 |
 | 最佳 | O(n) | O(h) | 单个后序遍历计算总和和倾斜 |

 这里，`h`是树的高度。 

## 算法演练

 1. 初始化一个名为`total_tilt`存储所有节点的累积倾斜度。 
2. 定义一个递归辅助函数，返回以当前节点为根的子树的总和。 
3. 在helper函数中，首先检查当前节点是否为`None`。 如果是，则返回`0`因为空子树没有任何价值。 
4. 递归计算左子树的和。 这确保在处理当前节点之前已经处理了整个左侧。 
5. 同理递归计算右子树之和。 
6. 使用左子树和右子树之和之间的绝对差来计算当前节点的倾斜度。 

对于有左和的节点`L`和正确的总和`R`：$|L-R|$1.将此倾斜值添加到`total_tilt`。 
2. 返回以当前节点为根的子树总和。 这包括：

 - 当前节点值
 - 左子树和
 - 右子树和

 对于节点值`v`：$v+L+R$1、从根节点开始递归。 
2.遍历结束后，返回`total_tilt`。 

### 为什么它有效

 该算法之所以有效，是因为每个节点只有在其两个子树都已完全评估后才会被处理。 这保证了在计算节点的倾斜时，左右子树和是正确且完整的。 

递归助手返回每个节点的精确子树总和，这允许父节点正确计算自己的倾斜度。 由于每个节点只贡献一次`total_tilt`，最终答案是所有节点倾斜度之和。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def findTilt(self, root: Optional[TreeNode]) -> int:
        total_tilt = 0

        def subtree_sum(node: Optional[TreeNode]) -> int:
            nonlocal total_tilt

            if not node:
                return 0

            left_sum = subtree_sum(node.left)
            right_sum = subtree_sum(node.right)

            total_tilt += abs(left_sum - right_sum)

            return node.val + left_sum + right_sum

        subtree_sum(root)

        return total_tilt
```该实现使用了一个名为的嵌套辅助函数`subtree_sum`。 该函数执行后序遍历并返回当前子树的总和。 

底壳手柄`None`通过返回节点`0`。 

对于每个非空节点：

 1. 递归计算左子树和。 
2. 递归计算右子树和。 
3. 使用绝对差计算节点的倾斜度。 
4. 倾斜度将添加到运行总计中。 
5.向上返回完整的子树和。 

这`nonlocal`关键字允许辅助函数修改`total_tilt`定义在外部范围内。 

此实现仅访问每个节点一次，即使对于大型树也非常高效。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func findTilt(root *TreeNode) int {
    totalTilt := 0

    var subtreeSum func(node *TreeNode) int

    subtreeSum = func(node *TreeNode) int {
        if node == nil {
            return 0
        }

        leftSum := subtreeSum(node.Left)
        rightSum := subtreeSum(node.Right)

        if leftSum > rightSum {
            totalTilt += leftSum - rightSum
        } else {
            totalTilt += rightSum - leftSum
        }

        return node.Val + leftSum + rightSum
    }

    subtreeSum(root)

    return totalTilt
}
```Go 实现遵循与 Python 版本相同的后序遍历策略。 

一个显着的区别是 Go 没有内置的`abs`标准库中的整数函数。 相反，代码使用条件语句手动计算绝对差。 

递归助手被定义为函数变量，因此它可以递归引用自身。 

Go 中的 Nil 指针的作用与`None`在Python中。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用堆栈最多存储树高帧 |

 该算法对树执行一次 DFS 遍历。 每个节点都贡献持续的工作：

 - 计算左子树和
 - 计算右子树和
 - 计算倾斜
 - 返回子树总和

 因此，总运行时间与节点数量呈线性关系。 

辅助空间复杂度来自递归深度。 在平衡树中，高度为`O(log n)`。 在完全倾斜的树的最坏情况下，高度变为`O(n)`。

 ## 边缘情况

 ### 空树

 空树不包含任何节点，因此无需计算倾斜。 有缺陷的实现可能会尝试访问以下属性`None`和崩溃。 

该实现可以安全地处理这个问题，因为递归助手会立即返回`0`当给定一个空节点时。 因此，`findTilt(None)`正确返回`0`。 

### 单节点树

 一棵只有一个节点的树没有左子树或右子树。 因此，两个子树的总和都是`0`，所以倾斜度为：$|0-0|=0$某些实现意外地以不同方式对待叶节点或忘记将它们包含在遍历逻辑中。 该解决方案自然地通过递归基本情况处理叶节点。 

### 高度不平衡的树

 倾斜树的行为与链表类似，并且可能会暴露暴力方法的低效率，因为子树总和会被重复重新计算。 

最佳解决方案仍然对每个节点只处理一次。 即使递归深度变为`O(n)`在最坏的情况下，总计算保持线性。 

### 负节点值

 由于节点值可能为负，因此子树和也可能变为负。 不正确的实现有时会忘记正确应用绝对值。 

例如：$|-20-(-30)|=10$该实现始终使用绝对差，确保无论子树符号如何，倾斜都保持非负值。
