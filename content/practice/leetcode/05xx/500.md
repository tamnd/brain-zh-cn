[LeetCode 500 题](https://leetcode.com/problems/keyboard-row/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定列表中的哪些单词可以仅使用美式键盘的一行字母来输入。 

输入是一个字符串数组，`words`，其中每个字符串代表一个仅由英文字母字符组成的单词。 任务是仅返回每个字符都属于同一键盘行的单词。 键盘有三排：

 - 第一行：`"qwertyuiop"`- 第二行：`"asdfghjkl"`- 第三行：`"zxcvbnm"`该问题不区分大小写，这意味着同一字符的大写和小写版本会被同等对待。 例如，`'A'`和`'a'`属于同一行。 

要理解预期的输出，请考虑这个词`"Alaska"`。 忽略大小写后，所有字母都属于第二行，因此它应该包含在结果中。 然而，`"Hello"`使用多行字母，因此不应包含它。 

限制很小：

 - 最多20个字
 - 每个单词长度最多100个字符

 这告诉我们性能不是主要问题，即使是简单的方法也可以在限制内舒适地运行。 然而，我们仍然希望有一个干净、高效的实施。 

有几种边缘情况值得预先识别。 单词可能包含大小写字母的混合，因此除非执行规范化，否则区分大小写的实现将会失败。 单字符单词应始终符合条件，因为一个字符必然属于一行。 从一行开始但随后包含另一行字符的单词必须被拒绝。 该问题保证所有字符都是英文字母，这意味着我们不需要处理数字、空格或符号。 

## 方法

 ### 蛮力方法

 暴力解决方案会将单词的每个字符与所有三个键盘行重复进行比较。 

对于每个单词，我们可以单独检查每一行并确定所有字符是否都属于该行。 这意味着：

 1. 将单词转换为小写。 
2. 对于每个键盘行：

 - 检查该行中是否存在每个字符。 
3. 如果任何行完全匹配，则将该单词添加到结果中。 

这种方法是正确的，因为它显式测试每个可能的键盘行。 如果所有字符都适合一行，则该单词合格。 

然而，字符串内部的成员资格检查效率相对较低，因为在行字符串内搜索字符需要线性时间。 由于我们重复扫描行字符串中的每个字符，因此会发生不必要的重复工作。 

尽管约束足够小，这仍然可以通过，但我们可以提高查找效率。 

### 最佳方法

 关键的观察结果是每个字母始终属于键盘的一行。 我们可以预先计算从字符到行号的映射，而不是重复搜索行字符串。 

例如：

-`'q' → 1`-`'a' → 2`-`'z' → 3`一旦存在这种映射，检查单词就变得很简单：

 1. 将单词转换为小写。 
2. 找到第一个字符所在的行。 
3. 确保剩余的每个字符都属于同一行。 
4. 如果它们全部匹配，则将该单词包含在结果中。 

哈希表（Python 中的字典，Go 中的映射）使行查找时间恒定，从而简化了实现并避免了重复扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m × r) | O(1) | O(1) | 对于每个单词和字符，重复检查行成员资格，其中`r = 3`键盘行|
 | 最佳| O(n × m) | O(1) | O(1) | 使用哈希表进行恒定时间行查找 |

 这里：

-`n`= 字数
 -`m`= 平均字长

 由于键盘只有 26 个字母，因此额外的空格保持不变。 

## 算法演练

 1. 创建一个哈希表，将每个小写字符映射到其键盘行号。 

此预处理步骤允许对每个字母进行恒定时间的行查找。 而不是重复搜索字符串，例如`"qwertyuiop"`，我们立即知道一个字符属于哪一行。 
2. 初始化一个空的结果列表。 

该列表将存储满足单行条件的单词。 
3. 迭代中的每个单词`words`。 

每个单词都必须独立检查。 
4. 将当前单词转换为小写。 

由于问题不区分大小写，因此规范化大小写可确保行查找的一致性。 
5.确定第一个字符的键盘行。 

第一个字母建立所有其他字符必须匹配的行。 
6. 迭代单词中的剩余字符。 

对于每个字符：

 - 使用哈希表查找其行。 
- 将其与第一个字符的行进行比较。 
7. 如果任何字符属于不同的行，则停止检查当前单词。 

该单词立即变得无效，因为它使用了多个键盘行。 
8. 如果所有字符都匹配同一行，则将原始单词添加到结果中。 

我们返回原始大小写，而不是小写版本。 
9. 处理完所有单词后返回结果列表。 

### 为什么它有效

 该算法维护一个简单的不变量：当前单词中的每个处理的字符必须与第一个字符属于同一键盘行。 由于每个英文字母都属于一个键盘行，因此一旦我们发现不匹配，该单词就无法符合条件。 如果检查所有字符后不存在不匹配，则每个字符都属于同一行，证明该单词是有效的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findWords(self, words: List[str]) -> List[str]:
        keyboard_row = {}

        for char in "qwertyuiop":
            keyboard_row[char] = 1

        for char in "asdfghjkl":
            keyboard_row[char] = 2

        for char in "zxcvbnm":
            keyboard_row[char] = 3

        valid_words = []

        for word in words:
            lowercase_word = word.lower()
            target_row = keyboard_row[lowercase_word[0]]

            can_type = True

            for char in lowercase_word:
                if keyboard_row[char] != target_row:
                    can_type = False
                    break

            if can_type:
                valid_words.append(word)

        return valid_words
```该实现首先构建一个字典，将每个字母映射到其键盘行号。 此预处理步骤消除了重复的行扫描，并为我们提供了恒定时间的查找。 

接下来，我们迭代每个单词。 由于大写和小写字母应被同等对待，因此在处理之前将单词转换为小写。 

第一个字符确定目标行。 使用字典查找将每个剩余字符与该行进行比较。 如果出现任何不匹配的情况，我们会立即停止检查该单词，因为它不能满足要求。 

如果所有字符都匹配同一行，则将原始单词添加到结果列表中。 返回原始单词会保留其大小写，这与预期输出相匹配。 

## 解决方案```go
func findWords(words []string) []string {
	keyboardRow := make(map[rune]int)

	for _, char := range "qwertyuiop" {
		keyboardRow[char] = 1
	}

	for _, char := range "asdfghjkl" {
		keyboardRow[char] = 2
	}

	for _, char := range "zxcvbnm" {
		keyboardRow[char] = 3
	}

	result := []string{}

	for _, word := range words {
		lowercaseWord := []rune(strings.ToLower(word))
		targetRow := keyboardRow[lowercaseWord[0]]

		canType := true

		for _, char := range lowercaseWord {
			if keyboardRow[char] != targetRow {
				canType = false
				break
			}
		}

		if canType {
			result = append(result, word)
		}
	}

	return result
}
```Go 解决方案遵循与 Python 版本相同的逻辑，但存在一些实现差异。 

Go 使用一个`map[rune]int`而不是 Python 字典。 由于 Go 中的字符串是 UTF-8 编码的，因此迭代字符使用`rune`。 使用以下命令将单词转换为小写`strings.ToLower()`。 

与 Python 列表不同，Go 切片用于结果集合。 附加限定词是使用完成的`append()`。 

一个重要的细节是该解决方案需要导入`strings`包裹：```go
import "strings"
```不需要对 nil 与空切片进行特殊处理，因为空切片自然代表空结果。

 ## 边缘情况

 ### 单字符单词

 单字符单词始终符合条件，因为单个字母必然属于一个键盘行。 粗心的实现可能会意外地假设存在多个字符并导致索引问题。 此实现可以自然地处理它，因为第一个字符定义了行，并且验证循环立即成功。 

### 混合大小写字母

 诸如此类的话`"Dad"`或者`"QwErTy"`包含大写字母。 区分大小写的实现会错误地将大写字母视为行映射中缺失。 该解决方案在检查之前将每个单词转换为小写，以确保正确的行比较。 

### 早期单词不匹配

 一个词就像`"Hello"`一旦失效`'e'`遇到这个问题是因为它属于不同的键盘行`'h'`。 幼稚的实现可能会继续不必要的扫描。 该解决方案立即停止使用`break`，避免额外的工作并提高效率。
