 # LeetCode 514 - 自由之路

 ## 问题理解

 该问题模拟了一个圆形表盘，由字符串表示`ring`，每个字符都刻在圆周围的某个位置。 另一个字符串，`key`，代表我们必须拼写的字符序列。 

首先，索引处的字符`0`的`ring`对齐于`"12:00"`位置。 拼写每个字符`key`，我们可以顺时针或逆时针旋转环，直到所需字符的一次出现对齐在`"12:00"`。 对齐后，我们必须按下中心按钮，这需要额外的一步。 

目标是计算拼写整个单词所需的最少总步骤数`key`。 

重要的细节是环是圆形的。 从位置移动`0`定位`n - 1`只需要一步，因为我们可以向任一方向旋转。 对于任意两个职位，实际轮换成本是以下各项中的最小值：

 - 顺时针距离
 - 逆时针距离

 输入大小相对较小：

 -`1 <= ring.length <= 100`-`1 <= key.length <= 100`尽管这些限制并不大，但简单的递归探索仍然会变得极其昂贵，因为许多角色可能会在环中多次出现。 每个重复的角色都会产生分支选择。 

另一个重要的观察结果是，该问题保证了中的每个字符`key`存在于某处`ring`。 因此，我们永远不需要处理不可能的状态。 

一些边缘情况很重要：

 - 一个角色可能会出现多次`ring`，贪婪地选择最接近的事件并不总是最优的。 
- 环是圆形的，因此必须正确处理缠绕。 
-`ring`和`key`两者都可以有长度`1`。 
- 连续相同的字符`key`应该只需要再次按下按钮而无需旋转。 

## 方法

 ### 蛮力方法

 暴力解决方案递归地尝试每个字符的所有可能出现`key`。 

假设当前环指针位于位置`current`，我们需要拼写`key[i]`。 我们可以：

 1. 查找其中的每个索引`ring`在哪里`ring[index] == key[i]`2. 轮换到各个候选索引
 3. 递归求解剩余后缀`key`递归转换计算：

 - 轮换成本
 - 加一键按下
 - 加上解决剩余角色的成本

 这种方法是正确的，因为它探索了每种可能的轮换序列，因此最终找到了最小的总成本。 

然而，如果没有记忆的话，速度太慢了。 如果一个字符出现多次，则递归分支会很多。 在最坏的情况下，状态的数量随着长度的增加呈指数增长。`key`。 

### 关键见解

 关键的观察是该问题包含重叠的子问题。 

未来的成本仅取决于：

 - 环的当前位置
 - 当前索引`key`如果我们已经计算了一个状态的最低成本`(ring_position, key_index)`，我们应该重用它而不是重新计算它。 

这自然会导致动态规划。 

我们还通过存储每个字符的所有索引来预处理环。 这样，我们就可以直接跳转到目标字符的所有候选位置，而不是每次都扫描整个环。 

最佳解决方案使用具有记忆功能的 DFS：

 - 状态：`(current_ring_position, current_key_index)`- 过渡：

 - 尝试每个匹配的出现`key[current_key_index]`- 计算旋转距离
 - 递归求解剩余子串

 因为最多有`100 * 100 = 10,000`状态，解决方案变得有效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(密钥.长度) | 探索每一种可能的轮换顺序 |
 | 最佳 DFS + 记忆 | O(K × R × M) | O(K × R) | 重用子问题结果并仅探索有效的角色位置 |

 在哪里：

-`K = len(key)`-`R = len(ring)`-`M = average number of matching character positions`由于所有约束最多`100`，这在限制范围内运行舒适。 

## 算法演练

 1. 创建从每个字符到它出现的所有索引的映射`ring`。 

此预处理步骤很重要，因为许多字符可能会出现多次。 我们可以立即检索某个角色的所有候选位置，而不是重复扫描环。 
2. 定义递归DFS 函数。 

DFS状态为：

 -`ring_pos`，当前对齐位置
 -`key_index`，我们需要拼写的下一个字符

 该函数返回拼写所需的最少步骤数`key[key_index:]`。 
3. 处理基本情况。 

如果`key_index == len(key)`，那么我们已经拼出了整个密钥，所以剩余的成本是`0`。 
4. 检索目标字符的所有候选位置。 

让：```
target = key[key_index]
```使用预处理图，获取每个位置`ring`该字符出现的位置。 
5. 计算每个候选人的轮换成本。 

对于每个候选人职位：

 - 顺时针距离：```
abs(candidate - ring_pos)
```- 逆时针距离：```
ring_length - abs(candidate - ring_pos)
```实际旋转成本是两者中较小的一个。 
6. 递归计算剩余成本。 

总成本变为：

 - 旋转步骤
 - 加一键按下
 - 加上下一个字符的递归成本
 7. 在所有候选者中取最小值。 

由于可能存在多种情况，我们必须探索所有情况以确保最优性。 
8. 记住结果。 

存储答案`(ring_pos, key_index)`因此重复状态仅计算一次。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的解决方案都可以分解为更小的独立子问题。 在每个阶段，未来决策所需的唯一信息是：

 - 当前环对齐方式
 - 下一个关键字符索引

 DFS 探索每个有效的下一个对齐，而记忆则保证每个状态被解决一次。 由于递归总是考虑所有可能的转换并取最小值，因此最终结果是全局最优的。 

## Python 解决方案```python
from collections import defaultdict
from functools import lru_cache
from typing import List

class Solution:
    def findRotateSteps(self, ring: str, key: str) -> int:
        char_positions = defaultdict(list)

        for index, char in enumerate(ring):
            char_positions[char].append(index)

        ring_length = len(ring)

        @lru_cache(None)
        def dfs(ring_pos: int, key_index: int) -> int:
            if key_index == len(key):
                return 0

            target_char = key[key_index]
            minimum_steps = float("inf")

            for target_pos in char_positions[target_char]:
                direct_distance = abs(target_pos - ring_pos)
                rotation_steps = min(
                    direct_distance,
                    ring_length - direct_distance
                )

                total_steps = (
                    rotation_steps
                    + 1
                    + dfs(target_pos, key_index + 1)
                )

                minimum_steps = min(minimum_steps, total_steps)

            return minimum_steps

        return dfs(0, 0)
```该实现首先将环预处理为字典，将每个字符映射到其所有索引。 这允许恒定时间访问目标角色的所有候选位置。 

递归`dfs`函数代表动态规划状态。 它的参数唯一地定义了当前的问题：

 -`ring_pos`是当前对齐的位置
 -`key_index`表示其中的哪个字符`key`接下来必须拼写

 的`@lru_cache`装饰器自动记住结果。 如果没有记忆，许多相同的状态将被重复重新计算。 

在 DFS 内部，我们迭代目标字符的每次出现。 对于每位候选人：

 - 计算圆周旋转距离
 - 添加一键按下
 - 递归求解剩余后缀

 最后，我们返回所有候选者中最小的总成本。 

## 解决方案```go
package main

import "math"

func findRotateSteps(ring string, key string) int {
	charPositions := make(map[byte][]int)

	for i := 0; i < len(ring); i++ {
		charPositions[ring[i]] = append(charPositions[ring[i]], i)
	}

	ringLength := len(ring)

	type State struct {
		ringPos  int
		keyIndex int
	}

	memo := make(map[State]int)

	var dfs func(int, int) int

	dfs = func(ringPos int, keyIndex int) int {
		if keyIndex == len(key) {
			return 0
		}

		state := State{ringPos, keyIndex}

		if value, exists := memo[state]; exists {
			return value
		}

		minimumSteps := math.MaxInt32
		targetChar := key[keyIndex]

		for _, targetPos := range charPositions[targetChar] {
			directDistance := abs(targetPos - ringPos)

			rotationSteps := min(
				directDistance,
				ringLength-directDistance,
			)

			totalSteps := rotationSteps +
				1 +
				dfs(targetPos, keyIndex+1)

			minimumSteps = min(minimumSteps, totalSteps)
		}

		memo[state] = minimumSteps
		return minimumSteps
	}

	return dfs(0, 0)
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}

func min(a int, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但 Go 不提供内置的记忆化装饰器，例如`lru_cache`。 相反，我们将结果显式存储在`map[State]int`。 

定制`State`struct 被用作记忆键，因为 DP 状态取决于两者：

 - 当前环位置
 - 当前关键索引

 Go 还需要辅助函数`abs`和`min`。 

由于所有值都很小，因此不必担心整数溢出。

 ## 边缘情况

 ### 同一字符多次出现

 天真的贪婪策略可能总是选择最近出现的字符。 这可能会失败，因为现在稍微昂贵的移动可能会创建更便宜的未来配置。 

例如，如果环周围存在某个字符的多个副本，则选择最接近的一个可能会将指针放置在下一个所需字母的位置上。 该实现通过探索每个事件并通过动态编程获取全局最小值来正确处理这个问题。 

### 圆形环绕

 该环是圆形的，因此从索引处移动`0`索引`n - 1`仅需一步成本。 忘记这个细节会导致距离计算不正确。 

实现正确计算：```
min(distance, ring_length - distance)
```这保证了始终使用较短的旋转方向。 

### 键中连续相同的字符

 如果下一个所需字符已对齐`"12:00"`，无需旋转。 仅应计算按钮按下次数。 

例如：```
ring = "abc"
key = "aa"
```写完第一个字后`'a'`，第二个`'a'`只需再按一次按钮即可。 

DFS 自然地处理这个问题，因为旋转距离变成`0`。 

### 具有所有相同字符的戒指

 如果环中的每个字符都相同，则有许多相同的位置。 设计不当的算法可能会重复地重新计算相同的状态。 

记忆化通过缓存先前解决的状态来防止这种低效率。
