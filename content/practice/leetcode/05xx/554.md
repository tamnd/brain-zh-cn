[LeetCode 554 题](https://leetcode.com/problems/brick-wall/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表

 ## 解决方案

 ## 问题理解

 这个问题给了我们一堵由多排砖块组成的墙。 每行都表示为一个整数数组，其中每个整数描述砖块的宽度。 每块砖都有高度`1`，所有行一起形成一个总宽度相同的矩形。 

我们想要从墙的顶部到底部画一条垂直线，使得该线穿过尽可能少的砖块。 

一个非常重要的规则是，如果垂直线正好沿着两块砖之间的边界穿过，那么这些砖就不会被认为是交叉的。 这意味着最好的线通常是与尽可能多的砖块边缘对齐的线。 

但是，我们不能沿着墙的最左或最右边缘画线。 这些位置很容易跨越零砖，并且问题明确禁止它们。 

输入是一个二维数组：```
wall[i] = widths of bricks in row i
```例如：```
wall = [[1,2,2,1],[3,1,2]]
```第一行的砖块宽度为：```
1 | 2 | 2 | 1
```第二行有：```
3 | 1 | 2
```输出是一个整数，表示最佳垂直线穿过的砖块的最小数量。 

这些约束告诉我们一些重要的事情：

 - 最多可以有`10^4`行。 
- 所有行的砖块总数最多为`2 * 10^4`。 
- 砖块宽度可以非常大，可达`2^31 - 1`。 

从约束中观察到的关键是我们无法连续模拟每个可能的垂直位置。 宽度值很大，理论上墙可以跨越数十亿个单位。 相反，我们只需要关注有意义的位置，特别是砖块之间的边界。 

有几个重要的边缘情况：

 - 由单块砖组成的行。 在这种情况下，线没有可以通过的内部边缘，因此必须穿过每一行。 
- 多行共享相同的砖块边界。 这是理想的场景，因为该线可以避免同时穿过许多砖块。 
- 完全未对齐的行，没有内部边界匹配。 在这种情况下，该线会穿过每一行。 
- 大砖宽度。 我们不能构建与墙宽成正比的阵列。 

## 方法

 ### 蛮力方法

 一种简单的方法是考虑可以画线的每个可能的垂直位置，并计算它穿过了多少块砖。 

为此，我们可以：

 1. 计算每一行的所有可能的边缘位置。 
2. 对于每个候选人职位：

 - 检查每一行。 
- 确定该位置是位于砖块内部还是恰好位于边界上。 
3. 计算有多少行交叉。 
4. 返回最小计数。 

这种方法是正确的，因为它明确地评估每个有效的行放置。 

然而，它的效率很低，因为对于每个候选位置，我们可能会再次扫描所有行，甚至可能扫描所有砖块。 如果有`B`总砖块，复杂性可以接近`O(B^2)`。 

鉴于砖块的总数可达`2 * 10^4`，二次方法的成本不必要地高。 

### 关键见解

 我们可以最大化线穿过砖块边界的行数，而不是直接最小化交叉砖块的数量。 

假设墙有`n`行。 

如果一条垂直线穿过砖块边界`k`行，然后它正好穿过砖块：```
n - k
```行。 

所以：```
minimum crossed bricks = total rows - maximum shared edge count
```这将问题转化为频率计数问题。 

对于每一行：

 - 计算砖块宽度的前缀和。 
- 每个前缀和代表一个内部边缘位置。 
- 使用哈希图存储每个边缘位置出现的次数。 

我们忽略最后的边缘，因为它对应于墙的右边界，这是禁止的。 

最后：

 - 找到频率最高的边缘位置。 
- 从行数中减去该频率。 

这种方法非常有效，因为每块砖都只被处理一次。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(B²) | O(B) | 反复核对众多候选人职位|
 | 最佳| O(B) | O(B) | 使用哈希图来计算共享砖块边缘 |

 这里，`B`表示所有行中的砖块总数。 

## 算法演练

 1. 创建一个名为的哈希图`edge_count`。 

键将是边缘位置，值将存储包含该边缘的行数。 
2. 遍历墙上的每一行。 

对于每一行，我们使用运行前缀和来计算累积宽度。 
3. 遍历该行中除最后一块之外的所有砖块。 

我们排除最后一块砖，因为它的结束位置是墙的右边缘，并且不允许在那里画线。 
4. 更新运行前缀和。 

例如，如果一行是`[1,2,2,1]`，内部边缘位置为：```
1
1 + 2 = 3
3 + 2 = 5
```5. 增加哈希图中每个边缘位置的频率。 

这跟踪有多少行共享相同的边界。 
6. 处理完所有行后，找到哈希图中的最大频率。 

这代表穿过最多砖块边界的垂直线。 
7、退货：```
number_of_rows - maximum_frequency
```因为这些是线必须穿过砖块的行。 

### 为什么它有效

 每行要么在一个位置贡献一个边界，要么迫使线穿过那里的砖块。 通过计算有多少行共享相同的边界位置，我们可以直接确定可以避免多少块砖。 最大化共享边界会自动最小化交叉的砖块。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def leastBricks(self, wall: List[List[int]]) -> int:
        edge_count = defaultdict(int)

        for row in wall:
            prefix_sum = 0

            # Exclude the last brick to avoid the wall boundary
            for brick_width in row[:-1]:
                prefix_sum += brick_width
                edge_count[prefix_sum] += 1

        max_edges = max(edge_count.values(), default=0)

        return len(wall) - max_edges
```实现直接遵循算法。 

我们使用一个`defaultdict(int)`这样看不见的边缘位置就会自动从计数开始`0`。 

对于每一行，我们维护一个运行`prefix_sum`。 最后一块砖之前的每个前缀和代表一个有效的内部边界位置。 

表达式：```python
row[:-1]
```非常重要，因为它排除了墙的最终边缘。 

处理完所有行后，我们计算存储在哈希图中的最大频率。 如果不存在内部边缘，例如每行仅包含一个砖块，则地图将为空。 在这种情况下我们使用：```python
default=0
```以避免错误并正确返回总行数。 

最后，我们从总行数中减去最大共享边数。 

## 解决方案```go
func leastBricks(wall [][]int) int {
    edgeCount := make(map[int]int)

    for _, row := range wall {
        prefixSum := 0

        // Exclude the last brick
        for i := 0; i < len(row)-1; i++ {
            prefixSum += row[i]
            edgeCount[prefixSum]++
        }
    }

    maxEdges := 0

    for _, count := range edgeCount {
        if count > maxEdges {
            maxEdges = count
        }
    }

    return len(wall) - maxEdges
}
```Go 解决方案在结构上与 Python 版本相同。 

一个`map[int]int`用来代替Python的字典。 由于 Go 映射会针对缺失的键返回零值，因此递增计数非常简单。 

我们显式地使用索引进行循环，这样我们就可以在最后一块砖块之前停止：```go
for i := 0; i < len(row)-1; i++
```Go 整数在这里就足够了，因为约束符合平台的整数范围。

 ## 边缘情况

 ### 只有一块砖的行

 如果一行恰好包含一块砖，则不存在内部边界，线可以在不穿过砖的情况下通过。 幼稚的实现可能会错误地将墙边界本身包含为有效边缘。 

此实现通过迭代避免了该问题：```
row[:-1]
```这完全排除了最终的砖块边缘。 

### 无共享内部边缘

 有些墙可能有内部边界，但没有跨行对齐。 在这种情况下，每条可能的垂直线几乎都会穿过每一行。 

该算法自然地处理这个问题，因为每个边缘位置仅接收很小的频率计数。 最大频率保持较低，从而得出正确的最小交叉计数。 

### 空边图

 当每行都包含一个砖块时，边缘图会变为空，因为没有添加内部边界。 

呼唤`max()`在空集合上通常会引发错误。 该实现使用以下方法安全地处理此问题：```
max(edge_count.values(), default=0)
```它正确地将最大共享边计数视为零。
