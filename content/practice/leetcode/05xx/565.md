[LeetCode 565 题](https://leetcode.com/problems/array-nesting/)

 **难度：** 🟡 中等
 **Topics:** Array, Depth-First Search

 ## 解决方案

 ## 问题理解

 The problem gives us an array`nums`保证是以下整数的排列`0`到`n - 1`。 排列意味着每个值都只出现一次，并且每个值都在数组的有效索引范围内。 

对于每个起始索引`k`，我们反复遵循这条链：

 - 开始于`nums[k]`- 移至`nums[nums[k]]`- 然后`nums[nums[nums[k]]]`- 继续，直到遇到当前序列中已经出现过的值

 结果序列形成一个集合`s[k]`，我们想要计算所有这些集合中的最大可能大小。 

思考该问题的另一种方法是，数组定义一个有向图，其中每个索引恰好指向一个下一个索引。 由于该数组是一个排列，因此每个节点都恰好有一个传入边和一个传出边。 这种结构自然形成一个或多个循环。 

因此，该任务相当于找到排列图中最大循环的长度。 

考虑第一个例子：```
nums = [5,4,0,3,1,6,2]
```从索引开始`0`：```
0 -> 5 -> 6 -> 2 -> 0
```收集的值是：```
{5, 6, 2, 0}
```周期长度为`4`，这是最大可能的答案。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 每个值都是独一无二的
 - 每个值都在有效索引范围内

 这些保证告诉我们几件事：

 - 我们必须避免二次解
 - 遍历永远不会越界
 - 由于值是唯一的，因此结构完全由不相交的循环组成
 - 每个索引恰好属于一个周期

 幼稚的实现可能会多次重复访问同一周期，这对于大量输入来说会变得太慢。 关键的优化是认识到一旦处理了一个节点，我们就不需要再次处理它。 

重要的边缘情况包括：

 - 具有单个元素的数组
 - 每个元素都指向自身的数组
 - 包含一个非常大的循环的数组
 - 包含多个不同长度的不相交循环的数组

 因为输入保证是排列，所以我们永远不需要处理无效索引或重复值。 

## 方法

 ### 蛮力方法

 暴力解决方案独立地从每个索引开始遍历。 

对于每个起始位置：

 1.创建一个临时集合来跟踪当前遍历中访问过的元素
 2. 重复跟随下一个索引
 3.遇到重复时停止
 4.记录集合的大小

 这种方法是正确的，因为它明确地模拟了问题陈述中针对每个可能的起始索引描述的过程。 

然而，它的效率很低，因为许多遍历重复相同的工作。 如果多个起点属于同一个循环，则循环会一次又一次地遍历。 

例如：```
0 -> 1 -> 2 -> 0
```开始于`0`,`1`， 或者`2`全部经历完全相同的循环。 

在最坏的情况下，一个周期的大小`n`被遍历`n`次，导致`O(n^2)`时间复杂度。 

### 最佳方法

 关键的见解是每个索引都属于一个循环，一旦我们访问了一个循环，我们就不需要再次遍历它。 

我们维持全球`visited`数组：

 - 如果索引已被处理，则跳过它
 - 否则，从该索引开始遍历循环
 - 将每个遇到的节点标记为已访问

 由于在整个算法中每个节点仅被访问一次，因此总工作量变为线性。 

这特别有效，因为排列属性保证：

 - 没有分支路径
 - 无死角
 - 每次遍历最终都会进入一个循环

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复遍历相同的循环 |
 | 最佳 | O(n) | O(n) | 只访问每个索引一次 |
