 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`并询问最短连续子数组的长度，这样，如果仅该子数组按非递减顺序排序，则整个数组都会排序。 

换句话说，除了一些放错位置的元素之外，数组“几乎已排序”。 我们需要确定造成这种紊乱的最小连续部分。 一旦该部分被独立排序，整个数组中的每个元素都应该以非降序出现。 

例如，考虑：```
[2,6,4,8,10,9,15]
```数组大部分在增加，但是`6`和`4`出现故障，并且`10`和`9`也出故障了。 仅排序：```
[6,4,8,10,9]
```产生：```
[2,4,6,8,9,10,15]
```这是完全排序的。 因此答案是`5`，因为子数组长度为 5。 

约束条件很重要：

 - 数组长度可以大到`10^4`- 值可能为负
 - 后续要求我们实现`O(n)`时间

 这些限制告诉我们，诸如检查每个可能的子数组之类的极其缓慢的方法是不切实际的。 一个`O(n^2)`根据实施情况，解决方案可能勉强通过，但更糟糕的是太慢了。 后续行动强烈表明存在线性时间洞察力。 

一些边缘情况很重要：

 - 数组可能已经排序，在这种情况下答案是`0`- 数组只能包含一个元素
 - 允许重复值，因此我们必须保留非递减顺序而不是严格递增顺序
 - 未排序的部分可能会比第一个可见反转延伸得更远，因为放错位置的元素可能会影响更早或更晚的位置

 例如：```
[1,3,2,2,2]
```第一次反转发生在`3 > 2`，但是整个子数组`[3,2,2,2]`必须包括在内，因为所有`2`s 属于之前`3`。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是检查每个可能的子数组。 对于每个候选子数组：

 1.复制数组
 2. 仅对该子数组进行排序
 3. 检查整个结果数组是否已排序
 4.跟踪最小有效长度

 这种方法是正确的，因为它显式测试每个可能的连续段并返回修复数组的最小段。 

然而，运行时间非常昂贵。 有`O(n^2)`可能的子数组。 对子数组进行排序的成本高达`O(n log n)`，并检查整个数组是否已排序成本`O(n)`。 

总的复杂性对于`n = 10^4`。 

### 最佳方法

 关键的见解是我们实际上不需要模拟排序子数组。 

相反，我们可以识别哪些元素“不合适”。 

如果数组已完全排序：

 - 每个元素都大于或等于它之前的所有元素
 - 每个元素都小于或等于其后的所有元素

 我们可以通过两次线性扫描来利用这个特性。 

从左到右：

 - 跟踪迄今为止看到的最大值
 - 如果当前元素小于这个最大值，则它是乱序的
 - 未排序子数组的右边界必须包含该位置

 从右到左：

 - 跟踪迄今为止看到的最小值
 - 如果当前元素大于这个最小值，则它是乱序的
 - 未排序子数组的左边界必须包含该位置

 这是可行的，因为任何违反排序顺序的元素都必须属于需要排序的子数组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3 log n) | O(n3 log n) | O(n) | 通过排序和验证来测试每个子数组 |
 | 最佳 | O(n) | O(1) | O(1) | 使用两次线性扫描来查找无序边界 |

 ## 算法演练

 ### 最佳线性扫描算法

 1.初始化两个边界变量：

 -`left = -1`-`right = -1`这些最终将代表最小的未排序子数组。 
2. 执行从左到右的扫描。 

维护一个变量`max_seen`，初始化为第一个元素。 

对于每个索引`i`：

- 更新`max_seen = max(max_seen, nums[i])`- 如果`nums[i] < max_seen`，那么当前值比之前的值小，这意味着它是无序的
 - 更新`right = i`此步骤查找右侧违反排序顺序的最远位置。 
3. 执行从右到左的扫描。 

维护一个变量`min_seen`，初始化为最后一个元素。 

对于每个索引`i`从右到左：

 - 更新`min_seen = min(min_seen, nums[i])`- 如果`nums[i] > min_seen`，那么当前值比它后面的值大，这意味着它是无序的
 - 更新`left = i`此步骤查找左侧违反排序顺序的最远位置。 
4. 检查数组是否已排序。 

如果`right == -1`，那么扫描时没有发现违规，所以返回`0`。 
5. 否则，计算：```
right - left + 1
```这给出了必须排序的最短连续子数组的长度。 

### 为什么它有效

 该算法依赖于排序数组必须保持的不变量：```
nums[i] >= max(nums[0:i])
```在从左到右遍历期间，并且：```
nums[i] <= min(nums[i+1:])
```在从右到左的遍历过程中。 

任何违反这些条件的元素都不能保留在最终排序数组中的当前位置。 因此，最早和最新的违规恰好定义了必须排序的最小子数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def findUnsortedSubarray(self, nums: List[int]) -> int:
        n = len(nums)

        left = -1
        right = -1

        max_seen = nums[0]

        for i in range(n):
            max_seen = max(max_seen, nums[i])

            if nums[i] < max_seen:
                right = i

        min_seen = nums[-1]

        for i in range(n - 1, -1, -1):
            min_seen = min(min_seen, nums[i])

            if nums[i] > min_seen:
                left = i

        if right == -1:
            return 0

        return right - left + 1
```实现首先初始化数组长度和边界索引`left`和`right`。 

第一个循环从左到右扫描，同时跟踪迄今为止遇到的最大值。 如果当前值小于该最大值，则它违反排序顺序，因为较小的数字出现在较大的数字之后。 索引存储在`right`。 

第二个循环从右向左扫描，同时跟踪迄今为止遇到的最小值。 如果当前值大于此最小值，则它违反排序顺序，因为较大的数字出现在较小的数字之前。 索引存储在`left`。 

如果没有检测到违规，则数组已排序并且函数返回`0`。 

否则，未排序子数组的长度计算如下：```python
right - left + 1
```这恰好对应于必须排序的最小连续段。 

## 解决方案```go
func findUnsortedSubarray(nums []int) int {
    n := len(nums)

    left := -1
    right := -1

    maxSeen := nums[0]

    for i := 0; i < n; i++ {
        if nums[i] > maxSeen {
            maxSeen = nums[i]
        }

        if nums[i] < maxSeen {
            right = i
        }
    }

    minSeen := nums[n-1]

    for i := n - 1; i >= 0; i-- {
        if nums[i] < minSeen {
            minSeen = nums[i]
        }

        if nums[i] > minSeen {
            left = i
        }
    }

    if right == -1 {
        return 0
    }

    return right - left + 1
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于 Go 没有提供内置的`max`和`min`整数函数，比较是显式编写的`if`声明。 

Go 中的切片自然地处理动态数组行为，因此不需要额外的数据结构。 整数溢出不是问题，因为约束完全在 Go 的整数范围内。 

该算法使用恒定的额外内存并且仅执行两次线性扫描。

 ## 边缘情况

 ### 已经排序的数组

 已经排序的数组是最重要的边缘情况之一，因为许多实现意外地返回正长度。 

例子：```
[1,2,3,4]
```在从左到右扫描期间，没有元素小于`max_seen`， 所以`right`遗迹`-1`。 该实现显式检查此条件并返回`0`。 

### 具有重复项的数组

 如果实现采用严格递增的顺序，则重复项很容易引入相差一的错误。 

例子：```
[1,3,2,2,2]
```这`3`毕竟必须移动`2`s，因此未排序区域比第一次反转延伸得更远。 该算法可以正确处理此问题，因为它使用：```
nums[i] < max_seen
```和：```
nums[i] > min_seen
```而不是严格的排序假设。 

### 整个数组未排序

 有些数组需要对每个元素进行排序。 

例子：```
[5,4,3,2,1]
```在两次扫描期间，每个元素都违反排序顺序。 该算法扩展边界以包含整个范围，正确返回数组长度。 

### 单元素数组

 单个元素被简单排序。 

例子：```
[1]
```两次扫描都可以安全执行，因为该实现从有效索引进行初始化并且不执行无效访问。 由于没有发生违规，函数正确返回`0`。
