 # LeetCode 573 - 松鼠模拟

 ## 问题理解

 此问题模拟松鼠在 2D 花园网格中收集坚果。 花园有固定的树位置、起始松鼠位置和散布在网格周围的多个坚果。 

松鼠可以在四个基本方向上一次移动一个单元格，因此两个位置之间的距离就是曼哈顿距离：$$|r_1 - r_2| + |c_1 - c_2|$$松鼠一次只能携带一颗坚果。 每一颗坚果最终都必须被带回树上。 

重要的细节是，在将坚果送到树上后，松鼠总是会再次站在树上。 因此，对于除第一个螺母之外的每个螺母，行程模式都是固定的：

 1. 从树开始
 2. 走向坚果
 3.返回树

 这需要花费：$$2 \times \text{distance(tree, nut)}$$唯一的特殊情况是第一个坚果，因为松鼠从自己的初始位置开始，而不是从树开始。 

任务是确定收集坚果的顺序，以使总行进距离最小化。 

限制相对较小：

 - 网格尺寸最多为`100 x 100`- 最多可以有`5000`坚果

 处理每个坚果一次的解决方案很容易足够快。 然而，探索所有可能的集合顺序将过于昂贵，因为排列的数量呈阶乘增长。 

有几个值得预先注意的边缘情况：

 - 可能只有一颗螺母。 
- 松鼠可能已经站在树上了。 
- 坚果可能靠近树或靠近松鼠。 
- 最佳的第一个坚果可能不是距离松鼠最近的坚果。 
- 由于除了第一个螺母之外的每个螺母的行为都相同，因此选择正确的第一个螺母是核心优化挑战。 

## 方法

 ### 蛮力方法

 蛮力解决方案将尝试松鼠收集坚果的所有可能顺序。 

对于选定的订单：

 1. 松鼠从起始位置移动到第一个螺母。 
2. 它把坚果带回树上。 
3. 对于每个剩余的坚果，它会从树到坚果并返回。 

我们可以计算每个排列的总距离并返回最小值。 

这种方法是正确的，因为它明确评估了每个有效策略。 然而，这在计算上是不可行的。 高达`5000`坚果，排列数为：$$5000!$$即使对于更小的输入，这也变得不可能计算。 

### 最佳观察

 关键的见解是，除了第一个坚果之外，每个坚果都贡献相同的固定成本：$$2 \times \text{distance(tree, nut)}$$如果我们假设从树开始收集每个坚果，则总基线成本变为：$$\sum 2 \times \text{distance(tree, nut)}$$唯一的区别来自第一个螺母。 

通常，收集坚果的成本为：$$2 \times \text{distance(tree, nut)}$$但对于第一个坚果，松鼠从其初始位置而不是树开始，因此成本变为：$$\text{distance(squirrel, nut)} + \text{distance(nut, tree)}$$因此，与基准相比节省的成本为：$$2 \times d(tree, nut) - (d(squirrel, nut) + d(tree, nut))$$简化为：$$d(tree, nut) - d(squirrel, nut)$$所以我们只需选择最大化的坚果：$$d(tree, nut) - d(squirrel, nut)$$这会将问题转换为对所有螺母进行单一线性扫描。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 尝试所有可能的坚果收集顺序 |
 | 最佳 | O(n) | O(1) | O(1) | 计算基线往返成本并选择最佳的第一个坚果 |

 ## 算法演练

 1. 定义一个辅助函数来计算两个位置之间的曼哈顿距离。 

松鼠仅垂直和水平移动，因此曼哈顿距离给出了准确的移动成本。 
2. 初始化变量`total_distance`为零。 

该变量存储基线假设，即每个坚果都是从树开始收集并返回到树的。 
3. 初始化变量`best_gain`。 

这跟踪通过选择特定螺母作为第一个螺母所实现的最大节省。 
4. 迭代每一个细节。 

对于每个螺母：

 - 计算从树到坚果的距离。 
- 计算从松鼠到坚果的距离。 
5. 将坚果的往返树成本添加到`total_distance`。 

每个坚果的成本通常为：$$2 \times d(tree, nut)$$6. 首先计算选择该螺母的增益。 

基线假设松鼠从树开始。 但对于第一个坚果，它从松鼠的初始位置开始。 

增益为：$$d(tree, nut) - d(squirrel, nut)$$更大的收益意味着更多的节省。 
7. 更新`best_gain`如果当前的坚果提供更好的储蓄价值。 
8. 处理完所有螺母后，返回：$$total\_distance - best\_gain$$自从`best_gain`表示从基线节省的量，减去它即可得出最佳总距离。 

### 为什么它有效

 该算法之所以有效，是因为除了第一个坚果之外的每个坚果总是要求松鼠离开树并返回树，从而产生固定的不可避免的成本。 改变总距离的唯一决定是首先收集哪个坚果。 通过评估每个可能的第一个螺母的节省并选择最大节省，该算法保证了最小的总距离。 

## Python 解决方案```python
from typing import List

class Solution:
    def minDistance(
        self,
        height: int,
        width: int,
        tree: List[int],
        squirrel: List[int],
        nuts: List[List[int]]
    ) -> int:

        def manhattan(p1: List[int], p2: List[int]) -> int:
            return abs(p1[0] - p2[0]) + abs(p1[1] - p2[1])

        total_distance = 0
        best_gain = float("-inf")

        for nut in nuts:
            tree_distance = manhattan(tree, nut)
            squirrel_distance = manhattan(squirrel, nut)

            total_distance += 2 * tree_distance

            gain = tree_distance - squirrel_distance
            best_gain = max(best_gain, gain)

        return total_distance - best_gain
```该实现从曼哈顿距离的辅助函数开始。 这可以保持代码简洁，并避免在整个解决方案中重复距离公式。 

变量`total_distance`存储基线成本，其中每个坚果都被视为来自树的往返。 在循环过程中，每个螺母贡献：```python
2 * tree_distance
```变量`best_gain`跟踪通过选择特定坚果作为第一个收集的坚果可以节省多远的距离。 

对于每个坚果，算法计算：```python
gain = tree_distance - squirrel_distance
```如果松鼠比树更接近坚果，则该值会变大且为正，这意味着首先选择该坚果是有利的。 

最后，该算法从基线成本中减去最大增益，以产生最小总距离。 

## 解决方案```go
func minDistance(height int, width int, tree []int, squirrel []int, nuts [][]int) int {
	manhattan := func(a []int, b []int) int {
		rowDiff := a[0] - b[0]
		if rowDiff < 0 {
			rowDiff = -rowDiff
		}

		colDiff := a[1] - b[1]
		if colDiff < 0 {
			colDiff = -colDiff
		}

		return rowDiff + colDiff
	}

	totalDistance := 0
	bestGain := -1 << 30

	for _, nut := range nuts {
		treeDistance := manhattan(tree, nut)
		squirrelDistance := manhattan(squirrel, nut)

		totalDistance += 2 * treeDistance

		gain := treeDistance - squirrelDistance
		if gain > bestGain {
			bestGain = gain
		}
	}

	return totalDistance - bestGain
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于 Go 没有为标准库中的整数提供内置的绝对值函数（无需转换），因此曼哈顿距离助手会手动将负差值转换为正值。 

变量`bestGain`用一个非常小的整数值进行初始化，以确保在迭代过程中任何有效的增益都会替换它。 

切片自然地用于坐标和螺母位置，直接匹配问题输入格式。

 ## 边缘情况

 当只有一个螺母时，就会出现一种重要的边缘情况。 在这种情况下，松鼠在第一次收集后永远不会执行标准的树到坚果到树的循环。 有缺陷的实现可能会错误地普遍应用往返公式。 这种实现可以自然地处理这种情况，因为即使只有一个螺母，基线也会通过增益计算进行调整。 

另一个重要的边缘情况是松​​鼠从与树相同的位置开始。 在这种情况下，最优策略与树中的重复往返相同。 每个坚果的增益变为零，因为松鼠和树的距离相同。 该算法正确返回基线往返总数。 

第三个重要的边缘情况是当松鼠开始非常接近一个特定的坚果但远离树时。 天真的贪婪策略可能会错误地首先选择最靠近树的坚果。 然而，正确的优化取决于松鼠距离和树距离之间的差异。 该实现明确计算每个坚果的增益值，保证正确的选择。 

当所有坚果的增益均为负值时，就会出现最后一个微妙的边缘情况。 这意味着松鼠距离每个坚果比树距离更远。 即使在这种情况下，仍然必须先收集一颗坚果。 该算法正确地选择了最小的负增益，最大限度地减少了不可避免的额外距离。
