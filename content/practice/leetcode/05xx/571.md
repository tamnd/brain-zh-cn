 # LeetCode 571 - 求给定数字频率的中位数

 ## 问题理解

 该问题提供了数据集的压缩表示，而不是单独列出每个数字。 桌子`Numbers`包含两列：

 -`num`, 实际数量
 -`frequency`，该数字出现了多少次

 如果我们将表扩展为完全排序的数组，则每个`num`会准确地出现`frequency`次。 

任务是计算该解压缩数据集的中值。 

中位数取决于元素总数是奇数还是偶数：

 - 如果总数为奇数，则中位数为中间元素。 
- 如果总数是偶数，则中位数是中间两个元素的平均值。 

最终答案必须四舍五入到小数点后一位。 

例如，如果解压后的数组为：```
[0, 0, 0, 1, 2]
```中位数是`0`因为中间的元素是第三个值。 

如果解压后的数组为：```
[1, 2, 3, 4]
```中位数是`(2 + 3) / 2 = 2.5`。 

一个重要的细节是我们从未被要求实际解压缩数据。 频率可能很大，因此显式扩展数据集可能效率极低。 相反，我们应该推理排序顺序内的位置。 

该表保证`num`是唯一的，这意味着每个值恰好出现在一行中。 由于中位数仅取决于排序和计数，因此这使我们能够按排序顺序处理行并确定中间位置的位置。 

一些边缘情况很重要：

 - 元素总数可以是奇数或偶数。 
- 多行可能有助于中间位置。 
- 两个中间位置可能落在同一频率块内。 
- 频率可能非常大，导致减压不切实际。 
- 数据集可能包含负值。 
- 该表只能包含一个不同的数字。 

正确的解决方案必须直接从累积频率确定中间位置或多个位置。 

## 方法

 ### 蛮力方法

 最直接的解决方案是显式解压缩数据集。 

对于表中的每一行：

 - 重复`num`确切地`frequency`次。 
- 将这些值附加到数组中。 
- 如有必要，对数组进行排序。 
- 使用标准数组索引计算中位数。 

这种方法是正确的，因为它重建了频率表描述的精确数据集。 一旦我们有了完整排序的数组，计算中位数就变得微不足道了。 

然而，当频率很大时，这种方法效率低下。 如果一个数字出现数百万次，解压后的数组就会变得巨大。 内存使用量与元素总数成比例增长，而不是与行数成比例增长。 

因此，暴力方法对于大型数据集来说并不实用。 

### 最佳方法

 关键的观察结果是中位数仅取决于排序顺序的位置，而不取决于显式解压缩的数组。 

假设元素总数为`N`。 

中位位置为：

 - 如果`N`为奇数，位置`(N + 1) / 2`- 如果`N`是偶数，位置`N / 2`和`N / 2 + 1`我们可以计算累积频率，而不是扩展数组。 

对于按升序排列的每一行`num`：

 - 跟踪到目前为止我们已经处理了多少元素。 
- 确定当前号码覆盖的位置范围。 
- 检查目标中位位置是否落在该范围内。 

这是有效的，因为每一行代表排序的解压缩数据集中的一个连续块。 

例如：

 | 编号 | 频率| 涵盖职位 |
 | --- | --- | --- |
 | 0 | 7 | 1 至 7 |
 | 1 | 1 | 8 到 8 |
 | 2 | 3 | 9 至 11 |

 如果中位位置是`6`，它显然属于`0`。 

这完全避免了减压并且只需要累积计数。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(T)| O(T)| 显式解压缩所有值，其中 T 是总频率 |
 | 最佳 | O(N log N) | O(N log N) | O(1) | O(1) | 使用累积频率而无需减压 |

 这里：

-`N`是不同行的数量
 -`T`是总解压大小

 的`O(N log N)`因子来自排序依据`num`。 在 SQL 中，这对应于对行进行排序。 

## 算法演练

 1. 通过对所有频率求和来计算元素总数。 

这告诉我们数据集大小是奇数还是偶数，并确定目标中值位置。 
2. 确定中位指数位置。 

如果总计数为奇数，则两个目标位置是相同的中间索引。 

如果总数是偶数，我们需要两个中间索引。 

使用从 1 开始的索引：

 -`left_pos = (total_count + 1) // 2`-`right_pos = (total_count + 2) // 2`该公式对于奇数和偶数总数均适用。 
3. 按升序处理行`num`。 

由于解压缩的数组将被排序，因此我们必须按数字顺序检查值。 
4. 维护累积频率计数器。 

假设处理当前行之前的累计计数为`prev`。 

添加当前频率后，当前数字覆盖位置：```
prev + 1 through cumulative
```5. 检查目标仓位是否在当前范围内。 

如果任一中间位置位于该区间内，则当前`num`对中位数有贡献。 
6. 收集中值。 

根据总计数是奇数还是偶数，可以有一个或两个贡献值。 
7. 计算最终中位数。 

对收集的值进行平均并四舍五入到小数点后一位。 

### 为什么它有效

 该算法之所以有效，是因为累积频率准确地代表了排序解压缩数据集中的连续范围。 

每个数字占据特定的位置间隔。 中位数仅取决于中间位置或多个位置，因此一旦我们确定哪个区间包含这些位置，我们就知道相应的中值。 

由于每个解压元素恰好属于一个累积区间，因此该算法始终会识别正确的中位数，而无需显式构造完整数组。 

## Python 解决方案```python
SELECT ROUND(AVG(num), 1) AS median
FROM (
    SELECT
        num,
        SUM(frequency) OVER (ORDER BY num) AS cumulative_frequency,
        SUM(frequency) OVER () AS total_frequency
    FROM Numbers
) AS ordered_numbers
WHERE
    total_frequency / 2.0 BETWEEN
        cumulative_frequency - frequency
        AND cumulative_frequency;
```### 实现说明

 该解决方案使用 SQL 窗口函数来有效地计算累积统计信息。 

内部查询按升序处理行`num`。```
SUM(frequency) OVER (ORDER BY num)
```计算累积频率。 这告诉我们解压缩数组中每个数字的结束位置范围。```
SUM(frequency) OVER ()
```计算解压缩元素的总数。 

对于每一行：

 -`cumulative_frequency - frequency + 1`是起始位置
 -`cumulative_frequency`是结束位置

 中位位置集中在`total_frequency / 2.0`。 

这`WHERE`子句选择频率范围与中值位置重叠的所有行。 

最后：```
AVG(num)
```自动处理这两种情况：

 - 总计数为奇数，一个匹配行
 - 偶数总计数，可能有两个匹配的行

 结果使用四舍五入到小数点后一位`ROUND`。 

## 解决方案```go
package main

import "fmt"

type Number struct {
	Num       int
	Frequency int
}

func findMedian(numbers []Number) float64 {
	totalFrequency := 0

	for _, number := range numbers {
		totalFrequency += number.Frequency
	}

	leftPos := (totalFrequency + 1) / 2
	rightPos := (totalFrequency + 2) / 2

	cumulative := 0
	medianValues := []int{}

	for _, number := range numbers {
		start := cumulative + 1
		cumulative += number.Frequency
		end := cumulative

		if leftPos >= start && leftPos <= end {
			medianValues = append(medianValues, number.Num)
		}

		if rightPos >= start && rightPos <= end {
			if len(medianValues) == 0 || medianValues[len(medianValues)-1] != number.Num {
				medianValues = append(medianValues, number.Num)
			}
		}
	}

	sum := 0

	for _, value := range medianValues {
		sum += value
	}

	return float64(sum) / float64(len(medianValues))
}

func main() {
	numbers := []Number{
		{Num: 0, Frequency: 7},
		{Num: 1, Frequency: 1},
		{Num: 2, Frequency: 3},
		{Num: 3, Frequency: 1},
	}

	fmt.Println(findMedian(numbers))
}
```### Go 实现说明

 Go 版本在程序上演示了相同的累积频率逻辑。 

与 SQL 解决方案不同，Go 需要显式迭代和状态管理。 

该实现假设输入切片已按以下方式排序`Num`。 在实际的 SQL 问题中，排序是由数据库引擎直接处理的。 

中位位置使用整数算术计算，这避免了索引计算期间的浮点精度问题。 

最终结果转换为`float64`在除法之前确保正确的小数输出。

def median_from_frequencies(numbers):
    total = sum(freq for _, freq in numbers)

    left_pos = (total + 1) // 2
    right_pos = (total + 2) // 2

    cumulative = 0
    values = []

    for num, freq in sorted(numbers):
        start = cumulative + 1
        cumulative += freq
        end = cumulative

        if start <= left_pos <= end:
            values.append(num)

        if start <= right_pos <= end:
            values.append(num)

    return sum(values) / 2

 ## 边缘情况

 ### 偶数个元素

 当解压后的数据集包含偶数个元素时，中位数是中间两个值的平均值，而不是单个值。 

这是差一错误的常见来源，因为算法必须识别两个不同的位置。 

该实现通过计算以下两者来处理这个问题：```
left_pos = (N + 1) // 2
right_pos = (N + 2) // 2
```对于奇数计数，这些位置会自动变得相同。 

### 大频率

 简单的实现可能会尝试根据频率计数显式扩展数据集。 

如果一行的频率达到数百万，这将变得非常占用内存并且速度很慢。 

最佳解决方案通过使用累积频率来完全避免这种情况，无论解压大小如何，都可以保持内存使用量恒定。 

### 一个频率块内的中值

 有时两个中间位置都落在同一频率范围内。 

例如：```
num = 5, frequency = 100
```可能包含两个中间位置。 

不正确的实现可能会意外地将同一值错误地计算两次或无法正确平均。 

该算法自然地处理这个问题，因为对相同的值进行平均仍然会产生正确的中值。
