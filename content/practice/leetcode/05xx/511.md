[LeetCode 511 题](https://leetcode.com/problems/game-play-analysis-i/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们根据名为的表确定每个玩家登录游戏的第一天`Activity`。 该表的每一行包含一个`player_id`， 这`device_id`使用过的、`event_date`玩家登录的账号以及登录人数`games_played`在那次会议期间。 这`player_id`和`event_date`组合是唯一的，因此没有玩家在同一天有多个记录。 

预期输出是一个包含两列的表：`player_id`和`first_login`。 这`first_login`是最早的`event_date`该玩家的所有活动记录。 输出行的顺序并不重要。 

约束很简单：每个玩家至少有一条记录，日期有效，并且表中每个玩家可以有多个记录。 重要的边缘情况包括仅一次登录的玩家、同一天在不同设备上多次登录，以及确保正确处理日期比较。 

该问题保证了`(player_id, event_date)`是唯一的，因此我们不需要在同一天处理同一玩家的重复项。 

## 方法

 最直接的方法是蛮力：我们可以迭代所有记录，并为每个玩家跟踪我们见过的最小日期。 这是正确的，因为我们比较每个玩家的所有日期，但如果表很大，它不是最有效的。 在 SQL 中，这意味着子查询或多个联接，这可能会很慢。 

最佳方法是利用 SQL 聚合函数。 由于我们想要每个玩家的最早日期，`MIN`功能于`event_date`分组依据`player_id`自然高效地给了我们答案。 此方法仅扫描表一次，并使用数据库的内部优化进行分组和聚合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(p) | 迭代所有记录，手动跟踪每个玩家的最早日期 |
 | 最佳| O(n) | O(p) | 使用`GROUP BY player_id`和`MIN(event_date)`首次登录|

 这里，`n`是活动记录的总数，并且`p`是独特玩家的数量。 

## 算法演练

 1. 选择`player_id`从`Activity`桌子。 这确保了每个玩家都被代表一次。 
2. 使用`MIN()`函数在`event_date`柱子。`MIN()`自动查找组中最早的日期。 
3. 对结果进行分组`player_id`使用`GROUP BY`。 这会汇总每个玩家的所有记录，从而允许`MIN(event_date)`每个玩家进行操作。 
4. Return the results with the columns`player_id`和`first_login`（别名为`MIN(event_date)`）。 

为什么有效：分组确保每个玩家仅对单个输出行做出贡献，并且`MIN(event_date)`保证我们在他们的所有活动记录中选择最早的登录日期。 SQL 保证这些操作的确定性聚合。 

## Python 解决方案

 由于这是一个数据库问题，在 Python 中我们通常会使用连接对象执行 SQL 查询：```python
import sqlite3
from typing import List, Tuple

def first_login(conn: sqlite3.Connection) -> List[Tuple[int, str]]:
    query = """
    SELECT player_id, MIN(event_date) AS first_login
    FROM Activity
    GROUP BY player_id
    """
    cursor = conn.cursor()
    cursor.execute(query)
    result = cursor.fetchall()
    return result
```在这个实现中，我们使用`sqlite3`用于演示。 我们构造 SQL 查询`MIN(event_date)`和`GROUP BY player_id`。 游标执行查询，并且`fetchall()`返回元组的结果列表，其中每个元组包含一个`player_id`和他们的`first_login`日期。 

## 解决方案

 在 Go 中，我们将使用以下命令执行 SQL 查询`database/sql`包裹：```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func FirstLogin(db *sql.DB) ([]struct{ PlayerID int; FirstLogin string }, error) {
    rows, err := db.Query(`
        SELECT player_id, MIN(event_date) AS first_login
        FROM Activity
        GROUP BY player_id
    `)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var results []struct {
        PlayerID   int
        FirstLogin string
    }

    for rows.Next() {
        var r struct {
            PlayerID   int
            FirstLogin string
        }
        if err := rows.Scan(&r.PlayerID, &r.FirstLogin); err != nil {
            return nil, err
        }
        results = append(results, r)
    }

    return results, nil
}
```在 Go 中，与 Python 的差异主要与语法相关。 我们为每一行定义一个结构体，迭代`rows.Next()`，并将每一行扫描到结构中。 我们还显式处理错误并推迟关闭行以避免资源泄漏。 

## 工作示例

 示例表：```
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-05-02 | 6            |
| 2         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-02 | 0            |
| 3         | 4         | 2018-07-03 | 5            |
+-----------+-----------+------------+--------------+
```一步一步：

 1. 分组依据`player_id`:

 | 玩家 ID | 事件日期 |
 | --- | --- |
 | 1 | 2016-03-01, 2016-05-02 |
 | 2 | 2017-06-25 |
 | 3 | 2016-03-02, 2018-07-03 |

 1. 申请`MIN(event_date)`每个玩家：

 | 玩家 ID | 首次登录 |
 | --- | --- |
 | 1 | 2016-03-01 |
 | 2 | 2017-06-25 |
 | 3 | 2016-03-02 |

 这与预期输出相符。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 数据库扫描全部`n`记录一次以执行分组和聚合|
 | 空间| O(p) | 需要空间来存放`p`结果，每位玩家一个 |

 数据库查询优化器保证高效执行； 主要成本是读取所有记录，这是不可避免的。 产出与玩家数量成正比。

 ## 边缘情况

 首先，只有一次登录的玩家。 这是最简单的情况，算法正确返回该单个日期，因为`MIN`一个值就是该值本身。 

其次，同一天在不同设备上多次登录。 自从`(player_id, event_date)`是唯一的，SQL 查询仍然正确识别最早的登录日期，即共享日期，这表明设备差异不会干扰。 

第三，多年来登录次数非常多的玩家。 该算法可有效扩展，因为`GROUP BY`聚合对数据进行单次传递，因此即使玩家有数千个条目，也只会保留最小日期
