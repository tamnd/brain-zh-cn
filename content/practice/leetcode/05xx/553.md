[LeetCode 553 题](https://leetcode.com/problems/optimal-division/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、动态规划

 ## 解决方案

 ## 问题理解

 该问题给了我们一个正整数数组，并且数组元素按照从左到右的顺序使用除法运算进行组合。 

例如，如果输入是：```
[2, 3, 4]
```默认表达式变为：```
2/3/4
```其评估结果为：```
(2/3)/4
```因为除法是左结合的。 

问题的关键部分是我们可以在任何我们想要的地方插入括号，以便最大化最终的数值结果。 我们不会改变数字的顺序，只是改变操作的分组。 

输出不是数值本身。 相反，我们必须返回产生最大值的表达式字符串。 

该问题还指出返回的表达式不应包含多余的括号。 这意味着括号只能出现在实际改变计算顺序的地方。 

限制非常小：

 -`1 <= nums.length <= 10`-`2 <= nums[i] <= 1000`由于数组长度最多为 10，因此即使是指数或动态编程解决方案在技术上也是可行的。 然而，除法的数学结构使我们能够得出更简单的最优解。 

几个重要的边缘情况立即脱颖而出：

 - 一个数字，根本不存在除法。 
- 两个数字，其中不需要括号，因为只有一种可能的表达式。 
- 三个或更多数字，其中括号可能会显着改变结果。 
- 避免多余的括号，例如`"1000/((100/10)/2)"`，因为内部分组已经决定了顺序。 

另一个重要的保证是只有一个最优表达。 这意味着我们不需要担心关系。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试一切可能的方法来对除法表达式添加括号。 

这类似于经典的“添加括号的不同方法”问题。 对于每个子数组，我们可以递归计算：

 - 从该子表达式可获得的最大值
 - 从该子表达式可获得的最小值
 - 对应的表达式字符串

 对于每个分割点，我们将使用除法组合左右结果。 

这是有效的，因为每个有效的括号都会被探索，所以最终必须找到最佳答案。 

然而，可能的括号数量呈指数增长。 二叉表达式树的数量对应于加泰罗尼亚数字，它会很快变大。 虽然`n <= 10`虽然这在技术上是可以管理的，但它比必要的要复杂得多。 

### 关键见解

 批判性观察基于除法的数学表现。 

假设我们有：```
a / b / c / d
```我们想要最大化结果。 

除以较小的数会产生较大的结果。 因此，在第一个数字之后，我们希望分母变得尽可能小。 

最好的策略是：```
a / (b / c / d / ...)
```为什么？ 

因为：```
b / c / d
```评估为相对较小的数字，并除以`a`通过较小的分母最大化最终值。 

例如：```
1000 / (100 / 10 / 2)
= 1000 / ((100 / 10) / 2)
= 1000 / 5
= 200
```任何其他括号都会产生较小的分母减少效果。 

这导致了一个非常简单的最佳解决方案：

 - 如果只有一个数字，则直接返回。 
- 如果有两个数字，则返回`"a/b"`。 
- 如果有三个或更多数字，请将所​​有数字放在第一个数字后面的一对括号内。

 ## 算法演练

 1. 检查数组是否只有一个数字。 

如果数组长度是`1`，根本没有除法运算。 答案很简单，就是将数字本身转换为字符串。 
2. 检查数组是否恰好包含两个数字。 

只有两个数字，就只有一种可能的表达式：```
a/b
```括号不能改变任何内容，因此我们返回简单的除法字符串。 
3. 处理数组包含三个或更多数字的一般情况。 

最佳结构始终是：```
nums[0] / (nums[1] / nums[2] / ... / nums[n-1])
```这使得分母最小化，从而使总结果最大化。 
4. 构造表达式字符串。 

将每个数字转换为字符串并使用`'/'`。 

分子很简单：```
str(nums[0])
```分母部分为：```
"/".join(...)
```包裹在括号内。 
5. 返回最终的表达式。 

### 为什么它有效

 表达式：```
a / x
```变大时`x`变小。 

所有数字都是大于 1 的正整数。因此，为了最大化总体结果，我们必须最小化分母。 

对于任意序列：```
b / c / d / ...
```当从左到右求值时，出现最小可能值：```
((b / c) / d) / ...
```将整个后缀括在括号中会强制执行此评估顺序。 结果，分母变得最小，整体表达式变得最大。 

## Python 解决方案```python
from typing import List

class Solution:
    def optimalDivision(self, nums: List[int]) -> str:
        n = len(nums)

        if n == 1:
            return str(nums[0])

        if n == 2:
            return f"{nums[0]}/{nums[1]}"

        denominator = "/".join(str(num) for num in nums[1:])

        return f"{nums[0]}/({denominator})"
```实现直接遵循数学观察。 

首先，我们计算数组长度，因为行为完全取决于存在的数字数量。 

如果只有一个数字，我们立即将其作为字符串返回。 不需要运算符或括号。 

如果有两个数字，我们只需返回标准除法格式。 添加括号是多余的，因为只有一个操作。 

对于具有三个或更多数字的数组，我们通过将第一个之后的所有元素连接起来来构建分母`'/'`。 这将创建一个如下字符串：```python
100/10/2
```然后，我们将整个分母放在括号内，并在前面添加第一个数字：```python
1000/(100/10/2)
```该实现很简洁，因为数学证明消除了递归或动态编程的需要。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

func optimalDivision(nums []int) string {
	n := len(nums)

	if n == 1 {
		return strconv.Itoa(nums[0])
	}

	if n == 2 {
		return strconv.Itoa(nums[0]) + "/" + strconv.Itoa(nums[1])
	}

	parts := make([]string, 0, n-1)

	for _, num := range nums[1:] {
		parts = append(parts, strconv.Itoa(num))
	}

	denominator := strings.Join(parts, "/")

	return strconv.Itoa(nums[0]) + "/(" + denominator + ")"
}
```Go 解决方案密切反映了 Python 逻辑。 

由于Go不提供Python风格的字符串插值，我们使用`strconv.Itoa()`将整数转换为字符串。 

我们使用一段字符串来收集分母分量，然后将它们与`strings.Join()`。 

不存在溢出问题，因为我们从未实际计算数值结果。 我们只构造表达式字符串。

 ## 边缘情况

 一种非常重要的边缘情况是输入仅包含一个数字。 在这种情况下，根本没有除法运算符，因此添加括号是没有意义的。 有缺陷的实现可能会意外添加不必要的格式，例如`"5()"`或尝试连接不存在的分母元素。 该实现通过立即返回数字来干净地处理这个问题。 

当数组恰好包含两个数字时，会出现另一个关键边缘情况。 某些实现错误地添加括号并生成如下表达式`"8/(2)"`。 虽然数学上是正确的，但该问题明确禁止多余的括号。 该解决方案通过单独处理二元情况来避免这种情况。 

更微妙的边缘情况是确保分母包含一对括号内的所有剩余数字。 简单的实现可能只将部分后缀括起来，例如：```
1000/(100/10)/2
```这不会最小化分母，因此不会最大化结果。 该实现正确地将整个后缀分组在第一个数字之后。 

重复值是另一个有用的边缘情况，因为它们使视觉验证正确性变得更加困难。 例如：```
[2,2,2,2]
```该算法仍然有效，因为数学原理取决于运算结构，而不是不同的值。
