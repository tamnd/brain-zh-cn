[LeetCode 564 题](https://leetcode.com/problems/find-the-closest-palindrome/)

 **难度：** 🔴难
 **主题：** 数学、字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`n`代表一个正整数，并要求我们找到数值最接近且不等于原始数字本身的回文。 

回文是向前和向后读相同的数字。 例子包括`121`,`999`， 和`1331`。 

关键要求是我们最小化绝对差异：$$|candidate - original|$$如果两个回文数同样接近，我们必须返回较小的一个。 

输入以字符串而不是整数形式提供，因为该值可能非常大，最多可达$10^{18} - 1$。 这超出了某些语言中的安全整数范围，并且还暗示解决方案应该专注于数字操作而不是强力数字迭代。 

这些约束告诉我们一些重要的事情：

 - 长度`n`最多可为 18 位数字。 
- 该数字始终没有前导零。 
- 该数字始终有效且为正值。 

这些限制立即消除了任何一次向外搜索一个数字的方法。 在最坏的情况下，回文之间的差距可能非常大。 

一些边缘情况尤其重要：

 - 个位数的数字，例如`"1"`或者`"9"`- 像这样的数字`"10"`或者`"1000"`其中最接近的回文数字较少
 - 像这样的数字`"99"`或者`"999"`其中最接近的回文有更多的数字
 - 已经是回文的数字，因为我们无法返回数字本身
 - 两个回文数距离相等的平局情况

 例如：

 -`"1000"`有附近的回文`999`和`1001`，距离都是 1，所以我们返回`999`-`"1"`有附近的回文`0`和`2`，距离都是 1，所以我们返回`0`了解回文是如何形成的是有效解决这个问题的关键。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是从给定的数字开始反复向外查找。 

我们可以：

 1. 将输入字符串转换为整数。 
2. 检查`num - 1`,`num + 1`,`num - 2`,`num + 2`， 等等。 
3. 对于每个值，测试它是否是回文。 
4. 返回找到的第一个距离最小的回文。 

回文检查很简单，只需将数字转换为字符串并将其与相反的字符串进行比较即可。 

这种方法是正确的，因为最终我们会遇到最近的回文。 然而，对于给定的限制来说，它太慢了。 

考虑一个很大的 18 位数字。 回文之间的差距可能很大，并且一一重复检查数字变得不可行。 

### 最佳方法的关键见解

 回文完全由其前半部分决定。 

例如：

-`12321`是由`123`-`4554`是由`45`我们不需要搜索所有附近的整数，而只需要生成一小组看似合理的回文候选者。 

最近的回文必须来自以下类别之一：

 1.直接镜像当前上半场
 2. 加 1 后镜像前半部分
 3. 减1后镜像前半部分
 4.特殊边界回文：

 -`999...999`-`1000...0001`为什么这些有效？ 

因为改变远离中心的数字会导致更大的数字差异。 最近的回文几乎总是仅在中间数字附近有所不同。 

这将问题从搜索潜在的数十亿个数字减少到仅检查少数候选者。

-`d`是位数

 ## 算法演练

 ### 第 1 步：转换输入数字

 将输入字符串转换为整数，以便我们可以计算候选值与原始值之间的数值差异。 

我们仍然保留原始字符串，因为使用字符串进行数字操作更容易。 

### 步骤 2：生成边界候选

 有两个极其重要的边回文：

 1、少一位数字的最大回文数：$$10^{len(n)-1} - 1$$示例：

 -`999`-`99`-`9`1.多一位数的最小回文数：$$10^{len(n)} + 1$$示例：

 -`1001`-`10001`这些处理案例如下：

 -`"1000"`→ 最近的可能是`999`-`"999"`→ 最近的可能是`1001`如果没有这些特殊的候选人，许多边缘情况都会失败。 

### 步骤 3：提取前缀

 取数字的前半部分。 

对于多个长度`L`，前缀长度为：$$(L + 1) // 2$$示例：

 | 数量 | 前缀 |
 | --- | --- |
 | 12345 | 123 | 123
 | 4567 | 4567 45 | 45

 前缀包含足够的信息来重建回文。 

### 步骤 4：创建附近的前缀变体

 生成三个前缀：

 -`prefix - 1`-`prefix`-`prefix + 1`这些代表了唯一真实的附近回文结构。 

例如：

 - 原文：`12345`- 前缀：`123`- 候选者来自：

 -`122`-`123`-`124`### 步骤 5：镜像每个前缀

 通过镜像前缀构造回文。 

对于奇数长度的数字：

 - 镜像除最后一位数字之外的所有内容

 示例：

 - 前缀`123`- 结果`12321`对于偶数长度的数字：

 - 镜像整个前缀

 示例：

 - 前缀`45`- 结果`4554`### 步骤 6：删除原始号码

 如果输入本身是回文，它可能会出现在候选集中。 我们必须排除它，因为该问题明确禁止返回原始数字。 

### 第 7 步：选择最佳候选人

 在所有候选人中：

 1. 选择绝对差最小的一个
 2. 如果有平局，则选择较小的值

 这完全符合问题的定义。 

### 为什么它有效

 最近的回文必须保留原始数字的大部分前导数字。 左侧的大变化比中心附近的小变化产生更大的数值差异。 

通过镜像当前前缀及其直接邻居，我们覆盖了所有可能的最接近的回文结构。 两个额外的候选边界处理数字长度转换，例如`999`和`1000`。 

因为每个可能的最接近的回文都包含在这个小的候选集中，所以选择最小差异可以保证正确性。 

## Python 解决方案```python
class Solution:
    def nearestPalindromic(self, n: str) -> str:
        length = len(n)
        original = int(n)

        candidates = set()

        # Edge case candidates
        candidates.add(10 ** (length - 1) - 1)
        candidates.add(10 ** length + 1)

        # First half of the number
        prefix_length = (length + 1) // 2
        prefix = int(n[:prefix_length])

        # Generate palindromes from prefix - 1, prefix, prefix + 1
        for delta in (-1, 0, 1):
            new_prefix = str(prefix + delta)

            if length % 2 == 0:
                palindrome = new_prefix + new_prefix[::-1]
            else:
                palindrome = new_prefix + new_prefix[:-1][::-1]

            candidates.add(int(palindrome))

        # Remove the original number itself
        candidates.discard(original)

        best = None

        for candidate in candidates:
            difference = abs(candidate - original)

            if best is None:
                best = candidate
            else:
                best_difference = abs(best - original)

                if difference < best_difference:
                    best = candidate
                elif difference == best_difference and candidate < best:
                    best = candidate

        return str(best)
```实现首先确定输入的长度并将原始数字转换为整数以进行算术比较。 

集合用于候选存储，因为多个构造路径可以生成相同的回文。 使用集合会自动删除重复项。 

首先插入两个候选边界。 这些对于处理数字计数转换至关重要。 

接下来，代码提取确定回文结构的前缀。 表达式`(length + 1) // 2`确保奇数长度的数字包含前缀中的中间数字。 

循环结束`(-1, 0, 1)`创建附近的前缀。 每个前缀的镜像方式不同，具体取决于号码长度是偶数还是奇数。 

对于偶数长度，整个前缀都会被镜像。 

对于奇数长度，镜像过程中会跳过最后一位数字，以避免重复中心数字。 

生成所有候选后，原始编号将被删除，因为它无法返回。 

最后，该算法扫描所有候选者并使用问题的比较规则选择最好的一个：

 - 绝对差值越小获胜
 - 如果平局，较小的数值获胜

 ## 解决方案```go
package main

import (
	"math"
	"strconv"
)

func nearestPalindromic(n string) string {
	length := len(n)

	original, _ := strconv.ParseInt(n, 10, 64)

	candidates := make(map[int64]bool)

	// Edge candidates
	candidates[int64(math.Pow10(length-1))-1] = true
	candidates[int64(math.Pow10(length))+1] = true

	prefixLength := (length + 1) / 2
	prefix, _ := strconv.ParseInt(n[:prefixLength], 10, 64)

	for _, delta := range []int64{-1, 0, 1} {
		newPrefix := strconv.FormatInt(prefix+delta, 10)

		var palindrome string

		if length%2 == 0 {
			palindrome = newPrefix + reverse(newPrefix)
		} else {
			palindrome = newPrefix + reverse(newPrefix[:len(newPrefix)-1])
		}

		value, _ := strconv.ParseInt(palindrome, 10, 64)
		candidates[value] = true
	}

	delete(candidates, original)

	var best int64 = -1

	for candidate := range candidates {
		diff := abs(candidate - original)

		if best == -1 {
			best = candidate
			continue
		}

		bestDiff := abs(best - original)

		if diff < bestDiff ||
			(diff == bestDiff && candidate < best) {
			best = candidate
		}
	}

	return strconv.FormatInt(best, 10)
}

func reverse(s string) string {
	runes := []rune(s)

	left := 0
	right := len(runes) - 1

	for left < right {
		runes[left], runes[right] = runes[right], runes[left]
		left++
		right--
	}

	return string(runes)
}

func abs(x int64) int64 {
	if x < 0 {
		return -x
	}
	return x
}
```Go 实现遵循与 Python 版本相同的逻辑，但有一些特定于语言的细节值得注意。 

Go没有内置的字符串反转操作，因此需要手动实现辅助函数。 

该解决方案使用`int64`because the input range fits safely within signed 64 bit integers.

 一个`map[int64]bool`is used instead of a set, since Go does not provide a native set type.

 The palindrome construction logic is identical to the Python version, including separate handling for even and odd lengths.

 ## 边缘情况

 ### 十个输入的幂

 像这样的数字`"10"`,`"100"`， 和`"1000"`特别棘手，因为最近的回文可能有更少的数字。 

例如：

-`"1000"`有最近的回文`999`和`1001`- 两者距离均为 1
 - 较小的必须退回

 幼稚的镜像方法常常会错过`999`。 此实现通过显式包含以下内容来处理它：$$10^{length-1} - 1$$作为候选人。 

### 全九输入

 数字如`"9"`,`"99"`， 和`"999"`需要转换到更大的位数。 

例如：

-`"999"`→ 最近的回文是`1001`简单地镜像前缀无法产生此结果。 该实现使用显式边界候选解决了这个问题：$$10^{length} + 1$$### 输入已经是回文

例如：

-`"121"`自然生成候选`121`然而，问题明确表明我们无法返回原始数字本身。 

该实现使用以下方法安全地处理此问题：```

```这保证了返回的回文与输入不同。

```这可确保根据规范正确解决关系。
