[LeetCode 第 578 题](https://leetcode.com/problems/get-highest-answer-rate-question/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们分析存储在`SurveyLog`表并确定哪个问题的回答率最高。 

该表记录了用户在调查会话期间执行的操作。 每一行代表与问题的一次交互。 此问题的重要列是：

 | 专栏 | 意义|
 | --- | --- |
 |`question_id`| 正在互动的问题 |
 |`action`| 交互类型`"show"`,`"answer"`， 或者`"skip"`|

 问题的回答率定义为：$\text{Answer Rate} = \frac{\text{Number of answer actions}}{\text{Number of show actions}}$任务是计算每个问题的比率并返回`question_id`具有最高的价值。 

如果多个问题的最大回答率相同，我们必须返回最小的`question_id`。 

输入由可能包含重复行的数据库表组成。 这个细节很重要，因为仍然应该计算重复项。 如果相同的交互出现多次，则每次出现都会对计数产生影响。 

预期输出是包含具有最佳答案率的问题的单行。 

一些重要的观察立即脱颖而出：

 一个问题可能会出现多次，但只回答几次。 在这种情况下，其回答率将小于 1。 

如果数据集格式错误，理论上问题可以有答案操作而没有相应的显示操作，但问题隐含地假设有效的调查日志。 在实践中，每个答案都应该对应于所显示的问题。 

回答率相同的问题需要仔细打破平局。 简单地按速率降序排序的简单实现可能会忘记按`question_id`上升为次要条件。 

由于这是一个数据库聚合问题，因此核心挑战是按以下方式有效地对行进行分组：`question_id`并计算条件计数。 

## 方法

 ### 蛮力方法

 暴力解决方案将处理每个不同的`question_id`独立。 

对于每个问题，我们都会扫描整个表格并进行计数：

 - 有多少行`action = 'show'`- 有多少行`action = 'answer'`然后我们将计算比率并跟踪最佳问题。 

这种方法是正确的，因为每个问题的回答率都是直接根据完整数据集计算的。 然而，它的效率很低，因为每个问题都会重复地重新扫描表。 

如果有`n`行和`k`独特的问题，这成为`O(n * k)`解决方案。 在最坏的情况下，每行都属于不同的问题，复杂性接近`O(n²)`。 

这种重复扫描使得暴力方法变得不必要地昂贵。 

### 最佳方法

 关键的见解是所有必需的统计数据都可以在单个分组聚合中计算。 

我们不是多次扫描表，而是按以下方式对行进行分组`question_id`并计算：

 - 总数`"answer"`行动
 - 总数`"show"`行动

 使用具有条件计数的 SQL 聚合函数使我们能够在一次遍历分组数据的过程中同时计算这两个值。 

计算出每个问题的回答率后，我们进行排序：

 1.按回答率递减
 2. 通过`question_id`上升

 排序后的第一行是正确答案。 

这种方法非常有效，因为分组可以在一次操作中合并每个问题的所有相关信息。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描表格中的每个问题 |
 | 最佳 | O(n log n) | O(n log n) | O(k) | 使用分组和排序来有效计算所有费率 |

 在大多数 SQL 实现中，排序步骤在复杂性上占主导地位。 聚合本身是线性的。 

## 算法演练

 1. 对所有行进行分组`question_id`。 

这确保了属于同一问题的所有交互都被一起处理。 由于回答率是按问题计算的，因此分组是计算的自然结构。 
2. 数数`"answer"`每个问题的行动。 

我们使用条件聚合表达式，例如：```
SUM(action = 'answer')
```或同等的`CASE WHEN`表达式取决于 SQL 方言。 
3. 数一下数量`"show"`每个问题的行动。 

这提供了答案率公式的分母。 
4. 计算回答率。 

费率为：$\frac{\text{answer count}}{\text{show count}}$如果至少有一个操作数被视为非整数，SQL 会自动处理浮点除法。 
5. 对所有分组的问题进行排序。 

订购标准为：

 - 回答率最高的优先
 - 最小的`question_id`首先当利率平局时
 6. 仅返回第一行。 

由于行是根据所需条件排序的，因此顶行是正确的结果。 

### 为什么它有效

 该算法之所以有效，是因为每个问题的回答率仅取决于两个聚合值：总回答数和总显示数。 

分组依据`question_id`保证所有相关行都被一起考虑。 条件聚合仅正确计算所需的操作类型。 按计算的速率排序可确保最大速率首先出现，而二次排序则按`question_id`正确解决关系。 

因此，算法总是返回所需的问题。 

## Python 解决方案

 尽管这本质上是一个 SQL 问题，但 LeetCode 数据库问题是通过编写 SQL 查询来解决的。 下面是根据要求在 Python 块内格式化的正确 SQL 解决方案。```python
SELECT
    question_id AS survey_log
FROM SurveyLog
GROUP BY question_id
ORDER BY
    SUM(action = 'answer') / SUM(action = 'show') DESC,
    question_id ASC
LIMIT 1;
```查询首先根据以下条件对所有记录进行分组`question_id`。 这允许数据库引擎单独聚合每个问题的统计信息。 

表达式：```python
SUM(action = 'answer')
```计算问题发生的回答次数，因为布尔表达式的计算结果为`1`对于真实和`0`MySQL 中为 false。 

相似地：```python
SUM(action = 'show')
```计算显示操作的数量。 

将这两个值相除即可得出答案率。 

这`ORDER BY`子句首先按回答率降序排序，因此最高的回答率首先出现。 然后它排序`question_id`上升以满足打破平局的要求。 

最后，`LIMIT 1`确保只返回最好的问题。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 聚合是线性的，排序分组结果占主导地位 |
 | 空间| O(k) | 存储 k 个独特问题的分组聚合 |

 数据库在分组期间扫描所有行一次，这需要相对于记录数呈线性时间。 

聚合后，对分组结果进行排序。 如果有`k`独特的问题，分类成本`O(k log k)`时间。 

数据库引擎还存储每个不同问题的聚合信息，这需要`O(k)`额外的空间。

 ## 边缘情况

 ### 多个问题的回答率相同

 这是最重要的边缘情况之一，因为许多错误的解决方案仅按答案率排序，而忘记了打破平局的规则。 

例如，如果有问题`1`和`2`两者的回答率均为`1.0`，正确答案一定是`1`因为它有较小的`question_id`。 

该实现通过添加以下内容来正确处理此问题：```
question_id ASC
```作为二次排序条件。 

### 从未得到解答的问题

 一个问题可能会出现多次但从未得到回答。 在这种情况下，答案计数为零，答案率变为`0`。 

有缺陷的实现可能会意外地除以错误的计数或完全排除此类问题。 

聚合逻辑正确地计算了零答案，并且仍然计算有效率。 

### 重复行

 该问题明确指出可能存在重复行。 

一个常见的错误是在处理之前尝试删除重复项。 这会产生不正确的计数，因为重复项会计入总数。 

该解决方案完全避免了重复数据删除，并精确地按照表中显示的方式对每一行进行计数。
