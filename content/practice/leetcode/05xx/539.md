[LeetCode 第 539 题](https://leetcode.com/problems/minimum-time-difference/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、字符串、排序

 ## 解决方案

 ## 问题理解

 该问题给出了 **24 小时制格式 ** 的时间点列表，其中每个时间都表示为以下形式的字符串`"HH:MM"`。 您的任务是确定列表中任意两个时间点之间的**最小差异（以分钟为单位）。 

一个关键细节是时间是**循环**的，这意味着时钟在午夜绕行。 例如，之间的区别`"23:59"`和`"00:00"`不是`1439`分钟，就是`1`分钟，因为时钟在午夜后重置。 这种环绕行为是问题最重要的方面之一。 

输入由字符串数组组成，其中每个字符串代表一个有效时间。 输出是一个整数，表示任意两个时间点之间间隔的最小分钟数。 

约束条件很重要：

 -`2 <= timePoints.length <= 2 * 10^4`- 每次字符串都保证在`"HH:MM"`格式。 

输入的数量可以多达 **20,000**，这意味着每对的简单比较会变得昂贵。 因为一天只有 **1440 分钟**（`24 * 60`），这个观察可以帮助我们优化。 

有几个重要的边缘情况：

 1. **重复时间点**

 如果同一时间出现多次，则立即给出答案`0`，因为相同时间之间的差异为零。 
2. **午夜环绕**

 简单的排序比较可能会错过类似的情况`"23:59"`和`"00:00"`，最小的差异跨越午夜。 
3. **最小输入尺寸**

 当只存在两个时间点时，我们仍然必须正确考虑循环时间。 
4. **具有重复值的大输入量**

 由于只有 1440 个不同时间，但条目多达 20,000 个，因此很可能出现重复。 根据鸽巢原理，如果`len(timePoints) > 1440`，答案一定是`0`。 

## 方法

 ### 蛮力方法

 解决这个问题最简单的方法就是比较**每对时间点**。 

首先，转换每个`"HH:MM"`字符串为从午夜开始的总分钟数。 例如：

-`"01:30"`→`90`-`"23:59"`→`1439`然后，对于每一对`(i, j)`，计算以分钟为单位的绝对差异。 由于时钟绕行，我们还必须考虑循环差：$$\text{difference} = \min(|a - b|, 1440 - |a - b|)$$我们记录遇到的最小差异。 

这种方法是正确的，因为它显式地检查每个可能的对，保证找到最小的差异。 然而，对于大输入来说它太慢了，因为比较每对都需要平方时间。 

高达`20,000`时间点：$$O(n^2) = 400,000,000$$在最坏的情况下进行操作，这是不切实际的。 

### 最佳方法

 关键的观察结果是，将时间转换为分钟后，**排序**使问题变得更加容易。 

如果对数字进行排序，任何两个值之间的最小差异必须出现在**相邻元素**之间。 这是排序序列的基本属性。 

例如：```
["23:59", "00:00", "12:30"]
```转换为分钟：```
[1439, 0, 750]
```种类：```
[0, 750, 1439]
```现在我们只比较相邻值：

 -`750 - 0 = 750`-`1439 - 750 = 689`但我们仍然需要处理循环环绕：```
(1440 - 1439) + 0 = 1
```所以最小值是`1`。 

这大大减少了工作量，因为分拣成本`O(n log n)`以及相邻扫描成本`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 转换时间并比较每对 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 对分钟进行排序并比较相邻时间以及总结 |

 ## 算法演练

 ### 最优算法

 1. **处理重复的快捷方式**

 由于只有`1440`一天中唯一的分钟值，如果时间点的数量超过`1440`，必须存在重复项。 在这种情况下，返回`0`立即地。 
2. **将所有时间字符串转换为分钟**

 对于每个时间字符串：

 - 分为小时和分钟
 - 转换为整数
 - 计算：```
total_minutes = hours * 60 + minutes
```这提供了更容易排序和比较的数字表示形式。 
3. **对分钟数组进行排序**

 排序将所有时间点按时间顺序排列。 

一旦排序，相邻元素之间必须存在任意两个非回绕时间之间的最小差异。 
4. **比较相邻元素**

 迭代排序后的数组并计算：```
difference = current - previous
```跟踪迄今为止看到的最小差异。 
5. **处理午夜循环案件**

 比较第一次和最后一次：```
wrap_difference = 1440 - last + first
```这捕获了最短间隙跨越午夜的情况。 
6. **返回最小差异**

 检查相邻对和环绕对后，返回找到的最小值。 

### 为什么它有效

 排序后，每个时间点最接近的最小差异候选点必须是其邻居之一。 如果非相邻元素之间的差异较小，那么它们之间的某些相邻元素之间的差异必然更小，这是一个矛盾。 

唯一缺少的比较是最后一个元素和第一个元素之间的循环连接，因为时钟在午夜绕行。 包括这个最终比较可以保证考虑每个相关的对。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMinDifference(self, timePoints: List[str]) -> int:
        # Pigeonhole principle: more than 1440 times means duplicates
        if len(timePoints) > 1440:
            return 0

        minutes = []

        for time_point in timePoints:
            hours, mins = map(int, time_point.split(":"))
            total_minutes = hours * 60 + mins
            minutes.append(total_minutes)

        minutes.sort()

        minimum_difference = float("inf")

        for index in range(1, len(minutes)):
            difference = minutes[index] - minutes[index - 1]
            minimum_difference = min(minimum_difference, difference)

        wraparound_difference = (
            1440 - minutes[-1] + minutes[0]
        )

        minimum_difference = min(
            minimum_difference,
            wraparound_difference
        )

        return minimum_difference
```实施首先基于鸽巢原理进行优化。 由于只有`1440`一天中唯一的分钟值，任何大于此的输入都必须包含重复项，这保证了最小差异`0`。 

接下来，每个时间字符串都会转换为从午夜开始的总分钟数。 这简化了比较，因为使用整数比操作时间字符串更容易。 

然后对分钟列表进行排序。 排序后，我们扫描相邻元素并计算它们的差异，每当发现更小的间隙时更新运行最小值。 

最后，该实现显式检查最后一个时间值和第一个时间值之间的循环差异，以考虑午夜环绕。 返回最小的计算值。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
	"strings"
)

func findMinDifference(timePoints []string) int {
	// Pigeonhole principle
	if len(timePoints) > 1440 {
		return 0
	}

	minutes := make([]int, 0, len(timePoints))

	for _, timePoint := range timePoints {
		parts := strings.Split(timePoint, ":")

		hours, _ := strconv.Atoi(parts[0])
		mins, _ := strconv.Atoi(parts[1])

		totalMinutes := hours*60 + mins
		minutes = append(minutes, totalMinutes)
	}

	sort.Ints(minutes)

	minDifference := 1 << 30

	for i := 1; i < len(minutes); i++ {
		difference := minutes[i] - minutes[i-1]

		if difference < minDifference {
			minDifference = difference
		}
	}

	wraparoundDifference := 1440 - minutes[len(minutes)-1] + minutes[0]

	if wraparoundDifference < minDifference {
		minDifference = wraparoundDifference
	}

	return minDifference
}
```Go 实现遵循与 Python 版本相同的逻辑。 时间字符串的分割使用`strings.Split`，并且数值转换是用`strconv.Atoi`。 

与Python不同`float("inf")`, Go 使用一个非常大的整数 (`1 << 30`) 作为初始最小值。 由于最大可能的差异仅为`1440`，这比任何有效答案都大。 

Go 切片的大小是动态调整的，因此我们使用等于输入长度的容量来初始化切片，以减少重新分配。

 ## 边缘情况

 ### 重复时间点

 错误的一个常见来源是忘记可以存在相同的时间点。 如果`"00:00"`出现两次，最小差异立即`0`。 该实现自然会在排序后处理此问题，因为重复项会变得相邻，从而产生以下差异`0`。 此外，当输入大小超过时，鸽巢优化可以捕获保证的重复项`1440`。 

### 午夜环绕

 最小的差异可能发生在午夜，而不是相邻的排序值之间。 例如，`"23:59"`和`"00:00"`在数值上显得相距很远（`1439`和`0`）但实际上时钟上的时间间隔只有一分钟。 该实现使用以下方式显式处理此问题：```
1440 - last + first
```它正确地模拟了循环时间。 

### 最小输入大小

 当只有两个时间点时，排序后只有一个相邻的比较。 粗心的实现可能会忘记单独检查环绕，从而导致以下情况的错误结果：`"23:59"`和`"00:00"`。 此实现始终执行循环比较，即使对于最小的有效输入大小也能确保正确性。
