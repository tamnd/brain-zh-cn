[LeetCode 538 题](https://leetcode.com/problems/convert-bst-to-greater-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们将二叉搜索树（Binary Search Tree，缩写为BST）转变为“更大的树”。 在转换后的树中，每个节点的值应变为：

 - 它的原始值
 - 加上原始 BST 中所有大于它的值的总和

 树的结构没有改变。 仅更新节点值。 

二叉搜索树有一个重要的排序属性：

 - 左子树中的每个值都小于当前节点
 - 右子树中的每个值都大于当前节点

 这种排序是实现有效解决方案的关键观察结果。 

例如，考虑这个 BST：```
        4
      /   \
     1     6
```节点`4`应该变成：```
4 + 6 = 10
```因为`6`大于`4`。 

节点`1`应该变成：```
1 + 4 + 6 = 11
```因为两者`4`和`6`大于`1`。 

节点`6`遗迹`6`因为没有更大的值。 

输入是 BST 的根，预期输出是所有节点值更新后的同一棵树。 

这些约束告诉我们一些重要的事情：

 - 树最多可以包含`10^4`节点。 
- 节点值可能为负。 
- 所有值都是唯一的。 
- 输入保证是有效的 BST。 

因为树可能相当大，所以我们应该避免比以下更糟糕的算法`O(n log n)`如果可能的话。 由于每个节点必须至少被访问一次，因此`O(n)`解决方案是理想的。 

一些边缘情况很重要：

 - 一棵空树，`root = None`- 一棵只有一个节点的树
 - 完全倾斜的树，其行为类似于链表
 - 包含负值的树
 - 所有较大值都集中在一侧的树

 BST 保证尤其重要，因为最优解完全取决于 BST 排序属性。 

## 方法

 ### 蛮力方法

 一种简单的方法是独立处理每个节点。 

对于每个节点：

 1. 遍历整棵树。 
2. 查找所有值大于当前节点的节点。 
3. 计算它们的总和。 
4. 将该总和添加到当前节点。 

这是有效的，因为每个节点都会显式计算大于其自身的精确值。 

然而，效率低下是显而易见的。 如果树包含`n`节点：

 - 我们处理`n`节点
 - 对于每个节点，我们可能扫描所有`n`再次节点

 这导致`O(n^2)`时间复杂度。 

高达`10^4`节点，这可能会变得太慢。 

### 最佳解决方案的关键见解

 BST 属性自动为我们提供排序顺序。 

在正常的中序遍历中：```
Left -> Node -> Right
```BST 值按升序访问。 

对于这个问题，我们需要所有较大值的总和。 这意味着我们应该从最大到最小处理节点。 

我们可以使用逆序遍历来实现这一点：```
Right -> Node -> Left
```这按降序访问节点。 

穿越时：

 - 维护所有先前访问过的节点的运行总和
 - 由于遍历是递减的，所以之前访问过的节点都更大
 - 使用运行总和更新当前节点

 这会在一次遍历中转换树。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 对于每个节点，再次遍历树以计算更大的总和 |
 | 最佳| O(n) | O(h) | 逆序遍历按降序处理节点 |

 这里，`h`代表树的高度。 

## 算法演练

 ### 最优算法：逆序遍历

 1. 初始化一个名为`running_sum`到`0`。 

该变量存储遍历期间已访问的所有节点值的总和。 由于我们从最大到最小遍历，它总是代表较大值的总和。 
2. 开始逆中序遍历。 

而不是通常的中序遍历：```
Left -> Node -> Right
```我们使用：```
Right -> Node -> Left
```这保证了按降序访问节点。 
3. 先递归访问右子树。 

右子树包含较大的值，因此必须在当前节点之前处理这些节点。 
4. 更新当前节点。 

访问节点时：

 - 将其原始值添加到`running_sum`- 用更新后的值替换节点的值`running_sum`例子：```
running_sum = 15
current node = 6

running_sum = 21
node.val = 21
```5. 递归访问左子树。 

左子树包含较小的值，因此这些节点应使用更新后的运行总和。 
6. 继续，直到处理完所有节点。 
7. 返回修改后的树的根。 

### 为什么它有效

 正确性取决于逆序遍历按降序访问 BST 节点。 

在任意节点：

 - 每个先前访问过的节点都有较大的值
 -`running_sum`因此等于所有较大值的总和
 - 添加当前节点的值产生所需的更大树值

 因为每个节点都按正确的顺序处理一次，所以转换是正确的。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def convertBST(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        running_sum = 0

        def reverse_inorder(node: Optional[TreeNode]) -> None:
            nonlocal running_sum

            if not node:
                return

            reverse_inorder(node.right)

            running_sum += node.val
            node.val = running_sum

            reverse_inorder(node.left)

        reverse_inorder(root)

        return root
```该实现使用了一个名为的嵌套辅助函数`reverse_inorder`。 

变量`running_sum`在助手外部声明，因此它可以在递归调用中持续存在。 这`nonlocal`关键字允许嵌套函数修改它。 

遍历从右子树开始，因为必须首先处理较大的值。 

当一个节点被访问时：```python
running_sum += node.val
node.val = running_sum
```这使用所有较大值的总和加上其自己的原始值来更新节点。 

最后，遍历进入左子树，以便较小的节点接收更新的累积和。 

该函数就地修改树并返回原始根引用。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func convertBST(root *TreeNode) *TreeNode {
    runningSum := 0

    var reverseInorder func(node *TreeNode)

    reverseInorder = func(node *TreeNode) {
        if node == nil {
            return
        }

        reverseInorder(node.Right)

        runningSum += node.Val
        node.Val = runningSum

        reverseInorder(node.Left)
    }

    reverseInorder(root)

    return root
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

而不是使用`nonlocal`, Go 闭包自动从周围范围捕获变量，所以`runningSum`可以直接在递归函数内更新。 

基本情况检查`nil`递归之前的指针。 

由于 Go 将指针传递给树节点，因此修改`node.Val`直接更新原始树。 

整数溢出不是问题，因为约束仍然在 Go 的标准整数范围内。

 ## 边缘情况

 ### 空树

 一棵空树表示为`root = None`。 幼稚的实现可能会尝试递归或取消引用属性而不检查空引用。 

该实现可以安全地处理这个问题，因为递归助手在遇到`None`。 

### 单节点树

 仅包含一个节点的树没有更大的值。 正确的结果是节点保持不变。 

该算法自然地处理这个问题，因为运行总和从零开始，并且节点简单地变为：```
0 + original_value
```等于其原始值。 

### 完全倾斜的树

 BST 可能完全左偏或右偏，实际上表现得像链表。 

这些案例很重要，因为：

 - 递归深度变为`O(n)`- 遍历顺序变得严格线性

 该实现仍然可以正常工作，因为即使在倾斜结构中，反向中序遍历也保留降序。 

### 具有负值的树

 由于节点值可能为负，因此错误地假设正和的实现可能会失败。 

例如：```
    0
   / \
 -1   2
```节点`-1`应该变成：```
-1 + 0 + 2 = 1
```该算法可以正确处理此问题，因为它仅依赖于 BST 排序，而不依赖于正性假设。
