 ## 解决方案

 ## 问题理解

 这个问题要求我们计算`n`第一个斐波那契数列。 

斐波那契数列是递归定义的。 前两个数字是固定的：```
F(0) = 0
F(1) = 1
```之后的每个值都计算为前两个值的总和：```
F(n) = F(n - 1) + F(n - 2)
```给定一个整数`n`，我们必须返回值`F(n)`。 

换句话说，输入表示斐波那契数列中的位置，输出是存储在该位置的数字。 

例如：

-`n = 2`意味着我们想要第三个斐波那契数：`F(2) = F(1) + F(0) = 1 + 0 = 1`-`n = 4`方法：`F(4) = F(3) + F(2) = 2 + 1 = 3`限制非常小：```
0 <= n <= 30
```这告诉我们有关该问题的几个重要信息：

 - 最大输入大小很小，因此即使较慢的解决方案仍可能通过。 
- 自从`n`永远不会超过`30`，递归深度并不危险。 
- 整数溢出不是问题，因为斐波那契值在此范围内仍然很小。 

然而，仍然存在效率方面的考虑。 简单的递归解决方案会多次重新计算相同的子问题，从而导致不必要的昂贵。 

一些边缘情况很重要：

 -`n = 0`，我们必须返回`0`立即地。 
-`n = 1`，我们必须返回`1`。 
- 小值，例如`n = 2`是很容易出现差一错误的地方。 
- 没有记忆的递归实现可能会重复计算相同的值，从而导致性能不佳。 

该问题保证了有效输入，因此我们不需要处理负数或无效类型。 

## 方法

 ### 蛮力方法，简单递归

 最直接的解决方案直接遵循斐波那契定义。 

计算`F(n)`，我们递归计算：```
F(n - 1) + F(n - 2)
```这准确地反映了数学公式。 例如：```
F(5)
= F(4) + F(3)
= (F(3) + F(2)) + (F(2) + F(1))
```问题是许多值被重复重新计算。 例如，`F(3)`可以在同一递归树期间多次计算。 

尽管这种蛮力方法是正确的，因为它直接实现了递归关系，但由于子问题重叠，效率很低。 

由于递归树反复分支，时间复杂度呈指数增长。 

### 最优方法，迭代动态规划

 关键的观察是每个斐波那契数仅取决于前两个数。 

我们可以迭代地构建序列，而不是重复地重新计算早期值。 

在任何时候，我们只需要：

 - 之前的斐波那契数
 - 之前的斐波那契数

 这意味着我们不需要数组或递归。 我们可以只保留两个变量并在前进时更新它们。 

例如：```
0, 1 → 1 → 2 → 3 → 5
```每个新数字都是根据前两个数字计算得出的。 

这将解决方案从指数时间转换为线性时间，同时还将空间使用量减少到恒定内存。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2ⁿ) | O(n) | 递归解决方案重复重新计算相同的斐波那契值 |
 | 最佳| O(n) | O(1) | O(1) | 仅使用两个变量的迭代动态规划 |

 ## 算法演练

 1. 首先处理基本情况。 

如果`n`是`0`， 返回`0`。 如果`n`是`1`， 返回`1`。 

这些情况是必要的，因为斐波那契数列明确定义了它们，并且它们防止了不必要的迭代。 
2. 初始化两个变量。 

我们维持：

 -`prev2 = 0`，代表`F(0)`-`prev1 = 1`，代表`F(1)`这些值充当我们计算的滚动状态。 
3. 迭代自`2`通过`n`。 

在每一步中，计算下一个斐波那契数：```
current = prev1 + prev2
```这完全遵循斐波那契递推规律。 
4. 将变量前移。 

计算新的斐波那契数后：```
prev2 = prev1
prev1 = current
```这确保下一次迭代始终可以访问两个最新的斐波那契值。 
5. 返回最终结果。 

完成循环后，`prev1`包含`F(n)`。 

### 为什么它有效

 该算法在整个执行过程中保持不变：```
prev2 = F(i - 2)
prev1 = F(i - 1)
```在每次迭代之前，这些变量始终代表前两个斐波那契数。 由于斐波那契数被定义为前面两个数字的总和，因此计算：```
current = prev1 + prev2
```正确产生`F(i)`。 更新变量可以保留下一次迭代的不变量。 通过归纳，算法正确计算`F(n)`。 

## Python 解决方案```python
class Solution:
    def fib(self, n: int) -> int:
        if n == 0:
            return 0

        if n == 1:
            return 1

        prev2 = 0
        prev1 = 1

        for _ in range(2, n + 1):
            current = prev1 + prev2
            prev2 = prev1
            prev1 = current

        return prev1
```此实现首先直接处理两个基本情况。 自从`F(0)`和`F(1)`是预定义的，立即返回可以避免不必要的工作。 

之后，两个变量被初始化。`prev2`商店`F(0)`和`prev1`商店`F(1)`。 

循环运行自`2`到`n`，包含在内。 在每次迭代期间，`current`计算为前两个斐波那契数之和。 然后变量向前移动，以便它们继续代表最新的两个斐波那契值。 

一旦循环结束，`prev1`包含答案并返回。 

这种实现非常高效，因为它避免了递归并且仅存储所需的最少信息。 

## 解决方案```go
func fib(n int) int {
    if n == 0 {
        return 0
    }

    if n == 1 {
        return 1
    }

    prev2 := 0
    prev1 := 1

    for i := 2; i <= n; i++ {
        current := prev1 + prev2
        prev2 = prev1
        prev1 = current
    }

    return prev1
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 使用显式变量声明，因此我们用以下命令初始化整数`:=`。 

这个问题不用担心整数溢出，因为`n <= 30`，因此斐波那契值仍然在 Go 的范围内`int`范围。 

与 Python 不同，Go 没有类，因此该解决方案是作为与所需 LeetCode 签名匹配的独立函数来实现的。

 ## 边缘情况

 ###`n = 0`这是最小的有效输入，也是容易出现错误的来源。 一些实现意外地立即开始迭代或假设斐波那契开始于`1`。 

我们的实现明确检查：```
if n == 0:
    return 0
```这样就保证了正确的结果而不进入循环。 

###`n = 1`第二个基本情况也可能被错误处理，特别是如果循环从`2`而不先检查较小的值。 

我们的实现单独处理这个问题：```
if n == 1:
    return 1
```这确保了正确性并避免了不必要的计算。 

### 非常小的输入，例如`n = 2`小输入通常会因循环中的一个错误而暴露出来。 

例如，如果循环范围不正确，算法可能会执行太多或太少的迭代。 

我们的循环运行：```
range(2, n + 1)
```这保证了对于`n = 2`，循环只执行一次，产生：```
F(2) = 1
```正确。
