[LeetCode 问题 501](https://leetcode.com/problems/find-mode-in-binary-search-tree/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们在二叉搜索树（BST）中找到**模式**。 模式是树中**最频繁**出现的值。 由于此 BST 定义中允许重复，因此一个值可能会出现多次。 

输入是`root`BST 的节点。 每个节点都包含一个整数值和指向左子节点和右子节点的指针。 因为该树是 BST，所以左子树中的值小于或等于当前节点的值，右子树中的值大于或等于当前节点的值。 

预期输出是一个整数列表，表示出现频率最高的所有值。 如果多个值与最大计数相关，我们将按任意顺序返回所有值。 

约束告诉我们树包含`1`和`10^4`节点。 由于树木大小相对适中，`O(n)`遍历是完全可行的。 然而，比线性时间更糟糕的解决方案会变得不必要的低效。 

BST 性质在这里尤为重要。 由于 BST 的中序遍历会按排序顺序生成值，因此重复项将连续出现。 这意味着我们可以在不使用哈希映射的情况下计算重复值。 

有几种边缘情况值得考虑：

 - 一棵只有一个节点的树，其中该值必须是众数。 
- 每个值都是唯一的树，这意味着每个值都出现一次并且所有值都是众数。 
- 多个值与最高频率相关的树。 
- 所有节点都包含相同值的树。 
- 类似于链表的深度倾斜的树。 

该问题还包括后续询问我们是否可以在没有额外空间（不包括递归堆栈空间）的情况下解决它。 这强烈暗示我们应该利用 BST 排序而不是使用频率图。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是遍历树并使用哈希图计算每个值的频率。 

我们可以执行 DFS 遍历并维护一个字典，其中键是节点值，值是出现次数。 遍历之后，我们扫描字典以找到最大频率并收集具有该计数的所有键。 

这是有效的，因为每个节点都被访问一次，并且频率图准确地记录了发生的次数。 

但是，此方法使用与树中唯一值的数量成比例的额外内存。 由于 BST 属性在中序遍历期间为我们提供了排序顺序，因此我们可以做得更好并避免存储所有频率。 

### 最佳方法

 关键的观察结果是 **BST 的中序遍历按排序顺序访问节点**。 

因为重复值连续出现，所以我们只需要跟踪：

 - 之前访问过的值
 - 当前的连胜次数
 - 迄今为止看到的最高频率
 - 模式列表

 当我们遍历时：

 - 如果当前值与前一个值匹配，则增加计数。 
- 否则，将计数重置为`1`。 
- 如果计数超过最大频率，则更新模式列表。 
- 如果计数等于最大频率，则附加该值。 

这完全避免了哈希映射，并且只需要跟踪一些变量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | DFS 遍历与哈希图频率计数 |
 | 最佳| O(n) | O(h) | 使用 BST 排序进行中序遍历，其中`h`是树高 |

 最佳解决方案仅使用递归堆栈空间。 在平衡 BST 中，这是`O(log n)`，而在倾斜树的最坏情况下，它会变成`O(n)`。 

## 算法演练

 1. 初始化跟踪变量。 

我们保留：

 -`previous_value`记住最后看到的节点值。 
-`current_count`来计算连续出现的次数。 
-`max_frequency`跟踪遇到的最高计数。 
-`modes`存储最频繁的值。 
2. 进行中序遍历。 

我们递归地遍历左子树，处理当前节点，然后遍历右子树。 

这种排序很重要，因为 BST 的中序遍历会产生按排序顺序的值。 
3.更新运行频率。 

访问节点时：

 - 如果其值匹配`previous_value`, 增量`current_count`。 
- 否则，重置`current_count`到`1`。 

然后更新`previous_value`到当前节点值。 
4. 与最大频率进行比较。 

如果`current_count > max_frequency`，我们发现了一种新模式：

 - 更新`max_frequency`- 重置`modes`仅包含该值

 如果`current_count == max_frequency`，该值与当前模式频率相关，因此附加它。 
5. 继续遍历，直到处理完所有节点。 

遍历结束后返回`modes`。 

### 为什么它有效

 正确性依赖于 BST 的有序属性。 由于值按排序顺序出现，因此重复的值会分组在一起。 这保证了维护连续相等值的运行计数可以正确测量每个值的频率。 通过在发现更高或相等的频率时更新模式列表，该算法可确保每个最频繁的值都包含在最终结果中。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import List, Optional

class Solution:
    def findMode(self, root: Optional[TreeNode]) -> List[int]:
        modes = []
        previous_value = None
        current_count = 0
        max_frequency = 0

        def inorder(node: Optional[TreeNode]) -> None:
            nonlocal previous_value, current_count, max_frequency

            if not node:
                return

            inorder(node.left)

            if previous_value == node.val:
                current_count += 1
            else:
                current_count = 1

            previous_value = node.val

            if current_count > max_frequency:
                max_frequency = current_count
                modes.clear()
                modes.append(node.val)
            elif current_count == max_frequency:
                modes.append(node.val)

            inorder(node.right)

        inorder(root)
        return modes
```该实现使用嵌套`inorder`递归遍历 BST 的函数。 递归自然遵循中序序列，这保证了排序值。 

这`previous_value`变量跟踪最近处理的节点。 如果当前节点具有相同的值，我们就增加运行频率。 否则，我们将其重置为`1`因为我们遇到了一个新的值。 

每当运行计数超过最大频率时，我们就会清除模式列表并插入当前值作为新的唯一模式。 如果频率与最大值匹配，我们会附加该值，因为它与现有模式相关。 

最后遍历结束后，累计`modes`返回列表。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func findMode(root *TreeNode) []int {
	var modes []int
	var previous *int
	currentCount := 0
	maxFrequency := 0

	var inorder func(node *TreeNode)

	inorder = func(node *TreeNode) {
		if node == nil {
			return
		}

		inorder(node.Left)

		if previous != nil && *previous == node.Val {
			currentCount++
		} else {
			currentCount = 1
		}

		value := node.Val
		previous = &value

		if currentCount > maxFrequency {
			maxFrequency = currentCount
			modes = []int{node.Val}
		} else if currentCount == maxFrequency {
			modes = append(modes, node.Val)
		}

		inorder(node.Right)
	}

	inorder(root)

	return modes
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 没有`None`，我们使用一个指针`*int`为了`previous`区分未初始化值和实际整数。 

切片用于`modes`结果。 当找到新的最大频率时，我们用仅包含当前值的新切片替换该切片。 

这里不存在整数溢出问题，因为节点计数限制为`10^4`。

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树是最小的有效输入。 有错误的实现可能无法正确初始化计数器或意外返回空结果。 我们的实现自然地处理了这个问题，因为第一个访问的节点集`current_count = 1`, 更新`max_frequency`，并成为第一模式。 

### 每个值都是独一无二的

 如果每个节点都包含不同的值，则每个值仅出现一次。 这意味着所有值都是众数。 一个常见的错误是不小心覆盖了以前的候选者而不是保持联系。 我们的实现会在任何时候正确地附加值`current_count == max_frequency`。 

### 多个值共享最高频率

 多个值可能出现相同的次数。 例如，两者`1`和`3`可能出现两次，而所有其他出现一次。 不正确的实现可能只返回遇到的第一个最大值。 我们的解决方案显式检查频率是否相等，并将关联值附加到结果列表中。 

### 所有节点具有相同的值

 如果每个节点都包含相同的值，则算法必须避免重复将重复项添加到模式列表中。 我们的实现仅在找到严格更高的频率时才替换模式列表，确保最终结果恰好包含模式值的一份副本。
