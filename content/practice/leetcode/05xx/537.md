 **主题：** 数学、字符串、模拟

 ## 解决方案

 ## 问题理解

 该问题要求我们将两个表示为字符串的复数相乘，并以相同的字符串格式返回结果。 

复数可写为：```
"real+imaginaryi"
```例如：

-`"1+1i"`代表$1 + i$-`"1+-1i"`代表$1 - i$输入字符串始终遵循有效的格式，这意味着我们不需要担心格式错误的输入。 每个数字包含：

 - **实部**，它是一个整数
 - **虚部**，也是一个整数
 - 虚数单位`i`， 在哪里：$$i^2 = -1$$任务是解析两个输入字符串，以数学方式相乘复数，并以完全相同的格式返回结果。 

如果我们表示：$$(a + bi)$$和$$(c + di)$$它们的乘法变为：$$(a + bi)(c + di)$$展开这个表达式：$$= ac + adi + bci + bd i^2$$自从：$$i^2 = -1$$我们得到：$$= (ac - bd) + (ad + bc)i$$所以最终结果包括：

 - **实部**：`ac - bd`- **虚部**：`ad + bc`约束很小，因为实值和虚值都在`[-100, 100]`。 这意味着性能不是这里关注的问题。 挑战主要在于正确解析字符串表示并无错误地实现乘法公式。 

一个重要的观察结果是，诸如`"1+-1i"`包含负虚部。 一个简单的解析器，简单地分裂`'+'`如果不正确处理负数，不小心可能会失败。 

该问题保证所有输入都是有效的复数，因此我们不需要防御性验证逻辑。 

### 重要的边缘案例

 有几种情况很容易导致实施失败：

 - **负虚数**，例如`"1+-1i"`，因为虚部包含负号。 
- **零值**，例如`"0+0i"`或者`"0+1i"`，它可以在任一分量中产生零。 
- **负实数值**，例如`"-1+2i"`，它仍然必须正确解析。 
- **结果为负值**，其中输出格式必须保留`"real+imaginaryi"`，即使虚部为负，例如`"0+-2i"`。 

## 方法

 ### 蛮力方法

 强力解释是通过手动逐个字符扩展代数表达式、将字符串视为数学表达式并单独评估每个项来模拟乘法。 

例如：```
(1 + i)(1 + i)
```将扩展到：```
1 * 1
1 * i
i * 1
i * i
```然后我们将使用以下方法简化结果：$$i^2 = -1$$虽然这种方法在数学上是正确的，但它引入了不必要的复杂性。 我们需要对字符串进行标记，模拟符号乘法，分别跟踪实部和虚部，然后简化术语。 

考虑到复数乘法有一个直接的公式，符号展开就显得矫枉过正了。 

### 关键见解

 重要的观察是每个有效的复数总是恰好有两个整数分量：$$a + bi$$如果我们能够提取`a`和`b`从字符串中，乘法变得简单：$$(a + bi)(c + di) = (ac - bd) + (ad + bc)i$$我们不需要符号模拟代数，只需：

 1. 解析实部和虚部。 
2. 应用乘法公式。 
3. 将结果格式化回字符串。 

这使得解决方案既简单又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 模拟符号乘法和化简 |
 | 最佳| O(n) | O(1) | O(1) | 解析整数并应用复数乘法公式 |

 这里，`n`表示输入字符串的长度。 由于字符串很小且有界，因此运行时间实际上是恒定的。 

## 算法演练

 ### 最优算法

 1. **解析第一个复数**

 将字符串拆分为`'+'`分离实部和虚部。 删除尾随`'i'`虚部并将这两个值转换为整数。 
2. **解析第二个复数**

 对第二个输入字符串重复相同的解析逻辑。 
3. **应用乘法公式**

 假设解析的值是：$$(a + bi)$$和$$(c + di)$$计算：

 - 真实部分：$$ac - bd$$- 虚部：$$ad + bc$$4. **格式化结果字符串**

 完全按照要求构造输出：```
"real+imaginaryi"
```即使虚部为负数，格式也保持不变，例如：```
"0+-2i"
```### 为什么它有效

 正确性直接来自于复数乘法的代数定义：$$(a + bi)(c + di) = ac + adi + bci + bd i^2$$自从：$$i^2 = -1$$这简化为：$$(ac - bd) + (ad + bc)i$$该算法正确解析组件并准确计算这两个值，保证结果正确。 

## Python 解决方案```python
class Solution:
    def complexNumberMultiply(self, num1: str, num2: str) -> str:
        def parse_complex(number: str) -> tuple[int, int]:
            real_part, imaginary_part = number.split("+")
            return int(real_part), int(imaginary_part[:-1])

        real1, imaginary1 = parse_complex(num1)
        real2, imaginary2 = parse_complex(num2)

        real_result = (
            real1 * real2
            - imaginary1 * imaginary2
        )

        imaginary_result = (
            real1 * imaginary2
            + imaginary1 * real2
        )

        return f"{real_result}+{imaginary_result}i"
```### 实现说明

 解决方案首先定义一个名为的辅助函数`parse_complex`。 该函数将复数字符串转换为其数字部分。 

我们将字符串拆分为`'+'`，它将实部和虚部分开。 由于虚数部分以`'i'`，我们使用切片删除最后一个字符：```
imaginary_part[:-1]
```两个部分都转换为整数。 

解析两个输入后，我们使用标准复数乘法公式计算乘法结果：```
real1 * real2 - imaginary1 * imaginary2
```对于真实分量，并且：```
real1 * imaginary2 + imaginary1 * real2
```为虚部。 

最后，我们使用 Python 字符串格式返回结果，以完全匹配所需的 LeetCode 输出格式。 

## 解决方案```go
package main

import (
	"fmt"
	"strconv"
	"strings"
)

func complexNumberMultiply(num1 string, num2 string) string {
	parseComplex := func(number string) (int, int) {
		parts := strings.Split(number, "+")

		realPart, _ := strconv.Atoi(parts[0])

		imaginaryStr := strings.TrimSuffix(parts[1], "i")
		imaginaryPart, _ := strconv.Atoi(imaginaryStr)

		return realPart, imaginaryPart
	}

	real1, imaginary1 := parseComplex(num1)
	real2, imaginary2 := parseComplex(num2)

	realResult := real1*real2 - imaginary1*imaginary2
	imaginaryResult := real1*imaginary2 + imaginary1*real2

	return fmt.Sprintf("%d+%di", realResult, imaginaryResult)
}
```### Go 具体注释

 Go 实现遵循与 Python 相同的逻辑，但字符串解析需要标准库帮助程序。 

我们使用：

 -`strings.Split()`分离实部和虚部。 
-`strings.TrimSuffix()`删除尾随`'i'`。 
-`strconv.Atoi()`将字符串转换为整数。 

错误处理来自`Atoi`被忽略，因为问题保证了有效输入。 

与 Python f 字符串不同，Go 使用：```
fmt.Sprintf()
```构建最终结果字符串。 

整数溢出在这里不是问题，因为值仍然非常小。 最大的乘法完全在 Go 的范围内`int`范围。

 ## 边缘情况

 ### 负虚部

 输入例如：```
"1+-1i"
```如果解析不正确，可能会导致错误。 天真的解析器可能会误解减号或不正确地分割。 此实现仅安全地拆分`'+'`然后将结果子字符串直接转换为整数，并正确保留负号。 

### 乘法结果等于零

 有些产品完全消除了实部或虚部。 例如：```
"1+1i" * "1+1i"
```产生：```
"0+2i"
```该实现显式独立地计算两个分量，因此自然会保留零值，而不需要特殊处理。 

### 纯虚取消

 虚项相互抵消的情况可能会产生如下结果：```
"-2+0i"
```这很重要，因为输出格式仍然需要出现虚部。 实现总是返回：```
"real+imaginaryi"
```确保即使一个分量变为零时结果仍然有效。
