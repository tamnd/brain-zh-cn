[LeetCode Problem 531](https://leetcode.com/problems/lonely-pixel-i/)

 **Difficulty:** 🟡 Medium
 **Topics:** Array, Hash Table, Matrix

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二维网格，称为`picture`，其中每个单元格包含：

 -`'B'`，代表黑色像素
 -`'W'`，代表一个白色像素

 我们需要计算矩阵中存在多少个**孤独的黑色像素**。 

如果满足以下条件，则黑色像素被视为**孤独**：

 1.它是黑色的（`'B'`）
 2. **同一行中没有其他黑色像素**
 3. **同一列中没有其他黑色像素**

 换句话说，如果一个细胞`(row, col)`包含`'B'`，那么该行必须恰好包含一个黑色像素，并且该列也必须恰好包含一个黑色像素。 

例如，考虑这个矩阵：```
W W B
W B W
B W W
```每行恰好包含一个黑色像素，每列也恰好包含一个黑色像素。 因此，所有三个黑色像素都是孤独的。 

现在考虑：```
B B B
B B W
B B B
```尽管有黑色像素，但每行和每列都包含多个黑色像素。 由于没有黑色像素在其行和列上都是唯一的，所以答案是`0`。 

约束条件告诉我们：

 -`1 <= m, n <= 500`- 矩阵大小可以大到`500 × 500 = 250,000`细胞。 

这意味着二次或三次解可能会变得昂贵。 我们的目标应该是一种能够有效处理矩阵的算法，最好是在相对于单元数量的线性时间内。 

有几种边缘情况值得考虑：

 - 只有一个单元格的矩阵，`[['B']]`，应该返回`1`因为单个黑色像素自然是孤独的。 
- 应返回仅包含白色像素的矩阵`0`。 
- 一行可能只包含一个黑色像素，但其列可能包含多个黑色像素，这意味着它并不孤独。 
- 同样，一列可能只包含一个黑色像素，而其行则包含多个黑色像素。 

该问题保证矩阵维度有效并且每个条目都是`'B'`或者`'W'`，所以我们不需要额外的输入验证。 

## 方法

 ### 蛮力方法

 一个简单的想法是单独检查每个黑色像素并检查它是否是孤独的。 

对于每个包含`'B'`，我们可以扫描它的整行来统计黑色像素，然后扫描它的整列来统计黑色像素。 如果两者相等`1`，则该像素是孤独的。 

这种方法是正确的，因为它直接遵循问题定义。 每个候选黑色像素都根据确切的孤独条件进行验证。 

然而，它的效率很低。 假设矩阵有`m`行和`n`列。 对于每个单元格，我们可以扫描整行和整列。 由于有`m × n`单元格，总运行时间变为：```
O(m × n × (m + n))
```尺寸可达`500 × 500`，这种重复的重新扫描变得不必要地昂贵。 

### 最佳方法

 关键的观察是我们重复地重新计算相同的行和列信息。 

我们可以进行预处理，而不是分别检查每个黑色像素的行数和列数：

 - 每行有多少个黑色像素
 - 每列中有多少个黑色像素

 一旦我们有了这些计数，确定黑色像素是否孤独就变得非常快。 

该过程分两遍进行：

 1. 遍历矩阵并计算每行和每列的黑色像素。 
2. 再次遍历并计算黑色像素，其中：

 - 行数 =`1`- 列数 =`1`这避免了重复扫描，并为我们提供了有效的线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n × (m + n)) | O(m × n × (m + n)) | O(1) | O(1) | 对于每个黑色像素，重新扫描其行和列 |
 | 最佳| O(m × n) | O(m + n) | 预先计算行和列的黑色计数 |

 ## 算法演练

 ### 最优算法

 1.创建两个数组：

 -`row_black_count`尺寸的`m`-`col_black_count`尺寸的`n`这些数组将存储每行和每列中出现的黑色像素数量。 使用数组非常高效，因为行和列都是按数字索引的。 
2. 遍历整个矩阵一次。 

对于每个细胞`(row, col)`：

- 如果`picture[row][col] == 'B'`- 增量`row_black_count[row]`- 增量`col_black_count[col]`经过这一遍，我们确切地知道每行和每列包含多少个黑色像素。 
3. 第二次遍历矩阵。 

对于每个细胞`(row, col)`:

 - 如果单元格包含`'B'`- 检查是否：

 -`row_black_count[row] == 1`-`col_black_count[col] == 1`如果两者都为真，则增加孤独像素计数器。 
4. 返回最终计数。 

### 为什么它有效

 该算法之所以有效，是因为黑色像素是孤独的**当且仅当**其行恰好包含一个黑色像素并且其列恰好包含一个黑色像素。 

第一次遍历准确计算每行和每列的这些计数。 第二次遍历只是验证每个黑色像素的孤独条件。 由于每个黑色像素都会根据正确的行和列总数进行一次检查，因此该算法始终返回正确的孤立像素数。 

## Python 解决方案```python
from typing import List

class Solution:
    def findLonelyPixel(self, picture: List[List[str]]) -> int:
        rows = len(picture)
        cols = len(picture[0])

        row_black_count = [0] * rows
        col_black_count = [0] * cols

        # First pass: count black pixels in rows and columns
        for row in range(rows):
            for col in range(cols):
                if picture[row][col] == 'B':
                    row_black_count[row] += 1
                    col_black_count[col] += 1

        lonely_pixels = 0

        # Second pass: count lonely black pixels
        for row in range(rows):
            for col in range(cols):
                if (
                    picture[row][col] == 'B'
                    and row_black_count[row] == 1
                    and col_black_count[col] == 1
                ):
                    lonely_pixels += 1

        return lonely_pixels
```该实现遵循前面描述的精确的两遍策略。 

第一部分初始化两个计数数组。`row_black_count`存储每行中黑色像素的数量，而`col_black_count`存储每列中黑色像素的数量。 

第一个嵌套循环遍历矩阵一次。 每当遇到黑色像素时，两个计数器都会更新。 此预处理步骤可确保我们以后不再需要重新扫描行或列。 

第二个嵌套循环再次检查每个黑色像素。 由于行数和列数是已知的，因此确定像素是否孤独变成了恒定时间操作。 如果两者相等`1`，我们增加答案。 

最后，该方法返回总的孤独像素数。 

## 解决方案```go
func findLonelyPixel(picture [][]byte) int {
	rows := len(picture)
	cols := len(picture[0])

	rowBlackCount := make([]int, rows)
	colBlackCount := make([]int, cols)

	// First pass: count black pixels in rows and columns
	for row := 0; row < rows; row++ {
		for col := 0; col < cols; col++ {
			if picture[row][col] == 'B' {
				rowBlackCount[row]++
				colBlackCount[col]++
			}
		}
	}

	lonelyPixels := 0

	// Second pass: count lonely black pixels
	for row := 0; row < rows; row++ {
		for col := 0; col < cols; col++ {
			if picture[row][col] == 'B' &&
				rowBlackCount[row] == 1 &&
				colBlackCount[col] == 1 {
				lonelyPixels++
			}
		}
	}

	return lonelyPixels
}
```Go 的实现与 Python 解决方案非常相似。 

输入使用`[][]byte`而不是字符串，因此与字节文字进行比较`'B'`。 切片是使用创建的`make()`用于行数和列数。 

对于 nil 或空矩阵不需要特殊处理，因为该问题保证至少具有一行和一列的有效维度。 整数溢出不是问题，因为最大计数最多为`500`，它很容易适合 Go 的`int`。

 ## 边缘情况

 ### 单细胞矩阵

 像这样的矩阵`[['B']]`是一种重要的边缘情况，因为根据定义，行和列都包含一个黑色像素。 粗心的实现可能会错误地假设至少存在两行或两列。 我们的解决方案自然地处理了这个问题，因为两个计数数组都正确记录了值`1`。 

### 同一行中有多个黑色像素

 考虑：```
B B
W W
```尽管黑色像素占据唯一的列，但两个像素都不是孤立的，因为该行包含多个黑色像素。 有缺陷的实现可能只检查列的唯一性。 我们的解决方案通过要求来防止这种情况发生`row_black_count[row] == 1`。 

### 同一列中有多个黑色像素

 考虑：```
B W
B W
```这里，两行仅包含一个黑色像素，但该列包含两个黑色像素。 两个像素都不孤独。 此案例说明了为什么行和列的唯一性都是必要的。 该实现在计算像素之前明确验证这两个条件。 

### 没有黑色像素的矩阵

 矩阵仅包含`'W'`像素应该返回`0`。 由于在遍历过程中没有遇到黑色像素，因此两个计数数组都保持全零，并且第二遍永远不会增加答案。 该算法无需任何特殊情况逻辑即可有效处理此问题。
