[LeetCode 512 题](https://leetcode.com/problems/game-play-analysis-ii/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题提供了一个名为`Activity`。 每行代表玩家在特定日期的一次登录会话。 该表包含四列：

 | 专栏 | 意义|
 | --- | --- |
 |`player_id`| 玩家的唯一标识符 |
 |`device_id`| 该登录会话期间使用的设备 |
 |`event_date`| 登录日期 |
 |`games_played`| 该会话期间玩的游戏数量 |

 组合`(player_id, event_date)`保证是唯一的。 这意味着一个玩家可以在表中出现多次，但在同一日期只能出现一次。 

任务是确定每个玩家首次登录时使用的设备。 换句话说，对于每一个独特的`player_id`，我们必须找到最早的行`event_date`，然后返回对应的`device_id`。 

The output should contain exactly two columns:

 | 专栏 | 意义|
 | --- | --- |
 |`player_id`| 玩家|
 |`device_id`| 玩家首次登录时使用的设备 |

 输出行的顺序并不重要。 

重要的细节是，我们并不是在寻找数字上最早的设备，也不是在寻找最常用的设备。 我们特别需要与每个玩家的最短登录日期相关联的设备。 

因为`(player_id, event_date)`是唯一的，该问题保证每个玩家都有一个最早登录的行。 这消除了歧义，意味着我们不需要打破平局的逻辑。 

如果错误地假设，幼稚的实现可能会失败：

 - 最小的`device_id`就是答案
 - 玩家只出现一次
 - 行已经按日期排序
 - 多个玩家不能共享同一设备

 输入可能包含只有一条登录记录的玩家、随时间切换设备的玩家以及任意顺序的登录日期。 正确的解决方案必须处理所有这些情况。 

## 方法

 ### 蛮力方法

 暴力解决方案将独立处理每个玩家。 对于每个玩家，我们可以扫描整个表以找到最早的玩家`event_date`。 一旦找到最小日期，我们就可以再次扫描以检索关联的`device_id`。 

这种方法是正确的，因为它明确检查每个玩家的每个可能的行，因此不会错过最早的登录。 

然而，它的效率很低。 如果有`n`行和`p`不同的玩家，重复扫描桌子上的每个玩家会在最坏的情况下导致二次行为。 当表变大时，这会变得不必要的昂贵。 

### 最佳方法

 关键的观察是，我们每个玩家只需要一行，特别是具有最小值的行`event_date`。 

SQL 特别擅长分组聚合。 我们可以首先计算每个玩家的最早登录日期`MIN(event_date)`分组依据`player_id`。 一旦我们知道每个玩家的最早日期，我们就可以将此结果连接回原始结果`Activity`用于检索匹配的表`device_id`。 

这很有效，因为：

 - 聚合将每个玩家减少到一个最早的日期
 - 连接检索确切对应的行
 - 主键保证确保唯一性

 这避免了重复扫描表并利用 SQL 的优化分组和连接操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描桌子上的每个玩家 |
 | 最佳| O(n) | O(n) | 使用分组和连接直接定位第一个登录行 |

 ## 算法演练

 1. 首先将所有行分组`player_id`。 

这使我们能够独立分析每个玩家的活动。 
2. 对于每个玩家，计算最小值`event_date`。 

最短日期代表该玩家的首次登录日期。 
3. 将结果存储为临时派生表，其中包含：

 -`player_id`- 最早`event_date`4. 将此派生表与原始表连接起来`Activity`桌子。 

连接条件匹配：

 - 相同`player_id`- 相同的`event_date`这标识了与玩家首次登录相对应的确切原始行。 
5. 选择`player_id`和`device_id`匹配行中的列。 

这些是所需的输出值。 

### 为什么它有效

 该算法之所以有效，是因为每个玩家的首次登录都是由最小值唯一确定的`event_date`。 自从`(player_id, event_date)`是主键，则只能有一行与给定玩家的最早日期匹配。 因此，将分组结果连接回原始表始终会准确检索正确的设备。 

## Python 解决方案

 尽管这是一个 SQL 数据库问题，但 LeetCode 数据库问题是使用 SQL 查询来解决的。 以下查询是正确的 LeetCode 提交。```python
# This problem is solved with SQL, not Python.

SELECT a.player_id, a.device_id
FROM Activity a
JOIN (
    SELECT player_id, MIN(event_date) AS first_login
    FROM Activity
    GROUP BY player_id
) first_activity
ON a.player_id = first_activity.player_id
AND a.event_date = first_activity.first_login;
```该查询有两个主要逻辑部分。 

内部子查询计算每个玩家的最早登录日期。 这`GROUP BY player_id`条款确保每个玩家都被独立处理，同时`MIN(event_date)`提取首次登录日期。 

外部查询连接原始查询`Activity`包含此分组结果的表。 连接条件确保仅选择与同一玩家和最早登录日期匹配的行。 

最后，查询返回所需的列：`player_id`和`device_id`。

 ## 边缘情况

 一个重要的边缘情况是一名玩家仅在牌桌上出现一次。 在这种情况下，该单行自动成为最早的登录。 有缺陷的实现可能会错误地期望每个玩家有多个记录，或者在分组期间失败。 SQL 解决方案自然地处理这个问题，因为`MIN(event_date)`超过一个值只是返回该值。 

当行不按时间顺序排序时，会出现另一个重要的边缘情况。 许多幼稚的实现错误地假设玩家遇到的第一行是最早登录的行。 由于除非显式排序，否则 SQL 表不保证行顺序，因此依赖插入顺序是不安全的。 使用`MIN(event_date)`无论行排列如何，都能确保正确性。 

第三个重要的边缘情况涉及玩家随着时间的推移切换设备。 有缺陷的实现可能会意外返回最小的值`device_id`或最近的设备而不是首次登录的设备。 加入条件专门匹配最早的登录日期，保证返回的`device_id`与第一次登录事件完全对应。
