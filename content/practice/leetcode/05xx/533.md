[LeetCode 533 题](https://leetcode.com/problems/lonely-pixel-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们一个矩阵，称为`picture`，其中每个单元格包含`'B'`对于黑色像素或`'W'`对于白色像素。 我们还得到一个整数`target`。 

我们需要在两个严格的条件下计算有多少黑色像素符合“孤独像素”的条件。 

假设黑色像素位于位置`(r, c)`。 

第一、排`r`必须准确包含`target`黑色像素和列`c`还必须准确包含`target`黑色像素。 

其次，列中具有黑色像素的每一行`c`必须与行相同`r`。 这是更微妙的要求。 这意味着如果列`c`多行包含黑色像素，所有这些行必须具有完全相同的黑色和白色像素图案。 

输出是满足这两个条件的黑色像素总数。 

约束条件很重要：

 -`m`和`n`每个最多`200`- 矩阵仅包含`'B'`和`'W'`-`target`至多是`min(m, n)`一个`200 x 200`矩阵最多包含`40,000`细胞，它足够小，可以解决周围的问题`O(m * n)`或者`O(m * n * k)`对于小的额外因素。 然而，重复地对许多行和列进行极其昂贵的强力检查可能会变得低效。 

有几个重要的边缘情况：

 - 一行可能包含少于或多于`target`黑色像素，立即取消该行中所有像素的资格。 
- 列可能恰好包含`target`黑色像素，但对应的行可能不相同。 
- 多个相同的行可能出现多次，并且只有某些列可能满足列数条件。 
- 应返回包含所有白色像素的矩阵`0`。 
- 具有全黑色像素的矩阵通常会失败，因为行数和列数相对于`target`。 

关键挑战是有效验证第二个条件，而无需重复比较每个黑色像素的整行。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是单独检查每个黑色像素。 

对于每个黑色像素`(r, c)`:

 1. 计算行中有多少个黑色像素`r`。 
2. 统计该列中有多少个黑色像素`c`。 
3. 如果两者相等`target`，检查列中包含黑色像素的每一行`c`。 
4. 将每一行与行进行比较`r`以确保它们相同。 

这种方法是正确的，因为它直接检查每个候选黑色像素的问题定义。 

然而，由于对许多像素重复执行行比较，因此效率低下。 在最坏的情况下，每次验证可能需要多次扫描矩阵的大部分。 

### 最佳方法

 关键的观察结果是行比单个像素更重要。 

如果一行有效，则：

 - 它必须准确包含`target`黑色像素。 
- 任何有助于答案的列必须准确包含`target`黑色像素。 
- 该列中包含黑色像素的每一行必须相同。 

我们可以使用哈希映射将相同的行分组在一起，而不是重复比较行。 

这个想法是：

 1. 计算每一列中的黑色像素。 
2. 将每一行转换为字符串表示形式。 
3. 计算每个唯一行模式出现的次数。 
4. 仅考虑以下行模式：

 - 准确包含`target`黑色像素
 - 准确地出现`target`次

 为什么“恰好出现`target`次”重要吗？

 假设行图案在某些列中具有黑色像素。 如果该行恰好出现`target`次，并且包含黑色像素的列也恰好有`target`黑色像素总数，那么该列中的所有黑色像素必须来自那些相同的行。 这自动满足第二个条件。 

这将昂贵的重复行比较转换为高效的哈希图查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * (m + n)) | O(m * n * (m + n)) | O(1) | O(1) | 重复验证每个黑色像素的行和列 |
 | 最佳| O(m * n) | O(m * n) | 使用行散列和列计数来避免重复比较 |

 ## 算法演练

 1. 计算每列中黑色像素的数量。 

创建一个数组`column_black_count`尺寸的`n`。 

遍历矩阵一次。 每当我们看到一个`'B'`在`(r, c)`, 增量`column_black_count[c]`。 

我们这样做是因为每个有效的孤独像素必须属于恰好包含`target`黑色像素。 
2. 将每一行转换为可散列表示。 

由于列表不能直接作为字典键，因此将每一行转换为字符串，例如`"WBWBBW"`。 

将每个行模式的频率存储在名为的哈希映射中`row_frequency`。 

这让我们可以快速确定相同的行出现了多少次。 
3. 仅处理候选行。 

再次迭代每一行。 

对于每一行：

 - 计算黑色像素的数量。 
- 如果计数不准确则跳过该行`target`。 

这会立即删除无法对答案做出贡献的行。 
4、检查行图案是否准确出现`target`次。 

让`row_string`是行的字符串表示形式。 

如果`row_frequency[row_string] != target`，跳过这一行。 

为什么？ 

如果行模式出现的数量多于或少于`target`有时，则所需的列结构无法匹配问题约束。 
5. 验证每个黑色列。 

对于每一列`c`其中该行包含`'B'`:

 - 检查是否`column_black_count[c] == target`。 

如果为真，则该列中的每个黑色像素都来自由下式表示的相同行`row_string`。 

因此，该列中的所有黑色像素都满足这两个条件。 
6. 积累答案。 

每个有效列都为当前行贡献一个单独的像素。 

将有效列数添加到结果中。 

### 为什么它有效

 该算法依赖于一个重要的不变量：

 如果行图案恰好出现`target`次，以及一列包含`'B'`也恰好包含`target`黑色像素，那么该列中的每个黑色像素都必须属于那些相同的行。 

这自动保证：

 - 该行恰好包含`target`黑色像素
 - 该列准确包含`target`黑色像素
 - 对该列做出贡献的每一行都是相同的

 因此，每个计数的像素都满足黑色孤独像素的定义。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def findBlackPixel(self, picture: List[List[str]], target: int) -> int:
        rows = len(picture)
        cols = len(picture[0])

        # Count black pixels in each column
        column_black_count = [0] * cols

        # Store row string frequencies
        row_frequency = Counter()

        for row in picture:
            row_string = ''.join(row)
            row_frequency[row_string] += 1

            for c in range(cols):
                if row[c] == 'B':
                    column_black_count[c] += 1

        result = 0

        # Process candidate rows
        for row in picture:
            row_string = ''.join(row)

            # Row must appear exactly target times
            if row_frequency[row_string] != target:
                continue

            # Row must contain exactly target black pixels
            if row_string.count('B') != target:
                continue

            # Check valid columns
            for c in range(cols):
                if row[c] == 'B' and column_black_count[c] == target:
                    result += 1

        return result
```该实现紧密遵循前面描述的算法。 

第一个循环同时执行两个任务。 它构建行图案的频率图并计算每列中黑色像素的数量。 组合这些操作可以保持实现的效率并避免不必要的矩阵传递。 

这`Counter`数据结构是理想的，因为它允许恒定时间查找行模式出现的次数。 

在第二阶段，每一行都作为候选行进行检查。 不完全包含的行`target`黑色像素会立即被跳过。 模式频率不完全一致的行`target`也被跳过。 

最后，该算法扫描该行中的每个黑色像素并检查其列是否恰好包含`target`黑色像素。 每一个这样的立场都有助于最终的答案。 

由于该问题保证所有相同的行通过频率图进行逻辑分组，因此在验证期间不需要显式的行比较。 

## 解决方案```go
func findBlackPixel(picture [][]byte, target int) int {
	rows := len(picture)
	cols := len(picture[0])

	columnBlackCount := make([]int, cols)
	rowFrequency := make(map[string]int)

	// Build column counts and row frequencies
	for _, row := range picture {
		rowString := string(row)
		rowFrequency[rowString]++

		for c := 0; c < cols; c++ {
			if row[c] == 'B' {
				columnBlackCount[c]++
			}
		}
	}

	result := 0

	// Process candidate rows
	for _, row := range picture {
		rowString := string(row)

		if rowFrequency[rowString] != target {
			continue
		}

		blackCount := 0
		for c := 0; c < cols; c++ {
			if row[c] == 'B' {
				blackCount++
			}
		}

		if blackCount != target {
			continue
		}

		for c := 0; c < cols; c++ {
			if row[c] == 'B' && columnBlackCount[c] == target {
				result++
			}
		}
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个显着的区别是 Go 使用`map[string]int`而不是Python的`Counter`。 行转换自`[]byte`转换为字符串，以便它们可以用作映射键。 

Go 没有像 Python 那样提供内置的字符串计数方法`count`，因此该实现使用循环显式地计算黑色像素。 

不存在整数溢出问题，因为矩阵大小最多为`200 x 200`，意味着结果不能超过`40,000`。

 ## 边缘情况

 当多行相同，但相应的列包含多个行时，就会出现一种重要的边缘情况`target`黑色像素。 简单的实现可能会仅仅因为行匹配而错误地计算这些像素。 该算法通过显式检查来避免这种情况`column_black_count[c] == target`在计算像素之前。 

当一行恰好包含`target`黑色像素，但行图案出现多于或少于`target`次。 即使列计数单独看来是正确的，第二条规则也会失败，因为并非所有贡献行都按要求的方式相同。 频率图检查可确保立即拒绝这些行。 

第三种边缘情况涉及非常小的矩阵，例如`1 x 1`。 这些情况很容易被错误处理，因为单个单元格同时属于唯一的行和唯一的列。 该实现自然会处理这个问题，因为行计数、列计数和频率检查仍然正确应用。 

另一种微妙的情况是所有像素都是黑色的。 例如：```
[
  ["B","B"],
  ["B","B"]
]
```和`target = 1`。 

每行和每列都包含太多黑色像素，所以答案应该是`0`。 该算法正确地拒绝每个候选值，因为行数和列数都超过了目标值。
