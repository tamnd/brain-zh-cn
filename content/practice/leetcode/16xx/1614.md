 # LeetCode 1614，括号的最大嵌套深度

 ## 问题理解

 该问题要求我们计算有效括号字符串中括号的最大嵌套深度。 

有效的括号字符串，通常缩写为 VPS，是一个字符串，其中每个左括号`'('`有匹配的右括号`')'`，并且括号是正确平衡的。 字符串还可以包含数字和算术运算符，但只有括号会影响嵌套深度。 

嵌套深度是指括号之间嵌套的深度。 例如：

-`"()"`有深度`1`-`"(())"`有深度`2`-`"((()))"`有深度`3`目标是扫描字符串并确定任意点同时开括号的最大数量。 

对于输入：```
"(1+(2*3)+((8)/4))+1"
```数字`8`位于三对嵌套的括号内，所以答案是`3`。 

限制非常小：

 -`1 <= s.length <= 100`- 保证字符串有效

 这些限制告诉我们，性能不是主要问题，但我们仍然应该设计一个干净、高效的解决方案。 由于保证字符串有效，因此我们不需要处理格式错误的表达式或不匹配的括号。 

记住几个边缘情况很重要：

 - 没有嵌套的字符串，例如`"()"`，应该返回`1`- 具有深层嵌套的字符串，例如`"(((())))"`，应该正确计算每个级别
 - 包含许多非括号字符的字符串应该完全忽略它们
 - 顺序组，例如`"()()()"`嵌套深度不应超过`1`- 处理右括号后的空当前深度不应变为负数，因为保证输入有效

 ## 方法

 ### 蛮力方法

 强力解决方案将检查字符串中的每个位置并确定该位置的嵌套深度。 

一种方法是：

 - 对于字符串中的每个字符：

 - 计算该位置之前存在多少个不匹配的左括号
 - 跟踪遇到的最大计数

 这是有效的，因为任何点的嵌套深度都等于当前打开的括号的数量。 

然而，从头开始重新计算每个字符的嵌套深度会导致重复工作。 如果字符串长度为`n`，并且我们扫描字符串的一部分以查找每个位置，总复杂度变为`O(n^2)`。 

尽管约束足够小，这仍然可以通过，但效率低下且不必要。 

### 最佳方法

 关键的观察是我们不需要重复地重新计算嵌套深度。 

相反，我们可以从左到右处理一次字符串，同时保持：

 -`current_depth`, 当前左括号的数量
 -`max_depth`，迄今为止所见的最大深度

 当我们遇到`'('`：

- 增加`current_depth`- 更新`max_depth`如果需要的话

 当我们遇到`')'`：

- 减少`current_depth`所有其他字符都将被忽略，因为它们不影响嵌套。 

这是有效的，因为任何点的当前嵌套深度正是迄今为止遇到的不匹配左括号的数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复重新计算嵌套深度 |
 | 最佳 | O(n) | O(1) | O(1) | 跟踪当前深度时单次通过 |

 ## 算法演练

 1.初始化两个变量：

 -`current_depth = 0`-`max_depth = 0`这`current_depth`变量跟踪当前有多少个左括号处于活动状态。 这`max_depth`变量存储遍历过程中遇到的最大深度。 
2. 逐个字符地遍历字符串。 

我们只处理每个字符一次，因为嵌套信息可以增量维护。 
3. 如果当前字符是`'('`:

 - 增量`current_depth`经过`1`- 更新`max_depth`与较大者：

 - 当前`max_depth`- 当前的`current_depth`这反映了进入更深的嵌套层次。 
4. 如果当前字符是`')'`:

 - 递减`current_depth`经过`1`这反映了退出一级嵌套。 
5. 忽略所有其他字符。 

数字和运算符不影响嵌套结构。 
6.处理完整个字符串后，返回`max_depth`。 

### 为什么它有效

 在字符串中的每个位置，`current_depth`等于尚未关闭的左括号的数量。 这正是当前嵌套级别的定义。 自从`max_depth`存储最大值`current_depth`一旦达到，它必须等于整个表达式的最大嵌套深度。 

## Python 解决方案```python
class Solution:
    def maxDepth(self, s: str) -> int:
        current_depth = 0
        max_depth = 0

        for char in s:
            if char == "(":
                current_depth += 1
                max_depth = max(max_depth, current_depth)
            elif char == ")":
                current_depth -= 1

        return max_depth
```该实现遵循前面描述的确切算法。 

变量`current_depth`遍历字符串时跟踪活动嵌套级别。 每个左括号都会增加深度，因为我们正在进入更深层次的嵌套。 增加后立即与`max_depth`创下迄今为止达到的最高水平。 

当遇到右括号时，我们减少`current_depth`因为一个嵌套级别已经结束。 

数字和算术运算符等字符会被自动忽略，因为它们不满足任一条件。 

由于保证字符串有效，`current_depth`在遍历过程中永远不会变成负值。 

## 解决方案```go
func maxDepth(s string) int {
    currentDepth := 0
    maxDepth := 0

    for _, char := range s {
        if char == '(' {
            currentDepth++

            if currentDepth > maxDepth {
                maxDepth = currentDepth
            }
        } else if char == ')' {
            currentDepth--
        }
    }

    return maxDepth
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用`rune`字符串迭代期间的值`range`，因此与字符文字进行比较，例如`'('`和`')'`。 

不需要额外的数据结构，并且整数溢出不是问题，因为最大字符串长度仅为`100`。

 ## 边缘情况

 一个重要的边缘情况是根本没有括号的字符串，例如`"12345"`。 幼稚的实现可能会错误地假设至少存在一个括号并返回`1`。 正确答案是`0`因为没有嵌套。 该实现自然地处理了这个问题，因为`current_depth`和`max_depth`永远不会增加。 

另一个重要的情况是连续的括号组，例如`"()()()"`。 这些组没有相互嵌套，因此应保留最大深度`1`。 不正确的解决方案可能会意外地计算括号对的总数，而不是最大活动嵌套级别。 由于算法在组打开和关闭时立即增加和减少深度，因此它可以正确报告`1`。 

第三个重要的边缘情况是深度嵌套的输入，例如`"(((())))"`。 这种情况确保实现正确地跟踪多个级别上不断增加的深度。 算法更新`max_depth`紧跟在每个左括号之后，保证准确记录最深的级别。 

另一个微妙的情况涉及散布在整个表达式中的非括号字符，例如`"(1+(2*3)-4)"`。 数字和运算符不应影响嵌套深度。 该实现仅显式检查`'('`和`')'`，因此所有其他字符都会被安全地忽略。
