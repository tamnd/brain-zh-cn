[LeetCode 问题 1608](https://leetcode.com/problems/special-array-with-x-elements-greater-than-or-equal-x/)

 **难度：** 🟢简单
 **主题：** 数组、二分查找、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个数组`nums`包含非负整数。 我们需要判断是否存在一个整数`x`这样正好`x`数组中的元素大于或等于`x`。 

重要的细节是`x`不需要出现在数组本身内部。 我们只关心满足条件的元素的数量。 

例如，如果`nums = [3,5]`，那么正好有两个数大于或等于`2`，即`3`和`5`。 因此，数组很特殊，答案是`2`。 

如果不存在这样的整数，我们返回`-1`。 

限制相对较小：

 -`1 <= nums.length <= 100`-`0 <= nums[i] <= 1000`由于数组大小最多为 100，因此即使是二次算法也是可以接受的。 然而，设计一个干净、高效的解决方案仍然有价值。 

有几种边缘情况很容易导致错误：

 - 仅包含零的数组，例如`[0,0]`- 乍一看可能出现多个候选值的数组
 - 具有重复值的数组
 - 有效的情况`x`数组中不存在
 - 非常小的数组，尤其是长度数组`1`该问题保证如果有效`x`存在，它是独一无二的。 This means we do not need to handle multiple valid answers.

 ## 方法

 ### 蛮力方法

 The most direct solution is to try every possible value of`x`。 

由于数组长度是`n`，大于或等于的元素数量`x`永远不能超过`n`。 因此，我们只需要测试来自`0`到`n`。 

对于每位候选人`x`:

 1.遍历数组
 2. 统计有多少个元素大于等于`x`3. 检查计数是否等于`x`如果找到匹配项，我们将返回`x`。 否则，在测试了所有可能性后，我们返回`-1`。 

这种方法是正确的，因为它显式检查每个可能候选者的特殊数组的定义。 

时间复杂度为`O(n^2)`因为对于每个候选人`x`，我们扫描整个数组。 

### 最佳方法

 更好的解决方案来自对数组进行排序。 

按升序排序后，我们可以推断出有多少元素大于或等于特定值。 

假设排序后的数组为：```
a[0], a[1], a[2], ..., a[n-1]
```在索引处`i`，正好有`n - i`元素来自`a[i]`到数组的末尾。 

如果：```
a[i] >= n - i
```那么至少`n - i`元素足够大。 

然而，我们还需要确保准确地`n - i`元素满足条件。 这意味着前一个元素必须小于`n - i`。 

正式：```
a[i] >= n - i
and
a[i - 1] < n - i
```如果两个条件都成立，那么`x = n - i`。 

排序允许我们在排序后在单个线性扫描中计算答案。

 ## 算法演练

 ### 最优排序算法

 1. 对数组进行非降序排序。 

排序将较小的值分组在开头，将较大的值分组在末尾。 这使得确定有多少元素大于或等于阈值变得容易。 
2.让`n`是数组的长度。 

如果我们当前正在检查索引`i`，那么正好有`n - i`索引中的元素`i`穿过数组的末尾。 
3. 从左到右迭代排序后的数组。 

对于每个位置`i`，计算：```
candidate = n - i
```这表示后缀中剩余的元素数量。 
4. 检查当前值是否支持该候选值。 

我们需要：```
nums[i] >= candidate
```因为所有元素都来自`i`向前必须至少`candidate`。 
5. 确保前一个元素不满足条件。 

如果`i > 0`，我们还要求：```
nums[i - 1] < candidate
```这准确地保证了`candidate`元素符合条件，而不是更多。 
6. 如果两个条件都成立，则返回`candidate`。 
7. 如果循环结束时没有找到有效的候选者，则返回`-1`。 

### 为什么它有效

 排序后，后缀从index开始`i`恰好包含`n - i`元素。 如果该后缀中的最小元素至少是`n - i`，那么后缀中的每个元素也满足条件。 

第二个条件确保前缀元素不会意外地将计数增加到超出`n - i`。 这些条件共同保证了`x`元素大于或等于`x`。 

## Python 解决方案```python
from typing import List

class Solution:
    def specialArray(self, nums: List[int]) -> int:
        nums.sort()
        n = len(nums)

        for i in range(n):
            candidate = n - i

            if nums[i] >= candidate:
                if i == 0 or nums[i - 1] < candidate:
                    return candidate

        return -1
```实现首先对数组进行排序。 排序后，数组的每个后缀都包含大于或等于该后缀中第一个值的元素。 

变量`candidate`表示从当前索引到数组末尾的元素数量。 

第一个条件：```python
nums[i] >= candidate
```检查后缀中的所有元素是否足够大。 

第二个条件：```python
i == 0 or nums[i - 1] < candidate
```确保没有更早的元素也符合条件，这会增加计数超出候选值。 

如果两个条件都成立，我们立即返回候选者，因为问题保证了唯一性。 

如果不存在有效的候选者，该函数返回`-1`。 

## 解决方案```go
package main

import "sort"

func specialArray(nums []int) int {
	sort.Ints(nums)

	n := len(nums)

	for i := 0; i < n; i++ {
		candidate := n - i

		if nums[i] >= candidate {
			if i == 0 || nums[i-1] < candidate {
				return candidate
			}
		}
	}

	return -1
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

主要区别在于 Go 使用`sort.Ints(nums)`将切片排序到位。 Go 中的切片的行为已经类似于对底层数组的引用，因此不需要额外的复制。 

不存在整数溢出问题，因为约束非常小。

 ## 边缘情况

 一个重要的边缘情况是仅包含零的数组，例如`[0,0]`。 天真的实现可能会错误地认为`x = 0`之所以有效，是因为没有元素大于或等于正数。 然而，当`x = 0`，每个元素都大于或等于`0`，因此计数变为完整数组长度而不是零。 该实现通过显式检查确切的计数条件来正确处理此问题。 

另一个重要的情况是当有效`x`不会出现在数组本身中。 例如，在`[0,1,2,3,4]`，答案是`2`， 虽然`2`只是几个值之一。 该算法从不假设`x`必须存在于数组中。 相反，它根据排序后剩余元素的数量得出候选元素。 

第三种边缘情况涉及边界附近的重复值。 考虑`[0,0,3,3]`。 这里，正好有两个元素大于或等于`2`。 第二个条件：```
nums[i - 1] < candidate
```至关重要，因为它可以防止出现重复值时出现过度计数。 如果没有这项检查，算法可能会错误地接受超过`x`元素满足条件。 

当每个元素都符合条件时，就会出现最后一个微妙的情况，例如`[5,5,5,5,5]`。 在这种情况下，有效的答案是数组长度本身。 该实现正确地处理了这个问题，因为第一个索引自然表示包含整个数组的后缀。
