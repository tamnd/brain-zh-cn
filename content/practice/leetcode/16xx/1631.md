[LeetCode 问题 1631](https://leetcode.com/problems/path-with-minimum-effort/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、深度优先搜索、广度优先搜索、联合查找、堆（优先级队列）、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为`heights`，其中每个单元格包含一个代表海拔的整数。 我们从左上角开始`(0, 0)`并想要到达右下角`(rows - 1, columns - 1)`。 

在每一步中，我们可能会朝以下四个方向之一移动：

 - 向上
 - 向下
 - 左
 - 右

 重要的细节是如何定义路径的成本。 

通常，最短路径问题使用边权重之和。 这个问题是不同的。 路径的努力定义为：

 > 沿路径的任意两个连续单元格之间的最大绝对高度差。 

例如，如果路径穿过高度差`[1, 2, 5, 3]`，那么路径的努力就是`5`，因为这是沿途任何地方遇到的最大跳跃。 

我们的目标是最小化这个最大跳跃。 

输入约束很重要：

 -`rows, columns <= 100`- 最大细胞数为`100 * 100 = 10,000`这足够大，以至于不可能对所有路径进行强力枚举，因为可能的路径数量呈指数增长。 

然而，对于以下算法来说，图形大小仍然是可以管理的：

 - Dijkstra算法
 - 使用 BFS/DFS 进行二分搜索
 - 并查

 网格保证：

 - 至少存在一个单元格
 - 高度为正整数
 - 目的地始终可达，因为网格内的移动不受限制

 一些边缘情况很重要：

 - 单细胞网格，不需要移动，所以努力`0`- 所有高度都相同的网格，产生努力`0`- 一个网格有一个不可避免的大跳跃
 - 多个可能的路径，其中距离最短的路径不是最小努力路径

 关键的挑战是认识到最小化最大边缘成本需要与最小化总距离不同的策略。 

## 方法

 ### 蛮力方法

 暴力解决方案将探索从左上角到右下角的所有可能路径。 

对于每条路径：

 1. 计算连续单元格之间的绝对差
 2. 跟踪遇到的最大差异
 3. 记录所有可能路径上的最小值

 这种方法是正确的，因为它明确地检查每条有效路由。 

然而，这在计算上是不可行的。 

在网格中，可能的路径数量随着单元数量呈指数增长。 即使对于中等规模的网格，路线总数也会变得巨大。 由于网格最多可以包含 10,000 个单元，因此穷举搜索是完全不切实际的。 

带有回溯功能的简单 DFS 会超时。 

### 最优方法，Dijkstra 算法

 关键的见解是这个问题可以建模为图问题。 

每个单元格都是一个节点。 

相邻单元格之间的每次移动都是一条带有权重的边：$$|heights[r1][c1] - heights[r2][c2]|$$挑战在于路径成本不是边权重的总和。 相反，路径成本是沿路径的最大边权重。 

幸运的是，Dijkstra 的算法只需稍加修改仍然可以工作。 

通常，Dijkstra 使用以下方法松弛边缘：$$newDistance = currentDistance + edgeWeight$$在这里，我们定义：$$newEffort = \max(currentEffort, edgeWeight)$$This works because once we reach a node with the minimum possible effort, no future path can improve it. The monotonic property required by Dijkstra still holds.

 We use a min-heap to always process the cell with the currently smallest known effort.

 ## 算法演练

 ### 使用 Dijkstra 算法的最优算法

 1. 将每个网格单元视为一个图节点。 

Each cell can connect to up to four neighboring cells. The edge weight between two adjacent cells is the absolute difference in heights.
 2. 创建一个`dist`矩阵。`dist[r][c]`存储到达单元格所需的最小努力`(r, c)`从一开始。 

将每个值初始化为无穷大，除了：```
dist[0][0] = 0
```3. 创建一个最小堆。 

每个堆条目存储：```
(current_effort, row, col)
```首先插入：```
(0, 0, 0)
```4. 反复从堆中弹出最小努力单元。 

这保证了我们始终首先处理当前最著名的状态。 
5. 如果弹出的单元格是目的地，则立即返回其努力。 

由于 Dijkstra 的排序特性，我们第一次到达目的地的时间保证是最优的。 
6. 探索所有四个相邻单元格。 

对于每个有效邻居：

 - 计算高度差
 - 计算新的努力：$$newEffort = \max(currentEffort, heightDifference)$$7. 放松边缘。 

如果`newEffort`小于先前记录的邻居的努力：

 - 更新`dist`- 将新状态推入堆中
 8. 继续前进，直至到达目的地。 

### 为什么它有效

 只要路径成本是单调的，迪杰斯特拉算法就会起作用，这意味着延长路径永远不会降低其成本。 

在这个问题中：$$newEffort = \max(oldEffort, edgeWeight)$$努力只能保持不变或增加。 

因此，一旦从最小堆中删除一个节点，我们就已经找到了到达它所需的最小可能的努力。 这样就保证了正确性。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minimumEffortPath(self, heights: List[List[int]]) -> int:
        rows = len(heights)
        cols = len(heights[0])

        efforts = [[float("inf")] * cols for _ in range(rows)]
        efforts[0][0] = 0

        min_heap = [(0, 0, 0)]

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while min_heap:
            current_effort, row, col = heapq.heappop(min_heap)

            if row == rows - 1 and col == cols - 1:
                return current_effort

            if current_effort > efforts[row][col]:
                continue

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if 0 <= new_row < rows and 0 <= new_col < cols:
                    height_diff = abs(
                        heights[row][col] - heights[new_row][new_col]
                    )

                    new_effort = max(current_effort, height_diff)

                    if new_effort < efforts[new_row][new_col]:
                        efforts[new_row][new_col] = new_effort

                        heapq.heappush(
                            min_heap,
                            (new_effort, new_row, new_col)
                        )

        return 0
```实施首先确定网格尺寸。 然后我们创建`efforts`矩阵，存储到达每个单元格所需的最小努力。 

最小堆用于按工作量递增顺序处理单元。 这就是Dijkstra算法的核心要求。 

每个堆元素包含：

 - 当前最小努力
 - 行索引
 - 列索引

 对于每个弹出的单元格，我们尝试向四个方向移动。 移动到相邻小区所需的努力是以下最大值：

 - 当前路径的努力
 - 当前边缘高度差

 如果这为邻居产生了更好的结果，我们会更新邻居并将其推入堆中。 

陈旧状态检查：```python
if current_effort > efforts[row][col]:
    continue
```防止对过时的堆条目进行不必要的处理。 

一旦目标从堆中删除，算法就会终止，因为保证这种努力是最小的。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

type State struct {
	effort int
	row    int
	col    int
}

type MinHeap []State

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].effort < h[j].effort
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(State))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)

	item := old[n-1]
	*h = old[:n-1]

	return item
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func minimumEffortPath(heights [][]int) int {
	rows := len(heights)
	cols := len(heights[0])

	efforts := make([][]int, rows)

	for i := 0; i < rows; i++ {
		efforts[i] = make([]int, cols)

		for j := 0; j < cols; j++ {
			efforts[i][j] = math.MaxInt32
		}
	}

	efforts[0][0] = 0

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	heap.Push(minHeap, State{0, 0, 0})

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	for minHeap.Len() > 0 {
		current := heap.Pop(minHeap).(State)

		currentEffort := current.effort
		row := current.row
		col := current.col

		if row == rows-1 && col == cols-1 {
			return currentEffort
		}

		if currentEffort > efforts[row][col] {
			continue
		}

		for _, dir := range directions {
			newRow := row + dir[0]
			newCol := col + dir[1]

			if newRow >= 0 && newRow < rows &&
				newCol >= 0 && newCol < cols {

				heightDiff := abs(
					heights[row][col] - heights[newRow][newCol],
				)

				newEffort := max(currentEffort, heightDiff)

				if newEffort < efforts[newRow][newCol] {
					efforts[newRow][newCol] = newEffort

					heap.Push(
						minHeap,
						State{newEffort, newRow, newCol},
					)
				}
			}
		}
	}

	return 0
}
```Go 解决方案遵循与 Python 版本相同的算法结构。 最大的区别是 Go 需要使用显式堆实现`container/heap`包裹。 

定制`State`结构存储：

 - 目前的努力
 - 行
 - 专栏

 堆接口需要实现：

 -`Len`-`Less`-`Swap`-`Push`-`Pop`Go 没有提供内置的`max`或者`abs`整数函数，因此辅助函数是手动实现的。 

其余逻辑完全反映了 Python 解决方案。

## 测试用例```python
from typing import List

class Solution:
    def minimumEffortPath(self, heights: List[List[int]]) -> int:
        import heapq

        rows = len(heights)
        cols = len(heights[0])

        efforts = [[float("inf")] * cols for _ in range(rows)]
        efforts[0][0] = 0

        heap = [(0, 0, 0)]

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while heap:
            effort, r, c = heapq.heappop(heap)

            if r == rows - 1 and c == cols - 1:
                return effort

            if effort > efforts[r][c]:
                continue

            for dr, dc in directions:
                nr = r + dr
                nc = c + dc

                if 0 <= nr < rows and 0 <= nc < cols:
                    diff = abs(heights[r][c] - heights[nr][nc])

                    new_effort = max(effort, diff)

                    if new_effort < efforts[nr][nc]:
                        efforts[nr][nc] = new_effort
                        heapq.heappush(heap, (new_effort, nr, nc))

        return 0

 ## 边缘情况

 ### 单细胞网格

 仅包含一个单元格的网格是一种重要的边界情况。```
[[7]]
```由于起点和目的地是同一单元格，因此不会发生移动。 因此，必须努力`0`。 

有缺陷的实现可能会错误地尝试邻居探索或返回无穷大。 我们的实现自然地处理了这个问题，因为起始节点立即被识别为目的地。 

### 间接路径比直接路径更好

 考虑：```
[
  [1,1000],
  [1,1]
]
```直接向右移动有努力：```
999
```但首先向下移动可以避免任何高度差：```
1 → 1 → 1
```努力变成：```
0
```这个案例很重要，因为贪婪的局部决策会失败。 该算法使用优先级队列正确地探索替代路线。 

### 身高差异大

 高度可以大到：```
10^6
```因此，边缘差异也可能非常大。 

不正确的实现可能会在某些语言中溢出或错误地将值累加为总和。 我们的算法仅计算绝对差和最大值，这两者都安全地符合 Python 和 Go 的标准整数范围。 

### 同一单元格的多次堆插入

 一个单元可能会以不同的努力值多次进入堆。 

这在 Dijkstra 算法中很常见。 

没有陈旧状态检查：```
if current_effort > efforts[row][col]:
    continue
```该算法仍然是正确的，但会执行不必​​要的处理。 该实现安全地跳过过时的状态，同时保持正确性。
