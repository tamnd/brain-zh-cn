 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个可变序列数据结构，有效支持四种操作：

 1. 将一个值附加到序列中。 
2. 为序列中当前的每个元素添加一个常量值。 
3. 将序列中当前的每个元素乘以一个常数。 
4. 检索特定索引处的值。 

所有返回值必须取模`10^9 + 7`。 

关键的困难在于序列可以增长到多达`10^5`操作，以及操作`addAll`和`multAll`影响每个现有元素。 每次显式更新每个数字的幼稚实现很快就会变得太慢。 

该序列随着时间的推移而演变。 当我们打电话时`addAll`或者`multAll`，只有序列中已经存在的元素受到影响。 未来附加的元素不应继承过去的操作。 这个细节非常重要。 

例如：```
append(2)      -> [2]
addAll(3)      -> [5]
append(7)      -> [5, 7]
```新追加的`7`没有收到之前的`+3`。 

这些限制强烈表明我们需要接近恒定时间的操作：

 - 最多`10^5`总运营
 - 每项操作必须高效
 - 重复的全阵列更新不可行

 另一个重要的观察是所有更新都是以下形式的线性变换：```
x -> a*x + b
```加法和乘法都可以这样表示：```
addAll(inc): x -> x + inc
multAll(m):  x -> m*x
```这一观察直接导致最优解。 

重要的边缘情况包括：

 - 通话`getIndex`索引超出范围
 - 多个链式乘法和加法
 - 乘以零
 - 需要模运算的大中间值
 - 在许多全局操作之后附加值

 所有算术必须一致地使用模`10^9 + 7`。 

## 方法

 ### 蛮力方法

 最直接的解决方案是直接存储整个序列。 

-`append(val)`推动`val`进入数组。 
-`addAll(inc)`迭代每个元素并添加`inc`。 
-`multAll(m)`迭代每个元素并乘以`m`。 
-`getIndex(idx)`如果索引存在则返回值。 

这种方法是正确的，因为每个操作都按照描述直接修改底层序列。 

然而，它太慢了。 如果我们执行`10^5`操作，其中许多是`addAll`或者`multAll`，每个要求`O(n)`更新后，总运行时间可能会降级为`O(n^2)`。 

### 最佳方法

 关键的见解是每个全局操作都可以表示为线性变换：```
x -> mul*x + add
```我们不更新每个存储的元素，而是维护两个全局参数：

 -`global_mul`-`global_add`这些描述了应用于每个存储值的转换。 

当我们附加一个新值时，我们会存储它的标准化版本，以便将来仍然可以正确应用转换。 

假设当前的变换是：```
x -> global_mul*x + global_add
```如果我们附加值`v`，我们想要：```
global_mul*stored + global_add = v
```解决`stored`:```
stored = (v - global_add) / global_mul
```由于模算术下的除法需要模逆：```
stored = (v - global_add) * inverse(global_mul)
```现在所有未来的更新都可以通过仅调整来延迟表示`global_mul`和`global_add`。 

这提供了接近恒定时间的操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次更新 O(n) | O(n) | 显式更新所有元素 |
 | 最佳 | O(1) 摊销 | O(n) | 使用惰性仿射变换 |

 ## 算法演练

 1. 初始化一个空数组，名为`values`。 

该数组不会存储文字可见序列值。 相反，它存储标准化值，稍后可以使用当前全局转换来转换这些值。 
2.维护两个全局变量：```
global_mul = 1
global_add = 0
```这些表示当前应用于每个存储元素的仿射变换。 
3.为了`append(val)`:

 可见值应该恰好变成`val`在插入时。 

由于所有存储的值都是通过以下方式解释的：```
visible = stored * global_mul + global_add
```我们反转变换：```
stored = (val - global_add) * inverse(global_mul)
```将此标准化值存储到数组中。 
4. 对于`addAll(inc)`:

 每个可见值都变为：```
x -> x + inc
```所以我们简单更新一下：```
global_add += inc
```5. 对于`multAll(m)`:

 每个可见值都变为：```
x -> x * m
```扩大当前转型：```
x -> (global_mul*x + global_add) * m
```所以：```
global_mul *= m
global_add *= m
```6. 对于`getIndex(idx)`:

 如果索引无效，则返回`-1`。 

否则重建可见值：```
visible = stored * global_mul + global_add
```返回结果取模`10^9 + 7`。 

### 为什么它有效

 不变的是，每个存储的数字都代表应用当前全局变换之前的归一化值。 

随时：```
visible_value = stored_value * global_mul + global_add
```所有更新都保留了这一不变性。 由于加法和乘法组成仿射变换，因此我们可以延迟更新并在需要时正确重建值。 

## Python 解决方案```python
class Fancy:

    MOD = 10**9 + 7

    def __init__(self):
        self.values = []
        self.global_mul = 1
        self.global_add = 0

    def mod_inverse(self, x: int) -> int:
        return pow(x, self.MOD - 2, self.MOD)

    def append(self, val: int) -> None:
        normalized = (
            (val - self.global_add)
            * self.mod_inverse(self.global_mul)
        ) % self.MOD

        self.values.append(normalized)

    def addAll(self, inc: int) -> None:
        self.global_add = (self.global_add + inc) % self.MOD

    def multAll(self, m: int) -> None:
        self.global_mul = (self.global_mul * m) % self.MOD
        self.global_add = (self.global_add * m) % self.MOD

    def getIndex(self, idx: int) -> int:
        if idx >= len(self.values):
            return -1

        return (
            self.values[idx] * self.global_mul
            + self.global_add
        ) % self.MOD

# Your Fancy object will be instantiated and called as such:
# obj = Fancy()
# obj.append(val)
# obj.addAll(inc)
# obj.multAll(m)
# param_4 = obj.getIndex(idx)
```其实现紧密遵循仿射变换的思想。 

构造函数初始化：

 - 标准化存储阵列
 - 乘法变换
 - 加法变换

 的`mod_inverse`helper 使用费马小定理计算模逆：```python
x^(MOD-2) mod MOD
```这有效是因为`10^9 + 7`是素数。 

这`append`方法反转当前转换，以便插入的元素完全按照请求显示。 

这`addAll`方法仅改变变换的加法分量。 

这`multAll`方法同时缩放乘法和加法分量，因为乘法分布在整个仿射表达式中。 

这`getIndex`方法延迟重建当前可见值。 

## 解决方案```go
package main

const MOD int64 = 1_000_000_007

type Fancy struct {
	values    []int64
	globalMul int64
	globalAdd int64
}

func Constructor() Fancy {
	return Fancy{
		values:    []int64{},
		globalMul: 1,
		globalAdd: 0,
	}
}

func modPow(base, exp int64) int64 {
	result := int64(1)

	for exp > 0 {
		if exp&1 == 1 {
			result = (result * base) % MOD
		}

		base = (base * base) % MOD
		exp >>= 1
	}

	return result
}

func modInverse(x int64) int64 {
	return modPow(x, MOD-2)
}

func (this *Fancy) Append(val int) {
	normalized := (
		(int64(val)-this.globalAdd+MOD)%MOD *
			modInverse(this.globalMul),
	) % MOD

	this.values = append(this.values, normalized)
}

func (this *Fancy) AddAll(inc int) {
	this.globalAdd = (this.globalAdd + int64(inc)) % MOD
}

func (this *Fancy) MultAll(m int) {
	this.globalMul = (this.globalMul * int64(m)) % MOD
	this.globalAdd = (this.globalAdd * int64(m)) % MOD
}

func (this *Fancy) GetIndex(idx int) int {
	if idx >= len(this.values) {
		return -1
	}

	result := (
		this.values[idx]*this.globalMul +
			this.globalAdd,
	) % MOD

	return int(result)
}

/**
 * Your Fancy object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Append(val);
 * obj.AddAll(inc);
 * obj.MultAll(m);
 * param_4 := obj.GetIndex(idx);
 */
```Go 解决方案密切反映了 Python 实现。 

Go 特有的主要差异是：

 - 明确使用`int64`以避免溢出
 - 手动模幂实现
 - 切片处理而不是 Python 列表
 - 没有内置的模块化逆助手

 Go 需要仔细进行类型转换`int`和`int64`算术期间。

 ## 边缘情况

 一种重要的边缘情况是访问无效索引。 由于序列大小动态变化，很容易意外读取超出数组范围。 该实现显式检查是否`idx >= len(values)`并返回`-1`立即地。 

另一个棘手的情况是在多次全局转换后附加元素。 幼稚的实现可能会意外地将旧操作应用于新插入的元素。 归一化步骤通过在存储之前反转当前的仿射变换来防止此问题。 

第三个重要情况涉及非常大的值和重复操作。 如果没有模运算，数字很快就会溢出标准整数范围。 实现中的每个算术运算都会减少模数`10^9 + 7`，保证正确性并防止溢出问题。 

乘以零是另一个微妙的情况。 一次`global_mul`变为零，所有先前的元素都会折叠为相同的值。 仿射表示仍然可以正确处理这个问题，因为后续操作会继续一致地转换折叠值。
