 # LeetCode 1640 - 通过串联检查数组构成

 ## 问题理解

 这个问题给了我们两个输入：

 -`arr`，不同整数的一维数组
 -`pieces`，较小整数数组的集合

 目标是确定我们是否可以重新创建`arr`通过连接里面的数组`pieces`以任何顺序。 

重要的限制是我们不允许重新排列单个片段内的元素。 我们可以对整个片段重新排序，但每个片段内的数字顺序必须保持不变。 

例如，如果一块是`[4, 64]`，那么这两个数字必须连续出现，并且在最终构造的数组中完全按照该顺序出现。 我们无法将其转变为`[64, 4]`。 

该问题保证：

 - 中的每个整数`arr`是独一无二的
 - 所有整数中的每个整数`pieces`也是独一无二的
 - 所有部分的整数总数等于`arr`这些保证非常重要，因为它们消除了歧义。 由于所有数字都是不同的，因此中的每个值`arr`只能属于一件。 这使我们能够有效地匹配`arr`针对正确的部分。 

限制非常小：

 -`arr.length <= 100`- 整数总数最多为`100`即使是较慢的解决方案也可以在限制内轻松工作，但该问题自然承认使用哈希图的干净线性时间解决方案。 

需要考虑一些重要的边缘情况：

 - 一块只能包含一个元素
 - 一块可能看起来部分匹配，但后来由于内部顺序不同而失败
 - 中某个段的第一个元素`arr`可能不作为任何作品的开头存在
 - 这些碎片可能已经以正确的顺序出现，或者可能需要完全重新排列

 因为整数是不同的，所以我们永远不需要担心重复匹配或重叠部分。 

## 方法

 ### 蛮力方法

 蛮力策略会尝试所有可能的顺序`pieces`，连接它们，并将结果数组与`arr`。 

假设有`k`件。 我们可以生成所有`k!`片段的排列。 对于每个排列，我们连接所有数组并检查结果是否等于`arr`。 

这种方法是正确的，因为它探索了每一个可能的有效的片段排序。 如果有任何顺序重建`arr`，我们返回`true`。 

然而，随着部件数量的增加，该解决方案变得极其昂贵。 阶乘增长非常快，即使对于中等输入大小，该方法也不切实际。 

### 最佳方法

 关键的观察结果是每个数字都是唯一的。 

这意味着当我们遇到一个值时`arr`，最多有一个片段可以以该值开始。 因此，我们可以使用哈希图直接定位正确的部分，而不是尝试排列。 

我们构建一个映射：

 - key = 一块的第一个数字
 - 价值 = 整件

 然后我们扫描一下`arr`从左到右。 

在每个位置：

 1.在哈希图中查找当前数字
 2. 检索匹配的棋子
 3. 验证该片段的每个元素是否与该片段的相应部分相匹配`arr`如果出现任何不匹配的情况，则返回`false`。 

如果我们成功完成扫描，则返回`true`。 

这是有效的，因为每个部分都必须显示为内部的连续块`arr`，并且不同的整数保证映射是明确的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k! * n) | O(k! * n) | O(n) | 尝试每一个片段的排列 |
 | 最佳 | O(n) | O(n) | 使用哈希图直接匹配棋子 |

 这里：

-`n`是整数的总数
 -`k`是件数

 ## 算法演练

 1. 创建一个哈希映射，其中键是每个片段的第一个整数，值是整个片段。 

这允许在处理时恒定时间查找正确的部分`arr`。 
2. 初始化一个索引变量`i = 0`。 

该索引跟踪我们当前的位置`arr`。 
3.同时`i`小于的长度`arr`，执行以下操作：

 - 检查是否`arr[i]`作为哈希映射中的键存在。 
- 如果不存在，则返回`false`立即，因为没有任何作品可以以此数字开头。 
4. 从哈希图中检索对应的片段。 

由于整数是不同的，因此这是唯一可以在这里匹配的部分。 
5. 将乐曲中的每个数字与乐曲中相应的数字进行比较`arr`。 

对于每个元素`value`在作品中：

 - 验证`arr[i] == value`- 如果没有，请返回`false`- 否则递增`i`6. 继续直到所有元素`arr`已被处理。 
7. 如果整个数组匹配成功，则返回`true`。 

### 为什么它有效

 该算法依赖于整数的唯一性。 

因为每个数字在所有片段中都只出现一次，所以片段的第一个数字唯一标识哪个片段必须出现在那里。 一旦我们选择了该部分，其内部顺序就无法更改，因此唯一有效的操作是验证中的下一个元素`arr`完全匹配。 

如果每个片段都成功匹配，则连接识别的片段重建`arr`。 如果发生任何不匹配，则不存在有效的串联。 

## Python 解决方案```python
from typing import List

class Solution:
    def canFormArray(self, arr: List[int], pieces: List[List[int]]) -> bool:
        piece_map = {}

        for piece in pieces:
            piece_map[piece[0]] = piece

        index = 0
        n = len(arr)

        while index < n:
            current = arr[index]

            if current not in piece_map:
                return False

            piece = piece_map[current]

            for value in piece:
                if index >= n or arr[index] != value:
                    return False
                index += 1

        return True
```实现首先构建一个名为的字典`piece_map`。 每个键都是片段的第一个元素，每个值都是片段本身。 

接下来，算法扫描`arr`使用变量`index`。 

对于每个位置`arr`，我们通过查找来确定哪一块必须从那里开始`arr[index]`在字典里。 如果不存在匹配块，则无法形成数组。 

一旦找到正确的部分，我们就会依次将该部分的每个元素与相应的部分进行比较`arr`。 

如果任何时候发生不匹配，函数立即返回`False`。 

如果整个数组都被使用而没有不匹配，则该函数返回`True`。 

## 解决方案```go
func canFormArray(arr []int, pieces [][]int) bool {
	pieceMap := make(map[int][]int)

	for _, piece := range pieces {
		pieceMap[piece[0]] = piece
	}

	index := 0
	n := len(arr)

	for index < n {
		current := arr[index]

		piece, exists := pieceMap[current]
		if !exists {
			return false
		}

		for _, value := range piece {
			if index >= n || arr[index] != value {
				return false
			}
			index++
		}
	}

	return true
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

一个`map[int][]int`用于将每个起始值与其相应的片段相关联。 然后算法会迭代`arr`，逐一检索和验证片段。 

Go 切片自然而然地可以有效地处理可变长度的片段，因此不需要额外的数据结构。 

整数溢出不是问题，因为所有值都非常小并且不执行算术运算。

 ## 边缘情况

 ### 缺少起始元素

 当某些值出现时，就会出现一个非常重要的边缘情况`arr`不作为任何作品的第一个元素出现。 

例如：```
arr = [1, 2, 3]
pieces = [[2, 3]]
```当算法开始于`arr[0] = 1`，它找不到以`1`。 这立即证明重建是不可能的。 

该实现通过以下方式安全地处理此问题：```
if current not in piece_map:
    return False
```### 内部排序不匹配

 当所有数字都存在但片段内的顺序不匹配时，会发生另一种严重情况`arr`。 

例子：```
arr = [1, 2, 3]
pieces = [[1, 3], [2]]
```这件作品`[1, 3]`无法融入`arr`因为匹配后`1`，下一个值`arr`是`2`， 不是`3`。 

实现在逐个元素比较期间正确检测到这一点。 

### 单元素件

 某些输入仅包含单元素片段。 

例子：```
arr = [4, 5, 6]
pieces = [[6], [4], [5]]
```这有效地减少了检查所有值是否存在的问题。 

该算法自然会处理这个问题，因为每个比较循环只运行一次。 

### 单件覆盖整个阵列

 当一个片段已经包含整个数组时，会出现另一种边缘情况。 

例子：```
arr = [7, 8, 9]
pieces = [[7, 8, 9]]
```该算法一次性正确匹配整个片段并返回`true`。 

这验证了该解决方案适用于许多小部件和一个大部件。
