[LeetCode 问题 1684](https://leetcode.com/problems/count-the-number-of-concient-strings/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串、位操作、计数

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定有多少个字符串`words`数组与给定的允许字符集**一致**。 

您有两个输入：

 -`allowed`, a string containing distinct lowercase English letters.
 -`words`，小写字符串数组。 

如果**该单词中的每个字符都存在于内部，则该单词被认为**一致**`allowed`**。 如果其中不存在一个字符`allowed`，这个词不一致，不应该算。 

简单来说，我们可以想到`allowed`作为有效字符的白名单。 中的每一个字`words`必须逐个字符进行检查，以确保它仅包含此白名单中的字符。 

例如，如果：```
allowed = "ab"
```那么有效的单词可能只包含`'a'`和`'b'`。 

-`"aaab"`有效，因为每个字母都是`'a'`或者`'b'`-`"baa"`出于同样的原因也是有效的
 -`"ad"`无效，因为`'d'`不允许

 预期输出是一个整数，表示一致字符串的总数。 

### 了解限制

 这些约束为我们的解决方案需要达到的效率提供了有用的见解：

 -`1 <= words.length <= 10^4`-`1 <= allowed.length <= 26`-`1 <= words[i].length <= 10`最重要的观察是`allowed`最多 **26 个字符**，因为它只包含小写英文字母。 这意味着我们可以有效地将允许的字符存储在针对快速成员资格查找而优化的结构中。 

所有单词的字符总数也相对较少：```
10^4 words × 10 characters = at most 100,000 characters
```这告诉我们一个`O(total_characters)`解决方案是完全可以接受的。 

### 重要的边缘案例

 一些边缘情况值得尽早识别。 

具有单个无效字符的单词应立即被拒绝。 例如：```
allowed = "abc"
word = "abx"
```的存在`'x'`单独使这个词不一致。 

这`allowed`字符串只能包含一个字符：```
allowed = "a"
words = ["a", "aa", "aaa", "ab"]
```只有词完全由`'a'`是有效的。 

所有的词可能已经是一致的：```
allowed = "abc"
words = ["a", "ab", "abc"]
```在这种情况下，结果等于单词数。 

相反，没有一个词可以是一致的：```
allowed = "a"
words = ["b", "bc", "xyz"]
```结果将是`0`。 

该问题保证了几个有用的条件：

 -`allowed`包含**不同的字符**，因此我们不需要处理重复项。 
- 所有输入仅包含**小写英文字母**，这使得字符检查变得简单。 
- 每个单词至少有一个字符。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是反复搜索`allowed`每个单词中每个字符的字符串。 

对于每个单词：

 1. 迭代每个字符。 
2. 检查里面是否存在该字符`allowed`。 
3. 如果缺少任何字符，则拒绝该单词。 
4. 否则，视为一致。 

自从`allowed`是一个字符串，检查成员资格需要线性扫描它。 

例如：```
allowed = "abc"
word = "ac"
```验证`'a'`，我们扫描`"abc"`。 

验证`'c'`，我们扫描`"abc"`再次。 

这可以正常工作，因为每个字符都经过显式验证。 但反复扫描`allowed`执行多次后会变得低效。 

### 最佳解决方案的关键见解

 关键的观察是我们反复问同样的问题：

 > “允许使用这个字符吗？”

 而不是扫描`allowed`每次字符串，我们都应该将其预处理为支持**恒定时间成员资格检查**的数据结构。 

**哈希集**对此非常理想。 

我们转换：```
allowed = "abc"
```进入：```
{'a', 'b', 'c'}
```现在检查是否`'a'`或者`'c'`允许成为平均值`O(1)`手术。 

然后：

 1. 构建一组允许的字符。 
2. 迭代每个单词。 
3. 验证集合中是否存在每个字符。 
4. 计算有效单词数。 

由于每个字符仅检查一次，因此这与字符总数呈线性关系。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(宽×长×高) | O(1) | O(1) | 扫描`allowed`对于每个角色，其中`W`是单词数，`L`是平均字长，`A`的长度是`allowed`|
 | 最佳 | O(宽 × 长) | O(A) | 使用哈希集进行恒定时间字符查找 |

 在哪里：

-`W`= 字数
 -`L`= 平均字长
 -`A`= 的长度`allowed`自从`A ≤ 26`，额外的内存很小。 

## 算法演练

 ### 分步过程

 1. **转换`allowed`到哈希集**

 我们将每个角色放置在`allowed`成一个集合，这样成员资格检查就会变得很快。 

例子：```
allowed = "cad"
```变成：```
{'c', 'a', 'd'}
```2. **初始化一个计数器**

 我们维护一个名为`consistent_count`跟踪有多少单词是有效的。 

最初：```
consistent_count = 0
```3. **迭代每个单词**

 对于其中的每个单词`words`，我们测试是否允许所有字符。 
4. **检查单词中的每个字符**

 迭代当前单词的字符。 

如果任何字符不存在于允许的集合中：

 - 将单词标记为不一致
 - 立即停止检查该词

 这种提前停止可以避免不必要的工作。 
5. **计算有效字数**

 如果我们检查完一个单词而没有发现无效字符，则增加计数器。 
6. **返回最终计数**

 处理完所有单词后，返回一致字符串的总数。 

### 为什么它有效

 该算法之所以有效，是因为每个单词都根据一致性的确切定义进行验证。 

一个单词是一致的**当且仅当**每个字符都属于`allowed`。 哈希集准确地存储了允许的字符，因此检查成员资格可以直接验证此条件。 

不变量是：

 > 仅当每个字符都通过成员资格测试时才算单词。 

由于每个单词都会被检查并立即排除无效单词，因此保证最终计数是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def countConsistentStrings(self, allowed: str, words: List[str]) -> int:
        allowed_chars = set(allowed)
        consistent_count = 0

        for word in words:
            is_consistent = True

            for char in word:
                if char not in allowed_chars:
                    is_consistent = False
                    break

            if is_consistent:
                consistent_count += 1

        return consistent_count
```实现从转换开始`allowed`进入一个名为`allowed_chars`。 此预处理步骤可实现恒定时间的成员资格检查。 

然后我们初始化`consistent_count`，它存储迄今为止找到的有效单词的数量。 

对于每个单词，我们通过设置来假设它是有效的`is_consistent = True`。 

我们迭代单词中的每个字符。 如果我们遇到一个不存在的角色`allowed_chars`，该词无效。 我们设定`is_consistent`到`False`并立即停止处理该单词使用`break`。 

这种提前终止提高了效率，因为没有理由继续检查已经无效的单词。 

处理完单词后，如果`is_consistent`仍然是`True`，我们递增计数器。 

最后，我们返回总数。 

## 解决方案```go
func countConsistentStrings(allowed string, words []string) int {
	allowedChars := make(map[rune]bool)

	for _, ch := range allowed {
		allowedChars[ch] = true
	}

	consistentCount := 0

	for _, word := range words {
		isConsistent := true

		for _, ch := range word {
			if !allowedChars[ch] {
				isConsistent = false
				break
			}
		}

		if isConsistent {
			consistentCount++
		}
	}

	return consistentCount
}
```Go 实现遵循与 Python 版本相同的算法结构。 

而不是Python`set`, Go 使用`map[rune]bool`模拟恒定时间的成员资格检查。 

我们迭代一遍`allowed`并将每个字符标记为`true`在地图中。 

对于每个单词，我们验证每个字符是否都存在于地图中。 如果出现无效字符，我们立即停止检查。 

由于输入仅包含小写英文字母，因此不必担心整数溢出。 Go 切片自然地处理空和非空输入，并且约束保证至少一个单词。

 ## 边缘情况

 ### 只允许使用一个字符

 错误的常见来源是`allowed`仅包含一个字符。 

例子：```
allowed = "a"
words = ["a", "aa", "aaa", "ab"]
```幼稚的实现可能会错误地假设单词内部的唯一性很重要。 然而，重复的字符是完全有效的，只要它们属于`allowed`。 

该实现可以正确处理此问题，因为每个字符都是独立检查的，并且重复的成员资格检查仍然会成功。 

### 结尾附近有无效字符的单词

 考虑：```
allowed = "abc"
word = "abx"
```有缺陷的实现可能会意外地过早停止，或者在仅检查前缀后错误地将单词标记为有效。 

我们的实现按顺序检查字符并在发现后立即拒绝该单词`'x'`。 无论无效字符出现在何处，这都保证了正确性。 

### 没有有效字词

 示例：```
allowed = "a"
words = ["b", "bb", "bc"]
```某些实现可能会意外地错误地初始化计数或过早地增加计数。 

我们的方法**仅在**确认单词中的每个字符都有效后才增加计数器。 因此，如果没有单词通过验证，该方法会正确返回`0`。
