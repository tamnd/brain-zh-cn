[LeetCode 问题 1662](https://leetcode.com/problems/check-if-two-string-arrays-are-equivalent/)

 **难度：** 🟢简单
 **主题：** 数组、字符串

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个字符串数组，`word1`和`word2`。 每个数组代表一个较大的字符串，该字符串是通过按顺序连接其所有元素而形成的。 我们的任务是确定两个数组生成的最终字符串是否完全相同。 

例如，如果：```
word1 = ["ab", "c"]
word2 = ["a", "bc"]
```然后：```
word1 -> "ab" + "c" = "abc"
word2 -> "a" + "bc" = "abc"
```由于两个数组产生相同的最终字符串，所以答案是`true`。 

重要的细节是比较是基于完全连接的结果，而不是基于数组本身的结构。 数组可能具有不同数量的元素，并且字符串之间的边界并不重要。 只有最终的字符序列很重要。 

限制相对较小。 每个数组中的字符总数最多为`10^3`，这意味着即使是简单的方法也足够快。 然而，这个问题旨在测试对字符串处理和有效比较技术的理解。 

输入保证：

 - 每个数组至少包含一个字符串
 - 每个字符串仅包含小写英文字母
 - 总组合字符数是可控的

 考虑几个边缘情况很重要：

 - 具有不同分区但最终字符串相同的数组
 - 具有不同总长度的数组
 - 早期发生不匹配的数组
 - 包含许多非常小的字符串的数组
 - 包含单个大字符串的数组

 幼稚的实现可能会错误地逐个元素地比较数组，而不是比较结果连接的字符串。 

## 方法

 ### 蛮力方法

 最简单的解决方案是将所有字符串连接起来`word1`将所有字符串连接成一个大字符串`word2`到另一个大字符串中，并比较结果。 

在 Python 中，这可以通过使用来完成`"".join(word1)`和`"".join(word2)`。 在 Go 中，我们可以使用字符串生成器或重复连接。 

这种方法之所以有效，是因为问题定义直接指出每个数组代表其元素的串联。 一旦我们构造了两个完整的字符串，检查相等性就变得微不足道了。 

缺点是我们为连接的字符串分配额外的内存。 尽管约束足够小，这是完全可以接受的，但它并不是内存效率最高的解决方案。 

### 最佳方法

 一种更有效的方法是逐个比较字符，而不构建完整的字符串。 

关键的见解是我们实际上并不需要连接的字符串本身。 我们只需要验证两个数组是否生成相同的字符序列。 

我们可以维护：

 - 当前字符串的索引`word1`- 该字符串中当前字符的索引
 - 同一对索引`word2`在每一步中，我们都会比较两个数组中的当前字符。 如果它们不同，我们立即返回`false`。 如果它们匹配，我们将相应的字符指针前进。 当到达字符串末尾时，我们移动到数组中的下一个字符串。 

这避免了创建临时连接字符串并以流方式执行比较。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n + m) | O(n + m) | 在比较之前构建完整的串联字符串 |
 | 最佳 | O(n + m) | O(1) | O(1) | 直接比较字符，无需额外的字符串分配 |

 这里，`n`和`m`是字符总数`word1`和`word2`。 

## 算法演练

 1.初始化四个指针：

 -`i`为当前字符串索引`word1`-`j`为里面的当前字符索引`word1[i]`-`k`为当前字符串索引`word2`-`l`为里面的当前字符索引`word2[k]`2. 当两个数组仍包含要处理的字符时继续循环。 
3.比较当前字符：```
word1[i][j] vs word2[k][l]
```如果不同，立即返回`false`因为所表示的字符串不能相等。 
4. 使两个字符指针前进：

 - 增量`j`- 增量`l`5.如果`j`达到的长度`word1[i]`，移至下一个字符串：

 - 增量`i`- 重置`j`到`0`6. 如果`l`达到的长度`word2[k]`，移至下一个字符串：

 - 增量`k`- 重置`l`到`0`7. 继续，直到完全处理一个或两个阵列。 
8.最后返回`true`仅当两个数组同时被完全消耗时。 

### 为什么它有效

 该算法保持了所有先前比较的字符都相等的不变性。 在每一步中，它都会比较逻辑连接字符串中的下一个字符。 由于字符是按顺序处理的，并且每个字符都必须匹配，因此算法可以正确确定所表示的字符串是否相同。 

## Python 解决方案```python
from typing import List

class Solution:
    def arrayStringsAreEqual(self, word1: List[str], word2: List[str]) -> bool:
        i = j = 0
        k = l = 0

        while i < len(word1) and k < len(word2):
            if word1[i][j] != word2[k][l]:
                return False

            j += 1
            l += 1

            if j == len(word1[i]):
                i += 1
                j = 0

            if l == len(word2[k]):
                k += 1
                l = 0

        return i == len(word1) and k == len(word2)
```该实现完全遵循基于指针的算法。 

变量`i`和`j`跟踪内部当前位置`word1`， 尽管`k`和`l`跟踪内部当前位置`word2`。 

在循环内，算法一次比较一个字符。 如果发现不匹配，则立即返回`False`。 

每次成功比较后，字符指针向前移动。 当指针到达当前字符串的末尾时，算法前进到下一个字符串并将字符位置重置为零。 

最后，该解决方案验证两个阵列是否已完全消耗。 这可以确保所表示的字符串都不包含额外的不匹配字符。 

## 解决方案```go
func arrayStringsAreEqual(word1 []string, word2 []string) bool {
	i, j := 0, 0
	k, l := 0, 0

	for i < len(word1) && k < len(word2) {
		if word1[i][j] != word2[k][l] {
			return false
		}

		j++
		l++

		if j == len(word1[i]) {
			i++
			j = 0
		}

		if l == len(word2[k]) {
			k++
			l = 0
		}
	}

	return i == len(word1) && k == len(word2)
}
```Go 的实现与 Python 解决方案非常相似。 

Go 字符串是字节索引的，这里可以正常工作，因为问题只保证小写英文字母。 如果涉及 Unicode 字符，我们将需要符文处理。 

该解决方案将整数索引直接用于字符串切片和字符位置。 由于约束很小，因此不必担心整数溢出。 

Nil 切片和空切片不是问题，因为约束保证每个数组中至少有一个字符串。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 两个数组中的每个字符最多被访问一次 |
 | 空间| O(1) | O(1) | 仅使用了少数索引变量 |

 该算法对两个表示的字符串执行一次传递。 由于每个字符只处理一次，因此运行时间与总输入大小呈线性关系。 

该解决方案使用恒定的额外内存，因为它仅存储索引指针，并且不分配额外的串联字符串。

 ## 边缘情况

 一种重要的边缘情况是数组具有不同的分区边界但仍然表示相同的最终字符串。 例如：```
["ab", "c"] vs ["a", "bc"]
```直接比较数组元素的有缺陷的实现会错误地返回`false`。 基于指针的解决方案避免了这个问题，因为它按顺序比较字符而不是比较数组结构。 

另一个重要的边缘情况是总长度不同。 例如：```
["abc"] vs ["ab"]
```即使所有比较的字符最初都匹配，一个表示的字符串也会更早结束。 该实现通过在返回之前检查两个数组是否同时完全消耗来正确处理此问题`true`。 

第三个重要的边缘情况是跨字符串边界发生的不匹配。 例如：```
["ab", "x"] vs ["a", "bc"]
```仅在从一个字符串段移动到另一字符串段后才会发生不匹配。 指针转换逻辑通常是 off by one 错误的根源，但每当到达字符串末尾时，此实现都会仔细重置字符索引，以确保跨边界正确地继续比较。
