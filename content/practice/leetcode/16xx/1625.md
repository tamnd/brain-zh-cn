[LeetCode 问题 1625](https://leetcode.com/problems/lexicographyally-smallest-string-after-applying-operations/)

 **难度：** 🟡 中等
 **主题：** 字符串、深度优先搜索、广度优先搜索、枚举

 ## 解决方案

 ## 问题理解

 问题给了我们一个数字字符串`s`长度为偶数且两个操作可以按任意顺序执行任意次数。 

第一个操作将整数相加`a`位于奇数索引处的每个数字。 由于数字必须保留在`0`和`9`，加法使用模进行环绕`10`。 例如，如果一个数字是`8`我们添加`5`，结果变为`3`。 

第二个操作将字符串向右旋转`b`职位。 旋转会改变出现在奇数和偶数索引处的数字，这非常重要，因为加法运算仅影响奇数索引。 

我们的任务是找到重复执行这些操作后可以到达的字典顺序最小的字符串。 

字典顺序较小的字符串的确定方式与字典中单词的排序方式相同。 我们从左到右比较字符，第一个较小的数字决定较小的字符串。 

限制相对较小：

 -`s.length <= 100`- 仅限数字
 - 长度始终是偶数

 尽管字符串长度很小，但如果简单地探索，操作序列的数量可能会变得巨大。 由于操作可以无限重复，我们需要一种方法来避免重复访问相同的状态。 

重要的观察是不同的可达字符串的数量是有限的。 每个字符只能取十个值之一，并且旋转也是有限的。 这自然建议使用广度优先搜索或深度优先搜索与访问集进行图遍历。 

一些边缘情况很重要：

 - 如果旋转`b`永远不会改变奇偶校验位置，某些数字可能永远无法修改。 
- 如果`a`和`10`共享因子，重复相加可能不会生成所有数字。 
- 原始字符串本身可能已经是字典顺序上最小的答案。 
- 什么时候`b`是奇数，旋转可以在偶数和奇数位置之间移动数字，从而允许最终修改所有位置。 
- 什么时候`b`是偶数，只能改变原来的奇数位置。 

正确的解决方案必须仔细探索所有可到达的状态，而不会出现无限循环。 

## 方法

 ### 蛮力方法

 最直接的想法是递归地尝试每个可能的操作序列并跟踪遇到的最小字符串。 

从每个州，我们可以：

 1. 应用添加操作。 
2. 应用旋转操作。 
3. 从两个结果状态继续递归。 

这种方法是正确的，因为最终会探索每个可能的操作序列。 

然而，问题是操作可能会永远重复。 在不记住之前看到的状态的情况下，搜索立即进入循环。 例如，重复旋转最终会返回到原始字符串。 

即使我们添加循环检测，简单的暴力实现仍然可能会重复地重新计算转换并低效地探索状态。 

### 关键见解

 关键的观察是问题形成了一个图：

 - 每个唯一的字符串都是一个节点。 
- 每个操作都会创建到相邻状态的边缘。 

由于不同的可达字符串的数量是有限的，我们可以从以下位置开始执行图遍历`s`。 

广度优先搜索或深度优先搜索都有效，因为我们没有最小化操作数量。 我们只需要字典顺序上最小的可达状态。 

遍历过程中：

 - 维持一个`visited`设置以避免多次处理同一字符串。 
- 对于每个新发现的状态，将其与当前的最佳答案进行比较。 
- 生成两个相邻状态：

 - Add operation
 - Rotate operation

 最终，所有可达状态都被探索一次。 

这将无限操作问题转化为有限图遍历问题。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数/无界| 指数| 反复探索循环和操作顺序|
 | 最优 BFS/DFS 图遍历 | O(N × S) | O(S) | 探索每个可达状态一次 |

 在哪里：

-`N`是字符串长度
 -`S`是可达状态的数量

 由于每个状态生成两个邻居并且字符串操作成本`O(N)`，总运行时间变得可控。 

## 算法演练

 ### 最优 BFS 算法

 1. 使用起始字符串初始化队列`s`。 

我们从初始状态开始图遍历。 
2. 创建一个`visited`设置并插入`s`。 

这可以防止无限循环和重复处理。 
3. 将答案初始化为`s`。 

由于原始字符串可以通过零操作到达，因此它是我们的初始候选者。 
4. 当队列不为空时，删除前面的字符串。 

每个弹出的字符串代表一个可达状态。 
5. 将当前字符串与最佳答案进行比较。 

如果当前字符串按字典顺序较小，则更新答案。 
6. 生成添加操作生成的字符串。 

对于每个奇数索引：

 - 将数字转换为整数。 
- 添加`a`。 
- 应用模数`10`。 
- 转换回字符。 
7. 如果添加生成的字符串未被访问过：

 - 添加到`visited`- 将其推入队列
 8. 生成旋转后的字符串。 

向右旋转`b`使用切片的位置：

 - 最后`b`字符移动到前面。 
- 其余角色随后跟进。 
9. 如果旋转后的字符串未被访问过：

 - 添加到`visited`- 将其推入队列
 10. 继续，直到队列变空。 

至此，每个可到达的字符串都已被探索过。 
11. 返回找到的最小字符串。 

### 为什么它有效

 该算法之所以有效，是因为操作定义了有限状态图。 BFS 使用以下方法系统地探索每个可达状态一次`visited`放。 由于考虑了每个可达字符串，并且我们不断跟踪字典顺序最小的字符串，因此最终答案必须是最小的可达字符串。 

## Python 解决方案```python
from collections import deque
from typing import Set

class Solution:
    def findLexSmallestString(self, s: str, a: int, b: int) -> str:
        def add_operation(current: str) -> str:
            chars = list(current)

            for i in range(1, len(chars), 2):
                digit = (int(chars[i]) + a) % 10
                chars[i] = str(digit)

            return "".join(chars)

        def rotate_operation(current: str) -> str:
            return current[-b:] + current[:-b]

        visited: Set[str] = set([s])
        queue = deque([s])

        smallest = s

        while queue:
            current = queue.popleft()

            if current < smallest:
                smallest = current

            added = add_operation(current)

            if added not in visited:
                visited.add(added)
                queue.append(added)

            rotated = rotate_operation(current)

            if rotated not in visited:
                visited.add(rotated)
                queue.append(rotated)

        return smallest
```实现直接遵循图遍历算法。 

这`add_operation`helper 将字符串转换为可变列表，以便可以有效地更新奇数索引数字。 每个数字递增`a`并使用模包裹`10`。 

这`rotate_operation`helper 使用 Python 切片将字符串向右旋转`b`职位。 

队列用于BFS遍历，`visited`set 保证每个可达状态仅被处理一次。 

在遍历过程中，使用普通字符串比较将每个当前状态与当前最佳答案进行比较，该比较已经在 Python 中正确执行字典排序。 

## 解决方案```go
package main

func findLexSmallestString(s string, a int, b int) string {
	addOperation := func(current string) string {
		chars := []byte(current)

		for i := 1; i < len(chars); i += 2 {
			digit := int(chars[i]-'0')
			digit = (digit + a) % 10
			chars[i] = byte(digit) + '0'
		}

		return string(chars)
	}

	rotateOperation := func(current string) string {
		n := len(current)
		return current[n-b:] + current[:n-b]
	}

	queue := []string{s}
	visited := map[string]bool{
		s: true,
	}

	smallest := s

	for len(queue) > 0 {
		current := queue[0]
		queue = queue[1:]

		if current < smallest {
			smallest = current
		}

		added := addOperation(current)

		if !visited[added] {
			visited[added] = true
			queue = append(queue, added)
		}

		rotated := rotateOperation(current)

		if !visited[rotated] {
			visited[rotated] = true
			queue = append(queue, rotated)
		}
	}

	return smallest
}
```Go 的实现与 Python 解决方案非常相似。 

由于 Go 字符串是不可变的，因此添加操作会在修改数字之前将字符串转换为字节切片。 

队列是使用切片来实现的。 移除前面的元件是这样完成的`queue = queue[1:]`。 

字符串之间的字典顺序比较直接与`<`Go 中的运算符，因此不需要自定义比较器。 

整数溢出不是问题，因为所有数字算术都保持在很小的范围内。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`b`是均匀的。 在这种情况下，旋转字符串永远不会改变哪些索引是奇数，哪些是偶数。 原来位于偶数位置的数字始终保留在偶数位置，这意味着它们永远不会被加法运算修改。 有缺陷的实现可能会错误地假设每个数字最终都会改变。 BFS 解决方案自然地处理了这个问题，因为它只探索通过合法操作实际可达的状态。 

另一个重要的情况是，重复加法在到达每个可能的数字之前循环回到原始数字。 例如，如果`a = 2`，重复相加只能达到奇偶校验相同的位数。 幼稚的实现可能会错误地假设所有十位数字都可以访问。 由于该算法显式生成可达状态而不是做出假设，因此它仍然是正确的。 

前导零是另一个微妙的情况。 词典比较非常倾向于较小的前导数字，因此以`'0'`are often optimal. 某些实现会意外地将字符串视为整数并丢失前导零。 该解决方案始终将值保留为字符串，从而保留正确的字典顺序行为。 

当操作重复产生相同的状态时，就会出现最后的边缘情况。 如果没有访问过的集合，搜索将永远循环。 该实现通过存储每个已处理的状态并且从不重新访问它来防止这种情况。
