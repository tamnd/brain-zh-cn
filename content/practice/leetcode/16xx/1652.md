[LeetCode 1652 题](https://leetcode.com/problems/defuse-the-bomb/)

 **难度：** 🟢简单
 **主题：** 数组、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为的圆形数组`code`和一个整数`k`。 我们必须生成一个新数组，其中每个元素都根据 的值进行替换`k`。 

如果`k > 0`，每个元素成为下一个元素的总和`k`圆形数组中的元素。 

如果`k < 0`，每个元素成为前一个元素的总和`|k|`元素。 

如果`k == 0`，每个元素都变成`0`。 

重要的细节是该阵列是圆形的。 这意味着移动到结束位置会回绕到开头，并且在开始位置之前移动到结束位置。 

例如，与：```
code = [5,7,1,4]
k = 3
```第一个元素`5`替换为：```
7 + 1 + 4 = 12
```第二个元素`7`替换为：```
1 + 4 + 5 = 10
```因为索引之后`3`，我们环绕索引`0`。 

限制很小：

 -`1 <= n <= 100`-`1 <= code[i] <= 100`这意味着即使是`O(n^2)`解决方案在技术上会通过。 然而，这个问题是为了练习滑动窗口技术而设计的，所以我们仍然应该以高效的实现为目标。 

一些边缘情况很重要：

 -`k == 0`，每个输出值必须是`0`-`k > 0`，我们必须正确地环绕数组
 -`k < 0`，我们必须正确地向后移动并绕回
 - 具有长度的数组`1`- 价值观`k`附近`n - 1`简单的实现在包装索引时很容易犯一个相差一的错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立计算每个结果。 

对于每个索引`i`：

- 如果`k > 0`, 迭代下一个`k`元素并对它们求和。 
- 如果`k < 0`, 迭代前一个`|k|`元素并对它们求和。 
- 使用模算术环绕圆形数组。 

这种方法很容易理解，并且直接遵循问题陈述。 

对于每个`n`元素，我们可以扫描到`|k|`元素。 自从`|k|`可以大到`n - 1`，总复杂度变为`O(n^2)`。 

尽管这对于给定的约束是可以接受的，但我们可以做得更好。 

### 最优滑动窗口方法

 关键的观察结果是相邻窗口严重重叠。 

认为`k > 0`。 

如果我们已经知道下一个的总和`k`索引号`i`，然后对于索引`i + 1`：

 - 一个元素离开窗口
 - 一个新元素进入窗口

 我们可以在常数时间内更新它，而不是重新计算整个总和。 

这正是滑动窗口技术。 

同样的逻辑适用于`k < 0`，除了窗口的移动方式不同。 

通过维护当前窗口的运行总和，我们将时间复杂度降低到`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 独立重新计算每个总和 |
 | 最佳 | O(n) | O(n) | 使用滑动窗口重用之前的计算 |

 ## 算法演练

 ### 最优滑动窗口算法

 1.首先处理特殊情况`k == 0`。 

如果`k`为零，每个元素都变成`0`，所以我们立即返回一个由零组成的数组。 
2.创建一个长度为result的数组`n`。 

该数组将存储解密的值。 
3. 确定初始滑动窗口边界。 

如果`k > 0`：

 - 第一个窗口包含索引`1`通过`k`- 这些是下一个`k`索引后的元素`0`如果`k < 0`：

 - 第一个窗口包含前一个窗口`|k|`元素
 - 这些对应于索引`n - |k|`通过`n - 1`4. 计算初始窗口总和。 

这给出了索引的解密值`0`。 
5. 迭代每个索引`i`从`0`到`n - 1`。 

对于每个位置：

 - 将当前窗口总和存储到`result[i]`- 将窗口向前滑动一个位置
 6.高效更新滑动窗口。 

移动窗口：

 - 减去离开窗口的元素
 - 添加进入窗口的新元素
 - 使用模运算来环绕圆形数组
 7. 继续，直到处理完所有位置。 

### 为什么它有效

 该算法保持了滑动窗口始终包含当前索引所需的元素的不变性。 

当从一个索引移动到下一个索引时，所需的元素集仅更改一个传出元素和一个传入元素。 更新运行总和可以保持正确性，同时避免重复工作。 

由于每个窗口都会一致更新，并且模算术可以正确处理换行，因此每个结果都可以准确计算。 

## Python 解决方案```python
from typing import List

class Solution:
    def decrypt(self, code: List[int], k: int) -> List[int]:
        n = len(code)

        if k == 0:
            return [0] * n

        result = [0] * n

        if k > 0:
            left = 1
            right = k
        else:
            left = n + k
            right = n - 1

        window_sum = 0

        for i in range(left, right + 1):
            window_sum += code[i % n]

        for i in range(n):
            result[i] = window_sum

            window_sum -= code[left % n]
            left += 1

            right += 1
            window_sum += code[right % n]

        return result
```实现从处理开始`k == 0`单独的情况，因为不需要滑动窗口。 

对于积极的`k`，初始窗口由下一个窗口组成`k`索引后的元素`0`。 

对于负数`k`，初始窗口包含前一个`|k|`索引之前的元素`0`。 

变量`left`和`right`代表当前窗口的边界。 初始窗口总和计算一次。 

在每次迭代期间：

 - 将当前窗口总和分配给答案
 - 最左边的元素被删除
 - 窗口边界向前移动了一步
 - 添加了新的最右边元素

 模运算确保循环行为。 

## 解决方案```go
func decrypt(code []int, k int) []int {
    n := len(code)

    if k == 0 {
        return make([]int, n)
    }

    result := make([]int, n)

    left, right := 0, 0

    if k > 0 {
        left = 1
        right = k
    } else {
        left = n + k
        right = n - 1
    }

    windowSum := 0

    for i := left; i <= right; i++ {
        windowSum += code[i%n]
    }

    for i := 0; i < n; i++ {
        result[i] = windowSum

        windowSum -= code[left%n]
        left++

        right++
        windowSum += code[right%n]
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

切片用于结果数组。 由于约束很小，所以标准`int`算术是完全安全的，不存在溢出问题。 

Go 不支持 Python 风格的负索引，因此所有包装都是使用模算术显式处理的。

 ## 边缘情况

 一个重要的边缘情况是当`k == 0`。 一个常见的错误是仍然尝试滑动窗口逻辑，这可能会创建无效的范围或不正确的总和。 该实现通过返回一个用零填充的数组来立即处理这个问题。 

另一个棘手的情况是负面的`k`。 在循环数组中向后移动更容易出错，因为索引可能会变为负数。 该实现通过仔细定义初始窗口并始终使用模算术来完全避免负索引。 

第三个重要的边缘情况发生在以下情况：`|k|`接近于`n - 1`。 在这些情况下，窗口几乎跨越整个阵列。 不正确的窗口更新可能会意外包含或排除当前元素。 该实现保持精确的左右边界，因此窗口始终包含准确的所需元素。 

大小的数组`1`也值得考虑。 约束保证如果`n == 1`， 然后`k`必须是`0`， 因为`-(n - 1) <= k <= n - 1`。 该实现自然会通过返回来正确处理这种情况`[0]`。
