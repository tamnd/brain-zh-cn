[LeetCode 问题 1664](https://leetcode.com/problems/ways-to-make-a-fair-array/)

 **难度：** 🟡 中等
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`，并要求我们从数组中删除一个元素。 删除该元素后，剩余元素左移，这意味着它们的索引可能会发生变化。 

如果满足以下条件，则数组被认为是公平的：

 - 偶数索引处的元素之和等于奇数索引处的元素之和。 

我们的任务是计算可以删除多少个索引以使结果数组变得公平。 

重要的细节是，删除一个元素会更改其后的所有元素的奇偶性。 删除索引之前的元素保留其原始位置，但删除索引之后的每个元素左移一个位置。 这意味着：

 - 最初位于偶数索引的元素可能会变成奇数。 
- 最初位于奇数索引的元素可能会变成偶数。 

这种奇偶校验翻转是问题的核心挑战。 

例如，考虑：```
nums = [2,1,6,4]
```如果我们删除索引`1`，结果数组变为：```
[2,6,4]
```现在的指数是：```
index: 0 1 2
value: 2 6 4
```偶数索引和为：```
2 + 4 = 6
```奇数索引和为：```
6
```它们是相等的，因此删除索引`1`作品。 

约束条件很重要：

 -`1 <= nums.length <= 10^5`-`1 <= nums[i] <= 10^4`一个`O(n^2)`对于大小的数组来说，解决方案将太慢`100000`。 我们需要一个线性或近线性的解决方案。 

一些边缘情况很重要：

 - 只有一个元素的数组。 
- 每次删除都有效的数组。 
- 无法进行删除的阵列。 
- 删除后奇偶校验发生显着变化的情况。 
- 大小交替的数组。 

幼稚的实现很容易犯错误，因为忘记删除元素移位奇偶校验后的索引。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试将每个索引一一删除。 

对于每个索引：

 1. 创建一个不包含该元素的新数组。 
2. 计算偶数索引元素的总和。 
3. 计算奇数索引元素的总和。 
4. 检查它们是否相等。 

这种方法是正确的，因为它明确地模拟了每一个可能的删除并直接检查公平条件。 

然而，它的效率很低。 

如果数组有`n`要素：

 - 我们尝试`n`搬迁。 
- 每次删除需要扫描最多`n`元素。 

这导致`O(n^2)`时间复杂度。 

和`n = 100000`，这变得太慢了。 

### 最优前缀和方法

 关键的观察结果是删除一个元素后：

 - 删除索引之前的元素保持相同的奇偶校验。 
- 删除索引开关奇偶校验后的元素。 

我们可以预先计算，而不是重复重建数组：

 - 偶数索引元素的总和。 
- 奇数索引元素的总和。 

然后，在遍历数组时，我们维护：

 - 前缀偶数和。 
- 前缀奇数和。 

对于索引处的删除`i`，我们可以计算：

 - 删除后新的偶数索引总和。 
- 删除后新的奇数索引和。 

在恒定的时间内。 

这将总复杂度降低到`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 模拟每次删除并重建阵列 |
 | 最佳 | O(n) | O(1) | O(1) | 使用运行前缀和和奇偶校验交换 |

 ## 算法演练

 ### 第 1 步：计算偶数和奇数总和

 首先，扫描一次数组并计算：

 -`total_even`，偶数索引处的元素之和
 -`total_odd`, 奇数索引处的元素之和

 这些代表删除之前的原始数组。 

### 步骤 2：维护前缀和

 当我们迭代数组时，我们维护：

 -`left_even`, 当前索引之前偶数索引元素的总和
 -`left_odd`, 当前索引之前奇数索引元素的总和

 最初，两者都为零，因为左侧还没有元素。 

### 步骤 3：模拟删除每个索引

 假设我们删除索引`i`。 

该数组分为两部分：

 - 左侧，元素之前`i`- 右侧，之后的元素`i`左侧保持相同的奇偶性。 

右侧更改奇偶校验，因为所有元素左移一位。 

### 步骤 4：计算新的偶数和

 新的偶数索引和包括：

 1. 左侧原始偶数索引元素
 2. 原始奇数索引元素位于右侧，因为它们会移位奇偶校验

 如果`nums[i]`是偶数索引的：```
right_odd = total_odd - left_odd
```如果`nums[i]`是奇数索引：```
right_odd = total_odd - left_odd - nums[i]
```更清晰的统一方法是：```
new_even = left_even + (total_odd - left_odd - removed_if_odd)
```但我们可以在迭代过程中使用直接公式进行简化。 

### 步骤 5：计算新的奇数和

 同样，新的奇数索引和包括：

 1. 左侧原始奇数索引元素
 2. 右侧原始偶数索引元素

 因为右侧翻转了奇偶校验。 

### 步骤 6：比较两个总和

 如果：```
new_even == new_odd
```然后删除索引`i`使数组公平。 

增加答案。 

### 步骤 7：更新前缀和

 处理后指标`i`， 添加`nums[i]`至：

 -`left_even`， 如果`i`是偶数
 -`left_odd`， 如果`i`很奇怪

 然后继续。 

### 为什么它有效

 该算法之所以有效，是因为它正确地模拟了索引在删除后如何变化。 

对于每次删除：

 - 删除索引之前的元素保留奇偶校验。 
- 删除索引翻转奇偶校验后的元素。 

通过将数组分为左右部分并使用前缀和，我们可以在恒定时间内为每个索引重建所得的偶数和奇数和。 

由于每个索引都被检查一次并且奇偶校验转换得到正确处理，因此该算法始终会产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def waysToMakeFair(self, nums: List[int]) -> int:
        total_even = 0
        total_odd = 0

        for i, value in enumerate(nums):
            if i % 2 == 0:
                total_even += value
            else:
                total_odd += value

        left_even = 0
        left_odd = 0
        result = 0

        for i, value in enumerate(nums):
            if i % 2 == 0:
                right_even = total_even - left_even - value
                right_odd = total_odd - left_odd
            else:
                right_even = total_even - left_even
                right_odd = total_odd - left_odd - value

            new_even = left_even + right_odd
            new_odd = left_odd + right_even

            if new_even == new_odd:
                result += 1

            if i % 2 == 0:
                left_even += value
            else:
                left_odd += value

        return result
```该实现首先计算偶数和奇数索引的总和。 这些总数代表任何删除之前的整个阵列。 

接下来，算法迭代数组，同时维护左侧的前缀和。 

对于每个索引：

 - 当前值被暂时删除。 
- 计算剩余的右侧总和。 
- 移除后右侧切换奇偶校验。 
- 重建新的偶数和奇数和。 

如果重建的总和相等，则索引有助于答案。 

最后，当前元素被添加到适当的左侧前缀和中，以便将来的迭代将其视为左侧部分的一部分。 

该实现仅使用恒定的额外空间，并且只处理每个元素一次。 

## 解决方案```go
func waysToMakeFair(nums []int) int {
	totalEven := 0
	totalOdd := 0

	for i, value := range nums {
		if i%2 == 0 {
			totalEven += value
		} else {
			totalOdd += value
		}
	}

	leftEven := 0
	leftOdd := 0
	result := 0

	for i, value := range nums {
		var rightEven int
		var rightOdd int

		if i%2 == 0 {
			rightEven = totalEven - leftEven - value
			rightOdd = totalOdd - leftOdd
		} else {
			rightEven = totalEven - leftEven
			rightOdd = totalOdd - leftOdd - value
		}

		newEven := leftEven + rightOdd
		newOdd := leftOdd + rightEven

		if newEven == newOdd {
			result++
		}

		if i%2 == 0 {
			leftEven += value
		} else {
			leftOdd += value
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 使用显式整数变量而不是 Python 的动态整数。 整数溢出在这里不是问题，因为最大可能的总和是：```go
10^5 * 10^4 = 10^9
```安全地符合 Go 的标准`int`在 LeetCode 平台上输入。 

直接使用切片，不分配额外的数组，空间复杂度保持在`O(1)`。

 该算法处理数组两次：

 1. 第一遍计算总偶数和奇数和。 
2. 第二遍评估每一个可能的移除。 

循环内的每个操作都是恒定时间，因此总运行时间是线性的。 

不需要辅助数组或哈希映射，因此额外的空间使用量保持不变。

 ## 边缘情况

 ### 单元素数组

 如果数组仅包含一个元素，则删除它会留下一个空数组。 

空数组有：```
even sum = 0
odd sum = 0
```这是公平的。 

如果实现假设至少有一个剩余元素，则这种情况很容易被忽视。 当前的解决方案可以自然地处理它，因为两个重建的总和都变为零。 

### 移除后奇偶校验切换

 该问题最容易出错的方面是删除索引之后的元素会更改奇偶校验。 

例如：```
[2,1,6,4]
```去除`1`产生：```
[2,6,4]
```原始偶数索引`6`移位后变为奇数索引。 

有缺陷的实现可能会错误地保留原始奇偶校验分配。 前缀和方法显式地分别对左侧和右侧进行建模，确保正确处理奇偶校验切换。 

### 每次删除都有效的数组

 数组例如：```
[1,1,1]
```无论删除哪个索引，都可以生成公平的数组。 

某些实现在找到第一个有效索引后意外停止，或者在迭代之间错误地重用状态。 该解决方案独立评估每次删除并正确计算所有有效索引。 

### 大输入

 约束允许的数组大小`100000`。 

反复重建阵列的强力解决方案将会超时。 前缀和解决方案避免了重复工作并保证线性性能，即使在最大输入大小下也能保持高效。
