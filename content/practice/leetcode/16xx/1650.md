[LeetCode 问题 1650](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree-iii/)

 **难度：** 🟡 中等
 **主题：** 哈希表、两个指针、树、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到二叉树中两个节点的最低公共祖先，通常缩写为 LCA。 与问题的经典版本不同，每个节点都包含一个指向其父节点的直接指针。 额外的父参考改变了我们有效解决问题的方式。 

输入给我们两个节点，`p`和`q`。 我们保证两个节点已经存在于同一二叉树中的某个位置。 每个节点包含四个字段：```
val
left
right
parent
```这`parent`指针允许我们在树中从任何节点向上移动到其祖先。 

两个节点的最低公共祖先是作为两个节点的祖先的最深节点。 节点被视为其自身的祖先，这对于一个节点直接位于从根到另一节点的路径上的情况很重要。 

例如：

 - 如果`p = 5`和`q = 1`，他们的第一个共同祖先是`3`。 
- 如果`p = 5`和`q = 4`， 然后`5`本身就是答案，因为`5`是的祖先`4`。 

这些约束告诉我们一些重要的事情：

 - 树最多可以包含`10^5`节点，因此我们应该避免低效的重复遍历。 
- 节点值是唯一的，但是问题直接给了我们节点引用，所以我们不需要按值搜索。 
-`p != q`，这简化了一些边缘处理。 
- 保证两个节点存在于同一棵树中。 

最重要的边缘情况是：

 - 一个节点是另一个节点的祖先。 
- LCA 是根。 
- 这棵树极其不平衡，本质上就像一个链表。 
- 两个节点的深度非常不同。 

如果一个幼稚的实现重复地遍历长祖先链，它很容易变得低效。 

## 方法

 ### 蛮力方法

 一种简单的解决方案是收集哈希集中一个节点的所有祖先，然后从另一个节点向上遍历，直到找到集合中已存在的节点。 

该算法的工作原理如下：

 1. 从`p`并使用父指针向上移动。 
2. 将每个访问过的祖先存储在哈希集中。 
3. 从`q`并向上移动。 
4. 该集合中也存在的第一个祖先是 LCA。 

这是有效的，因为每个祖先`p`被记录下来，并从`q`最终到达第一个共同祖先。 

尽管该解决方案在约束条件下已经可以接受，但它需要与树的高度成比例的额外内存。 

### 最佳方法

 更优雅的解决方案使用与两个链表的交集相同的想法。 

由于每个节点都有一个父指针，因此从节点到根的路径就像一个单链表。 因此，我们可以将祖先链视为`p`和`q`就像两个最终相交的链表一样。 

我们使用两个指针：

 - 一开始于`p`- 一开始于`q`每个指针一次向上移动一步。 当指针到达`None`，它切换到另一个节点的起始位置。 

最终，两个指针行进的总距离相同并在 LCA 处相遇。 

关键的见解是切换起始位置可以补偿两个节点之间的深度差异。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(h) | O(h) | 将一个节点的祖先存储在哈希集中 |
 | 最佳 | O(h) | O(1) | O(1) | 类似链表交集的两指针技术 |

 这里，`h`代表树的高度。 

## 算法演练

 ### 最优两指针算法

 1.初始化两个指针：

 -`pointerA = p`-`pointerB = q`每个指针都会向上移向根。 
2. 将两个指针一次向上移动一步。 

在每次迭代时：

 -`pointerA = pointerA.parent`-`pointerB = pointerB.parent`3. 如果指针变成`None`，将其重定向到另一个起始节点。 

具体来说：

 - 如果`pointerA`变成`None`，将其设置为`q`- 如果`pointerB`变成`None`，将其设置为`p`这使得两个指针经过的总路径长度相等。 
4. 继续，直到两个指针相等。 

它们相遇的第一个节点是最低共同祖先。 
5. 返回会议节点。 

### 为什么它有效

 假设距离`p`LCA 是`a`，距离`q`LCA 是`b`，从 LCA 到根的距离是`c`。 

每个指针遍历的总路径变为：```
a + c + b
```切换起点后。 

由于两个指针移动的总距离完全相同，因此它们同步并在 LCA 处相遇。 这与用于链表相交检测的证明相同。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None
        self.parent = None
"""

class Solution:
    def lowestCommonAncestor(self, p: 'Node', q: 'Node') -> 'Node':
        pointer_a = p
        pointer_b = q

        while pointer_a != pointer_b:
            if pointer_a is None:
                pointer_a = q
            else:
                pointer_a = pointer_a.parent

            if pointer_b is None:
                pointer_b = p
            else:
                pointer_b = pointer_b.parent

        return pointer_a
```实现直接遵循两指针策略。 

我们首先分配两个指针，每个节点一个。 在循环的每次迭代期间，两个指针都通过父引用向上移动。 

如果指针到达树的顶部并变为`None`，它被重定向到另一个节点的起始位置。 这个平衡步骤保证了两个指针最终对齐。 

仅当两个指针都指向同一节点时循环才会停止。 该共享节点是 LCA，因此我们返回它。 

该实现使用恒定的额外内存，因为不需要辅助数据结构。 

## 解决方案```go
/**
 * Definition for Node.
 * type Node struct {
 *     Val int
 *     Left *Node
 *     Right *Node
 *     Parent *Node
 * }
 */

func lowestCommonAncestor(p *Node, q *Node) *Node {
    pointerA := p
    pointerB := q

    for pointerA != pointerB {
        if pointerA == nil {
            pointerA = q
        } else {
            pointerA = pointerA.Parent
        }

        if pointerB == nil {
            pointerB = p
        } else {
            pointerB = pointerB.Parent
        }
    }

    return pointerA
}
```Go 的实现与 Python 版本非常相似。 

主要的语言特定差异是使用`nil`而不是`None`。 指针相等性检查在 Go 中很自然地工作，因此我们可以使用以下命令直接比较节点引用`!=`。 

不需要额外的切片、映射或递归，这可以保持内存使用量恒定。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(h) | 每个指针最多遍历两个祖先链 |
 | 空间| O(1) | O(1) | 只使用了两个指针|

 树的高度是主要因素，因为两个指针仅通过父引用向上移动。 即使在最坏的情况下，每个指针在相遇之前最多遍历树高的两倍。 

不需要递归、堆栈或哈希表，因此额外的内存使用量保持不变。

 ## 边缘情况

 ### 一个节点是另一个节点的祖先

 这是 LCA 问题中最重要的边缘情况。 一个常见的错误是只考虑严格的祖先，而忘记节点被视为其自己的后代。 

例如：```
5
 \
  4
```如果`p = 5`和`q = 4`，答案一定是`5`。 

两指针算法很自然地处理这个问题，因为祖先节点直接出现在后代节点的遍历路径中。 

### 极度不平衡的树

 一棵树可能会退化为一个高度接近于的链表`10^5`。 

在这种情况下，递归解决方案可能会面临堆栈溢出的风险。 迭代两指针解决方案完全避免了递归，即使对于最大高度的树也是安全的。 

### 深度不同的节点

 一个节点可能靠近根，而另一个节点可能位于树的深处。 

单纯的同时向上遍历可能会失败，因为更深的节点在对齐之前需要更多的步骤。 指针切换技术通过使两个指针在相遇之前移动的总距离相等来自动解决这个问题。
