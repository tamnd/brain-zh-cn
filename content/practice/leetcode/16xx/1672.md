 # LeetCode 1672 - 最富有的客户财富

 ## 问题理解

 这个问题给了我们一个二维整数数组，称为`accounts`。 每行代表一个客户，每列代表该客户的一个银行帐户。 

价值`accounts[i][j]`代表多少钱`i-th`客户有在`j-th`银行账户。 

我们的任务是计算每个客户的总财富，并返回所有客户中最大的财富。 

客户的财富就是他们所在行中所有价值的总和。 

例如，如果客户有帐户`[1, 2, 3]`，他们的总财富为：$1+2+3=6$我们对每个客户重复这个过程并返回最大的金额。 

限制相对较小：

 -`1 <= m, n <= 50`-`m`是客户数量
 -`n`是每个客户的银行账户数量
 - 每一个平衡都介于`1`和`100`这些限制告诉我们，即使是简单的解决方案也能高效运行。 矩阵最多包含：$50\times50=2500$元素，对于现代计算来说非常小。 

该问题还保证：

 - 每一位客户至少拥有一个银行账户
 - 每个余额都是正值
 - 矩阵是矩形的，这意味着所有行具有相同的列数

 重要的边缘情况包括：

 - 只有一个客户的矩阵
 - 每个客户只有一个银行账户的矩阵
 - 多个客户拥有相同的最大财富
 - 非常小的矩阵，例如`[[5]]`因为保证输入非空，所以我们永远不需要处理无效或空矩阵。 

## 方法

 ### 蛮力方法

 强力解决方案是独立计算每个客户的总财富，并跟踪迄今为止发现的最大价值。 

对于每一行：

 1. 遍历所有银行账户
 2. 将所有余额加在一起
 3. 将总和与当前最大财富进行比较
 4. 如果需要更新最大值

 这是可行的，因为最富有的客户必须是矩阵中的行之一，并且计算每行总和可以保证我们检查每个可能的候选者。 

虽然这种方法被称为暴力，但对于问题约束来说它已经足够有效了，因为我们只访问每个单元一次。 

### 最佳解决方案的关键见解

 重要的观察是该问题仅要求最大行总和。 

我们不需要存储所有客户财富值。 相反，在计算每行总和时，我们可以立即将其与当前最佳答案进行比较。 

这使我们能够以恒定的额外空间一次性处理矩阵。 

由于每个元素必须至少检查一次才能知道真正的财富值，因此任何正确的解决方案都必须至少具有相对于单元格数量的线性复杂度。 因此，单次遍历的方式是最优的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n) | O(米) | 在找到最大价值之前为所有客户储存财富 |
 | 最佳 | O(m × n) | O(1) | O(1) | 同时计算行总和和最大值 |

 ## 算法演练

 1. 初始化一个名为`max_wealth`到`0`。 

该变量跟踪迄今为止发现的最富有的客户。 
2. 遍历每个客户行`accounts`。 

每行包含一个客户的所有银行余额。 
3. 计算当前客户的总财富。 

我们将行中的所有余额加在一起。 在Python中，我们可以使用内置的`sum()`功能。 在 Go 中，我们手动迭代行并累加总数。 
4. 比较当前客户的财富`max_wealth`。 

如果当前财富较大，则更新`max_wealth`。 
5. 继续，直到处理完所有客户。 

到遍历结束时，`max_wealth`包含矩阵中最大的行和。 
6. 返回`max_wealth`。 

### 为什么它有效

 该算法之所以有效，是因为每个客户的财富恰好是矩阵中一行的总和。 通过计算每一行的总和并保持迄今为止看到的最大值，我们保证最终的答案是所有客户中最大的财富。 

整个算法的不变量是：

 > 处理完第一条后`k`顾客，`max_wealth`储存其中最大的财富`k`顾客。 

一旦处理完所有客户，不变式就保证了`max_wealth`是整个矩阵中最丰富的客户财富。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumWealth(self, accounts: List[List[int]]) -> int:
        max_wealth = 0

        for customer_accounts in accounts:
            current_wealth = sum(customer_accounts)
            max_wealth = max(max_wealth, current_wealth)

        return max_wealth
```解决方案从初始化开始`max_wealth`到`0`。 该变量存储迄今为止找到的最佳答案。 

然后我们遍历每一行`accounts`。 每行代表单个客户的银行余额。 

对于每个客户，我们使用 Python 的内置工具计算他们的总财富`sum()`功能。 这可以有效且清晰地生成行总和。 

接下来，我们将当前客户的财富与现有的进行比较`max_wealth`。 如果当前客户更富有，我们会更新答案。 

处理完所有行后，函数返回遍历过程中发现的最大财富。 

该实现直接反映了算法演练，并且仅使用恒定的额外内存。 

## 解决方案```go
func maximumWealth(accounts [][]int) int {
    maxWealth := 0

    for _, customerAccounts := range accounts {
        currentWealth := 0

        for _, balance := range customerAccounts {
            currentWealth += balance
        }

        if currentWealth > maxWealth {
            maxWealth = currentWealth
        }
    }

    return maxWealth
}
```Go 实现遵循与 Python 版本相同的逻辑。 

因为 Go 没有提供内置的`sum()`函数用于切片，我们手动迭代每个客户的帐户并将总数累加到`currentWealth`。 

Go 切片自然地用于矩阵表示。 整数溢出不是问题，因为最大可能的财富是：$50\times100=5000$可以轻松装入标准 Go 中`int`。 

输入约束还保证矩阵非空，因此不需要对空切片进行特殊处理。

 ## 边缘情况

 一种重要的边缘情况是仅包含一个客户的矩阵，例如`[[10, 20, 30]]`。 有缺陷的实现可能会错误地假设存在多行或不正确地初始化最大值。 我们的解决方案可以自然地处理这个问题，因为循环处理单行并返回其总和。 

另一个重要的情况是多个客户共享相同的最大财富。 例如：```
[[1,2,3],[3,2,1]]
```两个客户都有财富`6`。 由于该问题只要求最大财富值而不是客户指数，因此我们的实现只需跟踪迄今为止看到的最大金额即可正确运行。 

第三种边缘情况是每个客户只有一个银行账户的矩阵，例如：```
[[1],[5],[3]]
```在这种情况下，每行总和等于单个帐户值本身。 该算法仍然有效，因为对一个元素行求和是有效的并产生正确的财富。 

另一个微妙的情况涉及最大约束值。 一个客户可能有 50 个账户，每个账户包含 100 美元。 最大财富变为：$50\times100=5000$我们的实现可以安全地处理这个问题，因为 Python 整数和 Go 整数都可以轻松支持远大于 5000 的值。
