[LeetCode 问题 1658](https://leetcode.com/problems/minimum-operations-to-reduce-x-to-zero/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、二分查找、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个目标整数`x`。 在一次操作中，我们可以从数组中删除最左边的元素或最右边的元素。 每当我们删除一个值时，我们都会从中减去它`x`。 

我们的目标是减少`x`准确地`0`使用最少的移除次数。 如果无法制作`x`确切地`0`，我们返回`-1`。 

重要的细节是我们只能从数组的两端删除元素。 我们不允许删除任意中间元素。 每次删除都会更改剩余的数组以供将来操作。 

例如，如果：```
nums = [1,1,4,2,3], x = 5
```我们可以删除最右边的`3`，那么新数组就变成了`[1,1,4,2]`和`x`变成`2`。 然后删除最右边的`2`， 制作`x = 0`。 这需要`2`运营。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 每个元素最多可达`10^4`-`x`可以大到`10^9`这些约束立即告诉我们二次解会太慢。 任何接近的算法`O(n^2)`对于大小的数组可能会超时`100000`。 我们的目标应该是`O(n)`或者`O(n log n)`解决方案。 

有几个重要的边缘情况需要考虑：

 -`x`可能大于数组的总和，使得答案不可能。 
- 最佳解决方案可能需要删除所有元素。 
- 可能有多种有效的方法来减少`x`为零，我们必须选择操作次数最少的那个。 
- 该数组仅包含正整数，这非常重要，因为它可以实现滑动窗口优化。 
- 天真的贪婪策略可能会失败，因为局部最优删除可能会阻止全局最优答案。 

## 方法

 ### 蛮力方法

 一个简单的想法是尝试从左侧和右侧删除元素的所有可能组合。 

假设我们删除`i`从左边开始的元素和`j`从右边开始的元素。 我们可以计算这些删除的元素之和是否为`x`。 如果他们这样做，那么操作数是`i + j`。 

为了实现这一点，我们可以：

 1. 从左侧开始预先计算前缀和。 
2. 从右侧预先计算后缀和。 
3. 尝试左删除和右删除之间的所有可能的划分。 

这是有效的，因为每个有效的解决方案都对应于左右删除的某种组合。 

然而，如果简单地实现，这可能需要检查许多组合。 纯粹的蛮力方法将检查所有对`(i, j)`，导致`O(n^2)`时间复杂度，对于`n = 100000`。 

### 关键见解

 我们可以考虑保留哪些元素，而不是考虑删除哪些元素。 

如果数组的总和是：```
totalSum
```我们删除元素总和为`x`，那么剩余的中间子数组的总和必须为：```
target = totalSum - x
```那么问题就变成了：

 > 找到总和等于的最长连续子数组`target`。 

为什么最长？ 

因为必须删除不在该子数组中的每个元素。 如果剩余的子数组尽可能长，则删除的元素数量将最小化。 

这种转变完全将问题变成了经典的滑动窗口问题。 

由于所有数字都是正数，因此滑动窗口技术可以完美运行：

 - 如果当前窗口总和太小，则扩大窗口。 
- 如果当前窗口总和太大，则缩小窗口。 
- 每当总和等于`target`，更新最大子数组长度。 

最后：```
minimum operations = n - longestSubarrayLength
```## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 尝试左右移除的组合 |
 | 最优滑动窗口| O(n) | O(1) | O(1) | 查找具有总和的最长子数组`totalSum - x`|

 ## 算法演练

 ### 最优滑动窗口算法

 1. 计算数组的总和。 

我们首先计算：```
totalSum = sum(nums)
```这告诉我们整个数组中存在多少值。 
2. 计算目标子数组和。 

由于删除的元素之和必须为`x`，剩余子数组的总和必须为：```
target = totalSum - x
```3. 尽早处理不可能的情况。 

如果`target < 0`， 然后`x`大于数组总和，因此不可能减少`x`为零。 

返回`-1`。 
4. 处理必须删除整个数组的情况。 

如果`target == 0`，那么唯一的解决方案就是删除每个元素。 

返回`len(nums)`。 
5.初始化滑动窗口。 

我们维持：

 -`left`, 窗口的开始
 -`currentSum`, 当前窗口的总和
 -`maxLength`，迄今为止找到的最长有效子数组的长度
 6. 使用右侧指针展开窗口。 

对于每个`right`索引：

 - 添加`nums[right]`到`currentSum`。 
7. 必要时缩小窗口。 

由于所有数字都是正数，如果`currentSum > target`，减少总和的唯一方法是将左指针向前移动。 

尽管：```
currentSum > target
```减去`nums[left]`并增加`left`。 
8. 检查有效窗口。 

每当：```
currentSum == target
```我们找到了一个有效的剩余子数组。 

更新：```
maxLength = max(maxLength, right - left + 1)
```9. 计算答案。 

如果不存在有效子数组，则返回`-1`。 

否则：```
answer = len(nums) - maxLength
```### 为什么它有效

 每个有效的删除序列都会留下一个连续的中间子数组。 剩余子数组的总和必须等于`totalSum - x`。 

因此，最小化移除相当于最大化剩余子数组的大小。 

因为所有数字都是正数，所以滑动窗口总是单调向前移动。 一旦窗口总和超过目标，从左侧收缩一定会减少总和。 此属性确保算法在线性时间内有效地检查每个有效窗口。 

## Python 解决方案```python
from typing import List

class Solution:
    def minOperations(self, nums: List[int], x: int) -> int:
        total_sum = sum(nums)
        target = total_sum - x

        if target < 0:
            return -1

        if target == 0:
            return len(nums)

        left = 0
        current_sum = 0
        max_length = -1

        for right in range(len(nums)):
            current_sum += nums[right]

            while current_sum > target:
                current_sum -= nums[left]
                left += 1

            if current_sum == target:
                window_length = right - left + 1
                max_length = max(max_length, window_length)

        if max_length == -1:
            return -1

        return len(nums) - max_length
```实现首先计算数组总和并导出剩余子数组的目标和。 

两个早期返回条件简化了重要的边缘情况：

 - 如果`target < 0`，数组没有包含足够的总值。 
- 如果`target == 0`，每个元素都必须被删除。 

滑动窗口使用两个指针：

 -`left`-`right`这`right`指针扩大窗口，而`left`每当总和变得太大时，指针就会缩小它。 

因为所有值都是正数，所以窗口总和的变化是可预测的：

 - 扩大总和。 
- 收缩会减少总和。 

该属性保证了正确性和线性复杂性。 

每当当前窗口总和与目标匹配时，我们就计算窗口长度并更新最大有效子数组长度。 

最后，我们从数组总大小中减去最大长度，以确定必须删除多少个元素。 

## 解决方案```go
func minOperations(nums []int, x int) int {
    totalSum := 0

    for _, num := range nums {
        totalSum += num
    }

    target := totalSum - x

    if target < 0 {
        return -1
    }

    if target == 0 {
        return len(nums)
    }

    left := 0
    currentSum := 0
    maxLength := -1

    for right := 0; right < len(nums); right++ {
        currentSum += nums[right]

        for currentSum > target {
            currentSum -= nums[left]
            left++
        }

        if currentSum == target {
            windowLength := right - left + 1

            if windowLength > maxLength {
                maxLength = windowLength
            }
        }
    }

    if maxLength == -1 {
        return -1
    }

    return len(nums) - maxLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个区别是 Go 不提供内置函数，例如`sum()`，因此我们使用循环手动计算数组总和。 

Go 切片直接使用，不需要对空数组进行任何特殊处理，因为约束保证至少有一个元素。 

整数溢出不是问题，因为最大可能的总和为：```go
10^5 * 10^4 = 10^9
```符合 Go 的标准`int`在 LeetCode 环境中输入。

不需要与输入大小成比例的额外数据结构，因此空间复杂度保持不变。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`x`大于数组总和。 在这种情况下，从数学上来说不可能移除足够的值来减少`x`为零。 有错误的实现可能会继续不必要的搜索或产生无效的答案。 该实现通过立即检查是否`target < 0`。 

当唯一有效的解决方案是删除每个元素时，会发生另一个关键的边缘情况。 出现这种情况时：```
x == sum(nums)
```在这种情况下，目标剩余子数组和变为零。 由于所有数字都是正数，因此唯一总和为零的子数组是空子数组。 该实现通过返回来干净地处理这个问题`len(nums)`立即地。 

第三种微妙的边缘情况涉及数组，其中不存在有效的子数组，即使`x`小于总和。 例如：```
nums = [5,6,7,8,9]
x = 4
```这里：```
target = 31
```但没有连续的子数组总和为`31`。 如果幼稚的实现没有正确跟踪是否找到了有效窗口，则可能会意外返回错误的操作计数。 该解决方案使用`max_length = -1`作为安全检测这种情况的哨兵值。 

另一个重要的考虑因素是，滑动窗口技术仅在所有数字均为正数时才有效。 对于负数，缩小窗口不会可靠地减少总和，并且算法会失败。 问题约束保证正整数，这使得线性滑动窗口解正确。
