[LeetCode 问题 1607](https://leetcode.com/problems/sellers-with-no-sales/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们识别所有**在 2020 年期间没有进行任何销售**的卖家。 

我们得到三个数据库表：

 的`Customer`表包含有关网上商店中的客户的信息。 每个客户都有独特的`customer_id`和一个`customer_name`。 然而，这个表实际上并不是解决问题所必需的，因为任务只涉及卖家和订单。 

这`Orders`表存储交易信息。 每行代表一个订单，并包含销售日期、涉及的客户以及负责交易的卖家等详细信息。 最重要的是，我们感兴趣的是`sale_date`和`seller_id`列，因为我们需要确定哪些卖家在 2020 年专门进行了销售。 

的`Seller`表包含平台中的所有卖家。 每个卖家都有独特的`seller_id`和一个`seller_name`。 

目标是返回 **2020 年销售额为零** 的卖家姓名，按字母顺序排序`seller_name`按升序排列。 

换句话说，我们必须：

 1. 查找 2020 年至少完成一笔销售的所有卖家。 
2. 将这些卖家从完整卖家列表中排除。 
3. 按升序返回剩余的卖家名称。 

看一下例子：

 - 丹尼尔在 2020 年 3 月卖掉了一些东西。 
- 伊丽莎白在 2020 年出售了多次。 
- 弗兰克仅在 2019 年出售。 

由于 Frank 在 2020 年没有销售额，因此他被包含在结果中。 

因为这是一个数据库问题，所以输入表示为关系表而不是数组或对象。 输出是包含单个列的结果表，`seller_name`。 

一个重要的细节是**其他年份的销售额并不重要**。 在 2019 年或 2021 年销售过产品但未在 2020 年销售过产品的卖家仍必须包含在内。 

有几种边缘情况值得考虑。 卖家可能根本没有订单，在这种情况下，它们肯定属于输出。 2020 年的多次销售仍应被视为排除卖家的原因之一。 只有非 2020 年销售额的卖家必须留在答案中。 该问题保证了卖家和订单的唯一 ID，从而简化了连接和过滤。 

## 方法

 ### 蛮力方法

 暴力解决方案将单独检查每个卖家并扫描整个卖家`Orders`表以确定该卖家在 2020 年是否进行过任何销售。 

对于每个卖家，我们将迭代所有订单并检查两个条件：

 - 是否`seller_id`与当前卖家匹配。 
- 是否`sale_date`落在2020年。 

如果我们找到一个匹配的订单，我们就会将该卖家排除在结果之外。 否则，我们将它们包括在内。 

这种方法是正确的，因为每个卖家都会根据每个订单进行检查，确保不会错过任何符合条件的销售。 然而，它的效率很低，因为它会重复扫描`Orders`每个卖家的桌子。 

### 最佳方法

 关键的见解是我们不需要重复搜索每个卖家的订单。 相反，我们可以首先识别**在 2020 年至少进行过一笔销售的所有卖家**，然后将其从卖家列表中删除。 

在 SQL 中，这自然会转化为使用子查询`NOT IN`，或者替代地`LEFT JOIN`与过滤。 

该过程变为：

 1. 全部提取`seller_id`2020 年订单中出现的值。 
2. 选择ID不在该集合中的卖家。 
3. 按字母顺序对结果进行排序。 

这更有效，因为我们处理订单表一次以确定 2020 年的活跃卖家。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(S × O) | O(1) | O(1) | 扫描每个卖家的所有订单 |
 | 最佳| O(S + O) | O(O)| 打造2020年销量卖家集 |

 这里，`S`代表卖家数量，`O`代表订单数量。 

## 算法演练

 ### 最优 SQL 策略

 1. 查询`Orders`表并查找所有`seller_id`2020 年发生销售的值。这会创建一组应被排除在外的卖家。 
2. 查询`Seller`表并选择卖家`seller_id`**没有**出现在排除集中。 这保证了我们在 2020 年只保留零销售额的卖家。 
3. 对剩余卖家进行排序`seller_name`按升序排列以满足问题要求。 
4. 仅返回`seller_name`柱子。 

### 为什么它有效

 这种方法的正确性来自于一个简单的不变量：每个卖家都属于两个群体中的一个：在 2020 年至少完成一笔交易的卖家，以及没有完成一笔交易的卖家。 通过明确构建第一组并将其从完整卖家列表中排除，剩余的卖家必须正是那些在 2020 年没有销售的卖家。 

## Python 解决方案

 由于这是一个数据库问题，Python 部分表示的 SQL 查询与 LeetCode 上提交的完全一样。```python
import pandas as pd

def sellers_with_no_sales(customer: pd.DataFrame,
                           orders: pd.DataFrame,
                           seller: pd.DataFrame) -> pd.DataFrame:
    sellers_2020 = orders[
        orders["sale_date"].dt.year == 2020
    ]["seller_id"].unique()

    result = seller[
        ~seller["seller_id"].isin(sellers_2020)
    ][["seller_name"]]

    return result.sort_values("seller_name")
```该实现首先过滤`Orders`表仅保留销售年份为 2020 年的行。它从这些行中提取唯一的`seller_id`值，代表当年销售额的卖家。 

接下来，`Seller`表的过滤使用`isin()`。 任何 ID 出现在 2020 年卖家集中的卖家均被排除在外。 Only the`seller_name`选择列是因为这是所需的输出格式。 

最后，结果按字母顺序排序`seller_name`在被归还之前。 

对于实际的LeetCode SQL提交，解决方案是：```python
# SQL query representation
SELECT seller_name
FROM Seller
WHERE seller_id NOT IN (
    SELECT seller_id
    FROM Orders
    WHERE YEAR(sale_date) = 2020
)
ORDER BY seller_name;
```## 解决方案

 ## 边缘情况

 当卖家**根本没有订单**时，就会出现一种重要的边缘情况。 如果仅检查存在于`Orders`桌子。 我们的实现正确地处理了这个问题，因为它从完整的开始`Seller`表中仅排除明确出现在 2020 年交易中的卖家。 

另一个重要的情况是，当卖家**仅在 2020 年之外**销售时，例如 2019 年或 2021 年。粗心的实施可能会通过检查卖家是否出现在任何订单中来错误地排除它们。 我们的解决方案专门过滤`YEAR(sale_date) = 2020`，确保只有相关交易才重要。 

第三个边缘案例涉及 **同一卖家在 2020 年进行多次销售**。 如果没有重复数据删除，实施可能会浪费内存或执行冗余检查。 使用`DISTINCT`通过子查询或唯一卖家 ID 集的行为可确保重复销售不会影响正确性，因为卖家要么在 2020 年至少进行过一次销售，要么没有。 

最后，考虑**每个卖家在 2020 年都有销售**的情况。 正确的输出应该是一个空表。 由于我们的查询使用以下方式过滤卖家`NOT IN`，当每个卖家都属于排除集时，它自然不会返回任何行。
