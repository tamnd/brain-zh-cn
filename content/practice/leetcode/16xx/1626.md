[LeetCode 第 1626 题](https://leetcode.com/problems/best-team-with-no-conflicts/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、排序

 ## 解决方案

 ## 问题理解

 问题要求我们建立一支总得分尽可能高的篮球队，同时保证球队中不包含任何冲突。 

每个玩家都有两个属性：

 -`scores[i]`, 玩家的技能得分
 -`ages[i]`, 玩家的年龄

 当出现以下情况时，就会发生冲突：

 - 年轻玩家的分数明显高于年长玩家

 这意味着，如果玩家 A 比玩家 B 年轻，那么玩家 A 的分数必须小于或等于玩家 B 的分数。 同等分数是完全有效的。 同年龄的玩家可以有任何分数关系，不会产生冲突。 

目标是选择任意玩家子集，使得：

 1.不存在冲突
 2. 最大化所选分数的总和

 输入大小最多为`1000`，它足够大，以至于无法进行强力子集枚举。 由于每个玩家都可以被选择或跳过，一个简单的解决方案是检查`2^1000`子集，这在计算上是不可行的。 

这些约束还揭示了一个重要细节：

 - 年龄相对较小，最多`1000`- 分数可能很大，最多可达`10^6`适度的输入大小强烈表明`O(n^2)`动态规划解决方案是可以接受的，因为`1000^2 = 1,000,000`，这是可以管理的。 

有几个重要的边缘情况需要记住：

 - 多个玩家可能具有相同的年龄。 这些玩家从不互相冲突。 
- 多个玩家可能有相同的分数。 
- 得分较高的年轻球员会使球队无效。 
- 最佳团队不一定是由个人得分最高的组成。 
- 单个玩家始终是一个有效的团队。 

例如，得分非常高的年轻球员可能会阻止添加几名年长球员，从而降低总体总得分。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的玩家子集并检查该子集是否包含任何冲突。 

对于每个子集：

 1. 比较每对选定的球员
 2. 检测年轻玩家的分数是否严格更高
 3. 如果子集有效，则计算其总分
 4. 跟踪所有有效子集中的最大总分

 这种方法是正确的，因为它明确地检查了每种可能的团队配置。 因此，它不会错过最佳答案。 

然而，它太慢了。 和`n`玩家们，有`2^n`子集。 即使是为了`n = 30`，这变得巨大。 由于实际约束是`1000`，蛮力是完全不切实际的。 

### 关键见解

 如果我们正确地对玩家进行排序，冲突规则就会变得更容易处理。 

假设我们按以下方式对玩家进行排序：

 1. 年龄从小到大排列
 2. 年龄相同时按升序排列

 排序后：

 - 每个后来的玩家至少和早期的玩家一样老
 - 我们只需要保证分数不减

 这将问题转化为与最长递增子序列动态规划模式非常相似的问题。 

我们不是最大化序列长度，而是最大化总分。 

我们定义：

 -`dp[i]`= 球员的最大团队得分`i`是最后选择的玩家

 然后对于每个较早的玩家`j`：

- 如果`score[j] <= score[i]`, 玩家`i`可以安全地加入结束于`j`- 我们更新：`dp[i] = max(dp[i], dp[j] + score[i])`这是有效的，因为按年龄排序可以保证年轻玩家不会出现在年长玩家之后。

 ## 算法演练

 1. 将每个玩家的年龄和得分合并为一对。 

这使得排序变得更容易，因为每个玩家都被表示为包含这两个属性的单个对象。 
2. 按年龄升序对选手进行排序，然后按得分升序排列。 

按年龄排序可确保后来的玩家永远不会比早期的玩家年轻。 

按分数对相等的年龄进行排序可确保稳定的排序并简化 DP 条件。 
3. 创建DP阵列。 

让`dp[i]`代表球队可达到的最高得分，其中玩家`i`被列为团队中的最后一名球员。 

最初：```
dp[i] = score of player i
```因为每个球员单独组成一个有效的团队。 
4. 迭代每个玩家`i`。 

对于每个玩家，检查所有之前的玩家`j`。 
5. 检查是否有播放器`i`可以延长团队结束时间`j`。 

由于年龄已经排序，唯一剩下的条件是：```
score[j] <= score[i]
```如果为 true，则添加玩家`i`不会产生冲突。 
6. 更新DP值。 

如果玩家`i`可以扩展播放器`j`'蒸汽：```
dp[i] = max(dp[i], dp[j] + score[i])
```7. 跟踪全局最大值。 

答案是DP数组中的最大值。 

### 为什么它有效

 排序可以保证玩家的年龄不会随着我们的前进而减少。 因此，只有分数下降，才会发生冲突。 

DP 转换仅允许扩展先前得分小于或等于当前得分的团队。 这保持了一个不变量，即没有年轻玩家的分数严格高于年长玩家。 

由于考虑了每个有效的扩展，因此该算法会探索所有有效的团队结构并找到最大总分。 

## Python 解决方案```python
from typing import List

class Solution:
    def bestTeamScore(self, scores: List[int], ages: List[int]) -> int:
        players = sorted(zip(ages, scores))

        n = len(players)
        dp = [0] * n

        best = 0

        for i in range(n):
            current_score = players[i][1]

            dp[i] = current_score

            for j in range(i):
                previous_score = players[j][1]

                if previous_score <= current_score:
                    dp[i] = max(dp[i], dp[j] + current_score)

            best = max(best, dp[i])

        return best
```实现首先使用组合年龄和分数`zip`，然后对结果对进行排序。 Python 的元组排序会自动按第一个值排序，然后按第二个值排序，这完全符合所需的排序。 

DP 数组存储每个玩家结束时可能的最佳团队得分。 每个玩家最初都是自己组成一个有效的团队，所以`dp[i]`从玩家自己的分数开始。 

嵌套循环检查所有较早的玩家。 因为球员是按年龄排序的，所以我们只需要验证得分情况即可。 如果前一个玩家的分数小于或等于当前玩家的分数，那么当前玩家可以安全地扩展该团队。 

变量`best`持续跟踪处理过程中发现的最大有效团队分数。 

## 解决方案```go
package main

import "sort"

func bestTeamScore(scores []int, ages []int) int {
	n := len(scores)

	type Player struct {
		age   int
		score int
	}

	players := make([]Player, n)

	for i := 0; i < n; i++ {
		players[i] = Player{
			age:   ages[i],
			score: scores[i],
		}
	}

	sort.Slice(players, func(i, j int) bool {
		if players[i].age == players[j].age {
			return players[i].score < players[j].score
		}
		return players[i].age < players[j].age
	})

	dp := make([]int, n)

	best := 0

	for i := 0; i < n; i++ {
		dp[i] = players[i].score

		for j := 0; j < i; j++ {
			if players[j].score <= players[i].score {
				if dp[j]+players[i].score > dp[i] {
					dp[i] = dp[j] + players[i].score
				}
			}
		}

		if dp[i] > best {
			best = dp[i]
		}
	}

	return best
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

由于 Go 没有像 Python 那样内置元组排序，因此我们定义了一个`Player`结构体包含`age`和`score`。 然后我们使用`sort.Slice`带有自定义比较器。 

DP 逻辑是相同的。 Go 切片的大小是动态调整的，其工作方式与索引访问的数组类似。 

整数溢出不是问题，因为最大总分最多为：```go
1000 × 10^6 = 10^9
```可以安全地放入 Go 中`int`在标准 LeetCode 环境中。

 ## 边缘情况

 当所有玩家年龄相同时，就会出现一种重要的边缘情况。 由于冲突只发生在年轻玩家和年长玩家之间，年龄相等永远不会产生冲突。 有缺陷的实现可能会错误地强制执行分数排序，即使是在同龄玩家中也是如此。 按年龄和分数排序，结合DP条件，自然可以正确处理这个问题。 

另一个重要的边缘情况是随着年龄的增长分数严格降低。 在这种情况下，选择多个玩家总是会产生冲突，因为年轻玩家会比年长玩家获得更高的分数。 该算法正确地避免了扩展无效序列，因为 DP 转换只允许非递减分数。 

第三个关键边缘情况涉及重复分数。 即使年龄不同，也允许相同的分数，因为冲突需要严格更高的分数。 使用条件`<=`而不是`<`是必不可少的。 如果实现使用严格的不平等，它会错误地拒绝许多有效的团队。 

最后的边缘情况是单人输入。 由于任何单个玩家都会组成一个有效的团队，因此算法会使用玩家自己的分数来初始化每个 DP 条目。 即使不存在有效的扩展，这也能保证正确的行为。
