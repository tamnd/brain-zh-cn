[LeetCode 问题 1602](https://leetcode.com/problems/find-nearest-right-node-in-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 树、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到给定节点右侧最近的节点`u`在二叉树的同一层上。 

二叉树被组织成多个级别。 根部处于水平位置`0`，它的孩子们处于同一水平`1`，他们的孩子处于同一水平`2`， 等等。 对于给定的节点`u`，我们想要找到同一级别内紧邻其右侧的下一个节点。 

重要的细节是，我们并不是在中序遍历、前序遍历或任何 DFS 排序中寻找下一个节点。 我们特别关心级别排序，这自然意味着广度优先遍历。 

输入包括：

 -`root`，二叉树的根节点
 -`u`，对树内某处存在的节点的引用

 输出应该是：

 - 右侧最近的节点`u`在同一水平上
 -`null`如果`u`已经是该级别最右边的节点

 约束条件很重要：

 - 树最多可以包含`10^5`节点
 - 所有节点值都是不同的
 -`u`保证存在于树中

 由于树可能变得非常大，因此任何比线性时间更差的算法都有超时的风险。 这立即排除了重复扫描树的大部分的解决方案。 

一些边缘情况很重要：

 -`u`可能已经是其级别中最右边的节点
 - 树可能只包含一个节点
 - 树可能极度不平衡
 -`u`可能会出现在最深层
 - 某些节点可能只有一个子节点

 该问题保证了`u`存在于树中，因此我们永远不需要处理目标节点不存在的情况。 

## 方法

 ### 蛮力方法

 一个简单的蛮力想法是首先确定节点的级别`u`，然后收集该层的所有节点，最后定位紧接其后的节点`u`。 

一种方法是：

 1. 执行 DFS 以确定深度`u`2. 再次遍历，收集该深度的所有节点
 3.扫描收集到的节点发现`u`4. 如果存在则返回下一个节点

 这种方法是正确的，因为它明确地重建了整个目标级别并在其中进行搜索。 然而，它执行了不必要的工作，因为它可能多次遍历树的大部分。 

在最坏的情况下，树可能包含`10^5`节点，因此重复遍历会增加开销。 虽然如果仔细实施的话，总体上在技术上仍然是线性的，但在实践中它比直接的 BFS 解决方案更复杂且效率更低。 

### 最佳方法

 关键的观察是广度优先搜索自然地逐层处理树。 

执行 BFS 时：

 - 在移动到下一个级别之前处理一个级别的所有节点
 - 在一个级别内从左到右访问节点

 这意味着当我们遇到节点`u`在关卡遍历期间：

 - 同一级别队列中的下一个节点恰好是最近的右侧节点
 - 如果`u`是该级别中的最后一个节点，则不存在这样的节点

 这使得 BFS 成为解决该问题的理想技术。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 多次遍历和额外记账|
 | 最佳 | O(n) | O(w) | 单次BFS遍历，其中`w`是最大树宽度 |

 ## 算法演练

 ### 最优 BFS 算法

 1. 初始化一个队列，并将根节点放入其中。 

队列允许我们按照从左到右的顺序逐级处理节点。 这个顺序正是问题所需要的。 
2. 启动一个循环，该循环在队列不为空时继续。 

该外循环的每次迭代都会处理树的一个完整级别。 
3. 记录当前队列大小。 

这个大小告诉我们有多少个节点属于当前级别。 这很重要，因为在处理过程中添加的子节点属于下一个级别，不应混合到当前级别中。 
4、将当前关卡的所有节点一一处理。 

从队列的前面删除节点。 
5. 对于每个节点，检查它是否等于`u`。 

由于问题给了我们实际的节点引用，因此我们直接比较节点对象而不是比较值。 
6. 如果当前节点是`u`:

 - 如果不是当前层的最后一个节点，则队列中的下一个节点是最近的右侧节点
 - 如果是该层的最后一个节点，则返回`None`7. 将当前节点的左子节点和右子节点添加到队列中（如果存在）。 

这些节点属于下一级，稍后将进行处理。 
8.如果BFS完成没有返回，则返回`None`。 

这种情况从技术上讲是不可能发生的，因为`u`保证存在。 

### 为什么它有效

 广度优先搜索从左到右逐级处理节点。 在级别处理期间的任何时刻，队列都包含当前级别的剩余节点，后面跟着未来级别。 因此，当我们遇到`u`，当前层处理顺序中的下一个节点恰好是其右侧最近的节点。 如果`u`是该级别的最后一个节点，不存在这样的节点。 

## Python 解决方案```python
from collections import deque
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def findNearestRightNode(
        self,
        root: TreeNode,
        u: TreeNode
    ) -> Optional[TreeNode]:

        queue = deque([root])

        while queue:
            level_size = len(queue)

            for i in range(level_size):
                current = queue.popleft()

                if current == u:
                    if i == level_size - 1:
                        return None
                    return queue[0]

                if current.left:
                    queue.append(current.left)

                if current.right:
                    queue.append(current.right)

        return None
```实现直接遵循BFS算法。 

一个`deque`被使用是因为它提供了有效的`O(1)`从两端进行插入和移除操作。 这对于队列行为来说是理想的。 

外层`while`循环逐层处理树。 在每个级别开始时，`level_size`存储属于该级别的节点数。 

内循环精确迭代`level_size`次。 这保证了我们在迭代期间仅处理当前级别的节点。 

当我们遇到节点时`u`，我们通过检查来确定它是否是该级别中的最后一个节点：```python
i == level_size - 1
```如果这个条件为真，则右侧没有节点，因此我们返回`None`。 

否则，队列中的下一个节点是最近的右侧节点，因此我们返回：```python
queue[0]
```处理当前节点后，子节点将被追加到队列中，以确保正确的 BFS 排序。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func findNearestRightNode(root *TreeNode, u *TreeNode) *TreeNode {
    queue := []*TreeNode{root}

    for len(queue) > 0 {
        levelSize := len(queue)

        for i := 0; i < levelSize; i++ {
            current := queue[0]
            queue = queue[1:]

            if current == u {
                if i == levelSize-1 {
                    return nil
                }
                return queue[0]
            }

            if current.Left != nil {
                queue = append(queue, current.Left)
            }

            if current.Right != nil {
                queue = append(queue, current.Right)
            }
        }
    }

    return nil
}
```Go 实现密切反映了 Python 逻辑。 

Go 没有使用双端队列，而是使用切片来模拟队列。 移除前面的元件是通过以下方式完成的：```go
queue = queue[1:]
```节点比较使用指针相等：```go
current == u
```这有效是因为`u`是树中的实际节点引用。 

Go 使用`nil`而不是Python的`None`。 

## 工作示例

 ### 示例 1

 输入：```
root = [1,2,3,null,4,5,6]
u = 4
```树结构：```
        1
       / \
      2   3
       \ / \
       4 5 6
```我们逐级执行 BFS。 

| 步骤| 处理前排队 | 当前节点| 行动|
 | ---| ---| ---| ---|
 | 1 | [1] | 1 | 添加 2, 3 |
 | 2 | [2, 3] | 2 | 添加 4 |
 | 3 | [3, 4] | 3 | 添加 5, 6 |
 | 4 | [4,5,6]| 4 | 成立`u`|

 此时此刻：

 -`4`不是该级别中的最后一个节点
 - 队列中的下一个节点是`5`所以答案是：```
5
```### 示例 2

 输入：```
root = [3,null,4,2]
u = 2
```树结构：```
    3
     \
      4
     /
    2
```BFS遍历：

 | 步骤| 处理前排队 | 当前节点| 行动|
 | ---| ---| ---| ---|
 | 1 | [3] | 3 | 添加 4 |
 | 2 | [4] | 4 | 添加 2 |
 | 3 | [2] | 2 | 成立`u`|

 节点`2`是其级别中的最后一个节点，因此其右侧没有节点。 

结果：```

```## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(w) | 队列一次最多存储一层 |

 BFS 遍历对每个节点都处理一次，因此运行时间与节点数量呈线性关系。 

空间使用取决于树的最大宽度。 在最坏的情况下，完整的二叉树可能大致有`n / 2`最后一层的节点，因此最坏情况的辅助空间变为`O(n)`。

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树是最小的有效输入。 在这种情况下，该节点在其级别上没有邻居。 粗心的实现可能会在处理节点后错误地访问空队列。 该解决方案可以正确处理此问题，因为该节点被识别为其级别中的最后一个节点并立即返回`None`。 

### 目标节点位于其级别的最右边

 这是问题中最重要的边缘情况。 如果`u`是其级别的最后一个节点，没有有效答案。 实现明确检查：```
i == level_size - 1
```这保证了我们永远不会错误地从下一级返回节点。 

### 稀疏的树木和失踪的孩子

 二叉树并不总是完整的。 某些节点可能只有一个子节点或没有子节点。 假设两个子级始终存在的幼稚实现可能会崩溃或产生错误的排序。 该解决方案安全地检查：```
if current.left:
```和```
if current.right:
```在将子项添加到队列之前。 

### 极深的树

 该树最多可以包含`10^5`节点，并且可能会变得严重倾斜。 递归 DFS 解决方案在递归深度有限的语言中存在堆栈溢出的风险。 迭代 BFS 方法完全避免了递归，因此对于非常深的树来说是安全的。
