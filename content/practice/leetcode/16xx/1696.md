 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和最大跳跃距离`k`。 我们从索引开始`0`，并且从任何位置`i`，我们可以跳转到之间的任何索引`i + 1`和`i + k`，只要目标仍在数组内。 

每次我们找到一个指数时，它的价值都会对我们的得分有所贡献。 因此，总分是所有访问过的索引（包括起始索引和最终索引）的值的总和。 

目标是计算到达数组的最后一个索引时可获得的最大可能分数。 

这本质上是一个动态规划问题。 对于每个指数，我们想知道到达该指数时可获得的最佳分数。 过渡看起来很自然：$$dp[i] = nums[i] + \max(dp[j])$$在哪里`j`是范围内的任意索引：$$[i-k, i-1]$$这意味着要计算索引的最佳分数`i`，我们需要前面的最大DP值`k`职位。 

约束条件很重要：

 -`1 <= nums.length <= 10^5`-`1 <= k <= 10^5`一个`O(n * k)`在最坏的情况下，解决方案太慢，因为两个值都可以大到`100000`。 这可能需要最多`10^10`的操作，远远超出了可接受的范围。 

输入保证：

 - 数组非空。 
- 我们总是可以到达最后一个索引，因为我们可能会跳到`k`向前迈出一步。 
- 值可能为负数，因此始终采用局部最大数字的贪婪方法不起作用。 

重要的边缘情况包括：

 - 全部为负数的数组。 
- 非常大`k`，几乎每个较早的位置都是可以到达的。 
-`k = 1`，这会强制线性遍历数组。 
- 长度数组`1`，答案很简单`nums[0]`。 

## 方法

 ### 暴力动态规划

 最直接的解决方案是使用动态规划。 

定义`dp[i]`作为达到指数时可获得的最高分数`i`。 

对于每个索引`i`，我们检查所有可以跳入其中的先前索引：$$dp[i] = nums[i] + \max(dp[j])$$对于所有有效的：$$j \in [i-k, i-1]$$该解决方案是正确的，因为它明确检查每个合法转换并选择最佳的一个。 

然而，它太慢了。 对于每个索引，我们最多可以扫描`k`先前的位置，产生最坏情况的复杂性：$$O(nk)$$和`n = 100000`和`k = 100000`，这变得不可行。 

### 单调队列的最优动态规划

 关键的观察是每个 DP 转换只需要前一个滑动窗口的最大值`k`民主党指出。 

我们不是每次都重新计算最大值，而是维护一个数据结构，始终保持恒定时间内可用的窗口最大值。 

单调双端队列非常适合于此。 

双端队列按照 DP 分数的降序存储 DP 值的索引：

 - 前面始终包含当前窗口中的最大 DP 值。 
- 超出允许范围的索引从前面删除。 
- 较小的 DP 值从后面删除，因为它们永远无法再次达到最佳状态。 

这将复杂性降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(nk) | O(nk) | O(n) | 检查每个可到达的先前索引 |
 | 最佳 | O(n) | O(n) | 使用单调双端队列来保持滑动最大值 |

 ## 算法演练

 1.创建一个DP数组，其中`dp[i]`表示达到指数后可获得的最高分数`i`。 
2.初始化第一个位置：```
dp[0] = nums[0]
```由于我们从索引开始`0`，这是初始分数。 
3. 创建一个双端队列，以降序存储 DP 值的索引。 

最初：```
deque = [0]
```双端队列的前面始终代表当前索引可用的最佳先前位置。 
4. 从索引处开始从左到右迭代数组`1`。 
5. 处理前索引`i`，如果索引超出有效跳转范围，则从前面删除索引。 

如果：```
deque[0] < i - k
```那么该索引就不能再跳转到`i`，因此必须将其丢弃。 
6. 双端队列的前面现在包含所有有效的先前位置中具有最大 DP 值的索引。 

计算：$$dp[i] = nums[i] + dp[deque[0]]$$7. 保持双端队列内DP值的降序。 

当当前 DP 值大于或等于双端队列后面的 DP 值时：```
dp[i] >= dp[deque[-1]]
```删除后面的索引。 

这些较小的值是无用的，因为当前的索引既更新又更好。 
8. 将当前索引附加到双端队列。 
9. 继续，直到处理完最后一个索引。 
10、退货：```
dp[n - 1]
```### 为什么它有效

 双端队列始终按照 DP 值的降序维护索引。 因此，双端队列的前面始终是当前size的滑动窗口内的最大DP值`k`。 

每个索引进入双端队列一次并离开一次。 因为我们总是从后面删除较弱的候选者，所以不会留下不必要的索引。 

这保证了每个 DP 转换都使用最佳的先前状态，产生正确的最大分数。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def maxResult(self, nums: List[int], k: int) -> int:
        n = len(nums)

        dp = [0] * n
        dp[0] = nums[0]

        window = deque([0])

        for i in range(1, n):
            # Remove indices outside the jump range
            while window and window[0] < i - k:
                window.popleft()

            # Best previous score is at the front
            dp[i] = nums[i] + dp[window[0]]

            # Maintain decreasing dp values
            while window and dp[i] >= dp[window[-1]]:
                window.pop()

            window.append(i)

        return dp[-1]
```实现完全遵循算法。 

这`dp`数组存储每个索引处可获得的最佳分数。 第一个值被初始化为`nums[0]`因为我们从那里开始。 

双端队列命名为`window`直接存储索引，而不是 DP 值。 这很重要，因为我们需要知道索引何时超出有效跳转窗口。 

在每次迭代中，代码首先从前面删除过时的索引。 这些位置距离当前指数太远。 

双端队列的前面始终包含最佳的可达先前状态，因此我们立即使用它来计算新的 DP 值。 

计算后`dp[i]`，代码从双端队列的后面删除较弱的候选者。 任何DP值比当前指数更小的指数在未来永远不可能成为最优的，因为当前指数更新且更强。 

最后，将当前索引附加到双端队列中。 

最终答案存储在DP数组的最后一个位置。 

## 解决方案```go
func maxResult(nums []int, k int) int {
	n := len(nums)

	dp := make([]int, n)
	dp[0] = nums[0]

	// Monotonic deque storing indices
	deque := []int{0}

	for i := 1; i < n; i++ {
		// Remove indices outside the valid range
		if deque[0] < i-k {
			deque = deque[1:]
		}

		// Best previous score
		dp[i] = nums[i] + dp[deque[0]]

		// Maintain decreasing dp values
		for len(deque) > 0 && dp[i] >= dp[deque[len(deque)-1]] {
			deque = deque[:len(deque)-1]
		}

		deque = append(deque, i)
	}

	return dp[n-1]
}
```Go 的实现与 Python 解决方案非常相似。 

而不是Python的`deque`，Go使用切片来模拟双端队列。 从前面移除是通过切片处理的：```go
deque = deque[1:]
```附加到后面使用内置`append`功能。 

Go 整数就足够了，因为最大可能分数仍然在 32 位整数范围内，尽管 Go 的`int`无论如何，现代系统上的类型通常是 64 位。 

与 Python 不同，Go 没有内置的动态双端队列结构，因此切片操作是这里的标准方法。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个索引最多进入和离开双端队列一次 |
 | 空间| O(n) | DP 数组加双端队列存储 |

 该算法是线性的，因为每个数组索引都会被处理固定次数。 尽管双端队列操作发生在循环内部，但每个元素只能插入和删除一次，因此整个执行过程中双端队列操作的总数与`n`。 

DP阵列需要`O(n)`内存，并且双端队列还可以存储最多`n`最坏情况下的指数。

 ## 边缘情况

 一种重要的边缘情况是仅包含一个元素的数组。 在这种情况下，我们立即从最后一个索引开始，因此不会发生跳转。 有缺陷的实现可能会错误地尝试假设至少存在两个元素的双端队列操作或转换。 该实现自然地处理这个问题，因为循环从索引处开始`1`，当数组长度为`1`。 

当所有值都为负时，会出现另一种关键的边缘情况。 贪婪的方法在这里常常会失败，因为每一步都会降低分数。 该算法仍然可以正常工作，因为动态规划会评估所有可达状态并始终选择危害最小的路径。 双端队列优化不依赖于正性，仅依赖于 DP 值的相对排序。 

第三个重要的边缘情况是`k = 1`。 在这种情况下，每一步都是被迫的，因为我们可能只能跳转到下一个索引。 一些滑动窗口实现意外地假设始终存在多个候选者。 在这里，双端队列的行为实际上就像单个活动状态，并且 DP 简化为简单的运行总和。 该实现在没有任何特殊情况逻辑的情况下处理这个问题。 

另一个微妙的情况出现在`k`非常大，可能大于数组长度。 在这种情况下，几乎所有先前的索引仍然可以访问。 双端队列仍然可以正常工作，因为仅在必要时才会删除过时的索引，并且前端始终存储可到达位置中的全局最佳 DP 值。
