 ## 解决方案

 ## 问题理解

 此问题要求我们计算 2020 年每个月的司机在该月实际工作的百分比。 

该数据库包含三个表：

 -`Drivers`当每个司机加入 Hopper 时，商店。 
-`Rides`存储所有乘车请求。 
-`AcceptedRides`仅存储由司机接受并完成的行程。 

关键的观察结果是，如果司机在该月月底或之前加入，则该司机被视为在该月内“可用”。 如果司机在该月完成了至少一次可接受的行程，则该司机在该月内被视为“工作”。 

对于 2020 年 1 月到 12 月的每个月，我们必须计算：$$\text{working\_percentage} = \frac{\text{number of distinct working drivers in that month}} {\text{number of available drivers by end of that month}} \times 100$$结果必须：

 - 包括所有 12 个月，
 - 按月份升序排序，
 - 将百分比四舍五入到小数点后两位，
 - 返回`0`如果没有可用的驱动程序。 

困难在于驱动程序的可用性是累积的。 一旦司机加入，他们将在未来几个月内保持可用状态。 同时，每个月的在职司机都是独立计算的。 

另一个微妙的细节是，我们计算的是当月工作的不同司机，而不是总乘车次数。 如果一名司机在同一个月内完成了多次行程，他们仍然只计算一次。 

语句中没有明确给出输入大小，但由于这是一个数据库问题，因此效率很重要。 每个月重复扫描表的简单解决方案可能会变得不必要的昂贵。 最佳解决方案是将数据聚合一次并重复使用。 

重要的边缘情况包括：

 - 接受乘车次数为零的月份。 
- 可用司机为零的月份。 
- 2020 年之前加入的司机。 
- 2020年之后加入的司机，这些应该不会影响2020年的计算。 
- 司机在同一个月内完成多次行程。 
- 存在于的乘车请求`Rides`但从未被接受。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是独立处理每个月。 

每个月从`1`到`12`：

 1. 扫描`Drivers`表格并计算有多少司机在该月底或之前加入。 
2. 加入`AcceptedRides`和`Rides`确定当月发生了哪些行程。 
3. 计算该月内完成接受的行程的不同司机的数量。 
4. 计算百分比。 

这是有效的，因为每个月都是直接根据原始数据计算的。 

然而，问题是效率低下。 在这 12 个月中的每一个月，我们都会重复扫描相同的表。 如果表很大，这就会变得浪费。 累积驱动程序的重复连接和重复计数会带来不必要的开销。 

### 最佳方法

 关键的见解是计算可以预先聚合。 

我们注意到两个重要的模式：

 1. 可用驱动程序按月累计。 
2. 在职司机只需要每月的独立计数。 

我们可以：

 - 首先计算每个月有多少司机加入。 
- 建立可用驱动程序的累积运行总数。 
- 单独计算每个月不同的工作驱动因素。 
- 将两个月度总结合并在一起。 

这避免了重复的表扫描，并将问题转化为简单的分组聚合。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(12 × (D + R)) | O(12 × (D + R)) | O(1) | O(1) | 每个月重复扫描表格 |
 | 最佳 | O(D + R) | O(12) | 每月统计数据预先汇总一次 |

 这里：

-`D`= 中的行数`Drivers`-`R`= 中的行数`Rides`和`AcceptedRides`## 算法演练

 ### 第 1 步：生成所有月份

 我们首先创建一个月份列表`1`通过`12`。 

这保证了即使没有司机或没有乘车的月份仍然会出现在最终输出中。 

### 第 2 步：计算每月加入的司机数量

 我们检查`Drivers`表格并统计 2020 年或更早每个月有多少司机加入。 

例如：

 | 加入月份 | 新驱动程序 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |

 从 1 月份开始，2020 年之前加入的司机被视为已经活跃。 

### 步骤 3：建立累计活跃驾驶员计数

 可用的驱动程序是累积的。 

如果：

 - 1 月增加 2 名车手，
 - 2 月增加 1 名驾驶员，
 - 3 月增加 1 名驾驶员，

 那么：

 | 月 | 活动驱动程序 |
 | --- | --- |
 | 1 | 2 |
 | 2 | 3 |
 | 3 | 4 |

 我们使用运行总计来有效地计算这一点。 

### 步骤 4：计算每月工作驱动程序

 我们加入`AcceptedRides`和`Rides`因为月份信息存在于`Rides.requested_at`。 

2020 年每个月：

 - 提取骑行月份，
 - 计数不同的`driver_id`。 

使用`COUNT(DISTINCT driver_id)`至关重要，因为同一司机的多次乘车只算一次。 

### 步骤 5：计算百分比

 每个月：$$\text{working\_percentage} = \frac{\text{working drivers}} {\text{active drivers}} \times 100$$如果活动驱动程序为零，则返回`0`。 

最后，将值四舍五入到小数点后两位。 

### 为什么它有效

 该算法之所以有效，是因为它将问题分为两个独立的每月聚合：

 - 累积可用驱动程序，
 - 独特的工作驱动力。 

累积计数正确地模拟了司机的可用性，因为一旦司机加入，他们就会在未来的几个月中保持活跃状态​​。 每月不同计数正确地模拟了工作参与度，因为司机要么在该月工作，要么不工作，无论他们完成了多少次乘车。 

由于每个月都是根据这些正确的汇总计算出来的，因此最终的百分比是正确的。 

## Python 解决方案```python
# Write your MySQL query statement below

WITH RECURSIVE months AS (
    SELECT 1 AS month
    UNION ALL
    SELECT month + 1
    FROM months
    WHERE month < 12
),

driver_counts AS (
    SELECT
        MONTH(join_date) AS month,
        COUNT(*) AS new_drivers
    FROM Drivers
    WHERE YEAR(join_date) = 2020
    GROUP BY MONTH(join_date)
),

active_drivers AS (
    SELECT
        m.month,
        (
            SELECT COUNT(*)
            FROM Drivers d
            WHERE d.join_date <= LAST_DAY(CONCAT('2020-', m.month, '-01'))
        ) AS active_count
    FROM months m
),

working_drivers AS (
    SELECT
        MONTH(r.requested_at) AS month,
        COUNT(DISTINCT ar.driver_id) AS working_count
    FROM AcceptedRides ar
    JOIN Rides r
        ON ar.ride_id = r.ride_id
    WHERE YEAR(r.requested_at) = 2020
    GROUP BY MONTH(r.requested_at)
)

SELECT
    m.month,
    ROUND(
        IFNULL(wd.working_count, 0) * 100.0 /
        IF(ad.active_count, ad.active_count, NULL),
        2
    ) AS working_percentage
FROM months m
LEFT JOIN active_drivers ad
    ON m.month = ad.month
LEFT JOIN working_drivers wd
    ON m.month = wd.month
ORDER BY m.month;
```该解决方案首先生成所有月份`1`通过`12`使用递归公用表表达式。 

接下来，`active_drivers`CTE 会计算每个月底加入的司机数量。 条件：```python
d.join_date <= LAST_DAY(CONCAT('2020-', m.month, '-01'))
```确保累积包含。 

这`working_drivers`CTE 将已接受的行程与行程连接起来以检索行程日期。 它按月分组并计算不同的驱动程序。 

最后，主查询将所有内容连接在一起并计算百分比。 这`IFNULL`可以处理几个月没有工作的司机，而`IF(..., NULL)`防止被零除。

 ## 边缘情况

 ### 没有活跃驾驶员的月份

 当还没有司机加入时，会出现一个特别重要的边缘情况。 在这种情况下，分母变为零。 幼稚的实现可能会产生除零错误或返回`NULL`。 

该解决方案通过使用条件除法逻辑显式处理这种情况。 如果活跃驾驶员数量为零，则该百分比可以安全评估为`0`。 

### 同一司机多次接受乘车

 错误的另一个常见来源是计算乘车次数而不是司机。 

假设一名司机在一个月内完成了五次行程。 问题涉及的是在职司机的百分比，而不是完成的乘车次数。 因此，该驾驶员只需贡献一次计数。 

实现正确使用：```
COUNT(DISTINCT ar.driver_id)
```这保证了唯一性。 

### 2020 年之前加入的司机

 2020 年 1 月之前加入的司机在新年伊始就已经活跃起来。 有缺陷的实现可能只计算加入日期在 2020 年期间的司机。 

该解决方案将加入日期与每月月底进行比较，确保所有之前加入的司机在 2020 年保持活跃状态。 

### 没有接受乘车的月份

 有些月份可能根本不包含任何可接受的游乐设施。 如果内部联接使用不正确，这些月份可能会从结果中消失。 

专注的`months`表保证每个月从`1`到`12`出现在最终输出中。 然后左连接用零填充缺失值。
