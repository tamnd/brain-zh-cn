[LeetCode 问题 1604](https://leetcode.com/problems/alert-using-same-key-card-third-or-more-times-in-a-one-hour-period/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、排序

 ## 解决方案

 ## 问题理解

 该问题给了我们两个并行数组，`keyName`和`keyTime`。 每个索引代表一个单一的钥匙卡使用事件。 例如：```
keyName[i] = employee name
keyTime[i] = time of usage
```它们共同描述了特定员工在一天内使用其钥匙卡的时间。 

我们的任务是识别在任何一小时内至少使用钥匙卡 3 次的每位员工。 结果必须包含按字母顺序排序的唯一员工姓名。 

重要的细节是如何解释一小时规则。 如果三人组中最早和最晚访问时间之间的差异小于或等于 60 分钟，则该员工应触发警报。 

例如：```
10:00, 10:40, 11:00
```这很重要，因为之间的差异`10:00`和`11:00`正好是60分钟。 

然而：```
22:51, 23:52
```不算在内，因为相差 61 分钟。 

限制条件很大：

 - 最多`10^5`访问记录
 - 员工姓名可以重复多次
 - 时间以字符串形式给出`"HH:MM"`格式

 这些限制立即告诉我们，低效的重复扫描可能会太慢。 我们需要一个接近的解决方案`O(n log n)`或更好。 

另一个重要的观察结果是所有访问事件都发生在一天之内。 这意味着我们永远不需要担心穿越午夜。 因此，将时间转换为从午夜算起的分钟数既简单又安全。 

一些重要的边缘情况包括：

 - 一名员工在 60 分钟内恰好有 3 次访问权限
 - 多个重叠的一小时窗口
 - 拥有大量出入记录的员工
 - 最初未排序的时间
 - 访问权限少于 3 次的员工
 - 访问间隔正好 60 分钟，这应该算在内

 该问题还保证每个`[keyName[i], keyTime[i]]`pair 是唯一的，因此我们不需要处理重复的事件。 

## 方法

 ### 蛮力方法

 强力解决方案将按员工对所有访问时间进行分组，然后检查每个员工的三种访问的每种可能组合。 

对于每位员工：

 1. 将所有时间转换为分钟。 
2.对时间进行排序。 
3. 检查每个三元组`(i, j, k)`在哪里`i < j < k`。 
4. 如果`times[k] - times[i] <= 60`，触发警报。 

这是有效的，因为排序可确保三元组中的最早和最晚时间确定所有三个访问是否适合在一小时内。 

然而，这种方法效率低下。 如果一名员工有`m`访问记录，检查所有三元组需要`O(m^3)`最坏情况下的时间。 高达`10^5`总记录，这变得不可行。 

### 关键见解

 对员工的访问时间进行排序后，我们不需要检查每个三元组。 

如果一小时内适合三个访问，则按排序顺序，它们必须连续出现在列表中的某个位置。 

这意味着我们只需要检查尺寸为三的窗口：```
times[i], times[i+1], times[i+2]
```如果：```
times[i+2] - times[i] <= 60
```然后我们发现了一个有效的警报条件。 

这大大减少了工作量。 排序后，我们线性扫描时间。 

优化之所以有效，是因为排序顺序保证了如果存在有效的三元组，任何更宽的窗口都将包含连续的三元组。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况 O(n3) | O(n) | 检查所有可能的三重访问 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 对时间进行排序并检查大小为 3 的连续窗口 |

 ## 算法演练

 1. 创建一个哈希映射，其中键是员工姓名，值是访问时间列表。 

我们使用哈希映射，因为它允许按员工姓名对记录进行有效分组。 
2. 分别转换`"HH:MM"`字符串为从午夜开始的总分钟数。 

例如：```
"10:40" -> 640
```这使得时间比较成为简单的算术而不是字符串操作。 
3. 将每个转换后的时间存储在相应的员工列表中。 
4. 对于每位员工：

 - 按升序排列访问时间列表。 
- 使用大小为 3 的滑动窗口迭代排序列表。 
5. 对于每个索引`i`， 查看：```
times[i + 2] - times[i] <= 60
```如果属实，该员工就会触发警报。 
6. 将员工姓名添加到答案列表中，并停止检查该员工的其他窗口。 

一旦员工符合资格，就无需进行额外的检查。 
7. 按字母顺序对最终答案列表进行排序。 
8. 返回排序后的结果。 

### 为什么它有效

 对时间进行排序可确保按时间顺序排列。 任何包含至少 3 次访问的有效一小时间隔必须在排序列表中包含 3 次连续访问。 因此，检查每三个连续组足以检测所有警报条件。 如果该组中最早和最晚时间最多相差60分钟，则所有三个访问都在要求的时间间隔内。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def alertNames(self, keyName: List[str], keyTime: List[str]) -> List[str]:
        employee_times = defaultdict(list)

        for name, time_str in zip(keyName, keyTime):
            hours, minutes = map(int, time_str.split(":"))
            total_minutes = hours * 60 + minutes
            employee_times[name].append(total_minutes)

        alerted_employees = []

        for name, times in employee_times.items():
            times.sort()

            for i in range(len(times) - 2):
                if times[i + 2] - times[i] <= 60:
                    alerted_employees.append(name)
                    break

        alerted_employees.sort()
        return alerted_employees
```实现首先使用`defaultdict(list)`按员工姓名对访问时间进行分组。 这避免了在插入值之前手动检查存在性。 

每个时间字符串都会转换为从午夜开始的分钟数。 这种转换简化了比较，因为整数减法直接给出了以分钟为单位的差异。 

对所有记录进行分组后，算法独立处理每个员工。 它们的访问时间按时间顺序排序，使我们能够检查大小为三的连续窗口。 

条件：```python
times[i + 2] - times[i] <= 60
```检查1小时内是否发生3次访问。 

一旦员工满足条件，他们的名字就会添加到结果列表中，并且循环会提前停止以提高效率。 

最后，在返回之前将结果按字母顺序排序。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
	"strings"
)

func alertNames(keyName []string, keyTime []string) []string {
	employeeTimes := make(map[string][]int)

	for i := 0; i < len(keyName); i++ {
		name := keyName[i]
		timeStr := keyTime[i]

		parts := strings.Split(timeStr, ":")
		hours, _ := strconv.Atoi(parts[0])
		minutes, _ := strconv.Atoi(parts[1])

		totalMinutes := hours*60 + minutes

		employeeTimes[name] = append(employeeTimes[name], totalMinutes)
	}

	var alertedEmployees []string

	for name, times := range employeeTimes {
		sort.Ints(times)

		for i := 0; i+2 < len(times); i++ {
			if times[i+2]-times[i] <= 60 {
				alertedEmployees = append(alertedEmployees, name)
				break
			}
		}
	}

	sort.Strings(alertedEmployees)

	return alertedEmployees
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个`map[string][]int`存储每个员工的访问时间。 

不像Python的方便`split(":")`和元组解包，Go 需要显式解析`strings.Split`和`strconv.Atoi`。 

排序是使用完成的`sort.Ints`，最终结果按字母顺序排列`sort.Strings`。 

Go切片在使用时自动增长`append`，这使得它们可以方便地动态收集访问时间。

 ## 边缘情况

 一种重要的边缘情况是三个通道的间隔正好是 60 分钟。 例如：```
10:00, 10:30, 11:00
```一个常见的错误是使用严格的不等式，例如`< 60`而不是`<= 60`。 实现通过显式检查来正确处理此问题：```
times[i + 2] - times[i] <= 60
```另一个重要的边缘情况是未排序的输入。 不保证记录按时间顺序出现。 检查相邻记录而不排序的简单实现可能会错过有效的警报窗口。 该解决方案通过在扫描前对每个员工的访问时间进行排序来避免此问题。 

访问权限少于 3 次的员工也很重要。 无论何时，此类员工永远无法触发警报。 实现自然会处理这个问题，因为循环：```
for i in range(len(times) - 2):
```当访问次数少于 3 次时不执行。 

最后一个微妙的边缘情况涉及重叠窗口。 考虑：```
10:00, 10:20, 10:40, 11:00
```这里存在几个有效的三元组。 该算法正确识别第一个有效窗口并立即停止处理该员工，从而防止结果列表中出现重复条目​​。
