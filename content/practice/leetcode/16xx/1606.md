[LeetCode 问题 1606](https://leetcode.com/problems/find-servers-that-handled-most-number-of-requests/)

 **难度：** 🔴难
 **主题：** 数组、堆（优先级队列）、模拟、有序集

 ## 解决方案

 ## 问题理解

 该问题提出了一个模拟场景，涉及`k`服务器，每个服务器都唯一标识`0`到`k-1`。 每个服务器一次只能处理一个请求，并且请求在严格递增的离散时间到达`arrival`大批。 每个请求都需要一定的`load`的时间来完成。 请求根据**模块化规则**分配给服务器：`i`th 请求更喜欢服务器`(i % k)`; 如果该服务器繁忙，则分配将绕到下一个可用服务器，从该服务器开始并循环回到`0`如果需要的话。 如果所有服务器都繁忙，则请求将被丢弃。 

输入由一个整数组成`k`表示服务器数量，一个数组`arrival`表示请求到达时间的严格递增正整数，以及一个数组`load`代表每个请求的处理时间。 

输出是处理**最大请求数**的服务器 ID 列表。 多个服务器可能共享最大计数，ID 的顺序并不重要。 

Key constraints include a large upper limit (`k`和`arrival.length`最多`10^5`）并严格增加到达时间。 这消除了朴素的 O(k * n) 方法，因为这样的解决方案太慢了。 要考虑的边缘情况包括所有服务器在特定时间繁忙、请求计数相关以及单服务器场景。 

## 方法

 ### 蛮力方法

 天真的方法会迭代每个请求，从以下位置开始依次检查服务器`(i % k)`并继续寻找可用的服务器。 如果没有空闲服务器，则请求将被丢弃。 这需要扫描最多`k`每个请求的服务器数，导致 **时间复杂度为 O(n * k)**。 虽然正确，但对于大型设备来说太慢了`k`和`n`（最多`10^5`每个），使得它对于给定的约束是不切实际的。 

### 最佳方法

 关键的见解是有效跟踪哪些服务器**可用**以及哪些服务器**在给定时间**繁忙。 使用两个数据结构可以实现这一点：

 1. **最小堆**（优先级队列）来存储繁忙的服务器及其释放时间，使我们能够在请求到达时快速释放服务器。 
2.可用服务器ID的**有序集合**，用于有效地找到从以下位置开始的下一个空闲服务器`(i % k)`并环绕。 

该算法的工作原理如下：对于每个到达的请求，我们首先释放完成时间小于或等于当前到达的所有服务器。 然后我们找到第一个可用的服务器>=`(i % k)`，必要时环绕。 如果找到服务器，我们会分配请求，更新其繁忙时间，并增加其计数。 处理完所有请求后，我们返回具有最大处理请求数的服务器。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * k) | O(k) | 按顺序检查每个服务器的每个请求 |
 | 最佳| O(n log k) | O(n log k) | O(k) | 对繁忙的服务器使用最小堆+有序集以获得可用性|

 ## 算法演练

 1.初始化一个数组`request_count`尺寸的`k`为 0 以跟踪每个服务器处理的请求数量。 
2. 创建一个**最小堆**`busy_servers`存储元组`(release_time, server_id)`代表当前正在处理请求的服务器。 
3. 初始化一个**排序集**`available_servers`包含所有服务器 ID`[0, 1, ..., k-1]`。 
4. 迭代每个请求`i`和`arrival[i]`和`load[i]`:

 1.免费服务器：弹出所有服务器`busy_servers`谁`release_time <= arrival[i]`并将他们的 ID 添加回`available_servers`。 
2. 搜索第一个可用的服务器ID >=`(i % k)`。 如果不存在，则回绕并选择最小的可用服务器 ID。 
3. 如果没有可用的服务器，则丢弃请求。 
4. 否则，将请求分配给所选服务器：

 1. 删除服务器`available_servers`。 
2. 推`(arrival[i] + load[i], server_id)`进入`busy_servers`。 
3. 增量`request_count[server_id]`。 
5.处理完所有请求后，找到其中的最大值`request_count`。 
6. 返回所有数量等于最大值的服务器ID。 

**Why it works:** By maintaining a heap of busy servers and a sorted set of available servers, we can assign requests in O(log k) time per request while ensuring the modular preference and wrap-around requirement. 请求计数是准确的，因为每个请求仅被处理一次或被丢弃。 

## Python 解决方案```python
from typing import List
import heapq
from sortedcontainers import SortedSet

class Solution:
    def busiestServers(self, k: int, arrival: List[int], load: List[int]) -> List[int]:
        request_count = [0] * k
        busy_servers = []
        available_servers = SortedSet(range(k))

        for i, (start, duration) in enumerate(zip(arrival, load)):
            while busy_servers and busy_servers[0][0] <= start:
                _, freed_server = heapq.heappop(busy_servers)
                available_servers.add(freed_server)

            if not available_servers:
                continue

            index = available_servers.bisect_left(i % k)
            if index == len(available_servers):
                index = 0
            server_id = available_servers[index]

            available_servers.remove(server_id)
            heapq.heappush(busy_servers, (start + duration, server_id))
            request_count[server_id] += 1

        max_requests = max(request_count)
        return [i for i, count in enumerate(request_count) if count == max_requests]
```该代码首先初始化请求跟踪和服务器可用性。 对于每个传入请求，它都会使用最小堆释放已完成的服务器。 使用`SortedSet`，它根据模块化规则有效地找到下一个可用服务器，必要时进行包装，分配请求并更新计数器。 最后，它返回具有最大处理请求数的服务器。 

## 解决方案```go
package main

import (
    "container/heap"
    "sort"
)

type Server struct {
    endTime int
    id      int
}

type MinHeap []Server

func (h MinHeap) Len() int           { return len(h) }
func (h MinHeap) Less(i, j int) bool { return h[i].endTime < h[j].endTime }
func (h MinHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

func (h *MinHeap) Push(x interface{}) {
    *h = append(*h, x.(Server))
}

func (h *MinHeap) Pop() interface{} {
    n := len(*h)
    item := (*h)[n-1]
    *h = (*h)[:n-1]
    return item
}

func busiestServers(k int, arrival []int, load []int) []int {
    requestCount := make([]int, k)
    available := make([]int, k)
    for i := 0; i < k; i++ {
        available[i] = i
    }

    busy := &MinHeap{}
    heap.Init(busy)

    for i, start := range arrival {
        duration := load[i]
        for busy.Len() > 0 && (*busy)[0].endTime <= start {
            freed := heap.Pop(busy).(Server).id
            index := sort.SearchInts(available, freed)
            available = append(available[:index], append([]int{freed}, available[index:]...)...)
        }

        if len(available) == 0 {
            continue
        }

        idx := sort.Search(len(available), func(j int) bool { return available[j] >= i%k })
        if idx == len(available) {
            idx = 0
        }
        serverID := available[idx]
        available = append(available[:idx], available[idx+1:]...)
        heap.Push(busy, Server{endTime: start + duration, id: serverID})
        requestCount[serverID]++
    }

    maxReq := 0
    for _, cnt := range requestCount {
        if cnt > maxReq {
            maxReq = cnt
        }
    }

    res := []int{}
    for i, cnt := range requestCount {
        if cnt == maxReq {
            res = append(res, i)
        }
    }
    return res
}
```Go 解决方案反映了 Python 方法。 而不是一个`SortedSet`，它使用切片和二分搜索进行插入和查找。 最小堆跟踪繁忙的服务器。 服务器分配、请求计数和最终最大检测遵循相同的逻辑。
