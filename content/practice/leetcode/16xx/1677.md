[LeetCode 问题 1677](https://leetcode.com/problems/products-worth-over-invoices/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们根据发票计算每种产品的汇总货币信息。 我们有两张表：`Product`和`Invoice`。 这`Product`表包含一个唯一的`product_id`和`name`产品的。 这`Invoice`表包含产品的单独发票，包括金额`rest`（剩余金额），`paid`,`canceled`， 和`refunded`。 

我们的目标是返回一个表格，对于每种产品，汇总其所有发票中的这四个货币字段。 输出必须包括产品名称和合计金额，按字母顺序排列`name`。 

关键点是，每个产品可能有多个发票或根本没有发票，并且问题保证了唯一的产品名称。 边缘情况包括没有发票的产品、所有金额为零的发票以及仅具有发票类型子集的产品（例如，仅`rest`或仅`refunded`）。 

## 方法

 暴力方法是首先获取所有产品，然后手动扫描整个产品`Invoice`每个产品的表总结其`rest`,`paid`,`canceled`， 和`refunded`价值观。 这工作正常但效率低下，因为它会重复扫描`Invoice`每个产品的表，导致 O(n * m) 时间，其中 n 是产品数量，m 是发票数量。 

最佳方法是利用 SQL 聚合。 通过加入`Product`表与`Invoice`表并使用`SUM()`函数分组依据`product_id`和`name`，我们可以一次性计算总数。 使用`LEFT JOIN`确保仍然包括没有发票的产品，所有金额默认为零`COALESCE`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(n) | 单独迭代每个产品的发票 |
 | 最佳 | O(m + n) | O(n) | 使用 SQL`JOIN`和`SUM()`有效聚合 |

 ## 算法演练

 1. 执行`LEFT JOIN`之间的`Product`和`Invoice`桌子上`product_id`。 这确保了所有产品都包含在内，即使是那些没有发票的产品。 
2. 对结果进行分组`product_id`和`name`。 分组依据`name`确保最终输出可以按字母顺序排序。 
3. 对于每组，计算总和`rest`,`paid`,`canceled`， 和`refunded`。 使用`COALESCE`处理产品没有发票的情况，默认金额为零。 
4. 选择产品`name`以及作为列的汇总总和`rest`,`paid`,`canceled`,`refunded`。 
5. 对结果进行排序`name`以满足输出要求。 

**为什么有效**：SQL 聚合保证产品的所有发票都汇总在一起。`LEFT JOIN`确保甚至包括没有发票的产品。`COALESCE`保证没有空值，而是生成零，这与预期的输出格式匹配。 

## Python 解决方案```python
# Python solution using SQL query
def product_worth_over_invoices():
    query = """
    SELECT 
        p.name,
        COALESCE(SUM(i.rest), 0) AS rest,
        COALESCE(SUM(i.paid), 0) AS paid,
        COALESCE(SUM(i.canceled), 0) AS canceled,
        COALESCE(SUM(i.refunded), 0) AS refunded
    FROM Product p
    LEFT JOIN Invoice i ON p.product_id = i.product_id
    GROUP BY p.product_id, p.name
    ORDER BY p.name;
    """
    return query
```**说明**：Python 函数仅返回 SQL 查询。 我们`LEFT JOIN` `Product`和`Invoice`包括所有产品。`SUM()`计算每个产品的总计，以及`COALESCE`确保无发票的产品归零。`GROUP BY`确保按产品进行聚合，并且`ORDER BY`确保按字母顺序排列`name`。 

## 解决方案```go
// Go solution using SQL query
func ProductWorthOverInvoices() string {
    query := `
    SELECT 
        p.name,
        COALESCE(SUM(i.rest), 0) AS rest,
        COALESCE(SUM(i.paid), 0) AS paid,
        COALESCE(SUM(i.canceled), 0) AS canceled,
        COALESCE(SUM(i.refunded), 0) AS refunded

    ORDER BY p.name;
    `
    return query
}

 ## 边缘情况

 一种重要的边缘情况是没有发票的产品。 没有`LEFT JOIN`和`COALESCE`，这些产品将被省略或返回 null，这是不正确的。 该查询明确确保返回零。 

另一个边缘情况是发票中某些货币栏为零。 聚合必须正确地对零值求和而不跳过它们，这就是 SQL`SUM()`自然处理。 

第三种边缘情况是同一产品的多张发票具有重叠的非零值。 聚合必须正确地对所有行（而不仅仅是一行）求和，以确保总计准确。 使用`GROUP BY`确保每个产品将其所有发票汇总到一行中。
