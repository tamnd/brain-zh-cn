[LeetCode 问题 1663](https://leetcode.com/problems/smallest-string-with-a-given-numeric-value/)

 **难度：** 🟡 中等
 **主题：** 字符串、贪婪

 ## 解决方案

 ## 问题理解

 问题要求我们构造一个长度为小写的字符串`n`使得其字符的数值总和等于`k`，同时还确保结果字符串**按字典顺序最小**。 

每个小写字母都有一个与其在字母表中的位置相等的数值：

 -`a = 1`-`b = 2`-`c = 3`- ...
 -`z = 26`例如，字符串`"abe"`其数值为：`1 + 2 + 5 = 8`我们有两个整数：

 -`n`, 所需的字符串长度
 -`k`, 所需的总数值

 我们的任务是返回满足这两个约束的**最小的字典字符串**。 

词典排序的行为类似于字典排序。 如果字符串在最早的不同位置具有较小的字符，则字符串较小。 这个细节非常重要，因为它告诉我们如何优化构造。 

例如，考虑：

 -`"aay"`→ 开始于`"aa"`-`"aby"`→ 开始于`"ab"`自从`'a' < 'b'`在第二个字符处，`"aay"`按字典顺序更小。 

挑战不仅仅是找到_任何_有效字符串，而是**尽可能小的字符串**。 

这些约束提供了重要的见解：

 -`1 <= n <= 10^5`-`n <= k <= 26 * n`下界`k >= n`保证存在解，因为我们总是可以用`'a'`，这有助于`1`每个。 

上限`k <= 26 * n`保证我们永远不需要更多`'z'`在任何位置。 

自从`n`可以大到`100,000`，指数或强力枚举是不可能的。 我们需要一个接近线性时间的解决方案。 

一些边缘情况立即脱颖而出：

 - 当`k = n`，每个字符都必须是`'a'`- 什么时候`k = 26 * n`，每个字符都必须是`'z'`- 当仅进行小调整时就超出了所有`'a'`需要字符
 - 当大值强制多个尾随时`'z'`人物
 - When the optimal string contains a mix of`'a'`，一个中间字符，以及几个`'z'`人物

 该问题保证有效答案始终存在，因此我们永远不需要处理不可能的输入。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的小写字符串长度`n`，计算它们的数值，并返回字典顺序最小的有效值。 

我们可以想象递归地生成字符串：

 - 在每个位置，尝试每个角色`'a'`到`'z'`- 继续直到长度`n`- 计算总数值
 - 保留最小的有效候选者

 这在概念上是有效的，因为它探索了每一种可能的解决方案并保证了正确性。 

然而，可能的字符串数量是：$$26^n$$即使对于较小的值`n`，这在计算上变得不可能。 

例如：

-`n = 10`大致给出`1.4 × 10^14`可能性
 -`n = 100000`大得难以想象

 因此，暴力破解是完全行不通的。 

### 最佳解决方案的关键见解

 为了获得按字典顺序排列的最小字符串，我们希望**最左边的字符尽可能小**。 

自从`'a'`是最小的字母，我们的第一直觉应该是：

 1. 填充字符串`'a'`2.战略性分配剩余价值

 最初，一个全`'a'`字符串具有值：$$n$$所以我们定义：$$remaining = k - n$$这代表我们仍然需要的额外数值。 

现在是贪婪的观察：

 为了最大限度地减少字典顺序，我们应该将较大的字母**尽可能放在最右边**。 

为什么？ 

因为较早的字符比较晚的字符对词典顺序的影响更大。 

例如：

-`"aay"`小于`"aya"`尽管两者包含相同的字母，但较早的`'a'`使第一个字符串变小。 

所以我们贪婪地工作**从右到左**，为每个角色添加尽可能多的价值。 

每个位置都已做出贡献`1`因为它开始于`'a'`。 

一个角色最多可以获得：$$26 - 1 = 25$$额外的价值。 

因此，对于从右到左的每个位置：

 - 尽可能多地添加，上限为`25`- 相应地转换字符
 - 减少剩余价值

 这种贪婪的策略保证了词典编纂的最小性。

 | --- | --- | --- | --- |
 | 蛮力 | O(26^n) | O(26^n) | O(n) | 枚举所有可能的字符串 |
 | 最优贪心 | O(n) | O(n) | 从右向左贪婪填充 |

 ## 算法演练

 1. 首先假设每个角色都是`'a'`。 

自从`'a'`贡献`1`, 一个全`'a'`字符串有总值`n`。 
2. 计算仍然需要的额外价值。 

我们计算：$$remaining = k - n$$这告诉我们必须在基线之外增加多少价值`'a'`人物。 
3.创建大小为的字符数组`n`，初始化为`'a'`。 

我们使用数组是因为字符串在许多语言中是不可变的，并且我们将有效地修改字符。 
4.从最右边的位置遍历到最左边的位置。 

我们从右向左移动，因为较大的字母应该稍后出现，以保持字符串按字典顺序最小。 
5. 在每个位置，添加尽可能多的额外价值。 

Each character can gain at most`25`额外积分。 

计算：$$extra = \min(25, remaining)$$6.更新当前角色。 

将字符转换为`'a'`到：$$chr(ord('a') + extra)$$示例：

 -`0 → 'a'`-`1 → 'b'`-`25 → 'z'`7. 减去附加值。 

更新：$$remaining -= extra$$8. 继续，直到分配完所有额外值。 
9. 将字符数组连接成字符串并返回。 

### 为什么它有效

 关键的不变量是早期的字符总是保持尽可能小。 

在每一步中，我们都会贪婪地将最大可能值分配给**最右边的可用位置**。 由于字典顺序优先考虑较早的字符，因此将大字母延迟到最后可以保证最小化。 

任何将较大字符放置在前面的替代解决方案必然会在字典顺序上更大。 

因此，这种贪心策略总是产生最小的有效字符串。 

## Python 解决方案```python
class Solution:
    def getSmallestString(self, n: int, k: int) -> str:
        chars = ['a'] * n
        
        remaining = k - n
        
        for i in range(n - 1, -1, -1):
            if remaining == 0:
                break

            extra = min(25, remaining)
            chars[i] = chr(ord('a') + extra)
            remaining -= extra

        return ''.join(chars)
```实现首先初始化一个数组`'a'`字符长度`n`。 这为我们提供了尽可能小的起点，同时贡献了基线值`n`。 

然后我们计算`remaining = k - n`，它表示仍必须分配多少额外数值。 

接下来，我们从最后一个索引向开头迭代。 对于每个位置，我们贪婪地分配尽可能多的额外价值，上限为`25`， 因为`'a'`已经做出贡献`1`和`'z'`贡献`26`。 

使用 ASCII 算术更新字符`ord()`和`chr()`。 最后，一旦分配了所有额外的值，我们就将字符列表加入到最终的字符串中。 

## 解决方案```go
func getSmallestString(n int, k int) string {
	chars := make([]byte, n)

	for i := 0; i < n; i++ {
		chars[i] = 'a'
	}

	remaining := k - n

	for i := n - 1; i >= 0; i-- {
		if remaining == 0 {
			break
		}

		extra := remaining
		if extra > 25 {
			extra = 25
		}

		chars[i] = byte('a' + extra)
		remaining -= extra
	}

	return string(chars)
}
```Go 的实现遵循完全相同的贪婪策略。 

由于 Go 中的字符串是不可变的，因此我们使用`[]byte`切片以有效地就地修改字符。 每个位置开始为`'a'`，然后我们从右向左遍历，贪婪地分配额外的价值。 

与 Python 不同，Go 不提供`min()`对于直接整数，因此我们使用条件语句手动实现上限。 

整数溢出不是问题，因为约束仍然在 Go 的整数限制内。

 ## 边缘情况

 ### 边缘情况 1：最小可能值

 当`k = n`，每个字符都必须是`'a'`。 

例如：```
n = 5, k = 5
```有缺陷的实现可能仍会尝试不必要地修改字符。 我们的实现正确计算：```
remaining = 0
```由于不需要额外的值，循环立即退出并返回`"aaaaa"`。 

### 边缘情况 2：最大可能值

 何时：```
k = 26 * n
```每个角色都必须成为`'z'`。 

例如：```
n = 3, k = 78
```该算法重复添加`25`为每个职位带来额外价值，最终产生：```
"zzz"
```贪婪逻辑自然地处理这个问题，而不需要任何特殊情况的代码。 

### 边缘情况 3：中间部分填充

 有时答案包含很多`'a'`字符、一个中间字符和几个`'z'`人物。 

例子：```
n = 5, k = 52
```从以下开始：```
aaaaa
```其余的：```
47
```我们从右边开始填写：

 - 最后一个字符→`z`(+25)
 - 倒数第二 →`w`(+22)

 结果：```
aaawz
```如果字符从左到右填充，这种情况很容易出错，因为这会产生按字典顺序更大的字符串。 通过从右到左填充，我们的实现保证了尽可能小的结果。
