[LeetCode 问题 1633](https://leetcode.com/problems/percentage-of-users-attended-a-contest/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算**参加每次竞赛的用户百分比**。 我们有两张表：`Users`和`Register`。 这`Users`表包含所有用户，每个用户都有一个唯一的`user_id`。 这`Register`表包含哪个用户注册了哪个比赛的记录，使用`contest_id`和`user_id`。 

目标是计算**每次竞赛中注册的唯一用户数量**，将其除以用户总数，再乘以 100，并将结果四舍五入到**两位小数**。 最终输出必须首先排序`percentage`按**降序**，如果出现平局，则按`contest_id`按**升序**。 

重要的限制和观察包括`user_id`是独一无二的，`(contest_id, user_id)`是唯一的，并且不存在缺失值。 可能会阻碍简单解决方案的边缘情况包括零注册竞赛、四舍五入问题和排序关系。 

## 方法

 **暴力方法**将迭代每个竞赛，计算注册用户的数量，计算每个竞赛的百分比，然后对结果进行排序。 虽然简单，但需要扫描整个`Register`如果简单地实现，则多次表，这对于大型数据集来说效率低下。 

**最佳方法**利用 SQL 聚合函数。 关键的见解是我们可以使用以下方法来计算每次比赛的用户数量`COUNT(user_id)`分组依据`contest_id`，并使用从以下位置获得的用户总数计算百分比`Users`。 这避免了多次扫描并将解决方案简化为单个查询。 然后可以在最后应用舍入和排序。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(k) | 对于每场比赛，迭代计算注册人数； n = 用户，m = 注册，k = 竞赛 |
 | 最佳 | O(n + m) | O(k) | 使用 SQL GROUP BY 进行聚合，对每次比赛进行计数，并一次性计算百分比 |

 ## 算法演练

 1. **统计总用户数**：从列表中检索用户总数`Users`表使用`COUNT(*)`。 这代表我们百分比计算的分母。 
2. **计算每次比赛的用户数**：汇总`Register`表格依据`contest_id`使用`COUNT(user_id)`获取每次比赛的注册用户数。 
3. **计算百分比**：对于每次比赛，将注册用户数除以总用户数，然后乘以 100。使用四舍五入确保结果具有**两位小数**。 
4. **对结果进行排序**：将最终结果首先排序`percentage`按降序排列，然后按`contest_id`按关系升序排列。 

**为什么有效**：计算每次比赛的用户数并除以总数可以保证准确的百分比，因为用户总数是恒定的。 SQL 聚合确保每个竞赛都是独立处理的，排序确保正确的呈现。 

## Python 解决方案```python
import sqlite3

def percentage_users_attended(db: sqlite3.Connection):
    query = """
    WITH total_users AS (
        SELECT COUNT(*) AS total FROM Users
    )
    SELECT
        r.contest_id,
        ROUND(COUNT(r.user_id) * 100.0 / t.total, 2) AS percentage
    FROM Register r
    CROSS JOIN total_users t
    GROUP BY r.contest_id
    ORDER BY percentage DESC, contest_id ASC
    """
    cursor = db.cursor()
    cursor.execute(query)
    return cursor.fetchall()
```**说明**：

 我们首先计算`total_users`作为持有用户总数的 CTE。 然后，我们汇总`Register`表格依据`contest_id`并计算每场比赛的百分比。`ROUND`确保两位小数的要求，并且`CROSS JOIN`允许访问总计数而无需每行中的子查询。 最后，我们根据问题要求对结果进行排序。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
    "fmt"
)

func PercentageUsersAttended(db *sql.DB) ([]struct {
    ContestID  int
    Percentage float64
}, error) {
    query := `
    WITH total_users AS (
        SELECT COUNT(*) AS total FROM Users
    )
    SELECT
        r.contest_id,
        ROUND(COUNT(r.user_id) * 100.0 / t.total, 2) AS percentage
    FROM Register r
    CROSS JOIN total_users t
    GROUP BY r.contest_id
    ORDER BY percentage DESC, contest_id ASC
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var results []struct {
        ContestID  int
        Percentage float64
    }

    for rows.Next() {
        var contestID int
        var percentage float64
        if err := rows.Scan(&contestID, &percentage); err != nil {
            return nil, err
        }
        results = append(results, struct {
            ContestID  int
            Percentage float64
        }{contestID, percentage})
    }
    return results, nil
}
```**Go 特定注释**：

 在 Go 中，我们定义了一个结构体切片来保存结果。`db.Query`执行 SQL，我们使用以下方法迭代行`rows.Next()`。`Scan`将结果列映射到 Go 变量。 我们使用`ROUND`在 SQL 中确保两位小数的精度，避免在 Go 中进行任何后处理。 

## 工作示例

 使用问题中的示例：

 | 竞赛_id | 注册用户 | 百分比 |
 | --- | --- | --- |
 | 208 | 208 3 | 100.0 | 100.0
 | 209 | 209 3 | 100.0 | 100.0
 | 210 | 210 3 | 100.0 | 100.0
 | 215 | 215 2 | 66.67 | 66.67
 | 207 | 207 1 | 33.33 |

 **步骤**：

 1. 用户总数 = 3
 2. 每场比赛计数：208 -> 3、209 -> 3、210 -> 3、215 -> 2、207 -> 1
 3. 计算百分比：`(count / 3) * 100`, 四舍五入到小数点后两位
 4. 对于平局，按百分比降序排序，并按 racing_id 升序排序

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | n = 用户数，m = 注册数； 计算用户数和聚合注册是线性运算 |
 | 空间| O(k) | k = 比赛次数； 存储每次比赛的汇总计数 |

 这是最佳的，因为我们只扫描一次用户表和一次寄存器表。 排序是根据比赛的数量进行的，该数量通常比总行数小得多。

 ## 边缘情况

 **无注册**：如果竞赛没有注册，则不应出现在输出中。 使用`GROUP BY`于`Register`表自然排除了此类竞赛。 

**所有用户在竞赛中注册**：这会导致百分比为 100。正确的舍入至关重要，解决方案使用以下方法处理此问题`ROUND`。 

**舍入精度**：如果百分比的小数位数超过两位，舍入可能会导致边缘情况，例如 66.666... 变成 66.67。 使用 SQL`ROUND`函数保证两位小数的精度。 

**百分比平局**：具有相同百分比的多个比赛必须按以下顺序排序`contest_id`上升。 这是在`ORDER BY`条款。 

这种方法可确保正确处理所有边缘情况，无需额外的逻辑。
