[LeetCode 第 1610 题](https://leetcode.com/problems/maximum-number-of-visible-points/)

 **难度：** 🔴难
 **主题：** 数组、数学、几何、滑动窗口、排序

 ## 解决方案

 ## 问题理解

 在这个问题中，我们站在 2D 平面上的固定位置，由`location = [posx, posy]`。 我们周围有多个点，每个点都有整数坐标。 我们可以原地旋转，但不能移动。 

我们的视觉就像一个视角有限的相机。 参数`angle`告诉我们视野有多宽。 如果我们向某个方向旋转`d`，那么我们可以看到相对于我们的方向落在包含角度区间内的每个点：$$[d - \tfrac{\text{angle}}{2},\ d + \tfrac{\text{angle}}{2}]$$目标是确定某个旋转方向同时可见的最大点数。 

重要的几何细节是可见性仅取决于我们的位置到每个点的角度。 距离并不重要。 多个点可以在同一坐标处重叠，并且点之间不会相互遮挡。 

无论旋转如何，恰好位于我们自己位置的点始终可见。 这些点需要特殊处理，因为它们的方向未定义。 

限制条件很大：

 - 最多`10^5`点
 - 坐标是小整数，但点数很大
 - 解必须明显优于二次时间

 这立即排除了任何比较每对点或天真的尝试每个可能的观察方向的算法。 

一些边缘情况尤其重要：

 - 点恰好位于`location`- 附近的角度`0° / 360°`边界
 - 重复的方向
 -`angle = 0`，其中只能同时看到完全相同方向的点
 - 非常大的视角接近`360°`角度的圆形性质是这个问题的主要挑战。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将每个点方向视为观察窗口的可能中心。 

对于每个候选方向：

 1. 计算每隔一点的角度方向
 2. 计算有多少个落在观看范围内
 3. 跟踪最大计数

 这是有效的，因为最佳观看方向必须与某个点边界对齐。 然而，如果有`n`点，那么对于每个点，我们可以扫描所有其他点，从而导致`O(n^2)`时间复杂度。 

和`n = 10^5`，二次时间太慢了。 

### 关键见解

 关键的观察是每个点都可以用相对于观察者的单个角度来表示。 

使用`atan2(dy, dx)`，我们可以将每个点转换为以度为单位的角度。 一旦所有点都以这种方式表示：

 - 问题变成在一定大小的窗口内找到最大的角度组`angle`- 对角度进行排序后，可见点形成连续的线段

 这将几何问题转换为排序数组上的滑动窗口问题。 

剩下的复杂问题是圆形环绕。 例如：

 - 一点可能有角度`359°`- 另一个可能有角度`1°`这些点其实只是`2°`分开，但按排序顺序，它们看起来很远。 

我们通过复制角度列表来解决这个问题`+360°`添加到每个角度。 这使圆形结构线性化并允许标准滑动窗口。

 ## 算法演练

 ### 第 1 步：分离重合点

 点正好位于`location`始终可见。 

对于每个点：

 - 如果`(x, y) == location`, 增量`same_position`- 否则，正常处理其方向

 我们单独存储始终可见的点，因为它们不参与角度计算。 

### 步骤 2：将点转换为角度

 对于每个剩余点：

 1. 计算：$$dx = x - posx$$

$$dy = y - posy$$2. 使用以下公式计算角度：$$\theta = \text{atan2}(dy, dx)$$这`atan2`函数正确处理所有象限并返回以弧度为单位的角度。 

1. 将弧度转换为度数。 

我们现在有一个方向角列表。 

### 步骤 3：对角度进行排序

 排序将所有方向按升序排列。 

这是至关重要的，因为任何可见的点集都必须按角度顺序连续出现。 

### 步骤 4：处理圆形环绕

 角是圆形的。 

例如：

-`359°`-`1°`它们在几何上接近，但在数值上相距甚远。 

要干净地处理这个问题：

 - 复制每个角度`+360°`- 将这些新值附加到数组中

 示例：```
Original:
[1, 45, 359]

Extended:
[1, 45, 359, 361, 405, 719]
```现在，每个有效的查看窗口都成为一个标准的连续间隔。 

### 步骤 5：使用滑动窗口

 维护两个指针：

 -`left`-`right`扩张`right`通过扩展数组。 

尽管：$$angles[right] - angles[left] > angle$$移动`left`向前。 

步步：$$window\_size = right - left + 1$$跟踪最大窗口大小。 

这给出了可见方向点的最大数量。 

### 步骤 6：添加重合点

 最后：```
answer = best_window + same_position
```因为重合点总是可见的。 

### 为什么它有效

 排序后，每组可见点对应一个连续的角度区间。 滑动窗口保持了窗口内所有点最多相差的不变性`angle`度。 

复制数组`+360°`将圆形几何图形转换为线性间隔问题，确保正确处理环绕可见性。 

因为每个可能的有效区间都会被滑动窗口检查一次，所以算法总是能找到最佳答案。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def visiblePoints(self, points: List[List[int]], angle: int, location: List[int]) -> int:
        same_position = 0
        angles = []

        posx, posy = location

        for x, y in points:
            if x == posx and y == posy:
                same_position += 1
            else:
                dx = x - posx
                dy = y - posy

                degree = math.degrees(math.atan2(dy, dx))
                angles.append(degree)

        angles.sort()

        extended_angles = angles + [a + 360 for a in angles]

        max_visible = 0
        left = 0

        for right in range(len(extended_angles)):
            while extended_angles[right] - extended_angles[left] > angle:
                left += 1

            max_visible = max(max_visible, right - left + 1)

        return max_visible + same_position
```实现首先将精确位于观察者位置的点分开。 这些点会立即计算在内，因为它们始终可见。 

对于每个其他点，代码使用以下方式计算方向角`atan2`。 使用`math.degrees`将弧度转换为度数，以便比较直接匹配问题陈述。 

对角度列表进行排序后，实现构造`extended_angles`通过附加移动的每个角度`360`。 这消除了圆形环绕的复杂性。 

然后滑动窗口扫描扩展数组。 只要角度跨度超过允许的视角，左指针就会前进。 

在每次迭代中，当前窗口代表一组有效的可见点。 该算法跟踪最大的此类窗口，并最终添加始终可见的重合点。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func visiblePoints(points [][]int, angle int, location []int) int {
	posx, posy := location[0], location[1]

	samePosition := 0
	angles := make([]float64, 0)

	for _, point := range points {
		x, y := point[0], point[1]

		if x == posx && y == posy {
			samePosition++
		} else {
			dx := float64(x - posx)
			dy := float64(y - posy)

			degree := math.Atan2(dy, dx) * 180.0 / math.Pi
			angles = append(angles, degree)
		}
	}

	sort.Float64s(angles)

	extended := make([]float64, 0, len(angles)*2)
	extended = append(extended, angles...)

	for _, a := range angles {
		extended = append(extended, a+360.0)
	}

	maxVisible := 0
	left := 0

	for right := 0; right < len(extended); right++ {
		for extended[right]-extended[left] > float64(angle) {
			left++
		}

		windowSize := right - left + 1
		if windowSize > maxVisible {
			maxVisible = windowSize
		}
	}

	return maxVisible + samePosition
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个显着的区别是显式浮点转换。 由于Go严格区分整数和浮点值，`dx`和`dy`必须转换为`float64`打电话之前`math.Atan2`。 

Go 还需要手动构建重复角度数组的切片。 滑动窗口逻辑保持不变。 

不存在整数溢出问题，因为坐标很小并且所有角度计算都使用浮点运算。

 ## 边缘情况

 当点恰好位于观察者的位置时，就会出现一种重要的边缘情况。 这些点没有有意义的方向，因为从观察者到该点的矢量为零。 幼稚的实现可能会错误地尝试计算它们的角度，从而导致未定义的行为。 该解决方案通过单独计算这些点并将它们添加到最终结果中来完全避免这种情况。 

另一个关键的边缘情况涉及附近的环绕`0°`和`360°`。 例如，指向`359°`和`1°`几何上只有两度，但数值上却相距甚远。 无需使用复制角度数组`+360°`，滑动窗口将无法检测到这些有效间隔。 扩展数组将循环问题转化为线性问题。 

第三种微妙的情况发生在`angle = 0`。 在这种情况下，只能一起查看方向完全相同的点。 浮点不准确可能会在这里引入错误。 然而，因为所有角度都是使用一致计算的`atan2`，相同的方向产生相同的浮点值，从而允许滑动窗口比较正常工作。 

另一个重要的场景是当多个点共享相同方向但距离不同时。 由于能见度仅取决于角度，而不取决于距离，因此所有此类点应同时计数。 该算法自然地处理这个问题，因为具有相同方向的点按排序的角度顺序占据相同的位置。
