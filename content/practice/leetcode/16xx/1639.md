[LeetCode 问题 1639](https://leetcode.com/problems/number-of-ways-to-form-a-target-string-given-a-dictionary/)

 **难度：** 🔴难
 **主题：** 数组、字符串、动态规划

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为的字符串列表`words`，其中每个字符串具有相同的长度，另一个字符串称为`target`。 我们需要计算我们可以构建多少种不同的方式`target`通过从列中选择字符`words`。 

重要的限制是我们构建`target`从左到右，一旦我们使用列索引`k`, 每列`<= k`在所有字符串中永久不可用。 这意味着所选的列索引必须严格递增。 

例如，假设我们选择列`2`建造`target[0]`。 那么目标的下一个字符只能来自列`3`,`4`， 等等。 我们不是选择整个单词，而是选择列，并且在每一列中我们可以使用包含那里所需字符的任何单词。 

这将问题从简单的字符串匹配任务变成了组合动态规划问题。 

输入约束很大：

 - 最多`1000`话
 - 每个单词长度可达`1000`- 目标长度可达`1000`简单的递归搜索会呈指数级增长，因为每个目标字符可能有许多有效的列选择。 因此，我们需要一个高度优化的解决方案。 

一些观察结果立即引人注目：

 - 由于所有单词的长度相同，我们可以逐列思考。 
- 列的顺序很重要。 
- 多个单词可能在同一列中贡献相同的字符。 
- 我们只关心每列的字符频率，而不是每个单词的确切身份。 

重要的边缘情况包括：

 - 目标比单词长度长，自动给出答案`0`。 
- 不包含所需字符的列。 
- 需要模运算的大量计数。 
- 目标中的重复字符，这可能会产生许多重叠的子问题。 

## 方法

 ### 蛮力方法

 强力解决方案将递归地尝试目标中每个字符的每个可能的列。 

对于每个目标字符：

 1. 迭代所有剩余的列。 
2. 检查每个单词，看看该列是否包含所需的字符。 
3. 递归地继续构建目标的其余部分。 

这种方法是正确的，因为它探索了增加列索引的每个有效序列。 然而，它太慢了。 

如果有`m`列和目标长度`t`，单独可能的增加列序列的数量大致是组合的，接近于`C(m, t)`。 此外，每个步骤都会扫描所有单词。 

运行时间呈指数增长，无法处理约束大小。 

### 关键见解

 关键的观察是这个词的实际身份并不重要。 重要的是：

 > 对于每一列，每个字符包含多少个单词。 

假设列`5`包含字母`'a'`在`7`不同的词。 如果我们想放置`'a'`到了这一步，那么这个列就贡献了`7`可能的选择。 

这让我们可以预处理频率计数：```
count[column][character] = number of words having that character in that column
```那么问题就变成了：

 - 从左到右处理列。 
- 决定是否使用当前列作为下一个目标字符。 
- 使用动态规划有效地计算路数。 

这将指数搜索转换为多项式时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 大约 O(2^m × n) | O(t) 递归 | 探索所有列组合 |
 | 最优动态规划| O(n × m + m × t) | O(m × 26 + t) | 使用列字符频率和 DP |

 在哪里：

-`n = len(words)`-`m = len(words[0])`-`t = len(target)`## 算法演练

 ### 步骤 1：预先计算每列的字符频率

 我们创建一个二维数组，其中：```
freq[col][char]
```存储包含多少个单词`char`在列`col`。 

例如：```
words = ["acca","bbbb","caca"]
```柱子`0`包含：```
a, b, c
```所以：```
freq[0]['a'] = 1
freq[0]['b'] = 1
freq[0]['c'] = 1
```这种预处理使我们能够立即知道给定列中的目标字符存在多少个选择。 

### 步骤 2：定义 DP 状态

 我们定义：```
dp[i]
```作为形成第一个的方式的数量`i`目标的字符。 

最初：```
dp[0] = 1
```因为只有一种方法可以形成空字符串。 

### 步骤 3：从左到右处理列

 对于每一列：

 - 我们可能会选择将其用于某些目标角色。 
- 或者我们可以跳过它。 

为了避免过早覆盖状态，我们向后迭代目标索引。 

假设当前列贡献字符`'a'`三次。 

如果：```
target[j] == 'a'
```然后：```
dp[j + 1] += dp[j] * 3
```这意味着：

 - 以各种方式建造第一个`j`人物
 - 可以扩展成构建第一个的方式`j + 1`- 使用三个可用的任何一个`'a'`此列中的字符。 

### 步骤 4：使用模运算

 组合的数量可能会变得巨大，因此每次更新都以模计算：```
10^9 + 7
```###第五步：返回最终答案

 处理完所有列后：```
dp[len(target)]
```包含形成整个目标的方法总数。 

### 为什么它有效

 该算法保持了处理列后的不变性`c`,`dp[i]`存储构建第一个的方法数量`i`仅使用列的目标字符`0...c`。 

每列只处理一次，并且向后迭代可确保同一列不能针对不同的目标位置多次重复使用。 由于每个有效的构造都对应于唯一的递增列序列，因此 DP 对每个有效解决方案仅计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def numWays(self, words: List[str], target: str) -> int:
        MOD = 10**9 + 7
        
        word_length = len(words[0])
        target_length = len(target)
        
        if target_length > word_length:
            return 0
        
        # freq[col][char_index]
        freq = [[0] * 26 for _ in range(word_length)]
        
        for word in words:
            for col, ch in enumerate(word):
                freq[col][ord(ch) - ord('a')] += 1
        
        # dp[i] = number of ways to form first i characters
        dp = [0] * (target_length + 1)
        dp[0] = 1
        
        for col in range(word_length):
            # Traverse backwards to avoid reusing same column
            for i in range(target_length - 1, -1, -1):
                target_char_index = ord(target[i]) - ord('a')
                
                char_count = freq[col][target_char_index]
                
                if char_count > 0:
                    dp[i + 1] = (
                        dp[i + 1] + dp[i] * char_count
                    ) % MOD
        
        return dp[target_length]
```实现首先检查目标是否长于可用列数。 如果是的话，就不可能形成目标。 

接下来，该解决方案构建频率表。 每列存储每个字符出现的次数，而不是在 DP 转换期间重复扫描所有单词。 

然后动态编程数组被初始化。`dp[0] = 1`代表空前缀。 

对于每一列，我们向后迭代目标索引。 向后遍历至关重要，因为它可以防止在一次迭代中多次使用同一列。 

每次更新：```python
dp[i + 1] += dp[i] * char_count
```意思是：

 - 有`dp[i]`形成当前前缀的方法。 
- 当前栏目提供`char_count`扩展它的方法。 

最后，`dp[target_length]`包含有效结构的总数。 

## 解决方案```go
func numWays(words []string, target string) int {
	const MOD int = 1_000_000_007

	wordLength := len(words[0])
	targetLength := len(target)

	if targetLength > wordLength {
		return 0
	}

	// freq[col][char]
	freq := make([][]int, wordLength)
	for i := 0; i < wordLength; i++ {
		freq[i] = make([]int, 26)
	}

	for _, word := range words {
		for col, ch := range word {
			freq[col][ch-'a']++
		}
	}

	dp := make([]int, targetLength+1)
	dp[0] = 1

	for col := 0; col < wordLength; col++ {
		for i := targetLength - 1; i >= 0; i-- {
			charIndex := target[i] - 'a'
			charCount := freq[col][charIndex]

			if charCount > 0 {
				dp[i+1] = (dp[i+1] + dp[i]*charCount) % MOD
			}
		}
	}

	return dp[targetLength]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个重要的区别是整数处理。 由于中间乘法值可能会变大，因此每次更新后立即应用模运算。 

Go 切片是显式初始化的，与可以使用乘法语法创建的 Python 列表不同。 

反向遍历逻辑保持完全相同，因为它对于正确性至关重要。

 ## 边缘情况

 ### 目标比字长长

 如果目标长度超过字长，则不可能形成目标，因为列必须严格按递增顺序使用，并且每一列最多只能贡献一个字符。 

幼稚的实现可能仍然尝试递归或 DP，浪费时间。 该解决方案立即返回`0`。 

### 缺少必需的字符

 某些目标可能包含从未出现在必要列中的字符。 

例如：```
words = ["abc", "def"]
target = "zzz"
```在这种情况下，每次频率查找都变为零，因此不会发生 DP 转换。 该算法自然地将最终 DP 状态保留为零。 

### 重复字符导致重复计数

 目标例如：```
target = "aaa"
```如果从左到右执行 DP 更新，很容易导致错误。 

如果我们向前更新，同一列可能会在一次迭代中意外地贡献多个目标位置。 向后遍历通过确保每个列在每个过渡层最多使用一次来防止这种情况发生。 

### 极大的答案值

 组合的数量可能会变得巨大，因为每一列都可能提供许多有效的选择。 

如果没有模运算，许多语言都会发生整数溢出。 两种实现都适用模数`10^9 + 7`每次更新后，即使对于最大的输入也能保证正确性。
