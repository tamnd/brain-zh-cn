[LeetCode 第 1618 题](https://leetcode.com/problems/maximum-font-to-fit-a-sentence-in-a-screen/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、二分查找、交互

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给定一个字符串`text`必须在屏幕内以单行显示，宽度为`w`和身高`h`。 我们还得到了一个排序数组`fonts`，其中每个值代表我们可以使用的可用字体大小。 

重要的细节是文本的实际渲染尺寸不是由我们直接计算的。 相反，我们必须使用提供的`FontInfo`界面：

-`getWidth(fontSize, ch)`返回单个字符的宽度`ch`当使用渲染时`fontSize`-`getHeight(fontSize)`使用以下命令返回任何字符的高度`fontSize`整个字符串的宽度是其中所有字符的宽度之和`text`，因为文本显示在一行上。 字符串的高度就是返回的字体高度`getHeight(fontSize)`。 

我们的任务是确定最大字体大小`fonts`这样：

 - 文本总宽度小于或等于`w`- 文字高度小于或等于`h`如果没有字体大小满足这两个条件，我们返回`-1`。 

约束足够大，效率很重要：

 -`text.length`可以达到`50,000`-`fonts.length`可以达到`100,000`检查每种字体并重复重新计算每个字符宽度的简单解决方案可能会变得极其昂贵。 

该问题还提供了非常重要的单调性保证：

 - 字符宽度不会随着字体大小的增加而减小
 - 字体高度不会随着字体大小的增加而减小

 这种单调行为强烈表明可以使用二分搜索。 

一些边缘情况很重要：

 - 即使是最小的字体也可能不适合
 - 每种字体都可能适合，在这种情况下我们返回最大的字体
 - 宽度可能会失败，而高度会通过
 - 高度可能会失败，而宽度会通过
 - 字符串中可以包含重复的字符，导致很多重复`getWidth`调用一个简单的实现

 由于接口调用理论上是恒定的时间，但实际上仍然很昂贵，因此最大限度地减少不必要的调用是很有价值的。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代中的每个字体大小`fonts`从最小到最大。 

对于每种字体：

 1.检查内部高度是否合适`h`2. 通过对每个字符的宽度求和来计算字符串的总宽度
 3. 如果两个约束都满足，则更新答案

 自从`fonts`已排序，最后遇到的有效字体就是答案。 

这种方法是正确的，因为它明确验证了每种可能的字体大小。 然而，这是低效的，因为我们可能会扫描所有字体大小，并且对于每一种字体大小，我们可能会扫描整个字符串。 

如果：

-`F = len(fonts)`-`N = len(text)`那么复杂度就变成了`O(F * N)`。 

如果两个值都很大，这可能会变得太慢。 

### 最佳方法

 关键的观察结果是字体大小的有效性是单调的。 

如果字体大小适合屏幕，那么每个较小的字体大小也适合。 

如果字体大小不适合，那么每个较大的字体大小也都不适合。 

这创建了一个经典的二分搜索条件。 

我们定义一个辅助函数：

 -`can_fit(fontSize)`返回文本是否适合宽度`w`和身高`h`然后我们对排序后的结果进行二分查找`fonts`数组来查找最大的有效字体。 

每个二分搜索步骤都会检查一种字体大小。 助手计算：

 - 身高条件优先
 - 仅当高度超过时宽度条件

 这提供了更有效的解决方案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(F × N) | O(1) | O(1) | 按顺序检查每个字体大小 |
 | 最佳 | O(N × log F) | O(N × log F) | O(1) | O(1) | 在单调有效性上使用二分搜索 |

 在哪里：

-`F = len(fonts)`-`N = len(text)`## 算法演练

 1. 定义辅助函数`can_fit(font_size)`。 

此函数确定文本是否适合使用给定字体大小的屏幕。 
2. 内部`can_fit`，首先检查字体高度。 

称呼：```
fontInfo.getHeight(font_size)
```如果高度超过`h`， 返回`False`立即地。 

这种早期拒绝很重要，因为它避免了不必要的宽度计算。 
3. 计算文本的总宽度。 

遍历中的每个字符`text`和总和：```
fontInfo.getWidth(font_size, ch)
```如果运行总计超过`w`, 提早停车并返回`False`。 
4. 如果高度和宽度约束都通过，则返回`True`。 
5. 对以下内容执行二分查找`fonts`大批。 

由于数组已排序并且有效性是单调的：

 - 如果字体适合，则在右半部分搜索更大的有效字体
 - 如果字体不适合，则搜索左半部分
 6. 维护一个变量`answer`。 

每当找到有效字体时，将其存储为当前最佳答案。 
7. 继续直到二分查找完成。 
8. 返回存储的答案。 

如果没有合适的字体，答案仍然存在`-1`。 

### 为什么它有效

 该算法依赖于字体有效性的单调性。 

如果特定的字体大小适合：

 - 所有较小的字体大小也必须适合，因为宽度和高度永远不会减小。 

如果特定字体大小不适合：

 - 所有较大的字体大小也必须失败。 

这将创建一个有效的二分搜索空间。 二分查找保证我们有效地找到最大的有效字体。 

## Python 解决方案```python
from typing import List

# """
# This is FontInfo's API interface.
# You should not implement it, or speculate about its implementation
# """
# class FontInfo(object):
#     def getWidth(self, fontSize, ch):
#         pass
#
#     def getHeight(self, fontSize):
#         pass

class Solution:
    def maxFont(
        self,
        text: str,
        w: int,
        h: int,
        fonts: List[int],
        fontInfo: 'FontInfo'
    ) -> int:

        def can_fit(font_size: int) -> bool:
            if fontInfo.getHeight(font_size) > h:
                return False

            total_width = 0

            for ch in text:
                total_width += fontInfo.getWidth(font_size, ch)

                if total_width > w:
                    return False

            return True

        left = 0
        right = len(fonts) - 1
        answer = -1

        while left <= right:
            mid = (left + right) // 2
            font_size = fonts[mid]

            if can_fit(font_size):
                answer = font_size
                left = mid + 1
            else:
                right = mid - 1

        return answer
```该实现紧密遵循前面描述的算法。 

这`can_fit`helper 封装了单个字体大小的验证逻辑。 它首先检查高度，因为高度评估是恒定时间，并且可以立即消除无效字体。 

宽度计算使用运行总和。 一旦宽度超过`w`，函数提前退出。 这避免了对长字符串的不必要的接口调用。 

二分查找对以下索引进行操作`fonts`大批。 每当一种字体适合时，它就会成为当前的最佳答案，并且继续向右搜索以寻找更大的有效字体。 

如果字体不适合，搜索将向左移动，因为较大的字体也会由于单调性而失败。 

二分查找完成后返回最终答案。 

## 解决方案```go
/**
 * // This is FontInfo's API interface.
 * // You should not implement it, or speculate about its implementation
 * type FontInfo struct {}
 *
 * func (f *FontInfo) GetWidth(fontSize int, ch byte) int {}
 *
 * func (f *FontInfo) GetHeight(fontSize int) int {}
 */

type Solution struct{}

func (s *Solution) maxFont(
	text string,
	w int,
	h int,
	fonts []int,
	fontInfo FontInfo,
) int {

	canFit := func(fontSize int) bool {
		if fontInfo.GetHeight(fontSize) > h {
			return false
		}

		totalWidth := 0

		for i := 0; i < len(text); i++ {
			totalWidth += fontInfo.GetWidth(fontSize, text[i])

			if totalWidth > w {
				return false
			}
		}

		return true
	}

	left := 0
	right := len(fonts) - 1
	answer := -1

	for left <= right {
		mid := left + (right-left)/2
		fontSize := fonts[mid]

		if canFit(fontSize) {
			answer = fontSize
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return answer
}
```Go 实现几乎完全反映了 Python 逻辑。 

一个小的语言差异是 Go 字符串以字节为索引。 由于该问题仅保证小写英文字母，因此使用`text[i]`因为字节是完全安全的。 

二分查找使用：```go
mid := left + (right-left)/2
```这避免了一般二分搜索实现中潜在的整数溢出。 

Go 还使用显式变量声明和类型化切片而不是 Python 列表。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N × log F) | O(N × log F) | 二分查找执行 O(log F) 检查，每次最多扫描 N 个字符 |
 | 空间| O(1) | O(1) | 仅使用常量额外变量 |

 与暴力方法相比，二分搜索极大地减少了字体检查的数量。 

在最坏的情况下，每次有效性检查可能会扫描整个字符串，尽管提前终止通常会提高实际性能。 

没有使用与输入大小成比例的辅助数据结构，因此该算法需要恒定的额外空间。

 ## 边缘情况

 当字体大小不合适时，就会出现一种重要的边缘情况。 有错误的实现可能会意外返回最小字体或无法正确初始化答案。 在这个解决方案中，`answer`开始为`-1`并且仅在找到有效字体时更新，以确保正确的行为。 

另一个关键的边缘情况是高度约束立即失效。 由于高度是单调的并且与文本长度无关，因此在计算宽度之前检查它可以防止不必要的工作。 这种优化在以下情况下尤其重要：`text`非常大。 

第三个重要的边缘情况涉及精确的边界拟合。 允许文本恰好占据宽度`w`和身高`h`。 实现正确使用`>`比较而不是`>=`，意味着平等被视为有效。 

极长的字符串会出现与性能相关的微妙边缘情况。 一个天真的实现可能会继续对宽度进行求和，即使在超过`w`。 这种方案一旦宽度变得太大就立即停止，避免了不必要的接口调用。 

另一个重要的场景是每种字体都适合。 只要找到有效字体，二分搜索就会继续向右移动，保证返回最大的有效字体，而不是遇到的第一个字体。
