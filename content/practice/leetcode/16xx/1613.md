[LeetCode 问题 1613](https://leetcode.com/problems/find-the-missing-ids/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`Customers`，其中每行包含一个唯一的`customer_id`以及相应的`customer_name`。 

我们的任务是识别之间所有丢失的客户 ID`1`和最大`customer_id`目前出现在表中。 

换句话说，假设表中最大的客户 ID 是`max_id`。 我们必须检查包含范围内的每个整数`[1, max_id]`并确定哪些 ID 没有出现在`Customers`桌子。 

例如，如果现有客户 ID 为：```
1, 4, 5
```那么最大ID是`5`，所以完整的预期范围是：```
1, 2, 3, 4, 5
```在这些值中，`2`和`3`丢失了，所以应该归还。 

结果必须包含名为的单个列`ids`，按升序排列。 

一个非常重要的约束是最大`customer_id`不超过`100`。 这告诉我们搜索空间非常小。 即使是简单的方法在这里也足够有效。 然而，我们仍然希望编写一个干净且可扩展的 SQL 解决方案。 

一些重要的边缘情况包括：

 - 该表可能已经包含来自`1`到`max_id`。 在这种情况下，结果应该为空。 
- 最小的 ID 可能不开始于`1`。 例如，如果表仅包含 ID`3`和`4`，然后是 ID`1`和`2`被视为失踪，必须归还。 
- 该表可能仅包含一名客户。 如果该客户有 ID`1`，没有丢失的 ID。 如果顾客有身份证`5`，然后是 ID`1, 2, 3, 4`失踪了。 
- 由于 ID 是唯一的，因此我们不需要处理重复项。 

## 方法

 ### 蛮力方法

 蛮力的想法很简单。 首先，确定表中最大的客户ID。 然后生成每个数字`1`通过该最大值。 对于每个生成的数字，扫描`Customers`表以查看该 ID 是否存在。 

如果该 ID 不存在，则将其包含在结果中。 

这种方法是正确的，因为它明确检查所需范围内的每个可能的有效 ID。 

然而，效率低下的部分是重复扫描表中的每个候选 ID。 如果表很大，这会变得昂贵，因为每次查找都可能需要全表扫描。 

尽管这里的限制很小，但蛮力在概念上仍然是低效的。 

### 最佳方法

 更好的方法是生成所有数字`1`到`max(customer_id)`一次，然后使用基于集合的 SQL 操作，例如`LEFT JOIN`或者`NOT EXISTS`有效识别缺失值。 

关键的见解是我们不是在寻找模式或执行复杂的计算。 我们只需要以下之间的数学差异：

 - 完整的有效 ID 范围
 - 表中已存在的 ID

 由于最大ID最多为`100`，我们可以使用递归公用表表达式（也称为递归 CTE）方便地生成数字。 

递归 CTE 产生序列：```
1, 2, 3, ..., max_id
```然后我们将生成的序列与`Customers`桌子。 任何没有匹配客户记录的生成号码都会丢失。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(M × N) | O(M)| 生成所有 ID 并扫描表中的每个 ID |
 | 最佳 | O(M + N) | O(M)| 生成 ID 一次并使用基于集合的过滤 |
 | | | | |

 这里：

-`N`是行数`Customers`-`M`是最大客户ID，最多`100`## 算法演练

 1. 首先，计算最大客户 ID`Customers`桌子。 这定义了我们必须检查的有效范围的上限。 
2. 使用递归 CTE 生成从`1`直到最大 ID。 这将创建预期客户 ID 的完整序列。 
3. 执行`LEFT JOIN`生成的序列和之间`Customers`使用客户 ID 作为连接条件的表。 
4. join后，客户端所在行`NULL`表示原表中不存在的ID。 
5. 按升序返回这些缺失的 ID。 

### 为什么它有效

 该算法之所以有效，是因为递归 CTE 只生成所需范围内的每个有效 ID 一次。 这`LEFT JOIN`保留所有生成的 ID，即使是那些没有匹配客户记录的 ID。 因此，任何无法与客户行匹配的生成 ID 必定会从表中丢失。 

由于每个 ID 在`[1, max_id]`经检查，结果完整、正确。 

## Python 解决方案

 LeetCode 数据库问题是使用 SQL 而不是可执行的 Python 代码来解决的。 以下部分以 Python 风格的代码块提供 SQL 查询，以与请求的格式保持一致。```python
WITH RECURSIVE numbers AS (
    SELECT 1 AS ids
    
    UNION ALL
    
    SELECT ids + 1
    FROM numbers
    WHERE ids < (SELECT MAX(customer_id) FROM Customers)
)

SELECT n.ids
FROM numbers n
LEFT JOIN Customers c
    ON n.ids = c.customer_id
WHERE c.customer_id IS NULL
ORDER BY n.ids;
```该解决方案首先定义一个名为的递归 CTE`numbers`。 

基本情况生成初始值`1`。 

递归步骤重复添加`1`到先前的值，直到序列达到表中存在的最大客户 ID。 

生成完整序列后，查询执行`LEFT JOIN`反对`Customers`桌子。 现有客户 ID 成功匹配表中的行，而缺少 ID 则产生`NULL`客户方面的价值观。 

这`WHERE`子句仅过滤那些与缺失 ID 相对应的不匹配行。 

最后将结果按要求升序排序。

 ## 边缘情况

 ### 情况 1：没有丢失 ID

 如果该表已包含来自`1`到`max_id`，结果应该为空。 

例如：```
1, 2, 3, 4
```有缺陷的实现可能会由于不正确的连接条件或过滤逻辑而意外返回额外的行。 

该解决方案可以正确处理这种情况，因为只有带有`NULL`返回匹配项。 完全匹配的行被排除。 

### 情况 2：ID 不从 1 开始

 该表可能以较大的 ID 开头，例如：```
3, 4, 5
```在这种情况下，ID`1`和`2`仍然被认为是缺失的，因为所需的范围总是从`1`。 

一些不正确的解决方案错误地从现有的最小 ID 开始生成数字，而不是从`1`。 

此实现显式地开始递归序列`1`, guaranteeing correct behavior.

 ### Case 3: Only One Customer Exists

 如果表包含单行：```
customer_id = 5
```然后是ID`1, 2, 3, 4`必须归还。 

当仅存在一行时，幼稚的实现可能会错误地假设不存在缺失值。 

递归生成步骤避免了这个问题，因为它仍然构建从`1`通过`5`。
