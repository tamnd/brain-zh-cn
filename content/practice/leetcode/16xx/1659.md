[LeetCode 第 1659 题](https://leetcode.com/problems/maximize-grid-happiness/)

 **难度：** 🔴难
 **主题：** 动态编程、位操作、记忆、位掩码

 ## 解决方案

 ## 问题理解

 这个问题要求我们将内向者和外向者置于一个`m x n`以最大化总幸福分数的方式网格。 每个网格单元格可以保持为空、包含一名内向者或包含一名外向者。 我们可以留下一些不使用的人，所以我们不一定要放置所有内向和外向的人。 

每种类型的人都会贡献不同的基本幸福值，并对邻居做出不同的反应：

 - 内向者开始于`120`幸福与失去`30`为每一个相邻的邻居带来幸福。 
- 外向的人开始于`40`幸福与收获`20`为每一个相邻的邻居带来幸福。 

邻居只是四个直接相邻的单元格：上、下、左、右。 

重要的细节是，邻里关系的影响同时影响到两个人。 例如：

 - 两个内向的人在一起：

 - 第一个内向者输了`30`- 第二个内向者输了`30`- 总变化：`-60`- 内向者与外向者相邻：

 - 内向的人会失败`30`- 外向的增益`20`- 总变化：`-10`- 两个外向的人在一起：

 - 各有所获`20`- 总变化：`+40`目标是在考虑每个占用的单元格和每个相邻的交互后最大化网格的总体幸福感。 

约束条件非常重要：

 -`m, n <= 5`-`introvertsCount, extrovertsCount <= 6`一个网格最多可以包含`25`细胞，这通常使暴力破解变得不可能，因为每个细胞都有三种选择：

 - 空
 - 内向
 - 外向

 那会产生`3^(m*n)`的可能性。 对于一个`5 x 5`网格，这变成`3^25`，这是一个天文数字。 

然而，内向者和外向者的数量都很少，最多`6`每个。 This strongly suggests that a dynamic programming solution with compressed state representation is intended.

 一些边缘情况很重要：

 - A completely empty placement may be optimal when placing additional people decreases happiness.
 - 非常小的网格，例如`1 x 1`简化邻居处理。 
- 窄网格，例如`1 x n`或者`m x 1`仅具有水平或垂直邻居。 
- 仅内向者或仅外向者的情况表现非常不同。 
- 相邻效果必须精确计算一次，否则容易出现重复计算错误。 

## 方法

 ### 蛮力

 最直接的方法是尝试每种可能的网格配置。 

对于每个单元格，我们选择：

 1.留空
 2. 放置一个内向的人
 3.放置一个外向的人

 生成完整的网格配置后，我们通过评估所有相邻关系来计算总幸福度。 

这种方法保证找到最佳答案，因为它详尽地检查了每个有效的排列。 

不幸的是，它太慢了。 

对于一个`5 x 5`网格：```
3^25 ≈ 2.8 * 10^11
```即使在考虑修剪或幸福计算之前，也不可能在时间限制内探索这个搜索空间。 

### 最优方法，带有状态压缩的动态规划

 关键的见解是，当逐个单元处理网格时，当前单元的幸福贡献仅取决于：

 - 左边的邻居
 - 上层邻居

 未来的单元不会影响已处理的单元，除非通过局部邻接。 

这意味着我们不需要整个网格历史记录。 我们只需要足够的信息来重建前一行和当前行中的前一个单元格。 

我们代表最后的状态`n`使用 base-3 编码的单元格：

 -`0`= 空
 -`1`= 内向
 -`2`= 外向

 自从`n <= 5`，可能的行状态数为：```
3^5 = 243
```对于动态规划来说足够小。 

我们从左到右、从上到下处理网格。 在每个单元格，我们尝试：

 - 留空
 - 性格内向
 - 外向的地方

 对于每个选择，我们计算仅由左邻居和上邻居引起的增量幸福变化。 

记忆化确保每个状态被计算一次。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(3^(m*n)) | O(3^(m*n)) | O(m*n) | 枚举每个可能的网格 |
 | 最佳 | O(m * n * 3^n * 内向者计数 * 外向者计数 * 3) | O(3^n * 内向者计数 * 外向者计数) | 使用具有三态压缩的 DP |

 ## 算法演练

 ### 步骤 1：使用 Base-3 编码表示网格状态

 我们对最后一个进行编码`n`将单元格处理为三进制数。 

例如，如果`n = 3`：```
[empty, introvert, extrovert]
= [0,1,2]
= 0 * 3^2 + 1 * 3 + 2
= 5
```这种压缩表示使我们能够有效地存储行历史记录。 

### 第 2 步：按顺序处理单元

 我们按行优先顺序处理单元格：```
(0,0) -> (0,1) -> ... -> (m-1,n-1)
```在每一步中，我们都知道：

 - 当前细胞索引
 - 剩下的内向者
 - 剩下的外向者
 - 编码之前的状态

 这些值完全定义了子问题。 

### 步骤 3：提取邻居信息

 从编码状态：

 - 左邻居是最后一个 trit
 - 上邻居是第一个 trit

 这是有效的，因为状态总是存储以前的`n`处理过的细胞。 

### 第 4 步：尝试所有可能的放置位置

 对于每个单元格，我们考虑：

 1.留空
 2. 性格内向
 3. 放置外向型

 如果我们放置某人，我们会计算：

 - 基础幸福感
 - 与左邻居互动
 - 与上层邻居互动

 我们只计算与已处理的邻居的交互，因此每条边都只计算一次。 

### 步骤 5：更新状态

 要移动到下一个单元格：

 1.删除最旧的trit
 2. 基数 3 左移
 3. 追加当前单元格类型

 数学上：```
new_state = (old_state % (3^(n-1))) * 3 + current_type
```### 第 6 步：使用记忆化

 许多状态在递归期间重复。 

我们记住：```
(position, introverts_left, extroverts_left, state)
```这将指数蛮力转化为可管理的动态规划。 

### 为什么它有效

 该算法之所以有效，是因为一个细胞的幸福贡献仅取决于相邻细胞。 当从左到右、从上到下处理时，唯一已确定的邻居是左侧和上方的单元格。 因此，之前的`n`单元格包含优化计算未来决策所需的所有信息。 

DP 探索每一个有效的放置组合，同时避免通过记忆重新计算，保证最大可能的幸福。 

## Python 解决方案```python
from functools import lru_cache
from typing import List

class Solution:
    def getMaxGridHappiness(
        self,
        m: int,
        n: int,
        introvertsCount: int,
        extrovertsCount: int
    ) -> int:

        pow3 = [1] * (n + 1)
        for i in range(1, n + 1):
            pow3[i] = pow3[i - 1] * 3

        # Happiness interaction table
        # 0 = empty
        # 1 = introvert
        # 2 = extrovert
        interaction = [
            [0, 0, 0],
            [0, -60, -10],
            [0, -10, 40]
        ]

        @lru_cache(None)
        def dp(
            pos: int,
            introverts_left: int,
            extroverts_left: int,
            state: int
        ) -> int:

            if pos == m * n:
                return 0

            row = pos // n
            col = pos % n

            left = state % 3
            up = state // pow3[n - 1]

            next_state_base = (state % pow3[n - 1]) * 3

            best = dp(
                pos + 1,
                introverts_left,
                extroverts_left,
                next_state_base
            )

            # Place introvert
            if introverts_left > 0:
                gain = 120

                if col > 0:
                    gain += interaction[1][left]

                if row > 0:
                    gain += interaction[1][up]

                best = max(
                    best,
                    gain + dp(
                        pos + 1,
                        introverts_left - 1,
                        extroverts_left,
                        next_state_base + 1
                    )
                )

            # Place extrovert
            if extroverts_left > 0:
                gain = 40

                if col > 0:
                    gain += interaction[2][left]

                if row > 0:
                    gain += interaction[2][up]

                best = max(
                    best,
                    gain + dp(
                        pos + 1,
                        introverts_left,
                        extroverts_left - 1,
                        next_state_base + 2
                    )
                )

            return best

        return dp(0, introvertsCount, extrovertsCount, 0)
```实现从预计算能力开始`3`，用于三元状态操作。 由于行宽最多为`5`，这仍然很小。 

这`interaction`矩阵存储由相邻对引起的总幸福感变化。 例如：```python
interaction[1][1] = -60
```因为两个内向的人都输了`30`。 

递归`dp`函数表示从当前位置开始可实现的最大幸福感。 

编码状态存储先前的状态`n`细胞。 使用模和除运算，我们提取：

 - 左邻居
 - 上层邻居

 对于每个单元格，我们尝试所有有效的操作：

 - 跳过
 - 性格内向
 - 外向的地方

 当放置一个人时，我们立即计算当地的幸福感贡献。 

状态转换删除最旧的单元并附加当前选择，维护最后一个单元的滑动窗口`n`处理过的细胞。 

记忆化避免了相同子问题的重新计算。 

## 解决方案```go
package main

func getMaxGridHappiness(m int, n int, introvertsCount int, extrovertsCount int) int {
	pow3 := make([]int, n+1)
	pow3[0] = 1

	for i := 1; i <= n; i++ {
		pow3[i] = pow3[i-1] * 3
	}

	interaction := [][]int{
		{0, 0, 0},
		{0, -60, -10},
		{0, -10, 40},
	}

	type State struct {
		pos              int
		introvertsLeft   int
		extrovertsLeft   int
		mask             int
	}

	memo := make(map[State]int)

	var dp func(int, int, int, int) int

	dp = func(pos int, introvertsLeft int, extrovertsLeft int, mask int) int {
		if pos == m*n {
			return 0
		}

		key := State{
			pos,
			introvertsLeft,
			extrovertsLeft,
			mask,
		}

		if val, exists := memo[key]; exists {
			return val
		}

		row := pos / n
		col := pos % n

		left := mask % 3
		up := mask / pow3[n-1]

		nextMaskBase := (mask % pow3[n-1]) * 3

		best := dp(
			pos+1,
			introvertsLeft,
			extrovertsLeft,
			nextMaskBase,
		)

		if introvertsLeft > 0 {
			gain := 120

			if col > 0 {
				gain += interaction[1][left]
			}

			if row > 0 {
				gain += interaction[1][up]
			}

			candidate := gain + dp(
				pos+1,
				introvertsLeft-1,
				extrovertsLeft,
				nextMaskBase+1,
			)

			if candidate > best {
				best = candidate
			}
		}

		if extrovertsLeft > 0 {
			gain := 40

			if col > 0 {
				gain += interaction[2][left]
			}

			if row > 0 {
				gain += interaction[2][up]
			}

			candidate := gain + dp(
				pos+1,
				introvertsLeft,
				extrovertsLeft-1,
				nextMaskBase+2,
			)

			if candidate > best {
				best = candidate
			}
		}

		memo[key] = best
		return best
	}

	return dp(0, introvertsCount, extrovertsCount, 0)
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但使用自定义结构作为记忆键，因为 Go 不提供内置元组哈希。 

一个`map[State]int`存储缓存的 DP 结果。 由于所有状态字段都是整数，因此该结构是可散列且高效的。 

Go 整数就足够了，因为最大幸福值保持在 32 位范围内。

 ## 边缘情况

 当无人可用时会出现一种重要的边缘情况。 In this situation, the optimal answer is simply`0`。 A buggy implementation might still attempt transitions or compute neighbor interactions unnecessarily. This implementation handles the case naturally because the recursion can only choose the empty placement option.

 Another tricky case involves very small grids such as`1 x 1`。 在这些网格中，不存在邻居，因此不应应用交互惩罚或奖励。 执行正确检查`row > 0`和`col > 0`在评估上邻居或左邻居之前。 

单行和单列网格是错误的另一个常见来源。 在一个`1 x n`网格中，没有上层邻居。 在一个`m x 1`网格中，没有左邻居。 由于该算法显式地使用行和列条件来保护邻居检查，因此它可以正确处理这些退化维度。 

重复计算邻居效应会产生一个微妙的问题。 如果两个细胞稍后独立应用交互更新，则总幸福感将变得不正确。 此实现通过仅评估与已处理的邻居（特别是左侧和上部单元格）的交互来避免这种情况。 每个相邻的对都只计算一次。 

最后，在有许多内向者的情况下，可能会出现这样的情况：让牢房空着比安置更多的人更好。 由于 DP 始终包含跳过单元格的选项，因此算法自然会发现部分放置何时会产生更高的总幸福感。
