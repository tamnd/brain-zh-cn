[LeetCode Problem 1605](https://leetcode.com/problems/find-valid-matrix-given-row-and-column-sums/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们两个数组：

 -`rowSum`， 在哪里`rowSum[i]`表示行所需的总和`i`-`colSum`， 在哪里`colSum[j]`表示列所需的总和`j`我们的任务是构造任意非负整数矩阵，使得：

 1. 每行相加等于其对应的值`rowSum`2. 每列相加等于其对应的值`colSum`我们不需要找到唯一的矩阵。 任何有效的矩阵都是可接受的。 

认为`rowSum = [3, 8]`和`colSum = [4, 7]`。 这意味着：

 - 第一行总数必须为 3
 - 第二行总数必须为 8
 - 第一列总计必须为 4
 - 第二列总计必须为 7

 我们必须在矩阵中分配值，以便同时满足所有这些约束。 

约束条件很重要：

 - 最多 500 行和 500 列
 - 个人金额可以高达`10^8`- 行总和始终等于列总和

 最终的保证极其重要。 由于行所需的总量等于列所需的总量，因此总是存在至少一个有效的解决方案。 

简单的实现可能会在几种边缘情况下失败：

 - 带总和的行或列`0`- 需要仔细更新的大值
 - 分布不均匀，其中一行或一列提前耗尽
 - 矩阵尺寸较大，低效回溯会超时

 因为该问题只要求任何有效的矩阵，所以我们不需要对矩阵内容本身进行优化。 我们只需要正确的构造。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试为每个单元格分配值，同时递归检查行和列的总和是否仍然有效。 

在每个位置`(i, j)`，我们可以尝试每一个可能的值`0`直到剩余行总和和列总和的最小值。 然后我们递归地继续填充矩阵。 

这种方法是正确的，因为它探索了所有可能的有效分配。 最终，将找到一个有效的矩阵。 

然而，可能性的数量呈指数级增长。 即使对于中等大小的矩阵，搜索空间也会变得巨大。 由于两个维度都可以达到 500，因此强力回溯是完全不切实际的。 

### 最优贪心法

 关键的观察结果是对于任何细胞`(i, j)`，我们可以安全放置的最大值是：$$\min(rowSum[i], colSum[j])$$如果我们放置这个金额：

 - 我们尽可能满足当前行和列
 - 两个约束中至少一个得到完全满足
 - 我们从不违反非负面要求

 这自然暗示了一种贪婪的策略。 

对于每个单元格：

 1. 输入尽可能大的有效值
 2.从行和列的要求中减去它
 3.继续填充矩阵

 因为总和是平衡的，所以这个过程总是成功的。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(m × n) | 递归尝试所有可能的分配 |
 | 最优贪心 | O(m × n) | O(m × n) | 使用贪婪赋值填充每个单元格一次 |

 ## 算法演练

 ### 第 1 步：初始化结果矩阵

 创建一个`m x n`用零填充的矩阵，其中：

 -`m = len(rowSum)`-`n = len(colSum)`该矩阵将逐渐填充有效值。 

### 第 2 步：迭代每个单元格

 使用嵌套循环：

 - 行的外循环
 - 列的内循环

 在每个位置`(i, j)`，确定有多少价值可以安全地放置在那里。 

### 步骤 3：计算最大有效值

 对于细胞`(i, j)`:```
value = min(rowSum[i], colSum[j])
```我们选择最小值是因为：

 - 一行不能超过其剩余所需总和
 - A column cannot exceed its remaining required sum

 这保证了分配仍然有效。 

### 步骤 4：将值放入矩阵中

 将计算值存储到：```
matrix[i][j] = value
```这对行总计和列总计都有贡献。 

### 步骤 5：更新剩余金额

 赋值后：```
rowSum[i] -= value
colSum[j] -= value
```这跟踪了以后还需要分配多少金额。 

### 第 6 步：继续，直到处理完所有单元格

 由于每次分配都会将至少一项剩余总和减至零，因此算法会稳步向完成方向前进。 

最终：

 - 每行总和变为零
 - 每列总和变为零

 因此构造的矩阵是有效的。 

### 为什么它有效

 贪婪策略之所以有效，是因为每个单元格分配同时尊重两个剩余的约束。 通过始终放置最大可行值，我们保证未来的放置不会成为不可能。 

每一步：

 - 行总和保持非负数
 - 列总和保持非负数
 - 剩余行总和始终等于剩余列总和

 由于每次放置后都会满足至少一个约束，因此该过程最终会以有效矩阵终止。 

## Python 解决方案```python
from typing import List

class Solution:
    def restoreMatrix(self, rowSum: List[int], colSum: List[int]) -> List[List[int]]:
        rows = len(rowSum)
        cols = len(colSum)

        matrix = [[0] * cols for _ in range(rows)]

        for i in range(rows):
            for j in range(cols):
                value = min(rowSum[i], colSum[j])

                matrix[i][j] = value

                rowSum[i] -= value
                colSum[j] -= value

        return matrix
```实现首先从输入数组确定矩阵维度。 

创建一个用零初始化的结果矩阵。 这确保每个单元格在赋值之前已经包含有效的非负值。 

嵌套循环只访问每个矩阵单元一次。 对于每个单元格，该算法使用以下方法计算可以安全拟合的最大值：```python
min(rowSum[i], colSum[j])
```该值被插入到矩阵中，行和列的要求都会立即更新。 

由于剩余总和已就地更新，因此算法始终准确地知道未来电池剩余的容量。 

最后返回完整的矩阵。 

## 解决方案```go
func restoreMatrix(rowSum []int, colSum []int) [][]int {
    rows := len(rowSum)
    cols := len(colSum)

    matrix := make([][]int, rows)

    for i := 0; i < rows; i++ {
        matrix[i] = make([]int, cols)

        for j := 0; j < cols; j++ {
            value := rowSum[i]
            if colSum[j] < value {
                value = colSum[j]
            }

            matrix[i][j] = value

            rowSum[i] -= value
            colSum[j] -= value
        }
    }

    return matrix
}
```Go 实现遵循与 Python 版本完全相同的贪婪逻辑。 

一个小小的区别是 Go 没有提供内置的`min`函数用于整数，因此比较是通过手动实现的`if`陈述。 

该矩阵是使用切片的切片创建的。 由于 Go 切片会自动用零值初始化，因此每个单元格都从`0`。 

整数溢出不是问题，因为约束安全地符合 Go 的标准整数范围。

 ## 边缘情况

 ### 总和为零的行或列

 行或列可能需要总和为零。 如果实现假设每一行或每一列都接收正值，这很容易导致错误。 

例如：```
rowSum = [0, 5]
colSum = [2, 3]
```第一行必须仅包含零。 

贪心解决方案自然可以处理这个问题，因为：```
min(0, colSum[j]) = 0
```不会进行无效的正分配。 

### 单行或单列

 如果矩阵只有一行或一列，则整个分布必须线性拟合。 

例子：```
rowSum = [10]
colSum = [3, 4, 3]
```该算法仍然有效，因为每一步都会贪婪地填充尽可能多的值，同时尊重剩余的总和。 

无需特殊处理。 

### 非常大的值

 约束允许的值大到`10^8`。 

糟糕的实现可能会使用低效的重复操作或溢出较小的整数类型。 

该解决方案仅执行减法和最小比较，两者都是安全且高效的。 Python 整数根据需要自动扩展，Go 整数在标准约束下安全地支持这些值。
