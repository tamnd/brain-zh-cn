 # LeetCode 1695，最大擦除值

 ## 问题理解

 这个问题要求我们找到一个仅包含唯一元素的连续子数组，这意味着该子数组内没有值出现多次。 在所有此类有效子数组中，我们必须返回其元素的最大可能总和。 

输入是一个数组`nums`由正整数组成。 由于所有数字都是正数，因此添加更多唯一元素总是会增加总和。 在设计最佳解决方案时，这一观察变得很重要。 

子数组必须是连续的。 我们不能跳过元素或重新排列它们。 例如，在`[4,2,4,5,6]`，子数组`[2,4,5,6]`有效，因为它在原始数组中连续出现。 

输出是一个整数，表示从元素全部不同的一个子数组中可获得的最大总和。 

约束条件很重要：

 -`1 <= nums.length <= 10^5`-`1 <= nums[i] <= 10^4`数组大小为`10^5`立即告诉我们二次解可能会太慢。 我们需要一种接近线性时间的算法。 

由于所有值都是正整数，因此出现了几个有用的属性：

 - 扩展有效的唯一窗口会增加总和。 
- 一旦出现重复项，我们应该缩小窗口以恢复唯一性。 
- 我们永远不会从不必要的删除唯一正数中受益。 

一些重要的边缘情况包括：

 - 具有所有唯一值的数组，其中整个数组就是答案。 
- 每个元素都相同的数组，其中最佳答案只有一个元素。 
- 重复出现的距离很远，这测试了滑动窗口是否正确调整。 
- 非常小的数组，例如长度`1`。 

## 方法

 ### 蛮力方法

 强力解决方案会检查每个可能的子数组。 

对于每个起始索引`i`，我们向右扩展子数组，同时跟踪所有元素是否保持唯一。 我们可以使用哈希集来检测重复项。 只要当前子数组包含唯一值，我们就计算其总和并更新答案。 

这是有效的，因为每个可能的连续子数组都会被检查，因此最终会找到最大的有效总和。 

然而，有`O(n^2)`可能的子数组。 即使使用哈希集进行重复检测是有效的，检查的元素总数对于`n = 10^5`。 

因此，暴力破解的速度太慢。 

### 最优滑动窗口方法

 关键的观察是我们只关心具有唯一元素的子数组。 这自然意味着滑动窗口。 

我们维护一个窗口`[left, right]`总是包含独特的元素。 

当我们扩展右边界时：

 - 如果新元素尚未位于窗口内，我们只需将其包含进来即可。 
- 如果新元素创建了重复项，我们将重复向前移动左边界，直到删除重复项。 

由于所有值都是正数，因此保持窗口尽可能大总是有益的。 除非违反唯一性，否则我们永远不需要缩小窗口。 

哈希集允许恒定时间重复检查，而运行总和允许恒定时间窗口总和更新。 

每个元素最多进入和离开窗口一次，给出线性时间复杂度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 检查每个可能的子数组 |
 | 最佳 | O(n) | O(n) | 具有哈希集和运行总和的滑动窗口 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`，表示当前滑动窗口边界。 
2. 创建一个名为的哈希集`seen`存储当前窗口内的所有独特元素。 这允许恒定时间重复检测。 
3. 维护一个变量`current_sum`表示当前窗口内元素的总和。 
4.维护另一个变量`max_sum`存储迄今为止找到的最佳答案。 
5. 使用迭代遍历数组`right`。 
6. 对于每个新元素`nums[right]`，检查它是否已经存在于`seen`。 
7. 如果它已经存在，则该窗口不再有效，因为不允许重复。 反复：

 - 删除`nums[left]`从`seen`- 从中减去它`current_sum`- 移动`left`前进
 8. 继续缩小，直到重复元素被删除并且窗口再次变得唯一。 
9. 添加`nums[right]`到`seen`。 
10. 添加`nums[right]`到`current_sum`。 
11. 更新`max_sum`当前答案和之间的较大值`current_sum`。 
12. 继续，直到处理完所有元素。 

### 为什么它有效

 滑动窗口始终保持窗口内所有元素都是唯一的不变性。 每当出现重复项时，左指针就会前移足以恢复有效性。 

因为每个数字都是正数，所以较大的有效窗口总是比同一窗口的较小版本产生更大或相等的总和。 因此，在每一步中保持最大可能的唯一窗口可以保证我们最终发现可实现的最大总和。 

每个元素被插入到窗口一次并被移除一次，这保证了线性复杂度。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumUniqueSubarray(self, nums: List[int]) -> int:
        seen = set()
        
        left = 0
        current_sum = 0
        max_sum = 0
        
        for right in range(len(nums)):
            while nums[right] in seen:
                seen.remove(nums[left])
                current_sum -= nums[left]
                left += 1
            
            seen.add(nums[right])
            current_sum += nums[right]
            
            max_sum = max(max_sum, current_sum)
        
        return max_sum
```其实现直接遵循滑动窗口算法。 

这`seen`set 存储当前窗口内的所有元素。 在添加新值之前，我们检查它是否已存在于集合中。 如果是这样，窗口就会变得无效，因此我们不断地从左侧删除元素，直到重复项消失。 

变量`current_sum`增量跟踪当前窗口的总和。 这可以避免重复重新计算总和，从而增加复杂性。 

这`max_sum`每次有效扩展窗口后都会更新变量。 

由于每个元素最多添加和删除一次，因此该算法在线性时间内高效运行。 

## 解决方案```go
func maximumUniqueSubarray(nums []int) int {
    seen := make(map[int]bool)

    left := 0
    currentSum := 0
    maxSum := 0

    for right := 0; right < len(nums); right++ {
        for seen[nums[right]] {
            seen[nums[left]] = false
            currentSum -= nums[left]
            left++
        }

        seen[nums[right]] = true
        currentSum += nums[right]

        if currentSum > maxSum {
            maxSum = currentSum
        }
    }

    return maxSum
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用的不是 Python 集，而是`map[int]bool`跟踪滑动窗口中当前存在哪些元素。 

Go 没有内置的`max`函数用于整数，因此比较是手动编写的。 

在给定的约束下，整数溢出不是问题，因为最大可能的总和最多为`10^5 * 10^4 = 10^9`，它安全地适合 LeetCode 环境中 Go 的标准整数类型。

 ## 边缘情况

 一种重要的边缘情况是所有元素都已经是唯一的。 例如，`[1,2,3,4,5]`。 有缺陷的实现可能会不必要地缩小窗口或无法正确计算总和。 在这种情况下，滑动窗口只是扩展到整个数组，最终的答案成为所有元素的总和。 

当每个元素都相同时会出现另一个重要情况，例如`[7,7,7,7]`。 在这里，每个新元素都会立即创建一个副本。 该算法在添加新的事件之前会反复删除旧的事件。 因此，最大的有效子数组仅包含一个元素，并且实现正确返回`7`。 

一个更微妙的边缘情况是当重复项出现很远时，例如`[9,1,2,3,9]`。 天真的实现可能会在看到第二个窗口时错误地重置整个窗口`9`。 滑动窗口解决方案仅删除元素直到重复项消失，从而保留尽可能多的有效子数组。 这确保了最优子阵列`[1,2,3,9]`被发现。 

另一个潜在的错误来源是在缩小窗口的同时处理运行总和。 如果从集合中删除值但未从总和中减去值，则计算出的答案将变得不正确。 该实现同时更新两个结构，保证窗口内容与其记录的总和之间的一致性。
