[LeetCode 问题 1649](https://leetcode.com/problems/create-sorted-array-through-instructions/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、分而治之、二叉索引树、线段树、归并排序、有序集

 ## 解决方案

 ## 问题理解

 该问题要求我们模拟增量构建排序数组。 我们处理`instructions`数组从左到右，对于每个值，我们将其插入到一个名为的容器中`nums`同时保持排序顺序。 

然而，实际插入并不是困难的部分。 重要的部分是计算插入成本。 

对于每个值`instructions[i]`，插入成本定义为：

 - 中现有元素的数量`nums`严格小于`instructions[i]`- 中现有元素的数量`nums`严格大于`instructions[i]`我们取这两个值中的最小值并将其添加到总答案中。 

容器开始时是空的，因此第一次插入总是有成本`0`。 

最终答案是所有插入成本的总和，模`10^9 + 7`。 

约束条件非常重要：

 -`instructions.length <= 10^5`-`instructions[i] <= 10^5`二次解不起作用，因为`10^5 × 10^5 = 10^10`运营规模太大了。 我们需要一些接近的东西`O(n log n)`。 

关键的挑战是对于每次插入，我们需要有效地回答两个查询：

 1. 之前有多少个数字比当前值小？ 
2. 之前有多少个数字比当前值大？ 

这是一个经典的频率计数和前缀和问题。 

一些边缘情况很重要：

 - 重复值，因为该问题使用严格较小和严格较大的比较。 
- 已经排序的数组，其中每个插入成本变为`0`。 
- 反向排序数组，其中最小值的一侧始终是`0`。 
- 大量重复输入，高效计数很重要。 
- 非常大的答案，需要模运算。 

## 方法

 ### 蛮力方法

 最简单的解决方案是显式维护已排序的容器`nums`。 

对于每条指令：

 1.找到插入位置。 
2. 计算有多少个元素更小。 
3. 计算有多少个元素更大。 
4. 将值插入排序列表中。 

我们可以使用二分查找来找到插入点，但是插入到Python列表或数组中仍然需要移动元素，这会产生成本`O(n)`时间。 

由于我们对每个元素都执行此操作，因此总复杂度变为`O(n^2)`在最坏的情况下。 

这种方法是正确的，因为它直接模拟了问题陈述，但是对于`10^5`元素。 

### 最佳方法

 重要的观察是我们实际上不需要存储完全排序的数组。 

我们只需要频率信息：

 - 之前有多少个数字小于`x`- 之前有多少个数字大于`x`这自然会导致支持以下数据结构：

 - 点更新
 - 前缀和查询

 二元索引树（也称为 Fenwick 树）非常适合此目的。 

自从`instructions[i] <= 10^5`，我们可以直接使用这些值作为 Fenwick 树中的索引。 

对于每个值`x`：

 -`less = query(x - 1)`-`greater = inserted_so_far - query(x)`然后：

-`cost += min(less, greater)`最后，我们将该值插入到 Fenwick 树中。 

每次操作费用`O(log M)`在哪里`M = 10^5`。 

这给出了总复杂度`O(n log M)`。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 维护显式排序数组并插入每个元素 |
 | 最佳 | O(n log M) | O(n log M) | O(M)| 使用 Fenwick Tree 进行前缀频率计数 |

 这里，`M`是最大可能值`instructions`。 

## 算法演练

 ### 第 1 步：初始化 Fenwick 树

 我们创建一个足够大的芬威克树来存储所有可能值的频率。 

该树支持：

 - 更新值的频率
 - 查询插入的数字有多少个小于等于某个值

 ### 第 2 步：从左到右处理指令

 我们迭代每个值`x`在`instructions`。 

此时，芬威克树包含所有先前插入的值的频率。 

### 步骤 3：计算较小的元素

 计算严格小于的数字`x`，我们查询前缀总和`x - 1`。```
less = query(x - 1)
```这告诉我们有多少插入的数字小于`x`。 

### 步骤 4：计算更大的元素

 计算严格大于的数字`x`，我们首先计算有多少个数字小于或等于`x`。```
not_greater = query(x)
```如果我们已经插入了`i`元素，那么：```
greater = i - not_greater
```### 步骤 5：添加最低成本

 插入成本为：```
min(less, greater)
```我们将此值添加到运行总计中。 

### 步骤 6：插入当前值

 我们更新芬威克树频率`x`。```
update(x, +1)
```这可确保将来的查询包含当前号码。 

### 步骤7：返回结果

 由于答案可能会变大，我们返回：```
answer % (10^9 + 7)
```### 为什么它有效

 Fenwick 树始终存储所有先前插入值的精确频率分布。 

因为前缀和可以有效地计算有多少个数字小于或等于某个值，所以我们可以推导两者：

 - 数量更小
 - 严格更多的计数

 对于每个插入。 

由于每一步都会计算问题定义的精确插入成本，因此累积结果是正确的。 

## Python 解决方案```python
from typing import List

class FenwickTree:
    def __init__(self, size: int):
        self.size = size
        self.tree = [0] * (size + 1)

    def update(self, index: int, delta: int) -> None:
        while index <= self.size:
            self.tree[index] += delta
            index += index & -index

    def query(self, index: int) -> int:
        total = 0

        while index > 0:
            total += self.tree[index]
            index -= index & -index

        return total

class Solution:
    def createSortedArray(self, instructions: List[int]) -> int:
        MOD = 10**9 + 7

        max_value = max(instructions)
        fenwick = FenwickTree(max_value)

        total_cost = 0

        for i, value in enumerate(instructions):
            less = fenwick.query(value - 1)
            less_or_equal = fenwick.query(value)

            greater = i - less_or_equal

            total_cost += min(less, greater)
            total_cost %= MOD

            fenwick.update(value, 1)

        return total_cost
```实现从 Fenwick Tree 类开始。 这`update`方法增加了某个值的频率，而`query`方法返回前缀和`1`通过`index`。 

里面`createSortedArray`，我们首先确定最大值，这样我们就知道芬威克树必须有多大。 

当我们迭代说明时：

 -`less`计算严格小于当前值的数字。 
-`less_or_equal`计算小于或等于当前值的数字。 
-`greater`是根据已插入的值的数量得出的。 

将插入成本添加到运行答案中，然后将当前值插入到芬威克树中。 

每次加法后都会应用模运算以避免溢出。 

## 解决方案```go
package main

func createSortedArray(instructions []int) int {
	const MOD int = 1_000_000_007

	maxValue := 0
	for _, value := range instructions {
		if value > maxValue {
			maxValue = value
		}
	}

	fenwick := make([]int, maxValue+1)

	update := func(index int, delta int) {
		for index <= maxValue {
			fenwick[index] += delta
			index += index & -index
		}
	}

	query := func(index int) int {
		sum := 0

		for index > 0 {
			sum += fenwick[index]
			index -= index & -index
		}

		return sum
	}

	totalCost := 0

	for i, value := range instructions {
		less := query(value - 1)
		lessOrEqual := query(value)

		greater := i - lessOrEqual

		if less < greater {
			totalCost += less
		} else {
			totalCost += greater
		}

		totalCost %= MOD

		update(value, 1)
	}

	return totalCost
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

该树不是定义单独的 Fenwick Tree 类，而是表示为具有本地辅助函数的切片`update`和`query`。 

Go 使用显式整数运算，因此每次加法后都会仔细应用模运算。 由于中间操作期间约束适合 32 位整数，因此标准`int`就足够了。

 ## 边缘情况

 ### 所有元素都相等

 输入如下：```
[2,2,2,2]
```很容易处理不当，因为该问题需要严格较少的比较和严格较大的比较。 

相同的值不应影响任一计数。 

该实现正确地处理了这个问题，因为：

 -`less = query(value - 1)`-`greater = inserted - query(value)`两个计算中均排除相同的值。 

###严格加大投入

 对于这样的输入：```
[1,2,3,4,5]
```每个新值都有：

 - 许多较小的元素
 - 零个更大的元素

 由于插入成本使用最小，因此每次插入都会贡献`0`。 

该算法自然会处理这个问题，因为`greater`每一步都变为零。 

### 严格减少输入

 对于这样的输入：```
[5,4,3,2,1]
```每个插入都有：

 - 零较小的元素
 - 许多更大的元素

 再次强调，最小值始终是`0`。 

这种情况很重要，因为幼稚的实现有时会错误地在计数中包含相等或当前的元素。 

Fenwick 树仅存储先前插入的值，因此当前元素永远不会对其自身进行计数。 

### 具有最大值的大输入

 约束条件允许：```
instructions.length = 100000
instructions[i] = 100000
```基于插入的简单方法会变得太慢。 

即使在最大约束大小下，芬威克树也能保证高效的对数运算，从而使解决方案能够针对所有有效输入进行足够的扩展。
