 ## 解决方案

 ## 问题理解

 该问题需要根据乘车公司数据库中的乘车数据计算 3 个月的滚动平均值乘车距离和乘车持续时间。 我们得到了三张表：`Drivers`,`Rides`， 和`AcceptedRides`。`Drivers`提供司机信息和加入日期，`Rides`包含请求的行程和日期，以及`AcceptedRides`包含司机实际接受的行程，以及行程距离和持续时间。 

目标是计算从 2020 年 1 月至 3 月至 2020 年 10 月至 12 月期间**每 3 个月窗口**的平均乘车距离和持续时间。每个窗口由连续三个月组成，一个月的平均值是通过将该月和前两个月的乘车距离（或持续时间）相加除以 3 计算得出的。如果有月份没有乘车，则总和视为零。 平均值四舍五入至小数点后两位。 输出应按升序列出窗口的起始月份和相应的平均值。 

主要限制包括关注 **2020**、计算 **3 个月滚动平均值**的要求，以及通过将缺席月份视为零来正确处理缺失数据。 边缘情况包括没有接受乘车的月份、2020 年以外发生的乘车或前 3 个月窗口中有部分数据的月份。 

## 方法

 **暴力方法**将涉及迭代从一月到十二月的每个月，提取该月的乘车次数，然后将该月和前两个月的距离和持续时间相加。 这将涉及多个嵌套查询或循环，重复连接所有三个表，这对于大型数据集来说效率低下。 

**最佳方法**使用每月一次的乘车聚合，然后使用**自连接或窗口函数**对 3 个月窗口内的值进行求和。 通过预先计算每月总计，然后对滚动窗口求和，我们可以避免重复连接，并可以有效地处理缺失的月份`COALESCE`将缺失的数据视为零。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N*M) | O(M)| 每 3 个月的窗口期重复加入乘车和每月接受的乘车； 对于大型数据集效率低下 |
 | 最佳 | O(N) | O(M)| 首先汇总每月总计，然后使用窗口函数计算滚动总和； 有效处理缺失月份 |

 ## 算法演练

 1. **提取每月数据：** 加入`Rides`和`AcceptedRides`获得所有接受的游乐设施`requested_at`日期。 将每个日期转换为月份数字 (1-12) 和年份。 仅筛选 2020 年。 
2. **每月合计：** 求和`ride_distance`和`ride_duration`每月获取每月的总距离和持续时间。 如果一个月没有乘车，则总数为零。 
3. **创建月份系列：** 构建包含 1 到 12 个月的表或系列，确保即使不存在游乐设施，也能代表所有月份。 
4. **计算 3 个月滚动总和：** 对于每个月，计算该月和前两个月的总距离和持续时间之和。 使用`COALESCE`数月以来数据缺失。 
5. **除以 3：** 对于每个滚动总和，将总和除以 3 以计算平均值。 将结果四舍五入到小数点后两位。 
6. **对结果进行排序：** 对最终输出进行排序`month`按升序排列。 

**为什么有效：** 通过预先汇总每月总计并使用三个月内的滚动总和，我们可以正确捕获每个窗口的平均骑行距离和持续时间。 将缺失的月份视为零可确保即使没有发生乘车情况，平均值也是准确的。 

## Python 解决方案```python
# SQL-oriented solution using Python style (for LeetCode's database execution)
# Here we write it as a string to execute directly on LeetCode

sql = """
WITH monthly_totals AS (
    SELECT
        EXTRACT(MONTH FROM r.requested_at) AS month,
        SUM(a.ride_distance) AS total_distance,
        SUM(a.ride_duration) AS total_duration
    FROM Rides r
    JOIN AcceptedRides a ON r.ride_id = a.ride_id
    WHERE EXTRACT(YEAR FROM r.requested_at) = 2020
    GROUP BY EXTRACT(MONTH FROM r.requested_at)
),
months AS (
    SELECT 1 AS month UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL
    SELECT 4 UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL
    SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9 UNION ALL
    SELECT 10
),
combined AS (
    SELECT
        m.month,
        COALESCE(mt1.total_distance, 0) AS d1,
        COALESCE(mt2.total_distance, 0) AS d2,
        COALESCE(mt3.total_distance, 0) AS d3,
        COALESCE(mt1.total_duration, 0) AS du1,
        COALESCE(mt2.total_duration, 0) AS du2,
        COALESCE(mt3.total_duration, 0) AS du3
    FROM months m
    LEFT JOIN monthly_totals mt1 ON mt1.month = m.month
    LEFT JOIN monthly_totals mt2 ON mt2.month = m.month - 1
    LEFT JOIN monthly_totals mt3 ON mt3.month = m.month - 2
)
SELECT
    month,
    ROUND((d1 + d2 + d3)/3, 2) AS average_ride_distance,
    ROUND((du1 + du2 + du3)/3, 2) AS average_ride_duration
FROM combined
ORDER BY month;
"""
```面向Python的解决方案构建了三个CTE：`monthly_totals`每月总计乘车次数，`months`确保所有月份都存在，并且`combined`将当月和前两个月相结合以获得滚动金额。`COALESCE`处理丢失的数据。

## 工作示例

 对于 1 月（月 = 1），三个月的窗口是 2019 年 11 月至 12 月以及 2020 年 1 月。仅存在 2020 年 1 月的行程，给出总数`ride_distance=63`和`ride_duration=38`。 除以 3 给出`21.00`和`12.67`。 

对于 2 月（月 = 2），窗口是 2019 年 12 月至 2020 年 2 月。只有 2 月的骑行有所贡献，因此平均值保持不变`21.00`和`12.67`。 

继续这种方式，每个月都会汇总自身和前两个月的总计，确保滚动平均值与示例中的输出相匹配。
