[LeetCode 第 1690 题](https://leetcode.com/problems/stone-game-vii/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、动态规划、博弈论

 ## 解决方案

 ## 问题理解

 该问题描述了在一系列石头上进行的两人游戏。 每个石子都有一个正整数值，石子排列成一排。 爱丽丝首先移动，当前玩家每回合都会移走最左边的石头或最右边的石头。 

评分规则是让这个问题变得有趣的关键细节。 当玩家移走棋子时，他们不会获得所移走的棋子的价值。 相反，他们获得移除后所有剩余宝石的总和。 

例如，如果当前的石头是：```
[5, 3, 1, 4]
```然后玩家移除`5`，剩下的石头变成：```
[3, 1, 4]
```玩家获得：```
3 + 1 + 4 = 8
```Alice想要最大化最终的分数差异：```
Alice score - Bob score
```鲍勃希望尽量减少同样的差异。 由于两个玩家都处于最佳状态，因此这是一个经典的极小极大博弈论问题。 

输入是一个整数数组`stones`， 在哪里：

-`stones[i]`是的值`i-th`石头
-`2 <= n <= 1000`-`1 <= stones[i] <= 1000`输出是一个整数，表示 Alice 和 Bob 之间的最终最佳分数差。 

约束条件`n <= 1000`非常重要。 简单的递归游戏模拟会探索指数级的多种可能性，但速度太慢了。 由于数组大小适中，因此强烈建议采用动态编程解决方案。 

一个重要的观察是游戏状态完全由剩余的子数组决定：```
stones[left:right]
```不需要额外的信息，因为移动获得的分数仅取决于当前剩余的棋子。 

一些边缘情况很重要：

 - 只有两块石头的阵列
 - 所有值都相同的数组
 - 具有非常大值的数组
 - 贪婪移除不正确的情况

 天真的贪婪策略可能会失败，因为立即获得更大的分数可能会让对手稍后获得更大的优势。 

## 方法

 ### 蛮力方法

 蛮力解决方案递归地尝试每一个可能的动作。 

在每个游戏状态：

 - 移除左边的石头
 - 移除右边的石头
 - 递归计算对手的最佳反应
 - 选择给出最佳最终分差的动作

 递归自然地形成了极小极大博弈树。 

假设当前子数组是：```
stones[left:right]
```如果玩家移走左边的石头：```
gain = sum(left+1 ... right)
```然后对手在较小的子阵列上发挥最佳效果。 

同样，移除右边的石头会得到：```
gain = sum(left ... right-1)
```蛮力解决方案是正确的，因为它详尽地探索了每一种可能的游戏序列并假设双方都是最佳游戏。 

然而，相同的子问题会被重复重新计算。 由于每个状态又分支为两个状态，因此总复杂度呈指数级增长。 

为了`n = 1000`，这是完全不可行的。 

### 关键见解

 关键的观察是游戏有重叠的子问题。 

子数组的最优结果：```
stones[left:right]
```会被需要很多次。 

我们可以定义：```
dp[left][right]
```作为仅考虑子数组时当前玩家可以实现的与对手的最大分数差异：```
stones[left:right]
```这将问题转化为区间动态规划。 

另一个重要的优化是前缀和。 

由于每次移动都需要计算剩余棋子的总和，因此重复对子数组求和将过于昂贵。 前缀总和允许恒定时间范围总和查询。 

递归变为：

 - 移除左边的石头：```
remaining_sum_after_left_removal - opponent_advantage
```- 移除右边的石头：```
remaining_sum_after_right_removal - opponent_advantage
```我们选择最大值是因为当前玩家想要最大的分数差。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索每个可能的游戏序列 |
 | 最优动态规划| O(n^2) | O(n^2) | O(n^2) | O(n^2) | 使用带有前缀和的区间 DP |

 ## 算法演练

 ### 第 1 步：构建前缀和

 我们首先构造一个前缀和数组，这样我们就可以在常数时间内计算任何子数组的和。 

如果：```
prefix[i]
```存储第一个的总和`i`元素，那么：```
sum(left, right) = prefix[right + 1] - prefix[left]
```这很重要，因为每一步都需要计算剩余棋子的总和。 

### 步骤 2：定义 DP 状态

 定义：```
dp[left][right]
```作为当前玩家可以从子数组中获得的最大分数差：```
stones[left:right+1]
```该值已经假定两名玩家都处于最佳状态。 

### 第 3 步：处理基本情况

 如果：```
left == right
```只剩下一块石头了。 

移除它不会留下任何石头，因此玩家获得`0`点。 

所以：```
dp[left][right] = 0
```### 步骤 4：计算移除左侧石子的转换

 如果当前玩家移走最左边的石头：```
stones[left]
```那么剩下的子数组就变成：```
[left+1, right]
```玩家获得：```
sum(left+1, right)
```但之后，对手可以实现：```
dp[left+1][right]
```比当前玩家有优势。 

因此，净优势是：```
remove_left =
sum(left+1, right) - dp[left+1][right]
```### 步骤 5：计算移除右侧石头的过渡

 同样，如果玩家移走最右边的石头：```
stones[right]
```剩余的子数组变为：```
[left, right-1]
```获得的分数为：```
sum(left, right-1)
```对手然后实现：```
dp[left][right-1]
```所以：```
remove_right =
sum(left, right-1) - dp[left][right-1]
```### 第 6 步：选择更好的举措

 当前玩家希望获得最大可能的优势。 

所以：```
dp[left][right] =
max(remove_left, remove_right)
```### 步骤 7：通过增加长度来填充 DP 表

 必须先解决较小的区间，然后再解决较大的区间。 

我们迭代区间长度`2`到`n`。 

对于每个间隔：```
[left, right]
```我们使用之前求解的较小区间来计算 DP 值。 

### 步骤 8：返回最终答案

 完整游戏对应：```
dp[0][n-1]
```它代表 Alice 可以比 Bob 获得的最佳分数差。 

### 为什么它有效

 DP 递归之所以有效，是因为每一步都会将游戏分解为更小的相同子问题。 当前玩家选择一步棋后，对手在剩余的时间间隔内面临完全相同的优化问题。 

递归正确地模拟了双方的最佳发挥：

 - 当前玩家最大化分差
 - 减去对手未来的最优优势
 - 考虑每一个可能的举动

 由于所有区间都只求解一次并由较小的有效区间构建，因此最终结果是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def stoneGameVII(self, stones: List[int]) -> int:
        n = len(stones)

        # Build prefix sums
        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + stones[i]

        # dp[left][right] =
        # maximum score difference current player can achieve
        dp = [[0] * n for _ in range(n)]

        # length represents interval size
        for length in range(2, n + 1):
            for left in range(n - length + 1):
                right = left + length - 1

                # Sum after removing left stone
                remove_left_sum = (
                    prefix[right + 1] - prefix[left + 1]
                )

                # Sum after removing right stone
                remove_right_sum = (
                    prefix[right] - prefix[left]
                )

                remove_left = (
                    remove_left_sum - dp[left + 1][right]
                )

                remove_right = (
                    remove_right_sum - dp[left][right - 1]
                )

                dp[left][right] = max(
                    remove_left,
                    remove_right
                )

        return dp[0][n - 1]
```实现首先构建一个前缀和数组。 这允许恒定时间范围的求和查询，这是必要的，因为每次移动都取决于剩余棋子的总和。 

DP 表存储每个间隔的最佳分数差。 最初所有值都为零，因为大小为 1 的间隔产生零分。 

外循环从最小到最大迭代间隔长度。 这种排序很重要，因为较大的间隔取决于已解决的较小间隔。 

对于每个间隔：```python
[left, right]
```该算法评估两种可能的移动：

 - 移除左边的石头
 - 移除右边的石头

 每次移动都会获得剩余的子数组总和，然后从所得间隔中减去对手的最佳响应。 

两个选择中的最大值成为该区间的最佳答案。 

最后，返回整个数组的答案。 

## 解决方案```go
func stoneGameVII(stones []int) int {
	n := len(stones)

	// Build prefix sums
	prefix := make([]int, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + stones[i]
	}

	// dp[left][right]
	dp := make([][]int, n)

	for i := 0; i < n; i++ {
		dp[i] = make([]int, n)
	}

	// Iterate by interval length
	for length := 2; length <= n; length++ {
		for left := 0; left <= n-length; left++ {
			right := left + length - 1

			removeLeftSum := prefix[right+1] - prefix[left+1]
			removeRightSum := prefix[right] - prefix[left]

			removeLeft := removeLeftSum - dp[left+1][right]
			removeRight := removeRightSum - dp[left][right-1]

			if removeLeft > removeRight {
				dp[left][right] = removeLeft
			} else {
				dp[left][right] = removeRight
			}
		}
	}

	return dp[0][n-1]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go不提供内置的动态多维数组，因此DP表是使用嵌套切片手动创建的。 

整数溢出不是问题，因为最大总石数为：```go
1000 * 1000 = 1,000,000
```很容易适合 Go 的内部`int`类型。 

与 Python 不同，Go 没有内置的`max`函数用于整数，因此比较是用标准实现的`if`陈述。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n^2) | O(n^2) | 有 O(n^2) 个间隔，每个间隔都在 O(1) 时间内处理 |

n * n
```每个条目仅执行恒定时间工作，因为前缀和允许即时范围和计算。 

因此，总运行时间是二次的。

 ## 边缘情况

 ### 最小长度数组

 最小的有效输入仅包含两个棋子。 

例如：```
[1, 2]
```第一个玩家移走一颗石子并获得剩余石子的价值。 然后第二个玩家获得零，因为之后没有剩下任何棋子。 

这种情况很重要，因为许多间隔 DP 实现意外地错误地处理了非常小的间隔。 该实现自然地处理它，因为长度间隔`2`直接根据长度的基本情况计算`1`。 

### 所有宝石都具有相同的价值

 考虑：```
[4,4,4,4]
```由于两种删除选择通常看起来是相同的，因此很容易错误地认为贪婪行为有效。 

然而，未来的区间结构仍然很重要。 DP 公式能够正确地递归评估两种可能性，即使在值相同的情况下也能确保最佳发挥。 

### 贪婪的选择可能会失败

 考虑：```
[1,100,1]
```最大化即时收益的贪婪策略可能不会最大化最终的分数差异。 

该算法通过考虑对手的最佳响应来避免这种错误：```
current_gain - opponent_best_result
```这是保证正确性的基本极小极大原则。 

### 大输入量

 最大输入大小为：```
n = 1000
```指数递归解决方案不可能在时间限制内运行。 

区间 DP 解决方案对每个状态计算一次，从而产生可管理的二次复杂度。
