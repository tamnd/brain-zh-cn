[LeetCode 问题 1667](https://leetcode.com/problems/fix-names-in-a-table/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个数据库表，名为`Users`有两列：`user_id`和`name`。 这`user_id`列唯一标识每个用户，而`name`列使用大写和小写英文字母的混合形式存储人名。 

任务是规范每个名称，使其遵循标准的大写规则：

 - 第一个字符必须是大写
 - 每个剩余字符都必须是小写

 例如：

 -`"aLice"`变成`"Alice"`-`"bOB"`变成`"Bob"`-`"JOHN"`变成`"John"`查询必须返回两列：

 -`user_id`- 修正后的`name`输出还必须按升序排序`user_id`。 

输入保证名称仅包含字母字符。 这简化了问题，因为我们不需要处理空格、标点符号、数字或特殊符号。 

由于这是一个数据库问题，因此主要的挑战是了解哪些 SQL 字符串函数可以正确转换名称。 幼稚的实现可能只将第一个字符大写，而忘记将其余字符小写，这会产生不正确的结果，例如`"ALICE"`成为`"ALICE"`而不是`"Alice"`。 

另一种可能的错误是错误地处理非常短的名称，尤其是只有一个字符的名称。 在这种情况下，该解决方案仍必须正常工作。 

## 方法

 ### 蛮力方法

 暴力式解决方案将手动处理每个名称的每个字符。 该查询可以：

 1. 提取第一个字符
 2.将其转换为大写
 3. 迭代每个剩余的字符
 4. 将剩余的每个字符转换为小写
 5. 将所有字符重新连接在一起

 这种方法在逻辑上是正确的，因为它以所需的格式逐个字符地显式重建字符串。 

然而，这个解决方案对于 SQL 来说过于复杂。 数据库系统已经提供了优化的内置字符串函数，可以有效地执行子字符串提取和大小写转换。 逐字符编写逻辑会使查询更难以阅读、维护和优化。 

### 最佳方法

 关键的观察是我们只需要两个转换：

 - 将第一个字符转换为大写
 - 将字符串的其余部分转换为小写

 SQL 正好提供了所需的函数：

 -`UPPER()`将文本转换为大写
 -`LOWER()`将文本转换为小写
 -`SUBSTRING()`提取字符串的一部分
 -`CONCAT()`将字符串连接在一起

 使用这些函数，我们可以直接构造正确的名称：

 1. 提取第一个字符并将其大写
 2. 提取剩余子串并将其小写
 3. 将两个部分连接在一起

 这产生了一个清洁且高效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 手动处理每个字符 |
 | 最佳 | O(n) | O(n) | 高效使用内置 SQL 字符串函数 |

 这里，`n`表示所有名称中处理的字符总数。 

## 算法演练

 1. 读取每一行`Users`桌子。 

每行包含一个`user_id`和一个`name`可能存在大小写不一致的值。 
2. 提取名称的第一个字符。 

我们使用`SUBSTRING(name, 1, 1)`获得第一个字母。 这是必须变为大写的字符。 
3. 将第一个字符转换为大写。 

正在申请`UPPER()`确保第一个字符遵循所需的格式规则。 
4. 提取名称的剩余部分。 

我们使用`SUBSTRING(name, 2)`获取从索引 2 开始的所有字符。 
5. 将剩余的子字符串转换为小写。 

正在申请`LOWER()`确保所有尾随字符均为小写，即使原始字符串包含大写字母也是如此。 
6. 连接两个转换后的部分。`CONCAT()`将大写的第一个字符与小写的其余字符连接起来。 
7. 返回排序后的格式化结果`user_id`。 

该问题明确要求对输出表进行排序`user_id`。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的输出名称必须恰好满足两个条件：

 - 第一个字符是大写的
 - 每个后续字符都是小写

 该解决方案直接根据这些规则构造输出字符串。 由于每个字符要么属于第一个位置，要么属于其余位置，因此每个字母都会正确转换。 

## Python 解决方案

 虽然这是 LeetCode 上的 SQL 问题，但下面显示了等效的 Python 逻辑，以清楚地说明转换过程。```python
class Solution:
    def fixName(self, name: str) -> str:
        if not name:
            return ""

        return name[0].upper() + name[1:].lower()
```### 实现说明

 该实现首先检查字符串是否为空。 虽然 SQL 问题保证了有效的名称，但防御性编程使函数更加健壮。 

表达式`name[0].upper()`将第一个字符转换为大写。 

表达式`name[1:].lower()`提取所有剩余字符并将其转换为小写。 

最后，将这两部分连接在一起形成正确的名称。 

对于实际的 LeetCode 数据库提交，SQL 查询是必需的答案：```sql
SELECT
    user_id,
    CONCAT(
        UPPER(SUBSTRING(name, 1, 1)),
        LOWER(SUBSTRING(name, 2))
    ) AS name
FROM Users
ORDER BY user_id;
```## 解决方案

 为了完整起见，等效的 Go 实现如下所示。```go
package main

import (
	"strings"
)

func fixName(name string) string {
	if len(name) == 0 {
		return ""
	}

	first := strings.ToUpper(name[:1])
	rest := strings.ToLower(name[1:])

	return first + rest
}
```### Go 具体注释

 Go 字符串是不可变的，类似于 Python 字符串，因此该解决方案构造一个新字符串而不是修改原始字符串。 

这`strings.ToUpper()`和`strings.ToLower()`函数可以干净地处理大小写转换。 

切片语法与 Python 略有不同，但逻辑保持不变。

 ## 边缘情况

 ### 单字符名称

 仅包含一个字符的名称很容易导致子字符串错误。 例如，在某些实现中，访问索引 1 之后的字符可能会失败。 

此解决方案可以正确处理这种情况，因为第一个字符之后的子字符串只是变成空字符串。 将大写第一个字符与空字符串连接仍然会产生正确的结果。 

### 全大写名称

 输入如`"ALICE"`很重要，因为简单的解决方案可能只会将第一个字符大写，而其余字母保持不变。 

该实现显式地小写剩余的子字符串，确保`"ALICE"`变成`"Alice"`。 

### 完全小写的名称

 输入如`"alice"`验证算法是否正确地将第一个字母大写，同时保留字符串其余部分的小写格式。 

该解决方案独立地转换第一个字符并将后缀小写，产生`"Alice"`正确。 

### 空字符串

 尽管数据库约束保证有效名称，但防御性实现仍应考虑空字符串。 

Python 和 Go 示例显式检查空输入并安全返回空字符串，而不会导致索引访问错误。
