[LeetCode 问题 1687](https://leetcode.com/problems/delivering-boxes-from-storage-to-ports/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、线段树、队列、堆（优先级队列）、前缀和、单调队列

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大限度地减少将箱子从仓库运送到港口所需的船舶总行程次数，同时遵守两个限制：

 1.船舶最多可承载`maxBoxes`立即盒子。 
2. 装载的箱子总重量不能超过`maxWeight`。 

盒子必须按照它们在输入数组中出现的确切顺序进行传送。 这种订购限制非常重要，因为它阻止我们按端口自由地重新组合盒子。 

每个框表示为：```
boxes[i] = [port_i, weight_i]
```在哪里：

-`port_i`是目的港
 -`weight_i`是箱子的重量

 船舶从储存处开始。 对于装载的每批箱子：

 - 它按照盒子要求的顺序访问端口。 
- 从一个港口移动到另一个港口算作一次行程。 
- 从最终港口返回仓库也算一次行程。 

如果连续的箱子前往同一个港口，则船舶不需要在它们之间进行额外的行程，因为它已经到达该港口。 

目标是计算交付所有箱子并最终返回存储所需的最少总行程次数。 

限制条件非常大：```
1 <= boxes.length <= 100000
```这立即告诉我们二次解太慢了。 任何接近的算法`O(n^2)`会超时。 我们需要一种方法`O(n)`或者`O(n log n)`。 

有几个方面使这个问题变得棘手：

 - 箱子必须保持整齐。 
- 一批货物可能包含多个港口。 
- 连续的同等港口减少旅行成本。 
- 重量和箱数限制都会影响有效的装运边界。 
- 局部最优装运并不总是全局最优。 

一个重要的观察结果是，一批货物的成本取决于该批货物内的港口中转数量。 

例如：```
[1,1], [1,2], [2,1], [2,3], [3,1]
```船舶路径变为：```
storage -> 1 -> 2 -> 3 -> storage
```行程次数为：```
(number of port changes) + 2
```这`+2`来自：

 - 离开存储空间
 - 返回存储

 容易导致错误的边缘情况包括：

 - 所有箱子都去同一个港口
 - 每个箱子前往不同的港口
 - 重量限制迫使小批量运输
 -`maxBoxes = 1`- 装运边界恰好发生在重量限制处
 - 货件边缘的连续相等端口

 该问题保证每个单独的盒子重量最多为`maxWeight`，因此每个盒子最终都可以发货。 

## 方法

 ### 蛮力方法

 强力动态规划解决方案将尝试每个可能的先前分割点。 

定义：```
dp[i] = minimum trips needed to deliver first i boxes
```对于每个`i`，我们尝试所有有效的`j < i`这样盒子`[j, i-1]`可以装入一批货物中。 

过渡变为：```
dp[i] = min(dp[j] + cost(j, i-1))
```在哪里：

-`cost(j, i-1)`是货物内的港口中转次数加上回程次数。 

为了计算这个，我们必须：

 1、检查该段是否满足：

 - 箱数限制
 - 重量限制
 2. 统计网段内的端口变化。 

该解决方案是正确的，因为它探索了发货的每个可能的有效分区。 

然而，它太慢了。 

有`O(n^2)`可能的间隔，即使有前缀和，DP 仍然是二次的。 

和`n = 100000`，这是不可行的。 

### 最佳解决方案背后的关键见解

 关键的观察是发货有效性形成了一个滑动窗口。 

对于每个结束位置`i`，存在左边界`j`这样：```
[j, i]
```是最大的有效发货。 

作为`i`增加，`j`只会前进。 

这种单调行为允许我们使用：

 - 前缀和
 - 滑动窗
 - 单调队列优化

 我们将 DP 转换转变为动态维护最佳候选的形式。 

优化后的递归变为：```
dp[i] = min(dp[j] + transitionCost)
```其中转换成本可以使用前缀信息重写。 

这允许每个索引进入和离开双端队列一次，产生一个`O(n)`解决方案。

 ## 算法演练

 ### 前缀定义

 我们首先预处理几个数组。 

让：```
weights[i] = weight of box i
ports[i] = destination port of box i
```我们建造：```
prefixWeight[i]
```它存储第一个的总重量`i`盒子。 

我们还建造：```
portChanges[i]
```在哪里：```
portChanges[i]
```等于第一个之间的端口转换数`i`盒子。 

例如：```
ports = [1,1,2,2,3]
```然后：```
portChanges = [0,0,1,1,2]
```### DP 状态

 定义：```
dp[i]
```作为首先交付所需的最少行程`i`盒子。 

答案是：```
dp[n]
```### 运输成本公式

 假设我们从索引中交付盒子`j`到`i-1`。 

行程费用等于：```
(number of port changes inside segment) + 2
```这`+2`来自：

 - 离开存储空间
 - 返回存储

 使用前缀数组：```
cost(j, i-1)
=
(portChanges[i-1] - portChanges[j]) + 2
```所以：```
dp[i]
=
min(
    dp[j]
    + portChanges[i-1]
    - portChanges[j]
    + 2
)
```重新排列：```
dp[i]
=
portChanges[i-1] + 2
+
min(dp[j] - portChanges[j])
```现在优化目标变为：```
dp[j] - portChanges[j]
```### 滑动窗口约束

 对于每一个`i`，我们必须保证发货`[j, i-1]`满足：

 1、箱数：```
i - j <= maxBoxes
```1. 总重量：```
prefixWeight[i] - prefixWeight[j] <= maxWeight
```作为`i`增加，无效`j`值从前面删除。 

### 单调队列

 我们维护候选索引的双端队列`j`。 

双端队列通过增加以下值来排序：```
dp[j] - portChanges[j]
```对于每个`i`:

 1. 删除前面无效的索引。 
2. 双端队列的前端给出最优`j`。 
3. 计算`dp[i]`。 
4. 插入`i`进入双端队列，同时保持单调顺序。 

每个索引插入和删除一次，给出线性复杂度。 

## 为什么它有效

 DP 保证最优性，因为每个有效的发货都以位置结束`i`被考虑。 

滑动窗口确保仅保留可行的发货。 

单调队列之所以有效，是因为 DP 转换仅取决于以下各项中的最小值：```
dp[j] - portChanges[j]
```在有效候选人中。 由于无效候选者永久离开，而新候选者进入一次，因此维持双端队列中的最小值可以有效地产生正确的最佳转换。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def boxDelivering(
        self,
        boxes: List[List[int]],
        portsCount: int,
        maxBoxes: int,
        maxWeight: int
    ) -> int:

        n = len(boxes)

        ports = [0] * n
        weights = [0] * n

        for i in range(n):
            ports[i] = boxes[i][0]
            weights[i] = boxes[i][1]

        prefix_weight = [0] * (n + 1)

        for i in range(n):
            prefix_weight[i + 1] = prefix_weight[i] + weights[i]

        port_changes = [0] * n

        for i in range(1, n):
            port_changes[i] = port_changes[i - 1]
            if ports[i] != ports[i - 1]:
                port_changes[i] += 1

        dp = [0] * (n + 1)

        dq = deque([0])

        for i in range(1, n + 1):

            while dq and (
                i - dq[0] > maxBoxes or
                prefix_weight[i] - prefix_weight[dq[0]] > maxWeight
            ):
                dq.popleft()

            j = dq[0]

            dp[i] = (
                dp[j]
                + port_changes[i - 1]
                - (port_changes[j] if j < n else 0)
                + 2
            )

            if i < n:
                current_value = dp[i] - port_changes[i]

                while dq:
                    back = dq[-1]
                    back_value = dp[back] - (
                        port_changes[back] if back < n else 0
                    )

                    if back_value <= current_value:
                        break

                    dq.pop()

                dq.append(i)

        return dp[n]
```实现首先将端口和权重分离到单独的数组中，以实现更清晰的索引。 

接下来，为重量构建前缀和，以便我们可以在恒定时间内检查装运重量限制。 

这`port_changes`array 跟踪遍历盒子时目标端口发生变化的次数。 这使我们能够计算恒定时间内的运输成本。 

DP数组存储第一次所需的最小行程`i`盒子。 

双端队列维护候选装运起始点。 在处理每个之前`i`，如果无效候选人违反以下任一规定，则将被删除：

 - 最大盒子数量
 - 最大重量

 双端队列的前面始终包含最佳有效转换，因为双端队列按以下升序维护：```python
dp[j] - port_changes[j]
```计算后`dp[i]`，插入当前索引，同时保持单调性。 

由于每个索引进入和离开双端队列一次，因此该算法以线性时间运行。 

## 解决方案```go
package main

func boxDelivering(boxes [][]int, portsCount int, maxBoxes int, maxWeight int) int {
	n := len(boxes)

	ports := make([]int, n)
	weights := make([]int, n)

	for i := 0; i < n; i++ {
		ports[i] = boxes[i][0]
		weights[i] = boxes[i][1]
	}

	prefixWeight := make([]int, n+1)

	for i := 0; i < n; i++ {
		prefixWeight[i+1] = prefixWeight[i] + weights[i]
	}

	portChanges := make([]int, n)

	for i := 1; i < n; i++ {
		portChanges[i] = portChanges[i-1]

		if ports[i] != ports[i-1] {
			portChanges[i]++
		}
	}

	dp := make([]int, n+1)

	deque := make([]int, 0)
	deque = append(deque, 0)

	for i := 1; i <= n; i++ {

		for len(deque) > 0 &&
			(i-deque[0] > maxBoxes ||
				prefixWeight[i]-prefixWeight[deque[0]] > maxWeight) {

			deque = deque[1:]
		}

		j := deque[0]

		changeJ := 0
		if j < n {
			changeJ = portChanges[j]
		}

		dp[i] = dp[j] + portChanges[i-1] - changeJ + 2

		if i < n {

			currentValue := dp[i] - portChanges[i]

			for len(deque) > 0 {

				back := deque[len(deque)-1]

				backValue := dp[back]

				if back < n {
					backValue -= portChanges[back]
				}

				if backValue <= currentValue {
					break
				}

				deque = deque[:len(deque)-1]
			}

			deque = append(deque, i)
		}
	}

	return dp[n]
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片来实现双端队列。 

Go 没有提供内置的双端队列结构，因此我们使用切片操作来模拟一个双端队列结构：

 -`deque[1:]`删除前面
 -`deque[:len(deque)-1]`移除背面

 所有值都安全地适合 Go 内部`int`因为最大行程次数受到一小部分的限制`n`。

 ## 边缘情况

 ### 所有盒子都去同一个端口

 如果每个箱子都有相同的目的港，最佳策略通常是在一次装运中装载尽可能多的箱子。 有缺陷的实现可能会错误地计算多个端口访问。 

例如：```
[[1,1],[1,1],[1,1]]
```应该只需要：```
storage -> 1 -> storage
```相当于 2 次行程。 

该实现正确处理了这个问题，因为`port_changes`对于连续的相同端口不会增加。 

### 重量限制迫使小批量运输

 一个常见的错误是假设盒子数量限制是唯一的约束。 

例如：```
maxBoxes = 10
maxWeight = 5
```和：```
[[1,5],[2,5],[3,5]]
```尽管箱子数量有限，但每批货物只能携带一个箱子。 

滑动窗口显式检查两者：```
i - j <= maxBoxes
```和```
prefixWeight[i] - prefixWeight[j] <= maxWeight
```因此超重的窗户会立即被拆除。 

### 港口周边装运边界变化

 计算端口转换时经常出现差一错误。 

考虑：```
[1,1,2,2,3]
```转换次数为：```
1 -> 2
2 -> 3
```等于 2，而不是 4。 

该实现通过将累积转换计数存储在中来避免重复计算`port_changes`并使用前缀减法来正确计算任何装运间隔内的转换。
