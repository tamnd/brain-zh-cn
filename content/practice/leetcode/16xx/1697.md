 # LeetCode 1697 - 检查边长有限路径的存在性

 ## 问题理解

 这个问题给了我们一个无向加权图`n`节点。 每条边连接两个节点并具有与其关联的距离值。 我们还得到多个查询，其中每个查询询问两个节点之间是否存在一条路径，使得该路径中使用的每条边的权重严格小于给定的限制。 

对于查询`[p, q, limit]`，我们并不是试图最小化总距离。 相反，我们只关心是否可以从`p`到`q`使用每个单独边权重小于的边`limit`。 

这种区别极其重要。 一条路径可能包含许多边，距离的总和并不重要。 唯一的要求是每条边独立满足：```
edge_weight < limit
```该图可能包含同一对节点之间的多条边，并且这些边可能具有不同的权重。 我们必须独立对待每条边。 

限制条件非常大：

 - 最多`10^5`节点
 - 最多`10^5`边缘
 - 最多`10^5`queries

 这些限制立即告诉我们，独立地为每个查询运行图形遍历可能会太慢。 任何比粗略更糟糕的算法`O((E + Q) log N)`会挣扎。 

一个重要的观察是查询条件是单调的。 如果一条边有权重`w`允许有一定的限制`L`，那么对于每个更大的限制也是允许的。 此属性强烈建议使用排序的离线处理策略。 

一些重要的边缘情况包括：

 - 没有边满足限制的查询
 - 相同节点之间的多条边
 - 断开的组件
 - 限制小于所有边权重
 - 限制大于所有边权重
 - 随着更多边可用，连通性逐渐变化的图表

 该问题保证：

 - 节点索引有效
 - 查询中的节点是不同的
 - 边权重和限制为正
 - 图形可能包含循环和重复边

 ## 方法

 ### 蛮力方法

 一个简单的解决方案是独立处理每个查询。 

对于每个查询`[p, q, limit]`，我们可以构造一个仅包含权重严格小于的边的子图`limit`。 然后我们运行 DFS 或 BFS`p`以确定是否`q`是可达的。 

这种方法是正确的，因为它直接对问题定义进行建模。 如果过滤图中存在路径，则该路径上的每条边都满足约束。 

然而，对于大输入，性能极差。 

对于每个查询：

 - 我们可以扫描所有边缘以过滤有效边缘
 - 我们可以使用 BFS 或 DFS 遍历大部分图

 高达`10^5`查询和`10^5`边缘，这变得太昂贵了。 

### 最优方法，Union-Find 离线查询

 关键的见解是查询的不同之处仅在于允许的边缘限制。 

假设我们按权重对所有边进行排序。 然后我们还按查询的限制对查询进行排序。 随着查询限制的增加，更多的边变得可用。 

我们不是为每个查询重建图，而是按限制的升序处理查询，并增量添加权重小于当前限制的边。 

为了有效地维护连接性，我们使用并查数据结构，也称为不相交集并集，DSU。 

Union-Find 高效支持两种操作：

 - 合并两个连接的组件
 - 检查两个节点是否属于同一个组件

 按排序顺序处理查询时：

 - 添加所有边的权重`< limit`- 联合他们的端点
 - 检查查询节点是否属于同一集合

 这是有效的，因为一旦一条边对较小的限制有效，它对所有较大的限制仍然有效。

 ## 算法演练

 1. 为所有人初始化一个并查结构`n`节点。 

最初，每个节点都属于其自己的连接组件，因为尚未添加边。 
2. 排序`edgeList`按边权重升序排列。 

这允许我们随着查询限制的增加逐步添加边缘。 
3. 将原始索引附加到每个查询。 

由于排序会改变查询顺序，因此我们必须记住每个查询的原始位置，以便我们可以正确放置答案。 

每个查询变为：```
[p, q, limit, original_index]
```4. 对所有查询进行排序`limit`按升序排列。 

这确保我们处理从允许的最小边权重到最大边权重的查询。 
5. 维护一个指向已排序边缘列表的指针。 

指针表示已添加到并查结构中的边数。 
6. 按排序顺序一一处理查询。 

对于当前的查询限制：

 - 添加权重严格小于限制的每一条边
 - 合并边缘端点
 - 推进边缘指针

 由于边已排序，因此每条边都只处理一次。 
7. 添加当前查询的所有有效边后，检查连通性。 

如果两个查询节点在并查中具有相同的根，则存在有效路径。 
8. 使用查询的原始索引将结果存储在答案数组中。 

这将恢复问题所需的原始查询顺序。 
9. 返回最终答案数组。 

### 为什么它有效

 在处理过程中的任何时刻，并查结构都恰好包含权重小于当前查询限制的边。 

并查仅使用那些允许的边将图划分为连接的组件。 因此，当且仅当在查询约束下两个节点之间存在有效路径时，两个节点属于同一组件。 

由于查询是按照限制的递增顺序处理的，因此永远不需要删除边。 每条边都添加一次，这提高了算法的效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def distanceLimitedPathsExist(
        self,
        n: int,
        edgeList: List[List[int]],
        queries: List[List[int]]
    ) -> List[bool]:

        parent = list(range(n))
        rank = [0] * n

        def find(node: int) -> int:
            if parent[node] != node:
                parent[node] = find(parent[node])
            return parent[node]

        def union(a: int, b: int) -> None:
            root_a = find(a)
            root_b = find(b)

            if root_a == root_b:
                return

            if rank[root_a] < rank[root_b]:
                parent[root_a] = root_b
            elif rank[root_a] > rank[root_b]:
                parent[root_b] = root_a
            else:
                parent[root_b] = root_a
                rank[root_a] += 1

        edgeList.sort(key=lambda edge: edge[2])

        indexed_queries = [
            [p, q, limit, index]
            for index, (p, q, limit) in enumerate(queries)
        ]

        indexed_queries.sort(key=lambda query: query[2])

        answers = [False] * len(queries)

        edge_index = 0

        for p, q, limit, original_index in indexed_queries:

            while (
                edge_index < len(edgeList)
                and edgeList[edge_index][2] < limit
            ):
                u, v, _ = edgeList[edge_index]
                union(u, v)
                edge_index += 1

            answers[original_index] = (find(p) == find(q))

        return answers
```实现首先使用两个数组创建并查数据结构：

 -`parent`，它存储每个节点的代表父节点
 -`rank`，这有助于在联合期间保持树浅

 的`find`函数使用路径压缩。 每当我们搜索节点的根时，我们都会直接将中间节点连接到根。 这极大地提高了性能。 

这`union`函数使用按等级并集。 较小的树附着在较大的树下，以保持结构平衡。 

接下来，边列表按权重排序，以便可以按升序递增添加边。 

由于排序改变了查询的顺序，因此查询会使用其原始索引进行增强。 

主循环从最小限制到最大限制处理查询。 在回答查询之前，我们添加权重严格小于查询限制的每条边。 

一旦所有符合条件的边都合并到并查结构中，连接性就变得很容易测试。 如果两个查询节点共享相同的根，则存在有效路径。 

最后，使用原始查询索引存储答案并以正确的顺序返回。 

## 解决方案```go
package main

import "sort"

func distanceLimitedPathsExist(n int, edgeList [][]int, queries [][]int) []bool {

	parent := make([]int, n)
	rank := make([]int, n)

	for i := 0; i < n; i++ {
		parent[i] = i
	}

	var find func(int) int

	find = func(node int) int {
		if parent[node] != node {
			parent[node] = find(parent[node])
		}
		return parent[node]
	}

	union := func(a int, b int) {
		rootA := find(a)
		rootB := find(b)

		if rootA == rootB {
			return
		}

		if rank[rootA] < rank[rootB] {
			parent[rootA] = rootB
		} else if rank[rootA] > rank[rootB] {
			parent[rootB] = rootA
		} else {
			parent[rootB] = rootA
			rank[rootA]++
		}
	}

	sort.Slice(edgeList, func(i, j int) bool {
		return edgeList[i][2] < edgeList[j][2]
	})

	type Query struct {
		p      int
		q      int
		limit  int
		index  int
	}

	indexedQueries := make([]Query, len(queries))

	for i, query := range queries {
		indexedQueries[i] = Query{
			p:     query[0],
			q:     query[1],
			limit: query[2],
			index: i,
		}
	}

	sort.Slice(indexedQueries, func(i, j int) bool {
		return indexedQueries[i].limit < indexedQueries[j].limit
	})

	answers := make([]bool, len(queries))

	edgeIndex := 0

	for _, query := range indexedQueries {

		for edgeIndex < len(edgeList) &&
			edgeList[edgeIndex][2] < query.limit {

			u := edgeList[edgeIndex][0]
			v := edgeList[edgeIndex][1]

			union(u, v)

			edgeIndex++
		}

		answers[query.index] = (find(query.p) == find(query.q))
	}

	return answers
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 主要差异来自语言语法和类型处理。 

Go不支持嵌套类，因此并查逻辑是使用闭包实现的。 

查询使用自定义表示`Query`struct 因为 Go 切片本身不支持像 Python 列表这样的异构元组。 

这`sort.Slice`函数用于对边和查询进行排序。 

由于所有约束都适合 Go 的范围`int`在现代平台上，整数溢出不是这里关注的问题。

 ## 边缘情况

 ### 严格小于与小于或等于

 最常见的错误之一是不小心将这种情况视为：```
edge_weight <= limit
```而不是：```
edge_weight < limit
```这会显着改变行为。 例如，有权重的边`5`当限制也时不能使用`5`。 

该实现使用以下方式正确处理此问题：```
while edge_weight < limit:
```而不是`<=`。 

### 同一节点之间的多条边

 该图可能包含连接具有不同权重的同一对节点的多条边。 

幼稚的实现可能会错误地覆盖边缘或假设唯一性。 

该解决方案在排序后独立处理每条边。 如果任何边满足极限约束，它就可以有助于连通性。 

### 查询以任意顺序到达

 为了提高效率，查询在内部按限制排序，但输出必须与原始查询顺序匹配。 

如果不存储原始索引，结果将按排序顺序而不是输入顺序返回。 

该实现通过使用原始索引扩充每个查询并将答案写回到正确的位置来解决这个问题。
