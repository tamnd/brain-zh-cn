[LeetCode 问题 1683](https://leetcode.com/problems/invalid-tweets/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为`Tweets`有两列：

 | 专栏 | 描述 |
 | ---| ---|
 |`tweet_id`| 每条推文的唯一标识符 |
 |`content`| 推文的文字内容 |

 任务是返回所有无效推文的 ID。 如果推文中的字符数低于推文的字符数，则推文被视为无效`content`严格大于`15`。 

换句话说，对于数组中的每一行`Tweets`桌子，我们必须测量的长度`content`细绳。 如果该长度超过`15`，我们包括相应的`tweet_id`在结果中。 

输出只需要一列：

 | 专栏 | 意义|
 | ---| ---|
 |`tweet_id`| 内容长度大于15的推文ID |

 返回行的顺序并不重要。 

问题陈述中的重要细节是短语“严格大于 15”。 这意味着：

 - 长度`15`有效
 - 长度`16`或以上无效

 该问题保证：

 -`tweet_id`是独一无二的
 -`content`仅包含字母数字字符、空格和感叹号
 - 每行都独立于其他行

 由于这是一个数据库问题，因此预期的解决方案是 SQL 查询，而不是 Python 或 Go 中的传统算法实现。 

一些重要的边缘情况包括：

 - 准确地发推文`15`字符，不应返回这些字符
 - 空推文、长度`0`有效
 - 包含空格的推文，空格算作字符
 - 包含标点符号的推文，例如`!`，这些也算作字符

 简单的实现在计算长度时可能会错误地忽略空格或特殊字符，但 SQL 字符串长度函数会计算字符串中的所有字符。 

## 方法

 ### 蛮力方法

 蛮力方法将扫描中的每一行`Tweets`表并手动一一统计每条推文内容中的字符。 计数后，它将与总数进行比较`15`。 如果计数大于`15`，推文 ID 将添加到结果中。 

这种方法是正确的，因为它直接遵循问题定义。 每个字符都会被检查并计算一次。 

然而，手动迭代字符是不必要的，因为 SQL 数据库已经提供了内置的字符串长度函数来有效地执行此操作。 

### 最佳方法

 最佳方法是使用内置的 SQL`LENGTH()`函数直接在查询中计算每条推文内容的字符数。 

关键的见解是数据库引擎已经针对字符串长度计算和过滤等操作进行了优化。 我们可以将工作委托给 SQL，而不是手动处理字符。 

查询很简单：

 1. 计算`LENGTH(content)`2. 过滤长度大于的行`15`3.返回对应的`tweet_id`这是简洁、高效且易于阅读的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(1) | O(1) | 手动计算每条推文的字符数 |
 | 最佳 | O(n × m) | O(1) | O(1) | 使用 SQL 内置字符串长度过滤 |

 这里：

-`n`是推文的数量
 -`m`是平均推文长度

 ## 算法演练

 ### 最优 SQL 算法

 1. 首先从以下位置选择数据`Tweets`桌子。 
2. 对于每一行，计算其中的字符数`content`使用 SQL 的列`LENGTH()`功能。 
3. 将计算出的长度与`15`。 
4. 仅保留长度严格大于的行`15`。 
5. 返回`tweet_id`这些已过滤行的列。 

### 为什么它有效

 该算法之所以有效，是因为`LENGTH(content)`准确返回推文中的字符总数，包括字母、空格和标点符号。 由于该问题将无效推文定义为内容长度超过的推文`15`，过滤`LENGTH(content) > 15`完全符合所需条件。 

## Python 解决方案

 虽然这从根本上来说是一个 SQL 问题，但下面是用于概念理解的逻辑的 Python 风格表示。```python
from typing import List, Dict

class Solution:
    def invalidTweets(self, tweets: List[Dict]) -> List[int]:
        invalid_tweet_ids: List[int] = []

        for tweet in tweets:
            if len(tweet["content"]) > 15:
                invalid_tweet_ids.append(tweet["tweet_id"])

        return invalid_tweet_ids
```此实现会迭代每条推文并检查推文的长度`content`使用Python内置的字段`len()`功能。 

这`invalid_tweet_ids`list 存储内容超过的推文 ID`15`人物。 

条件：```python
len(tweet["content"]) > 15
```直接反映问题陈述。 

然而，对于实际的 LeetCode 数据库问题，预期的答案是 SQL 而不是 Python。 

正确的SQL解决方案是：```python
SELECT tweet_id
FROM Tweets
WHERE LENGTH(content) > 15;
```## 解决方案

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|

该查询仅过滤行并返回匹配的 ID，因此不会使用大量辅助内存。

 ## 边缘情况

 ### 包含 15 个字符的推文

 这是问题中最重要的边界条件。 由于规则规定“严格大于 15”，因此长度恰好等于`15`必须保持有效。 

一个常见的错误是使用`>= 15`而不是`> 15`。 该实现通过显式检查来避免此错误：```
LENGTH(content) > 15
```### 空推文

 理论上，一条推文可以包含一个空字符串。 它的长度是`0`，远低于无效阈值。 

该实现自然地处理了这个问题，因为`LENGTH('')`回报`0`，因此该行不包含在结果中。 

### 空格和特殊字符

 某些实现错误地只计算字母和数字。 但是，问题指出内容中的所有字符都会影响长度，包括空格和感叹号。 

例如：```
"12345 67890 1234"
```包含必须计算的空格。 

SQL`LENGTH()`函数会正确计算字符串中的每个字符，因此会自动处理这些情况。
