[LeetCode 第 1616 题](https://leetcode.com/problems/split-two-strings-to-make-palindrome/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个字符串，`a`和`b`，两者具有相同的长度。 我们可以选择分割索引并在完全相同的位置分割两个字符串。 

如果我们分开：

 -`a`进入`aprefix + asuffix`-`b`进入`bprefix + bsuffix`那么我们可以形成两个候选字符串：

 -`aprefix + bsuffix`-`bprefix + asuffix`任务是确定这些组合中至少一个是否可以成为回文。 

回文是向前和向后读相同的字符串。 

重要的细节是分割可以发生在任何地方，包括字符串的边界。 这意味着裂缝的一侧可能是空的。 例如：

 - 在索引处分割`0`- 在索引处分割`n`都是有效的。 

约束条件非常重要：

 -`1 <= n <= 10^5`- 仅限小写英文字母
 - 两个字符串的长度相等

 长度为`10^5`立即告诉我们二次解太慢了。 任何重复尝试每次分割和重建字符串的方法都可能会超出时间限制。 我们需要接近线性时间的东西。 

一些边缘情况很重要：

 - 单字符串始终有效，因为每个单字符串都是回文。 
- 原始字符串之一可能已经是回文。 
- 有效的回文只有在混合两个字符串后才会出现。 
- 字符串中可能会出现很早或很晚的不匹配情况。 
- 分割可能发生在开头或结尾，这意味着我们可以有效地仅选择一个原始字符串。 

该问题保证：

 - 两个字符串的长度相等。 
- 字符串仅包含小写英文字母。 
- 长度至少为`1`，所以空输入永远不会发生。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的拆分索引。 

对于每个分割位置`i`：

- 建造`a[:i] + b[i:]`- 建造`b[:i] + a[i:]`- 检查任一结果是否是回文

 回文检查本身的成本`O(n)`，并且有`n + 1`可能的分割位置。 

因此：

 - 构建和检查每个候选人的成本`O(n)`- 我们这样做`O(n)`次

 这导致`O(n^2)`时间复杂度。 

和`n = 10^5`，这变得太慢了。 

### 最佳解决方案的关键见解

 仅当镜像位置的字符不同时，回文才会失败。 

假设我们尝试形成：```
a prefix + b suffix
```我们比较：

 - 左侧从`a`- 右侧`b`使用两个指针：

 -`left`从头开始
 -`right`从结束开始

 只要：```
a[left] == b[right]
```回文条件仍然成立。 

最终发生以下两件事之一：

 1.我们顺利完成
 2.我们遇到第一个不匹配的情况

 在第一次不匹配时，我们不再有继续任意混合的自由。 剩余的中间部分必须已经是完全在一根字符串内的回文。 

所以在不匹配之后，我们只需要检查：

 - 是`a[left:right+1]`回文？ 
- 或是`b[left:right+1]`回文？ 

如果任一为真，则存在有效的分割。 

这一观察结果将问题从独立尝试每个分割减少到单个线性扫描。 

我们必须测试两个方向：

 -`a prefix + b suffix`-`b prefix + a suffix`因为任何一种安排都可能成功。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 尝试每个分割并构造候选字符串 |

 ## 算法演练

 1. 定义辅助函数`is_palindrome(s, left, right)`。 

该函数检查子字符串是否`s[left:right+1]`是使用两个向内移动的指针的回文。 
2.定义另一个辅助函数`check(x, y)`。 

该函数测试是否组合：```
x prefix + y suffix
```可以组成一个回文。 
3. 内部`check(x, y)`，初始化：

 -`left = 0`-`right = len(x) - 1`4. 将指针向内移动，同时：```
x[left] == y[right]
```这意味着外部字符仍然满足回文对称性。 
5. 在第一个不匹配处停止。 

此时，剩余的中间部分必须完全来自一根弦。 
6. 检查剩余的子串是否已经是回文：

 -`x[left:right+1]`-`y[left:right+1]`如果其中一个是回文数，则返回`True`。 
7. 如果整个扫描完成且没有不匹配，则返回`True`。 

这意味着混合串已经完全满足回文对称性。 
8. 运行：```
check(a, b)
```和```
check(b, a)
```9. 如果其中一个成功，则返回`True`。 否则返回`False`。 

### 为什么它有效

 该算法依赖于这样一个事实：回文有效性仅取决于镜像字符对。 

当从外向内扫描时，我们可以有效地确定哪些部分来自哪根弦。 一旦发生第一个不匹配，就无法再进行进一步的混合来修复不匹配模式。 唯一的可能性是剩余的中间部分已经完全在一个字符串内形成一个回文。 

因此，检查任一原始字符串内的剩余子字符串就足够了并且保证了正确性。 

## Python 解决方案```python
class Solution:
    def checkPalindromeFormation(self, a: str, b: str) -> bool:
        def is_palindrome(s: str, left: int, right: int) -> bool:
            while left < right:
                if s[left] != s[right]:
                    return False
                left += 1
                right -= 1
            return True

        def check(x: str, y: str) -> bool:
            left = 0
            right = len(x) - 1

            while left < right and x[left] == y[right]:
                left += 1
                right -= 1

            return (
                is_palindrome(x, left, right)
                or is_palindrome(y, left, right)
            )

        return check(a, b) or check(b, a)
```实施开始于`is_palindrome`helper，它对子字符串执行标准的两指针回文检查。 这可以避免创建新字符串并保持内存使用量恒定。 

这`check`助手执行主要逻辑。 它将一个字符串的左侧与另一字符串的右侧进行比较。 只要字符匹配，混合回文仍然有效。 

当出现不匹配时，算法会检查剩余的中间部分是否已经是任一原始字符串中的回文。 如果是这样，我们可以选择在该位置进行分割。 

最后，该解决方案检查两个可能的串联方向，因为任何一种排列都可能产生回文。 

## 解决方案```go
func checkPalindromeFormation(a string, b string) bool {
	isPalindrome := func(s string, left int, right int) bool {
		for left < right {
			if s[left] != s[right] {
				return false
			}
			left++
			right--
		}
		return true
	}

	var check func(string, string) bool

	check = func(x string, y string) bool {
		left := 0
		right := len(x) - 1

		for left < right && x[left] == y[right] {
			left++
			right--
		}

		return isPalindrome(x, left, right) ||
			isPalindrome(y, left, right)
	}

	return check(a, b) || check(b, a)
}
```Go 的实现与 Python 版本非常相似。 

Go 中的字符串按字节索引，这在这里是安全的，因为输入仅包含小写英文字母。 不需要 Unicode 处理。 

辅助函数使用闭包来实现更清晰的组织。 内存使用量保持不变，因为没有创建子字符串副本。

 ## 边缘情况

 ### 单字符串

 当两个字符串都只包含一个字符时，答案始终是`true`。 任何单个字符串本质上都是回文。 幼稚的实现可能会错误地认为拆分是必要的，但问题是允许空前缀和后缀。 该实现自然地处理了这个问题，因为两个指针循环立即终止并且子串回文检查成功。 

### 第一个字符不匹配

 案例如下：```
a = "abc"
b = "xyz"
```在最外面的比较处立即失败。 有缺陷的实现可能会不必要地继续搜索另一个拆分。 最佳解决方案正确地认识到，一旦发生第一个不匹配，只有剩余的子串很重要。 由于剩下的子串都不是回文，所以答案是正确的`false`。 

### 一个原始字符串已经是回文串

 假设：```
a = "racecar"
b = "abcdefg"
```即使没有混合字符串，答案也应该是`true`因为我们可能会在索引处拆分`0`或者`n`并且有效地只使用一根绳子。 该实现会自动处理此问题，因为在不匹配检测之后，它会检查剩余的子字符串是否已经是回文。
