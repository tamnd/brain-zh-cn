[LeetCode 问题 1666](https://leetcode.com/problems/change-the-root-of-a-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们在给定的叶节点处重新定位二叉树。 通常，二叉树只有一个根，每个节点都向下指向其子节点。 在这个问题中，每个节点还包含一个`parent`指针，允许向上遍历到根。 

我们有两个输入：

 -`root`，二叉树的当前根
 -`leaf`，保证是树中某处叶子的节点

 我们的任务是改造这棵树，使得给定的`leaf`成为新的根。 

重新生根过程遵循非常具体的规则。 从`leaf`并向上移动到原始根：

 1. 如果当前节点已有左子节点，则该左子节点必须成为当前节点的右子节点。 
2. 当前节点的父节点成为其左子节点。 
3. 必须删除从父节点到当前节点的原始连接。 

对从叶到原始根的路径上的每个节点重复此操作，不包括原始根本身。 

重要的细节是我们必须正确维护：

 - 子指针（`left`和`right`）
 - 父指针（`parent`）

 只更新树结构但忘记更新父引用的解决方案将会失败。 

限制很小，最多 100 个节点，这意味着效率并不是非常关键。 但是，树操作在逻辑上仍然必须正确，因为指针更新可以轻松创建循环或留下悬空引用。 

一些重要的边缘情况立即脱颖而出：

 - 叶子可能已经直接连接到根。 
- 重新根路径上的节点可能已经有左子节点，必须将其向右移动。 
- 当前节点可能是其父节点的左子节点或右子节点，因此我们必须断开正确的指针。 
- 不正确的指针更新可能会在树中创建循环。 
- 除非明确清理，否则原始根可能仍保留对旧子项的引用。 

因为每个节点值都是唯一的，并且保证叶子存在于树中，所以我们不需要担心歧义或无效输入。 

## 方法

 ### 蛮力方法

 暴力策略会在确定从叶子到根的路径后尝试从头开始完全重建树。 

一种可能的实施方式是：

 1. 执行DFS或BFS来记录整个树结构。 
2. 提取从叶子到根的路径。 
3. 创建一棵全新的树，其中沿着该路径的边缘是相反的。 
4. 手动重新附加每个不受影响的子树。 

这是有效的，因为重新定位从根本上意味着沿着单一路径反转父子关系。 通过明确地重建整个结构，我们可以保证正确性。 

然而，这种方法不必要地复杂。 重建树需要大量的簿记工作，并且在重新连接子树和父指针时会引入许多出错的机会。 

尽管约束很小，但与直接修改指针相比，重建整个结构效率很低。 

### 最佳方法

 关键的见解是，只有从叶到根的路径上的节点会改变方向。 

其他所有子树都保持在原来的位置。 

因此，我们可以不重建树，而是从叶子向上走，一步步局部反转父子关系。 

在每个节点：

 - 通过将其移至右侧来保留任何现有的左子项
 - 让父母成为新的左孩子
 - 断开旧的父引用
 - 继续向上

 这类似于反转链表，只不过每个节点还可以包含另一个必须正确保留的子树。 

因为我们只遍历根到叶路径一次，所以该算法既简单又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 从头开始重建树结构 |
 | 最佳 | O(n) | O(1) | O(1) | 沿叶到根路径反转指针 |

 ## 算法演练

 1.从给定开始`leaf`节点。 

该节点最终将成为新的根。 我们将使用父指针向上走向原始根。 
2. 在修改指针之前存储当前节点的父节点。 

一旦我们开始改变孩子的关系，原来的结构就会改变。 因此，我们首先保存父引用，以便我们可以继续安全地向上遍历。 
3. 如果当前节点有左子节点，则将其移动到右子节点位置。 

问题陈述明确要求进行这种转换。 我们在分配新的左子节点之前执行此操作，因为左指针很快就会被父节点覆盖。 
4. 使原父节点成为当前节点的左子节点。 

这会反转当前节点与其父节点之间的边的方向。 
5. 断开原始父节点对当前节点的引用。 

父节点可以通过其任一引用当前节点`left`或者`right`指针。 我们检查两种可能性并将正确的一种设置为`None`。 

此步骤至关重要，因为未能断开旧边缘会产生循环。 
6. 仔细更新父指针。 

- 当前节点的父节点成为重根链中处理的前一个节点。 
- 当处理继续向上时，原始父级的父级稍后将被更新。 
7. 向上移动到原始父级并重复。 

继续，直到到达原始根。 
8. 完成新根。 

一旦遍历完成，原来的叶子就成为新的根，所以它的父指针必须是`None`。 

### 为什么它有效

 该算法之所以有效，是因为每次迭代都会沿从叶到根的唯一路径恰好反转一条边。 

每一步：

 - 旧的父子关系被移除
 - 创建反向关系
 - 未受影响的子树保持正确连接

 由于路径上的每条边都恰好反转一次，并且不会留下任何循环，因此最终的结构是一个以原始叶子为根的有效二叉树。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None
        self.parent = None
"""

from typing import Optional

class Solution:
    def flipBinaryTree(self, root: 'Node', leaf: 'Node') -> 'Node':
        current = leaf
        previous = None

        while current != root:
            parent = current.parent

            # Preserve existing left child by moving it to the right
            if current.left:
                current.right = current.left

            # Reverse the edge
            current.left = parent

            # Disconnect parent from current
            if parent.left == current:
                parent.left = None
            elif parent.right == current:
                parent.right = None

            # Update parent pointer
            current.parent = previous

            # Move upward
            previous = current
            current = parent

        # Final root processing
        current.parent = previous

        # Disconnect any leftover child reference
        if current.left == previous:
            current.left = None
        elif current.right == previous:
            current.right = None

        return leaf
```该实现直接遵循前面描述的指针反转策略。 

变量`current`从叶子向上行走时跟踪当前正在处理的节点。 变量`previous`表示已经在当前节点下重新定位的节点。 

在更改任何结构之前，算法会存储`parent = current.parent`。 这是必要的，因为亲子关系很快就会颠倒过来。 

如果当前节点已有左子节点，则它将移至右侧。 这会在覆盖左指针之前保留子树。 

边沿反转发生在：```python
current.left = parent
```此时，父节点仍然指向当前节点，因此必须删除旧的引用。 该代码检查当前节点是否作为左子节点或右子节点附加，并断开正确的指针。 

最后，更新父指针，以便重新定位的结构保持一致。 

一旦到达原始根，循环就会停止。 退出循环后，原始根仍然需要清理，因为它可能仍然引用重新根的链。 

函数最终返回`leaf`，现在是新的根。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val    int
 *     Left   *Node
 *     Right  *Node
 *     Parent *Node
 * }
 */

func flipBinaryTree(root *Node, leaf *Node) *Node {
	current := leaf
	var previous *Node = nil

	for current != root {
		parent := current.Parent

		// Preserve existing left child
		if current.Left != nil {
			current.Right = current.Left
		}

		// Reverse the edge
		current.Left = parent

		// Disconnect parent from current
		if parent.Left == current {
			parent.Left = nil
		} else if parent.Right == current {
			parent.Right = nil
		}

		// Update parent pointer
		current.Parent = previous

		previous = current
		current = parent
	}

	// Final cleanup for original root
	current.Parent = previous

	if current.Left == previous {
		current.Left = nil
	} else if current.Right == previous {
		current.Right = nil
	}

	return leaf
}
```Go 实现在结构上几乎与 Python 版本相同。 

主要区别是使用显式指针处理`nil`而不是`None`。 Go 还需要显式变量声明和类型注释。 

由于 Go 直接使用指针，因此树操作保持高效且到位，无需额外分配。

    parent.left = left
    parent.right = right

    if left:
        left.parent = parent

    if right:
        right.parent = parent

def serialize(root):
    from collections import deque

    result = []
    queue = deque([root])

    while queue:
        node = queue.popleft()

        if node:
            result.append(node.val)
            queue.append(node.left)
            queue.append(node.right)
        else:
            result.append(None)

        result.pop()

    return result

 ## 边缘情况

 当树仅包含两个节点时，会出现一种重要的边缘情况。 在这种情况下，叶子直接连接到根，重新生根只需要单边反转。 有缺陷的实现可能会意外地将原始根指向叶子，从而形成循环。 该解决方案通过在每次迭代期间显式断开父引用来处理此问题。 

当重新根路径上的节点已经有左子节点时，会发生另一种微妙的情况。 根据问题规则，该子树不能被丢弃。 相反，在将父节点附加为新的左子节点之前，它会成为节点的右子节点。 忘记这一步将会丢失部分树结构。 该实现通过移动来保留子树`current.left`进入`current.right`在覆盖左指针之前。 

第三个关键边缘情况涉及父指针。 许多树问题只需要更新子引用，但这个问题明确验证`parent`链接也是如此。 如果新的根仍然具有非空父节点，或者如果中间节点引用过时的父节点，则解决方案将失败。 该实现会仔细更新每个节点的`parent`重新根期间字段并明确确保最终根具有`parent = None`。
