 # LeetCode 1691 - 堆叠长方体的最大高度

 ## 问题理解

 这个问题给了我们一个 3D 长方体的集合，其中每个长方体由三个维度表示：宽度、长度和高度。 我们可以选择这些长方体的任何子集并将它们垂直堆叠以最大化总高度。 

仅当一个长方体的所有三个尺寸都小于或等于其下方长方体的相应尺寸时，才可以将其放置在另一个长方体的顶部。 重要的细节是每个长方体都可以自由旋转。 由于长方体具有三个维度，因此我们可以在堆叠之前以任何顺序重新排列它们。 

任务是确定通过堆叠有效长方体可获得的最大可能总高度。 

输入是长方体列表：```
cuboids[i] = [widthi, lengthi, heighti]
```输出是一个整数，表示可实现的最高堆栈。 

限制相对较小：

 - 长方体的数量，`n <= 100`- 每个维度最多`100`这些限制强烈表明`O(n²)`动态规划解决方案是可以接受的。 指数方法变得不可行，因为每个长方体可能被包含也可能不被包含，并且每个长方体也有多个方向。 

一些边缘情况很重要：

 - 单个长方体，其中答案只是旋转后其最大可能高度。 
- 根本无法堆叠在一起的长方体。 
- 多个具有相同尺寸的长方体。 
- 需要旋转长方体才能获得最佳答案的情况。 
- 局部较高的长方体不是全局最优的链。 

该问题保证所有维度都是正整数，因此我们永远不需要处理零或负大小。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试长方体的每个可能的子集以及这些长方体的每个可能的顺序和方向。 

对于每个长方体，最多有 6 种可能的旋转。 如果我们考虑所有子集、所有排列和所有方向，搜索空间就会变得巨大。 

暴力算法将：

 1. 生成每个长方体的每个方向。 
2. 尝试长方体的每种排序。 
3. 验证堆栈是否合法。 
4. 计算总高度。 
5. 跟踪最大值。 

这保证了正确性，因为每个有效的堆栈都会被探索。 然而，复杂性变成阶乘和指数，即使对于`n = 100`。 

### 关键见解

 关键的观察是旋转自由度允许我们标准化每个长方体。 

如果我们对长方体的三个维度进行排序：```
[a, b, c] where a <= b <= c
```那么我们就可以随时治疗`c`作为高度和`a`,`b`作为基础尺寸。 

为什么这有效？ 

因为如果长方体可以任意旋转，那么排序维度可以保证规范方向，该方向永远不会比用于堆叠目的的任何其他方向更差。 

在单独规范化每个长方体后，我们可以按字典顺序对整个长方体列表进行排序。 那么这个问题就变得与最长递增子序列问题极其相似。 

我们定义：```
dp[i] = maximum stack height ending with cuboid i on top
```对于每对`(j, i)`在哪里`j < i`，如果是长方体`j`可以支持长方体`i`， 然后：```
dp[i] = max(dp[i], dp[j] + height[i])
```这将问题简化为干净的`O(n²)`动态规划解决方案。

 ## 算法演练

 1. 通过对每个长方体的三个维度进行排序来标准化它。 

例如：```
[50, 45, 20] -> [20, 45, 50]
```这保证了每个长方体的方向一致。 
2. 按字典顺序对整个 cuboid 列表进行排序。 

排序后，较小的长方体自然出现在较大的长方体之前。 这简化了转换逻辑，因为在处理长方体时`i`，所有潜在的下长方体已经出现在数组的前面。 
3. 创建DP阵列。```
dp[i]
```表示长方体可实现的最大堆叠高度`i`在顶部。 
4. 初始化各个状态。 

至少，一个仅包含长方体的堆栈`i`有高度：```
dp[i] = cuboids[i][2]
```因为最大尺寸被视为高度。 
5. 比较每个较早的长方体。 

对于每个`i`, 迭代所有`j < i`。 

如果：```
cuboids[j][0] <= cuboids[i][0]
cuboids[j][1] <= cuboids[i][1]
cuboids[j][2] <= cuboids[i][2]
```然后是长方体`j`可以放在长方体下面`i`。 
6. 更新 DP 转换。 

如果堆叠有效：```
dp[i] = max(dp[i], dp[j] + cuboids[i][2])
```7. 返回DP数组中的最大值。 

该值代表可实现的最高堆栈。 

### 为什么它有效

 在内部对每个长方体进行排序可以保证规范的方向，从而保留所有有效的堆叠可能性。 对整个长方体列表进行排序可确保在处理长方体时`i`，每个可能的前驱都出现在数组的较早位置。 

DP 递归正确地计算出在每个长方体处结束的最佳堆栈，因为每个有效的先前长方体都被仅考虑一次。 由于每个堆栈必须以某个长方体结束，因此最大 DP 值是最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxHeight(self, cuboids: List[List[int]]) -> int:
        # Normalize each cuboid by sorting dimensions
        for cuboid in cuboids:
            cuboid.sort()

        # Sort all cuboids lexicographically
        cuboids.sort()

        n = len(cuboids)

        # dp[i] = maximum stack height with cuboid i on top
        dp = [0] * n

        max_height = 0

        for i in range(n):
            dp[i] = cuboids[i][2]

            for j in range(i):
                if (
                    cuboids[j][0] <= cuboids[i][0]
                    and cuboids[j][1] <= cuboids[i][1]
                    and cuboids[j][2] <= cuboids[i][2]
                ):
                    dp[i] = max(dp[i], dp[j] + cuboids[i][2])

            max_height = max(max_height, dp[i])

        return max_height
```实现首先对每个长方体内部的尺寸进行排序。 此步骤隐式处理旋转并将每个长方体转换为标准形式。 

接下来，整个长方体列表按字典顺序排序。 这种顺序保证了较小的长方体出现在较大的兼容长方体之前。 

动态编程数组存储以每个长方体结束的最佳堆栈高度。 最初，每个长方体形成一个高度等于其自身高度的堆栈。 

嵌套循环检查所有先前的长方体。 如果前一个长方体适合当前长方体，则 DP 转换会尝试扩展堆栈。 

最后，返回所有 DP 状态中的最大值。 

## 解决方案```go
package main

import "sort"

func maxHeight(cuboids [][]int) int {
	// Normalize dimensions inside each cuboid
	for _, cuboid := range cuboids {
		sort.Ints(cuboid)
	}

	// Sort all cuboids lexicographically
	sort.Slice(cuboids, func(i, j int) bool {
		for k := 0; k < 3; k++ {
			if cuboids[i][k] != cuboids[j][k] {
				return cuboids[i][k] < cuboids[j][k]
			}
		}
		return false
	})

	n := len(cuboids)

	dp := make([]int, n)

	maxHeight := 0

	for i := 0; i < n; i++ {
		dp[i] = cuboids[i][2]

		for j := 0; j < i; j++ {
			if cuboids[j][0] <= cuboids[i][0] &&
				cuboids[j][1] <= cuboids[i][1] &&
				cuboids[j][2] <= cuboids[i][2] {

				if dp[j]+cuboids[i][2] > dp[i] {
					dp[i] = dp[j] + cuboids[i][2]
				}
			}
		}

		if dp[i] > maxHeight {
			maxHeight = dp[i]
		}
	}

	return maxHeight
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 主要区别在于使用`sort.Slice`用于字典排序。 

Go 切片是引用类型，因此对各个长方体进行排序会就地修改它们。 整数溢出不是问题，因为最大可能的高度最多为：```go
100 cuboids * 100 height = 10000
```很容易适合 Go 的内部`int`。

 ## 边缘情况

 ### Single Cuboid

 当仅存在一个长方体时，无需做出堆叠决策。 有缺陷的实现可能会错误地初始化 DP 值或假设至少存在一个转换。 

这个实现自然地处理了这种情况，因为每个`dp[i]`从长方体自身的高度开始。 答案就变成了那个单一值。 

### 无法堆叠的长方体

 某些输入包含长方体，其中没有一对满足尺寸约束。 在这些情况下，正确的答案就是旋转后最高的单个长方体。 

该实现会处理此问题，因为仅当所有三个维度都满足堆叠条件时才会发生 DP 转换。 否则，长方体仍然是一个独立的堆栈。 

### 多个相同的长方体

 允许相同的尺寸，因为条件使用`<=`， 不是`<`。 

一个常见的错误是意外地强制执行严格的不平等，这会错误地拒绝有效的相同长方体堆栈。 

该解决方案明确使用`<=`比较，因此相同的长方体可以正确堆叠。 

### 旋转相关的解决方案

 一些最佳堆叠只有在旋转长方体后才可能实现。 保留原始方向的简单实现可能会完全错过有效的堆栈。 

对每个长方体的尺寸进行排序可以保证每个长方体都被认为处于堆叠的最佳规范方向，从而消除了与方向相关的错误。
