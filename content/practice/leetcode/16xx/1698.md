[LeetCode 第 1698 题](https://leetcode.com/problems/number-of-distinct-substrings-in-a-string/)

 **难度：** 🟡 中等
 **主题：** 字符串、Trie、滚动哈希、后缀数组、哈希函数

 ## 解决方案

 ## 问题理解

 该问题要求给出给定字符串的 **不同子字符串** 的总数`s`。 子字符串是字符串中任何连续的字符序列，包括单字符子字符串和字符串本身。 输出是一个整数，表示可以由多少个唯一子字符串组成`s`。 

例如，在字符串中`"aabbaba"`，子串如`"a"`,`"aa"`,`"ab"`,`"aba"`等等都会被计算在内，但重复的会被忽略。 结果应包括所有可能的长度，从 1 到字符串的完整长度。 

约束表明`s`最多 500 个字符且仅包含小写字母。 这使得枚举所有可能子串的强力解决方案可行，但不是最优的。 要考虑的边缘情况包括所有字符都相同的字符串、具有所有唯一字符的字符串以及非常短的字符串（长度为 1）。 

## 方法

 最简单的方法是**暴力**：生成所有可能的子字符串，将它们存储在一个集合中以删除重复项，然后返回集合的大小。 虽然正确，但这种方法很慢，因为它需要粗略地生成`n*(n+1)/2`长度字符串的子字符串`n`并且每个子串比较可能需要线性时间。 总体复杂度约为`O(n^3)`。 

更有效的方法利用 **Trie、滚动哈希或后缀数组**。 关键的见解是我们不需要逐个字符地重复比较子字符串。 Trie 可以有效地存储所有子字符串：从根开始的每个路径都代表一个子字符串，插入所有子字符串可以保证自动处理重复项。 **滚动哈希**允许使用哈希值进行恒定时间的子字符串比较，从而实现`O(n^2)`方法。 为了`O(n)`现在，**后缀自动机**是理想的，但那更高级，并且涉及构建表示所有子串的结构。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 生成所有子字符串并存储在集合中 |
 | 特里树/滚动哈希 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 将所有子字符串插入 Trie 或计算哈希值以有效跟踪唯一性 |
 | 后缀自动机 | O(n) | O(n) | 隐式存储所有子字符串的先进技术 |

 ## 算法演练

 我们将描述 **Rolling Hash / Set** 方法，该方法对于输入大小而言简单且高效：

 1.初始化一个空集`unique_substrings`存储子字符串的哈希值。 
2. 迭代所有起始索引`i`字符串的`s`。 
3. 对于每个`i`，迭代所有结束索引`j >= i`提取子字符串`s[i:j+1]`。 
4. 计算滚动哈希值`s[i:j+1]`以避免直接比较子字符串。 
5.将哈希值插入`unique_substrings`。 
6.处理完所有子串后，返回大小`unique_substrings`。 

工作原理：滚动哈希确保相同的子字符串映射到相同的哈希值，因此当存储在集合中时，重复项会被自动过滤。 由于我们考虑了所有可能的开始和结束位置，因此所有子字符串都被考虑在内。 

## Python 解决方案```python
class Solution:
    def countDistinct(self, s: str) -> int:
        n = len(s)
        mod = 10**9 + 7
        base = 31
        unique_hashes = set()
        
        for i in range(n):
            current_hash = 0
            for j in range(i, n):
                current_hash = (current_hash * base + (ord(s[j]) - ord('a') + 1)) % mod
                unique_hashes.add(current_hash)
        
        return len(unique_hashes)
```说明：我们迭代从以下位置开始的所有子字符串`i`。 内循环将子字符串扩展为`j`，增量计算哈希值。`ord(s[j]) - ord('a') + 1`将字符转换为适合散列的数值。 所有唯一的哈希值都存储在一个集合中，其长度作为答案返回。 

## 解决方案```go
func countDistinct(s string) int {
    n := len(s)
    mod := int64(1e9 + 7)
    base := int64(31)
    unique := make(map[int64]struct{})
    
    for i := 0; i < n; i++ {
        var currentHash int64 = 0
        for j := i; j < n; j++ {
            currentHash = (currentHash*base + int64(s[j]-'a'+1)) % mod
            unique[currentHash] = struct{}{}
        }
    }
    
    return len(unique)
}
```Go 差异：我们使用`int64`用于散列以避免溢出，以及`map[int64]struct{}`作为一个集合。 空结构使用最少的内存。 

## 工作示例

 **示例1：`s = "aabbaba"`**

 | 我| j | 子串 | 已添加哈希值 |
 | ---| ---| ---| ---|
 | 0 | 0 | “一个”| 哈希（“a”）|
 | 0 | 1 | “aa”| 哈希（“aa”）|
 | 0 | 2 | “aab”| 哈希（“aab”）|
 | 0 | 3 | “aabb”| 哈希（“aabb”）|
 | ... | ... | ... | ... |

 这对所有人来说都是持续的`(i, j)`对。 经过所有迭代后，该集合包含 21 个唯一的哈希值，对应于 21 个不同的子字符串。 

**示例2：`s = "abcdefg"`**

 所有子字符串都是唯一的，因为所有字符都不同。 不同子串总数 =`n*(n+1)/2 = 28`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n^2) | O(n^2) | 外循环结束`i`和内循环`j`大致产生`n*(n+1)/2`迭代|

尽管最坏情况空间是二次的，但它是可以接受的`n <= 500`。

 ## 边缘情况

 1. **单字符串**：对于`s = "a"`，算法正确返回 1，因为唯一的子字符串是`"a"`。 这测试了最小输入的处理。 
2. **所有相同的字符**：对于`s = "aaaa"`，直接比较子字符串的简单方法可能会多次计算重复项。 我们的散列方法会自动处理这个问题，因为所有相同的子字符串都映射到相同的散列。 
3. **所有独特字符**：对于`s = "abcdef"`，每个子串都是唯一的。 这测试算法是否正确处理不同子字符串的数量呈二次方增长的情况，并确保集合或映射正确计算所有条目而不会发生冲突。
