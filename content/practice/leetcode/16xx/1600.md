 **难度：** 🟡 中等
 **主题：** 哈希表、树、深度优先搜索、设计

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个模拟皇室继承系统的数据结构。 家谱的顶端有一位国王，随着时间的推移，人们可以出生或死亡。 我们必须有效支持三项行动：

 1. 为现有人员添加子级。 
2. 将一个人标记为死亡。 
3. 返回当前的继承顺序。 

继承顺序遵循家谱的前序遍历。 父母总是出现在孩子之前，而在兄弟姐妹中，年长的孩子出现在年幼的孩子之前。 由于出生是按时间顺序添加的，因此插入孩子的顺序很重要。 

一个重要的细节是死亡不会将一个人从家谱中删除。 死去的人仍然会影响遍历顺序，因为他们的后代必须保持在正确的位置。 唯一的区别是，在生成最终的继承名单时，会跳过已故的人。 

递归`Successor`语句中的定义有效地描述了前序深度优先遍历：

 1.拜访当前人。 
2. 从最大到最小的顺序递归地访问每个孩子。 

输入操作动态修改家谱。 这`birth`操作添加了定向父子关系。 这`death`手术只是将一个人标记为死亡。 这`getInheritanceOrder`操作必须以正确的继承顺序返回所有活着的人。 

约束条件非常重要：

 - 最多`10^5`可以拨打`birth`和`death`。 
- 仅限至`10`拨打电话至`getInheritanceOrder`。 

这告诉我们更新比查询发生得更频繁。 这种观察强烈影响了设计选择。 我们不想在每次出生或死亡后重建昂贵的建筑。 相反，我们应该增量存储家谱，并仅在需要时生成继承顺序。 

一些边缘情况很重要：

 - 国王可能会死，但他们的后代仍然按顺序继承。 
- 死者的孩子仍必须出现在继承名单中。 
- 一个人可能有很多孩子，出生顺序必须保留。 
- 多次更新后可能会出现继承顺序查询的情况。 
- 树可能变得非常深，因此递归遍历在实际限制内仍应保持正确。 

## 方法

 ### 蛮力方法

 强力方法会尝试在每次操作后显式维护继承顺序。 

例如，在每次出生或死亡后，我们可以通过模拟来重建整个继承顺序。`Successor`从头开始的过程。 这将涉及重复遍历整个家谱。 

这种做法是正确的，因为前序遍历自然符合继承规则。 然而，每次更新后重建整个订单的成本很高。 

如果有`N`人们和我们在每次操作后重建订单，总成本可以变为`O(N^2)`跨越许多操作。 

由于最多可以有`10^5`更新，重复重新计算整个订单效率低下。 

### 最佳方法

 关键的见解是出生和死亡只会修改本地信息：

 - 出生将孩子添加到父母的孩子列表中。 
- 死亡标志着一个人已故。 

这两种操作都不需要立即重新计算继承顺序。 

因为`getInheritanceOrder`最多被调用 10 次，我们可以将所有昂贵的工作推迟到查询时间。 我们存储：

 - 代表家谱的邻接列表。 
- 包含死人的集合。 
- 国王的名字。 

什么时候`getInheritanceOrder`被调用后，我们执行前序 DFS 遍历：

 1.拜访当前人。 
2. 如果还活着，则将它们添加到结果中。 
3. 按出生顺序递归处理孩子。 

这直接反映了继承规则。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次更新 O(N) | O(N) | 反复重建继承顺序 |
 | 最佳 | 出生：O(1)，死亡：O(1)，查询：O(N) | O(N) | 仅在需要时存储树并计算顺序 |

 ## 算法演练

 ### 最优算法

 1.用国王的名字初始化数据结构。 

我们单独存储国王，因为遍历总是从国王开始。 我们还创建：

 - 从父级到子级列表的哈希映射。 
- 一群死人。 
2. 通过将孩子添加到父母的孩子列表来处理出生。 

插入顺序很重要，因为继承遵循从大到小的子顺序。 追加自然会保留此顺序。 
3. 通过将人的名字添加到死亡集中来处理死亡。 

我们不会将它们从树中删除，因为它们的后代仍然在同一位置继承。 
4. 什么时候`getInheritanceOrder`叫做，从王开始预购DFS。 

遍历完全遵循继承规则：

 - 首先处理当前人。 
- 然后从最大到最小递归处理孩子。 
5. 在 DFS 期间，仅将活着的人添加到结果中。 

死去的人会被跳过，但遍历会继续通过他们的后代。 
6. 返回完成的结果列表。 

### 为什么它有效

 继承规则相当于家谱的前序遍历。 每个父母都出现在后代面前，兄弟姐妹按出生顺序被拜访。 由于出生按时间顺序追加孩子，因此 DFS 遍历自然会产生正确的继承顺序。 在继续遍历的同时跳过死去的人可以保留后代所需的顺序。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class ThroneInheritance:

    def __init__(self, kingName: str):
        self.king = kingName
        self.children = defaultdict(list)
        self.dead = set()

    def birth(self, parentName: str, childName: str) -> None:
        self.children[parentName].append(childName)

    def death(self, name: str) -> None:
        self.dead.add(name)

    def getInheritanceOrder(self) -> List[str]:
        order = []

        def dfs(person: str) -> None:
            if person not in self.dead:
                order.append(person)

            for child in self.children[person]:
                dfs(child)

        dfs(self.king)
        return order
```该实现使用邻接表将王室存储为一棵树。 这`children`字典将每个人按出生顺序映射到他们的孩子列表。 

构造函数初始化王、邻接表和死集。 

这`birth`方法将子级附加到父级的子级列表中。 由于出生是按时间顺序发生的，因此附加会自动保留从最老到最年轻的顺序。 

这`death`方法将人添加到`dead`放。 我们故意将死者保留在树中，因为他们的后代仍然属于继承顺序。 

这`getInheritanceOrder`方法执行前序 DFS 遍历。 如果当前人还活着，则会将其添加到结果中。 然后按顺序递归处理所有子项。 

该实现直接反映了问题陈述中的继承定义。 

## 解决方案```go
package main

type ThroneInheritance struct {
	king     string
	children map[string][]string
	dead     map[string]bool
}

func Constructor(kingName string) ThroneInheritance {
	return ThroneInheritance{
		king:     kingName,
		children: make(map[string][]string),
		dead:     make(map[string]bool),
	}
}

func (this *ThroneInheritance) Birth(parentName string, childName string) {
	this.children[parentName] = append(this.children[parentName], childName)
}

func (this *ThroneInheritance) Death(name string) {
	this.dead[name] = true
}

func (this *ThroneInheritance) GetInheritanceOrder() []string {
	order := []string{}

	var dfs func(string)

	dfs = func(person string) {
		if !this.dead[person] {
			order = append(order, person)
		}

		for _, child := range this.children[person] {
			dfs(child)
		}
	}

	dfs(this.king)

	return order
}
```Go 实现遵循与 Python 版本相同的逻辑。 

这`children`结构使用从字符串到字符串切片的映射。 切片自然地保留插入顺序，这对于维持出生顺序很重要。 

这`dead`结构被实现为`map[string]bool`因为 Go 没有内置的集合类型。 

DFS 遍历是使用嵌套函数闭包实现的。 递归将活着的人追加到结果切片中，同时继续遍历所有后代。

 这`birth`操作是恒定时间，因为附加到子列表是`O(1)`摊销。 这`death`操作也是恒定时间，因为哈希集插入是`O(1)`平均情况。 

这`getInheritanceOrder`操作对整个家谱执行前序遍历。 每个人都被访问过一次，所以复杂度为`O(N)`。 

空间复杂度为`O(N)`因为我们将所有的人存储在邻接列表中，并且可能存储在死集中。

 ## 边缘情况

 ###国王去世

 一种微妙的情况是国王被标记为死亡。 幼稚的实现可能会错误地删除以国王为根的整个子树。 这是错误的，因为后代仍然继承。 

这个实现正确地处理了这个情况，因为死亡只会将国王添加到`dead`放。 在 DFS 遍历期间，国王在输出中被跳过，但遍历仍然继续遍历所有后代。 

### 死人有活着的孩子

 另一个重要的边缘情况发生在某人生完孩子后去世。 他们的后代仍必须按照通常的方式出现在继承顺序中。 

DFS 遍历自然可以处理这个问题。 在构建结果列表时会跳过死者，但递归仍然会处理所有子级。 这正确地保留了继承结构。 

###大量分娩手术

 高达`10^5`操作，每次出生后重复重新计算继承顺序会太慢。 

此实现通过将出生增量存储在邻接列表中来避免该问题。 每次出生仅在恒定时间内附加到列表中。 昂贵的遍历被推迟到`getInheritanceOrder`实际上是被请求的，最多发生10次。
