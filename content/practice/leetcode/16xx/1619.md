 # LeetCode 1619，删除一些元素后的数组平均值

 ## 问题理解

 问题给了我们一个整数数组`arr`并要求我们计算去除最小值后的平均值`5%`和最大的`5%`的元素。 

重要的细节是删除是基于数组的排序顺序的。 我们并不是简单地删除一个最小值和一个最大值。 相反，我们对数组进行排序并删除最低的`5%`元素和最高`5%`的元素。 

例如，如果数组长度是`20`， 然后：

-`5% of 20 = 1`- 我们删除第一个`1`排序后的元素
 - 我们还删除了最后一个`1`排序后的元素

 剩余的`18`元素用于计算平均值。 

输入数组：

 - 包含整数
 - 长度介于`20`和`1000`- 长度总是为`20`最后一个约束非常重要，因为它保证`5%`数组大小始终是整数。 在确定要删除的元素数量时，我们永远不需要担心舍入问题。 

预期输出是一个浮点数，表示剩余元素的算术平均值。 

约束已经处理了几种边缘情况：

 - 数组永远不会为空
 - 至少有一个元素将始终从每一侧删除，因为最小长度为`20`- 去除百分比计数始终准确
 - 值可能会重复多次，因此排序后我们必须按位置删除元素，而不是按值删除元素

 幼稚的实现可能会因以下原因而犯错误：

 - 仅删除最小值和最大值而不是`5%`- 忘记对数组进行排序
 - 计算平均值时使用整数除法
 - 错误地处理重复值

 ## 方法

 ### 蛮力方法

 蛮力的想法是对数组进行排序，显式创建一个仅包含中间部分的新数组，然后计算平均值。 

该算法的工作原理如下：

 1. 对数组进行排序
 2. 计算要删除的元素数量：`remove_count = len(arr) // 20`3. 创建一个新的切片数组：`trimmed = arr[remove_count : n - remove_count]`4. 计算修剪后的数组的总和
 5.除以剩余元素的数量

 这种方法是正确的，因为排序保证最小的元素首先出现，最大的元素最后出现。 

然而，这种方法使用额外的空间，因为它创建了一个新的切片数组。 虽然约束足够小，仍然可以轻松通过，但我们可以优化内存使用。 

### 最佳方法

 关键的观察是我们实际上不需要创建单独的修剪数组。 

排序后，我们已经确切地知道哪些索引属于有效的中间部分。 我们可以简单地迭代该范围并直接计算总和。 

这避免了分配额外的数组并降低了辅助空间复杂度。 

步骤变为：

 1. 对数组进行排序
 2. 计算要丢弃多少个元素
 3. 仅迭代有效的中间范围
 4. 计算总和
 5.返回平均值

 排序操作在运行时占据主导地位。

 ## 算法演练

 ### 最优算法

 1. 将数组按升序排序。 

排序是必要的，因为问题定义了最小和最大`5%`相对于排序顺序。 如果不进行排序，我们就无法知道哪些元素属于极端。 
2. 计算必须删除多少个元素。 

由于数组长度始终是`20`，我们可以计算：```
remove_count = n // 20
```这有效是因为`5% = 1/20`。 
3. 确定指标的有效范围。 

去掉最小和最大之后`5%`，其余元素位于：```
start = remove_count
end = n - remove_count
```有效索引是`[start, end)`。 
4. 计算剩余元素的总和。 

迭代有效的中间范围并累加总数。 
5. 计算平均值。 

剩余元素的数量为：```
remaining = n - 2 * remove_count
```返回：```
total / remaining
```### 为什么它有效

 排序将所有元素按升序排列。 删除第一个`remove_count`elements 恰好删除最小的`5%`，并删除最后一个`remove_count`元素恰好删除最大的`5%`。 

每个剩余元素都属于已排序数组的有效中间部分。 由于算术平均值只是总和除以元素数量，因此计算中间部分的平均值会产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def trimMean(self, arr: List[int]) -> float:
        arr.sort()

        n = len(arr)
        remove_count = n // 20

        total = 0

        for i in range(remove_count, n - remove_count):
            total += arr[i]

        remaining_count = n - 2 * remove_count

        return total / remaining_count
```实现首先按升序对数组进行排序。 这是最重要的预处理步骤，因为该问题需要删除数组的最小和最大部分。 

接下来，代码计算`remove_count`，代表有多少个元素对应`5%`数组长度。 

该解决方案不是创建单独的修剪数组，而是直接迭代有效的中间索引。 在此循环期间，它将总和累加到`total`。 

最后，代码计算两次删除后剩余的元素数量，并将总和除以该计数以得出平均值。 

该实现在 Python 中自动使用浮点除法，因为`/`运算符返回一个浮点数。 

## 解决方案```go
package main

import "sort"

func trimMean(arr []int) float64 {
	sort.Ints(arr)

	n := len(arr)
	removeCount := n / 20

	total := 0

	for i := removeCount; i < n-removeCount; i++ {
		total += arr[i]
	}

	remainingCount := n - 2*removeCount

	return float64(total) / float64(remainingCount)
}
```Go 解决方案遵循与 Python 版本完全相同的算法结构。 

一个重要的区别是 Go 需要显式转换为`float64`划分之前。 如果我们直接将两个整数相除，Go 将执行整数除法并丢失小数部分。 

使用以下方法对数组进行就地排序`sort.Ints`。 

Go 切片是类似引用的结构，因此排序直接修改原始切片，无需额外复制。

 ## 边缘情况

 一种重要的边缘情况是最小数组长度`20`。 自从`5% of 20 = 1`，该算法从每一侧恰好删除一个元素。 有缺陷的实现可能会由于不正确的百分比处理或整数舍入而意外删除零元素。 使用`n // 20`保证计数正确。 

另一个重要的边缘情况涉及重复值。 例如，最小值可能出现多次。 该问题并不要求我们删除所有出现的最小值或最大值。 它只要求我们删除最小和最大的`5%`排序后的元素。 该实现可以正确处理此问题，因为它按索引范围而不是按值比较进行修剪。 

当所有元素都相同时，会出现第三种边缘情况。 在这种情况下，删除最小和最大的`5%`仍然在各处留下相同的值。 某些实现可能会意外除以零或错误地处理边界。 我们的实现总是至少留下`90%`数组完好无损，因此分母始终为正。 

另一个微妙的边缘情况涉及均值计算期间的整数除法。 在 Go 等语言中，两个整数相除执行整数除法。 无需转换为`float64`，小数部分将丢失。 Go 实现在除法之前显式转换两个操作数以确保正确的浮点结果。
