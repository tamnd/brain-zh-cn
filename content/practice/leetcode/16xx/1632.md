[LeetCode 1632 题](https://leetcode.com/problems/rank-transform-of-a-matrix/)

 **难度：** 🔴难
 **主题：** 数组、并查集、图论、拓扑排序、排序、矩阵

 ## 解决方案

 ## 问题理解

 该问题要求我们为矩阵中的每个元素分配一个等级，同时保留行和列内的排序关系。 

对于任意两个共享同一行或同一列的元素：

 - 如果一个值较小，则其排名也必须较小。 
- 如果两个值相等，则它们的排名也必须相等。 

此外，在满足所有约束的同时，分配的等级必须尽可能小。 

输入是一个`m x n`矩阵其中：

 -`m`和`n`每个都可以大到`500`- 值可能为负数
 - 值可能重复多次

 输出是另一个相同维度的矩阵，其中每个位置包含计算的排名。 

重要的挑战是通过行和列连接的相等值必须获得相同的排名。 这会创建必须一起处理的单元组。 简单的局部比较方法会失败，因为等级依赖性可以在矩阵中传播。 

例如：```
1 2
3 4
```价值`4`必须有等级`3`, 不排名`2`，因为它大于两者`2`和`3`，以及那些已经需要排名的`2`。 

约束足够大，以至于昂贵的重复传播或图松弛方法将会超时。 解决方案必须有效地处理最多`250,000`细胞。 

一些边缘情况尤其重要：

 - 同一行或同一列中有多个相等的值
 - 通过链条间接连接的等值
 - 负数
 - 单行或单列矩阵
 - 大组重复值
 - 相同值必须共享一个等级的情况，即使它们看起来相距很远

 该问题保证存在唯一的最小有效排名。 

## 方法

 ### 蛮力方法

 暴力解决方案将重复尝试更新排名，直到满足所有行和列约束。 

一种可能的实施方式是：

 1. 将所有等级初始化为`1`2. 比较共享行或列的每对单元格
 3. 如果违反排序限制，则增加排名
 4. 重复直到没有变化发生

 这最终会收敛，因为等级只会增加并且约束是有限的。 

然而，这种方法效率极低。 每次迭代可能会扫描许多行和列关系，并且在排名稳定之前可能需要多次迭代。 

高达`250,000`细胞，重复繁殖变得过于昂贵。 

### 关键见解

 关键的观察是矩阵值应按排序顺序处理。 

假设我们已经知道所有较小值的最终排名。 然后对于当前值：

 - 其排名必须比其行或列中已存在的最大排名大一。 
- 通过行或列连接的相等值必须合并在一起并分配相同的排名。 

这自然表明：

 1. 按值对单元格进行排序
 2. 一起处理相等的值
 3. 使用并查对相连的等值单元格进行分组
 4. 跟踪已分配给每行和列的最大排名

 并查结构至关重要，因为相等的值可能通过行和列形成连通分量。 

例如：```
7 7
7 7
```所有四个单元必须具有相同的等级。 

甚至存在更微妙的情况，即平等联系是间接的。 

通过按升序处理值，我们确保在分配下一个排名之前已经解决了所有较小的依赖关系。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 1. 创建从值到包含该值的所有位置的映射。 

我们按升序处理值，因为较小的值决定较大值的最小有效排名。 
2. 维护一个名为`rank`。 

第一个`m`位置代表行排名。 

下一个`n`位置代表列排名。`rank[i]`存储该行或列中已分配的最大排名。 
3. 按排序顺序处理矩阵值。 

对于每个不同的值：

 - 收集包含该值的所有单元格。 
- 使用并查在等值单元格之间构建连接组件。 
4. 建立并查组。 

对于每个单元格`(r, c)`:

 - 治疗行`r`和列`c`作为节点。 
- 联合行节点`r`带列节点`c + m`。 

这将连接共享行或列的所有等值单元格。 
5. 按并查根对单元格进行分组。 

同一组件中的单元格必须具有相同的排名，因为它们是相等的并且通过行/列关系连接。 
6. 计算每个组件的排名。 

对于每个细胞`(r, c)`在组件中：

 - 新的排名必须超过以下两项：

 - 行的当前排名`r`- 列的当前排名`c`所以：```
new_rank = max(rank[r], rank[c + m]) + 1
```组件等级是组件中所有单元格的最大此类值。 
7. 将计算出的排名分配给组件中的每个单元格。 
8. 更新行和列排名跟踪器。 

分配等级后：

 -`rank[r] = component_rank`-`rank[c + m] = component_rank`这确保了更大的未来价值建立在正确的依赖关系之上。 

### 为什么它有效

 按升序处理值可以保证所有较小的值已经具有最终的排名。 并查可确保所有连接的等值单元被视为一个单元。 该算法始终分配与现有行和列约束一致的最小可能排名。 因为每个分配都是最小的，并且依赖项是按排序顺序处理的，所以最终排名既有效又最小。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class UnionFind:
    def __init__(self):
        self.parent = {}

    def find(self, x):
        if x != self.parent.setdefault(x, x):
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):
        self.parent[self.find(x)] = self.find(y)

class Solution:
    def matrixRankTransform(self, matrix: List[List[int]]) -> List[List[int]]:
        rows = len(matrix)
        cols = len(matrix[0])

        value_positions = defaultdict(list)

        for r in range(rows):
            for c in range(cols):
                value_positions[matrix[r][c]].append((r, c))

        answer = [[0] * cols for _ in range(rows)]

        # rank[i] for rows, rank[rows + j] for columns
        rank = [0] * (rows + cols)

        for value in sorted(value_positions):
            uf = UnionFind()

            positions = value_positions[value]

            # Build connected components
            for r, c in positions:
                uf.union(r, c + rows)

            groups = defaultdict(list)

            # Group cells by connected component
            for r, c in positions:
                root = uf.find(r)
                groups[root].append((r, c))

            updates = []

            # Compute rank for each component
            for group in groups.values():
                max_rank = 0

                for r, c in group:
                    max_rank = max(
                        max_rank,
                        rank[r],
                        rank[c + rows]
                    )

                new_rank = max_rank + 1

                for r, c in group:
                    answer[r][c] = new_rank
                    updates.append((r, c, new_rank))

            # Apply updates after processing entire value
            for r, c, new_rank in updates:
                rank[r] = new_rank
                rank[c + rows] = new_rank

        return answer
```实现首先根据矩阵位置的值对其进行分组。 这允许一起处理所有相等的值。 

这`rank`数组跟踪每行和每列的最高分配排名。 行占用索引`[0, rows-1]`，而列占据`[rows, rows+cols-1]`。 

对于每个不同的值，都会创建一个新的并查结构。 由等值单元格连接的行和列被合并在一起。 这将创建代表必须共享相同等级的单元的组件。 

构建组件后，算法通过检查最大现有行和列排名来计算每个组的最小有效排名。 

由于必须同时处理所有等值单元格，因此临时存储更新。 立即更新排名可能会错误地影响具有相同值的其他单元格。 

最后，计算出的排名被写入答案矩阵并更新行/列跟踪器。 

## 解决方案```go
package main

import (
	"sort"
)

type UnionFind struct {
	parent map[int]int
}

func NewUnionFind() *UnionFind {
	return &UnionFind{
		parent: make(map[int]int),
	}
}

func (uf *UnionFind) Find(x int) int {
	if _, exists := uf.parent[x]; !exists {
		uf.parent[x] = x
	}

	if uf.parent[x] != x {
		uf.parent[x] = uf.Find(uf.parent[x])
	}

	return uf.parent[x]
}

func (uf *UnionFind) Union(x, y int) {
	rootX := uf.Find(x)
	rootY := uf.Find(y)

	if rootX != rootY {
		uf.parent[rootX] = rootY
	}
}

func matrixRankTransform(matrix [][]int) [][]int {
	rows := len(matrix)
	cols := len(matrix[0])

	valuePositions := make(map[int][][]int)

	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			val := matrix[r][c]
			valuePositions[val] = append(valuePositions[val], []int{r, c})
		}
	}

	values := make([]int, 0, len(valuePositions))

	for val := range valuePositions {
		values = append(values, val)
	}

	sort.Ints(values)

	answer := make([][]int, rows)

	for i := range answer {
		answer[i] = make([]int, cols)
	}

	rank := make([]int, rows+cols)

	for _, val := range values {
		uf := NewUnionFind()

		positions := valuePositions[val]

		for _, pos := range positions {
			r := pos[0]
			c := pos[1]

			uf.Union(r, c+rows)
		}

		groups := make(map[int][][]int)

		for _, pos := range positions {
			r := pos[0]
			c := pos[1]

			root := uf.Find(r)
			groups[root] = append(groups[root], []int{r, c})
		}

		type Update struct {
			rank int
			row  int
			col  int
		}

		updates := []Update{}

		for _, group := range groups {
			maxRank := 0

			for _, pos := range group {
				r := pos[0]
				c := pos[1]

				if rank[r] > maxRank {
					maxRank = rank[r]
				}

				if rank[c+rows] > maxRank {
					maxRank = rank[c+rows]
				}
			}

			newRank := maxRank + 1

			for _, pos := range group {
				r := pos[0]
				c := pos[1]

				answer[r][c] = newRank

				updates = append(updates, Update{
					rank: newRank,
					row:  r,
					col:  c,
				})
			}
		}

		for _, upd := range updates {
			rank[upd.row] = upd.rank
			rank[upd.col+rows] = upd.rank
		}
	}

	return answer
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 由于Go不提供默认初始化的内置字典，因此Union-Find`Find`方法显式初始化缺失的父母。 

使用切片而不是元组进行坐标存储。 结构体用于更新跟踪，因为 Go 不支持轻量级元组语法。 

不存在整数溢出问题，因为排名永远不会超过`m + n`。

 ## 边缘情况

 ### 所有值都相等

 当每个单元格包含相同的值时，每个单元格都必须获得相同的排名。 有缺陷的实现可能会在顺序扫描行或列时错误地分配递增的排名。 并查分组通过将所有连接的等值单元格合并到一个组件中并为它们分配一个共享等级来防止这种情况发生。 

### 间接连接的相等值

 考虑：```
1 2 2
2 2 3
```一些相等的值并不直接相邻，而是通过共享的行和列连接。 仅检查直接邻居的简单实现可能会分配不一致的排名。 并查结构正确地将所有连接的等值单元格合并到同一组件中。 

### 更新排名太早

 假设几个等值单元格正在一起处理。 如果行和列的排名在每个单元格之后立即更新，则具有相同值的后续单元格可能会错误地看到膨胀的依赖性并接收太大的排名。 该实现通过临时存储更新并仅在处理当前值的所有组后应用它们来避免这种情况。
