[LeetCode 问题 1601](https://leetcode.com/problems/maximum-number-of-achievable-transfer-requests/)

 **难度：** 🔴难
 **主题：** 数组、回溯、位操作、枚举

 ## 解决方案

 ## 问题理解

 该问题要求我们在每栋大楼的员工总数保持不变的情况下，最大化可以满足的员工调动请求的数量。 每个请求都表示为一对`[from, to]`，表示员工想要从大楼搬走`from`到建筑物`to`。 挑战在于所有建筑物均已满员，因此对于我们选择批准的任何请求子集，每栋建筑物的员工净变化必须为零。 换句话说，离开建筑物的员工人数必须等于搬入建筑物的人数。 

输入包括建筑物的数量`n`和一个列表`requests`。 输出是一个整数：在保持每栋建筑人口不变的情况下可以同时满足的最大请求数。 

约束为我们提供了有关问题规模的有用信息。 和`n <= 20`和`requests.length <= 16`，我们可以考虑请求数量可能呈指数增长但不是指数增长的方法`n`。 这暗示枚举或位掩码方法可能是可行的。 

重要的边缘情况包括员工希望留在同一栋大楼的请求（这些请求总是可以实现的），以及请求形成循环的情况，允许在不违反净零约束的情况下交换多名员工。 

## 方法

 暴力方法将检查请求的所有子集。 对于每个子集，我们计算每个建筑物的净变化并检查所有变化是否为零。 如果是这样，我们会更新已满足的请求的最大计数。 虽然正确，但这种方法的最坏情况复杂度为`O(2^m * n)`在哪里`m`是请求数，在给定约束的情况下可接受`m <= 16`。 

优化的关键观察是`requests.length`很小。 我们可以使用**回溯方法**来逐步探索每个请求，决定是否将其包含在当前解决方案中。 我们动态跟踪每栋大楼的员工净变化。 如果我们达到所有净变化为零的配置，我们将更新最大计数。 这避免了重新计算每个子集的更改，并允许在某些实现中进行修剪。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^m * n) | O(2^m * n) | O(n) | 检查所有请求子集并验证净零条件 |
 | 回溯/位掩码| O(2^m * n) | O(2^m * n) | O(n) | 逐步构建有效的子集； m 小，实用 |

 ## 算法演练

 1.初始化一个数组`delta`尺寸的`n`跟踪每栋大楼员工的净变化。 
2. 定义一个递归回溯函数，将当前索引取入`requests`以及到目前为止选择的请求数量。 
3. 在每一步，我们有两个选择：要么包含当前请求，要么跳过它。 
4. 如果我们提出请求`[from, to]`, 增量`delta[to]`加 1 并减`delta[from]`1.
 5. 递归调用下一个索引的函数。 
6. 探索包含后，撤消对以下内容的更改`delta`回溯并探索跳过选项。 
7. 当索引到达末尾时`requests`，检查是否所有元素都在`delta`为零。 如果是这样，请更新最大计数。 
8. 返回探索所有子集后找到的最大计数。 

**为什么有效：** 通过探索所有子集并检查净零约束，我们确保考虑所有可能的有效请求组合。 递归回溯可确保正确维护和恢复净更改的状态，从而保证正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumRequests(self, n: int, requests: List[List[int]]) -> int:
        delta = [0] * n
        max_requests = 0
        
        def backtrack(index: int, count: int):
            nonlocal max_requests
            if index == len(requests):
                if all(d == 0 for d in delta):
                    max_requests = max(max_requests, count)
                return
            from_building, to_building = requests[index]
            
            # Include the request
            delta[from_building] -= 1
            delta[to_building] += 1
            backtrack(index + 1, count + 1)
            
            # Backtrack
            delta[from_building] += 1
            delta[to_building] -= 1
            
            # Skip the request
            backtrack(index + 1, count)
        
        backtrack(0, 0)
        return max_requests
```该实现定义了一个助手`backtrack`探索请求的每个子集的函数。 这`delta`数组跟踪每个建筑物的净变化。 对于每个请求，我们递归地尝试包含它并跳过它，更新`delta`因此。 在每条路径的末尾，我们检查所有净变化是否为零以更新最大计数。 

## 解决方案```go
func maximumRequests(n int, requests [][]int) int {
    delta := make([]int, n)
    maxRequests := 0
    
    var backtrack func(index int, count int)
    backtrack = func(index int, count int) {
        if index == len(requests) {
            valid := true
            for _, d := range delta {
                if d != 0 {
                    valid = false
                    break
                }
            }
            if valid && count > maxRequests {
                maxRequests = count
            }
            return
        }
        
        from, to := requests[index][0], requests[index][1]
        
        // Include the request
        delta[from]--
        delta[to]++
        backtrack(index+1, count+1)
        
        // Backtrack
        delta[from]++
        delta[to]--
        
        // Skip the request
        backtrack(index+1, count)
    }
    
    backtrack(0, 0)
    return maxRequests
}
```在 Go 中，我们使用切片`delta`跟踪网络变化和嵌套函数`backtrack`用于递归。 逻辑反映了 Python：对于每个请求，我们尝试包含它并跳过它，更新`delta`适当地。 Go 的切片语义需要显式回溯来恢复状态，其处理方式与 Python 类似。
