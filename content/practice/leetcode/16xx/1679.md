[LeetCode 第 1679 题](https://leetcode.com/problems/max-number-of-k-sum-pairs/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、两个指针、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们重复从数组中删除数字对，以使每个选定数字对的总和等于目标值`k`。 每次我们成功删除一对有效的操作，就算作一次操作。 我们的目标是确定在不再保留有效对之前可以执行的**最大操作数**。 

简单来说，我们想要找出可以在以下位置形成多少个不相交对：```
num1 + num2 = k
```数组中的每个元素只能使用一次，因为一旦选择了一对，两个数字都会从数组中删除。 这意味着我们必须小心，不要意外地重用值。 

输入包括：

 -`nums`，一个整数数组，包含我们可以配对的值。 
-`k`，每个有效对必须相等的目标总和。 

预期输出是一个整数，表示可能的最大配对删除操作数。 

约束条件很重要：

 -`nums.length <= 10^5`-`nums[i] <= 10^9`-`k <= 10^9`由于数组最多可以包含十万个元素，因此低效的嵌套循环解决方案将无法很好地扩展。 大值范围为`nums[i]`还表明使用固定大小的数组进行计数是不切实际的。 相反，我们需要一种能够有效跟踪先前看到的数字的方法，这使得哈希图成为一个很好的候选者。 

一些边缘情况值得尽早识别。 该数组可能根本不包含有效的对，在这种情况下答案是`0`。 可能存在重复的值，例如多个相同的数字构成不同的有效对。 数字与自身配对的情况，例如`k = 6`并且出现两次`3`，需要仔细计数，这样我们就不会重复使用同一元素两次。 该问题保证输入非空且包含正整数，因此我们不需要处理无效输入或负长度。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是通过检查每个可能的数字组合来重复搜索有效对。 

对于每个元素，我们可以扫描数组的其余部分，寻找总和等于的另一个元素`k`。 一旦找到一对，我们就删除这两个数字并继续在剩余元素中搜索。 

这种方法是正确的，因为它显式地检查每个可能的对并一次删除一个有效的匹配。 最终，没有有效的对剩下，删除的总数给出了答案。 

然而，这种方法效率低下。 在最坏的情况下，我们会比较几乎每一对元素，导致时间复杂度呈二次方。 和`10^5`元素，一个`O(n²)`算法变得太慢。 

### 最优方法，补集的哈希图

 关键的观察是对于任何数字`x`，可以形成有效对的唯一值是：```
k - x
```我们可以维护一个哈希映射来存储到目前为止我们看到的不匹配数字的数量，而不是重复搜索整个数组。 

当我们遍历数组时：

 - 对于当前号码`num`,计算其补数`k - num`。 
- 如果补码已经存在于我们的哈希图中，我们立即形成一对并减少存储频率。 
- 否则，我们存储当前号码以供将来可能的匹配。 

这是有效的，因为每个元素都被处理一次，并且每个有效对都会尽快形成。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复检查所有可能的对 |
 | 最佳 | O(n) | O(n) | 使用哈希映射来跟踪不匹配的补集 |

 ## 算法演练

 1. 创建一个名为的哈希图`frequency`跟踪我们遇到的不匹配的数字。 
2. 初始化变量`operations = 0`计算成功的配对删除。 
3. 迭代每个数字`num`在`nums`。 
4. 对于当前数字，计算补码：```
complement = k - num
```这是唯一可以与以下数字形成有效对的数字`num`。 
5. 检查哈希图中是否存在补码并且计数是否为正。 

- 如果存在，我们就找到了有效的对。 
- 增量`operations`。 
- 减少补码计数，因为现在已经使用了一次。 
6. 如果不存在补数，则通过增加当前数字的频率计数来将当前数字存储在哈希图中。 
7. 继续，直到处理完所有元素。 
8. 返回`operations`。 

我们使用哈希图的原因是它提供了平均值`O(1)`查找和插入时间。 我们无需重复扫描数组来查找匹配值，而是立即知道补码是否可用。 

### 为什么它有效

 该算法保持了一个重要的不变量：哈希映射仅包含迄今为止见过的**不匹配的数字**。 

每当我们遇到一个数字时，我们首先尝试将它与之前未匹配的补码进行匹配。 如果存在补集，则立即形成配对始终是最佳选择，因为延迟匹配无法在以后产生更多配对。 由于每个数字最多参与一对，因此贪婪地匹配有效补集可以保证操作的最大数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxOperations(self, nums: List[int], k: int) -> int:
        frequency = {}
        operations = 0

        for num in nums:
            complement = k - num

            if frequency.get(complement, 0) > 0:
                operations += 1
                frequency[complement] -= 1
            else:
                frequency[num] = frequency.get(num, 0) + 1

        return operations
```实现直接遵循算法。 

我们首先创建一个名为`frequency`。 该字典存储已出现但尚未配对的数字。 键是数字本身，值是当前存在多少个不匹配的副本。 

对于每个数字`nums`，我们使用以下方法计算补集`k - num`。 然后我们检查字典中是否已经存在该补语。 

如果它存在且计数为正，我们立即形成一对。 我们增加操作计数器并减少存储的补码计数，因为现在已经消耗了一个实例。 

如果补数不存在，我们将当前数字存储在字典中以供将来匹配。 

遍历结束时，操作计数器包含有效对删除的最大数量。 

## 解决方案```go
func maxOperations(nums []int, k int) int {
	frequency := make(map[int]int)
	operations := 0

	for _, num := range nums {
		complement := k - num

		if frequency[complement] > 0 {
			operations++
			frequency[complement]--
		} else {
			frequency[num]++
		}
	}

	return operations
}
```Go 实现与 Python 版本几乎相同。 

我们不使用 Python 字典，而是使用`map[int]int`存储不匹配数字的频率。 Go 映射返回缺失键的零值，这简化了补码检查，因为`frequency[complement]`自动评估为`0`当缺席时。 

关于整数溢出没有特别的担忧，因为这些约束完全适合 Go 的范围`int`类型。 空切片和 nil 切片自然由循环处理，尽管该问题保证至少有一个元素。

 ## 边缘情况

 ### 没有有效对的数组

 当两个数字之和不等于时，就会出现一个重要的情况`k`， 例如：```
nums = [1,2,3], k = 10
```有缺陷的实现可能会意外地计算部分匹配或假设每个数字都构成一对。 我们的实现可以安全地处理这个问题，因为不匹配的数字只是在哈希映射中累积，并且操作计数仍然存在`0`。 

### 与自身配对的数字

 当`num * 2 == k`，一个数字必须与另一个相同的值配对。 例如：```
nums = [3,3,3], k = 6
```只有一对是可能的，因为一个`3`仍然未使用。 如果算法重复使用相同的事件两次，这种情况很容易引入错误。 我们的频率图通过在消耗匹配时减少计数来避免这个问题。 

### 匹配值的奇数

 考虑：```
nums = [2,2,2,2,2], k = 4
```尽管理论上每个值都可以配对，但奇数计数会留下一个不匹配的元素。 正确答案是`2`， 不是`2.5`或者`3`。 由于该算法恰好删除了每个成功匹配的一个补码，因此剩余的不匹配值仍然正确地未使用。 

### 大量重复的输入

 随着数组逼近`10^5`元素，嵌套循环方法变得异常缓慢。 例如，包含数千个重复数字的输入将在暴力实现中导致二次行为。 哈希映射方法仍然对每个元素处理一次，确保解决方案在规模上保持高效。
