[LeetCode 问题 1656](https://leetcode.com/problems/design-an-ordered-stream/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、设计、数据流

 ## 解决方案

 ## 问题理解

 这个问题要求我们模拟一个数据流，其中每个元素以任意顺序以唯一 ID 到达。 每个元素由一个整数组成`idKey`（之间`1`和`n`) 和一个字符串`value`。 目标是设计一个流，在每次插入后，返回可以从最后一个输出点开始按顺序输出的**最大连续值块**。 随着时间的推移，所有值都应按递增顺序返回`idKey`。 

输入由一系列插入组成。 每次插入后，输出是表示下一个有序值块的字符串列表。 如果插入的`idKey`不继续当前序列，输出为空列表。 

约束条件澄清了`n`相对较小（最多 1000 个），每个`value`长度为5，ID是唯一的。 每次致电`insert`保证有一个唯一的ID并且会有准确的`n`插入。 这保证了流最终将包含所有值，因此我们不需要处理丢失或重复的 ID。 

边缘情况包括首先插入第一个或最后一个 ID、插入无序序列以及接收在返回下一个块之前留下间隙的 ID。 在每次插入时对整个流进行排序的简单实现会不必要地缓慢。 

## 方法

 **暴力方法**将存储所有插入的`(idKey, value)`映射或数组中的对，并且在每个`insert`，对所有键进行排序并返回从最后一个输出 ID 开始的下一个连续块。 这是可行的，因为排序保证了顺序，但对每个插入进行排序效率很低。 

**最佳方法**利用了 ID 是整数的事实`[1, n]`。 我们可以预先分配一个大小的数组`n + 1`（基于 1 的索引）将值直接存储在其相应的索引处。 我们还维护一个指针`ptr`跟踪尚未输出的最小ID。 插入一个值后，我们检查是否`ptr`指向一个非空值。 如果是这样，我们收集从以下位置开始的所有连续非空值`ptr`成块并前进`ptr`因此。 这种方法避免了排序，并使用直接数组访问来进行常数时间插入和顺序收集。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次插入 O(n log n) | O(n) | 存储所有值，在每次插入时对键进行排序 |
 | 最佳 | O(1) 每个插入分摊 | O(n) | 具有指针跟踪连续输出的基于数组的存储 |

 ## 算法演练

 1.初始化一个数组`stream`尺寸的`n + 1`和`None`（或 Go 中的空字符串）用于保存与 ID 对应的索引处的值。 
2. 初始化一个指针`ptr = 1`跟踪下一个要输出的 ID。 
3. 对于每个`insert(idKey, value)`致电：

 1. 商店`value`在`stream[idKey]`。 
2.初始化一个空列表`chunk`。 
3.同时`ptr <= n`和`stream[ptr]`不是`None`：

 1. 追加`stream[ptr]`到`chunk`。 
2. 增量`ptr`。 
4. 返回`chunk`。 

**为什么有效**：指针`ptr`确保我们始终从最小的未返回 ID 开始收集输出。 将值存储在索引为的数组中`idKey`确保 O(1) 访问，并且 while 循环按顺序收集连续的值。 这保证了每个返回的块都是最大的并且按 ID 顺序是连续的。 

## Python 解决方案```python
from typing import List

class OrderedStream:

    def __init__(self, n: int):
        self.stream = [None] * (n + 1)  # 1-based indexing
        self.ptr = 1

    def insert(self, idKey: int, value: str) -> List[str]:
        self.stream[idKey] = value
        chunk = []
        while self.ptr < len(self.stream) and self.stream[self.ptr] is not None:
            chunk.append(self.stream[self.ptr])
            self.ptr += 1
        return chunk
```**解释**：我们预先分配一个数组`stream`有尺寸`n + 1`直接存储值`idKey`。 这`ptr`指向尚未输出的最小ID。 在每次插入时，如果`ptr`有一个值，我们收集从以下位置开始的所有连续值`ptr`。 这有效地实现了最大可能的块逻辑。 

## 解决方案```go
type OrderedStream struct {
	stream []string
	ptr    int
}

func Constructor(n int) OrderedStream {
	return OrderedStream{
		stream: make([]string, n+1), // 1-based indexing
		ptr:    1,
	}
}

func (this *OrderedStream) Insert(idKey int, value string) []string {
	this.stream[idKey] = value
	chunk := []string{}
	for this.ptr < len(this.stream) && this.stream[this.ptr] != "" {
		chunk = append(chunk, this.stream[this.ptr])
		this.ptr++
	}
	return chunk
}

/**
 * Your OrderedStream object will be instantiated and called as such:
 * obj := Constructor(n);
 * param_1 := obj.Insert(idKey,value);
 */
```**Go 特定注释**：我们使用用空字符串初始化的字符串切片。 检查`""`取代Python的`None`。 切片追加处理动态块构建。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(1) 按插入分摊 | 每个元素都被访问一次`ptr`，n 次插入的总 O(n) |
 | 空间| O(n) | 大小为 n+1 的数组，用于存储所有值 |

 因为`ptr`仅向前移动，所有插入的总时间是线性的，使得每次插入分摊为 O(1)。

 ## 边缘情况

 **边缘情况 1**：以相反的顺序插入 ID。 这可能会导致假设立即输出的幼稚实现失败。 我们的实现通过返回空块来处理它，直到序列可以从`ptr`。 

**边缘情况 2**：首先插入第一个或最后一个 ID。 如果`idKey = n`首先到达，在前面的 ID 到达之前不会输出任何值。 使用`ptr`确保我们只输出从第一个缺失 ID 开始的连续块。 

**边缘情况 3**：流式传输`n = 1`。 最小输入大小可能会触发相差一错误。 我们从 1 开始的数组和指针自然地处理这个问题，产生一个输出。 

**边缘情况 4**：所有插入均以不连续的随机顺序到达。 该数组允许 O(1) 插入和块形成，确保性能不会因随机输入而降低。 

该解决方案对于约束内的所有输入都是稳健的。
