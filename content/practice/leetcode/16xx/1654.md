[LeetCode 问题 1654](https://leetcode.com/problems/minimum-jumps-to-reach-home/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、广度优先搜索

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到一个 bug 从某个位置移动所需的最小跳跃次数`0`定位`x`在一维数轴上。 

该错误遵循几个移动规则：

 - 它可能会准确地向前跳跃`a`单位。 
- 它可能会精确地向后跳`b`单位。 
- 它不能执行两次连续的向后跳转。 
- 它可能永远不会降落在禁止位置。 
- 它可能永远不会移动到负位置。 

目标不仅仅是确定目标是否可达，而是计算达到目标所需的最小跳跃次数。 

输入包括：

 -`forbidden`，封锁位置的数组。 
-`a`，固定的向前跳跃距离。 
-`b`，固定向后跳跃距离。 
-`x`，目标位置。 

限制相对较小：

 - 仓位限制在2000左右。 
- 最多存在 1000 个禁止位置。 

这些约束强烈表明图遍历方法是可行的。 每个可达位置都可以看成一个节点，每个合法的跳跃可以看成一条边。 

该问题的一个微妙方面是对连续向后跳跃的限制。 这意味着状态不仅仅由当前位置决定。 我们还必须知道之前的举动是否落后。 对同一职位的两次访问可能代表不同的有效未来可能性，具体取决于达到该职位的方式。 

另一个重要的细节是该错误可能会超出目标。 一个幼稚的实现，限制移动到小于或等于的位置`x`在超出范围的有效情况下会失败`x`在向后跳到目标之前是必要的。 

关键的边缘情况包括：

 - 目标可能已经无法到达，因为所有有用的路径都被阻止。 
- 最佳路径可能需要超调`x`。 
- 必须正确处理以不同的先前跳跃方向重新访问同一位置。 
- 必须避免无限探索，因为向前跳跃可以无限期地继续。 

该问题保证了`x`本身并没有被禁止，这稍微简化了实现。 

## 方法

 ### 蛮力方法

 强力解决方案将从位置开始递归地探索每个可能的有效跳跃序列`0`。 

在每个位置，算法可以：

 - 向前跳跃`a`- 向后跳`b`，如果之前的移动没有向后移动

 递归将继续直到：

 - 目标`x`已达到
 - 路径无效

 这种方法是正确的，因为它探索了所有合法的跳转序列。 然而，这在计算上是不可行的，因为可能的路径数量呈指数增长。 如果没有仔细的修剪，相同的状态会被反复访问，并且向前跳跃可以无限期地继续。 

即使添加记忆也是不够的，除非状态同时包含以下两者：

 - 当前位置
 - 上一次跳跃是否向后

 此外，我们必须施加最大探索边界以防止无限搜索。 

### 最优方法，广度优先搜索

 该问题自然映射到未加权的最短路径问题。 

每个有效状态包括：

 - 当前位置
 - 上一次跳跃是否向后

 每次跳跃只花费一次移动，因此广度优先搜索（BFS）保证我们第一次到达目标时，就找到了最少的跳跃次数。 

关键的见解是 BFS 逐级探索状态：

 - 1次跳跃即可到达所有状态
 - 然后所有状态都可以通过 2 次跳跃到达
 - 等等

 这完全符合最小化跳跃的要求。 

我们还维护一个包含以下两者的访问集：

 - 位置
 - 先前的移动方向

 这可以防止重新访问相同的状态，同时仍然允许在不同的运动条件下重新访问相同的位置。 

最后，我们建立了探索的实际上限。 由于所有值最多为 2000，因此有一个限制`6000`安全地覆盖所有有意义的可达状态，而不会冒无限扩展的风险。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 递归探索所有可能的跳转序列 |
 | 最优 BFS | O(M)| O(M)| BFS 在可达状态上，其中 M 是有界搜索空间 |

 ## 算法演练

 1. 转换`forbidden`数组转换为哈希集。 

遍历过程中频繁发生成员资格检查。 哈希集允许在确定位置是否被阻止时进行恒定时间查找。 
2. 定义BFS状态。 

每个状态包含：

 - 当前位置
 - 先前的动作是否向后

 这种区别是必要的，因为连续两次向后跳转是被禁止的。 
3. 选择一个安全的上限。 

搜索空间必须是有限的。 常见的安全界限是：```
upper_bound = max(x, max(forbidden)) + a + b + 2000
```许多实现简单地使用`6000`，在给定约束的情况下这已经足够了。 
4. 初始化BFS队列。 

开始于：

 - 位置`0`- 上一步没有向后移动
 - 跳跃计数`0`5. 初始化访问集。 

标记`(0, False)`正如访问过的那样。 

布尔值表示前一步是否向后移动。 
6. 逐级处理状态。 

重复从 BFS 队列中出列状态。 

如果当前位置等于`x`，返回当前的跳转计数。 
7. 尝试向前跳跃。 

计算：```
next_forward = position + a
```如果满足以下条件，则向前跳跃有效：

 - 不超过上限
 - 不禁止
 - 之前没有访问过该状态

 将新状态添加到队列中：

 - 位置`next_forward`- 上一步没有向后移动
 8.尝试向后跳跃。 

仅当前一移动未向后移动时才允许向后移动。 

计算：```
next_backward = position - b
```如果满足以下条件，则向后跳转有效：

 - 位置非负
 - 该位置不被禁止
 - 之前没有访问过该状态

 添加新状态：

 - 位置`next_backward`- 之前的动作是向后的
 9. 继续，直到队列变空。 

如果 BFS 完成但未到达`x`， 返回`-1`。 

### 为什么它有效

 BFS 保证未加权图中的最短路径发现。 每一次合法的跳跃都对应于一条具有相同成本的边。 由于 BFS 探索了所有可达的状态`k`在探索可到达的状态之前跳转`k + 1`跳跃，我们第一次到达`x`必须代表最小跳跃次数。 

访问集可以防止无限循环和冗余探索，而附加的向后状态正确地执行禁止连续向后跳转的规则。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def minimumJumps(self, forbidden: List[int], a: int, b: int, x: int) -> int:
        forbidden_set = set(forbidden)

        upper_bound = 6000

        queue = deque([(0, False, 0)])
        visited = {(0, False)}

        while queue:
            position, last_backward, jumps = queue.popleft()

            if position == x:
                return jumps

            forward_position = position + a

            if (
                forward_position <= upper_bound
                and forward_position not in forbidden_set
                and (forward_position, False) not in visited
            ):
                visited.add((forward_position, False))
                queue.append((forward_position, False, jumps + 1))

            backward_position = position - b

            if (
                not last_backward
                and backward_position >= 0
                and backward_position not in forbidden_set
                and (backward_position, True) not in visited
            ):
                visited.add((backward_position, True))
                queue.append((backward_position, True, jumps + 1))

        return -1
```实现首先将禁止位置转换为一组以进行有效查找。 

BFS 队列存储包含以下内容的元组：

 - 当前位置
 - 先前的动作是否向后
 - 到目前为止的跳跃次数

 的`visited`set 还存储位置和向后状态。 这是至关重要的，因为在不同的运动条件下到达相同的位置会产生不同的未来可能性。 

在 BFS 循环内，算法首先检查当前位置是否等于目标位置。 

始终考虑向前跳跃。 如果有效，则将其添加到队列中`last_backward = False`。 

仅当前一步未向后移动时才考虑向后跳跃。 这直接强制针对连续向后跳转的问题约束。 

如果 BFS 穷尽所有可达状态仍未到达目标，则函数返回`-1`。 

## 解决方案```go
package main

import "container/list"

type State struct {
	position     int
	lastBackward bool
	jumps        int
}

type VisitState struct {
	position     int
	lastBackward bool
}

func minimumJumps(forbidden []int, a int, b int, x int) int {
	forbiddenSet := make(map[int]bool)

	for _, pos := range forbidden {
		forbiddenSet[pos] = true
	}

	upperBound := 6000

	queue := list.New()
	queue.PushBack(State{0, false, 0})

	visited := make(map[VisitState]bool)
	visited[VisitState{0, false}] = true

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		current := front.Value.(State)

		position := current.position
		lastBackward := current.lastBackward
		jumps := current.jumps

		if position == x {
			return jumps
		}

		forwardPosition := position + a

		for forwardPosition <= upperBound &&
			!forbiddenSet[forwardPosition] &&
			!visited[VisitState{forwardPosition, false}] {

			visited[VisitState{forwardPosition, false}] = true
			queue.PushBack(State{forwardPosition, false, jumps + 1})
			break
		}

		backwardPosition := position - b

		if !lastBackward &&
			backwardPosition >= 0 &&
			!forbiddenSet[backwardPosition] &&
			!visited[VisitState{backwardPosition, true}] {

			visited[VisitState{backwardPosition, true}] = true
			queue.PushBack(State{backwardPosition, true, jumps + 1})
		}
	}

	return -1
}
```Go 解决方案遵循与 Python 实现相同的 BFS 逻辑。 

由于 Go 没有提供与 Python 等效的内置双端队列结构`collections.deque`，实现使用`container/list`作为队列。 

自定义结构用于：

 - BFS状态存储
 - 访问状态跟踪

 Go 映射用于模拟禁止位置和访问状态的哈希集。 

与 Python 元组不同，Go 需要显式的结构定义来表示哈希映射中的复合键。

 ## 边缘情况

 当目标是`0`。 由于错误已经从位置开始`0`，答案应该立即是`0`不执行任何 BFS 扩展。 该实现自然会处理这个问题，因为在生成新的移动之前会根据目标检查初始队列状态。 

另一个棘手的边缘情况涉及超出目标。 一个幼稚的解决方案可能会将探索限制在小于或等于`x`，但有效的路径有时需要经过目的地然后向后跳跃。 该实现通过允许探索达到安全上限而不是停止在目标来避免此错误。 

一个特别微妙的边缘情况是由于对连续向后跳跃的限制而产生的。 假设向后移动后到达某个位置。 禁止将来从该状态向后移动。 如果访问的结构仅跟踪位置，则算法可能会错误地修剪有效路径。 该实现通过存储位置以及上一步是否向后移动来解决这个问题。 

另一个重要场景涉及无限探索。 由于向前跳跃可以无限地继续，因此无边界的 BFS 在某些不可达的情况下永远不会终止。 该实现使用固定上限`6000`，这在给定的约束下是足够的并保证终止。
