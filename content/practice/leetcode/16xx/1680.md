[LeetCode Problem 1680](https://leetcode.com/problems/concatenation-of-consecutive-binary-numbers/)

 **难度：** 🟡 中等
 **主题：** 数学、位操作、模拟

 ## 解决方案

 ## 问题理解

 The problem asks us to build a very large binary number by concatenating the binary representations of every integer from`1`通过`n`，按顺序，然后返回其十进制值模`10^9 + 7`。 

例如，如果`n = 3`：

 -`1`二进制是`"1"`-`2`二进制是`"10"`-`3`二进制是`"11"`连接它们会产生：```
"1" + "10" + "11" = "11011"
```二进制字符串`"11011"`等于`27`为十进制，所以答案是`27`。 

重要的细节是我们没有被要求返回二进制字符串本身。 相反，我们必须有效地计算它的十进制值。 

约束条件`1 <= n <= 10^5`很关键。 从字面上构建二进制字符串的简单实现最终将创建一个包含数十万个字符的字符串。 将巨大的字符串转换回整数也将是昂贵且不必要的。 

该问题保证了`n`总是至少`1`，所以我们不需要处理空输入情况。 然而，仍然存在重要的实施问题：

 - 连接值增长得非常快，因此整数溢出成为具有固定整数大小的语言中的一个问题。 
- 构造完整的二进制字符串会浪费内存。 
- 我们必须应用模数`10^9 + 7`计算过程中连续进行。 

关键的挑战是找到一种在数学上模拟二进制连接的方法，而无需实际构建巨大的二进制字符串。 

## 方法

 ### 蛮力方法

 最直接的解决办法是：

 1. 将每个数字转换为`1`到`n`成二进制。 
2. 将每个二进制字符串附加到不断增长的结果字符串中。 
3. 将最终的二进制字符串转换为十进制整数。 
4. 返回取模后的值`10^9 + 7`。 

这种方法在概念上很简单，因为它从字面上遵循问题陈述。 

例如，如果`n = 5`：```
1  -> "1"
2  -> "10"
3  -> "11"
4  -> "100"
5  -> "101"

Concatenated:
"11011100101"
```构建完整的字符串后，我们可以将其解析为二进制整数。 

问题是效率。 二进制总长度大致增长如下：$$O(n \log n)$$为了`n = 100000`，生成的二进制字符串变得非常大。 字符串连接和大整数转换成为昂贵的操作。 

尽管这在某些具有优化大整数的高级语言中可能几乎不起作用，但它不是预期的解决方案，并且在内存和运行时效率都很低。 

### 最佳方法

 关键的观察是可以使用位移位来模拟连接二进制数。 

假设我们当前的累计值为：```
result
```我们想附加一些数字的二进制表示`x`。 

附加二进制数字相当于：

 1. 转变`result`剩下的位数`x`2.添加`x`数学上：$$result = (result \ll bits) + x$$例如：```
result = binary "11011" = 27
x = binary "100" = 4
```追加`"100"`方法：```
"11011" -> "11011100"
```左移 3 位：```
27 << 3 = 216
```然后添加`4`：```
216 + 4 = 220
```二进制的`220`：```
11011100
```正是我们想要的。 

剩下的挑战是确定每个数字需要多少位。 

每当一个数字变成 2 的幂时，它就会获得一个新的二进制数字：```
1   -> 1 bit
2   -> 2 bits
4   -> 3 bits
8   -> 4 bits
16  -> 5 bits
```所以每当`x`是 2 的幂，我们增加位长度计数器。 

这提供了具有恒定额外空间的优雅线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n log n) | O(n log n) | 显式构建整个二进制字符串 |
 | 最佳 | O(n) | O(1) | O(1) | 使用位移来模拟串联 |

 ## 算法演练

 1. 初始化变量`result = 0`。 

该变量存储到目前为止处理的串联二进制序列的十进制值。 
2. 初始化`bit_length = 0`。 

这跟踪当前数字需要多少个二进制数字。 
3. 迭代所有整数`num`从`1`到`n`。 

对于每个数字，我们将其二进制表示形式附加到累积结果中。 
4. 检查是否`num`是二的幂。 

一个数是 2 的幂，如果：$$num \& (num - 1) = 0$$这是可行的，因为二的幂恰好包含二进制中的一组位。 
5.如果`num`是 2 的幂，增量`bit_length`。 

这意味着我们现在需要一个额外的二进制数字来表示该范围内的所有数字。 
6. 转变`result`留下来`bit_length`。 

左移会创建足够的空二进制位置来附加新数字。 
7. 添加`num`到移位后的值。 

这有效地连接了二进制数字`num`。 
8. 应用模数`10^9 + 7`。 

这可以防止溢出并保持数量易于管理。 
9.处理完所有数字后，返回`result`。 

### 为什么它有效

 在每次迭代中，`result`存储由以下形式连接的二进制字符串的精确十进制值`1`通过`num - 1`。 

加工时`num`，左移其位长度会创建足够的空二进制位置来附加新的二进制数字。 添加`num`用正确的位填充这些位置。 

因为这个不变量在每一步都成立，所以最终值是完整连接的二进制序列的十进制表示。 

## Python 解决方案```python
class Solution:
    def concatenatedBinary(self, n: int) -> int:
        MOD = 10**9 + 7
        
        result = 0
        bit_length = 0
        
        for num in range(1, n + 1):
            if (num & (num - 1)) == 0:
                bit_length += 1
            
            result = ((result << bit_length) + num) % MOD
        
        return result
```实现首先定义模常数`10^9 + 7`，因为结果可能会变得非常大。 

变量`result`存储到目前为止处理的连接二进制序列的十进制值。 

变量`bit_length`跟踪需要多少位来表示当前数字。 该代码仅在当前数字是 2 的幂时才更新它，而不是通过对数或字符串转换来重新计算它。 

在循环内部，条件：```python
(num & (num - 1)) == 0
```检查是否`num`是二的幂。 如果是，则二进制表示长度增加一。 

核心操作是：```python
result = ((result << bit_length) + num) % MOD
```左移为新的二进制数字创建空间，并添加`num`附加这些数字。 

每次更新后立即应用模数以避免较大的中间值。 

## 解决方案```go
func concatenatedBinary(n int) int {
    const MOD int = 1000000007

    result := 0
    bitLength := 0

    for num := 1; num <= n; num++ {
        if (num & (num - 1)) == 0 {
            bitLength++
        }

        result = ((result << bitLength) + num) % MOD
    }

    return result
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

Go 中的一个重要考虑因素是整数溢出。 由于中间值可能会变大，因此在每次迭代期间应用模是至关重要的。 

Go 整数是固定宽度的，与 Python 的任意精度整数不同。 然而，因为我们减少模数`10^9 + 7`在每次操作之后，标准整数算术对于这个问题仍然是安全的。

 ## 边缘情况

 一个重要的边缘情况是尽可能最小的输入，`n = 1`。 在这种情况下，算法仅处理单个数字。 实现正确初始化`bit_length`到`1`当遇到二的一次方并返回时`1`第一次迭代之后立即。 

另一种关键的边缘情况发生在 2 的幂处，例如`2`,`4`,`8`， 和`16`。 与之前的数字相比，这些数字需要额外一位二进制数字。 忘记更新这些边界处的位长度会产生不正确的串联结果，因为左移不会为附加位创建足够的空间。 该实现使用二次方检查正确处理此问题：```
(num & (num - 1)) == 0
```第三个重要的边缘情况涉及非常大的值`n`，特别是在上约束附近`100000`。 连接的二进制数变得非常大，远远超过标准整数大小。 构造实际二进制字符串的简单解决方案可能会消耗过多的内存和运行时间。 此实现通过仅维护当前模值并且从不存储完整的二进制表示来完全避免这种情况。 

另一个微妙的边缘情况是 Go 等固定宽度语言中的整数溢出。 重复移位和加法很容易超出 32 位整数限制。 在每次迭代期间应用模可以保持中间值有界并确保整个计算的正确性。
