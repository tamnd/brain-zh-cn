[LeetCode 问题 1627](https://leetcode.com/problems/graph-connectivity-with-threshold/)

 **难度：** 🔴难
 **主题：** 数组、数学、并查集、数论

 ## 解决方案

 ## 问题理解

 问题给了我们`n`城市标记为`1`到`n`。 如果两个城市的公约数**严格大于**给定值，则两个城市直接相连`threshold`。 

例如，如果`threshold = 2`，然后是城市`6`和`9`直接连接，因为它们共享除数`3`， 和`3 > 2`。 然而，城市`4`和`6`不直接相连，因为它们的最大共享因子大于`1`是`2`，**不严格大于**`2`。 

关键细节是，问题不仅仅问两个城市是否**直接相连**，而是问它们是**直接相连**还是间接**。 这意味着我们正在寻找无向图中的连通性。 如果城市`A`连接到城市`B`，和城市`B`连接到城市`C`， 然后`A`和`C`即使它们本身不共享有效的除数，也被认为是连接的。 

输入由三部分组成：

 -`n`，代表城市数量。 
-`threshold`，它确定哪些除数对于创建道路有效。 
-`queries`，其中每个查询`[a, b]`询问是否城市`a`和城市`b`属于同一个连通分量。 

输出是一个布尔数组，其中每个条目对应一个查询。 如果两个城市通过任何路径连接，我们返回`true`; 否则，我们返回`false`。 

约束对于选择算法非常重要：

 -`n <= 10^4`-`queries.length <= 10^5`比较每对城市的简单图表结构需要`O(n²)`比较，并检查每对的除数会使速度变得更慢。 由于查询可以到达`100,000`，我们需要一种有效地预处理连接并快速回答每个查询的方法。 

一些边缘情况立即脱颖而出：

 - 当`threshold = 0`, 每个数都有除数`1`，并且自从`1 > 0`，所有城市都连接起来。 
- 什么时候`threshold = n`，除数不能大于`n`，意味着不存在道路。 
- 城市`1`行为不同，因为它只有除数`1`，所以它经常变得孤立，除非`threshold = 0`。 
- 可能会出现多个相同的查询，并且查询是对称的，意味着`[a, b]`相当于`[b, a]`。 

## 方法

 ### 蛮力方法

 最直接的方法是显式构建图。 

对于每对城市`(x, y)`，我们计算它们的最大公约数（GCD）。 如果`gcd(x, y) > threshold`，我们在它们之间添加一条边。 构建图后，我们使用图遍历（例如 BFS 或 DFS）来回答每个查询，以检查两个城市是否相连。 

这是有效的，因为图形定义与问题陈述完全匹配。 每个有效对都接收一条边，连接查询只是图可达性问题。 

然而，这种方法太慢了。 

有`O(n²)`城市对。 对于每一对，计算 GCD 成本`O(log n)`。 那么，对于每个查询，执行 BFS 或 DFS 可能会花费`O(n + e)`。 

和`n = 10^4`， 一个`O(n²)`图构造大约变为`10^8`运营，这已经太昂贵了。 

### 最佳方法，除数倍数并查

 关键的观察是我们**不需要**需要比较每一对城市。 

假设有一个除数`d > threshold`存在。 任何可以被以下整除的城市`d`直接连接，因为它们共享除数`d`。 

例如：

 - 如果`d = 3`， 然后`3, 6, 9, 12...`应该都属于同一个连接组件。 
- 我们可以连接所有的倍数，而不是检查每一对`d`。 

这类似于**埃拉托色尼筛**的想法。 对于每个除数`d`从`threshold + 1`到`n`，我们联合所有的倍数`d`。 

例如，当`d = 4`：

- 连接`4`和`8`- 连接`4`和`12`- 连接`4`和`16`所有倍数都成为同一连通分量的一部分。 

为了有效地维护连接的组件，我们使用 **Union-Find（不相交集并集，DSU）** 结构。 

统查支持：

 -`union(a, b)`合并组件
 -`find(x)`确定组件代表

 预处理后，回答每个查询变得简单：

 两个城市是相连的，如果：```
find(a) == find(b)
```这将昂贵的图形遍历转变为几乎恒定时间的查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² log n + q(n + e)) | O(n² log n + q(n + e)) | O(n²) | 显式图构建和遍历 |
 | 最佳| O(n log log n + qα(n)) | O(n log log n + qα(n)) | O(n) | 除数倍数的并查找 |

 这里，`α(n)`是阿克曼反函数，在实践中它实际上是常数。 

## 算法演练

 ### 第 1 步：初始化并查

 创建一个父数组，其中每个城市最初属于自己的集合。 

例如：```
parent = [0,1,2,3,4,5,6]
```每个节点开始断开连接。 

我们还使用**路径压缩**，因此重复查找变得非常快。 

### 步骤 2：迭代有效除数

 循环自：```
threshold + 1
```到：```
n
```只有严格大于阈值的除数才重要。 

### 步骤 3：连接每个除数的倍数

 对于每个除数`d`，连接所有倍数：```
d, 2d, 3d, 4d...
```我们反复联合：```
union(d, multiple)
```例如：

 如果：```
n = 12
threshold = 2
```对于除数`3`:```
union(3,6)
union(3,9)
union(3,12)
```对于除数`4`:```
union(4,8)
union(4,12)
```这保证了每个数字共享除数`d`最终位于同一个组件内。 

### 第 4 步：回答问题

 对于每个查询`[a, b]`:

 1. 寻找代表`a`2. 寻找代表`b`3.比较它们

 如果代表匹配：```
True
```否则：```
False
```### 为什么它有效

 该算法之所以有效，是因为每条有效道路都因某个除数而存在`d > threshold`。 

通过迭代每个这样的除数并将其所有倍数合并，我们保证任何直接连接的城市都被合并到同一个组件中。 由于 Union-Find 保留了传递连通性，因此间接连接的城市也最终位于同一集合中。 

因此，两个城市是相连的当且仅当它们的代表是平等的。 

## Python 解决方案```python
from typing import List

class Solution:
    def areConnected(
        self,
        n: int,
        threshold: int,
        queries: List[List[int]]
    ) -> List[bool]:

        parent = list(range(n + 1))

        def find(x: int) -> int:
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]

        def union(a: int, b: int) -> None:
            root_a = find(a)
            root_b = find(b)

            if root_a != root_b:
                parent[root_b] = root_a

        # Connect multiples of each valid divisor
        for divisor in range(threshold + 1, n + 1):
            multiple = divisor * 2

            while multiple <= n:
                union(divisor, multiple)
                multiple += divisor

        result = []

        for city_a, city_b in queries:
            result.append(find(city_a) == find(city_b))

        return result
```实现从初始化并查结构开始。 每个城市最初都是其自己的父城市，因为尚未处理任何连接。 

这`find()`函数执行路径压缩。 每当我们搜索代表时，中间节点都会更新为直接指向根。 这极大地提高了重复操作的性能。 

这`union()`函数合并两个组件。 如果两个城市已经属于同一集合，则无需进行任何工作。 

预处理阶段循环遍历每个大于阈值的除数。 它不是比较每对城市，而是仅连接除数的倍数。 这是核心优化。 

最后，通过比较组件代表，每个查询变成恒定时间的连接检查。 

## 解决方案```go
func areConnected(n int, threshold int, queries [][]int) []bool {
	parent := make([]int, n+1)

	for i := 0; i <= n; i++ {
		parent[i] = i
	}

	var find func(int) int

	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}

	union := func(a int, b int) {
		rootA := find(a)
		rootB := find(b)

		if rootA != rootB {
			parent[rootB] = rootA
		}
	}

	// Connect multiples of each valid divisor
	for divisor := threshold + 1; divisor <= n; divisor++ {
		for multiple := divisor * 2; multiple <= n; multiple += divisor {
			union(divisor, multiple)
		}
	}

	result := make([]bool, len(queries))

	for i, query := range queries {
		a := query[0]
		b := query[1]

		result[i] = find(a) == find(b)
	}

	return result
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

最大的区别是函数处理。 由于 Go 不像 Python 那样方便地支持嵌套命名函数，`find`被声明为函数变量以允许递归。 

切片用于`parent`数组和结果列表。 由于 Go 中的整数对于问题约束来说已经足够大，因此整数溢出不是问题。 

与 Python 不同，Go 需要对结果切片进行显式分配：```go
result := make([]bool, len(queries))
```这样就避免了重复的append操作，提高了效率。

 ## 边缘情况

 ### 阈值为零

 当`threshold = 0`, 除数`1`变得有效，因为`1 > 0`。 

因为每个数都可以被整除`1`，所有城市都成为同一个连接组件的一部分。 有缺陷的实现可能会意外忽略除数`1`，导致不正确的断开连接结果。 此实现可以自然地处理它，因为迭代开始于：```
threshold + 1
```这变成`1`。 

### 阈值等于`n`如果`threshold = n`，除数不能严格大于阈值。 因此，根本不存在道路。 

幼稚的实现可能仍会尝试不必要的联合操作或意外连接节点。 在此解决方案中，除数循环变为空：```
range(n + 1, n + 1)
```所以每个城市都保持孤立。 

＃＃＃ 城市`1`被孤立

 城市`1`只有除数`1`。 

如果`threshold >= 1`， 城市`1`无法与另一个城市共享任何有效的除数，这意味着它始终保持断开连接。 如果实现假设每个城市最终都加入一个组件，这很容易导致错误。 

Union-Find 设置自然会处理这个问题，因为城市`1`永远不会出现在任何联合运算中，除非除数`1`是有效的。 

### 重复查询

 该问题允许重复查询，例如：```
[4,5]
[4,5]
```效率较低的解决方案可能每次都会重新计算图遍历。 由于并查预处理发生一次，因此重复的查询会在恒定的时间内得到答复，而无需额外成本。 

### 间接连接

 两个城市可能不直接共享除数，但仍通过中间城市连接。 

例如：```
3 -> 6 -> 12
```仅检查直接整除性的有缺陷的实现将会失败。 并查正确合并整个连接组件，自动保留传递连接。
