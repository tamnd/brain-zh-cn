[LeetCode 问题 1676](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree-iv/)

 **难度：** 🟡 中等
 **主题：** 哈希表、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到二叉树中多个节点的最低公共祖先（LCA）。 与仅涉及两个节点的经典 LCA 问题不同，这种变体将定义推广到任意数量的目标节点。 

输入包括：

 -`root`，二叉树的根节点
 -`nodes`，一个数组，包含对树中某处存在的不同节点的引用

 目标是返回树中最低节点的单个节点，该树的子树包含`nodes`。 

“最低共同祖先”这个短语很重要。 节点被视为其自身的祖先，因此如果列表仅包含一个节点，则该节点自动成为其自己的 LCA。 

例如，如果目标节点是`4`和`7`，它们向上的路径最终在节点处相遇`2`，所以答案是`2`。 

这些约束告诉我们一些重要的事情：

 - 树最多可以包含`10^4`节点，所以我们需要一个高效的遍历算法
 - 所有节点值都是唯一的，这使我们能够在需要时通过值安全地识别节点
 - 保证每个目标节点都存在于树中
 - 所有目标节点都是不同的

 这些保证简化了实现，因为我们永远不需要处理无效或重复的目标。 

一些边缘情况很重要：

 - 的`nodes`数组只能包含一个节点
 - 一个目标节点可能已经是所有其他节点的祖先
 - LCA可能是根本身
 - 目标节点可能全部位于一棵子树内
 - 树可能极度不平衡，表现得像一个链表

 如果简单的实现重复搜索子树中的每个目标节点，它很容易变得低效。 由于树的大小可以达到`10^4`，我们应该以线性时间解决方案为目标。 

## 方法

 ### 蛮力方法

 一种简单的方法是计算每个目标节点的祖先链，然后对它们进行比较。 

一种方法是：

 1. 为整棵树构建父指针
 2.对于每个目标节点，向上向根走去，记录所有祖先
 3. 祖先集相交
 4.找到最深的共同祖先

 这种方法之所以有效，是因为 LCA 必须出现在每个目标节点的祖先链中。 

然而，该解决方案引入了不必要的开销。 我们花费额外的时间构建父映射并重复向上遍历每个目标节点。 虽然对于适度的约束仍然可以接受，但它比必要的更复杂且不太优雅。 

### 最优 DFS 方法

 关键的见解是，这个问题可以使用与经典两节点 LCA 问题完全相同的递归结构来解决。 

对于任意子树：

 - 如果当前节点是目标之一，我们返回它
 - 否则，递归搜索左右子树
 - 如果双方都返回非空值，则当前节点是LCA
 - 如果只有一侧返回非空值，则向上传播

 与经典问题的唯一区别是，不是检查当前节点是否等于`p`或者`q`，我们检查它是否属于目标节点集。 

这是可行的，因为其子树包含来自多个分支的目标的第一个节点必须是所有目标节点的最低公共祖先。 

对目标使用哈希集可以实现恒定时间的成员资格检查。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N + KH) | O(N + KH) | 构建父地图和祖先链 |
 | 最佳 | O(N) | O(H + K) | 带有哈希集查找的单次 DFS 遍历 |

 在哪里：

-`N`是树中的节点数
 -`K`是目标节点的数量
 -`H`是树的高度

 ## 算法演练

 1. 转换`nodes`列表到哈希集。 

我们使用哈希集，因为成员资格检查变得`O(1)`。 在进行DFS时，我们需要快速判断当前节点是否是目标之一。 
2. 从根开始深度优先搜索。 

递归函数自下而上地探索树。 每个递归调用都会返回：

 -`None`，如果该子树中不存在目标节点
 - 目标节点或 LCA 候选节点（如果该子树中存在）
 3. 检查当前节点是否为目标节点。 

如果当前节点存在于目标集中，则立即返回。 

这很重要，因为如果所有其他目标都位于目标节点下方，则目标节点本身可以​​成为 LCA。 
4. 递归搜索左子树。 

左递归调用告诉我们左分支中是否存在任何目标节点。 
5. 递归搜索右子树。 

右递归调用告诉我们右分支中是否存在任何目标节点。 
6. 确定如何向上传播结果。 

有以下三种可能：

 - 左、右均非空

 这意味着在两个分支中都找到了目标节点，因此当前节点是它们的最低公共祖先。 
- 只有一侧非空

 这意味着到目前为止发现的所有目标节点都位于一个子树内，因此向上传播该结果。 
- 两边都为空

 该子树不包含目标节点，因此返回`None`。 
7. 继续直到递归完成。 

根 DFS 调用最终返回整体 LCA。 

### 为什么它有效

 该算法之所以有效，是因为每个递归调用都会总结其子树是否包含任何目标节点。 

多个分支中出现目标的第一个节点必须是其子树包含所有目标的最低节点。 由于递归在处理父母之前处理孩子，因此算法自然会在任何更高祖先之前发现最低有效祖先。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, x):
#         self.val = x
#         self.left = None
#         self.right = None

from typing import List, Optional

class Solution:
    def lowestCommonAncestor(
        self,
        root: 'TreeNode',
        nodes: 'List[TreeNode]'
    ) -> 'TreeNode':

        target_nodes = set(nodes)

        def dfs(current: Optional['TreeNode']) -> Optional['TreeNode']:
            if current is None:
                return None

            if current in target_nodes:
                return current

            left_result = dfs(current.left)
            right_result = dfs(current.right)

            if left_result and right_result:
                return current

            return left_result if left_result else right_result

        return dfs(root)
```实现首先将`nodes`列表到一个名为的集合中`target_nodes`。 这允许在遍历期间进行恒定时间的成员资格测试。 

递归`dfs`函数自下而上处理树。 

基本情况通过返回来处理空节点`None`，这表明该子树中不存在目标节点。 

接下来，算法检查当前节点是否属于目标集。 如果是，则立即返回当前节点。 这使得目标之间的祖先关系能够正常工作。 

递归调用独立地搜索两个子树。 

如果两次递归调用都返回非空结果，则当前节点一定是连接不同分支目标的最低节点，因此它成为LCA。 

否则，无论哪一个子树返回非空结果，都会向上传播。 

最后，来自根的原始 DFS 调用返回总体答案。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func lowestCommonAncestor(root *TreeNode, nodes []*TreeNode) *TreeNode {
	targetSet := make(map[*TreeNode]bool)

	for _, node := range nodes {
		targetSet[node] = true
	}

	var dfs func(node *TreeNode) *TreeNode

	dfs = func(node *TreeNode) *TreeNode {
		if node == nil {
			return nil
		}

		if targetSet[node] {
			return node
		}

		leftResult := dfs(node.Left)
		rightResult := dfs(node.Right)

		if leftResult != nil && rightResult != nil {
			return node
		}

		if leftResult != nil {
			return leftResult
		}

		return rightResult
	}

	return dfs(root)
}
```Go 实现遵循与 Python 解决方案相同的递归策略。 

Go 使用的不是 Python 集，而是`map[*TreeNode]bool`来跟踪目标节点。 由于节点引用用作键，因此成员资格检查保持恒定时间。 

Go 使用`nil`而不是`None`对于缺失的节点。 递归 DFS 函数返回一个`*TreeNode`指针，它自然代表有效节点或不存在结果。 

不存在整数溢出问题，因为该算法从不对节点值执行算术。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | DFS | 每个节点都会被访问一次
 | 空间| O(H + K) | 递归栈加目标哈希集|

 DFS 遍历只触及每个节点一次，因此总运行时间与树的大小呈线性关系。 

递归栈需要`O(H)`空间，哪里`H`是树的高度。 在完全倾斜的树的最坏情况下，这变成`O(N)`。 

目标集存储所有目标节点，要求`O(K)`额外的空间。

 ## 边缘情况

 ### 单目标节点

 如果`nodes`数组仅包含一个节点，正确答案是该节点本身。 某些实现错误地继续搜索另一个匹配分支，并且可能会意外返回祖先。 

此实现可以自然地处理这种情况，因为当节点出现在目标集中时，DFS 会立即返回该节点。 

### 一个目标是其他目标的祖先

 假设目标列表包含两个节点`5`和节点`4`， 在哪里`5`是的祖先`4`。 

一个常见的错误是发现节点后继续递归`5`，这可能会错误地提升更高的祖先。 

此实现避免了该问题，因为目标节点会立即返回。 一次节点`5`找到后，它会作为有效的 LCA 向上传播。 

### 根是最低的共同祖先

 当目标节点位于树的完全不同的分支时，根本身可能就是答案。 

例如，节点`6`和`8`存在于根的相反子树中`3`。 

该算法正确地处理了这个问题，因为左递归调用和右递归调用都在根处返回非空值，导致根成为 LCA。 

### 高度不平衡的树

 倾斜树的行为类似于链表，可以创建深度递归。 

该算法仍然可以正常工作，因为每个节点只被处理一次。 唯一的影响是递归深度变成`O(N)`而不是`O(log N)`对于平衡树。
