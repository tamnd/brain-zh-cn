[LeetCode 问题 1671](https://leetcode.com/problems/minimum-number-of-removals-to-make-mountain-array/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、动态规划、贪心

 ## 解决方案

 ## 问题理解

 该问题要求我们从数组中删除最少数量的元素，以便剩余元素形成有效的山数组。 

山阵有两个严格的阶段：

 1. 严格递增序列
 2.紧随其后的是严格递减序列

 中间某处必须有一个有效的峰值，这意味着峰值不能是第一个或最后一个元素。 

更正式地说，对于某些索引`i`：

 -`nums[0] < nums[1] < ... < nums[i]`-`nums[i] > nums[i+1] > ... > nums[n-1]`重要的细节是双方必须严格单调。 不允许相邻值相等。 

输入是一个整数数组`nums`，我们可以删除任何我们想要的元素。 其余元素不需要保持连续，因为删除实际上会创建一个子序列。 我们的目标是找到所需的最小移除次数，以便剩余的子序列成为山数组。 

约束条件很重要：

 -`3 <= nums.length <= 1000`-`1 <= nums[i] <= 10^9`自从`n`只有 1000 个`O(n^2)`动态规划解决方案是完全可以接受的。 然而，对所有子序列进行强力枚举的速度会呈指数级缓慢。 

一个关键的观察结果是，山阵本质上是：

 - 以峰值结束的递增子序列
 - 与从该峰值开始的递减子序列相结合

 这自然建议使用最长递增子序列 (LIS) 和最长递减子序列 (LDS)。 

有几个重要的边缘情况：

 - 已经是山的阵列
 - 具有重复值的数组，因为严格的不等式很重要
 - 边界处的峰值，这是无效的
 - 完全递增或完全递减的数组
 - 多个可能的峰值，我们必须选择最好的一个

 该问题保证了总是有可能形成山阵。 

## 方法

 ### 蛮力方法

 蛮力的想法是生成每个可能的子序列并检查它是否形成有效的山数组。 

对于每个子序列：

 1.验证其长度至少为3
 2. 判断是否存在有效峰值
 3、高峰前检查严格的递增顺序
 4、峰值后检查严格降序
 5. 跟踪最长的有效山子序列

 最后，答案是：```
n - longest_mountain_length
```这种方法是正确的，因为它检查了每个可能的子序列，因此它不会错过最佳解决方案。 

然而，子序列的数量是`2^n`，即使对于中等输入大小，这也变得完全不可行。 和`n = 1000`，暴力是不可能的。 

### 最优动态规划方法

 关键的见解是每座有效的山都有一个峰顶。 

对于每个索引`i`，我们想知道：

 - 结束于的最长递增子序列的长度`i`- 从 开始的最长递减子序列的长度`i`如果两个值都大于 1，则索引`i`可以作为一座山峰。 

使用峰值的山总长度`i`是：```
LIS[i] + LDS[i] - 1
```我们减去 1，因为峰值被计算了两次。 

然后：```
minimum removals = n - maximum mountain length
```这将问题转化为两个经典的动态规划计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 枚举每个子序列 |
 | 最佳 | O(n^2) | O(n^2) | O(n) | 使用 LIS 和 LDS 动态规划 |

 ## 算法演练

 1. 创建数组`lis`在哪里`lis[i]`表示以索引结尾的最长严格递增子序列的长度`i`。 

将所有值初始化为 1，因为每个元素单独形成长度为 1 的递增子序列。 
2. 使用动态规划计算 LIS。 

对于每个索引`i`，检查所有先前的索引`j < i`。 

如果`nums[j] < nums[i]`， 然后`nums[i]`可以扩展结束于的递增子序列`j`。 

更新：```
lis[i] = max(lis[i], lis[j] + 1)
```3. 创建数组`lds`在哪里`lds[i]`表示从索引处开始的最长严格递减子序列的长度`i`。 

再次将所有值初始化为 1。 
4. 从右到左计算LDS。 

对于每个索引`i`，检查所有后面的索引`j > i`。 

如果`nums[j] < nums[i]`， 然后`nums[i]`可以跟随`nums[j]`在递减的子序列中。 

更新：```
lds[i] = max(lds[i], lds[j] + 1)
```5. 迭代每个可能的峰值索引`i`。 

有效的山峰必须满足：```
lis[i] > 1 and lds[i] > 1
```这确保了在峰值之前至少有一个增加元素，在峰值之后至少有一个减少元素。 
6. 对于每个有效的山峰，计算山的长度：```
mountain_length = lis[i] + lds[i] - 1
```7. 追踪找到的最大山脉长度。 
8、退货：```
n - max_mountain_length
```### 为什么它有效

 该算法之所以有效，是因为每个山脉阵列都可以通过峰值索引来唯一描述：

 - 增加的子序列在峰值处结束
 - 从峰值开始递减的子序列

 LIS 计算保证我们知道每个候选峰的最佳增长部分。 LDS 计算保证我们知道最佳的递减部分。 将它们结合起来给出以每个索引为中心的最大可能山峰。 因此，在所有山峰中选取最好的会产生最长的有效山峰子序列，从而最大限度地减少移除。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumMountainRemovals(self, nums: List[int]) -> int:
        n = len(nums)

        lis = [1] * n

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    lis[i] = max(lis[i], lis[j] + 1)

        lds = [1] * n

        for i in range(n - 1, -1, -1):
            for j in range(i + 1, n):
                if nums[j] < nums[i]:
                    lds[i] = max(lds[i], lds[j] + 1)

        max_mountain = 0

        for i in range(1, n - 1):
            if lis[i] > 1 and lds[i] > 1:
                mountain_length = lis[i] + lds[i] - 1
                max_mountain = max(max_mountain, mountain_length)

        return n - max_mountain
```实现直接遵循算法。 

这`lis`数组存储以每个索引结尾的最长递增子序列。 我们使用嵌套循环来计算它，因为约束允许`O(n^2)`舒适地解决。 

这`lds`数组存储从每个索引开始的最长递减子序列。 其计算方式类似，但从右到左。 

当两个数组都可用后，我们迭代所有索引并将每个索引视为可能的山峰。 有效峰值必须同时具有增加侧和减少侧，因此两者`lis[i]`和`lds[i]`必须超过 1。 

对于每个有效的山峰，我们计算山的长度并跟踪最大可能的山子序列。 

最后，从原始阵列大小中减去最大山体长度即可得出所需的最小移除量。 

## 解决方案```go
func minimumMountainRemovals(nums []int) int {
	n := len(nums)

	lis := make([]int, n)
	for i := 0; i < n; i++ {
		lis[i] = 1
	}

	for i := 0; i < n; i++ {
		for j := 0; j < i; j++ {
			if nums[j] < nums[i] && lis[j]+1 > lis[i] {
				lis[i] = lis[j] + 1
			}
		}
	}

	lds := make([]int, n)
	for i := 0; i < n; i++ {
		lds[i] = 1
	}

	for i := n - 1; i >= 0; i-- {
		for j := i + 1; j < n; j++ {
			if nums[j] < nums[i] && lds[j]+1 > lds[i] {
				lds[i] = lds[j] + 1
			}
		}
	}

	maxMountain := 0

	for i := 1; i < n-1; i++ {
		if lis[i] > 1 && lds[i] > 1 {
			mountainLength := lis[i] + lds[i] - 1
			if mountainLength > maxMountain {
				maxMountain = mountainLength
			}
		}
	}

	return n - maxMountain
}
```Go 的实现与 Python 版本非常相似。 

切片使用初始化`make`，并且所有 LIS 和 LDS 值都手动设置为 1，因为 Go 不像 Python 那样支持列表乘法。 

Go 整数就足够了，因为最大子序列长度只有 1000，所以溢出不是问题。 

嵌套循环和转换逻辑与 Python 解决方案保持相同。

 ## 边缘情况

 ### 具有重复值的数组

 重复值是错误的常见来源，因为山数组需要严格的不平等。 例如：```
[1,2,2,3,2,1]
```顺序`2,2`不是严格递增的，因此必须删除其中一个重复值。 

该实现可以正确处理此问题，因为它仅在以下情况下扩展子序列：```
nums[j] < nums[i]
```平等是永远不允许的。 

### 边界的峰值

 有效的山峰不能是第一个或最后一个元素。 

例如：```
[1,2,3,4]
```没有递减的边，因此不存在没有移除的有效山。 

该实现通过要求以下方式来防止无效峰值：```
lis[i] > 1 and lds[i] > 1
```这就保证了山的两边都存在。 

### 完全递增或递减数组

 数组如：```
[1,2,3,4,5]
```或者```
[5,4,3,2,1]
```不包含有效的山脉结构。 

幼稚的实现可能会错误地接受它们，因为它们包含单调序列。 然而，一座山需要递增和递减的部分。 

该实现正确地拒绝了这些，因为没有索引可以同时满足这两个要求：```
lis[i] > 1
lds[i] > 1
```### 多个有效峰值

 某些阵列包含多个潜在峰值：```
[1,2,1,2,1]
```贪婪的选择可能会选择错误的峰值并产生不必要的删除。 

动态规划解决方案独立评估每个可能的峰值，并选择产生最长山峰子序列的峰值，从而保证最小的去除量。
