[LeetCode 问题 1685](https://leetcode.com/problems/sum-of-absolute-differences-in-a-sorted-array/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、前缀和

 ## 解决方案

 ## 问题理解

 该问题给了我们一个排序的整数数组`nums`，按非降序排列。 对于每个索引`i`，我们必须计算之间的绝对差的总和`nums[i]`以及数组中的所有其他元素。 

正式来说，对于每个位置`i`:$$result[i] = \sum_{j=0}^{n-1} |nums[i] - nums[j]|$$输出必须是一个长度相同的数组，其中每个元素都包含此计算值。 

关键细节是数组已经排序。 这显着改变了问题，因为根据元素是在当前位置的左侧还是右侧，绝对差异变得可预测。 

例如，如果：```
nums = [1,4,6,8,10]
```然后对于索引`2`，值为`6`， 和：```
|6-1| + |6-4| + |6-6| + |6-8| + |6-10|
= 5 + 2 + 0 + 2 + 4
= 13
```约束条件很重要：

 -`2 <= nums.length <= 10^5`-`nums`已排序
 - 值为正整数

 数组大小为`10^5`立即告诉我们`O(n^2)`解决方案会太慢。 二次解最多需要：$$10^5 \times 10^5 = 10^{10}$$的操作，远远超出了可接受的范围。 

排序后的属性是关键的观察结果。 由于数组是有序的，我们知道：

 - 左边的每个元素`nums[i]`小于或等于它
 - 右边的每个元素都大于或等于它

 这使我们能够删除绝对值运算并使用前缀和以数学方式计算贡献。 

一些重要的边缘情况包括：

 - 只有两个元素的数组
 - 所有值都相等的数组
 - 具有重复数字的数组
 - 严格增加数组
 - 效率至关重要的大型阵列

 该问题保证数组已排序，因此我们不需要处理未排序的输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是直接计算每个绝对差。 

对于每个索引`i`，我们迭代整个数组并计算：```
abs(nums[i] - nums[j])
```对于每一个`j`。 

然后我们将所有这些值相加并存储结果。 

这是有效的，因为它直接遵循问题定义。 每个成对差异均经过明确计算。 

然而，这种方法需要两个嵌套循环：

 - 所有元素的外循环
 - 再次对所有元素进行内循环

 这导致`O(n^2)`时间复杂度。 

和`n = 10^5`，这变得太慢了。 

### 最优前缀和方法

 关键的见解来自数组的排序性质。 

假设我们正在处理`nums[i]`。 

由于数组已排序：

 - 索引之前的所有元素`i`小于或等于
 - 索引后的所有元素`i`大于或等于

 因此：

 对于左侧的元素：$$|nums[i] - nums[j]| = nums[i] - nums[j]$$对于右侧的元素：$$|nums[i] - nums[j]| = nums[j] - nums[i]$$我们可以分别计算这两部分。 

如果我们知道：

 - 左侧所有元素的总和
 - 右边所有元素的总和

 然后我们可以计算常数时间内的贡献。 

使用前缀和可以让我们有效地获得这些和。 

对于索引`i`:

 左贡献：$$nums[i] \times i - leftSum$$正确的贡献：$$rightSum - nums[i] \times (n-i-1)$$添加它们给出了索引的最终答案`i`。 

这将总复杂度降低到`O(n)`。

 ## 算法演练

 1. 计算数组的总和。 

我们首先计算所有元素的总和。 这使我们能够在迭代过程中有效地确定当前索引右侧元素的总和。 
2. 初始化运行前缀和。 

我们维持`left_sum`，它存储当前索引之前的所有元素的总和。 
3. 迭代数组。 

对于每个索引`i`，令当前值为`num`。 
4. 计算左贡献。 

由于左边的所有元素都小于或等于`num`，左侧的总差异贡献为：$$num \times i - left\_sum$$这里：

-`num * i`表示所有左侧元素等于的总和`num`- 减法`left_sum`给出总差
 5. 计算正确的贡献。 

右侧元素之和为：$$total\_sum - left\_sum - num$$让这成为`right_sum`。 

由于所有右侧元素都大于或等于`num`，他们的贡献是：$$right\_sum - num \times (n-i-1)$$6. 添加两项贡献。 

最终索引结果`i`是：$$left\_contribution + right\_contribution$$7. 更新前缀和。 

添加`num`到`left_sum`在移动到下一个索引之前。 

### 为什么它有效

 该算法之所以有效，是因为数组已排序。 这保证了对于任何索引`i`:

 - 每个左边的元素都有贡献`nums[i] - nums[j]`- 每个正确的元素都有贡献`nums[j] - nums[i]`通过对这些进行数学分组，而不是单独计算每一对，我们将许多重复计算转换为使用前缀和的简单算术。 每个元素的总贡献仅计算一次，从而给出正确且有效的解决方案。 

## Python 解决方案```python
from typing import List

class Solution:
    def getSumAbsoluteDifferences(self, nums: List[int]) -> List[int]:
        n = len(nums)
        total_sum = sum(nums)

        result = [0] * n
        left_sum = 0

        for i, num in enumerate(nums):
            right_sum = total_sum - left_sum - num

            left_contribution = num * i - left_sum
            right_contribution = right_sum - num * (n - i - 1)

            result[i] = left_contribution + right_contribution

            left_sum += num

        return result
```实现首先计算数组的总和。 这使我们能够在迭代期间确定右侧元素的总和，而无需其他数据结构。 

这`left_sum`变量跟踪当前索引之前元素的累积和。 

循环内部：

 -`right_sum`通过减去当前元素来计算`left_sum`从总和中。 
-`left_contribution`计算所有左侧元素对绝对差的贡献程度。 
-`right_contribution`计算所有正确元素的贡献量。 

这两个值相加并存储在结果数组中。 

最后我们更新一下`left_sum`因此下一次迭代具有正确的前缀信息。 

该算法对每个元素只处理一次，给出线性时间复杂度。 

## 解决方案```go
func getSumAbsoluteDifferences(nums []int) []int {
	n := len(nums)

	totalSum := 0
	for _, num := range nums {
		totalSum += num
	}

	result := make([]int, n)
	leftSum := 0

	for i, num := range nums {
		rightSum := totalSum - leftSum - num

		leftContribution := num*i - leftSum
		rightContribution := rightSum - num*(n-i-1)

		result[i] = leftContribution + rightContribution

		leftSum += num
	}

	return result
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

主要差异是特定于语言的：

 - Go 需要使用显式切片分配`make`。 
- 没有内置的`sum`切片函数，所以我们计算`totalSum`手动。 
- 整数算术在给定的约束下是安全的，因为最大可能的和完全适合 Go 的范围`int`范围。 

由于输入长度保证至少为 2，因此不需要特殊的 nil 或空处理。

 ## 边缘情况

 ### 所有元素都相等

 如果数组中的每个值都相同，则每个绝对差为零。 

例如：```
[5,5,5,5]
```每个元素都会产生：```
|5-5| = 0
```有缺陷的实现可能会错误地计算负值或错误地处理重复计数。 该解决方案可以正确工作，因为左贡献公式和右贡献公式自然都计算为零。 

### 最小数组大小

 允许的最小输入大小是`2`。 

例如：```
[1,2]
```这很重要，因为某些实现意外地假设每个索引的两侧都有元素。 我们的实现可以安全地处理边缘位置，因为：

 - 索引的左贡献变为零`0`- 最后一个指数的正确贡献为零

 不需要特殊情况逻辑。 

### 具有重复值的数组

 如果算法错误地假设严格排序，重复的数字可能会导致逻辑错误。 

例如：```
[1,1,3,3]
```排序数组属性仍然成立，因为数组是非递减的，而不是严格递增的。 

这些公式仍然有效，因为相同的元素自然会贡献零差异。 

### 大输入

 高达`10^5`要素，性能非常重要。 

由于二次复杂度，暴力解决方案会超时。 前缀和方法对每个元素处理一次，并且仅使用恒定的额外内存，使其对于最大允许输入来说足够高效。
