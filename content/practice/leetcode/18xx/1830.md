[LeetCode 问题 1830](https://leetcode.com/problems/minimum-number-of-operations-to-make-string-sorted/)

 **难度：** 🔴难
 **主题：** 哈希表、数学、字符串、组合、计数

 ## 解决方案

 ## 问题理解

 问题中描述的操作正是生成字符串的先前字典排列的过程。 从当前字符串开始，每个操作都会将其转换为按字典顺序仍然小于当前字符串的最大字符串。 

目标是确定在字符串完全按升序排序之前需要多少次此类操作。 另一种思考这个问题的方法是：

 - 每个操作都会将字符串按字典顺序向后移动一步。 
- 排序后的字符串是可能的最小排列。 
- 因此，答案是按字典顺序小于给定字符串的不同排列的数量。 

这一观察彻底改变了问题。 我们可以计算字符串在所有不同排列中的字典顺序，而不是一一模拟操作，这会非常慢。 

输入为小写英文字符串`s`长度可达`3000`。 这是一个非常重要的约束。 自从`3000!`是一个天文数字，我们必须取模`10^9 + 7`，并且我们需要一种比阶乘时间排列生成快得多的算法。 

另一个复杂的问题是字符可能会重复。 重复的字母减少了不同排列的数量。 例如：

-`"abc"`有`3! = 6`不同的排列。 
-`"aab"`有`3! / 2! = 3`不同的排列，因为两个`'a'`字符是无法区分的。 

这意味着我们必须使用具有重复处理的组合学。 

一些边缘情况很重要：

 - 已经排序的字符串，例如`"abc"`，应该返回`0`。 
- 包含所有相同字符的字符串，例如`"aaaa"`，也返回`0`。 
- 具有许多重复项的字符串需要仔细的阶乘除法处理。 
- 大字符串需要模运算和高效的组合计算。 

## 方法

 ### 蛮力方法

 直接方法将完全按照描述模拟操作：

 1. 找到下一个先前的词典排列。 
2. 计算一次操作。 
3. 重复此操作，直到字符串排序完毕。 

这是有效的，因为每个操作都确定性地移动到紧邻的更小的排列。 

然而，这对于大量输入来说是完全不切实际的。 不同排列的数量可能是巨大的。 对于一个长度的字符串`3000`，甚至迭代所有排列也是不可能的。 

此外，生成每个先前的排列至少需要花费`O(n)`，使总运行时间在实践中呈指数级增长。 

### 最佳方法

 关键的见解是操作顺序与字典顺序完全匹配。 

我们不是模拟排列，而是计算：

 > 有多少个不同的排列按字典顺序小于当前字符串？ 

这就是重复字符的词典排序问题。 

对于每个职位`i`:

 - 计算该位置可以出现多少个较小的字符`i`。 
- 修复一个这样较小的角色。 
- 计算剩余字符可以形成多少种不同的排列。 

具有重复项的排列数为：$\frac{n!}{c_1!c_2!\cdots c_k!}$在哪里：

-`n`是剩余位置的数量
 -`c1, c2, ..., ck`是每个字符的出现频率

 我们预先计算阶乘和模逆，以便这些计算变得高效。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 模拟每个排列步骤 |
 | 最佳| O(n * 26) | O(n) | 使用组合学计算字典顺序 |

 ## 算法演练

 ### 第 1 步：预先计算阶乘和逆阶乘

 我们需要频繁计算涉及阶乘除法的排列计数。 

因为模算术下的除法不能直接进行，所以我们使用模逆：$a^{-1} \equiv a^{MOD-2} \pmod{MOD}$使用费马小定理。 

我们预先计算：

 -`fact[i] = i! mod MOD`-`inv_fact[i] = (i!)^{-1} mod MOD`为所有人`0 <= i <= n`。 

### 步骤 2：计算字符频率

 我们维护一个大小为 26 的频率数组，表示每个字符在当前考虑的后缀中出现的次数。 

最初，频率数组包含字符串中的所有字符。 

### 步骤 3：从左到右处理位置

 在每个位置`i`:

 - 暂时删除当前角色。 
- 尝试放置仍然可用的每个较小的角色。 

假设当前字符是`'d'`。 

我们尝试`'a'`,`'b'`,`'c'`如果它们的频率为正。 

每个较小的字符都会创建一个按字典顺序更小的字符串。 

### 步骤 4：计算每个较小字符的排列

 在该位置固定较小的字符后`i`，剩余的后缀可以排列为：$\frac{(n-i-1)!}{\prod c_j!}$方式。 

我们将所有此类计数添加到答案中。 

### 步骤 5：恢复频率计数并继续

 评估所有较小的选择后：

 - 从频率数组中永久删除实际的当前字符。 
- 移动到下一个位置。 

###第六步：返回累计答案

 所有计算均以模进行`10^9 + 7`。 

### 为什么它有效

 在每个索引中，我们精确计算在第一个不同位置按字典顺序变小的排列。 

这是标准的词典排序原则：

 - 较早的位置首先确定排序。 
- 一旦放置了较小的字符，后缀的每个有效排列都保证小于原始字符串。 

通过对所有位置的这些计数求和，我们对每个字典顺序较小的不同排列进行一次计数。 

## Python 解决方案```python
class Solution:
    def makeStringSorted(self, s: str) -> int:
        MOD = 10**9 + 7
        n = len(s)

        # Precompute factorials
        fact = [1] * (n + 1)
        for i in range(1, n + 1):
            fact[i] = fact[i - 1] * i % MOD

        # Precompute inverse factorials
        inv_fact = [1] * (n + 1)
        inv_fact[n] = pow(fact[n], MOD - 2, MOD)

        for i in range(n, 0, -1):
            inv_fact[i - 1] = inv_fact[i] * i % MOD

        # Frequency array
        freq = [0] * 26
        for ch in s:
            freq[ord(ch) - ord('a')] += 1

        answer = 0

        for i in range(n):
            current = ord(s[i]) - ord('a')

            # Remove current character temporarily
            freq[current] -= 1

            # Try all smaller characters
            for smaller in range(current):
                if freq[smaller] == 0:
                    continue

                freq[smaller] -= 1

                permutations = fact[n - i - 1]

                for count in freq:
                    permutations = (
                        permutations * inv_fact[count]
                    ) % MOD

                answer = (answer + permutations) % MOD

                freq[smaller] += 1

        return answer
```实现从预计算阶乘和逆阶乘开始。 这允许在模运算下进行快速组合计算。 

频率数组跟踪从左到右处理字符串时每个字符的可用数量。 

对于每个位置，算法会暂时删除当前字符并检查可能合法出现在该位置的每个较小字符。 如果存在这样的字符，我们计算剩余字符可以形成多少个不同的排列。 

排列公式自动处理重复字符，因为我们使用逆阶乘除以重复计数的阶乘。 

每个有效的较小前缀都会贡献排列，这些排列保证按字典顺序小于原始字符串，因此累积的总数成为最终答案。 

## 解决方案```go
package main

func makeStringSorted(s string) int {
	const MOD int64 = 1_000_000_007

	n := len(s)

	// Precompute factorials
	fact := make([]int64, n+1)
	fact[0] = 1

	for i := 1; i <= n; i++ {
		fact[i] = fact[i-1] * int64(i) % MOD
	}

	// Fast exponentiation
	powMod := func(base, exp int64) int64 {
		result := int64(1)

		for exp > 0 {
			if exp&1 == 1 {
				result = result * base % MOD
			}

			base = base * base % MOD
			exp >>= 1
		}

		return result
	}

	// Precompute inverse factorials
	invFact := make([]int64, n+1)
	invFact[n] = powMod(fact[n], MOD-2)

	for i := n; i >= 1; i-- {
		invFact[i-1] = invFact[i] * int64(i) % MOD
	}

	// Frequency array
	freq := make([]int, 26)

	for _, ch := range s {
		freq[ch-'a']++
	}

	var answer int64 = 0

	for i := 0; i < n; i++ {
		current := int(s[i] - 'a')

		// Remove current character temporarily
		freq[current]--

		// Try all smaller characters
		for smaller := 0; smaller < current; smaller++ {
			if freq[smaller] == 0 {
				continue
			}

			freq[smaller]--

			permutations := fact[n-i-1]

			for _, count := range freq {
				permutations = permutations * invFact[count] % MOD
			}

			answer = (answer + permutations) % MOD

			freq[smaller]++
		}
	}

	return int(answer)
}
```Go 版本遵循与 Python 实现相同的逻辑。 

一个重要的区别是整数处理。 由于中间阶乘值变得非常大，因此实现使用`int64`贯穿所有模算术运算。 

Go 不提供内置模幂运算，因此该解决方案包括用于计算模逆的自定义快速幂函数。 

切片用于阶乘数组和频率计数，密切镜像 Python 列表。

 ## 边缘情况

 ### 已经排序的字符串

 像这样的字符串`"abc"`已经是最小可能的排列。 不存在字典序上更小的排列，所以答案一定是`0`。 

有缺陷的实现可能仍会尝试交换或计算无效排列。 此实现正确地在任何位置都找不到更小的字符，因此累积的答案仍然为零。 

### 所有字符都相同

 考虑`"aaaa"`。 

即使有多个位置，所有排列都是相同的。 未经重复校正的简单阶乘计算会错误地计算多个排列。 

该实现通过使用逆阶乘除以重复字符计数的阶乘来避免这种情况。 

### 大输入和大量重复

 一个长度的字符串`3000`包含许多重复字符强调性能和组合正确性。 

直接排列生成是不可能的。 该解决方案仍然有效，因为：

 - 字母大小固定为 26。 
- 阶乘预先计算一次。 
- 每个职位仅执行有限的工作。 

模运算可防止溢出，同时保持计算的数学正确性。
