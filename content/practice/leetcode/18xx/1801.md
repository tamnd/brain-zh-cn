[LeetCode 问题 1801](https://leetcode.com/problems/number-of-orders-in-the-backlog/)

 **难度：** 🟡 中等
 **主题：** 数组、堆（优先级队列）、模拟

 ## 解决方案

 ## 问题理解

 此问题模拟简化的证券交易所订单簿。 每个传入订单要么是买入订单，要么是卖出订单，并且每个订单都包含价格和金额。 订单严格按照其在输入中出现的顺序进行处理。 

买入订单希望以某个最高价格购买股票。 卖单希望以特定的最低价格出售股票。 只要买单可以负担当前可用的最便宜的卖单，或者当卖单可以由当前可用的最昂贵的买单满足时，就会发生匹配。 

关键细节是匹配总是针对最优惠的价格进行：

 - 买单与价格最小的卖单匹配。 
- 卖单与最高价格的买单匹配。 

如果可能匹配，订单将立即执行。 允许部分匹配，这意味着在交易过程中只能消耗订单的一部分。 任何剩余的未匹配金额都会保留在积压中。 

输入`orders[i] = [pricei, amounti, orderTypei]`方法：

-`pricei`是订单价格
 -`amounti`是购买或出售的单位数量
 -`orderTypei`是：

-`0`购买
 -`1`出售

 目标是处理每个订单，并在所有可能的匹配完成后返回积压中剩余的单位总数。 

约束条件非常重要：

 - 最多`10^5`订单
 - 价格和金额可以大至`10^9`扫描所有现有订单以查找每个新订单的简单模拟会太慢。 由于我们反复需要：

 - 最低售价
 - 最大买入价

 这强烈建议使用优先级队列，也称为堆。 

一些重要的边缘情况包括：

 - 仅部分匹配的订单
 - 完全消耗多个积压条目的订单
 - 无法匹配的情况
 - 需要模运算的非常大的数量
 - 许多订单价格相同
 - 匹配期间一个待办事项堆变空的情况

 该问题保证了有效的输入格式和有效的订单类型，因此我们只需要关注正确的匹配行为和效率。 

## 方法

 ### 蛮力方法

 一个简单的解决方案将维护两个列表：

 - 所有待处理的买单
 - 所有待处理的卖单

 对于每个传入的订单，我们都会扫描相反的列表以找到最佳的匹配订单：

 - 买入订单的最小卖出价格
 - 卖单的最大买入价

 找到候选者后，我们将更新数量并继续匹配，直到没有有效交易为止。 

这种方法是正确的，因为它完全按照描述忠实地模拟了交换过程。 然而，它的效率很低，因为每次插入可能需要扫描许多现有订单。 

在最坏的情况下：

 - 每个`10^5`订单扫描几乎所有以前的订单
 - 总复杂度变为`O(n^2)`对于给定的约束来说这太慢了。 

### 使用两个堆的最佳方法

 关键的观察是我们只关心：

 - 最低售价
 - 最高买入价

 优先级队列非常适合以下情况：

 - 卖单的最小堆
 - 买单的最大堆

 对于堆：

 - 检索最佳匹配顺序变为`O(log n)`- 插入也变成`O(log n)`Python 仅提供最小堆，因此对于买入订单，我们存储负价格来模拟最大堆。 

该算法重复地将订单与相反堆的顶部进行匹配，直到：

 - 当前订单已完全消耗，或
 - 不存在有效的价格匹配

 这将总复杂度降低到`O(n log n)`。

 ## 算法演练

 1. 初始化两个堆。 

我们维持：

 - 买单的最大堆
 - 卖单的最小堆

 每个堆条目存储：

 - 价格
 - 剩余金额

 购买堆使用负价格，因为 Python 堆默认是最小堆。 
2. 按顺序处理每个订单。 

每个订单都必须按照输入给出的确切顺序进行处理。 
3. 处理买入订单。 

对于买入订单：

 - 反复检查最便宜的卖单
 - 如果卖出价小于或等于买入价，则可以进行交易

 每场比赛期间：

 - 计算匹配数量
 - 减少这两项金额
 - 从堆中删除完全消耗的卖单

 继续直到：

 - 购买订单完全满足，或者
 - 不存在实惠的卖单
 4. 将剩余购买数量添加到积压订单中。 

如果部分买单仍然不匹配，则将其插入买堆中。 
5. 处理卖单。 

对于卖单：

 - 反复检查最高买入价
 - 如果买入价大于或等于卖出价，则可以进行交易

 每场比赛期间：

 - 计算匹配数量
 - 减少这两项金额
 - 删除完全消耗的购买订单

 继续直到：

 - 卖单已完全消耗，或
 - 不存在匹配的买单
 6. 将剩余销售数量添加到积压订单中。 

如果某些卖出数量仍然不匹配，则将其推入卖出堆。 
7. 计算最终积压工作量。 

将所有剩余金额相加：

 - 购买堆
 - 出售堆

 返回结果取模`10^9 + 7`。 

### 为什么它有效

 堆始终保持正确的优先级顺序：

 - 购买堆总是暴露最高购买价格
 - 卖出堆总是暴露最低卖出价

 在每一步中，算法都会执行与问题陈述所需的完全相同的交易。 由于订单是按顺序处理的，并且在存在有效价格的情况下贪婪地继续匹配，因此最终的积压状态与预期的交易模拟相同。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def getNumberOfBacklogOrders(self, orders: List[List[int]]) -> int:
        MOD = 10**9 + 7

        # Max heap for buy orders: (-price, amount)
        buy_heap = []

        # Min heap for sell orders: (price, amount)
        sell_heap = []

        for price, amount, order_type in orders:

            # Buy order
            if order_type == 0:

                # Match with cheapest sell orders
                while amount > 0 and sell_heap and sell_heap[0][0] <= price:
                    sell_price, sell_amount = heapq.heappop(sell_heap)

                    matched = min(amount, sell_amount)

                    amount -= matched
                    sell_amount -= matched

                    # Put remaining sell order back
                    if sell_amount > 0:
                        heapq.heappush(sell_heap, (sell_price, sell_amount))

                # Remaining buy order goes to backlog
                if amount > 0:
                    heapq.heappush(buy_heap, (-price, amount))

            # Sell order
            else:

                # Match with highest buy orders
                while amount > 0 and buy_heap and -buy_heap[0][0] >= price:
                    buy_price, buy_amount = heapq.heappop(buy_heap)

                    matched = min(amount, buy_amount)

                    amount -= matched
                    buy_amount -= matched

                    # Put remaining buy order back
                    if buy_amount > 0:
                        heapq.heappush(buy_heap, (buy_price, buy_amount))

                # Remaining sell order goes to backlog
                if amount > 0:
                    heapq.heappush(sell_heap, (price, amount))

        total = 0

        for _, amount in buy_heap:
            total = (total + amount) % MOD

        for _, amount in sell_heap:
            total = (total + amount) % MOD

        return total
```实现直接遵循基于堆的模拟策略。 

这`buy_heap`存储负价格，以便堆中的最小值对应于最大的实际购买价格。 这样可以有效地获取最佳可用购买订单。 

这`sell_heap`自然地作为最小堆工作，因为我们总是需要最小的销售价格。 

对于每个订单，代码都会重复尝试与相反的堆进行匹配。 匹配将持续进行，直到出现以下情况之一：

 - 当前订单没有剩余数量
 - 价格条件不成立
 - 对面的堆变空

 部分匹配被仔细处理。 交易结束后，如果积压订单仍有剩余数量，则会以其更新后的数量推回堆中。 

最后，将两个堆中的所有剩余数量求模求和`10^9 + 7`。 

## 解决方案```go
package main

import (
	"container/heap"
)

const MOD int = 1e9 + 7

type Order struct {
	price  int
	amount int
}

type BuyHeap []Order

func (h BuyHeap) Len() int {
	return len(h)
}

func (h BuyHeap) Less(i, j int) bool {
	return h[i].price > h[j].price
}

func (h BuyHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *BuyHeap) Push(x interface{}) {
	*h = append(*h, x.(Order))
}

func (h *BuyHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

type SellHeap []Order

func (h SellHeap) Len() int {
	return len(h)
}

func (h SellHeap) Less(i, j int) bool {
	return h[i].price < h[j].price
}

func (h SellHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *SellHeap) Push(x interface{}) {
	*h = append(*h, x.(Order))
}

func (h *SellHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func getNumberOfBacklogOrders(orders [][]int) int {
	buyHeap := &BuyHeap{}
	sellHeap := &SellHeap{}

	heap.Init(buyHeap)
	heap.Init(sellHeap)

	for _, order := range orders {
		price := order[0]
		amount := order[1]
		orderType := order[2]

		if orderType == 0 {

			for amount > 0 &&
				sellHeap.Len() > 0 &&
				(*sellHeap)[0].price <= price {

				top := heap.Pop(sellHeap).(Order)

				matched := min(amount, top.amount)

				amount -= matched
				top.amount -= matched

				if top.amount > 0 {
					heap.Push(sellHeap, top)
				}
			}

			if amount > 0 {
				heap.Push(buyHeap, Order{
					price:  price,
					amount: amount,
				})
			}

		} else {

			for amount > 0 &&
				buyHeap.Len() > 0 &&
				(*buyHeap)[0].price >= price {

				top := heap.Pop(buyHeap).(Order)

				matched := min(amount, top.amount)

				amount -= matched
				top.amount -= matched

				if top.amount > 0 {
					heap.Push(buyHeap, top)
				}
			}

			if amount > 0 {
				heap.Push(sellHeap, Order{
					price:  price,
					amount: amount,
				})
			}
		}
	}

	total := 0

	for buyHeap.Len() > 0 {
		order := heap.Pop(buyHeap).(Order)
		total = (total + order.amount) % MOD
	}

	for sellHeap.Len() > 0 {
		order := heap.Pop(sellHeap).(Order)
		total = (total + order.amount) % MOD
	}

	return total
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 版本使用`container/heap`包，需要手动实现堆接口。 

与 Python 不同，Go 不需要购买堆的负价格，因为我们可以自定义`Less`直接运行。 因此，购买堆自然表现为最大堆。 

匹配和重新插入部分消耗的订单的逻辑与 Python 解决方案相同。

 ## 边缘情况

 ### 部分订单消费

 最常见的错误来源之一是部分匹配。 例如，买单可能仅消耗卖单的一部分。 剩余部分必须以相同的价格留在积压订单中。 

该实现通过以下方式处理此问题：

 1.去除顶堆顺序
 2.减少用量
 3. 如果数量剩余，则将其推回堆中

 这保证了剩余数量不会丢失。 

### 多次连续匹配

 传入订单可能需要与许多积压条目进行匹配。 例如，一个大的买单可能会消耗多个按价格升序排列的卖单。 

单个`if`语句在这里会失败，因为只会发生一笔交易。 该实现正确地使用了`while`循环，匹配继续进行，直到没有有效交易为止。 

### 数量极其巨大

 金额可能大至`10^9`，并且许多这样的订单可以累积。 在某些语言中，总待办事项大小可能超出正常整数范围。 

该解决方案通过以下方式避免溢出问题：

 - 使用Python整数，它会自动扩展
 - 在最终总和中使用模算术
 - 依赖 Go 的 64 位整数行为足以满足约束

 即使对于问题允许的最大输入，这也能确保正确的结果。
