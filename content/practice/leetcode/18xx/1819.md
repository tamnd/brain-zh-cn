 **难度：** 🔴难

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定数组的某些非空子序列的 GCD 可以出现多少个不同的值。 

子序列是通过删除零个或多个元素同时保留顺序而形成的。 由于顺序对于 GCD 运算并不重要，因此真正的挑战是确定可以生成哪些整数作为某些值子集的 GCD。 

例如，如果`nums = [6,10,3]`，可能的子序列包括：

 -`[6]`，GCD = 6
 -`[10]`，GCD = 10
 -`[3]`，GCD = 3
 -`[6,10]`，GCD = 2
 -`[6,3]`，GCD = 3
 -`[10,3]`，GCD = 1
 -`[6,10,3]`，GCD = 1

 不同的 GCD 值是`{1,2,3,6,10}`，所以答案是`5`。 

约束条件极其重要：

 -`nums.length <= 10^5`-`nums[i] <= 2 * 10^5`对所有子序列进行暴力枚举是不可能的，因为大小为`10^5`有`2^100000`子序列。 

最大值仅为`2 * 10^5`，这强烈表明解决方案应该关注值和整除性属性，而不是直接关注子序列。 这是一个经典的数论优化模式。 

一些边缘情况很重要：

 - 仅包含一个数字的数组
 - 具有许多重复项的数组
 - 所有数字互质的数组
 - 所有数字都是一个基值的倍数的数组
 - 数组包含`1`，因为有一次`1`存在，它自动是一个有效的子序列GCD

 该问题保证所有数字都是正整数，因此我们在 GCD 计算中永远不需要处理零或负值。 

## 方法

 ### 蛮力方法

 最直接的方法是生成每个非空子序列，计算其 GCD，并将结果插入到集合中。 

对于每个子序列：

 1. 构建子序列
 2.计算其中所有元素的GCD
 3. 将GCD存储在哈希集中

 最后，集合的大小就是答案。 

这是有效的，因为每个子序列都被检查一次，所以每个可能的子序列 GCD 最终都会被插入到集合中。 

然而，这种做法是完全不可行的。 一个数组`n`元素有`2^n - 1`非空子序列。 即使是为了`n = 30`，这变得巨大。 和`n = 10^5`，这是不可能的。 

### 关键见解

 我们不是生成子序列，而是扭转思维。 

假设我们想知道某个整数是否`g`可以是子序列的 GCD。 

如果`g`是某个子序列的 GCD，那么该子序列中的每个数字都必须能被`g`。 

因此，我们只需要查看数组中的倍数即可`g`。 

现在考虑中的所有数字`nums`可以被整除`g`。 如果所有这些数字的 GCD 等于`g`，那么某个子序列可以实现GCD`g`。 

为什么？ 

因为反复服用GCD只能减少或保持不变。 如果所有倍数的总 GCD`g`恰好变成`g`，则存在一个子集，其 GCD 为`g`。 

这将问题转化为：

 对于每个可能的整数`g`从`1`到`max(nums)`:

 1. 收集所有能被整除的数组值`g`2. 计算他们的 GCD
 3. 如果结果等于`g`, 算一下

 这完全避免了子序列的生成。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × n) | O(2^n × n) | O(不同 GCD 的数量) | 枚举每个子序列 |
 | 最佳| O(M log M) 大约 | O(M)| 使用整除性和 GCD 属性 |

 这里，`M = max(nums)`。 

## 算法演练

 ### 第 1 步：存储所有号码以便快速查找

 我们首先创建一个布尔数组或集合来指示哪些数字存在于`nums`。 

这使我们能够快速检查数组中是否存在特定的倍数。 

例如：```
nums = [6,10,3]
present[3] = true
present[6] = true
present[10] = true
```这很重要，因为稍后我们将迭代多个候选 GCD 值。 

### 步骤 2：迭代每个可能的 GCD 候选者

 我们尝试每个整数`g`从`1`到`max(nums)`。 

问题变成：

 “可以`g`出现为某个子序列的 GCD？”

 ### 步骤 3：检查所有倍数`g`如果`g`是一个子序列 GCD，那么该子序列中的每个元素都可以被整除`g`。 

所以我们迭代：```
g, 2g, 3g, 4g, ...
```最多`max(nums)`。 

对于数组中实际存在的每个倍数，我们将其包含在正在运行的 GCD 计算中。 

### 步骤 4：计算运行 GCD

 假设`g = 2`。 

我们检查数组中所有可被整除的数字`2`。 

如果这些数字的运行 GCD 最终变为`2`， 然后`2`是可以实现的。 

例子：```
nums = [6,10,3]

Multiples of 2 present:
6, 10

gcd(6,10) = 2
```所以`2`是一个有效的子序列GCD。 

### 步骤 5：计算有效的 GCD

 每当运行的 GCD 恰好等于`g`，我们增加答案。 

到那时我们就可以提前停下来`g`，因为额外的数字无法再次增加 GCD。 

### 为什么它有效

 该算法依赖于一个关键的数论属性：

 如果某个子序列有GCD`g`，那么该子序列的每个元素都必须可以被整除`g`。 

因此，子序列必须完全从数组元素的集合中提取，这些元素是`g`。 

现在考虑数组中所有此类倍数的 GCD。 如果这个总体 GCD 等于`g`，则存在一个子集，其 GCD 恰好为`g`。 相反，如果 GCD 仍然大于`g`，那么由这些倍数形成的每个可能的子序列也必须具有大于`g`。 

因此，正确检查所有当前倍数的 GCD 可以确定是否`g`可以作为子序列 GCD 出现。 

## Python 解决方案```python
from typing import List
from math import gcd

class Solution:
    def countDifferentSubsequenceGCDs(self, nums: List[int]) -> int:
        max_num = max(nums)

        present = [False] * (max_num + 1)

        for num in nums:
            present[num] = True

        answer = 0

        for candidate_gcd in range(1, max_num + 1):
            current_gcd = 0

            for multiple in range(candidate_gcd, max_num + 1, candidate_gcd):
                if present[multiple]:
                    current_gcd = gcd(current_gcd, multiple)

                    if current_gcd == candidate_gcd:
                        answer += 1
                        break

        return answer
```实现首先找到数组中的最大值，因为这决定了所有可能的 GCD 值的上限。 

然后我们构建`present`数组，其作用类似于频率表或存在表。 这允许恒定时间检查输入中是否存在数字。 

接下来，我们迭代每个可能的候选 GCD`1`到`max_num`。 

对于每位候选人：

 - 我们初始化`current_gcd`到`0`- 我们迭代候选者的所有倍数
 - 如果数组中存在倍数，我们更新正在运行的 GCD

 数学性质：```python
gcd(0, x) = x
```使初始化变得简单。 

一旦运行的 GCD 等于候选值，我们就知道该候选值是可以实现的，因此我们增加答案并停止处理进一步的倍数。 

提前休息是一个重要的优化，因为一旦 GCD 达到候选值，添加更多数字就无法再次增加它。 

## 解决方案```go
package main

func gcd(a, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func countDifferentSubsequenceGCDs(nums []int) int {
	maxNum := 0

	for _, num := range nums {
		if num > maxNum {
			maxNum = num
		}
	}

	present := make([]bool, maxNum+1)

	for _, num := range nums {
		present[num] = true
	}

	answer := 0

	for candidateGCD := 1; candidateGCD <= maxNum; candidateGCD++ {
		currentGCD := 0

		for multiple := candidateGCD; multiple <= maxNum; multiple += candidateGCD {
			if present[multiple] {
				currentGCD = gcd(currentGCD, multiple)

				if currentGCD == candidateGCD {
					answer++
					break
				}
			}
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是，Go 在标准库中没有为整数提供内置的 GCD 函数，因此我们手动实现 Euclid 算法。 

这`present`切片分配了大小`maxNum + 1`因此索引直接映射到值。 

Go 切片会自动初始化为`false`，这自然适用于存在表。 

整数溢出不是问题，因为所有值都在问题约束范围内。

 ## 边缘情况

 ### 仅包含一个元素的数组

 单元素数组很重要，因为唯一可能的子序列是元素本身。 

例如：```
nums = [7]
```唯一的子序列 GCD 是`7`。 

有缺陷的实现可能会错误地假设较小的除数，例如`1`也是可以实现的。 我们的实现避免了这种情况，因为它仅在当前倍数的运行 GCD 完全等于该候选者时才验证该候选者。 

### 具有许多重复项的数组

 考虑：```
nums = [5,5,5,5]
```即使有很多子序列，但每个非空子序列都有GCD`5`。 

正确答案是`1`。 

我们的实现自然地处理重复项，因为存在表只跟踪值是否存在，而不跟踪它出现的次数。 重复的副本不会改变 GCD 计算。 

### 包含成对互质数的数组

 考虑：```
nums = [2,3,5,7]
```每个单独的数字都是一个有效的 GCD，并且组合不同的素数会产生 GCD`1`。 

不同的 GCD 是：```
1,2,3,5,7
```这种情况很重要，因为它确保算法正确发现`1`通过在多个值上重复进行 GCD 缩减。 

### 无法获得更小的除数的数组

 考虑：```
nums = [4,8,16]
```尽管所有数字都可以被整除`2`, 没有子序列有 GCD`2`。 

GCD 是：```
4,8,16
```我们的算法正确拒绝`2`因为：```
gcd(4,8,16) = 4
```永远不会成为`2`。 

这说明了为什么仅检查整除性是不够的，我们必须计算倍数的实际 GCD。
