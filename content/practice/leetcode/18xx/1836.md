[LeetCode 问题 1836](https://leetcode.com/problems/remove-duplicates-from-an-unsorted-linked-list/)

 **难度：** 🟡 中等
 **主题：** 哈希表、链表

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个单链表的头，其值未排序。 我们的任务是删除其值在列表中任何位置多次出现的每个节点。 

重要的细节是，我们不会在保留一份副本的同时删除重复出现的内容。 相反，如果某个值出现多次，则必须删除包含该值的所有节点。 

例如，在列表中：```
1 -> 2 -> 3 -> 2
```价值`2`出现两次，所以两者`2`必须删除节点。 最终列表变为：```
1 -> 3
```输入代表一个标准的单链表。 每个节点包含一个整数值和一个指向下一个节点的指针。 输出还必须是一个链表，特别是删除所有值多次出现的节点后的原始列表。 

约束条件很重要：

 - 该列表最多可以包含`10^5`节点
 - 节点值也受`10^5`这些限制立即告诉我们，低效的嵌套循环解决方案可能会超时。 一个`O(n^2)`方法将执行高达`10^10`在最坏的情况下，操作速度太慢了。 这强烈表明我们需要一个线性或近线性的解决方案。 

一些边缘情况尤其重要：

 - 每个值都是唯一的列表，该列表应保持不变。 
- 每个值都是重复的列表，结果应该是一个空列表。 
- 由于列表未排序，重复项可能会不连续出现。 
- 头节点本身可能需要删除。 
- 整个列表中可能会出现多个重复值。 

因为列表是未排序的，所以我们不能像在排序链表问题中那样依赖相邻比较。 我们需要一种方法来计算整个列表中全局出现的次数。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查每个节点并计算其值在整个列表中出现的次数。 

对于每个节点：

 1. 再次遍历整个链表。 
2. 计算该节点值的出现次数。 
3. 如果计数大于1，则删除该节点。 

这种方法是正确的，因为每个节点都会与其他节点进行检查，从而保证准确的频率计数。 

然而，性能较差。 如果列表包含`n`节点，那么对于每个节点我们可以扫描所有`n`再次节点。 这导致`O(n^2)`时间复杂度。 

高达`100000`节点，这种方法是不切实际的。 

### 最佳方法

 关键的观察结果是，问题仅取决于每个值在整个列表中出现的次数。 

我们可以：

 1. 遍历列表以构建频率图。 
2.进行第二遍删除频率大于1的节点。 

哈希映射在这里是理想的，因为它允许恒定时间平均查找和插入。 

算法变为：

 - 第一遍：计算频率。 
- 第二遍：仅使用仅出现一次的值重建链表。 

这将时间复杂度降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重新计算每个节点的出现次数 |
 | 最佳| O(n) | O(n) | 使用哈希映射来存储频率 |

 ## 算法演练

 ### 最优算法

 1. 创建一个名为的哈希图`frequency`。 

该映射将存储每个值在链表中出现的次数。 
2. 遍历链表一次，填充频率图。 

对于每个节点：

 - 阅读`node.val`- 增加其在哈希图中的计数

 经过此遍后，我们确切地知道哪些值是重复的。 
3. 在 head 之前创建一个虚拟节点。 

虚拟节点简化了删除逻辑，特别是当原始头本身必须被删除时。 
4.初始化两个指针：

 -`prev`，最初指向虚拟节点
 -`current`，最初指向头部
 5. 再次遍历链表。 

对于每个节点：

 - 向上看`frequency[current.val]`- 如果频率大于一：

 - 通过设置跳过节点`prev.next = current.next`- 否则：

 - 保持节点并移动`prev`前进
 6. 移动`current`每次迭代后向前。 
7. 返回`dummy.next`。 

这可以正确处理所有情况，包括移除原始头时。 

### 为什么它有效

 频率图保证我们知道某个值在整个列表中是出现一次还是多次。 在第二次遍历期间，删除每个具有重复值的节点，同时保留每个唯一值。 由于每个节点在每次传递中都只处理一次，因此生成的链表恰好包含其值在原始列表中只出现过一次的节点。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional
from collections import defaultdict

class Solution:
    def deleteDuplicatesUnsorted(self, head: ListNode) -> ListNode:
        frequency = defaultdict(int)

        current = head

        # First pass: count frequencies
        while current:
            frequency[current.val] += 1
            current = current.next

        dummy = ListNode(0)
        dummy.next = head

        prev = dummy
        current = head

        # Second pass: remove duplicated values
        while current:
            if frequency[current.val] > 1:
                prev.next = current.next
            else:
                prev = current

            current = current.next

        return dummy.next
```该实现遵循前面描述的精确的两遍策略。 

第一部分使用创建频率图`defaultdict(int)`。 这允许在不检查键是否已存在的情况下增加计数。 

第一次遍历遍历整个链表并记录每个值出现的次数。 

接下来，创建一个虚拟节点。 这是一种常见的链表技术，可以简化节点删除逻辑。 如果没有虚拟节点，移除头部将需要特殊处理。 

第二次遍历再次检查每个节点。 如果该节点的值出现多次，则通过重新连接来跳过该节点`prev.next`直接到`current.next`。 否则，该节点仍保留在列表中，并且`prev`正常推进。 

最后，`dummy.next`返回，因为过滤列表的实际头部可能与原始头部不同。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func deleteDuplicatesUnsorted(head *ListNode) *ListNode {
    frequency := make(map[int]int)

    current := head

    // First pass: count frequencies
    for current != nil {
        frequency[current.Val]++
        current = current.Next
    }

    dummy := &ListNode{Next: head}

    prev := dummy
    current = head

    // Second pass: remove duplicated values
    for current != nil {
        if frequency[current.Val] > 1 {
            prev.Next = current.Next
        } else {
            prev = current
        }

        current = current.Next
    }

    return dummy.Next
}
```Go 实现在结构上与 Python 版本相同。 

Go 使用带有类型的内置映射`map[int]int`用于频率计数。 由于Go没有Python的`defaultdict`，缺失的键会自动返回整数的零值，这使得递增变得简单。 

虚拟节点的分配使用：```go
dummy := &ListNode{Next: head}
```指针操作的工作方式与 Python 引用类似，但 Go 需要显式的指针语法。 

实施安全地处理`nil`指针并正确删除节点，即使必须删除头也是如此。

 ## 边缘情况

 当头节点本身必须被删除时，就会出现一种重要的边缘情况。 例如：```
1 -> 1 -> 2 -> 3
```幼稚的实现可能会在删除后失去对新头的跟踪。 虚拟节点通过在头部之前提供一个稳定的节点来干净地解决这个问题。 拆除后，`dummy.next`总是指向正确的新头。 

另一个棘手的情况是所有节点都是重复的：```
2 -> 2 -> 3 -> 3
```在这种情况下，最终列表应该为空。 某些实现错误地留下悬空引用或无法返回`None`。 因为算法会小心地重新连接指针并返回`dummy.next`，结果正确地变成一个空列表。 

非连续的重复也很容易被错误处理：```
1 -> 2 -> 3 -> 1
```由于列表未排序，因此重复项不一定相邻。 仅比较相邻节点的算法在这里将失败。 频率图保证整个列表的全局计数，确保删除所有重复值，无论位置如何。 

最后一个重要的边缘情况是仅包含唯一值的列表。 在这种情况下，不应删除任何节点，并且原始结构应保持完整。 该算法自然地处理这个问题，因为每个频率计数都等于 1，因此在第二次遍历期间所有节点都被保留。
