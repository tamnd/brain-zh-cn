[LeetCode 问题 1820](https://leetcode.com/problems/maximum-number-of-accepted-invitations/)

 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、图论、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们在一对一匹配约束下最大化男孩和女孩之间成功邀请的数量。 

我们被赋予了一个`m x n`二进制矩阵称为`grid`。 

-`grid[i][j] == 1`意思是男孩`i`愿意或者能够邀请女孩`j`-`grid[i][j] == 0`意思是男孩`i`不能邀请女孩`j`每个男生最多可以邀请一名女生，每个女生最多可以接受一名邀请。 目标是确定可以同时存在而不发生冲突的最大配对数量。 

这本质上是二分图上的匹配问题。 

我们可以想到：

 - 男孩作为左侧的节点
 - 女孩作为右侧的节点
 - A`1`在矩阵中作为它们之间的边

 任务变成找到最大数量的边，使得没有两个选定的边共享相同的端点。 这正是最大二分匹配的定义。 

约束条件很重要：

 -`1 <= m, n <= 200`- 可能的边总数可达`200 * 200 = 40,000`对所有可能的分配进行强力搜索是完全不可行的，因为组合的数量呈指数级增长。 

一些重要的边缘情况包括：

 - 一个充满零的矩阵，其中不可能有邀请
 - 一个充满 1 的矩阵，其中答案变为`min(m, n)`- 多个男孩争夺同一个女孩
 - 贪婪分配失败的情况，因为需要重新分配较早的匹配才能获得最佳结果

 最后一点尤其重要。 天真的贪婪策略很容易陷入次优配置。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的将女孩分配给男孩的方法。 

对于每个男孩，我们可以：

 - 跳过指定女孩
 - 尝试男孩可以邀请的每个可用女孩

 然后递归地继续下一个男孩，同时跟踪哪些女孩已经被带走。 

这种方法保证了正确性，因为它会探索每个有效的匹配配置并保留找到的最大大小。 

然而，它太慢了。 

在最坏的情况下，每个男孩都可能与许多女孩配对，从而产生指数级的可能性。 即使进行了修剪，搜索空间也会变得巨大`m`和`n`接近200。 

### 最佳方法

 关键的观察是这个问题是一个经典的最大二分匹配问题。 

我们可以使用增广路径迭代地构建匹配，而不是在全局范围内尝试每个分配。 

这个想法是：

 - 尝试将每个男孩与一个女孩配对
 - 如果想要的女孩已经匹配，请尝试将当前匹配的男孩重新分配给另一个女孩
 - 如果重新分配成功，我们会释放女孩并增加总匹配大小

 这通常使用深度优先搜索来实现。 

DFS 搜索增广路径，这是一系列重新分配的序列，可将匹配总数增加一个。 

由于图尺寸相对较小，因此标准的基于 DFS 的 Kuhn 算法足够高效。

 ## 算法演练

 ### 步骤 1：将问题建模为二分图

 治疗：

 - 每个男孩作为左侧的一个节点
 - 每个女孩作为右侧的一个节点
 - 每个`1`在矩阵中作为边

 我们想要最大数量的不重叠边。 

### 第 2 步：维持当前的女孩任务

 创建一个名为的数组`girl_match`。 

-`girl_match[g] = b`意思是女孩`g`目前与 boy 匹配`b`- 将所有条目初始化为`-1`，意味着最初没有女孩匹配

 这种结构可以让我们快速判断一个女孩是否有空。 

### 第 3 步：尝试匹配每个男孩

 遍历每个男孩。 

对于每个男孩，运行 DFS 来尝试找到一条增广路径。 

如果 DFS 成功，则增加答案，因为我们成功添加了另一场比赛。 

### 步骤 4：DFS 搜索增广路径

 DFS内部：

 1. 遍历所有女孩
 2. 跳过这个男孩不能邀请的女孩
 3. 跳过当前 DFS 通话中已经拜访过的女孩

 对于每个有效的女孩：

 - 将她标记为已访问
 - 如果她不匹配，请立即分配她
 - 否则，递归地尝试在其他地方重新匹配她当前的男孩

 如果重匹配成功：

 - 将当前的女孩分配给新男孩
 - 返回`True`否则继续搜索。 

### 第 5 步：重复直到处理完所有男孩

 每一次成功的 DFS 都会将匹配大小恰好增加 1。 

处理完所有男孩后，答案就是接受邀请的最大数量。 

### 为什么它有效

 该算法之所以有效，是因为每个 DFS 都会搜索一条增广路径。 

增广路径以将匹配总数增加一的方式重新排列现有分配。 重复应用增广路径是二分匹配理论中的一个标准定理，它保证当不再存在增广路径时，匹配是最大的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumInvitations(self, grid: List[List[int]]) -> int:
        m = len(grid)
        n = len(grid[0])

        girl_match = [-1] * n

        def dfs(boy: int, visited: List[bool]) -> bool:
            for girl in range(n):
                if grid[boy][girl] == 0 or visited[girl]:
                    continue

                visited[girl] = True

                if girl_match[girl] == -1:
                    girl_match[girl] = boy
                    return True

                if dfs(girl_match[girl], visited):
                    girl_match[girl] = boy
                    return True

            return False

        matches = 0

        for boy in range(m):
            visited = [False] * n

            if dfs(boy, visited):
                matches += 1

        return matches
```该实现遵循前面描述的确切的增广路径策略。 

这`girl_match`数组存储每个女孩的当前所有者。 最初每个条目都是`-1`，意味着不存在任何分配。 

DFS 函数尝试为当前男孩找到一个有效的女孩。 它会遍历每个可能的女孩并检查是否：

 - 男孩可以邀请她
 - 在当前的 DFS 遍历中尚未探索过她

 的`visited`数组极其重要。 如果没有它，DFS 可能会反复访问同一个女孩并创建无限的递归循环。 

如果一个女孩有空，现任男孩会立即认领她。 

如果她已经匹配，算法会递归地尝试将她当前的伴侣重新定位到另一个可用的女孩。 如果成功，现任男孩将取代她的位置。 

外循环独立处理每个男孩。 每次成功的 DFS 都会将匹配大小增加一。 

## 解决方案```go
func maximumInvitations(grid [][]int) int {
	m := len(grid)
	n := len(grid[0])

	girlMatch := make([]int, n)

	for i := 0; i < n; i++ {
		girlMatch[i] = -1
	}

	var dfs func(int, []bool) bool

	dfs = func(boy int, visited []bool) bool {
		for girl := 0; girl < n; girl++ {
			if grid[boy][girl] == 0 || visited[girl] {
				continue
			}

			visited[girl] = true

			if girlMatch[girl] == -1 {
				girlMatch[girl] = boy
				return true
			}

			if dfs(girlMatch[girl], visited) {
				girlMatch[girl] = boy
				return true
			}
		}

		return false
	}

	matches := 0

	for boy := 0; boy < m; boy++ {
		visited := make([]bool, n)

		if dfs(boy, visited) {
			matches++
		}
	}

	return matches
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于显式切片分配和初始化。 由于 Go 数组默认为`0`，我们必须手动初始化`girlMatch`和`-1`代表无与伦比的女孩。 

DFS 是作为递归闭包实现的。 Go 针对这些约束安全地处理递归，因为递归深度受到男孩数量的限制，男孩数量最多为 200。 

不存在整数溢出问题，因为所有值都非常小。

 基于 DFS 的二分匹配算法对每个男孩处理一次。 在每次 DFS 调用期间，我们可能会检查每个女孩，并递归地触发之前匹配的男孩的额外 DFS 调用。 

在最坏的情况下，这会导致大约`O(m × n × m)`复杂度，这对于`m, n <= 200`。 

空间使用量不大，因为我们只存储：

 - 当前匹配的数组
 - DFS递归期间访问的数组

 ## 边缘情况

 当矩阵仅包含零时，会出现一种重要的边缘情况。 在这种情况下，没有男孩可以邀请任何女孩。 有缺陷的实现可能会意外增加匹配计数或错误处理空 DFS 遍历。 此实现正确返回`0`因为如果没有找到有效的边，每个 DFS 都会立即失败。 

另一个重要的情况是当许多男孩争夺同一个女孩时。 例如：```
[
  [1],
  [1],
  [1]
]
```最终只有一个男孩可以与唯一可用的女孩匹配。 该算法自然地处理这个问题，因为一旦分配了女孩，后面的 DFS 调用就无法找到增广路径。 

一个特别棘手的边缘情况涉及贪婪匹配失败的情况，除非发生重新分配。 考虑：```
[
  [1,1],
  [1,0]
]
```如果男孩 0 贪婪地占有女孩 0，男孩 1 就会被阻止。 但是，如果将男孩 0 重新分配给女孩 1，则两个男孩都可以匹配。 增广路径 DFS 正确地发现了这种重新分配并产生了最佳结果。 

另一个微妙的情况是全连接图。 在这种情况下，有许多可能的有效匹配。 该算法并不关心它找到哪个匹配，只关心总大小是最大的。 无论分配顺序如何，增广路径属性都能保证最优性。
