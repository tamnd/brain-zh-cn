[LeetCode 问题 1831](https://leetcode.com/problems/maximum-transaction-each-day/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`Transactions`其中每一行代表一笔金融交易。 每笔交易都有独特的`transaction_id`，存储在的时间戳`day`列和一个整数`amount`。 

目标是找到其交易 ID`amount`是各自日历日的最高值。 重要的细节是`day`列包括日期和时间，但必须仅按日历日期进行比较。 例如，`2021-04-29 13:28:30`和`2021-04-29 23:39:28`属于同一天，`2021-04-29`。 

如果同一天的多笔交易共享最大金额，则所有交易都必须包含在结果中。 收集所有符合条件的交易 ID 后，最终输出必须按以下顺序排序`transaction_id`按升序排列。 

输入表可以包含每天的多笔交易、一天的单笔交易或最大金额的关联。 由于交易 ID 是唯一的，因此输出中不可能出现重复。 

幼稚的实现可能会在多个地方出错。 一个常见问题是按完整日期时间进行分组，而不是提取日期部分，这会将同一天不同时间发生的事务错误地视为单独的组。 另一个问题是未能包含关联，即使当天多笔交易共享相同的最大金额，也仅返回一笔交易。 

后续询问是否可以在不使用的情况下解决问题`MAX()`聚合函数。 这暗示其他 SQL 模式（例如自联接或窗口函数）也是解决该问题的有效方法。 

## 方法

 ### 蛮力方法

 强力方法将每笔交易与同一天的所有其他交易进行检查。 

对于每笔交易：

 1. 提取其日历日期。 
2. 再次扫描整个表。 
3. 找出同一日期的最大金额。 
4. 如果当前交易的金额等于该最大值，请包含其 ID。 

这是有效的，因为每笔交易都会独立验证它是否是当天最大的交易。 然而，它的效率很低，因为每一行都可能将自身与所有其他行进行比较。 

如果有`n`事务，嵌套扫描产生`O(n²)`时间复杂度。 

### 最佳方法

 关键的见解是问题自然分为两个步骤：

 1. 计算每个日历日的最大交易金额。 
2. 检索金额与每日最大金额匹配的所有交易。 

SQL 聚合非常适合这种类型的分组计算。 我们可以首先按日期对交易进行分组，并计算每组的最大金额。 然后我们将此结果与原始表连接起来以查找所有匹配的行。 

这避免了对表的重复重新扫描，并允许数据库引擎有效地优化分组和连接。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 将每笔交易与同一天的所有其他交易进行比较 |
 | 最佳| 通常为 O(n log n) | O(k) | 使用分组和连接，其中`k`是不同天数 |

 ## 算法演练

 1. 从日历中提取日历日期`day`柱子。 

这`day`列包含日期和时间信息，但问题仅按日期对事务进行分组。 因此我们使用`DATE(day)`隔离日期部分。 
2. 按日历日期对交易进行分组。 

对于每个不同的日期，收集属于该天的所有交易。 
3. 计算每天的最大金额。 

使用`MAX(amount)`，确定每个日期组内的最大交易金额。 
4. 将分组结果连接回原表。 

确定每个日期的最大金额后，将每笔原始交易与其当天的最大值进行比较。 
5. 仅保留匹配的交易。 

如果交易金额等于当天计算的最大值，请包括其交易金额`transaction_id`。 
6. 对结果进行排序。 

对最终输出进行排序`transaction_id`按照问题陈述的要求，按升序排列。 

### 为什么它有效

 分组子查询保证每个日历日都与一个最大金额相关联。 通过将此信息连接回原始表并选择金额与最大值匹配的交易，我们确保包含每笔符合条件的交易，包括平局交易。 由于每笔交易都会根据正确的每日最高限额进行检查，因此结果是完整且正确的。 

## Python 解决方案

 虽然这是一个数据库问题，但 LeetCode 数据库解决方案是用 SQL 编写的。 以下查询是正确的提交。```python
# This problem is solved using SQL, not Python.

SELECT t.transaction_id
FROM Transactions t
JOIN (
    SELECT DATE(day) AS transaction_day,
           MAX(amount) AS max_amount
    FROM Transactions
    GROUP BY DATE(day)
) daily_max
ON DATE(t.day) = daily_max.transaction_day
AND t.amount = daily_max.max_amount
ORDER BY t.transaction_id;
```该解决方案首先创建一个名为的派生表`daily_max`。 该子查询按日历日期对交易进行分组，并计算每天的最大金额。 

外部查询连接原始查询`Transactions`包含此分组结果的表。 连接条件确保两件事：

 1、交易属于同一日历日。 
2、交易金额为当日最高交易金额。 

任何满足这两个条件的交易都是最终答案的一部分。 

最后将结果排序为`transaction_id`按升序排列。

 ## 边缘情况

 ### 多笔交易共享最大金额

 当同一天的几笔交易具有完全相同的最大金额时，就会出现最重要的边缘情况之一。 有缺陷的实现可能会意外地仅返回一笔交易`LIMIT 1`或其他限制性技术。 

该解决方案可以正确处理这种情况，因为连接条件检查是否与每日最大值相等。 每笔匹配交易都会自动包含在内。 

### 一天只能进行一笔交易

 一天可能只包含一笔交易。 在这种情况下，该交易通常是当天的最大交易，并且必须出现在结果中。 

分组逻辑自然会处理这个问题，因为单个元素组的最大值就是该元素本身。 

### 同一日期的不同时间戳

 交易可以在同一天的不同时间发生。 如果实现按完整日期时间值而不是提取的日期进行分组，则每个时间戳将错误地成为其自己的组。 

使用`DATE(day)`确保属于同一日历日的所有时间戳都正确分组在一起。
