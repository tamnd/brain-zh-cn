[LeetCode 问题 1868](https://leetcode.com/problems/product-of-two-run-length-encoded-arrays/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 这个问题要求我们将两个已经以游程编码形式存储的数组相乘，而不将它们完全扩展为普通数组。 

游程编码数组紧凑地存储连续的重复值。 它不是显式存储每个元素，而是存储以下元素对：

 - 价值
 - 连续出现多少次

 例如：```
[5,5,5,5,2,2]
```变成：```
[[5,4],[2,2]]
```任务是计算两个此类编码数组的逐元素乘积。 

如果：```
nums1 = [1,1,1,2,2,2]
nums2 = [6,6,6,3,3,3]
```那么产品数组是：```
[6,6,6,6,6,6]
```其压缩为：```
[[6,6]]
```重要的细节是最终输出还必须以尽可能小的长度进行游程编码。 这意味着具有相同产品价值的相邻细分市场必须合并在一起。 

限制条件很大：

 -`encoded1.length`和`encoded2.length`每个都可以达到`10^5`- 频率也可以很大
 - 扩展后的数组可能会非常巨大

 这立即告诉我们完全扩展阵列是不可行的。 尽管编码表示很小，但解压缩的数组可能包含数十亿个元素。 

该问题保证两个扩展数组具有相同的总长度，从而简化了两种编码之间的同步。 

一些边缘情况很重要：

 - 相邻的产品部分可能需要合并
 - 一个片段可能与另一阵列中的多个片段部分重叠
 - 整个数组可能会折叠成单个编码段
 - 当我们消耗部分段时，频率可能会变为零
 - 最佳解决方案必须完全避免减压

 ## 方法

 ### 蛮力方法

 最直接的解决方案是：

 1. 将两个编码数组展开为其完整形式
 2. 对应元素相乘
 3. 将结果数组压缩回游程编码

 这种方法在概念上很简单并且显然是正确的，因为它直接遵循问题定义。 

例如：```
encoded1 = [[1,3],[2,2]]
encoded2 = [[4,3],[5,2]]
```将扩展到：```
nums1 = [1,1,1,2,2]
nums2 = [4,4,4,5,5]
```然后：```
product = [4,4,4,10,10]
```最后压缩：```
[[4,3],[10,2]]
```问题是可扩展性。 频率可能非常大，因此扩展的数组可能包含太多元素，无法适应内存或有效处理。 

### 最佳方法

 关键的观察是我们实际上从来不需要完全扩展的数组。 

每个编码段已经告诉我们：

 - 哪个值重复
 - 重复多少次

 我们可以直接使用两个指针来处理这两种编码。 

任何时刻：

 - 一个指针引用当前段`encoded1`- 另一个指针引用当前段`encoded2`当前产品值为：```
value1 * value2
```该产品适用的职位数量为：```
min(freq1, freq2)
```因为较短的剩余段决定了重叠的持续时间。 

处理重叠后：

 - 从两个段中减去使用的频率
 - 推进哪个部分耗尽

 这使我们能够仅以压缩形式处理数组，从而实现编码段数量的线性复杂度。 

当它们的乘积值匹配时，我们还会合并相邻的输出段，以确保最小的压缩。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N) | O(N) | 完全扩展两个阵列，对于大频率来说不切实际 |
 | 最佳 | O(m + n) | O(m + n) | 使用两个指针直接处理编码段 |

 这里：

-`N`是扩展数组的大小
 -`m`和`n`是编码数组的长度

 ## 算法演练

 ### 最优二指针算法

 1. 初始化两个指针，每个指针对应一个编码数组。 

指针`i`跟踪当前段`encoded1`，和指针`j`跟踪当前段`encoded2`。 
2. 读取当前值和频率。 

认为：```
encoded1[i] = [value1, freq1]
encoded2[j] = [value2, freq2]
```当前产品值为：```
product = value1 * value2
```3. 确定该产品跨越了多少个位置。 

由于两个段连续重复其值，因此重叠长度为：```
overlap = min(freq1, freq2)
```这意味着产品价值重复`overlap`次。 
4. 将产品细分添加到结果中。 

如果前一个输出段已经具有相同的产品值，则通过增加其频率来合并它们。 

否则，附加一个新段。 
5. 减少剩余频率。 

自从我们使用`overlap`职位：```
freq1 -= overlap
freq2 -= overlap
```6. 推进耗尽的部分。 

如果`freq1`变为零，增量`i`。 

如果`freq2`变为零，增量`j`。 
7. 继续，直到两个编码数组都被完全处理。 

### 为什么它有效

 该算法之所以有效，是因为游程编码将原始数组划分为连续的常量值范围。 

在每一步中，当前段都会在连续范围内定义相同的值。 重叠长度表示两个当前值同时保持活动状态的最大范围。 

通过增量消耗重叠，我们可以精确地模拟逐元素乘法，而无需解压缩。 由于每个位置都被处理一次并且相邻的相等的乘积被立即合并，所以最终的编码保证是最小的和正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findRLEArray(
        self,
        encoded1: List[List[int]],
        encoded2: List[List[int]]
    ) -> List[List[int]]:

        i = 0
        j = 0

        result = []

        while i < len(encoded1) and j < len(encoded2):

            value1, freq1 = encoded1[i]
            value2, freq2 = encoded2[j]

            product = value1 * value2
            overlap = min(freq1, freq2)

            if result and result[-1][0] == product:
                result[-1][1] += overlap
            else:
                result.append([product, overlap])

            encoded1[i][1] -= overlap
            encoded2[j][1] -= overlap

            if encoded1[i][1] == 0:
                i += 1

            if encoded2[j][1] == 0:
                j += 1

        return result
```实现直接遵循两指针策略。 

指针`i`和`j`跟踪两个编码数组中的当前段。 在每次迭代中，算法计算：

 - 当前产品价值
 - 重叠频率

 重叠是在至少一个段耗尽之前可以处理的元素数量。 

结果压缩在施工期间立即处理。 如果新产品与最后存储的产品相匹配，则频率将被合并，而不是附加新的段。 这保证了最小的编码长度，而不需要第二次压缩。 

随着重叠的消耗，输入阵列内的频率会适当降低。 一旦分段频率达到零，相应的指针就会前进到下一个分段。 

循环继续，直到完全处理完所有段。 

## 解决方案```go
func findRLEArray(encoded1 [][]int, encoded2 [][]int) [][]int {

	i := 0
	j := 0

	result := [][]int{}

	for i < len(encoded1) && j < len(encoded2) {

		value1 := encoded1[i][0]
		freq1 := encoded1[i][1]

		value2 := encoded2[j][0]
		freq2 := encoded2[j][1]

		product := value1 * value2

		overlap := freq1
		if freq2 < overlap {
			overlap = freq2
		}

		if len(result) > 0 && result[len(result)-1][0] == product {
			result[len(result)-1][1] += overlap
		} else {
			result = append(result, []int{product, overlap})
		}

		encoded1[i][1] -= overlap
		encoded2[j][1] -= overlap

		if encoded1[i][1] == 0 {
			i++
		}

		if encoded2[j][1] == 0 {
			j++
		}
	}

	return result
}
```Go 的实现与 Python 解决方案非常相似。 

切片用于编码数组和结果。 由于 Go 没有提供内置的`min`对于整数函数，重叠是使用简单的比较手动计算的。 

该算法直接改变输入频率，就像 Python 版本一样。 这避免了用于跟踪剩余计数的额外内存分配。 

整数溢出在这里不是问题，因为最大乘积是：```go
10^4 * 10^4 = 10^8
```适合 Go 的内部`int`类型。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m + n) | 每个编码段被处理一次 |
 | 空间| O(m + n) | 结果可能包含最多所有组合的段转换 |

 该算法从不扩展数组，这是关键的优化。 

中的每个段`encoded1`和`encoded2`最多被访问一次。 每次迭代至少完全消耗一个段，保证线性进度。 

结果数组最多可以包含`m + n - 1`最坏情况下的段，因此输出大小主导辅助空间的使用。

 ## 边缘情况

 ### 相邻的产品细分产生相同的价值

 不同的输入段对可以连续生成相同的产品。 

例如：```
encoded1 = [[1,2],[2,2]]
encoded2 = [[6,2],[3,2]]
```两者都生产产品`6`。 

有缺陷的实现可能会附加：```
[[6,2],[6,2]]
```而不是将它们合并到：```
[[6,4]]
```该实现通过在附加新结果段之前检查最后一个结果段来处理此问题。 

### 一个片段与多个片段重叠

 一个阵列中的单个片段可能与另一阵列中的多个片段部分重叠。 

例如：```
encoded1 = [[5,10]]
encoded2 = [[1,3],[2,4],[3,3]]
```第一段`encoded1`必须从多个细分市场逐步消费`encoded2`。 

幼稚的实现可能会错误地过早地推进指针。 该算法通过仅减去重叠量并仅在频率达到零时推进指针来避免这种情况。 

### 同时段耗尽

 有时，当前的两个段会完全相同地完成。 

例子：```
[1,3]
[2,3]
```处理重叠后两个频率都变为零`3`。 

不正确的实现可能只会推进一个指针，从而导致重复处理或无限循环。 

该解决方案在相减后独立检查两个频率，并在必要时前进两个指针。
