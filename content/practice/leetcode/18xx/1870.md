[LeetCode 问题 1870](https://leetcode.com/problems/minimum-speed-to-arrive-on-time/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们找到在给定浮点数内行驶一系列火车并到达目的地所需的最小恒定速度（以公里每小时为单位）`hour`。 每趟列车都有固定的距离，后续的每趟列车只能在下一个整数小时出发。 每次乘车后的等待时间都会对每个路段的行驶时间产生非线性依赖性。 

输入由一个整数数组组成`dist`在哪里`dist[i]`是距离`i-th`乘坐火车和花车`hour`代表允许的总时间。 输出是允许准时到达的最小整数速度，或者`-1`如果不可能的话。 约束保证距离和列车数量可以很大（`up to 10^5`）， 和`hour`最多有两位小数，这暗示如果我们不小心使用浮点运算，可能会出现精度问题。 

关键边缘情况包括以下场景：`hour`小于列车数量，这将导致无法准时到达，因为除最后一趟列车外的所有列车都强制四舍五入到下一个整数。 

## 方法

 蛮力方法会尝试从以下位置开始的每个速度`1`向上，计算每个速度的总行驶时间，并返回允许到达的第一个速度`hour`。 这种方法可行，但由于限制而太慢（`speed`可以达到`10^7`并且距离可能很大）。 

最佳方法使用**二分搜索速度**。 关键的见解是，随着速度的增加，旅行时间**单调减少**。 这使我们能够有效地搜索满足时间约束的最小速度。 在每个候选速度下，我们计算总行程时间，取除最后一趟列车外每趟列车的时间上限。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(最大速度 * n) | O(1) | O(1) | 迭代所有可能的速度，直到找到可行的速度 |
 | 最佳 | O(n * log(最大速度)) | O(1) | O(1) | 在速度范围上使用二分搜索来找到最小可行速度 |

 ## 算法演练

 1. **初始化二分查找边界**：设置`left = 1`和`right = 10^7`，问题陈述保证它是一个足够的上限。 
2. **二分查找循环**：While`left <= right`，计算中点速度`mid = (left + right) // 2`。 这代表了候选速度。 
3. **计算当前速度下的旅行时间**：对于每次乘坐火车，计算`time = dist[i] / mid`。 对于除最后一列之外的所有列车，将时间**向上舍入到最接近的整数**。 将所有时间相加即可得到总行程时间。 
4. **检查可行性**：如果总行程时间小于或等于`hour`，这个速度是可行的。 移动`right`绑定到`mid - 1`尝试较小的速度。 否则，移动`left`到`mid + 1`尝试更大的速度。 
5. **返回结果**：二分查找结束后，如果找到可行的速度，则返回。 如果没有速度满足条件，则返回`-1`。 

**为什么有效**：随着速度的增加，总行驶时间单调减少。 通过执行二分搜索，我们有效地缩小了满足总时间约束的最小速度。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def minSpeedOnTime(self, dist: List[int], hour: float) -> int:
        left, right = 1, 10**7
        result = -1
        
        while left <= right:
            mid = (left + right) // 2
            total_time = 0.0
            
            for i in range(len(dist)):
                t = dist[i] / mid
                if i != len(dist) - 1:
                    total_time += math.ceil(t)
                else:
                    total_time += t
            
            if total_time <= hour:
                result = mid
                right = mid - 1
            else:
                left = mid + 1
        
        return result
```此实现初始化二分搜索边界，迭代可能的速度，计算除最后一列列车之外的所有列车的行程时间，并相应地更新搜索边界。 最终结果是最小可行速度或`-1`如果没有速度。 

## 解决方案```go
import (
    "math"
)

func minSpeedOnTime(dist []int, hour float64) int {
    left, right := 1, 10000000
    result := -1
    
    for left <= right {
        mid := (left + right) / 2
        totalTime := 0.0
        
        for i := 0; i < len(dist); i++ {
            t := float64(dist[i]) / float64(mid)
            if i != len(dist)-1 {
                totalTime += math.Ceil(t)
            } else {
                totalTime += t
            }
        }
        
        if totalTime <= hour {
            result = mid
            right = mid - 1
        } else {
            left = mid + 1
        }
    }
    
    return result
}
```Go 特定的差异包括整数和浮点数之间除法的显式类型转换，以及使用`math.Ceil`用于四舍五入。 

## 工作示例

 **示例1**：`dist = [1,3,2], hour = 6`二分搜索从中间值开始测试速度。 当速度为 1 时，行程时间为`[1, 3, 2]`四舍五入为`[1, 3, 2]`。 总计 = 6，匹配`hour`。 最小速度 = 1。 

**示例2**：`dist = [1,3,2], hour = 2.7`二分查找找到最低速度 3。行驶时间：`[1/3, 3/3, 2/3]`四舍五入为`[1, 1, 0.6667]`。 总计 ≈ 2.6667 ≤ 2.7。 

**示例3**：`dist = [1,3,2], hour = 1.9`即使在最大速度 10^7 下，总行程时间也超过 1.9。 返回`-1`。

 ## 边缘情况

 第一个重要的边缘情况是`hour`小于列车数量，不包括末班车。 这保证了不可能，因为即使所有火车都以无限速度行驶，仅等待时间就会超过`hour`。 该解决方案在二分搜索中自然地处理了这个问题。 

第二种边缘情况是最后一列火车的行驶时间不完整。 只有末班车可以有小数小时而不进行四舍五入，我们会小心处理这个问题，不申请`ceil`到最后一段。 

第三种边缘情况是大输入尺寸，例如最大`dist[i]`和`n`。 我们的算法与`n`每次迭代都以最大可能的速度进行二分搜索和对数搜索，即使在最大的约束下也能确保性能。 

该实现正确处理浮点运算和舍入，通过使用适当的数据类型避免整数溢出，并有效地找到最小可行速度或返回`-1`。
