[LeetCode 问题 1866](https://leetcode.com/problems/number-of-ways-to-rearrange-sticks-with-k-sticks-visible/)

 **难度：** 🔴难
 **主题：** 数学、动态规划、组合学

 ## 解决方案

 ## 问题理解

 问题给了我们`n`具有独特长度的棍棒`1`到`n`。 我们必须按某种顺序排列这些木棍，以便准确地`k`从左侧看时可以看到棍子。 

如果一根棍子之前的每根棍子都较短，则该棍子是可见的。 换句话说，如果从左向右扫描时创建了新的最大高度，则棒是可见的。 

例如，在安排中`[1,3,2,5,4]`：

 -`1`是可见的，因为它之前没有任何东西。 
-`3`是可见的，因为它比`1`。 
-`2`不可见，因为`3`阻止它。 
-`5`之所以可见，是因为它比之前的所有东西都高。 
-`4`不可见，因为`5`阻止它。 

所以正好有 3 根可见的棍子。 

任务是计算数字的排列有多少种`1`通过`n`准确地生产`k`可见的棍子。 由于排列的数量增长得非常快，我们返回模数的答案`10^9 + 7`。 

约束条件很重要：

 -`1 <= n <= 1000`-`1 <= k <= n`暴力解决方案需要检查所有`n!`排列，即使对于中等值也是不可能的`n`。 例如：

-`10! = 3,628,800`-`15!`已经超过一万亿
 -`1000!`天文数字般巨大

 这立即表明我们需要一个组合或动态规划解决方案。 

一些边缘情况很重要：

 -`k = 1`，只有一根棍子可见。 当最高的棍子首先出现时就会发生这种情况。 
-`k = n`，每根棍子都是可见的。 仅当棍子严格按递增顺序排列时才会发生这种情况。 
-`n = 1`，只有一种排列和一根可见的棍子。 
- 大值，例如`n = 1000`，其中没有记忆或阶乘枚举的递归将失败。 

## 方法

 ### 蛮力方法

 最直接的想法是生成木棍的每种排列，并计算每种排列产生的可见木棍数量。 

对于每个排列：

 1. 从左到右扫描。 
2. 追踪目前为止看到的最高的棍子。 
3. 每当出现更高的棍子时，增加可见计数。 
4. 如果可见计数等于`k`，增加答案。 

这种方法是正确的，因为它明确地检查了每种可能的安排。 

然而，它太慢了。 有`n!`排列，并且每个排列需要`O(n)`努力计算可见的棍子。 总复杂度变为`O(n × n!)`，这对于`n = 1000`。 

### 关键见解

 我们可以使用动态编程逐步构建答案，而不是直接构建完整的排列。 

假设我们已经知道有效排列的数量`n - 1`棍子。 怎样才能插入最大的木棍`n`？ 

最大的棍子很特别，因为它每次出现时总是可见的。 

有两种可能：

 1. 放置棒`n`在前面。 

- 它变得可见。 
- 其余`n - 1`棍棒必须做出贡献`k - 1`可见的棍子。 
- 贡献：`dp[n-1][k-1]`2. 放置棒`n`除了前面以外的其他地方。 

- 自从`n`是最高的棍子，它将阻挡其后所有物体的可见性。 
- 它不会创建超出之前已存在的新可见计数。 
- 有`n - 1`第一个位置之后可能的插入位置。 
- 贡献：`(n - 1) * dp[n-1][k]`这给出了递归式：$$dp[n][k] = dp[n-1][k-1] + (n-1) \times dp[n-1][k]$$这种重现是使问题变得易于处理的核心见解。

 | --- | --- | --- | --- |
 | 蛮力 | O(n × n!) | O(n) | 枚举每个排列 |
 | 最优动态规划| O(n × k) | O(n × k) | O(n × k) | O(n × k) | 使用组合递归 |

 ## 算法演练

 1. 定义`dp[i][j]`作为排列方式的数量`i`坚持这样完全`j`从左侧可以看到棍子。 
2. 初始化基本情况：

 -`dp[1][1] = 1`- 使用一根棍子，就只有一种排列和一根可见的棍子。 
3. 迭代自`i = 2`到`n`。 

- 我们计算所有涉及的答案`i`坚持使用先前计算的状态。 
4. 对于每个`j`从`1`到`min(i, k)`：

 - 考虑把最大的棍子放在哪里`i`。 
5.案例1，放置棒`i`在开始时：

 - 最大的棍子立即可见。 
- 其余`i - 1`棍棒必须做出贡献`j - 1`可见的棍子。 
- 添加：`dp[i-1][j-1]`6.案例2，放置棒`i`第一个位置之后的某处：

 - 有`i - 1`选择。 
- 既然坚持`i`最高，稍后插入时不会增加可见计数。 
- 添加：`(i - 1) * dp[i-1][j]`7. 合并两个贡献：$$dp[i][j] = dp[i-1][j-1] + (i-1)\times dp[i-1][j]$$8. 应用模数`10^9 + 7`每次更新后以避免溢出。 
9. 返回`dp[n][k]`。 

### 为什么它有效

 递归根据最大棒的位置将所有有效排列划分为两个不相交的类别。 每个有效排列都属于这些类别之一，并且这两个类别都以可预测的方式保留可见性计数。 由于递归穷尽了所有可能性且没有重叠，因此 DP 计算有效排列的确切数量。 

## Python 解决方案```python
class Solution:
    def rearrangeSticks(self, n: int, k: int) -> int:
        MOD = 10**9 + 7

        dp = [[0] * (k + 1) for _ in range(n + 1)]
        dp[1][1] = 1

        for sticks in range(2, n + 1):
            for visible in range(1, min(sticks, k) + 1):
                place_front = dp[sticks - 1][visible - 1]

                place_elsewhere = (
                    (sticks - 1) * dp[sticks - 1][visible]
                ) % MOD

                dp[sticks][visible] = (
                    place_front + place_elsewhere
                ) % MOD

        return dp[n][k]
```该实现直接反映了递归关系。 

这`dp`表存储棒计数和可见计数的每个组合的有效排列的数量。 

外循环迭代当前正在考虑的木棍数量。 内部循环计算该棒计数的所有可能的可见计数。 

对于每个州：

 -`place_front`对应于将最大的棍子放在第一位。 
-`place_elsewhere`相当于将最大的木棍插入剩余位置之一。 

在乘法和加法之后应用模运算，以确保值保持在范围内。 

最后，`dp[n][k]`包含所需的答案。 

## 解决方案```go
func rearrangeSticks(n int, k int) int {
    const MOD int = 1_000_000_007

    dp := make([][]int, n+1)
    for i := range dp {
        dp[i] = make([]int, k+1)
    }

    dp[1][1] = 1

    for sticks := 2; sticks <= n; sticks++ {
        limit := k
        if sticks < k {
            limit = sticks
        }

        for visible := 1; visible <= limit; visible++ {
            placeFront := dp[sticks-1][visible-1]

            placeElsewhere := int(
                (int64(sticks-1) * int64(dp[sticks-1][visible])) % int64(MOD),
            )

            dp[sticks][visible] =
                (placeFront + placeElsewhere) % MOD
        }
    }

    return dp[n][k]
}
```Go 实现遵循与 Python 版本相同的递归和 DP 结构。 

Go 特有的主要考虑因素是整数溢出。 之间的乘法`(sticks - 1)`和`dp[sticks-1][visible]`可以超过 32 位整数限制，因此乘法是使用`int64`在转换回之前`int`。 

切片用于动态构造二维DP表。

 | 测量 | 复杂性 | 说明|

 DP表包含`(n + 1) × (k + 1)`州。 每个状态都需要使用递归关系进行持续工作，因此总运行时间为`O(n × k)`。

 ## 边缘情况

 一个重要的边缘情况是`k = 1`。 在这种情况下，只有第一根棍子可见。 因此，最高的棍子必须首先出现，否则另一根棍子会在它之前出现。 有缺陷的实现可能会错误地计算额外的排列。 DP 通过递归自然地处理这个问题，并且结果值匹配`(n - 1)!`。 

另一个关键的边缘情况是`k = n`。 每根棍子都必须是可见的，这意味着排列必须是严格递增的。 确实存在一种有效的安排。 递归正确地保留了此属性，因为每个新的最大棒必须插入到前面可见的位置。 

最小的输入，`n = 1`和`k = 1`，也很重要。 如果没有正确的基本情况，递归将引用无效状态并产生零而不是一。 正在初始化`dp[1][1] = 1`确保 DP 从最小的有效配置正确构建。 

一个微妙的边缘情况涉及模运算。 中间乘法值可能变得非常大，尤其是接近`n = 1000`。 在乘法和加法之后不取模，在 Go 等语言中可能会发生整数溢出。 该实现通过在每次转换期间一致地应用模来避免这种情况。
