 # LeetCode 1847：最近的房间

 ## 问题理解

 ## 问题理解

 该问题为我们提供了一组酒店房间，其中每个房间都有两个属性：

 - 唯一的房间ID
 - 房间大小

 我们还收到了一些询问。 每个查询包含：

 -`preferred`：我们想要入住的房间ID
 -`minSize`：可接受的最小房间尺寸

 对于每个查询，我们必须选择一个满足大小要求的房间：

 -`room.size >= minSize`在所有有效房间中，我们想要ID最接近的房间`preferred`。 

换句话说，我们最小化：$$|roomId - preferred|$$如果多个房间的最小距离相同，我们选择较小的房间ID。 

如果没有房间满足最小尺寸要求，则答案是`-1`。 

### 示例解释

 假设有效的房间 ID 为：```
1, 5, 9
```和：```
preferred = 6
```距离为：```
|1 - 6| = 5
|5 - 6| = 1
|9 - 6| = 3
```最近的房间是`5`。 

如果有效的房间 ID 是：```
4, 8
```和：```
preferred = 6
```然后：```
|4 - 6| = 2
|8 - 6| = 2
```两者同样接近，所以我们选择较小的 ID，即`4`。 

### 约束告诉我们什么

 - 最多`10^5`房间。 
- 最多`10^4`查询。 
- 房间 ID 和大小可以大到`10^7`。 

扫描所有房间以查找每个查询的强力解决方案需要：$$O(nk)$$运营。 

在最坏的情况下：$$10^5 \times 10^4 = 10^9$$这太慢了。 

因此，我们需要一种更接近于：$$O((n+k)\log n)$$或类似的。 

### 重要的边缘案例

 有几种情况需要特殊处理：

 - 没有房间满足最小面积要求。 
- 仅存在一间有效房间。 
- 首选房间 ID 本身存在且有效。 
- 两个候选房间距首选 ID 的距离相等。 
- 所有房间均满足查询。 
- 房间 ID 未排序。 
- 多个查询有不同的最小大小要求。 

房间ID的唯一性保证了我们永远不需要处理重复的ID。 

## 方法

 ### 蛮力

 对于每个查询：

 1. 遍历每个房间。 
2. 忽略尺寸小于的房间`minSize`。 
3. 计算到的距离`preferred`。 
4. 记录迄今为止见过的最好的房间。 
5. 当距离相等时应用平局决胜规则。 

这是正确的，因为每个有效的房间都会被检查。 

然而，对于每个查询，我们都会扫描所有房间。 

时间复杂度：$$O(nk)$$对于给定的限制来说这太慢了。 

### 关键见解

 困难的部分是最小尺寸限制。 

假设我们按降序处理查询`minSize`。 

同时，按房间大小降序对房间进行排序。 

处理需要大小的查询时`S`，我们可以将所有大小至少为`S`。 

由于查询是从较大的尺寸要求到较小的尺寸要求进行处理的，因此一旦房间符合条件，它仍然符合所有后续查询的条件。 

这将问题转化为：

 > 给定一组动态增长的有效房间 ID，找到最接近的 ID`preferred`。 

如果房间ID按排序顺序维护，我们只需要检查：

 - 第一个ID大于或等于`preferred`- 紧接其前面的 ID

 这些是唯一可能最接近的候选人。 

具有二分查找的有序集正好支持此操作。

 1. 排序`rooms`按房间大小降序排列。 
2. 对于每个查询，存储：

 - 首选身份证件
 - 最小尺寸
 - 原始查询索引
 3. 按降序对查询进行排序`minSize`。 
4.维护当前满足大小要求的房间ID的排序集合。 
5. 使用指针进入已排序的房间列表。 
6. 处理来自最大的查询`minSize`到最小。 
7. 对于当前查询，插入大小至少为查询的每个房间`minSize`进入已排序的集合。 
8. 如果集合为空，则回答`-1`。 
9. 否则执行二分查找`preferred`。

12. 如果距离相等，则选择较小的房间 ID。 
13. 使用查询的原始索引存储结果。 
14. 继续，直到处理完所有查询。 
15. 返回答案数组。 

### 为什么它有效

 处理最小大小的查询时`S`，当前存储的每个房间至少有大小`S`，并且每个未存储的房间的大小小于`S`。 

因此，数据结构准确包含该查询的有效房间。 

由于房间 ID 已排序，因此距离最近的房间`preferred`必须是：

 - 的前身`preferred`- 的继任者`preferred`任何比前一个房间更左边或比后一个房间更右边的房间必须有更大的距离。 

因此，仅检查这两个候选者总是会产生正确的答案。 
我们还收到多个查询。 每个查询包含：

 - 首选房间 ID
 - 所需的最小房间面积

 对于每个查询，我们必须找到一个满足最小尺寸要求并且最接近首选房间 ID 的房间。 

紧密度由下式决定：```
abs(roomID - preferred)
```在所有有效房间中，我们选择绝对差值最小的一间。 如果多个房间的距离相同，我们选择较小的房间ID。 

如果没有房间满足最小尺寸要求，则答案是`-1`。 

重要的细节是房间 ID 不是连续的，并且可以大到`10^7`。 我们不能使用按房间 ID 索引的数组。 限制也很大：

 - 最多`10^5`房间
 - 最多`10^4`查询

 检查每个房间的每个查询的简单方法最多需要：```
10^5 * 10^4 = 10^9
```操作，这太慢了。 

另一个重要的观察是查询条件有两个独立的部分：

 - 尺寸过滤
 - 最近的ID搜索

 面临的挑战是有效维护满足当前最小尺寸约束的房间集，同时还能够快速找到最近的房间 ID。 

一些边缘情况在这里很重要：

 - 没有房间满足最小尺寸
 - 多个房间同样接近首选ID
 - 首选 ID 本身可能存在
 - 查询可能要求非常大的最小尺寸
 - 房间 ID 稀疏且无序

 该问题保证了房间 ID 是唯一的，从而简化了有序查找。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立处理每个查询。 

对于每个查询：

 1. 遍历所有房间
 2. 仅保留大小至少为`minSize`3. 计算与首选房间ID的绝对距离
 4. 追踪最佳候选人
 5. 通过选择较小的房间ID来应用平局规则

 这种方法是正确的，因为它明确地检查每个可能的有效房间并根据问题规则选择最佳房间。 

然而，对于给定的约束，其性能是不可接受的。 如果我们有`k`查询和`n`房间，总复杂度变为：```
O(n * k)
```和`n = 10^5`和`k = 10^4`，这变得太大了。 

### 最佳方法

 关键的见解是，具有较大最小大小要求的查询形成具有较小要求的查询子集。 

假设我们排序：

 - 房间按大小降序排列
 - 按最小尺寸降序查询

 然后，在处理来自最大的查询时`minSize`为了最小，我们可以逐步添加满足当前阈值的房间。 

在任何时刻，我们都会维护一个数据结构，其中包含精确的房间 ID，其大小对于当前查询来说足够大。 

现在问题变成：

 > 给定一组已排序的房间 ID，找到最接近目标的值。 

使用二分搜索可以有效地解决这个问题。 

因此，最优策略结合了：

 - 离线查询处理
 - 排序
 - 对有序房间 ID 进行二分搜索

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(1) | O(1) | 检查每个房间的每个查询 |
 | 最佳| O((n + k) log n) | O((n + k) log n) | O(n) | 对房间和查询进行排序，然后对有效房间 ID 使用二分搜索 |

 ## 算法演练

 1. 按房间大小降序对所有房间进行排序。 

这使我们能够首先处理大房间。 随着查询要求变得不那么严格，更多的房间变得符合条件。 
2. 将原始索引附加到查询并按以下方式对查询进行排序`minSize`按降序排列。 

由于排序会改变查询的顺序，因此我们必须记住每个查询的原始位置，以便我们可以将答案正确地放置在结果数组中。 
3. 维护有效房间 ID 的排序列表。 

当我们处理查询时，我们插入大小足以满足当前查询的房间。 
4. 将指针放在已排序的 rooms 数组上。 

对于每个查询：

 - 当前房间的大小至少是查询的大小`minSize`- 将其房间ID插入排序结构中
 - 前进指针

 这保证了数据结构始终包含对当前查询有效的房间。 
5. 执行二分查找找到最接近的房间ID。 

由于房间 ID 是按排序顺序存储的：

 - 使用二分查找来查找插入位置`preferred`- 检查该职位的候选人
 - 检查紧邻其之前的候选者

 这些是唯一可能的最近的房间。 
6. 应用打破平局规则。 

如果两个候选人的距离相等：

 - 选择较小的房间ID
 7. 将答案存储在原来的查询位置。 

由于查询之前已排序，因此我们使用保存的索引来重建最终的输出顺序。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 在处理最小尺寸的查询之前`m`，有序结构包含所有且仅大小至少为`m`。 

因为查询是按降序处理的`minSize`，房间只需要插入一次。 

二分搜索保证我们检查首选值附近最接近的房间 ID。 由于房间 ID 已排序，因此最近的有效房间必须是插入点周围的直接邻居之一。 

因此，每个查询都会得到正确回答。

from typing import List
from sortedcontainers import SortedList

class Solution:
    def closestRoom(self, rooms: List[List[int]], queries: List[List[int]]) -> List[int]:
        rooms.sort(key=lambda x: -x[1])

        indexed_queries = [
            (min_size, preferred, idx)
            for idx, (preferred, min_size) in enumerate(queries)
        ]
        indexed_queries.sort(reverse=True)

        room_ids = SortedList()
        answers = [-1] * len(queries)

        room_idx = 0
        n = len(rooms)

        for min_size, preferred, query_idx in indexed_queries:
            while room_idx < n and rooms[room_idx][1] >= min_size:
                room_ids.add(rooms[room_idx][0])
                room_idx += 1

            if not room_ids:
                continue

            pos = room_ids.bisect_left(preferred)

            best_room = -1
            best_dist = float("inf")

            if pos < len(room_ids):
                candidate = room_ids[pos]
                best_room = candidate
                best_dist = abs(candidate - preferred)

            if pos > 0:
                candidate = room_ids[pos - 1]
                dist = abs(candidate - preferred)

                if (
                    dist < best_dist
                    or (dist == best_dist and candidate < best_room)
                ):
                    best_room = candidate
                    best_dist = dist

            answers[query_idx] = best_room
from bisect import bisect_left, insort
from typing import List

class Solution:
    def closestRoom(self, rooms: List[List[int]], queries: List[List[int]]) -> List[int]:
        # Sort rooms by size descending
        rooms.sort(key=lambda x: -x[1])

        # Add original indices to queries
        indexed_queries = [
            (preferred, min_size, index)
            for index, (preferred, min_size) in enumerate(queries)
        ]

        # Sort queries by min_size descending
        indexed_queries.sort(key=lambda x: -x[1])

        answers = [-1] * len(queries)

        valid_room_ids = []
        room_pointer = 0

        for preferred, min_size, query_index in indexed_queries:

            # Add all rooms that satisfy the size requirement
            while (
                room_pointer < len(rooms)
                and rooms[room_pointer][1] >= min_size
            ):
                room_id = rooms[room_pointer][0]
                insort(valid_room_ids, room_id)
                room_pointer += 1

            # No valid rooms
            if not valid_room_ids:
                continue

            # Find insertion position
            position = bisect_left(valid_room_ids, preferred)

            best_room = -1
            best_distance = float("inf")

            # Check right candidate
            if position < len(valid_room_ids):
                candidate = valid_room_ids[position]
                distance = abs(candidate - preferred)

                if (
                    distance < best_distance
                    or (
                        distance == best_distance
                        and candidate < best_room
                    )
                ):
                    best_room = candidate
                    best_distance = distance

            # Check left candidate
            if position > 0:
                candidate = valid_room_ids[position - 1]
                distance = abs(candidate - preferred)

                if (
                    distance < best_distance
                    or (
                        distance == best_distance
                        and candidate < best_room
                    )
                ):
                    best_room = candidate
                    best_distance = distance

            answers[query_index] = best_room

        return answers

 房间按大小降序排列，以便首先处理较大的房间。 

查询还按其最小大小要求排序。 这使我们能够逐步添加房间。 变量`room_idx`跟踪哪些房间已经插入到有序集中。`SortedList`按排序顺序维护房间 ID 并支持：

 - 插入`O(log n)`- 二分查找`O(log n)`对于每个查询，二分查找找到插入位置`preferred`。 

那个位置的房间就是后继候选者。 

紧邻其前面的房间是前任候选者。 

选择两者中最接近的一个，ID 较小的获胜。 

最后，结果被写回到原来的查询位置。 
实现首先按大小降序对房间进行排序。 这确保了随着查询限制的减少，我们可以不断添加更多有效房间，而无需删除任何房间。 

在排序之前，查询会使用其原始索引进行扩充。 这是必要的，因为输出必须保留原始查询顺序。 

这`valid_room_ids`list 按排序顺序维护所有当前符合条件的房间 ID。 蟒蛇的`bisect`模块允许高效的二分搜索来定位距离首选 ID 最近的房间。 

对于每个查询，都会添加房间，直到包含满足当前最小大小的所有房间。 由于房间和查询均按大小降序排序，因此每个房间仅插入一次。 

准备好有效的房间 ID 后，二分搜索会找到首选房间 ID 的插入位置。 最近的有效房间必须是：

 - 第一个大于或等于首选ID的房间
 - 房间小于首选 ID 的房间

 该实现会检查两位候选人并正确应用平局打破规则。

	})

		minSize  int
		preferred int
		index    int
	}

			minSize:  q[1],
			preferred: q[0],
			index:    i,
		}

		return qs[i].minSize > qs[j].minSize
	})

			tree.Put(rooms[roomIdx][0], nil)
			roomIdx++
		}

			ans[q.index] = -1

				bestRoom = id
				bestDist = dist
			}
		}

	return ans

一个重要的区别是 Go 不提供内置的有序多重集结构。 为了维护排序的房间 ID，实现手动将元素插入到正确的位置，使用`sort.SearchInts`和切片移位`copy`。 

与 Python 不同，Go 需要查询元数据的显式结构定义。 

该算法仍然保证每个房间只插入一次，并且每个查询仅执行对数二进制搜索。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O((n + k) log n) | O((n + k) log n) | 每个房间插入一次，每次查询执行对数运算 |
 | 空间| O(n + k) | 有序集加上索引查询和答案数组 |

 房间整理一次，费用`O(n log n)`。 查询被排序一次，成本`O(k log k)`。 

每个房间在有序结构中只插入一次，有助于`O(n log n)`总工作量。 

每个查询执行恒定数量的二分搜索操作，有助于`O(k log n)`。 

结合所有项得出：$$O((n+k)\log n)$$时间复杂度和`O(n + k)`辅助空间。 
| 时间 | O((n + k) log n) | O((n + k) log n) | 排序占主导地位，每个查询都执行二分查找 |
 | 空间| O(n) | 存储有效的房间 ID 和查询元数据 |

 房间排序和查询需要：```
O(n log n + k log k)
```每个房间插入一次，每个查询执行二分搜索。 

因此，总复杂度变为：```
O((n + k) log n)
```辅助空间主要由：

 - 排序后的有效房间ID结构
 - 索引查询数组
 - 结果数组

 总而言之，这需要线性额外空间。

 ## 边缘情况

 ### 没有房间满足最小面积要求

 查询可能需要比每个可用房间都大的房间大小。 在这种情况下，处理查询时有序集仍为空。 算法立即返回`-1`对于该查询。 这可以避免任何无效的二分查找操作。 

### 两侧距离相等

 假设有效的房间 ID 是`1`和`3`， 尽管`preferred = 2`。 两个房间都有距离`1`离开。 该问题需要选择较小的房间ID。 该实现显式检查相等距离并选择较小的 ID，以确保正确的平局打破行为。 

### 首选 ID 超出有效房间范围

 如果每个有效房间 ID 都小于`preferred`，不会有上限候选人。 类似地，如果每个有效的房间 ID 都大于`preferred`, there will be no floor candidate. 该实现在比较距离之前独立检查每个候选者是否存在，从而正确处理这两种情况。 

### 房间 ID 精确匹配

 If a valid room has ID equal to`preferred`，二分查找直接定位。 它的距离为零，这是可能的最小距离。 该算法自然会选择它，而不需要任何特殊情况的代码。 

### 具有不同大小要求的多个查询

 查询可能具有非常不同的最小大小阈值。 按降序处理它们`minSize`确保房间仅添加一次。 这是保持算法高效同时仍然保证每个查询的正确性的关键不变量。

## Edge Cases

### No Rooms Satisfy the Minimum Size

A query may require a room size larger than every available room. This is a common source of bugs because binary search structures may be empty.

For example:

```房间= [[1,2]]
 查询 = [[5,10]]```

No room satisfies the size requirement.

The implementation explicitly checks whether the valid room structure is empty before performing binary search. If it is empty, the answer remains `-1`.

### Tie Between Two Equally Close Rooms

Suppose two rooms are equally distant from the preferred ID:

```房间 = [[1,5],[3,5]]
 查询 = [2,5]```

Both room IDs are distance `1` away.

The problem requires choosing the smaller room ID. This is easy to mishandle if the implementation only updates the answer when a strictly smaller distance is found.

The solution explicitly compares room IDs when distances are equal and selects the smaller candidate.

### Preferred Room Does Not Exist

The preferred room ID may not actually exist among valid rooms.

For example:

```房间 = [[1,5],[10,5]]
 查询 = [6,5]
 ````

 最近的房间可以是插入点周围的邻居。 

这就是该算法检查以下两项的原因：

 - 第一个大于或等于首选值的房间ID
 - 就在它前面的房间

 在许多情况下，仅检查一侧会产生错误的答案。
