[LeetCode 问题 1855](https://leetcode.com/problems/maximum-distance- Between-a-pair-of-values/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找

 ## 解决方案

 ## 问题理解

 给你两个整数数组，`nums1`和`nums2`，并且两个数组均按非递增顺序排序。 这意味着当我们从左向右移动时，这些值要么保持不变，要么减少。 

一对索引`(i, j)`如果满足两个条件，则视为有效：

 1.`i <= j`2.`nums1[i] <= nums2[j]`对于每个有效对，距离定义为：$$j - i$$目标是找到所有有效对之间的最大可能距离。 如果不存在有效对，则答案为`0`。 

重要的细节是两个数组都已按降序排序。 这种结构使我们能够设计有效的算法。 

例如，假设：```
nums1 = [55,30,5,4,2]
nums2 = [100,20,10,10,5]
```如果我们选择`i = 2`和`j = 4`:```
nums1[2] = 5
nums2[4] = 5
```自从：```
2 <= 4
5 <= 5
```该对有效，距离为：```
4 - 2 = 2
```限制条件很大：```
1 <= nums1.length, nums2.length <= 100000
```这立即告诉我们二次解会太慢。 一个$O(n \times m)$解决方案可能需要最多$10^{10}$在最坏的情况下进行操作，这远远超出了可接受的范围。 

该问题保证：

 - 两个数组都非空
 - 值为正整数
 - 数组已经按非递增顺序排序

 这些保证非常重要，因为排序顺序可以实现高效的指针移动和二分搜索优化。 

一些边缘情况很重要：

 - 不存在有效的对
 - 数组只有一个元素
 - 所有配对均有效
 - 数组包含许多重复值
 -`nums1`比 短得多或长得多`nums2`正确的解决方案必须有效地处理所有这些问题。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每一个可能的对`(i, j)`。 

对于每个索引`i`在`nums1`，我们迭代每个索引`j`在`nums2`。 对于每一对，我们验证：```
i <= j
nums1[i] <= nums2[j]
```如果该对有效，我们计算距离`j - i`并更新最大答案。 

这种方法是正确的，因为它详尽地检查了所有可能的对。 任何有效的配对都不能被遗漏。 

然而，对于给定的约束，其性能是不可接受的。 如果两个数组都包含`100000`元素，嵌套循环最多需要：$$100000 \times 100000 = 10^{10}$$比较。 

这太慢了。 

### 最佳两指针方法

 关键的观察结果来自两个数组的排序顺序。 

因为数组是非递增的：

 - 在任一数组中向右移动都不会增加值
 - 一旦某个指针配置的条件失败，我们通常可以智能地移动指针，而无需重新访问以前的状态

 我们使用两个指针：

 -`i`为了`nums1`-`j`为了`nums2`策略是：

 - 展开`j`在该货币对保持有效的情况下尽可能
 - 如果该对无效，则移动`i`前进
 - 确保`j >= i`任何时候

 这是有效的，因为两个指针都只向前移动。 指针不会向后移动，这保证了线性时间复杂度。

 ## 算法演练

 ### 最优两指针算法

 1.初始化两个指针：

 -`i = 0`为了`nums1`-`j = 0`为了`nums2`同时初始化：

 -`max_distance = 0`2. 当两个指针都在其数组内时继续。 
3. 在每一步中，检查当前对是否`(i, j)`有效：

 -`i <= j`-`nums1[i] <= nums2[j]`4. 如果该对有效：

 - 计算距离`j - i`- 更新`max_distance`- 移动`j`向前尝试达到更大的距离
 5. 如果该对无效：

 - 移动`i`向前因为`nums1[i]`太大了
 - 如果`i`变得大于`j`， 移动`j`匹配`i`6. 继续，直到一个指针到达其数组的末尾。 
7. 返回`max_distance`。 

### 为什么它有效

 该算法依赖于两个数组的单调排序。 

当一对`(i, j)`有效，增加`j`可能会产生更大的距离，所以我们不断扩大。 

当一对无效时，增加`j`进一步无济于事，因为`nums2[j]`只能保持不变或者减少。 因此，恢复有效性的唯一方法就是移动`i`向前。 

由于每个指针仅向前移动而从不向后移动，因此每个数组位置最多被处理一次。 这保证了线性时间复杂度，同时仍然探索所有潜在的最佳对。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxDistance(self, nums1: List[int], nums2: List[int]) -> int:
        i = 0
        j = 0
        max_distance = 0

        while i < len(nums1) and j < len(nums2):
            if nums1[i] <= nums2[j]:
                max_distance = max(max_distance, j - i)
                j += 1
            else:
                i += 1

                if i > j:
                    j = i

        return max_distance
```实现直接遵循两指针策略。 

我们维护两个指数，`i`和`j`，代表位置`nums1`和`nums2`。 

在循环内，我们首先测试当前对是否有效。 

如果有效，我们会更新答案并移动`j`前进，因为增加`j`增加距离。 

如果该对无效，`nums1[i]`相比而言太大`nums2[j]`。 自从`nums2`是非增加的、移动的`j`进一步向右不会增加其价值。 因此，我们搬家`i`改为向前。 

调整：```python
if i > j:
    j = i
```确保条件`i <= j`始终保持。 

由于两个指针仅向前移动，因此迭代总数是线性的。 

## 解决方案```go
func maxDistance(nums1 []int, nums2 []int) int {
    i := 0
    j := 0
    maxDistance := 0

    for i < len(nums1) && j < len(nums2) {
        if nums1[i] <= nums2[j] {
            if j-i > maxDistance {
                maxDistance = j - i
            }
            j++
        } else {
            i++

            if i > j {
                j = i
            }
        }
    }

    return maxDistance
}
```Go 实现几乎完全反映了 Python 逻辑。 

Go 中的切片的行为与动态数组类似，因此索引访问仍然很简单。 

不存在整数溢出问题，因为最大可能距离是`100000`，它很容易适合 Go 的内部`int`类型。 

与 Python 不同，Go 需要显式变量声明和手动最大比较，而不是使用内置变量`max()`功能。

 ## 边缘情况

 当不存在有效对时，就会出现一种重要的边缘情况。 例如：```
nums1 = [10,9,8]
nums2 = [1,1,1]
```中的每个值`nums1`大于中的每个值`nums2`，所以条件`nums1[i] <= nums2[j]`永远不会满足。 有缺陷的实现可能会意外地产生负距离或无法干净地处理这个问题。 当前的实现正确返回`0`因为`max_distance`开始于`0`并且仅针对有效对进行更新。 

另一个重要的边缘情况是所有对都有效。 考虑：```
nums1 = [1,1,1]
nums2 = [10,10,10]
```每次比较都成功，因此算法不断扩展`j`。 最大距离成为最大可能值，`2`。 此案例验证了算法正确地探索更远的索引，而不是停在第一个有效对上。 

当需要指针同步时，会出现第三种重要的边缘情况。 认为：```
nums1 = [100]
nums2 = [1,1,1]
```最初，`(0,0)`是无效的，所以`i`向前移动。 如果不小心处理，`j`可能会变得小于`i`，违反所需条件`i <= j`。 该实现使用以下方法来防止这种情况发生：```
if i > j:
    j = i
```这保证了未来的比较始终满足索引排序要求。 

另一个微妙的边缘情况涉及重复值。 数组如：```
nums1 = [5,5,5]
nums2 = [5,5,5,5]
```包含许多等价比较。 当重复出现相同的值时，某些实现会意外地跳过有效距离。 两个指针方法可以自然地处理重复项，因为条件明确允许相等：```
nums1[i] <= nums2[j]
```结果，算法正确地发现了最远的有效对。
