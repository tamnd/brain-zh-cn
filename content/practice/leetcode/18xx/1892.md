 ## 解决方案

 ## 问题理解

 这个问题要求我们实现一个基于用户的友谊和他们的页面喜欢的**页面推荐系统**。 我们有两个数据库表：`Friendship`和`Likes`。 这`Friendship`表包含成对的朋友用户，并且`Likes`表包含成对的用户和他们喜欢的页面。 

目标是根据以下规则向每个用户推荐页面：如果**至少一个用户的朋友喜欢该页面**，但用户自己**尚未喜欢该页面**，则向用户推荐该页面。 输出应包括`user_id`,`page_id`，以及喜欢该页面的朋友数量`friends_likes`。 

重要的澄清包括：友谊是双向的，所以如果`(1, 2)`存在于`Friendship`，用户 1 都是用户 2 的朋友，反之亦然。 此外，用户可能没有朋友，或者可能喜欢他们的朋友喜欢的所有页面，在这种情况下，将不会有针对该用户的推荐。 

边缘情况包括没有朋友的用户、喜欢其朋友喜欢的所有页面的用户、多个朋友喜欢的页面（应该正确计数）以及仅显示为`user2_id`在`Friendship`。 

## 方法

 ### 暴力方法

 一种简单的方法是迭代每个用户，检索他们所有的朋友，然后为每个朋友检索他们喜欢的页面。 对于每个页面，检查用户是否已经喜欢它。 如果没有，请增加一个计数器来计算有多少朋友喜欢此页面。 这种方法有效，但需要多个嵌套循环：一个对用户，一个对朋友，一个对喜欢的页面。 对于大型数据集，这变得非常慢。 

### 最佳方法

 关键的见解是 SQL 允许我们**有效地连接表**。 我们可以首先构造一整套双向的友谊对，将其与`Likes`表查找朋友喜欢的所有页面，然后排除用户已经喜欢的页面。 最后，我们分组`user_id`和`page_id`计算喜欢每个页面的朋友数量。 这避免了嵌套循环并有效地使用数据库集操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(U * F * P) | O(P)| 遍历每个用户和每个朋友的喜欢的页面； 大数据速度慢|
 | 最佳| O(F + L) | O(F + L) | 使用 SQL join 和 group by 高效统计好友的点赞数 |

 ## 算法演练

 1. **使友谊正常化**：构建一个列表`(user_id, friend_id)`双向配对，因此友谊是双向的。 
2. **加入喜欢的朋友**：对于每个`(user_id, friend_id)`配对，加入`Likes`桌上`friend_id`获得每个朋友喜欢的页面。 
3. **排除已经喜欢的页面**：左连接或使用`WHERE NOT EXISTS`条件来保证`user_id`还没有喜欢该页面。 
4. **统计喜欢每个页面的朋友**：对结果进行分组`user_id`和`page_id`并使用`COUNT(*)`计算有多少朋友喜欢该页面。 
5. **返回结果**：将最终结果输出为表格`user_id`,`page_id`， 和`friends_likes`。 

**为什么有效**：通过与喜欢的朋友建立友谊并过滤掉用户已经喜欢的页面，我们保证捕获所有候选推荐。 分组可确保每个页面的好友数量准确。 

## Python 解决方案```python
class Solution:
    def recommendPages(self, Friendship: list[list[int]], Likes: list[list[int]]) -> list[list[int]]:
        from collections import defaultdict
        
        friends = defaultdict(set)
        user_likes = defaultdict(set)
        
        for u1, u2 in Friendship:
            friends[u1].add(u2)
            friends[u2].add(u1)
        
        for u, p in Likes:
            user_likes[u].add(p)
        
        recommendations = []
        
        for user in friends:
            candidate_pages = defaultdict(int)
            for friend in friends[user]:
                for page in user_likes.get(friend, []):
                    if page not in user_likes[user]:
                        candidate_pages[page] += 1
            for page, count in candidate_pages.items():
                recommendations.append([user, page, count])
        
        return recommendations
```Python实现构建了双向友谊图和用户喜欢图。 对于每个用户，它会迭代朋友喜欢的页面，计算喜欢的数量，排除用户已经喜欢的页面，并收集结果。 

## 解决方案```go
package main

func RecommendPages(Friendship [][]int, Likes [][]int) [][]int {
    friends := make(map[int]map[int]bool)
    userLikes := make(map[int]map[int]bool)
    
    for _, f := range Friendship {
        u1, u2 := f[0], f[1]
        if friends[u1] == nil {
            friends[u1] = make(map[int]bool)
        }
        if friends[u2] == nil {
            friends[u2] = make(map[int]bool)
        }
        friends[u1][u2] = true
        friends[u2][u1] = true
    }
    
    for _, l := range Likes {
        u, p := l[0], l[1]
        if userLikes[u] == nil {
            userLikes[u] = make(map[int]bool)
        }
        userLikes[u][p] = true
    }
    
    var recommendations [][]int
    
    for user, frSet := range friends {
        pageCount := make(map[int]int)
        for friend := range frSet {
            for page := range userLikes[friend] {
                if !userLikes[user][page] {
                    pageCount[page]++
                }
            }
        }
        for page, count := range pageCount {
            recommendations = append(recommendations, []int{user, page, count})
        }
    }
    
    return recommendations
}
```Go 解决方案镜像了 Python 版本，使用地图的地图来跟踪朋友和喜好。 Go 需要显式的映射初始化并且不允许默认的空集，因此我们确保在添加元素之前创建每个映射。
