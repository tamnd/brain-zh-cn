 # LeetCode 1840 - 最大建筑高度

 ## 问题理解

 这个问题要求我们构造高度`n`建筑物排列成一条直线，同时满足一些限制。 

每个建筑物都有一个非负整数高度。 建筑`1`必须始终有高度`0`。 此外，相邻建筑物的高度差异不能超过`1`。 这意味着如果一栋建筑物有高度`h`，下一栋建筑只能有高度`h - 1`,`h`， 或者`h + 1`，假设高度保持非负值。 

除了这些全局限制之外，一些建筑物还有明确的上限。 数组`restrictions`包含对`[id, maxHeight]`, 意思是建筑`id`不能超过`maxHeight`。 

目标不是显式构造全高度数组。 相反，我们只需要确定任何建筑物在满足所有约束的情况下可以达到的最大可能高度。 

输入尺寸很大：

 -`n`可以大到`10^9`-`restrictions.length`可以大到`10^5`的巨大价值`n`立即告诉我们，我们无法一一模拟所有建筑物。 任何依赖于迭代每个建筑位置的解决方案都会太慢。 

重要的观察是，只有受限制的建筑物才具有直接影响。 在受限位置之间，高度变化完全由最多的坡度约束控制`1`每一步。 

一些边缘情况很重要：

 - 可能根本没有任何限制。 在这种情况下，最高的建筑物就是`n - 1`，因为高度可以增加`1`从建筑开始`1`。 
- 除非进行调整，否则限制可能会不一致。 例如，如果一栋建筑被迫很低，附近的限制也可能需要减少。 
- 最后一个建筑物可能不会出现在限制数组中。 我们仍然必须考虑到这一点。 
- 限制可以以任意顺序出现，因此需要排序。 

## 方法

 ### 蛮力方法

 强力策略将尝试在尊重所有约束的同时为每座建筑物指定高度。 

一种可能性是：

 1. 初始化所有建筑物的最大可行高度。 
2. 反复向左和向右传播约束，直到最多所有相邻差异`1`。 
3. 跟踪最大结果高度。 

这种方法是正确的，因为最终所有约束都会通过反复松弛而得到满足。 

然而，对于给定的约束，这是完全不切实际的。 自从`n`可以达到`10^9`，即使存储所有建筑物高度也是不可能的。 

暴力破解的想法失败了，因为它单独对待每个建筑物，而问题的真正结构仅取决于限制边界。 

### 最佳方法

 关键的见解是只有受限制的建筑物才重要。 

假设我们知道两个位置的最大允许高度：

 -`(x1, h1)`-`(x2, h2)`因为相邻的高度最多可以相差`1`，它们之间的可行高度轮廓形成“山”形。 

这些位置之间可达到的最高点仅取决于：

 - 他们之间的距离
 - 端点高度限制

 这将问题转化为受限位置之间的约束传播。 

该算法分三个阶段工作：

 1.添加隐式限制：

 - 建筑物`1`有高度`0`- 建筑`n`最初最多可以是`n - 1`2. 按位置对限制进行排序。 
3. 执行：

 - 从左到右的传球
 - 从右向左传球

 这些通道收紧了所有限制高度，使它们变得相互一致。 

之后，每个相邻的限制对独立地确定它们之间可达到的最高峰值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 或更糟 | O(n) | 大的不可能`n`|
 | 最佳| O(m log m) | O(米) |`m = restrictions.length`，使用排序和约束传播 |

 ## 算法演练

 ### 第 1 步：添加隐式限制

 建筑`1`必须始终有高度`0`，所以我们添加：```
[1, 0]
```如果建设`n`尚未受到限制，我们添加：```
[n, n - 1]
```为什么`n - 1`？ 

从建筑开始`1`在高处`0`，最大可能的高度增加超过`n - 1`步骤正是`n - 1`。 

这给出了最后一座建筑的自然上限。 

### 第 2 步：排序限制

 我们通过构建索引对所有限制进行排序。 

这使我们能够有效地处理邻近限制。 

假设排序后我们有：```
[id1, h1], [id2, h2]
```他们之间的距离是：```
d = id2 - id1
```因为高度最多可以改变`1`每一步：```
h2 <= h1 + d
```类似地：```
h1 <= h2 + d
```这些不等式定义了相邻限制之间的可行关系。 

### 步骤 3：从左到右的约束传播

 我们从左到右扫描。 

对于每个限制：```
currentHeight = min(currentHeight, previousHeight + distance)
```这确保当前限制可以从前一个限制到达。 

如果没有这个通行证，一些限制可能会要求不可能的向上跳跃。 

### 步骤 4：从右到左的约束传播

 我们现在从右向左扫描。 

对于每个限制：```
currentHeight = min(currentHeight, nextHeight + distance)
```这确保了相反方向的可行性。 

这两个通道共同保证了全局一致性。 

### 步骤 5：计算限制之间的最大峰值

 现在考虑两个相邻限制：```
(x1, h1)
(x2, h2)
```让：```
d = x2 - x1
```当我们从较低的一侧尽可能增加，然后向另一个端点下降时，可能会出现最高的峰值。 

可达到的最大高度为：```
(h1 + h2 + d) // 2
```该公式来自平衡上升和下降坡度。 

我们计算每个相邻对的该值并取最大值。 

### 为什么它有效

 经过两次传播之后，每个限制都变得全局可行。 这意味着任何相邻的限制对都可以使用有效的斜率连接。 

在两个可行的端点之间，最大化高度的最佳策略始终是在下降之前爬得尽可能高。 因为坡度极限是`1`，可达到的最高点正是中点平衡公式：```
(h1 + h2 + d) // 2
```因此，取所有相邻间隔的最大值即可得出总体上可达到的最高建筑物。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxBuilding(self, n: int, restrictions: List[List[int]]) -> int:
        restrictions.append([1, 0])

        has_last = False
        for building_id, _ in restrictions:
            if building_id == n:
                has_last = True
                break

        if not has_last:
            restrictions.append([n, n - 1])

        restrictions.sort()

        # Left-to-right pass
        for i in range(1, len(restrictions)):
            prev_id, prev_height = restrictions[i - 1]
            curr_id, curr_height = restrictions[i]

            max_allowed = prev_height + (curr_id - prev_id)
            restrictions[i][1] = min(curr_height, max_allowed)

        # Right-to-left pass
        for i in range(len(restrictions) - 2, -1, -1):
            next_id, next_height = restrictions[i + 1]
            curr_id, curr_height = restrictions[i]

            max_allowed = next_height + (next_id - curr_id)
            restrictions[i][1] = min(curr_height, max_allowed)

        answer = 0

        # Compute best peak between adjacent restrictions
        for i in range(1, len(restrictions)):
            left_id, left_height = restrictions[i - 1]
            right_id, right_height = restrictions[i]

            distance = right_id - left_id

            peak = (left_height + right_height + distance) // 2
            answer = max(answer, peak)

        return answer
```实施首先插入强制限制`[1, 0]`。 

接下来，它确保构建`n`有明确的限制。 即使问题可能没有提供，添加`[n, n - 1]`简化了后续处理，因为每个间隔现在都有一个定义的端点。 

然后根据建筑物位置对限制进行排序。 

从左到右的传递强制每个限制都可以在坡度约束下从前一个限制到达。 如果限制太高，就会减少。 

从右到左的传递从相反方向执行对称调整。 

此时，所有限制在全球范围内都是可行的。 

最后，该算法检查每个相邻对并使用中点公式计算它们之间可达到的最高峰值。 

返回所有间隔的最大值。 

## 解决方案```go
package main

import "sort"

func maxBuilding(n int, restrictions [][]int) int {
	restrictions = append(restrictions, []int{1, 0})

	hasLast := false
	for _, r := range restrictions {
		if r[0] == n {
			hasLast = true
			break
		}
	}

	if !hasLast {
		restrictions = append(restrictions, []int{n, n - 1})
	}

	sort.Slice(restrictions, func(i, j int) bool {
		return restrictions[i][0] < restrictions[j][0]
	})

	// Left-to-right pass
	for i := 1; i < len(restrictions); i++ {
		prevID := restrictions[i-1][0]
		prevHeight := restrictions[i-1][1]

		currID := restrictions[i][0]
		currHeight := restrictions[i][1]

		maxAllowed := prevHeight + (currID - prevID)

		if currHeight > maxAllowed {
			restrictions[i][1] = maxAllowed
		}
	}

	// Right-to-left pass
	for i := len(restrictions) - 2; i >= 0; i-- {
		nextID := restrictions[i+1][0]
		nextHeight := restrictions[i+1][1]

		currID := restrictions[i][0]
		currHeight := restrictions[i][1]

		maxAllowed := nextHeight + (nextID - currID)

		if currHeight > maxAllowed {
			restrictions[i][1] = maxAllowed
		}
	}

	answer := 0

	for i := 1; i < len(restrictions); i++ {
		leftID := restrictions[i-1][0]
		leftHeight := restrictions[i-1][1]

		rightID := restrictions[i][0]
		rightHeight := restrictions[i][1]

		distance := rightID - leftID

		peak := (leftHeight + rightHeight + distance) / 2

		if peak > answer {
			answer = peak
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

主要区别在于使用`sort.Slice`用于对限制进行排序。 

Go 切片是就地修改的，因此更新限制高度直接改变底层数据结构，无需额外复制。 

整数溢出不是一个问题，因为在现代系统上最大可能值仍然在 Go 的 64 位整数范围内，而 LeetCode 的`int`type 足以满足这些约束。

 ## 边缘情况

 当完全没有限制时，就会出现一种重要的边缘情况。 幼稚的实现可能会错误地返回`0`或因不存在间隔而失败。 正确的行为是身高可以增加`1`从建筑开始`1`，产生最高高度`n - 1`。 该实现通过显式添加来处理此问题`[1,0]`和`[n,n-1]`。 

当限制最初不一致时，就会发生另一个棘手的情况。 例如：```
[[2,0],[5,10]]
```建筑物的限制`5`无法真正达到高度`10`因为建筑物之间只有三级台阶`2`和`5`。 从左到右的传播过程会自动将不可能的高度降低到最大可行值。 

当最高点位于限制之间而不是直接位于限制上时，就会出现第三种重要的边缘情况。 许多不正确的解决方案仅检查受限制的建筑物本身。 然而，实际的最大值可能出现在高度先上升然后下降的区间的中间。 中点公式可以正确计算该隐藏峰值。 

另一个微妙的情况是最终建筑物已经出现在限制列表中。 该实现避免了为构建添加重复的限制`n`，防止错误的间隔计算或重复处理。
