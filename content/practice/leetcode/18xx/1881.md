[LeetCode 问题 1881](https://leetcode.com/problems/maximum-value-after-insertion/)

 **难度：** 🟡 中等
 **主题：** 字符串、贪婪

 ## 解决方案

 ## 问题理解

 这个问题要求我们插入一个数字`x`变成一个很大的整数`n`，表示为字符串，位于最大化结果数值的位置。 

整数`n`可以是正值，也可以是负值。 由于数量可能非常大，最多可达`10^5`由于字符长，我们无法在大多数编程语言中安全地将其转换为整数类型。 相反，我们必须直接使用字符串表示形式。 

对于正数，最大化该值意味着使该数字在正常数值意义上尽可能大。 由于前面的数字比较后面的数字对整体价值的贡献更大，因此我们通常希望插入`x`如果可以提高数量，请尽早进行。 

对于负数，情况相反。 像这样的数字`-123`大于`-523`因为它的负面影响较小。 因此，为了最大化负数，我们希望它的大小尽可能小。 这改变了插入策略。 

输入包括：

 -`n`，整数的字符串表示形式
 -`x`，一个数字`1`到`9`输出应该是一个字符串，表示插入后的最大可能值`x`正好一次。 

这些约束告诉我们一些重要的事情：

 -`n.length`可以大到`100000`，这立即排除了昂贵的算法，例如生成所有可能的插入并比较它们。 
- 数字保证在之间`1`和`9`，这意味着输入中没有零。 
- 负数总是以`'-'`。 
- 由于数字可能超出正常的整数限制，因此需要进行字符串操作。 

有几种边缘情况值得尽早识别：

 - 如果所有数字都已经大于`x`为正数，那么`x`应附在最后。 
- 如果所有数字都小于`x`为正数时，`x`应插入靠近前部的位置。 
- 对于负数，比较逻辑相反，因为最小化幅度会使值最大化。 
- 如果`x`等于现有数字，多个插入位置可能会产生相同的答案。 

## 方法

 ### 蛮力方法

 解决这个问题的一个简单方法是尝试插入`x`在字符串中每个可能的位置，计算结果数字，并选择最大的数字。 

对于一个长度的字符串`n`， 有`n + 1`可能的插入点。 在每个位置，我们创建一个新字符串`x`插入。 然后我们比较所有生成的候选者并保留最大值。 

这种方法是正确的，因为它详尽地评估了每个有效的插入可能性，保证找到最佳答案。 

然而，它的效率很低。 创建每个候选字符串需要`O(n)`时间，我们这样做是为了`n + 1`职位。 由于比较也可能会花费`O(n)`，总复杂度变为`O(n²)`。 和`n`最多`10^5`，这太慢了。 

### 最优贪心法

 关键的观察是可以贪婪地确定插入位置。 

对于**正数**，前面的数字更重要。 我们应该插入`x`在**小于的第一个数字之前`x`**，因为用较大的前导数字替换较小的前导数字可以最大程度地增加价值。 

例如：`n = "469"`和`x = 5`我们从左到右扫描：

 -`4 < 5`,立即插入

 结果：`"5469"`任何稍后的插入都会更小，因为第一个数字将保留`4`。 

对于**负数**，最大化该值意味着最小化绝对大小。 我们应该插入`x`在**大于的第一个数字之前`x`**，使数字减少负值。 

例如：`n = "-763"`和`x = 5`我们扫描减号后：

 -`7 > 5`,立即插入

 结果：`"-5763"`与稍后插入相比，这使得幅度更小。 

由于我们只扫描一次并立即插入到最佳位置，因此解决方案以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n²) | 尝试每个插入位置并比较结果 |
 | 最佳| O(n) | O(n) | 单次贪婪扫描寻找最佳插入点 |

 ## 算法演练

 1. 转换`x`到一个字符串中，以便可以将其插入`n`。 
2. 检查是否`n`通过测试第一个字符是否为负`'-'`。 
3.如果`n`为正数，从左向右扫描，寻找第一个小于的数字`x`。 

- 如果`digit < x`， 插入`x`该数字之前。 
- 这是有效的，因为较早的位置在十进制表示中具有更大的意义。 
4. 如果没有找到这样的数字，则追加`x`在最后。 

- 这意味着每个数字都已经大于或等于`x`。 
5.如果`n`为负数，跳过减号并扫描数字。 

- 查找大于的第一个数字`x`。 
6. 什么时候`digit > x`， 插入`x`该数字之前。 

- 这可以尽早减少负面影响。 
7. 如果不存在有效的插入点，则追加`x`到最后。 

### 为什么它有效

 贪心选择之所以有效，是因为十进制数是按字典顺序由前面的数字决定的。 对于正数，插入`x`在第一个较小的数字最大化最显着的不同位置之前。 对于负数，插入`x`在第一个较大的数字最小化最早可能位置的幅度之前。 由于较早的位置支配较晚的位置，因此任何延迟的插入都会产生更糟糕的结果。 

## Python 解决方案```python
class Solution:
    def maxValue(self, n: str, x: int) -> str:
        digit = str(x)

        # Negative number
        if n[0] == '-':
            for i in range(1, len(n)):
                if n[i] > digit:
                    return n[:i] + digit + n[i:]

            return n + digit

        # Positive number
        for i in range(len(n)):
            if n[i] < digit:
                return n[:i] + digit + n[i:]

        return n + digit
```实现从转换开始`x`到字符串中，以便可以直接与中的字符进行比较`n`。 

第一个主分支检查该数字是否为负数。 如果`n[0] == '-'`，我们跳过索引`0`因为减号之前不允许插入。 

对于负数，代码搜索大于的第一个数字`x`。 一旦找到，就会插入`x`立即并返回结果。 立即返回很重要，因为最早的有效位置始终是最佳的。 

如果不存在这样的数字，则将该数字附加在末尾。 

对于正数，逻辑是对称的，但比较相反。 我们搜索第一个小于的数字`x`。 一旦找到，就会立即插入。 

如果扫描结束时没有找到有效位置，则在末尾追加会产生最大的可能值。 

## 解决方案```go
func maxValue(n string, x int) string {
	digit := byte('0' + x)

	// Negative number
	if n[0] == '-' {
		for i := 1; i < len(n); i++ {
			if n[i] > digit {
				return n[:i] + string(digit) + n[i:]
			}
		}

		return n + string(digit)
	}

	// Positive number
	for i := 0; i < len(n); i++ {
		if n[i] < digit {
			return n[:i] + string(digit) + n[i:]
		}
	}

	return n + string(digit)
}
```Go 实现遵循与 Python 版本完全相同的贪婪逻辑。 

而不是转换`x`到一个字符串中，我们使用以下命令创建字节表示：```go
digit := byte('0' + x)
```这是可行的，因为 ASCII 数字是连续的。 

Go 中的字符串切片对于这个问题非常有效，因为我们在一次扫描后只执行一次插入。 由于输入大小可以达到`10^5`，避免循环内重复分配很重要。 

整数溢出不是问题，因为该算法永远不会将数字转换为整数类型。 一切都作为字符串操作来处理。

 ## 边缘情况

 ### 所有数字都大于`x`为正数

 考虑：```
n = "987"
x = 1
```有缺陷的实现可能会尝试过早插入。 由于每个数字都已经大于`1`，最好的做法是在末尾添加。 该实现通过完成扫描并返回来正确处理此问题`n + digit`。 

### 所有数字都小于`x`为正数

 考虑：```
n = "123"
x = 9
```最佳插入点是开头，因为`9`比每个现有数字都大。 该实现发现第一个数字小于`9`立即并插入到索引处`0`。 

### 逻辑相反的负数

 考虑：```
n = "-763"
x = 5
```一个常见的错误是应用与正数相同的比较逻辑。 这会错误地最大化绝对幅度。 相反，对于负数，我们在第一个大于的数字之前插入`x`，使负数减少。 该实现显式地分支为负值的单独逻辑。 

### 等数

 考虑：```
n = "999"
x = 9
```自从插入`9`任何地方都给出相同的结果，算法应该保持稳定并且不要不必要地过早插入。 因为条件检查严格`<`对于正数和`>`对于负数，自然跳过相同的数字，并将该数字附加在末尾。
