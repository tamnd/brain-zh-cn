 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们从两个数据库表中计算出完整的联赛表，`Teams`和`Matches`。 

这`Teams`表包含联盟中每支球队的身份。 每一行代表一个团队并包含一个独特的`team_id`以及相应的`team_name`。 

这`Matches`表包含球队之间比赛的结果。 每行描述一场比赛，包括：

 - 主队
 - 客队
 - 主队进球数
 - 客队进球数

 从这些比赛中，我们必须计算每支球队的联赛统计数据。 

对于每个团队，我们需要计算：

 -`matches_played`, 主队或客队的总场数
 -`points`，根据足球计分规则：

 - 获胜 = 3 分
 - 平局 = 1 分
 - 损失 = 0 分
 -`goal_for`, 球队的总进球数
 -`goal_against`, 总失球数
 -`goal_diff`，计算为`goal_for - goal_against`最终结果必须按照联赛排名规则进行排序：

 1. 更高`points`第一
 2. 如果积分相同，则更高`goal_diff`第一
 3. 如果仍然绑在一起，则较小`team_name`按字典顺序

 重要的观察是每场比赛同时为两支不同的球队提供统计数据。 一个幼稚的实现可能会单独扫描整个`Matches`每个团队的表，但这会重复处理相同的行并且效率低下。 

该问题保证了每个`(home_team_id, away_team_id)`配对是唯一的，这意味着同一主客队之间不存在重复的比赛记录。 它还保证有效的团队参考。 

一些边缘情况很重要：

 - 球队可能打了零场比赛
 - 球队只能以主队或客队身份出现
 - 比赛可能以平局结束
 - 多支球队可以以相同的分数和净胜球结束
 - 球队可能有负净胜球
 - 一支球队可以在所有比赛中进球为零

 正确的解决方案必须干净利落地处理所有这些情况。 

## 方法

 ### 蛮力方法

 暴力解决方案独立处理每个团队。 

对于每支球队来说`Teams`表，我们扫描整个`Matches`表并检查球队是否参加了每场比赛。 如果是这样，我们更新：

 - 参加的比赛
 - 进球数
 - 失球数
 - 获得的积分

 这种方法很简单，因为每个团队的统计数据都是从头开始独立计算的。 这一逻辑很容易推理，因为所有计算一次都仅限于一个团队。 

但是，此方法会重复扫描相同的匹配项。 如果有`T`团队和`M`匹配，然后我们处理匹配表`T`时间分开，造成不必要的重复工作。 

### 最佳方法

 关键的见解是，每场比赛都会向两支球队（主队和客队）提供信息。 

我们无需单独扫描每支球队的所有比赛，而是可以处理每场比赛一次并立即更新两支参赛球队的统计数据。 

我们维护一个汇总统计结构，索引为`team_id`。 当我们迭代匹配时：

 - 增加两支球队的比赛次数
 - 添加进球数和失球数
 - 根据结果分配分数

 处理完所有匹配后，我们将计算出的统计数据与`Teams`用于检索团队名称并计算的表`goal_diff`。 

这极大地减少了重复工作，因为每个匹配项都只处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(T × M) | O(T)| 单独扫描每支球队的所有比赛 |
 | 最佳| O(T + M) | O(T)| 处理每场比赛一次并增量汇总统计数据 |

 ## 算法演练

 1. 创建索引为的统计结构`team_id`。 

对于每个团队，我们存储：

 - 参加的比赛
 - 点
 - 目标
 - 目标反对

 哈希映射是理想的，因为它提供恒定的时间更新和查找。 
2. 将每支球队的统计数据初始化为零。 

这很重要，因为有些球队可能不会出现在任何比赛中。 这些球队仍必须出现在最终结果中。 
3. 迭代每场比赛`Matches`桌子。 

对于每场比赛：

 - 确定主队和客队
 - 读取两支球队的进球数
 4. 更新已进行的比赛。 

两支球队都参加了这场比赛，因此增加了他们的实力`matches_played`数数。 
5.更新进球数和失球数。 

对于主队：

 - 添加`home_team_goals`达到目标
 - 添加`away_team_goals`目标

 对于客队：

 - 添加`away_team_goals`达到目标
 - 添加`home_team_goals`目标
 6. 分配分数。 

比较目标：

 - 如果主场进球>客场进球，主队得3分
 - 如果客场进球数>主场进球数，则客队得 3 分
 - 否则两队各得 1 分
 7. 构建最终结果。 

对于每个团队：

 - 检索累积的统计数据
 - 计算`goal_diff = goal_for - goal_against`- 附上团队名称
 8. 对结果进行排序。 

应用所需的订购：

 - 下降点
 - 净胜球下降
 - 升序团队名称
 9. 返回排序后的结果表。 

### 为什么它有效

 该算法之所以有效，是因为每场比赛都会独立且准确地为两支参赛球队的统计数据做出贡献。 通过在比赛表上一次更新两支球队，我们保证所有进球、比赛和积分都被正确计算，没有重复或遗漏。 

由于最终的排序完全遵循问题陈述中描述的排名规则，因此生成的排行榜是正确的。 

## Python 解决方案```python
SELECT
    t.team_name,
    COALESCE(stats.matches_played, 0) AS matches_played,
    COALESCE(stats.points, 0) AS points,
    COALESCE(stats.goal_for, 0) AS goal_for,
    COALESCE(stats.goal_against, 0) AS goal_against,
    COALESCE(stats.goal_for, 0) - COALESCE(stats.goal_against, 0) AS goal_diff
FROM Teams t
LEFT JOIN (
    SELECT
        team_id,
        COUNT(*) AS matches_played,
        SUM(points) AS points,
        SUM(goal_for) AS goal_for,
        SUM(goal_against) AS goal_against
    FROM (
        SELECT
            home_team_id AS team_id,
            home_team_goals AS goal_for,
            away_team_goals AS goal_against,
            CASE
                WHEN home_team_goals > away_team_goals THEN 3
                WHEN home_team_goals = away_team_goals THEN 1
                ELSE 0
            END AS points
        FROM Matches

        UNION ALL

        SELECT
            away_team_id AS team_id,
            away_team_goals AS goal_for,
            home_team_goals AS goal_against,
            CASE
                WHEN away_team_goals > home_team_goals THEN 3
                WHEN away_team_goals = home_team_goals THEN 1
                ELSE 0
            END AS points
        FROM Matches
    ) AS all_matches
    GROUP BY team_id
) AS stats
ON t.team_id = stats.team_id
ORDER BY
    points DESC,
    goal_diff DESC,
    team_name ASC;
```该解决方案使用以下方法将每个匹配项转换为两行`UNION ALL`。 

第一个查询代表主队的观点：

 - 进球数变为`goal_for`- 失球变成`goal_against`- 积分根据比赛结果计算

 第二个查询代表客队的观点，但逻辑相反。 

创建这个统一的表示后，我们通过以下方式聚合`team_id`使用`GROUP BY`。 

外部查询将聚合统计信息连接回`Teams`表中的每个球队都会出现在最终结果中，即使他们参加了零场比赛。`COALESCE`皈依者`NULL`对于这样的团队来说，价值为零。 

最后根据排名规则对结果进行排序。

 ## 边缘情况

 ### 没有比赛的球队

 一个团队可能存在于`Teams`表但从未出现在`Matches`桌子。 幼稚的内部联接将完全排除此类团队。 

该解决方案使用`LEFT JOIN`从`Teams`到聚合统计表。 使用以下方法将缺失值转换为零`COALESCE`，确保每支球队都出现在最终排名中。 

### 抽签比赛

 平局很容易处理不当，因为两队同时得分。 

该实现明确检查目标的平等性：

 - 主场进球数等于客场进球数
 - 两队均得 1 分

 这保证了平局比赛的正确处理。 

### 两队积分相同

 两支或多支球队可能会获得相同的总得分。 该问题指定了额外的决定因素：

 - 首先是更高的净胜球
 - 之后按字典顺序排列队名

 决赛`ORDER BY`子句按照所需的确切顺序应用这些条件，确保排名的确定性和正确性。
