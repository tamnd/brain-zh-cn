 # LeetCode 1852 - 每个子数组中的不同数字

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 对于每个长度连续的子数组`k`，我们必须确定该窗口内出现了多少个唯一值。 

子数组是数组的连续部分。 由于窗口大小固定为`k`，第一个子数组是`nums[0:k]`，下一个是`nums[1:k+1]`，依此类推，直到最后的有效窗口。 

对于每个窗口，我们计算它包含多少个不同的整数。 结果数组应按顺序存储这些计数。 

例如，如果：```
nums = [1,2,3,2,2,1,3]
k = 3
```那么窗口是：```
[1,2,3] -> 3 distinct
[2,3,2] -> 2 distinct
[3,2,2] -> 2 distinct
[2,2,1] -> 2 distinct
[2,1,3] -> 3 distinct
```所以答案就变成了：```
[3,2,2,2,3]
```约束条件很重要：```
1 <= k <= nums.length <= 10^5
1 <= nums[i] <= 10^5
```数组大小为`100000`意味着我们必须设计一个有效的算法。 任何从头开始重复扫描每个窗口的解决方案都会变得太慢。 

关键的挑战是避免重叠窗口之间的冗余工作。 连续的窗口共享大部分元素，因此每次重新计算所有内容都是浪费的。 

一些重要的边缘情况包括：

 -`k = 1`，每个窗口只包含一个元素，所以每个答案都是`1`。 
-`k = nums.length`，只有一个窗口覆盖整个数组。 
- 具有所有相同值的数组，其中每个窗口只有一个不同的元素。 
- 每个值都不同的数组，每个窗口都有完全相同的值`k`独特的元素。 
- 随着滑动窗口的移动重复插入和删除相同的值。 

该问题保证了有效的输入大小和有效的窗口大小，因此我们不需要处理无效的情况，例如`k > len(nums)`。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立处理每个子数组。 

对于每个起始索引`i`，我们取子数组：```
nums[i : i + k]
```我们将该子数组的所有元素插入到哈希集中，然后测量集合的大小。 由于集合仅存储唯一值，因此集合的大小等于不同元素的数量。 

这种方法是正确的，因为每个窗口都是独立检查的，并且每个不同的值都只计算一次。 

然而，该解决方案效率低下。 大约有`n - k + 1`窗口，每个窗口最多需要`k`插入到集合中。 

总复杂度变为：```
O((n - k + 1) * k)
```在最坏的情况下，这会变成`O(n * k)`，可以达到`10^10`操作时两者`n`和`k`很大。 

### 最优方法，带有频率图的滑动窗口

 重要的观察结果是相邻的窗口严重重叠。 

假设我们从：```
[1,2,3]
```到：```
[2,3,2]
```大多数元素保持不变。 仅：

 - 一个元素离开窗口
 - 一个元素进入窗口

 我们可以维护当前窗口的频率图，而不是从头开始重建不同计数。 

频率图存储：```
value -> count inside current window
```当窗口滑动时：

 - 减少传出元素的频率
 - 如果其计数变为零，则将其从地图中删除
 - 增加传入元素的频率

 在任何时刻，不同元素的数量等于频率图中键的数量。 

这允许每个元素仅被处理固定次数，给出`O(n)`解决方案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * k) | O(k) | 为每个窗口重建一组 |
 | 最佳| O(n) | O(k) | 使用滑动窗口和频率计数 |

 ## 算法演练

 1. 创建一个空的频率图。 

地图将存储每个数字在当前窗口中出现的次数。 
2. 构建第一个窗口。 

迭代第一个`k`元素并增加它们在频率图中的计数。 
3. 记录不同元素的数量。 

唯一值的数量等于当前存储在频率图中的键的数量。 
4. 开始将窗口滑动一个位置。 

对于每个新职位：

 - 删除传出元素，即前一个窗口中最左边的值。 
- 降低其频率。 
- 如果其频率变为零，请将其从地图中完全删除。 
- 添加传入元素，它是进入窗口的新的最右边的值。 
- 增加其在地图中的出现频率。 
5. 更新窗口后，附加不同元素的数量。 

同样，不同的计数等于频率图中的键的数量。 
6. 继续，直到处理完所有窗口。 

### 为什么它有效

 滑动窗口始终准确地表示一个大小连续的子数组`k`。 

频率图维护当前窗口内每个数字的准确计数。 当元素离开窗口时，其计数就会减少。 当新元素进入时，其计数就会增加。 

当且仅当一个数字的频率大于零时，该数字才是不同的。 因此，频率图中的键数始终等于当前窗口中不同元素的数量。 

由于每一步都会正确执行窗口更新，因此该算法会为每个子数组生成正确的答案。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def distinctNumbers(self, nums: List[int], k: int) -> List[int]:
        frequency = defaultdict(int)
        result = []

        # Build the first window
        for i in range(k):
            frequency[nums[i]] += 1

        result.append(len(frequency))

        # Slide the window
        for right in range(k, len(nums)):
            left = right - k

            outgoing = nums[left]
            frequency[outgoing] -= 1

            if frequency[outgoing] == 0:
                del frequency[outgoing]

            incoming = nums[right]
            frequency[incoming] += 1

            result.append(len(frequency))

        return result
```实现首先使用创建频率图`defaultdict(int)`。 这允许增加频率，而无需手动检查密钥是否已存在。 

第一个循环构造大小的初始窗口`k`。 每个数字都被添加到频率映射中，循环完成后，映射中的键数等于第一个窗口中不同值的数量。 

第二个循环处理滑动过程。 对于每个新窗口位置：

 - 传出元素被删除
 - 添加传入元素
 - 不同计数附加到结果中

 如果传出元素的频率达到零，则必须将其完全从字典中删除。 否则，字典会错误地将其视为仍然存在于窗口中。 

该算法从不从头开始重建窗口，这就是它在线性时间内高效运行的原因。 

## 解决方案```go
func distinctNumbers(nums []int, k int) []int {
	frequency := make(map[int]int)
	result := []int{}

	// Build the first window
	for i := 0; i < k; i++ {
		frequency[nums[i]]++
	}

	result = append(result, len(frequency))

	// Slide the window
	for right := k; right < len(nums); right++ {
		left := right - k

		outgoing := nums[left]
		frequency[outgoing]--

		if frequency[outgoing] == 0 {
			delete(frequency, outgoing)
		}

		incoming := nums[right]
		frequency[incoming]++

		result = append(result, len(frequency))
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 使用内置的`map[int]int`而不是Python的字典。 当移除频率为零的元素时，`delete()`函数用于从映射中完全删除密钥。 

切片用于存储结果数组。 由于 Go 映射对于丢失的键返回零值，因此增加频率很简单，无需额外的存在检查。 

不存在整数溢出问题，因为频率永远不会超过`k`， 和`k <= 100000`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 在这种情况下，每个窗口只包含一个元素，因此答案必须始终是`1`。 有缺陷的实现可能会使逻辑过于复杂或错误地维护跨窗口的频率。 该解决方案可以自然地处理它，因为每个窗口在频率图中包含一个键。 

另一个重要的情况是所有数字都相同。 例如：```
[7,7,7,7,7]
```每个窗口都应该有一个独特的值。 忘记正确减少频率的实现可能会意外地多次计算重复值。 频率图可确保正确跟踪重复项。 

当传出元素从窗口中完全消失时，会出现第三种关键边缘情况。 例如：```
[1,2,3]
```滑动至：```
[2,3,4]
```价值`1`在其计数变为零后，必须将其从频率图中删除。 如果键留在映射中，则非重复计数将变得不正确。 该实现显式删除零频率条目以避免此错误。 

当整个数组形成一个窗口时，会出现最后的边缘情况，这意味着`k = len(nums)`。 在这种情况下，只有一个答案值。 该实现正确地处理了这个问题，因为它构建了初始窗口并立即返回正确的结果，而无需进入滑动循环。
