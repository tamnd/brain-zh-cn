[LeetCode 问题 1809](https://leetcode.com/problems/ad-free-sessions/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题是要求我们识别所有未显示广告的播放会话。 我们有两张表：`Playback`和`Ads`。 这`Playback`表列出了每个客户的会话以及每个会话的开始和结束时间。 保证同一客户的每个会话不重叠。 这`Ads`表列出了向客户展示的广告，以及每个广告发生的时间戳。 

我们的目标是返回`session_id`不包含任何广告时间戳的所有会话的数量。 这需要对照该客户的所有广告检查每个会话，以查看是否有任何广告属于该会话的包含范围`[start_time, end_time]`间隔。 

重要的约束是同一客户的会话不重叠，并且 start_time ≤ end_time，这简化了我们的检查，因为我们不需要处理同一客户的交叉会话。 边缘情况包括根本没有广告的会话、会话间隔之外的多个广告以及正好位于会话边界上的多个广告。 

## 方法

 强力方法是将每个会话与该客户的所有广告结合起来，并检查是否有任何广告时间戳落在会话间隔内。 如果在该时间间隔内没有发现广告，则该会话没有广告。 这是正确的，因为它会针对该客户的每个广告彻底检查每个会话，但对于大型数据集来说效率低下，因为它可能会导致大型笛卡尔积。 

最佳方法利用左连接`Playback`和`Ads`在`customer_id`附加条件是`timestamp`落在会话间隔内。 然后，我们过滤不存在​​匹配广告的行（连接后为 NULL）。 这减少了不必要的比较，并允许数据库引擎使用索引有效地过滤匹配项`customer_id`和`timestamp`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(P * A) | O(1) | O(1) | 加入包含客户所有广告的每个会话并手动过滤 |
 | 最佳 | O(P + A) | O(1) | O(1) | 使用带有条件的 LEFT JOIN 并过滤 NULL 来高效获取无广告的会话 |

 ## 算法演练

 1. 首先在`Playback`表和`Ads`桌上`customer_id`。 这可确保每个会话都与同一客户的潜在广告相匹配。 
2. 在连接中添加一个条件，即广告`timestamp`属于会话范围内`[start_time, end_time]`间隔。 这只会过滤每个会话的相关广告。 
3. 连接后，没有匹配广告的行将有`NULL`广告列中的值。 过滤结果集`NULL`中的值`ad_id`柱子。 
4. 选择`session_id`这些过滤后的行作为最终结果。 

**为什么有效**：通过左加入`customer_id`并且限制会话间隔内的广告时间戳，任何没有广告的会话在`Ads`表，结果是`NULL`。 过滤这些 NULL 可保证我们仅捕获无广告的会话。 这种方法之所以有效，是因为每个客户的会话间隔不重叠，从而确保没有歧义。 

## Python 解决方案```python
# SQL-based solution in Python using a raw query approach
def ad_free_sessions() -> str:
    return """
    SELECT p.session_id
    FROM Playback p
    LEFT JOIN Ads a
    ON p.customer_id = a.customer_id
       AND a.timestamp BETWEEN p.start_time AND p.end_time
    WHERE a.ad_id IS NULL
    """
```**说明**：我们选择`Playback`作为主表和左连接`Ads`关于匹配`customer_id`和会话范围内的时间戳。 过滤位置`ad_id IS NULL`确保仅返回没有任何广告的会话。 这直接实现了所描述的算法步骤。 

## 解决方案```go
// Go version using database/sql raw query
package main

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
    "fmt"
)

func AdFreeSessions(db *sql.DB) ([]int, error) {
    query := `
    SELECT p.session_id
    FROM Playback p
    LEFT JOIN Ads a
    ON p.customer_id = a.customer_id
       AND a.timestamp BETWEEN p.start_time AND p.end_time
    WHERE a.ad_id IS NULL
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var result []int
    for rows.Next() {
        var sessionID int
        if err := rows.Scan(&sessionID); err != nil {
            return nil, err
        }
        result = append(result, sessionID)
    }
    return result, nil
}
```**说明**：Go 解决方案执行与 Python 解决方案相同的 SQL 查询。 没有匹配广告的行产生`NULL`为了`ad_id`，并将这些行扫描到切片中会收集所有无广告会话 ID。 

## 工作示例

 使用问题中的示例：

 回放：

 | 会话 ID | 客户 ID | 开始时间 | 结束时间 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 5 |
 | 2 | 1 | 15 | 15 23 | 23
 | 3 | 2 | 10 | 10 12 | 12
 | 4 | 2 | 17 | 17 28 | 28
 | 5 | 2 | 2 | 8 |

 广告：

 | 广告 ID | 客户 ID | 时间戳|
 | --- | --- | --- |
 | 1 | 1 | 5 |
 | 2 | 2 | 17 | 17
 | 3 | 2 | 20 |

 执行：

 1. 使用广告加入会话 1（客户 1、1-5）→ 匹配广告 1（时间戳 5）→ 排除。 
2. 加入带有广告的会话 2（客户 1、15-23）→ 范围内无广告→ 包含。 
3. 加入带有广告的会话 3（客户 2、10-12）→ 范围内无广告→ 包含。 
4. 加入会话 4（客户 2、17-28）→ 匹配广告 2 和 3 → 排除。 
5. 加入会话 5（客户 2、2-8）→ 范围内无广告→ 包含。 

结果：session_ids 2、3、5。

 ## 边缘情况

 1. **恰好在 start_time 或 end_time 出现广告的会话**：由于包含时间间隔，因此这些会话应计为具有广告。 我们的`BETWEEN`条件可以正确处理这个问题。 
2. **根本没有广告的客户**：该客户的所有会话都应显示在结果中。 左连接产生`NULL`对于所有广告，因此过滤按预期进行。 
3. **同一客户的多个会话**：每个会话都是独立的，因为会话不重叠。 广告是单独匹配的，因此不会错误地标记任何会话。 

该解决方案可以正确处理所有这些边缘情况，确保结果稳健且准确。
