[LeetCode 1886 题](https://leetcode.com/problems/define-whether-matrix-can-be-obtained-by-rotation/)

 **难度：** 🟢简单
 **主题：** 数组、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们两个二进制方阵，`mat`和`target`, 两者的大小`n x n`。 每个单元格包含`0`或者`1`。 我们的任务是确定是否`mat`可以转化为`target`顺时针旋转 90 度。 

旋转可以执行多次。 由于将方阵旋转四次会将其返回到原始方向，因此我们只需要考虑四种可能的状态：

 1.无旋转，0度
 2.旋转一圈，90度
 3. 两次旋转，180度
 4. 三旋转，270度

 如果这些轮换版本中有任何一个匹配`target`，我们返回`true`。 否则，我们返回`false`。 

矩阵保证是方阵，并且大小约束非常小：

 -`1 <= n <= 10`这个小约束告诉我们，效率并不是主要问题。 即使是立方复杂度的算法也能轻松通过。 然而，我们仍然想要一个干净且逻辑上最佳的解决方案。 

一个重要的细节是矩阵元素是二进制的，但这一事实并没有从根本上改变算法。 同样的逻辑适用于任何值。 

一些重要的边缘情况包括：

 - A`1 x 1`矩阵，其中旋转不执行任何操作。 
- 已经匹配且没有任何旋转的矩阵。 
- 仅在多次旋转后才匹配的矩阵。 
- 永远不匹配的矩阵。 
- 对称矩阵，其中多次旋转可能产生相同的矩阵。 

因为保证输入是相同维度的有效方阵，所以我们不需要处理格式错误的输入。 

## 方法

 ### 蛮力方法

 蛮力策略很简单。 我们反复旋转矩阵并将其与`target`。 

该算法的工作原理如下：

 1. 比较`mat`和`target`。 
2. 如果匹配，则返回`true`。 
3. 否则，旋转`mat`顺时针旋转90度。 
4. 重复此过程最多四次。 

由于只有四种可能的方向，这保证了我们检查每个有效的旋转。 

为了旋转矩阵，我们创建一个新矩阵，其中每个元素根据旋转规则重新定位：```
new[j][n - 1 - i] = old[i][j]
```每次旋转都需要访问每个单元格，这会花费`O(n^2)`。 每次比较也需要花费`O(n^2)`。 由于我们最多执行四次，因此总工作量仍然是可控的。 

对于问题约束来说，这种方法已经足够有效。 

### 最佳解决方案的关键见解

 关键的观察结果是方阵只有四种独特的旋转状态。 我们不需要任何高级搜索或模拟。 

我们可以系统地生成每个旋转版本并将其直接与目标矩阵进行比较，而不是尝试任意变换。 

由于旋转次数是恒定的，因此复杂性实际上与矩阵单元的数量成正比。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4 × n²) | O(4 × n²) | O(n²) | 旋转并比较最多四次 |
 | 最佳| O(n²) | O(n²) | 相同的实用方法，因为旋转的范围为 4 |

 尽管两行看起来相似，但第二个框架强调了旋转次数恒定的重要观察结果。 

## 算法演练

 1.从原始矩阵开始`mat`。 
2. 将当前矩阵与`target`。 

此检查确定当前方向是否已与所需矩阵匹配。 如果它们相等，我们可以立即返回`True`。 
3. 如果矩阵不匹配，则将矩阵顺时针旋转 90 度。 

对于每个职位`(i, j)`在原始矩阵中，将其值放入位置`(j, n - 1 - i)`在旋转矩阵中。 
4. 将当前矩阵替换为旋转后的版本。 

这允许下一次迭代继续从当前方向旋转。 
5. 重复该过程四次。 

四次旋转涵盖了所有可能的方向：

 - 0 度
 - 90 度
 - 180 度
 - 270 度
 6. 如果没有一个旋转匹配`target`， 返回`False`。 

### 为什么它有效

 顺时针旋转的方阵在返回到其原始状态之前反复循环恰好四个可能的方向。 因此，检查所有四个旋转可以保证我们检查每个可能的有效转换。 如果没有一个与目标矩阵匹配，则不存在有效的旋转。 

## Python 解决方案```python
from typing import List

class Solution:
    def findRotation(self, mat: List[List[int]], target: List[List[int]]) -> bool:
        def rotate(matrix: List[List[int]]) -> List[List[int]]:
            n = len(matrix)
            rotated = [[0] * n for _ in range(n)]

            for i in range(n):
                for j in range(n):
                    rotated[j][n - 1 - i] = matrix[i][j]

            return rotated

        current = mat

        for _ in range(4):
            if current == target:
                return True

            current = rotate(current)

        return False
```实现首先定义一个名为的辅助函数`rotate`。 该函数构造一个相同大小的新矩阵，并按照顺时针旋转映射进行填充。 

表达式：```python
rotated[j][n - 1 - i] = matrix[i][j]
```是顺时针旋转的核心变换规则。 

变量`current`存储矩阵的当前方向。 最初，它引用了原始`mat`。 

该循环运行四次，因为只有四种可能的旋转。 在每次迭代期间：

 1.当前矩阵与`target`。 
2. 如果相等，函数立即返回`True`。 
3. 否则，矩阵将在下一次迭代中旋转一次。 

如果所有四个方向均不匹配，则函数返回`False`。 

## 解决方案```go
func findRotation(mat [][]int, target [][]int) bool {
    rotate := func(matrix [][]int) [][]int {
        n := len(matrix)

        rotated := make([][]int, n)
        for i := 0; i < n; i++ {
            rotated[i] = make([]int, n)
        }

        for i := 0; i < n; i++ {
            for j := 0; j < n; j++ {
                rotated[j][n-1-i] = matrix[i][j]
            }
        }

        return rotated
    }

    isEqual := func(a [][]int, b [][]int) bool {
        n := len(a)

        for i := 0; i < n; i++ {
            for j := 0; j < n; j++ {
                if a[i][j] != b[i][j] {
                    return false
                }
            }
        }

        return true
    }

    current := mat

    for k := 0; k < 4; k++ {
        if isEqual(current, target) {
            return true
        }

        current = rotate(current)
    }

    return false
}
```Go 解决方案遵循与 Python 实现相同的逻辑，但存在一些特定于语言的差异。 

Go不支持切片的直接矩阵相等比较，因此我们定义了一个显式的`isEqual`手动比较每个单元格的辅助函数。 

矩阵分配还需要使用显式初始化`make`。 

旋转逻辑本身与 Python 版本相同。 

由于矩阵大小非常小，因此无需担心内存使用或整数溢出。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 最多四次轮换和比较 |
 | 空间| O(n²) | 旋转期间创建的额外矩阵 |

 该算法对每个矩阵单元执行恒定数量的运算。 由于旋转次数固定为四，因此常数因子不会影响渐近复杂度。 

额外的空间来自于每次变换期间构建旋转矩阵。

 ## 边缘情况

 一个重要的边缘情况是`1 x 1`矩阵。 由于旋转单个元素矩阵不会改变任何内容，因此算法必须正确识别两个值是否已经匹配。 该实现自然地处理了这个问题，因为所有旋转都会产生相同的矩阵。 

另一个重要的情况是在发生任何旋转之前矩阵已经相等。 有缺陷的实现可能会首先轮换并错过这种情况。 我们的解决方案在每次旋转之前检查相等性，包括原始方向。 

第三个重要的边缘情况涉及对称矩阵。 一些矩阵在一次或多次旋转后保持不变。 例如：```
[
  [1,0],
  [0,1]
]
```在某些变换下可能看起来相同。 该实现正确地处理了这个问题，因为它只是在每个阶段比较矩阵，而不假设旋转之间的唯一性。 

当正确答案需要恰好旋转 3 次（顺时针 270 度）时，就会出现最后一个微妙的边缘情况。 一些不正确的实现仅检查一到两次旋转。 通过精确迭代四次，我们的解决方案保证检查每个有效方向。
