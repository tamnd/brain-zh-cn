 ## 解决方案

 ## 问题理解

 该问题给出了一个正整数数组，称为`nums`。 我们必须找到严格递增且总和最大的连续子数组。 

子数组是连续的，这意味着元素必须在原始数组中彼此相邻出现。 我们不允许跳过元素。 

“严格递增”意味着子数组中的每个元素都必须大于前一个元素。 例如：

-`[5, 10, 50]`是有效的，因为`5 < 10 < 50`-`[10, 10, 20]`无效，因为`10`不严格小于`10`目标是计算所有有效升序子数组的最大和。 

例如，在：```
[10,20,30,5,10,50]
```有两个重要的上升部分：

 -`[10,20,30]`与总和`60`-`[5,10,50]`与总和`65`正确答案是`65`。 

限制很小：

 -`1 <= nums.length <= 100`-`1 <= nums[i] <= 100`由于数组长度最多为`100`，即使效率较低的解决方案也能发挥作用。 然而，该问题旨在鼓励识别简单的线性扫描解决方案。 

一些重要的观察结果和边缘情况：

 - 单个元素始终是有效的升序子数组。 
- 如果整个数组严格递增，则答案是整个数组的和。 
- 如果数组严格递减，则答案就是最大的单个元素。 
- 相邻值相等会破坏上升条件，因为增加必须严格。 
- 因为所有数字都是正数，所以扩展升序子数组总是会增加其总和，从而简化了逻辑。 

## 方法

 ### 蛮力方法

 一种简单的方法是检查每个可能的子数组。 

对于每个起始索引，我们可以一次扩展子数组一个元素，同时检查它是否保持严格递增。 如果是，我们计算其总和并更新答案。 

这是有效的，因为它显式地评估每个有效的升序子数组，保证最终找到最大和。 

但是，此方法会重复重新计算总和并重复检查重叠范围的增加条件。 尽管约束足够小，可以通过，但与实际需要相比，效率很低。 

### 最佳方法

 关键的观察是我们只关心连续递增的运行。 

当我们从左到右扫描数组时：

 - 如果当前数字大于前一个数字，我们可以扩展当前的升序子数组。 
- 否则，升序会中断，因此我们必须从当前元素开始一个新的子数组。 

这意味着我们永远不需要嵌套循环。 我们可以维护：

 -`current_sum`, 当前上升段的总和
 -`max_sum`，迄今为止看到的最佳答案

 每个元素只处理一次，给出干净的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查所有可能的升序子数组 |
 | 最佳 | O(n) | O(1) | O(1) | 单通道跟踪当前上升段 |

 ## 算法演练

 1.初始化两个变量：

 -`current_sum`到第一个元素
 -`max_sum`到第一个元素

 我们这样做是因为单个元素本身形成一个有效的升序子数组。 
2.从索引开始迭代`1`到数组的末尾。 
3. 对于每个元素，将其与前一个元素进行比较：

 - 如果`nums[i] > nums[i - 1]`，升序继续。 
- 添加`nums[i]`到`current_sum`。 
4. 否则，升序会中断：

 - 重置`current_sum`到`nums[i]`- 这将启动一个从当前元素开始的新升序子数组。 
5.更新后`current_sum`，将其与`max_sum`：

- 如果`current_sum`较大，更新`max_sum`。 
6. 继续，直到处理完所有元素。 
7. 返回`max_sum`。 

### 为什么它有效

 该算法保持不变式`current_sum`始终表示以当前索引结尾的当前严格递增的连续段的总和。 

每当增加条件失败时，没有有效的升序子数组可以继续跨越该边界，因此重置是正确的。 

由于每个上升段仅被考虑一次并且`max_sum`存储迄今为止看到的最大的段总和，最终的答案保证是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxAscendingSum(self, nums: List[int]) -> int:
        current_sum = nums[0]
        max_sum = nums[0]

        for i in range(1, len(nums)):
            if nums[i] > nums[i - 1]:
                current_sum += nums[i]
            else:
                current_sum = nums[i]

            max_sum = max(max_sum, current_sum)

        return max_sum
```实现首先初始化两个`current_sum`和`max_sum`与第一个元素。 这是有效的，因为至少单个数字是有效的升序子数组。 

循环从索引开始`1`因为每个元素都必须与其前一个元素进行比较。 

在循环内部，条件：```python
nums[i] > nums[i - 1]
```检查升序是否继续。 如果是，我们通过添加当前值来扩展当前子数组。 

如果条件失败，则上升运行结束。 由于当前值不能属于之前的升序子数组，因此我们重置`current_sum`开始一个新的段。 

每次更新后，我们都会比较`current_sum`反对`max_sum`跟踪迄今为止找到的最佳答案。 

最后，函数返回`max_sum`。 

## 解决方案```go
func maxAscendingSum(nums []int) int {
    currentSum := nums[0]
    maxSum := nums[0]

    for i := 1; i < len(nums); i++ {
        if nums[i] > nums[i-1] {
            currentSum += nums[i]
        } else {
            currentSum = nums[i]
        }

        if currentSum > maxSum {
            maxSum = currentSum
        }
    }

    return maxSum
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个小小的区别是 Go 没有提供内置的`max`整数函数，所以我们使用一个简单的`if`更新声明`maxSum`。 

约束非常小，因此整数溢出不是问题。 最大可能的总和仅为`100 * 100 = 10000`，它很容易适合 Go 的`int`类型。 

该问题保证数组中至少有一个元素，因此访问`nums[0]`总是安全的。

 ## 边缘情况

 一种重要的边缘情况是单元素数组。 由于单个数字本身就是有效的升序子数组，因此算法必须立即正确返回该值。 初始化两者`current_sum`和`max_sum`和`nums[0]`确保其自然工作，无需稍后进行特殊处理。 

另一个重要的情况是当数组严格递减时。 在这种情况下，每个升序子数组的长度均为一。 有缺陷的实现可能会错误地跨递减的边界累积值。 此实施重置`current_sum`每当升序条件失​​败时，确保仅计算有效段。 

相邻值相等也是一种微妙的边缘情况。 该问题需要严格的升序，而不是非降序。 这意味着像这样的序列`[3,3]`必须破坏当前子数组。 条件：```
nums[i] > nums[i - 1]
```正确地执行严格的不平等。 

最后一个重要的情况是最佳升序子数组出现在数组末尾附近。 一些不正确的解决方案仅在序列结束时更新最大值。 此实施更新`max_sum`在每次迭代期间，都能正确处理后期的最佳片段。
