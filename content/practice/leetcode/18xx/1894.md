[LeetCode 1894 题](https://leetcode.com/problems/find-the-student-that-will-replace-the-chalk/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、模拟、前缀和

 ## 解决方案

 ## 问题理解

 该问题呈现了一个课堂场景，其中学生按循环顺序提出问题，每个问题消耗一定数量的粉笔。 我们得到一个数组`chalk`， 在哪里`chalk[i]`表示学生粉笔的数量`i`使用，和一个整数`k`代表最初的粉笔供应量。 从 0 号学生开始，每个学生按顺序使用粉笔，然后再回到 0 号学生`n-1`。 目标是确定哪个学生**首先用完粉笔**，这意味着当前的供应量严格低于学生的需求。 

输入由长度数组组成`n`(1 ≤ n ≤ 10^5) 和一个整数`k`(1 ≤ k ≤ 10^9)。 每个粉笔消耗值在 1 到 10^5 之间。 这意味着暴力迭代`k`由于潜在的巨大价值，粉笔的使用是不可行的。 我们必须利用模式或累积总和来优化。 

重要的边缘情况包括以下情况`k`小于第一个学生的粉笔需求，或者当`k`非常大，需要对所有学生进行多次完整的轮次。 

## 方法

 **暴力方法**完全按照所描述的方式模拟该过程。 从学生 0 开始，我们减去`chalk[i]`从`k`并继续下一个学生。 什么时候`k`小于当前学生的粉笔要求，我们返回该学生的索引。 虽然正确，但这种方法效率低下，因为在最坏的情况下，我们可能会迭代数十亿次`k`很大。 

**最佳方法**依赖于粉笔消耗模式每次重复的洞察力`n`学生。 我们首先计算**一轮中使用的粉笔总数**，`total = sum(chalk)`。 如果`k >= total`，我们可以将问题简化为`k % total`因为完整的回合并不影响最终的结果。 计算后`k % total`，我们使用累积减法对学生进行一次迭代，直到剩余的粉笔不足以容纳一个学生。 这将迭代次数从潜在的数十亿次减少到最多`n`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k) | O(1) | O(1) | 模拟每个学生的粉笔使用情况直至更换 |
 | 最佳| O(n) | O(1) | O(1) | 使用模数跳过整轮并通过一次查找替换 |

 ## 算法演练

 1. 计算所有粉笔需求的总和：`total = sum(chalk)`。 这代表所有学生在一轮完整的比赛中使用的粉笔。 
2. 将剩余的粉笔减少到整轮后的剩余部分：`k = k % total`。 这是有效的，因为每一轮都不会改变哪个学生将更换粉笔。 
3. 迭代每个学生`i`按顺序：

 - 如果`k < chalk[i]`， 学生`i`无法完成该题，必须更换粉笔。 返回`i`。 
- 否则，减去`chalk[i]`从`k`并继续。 
4. 由于取模运算保证替换将在一次传递内发生，因此保证迭代在数组末尾之前终止。 

**为什么有效**：模运算保留了将用完粉笔的学生的位置，因为任何整轮都是无关紧要的。 累积减法可确保正确识别第一个超过剩余粉笔的学生。 

## Python 解决方案```python
from typing import List

class Solution:
    def chalkReplacer(self, chalk: List[int], k: int) -> int:
        total = sum(chalk)
        k %= total  # reduce k to the remaining chalk after full rounds
        
        for i, c in enumerate(chalk):
            if k < c:
                return i
            k -= c
        return 0  # fallback, technically unreachable due to constraints
```该实现首先计算一个完整周期中使用的粉笔总量。 然后模运算会减少有效粉笔数。 该循环在数组中迭代一次，返回第一个粉笔需求超过剩余粉笔的学生。 

## 解决方案```go
func chalkReplacer(chalk []int, k int) int {
    total := 0
    for _, c := range chalk {
        total += c
    }
    
    k %= total
    
    for i, c := range chalk {
        if k < c {
            return i
        }
        k -= c
    }
    return 0
}
```Go 解决方案反映了 Python 方法。 我们对 chalk 数组求和，减少`k`对总计求模，并迭代学生，返回索引，其中`k < chalk[i]`。 Go 的整数运算足以满足输入约束，如下所示`total`和`k`在之内`int`这些限制的范围。

 ## 边缘情况

 **案例1：只有一名学生**

 如果只有一个学生，他们总是会在以下时间更换粉笔：`k < chalk[0]`或经过多轮后`k`是不够的。 我们的实现通过迭代单个元素并检查来正确处理这个问题`k < chalk[0]`。 

**情况 2：k 比第一个学生的粉笔小**

 当`k < chalk[0]`，第一个学生必须立即更换粉笔。 模运算不改变`k`，因此循环正确返回索引 0。 

**情况 3：k 恰好是粉笔总数的倍数**

 如果`k`正好等于`sum(chalk)`或任何倍数，`k % total`变为 0。迭代中的第一个学生则有`k < chalk[i]`并替换了粉笔，这符合预期的行为。 这确保了整圆边缘对齐的正确性。
