[LeetCode 问题 1869](https://leetcode.com/problems/longer-contigious-segments-of-ones-than-zeros/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`，这意味着字符串仅包含字符`'0'`和`'1'`。 我们需要确定最长的连续序列是否`1`s 严格长于最长连续序列`0`s。 

连续的段意味着连续的字符而不中断。 例如，在字符串中`"1110011"`：

 - 最长的一段`1`是`"111"`，其长度为`3`- 最长的一段`0`是`"00"`，其长度为`2`自从`3 > 2`，答案是`true`。 

关键细节是我们只关心每种字符类型的最大长度。 我们不关心总共存在多少个段。 我们只比较：

 - 最长的运行时间`1`s
 - 最长的运行时间`0`是
 该问题保证：
 -`1 <= s.length <= 100`- 每个角色都是`'0'`或者`'1'`由于输入量非常小，因此即使是低效的解决方案也能发挥作用。 然而，目标仍然是设计一个干净且最佳的线性时间解决方案。 

有几个重要的边缘情况需要考虑：

 - 一个字符串只包含`1`s，例如`"1111"`- 一个字符串只包含`0`s，例如`"0000"`- 交替的字符，如`"101010"`- 相同的最大长度，例如`"111000"`- 长度非常短的字符串`1`当在段之间转换或更新字符串末尾的最大长度时，幼稚的实现很容易出错。 

## 方法

 ### 蛮力方法

 暴力解决方案将检查每个可能的子字符串并确定它是否完全由`0`或全部`1`s。 在扫描这些子字符串时，我们可以跟踪每个字符的最长有效段。 

对于一个长度的字符串`n`， 有`O(n²)`子串。 检查每个子字符串是否完全由一个重复字符组成可能需要长达`O(n)`时间。 这导致总复杂度为`O(n³)`。 

虽然`n <= 100`，使得这种方法在技术上可行，但它的效率不必要地低，因为该问题只需要识别连续的运行，这可以在单遍中完成。 

### 最佳方法

 关键的观察是，从左到右扫描字符串时，连续的段会自然出现。 

我们可以：

 - 跟踪当前字符段长度
 - 每当角色发生变化时重置计数
 - 保持最大段长度`0`沙`1`分别

 这是有效的，因为在线性扫描期间每个连续的段只遇到一次。 

当我们遍历字符串时：

 - 如果当前字符与前一个字符匹配，则扩展当前段
 - 否则，我们开始一个新的长度段`1`- 更新当前段长度后，我们更新适当的最大值

 最后，我们简单地比较两个最大值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 检查所有子字符串并验证段 |
 | 最佳 | O(n) | O(1) | O(1) | 单次线性扫描跟踪连续运行 |

 ## 算法演练

 1.初始化四个变量：

 -`max_ones`存储最长的段`1`s
 -`max_zeros`存储最长的段`0`s
 -`current_length`跟踪当前段大小
 -`previous_char`记住最后看到的字符
 2. 开始从左到右迭代字符串。 
3. 对于每个字符：

 - 如果与前一个字符匹配，则递增`current_length`- 否则，重置`current_length`到`1`因为新的一段开始了
 4.根据当前字符是否为`'1'`或者`'0'`：

- 更新`max_ones`- 或者更新`max_zeros`5. 更新`previous_char`到当前字符，以便下一次迭代可以与其进行比较。 
6. 处理完整个字符串后，比较：

 -`max_ones > max_zeros`7. 返回比较结果。 

### 为什么它有效

 该算法保持不变式`current_length`始终表示以当前索引结尾的当前连续段的长度。 

每当一个段增长时，我们都会更新相应的最大值。 由于每个字符都被处理一次，因此每个连续的段都被考虑一次。 因此，最终的最大值正确地代表了最长的段`1`沙`0`s。 

## Python 解决方案```python
class Solution:
    def checkZeroOnes(self, s: str) -> bool:
        max_ones = 0
        max_zeros = 0

        current_length = 0
        previous_char = ""

        for char in s:
            if char == previous_char:
                current_length += 1
            else:
                current_length = 1

            if char == '1':
                max_ones = max(max_ones, current_length)
            else:
                max_zeros = max(max_zeros, current_length)

            previous_char = char

        return max_ones > max_zeros
```实现首先初始化两个的最大段长度`1`沙`0`s。 这些变量将存储迄今为止看到的最佳段长度。 

变量`current_length`跟踪当前连续段的大小。 变量`previous_char`帮助确定当前片段是继续还是新片段开始。 

迭代期间：

 - 如果当前字符与前一个字符匹配，则该段继续并且长度增加。 
- 否则，新段以 length 开始`1`。 

更新段长度后，代码会更新`max_ones`或者`max_zeros`取决于当前角色。 

最后，该函数返回是否是最长的线段`1`s 严格大于最长的线段`0`s。 

## 解决方案```go
func checkZeroOnes(s string) bool {
    maxOnes := 0
    maxZeros := 0

    currentLength := 0
    previousChar := byte(0)

    for i := 0; i < len(s); i++ {
        if s[i] == previousChar {
            currentLength++
        } else {
            currentLength = 1
        }

        if s[i] == '1' {
            if currentLength > maxOnes {
                maxOnes = currentLength
            }
        } else {
            if currentLength > maxZeros {
                maxZeros = currentLength
            }
        }

        previousChar = s[i]
    }

    return maxOnes > maxZeros
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 由于 Go 字符串是 ASCII 字符的字节数组，因此我们使用索引来访问字符，例如`s[i]`。 

变量`previousChar`初始化为`byte(0)`，也不匹配`'0'`或者`'1'`。 这保证了第一个字符正确地开始一个新的段。 

Go 没有提供内置的`max`旧版本中的整数函数，因此实现在更新最大值时使用显式比较。

 ## 边缘情况

 一种重要的边缘情况是字符串仅包含一种类型的字符。 例如，`"11111"`根本不包含零。 有缺陷的实现可能会错误地假设两种字符类型总是出现。 在这个解决方案中，`max_zeros`简单地保留下来`0`，它正确地反映了问题陈述。 

另一个重要的情况是交替字符，例如`"101010"`。 每个连续的段都有长度`1`，所以两个最大值都保持不变`1`。 由于该问题要求 those 段严格更长，因此算法正确返回`false`。 

当最长的段相等时会出现第三种边缘情况，例如`"111000"`。 一些实现错误地使用`>=`而不是`>`。 该解决方案显式检查`max_ones > max_zeros`，确保平等回报`false`完全按照要求。 

最后一个微妙的情况是字符串中的第一个字符。 由于还没有前一个字符，因此实现必须正确初始化第一个段的长度。 该解决方案通过重置来处理此问题`current_length`到`1`每当角色发生变化时，包括第一次迭代。
