[LeetCode 问题 1865](https://leetcode.com/problems/finding-pairs-with-a-certain-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、设计

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个可变的数据结构，它可以有效地支持两个数组上的两个操作，`nums1`和`nums2`。 

第一个数组，`nums1`，在初始化后固定不变。 第二个数组，`nums2`，是可变的，这意味着它的元素可以通过以下方式更新`add(index, val)`运营。 

数据结构的目标是回答以下形式的重复查询：

 > 有多少个索引对`(i, j)`满足`nums1[i] + nums2[j] == tot`？ 

对于每个查询，我们需要计算一个元素来自的所有有效组合`nums1`另一个来自`nums2`使它们的总和等于所请求的目标。 

该类必须支持三种操作：

 -`FindSumPairs(nums1, nums2)`初始化结构。 
-`add(index, val)`修改`nums2[index]`通过添加`val`。 
-`count(tot)`返回有效的数量`(i, j)`总和等于的对`tot`。 

一个关键的观察是`nums1`相对较小，最多有`1000`元素，同时`nums2`最多可包含`100,000`元素。 另外，最多有`1000`呼叫每个`add()`和`count()`。 

这个约束强烈表明，在每个查询期间迭代所有对将是非常昂贵的。 自从`nums2`随着时间的推移而变化，我们需要一种在每次修改后有效更新信息的方法。 

一个重要的细节是`nums1[i]`值可能非常大，最多可达`10^9`，这意味着我们不能依赖基于值范围的数组索引或频率数组。 哈希图是跟踪频率的自然选择。 

一些边缘情况值得关注：

 -`nums1`可以包含重复值，这意味着多个索引可能贡献相同的总和。 
-`nums2`还可以包含重复项，并且更新可以将现有值增加为其他地方已经存在的重复值。 
- 相同的索引`nums2`可能会更新多次，需要频率簿记以保持准确。 
- 大整数值意味着我们必须避免依赖于有限数值范围的方法。 
- 自从`nums2`是可变的，如果不仔细处理更新，过时的频率计数很容易引入错误。 

该问题保证了更新的有效索引和正更新值，从而简化了正确性处理。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是每次显式计算有效对的数量`count(tot)`被称为。 

对于每个查询：

 1. 迭代中的每个元素`nums1`。 
2. 迭代中的每个元素`nums2`。 
3. 检查它们的总和是否等于`tot`。 
4. 如果是，则增加答案。 

这`add()`在这种方法中操作很简单，因为我们只修改`nums2[index]`。 

这个解决方案是正确的，因为它检查了每一个可能的对`(i, j)`恰好一次并计算所有有效的总和。 

然而，性能较差。 自从`nums1.length ≤ 1000`和`nums2.length ≤ 100000`， 每个`count()`操作可能需要最多：$$1000 \times 100000 = 10^8$$比较。 

高达`1000`计算操作，这变得太昂贵了。 

### 最佳解决方案的关键见解

 主要观察结果是`nums1`是小且固定的，而`nums2`很大但是逐渐变化。 

而不是扫描所有`nums2`对于每个查询，我们可以维护一个值的频率图`nums2`。 

假设我们想要计算总和为`tot`。 

对于每个值`x`在`nums1`，我们需要：$$x + y = tot$$重新排列：$$y = tot - x$$所以对于每个`x`在`nums1`，我们只需要知道有多少次`tot - x`存在于`nums2`。 

哈希映射为我们提供了这个计数`O(1)`平均时间。 

挑战是在之后保持频率图更新`add()`运营。 我们通过以下方式解决这个问题：

 1. 降低旧值的频率。 
2. 更新`nums2[index]`。 
3. 增加新值的频率。 

这使得更新和查询都保持高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n × m)`每计数|`O(1)`| 显式检查每一对 |
 | 最佳 |`O(m)`初始化，`O(1)`添加，`O(n)`计数|`O(m)`| 使用频率图`nums2`|

 在哪里：

-`n = len(nums1)`-`m = len(nums2)`## 算法演练

 ### 初始化

 1. 商店`nums1`和`nums2`班级内。 

我们需要直接访问`nums2`因为未来的更新会对其进行适当修改。 
2. 构建频率图`nums2`。 

对于每一个值`nums2`，存储它出现的次数。 

示例：

 如果：```
nums2 = [1,4,5,2,5,4]
```然后：```
frequency = {
    1: 1,
    2: 1,
    4: 2,
    5: 2
}
```该结构允许在计数期间进行恒定时间查找。 

### 添加操作

 1. 检索旧值`nums2[index]`。 

由于频率图当前反映了旧的阵列状态，因此我们必须消除它的贡献。 
2. 降低旧值的频率。 

如果它的频率变为零，我们可以选择将其从地图中删除。 
3. 更新`nums2[index] += val`。 
4. 增加新值的频率。 

这使地图与更新的数组保持同步。 

### 计数操作

 1. 初始化`result = 0`。 
2. 迭代每个值`x`在`nums1`。 

自从`nums1`很小，迭代它很便宜。 
3. 计算补码：```
needed = tot - x
```4.查询多少次`needed`存在于`nums2`。 

将该频率添加到结果中。 
5. 返回累加结果。 

### 为什么它有效

 该算法之所以有效，是因为每个有效对都必须满足：$$nums1[i] + nums2[j] = tot$$对于每个固定`nums1[i] = x`，唯一可能的匹配值`nums2`是：$$tot - x$$频率图总是准确地代表当前的内容`nums2`，因为每次更新都会删除旧值计数并添加新值计数。 因此，对所需补集的频率求和只会对每个有效对进行一次计数，并且不会错过任何有效组合。 

## Python 解决方案```python
from collections import Counter
from typing import List

class FindSumPairs:

    def __init__(self, nums1: List[int], nums2: List[int]):
        self.nums1 = nums1
        self.nums2 = nums2
        self.frequency = Counter(nums2)

    def add(self, index: int, val: int) -> None:
        old_value = self.nums2[index]

        self.frequency[old_value] -= 1
        if self.frequency[old_value] == 0:
            del self.frequency[old_value]

        self.nums2[index] += val
        new_value = self.nums2[index]

        self.frequency[new_value] += 1

    def count(self, tot: int) -> int:
        pair_count = 0

        for num in self.nums1:
            needed = tot - num
            pair_count += self.frequency.get(needed, 0)

        return pair_count

# Your FindSumPairs object will be instantiated and called as such:
# obj = FindSumPairs(nums1, nums2)
# obj.add(index, val)
# param_2 = obj.count(tot)
```实现严格遵循算法。 

在初始化期间，我们存储两个数组并构造一个`Counter`为了`nums2`。 这用作我们的频率图并支持恒定时间查找。 

这`add()`方法首先从频率图中删除先前值的贡献。 更新后`nums2[index]`，它将新值插入回频率结构中。 这确保了之间的一致性`nums2`及其始终的频率图。 

这`count()`方法迭代`nums1`。 对于每个数字，它计算达到所需的补数`tot`并检索其出现次数`nums2`。 由于频率图自然会跟踪重复值，因此会自动对重复的有效对进行计数。 

## 解决方案```go
type FindSumPairs struct {
	nums1 []int
	nums2 []int
	freq  map[int]int
}

func Constructor(nums1 []int, nums2 []int) FindSumPairs {
	freq := make(map[int]int)

	for _, num := range nums2 {
		freq[num]++
	}

	return FindSumPairs{
		nums1: nums1,
		nums2: nums2,
		freq:  freq,
	}
}

func (this *FindSumPairs) Add(index int, val int) {
	oldValue := this.nums2[index]

	this.freq[oldValue]--
	if this.freq[oldValue] == 0 {
		delete(this.freq, oldValue)
	}

	this.nums2[index] += val
	newValue := this.nums2[index]

	this.freq[newValue]++
}

func (this *FindSumPairs) Count(tot int) int {
	pairCount := 0

	for _, num := range this.nums1 {
		needed := tot - num
		pairCount += this.freq[needed]
	}

	return pairCount
}

/**
 * Your FindSumPairs object will be instantiated and called as such:
 * obj := Constructor(nums1, nums2);
 * obj.Add(index,val);
 * param_2 := obj.Count(tot);
 */
```Go 的实现与 Python 解决方案非常相似。 

而不是`Counter`, Go 使用`map[int]int`来跟踪频率。 访问丢失的密钥会自动返回`0`，这使得补码查找变得简单。 

这`Add()`方法通过在增加新值之前减少旧值来仔细更新频率。 删除计数为零的键是可选的，但可以保持地图更干净。 

整数溢出在这里不是问题，因为值保持在标准 64 位整数限制内，并且 Go 的`int`类型安全地适应了约束。

 ## 边缘情况

 ### 两个数组中都有重复值

 一个常见的错误是忘记问题计算的是索引对，而不是唯一值。 如果`nums1 = [2,2,2]`和`nums2 = [3,3]`，有六对有效，而不是一对。 

频率图自然地处理了这个问题。 计数时，每出现一次`nums1`独立贡献，并且存储的匹配值的数量`nums2`自动正确地相乘结果。 

### 多次更新元素

 如果在添加新值之前未删除旧值，则对同一索引的重复更新很容易破坏频率跟踪。 

例如：```
nums2 = [5]
```后：```
add(0, 5)
```该值变为`10`。 

如果我们忘记减少计数`5`，将来的查询可能会错误地计算两者`5`和`10`。 该实现在插入新贡献之前显式删除旧贡献，从而防止频率过时。 

### 价值观变得独特或消失

 当更新更改某个值的最后一次出现时，其频率变为零。 

例如：```
nums2 = [5]
```后：```
add(0, 3)
```没有剩余的`5`s。 

该实现从哈希图中删除频率为零的键。 虽然正确性并不严格要求，但这可以防止不必要的过时条目并保持结构准确和内存高效。
