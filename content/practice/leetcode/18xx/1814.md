[LeetCode 问题 1814](https://leetcode.com/problems/count-nice-pairs-in-an-array/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学、计数

 ## 解决方案

 ## 问题理解

 该问题给了我们一个非负整数数组，称为`nums`。 我们需要计算有多少个索引对`(i, j)`满足以下条件：

 -`i < j`-`nums[i] + rev(nums[j]) == nums[j] + rev(nums[i])`这里，`rev(x)`表示将整数的数字反转。 例如：

-`rev(123) = 321`-`rev(120) = 21`目标是返回此类“好对”的总数。 由于对的数量可能变得非常大，我们返回模数的答案`10^9 + 7`。 

输入大小很重要：

 -`nums.length`可以大到`100000`- 每个数字最多可达`10^9`这些限制立即告诉我们，`O(n^2)`解决方案会太慢。 二次解需要粗略检查`10^10`在最坏的情况下配对，这是不可行的。 

为了有效地解决问题，我们需要将方程转换为允许快速分组或计数的形式。 

有几个重要的边缘情况需要记住：

 - 只包含一个元素的数组应该返回`0`，因为不存在对。 
- 以零结尾的数字很重要，因为反转会删除前导零。 例如，`120`变成`21`。 
- 具有许多重复转换值的大型数组可以生成大量对，因此需要模运算。 
- 值可以是`0`， 和`rev(0)`仍然是`0`。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每一个可能的对`(i, j)`。 

对于每对：

 1. 计算`rev(nums[i])`2. 计算`rev(nums[j])`3. 检查是否```
nums[i] + rev(nums[j]) == nums[j] + rev(nums[i])
```如果条件为真，则增加答案。 

这种方法是正确的，因为它直接评估问题陈述中每个可能对的确切条件。 

但时间复杂度太高。 有`O(n^2)`对，并且与`n = 100000`，这变得太慢了。 

### 最佳解决方案的关键见解

 我们从条件开始：```
nums[i] + rev(nums[j]) == nums[j] + rev(nums[i])
```重新排列术语：```
nums[i] - rev(nums[i]) == nums[j] - rev(nums[j])
```这种转变是关键的观察结果。 

我们不直接比较对，而是计算值：```
value = num - rev(num)
```对于每个数字。 

现在问题变成：

 > 计算有多少对具有相同的转换值。 

这是一个经典的哈希图计数问题。 

当我们遍历数组时：

 - 如果我们已经看到相同的转换值`k`次，
 - 然后当前元素形成`k`新的好对。 

这使我们能够在线性时间内对对进行计数。

 ## 算法演练

 1. 创建一个辅助函数来反转整数。 

该函数使用模数重复提取数字`% 10`并构造反转数。 
2. 初始化一个名为的哈希图`difference_count`。 

关键是：```
num - rev(num)
```该值将是该转换后的值迄今为止出现的次数。 
3.初始化answer变量`result = 0`。 
4. 迭代中的每个数字`nums`。 
5. 对于当前号码：

 - 计算其相反数。 
- 计算变换后的差值：```
difference = num - rev(num)
```6. 检查这种差异已经出现了多少次。 

如果出现同样的差异`k`之前的次数，然后形成当前的数字`k`与早期元素的新搭配。 
7. 添加`k`到答案。 
8. 更新此差异的哈希映射计数。 
9. 应用模数`10^9 + 7`每次添加后避免溢出。 
10.处理完所有数字后，返回结果。 

### 为什么它有效

 该算法之所以有效，是因为原始方程可以代数变换为：```
nums[i] - rev(nums[i]) == nums[j] - rev(nums[j])
```这意味着当且仅当两个索引的转换值相等时，它们才形成一对。 

哈希映射存储有多少先前的元素具有相同的转换值。 每当我们遇到另一个相同的值时，我们可以立即计算所有新形成的对。 

由于在处理后面的索引时，每对都只计算一次，因此最终答案是正确的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countNicePairs(self, nums: List[int]) -> int:
        MOD = 10**9 + 7

        def reverse_number(value: int) -> int:
            reversed_value = 0

            while value > 0:
                reversed_value = reversed_value * 10 + value % 10
                value //= 10

            return reversed_value

        difference_count = defaultdict(int)
        result = 0

        for num in nums:
            difference = num - reverse_number(num)

            result = (result + difference_count[difference]) % MOD

            difference_count[difference] += 1

        return result
```该实现遵循前面描述的确切算法。 

这`reverse_number`辅助函数以数学方式反转数字而不转换为字符串。 这使得实施高效且简单。 

这`difference_count`哈希图跟踪每个转换后的值出现的次数。 

对于每个数字：

 - 我们计算`num - reverse(num)`- 我们将当前差异的频率添加到答案中
 - 然后我们增加频率

 这个顺序很重要。 在添加当前的数字之前，我们必须计算以前出现的数字，否则我们会错误地计算与其自身配对的数字。 

在累加过程中应用模运算以确保结果不会变得太大。 

## 解决方案```go
func countNicePairs(nums []int) int {
    const MOD int = 1e9 + 7

    reverseNumber := func(value int) int {
        reversed := 0

        for value > 0 {
            reversed = reversed*10 + value%10
            value /= 10
        }

        return reversed
    }

    differenceCount := make(map[int]int)
    result := 0

    for _, num := range nums {
        difference := num - reverseNumber(num)

        result = (result + differenceCount[difference]) % MOD

        differenceCount[difference]++
    }

    return result
}
```Go 实现密切反映了 Python 逻辑。 

一个`map[int]int`用来代替Python的`defaultdict`。 在 Go 中，从映射中读取缺失的键会自动返回零值，这方便了频率计数。 

整数溢出在这里不是问题，因为我们不断应用模运算。 最终的答案总是在界限之内。 

与 Python 版本一样，reverse 函数使用整数算术而不是字符串转换。

 ## 边缘情况

 一种重要的边缘情况涉及带有尾随零的数字，例如`10`,`100`， 或者`1200`。 反转时，前导零会自动消失。 例如，`120`变成`21`， 不是`021`。 使用字符串的粗心实现可能会错误地处理这种转换。 所提供的实现通过使用数学数字提取来避免此问题。 

另一个重要的情况是所有转换值都相同的数组。 例如：```
[11, 22, 33]
```每个数字都有差异`0`，所以每一对都很好。 对的数量以组合方式增长，对于大数组来说可能会变得非常大。 该实现使用增量计数和模算术正确处理这个问题。 

包含零的数组也很重要。 自从`rev(0) = 0`，变换后的差值仍然存在`0`。 因此，多个零都彼此形成良好的配对。 反向函数正确处理`0`因为循环永远不会执行并返回`0`。 

一种微妙的边缘情况是只有一个元素的数组。 由于条件要求`i < j`，不可能有配对。 该算法自然会处理这个问题，因为循环永远不会找到任何先前的匹配差异。 

最后，非常大的输入尺寸需要有效的解决方案。 最佳算法处理每个数字一次，并使用哈希图进行恒定平均时间查找，确保即使对于大小的数组也保持高效`100000`。
