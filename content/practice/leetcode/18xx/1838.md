 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、贪心、滑动窗口、排序、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们确定整数数组中元素的最大频率`nums`最多表演后`k`增量操作。 每个操作都允许您选择一个元素并将其增加`1`。 元素的**频率**是它在数组中出现的次数。 

换句话说，鉴于能够“升级”数组中的数字，我们希望最大化相同元素的数量。 输入是一个整数数组和一个整数`k`，它表示我们可以在元素之间分配的增量总数。 输出是一个整数，表示这些操作后任何数字的最大可能频率。 

限制因素很重要：`nums`长度最多可达 100,000 个元素，并且`nums[i]`和`k`最大可达 100,000。 这表明检查所有可能性的强力解决方案会太慢。 要考虑的边缘情况包括只有一个元素的数组、所有元素都相等的数组、已经包含重复数字的数组以及以下场景：`k`相对于元素之间的差异非常小或非常大。 

## 方法

 **暴力**方法将涉及迭代每个元素并尝试增加更小的元素来匹配它，并跟踪所使用的操作数量。 对于每个目标元素，我们可以计算可以增加多少个元素以在`k`运营。 虽然这是正确的，但它的时间复杂度为 O(n^2)，并且对于大型数组来说太慢。 

最佳解决方案的**关键见解**是我们可以对数组进行排序并专注于**滑动窗口**。 通过排序，我们知道，如果我们想让一个元素子集等于该子集中最大的元素，那么增加该窗口中较小的元素以匹配最大的元素总是最佳的。 然后我们可以维护一个窗口`[left, right]`代表我们试图使其等于的元素`nums[right]`。 将窗口中所有元素增加到的总成本`nums[right]`可以使用运行总和来有效地维护。 

因此，最佳解决方案是带有前缀和的**滑动窗口**方法，其中窗口贪婪地扩展，直到所需的总增量超过`k`，此时我们从左侧收缩。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 单独增加每个元素并计算频率 |
 | 最佳| O(n log n) | O(n log n) | O(1) | O(1) | 排序+滑动窗口维护增量之和 |

 ## 算法演练

 1. **对数组进行排序**。 这使我们能够考虑连续的数字序列，其中最小的数字可以递增以匹配最大的数字。 
2. **初始化两个指针**，`left = 0`并迭代`right`在阵列上。 
3. **维护一个运行总和**，表示当前窗口中的元素总数。 
4. 对于每个新的`right`，计算增加窗口中所有元素的总成本`[left, right]`到`nums[right]`使用公式`cost = nums[right] * window_size - window_sum`。 
5. 如果成本超过`k`, 增量`left`缩小窗口并相应调整窗口总和。 
6. 将最大频率更新为`right - left + 1`每一步之后。 
7. 返回找到的最大频率。 

**为什么它有效：** 保持的不变性是窗口中的所有元素`[left, right]`可以增加到`nums[right]`不超过`k`运营。 通过贪婪地扩大窗口并在必要时缩小窗口，我们确保在每一步都考虑最大可能的有效频率。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxFrequency(self, nums: List[int], k: int) -> int:
        nums.sort()
        left = 0
        total = 0
        max_freq = 0
        
        for right in range(len(nums)):
            total += nums[right]
            while (nums[right] * (right - left + 1) - total) > k:
                total -= nums[left]
                left += 1
            max_freq = max(max_freq, right - left + 1)
        
        return max_freq
```**实现演练：** 首先，我们排序`nums`这样我们就可以按升序处理元素。 我们维护一个滑动窗口`[left, right]`和一个运行总和`total`该窗口中的元素。 对于每个`right`，我们计算使所有元素等于所需的操作`nums[right]`。 如果这超过`k`，我们从左侧缩小窗口。 处理完每个元素后，我们更新`max_freq`跟踪最大的有效窗口。 

## 解决方案```go
import "sort"

func maxFrequency(nums []int, k int) int {
    sort.Ints(nums)
    left := 0
    total := 0
    maxFreq := 0

    for right := 0; right < len(nums); right++ {
        total += nums[right]
        for nums[right]*(right-left+1)-total > k {
            total -= nums[left]
            left++
        }
        if right-left+1 > maxFreq {
            maxFreq = right - left + 1
        }
    }

    return maxFreq
}
```**Go 特定注释：** 排序是使用`sort.Ints`。 我们小心地使用整数运算，并且因为`total`是一个`int`，在 Go 中它可以容纳最多 10^10 的和而不会溢出。 该逻辑反映了使用滑动窗口和运行总和的 Python 解决方案。 

## 工作示例

 ### 示例 1：`nums = [1,2,4], k = 5`排序后：`[1,2,4]`窗口展开：

 | 左| 对| 窗口总和 | 成本| 最大频率|
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 1 | 0 | 1 |
 | 0 | 1 | 3 | 1*2 -3=1? 等等我们来算一下| 2 |
 | 0 | 2 | 7 | 4*3 - 7 = 5 | 4*3 - 7 = 5 3 |

 所有元素都可以增加到 4，总成本 5 ≤ k。 输出：3。 

### 示例 2：`nums = [1,4,8,13], k = 5`排序后：`[1,4,8,13]`窗口计算：

 - 右=0：最大频率=1
 - 右=1：成本= 4*2 - (1+4)=8-5=3 ≤ 5 → max_freq=2
 - Right=2: cost = 8_3 - (1+4+8)=24-13=11 > 5 → 向左收缩 → left=1 → cost=8_2-(4+8)=16-12=4 ≤5 → max_freq=2
 - 右=3：cost=13_3-(4+8+13)=39-25=14>5→向左缩小→左=2→cost=13_2-(8+13)=26-21=5→max_freq=2

 输出：2

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 排序需要 O(n log n)，滑动窗口是 O(n) |
 | 空间| O(1) | O(1) | 仅使用指针和运行总和 |

 排序主导时间复杂度。 滑动窗口确保我们对于左指针和右指针只遍历每个元素一次。
