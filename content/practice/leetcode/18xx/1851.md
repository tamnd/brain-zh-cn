[LeetCode 问题 1851](https://leetcode.com/problems/minimum-interval-to-include-each-query/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、扫描线、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题为我们提供了包含整数区间的集合和查询值列表。 对于每个查询，我们必须确定包含该查询值的最小区间的大小。 

一个区间`[left, right]`包含一个查询`q`如果：```
left <= q <= right
```区间的大小为：```
right - left + 1
```对于每个查询，我们不仅仅寻找包含它的任何区间。 我们特别需要所有有效区间中最小尺寸的区间。 

例如，如果间隔是：```
[1, 10]
[3, 5]
[4, 4]
```查询是`4`，那么所有三个区间都包含`4`，但它们的大小是：```
10
3
1
```所以答案是`1`， 因为`[4,4]`是最小有效区间。 

输入尺寸很大：

 - 最多`10^5`间隔
 - 最多`10^5`查询

 检查每个查询的每个间隔的简单解决方案需要：```
10^5 * 10^5 = 10^10
```在最坏的情况下，操作速度太慢了。 

这些限制强烈表明我们需要一种接近以下的算法：```
O(n log n)
```或者```
O((n + q) log n)
```在哪里：

-`n = len(intervals)`-`q = len(queries)`几个重要的边缘情况立即出现：

 - 不在任何区间内的查询应该返回`-1`- 多个间隔可能包含相同的查询
 - 间隔可能会严重重叠
 - 查询可能以任意顺序出现
 - 多个查询可以具有相同的值
 - 间隔可以有大小`1`， 例如`[4,4]`- 非常大的间隔可能包含许多查询，但较小的间隔仍然可能是正确的答案

 该问题保证：

 - 每个区间都是有效的，因为`lefti <= righti`- 所有值均为正整数
 - 输入数组非空
 这个问题要求我们在一组间隔内有效地回答多个范围查询。 每个区间由起点和终点定义，其大小只是其覆盖的整数数量，计算如下`right - left + 1`。 

对于每个查询值，我们需要找到包含该查询点的所有区间，这意味着区间的起点小于或等于查询，终点大于或等于查询。 在所有这些有效间隔中，我们必须返回最小的间隔大小。 如果没有区间包含查询点，我们返回`-1`。 

关键的挑战是间隔数量和查询数量都可能高达 100,000，因此任何为每个查询检查每个间隔的解决方案都会太慢。 

输入保证间隔边界和查询是最大 10^7 的正整数，并且包含间隔。 重要的边缘情况包括落在所有间隔之外的查询、具有不同大小的多个重叠间隔以及折叠到单个点的间隔。 

一种简单的方法会重复扫描每个查询的所有间隔，但这在规模上是不可行的。 该结构表明我们需要预处理间隔并在接近对数的时间内回答查询。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立处理每个查询。 

对于每个查询：

 1. 迭代所有区间
 2、检查区间是否包含查询
 3. 如果是，计算它的大小
 4. 追踪目前看到的最小尺寸
 5、如果没有区间包含查询，则返回`-1`这种方法很简单，而且显然是正确的，因为它明确地检查了可能有助于得出答案的每个可能的区间。 

然而，其性能却令人无法接受。 

如果有：

 -`n`间隔
 -`q`查询

 那么总复杂度就变成：```
O(n * q)
```两个值都达到`10^5`，这变得太慢了。 

### 最佳方法

 关键的观察是查询可以按排序顺序处理。 

假设我们排序：

 - 按起始点划分的间隔
 - 按值查询

 然后，当我们从较小的查询转向较大的查询时，我们可以增量维护可能包含当前查询的间隔集。 

我们使用最小堆来有效地检索所有当前有效间隔中的最小间隔。 

对于每个查询：

 - 添加所有间隔`left <= query`- 删除间隔`right < query`- 剩余的间隔正是包含查询的间隔
 - 堆顶立即给出最小的区间大小

 这将问题转化为具有优先级队列的扫线算法。 

### 方法比较

 ## 算法演练

 ### 第 1 步：按起始位置对间隔进行排序

 我们首先排序`intervals`通过他们的左端点。 

这使我们能够随着查询的增加逐步处理间隔。 

例如：```
intervals = [[3,6],[1,4],[2,4]]
```变成：```
[[1,4],[2,4],[3,6]]
```### 步骤 2：将查询与其原始索引配对

 我们必须按照原始查询顺序返回答案。 

对查询进行排序后，否则它们的位置将会丢失。 

所以我们创建对：```
(query_value, original_index)
```例子：```
queries = [2,3,4,5]
```变成：```
[(2,0),(3,1),(4,2),(5,3)]
```然后我们按查询值对这些对进行排序。 

### 步骤 3：创建最小堆

 堆存储候选区间。 

每个堆条目包含：```
(interval_size, interval_right)
```为什么有这些值？ 

-`interval_size`允许堆优先考虑最小间隔
 -`interval_right`允许我们确定间隔是否仍然包含当前查询

 ### 步骤 4：按排序顺序扫描查询

 我们维护一个指向排序间隔数组的指针。 

对于每个查询：

 #### 4.1 添加新的符合条件的区间

 同时：```
interval.left <= query
```我们将间隔压入堆中。 

间隔大小为：```
right - left + 1
```此时，堆包含在查询之前或查询时开始的间隔。 

### 步骤 5：删除过期的间隔

 某些间隔不再包含当前查询。 

如果：```
interval.right < query
```那么该间隔不能包含此查询或任何未来的查询。 

所以我们把它从堆中删除。 

### 第 6 步：确定答案

 清理后：

 - 堆中剩余的每个区间都包含查询
 - 堆顶是最小的此类间隔

 如果堆为空：```
answer = -1
```否则：```
answer = heap[0].size
```### 步骤7：将答案存储在原来的位置

 由于查询已排序，因此我们使用原始查询索引存储结果。 

这将正确恢复最终的答案顺序。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 在回答查询之前，堆恰好包含包含该查询的间隔。 

这是有保证的，因为：

 - 我们添加左端点足够小的每个区间
 - 我们删除右端点太小的每个区间

 因此，堆始终代表当前查询的有效候选区间。 

由于堆是按间隔大小排序的，因此最小的有效间隔始终位于顶部。 
暴力方法会迭代每个查询，并且对于每个查询，扫描所有间隔以检查该间隔是否包含该查询。 如果是，我们计算它的大小并跟踪最小值。 

这种方法是正确的，因为它直接应用问题定义而不进行优化。 然而，它太慢了，因为它每个查询执行 O(n) 工作，导致 O(n × q)，最多 10^10 次操作。 

### 关键见解

 关键的观察是我们想要有效地回答：“在覆盖一个点的所有区间中，最小长度是多少？”

 如果我们按排序顺序处理查询，我们也可以按其起点的排序顺序处理间隔。 对于每个查询，我们维护一组“活动间隔”，即左端点已经≤查询的间隔。 在这些活动区间中，我们只想要那些右端点仍然≥查询的区间。 

为了有效地检索活动间隔中的最小间隔，我们使用按间隔大小排序的最小堆。 然而，我们还需要惰性地丢弃不再覆盖查询的间隔（它们的右端点太小）。 

这导致了扫描线方法与优先级队列的结合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × q) | O(1) | O(1) | 检查每个查询的所有间隔 |
 | 最优（扫描线 + 堆）| O((n + q) log n) | O((n + q) log n) | O(n) | 对间隔和查询进行排序，使用 min-heap |

 ## 算法演练

 1. 首先，我们按左端点对所有区间进行排序。 这确保了当我们以递增的顺序浏览查询时，我们可以逐步添加变为“活动”的间隔。 
2. 我们将查询转换为对的列表`(query_value, original_index)`并按查询值对它们进行排序。 这使我们能够按升序处理查询，同时仍然能够恢复原始排序。 
3. 我们初始化一个最小堆来存储活动间隔。 每个堆条目包含`(interval_size, right_endpoint)`所以我们总是可以有效地检索最小区间。 
4. 我们维护一个指向已排序区间的指针。 对于每个查询，我们将所有左端点小于或等于查询的间隔添加到堆中。 这些间隔现在是候选间隔，因为它们在查询之前或查询时开始。 
5. 添加间隔后，我们从堆中删除无效间隔。 具体来说，虽然堆顶的右端点小于当前查询，但它无法再覆盖该查询，因此我们将其丢弃。 
6. 如果清理后堆不为空，则顶部元素给出覆盖查询的最小有效区间。 否则，我们分配`-1`。 
7. 我们按排序顺序对所有查询继续此过程。 

关键思想是每个区间只被压入堆一次，最多弹出一次，以确保效率。 

### 为什么它有效

 该算法保持了这样的不变性：在每次查询时，堆恰好包含左端点 ≤ query 且尚未过期（右端点 ≥ query）的间隔。 由于堆是按区间大小排序的，因此顶部始终代表最小的有效区间，从而保证了正确性。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minInterval(self, intervals: List[List[int]], queries: List[int]) -> List[int]:
        intervals.sort()

        sorted_queries = sorted(
            (query, index)
            for index, query in enumerate(queries)
        )

        answers = [-1] * len(queries)

        min_heap = []

        interval_index = 0
        total_intervals = len(intervals)

        for query_value, query_index in sorted_queries:

            while (
                interval_index < total_intervals
                and intervals[interval_index][0] <= query_value
            ):
                left, right = intervals[interval_index]

                interval_size = right - left + 1

                heapq.heappush(
                    min_heap,
                    (interval_size, right)
                )

                interval_index += 1

            while min_heap and min_heap[0][1] < query_value:
                heapq.heappop(min_heap)

            if min_heap:
                answers[query_index] = min_heap[0][0]

        return answers
```实现首先根据起点对间隔进行排序。 这支持扫描线策略，因为随着查询的增加，间隔按排序顺序变得符合条件。 

在排序之前，查询会与其原始索引配对。 这是必要的，因为算法按升序处理查询，但最终结果必须与原始查询顺序匹配。 

堆存储以下元组：```python
(interval_size, interval_right)
```蟒蛇的`heapq`实现了最小堆，因此具有最小尺寸的区间自动出现在顶部。 

对于每个查询，第一个循环插入左端点小于或等于查询的所有间隔。 这些间隔可能包含查询。 

第二个循环删除右端点小于查询的间隔。 此类间隔已过期，因为它们不再与当前扫描位置重叠。 

在这些更新之后，堆仅包含有效的候选区间。 因此，最小间隔大小可在`min_heap[0][0]`。 

使用原始查询索引存储答案，以便最终输出顺序与输入顺序匹配。

### Code Explanation

The code first sorts intervals so we can process them in increasing order of start time. Then it sorts queries while keeping track of original indices.

The heap stores candidate intervals as `(size, right)`. As we move through queries, we push all intervals whose start is valid. Then we remove intervals that no longer cover the query.

Finally, the smallest interval size is taken from the heap top.

This matches the sweep line logic described earlier, ensuring each interval is processed efficiently.

type Interval struct {
    left, right int
}

type Item struct {
    size  int
    right int
}

type MinHeap []Item

func (h MinHeap) Len() int { return len(h) }
func (h MinHeap) Less(i, j int) bool {
    return h[i].size < h[j].size
}
func (h MinHeap) Swap(i, j int) {
    h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
    *h = append(*h, x.(Item))
}

func (h *MinHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func minInterval(intervals [][]int, queries []int) []int {
    type Q struct {
        val int
        idx int
    }

    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0]
    })

    qs := make([]Q, len(queries))
    for i, q := range queries {
        qs[i] = Q{q, i}
    }

    sort.Slice(qs, func(i, j int) bool {
        return qs[i].val < qs[j].val
    })

    h := &MinHeap{}
    res := make([]int, len(queries))
    for i := range res {
        res[i] = -1
    }

    idx := 0

    for _, q := range qs {
        for idx < len(intervals) && intervals[idx][0] <= q.val {
            left := intervals[idx][0]
            right := intervals[idx][1]
            size := right - left + 1
            heap.Push(h, Item{size, right})
            idx++
        }

        for h.Len() > 0 {
            top := (*h)[0]
            if top.right < q.val {
                heap.Pop(h)
            } else {
                break
            }
        }

        if h.Len() > 0 {
            res[q.idx] = (*h)[0].size
        }
    }

    return res
}

## 测试用例```python
from typing import List

class Solution:
    def minInterval(self, intervals: List[List[int]], queries: List[int]) -> List[int]:
        import heapq

        intervals.sort()

        sorted_queries = sorted(
            (q, i) for i, q in enumerate(queries)
        )

        result = [-1] * len(queries)

        heap = []

        i = 0

        for query, original_index in sorted_queries:

            while i < len(intervals) and intervals[i][0] <= query:
                left, right = intervals[i]

                heapq.heappush(
                    heap,
                    (right - left + 1, right)
                )

                i += 1

            while heap and heap[0][1] < query:
                heapq.heappop(heap)

            if heap:
                result[original_index] = heap[0][0]

        return result

solution = Solution()

## Edge Cases

### Queries Not Covered by Any Interval

A common source of bugs occurs when no interval contains a query. Some implementations may accidentally leave stale intervals inside the heap or incorrectly return a previous answer.

For example:

```间隔 = [[1,2]]
 查询 = [5]```

The implementation handles this correctly by removing all expired intervals before answering the query. If the heap becomes empty, the answer remains `-1`.

### Single-Point Intervals

Intervals such as:

```[4,4]```

have size `1`.

These intervals are especially important because they are often the optimal answer. A buggy implementation might incorrectly compute the size as:

```右 - 左```

instead of:

```右 - 左 + 1```

The implementation explicitly uses:

```右 - 左 + 1```

which correctly handles inclusive intervals.

### Large Overlapping Intervals

Another tricky case occurs when many intervals overlap the same query.

Example:

```间隔 = [[1,100],[20,30],[25,26]]
 查询=25
 ````

 所有区间包含`25`，但必须选择最小的间隔。 

堆结构保证了正确性，因为间隔是按大小排序的，而不是按开始或结束位置排序的。 即使之前添加了较大的间隔，最小的间隔也会自动上升到堆的顶部。

 ## 边缘情况

 一种重要的边缘情况是所有间隔都相同或完全嵌套。 在这种情况下，许多间隔同时保持活动状态，算法必须正确选择最小的间隔，而不是最近或最大的间隔。 

当查询完全超出所有间隔的范围时，会出现另一种边缘情况。 在整个处理过程中堆将保持为空，并且实现必须正确返回`-1`而不尝试无效的堆访问。 

第三种边缘情况涉及折叠成单个点的间隔，其中`left == right`。 这些间隔的大小为 1，并且当查询与该点完全匹配时，算法必须确保它们正确排列优先级，即使也存在更大的重叠间隔。
