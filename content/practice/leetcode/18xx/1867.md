[LeetCode 问题 1867](https://leetcode.com/problems/orders-with-maximum-quantity-above-average/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们识别“不平衡订单”`OrdersDetails`桌子。 每行代表订单中的一个产品，包含`order_id`,`product_id`， 和`quantity`订购了。 一个订单可以有多个产品，这意味着多行可以共享相同的产品`order_id`。 

**不平衡订单**定义为任何单一产品的**最大数量**严格大于**所有订单**的平均数量**（包括其本身）。 订单的平均数量计算为该订单中所有数量的总和除以该订单中的产品数量。 最大数量就是最大的`quantity`按这个顺序。 

我们有一个任意大小的表，并且必须返回`order_id`所有不平衡订单的值。 对订单或产品的数量没有明确的限制，但聚合计算的使用意味着将每个订单与其他每个订单进行单独比较的简单解决方案可能效率低下。 

关键的边缘情况包括：

 - 仅包含一种产品的订单：最大值等于平均值。 
- 所有数量都相等的订单：最大值等于平均值​​。 
- 多个订单共享相同的最大值或平均值：需要仔细比较，因为需要“严格更大”。 
- 预计不会出现负数量或零数量，因为这是电子商务订单上下文，从而简化了计算。 

该问题保证了`(order_id, product_id)`是唯一的，因此订单中的同一产品不存在重复项。 
问题提供了一个关系表`OrdersDetails`其中每一行代表订单中的一个产品。 每个`order_id`可以出现多次，因为一个订单可能包含多个产品，并且每行存储该订单中特定产品的数量。 

对于每个订单，我们定义两个指标。 第一个是平均数量，计算方式为该订单中所有数量的总和除以该订单中不同产品的数量。 第二个是最大数量，即该订单中单个产品的最大数量。 

如果订单的最大产品数量严格大于表中每个订单（包括其自身）的平均数量，则订单被视为**不平衡**。 换句话说，如果我们计算所有订单的平均值，则只有当订单的最大值大于这些平均值的全局最大值时，订单才符合资格。 

任务是归还所有`order_id`满足这个条件的值。 

The input size is not explicitly given, but since this is a database problem, we assume potentially large datasets where efficiency matters. A naive approach that repeatedly scans the table per order would be too slow.

 重要的边缘情况包括具有单一产品的订单（其中最大值等于平均值​​）、所有订单的平均值相同的订单，以及如果处理不仔细，浮点除法可能导致精度问题的订单。 

## 方法

 ### 蛮力方法

 暴力方法需要计算每个订单的最大数量和平均数量，然后对于每个订单，将其最大数量与**所有订单**的平均数量进行比较。 If the maximum quantity is greater than every average, we mark it as imbalanced.

 While this approach works logically, it is inefficient. 为了`n`订单，如果将每个订单与所有其他平均值进行比较，则复杂度为 O(n²)，这对于大型数据集来说变得不切实际。 在 SQL 中，这可能会转化为自连接，但代价高昂。 

### 最佳方法

 关键的见解是，如果订单的最大数量超过订单中所有平均数量的最大值，则订单不平衡**。 这是因为，要大于_every_平均值，它必须至少超过最高平均值。 因此，我们不需要将每个订单与其他每个订单单独进行比较。 

最佳方法涉及两个聚合步骤：

 1. 计算每个订单的平均数量和最大数量。 
2. 找出所有平均数量中的最大值。 
3. 选择最大数量超过该全局最大平均值的订单。 

这显着减少了比较，并且在 SQL 和编程实现中都很高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 将每个订单的最大值与所有订单的平均值进行比较 |
 | 最佳 | O(n) | O(n) | 计算每个订单的聚合，然后与全局最大平均值进行比较 |

 ## 算法演练

 1. **每个订单聚合：** 迭代每个订单并计算总数量、产品数量和最大数量。 将这些存储为`(order_id, avg_quantity, max_quantity)`对于每个订单。 
2. **计算全局最大平均值：** 迭代所有订单并确定所有订单的最大平均数量。 
3. **过滤不平衡订单：** 对于每个订单，将其最大数量与全局最大平均值进行比较。 如果`max_quantity > global_max_average`，将顺序包含在结果中。 
4. **返回结果：** 输出列表`order_id`s 满足条件。 

**为什么有效：**

 根据问题定义，如果订单的最大数量超过所有平均值，则订单不平衡。 全局最大平均值是所有订单平均值中最大的。 因此，将订单的最大值与全局最大值进行比较对于识别不平衡订单来说既必要又充分。 
暴力解决方案计算每个订单的平均值和最大值，然后将该订单的最大值与每个其他订单的平均值进行比较。 这需要重复重新计算聚合或跨订单执行嵌套扫描。 虽然正确，但效率低下，因为每次比较可能需要多次扫描整个数据集。 

### 最佳方法

 关键的观察是，条件“最大数量严格大于每个订单的平均数量”相当于说：

 我们只需要**所有订单的全局最大平均值**，然后过滤最大值超过该单个值的订单。 

因此，我们不是将每个订单与所有其他订单进行比较，而是首先计算每个订单的聚合（总和、计数、最大值），得出每个订单的平均值，然后全局计算这些平均值的最大值。 最后，我们选择最大数量超过此全局阈值的订单。 

这将问题减少到两个聚合过程，SQL 使用以下方法有效处理：`GROUP BY`。

 | 蛮力 | O(n²) | O(n) | 重复扫描每笔订单对比|
 | 最佳 | O(n) | O(k) | 使用 GROUP BY | 进行两次聚合传递

 ## 算法演练

 1. 首先，对表格进行分组`order_id`计算每个订单的三个值：总数量、产品数量和最大单产品数量。 此步骤是必要的，因为所有必需的指标都是从行级数据派生的订单级聚合。 
2. 将总数量除以产品数量来计算每个订单的平均数量。 我们将其保留为派生列，因为我们需要比较所有订单的平均值。 
3. 计算所有订单中这些平均值的最大值。 这成为判断订单是否不平​​衡的全局阈值。 
4. 过滤之前计算的订单聚合，仅保留那些订单`max_quantity > global_max_average`。 
5. 返回结果`order_id`价值观。 

### 为什么它有效

 关键的不变量是条件“最大值大于每个订单的平均值”减少为“最大值大于所有订单的最大平均值”。 这种转换消除了成对比较的需要，并通过全局聚合确保正确性。 

## Python 解决方案```python
import pandas as pd

def find_imbalanced_orders(OrdersDetails: pd.DataFrame) -> pd.DataFrame:
    # Step 1: Calculate per-order aggregates
    order_stats = OrdersDetails.groupby('order_id').agg(
        total_quantity=('quantity', 'sum'),
        product_count=('product_id', 'count'),
        max_quantity=('quantity', 'max')
    ).reset_index()
    
    # Calculate average quantity per order
    order_stats['avg_quantity'] = order_stats['total_quantity'] / order_stats['product_count']
    
    # Step 2: Determine the maximum of all average quantities
    global_max_avg = order_stats['avg_quantity'].max()
    
    # Step 3: Filter orders whose max quantity exceeds global max average
    imbalanced_orders = order_stats[order_stats['max_quantity'] > global_max_avg][['order_id']]
    
    return imbalanced_orders

type OrderRow struct {
    orderID   int
    productID int
    quantity  int
}

func findImbalancedOrders(rows []OrderRow) []int {
    type agg struct {
        sum   int
        count int
        max   int
    }

    stats := make(map[int]*agg)

    // Step 1: aggregate per order
    for _, r := range rows {
        if _, ok := stats[r.orderID]; !ok {
            stats[r.orderID] = &agg{sum: 0, count: 0, max: 0}
        }
        a := stats[r.orderID]
        a.sum += r.quantity
        a.count++
        if r.quantity > a.max {
            a.max = r.quantity
        }
    }

    // Step 2: compute averages and global max average
    maxAvg := 0.0
    avgMap := make(map[int]float64)

    for id, a := range stats {
        avg := float64(a.sum) / float64(a.count)
        avgMap[id] = avg
        if avg > maxAvg {
            maxAvg = avg
        }
    }

    // Step 3: collect results
    result := make([]int, 0)
    for id, a := range stats {
        avg := avgMap[id]
        if float64(a.max) > maxAvg {
            result = append(result, id)
        }
    }

    sort.Ints(result)
    return result
}

 ## 边缘情况

 一个重要的边缘情况是订单仅包含一种产品。 在这种情况下，平均值和最大值相同，这意味着此类订单永远不会不平衡，除非与其他订单的较小全局平均值进行比较。 

当所有订单具有相同的平均值时，会出现另一种边缘情况。 在这种情况下，全局最大平均值等于每个个体平均值，因此没有顺序可以满足严格的不平等条件。 该实现通过要求正确处理这个问题`max_quantity > max_avg`。 

最后的边缘情况涉及浮点精度。 由于平均值是通过除法计算的，因此使用整数除法会默默地产生不正确的结果。 该解决方案确保 Python 和 Go 中的浮点运算正确，以保持正确性。
