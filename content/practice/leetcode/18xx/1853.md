[LeetCode 问题 1853](https://leetcode.com/problems/convert-date-format/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题提供了一个名为`Days`有一列称为`day`。 此列中的每个值都是有效的 SQL`DATE`，并且每个值都是唯一的。 

任务是将每个日期转换为人类可读的字符串格式：```
"day_name, month_name day, year"
```例如：```
2022-04-12
```应该变成：```
Tuesday, April 12, 2022
```输出必须保留示例中所示的准确大小写和格式。 这意味着：

 - 工作日名称必须完整拼写。 
- 月份名称也必须完整拼写。 
- 月份中的某一天不应包含前导零。 
- 年份应显示为四位数。 
- 逗号和空格必须与所需的格式完全匹配。 

输入由来自的行组成`Days`桌子。 预期输出是另一个表，其中格式化字符串替换了原始的原始日期表示形式。 

由于这是一个数据库问题，主要的挑战是了解哪个 SQL 日期格式化函数会生成所需的输出格式。 

约束非常小，因为每一行都是独立处理的。 行之间没有联接、聚合、排序要求或复杂的关系。 这意味着性能不是这里关注的问题。 重点完全在于正确的日期格式。 

一个重要的边缘情况是处理个位数的日期，例如一个月的 9 号。 预期输出是：```
August 9, 2021
```不是：```
August 09, 2021
```另一个微妙之处是工作日名称必须与实际日历日期匹配。 手动计算工作日很容易出错，因此应使用内置的 SQL 格式化函数。 

该问题还保证有效日期，因此我们不需要处理格式错误的输入或无效的日历值。 

## 方法

 ### 蛮力方法

 强力方法将手动将日期分解为年、月和日部分，然后使用自定义映射计算工作日名称和月份名称。 

例如，我们可以：

 1. 提取数字年、月、日。 
2. 使用查找表或条件语句将月份数字转换为月份名称。 
3. 使用日历算法（例如 Zeller’s Congruence）计算工作日。 
4. 将所有部分连接成所需的字符串格式。 

这种方法可以正常工作，因为每个日期都可以通过确定性计算转换为其文本表示形式。 然而，对于数据库问题来说，这不必要地复杂，因为 SQL 已经提供了内置的日期格式化函数。 

手动工作日计算还会带来错误的机会，并使查询更难以阅读和维护。 

### 最佳方法

 最佳解决方案使用 SQL 的内置日期格式化功能。 

在 MySQL 中，`DATE_FORMAT()`函数可以直接将日期转换为所需的文本格式。 

格式字符串：```
'%W, %M %e, %Y'
```意思是：

 | 说明符 | 意义|
 | --- | --- |
 |`%W`| 工作日完整名称 |
 |`%M`| 完整的月份名称 |
 |`%e`| 不带前导零的月份中的某天 |
 |`%Y`| 四位数年份 |

 这种方法既简单又可靠，因为数据库引擎在内部处理所有日期计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 手动计算工作日和月份名称 |
 | 最佳| O(n) | O(1) | O(1) | 使用内置的 SQL 日期格式 |

 ## 算法演练

 1. 读取每一行`Days`桌子。 

每行包含一个`DATE`值存储在`day`柱子。 
2. 应用`DATE_FORMAT()`功能。 

该函数使用指定的格式模式将日期转换为格式化字符串。 
3.使用格式字符串`%W, %M %e, %Y`。 

这会生成：

 -`%W`工作日名称
 -`%M`月份名称
 -`%e`没有前导零的一天
 -`%Y`今年
 4.使用相同的列名返回格式化结果`day`。 

该问题期望输出列也被命名`day`。 

### 为什么它有效

 该解决方案之所以有效，是因为 SQL 日期格式化函数旨在转换有效的日期`DATE`根据格式说明符将值转换为文本表示形式。 所需输出格式的每个组成部分都直接映射到内置格式标记，确保生成的字符串与预期格式完全匹配。 

## Python 解决方案

 LeetCode 数据库问题是使用 SQL 而不是可执行的 Python 代码来解决的。 以下代表正确的 MySQL 查询。```python
# Write your MySQL query statement below

SELECT DATE_FORMAT(day, '%W, %M %e, %Y') AS day
FROM Days;
```该查询处理中的每一行`Days`独立表。`DATE_FORMAT()`是解决方案中的关键功能。 它需要两个参数：

 - 要格式化的日期列
 - 格式化模式

 结果被别名化回`day`因为输出表必须包含具有该确切名称的列。 

格式化字符串与所需的输出完全匹配：

 -`%W`产生像这样的名字`Tuesday`-`%M`产生像这样的名字`April`-`%e`从天数中删除前导零
 -`%Y`产生四位数年份

 ## 边缘情况

 ### 个位数天数

 日期如`2021-08-09`很重要，因为输出必须显示`9`而不是`09`。 一个常见的错误是使用`%d`，用前导零填充日期。 这个实现正确地使用了`%e`，这会删除不必要的填充。 

### 闰年日期

 闰年日期如下`2020-02-29`可以暴露手动日历计算中的错误。 由于该解决方案依赖于 MySQL 的内置日期处理，因此无需额外逻辑即可自动正确处理闰年。 

### 年份界限

 接近年初或年末的日期，例如`2021-12-31`或者`2022-01-01`，是手动实施中工作日计算错误的常见来源。 使用`DATE_FORMAT()`保证数据库引擎自动计算正确的工作日和月份名称。
