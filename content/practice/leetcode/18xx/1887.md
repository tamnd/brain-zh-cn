[LeetCode 问题 1887](https://leetcode.com/problems/reduction-operations-to-make-the-array-elements-equal/)

 **难度：** 🟡 中等
 **主题：** 数组、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们通过重复地将最大元素减少到数组中的下一个最大元素来使整数数组中的所有元素相等。 输入是一个数组`nums`整数，其中每个操作都需要识别**当前最大元素**并将其减少到**严格小于它的**下一个最大元素**的值。 输出是直到所有元素相等为止所需的此类操作的总数。 

限制条件`1 <= nums.length <= 5 * 10^4`和`1 <= nums[i] <= 5 * 10^4`表明数组可能相当大，因此任何重复扫描数组以查找最大元素的简单方法都可能太慢。 边缘情况包括所有元素最初都相等的数组、具有所有不同元素的数组或具有许多重复项的数组。 

该问题保证了具有正整数的非空数组，这简化了空数组或零值数组的处理。 

## 方法

 ### 蛮力方法

 强力解决方案会重复扫描数组以找到最大的元素，然后将其减少到下一个最大的元素。 我们会对每个操作进行计数，直到所有元素都相等。 虽然这种方法是正确的，但效率很低。 每次操作都需要找到最大和第二大元素，每次操作的时间复杂度为 O(n)。 如果数组包含许多不同的元素，则总时间复杂度可能为 O(n^2)，这对于 n 高达 50,000 时是不可接受的。 

### 最佳方法

 关键的观察结果是，每个元素所需的操作数量由其**在唯一值集中的排名**决定。 如果我们对数组进行排序，每个元素只需要重复减少到下一个较小的唯一值。 具体来说，最大的独特元素贡献`0`最初为自己运营，第二大贡献`count of elements greater than it`操作等。 我们可以根据每个唯一元素在排序的唯一数组中的排名对每个唯一元素的贡献求和来计算总操作。 

这避免了重复扫描数组，而是依赖于计算每个值的出现次数并迭代排序的唯一值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 重复扫描数组以减少最大元素 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 对唯一值进行排序并根据排名进行计数操作 |

 ## 算法演练

 1. 使用哈希图统计数组中每个数字的出现频率。 这有助于我们快速确定有多少元素大于任何给定元素。 
2. 从数组中提取唯一元素并按升序对它们进行排序。 需要排序来建立数字之间的“下一个最大”关系。 
3. 初始化变量`operations`到 0。这将累积归约操作的总数。 
4. 初始化变量`runningSum`到 0。这表示大于当前数量的元素的累积数量。 
5. 从第二小的元素开始迭代已排序的唯一元素：

 1. 对于每个元素，添加`runningSum`到`operations`。 这说明了大于当前元素的元素必须减少到当前元素的次数。 
2. 更新`runningSum`通过添加当前元素的频率。 这确保下一次迭代考虑所有较大元素的累积效应。 
6. 返回`operations`作为最终结果。 

**为什么有效：** 通过迭代已排序的唯一元素并跟踪较大元素的累积计数，我们确保每个元素对总操作的贡献被精确计算一次。 该算法利用了这样一个事实：归约操作总是沿着已排序的唯一序列将元素移向较小的值。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def reductionOperations(self, nums: List[int]) -> int:
        freq = Counter(nums)
        unique_nums = sorted(freq)
        operations = 0
        running_sum = 0
        for num in unique_nums[1:]:
            running_sum += freq[unique_nums[unique_nums.index(num)-1]]
            operations += running_sum
        return operations
```**解释：** 我们首先使用`Counter`。 我们对唯一的数字进行排序并从第二小的元素开始迭代。 对于每个元素，我们将所有较大元素的频率累积和添加到`operations`并更新`running_sum`包括前一个元素的计数。 这反映了问题中描述的归约操作。 

## 解决方案```go
import (
    "sort"
)

func reductionOperations(nums []int) int {
    freqMap := make(map[int]int)
    for _, num := range nums {
        freqMap[num]++
    }
    
    uniqueNums := make([]int, 0, len(freqMap))
    for num := range freqMap {
        uniqueNums = append(uniqueNums, num)
    }
    
    sort.Ints(uniqueNums)
    
    operations := 0
    runningSum := 0
    
    for i := 1; i < len(uniqueNums); i++ {
        prevNum := uniqueNums[i-1]
        runningSum += freqMap[prevNum]
        operations += runningSum
    }
    
    return operations
}
```**说明：** Go 实现镜像了 Python 逻辑。 我们使用映射来计算频率、收集和排序唯一数字，并使用累积和计算运算。 差异包括显式地图处理和索引，但算法逻辑是相同的。

 ## 边缘情况

 **单元素数组：** 长度为1的数组需要零次操作。 该算法正确处理了这个问题，因为唯一元素列表的长度为 1，并且索引 1 开始的循环将不会执行。 

**所有元素相等：** 如果所有元素都相同，则不需要归约。 累积和机制正确地导致零操作。 

**大量重复项：** 具有许多重复值的数组会给简单的方法带来压力。 我们的算法使用频率图和累积和有效地处理重复项，而无需多次扫描数组。 

**严格增加或减少数组：** 这些情况确保每个元素贡献最大的操作。 我们的算法通过计算大于当前元素的元素来正确地求和贡献。 

**边缘数值：** 元素处于最大约束值（例如 50,000）的数组可以正确处理，因为 Python 和 Go 支持达到这些范围的整数而不会溢出。
