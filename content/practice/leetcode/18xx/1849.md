[LeetCode 问题 1849](https://leetcode.com/problems/splitting-a-string-into-descending-consecutive-values/)

 **难度：** 🟡 中等
 **主题：** 字符串、回溯、枚举

 ## 解决方案

 ## 问题理解

 问题给了我们一个数字字符串`s`并询问是否可以将其拆分为至少两个非空子字符串，使得它们的整数值形成严格的降序序列，其中每个相邻对的相差恰好`1`。 

重要的细节是我们比较子字符串的数值，而不是字面子字符串文本。 这意味着允许使用前导零。 例如，`"05"`被解释为整数`5`， 和`"004"`被解释为`4`。 

我们必须确定是否存在至少一个有效的字符串分区。 我们可以根据需要自由选择子串边界，只要：

 1. 每个子串都非空。 
2. 数字的顺序是严格降序的。 
3. 每个相邻对的差异恰好是`1`。 
4. 至少有两个子串。 

例如：

-`"050043"`可以成为`["05", "004", "3"]`，对应于`[5, 4, 3]`。 
-`"1234"`不能分成降序的连续序列。 

输入尺寸非常小，因为`s.length <= 20`。 这个约束非常重要，因为它告诉我们指数探索是可以接受的。 在较大的输入大小中，尝试所有子字符串拆分是不可能的，但只有 20 个字符，我们可以安全地使用回溯或 DFS。 

有几个重要的边缘情况：

 - 带有前导零的字符串，例如`"0090089"`。 
- 只能形成递增序列的字符串，例如`"001"`。 
- 非常短的字符串，例如`"1"`，它不能分成至少两部分。 
- 超过 32 位整数限制的大数字子字符串。 由于长度最多可达 20 位数字，因此我们应该在 Python 中使用任意精度的整数，`int64`在围棋中。 
- 多次分区尝试在一次成功之前失败的情况。 

## 方法

 ### 蛮力方法

 强力解决方案将生成将字符串拆分为子字符串的所有可能方法。 对于一个长度的字符串`n`， 有`2^(n-1)`可能的分区模式，因为字符之间的每个间隙都可以包含分割或不包含分割。 

对于每个分区配置，我们将：

 1. 将每个子字符串转换为整数。 
2. 检查序列是否严格降序。 
3. 验证每个相邻的差值是否相等`1`。 

这种方法是正确的，因为它会检查所有可能的分割，因此如果存在有效的分区，它最终会找到它。 

然而，它的效率很低，因为每个分区都必须显式地构建和验证。 虽然`n <= 20`使其在技术上可行，我们可以通过尽早修剪无效路径来做得更好。 

### 最优方法，回溯与早期剪枝

 关键的观察是，一旦我们选择了第一个数字，未来的每个数字就完全确定了。 如果之前的值是`x`，那么下一个值必须恰好是`x - 1`。 

这意味着我们不需要在第一次选择后生成任意分区。 相反，我们可以：

 1. 尝试所有可能的第一个子串。 
2. 递归地尝试匹配下一个所需的值。 
3. 当子串与期望的数字不匹配时立即停止。 

这大大减少了不必要的探索，因为无效分支会提前终止。 

由于字符串长度只有20，递归回溯既简单又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 生成每个分区并随后验证 |
 | 最佳| O(2^n) | O(2^n) | O(n) | 基于预期的下一个值进行剪枝回溯 |

 ## 算法演练

 ### 第 1 步：选择第一个数字

 我们迭代字符串的每个可能的前缀作为第一个数字。 

例如，如果`s = "050043"`:

 - 第一个数字可能是`"0"`- 或者`"05"`- 或者`"050"`- 等等

 我们在最后一个字符之前停止，因为我们至少需要两个子字符串。 

### 步骤2：开始递归回溯

 一旦选择了第一个值，我们就会递归地搜索下一个值等于的子字符串：```
previous_value - 1
```如果之前的值是`5`，那么下一个子字符串必须计算为`4`。 

### 第 3 步：逐步构建下一个数字

 在每次递归调用时，我们一次将下一个子字符串扩展一位。 

例如：```
s = "0043"
```可能的子串是：

 -`"0"`→ 0
 -`"00"`→ 0
 -`"004"`→ 4

 我们不断构建整数值并将其与预期目标进行比较。 

### 步骤 4：找到匹配项时递归

 如果子字符串值等于预期的下一个值：

 - 我们从剩余的后缀递归地继续。 
- 匹配的值成为新的先前值。 

### 步骤5：当整个字符串被消耗时返回成功

 如果我们成功到达字符串的末尾，那么我们就找到了有效的分割。 

### 第 6 步：失败时回溯

 如果没有子字符串产生所需的下一个值，我们返回`False`并尝试另一个分区。 

### 为什么它有效

 该算法之所以有效，是因为每个递归状态都保持严格的不变量：

 > 先前选择的数字已经形成有效的降序连续序列。 

在每一步中，我们只接受子字符串，如果它的值恰好等于`previous - 1`。 因此，每个递归扩展都保持有效性。 由于我们探索所有可能的第一个数字和所有可能的匹配延续，因此算法将找到有效的分割（如果存在）。 

## Python 解决方案```python
class Solution:
    def splitString(self, s: str) -> bool:
        n = len(s)

        def dfs(index: int, previous: int) -> bool:
            if index == n:
                return True

            current = 0

            for end in range(index, n):
                current = current * 10 + int(s[end])

                if current == previous - 1:
                    if dfs(end + 1, current):
                        return True

                if current >= previous:
                    break

            return False

        first = 0

        for i in range(n - 1):
            first = first * 10 + int(s[i])

            if dfs(i + 1, first):
                return True

        return False
```实现首先尝试将每个可能的前缀作为第一个数字。 变量`first`是增量构建的以避免重复的子字符串转换。 

递归`dfs`函数接收两个参数：

 -`index`，字符串中的当前位置
 -`previous`，下一个数字的值必须小于

 在 DFS 中，我们逐位构建下一个数字。 如果构造的值等于`previous - 1`，我们进一步递归。 

修剪条件：```python
if current >= previous:
    break
```很重要，因为数字只会随着我们添加更多数字而增长。 一旦当前值变得太大，以后的扩展就无法满足下降条件。 

如果我们成功消耗整个字符串，我们将返回`True`。 

## 解决方案```go
package main

func splitString(s string) bool {
	n := len(s)

	var dfs func(index int, previous int64) bool

	dfs = func(index int, previous int64) bool {
		if index == n {
			return true
		}

		var current int64 = 0

		for end := index; end < n; end++ {
			current = current*10 + int64(s[end]-'0')

			if current == previous-1 {
				if dfs(end+1, current) {
					return true
				}
			}

			if current >= previous {
				break
			}
		}

		return false
	}

	var first int64 = 0

	for i := 0; i < n-1; i++ {
		first = first*10 + int64(s[i]-'0')

		if dfs(i+1, first) {
			return true
		}
	}

	return false
}
```Go 实现遵循与 Python 版本相同的递归结构。 

一个重要的区别是数字处理。 Python 整数自动支持任意精度，但 Go 整数是固定大小的。 由于最大字符串长度为 20，`int64`足以满足问题的约束条件。 

Go 还要求在分配函数体之前显式声明递归函数变量。

 ## 边缘情况

 ### 子字符串中的前导零

 错误的一个常见来源是按字典顺序而不是数字方式处理子字符串。 例如，`"004"`应该被解释为整数`4`，而不是作为一个独特的值。 该实现可以正确处理这个问题，因为每个子字符串在构造过程中都会进行数字转换。 

### 非常短的字符串

 长度的字符串`1`不能产生至少两个子串。 粗心的实现可能会错误地返回`True`如果 DFS 立即到达末尾。 该解决方案通过确保初始循环仅选择第一个数字来避免这种情况`n - 1`，保证至少有一个剩余子串。 

### 大数值

 该字符串最多可以包含 20 位数字，这可能会溢出标准 32 位整数。 Python天然支持任意大的整数，而Go解决方案明确使用`int64`。 这确保了即使对于大子字符串，比较也保持正确。 

### 失败前部分匹配的路径

 某些输入可能最初看起来有效，但后来会失败。 例如，`"1098"`作为`10,9,8`， 但`"1097"`第一步后失败。 递归回溯正确地探索更深层次的状态，并在后面的条件失败时回溯。
