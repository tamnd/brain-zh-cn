[LeetCode 问题 1806](https://leetcode.com/problems/minimum-number-of-operations-to-reinitialize-a-permutation/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、模拟

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个偶数`n`并定义初始排列：```
perm[i] = i
```这意味着数组最初看起来像：```
[0, 1, 2, 3, ..., n - 1]
```我们重复应用转换规则来构建一个新数组`arr`：

 - 如果索引`i`是偶数：```
arr[i] = perm[i / 2]
```- 如果索引`i`是奇数：```
arr[i] = perm[n / 2 + (i - 1) / 2]
```施工后`arr`，我们替换`perm`和`arr`。 

任务是确定排列返回其原始状态所需的最小非零操作数。 

重要的细节是转换是确定性的。 每个操作都会以完全相同的方式重新排列索引。 最终，因为大小的排列只有有限种`n`，该过程必须循环回到起始配置。 

限制相对较小：```
2 <= n <= 1000
```自从`n`最多1000，即使直接模拟的方法也是可行的。 然而，该问题包含一个重要的数学观察，使我们能够避免模拟整个排列。 

一些重要的边缘情况立即脱颖而出：

 -`n = 2`是最小的有效输入。 经过一次操作后排列已经恢复。 
- 一些值`n`产生短周期，而其他产生更长的周期。 
- 重复构造数组的简单实现是可行的，但这是不必要的，因为只有索引的移动才重要。 

关键的挑战是了解元素在变换下如何移动，并确定所有位置何时同时返回到其原始位置。 

## 方法

 ### 暴力模拟

 最直接的方法是逐字模拟问题陈述中描述的过程。 

我们从以下开始：```
perm = [0, 1, 2, ..., n - 1]
```在每次操作时：

 1.创建一个新数组`arr`。 
2、按照转换规则填写。 
3. 更换`perm`和`arr`。 
4. 计算操作次数。 
5.停一次`perm`再次等于原来的排列。 

这种方法简单明了且易于推理，因为它完全反映了问题陈述。 

它是正确的，因为每个操作都会产生由规则定义的精确的下一个状态，并且我们继续直到再次遇到初始排列。 

然而，该解决方案重复重建大小的数组`n`，尽管问题本质上与指数变动有关。 虽然这是可以接受的`n <= 1000`，这不是最优雅或最有洞察力的解决方案。 

### 最优数学观察

 我们可以跟踪单个索引的移动，而不是模拟整个排列。 

该变换可以重写为索引的映射：

 对于一个索引`i`：```
if i is even:
    next = i / 2
else:
    next = n / 2 + (i - 1) / 2
```但更有用的形式来自于观察元素在一次操作后移动的位置。 

对于除以下以外的指数`0`和`n - 1`，变换的行为如下：```
position = (position * 2) % (n - 1)
```这意味着我们只需要重复应用这个模变换，直到位置返回到`1`。 

所需的申请数量正是答案。 

这将问题简化为求乘法阶`2`模数`n - 1`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × k) | O(n × k) | O(n) | 模拟每个排列状态 |
 | 最佳 | O(k) | O(1) | O(1) | 以数学方式追踪指数走势 |

 这里，`k`是排列返回其原始形式之前所需的操作数。 

## 算法演练

 ### 最优算法

 1. 从位置开始`1`。 

我们不使用位置`0`因为索引`0`每次操作后始终保持固定。 位置`1`是第一个实际移动的索引。 
2. 初始化一个操作计数器`0`。 

该计数器记录已应用的转换次数。 
3. 重复应用变换：```
position = (position * 2) % (n - 1)
```该公式描述了一次操作后指数如何变化。 
4. 每次转换后递增操作计数器。 
5. 继续，直到位置变为`1`再次。 

一旦定位`1`返回到原来的位置，整个排列周期就完成了。 
6. 返回操作次数。 

### 为什么它有效

 置换运算定义了索引的循环移动。 每个索引都遵循确定性路径。 当每个索引返回到其起始位置时，整个排列恰好返回到原始配置。 

指数的变动由乘法控制`2`模数`n - 1`。 因此，问题就变成了寻找最小的正整数`k`这样：$2^k \equiv 1 \pmod{n-1}$该值正是重新初始化排列所需的操作数。 

## Python 解决方案```python
class Solution:
    def reinitializePermutation(self, n: int) -> int:
        position = 1
        operations = 0

        while True:
            position = (position * 2) % (n - 1)
            operations += 1

            if position == 1:
                return operations
```实现直接遵循数学观察。 

我们从`position = 1`因为索引`1`是第一个不平凡的移动位置。 在每次迭代期间，我们应用模块化变换：```python
position = (position * 2) % (n - 1)
```这模拟了一次操作后跟踪索引的移动位置。 

循环继续，直到位置返回到`1`，这意味着循环已经完成。 变量`operations`存储应用的转换数量。 

该解决方案完全避免了构建数组，使其比暴力模拟更干净、更高效。 

## 解决方案```go
func reinitializePermutation(n int) int {
    position := 1
    operations := 0

    for {
        position = (position * 2) % (n - 1)
        operations++

        if position == 1 {
            return operations
        }
    }
}
```Go 实现与 Python 版本几乎相同。 

Go 使用显式整数变量`:=`初始化语法。 由于约束很小，因此不必担心整数溢出。 该循环是使用无限编写的`for`一旦位置返回到则终止循环`1`。 

不需要额外的切片或数组，因为数学方法仅跟踪单个移动索引。

 ## 边缘情况

 最小的有效输入是`n = 2`。 这种情况很重要，因为在单个操作之后排列已经返回到自身。 假设多次迭代或错误处理模算术的实现`n - 1 = 1`可能会在这里失败。 提供的解决方案可以自然地处理它，因为循环在第一次转换后立即完成。 

当周期长度异常短时会出现另一个重要的边缘情况，例如`n = 8`。 一些实现错误地假设答案随着`n`，但模块化循环可以快速重复。 无论其大小如何，数学方法都能正确计算出精确的周期长度。 

大值，例如`n = 1000`也很重要。 重复分配数组的暴力解决方案仍然可以在约束范围内工作，但它会执行不必​​要的内存操作。 最佳解决方案通过仅跟踪单个整数位置来完全避免此问题，即使对于最大的输入也确保恒定的空间使用。 

微妙的边缘情况涉及二的幂，例如`n = 16`。 由于模算术根据模数的不同而表现不同，因此索引转换公式的一些不正确的推导对于这些值会失败。 该实现直接使用经过验证的模块化关系，保证所有甚至的正确性`n`。
