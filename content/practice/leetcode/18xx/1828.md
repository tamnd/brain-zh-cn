[LeetCode 问题 1828](https://leetcode.com/problems/queries-on-number-of-points-inside-a-circle/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、几何

 ## 解决方案

 ## 问题理解

 这个问题给了我们二维平面上的两个几何对象的集合。 

第一个集合是一个名为的数组`points`，其中每个元素是一个坐标对`[x, y]`。 每对代表平面上的一个点。 允许多个点具有完全相同的坐标，因此必须单独计算重复项。 

第二个集合是一个名为的数组`queries`。 每个查询表示为`[x, y, r]`， 在哪里：

-`(x, y)`是圆的中心
 -`r`是该圆的半径

 对于每个查询，我们必须确定有多少点位于圆内部或圆边界上。 

一点`(px, py)`位于以`(cx, cy)`有半径`r`如果：$$(px - cx)^2 + (py - cy)^2 \le r^2$$左侧表示该点与中心之间的平方欧氏距离。 右侧是半径的平方。 使用平方值可以避免浮点运算和平方根。 

输出是一个数组，其中每个元素对应一个查询。 对于每个圆，我们返回满足距离条件的点数。 

限制相对较小：

 - 最多500分
 - 最多 500 条查询

 这意味着最多有：$$500 \times 500 = 250000$$点查询比较。 

这对于直接模拟方法来说足够小，可以轻松通过。 

一些边缘情况很重要：

 - 必须计算恰好位于圆边界上的点。 
- 多个点可以共享相同的坐标，并且必须全部计算在内。 
- 半径值可以足够大以包含所有点。 
- 查询可能包含内部没有点的圆圈。 
- 坐标是非负整数，但距离计算仍然可以变得足够大，以至于使用平方距离比使用浮点平方根更安全。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立处理每个查询。 

对于每个查询：

 1. 提取圆心和半径。 
2. 迭代每个点。 
3. 计算该点到圆心的平方距离。 
4. 如果距离的平方小于或等于半径的平方，则计算该点。 

这是可行的，因为圆内点的定义仅取决于其距圆心的距离。 

由于每个查询只检查每个点一次，因此总复杂度为：$$O(q \times n)$$在哪里：

-`q`是查询数
 -`n`是点数

 考虑到限制，这是完全可以接受的。 

### 更好的洞察力

 后续询问我们是否可以更好地回答查询`O(n)`时间。 

对于更大的约束，我们可以考虑空间索引结构，例如：

 - 四棵树
 - KD树
 - 网格分桶
 - 坐标上的前缀和技术

 然而，由于这个问题的限制，这样的优化是不必要的，只会使实现变得复杂。 

关键的见解是输入大小足够小，以至于仔细实施的强力解决方案在实践中已经是最佳的。

 ## 算法演练

 ### 最优算法

 1. 创建一个空结果数组。 

我们将把每个查询的答案存储在这个数组中。 
2. 迭代每个查询。 

每个查询包含：

 -`centerX`-`centerY`-`radius`3. 计算半径的平方。 

不使用平方根，而是计算：$$radiusSquared = radius \times radius$$这使所有计算保持在整数中并避免浮点精度问题。 
4. 为当前查询初始化一个计数器。 

该计数器跟踪有多少个点位于圆内或圆上。 
5. 迭代每个点。 

对于每个点：

 - 计算水平差：$$dx = pointX - centerX$$- 计算垂直差：$$dy = pointY - centerY$$6. 计算平方距离。 

使用：$$distanceSquared = dx^2 + dy^2$$7. 比较距离的平方与半径的平方。 

如果：$$distanceSquared \le radiusSquared$$那么该点在圆的内部或边界上，因此增加计数器。 
8. 检查所有点后，将计数器附加到结果数组中。 
9. 处理完所有查询后返回结果数组。 

### 为什么它有效

 欧几里得距离公式确定一个点是否位于圆内。 我们不比较实际距离，而是比较平方距离：$$(px - cx)^2 + (py - cy)^2 \le r^2$$该条件在数学上等价于标准圆方程，并且正确地包括边界点，因为`<=`比较。 

由于每个查询只检查每个点一次，因此每个有效点都会被计算在内，并且不包括无效点。 

## Python 解决方案```python
from typing import List

class Solution:
    def countPoints(self, points: List[List[int]], queries: List[List[int]]) -> List[int]:
        answer = []

        for center_x, center_y, radius in queries:
            radius_squared = radius * radius
            count = 0

            for point_x, point_y in points:
                dx = point_x - center_x
                dy = point_y - center_y

                distance_squared = dx * dx + dy * dy

                if distance_squared <= radius_squared:
                    count += 1

            answer.append(count)

        return answer
```实现直接遵循算法。 

外循环独立处理每个查询。 对于每个查询，代码都会提取中心坐标和半径。 

在检查点之前先对半径进行一次平方。 这避免了重新计算`radius * radius`反复。 

内循环遍历每个点。 对于每个点，代码计算距圆心的水平和垂直偏移。 

使用这些偏移量，计算平方距离：```python
dx * dx + dy * dy
```如果该值小于或等于半径的平方，则该点位于圆的内部或边界上，因此计数器会递增。 

处理完查询的所有点后，计数将附加到结果列表中。 

最后，该方法返回完整的答案数组。 

## 解决方案```go
func countPoints(points [][]int, queries [][]int) []int {
    answer := make([]int, 0, len(queries))

    for _, query := range queries {
        centerX := query[0]
        centerY := query[1]
        radius := query[2]

        radiusSquared := radius * radius
        count := 0

        for _, point := range points {
            dx := point[0] - centerX
            dy := point[1] - centerY

            distanceSquared := dx*dx + dy*dy

            if distanceSquared <= radiusSquared {
                count++
            }
        }

        answer = append(answer, count)
    }

    return answer
}
```Go 的实现与 Python 解决方案非常相似。 

切片用于输入和输出数组。 结果切片的初始化容量等于查询数量，以避免不必要的重新分配。 

所有计算都使用整数，这是安全的，因为最大坐标差很小。 在给定的约束下，整数溢出不是问题。 

与 Python 不同，Go 需要显式变量声明和使用`:=`用于局部变量初始化。

 ## 边缘情况

 ### 圆边界上的点

 一个常见的错误是使用严格的不等式：```
distance_squared < radius_squared
```而不是：```
distance_squared <= radius_squared
```该问题明确指出边界点被视为在圆内。 该实现可以正确处理这个问题`<=`比较。 

### 重复点

 输入允许多个相同的点。 有缺陷的实现可能会尝试使用集合或散列结构来删除重复点，这会产生不正确的计数。 

该算法独立处理每个点，因此重复项自然会被多次计算。 

### 非常大的圆圈

 某些查询的半径可能足够大以包含每个点。 该实现仍然可以正常工作，因为每个点都是根据距离公式独立检查的。 

由于坐标上限为 500，因此平方距离值仍然很小并且对于整数算术来说是安全的。 

### 没有匹配点的查询

 查询可以描述远离所有点的圆。 在这种情况下，计数应保持为零。 

该实现将每个查询的计数器初始化为零，并且仅在点满足条件时递增，因此自然会处理空结果。 

### 整数算术与浮点算术

 使用平方根会引入不必要的浮点计算和可能的精度问题。 

该实现改为比较平方距离：$$dx^2 + dy^2 \le r^2$$这在数学上是等价的并且保证了精确的整数比较。
