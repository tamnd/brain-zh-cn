[LeetCode 问题 1883](https://leetcode.com/problems/minimum-skips-to-arrive-at-meeting-on-time/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 您将获得一系列必须按顺序行驶的道路。 每条路都有一段距离，并且您以固定的速度行驶。 因为速度恒定，所以道路行驶时间`i`是：$$\frac{dist[i]}{speed}$$问题的棘手部分是强制休息规则。 走完除最后一条路以外的每条路后，必须等到下一个整数小时才能开始下一条路。 

例如：

 - 如果你及时完成一条路`2.3`，你必须等到时间`3.0`- 如果你准时完成`5.0`，你立即继续
 - 最后一条路后无需等待

 您可以跳过其中一些休息时间。 跳过休息意味着您立即继续驾驶，而不是四舍五入到下一个整数小时。 

目标是确定所需的最小跳跃次数，以便总行程时间最多为`hoursBefore`。 

如果即使跳过每次休息也无法让您准时到达，您就返回`-1`。 

输入包括：

 -`dist`，一系列道路距离
 -`speed`, 恒定行驶速度
 -`hoursBefore`, 截止日期

 约束条件很重要：

 -`n <= 1000`- 距离可能很大
 - 浮点精度可能变得危险
 - 对跳过的休息的所有子集进行强力搜索是不可能的，因为最多有`2^(n-1)`组合

 该问题强烈暗示动态规划，因为：

 - 决策是连续的
 - 每条路都有一个选择：

 - 跳过其余部分
 - 不要跳过其余部分
 - 我们想要一个最佳的最小值

 一些边缘情况很重要：

 - 行程可能已经适合，无需跳过
 - 即使跳过每次休息，仍有可能超过截止日期
 - 准确的整数小时到达时间不得错误地向上舍入
 - 浮点舍入错误很容易破坏正确性
 - 最终道路不需要绕行

 ## 方法

 ### 蛮力方法

 一个简单的方法是尝试跳过休息的所有可能的组合。 

有`n - 1`可能的休息站，可以做出跳过决定。 对于每个站点：

 - 要么跳过
 - 或者不跳过

 这创造了`2^(n-1)`的可能性。 

对于每个组合：

 1. 模拟旅程
 2. 应用等待规则
 3. 计算总时间
 4. 检查是否在规定时间内到达`hoursBefore`5. 跟踪最小跳过次数

 这是有效的，因为它详尽地检查了每一个有效的策略。 

然而，它太慢了。 和`n = 1000`，组合的数量变得非常大。 

### 关键见解

 重要的观察是，处理一些道路后唯一重要的是：

 - 我们使用了多少个跳过
 - 达到的最短可能时间

 这自然会导致动态规划。 

定义：$$dp[i][k]$$作为完成第一个任务所需的最短总时间`i`道路完全使用`k`跳过。 

对于每条路，我们都有两个转换：

 1. 不要跳过其余部分：

 - 添加旅行时间
 - 如果不是最后一条路，则四舍五入到下一个整数小时
 2. 跳过其余部分：

 - 直接添加行程时间
 - 没有四舍五入

 我们不使用浮点运算，而是以距离为单位而不是小时来存储时间。 

如果实际时间是：$$\frac{x}{speed}$$我们储存`x`。 

这完全避免了精度问题。 

舍入运算变为：$$\left\lceil \frac{x}{speed} \right\rceil \cdot speed$$可以使用整数算术来计算。 

## 方法比较

 | --- | --- | --- | --- |

 ## 算法演练

 1.定义一个DP表，其中`dp[k]`表示精确处理某些道路后的最小累积距离-时间单位`k`跳过使用。 
2. 不存储浮点小时，而是存储缩放值：$$\text{scaled time} = \text{actual time} \times speed$$这使所有内容都保持为整数并消除了精度问题。 
3.初始化：

 -`dp[0] = 0`- 所有其他状态都是无穷大
 4. 一条一条地处理道路。 
5. 对于每条道路和每个可能的跳跃计数，考虑两种选择。 
6.第一选择，不要跳过其余的：

 - 添加道路距离
 - 如果这不是最终道路，则四舍五入到下一个倍数`speed`舍入公式为：$\left\lceil \frac{x}{speed} \right\rceil \cdot speed$使用整数运算：$$\frac{x + speed - 1}{speed} \times speed$$7.第二个选择，跳过其余的：

 - 只需添加道路距离
 - 不发生舍入
 8. 存储每个的最小值`(road, skips)`状态。 
9. 处理完所有道路后，检查总时间满足以下条件的最小跳跃次数：$$dp[k] \le hoursBefore \times speed$$10. 返回最小跳过计数。 
11. 如果没有州满足截止日期，则返回`-1`。 

### 为什么它有效

 DP 不变量为：$$dp[i][k]$$始终存储完成第一个任务后可能的最小累积缩放时间`i`道路完全使用`k`跳过。 

每一个有效的道路策略`i`必须：

 - 跳过其余部分
 - 或等到下一个整数小时

 过渡步骤探索了两种可能性，并且仅保留可实现的最短时间。 由于考虑了所有有效决策并且保持最佳子结构，因此该算法可以正确计算所需的最小跳跃次数。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def minSkips(self, dist: List[int], speed: int, hoursBefore: int) -> int:
        n = len(dist)
        INF = float('inf')

        dp = [INF] * (n + 1)
        dp[0] = 0

        for i in range(n):
            next_dp = [INF] * (n + 1)

            for skips in range(i + 1):
                if dp[skips] == INF:
                    continue

                current = dp[skips] + dist[i]

                # Do not skip rest
                if i < n - 1:
                    wait_time = ((current + speed - 1) // speed) * speed
                else:
                    wait_time = current

                next_dp[skips] = min(next_dp[skips], wait_time)

                # Skip rest
                next_dp[skips + 1] = min(
                    next_dp[skips + 1],
                    current
                )

            dp = next_dp

        limit = hoursBefore * speed

        for skips in range(n + 1):
            if dp[skips] <= limit:
                return skips

        return -1
```该实现使用一维 DP 数组进行空间优化。`dp[k]`准确地存储可实现的最小缩放旅行时间`k`处理一些道路前缀后跳过。 

对于每条道路：

 -`current`表示行驶该道路后的累积时间
 - 第一个转换通过向上舍入应用强制等待
 - 第二个过渡完全跳过其余部分

 最后一条路经过特殊处理，因为之后不会发生等待。 

使用缩放整数时间而不是浮点时间是最重要的实现细节。 它可以防止此问题中经常出现的细微精度错误。 

该算法最终检查总缩放时间不超过的最小跳过计数：$$hoursBefore \times speed$$## 解决方案```go
package main

import "math"

func minSkips(dist []int, speed int, hoursBefore int) int {
	n := len(dist)
	inf := math.MaxInt64

	dp := make([]int, n+1)

	for i := 1; i <= n; i++ {
		dp[i] = inf
	}

	dp[0] = 0

	for i := 0; i < n; i++ {
		nextDP := make([]int, n+1)

		for j := 0; j <= n; j++ {
			nextDP[j] = inf
		}

		for skips := 0; skips <= i; skips++ {
			if dp[skips] == inf {
				continue
			}

			current := dp[skips] + dist[i]

			// Do not skip rest
			waitTime := current
			if i < n-1 {
				waitTime = ((current + speed - 1) / speed) * speed
			}

			if waitTime < nextDP[skips] {
				nextDP[skips] = waitTime
			}

			// Skip rest
			if current < nextDP[skips+1] {
				nextDP[skips+1] = current
			}
		}

		dp = nextDP
	}

	limit := hoursBefore * speed

	for skips := 0; skips <= n; skips++ {
		if dp[skips] <= limit {
			return skips
		}
	}

	return -1
}
```Go 实现遵循与 Python 解决方案相同的 DP 逻辑。 

一些 Go 的具体细节值得注意：

 -`math.MaxInt64`被用作无穷大
 - 切片用于DP存储
 - 整数算术安全地处理舍入
 - 不使用浮点值
 - Go整数除法自然地向零截断，这使得上限公式正确工作

 ## 边缘情况

 当到达时间正好落在整数小时边界上时，就会出现一种重要的边缘情况。 即使不需要等待，粗心的实现也可能会错误地向上舍入。 例如，恰好完成`3.0`小时数应允许立即继续。 该实现使用整数上限算术正确处理这个问题，这自然地保留了`speed`。 

另一个关键的边缘情况是最后的道路。 等待规则仅适用于道路之间，而不是到达目的地后。 许多错误的解决方案也会意外地绕过最终道路，从而导致行程时间增加。 该实现在处理最后一条路时明确跳过舍入。 

第三个重要的边缘情况涉及浮点精度。 由于行程时间是分数，重复的加法和取上限运算会累积浮点误差。 数学上应该等于的值`2.0`可能会成为`2.000000001`，导致不正确的额外等待。 该实现通过存储缩放的整数时间而不是浮点时间来完全避免这个问题。 

第四种边缘情况发生在即使跳过每次休息后仍无法出行时。 在这种情况下，每个 DP 州都会超过允许的最后期限。 最终验证循环正确返回`-1`如果不存在可行的跳过计数。
