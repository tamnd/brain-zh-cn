[LeetCode 问题 1896](https://leetcode.com/problems/minimum-cost-to-change-the-final-value-of-expression/)

 **难度：** 🔴难
 **主题：** 数学、字符串、动态规划、堆栈

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个布尔表达式，仅包含：

 -`'0'`和`'1'`- 二元运算符`'&'`和`'|'`- 括号

 该表达式保证有效，这意味着每个运算符都有有效的操作数，并且每个括号都正确匹配。 

重要的细节是表达式**不**使用正常的运算符优先级进行计算。 相反：

 1. 首先评估括号。 
2. 其他所有内容均严格从左到右进行评估。 

例如：```
1|1&0
```被评估为：```
(1|1)&0 = 1&0 = 0
```不是：```
1|(1&0) = 1
```目标是确定翻转表达式最终值所需的最少操作数。 

允许的操作有：

 - 改变`'0'`到`'1'`- 改变`'1'`到`'0'`- 改变`'&'`到`'|'`- 改变`'|'`到`'&'`每一次操作的成本都是准确的`1`。 

表达式长度可以大到`10^5`，所以我们需要一个非常高效的算法。 对所有可能的修改进行任何指数或二次探索都会太慢。 

幼稚的实现很容易失败，因为：

 - 表达式可以深度嵌套。 
- 从左到右的评估改变了操作员交互的方式。 
- 局部变化可能会影响全局结果。 
- 有时更改运算符比更改操作数更便宜。 
- 有时翻转深层嵌套的子表达式是最佳选择。 

另一个重要的观察结果是，我们没有被要求构建修改后的表达式。 我们只需要最少的操作次数。 

边缘情况包括：

 - 单个数字，例如`"0"`或者`"1"`- 非常深的括号嵌套
 - 长链，例如`"1|0|1|0|1"`- 改变操作符比改变操作数更便宜的情况
 - 翻转一个子表达式会自动改变整个结果的情况

 因为表达式是有效的并且在需要时完全用括号括起来，所以我们可以使用堆栈安全地解析它。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的修改序列，直到最终的表达式值翻转。 

对于表达式中的每个字符，我们可以：

 - 保持不变
 - 翻转一个数字
 - 翻转操作员

 然后，我们将评估结果表达式并跟踪更改最终值的最小修改次数。 

这种方法在理论上是正确的，因为它探索了所有可能的变换表达式。 最终它会找到最佳的。 

然而，这是完全不切实际的。 

如果表达式有长度`n`，那么每个可变字符都会引入多种可能性。 转换后的表达式的数量呈指数增长。 即使评估每个候选表达式也会花费额外的时间。 

和`n`最多`100000`，暴力是不可能的。 

### 关键见解

 关键的观察是，对于每个子表达式，我们只需要两条信息：

 - 当前的布尔值
 - 翻转该值所需的最低成本

 我们不是探索每个转换后的表达式，而是在解析表达式时增量计算这些值。 

例如，假设我们知道：

 - 左子表达式的计算结果为`0`和成本`2`翻转
 - 右子表达式的计算结果为`1`和成本`1`翻转

 那么我们可以确定：

 - 结果`left & right`- 翻转该结果的最低成本

 使用当地规则。 

这将问题转化为动态编程风格的解析问题。 

我们使用堆栈处理表达式：

 - 一个操作数栈
 - 操作员的一个堆栈

 每个操作数存储：```
(current_value, min_cost_to_flip)
```当我们用一个运算符组合两个操作数时，我们计算结果对。 

由于每个字符仅处理一次，因此解决方案变为线性。

 ## 算法演练

 ### 状态定义

 对于每个子表达式，我们存储：```
(value, flip_cost)
```在哪里：

-`value`是评估结果，或者`0`或者`1`-`flip_cost`是将这个子表达式更改为相反值所需的最少操作

 示例：```
"0" -> (0, 1)
"1" -> (1, 1)
```成本总是个位数`1`翻转。 

### 第 1 步：初始化堆栈

 我们使用：

 -`values`堆栈为`(value, flip_cost)`-`operators`堆栈为`'&'`,`'|'`,`'('`### 步骤 2：从左到右处理表达式

 我们迭代每个角色。 

如果角色是：

 -`'0'`或者`'1'`- 将其状态推送到`values`-`'&'`,`'|'`， 或者`'('`- 推到`operators`-`')'`- 解决一切问题，直到`'('`### 步骤 3：减少表达式

 每当我们有：```
left operator right
```我们将它们组合成一个新的状态。 

认为：```
left  = (lv, lc)
right = (rv, rc)
```### 步骤 4：合并 AND

 如果运算符是`'&'`：

 #### 结果值```
lv & rv
```#### 最低翻转成本

 如果结果是`1`：

 目前双方必须`1`。 

为了做出结果`0`，我们可以：

 - 向左翻转
 - 向右翻转
 - 将运营商更改为`'|'`并制作一侧`0`最优公式简化为：```
min(lc, rc)
```如果结果是`0`：

 为了做出结果`1`：

 - 两个操作数都必须变为`1`- 或运算符更改为`'|'`公式：```
if lv == 0 and rv == 0:
    min(lc + rc, 1 + min(lc, rc))
else:
    1
```### 步骤 5：合并 OR

 适用对称逻辑。 

如果结果是`0`：```
min(lc, rc)
```如果结果是`1`：```
if lv == 1 and rv == 1:
    min(lc + rc, 1 + min(lc, rc))
else:
    1
```### 步骤 6：处理括号

 当遇到`')'`，反复评估，直到`'('`已达到。 

### 第 7 步：最终答案

 完整解析后，仍保留一种状态。 

它是`flip_cost`就是答案。 

## 为什么它有效

 对于每个子表达式，该算法都保持一个不变量：```
(value, flip_cost)
```准确地表示：

 - 评估的布尔值
 - 反转该值所需的最少操作

 每个合并操作都会考虑翻转组合表达式的所有有效方法：

 - 改变操作数
 - 更换运营商
 - 两者的组合

 因为所有可能性都被局部最小化，并且每个子表达式只被处理一次，所以最终结果是全局最优的。 

## Python 解决方案```python
class Solution:
    def minOperationsToFlip(self, expression: str) -> int:
        values = []
        operators = []

        def apply():
            right_val, right_cost = values.pop()
            left_val, left_cost = values.pop()
            op = operators.pop()

            if op == '&':
                value = left_val & right_val

                if value == 1:
                    cost = min(left_cost, right_cost)
                else:
                    if left_val == 0 and right_val == 0:
                        cost = min(
                            left_cost + right_cost,
                            1 + min(left_cost, right_cost)
                        )
                    else:
                        cost = 1

            else:
                value = left_val | right_val

                if value == 0:
                    cost = min(left_cost, right_cost)
                else:
                    if left_val == 1 and right_val == 1:
                        cost = min(
                            left_cost + right_cost,
                            1 + min(left_cost, right_cost)
                        )
                    else:
                        cost = 1

            values.append((value, cost))

        for ch in expression:
            if ch == '0':
                values.append((0, 1))

            elif ch == '1':
                values.append((1, 1))

            elif ch in '&|(':
                operators.append(ch)

            elif ch == ')':
                while operators and operators[-1] != '(':
                    apply()

                operators.pop()

            else:
                while (
                    operators
                    and operators[-1] in '&|'
                ):
                    apply()

                operators.append(ch)

            while (
                len(values) >= 2
                and operators
                and operators[-1] in '&|'
            ):
                apply()

        while operators:
            apply()

        return values[-1][1]
```该实现使用两个堆栈来模拟表达式求值。 

这`values`堆栈存储元组：```python
(value, flip_cost)
```每个元组都总结了子表达式所需的所有内容。 

这`apply()`弹出助手：

 - 正确的操作数
 - 左操作数
 - 操作员

 并计算合并状态。 

里面的逻辑`apply()`直接编码 AND 和 OR 运算的最小成本转换规则。 

主解析循环逐个字符地处理表达式。 

数字立即变成状态：```python
(0, 1)
(1, 1)
```运算符和括号的处理方式与经典中缀表达式求值类似。 

每当有足够的信息可用于评估表达式时，`apply()`被称为。 

最后，剩余的元组包含完整的表达式结果和翻转它的最小成本。 

## 解决方案```go
type State struct {
	value int
	cost  int
}

func minOperationsToFlip(expression string) int {
	values := []State{}
	operators := []byte{}

	apply := func() {
		right := values[len(values)-1]
		values = values[:len(values)-1]

		left := values[len(values)-1]
		values = values[:len(values)-1]

		op := operators[len(operators)-1]
		operators = operators[:len(operators)-1]

		value := 0
		cost := 0

		if op == '&' {
			value = left.value & right.value

			if value == 1 {
				if left.cost < right.cost {
					cost = left.cost
				} else {
					cost = right.cost
				}
			} else {
				if left.value == 0 && right.value == 0 {
					a := left.cost + right.cost

					b := left.cost
					if right.cost < b {
						b = right.cost
					}
					b += 1

					if a < b {
						cost = a
					} else {
						cost = b
					}
				} else {
					cost = 1
				}
			}

		} else {
			value = left.value | right.value

			if value == 0 {
				if left.cost < right.cost {
					cost = left.cost
				} else {
					cost = right.cost
				}
			} else {
				if left.value == 1 && right.value == 1 {
					a := left.cost + right.cost

					b := left.cost
					if right.cost < b {
						b = right.cost
					}
					b += 1

					if a < b {
						cost = a
					} else {
						cost = b
					}
				} else {
					cost = 1
				}
			}
		}

		values = append(values, State{
			value: value,
			cost:  cost,
		})
	}

	for i := 0; i < len(expression); i++ {
		ch := expression[i]

		if ch == '0' {
			values = append(values, State{0, 1})

		} else if ch == '1' {
			values = append(values, State{1, 1})

		} else if ch == '&' || ch == '|' || ch == '(' {
			operators = append(operators, ch)

		} else if ch == ')' {
			for len(operators) > 0 &&
				operators[len(operators)-1] != '(' {
				apply()
			}

			operators = operators[:len(operators)-1]
		}

		for len(values) >= 2 &&
			len(operators) > 0 &&
			(operators[len(operators)-1] == '&' ||
				operators[len(operators)-1] == '|') {
			apply()
		}
	}

	for len(operators) > 0 {
		apply()
	}

	return values[len(values)-1].cost
}
```Go 实现遵循与 Python 版本相同的基于堆栈的设计。 

主要区别在于 Go 使用自定义`State`结构体而不是元组。 

切片用作堆栈：

 -`append()`推动
 - 切片删除顶部元素

 Go 不支持像 Python 那样自然地改变外部变量的嵌套辅助函数，但闭包在这里仍然可以正常工作。 

不存在整数溢出问题，因为成本永远不会超过表达式长度。

 ## 边缘情况

 ### 单字符表达式

 表达如`"0"`或者`"1"`很重要，因为它们不包含运算符或括号。 假设每个表达式都包含二元运算的解析器可能会在这里失败。 

该实现通过将单个状态推入堆栈并直接返回其翻转成本来自然地处理此问题。 

### 深层嵌套括号

 表达式例如：```
"((((1))))"
```可以暴露堆栈管理和括号处理中的错误。 

该算法安全地处理嵌套组，因为`'('`标记隔离子表达式直到匹配`')'`遇到。 

### 从左到右评估

 一个主要的陷阱是假设正常的运算符优先级。 

例如：```
1|1&0
```必须评估为：```
(1|1)&0
```不是：```
1|(1&0)
```该实现通过尽可能立即减少运算符来正确地强制执行此操作，而不是给出`&`更高的优先级。 

### 操作员变更最佳的情况

 有时更改运算符比修改操作数更便宜。 

例子：```
1&(0|1)
```改变`|`到`&`仅成本`1`，立即翻转最终结果。 

合并公式明确考虑运算符修改，确保始终找到最小成本。
