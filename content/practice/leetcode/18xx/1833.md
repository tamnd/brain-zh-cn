[LeetCode 1833 题](https://leetcode.com/problems/maximum-ice-cream-bars/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序、计数排序

 ## 解决方案

 ## 问题理解

 该问题要求我们确定一个男孩可以用有限数量的硬币购买最多数量的冰淇淋。 输入由一个数组组成`costs`， 在哪里`costs[i]`代表的是价格`i-th`冰淇淋棒和一个整数`coins`代表可用硬币总数。 男孩可以按任意顺序购买金条，但不能超出他的硬币预算。 预期输出是一个整数，表示他可以购买的最大金条数。 

约束告诉我们条形的数量，`n`，可大至 100,000，个人成本高达 100,000。 币预算可达1亿。 这种规模使得尝试所有子集或使用基于标准比较的排序进行排序等简单方法对于非常大的输入而言并不是最佳选择。 

重要的边缘情况包括所有成本超过的阵列`coins`（导致购买了零根柱），数组其中`coins`足以购买所有金条，以及许多金条具有相同成本的阵列。 该问题保证了`costs`和`coins`是正整数。 

## 方法

 蛮力方法涉及迭代所有子集`costs`找到总和不超过的最大子集`coins`。 虽然这给出了正确的答案，但子集的数量呈指数增长 (O(2^n))，这对于`n`最多 100,000。 

更好的方法是贪婪策略：首先购买最便宜的金条。 对数组进行排序并迭代地减去 bar 成本`coins`直到我们买不起更多的酒吧才能实现这一目标。 标准排序需要 O(n log n)，但该问题特别需要计数排序解决方案。 计数排序之所以有效，是因为成本是有界范围（1 到 100,000）内的整数。 我们计算每种成本的出现次数，然后从最便宜到最昂贵的迭代，在不超出硬币预算的情况下购买尽可能多的金条。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 生成所有子集和校验和，这对于大 n 来说是不切实际的 |
 | 最优（计数排序+贪心）| O(n + m) | O(米) | 计算每种成本的出现次数，从最便宜到最昂贵进行迭代；`m`是最大成本|

 ## 算法演练

 1. **初始化一个大小为计数的数组**`max_cost + 1`， 在哪里`max_cost`是最大可能成本 (100,000)。 各指标`i`该数组中代表了多少条柱的确切成本`i`硬币。 
2. **通过迭代填充计数数组**`costs`。 对于每个成本，增加计数数组中相应的索引。 这可以有效地按成本对条进行分组，而无需排序。 
3. **初始化计数器**`bars_bought = 0`并开始从最小成本到最大成本迭代。 
4. **每项费用`i`**：

 - 计算剩余的成本可以购买多少根金条`coins`:`buy = min(count[i], coins // i)`。 
- 增量`bars_bought`经过`buy`。 
- 减法`buy * i`从`coins`。 
- 如果`coins`变为零，则尽早突破，因为无法购买更多金条。 
5. **返回`bars_bought`** 作为男孩可以购买的冰淇淋棒的最大数量。 

**为什么有效**：计数排序可确保我们按成本升序处理条形。 通过始终首先购买最便宜的金条，我们可以最大限度地增加购买的金条数量。 当我们用完硬币或我们考虑了所有金条价格时，算法终止。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxIceCream(self, costs: List[int], coins: int) -> int:
        max_cost = max(costs)
        count = [0] * (max_cost + 1)
        
        # Populate counting array
        for cost in costs:
            count[cost] += 1
        
        bars_bought = 0
        for price in range(1, max_cost + 1):
            if count[price] == 0:
                continue
            buy = min(count[price], coins // price)
            bars_bought += buy
            coins -= buy * price
            if coins == 0:
                break
                
        return bars_bought
```Python 实现首先找到有效分配计数数组的最大成本。 然后，它计算每个成本的出现次数并按升序迭代成本。 对于每项成本，它都会计算剩余硬币可以承受的金条数量，更新购买的金条总数，并减少硬币数量。 如果硬币用完，循环就会提前中断，从而提高效率。 

## 解决方案```go
func maxIceCream(costs []int, coins int) int {
    maxCost := 0
    for _, c := range costs {
        if c > maxCost {
            maxCost = c
        }
    }

    count := make([]int, maxCost+1)
    for _, c := range costs {
        count[c]++
    }

    barsBought := 0
    for price := 1; price <= maxCost; price++ {
        if count[price] == 0 {
            continue
        }
        buy := count[price]
        if coins/price < buy {
            buy = coins / price
        }
        barsBought += buy
        coins -= buy * price
        if coins == 0 {
            break
        }
    }

    return barsBought
}
```在 Go 中，我们显式计算计数数组大小的最大成本。 其余逻辑反映了 Python。 整数除法自动处理我们可以购买的金条数量。 Go 的切片处理内存分配，并且在给定约束下整数操作是安全的。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 计算数组构造是 O(n)，迭代成本是 O(m)，其中`m`是最大成本|
