[LeetCode 问题 1839](https://leetcode.com/problems/longest-substring-of-all-vowels-in-order/)

 **难度：** 🟡 中等
 **主题：** 字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们根据两个严格条件找到被认为“美丽”的最长子串的长度。 

首先，子串必须包含所有五个元音，`'a'`,`'e'`,`'i'`,`'o'`， 和`'u'`，至少一次。 

其次，子串内的元音必须按非降序字母顺序出现。 这意味着每一个`'a'`必须出现在每个之前`'e'`， 每一个`'e'`在每个之前`'i'`， 等等。 允许重复元音，但顺序不能倒退。 

例如：

-`"aeiou"`有效，因为所有元音都出现一次并且顺序正确。 
-`"aaaaeiiiouuu"`也是有效的，因为元音是按排序顺序分组的。 
-`"aeioeu"`无效，因为之后`'o'`，子串返回到`'e'`。 
-`"aaaeeeooo"`无效，因为它从不包含`'i'`或者`'u'`。 

输入是一个字符串`word`仅包含元音。 字符串的长度可以大到`5 * 10^5`，它立即告诉我们低效的二次解可能会超时。 我们需要一种能够在线性时间内或非常接近线性时间处理字符串的算法。 

预期输出是一个整数，表示所有漂亮子字符串中的最大长度。 如果不存在美丽的子串，我们返回`0`。 

一些边缘情况很重要：

 - 少于 5 个字符的字符串永远不可能包含所有五个元音。 
- 只有一个重复元音的字符串，例如`"aaaaa"`，并不美丽。 
- 重复破坏字母顺序的字符串必须重新开始搜索。 
- 允许连续的重复元音，并且应该扩展当前的子串。 
- 有效的子字符串可能出现在字符串的中间而不是从索引处开始`0`。 

## 方法

 ### 蛮力方法

 一种简单的方法是检查每个可能的子串并检查它是否漂亮。 

对于每个起始索引，我们可以一次将结束索引扩展一个字符。 对于每个子字符串，我们验证两个属性：

 1. 字符按非降序排列。 
2. 所有五个元音都至少出现一次。 

这是有效的，因为每个可能的子字符串都会被显式检查，因此不会错过正确的答案。 

然而，对于限制而言，性能太慢了。 一个长度的字符串`n`有`O(n^2)`子串。 验证每个子字符串可能需要另一个`O(n)`最坏情况下的时间，导致`O(n^3)`复杂。 即使进行了优化，解决方案仍然太慢`n = 500000`。 

### 最佳滑动窗口/单通道方法

 关键的观察是，一个漂亮的子串必须由按排序顺序出现的元音组成。 当我们从左到右扫描字符串时，我们只需要跟踪：

 - 订单是否仍然有效。 
- 有多少个不同的元音按顺序出现。 
- 当前有效段的起始位置。 

每当当前字符比字母顺序上的前一个字符小时，排序规则就会被打破。 此时，当前子字符串无法再扩展，因此我们必须从当前字符重新开始。 

如果当前字符大于前一个字符，则我们已转换到新的元音组，因此我们增加不同的元音计数。 

每当不同元音计数达到`5`，我们知道当前子串按顺序包含所有元音，因此我们更新答案。 

这使我们能够一次性处理字符串。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n2) 到 O(n3) | O(1) | O(1) | 显式检查每个子字符串 |
 | 最佳| O(n) | O(1) | O(1) | 跟踪元音转换时单次通过 |

 ## 算法演练

 1.初始化三个变量：

 -`start`，当前有效段的开始索引。 
-`distinct_vowels`，到目前为止看到的元音组的数量。 
-`max_length`，找到的最佳答案。 
2. 从索引处开始从左到右扫描字符串`1`因为我们将每个字符与前一个字符进行比较。 
3. 如果当前字符按字母顺序小于前一个字符，则违反了元音排序规则。 

例如：

-`"aeiou"`是有效的。 
-`"aeioa"`失效于`'a'`因为`'a' < 'o'`。 

当这种情况发生时：

 - 重置`start`到当前索引。 
- 重置`distinct_vowels`到`1`因为当前角色开始一个新序列。 
4. 如果当前字符比前一个字符大，我们就移动到下一个元音组。 

例如：

-`'a' -> 'e'`-`'e' -> 'i'`增加`distinct_vowels`经过`1`。 
5. 如果当前字符与前一个字符相同，则我们仍处于同一元音组中，因此不会发生任何变化。 
6. 每当`distinct_vowels == 5`，当前子字符串包含按有效顺序排列的所有五个元音。 

计算它的长度：$$\text{length} = i - start + 1$$更新`max_length`如果这个子串更长。 
7. 继续直到字符串末尾。 
8. 返回`max_length`。 

### 为什么它有效

 该算法保持了子字符串的不变性`start`到当前索引始终按字母顺序排列。 每当顺序中断时，子字符串就会变得不可用并且必须重新启动。 

这`distinct_vowels`计数器跟踪按顺序发生了多少元音转换。 由于唯一可能的元音是`'a'`,`'e'`,`'i'`,`'o'`， 和`'u'`，达到`5`保证所有元音都以正确的顺序出现。 

因为每个字符都被处理一次，并且考虑在每个位置结束的每个有效子串，所以该算法总是找到最长的漂亮子串。 

## Python 解决方案```python
class Solution:
    def longestBeautifulSubstring(self, word: str) -> int:
        if len(word) < 5:
            return 0

        max_length = 0
        start = 0
        distinct_vowels = 1

        for i in range(1, len(word)):
            if word[i] < word[i - 1]:
                start = i
                distinct_vowels = 1
            elif word[i] > word[i - 1]:
                distinct_vowels += 1

            if distinct_vowels == 5:
                max_length = max(max_length, i - start + 1)

        return max_length
```实施从快速优化开始。 如果字符串长度小于`5`，不可能包含所有五个元音，所以我们立即返回`0`。 

变量`start`存储当前有序子字符串的开始索引。 变量`distinct_vowels`跟踪到目前为止出现了多少不同的元音组。 

在循环内，我们将当前字符与前一个字符进行比较。 

如果当前字符较小，则排序规则已被破坏。 我们重置当前段并从当前位置开始新的段。 

如果当前字符较大，则我们遇到了一个新的元音组，因此我们递增`distinct_vowels`。 

如果当前字符等于前一个字符，我们将留在同一元音组内并继续扩展子字符串。 

每当`distinct_vowels`变成`5`，我们知道子字符串按顺序包含所有元音，因此我们使用当前窗口长度更新答案。 

该解决方案使用恒定的额外内存并以线性时间处理字符串。 

## 解决方案```go
func longestBeautifulSubstring(word string) int {
    if len(word) < 5 {
        return 0
    }

    maxLength := 0
    start := 0
    distinctVowels := 1

    for i := 1; i < len(word); i++ {
        if word[i] < word[i-1] {
            start = i
            distinctVowels = 1
        } else if word[i] > word[i-1] {
            distinctVowels++
        }

        if distinctVowels == 5 {
            currentLength := i - start + 1
            if currentLength > maxLength {
                maxLength = currentLength
            }
        }
    }

    return maxLength
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 中的字符串是字节索引的，并且输入仅包含小写英文元音，因此直接索引`word[i]`是完全安全的。 

不需要对整数溢出进行特殊处理，因为最大字符串长度仅为`500000`，完全在 Go 的范围内`int`范围。

 ## 边缘情况

 当输入字符串短于五个字符时，会出现一种重要的边缘情况。 由于一个漂亮的子串必须至少包含一次所有五个元音，因此任何短于五个的字符串永远无法满足要求。 该实现立即处理这个问题并提前返回`0`。 

当字母顺序在候选子字符串中间中断时，会发生另一个棘手的情况。 例如，在`"aeioa"`，最后的`'a'`违反了排序规则，因为它出现在`'o'`。 幼稚的实现可能会意外地继续从旧的子字符串开始计数。 当算法检测到递减的转变时，它会正确地重置起始索引和不同的元音计数。 

第三个重要的边缘情况涉及重复的元音。 连续的重复元音是完全有效的，应该扩展子串而不是重新启动它。 例如，`"aaaaeeeeiiiioooouuuu"`完全是美丽的。 该实现通过在相邻字符相等时不执行任何操作来处理此问题，从而允许当前子字符串继续自然增长。 

当字符串以元音以外的元音开头时，会出现最后一个微妙的情况`'a'`。 例如，`"eiiiouu"`包含有序元音，但仍然无效，因为漂亮的子字符串必须包含以开头的所有五个元音`'a'`。 该算法自然会处理这个问题，因为不同的元音计数永远不会达到`5`，所以答案仍然是`0`。
