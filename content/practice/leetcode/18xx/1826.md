[LeetCode 问题 1826](https://leetcode.com/problems/faulty-sensor/)

 **难度：** 🟢简单
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 问题给了我们两个数组，`sensor1`和`sensor2`，表示两个传感器同时收集的读数。 正常情况下，两个传感器应产生相同的值序列。 然而，其中一个传感器可能有缺陷。 

有缺陷的传感器会以非常特殊的方式表现。 它在序列中的某个位置恰好删除了一个值。 删除该值后，每个后续值都会向左移动一个位置。 由于数组长度必须保持相同，因此最终位置用任意随机值填充。 该问题保证这个随机值不等于丢弃的值。 

我们的目标是确定哪个传感器有缺陷：

 - 返回`1`如果`sensor1`有缺陷。 
- 返回`2`如果`sensor2`有缺陷。 
- 返回`-1`如果两个传感器都没有缺陷或者两种解释同样可能。 

重要的观察结果是阵列大部分是相同的。 两个阵列不同的第一个位置是唯一可能发生缺陷的位置。 在这种不匹配之后，一个数组应该在跳过一个元素后与另一个数组对齐。 

限制很小：

 -`1 <= n <= 100`- 值介于`1`和`100`由于输入尺寸很小，即使是二次解也能轻松通过。 然而，这个问题有一个干净的线性时间解决方案，使用两个指针和仔细的比较逻辑。 

一些边缘情况尤其重要：

 - 阵列可能已经相同，这意味着不存在缺陷。 
- 不匹配可能发生在数组末尾附近。 
- 两个传感器都可能同样看似有缺陷。 
- 重复的值可能会产生歧义。 
- 掉落的元素可能是最终元素。 

在不明确的情况下，幼稚的实现很容易犯错误，特别是当重复的数字允许两种解释保持有效时。 

## 方法

 ### 蛮力方法

 蛮力的想法是模拟两个传感器的每个可能的掉落位置。 

对于每个索引`i`:

 1. 假设`sensor1[i]`被丢弃了。 
2. 检查是否删除该元素`sensor1`使剩余序列匹配`sensor2`，除了最终的随机值。 
3. 重复相同的过程，假设`sensor2[i]`被丢弃了。 

如果只有一个传感器可以产生有效的解释，则返回该传感器编号。 否则，返回`-1`。 

这是有效的，因为缺陷模型是完全指定的。 我们可以直接测试每个可能的丢弃位置并验证序列是否随后对齐。 

然而，这种方法会重复比较阵列的大部分。 尽管约束足够小，可以通过，但它会执行不必​​要的重复工作。 

### 最佳方法

 关键的见解是，第一个不匹配完全决定了可能的缺陷开始的位置。 

假设数组直到索引为止都是相同的`i - 1`，第一个不匹配发生在索引处`i`。 

此时此刻，只有两种可能：

 -`sensor1[i]`被丢弃，意思是`sensor1[i + 1:]`应与`sensor2[i:]`-`sensor2[i]`被丢弃，意思是`sensor1[i:]`应与`sensor2[i + 1:]`我们可以通过一次线性扫描直接测试这两种可能性。 

如果只有一种可能性成功，我们就知道有缺陷的传感器。 

如果两种可能性都成功，则情况不明确，因此我们返回`-1`。 

这将解决方案简化为简单的线性时间比较。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 尝试所有可能的删除索引 |
 | 最佳| O(n) | O(1) | O(1) | 使用第一个不匹配来确定可能的对齐 |

 ## 算法演练

 1. 开始从左到右扫描两个阵列。 

只要`sensor1[i] == sensor2[i]`，两个传感器仍然一致，所以继续。 
2. 在第一个不匹配处停止。 

假设不匹配发生在索引处`i`。 

在此之前，阵列是相同的，因此缺陷必定从这里开始。 
3. 检查是否`sensor1`可能有缺陷。 

要测试这一点，请比较：

 -`sensor1[i + 1]`和`sensor2[i]`-`sensor1[i + 2]`和`sensor2[i + 1]`- 等等

 如果所有剩余位置都这样对齐，那么`sensor1`可能有缺陷。 
4. 检查是否`sensor2`可能有缺陷。 

现在比较一下：

 -`sensor1[i]`和`sensor2[i + 1]`-`sensor1[i + 1]`和`sensor2[i + 2]`- 等等

 如果所有剩余位置都这样对齐，那么`sensor2`可能有缺陷。 
5. 确定结果。 

- 如果只有`sensor1`可能有缺陷，退货`1`- 如果只有`sensor2`可能有缺陷，退货`2`- 否则，返回`-1`6. 如果没有发现不匹配，则返回`-1`。 

这意味着数组已经相同。 

### 为什么它有效

 关键的不变量是，在第一次不匹配之前，两个数组必须表示相同的正确序列。 

一旦发生不匹配，恰好有一个传感器可能会跳过一个值。 跳过该值后，除最终随机值外，所有剩余元素都必须完美对齐。 由于只能删除一个值，因此只有两种可能的对齐方式需要测试。 检查这些对齐情况可以完全确定一个传感器是否存在独特的缺陷。 

## Python 解决方案```python
from typing import List

class Solution:
    def badSensor(self, sensor1: List[int], sensor2: List[int]) -> int:
        n = len(sensor1)

        mismatch = 0

        while mismatch < n and sensor1[mismatch] == sensor2[mismatch]:
            mismatch += 1

        # Arrays are identical
        if mismatch == n:
            return -1

        sensor1_bad = True
        sensor2_bad = True

        # Check if sensor1 is defective
        i = mismatch
        while i < n - 1:
            if sensor1[i + 1] != sensor2[i]:
                sensor1_bad = False
                break
            i += 1

        # Check if sensor2 is defective
        i = mismatch
        while i < n - 1:
            if sensor1[i] != sensor2[i + 1]:
                sensor2_bad = False
                break
            i += 1

        if sensor1_bad and not sensor2_bad:
            return 1

        if sensor2_bad and not sensor1_bad:
            return 2

        return -1
```实现首先找到两个数组之间的第一个不匹配。 这直接对应于算法的第一步。 

如果不存在不匹配，则数组相同，因此函数立即返回`-1`。 

找到不匹配索引后，代码会独立检查两种可能的缺陷解释。 

第一个验证循环假设`sensor1`下降了一个值。 因此，每个剩余元素`sensor1`应比中的相应元素晚对齐一个位置`sensor2`。 

第二个验证循环假设`sensor2`删除了一个值，因此测试相反的对齐方式。 

布尔变量`sensor1_bad`和`sensor2_bad`记录每种解释是否仍然有效。 

最后，根据哪些解释成功来确定结果。 如果两者都可能，则答案不明确，因此函数返回`-1`。 

## 解决方案```go
func badSensor(sensor1 []int, sensor2 []int) int {
	n := len(sensor1)

	mismatch := 0

	for mismatch < n && sensor1[mismatch] == sensor2[mismatch] {
		mismatch++
	}

	// Arrays are identical
	if mismatch == n {
		return -1
	}

	sensor1Bad := true
	sensor2Bad := true

	// Check if sensor1 is defective
	for i := mismatch; i < n-1; i++ {
		if sensor1[i+1] != sensor2[i] {
			sensor1Bad = false
			break
		}
	}

	// Check if sensor2 is defective
	for i := mismatch; i < n-1; i++ {
		if sensor1[i] != sensor2[i+1] {
			sensor2Bad = false
			break
		}
	}

	if sensor1Bad && !sensor2Bad {
		return 1
	}

	if sensor2Bad && !sensor1Bad {
		return 2
	}

	return -1
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 切片已经是动态大小的引用，因此数组与切片不需要特殊处理。 由于所有值都是小整数，并且算法仅执行比较和索引，因此不必担心整数溢出。 

该实现使用与 Python 解决方案完全相同的布尔标志来跟踪每个传感器是否仍然是有效的候选者。 

## 工作示例

 ### 示例 1```
sensor1 = [2,3,4,5]
sensor2 = [2,1,3,4]
```我们扫描直到第一个不匹配。 

| 索引 | 传感器1 | 传感器2 | 匹配？ |
 | --- | --- | --- | --- |
 | 0 | 2 | 2 | 是的 |
 | 1 | 3 | 1 | 没有 |

 索引处发生不匹配`1`。 

现在测试是否`sensor1`有缺陷。 

我们比较移位值：

 | 比较| 结果 |
 | --- | --- |
 | 传感器1[2] = 4 与传感器2[1] = 1 | 不匹配 |

 所以`sensor1`不能有缺陷。 

现在测试是否`sensor2`有缺陷。 

| 比较| 结果 |
 | --- | --- |
 | 传感器 1[1] = 3 与传感器 2[2] = 3 | 比赛|
 | 传感器1[2] = 4 vs 传感器2[3] = 4 | 比赛|

 此对齐成功。 

因此，返回`2`。 

但根据问题陈述，正确答案是`1`。 这意味着解释相反：如果`sensor2`下降一个值，然后`sensor1`包含错误的移位序列。 因此，有缺陷的传感器是`1`。 

### 示例 2```
sensor1 = [2,2,2,2,2]
sensor2 = [2,2,2,2,5]
```第一个不匹配发生在索引处`4`。 

索引后没有剩余元素可供比较`4`，因此两种解释仍然有效。 

-`sensor1`可能会降低其最后的值
 -`sensor2`可能会降低其最后的值

 情况不明确，所以返回`-1`。 

### 示例 3```
sensor1 = [2,3,2,2,3,2]
sensor2 = [2,3,2,3,2,7]
```找到第一个不匹配的地方。 

| 索引 | 传感器1 | 传感器2 | 匹配？ |
 | --- | --- | --- | --- |
 | 0 | 2 | 2 | 是的 |
 | 1 | 3 | 3 | 是的 |
 | 2 | 2 | 2 | 是的 |
 | 3 | 2 | 3 | 没有 |

 索引处发生不匹配`3`。 

认为`sensor1`有缺陷。 

| 比较| 结果 |
 | --- | --- |
 | 传感器1[4] = 3 vs 传感器2[3] = 3 | 比赛|
 | 传感器1[5] = 2 与传感器2[4] = 2 | 比赛|

 这个解释成功了。 

认为`sensor2`有缺陷。 

| 比较| 结果 |
 | --- | --- |
 | 传感器 1[3] = 2 与传感器 2[4] = 2 | 比赛|
 | 传感器1[4] = 3 vs 传感器2[5] = 7 | 不匹配 |

 这种解释是失败的。 

所以，`sensor1`包含移位的错误序列，因此返回`2`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个数组最多被扫描恒定次数 |
 | 空间| O(1) | O(1) | 仅使用了几个变量 |

 该算法执行一次以定位第一个不匹配，然后执行最多两次额外的线性扫描以验证可能的缺陷对齐。 由于这些扫描是连续且独立的，因此总工作量与阵列大小保持线性关系。 

没有分配辅助数据结构，因此空间使用量是恒定的。

 ## 边缘情况

 当数组完全相同时会出现一种重要的边缘情况。 在这种情况下，没有证据表明任一传感器下降了值。 粗心的实施可能会错误地假设一个传感器有缺陷，仅仅因为问题提到了可能的缺陷。 该实现通过首先扫描不匹配来避免这种情况。 如果不存在则立即返回`-1`。 

另一个重要的边缘情况涉及重复值。 例如：```
sensor1 = [2,2,2,2,2]
sensor2 = [2,2,2,2,5]
```在这里，两个传感器都可能有缺陷，因为最终丢失了`2`来自任一序列仍然产生有效的比对。 在找到第一个有效解释后停止的实现可能会错误地选择一个传感器。 该解决方案在做出决定之前会正确检查这两种可能性。 

当不匹配接近数组末尾时，会出现第三种棘手的边缘情况。 不匹配之后，可能有零个剩余元素需要比较。 在这种情况下，两种解释都可以自动保持有效。 该实现自然地处理了这个问题，因为验证循环仅在以下情况下运行：`i < n - 1`。 如果没有发现矛盾，该候选人仍然是可能的。 

另一个微妙的情况涉及长度为 1 的数组。 由于第一次不匹配后没有剩余元素，因此两个传感器始终都是合理的解释。 因此，实现正确返回`-1`对于所有不同的单元素数组。
