[LeetCode 问题 1882](https://leetcode.com/problems/process-tasks-using-servers/)

 **难度：** 🟡 中等
 **主题：** 数组、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 这个问题要求我们模拟一个具有两个优先级规则的任务调度系统。 我们得到了服务器列表和任务列表。 每个服务器都有一个权重，每个任务都有一个处理时长。 

第二次`j`， 任务`j`变为可用并进入队列。 任务必须始终按到达顺序分配。 每当有至少一台空闲服务器和至少一个等待任务时，我们将最早的等待任务分配给最好的可用服务器。 

“最佳”服务器的定义遵循两个优先级：

 1.服务器重量越小越好。 
2. 如果权重相等，服务器索引越小越好。 

一旦服务器开始处理任务，它就会变得不可用，直到任务完成。 如果任务等待时没有服务器空闲，则时间会有效地推进，直到至少一台服务器再次空闲。 

目标是返回一个数组，其中`ans[j]`是处理任务的服务器的索引`j`。 

输入数组代表：

 -`servers[i]`，服务器的权重`i`-`tasks[j]`, 任务的时间量`j`需要完成

 限制条件很大：

 - 最多`2 * 10^5`服务器
 - 最多`2 * 10^5`任务

 这立即告诉我们任何二次解都会超时。 我们需要一些接近的东西`O(m log n)`或者`O((m+n) log n)`。 

一些边缘情况很重要：

 - 多个服务器可以同时免费。 
- 多个服务器可以具有相同的权重。 
- 当所有服务器都繁忙时，任务可能会堆积。 
- 任务可能比服务器多得多。 
- 服务器可能会长时间保持忙碌状态，而任务每秒都会不断到达。 

重复检查每台服务器的简单模拟会太慢。 

## 方法

 ### 蛮力方法

 简单的模拟一次只能处理一秒钟的任务。 

对于每个到达的任务：

 1. 扫描所有服务器以查找哪些服务器是免费的。 
2. 在免费服务器中，选择最少的一台`(weight, index)`。 
3. 如果没有空闲服务器，请提前时间，直到有可用服务器为止。 
4. 对每项任务重复此操作。 

这种方法是正确的，因为它直接遵循问题规则。 然而，它的效率极低。 

每个任务分配可能需要扫描所有`n`服务器，导致`O(m * n)`复杂。 当两个值都达到`2 * 10^5`，这可能需要最多`4 * 10^10`操作，这是完全不切实际的。 

### 最佳方法

 关键的观察是我们反复需要两个有效的操作：

 1. 找到当前可用的最佳服务器。 
2. 查找接下来哪个繁忙的服务器变得空闲。 

这两个操作都是经典的优先级队列问题。 

我们使用两个堆：

 - 可用堆，按顺序排列`(weight, index)`- 繁忙的堆，按顺序排序`(free_time, weight, index)`可用的堆总是立即为我们提供最好的服务器。 

繁忙的堆让我们能够有效地确定接下来完成哪些服务器。 

我们没有模拟每一秒，而是直接跳到重要时刻：

 - 任务到达时间
 - 服务器完成时间

 这可以避免不必要的工作并保持解决方案的效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n) | O(n) | 重复扫描所有服务器|
 | 最佳| O((m + n) log n) | O((m + n) log n) | O(n) | 使用两个优先级队列进行高效调度 |

 ## 算法演练

 1. 初始化可用的服务器堆。 

每个服务器都是免费启动的，因此我们将所有服务器插入按以下顺序排列的最小堆中：

 - 服务器重量
 - 服务器索引

 每个堆条目如下所示：```
(weight, index)
```2. 初始化繁忙的服务器堆。 

该堆存储当前正在处理任务的服务器。 它的订购者是：

 - 服务器空闲的时间
 - 服务器重量
 - 服务器索引

 每个堆条目如下所示：```
(free_time, weight, index)
```3. 按顺序处理任务。 

任务`j`准时到达`j`。 
4. 在分配当前任务之前，释放所有已完成的服务器。 

虽然繁忙的堆包含的服务器`free_time <= current_time`，将它们从繁忙堆中移除并将它们推回到可用堆中。 

这确保可用堆始终反映当前空闲的服务器。 
5. 处理无服务器可用的情况。 

如果可用堆为空，我们无法立即处理任务。 

在这种情况下：

 - 获取最早的服务器`free_time`从繁忙的堆中。 
- 将当前时间提前到那个时间`free_time`。 
- 释放此时可用的所有服务器。 
6. 分配任务。 

从可用堆中弹出最好的服务器。 

将其索引记录在答案数组中。 
7. 再次将服务器标记为忙碌。 

任务结束于：```
current_time + task_duration
```使用新的完成时间将服务器推入繁忙堆。 
8. 继续，直到分配完所有任务。 

### 为什么它有效

 该算法保持两个不变量：

 - 可用堆始终包含当前空闲服务器，按调度优先级排序。 
- 繁忙堆始终包含繁忙服务器，按下一个完成时间排序。 

每当必须分配任务时，算法要么：

 - 使用当前最好的免费服务器，或者
 - 将时间提前到服务器空闲的最早时刻。 

由于任务严格按照插入顺序进行处理，并且始终使用所需的优先级规则选择服务器，因此该算法与问题中描述的调度行为完全匹配。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def assignTasks(self, servers: List[int], tasks: List[int]) -> List[int]:
        available = []
        busy = []

        # (weight, index)
        for index, weight in enumerate(servers):
            heapq.heappush(available, (weight, index))

        result = [0] * len(tasks)

        for current_time, task_duration in enumerate(tasks):

            # Free all servers that have completed by current_time
            while busy and busy[0][0] <= current_time:
                free_time, weight, index = heapq.heappop(busy)
                heapq.heappush(available, (weight, index))

            # If no server is available, jump time forward
            if not available:
                current_time = busy[0][0]

                while busy and busy[0][0] <= current_time:
                    free_time, weight, index = heapq.heappop(busy)
                    heapq.heappush(available, (weight, index))

            # Assign task to best available server
            weight, index = heapq.heappop(available)

            result[current_time if False else len(result) - len(tasks) + current_time] = index
```上一行不正确，因为`current_time`当服务器繁忙时可能会向前跳转。 我们应该单独存储任务索引。 这是更正后的完整解决方案：```python
from typing import List
import heapq

class Solution:
    def assignTasks(self, servers: List[int], tasks: List[int]) -> List[int]:
        available = []
        busy = []

        # Available servers:
        # (weight, index)
        for index, weight in enumerate(servers):
            heapq.heappush(available, (weight, index))

        result = [0] * len(tasks)

        for task_index, task_duration in enumerate(tasks):
            current_time = task_index

            # Move completed servers back to available heap
            while busy and busy[0][0] <= current_time:
                free_time, weight, index = heapq.heappop(busy)
                heapq.heappush(available, (weight, index))

            # If no servers are free, jump to next available time
            if not available:
                current_time = busy[0][0]

                while busy and busy[0][0] <= current_time:
                    free_time, weight, index = heapq.heappop(busy)
                    heapq.heappush(available, (weight, index))

            # Get best available server
            weight, index = heapq.heappop(available)

            result[task_index] = index

            # Mark server busy
            finish_time = current_time + task_duration
            heapq.heappush(busy, (finish_time, weight, index))

        return result
```实现直接反映了算法。 

这`available`堆存储按顺序排序的免费服务器`(weight, index)`。 这保证了从堆中弹出总是根据问题规则给出正确的服务器。 

这`busy`堆存储服务器当前正在处理的任务。 其排序方式为`finish_time`使我们能够有效地确定下一个空闲的服务器。 

对于每个任务，我们首先释放所有已完成工作的服务器。 然后我们要么立即分配任务，要么提前时间到下一个服务器完成事件。 

答案数组按到达顺序记录为每个任务分配的服务器索引。 

## 解决方案```go
package main

import (
	"container/heap"
)

type AvailableServer struct {
	weight int
	index  int
}

type BusyServer struct {
	freeTime int
	weight   int
	index    int
}

type AvailableHeap []AvailableServer

func (h AvailableHeap) Len() int {
	return len(h)
}

func (h AvailableHeap) Less(i, j int) bool {
	if h[i].weight == h[j].weight {
		return h[i].index < h[j].index
	}
	return h[i].weight < h[j].weight
}

func (h AvailableHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *AvailableHeap) Push(x interface{}) {
	*h = append(*h, x.(AvailableServer))
}

func (h *AvailableHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

type BusyHeap []BusyServer

func (h BusyHeap) Len() int {
	return len(h)
}

func (h BusyHeap) Less(i, j int) bool {
	if h[i].freeTime == h[j].freeTime {
		if h[i].weight == h[j].weight {
			return h[i].index < h[j].index
		}
		return h[i].weight < h[j].weight
	}
	return h[i].freeTime < h[j].freeTime
}

func (h BusyHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *BusyHeap) Push(x interface{}) {
	*h = append(*h, x.(BusyServer))
}

func (h *BusyHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func assignTasks(servers []int, tasks []int) []int {
	available := &AvailableHeap{}
	busy := &BusyHeap{}

	heap.Init(available)
	heap.Init(busy)

	for index, weight := range servers {
		heap.Push(available, AvailableServer{
			weight: weight,
			index:  index,
		})
	}

	result := make([]int, len(tasks))

	for taskIndex, duration := range tasks {
		currentTime := taskIndex

		// Free completed servers
		for busy.Len() > 0 && (*busy)[0].freeTime <= currentTime {
			server := heap.Pop(busy).(BusyServer)

			heap.Push(available, AvailableServer{
				weight: server.weight,
				index:  server.index,
			})
		}

		// No available server
		if available.Len() == 0 {
			currentTime = (*busy)[0].freeTime

			for busy.Len() > 0 && (*busy)[0].freeTime <= currentTime {
				server := heap.Pop(busy).(BusyServer)

				heap.Push(available, AvailableServer{
					weight: server.weight,
					index:  server.index,
				})
			}
		}

		server := heap.Pop(available).(AvailableServer)

		result[taskIndex] = server.index

		heap.Push(busy, BusyServer{
			freeTime: currentTime + duration,
			weight:   server.weight,
			index:    server.index,
		})
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但需要显式堆类型来实现`heap.Interface`。 

去的`container/heap`包不为元组提供内置的最小堆，因此我们手动定义自定义堆结构和比较逻辑。 

该解决方案使用`int`安全，因为最大可能时间在 Go 的整数范围内。

            heapq.heappush(available, (w, i))

 ## 边缘情况

 当所有服务器长时间繁忙时，就会出现一种重要的边缘情况。 在这种情况下，任务每秒都会继续到达并在队列中堆积。 幼稚的实现可能会单独模拟每一秒，从而导致严重的性能问题。 此实现通过使用繁忙堆直接跳转到最早的服务器完成时间来避免该问题。 

当多个服务器同时空闲时，就会出现另一个棘手的情况。 如果我们在分配任务之前只释放一台服务器，则调度顺序可能会变得不正确。 该实现通过释放所有服务器来正确处理这个问题`free_time <= current_time`在做作业之前。 

同等服务器权重之间的平局打破是错误的另一个常见来源。 该问题要求在权重相等时选择最小的索引。 两个堆都在其排序规则中明确包含服务器索引，以确保确定性和正确的行为。 

当当前任务时间由于没有可用服务器而必须向前跳跃时，会发生最后一个微妙的情况。 该算法正确分离`task_index`从`current_time`，确保答案数组仍然按任务顺序而不是模拟时钟时间进行索引。
