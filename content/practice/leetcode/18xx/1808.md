 ## 解决方案

 ## 问题理解

 问题给了我们一个整数`primeFactors`，表示构造某个正整数时允许使用的质因数的最大总数`n`。 

目标不是最大化`n`本身。 相反，我们想要最大化“好除数”的数量`n`。 

除数为`n`如果它可以被每个不同的质因数整除，则被认为是好的`n`。 

认为：

-`n = 2^a * 3^b * 5^c`那么任何好的除数都必须至少包含每个不同质因数的一个副本：

 - 至少一个`2`- 至少一个`3`- 至少一个`5`这样的除数的数量变为：$$a \times b \times c$$因为：

 - 除数可以选择指数`1..a`对于总理`2`- 指数`1..b`对于总理`3`- 指数`1..c`对于总理`5`那么整个问题就转化为：

 > 拆分`primeFactors`转化为乘积最大化的正整数。 

这是与经典的“整数中断”问题相同的数学优化问题。 

限制条件非常大：

 -`1 <= primeFactors <= 10^9`这立即告诉我们：

 - 暴力枚举是不可能的
 - 对所有值进行动态规划也是不可能的
 - 我们需要一个具有对数复杂度的数学解决方案

 一些边缘情况很重要：

 -`primeFactors = 1`-`primeFactors = 2`-`primeFactors = 3`这些小值不遵循正常的“分成 3 部分”规则，必须小心处理。 

另一个重要问题是溢出。 答案可能会变得非常大，因此所有计算都必须进行模运算：$$10^9 + 7$$因此，有效的模幂运算是必要的。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试枚举所有可能的方法，以在不同的素数幂之间分配可用的素数因子。 

例如，如果`primeFactors = 8`，我们可以尝试这样的分区：

 -`8`-`7 + 1`-`6 + 2`-`5 + 3`-`4 + 4`-`3 + 3 + 2`- 等

 对于每个分区：

 - 将每个部分解释为不同质数的指数
 - 计算零件的乘积
 - 保持最大值

 这是可行的，因为好除数的数量等于指数的乘积。 

然而，整数分区的数量呈指数增长。 和`primeFactors`最多`10^9`，暴力破解是完全行不通的。 

### 关键见解

 重要的数学观察是：

 > 为了最大化总和固定的整数的乘积，我们应该使用尽可能多的`3`尽可能。 

这是众所周知的优化结果。 

为什么`3`？ 

- 将数字分割成更大的块会减少乘积。 
- 分裂成太多`2`s 的效率低于`3`s。 
- 任意号码`>= 5`可以通过提取改进`3`。 

例如：$$5 = 2 + 3,\quad 2 \times 3 = 6 > 5$$

$$6 = 3 + 3,\quad 3 \times 3 = 9 > 6$$唯一的特殊情况是当余数变为`1`。 

例如：$$10 = 3 + 3 + 3 + 1$$这很糟糕，因为：$$3 \times 3 \times 3 \times 1 = 27$$反而：$$10 = 3 + 3 + 4$$这给出：$$3 \times 3 \times 4 = 36$$所以最优策略变为：

 - 使用尽可能多的`3`尽可能。 
- 如果余数是`1`，换算一`3 + 1`进入`2 + 2`。 
- 如果余数是`2`，保留它。

 ## 算法演练

 ### 步骤 1：处理小值

 如果`primeFactors <= 3`， 返回`primeFactors`。 

为什么？ 

因为进一步拆分它们并不能改善产品。 

示例：

 -`2 -> 2`-`3 -> 3`### 第 2 步：除以 3

 计算：$$q = primeFactors // 3$$

$$r = primeFactors \% 3$$商告诉我们有多少`3`我们可以使用。 

余数决定调整策略。 

### 步骤3：处理余数0

 如果：$$r = 0$$那么最优分解完全是`3`s。 

结果：$$3^q$$### 步骤 4：处理余数 1

 如果：$$r = 1$$我们应该避免以`+1`。 

而不是：$$3^{q} \times 1$$我们改造：$$3 + 1 \rightarrow 2 + 2$$所以：$$3^{q-1} \times 4$$### 步骤 5：处理剩余部分 2

 如果：$$r = 2$$只需附加一个`2`。 

结果：$$3^q \times 2$$### 步骤 6：使用模幂

 由于幂变得非常大，因此对它们进行模计算：$$10^9 + 7$$Python 提供：```
pow(base, exponent, mod)
```它以对数时间执行快速求幂。 

在 Go 中，我们手动实现二进制求幂。 

### 为什么它有效

 正确性来自于将数字分解为大多数的数学属性`3`s 最大化固定总和的乘积。 

任意整数`>= 5`拆分的好处`3`：$$x < 3(x-3)$$为所有人`x >= 5`。 

如此反复提取`3`始终改进产品，直到`2`,`3`， 或者`4`保持。 

唯一有问题的余数是`1`，因为乘以`1`没有任何贡献。 更换`3 + 1`和`2 + 2`增加产品：$$3 \times 1 < 2 \times 2$$因此，该算法总是产生最优分解。 

## Python 解决方案```python
class Solution:
    def maxNiceDivisors(self, primeFactors: int) -> int:
        MOD = 10**9 + 7

        if primeFactors <= 3:
            return primeFactors

        quotient = primeFactors // 3
        remainder = primeFactors % 3

        if remainder == 0:
            return pow(3, quotient, MOD)

        if remainder == 1:
            return (pow(3, quotient - 1, MOD) * 4) % MOD

        return (pow(3, quotient, MOD) * 2) % MOD
```The implementation follows the mathematical derivation directly.

 The first section handles the small edge cases where splitting is not beneficial.

 接下来，我们将该值除以`3`来确定有多少组`3`应该出现在最佳分区中。 

余数决定使用哪个公式：

 - 余数`0`意味着全部`3`s
 - 余数`1`意思是替换一个`3 + 1`和`2 + 2`- 余数`2`意味着附加一个`2`内置的`pow(base, exponent, mod)`函数在对数时间内执行有效的模幂运算。 

## 解决方案```go
func maxNiceDivisors(primeFactors int) int {
	const MOD int64 = 1_000_000_007

	if primeFactors <= 3 {
		return primeFactors
	}

	quotient := primeFactors / 3
	remainder := primeFactors % 3

	if remainder == 0 {
		return int(modPow(3, int64(quotient), MOD))
	}

	if remainder == 1 {
		return int((modPow(3, int64(quotient-1), MOD) * 4) % MOD)
	}

	return int((modPow(3, int64(quotient), MOD) * 2) % MOD)
}

func modPow(base, exponent, mod int64) int64 {
	result := int64(1)

	base %= mod

	for exponent > 0 {
		if exponent&1 == 1 {
			result = (result * base) % mod
		}

		base = (base * base) % mod
		exponent >>= 1
	}

	return result
}
```Go 实现密切反映了 Python 逻辑。 

由于 Go 没有提供内置的整数模幂函数，因此我们手动实现二进制幂运算`modPow`。 

所有算术运算均使用`int64`以避免在取模之前的乘法过程中溢出。 

最终答案被转换回`int`因为 LeetCode 需要该返回类型。

 ## 边缘情况

 一个重要的边缘情况是当`primeFactors`小于或等于`3`。 一个常见的错误是总是将数字分成更小的部分。 然而，对于这些微小的值，分割会减少而不是增加乘积。 例如，分割`3`进入`1 + 2`给出一个乘积`2`，这比保留更糟糕`3`本身。 对于这些情况，实现显式返回原始值。 

当除以后的余数时，会出现另一个关键的边缘情况`3`等于`1`。 一个简单的实现可能会计算：$$3^q \times 1$$但乘以`1`浪费主要因素并产生次优产品。 正确的调整是更换一个`3 + 1`与`2 + 2`，产生更大的乘法结果。 该实现使用以下方法处理此问题：```
pow(3, quotient - 1, MOD) * 4
```第三个重要的边缘情况是极大的上限：$$primeFactors = 10^9$$直接求幂或递归乘法会溢出或超时。 该实现通过使用模幂来避免这种情况，模幂计算对数时间的幂，同时不断减少中间值模`10^9 + 7`。
