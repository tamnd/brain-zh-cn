 # LeetCode 1864 - 使二进制字符串交替的最小交换次数

 ## 问题理解

 该问题给了我们一个二进制字符串`s`只包含`'0'`和`'1'`。 我们可以交换字符串中的任意两个字符，不一定是相邻的字符。 我们的目标是使用最少的交换次数将字符串转换为交替的二进制字符串。 

交替二进制字符串是指没有两个相邻字符相同的字符串。 这意味着字符串必须遵循两种可能的模式之一：

 -`"010101..."`-`"101010..."`例如：

-`"010"`是交替的
 -`"1010"`是交替的
 -`"110"`不是交替的，因为前两个字符相等

 输出应该是使字符串交替所需的最小交换次数。 如果不可能，我们就必须返回`-1`。 

约束条件`1 <= s.length <= 1000`告诉我们输入大小相对较小，但我们仍然应该以高效的线性时间解决方案为目标。 由于字符串仅包含两个字符，因此有效交替字符串的结构受到极大限制，这表明我们可以推断计数和位置，而不是尝试每种可能的交换排列。 

一个非常重要的观察是，只有当计数为`'0'`和`'1'`最多相差`1`。 

例如：

-`"0101"`有两个`0`和两个`1`s，有效
 -`"101"`有一个`0`和两个`1`s，有效
 -`"1110"`有一个`0`和三个`1`s, 不可能的

 一些很容易导致错误的边缘情况包括：

 - 已经交替的字符串
 - 一个字符比另一个字符出现频率更高的字符串
 - 长度的字符串`1`- 具有相同计数的字符串，其中两种交替模式都是可能的
 - 计数不等的字符串，其中只有一个起始模式有效

 预先了解这些情况有助于避免在实施过程中出现错误的假设。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的交换并搜索生成交替字符串所需的最少操作数。 

思考这个问题的一种方法是将其视为图形问题。 每个字符串状态都是一个节点，每次交换都会创建另一个节点。 我们可以使用广度优先搜索来查找到交替字符串的最短路径。 

这种做法是正确的，因为 BFS 保证了最少的交换次数。 然而，这在计算上是不可行的，因为可能的字符串状态的数量随着字符串的长度而按阶乘增长。 即使对于中等大小的输入，搜索空间也会变得巨大。 

另一种暴力变体将生成两个目标交替模式并通过尝试不同的不匹配位置来直接模拟交换。 虽然比 BFS 更好，但与最优贪婪观察相比，它仍然做了不必要的工作。 

### 最优贪心法

 关键的见解是交替的二进制字符串具有完全固定的结构。 

对于一个长度的字符串`n`，最多有两个有效的目标模式：

 - 开始于`0`：`"010101..."`- 开始于`1`：`"101010..."`我们可以将当前字符串与这些目标模式进行比较，而不是通过交换进行搜索。 

每当某个位置的字符与预期字符不匹配时，该位置就是“错误的”。 每次交换都会同时修复两个错误的位置，因为交换一个错误的位置`0`与一个放错地方的`1`纠正两者。 

因此：

 - 计算有多少个位置与目标模式不匹配
 - 所需的最小交换量为`mismatches / 2`我们只需要根据字符数考虑有效的目标模式。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n!) | 探索巨大的交换状态空间 |
 | 最佳 | O(n) | O(1) | O(1) | 计算与有效交替模式的不匹配次数 |

 ## 算法演练

 1. 数一下数量`'0'`字符和`'1'`字符串中的字符。 

该步骤确定是否可以形成交替串。 在有效的交替字符串中，计数最多可以相差`1`。 
2. 检查可行性。 

如果`abs(count0 - count1) > 1`， 返回`-1`。 

当一个字符出现太多次时，任何排列都无法正确交替。 
3. 定义一个辅助函数，用于计算目标起始字符所需的交换。 

例如，如果目标以`'0'`，预期模式变为：

 - 索引`0`->`'0'`- 指数`1`->`'1'`- 指数`2`->`'0'`- 等等

 我们将每个位置与其预期值进行比较并计算不匹配的情况。 
4. 计算不匹配的位置。 

每次不匹配都意味着当前字符不在目标交替模式中所属的位置。 
5. 将不匹配除以`2`。 

一次交换同时修复两个不匹配的位置。 因此，所需的最小交换量等于`mismatches // 2`。 
6. 确定哪些目标模式有效。 

- 如果计数相等，则两种起始模式都是可能的。 返回较小的结果。 
- 如果零更频繁，则字符串必须以`'0'`。 
- 如果更频繁，则字符串必须以`'1'`。 

### 为什么它有效

 该算法之所以有效，是因为一旦选择了起始字符，每个交替的二进制字符串在每个索引处都有一个唯一确定的字符。 任何不匹配都代表属于其他地方的字符。 由于交换两个放错位置的字符同时修复了两个位置，因此最佳交换次数恰好是不匹配计数的一半。 计数可行性条件保证存在有效的交替排列。 

## Python 解决方案```python
class Solution:
    def minSwaps(self, s: str) -> int:
        zeros = s.count('0')
        ones = len(s) - zeros

        if abs(zeros - ones) > 1:
            return -1

        def count_swaps(start_char: str) -> int:
            mismatches = 0

            for i, ch in enumerate(s):
                expected = start_char if i % 2 == 0 else (
                    '1' if start_char == '0' else '0'
                )

                if ch != expected:
                    mismatches += 1

            return mismatches // 2

        if zeros > ones:
            return count_swaps('0')

        if ones > zeros:
            return count_swaps('1')

        return min(count_swaps('0'), count_swaps('1'))
```实现从计算零和一开始。 这立即告诉我们是否可以进行交替安排。 

辅助函数`count_swaps`计算如果交替字符串以特定字符开头则需要多少次交换。 它迭代每个索引并确定该位置的预期字符。 如果实际字符不同，则不匹配计数器会增加。 

在扫描结束时，不匹配被除以二，因为每次交换解决了两个不正确的位置。 

最后一部分根据字符频率确定哪种交替模式有效。 如果两种模式都有效，则返回最小结果。 

## 解决方案```go
func minSwaps(s string) int {
    zeros := 0

    for _, ch := range s {
        if ch == '0' {
            zeros++
        }
    }

    ones := len(s) - zeros

    if abs(zeros-ones) > 1 {
        return -1
    }

    countSwaps := func(start byte) int {
        mismatches := 0

        for i := 0; i < len(s); i++ {
            expected := start

            if i%2 == 1 {
                if start == '0' {
                    expected = '1'
                } else {
                    expected = '0'
                }
            }

            if s[i] != expected {
                mismatches++
            }
        }

        return mismatches / 2
    }

    if zeros > ones {
        return countSwaps('0')
    }

    if ones > zeros {
        return countSwaps('1')
    }

    swapsStartingWithZero := countSwaps('0')
    swapsStartingWithOne := countSwaps('1')

    if swapsStartingWithZero < swapsStartingWithOne {
        return swapsStartingWithZero
    }

    return swapsStartingWithOne
}

func abs(x int) int {
    if x < 0 {
        return -x
    }

    return x
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个显着的区别是 Go 使用`byte`字符比较的值。 辅助函数以闭包的形式实现，这样可以保持代码简洁并避免不必要的重复。 

Go 没有提供内置整数`abs`函数，所以我们手动定义一个小助手。

 ## 边缘情况

 一种重要的边缘情况是字符串长度为`1`。 单个字符始终是交替的，因为不存在违反条件的相邻字符。 幼稚的实现有时会错误地尝试交换或拒绝不相等的计数，而不考虑这种微不足道的情况。 当前的实现自然地处理了这个问题，因为不匹配计数变为零。 

当 0 和 1 的计数相差超过 1 时，就会出现另一种关键的边缘情况。 例如，`"1110"`包含三个一和一个零。 无论字符如何重新排列，至少有两个字符最终必须相邻。 该实现在尝试任何进一步处理之前显式检查此条件并立即返回`-1`。 

当计数相等时，会出现第三种微妙的边缘情况。 在这些情况下，两种交替模式在理论上都是可能的。 例如，`"111000"`可以瞄准其中之一`"101010"`或者`"010101"`。 有缺陷的实现可能只检查一种模式而错过最佳答案。 该解决方案评估两种可能性并返回最小交换计数。
