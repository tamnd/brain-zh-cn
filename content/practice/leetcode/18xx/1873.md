[LeetCode 问题 1873](https://leetcode.com/problems/calculate-special-bonus/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们编写一个 SQL 查询来计算公司中每个员工的特殊奖金`Employees`桌子。 

表中的每一行包含三条信息：

 | 专栏 | 意义|
 | --- | --- |
 |`employee_id`| 员工的唯一标识符 |
 |`name`| 员工姓名|
 |`salary`| 员工薪资|

 任务是计算一个名为的新列`bonus`根据两个条件：

 1. 员工的`employee_id`必须是奇数。 
2. 员工的`name`不得以字符开头`'M'`。 

如果这两个条件都成立，员工将获得相当于其全额工资的奖金，这意味着`100%`的工资。 

如果任一条件不满足，员工将获得奖金`0`。 

最终输出应包含：

 | 专栏 | 意义|
 | --- | --- |
 |`employee_id`| 员工身份 |
 |`bonus`| 计算奖金 |

 结果必须按以下顺序排序`employee_id`。 

这本质上是一个条件转换问题。 对于每一行，我们评估一个布尔条件并在两个值之间进行选择：

 -`salary`-`0`该问题被归类为简单数据库问题，因为它主要测试对以下内容的熟悉程度：

 -`CASE WHEN`- 用于检查奇数/偶数的模运算
 - 字符串模式匹配
 - 排序结果

 一个重要的细节是涉及以下名称开头的条件`'M'`。 我们只关心字符串的第一个字符。 名称如`"Michael"`和`"Meir"`应该不符合条件，而名称如`"Alice"`或者`"Kannon"`应该通过。 

该问题保证了`employee_id`是唯一的，所以我们永远不需要处理重复的 ID。 由于这是简单的逐行计算，因此可扩展性问题很少。 

一些重要的边缘情况包括：

 - 拥有偶数身份证的员工，他们总是会收到`0`- 名字开头为`'M'`，他们总是收到`0`- 满足这两个条件的员工，他们将获得全额工资
 - 非常小的 ID，例如`1`- 单字符名称，例如`"M"`或者`"A"`由于每行的逻辑是独立的，因此记录之间不存在复杂的交互。 

## 方法

 ### 蛮力方法

 从概念上讲，强力方法将一次一行地迭代每个员工，并手动评估两个所需的条件。 

对于每位员工：

 1. 检查是否`employee_id`很奇怪。 
2. 检查名称是否以`'M'`。 
3. 如果两者都为真，则将奖金分配为工资。 
4. 否则，分配`0`。 

处理完所有行后，结果将按以下顺序排序`employee_id`。 

这种方法是正确的，因为每个员工都是根据问题陈述中给出的确切规则进行独立评估的。 

在传统的编程环境中，这将涉及显式循环所有行。 然而，在 SQL 中，数据库是为基于集合的操作而设计的，因此逐行过程逻辑是不必要的，并且从概念上讲效率较低。 

### 最佳方法

 最佳解决方案直接在查询中使用 SQL 的内置条件表达式和过滤功能。 

关键的见解是奖金计算完全是确定性的，并且仅取决于单行中的值。 SQL 使用一个自然的方式处理这个问题`CASE`表达。 

我们可以：

 - 使用`employee_id % 2 = 1`检查奇数 ID
 - 使用`name NOT LIKE 'M%'`确保名称不以`'M'`- 使用`CASE WHEN`返回任一`salary`或者`0`这使得数据库引擎可以在一次遍历表的过程中高效地计算结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 迭代所有行并分别对结果进行排序 |
 | 最佳| O(n log n) | O(n log n) | O(1) | O(1) | 具有条件逻辑和排序的单个 SQL 查询 |

 排序步骤在运行时占据主导地位，因为最终结果必须按以下顺序排序`employee_id`。 

## 算法演练

 ### 最优 SQL 算法

 1. 首先选择`employee_id`列，因为它必须出现在最终输出中。 
2. 使用`CASE WHEN`表达式来确定每个员工的奖金值。 
3. 在条件内，使用以下命令检查员工 ID 是否为奇数：```sql
employee_id % 2 = 1
```4.还要检查员工姓名是否不以`'M'`使用：```sql
name NOT LIKE 'M%'
```5. 将两个条件结合起来`AND`因为这两个要求必须同时满足。 
6. 如果两个条件都成立，则返回员工的`salary`作为奖金。 
7. 否则，返回`0`。 
8. 将计算值别名为`bonus`。 
9. Order the final result by`employee_id`使用：```sql
ORDER BY employee_id
```### 为什么它有效

 该算法之所以有效，是因为每个员工都根据问题中指定的确切规则进行独立评估。 这`CASE WHEN`表达式保证每一行收到全额工资或零工资，具体取决于条件是否满足。 由于查询对每一行只处理一次，然后对输出进行排序，因此最终结果既完整又排序正确。 

## Python 解决方案

 虽然这是一个数据库问题，但等效的 Python 逻辑有助于清楚地说明算法。```python
from typing import List, Dict

class Solution:
    def calculateSpecialBonus(
        self,
        employees: List[Dict[str, int | str]]
    ) -> List[Dict[str, int]]:
        
        result = []

        for employee in employees:
            employee_id = employee["employee_id"]
            name = employee["name"]
            salary = employee["salary"]

            if employee_id % 2 == 1 and not name.startswith("M"):
                bonus = salary
            else:
                bonus = 0

            result.append({
                "employee_id": employee_id,
                "bonus": bonus
            })

        result.sort(key=lambda x: x["employee_id"])

        return result
```实现直接遵循算法。 

该循环对每个员工只处理一次。 对于每个员工，代码都会提取 ID、姓名和薪水字段。 条件语句检查 ID 是否为奇数以及名称是否避免以`'M'`。 

如果两个条件都成立，则奖金将分配给员工的工资。 否则，奖金将变为`0`。 

每个计算结果被追加到输出列表中，最后结果按以下顺序排序`employee_id`。 

对于实际的 LeetCode 数据库提交，SQL 查询将是：```python
SELECT
    employee_id,
    CASE
        WHEN employee_id % 2 = 1
             AND name NOT LIKE 'M%'
        THEN salary
        ELSE 0
    END AS bonus
FROM Employees
ORDER BY employee_id;
```## 解决方案

 以下 Go 实现以编程方式反映了相同的逻辑。```go
package main

import (
	"sort"
)

type Employee struct {
	EmployeeID int
	Name       string
	Salary     int
}

type Result struct {
	EmployeeID int
	Bonus      int
}

func calculateSpecialBonus(employees []Employee) []Result {
	results := make([]Result, 0)

	for _, employee := range employees {
		bonus := 0

		if employee.EmployeeID%2 == 1 &&
			(len(employee.Name) == 0 || employee.Name[0] != 'M') {
			bonus = employee.Salary
		}

		results = append(results, Result{
			EmployeeID: employee.EmployeeID,
			Bonus:      bonus,
		})
	}

	sort.Slice(results, func(i, j int) bool {
		return results[i].EmployeeID < results[j].EmployeeID
	})

	return results
}
```Go 实现与 Python 版本非常相似，但存在一些特定于语言的差异。 

Go 使用结构体而不是字典来表示员工和结果。 排序步骤使用`sort.Slice`具有自定义比较功能。 Go 中的字符串索引访问字节，因此检查第一个字符是通过`employee.Name[0] != 'M'`。 

该实现还通过检查来安全地处理空字符串`len(employee.Name) == 0`。

 ## 边缘情况

 ### ID 为偶数的员工

 一名员工甚至`employee_id`必须始终获得奖金`0`，无论他们的名字如何。 如果实现首先检查姓名条件并错误地授予薪水，这可能会成为错误的根源。 该实现通过使用逻辑要求两个条件同时为真来防止这种情况发生`AND`。 

### 以“M”开头的名字

 姓名以以下开头的员工`'M'`即使他们的 ID 是奇数，也不得获得任何奖金。 这种边缘情况很重要，因为开发人员可能会意外地检查是否存在`'M'`字符串中的任何位置，而不是专门在开头。 使用`LIKE 'M%'`在 SQL 中和`startswith("M")`在 Python 中确保只有第一个字符重要。 

### 空名称或非常短的名称

 简称，例如`"M"`或者`"A"`如果实现假设名称始终包含多个字符，则可能会暴露索引错误。 该解决方案通过使用内置字符串方法来安全地处理这个问题，而不是在没有检查的情况下手动索引。 

### 空输入表

 如果表不包含员工，则正确的结果只是一个空结果集。 该实现自然会处理这个问题，因为迭代空集合不会产生任何行，并且最终返回的结果仍然为空。
