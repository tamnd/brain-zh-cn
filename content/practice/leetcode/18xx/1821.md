[LeetCode 问题 1821](https://leetcode.com/problems/find-customers-with-positive-revenue-this-year/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`Customers`三列：

 | 专栏 | 意义|
 | --- | --- |
 |`customer_id`| 客户的唯一标识符 |
 |`year`| 与收入相关的年份|
 |`revenue`| 该客户当年的收入值 |

 组合`(customer_id, year)`保证是唯一的，这意味着客户在给定年份最多只能出现一次。 

任务是返回当年收入的所有客户`2021`严格大于`0`。 

重要的细节是收入可能为负。 有收入的客户`0`或负收入不应出现在输出中。 另外，当年没有任何条目的客户`2021`不得包含在内。 

简单来说，我们只希望客户满足这两个条件：

 1.`year == 2021`2.`revenue > 0`输出应仅包含`customer_id`列和行可以按任何顺序返回。 

因为这是一个数据库问题，所以预期的解决方案是 SQL 查询，而不是用传统数据结构实现的算法。 数据集大小没有明确指定，但数据库问题通常旨在鼓励使用 SQL 谓词进行有效的过滤操作。 

一些重要的边缘情况立即脱颖而出：

 - 客户可能只存在于 2021 年以外的年份，这些客户必须被忽略。 
- 收入可能为负数，因此仅检查年份是不够的。 
- 收入可能为零，零并不被视为积极的。 
- 多个客户可以独立获得资格。 
- 自从`(customer_id, year)`是独一无二的，我们永远不需要担心 2021 年同一客户的重复行。 

## 方法

 ### 蛮力方法

 暴力式解决方案从概念上讲会扫描表中的每一行，并手动评估每一行是否属于答案。 

对于每一行：

 - 检查年份是否为`2021`- 检查收入是否大于`0`- 如果两个条件都成立，则在结果中包含客户 ID

 这是有效的，因为每一行都是根据问题条件独立评估的。 由于该表已经存储了所有必要的信息，因此不需要额外的计算或聚合。 

虽然这种方法很简单，但它并没有以优化的 SQL 方式进行描述。 实际上，除非索引存在，否则数据库引擎仍然会在内部执行表扫描。 

### 最佳方法

 关键的观察结果是该问题纯粹是过滤操作。 

我们不需要：

 - 分组，
 - 聚合，
 - 排序，
 - 加入，
 - 或子查询。 

我们只需要选择满足两个谓词的行。 

SQL 正是为这种类型的操作而设计的`WHERE`条款。 通过直接在查询中进行过滤，数据库引擎可以有效地仅返回匹配的行。 

因此，最佳解决方案使用：```
WHERE year = 2021 AND revenue > 0
```这直接表达了业务需求，避免了不必要的复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描每一行并手动检查条件 |
 | 最佳| O(n) | O(1) | O(1) | 使用 SQL 过滤`WHERE`条款|

 ## 算法演练

 1. 开始读取行`Customers`桌子。 
2. 对于每一行，检查是否`year`列等于`2021`。 这确保我们只考虑所需年份的收入记录。 
3. 对于 2021 年以来的行，检查是否`revenue`值大于`0`。 这会过滤掉收入为负或零的客户。 
4. 如果两个条件都满足，则返回`customer_id`对于该行。 
5. 继续，直到处理完所有行。 
6. 输出生成的客户 ID 集。 

### 为什么它有效

 该算法之所以有效，是因为表中的每一行都独立地代表客户在特定年份的收入。 该问题准确地要求那些行：

 - 年份是 2021 年，并且
 - 收入为正。 

通过同时使用这两个条件过滤行，查询可以精确返回所需的客户并排除所有无效情况。 

## Python 解决方案

 LeetCode 数据库问题是使用 SQL 解决的，但为了完整起见，以下部分显示了 Python 代码块内格式化的 SQL 查询。```python
SELECT customer_id
FROM Customers
WHERE year = 2021
AND revenue > 0;
```该查询仅选择`customer_id`列，因为输出格式不需要附加数据。 

这`FROM Customers`子句指定要查询的表。 

这`WHERE`子句应用两个必需的过滤器：

 -`year = 2021`将结果限制在目标年份。 
-`revenue > 0`确保仅包含正收入值。 

自从`(customer_id, year)`是唯一的，2021 年不会出现重复的客户 ID。 

## 解决方案

 再次强调，因为这是一个数据库问题，所以实际的解决方案是 SQL 而不是 Go 代码。 等效的 SQL 查询如下所示。```go
SELECT customer_id
FROM Customers
WHERE year = 2021
AND revenue > 0;
```这里没有 Go 特定的实现问题，因为执行环境是基于 SQL 的。 不涉及数组、映射、指针或溢出注意事项。

 ## 边缘情况

 一个重要的边缘情况是 2021 年根本不会出现的客户。 幼稚的实施可能会意外地包括其他年份有正收入的客户。 该查询通过明确要求避免此问题`year = 2021`在`WHERE`条款。 

另一个重要案例是2021年收入为负或为零的客户。 由于该问题特别要求正收入，因此诸如`0`和`-50`不得出现在结果中。 使用条件`revenue > 0`正确排除这两个类别。 

第三种边缘情况涉及重复处理。 在许多数据库问题中，重复的行可能会意外地产生重复的输出。 然而，这个问题保证了`(customer_id, year)`是独一无二的。 由于此保证，每个客户在 2021 年最多只能出现一次，因此无需额外`DISTINCT`关键字是必要的。 

最后一个边缘情况是空表。 如果不存在任何行，查询自然会返回一个空结果集，不会出现错误。 此行为由 SQL 过滤语义自动处理。
