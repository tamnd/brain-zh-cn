[LeetCode 问题 1848](https://leetcode.com/problems/minimum-distance-to-the-target-element/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`，一个称为`target`，以及一个名为`start`。 我们需要找到一个索引`i`在哪里`nums[i] == target`和之间的距离`i`和`start`尽可能小。 

使用绝对差来测量距离：$|i-start|$这意味着我们只关心索引之间的距离，无论方向如何。 例如，如果`start = 3`，然后指数`2`和`4`都是距离`1`离开。 

输入数组的索引为 0，这意味着第一个元素位于索引处`0`，索引处的第二个`1`， 等等。 

该任务并不要求我们返回索引本身。 相反，我们返回之间的最小距离`start`以及任何发生`target`。 

限制很小：

 -`1 <= nums.length <= 1000`-`target`保证存在于数组中

 由于数组大小最多为 1000，因此即使直接扫描数组也足够高效。 我们不需要先进的数据结构或优化技术。 

一些边缘情况很重要：

 - 的`target`可能恰好出现在`start`，这意味着答案是`0`。 
- 这`target`可能会出现多次，因此我们必须选择最接近的一次出现。 
- 数组只能包含一个元素。 
- 最近的目标可能出现在之前或之后`start`。 
- 由于问题保证了`target`存在，我们永远不需要处理不存在有效答案的情况。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查数组中的每个元素。 

对于每个索引`i`:

 1. 检查是否`nums[i] == target`。 
2. 如果存在，计算距离`abs(i - start)`。 
3. 记录目前为止看到的最小距离。 

扫描结束时，存储的最小距离就是答案。 

这种方法是正确的，因为它评估目标出现的每个可能的有效索引。 由于我们比较所有候选距离，找到的最小距离必定是真正的最小值。 

虽然这被称为暴力解决方案，但这里完全可以接受，因为数组大小很小。 该算法仅执行一次线性扫描。 

### 最佳方法的关键见解

 重要的观察是，我们不需要搜索组合、路径或复杂的关系。 该问题仅要求到匹配值的最小距离。 

因为每个有效的候选者都可以独立评估，所以一次遍历数组就足够了。 扫描时：

 - 每次我们相遇`target`，我们计算它的距离`start`。 
- 我们不断更新最小距离。 

不需要额外的数据结构，因为我们只需要一个运行最小值。 

实际上，暴力方法和最优方法本质上是相同的，因为线性扫描对于这个问题来说已经是最优的。

 ## 算法演练

 1. 初始化一个名为`minimum_distance`具有非常大的价值。 

该变量存储迄今为止找到的最小距离。 我们从一个很大的数字开始，以便第一个有效的目标出现将取代它。 
2. 使用索引和值迭代数组。 

我们需要索引，因为距离取决于位置，而不是值。 
3. 对于每个元素，检查它是否等于`target`。 

只有包含目标的索引才是相关的。 
4. 如果当前元素等于`target`，计算绝对距离`start`。$|i-start|$这给出了当前目标索引和起始索引之间的距离。 
5. 将计算出的距离与`minimum_distance`。 

如果新的距离较小，则更新`minimum_distance`。 
6. 继续扫描直到阵列末尾。 

这保证了每个可能的目标发生都已被考虑。 
7. 返回`minimum_distance`。 

处理完所有元素后，它包含尽可能小的距离。 

### 为什么它有效

 该算法之所以有效，是因为它检查了每个索引，其中`nums[i] == target`。 对于每个有效索引，它计算与`start`。 由于算法保持扫描过程中遇到的最小距离，因此最终结果必须是所有有效目标位置中可能的最小距离。 

## Python 解决方案```python
from typing import List

class Solution:
    def getMinDistance(self, nums: List[int], target: int, start: int) -> int:
        minimum_distance = float("inf")

        for index, value in enumerate(nums):
            if value == target:
                distance = abs(index - start)
                minimum_distance = min(minimum_distance, distance)

        return minimum_distance
```实现从初始化开始`minimum_distance`到无穷大。 这确保了数组中找到的任何实际距离都会更小。 

这`enumerate`使用函数以便我们可以在迭代期间访问索引和值。 每当当前值等于`target`，该算法计算当前索引和`start`。 

内置的`min`函数有效地更新运行最小值。 

最后，循环完成后，该函数返回扫描期间发现的最小距离。 

## 解决方案```go
import "math"

func getMinDistance(nums []int, target int, start int) int {
    minimumDistance := math.MaxInt32

    for index, value := range nums {
        if value == target {
            distance := index - start

            if distance < 0 {
                distance = -distance
            }

            if distance < minimumDistance {
                minimumDistance = distance
            }
        }
    }

    return minimumDistance
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个小小的区别是 Go 没有提供内置的泛型`abs`函数用于整数，因此我们手动将负距离转换为正值。 

该解决方案使用`math.MaxInt32`作为初始大值`minimumDistance`。 

由于问题约束很小，因此整数溢出不是这里的问题。

 ## 边缘情况

 当目标已经位于起始索引处时，会出现一种重要的边缘情况。 在这种情况下，正确答案是立即`0`因为索引与其自身之间的距离为零。 有缺陷的实现可能会继续进行不必要的搜索，或者无法认识到零已经是最小的可能答案。 这个实现自然地处理了这种情况，因为`abs(start - start)`评估为`0`，运行最小值变为`0`。 

另一个重要的情况是当目标在整个数组中多次出现时。 幼稚的实现可能会错误地返回第一个出现的位置，而不是最接近的出现位置。 该解决方案通过扫描整个阵列并在每次发现目标时更新最小距离来避免此问题。 

第三种边缘情况涉及非常小的数组，尤其是长度数组`1`。 在这种情况下，唯一的元素也必须是目标，因为问题保证目标存在。 该实现工作正常，因为循环仍然正常处理单个元素并计算距离`0`。 

最后的边缘情况是最接近的目标出现在起始索引之前而不是之后。 如果没有绝对值处理，距离可能会变为负值并产生错误的结果。 使用`abs(index - start)`保证无论方向如何，距离始终被正确处理。
