[LeetCode 问题 1875](https://leetcode.com/problems/group-employees-of-the-same-salary/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这是一个 SQL 数据库问题，我们需要根据工资将员工分组。 重要的细节是，团队完全由薪水定义，这意味着团队中的每个员工必须具有完全相同的薪水，并且所有具有相同薪水的员工必须属于同一个团队。 

然而，并不是每一份薪水都能组成一个有效的团队。 仅当至少有两名员工分享该工资时，该工资组才被视为一个团队。 如果薪水只出现一次，则该员工将完全排除在输出之外。 

确定有效的团队后，我们必须分配一个`team_id`。 这个ID不是任意的。 这仅取决于有效球队之间的薪资排名。 工资最低的团队获得`team_id = 1`，第二小的有效工资得到`team_id = 2`， 等等。 具有独特薪资的员工不参与排名过程。 

输入由一个表组成，`Employees`，包含：

 -`employee_id`，每个员工的唯一标识符
 -`name`, 员工姓名
 -`salary`, 雇员的工资

 输出应仅包括属于有效团队的员工，以及：

 -`employee_id`-`name`-`salary`-`team_id`结果必须按以下顺序排序`team_id`按升序排列，然后按`employee_id`按升序排列。 

主要挑战是正确实施薪资分组和排名。 幼稚的实现可能会错误地对所有工资进行排名，包括独特的工资，这会产生不正确的结果`team_id`价值观。 另一个常见的错误是为工资相同的员工分配不同的团队，违反了所有工资相同的员工属于同一团队的要求。 

问题中的一个重要保证是`employee_id`是唯一的，这意味着我们永远不会有重复的员工记录。 工资可以任意重复，并且可以存在多个组。 

## 方法

 ### 蛮力方法

 暴力方法会检查每个员工，并将他们的工资与其他每个员工进行比较，以确定是否存在匹配的工资。 

对于每个员工，我们可以扫描整个表来统计有多少员工的工资相同。 如果计数至少为 2，则该员工属于有效团队。 在确定所有有效工资后，我们将对它们进行排序并手动分配排名。 最后，我们再次扫描员工列表，分配相应的员工`team_id`。 

这种方法之所以有效，是因为它明确地检查了员工和工资之间的所有关系。 但是，它会重复扫描表，从而导致效率低下。 如果有`n`员工，检查每个员工的工资匹配情况`O(n²)`时间。 

### 最佳方法

 关键的见解是这个问题本质上是一个分组问题。 

我们可以使用 SQL 聚合一次按工资对员工进行分组，而不是重复扫描表。 通过申请`GROUP BY salary`，我们可以统计有多少员工属于每个薪资组。 

仅薪资组`COUNT(*) >= 2`作为团队获得资格。 一旦确定了有效的薪资组，我们就可以使用窗口函数对它们进行排名。 由于问题指定团队ID是根据工资顺序确定的，`DENSE_RANK()`按升序排列的工资恰好满足了我们的需要。 

最后，我们将排名后的薪资组重新加入到原来的`Employees`表来检索员工信息。 

这种方法非常有效，因为分组和排名只需执行一次，避免了重复扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复扫描员工以计算匹配的工资|
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用 SQL 聚合进行分组和排名 |

 ## 算法演练

 1. 按工资对员工进行分组，并统计有多少员工分享每份工资。 这告诉我们哪些薪资组是有效的团队。 
2. 过滤掉只有一名员工的薪资组。 由于团队需要至少两名成员，因此这些工资不应参与团队创建或排名。 
3. 使用以下方法将剩余工资按升序排列`DENSE_RANK()`。 我们使用`DENSE_RANK()`因为团队ID必须是连续的整数，不能有空格。 
4. 加入排名薪资组`Employees`桌子。 这使我们能够检索所有团队成员的员工详细信息。 
5. 对最终结果进行排序`team_id`进而`employee_id`，按照问题陈述的要求。 

### 为什么它有效

 该算法之所以有效，是因为每份工资都通过分组处理一次。 这`GROUP BY salary`运营保证所有同薪水的员工保持在一起。 过滤用`COUNT(*) >= 2`确保仅包含有效的团队。 最后，`DENSE_RANK()`仅根据有效的薪资组分配连续的团队 ID，这与问题定义完全匹配。 

## Python 解决方案

 尽管这是一个数据库问题并且 LeetCode 需要 SQL，但以下 Python 实现以编程方式演示了等效逻辑。```python
from typing import List, Dict

class Solution:
    def groupEmployees(self, employees: List[Dict]) -> List[Dict]:
        salary_count = {}

        # Count occurrences of each salary
        for employee in employees:
            salary = employee["salary"]
            salary_count[salary] = salary_count.get(salary, 0) + 1

        # Keep only valid team salaries
        valid_salaries = sorted(
            salary
            for salary, count in salary_count.items()
            if count >= 2
        )

        # Assign team IDs
        salary_to_team = {
            salary: idx + 1
            for idx, salary in enumerate(valid_salaries)
        }

        # Build result
        result = []

        for employee in employees:
            salary = employee["salary"]

            if salary in salary_to_team:
                result.append({
                    "employee_id": employee["employee_id"],
                    "name": employee["name"],
                    "salary": salary,
                    "team_id": salary_to_team[salary]
                })

        # Required ordering
        result.sort(key=lambda x: (x["team_id"], x["employee_id"]))

        return result
```实现首先计算每个工资出现的次数。 这反映了 SQL`GROUP BY salary`和`COUNT(*)`。 

接下来，提取至少出现两次的工资并对其进行排序。 排序是必要的，因为`team_id`取决于薪资从低到高的排名。 

然后创建从工资到团队 ID 的映射。 这允许在将团队分配给员工时进行恒定时间查找。 

最后，该算法迭代员工，并仅包括那些工资属于有效团队的员工。 结果按照问题要求排序。 

### SQL 解决方案

 由于 LeetCode 需要 SQL 查询，因此这是实际可提交的答案：```sql
WITH team_salaries AS (
    SELECT
        salary,
        DENSE_RANK() OVER (ORDER BY salary) AS team_id
    FROM Employees
    GROUP BY salary
    HAVING COUNT(*) >= 2
)

SELECT
    e.employee_id,
    e.name,
    e.salary,
    t.team_id
FROM Employees e
JOIN team_salaries t
    ON e.salary = t.salary
ORDER BY t.team_id, e.employee_id;
```该解决方案首先计算有效的薪资组并对它们进行排名。 最终加入确保每个拥有团队工资的员工都获得正确的`team_id`。 

## 解决方案

 以下 Go 实现演示了等效的编程逻辑。```go
package main

import (
	"sort"
)

type Employee struct {
	EmployeeID int
	Name       string
	Salary     int
}

type Result struct {
	EmployeeID int
	Name       string
	Salary     int
	TeamID     int
}

func groupEmployees(employees []Employee) []Result {
	salaryCount := make(map[int]int)

	// Count salary frequency
	for _, employee := range employees {
		salaryCount[employee.Salary]++
	}

	// Collect valid salaries
	var validSalaries []int
	for salary, count := range salaryCount {
		if count >= 2 {
			validSalaries = append(validSalaries, salary)
		}
	}

	sort.Ints(validSalaries)

	// Assign team IDs
	salaryToTeam := make(map[int]int)
	for idx, salary := range validSalaries {
		salaryToTeam[salary] = idx + 1
	}

	// Build result
	var result []Result

	for _, employee := range employees {
		teamID, exists := salaryToTeam[employee.Salary]
		if exists {
			result = append(result, Result{
				EmployeeID: employee.EmployeeID,
				Name:       employee.Name,
				Salary:     employee.Salary,
				TeamID:     teamID,
			})
		}
	}

	// Required ordering
	sort.Slice(result, func(i, j int) bool {
		if result[i].TeamID == result[j].TeamID {
			return result[i].EmployeeID < result[j].EmployeeID
		}
		return result[i].TeamID < result[j].TeamID
	})

	return result
}
```Go 的实现与 Python 解决方案非常相似。 一个`map[int]int`存储薪资频率，另一个映射存储薪资与团队的关系。 

由于 Go 地图是无序的，因此在分配团队 ID 之前必须对工资进行显式排序。 最后的排序步骤使用`sort.Slice`以满足所需的输出排序。

对于 SQL 解决方案，数据库优化器通常使用索引或内部排序机制有效地实现分组和排序。

 ## 边缘情况

 当每个员工都有独特的薪水时，就会出现一个重要的边缘情况。 粗心的实施可能仍会为每个员工分配团队 ID。 然而，该问题明确指出，独特的薪资并不能形成团队。 该实现通过使用过滤工资组来处理这个问题`count >= 2`。 

当多名员工共享一份薪水时，就会出现另一种边缘情况。 由于只有一个有效的薪资组，因此每位员工都应该收到`team_id = 1`。 该算法在对有效工资进行排序后正确分配排名，确保最小的有效工资始终从 1 开始。 

一个微妙的边缘情况涉及工资是唯一的，但在数字上介于有效团队工资之间。 例如，工资`[3000, 5000, 7000]`仅在哪里`3000`和`7000`重复。 不正确的实现可能会排名`7000`作为第 3 队，因为`5000`存在。 正确的行为完全忽略独特的薪资，这就是为什么只有在过滤有效薪资组后才会进行排名的原因。
