[LeetCode 1834 题](https://leetcode.com/problems/single-threaded-cpu/)

 **难度：** 🟡 中等
 **主题：** 数组、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题要求我们模拟在**单线程CPU**上执行任务。 每个任务都有一个**排队时间**和**处理时间**。 CPU 可以**一次处理一个任务**，并且必须根据两个规则选择下一个任务：首先按照**最短处理时间**，然后如果存在平局则按照**最小索引**。 如果没有可用的任务，CPU 将保持空闲状态，直到下一个任务到达。 

输入是表示为的任务列表`tasks[i] = [enqueueTimei, processingTimei]`。 每个任务由其在原始列表中的索引唯一标识。 输出应该是任务索引的**顺序**，因为它们由 CPU 处理。 

约束表明输入大小最多可以是 100,000 个任务，并且排队/处理时间可以高达 **10^9**，这意味着我们不能使用在每个时间步重复扫描所有任务的简单模拟方法。 我们需要一种有效的选择方法，通常是**优先级队列（最小堆）**。 

重要的边缘情况包括具有**相同排队时间**的任务、具有**相同处理时间**的任务，或者当 CPU 由于下一个任务尚未到达而必须**保持空闲**时。 

## 方法

 **暴力方法**会模拟从 0 到最大排队/处理时间的每个时间单位。 在每个单元，我们都会扫描所有任务以查找可用的任务，并选择处理时间最短的任务。 这种方法是**正确的**，但对于大输入量来说效率极低，因为它导致时间复杂度为**O(n * maxTime)**，考虑到约束，这是不可接受的。 

**最佳方法**使用两个关键见解：

 1. **按入队时间对任务进行排序**允许我们按照可用性顺序处理它们。 
2. **使用最小堆（优先级队列）** 由`(processingTime, index)`允许 CPU 以最短的处理时间有效地选择下一个任务，并通过索引在每次选择的 **O(log n)** 中解决关系。 

这种方法减少了不必要的扫描，并直接模拟任务处理事件而不是每个时间单元。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 最大时间) | O(n) | 模拟每个时间单元，扫描每一步的所有任务 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 对任务进行排序并使用堆高效地选择下一个任务 |

 ## 算法演练

 1. **附加索引**：将每个任务与其原始索引配对以打破平局。 
2. **排序任务**：按照任务入队时间排序。 
3. **初始化堆**：使用最小堆来存储可用的任务，首先按处理时间键，然后按索引键。 
4. **模拟CPU**：跟踪当前时间。 对于每次迭代：

 1. 将入队时间<=当前时间的所有任务添加到堆中。 
2. 如果堆不为空，则弹出处理时间最小的任务（按索引打破平局）并执行它，更新当前时间。 
3. 如果堆为空，则将当前时间提前到下一个任务的入队时间。 
5. 重复此操作，直至处理完所有任务。 

**为什么有效**：堆确保CPU始终根据规则选择最短的可用任务。 按排队时间排序可确保按正确的顺序考虑任务。 通过仅在必要时提前时间，我们可以避免空闲模拟。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def getOrder(self, tasks: List[List[int]]) -> List[int]:
        # Attach original indices to tasks
        indexed_tasks = [(enqueue, process, i) for i, (enqueue, process) in enumerate(tasks)]
        # Sort tasks by enqueue time
        indexed_tasks.sort()
        
        result = []
        min_heap = []
        time = 0
        i = 0
        n = len(tasks)
        
        while len(result) < n:
            # Add all tasks that are now available to the heap
            while i < n and indexed_tasks[i][0] <= time:
                enqueue, process, idx = indexed_tasks[i]
                heapq.heappush(min_heap, (process, idx))
                i += 1
            
            if min_heap:
                process, idx = heapq.heappop(min_heap)
                time += process
                result.append(idx)
            else:
                # If no task is available, jump time to next task's enqueue time
                time = indexed_tasks[i][0]
        
        return result
```**说明**：Python 解决方案使用堆来存储可用任务。 在每一步中，所有新可用的任务都被推送到堆上。 CPU 在堆顶部处理任务，确保选择最短的处理时间。 如果堆是空的，CPU会跳转到下一个任务的入队时间以避免空闲时间。 

## 解决方案```go
package main

import (
    "container/heap"
    "sort"
)

type Task struct {
    enqueue int
    process int
    index   int
}

type TaskHeap []Task

func (h TaskHeap) Len() int { return len(h) }
func (h TaskHeap) Less(i, j int) bool {
    if h[i].process == h[j].process {
        return h[i].index < h[j].index
    }
    return h[i].process < h[j].process
}
func (h TaskHeap) Swap(i, j int) { h[i], h[j] = h[j], h[i] }
func (h *TaskHeap) Push(x interface{}) {
    *h = append(*h, x.(Task))
}
func (h *TaskHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func getOrder(tasks [][]int) []int {
    n := len(tasks)
    indexedTasks := make([]Task, n)
    for i, t := range tasks {
        indexedTasks[i] = Task{enqueue: t[0], process: t[1], index: i}
    }
    sort.Slice(indexedTasks, func(i, j int) bool {
        return indexedTasks[i].enqueue < indexedTasks[j].enqueue
    })
    
    result := make([]int, 0, n)
    h := &TaskHeap{}
    heap.Init(h)
    
    time := 0
    i := 0
    
    for len(result) < n {
        for i < n && indexedTasks[i].enqueue <= time {
            heap.Push(h, indexedTasks[i])
            i++
        }
        if h.Len() > 0 {
            t := heap.Pop(h).(Task)
            time += t.process
            result = append(result, t.index)
        } else {
            time = indexedTasks[i].enqueue
        }
    }
    
    return result
}
```**Go 特定注释**：在 Go 中，我们定义了一个自定义的`TaskHeap`实现的类型`heap.Interface`方法。 堆按处理时间排序，并按原始索引断开关系。 该逻辑反映了 Python 版本，具有显式的切片处理和堆操作。

 **示例2：`[[7,10],[7,12],[7,5],[7,4],[7,2]]`**

 堆序列：(2,4),(4,3),(5,2),(10,0),(12,1) → 结果`[4,3,2,0,1]`## 复杂度分析
