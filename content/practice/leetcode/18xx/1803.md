 # LeetCode 1803 - 计算某个范围内异或的对数

 ## 问题理解

 问题给了我们一个整数数组`nums`和两个整数，`low`和`high`。 我们需要计算有多少个索引对`(i, j)`满足两个条件：

 -`i < j`-`low <= nums[i] XOR nums[j] <= high`XOR 运算比较两个数字之间的位。 对于每个位位置：

 - 如果位不同，结果位变为`1`- 如果位相同，则结果位变为`0`任务不是要求我们自行归还这些对。 我们只需要总数。 

例如，如果：```
nums = [1,4,2,7]
low = 2
high = 6
```然后：```
1 XOR 4 = 5
1 XOR 2 = 3
1 XOR 7 = 6
```所有这些值都在`[2, 6]`，所以他们对答案做出了贡献。 

约束条件很重要：

 -`nums.length <= 2 * 10^4`-`nums[i] <= 2 * 10^4`检查每一对的简单解决方案大约需要：```
(2 * 10^4)^2 = 4 * 10^8
```最坏情况下的比较，速度太慢。 

这些值也相对较小，这强烈表明按位数据结构可能会有所帮助。 由于 XOR 本质上是一种位运算，因此二进制 trie 成为自然的候选者。 

有几个边缘情况值得注意：

 - 应该返回只有一个元素的数组`0`- 多个相同的值可能会产生异或`0`- 该范围可能包括几乎所有可能的 XOR 值
 - 范围边界包含在内
 - 我们必须避免重复计算对

 该问题保证了有效的输入，因此我们不需要处理无效范围或空数组。 

## 方法

 ### 蛮力方法

 最简单的解决方案是检查每一个可能的对`(i, j)`在哪里`i < j`。 

对于每对：

 1. 计算`nums[i] XOR nums[j]`2. 检查异或结果是否在范围内`[low, high]`3. 如果有则增加答案

 这是有效的，因为它直接遵循问题定义。 

但时间复杂度太高。 有`O(n^2)`对，并且与`n = 20,000`，这变得不可行。 

### 最佳解决方案的关键见解

 重要的观察是，我们可以计算：```
count(XOR <= high) - count(XOR < low)
```更具体地说：```
count(low <= XOR <= high)
=
count(XOR <= high) - count(XOR <= low - 1)
```因此，问题简化为有效地计算有多少先前的数字产生小于或等于限制的 XOR 值。 

这就是二进制字典树的用处。 

二进制 trie 逐位存储数字。 处理一个数字时`x`，我们可以有效地计算出有多少先前插入的数字满足：```
x XOR y < limit
```trie 允许我们一次一点地评估这个条件。 

因为数字最多是`2 * 10^4`，它们适合 15 位。 使用固定位数可以保持操作高效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 直接检查每对 |
 | 最优 Trie 解决方案 | O(n × B) | O(n × B) | 使用二进制 trie，其中`B`是位数 |

 这里，`B = 15`或者`16`，这实际上是常数。 

## 算法演练

 ### 第 1 步：转换范围查询

 而不是直接计算里面的异或值`[low, high]`，计算：```
countPairsLessThan(high + 1) - countPairsLessThan(low)
```在哪里：```
countPairsLessThan(limit)
```返回 XOR 严格小于的对的数量`limit`。 

这种转换显着简化了逻辑。 

### 第 2 步：构建二进制 Trie

 二进制特里树存储从最高有效位到最低有效位的位。 

每个 trie 节点包含：

 - 两个孩子：

 -`0`-`1`- 表示有多少数字通过该节点的计数

 例如，数字`5`：```
0101
```会一点一点地插入。 

### 第三步：一一处理数字

 我们迭代`nums`。 

对于每个数字`x`：

 1. 查询 trie 来统计之前插入的数字有多少个满足：```
x XOR y < limit
```2. 将计数添加到答案中
 3. 插入`x`进入特里树

 这保证：

 - 每对只计算一次
 - 仅考虑较早的元素

 ### 步骤 4：查询逻辑

 查询一点一点地进行。 

假设我们正在检查位`k`。 

让：

-`xBit`是当前位`x`-`limitBit`是当前位`limit`有两种情况。 

#### 情况 1：`limitBit == 1`如果限制位是`1`，那么：

 - 选择异或位`0`使我们严格低于该位置的限制
 - 选择异或位`1`意味着到目前为止我们保持相等并且必须继续检查较低位

 所以：

 - 添加产生 XOR 位的所有有效分支`0`- 继续遍历产生 XOR 位的分支`1`#### 情况 2：`limitBit == 0`如果限制位是`0`，我们不能超过它。 

因此：

 - 我们被迫选择异或位`0`- 仅在该分支上继续遍历

 这种按位推理使得 trie 变得高效。 

### 步骤 5：计算最终答案

 最后：```
answer =
countPairsLessThan(high + 1)
-
countPairsLessThan(low)
```这给出了包含范围内的 XOR 值的计数。 

### 为什么它有效

 trie 始终包含出现在当前索引之前的数字，因此每一对都满足`i < j`。 

查询逻辑精确计算与当前数字异或小于指定限制的数字。 由于异或比较可以按字典顺序从最高有效位向下进行评估，因此贪婪地处理位会产生正确的计数。 

减去两个前缀计数即可隔离所需的范围。 

## Python 解决方案```python
from typing import List

class TrieNode:
    def __init__(self):
        self.children = {}
        self.count = 0

class Solution:
    def countPairs(self, nums: List[int], low: int, high: int) -> int:
        MAX_BIT = 15

        def count_less_than(limit: int) -> int:
            root = TrieNode()
            total_pairs = 0

            def insert(num: int) -> None:
                node = root

                for bit in range(MAX_BIT, -1, -1):
                    current_bit = (num >> bit) & 1

                    if current_bit not in node.children:
                        node.children[current_bit] = TrieNode()

                    node = node.children[current_bit]
                    node.count += 1

            def query(num: int) -> int:
                node = root
                count = 0

                for bit in range(MAX_BIT, -1, -1):
                    if node is None:
                        break

                    num_bit = (num >> bit) & 1
                    limit_bit = (limit >> bit) & 1

                    if limit_bit == 1:
                        same_branch = node.children.get(num_bit)

                        if same_branch:
                            count += same_branch.count

                        node = node.children.get(1 - num_bit)
                    else:
                        node = node.children.get(num_bit)

                return count

            for num in nums:
                total_pairs += query(num)
                insert(num)

            return total_pairs

        return count_less_than(high + 1) - count_less_than(low)
```实现首先定义一个 trie 节点。 每个节点存储：

 - 位的子指针`0`和`1`- 有多少数字通过该节点的计数

 辅助函数`count_less_than(limit)`计算有多少对的 XOR 严格小于`limit`。 

在这个函数内部：

 -`insert()`将一个数字逐位添加到 trie 中
 -`query()`计算之前插入的数字满足的数量：```python
num XOR previous < limit
```查询从最高有效位到最低有效位处理位。 在每一步中，它使用当前限制位来决定是否可以立即对整个子树进行计数，或者是否必须继续遍历。 

主循环按顺序处理数字：

 - 先查询
 - 之后插入

 这保证了仅计算较早的索引。 

最后，main函数将包含范围转换为两个前缀查询：```python
count(< high + 1) - count(< low)
```which produces the required answer.

 ## 解决方案```go
package main

type TrieNode struct {
	children [2]*TrieNode
	count    int
}

func countPairs(nums []int, low int, high int) int {
	const MAX_BIT = 15

	countLessThan := func(limit int) int {
		root := &TrieNode{}
		totalPairs := 0

		insert := func(num int) {
			node := root

			for bit := MAX_BIT; bit >= 0; bit-- {
				currentBit := (num >> bit) & 1

				if node.children[currentBit] == nil {
					node.children[currentBit] = &TrieNode{}
				}

				node = node.children[currentBit]
				node.count++
			}
		}

		query := func(num int) int {
			node := root
			count := 0

			for bit := MAX_BIT; bit >= 0; bit-- {
				if node == nil {
					break
				}

				numBit := (num >> bit) & 1
				limitBit := (limit >> bit) & 1

				if limitBit == 1 {
					sameBranch := node.children[numBit]

					if sameBranch != nil {
						count += sameBranch.count
					}

					node = node.children[1-numBit]
				} else {
					node = node.children[numBit]
				}
			}

			return count
		}

		for _, num := range nums {
			totalPairs += query(num)
			insert(num)
		}

		return totalPairs
	}

	return countLessThan(high+1) - countLessThan(low)
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用固定大小的子数组而不是字典。 

这是有效的，因为每个节点只有两个可能的子节点。 

Go-specific details include:

- Pointer-based trie nodes
- Explicit`nil`遍历期间检查
 - 固定阵列`[2]*TrieNode`供儿童参考
 - 整数运算仍然安全，因为最大答案符合标准`int`## 工作示例

 ## 边缘情况

 ### 单元素数组

 如果数组仅包含一个数字，则没有有效的对，因为条件需要`i < j`。 

如果插入和查询以错误的顺序完成，则幼稚的实现可能会意外地计算自对。 

此实现通过在插入之前进行查询来避免这种情况。 当前数字永远不会与其自身匹配。 

### 重复的数字

 当两个数相同时：```
x XOR x = 0
```当范围包含零时，这可以轻松创建许多有效对。 

trie 可以正确处理重复项，因为每个 trie 节点都存储有多少个数字通过它的计数。 多个相同的数字会增加相同的路径，从而允许对所有组合进行计数。 

### 包含范围边界

 问题使用：```
low <= XOR <= high
```包含边界是差一错误的常见来源。 

该实现仔细地将范围转换为：```
count(< high + 1) - count(< low)
```此转换可确保正确处理两个边界，而无需特殊情况逻辑。
