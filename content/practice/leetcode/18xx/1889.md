[LeetCode 问题 1889](https://leetcode.com/problems/minimum-space-wasted-from-packaging/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、排序、前缀和

 ## 解决方案

 ## 问题理解

 该问题为我们提供了封装尺寸和几个供应商的列表。 每个供应商提供无限数量的盒子，但仅限于某些固定尺寸。 我们必须准确选择一个供应商，并仅使用供应商提供的盒子尺寸包装每个包裹。 

每个包裹必须放入一个尺寸大于或等于包裹尺寸的盒子中。 一个包浪费的空间是：$$\text{box size} - \text{package size}$$我们的目标是最大限度地减少所有包装中浪费的总空间。 

重要的限制是我们只能使用一个供应商。 我们不能混合来自不同供应商的盒子。 

输入包括：

 -`packages`，封装尺寸数组
 -`boxes`， 在哪里`boxes[j]`包含供应商提供的盒子尺寸`j`输出是可能浪费的最小空间，或者`-1`如果没有供应商能够适合每个包裹。 

限制条件很大：

 - 最多`10^5`包
 - 所有供应商的盒子尺寸总数也高达`10^5`这些限制立即排除了任何二次型解决方案。 我们需要一种接近于：$$O(n \log n)$$或者$$O((n + \text{total boxes}) \log n)$$这些约束还强烈建议排序和二分搜索。 

一些边缘情况很重要：

 - 供应商可能没有足够大的盒子来容纳最大的包裹
 - 多个包裹可能适合同一盒子尺寸类别
 - 供应商可以按任意顺序提供盒子尺寸
 - 一些供应商可能有许多多余的盒子尺寸
 - 答案可能会变得非常大，所以我们必须将其模数返回$10^9 + 7$## 方法

 ### 蛮力方法

 一个简单的方法是独立尝试每个供应商。 

对于每个供应商：

 1. 对于每个包裹，搜索最小的有效盒子
 2. 计算该包裹造成的浪费
 3. 汇总所有浪费

 如果我们线性扫描每个包裹的盒子尺寸，复杂性就会变得非常大。 

即使我们对每个供应商的盒子进行排序并对每个包裹进行二分搜索，总的复杂性也会变成：$$O\left(\sum_j n \log b_j\right)$$在哪里：

-$n$是包裹数量
 -$b_j$是供应商的盒子尺寸数量$j$由于两个值都可以大到$10^5$，这种方法太慢了。 

### 关键见解

 重要的观察结果是，一旦对包裹进行排序，分配给相同盒子尺寸的包裹就会形成一个连续的范围。 

假设供应商提供排序的盒子尺寸：$$[4, 8, 10]$$然后：

 - 所有包裹均符合尺寸`4`可以用盒子`4`- 下一个范围可以使用盒子`8`- 剩余范围可以使用盒子`10`我们不是一个一个地处理包，而是分组处理它们。 

我们可以使用二分搜索来确定每个盒子尺寸可以容纳多少个包裹。 

为了有效计算某个范围内的总包大小，我们使用前缀和数组。 

这将重复的每个包工作转化为有效的范围计算。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 1. 排序`packages`大批。 

排序至关重要，因为它允许我们将连续范围的包裹分配给特定的盒子尺寸。 
2. 构建包大小的前缀和数组。 

让：$$prefix[i]$$代表第一个的总和`i`包。 

这使我们能够在恒定时间内计算任何包范围的总和。 
3. 跟踪最大包裹尺寸。 

如果供应商的最大盒子小于最大包装，则该供应商无法使用。 
4. 独立处理每个供应商。 

对于每个供应商：

 - 对盒子尺寸进行排序
 - 如果最大的盒子无法容纳最大的包裹，请跳过它
 5. 贪婪地将包裹分配给盒子尺寸。 

维护一个指针`start`代表第一个未分配的包。 

对于每个盒子尺寸：

 - 使用二分搜索找到最右边适合的包
 - 假设包裹来自`start`到`end - 1`适合
 6. 计算该组的浪费。 

如果`count = end - start`， 然后：$$\text{space used} = \text{box size} \times count$$和：$$\text{actual package sum} = prefix[end] - prefix[start]$$所以：$$\text{waste} = (\text{box size} \times count) - (\text{package sum})$$7. 收集废物并继续。 

移动`start = end`并处理下一个盒子尺寸。 
8. 跟踪所有供应商的最低浪费情况。 
9. 返回最小模数$10^9 + 7$。 

If no supplier can fit all packages, return`-1`。 

### 为什么它有效

 Because both packages and box sizes are sorted, assigning the smallest possible box to every package is always optimal for a fixed supplier. 任何更大的盒子只会增加浪费的空间。 

The binary search step correctly partitions packages into contiguous groups that fit each box size. Prefix sums ensure we compute the total wasted space for each group exactly.

 Therefore, the algorithm computes the minimum possible waste for every supplier and returns the global minimum.

 ## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def minWastedSpace(self, packages: List[int], boxes: List[List[int]]) -> int:
        MOD = 10**9 + 7

        packages.sort()
        n = len(packages)

        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + packages[i]

        largest_package = packages[-1]

        answer = float("inf")

        for supplier_boxes in boxes:
            supplier_boxes.sort()

            if supplier_boxes[-1] < largest_package:
                continue

            waste = 0
            start = 0

            for box_size in supplier_boxes:
                end = bisect_right(packages, box_size, start)

                if end > start:
                    count = end - start
                    package_sum = prefix[end] - prefix[start]

                    waste += box_size * count - package_sum

                    start = end

                if start == n:
                    break

            answer = min(answer, waste)

        return answer % MOD if answer != float("inf") else -1
```实施首先对包进行排序。 This enables grouped processing with binary search.

 The prefix sum array stores cumulative package sizes. 有了它，我们可以在常数时间内计算任意包间隔的总和。 

对于每个供应商，我们首先对可用的盒子尺寸进行排序。 如果供应商无法容纳最大的包装，我们会立即跳过该供应商。 

变量`start`tracks the first package not yet assigned to a box. 对于每个盒子尺寸，`bisect_right`查找第一个大于盒子大小的包索引。 该索引之前的所有内容都可以放入当前框中。 

使用前缀总和，我们可以一次性计算整个组造成的浪费，而不是单独处理包。 

最后，我们在所有供应商中保持最少的浪费，并以模数返回$10^9 + 7$。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func minWastedSpace(packages []int, boxes [][]int) int {
	const MOD int64 = 1e9 + 7

	sort.Ints(packages)

	n := len(packages)

	prefix := make([]int64, n+1)
	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + int64(packages[i])
	}

	largestPackage := packages[n-1]

	answer := int64(math.MaxInt64)

	for _, supplierBoxes := range boxes {
		sort.Ints(supplierBoxes)

		if supplierBoxes[len(supplierBoxes)-1] < largestPackage {
			continue
		}

		var waste int64 = 0
		start := 0

		for _, boxSize := range supplierBoxes {
			end := sort.Search(
				n,
				func(i int) bool {
					return packages[i] > boxSize
				},
			)

			if end < start {
				end = start
			}

			if end > start {
				count := int64(end - start)
				packageSum := prefix[end] - prefix[start]

				waste += int64(boxSize)*count - packageSum

				start = end
			}

			if start == n {
				break
			}
		}

		if waste < answer {
			answer = waste
		}
	}

	if answer == int64(math.MaxInt64) {
		return -1
	}

	return int(answer % MOD)
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个重要的区别是整数处理。 由于浪费可能会变得非常大，因此实施时使用`int64`用于前缀和和浪费计算以避免溢出。 

Go 没有提供与 Python 直接等效的功能`bisect_right`，所以我们使用`sort.Search`找到第一个索引在哪里`packages[i] > boxSize`。 

切片自然用于数组，排序是用`sort.Ints`。

from typing import List

class Solution:
    def minWastedSpace(self, packages: List[int], boxes: List[List[int]]) -> int:
        from bisect import bisect_right

        MOD = 10**9 + 7

        packages.sort()
        n = len(packages)

        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + packages[i]

        answer = float("inf")

        for supplier_boxes in boxes:
            supplier_boxes.sort()

            if supplier_boxes[-1] < packages[-1]:
                continue

            waste = 0
            start = 0

            for box_size in supplier_boxes:
                end = bisect_right(packages, box_size, start)

                if end > start:
                    count = end - start
                    waste += (
                        box_size * count
                        - (prefix[end] - prefix[start])
                    )
                    start = end

                if start == n:
                    break

            answer = min(answer, waste)

        return answer % MOD if answer != float("inf") else -1

 ## 边缘情况

 当没有供应商能够安装最大的包装时，就会出现一种重要的边缘情况。 幼稚的实现可能仍会尝试计算并产生不正确的结果。 在处理该供应商之前，该实现会明确检查该供应商的最大盒子是否至少与最大包裹一样大。 

另一个重要的情况是许多包共享相同的大小。 当存在重复项时，二分搜索边界可能会变得很棘手。 使用`bisect_right`确保所有小于或等于当前盒子尺寸的包裹都正确分组。 

第三种边缘情况涉及供应商提供多余或订购不当的包装盒尺寸。 由于每个供应商的盒子尺寸在处理前都会进行排序，因此该算法始终首先使用最小的可行盒子来分配包裹，这保证了该供应商的浪费最小化。 

最后一个边缘情况是极大的浪费值。 因为包裹数量和盒子尺寸都可以达到`10^5`，中间和可以超过 32 位整数限制。 Python 实现自然地处理大整数，而 Go 解决方案明确使用`int64`以防止溢出。
