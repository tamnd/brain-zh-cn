 # LeetCode 1884 - 2 个鸡蛋和 N 层楼的蛋掉落

 ## 问题理解

 这个问题要求我们确定识别关键楼层所需的最少移动次数`f`在一座建筑物中`n`地板，正好使用两个鸡蛋。 

临界层`f`有以下含义：

 - 任何从高于以下楼层掉落的鸡蛋`f`会破裂。 
- 任何从地板上掉落的鸡蛋`f`或更低的将生存。 

的价值`f`范围可以从`0`到`n`。 

如果`f = 0`，鸡蛋从每层楼破裂。 

如果`f = n`，鸡蛋永远不会破裂。 

我们需要设计一个策略来保证我们能够确定的准确值`f`，无论实际答案是什么。 重要的是我们要尽量减少最坏情况下的移动次数。 

输入是单个整数`n`，代表建筑物的层数。 输出是保证成功所需的最小移动次数。 

限制相对较小：

 -`1 <= n <= 1000`这告诉我们，即使是二次动态规划解决方案也是可行的。 然而，还有一个更清晰的数学观察可以得出最佳的线性时间解决方案。 

关键的困难来自于我们只有两个鸡蛋。 一旦鸡蛋破裂，我们就失去了冒险跳跃的能力。 只剩下一颗蛋了，唯一安全的策略就是线性搜索。 

一些边缘情况很重要：

 -`n = 1`，只存在一层，因此只需要移动一步。 
- 小值，例如`n = 2`或者`n = 3`，幼稚的策略可能会意外地高估或低估答案。 
- 大值，例如`n = 1000`，其中低效的递归解决方案可能会变得太慢。 
- 第一个鸡蛋提前破裂，迫使第二个鸡蛋进行连续搜索的情况。 

## 方法

 ### 暴力动态规划

 一种直接的方法是使用动态规划。 

定义`dp[i]`作为所需的最小移动次数`i`地板使用两个鸡蛋。 

对于每一个可能的第一层下降`x`：

 - 如果鸡蛋碎了，我们必须线性搜索下面的楼层`x`，要求`x - 1`额外的动作。 
- 如果鸡蛋存活下来，我们还需要解决剩下的问题`i - x`地板上有两个鸡蛋。 

最坏的情况是掉落在地板上`x`是：$1 + \max(x-1, dp[i-x])$我们尝试一切`x`值并选择最小值。 

这给出了正确的结果，因为它明确地评估了每一个可能的第一步并考虑了最坏情况的结果。 

然而，时间复杂度变成了二次方，因为对于每个楼层数`i`，我们测试每一个可能下降的楼层。 

### 最优数学观察

 最佳解决方案来自于平衡两种可能的结果。 

假设我们最多可以做`k`移动。 

如果我们从地板上掉下第一个鸡蛋`k`：

 - 如果它破裂了，我们可以使用第二个鸡蛋依次测试下面的楼层，最多需要`k - 1`更多动作。 
- 如果它幸存下来，我们还有`k - 1`向左移动。 

因此，下一次跳跃应该小一层楼：

 - 第一次跳跃：`k`- 第二次跳跃：`k - 1`- 第三跳：`k - 2`等等。 

后`k`移动，我们可以覆盖的总楼层数为：$1 + 2 + 3 + \cdots + k = \frac{k(k+1)}{2}$我们只需要最小的`k`这样：$\frac{k(k+1)}{2} \ge n$这将问题转化为寻找大于或等于的最小三角数`n`。

 ## 算法演练

 1.初始化两个变量：

 -`moves = 0`-`floorsCovered = 0`2.每次移动都会增加我们可以保证测试的楼层数。 

第一步我们可以覆盖一层。 

在第二次搬家时，我们可以覆盖另外两层楼。 

在第三次移动时，我们可以覆盖另外 3 层楼。 
3. 反复增加移动次数：

 - 增量`moves`- 添加`moves`到`floorsCovered`4. 继续直到`floorsCovered >= n`。 
5. 返回`moves`。 

例如，如果`n = 100`：

 - 移动 1 次后：1 层
 - 2次移动后：3层
 - 3次移动后：6层
 - ...
 - 14次移动后：105层

 由于 105 是第一个至少为 100 的三角数，所以答案是 14。 

### 为什么它有效

 该策略之所以有效，是因为每次下降都必须考虑两种结果：

 - 鸡蛋破碎
 - 蛋存活下来

 通过每次将跳跃大小减少一，我们保证无论第一个鸡蛋何时破裂，仍然可以通过剩余的动作顺序检查剩余的楼层。 

三角数公式准确地表示了可以安全覆盖的最大楼层数`k`动作和两个鸡蛋。 

## Python 解决方案```python
class Solution:
    def twoEggDrop(self, n: int) -> int:
        moves = 0
        floors_covered = 0

        while floors_covered < n:
            moves += 1
            floors_covered += moves

        return moves
```实现直接遵循数学观察。 

变量`moves`代表允许的跌落次数。 变量`floors_covered`存储我们可以使用那么多步数确定的最大楼层数。 

每次迭代都会增加一次移动，并根据新跳跃的大小扩大覆盖范围。 

一旦覆盖的地板至少变成`n`，我们知道当前的移动次数是足够的。 

由于三角形数按二次方增长，因此循环仅运行约`√n`次。 

## 解决方案```go
func twoEggDrop(n int) int {
    moves := 0
    floorsCovered := 0

    for floorsCovered < n {
        moves++
        floorsCovered += moves
    }

    return moves
}
```Go 实现与 Python 版本几乎相同。 

Go 使用显式变量声明`:=`。 自从`n <= 1000`，整数溢出不是问题。 不需要切片或动态内存，因为该解决方案仅使用恒定的额外空间。

 ## 边缘情况

 一个重要的边缘情况是当`n = 1`。 只有一层楼，答案一定是一招。 某些实现意外地返回零，因为它们初始化不正确或使用了错误的循环条件。 我们的实现正确地处理了这个问题，因为循环执行一次并立即达到足够的覆盖范围。 

另一个重要的边缘情况发生在`n`恰好是一个三角形数，例如 3、6 或 10。在这些情况下，最佳移动次数恰好落在边界上。 相差一的错误在这里很常见。 我们的实现使用`while floors_covered < n`，确保当覆盖范围等于时我们立即停止`n`。 

第三个重要的情况发生在`n`就在一个三角形数字的上方，例如 7 或 11。即使前一个三角形数字非常接近，这些值也需要进行一次额外的移动。 不正确的实施有时会低估所需的动作。 由于我们继续迭代直到覆盖率至少达到`n`，这些情况都得到了正确的处理。 

最后，大量输入，例如`n = 1000`验证实施仍然有效。 递归或二次方法可能仍然适用于此约束，但数学解决方案保持极快并使用恒定内存。
