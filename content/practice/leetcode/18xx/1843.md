[LeetCode 1843 题](https://leetcode.com/problems/suspicious-bank-accounts/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们识别月收入至少连续两个月超过预定限额的银行账户。 

我们有两张表：

 的`Accounts`表存储每个帐户允许的最大月收入。 每个账户都只有一个`max_income`价值。 

这`Transactions`表存储个人银行交易。 每笔交易都属于一个账户并具有：

 - 交易类型，
 - 金额，
 - 和时间戳。 

仅具有类型的交易`'Creditor'`算作收入。 交易类型`'Debtor'`代表提款，在计算收入时必须忽略。 

任务是计算每个月每个帐户的总存款金额。 然后，对于每个帐户，我们必须确定是否存在至少连续两个月：```
monthly_income > max_income
```如果存在连续几个月，则该帐户被视为可疑，应包含在结果中。 

结果可以按任何顺序返回。 

一个非常重要的细节是，月份必须按日历顺序连续，而不仅仅是数据集中的相邻行。 例如：

 - 五月和六月是连续的。 
- 六月和七月是连续的。 
- 五月和七月不连续，因为缺少六月。 

另一个重要的细节是平等并不重要。 条件明确规定收入必须超过限制，因此：```
monthly_income > max_income
```有效，同时：```
monthly_income == max_income
```不是。 

该问题本质上是 SQL 中的分组和序列检测问题。 我们首先按账户和月份汇总存款，然后识别连续违规月份的运行情况。 

一些重要的边缘情况包括：

 - 只有一个月违规的账户，这些账户并不可疑。 
- 违规月份由非违规月份分隔的账户。 
- 完全没有债权人交易的月份。 
- 月收入等于的账户`max_income`。 
- 同一个月内的多笔债权人交易，必须合计。 

由于输入是关系数据，因此预期的解决方案严重依赖于 SQL 聚合、联接和日期操作。 

## 方法

 ### 蛮力方法

 强力解决方案将独立处理每个帐户并逐月检查其所有交易。 

该方法的工作原理如下：

 1. 仅过滤`'Creditor'`交易。 
2. 交易分组依据`(account_id, year-month)`。 
3. 计算每个月的总收入。 
4. 比较每月收入`max_income`。 
5. 按时间顺序对每个帐户的月份进行排序。 
6. 检查每对相邻的月份以确定是否：

 - 均超出限制，
 - 并且月份是连续的。 

这种方法是正确的，因为它明确计算每个月的收入并直接检查可疑情况。 

然而，如果在 SQL 之外简单地实现，它可能会变得低效，因为：

 - 每个帐户可能需要重复扫描，
 - 按时间顺序比较需要排序，
 - 并且手动检查连续月份会带来额外的开销。 

在大型数据集中，逐个帐户地重复遍历交易记录会变得昂贵。 

### 最佳方法

 关键的观察是这个问题自然分解为两个 SQL 操作：

 1. 每月总收入。 
2. 检测连续违规月份。 

我们首先创建一个紧凑的月度汇总表，而不是重复处理交易。 此摘要中的每一行代表：```
(account_id, month, total_income)
```之后，我们只需要判断同一个账户的相邻两个月份是否连续并且都超过阈值即可。 

SQL 窗口函数或自连接使这一过程变得高效，因为它们允许我们直接将每个月与其相邻月份进行比较，而无需重复扫描整个数据集。 

因此最优解为：

 - 聚合一次，
 - 过滤一次，
 - 并执行有效的时间顺序比较。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(T log T) | O(T log T) | O(T)| 手动汇总并重复排序/检查月份 |
 | 最佳| O(T log T) | O(T log T) | O(T)| 汇总每月收入一次，然后使用 SQL 连接/窗口逻辑 |

 这里，`T`代表交易数量。 

## 算法演练

 ### 第 1 步：过滤债权人交易

 我们首先忽略所有`'Debtor'`交易，因为提款不会贡献收入。 

仅包含以下内容的行：```
type = 'Creditor'
```是相关的。 

这减少了不必要的处理并仅关注存款活动。 

### 第 2 步：按账户和月份划分的总收入

 对于每个帐户和每个月，我们计算：```
SUM(amount)
```我们分组依据：

 -`account_id`- 年月提取自`day`这将创建每月收入摘要。 

例如：

 | 帐户 ID | 月 | 收入 |
 | --- | --- | --- |
 | 3 | 2021 年 6 月 | 300100 |
 | 3 | 2021 年 7 月 | 64900 |

 这种转变很重要，因为可疑条件适用于每月级别，而不是交易级别。 

### 步骤 3：加入账户表

 接下来，我们将每个月的收入与相应的收入进行比较`max_income`。 

我们将每月汇总表加入`Accounts`使用：```
account_id
```然后我们只保留以下行：```
income > max_income
```这些是违规月份。 

### 步骤 4：检测连续月份

 现在我们必须判断一个账户是否连续两个月违规。 

对于每个违规月份，我们都会将其与同一帐户中的另一个违规月份进行比较，其中：```
month_difference = 1
```这可以使用以下方法完成：

 - 自加入，
 - 或窗口函数，例如`LAG`。 

自连接解决方​​案检查是否：```
TIMESTAMPDIFF(MONTH, prev_month, current_month) = 1
```如果属实，则该帐户可疑​​。 

### 步骤 5：返回不同的帐户 ID

 一个账户可能包含多个连续的违规月份对。 

我们返回不同的`account_id`值仅一次。 

### 为什么它有效

 该算法之所以有效，是因为它直接对可疑活动的定义进行建模。 

聚合步骤保证了每个月收入的计算正确。 过滤步骤保证只考虑超过阈值的月份。 最后，连续月份比较可确保仅返回具有相邻违规月份的账户。 

由于每个可疑账户必须包含至少一对连续违规月份，并且每一对都经过明确检查，因此该算法是正确的。 

## Python 解决方案

 虽然这是一个数据库问题，但Python中的等效逻辑有助于理清算法思维。```python
from collections import defaultdict
from typing import List

class Solution:
    def suspiciousBankAccounts(
        self,
        accounts: List[List[int]],
        transactions: List[List]
    ) -> List[int]:

        max_income = {}
        for account_id, income_limit in accounts:
            max_income[account_id] = income_limit

        monthly_income = defaultdict(int)

        for transaction_id, account_id, trans_type, amount, day in transactions:
            if trans_type != "Creditor":
                continue

            month_key = day[:7]
            monthly_income[(account_id, month_key)] += amount

        violating_months = defaultdict(list)

        for (account_id, month), income in monthly_income.items():
            if income > max_income[account_id]:
                violating_months[account_id].append(month)

        suspicious_accounts = []

        for account_id, months in violating_months.items():
            months.sort()

            for i in range(1, len(months)):
                prev_year, prev_month = map(int, months[i - 1].split("-"))
                curr_year, curr_month = map(int, months[i].split("-"))

                prev_total = prev_year * 12 + prev_month
                curr_total = curr_year * 12 + curr_month

                if curr_total - prev_total == 1:
                    suspicious_accounts.append(account_id)
                    break

        return suspicious_accounts
```该实现首先将每个帐户的最大收入限制存储在字典中以进行恒定时间查找。 

接下来，我们通过以下方式汇总所有债权人交易`(account_id, month)`。 使用日期字符串的前七个字符提取月份，生成`YYYY-MM`表示。 

计算每月总计后，我们仅保留收入超过允许最高限额的月份。 

对于每个帐户，违规月份按时间顺序排序。 然后我们将每个月转换为数字表示形式：```python
year * 12 + month
```这使得连续月份的检测变得简单，因为连续的日历月份完全不同`1`。 

一旦发现连续的一对，该帐户就会被标记为可疑。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
	"strings"
)

type Transaction struct {
	TransactionID int
	AccountID     int
	Type          string
	Amount        int
	Day           string
}

type Solution struct{}

func (s Solution) SuspiciousBankAccounts(
	accounts [][]int,
	transactions []Transaction,
) []int {

	maxIncome := make(map[int]int)

	for _, acc := range accounts {
		maxIncome[acc[0]] = acc[1]
	}

	monthlyIncome := make(map[[2]string]int)

	for _, t := range transactions {
		if t.Type != "Creditor" {
			continue
		}

		monthKey := t.Day[:7]

		key := [2]string{
			strconv.Itoa(t.AccountID),
			monthKey,
		}

		monthlyIncome[key] += t.Amount
	}

	violatingMonths := make(map[int][]string)

	for key, income := range monthlyIncome {
		accountID, _ := strconv.Atoi(key[0])
		month := key[1]

		if income > maxIncome[accountID] {
			violatingMonths[accountID] =
				append(violatingMonths[accountID], month)
		}
	}

	result := []int{}

	for accountID, months := range violatingMonths {
		sort.Strings(months)

		for i := 1; i < len(months); i++ {
			prev := convertMonth(months[i-1])
			curr := convertMonth(months[i])

			if curr-prev == 1 {
				result = append(result, accountID)
				break
			}
		}
	}

	return result
}

func convertMonth(month string) int {
	parts := strings.Split(month, "-")

	year, _ := strconv.Atoi(parts[0])
	mon, _ := strconv.Atoi(parts[1])

	return year*12 + mon
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个显着的区别是 Go 需要显式类型定义和手动字符串解析。 我们广泛使用地图：

 -`map[int]int`对于收入限制，
 -`map[[2]string]int`对于每月汇总，
 -`map[int][]string`对于违规月份。 

使用 Go 切片代替 Python 列表，并且`sort.Strings`处理时间顺序，因为`YYYY-MM`格式可按字典顺序排序。 

与Python不同，Go没有直接的元组字典键，因此使用固定大小的字符串数组作为复合映射键。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(T log T) | O(T log T) | 聚合呈线性，违规月份排序占主导地位 |

 该算法在构建每月收入总额的同时处理每笔交易一次。 

汇总后，对每个账户的违规月份进行排序。 在最坏的情况下，所有交易都属于唯一的月份，从而导致排序开销。 因此，整体复杂度变为`O(T log T)`。 

辅助空间使用来自存储每月聚合和违规月份列表。

 ## 边缘情况

 ### 月收入等于 max_venue

 当月收入完全符合允许的最大值时，就会出现一种微妙的边缘情况。 

这个问题要求收入超过门槛，而不仅仅是达到门槛。 粗心的实现使用：```
>=
```而不是：```
>
```会错误地将帐户标记为可疑。 

实现明确检查：```
income > max_income[account_id]
```它正确地处理了这种情况。 

### 违规之间缺失的月份

 当账户在不连续的两个月内超过阈值时，就会出现另一个重要的边缘情况。 

例如：```
January -> exceeds
February -> does not exceed
March -> exceeds
```简单地计算违规月份的简单实现会错误地将此帐户标记为可疑。 

该解决方案通过将月份转换为数字表示形式并确保差值完全相等来避免此错误`1`。 

### 同月多笔交易

 一个账户在一个月内可能包含许多存款交易。 

一个幼稚的实现可能会单独比较每个事务`max_income`，这是不正确的，因为该条件适用于月总收入。 

在执行比较之前，聚合步骤正确地对所有债权人交易进行求和。 无论当月发生多少笔交易，这都保证了准确的每月总计。
