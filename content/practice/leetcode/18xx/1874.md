[LeetCode 问题 1874](https://leetcode.com/problems/minimize-product-sum-of-two-arrays/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 该问题将两个数组的**乘积和**定义为相同索引处相应元素的乘积之和。 如果我们有数组`a`和`b`，则乘积和为：$$\sum_{i=0}^{n-1} a[i] \times b[i]$$我们有两个数组，`nums1`和`nums2`, 两者长度相同`n`。 我们只被允许重新安排`nums1`， 尽管`nums2`必须保持固定。 我们的目标是重新排序`nums1`使得最终的乘积之和尽可能小。 

关键的挑战是决定其中的哪些元素`nums1`应该与哪些元素配对`nums2`。 由于每个元素的贡献都是相乘的，不良的配对会大大增加总和。 

约束提供了有关问题大小的重要信息：

 -`1 <= n <= 10^5`-`1 <= nums1[i], nums2[i] <= 100`数组长度可能非常大，因此任何阶乘或二次解都是不可行的。 然而，这些值本身非常小，只能从`1`到`100`，这暗示计数技术也是可能的。 

一个重要的观察是，较大的数字通常应与较小的数字配对，以尽量减少总贡献。 大与大的搭配会产生不必要的大产品。 

一些边缘情况值得预先考虑：

 - 长度数组`1`，其中重排无关紧要。 
- 所有元素都相等的数组，每个排列给出相同的答案。 
- 数组已经以最佳或最悲观的方式排列。 
- 具有重复值的大型数组。 
- 一个数组包含非常大的值而另一个数组包含非常小的值的情况。 

该问题保证两个数组都非空且长度相等，因此我们不需要处理无效输入。 

## 方法

 ### 蛮力方法

 蛮力的想法是生成所有可能的排列`nums1`，计算每个排列的乘积和，并返回最小结果。 

这是有效的，因为尝试所有排列可以保证我们最终检查最佳排列。 

对于每个排列：

 1. 重新排列`nums1`2. 计算乘积和
 3. 跟踪迄今为止看到的最小结果

 问题在于排列的数量呈阶乘增长。 对于长度的数组`n`， 有`n!`可能的安排。 

即使对于相对较小的值，例如`n = 10`，这变得不切实际：$$10! = 3,628,800$$实际约束允许`n`最多`100000`，使得暴力破解完全不可能。 

### 最优贪心法

 关键的见解来自于理解乘法如何影响总和。 

假设我们有两个大数字配对在一起：$$10 \times 9 = 90$$相反，如果我们将大数与小数配对：$$10 \times 1 = 10$$总贡献变得更小。 

为了最小化总和，我们应该：

 - 将最小值配对`nums1`中的最大值`nums2`- 将其中的最大值配对`nums1`中的最小值`nums2`这是一种基于重排不等式的经典贪心策略。 

实现很简单：

 1. 排序`nums1`按升序排列
 2. 排序`nums2`按降序排列
 3. 对应元素相乘
 4. 对结果求和

 这保证了尽可能最小的乘积总和。

 ## 算法演练

 ### 最优贪心算法

 1. 排序`nums1`按升序排列。 

我们将最小值放在前面，因为我们希望它们与来自的最大值配对`nums2`。 
2. 排序`nums2`按降序排列。 

这可确保最大值首先出现并与中的最小值对齐`nums1`。 
3. 初始化变量`product_sum`到`0`。 

该变量累加总的最小乘积和。 
4. 同时迭代两个数组。 

对于每个索引`i`，计算：$$nums1[i] \times nums2[i]$$将此值添加到`product_sum`。 
5. 返回`product_sum`。 

处理完每一对后，累加值就是最小可能的乘积和。 

### 为什么它有效

 正确性来自重排不等式。 当一个序列按升序排序而另一个序列按降序排序时，大值始终与小值配对。 这最小化了每次乘法的贡献，从而最小化了总和。 

如果将两个大数字配对在一起，它们的乘积将不必要地增加总数。 贪婪配对避免了全球范围内的这种情况，而不仅仅是局部的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minProductSum(self, nums1: List[int], nums2: List[int]) -> int:
        nums1.sort()
        nums2.sort(reverse=True)

        product_sum = 0

        for i in range(len(nums1)):
            product_sum += nums1[i] * nums2[i]

        return product_sum
```实现从排序开始`nums1`按升序排列并且`nums2`按降序排列。 这直接应用了前面讨论的贪心策略。 

变量`product_sum`存储运行总计。 然后我们使用两个数组的索引来迭代它们。 在每一步中，我们将相应的元素相乘并将结果添加到总数中。 

最后，我们返回累计的总和。 

代码很简洁，因为 Python 的内置排序实用程序可以有效地处理排序。 

## 解决方案```go
package main

import "sort"

func minProductSum(nums1 []int, nums2 []int) int {
	sort.Ints(nums1)

	sort.Slice(nums2, func(i, j int) bool {
		return nums2[i] > nums2[j]
	})

	productSum := 0

	for i := 0; i < len(nums1); i++ {
		productSum += nums1[i] * nums2[i]
	}

	return productSum
}
```Go 实现遵循与 Python 版本相同的算法结构。`sort.Ints`用于排序`nums1`按升序排列。 对于降序，Go 需要一个自定义比较器`sort.Slice`。 

实现的其余部分使用标准循环来计算总乘积和。 

Go 切片自然地处理动态数组行为，因此不需要对空数组进行特殊处理，因为该问题保证了有效的输入大小。 

在给定的约束下，整数溢出不是问题。 最大可能的总和是：$$100 \times 100 \times 100000 = 10^9$$可以安全地放入 Go 中`int`在标准 64 位系统上键入。

 ## 边缘情况

 一种重要的边缘情况是数组仅包含一个元素。 在这种情况下，不可能进行重新排列，因为只有一个配对。 粗心的实现可能仍会尝试不必要的排序或索引逻辑，但提供的解决方案可以自然地处理此问题，因为对单元素数组进行排序是有效的，并且循环只执行一次。 

当所有值都相同时，会出现另一个重要情况。 例如：```
nums1 = [5,5,5]
nums2 = [5,5,5]
```每种可能的排列都会产生相同的结果。 一些算法错误地假设重新排列总是会改变结果，但贪婪方法仍然可以正确工作，因为排序保留了值并且最终的总和保持不变。 

第三个重要的边缘情况涉及高度不平衡的值，例如：```
nums1 = [1,100]
nums2 = [1,100]
```按原始顺序对元素进行配对的简单实现会产生：$$1 \times 1 + 100 \times 100 = 10001$$最佳安排反而会产生：$$1 \times 100 + 100 \times 1 = 200$$这说明了为什么相反方向排序至关重要。 该实现通过对一个数组升序排序和另一个数组降序排序来明确保证这种配对策略。 

另一个微妙的边缘情况是输入大小很大并且有很多重复项。 自从`n`可以达到`100000`，低效的方法变得不可行。 基于排序的解决方案对于约束仍然足够高效，并且可以自然地处理重复值，而无需任何额外的逻辑。
