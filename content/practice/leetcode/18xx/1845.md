[LeetCode 问题 1845](https://leetcode.com/problems/seat-reservation-manager/)

 **难度：** 🟡 中等
 **主题：** 设计、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题需要设计一个系统来管理座位预订`n`座位号从`1`到`n`。 你需要实施一个`SeatManager`类有两个主要操作：`reserve`和`unreserve`。 这`reserve`操作必须始终分配**编号最小的可用座位**，而`unreserve`释放之前保留的座位，使其再次可用。 

初始化的输入是一个整数`n`，指定座位总数。 致电`reserve`返回一个整数，表示分配的座位号。 致电`unreserve`将座位号作为输入并释放该座位。 约束保证每个`reserve`呼叫将找到至少一个可用座位，并且每个`unreserve`呼叫将引用当前预订的座位。 

关键考虑因素包括有效跟踪**最低的可用座位**并处理最多`10^5`运营。 简单的方法，例如扫描所有座位以了解每个座位的空位情况`reserve`会太慢。 该问题保证了有效的输入，因此我们不需要处理无效的座位号或过度预订。 

需要考虑的重要边缘情况是所有座位均已预订、预订后座位立即取消预订以及仅剩一个座位可用。 

## 方法

 强力方法是维护一个表示座位可用性的数组或列表。 为了`reserve`，迭代列表以找到第一个未保留的座位并将其标记为保留。 为了`unreserve`，将座位标记为可用。 虽然正确，但这种方法的时间复杂度为 O(n)`reserve`，这对于`n`操作次数最多为`10^5`。 

最佳解决方案的关键是使用**最小堆（优先级队列）**。 通过将所有未预订的座位保留在最小堆中，`reserve`可以在 O(log n) 时间内弹出最小的座位，并且`unreserve`可以在 O(log n) 时间内将一个席位推回堆中。 这确保我们始终有效地获得最少数量的可用座位。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个保留的 O(n) | O(n) | 扫描座位阵列以找到最小的可用座位 |
 | 最佳| 每次保留/取消保留 O(log n) | O(n) | 使用最小堆有效跟踪可用座位 |

 ## 算法演练

 1. 用所有座位号初始化一个最小堆`1`到`n`。 这代表最初可用的所有座位。 
2. 什么时候`reserve`被调用时，从堆中弹出最小的座位号并将其返回。 这保证了分配最小的可用座位。 
3. 什么时候`unreserve`被称为`seatNumber`，将座位推回到最小堆中。 这会将其恢复为未来可用的座位`reserve`运营。 
4. 堆的性质保证了最小的元素总是在顶部，所以`reserve`操作总是能有效地找回正确的座位。 

**工作原理：** 堆不变量保证编号最小的可用座位始终可以作为根在 O(1) 内访问，并且压入/弹出操作保持堆属性。 这保证了正确性和效率。 

## Python 解决方案```python
import heapq

class SeatManager:

    def __init__(self, n: int):
        self.available_seats = list(range(1, n + 1))
        heapq.heapify(self.available_seats)

    def reserve(self) -> int:
        return heapq.heappop(self.available_seats)

    def unreserve(self, seatNumber: int) -> None:
        heapq.heappush(self.available_seats, seatNumber)
```在 Python 实现中，`__init__`方法创建所有座位号的最小堆。`reserve`弹出最小的元素，并且`unreserve`将座位号推后。 这`heapq`模块自动维护堆属性。 

## 解决方案```go
package main

import (
	"container/heap"
)

type SeatManager struct {
	minHeap *IntHeap
}

func Constructor(n int) SeatManager {
	h := &IntHeap{}
	for i := 1; i <= n; i++ {
		*h = append(*h, i)
	}
	heap.Init(h)
	return SeatManager{minHeap: h}
}

func (this *SeatManager) Reserve() int {
	return heap.Pop(this.minHeap).(int)
}

func (this *SeatManager) Unreserve(seatNumber int) {
	heap.Push(this.minHeap, seatNumber)
}

// IntHeap implements heap.Interface
type IntHeap []int

func (h IntHeap) Len() int            { return len(h) }
func (h IntHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h IntHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *IntHeap) Push(x any)         { *h = append(*h, x.(int)) }
func (h *IntHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}
```Go 解决方案使用`container/heap`并定义一个自定义`IntHeap`类型。`Reserve`弹出最小的座位，并且`Unreserve`把它推回来。 主要区别在于 Go 中需要显式定义堆接口。

 ## 边缘情况

 一种边缘情况是所有座位都已预订，然后立即取消预订。 该堆确保未预留的座位重新插入并立即可供使用`reserve`。 

另一个边缘情况是`n = 1`。 该算法仍必须正确保留和取消保留唯一的座位。 堆操作可以简单地处理这个问题。 

第三种边缘情况是无序执行多个取消预订操作，例如取消预订 5 个席位，然后取消预订 3 个席位，然后取消预订 2 个席位。最小堆确保`reserve`无论取消预订的顺序如何，始终选择最小的可用号码。 这可以防止基于简单数组的方法中可能出现的错误。
