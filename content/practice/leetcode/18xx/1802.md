 # LeetCode 1802，有界数组中给定索引处的最大值

 ## 问题理解

 这道题要求我们构造一个长度的数组`n`其中每个元素都是正整数，相邻元素之间的差异最多为`1`，并且数组的总和不超过`maxSum`。 

在所有有效数组中，我们希望最大化特定位置的值，`index`。 

邻接约束尤其重要：```
abs(nums[i] - nums[i+1]) <= 1
```这意味着相邻位置之间的值不能急剧跳跃。 如果一个元素很大，那么附近的元素也一定也相对较大。 例如，如果`nums[index] = 5`，那么相邻值只能是`4`,`5`， 或者`6`。 由于我们希望总和尽可能小，同时保持峰值较高，因此最佳结构自然形成一个以`index`。 

输入包括：

 -`n`，数组的长度
 -`index`，我们想要最大化的位置
 -`maxSum`，总数组和的上限

 输出是一个整数：

 - 最大可能值`nums[index]`限制条件非常大：```
1 <= n <= maxSum <= 10^9
```这立即告诉我们，显式构造数组或使用基于模拟的方法会太慢。 任何比对数或接近对数时间更差的解决方案都不太可能通过。 

有几个重要的边缘情况需要记住。 

如果`n = 1`，那么整个数组只包含一个值，所以答案很简单`maxSum`。 

如果`index = 0`或者`index = n - 1`，则金字塔仅向一个方向延伸。 对于这些边界位置，逻辑仍然必须正确工作。 

当递减序列达到`1`在覆盖所有位置之前。 由于每个元素都必须保持正数，因此剩余位置必须填充`1`s 而不是继续向下直至零或负值。 

最后，由于总和可能变得非常大，因此整数溢出是 Go 等语言中的一个问题。 我们在计算时必须使用 64 位整数。 

## 方法

 ### 蛮力方法

 蛮力策略会尝试所有可能的值`nums[index]`并判断是否可以在总和限制内构造出有效的数组。 

对于候选值`x`，我们可以显式构建以`index`：

 - 开始于`x`在`index`- 减少`1`向外移动
 - 停止减少`1`- 填充剩余位置`1`然后计算总和并检查是否超过`maxSum`。 

这种方法是正确的，因为固定峰值的最小有效数组总是使用尽可能陡峭的下降`1`。 任何较大的相邻值只会不必要地增加总和。 

然而，如果简单地实现的话，这种方法就太慢了。 候选值可能大到`10^9`，并且重复构造数组每次都需要线性工作。 

### 关键见解

 关键的观察是，如果一个值`x`是可行的`index`，那么每个较小的值也是可行的。 

这创建了一个单调条件：```
If x works, then all values <= x also work.
```每当问题具有单调可行性属性时，二分搜索就成为强有力的候选者。 

下一个见解是我们不需要显式构建数组。 我们只需要计算所选峰值所需的最小可能总和。 

最佳阵列形状形成从峰值向左和向右延伸的两个算术序列。 使用算术级数公式，我们可以在常数时间内计算所需的总和。 

这将解决方案简化为：

 1.二分查找答案
 2. 高效计算候选峰值是否符合`maxSum`## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × 最大和) | O(n) | 为每个候选值显式构造数组 |
 | 最佳 | O(log 最大和) | O(1) | O(1) | 使用二分查找和算术级数公式 |

 ## 算法演练

 1. 观察固定峰值`x`，最小有效数组通过减少获得`1`当我们远离`index`。 
2. 对于峰的左侧，计算所需的最小总和`index`职位。 

如果峰值足够大，我们可以形成一个完整的下降序列：```
x-1, x-2, x-3, ...
```否则，序列达到`1`早到了，剩下的位置都被填满了`1`s。 
3. 对右侧进行同样的计算，其中包含`n - index - 1`职位。 
4.添加：

 - 峰值`x`- 左侧贡献
 - 右侧贡献

 这给出了峰值的最小可能总和`x`。 
5. 将所需金额与`maxSum`。 

- 如果总和在限制范围内，则`x`是可行的。 
- 否则，`x`太大了。 
6. 由于可行性是单调的，因此在范围内应用二分搜索：```
[1, maxSum]
```7. 二分查找时：

 - 如果`mid`可行，将其存储为候选答案并进行更高的搜索。 
- 否则，向下搜索。 
8. 继续，直到搜索间隔用完。 
9. 返回找到的最大可行值。 

### 为什么它有效

 对于任何固定峰值，最小可能的有效数组是通过在允许的范围内积极向外减少值来唯一确定的。 任何其他安排都会增加总和，同时保持相同的峰值。 

由于可行性单调取决于峰值，因此二分搜索可以正确找到最大可行值。 

算术级数公式计算出精确的最小所需总和，因此每次可行性检查都是准确的。 

## Python 解决方案```python
class Solution:
    def maxValue(self, n: int, index: int, maxSum: int) -> int:
        
        def side_sum(peak: int, length: int) -> int:
            if peak > length:
                smallest = peak - length
                return (peak - 1 + smallest) * length // 2
            else:
                descending_sum = (peak - 1 + 1) * (peak - 1) // 2
                ones_needed = length - (peak - 1)
                return descending_sum + ones_needed
        
        def can_build(value: int) -> bool:
            total = value
            
            total += side_sum(value, index)
            total += side_sum(value, n - index - 1)
            
            return total <= maxSum
        
        left = 1
        right = maxSum
        answer = 1
        
        while left <= right:
            mid = (left + right) // 2
            
            if can_build(mid):
                answer = mid
                left = mid + 1
            else:
                right = mid - 1
        
        return answer
```实现从辅助函数开始`side_sum`，它计算峰值一侧所需的最小总和。 

参数`peak`代表值`nums[index]`， 尽管`length`代表该侧存在多少个位置。 

有两种情况。 

如果递减序列没有达到`1`，则边构成完整的等差数列。 该代码使用算术级数公式直接计算总和。 

如果序列达到`1`在覆盖所有位置之前，然后将剩余位置填充为`1`s。 该代码单独计算下降部分并添加额外的部分。 

这`can_build`函数计算候选峰值所需的最小总和。 它包括：

 - 峰本身
 - 左侧贡献
 - 右侧贡献

 如果这个总数在`maxSum`，候选值是可行的。 

主要算法对可能的峰值执行二分搜索。 每当候选者起作用时，算法就会尝试更大的值。 否则，它会缩小搜索范围。 

由于每次可行性检查都以恒定的时间运行，因此整个解决方案非常高效。 

## 解决方案```go
func maxValue(n int, index int, maxSum int) int {
    
    sideSum := func(peak int64, length int64) int64 {
        if peak > length {
            smallest := peak - length
            return (peak - 1 + smallest) * length / 2
        }
        
        descendingSum := (peak - 1 + 1) * (peak - 1) / 2
        onesNeeded := length - (peak - 1)
        
        return descendingSum + onesNeeded
    }
    
    canBuild := func(value int64) bool {
        total := value
        
        total += sideSum(value, int64(index))
        total += sideSum(value, int64(n-index-1))
        
        return total <= int64(maxSum)
    }
    
    left := int64(1)
    right := int64(maxSum)
    answer := int64(1)
    
    for left <= right {
        mid := (left + right) / 2
        
        if canBuild(mid) {
            answer = mid
            left = mid + 1
        } else {
            right = mid - 1
        }
    }
    
    return int(answer)
}
```Go 实现遵循与 Python 版本相同的逻辑，但有一个重要的区别。 

所有算术用途`int64`而不是`int`因为总和可能超出 32 位整数的范围。 如果没有这种转换，溢出可能会对大输入产生不正确的结果。 

除了显式的整数类型处理之外，算法结构保持相同。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n = 1`。 在这种情况下，数组仅包含一个元素，因此无需担心邻接约束。 答案很简单`maxSum`。 该实现自然地处理了这个问题，因为边长变为零，并且二分搜索正确地扩展到最大可行值。 

当递减序列达到`1`在覆盖所有位置之前。 例如，如果峰值是`3`但一侧有长度`10`，序列变为：```
2, 1, 1, 1, 1, ...
```有缺陷的实现可能会错误地继续减少到零或负值。 辅助函数通过将降序算术序列与剩余的序列分开来显式处理此问题`1`s。 

边界索引也是容易出错的来源。 如果`index = 0`或者`index = n - 1`，金字塔的一侧长度为零。 在这些情况下，某些实现会意外地重复计数或访问无效位置。 此解决方案避免了这些问题，因为辅助函数可以安全地处理零边长并返回零贡献。
