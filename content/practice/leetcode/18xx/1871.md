[LeetCode 1871 题](https://leetcode.com/problems/jump-game-vii/)

 **难度：** 🟡 中等
 **主题：** 字符串、动态规划、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`，其中每个字符是`'0'`或者`'1'`。 我们从索引开始`0`，并且该问题保证`s[0] == '0'`，意味着起始位置始终有效。 

从任意索引`i`，我们可以跳转到另一个索引`j`如果两个条件成立：

 1、跳跃距离在允许范围内：`i + minJump <= j <= i + maxJump`2. 目标位置必须包含`'0'`。 

目标是确定是否有可能最终到达字符串的最后一个索引。 

换句话说，我们在字符串中导航，同时只登陆包含以下内容的位置：`'0'`，并且每次跳跃长度必须保持在包含区间内`[minJump, maxJump]`。 

约束条件极其重要：

 -`s.length`可以大到`10^5`- 检查每个索引的每个可能的跳跃的简单图遍历可能会变成二次方
 - 安`O(n^2)`解决方案将超时

 这意味着我们需要一种能够有效处理字符串的算法，最好是在线性时间内。 

一些重要的观察立即浮现出来：

 - 我们永远不需要登陆包含以下内容的索引`'1'`- Reachability matters more than the exact path
 - 对于每一个位置，我们需要知道是否存在至少一个先前可达的索引可以跳转到该位置
 - 重复扫描大范围的成本太高

 几种边缘情况很容易破坏简单的实现：

 - The last index may contain`'1'`，自动做出答案`false`- 跳跃范围过大可能会导致重复冗余扫描
 - 某些指数在技术上可能在范围内，但本身无法达到
 - 连续`'1'`块可以完全隔离字符串的各个部分
 - 非常小的字符串可能会暴露相差一的错误

 该问题保证：

 - 字符串长度至少为`2`-`minJump <= maxJump`- 起始索引始终有效

 这些保证简化了初始化逻辑。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将问题建模为图遍历问题。 

每个索引代表一个节点。 来自索引`i`，我们尝试每一个可能的跳跃长度`minJump`和`maxJump`。 如果目标索引包含`'0'`，我们从那里递归或迭代地继续探索。 

这可以使用 DFS 或 BFS 来实现。 

该方法是正确的，因为它探索了每个可到达的位置并检查最终索引是否可以访问。 

然而，性能较差。 

对于每个索引，我们最多可以检查`maxJump - minJump + 1`目的地。 在最坏的情况下，这大约变成`O(n)`每个索引的工作量，产生的总体复杂度为`O(n^2)`。 

和`n = 100000`，二次行为太慢了。 

### 最佳解决方案的关键见解

 暴力解决方案的昂贵部分是重复扫描重叠的跳跃范围。 

假设我们要判断索引是否`i`是可达的。 

我们不需要单独检查每个早期索引，我们只需要知道这一点：

 > 有效跳转窗口内是否存在至少一个可达索引`i`？ 

对于索引`i`，之前有效的索引为：```
[i - maxJump, i - minJump]
```如果在这个区间内存在任何可达位置，那么`i`是可达的，前提是`s[i] == '0'`。 

这成为一个经典的滑动窗口问题。 

我们维护有效范围内当前存在的可达索引数量的运行计数。 当我们从左向右移动字符串时：

 - 我们添加进入窗口的索引
 - 我们删除离开窗口的索引
 - 我们检查计数是否为正

 这避免了重复地重新扫描相同的范围。 

结果是线性时间解。

 ## 算法演练

 ### 第 1 步：创建 DP 阵列

 我们创建一个布尔数组`reachable`尺寸的`n`。`reachable[i]`方法：```
Can we reach index i?
```初始化：

 -`reachable[0] = True`- 所有其他位置开始为`False`我们知道索引`0`is reachable because that is the starting position.

 ### 步骤 2：维护滑动窗口计数

 我们维护一个名为的整型变量`window_reachable`。 

这家店：```
How many reachable indices currently exist inside the valid jump window?
```对于每个位置`i`，之前有效的索引为：```
[i - maxJump, i - minJump]
```我们不是每次都重新扫描这个范围，而是增量更新计数。 

### 步骤 3：展开窗口

 当我们从左到右迭代时：

 当索引`i - minJump`生效后，进入窗口。 

如果该索引可达，我们就递增`window_reachable`。```
if reachable[i - minJump]:
    window_reachable += 1
```这意味着未来的头寸可能会从此跳升。 

### 步骤 4：缩小窗口

 当索引`i - maxJump - 1`超出范围，它离开窗口。 

如果该索引可达，我们就会减少计数。```
if reachable[i - maxJump - 1]:
    window_reachable -= 1
```这可以保持窗口准确。 

### 步骤 5：确定可达性

 现在我们检查当前索引`i`。 

如果满足以下条件，则可以到达：

 1.`s[i] == '0'`2. 窗口中至少存在一个可达索引

 第二个条件变为：```
window_reachable > 0
```所以：```
reachable[i] = (s[i] == '0' and window_reachable > 0)
```###第6步：返回最终结果

 最后返回：```
reachable[n - 1]
```这告诉我们是否可以到达最后一个索引。 

### 为什么它有效

 该算法保持不变式`window_reachable`始终等于当前位置的有效跳转间隔内可达索引的数量。 

对于每个索引`i`，到达它的唯一方法是从内部先前可到达的索引：```
[i - maxJump, i - minJump]
```The sliding window ensures we always know whether such an index exists in constant time. Since every index is processed exactly once, the algorithm correctly computes reachability for the entire string.

 ## Python 解决方案```python
class Solution:
    def canReach(self, s: str, minJump: int, maxJump: int) -> bool:
        n = len(s)

        reachable = [False] * n
        reachable[0] = True

        window_reachable = 0

        for i in range(1, n):
            enter_index = i - minJump
            if enter_index >= 0 and reachable[enter_index]:
                window_reachable += 1

            leave_index = i - maxJump - 1
            if leave_index >= 0 and reachable[leave_index]:
                window_reachable -= 1

            reachable[i] = (
                s[i] == '0' and window_reachable > 0
            )

        return reachable[-1]
```其实现直接遵循滑动窗口动态规划策略。 

这`reachable`数组存储每个位置是否可以访问。 最初，只有索引`0`是可达的。 

变量`window_reachable`跟踪当前位置的有效跳转间隔内当前存在多少个可达索引。 

对于每个索引：

 -`enter_index`是进入滑动窗口的新索引
 -`leave_index`旧索引是否离开窗口

 每当可到达的索引进入窗口时，计数就会增加。 每当有人离开时，计数就会减少。 

更新窗口后，如果满足以下条件，则当前位置可到达：

 - 角色是`'0'`- 当前有效范围内至少存在一个可达索引

 最后，算法返回最终索引是否可达。 

## 解决方案```go
func canReach(s string, minJump int, maxJump int) bool {
    n := len(s)

    reachable := make([]bool, n)
    reachable[0] = true

    windowReachable := 0

    for i := 1; i < n; i++ {
        enterIndex := i - minJump
        if enterIndex >= 0 && reachable[enterIndex] {
            windowReachable++
        }

        leaveIndex := i - maxJump - 1
        if leaveIndex >= 0 && reachable[leaveIndex] {
            windowReachable--
        }

        reachable[i] = s[i] == '0' && windowReachable > 0
    }

    return reachable[n-1]
}
```Go 实现与 Python 版本几乎相同。 

使用布尔切片而不是 Python 列表。 Go 字符串可以按字节索引，因此检查`s[i] == '0'`直接工作，因为字符串仅包含 ASCII 字符。 

不需要特殊的溢出处理，因为所有索引都保持在给定约束的标准整数范围内。

 ## 边缘情况

 当最终索引包含时，会出现一种重要的边缘情况`'1'`。 即使每个较早的位置都可以到达，但最后一个位置也无法着陆，因为只允许跳跃到`'0'`细胞。 该实现自然地处理了这个问题，因为`reachable[i]`仅设置为`True`什么时候`s[i] == '0'`。 

另一个微妙的情况涉及大面积的`'1'`断开图形的字符。 幼稚的实现可能会反复重新扫描这些区域，从而导致严重的性能下降。 滑动窗口方法完全避免了这个问题，因为它只跟踪有效区间内可达索引的计数。 

第三个重要的边缘情况发生在以下情况：`minJump == maxJump`。 在这种情况下，每一步都必须恰好使用一个跳跃长度。 许多实现意外地假设一系列可能性始终存在。 滑动窗口仍然可以正常工作，因为窗口只是折叠成大小为 1 的固定宽度间隔。 

最后一个棘手的情况涉及早期索引，其中滑动窗口边界变为负值。 如果没有仔细的边界检查，实现可能会意外访问无效索引。 该解决方案明确检查`>= 0`使用前`enterIndex`或者`leaveIndex`，防止超出范围的访问错误。
