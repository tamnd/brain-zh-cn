[LeetCode 问题 1829](https://leetcode.com/problems/maximum-xor-for-each-query/)

 **难度：** 🟡 中等
 **主题：** 数组、位操作、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个排序数组`nums`和一个整数`maximumBit`。 对于每个查询，我们必须选择一个数字`k`这样：

 -`0 <= k < 2^maximumBit`- 价值：```
nums[0] XOR nums[1] XOR ... XOR nums[last] XOR k
```尽可能大。 

回答查询后，我们从数组中删除最后一个元素并重复该过程，直到数组变空。 

重要的细节是每个查询的答案取决于所有当前剩余元素的异或。 由于每次查询后数组都会从末尾收缩，因此我们会重复计算数组中逐渐变小的前缀的答案。 

输出是一个数组，其中：

 -`answer[0]`对应于完整数组
 -`answer[1]`对应删除一次最后一个元素后的数组
 - 等等

 约束条件很重要：

 -`n`可以大到`10^5`-`maximumBit`可以达到`20`二次解决方案太慢，因为为每个查询重复重新计算 XOR 需要太多操作。 

另一个重要的观察是，中的每个数字`nums`保证小于`2^maximumBit`。 这意味着每个相关值都完全符合`maximumBit`位。 

尽管问题指出数组已排序，但排序属性实际上与解决问题无关。 XOR 运算不依赖于顺序。 

早期值得注意的几个边缘情况：

 - 单元素数组
 - 所有元素均为零的数组
 - 最大可能的位大小
 - XOR 已经等于最大可能值的情况
 - 重复值，因为 XOR 取消了相同的对

 了解 XOR 的行为方式是有效解决此问题的关键。 

## 方法

 ### 蛮力方法

 一个简单的解决方案将独立处理每个查询。 

对于每个查询：

 1. 计算所有当前元素的异或。 
2. 尝试每一个可能的值`k`从`0`到`2^maximumBit - 1`。 
3. 计算：```
currentXor XOR k
```1. 选择`k`产生最大值。 
2. 删除最后一个元素并继续。 

这种方法是正确的，因为它明确地检查每个有效的候选者`k`。 

然而，它的效率极低。 

如果有`n`查询并且每个查询尝试最多`2^maximumBit`可能的值，复杂性变得巨大。 自从`maximumBit`可以是`20`，我们可能需要为每个查询测试超过一百万个候选者。 

这对于`n = 10^5`。 

### 关键见解

 最大化：```
currentXor XOR k
```我们希望结果中的每一位都变成`1`。 

可以表示的最大数`maximumBit`位是：```
(1 << maximumBit) - 1
```例如：

-`maximumBit = 2`→ 最大值为`3`→ 二进制`11`-`maximumBit = 3`→ 最大值为`7`→ 二进制`111`认为：```
mask = (1 << maximumBit) - 1
```那么最好的可能`k`是：```
k = currentXor XOR mask
```为什么？ 

因为 XOR 会翻转位：

 - 如果有点`currentXor`是`0`，我们想要`k`做出贡献`1`- 如果有点`currentXor`是`1`，我们想要`k`做出贡献`0`这保证：```
currentXor XOR k = mask
```这是最大可能值。 

我们还避免每次从头开始重新计算异或。 

如果：```
currentXor = XOR of all current elements
```然后删除最后一个元素后`x`:```
newXor = currentXor XOR x
```因为异或是可逆的。 

这给了我们一个线性时间的解决方案。

 ## 算法演练

 1. 计算中所有元素的异或`nums`。 

这表示第一个查询的 XOR 值，因为第一个查询使用完整数组。 
2. 创建一个包含所有内容的掩码`maximumBit`位设置为`1`。 

公式为：```
mask = (1 << maximumBit) - 1
```例如：

-`maximumBit = 2`→`11`以二进制形式
 -`maximumBit = 3`→`111`以二进制形式
 3. 初始化一个空结果数组。 

我们将按查询顺序附加答案。 
4. 对于每个查询：

 - 计算：```
k = currentXor XOR mask
```- 追加`k`到结果。 

这是有效的，因为与掩码的异或恰好翻转了产生最大可能值所需的位。 
5. 逻辑删除最后一个元素。 

不修改数组，而是更新正在运行的 XOR：```
currentXor ^= nums[lastIndex]
```再次与相同的数字进行异或可消除其贡献。 
6. 继续，直到处理完所有元素。 
7. 返回结果数组。 

### 为什么它有效

 该算法依赖于这样一个事实，即使用可表示的最大值`maximumBit`位是一个数字，其中所有这些位都是`1`。 

对于每个查询，我们选择`k`以便：```
currentXor XOR k = mask
```由于XOR可以独立控制每一位，因此选择：```
k = currentXor XOR mask
```保证结果等于最大可能值。 

运行的 XOR 更新也是正确的，因为 XOR 是自逆的：```
a XOR b XOR b = a
```因此，从累积异或中删除一个元素只需要另一次异或运算。 

## Python 解决方案```python
from typing import List

class Solution:
    def getMaximumXor(self, nums: List[int], maximumBit: int) -> List[int]:
        current_xor = 0

        for num in nums:
            current_xor ^= num

        mask = (1 << maximumBit) - 1

        answer = []

        for i in range(len(nums) - 1, -1, -1):
            best_k = current_xor ^ mask
            answer.append(best_k)

            current_xor ^= nums[i]

        return answer
```实现首先计算整个数组的异或。 该值表示第一个查询的 XOR。 

接下来，代码创建位掩码：```python
mask = (1 << maximumBit) - 1
```该掩码表示允许位范围内可能的最大值。 

该循环向后迭代数组，因为每个查询都会删除最后一个剩余元素。 

对于每次迭代：```python
best_k = current_xor ^ mask
```计算最优值`k`。 

存储答案后，代码删除当前最后一个元素的贡献：```python
current_xor ^= nums[i]
```这可以有效地为下一个查询准备 XOR，而无需从头开始重新计算。 

最后返回完整的答案数组。 

## 解决方案```go
func getMaximumXor(nums []int, maximumBit int) []int {
	currentXor := 0

	for _, num := range nums {
		currentXor ^= num
	}

	mask := (1 << maximumBit) - 1

	answer := make([]int, 0, len(nums))

	for i := len(nums) - 1; i >= 0; i-- {
		bestK := currentXor ^ mask
		answer = append(answer, bestK)

		currentXor ^= nums[i]
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

创建的切片的预分配容量等于`len(nums)`为了效率：```go
answer := make([]int, 0, len(nums))
```Go 整数可以安全地处理约束范围，因为`maximumBit <= 20`，因此所有值仍然很小。 

对于空数组不需要特殊处理，因为约束保证至少有一个元素。

 ## 边缘情况

 单元素数组是一种重要的边缘情况，因为只有一个查询。 有缺陷的实现可能会在计算答案之前错误地尝试删除元素，或者在向后迭代时错误处理索引。 该解决方案自然地处理了这个问题，因为循环首先计算答案，然后才从运行的 XOR 中删除该元素。 

包含许多零的数组是另一个重要的情况。 由于与零的异或不会改变任何内容，因此累积异或可能在多个查询中保持不变。 某些实现错误地假设 XOR 值在删除元素后始终会发生变化。 此实现使用 XOR 属性正确更新，因此会自动处理零值。 

重复的值也会产生微妙的错误，因为 XOR 会取消相同的对：```
x XOR x = 0
```例如，像这样的数组`[1,1,1,1]`当元素被移除时产生交替的 XOR 状态。 该算法正确地增量地维护正在运行的 XOR，因此无需任何特殊逻辑即可处理取消效果。 

最大位边界是另一个重要的考虑因素。 什么时候`maximumBit = 20`，掩码变为：```
(1 << 20) - 1
```该实现可以在 Python 和 Go 中安全地计算该值，而不会出现溢出问题，因为所有值都保持在标准整数限制内。
