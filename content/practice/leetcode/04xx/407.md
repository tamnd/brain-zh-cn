 # LeetCode 407 - 捕获雨水 II

 ## 问题理解

 该问题是经典“捕获雨水”问题的二维版本。 我们给出的不是一维高度数组，而是`m x n`网格，其中每个单元格代表地形中某个块的海拔。 

目标是确定降雨后仍有多少水被困住。 

每个单元格都有一个高度，只有当它被更高的边界包围时，水才能被困住。 如果存在从细胞到外部边界的任何路径，通过较低或相同的高度，水可以逸出并且不会被困在那里。 

输入是：

 -`heightMap[i][j]`，行中单元格的高度`i`和列`j`-`m`行和`n`列

 输出是一个整数，表示截留水的总量。 

约束条件很重要：

 -`1 <= m, n <= 200`- 高度可以大到`2 * 10^4`尺寸网格`200 x 200`包含多达`40,000`细胞。 任何比粗略更糟糕的解决方案`O(m * n * log(m * n))`存在超时风险。 这立即排除了许多天真的重复模拟方法。 

有几个重要的观察结果和边缘情况：

 - 边界单元永远无法捕获水，因为水总是可以从边界流出地图。 
- 非常小的网格，例如`1 x n`,`m x 1`，甚至`2 x 2`，不能存水，因为没有封闭的内部区域。 
- 单元中的水位不仅取决于其直接邻居，还取决于整个连接区域周围的最小边界。 
- 如果存在通过较低的墙到达边界的另一条路径，则局部较高的墙不能保证截留水。 

主要挑战是有效确定每个内部单元的有效边界高度。 

## 方法

 ### 蛮力方法

 强力解决方案将独立检查每个内部单元。 

对于每个单元格，我们可以尝试确定可以保持在那里而不泄漏到边界的最高水位。 思考这个问题的一种方法是：

 - 从当前单元格开始。 
- 向各个方向向外探索。 
- 确定单元周围的最小边界高度。 
- 截留的水等于：$$\text{boundary height} - \text{cell height}$$如果是积极的。 

然而，这很困难，因为周围的边界是全局的，而不是局部的。 为了正确确定水是否逃逸，我们实际上需要从每个单元格到边界进行搜索。 

如果我们对每个单元执行 BFS 或 DFS，复杂度就会变得非常大：

 - 最多`40,000`细胞
 - 每次搜索可能访问大部分网格

 这大约产生`O((m * n)^2)`复杂性，速度太慢。 

尽管暴力破解的想法在概念上是正确的，但它会重复重新计算相同的信息。 

### 最优方法，最小堆 + BFS

 关键的见解是，滞留的水是由区域周围的最低边界决定的。 

这与现实世界中水充满盆地的方式非常相似：

 - 水开始从最低边界泄漏。 
- 最小的围墙决定了最高水位。 

我们不是独立处理单元，而是从外向内处理地形。 

策略是：

 - 将所有边界单元插入最小堆。 
- 始终从当前最低边界扩展。 
- 访问相邻小区时：

 - 如果邻居低于当前边界高度，水就会被困住。 
- 否则，不会积水。 
- 然后邻居成为高度边界的一部分：$$\max(\text{current boundary height}, \text{neighbor height})$$这是有效的，因为一旦从最小可能边界到达细胞，我们就已经知道其周围可以容纳水的最小壁。 

这本质上是应用于水位的 Dijkstra 算法。 

## 方法比较

 ## 算法演练

 1.初始化尺寸并处理小网格。 

如果网格的行数或列数少于 3 行或列，则不会积聚水，因为没有封闭的内部区域。 
2. 创建一个访问矩阵。 

我们必须确保每个单元格只被处理一次。 如果没有这个，同一个单元格可能会被多次插入到堆中。 
3. 创建最小堆。 

堆以以下格式存储单元格：```
(height, row, column)
```堆总是为我们提供当前最低的边界单元。 
4. 将所有边界单元推入堆中。 

添加每个外部边界单元是因为边界定义了水可以逸出的位置。 

这些单元格也被标记为立即访问。 
5. 使用堆启动 BFS。 

反复从堆中弹出最小高度的单元格。 

该单元格表示当前扩展的最小边界高度。 
6. 探索四个相邻的单元格。 

对于每个邻居：

 - 越界则跳过
 - 如果已经访问过则跳过
 - 否则将其标记为已访问
 7. 计算滞留水。 

如果邻居的高度小于当前边界高度：$$\text{water trapped} = \text{boundary height} - \text{neighbor height}$$将此金额添加到答案中。 
8. 更新有效边界高度。 

邻居成为未来扩张边界的一部分。 

其有效高度为：$$\max(\text{current boundary height}, \text{neighbor height})$$这很重要，因为一旦水充满较低的单元，水面就像一个较高的边界。 
9. 继续，直到堆变空。 

那时，每个可到达的单元都已被处理，并且所有截留的水都已被计算在内。 

### 为什么它有效

 该算法保持了一个非常重要的不变量：

 > 使用可以到达的最小可能边界高度来处理从堆中弹出的每个单元格。 

因为堆总是首先扩展最低边界，所以我们以后不会错过更小的逃生路线。 这保证了我们第一次处理细胞时，我们已经知道该细胞的正确水位。 

这与 Dijkstra 的最短路径算法中使用的正确性原理完全相同。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def trapRainWater(self, heightMap: List[List[int]]) -> int:
        if not heightMap or not heightMap[0]:
            return 0

        rows = len(heightMap)
        cols = len(heightMap[0])

        if rows < 3 or cols < 3:
            return 0

        visited = [[False] * cols for _ in range(rows)]
        min_heap = []

        # Add all border cells to the heap
        for row in range(rows):
            for col in [0, cols - 1]:
                heapq.heappush(min_heap, (heightMap[row][col], row, col))
                visited[row][col] = True

        for col in range(cols):
            for row in [0, rows - 1]:
                if not visited[row][col]:
                    heapq.heappush(min_heap, (heightMap[row][col], row, col))
                    visited[row][col] = True

        total_water = 0

        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1)
        ]

        while min_heap:
            current_height, row, col = heapq.heappop(min_heap)

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    new_row < 0 or
                    new_row >= rows or
                    new_col < 0 or
                    new_col >= cols or
                    visited[new_row][new_col]
                ):
                    continue

                visited[new_row][new_col] = True

                neighbor_height = heightMap[new_row][new_col]

                if neighbor_height < current_height:
                    total_water += current_height - neighbor_height

                effective_height = max(current_height, neighbor_height)

                heapq.heappush(
                    min_heap,
                    (effective_height, new_row, new_col)
                )

        return total_water
```实现直接遵循算法。 

第一部分验证输入并处理无法积水的小网格。 

接下来，该解决方案初始化访问矩阵和最小堆。 每个边界单元都被插入到堆中，因为边界形成了水的初始逃逸边界。 

BFS 循环重复提取最低边界单元。 这保证了我们总是从当前已知的最小的墙开始扩展。 

对于每个未访问过的邻居：

 - 如果邻居较低，则添加滞留的水。 
- 使用有效边界高度将邻居插入回堆中。 

有效高度至关重要。 一旦水充满细胞，水面就成为未来探索的新边界。 

该算法对每个单元只处理一次，使其对于约束条件足够有效。 

## 解决方案```go
package main

import (
	"container/heap"
)

type Cell struct {
	height int
	row    int
	col    int
}

type MinHeap []Cell

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].height < h[j].height
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(Cell))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)

	item := old[n-1]
	*h = old[:n-1]

	return item
}

func trapRainWater(heightMap [][]int) int {
	if len(heightMap) == 0 || len(heightMap[0]) == 0 {
		return 0
	}

	rows := len(heightMap)
	cols := len(heightMap[0])

	if rows < 3 || cols < 3 {
		return 0
	}

	visited := make([][]bool, rows)
	for i := range visited {
		visited[i] = make([]bool, cols)
	}

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	// Add border cells
	for row := 0; row < rows; row++ {
		heap.Push(minHeap, Cell{heightMap[row][0], row, 0})
		heap.Push(minHeap, Cell{heightMap[row][cols-1], row, cols - 1})

		visited[row][0] = true
		visited[row][cols-1] = true
	}

	for col := 0; col < cols; col++ {
		if !visited[0][col] {
			heap.Push(minHeap, Cell{heightMap[0][col], 0, col})
			visited[0][col] = true
		}

		if !visited[rows-1][col] {
			heap.Push(minHeap, Cell{heightMap[rows-1][col], rows - 1, col})
			visited[rows-1][col] = true
		}
	}

	totalWater := 0

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	for minHeap.Len() > 0 {
		current := heap.Pop(minHeap).(Cell)

		for _, dir := range directions {
			newRow := current.row + dir[0]
			newCol := current.col + dir[1]

			if newRow < 0 ||
				newRow >= rows ||
				newCol < 0 ||
				newCol >= cols ||
				visited[newRow][newCol] {
				continue
			}

			visited[newRow][newCol] = true

			neighborHeight := heightMap[newRow][newCol]

			if neighborHeight < current.height {
				totalWater += current.height - neighborHeight
			}

			effectiveHeight := max(current.height, neighborHeight)

			heap.Push(
				minHeap,
				Cell{effectiveHeight, newRow, newCol},
			)
		}
	}

	return totalWater
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```Go 解决方案密切反映了 Python 逻辑，但 Go 需要使用以下自定义堆实现`container/heap`包裹。 

与Python内置的不同`heapq`，Go 需要定义：

 -`Len`-`Less`-`Swap`-`Push`-`Pop`访问矩阵是使用布尔切片的切片来实现的。 

Go 整数足以解决这个问题，因为最大捕获的水量仍然在 32 位整数范围内。

 | --- | --- | --- |

from typing import List

class Solution:
    def trapRainWater(self, heightMap: List[List[int]]) -> int:
        import heapq

        if not heightMap or not heightMap[0]:
            return 0

        rows = len(heightMap)
        cols = len(heightMap[0])

        if rows < 3 or cols < 3:
            return 0

        visited = [[False] * cols for _ in range(rows)]
        heap = []

        for r in range(rows):
            for c in [0, cols - 1]:
                heapq.heappush(heap, (heightMap[r][c], r, c))
                visited[r][c] = True

        for c in range(cols):
            for r in [0, rows - 1]:
                if not visited[r][c]:
                    heapq.heappush(heap, (heightMap[r][c], r, c))
                    visited[r][c] = True

        water = 0
        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while heap:
            h, r, c = heapq.heappop(heap)

            for dr, dc in directions:
                nr = r + dr
                nc = c + dc

                if (
                    nr < 0 or nr >= rows or
                    nc < 0 or nc >= cols or
                    visited[nr][nc]
                ):
                    continue

                visited[nr][nc] = True

                nh = heightMap[nr][nc]

                if nh < h:
                    water += h - nh

                heapq.heappush(heap, (max(h, nh), nr, nc))

        return water

 ## 边缘情况

 ### 非常小的网格

 少于三行或三列的网格无法积水，因为没有封闭的内部空间。 

例如：```
[[1,2,3]]
```每个细胞都位于边界上，因此水总是立即逸出。 

实现明确检查：```
if rows < 3 or cols < 3:
    return 0
```这避免了不必要的堆处理。 

### 平坦的地形

 完全平坦的地图不会积水，因为没有单元格低于其周围边界。 

例子：```
[
  [5,5,5],
  [5,5,5],
  [5,5,5]
]
```有缺陷的实现可能会错误地认为中心可以容纳水，因为它是封闭的。 

堆方法避免了这种情况，因为仅在以下情况下添加滞留的水：```
neighbor_height < current_height
```相同的高度不会困住任何东西。 

### 隐藏的逃生路径

 这是最微妙的情况。 

考虑一个局部看起来封闭的区域，但在其他地方有一个遥远的低边界。 

一种天真的本地方法可能会高估滞留的水，因为它只查看附近的墙壁。 

基于堆的 BFS 正确地解决了这个问题，因为扩展总是从全局最小边界开始。 如果水可以通过地图上任何位置较低的路线逸出，则该路线将在较高边界之前进行处理。 

这保证了该算法永远不会捕获比物理上可能的更多的水。
