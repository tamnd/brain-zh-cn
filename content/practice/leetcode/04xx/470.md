 ## 解决方案

 ## 问题理解

 该问题提供了对单个 API 的访问，`rand7()`，它返回一个均匀随机整数`1`到`7`。 任务是实现另一个功能，`rand10()`，它必须返回一个均匀随机整数`1`到`10`。 

重要的限制是我们不允许使用任何内置的随机数生成器。 每一个随机性最终都必须来自于重复调用`rand7()`。 

挑战不仅仅是生成范围内的数字`[1, 10]`。 困难的部分是确保每个数字`1`通过`10`被选中的概率完全相同。 幼稚的实现很容易引入偏差。 

隐藏参数`n`测试用例中仅表示在线法官会调用多少次`rand10()`。 不直接传入函数，不影响实现逻辑。 

因为`n`可以大到`10^5`，解决方案必须是有效的。 重复重试次数过多的糟糕实施可能会变得不必要的缓慢。 

一个主要的观察结果是`7`不均匀地分为`10`，这意味着我们不能简单地将一个调用映射到`rand7()`直接转化为一个结果`1`到`10`。 例如，使用类似的东西：```
return rand7() % 10 + 1
```永远不会产生大于`8`。 同样，错误地组合多个调用可能会使某些输出比其他输出更有可能出现。 

该问题保证了`rand7()`本身是完全一致的，这意味着每个值来自`1`通过`7`有概率发生`1/7`。 我们的实现必须在改变输出空间大小的同时保持一致性`7`成尺寸`10`。 

重要的边缘情况包括生成的中间随机值未均匀映射到的情况`[1, 10]`。 幼稚的实现可能会错误地压缩范围并产生概率偏差。 正确的解决方案必须明确拒绝无效范围以保持相等的概率。 

## 方法

 ### 蛮力方法

 一个蛮力的想法是重复调用`rand7()`并尝试直接将其输出映射到范围内`[1, 10]`。 一种尝试可能是合并两个调用：```
(rand7() + rand7()) % 10 + 1
```这确实产生了来自`1`到`10`，但分布并不均匀。 有些总和比其他总和出现得更频繁。 例如，总和`2`只能以一种方式发生，而总和`8`可以以多种不同的方式发生。 

另一种强力尝试是不断生成数字，直到我们以某种方式落在所需的范围内。 然而，如果没有仔细的概率管理，这仍然会引入不均匀的概率。 

暴力方法失败是因为它忽略了一个关键要求：每个输出必须具有相同的概率。 

### 关键见解

 关键的见解是两个独立的调用`rand7()`可以生成均匀分布`49`同样可能的结果。 

自从：```
7 × 7 = 49
```我们可以想到这一对`(a, b)`代表数字`1`到`49`。 

因为`49`大于`10`，我们可以使用拒绝采样。 具体来说：

 - 使用第一个`40`值因为`40`可以整除`10`- 拒绝值`41`通过`49`- 将剩余值均匀映射到`1`通过`10`这是有效的，因为每个`40`接受的状态以相同的概率出现。

 ## 算法演练

 1. 打电话`rand7()`两次生成两个独立的随机值。 

让：```
row = rand7()
col = rand7()
```由于每次调用都是独立且均匀分布的，所以每对`(row, col)`是同样有可能的。 
2. 将二维对转换为单个数字`1`到`49`。 

我们使用：```
index = (row - 1) * 7 + col
```这有效地将所有可能的对排列在 7 × 7 网格中。 

例如：

 | 行| 上校 | 索引 |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 1 | 7 | 7 |
 | 2 | 1 | 8 |
 | 7 | 7 | 49 | 49
 3. 检查生成的号码是否在可用范围内。 

我们只接受来自`1`通过`40`。 

为什么`40`？ 

因为：```
40 = 10 × 4
```这意味着每个输出`1`到`10`可以恰好出现四次。 
4. 拒绝无效值。 

如果生成的值介于`41`和`49`，丢弃它并重复该过程。 

这是拒绝采样背后的核心思想。 
5. 将接受的值转换为最终答案。 

一旦我们获得了有效的号码`1`到`40`，将其映射到`[1, 10]`使用：```
result = (index - 1) % 10 + 1
```这样可以均匀地分配结果。 

### 为什么它有效

 每对`rand7()`调用产生以下之一`49`同样可能的结果。 通过拒绝价值观`41`通过`49`，我们剩下`40`同样可能的结果。 自从`40`均匀地分为`10`，每个最终值来自`1`通过`10`正好出现四次。 因此，概率分布是完全均匀的。 

## Python 解决方案```python
# The rand7() API is already defined for you.
# def rand7():
#     # returns a random integer in the range 1 to 7

class Solution:
    def rand10(self) -> int:
        while True:
            row = rand7()
            col = rand7()

            index = (row - 1) * 7 + col

            if index <= 40:
                return (index - 1) % 10 + 1
```该实现不断生成候选值，直到找到有效值。 

变量`row`和`col`代表两个独立的随机值`1`到`7`。 这些被组合成一个单一的均匀分布的值`1`到`49`。 

表达式：```python
(row - 1) * 7 + col
```将 7 × 7 网格映射为线性序列。 

条件：```python
if index <= 40:
```实施拒绝抽样。 以上数值`40`被丢弃，因为它们会产生不均匀的概率。 

最后，模算术将接受的范围转换为以下值：`1`到`10`。 

## 解决方案```go
func rand10() int {
    for {
        row := rand7()
        col := rand7()

        index := (row-1)*7 + col

        if index <= 40 {
            return (index-1)%10 + 1
        }
    }
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 使用显式变量声明`:=`。 由于该问题中的整数仍然非常小，因此不必担心整数溢出。 

无限的`for`循环是 Go 中 Python 的等价物`while True:`环形。

 ## 边缘情况

 当生成的中间值介于`41`和`49`。 这些值不能均匀地映射到`1`通过`10`。 A buggy implementation might still apply modulo arithmetic directly, which would make some outputs more likely than others. The rejection sampling step prevents this by discarding those values entirely.

 Another important case is repeated rejection. In theory, the algorithm could repeatedly generate invalid values. A poor implementation might accidentally enter an infinite loop because of incorrect retry logic. This implementation handles retries safely using a simple infinite loop that continues until a valid value is produced.

 A third edge case involves incorrect index construction. If the formula converting two`rand7()`调用一个值`1`到`49`错误，某些号码可能无法访问或重复。 表达式：```
(row - 1) * 7 + col
```保证每个值来自`1`通过`49`只出现一次，在整个空间中保持统一的概率。
