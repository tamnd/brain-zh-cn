[LeetCode 第 481 题](https://leetcode.com/problems/magical-string/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 这个问题定义了一个特殊的无限序列，称为神奇字符串。 该字符串仅包含字符`'1'`和`'2'`，它的定义属性非常不寻常：

 如果将连续的相同数字组合在一起并记录每组的长度，则生成的长度序列将重新创建原始字符串本身。 

例如，神奇字符串的开头是：```
1221121221221121122...
```如果我们将其分成连续的相等数字组：```
1 | 22 | 11 | 2 | 1 | 22 | 1 | 22 | ...
```这些组的长度为：```
1 2 2 1 1 2 1 2 ...
```这个顺序和魔法弦一模一样。 

输入是一个整数`n`，并且我们必须确定有多少`'1'`字符出现在第一个`n`神奇字符串的元素。 

限制条件是：```
1 <= n <= 10^5
```这告诉我们几个重要的事情：

 - 该解决方案必须足够高效，能够处理多达十万个字符。 
- 增量生成序列是可行的。 
- 应避免昂贵的重新计算或重复的字符串重建。 

还有一些重要的边缘情况：

 -`n = 1`，答案是立即`1`。 
- 非常小的值，例如`n = 2`或者`n = 3`，其中初始化错误很常见。 
- 代数稍微超过的情况`n`，因为序列是按组生成的，而不是一次生成一个字符。 
- 只计算第一个`n`字符，即使内部生成了更多字符。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是在每次添加新字符时扫描整个序列，尝试重复重建神奇的字符串。 

这个想法是：

 1. 从最初的神奇字符串前缀开始。 
2. 重复对连续的字符进行分组。 
3. 计算组长度。 
4. 根据这些长度验证或重新生成序列。 
5. 继续直到字符串达到长度`n`。 

这种方法在概念上是有效的，因为它直接遵循神奇字符串的定义。 然而，它的效率非常低，因为重复对序列进行分组和重新扫描会带来不必要的重复工作。 

如果我们多次重建或扫描序列，总复杂度可能会成二次方。 

和`n = 10^5`， 一个`O(n^2)`方法太慢了。 

### 最佳方法

 关键的观察是神奇的字符串描述了它自己的游程长度。 

这意味着我们可以增量生成序列，同时从序列本身读取指令。 

我们维持：

 - 读取下一个组大小的指针。 
- 要附加的当前数字，在之间交替`1`和`2`。 
- 代表神奇字符串的动态增长数组。 

例如：```
Initial sequence: 1 2 2
```下一个未读值是`2`， 意义：```
append two copies of the opposite digit
```由于最后一位数字是`2`，我们附加：```
1 1
```现在序列变成：```
1 2 2 1 1
```这个过程一直持续到我们至少生成`n`元素。 

这可以有效地工作，因为每个字符都只生成一次。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复重新扫描和重组 |
 | 最佳| O(n) | O(n) | 每个字符恰好生成一次 |

 ## 算法演练

 1. 立即处理最小的边缘情况。 

如果`n <= 3`，我们已经知道神奇的字符串开头为：```
122
```的计数为`'1'`很容易直接确定。 
2. 初始化神奇字符串。 

我们从以下开始：```
magical = [1, 2, 2]
```这是序列的已知起始前缀。 
3. 维护一个用于读取组大小的指针。 

我们使用一个名为`head`。 

该指针告诉我们要附加下一个数字的多少个副本。 

最初：```
head = 2
```因为第一个未读游程长度是第三个元素。 
4. 跟踪要附加的下一个数字。 

我们交替进行`1`和`2`。 

由于当前序列以`2`，下一个附加数字将是`1`。 
5. 增量生成序列。 

当序列长度小于`n`:

 - 读取计数`magical[head]`- 多次追加当前数字
 - 附加计数`1`s 如果它们落在第一个范围内`n`职位
 - 翻转数字`1`和`2`- 进步`head`6. 一旦生成了足够的元素就停止。 

因为我们只关心第一个`n`元素，一旦序列达到长度，生成就会停止`n`。 

### 为什么它有效

 该算法之所以有效，是因为神奇的字符串是自我描述的。 序列中的每个值指定下一组的大小。 通过从已经生成的部分读取游程长度，同时附加交替的数字，我们准确地再现了神奇的字符串定义。 

不变量是：```
Every generated prefix satisfies the magical string property.
```由于每个步骤都使用下一个有效游程长度来扩展序列，因此在整个构建过程中都保留了正确性。 

## Python 解决方案```python
class Solution:
    def magicalString(self, n: int) -> int:
        if n <= 3:
            return 1

        magical = [1, 2, 2]

        head = 2
        next_num = 1

        ones_count = 1

        while len(magical) < n:
            repeat = magical[head]

            for _ in range(repeat):
                magical.append(next_num)

                if next_num == 1 and len(magical) <= n:
                    ones_count += 1

            next_num = 2 if next_num == 1 else 1
            head += 1

        return ones_count
```实现从已知前缀开始`[1, 2, 2]`，它已经满足了神奇的字符串属性。 

变量`head`充当读者指针。 我们不重新计算组大小，而是直接使用序列中已经存在的值。 

变量`next_num`跟踪接下来应该附加哪个数字。 由于小组之间交替`1`和`2`，我们只需在每组之后切换值即可。 

每当一个`1`附加在第一个内`n`位置，我们增加`ones_count`。 

一旦序列包含至少一个，循环就会停止`n`元素。 

## 解决方案```go
func magicalString(n int) int {
    if n <= 3 {
        return 1
    }

    magical := []int{1, 2, 2}

    head := 2
    nextNum := 1

    onesCount := 1

    for len(magical) < n {
        repeat := magical[head]

        for i := 0; i < repeat; i++ {
            magical = append(magical, nextNum)

            if nextNum == 1 && len(magical) <= n {
                onesCount++
            }
        }

        if nextNum == 1 {
            nextNum = 2
        } else {
            nextNum = 1
        }

        head++
    }

    return onesCount
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

使用切片代替 Python 列表，并且`append`动态增长序列。 整数溢出不是问题，因为约束只是`10^5`。 

与 Python 不同，Go 没有内置的三元运算符，因此数字切换使用标准`if`陈述。

 ## 边缘情况

 一个重要的边缘情况是`n <= 3`。 神奇的字符串开始于`"122"`，并且许多实现错误地尝试生成附加值，即使对于这些微小的输入也是如此。 这可能会导致一个错误或不正确的计数。 该实现立即处理这个问题并直接返回`1`。 

当代数超过时，会发生另一个微妙的情况`n`。 由于数字是按大小为一或二的组附加的，因此该算法可能会稍微超出所需的前缀长度。 如果计数不小心，则额外`'1'`超越地位的价值观`n`可以包括在内。 该实现通过检查来避免这种情况：```
len(magical) <= n
```在增加计数之前。 

第三个重要的边缘情况涉及正确交替数字。 因为神奇的字符串是从它自己的游程长度生成的，所以忘记在它们之间交替`1`和`2`每组破坏整个结构后。 该实现在处理每个组后显式翻转值，确保生成的序列保持神奇的属性。
