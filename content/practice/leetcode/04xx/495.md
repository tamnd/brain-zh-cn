 ## 解决方案

 ## 问题理解

 该问题要求我们计算阿什被提莫攻击中毒的总持续时间。 特定秒内的每次攻击`t`导致艾什中毒的原因正是`duration`秒，中毒时间**含**，即中毒效果持续时间`t`到`t + duration - 1`。 如果提莫在上次攻击的毒药结束之前再次攻击，则毒药计时器会**重置**，这意味着毒药持续时间实际上会重叠，但不会重复计算时间。 

输入是一个非递减数组`timeSeries`整数，每个代表提莫攻击时的一秒，以及一个整数`duration`代表单次攻击使艾什中毒的时间。 输出是一个整数，表示考虑到重叠攻击后，Ashe 保持中毒状态的总秒数。 

约束告诉我们`timeSeries`最多可以有`10^4`元素和值可以大到`10^7`，这意味着任何针对每次攻击迭代每一秒毒药的解决方案都可能效率低下。 保证`timeSeries`已排序允许我们考虑攻击之间的顺序比较，而无需先排序。 重要的边缘情况包括同一秒发生的攻击、持续时间为零以及仅存在一次攻击。 

## 方法

 一种强力方法是模拟艾什中毒的每一秒，在集合或布尔数组中标记每一秒，然后对所有中毒秒数求和。 虽然这有效，但效率很低，因为如果`duration`规模很大且攻击稀疏，每秒迭代可能会导致运行时间较长。 

最佳方法依赖于观察重叠的中毒持续时间应该只计算每个新攻击的非重叠部分。 对于第一次攻击之后的每次攻击，我们计算当前攻击时间与上一次中毒效果结束之间的差距。 如果间隙大于或等于持续时间，则添加完整的持续时间。 如果间隔较小，则仅将间隔计入新的中毒时间，因为剩余的秒数已包含在前一次攻击的中毒间隔中。 这允许单次通过阵列，而无需单独模拟每一秒。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 持续时间) | O(n * 持续时间) | 每次攻击都会迭代每秒的毒药，长时间内效率低下 |
 | 最佳| O(n) | O(1) | O(1) | 一次计算非重叠中毒时间，最小的额外空间 |

 ## 算法演练

 1. 初始化变量`total_poisoned`到 0 来累计总中毒秒数。 
2. 初始化`end_time`为 0。当前中毒效果结束时，该变量将跟踪第二个。 
3. 迭代每个攻击时间`t`在`timeSeries`。 
4. 对于每个`t`，计算本次攻击贡献的有效中毒时间。 如果`t`大于或等于`end_time`，这次攻击的毒与之前的毒不重叠，所以加满`duration`到`total_poisoned`。 否则，添加差值`t + duration - end_time`仅考虑新的中毒秒数。 
5. 更新`end_time`到`t + duration`，本次攻击的中毒效果结束。 
6.处理完所有攻击后，返回`total_poisoned`。 

该算法之所以有效，是因为它保持的不变量是`end_time`总是追踪艾什中毒最远的那一秒。 通过仅添加不重叠的毒物间隔，我们确保每一秒都被精确地计算一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def findPoisonedDuration(self, timeSeries: List[int], duration: int) -> int:
        if not timeSeries or duration == 0:
            return 0
        
        total_poisoned = 0
        end_time = 0
        
        for t in timeSeries:
            if t >= end_time:
                total_poisoned += duration
            else:
                total_poisoned += t + duration - end_time
            end_time = t + duration
        
        return total_poisoned
```在此实现中，我们首先处理攻击列表为空或持续时间为零的边缘情况，立即返回 0。然后迭代每个攻击时间。 对于非重叠攻击，我们添加完整的持续时间。 对于重叠攻击，我们仅添加先前毒害间隔尚未覆盖的部分。 最后我们更新一下`end_time`每次攻击后代表当前中毒效果结束。 

## 解决方案```go
func findPoisonedDuration(timeSeries []int, duration int) int {
    if len(timeSeries) == 0 || duration == 0 {
        return 0
    }
    
    totalPoisoned := 0
    endTime := 0
    
    for _, t := range timeSeries {
        if t >= endTime {
            totalPoisoned += duration
        } else {
            totalPoisoned += t + duration - endTime
        }
        endTime = t + duration
    }
    
    return totalPoisoned
}
```在 Go 中，我们同样预先处理边缘情况。 循环逻辑反映了 Python 解决方案，使用整数算术来计算非重叠中毒持续时间。 Go 的切片和范围循环使这变得简单，并且`endTime`变量跟踪中毒效果与 Python 中完全相同。

 ## 边缘情况

 1. **清空攻击列表**：当`timeSeries`如果为空，算法必须立即返回 0。这可以防止不必要的计算，并确保不会因访问空列表中的元素而发生错误。 
2. **零持续攻击**：如果`duration`为0时，无论攻击次数多少，艾什都不会中毒。 实现通过检查来处理这个问题`duration == 0`预付并返回 0。 
3. **同一秒重叠攻击**：如果同一秒发生多次攻击，则中毒持续时间不应重复计算。 该实现正确地仅添加第一次攻击的完整持续时间，并将后续攻击视为重叠，贡献零额外秒数。 这是通过计算来管理的`t + duration - end_time`，对于同一秒的重复攻击，该值变为零。
