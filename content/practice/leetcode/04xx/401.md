[LeetCode 401 题](https://leetcode.com/problems/binary-watch/)

 **难度：** 🟢简单
 **主题：** 回溯、位操作

 ## 解决方案

 ## 问题理解

 该问题描述了一个使用 LED 来表示时间的二进制手表。 该手表有两个部分。 顶部包含 4 个表示小时的 LED，底部包含 6 个表示分钟的 LED。 

每个 LED 代表一个二进制数字。 如果 LED 亮起，它就会提供相应的二进制值。 小时 LED 可以表示 0 到 11 之间的值，而分钟 LED 可以表示 0 到 59 之间的值。 

输入，`turnedOn`，告诉我们当前有多少个 LED 亮着。 我们的任务是生成可以使用那么多活动 LED 来表示的每个有效时间。 

例如，如果`turnedOn = 1`，则正好有一个 LED 亮起。 这意味着有效时间包括以下值：

 -`"1:00"`因为 LED 处于活动状态一小时
 -`"0:01"`因为 LED 处于活动状态一分钟
 -`"0:32"`因为最高分钟 LED 处于活动状态

 输出应包含任意顺序的所有有效时间。 

生成时间有重要的格式规则：

 - 小时数不得有前导零。`"1:00"`是有效的，但是`"01:00"`不是。 
- 分钟必须始终包含恰好两位数。`"10:02"`是有效的，但是`"10:2"`不是。 

限制非常小：

 -`0 <= turnedOn <= 10`这告诉我们 LED 总数固定为 10，这意味着搜索空间极其有限。 即使暴力解决方案也是可行的，因为只有：

 - 12小时可能
 - 可能 60 分钟

 这仅给出`12 × 60 = 720`可能的总次数。 

一些边缘情况很重要：

 -`turnedOn = 0`， 仅有的`"0:00"`是有效的。 
-`turnedOn = 9`或者`10`，可能不存在有效时间，因为有效小时和分钟不能同时使用那么多 LED。 
- 分钟格式必须始终保留两位数字。 
- 营业时间必须在`0-11`。 
- 会议记录必须保留在`0-59`。 

## 方法

 ### 蛮力方法

 暴力解决方案会检查手表上每个可能的有效时间。 由于营业时间范围为`0`到`11`分钟范围为`0`到`59`，我们可以迭代所有 720 种可能的组合。 

对于每个`(hour, minute)`对，我们计算两个值中设置位的数量。 设置位代表打开的 LED。 如果设置的位数等于`turnedOn`，然后将该时间添加到答案中。 

这种方法是正确的，因为它详尽地检查了每个有效的时间配置。 不会遗漏任何有效答案，也不包含无效答案，因为我们明确验证了 LED 计数。 

尽管这在技术上是蛮力的，但输入量非常小，因此在实践中表现得非常好。 

### 最佳方法

 关键的见解是该问题从根本上取决于对二进制集位进行计数。 

每个LED直接对应一个二进制`1`。 因此：

 - 每小时的活动 LED 数量等于`1`小时值中的位。 
- 每分钟活动 LED 的数量等于`1`分钟值中的位。 

我们可以直接利用位操作，而不是通过回溯显式模拟 LED 位置。 我们迭代所有有效时间并使用位计数操作来确定活动位的总数是否匹配`turnedOn`。 

该解决方案是最佳的，因为：

 - 总搜索空间是固定的且很小。 
- 位计数速度极快。 
- 实现简单且易于验证。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(720 × B) | O(1) 不包括输出 | 检查每个有效时间并手动计数位 |
 | 最佳 | O(720) | O(1) 不包括输出 | 通过位操作使用高效的位计数 |

 这里，`B`表示手动计数时检查的位数，最多为 10。 

## 算法演练

 1. 初始化一个空结果列表，用于存储所有有效时间字符串。 
2. 迭代每个可能的小时`0`到`11`。 这些是二进制手表唯一有效的小时值。 
3. 对于每个小时，迭代从`0`到`59`。 这些是唯一有效的分钟值。 
4. 计算小时值中设置的位数。 每个设置位对应一个点亮的小时 LED。 
5. 计算分钟值中设置的位数。 每个设置位对应一个亮起的分钟 LED。 
6. 将两个计数相加。 这给出了当前打开的 LED 的总数。 
7. 将总计数与`turnedOn`。 如果它们匹配，则这是有效的时间表示。 
8. 在将时间添加到结果之前正确设置时间格式：

 1. 小时正常转换，不带前导零。 
2. 分钟使用零填充精确地格式化为两位数。 
9. 继续，直到检查完所有 720 个可能的时间。 
10. 返回完成的结果列表。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的手表状态都唯一对应于一对`(hour, minute)`。 通过迭代所有有效的小时和分钟组合，我们保证每种可能的手表配置都被检查一次。 

发光二极管的数量正好等于二进制数`1`小时和分钟值中的位组合。 因此，选择总设置位数等于的所有时间`turnedOn`与问题定义精确匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def readBinaryWatch(self, turnedOn: int) -> List[str]:
        result = []

        for hour in range(12):
            for minute in range(60):
                led_count = bin(hour).count("1") + bin(minute).count("1")

                if led_count == turnedOn:
                    result.append(f"{hour}:{minute:02d}")

        return result
```实现首先创建一个名为的空列表`result`存储所有有效时间。 

外循环迭代每个有效小时`0`到`11`，而内部循环则迭代每个有效分钟`0`到`59`。 

对于每个时间组合，代码都会计算活动 LED 的总数。 这是使用 Python 的二进制字符串表示形式完成的：```python
bin(value).count("1")
```这`bin()`函数将数字转换为二进制形式，并且`count("1")`计算设置了多少位。 

如果 LED 总数匹配`turnedOn`，时间被格式化并附加到结果列表中。 表达式：```python
f"{hour}:{minute:02d}"
```确保分钟始终包含两位数。 例如：

-`5`变成`"05"`-`0`变成`"00"`最后返回完成的列表。 

## 解决方案```go
package main

import (
	"fmt"
	"math/bits"
)

func readBinaryWatch(turnedOn int) []string {
	result := []string{}

	for hour := 0; hour < 12; hour++ {
		for minute := 0; minute < 60; minute++ {
			ledCount := bits.OnesCount(uint(hour)) +
				bits.OnesCount(uint(minute))

			if ledCount == turnedOn {
				timeString := fmt.Sprintf("%d:%02d", hour, minute)
				result = append(result, timeString)
			}
		}
	}

	return result
}
```Go解决方案遵循与Python实现相同的逻辑，但它使用Go的标准库函数：```go
bits.OnesCount()
```这可以有效地计算整数中设置位的数量。 

切片用于动态存储结果。 与 Python 列表不同，Go 切片需要使用显式追加`append()`。 

格式化是通过以下方式处理的：```go
fmt.Sprintf("%d:%02d", hour, minute)
```这确保分钟部分始终有两位数。 

不存在整数溢出问题，因为所有值都非常小。

 ## 边缘情况

 ### 边缘情况 1：`turnedOn = 0`这种情况意味着 LED 根本没有亮起。 幼稚的实现可能会意外返回一个空列表，因为它需要至少一个活动位。 

唯一有效的配置是：```
0:00
```该实现自然地处理了这个问题，因为`0`小时位和`0`分钟位总和为零。 

### 边缘情况 2：LED 数量非常多

 输入如`turnedOn = 9`或者`10`如果实现假设每个 LED 组合都对应一个有效时间，则很容易导致错误。 

尽管手表实际上有 10 个 LED，但有效的小时和分钟并不使用所有二进制组合。 最大有效 LED 数量实际上是 8 个。 

该算法通过仅检查有效的小时和分钟范围来正确处理此问题。 由于没有有效对达到 9 或 10 个设置位，因此结果保持为空。 

### 边缘情况 3：分钟格式化

 分钟格式不正确是此问题中最常见的错误之一。 

例如：```
10:2
```无效，因为分钟必须始终包含两位数字。 

该实现使用以下方式显式格式化分钟：```
f"{minute:02d}"
```它保证对所有低于 10 的值进行正确的零填充。 

### 边缘情况 4：小时前导零

 小时数不得包含前导零。 粗心的格式化方法可能会生成无效的输出，例如：```
01:00
```该实现通过将小时格式化为普通整数而不进行填充来避免这种情况。
