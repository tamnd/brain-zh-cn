[LeetCode 第 489 题](https://leetcode.com/problems/robot-room-cleaner/)

 **难度：** 🔴难
 **主题：** 回溯、互动

 ## 解决方案

 ## 问题理解

 这个问题是一个交互式回溯问题，我们必须在不直接看到房间布局的情况下控制机器人。 与传统的网格遍历问题不同，我们无法访问实际的网格`room`执行期间的矩阵。 探索环境的唯一方法是通过机器人的 API。 

该房间在概念上是一个二元网格：

 -`1`代表机器人可以进入的空单元格。 
-`0`代表墙壁或阻塞的细胞。 

机器人从某个未知的有效空单元开始，面朝上。 我们不知道：

 - 机器人的绝对坐标
 - 房间的尺寸
 - 墙壁所在的位置

 相反，我们只能通过四个 API 调用进行交互：

 -`move()`尝试前进
 -`turnLeft()`将机器人逆时针旋转 90 度
 -`turnRight()`将机器人顺时针旋转 90 度
 -`clean()`清理当前单元格

 目标是确保每个可到达的空单元格都被精确地清洁一次或至少一次。 

重要的挑战是，这实际上是一个蒙着眼睛的图遍历问题。 由于我们事先不知道地图，所以我们在探索时必须建立自己的虚拟坐标系。 

约束条件告诉我们：

 - 房间最多可容纳`100 * 200 = 20,000`细胞。 
- 每个空单元格都可以从起始位置到达。 
- 机器人从有效的空单元格开始。 
- 边界保证是墙壁，因此机器人无法离开房间。 

这些保证很重要，因为它们使我们能够执行完整的遍历，而不必担心可到达的组件断开连接或无限移动到边界之外。 

一些边缘情况尤其重要：

 - 一间只有一个牢房的房间
 - 狭窄的走廊，许多动作都失败
 - 循环路径，机器人可以通过不同的路线重新访问细胞
 - 大型开放区域，天真的重访会导致指数级工作
 - 递归探索后保持机器人正确的方向

 问题最难的部分不是遍历本身，而是确保机器人在探索一个方向后始终返回到之前的位置和方向。 

## 方法

 ### 蛮力方法

 一个幼稚的策略是在所有可能的方向上重复移动，而不记住机器人已经在哪里。 机器人可以递归地尝试每个可能的运动序列。 

这种方法最终会清理所有可到达的单元格，因为每条路径都被探索过。 然而，它执行了大量的冗余工作，因为机器人通过不同的路径重复访问相同的单元。 

例如，在一个开放的房间里，机器人可以在相邻的单元之间无休止地循环。 如果不跟踪访问过的状态，遍历实际上会变成指数级的。 

另一个问题是方向管理。 如果我们在递归后不仔细恢复机器人的方向，未来的探索就会变得不一致并且难以推理。 

由于需要反复重访，这种强力方法对于大房间来说是不切实际的。 

### 最佳方法

 关键的观察结果是房间形成了一个隐式图：

 - 每个空单元格都是一个节点
 - 相邻的可到达单元格形成边缘

 因此，我们可以使用带有回溯的深度优先搜索（DFS）。 

由于机器人不知道真实坐标，我们创建一个虚拟坐标系：

 - 起始位置是`(0, 0)`- 向上移动减少行数
 - 向右移动增加列
 - 向下移动增加行数
 - 向左移动减少列

 我们维护一个访问集，因此每个单元格仅被探索一次。 

关键技术是回溯：

 1. 移入相邻小区
 2. 递归清理该区域
 3.将机器人放回原来的牢房
 4.恢复原来的方向

 这保证了机器人在探索一个方向后处于与之前完全相同的状态，从而可以安全地探索其余方向。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 反复重访细胞并探索冗余路径 |
 | 最优DFS+回溯| O(N) | O(N) | 访问每个可达单元一次，其中 N 是空单元的数量 |

 ## 算法演练

 ### 步骤 1：定义方向向量

 我们将这四个方向表示为：

 - 向上：`(-1, 0)`- 正确的：`(0, 1)`- 向下：`(1, 0)`- 左边：`(0, -1)`我们还分配方向索引：

 -`0 = up`-`1 = right`-`2 = down`-`3 = left`这使我们能够一致地计算新坐标。 

### 步骤 2：维护访问集

 由于机器人可以通过不同的路径重新访问单元格，因此我们将访问过的坐标存储在哈希集中。 

当我们进入一个单元格时：

 - 将其坐标添加到`visited`- 清洁当前单元格

 这可以防止无限循环和冗余探索。 

### 第 3 步：探索所有四个方向

 对于每个单元，我们尝试在相对于机器人当前方向的所有四个方向上进行探索。 

对于每个方向：

 1. 计算邻居坐标
 2. 如果没有访问过：

 - 尝试`move()`- 如果成功：

 - 递归探索
 - 之后原路返回
 3. 向右旋转以对齐下一个方向

 即使由于墙壁而导致移动失败，我们仍然会旋转并继续检查其他方向。 

### 步骤 4：正确回溯

 经过递归探索后，机器人在 DFS 树中更深。 

我们必须准确地恢复之前的状态。 

要返回到上一个单元格：

 1. 转180度
 2. 前进
 3.再次转身

 这将返回：

 - 定位到父单元格
 - 朝向其原始方向

 这一步是算法的核心不变量。 

### 步骤 5：继续直至 DFS 完成

 最终所有可到达的单元都被访问。 

因为每个可到达的单元格都被探索一次，并且每个递归调用都会正确恢复状态，所以整个房间都被成功清理。 

### 为什么它有效

 该算法保持不变式，即每次递归 DFS 调用完成后，机器人都会返回到调用开始之前的相同位置和方向。 

由于每个可到达的单元格都被添加到访问集中一次，因此 DFS 遍历最终会探索每个可到达的单元格，而不会出现无限循环。 回溯保证了探索顺序的一致性，并防止机器人相对于虚拟坐标系迷失方向。 

## Python 解决方案```python
# """
# This is the robot's control interface.
# You should not implement it, or speculate about its implementation
# """
# class Robot:
#     def move(self):
#         pass
#
#     def turnLeft(self):
#         pass
#
#     def turnRight(self):
#         pass
#
#     def clean(self):
#         pass

from typing import Set, Tuple

class Solution:
    def cleanRoom(self, robot) -> None:
        directions = [
            (-1, 0),  # up
            (0, 1),   # right
            (1, 0),   # down
            (0, -1)   # left
        ]

        visited: Set[Tuple[int, int]] = set()

        def go_back() -> None:
            robot.turnRight()
            robot.turnRight()

            robot.move()

            robot.turnRight()
            robot.turnRight()

        def dfs(row: int, col: int, direction: int) -> None:
            visited.add((row, col))
            robot.clean()

            for i in range(4):
                new_direction = (direction + i) % 4

                dr, dc = directions[new_direction]
                new_row = row + dr
                new_col = col + dc

                if (new_row, new_col) not in visited:
                    if robot.move():
                        dfs(new_row, new_col, new_direction)
                        go_back()

                robot.turnRight()

        dfs(0, 0, 0)
```实现首先按顺时针顺序定义四个移动方向。 这种顺序很重要，因为机器人在每次探索尝试后都会立即旋转。 

这`visited`set 存储虚拟坐标。 由于真实房间坐标未知，算法将起始位置视为`(0, 0)`并得出与其相关的所有其他位置。 

这`go_back()`helper 执行回溯操作。 机器人转身，向后移动一步，恢复方向。 这保证了 DFS 递归行为正确。 

这`dfs()`函数负责探索和清理可到达的单元格。 

进入单元格时：

 1. 标记已访问过
 2. 清洁

 然后该函数检查所有四个方向。 对于每个方向：

 - 计算邻居坐标
 - 跳过已经访问过的单元格
 - 尝试运动
 - 如果移动成功则递归
 - 之后原路返回

 最后，机器人向右旋转，准备检查下一个方向。 

递归结构反映了标准的 DFS 遍历，同时小心地保持机器人方向。 

## 解决方案```go
/**
 * // This is the robot's control interface.
 * // You should not implement it, or speculate about its implementation
 * type Robot struct {
 * }
 *
 * // Returns true if the cell in front is open and robot moves into the cell.
 * // Returns false if the cell in front is blocked and robot stays in the current cell.
 * func (robot *Robot) Move() bool {}
 *
 * // Robot will stay on the same cell after calling TurnLeft/TurnRight.
 * // Each turn will be 90 degrees.
 * func (robot *Robot) TurnLeft() {}
 * func (robot *Robot) TurnRight() {}
 *
 * // Clean the current cell.
 * func (robot *Robot) Clean() {}
 */

func cleanRoom(robot *Robot) {
	directions := [][]int{
		{-1, 0}, // up
		{0, 1},  // right
		{1, 0},  // down
		{0, -1}, // left
	}

	type Position struct {
		row int
		col int
	}

	visited := make(map[Position]bool)

	var goBack func()
	goBack = func() {
		robot.TurnRight()
		robot.TurnRight()

		robot.Move()

		robot.TurnRight()
		robot.TurnRight()
	}

	var dfs func(row, col, direction int)

	dfs = func(row, col, direction int) {
		visited[Position{row, col}] = true
		robot.Clean()

		for i := 0; i < 4; i++ {
			newDirection := (direction + i) % 4

			dr := directions[newDirection][0]
			dc := directions[newDirection][1]

			newRow := row + dr
			newCol := col + dc

			if !visited[Position{newRow, newCol}] {
				if robot.Move() {
					dfs(newRow, newCol, newDirection)
					goBack()
				}
			}

			robot.TurnRight()
		}
	}

	dfs(0, 0, 0)
}
```Go 的实现紧密遵循 Python 版本。 

主要区别在于 Go 没有内置元组哈希，因此我们定义了一个`Position`struct 并将其用作映射键。 

DFS 逻辑和回溯行为是相同的。 

对于给定的约束，Go 递归深度是可以接受的，因为可到达单元的最大数量最多为 20,000，这在 LeetCode 的环境中通常是可以管理的。 

不存在整数溢出问题，因为坐标保持在合理的范围内。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | 每个可达单元都被访问一次 |
 | 空间| O(N) | 访问集和递归堆栈存储可达单元 |

 这里，`N`表示可到达的空单元格的数量。 

尽管机器人可以旋转很多次，但每个单元只会产生恒定的额外工作。 相邻单元格之间的每条边最多遍历固定次数，因为 DFS 每次成功移动都会精确地探索和回溯一次。 

递归堆栈可以增长到`O(N)`在最坏的情况下，例如很长的走廊。

 ## 边缘情况

 ### 单个可达单元格

 一个房间可能只包含一个可访问的单元格。 在这种情况下，所有移动尝试都会立即失败。 有缺陷的实现可能会不必要地递归，或者在移动失败后错误地处理方向变化。 

此实现可以自然地处理它，因为 DFS 会清理当前单元，尝试四次失败的移动，适当轮换，然后终止。 

### 循环路径

 开放的房间通常包含循环，机器人可以通过不同的路径返回之前访问过的单元格。 如果没有访问过的集合，机器人将无限循环。 

该实现通过在探索邻居之前将每个访问过的坐标存储在哈希集中来避免这种情况。 

### 长长的走廊

 狭窄的走廊可以产生非常深的递归。 不正确的回溯会使机器人在从递归返回时面临错误的方向。 

这`go_back()`helper保证在递归探索之后，机器人的位置和方向都准确恢复，使得后续的探索正确。 

### 与各个方向相邻的墙

 单元可以被多个侧面的壁包围。 不正确的解决方案可能会假设移动成功，或者在移动受阻后无法正确旋转。 

此实现始终在每次方向尝试后旋转，无论移动是否成功，从而确保一致的方向管理。
