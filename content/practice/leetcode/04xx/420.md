 # 强密码检查器

 ## 问题理解

 该问题要求我们根据三个规则确定将给定密码转换为“强”密码所需的最少操作次数。 

强密码必须满足以下所有条件：

 1. 密码长度必须在 6 至 20 个字符之间（含 6 和 20 个字符）。 
2. 密码必须包含至少1个小写字母、至少1个大写字母和至少1个数字。 
3. 密码不能包含三个相同的连续字符。 

输入是一个名为`password`。 输出是一个整数，表示使密码有效所需的最小编辑次数。 

每个编辑操作可以是以下三个操作之一：

 - 插入一个字符
 - 删除一个角色
 - 替换一个角色

 限制相对较小，密码长度最多为 50，但挑战不是暴力计算规模。 困难来自于同时平衡多个约束。 有时，一次操作可以同时解决多个问题。 例如，用数字替换重复的字符可能会破坏重复并满足缺少数字的要求。 

一些边缘情况使这个问题变得棘手：

 - 密码非常短，不可避免地需要插入
 - 密码非常长，必须删除
 - 具有许多重复序列的密码
 - 密码缺少多个字符类别
 - 一次操作可以满足多种需求的情况
 - 长重复序列，仔细的删除放置可最大限度地减少替换

 幼稚的实现通常会失败，因为它独立地处理每个规则而不是全局优化。 

## 方法

 ### 蛮力方法

 强力解决方案将使用广度优先搜索或穷举递归来尝试所有可能的有效转换。 在每一步中，它都会尝试所有可能的插入、删除和替换，然后检查生成的密码是否强。 

这种方法在概念上是正确的，因为它探索每个可访问的密码配置并找到最少的编辑次数。 

然而，这在计算上是不可行的。 在每个位置我们都可以：

 - 插入许多可能的字符
 - 替换为许多可能的字符
 - 删除字符

 分支因子很快就会变得巨大。 即使对于中等长度的密码，状态空间也会呈指数级爆炸。 

因此，暴力方法实际上无法在合理的时间内解决问题。 

### 最优贪心法

 关键的见解是这三个约束以可预测的方式相互作用。 

我们可以分别分析：

 - 缺少角色类别
 - 重复角色运行
 - 长度违规

 最重要的观察是重复的序列决定了替换需求。 对于任何长度的运行`L`，我们需要`L // 3`如果我们只使用替换品的话。 

例如：

-`"aaa"`需要 1 次更换
 -`"aaaaaa"`需要 2 个替换件
 -`"aaaaaaaa"`需要 2 个替换件

 当密码太长时，必须删除。 关键的优化是删除可以减少所需替换的数量。 因此，我们贪婪地从重复组中删除字符，其中删除提供了最大的好处。 

删除策略取决于模 3 的余数：

 - 团体有`length % 3 == 0`一次删除即可立即受益
 - 团体有`length % 3 == 1`受益于两次删除
 - 团体有`length % 3 == 2`受益于三项删除

 这种贪婪排序最大限度地减少了总操作量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 探索所有可能的编辑序列 |
 | 最佳| O(n) | O(n) | 重复和长度的贪心分析 |

 ## 算法演练

 1. 统计缺失的字符类别。 

我们扫描一次密码并判断其中是否包含：

 - 一个小写字母
 - 一个大写字母
 - 一个数字

 缺失类别的数量很重要，因为替换或插入可以同时满足这些要求。 
2. 识别重复字符组。 

我们扫描字符串并找到连续的相同字符。 

例如：

-`"aaabbcccc"`产生一定长度的运行`[3, 2, 4]`任何长度至少为 3 的运行都违反了重复规则。 
3. 处理短密码情况。 

如果密码长度小于6，则需要插入。 

插入还可以修复：

 - 缺少字符类型
 - 重复违规

 因此，答案就变成：```
max(missing_types, 6 - length)
```因为每次插入都可能同时解决这两个问题。 
4. 计算有效长度密码的替换要求。 

对于每个长度的重复组`L`，所需的替换是：$\left\lfloor \frac{L}{3} \right\rfloor$我们将所有组的这个值相加。 
5. 处理有效长度的情况。 

如果密码长度已经在 6 到 20 之间（含 6 和 20），则无需删除。 

最终的答案是：```
max(missing_types, replacements)
```因为替换可以同时修复缺失的类别和重复的序列。 
6. 处理超长的箱子。 

如果密码长度超过20位，则强制删除。 

让：$\text{deletions} = n - 20$我们贪婪地将删除应用于重复组以减少未来的替换成本。 
7. 按模类确定删除的优先级。 

对于长度重复组`L`：

- 如果`L % 3 == 0`，删除 1 个字符会减少 1 个替换
 - 如果`L % 3 == 1`，删除 2 个字符会减少 1 个替换
 - 如果`L % 3 == 2`，删除 3 个字符减少替换 1 个字符

 我们按此顺序处理组，因为它可以为每次删除提供最佳的减少量。 
8. 应用剩余的删除。 

在有针对性的删除之后，任何剩余的删除仍然可以进一步减少三个块的替换。 
9. 计算最终答案。 

总操作等于：```
mandatory deletions + max(missing_types, remaining_replacements)
```### 为什么它有效

 该算法之所以有效，是因为每个约束都可以独立量化，并且每个操作都有可预测的效果。 

对于短密码，插入占主导地位，因为长度必须增加。 对于有效长度密码，替换占主导地位，因为不需要删除。 对于过长的密码，删除是不可避免的，因此最佳策略是在最大程度地减少未来替换的情况下使用删除。 

基于模的贪婪删除排序是最佳的，因为它最大限度地减少了每次删除的替换减少成本。 

## Python 解决方案```python
class Solution:
    def strongPasswordChecker(self, password: str) -> int:
        n = len(password)

        has_lower = any(c.islower() for c in password)
        has_upper = any(c.isupper() for c in password)
        has_digit = any(c.isdigit() for c in password)

        missing_types = 3 - has_lower - has_upper - has_digit

        groups = []
        i = 0

        while i < n:
            j = i
            while j < n and password[j] == password[i]:
                j += 1

            length = j - i
            if length >= 3:
                groups.append(length)

            i = j

        if n < 6:
            return max(missing_types, 6 - n)

        replacements = sum(length // 3 for length in groups)

        if n <= 20:
            return max(missing_types, replacements)

        deletions = n - 20
        remaining_deletions = deletions

        groups.sort(key=lambda length: length % 3)

        for idx in range(len(groups)):
            length = groups[idx]

            if remaining_deletions <= 0:
                break

            if length % 3 == 0:
                delete_needed = 1
            elif length % 3 == 1:
                delete_needed = 2
            else:
                delete_needed = 3

            if remaining_deletions >= delete_needed:
                groups[idx] -= delete_needed
                remaining_deletions -= delete_needed
                replacements -= 1

        for idx in range(len(groups)):
            if remaining_deletions <= 0:
                break

            length = groups[idx]

            if length < 3:
                continue

            extra_reduce = min(
                replacements,
                remaining_deletions // 3
            )

            reduction = min(
                extra_reduce,
                (groups[idx] - 2) // 3
            )

            groups[idx] -= reduction * 3
            remaining_deletions -= reduction * 3
            replacements -= reduction

        return deletions + max(missing_types, replacements)
```实现首先检查存在哪些字符类别。 这`missing_types`变量记录缺少多少必需的类别。 

接下来，代码扫描密码并记录长度至少为 3 的所有重复组。这些组是唯一与替换计算相关的组。 

如果密码太短，算法立即返回`max(missing_types, 6 - n)`因为插入可以同时解决这两个问题。 

如果长度已经有效，那么唯一剩下的问题就是平衡缺失类别和重复修复。 更换可以同时解决这两个问题，因此两者中的最大值决定了答案。 

对于过长的密码，必须删除。 该算法对重复组进行排序`length % 3`因为这决定了删除效率。 它贪婪地在最有效地减少替换的地方应用删除。 

最后，在处理所有删除之后，答案将强制删除与剩余的替换或缺失类别要求结合起来。 

## 解决方案```go
package main

import (
	"sort"
	"unicode"
)

func strongPasswordChecker(password string) int {
	n := len(password)

	hasLower := false
	hasUpper := false
	hasDigit := false

	for _, ch := range password {
		if unicode.IsLower(ch) {
			hasLower = true
		}
		if unicode.IsUpper(ch) {
			hasUpper = true
		}
		if unicode.IsDigit(ch) {
			hasDigit = true
		}
	}

	missingTypes := 0
	if !hasLower {
		missingTypes++
	}
	if !hasUpper {
		missingTypes++
	}
	if !hasDigit {
		missingTypes++
	}

	groups := []int{}

	for i := 0; i < n; {
		j := i

		for j < n && password[j] == password[i] {
			j++
		}

		length := j - i

		if length >= 3 {
			groups = append(groups, length)
		}

		i = j
	}

	if n < 6 {
		return max(missingTypes, 6-n)
	}

	replacements := 0
	for _, length := range groups {
		replacements += length / 3
	}

	if n <= 20 {
		return max(missingTypes, replacements)
	}

	deletions := n - 20
	remainingDeletions := deletions

	sort.Slice(groups, func(i, j int) bool {
		return groups[i]%3 < groups[j]%3
	})

	for i := 0; i < len(groups); i++ {
		if remainingDeletions <= 0 {
			break
		}

		deleteNeeded := 0

		if groups[i]%3 == 0 {
			deleteNeeded = 1
		} else if groups[i]%3 == 1 {
			deleteNeeded = 2
		} else {
			deleteNeeded = 3
		}

		if remainingDeletions >= deleteNeeded {
			groups[i] -= deleteNeeded
			remainingDeletions -= deleteNeeded
			replacements--
		}
	}

	for i := 0; i < len(groups); i++ {
		if remainingDeletions <= 0 {
			break
		}

		if groups[i] < 3 {
			continue
		}

		reduction := min(
			(groups[i]-2)/3,
			remainingDeletions/3,
		)

		groups[i] -= reduction * 3
		remainingDeletions -= reduction * 3
		replacements -= reduction
	}

	return deletions + max(missingTypes, replacements)
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的算法结构。 主要差异与语言机制有关。 

Go 不提供 Python 风格的生成器表达式，因此类别检查是使用显式循环和布尔标志来实现的。 

重复组存储在整数切片中。 排序是使用`sort.Slice`。 

Go 字符串是字节索引的，这在这里是安全的，因为问题约束限制输入为 ASCII 字符。 

不需要特殊的 nil 处理，因为空切片在循环和排序操作中自然表现。

 ## 边缘情况

 ### 极短的密码

 密码类似`"a"`具有挑战性，因为它同时违反了多个约束。 它太短并且缺少字符类别。 简单的解决方案可能会错误地为每个问题分别添加操作。 

该实现正确地认识到插入可以同时解决这两个问题。 每个插入的字符都可以增加长度并引入缺失的类别。 

### 非常长的重复密码

 密码例如`"aaaaaaaaaaaaaaaaaaaaa"`超过最大长度并包含大量重复组。 一种简单的方法可能首先计算替换，然后独立添加删除，产生一个非最小答案。 

相反，在计算最终答案之前，实现策略性地使用删除来减少替换要求。 

### 多个独立重复组

 密码如`"aaaBBB111"`包含几个不同的违规运行。 每个组独立地贡献替换需求。 

该实现将密码扫描到单独的重复组中，并独立计算其替换成本，确保不会遗漏或重复计算违规序列。
