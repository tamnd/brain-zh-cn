[LeetCode 第 486 题](https://leetcode.com/problems/predict-the-winner/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、动态规划、递归、博弈论

 ## 解决方案

 ## 问题理解

 该问题描述了在整数数组上玩的两人游戏。 玩家轮流轮流，在每个回合中，玩家只能从数组两端之一获取一个数字。 所选值将添加到该玩家的分数中，并且该元素将从数组中删除。 游戏继续进行，直到所有元素都被拿走。 

目标是确定玩家 1 在两名玩家都发挥最佳的情况下是否可以保证获胜。 在此问题中，平局也被视为玩家 1 的胜利。 

输入是一个整数数组`nums`，其中每个元素代表一个可供选择的分数值。 由于玩家只能从最左边或最右边的剩余元素中进行选择，因此游戏状态完全由当前子数组决定。 

输出是一个布尔值：

 - 返回`true`如果玩家 1 可以以大于或等于玩家 2 的分数结束游戏。 
- 返回`false`如果玩家2可以迫使玩家1输。 

限制相对较小：

 -`1 <= nums.length <= 20`-`0 <= nums[i] <= 10^7`小数组长度是一个重要线索。 对于小输入来说，探索所有可能性的朴素递归解决方案在技术上是可行的，但它仍然呈指数增长，并且随着长度接近 20 而变得低效。这表明动态编程或记忆化是预期的优化。 

需要考虑一些重要的边缘情况：

 - 只有一个元素的数组。 玩家 1 立即拿走唯一的数字并获胜。 
- 两个玩家可以以相同分数结束的数组。 该问题明确指出，平局算作玩家 1 的胜利。 
- 具有重复值的数组，其中许多游戏路径看起来相同。 
- 贪婪策略失败的数组。 立即选择较大的一端并不总是能带来最佳的最终结果。 
- 包含零的数组，其中分数差异变得微妙。 

关键的挑战是两名球员都发挥最佳水平，这意味着每个决定都必须考虑到对手做出最佳反应。 

## 方法

 ### 蛮力方法

 暴力方法递归地模拟每种可能的游戏状态。 

在任何时候，当前玩家都有两个选择：

 - 取最左边的数字
 - 取最右边的数字

 做出选择后，对手在剩余的子数组上递归地发挥最佳效果。 

一个简单的实现是计算玩家 1 通过探索每个可能的移动序列可以获得的最大总分。 由于每个递归级别都分支为两种可能性，因此状态总数呈指数增长。 

这种方法是正确的，因为它详尽地评估了所有有效的游戏路径，并且始终假设双方都是最佳游戏。 然而，它会反复重新计算相同的子问题。 例如，可以从不同的递归路径对同一子数组求值多次。 

时间复杂度大约变为`O(2^n)`，即使对于中等大小的输入，这也是低效的。 

### 最优动态规划方法

 关键的见解是游戏是零和游戏。 

我们可以跟踪当前玩家和对手之间的分数差异，而不是分别跟踪两个玩家的绝对分数。 

定义：

-`dp(left, right)`= 使用子数组当前玩家可以达到的与对手的最大分数差`nums[left:right+1]`如果当前玩家选择左边的值：

 - 他们获得`nums[left]`- 然后对手成为剩余子数组的当前玩家
 - 对手的优势是`dp(left + 1, right)`所以得到的分数差就变成了：```
nums[left] - dp(left + 1, right)
```同样，如果当前玩家选择了正确的值：```
nums[right] - dp(left, right - 1)
```当前玩家选择更好的选项：```
dp(left, right) =
max(
    nums[left] - dp(left + 1, right),
    nums[right] - dp(left, right - 1)
)
```如果全阵的最终分数差为非负数，则玩家 1 可以保证至少平局。 

这将指数递归解决方案转换为具有重叠子问题的动态规划问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索每个可能的游戏序列 |
 | 最佳 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 使用 memoization 或 DP 重用子问题结果 |

 ## 算法演练

 1.定义递归函数`dfs(left, right)`返回索引子数组中当前玩家与对手的最大分数差`left`到`right`。 
2. 首先处理基本情况。 如果`left == right`，只剩下一个数字，所以当前玩家立即拿走它。 分数差异简单来说就是：```
nums[left]
```3. 对于较大的子阵列，请考虑两个可用的移动。 

如果当前玩家选择左边的元素：```
nums[left] - dfs(left + 1, right)
```减法很重要，因为移动后，对手就变成了当前玩家。 无论对手获得什么优势，都必须减少当前玩家的最终优势。 
4. 同样，如果当前玩家选择了正确的元素：```
nums[right] - dfs(left, right - 1)
```5. 选择使当前玩家的分差最大化的着法。```
max(left_choice, right_choice)
```6.使用memoization来存储之前计算的结果`(left, right)`州。 如果没有记忆化，许多子数组将被重复重新计算。 
7. 使用完整数组开始递归：```
dfs(0, n - 1)
```8. 如果返回的分数差大于等于0，则玩家1可以保证至少平局，所以返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为每个游戏状态都可以由子数组和当前玩家的身份表示。 递归关系正确地模拟了双方的最佳游戏。 每个玩家都最大化自己的分数差异，同时假设对手也发挥最佳。 由于每个子问题都通过记忆解决一次，因此最终结果代表了游戏的真正最佳结果。 

## Python 解决方案```python
from typing import List
from functools import lru_cache

class Solution:
    def predictTheWinner(self, nums: List[int]) -> bool:
        n = len(nums)

        @lru_cache(None)
        def dfs(left: int, right: int) -> int:
            if left == right:
                return nums[left]

            take_left = nums[left] - dfs(left + 1, right)
            take_right = nums[right] - dfs(left, right - 1)

            return max(take_left, take_right)

        return dfs(0, n - 1) >= 0
```实施从导入开始`lru_cache`，它为递归函数提供记忆。 记忆化至关重要，因为在递归过程中会出现许多重叠的子问题。 

这`dfs(left, right)`函数表示当前玩家在当前子数组中可以获得的最大分数差。 

基本情况处理长度为一的子数组。 如果只剩下一个数字，则当前玩家必须拿走它，因此分数差等于该数字。 

对于较大的子数组，该函数会计算两个有效的移动：

 - 取最左边的数字
 - 取最右边的数字

 拿走一个数字后，对手在剩余的子阵列上发挥最佳作用。 自从`dfs()`返回对手的未来优势，该值从当前玩家的增益中减去。 

该函数返回两个选择中的最大值，因为当前玩家总是选择最佳走法。 

最后，该算法评估整个数组并检查所得分数差异是否为非负数。 非负值意味着玩家 1 至少可以确保平局。 

## 解决方案```go
package main

func predictTheWinner(nums []int) bool {
	n := len(nums)

	memo := make([][]int, n)
	visited := make([][]bool, n)

	for i := 0; i < n; i++ {
		memo[i] = make([]int, n)
		visited[i] = make([]bool, n)
	}

	var dfs func(int, int) int

	dfs = func(left int, right int) int {
		if left == right {
			return nums[left]
		}

		if visited[left][right] {
			return memo[left][right]
		}

		takeLeft := nums[left] - dfs(left+1, right)
		takeRight := nums[right] - dfs(left, right-1)

		if takeLeft > takeRight {
			memo[left][right] = takeLeft
		} else {
			memo[left][right] = takeRight
		}

		visited[left][right] = true

		return memo[left][right]
	}

	return dfs(0, n-1) >= 0
}
```Go 实现遵循与 Python 解决方案相同的动态编程策略，但记忆是手动实现的。 

由于 Go 没有像 Python 那样提供内置的记忆化装饰器`lru_cache`，使用两个 2D 切片：

 -`memo`存储计算结果
 -`visited`跟踪状态是否已被计算

 这避免了歧义，因为有效的分数差异也可能为零。 

使用 Go 切片而不是固定数组，因为输入大小是动态的。 整数溢出不是问题，因为最大总分完全在 Go 的整数范围内。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^2) | O(n^2) | 有`n * n`可能的子数组状态 |
 | 空间| O(n^2) | O(n^2) | 记忆化为每个子数组存储一个值 |

 递归考虑了所有可能的情况`(left, right)`只配对一次，因为记忆可以防止重复计算。 由于有`n^2`不同的子数组，总时间复杂度为`O(n^2)`。 

记忆表还为每个子数组存储一个值，需要`O(n^2)`空间。 递归栈最多添加`O(n)`额外的空间，但备忘录表主导了整体内存使用。

 ## 边缘情况

 单元素数组是最简单的输入。 由于玩家 1 总是先移动，因此他们立即拿走唯一的数字并获胜。 如果基本情况处理不正确，递归解决方案可能会失败。 实施明确检查`left == right`并直接返回剩余数。 

两个玩家以相同分数结束的数组是另一个重要的情况。 许多实现错误地要求玩家 1 具有严格更高的分数。 该问题指出，平局算作玩家 1 的胜利，因此最终条件必须是：```
score_difference >= 0
```而不是：```
score_difference > 0
```贪婪选择失败的情况尤其危险。 例如：```
[1, 5, 233, 7]
```天真的贪婪算法可能总是立即获取较大的最终值，但最佳游戏通常需要牺牲短期收益以获得更好的未来结果。 动态规划解决方案通过递归地评估每个移动的完整结果来避免这个问题。 

重复值和零重数组也可能暴露记忆错误。 不同的递归路径可能会产生相同的状态，并且如果没有缓存，算法会变得指数级缓慢。 记忆化实现保证每个子数组状态仅计算一次。
