[LeetCode 第 441 题](https://leetcode.com/problems/arranging-coins/)

 **难度：** 🟢简单
 **主题：** 数学、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们确定使用精确的方法可以形成多少完整的硬币楼梯行`n`硬币。 

楼梯的布置遵循非常具体的结构：

 - 第一行包含`1`硬币
 - 第二行包含`2`硬币
 - 第三行包含`3`硬币
 - 继续这种模式，`kth`行恰好包含`k`硬币

 楼梯必须按顺序逐行搭建。 如果没有足够的剩余硬币来完全完成下一行，则构建停止，并且我们返回完全完成的行数。 

例如，如果`n = 5`:

 - 第 1 行使用 1 个硬币，剩余 = 4
 - 第 2 行使用 2 个硬币，剩余 = 2
 - 第 3 行需要 3 个硬币，但只剩下 2 个

 由于第三行无法完成，所以答案是`2`。 

输入是单个整数`n`，代表可用硬币的总数。 输出是一个整数，表示完整楼梯行的最大数量。 

约束条件很重要：```
1 <= n <= 2^31 - 1
```这意味着`n`最大可达 2,147,483,647。 简单的模拟可能仍然适用于此范围，因为行数大约随着平方根的增长而增长`n`，但这个问题强烈表明我们应该仔细考虑效率和可能的数学优化。 

一个重要的数学观察是建造所需的硬币总数`k`完整的行是：$1+2+3+\cdots+k=\frac{k(k+1)}{2}$所以真正的目标是找到最大的整数`k`这样：$\frac{k(k+1)}{2}\le n$一些边缘情况很重要：

 - 非常小的输入，例如`n = 1`- 精确形成完美楼梯的输入，例如`n = 6`- 下一行仅差一枚硬币的输入，例如`n = 5`- 附近非常大的值`2^31 - 1`，在某些语言中溢出可能成为一个问题

 该问题保证了`n`始终为正，因此我们永远不需要处理零或负输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是模拟一次建造一排楼梯。 

我们从行开始`1`，减去所需的硬币数量`n`，然后移动到行`2`，并继续，直到我们不再有足够的硬币来完成下一行。 

例如：

 - 减去1个硬币
 - 减去2个硬币
 - 减去3个硬币
 - 当剩余足够的硬币时继续

 当剩余硬币小于下一行的大小时，我们停止并返回已完成的行数。 

这种方法是正确的，因为它完全反映了问题陈述中描述的构建过程。 每个成功的减法对应于一个完全完成的行。 

时间复杂度约为`O(sqrt(n))`，因为可以形成的行数大致随平方根增长`n`。 

尽管对于给定的约束来说这已经足够快了，但我们可以通过使用数学和二分搜索做得更好。 

### 最佳方法

 关键的见解是所需的硬币数量`k`rows 遵循已知的算术级数公式：$\frac{k(k+1)}{2}$我们可以直接搜索最大的有效行，而不是逐行构建`k`满意：$\frac{k(k+1)}{2}\le n$这个条件是单调的：

 - 如果有一些`k`有效，那么所有较小的值也有效
 - 如果有一些`k`不起作用，那么所有较大的值也会失败

 这种单调特性使二分搜索成为理想的解决方案。 

我们在范围内搜索`[1, n]`:

 - 计算中点`mid`- 计算需要多少硬币`mid`行
 - 如果所需硬币小于或等于`n`， 然后`mid`是有效的，所以我们尝试更大的值
 - 否则，`mid`太大，所以我们搜索较小的值

 这将时间复杂度降低到`O(log n)`。

 ## 算法演练

 1.初始化两个指针，`left`和`right`。 

我们在范围内寻找答案`[1, n]`。 最小可能的答案是1，最大可能的答案不能超过`n`。 
2. 启动二分查找循环 while`left <= right`。 

这确保了系统地检查每个可能的候选值。 
3. 计算中点。```
mid = (left + right) // 2
```中点表示完整行的候选数。 
4.计算所需金币数量`mid`行。 

使用算术级数公式：$\text{coins}=\frac{mid(mid+1)}{2}$5. 比较所需的硬币`n`。 

- 如果所需的数量正好`n`，我们找到了完美的楼梯，所以返回`mid`- 如果所需数量小于`n`， 然后`mid`是有效的，但可能存在更大的答案
 - 如果所需数量大于`n`， 然后`mid`太大了
 6. 相应调整搜索范围。 

- 有效中点：```
left = mid + 1
```- 无效的中点：```
right = mid - 1
```7. 继续，直到搜索空间耗尽。 

在搜索结束时，`right`将包含完整行的最大有效数量。 

### 为什么它有效

 二分查找之所以有效，是因为该函数：$f(k)=\frac{k(k+1)}{2}$是严格增加的。 作为`k`随着增长，所需的硬币数量也会不断增加。 

因此：

 - 所有有效值出现在所有无效值之前
 - 二分查找可以高效定位它们之间的边界

 算法总是收敛到最大的`k`满意：$\frac{k(k+1)}{2}\le n$这正是问题的定义。 

## Python 解决方案```python
class Solution:
    def arrangeCoins(self, n: int) -> int:
        left = 1
        right = n

        while left <= right:
            mid = (left + right) // 2
            required_coins = mid * (mid + 1) // 2

            if required_coins == n:
                return mid

            if required_coins < n:
                left = mid + 1
            else:
                right = mid - 1

        return right
```实现首先设置二分搜索边界。 搜索空间包括所有可能的楼梯行数`1`到`n`。 

在循环内部，中点被视为候选答案。 该代码计算需要多少硬币才能构建那么多行。 

如果所需数量匹配`n`，楼梯很完美，所以立即返回答案。 

如果所需的硬币少于可用的硬币，则候选者有效，并且算法尝试通过向上移动左边界来找到更大的有效值。 

如果需要的硬币太多，中点就无效，所以右边界向下移动。 

当循环结束时，`right`存储返回的最大有效完整行数。 

Python 整数自动安全地处理大值，因此在此实现中不存在溢出问题。 

## 解决方案```go
func arrangeCoins(n int) int {
    left := 1
    right := n

    for left <= right {
        mid := left + (right-left)/2

        requiredCoins := int64(mid) * int64(mid+1) / 2

        if requiredCoins == int64(n) {
            return mid
        }

        if requiredCoins < int64(n) {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }

    return right
}
```Go 实现遵循与 Python 版本相同的二分搜索逻辑。 主要区别在于整数溢出处理。 

自从`mid * (mid + 1)`可能超出 32 位整数的范围，计算被显式转换为`int64`乘法之前。 这可以防止附近的大输入值溢出`2^31 - 1`。 

中点计算使用：```go
mid := left + (right-left)/2
```这是一种常见的溢出安全二分搜索模式。

 ## 边缘情况

 一个重要的边缘情况是尽可能最小的输入，`n = 1`。 有错误的实现可能会错误地返回`0`如果二分搜索边界初始化不正确。 在此解决方案中，搜索开始于`1`，并且该公式正确地识别出可以构建一个完整的行。 

另一个重要的边缘情况发生在`n`恰好是一个三角数，例如`n = 6`或者`n = 10`。 在这种情况下，楼梯就可以完美完成，没有剩余的硬币。 该实现正确处理了这个问题，因为它立即返回`mid`当所需的硬币数量恰好等于`n`。 

第三种临界边缘情况涉及接近约束上限的极大值。 在 Go 中，大整数相乘可能会溢出 32 位整数类型。 该实现通过将中间计算转换为`int64`乘法之前。 即使对于`n = 2147483647`。 

当答案位于无效中点正下方时，会出现另一种微妙的边缘情况。 例如，与`n = 5`, 中点`3`需要`6`硬币并且无效，而`2`是正确的答案。 返回`right`after 循环保证我们返回最大的有效值而不是第一个无效值。
