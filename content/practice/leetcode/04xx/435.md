[LeetCode 第 435 题](https://leetcode.com/problems/non-overlapping-intervals/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、贪心、排序

 ## 解决方案

 ## 问题理解

 该问题给出了一个间隔数组，其中每个间隔表示为`[start, end]`。 每个区间描述数轴上的连续范围。 任务是删除最少数量的间隔，使剩余的间隔不再重叠。 

如果一个间隔在另一个间隔结束之前开始，则两个间隔重叠。 然而，仅在边界处接触的间隔被认为是不重叠的。 例如，`[1,2]`和`[2,3]`一起有效，因为第一个间隔的结束等于第二个间隔的开始。 

输出不是剩余间隔的集合。 相反，我们必须返回需要删除的最小间隔数。 

约束条件很重要：

 - 最多可以有`10^5`间隔
 - 间隔值可以为负数
 - 每个区间满足`start < end`由于输入大小非常大，任何解决方案都比大约更糟糕`O(n log n)`可能会超时。 这立即排除了大多数暴力或二次动态规划方法。 

尽早识别一些边缘情况很重要：

 - 已经不重叠的间隔，答案应该是`0`- 间隔全部相同，我们必须删除除一个之外的所有间隔
 - 与端点完全接触的间隔，这些不应算作重叠
 - 嵌套间隔，例如`[1,10]`和`[2,3]`，选择错误的保留间隔可能会导致以后更多的删除
 - 负间隔值、排序和比较必须仍然正常工作

 核心挑战是决定在发生重叠时保留哪个间隔。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试每个可能的间隔子集，并检查剩余间隔是否不重叠。 在所有有效子集中，我们将选择保留最大间隔数的子集，然后计算删除了多少个。 

对于每个子集：

 1. 检查区间是否重叠
 2. 跟踪最大有效子集
 3. 计算移除量为`n - kept`这保证了正确的答案，因为每种可能的配置都被探索过。 

然而，子集的数量`n`间隔是`2^n`。 和`n`最多`100000`，这种做法是完全不可行的。 

另一种可能的暴力方式方法是使用成对比较的动态编程，类似于最长递增子序列。 该方法将对间隔进行排序并计算最大非重叠链`O(n^2)`时间。 虽然比指数时间好得多，但对于问题约束来说仍然太慢。 

### 最优贪心法

 关键的见解是，当间隔重叠时，我们应该保留较早结束的间隔。 

为什么这有帮助？ 

假设我们有两个重叠的区间：

 -`[1,5]`-`[2,3]`如果我们保留`[1,5]`，它会阻塞许多未来的间隔，因为它向右延伸得很远。 

如果我们保留`[2,3]`，我们为未来的间隔留出更多空间。 

这是一个经典的区间调度贪心策略。 通过始终保持间隔具有最小的终点，我们可以最大化未来间隔的剩余空间，从而最大限度地减少移除。 

算法变为：

 1.按照结束时间对区间进行排序
 2. 贪婪地保留其开始点至少是前一个保留的间隔结束点的间隔
 3. 将重叠计算为移除

 这可以有效地工作在`O(n log n)`时间，因为排序在运行时占主导地位。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) 或 O(n^2) DP | O(n) | 探索多种间隔组合 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(log n) | 按最早结束时间进行贪婪调度 |

 ## 算法演练

 1. 按结束值对所有间隔进行排序。 

按结束时间排序是关键的贪心步骤。 较早结束的间歇期更加灵活，因为它们为未来的间歇期留下了更多空间。 
2. 初始化一个变量来跟踪最后一个非重叠间隔的结束位置。 

排序后，我们首先保留第一个区间，因为它具有最早的结束点。 
3. 迭代剩余的时间间隔。 

对于每个间隔，将其起始值与先前保留的间隔的结束值进行比较。 
4. 如果当前间隔在前一个间隔结束之前开始，则存在重叠。 

在这种情况下，我们删除当前间隔。 由于间隔按结束时间排序，因此当前间隔不能早于保留的间隔结束，因此保留较早结束的间隔始终是最佳选择。 
5. 如果当前间隔在上一个间隔结束时或之后开始，则间隔不会重叠。 

我们保留当前间隔并更新跟踪的最终值。 
6. 继续，直到处理完所有间隔。 
7. 返回删除的间隔数。 

### 为什么它有效

 贪婪不变量是，在处理到某个点的区间后，我们总是保持最大可能数量的非重叠区间和最小可能的结束边界。 

选择最早结束时间的间隔始终是安全的，因为它为未来的间隔留下了最大的空间。 任何保留较晚结束的重叠间隔的解决方案都可以替换为较早结束的重叠间隔，而不会减少我们最终可以保留的间隔数量。 

这保证了贪心策略产生最优解。 

## Python 解决方案```python
from typing import List

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        if not intervals:
            return 0

        # Sort by ending time
        intervals.sort(key=lambda interval: interval[1])

        removals = 0

        # Keep the first interval
        previous_end = intervals[0][1]

        # Process remaining intervals
        for start, end in intervals[1:]:
            # Overlap detected
            if start < previous_end:
                removals += 1
            else:
                previous_end = end

        return removals
```尽管约束保证至少有一个间隔，但该实现首先处理空输入情况。 包含此检查可以使函数更加健壮。 

接下来，间隔按其结束值排序。 这种顺序使得贪婪策略能够正确发挥作用。 

变量`previous_end`存储我们决定保留的最后一个间隔的结束边界。 最初，我们保留第一个间隔，因为它在排序后最早结束。 

在迭代过程中，每个间隔都会被检查`previous_end`。 

如果`start < previous_end`，间隔重叠，因此我们增加移除计数器。 

如果`start >= previous_end`，间隔不重叠，所以我们保留间隔并更新`previous_end`。 

因为间隔已经按结束时间排序，所以我们永远不需要重新考虑之前的决定。 

## 解决方案```go
package main

import "sort"

func eraseOverlapIntervals(intervals [][]int) int {
	if len(intervals) == 0 {
		return 0
	}

	// Sort by ending time
	sort.Slice(intervals, func(i, j int) bool {
		return intervals[i][1] < intervals[j][1]
	})

	removals := 0

	// Keep the first interval
	previousEnd := intervals[0][1]

	// Process remaining intervals
	for i := 1; i < len(intervals); i++ {
		start := intervals[i][0]
		end := intervals[i][1]

		// Overlap detected
		if start < previousEnd {
			removals++
		} else {
			previousEnd = end
		}
	}

	return removals
}
```Go 实现遵循与 Python 版本相同的贪婪逻辑。 

主要区别在于使用`sort.Slice`对间隔进行排序。 Go 切片是可变的，因此排序就地进行。 

Go 在这里不需要对整数溢出进行特殊处理，因为间隔边界相对于 Go 的整数范围来说很小。 

与 Python 不同，Go 不支持直接在循环中解包元组，因此使用索引手动提取间隔值。

 ## 边缘情况

 一种重要的边缘情况是间隔恰好接触其边界，例如`[1,2]`和`[2,3]`。 一个常见的错误是使用`<=`而不是`<`检查重叠时。 该问题明确指出触摸间隔是不重叠的。 实现正确使用`start < previous_end`，它允许边界接触区间共存。 

另一个重要的边缘情况是嵌套间隔。 考虑`[1,10]`,`[2,3]`， 和`[3,4]`。 保留遇到的第一个间隔的幼稚策略将保留`[1,10]`并删除另外两个，导致删除次数超出必要。 贪心策略通过按结束时间排序并始终保留最早完成的间隔来避免此问题。 

第三种关键边缘情况是所有区间完全重叠，例如`[[1,2],[1,2],[1,2]]`。 在这种情况下，只能保留一个间隔。 该实现正确地将每个后续间隔计数为重叠，并删除除一个之外的所有间隔。 

另一个微妙的情况涉及负值，例如`[[-5,-3],[-3,-1],[-2,0]]`。 由于该算法仅依赖于排序和比较，因此自然地处理负数，无需任何特殊逻辑。
