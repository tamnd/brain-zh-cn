[LeetCode 第 424 题](https://leetcode.com/problems/longest-repeating-character-replacement/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`仅由大写英文字母和整数组成`k`。 我们最多可以表演`k`更换操作。 在一次操作中，我们可以将字符串中的任何字符更改为任何其他大写英文字符。 

目标是找到最长的子串的长度，该子串最多执行一次后可以转化为只包含一个重复字符的子串`k`替代品。 

简单来说，我们想要字符串的最大连续部分，在其中我们可以通过最多更改来使所有字符相同`k`人物。 

例如，考虑子字符串`"AABA"`和`k = 1`。 这个子串可以变成`"AAAA"`通过更换单个`'B'`和`'A'`。 由于只需要替换一次，因此该子串是有效的。 

输入约束很重要：

 - 字符串长度可以大到`10^5`- 字符串仅包含大写英文字母
 -`k`范围可以从`0`到字符串的长度

 这些限制立即告诉我们，`O(n^2)`或者更糟糕的解决方案对于大量输入可能会变得太慢。 我们需要一种能够有效地处理字符串的算法，最好是在线性时间内。 

一些边缘情况很重要：

 - 当`k = 0`，我们无法替换任何内容，因此我们只是寻找相同连续字符的最长序列。 
- 什么时候`k >= len(s)`，整个字符串始终可以转换为单个重复字符。 
- 具有所有相同字符的字符串应立即返回完整的字符串长度。 
- 具有高度交替字符的字符串，例如`"ABABABAB"`，强调算法是否正确维护替换计数。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查每个可能的子字符串，并确定是否可以使用最多使用将其转换为相同字符的子字符串`k`替代品。 

对于每个子串：

 1.统计每个字符出现的频率。 
2. 识别出现频率最高的字符。 
3. 计算需要更换的数量。 

如果子串有长度`L`并且出现最频繁的字符`maxFreq`次，那么：```
replacementsNeeded = L - maxFreq
```这是有效的，因为最佳策略始终是保留最常见的角色并替换所有其他角色。 

如果`replacementsNeeded <= k`，则该子串有效。 

蛮力方法是正确的，因为它详尽地检查了每个可能的子字符串。 然而，对于输入限制来说，它太慢了。 有`O(n^2)`子串，并且评估每个子串可能需要`O(26)`或更长时间。 

### 最佳解决方案的关键见解

 关键的观察是子字符串有效：```
windowLength - maxCharacterFrequency <= k
```这意味着非主导字符的字符数不得超过`k`。 

我们可以使用滑动窗口，而不是独立检查每个子字符串。 这个想法是保持最大的有效窗口，同时一次扩展一个字符的右边界。 

当我们扩大窗口时：

 - 我们跟踪字符频率。 
- 我们跟踪当前窗口中最常见字符的频率。 
- 如果窗口变得无效，我们会从左侧缩小它，直到它再次变得有效。 

这允许我们最多处理每个字符两次，一次进入窗口时，一次离开窗口时，给出`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 独立检查每个子字符串 |
 | 最佳 | O(n) | O(1) | O(1) | 带频率跟踪的滑动窗口 |

 ## 算法演练

 ### 最优滑动窗口算法

 1.初始化两个指针，`left`和`right`，表示当前窗口边界。 

该窗口将代表当前正在分析的子字符串。 
2. 维护当前窗口内字符的频率图。 

由于字符串仅包含大写英文字母，因此地图大小以 26 为界限。 
3. 跟踪当前窗口中最常见字符的出现频率。 

该值至关重要，因为所需的更换数量为：```
windowSize - maxFrequency
```4. 通过移动扩大窗口`right`一次一步。 

对于每个新角色：

 - 增加其在地图中的出现频率。 
- 更新`maxFrequency`如果需要的话。 
5. 检查当前窗口是否有效。 

该窗口在以下情况下有效：```
(right - left + 1) - maxFrequency <= k
```这意味着我们可以在允许的操作次数内替换所有非主导字符。 
6. 如果窗口无效，请从左侧缩小它。 

- 减少频率`s[left]`- 移动`left`前进

 继续缩小，直到窗口再次有效。 
7. 跟踪迄今为止看到的最大有效窗口长度。 

由于每个有效窗口都代表一个候选答案，因此我们不断更新最佳结果。 

### 为什么它有效

 滑动窗口保持当前窗口始终有效或在无效时立即调整的不变性。 关键的观察结果是，窗口所需的最小替换次数仅取决于该窗口中最常见的字符。 

通过始终贪婪地扩展并仅在必要时收缩，我们确保有效地考虑每个有效窗口。 由于每个指针最多移动`n`次，算法以线性时间运行。 

## Python 解决方案```python
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        frequency = {}
        
        left = 0
        max_frequency = 0
        longest = 0
        
        for right in range(len(s)):
            current_char = s[right]
            
            frequency[current_char] = frequency.get(current_char, 0) + 1
            
            max_frequency = max(
                max_frequency,
                frequency[current_char]
            )
            
            window_length = right - left + 1
            
            while window_length - max_frequency > k:
                left_char = s[left]
                frequency[left_char] -= 1
                left += 1
                
                window_length = right - left + 1
            
            longest = max(longest, window_length)
        
        return longest
```该实现首先创建一个频率字典来存储当前窗口内每个字符的计数。 

这`left`指针标记滑动窗口的开始，而`right`指针在字符串中扩展。 

每当一个新字符进入窗口时，其频率就会增加。 我们还更新了`max_frequency`，它存储当前窗口中看到的任何字符的最高频率。 

中心有效性条件是：```python
window_length - max_frequency <= k
```如果这个条件失败，则窗口需要太多替换，因此我们从左侧缩小它，直到它再次有效。 

每一步，我们都会更新`longest`遇到的最大有效窗口长度。 

一个重要的优化是`max_frequency`永远不会减少。 尽管它偶尔可能会变得陈旧，但该算法仍然可以正确工作，因为窗口仅在明确无效时才会缩小。 这保留了线性复杂性。 

## 解决方案```go
func characterReplacement(s string, k int) int {
    frequency := make(map[byte]int)

    left := 0
    maxFrequency := 0
    longest := 0

    for right := 0; right < len(s); right++ {
        currentChar := s[right]

        frequency[currentChar]++

        if frequency[currentChar] > maxFrequency {
            maxFrequency = frequency[currentChar]
        }

        windowLength := right - left + 1

        for windowLength-maxFrequency > k {
            leftChar := s[left]
            frequency[leftChar]--

            left++
            windowLength = right - left + 1
        }

        if windowLength > longest {
            longest = windowLength
        }
    }

    return longest
}
```Go 实现遵循与 Python 版本相同的滑动窗口逻辑。 

一个`map[byte]int`用于字符频率，因为字符串包含 ASCII 大写字母。 Go 字符串是字节可索引的，因此使用`byte`是高效的。 

与 Python 字典不同，Go 映射需要显式的存在处理，但增加不存在的键自然会起作用，因为缺失的条目默认为零。 

整数溢出不是问题，因为最大字符串长度仅为`10^5`。

 ## 边缘情况

 ### 情况 1：不允许更换

 考虑：```
s = "ABAA"
k = 0
```有缺陷的实现可能仍会尝试扩展包含混合字符的窗口。 然而，当`k = 0`，只有已经由相同字符组成的子字符串才有效。 

该算法自然地处理这个问题，因为有效性条件变为：```
windowLength - maxFrequency <= 0
```仅当窗口中的每个字符都相同时才会出现这种情况。 

### 情况 2：可以替换整个字符串

 考虑：```
s = "ABCDE"
k = 5
```由于我们可以根据需要替换每个字符，因此答案应该是整个字符串长度。 

某些实现错误地不必要地缩小了窗口。 滑动窗口解决方案正确认识到：```
5 - 1 <= 5
```所以整个字符串仍然有效。 

### 情况 3：交替字符

 考虑：```
s = "ABABABAB"
k = 1
```交替模式很棘手，因为窗口随着增长而反复变得无效。 

简单的实现可能会错误地跟踪收缩后的主频率。 该解决方案通过维持非递减关系避免了该问题`max_frequency`，在保持线性运行时间的同时仍然保证了正确性。 

### 情况 4：单个字符串

 考虑：```
s = "A"
k = 0
```小输入通常会在窗口计算中暴露出相差一的错误。 

该实现正确初始化窗口、处理单个字符并返回`1`无需任何特殊情况处理。
