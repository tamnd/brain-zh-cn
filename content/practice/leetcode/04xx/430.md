[LeetCode 430 题](https://leetcode.com/problems/flatten-a-multilevel-doubly-linked-list/)

 **难度：** 🟡 中等
 **主题：** 链表、深度优先搜索、双向链表

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一种特殊类型的双向链表，其中每个节点包含四个字段：```
val
prev
next
child
```这`next`和`prev`指针的行为与普通的双向链表完全相同。 额外的`child`指针引入了另一个从当前节点向下分支的链表。 该子列表本身可以包含带有自己的子指针的节点，从而创建递归多级结构。 

任务是将这个多级结构转换为单个展平的双向链表。 展平顺序遵循深度优先遍历模式。 每当节点有子列表时，整个子列表必须立即插入到当前节点之后和最初的下一个节点之前。 

例如，假设节点`3`有一个从以下位置开始的子列表`7`：```
1 - 2 - 3 - 4
        |
        7 - 8
```展平后，列表变为：```
1 - 2 - 3 - 7 - 8 - 4
```重要的细节是原始顺序仍必须保留。 子列表被插入到位，而不是附加在末尾。 

输出必须保持有效的双向链表。 这意味着：

 - 每个`next`指针必须正确
 - 每个`prev`指针必须正确
 - 每个`child`指针必须设置为`null`约束告诉我们节点总数最多为`1000`。 这个值足够小，即使是递归解决方案在实践中也是安全的，尽管迭代方法也是完全合理的。 由于该结构是基于指针而不是基于数组，因此主要挑战是正确地重新连接指针而不丢失列表的部分内容。 

一些边缘情况很重要：

 - 输入内容可能为空
 - 一个节点可能没有子节点
 - 可能存在多层嵌套
 - 子列表本身可能包含子列表
 - 子列表的尾部必须正确地重新连接到原始列表`next`节点
 - 每个`child`指针最终必须变成`null`如果在保存指针之前覆盖指针，则幼稚的实现很容易丢失对列表部分的引用。 

## 方法

 ### 暴力方法

 一种简单的暴力策略是重复扫描列表以查找具有子指针的节点。 每当找到这样的节点时，我们将子列表拼接到主列表中，然后继续扫描，直到没有子指针剩余。 

该算法之所以有效，是因为每次迭代都会减少剩余子指针的数量。 最终结构变得完全扁平化。 

然而，这种方法效率低下，因为列表可能会被重新扫描多次。 在深度嵌套结构中，相同的节点会被重复访问。 指针操作也变得很麻烦，因为重新连接尾部需要额外的遍历工作。 

尽管限制相对较小，但这种重复扫描会带来不必要的开销。 

### 最佳方法

 关键的见解是，扁平化自然会遵循深度优先遍历。 

当我们遇到一个有子节点的节点时：

 1.保存原件`next`节点
 2. 递归地展平子列表
 3. 将展平的子列表插入到当前节点之后
 4. 将子列表的尾部连接回保存的`next`节点

 这是有效的，因为子列表必须完全出现在原始列表之前`next`扁平化排序中的节点。 

递归深度优先搜索在这里特别干净，因为每个递归调用都可以返回展平子列表的尾部。 这条尾巴正是我们重新连接其余节点所需要的。 

每个节点都被处理一次，而不是重复地重新扫描列表的各个部分。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复扫描列表定位并拼接子列表 |
 | 最佳 | O(n) | O(n) | DFS 扁平化处理每个节点一次 |

 ## 算法演练

 ### 最优DFS算法

 1、从链表头部开始，逐个节点遍历。 

我们使用从左到右的正常顺序处理列表`next`指针。 
2.对于每个节点，首先保存其原始的`next`指针。 

这一步很关键，因为一旦我们附加了子列表，原始列表就会被删除。`next`否则参考将会丢失。 
3. 如果当前节点没有子节点，则继续前进。 

在这种情况下不需要进行结构修改。 
4. 如果当前节点有子列表，则递归地展平该子列表。 

递归调用返回展平子部分的尾节点。 这很重要，因为我们稍后需要重新连接原来的`next`子链结束后的节点。 
5、在当前节点和原节点之间插入子列表`next`。 

连接变为：```
current.next = child_head
child_head.prev = current
```6. 删除子指针。 

该问题明确要求每个`child`指针变为`null`。 
7. 将展平的子列表的尾部连接回保存的`next`节点。 

如果原来的`next`节点存在：```
child_tail.next = next_node
next_node.prev = child_tail
```8.从保存的继续遍历`next`节点。 

这确保了整个结构按照深度优先的顺序进行处理。 
9. 返回展平段的尾节点。 

返回尾部允许父递归调用有效地重新连接列表，而无需重新扫描。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 在每次递归返回时，从当前节点开始的子列表都被完全展平并正确连接。 

因为每个子列表在重新连接原始列表之前都已完全展平`next`节点，最终的顺序与所需的深度优先遍历顺序完全匹配。 每个节点都被访问一次，并且每个指针都会一致更新。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, val, prev, next, child):
        self.val = val
        self.prev = prev
        self.next = next
        self.child = child
"""

from typing import Optional

class Solution:
    def flatten(self, head: 'Optional[Node]') -> 'Optional[Node]':

        def dfs(node: 'Optional[Node]') -> 'Optional[Node]':
            current = node
            last = node

            while current:
                next_node = current.next

                if current.child:
                    child_head = current.child
                    child_tail = dfs(child_head)

                    current.next = child_head
                    child_head.prev = current
                    current.child = None

                    if next_node:
                        child_tail.next = next_node
                        next_node.prev = child_tail

                    last = child_tail
                else:
                    last = current

                current = next_node

            return last

        if not head:
            return None

        dfs(head)
        return head
```该实现使用辅助 DFS 函数，该函数递归地展平子列表并返回其尾节点。 

变量`current`遍历列表的当前级别。 在修改指针之前，代码存储`current.next`里面`next_node`。 这可以防止在插入子链后失去对列表剩余部分的访问。 

当子列表存在时，算法会递归地展平该子列表。 返回的`child_tail`然后用于重新连接原来的`next`节点。 

子列表会立即插入到当前节点之后：```python
current.next = child_head
child_head.prev = current
```然后清除子指针：```python
current.child = None
```最后，如果原来的`next`节点存在，展平的子尾会重新连接到它。 

助手返回完全展平部分的尾部，以便更高的递归级别可以正确地重新连接，而无需额外的遍历。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Prev *Node
 *     Next *Node
 *     Child *Node
 * }
 */

func flatten(root *Node) *Node {
	if root == nil {
		return nil
	}

	var dfs func(node *Node) *Node

	dfs = func(node *Node) *Node {
		current := node
		last := node

		for current != nil {
			nextNode := current.Next

			if current.Child != nil {
				childHead := current.Child
				childTail := dfs(childHead)

				current.Next = childHead
				childHead.Prev = current
				current.Child = nil

				if nextNode != nil {
					childTail.Next = nextNode
					nextNode.Prev = childTail
				}

				last = childTail
			} else {
				last = current
			}

			current = nextNode
		}

		return last
	}

	dfs(root)
	return root
}
```Go 的实现与 Python 版本非常相似。 主要区别是显式指针处理`nil`检查而不是Python的`None`。 

Go 还要求在赋值之前使用变量声明来定义递归 DFS 函数：```go
var dfs func(node *Node) *Node
```由于约束很小，递归深度是安全的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 最坏情况嵌套中的递归调用堆栈

 该算法对每个节点执行恒定时间的指针更新，因此总工作量与节点数量成线性比例。 

递归 DFS 引入了与最大嵌套深度成比例的堆栈使用量。 在最坏的情况下，每个节点都包含一个子节点并且没有`next`节点，递归深度可以变为`O(n)`。

 ## 边缘情况

 ### 空输入列表

 输入头可以是`None`。 这是最简单的边缘情况，但是忘记处理它可能会在遍历期间立即导致空指针错误。 

实现在一开始就检查这一点：```
if not head:
    return None
```这保证了任何递归处理开始之前的安全行为。 

### 子列表在尾部

 靠近列表末尾的节点可能包含一个子节点，而其`next`指针已经是`null`。 

例如：```
1 - 2
    |
    3
```这种情况下，子列表展平后，就没有原来的了`next`节点重新连接。 不正确的实现可能会意外地取消引用空指针或创建无效链接。 

该解决方案安全地检查：```
if next_node:
```在重新连接指针之前。 

### 多层嵌套

 子节点本身可能包含另一个深度为几层的子列表。 

例如：```
1
|
2
|
3
```仅处理一个级别的浅层扁平化策略在这里会失败。 

递归 DFS 确保每个子列表在重新连接到父链之前都完全扁平化。 因为每个递归调用都完全处理其子树，所以可以正确处理任意嵌套深度。
