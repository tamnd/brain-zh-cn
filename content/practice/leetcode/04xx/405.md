 ## 解决方案

 ## 问题理解

 该问题要求我们转换给定的 32 位整数`num`转换为字符串的十六进制表示形式。 十六进制或以 16 为基数，使用数字`0-9`和字母`a-f`代表价值观`0-15`。 对于正数，转换很简单：重复将数字除以 16，并将余数映射到十六进制数字。 对于负数，问题明确指定使用**二进制补码**，这意味着将数字表示为存储在 32 位中。 例如，`-1`变成`0xffffffff`因为二进制补码代表`-1`因为 32 位整数中的所有位都设置为 1。 

输入范围是从`-2^31`到`2^31 - 1`。 这保证了输入是标准的 32 位有符号整数，因此我们不需要处理任意大整数。 

重要的边缘情况包括`0`，应该返回`"0"`没有前导零和负数，需要适当的掩码才能转换为 32 位二进制补码十六进制。 处理像这样的数字`-1`或者`-2^31`不正确的天真的除法可能会导致错误，因此按位方法更可靠。 

## 方法

 ### 暴力方法

 一种简单的方法是重复将整数除以 16，然后根据余数构造十六进制字符串。 对于负数，直接的除法循环可能会失败，因为 Python 或 Go 处理负除法的方式不同，并且我们需要手动计算二进制补码表示。 这种方法既麻烦又容易出错，尤其是对于负数，因为我们必须手动模拟 32 位整数。 

### 最佳方法

 最佳解决方案的关键是使用**位操作**。 对于 32 位数字，我们可以使用按位与来重复提取最后 4 位`0xf`，然后将数字右移 4 位。 这对于正数和负数一致有效，因为我们可以用`0xffffffff`模拟 32 位无符号整数。 这避免了单独处理负数并生成正确的小写十六进制字符串。

 ## 算法演练

 1. **处理零**：如果`num`为零，立即返回`"0"`。 这可以处理没有循环的特殊情况。 
2. **屏蔽负数**：使用`num & 0xffffffff`确保我们将数字视为无符号 32 位整数。 这会将负数转换为其二进制补码表示形式。 
3. **准备十六进制数字**：创建字符串`hex_chars = "0123456789abcdef"`将值 0-15 映射到十六进制字符。 
4. **构建十六进制字符串**：初始化一个空字符串`res`。 尽管`num`不为零，提取最后 4 位`num & 0xf`，将其映射到相应的十六进制字符，将其添加到`res`，并右移`num`4 位。 
5. **返回结果**：处理完所有位后，`res`包含正确的十六进制字符串。 

**为什么有效**：每次迭代从最低有效数字开始精确提取一个十六进制数字。 掩码可确保负数以 32 位二进制补码形式表示。 由于32位整数最多有8位十六进制数字，因此循环最多迭代8次，保证了正确性和效率。 

## Python 解决方案```python
class Solution:
    def toHex(self, num: int) -> str:
        if num == 0:
            return "0"
        
        hex_chars = "0123456789abcdef"
        res = ""
        num &= 0xffffffff  # mask to 32-bit unsigned
        
        while num:
            res = hex_chars[num & 0xf] + res
            num >>= 4
        
        return res
```此实现首先检查零，然后屏蔽数字以处理负数。 该循环迭代地提取每个 4 位块并构建十六进制字符串。 在前面使用字符串连接可确保数字顺序正确，而无需在末尾反转。 

## 解决方案```go
func toHex(num int) string {
    if num == 0 {
        return "0"
    }

    hexChars := "0123456789abcdef"
    res := ""
    n := uint32(num) // cast to 32-bit unsigned integer
    
    for n != 0 {
        res = string(hexChars[n&0xf]) + res
        n >>= 4
    }

    return res
}
```在 Go 中，我们使用类型转换来`uint32`正确处理负数，因为 Go 没有 Python 风格的任意整数处理。 其余逻辑反映了 Python 方法。

 ## 边缘情况

 一个重要的边缘情况是`0`，应该返回`"0"`没有任何额外的零。 如果没有特殊检查，循环将返回一个空字符串。 

另一个边缘情况是负数，尤其是`-1`或者`-2147483648`。 由于 Python 或 Go 中负除法的工作方式，朴素除法可能会给出错误的结果，因此用`0xffffffff`确保正确的 32 位二进制补码表示。 

第三种边缘情况是与十六进制边界精确对齐的数字，例如 15、16、255 或 256。这些测试测试转换是否正确地从一个十六进制数字翻转到下一个，而不会丢失或重复数字。 

该解决方案通过屏蔽负数、显式检查零以及迭代处理 4 位块来正确处理所有三个类别。
