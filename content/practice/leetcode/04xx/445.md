 ## 解决方案

 ## 问题理解

 该问题给了我们两个非空单链表，其中每个节点存储非负整数的一位数字。 与经典的“两个数字相加”问题不同，数字按正向顺序存储，这意味着最高有效数字首先出现。 

例如，链表：```
7 -> 2 -> 4 -> 3
```代表整数`7243`。 

任务是将两个表示的整数相加，并以相同的前序格式将结果作为链表返回。 

关键的挑战来自这样一个事实：加法自然是从右到左进行的，从最低有效数字开始。 然而，单链表只允许从左到右遍历。 由于数字是从最高有效位到最低有效位存储的，因此我们无法直接按照给出的顺序处理列表。 

约束相对较小，每个列表最多 100 个节点，因此就原始性能而言，效率并不是一个严重的问题。 然而，后续内容明确询问我们是否可以在不反转输入列表的情况下解决问题，这强烈暗示预期的解决方案应该保留原始列表结构。 

需要考虑一些重要的边缘情况：

 - 两个列表的长度可能不同。 
- 进位可能会一直传播到新的前导数字，例如`999 + 1 = 1000`。 
- 一个或两个列表可以代表零。 
- 列表不包含前导零，这简化了最高有效数字的处理。 

由于数字是按向前顺序存储的，因此我们需要一种策略，允许我们从后面处理数字而不修改输入列表。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将两个链表都转换为整数，将它们加在一起，然后将结果总和转换回链表。 

该过程如下所示：

 1、遍历第一个链表，逐位构造整数。 
2、遍历第二个链表，同样操作。 
3. 将两个整数相加。 
4. 将结果整数转换回链表。 

这种方法在概念上是有效的，因为链表只是整数的另一种表示形式。 

然而，该解决方案有几个缺点。 在许多编程语言中，对于非常大的输入，整数可能会溢出。 虽然 Python 支持任意大的整数，但在面试环境中通常不鼓励依赖内置的大整数支持，因为它绕过了核心链表操作挑战。 

此外，这种方法并没有解决直接对链表进行操作而不将其转换为整数的后续要求。 

### 最佳方法

 关键的观察是加法必须从最低有效数字开始，但链表提供从最高有效数字到最低有效数字。 

堆栈自然地解决了这种不匹配问题。 

通过将每个链表中的所有数字推送到单独的堆栈上，我们隐式地反转了处理顺序。 每个堆栈的顶部成为剩余的最低有效数字，使我们能够从右到左模拟标准小学加法。 

每一步：

 - 从每个堆栈中弹出一位数字（如果有）。 
- 将它们与携带物一起添加。 
- 创建一个包含当前数字的新节点。 
- 将节点插入结果列表的前面。 

从前面建立结果可以避免最后需要第二次逆转。 

该解决方案保留了原始列表，干净地处理任意长度，并且自然支持进位传播。

 | 蛮力 | O(n + m) | O(n + m) | 将列表转换为整数并返回 |

 ## 算法演练

 1. 创建两个空堆栈。 

堆栈将存储两个链表中的数字。 由于堆栈是后进先出结构，因此按正向顺序推送数字允许我们稍后按反向顺序处理它们。 
2. 遍历第一个链表，将每个数字压入第一个堆栈。 

对于列表`7 -> 2 -> 4 -> 3`，堆栈变为：```
[7, 2, 4, 3]
```栈顶是`3`，这是最低有效数字。 
3. 遍历第二个链表，将每个数字压入第二个堆栈。 

这为从右到左加法准备了两个数字。 
4. 初始化一个名为`carry`到`0`。 

这存储了前一个数字加法的溢出。 
5. 将结果列表头初始化为`None`。 

我们将通过在前面插入节点来增量构建答案。 
6. 当任一堆栈仍包含数字或有剩余进位时：

 1. 如果有的话，从每个堆栈中弹出顶部数字。 
2. 将两个数字和进位相加。 
3. 计算：

 -`digit = total % 10`-`carry = total // 10`4. 创建一个新节点，其中包含`digit`。 
5. 将此节点插入到结果列表的前面。 

前面插入至关重要，因为我们正在处理从最低有效位到最高有效位的数字。 
7. 返回结果列表的头部。 

### 为什么它有效

 该算法之所以有效，是因为堆栈反转了链表的遍历顺序。 这使我们能够完全按照标准加法的要求处理数字，从最低有效位到最高有效位。 

在每次迭代中，该算法都保持不变量，即部分构造的结果列表已经表示所有已处理的低位数字的正确总和。 进位传播确保跨越数字边界的正确性。 由于每个新计算的数字都插入在前面，因此最终的链表按所需的前向顺序出现。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def addTwoNumbers(
        self,
        l1: Optional[ListNode],
        l2: Optional[ListNode]
    ) -> Optional[ListNode]:

        stack1 = []
        stack2 = []

        current = l1
        while current:
            stack1.append(current.val)
            current = current.next

        current = l2
        while current:
            stack2.append(current.val)
            current = current.next

        carry = 0
        head = None

        while stack1 or stack2 or carry:
            total = carry

            if stack1:
                total += stack1.pop()

            if stack2:
                total += stack2.pop()

            digit = total % 10
            carry = total // 10

            new_node = ListNode(digit)
            new_node.next = head
            head = new_node

        return head
```实现首先遍历两个链表并将它们的数字压入堆栈。 这将正序表示转换为允许逆序处理的结构。 

这`carry`变量存储数字加法之间的溢出。 在每次迭代期间，算法从每个堆栈中弹出一位数字（如果有），将它们与进位相加，并计算结果数字和更新的进位。 

然后将一个新节点插入到结果列表的前面。 这种前面插入很重要，因为数字是从最低有效位到最高有效位进行处理的，但最终输出必须保持正向顺序。 

只要堆栈仍包含数字或仍有进位，循环就会继续。 这自然可以处理最终加法产生额外前导数字的情况。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func addTwoNumbers(l1 *ListNode, l2 *ListNode) *ListNode {
    stack1 := []int{}
    stack2 := []int{}

    for l1 != nil {
        stack1 = append(stack1, l1.Val)
        l1 = l1.Next
    }

    for l2 != nil {
        stack2 = append(stack2, l2.Val)
        l2 = l2.Next
    }

    carry := 0
    var head *ListNode = nil

    for len(stack1) > 0 || len(stack2) > 0 || carry > 0 {
        total := carry

        if len(stack1) > 0 {
            total += stack1[len(stack1)-1]
            stack1 = stack1[:len(stack1)-1]
        }

        if len(stack2) > 0 {
            total += stack2[len(stack2)-1]
            stack2 = stack2[:len(stack2)-1]
        }

        digit := total % 10
        carry = total / 10

        newNode := &ListNode{
            Val:  digit,
            Next: head,
        }

        head = newNode
    }

    return head
}
```Go 实现遵循与 Python 版本相同的整体逻辑。 由于Go没有提供内置的堆栈类型，因此切片被用作堆栈。 切片的最后一个元素代表堆栈的顶部。 

与 Python 不同，Go 明确区分了`nil`指针和有效节点，因此结果列表头初始化为`nil`。 

整数溢出不是问题，因为每个数字加法仅涉及之间的小值`0`和`9`，最多加上进位`1`。

 | --- | --- | --- |

 该算法精确地遍历每个链表一次以构建堆栈，然后在加法过程中再次处理每个数字。 由于每个堆栈压入和弹出操作的时间都是恒定的，因此总运行时间与列表的组合长度呈线性关系。 

额外的空间使用完全来自两个堆栈，它们一起存储输入列表中的每个数字。

 ## 边缘情况

 当最后的加法产生一个新的前导数字时，就会出现一个重要的边缘情况。 例如，添加`999 + 1`结果`1000`。 一旦两个输入列表都耗尽并且忘记处理剩余的进位，天真的实现可能会停止处理。 此实现通过继续循环 while 来避免该错误`carry`是非零的。 

另一个重要的边缘情况涉及不同长度的列表。 由于不能保证两个链表包含相同数量的数字，因此一个堆栈可能会先于另一个堆栈变空。 该算法通过仅从堆栈中弹出（如果堆栈仍然包含值）来干净地处理此问题。 缺失的数字实际上被视为零。 

第三种边缘情况是两个输入均为零时。 在这种情况下，某些实现会意外返回空列表。 在这里，算法正确地创建了一个包含以下内容的节点：`0`因为当两个堆栈都包含零数字时，循环仍然执行一次。 

一个微妙的边缘情况涉及长链进位传播，例如`9999 + 9999`。 不正确的实现可能会错误地处理多次迭代中的进位更新。 该算法使用整数除法在每一步独立地重新计算进位，确保无论链长度如何，进位传播都保持正确。
