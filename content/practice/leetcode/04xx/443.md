[LeetCode 第 443 题](https://leetcode.com/problems/string-compression/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们对字符数组执行就地字符串压缩。 输入不是字符串对象，而是名为的可变数组`chars`，其中每个元素都是一个字符。 

压缩规则基于连续重复字符组。 对于每个连续的相同字符块：

 - 如果角色只出现一次，我们只保留角色本身。 
- 如果该字符出现多次，我们会在该字符后面加上其出现频率的十进制表示形式。 

例如，序列：```
["a","a","a","b","c","c"]
```变成：```
["a","3","b","c","2"]
```重要的细节是压缩结果必须写回到同一个输入数组中。 我们不允许分配与输入大小成比例的另一个数组。 该函数应仅返回压缩数组的新有效长度。 

任何超出返回长度的内容都是无关紧要的，并且可能包含剩余数据。 

限制比较小，最多2000个字符，所以时间复杂度限制不是很大。 然而，持续的额外空间需求才是真正的挑战。 我们必须就地修改数组，同时仍然正确处理多位数计数，例如`"12"`或者`"123"`。 

一些重要的观察结果和边缘情况立即出现：

 - 单个字符应保持不变。 
- 长度为 1 的游程不应附加计数。 
- 大于 9 的计数必须拆分为多个字符。 
- 数组可能已经不可压缩，例如交替字符。 
- 整个数组可以由一个重复的字符组成。 
- 由于压缩必须就地进行，因此不小心的覆盖可能会破坏未读的数据。 

该问题自然提出了一种双指针策略，其中一个指针读取原始数据，另一个指针写入压缩形式。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是扫描数组，在单独的字符串或列表中构建压缩结果，然后将压缩内容复制回原始数组。 

该算法的工作原理如下：

 - 从左到右遍历数组。 
- 计算连续的相同字符。 
- 将字符附加到临时结果。 
- 如果计数大于 1，则附加计数的字符串形式。 
- 处理完所有组后，覆盖开头`chars`与临时结果。 

这种方法很容易实现并且明显正确，因为它直接遵循压缩规则。 然而，它违反了恒定的额外空间要求，因为临时结构可能与输入大小成比例增长。 

### 最佳就地两指针方法

 关键的见解是我们可以逐组处理数组，同时将压缩输出直接写回到同一个数组中。 

我们使用：

 - 用于扫描输入的读指针
 - 用于放置压缩字符的写指针

 对于每组重复字符：

 - 写一次字符
 - 如果计数大于一，则分别写出计数的每一位数字

 因为写入位置永远不会以有问题的方式移动到未读数据之前，所以我们可以安全地就地覆盖数组。 

这满足了正确性要求和恒定的额外空间约束。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用额外的缓冲区来构建压缩结果 |
 | 最佳| O(n) | O(1) | O(1) | 使用两个指针并直接写入输入数组 |

 ## 算法演练

 1.初始化两个指针，`read_index`和`write_index`。 

这`read_index`扫描原始数组以识别重复字符组。 这`write_index`跟踪压缩输出应写入的位置。 
2. 开始处理新的字符组。 

在每次迭代时，存储当前字符并开始计算它连续出现的次数。 
3. 当字符匹配时前进读指针。 

继续移动`read_index`只要当前字符保持不变，就向前移动。 这决定了团体的规模。 
4. 将字符写入压缩部分。 

无论组大小如何，字符本身始终在压缩输出中出现一次。 
5. 如果组长度大于1，则逐位写入计数。 

将计数转换为字符串并将每个数字分别写入数组中。 

这很重要，因为诸如此类的计数`12`必须成为：```
['1', '2']
```而不是单个整数值。 
6. 继续，直到处理完整个数组。 

一旦所有组都被压缩，`write_index`表示有效压缩部分的长度。 
7. 返回写指针。 

问题只关心数组的压缩前缀。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 之前的一切`write_index`已经被正确压缩。 
- 当时或之后的一切`read_index`尚未处理。 

在写入该组的任何压缩数据之前，将完全读取该组。 这保证了我们永远不会丢失未读信息。 由于每个字符都被处理一次，因此该算法正确地构建了压缩表示。 

## Python 解决方案```python
from typing import List

class Solution:
    def compress(self, chars: List[str]) -> int:
        read_index = 0
        write_index = 0
        n = len(chars)

        while read_index < n:
            current_char = chars[read_index]
            group_start = read_index

            while (
                read_index < n
                and chars[read_index] == current_char
            ):
                read_index += 1

            group_length = read_index - group_start

            chars[write_index] = current_char
            write_index += 1

            if group_length > 1:
                for digit in str(group_length):
                    chars[write_index] = digit
                    write_index += 1

        return write_index
```该实现遵循前面描述的精确的两指针策略。 

变量`read_index`扫描数组并识别连续的相同字符组。 对于每个组，我们存储当前角色并记住组的开始位置。 

内部`while`循环继续进行，直到字符改变或数组结束。 新版和新版的区别`read_index`和`group_start`给出组的大小。 

接下来，我们使用以下命令将字符写入压缩部分`write_index`。 

如果组长度超过 1，我们将计数转换为字符串并单独写入每个数字。 这可以正确处理多位数计数，例如`"12"`或者`"100"`。 

最后，函数返回`write_index`，表示压缩后的长度。 

## 解决方案```go
package main

import "strconv"

func compress(chars []byte) int {
	readIndex := 0
	writeIndex := 0
	n := len(chars)

	for readIndex < n {
		currentChar := chars[readIndex]
		groupStart := readIndex

		for readIndex < n && chars[readIndex] == currentChar {
			readIndex++
		}

		groupLength := readIndex - groupStart

		chars[writeIndex] = currentChar
		writeIndex++

		if groupLength > 1 {
			countString := strconv.Itoa(groupLength)

			for i := 0; i < len(countString); i++ {
				chars[writeIndex] = countString[i]
				writeIndex++
			}
		}
	}

	return writeIndex
}
```Go 实现在逻辑上与 Python 版本几乎相同。 

一个重要的区别是 Go 使用`[]byte`而不是字符串列表。 字符存储为字节，因此计数字符串中的数字可以直接写入数组。 

这`strconv.Itoa`函数将整数计数转换为其十进制字符串表示形式。 

无需特殊处理`nil`切片是必需的，因为约束保证至少有一个字符。

 ## 边缘情况

 ### 单字符输入

 一个单元素数组，例如：```
["a"]
```如果实现假设每个组都有多个字符，则很容易处理不当。 正确的行为是保持字符不变并返回长度`1`。 

该实现自然地处理了这个问题，因为组计数变为`1`，只有当频率超过 1 时才会写入计数。 

### 多位频率

 输入如：```
["a","a","a","a","a","a","a","a","a","a","a","a"]
```产生一个计数`12`。 

一个常见的错误是将整数直接写入数组，而不是将其拆分为单独的字符。 正确的压缩形式是：```
["a","1","2"]
```该实现通过将计数转换为字符串并单独写入每个数字来解决此问题。 

### 交替字符

 输入例如：```
["a","b","c","d"]
```根本不压缩。 

有缺陷的实现可能会错误地附加`"1"`在每个字符之后，产生：```
["a","1","b","1","c","1","d","1"]
```该算法通过仅在组长度大于 1 时才写入计数来避免这种情况。 

### 就地覆盖

 由于必须直接修改数组，因此覆盖未读取的数据是潜在的错误来源。 

两个指针结构保证了安全性，因为该算法总是在写入其压缩表示之前完成读取整个组。 这会在整个执行过程中保留所有必要的信息。
