[LeetCode 第 465 题](https://leetcode.com/problems/optimal-account-balancing/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、回溯、位操作、位掩码

 ## 解决方案

 ## 问题理解

 该问题给出了人与人之间的资金转移清单。 每笔交易都表示为`[from, to, amount]`，意味着一个人向另一个人支付了一定金额。 所有交易完成后，可能有的人整体欠钱，有的人整体欠钱。 

目标不是重新创建原始交易。 相反，目标是使用尽可能少的新交易来结算所有剩余余额。 

思考这个问题的一个有用方法是从净余额的角度来考虑。 对于每个人：

 - 如果他们的最终余额为正，他们应该收到钱。 
- 如果他们的最终余额为负数，则他们欠钱。 
- 如果余额为零，则说明已结算，可以忽略。 

例如，如果有人付款$10 and later received $6、他们的最终余额是`-4`，这意味着他们总共还欠 4 美元。 

输入大小故意较小：

 - 最多8笔交易
 - 人员 ID 范围从 0 到 11

 尽管交易数量很少，但可能的结算组合数量仍然可以快速增长。 这是一个强烈的暗示，表明需要使用指数技术，例如回溯、使用位掩码的动态编程或基于修剪的搜索。 

重要的观察是，只有最终净余额才重要。 一旦我们计算出每个人的净债务，原始交易的确切顺序就无关紧要了。 

一些边缘情况很重要：

 - 有些人在所有交易后可能已经有零余额。 
- 同一对人之间的多次交易可能会相互抵消。 
- 最佳解决方案可能需要以非显而易见的方式合并债务。 
- 贪婪匹配可能会失败，因为局部最优解决可能会阻碍全局最优安排。 
- 可能有很多等价的结算订单，因此修剪重复的状态对于提高效率很重要。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试一切可能的方法来解决欠钱人和应该收钱人之间的债务。 

计算净余额后，我们可以反复选择：

 - 债务人
 - 债权人
 - 转账金额

 然后递归继续，直到所有余额变为零。 

这种方法是正确的，因为它探索了每一种可能的结算顺序，保证最终找到最小的交易计数。 

然而，搜索空间很快就会变得巨大。 每个递归步骤都会分支出多种可能性，并且许多状态实际上是通过不同的交易订单达到的重复。 如果不进行修剪，即使对于相对较小的输入，该算法也变得不可行。 

### 关键见解

 关键的见解是我们只关心净余额，而不关心原始交易。 

假设我们有：```
[-5, +5]
```这显然需要一笔交易。 

相似地：```
[-5, -5, +10]
```需要两次交易。 

这将问题转化为：

 > 给定非零余额列表，以最小化结算数量的方式将债务和信贷配对。 

最优策略使用回溯和剪枝：

 - 一次处理一笔未结算的余额。 
- 尝试根据每个相反符号的余额进行结算。 
- 递归地解决较小的子问题。 
- 跳过冗余的等效状态。 

由于非零余额的数量很少，因此这种指数解变得实用。

 ## 算法演练

 ### 第 1 步：计算净余额

 创建一个哈希映射，其中：

 - 汇款会减少余额
 - 收到钱会增加余额

 交易用`[u, v, amt]`:```
balance[u] -= amt
balance[v] += amt
```最后：

 - 负值表示债务
 - 正值代表信用

 ### 第 2 步：删除零余额

 余额已经为零的人不会影响答案。 

创建仅包含非零余额的列表。 

例如：```
[0, -5, 5, 0]
```变成：```
[-5, 5]
```这显着减少了搜索空间。 

### 步骤3：开始递归回溯

 定义一个递归函数：```
dfs(start)
```在哪里`start`is the first unsettled balance index.

 递归的工作原理是尝试解决平衡问题`start`稍后的余额具有相反的符号。 

### 第 4 步：跳过已结算的头寸

 处理前：```
while balances[start] == 0:
    start += 1
```这可以避免对已结算的帐户进行不必要的递归。 

如果`start`到达数组末尾，所有债务都已清偿，因此返回`0`。 

### 步骤 5：尝试与相反的符号配对

 假设：```
balances[start] = -5
```我们尝试后面的每一个索引`i`这样：```
balances[i] > 0
```我们暂时解决：```
balances[i] += balances[start]
```这有效地将债务转移到后来的余额中。 

然后递归求解剩余余额。 

### 第 6 步：回溯

 递归结束后：```
balances[i] -= balances[start]
```这会恢复到下一个可能性的原始状态。 

回溯是必要的，因为必须独立探索多种解决方案。 

### 步骤 7：修剪重复状态

 一个主要的优化是：```
if balances[i] + balances[start] == 0:
    break
```如果一笔交易完全结算了两个账户，则无需探索其他等价配对。 

这种修剪极大地提高了性能。 

### 为什么它有效

 在每个递归步骤中，算法都会选择一个未结算的帐户，并尝试所有有效的方法来使用相反签名的帐户进行结算。 由于探索了每种可能的定居点配置，因此该算法不会错过最佳解决方案。 回溯通过在每个递归分支之后恢复状态来保证正确性，而修剪则删除冗余的等效搜索而不排除任何最佳解决方案。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def minTransfers(self, transactions: List[List[int]]) -> int:
        balance = defaultdict(int)

        # Compute net balance for each person
        for sender, receiver, amount in transactions:
            balance[sender] -= amount
            balance[receiver] += amount

        # Keep only non-zero balances
        debts = [amount for amount in balance.values() if amount != 0]

        def dfs(start: int) -> int:
            # Skip settled balances
            while start < len(debts) and debts[start] == 0:
                start += 1

            # All settled
            if start == len(debts):
                return 0

            min_transactions = float("inf")

            for i in range(start + 1, len(debts)):
                # Must have opposite signs
                if debts[start] * debts[i] < 0:
                    # Try settling start with i
                    debts[i] += debts[start]

                    min_transactions = min(
                        min_transactions,
                        1 + dfs(start + 1)
                    )

                    # Backtrack
                    debts[i] -= debts[start]

                    # Perfect cancellation pruning
                    if debts[i] + debts[start] == 0:
                        break

            return min_transactions

        return dfs(0)
```该实现首先使用哈希图计算净余额。 每笔发出的交易都会减少一个人的余额，而每笔收到的交易都会增加一个人的余额。 

构建余额图后，代码会删除所有零余额，因为这些人已经定居并且不会对搜索做出贡献。 

递归`dfs`函数一次处理一个未结算的帐户。 这`start`指针标识当前正在解析的帐户。 任何已经确定的头寸都会立即跳过。 

对于每个具有相反符号的后续余额，该算法通过将当前债务添加到该余额中来模拟结算。 这代表一笔交易。 然后递归解决较小的剩余问题。 

递归调用完成后，通过回溯恢复状态。 这确保每个递归分支都在干净的状态下运行。 

修剪条件：```python
if debts[i] + debts[start] == 0:
    break
```检测到完美取消。 一旦找到这样的匹配，就没有必要探索其他等效匹配。 

## 解决方案```go
package main

func minTransfers(transactions [][]int) int {
	balance := map[int]int{}

	// Compute net balances
	for _, t := range transactions {
		from, to, amount := t[0], t[1], t[2]

		balance[from] -= amount
		balance[to] += amount
	}

	// Collect non-zero balances
	debts := []int{}
	for _, amount := range balance {
		if amount != 0 {
			debts = append(debts, amount)
		}
	}

	var dfs func(int) int

	dfs = func(start int) int {
		// Skip settled balances
		for start < len(debts) && debts[start] == 0 {
			start++
		}

		// All settled
		if start == len(debts) {
			return 0
		}

		minTransactions := int(^uint(0) >> 1)

		for i := start + 1; i < len(debts); i++ {
			// Opposite signs only
			if debts[start]*debts[i] < 0 {
				// Try settlement
				debts[i] += debts[start]

				result := 1 + dfs(start+1)
				if result < minTransactions {
					minTransactions = result
				}

				// Backtrack
				debts[i] -= debts[start]

				// Perfect cancellation pruning
				if debts[i]+debts[start] == 0 {
					break
				}
			}
		}

		return minTransactions
	}

	return dfs(0)
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个`map[int]int`存储净余额，切片仅存储非零债务。 

Go 没有内置的整数无穷大值，因此代码初始化`minTransactions`使用最大可能的整数：```go
int(^uint(0) >> 1)
```递归闭包捕获`debts`直接切片，允许就地回溯，无需额外分配。 

由于约束很小，因此整数溢出不是这里的问题。

class Solution:
    def minTransfers(self, transactions: List[List[int]]) -> int:
        from collections import defaultdict

        balance = defaultdict(int)

        for sender, receiver, amount in transactions:
            balance[sender] -= amount
            balance[receiver] += amount

        debts = [x for x in balance.values() if x != 0]

        def dfs(start: int) -> int:
            while start < len(debts) and debts[start] == 0:
                start += 1

            if start == len(debts):
                return 0

            ans = float("inf")

            for i in range(start + 1, len(debts)):
                if debts[start] * debts[i] < 0:
                    debts[i] += debts[start]

                    ans = min(ans, 1 + dfs(start + 1))

                    debts[i] -= debts[start]

                    if debts[i] + debts[start] == 0:
                        break

            return ans

        return dfs(0)

 ## 边缘情况

 ### 完全平衡的交易

 当所有交易在净余额计算后相互抵消时，就会出现常见的边缘情况。 

例子：```
[[0,1,5],[1,0,5]]
```幼稚的实现可能仍然会尝试不必要的递归解决。 此实现通过在递归开始之前删除所有零余额来避免该问题。 债务数组变空，算法立即返回`0`。 

### 多种等效结算路径

 不同的交易指令可以代表相同的有效状态。 

例子：```
[-5, 5, 5, -5]
```如果不进行修剪，算法可能会重复探索等效的递归分支，从而导致性能严重下降。 

完美取消剪枝条件：```
if debts[i] + debts[start] == 0:
    break
```消除冗余探索，同时保持正确性。 

### 循环债务结构

 债务周期可能会混淆专注于交易序列而不是净余额的实现。 

例子：```
0 -> 1 -> 2 -> 0
```即使存在多个交易，净效应也可能是完全平衡的。 

由于该解决方案首先计算最终净余额，因此所有周期自然会崩溃为其简化形式。 这避免了不必要的递归工作，并保证算法解决真正的优化问题而不是原始事务图。
