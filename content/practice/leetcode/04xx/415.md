[LeetCode 第 415 题](https://leetcode.com/problems/add-strings/)

 **难度：** 🟢简单
 **主题：** 数学、字符串、模拟

 ## 解决方案

 ## 问题理解

 该问题要求我们添加两个非负整数，其中每个整数都以字符串而不是数字类型的形式给出。 目标是将结果总和作为另一个字符串返回。 

例如，如果输入是`"11"`和`"123"`，我们应该返回`"134"`。 

重要的限制是我们不允许将整个字符串直接转换为整数。 这意味着诸如`int(num1) + int(num2)`在 Python 中或使用大整数库是被禁止的。 问题是具体测试能否模拟手动逐位相加。 

输入字符串仅包含数字字符`'0'`到`'9'`，并且字符串可以非常大，可达 length`10^4`。 这个大小非常重要，因为许多编程语言无法在内置数字类型中安全地存储该大小的整数。 即使一种语言在技术上支持任意精度整数，该问题也明确禁止使用它们。 

输出应该是总和的精确十进制表示形式，也可以是字符串。 

需要考虑一些重要的边缘情况：

 - 数字可以有不同的长度，例如`"1"`和`"9999"`。 
- 一个或两个数字都可以`"0"`。 
- 最后的加法可能会产生额外的进位数字，例如`"999" + "1" = "1000"`。 
- 由于输入没有前导零，除了`"0"`就其本身而言，我们不需要处理格式错误的情况。 

The problem is essentially asking us to simulate the same process humans use when adding numbers on paper, starting from the least significant digit and moving leftward while carrying overflow values forward.

 ## 方法

 ### 蛮力方法

 最明显的解决方案是将两个字符串都转换为整数，将它们相加，然后将结果转换回字符串。 

从概念上讲，这是可行的，因为整数算术已经在内部处理进位。 该实现将非常简短且易于理解。 

However, this approach violates the problem constraints because the problem explicitly forbids converting the inputs directly into integers or using built-in large integer support.

 此外，对于非常大的输入，许多语言中的标准整数类型都会溢出。 

### 最佳方法

 正确的做法是手动模拟小学加法。 

关键的观察是加法只需要从右到左一次处理一位数字。 在每个位置：

 - 添加当前数字`num1`- 添加当前数字`num2`- 添加上一步中的任何进位
 - 存储结果数字
 - 结转溢出

 由于表示数字的字符可以很容易地单独转换为其数值，因此我们可以处理字符串，而无需将完整的数字转换为整数。 

这种方法工作效率很高，因为每个数字都被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 将整个字符串转换为整数，违反约束 |
 | 最佳| O(n) | O(n) | 手动模拟逐位加法 |

 ## 算法演练

 1. 在每个字符串的末尾初始化两个指针。 

最右边的数字代表最低有效位值，因此加法必须从这里开始。 我们使用一个指针`num1`另一个用于`num2`。 
2. 初始化进位变量。 

进位存储前一个数字加法产生的溢出。 最初，没有溢出，因此进位开始于`0`。 
3. 创建结果容器。 

由于字符串在许多语言中都是不可变的，因此重复连接字符串可能效率低下。 相反，我们将数字存储在列表或切片中，然后将它们连接起来。 
4. 在指针仍然有效或进位仍然存在的情况下处理数字。 

即使一个字符串比另一个字符串短，我们也必须继续处理较长字符串的剩余数字。 如果处理完所有数字后还有剩余进位，我们也必须继续。 
5. 提取当前数字。 

如果指针仍在范围内，则将字符数字转换为其整数值。 否则，使用`0`。 
6. 计算当前位置的总计。 

添加：

 - 数字来自`num1`- 数字来自`num2`- 载流
 7. 确定新的数字并进位。 

个位成为输出数字：$\text{digit} = \text{total} \bmod 10$十位成为新的进位：$\text{carry} = \left\lfloor \frac{\text{total}}{10} \right\rfloor$8. 将结果数字附加到结果容器中。 

由于我们是从右向左处理，因此数字是以相反的顺序产生的。 
9. 向左移动两个指针。 

这将加法过程推进到下一个更有效的数字。 
10. 将结果反转并转换为字符串。 

由于数字是从最低有效位到最高有效位收集的，因此反转可以恢复正确的顺序。 

### 为什么它有效

 在每次迭代中，算法都会正确计算一位小数的总和，同时保留进位变量的溢出。 这完全符合以 10 为底的算术规则。 由于每个数字都被处理一次并且进位被正确传播，所以最终结果保证等于两个输入数字的数学和。 

## Python 解决方案```python
class Solution:
    def addStrings(self, num1: str, num2: str) -> str:
        i = len(num1) - 1
        j = len(num2) - 1
        
        carry = 0
        result = []
        
        while i >= 0 or j >= 0 or carry:
            digit1 = ord(num1[i]) - ord('0') if i >= 0 else 0
            digit2 = ord(num2[j]) - ord('0') if j >= 0 else 0
            
            total = digit1 + digit2 + carry
            
            result.append(str(total % 10))
            carry = total // 10
            
            i -= 1
            j -= 1
        
        result.reverse()
        
        return ''.join(result)
```该实现首先将两个指针放置在输入字符串的末尾。 这些位置对应于最低有效数字。 

这`carry`变量存储上一个加法步骤的溢出。 这`result`list 在计算时收集数字。 

在循环内部，如果指针有效，则提取当前数字。 如果一个指针已经移过其字符串的开头，则相应的数字被视为`0`。 这使得算法能够自然地处理不同长度的数字。 

当前位置的总数是通过将数字和进位相加来计算的。 当前输出数字是使用模 10 获得的，而整数除以 10 会产生新的进位。 

每个生成的数字都附加到结果列表中。 由于数字是从右向左处理的，因此在加入最终字符串之前，列表会在末尾反转。 

此实现不会将整个输入转换为整数，因此它满足所有问题约束。 

## 解决方案```go
func addStrings(num1 string, num2 string) string {
	i := len(num1) - 1
	j := len(num2) - 1

	carry := 0
	result := []byte{}

	for i >= 0 || j >= 0 || carry > 0 {
		digit1 := 0
		digit2 := 0

		if i >= 0 {
			digit1 = int(num1[i] - '0')
		}

		if j >= 0 {
			digit2 = int(num2[j] - '0')
		}

		total := digit1 + digit2 + carry

		result = append(result, byte(total%10)+'0')
		carry = total / 10

		i--
		j--
	}

	left := 0
	right := len(result) - 1

	for left < right {
		result[left], result[right] = result[right], result[left]
		left++
		right--
	}

	return string(result)
}
```Go 解决方案遵循与 Python 实现相同的算法结构，但有一些特定于语言的细节。 

Go字符串内部是字节切片，因此可以直接使用进行数字提取`num1[i] - '0'`。 

结果存储为`[]byte`而不是字符串，因为在 Go 中重复连接字符串效率很低。 收集所有数字并反转后，字节片将转换为字符串。 

与 Python 不同，Go 不为普通整数类型提供内置的任意精度整数，因此这种手动加法方法对于非常大的输入尤其重要。

 ## 边缘情况

 ### 不同长度输入

 一个数字可能比另一个数字包含更多的数字，例如`"1"`和`"999999"`。 

当较短的字符串耗尽时，幼稚的实现可能会过早停止。 此实现通过在任一指针仍然有效时继续循环来避免该问题。 缺失的数字被视为`0`，它正确反映了手动添加。 

### 所有数字后的最后进位

 类似的情况`"999"`和`"1"`在结果中产生一个额外的数字。 

这是错误的常见来源，因为在处理所有原始数字后，进位仍然存在。 循环条件明确包括`or carry`，确保正确附加剩余的进位。 

### 输入等于零

 当两个输入都是`"0"`，正确的输出也应该是`"0"`。 

某些实现会意外地生成空字符串或错误处理前导零。 由于当数字存在时，该算法总是至少处理一次迭代，因此结果正确地变为`"0"`。
