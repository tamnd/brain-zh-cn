 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少对索引`(i, j)`满足两个条件：

 1.`i < j`2.`nums[i] > 2 * nums[j]`这些对称为反向对。 

与经典的反转计数问题不同，我们检查是否`nums[i] > nums[j]`，这个问题使用了更严格的条件，涉及乘以二。 这个额外的条件显着改变了行为，并阻止我们直接使用一些更简单的反转计数技巧。 

输入是一个整数数组`nums`，输出是一个整数，表示有效反向对的总数。 

约束条件很重要：

 -`nums.length`可以大到`5 * 10^4`- 值的范围可以是`-2^31`到`2^31 - 1`暴力解决方案需要检查每一对`(i, j)`，这需要`O(n^2)`时间。 和`50,000`元素，这大致意味着`2.5 billion`在最坏的情况下进行比较，这太慢了。 

值范围也很重要，因为乘以`2`在某些语言（如 Go 或 Java）中可能会溢出 32 位整数。 在执行比较时，我们必须小心使用更大的整数类型，例如：```
nums[i] > 2 * nums[j]
```一些重要的边缘情况包括：

 - 数字全部相等的数组
 - 带有负数的数组
 - 数组已按升序或降序排序
 - 包含极大正整数或负整数的数组
 - 非常小的数组，例如长度`1`负值尤其棘手，因为乘以`2`以不直观的方式改变排序行为。 例如：```
-1 > 2 * -3
-1 > -6
```这是事实，因此即使值为负数，反向对也可能存在。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每一个可能的对`(i, j)`在哪里`i < j`。 

对于每对：

 - 计算是否`nums[i] > 2 * nums[j]`- 如果为真，则增加答案

 这种方法保证是正确的，因为它明确地评估每个有效对。 

然而，时间复杂度为`O(n^2)`因为大约有`n * (n - 1) / 2`对。 和`50,000`元素，这在计算上变得不可行。 

### 最佳方法，基于合并排序的计数

 关键的见解是这个问题类似于反转计数，可以使用合并排序有效地解决。 

合并排序递归地将数组分成已排序的两半。 一旦两个半体被单独排序，我们就可以有效地计算跨半体反向对。 

假设：

 - 左半部分已排序
 - 右半部分已排序

 对于左半部分中的每个值，我们要计算右半部分中有多少个值满足：```
left_value > 2 * right_value
```由于两半都已排序，因此我们可以在合并步骤期间使用双指针技术以线性时间对这些对进行计数。 

这将总复杂度从`O(n^2)`到`O(n log n)`。

 ## 算法演练

 ### 最优归并排序算法

 1. 递归地将数组分成两半，直到每个子数组包含一个元素。 

单个元素本身无法形成反向对，因此它们是简单排序的。 
2. 递归求解左半部分。 

这将返回：

 - 左半部分内反向对的数量
 - 左半部分按排序顺序
 3. 递归求解右半部分。 

同样，这会返回：

 - 右半部分内反向对的数量
 - 右半部分按排序顺序
 4. 计算两半的反向对。 

此时：

 - 左半部分已排序
 - 右半部分已排序

 使用两个指针：

 -`i`遍历左半部分
 -`j`traverses the right half

 对于每个`nums[i]`， 进步`j`尽管：```
nums[i] > 2 * nums[j]
```由于右半部分已排序，一旦一个值满足条件，所有较早的值也满足它。 

贡献的有效对数量`nums[i]`是：```
j - (mid + 1)
```5. 合并已排序的两半。 

从合并排序执行标准合并操作，以便当前段已排序。 
6. 返回总计数。 

最终答案等于：```
left_count + right_count + cross_count
```### 为什么它有效

 正确性依赖于以下事实：合并排序保证在计数阶段开始之前对两半进行排序。 

因为两半已排序：

 - 如果`nums[i] > 2 * nums[j]`对于某些人来说`j`,
 - 那么对于右半部分中所有较早的元素也是如此。 

这种单调行为允许两指针扫描有效地计算所有有效对，而无需重复访问元素。 

每个反向对都属于以下类别之一：

 - 完全在左半部分
 - 完全在右半部分
 - 半场之间的交叉

 递归对所有三个类别仅计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def reversePairs(self, nums: List[int]) -> int:
        def merge_sort(left: int, right: int) -> int:
            if left >= right:
                return 0

            mid = (left + right) // 2

            count = merge_sort(left, mid)
            count += merge_sort(mid + 1, right)

            # Count reverse pairs
            j = mid + 1

            for i in range(left, mid + 1):
                while j <= right and nums[i] > 2 * nums[j]:
                    j += 1

                count += j - (mid + 1)

            # Merge step
            merged = []
            p1 = left
            p2 = mid + 1

            while p1 <= mid and p2 <= right:
                if nums[p1] <= nums[p2]:
                    merged.append(nums[p1])
                    p1 += 1
                else:
                    merged.append(nums[p2])
                    p2 += 1

            while p1 <= mid:
                merged.append(nums[p1])
                p1 += 1

            while p2 <= right:
                merged.append(nums[p2])
                p2 += 1

            nums[left:right + 1] = merged

            return count

        return merge_sort(0, len(nums) - 1)
```其实现紧密遵循合并排序结构。 

这`merge_sort`函数对子数组进行递归排序并返回该范围内的反向对的数量。 

递归调用首先独立地处理左半部分和右半部分。 一旦两半都排序完毕，算法就会使用双指针扫描对跨半反向对进行计数。 

指针`j`只前进，绝不后退。 这很重要，因为它保证了每个合并阶段的线性工作。 

计数后，代码执行标准合并操作以维持排序顺序。 合并后的结果将替换原来的段`nums`。 

最后，返回总的反向对计数。 

## 解决方案```go
func reversePairs(nums []int) int {
	var mergeSort func(int, int) int

	mergeSort = func(left int, right int) int {
		if left >= right {
			return 0
		}

		mid := (left + right) / 2

		count := mergeSort(left, mid)
		count += mergeSort(mid+1, right)

		// Count reverse pairs
		j := mid + 1

		for i := left; i <= mid; i++ {
			for j <= right && int64(nums[i]) > 2*int64(nums[j]) {
				j++
			}

			count += j - (mid + 1)
		}

		// Merge step
		temp := make([]int, 0, right-left+1)

		p1 := left
		p2 := mid + 1

		for p1 <= mid && p2 <= right {
			if nums[p1] <= nums[p2] {
				temp = append(temp, nums[p1])
				p1++
			} else {
				temp = append(temp, nums[p2])
				p2++
			}
		}

		for p1 <= mid {
			temp = append(temp, nums[p1])
			p1++
		}

		for p2 <= right {
			temp = append(temp, nums[p2])
			p2++
		}

		for i := 0; i < len(temp); i++ {
			nums[left+i] = temp[i]
		}

		return count
	}

	return mergeSort(0, len(nums)-1)
}
```Go 实现在结构上与 Python 版本类似，但有一些特定于语言的细节值得注意。 

最重要的区别是整数溢出处理。 自从`nums[i]`可能接近32位限制，比较：```go
nums[i] > 2 * nums[j]
```如果使用正常执行可能会溢出`int`算术。 

为了避免这种情况，实现将值转换为`int64`乘法之前：```go
int64(nums[i]) > 2 * int64(nums[j])
```合并步骤使用切片构建临时合并数组，然后将其复制回原始数组段。 

Go 切片是动态的，所以`append`在合并期间使用。

 ## 边缘情况

 一种重要的边缘情况是包含负数的数组。 许多实现错误地假设反向对大多以较大的正值出现。 但是，负值也可以满足该条件，因为乘以 2 会使它们变得更小。 例如：```
-5 > 2 * -5
-5 > -10
```这是真实的。 合并排序解决方案自然地处理负值，因为它仅依赖于比较和排序。 

另一个关键的边缘情况涉及整数溢出。 如果`nums[j]`接近32位整数限制，计算`2 * nums[j]`在某些语言中可能会溢出。 Go 实现显式地将值转换为`int64`乘法之前，以避免不正确的比较。 Python 整数会自动扩展，因此 Python 不存在这个问题。 

第三个重要的边缘情况是具有许多重复值的数组。 由于条件严格大于：```
nums[i] > 2 * nums[j]
```除非乘法条件确实成立，否则相等的值不应计数。 例如：```
[2,2,2,2]
```包含零个反向对。 该实现在计数过程中正确地保留了严格的不平等。 

另一个微妙的情况是已经排序的升序数组。 天真的反转计数思维可能会期望存在一些对，但对于严格递增的数组，反转对通常不存在，因为后面的元素不够小，无法满足两倍的条件。 对于这种情况，算法会正确返回零。
