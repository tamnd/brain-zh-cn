[LeetCode 第 438 题](https://leetcode.com/problems/find-all-anagrams-in-a-string/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 问题给出两个字符串，`s`和`p`，都只包含小写英文字母。 我们需要找到每个起始索引`s`其中子字符串是 anagram`p`。 

字谜词意味着子字符串包含与`p`，具有相同的频率，但可能具有不同的顺序。 例如，`"abc"`,`"bca"`， 和`"cab"`都是彼此的字谜。 

关键的观察是每个有效子字符串的长度必须与`p`。 如果`p`长度为 3，则每个候选子串`s`长度也必须为 3。我们滑动一个大小的窗口`len(p)`穿过`s`并检查当前窗口是否是以下的字谜词`p`。 

输出应包含出现此类字谜的所有起始索引。 

约束条件很重要：

 -`1 <= s.length, p.length <= 3 * 10^4`- 字符串仅包含小写英文字母

 在这种规模下，对每个子串进行排序或重复重建频率图的强力解决方案会太慢。 由于字母表固定为仅 26 个小写字母，因此我们可以非常有效地使用频率计数。 

一些边缘情况很重要：

 -`p`可能长于`s`，在这种情况下不存在答案。 
- 多个字谜可能会重叠，例如`"abab"`和`"ab"`。 
- 中重复的字符`p`可能会产生微妙的计数错误，例如`"aa"`里面`"aaaaa"`。 
- 每个字符频率必须完全匹配，而不仅仅是字符集。 

## 方法

 ### 蛮力方法

 最简单的方法是检查每个长度的子串`len(p)`里面`s`。 

对于每个子串：

 1. 提取子字符串。 
2. 统计字符频率或对子字符串进行排序。 
3.比较一下`p`。 

如果频率匹配，则记录起始索引。 

这是有效的，因为字谜词是通过匹配字符频率来定义的。 然而，它的效率很低，因为我们反复重建重叠子串的信息。 

如果我们对每个子字符串进行排序，复杂性就会变得昂贵。 即使使用频率计数，为每个窗口从头开始重建计数也会浪费工作，因为相邻窗口仅相差一个字符。 

高达`3 * 10^4`角色，我们需要更有效的策略。 

### 最优滑动窗口方法

 重要的见解是相同长度的连续子串严重重叠。 

假设当前窗口是：```
cba
```下一个窗口是：```
bae
```我们可以：

 - 删除最左边的字符（`c`）
 - 添加新的最右边的字符（`e`）

 这自然就引出了滑动窗口算法。 

我们维持：

 - 频率计数`p`- 当前窗口的频率计数`s`当窗口滑动时：

 - 添加传入的字符
 - 删除传出字符
 - 比较频率阵列

 由于只有 26 个小写英文字母，频率比较实际上是常数时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 重建每个子串的频率计数 |
 | 最佳| O(n) | O(1) | O(1) | 滑动窗口更新增量计数 |

 这里：

-`n = len(s)`-`m = len(p)`## 算法演练

 1.首先检查是否`p`长于`s`。 

如果`len(p) > len(s)`，不可能有任何子串`s`匹配`p`，因此立即返回一个空列表。 
2. 创建两个大小为 26 的频率数组。 

一个数组存储字符频率`p`。 

另一个数组存储当前滑动窗口的字符频率`s`。 

由于字符串仅包含小写英文字母，因此我们映射：```
'a' -> 0
'b' -> 1
...
'z' -> 25
```3. 填充第一个窗口的频率数组。 

计算字符数：

 -`p`- 第一个`len(p)`的字符`s`4. 比较两个频率阵列。 

如果它们匹配，那么第一个窗口是一个字谜，所以添加索引`0`到答案。 
5. 开始滑动窗口，一次一个字符。 

对于每个新职位：

 - 将新的最右边的字符添加到窗口计数中。 
- 从窗口计数中删除旧的最左边的字符。 

这可以在恒定时间内有效地更新窗口。 
6. 每次更新后，将窗口频率数组与目标频率数组进行比较。 

如果它们匹配，则当前窗口是一个字谜，因此记录窗口的起始索引。 
7. 继续，直到窗口到达字符串末尾。 
8. 返回收集到的索引。 

### 为什么它有效

 该算法保持一个不变量：

 - 窗口频率数组始终表示当前长度子串的确切字符数`len(p)`。 

因为两个字符串当且仅当它们的字符频率匹配时才是字谜词，因此每次窗口频率等于目标频率时，当前子字符串必须是字谜词`p`。 

滑动窗口保证所需长度的每个可能的子串都被检查一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        if len(p) > len(s):
            return []

        result = []

        p_count = [0] * 26
        window_count = [0] * 26

        for i in range(len(p)):
            p_count[ord(p[i]) - ord('a')] += 1
            window_count[ord(s[i]) - ord('a')] += 1

        if p_count == window_count:
            result.append(0)

        left = 0

        for right in range(len(p), len(s)):
            window_count[ord(s[right]) - ord('a')] += 1
            window_count[ord(s[left]) - ord('a')] -= 1

            left += 1

            if p_count == window_count:
                result.append(left)

        return result
```对于以下情况，实施从提前返回开始：`p`长于`s`。 

使用两个长度为26的数组来存储字符频率。 选择数组而不是字典是因为字符集固定且较小，使得数组访问更快更简单。 

第一个循环初始化两者的频率计数`p`和第一个窗口`s`。 

初始化后，算法检查第一个窗口是否已形成字谜。 

然后滑动窗口在字符串上移动。 每一步：

 - 一名角色进入窗口。 
- 一名角色离开窗口。 

这使窗口大小固定为`len(p)`。 

每次更新后都会比较频率数组。 每当它们匹配时，当前窗口就是一个有效的字谜词，并且其起始索引将添加到结果中。 

## 解决方案```go
func findAnagrams(s string, p string) []int {
    if len(p) > len(s) {
        return []int{}
    }

    result := []int{}

    pCount := make([]int, 26)
    windowCount := make([]int, 26)

    for i := 0; i < len(p); i++ {
        pCount[p[i]-'a']++
        windowCount[s[i]-'a']++
    }

    if equalCounts(pCount, windowCount) {
        result = append(result, 0)
    }

    left := 0

    for right := len(p); right < len(s); right++ {
        windowCount[s[right]-'a']++
        windowCount[s[left]-'a']--

        left++

        if equalCounts(pCount, windowCount) {
            result = append(result, left)
        }
    }

    return result
}

func equalCounts(a []int, b []int) bool {
    for i := 0; i < 26; i++ {
        if a[i] != b[i] {
            return false
        }
    }

    return true
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个显着的区别是 Go 不支持整数切片的直接切片相等性比较，因此需要一个辅助函数`equalCounts`用于手动比较两个频率阵列。 

Go 字符串是字节可索引的，这在这里完美工作，因为输入仅包含小写英文字母。 

当不存在匹配项时，该函数返回一个空切片，这是 Go 的惯用行为。

 ## 边缘情况

 ### 模式比字符串长

 如果`p`长于`s`, 没有子串`s`可能符合所需的长度。 这是滑动窗口实现中索引错误的常见来源。 

该解决方案立即处理此问题：```
if len(p) > len(s):
    return []
```这可以防止无效的窗口初始化和不必要的工作。 

### 重复字符

 案例如下：```
s = "aaaaa"
p = "aa"
```可能会暴露仅跟踪唯一字符而不是确切频率的实现中的错误。 

该算法正确地跟踪每个字符的计数，因此重叠窗口如`"aa"`都被正确检测到。 

### 重叠字谜

 输入例如：```
s = "abab"
p = "ab"
```包含重叠的有效窗口。 

幼稚的实现可能会在找到匹配项后意外地跳过窗口。 滑动窗口一次只移动一个位置，确保检查每个可能的子字符串。 

### 开头或结尾匹配

 某些实现错误地处理边界更新并错过字符串边缘的窗口。 

示例包括：```
"abc", "abc"
"baa", "aa"
```该算法明确检查：

 - 滑动前的初始窗口
 - 每次更新后的每个后续窗口

 这保证了两个边界处的匹配都能被正确检测到。
