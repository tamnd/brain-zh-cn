 # LeetCode 464 - 我能赢吗

 ## 问题理解

 该问题描述了一个两人回合制游戏。 玩家轮流从共享整数池中选择一个数字，范围为`1`到`maxChoosableInteger`。 一旦选择了一个号码，就不能在接下来的游戏中再次使用它。 

每个选定的数字都会添加到总计中。 导致累计总分大于或等于的玩家`desiredTotal`立即获胜。 

任务是确定如果两个玩家都发挥最佳，第一个玩家是否可以强制获胜。 

The input consists of two integers:

 -`maxChoosableInteger`定义最大可选数量，这意味着可用数量是`1`通过`maxChoosableInteger`-`desiredTotal`定义获胜所需的目标金额

 输出是一个布尔值：

 -`true`意味着第一个玩家可以保证胜利
 -`false`意味着第二个玩家总是可以阻止第一个玩家获胜

 约束条件很重要：

 -`maxChoosableInteger <= 20`-`desiredTotal <= 300`20 的小上限强烈表明位掩码是可行的。 由于最多有 20 个数字，因此每个游戏状态都可以使用 20 位整数来表示。 这一观察对于最佳解决方案至关重要。 

一些边缘情况立即出现：

 如果`desiredTotal == 0`，第一个玩家在采取行动之前就已经满足条件，所以答案是自动的`true`。 

如果所有可用数字的总和仍然小于`desiredTotal`，那么没有人能够达到目标。 在这种情况下，第一个玩家无法获胜。 

来自的数字总和`1`到`maxChoosableInteger`是：$1+2+\cdots+n=\frac{n(n+1)}{2}$对于这个问题：```
maxPossibleSum = maxChoosableInteger * (maxChoosableInteger + 1) / 2
```如果该值小于`desiredTotal`，答案一定是`false`。 

另一个重要的挑战是重复状态。 不同的移动顺序可能会产生相同的剩余数字集。 简单的递归搜索会重复重新计算相同的游戏状态，从而导致指数爆炸。 

## 方法

 ### 蛮力方法

 暴力解决方案递归地模拟每一个可能的游戏路径。 

在每一回合中，当前玩家都会尝试所有未使用的数字。 选择一个数字后，算法会递归地检查对手是否可以从结果状态中获胜。 

递归逻辑的工作原理如下：

 - 如果选择一个号码立即达到`desiredTotal`，当前玩家获胜
 - 否则，递归模拟对手的回合
 - 如果任何一步导致对手失败，则当前玩家可以强行获胜

 这种方法在逻辑上是正确的，因为它在最佳游戏假设下详尽地探索了博弈树。 

然而，相同的状态会被重新计算多次。 例如，数字所在的状态`{1, 3, 5}`已使用的可以通过多个移动命令到达：

 -`1 -> 3 -> 5`-`3 -> 1 -> 5`-`5 -> 3 -> 1`如果没有缓存，每个状态都会被重复重新计算，从而使解决方案变得太慢。 

最坏情况的分支因子很大，递归树呈阶乘增长。 

### 最佳方法，DFS + 记忆 + 位掩码

 关键的见解是游戏状态完全取决于已使用的数字。 

一旦我们知道了使用的数字和剩余的目标，移动的确切顺序就不再重要了。 

因为`maxChoosableInteger <= 20`，我们可以将使用的数字编码在位掩码中：

 - 位`i`代表是否数`i + 1`已被选择
 - A`1`bit 表示该号码已被使用
 - A`0`位表示该号码仍然可用

 这使得每个独特的游戏状态都可以有效地表示为整数。 

然后我们使用带有记忆功能的深度优先搜索：

 - DFS探索所有可能的行动
 - 记忆存储特定位掩码状态是赢还是输

 递归策略变为：

 - 尝试每个可用的号码
 - 如果选择该数字立即获胜，则返回`true`- 否则，递归检查对手的结果
 - 如果对手在任何分支中失败，则当前玩家获胜

 由于每个状态都计算一次，因此该算法变得可行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 探索所有移动排列，无需缓存 |
 | 最佳| O(2^n * n) | O(2^n * n) | O(2^n) | O(2^n) | 使用记忆和位掩码状态 |

 ## 算法演练

 1. 处理琐碎的获胜条件。 

如果`desiredTotal <= 0`，第一个玩家已经满足目标条件而没有采取任何行动，因此返回`true`。 
2. 检查在数学上是否可以达到目标。 

计算所有数字的总和`1`到`maxChoosableInteger`。```
totalSum = n * (n + 1) / 2
```如果`totalSum < desiredTotal`，任何移动序列都无法达到目标，因此返回`false`。 
3. 使用位掩码表示游戏状态。 

使用一个整数，其中每一位指示一个数字是否已被选择。 

例如，如果`maxChoosableInteger = 5`:

 | 位掩码| 已用号码 |
 | --- | --- |
 | 00000 | 无 |
 | 00101 | 1 和 3 |
 | 11111 | 11111 所有数字|
 4. 定义递归DFS 函数。 

DFS 函数接收：

 -`usedMask`，代表哪些数字已经被占用
 -`remaining`，代表还需要多少才能获胜

 该函数返回当前玩家是否可以从此状态强制获胜。 
5. 尝试每个可用的数字。 

对于每个数字`1`到`maxChoosableInteger`:

 - 如果已经使用则跳过它
 - 否则，请考虑选择它
 6. 检查立即获胜的动作。 

如果所选数字大于或等于`remaining`，当前玩家立即获胜。 
7、模拟对手。 

将所选数字标记为已使用，并递归评估对手的位置。 

如果递归调用返回`false`，这意味着对手从该状态开始就输了，因此当前玩家可以强行获胜。 
8. 记住结果。 

存储当前结果`usedMask`这样以后的调用就可以立即重用它。 
9. 返回最终答案。 

从以下位置启动 DFS：

 -`usedMask = 0`-`remaining = desiredTotal`### 为什么它有效

 该算法依赖于最优游戏和递归游戏状态评估。 

如果存在至少一个动作迫使对手进入失败状态，则该状态获胜。 

如果一个国家的每一个可能的举动都让对手最终获胜，那么这个国家就失败了。 

记忆化保证每个唯一状态仅被解决一次，而位掩码确保紧凑的状态表示。 

## Python 解决方案```python
class Solution:
    def canIWin(self, maxChoosableInteger: int, desiredTotal: int) -> bool:
        if desiredTotal <= 0:
            return True

        total_sum = maxChoosableInteger * (maxChoosableInteger + 1) // 2

        if total_sum < desiredTotal:
            return False

        memo = {}

        def dfs(used_mask: int, remaining: int) -> bool:
            if used_mask in memo:
                return memo[used_mask]

            for number in range(1, maxChoosableInteger + 1):
                bit = 1 << (number - 1)

                if used_mask & bit:
                    continue

                if number >= remaining:
                    memo[used_mask] = True
                    return True

                next_mask = used_mask | bit

                opponent_can_win = dfs(next_mask, remaining - number)

                if not opponent_can_win:
                    memo[used_mask] = True
                    return True

            memo[used_mask] = False
            return False

        return dfs(0, desiredTotal)
```实施从两个重要的边缘情况检查开始。 

如果`desiredTotal <= 0`，第一个玩家获胜，因为目标已经达到。 

接下来，该算法使用所有数字计算最大可能的总和。 如果连这个总数都达不到`desiredTotal`，获胜是不可能的。 

这`memo`字典存储先前计算的游戏状态。 键是代表已用数字的位掩码，值指示当前玩家是否可以从该状态强制获胜。 

递归`dfs`函数探索每一个可用的动作。 

对于每个候选人编号：

 - 一位的计算使用`1 << (number - 1)`- 如果该位已设置，则该号码已被使用
 - 否则，将对移动进行评估

 如果选择的数字立即满足目标，则函数返回`True`。 

否则，算法在更新位掩码并减少剩余目标后递归地评估对手的位置。 

如果对手无法从下一个状态获胜，则当前玩家已找到获胜策略。 

如果每一步都可以让对方获胜，那么现在的状态就是失败。 

## 解决方案```go
func canIWin(maxChoosableInteger int, desiredTotal int) bool {
	if desiredTotal <= 0 {
		return true
	}

	totalSum := maxChoosableInteger * (maxChoosableInteger + 1) / 2

	if totalSum < desiredTotal {
		return false
	}

	memo := make(map[int]bool)
	visited := make(map[int]bool)

	var dfs func(int, int) bool

	dfs = func(usedMask int, remaining int) bool {
		if visited[usedMask] {
			return memo[usedMask]
		}

		for number := 1; number <= maxChoosableInteger; number++ {
			bit := 1 << (number - 1)

			if usedMask&bit != 0 {
				continue
			}

			if number >= remaining {
				memo[usedMask] = true
				visited[usedMask] = true
				return true
			}

			nextMask := usedMask | bit

			opponentCanWin := dfs(nextMask, remaining-number)

			if !opponentCanWin {
				memo[usedMask] = true
				visited[usedMask] = true
				return true
			}
		}

		memo[usedMask] = false
		visited[usedMask] = true
		return false
	}

	return dfs(0, desiredTotal)
}
```Go 实现遵循与 Python 版本相同的递归策略。 

一个显着的区别是记忆处理。 由于 Go 映射对于缺失的键返回零值，因此需要一个单独的`visited`地图用于区分：

 - 尚未计算的状态
 - 已计算并评估为的状态`false`位掩码运算在 Go 中自然地与整数一起工作，并且递归结构与 Python 几乎相同。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`desiredTotal`为零或负数。 在这种情况下，在任何行动发生之前，游戏实际上已经获胜。 无论如何，天真的实现可能会错误地启动递归。 该解决方案立即通过提前返回来处理此问题。 

当所有可用数字的总和仍然小于`desiredTotal`。 如果不预先检查此条件，递归将在最终失败之前探索许多不可能的状态。 该实现通过返回来防止不必要的计算`false`立即地。 

更微妙的边缘情况涉及通过不同的移动顺序达到的重复状态。 例如，选择数字`{1, 3}`无论顺序是否正确，都会导致相同的游戏状态`1 -> 3`或者`3 -> 1`。 如果没有记忆，这些状态将被重复重新计算，导致指数级减速。 位掩码表示确保相同的状态映射到相同的记忆结果。 

另一种棘手的情况是，玩家可以通过选择大于或等于剩余目标的数字来立即获胜。 如果实现在检查此条件之前递归，它可能会错误地继续探索更深的状态。 该算法在递归开始之前明确检查立即获胜的动作。
