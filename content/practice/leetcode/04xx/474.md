[LeetCode 第 474 题](https://leetcode.com/problems/ones-and-zeroes/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们选择二进制字符串的最大可能子集，同时保持在两个资源限制之内。 

每个字符串消耗一定数量的`0`字符和一定数量的`1`人物。 我们有两个限制：

 -`m`，我们可以使用的最大零个数
 -`n`，我们可以使用的最大数量

 我们的目标是在不超过任一限制的情况下最大化子集中包含的字符串数量。 

例如，如果一个字符串包含两个零和三个一，则将其添加到子集中会增加零的总使用量`2`我们的总使用量为`3`。 仅当两个总数均保持在允许的限制范围内时，我们才可能包含该字符串。 

这并不是要求最长的连接字符串或最大总字符数。 目标具体是选择的字符串数量。 

输入包括：

 -`strs`，二进制字符串数组
 -`m`, 最大允许零数
 -`n`, 允许的最大数量

 输出是一个整数，表示最大有效子集的大小。 

约束条件很重要：

 - 最多`600`字符串
 - 每个字符串长度可达`100`-`m`和`n`最多`100`这些限制强烈表明指数子集枚举将不起作用。 对所有子集进行强力搜索需要检查`2^600`组合，这是不可能的。 

相对较小的值`m`和`n`是关键的观察结果。 因为两者最多都是`100`，我们可以构建一个动态规划解决方案，其状态取决于可用的零和一。 

一些边缘情况很重要：

 - 字符串可能包含比允许的更多的零或一，这意味着它永远不会被选择。 
- 可能会出现多个相同的字符串，并且必须单独处理每个出现的字符串。 
- 最佳解决方案可能会跳过长字符串，转而使用许多短字符串。 
- 某些字符串可能仅包含零或仅包含一。 
- 子集最多可以包含所有字符串，但资源限制通常会阻止这种情况。 

## 方法

 ### 蛮力

 最直接的方法是尝试字符串的每个可能的子集。 

对于每个子集，我们计算所使用的 0 和 1 的总数。 如果两个总数都在限制范围内，我们会将子集大小与当前最佳答案进行比较。 

这是有效的，因为每个可能的子集都会被检查，因此最终必须找到最佳子集。 

然而，子集的数量呈指数增长。 和`k`字符串，有`2^k`可能的子集。 自从`k`可以大到`600`，这种方法在计算上是不可行的。 

即使使用修剪或记忆化，由于巨大的状态空间，简单的递归搜索仍然会很困难。 

### 最优动态规划方法

 关键的见解是，这个问题在结构上与 0/1 背包问题相同，有两个约束而不是一个。 

在传统的背包问题中：

 - 每件物品都有重量
 - 每件物品都有其价值
 - 我们在不超出容量的情况下最大化价值

 这里：

 - 每个字符串消耗零和一
 - 每根弦都贡献价值`1`因为选择任何字符串都会使子集大小增加一
 - 我们最大化所选字符串的数量

 这就变成了一个二维背包问题。 

我们定义：

 -`dp[i][j]`作为我们最多可以选择的字符串的最大数量`i`零点和`j`那些

 对于每个字符串：

 1. 计算它包含多少个 0 和 1
 2.逆序更新DP表
 3. 决定包含当前字符串是否可以改善答案

 反向迭代是必不可少的，因为每个字符串只能使用一次。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^k * k) | O(2^k * k) | O(k) | 尝试字符串的每个子集 |
 | 最佳 | O(k * m * n) | O(m * n) | 二维0/1背包DP|

 这里，`k`代表字符串的数量。 

## 算法演练

 1. 创建二维DP表。 

我们创造`dp[m + 1][n + 1]`，其中每个条目存储在给定的零和一预算下可实现的最大字符串数。 

最初，所有值都是`0`因为不选择任何字符串总是有效的。 
2. 一次处理每个字符串。 

对于中的每个字符串`strs`，计数：

 - 它包含多少个零
 - 它包含多少个

 这些计数代表选择字符串的“成本”。 
3. 以相反顺序遍历DP 表。 

对于每个可能的零容量`m`下降到`zero_count`，以及每一项容量`n`下降到`one_count`，我们评估采用当前字符串是否可以改进解决方案。 

反向遍历至关重要，因为它可以防止在单次迭代期间多次使用相同的字符串。 
4. 更新DP状态。 

过渡是：$dp[i][j] = \max(dp[i][j],\ dp[i-zeroCount][j-oneCount] + 1)$这意味着：

 - 要么不采用当前字符串
 - 或者将其添加到先前的最佳解决方案中
 5. 继续，直到处理完所有字符串。 

处理完每个字符串后，`dp[m][n]`包含在限制内可实现的最大子集大小。 

### 为什么它有效

 DP 表保持不变式：`dp[i][j]`始终表示最多使用的最佳可实现子集大小`i`零点和`j`到目前为止处理过的字符串中的那些。 

因为每个字符串都只被考虑一次，并且每个有效的容量组合都被正确更新，所以该算法会探索所有可行的组合，而不会重复。 反向迭代保证 0/1 行为，这意味着每个字符串可以选择一次或跳过。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaxForm(self, strs: List[str], m: int, n: int) -> int:
        # dp[i][j] = maximum number of strings
        # using at most i zeros and j ones
        dp = [[0] * (n + 1) for _ in range(m + 1)]

        for binary_string in strs:
            zero_count = binary_string.count('0')
            one_count = binary_string.count('1')

            # Reverse iteration ensures each string
            # is used at most once
            for zeros in range(m, zero_count - 1, -1):
                for ones in range(n, one_count - 1, -1):
                    dp[zeros][ones] = max(
                        dp[zeros][ones],
                        dp[zeros - zero_count][ones - one_count] + 1
                    )

        return dp[m][n]
```实现首先创建一个二维 DP 表。 每个单元格代表在特定的零和一预算下可实现的最佳子集大小。 

对于每个字符串，我们计算它的零和一。 这些计数确定字符串是否适合给定的容量状态。 

嵌套反向循环是实现中最重要的部分。 通过向后迭代，我们确保当前字符串的更新不会影响同一迭代中的未来计算。 这保留了 0/1 背包属性。 

在每个州，我们比较：

 - 不取字符串的当前最佳值
 - 取字符串得到的值

 这两者中的最大值成为新的 DP 值。 

最后，答案存储在`dp[m][n]`，它代表在全部资源限制下可实现的最佳子集。 

## 解决方案```go
func findMaxForm(strs []string, m int, n int) int {
	dp := make([][]int, m+1)

	for i := range dp {
		dp[i] = make([]int, n+1)
	}

	for _, s := range strs {
		zeroCount := 0
		oneCount := 0

		for _, ch := range s {
			if ch == '0' {
				zeroCount++
			} else {
				oneCount++
			}
		}

		for zeros := m; zeros >= zeroCount; zeros-- {
			for ones := n; ones >= oneCount; ones-- {
				candidate := dp[zeros-zeroCount][ones-oneCount] + 1

				if candidate > dp[zeros][ones] {
					dp[zeros][ones] = candidate
				}
			}
		}
	}

	return dp[m][n]
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

Go 使用切片来构建二维 DP 表，而不是 Python 列表。 字符串遍历是使用`range`循环字符。 

Go 没有提供内置的`max`函数用于整数，因此比较是用`if`陈述。 

不存在整数溢出问题，因为最大可能的答案是`600`，它很容易适合 Go 的`int`类型。

class Solution:
    def findMaxForm(self, strs: List[str], m: int, n: int) -> int:

        for s in strs:
            zeros = s.count('0')

 ## 边缘情况

 当字符串单独超出资源限制时，就会出现一种重要的边缘情况。 例如，如果`m = 2`并且一个字符串包含三个零，则永远无法选择该字符串。 幼稚的实现可能仍然会尝试无效的转换或在 DP 表中索引负位置。 这种实现避免了这个问题，因为反向循环仅在容量足够大以容纳字符串时才执行。 

另一个重要的情况是重复的字符串。 输入中可能会出现多个相同的字符串，但每次出现都代表一个单独的可选项目。 有缺陷的解决方案可能会错误地使用集合对它们进行重复数据删除。 动态编程方法独立处理每个字符串，因此可以正确处理重复项。 

第三种微妙的边缘情况涉及反向迭代。 如果按前向顺序更新 DP 表，则可以在同一迭代中有效地多次重复使用字符串，从而将问题转化为无界背包问题。 反向遍历保证每个字符串最多对任何状态更新贡献一次。 

当容量非常小时，会出现最后一种边缘情况，例如`m = 0`或者`n = 0`。 在这些情况下，只能选择包含允许的字符类型的字符串。 DP 公式自然地处理了这个问题，因为只有当存在足够的容量时才会发生转换。
