[LeetCode 第 408 题](https://leetcode.com/problems/valid-word-abbreviation/)

 **难度：** 🟢简单
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到两个字符串：

 -`word`, 原来的完整单词
 -`abbr`，该词的假定缩写

 我们必须确定是否`abbr`是一个有效的缩写`word`。 

缩写的工作原理是将一个或多个非空子字符串替换为其长度。 例如，`"internationalization"`可以成为`"i12iz4n"`因为：

-`"i"`保持不变
 -`"12"`跳过十二个字符
 -`"iz"`保持不变
 -`"4"`跳过四个字符
 -`"n"`保持不变

 关键规则是：

 1. 数字代表要跳过的字符数`word`。 
2. 替换的子串必须非空。 
3. 不允许相邻的缩写部分，因为它们会自动合并成一个更大的数字。 
4. 数字不能包含前导零。 

该任务本质上是两个字符串的同步扫描。 阅读缩写时：

 - 如果我们看到一个字母，它必须与中对应的字母完全匹配`word`。 
- 如果我们看到一个数字，我们会跳过其中的许多字符`word`。 

最后，两个字符串必须同时被完全消耗。 

限制很小：

 -`word.length <= 20`-`abbr.length <= 10`这意味着性能不是主要问题，但我们仍然应该编写一个干净高效的解决方案。 

一些边缘情况很重要：

 - 带有前导零的数字，例如`"01"`均无效。 
- 跳过计数可能会超过末尾`word`。 
- 缩写可能会在单词之前结束，反之亦然。 
- 连续的数字必须被解析为一个完整的数字。 
- 个位数跳过，例如`"1"`是有效的，但是`"0"`不是。 

## 方法

 ### 蛮力方法

 暴力策略将尝试重建缩写的所有可能的扩展并将其与原始单词进行比较。 

例如，给定`"i12iz4n"`，我们可以将每个数字解释为一系列通配符，生成所有可能的替换，并检查其中一个是否等于目标单词。 

这在概念上是有效的，因为缩写准确定义了哪些字符是固定的，哪些是跳过的。 然而，快速生成所有可能的扩展变得低效且不必要的复杂。 尽管约束很小，但重复构建字符串和探索组合会带来可避免的开销。 

另一种暴力变体将逐个字符显式构建扩展版本，为跳过的部分插入占位符符号。 这更简单，但仍然需要额外的空间和字符串结构。 

### 最佳方法

 更好的方法使用两个指针：

 - 一根指针遍历`word`- 一根指针遍历`abbr`关键的观察是我们永远不需要重建缩写字符串。 我们只需要验证缩写是否正确映射到单词上。 

扫描时`abbr`：

 - 如果当前字符是字母，则必须与中的当前字符匹配`word`。 
- 如果当前字符是数字，我们解析整个数字并推进`word`指针按该量。 

这是有效的，因为缩写已经告诉我们要跳过多少个字符。 一旦解析了数字，就不存在歧义了。 

该解决方案高效、简单，并且使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 构建或重建扩展形式 |
 | 最佳 | O(n + m) | O(1) | O(1) | 无需重建的两指针扫描 |

 这里：

-`n = len(word)`-`m = len(abbr)`## 算法演练

 1.初始化两个指针：

 -`word_index`用于遍历`word`-`abbr_index`用于遍历`abbr`2. 当两个指针都在边界内时继续处理。 
3. 如果当前字符在`abbr`是一封信：

 - 将其与当前字符进行比较`word`。 
- 如果不同，则返回`False`。 
- 否则，将两个指针都前进一。 
4. 如果当前字符在`abbr`是一个数字：

 - 首先检查是否是`'0'`。 
- 如果是的话`'0'`， 返回`False`因为前导零无效。 
- 通过消耗连续数字来解析完整的数字。 
- 将数字序列转换为整数。 
- 进步`word_index`按那个数字。 
5. 处理完成后，验证：

 -`word_index == len(word)`-`abbr_index == len(abbr)`6. 返回`True`仅当两根弦完全一起消耗时。 

### 为什么它有效

 该算法保持以下不变量：

 -`word_index`总是指向下一个不匹配的字符`word`-`abbr_index`总是指向下一个未处理的字符`abbr`每当我们遇到一个数字时，我们都会正确地跳过其中的多个字符`word`。 每当我们遇到一个字母时，我们都会确保它直接匹配。 由于剧中的每一个角色`abbr`仅处理一次并且精确考虑每个跳过的部分，算法正确地确定缩写是否有效。 

## Python 解决方案```python
class Solution:
    def validWordAbbreviation(self, word: str, abbr: str) -> bool:
        word_index = 0
        abbr_index = 0

        while word_index < len(word) and abbr_index < len(abbr):
            if abbr[abbr_index].isalpha():
                if word[word_index] != abbr[abbr_index]:
                    return False

                word_index += 1
                abbr_index += 1
            else:
                if abbr[abbr_index] == '0':
                    return False

                number = 0

                while abbr_index < len(abbr) and abbr[abbr_index].isdigit():
                    number = number * 10 + int(abbr[abbr_index])
                    abbr_index += 1

                word_index += number

        return word_index == len(word) and abbr_index == len(abbr)
```实现直接遵循两指针算法。 

变量`word_index`和`abbr_index`跟踪两个字符串中的当前位置。 当两个指针都没有到达末尾时，主循环将继续。 

当当前缩写字符是字母时，代码执行直接字符比较。 如果字符不匹配，则缩写无效。 

当当前缩写字符是数字时，代码首先立即拒绝前导零。 然后它使用循环解析整个数字，这很重要，因为多位值，例如`"12"`表示单个跳跃量而不是两个单独的跳跃。 

解析完数字后，代码前进`word_index`通过跳过量。 

最后，该解决方案验证两个字符串是否已完全处理。 这可以防止一个字符串早于另一字符串完成的情况。 

## 解决方案```go
func validWordAbbreviation(word string, abbr string) bool {
	wordIndex := 0
	abbrIndex := 0

	for wordIndex < len(word) && abbrIndex < len(abbr) {
		char := abbr[abbrIndex]

		if char >= 'a' && char <= 'z' {
			if word[wordIndex] != char {
				return false
			}

			wordIndex++
			abbrIndex++
		} else {
			if char == '0' {
				return false
			}

			number := 0

			for abbrIndex < len(abbr) &&
				abbr[abbrIndex] >= '0' &&
				abbr[abbrIndex] <= '9' {

				number = number*10 + int(abbr[abbrIndex]-'0')
				abbrIndex++
			}

			wordIndex += number
		}
	}

	return wordIndex == len(word) && abbrIndex == len(abbr)
}
```Go 实现遵循与 Python 版本相同的逻辑，但有一些特定于语言的细节。 

Go 字符串被索引为字节切片，因此使用 ASCII 比较来执行字符检查，例如：```go
char >= 'a' && char <= 'z'
```数字解析是通过手动减法完成的`'0'`从字节值。 

Go 不提供 Python 风格`isdigit()`或者`isalpha()`方法直接作用于字符，因此使用显式比较。 

该问题保证所有整数都适合 32 位整数，因此标准`int`处理就足够了。

 ## 边缘情况

 一种重要的边缘情况是前导零。 像这样的缩写`"a01b"`如果实现只是正常解析整数，则可能会意外地被视为跳过一个字符。 然而，该问题明确禁止前导零。 该解决方案通过立即返回来处理此问题`False`每当数字段开头时`'0'`。 

当跳过量超出单词末尾时，会出现另一种棘手的情况。 例如，`"word"`带缩写`"5"`即使该单词只包含四个字符，也会尝试跳过五个字符。 一些不正确的实现可能会提前停止并仍然返回`True`。 此实现避免了该错误，因为最终验证要求两个指针完全按照其字符串长度完成。 

第三个重要情况是处理后不完全对准。 考虑`"word"`和`"w1r1"`。 尽管缩写结构看起来似乎合理，但跳过的位置并未与其余字母正确对齐。 该算法捕获了这一点，因为在遍历过程中会立即检查每个文字字符比较。 

最后一个微妙的情况涉及正确解析多位数字。 例如，`"12"`必须意味着跳过十二个字符，而不是跳过一个字符两次。 该实现正确地一起消耗连续的数字并在推进指针之前构建完整的整数`word`。
