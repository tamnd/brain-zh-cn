 ## 解决方案

 ## 问题理解

 该问题模拟了在一排彩球上进行的递归消除游戏。 棋盘被表示为一个字符串，其中每个字符对应一个彩球。 可用的颜色有`'R'`,`'Y'`,`'B'`,`'G'`， 和`'W'`。 

您还获得了另一个名为的字符串`hand`，它代表您可以插入棋盘的额外球。 在每次移动过程中，您从手中选择一个球并将其插入棋盘上的任何位置，包括开始或结束。 

每次插入后，棋盘都会根据一个规则反复缩小：

 - 任何包含至少三个相同颜色的球的连续组将被删除。 
- 删除一个组可能会在其他地方创建一个新的可删除组。 
- 这种连锁反应持续进行，直到没有可去除的基团残留。 

目标是在使用尽可能少的插入球的情况下完全清除棋盘。 如果用可用的手无法清除棋盘，则答案是`-1`。 

约束条件极其重要：

 -`board.length <= 16`-`hand.length <= 5`这些限制足够小，指数搜索是可行的，但只能进行积极的修剪和记忆。 简单的暴力搜索仍然会爆炸，因为每次移动都可以分支到许多插入位置和颜色选择。 

另一个重要的保证是初始棋盘尚未包含三个或更多连续相同球的组。 这意味着每次消除都必须由插入触发。 

一些边缘情况使这个问题变得棘手：

 - 连锁反应可能会意外地去除大部分电路板。 
- 不同的插入顺序可能会导致截然不同的结果。 
- 可以通过多个路径达到相同的板状态，因此如果没有记忆，重新计算将变得极其昂贵。 
- 即使棋盘看起来接近完成，某些状态也是不可能的，因为手中没有所需的颜色。 
- 将球插入看似多余的位置可能仍然是最佳选择，因为它会引发未来的连锁反应。 

## 方法

 ### 蛮力

 蛮力解决方案使用手中的每个可用球尝试在每个位置处的所有可能插入。 每次插入后，它都会重复删除所有有效组并递归地继续探索。 

这种方法是正确的，因为它探索了可能移动的整个状态空间。 最终，如果存在解决方案，一个分支就会发现它。 

然而，分支因素是巨大的。 假设木板有长度`n`手有长度`m`。 对于每个递归级别，大约可以有：

 -`n + 1`插入位置
 - 最多`m`球的选择

 这将创建一个接近以下位置的搜索空间：$$O((n \cdot m)^m)$$即使有很小的限制，这也会变得非常昂贵，因为许多州都会重复。 

### 通过 Memoization 优化 DFS

 关键的见解是许多递归状态是相同的。 

状态完全由以下因素决定：

 - 当前板配置
 - 手中剩余的球

 如果我们解决了一个状态一次，我们就不应该再次重新计算它。 

优化的解决方案使用具有记忆功能的深度优先搜索：

 - 递归地尝试所有有用的插入。 
- 每次插入后，使用连锁反应完全折叠电路板。 
- 缓存每个结果`(board, hand)`状态。 

另一个重要的优化是修剪不必要的插入：

 - 如果插入球无法帮助形成或扩展可移动组，请跳过它。 
- 避免相同的插入位置以减少重复工作。 

由于棋盘长度很小，而手的大小最多为 5 只，记忆会大大减少有效搜索空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数，大致为 O((n·m)^m) | O(m) 递归深度 | 探索每个插入序列而不重复使用 |
 | 最佳 DFS + 记忆 | 最坏情况下呈指数增长，严重修剪 | O(缓存状态数) | 重用重复状态并删除冗余分支 |

 ## 算法演练

 1. 定义一个辅助函数，用于从板上删除连续的组。 

每次插入后，该板都可能引发多个连锁反应。 我们反复扫描棋盘，寻找长度至少为三的连续游程。 一旦发现，我们就会将其删除并重新启动扫描。 

这个标准化步骤至关重要，因为每个递归状态都应该代表一个完全稳定的板。 
2. 定义递归DFS 函数。 

DFS 函数接收：

 - 当前棋盘字符串
 - 剩余手数

 它的工作是计算将电路板从该状态清除所需的最小插入次数。 
3. 处理基本情况。 

如果棋盘是空的，则答案是`0`因为不需要更多的插入。 

如果手牌已耗尽而棋盘非空，则该状态是不可能的。 
4. 记住状态。 

由于许多递归路径会导致相同的配置，因此我们将结果存储在缓存中，键控如下：

 - 当前董事会
 - 剩余颜色的计数

 这避免了指数重新计算。 
5. 尝试每一种可能的插入方式。 

对于板上的每个位置，尝试插入每种可用的颜色。 

但是，我们应用修剪规则：

 - 跳过产生相同状态的重复插入。 
- 仅当移动有助于创建或扩展匹配组时才插入。 
6. 插入球并折叠板子。 

插入后构造新的板串，然后运行消除助手以应用所有连锁反应。 
7. 在缩减状态上递归。 

从手中扣除已使用的球并递归计算剩余成本。 

如果递归调用成功，则将答案更新为：$$1 + \text{recursive result}$$8. 返回最小答案。 

如果没有递归分支成功，则在内部返回无穷大，然后将其转换为`-1`。 

### 为什么它有效

 该算法探索每个有意义的插入序列，同时记忆保证每个唯一状态仅解决一次。 由于每个递归调用都代表完全消除后的有效游戏状态，因此递归正确地模拟了游戏的规则。 通过取所有有效递归分支的最小值，该算法保证了最佳答案。 

## Python 解决方案```python
from collections import Counter
from functools import lru_cache
from typing import Dict

class Solution:
    def findMinStep(self, board: str, hand: str) -> int:
        hand_count = Counter(hand)

        def shrink(s: str) -> str:
            changed = True

            while changed:
                changed = False
                i = 0
                new_board = []

                while i < len(s):
                    j = i

                    while j < len(s) and s[j] == s[i]:
                        j += 1

                    if j - i >= 3:
                        changed = True
                    else:
                        new_board.append(s[i:j])

                    i = j

                s = "".join(new_board)

            return s

        @lru_cache(None)
        def dfs(board_state: str, hand_state: tuple) -> int:
            if not board_state:
                return 0

            hand_map = dict(hand_state)

            INF = float("inf")
            best = INF

            for i in range(len(board_state) + 1):
                for color in hand_map:
                    if hand_map[color] == 0:
                        continue

                    # Pruning:
                    # Only insert if it can help form a group
                    should_insert = False

                    if i > 0 and board_state[i - 1] == color:
                        should_insert = True

                    if i < len(board_state) and board_state[i] == color:
                        should_insert = True

                    if not should_insert:
                        continue

                    new_board = board_state[:i] + color + board_state[i:]
                    reduced_board = shrink(new_board)

                    hand_map[color] -= 1

                    next_hand = tuple(sorted(hand_map.items()))
                    result = dfs(reduced_board, next_hand)

                    if result != INF:
                        best = min(best, 1 + result)

                    hand_map[color] += 1

            return best

        initial_hand = tuple(sorted(hand_count.items()))
        answer = dfs(board, initial_hand)

        return answer if answer != float("inf") else -1
```该实现首先使用以下方法计算手中的可用球`Counter`。 由于递归状态取决于剩余球数，因此这种结构使更新更加高效。 

这`shrink()`助手重复扫描棋盘并删除每个连续长度至少三个。 每次移除过程后，扫描都会重新启动，因为连锁反应可能会形成新的可移除组。 

DFS 函数使用以下方式记忆`lru_cache`。 缓存键由以下部分组成：

 - 当前棋盘字符串
 - 剩余手数的元组表示

 在 DFS 中，我们尝试每个插入位置和每种可用颜色。 在执行插入之前，修剪规则确定移动是否可能有用。 具体来说，我们只插入接近匹配的颜色，因为无助于形成组的随机插入几乎从不富有成效。 

插入后，使用以下方法将板折叠起来`shrink()`，然后以更新的手部状态继续递归。 

返回最小成功插入计数。 不可能的状态向上传播无穷大，最终转换为`-1`。 

## 解决方案```go
package main

import (
	"math"
	"sort"
	"strconv"
)

func findMinStep(board string, hand string) int {
	handCount := map[byte]int{}

	for i := 0; i < len(hand); i++ {
		handCount[hand[i]]++
	}

	memo := map[string]int{}

	var shrink func(string) string

	shrink = func(s string) string {
		changed := true

		for changed {
			changed = false
			result := ""

			for i := 0; i < len(s); {
				j := i

				for j < len(s) && s[j] == s[i] {
					j++
				}

				if j-i >= 3 {
					changed = true
				} else {
					result += s[i:j]
				}

				i = j
			}

			s = result
		}

		return s
	}

	var encodeHand func(map[byte]int) string

	encodeHand = func(handMap map[byte]int) string {
		colors := []byte{'R', 'Y', 'B', 'G', 'W'}

		result := ""

		for _, c := range colors {
			result += string(c) + strconv.Itoa(handMap[c])
		}

		return result
	}

	var dfs func(string, map[byte]int) int

	dfs = func(boardState string, handMap map[byte]int) int {
		if boardState == "" {
			return 0
		}

		key := boardState + "|" + encodeHand(handMap)

		if val, exists := memo[key]; exists {
			return val
		}

		best := math.MaxInt32

		for i := 0; i <= len(boardState); i++ {
			colors := []byte{'R', 'Y', 'B', 'G', 'W'}

			sort.Slice(colors, func(a, b int) bool {
				return colors[a] < colors[b]
			})

			for _, color := range colors {
				if handMap[color] == 0 {
					continue
				}

				shouldInsert := false

				if i > 0 && boardState[i-1] == color {
					shouldInsert = true
				}

				if i < len(boardState) && boardState[i] == color {
					shouldInsert = true
				}

				if !shouldInsert {
					continue
				}

				newBoard := boardState[:i] + string(color) + boardState[i:]
				reduced := shrink(newBoard)

				handMap[color]--

				result := dfs(reduced, handMap)

				if result != math.MaxInt32 {
					best = min(best, 1+result)
				}

				handMap[color]++
			}
		}

		memo[key] = best
		return best
	}

	answer := dfs(board, handCount)

	if answer == math.MaxInt32 {
		return -1
	}

	return answer
}

func min(a int, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 版本遵循与 Python 解决方案相同的递归结构，但几个实现细节有所不同。 

因为 Go 不提供内置的记忆化装饰器，例如`lru_cache`，记忆是使用手动实现的`map[string]int`。 

使用以下方法将剩余的手部状态编码为确定性字符串`encodeHand()`。 这使得它可以作为记忆密钥的一部分。 

Go 中的字符串是不可变的，因此构建新板需要使用字符串切片和连接。 由于板的长度最多为 16，因此这仍然足够高效。 

Go 也缺乏 Python 的无穷表示，所以`math.MaxInt32`用作哨兵不可能值。

 ## 边缘情况

 当棋盘仅包含一个球时，会出现一种重要的边缘情况，例如`"G"`。 幼稚的实现可能会错误地认为一次插入就足够了，但规则要求在移除之前至少插入三个连续的球。 该实现正确地处理了这个问题，因为仅当组大小达到三或更大时才会发生淘汰。 

另一个棘手的案例涉及连锁反应。 例如，删除一组可能会导致两个先前分离的组合并为可删除的三元组。 仅执行一次消除传递的实现在这里会失败。 这`shrink()`助手重复扫描电路板，直到无法进一步移除为止，确保每个连锁反应都得到完全处理。 

第三个重要的边缘情况涉及通过不同插入顺序达到的重复状态。 如果没有记忆，递归搜索就会变得异常缓慢，因为相同的子问题会被重复解决。 该实现通过缓存每个`(board, hand)`状态，确保每个配置仅计算一次。 

当插入在本地看起来无用但可以在将来删除时，就会出现另一种微妙的边缘情况。 积极的修剪可能会意外删除有效的最佳路径。 该实现使用保守的修剪规则，仅跳过明显冗余的插入，同时仍然探索所有潜在有用的组形成动作。
