[LeetCode 460 题](https://leetcode.com/problems/lfu-cache/)

 **难度：** 🔴难
 **主题：** 哈希表、链表、设计、双向链表

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个支持两种操作的缓存：

 -`get(key)`如果存在则返回与键关联的值，否则返回`-1`-`put(key, value)`插入或更新键值对

 与普通缓存不同，逐出不仅仅基于新近度。 相反，此缓存使用最不常用策略。 

每个键都维护一个频率计数器：

 - 新插入的钥匙以频率开始`1`- 每一次成功`get`- 每次更新通过`put`增加该频率

 当缓存已满并且必须插入新键时，我们会删除频率最小的键。 

如果多个键共享相同的最小频率，我们将使用最近最少使用的排序来打破联系。 在频率相同的键中，最旧的键被删除。 

最大的挑战是性能要求。 两个都`get`和`put`必须跑进去`O(1)`平均时间复杂度。 

约束足够大，任何线性扫描方法都会失败：

 - 容量可达`10^4`- 最多`2 * 10^5`执行操作

 这意味着我们无法重复搜索所有键来查找最不常用的项目。 

正确的解决方案必须有效支持：

 1.快速查找某个key
 2、更新频率快
 3.快速找到最小频率
 4. 快速删除等频率中最近最少使用的密钥

 一些边缘情况很重要：

 - 容量可以为零
 - 更新现有密钥应该增加频率
 - 多个按键可以共享相同的频率
 - 最小频率随着密钥更新而动态变化
 - 移动节点后频率列表可能会变空

 这些细节使得实现比标准 LRU 缓存复杂得多。 

## 方法

 ### 蛮力方法

 一个简单的实现会将所有缓存条目存储在哈希映射中，并为每个键维护一个频率计数器。 

对于每一个`get`或者`put`，我们更新相应的频率。 

当需要驱逐时，我们扫描所有键以查找：

 1. 最低频率
 2. 在这些键中，最近最少使用的键

 这种方法是正确的，因为我们每次都会显式地计算驱逐候选者。 

然而，驱逐步骤变得昂贵。 在最坏的情况下，我们可能会扫描每个`put`手术。 由于缓存最多可以包含`10^4`元素，并且可以有`2 * 10^5`操作，这变得太慢了。 

### 最佳方法

 关键的见解是我们需要两个层次的组织：

 1.按键快速查找
 2.按频率快速分组

 我们结合：

 - 从键到节点的哈希映射
 - 从频率到双向链表的哈希图

 每个频率都有自己的 LRU 列表。 

例如：

 - 频率`1`有一个双向链表
 - 频率`2`还有另一个清单
 - 频率`3`还有另一个清单

 在每个频率列表中：

 - 最近使用的节点靠近前面
 - 最近最少使用的节点靠近后面

 这种结构使我们能够：

 - 在频率列表之间移动节点`O(1)`- 从最小频率列表中删除LRU节点`O(1)`- 更新频率`O(1)`我们还维护着全球`min_freq`变量，所以我们总是知道当前的最小频率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n)`每次驱逐 |`O(n)`| 扫描所有键以查找 LFU/LRU 候选者 |
 | 最佳|`O(1)`每次操作的平均值 |`O(n)`| 使用哈希映射加上基于频率的双向链表 |

 ## 算法演练

 ### 数据结构

 我们维护四个重要组成部分：

 1.A`Node`对象存储：

 - 钥匙
 - 价值
 - 频率
 - 前一个指针
 - 下一个指针
 2. 哈希图：

 -`key_to_node[key] -> node`3. 哈希图：

 -`freq_to_list[freq] -> doubly linked list`4. 变量：

 -`min_freq`每个双向链表按照LRU顺序存储频率相同的节点。 

### 逐步算法

 1. 初始化固定容量的缓存。 

我们创造：

 - 一个空的键到节点映射
 - 一个空的频率列表映射
 -`min_freq = 0`2. 对于`get(key)`:

 首先检查缓存中是否存在该key。 

如果没有找到，则返回`-1`。 

否则：

 - 检索节点
 - 增加其频率
 - 将其从旧频率列表移至新频率列表
 - 返回它的值
 3. 增加节点的频率：

 假设节点当前有频率`f`。 

我们：

 - 从频率列表中删除它`f`- 如果该列表变空并且`f == min_freq`, 增量`min_freq`- 增加节点频率`f + 1`- 将节点插入频率列表`f + 1`4. 对于`put(key, value)`:

 如果容量为零，则不执行任何操作。 
5. 如果密钥已经存在：

 我们：

 - 更新节点值
 - 将此视为访问
 - 增加其频率
 6. 如果key不存在并且缓存已满：

 我们必须驱逐。 

驱逐候选人是：

 - 最近最少使用的节点
 - 从频率列表中`min_freq`由于列表是按 LRU 顺序维护的：

 - 尾部附近的节点被删除
 7. 驱逐后：

 我们创建一个新节点：

 - 频率开始于`1`然后：

 - 将其插入频率列表`1`- 将其添加到按键映射中
 - 设置`min_freq = 1`### 为什么它有效

 该算法保持两个不变量：

 1. 每个频率列表仅包含具有该确切频率的节点。 
2. 在频率列表中，节点按新近度排序。 

因为`min_freq`始终跟踪最小的现有频率，驱逐始终从正确的频率组中进行选择。 

由于每个频率列表均按 LRU 顺序维护，因此删除该组内最近最少使用的节点也是正确的。 

这些不变量共同保证驱逐始终遵循 LFU 规则和 LRU 平局打破。 

## Python 解决方案```python
from collections import defaultdict
from typing import Optional

class Node:
    def __init__(self, key: int, value: int):
        self.key = key
        self.value = value
        self.freq = 1

        self.prev: Optional["Node"] = None
        self.next: Optional["Node"] = None

class DoublyLinkedList:
    def __init__(self):
        self.head = Node(0, 0)
        self.tail = Node(0, 0)

        self.head.next = self.tail
        self.tail.prev = self.head

        self.size = 0

    def add_front(self, node: Node) -> None:
        node.next = self.head.next
        node.prev = self.head

        self.head.next.prev = node
        self.head.next = node

        self.size += 1

    def remove(self, node: Node) -> None:
        prev_node = node.prev
        next_node = node.next

        prev_node.next = next_node
        next_node.prev = prev_node

        self.size -= 1

    def remove_last(self) -> Node:
        if self.size == 0:
            return None

        last_node = self.tail.prev
        self.remove(last_node)

        return last_node

class LFUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.min_freq = 0

        self.key_to_node = {}
        self.freq_to_list = defaultdict(DoublyLinkedList)

    def _update_frequency(self, node: Node) -> None:
        old_freq = node.freq

        old_list = self.freq_to_list[old_freq]
        old_list.remove(node)

        if old_freq == self.min_freq and old_list.size == 0:
            self.min_freq += 1

        node.freq += 1

        new_list = self.freq_to_list[node.freq]
        new_list.add_front(node)

    def get(self, key: int) -> int:
        if key not in self.key_to_node:
            return -1

        node = self.key_to_node[key]
        self._update_frequency(node)

        return node.value

    def put(self, key: int, value: int) -> None:
        if self.capacity == 0:
            return

        if key in self.key_to_node:
            node = self.key_to_node[key]
            node.value = value

            self._update_frequency(node)
            return

        if len(self.key_to_node) == self.capacity:
            lfu_list = self.freq_to_list[self.min_freq]

            node_to_remove = lfu_list.remove_last()

            del self.key_to_node[node_to_remove.key]

        new_node = Node(key, value)

        self.key_to_node[key] = new_node

        freq_list = self.freq_to_list[1]
        freq_list.add_front(new_node)

        self.min_freq = 1
```该实现使用自定义双向链表，因为Python的内置结构不支持任意节点删除`O(1)`时间。 

每个频率都有自己的双向链表。 只要访问频率发生变化，节点就会在这些列表之间移动。 

这`_update_frequency`helper 集中了所有频率更新逻辑。 这可以防止之间重复的代码`get`和`put`。 

这`min_freq`变量尤为重要。 如果没有它，我们将需要扫描频率来确定驱逐目标，这将违反`O(1)`要求。 

双向链表按新近度顺序存储节点：

 - 前面 = 最近使用过的
 - 返回 = 最近最少使用

 这允许高效的 LFU 加 LRU 打破平局。 

## 解决方案```go
package main

type Node struct {
	key   int
	value int
	freq  int

	prev *Node
	next *Node
}

type DoublyLinkedList struct {
	head *Node
	tail *Node
	size int
}

func NewDoublyLinkedList() *DoublyLinkedList {
	head := &Node{}
	tail := &Node{}

	head.next = tail
	tail.prev = head

	return &DoublyLinkedList{
		head: head,
		tail: tail,
	}
}

func (dll *DoublyLinkedList) AddFront(node *Node) {
	node.next = dll.head.next
	node.prev = dll.head

	dll.head.next.prev = node
	dll.head.next = node

	dll.size++
}

func (dll *DoublyLinkedList) Remove(node *Node) {
	prevNode := node.prev
	nextNode := node.next

	prevNode.next = nextNode
	nextNode.prev = prevNode

	dll.size--
}

func (dll *DoublyLinkedList) RemoveLast() *Node {
	if dll.size == 0 {
		return nil
	}

	lastNode := dll.tail.prev
	dll.Remove(lastNode)

	return lastNode
}

type LFUCache struct {
	capacity  int
	minFreq   int
	keyToNode map[int]*Node
	freqToList map[int]*DoublyLinkedList
}

func Constructor(capacity int) LFUCache {
	return LFUCache{
		capacity:  capacity,
		minFreq:   0,
		keyToNode: make(map[int]*Node),
		freqToList: make(map[int]*DoublyLinkedList),
	}
}

func (this *LFUCache) updateFrequency(node *Node) {
	oldFreq := node.freq

	oldList := this.freqToList[oldFreq]
	oldList.Remove(node)

	if oldFreq == this.minFreq && oldList.size == 0 {
		this.minFreq++
	}

	node.freq++

	if _, exists := this.freqToList[node.freq]; !exists {
		this.freqToList[node.freq] = NewDoublyLinkedList()
	}

	newList := this.freqToList[node.freq]
	newList.AddFront(node)
}

func (this *LFUCache) Get(key int) int {
	node, exists := this.keyToNode[key]

	if !exists {
		return -1
	}

	this.updateFrequency(node)

	return node.value
}

func (this *LFUCache) Put(key int, value int) {
	if this.capacity == 0 {
		return
	}

	if node, exists := this.keyToNode[key]; exists {
		node.value = value
		this.updateFrequency(node)
		return
	}

	if len(this.keyToNode) == this.capacity {
		lfuList := this.freqToList[this.minFreq]

		nodeToRemove := lfuList.RemoveLast()

		delete(this.keyToNode, nodeToRemove.key)
	}

	newNode := &Node{
		key:   key,
		value: value,
		freq:  1,
	}

	if _, exists := this.freqToList[1]; !exists {
		this.freqToList[1] = NewDoublyLinkedList()
	}

	this.freqToList[1].AddFront(newNode)

	this.keyToNode[key] = newNode
	this.minFreq = 1
}

/**
 * Your LFUCache object will be instantiated and called as such:
 * obj := Constructor(capacity);
 * param_1 := obj.Get(key);
 * obj.Put(key,value);
 */
```Go 实现遵循与 Python 版本相同的整体设计。 

一个重要的区别是显式的指针处理。 Go 不像 Python 那样提供内置的可空对象引用，因此所有链表操作都直接使用指针。 

频率列表使用延迟初始化`make(map[int]*DoublyLinkedList)`和条件创造。 

对于给定的约束，Go 整数足够大，因此这里不存在溢出问题。

 ## 边缘情况

 ### 容量为零

 如果容量为零，则缓存无法存储任何内容。 这种情况很容易被忽视，因为插入逻辑可能仍然尝试分配节点或逐出条目。 

该实现在开始时立即处理这个问题`put`:```
if self.capacity == 0:
    return
```这保证了缓存始终保持为空。 

### 更新现有密钥

 当`put(key, value)`调用现有密钥时，该操作将计入使用情况，并且必须增加频率。 

一个常见的错误是更新值而不调整频率。 

该实现通过调用来避免这种情况`_update_frequency(node)`更新值后。 

### 相同频率的多个按键

 问题中最困难的部分是打破平局。 

假设几个键都有频率`2`。 我们必须驱逐其中最近最少使用的。 

如果不仔细维护新近度排序，幼稚的实现可能会意外地逐出错误的密钥。 

双向链表通过按照精确的使用顺序存储键来解决这个问题：

 - 前面 = 最近的
 - 返回=最近的

 驱逐总是从最小频率列表的尾部删除，保证正确的 LRU 行为。 

### 频率列表变空

 将节点移出当前最小频率列表时会出现另一个微妙的问题。 

如果该列表变空，`min_freq`必须增加。 

更新失败`min_freq`导致未来的驱逐以空列表为目标。 

实施检查：```
if old_freq == self.min_freq and old_list.size == 0:
    self.min_freq += 1
```这确保了`min_freq`始终指向有效的频率组。
