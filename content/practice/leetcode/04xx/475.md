[LeetCode 第 475 题](https://leetcode.com/problems/heaters/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找、排序

 ## 解决方案

 ## 问题理解

 问题给出两个数组，`houses`和`heaters`，其中每个值代表一维水平线上的一个位置。 每个加热器都有相同的取暖半径，如果至少有一个加热器到房屋的距离小于或等于该半径，则认为该房屋被覆盖。 

任务是计算所需的最小半径，以便每栋房屋至少有一个加热器覆盖。 

换句话说，对于每栋房子，我们想知道距离最近的加热器有多远。 由于所有加热器必须使用相同的半径，因此最终答案是这些最小距离中的最大值。 

例如，如果房屋位于位置`5`最近的加热器位于位置`2`，那么该房子至少需要半径`3`。 如果另一栋房子只需要半径`1`，整个系统仍然必须使用radius`3`，因为每间房子都必须被覆盖。 

约束条件很重要：

 - 最多`3 * 10^4`房屋和加热器
 - 头寸可以大到`10^9`这些限制告诉我们二次解太慢。 检查每间房屋的每个加热器的解决方案需要：$$3 \times 10^4 \times 3 \times 10^4 = 9 \times 10^8$$在最坏的情况下进行操作，其规模太大了。 

该问题还保证：

 - 至少有一所房子
 - 至少有一个加热器
 - 仓位为正整数

 重要的边缘情况包括：

 - 一个加热器覆盖两侧的房屋
 - 位于第一个加热器之前的房屋
 - 位于最后一个加热器之后的房屋
 - 不同距离的多个加热器
 - 重复或紧密排列的仓位
 - 非常大的坐标值

 这些情况很重要，因为靠近阵列边界的最近加热器计算很容易出现一误差。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每栋房屋并计算其与每个加热器的距离。 

对于每栋房子：

 1. 迭代所有加热器
 2. 计算绝对距离
 3. 与那所房子保持最小距离
 4. 跟踪所有房屋之间的最大最小距离

 这是有效的，因为最近的加热器决定了特定房屋所需的最小半径，而最大的此类值决定了全局半径。 

然而，这种方法效率低下。 如果有`n`房屋和`m`加热器，时间复杂度变为`O(n * m)`。 两个数组都可能包含`30,000`元素，这变得太慢了。 

### 最优方法，排序+二分查找

 关键的观察是我们只关心每间房子最近的加热器。 

如果加热器已排序，那么对于任何房屋，我们都可以使用二分搜索有效地找到最近的加热器，而不是扫描整个加热器阵列。 

对于给定的房屋位置：

 - 二分查找查找已排序的加热器数组中的插入位置
 - 最近的加热器必须是：

 - 加热器位于左侧
 - 加热器位于右侧

 无需检查任何其他加热器，因为数组已排序。 

这减少了每间房屋的加热器查找`O(m)`到`O(log m)`。 

由于我们一次性处理所有房屋，因此整体复杂性变为：$$O(n \log m)$$再加上分拣费用。

 ## 算法演练

 ### 最优算法

 1. 排序`heaters`大批。 

排序使我们能够有效地执行二分搜索。 一旦排序，位置附近的加热器也在阵列中附近。 
2. 初始化变量`max_radius = 0`。 

该变量存储覆盖目前看到的所有房屋所需的最小加热器半径。 
3. 遍历每一个房子`houses`。 

对于每栋房子，我们想要确定到最近的加热器的距离。 
4. 使用二分查找查找当前房屋在已排序的加热器数组中的插入位置。 

这给出了在保持排序顺序的同时插入房屋的索引。 
5. 计算到左侧最近的加热器的距离。 

如果插入索引大于`0`，然后加热器在`index - 1`是左边最近的加热器。 
6. 计算到右侧最近的加热器的距离。 

如果插入索引小于加热器阵列长度，则加热器位于`index`是右侧最近的加热器。 
7. 取两个距离中较小的一个。 

由于我们只需要一台加热器来覆盖整个房屋，因此最近的加热器决定了该房屋所需的半径。 
8. 更新`max_radius`。 

最终半径必须覆盖所有房屋，因此我们采用所有房屋所需的最大半径。 
9. 返回`max_radius`。 

处理完所有房屋后，该值代表通用取暖器的最小半径。 

### 为什么它有效

 排序后，二分查找保证插入位置将加热器分为两组：

 - 插入点之前的所有加热器均位于房屋的左侧
 - 插入点之后的所有加热器均位于右侧

 因此，最近的加热器必须是插入点周围的相邻加热器之一。 任何较远的加热器都会有更大的距离，因为阵列是排序的。 

通过计算每间房屋最近的加热器距离并取最大值，我们确保每间房屋都被覆盖，同时最小化共享加热器半径。 

## Python 解决方案```python
from bisect import bisect_left
from typing import List

class Solution:
    def findRadius(self, houses: List[int], heaters: List[int]) -> int:
        heaters.sort()

        max_radius = 0

        for house in houses:
            insert_pos = bisect_left(heaters, house)

            left_distance = float("inf")
            right_distance = float("inf")

            if insert_pos > 0:
                left_distance = house - heaters[insert_pos - 1]

            if insert_pos < len(heaters):
                right_distance = heaters[insert_pos] - house

            nearest_distance = min(left_distance, right_distance)

            max_radius = max(max_radius, nearest_distance)

        return max_radius
```实施首先对加热器位置进行排序。 这是必要的，因为二分搜索只能在排序数据上正确工作。 

对于每栋房子来说，`bisect_left`找到房屋插入加热器阵列的位置，同时保持秩序。 该插入点有助于识别两侧最近的加热器。 

然后计算两个距离：

 - 距左侧最近的加热器的距离
 - 距右侧最近加热器的距离

 如果一侧不存在，则距离保持无穷大，因此不会错误地影响最小值计算。 

两个距离中较小的一个代表当前房屋所需的半径。 该算法会跟踪最大此类值，因为最终的加热器半径必须覆盖每栋房屋。 

最后，该函数返回所需的最大半径。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func findRadius(houses []int, heaters []int) int {
	sort.Ints(heaters)

	maxRadius := 0

	for _, house := range houses {
		insertPos := sort.SearchInts(heaters, house)

		leftDistance := math.MaxInt32
		rightDistance := math.MaxInt32

		if insertPos > 0 {
			leftDistance = house - heaters[insertPos-1]
		}

		if insertPos < len(heaters) {
			rightDistance = heaters[insertPos] - house
		}

		nearestDistance := min(leftDistance, rightDistance)

		if nearestDistance > maxRadius {
			maxRadius = nearestDistance
		}
	}

	return maxRadius
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于使用`sort.SearchInts`，它对排序后的切片执行二分搜索。 

Go 没有为整数提供内置的无穷大值，所以`math.MaxInt32`当一侧不存在时用作足够大的占位符。 

该解决方案还包括一个助手`min`函数，因为Go在标准库中没有提供通用的整数最小值函数。 

由于所有计算都保持在问题约束定义的整数范围内，因此整数溢出不是问题。

 ## 边缘情况

 当所有房屋都位于第一个加热器的左侧或最后一个加热器的右侧时，会出现一个重要的边缘情况。 在这些情况下，二分搜索返回`0`或者`len(heaters)`。 有错误的实现可能会尝试访问无效索引。 该解决方案在计算距离之前安全地检查数组边界。 

另一个重要的情况是当房屋恰好位于加热器上时。 所需的正确距离是`0`，但使用严格不等式的实现可能会意外返回正值。 使用`bisect_left`正确识别加热器位置并计算零距离。 

大坐标值是另一个潜在的问题来源。 由于职位可能达到`10^9`，使用较小整数类型的实现可能会在减法过程中溢出。 Python 和 Go 都使用整数表示形式安全地处理这些值。 

一个微妙的边缘情况涉及以不同距离围绕房屋的多个加热器。 该算法必须正确比较左右候选加热器并选择较小的距离。 由于加热器数组已排序，因此仅检查插入点周围的直接邻居就足够了，并保证了正确性。
