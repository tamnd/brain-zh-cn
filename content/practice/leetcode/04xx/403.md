 # LeetCode 403 - 青蛙跳

 ## 问题理解

 该问题描述了一只青蛙试图通过跳过放置在特定位置的石头来过河。 输入数组`stones`包含所有棋子的位置，按升序排列。 青蛙从第一块石头开始，该石头始终位于位置`0`。 

青蛙不会随意移动。 它的运动受到先前跳跃大小的限制。 第一次跳跃必须准确`1`单元。 之后，如果之前的跳跃长度是`k`，那么下一个跳转长度只能是以下之一：

 -`k - 1`-`k`-`k + 1`此外，青蛙只能向前移动，并且只能落在现有的石头上。 如果跳跃落入水中，则该路径无效。 

任务是确定青蛙最终能否落在阵列中的最后一块石头上。 

这些约束很重要，因为它们强烈影响哪些算法是可行的：

 -`stones.length <= 2000`- 宝石位置可以非常大，最多可达`2^31 - 1`- 石头严格增加

 强力递归搜索将探索许多重复的状态并很快变得指数级。 由于宝石数量最多可达 2000 个，因此我们需要一种更有效的方法来避免重复重新计算相同的可能性。 

一些边缘情况很重要：

 - 第二颗棋子必须在位置`1`，否则青蛙无法进行强制性的第一次跳跃。 
- 石头之间的间隙过大可能会导致无法穿越。 
- 多个跳跃长度可能会导致相同的石头，这意味着状态重用很重要。 
- 青蛙可能会以不同的跳跃长度重新访问同一块石头，这些代表不同的状态。 

关键的观察是，青蛙的状态不仅取决于其当前位置，还取决于到达该位置的最后一次跳跃的大小。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是使用递归回溯。 从每块石头开始，尝试所有有效的下一次跳跃：

 -`k - 1`-`k`-`k + 1`对于每个有效的跳转，从目标棋子递归地继续。 

这种方法是正确的，因为它探索了每种可能的跳跃序列。 如果有任何路径到达最后一块石头，答案是`true`。 

然而，这个解决方案太慢了。 相同的状态会被重复重新计算。 例如，青蛙可能通过多条不同的路径以相同的跳跃长度到达同一块石头。 如果没有记忆化，递归树会呈指数增长。 

### 关键见解

 重要的见解是该问题包含重叠的子问题。 

一个状态可以表示为：```
(current stone position, last jump length)
```如果我们已经知道某个特定状态是否可以到达终点，我们就不应该再次重新计算它。 

这自然会导致动态规划。 

一个非常有效的 DP 公式是：```
For each stone, store all jump lengths that can land on it.
```如果青蛙使用跳跃长度到达石头`k`，那么从这块石头开始，它可能会尝试跳跃：

 -`k - 1`-`k`-`k + 1`每当其中一个跳跃落在另一颗有效棋子上时，我们就会记录目标棋子的新跳跃长度。 

这将问题从指数探索转变为有界状态遍历。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(3^n) 最坏情况 | O(n) 递归堆栈 | 递归探索所有跳跃组合 |
 | 最优动态规划| O(n²) | O(n²) | 存储每块石头的可达到的跳跃长度|

 ## 算法演练

 ### 最优动态规划算法

 1. 创建一个包含所有棋子位置的集合。 

这允许恒定时间查找来确定跳跃是否落在有效的石头上。 
2. 创建一个哈希映射，其中每个石头映射到一组可以到达它的跳跃长度。 

例如：```
reachable[5] = {2,3}
```意味着青蛙可以落在石头上`5`使用长度跳跃`2`或者`3`。 
3. 初始化启动状态。 

青蛙从位置开始`0`，并且第一次跳跃必须是`1`。 所以：```
reachable[0] = {0}
```这`0`跳转只是一个代表起始状态的占位符。 
4. 按顺序遍历每个石头。 

对于每个可以到达当前石头的跳跃长度，计算下一个可能的跳跃长度：

 -`jump - 1`-`jump`-`jump + 1`5. 忽略非正跳跃。 

跳跃长度为`0`或负数无效，因为青蛙必须向前移动。 
6. 计算下一个石子位置。```
next_position = current_stone + next_jump
```7. 如果目的地存在于宝石集中，则记录跳跃长度。```
reachable[next_position].add(next_jump)
```这意味着青蛙现在可以使用该跳跃大小到达那块石头。 
8. 继续处理，直到探索完所有可达状态。 
9. 最后，检查最后一块石头是否存储了任何可到达的跳跃长度。 

如果它的集合非空，青蛙就可以过河。 

### 为什么它有效

 该算法保持了每个存储的不变性`(stone, jump)`对代表青蛙使用该跳跃长度到达那块石头的有效方法。 

从每个有效状态，算法根据问题规则生成所有合法的下一个状态。 由于每个可达状态在每个跳跃长度上都会被探索一次，因此该算法最终会发现所有可能的有效路径。 

如果最后一块石头至少有一个可到达的跳跃长度，则存在一个有效的过河跳跃序列。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def canCross(self, stones: List[int]) -> bool:
        if stones[1] != 1:
            return False

        stone_set = set(stones)

        reachable = defaultdict(set)
        reachable[0].add(0)

        for stone in stones:
            for jump in reachable[stone]:
                for next_jump in (jump - 1, jump, jump + 1):
                    if next_jump <= 0:
                        continue

                    next_stone = stone + next_jump

                    if next_stone in stone_set:
                        reachable[next_stone].add(next_jump)

        return len(reachable[stones[-1]]) > 0
```实施从一个重要的优化开始：```python
if stones[1] != 1:
    return False
```由于第一次跳跃必须恰好是`1`，第二颗棋子必须位于位置`1`。 如果不是，则立即给出答案`False`。 

这`stone_set`提供持续时间的成员资格检查。 如果没有它，检查目标棋子是否存在将需要线性搜索。 

这`reachable`字典将每个石头位置映射到可以到达它的跳跃长度集。 使用集合可以防止重复存储重复的状态。 

外循环按升序处理石子。 对于每个可到达的跳跃大小，算法生成三个允许的下一个跳跃。 无效的非正跳转将被跳过。 

只要存在有效的目标棋子，就会记录该棋子相应的跳跃长度。 

最后，算法检查最后一块石头是否至少有一个可到达的跳跃长度。 

## 解决方案```go
func canCross(stones []int) bool {
	if stones[1] != 1 {
		return false
	}

	stoneSet := make(map[int]bool)
	for _, stone := range stones {
		stoneSet[stone] = true
	}

	reachable := make(map[int]map[int]bool)

	for _, stone := range stones {
		reachable[stone] = make(map[int]bool)
	}

	reachable[0][0] = true

	for _, stone := range stones {
		for jump := range reachable[stone] {
			for nextJump := jump - 1; nextJump <= jump+1; nextJump++ {
				if nextJump <= 0 {
					continue
				}

				nextStone := stone + nextJump

				if stoneSet[nextStone] {
					reachable[nextStone][nextJump] = true
				}
			}
		}
	}

	return len(reachable[stones[len(stones)-1]]) > 0
}
```Go 实现遵循与 Python 版本相同的逻辑，但存在一些特定于语言的差异。 

Go 没有内置的集合类型，因此带有布尔值的映射用于模拟集合：```go
map[int]bool
```嵌套结构：```go
map[int]map[int]bool
```代表：```go
stone -> set of jump lengths
```与Python不同`defaultdict`，Go 要求在插入值之前显式初始化嵌套映射。 

整数溢出在这里不是一个问题，因为这些约束很适合 Go 的范围`int`在 LeetCode 环境中输入。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 每块石头最多可存储 O(n) 个可达跳跃长度 |
 | 空间| O(n²) | DP 结构可能包含 O(n²) 个状态对 |

 在最坏的情况下，每块石头都可以通过许多不同的跳跃长度到达。 由于有`n`石头，每个可以存储`n`跳跃值，状态总数的界限为`O(n²)`。 

每个状态处理一次，每个处理步骤只考虑三个转换，因此总运行时间保持不变`O(n²)`。

 ## 边缘情况

 ### 位置 1 缺少石头

 第一次跳跃必须准确`1`。 如果第二颗棋子不在位置`1`，青蛙立即失败。 

例子：```
[0,2]
```幼稚的实现可能仍会开始递归探索，但这是不必要的工作。 该实现通过提前返回有效地处理了这个问题：```
if stones[1] != 1:
    return False
```### 石头之间的大间隙

 大的差距可能变得不可能跨越，因为跳跃的大小只能逐渐改变。 

例子：```
[0,1,2,3,4,8]
```即使青蛙到达石头`4`，它不能突然跳跃`4`单位，因为它之前的跳跃太小。 

DP 方法自然会处理这个问题，因为无法访问的状态永远不会添加到表中。 

### 到达同一块石头的多种方法

 使用不同的跳跃长度可以到达石头，这些代表了未来不同的可能性。 

例子：```
[0,1,3,5,6,8]
```石头`6`可以使用不同的跳跃大小来达到。 仅存储石头是否可到达的有缺陷的实现会丢失关键信息。 

该解决方案正确存储每块石头的所有可到达的跳跃长度：```
reachable[stone] = set(...)
```这保留了所有未来运动的可能性并保证了正确性。
