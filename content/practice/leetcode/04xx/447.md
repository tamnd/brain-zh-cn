[LeetCode 第 447 题](https://leetcode.com/problems/number-of-boomerangs/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学

 ## 解决方案

 ## 问题理解

 该问题要求我们计算一组不同的 2D 点中有效回旋镖的数量。 

回旋镖被定义为一个元组`(i, j, k)`其中点之间的距离`i`并点`j`等于点之间的距离`i`并点`k`。 重要的细节是顺序很重要。 这意味着`(i, j, k)`和`(i, k, j)`被认为是两个不同的回旋镖，如果`j != k`。 

输入是点列表，其中每个点表示为`[x, y]`。 每个点都是唯一的，因此不存在重复的坐标。 

输出是一个整数，表示可以形成的回旋镖总数。 

限制相对较小：

 - 最多可以有 500 点。 
- 坐标范围从`-10^4`到`10^4`。 

因为`n`只有500，一个`O(n^2)`解决方案是可以接受的，但是`O(n^3)`解决方案开始接近实际上限并且不太理想。 这强烈表明我们应该寻找一种方法来避免显式检查每个三元组。 

一个重要的观察是，我们实际上并不需要欧几里德距离本身。 由于我们只关心两个距离是否相等，因此我们可以比较距离的平方。 这避免了浮点运算和精度问题。 

一些边缘情况很重要：

 - 单个点不能形成任何回旋镖。 
- 两个点也不能形成回旋镖，因为我们需要元组中的三个不同位置。 
- 距中心点相同距离处可能存在多个点，从而产生许多排列。 
- 由于顺序很重要，如果有`k`距中心距离相同的点，贡献的回旋镖数量为`k * (k - 1)`。 

## 方法

 ### 蛮力方法

 最直接的方法是检查每个可能的有序三元组`(i, j, k)`并检查是否：

 -`i != j`-`i != k`-`j != k`- 距离（`i`,`j`) == 距离(`i`,`k`）

有`n`三个位置中每一个的选择，所以这需要`O(n^3)`迭代。 

这是有效的，因为它显式地检查每个可能的回旋镖定义。 然而，它的效率很低，因为许多距离计算会重复多次。 

例如，当检查以特定点为中心的所有三元组时`i`，我们反复重新计算距离`i`到其他点。 

### 最佳解决方案的关键见解

 关键的观察是对于固定的中心点`i`，我们只关心距每个距离有多少个其他点`i`。 

假设对于一个特定的中心点：

 - 3分距离5分
 - 2分距离为10

 对于 3 个等距点的组：

 - 我们可以挑选订购的对`(j, k)`在`3 * 2 = 6`方式。 

对于 2 个等距点的组：

 - 我们可以挑选订购的对`2 * 1 = 2`方式。 

因此，我们可以：

 1. 固定中心点`i`2. 计算距离`i`到其他所有点
 3. 计算每个距离出现的次数
 4. 对于每个频率`count`， 添加`count * (count - 1)`哈希图非常适合有效地对相等距离进行分组。 

## 方法比较

 ## 算法演练

 1. 初始化变量`total_boomerangs`存储最终答案。 
2.以每个点为中心点进行迭代`i`。 

对于每个中心点，我们想知道距它的每个距离处存在多少个其他点。 
3. 创建一个名为的哈希图`distance_count`。 

关键是距中心点的平方距离。 

该值是该距离处的点数。 
4. 遍历所有其他点`j`。 

计算平方距离：$(x_i - x_j)^2 + (y_i - y_j)^2$我们使用平方距离，因为相等的实际距离总是产生相等的平方距离，这避免了不必要的平方根计算。 
5. 增加散列图中该距离的频率。 

处理完所有点后，哈希图告诉我们有多少个点共享距中心点的每个距离。 
6. 迭代哈希图中的所有频率。 

如果出现距离`count`次，那么：$count \times (count - 1)$可以形成有序的回旋镖。 

这是有效的，因为：

 - 我们选择一个点作为`j`- 然后另一个明显的点是`k`- 订单事宜
 7. 将所有这些贡献添加到总答案中。 
8. 处理完所有中心点后，返回最终计数。 

### 为什么它有效

 对于每个中心点`i`，所有有效的回旋镖都是通过选择两个距离相同的不同点来形成的`i`。 哈希图按距离对点进行分组，确保每个有效对都被精确计数一次。 由于顺序很重要，因此每组的大小`k`贡献`k * (k - 1)`有序对。 将所有中心的这些贡献相加即可得出正确的回旋镖总数。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def numberOfBoomerangs(self, points: List[List[int]]) -> int:
        total_boomerangs = 0

        for i in range(len(points)):
            distance_count = defaultdict(int)

            x1, y1 = points[i]

            for j in range(len(points)):
                if i == j:
                    continue

                x2, y2 = points[j]

                dx = x1 - x2
                dy = y1 - y2

                squared_distance = dx * dx + dy * dy

                distance_count[squared_distance] += 1

            for count in distance_count.values():
                total_boomerangs += count * (count - 1)

        return total_boomerangs
```实现直接遵循算法。 

外循环选择每个点作为潜在回旋镖的中心点。 对于每个中心点，我们创建一个新的哈希图，名为`distance_count`。 

在内部循环中，我们计算从中心点到每个其他点的平方距离。 使用平方距离代替真正的欧氏距离，因为我们只需要相等比较。 

每个计算出的距离都存储在哈希图中。 地图会跟踪每个距离出现的点数量。 

处理给定中心的所有其他点后，我们迭代地图中的频率值。 如果`count`点的距离相同，那么`count * (count - 1)`可以形成有序对。 

最后，我们将所有贡献累积到`total_boomerangs`并返回结果。 

## 解决方案```go
func numberOfBoomerangs(points [][]int) int {
    totalBoomerangs := 0

    for i := 0; i < len(points); i++ {
        distanceCount := make(map[int]int)

        x1, y1 := points[i][0], points[i][1]

        for j := 0; j < len(points); j++ {
            if i == j {
                continue
            }

            x2, y2 := points[j][0], points[j][1]

            dx := x1 - x2
            dy := y1 - y2

            squaredDistance := dx*dx + dy*dy

            distanceCount[squaredDistance]++
        }

        for _, count := range distanceCount {
            totalBoomerangs += count * (count - 1)
        }
    }

    return totalBoomerangs
}
```Go 实现密切反映了 Python 逻辑。 

而不是Python的`defaultdict`, Go 使用`map[int]int`。 缺少的键会自动返回整数的零值，因此自然递增。 

整数溢出在这里不是一个问题，因为坐标差异的范围是`2 * 10^4`，并且将它们平方仍然适合 Go 的`int`类型。 

Go 切片直接用于点存储，嵌套循环的行为与 Python 版本相同。

    def numberOfBoomerangs(self, points: List[List[int]]) -> int:
        from collections import defaultdict

            dist_count = defaultdict(int)

            for j in range(len(points)):

 ## 边缘情况

 单个点是可能的最小输入。 由于回旋镖需要元组中的三个位置，因此不存在有效的配置。 有缺陷的实现可能会意外地计算自对或无法正确处理空距离图。 此实现避免了该问题，因为内部循环会跳过`i == j`，并且距离组的大小永远不会大于 1。 

两点输入是另一个重要的边界情况。 即使存在一种距离关系，仍然没有足够的明显点来形成`(i, j, k)`。 公式`count * (count - 1)`当`count == 1`，因此实现可以正确处理此问题，无需特殊情况逻辑。 

当许多点到中心点的距离相同时，会出现更微妙的边缘情况。 例如，距中心距离相等的四个周围点会产生许多有序组合。 一个常见的错误是忘记顺序很重要并使用组合而不是排列。 这个实现正确地使用了`count * (count - 1)`而不是`count * (count - 1) / 2`，确保正确计算有序元组。 

如果使用浮点距离计算，大坐标值在某些实现中也可能会导致问题。 通过完全使用整数计算平方距离，该解决方案可以避免精度问题，并且即使在最大坐标限制下也能保持完全准确。
