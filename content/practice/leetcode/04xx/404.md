[LeetCode 404 题](https://leetcode.com/problems/sum-of-left-leaves/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题给出了二叉树的根节点，并要求我们计算树中所有左叶的总和。 

二叉树节点最多可以有两个子节点，一个左子节点和一个右子节点。 叶节点是根本没有子节点的节点，这意味着它的子节点`left`和`right`指针是`None`在 Python 中或`nil`在围棋中。 

重要的细节是，并非每个留下的孩子都算作答案。 仅当这两个条件都为真时，节点才会对总和做出贡献：

 1. 该节点是其父节点的左子节点。 
2. 该节点是叶节点。 

例如，考虑这棵树：```
       3
      / \
     9  20
       /  \
      15   7
```节点`9`是左孩子，也是叶子，所以它对总和有贡献。 节点`15`也是左孩子和叶子，所以它也有贡献。 节点`20`是右孩子而不是叶子，所以它不算数。 节点`7`是右叶，所以也不算数。 

预期输出是所有此类左叶的总和。 

约束告诉我们节点的数量在`1`和`1000`。 这是一棵相对较小的树，因此`O(n)`遍历就足够了。 由于每个节点可能需要至少检查一次才能确定它是否是左叶，因此线性时间实际上是最佳的。 

一些边缘情况很重要：

 - 一棵只有一个节点的树没有父子关系，因此不可能有任何左叶。 
- 本身有孩子的左孩子不是叶子，不应该被计算在内。 
- 右叶绝对不能包含在总和中。 
- 树可能包含负值，因此最终的总和也可能为负数。 

## 方法

 强力方法将检查每个节点，并通过从根搜索或通过维护额外的结构检查来重复确定该节点是否是左叶。 例如，对于每个节点，我们可以再次搜索树以识别其父节点并确定它是否是左子节点。 这是正确的，因为每个节点最终都会被检查，但它引入了不必要的重复遍历工作。 

更好的解决方案来自于观察，当我们递归或迭代时，树遍历自然地为我们提供了父子关系。 当访问一个节点时，我们已经可以直接访问它的左子节点和右子节点。 这意味着我们可以立即确定左孩子是否是叶子，而无需任何额外的搜索。 

关键的见解是，当我们站在一个节点上时，我们只需要检查它的左子节点：

 - 如果左孩子存在并且没有孩子，则它是左叶子，应添加到答案中。 
- 否则，继续深入树中。 

这导致了干净的深度优先遍历，其中每个节点仅被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 反复搜索关系或重新扫描树的部分 |
 | 最佳 | O(n) | O(h) | 单个 DFS 遍历，在遍历期间检查左叶 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 ### 深度优先搜索策略

 1. 从根节点开始深度优先遍历。 
2. 在每个节点，首先检查该节点是否有左子节点。 如果是，则确定该左子节点是否为叶节点。 叶节点通过具有两者来标识`left`和`right`等于`None`或者`nil`。 
3. 如果左子节点是叶子，则将其值添加到运行总计中。 我们立即这样做，因为我们已经确认它满足问题所需的两个条件。 
4. 如果左子树存在但不是叶子，则继续递归遍历该子树。 里面可能还残留着叶子。 
5.同样独立遍历右子树。 即使右子节点本身不被计算在内，它们的子树也可能包含更下方的左叶节点。 
6. 继续此过程，直到访问完所有节点。 
7. 遍历完成后返回累加和。 

### 为什么它有效

 该算法之所以有效，是因为树中的每个节点都被访问一次，并且每个左子节点在处理其父节点时都会被精确检查。 仅当节点满足左叶的精确定义时，才会将其添加到总和中：它是左子节点，并且没有自己的子节点。 由于遍历探索了整棵树，因此不会遗漏有效的左叶，也不会错误地包含无效节点。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def sumOfLeftLeaves(self, root: Optional[TreeNode]) -> int:
        def dfs(node: Optional[TreeNode]) -> int:
            if not node:
                return 0

            total = 0

            if node.left:
                is_left_leaf = (
                    node.left.left is None and
                    node.left.right is None
                )

                if is_left_leaf:
                    total += node.left.val

            total += dfs(node.left)
            total += dfs(node.right)

            return total

        return dfs(root)
```该实现使用名为的递归辅助函数`dfs`执行树的深度优先遍历。 

第一个条件处理基本情况。 如果当前节点是`None`，没有什么可处理的，所以函数返回`0`。 

对于每个有效节点，一个局部变量`total`存储当前子树贡献的总和。 

然后代码检查当前节点是否有左子节点。 如果是，则实现通过验证其两个子级都是叶子来确定该子级是否是叶子`None`。 

如果左子节点是叶子，则将其值添加到`total`。 

处理完直接左子关系后，算法递归地探索左子树和右子树。 这确保了树中的每个节点最终都会被检查。 

最后，辅助函数返回当前子树的累计总数，外部函数返回从根开始的结果。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func sumOfLeftLeaves(root *TreeNode) int {
    var dfs func(node *TreeNode) int

    dfs = func(node *TreeNode) int {
        if node == nil {
            return 0
        }

        total := 0

        if node.Left != nil {
            isLeftLeaf := node.Left.Left == nil &&
                node.Left.Right == nil

            if isLeftLeaf {
                total += node.Left.Val
            }
        }

        total += dfs(node.Left)
        total += dfs(node.Right)

        return total
    }

    return dfs(root)
}
```Go 实现遵循与 Python 解决方案相同的递归策略。 主要区别是 Go 的显式指针处理`nil`检查而不是Python的`None`。 

Go 使用函数变量`dfs`定义递归辅助闭包。 整数溢出在这里不是一个问题，因为约束很小，并且最大可能的总和很容易符合 Go 的标准`int`类型。

 ## 边缘情况

 单节点树是一种重要的边缘情况，因为根节点没有父节点。 由于左叶必须是另一个节点的左子节点，因此根永远无法符合条件。 如果粗心的实现只检查节点是否是叶子，则可能会错误地计算根。 此解决方案避免了该问题，因为它仅通过节点的父关系来评估节点。 

当节点是左子节点而不是叶子节点时，会发生另一种棘手的情况。 例如，在类似的链中`1 -> 2 -> 3`, 节点`2`是一个左孩子，但仍然有自己的孩子。 唯一节点`3`应该算。 该实现通过在将值添加到总和之前显式检查两个子指针是否为空来正确处理此问题。 

仅包含右子节点的树也可能导致逻辑错误。 由于这样的树中没有节点是左子节点，因此正确答案始终为零。 遍历仍然会探索整个树，但仅当满足左叶条件时才会添加值。 

负节点值是另一个微妙的情况。 由于该问题允许值介于`-1000`和`1000`，总和可能变为负数。 该实现不会对正性做出假设，只是正常地累积值，因此负左叶可以正确处理。
