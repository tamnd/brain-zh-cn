[LeetCode 第 436 题](https://leetcode.com/problems/find-right-interval/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们为列表中的每个间隔找到在当前间隔结束时或之后开始并且在开始时间方面最接近的此类间隔的“正确间隔”。 形式上，给定一个区间数组`intervals[i] = [starti, endi]`其中每个`starti`是唯一的，一个区间的正确区间`i`是一个区间`j`这样`startj >= endi`和`startj`被最小化。 如果不存在这样的区间，我们返回`-1`对于该间隔。 

输入是间隔列表，其中每个间隔由两个整数组成`[start, end]`。 预期输出是与正确间隔的原始位置相对应的索引数组。 例如，如果索引处的间隔的正确间隔`i`位于索引处`j`在原始数组中，输出数组位于位置`i`应包含`j`。 

约束给出了有关输入的规模和性质的重要提示。 间隔的数量最多可达 20,000 个，并且起点是唯一的，这一点很重要，因为它允许我们将它们用作映射或排序的键。 大的输入大小表明检查每对间隔的简单方法会太慢。 

可能会导致幼稚实现失败的边缘情况包括没有正确间隔的间隔（应该返回`-1`)、已按开始排序的间隔、反向排序的间隔以及具有相同结束时间但开始时间不同的间隔。 

## 方法

 暴力方法很简单。 对于每个间隔，我们可以迭代所有其他间隔，并查找具有大于或等于当前间隔结束值的最小起始值的间隔。 这保证了正确性，因为我们正在明确检查所有可能性。 然而，它的时间复杂度是 O(n²)，对于 n 达到 20,000 来说太慢了。 

最佳解决方案利用排序和二分搜索。 关键的见解是，我们可以按开始时间对间隔进行排序，然后对于每个间隔执行二分搜索以快速找到大于或等于其结束时间的最小开始。 这显着降低了时间复杂度，因为每个区间的二分查找都是 O(log n)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个间隔的所有间隔对 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 按开始对间隔进行排序，并对每个间隔使用二分搜索 |

 ## 算法演练

 1. 存储每个区间的原始索引，因为排序会改变它们的顺序。 创建元组列表`(start, index)`对于所有间隔。 
2. 根据起始值对该列表进行排序。 这使得二分搜索能够有效地工作。 
3. 初始化一个结果数组，填充为`-1`因为有些音程可能没有正确的音程。 
4. 迭代原始列表中的每个区间。 对于每个间隔，对已排序的开始列表执行二分搜索，以查找大于或等于间隔结束的最小开始。 
5. 如果二分查找找到有效索引，则用找到的区间的原始索引更新原始区间索引处的结果数组。 
6. 返回结果数组。 

**为什么有效：** 排序可确保起始点按递增顺序排列，这允许二分搜索有效地找到大于或等于目标的最小起始点。 通过跟踪原始索引，我们确保输出对应于原始输入顺序。 该算法保证对于每个区间，如果存在正确的区间，就会找到它，否则`-1`被返回。 

## Python 解决方案```python
from typing import List
import bisect

class Solution:
    def findRightInterval(self, intervals: List[List[int]]) -> List[int]:
        n = len(intervals)
        start_with_index = [(intervals[i][0], i) for i in range(n)]
        start_with_index.sort()  # Sort by start times
        
        result = [-1] * n
        
        for i, (start, end) in enumerate(intervals):
            idx = bisect.bisect_left(start_with_index, (end, 0))
            if idx < n:
                result[i] = start_with_index[idx][1]
        
        return result
```**实现演练：** 我们首先将每个间隔映射到其起始位置和原始索引，并按起始位置排序。 对于每个间隔，`bisect_left`查找间隔末尾可以放入排序列表的插入点。 如果此索引在范围内，则它给出 >= 结束的最小开始。 使用原始索引更新结果数组以保持与输入的对齐。 

## 解决方案```go
import "sort"

func findRightInterval(intervals [][]int) []int {
    n := len(intervals)
    startWithIndex := make([][2]int, n)
    for i := 0; i < n; i++ {
        startWithIndex[i] = [2]int{intervals[i][0], i}
    }
    sort.Slice(startWithIndex, func(i, j int) bool {
        return startWithIndex[i][0] < startWithIndex[j][0]
    })
    
    result := make([]int, n)
    for i := range result {
        result[i] = -1
    }
    
    for i := 0; i < n; i++ {
        end := intervals[i][1]
        l, r := 0, n
        for l < r {
            m := l + (r-l)/2
            if startWithIndex[m][0] >= end {
                r = m
            } else {
                l = m + 1
            }
        }
        if l < n {
            result[i] = startWithIndex[l][1]
        }
    }
    
    return result
}
```**Go 特定说明：** Go 没有内置的对自定义键的二分搜索，因此我们手动实现。 我们使用`[2]int`元组为`(start, index)`。 切片初始化和边界检查确保安全。 

## 工作示例

 **示例2：**`intervals = [[3,4],[2,3],[1,2]]`创建后`start_with_index`:`[(3,0),(2,1),(1,2)]`排序后：`[(1,2),(2,1),(3,0)]`迭代每个区间：

 | 间隔 | 结束 | 二分查找索引 | 右区间索引 | 迄今为止的结果 |
 | --- | --- | --- | --- | --- |
 | [3,4]| 4 | 3 | -1 | [-1]|
 | [2,3]| 3 | 2 | 0 | [-1,0]|
 | [1,2]| 2 | 1 | 1 | [-1,0,1]|

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |

 ## 边缘情况

 一种关键的边缘情况是只有一个间隔时。 该函数必须返回`-1`因为没有其他间隔需要考虑。 另一种边缘情况是间隔的结束与数组中的任何开始都不匹配。 这是通过将结果数组初始化为来处理的`-1`并且仅在找到有效的正确间隔时才更新它。 第三种边缘情况涉及范围非常大或负值的间隔。 只要整数表示有效，排序和二分搜索对于这些值来说是稳健的。 所有这些边缘情况都由最优算法正确处理。
