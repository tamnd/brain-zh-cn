[LeetCode 第 440 题](https://leetcode.com/problems/k-th-smallest-in-lexicographyal-order/)

 **难度：** 🔴难
 **主题：** 特里树

 ## 解决方案

 ## 问题理解

 问题要求我们找到`k`- 所有整数中按字典顺序排列的最小数字`1`到`n`。 

字典顺序是指字典顺序，而不是数字顺序。 例如，如果`n = 13`，数字按以下顺序出现：```
1, 10, 11, 12, 13, 2, 3, 4, 5, 6, 7, 8, 9
```发生这种情况是因为数字是作为字符串进行比较的：```
"1" < "10" < "11" < ... < "2"
```输入包括：

 -`n`，范围的上限`[1, n]`-`k`，我们要检索的字典顺序位置

 输出是出现在`k`- 当所有整数来自时的第一个位置`1`到`n`按字典顺序排序。 

约束条件极其重要：```
1 <= k <= n <= 10^9
```自从`n`可能大到十亿，生成所有数字并对它们进行排序是完全不切实际的。 即使存储所有数字也需要太多内存，并且排序将花费太长时间。 

该问题被标记为 Trie 主题，因为数字的字典顺序自然形成前缀树。 例如：```
1
├── 10
├── 11
├── 12
└── 13
2
3
...
```关键的挑战是确定如何在不显式构造此隐式字典树的情况下有效地导航它。 

一些边缘情况很重要：

 - 当`n = 1`，答案一定是`1`- 什么时候`k = n`，我们可能需要非常深入地遍历字典顺序
 - 接近 10 次方的数字会产生不均匀的 trie 分支
 - 前缀可能部分超过`n`，因此必须仔细修剪子树大小
 - 大值`n`需要一种完全避免枚举的算法

 ## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个数字`1`到`n`，将它们转换为字符串，按字典顺序对它们进行排序，然后返回`k`-th 元素。 

例如：```
numbers = [str(i) for i in range(1, n + 1)]
numbers.sort()
return int(numbers[k - 1])
```这是可行的，因为字符串排序自然会产生字典顺序。 

然而，对于给定的约束，这种方法太慢并且占用大量内存。 如果`n = 10^9`，我们无法生成十亿个数字，更不用说对它们进行排序了。 

时间复杂度主要由排序决定：```
O(n log n)
```并且空间复杂度也是巨大的：```
O(n)
```这立即告诉我们我们需要一个根本不同的策略。 

### 最优方法，字典树遍历

 关键的观察是字典排序与 trie 的前序遍历完全对应。 

考虑来自的数字`1`到`13`:```
1
├── 10
├── 11
├── 12
└── 13
2
3
4
5
6
7
8
9
```我们可以将其视为隐式结构，而不是显式构建此特里树。 

关键的见解是，从任何前缀，我们都可以有效地计算该前缀下存在多少个有效数字。 

例如，带有前缀`1`和`n = 13`:```
1, 10, 11, 12, 13
```该子树中有 5 个数字。 

如果我们知道子树的大小，我们可以决定：

 - 跳过整个子树如果`k`大于其尺寸
 - 如果目标位于子树内部，则下降得更深

 这将问题转化为带有子树计数的 trie 导航。 

该算法的行为类似于遍历前缀树，同时尽可能跳过整个分支。

 ## 算法演练

 ### 步骤 1：从前缀开始`1`字典顺序总是以`1`。 

我们初始化：```
current = 1
k = k - 1
```我们减一是因为我们已经站在第一个字典序数上。 

### 步骤 2：计算当前前缀下的数字

 我们计算前缀下存在多少个有效整数。 

例如，如果：```
prefix = 1
n = 13
```那么子树包含：```
1, 10, 11, 12, 13
```这给出了大小`5`。 

为了有效计数，我们反复扩大范围：```
[1,2)
[10,20)
[100,200)
...
```在每个级别我们添加：```
min(n + 1, next_prefix) - current_prefix
```This counts how many numbers fall within the range.

 例如：```
n = 13
prefix = 1

Level 1:
[1,2) contributes 1

Level 2:
[10,20) contributes 4

Total = 5
```### 第 3 步：决定是跳过还是下降

 一旦我们知道子树的大小：

 - 如果`steps <= k`，目标不在该子树内
 - 我们跳过整个子树
 - 移至下一个同级前缀

 示例：```
current = 1
steps = 5
k = 10
```由于子树仅包含 5 个数字，因此我们跳过它：```
current = 2
k -= 5
```### 步骤 4：下降到子树

 如果子树包含目标：```
steps > k
```然后我们再深入一层：```
current *= 10
k -= 1
```乘以 10 移动到按字典顺序排列的第一个子项。 

例子：```
1 -> 10
```### 步骤 5：重复直到`k == 0`我们继续在字典树中导航，直到消耗完所有剩余的位置。 

那一刻，`current`就是答案。 

### 为什么它有效

 该算法保持不变式`current`始终指向隐式 trie 中当前的字典位置。 子树计数功能精确确定前缀下存在多少个词典数字。 因为字典顺序对应于 trie 的前序遍历，所以跳过子树相当于跳过该前缀范围内的所有数字。 下降更深可以保留遍历顺序。 因此，每一个动作都完全符合字典顺序的枚举，保证了正确的`k`已达到第 - 个数字。 

## Python 解决方案```python
class Solution:
    def findKthNumber(self, n: int, k: int) -> int:
        def count_steps(curr: int, nxt: int) -> int:
            steps = 0

            while curr <= n:
                steps += min(n + 1, nxt) - curr
                curr *= 10
                nxt *= 10

            return steps

        current = 1
        k -= 1

        while k > 0:
            steps = count_steps(current, current + 1)

            if steps <= k:
                current += 1
                k -= steps
            else:
                current *= 10
                k -= 1

        return current
```其实现紧密遵循 trie 遍历策略。 

辅助函数`count_steps`计算按字典顺序位于两个前缀之间有多少个数字。 它通过乘以 10 来重复扩展前缀范围，从而有效地向下移动 trie 级别。 

例如：```python
curr = 1
nxt = 2
```扩展为：```python
[1,2)
[10,20)
[100,200)
...
```在每个级别，我们都会计算其中剩余的有效数字`[1, n]`。 

主循环维护当前的字典位置。 

如果子树大小小于或等于剩余子树大小`k`，我们通过递增完全跳过子树`current`。 

否则，我们通过乘法深入到 trie 中`current`到 10 点。 

一旦所有位置都被消耗完，循环就会结束。 

## 解决方案```go
func findKthNumber(n int, k int) int {
    countSteps := func(curr int, next int) int {
        steps := 0

        for curr <= n {
            upper := next
            if n+1 < upper {
                upper = n + 1
            }

            steps += upper - curr

            curr *= 10
            next *= 10
        }

        return steps
    }

    current := 1
    k--

    for k > 0 {
        steps := countSteps(current, current+1)

        if steps <= k {
            current++
            k -= steps
        } else {
            current *= 10
            k--
        }
    }

    return current
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是 Go 不提供内置的`min`函数用于整数，因此我们使用条件逻辑手动计算较小的值。 

该算法仅使用整数运算和恒定的额外空间，即使对于最大的约束也能保持高效。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n = 1`。 在这种情况下，特里树仅包含一个节点。 许多实现都会失败，因为它们假设至少需要一个遍历步骤。 这个实现自然地处理了这种情况，因为`k`初始化后立即变为零，因此循环永远不会执行。 

另一个棘手的情况发生在十的幂附近，例如`n = 1000`。 前缀如`1`包含非常大的子树，而靠近末尾的前缀可能包含很少的元素。 当范围超出时，经常会发生不正确的子树计数`n`。 此实现使用以下方式安全地剪辑每个级别：```
min(n + 1, nxt)
```这可以防止过度计数。 

当答案恰好位于子树边界时，就会出现第三种重要的边缘情况。 例如，如果 prefix 下的子树`1`恰好包含 12 个元素并且`k = 12`，算法必须跳过整个子树而不是下降到它。 条件：```
if steps <= k:
```通过确保正确解释子树边界来正确处理这种情况。 

另一个微妙的问题涉及大值`n`靠近`10^9`。 递归特里结构或显式枚举将超出内存或时间限制。 该实现通过数学计算子树大小并仅存储恒定的附加状态来完全避免这两个问题。
