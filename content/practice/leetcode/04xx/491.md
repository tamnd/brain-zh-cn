 # LeetCode 491 - 非递减子序列

 ## 问题理解

 问题给了我们一个整数数组`nums`并要求我们返回每个非递减且长度至少为 2 的不同子序列。 

通过从数组中删除零个或多个元素而不改变剩余元素的相对顺序来形成子序列。 与子数组不同，子序列不需要是连续的。 

非递减子序列意味着下一个元素都大于或等于前一个元素。 例如：

-`[4,6,7]`是有效的，因为`4 <= 6 <= 7`-`[4,7,7]`有效，因为允许相等的值
 -`[6,4]`无效，因为序列减少

 重要的细节是输出必须仅包含不同的子序列。 由于输入数组可能包含重复值，因此不同的索引选择可以生成相同的子序列。 我们必须避免返回重复项。 

限制相对较小：

 -`1 <= nums.length <= 15`-`-100 <= nums[i] <= 100`由于数组长度最多为15，因此子序列总数最多为`2^15 = 32768`，这是可以管理的。 这强烈表明详尽的搜索或回溯解决方案是合适的。 

一些边缘情况很重要：

 - 值全部递减的数组，例如`[5,4,3,2]`，产生很少的有效子序列。 
- 具有重复项的数组，例如`[4,6,7,7]`，如果处理不当，可能会生成重复的子序列。 
- 具有所有相等值的数组，例如`[1,1,1]`，需要仔细消除重复。 
- 长度为 1 的数组永远无法生成有效的子序列，因为所需的最小长度为 2。 

## 方法

 ### 蛮力方法

 暴力解决方案生成数组的每个可能的子序列，然后过滤有效的子序列。 

由于每个元素都可以包含或排除，因此有`2^n`可能的子序列。 对于每个生成的子序列，我们检查：

 1. 其长度是否至少为2
 2、是否非减
 3.是否已经添加到答案中

 哈希集可用于通过将子序列存储为元组来消除重复项。 

这种方法是正确的，因为它检查了每个可能的子序列。 然而，它的效率很低，因为它会探索许多无效的子序列，并在构造后重复检查单调性。 

### 最优回溯方法

 更好的解决方案使用回溯增量构建子序列。 

关键的观察是我们不需要生成无效的子序列。 在构造子序列时，我们仅在保持非递减性质的情况下附加一个数字。 

另一个重要的见解是重复处理。 在每个递归级别，我们使用本地集来跟踪哪些值已被使用。 这可以防止从相同深度的重复值生成重复的子序列。 

例如，在`[4,6,7,7]`，之后探索候选人时`[4,6]`，选择第一个`7`和第二个`7`分开会产生重复的子序列。 本地集可以防止这种重复。 

这种修剪显着减少了冗余工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(2^n * n) | O(2^n * n) | 生成所有子序列，然后验证每个 |
 | 最佳 | O(2^n) | O(2^n) | O(2^n * n) | O(2^n * n) | 通过剪枝和重复消除进行回溯 |

 ## 算法演练

 1. 初始化一个空结果列表，用于存储所有有效子序列。 
2. 创建一个带有两个参数的递归回溯函数：

 -`start_index`，我们可以探索的下一个位置
 -`current_sequence`，当前正在构建的子序列
 3. 在每次递归调用开始时，检查是否`current_sequence`长度至少为 2。如果是，则将副本附加到结果中。 
4. 创建一个名为的本地哈希集`used`。 该集合跟踪在当前递归深度已经选择了哪些值。 
5. 从以下位置开始迭代数组`start_index`。 
6. 对于每个候选人编号：

 - 如果已经在此递归级别使用过，则跳过它。 这可以防止重复的子序列。 
- 如果添加它会违反非递减性质，请跳过它。 
7. 如果号码有效：

 - 添加到`used`- 将其附加到`current_sequence`- 使用下一个索引递归
 - 之后删除号码以回溯
 8. 继续，直到探索完所有递归路径。 

### 为什么它有效

 该算法探索保留数组顺序的每个可能的子序列。 在构造过程中强制执行非递减条件，因此每个生成的子序列都是有效的。 当地的`used`set 保证相同递归深度的重复值仅被考虑一次，从而防止重复的子序列进入结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def findSubsequences(self, nums: List[int]) -> List[List[int]]:
        result = []

        def backtrack(start_index: int, current_sequence: List[int]) -> None:
            if len(current_sequence) >= 2:
                result.append(current_sequence[:])

            used = set()

            for i in range(start_index, len(nums)):
                current_num = nums[i]

                if current_num in used:
                    continue

                if current_sequence and current_num < current_sequence[-1]:
                    continue

                used.add(current_num)

                current_sequence.append(current_num)
                backtrack(i + 1, current_sequence)
                current_sequence.pop()

        backtrack(0, [])

        return result
```实现直接遵循递归回溯策略。 

这`result`list 存储所有有效的子序列。 

这`backtrack`函数递归地构建子序列。 每当当前子序列至少有两个元素时，它就会被复制到结果列表中。 副本是必要的，因为列表是可变的，并且稍后在回溯期间会被修改。 

这`used`set 在每个递归级别重新创建。 这非常重要，因为重复消除应该只适用于相同的递归深度。 使用全局集会错误地删除有效的子序列。 

条件：```python
if current_sequence and current_num < current_sequence[-1]:
```确保子序列保持非递减。 

添加数字后，继续递归`i + 1`，保证索引保持递增顺序并且保留子序列顺序。 

最后，`pop()`恢复之前的状态，以便可以探索其他递归分支。 

## 解决方案```go
package main

func findSubsequences(nums []int) [][]int {
	var result [][]int
	var currentSequence []int

	var backtrack func(int)

	backtrack = func(startIndex int) {
		if len(currentSequence) >= 2 {
			sequenceCopy := make([]int, len(currentSequence))
			copy(sequenceCopy, currentSequence)
			result = append(result, sequenceCopy)
		}

		used := make(map[int]bool)

		for i := startIndex; i < len(nums); i++ {
			currentNum := nums[i]

			if used[currentNum] {
				continue
			}

			if len(currentSequence) > 0 &&
				currentNum < currentSequence[len(currentSequence)-1] {
				continue
			}

			used[currentNum] = true

			currentSequence = append(currentSequence, currentNum)
			backtrack(i + 1)
			currentSequence = currentSequence[:len(currentSequence)-1]
		}
	}

	backtrack(0)

	return result
}
```Go 的实现与 Python 解决方案非常相似。 

由于 Go 切片是对底层数组的引用，因此我们必须在将子序列附加到之前显式创建一个副本`result`。 否则，回溯期间的后续修改将破坏先前存储的子序列。 

这`used`集是使用实现的`map[int]bool`。 

Go 不会以对这个问题很重要的方式区分 nil 和空切片，因此实现自然会正确处理空子序列。 

整数溢出不是问题，因为输入范围非常小。

 ## 边缘情况

 一种重要的边缘情况是只有一个元素的数组，例如`[5]`。 由于该问题需要长度至少为 2 的子序列，因此不存在有效答案。 有缺陷的实现可能会意外地包含单元素子序列。 此解决方案通过仅在序列长度至少为 2 时将序列添加到结果中来避免该问题。 

另一个关键的边缘情况涉及重复值，例如`[1,1,1]`。 如果不仔细处理重复项，可能会通过不同的索引组合多次生成相同的子序列。 每级`used`set 确保在每个递归深度仅探索相同的值一次，从而干净地消除重复的输出。 

第三个重要的边缘情况是严格递减的数组，例如`[5,4,3,2]`。 在这种情况下，几乎每次尝试的扩展都会违反非递减条件。 该实现通过检查来有效地处理这个问题：```
current_num < current_sequence[-1]
```在递归之前，防止探索无效的子序列。 

另一个微妙的边缘情况是负数与重复项混合，例如`[-2,-1,-1]`。 某些实现错误地假设值是正数或错误地处理相等比较。 该解决方案仅依赖于标准整数比较，因此可以自然且正确地处理负值和相等值。
