[LeetCode 第 480 题](https://leetcode.com/problems/sliding-window-median/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、滑动窗口、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题要求我们计算每个连续子数组或“窗口”大小的中位数`k`当该窗口在输入数组上从左向右滑动时。 

对于窗口的每个位置，我们精确地考虑`k`元素。 我们必须确定这些元素的中位数并将其附加到结果数组中。 一旦记录了中位数，窗口就会向右移动一位，这意味着一个元素离开窗口，一个新元素进入窗口。 

输入包括：

 -`nums`，一个整数数组
 -`k`, 固定窗口大小

 输出是一组浮点中位数，每个有效窗口位置都有一个。 

关键的挑战是效率。 约束条件允许`nums.length`最多`10^5`，这意味着任何对每个窗口独立重复排序的算法都可能太慢。 

一些细节尤其重要：

 - 如果窗口大小为奇数，则中位数为排序后中间的元素。 
- 如果窗口大小是偶数，则中位数是中间两个元素的平均值。 
- 允许负数。 
- 重复值很常见，必须正确处理。 
- 由于值可以大到`2^31 - 1`或小至`-2^31`，对两个整数求平均值时，实现必须避免溢出问题。 

这个问题最困难的部分是在元素不断进入和离开滑动窗口的同时有效地维护动态变化的有序结构。 

重要的边缘情况包括：

 -`k = 1`，其中每个元素都是其自己的中位数
 - 所有元素相同
 - 平均期间可能溢出的大量数字
 - 重复的值使得从堆中删除变得棘手
 - 偶数大小的窗口，其中中位数是小数
 - 严格增减数组，强调平衡逻辑

 ## 方法

 ### 蛮力方法

 最简单的解决方案是独立处理每个窗口。 

对于每个窗口：

 1. 提取`k`元素。 
2. 对它们进行排序。 
3. 计算排序列表的中位数。 
4. 将窗口向右移动一步。 

这种方法很简单并且总是正确的，因为排序明确给出了确定中位数所需的精确顺序。 

然而，对于大输入来说它太慢了。 有`O(n)`窗口，并对每个窗口的成本进行排序`O(k log k)`。 在最坏的情况下，哪里`k`接近于`n`，这大约变成`O(n^2 log n)`。 

和`n = 10^5`，这种复杂性是不可行的。 

### 最佳方法

 关键的观察是我们不需要每次都对窗口进行完全排序。 

相反，我们只需要快速访问：

 - 下半部分的最大值
 - 上半部分的最小值

 这自然建议使用两个堆：

 - 下半部分的最大堆
 - 上半部分的最小堆

 然后可以直接从堆顶获得中位数。 

困难来自于滑动窗口，因为元素也必须被有效地删除。 标准堆支持高效插入，但任意删除成本高昂。 

为了解决这个问题，我们使用了一种称为延迟删除的技术。 

我们不是立即从堆中删除元素，而是在哈希映射中记录应该删除的元素。 每当这样的元素到达堆顶部时，我们就会丢弃它。 

这允许所有操作保持对数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * k log k) | O(n * k log k) | O(k) | 独立排序每个窗口 |
 | 最佳 | O(n log k) | O(n log k) | O(k) | 具有惰性删除的两个堆 |

 ## 算法演练

 ### 最优算法

 1. 初始化两个堆。 

第一个堆称为`small`，是存储窗口值的较小一半的最大堆。 由于Python仅提供最小堆，因此我们存储负值来模拟最大堆。 

第二个堆称为`large`，是存储较大一半值的普通最小堆。 
2. 维护平衡规则。 

我们维护这些不变量：

 -`small`最多可以多包含一个元素`large`- 中的每个元素`small`必须小于或等于中的每个元素`large`这保证了中值提取很简单。 
3. 插入新元素。 

当新号码进入窗口时：

 - 如果它属于下半部分，则插入`small`- 否则插入`large`插入后，如有必要，重新平衡堆。 
4. 延迟删除传出元素。 

直接堆移除效率低下。 

相反：

 - 在名为的哈希映射中记录传出元素`delayed`- 与物理堆大小分开跟踪逻辑堆大小

 当延迟元素到达堆顶部时，立即将其删除。 
5. 修剪无效的堆顶。 

在读取堆顶之前，在顶部元素被标记为删除时重复弹出。 

这确保顶部值始终是有效的窗口成员。 
6. 插入或删除后重新平衡堆。 

如果一个堆变得太大：

 - 在堆之间移动顶部元素
 - 必要时修剪无效的顶部
 7. 计算中位数。 

如果`k`是奇数：

 - 中位数是顶部`small`如果`k`是偶数：

 - 中位数是两个堆顶的平均值
 8. 滑动窗口。 

对于每个步骤：

 - 添加传入值
 - 标记要删除的传出值
 - 重新平衡
 - 计算新的中位数

 ### 为什么它有效

 该算法之所以有效，是因为两个堆总是将窗口划分为有序的两半。 

最大堆存储较小的一半值，最小堆存储较大的一半。 平衡不变量保证中位数始终位于堆顶。 

延迟删除保留了正确性，因为元素只有在离开窗口后才会被忽略。 尽管无效元素可能暂时保留在堆中，但修剪可确保它们永远不会用于中值计算。 

## Python 解决方案```python
from typing import List
import heapq
from collections import defaultdict

class DualHeap:
    def __init__(self, k: int):
        self.small = []  # max heap via negatives
        self.large = []  # min heap

        self.delayed = defaultdict(int)

        self.small_size = 0
        self.large_size = 0

        self.k = k

    def prune(self, heap):
        while heap:
            num = -heap[0] if heap is self.small else heap[0]

            if self.delayed[num]:
                heapq.heappop(heap)
                self.delayed[num] -= 1

                if self.delayed[num] == 0:
                    del self.delayed[num]
            else:
                break

    def make_balance(self):
        if self.small_size > self.large_size + 1:
            num = -heapq.heappop(self.small)
            heapq.heappush(self.large, num)

            self.small_size -= 1
            self.large_size += 1

            self.prune(self.small)

        elif self.small_size < self.large_size:
            num = heapq.heappop(self.large)
            heapq.heappush(self.small, -num)

            self.large_size -= 1
            self.small_size += 1

            self.prune(self.large)

    def insert(self, num: int):
        if not self.small or num <= -self.small[0]:
            heapq.heappush(self.small, -num)
            self.small_size += 1
        else:
            heapq.heappush(self.large, num)
            self.large_size += 1

        self.make_balance()

    def erase(self, num: int):
        self.delayed[num] += 1

        if num <= -self.small[0]:
            self.small_size -= 1

            if num == -self.small[0]:
                self.prune(self.small)
        else:
            self.large_size -= 1

            if self.large and num == self.large[0]:
                self.prune(self.large)

        self.make_balance()

    def get_median(self) -> float:
        if self.k % 2 == 1:
            return float(-self.small[0])

        return (-self.small[0] + self.large[0]) / 2.0

class Solution:
    def medianSlidingWindow(self, nums: List[int], k: int) -> List[float]:
        dual_heap = DualHeap(k)

        for i in range(k):
            dual_heap.insert(nums[i])

        result = [dual_heap.get_median()]

        for i in range(k, len(nums)):
            dual_heap.insert(nums[i])
            dual_heap.erase(nums[i - k])

            result.append(dual_heap.get_median())

        return result
```实施围绕`DualHeap`助手类。 

这`small`堆将值的下半部分存储为负数以模拟最大堆行为。 这`large`堆通常存储上半部分。 

这`delayed`哈希映射记录了计划删除的值。 由于堆不支持高效的任意删除，因此只有当元素出现在堆顶时才会被删除。 

这`prune`函数重复删除无效的顶部元素。 这保证了任何访问的堆顶都属于当前窗口。 

这`make_balance`函数恢复堆大小不变。 下半部分可能包含一个额外的元素，但否则堆应该保持平衡。 

这`insert`函数将传入的值放入适当的堆中，然后重新平衡。 

这`erase`函数逻辑上删除传出值。 它会立即调整逻辑堆大小，并依靠延迟删除来进行实际删除。 

最后，`get_median`直接计算堆顶的中位数。 

## 解决方案```go
package main

import (
	"container/heap"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

type DualHeap struct {
	small      *MaxHeap
	large      *MinHeap
	delayed    map[int]int
	smallSize  int
	largeSize  int
	k          int
}

func Constructor(k int) *DualHeap {
	small := &MaxHeap{}
	large := &MinHeap{}

	heap.Init(small)
	heap.Init(large)

	return &DualHeap{
		small:   small,
		large:   large,
		delayed: make(map[int]int),
		k:       k,
	}
}

func (dh *DualHeap) pruneSmall() {
	for dh.small.Len() > 0 {
		num := (*(dh.small))[0]

		if count, exists := dh.delayed[num]; exists {
			if count == 1 {
				delete(dh.delayed, num)
			} else {
				dh.delayed[num]--
			}

			heap.Pop(dh.small)
		} else {
			break
		}
	}
}

func (dh *DualHeap) pruneLarge() {
	for dh.large.Len() > 0 {
		num := (*(dh.large))[0]

		if count, exists := dh.delayed[num]; exists {
			if count == 1 {
				delete(dh.delayed, num)
			} else {
				dh.delayed[num]--
			}

			heap.Pop(dh.large)
		} else {
			break
		}
	}
}

func (dh *DualHeap) makeBalance() {
	if dh.smallSize > dh.largeSize+1 {
		num := heap.Pop(dh.small).(int)
		heap.Push(dh.large, num)

		dh.smallSize--
		dh.largeSize++

		dh.pruneSmall()

	} else if dh.smallSize < dh.largeSize {
		num := heap.Pop(dh.large).(int)
		heap.Push(dh.small, num)

		dh.largeSize--
		dh.smallSize++

		dh.pruneLarge()
	}
}

func (dh *DualHeap) insert(num int) {
	if dh.small.Len() == 0 || num <= (*(dh.small))[0] {
		heap.Push(dh.small, num)
		dh.smallSize++
	} else {
		heap.Push(dh.large, num)
		dh.largeSize++
	}

	dh.makeBalance()
}

func (dh *DualHeap) erase(num int) {
	dh.delayed[num]++

	if num <= (*(dh.small))[0] {
		dh.smallSize--

		if num == (*(dh.small))[0] {
			dh.pruneSmall()
		}
	} else {
		dh.largeSize--

		if dh.large.Len() > 0 && num == (*(dh.large))[0] {
			dh.pruneLarge()
		}
	}

	dh.makeBalance()
}

func (dh *DualHeap) getMedian() float64 {
	if dh.k%2 == 1 {
		return float64((*(dh.small))[0])
	}

	left := float64((*(dh.small))[0])
	right := float64((*(dh.large))[0])

	return (left + right) / 2.0
}

func medianSlidingWindow(nums []int, k int) []float64 {
	dh := Constructor(k)

	for i := 0; i < k; i++ {
		dh.insert(nums[i])
	}

	result := []float64{dh.getMedian()}

	for i := k; i < len(nums); i++ {
		dh.insert(nums[i])
		dh.erase(nums[i-k])

		result = append(result, dh.getMedian())
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构，但 Go 需要使用显式堆实现`container/heap`包裹。 

为最小堆和最大堆行为定义了单独的堆类型。 

由于 Go 在除法期间不提供自动整数提升，因此中值计算显式地将操作数转换为`float64`求平均之前。 

映射用于延迟删除，与 Python 中完全相同。

 ## 边缘情况

 ### 窗口大小为一

 当`k = 1`，每个窗口只包含一个元素，因此每个元素都是它自己的中位数。 

这种情况可能会暴露平衡错误，因为一个堆经常保持空状态。 该实现自然地处理了这一问题，因为允许较低的堆包含一个额外的元素。 

### 重复值

 重复值是这个问题最难的方面之一，因为堆不支持有效的任意删除。 

如果存在多个相同的值，删除错误的值可能会破坏中值计算。 惰性删除映射通过跟踪计数而不是位置来解决这个问题。 元素仅在到达堆顶时才被物理删除。 

### 窗口大小均匀

 对于甚至`k`，中位数是两个中间值的平均值。 

这可能会引入整数除法错误或溢出问题。 该实现在除法之前将值转换为浮点，确保精确的小数结果并防止在对大整数求和时溢出。 

### 大正整数和负整数

 该问题允许值接近 32 位整数边界。 

在转换为浮点之前对整数进行平均的简单实现可能会在某些语言中溢出。 两种实现在除法之前都显式转换为浮点以确保正确性。 

### 堆内剩余的延迟元素

 由于删除是惰性的，因此堆可能会暂时包含不再位于滑动窗口内的无效元素。 

如果在中值访问或平衡之前没有正确修剪这些元素，则该算法可能会产生不正确的中值。 该实现通过在使用堆顶之前始终修剪无效的顶部元素来保证正确性。
