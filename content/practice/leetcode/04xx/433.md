[LeetCode 第 433 题](https://leetcode.com/problems/minimum-genic-mutation/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题描述了基因序列之间的突变过程。 每个基因都表示为正好 8 个字符的字符串，每个字符必须是四种可能的核苷酸之一：`'A'`,`'C'`,`'G'`， 或者`'T'`。 

我们得到三个输入：

 -`startGene`，初始基因序列
 -`endGene`，我们想要达到的目标基因序列
 -`bank`，有效中间基因序列的列表

 突变就是只改变基因串中的一个字符。 然而，有一个重要的限制：每个中间突变都必须存在于基因库内部。 即使突变只有一个字符不同，除非它出现在`bank`。 

目标是确定转化所需的最小突变数`startGene`进入`endGene`。 如果不存在有效的突变序列，我们返回`-1`。 

这本质上是一个最短路径问题。 每个有效基因都可以被视为图中的一个节点。 如果两个基因恰好有一个字符不同，则它们是相连的。 我们希望从起始节点到目标节点的变换次数最少。 

限制非常小：

 -`bank.length <= 10`- 每个基因都有长度`8`这些限制告诉我们几件事：

 - 暴力探索是可行的
 - 动态生成邻居的成本低廉
 - 像广度优先搜索这样的图遍历算法是理想的
 - 性能不是主要挑战，正确性和干净的遍历逻辑更重要

 有几个重要的边缘情况：

 -`endGene`银行中可能根本不存在，在这种情况下答案是立即`-1`- 银行可能是空的
 - 可能有多种可能的突变路径，我们特别需要最短的一条
 - 如果我们重新访问之前探索过的基因，循环是可能的，因此我们必须跟踪访问过的状态
 - 起始基因本身可能不会出现在银行中，这是问题陈述所允许的

 ## 方法

 ### 蛮力方法

 暴力解决方案将递归地尝试每个可能的突变序列。 开始于`startGene`，我们可以尝试将每个位置突变为四个核苷酸字符中的每一个，检查生成的基因是否存在于库中，并继续递归直到`endGene`被找到或者所有的可能性都被用尽。 

这种方法是正确的，因为它探索了所有可能的有效突变序列。 最终，如果路径存在，它就会发现它。 

然而，暴力方法效率低下，因为它反复探索相同的状态。 不同的递归路径可能会多次重新访问相同的基因，从而产生冗余计算。 如果没有仔细修剪，递归树会快速生长。 

尽管约束足够小，暴力破解可能会通过，但它并不是最干净或最具可扩展性的解决方案。 

### 关键见解

 关键的观察结果是这个问题要求突变的数量最少。 每当我们需要未加权图中的最短步数时，广度优先搜索通常是正确的工具。 

每个基因代表一个节点。 如果两个基因恰好有一个字符不同，则它们之间存在边缘。 

广度优先搜索在这里完美地发挥作用，因为：

 - 每个突变都有相同的成本
 - BFS 远距离探索所有状态`1`距离之前`2`- 我们第一次到达`endGene`，我们保证找到了最短的突变路径

 为了有效地检查生成的突变是否有效，我们将银行存储在哈希集中。 这在验证候选突变时提供了恒定时间的查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 大约 O(4^8 * n) | O(n) | 递归探索许多冗余突变路径 |
 | 最优 BFS | O(n * 8 * 4) | O(n) | 使用 BFS 寻找最短突变序列 |

 这里，`n`是银行中基因的数量。 

## 算法演练

 ### 最优 BFS 算法

 1. 将基因库转换为哈希集。 

我们使用哈希集是因为我们经常需要检查生成的突变是否有效。 一组提供平均`O(1)`查找时间。 
2. 检查是否`endGene`存在银行。 

如果目标基因不存在，则任何有效序列都无法到达它。 我们可以立即返回`-1`。 
3. 初始化BFS队列。 

队列存储对：

 - 当前基因
 - 达到该目标所需的突变数量

 我们从以下开始：```
(startGene, 0)
```4. 维护一个已访问集。 

一旦我们处理了一个基因，我们就不应该重新审视它。 重新访问状态会造成循环和冗余工作。 
5. 逐级处理队列。 

从队列中删除最前面的基因。 如果匹配的话`endGene`，立即返回突变计数。 
6. 生成所有可能的单字符突变。 

对于 8 个位置中的每一个：

 - 尝试将当前字符替换为`'A'`,`'C'`,`'G'`， 和`'T'`- 构建新的基因串
 - 检查银行中是否存在且未被访问过
 7. 将有效的突变添加到队列中。 

每个有效的下一个突变都会添加突变计数 + 1。 
8. 继续，直到队列变空。 

如果 BFS 完成后没有找到`endGene`，不存在有效的突变路径。 返回`-1`。 

### 为什么它有效

 广度优先搜索以突变计数递增的顺序探索基因。 每条边都代表一个突变，因此所有边都具有相同的权重。 

因为BFS充分探索了所有需要的路径`k`在探索需要的路径之前进行突变`k + 1`突变，我们第一次遇到`endGene`必须对应于最小可能的突变数量。 

访问集保证每个基因仅被处理一次，防止无限循环和冗余探索。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def minMutation(self, startGene: str, endGene: str, bank: List[str]) -> int:
        bank_set = set(bank)

        if endGene not in bank_set:
            return -1

        queue = deque([(startGene, 0)])
        visited = {startGene}

        possible_chars = ["A", "C", "G", "T"]

        while queue:
            current_gene, mutations = queue.popleft()

            if current_gene == endGene:
                return mutations

            gene_chars = list(current_gene)

            for i in range(8):
                original_char = gene_chars[i]

                for char in possible_chars:
                    if char == original_char:
                        continue

                    gene_chars[i] = char
                    next_gene = "".join(gene_chars)

                    if next_gene in bank_set and next_gene not in visited:
                        visited.add(next_gene)
                        queue.append((next_gene, mutations + 1))

                gene_chars[i] = original_char

        return -1
```实施过程首先将银行转变为一套高效的成员资格检查机构。 这很重要，因为每个生成的突变都必须快速验证。 

提前返回`endGene not in bank_set`当无法到达目标时，防止不必要的遍历。 

然后使用起始基因和突变计数初始化 BFS 队列`0`。 队列确保我们从起点开始按照距离递增的顺序探索状态。 

对于每个出列的基因，代码通过迭代每个字符位置并将其替换为每个核苷酸选项来生成所有可能的一步突变。 

每当生成的变异既有效又未被访问时，它就会被添加到队列中，并且变异计数加一。 

在每次突变尝试后恢复原始字符非常重要，因为在迭代中会重复使用相同的字符数组。 

如果BFS穷举所有可达基因而没有找到`endGene`，函数返回`-1`。 

## 解决方案```go
package main

func minMutation(startGene string, endGene string, bank []string) int {
	bankSet := make(map[string]bool)

	for _, gene := range bank {
		bankSet[gene] = true
	}

	if !bankSet[endGene] {
		return -1
	}

	type State struct {
		gene      string
		mutations int
	}

	queue := []State{{startGene, 0}}
	visited := make(map[string]bool)
	visited[startGene] = true

	chars := []byte{'A', 'C', 'G', 'T'}

	for len(queue) > 0 {
		current := queue[0]
		queue = queue[1:]

		if current.gene == endGene {
			return current.mutations
		}

		geneBytes := []byte(current.gene)

		for i := 0; i < 8; i++ {
			originalChar := geneBytes[i]

			for _, ch := range chars {
				if ch == originalChar {
					continue
				}

				geneBytes[i] = ch
				nextGene := string(geneBytes)

				if bankSet[nextGene] && !visited[nextGene] {
					visited[nextGene] = true
					queue = append(queue, State{
						gene:      nextGene,
						mutations: current.mutations + 1,
					})
				}
			}

			geneBytes[i] = originalChar
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的 BFS 结构。 由于Go没有提供内置的双端队列，因此使用切片作为队列。 

一个小`State`struct 将基因字符串和突变计数存储在一起。 

该实现不是重复转换字符串，而是在生成突变时使用字节切片。 这更有效，因为 Go 字符串是不可变的。 

Go 地图用于银行集和访问跟踪。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * 8 * 4) | 对于每个基因，我们尝试 8 个位置和 4 个可能的突变 |
 | 空间| O(n) | 队列、访问集和银行集每个商店最多 n 个基因 |

 由于访问集的原因，BFS 最多处理每个有效基因一次。 对于每个处理过的基因，我们最多生成`8 * 4 = 32`候选突变。 

由于银行规模极小，该解决方案在实践中非常有效。

 ## 边缘情况

 ### 银行缺失的最终基因

 最常见的错误之一是忘记每个有效的突变都必须存在于库中，包括最终的目标基因。 如果`endGene`不存在，无论中间状态如何，变换都是不可能的。 

实现立即处理这个问题：```
if endGene not in bank_set:
    return -1
```这可以防止不必要的 BFS 遍历。 

### 起始基因已经等于终止基因

 当起始基因和终止基因相同时，会发生另一种微妙的情况。 在这种情况下，不需要突变，所以正确答案是`0`。 

BFS 自然会处理这个问题，因为第一个出队状态是起始基因本身。 相等性检查立即成功。 

### 循环与反复探索

 突变图可以包含循环。 例如：```
AACCGGTT -> AACCGGTA -> AACCGGTT
```如果没有访问集，BFS 可以无限期地重新访问相同的基因或重复处理相同的状态。 

该实现通过添加基因来防止这种情况发生`visited`一旦他们排队。 因此，每个基因最多被处理一次。 

### 空基因库

 空库意味着没有可用的有效突变。 除非目标已经达到，否则答案必须是`-1`。 

该实现正确处理了这个问题，因为：

 - 最终基因将无法通过银行会员资格检查
 - BFS 永远不会将额外的状态加入队列

 这保证了正确的行为，而不需要特殊情况的逻辑。
