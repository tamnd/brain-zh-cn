 # LeetCode 499 - 迷宫 III

 ## 问题理解

 这个问题扩展了早期迷宫问题中引入的机制，但增加了两个重要的复杂性。 首先，我们不再寻找简单的可达到或不可达到的答案。 相反，我们必须根据行驶距离找到最短路径。 其次，如果存在多个最短路径，我们必须返回字典顺序最小的指令字符串。 

迷宫被表示为二维网格，其中`0`表示一个空白区域并且`1`表示一堵墙。 球从给定位置开始，迷宫中的某处也有一个洞。 球可以沿四个方向之一滚动：上、下、左或右。 

重要的运动规则是球在移动一个单元格后不会停止。 一旦选择了方向，球就会继续滚动，直到发生以下两种情况之一：

 1. 它撞到了墙上，在这种情况下，它停在前一个有效单元格上。 
2. 落入洞中，此时运动立即结束。 

目标是产生一系列指示，以便：

 - 球最终落入洞中。 
- 总行驶距离被最小化。 
- 如果多个路径具有相同的最小距离，则选择字典顺序最小的指令串。 

返回值是由字符组成的指令字符串：

 -`'u'`对于向上
 -`'d'`对于羽绒
 -`'l'`向左
 -`'r'`为权利

 如果无法到达该孔，则结果必须是`"impossible"`。 

约束很重要，因为迷宫尺寸可以大到`100 x 100`。 这意味着最多可以有 10,000 个单元。 对所有可能的滚动序列进行天真的详尽搜索很快就会变得不可行。 我们需要一种能够有效避免重新访问更糟糕状态的算法。 

一些边缘情况尤其重要：

 - 球可能会滚过洞，除非我们在运动过程中遇到洞时明确停止。 
- 多条路径可能具有相同的最短距离，需要仔细的字典顺序比较。 
- 可以使用更好的距离或字典顺序更小的路径重新访问单元格。 
- 球不能任意停止，只能停在墙壁或洞内。 
- 即使迷宫包含许多开放空间，该洞也可能无法到达。 

最短路径计算和字典顺序打破平局的这种组合强烈建议使用图最短路径算法，例如 Dijkstra 算法。 

## 方法

 ### 蛮力方法

 强力解决方案将从起始位置递归地探索每个可能的滚动方向序列。 在每个停止点，算法将尝试在所有四个方向上滚动并继续，直到到达洞或所有可能性都用尽。 

这种方法是正确的，因为它最终枚举了每个可能的有效运动序列。 然而，这在计算上是不切实际的，因为可以使用不同的路径串和距离多次重新访问相同的停止位置。 

可能的运动序列的数量随着可到达的停止点的数量呈指数增长。 由于每个状态可以重复分支到四个方向，因此即使对于中等大小的迷宫，搜索空间也会变得巨大。 

此外，字典顺序使修剪变得复杂，因为具有相同距离的两条路径可能仍然需要比较。 

### 最佳方法

 关键的见解是，这从根本上来说是一个加权最短路径问题。 

迷宫中的每个停止位置都可以被视为一个图节点。 沿某个方向滚动会产生一条边缘，其重量等于停止或落入孔中之前行进的细胞数量。 

由于移动成本不均匀，普通的 BFS 是不够的。 BFS仅在所有边权重相等时保证正确性。 在这里，一卷可能会移动一个单元，而另一卷可能会移动二十个。 

Dijkstra 算法非常理想，因为：

 - 它计算最短加权路径。 
- 当发现更好的路径时，它自然会处理重新访问节点。 
- 优先级队列允许按总距离递增的顺序进行探索。 
- 当距离相等时，我们可以扩展比较逻辑以包括字典顺序。 

该算法存储：

 - 当前总距离
 - 当前路径字符串
 - 当前坐标

 优先级队列优先考虑：

 1.距离更小
 2. 按字典顺序更小的路径字符串

 这保证了我们第一次从优先级队列中删除漏洞时，我们就得到了最优答案。

 ## 算法演练

 1. 初始化一个包含起始位置和距离的优先级队列`0`和一个空指令字符串。 
2. 创建一个字典或矩阵来记录每个单元格的最佳已知状态。 状态由以下部分组成：

 - 到达细胞的最小距离
 - 该距离的字典顺序最小路径
 3. 定义四种可能的滚动方向：

 - 向上：`(-1, 0, 'u')`- 向下：`(1, 0, 'd')`- 左边：`(0, -1, 'l')`- 正确的：`(0, 1, 'r')`4. 反复从优先级队列中提取最佳状态。 优先级队列首先按总距离排序，然后按字典路径字符串排序。 
5. 如果当前位置是洞，则立即返回当前路径字符串。 由于 Dijkstra 排序，这保证是所有最短路径中最短路径并且按字典顺序最小。 
6. 对于每个方向：

 1. 从当前单元格开始。 
2. 朝该方向连续滚动。 
3. 计算遍历了多少个单元格。 
4. 如果出现以下情况，请停止：

 - 到达墙壁，或者
 - 遇到洞
 5. 计算：

 - 新的总距离
 - 新的路径字符串
 7. 将新发现的状态与停止位置的最已知状态进行比较。 

- 如果新的距离较小，则更新它。 
- 如果距离相等但路径字符串按字典顺序更小，也更新它。 
8. 将改进后的状态推入优先级队列。 
9. 继续直到：

 - 发现洞，或者
 - 优先级队列变空
 10.如果队列未到达洞口就变空，则返回`"impossible"`。 

### 为什么它有效

 Dijkstra 算法保证节点按照最短已知距离的非递减顺序进行处理。 通过扩展优先级比较以包括字典顺序，我们确保在所有最短路径中，首先处理字典顺序最小的路径。 

因为每条边的权重都是非负的，一旦空洞从优先级队列中移除，以后就不可能存在更好的解了。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def findShortestWay(
        self,
        maze: List[List[int]],
        ball: List[int],
        hole: List[int]
    ) -> str:

        rows = len(maze)
        cols = len(maze[0])

        directions = [
            (-1, 0, 'u'),
            (1, 0, 'd'),
            (0, -1, 'l'),
            (0, 1, 'r')
        ]

        priority_queue = [(0, "", ball[0], ball[1])]

        best = {
            (ball[0], ball[1]): (0, "")
        }

        while priority_queue:
            distance, path, row, col = heapq.heappop(priority_queue)

            if [row, col] == hole:
                return path

            if best[(row, col)] < (distance, path):
                continue

            for dr, dc, direction_char in directions:
                current_row = row
                current_col = col
                steps = 0

                while True:
                    next_row = current_row + dr
                    next_col = current_col + dc

                    if (
                        next_row < 0 or
                        next_row >= rows or
                        next_col < 0 or
                        next_col >= cols or
                        maze[next_row][next_col] == 1
                    ):
                        break

                    current_row = next_row
                    current_col = next_col
                    steps += 1

                    if [current_row, current_col] == hole:
                        break

                new_distance = distance + steps
                new_path = path + direction_char

                state = (current_row, current_col)

                if (
                    state not in best or
                    (new_distance, new_path) < best[state]
                ):
                    best[state] = (new_distance, new_path)

                    heapq.heappush(
                        priority_queue,
                        (
                            new_distance,
                            new_path,
                            current_row,
                            current_col
                        )
                    )

        return "impossible"
```实现首先定义迷宫尺寸和四个可能的滚动方向。 每个方向都包含坐标移动和相应的指令字符。 

优先级队列用于实现 Dijkstra 算法。 每个队列条目存储：

 - 总行驶距离
 - 路径字符串
 - 当前行
 - 当前栏目

 Python 的堆排序自然地按字典顺序对元组进行优先级排序，因此`(distance, path)`自动执行正确的排序。 

这`best`字典存储每个单元的最佳已知状态。 如果满足以下条件，则认为状态更好：

 - 它的距离较小，或者
 - 它具有相同的距离，但按字典顺序更小的路径

 滚动模拟是问题的核心。 对于每个方向，球都会继续移动，直到撞到墙壁或落入洞中。 重要的是，球洞检查发生在运动过程中，而不仅仅是停止后，因为球立即消失在球洞中。 

每当找到更好的状态时，它就会被插入到优先级队列中以供将来探索。 

如果从未到达该洞，算法将返回`"impossible"`。 

## 解决方案```go
package main

import (
	"container/heap"
)

type State struct {
	dist int
	path string
	row  int
	col  int
}

type PriorityQueue []State

func (pq PriorityQueue) Len() int {
	return len(pq)
}

func (pq PriorityQueue) Less(i, j int) bool {
	if pq[i].dist == pq[j].dist {
		return pq[i].path < pq[j].path
	}
	return pq[i].dist < pq[j].dist
}

func (pq PriorityQueue) Swap(i, j int) {
	pq[i], pq[j] = pq[j], pq[i]
}

func (pq *PriorityQueue) Push(x interface{}) {
	*pq = append(*pq, x.(State))
}

func (pq *PriorityQueue) Pop() interface{} {
	old := *pq
	n := len(old)

	item := old[n-1]
	*pq = old[:n-1]

	return item
}

func findShortestWay(maze [][]int, ball []int, hole []int) string {
	rows := len(maze)
	cols := len(maze[0])

	directions := [][]int{
		{-1, 0},
		{1, 0},
		{0, -1},
		{0, 1},
	}

	dirChars := []string{"u", "d", "l", "r"}

	pq := &PriorityQueue{}
	heap.Init(pq)

	heap.Push(pq, State{
		dist: 0,
		path: "",
		row:  ball[0],
		col:  ball[1],
	})

	best := make(map[[2]int]State)

	startKey := [2]int{ball[0], ball[1]}
	best[startKey] = State{
		dist: 0,
		path: "",
	}

	for pq.Len() > 0 {
		current := heap.Pop(pq).(State)

		if current.row == hole[0] && current.col == hole[1] {
			return current.path
		}

		key := [2]int{current.row, current.col}

		bestState := best[key]

		if current.dist > bestState.dist ||
			(current.dist == bestState.dist &&
				current.path > bestState.path) {
			continue
		}

		for i := 0; i < 4; i++ {
			dr := directions[i][0]
			dc := directions[i][1]

			row := current.row
			col := current.col
			steps := 0

			for {
				nextRow := row + dr
				nextCol := col + dc

				if nextRow < 0 ||
					nextRow >= rows ||
					nextCol < 0 ||
					nextCol >= cols ||
					maze[nextRow][nextCol] == 1 {
					break
				}

				row = nextRow
				col = nextCol
				steps++

				if row == hole[0] && col == hole[1] {
					break
				}
			}

			newDist := current.dist + steps
			newPath := current.path + dirChars[i]

			newKey := [2]int{row, col}

			prev, exists := best[newKey]

			if !exists ||
				newDist < prev.dist ||
				(newDist == prev.dist &&
					newPath < prev.path) {

				best[newKey] = State{
					dist: newDist,
					path: newPath,
				}

				heap.Push(pq, State{
					dist: newDist,
					path: newPath,
					row:  row,
					col:  col,
				})
			}
		}
	}

	return "impossible"
}
```Go 实现遵循与 Python 解决方案相同的算法结构，但一些特定于语言的细节有所不同。 

Go没有提供内置的优先级队列，所以`container/heap`使用包。 这需要实施`heap.Interface`，包括诸如`Len`,`Less`,`Swap`,`Push`， 和`Pop`。 

优先级排序是在内部明确实现的`Less`方法。 首先比较距离，然后比较路径字符串以进行字典顺序。 

Go 地图需要可比较的键，因此坐标存储为固定大小的数组`[2]int`而不是切片。 

与 Python 元组不同，Go 结构体不支持自动比较，因此所有平局逻辑都必须手动实现。

    def findShortestWay(

        import heapq

        rows = len(maze)
        cols = len(maze[0])

        directions = [
            (-1, 0, 'u'),
            (1, 0, 'd'),
            (0, -1, 'l'),

 ## 边缘情况

 当球在到达墙壁之前滚过洞时，就会出现一种重要的边缘情况。 一个常见的错误是只检查最终停止位置是否等于洞。 这种方法是不正确的，因为球一经过洞就立即落入洞中。 该实现通过在每个滚动步骤期间检查孔来处理这个问题。 

另一个关键的边缘情况涉及具有相同行进距离的多条最短路径。 标准最短路径算法通常只比较距离，但这个问题还需要字典顺序最小的指令串。 该实现通过将距离和路径存储在优先级队列排序和最佳状态比较逻辑中来处理此问题。 

当使用更好的路径重新访问单元时，就会出现第三种微妙的情况。 即使单元格被较早处理，较晚的路线也可能会产生：

 - 较短的距离，或
 - 距离相同，但路径按字典顺序更小

 每当发生任何改进时，实现都会正确更新存储的状态。 

第四个重要情况涉及滚入死胡同或保持静止。 有些方向可能会立即撞到墙上并产生零移动。 该算法可以安全地处理这些情况，因为结果状态不会改善现有的最佳状态，从而防止不必要的处理或无限循环。 

最后，不可触及的洞是一个重要的场景。 迷宫可能包含许多开放的单元格，但由于墙壁放置和滚动限制，仍然无法进入该洞。 算法正确返回`"impossible"`一旦优先级队列耗尽而没有到达洞口。
