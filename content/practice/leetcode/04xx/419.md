 # LeetCode 419 - 棋盘上的战舰

 ## 问题理解

 这个问题给了我们一个二维网格，其中每个单元格包含`'X'`或者`'.'`。 

一个`'X'`代表战舰的一部分，而`'.'`代表空水。 

重要的规则是战列舰总是排成直线。 战列舰可以是：

 - 水平，形状像`1 x k`- 垂直，形状像`k x 1`这意味着战舰永远不会弯曲或形成矩形。 

该问题还保证至少有一个空单元格分隔任意两艘战舰。 两艘船永远不会水平或垂直直接相邻。 

我们的任务是计算棋盘上有多少艘不同的战舰。 

例如，考虑：```
X..X
...X
...X
```最左边的`X`是一艘单细胞战列舰。 

右侧的垂直立柱形成了另一艘战舰。 

因此答案是`2`。 

约束条件告诉我们：

 - 板尺寸可达`200 x 200`- 对电路板进行全面扫描是完全可行的
 - 我们的目标应该是`O(m * n)`solution
 - The follow up specifically asks for:

 - One pass
 -`O(1)`额外的内存
 - 无需修改主板

 这些提示强烈建议我们应该尽可能避免 DFS 访问数组或洪水填充方法。 

一些边缘情况很重要：

 - 一块仅含有水的木板
 - 一块单电池板
 - 单细胞战舰
 - 长水平船
 - 长垂直船
 - 多艘船对角放置在彼此附近
 - 船舶对角线接触，这是允许的
 - 大密板

 幼稚的实现可能会意外地将来自同一艘船的多个单元计算为单独的战舰。 关键的挑战是确定何时`'X'`代表一艘船的开始与仅是已计数船舶的另一部分。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是使用深度优先搜索或广度优先搜索。 

每当我们遇到未曾拜访过的人`'X'`，我们开始探索所有连接的遍历`'X'`属于同一艘战舰的细胞。 遍历完成后，我们将战舰数量加一。 

这是有效的，因为每个连接的组件`'X'`在问题约束下，单元恰好对应于一艘战舰。 

然而，这种方法需要额外的内存：

 - 访问过的矩阵，或
 - 修改输入板

 DFS或BFS遍历也会引入不必要的开销，因为棋盘结构有很强的保证。 

虽然复杂度在约束条件下是可以接受的，但不能满足后续要求`O(1)`无需修改电路板即可获得额外空间。 

### 最佳方法

 关键的观察是我们只需要计算每艘战舰的起始单元即可。 

如果满足以下条件，则单元格是战舰的起点：

 - 当前单元格包含`'X'`- 没有`'X'`就在它上面
 - 没有`'X'`直接在其左侧

 为什么这有效？ 

如果战舰是水平的，除了第一个单元之外的每个单元都有另一个`'X'`在它的左边。 

如果战舰是垂直的，除了第一个单元之外的每个单元都有另一个`'X'`在它之上。 

因此，每艘船的第一个单元通过其上方和左侧不存在相邻的船单元来唯一标识。 

这使我们能够在具有恒定额外内存的单次遍历中对船只进行计数。

 ## 算法演练

 1.初始化一个计数器变量`battleships = 0`。 
2. 使用嵌套循环迭代面板中的每个单元格。 
3. 对于每个单元格，首先检查它是否包含`'X'`。 

如果细胞含有`'.'`，它不可能是战列舰的一部分，所以我们跳过它。 
4. 如果当前单元格包含`'X'`，判断是否是新船的开始。 

我们检查：

 - 有没有`'X'`直接在上面？ 
- 有没有`'X'`直接向左？ 
5. 如果任一邻居包含`'X'`，那么当前单元格属于已经计数的战列舰。 

这意味着：

 - 水平船从左侧继续
 - 一艘垂直的船从上方继续
 6. 如果两个邻居都不包含`'X'`，那么这个单元就是新战舰的第一部分。 

增加计数器。 
7. 继续扫描，直到整块板处理完毕。 
8. 返回最终战舰数量。 

### 为什么它有效

 每艘战列舰都有一个最左上角的单元格。 

对于水平船，只有第一个单元缺少左邻居。 

对于垂直船，只有第一个单元缺少上部邻居。 

由于舰船永远不会水平或垂直接触，因此每艘战列舰都贡献了一个这样的起始单元。 因此，对这些起始单元进行计数就对每艘战舰进行了一次计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def countBattleships(self, board: List[List[str]]) -> int:
        rows = len(board)
        cols = len(board[0])

        battleships = 0

        for row in range(rows):
            for col in range(cols):
                if board[row][col] != 'X':
                    continue

                if row > 0 and board[row - 1][col] == 'X':
                    continue

                if col > 0 and board[row][col - 1] == 'X':
                    continue

                battleships += 1

        return battleships
```实现首先确定行数和列数。 

然后我们初始化一个名为`battleships`。 

嵌套循环对矩阵中的每个位置精确扫描一次。 

对于每个单元，第一个条件检查该单元是否实际上是战舰的一部分。 如果没有，我们立即继续下一次迭代。 

接下来，我们检查当前单元格是否有另一个单元格`'X'`就在它上面。 如果是的话，这意味着当前单元格属于之前已经统计过的垂直战舰。 

同样，我们检查当前单元格是否有另一个单元格`'X'`直接在其左侧。 如果是的话，那就属于已经算过的卧式战列舰了。 

只有当这两个条件都不成立时，我们才会增加战舰数量。 这保证了每艘船只贡献一次计数。 

该算法从不修改电路板，仅使用恒定的额外内存。 

## 解决方案```go
func countBattleships(board [][]byte) int {
    rows := len(board)
    cols := len(board[0])

    battleships := 0

    for row := 0; row < rows; row++ {
        for col := 0; col < cols; col++ {

            if board[row][col] != 'X' {
                continue
            }

            if row > 0 && board[row-1][col] == 'X' {
                continue
            }

            if col > 0 && board[row][col-1] == 'X' {
                continue
            }

            battleships++
        }
    }

    return battleships
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

董事会表示为`[][]byte`，因此与字节文字进行比较，例如`'X'`。 

Go 切片自然提供对行和列的动态访问，因此不需要额外的处理。 

不存在整数溢出问题，因为最大单元数仅为`40,000`。 

该算法还使用 Go 中恒定的额外内存。

 ## 边缘情况

 ### 单电池板

 一块有尺寸的板`1 x 1`是可能的最小输入。 单细胞可以包含`'.'`或者`'X'`。 

如果边界检查写得不仔细，这种情况很容易处理错误。 访问`row - 1`或者`col - 1`不验证边界可能会导致错误。 

实施安全地检查：```
if row > 0
if col > 0
```在访问邻居之前。 

### 长水平或垂直船舶

 一艘船可能跨越整行或整列。 

一个幼稚的解决方案可能会错误地计算每个`'X'`细胞作为一艘单独的船。 

该算法通过仅计算没有的单元格来避免这种情况`'X'`上方或左侧。 每个连续段都会自动跳过。 

### 对角战列舰

 允许船舶对角接触：```
X.
.X
```这是两艘独立的船，而不是一个相连的部件。 

如果探索了所有八个方向，某些图遍历实现会意外地将对角邻接视为已连接。 

此实现仅检查顶部和左侧邻居，这正确保留了船舶仅水平或垂直连接的问题定义。
