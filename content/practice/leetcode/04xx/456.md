[LeetCode 第 456 题](https://leetcode.com/problems/132-pattern/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、堆栈、单调堆栈、有序集

 ## 解决方案

 ## 问题理解

 该问题要求我们确定数组是否包含称为“132 模式”的特定排序模式。 

有效的 132 模式由三个索引组成`i`,`j`， 和`k`这样：

 -`i < j < k`-`nums[i] < nums[k] < nums[j]`名称“132”来自值的相对顺序：

 -`nums[i]`是最小值，代表`1`-`nums[j]`是最大值，代表`3`-`nums[k]`位于它们之间，代表`2`索引必须按升序出现，但值遵循`1 < 2 < 3`与最后出现的中间值的关系。 

例如，在数组中`[3,1,4,2]`:

 -`1`is the smallest value
 -`4`是最大值
 -`2`位于他们之间

 索引的顺序正确，所以`[1,4,2]`形成有效的 132 模式。 

输入是一个整数数组`nums`长度可达`2 * 10^5`。 这个约束非常重要，因为它立即排除了实践中昂贵的三次甚至二次解。 一个`O(n^3)`暴力解决方案需要检查数十亿个组合以获取大量输入，这太慢了。 

值本身的范围可以是`-10^9`到`10^9`，这意味着：

 - 我们不能依赖计数排序或有界值技术
 - 比较是唯一有意义的操作
 - 必须正确处理负数和重复项

 一些边缘情况很重要：

 - 元素少于三个的数组永远不能包含 132 模式
 - 严格的不平等很重要，同等价值不符合条件
 - 单调递增数组不能包含该模式
 - 单调递减数组也不能包含该模式
 - 如果不仔细处理严格的比较，重复的值很容易破坏天真的逻辑

 面临的挑战是有效跟踪三个位置的候选值，同时保留索引顺序。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是尝试每一个可能的三元组`(i, j, k)`。 

我们迭代所有组合，其中`i < j < k`并检查是否：```
nums[i] < nums[k] < nums[j]
```如果任何三元组满足条件，我们返回`true`。 否则，在穷尽所有可能性后，我们返回`false`。 

这种方法是正确的，因为它显式检查长度为 3 的每个有效子序列。 如果 132 模式存在，我们就一定能找到它。 

但时间复杂度极差。 有`O(n^3)`在最坏的情况下是三胞胎，这对于`n = 2 * 10^5`。 

即使部分优化的双循环方法仍然很困难，因为我们需要一种快速的方法来确定两个元素之间是否存在有效的中间值。 

### 最佳解决方案的关键见解

 主要挑战是有效地发现：```
nums[i] < nums[k] < nums[j]
```同时保留索引顺序。 

一个非常重要的观察是可以从右到左搜索模式。 

假设我们修复`nums[j]`作为模式中潜在的最大元素。 那么我们想要：

 - 左侧较小的值，`nums[i]`- 右侧的中间值，`nums[k]`最佳解决方案在从右向左扫描时使用单调递减堆栈。 

堆栈存储候选值`3`元素，意思是潜力`nums[j]`价值观。 

同时，我们维护另一个代表最佳候选者的变量`2`元素、意义`nums[k]`。 

推理过程是这样的：

 - 从右向左扫描时，每个元素自然可以访问其右侧的所有内容
 - 如果我们遇到一个小于当前值的值`nums[k]`，我们发现：```
nums[i] < nums[k]
```- 自从`nums[k]`之前是从一个更大的栈元素中提取出来的，我们已经知道：```
nums[k] < nums[j]
```这将创建完整的图案。 

单调堆栈使我们能够在线性时间内维持这些关系。

 ## 算法演练

 ### 最优单调堆栈算法

 1. 初始化一个空堆栈。 

堆栈将存储候选值`3`元素按降序排列。 
2. 初始化一个名为`second`。 

该变量代表了该变量的最佳候选者`2`132 模式中的元素。 最初，将其设置为负无穷大，因为尚未找到候选者。 
3. 从右向左遍历数组。 

从右向左扫描至关重要，因为该模式需要：```
i < j < k
```回顾过去，我们可以将右侧的一切视为潜在的未来元素。 
4. 对于每个数字`num`，首先检查是否：```
num < second
```如果这是真的，我们发现：```
nums[i] = num
nums[k] = second
```自从`second`之前被更大的元素从堆栈中弹出，我们还知道：```
second < nums[j]
```因此，完整的132模式存在。 
5. 当堆栈不为空且：```
num > stack[-1]
```从堆栈中弹出元素。 

每个弹出的值都成为候选值`second`。 

这是有效的，因为：

 - 当前`num`更大
 - 弹出的值较小
 - 因此：```
popped < num
```符合所需的关系：```
nums[k] < nums[j]
```6. 将当前数字压入堆栈。 

它可能会成为未来`nums[j]`更左边的元素的候选者。 
7. 如果遍历结束没有找到有效模式，则返回`false`。 

### 为什么它有效

 堆栈维护递减的值，确保每当弹出一个值时，我们都会在其左侧找到更大的值。 

变量`second`始终存储中间值的有效候选值`nums[k]`这样，按遍历顺序，其左侧已经存在一些较大的元素。 

当我们稍后遇到小于的值时`second`，我们自动满足：```
nums[i] < nums[k] < nums[j]
```通过从右到左的遍历保证正确的索引排序。 

## Python 解决方案```python
from typing import List

class Solution:
    def find132pattern(self, nums: List[int]) -> bool:
        stack = []
        second = float('-inf')

        for num in reversed(nums):
            if num < second:
                return True

            while stack and num > stack[-1]:
                second = stack.pop()

            stack.append(num)

        return False
```该实现遵循算法演练中描述的确切逻辑。 

这`stack`存储代表候选的递减值`nums[j]`元素。 由于堆栈在递减，较小的值保留在顶部附近，当出现较大的值时可以弹出。 

变量`second`追踪最佳候选人`nums[k]`。 每次从堆栈中弹出时，我们都知道弹出的值小于当前数字，这意味着它可以合法地充当 132 模式的中间元素。 

遍历使用`reversed(nums)`这样每个元素自然会看到其右侧的所有值。 

条件：```python
if num < second:
```是关键的检测步骤。 那一刻：

 -`num`充当`nums[i]`-`second`充当`nums[k]`- 一些先前处理的较大数字充当`nums[j]`一旦发生这种情况，函数立即返回`True`。 

如果循环未成功完成，则不存在有效模式。 

## 解决方案```go
func find132pattern(nums []int) bool {
	stack := []int{}
	second := -(1 << 60)

	for i := len(nums) - 1; i >= 0; i-- {
		num := nums[i]

		if num < second {
			return true
		}

		for len(stack) > 0 && num > stack[len(stack)-1] {
			second = stack[len(stack)-1]
			stack = stack[:len(stack)-1]
		}

		stack = append(stack, num)
	}

	return false
}
```Go 的实现与 Python 解决方案非常相似。 

切片用作堆栈。 切片的最后一个元素充当堆栈的顶部。 

由于 Go 不直接为整数提供负无穷大，因此实现初始化`second`使用一个非常小的整数：```go
second := -(1 << 60)
```这安全地符合 Go 的整数范围，并且对于问题约束来说表现得像负无穷大。 

该算法在其他方面保持相同：

 - 从右向左遍历
 - 维持递减堆栈
 - 更新`second`当弹出时

 ## 边缘情况

 ### 元素少于三个的数组

 132 模式需要三个索引：```
i < j < k
```因此，大小的数组`0`,`1`， 或者`2`永远不能包含有效的模式。 

幼稚的实现有时会忘记这一点并意外访问无效索引或执行不必要的工作。 基于堆栈的解决方案可以自然地处理这个问题，因为遍历只是在没有找到有效关系的情况下完成。 

### 重复值

 问题中的不等式是严格的：```
nums[i] < nums[k] < nums[j]
```相同的值不算数。 

例如：```
[1,1,1,1]
```即使有多个重复的数字，也不包含有效的模式。 

如果像这样的非严格比较，这是错误的常见来源`<=`被意外使用。 实现正确使用：```
num > stack[-1]
```和：```
num < second
```它保留了严格的不平等要求。 

### 严格递增或递减数组

 数组如：```
[1,2,3,4]
```或者：```
[4,3,2,1]
```不能包含 132 模式。 

递增数组缺少小于最大元素的中间值。 

递减数组完全缺乏所需的排序关系。 

这些情况很重要，因为它们强调单调堆栈结构：

 - 增加数组使堆栈不断增长
 - 减少的数组很少从堆栈中弹出

 该算法可以在线性时间内有效地处理这两个问题。
