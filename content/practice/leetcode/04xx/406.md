 # LeetCode 406 - 按高度重建队列

 ## 问题理解

 这个问题给了我们一个人的列表，其中每个人都表示为一对`[h, k]`。 

价值`h`代表人的身高。 

价值`k`代表有多少人站在这个人面前，身高必须大于或等于`h`。 

我们的任务是重建原来的队列安排，使得每个人的`k`条件满足。 

例如，如果一个人是`[6,1]`，这意味着他们面前的一个人必须有身高`>= 6`。 

输入数组不一定以任何有意义的方式排序。 我们必须自己确定正确的安排。 

输出必须是一个队列，其中每个人同时满足其约束。 

约束条件很重要：

 - 最多可以有`2000`人们。 
- 高度可以大到`10^6`。 
- 该问题保证有效的重建始终存在。 

自从`n`只是`2000`， 一个`O(n^2)`解决方案是可以接受的，因为`2000^2 = 4,000,000`，这是可以管理的。 然而，立方解可能太慢。 

一些边缘情况很重要：

 - 多个人可能具有相同的身高。 
- 多个人可能有`k = 0`。 
- 如果我们处理的顺序错误，最矮的人是最难贪婪地安置的。 
- 身高相同的人需要仔细排序，因为他们互相算数`k`价值观。 
- 幼稚的插入策略很容易使先前放置的人员失效。 

保证有效队列的存在简化了问题，因为我们不需要检测不可能的状态。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试生成人员的排列，并检查每种排列是否满足所有约束。 

对于每个排列：

 1. 遍历队列。 
2. 统计之前有多少人的身高大于或等于当前人。 
3. 验证计数是否等于`k`。 

如果所有人都满足他们的约束，我们就会返回该排列。 

这种方法是正确的，因为它明确地测试了每种可能的顺序。 最终，将会找到有效的安排。 

然而，其复杂性是灾难性的。 有`n!`可能的排列，即使对于相对较小的值也是不可能的`n`。 

即使进行了修剪或回溯优化，这种方法对于`n = 2000`。 

### 最优贪心法

 关键的见解是，较高的人不会受到身后或周围较矮的人的影响。 

假设我们把最高的人放在第一位。 

放置高个子时：

 - 只有身高相同或更高的人才对他们的`k`价值。 
- 身材矮小的人不影响计数。 

这一观察结果允许采用贪婪策略。 

我们按以下方式对人员进行排序：

 1. 身高从高到低的顺序
 2.`k`对于相同高度按升序排列

 然后我们将每个人插入到索引处的结果中`k`。 

为什么这有效？ 

因为当先处理较高的人时，当前队列已经只包含身高大于或等于当前人的人。 

因此，在索引处插入`k`准确保证`k`合格的人站在他们面前。 

这种优雅的观察将问题转化为简单的排序和插入过程。

 ## 算法演练

 ### 第 1 步：对人员进行排序

 使用两个规则对数组进行排序：

 1.高度优先
 2. 较小`k`首先当高度相等时

 例如：```
[[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]
```变成：```
[[7,0],[7,1],[6,1],[5,0],[5,2],[4,4]]
```这种顺序至关重要，因为必须先修复较高的人，然后再修复较矮的人。 

### 步骤 2：初始化一个空队列

 创建一个空结果列表。```
queue = []
```我们将逐步建立正确的安排。 

### 步骤 3：按排序顺序处理每个人

 从左到右遍历排序后的数组。 

对于每个人`[h, k]`：

 - 将它们插入队列中的位置`k`。 

为什么？ 

此时此刻，已经在队列中的所有人至少都和当前的人一样高。 

因此，将当前人置于索引处`k`准确地确保`k`更高或同等的人出现在他们面前。 

### 步骤 4：继续，直到所有人员都被插入

 每次插入都会保留先前放置的较高人物的正确性。 

最终，队列同时满足所有约束。 

### 步骤 5：返回队列

 返回最终重建的队列。 

## 为什么它有效

 核心不变量是：

 > 插入人员之前`[h, k]`，队列中已仅包含身高大于或等于的人`h`。 

由于这个不变量：

 - 插入索引直接对应于当前人之前有效的高于或等于的人的数量。 
- 稍后插入的矮个子不会影响已放置的高个子的计数。 

按高度降序排序可保证此不变量始终成立。 

## Python 解决方案```python
from typing import List

class Solution:
    def reconstructQueue(self, people: List[List[int]]) -> List[List[int]]:
        # Sort by descending height, ascending k
        people.sort(key=lambda person: (-person[0], person[1]))

        queue = []

        # Insert each person at index k
        for person in people:
            queue.insert(person[1], person)

        return queue
```实现首先根据贪婪排序策略对人员进行排序。 

排序键`(-person[0], person[1])`确保：

 - 个子高的人优先
 - 同等高度中，较小`k`价值观至上

 排序后，我们创建一个空列表，名为`queue`。 

然后我们遍历每个人并将他们直接插入到索引处`k`。 

蟒蛇的`list.insert(index, value)`自动将后面的元素向右移动，非常适合这个问题。 

因为首先插入较高的人，所以每次插入都会保持正确性所需的不变性。 

最后返回完成的队列。 

## 解决方案```go
package main

import "sort"

func reconstructQueue(people [][]int) [][]int {
    // Sort by descending height, ascending k
    sort.Slice(people, func(i, j int) bool {
        if people[i][0] == people[j][0] {
            return people[i][1] < people[j][1]
        }
        return people[i][0] > people[j][0]
    })

    queue := make([][]int, 0)

    // Insert each person at index k
    for _, person := range people {
        index := person[1]

        queue = append(queue, nil)

        copy(queue[index+1:], queue[index:])

        queue[index] = person
    }

    return queue
}
```Go 解决方案遵循与 Python 版本完全相同的算法策略。 

由于Go切片没有提供像Python列表那样的内置插入方法，因此我们手动执行插入：

 1. 使用扩展切片`append`2.使用将元素向右移动`copy`3. 将新人放置在目标索引处

 排序逻辑使用`sort.Slice`带有自定义比较器。 

不存在整数溢出问题，因为所有值都适合 Go 的标准整数范围。 

该实现正确处理空切片和 Python 版本涵盖的所有边缘情况。

 ## 边缘情况

 ### 多个相同身高的人

 当几个人身高相同时，他们的相对顺序就变得极其重要。 

例如：```
[[5,0],[5,1],[5,2]]
```如果我们不按升序对相等高度进行排序`k`，插入一个更大的人`k`首先可能会使后来的展示位置无效。 

该实现通过使用升序对相等高度进行排序来正确处理此问题`k`。 

### 每个人都有`k = 0`考虑：```
[[1,0],[2,0],[3,0]]
```每个人都期望前面没有更高或同等的人。 

这迫使每个新插入的高个子都排在队列的前面。 

插入逻辑自然会处理这个问题，因为每次插入都发生在索引处`0`。 

### 身材矮小的人迟到

 个子矮的人往往需要大的`k`价值观，因为许多更高的人站在他们面前。 

例如：```
[[7,0],[6,1],[5,2],[4,3]]
```如果较早处理矮个子的人，那么随着较高的人的插入，他们的计数随后会发生变化。 

该算法通过首先处理较高的人来完全避免这个问题，确保稍后插入较短的人不会影响较高的人的约束。
