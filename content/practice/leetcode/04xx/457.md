[LeetCode 第 457 题](https://leetcode.com/problems/circular-array-loop/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、两个指针

 ## 解决方案

 ## 问题理解

 本题要求我们判断一个圆形数组在特定的运动规则下是否包含有效的循环。 数组中的每个元素代表我们距离当前索引多远。 正数向前移动，负数向后移动，由于数组是循环的，因此移动会回绕。 

关键要求是有效循环必须满足两个条件：

 1. 循环中的每个动作必须朝同一方向进行。 所有值必须为正值或全部为负值。 
2. 周期长度必须大于1。 指向自身的单个元素不算数。 

输入数组`nums`包含非零整数。 由于数组是循环的，移动到最后一个索引后会回到开头，移动到索引之前`0`循环到最后。 

例如，在数组中`[2, -1, 1, 2, 2]`:

 - 从索引开始`0`， 移动`2`建立索引的步骤`2`- 来自索引`2`， 移动`1`步骤到索引`3`- 来自索引`3`， 移动`2`建立索引的步骤`0`这就形成了循环`0 -> 2 -> 3 -> 0`，并且涉及的每个值都是正数，所以答案是`true`。 

约束条件很重要：

 -`nums.length <= 5000`- 值介于`-1000`和`1000`- 没有值为零

 后续要求`O(n)`时间和`O(1)`额外的空间，这强烈建议我们应该避免重复地重新访问相同的索引，并避免在每次遍历时使用额外的数据结构，例如哈希集。 

一些边缘情况很重要：

 - 索引等自循环`i`指向自身是无效的，因为循环长度必须超过 1。 
- 中途改变方向的路径无效。 
- 仅包含一个元素的数组永远不能包含有效的循环。 
- 大的跳转值仍必须使用模算术正确换行。 
- 必须仔细实施负模处理。 

## 方法

 ### 蛮力方法

 蛮力策略是尝试每一个指标作为起点，逐步模拟运动。 

对于每个起始索引：

 1. 跟踪本次遍历的访问索引。 
2. 从起始值确定所需的方向。 
3. 继续移动，同时：

 - 方向保持一致
 - 我们还没有重新审视索引
 4. 如果我们重新访问本次遍历中已经见过的索引，请检查循环长度是否大于 1。 

这种方法之所以有效，是因为它明确地探索每条可达路径并验证所有循环条件。 

然而，它的效率很低，因为许多遍历重复访问相同的索引。 在最坏的情况下，每个起始位置可能几乎遍历整个数组。 

这导致`O(n²)`时间复杂度。 

### 最佳方法

 最佳解决方案使用弗洛伊德周期检测算法，也称为龟兔赛跑技术。 

重要的见解是，数组可以被视为有向图，其中每个索引恰好指向下一个索引。 

循环检测自然适合 Floyd 算法：

 - 缓慢的指针一次移动一步
 - 快速指针一次移动两步
 - 如果它们相遇，则存在循环

 但是，我们必须添加额外的验证，因为并非每个图周期都对这个问题有效。 

我们必须确保：

 1.所有运动保持同一方向
 2. 周期长度大于1

 达到`O(n)`总体复杂性，我们还通过将遍历的元素设置为来标记已访问的路径`0`。 由于输入保证原始值不为零，因此零成为安全标记，表明索引已被处理并且无法促成有效循环。

 ## 算法演练

 1. 迭代数组中的每个索引。 

每个索引都可能属于一个有效的循环，因此我们必须检查所有未处理的位置。 
2. 跳过已标记为的索引`0`。 

我们使用`0`作为已被证明无法形成有效周期的指数的标记。 由于原始值永远不会为零，因此这是安全的。 
3. 确定运动方向。 

如果`nums[i] > 0`，遍历方向为正向。 否则就是落后了。 
4. 初始化慢指针和快指针。 

两个指针都从当前起始索引开始。 
5. 在移动保持有效的情况下推进指针。 

仅当满足以下条件时，运动才有效：

 - 下一个索引保持相同的方向
 - 遍历没有遇到零标记

 慢速指针前进一步。 

快速指针前进两步。 
6. 检查慢指针和快指针是否相遇。 

如果它们相遇，则可能存在循环。 
7.拒绝自循环。 

如果从交汇点开始的下一个索引与本身相同，则循环长度为 1，这是无效的。 
8. 返回`true`如果找到有效的循环。 

一旦检测到非平凡的同向循环，问题就解决了。 
9. 如果不存在有效循环，则将遍历路径标记为已访问。 

从当前索引开始，在方向保持一致的情况下继续沿着路径走，将每个访问过的元素设置为`0`。 

这确保了未来的遍历不会重复相同的工作。 
10. 继续，直到处理完所有索引。 

如果处理整个数组后没有找到有效循环，则返回`false`。 

### 为什么它有效

 弗洛伊德算法保证，如果有向图中存在环，则慢指针和快指针最终会相遇。 附加方向检查确保只有具有一致运动方向的循环才被视为有效。 自循环检查不包括长度为 1 的循环。 最后，将失败路径标记为零可以保证每个索引最多处理一次，从而确保线性时间复杂度。 

## Python 解决方案```python
from typing import List

class Solution:
    def circularArrayLoop(self, nums: List[int]) -> bool:
        n = len(nums)

        def next_index(current: int) -> int:
            return (current + nums[current]) % n

        for i in range(n):
            if nums[i] == 0:
                continue

            direction = nums[i] > 0

            slow = i
            fast = i

            while True:
                next_slow = next_index(slow)

                if nums[next_slow] == 0 or (nums[next_slow] > 0) != direction:
                    break

                next_fast = next_index(fast)

                if nums[next_fast] == 0 or (nums[next_fast] > 0) != direction:
                    break

                next_fast = next_index(next_fast)

                if nums[next_fast] == 0 or (nums[next_fast] > 0) != direction:
                    break

                slow = next_slow
                fast = next_fast

                if slow == fast:
                    if slow == next_index(slow):
                        break

                    return True

            current = i

            while nums[current] != 0 and (nums[current] > 0) == direction:
                next_pos = next_index(current)
                nums[current] = 0
                current = next_pos

        return False
```实现首先定义一个辅助函数`next_index`，它计算下一个位置，同时使用模算术正确处理循环环绕。 

主循环迭代每个索引。 如果索引已被标记为`0`，它被跳过，因为它已经被完全处理。 

对于每个未处理的索引，算法根据当前值的符号确定遍历方向。 

然后初始化慢指针和快指针。 在循环内部，仅当保持方向一致性时，两个指针才会移动。 这可以防止考虑无效的混合方向循环。 

当慢指针和快指针相遇时，算法检查循环长度是否大于 1。 通过验证下一个索引是否等于当前索引来拒绝自循环。 

如果从当前开始没有找到有效的循环，则通过将所有可到达的同向节点标记为来清理遍历路径`0`。 这可以防止重复工作并保证线性运行时间。 

## 解决方案```go
func circularArrayLoop(nums []int) bool {
	n := len(nums)

	nextIndex := func(current int) int {
		return ((current + nums[current]) % n + n) % n
	}

	for i := 0; i < n; i++ {
		if nums[i] == 0 {
			continue
		}

		direction := nums[i] > 0

		slow := i
		fast := i

		for {
			nextSlow := nextIndex(slow)

			if nums[nextSlow] == 0 || (nums[nextSlow] > 0) != direction {
				break
			}

			nextFast := nextIndex(fast)

			if nums[nextFast] == 0 || (nums[nextFast] > 0) != direction {
				break
			}

			nextFast = nextIndex(nextFast)

			if nums[nextFast] == 0 || (nums[nextFast] > 0) != direction {
				break
			}

			slow = nextSlow
			fast = nextFast

			if slow == fast {
				if slow == nextIndex(slow) {
					break
				}

				return true
			}
		}

		current := i

		for nums[current] != 0 && (nums[current] > 0) == direction {
			nextPos := nextIndex(current)
			nums[current] = 0
			current = nextPos
		}
	}

	return false
}
```Go 的实现与 Python 解决方案非常相似。 一个重要的区别是模处理。 Go 可以产生负模结果，因此表达式：```go
((current + nums[current]) % n + n) % n
```确保最终索引始终为非负数。 

直接使用Go切片，没有分配额外的内存结构，保留了`O(1)`空间要求。

        n = len(nums)

        def next_index(current: int) -> int:
            return (current + nums[current]) % n

        for i in range(n):
            if nums[i] == 0:
                continue

            direction = nums[i] > 0

            slow = i
            fast = i

            while True:
                next_slow = next_index(slow)

                if nums[next_slow] == 0 or (nums[next_slow] > 0) != direction:
                    break

                next_fast = next_index(fast)

                if nums[next_fast] == 0 or (nums[next_fast] > 0) != direction:
                    break

                next_fast = next_index(next_fast)

                    break

                slow = next_slow
                fast = next_fast

                if slow == fast:
                    if slow == next_index(slow):
                        break

                    return True

            current = i

                next_pos = next_index(current)
                nums[current] = 0
                current = next_pos

 ## 边缘情况

 ### 自循环

 错误的一个主要来源是将指向自身的单个索引视为有效循环。 例如：```
[1]
```指数`0`立即移回自身。 尽管这在技术上形成了图论中的循环，但该问题明确要求循环长度大于一。 

该实现通过以下方式处理此问题：```
if slow == next_index(slow):
    break
```这会拒绝所有自循环。 

### 方向改变

 当移动方向在遍历内改变时，会发生另一种棘手的情况。 

例如：```
[1, -1]
```指数`0`前进到索引`1`，但索引`1`向后移动。 这违反了同向要求。 

该实现在每次指针移动之前验证方向：```
(nums[next_index] > 0) == direction
```如果符号改变，则遍历立即停止。 

### 大圆形包裹

 大的跳转可能会多次环绕数组。 

例如：```
[7, 1, 1, 1, 1]
```由于数组长度是`5`, 移动`7`有效的步骤意味着移动`2`步骤。 

该实现使用模算术安全地处理包装：```
(current + nums[current]) % n
```这保证了下一个索引始终保持在有效范围内。
