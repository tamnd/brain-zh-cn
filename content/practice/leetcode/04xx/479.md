 # 最大的回文积

 ## 问题理解

 该问题要求我们找到可以写成两个的乘积的最大回文数`n`-数字整数。 

回文是向前和向后读相同的数字。 例如，`9009`是一个回文，因为反转它的数字仍然给出`9009`。 

输入是单个整数`n`， 在哪里`n`表示每个被乘数的位数。 例如：

 - 如果`n = 2`，有效数字范围为`10`到`99`- 如果`n = 3`，有效数字范围为`100`到`999`我们必须寻找最大的回文，可以表示为：$$a \times b$$两者都在哪里`a`和`b`是`n`-数字整数。 

这个问题并不要求我们返回回文本身。 相反，我们返回：$$\text{palindrome} \bmod 1337$$存在这种模量要求是因为对于较大的值，回文可能变得非常大`n`。 

约束条件是：

 -`1 <= n <= 8`这个上限非常重要。 一个简单的暴力解决方案需要检查数字的乘积`99,999,999`，这在计算上是不可行的。 

一个重要的观察是搜索空间呈二次方增长：$$(10^n)^2$$为了`n = 8`，这变得巨大，所以我们需要一个更明智的策略。 

有几个重要的边缘情况：

 -`n = 1`很特别，因为最大的回文就是`9`- 非常大的回文可能会超过 32 位整数限制，因此像 Go 这样的语言必须使用 64 位整数
 - 重复数百万次的简单回文检查变得极其昂贵
 - 最大回文数不一定是最大回文数的平方`n`- 位数

 该问题保证了`n`始终有效且在允许的范围内。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成两个的所有可能的乘积`n`- 位数字并检查乘积是否是回文。 

例如，当`n = 2`，我们会迭代：

 -`99 * 99`-`99 * 98`-`99 * 97`- 等等

 对于每个产品：

 1. 将数字转换为字符串
 2. 反转字符串
 3、与原版对比
 4. 追踪找到的最大回文数

 这种方法是正确的，因为它检查了每对可能的`n`- 数字。 最终，它会遇到最大的有效回文。 

然而，时间复杂度太大了。 

为了`n = 8`，大约有：$$(9 \times 10^7)^2$$配对来检查，这是完全不切实际的。 

蛮力方法还浪费了大量的工作来检查非回文数。 

### 最佳方法

 关键的见解是，我们可以直接生成回文，而不是生成产品并检查它们是否是回文。 

这大大减少了搜索空间。 

假设我们通过取一个数字并附加其逆序来构造回文：

 -`91 -> 9119`-`900 -> 900009`如果我们从最大到最小生成回文，那么第一个回文可以分解为两个`n`- 数字必须是答案。 

第二个主要见解是因素检查。 

如果是回文`p`可以写成：$$p = a \times b$$那么一个因素必须至少是：$$\sqrt{p}$$所以我们只需要从最大的向下查找约数即可`n`- 数字。 

这将不可能的强力搜索变成了可管理的枚举问题。 

## 方法比较

 | --- | --- | --- | --- |

 ## 算法演练

 ### 第 1 步：处理特殊情况

 如果`n == 1`， 返回`9`。 

两个 1 位数的最大乘积是：$$9 \times 9 = 81$$最大的回文积是：$$9 = 9 \times 1$$和：$$9 \bmod 1337 = 9$$### 步骤 2：确定最大和最小的 n 位数字

 计算：

 -`upper = 10^n - 1`-`lower = 10^(n - 1)`为了`n = 2`:

 -`upper = 99`-`lower = 10`这些界限定义了有效因子范围。 

### 步骤 3：从大到小生成回文

 开始于`left = upper`。 

通过以下方式构造回文：

 1. 转换`left`到一个字符串
 2. 逆转
 3. 附加反向

 例如：

 -`left = 99`- 反向=`99`- 回文=`9999`然后：

-`left = 98`- 回文=`9889`这保证了降序回文顺序。 

### 步骤 4：搜索有效因素

 对于每个回文：

 1. 起始除数`d = upper`2. 虽然`d * d >= palindrome`3. 检查是否`palindrome % d == 0`如果可整除：$$other = palindrome / d$$然后验证：

 -`other >= lower`-`other <= upper`如果为真，则两个因素均有效`n`- 数字。 

### 步骤 5：返回模数

 一旦找到第一个有效的回文：$$return palindrome \bmod 1337$$由于回文是按降序生成的，因此第一个有效的回文保证是最大的。 

### 为什么它有效

 该算法从最大到最小生成回文。 对于每个回文，它检查回文是否有两个有效的`n`- 数字因素。 

由于每个较大的回文数都会先于较小的回文数进行检查，因此满足分解条件的第一个回文数必须是最大有效答案。 

除数搜索是正确的，因为任何因子对必须包含至少与回文的平方根一样大的因子。 因此，检查除数到该边界可以保证我们不会错过任何有效的因式分解。 

## Python 解决方案```python
class Solution:
    def largestPalindrome(self, n: int) -> int:
        if n == 1:
            return 9

        upper = 10 ** n - 1
        lower = 10 ** (n - 1)

        for left in range(upper, lower - 1, -1):
            palindrome = int(str(left) + str(left)[::-1])

            divisor = upper

            while divisor * divisor >= palindrome:
                if palindrome % divisor == 0:
                    other = palindrome // divisor

                    if lower <= other <= upper:
                        return palindrome % 1337

                divisor -= 1

        return -1
```实施从特殊情况开始`n == 1`，因为这个案例有一个已知的直接答案。 

接下来，代码计算有效的上限和下限`n`- 数字。 

外层循环按降序生成回文。 该代码没有测试每个产品，而是通过镜像左半部分直接构造候选回文。 

对于每个回文，内循环搜索有效的除数。 条件：```python
divisor * divisor >= palindrome
```确保我们只搜索直到平方根边界。 

当找到整除性时，通过整数除法计算配对因子。 如果两个因子都在有效范围内，则回文满足问题要求，我们立即返回模结果。 

该算法提前终止，因为回文是从最大到最小生成的。 

## 解决方案```go
package main

import (
	"strconv"
)

func largestPalindrome(n int) int {
	if n == 1 {
		return 9
	}

	upper := intPow(10, n) - 1
	lower := intPow(10, n-1)

	for left := upper; left >= lower; left-- {
		palindrome := buildPalindrome(left)

		for divisor := upper; divisor*divisor >= palindrome; divisor-- {
			if palindrome%divisor == 0 {
				other := palindrome / divisor

				if other >= lower && other <= upper {
					return palindrome % 1337
				}
			}
		}
	}

	return -1
}

func buildPalindrome(x int) int {
	s := strconv.Itoa(x)
	reversed := reverseString(s)

	value, _ := strconv.Atoi(s + reversed)
	return value
}

func reverseString(s string) string {
	runes := []rune(s)

	for i, j := 0, len(runes)-1; i < j; i, j = i+1, j-1 {
		runes[i], runes[j] = runes[j], runes[i]
	}

	return string(runes)
}

func intPow(base int, exp int) int {
	result := 1

	for exp > 0 {
		result *= base
		exp--
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个重要的区别是整数处理。 Go 使用固定宽度整数，因此使用`int`这里是安全的，因为最大回文数`n <= 8`仍然适合现代系统的 64 位整数范围。 

与 Python 不同，Go 没有内置的字符串反转实用程序，因此在构造回文时使用辅助函数来反转字符串表示形式。 

Go 也不提供内置的整数求幂运算符，因此需要一个小的辅助函数来计算 10 的幂。

 ## 边缘情况

 ### 边缘情况 1：`n = 1`这是最重要的特殊情况。 用于较大值的回文生成策略仅创建偶数长度的回文，例如`9009`或者`9889`。 

为了`n = 1`，正确答案是个位数回文`9`。 

如果不明确处理这种情况，算法将无法返回正确的结果。 

该实现立即解决了这个问题：```
if n == 1:
    return 9
```### 边缘案例 2：非常大的产品

 对于`n = 8`，回文可以变得非常大。 使用 32 位整数的简单实现可能会溢出。 

Python 版本自然地处理这个问题，因为 Python 整数具有任意精度。 

Go 解决方案依赖于现代 64 位整数支持，它可以安全地容纳所需的值。 

### 边缘情况 3：无早期除数剪枝

 简单的除数搜索可能会检查所有可能的除数`1`。 

这是不必要的，因为一旦：$$d^2 < palindrome$$所有剩余的因子对都已经以相反的顺序进行了检查。 

该实施避免了冗余工作：```
while divisor * divisor >= palindrome:
```这种优化显着提高了性能，对于更大的值至关重要`n`。
