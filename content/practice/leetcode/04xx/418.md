[LeetCode 第 418 题](https://leetcode.com/problems/sentence-screen-fitting/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个具有固定数量的屏幕`rows`和`cols`，以及表示为单词数组的句子。 我们需要确定句子可以在屏幕上完整书写多少次，同时遵循严格的格式规则。 

句子必须从左到右、从上到下书写。 单词必须保持其原始顺序，并且每对相邻单词之间必须恰好有一个空格。 一个单词不能跨行分割。 如果某个单词不能完全放入当前行的剩余列中，则必须将其完全移动到下一行。 

输出是处理所有行后屏幕上可以容纳的句子的完整重复次数。 

例如，如果句子是：```
["hello", "world"]
```屏幕是：```
2 rows x 8 cols
```然后：```
hello---
world---
```完全符合该句子的完整重复。 

这些约束很重要，因为它们决定了我们应该使用的解决方案类型：

 - 行数和列数可以分别为`20,000`- 该句子最多可包含`100`话
 - 每个单词长度最多`10`单独处理每个单元的简单模拟可能会变得太慢。 在最坏的情况下，有`20,000 * 20,000 = 400,000,000`屏幕位置对于有效的解决方案来说太大了。 

有几个重要的边缘情况需要考虑：

 - 一个单词可能正好填满一行的剩余列
 - 部分填充一行后，单词可能太长而无法容纳，从而强制换行
 - 该句子可能在一行内重复多次
 - 句子可能只包含一个单词
 - 屏幕可能非常窄
 - 屏幕可能非常大，需要优化方法而不是逐个字符模拟

 该问题保证每个单词的长度最多为`10`，但它并没有明确保证每个单词都适合`cols`。 如果一个单词比列数长，则任何句子都无法容纳，所以答案是`0`。 

## 方法

 ### 蛮力方法

 最直接的做法就是逐行、逐字地模拟书写过程。 

对于每一行：

 1. 从当前单词索引开始。 
2. 尝试将单词放入剩余的列中。 
3. 如果这个词合适：

 - 从剩余空间中减去其长度
 - 如果还有更多空间，请添加一个额外空间
 - 移至下一个单词
 4. 每当我们回到第一个单词时，就增加已完成的句子数。 
5. 继续，直到当前行无法容纳更多单词。 

这种方法是正确的，因为它完全遵循问题陈述中描述的放置规则。 

然而，当屏幕很大时，它可能会变得低效。 在最坏的情况下，我们可能会为每一行重复处理相同的单词位置。 由于行和列都可以达到`20,000`，重复模拟变得不必要的昂贵。 

### 最佳方法的关键见解

 关键的观察是该句子总是以相同的循环顺序重复。 

我们可以将整个句子视为一个连续的字符串，而不是每次都单独处理单词：```
"hello world "
```注意尾随空格。 这使得重复变得更容易，因为每个单词自然地与下一个重复分开。 

现在想象一下，将这个无限循环字符串中的字符重复写入屏幕上。 

对于每一行：

 - 我们努力准确推进`cols`人物
 - 如果我们落在一个空格上，我们可以额外移动一步，因为下一行应该在空格之后开始
 - 如果我们落在单词的中间，我们必须回溯，直到到达前一个空格

 这将问题转化为循环句子字符串内有效的指针移动。 

由于每行仅执行有限的向前和向后调整，因此即使对于大量输入，该解决方案也能高效运行。

 ## 算法演练

 ### 最优算法

 1. 将所有单词连接成一个以空格分隔的字符串，并在末尾添加一个空格。 

例如：```
["hello", "world"]
```变成：```
"hello world "
```尾随空格很重要，因为它清楚地分隔了句子的重复副本。 
2. 存储该组合字符串的总长度。 

为了：```
"hello world "
```长度是`12`。 
3. 维护一个名为`position`。 

该指针表示到目前为止，无限重复句子中有多少个字符已被放置到屏幕上。 
4. 独立处理每一行。 

对于每一行：

 - 将指针前进`cols`- 这假设我们乐观地填充整行
 5. 检查指针所指向的字符。 

有两种可能：

 - 如果当前字符是空格：

 - 一行人在一句话后就结束了
 - 再向前移动一个位置以在空格后开始下一行
 - 否则：

 - 指针落在单词中间
 - 向后移动直到前一个字符是空格
 - 这确保单词永远不会跨行分割
 6. 对所有行重复此过程。 
7. 处理完所有行后，将总指针位置除以句子长度。 

由于句子循环重复，因此句子串的每次完整遍历都对应于一个完整的句子位置。 

答案是：```
position // sentence_length
```### 为什么它有效

 该算法保持了每行都从单词的开头开始并且每行仅包含完整单词的不变性。 前进通过`cols`模拟填充行，而向后调整保证单词永远不会拆分。 由于句子串循环重复，因此完整句子遍历的总数等于句子在屏幕上适合的次数。 

## Python 解决方案```python
from typing import List

class Solution:
    def wordsTyping(self, sentence: List[str], rows: int, cols: int) -> int:
        sentence_string = " ".join(sentence) + " "
        sentence_length = len(sentence_string)

        position = 0

        for _ in range(rows):
            position += cols

            if sentence_string[position % sentence_length] == " ":
                position += 1
            else:
                while (
                    position > 0
                    and sentence_string[(position - 1) % sentence_length] != " "
                ):
                    position -= 1

        return position // sentence_length
```该实现首先构造一个带有尾随空格的循环句子字符串。 这允许重复遍历而无需对句子边界进行特殊处理。 

变量`position`跟踪所有行消耗了多少个字符。 对于每一行，算法首先假设所有`cols`可以填充字符。 

前进后，代码检查当前位置是否落在空格上。 如果是，则该行在字边界处完美结束，因此下一行可以在空格之后立即开始。 

如果指针落在单词内，则`while`循环向后移动，直到前一个字符变成空格。 这保证了单词永远不会跨行拆分。 

最后，整数除以句子长度计算出遍历了多少个完整的句子循环。 

## 解决方案```go
func wordsTyping(sentence []string, rows int, cols int) int {
	sentenceString := ""
	for _, word := range sentence {
		sentenceString += word + " "
	}

	sentenceLength := len(sentenceString)
	position := 0

	for i := 0; i < rows; i++ {
		position += cols

		if sentenceString[position%sentenceLength] == ' ' {
			position++
		} else {
			for position > 0 &&
				sentenceString[(position-1)%sentenceLength] != ' ' {
				position--
			}
		}
	}

	return position / sentenceLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 Go 中的字符串使用字节进行索引，这在这里是安全的，因为问题只保证小写英文字母。 

Go 没有 Python 内置的切片字符串连接语法，因此句子字符串是使用连接手动构造的。 

Go 中的整数除法自然会截断为零，这给出了完整句子重复的正确数量。

 ## 边缘情况

 当字长超过列数时，就会出现一种重要的边缘情况。 在这种情况下，该单词永远无法容纳在任何行中，这意味着该句子甚至无法显示一次。 幼稚的实现可能会在反复尝试放置过大的单词时进入无限循环。 当前的实现自然地处理了这个问题，因为指针调整反复回溯并防止无效的放置，最终产生零个完整句子。 

当行恰好在字边界处结束时，会发生另一种棘手的情况。 如果算法未正确移过尾随空格，则下一行可能会错误地以空格或重复单词开头。 该实现在指针前进后显式检查空格并增加一个额外位置以确保下一行正确开始。 

第三种边缘情况涉及极大的屏幕尺寸。 和`rows`和`cols`每个潜在达到`20,000`，低效的模拟方法可能会超时。 优化的解决方案避免了逐个字符的屏幕构造，而是仅跟踪循环句子字符串中的单个指针，从而使其即使对于最大的输入也能有效扩展。
