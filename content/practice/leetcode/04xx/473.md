 # LeetCode 473 - 火柴棒到正方形

 ## 问题理解

 问题给了我们一个名为`matchsticks`，其中每个元素代表火柴棍的长度。 目标是确定所有火柴棍是否可以恰好排列成一个正方形。 

正方形有四个相等的边，因此所有火柴棒的总长度必须能被 4 整除。每根火柴棒必须只能使用一次，并且不得将任何火柴棒折成更小的碎片。 我们可以将多根棍子组合在一起形成一面。 

换句话说，我们尝试将数组分为四组，以便：

 - 每根火柴都属于一个组
 - 每组的总和相同
 - 该共同总和等于总长度的四分之一

 输入尺寸很小，最多 15 根火柴。 这是一个重要的观察结果，因为它表明如果仔细优化，指数算法仍然可能是可行的。 简单的暴力解决方案仍然太昂贵，但通过修剪进行回溯在这种规模下变得实用。 

一些边缘情况非常重要：

 - 如果总和不能被 4 整除，则不可能形成正方形。 
- 如果最大的火柴棒比目标边长长，则答案一定是错误的。 
- 如果算法未优化，具有许多重复值的数组可能会产生大量重复工作。 
- 由于每根棍子必须只使用一次，因此留下未使用的棍子的部分解决方案无效。 

这些约束强烈表明预期的解决方案使用回溯、递归、修剪或位掩码技术。 

## 方法

 ### 蛮力方法

 一个简单的暴力解决方案将尝试将火柴棒分配给四个面的所有可能的分配方式。 对于每根火柴棒，我们可以选择四个面之一并递归地继续，直到放置完所有火柴棒。 

这保证了正确性，因为每种可能的排列都会被探索。 如果存在有效的方块，蛮力最终会找到它。 

然而，这种方法极其昂贵。 每根棍子有四种放置选择，因此可能性总数约为：$4^n$如果有最多 15 根火柴，则结果为：$4^{15}=1073741824$超过十亿的可能性对于实际执行来说太大了。 

蛮力方法还浪费大量时间探索明显无效的状态，例如边已经超过目标长度。 

### 通过剪枝优化回溯

 关键的见解是我们不需要盲目地探索每一种可能的安排。 由于所有四个边必须具有相同的长度，因此我们可以尽早积极地修剪无效状态。 

优化策略包括几个重要的观察结果：

 - 总和必须能被 4 整除。 
- 施工期间任何边均不得超过目标长度。 
- 按降序对火柴棍进行排序可以让大火柴棍提前失效。 
- 如果两侧当前长度相同，则将当前棒放入任一侧会导致相同的状态，因此可以跳过重复的工作。 

我们不是生成每个配置，而是逐步构建四个边，同时立即放弃不可能的路径。 

这将搜索空间转变为易于管理的空间`n <= 15`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^n) | O(4^n) | O(n) | 尝试每一种棍棒分配方式 |
 | 最佳 | O(4^n) 最坏情况，大量修剪 | O(n) | 通过排序和修剪进行回溯可大大减少实际运行时间 |

 ## 算法演练

 1. 计算所有火柴棒的总和。 

正方形有四个相等的边，因此总和必须能被 4 整除。如果不能被 4 整除，我们立即返回`False`。 
2. 计算目标边长。 

目标长度为：$\text{target}=\frac{\sum matchsticks}{4}$每一方最终都必须等于该值。 
3. 将火柴棒按降序排列。 

较大的火柴棍更难放置。 通过先处理它们，无效的配置很快就会失败，从而大大提高了剪枝效率。 
4. 初始化一个代表四个边的数组。 

我们维持：```
sides = [0, 0, 0, 0]
```每个值存储一侧的当前长度。 
5. 开始递归回溯。 

在每个递归步骤中，我们尝试将当前火柴棒放入四个侧面之一。 
6. 跳过无效展示位置。 

在将火柴棒放入一侧之前，请检查是否：```
sides[i] + matchsticks[index] <= target
```如果边超过目标长度，则该放置是不可能的，应立即跳过。 
7. 放置后递归。 

如果放置有效：

 - 将棍子添加到侧面
 - 递归放置下一根棍子
 - 如果递归成功，则返回`True`- 否则通过移除棍子原路返回
 8. 避免重复状态。 

如果两侧当前具有相同的长度，则将当前棒放入任一侧会创建对称状态。 

为了避免多余的探索：```
if sides[i] == sides[i - 1]:
    continue
```9. 基本情况。 

当所有火柴都放置成功后，返回`True`。 
10.如果所有可能性均失败，则返回`False`。 

### 为什么它有效

 该算法系统地探索了在四边之间分配火柴棍的每一种有效方法，同时立即修剪不可能的状态。 

递归期间保持的不变量是任何边都不会超过目标长度。 由于每根棍子都被放置一次，并且总和等于目标长度的四倍，因此到达递归末尾可以保证所有四个边都等于目标长度。 

因为每个有效的配置要么被探索，要么被安全地修剪，所以该算法是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def makesquare(self, matchsticks: List[int]) -> bool:
        total_length = sum(matchsticks)

        if total_length % 4 != 0:
            return False

        target = total_length // 4

        matchsticks.sort(reverse=True)

        if matchsticks[0] > target:
            return False

        sides = [0] * 4

        def backtrack(index: int) -> bool:
            if index == len(matchsticks):
                return True

            current_stick = matchsticks[index]

            for side_index in range(4):
                if sides[side_index] + current_stick > target:
                    continue

                if side_index > 0 and sides[side_index] == sides[side_index - 1]:
                    continue

                sides[side_index] += current_stick

                if backtrack(index + 1):
                    return True

                sides[side_index] -= current_stick

            return False

        return backtrack(0)
```该实现首先计算所有火柴棒的总长度。 如果总和不能被四整除，则在数学上不可能形成平方。 

接下来，计算目标边长。 火柴棒按降序排列，因此首先处理大的火柴棒。 这显着改善了修剪，因为更早地发现了不可能的状态。 

这`sides`数组在递归进行时跟踪每条边的当前长度。 

递归`backtrack`函数尝试将当前火柴棒一根一根地放入每一侧。 在放置之前，算法会检查添加棍子是否会超过目标长度。 无效的展示位置将被立即跳过。 

重复状态优化尤其重要。 如果两侧当前具有相同的长度，则尝试两侧会导致对称递归状态。 跳过重复项会极大地减少搜索空间。 

如果递归分支成功，函数立即返回`True`。 否则，算法会通过移除棍子并尝试另一个放置位置来回溯。 

当所有火柴棒都放置成功后，算法返回`True`。 

## 解决方案```go
package main

import "sort"

func makesquare(matchsticks []int) bool {
	totalLength := 0

	for _, stick := range matchsticks {
		totalLength += stick
	}

	if totalLength%4 != 0 {
		return false
	}

	target := totalLength / 4

	sort.Sort(sort.Reverse(sort.IntSlice(matchsticks)))

	if matchsticks[0] > target {
		return false
	}

	sides := make([]int, 4)

	var backtrack func(int) bool

	backtrack = func(index int) bool {
		if index == len(matchsticks) {
			return true
		}

		currentStick := matchsticks[index]

		for sideIndex := 0; sideIndex < 4; sideIndex++ {
			if sides[sideIndex]+currentStick > target {
				continue
			}

			if sideIndex > 0 && sides[sideIndex] == sides[sideIndex-1] {
				continue
			}

			sides[sideIndex] += currentStick

			if backtrack(index + 1) {
				return true
			}

			sides[sideIndex] -= currentStick
		}

		return false
	}

	return backtrack(0)
}
```Go 的实现与 Python 版本非常相似。 主要区别在于 Go 需要显式的切片初始化和函数声明。 

递归函数是使用闭包定义的，因此它可以访问`sides`,`target`， 和`matchsticks`直接传递，无需重复传递。 

Go 切片的行为与动态数组类似，使它们适合跟踪边长。 由于这个问题的最大可能总和仍然在 Go 的整数限制范围内，因此整数溢出不是问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(4^n) worst case | 每根棍子都可以在四个侧面进行尝试 |
 | 空间| O(n) | 递归调用栈深度可达`n`|

 尽管理论上最坏情况的复杂性仍然是指数级的，但修剪极大地减少了实际的搜索空间。 按降序对火柴棍进行排序和跳过对称状态是使解决方案足够高效的主要优化`n <= 15`。

 ## 边缘情况

 当总和不能被四整除时，就会出现一种重要的边缘情况。 由于正方形需要四个相等的边，因此任何余数都会立即使该任务变得不可能。 跳过此检查的简单实现会浪费时间探索永远不会成功的递归状态。 该实现通过返回来处理这个问题`False`before recursion begins.

 当最大的火柴棒超过目标边长时，会发生另一种关键的边缘情况。 例如：```
[10,1,1,1,1,1,1,1]
```即使总和可能被四整除，长度的棍子`10`永远不能装入小于`10`。 该解决方案在排序后检测到这一点并立即终止。 

第三个重要的边缘情况涉及许多重复值，例如：```
[2,2,2,2,2,2,2,2]
```如果没有重复状态修剪，递归将重复探索等效的对称配置。 优化：```
if sides[i] == sides[i - 1]:
    continue
```防止这种多余的工作并显着提高效率。 

当火柴棍很少时，就会发生另一种微妙的情况。 例如：```
[1]
```总和不能被四整除，因此算法安全地返回`False`立即地。 这可以防止对所需的最小棒数做出无效假设。 

最后，在某些语言中，极大的火柴棒值可能会暴露整数处理问题。 Python 自然地处理任意大小的整数，而 Go 的整数范围足以满足给定的约束，因此两种实现都安全地支持最大允许值。
