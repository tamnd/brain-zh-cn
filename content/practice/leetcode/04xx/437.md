[LeetCode 第 437 题](https://leetcode.com/problems/path-sum-iii/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题给出了二叉树的根和一个整数`targetSum`。 我们需要计算树中有多少条向下路径的值加起来正好等于`targetSum`。 

路径可以从任何节点开始并在任何节点结束，只要它始终从父节点向下移动到子节点即可。 这是一个重要的区别，因为我们不限于从根开始或以叶子结束的路径。 树中的每个节点都可以作为有效路径的起点。 

例如，考虑如下路径：```
5 -> 3
```如果这些值的总和等于目标，则即使路径不是从根开始，它也算在内。 

输入是标准二叉树，其中每个节点包含：

 - 整数值
 - 一个左孩子
 - 一个正确的孩子

 输出是一个整数，表示有效向下路径的总数，其总和等于`targetSum`。 

约束条件很重要：

 - 树最多包含 1000 个节点
 - 节点值可以为负数
 - 目标值也可以是负数

 负数的存在意味着我们不能使用滑动窗口或贪婪剪枝等技术。 当前超出目标的路径可能会在添加负值后变得有效。 因此，我们需要一种更通用的方法。 

一些边缘情况立即脱颖而出：

 - 应该返回一棵空树`0`- 包含负数的树可能会创建许多重叠的有效路径
 - 单个节点本身可能等于目标
 - 多条路径可以重叠并共享节点
 - 较大的正值和负值意味着我们必须依靠精确的算术而不是启发法

 这些特征强烈表明这从根本上来说是一个前缀和和 DFS 问题。 

## 方法

 ### 蛮力方法

 暴力策略是将每个节点视为潜在的起点。 对于每个节点，我们递归地探索从该节点开始的所有向下路径，并计算有多少条路径产生目标总和。 

该算法的工作原理如下：

 1. 从树中的每个节点启动 DFS。 
2. 在每次 DFS 遍历期间，记录所需的剩余金额。 
3. 如果任何节点的剩余总和变为零，则增加答案。 
4. 继续探索左孩子和右孩子。 

这种方法是正确的，因为它明确地检查树中每个可能的向下路径。 

然而，它的效率很低，因为许多路径被重复重新计算。 如果树有`N`节点，那么对于每个节点，我们可以遍历它下面的几乎整个子树。 

在最坏的情况下，例如倾斜的树，这会导致`O(N^2)`时间复杂度。 

### 最佳方法

 关键的见解是这个问题类似于数组的经典“子数组和等于 k”问题。 

我们可以在遍历树时跟踪前缀和，而不是单独重新计算每条路径。 

认为：

-`currentSum`是从根到当前节点的总和
 - 我们之前遇到过前缀和`currentSum - targetSum`那么这两点之间的值之和必须为`targetSum`。 

这是有效的，因为：```
currentSum - previousPrefixSum = targetSum
```重新排列：```
previousPrefixSum = currentSum - targetSum
```因此，在DFS期间，我们维护一个哈希图，用于存储每个前缀和沿着当前遍历路径出现的次数。 

在每个节点：

 - 计算当前前缀和
 - 检查多少次`currentSum - targetSum`已经发生
 - 将计数添加到答案中
 - 在探索子项之前存储当前的前缀和
 - 回溯时将其删除

 这使我们能够计算一次 DFS 遍历中的所有有效路径。

## 算法演练

 ### 最优前缀和DFS算法

 1. 初始化一个名为的哈希图`prefixCount`。 

该映射存储特定前缀和沿着当前根到节点路径出现的次数。 

我们从以下开始：```
prefixCount[0] = 1
```这很重要，因为从根本身开始的路径可能等于`targetSum`。 
2. 从根开始深度优先遍历。 

在遍历的过程中，维护一个名为`currentSum`，表示从根节点到当前节点的所有节点值的总和。 
3. 在每个节点，更新运行前缀和。```
currentSum += node.val
```4. 确定有多少条有效路径终止于当前节点。 

如果我们之前看到前缀和等于：```
currentSum - targetSum
```那么之前的点和当前节点之间的线段总和为`targetSum`。 

我们添加：```
prefixCount[currentSum - targetSum]
```到答案。 
5. 将当前前缀和存储在哈希映射中。 

这允许子节点使用当前节点作为其路径计算的一部分。 
6. 递归地探索左子树和右子树。 

两个子进程都继承更新后的前缀和信息。 
7.处理完children后回溯。 

从映射中删除当前的前缀和：```
prefixCount[currentSum] -= 1
```此步骤至关重要，因为路径必须保留在当前遍历分支内。 如果没有回溯，来自不相关分支的路径可能会错误地组合。 
8. 继续，直到处理完所有节点。 

累计计数即为最终答案。 

### 为什么它有效

 该算法保持不变式`prefixCount`仅包含沿当前根到节点遍历路径的前缀和。 

对于每个节点，我们检查有多少个早期前缀和满足：```
currentSum - previousPrefixSum = targetSum
```每一次这样的出现都对应于一条结束于当前节点的唯一向下路径，其总和等于目标。 

因为每个节点都被访问一次，并且每个有效路径在处理其端点时都被精确计数，所以该算法既完整又正确。 

## Python 解决方案```python
from collections import defaultdict
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        prefix_count = defaultdict(int)
        prefix_count[0] = 1

        def dfs(node: Optional[TreeNode], current_sum: int) -> int:
            if not node:
                return 0

            current_sum += node.val

            paths_found = prefix_count[current_sum - targetSum]

            prefix_count[current_sum] += 1

            paths_found += dfs(node.left, current_sum)
            paths_found += dfs(node.right, current_sum)

            prefix_count[current_sum] -= 1

            return paths_found

        return dfs(root, 0)
```实现首先创建一个名为的哈希图`prefix_count`。 它存储每个前缀和沿着当前 DFS 路径出现的次数。 

该行：```python
prefix_count[0] = 1
```处理直接从根开始的路径。 

嵌套的`dfs`函数执行递归遍历。 每个呼叫都会收到：

 - 当前节点
 - 运行前缀和

 在每个节点：```python
current_sum += node.val
```更新运行总计。 

然后我们确定有多少条有效路径在当前节点结束：```python
paths_found = prefix_count[current_sum - targetSum]
```这是有效的，因为任何较早的前缀总和等于`current_sum - targetSum`创建有效的路径段。 

接下来，我们在遍历children之前记录当前的前缀和：```python
prefix_count[current_sum] += 1
```递归处理完两个子树后，我们回溯：```python
prefix_count[current_sum] -= 1
```这确保兄弟分支不会互相干扰。 

最后，DFS 返回在子树中找到的有效路径的总数。 

## 解决方案```go
package main

/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func pathSum(root *TreeNode, targetSum int) int {
	prefixCount := map[int]int{
		0: 1,
	}

	var dfs func(node *TreeNode, currentSum int) int

	dfs = func(node *TreeNode, currentSum int) int {
		if node == nil {
			return 0
		}

		currentSum += node.Val

		pathsFound := prefixCount[currentSum-targetSum]

		prefixCount[currentSum]++

		pathsFound += dfs(node.Left, currentSum)
		pathsFound += dfs(node.Right, currentSum)

		prefixCount[currentSum]--

		return pathsFound
	}

	return dfs(root, 0)
}
```Go 实现遵循与 Python 解决方案完全相同的算法结构。 

去吧`map[int]int`用来代替Python的`defaultdict(int)`。 缺少的键会自动返回整数零值，这使得逻辑简单明了。 

显式检查 Nil 节点：```go
if node == nil
```Go 整数在这里就足够了，因为现代系统上的约束保持在 64 位限制内，尽管某些实现可能会选择`int64`为了额外的安全。 

递归 DFS 闭包捕获`prefixCount`和`targetSum`，允许干净的状态管理而无需全局变量。

 DFS 遍历对每个节点恰好处理一次，并且每个哈希图操作都是`O(1)`平均而言。 

递归深度等于树的高度。 在平衡树中这是`O(log N)`，而在一棵倾斜的树中，它变成`O(N)`。 

前缀和映射仅存储沿活动递归路径的和，因此其大小受树高度限制。

 ## 边缘情况

 ### 空树

 一棵空树应该立即返回`0`因为根本就没有路。 

如果递归假设每个节点都存在，这种情况很容易导致空引用错误。 该实现通过检查来避免这种情况：```
if not node:
    return 0
```在进行任何处理之前。 

### 负数

 负值尤其重要，因为它们使修剪策略无效。 

例如，路径和可能暂时超过目标，然后由于负节点而减少。 当总和变得太大时提前停止的算法在这里会失败。 

无论正值或负值，前缀和方法都能正确工作，因为它纯粹依赖于累积和之间的算术差异。 

### 从树中间开始的路径

 一个常见的错误是假设路径必须从根开始。 

考虑：```
1
 \
  2
   \
    3
```有目标`5`。 

有效路径是：```
2 -> 3
```前缀和技术自然地处理这个问题，因为它检测沿当前遍历路径的任意两个前缀和之间的有效子路径。 

### 重复的前缀和

 当多个节点产生相同的前缀和时，每次出现都很重要。 

例如，包含许多零的树可以生成重复的前缀和。 如果实现仅存储布尔值而不是计数，则它将错过有效路径。 

使用频率图可确保正确计算所有匹配路径。
