 ## 解决方案

 ## 问题理解

 LeetCode 428，LeetCode Serialize and Deserialize N-ary Tree，要求我们为 N-ary 树设计一个可逆编码系统。 问题不在于要求特定的序列化格式。 相反，它要求我们保证在将树序列化为字符串然后反序列化该字符串之后，我们重建完全相同的树结构。 

N 叉树与二叉树不同，因为每个节点可以有任意数量的子节点，而不仅仅是两个。 每个节点都包含一个值和一个子节点列表。 挑战在于，当我们将树扁平化为字符串时，我们必须保留节点值和父子关系。 

输入到`serialize`是N叉树的根节点。 输出必须是该树的字符串表示形式。 输入到`deserialize`是序列化的字符串，输出必须是重构的根节点。 

这些限制很重要，因为它们决定了哪些方法是实用的。 该树最多可以包含`10^4`节点，这意味着算法在时间复杂度上必须至少是线性的或接近线性的。 高度可以大到`1000`，这意味着如果仔细管理递归限制，递归深度优先遍历在 Python 中是可以接受的，但迭代设计也值得考虑。 编解码器无状态的要求意味着我们不能依赖方法调用之间的全局变量或持久类状态。 

最大的概念挑战是序列化序列必须保留足够的结构信息来重建任意分支。 如果我们只按遍历顺序存储节点值，我们就会丢失有关每个节点有多少个子节点的信息。 因此，序列化格式必须显式编码子边界。 

一些边缘情况尤其重要。 空树必须正确序列化和反序列化。 节点可能有零个子节点，这意味着叶节点需要明确表示。 树可能高度不平衡，深度很大，并且节点可能有很多子节点。 重复值也是允许的，因此重建不能依赖节点值的唯一性。 

## 方法

 强力方法将尝试仅使用遍历顺序（例如前序或级别顺序遍历）来序列化树，同时在各处插入显式分隔符或空标记。 例如，我们可以在同级组之间重复插入分隔符，并在每个节点后面插入空标记。 虽然这种方法有效，但表示形式变得不必要地冗长并且更难以正确解析。 在最坏的情况下，序列化字符串包含过多的结构标记，这些标记会增加内存使用并使反序列化逻辑复杂化。 

最佳解决方案的关键在于，每个节点在序列化过程中只需要两条信息：它的值和它拥有的子节点的数量。 一旦我们知道有多少个子节点属于一个节点，反序列化就变得确定了。 在返回父树之前，我们可以递归地重建那么多子树。 

这种观察自然会导致先序深度优先遍历。 在序列化期间，对于我们存储的每个节点：

 1. 节点值
 2、子女数量
 3. 每个孩子的序列化表示

 例如，具有值的节点`3`两个孩子变成：```
3 2 ...
```解串器读取值和子节点计数，创建节点，然后递归地重建恰好那么多的子节点。 由于前序遍历自然地保留了层次结构，因此重建既简单又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用过多的空标记或分隔符、冗长的表示 |
 | 最佳 | O(n) | O(n) | 使用预序 DFS 存储节点值和子节点数量 |

 ## 算法演练

 ### 序列化

 1. 从根节点开始进行前序深度优先遍历。 预序是理想的，因为父节点在其子节点之前被处理，这允许反序列化以相同的顺序重建层次结构。 
2. 对于每个节点，将两个值附加到序列化输出：

 - 节点的值
 - 节点拥有的子节点数量

 这个子计数是使重建成为可能的关键结构信息。 
3.记录当前节点后，按顺序递归序列化每个子节点。 因为子树的数量是已知的，所以反序列化器稍后将确切地知道要执行多少个递归子树构造。 
4. 将所有值存储在字符串列表中，并在末尾用空格将它们连接起来。 使用列表可以避免低效的重复字符串连接。 
5. 如果树为空，则返回空字符串。 

### 反序列化

 1.如果序列化后的字符串为空，则返回`None`。 
2. 将字符串拆分为标记。 每个节点恰好贡献两个直接令牌：

 - 节点值
 - 儿童计数
 3. 维护一个索引指针，用于跟踪令牌列表中的当前读取位置。 
4. 递归重建树：

 - 读取节点值
 - 读取孩子数
 - 创建节点
 - 递归反序列化恰好那么多的孩子
 5. 将每个重建的子节点附加到节点的`children`列表。 
6. 所有递归调用完成后，返回重建的根节点。 

### 为什么它有效

 该算法之所以有效，是因为每个节点都显式存储其拥有的子节点的数量。 在反序列化期间，此子计数充当边界，准确地告诉我们有多少递归子树读取属于当前节点。 由于先序遍历先处理父项再处理子项，因此令牌流自然保留了层次结构。 每个序列化节点恰好对应一个反序列化节点，并且每个子树都按照其遍历的顺序进行重建。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node(object):
    def __init__(self, val: Optional[int] = None, children: Optional[List['Node']] = None):
        if children is None:
            children = []
        self.val = val
        self.children = children
"""

from typing import List, Optional

class Codec:
    def serialize(self, root: 'Node') -> str:
        """Encodes a tree to a single string.
        
        :type root: Node
        :rtype: str
        """
        
        if not root:
            return ""
        
        serialized = []
        
        def dfs(node: 'Node') -> None:
            serialized.append(str(node.val))
            serialized.append(str(len(node.children)))
            
            for child in node.children:
                dfs(child)
        
        dfs(root)
        return " ".join(serialized)

	
    def deserialize(self, data: str) -> 'Node':
        """Decodes your encoded data to tree.
        
        :type data: str
        :rtype: Node
        """
        
        if not data:
            return None
        
        tokens = data.split()
        index = 0
        
        def dfs() -> 'Node':
            nonlocal index
            
            value = int(tokens[index])
            index += 1
            
            child_count = int(tokens[index])
            index += 1
            
            node = Node(value, [])
            
            for _ in range(child_count):
                node.children.append(dfs())
            
            return node
        
        return dfs()
```实现直接遵循预购DFS策略。 在序列化期间，辅助函数记录节点值，后跟子节点的数量。 这会立即捕获节点身份和结构信息。 

递归遍历自然可以处理任意分支。 每个子子树都在其父子树之后立即序列化，从而保留层次结构顺序。 

在反序列化过程中，`index`变量跟踪标记列表中的当前位置。 每个递归调用恰好消耗当前节点的两个令牌，然后递归地消耗属于其子节点的所有令牌。 

使用`nonlocal index`允许递归调用共享相同的遍历状态而不依赖全局变量，满足无状态要求。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Children []*Node
 * }
 */

import (
    "strconv"
    "strings"
)

type Codec struct {
    
}

func Constructor() *Codec {
    return &Codec{}
}

func (this *Codec) serialize(root *Node) string {
    if root == nil {
        return ""
    }
    
    var serialized []string
    
    var dfs func(node *Node)
    
    dfs = func(node *Node) {
        serialized = append(serialized, strconv.Itoa(node.Val))
        serialized = append(serialized, strconv.Itoa(len(node.Children)))
        
        for _, child := range node.Children {
            dfs(child)
        }
    }
    
    dfs(root)
    
    return strings.Join(serialized, " ")
}

func (this *Codec) deserialize(data string) *Node {
    if data == "" {
        return nil
    }
    
    tokens := strings.Split(data, " ")
    index := 0
    
    var dfs func() *Node
    
    dfs = func() *Node {
        value, _ := strconv.Atoi(tokens[index])
        index++
        
        childCount, _ := strconv.Atoi(tokens[index])
        index++
        
        node := &Node{
            Val: value,
            Children: []*Node{},
        }
        
        for i := 0; i < childCount; i++ {
            node.Children = append(node.Children, dfs())
        }
        
        return node
    }
    
    return dfs()
}

/**
 * Your Codec object will be instantiated and called as such:
 * obj := Constructor();
 * data := obj.serialize(root);
 * ans := obj.deserialize(data);
 */
```Go 实现密切反映了 Python 逻辑。 主要区别是使用显式字符串转换`strconv.Itoa`和`strconv.Atoi`。 Go 切片用于动态令牌存储和子列表。 Nil 处理是明确的，因为 Go 区分`nil`指针和初始化结构。 

与 Python 不同，Go 需要闭包变量，例如`index`在嵌套函数内显式捕获。 否则，递归重建逻辑是相同的。

 时间复杂度是线性的，因为每个节点在序列化和反序列化期间贡献恒定量的工作。 递归堆栈可能会增长到树的高度。 在倾斜树的最坏情况下，这可能会变成`O(n)`。 序列化表示本身也需要线性空间，因为每个节点存储两个整数。

 ## 边缘情况

 空树是最重要的边界条件。 幼稚的实现可能会尝试将空字符串拆分为标记，并在解析过程中失败。 该实现通过在序列化期间返回空字符串并返回来显式处理此问题`None`在反序列化期间立即。 

叶节点是另一个微妙的情况。 由于叶节点没有子节点，因此序列化器记录的子节点数为`0`。 如果没有这个显式计数，反序列化器将不知道子树在哪里结束。 该实现保证了正确性，因为每个节点总是记录其子节点的确切数量。 

重复的节点值很容易破坏不正确的重建策略。 一些有缺陷的方法试图根据独特的值或标记来推断结构。 此实现从不依赖于唯一性。 相反，该结构完全根据预排序和子计数重建，因此重复值自然有效。 

高度不平衡的树也很重要，因为递归深度可能会变大。 一棵高大的链状树`1000`仍然可以正常工作，因为每个递归调用只处理一个节点，然后继续向下。 该算法的正确性不依赖于平衡分支。
