[LeetCode 第 453 题](https://leetcode.com/problems/minimum-moves-to-equal-array-elements/)

 **难度：** 🟡 中等
 **主题：** 数组、数学

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`和`n`元素。 In a single move, you are allowed to increment exactly`n - 1`元素由`1`。 您的目标是确定使数组中的每个元素相等所需的最小移动次数。 

乍一看，该操作感觉不寻常，因为我们不是递增一个元素，而是几乎递增整个数组。 然而，关键的观察是增加`n - 1`elements 在数学上相当于递减未递增的一个元素。 

例如，假设数组是：```
[1, 2, 3]
```如果我们增加前两个元素：```
[2, 3, 3]
```这与减少最后一个元素具有相同的相对效果`3`到`2`同时保持其他不变。 

这种转变是极大地简化问题的核心见解。 

输入约束很重要：

 - 数组长度可以大到`10^5`- 值的范围可以是`-10^9`到`10^9`由于输入可能很大，因此任何逐步重复模拟移动的解决方案都会太慢。 我们需要一种数学观察，使我们能够在线性时间内直接计算答案。 

有几个重要的边缘情况需要考虑：

 - 所有元素都相等的数组，答案应该是`0`- 包含负数的数组
 - 只有一个元素的数组
 - 具有非常大值的数组，在某些语言中溢出可能会成为问题
 - 最小元素出现多次的数组

 该问题保证最终答案适合 32 位整数，从而简化了实现细节。 

## 方法

 ### 蛮力方法

 直接模拟方法将重复执行移动，直到所有数字相等。 

一种可能的策略是：

 1.找到当前最大元素
 2. 将所有其他元素增加`1`3. 计算移动次数
 4. 重复直到所有元素都相等

 这种方法是正确的，因为每一步都完全遵循问题规则。 最终，所有元素将收敛到相同的值。 

然而，这种方法效率极低。 所需的移动次数可能非常大，尤其是当数组值差异很大时。 由于每次移动都需要扫描数组并更新许多元素，因此对于大小的数组来说，总运行时间变得太慢`10^5`。 

### 最优数学方法

 关键的见解是增加`n - 1`elements 相当于减少一个元素。 

我们可以考虑将所有数字减少到最小值，而不是考虑将所有数字提高到最大值。 

假设数组中的最小值是`min_value`。 

每个元素大于`min_value`必须有效地减少，直到达到最小值。 元素所需的约简数`x`是：```
x - min_value
```因此，总的移动次数就是：```
sum(nums) - n * min_value
```这给了我们一个线性时间的解决方案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k * n) | O(1) | O(1) | 单独模拟每个动作，其中`k`是移动次数 |
 | 最佳| O(n) | O(1) | O(1) | 使用递增之间的数学等价`n - 1`elements and decrementing one element |

 ## 算法演练

 ### 最优算法

 1. Find the minimum element in the array.

 该值成为所有元素最终匹配的目标值。 由于递增`n - 1`elements 相当于递减一个元素，我们可以把这个过程看成是把所有数字都减到最小。 
2. 初始化变量`moves`到`0`。 

该变量将存储所需的移动总数。 
3. 迭代数组中的每个元素。 

对于每个元素`num`，计算：```
num - min_value
```这表示需要多少有效减量才能将该数字降至最小值。 
4. 将所有这些差异加在一起。 

总和就是最少的移动次数。 
5. 返回最终结果。 

### 为什么它有效

 每一步都会增加`n - 1`元素由`1`，这会使一个元素保持不变。 相对于不变的元素，其他元素变大了`1`。 这相当于将未改变的元素减少`1`。 

由于这种等价性，使所有元素相等与将每个元素减少到最小元素相同。 所需减少的总数恰好是每个元素与最小值之间的差值之和。 

## Python 解决方案```python
from typing import List

class Solution:
    def minMoves(self, nums: List[int]) -> int:
        minimum_value = min(nums)
        
        moves = 0
        
        for num in nums:
            moves += num - minimum_value
        
        return moves
```实现首先使用 Python 的内置函数查找数组中的最小值`min()`功能。 

接下来我们初始化`moves`存储所需操作的运行总数。 

然后我们遍历数组中的每个数字。 对于每个数字，我们计算它比最小值高出多少。 该差值表示使其等于最小值所需的有效减量数。 

最后，我们返回累计总数。 

该实现直接遵循之前开发的数学观察，这使得代码既简短又高效。 

## 解决方案```go
func minMoves(nums []int) int {
    minimumValue := nums[0]

    for _, num := range nums {
        if num < minimumValue {
            minimumValue = num
        }
    }

    moves := 0

    for _, num := range nums {
        moves += num - minimumValue
    }

    return moves
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于 Go 没有提供内置的`min()`对于切片函数，我们手动扫描数组以找到最小值。 

之后，我们再次遍历数组以累积每个数字与最小值之间的总差。 

Go 直接使用整数类型，并且问题保证结果适合 32 位整数，因此这里不存在溢出问题。

 ### 示例 1

 输入：```

```首先，找到最小值：```

| 元素| 与最小值的差异| 跑步动作|
 | --- | --- | --- |
 | 1 | 1 - 1 = 0 | 1 - 1 = 0 0 |
 | 2 | 2 - 1 = 1 | 1 |
 | 3 | 3 - 1 = 2 | 3 |

 最终答案：```
3
```这符合预期的结果。

```最小值：```

```现在计算差异。 

| 元素| 与最小值的差异| 跑步动作|
 | --- | --- | --- |
 | 1 | 0 | 0 |
 | 1 | 0 | 0 |
 | 1 | 0 | 0 |

 最终答案：```
0
```数组已经相等了。

 ## 边缘情况

 ### 单元素数组

 如果数组仅包含一个元素，则无需移动，因为根据定义，所有元素都已相等。 幼稚的实现可能会意外地对多个元素执行不必要的计算或假设。 此实现可以自然地处理这种情况，因为单个值与最小值之间的差异为零。 

### 负数数组

 负值有时会破坏不正确的数学假设。 例如：```
[-5, -3, -1]
```最小值是`-5`，并且算法正确计算：```
(-5 - -5) + (-3 - -5) + (-1 - -5)
= 0 + 2 + 4
= 6
```由于该解决方案仅依赖于算术差异，因此无需任何特殊逻辑即可正确处理负值。 

### 数组已经相等

 当所有元素都相同时，与最小值的每个差异都为零。 因此该算法返回`0`。 

这很重要，因为如果等式检查实施不正确，基于模拟的方法可能会意外地进入不必要的循环。 

### 非常大的值

 约束允许的值大到`10^9`。 对于此类输入，重复模拟可能会变得极其缓慢。 数学解决方案通过直接在线性时间内计算答案来完全避免这个问题。 

此外，该问题保证最终答案符合 32 位整数，因此标准整数算术在 Python 和 Go 中都足够了。
