[LeetCode 第 446 题](https://leetcode.com/problems/arithmetic-slices-ii-subsequence/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定整数数组内存在多少个算术子序列`nums`。 

算术序列是连续元素之间的差值恒定的序列。 该序列必须至少包含三个元素。 与子数组不同，子序列不需要是连续的。 只要相对顺序保持不变，我们就可以跳过元素。 

例如，在数组中`[2,4,6,8,10]`，子序列`[2,6,10]`是有效的，因为连续的差异都是`4`，即使元素在原始数组中不相邻。 

输入是一个整数数组，长度可达`1000`。 值本身可以小到`-2^31`和一样大`2^31 - 1`。 这些限制很重要，因为：

 - 暴力子序列枚举是不可能的，因为数组的大小`1000`有`2^1000`子序列。 
- 两个数字之间的差异可能会溢出 32 位整数，因此在计算差异时我们必须使用更宽的整数类型。 
- 结果本身保证适合 32 位整数。 

输出应该是长度至少为算术子序列的总数`3`。 

一个关键的细节是长度的子序列`2`不直接计算。 然而，它们在动态编程期间极其重要，因为较长的算术子序列是通过扩展较短的算术子序列来构建的。 

几种边缘情况很容易破坏简单的实现：

 - 具有所有相等数字的数组会产生许多重叠的算术子序列。 
- 必须正确处理负差异。 
- 计算差异时，大整数值可能会导致溢出。 
- 数组小于长度`3`总是产生`0`。 
- 即使数值看起来相同，重复的值也会创建许多不同的子序列。 

## 方法

 ### 蛮力

 暴力解决方案将生成数组的每个可能的子序列，然后检查每个子序列是否是算术。 

为了验证子序列是否是算术序列，我们计算相邻元素之间的差异并确保所有差异都相同。 任意长度至少为`3`满足这个条件就可以得出答案。 

这种方法是正确的，因为它明确地检查了每个可能的子序列。 然而，这在计算上是不可行的。 

长度的数组`n`有`2^n`子序列。 和`n = 1000`，这变得天文数字般大。 即使有效地检查每个子序列仍然会慢得令人绝望。 

### 最优动态规划方法

 关键的观察是算术子序列完全由以下定义：

 - 他们的结束位置
 - 他们的共同点

 这提出了动态规划公式。 

假设我们想知道有多少算术子序列以索引结尾`i`具有共同差异`d`。 

如果我们看一些早期的索引`j < i`， 和：```
nums[i] - nums[j] = d
```那么每个算术子序列结束于`j`有差异`d`可以通过以下方式扩展`nums[i]`。 

此外，这对`(nums[j], nums[i])`本身形成一个新的长度子序列`2`，稍后可能会成长为有效的算术子序列。 

这导致了 DP 结构，其中：

 -`dp[i][d]`至少存储长度为的算术子序列的数量`2`结束于索引`i`有差异`d`- 扩展现有子序列时，我们添加到最终答案，因为所得子序列现在至少具有长度`3`这将问题从指数复杂性转变为二次复杂性。

 ## 算法演练

 1. 创建一个 DP 数组，其中每个位置都包含一个哈希映射。 

每个`dp[i]`是一张地图：```
difference -> count
```该值表示至少有多少个长度的算术子序列`2`结束于索引`i`与此不同。 
2. 初始化最终答案`0`。 

答案只计算至少长度的子序列`3`。 
3. 迭代每对索引`(j, i)`在哪里`j < i`。 

这对代表算术子序列的潜在扩展。 
4. 计算差值：```
diff = nums[i] - nums[j]
```我们使用 64 位整数，因为减法可能会溢出 32 位整数。 
5. 确定有多少个子序列已经结束`j`有了这个差异。```
previous_count = dp[j][diff]
```这些都是可以使用扩展的算术子序列`nums[i]`。 
6. 添加`previous_count`到答案。 

每次扩展都会将子序列长度增加一，因此每个扩展都成为长度至少为有效的算术子序列`3`。 
7. 更新`dp[i][diff]`。 

我们添加：

 -`previous_count`，代表所有扩展子序列
 -`1`，代表新的length-2子序列`(nums[j], nums[i])`所以：```
dp[i][diff] += previous_count + 1
```8. 继续，直到处理完所有对。 
9. 返回累计答案。 

### 为什么它有效

 不变的是`dp[i][diff]`总是存储至少长度的算术子序列的数量`2`结束于索引`i`具有共同差异`diff`。 

每当我们处理一对`(j, i)`:

 - 每个现有的子序列结束于`j`有差异`diff`可以安全地扩展到`i`- 扩展保留了算术属性，因为差异保持不变
 - 每个这样的扩展至少创建一个长度有效的算术子序列`3`由于每个算术子序列都有唯一的最终索引和差值，因此每个有效子序列只计算一次。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def numberOfArithmeticSlices(self, nums: List[int]) -> int:
        n = len(nums)

        # dp[i][diff] = number of arithmetic subsequences
        # of length >= 2 ending at index i with difference diff
        dp = [defaultdict(int) for _ in range(n)]

        total_slices = 0

        for i in range(n):
            for j in range(i):
                diff = nums[i] - nums[j]

                previous_count = dp[j][diff]

                # Extend all previous subsequences
                total_slices += previous_count

                # Add:
                # 1 for the new pair (nums[j], nums[i])
                # previous_count for all extended subsequences
                dp[i][diff] += previous_count + 1

        return total_slices
```该实现严格遵循前面描述的动态编程策略。 

我们首先创建一个名为的哈希映射列表`dp`。 每个映射跟踪有多少算术子序列在每个差值的特定索引处结束。 

外循环选择当前结束索引`i`。 内部循环考虑每个较早的索引`j`，形成一对`(j, i)`。 

对于每一对，我们计算差异：```python
diff = nums[i] - nums[j]
```然后我们查找有多少算术子序列已经结束于`j`使用同样的差异。```python
previous_count = dp[j][diff]
```这些子序列都可以通过附加来扩展`nums[i]`。 

这些扩展立即有助于最终答案，因为它们现在至少有长度`3`。 

最后，我们更新一下：```python
dp[i][diff] += previous_count + 1
```这`+1`考虑新的长度子序列`2`形成于`(nums[j], nums[i])`。 

## 解决方案```go
func numberOfArithmeticSlices(nums []int) int {
	n := len(nums)

	// dp[i][diff] = number of arithmetic subsequences
	// of length >= 2 ending at index i with difference diff
	dp := make([]map[int64]int, n)

	for i := 0; i < n; i++ {
		dp[i] = make(map[int64]int)
	}

	totalSlices := 0

	for i := 0; i < n; i++ {
		for j := 0; j < i; j++ {
			diff := int64(nums[i]) - int64(nums[j])

			previousCount := dp[j][diff]

			// Extend previous subsequences
			totalSlices += previousCount

			// Add new pair and extended subsequences
			dp[i][diff] += previousCount + 1
		}
	}

	return totalSlices
}
```Go 实现几乎完全反映了 Python 解决方案。 

主要区别在于 Go 需要对每个映射进行显式初始化`dp[i]`。 

另一个重要的区别是整数处理。 由于两个 32 位整数相减可能会溢出，因此差值存储为`int64`:```go
diff := int64(nums[i]) - int64(nums[j])
```Go 映射会自动返回缺失键的零值，这简化了查找逻辑。

 ## 边缘情况

 ### 少于三个元素的数组

 算术子序列必须至少包含三个元素。 长度数组`0`,`1`， 或者`2`应该总是返回`0`。 

如果实现意外地将对计为有效的算术子序列，则很容易出现错误处理。 DP 公式避免了这个错误，因为对仅存储为中间构建块，并且永远不会直接添加到答案中。 

### 所有元素都相等

 像这样的数组：```
[7,7,7,7,7]
```创建大量有效的算术子序列，因为每个子序列都有公差`0`。 

这种情况强调实现是否正确地累积计数而不是覆盖它们。 使用：```
dp[i][diff] += previous_count + 1
```确保保留所有重叠子序列。 

### 差分计算中的整数溢出

 这些约束允许值接近 32 位整数限制。 

例如：```
nums[i] = 2147483647
nums[j] = -2147483648
```它们的差异超出了有符号 32 位整数的范围。 

如果实现以 32 位整数存储差异，则哈希映射内部可能会发生不正确的冲突，从而产生无效计数。 

该解决方案通过使用Python的任意精度整数来避免这个问题`int64`在围棋中。
