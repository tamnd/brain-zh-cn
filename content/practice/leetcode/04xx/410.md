[LeetCode 410 题](https://leetcode.com/problems/split-array-largest-sum/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、动态规划、贪心、前缀和

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`和一个整数`k`。 我们必须将数组精确地划分为`k`非空连续子数组。 在这些子数组中，每个子数组都有自己的和，目标是最小化最大的子数组和。 

换句话说，我们试图根据累积和尽可能均匀地分割数组，同时保留元素的原始顺序并确保每个分区保持连续。 

例如，如果：```
nums = [7,2,5,10,8]
k = 2
```一种可能的划分是：```
[7,2,5] and [10,8]
```总和是：```
14 and 18
```最大的子数组和是`18`。 

另一种分裂：```
[7,2] and [5,10,8]
```产生总和：```
9 and 23
```最大的子数组和变为`23`，这更糟糕，因为我们希望最大子数组和尽可能小。 

输入约束非常重要：

 -`nums.length <= 1000`-`k <= 50`-`nums[i] <= 10^6`这些限制告诉我们几件事：

 - 数组并不小，因此不可能生成指数分区。 
- 这些值可能会变得非常大，这意味着在某些语言中子数组和可能会超过 32 位整数范围。 
- 自从`k`相对较小，动态规划是可能的，但我们仍然应该寻找更有效的解决方案。 

该问题还保证：

 - 每个拆分必须至少包含一个元素。 
- 数组包含非负整数。 
-`k`始终有效。 

所有数字均为非负数这一事实是能够对答案进行二分搜索的关键观察结果。 

一些边缘情况很重要：

 -`k = 1`，这意味着整个数组必须保留为一个子数组。 
-`k = len(nums)`，这意味着每个元素都成为自己的分区。 
- 包含零的数组，可以创建多个等效分区。 
- 非常大的值，这可能会暴露某些语言中的整数溢出问题。 
- 高度不均匀的阵列，例如`[1,1,1,1000]`，平衡变得困难。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试一切可能的方法来放置`k - 1`数组内部的分区边界。 

对于长度的数组`n`， 有`n - 1`可能的分割位置。 我们必须选择`k - 1`其中。 对于每个分区排列，我们计算每个子数组的总和并跟踪最大子数组总和。 答案是所有这些最大值中的最小值。 

这种方法是正确的，因为它详尽地检查了每个有效的分区配置。 

然而，它很快在计算上变得不可行。 可能的分区数量以组合方式增长：```
C(n - 1, k - 1)
```为了`n = 1000`，这是一个天文数字。 

即使使用前缀和之类的优化，暴力破解也无法处理输入约束。 

### 关键见解

 重要的观察是答案本身可以进行二分搜索。 

假设我们猜测一个值`X`并询问：

 > 我们能否将数组最多分割成`k`子数组，使得子数组总和不超过`X`？ 

这变成了一个贪婪的可行性问题。 

因为所有数字都是非负数：

 - 如果最大金额`X`可行，则每个较大的值也可行。 
- 如果`X`不可行，那么每个较小的值也不可行。 

这种单调行为正是二分搜索所需要的。 

最小可能的答案是：```
max(nums)
```因为没有子数组可以避免包含其最大元素。 

最大可能的答案是：```
sum(nums)
```这相当于只使用一个子数组。 

我们对这个范围进行二分搜索并贪婪地检查可行性。

 ## 算法演练

 ### 最优算法：二分查找+贪心

 1. 初始化二分查找边界。 

最小可能的最大子数组和是最大的单个元素，因为没有分区可以分割元素。 

最大可能的最大子数组和是总数组和，因为我们可以将所有内容放入一个子数组中。 

所以：```
left = max(nums)
right = sum(nums)
```2. 对答案空间执行二分查找。 

在每一步中，计算：```
mid = (left + right) // 2
```这里，`mid`表示最大允许子数组和的候选值。 
3. 贪心测试是否`mid`是可行的。 

遍历数组，同时维护运行的子数组和。 

对于每个数字：

 - 将其添加到当前子数组中。 
- 如果总和超过`mid`，开始一个新的子数组。 
- 增加子数组计数。 

这种贪婪策略最大限度地减少了分区数量，因为我们仅在绝对必要时才进行分区。 
4. 检查所需子数组的数量。 

如果我们可以将数组划分为`k`或更少的子数组，那么`mid`是可行的。 

这意味着我们可以进一步减少答案，因此向左移动：```
right = mid
```5. 否则，如果超过`k`需要子数组，那么`mid`太小了。 

增加搜索范围：```
left = mid + 1
```6. 继续直到`left == right`。 

至此，我们已经找到了最小的可行最大子数组和。 

### 为什么它有效

 正确性取决于两个属性。 

首先，可行性是单调的。 如果最大总和`X`有效，任何更大的值也有效，因为更大的限制只会使分区更容易。 

其次，贪婪分区策略总是在给定限制下生成最小数量的子数组。 由于我们仅在必要时进行拆分，因此任何替代策略都将至少使用同样多的分区。 

这些属性共同保证二分搜索收敛到最佳最小最大子数组和。 

## Python 解决方案```python
from typing import List

class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        def can_split(max_allowed_sum: int) -> bool:
            subarray_count = 1
            current_sum = 0

            for num in nums:
                if current_sum + num > max_allowed_sum:
                    subarray_count += 1
                    current_sum = num
                else:
                    current_sum += num

            return subarray_count <= k

        left = max(nums)
        right = sum(nums)

        while left < right:
            mid = (left + right) // 2

            if can_split(mid):
                right = mid
            else:
                left = mid + 1

        return left
```实现首先定义一个名为的辅助函数`can_split`。 

该函数回答了可行性问题：

 > 数组最多可以分为`k`子数组，使得每个子数组和最多为`max_allowed_sum`？ 

在助手内部，我们贪婪地将元素累积到当前子数组中。 一旦添加另一个元素超出限制，我们就会创建一个新的子数组。 

然后，二分查找在有效答案范围内进行：```python
left = max(nums)
right = sum(nums)
```在每次迭代中，中点成为候选最大子数组和。 

如果助手确认可行性，我们会尝试通过移动右侧边界来找到更小的有效答案。 

否则，我们增加下限。 

最终，搜索收敛到最小的可行值。 

## 解决方案```go
func splitArray(nums []int, k int) int {
	canSplit := func(maxAllowedSum int) bool {
		subarrayCount := 1
		currentSum := 0

		for _, num := range nums {
			if currentSum+num > maxAllowedSum {
				subarrayCount++
				currentSum = num
			} else {
				currentSum += num
			}
		}

		return subarrayCount <= k
	}

	left := nums[0]
	right := 0

	for _, num := range nums {
		if num > left {
			left = num
		}
		right += num
	}

	for left < right {
		mid := left + (right-left)/2

		if canSplit(mid) {
			right = mid
		} else {
			left = mid + 1
		}
	}

	return left
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个显着的区别是整数处理。 在 Go 中，如果使用较小的整数类型，可能会发生整数溢出，但标准`int`type 足以满足 LeetCode 上的问题约束。 

中点计算使用：```go
mid := left + (right-left)/2
```而不是：```go
(left + right) / 2
```这是一种常见的防御实践，可以避免固定宽度整数的语言中的溢出。 

Go 切片自然地通过类似引用的语义传递，因此在迭代期间不会发生额外的复制。

 ## 边缘情况

 ### 案例 1：`k = 1`什么时候`k`等于`1`，整个数组必须保持为单个子数组。 这意味着答案只是数组的总和。 

幼稚的实现可能仍然会尝试不必要的分区逻辑或意外地拆分数组。 二分搜索解决方案自然可以处理这一问题，因为任何小于总和的可行限制都将需要多个分区。 

### 案例 2：`k = len(nums)`什么时候`k`等于数组长度，每个元素都可以成为自己的子数组。 在这种情况下，最佳答案是数组中的最大元素。 

这很重要，因为任何分区都不能减少最大元素的贡献。 该算法正确地将下界初始化为`max(nums)`，确保最终答案永远不会低于该值。 

### 情况 3：包含零的数组

 具有多个零的数组可以创建多个具有相同总和的有效分区排列。 

例如：```
nums = [0,0,0,0]
```有缺陷的实现可能会错误地创建额外的分区或错误地处理零累积。 

贪心方法可以正确处理这个问题，因为添加零永远不会使当前子数组总和超出允许的限制。 

### 情况 4：非常大的数字

 约束允许值高达`10^6`，并且数组最多可以包含`1000`元素。 这意味着累计金额可能达到`10^9`。 

如果不小心进行中点计算，具有固定宽度整数的语言可能会溢出。 

Go 解决方案通过以下方式避免了这个问题：```go
mid := left + (right-left)/2
```这是标准的溢出安全二进制搜索模式。
