[LeetCode 第 476 题](https://leetcode.com/problems/number-complement/)

 **难度：** 🟢简单
 **主题：** 位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们通过翻转二进制表示中的每一位来计算正整数的补码。 二进制补码意味着改变每一个`1`咬进`0`，以及每一个`0`咬进`1`。 

例如，整数`5`以二进制表示为`101`。 翻转每一位给出`010`，等于`2`以十进制形式。 

这个问题中一个非常重要的细节是我们只翻转数字实际二进制表示形式的部分。 我们不考虑前导零。 例如，二进制表示`5`是`101`， 不是`00000101`。 如果我们包含前导零，答案就会变得不明确，因为整数在不同的系统上以不同的固定宽度存储。 
输入是单个整数`num`，并且我们必须返回另一个表示翻转后的二进制值的整数。 

限制条件是：

 -`1 <= num < 2^31`这些限制告诉我们一些重要的事情：

 - 数字总是正数，所以我们永远不需要处理负整数。 
- 最大尺寸足够小，任何位操作方法都将运行得非常快。 
- 由于数字适合 31 位，因此在 Python 中整数溢出不是问题，并且在 Go 中使用标准整数运算也是安全的。 

一个重要的边缘情况是`num = 1`。 它的二进制表示很简单`1`，然后翻转它会产生`0`。 另一个微妙的点是确保我们只翻转有意义的位，而不是机器表示引入的额外前导位。 

## 方法

 ### 蛮力方法

 强力解决方案会将数字转换为二进制字符串，迭代每个字符，手动翻转每个位，然后将生成的二进制字符串转换回整数。 

例如：

-`5`变成`"101"`- 翻转每个角色：

 -`'1' -> '0'`-`'0' -> '1'`-`'1' -> '0'`- 结果变成`"010"`- 转换回十进制，产生`2`这是可行的，因为二进制字符串直接公开了我们需要修改的位。 然而，这种方法涉及重复的字符串操作以及整数和字符串格式之间的转换。 

尽管约束足够小，这仍然可以通过，但这不是最优雅或最有效的解决方案，因为问题本质上是关于位操作的。 

### 最佳位操作方法

 关键在于 XOR 可以有效地翻转位。 

如果我们创建一个完全由以下内容组成的位掩码`1`s 的长度与二进制表示形式相同`num`，然后将数字与该掩码进行异或运算，翻转每一位。 

例如：

-`num = 5`- 二进制表示：`101`- 具有相同位数的掩码：`111`- 异或运算：

 -`101 ^ 111 = 010`结果：`2`主要挑战是构建正确的掩模。 

我们可以通过重复向左移动并添加来动态构建掩码`1`直到掩码包含足够的位来覆盖该数字。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k) | O(k) | 转换为二进制字符串并手动翻转字符 |
 | 最佳| O(k) | O(1) | O(1) | 使用位掩码和 XOR 进行直接位操作 |

 这里，`k`表示二进制表示中的位数`num`。 

## 算法演练

 ### 最优算法

 1. 初始化一个名为`mask`到`1`。 

掩码的目的是最终成为所有的序列`1`s 与二进制表示的长度匹配`num`。 
2. 当 mask 小于`num`。 

每一步：

 - 将掩码向左移动一位。 
- 添加`1`。 

这个过程逐渐创建如下掩码：

 -`1`-`11`-`111`-`1111`3. 一旦掩码足够大，就执行 XOR`num`和`mask`。 

异或具有以下性质：

 -`1 ^ 1 = 0`-`0 ^ 1 = 1`因此，与所有掩码进行异或`1`s 一点一点地翻转。 
4. 返回异或结果。 

### 为什么它有效

 该算法之所以有效，是因为掩码包含与`num`，并且掩码中的每一位都是`1`。 与任意位进行异或`1`翻转它。 因为我们只包含有意义的部分`num`，结果正是问题定义的补集。 

## Python 解决方案```python
class Solution:
    def findComplement(self, num: int) -> int:
        mask = 1
        
        while mask < num:
            mask = (mask << 1) | 1
        
        return num ^ mask
```实现首先创建一个初始化为的掩码`1`。 

这`while`循环通过向左移动掩码并将新的最低有效位设置为来不断扩展掩码`1`。 这逐渐构建了一系列连续的`1`s。 

例如：

-`1`-`11`-`111`-`1111`一旦掩码足够大以覆盖其中的所有位`num`，XOR 运算翻转数字中的每一位。 

最终的 return 语句直接使用位操作生成补码，避免任何字符串转换。 

## 解决方案```go
func findComplement(num int) int {
    mask := 1

    for mask < num {
        mask = (mask << 1) | 1
    }

    return num ^ mask
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个小的语言差异是使用`:=`用于变量声明和初始化。 Go 整数是固定宽度类型，但问题约束保证所有操作都安全地保持在范围内。 

无需对溢出或特殊整数行为进行额外处理。

 ## 边缘情况

 一种重要的边缘情况是当输入是`1`。 它的二进制表示仅包含一位。 粗心的实现可能会意外地产生负数或包含额外的前导位。 在此解决方案中，掩模仍然存在`1`， 和`1 ^ 1`正确产生`0`。 

当数字是 2 的幂时会出现另一个重要情况，例如`8`（`1000`二进制）。 这些数字包含一个`1`后面跟着零。 该算法正确构造了一个掩码`1111`，异或产生`0111`，等于`7`。 

第三种微妙的边缘情况是当所有位都已经`1`， 例如`7`（`111`） 或者`31`（`11111`）。 翻转每一位应该产生`0`。 掩码结构保证 XOR 运算将每个有效位恰好翻转一次，因此结果全部为零。 

最后一个考虑因素是避免前导零。 机器整数通常使用固定宽度（例如 32 或 64 位）存储。 如果我们直接使用按位 NOT 运算符，我们可能会意外翻转不需要的前导位并产生负数。 构建仅匹配有效位的掩码可确保实现的行为完全按照问题定义。
