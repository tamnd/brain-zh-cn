[LeetCode 第 487 题](https://leetcode.com/problems/max-consecutive-ones-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、滑动窗口

 ## 解决方案

 ## 问题理解

 问题给了我们一个二进制数组`nums`，其中每个元素都是`0`或者`1`。 我们想要找到最长的连续子数组只包含`1`s 之后我们最多可以翻转一个`0`变成一个`1`。 

换句话说，我们可以选择零个或一个包含`0`并假装它是一个`1`。 完成此可选翻转后，我们必须计算连续的最大长度`1`s。 

例如，如果数组是`[1,0,1,1,0]`，翻转第一个`0`产生`[1,1,1,1,0]`，其中包含四个连续的`1`s。 翻第二个`0`只给出三个连续的`1`s，所以答案是`4`。 

重要的细节是我们最多可以翻转一个`0`。 这意味着：

 - 我们可能会恰好翻转一个`0`- 我们可以选择不翻转任何东西
 - 我们永远不能翻转超过一个`0`约束条件很重要：

 -`1 <= nums.length <= 10^5`- 每个元素是`0`或者`1`数组长度为`10^5`强烈建议`O(n^2)`解决方案可能会太慢。 我们的目标应该是线性时间算法。 

一些边缘情况尤其重要：

 - 数组仅包含`1`s，例如`[1,1,1]`- 数组仅包含`0`s，例如`[0,0,0]`- 长度数组`1`- 最佳答案来自翻转的数组`0`在中间
 - 多次有效翻转产生相同最大长度的数组

 关于无限流的后续内容还暗示预期的解决方案应该使用恒定的额外内存并增量地处理元素。 

## 方法

 ### 蛮力方法

 一个简单的方法是尝试翻转所有可能的方法`0`分别计算最长的连续序列`1`每次翻转后 s。 

对于每个索引：

 1. 如果值为`0`，暂时翻转到`1`2. 扫描整个数组，计算最大连续数`1`s
 3.恢复原值
 4. 跟踪最佳结果

 我们还应该考虑不执行翻转的情况，特别是当数组已经只包含`1`s。 

这种方法是正确的，因为它详尽地检查了最多一个翻转的每一个有效选择`0`。 然而，它的效率很低。 如果数组有长度`n`，那么对于每个位置，我们可以执行另一个长度的完整扫描`n`，生产`O(n^2)`时间复杂度。 

和`n = 10^5`，这变得太慢了。 

### 最优滑动窗口方法

 关键的观察是我们实际上不需要单独测试每个翻转。 

相反，我们可以考虑找到最多包含一个的最长窗口`0`。 

为什么这有效？ 

如果一个窗口最多包含一个`0`，然后我们可以翻转那个单`0`变成一个`1`，使整个窗口由连续的`1`s。 

这将问题转化为：

 > 找到最多包含一个的最长连续子数组`0`。 

这是一个经典的滑动窗口问题。 

我们维护两个指针：

 -`left`, 窗口的开始
 -`right`, 窗口的末端

 当我们向右扩展窗口时：

 - 我们计算当前窗口内有多少个零
 - 如果窗口包含多个`0`，我们从左侧缩小它，直到它再次有效

 在每一步中，窗口都满足条件：

 - 窗口最多包含一个`0`因此，每个有效窗口代表一个序列，可以成为所有`1`最多翻转一次后。 

这给出了一个`O(n)`解决方案，因为每个元素最多进入和离开窗口一次。

 ## 算法演练

 1.初始化两个指针，`left`和`right`，都开始于`0`。 
2. 维护一个变量`zero_count`跟踪当前窗口内存在多少个零。 
3. 使用迭代遍历数组`right`作为窗口的扩展边界。 
4. 每当`nums[right]`是`0`, 增量`zero_count`因为当前窗口现在包含另一个零。 
5. 如果`zero_count`变得大于`1`，该窗口无效，因为我们只允许翻转一个零。 
6. 要恢复有效性，请重复移动`left`转发：

 - 如果`nums[left]`是`0`, 递减`zero_count`- 增量`left`- 继续直到窗口再次包含最多一个零
 7. 确保窗口有效后，计算其长度：`window_length = right - left + 1`8. 使用当前有效窗口大小更新最大答案。 
9. 继续，直到处理完整个数组。 

### 为什么它有效

 滑动窗口始终保持当前窗口最多包含一个不变式`0`。 

任何这样的窗口都可以转化为所有`1`通过翻转那个零来实现。 因此，每个有效窗口都对应一个可行解。 

因为我们不断地最大化有效窗口的大小，所以算法最终会找到满足条件的最大可能窗口，这正是所需的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:
        left = 0
        zero_count = 0
        max_length = 0

        for right in range(len(nums)):
            if nums[right] == 0:
                zero_count += 1

            while zero_count > 1:
                if nums[left] == 0:
                    zero_count -= 1
                left += 1

            current_length = right - left + 1
            max_length = max(max_length, current_length)

        return max_length
```实现直接遵循滑动窗口策略。 

变量`left`存储当前窗口的开头，而循环变量`right`一次将窗口展开一个元素。 

每当我们遇到一个`0`，我们增加`zero_count`。 这告诉我们需要多少个翻转位置才能使窗口完整`1`s。 

如果窗口包含多个零，则内部`while`循环从左侧缩小窗口，直到它再次有效。 在此过程中，如果移除的元素是`0`，我们递减`zero_count`。 

恢复有效性后，计算当前窗口长度并用于更新`max_length`。 

由于每个指针仅向前移动，因此该算法在线性时间内高效运行。 

## 解决方案```go
func findMaxConsecutiveOnes(nums []int) int {
    left := 0
    zeroCount := 0
    maxLength := 0

    for right := 0; right < len(nums); right++ {
        if nums[right] == 0 {
            zeroCount++
        }

        for zeroCount > 1 {
            if nums[left] == 0 {
                zeroCount--
            }
            left++
        }

        currentLength := right - left + 1
        if currentLength > maxLength {
            maxLength = currentLength
        }
    }

    return maxLength
}
```Go 的实现与 Python 解决方案非常相似。 

Go 切片已经提供了高效的索引访问，因此滑动窗口逻辑保持不变。 由于问题约束对于标准整数来说足够小，因此不存在整数溢出的风险。 

Go 不以影响此问题的方式区分 nil 和空切片。 无论如何，约束至少保证一个元素。

 ## 边缘情况

 一个重要的边缘情况是数组仅包含`1`s，例如`[1,1,1,1]`。 有缺陷的实现可能会错误地假设必须始终翻转一零。 事实上，翻转是可选的。 滑动窗口自然会处理这个问题，因为窗口始终保持有效`zero_count = 0`，让整个数组长度成为答案。 

另一个重要的情况是一个只包含`0`s，例如`[0,0,0]`。 由于我们只能翻转一个零，因此最大连续序列始终是`1`。 当出现多个零时，不正确的实现有时会由于无法正确缩小窗口而意外返回较大的值。 滑动窗口通过确保窗口永远不会包含多个零来防止这种情况发生。 

第三个重要的边缘情况涉及连续的零，例如`[1,0,0,1]`。 这是错误的常见来源，因为窗口在第二个零出现后立即变得无效。 该算法正确地从左侧缩小窗口，直到只剩下一个零，确保所有计数的窗口都是有效的候选窗口。 

另一个微妙的情况是单元素数组。 为了`[1]`，答案是`1`，同时对于`[0]`，我们可以翻转零并且仍然得到`1`。 该实现可以正确处理这两种情况，因为窗口逻辑甚至适用于长度为 1 的数组。
