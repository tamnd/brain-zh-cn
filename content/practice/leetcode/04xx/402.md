 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、贪婪、单调堆栈

 ## 解决方案

 ## 问题理解

 问题给了我们一个数字字符串`num`和一个整数`k`。 我们必须准确地删除`k`使所得整数尽可能小。 

关键细节是我们不允许对数字重新排序。 我们只能删除数字，同时保留剩余字符的相对顺序。 删除数字后，结果不应包含前导零。 如果每个数字都被删除，或者在修剪前导零后剩余的数字变成全零，则答案应该是`"0"`。 

例如，如果`num = "1432219"`和`k = 3`，我们希望通过删除三位数字获得最小的数字。 去除`4`,`3`，和一个`2`给出`"1219"`，这是可能的最小结果。 

输入大小很重要。 约束条件`num.length <= 10^5`意味着算法必须接近线性时间。 任何尝试所有可能的删除组合的解决方案都会太慢。 这强烈表明我们需要一种贪婪策略与有效的数据结构相结合。 

一些边缘情况很重要：

 - 删除所有数字，例如`num = "10", k = 2`，应该返回`"0"`。 
- 删除数字可能会产生前导零，例如`"10200"`成为`"0200"`，必须转换为`"200"`。 
- 已经在增加的数字，例如`"12345"`，需要从末尾删除数字。 
- 正在减少的数字，例如`"54321"`，受益于删除较早的大数字。 
- 必须小心处理重复的数字，因为删除错误的出现可能会导致最终数字更大。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试一切可能的方法来删除`k`字符串中的数字。 对于每个候选结果，我们都会对其进行数字比较并保留最小的那个。 

对于一个长度的字符串`n`，我们必须选择`k`要删除的数字，这会创建`C(n, k)`可能的组合。 对于大量输入，该值呈指数增长。 即使对于中等值`n`，可能性的数量变得巨大。 

这种方法是正确的，因为它检查每个有效结果，但对于`n`最多`100000`。 

### 最优贪婪+单调堆栈方法

 重要的观察是，通常应该首先删除出现在较小数字之前的较大数字。 

假设我们有`"143..."`。 如果我们保留`4`在较小的数字之前，例如`3`，结果数字变大。 因此，每当我们遇到比前一个数字小的数字时，我们就应该考虑删除前一个较大的数字。 

这自然会导致单调递增的堆栈：

 - 我们从左到右处理数字。 
- 虽然当前数字小于堆栈顶部，并且我们仍然可以删除，但我们会从堆栈中弹出较大的数字。 
- 这贪婪地确保较小的数字出现在最终数字的前面。 

堆栈保持单调递增，因为每当较小的数字到达时，较大的数字就会被删除。 

处理完所有数字后：

 - 如果仍有删除，我们会从末尾删除数字，因为这些是最大的剩余位置。 
- 然后我们去掉前导零。 
- 如果没有留下任何东西，则返回`"0"`。 

这种贪婪策略之所以有效，是因为最左边的数字对最终数值的贡献最大。 使前面的数字尽可能小总是可以改善结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数，大致为 O(C(n, k) * n) | O(n) | 尝试所有可能的删除组合 |
 | 最佳 | O(n) | O(n) | 使用带有贪婪删除的单调递增堆栈 |

 ## 算法演练

 1. 初始化一个空堆栈。 

当我们构建它时，堆栈将存储最终数字的数字。 我们希望堆栈尽可能保持单调递增。 
2. 遍历每个数字`num`。 

对于每个数字，将其与堆栈顶部进行比较。 
3. 当堆栈不为空时，顶部数字大于当前数字，并且我们仍然有可用的删除，从堆栈中弹出。 

这就是贪心的一步。 较大的数字放在较小的数字之前，会不必要地增加数字。 删除较大的数字会产生较小的结果。 
4. 将当前数字压入堆栈。 

删除前面任何较大的数字后，我们将当前数字添加到增长结果中。 
5. 处理完所有数字后，检查是否`k`仍然大于零。 

如果仍有删除，则堆栈中的数字已经单调递增。 在这种情况下，从末尾删除数字可以最大限度地减少数字。 
6. 取出剩余的`k`从堆栈末尾开始的数字。 

这些尾随数字最不值得保留，因为前面的位置更重要。 
7. 将堆栈转换为字符串。 

将所有剩余数字连接在一起。 
8. 删除前导零。 

该问题要求最终数字不包含前导零。 
9. 如果结果字符串为空，则返回`"0"`。 

这处理所有数字被删除或所有剩余数字变为零的情况。 

### 为什么它有效

 该算法保持了不变式：在处理每个数字后，堆栈始终表示最小的可能前缀。 每当出现较小的数字时，删除前面较大的数字会提高最早可能位置的数字，这对最终值影响最大。 因为每次删除都是局部最优的并且永远不会损害未来的决策，所以贪婪策略会产生全局最小的结果。 

## Python 解决方案```python
class Solution:
    def removeKdigits(self, num: str, k: int) -> str:
        stack: list[str] = []

        for digit in num:
            while k > 0 and stack and stack[-1] > digit:
                stack.pop()
                k -= 1

            stack.append(digit)

        # Remove remaining digits from the end
        while k > 0:
            stack.pop()
            k -= 1

        # Build result and remove leading zeros
        result = "".join(stack).lstrip("0")

        return result if result else "0"
```实现直接遵循贪婪单调堆栈策略。 

这`stack`存储将形成最终答案的数字。 在迭代过程中，`while`每当出现较小的当前数字时，循环就会删除较大的数字。 这可确保数字的左侧保持尽可能小。 

处理完每个数字后，可能仍然会留下一些删除的内容。 当数量已经增加时会发生这种情况，例如`"12345"`。 在这种情况下，最大的贡献来自尾随数字，因此我们从末尾删除它们。 

最终结果是用`"".join(stack)`。 致电给`lstrip("0")`有效删除前导零。 如果所有数字都消失，我们返回`"0"`。 

## 解决方案```go
func removeKdigits(num string, k int) string {
	stack := make([]byte, 0)

	for i := 0; i < len(num); i++ {
		digit := num[i]

		for k > 0 && len(stack) > 0 && stack[len(stack)-1] > digit {
			stack = stack[:len(stack)-1]
			k--
		}

		stack = append(stack, digit)
	}

	// Remove remaining digits from the end
	for k > 0 {
		stack = stack[:len(stack)-1]
		k--
	}

	// Remove leading zeros
	start := 0
	for start < len(stack) && stack[start] == '0' {
		start++
	}

	result := string(stack[start:])

	if result == "" {
		return "0"
	}

	return result
}
```Go 实现使用`[]byte`切片作为堆栈，因为数字是字符。 追加和切片使推入和弹出操作变得高效。 

与 Python 不同，Go 不提供内置的`lstrip`方法，因此使用索引指针手动删除前导零。 

Go 字符串是不可变的，因此在返回结果之前需要将字节切片转换回字符串。

 ## 边缘情况

 当所有数字都被删除时，就会出现一种重要的边缘情况。 例如，`num = "10"`和`k = 2`。 有缺陷的实现可能会返回一个空字符串而不是`"0"`。 该解决方案通过检查最终处理的字符串是否为空并返回来处理此问题`"0"`在这种情况下。 

另一个关键边缘情况涉及前导零。 考虑`"10200"`和`k = 1`。 删除前导`1`创造`"0200"`。 如果不删除前导零，输出将违反问题要求。 该实现在返回结果之前显式去除前导零。 

第三个重要的边缘情况是当数字已经按升序排列时，例如`"12345"`。 在这种情况下，贪婪弹出条件在遍历过程中永远不会触发。 幼稚的实现可能会忘记使用任何剩余的删除。 该算法通过在迭代完成后从末尾删除剩余的数字来正确处理这个问题。 

第四个微妙的边缘情况涉及重复的相同数字，例如`"11111"`。 该算法仅在堆栈顶部严格大于当前数字时删除数字。 这可以保持相等数字之间的稳定性，并避免不必要的删除，从而避免以后产生更大的最终数字。
