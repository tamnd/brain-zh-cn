[LeetCode 第 416 题](https://leetcode.com/problems/partition-equal-subset-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题询问是否可以将正整数数组分为两个子集，使得两个子集的总和完全相同。 

假设数组中所有数字的总和为`S`。 如果我们想将数组分成两个相等的子集，那么每个子集的总和必须为`S / 2`。 这立即给了我们一个重要的观察：如果总和是奇数，则不可能将其分为两个相等的整数和。 

例如：

-`nums = [1,5,11,5]`- 总和 =`22`- 目标子集总和 =`11`- 因为我们可以用 sum 形成一个子集`11`，其余数字的总和也为`11`，所以答案是`true`。 
-`nums = [1,2,3,5]`- 总和 =`11`- 自从`11`是奇数，相等的划分是不可能的，所以答案是`false`。 

输入约束很重要：

 - 数组长度最大可达`200`- 每个数字最多可达`100`这意味着最大可能的总和是：```
200 * 100 = 20000
```探索每个子集的强力解决方案需要检查`2^n`的可能性，对于`n = 200`。 然而，由于总和是相对有界的，因此基于子集和的动态规划变得可行。 

有几个重要的边缘情况需要记住：

 - 总和为奇数的数组必须立即返回`false`- 只有一个元素的数组永远不能被均分
 - 包含重复值的数组仍必须正确处理
 - 接近约束极限的大输入需要有效的多项式时间解决方案
 - 由于所有数字都是正数，子集和只会增加，这简化了 DP 逻辑

 ## 方法

 ### 蛮力方法

 暴力方法尝试数组的每个可能的子集，并检查任何子集的总和是否为数组总和的一半。 

递归的思想很简单：

 - 对于每个数字，选择：

 - 将其包含在当前子集中
 - 将其从当前子集中排除
 - 继续递归，直到处理完所有数字
 - 如果任何子集达到目标总和，则返回`true`这是有效的，因为每个可能的子集都会被探索，所以如果存在有效的分区，算法最终会找到它。 

然而，时间复杂度是指数级的。 每个元素有两个选择，所以子集总数为：```
2^n
```为了`n = 200`，这是完全不切实际的。 

### 最优动态规划方法

 关键的见解是我们实际上不需要显式枚举所有子集。 

我们只关心子集是否有和`target = total_sum / 2`存在。 

这将问题转化为经典的子集和问题：

 > 我们可以选择一些总和等于的数字吗`target`？ 

动态规划效果很好，因为：

 - 目标总和是有限的
 - 子问题严重重叠
 - 我们可以逐步构建解决方案

 我们维护一个 DP 数组，其中：```
dp[s] = whether sum s is achievable
```最初：

-`dp[0] = true`，因为总和`0`总是可以使用空子集

 对于每个数字：

 - 向后更新DP数组
 - 如果`dp[s - num]`是真的，那么`dp[s]`也可以成为现实

 向后迭代非常重要，因为它可以防止在单次迭代中多次重用同一元素。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试每个子集 |
 | 最优动态规划| O(n * 目标) | O（目标）| 使用具有滚动状态的子集和 DP |

 ## 算法演练

 ### 最优DP算法

 1. 计算数组的总和。 

我们首先将所有数字加在一起。 如果总和是奇数，我们立即返回`false`因为两个相等的整数子集是不可能的。 
2. 计算目标子集总和。 

由于两个子集的总和必须相等：```
target = total_sum // 2
```现在的问题是确定是否有任何子集之和为`target`。 
3. 创建DP阵列。 

我们创建一个大小的布尔数组`target + 1`。```
dp[s] = whether sum s can be formed
```最初：```
dp[0] = true
```因为空子集总是可以产生和`0`。 
4. 处理数组中的每个数字。 

对于每个数字`num`，我们从右向左更新DP数组。 

向后迭代是必要的，因为每个数字只能使用一次。 如果我们向前迭代，相同的数字可能会在同一次迭代中多次贡献。 
5. 更新可达金额。 

对于每一笔金额`s`从`target`下降到`num`：

- 如果`dp[s - num]`已经是事实了，
 - 那么我们也可以形成 sum`s`所以：```
dp[s] = dp[s] OR dp[s - num]
```6. 返回最终结果。 

处理完所有数字后：

 - 如果`dp[target]`为 true，则存在有效分区
 - 否则，它不会

 ### 为什么它有效

 DP 不变量为：

 > 处理完第一条后`i`数字，`dp[s]`当且仅当这些数字的某个子集之和为 true`s`。 

最初，仅求和`0`是可以实现的。 每个新数字要么构成新的总和，要么不构成新的总和。 通过迭代更新可达总和，该算法最终一次捕获每个可实现的子集总和。 所以，`dp[target]`正确判断是否存在相等分区。 

## Python 解决方案```python
from typing import List

class Solution:
    def canPartition(self, nums: List[int]) -> bool:
        total_sum = sum(nums)

        # Equal partition is impossible if total sum is odd
        if total_sum % 2 != 0:
            return False

        target = total_sum // 2

        # dp[s] indicates whether sum s is achievable
        dp = [False] * (target + 1)
        dp[0] = True

        for num in nums:
            # Iterate backwards to avoid reusing the same number
            for current_sum in range(target, num - 1, -1):
                if dp[current_sum - num]:
                    dp[current_sum] = True

        return dp[target]
```实现首先计算数组的总和。 如果总和为奇数，函数立即返回`False`因为等分在数学上是不可能的。 

接下来，目标子集总和被计算为总和的一半。 然后初始化 DP 数组，其中每个索引表示是否可以实现特定的总和。 

该算法一次处理每个数字一个。 对于每个数字，它都会向后迭代 DP 数组。 这种向后遍历确保每个数字在每个子集计算中仅使用一次。 

每当先前可达到的总和`current_sum - num`存在，则当前总和也变得可达。 

最后，该函数返回目标总和是否可以实现。 

## 解决方案```go
func canPartition(nums []int) bool {
	totalSum := 0

	for _, num := range nums {
		totalSum += num
	}

	// Equal partition is impossible if total sum is odd
	if totalSum%2 != 0 {
		return false
	}

	target := totalSum / 2

	// dp[s] indicates whether sum s is achievable
	dp := make([]bool, target+1)
	dp[0] = true

	for _, num := range nums {
		// Iterate backwards to avoid reusing the same number
		for currentSum := target; currentSum >= num; currentSum-- {
			if dp[currentSum-num] {
				dp[currentSum] = true
			}
		}
	}

	return dp[target]
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

使用切片代替 Python 列表，布尔值默认为`false`，这简化了初始化。 整数溢出在这里不是一个问题，因为最大可能的总和仅为`20000`，完全在 Go 的整数范围内。 

后向迭代在 Go 中仍然至关重要，确保每个数字在每个子集计算中最多贡献一次。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * 目标) | 每个数字处理的所有总和达到目标 |
 | 空间| O（目标）| 一个 DP 数组，大小为 target + 1 |

 DP数组包含`target + 1`条目，其中`target`是总金额的一半。 由于最大总和是`20000`，最大目标是`10000`，这是可以管理的。 

对于数组中的每个元素，算法都会迭代所有可能的总和，直至达到目标。 因此，总体时间复杂度为`O(n * target)`。

 ## 边缘情况

 当总和为奇数时，会出现一种重要的边缘情况。 许多不正确的解决方案浪费时间尝试 DP 或递归，即使相等划分在数学上是不可能的。 实现立即处理这个问题：```
if total_sum % 2 != 0:
    return False
```另一个重要的情况是只有一个元素的数组。 单个正数不能分成两个总和相等的非空子集。 该算法自然会处理这个问题，因为要么总和是奇数，要么无法形成目标和。 

第三个棘手的情况涉及重复值。 例如：```
[10,10,10,10]
```向前迭代的不正确 DP 实现可能会在一次迭代中意外地多次重复使用同一元素。 此实现向后迭代，确保每个数字仅使用一次。 

另一个微妙的边缘情况是当目标总和以多种方式存在时。 例如：```
[3,3,3,4,5]
```DP 方法同时正确地跟踪所有可达和，因此它不依赖于发现特定的子集排序。 

最后，接近约束的大型压力测试输入需要有效的内存使用。 使用一维 DP 数组可降低空间复杂度`O(n * target)`到`O(target)`，即使对于最大的有效输入，该解决方案也具有实用性。
