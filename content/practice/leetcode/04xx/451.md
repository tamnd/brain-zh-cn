 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、排序、堆（优先级队列）、桶排序、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们重新排列字符串的字符，使频率较高的字符出现在频率较低的字符之前。 输出字符串必须将相同的字符分组在一起，并且这些组必须按出现次数的降序排列。 

例如，如果输入是`"tree"`, 字符`'e'`出现两次，同时`'t'`和`'r'`各出现一次。 自从`'e'`具有最高频率，它必须在输出中排在第一位。 有效输出包括`"eert"`和`"eetr"`。 

输入是单个字符串`s`，由大写字母、小写字母和数字组成。 输出是另一个包含完全相同字符的字符串，但根据频率重新排序。 

一个重要的细节是大写和小写字母被视为不同的字符。 例如，`'A'`和`'a'`分别对待。 

限制因素很重要：

 -`1 <= s.length <= 5 * 10^5`这意味着该字符串最多可以包含 500,000 个字符。 任何具有二次复杂度的解决方案（例如重复扫描字符串来计算频率）都会太慢。 我们需要一种接近线性或`O(n log n)`最坏的情况是。 

一些边缘情况很重要：

 - 只包含一个字符的字符串，例如`"a"`- 具有相同频率的多个字符
 - 包含同一字母的大写和小写版本的字符串
 - 非常大的投入，效率很重要
 - 每个字符都是唯一的字符串

 该问题保证输入字符串非空，因此我们永远不需要处理完全空的输入。 

## 方法

 ### 蛮力方法

 暴力解决方案将重复搜索字符串中最常见的剩余字符。 

一种方法是：

 1. 计算每个字符出现的次数。 
2. 找出出现频率最大的字符。 
3. 将其附加到结果中所需的次数。 
4. 将其从考虑中删除。 
5. 重复此操作，直至处理完所有字符。 

这种方法是正确的，因为每一步都会贪婪地将当前最常见的字符放在结果中的下一个字符中。 

然而，如果我们重复扫描频率图来找到最大剩余频率，算法就会变得低效。 在最坏的情况下，当存在许多独特字符时，重复搜索会增加总体成本。 

更简单的暴力方法甚至可以从头开始计算每个字符的频率，从而导致二次行为。 

鉴于约束规模较大，我们需要更有效的策略。 

### 最佳方法

 关键的观察是我们只需要两个操作：

 1.统计每个字符出现的频率
 2.按频率排序输出字符

 哈希图非常适合计算频率，因为它平均允许恒定时间插入和查找。 

计算频率后，我们可以按字符的计数降序对字符进行排序。 由于与总字符串长度相比，不同字符的数量是有限的，因此这变得高效。 

其过程是：

 - 构建频率图
 - 按频率对字符进行排序
 - 构造最终的字符串

 这避免了重复扫描并有效地处理输入。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(k) | 反复搜索出现频率最高的字符 |
 | 最佳| O(n + k log k) | O(n + k log k) | O(k) | 使用哈希映射并按频率排序 |

 这里，`n`是字符串长度，`k`是不同字符的数量。 

## 算法演练

 1. 创建哈希映射来存储字符频率。 

我们遍历字符串一次并计算每个字符出现的次数。 哈希映射是理想的选择，因为它提供高效的更新和查找。 
2. 将频率图转换为可排序的结构。 

计数后，每个条目包含一个字符及其频率。 我们需要按频率降序对这些条目进行排序。 
3. 按出现频率对字符进行排序。 

我们全部排序`(character, frequency)`配对，以便最常见的字符首先出现。 
4. 构建结果字符串。 

对于每个排序对：

 - 重复该字符`frequency`次
 - 将其附加到结果中

 这保证了所有相同的角色保持在一起。 
5. 返回最终的字符串。 

构造的字符串满足按频率排序所需的要求。 

### 为什么它有效

 该算法之所以有效，是因为首先计算每个字符的确切频率，并且排序步骤保证较高频率的字符先于较低频率的字符处理。 由于每个字符的附加次数与其在原始字符串中出现的次数完全相同，因此最终结果包含按有效频率顺序排列的所有原始字符。 

## Python 解决方案```python
class Solution:
    def frequencySort(self, s: str) -> str:
        frequency = {}

        # Count character frequencies
        for char in s:
            frequency[char] = frequency.get(char, 0) + 1

        # Sort characters by descending frequency
        sorted_chars = sorted(
            frequency.items(),
            key=lambda item: item[1],
            reverse=True
        )

        # Build result string
        result = []

        for char, count in sorted_chars:
            result.append(char * count)

        return "".join(result)
```实现首先创建一个名为的字典`frequency`。 字符串中的每个字符都会被处理一次，并且其计数会递增。 

这`sorted()`然后对字典项使用函数。 每个项目都是一个`(character, count)`一对。 排序键是频率值，并且`reverse=True`确保降序排列。 

一个名为`result`用于有效构建输出字符串。 在 Python 中，循环内的字符串串联效率很低，因为字符串是不可变的。 使用列表并在最后加入可以避免重复分配。 

对于每个`(character, count)`对，字符重复`count`次并附加到结果列表中。 

最后，`"".join(result)`将所有片段组合成最终的字符串。 

## 解决方案```go
package main

import (
	"sort"
	"strings"
)

func frequencySort(s string) string {
	frequency := make(map[rune]int)

	// Count frequencies
	for _, ch := range s {
		frequency[ch]++
	}

	// Convert map to slice
	type pair struct {
		char  rune
		count int
	}

	pairs := make([]pair, 0, len(frequency))

	for ch, count := range frequency {
		pairs = append(pairs, pair{ch, count})
	}

	// Sort by descending frequency
	sort.Slice(pairs, func(i, j int) bool {
		return pairs[i].count > pairs[j].count
	})

	// Build result
	var builder strings.Builder

	for _, p := range pairs {
		for i := 0; i < p.count; i++ {
			builder.WriteRune(p.char)
		}
	}

	return builder.String()
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但存在一些特定于语言的差异。 

Go 地图用于频率计数。 由于 Go 中的字符串是 UTF-8 编码的，因此迭代`range`产生符文而不是字节。 

由于 Go 映射无法直接排序，因此频率映射被转换为包含字符计数对的结构体切片。 

这`sort.Slice`函数按频率降序对切片进行排序。 

一个`strings.Builder`用于有效地构造最终字符串。 这避免了在串联期间重复的字符串分配。

 ## 边缘情况

 一种重要的边缘情况是所有字符都只出现一次，例如`"abcd"`。 在这种情况下，每个字符都有相同的频率，因此任何顺序都是有效的。 有缺陷的实现可能会错误地假设稳定的排序要求。 我们的实现自然地处理了这个问题，因为该问题明确允许多个有效输出。 

另一种重要的情况是当字符串只包含一个不同的字符时，例如`"aaaaaa"`。 某些实现意外地引入了不必要的排序逻辑或不正确的连接。 我们的解决方案正确地计算字符一次并重复输出所需的次数。 

区分大小写也是错误的常见来源。 在`"Aabb"`, 大写`'A'`和小写`'a'`必须单独对待。 由于频率图使用确切的字符作为键，因此实现自然可以正确区分它们。 

最后一个重要的边缘情况是非常大的输入大小。 由于字符串长度可以达到 500,000 个字符，循环内低效的字符串连接可能会变得非常慢。 两种实现都通过使用高效的字符串构建技术来避免这个问题，特别是 Python 中的列表连接和`strings.Builder`在围棋中。
