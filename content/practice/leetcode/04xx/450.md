[LeetCode 450 题](https://leetcode.com/problems/delete-node-in-a-bst/)

 **难度：** 🟡 中等
 **主题：** 树、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 问题要求我们删除具有特定值的节点，`key`，来自二叉搜索树（缩写为 BST），并返回树的可能更新的根。 

二叉搜索树有一个重要的排序属性：

 - 左子树中的每个节点都包含小于当前节点的值。 
- 右子树中的每个节点都包含比当前节点大的值。 

由于所有节点值都是唯一的，因此值所属位置永远不会含糊不清。 

输入包括：

 -`root`，BST的根节点
 -`key`，我们要从树中删除的值

 输出应该是删除后更新的 BST 的根节点。 在某些情况下，根本身可能会被删除，因此返回的根可能与原始根不同。 

主要挑战是删除后保留 BST 属性。 从普通二叉树中删除节点很简单，但在 BST 中，我们必须小心地重新连接剩余节点，以便排序保持有效。 

删除场景主要有以下三种：

 1. 树中不存在该节点。 
2. 该节点有零个或一个子节点。 
3. 该节点有两个子节点。 

第三种情况是最重要的，因为简单地删除节点就会断开整个子树或违反 BST 排序。 

约束告诉我们树最多可以包含`10^4`节点，其足够大以至于低效的重建方法变得不可取。 后续具体要求`O(height of tree)`复杂性，这强烈暗示我们应该利用 BST 排序，而不是不必要地遍历整个树。 

一些边缘情况很重要：

 - 树可能是空的。 
- 密钥可能不存在。 
- 要删除的节点可能是根节点。 
- 该节点可能没有子节点。 
- 该节点可能只有一个子节点。 
- 该节点可以有两个子节点。 
- BST 可能高度不平衡，实际上表现为链表。 

正确的实现必须安全地处理所有这些问题，同时维护 BST 结构。 

## 方法

 ### 蛮力方法

 暴力解决方案会忽略大部分 BST 结构。 一种可能的策略是：

 1. 遍历整棵树，收集除被删除节点外的所有节点值。 
2. 通过将所有剩余值一一插入来重建新的 BST。 

这种方法之所以有效，是因为将值插入 BST 会重建有效的 BST 结构。 如果删除的密钥存在，则在重建时将其简单地忽略。 

然而，由于以下几个原因，这种方法效率低下：

 - 即使键位于根附近，我们也会遍历整棵树。 
- 我们分配额外的内存来存储所有值。 
- 重建 BST 需要重复插入。 
- 在最坏的情况下，重建可能会退化为`O(n^2)`。 

蛮力方法忽略了 BST 的关键优势，即基于排序的高效搜索和修改。 

### 最佳 BST 删除方法

 更好的解决方案是直接使用 BST 性质。 

由于较小的值总是在左侧，较大的值总是在右侧，因此我们可以将目标节点定位在`O(height)`时间。 

一旦找到节点，删除取决于节点的结构：

 - 如果该节点没有子节点，则直接删除它。 
- 如果该节点有一个子节点，则用其子节点替换该节点。 
- 如果该节点有两个子节点，则将其值替换为中序后继节点，然后删除后继节点。 

中序后继是右子树中最小的节点。 使用它可以保证 BST 排序仍然有效，因为：

 - 左子树中的每个节点仍然较小。 
- 右子树中的每个节点仍然更大。 

这使我们能够删除节点，同时有效地保留 BST 不变量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况 | O(n²) O(n) | 遍历树、存储值、重建 BST |
 | 最佳| O(h) | O(h) 递归堆栈 | 使用 BST 排序进行高效删除 |

 这里，`h`代表树的高度。 

## 算法演练

 1、从根节点开始比较`key`与当前节点的值。 

如果`key`如果较小，则移至左子树，因为 BST 排序保证目标只能存在于左子树中。 

如果`key`更大，出于同样的原因移动到右子树。 
2. 继续递归直到：

 - 找到节点。 
- A`None`到达节点，意味着键不存在。 
3. 找到目标节点后，检查其子节点。 

如果该节点没有左子节点，则返回其右子节点。 

这有效地删除了该节点并将父节点直接重新连接到右子树。 
4. 如果该节点没有右子节点，则返回其左子节点。 

这反映了之前的情况。 
5. 如果该节点同时有左子节点和右子节点，则查找中序后继节点。 

中序后继是右子树中最小的节点，通过反复左移找到。 
6. 将中序后继值复制到当前节点。 

我们还没有物理地移动后继节点。 相反，我们覆盖当前节点的值。 
7. 递归地从右子树中删除中序后继。 

由于后继节点是右子树中最小的节点，因此它永远不会有左子节点，从而使其删除更简单。 
8. 所有子树更新完成后返回当前节点。 

### 为什么它有效

 该算法在每一步都保持 BST 不变。 

遍历时，BST 排序保证我们只搜索从根到叶的一条路径。 

删除时：

 - 用单个子节点替换节点可以保留排序，因为子树已经有效。 
- 使用中序后继进行两个子删除可以保留排序，因为它是排序顺序中下一个较大的值。 

因此，删除后，每个节点仍然满足：

 - 左子树值较小。 
- 右子树值更大。 

因此，生成的结构仍然是有效的 BST。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def deleteNode(
        self,
        root: Optional[TreeNode],
        key: int
    ) -> Optional[TreeNode]:

        if root is None:
            return None

        if key < root.val:
            root.left = self.deleteNode(root.left, key)

        elif key > root.val:
            root.right = self.deleteNode(root.right, key)

        else:
            # Node with only right child or no child
            if root.left is None:
                return root.right

            # Node with only left child
            if root.right is None:
                return root.left

            # Node with two children
            successor = self.findMin(root.right)

            root.val = successor.val

            root.right = self.deleteNode(root.right, successor.val)

        return root

    def findMin(self, node: TreeNode) -> TreeNode:
        while node.left:
            node = node.left
        return node
```实现从递归 BST 搜索逻辑开始。 在每个节点，我们比较`key`反对`root.val`。 

如果键较小，则算法递归处理左子树。 如果更大，则处理右子树。 这利用了 BST 排序来避免不必要的遍历。 

当找到目标节点时，实现会仔细处理删除情况。 

如果该节点缺少左孩子，则直接返回右孩子。 这将父节点与剩余的子树重新连接。 

如果该节点缺少右子节点，则左子节点将替换它。 

最有趣的情况发生在两个孩子都存在的情况下。 该算法使用以下方法找到中序后继者`findMin`，它走到右子树中最左边的节点。 

当前节点的值将替换为后继节点的值。 然后后继节点本身从右子树中递归删除。 

最后，每次递归调用都会返回更新的子树根，确保父指针在整个递归过程中保持正确。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func deleteNode(root *TreeNode, key int) *TreeNode {
    if root == nil {
        return nil
    }

    if key < root.Val {
        root.Left = deleteNode(root.Left, key)
    } else if key > root.Val {
        root.Right = deleteNode(root.Right, key)
    } else {

        // No left child
        if root.Left == nil {
            return root.Right
        }

        // No right child
        if root.Right == nil {
            return root.Left
        }

        // Two children
        successor := findMin(root.Right)

        root.Val = successor.Val

        root.Right = deleteNode(root.Right, successor.Val)
    }

    return root
}

func findMin(node *TreeNode) *TreeNode {
    for node.Left != nil {
        node = node.Left
    }

    return node
}
```Go 实现与 Python 逻辑非常相似，但存在一些特定于语言的差异。 

Go 使用`nil`而不是`None`对于空指针。 树节点使用显式指针进行操作，因此子树更新是通过指针重新分配进行的。 

与 Python 不同，Go 自然不支持函数内嵌套辅助方法，因此`findMin`作为一个单独的函数实现。 

整数溢出在这里不是问题，因为节点值仍然在问题约束之内。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(h) | 只需要一次从根到叶的遍历 |
 | 空间| O(h) | 递归调用堆栈深度等于树高 |

 该算法在搜索节点时仅遍历 BST 的单条路径。 即使删除具有两个子节点的节点，查找中序后继节点也遵循单一的向下路径。 

因此，总工作量与树高成正比`h`。 

在平衡 BST 中，高度为`O(log n)`。 在最坏的情况下，不平衡的 BST 可能会退化为高度`O(n)`。 

递归实现使用与递归深度成比例的调用堆栈空间，这也是`O(h)`。

 ## 边缘情况

 ### 删除根节点

 删除根通常是错误的来源，因为树的入口点可能会改变。 如果实现仅更新子指针而不返回新的子树根，则调用者可能会保留过时的引用。 

此实现通过始终从递归调用返回更新的根来避免该问题。 如果根被删除并被其子节点之一替换，则调用者会收到正确的新根。 

### 删除有两个子节点的节点

 这是最复杂的场景，因为直接删除节点会断开子树或违反 BST 排序。 

该实现通过用中序后继替换节点的值来处理此问题，这保证是按排序顺序的下一个较大值。 然后从右子树递归地删除后继节点。 

由于后继节点是右子树中最小的节点，因此 BST 排序在替换后仍然有效。 

### 密钥不存在

 幼稚的实现可能会在搜索密钥失败时意外修改树。 

该解安全地遍历 BST，直到到达`None`。 At that point, recursion unwinds without changing any pointers, so the original tree structure remains intact.

 ### 空树

 一棵空树表示为`root = None`。 在不检查此条件的情况下尝试访问子指针或节点值将导致运行时错误。 

执行立即返回`None`当根为空时，使操作安全高效。
