[LeetCode 第 413 题](https://leetcode.com/problems/arithmetic-slices/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个长度至少为 3 的连续子数组构成一个算术序列。 

算术序列是每对相邻元素之间的差异相同的序列。 例如：

-`[1, 3, 5, 7]`有一个恒定的差异`2`-`[7, 7, 7, 7]`有一个恒定的差异`0`-`[5, 1, -3]`有一个恒定的差异`-4`我们给定一个整数数组`nums`，并且我们必须计算满足此属性的每个连续子数组。 

重要的细节是我们计算的是子数组，而不是子序列。 子数组必须由原始数组中的连续元素组成。 

例如，在`nums = [1,2,3,4]`，有效的算术切片是：

 -`[1,2,3]`-`[2,3,4]`-`[1,2,3,4]`所以答案是`3`。 

这些约束告诉我们一些重要的事情：

 -`nums.length`可以达到`5000`- 强力三次解可能会变得太慢
 - 数字本身很小，但长度足够大，算法效率很重要

 最重要的边缘情况包括：

 - 元素少于三个的数组，因为它们永远无法形成算术切片
 - 所有值都相同的数组，因为每个足够长的子数组都变成算术数组
 - 算术模式反复中断和重新启动的数组
 - 负差异，因为算术序列不限于递增数字

 ## 方法

 ### 蛮力方法

 蛮力的想法是检查长度至少为三的每个可能的子数组，并检查它是否是算术。 

我们可以使用两个嵌套循环生成所有子数组：

 - 选择起始索引
 - 选择结束索引

 对于每个子数组，我们使用前两个元素计算公差，然后验证每个相邻对是否具有相同的差。 

这种方法是正确的，因为它显式地检查每个可能的候选子数组。 

然而，它的效率很低。 有`O(n^2)`子数组，检查每个子数组可能需要`O(n)`时间。 这导致总复杂度为`O(n^3)`在最坏的情况下。 

和`n = 5000`，这变得太慢了。 

### 最优动态规划方法

 关键的观察是算术切片可以增量扩展。 

假设我们已经知道一个以索引结尾的子数组`i - 1`形成算术切片。 如果：```
nums[i] - nums[i-1] == nums[i-1] - nums[i-2]
```那么任何结束于的算术切片`i - 1`可以通过以下方式扩展`nums[i]`。 

此外，新的三重：```
nums[i-2], nums[i-1], nums[i]
```也形成一个新的算术切片。 

这意味着我们可以维护：

 -`current`, 以当前索引结尾的算术切片的数量
 -`total`, 总计数

 如果算术条件成立：```
current += 1
total += current
```否则：```
current = 0
```这使我们能够一次性处理该数组。

 ## 算法演练

 1. 首先，处理数组长度小于的小情况`3`。 

由于算术切片需要至少三个元素，因此我们立即返回`0`。 
2.初始化两个变量：

 -`current`, 以当前位置结束的算术切片的数量
 -`total`, 迄今为止找到的算术切片总数

 最初，两者都是`0`。 
3. 从索引开始迭代数组`2`。 

我们从索引开始`2`因为我们至少需要三个元素才能形成算术切片。 
4. 对于每个索引`i`，比较连续差异：```
nums[i] - nums[i-1]
nums[i-1] - nums[i-2]
```如果它们相等，则序列继续算术模式。 
5. 当差异匹配时：

 - 增量`current`经过`1`- 添加`current`到`total`这是有效的，因为之前的每个算术切片都以`i-1`现在可以扩展到`i`，新的长度为 3 的切片也计算在内。 
6. 如果差异不匹配：

 - 重置`current`到`0`这意味着算术链已经断裂。 
7.处理完所有索引后，返回`total`。 

### 为什么它有效

 该算法保持不变式`current`始终表示以当前索引结尾的算术切片的数量。 

如果算术属性在索引处继续`i`，然后每个有效切片结束于`i-1`扩展到一个新的有效切片，结束于`i`。 此外，最新的长度为 3 的切片将变得有效。 因此，新切片的数量比之前增加了整整一个。 

如果算术属性中断，则算术切片无法继续通过当前索引，因此`current`重置为零。 

因为每个算术切片在处理其结束索引时只计算一次，所以最终的总数是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def numberOfArithmeticSlices(self, nums: List[int]) -> int:
        n = len(nums)

        if n < 3:
            return 0

        current = 0
        total = 0

        for i in range(2, n):
            if nums[i] - nums[i - 1] == nums[i - 1] - nums[i - 2]:
                current += 1
                total += current
            else:
                current = 0

        return total
```实现首先检查数组是否包含至少三个元素。 如果不是，函数立即返回`0`。 

变量`current`跟踪有多少算术切片在当前索引处结束。 变量`total`累积最终答案。 

循环从索引处开始`2`因为算术切片需要三个连续的元素。 在每个步骤中，代码都会比较相邻的差异。 

当差异匹配时，算术序列继续。 代码递增`current`，因为之前的每个算术切片都可以扩展一个元素。 然后它添加`current`到`total`。 

当差异不同时，算术链就会断裂，所以`current`重置为零。 

最后，该函数返回累计总数。 

## 解决方案```go
func numberOfArithmeticSlices(nums []int) int {
	n := len(nums)

	if n < 3 {
		return 0
	}

	current := 0
	total := 0

	for i := 2; i < n; i++ {
		if nums[i]-nums[i-1] == nums[i-1]-nums[i-2] {
			current++
			total += current
		} else {
			current = 0
		}
	}

	return total
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 切片已经跟踪它们的长度，所以我们使用`len(nums)`判断数组是否足够大。 

整数溢出在这里不是一个问题，因为约束足够小，总计数可以轻松地适合 Go 的范围`int`类型。 

该解决方案仅使用恒定的额外空间并执行一次遍历数组。

 ## 边缘情况

 一种重要的边缘情况是元素少于三个的数组。 由于算术切片的定义需要至少三个数字，因此这些输入必须立即返回`0`。 幼稚的实现可能会意外地将对视为有效序列。 该解决方案通过检查开头的长度来避免这种情况。 

另一个重要的边缘情况是每个元素都相同的数组，例如`[7,7,7,7]`。 这里，共同的区别是`0`，这仍然是一个有效的算术级数。 某些实现错误地假设差异必须非零。 该解决方案只是比较相邻差异，因此零差异自然有效。 

当算术模式中断并稍后恢复时，会出现第三种重要的边缘情况，例如`[1,2,3,8,9,10]`。 实施正确重置`current`每当差异改变时为零。 这可以防止无效切片跨越断开的算术区域。 

第四种微妙的边缘情况涉及重叠算术切片。 例如，`[1,2,3,4,5]`包含许多共享元素的有效子数组。 幼稚的实现可能会低估这些重叠序列。 动态规划方法可以正确处理这个问题，因为`current`跟踪每个位置结束的算术切片数量，自动计算所有重叠。
