[LeetCode 第 439 题](https://leetcode.com/problems/ternary-expression-parser/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、递归

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个表示嵌套三元表达式的字符串，并要求我们对其求值。 三元表达式遵循熟悉的格式：```
condition ? value_if_true : value_if_false
```条件总是要么`'T'`或者`'F'`。 如果条件是`'T'`，表达式的计算结果为之前的值`':'`。 如果条件是`'F'`，它计算出之后的值`':'`。 

重要的复杂性是表达式可以任意深度地嵌套。 例如：```
F?1:T?4:5
```被解释为：```
F ? 1 : (T ? 4 : 5)
```因为三元表达式是从右到左关联的。 

输入字符串仅包含：

 - 数字来自`0`到`9`-`'T'`和`'F'`-`'?'`-`':'`每个数值都保证是单个数字，这简化了解析，因为我们永远不需要读取多字符数字。 

约束允许表达式达到最大长度`10^4`，这意味着递归重新解析或重复字符串切片可能会变得昂贵。 我们需要一个高效的线性时间解决方案。 

一些边缘情况尤其重要：

 - 深度嵌套的表达式，例如`"T?T?T?1:2:3:4"`- 仅最右分支重要的表达式
 - 交替真假条件
 - 最小有效表达式，例如`"T?2:3"`该问题保证表达式始终有效，这意味着我们永远不需要处理格式错误的语法。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是重复定位并计算最里面的三元表达式。 

例如：```
F?1:T?4:5
```我们可以首先确定：```
T?4:5
```将其评估为`4`，然后替换子字符串：```
F?1:4
```最后再次评估。 

这是有效的，因为嵌套三元表达式在求值后总是减少为单个值。 

然而，重复扫描字符串并重建子字符串效率很低。 每次更换可能会产生费用`O(n)`，并且我们可能会执行许多此类操作，从而在最坏的情况下导致二次复杂度。 

输入尺寸高达`10^4`，这会变得不必要的缓慢。 

### 最佳方法

 关键的观察结果是三元表达式从右到左关联。 

例如：```
T?T?F:5:3
```应解释为：```
T ? (T ? F : 5) : 3
```这自然建议从右到左处理字符串。 

堆栈在这里工作得非常好。 当我们向后扫描时：

 - 操作数被压入堆栈
 - 当我们遇到某种情况时（`T`或者`F`) 后面跟着一个`'?'`，我们已经在堆栈上有了正确和错误的结果
 - 我们立即评估并将所选结果推回

 这允许每个字符被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复重新解析和重建字符串 |
 | 最佳| O(n) | O(n) | 使用从右到左的堆栈遍历 |

 ## 算法演练

 1. 初始化一个空堆栈。 

堆栈将存储部分评估的结果。 由于每个表达式最终计算结果为单个字符，因此每个堆栈元素只是一个字符。 
2. 从右向左遍历表达式。 

从右到左的遍历符合三元表达式的自然结合性。 当我们遇到一个条件时，它的 true 和 false 分支已经被处理了。 
3. 对于每个字符，检查它是否开始三元运算。 

具体来说，如果当前字符是`'T'`或者`'F'`，下一个字符是`'?'`，那么我们正在查看一个条件表达式。 
4. 从堆栈中弹出 true 和 false 分支。 

堆栈布局将如下所示：```
[ ..., true_value, false_value ]
```因为表达式是从右到左处理的。 
5. 评估状况。 

- 如果条件是`'T'`,选择真正的分支
 - 否则选择错误分支

 将选定的值推回到堆栈中。 
6. 忽略`':'`和`'?'`正常遍历期间的字符。 

它们仅有助于识别表达结构。 
7. 将文字值压入堆栈。 

数字，`'T'`， 和`'F'`那些不是条件的被视为值。 
8. 遍历完成后，堆栈中恰好包含一个值。 

该值就是最终的结果。 

### 为什么它有效

 正确性依赖于从右到左的关联性。 处理条件时，堆栈已包含两个分支的完整评估结果。 用所选分支替换三元表达式可以保留原始表达式的含义。 重复此减少最终会将整个表达式折叠为单个值。 

## Python 解决方案```python
class Solution:
    def parseTernary(self, expression: str) -> str:
        stack: list[str] = []

        i = len(expression) - 1

        while i >= 0:
            current = expression[i]

            # If current character is a condition
            if (
                current in ("T", "F")
                and i + 1 < len(expression)
                and expression[i + 1] == "?"
            ):
                true_value = stack.pop()
                false_value = stack.pop()

                if current == "T":
                    stack.append(true_value)
                else:
                    stack.append(false_value)

                i -= 1  # Skip '?'
            elif current not in ("?", ":"):
                stack.append(current)

            i -= 1

        return stack[-1]
```该实现直接反映了算法。 

我们维护一堆评估值。 从右向左遍历可确保嵌套表达式在外部表达式之前得到解析。 

关键部分是：```python
if current in ("T", "F") and expression[i + 1] == "?":
```这可以识别当前字符是否充当条件而不仅仅是值。 

当找到这样的条件时，我们从堆栈中弹出两个值。 由于从右向左遍历：

 - 第一个弹出的值对应于真实分支
 - 第二个对应于错误分支

 然后我们根据条件选择正确的结果并将其推回。 

人物`':'`和`'?'`是结构标记，不需要存储。 

最后，堆栈包含完整评估的结果。 

## 解决方案```go
func parseTernary(expression string) string {
	stack := []byte{}

	for i := len(expression) - 1; i >= 0; i-- {
		current := expression[i]

		// Check if current character is a condition
		if (current == 'T' || current == 'F') &&
			i+1 < len(expression) &&
			expression[i+1] == '?' {

			trueValue := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			falseValue := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			if current == 'T' {
				stack = append(stack, trueValue)
			} else {
				stack = append(stack, falseValue)
			}

			i-- // Skip '?'
		} else if current != '?' && current != ':' {
			stack = append(stack, current)
		}
	}

	return string(stack[len(stack)-1])
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用字节切片作为堆栈。 

因为所有字符都是单字节 ASCII 值，所以使用`[]byte`效率很高并且避免了不必要的字符串分配。 

堆栈弹出是通过切片截断实现的：```go
stack = stack[:len(stack)-1]
```最后的字节在返回之前被转换回字符串。

 ## 边缘情况

 一种重要的边缘情况是深度嵌套的右关联表达式。 天真的从左到右解析器可能会错误地解释：```
T?T?1:2:3
```作为：```
(T ? T ? 1 : 2) : 3
```而不是正确的：```
T ? (T ? 1 : 2) : 3
```从右到左的遍历自然可以正确地处理这种关联性，因为内部表达式在外部表达式之前被评估。 

另一个微妙的情况是当`'T'`或者`'F'`显示为值而不是条件。 例如：```
T?F:5
```在这里，内在`'F'`不是一个条件。 不正确的实现可能会尝试对待每一个`'T'`或者`'F'`作为三元运算的开始。 该实现通过检查下一个字符是否是来避免这种情况`'?'`。 

第三个重要的情况是在最大输入大小附近非常深的嵌套。 如果嵌套深度变大，递归解决方案可能会面临堆栈溢出的风险。 基于迭代堆栈的解决方案完全避免了递归，使得长度可达的表达式是安全的`10^4`。
