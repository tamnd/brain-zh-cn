[LeetCode 第 432 题](https://leetcode.com/problems/all-oone-data-struct/)

 **难度：** 🔴难
 **主题：** 哈希表、链表、设计、双向链表

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种特殊的数据结构，用于存储字符串键及其出现次数。 该结构必须支持递增和递减计数，同时还能够立即检索具有最大计数的一个键和具有最小计数的一个键。 

与普通的频率计数问题不同，该问题对性能提出了严格的要求。 每个操作必须平均运行`O(1)`时间复杂度。 这意味着当我们需要最小或最大计数时，我们无法扫描所有键。 

这些操作的行为如下：

 -`inc(key)`增加频率`key`一个。 
- 如果键不存在，则应使用计数插入`1`。 
-`dec(key)`减少频率`key`一个。 
- 如果频率变为`0`，钥匙必须完全移除。 
-`getMaxKey()`返回频率最高的任意键。 
-`getMinKey()`返回频率最低的任意键。 

LeetCode 中的输入表示为一系列操作和参数。 输出包含生成一个操作的每个操作的返回值。 

这些约束很重要，因为它们消除了许多更简单的方法：

 - 最多`5 * 10^4`可以发生操​​作。 
- 每项操作都必须高效。 
- 键是短的小写字符串。 
- 该问题保证`dec()`仅在现有键上调用。 

这个问题最难的部分是动态维护最小和最大频率，同时支持恒定时间更新。 

一些边缘情况尤其重要：

 - 增加一个全新的密钥。 
- 减少计数变为零的键。 
- 在删除频率桶中的最后一个键后保持正确的最小值和最大值。 
- 以相同的频率处理多个按键。 
- 当结构变空时返回空字符串。 

当频率频繁变化时，简单的实现很容易变得低效或不一致。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用从键到计数的哈希映射。 

每当`inc()`或者`dec()`被调用后，我们只需更新地图中的计数即可。 那么，当`getMaxKey()`或者`getMinKey()`被调用时，我们扫描哈希映射中的每个键以查找最大或最小计数。 

这种方法是正确的，因为映射始终存储每个键的最新计数。 完整扫描可确保我们找到正确的最小值或最大值。 

然而，这种方法太慢，因为扫描所有键需要`O(n)`时间、地点`n`是不同键的数量。 由于截至`5 * 10^4`操作可能会发生，重复扫描在最坏的情况下可能会导致二次行为。 

### 最佳方法

 关键的见解是我们需要始终直接访问最小和最大的频率组。 

我们不是只存储单个密钥计数，而是按频率对密钥进行分组。 我们维持：

 - 频率桶的双向链表。 
- 每个桶存储：

 - 频率计数。 
- 具有该频率的一组键。 
- 从键到其当前存储桶的哈希映射。 

链表按频率从小到大排序。 由于这个顺序：

 - 第一个真实桶始终包含最小频率。 
- 最后一个真实的桶总是包含最大频率。 

当一个键改变频率时，我们会以恒定的时间在相邻的存储桶之间移动它。 

这种设计之所以有效，是因为频率只会改变`+1`或者`-1`，这意味着键只能移动到相邻的存储桶。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n)`每个查询|`O(n)`| 扫描所有键以查找最小/最大 |
 | 最佳 |`O(1)`每次操作的平均值|`O(n)`| 频率桶双向链表|

 ## 算法演练

 ### 数据结构

 我们使用三个核心组件：

 - 按频率排序的桶的双向链表。 
- 从键到存储桶节点的哈希映射。 
- 每个存储桶内的一组存储具有该频率的所有密钥。 

每个桶节点包含：

 -`count`-`keys`-`prev`-`next`我们还使用虚拟头节点和尾节点来简化插入和删除逻辑。 

### 逐步算法

 1. 用虚拟头节点和尾节点初始化链表。 

头部表示小于所有有效计数的值，尾部表示大于所有有效计数的值。 这消除了插入或移除存储桶时的边缘情况检查。 
2.维护从key到bucket节点的hash映射。 

这允许对密钥的当前频率桶进行恒定时间查找。 
3. 手柄`inc(key)`换一把新钥匙。 

如果密钥不存在：

 - 检查第一个真实的桶是否有计数`1`。 
- 如果没有，则创建一个带有计数的新存储桶`1`。 
- 将钥匙插入该桶中。 
- 存储从键到存储桶的映射。 
4. 手柄`inc(key)`对于现有的密钥。 

- 使用哈希映射定位当前存储桶。 
- 确定目标频率，即`current_count + 1`。 
- 检查下一个存储桶是否已经具有该频率。 
- 如果没有，则创建一个新的存储桶并将其插入到当前存储桶之后。 
- 将钥匙移入新桶中。 
- 从旧桶中取出钥匙。 
- 如果旧桶变空，则将其从链表中删除。 
5. 手柄`dec(key)`。 

- 找到当前存储桶。 
- 如果当前计数是`1`，从哈希图中完全删除该键。 
- 否则：

 - 确定目标频率，即`current_count - 1`。 
- 检查前一个桶是否已经有该频率。 
- 如果没有，则创建一个新的存储桶并将其插入到当前存储桶之前。 
- 将密钥移至目标存储桶中。 
- 更新哈希图。 
- 从旧桶中取出钥匙。 
- 如果旧桶变空，则将其从链表中删除。 
6. 手柄`getMaxKey()`。 

最大频率桶紧接在尾虚拟节点之前。 返回该存储桶中的任何密钥。 
7. 手柄`getMinKey()`。 

最小频率桶紧接在头虚拟节点之后。 返回该存储桶中的任何密钥。 

### 为什么它有效

 链表始终保持按频率排序。 每个键都恰好驻留在一个表示其当前计数的存储桶中。 由于频率一次仅改变一个，因此密钥仅在相邻存储桶之间移动。 因此，头和​​尾邻居总是代表最小和最大频率。 每次更新仅修改本地结构，这保证了恒定的平均时间复杂度。 

## Python 解决方案```python
class Node:
    def __init__(self, count: int):
        self.count = count
        self.keys = set()
        self.prev = None
        self.next = None

class AllOne:

    def __init__(self):
        self.head = Node(0)
        self.tail = Node(0)

        self.head.next = self.tail
        self.tail.prev = self.head

        self.key_to_node = {}

    def _insert_after(self, node: Node, new_node: Node) -> None:
        new_node.prev = node
        new_node.next = node.next

        node.next.prev = new_node
        node.next = new_node

    def _remove_node(self, node: Node) -> None:
        node.prev.next = node.next
        node.next.prev = node.prev

    def inc(self, key: str) -> None:
        if key not in self.key_to_node:
            if self.head.next != self.tail and self.head.next.count == 1:
                node = self.head.next
            else:
                node = Node(1)
                self._insert_after(self.head, node)

            node.keys.add(key)
            self.key_to_node[key] = node

        else:
            current = self.key_to_node[key]
            next_count = current.count + 1

            if current.next != self.tail and current.next.count == next_count:
                next_node = current.next
            else:
                next_node = Node(next_count)
                self._insert_after(current, next_node)

            next_node.keys.add(key)
            self.key_to_node[key] = next_node

            current.keys.remove(key)

            if not current.keys:
                self._remove_node(current)

    def dec(self, key: str) -> None:
        current = self.key_to_node[key]

        if current.count == 1:
            del self.key_to_node[key]
        else:
            prev_count = current.count - 1

            if current.prev != self.head and current.prev.count == prev_count:
                prev_node = current.prev
            else:
                prev_node = Node(prev_count)
                self._insert_after(current.prev, prev_node)

            prev_node.keys.add(key)
            self.key_to_node[key] = prev_node

        current.keys.remove(key)

        if not current.keys:
            self._remove_node(current)

    def getMaxKey(self) -> str:
        if self.tail.prev == self.head:
            return ""

        return next(iter(self.tail.prev.keys))

    def getMinKey(self) -> str:
        if self.head.next == self.tail:
            return ""

        return next(iter(self.head.next.keys))

# Your AllOne object will be instantiated and called as such:
# obj = AllOne()
# obj.inc(key)
# obj.dec(key)
# param_3 = obj.getMaxKey()
# param_4 = obj.getMinKey()
```实现首先定义一个`Node`表示频率桶的类。 每个节点存储一个计数和一组当前共享该计数的键。 

这`AllOne`类维护虚拟头节点和尾节点以简化链表操作。 这可以防止在开头或结尾插入时出现特殊情况逻辑。 

辅助方法`_insert_after()`直接在给定节点之后插入一个新存储桶。 这`_remove_node()`helper 从链表中删除一个空桶。 

这`inc()`方法处理两种情况。 对于新密钥，它会重用现有的频率 1 存储桶或创建一个。 对于现有密钥，它将密钥移动到下一个频率存储桶中，并在必要时创建该存储桶。 

这`dec()`方法反过来反映了这个逻辑。 带计数的按键`1`被完全删除。 否则，它们将移至前一个频率桶。 

这`getMaxKey()`和`getMinKey()`方法非常有效，因为链表总是按频率排序。 最大桶总是与尾部相邻，最小桶总是与头部相邻。 

## 解决方案```go
package main

type Node struct {
	count int
	keys  map[string]bool
	prev  *Node
	next  *Node
}

type AllOne struct {
	head      *Node
	tail      *Node
	keyToNode map[string]*Node
}

func Constructor() AllOne {
	head := &Node{
		keys: make(map[string]bool),
	}

	tail := &Node{
		keys: make(map[string]bool),
	}

	head.next = tail
	tail.prev = head

	return AllOne{
		head:      head,
		tail:      tail,
		keyToNode: make(map[string]*Node),
	}
}

func (this *AllOne) insertAfter(node *Node, newNode *Node) {
	newNode.prev = node
	newNode.next = node.next

	node.next.prev = newNode
	node.next = newNode
}

func (this *AllOne) removeNode(node *Node) {
	node.prev.next = node.next
	node.next.prev = node.prev
}

func (this *AllOne) Inc(key string) {
	if current, exists := this.keyToNode[key]; !exists {

		var node *Node

		if this.head.next != this.tail && this.head.next.count == 1 {
			node = this.head.next
		} else {
			node = &Node{
				count: 1,
				keys:  make(map[string]bool),
			}
			this.insertAfter(this.head, node)
		}

		node.keys[key] = true
		this.keyToNode[key] = node

	} else {

		nextCount := current.count + 1

		var nextNode *Node

		if current.next != this.tail && current.next.count == nextCount {
			nextNode = current.next
		} else {
			nextNode = &Node{
				count: nextCount,
				keys:  make(map[string]bool),
			}
			this.insertAfter(current, nextNode)
		}

		nextNode.keys[key] = true
		this.keyToNode[key] = nextNode

		delete(current.keys, key)

		if len(current.keys) == 0 {
			this.removeNode(current)
		}
	}
}

func (this *AllOne) Dec(key string) {
	current := this.keyToNode[key]

	if current.count == 1 {
		delete(this.keyToNode, key)
	} else {

		prevCount := current.count - 1

		var prevNode *Node

		if current.prev != this.head && current.prev.count == prevCount {
			prevNode = current.prev
		} else {
			prevNode = &Node{
				count: prevCount,
				keys:  make(map[string]bool),
			}
			this.insertAfter(current.prev, prevNode)
		}

		prevNode.keys[key] = true
		this.keyToNode[key] = prevNode
	}

	delete(current.keys, key)

	if len(current.keys) == 0 {
		this.removeNode(current)
	}
}

func (this *AllOne) GetMaxKey() string {
	if this.tail.prev == this.head {
		return ""
	}

	for key := range this.tail.prev.keys {
		return key
	}

	return ""
}

func (this *AllOne) GetMinKey() string {
	if this.head.next == this.tail {
		return ""
	}

	for key := range this.head.next.keys {
		return key
	}

	return ""
}

/**
 * Your AllOne object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Inc(key);
 * obj.Dec(key);
 * param_3 := obj.GetMaxKey();
 * param_4 := obj.GetMinKey();
 */
```Go 实现遵循与 Python 版本相同的设计，但存在一些特定于语言的差异。 

Go 没有内置的集合类型，因此我们使用以下方式模拟集合`map[string]bool`。 

Go 没有使用 Python 的动态引用，而是明确使用指针作为链表节点。 

当从存储桶中检索键时，Go 会迭代映射并立即返回遇到的第一个键。 

内存管理由 Go 的垃圾收集器自动处理，因此删除的节点不需要显式释放。

 ## 边缘情况

 当递减计数变为零的键时，会出现一种重要的边缘情况。 这是错误的常见来源，因为必须从其存储桶和全局哈希映射中删除密钥。 如果桶也变空了，则桶本身必须从链表中删除。 该实现通过首先更新或删除键映射，然后从存储桶中删除键，最后在必要时删除存储桶来处理此问题。 

当插入全新的钥匙时，会出现另一种棘手的情况。 如果不存在频率为 1 的桶，则必须在头节点之后直接插入一个新桶。 如果无法在此处保持排序顺序将会中断`getMinKey()`。 该实现显式检查第一个真实存储桶是否已经有计数`1`在决定创建新存储桶之前。 

当多个键共享相同频率时，会发生第三种边缘情况。 幼稚的实现可能会意外地创建具有相同计数的重复存储桶。 此实现通过在创建新存储桶之前始终检查相邻存储桶来避免这种情况。 由于频率仅改变一，因此正确的目标桶只能与当前桶相邻。 

最后一个重要的情况是当结构变空时。 两个都`getMaxKey()`和`getMinKey()`必须返回一个空字符串而不是导致错误。 虚拟头节点和尾节点使此检查变得简单，因为空结构始终满足`head.next == tail`。
