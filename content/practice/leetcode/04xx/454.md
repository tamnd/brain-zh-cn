[LeetCode 第 454 题](https://leetcode.com/problems/4sum-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表

 ## 解决方案

 ## 问题理解

 该问题给出了四个整数数组，`nums1`,`nums2`,`nums3`， 和`nums4`，每个包含`n`元素。 我们必须计算有多少个索引元组`(i, j, k, l)`满足：```
nums1[i] + nums2[j] + nums3[k] + nums4[l] == 0
```重要的细节是我们正在计算索引的元组，而不是唯一的值组合。 如果相同的值在数组中出现多次，则每个有效的索引组合分别对答案做出贡献。 

一种直接的解释是，我们必须检查从每个数组中选取一个元素的所有可能方法，并确定它们的总和是否为零。 由于每个数组都有长度`n`，总的组合数为：```
n * n * n * n = n^4
```约束条件告诉我们：```
1 <= n <= 200
```如果我们尝试了所有`200^4 = 1,600,000,000`组合起来，解决方案会太慢。 这立即表明暴力方法是不可行的。 

数组中的值可以是负数、正数或零。 这很重要，因为我们无法通过排序和直接跨越四个数组的两个指针来利用排序或单调行为。 相反，该问题强烈建议使用散列来存储部分和。 

一些边缘情况很重要：

 - 数组可能包含重复值，这意味着频率很重要。 
- 数组可能包含全零，这会创建许多有效的元组。 
- 负数和正数可以通过多种方式相互抵消。 
- 多个不同的对可能会产生相同的总和，因此正确计算频率至关重要。 
- 答案可能会变得很大，因为许多组合可能都是有效的。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试所有可能的元组`(i, j, k, l)`。 

我们使用四个嵌套循环：

 - 第一个循环从中选择一个元素`nums1`- 第二个循环从中选择一个元素`nums2`- 第三个循环从中选择一个元素`nums3`- 第四个循环选择一个元素`nums4`对于每个组合，我们计算：```
nums1[i] + nums2[j] + nums3[k] + nums4[l]
```如果总和为零，我们就增加答案。 

这种方法是正确的，因为它显式地检查每个可能的元组。 然而，它的计算成本很高。 和`n = 200`，该算法需要达到`200^4`操作，对于实际执行来说太大了。 

### 最佳方法

 关键的观察结果是方程：```
a + b + c + d = 0
```可以重新排列为：```
a + b = -(c + d)
```我们可以将问题分成两个独立的对和问题，而不是一次考虑四个数字。 

我们首先计算所有可能的总和`nums1`和`nums2`并存储每个和在哈希图中出现的次数。 

然后，对于每个可能的总和`nums3`和`nums4`，我们检查哈希映射中是否存在其否定。 

例如：```sql
If nums3[k] + nums4[l] = 5
Then we need a pair from nums1 and nums2 whose sum is -5
```这大大降低了复杂性：

 - 计算对和需要`O(n^2)`- 查找补语也需要`O(n^2)`总计变为`O(n^2)`而不是`O(n^4)`。

 ## 算法演练

 1. 创建一个名为的哈希图`pair_sum_count`。 

键将是由以下元素形成的和`nums1`和`nums2`。 这些值将表示每个总和出现的次数。 
2. 迭代中的每个元素`nums1`。 

对于每个元素，迭代中的每个元素`nums2`。 
3. 计算对和。 

对于每对`(a, b)`:```
current_sum = a + b
```增加哈希图中该和的频率。 
4. 初始化一个名为`result`为零。 

该变量将存储有效元组的总数。 
5. 迭代中的每个元素`nums3`。 

对于每个元素，迭代中的每个元素`nums4`。 
6. 计算第二对的当前总和。```
current_sum = c + d
```7. 求余数之和。 

满足：```
a + b + c + d = 0
```我们需要：```
a + b = -(c + d)
```所以我们计算：```
target = -current_sum
```8. 检查哈希图。 

如果`target`存在于哈希图中，将其频率添加到`result`。 

这是有效的，因为每次出现`target`表示前两个数组中的有效对。 
9. 返回`result`。 

### 为什么它有效

 该算法之所以有效，是因为每个有效元组都可以唯一地分解为：```
(nums1[i] + nums2[j]) + (nums3[k] + nums4[l]) = 0
```哈希映射准确地存储了等式前半部分可以产生给定总和的多少种方式。 对于每个后半部分的总和，我们寻找使总和为零所需的精确互补值。 由于考虑了所有对组合，因此每个有效元组都只计算一次。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def fourSumCount(
        self,
        nums1: List[int],
        nums2: List[int],
        nums3: List[int],
        nums4: List[int]
    ) -> int:
        
        pair_sum_count = defaultdict(int)

        # Store all sums from nums1 and nums2
        for num1 in nums1:
            for num2 in nums2:
                pair_sum_count[num1 + num2] += 1

        result = 0

        # Find complementary sums from nums3 and nums4
        for num3 in nums3:
            for num4 in nums4:
                target = -(num3 + num4)

                if target in pair_sum_count:
                    result += pair_sum_count[target]

        return result
```实现首先使用创建哈希图`defaultdict(int)`。 这允许轻松增加频率，而无需检查密钥是否已存在。 

第一个嵌套循环生成所有可能的和`nums1`和`nums2`。 每个总和与其频率一起存储。 如果相同的总和出现多次，则计数相应增加。 

第二个嵌套循环处理来自的所有对和`nums3`和`nums4`。 对于每一对，该算法都会计算使总和为零所需的互补值。 

如果哈希图中存在该互补值，则将其频率添加到结果中。 这会自动计算由存储的对形成的所有匹配元组的数量。 

最后，算法返回有效元组的总数。 

## 解决方案```go
func fourSumCount(nums1 []int, nums2 []int, nums3 []int, nums4 []int) int {
	pairSumCount := make(map[int]int)

	// Store all sums from nums1 and nums2
	for _, num1 := range nums1 {
		for _, num2 := range nums2 {
			pairSumCount[num1+num2]++
		}
	}

	result := 0

	// Find complementary sums from nums3 and nums4
	for _, num3 := range nums3 {
		for _, num4 := range nums4 {
			target := -(num3 + num4)

			if count, exists := pairSumCount[target]; exists {
				result += count
			}
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于 Go 使用显式的`map[int]int`而不是`defaultdict`。 

检查补码时，Go 使用二值映射查找语法：```go
count, exists := pairSumCount[target]
```这可以在使用值之前安全地确定键是否存在。 

约束足够小，以至于在 Go 标准中整数溢出不是问题`int`类型。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^2) | O(n^2) | 两个嵌套循环用于对和，另外两个嵌套循环用于补码检查 |
 | 空间| O(n^2) | O(n^2) | 哈希映射可以存储最多所有不同的对和 |

 该算法计算前两个数组的所有对和以及后两个数组的所有对和。 每个阶段都需要`n^2`操作，导致总体`O(n^2)`时间复杂度。 

哈希映射最多可以包含`n^2`最坏情况下的总和不同，因此空间复杂度也是`O(n^2)`。

 ## 边缘情况

 当所有数组仅包含零时，会出现一种重要的边缘情况。 在这种情况下，每个可能的元组都是有效的，因为总和始终为零。 有缺陷的实现可能会意外地仅计算唯一总和而不是所有索引组合。 哈希图频率方法可以正确处理这个问题，因为它存储每个对和出现的次数，而不仅仅是它是否存在。 

另一个关键的边缘情况涉及重复值。 例如：```
nums1 = [-1, -1]
nums2 = [1, 1]
```总和`0`可以多次形成。 仅存储唯一总和的解决方案会低估答案。 该实现正确跟踪哈希映射中的频率，确保每个有效组合都对最终结果做出贡献。 

当不存在有效元组时，会出现第三种边缘情况。 例如：```
nums1 = [1]
nums2 = [1]
nums3 = [1]
nums4 = [1]
```总和永远不可能为零。 该算法自然地处理这个问题，因为在哈希映射中没有找到互补的和，因此结果仍然为零。 

另一个微妙的情况涉及负数和大幅度。 由于该问题同时允许正整数和负整数，因此互补匹配至关重要。 实现正确计算：```
target = -(num3 + num4)
```这确保负和和正和正确配对，无论符号如何。
