[LeetCode 第 477 题](https://leetcode.com/problems/total-hamming-distance/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们计算数组中每个可能的整数对之间的总汉明距离。 

两个整数之间的汉明距离定义为两个数字不同的位位置的数量。 例如：

-`4 = 0100`-`14 = 1110`按位置比较位：

 | 位位置 | 4 | 14 | 14 不同的？ |
 | --- | --- | --- | --- |
 | 8s位| 0 | 1 | 是的 |
 | 4S处| 1 | 1 | 没有 |
 | 2s位| 0 | 1 | 是的 |
 | 1s位| 0 | 0 | 没有 |

 汉明距离为`2`。 

输入是一个数组`nums`包含非负整数。 我们必须考虑每一对独特的`(i, j)`在哪里`i < j`，计算之间的汉明距离`nums[i]`和`nums[j]`，并返回所有这些距离的总和。 

约束条件很重要：

 -`nums.length <= 10^4`-`nums[i] <= 10^9`大小的数组`10^4`大致包含`50 million`最坏情况下的配对：$$\frac{10000 \times 9999}{2}$$这立即告诉我们，简单的成对比较解决方案可能会变得太慢。 

另一个重要的观察是`10^9`适合 30 位，因此我们只需要检查每个数字的大约 30 到 32 位位置。 

重要的边缘情况包括：

 - 一个只有一个元素的数组，答案一定是`0`因为没有对。 
- 所有数字都相同的数组，每个汉明距离为`0`。 
- 数字在许多位位置不同的数组，这可以最大化答案。 
- 数组包含`0`，因为前导零位仍然参与比较。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每对数字。 

对于每对：

 1. 计算`a XOR b`2. 计算异或结果中设置了多少位
 3.将该计数添加到总数中

 这是有效的，因为 XOR 产生`1`正好位于位不同的位置。 

例如：

-`4 = 0100`-`14 = 1110`

$$0100 \oplus 1110 = 1010$$XOR结果有两个设置位，因此汉明距离为`2`。 

这种方法是正确的，因为它直接遵循汉明距离的定义。 然而，对于大输入来说它太慢了，因为有`O(n^2)`对。 

和`10^4`数字，这大致变成`50 million`比较，效率低下。 

### 最佳方法

 关键的观察结果是，汉明距离的贡献对于每个位位置都是独立的。 

我们可以一次一位地处理数组，而不是直接比较对。 

对于特定位位置：

 - 计算有多少个数字`1`- 计算有多少个数字`0`每一种组合`1`和一个`0`准确贡献`1`到总汉明距离。 

所以位位置的贡献为：$$(\text{count of 1s}) \times (\text{count of 0s})$$我们将所有位位置的贡献相加。 

这将问题从成对比较转化为位频率计数。 

由于最多有 32 位，`n`数，复杂度变为`O(32 * n)`，这实际上是`O(n)`。

 ## 算法演练

 ### 最佳比特计数算法

 1. 初始化变量`total_distance`到`0`。 

该变量存储所有对之间的累积汉明距离。 
2. 迭代每个位位置`0`到`31`。 

由于数字最多为`10^9`，32 位足以表示每个值。 
3. 对于当前位位置，计算有多少个数字包含 a`1`在那一点。 

我们可以使用以下方法检查这一点：```
(num >> bit) & 1
```这会将目标位移至最低有效位置并提取它。 
4. 计算有多少个数字包含 a`0`在那一点。 

如果`ones`是带有 a 的数字的计数`1`， 然后：```
zeros = len(nums) - ones
```5. 计算该位位置的贡献。 

每个数字都带有一个`1`与每个包含 a 的数字形成不同的对`0`。 

所以：$$contribution = ones \times zeros$$6. 添加贡献`total_distance`。 
7.处理完所有32位位置后，返回`total_distance`。 

### 为什么它有效

 对于任何位位置，有两个数字贡献`1`到汉明距离当且仅当它们的位在该位置不同时。 

如果有`ones`包含的数字`1`和`zeros`包含的数字`0`，那么每一个`(1,0)`组合只贡献一次。 这种组合的数量为：$$ones \times zeros$$对每个位位置独立求和即可得到所有对之间的总汉明距离。 

## Python 解决方案```python
from typing import List

class Solution:
    def totalHammingDistance(self, nums: List[int]) -> int:
        total_distance = 0
        n = len(nums)

        for bit in range(32):
            ones = 0

            for num in nums:
                ones += (num >> bit) & 1

            zeros = n - ones
            total_distance += ones * zeros

        return total_distance
```实现直接遵循位计数策略。 

变量`total_distance`存储最终答案。 我们循环遍历所有 32 个可能的位位置，因为整数可达`10^9`适合该范围内。 

对于每一位：```python
(num >> bit) & 1
```提取当前位的值。 如果结果是`1`，我们增加`ones`。 

检查完所有数字的当前位后，我们计算：```python
zeros = n - ones
```该位的不同对的数量为：```python
ones * zeros
```因为每一个`1`与每个配对`0`。 

最后，我们将贡献累积到`total_distance`并在处理完所有位后返回它。 

## 解决方案```go
func totalHammingDistance(nums []int) int {
    totalDistance := 0
    n := len(nums)

    for bit := 0; bit < 32; bit++ {
        ones := 0

        for _, num := range nums {
            ones += (num >> bit) & 1
        }

        zeros := n - ones
        totalDistance += ones * zeros
    }

    return totalDistance
}
```Go 实现与 Python 版本几乎相同。 

一些特定于 Go 的细节值得注意：

 - Go 整数是固定宽度的机器整数，但 32 次迭代就足够了，因为约束保证值高达`10^9`。 
- 范围循环：```go
for _, num := range nums
```有效地迭代切片。 
- 不需要对空或 nil 切片进行特殊处理，因为约束保证至少有一个元素。 
- 根据问题陈述，结果安全地适合 32 位整数。

 ## 边缘情况

 ### 单元素数组

 如果数组仅包含一个数字，则没有可比较的对。 幼稚的实现可能会意外地尝试生成对或产生不正确的计数。 

此实现可以自然地处理这种情况，因为每个位位置都会产生：```
ones = 0
zeros = 1
```或者：```
ones = 1
zeros = 0
```两者都产生了贡献`0`。 

### 所有数字都相同

 当每个数字都相同时，每对之间的汉明距离必须为`0`。 

这可能会暴露实现中的错误，这些错误会错误地计算重复对或错误地处理位提取。 

在位计数解决方案中，每个位位置具有：

 - 全部`1`s
 - 全部`0`s`

 因此：$$ones \times zeros = 0$$对于每一位位置。 

### 大位差异

 包含具有许多不同位的数字的数组可以产生很大的总数。 

例如：```
[0, 1073741823]
```这里：```
1073741823 = 111111111111111111111111111111
```汉明距离为`30`。 

这验证了实现是否正确处理较高位位置并且不会过早停止。 

### 具有重复项的数组

 重复值很重要，因为它们彼此之间的距离为零，但仍然与其他数字正常地贡献。 

例如：```
[4, 14, 4]
```该算法可以正确处理重复项，因为每个位的贡献仅取决于零和一的计数，而不取决于值的唯一性。
