[LeetCode 第 490 题](https://leetcode.com/problems/the-maze/)

 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、广度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定滚动的球是否可以准确地停在迷宫内的目标单元格处。 

迷宫表示为二维网格，其中：

 -`0`代表球可以滚动通过的空白空间
 -`1`代表一堵墙

 重要的细节是球一次不会移动一个细胞。 相反，一旦球开始朝某个方向移动，它就会继续滚动，直到撞到墙壁。 只有停下来后，它才能选择另一个方向。 

这极大地改变了标准网格遍历问题的问题。 在矩阵上的普通 BFS 或 DFS 中，我们一次移动一步。 在这里，每一个动作都会持续下去，直到撞到墙壁。 

输入包括：

 -`maze`, 网格
 -`start`, 球的起始坐标
 -`destination`，目标坐标

 输出应该是：

 -`true`如果球能准确停在目的地
 -`false`否则

 一个关键的微妙之处是仅仅经过目的地是不够的。 球必须停在那里。 如果目的地位于滚动路径的中间，并且球继续移动越过目的地直到到达墙壁，则该路径不算数。 

这些约束告诉我们一些重要的事情：

 - 迷宫尺寸最多为`100 x 100`- 最多可以有`10,000`细胞总数
 - 预计有图遍历解决方案
 - 指数暴力方法太慢
 - 我们需要避免重复访问状态

 该问题保证：

 - 边界就是墙，简化了滚动逻辑
 - 起点和目的地是有效的空单元格
 - 出发地和目的地不同
 - 至少有两个空单元格

 一些边缘情况很重要：

 - 目的地可能在几何上可达，但不可能停留在上面
 - 迷宫可能包含循环，需要访问跟踪
 - 长走廊会导致重复滚动计算
 - 球可能会从不同的路径重新到达相同的停止位置
 - 如果未正确跟踪访问的状态，具有许多开放空间的迷宫可能会产生无限的遍历循环

 ## 方法

 ### 蛮力方法

 强力解决方案将递归地尝试每个可能的滚动序列，而不跟踪访问过的停止位置。 

从每个停靠点，我们都会：

 1. 四个方向滚动
 2. 继续直到碰壁
 3.从新的停止位置开始递归探索

 这种方法是正确的，因为它最终会探索球可能采取的所有可能路径。 

然而，它的效率很低，因为迷宫可能包含循环。 球可以通过不同的路径重复地重新到达相同的停止位置。 如果不记住以前探索过的状态，该算法可能会无限循环或执行大量冗余工作。 

例如，在开放的迷宫中，球可能会在相同的几个停止位置之间无休止地弹跳。 

### 最佳方法

 关键的见解是，唯一有意义的状态是停止仓位。 

球在滚动时无法做出决定。 只有在碰壁并停下来后才会做出决定。 因此，我们不是将每个遍历的单元视为一个状态，而是将每个停止坐标视为一个图节点。 

这将问题转化为图遍历问题：

 - 每个停止位置都是一个节点
 - 两个停止位置之间的有效滚动是一个边缘

 然后，我们可以对已访问的集合使用 DFS 或 BFS 以避免重新访问停止位置。 

每当我们处理一个位置时：

 1. 四个方向滚动
 2. 计算下一个停止位置
 3. 如果该位置尚未访问过，则探索它

 这保证了每个可到达的停止位置最多被探索一次。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 反复探索相同的停止状态 |
 | 最优 DFS/BFS | O(m × n × 最大(m, n)) | O(m × n) | 每个停止位置访问一次 |

 ## 算法演练

 我们将使用广度优先搜索，尽管深度优先搜索同样有效。 

### 第1步：初始化遍历

 创建：

 - BFS 的队列
 - 访问过的集合或矩阵
 - 四个移动方向

 我们首先将起始位置添加到队列中并将其标记为已访问。 

我们跟踪访问过的停止位置，因为重新访问它们不会提供新信息并且可能会产生无限循环。 

### 步骤 2：逐级处理职位

 当队列不为空时：

 1. 移除当前停止位置
 2. 检查是否等于目的地
 3.如果是，则返回`True`这意味着球可以准确地停在目的地。 

### 第 3 步：向各个方向滚动

 对于每个方向：

 1.从当前位置开始
 2. 继续移动，直到下一步会碰壁
 3.停在最后一个有效的空单元格处

 这完全模拟了问题中描述的滚动行为。 

滚动循环是问题的核心：```
while within_bounds and next_cell_is_empty:
    move_forward
```该循环之后的最终位置是有效的停止点。 

### 第 4 步：探索未访问过的停靠点

 如果尚未访问过停止位置：

 1. 标记已访问过
 2.添加到队列中

 这确保每个停止节点仅被处理一次。 

###第五步：完成遍历

 如果队列未到达目的地就变空，则返回`False`。 

这意味着没有有效的投掷序列可以让球停在目的地。 

### 为什么它有效

 该算法之所以有效，是因为它系统地探索每个可到达的停止位置一次。 

不变量是：

 > 添加到队列中的每个位置都是从一开始就可以到达的有效停止点。 

由于探索了每个可到达停止点的每个可能的滚动，因此该算法最终会检查所有可到达的状态。 如果目的地作为停靠点是可到达的，则会被发现。 如果不是，遍历将在穷尽所有可能性后终止。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def hasPath(
        self,
        maze: List[List[int]],
        start: List[int],
        destination: List[int]
    ) -> bool:
        
        rows = len(maze)
        cols = len(maze[0])

        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1)
        ]

        queue = deque([tuple(start)])
        visited = set()
        visited.add(tuple(start))

        while queue:
            row, col = queue.popleft()

            if [row, col] == destination:
                return True

            for dr, dc in directions:
                new_row = row
                new_col = col

                while (
                    0 <= new_row + dr < rows
                    and 0 <= new_col + dc < cols
                    and maze[new_row + dr][new_col + dc] == 0
                ):
                    new_row += dr
                    new_col += dc

                if (new_row, new_col) not in visited:
                    visited.add((new_row, new_col))
                    queue.append((new_row, new_col))

        return False
```实现首先计算迷宫尺寸并定义四个移动方向。 

BFS 队列存储仍需要探索的停止位置。 访问过的集合可以防止重新访问已经探索过的停止点。 

对于每个出队位置，算法都会检查它是否与目的地匹配。 如果是这样，答案立即`True`。 

最重要的部分是滚动模拟。 对于每个方向，算法会重复使球前进，直到下一步：

 - 移出迷宫
 - 撞墙

 所得坐标表示滚动后的停止点。 

如果之前没有访问过该停止位置，则将其添加到队列中以供将来探索。 

最终，要么找到目的地，要么用完所有可到达的停止位置。 

## 解决方案```go
package main

import "container/list"

func hasPath(maze [][]int, start []int, destination []int) bool {
	rows := len(maze)
	cols := len(maze[0])

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	queue := list.New()
	queue.PushBack([]int{start[0], start[1]})

	visited := make(map[[2]int]bool)
	visited[[2]int{start[0], start[1]}] = true

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		position := front.Value.([]int)
		row, col := position[0], position[1]

		if row == destination[0] && col == destination[1] {
			return true
		}

		for _, dir := range directions {
			dr, dc := dir[0], dir[1]

			newRow := row
			newCol := col

			for (
				newRow+dr >= 0 &&
					newRow+dr < rows &&
					newCol+dc >= 0 &&
					newCol+dc < cols &&
					maze[newRow+dr][newCol+dc] == 0) {

				newRow += dr
				newCol += dc
			}

			key := [2]int{newRow, newCol}

			if !visited[key] {
				visited[key] = true
				queue.PushBack([]int{newRow, newCol})
			}
		}
	}

	return false
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但存在一些特定于语言的差异。 

Go 没有像 Python 那样内置的双端队列结构`collections.deque`，所以我们使用`container/list`作为 BFS 队列。 

对于访问跟踪，Go 地图不能使用切片作为键，因为切片不具有可比性。 相反，我们使用固定大小的数组类型`[2]int`。 

滚动逻辑与 Python 版本保持相同。 

由于约束很小，因此不必担心整数溢出。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m × n × 最大(m, n)) | 每个停止位置可能会滚动穿过整行或整列 |
 | 空间| O(m × n) | 队列和访问集可以存储每个单元|

 迷宫最多包含`m × n`停止位置。 

对于每个处理位置，我们尝试四卷。 单卷最多可横移`max(m, n)`最坏情况下的细胞。 

因此，总时间复杂度为：```
O(m × n × max(m, n))
```访问集和 BFS 队列一起最多可以包含迷宫中的所有单元格，给出：```
O(m × n)
```空间复杂度。

from typing import List

class Solution:
    def hasPath(self, maze: List[List[int]], start: List[int], destination: List[int]) -> bool:
        from collections import deque

        rows = len(maze)
        cols = len(maze[0])

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        queue = deque([tuple(start)])
        visited = {tuple(start)}

        while queue:
            row, col = queue.popleft()

            if [row, col] == destination:
                return True

            for dr, dc in directions:
                nr, nc = row, col

                while (
                    0 <= nr + dr < rows
                    and 0 <= nc + dc < cols
                    and maze[nr + dr][nc + dc] == 0
                ):
                    nr += dr
                    nc += dc

                if (nr, nc) not in visited:
                    visited.add((nr, nc))
                    queue.append((nr, nc))

        return False

 ## 边缘情况

 ### 目的地已通过但无法停止

 这个问题最棘手的方面之一是球可能会滚过目的地而不在那里停留。 

例如：```
[0,0,0]
```从最左边的单元格开始向右滚动会导致球仅在最右侧的墙边界处停止。 中间的单元格被穿过，但永远不会成为停止点。 

检查球在滚动过程中是否接触过目的地的简单实现会错误地返回`True`。 

此实现仅在滚动完全停止后检查位置，这可以正确处理这种情况。 

### 迷宫中的循环

 迷宫可以让球重复地重新访问相同的停止位置。 

如果没有访问集，DFS 或 BFS 可能会永远循环。 

例如：```
0 0 0
0 1 0
0 0 0
```球可以绕着中央墙反复循环。 

该实现通过标记发现后立即访问的每个停止位置来防止无限遍历。 

### 不间断的长走廊

 迷宫可能包含没有内墙的长行或列。 

在这些情况下，滚动模拟必须正确继续，直到最终停止点。 

一个常见的错误是过早停止一步或超出墙边界。 

此实现通过在前进之前检查下一个单元格是否有效来避免这些错误：```
while next_position_is_valid:
    move_forward
```结果，球总是停在墙前正确的最后一个空单元格处。
