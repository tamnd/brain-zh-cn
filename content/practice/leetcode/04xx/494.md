[LeetCode Problem 494](https://leetcode.com/problems/target-sum/)

 **难度：** 🟡 中等
 **Topics:** Array, Dynamic Programming, Backtracking

 ## 解决方案

 ## 问题理解

 The problem asks us to count how many different ways we can assign either a`'+'`或者`'-'`对数组中的每个数字进行签名`nums`这样得到的算术表达式的计算结果为`target`。 

每个数字必须只能使用一次，对于每个位置我们只有两种选择：

 - 添加号码
 - 减去数字

 例如，如果`nums = [1, 2]`，可能的表达式为：

 -`+1 +2 = 3`-`+1 -2 = -1`-`-1 +2 = 1`-`-1 -2 = -3`目标不是返回表达式本身，而是返回最终总和等于的有效表达式的总数`target`。 

输入包括：

 -`nums`，一个整数数组
 -`target`, 期望的最终总和

 输出是一个整数，表示有效符号分配的数量。 

这些约束对于选择正确的算法非常重要：

 -`nums.length <= 20`-`sum(nums) <= 1000`长度为 20 意味着暴力破解在技术上是可行的，因为`2^20`大约有一百万个组合。 然而，虽然这可能在某些经过优化的语言中通过，但它仍然是指数级的，对于面试质量的动态编程问题来说并不理想。 

总金额不大，上限为 1000，这才是真正的线索。 涉及总范围相对较小的和组合的问题通常建议基于子集和的动态规划。 

一些边缘情况很重要：

 - 包含零的数组，因为`+0`和`-0`是不同的选择，两者单独计算。 
- 目标大于可能的总和，因为这种情况不可能立即发生。 
- 负目标，因为目标的范围可以是`-1000`到`1000`。 
- 只有一个元素的数组。 
- 不存在有效表达式的情况。 

了解符号分配如何影响总和是获得最佳解决方案的关键见解。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试所有可能的分配`'+'`和`'-'`。 

对于每个数字，我们做出以下两个选择之一：

 - 将其添加到当前总数中
 - 从当前总数中减去它

 这自然就形成了二叉决策树。 由于有`n`数，每个都有两个选择，有`2^n`总表达量。 

递归回溯解决方案探索每条路径：

 - 从索引开始`0`与当前总和`0`- 递归尝试添加当前数字
 - 递归尝试减去当前数字
 - 当所有数字都处理完毕后，检查最后的总和是否等于`target`这种方法是正确的，因为它详尽地枚举了每种可能的表达式。 

然而，由于许多子问题重复出现，它变得低效。 例如，不同的路径可能以相同的运行和到达相同的索引，从而导致冗余计算。 

### 最优动态规划方法

 关键的见解来自于重写数学关系。 

认为：

-`P`是分配的数字的总和`'+'`-`N`是分配的数字的总和`'-'`然后：$$P - N = target$$还：$$P + N = totalSum$$将方程相加得出：$$2P = target + totalSum$$所以：$$P = \frac{target + totalSum}{2}$$这将问题转化为：

 > 计算总和等于的子集的数量`(target + totalSum) / 2`。 

现在这是一个经典的子集和计数问题。 

该转换仅在以下情况下有效：

 -`target + totalSum`是偶数
 -`abs(target) <= totalSum`否则，立即得到答复`0`。 

然后我们使用动态规划：

 -`dp[s]`存储求和的方法数`s`对于每个数字，我们以相反的顺序更新 DP 数组，以避免多次重复使用相同的数字。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试每个可能的符号分配 |
 | 最佳| O(n × S) | O(S)| 将问题转换为子集和计数，其中`S`是变换后的目标|

 ## 算法演练

 ### 最优动态规划算法

 1. 计算所有数字的总和。```
totalSum = sum(nums)
```该值决定任何表达式可以达到的最大可能大小。 
2. 检查是否可以进行有效的转换。 

子集和变换需要：$$P = \frac{target + totalSum}{2}$$如果`target + totalSum`是奇数，那么`P`不是整数，因此不存在解。 

如果`abs(target) > totalSum`，那么即使将所有符号赋值为正或负也无法达到目标。 
3. 计算子集总和目标。```
subsetTarget = (target + totalSum) // 2
```现在问题简化为计算总和等于的子集`subsetTarget`。 
4. 初始化动态编程数组。 

创建一个数组：```
dp[i] = number of ways to form sum i
```最初：```
dp[0] = 1
```形成总和的方法只有一种`0`，不选择任何元素。 
5. 处理每个数字`nums`。 

对于每个数字，向后更新 DP 数组。 

向后遍历很重要，因为每个数字只能使用一次。 
6. 更新子集计数。 

对于每个有效金额：```
dp[currentSum] += dp[currentSum - num]
```这意味着：

 - 保留现有方式
 - 通过包含当前数字来创建新的方式
 7. 返回最终答案。 

处理完所有数字后：```
dp[subsetTarget]
```包含有效表达式的总数。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的符号分配都唯一对应于将数字分为两组的分区：

 - 正数
 - 负数

 通过对方程进行代数变换，我们将问题简化为计算具有特定总和的子集。 动态编程表正确地计算了所有可能的子集，因为每个状态都会使用先前处理的数字来累积达到给定总和的方法数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        total_sum = sum(nums)

        # Impossible cases
        if abs(target) > total_sum:
            return 0

        if (target + total_sum) % 2 != 0:
            return 0

        subset_target = (target + total_sum) // 2

        # dp[i] = number of ways to form sum i
        dp = [0] * (subset_target + 1)
        dp[0] = 1

        for num in nums:
            for current_sum in range(subset_target, num - 1, -1):
                dp[current_sum] += dp[current_sum - num]

        return dp[subset_target]
```实现首先计算数组的总和。 这使我们能够快速拒绝不可能的情况。 

第一个拒绝条件检查目标幅度是否超过可能的总和。 如果目标大于所有数字的总和，则任何符号分配都无法达到它。 

第二个拒绝条件检查奇偶性。 由于变换后的子集方程需要除以二，因此结果必须是整数。 

接下来，算法计算`subset_target`，它代表我们需要计算的子集总和。 

然后动态编程数组被初始化。`dp[0] = 1`代表空子集。 

对于每个数字，算法向后迭代 DP 数组。 向后迭代可确保每个数字在每个子集构造中仅使用一次。 

每次更新：```python
dp[current_sum] += dp[current_sum - num]
```意思是：

 - 现有的形成方式`current_sum`保持有效
 - 通过包含创建其他方法`num`最后，`dp[subset_target]`包含有效表达式的总数。 

## 解决方案```go
func findTargetSumWays(nums []int, target int) int {
	totalSum := 0
	for _, num := range nums {
		totalSum += num
	}

	// Impossible cases
	if abs(target) > totalSum {
		return 0
	}

	if (target+totalSum)%2 != 0 {
		return 0
	}

	subsetTarget := (target + totalSum) / 2

	dp := make([]int, subsetTarget+1)
	dp[0] = 1

	for _, num := range nums {
		for currentSum := subsetTarget; currentSum >= num; currentSum-- {
			dp[currentSum] += dp[currentSum-num]
		}
	}

	return dp[subsetTarget]
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于手动处理辅助功能，例如`abs`，因为Go在标准库中没有提供内置的整数绝对值函数。 

切片用于 DP 阵列。 由于 Go 数组的大小是固定的，因此切片提供了动态编程所需的灵活性。 

整数溢出不是问题，因为约束很小。 最大组合数受以下限制`2^20`，它安全地适合 Go 的整数范围。

 ## 边缘情况

 ### 包含零的数组

 零特别棘手，因为`+0`和`-0`产生相同的数值但表示不同的表达式。 

例如：```
nums = [0,0]
target = 0
```有四种有效的表达式：```
+0 +0
+0 -0
-0 +0
-0 -0
```幼稚的实现可能会意外地将它们折叠成一个结果。 动态编程解决方案可以自然地处理这个问题，因为每个零都会使每个可达总和的计数加倍。 

### 不可能的目标

 如果目标的绝对值超过所有数字的总和，则答案必须为零。 

例子：```
nums = [1,2,3]
target = 10
```即使将所有数字正向分配也只会产生`6`，所以达到`10`是不可能的。 

实施立即检测到这一点：```
if abs(target) > total_sum:
    return 0
```这可以防止不必要的 DP 计算。 

### 奇怪的转换结果

 子集和变换需要：$$subsetTarget = \frac{target + totalSum}{2}$$如果`target + totalSum`为奇数，子集目标不是整数，意味着不存在有效分区。 

例子：```
nums = [1,2]
target = 2
```然后：$$(2 + 3) / 2 = 2.5$$由于子集和必须是整数，因此答案自动为零。 

该实现通过以下方式安全地处理此问题：```
if (target + total_sum) % 2 != 0:
    return 0
```这是错误解决方案中最常见的错误之一。
