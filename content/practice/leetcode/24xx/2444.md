[LeetCode 问题 2444](https://leetcode.com/problems/count-subarrays-with-fixed-bounds/)

 **难度：** 🔴难
 **主题：** 数组、队列、滑动窗口、单调队列

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算有多少个连续的子数组同时满足两个精确的边界条件：

 1. 子数组中的**最小元素**必须恰好是`minK`。 
2. 子数组中的**最大元素**必须正好是`maxK`。 

关键细节是这些是**精确匹配**，而不是不平等。 有效子数组的值不能简单地大于或等于`minK`且小于或等于`maxK`。 相反，存在的最小数字必须等于`minK`，并且存在的最大数量必须等于`maxK`。 

我们得到一个整数数组`nums`和两个整数，`minK`和`maxK`。 目标是返回其最小值和最大值恰好等于这些边界的**连续子数组的总数**。 

例如，如果`nums = [1,3,5,2]`,`minK = 1`， 和`maxK = 5`， 然后`[1,3,5]`是有效的，因为它的最小值是`1`其最大值为`5`。 相似地，`[1,3,5,2]`出于同样的原因也是有效的。 然而，`[3,5]`无效，因为它的最小值是`3`， 不是`1`。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 值可以大到`10^6`由于输入量很大，任何算法都比粗略地糟糕`O(n log n)`可能太慢了。 检查每个可能的子数组的强力解决方案需要`O(n²)`或者更糟，这对于`10^5`元素。 

一些边缘情况立即脱颖而出：

 如果`minK == maxK`，那么每个有效子数组必须仅包含该精确值。 例如，`[1,1,1,1]`和`minK = maxK = 1`使每个子数组都有效。 

如果元素超出范围`[minK, maxK]`一旦出现，它们就会立即使包含它们的任何子数组无效。 例如，如果`minK = 1`和`maxK = 5`，然后像这样的值`7`破坏任何候选子数组。 

当缺少一个所需值时，就会出现另一种棘手的情况。 即使所有数字都在界限内，也没有子数组有效，除非两者都满足`minK`和`maxK`出现。 

## 方法

 ### 蛮力方法

 一个简单的想法是生成每个可能的子数组并计算其最小值和最大值。 

对于每个起始索引`i`，我们考虑每个结束索引`j`，形成子数组`nums[i:j+1]`。 然后，我们计算该子数组内的最小值和最大值，并检查是否：

 -`min(subarray) == minK`-`max(subarray) == maxK`如果这两个条件都成立，我们就增加我们的答案。 

这种方法是正确的，因为它显式检查每个可能的子数组并准确验证问题约束。 然而，它的效率极低。 

有`O(n²)`长度数组中的子数组`n`。 如果我们重新计算每个子数组的最小值和最大值，则需要花费`O(n)`每个子数组，结果是`O(n³)`时间复杂度。 

即使进行了优化，在扩展子数组的同时保持运行最小值和最大值，我们仍然需要`O(n²)`时间，对于`n = 10^5`。 

### 最佳解决方案的关键见解

 关键的观察是我们**不需要**需要单独检查每个子数组。 

相反，我们可以在跟踪时一次性处理数组：

 - **最新索引`minK`**
 - **最新索引`maxK`**
 - **最近的无效索引**，其中值超出范围`[minK, maxK]`在每个位置`i`，我们问：

 > 有多少个有效子数组以索引结尾`i`？ 

结束于的子数组`i`仅在以下情况下有效：

 1. 至少包含一个`minK`2. 至少包含一个`maxK`3. 不包含无效值

 最早的有效起始位置受最近的无效索引的约束。 同时，保证两个所需值的最晚可能的起始位置由最新的较早者确定`minK`和最新的`maxK`。 

这让我们可以计算在恒定时间内以每个位置结束的有效子数组的数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 枚举所有子数组并跟踪最小/最大 |
 | 最优滑动窗口| O(n) | O(1) | O(1) | 跟踪所需值和无效值的最近位置 |

 ## 算法演练

 ### 最优滑动窗口算法

 1.初始化三个索引：

 -`last_min_index = -1`，存储最新出现的`minK`-`last_max_index = -1`，存储最新出现的`maxK`-`last_invalid_index = -1`，存储值超出范围的最新索引`[minK, maxK]`我们将它们初始化为`-1`因为最初什么也没有看到。 
2. 从左到右迭代数组。 

对于每个索引`i`， 检查`nums[i]`。 
3. 检查当前值是否无效。 

如果`nums[i] < minK`或者`nums[i] > maxK`，那么该元素不能出现在任何有效的子数组中。 

更新：`last_invalid_index = i`这意味着任何未来的有效子数组都必须严格在此位置之后开始。 
4. 更新最新出现的`minK`。 

如果`nums[i] == minK`， 更新：`last_min_index = i`5. 更新最新出现的`maxK`。 

如果`nums[i] == maxK`， 更新：`last_max_index = i`6. 判断是否存在结束于的有效子数组`i`存在。 

结束于的有效子数组`i`必须包含两个必需的值。 

极限位置为：`min(last_min_index, last_max_index)`这告诉我们保证两个所需值都存在的最早点。 
7. 计算有效的起始位置。 

起始索引必须大于`last_invalid_index`。 

所以：`valid_count = min(last_min_index, last_max_index) - last_invalid_index`如果该值为负数，则不存在以以下结尾的有效子数组`i`，所以我们添加`0`。 
8. 将贡献添加到总答案中。 

每个有效的起始点都会创建一个结束于的有效子数组`i`。 

### 为什么它有效

 该算法保持一个不变量：

 在每个索引处`i`，我们知道：

 - 最新位置`minK`出现了
 - 最新位置`maxK`出现了
 - 最新无效边界

 结束于的有效子数组`i`必须在无效边界之后开始并包含两个必需的值。 保证两个所需值的最早位置是两个最新所需索引中较小的一个。 

所以：`min(last_min_index, last_max_index) - last_invalid_index`精确计算存在多少个有效的起始位置。 

由于每个子数组只计算一次，因此当处理其结束索引时，该算法是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def countSubarrays(self, nums: List[int], minK: int, maxK: int) -> int:
        last_min_index = -1
        last_max_index = -1
        last_invalid_index = -1

        total_subarrays = 0

        for index, value in enumerate(nums):
            if value < minK or value > maxK:
                last_invalid_index = index

            if value == minK:
                last_min_index = index

            if value == maxK:
                last_max_index = index

            valid_endings = (
                min(last_min_index, last_max_index)
                - last_invalid_index
            )

            total_subarrays += max(0, valid_endings)

        return total_subarrays
```实现严格遵循算法。 

我们首先将跟踪索引初始化为`-1`，表明还没有看到边界值和无效元素。 

当我们迭代数组时，每个元素可能会更新一个或多个跟踪器。 如果元素位于有效范围之外，它将通过更新来重置有效搜索区域`last_invalid_index`。 

每当我们遇到`minK`或者`maxK`，我们存储他们的最新位置。 在每个索引处，我们计算有多少个有效子数组结束。 

表达式：```python
min(last_min_index, last_max_index)
```确保两个必需的值都存在。 如果还没有出现，则结果保持不变`-1`，自然产生零贡献。 

最后，我们将所有有效结局累加到总数中。 

## 解决方案```go
func countSubarrays(nums []int, minK int, maxK int) int64 {
	lastMinIndex := -1
	lastMaxIndex := -1
	lastInvalidIndex := -1

	var totalSubarrays int64 = 0

	for index, value := range nums {
		if value < minK || value > maxK {
			lastInvalidIndex = index
		}

		if value == minK {
			lastMinIndex = index
		}

		if value == maxK {
			lastMaxIndex = index
		}

		validEndings := min(lastMinIndex, lastMaxIndex) - lastInvalidIndex

		if validEndings > 0 {
			totalSubarrays += int64(validEndings)
		}
	}

	return totalSubarrays
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 解决方案几乎完全反映了 Python 实现。 

一个重要的区别是整数处理。 该问题可能会产生大量有效子数组，可能接近`n * (n + 1) / 2`，超出了 32 位整数的范围。 因此，返回类型为`int64`，并且我们在积累之前明确地贡献了贡献。 

Go 也没有提供内置的`min`函数用于整数，因此我们定义了一个小辅助函数。 

与 Python 不同，Go 切片已经是引用类型，因此不需要对数组进行特殊处理。

 ## 边缘情况

 ### 什么时候`minK == maxK`这种情况很容易处理不当，因为最小和最大要求会变成相同的值。 每个有效的子数组必须完全由该确切数字组成。 

例如：```
nums = [1,1,1]
minK = 1
maxK = 1
```每个子数组都变得有效。 该实现自然会处理这个问题，因为两者`last_min_index`和`last_max_index`一起更新。 

### 无效数字分割数组

 任何外部值`[minK, maxK]`立即使包含它的每个子数组无效。 

例如：```
nums = [1,5,9,1,5]
```这`9`强制重置。 索引之前的有效子数组`2`无法与索引后的那些连接`2`。 

该算法使用以下方法处理此问题`last_invalid_index`，确保未来的启动仅在无效位置之后发生。 

### 缺少一个必需的边界

 除非子数组同时包含两者，否则子数组无效`minK`和`maxK`。 

例如：```
nums = [1,2,2,2]
minK = 1
maxK = 5
```尽管所有值都在范围内，`5`永远不会出现。 因此，不存在有效的子数组。 

该实现自然会处理这个问题，因为跟踪的索引之一仍然存在`-1`， 制作：```
min(last_min_index, last_max_index)
```负数，对答案的贡献为零。
