[LeetCode 问题 2425](https://leetcode.com/problems/bitwise-xor-of-all-pairings/)

 **难度：** 🟡 中等
 **主题：** 数组、位操作、脑筋急转弯

 ## 解决方案

 ## 问题理解

 问题给了我们两个数组，`nums1`和`nums2`，并要求我们计算两个数组之间形成的每个可能对的异或。 

对于中的每个元素`nums1`，我们将它与中的每个元素配对`nums2`正好一次。 每对使用按位 XOR 运算生成一个值：```
nums1[i] ^ nums2[j]
```如果`nums1`有长度`m`和`nums2`有长度`n`，那么有`m × n`总共配对。 这些成对的 XOR 值在概念上形成另一个数组，`nums3`，任务是返回里面所有值的异或`nums3`。 

换句话说，我们想要：```
(nums1[0] ^ nums2[0]) ^
(nums1[0] ^ nums2[1]) ^
...
(nums1[m-1] ^ nums2[n-1])
```一种幼稚的解释建议显式生成每个配对，但约束立即表明这种方法无法扩展。 

每个数组长度可以大到`10^5`。 这意味着配对总数可能是：```
10^5 × 10^5 = 10^10
```在正常时间限制内处理一百亿对在计算上是不可行的。 这强烈表明存在数学观察或异或属性，可以让我们避免枚举所有配对。 

这些值本身是非负整数，最大可达`10^9`，这意味着普通的整数运算就足够了，并且不用担心 Python 中的溢出或 Go 中的标准整数处理。 

一个重要的观察结果是 XOR 具有有用的取消属性：```
x ^ x = 0
x ^ 0 = x
```这意味着出现偶数次的值完全抵消。 由于一个数组中的每个数字都参与许多配对，因此频率比显式构造更重要。 

值得尽早识别的边缘案例包括：

 - 当一个数组有长度时`1`，因为另一个数组的每个元素只贡献一次。 
- 当一个或两个数组的长度为偶数时，异或取消变得很重要。 
- 数组包含`0`，因为与零进行异或会使值保持不变。 
- 无法使用强力方法的大型阵列，更加需要优化的数学方法。 

## 方法

 ### 蛮力

 暴力解决方案直接模拟问题陈述。 

对于中的每个元素`nums1`，迭代中的每个元素`nums2`，计算该对的异或，并将结果连续异或到累加器中。 

从概念上讲：```
answer ^= (nums1[i] ^ nums2[j])
```这是有效的，因为它准确地再现了`nums3`。 每对生成一次，每个生成的值都会对最终的异或有贡献。 

然而，时间复杂度昂贵得令人望而却步。 由于中的每个元素`nums1`与中的每个元素配对`nums2`，运行时间变为`O(m × n)`。 两个数组都达到`10^5`，这变成了`10^10`操作，这太慢了。 

### 最优方法，异或贡献观察

 关键的见解来自于了解每个数字对最终异或的影响频率。 

假设一个元素`x`出现在`nums1`。 

自从`x`与中的每个元素配对`nums2`，它准确地出现在 XOR 运算中：```
len(nums2)
```次。 

如果`len(nums2)`是偶数，那么：```
x ^ x ^ x ^ x ... (even times) = 0
```所以每一份贡献都来自`x`取消。 

如果`len(nums2)`是奇数，则：```
x ^ x ^ x ... (odd times) = x
```所以`x`只存活一次。 

相同的逻辑对称地适用于中的元素`nums2`。 

因此：

 - 如果`len(nums2)`是奇数，异或所有元素`nums1`进入答案。 
- 如果`len(nums1)`是奇数，异或所有元素`nums2`进入答案。 

这将问题从检查所有配对减少为基于奇偶校验的简单异或数组元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m × n) | O(1) | O(1) | 显式计算每个成对 XOR |
 | 最佳| O(m + n) | O(1) | O(1) | 使用数组长度的 XOR 取消和奇偶校验 |

 ## 算法演练

 1. 初始化变量`result`到`0`。 

该变量存储正在运行的 XOR 答案。 由于异或与`0`保持值不变，`0`是自然的起点。 
2.检查长度是否`nums2`很奇怪。 

如果`len(nums2)`中的每个数都是奇数`nums1`对总 XOR 贡献了奇数次，这意味着这些贡献会保留下来。 

迭代`nums1`并将每个元素异或为`result`。 
3.检查长度是否`nums1`很奇怪。 

如果`len(nums1)`中的每个数都是奇数`nums2`贡献奇数次。 

迭代`nums2`并将每个元素异或为`result`。 
4. 返回`result`。 

至此，所有在取消后幸存下来的元素都已被包含一次。 

### 为什么它有效

 正确性依赖于异或的取消属性。 

中的每个元素`nums1`准确地出现`len(nums2)`所有配对中的次数。 如果该计数为偶数，则所有副本都会抵消。 如果是奇数，则保留一份。 同样的逻辑适用于`nums2`。 

由于 XOR 具有关联性和交换性，因此我们可以通过元素频率重新组合所有对贡献，而不是计算各个对。 这保证了算法产生与显式生成相同的最终 XOR`nums3`。 

## Python 解决方案```python
from typing import List

class Solution:
    def xorAllNums(self, nums1: List[int], nums2: List[int]) -> int:
        result = 0

        if len(nums2) % 2 == 1:
            for num in nums1:
                result ^= num

        if len(nums1) % 2 == 1:
            for num in nums2:
                result ^= num

        return result
```实现直接遵循数学观察。 

我们从`result = 0`，充当异或累加器。 

第一个条件检查是否`nums2`长度为奇数。 如果是这样，则中的每个元素`nums1`对最终答案贡献奇数次，因此我们对来自的所有值进行异或`nums1`进入`result`。 

第二个条件反映了这个逻辑。 如果`nums1`长度为奇数，其中的每个元素`nums2`取消后仍然存在，因此我们对来自的所有值进行异或`nums2`。 

最后，返回计算出的 XOR。 

请注意，没有显式构造任何配对。 相反，该实现通过奇偶校验来利用贡献计数，这使得它对于问题约束足够高效。 

## 解决方案```go
func xorAllNums(nums1 []int, nums2 []int) int {
	result := 0

	if len(nums2)%2 == 1 {
		for _, num := range nums1 {
			result ^= num
		}
	}

	if len(nums1)%2 == 1 {
		for _, num := range nums2 {
			result ^= num
		}
	}

	return result
}
```Go 实现与 Python 版本几乎相同。 

Go 切片自然支持迭代使用`range`，这使得异或累加简洁易读。 

关于整数溢出没有特别的担忧，因为问题约束完全符合 Go 的整数范围。 Nil 切片也可以自然处理，尽管问题保证非空数组。

 ## 边缘情况

 ### 两个数组的长度均为偶数

 这是错误的常见来源，因为每个元素出现偶数次。 

例如：```
nums1 = [1,2]
nums2 = [3,4]
```每个贡献都完全抵消，产生`0`。 有缺陷的实现可能会错误地对数组进行异或，而不管奇偶校验如何。 该实现通过仅在相反数组具有奇数长度时处理数组来避免这种情况。 

### 单元素数组

 当两个数组都包含一个元素时，则只有一对。 

例子：```
nums1 = [5]
nums2 = [7]
```答案很简单：```
5 ^ 7 = 2
```由于两个长度都是奇数，因此算法正确地将两个数组异或为结果。 

### 包含零的数组

 零在 XOR 运算中有特殊的表现：```
x ^ 0 = x
```粗心的实现可能会意外地将零视为不必要的特殊情况。 当前的解决方案不需要额外的处理，因为 XOR 自然支持它。 

例如：```
nums1 = [0,1]
nums2 = [0,2,3]
```仅有的`nums2`做出贡献是因为`nums1`具有偶数长度，并且与`0`保持结果不变。
