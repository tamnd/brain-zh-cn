[LeetCode 问题 2422](https://leetcode.com/problems/merge-operations-to-turn-array-into-a-palindrome/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、贪婪

 ## 解决方案

 ## 问题理解

 该问题要求我们使用最少的操作数将给定的正整数数组转换为回文，其中每个操作包括获取**两个相邻元素**并用它们的总和替换它们。 回文是向前和向后读取相同的数组，因此对于数组`nums`，我们要求`nums[i] == nums[n-1-i]`对于所有有效索引`i`。 

输入是一个整数列表`nums`尺寸可达`10^5`和值高达`10^6`。 输出是一个整数，表示所需的最小合并操作数。 边缘情况包括已经是回文的数组、具有单个元素的数组，或者需要重复合并才能将数组折叠成单个元素的数组（这通常是回文）。 

这些约束意味着任何解决方案都必须在大约 **O(n)** 或 **O(n log n)** 时间内运行； 模拟所有可能的合并的方法会太慢。 

主要观察结果包括只有**相邻元素**可以合并，因此该策略涉及**平衡数组两端**的总和，以逐渐使左半部分和右半部分相等。 

## 方法

 ### 蛮力

 暴力方法将尝试所有可能的合并序列，以查看哪个序列以最少的步骤产生回文。 这可以递归地完成，合并相邻元素并跟踪生成的数组，直到达到回文。 虽然这种方法是正确的，但时间复杂度呈指数级增长，因为合并元素的方法有很多种，这使得它对于大型数据不可行。`n`（`n <= 10^5`）。 

### 最佳方法

 最佳方法使用**双指针贪婪方法**。 这个想法是维护两个指针，`left`和`right`，从数组的末尾开始。 如果元素位于`left`和`right`相等，我们将两个指针向内移动。 如果`nums[left] < nums[right]`，我们合并`nums[left]`与其右邻居并增加合并计数。 相反，如果`nums[left] > nums[right]`，我们合并`nums[right]`与其左邻居。 我们继续直到指针相遇或交叉。 这种方法之所以有效，是因为每次合并都会减少数组大小，同时保持回文属性可以从末端贪婪地实现。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试所有可能的合并序列，但对于大型数组来说不可行 |
 | 最佳| O(n) | O(1) | O(1) | 两指针贪心法，从两端开始合并元素 |

 ## 算法演练

 1.初始化两个指针`left`在`0`和`right`在`len(nums) - 1`。 初始化`operations`到`0`。 
2. 虽然`left < right`:

 1.如果`nums[left] == nums[right]`，货币对已经平衡，所以移动`left`向前和`right`落后。 
2.如果`nums[left] < nums[right]`, 合并`nums[left]`和`nums[left + 1]`通过添加两个值，替换`nums[left + 1]`与总和，以及增量`operations`。 不要动`right`。 
3.如果`nums[left] > nums[right]`, 合并`nums[right]`和`nums[right - 1]`通过添加两个值，替换`nums[right - 1]`与总和，以及增量`operations`。 不要动`left`。 
3. 重复直到`left >= right`。 
4. 返回总计`operations`数数。 

**为什么有效：** 每次合并都会使数组更接近回文。 通过始终合并较小的一侧，我们逐渐平衡总和。 两指针方法确保我们进行必要的最少合并次数，因为每个操作都直接解决当前左右元素之间的不等式。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumOperations(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1
        operations = 0
        
        while left < right:
            if nums[left] == nums[right]:
                left += 1
                right -= 1
            elif nums[left] < nums[right]:
                nums[left + 1] += nums[left]
                left += 1
                operations += 1
            else:  # nums[left] > nums[right]
                nums[right - 1] += nums[right]
                right -= 1
                operations += 1
                
        return operations
```此实现使用两个指针来比较两端的元素。 如果左侧元素较小，则会将其与左侧的下一个元素合并。 如果右侧元素较小，则会将其与右侧的前一个元素合并。 每次合并都会增加`operations`柜台。 

## 解决方案```go
func minimumOperations(nums []int) int {
    left, right := 0, len(nums)-1
    operations := 0
    
    for left < right {
        if nums[left] == nums[right] {
            left++
            right--
        } else if nums[left] < nums[right] {
            nums[left+1] += nums[left]
            left++
            operations++
        } else { // nums[left] > nums[right]
            nums[right-1] += nums[right]
            right--
            operations++
        }
    }
    
    return operations
}
```Go 实现遵循相同的逻辑。 切片就地更新，考虑到问题约束，整数溢出不是问题（`nums[i] <= 10^6`且长度 <=`10^5`）。
