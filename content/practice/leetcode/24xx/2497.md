 **难度：** 🟡 中等
 **主题：** 数组、贪婪、图论、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个无向图，其中每个节点都有一个关联的整数值。 我们被要求形成一个星图并计算最大可能的星和。 

星图是通过选择一个节点作为中心并选择最多`k`它的邻居。 得到的星号总和是中心节点的值加上所有选定的相邻节点的值。 

关键细节是我们可以选择少于`k`邻居，包括零邻居。 这很重要，因为一些邻居可能有负值，将它们包括在内会减少总和。 

输入包括：

 -`vals`， 在哪里`vals[i]`是分配给节点的值`i`-`edges`，表示节点之间的无向连接
 -`k`, 星中可能包含的最大邻居数

 输出是所有有效星图的最大可能星形总和。 

约束条件很重要：

 -`n`可以大到`10^5`- 边数也可以达到`10^5`这些限制立即排除了昂贵的图形处理方法，例如不小心地对每个节点的大型邻居集进行重复排序，或者探索邻居的所有可能子集。 

问题陈述中出现了一些重要的观察结果：

 1. 由于图是无向的，因此每条边都对两个端点的邻居列表有贡献。 
2. 我们永远不想包含负值邻居，因为我们可以选择少于`k`邻居。 
3. 对于固定中心节点，最优策略始终是选择最大的正邻居值，最多`k`其中。 
4. 中心节点本身必须始终包含在内，即使其值为负数。 

一些边缘情况很重要：

 -`k = 0`，意味着不能选择任何邻居
 - 仅包含负值的图表
 - 没有邻居的孤立节点
 - 大型密集邻居列表
 - 少于的情况`k`存在积极的邻居

 正确的解决方案必须有效地处理所有这些问题。 

## 方法

 ### 蛮力方法

 强力解决方案将检查每个节点作为潜在的中心。 对于每个节点，我们将生成其邻居的所有子集，最多包含`k`节点，计算相应的星和，并保留最大值。 

这是有效的，因为每个可能的有效星图都被明确考虑。 

然而，这在计算上很快变得不可行。 如果一个节点有度`d`，邻居子集的数量呈指数级增长：$$\sum_{i=0}^{k} \binom{d}{i}$$在最坏的情况下，一个节点可能有近`10^5`邻居，使得详尽的子集生成变得不可能。 

即使是稍微改进的暴力版本，独立地对每个节点的邻居进行排序，如果不小心完成，仍然会变得低效。 

### 关键见解

 重要的观察是，绝对不应该包括负面邻居。 

假设中心节点的邻居的值为：```
[5, -2, 7, 1]
```如果`k = 2`，最优选择就是两个最大的正值：```
7 and 5
```从来没有理由包含`-2`。 

因此，对于每个节点：

 1. 收集其邻居的值
 2. 只保留正值
 3. 选择最大的`k`价值观
 4.将它们添加到中心节点值

 这将问题转化为简单的贪婪选择问题。 

我们可以有效地构建邻接信息并独立处理每个节点。

 ## 算法演练

 1. 创建一个邻接表，其中每个节点存储其邻居的正值。 

由于负邻居永远没有好处，我们只需要存储正邻居值。 对于每一个边缘`[u, v]`：

- 如果`vals[v] > 0`， 添加`vals[v]`到节点`u`- 如果`vals[u] > 0`， 添加`vals[u]`到节点`v`这样可以减少以后不必要的工作。 
2. 初始化答案。 

由于有效的星图可能只包含中心节点本身，因此将结果初始化为中的最大节点值`vals`。 
3. 独立处理每个节点。 

对于每个节点：

 - 按降序排列其正邻居值
 - 采取第一个`k`价值观
 - 将它们添加到中心节点值
 - 更新全局最大值
 4. 返回找到的最大星星总和。 

### 为什么它有效

 对于固定的中心节点，每个包含的邻居都独立地对总和做出贡献。 

因为我们可能选择少于`k`邻居，应排除任何负面贡献。 因此，中心节点的最佳星总是由最大的正邻居值组成。 

由于该逻辑对于每个中心节点都是独立最优的，因此检查所有中心可以保证找到全局最大值。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def maxStarSum(self, vals: List[int], edges: List[List[int]], k: int) -> int:
        neighbors = defaultdict(list)

        for u, v in edges:
            if vals[v] > 0:
                neighbors[u].append(vals[v])

            if vals[u] > 0:
                neighbors[v].append(vals[u])

        best = max(vals)

        for node in range(len(vals)):
            positive_neighbors = neighbors[node]
            positive_neighbors.sort(reverse=True)

            current_sum = vals[node]

            for i in range(min(k, len(positive_neighbors))):
                current_sum += positive_neighbors[i]

            best = max(best, current_sum)

        return best
```该实现首先构建一个仅存储正值邻居的邻接结构。 这是基于负邻居永远无法提高星号总和的观察的优化。 

变量`best`被初始化为最大节点值，因为每个节点单独形成一个具有零边的有效星图。 

对于每个节点，正邻居值按降序排序。 然后算法贪婪地占据顶部`k`值，因为这些值会尽可能增加星星总和。 

最后，返回所有中心的最大值。 

## 解决方案```go
package main

import (
	"sort"
)

func maxStarSum(vals []int, edges [][]int, k int) int {
	n := len(vals)

	neighbors := make([][]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		if vals[v] > 0 {
			neighbors[u] = append(neighbors[u], vals[v])
		}

		if vals[u] > 0 {
			neighbors[v] = append(neighbors[v], vals[u])
		}
	}

	best := vals[0]

	for _, value := range vals {
		if value > best {
			best = value
		}
	}

	for i := 0; i < n; i++ {
		sort.Sort(sort.Reverse(sort.IntSlice(neighbors[i])))

		currentSum := vals[i]

		limit := k
		if len(neighbors[i]) < limit {
			limit = len(neighbors[i])
		}

		for j := 0; j < limit; j++ {
			currentSum += neighbors[i][j]
		}

		if currentSum > best {
			best = currentSum
		}
	}

	return best
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

Go 使用切片的切片来进行邻接存储，而不是 Python 字典。 排序是使用处理的`sort.Sort(sort.Reverse(...))`。 

Go 切片自然会处理空的邻居列表，因此孤立的节点不需要特殊处理。 

这些约束确保整数溢出对于 Go 标准来说不是问题`int`类型。

 | --- | --- | --- |
 | 时间 | O(m log m) | 邻居列表已排序 |

 让`m`是边的数量。 

在构建邻接列表时，每条边都会被处理一次。 在所有节点上，存储的正邻居条目总数最多为`2m`。 

主要成本来自对邻居列表进行排序。 在最坏的情况下，一个节点可能包含几乎所有邻居值，导致总排序成本为`O(m log m)`。 

邻接结构要求`O(n + m)`空间。

 ## 边缘情况

 ### 案例 1：`k = 0`什么时候`k`为零，星图不能包含任何边。 有缺陷的实现可能仍会尝试添加邻居或由于空迭代而失败。 

该实现自然地处理了这个问题，因为添加邻居值的循环执行了零次。 每个节点只贡献自己的价值。 

### 情况 2：所有邻居值为负

 假设一个节点有很多邻居，但每个邻居都有负值。 包括其中任何一个都会减少星星总数。 

一个总是准确选择的简单实现`k`邻居会产生不正确的结果。 

该解决方案在构建邻接列表时显式过滤掉非正邻居，确保只考虑有益邻居。 

### 案例 3：大型`k`与节点度相比

 一个节点的数量可能少于`k`邻居。 如果不仔细检查边界，这可能会导致索引错误或超出范围的访问。 

该实现安全地使用：```
min(k, len(positive_neighbors))
```所以只处理现有的邻居。 

### 情况 4：孤立节点

 有些节点可能根本没有边。 由于单个节点仍然是有效的星图，因此仍然必须考虑孤立的节点。 

该解决方案将答案初始化为`max(vals)`，保证即使完全断开的节点也能得到正确处理。
