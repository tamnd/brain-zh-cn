[LeetCode 第 2498 题](https://leetcode.com/problems/frog-jump-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、贪婪

 ## 解决方案

 ## 问题理解

 问题给了我们一个排序数组`stones`，其中每个值代表石头在河流中的位置。 青蛙从第一块石头开始，该石头始终位于位置`0`，并且必须移动到最后一块石头，然后最终返回到第一块石头。 

重要的限制是每块石头最多只能被访问一次。 这意味着青蛙在前进和后退时不能重复使用中间的石头。 在整个行程中唯一可能出现两次的石头是起始石和结束石，因为青蛙从一个石开始，到达另一个后必须返回那里。 

每次跳跃的长度等于两块石头位置之间的绝对差。 整条路线的成本定义为行程中任何地方使用的最大跳跃长度。 我们的目标是最小化这个最大跳跃。 

换句话说，我们想要设计一个有效的前后遍历，使得最大的个体跳跃尽可能小。 

约束条件很重要：

 -`stones.length`可以大到`10^5`- 石头位置最多可达`10^9`- 数组严格递增

 这些约束立即排除了指数或二次解。 任何探索许多可能路径的算法都会太慢。 我们需要一种线性或近线性的方法。 

一些边缘情况立即脱颖而出：

 - 如果只有两块石头，青蛙别无选择，只能直接跳到那里再跳回来。 
- 石头之间的大间隙可能会影响答案。 
- 天真的贪婪遍历可能会失败，因为在前向旅行中使用附近的石头可能会为回程留下不可能的大跳跃。 
- 由于石头不能重复使用，我们必须仔细区分哪些石头用于去程，哪些用于回程。 

严格递增的顺序也很有用，因为它意味着所有跳跃自然地发生在有序位置之间，使我们能够推断相邻和交替的间隙。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试生成所有有效的方法来分割前向路径和返回路径之间的石头。 

对于中间石块的每个可能的划分，我们可以：

 1. 构建从第一块石头到最后一块石头的前进路线。 
2. 使用剩余的石头修建返回路线。 
3. 计算整个遍历的最大跳跃次数。 
4. 跟踪所有有效遍历的最小可能成本。 

这种方法是正确的，因为它检查每个可能的有效路径配置。 

然而，这在计算上是不可行的。 如果有`n`石头，每个中间石头可以有效地属于外出路径或返回路径。 这大致创建了`2^(n-2)`的可能性。 和`n`最多`100000`，这是完全不可能的。 

我们需要一种结构观察来消除搜索的需要。 

### 关键见解

 最佳策略是尽可能避免连续使用石头。 

假设我们以交替的方式穿过石头：

 - 向前旅行在索引处使用石头`0, 2, 4, ...`- 回程在索引处使用石头`..., 5, 3, 1`这会在相距两个指数的宝石之间产生跳跃。 

关键的观察是，任何有效的遍历最终都必须创建跳过一些石头的跳跃，因为石头不能在两次旅行中重复使用。 最佳可能的安排可以最小化最大的此类跳过跳跃。 

事实证明，最佳答案很简单：$$\max(stones[i] - stones[i-2])$$为所有人`i >= 2`。 

直观上，交替遍历尽可能均匀地分布跳跃。 如果我们在一个方向上过于频繁地使用连续的石头，相反的方向将被迫进行更大的跳跃。 

这导致了一个非常简单的线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试所有可能的前向/返回分配 |
 | 最佳 | O(n) | O(1) | O(1) | 使用交替跳跃观察|

 ## 算法演练

 ### 第 1 步：初始化答案

 我们从尽可能小的答案值开始。 

由于在某些情况下青蛙必须至少在前两块石头之间跳跃，因此我们可以使用第一个相邻差值进行初始化。 

### 步骤 2：检查相距两个索引的宝石之间的跳跃

 从索引开始`2`，计算：```
stones[i] - stones[i - 2]
```这表示由交替遍历模式创建的跳跃。 

我们跟踪最大此类值，因为总路径成本由最大跳跃决定。 

### 步骤3：更新最大跳跃

 对于每个有效的`i`， 更新：```
answer = max(answer, stones[i] - stones[i - 2])
```这确保我们捕获最佳排列所需的最差跳跃。 

### 第四步：返回最终答案

 扫描一次数组后，存储的最大值就是可实现的最小路径成本。 

### 为什么它有效

 关键的不变量是，任何石头都不能在前进和回程中重复使用。 因此，连续的石块不能全部在两个方向上顺序遍历。 在某些时候，青蛙必须跳过石头。 

交替遍历模式最大限度地减少了所需的最大跳跃。 任何其他安排都会迫使某些跳跃至少与其中之一一样大`stones[i] - stones[i-2]`差距。 

因此，两块石头之间的最大间隙既是必要的也是充分的，证明了该算法是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxJump(self, stones: List[int]) -> int:
        n = len(stones)

        if n == 2:
            return stones[1] - stones[0]

        max_jump = stones[1] - stones[0]

        for i in range(2, n):
            max_jump = max(max_jump, stones[i] - stones[i - 2])

        return max_jump
```实现直接遵循算法的数学观察。 

我们首先处理尽可能小的输入尺寸，其中只有两颗石头。 在这种情况下，青蛙必须直接跳到它们之间。 

接下来我们初始化`max_jump`使用第一个相邻差异。 

循环从索引处开始`2`因为我们需要将每颗棋子与之前两个位置的棋子进行比较。 对于每次迭代，我们计算交替跳跃距离并更新运行最大值。 

最后，返回最大的交替间隙作为最优成本。 

该实现以线性时间运行并使用恒定的额外内存。 

## 解决方案```go
func maxJump(stones []int) int {
	n := len(stones)

	if n == 2 {
		return stones[1] - stones[0]
	}

	maxJumpValue := stones[1] - stones[0]

	for i := 2; i < n; i++ {
		jump := stones[i] - stones[i-2]

		if jump > maxJumpValue {
			maxJumpValue = jump
		}
	}

	return maxJumpValue
}
```Go 的实现与 Python 解决方案非常相似。 

由于 Go 没有提供内置的`max`对于整数函数，我们手动将值与`if`陈述。 

整数溢出不是问题，因为棋子位置之间的最大差异最多为`10^9`，它安全地适合 Go 的内部`int`在 LeetCode 环境中输入。 

切片自然用于数组访问，不需要额外的内存分配。

 ## 边缘情况

 当只有两颗棋子时，就会出现一种重要的边缘情况。 在这种情况下，青蛙就没有任何灵活性了。 它必须直接从第一块石头跳到最后一块石头，然后再跳回来。 粗心的实现可能会错误地假设总是有一个索引`i-2`可用的。 该实现通过提前返回显式处理此问题。 

另一个重要的情况是当一个差距明显大于所有其他差距时，例如`[0,1,100]`。 尽管大多数跳跃都很小，但青蛙无法避免跳跃很长的距离`100`在某个时刻。 该算法正确地捕获了这一点，因为交替间隙计算自然会暴露出不可避免的大跳跃。 

均匀的间距也值得考虑。 例如，`[0,2,4,6,8]`可能会诱使某人认为答案是`2`，因为相邻的石头仅相差`2`。 然而，由于石头不能重复使用，青蛙必须有效地交替石头，产生大小的跳跃`4`。 该实现通过检查两个索引之间的间隙来正确识别这一点。 

最后一个微妙的情况涉及奇数与偶数数量的石头。 根据奇偶性，交替遍历模式的行为略有不同，但数学观察仍然普遍成立。 由于该算法仅依赖于最大`stones[i] - stones[i-2]`，它会自动处理这两种情况，无需特殊分支。
