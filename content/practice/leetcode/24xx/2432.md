[LeetCode 问题 2432](https://leetcode.com/problems/the-employee-that-worked-on-the-longest-task/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们在给定员工完成的一系列任务的情况下，确定哪位员工在**最长的持续时间内**完成该任务。 每个任务都表示为`logs[i] = [idi, leaveTimei]`， 在哪里`idi`是员工 ID，`leaveTimei`是任务完成的时间。 每个任务的开始时间都是隐式定义的：第一个任务开始于`0`并且每个后续任务在前一个任务结束后立即开始。 应返回完成任务的**最长持续时间**的员工，如果出现平局，则应返回最小的员工 ID。 

输入约束很小：`n`和`logs.length`最多 500 个。全部`leaveTimei`价值观是唯一且严格递增的，连续的任务由不同的员工完成。 这保证了每个任务都有一个正的持续时间，并且任务顺序不存在歧义。 边缘情况包括多个任务共享最长持续时间或第一个或最后一个任务最长。 

## 方法

 一种简单的方法是显式计算每个任务的持续时间并将所有持续时间存储在列表中，然后搜索最大持续时间并检索相应的员工 ID。 这是正确的，但需要单独的遍历和额外的空间，这是不必要的，因为我们可以动态跟踪最大值。 

最佳方法利用了这样一个事实：任务持续时间可以动态计算，我们只需要**当前最大值**。 我们迭代日志，通过减去前一个任务的休假时间（或`0`对于第一个任务），并维护最大持续时间和相应员工 ID 的记录。 如果多个任务具有相同的最大持续时间，则仅当当前员工 ID 较小时我们才会更新 id。 该方法在时间上是线性的并且使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 显式存储所有任务持续时间并搜索 max |
 | 最佳| O(n) | O(1) | O(1) | 动态跟踪最长持续时间和相应的员工 ID |

 ## 算法演练

 1. 初始化`max_duration`到`0`和`hardest_employee`到`0`。 这些将跟踪最长的任务持续时间和相应的员工 ID。 
2. 初始化`prev_time`到`0`。 该变量表示前一个任务的结束时间，用于计算当前任务的持续时间。 
3. 迭代每个任务`logs`。 对于每个任务：

 1. 计算任务持续时间为`duration = leaveTimei - prev_time`。 
2.如果`duration > max_duration`， 更新`max_duration = duration`和`hardest_employee = idi`。 
3.如果`duration == max_duration`和`idi < hardest_employee`， 更新`hardest_employee = idi`来处理关系。 
4. 更新`prev_time = leaveTimei`用于下一次迭代。 
4. 迭代完所有任务后，返回`hardest_employee`。 

**Why it works:** The algorithm maintains the invariant that`hardest_employee`始终代表迄今为止已完成最长持续时间任务的员工。 由于每个任务的持续时间是由连续的休假时间唯一确定的，这保证了正确性。 通过比较平等时刻的员工 ID 来解决平局。 

## Python 解决方案```python
from typing import List

class Solution:
    def hardestWorker(self, n: int, logs: List[List[int]]) -> int:
        max_duration = 0
        hardest_employee = 0
        prev_time = 0

        for emp_id, leave_time in logs:
            duration = leave_time - prev_time
            if duration > max_duration or (duration == max_duration and emp_id < hardest_employee):
                max_duration = duration
                hardest_employee = emp_id
            prev_time = leave_time

        return hardest_employee
```**说明：** 我们初始化跟踪变量并迭代每个日志。 对于每个任务，我们计算相对于前一个任务完成时间的持续时间。 每当发现更长的持续时间时，我们都会更新`max_duration`和`hardest_employee`。 如果持续时间与当前最大值一致，我们确保选择 ID 较小的员工。 最终值`hardest_employee`被返回。 

## 解决方案```go
func hardestWorker(n int, logs [][]int) int {
    maxDuration := 0
    hardestEmployee := 0
    prevTime := 0

    for _, log := range logs {
        empID := log[0]
        leaveTime := log[1]
        duration := leaveTime - prevTime
        if duration > maxDuration || (duration == maxDuration && empID < hardestEmployee) {
            maxDuration = duration
            hardestEmployee = empID
        }
        prevTime = leaveTime
    }

    return hardestEmployee
}
```**说明：** Go 解决方案反映了 Python 方法。 切片用于访问日志条目和变量`maxDuration`,`hardestEmployee`， 和`prevTime`跟踪相同的信息。 通过以相同的方式比较员工 ID 可以解决关系问题。 除了几个整数之外，不会使用额外的内存。
