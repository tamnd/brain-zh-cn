[LeetCode 问题 2417](https://leetcode.com/problems/closest-fair-integer/)

 **难度：** 🟡 中等
 **主题：** 数学、枚举

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出一个正整数`n`，我们必须找到大于或等于的最小整数`n`这被认为是“公平的”。 

当偶数位的数量恰好等于奇数位的数量时，一个数字是公平的。 例如：

-`10`是公平的，因为它包含一个偶数（`0`) 和一位奇数 (`1`）
 -`1234`是公平的，因为它包含两个奇数位（`1`,`3`) 和两个偶数 (`2`,`4`）
 -`2221`不公平，因为它包含三个偶数和一个奇数

 该任务不是要求所有公平数，也不是要求绝对距离中最接近的公平数。 我们特别需要大于或等于的最小公平整数`n`。 

限制相对较小：

 -`1 <= n <= 10^9`自从`10^9`最多有 10 位数字，这立即表明基于数字的推理是可行的。 我们处理的不是需要复杂组合或动态规划的极大整数。 

一个重要的观察是，公平的数字必须包含偶数个数字。 这是因为偶数位数必须等于奇数位数。 因此：

 - 一位数字永远不可能是公平的
 - 3 位数字永远不可能公平
 - 5 位数字永远不可能公平

 只有偶数位的数字才有可能满足条件。 

一些边缘情况尤其重要：

 - 非常小的数字，例如`1`或者`2`，其中答案必须跳转到 2 位数字
 - 数字位数为奇数的数字，因为相同长度的数字不可能是公平的
 - 已经公平的数字，我们应该立即返回数字本身
 - 附近的大值`10^9`，其中下一个公平数字可能需要增加数字长度

 ## 方法

 ### 蛮力方法

 最简单的策略是从`n`并一次增加一个数字，直到找到一个公平的整数。 

对于每个数字：

 1.将其转换为字符串
 2. 计算有多少位数字是偶数
 3. 计算有多少位数字是奇数
 4. 检查计数是否相等

 一旦我们找到这样的数字，我们就会将其返回。 

这种方法很简单并且总是正确的，因为我们按升序检查每个候选人。 因此，我们遇到的第一个有效的公平整数必须是大于或等于的最小整数`n`。 

然而，当公平数字之间存在较大差距时，此方法可能会变得低效。 例如，如果`n`如果数字位数为奇数，我们可能会浪费时间检查许多不可能的候选数字，然后才能得到偶数数字。 

### 最佳方法

 关键的见解是输入约束足够小，我们实际上不需要高级数字 DP 或组合构造。 

相反，我们可以通过利用一个关键属性来稍微优化暴力方法：

 公平数的位数必须为偶数。 

这意味着：

 - 如果当前候选者的位数为奇数，我们可以立即跳转到下一个 10 次方
 - 我们只需要测试偶数位长度的数字

 由于数字高达`10^9`最多包含 10 位数字，搜索空间可控。 

算法变为：

 1. 从`n`2. 如果位数为奇数：

 - 直接跳转到下一个数字长度最小的数字
 3.否则：

 - 检查数字是否公平
 - 如果没有，则增加并继续

 这种修剪极大地减少了不必要的检查。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k × d) | O(1) | O(1) | 逐一检查每个数字 |
 | 最佳| O(k × d) | O(1) | O(1) | 跳过不可能的奇数长度范围 |

 这里：

-`k`是检查的候选人数
 -`d`是位数，最多 10

 ## 算法演练

 1. 初始化变量`current`与价值`n`。 
2.进入无限循环，因为我们保证最终存在一个公平的数字。 
3. 转换`current`到一个字符串并确定其位数。 
4. 如果位数为奇数，那么具有该位数长度的数字不可能是公平的。 因此：

 - 直接跳转到下一个10次方
 - 例如：

 -`999`变成`1000`-`12345`变成`100000`5. 如果位数是偶数：

 - 计算有多少位数字是偶数
 - 计算有多少位数字是奇数
 6. 如果两个计数相等：

 - 返回`current`- 由于我们按升序搜索，因此这是最小的有效答案
 7. 否则：

 - 增量`current`1
 - 继续循环

 ### 为什么它有效

 该算法按严格递增的顺序检查候选数。 任何跳过的范围都包含奇数位长度的数字，并且此类数字永远不可能是公平的，因为偶数和奇数数字的相等计数需要偶数总数字计数。 

因此，遇到的第一个公平数必须是大于或等于的最小公平整数`n`。 

## Python 解决方案```python
class Solution:
    def closestFair(self, n: int) -> int:
        current = n

        while True:
            digits = str(current)

            # Fair numbers must have an even number of digits
            if len(digits) % 2 == 1:
                current = 10 ** len(digits)
                continue

            even_count = 0

            for ch in digits:
                if int(ch) % 2 == 0:
                    even_count += 1

            odd_count = len(digits) - even_count

            if even_count == odd_count:
                return current

            current += 1
```该实现紧密遵循前面描述的算法。 

我们从`current = n`并反复测试候选数。 

第一个优化检查位数是否为奇数。 如果是这样，我们立即跳转到 10 的下一个幂，因为奇数长度的数字不可能是公平的。 

对于偶数长度的数字，我们迭代每个数字并计算有多少个数字是偶数。 由于总位数已知，奇数位数可以计算如下：```python
odd_count = len(digits) - even_count
```如果计数匹配，我们立即返回该数字。 

否则，我们增加候选者并继续搜索。 

由于最大位数非常小，因此该解决方案对于约束来说足够有效。 

## 解决方案```go
func closestFair(n int) int {
	current := n

	for {
		digits := []rune(string(runeSlice(current)))

		// Fair numbers must have even digit counts
		if len(digits)%2 == 1 {
			current = powerOf10(len(digits))
			continue
		}

		evenCount := 0

		for _, ch := range digits {
			digit := int(ch - '0')

			if digit%2 == 0 {
				evenCount++
			}
		}

		oddCount := len(digits) - evenCount

		if evenCount == oddCount {
			return current
		}

		current++
	}
}

func runeSlice(num int) []rune {
	return []rune(fmt.Sprintf("%d", num))
}

func powerOf10(exp int) int {
	result := 1

	for i := 0; i < exp; i++ {
		result *= 10
	}

	return result
}
```更干净、更典型的 LeetCode Go 实现将避免通过符文切片进行辅助转换，而是使用`strconv.Itoa`。 这是首选版本：```go
import "strconv"

func closestFair(n int) int {
	current := n

	for {
		digits := strconv.Itoa(current)

		if len(digits)%2 == 1 {
			current = 1

			for i := 0; i < len(digits); i++ {
				current *= 10
			}

			continue
		}

		evenCount := 0

		for _, ch := range digits {
			digit := int(ch - '0')

			if digit%2 == 0 {
				evenCount++
			}
		}

		if evenCount*2 == len(digits) {
			return current
		}

		current++
	}
}
```Go 实现几乎完全反映了 Python 逻辑。 

主要的语言特定差异是数字转换。 在Python中，将数字转换为字符串并迭代字符非常简洁。 在 Go 中，我们使用`strconv.Itoa`将整数转换为字符串。 

另一个小区别是 Go 不直接提供整数求幂，因此我们使用循环手动计算 10 的幂。

 ## 边缘情况

 ### 个位数输入

 单位数字永远不可能是公平的，因为它们要么包含一个偶数位，要么包含一个奇数位，永远不会相等。 幼稚的实现可能会浪费时间单独检查所有单位值。 

此实现通过检测数字计数为奇数并立即跳转到 10 的下一个幂来有效地处理这种情况。 

### 数字长度为奇数的数字

 任何位数为奇数的数字自动无效。 例如：

 - 100
 - 12345
 - 9999999

 有缺陷的实现可能会继续一一检查这些数字，尽管没有一个是公平的。 

该解决方案通过直接跳转到具有下一个数字长度的最小数字来跳过整个不可能的范围。 

### 输入已经公平

 一些输入已经满足条件。 示例包括：

 -`10`-`1234`-`1001`不正确的实现可能会在检查当前数字之前意外地增加，从而错过最佳答案。 

此实现始终在递增之前检查当前值，确保返回最小的有效数字。
