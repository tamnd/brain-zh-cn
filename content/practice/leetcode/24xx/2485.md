 # LeetCode 2485 - 求主元整数

 ## 问题理解

 问题给了我们一个正整数`n`并要求我们找到一个特殊的整数`x`，称为主元整数，这样：

 - 所有整数的总和`1`到`x`等于
 - 所有整数的总和`x`到`n`重要的细节是`x`属于这两个总和。 换句话说：$$1 + 2 + \dots + x = x + (x+1) + \dots + n$$我们需要返回的值`x`如果这样的整数存在。 如果不存在这样的整数，我们返回`-1`。 

输入由单个整数组成`n`， 在哪里：$$1 \le n \le 1000$$这个限制非常小，这意味着即使效率较低的方法也可以在时间限制内发挥作用。 然而，问题主要在于识别数学关系，从而提供更清晰、更优化的解决方案。 

该问题还保证最多有一个有效的主元整数。 这意味着我们永远不需要担心多个答案或在它们之间做出决定。 

一些边缘情况很重要：

 - 当`n = 1`，唯一的数字是左右和，所以答案是`1`。 
- 一些值`n`根本不产生任何主元整数，例如`n = 4`。 
- 由于总和增长很快，我们应该小心正确处理两个范围内重叠的主值。 

## 方法

 ### 蛮力方法

 最直接的方法是尝试每个可能的主元整数`1`到`n`。 

对于每位候选人`x`：

 - 计算总和`1`到`x`- 计算总和`x`到`n`- 比较两个总和

 如果相等则返回`x`。 

这种方法是正确的，因为它显式地检查每个可能的主元整数并完全按照问题中所述验证所需的条件。 

然而，该解决方案会重复地重新计算每个候选者的总和。 如果我们使用循环计算每个总和，那么对于每个`x`我们最多可以执行`O(n)`工作。 由于有`n`可能的主元值，总复杂度变为`O(n²)`。 

虽然`n <= 1000`使这成为可能，我们可以做得更好。 

### 最优数学方法

 关键的观察来自于使用第一个总和的公式`n`整数。 

总金额来自`1`到`n`是：$1+2+\cdots+n=\frac{n(n+1)}{2}$认为`x`是主元整数。 

左边的和是：$$1 + 2 + \dots + x$$右边的和是：$$x + (x+1) + \dots + n$$由于两个总和相等，并且它们一起覆盖了整个范围`x`计算两次，可以得出：$$\text{left sum} = \text{total sum} - \text{left sum} + x$$让：$$S = \frac{n(n+1)}{2}$$和：$$\text{left sum} = \frac{x(x+1)}{2}$$替换：$$\frac{x(x+1)}{2} = S - \frac{x(x+1)}{2} + x$$化简后，我们得到：$x^2=\frac{n(n+1)}{2}$这意味着仅当总和是完全平方时才存在主元整数。 

所以算法就变成了：

 1. 计算总和。 
2. 计算其整数平方根。 
3. 如果该根的平方等于总和，则返回该根。 
4.否则返回`-1`。 

这将时间复杂度降低到`O(1)`。

 ## 算法演练

 1. 计算以下整数的总和`1`到`n`。 

我们使用算术级数公式：$$\text{total} = \frac{n(n+1)}{2}$$这可以避免循环遍历数字。 
2. 计算总和的整数平方根。 

如果存在主元整数，则：$$x^2 = \text{total}$$因此，主元整数必须是总和的平方根。 
3. 验证总和是否是完全平方数。 

我们计算：$$\text{root} \times \text{root}$$如果这恰好等于总和，那么`root`是主元整数。 
4. 返回结果。 

- 如果总和是完全平方数，则返回`root`。 
- 否则返回`-1`。 

### 为什么它有效

 正确性直接来自两个范围之间的相等条件。 通过以数学方式表达两个总和并简化方程，我们证明主元整数存在当且仅当总和来自`1`到`n`是一个完美的正方形。 因此，检查完全平方就足够了并且保证了正确的答案。 

## Python 解决方案```python
import math

class Solution:
    def pivotInteger(self, n: int) -> int:
        total_sum = n * (n + 1) // 2
        
        root = math.isqrt(total_sum)
        
        if root * root == total_sum:
            return root
        
        return -1
```该实现首先计算总和`1`到`n`使用算术级数公式。 这避免了迭代并在恒定时间内给出结果。 

下一个，`math.isqrt()`安全高效地计算整数平方根。 与浮点平方根不同，整数平方根避免了精度问题。 

然后，代码检查计算出的根的平方是否等于总和。 如果是，则总和是完全平方，根是主元整数。 

如果条件失败，则不存在有效的主元整数，因此函数返回`-1`。 

## 解决方案```go
package main

import "math"

func pivotInteger(n int) int {
    totalSum := n * (n + 1) / 2

    root := int(math.Sqrt(float64(totalSum)))

    if root*root == totalSum {
        return root
    }

    return -1
}
```Go 实现遵循与 Python 版本相同的数学逻辑。 

一个小小的区别是 Go 不像 Python 在标准库中提供整数平方根函数`math.isqrt()`。 相反，我们使用`math.Sqrt()`与一个`float64`转换，然后将结果转换回整数。 

由于约束非常小，因此浮点精度在这里不是问题。

 ## 边缘情况

 ### 边缘情况 1：最小输入值

 当`n = 1`，该范围仅包含一个数字。 左边和右边的和都是简单的`1`，所以主元整数存在并且等于`1`。 

这种情况很重要，因为某些实现错误地假设双方都必须包含多个元素。 数学推导自然可以正确处理这种情况，因为：$$\frac{1(1+1)}{2} = 1$$这是一个完美的正方形。 

### 边缘情况 2：没有有效的主元整数

 许多价值观`n`不产生任何主元整数。 例如：```
n = 4
```总和为：$$10$$自从`10`不是完全平方数，没有整数`x`可以满足条件。 

有缺陷的实现可能会错误地舍入平方根或不小心使用浮点比较。 该实现通过验证来避免这种情况：```
root * root == total_sum
```确切地。 

### 边缘情况 3：大边界值

 最大可能的输入是：```
n = 1000
```尽管限制很小，但边界测试仍然很重要。 总和仍然在整数限制内：$$\frac{1000 \times 1001}{2} = 500500$$该实现始终使用整数运算，因此在给定约束下，Python 或 Go 中都不存在溢出问题。
