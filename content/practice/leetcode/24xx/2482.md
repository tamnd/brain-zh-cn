 # LeetCode 2482 - 行和列中的 1 和 0 之间的差异

 ## 问题理解

 该问题给了我们一个二元矩阵`grid`和`m`行和`n`列。 每个细胞都包含`0`或者`1`。 我们必须构造另一个矩阵，称为`diff`，其中每个位置`diff[i][j]`取决于行中有多少个 1 和 0`i`和列`j`。 

对于每个细胞`(i, j)`，我们计算：$$\text{diff}[i][j] = \text{onesRow}_i + \text{onesCol}_j - \text{zerosRow}_i - \text{zerosCol}_j$$这意味着每个单元格完全由四个计数决定：

 - 其行中的个数
 - 其列中的个数
 - 其行中零的数量
 - 其列中零的数量

 输入矩阵本身永远不会改变。 我们仅使用它来收集有关行和列的统计信息。 

约束条件很重要：

 -`1 <= m, n <= 10^5`-`1 <= m * n <= 10^5`产品`m * n`至多是`100000`，这意味着单元总数是可控的。 然而，重复扫描每个单元格的行和列仍然是低效的。 

如果单独重新计算每个矩阵位置的行和列计数，则简单的实现很容易变得太慢。 

有几个重要的边缘情况：

 - 全为 1 的矩阵
 - 全零的矩阵
 - 单行矩阵
 - 单列矩阵
 - 非常矩形的矩阵，例如`1 x 100000`或者`100000 x 1`该问题保证每个值都是`0`或者`1`，所以我们永远不需要处理无效数据。 

## 方法

 ### 蛮力方法

 最直接的解决方案是计算每个`diff[i][j]`独立。 

对于每个细胞`(i, j)`:

 1. 扫描行`i`并数一和零。 
2. 扫描栏`j`并数一和零。 
3. 应用公式。 

这种方法是正确的，因为每个单元格都准确接收定义所需的值。 

然而，这是低效的。 对于每个单元格，我们扫描整行和整列。 

如果有`m * n`单元格，每次计算都需要`O(m + n)`，总复杂度变为：$$O(m \cdot n \cdot (m + n))$$这对于最大约束来说太慢了。 

### 最佳方法

 关键的观察结果是行和列计数被重复重用。 

例如：

 - 同一行中的每个单元格共享相同的内容`onesRow`和`zerosRow`。 
- 同一列中的每个单元格共享相同的内容`onesCol`和`zerosCol`。 

我们可以预先计算一次，而不是多次重新计算这些计数。 

我们创造：

 -`rowOnes[i]`= 行中的个数`i`-`colOnes[j]`= 列中的个数`j`然后：$$\text{zerosRow}_i = n - \text{rowOnes}_i$$

$$\text{zerosCol}_j = m - \text{colOnes}_j$$代入公式：$$\text{diff}[i][j] = \text{rowOnes}[i] + \text{colOnes}[j] - (n - \text{rowOnes}[i]) - (m - \text{colOnes}[j])$$简化：$$\text{diff}[i][j] = 2 \cdot \text{rowOnes}[i] + 2 \cdot \text{colOnes}[j] - n - m$$现在，预处理后可以在恒定时间内计算每个单元格。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * (m + n)) | O(m * n * (m + n)) | O(1) | O(1) | 重复重新计算行数和列数 |
 | 最佳 | O(m * n) | O(m + n) | 预先计算行和列统计信息一次 |

 ## 算法演练

 1.确定矩阵维度`m`和`n`。 
2. 创建两个数组：

 -`rowOnes`尺寸的`m`-`colOnes`尺寸的`n`这些数组存储每行和每列中出现的数量。 
3. 遍历一次矩阵。 

对于每个细胞`(i, j)`：

- 如果`grid[i][j] == 1`- 增量`rowOnes[i]`- 增量`colOnes[j]`经过这一步之后，我们就知道了每一行和每一列的个数。 
4. 创建结果矩阵`diff`。 
5. 再次遍历矩阵。 

对于每个单元格`(i, j)`:

 - 计算行中的零：$$zerosRow = n - rowOnes[i]$$- 计算列中的零：$$zerosCol = m - colOnes[j]$$- 应用公式：$$diff[i][j] = rowOnes[i] + colOnes[j] - zerosRow - zerosCol$$6.返回填写完毕的`diff`矩阵。 

### 为什么它有效

 该算法之所以有效，是因为每个`diff[i][j]`仅取决于有关行的聚合信息`i`和列`j`。 通过对这些聚合进行一次预处理，我们可以避免冗余计算。 

计数存储在`rowOnes`和`colOnes`是精确的，并且零值直接从矩阵维度导出。 因此，每个计算单元都与问题陈述中的定义相匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def onesMinusZeros(self, grid: List[List[int]]) -> List[List[int]]:
        m = len(grid)
        n = len(grid[0])

        row_ones = [0] * m
        col_ones = [0] * n

        # Count ones in rows and columns
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 1:
                    row_ones[i] += 1
                    col_ones[j] += 1

        # Build result matrix
        diff = [[0] * n for _ in range(m)]

        for i in range(m):
            for j in range(n):
                zeros_row = n - row_ones[i]
                zeros_col = m - col_ones[j]

                diff[i][j] = (
                    row_ones[i]
                    + col_ones[j]
                    - zeros_row
                    - zeros_col
                )

        return diff
```实现首先确定矩阵维度。 这是必要的，因为在计算零计数时会重复使用行和列的大小。 

数组`row_ones`和`col_ones`存储每行和每列中的个数。 第一个嵌套循环在一次矩阵遍历中填充这些数组。 

第二个嵌套循环构造最终的答案矩阵。 对于每个单元格，零的数量是通过数学计算得出的，而不是明确计算的。 这避免了不必要的工作，并使解决方案与单元格数量保持线性。 

该算法从不修改输入矩阵，并且每个值都是使用预处理的统计数据独立计算的。 

## 解决方案```go
func onesMinusZeros(grid [][]int) [][]int {
    m := len(grid)
    n := len(grid[0])

    rowOnes := make([]int, m)
    colOnes := make([]int, n)

    // Count ones in rows and columns
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if grid[i][j] == 1 {
                rowOnes[i]++
                colOnes[j]++
            }
        }
    }

    // Build result matrix
    diff := make([][]int, m)

    for i := 0; i < m; i++ {
        diff[i] = make([]int, n)

        for j := 0; j < n; j++ {
            zerosRow := n - rowOnes[i]
            zerosCol := m - colOnes[j]

            diff[i][j] = rowOnes[i] +
                colOnes[j] -
                zerosRow -
                zerosCol
        }
    }

    return diff
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 切片用于动态数组，结果矩阵是逐行分配的。 

整数溢出不是问题，因为最大可能值的边界为`m + n`，这最多是`200000`。 

Go 需要显式的矩阵分配，因此每一行`diff`单独初始化。

 ## 边缘情况

 ### 单细胞矩阵

 一个`1 x 1`矩阵是最小的可能输入。 这种情况可能会暴露涉及维度或索引处理的错误。 例如，假设多行或多列的解决方案可能会失败。 

该实现自然地处理了这个问题，因为即使两个维度都等于 1，行数和列数仍然可以正确计算。 

### 全零矩阵

 当每个单元格都为零时，所有 1 计数都为零，并且所有零计数都变为最大。 这会在整个结果矩阵中产生负值。 

一些不正确的实现意外地假设结果总是非负的。 提供的解决方案遵循精确的公式并正确处理负输出。 

### 高度矩形矩阵

 约束允许像这样的矩阵`1 x 100000`或者`100000 x 1`。 这些形状可能会暴露重复扫描行或列的算法效率低下的问题。 

优化的解决方案仍然有效，因为每个单元仅被处理恒定的次数。 运行时间与单元总数保持线性关系。 

### 全一矩阵

 如果每个值都是一，那么零计数到处都为零。 这测试了实现是否使用维度正确地导出零，而不是显式地计算它们。 

该算法计算：$$zerosRow = n - rowOnes[i]$$和$$zerosCol = m - colOnes[j]$$在这种情况下它正确地变为零。
