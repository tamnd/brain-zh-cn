[LeetCode 问题 2431](https://leetcode.com/problems/maximize-total-tastiness-of-purchased-fruits/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们在保持固定预算的情况下最大限度地提高所购买水果的总体美味。 每种水果都有两个属性：`price`和一个`tastiness`价值。 我们可以跳过某种水果，也可以购买它，但每种水果只能购买一次。 

还有一个额外的变化：我们可以使用优惠券。 优惠券可将水果的成本降低至原价的一半（四舍五入）。 但优惠券数量有限，且每张优惠券只能使用一种水果。 

目标是选择水果的子集，决定每个购买的水果是否使用优惠券，以便：

 1. 花费的总金额不超过`maxAmount`。 
2.优惠券使用张数不超过`maxCoupons`。 
3. 美味值总和最大化。 

输入包括：

 -`price[i]`，购买成本`i-th`水果。 
-`tastiness[i]`, 的美味评分`i-th`水果。 
-`maxAmount`，最大总预算。 
-`maxCoupons`，可用优惠券的最大数量。 

输出是一个整数，表示在这些约束下可实现的最大总味道。 

这些约束告诉我们很多关于预期解决方案的信息：

 -`n <= 100`，这意味着我们可以负担多项式时间动态规划。 
-`maxAmount <= 1000`，这表明基于预算的 DP 是可行的。 
-`maxCoupons <= 5`，它非常小，强烈暗示优惠券计数应该是 DP 状态的一部分。 

探索每种购买可能性的强力解决方案将过于昂贵，因为每种水果都有三种选择：

 - 跳过它
 - 正常购买
 - 使用优惠券购买

 这导致大约`3^n`的可能性，这是不可能的`n = 100`。 

一些重要的边缘情况包括零价格的水果、零味道的水果、无法购买的情况以及优惠券极大地改变负担能力的情况。 我们还必须正确处理整数除法，因为优惠券折扣使用下限除法。 

## 方法

 ### 蛮力

 一个简单的方法是对每种水果尝试所有可能的决定。 

对于每种水果，我们有三种选择：

 1. 跳过它。 
2.正常购买。 
3.使用优惠券购买。 

我们在跟踪时递归地探索每个组合：

 - 剩余预算
 - 剩余优惠券
 - 累积总美味

 这保证了正确性，因为每个有效的购买组合都会被考虑，并且我们只是在所有可行状态中选择最大的美味。 

然而，可能性的数量呈指数级增长。 由于每种水果大约有三种选择，因此总复杂度约为`O(3^n)`。 和`n = 100`，这是完全不可行的。 

### 最优方法，动态规划

 关键的观察结果是许多递归状态重复。 

假设我们处于水果指数`i`，还有剩余预算`money`， 和`coupons`左边。 这个状态的最佳答案并不取决于我们如何到达那里，只取决于这三个值。 

这种重叠子问题结构使动态规划成为完美的选择。 

我们定义一个DP状态：`dp(i, remainingAmount, remainingCoupons)`这代表从水果开始可获得的最大美味`i`。 

对于每种水果，我们都会考虑三种可能性：

 - 跳过水果。 
- 如果负担得起的话，正常购买。 
- 如果价格实惠且仍有优惠券，请使用优惠券购买。 

因为只有：

 -`n <= 100`-`maxAmount <= 1000`-`maxCoupons <= 5`状态总数是可控的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 探索每种购买组合 |
 | 最佳| O(n × 最大金额 × 最大优惠券) | O(n × 最大金额 × 最大优惠券) | 记忆 DP 超过指数、预算和优惠券 |

 ## 算法演练

 我们使用自上而下的动态规划和记忆。 

1.定义递归函数`dfs(index, remaining_amount, remaining_coupons)`。 

这个函数返回我们仍然可以获得的最大美味`index`，给定剩余预算和优惠券。 
2. 处理基本情况。 

如果`index == n`，没有剩余的水果可以加工，所以答案是`0`。 
3.考虑跳过当前的水果。 

我们总是可以选择不买水果。 这给出：```
dfs(index + 1, remaining_amount, remaining_coupons)
```4.考虑正常购买。 

如果水果价格实惠的话：```
price[index] <= remaining_amount
```然后我们就可以购买它并享受它的美味：```
tastiness[index] +
dfs(index + 1,
    remaining_amount - price[index],
    remaining_coupons)
```5.考虑使用优惠券购买。 

如果我们还有优惠券：```
remaining_coupons > 0
```我们计算折扣价格：```
discounted_price = price[index] // 2
```如果负担得起，我们采取：```
tastiness[index] +
dfs(index + 1,
    remaining_amount - discounted_price,
    remaining_coupons - 1)
```6. 在所有有效选项中取最大值。 

因为我们想要最大的美味，所以我们选择最好的结果。 
7. 使用记忆法。 

如果没有记忆，相同的状态将被重新计算多次。 缓存确保每个状态都被解决一次。 

### 为什么它有效

 该算法之所以有效是因为最优子结构。 对于任何水果指数和剩余资源，最佳答案仅取决于该水果的三个有效操作中的最佳决策。 由于每个状态都得到最优解决并被记忆，因此递归会在每个状态上精确地探索所有有效的购买计划一次，从而保证全局最佳的美味。 

## Python 解决方案```python
from functools import lru_cache
from typing import List

class Solution:
    def maxTastiness(
        self,
        price: List[int],
        tastiness: List[int],
        maxAmount: int,
        maxCoupons: int
    ) -> int:
        n = len(price)

        @lru_cache(None)
        def dfs(
            index: int,
            remaining_amount: int,
            remaining_coupons: int
        ) -> int:
            if index == n:
                return 0

            # Option 1: Skip this fruit
            best = dfs(
                index + 1,
                remaining_amount,
                remaining_coupons
            )

            # Option 2: Buy normally
            normal_price = price[index]
            if normal_price <= remaining_amount:
                best = max(
                    best,
                    tastiness[index] + dfs(
                        index + 1,
                        remaining_amount - normal_price,
                        remaining_coupons
                    )
                )

            # Option 3: Buy with coupon
            if remaining_coupons > 0:
                discounted_price = price[index] // 2

                if discounted_price <= remaining_amount:
                    best = max(
                        best,
                        tastiness[index] + dfs(
                            index + 1,
                            remaining_amount - discounted_price,
                            remaining_coupons - 1
                        )
                    )

            return best

        return dfs(0, maxAmount, maxCoupons)
```实现直接遵循算法。 

我们首先将水果的数量存储在`n`。 然后我们定义一个记忆递归函数`@lru_cache(None)`因此重复状态仅计算一次。 

每个递归调用代表一个由以下定义的状态：

 - 当前水果指数
 - 剩余预算
 - 剩余优惠券

 该函数首先考虑跳过水果，因为这个选择始终有效。 

接下来，它检查正常购买水果是否负担得起。 如果是这样，它会添加水果的美味并递归计算剩余的最佳结果。 

然后它会考虑优惠券选项。 折扣价格按楼层划分计算（`// 2`），与问题陈述完全匹配。 我们还确保在尝试此转换之前至少保留一张优惠券。 

最后，该函数返回所有有效选择中的最大美味。 初次通话从第一个水果开始，并提供全部预算和所有优惠券。 

## 解决方案```go
func maxTastiness(price []int, tastiness []int, maxAmount int, maxCoupons int) int {
	n := len(price)

	memo := make(map[[3]int]int)

	var dfs func(int, int, int) int

	dfs = func(index int, remainingAmount int, remainingCoupons int) int {
		if index == n {
			return 0
		}

		key := [3]int{index, remainingAmount, remainingCoupons}

		if value, exists := memo[key]; exists {
			return value
		}

		// Option 1: Skip this fruit
		best := dfs(index+1, remainingAmount, remainingCoupons)

		// Option 2: Buy normally
		if price[index] <= remainingAmount {
			candidate := tastiness[index] + dfs(
				index+1,
				remainingAmount-price[index],
				remainingCoupons,
			)

			if candidate > best {
				best = candidate
			}
		}

		// Option 3: Buy with coupon
		if remainingCoupons > 0 {
			discountedPrice := price[index] / 2

			if discountedPrice <= remainingAmount {
				candidate := tastiness[index] + dfs(
					index+1,
					remainingAmount-discountedPrice,
					remainingCoupons-1,
				)

				if candidate > best {
					best = candidate
				}
			}
		}

		memo[key] = best
		return best
	}

	return dfs(0, maxAmount, maxCoupons)
}
```Go 解决方案遵循与 Python 相同的记忆递归模式。 由于 Go 没有内置的记忆化装饰器，例如`lru_cache`，我们将计算出的状态显式存储在映射中。 

记忆键是一个由三个整数组成的固定大小的数组：```go
[index, remainingAmount, remainingCoupons]
```这可以有效地工作，因为数组是可比较的并且可以用作映射键。 

Go 中的整数除法自然会执行整数除法，因此：```go
price[index] / 2
```正确匹配优惠券行为。 

Go 切片用于`price`和`tastiness`，并且不需要特殊处理`nil`与空切片相比，因为问题保证了有效的输入长度。

 ## 边缘情况

 ### 零预算

 当`maxAmount = 0`，幼稚的实现可能会错误地尝试购买或未考虑免费水果。 我们的实施正确地阻止了购买，除非有效价格（包括优惠券折扣）为零。 由于在转换之前始终会检查负担能力，因此永远不会发生无效购买。 

### 优惠券让昂贵的水果变得买得起

 一种水果可能平时买不到，但用优惠券后却可以买得起。 例如：```
price = [10]
budget = 5
coupon = 1
```自从`10 // 2 = 5`，水果就可以购买了。 有缺陷的实施可能只考虑正常价格或错误处理楼层划分。 我们的解决方案明确计算：```
price[i] // 2
```在检查负担能力之前。 

### 策略优惠券分配

 立即使用优惠券并不总是最好的解决方案。 有时，为以后购买昂贵的水果保留优惠券会产生更高的美味。 由于DP探索了每种水果的所有有效选择，包括跳过优惠券的使用，它自然会找到全局最优分配。 

### 零价水果

 有些水果可能已经涨价了`0`。 由于每种水果只能购买一次，因此错误的实现可能会在设计不良的 DP 中意外地无限地重复使用它们。 我们州的指数总是领先：```
index + 1
```确保每个水果只加工一次。
