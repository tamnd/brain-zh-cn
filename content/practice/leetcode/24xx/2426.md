 # LeetCode 2426 - 满足不等式的对数

 ## 问题理解

 我们有两个整数数组，`nums1`和`nums2`, 相同长度`n`，以及一个整数`diff`。 

我们必须计算有多少个索引对`(i, j)`满足两者：

 -`i < j`-`nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff`目标是返回有效对的总数。 

乍一看，不等式涉及两个数组和两个不同索引的值，因此很难直接计数。 自从`n`可以大到`100,000`，检查每个可能的对是不可行的。 

这些约束告诉我们一些重要的事情：

 - 最多可以有`10^5`元素。 
- 值可能为负值。 
- 答案可能比`2^31 - 1`，因此我们必须使用 64 位整数作为结果。 
- 一个`O(n²)`解决方案大约需要`10^10`在最坏的情况下进行比较，这太慢了。 

一个有用的观察是，不等式可以转换为一种只涉及每个索引一个值的形式。 一旦进行了转换，问题就变成了一个经典的计数问题，可以使用合并排序来有效解决。 

重要的边缘情况包括：

 - 所有配对均有效。 
- 没有有效的配对。 
- 两个数组中的负值。 
- 消极的`diff`。 
- 答案超出 32 位整数范围的大输入。 
- 重复的转换值，需要仔细处理`<=`而不是`<`。 

## 方法

 ### 蛮力

 最直接的方法是检查每一对`(i, j)`和`i < j`。 

对于每一对，评估：```
nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff
```如果条件成立，则增加答案。 

这种方法显然是正确的，因为它严格按照问题陈述的定义检查每个可能的对。 

然而，有：```
n(n - 1) / 2
```可能的对。 

为了`n = 100,000`，这大约有 50 亿对，使得该方法完全不切实际。 

### 关键见解

 Start with the original inequality:```
nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff
```将涉及相同索引的项移到一起：```
nums1[i] - nums2[i] <= nums1[j] - nums2[j] + diff
```定义：```
arr[k] = nums1[k] - nums2[k]
```条件变为：```
arr[i] <= arr[j] + diff
```重新排列：```
arr[i] - diff <= arr[j]
```现在问题变成：

 数对`(i, j)`这样：```
i < j
arr[i] <= arr[j] + diff
```这与计数反转类似，只是比较条件不同。 

每当我们看到具有索引排序约束和值之间比较的成对计数问题时，基于合并排序的计数技术通常适用。 

在合并排序期间，两半都已排序。 在合并两半之前，我们可以使用两个指针来计算有效的跨半对。

 ## 算法演练

 ### 第 1 步：转换数组

 创建一个新数组：```
arr[i] = nums1[i] - nums2[i]
```原来的不等式变为：```
arr[i] <= arr[j] + diff
```这减少了使用单个阵列的问题。 

### 第 2 步：使用分而治之的方法

 应用归并排序`arr`。 

就像反转计数一样，每个有效对都属于以下三个类别之一：

 1. 两个索引都位于左半部分。 
2. 两个指数都在右半部分。 
3. 每半个一个索引。 

递归调用会自动计算前两个类别。 

我们只需要在合并步骤中计算跨半对的数量。 

### 步骤 3：计算跨半对的数量

 假设：```
left half  = arr[left:mid+1]
right half = arr[mid+1:right+1]
```两半都已经排序了。 

对于左半部分的每个值，我们想知道右半部分有多少个值满足：```
left_value <= right_value + diff
```等效地：```
right_value >= left_value - diff
```由于右半部分已排序，因此指针可以单调地在其中移动。 

对于每个左侧元素：

 - 在以下情况下前进指针：```
right_value < left_value - diff
```- 指针停止后，右半部分剩余的每个元素形成有效对。 

有效合伙人数量为：```
right_end - pointer + 1
```### 步骤 4：合并两半

 计数完毕后，进行正常的归并排序合并操作。 

这保留了更高递归级别的排序顺序。 

### 步骤5：返回累计计数

 在递归过程中，所有有效对都只计算一次。 

最后的计数就是答案。 

### 为什么它有效

 在每个合并步骤中，左半部分和右半部分都已排序。 对于固定的左值，一旦右值变得足够大以满足：```
right_value >= left_value - diff
```所有后面的右值也将满足条件，因为右半部分已排序。 因此，单个移动指针可以有效地计算所有有效的跨半对。 

每对`(i, j)`恰好属于一个合并步骤，其中索引首先分成不同的两半。 该合并步骤对这对进行了一次计数。 因此，每个有效对都被计数一次且仅一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def numberOfPairs(self, nums1: List[int], nums2: List[int], diff: int) -> int:
        arr = [a - b for a, b in zip(nums1, nums2)]
        temp = [0] * len(arr)

        def merge_sort(left: int, right: int) -> int:
            if left >= right:
                return 0

            mid = (left + right) // 2

            count = merge_sort(left, mid)
            count += merge_sort(mid + 1, right)

            j = mid + 1

            for i in range(left, mid + 1):
                while j <= right and arr[j] < arr[i] - diff:
                    j += 1

                count += right - j + 1

            i = left
            j = mid + 1
            k = left

            while i <= mid and j <= right:
                if arr[i] <= arr[j]:
                    temp[k] = arr[i]
                    i += 1
                else:
                    temp[k] = arr[j]
                    j += 1
                k += 1

            while i <= mid:
                temp[k] = arr[i]
                i += 1
                k += 1

            while j <= right:
                temp[k] = arr[j]
                j += 1
                k += 1

            for idx in range(left, right + 1):
                arr[idx] = temp[idx]

            return count

        return merge_sort(0, len(arr) - 1)
```实现首先构建转换后的数组：```python
arr[i] = nums1[i] - nums2[i]
```这将原始的不等式转换为仅涉及一个数组的比较。 

递归`merge_sort`函数返回当前范围内有效对的数量，同时对该范围进行排序。 

递归求解左半部分和右半部分后，该函数对跨半部分进行计数。 由于两半都已排序，因此单个指针`j`仅扫描右半部分一次。 这使计数步骤保持线性。 

计数后，标准合并操作将已排序的两半组合起来。 合并的结果被复制回原始数组，以便更高的递归级别接收排序的段。 

所有递归调用累积的总计数作为最终答案返回。 

## 解决方案```go
func numberOfPairs(nums1 []int, nums2 []int, diff int) int64 {
	n := len(nums1)

	arr := make([]int, n)
	for i := 0; i < n; i++ {
		arr[i] = nums1[i] - nums2[i]
	}

	temp := make([]int, n)

	var mergeSort func(int, int) int64

	mergeSort = func(left, right int) int64 {
		if left >= right {
			return 0
		}

		mid := (left + right) / 2

		count := mergeSort(left, mid)
		count += mergeSort(mid+1, right)

		j := mid + 1

		for i := left; i <= mid; i++ {
			for j <= right && arr[j] < arr[i]-diff {
				j++
			}

			count += int64(right - j + 1)
		}

		i := left
		j = mid + 1
		k := left

		for i <= mid && j <= right {
			if arr[i] <= arr[j] {
				temp[k] = arr[i]
				i++
			} else {
				temp[k] = arr[j]
				j++
			}
			k++
		}

		for i <= mid {
			temp[k] = arr[i]
			i++
			k++
		}

		for j <= right {
			temp[k] = arr[j]
			j++
			k++
		}

		for idx := left; idx <= right; idx++ {
			arr[idx] = temp[idx]
		}

		return count
	}

	return mergeSort(0, n-1)
}
```Go 的实现遵循完全相同的分治策略。 

一个重要的区别是返回类型是显式的`int64`，因为有效对的数量可能超出 32 位整数的范围。 因此，所有对计数都使用累积`int64`。 

切片用于工作数组和临时合并缓冲区，提供与 Python 列表相同的功能。

 ## 边缘情况

 ### 重复的转换值

 当多个索引产生相同的值时`nums1[i] - nums2[i]`，仍然可以满足不等式。 一个常见的错误是在计数时使用严格比较。 该实现仔细计算满足的值`>= arr[i] - diff`，确保正确处理重复项。 

＃＃＃ 消极的`diff`负数`diff`使条件更难满足。 一些解决方案错误地假设阈值总是增加。 无论符号如何，变换后的不等式仍然有效`diff`，并且合并排序计数逻辑无需修改即可工作。 

### 非常大的答案

 对于`n = 100000`，对的数量可以是：```
100000 * 99999 / 2
```大约是五十亿。 这超出了有符号 32 位整数的范围。 因此，Go 实现使用`int64`，Python天然支持任意大的整数。 

### 包含负数的数组

 由于两个输入数组都可能包含负值，因此转换后的值也可以为负值。 合并排序方法仅取决于相对顺序，而不取决于值范围，因此可以自然地处理负数，无需任何特殊情况。 

### 所有配对均有效

 如果每对都满足不等式，则答案达到最大可能的对数。 该算法仍然只执行`O(n log n)`之所以有效，是因为它通过排序范围对成对的组进行计数，而不是单独检查对。
