[LeetCode 问题 2427](https://leetcode.com/problems/number-of-common-factors/)

 **难度：** 🟢简单
 **主题：** 数学、枚举、数论

 ## 解决方案

 ## 问题理解

 该问题给了我们两个正整数，`a`和`b`，并要求我们计算有多少个整数可以整除这两个数字。 

一个数字`x`如果满足以下条件，则被视为公因子：

 -`a % x == 0`-`b % x == 0`这意味着`x`将两个整数相除，不留余数。 

例如，如果`a = 12`和`b = 6`，共同因素有：

 -`1`，因为两个数字都可以被 1 整除
 -`2`，因为两个数字都可以被 2 整除
 -`3`，因为两个数字都可以被 3 整除
 -`6`，因为两个数字都可以被 6 整除

 所以答案是`4`。 

输入约束很小：

 -`1 <= a, b <= 1000`由于数字最多为 1000，因此即使相对简单的枚举方法也足够快。 这很重要，因为这意味着我们不需要高级的数论优化来有效地解决问题。 

关键的观察是任何公因数`a`和`b`必须将两个数字相除。 另一种思考方式是，每个公因数也必须整除`gcd(a, b)`。 

重要的边缘情况包括：

 - 当两个数字都是`1`，唯一的共同因素是`1`- 当数字互质时，答案应该是`1`- 当两个数相等时，该数的每个因数都是公因数
 - 当一个数整除另一个数时，公因数就是较小数除以较大数的因数

 因为输入保证是正整数，所以我们不需要处理零或负值。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个整数`1`最多`min(a, b)`。 

对于每个候选人编号`i`：

 - 检查是否`a % i == 0`- 检查是否`b % i == 0`如果两个条件都为真，那么`i`is a common factor, so we increment the answer.

 这种方法是正确的，因为没有因子大于`min(a, b)`可以除掉这两个数。 通过检查该范围内的每个可能的候选者，我们保证将每个公因子精确地计算一次。 

虽然这被称为暴力方法，但对于给定的约束来说这是完全可以接受的，因为最大范围只有 1000。 

### 最佳方法

 更好的数学观察是，所有公因数`a`和`b`正是以下因素`gcd(a, b)`。 

如果我们计算：$g = \gcd(a,b)$那么每个公因数都必须整除`g`。 

因此，不要检查两者的因素`a`和`b`，我们可以：

 1. 计算最大公约数
 2. 计算 GCD 有多少个约数

 这减少了冗余的整除性检查，并使用数论更清晰地表达问题。 

由于约束很小，我们可以简单地枚举来自`1`到`g`并计算除数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(min(a, b)) | O(1) | O(1) | 根据两个数字检查每个可能的因素 |
 | 最佳| O(gcd(a, b)) | O(1) | O(1) | 首先计算 GCD，然后计算 GCD 的除数 |

 ## 算法演练

 ### 最优算法

 1. 计算最大公约数`a`和`b`。 

GCD 表示能整除这两个整数的最大数。 的每个公因数`a`和`b`还必须划分GCD。 
2. 将 GCD 存储在名为的变量中`common_divisor`。 

该值成为我们需要进一步分析的唯一数字。 
3. 初始化一个计数器变量`count`到`0`。 

该变量将跟踪 GCD 有多少个除数。 
4. 迭代自`1`到`common_divisor`包容性。 

GCD 的每个除数都对应于原始两个数字的公因数。 
5. 对于每个数字`i`，检查是否：```
common_divisor % i == 0
```如果为真，那么`i`均匀地划分 GCD，这意味着它是两者的公因数`a`和`b`。 
6. 增量`count`每当找到有效除数时。 
7. 返回`count`循环结束后。 

### 为什么它有效

 正确性来自于整除性的一个基本属性：$x \mid a \text{ and } x \mid b \iff x \mid \gcd(a,b)$这意味着的一组公因数`a`和`b`正是它们的 GCD 的约数集。 通过计算 GCD 的除数，我们可以正确计算所有公因数。 

## Python 解决方案```python
class Solution:
    def commonFactors(self, a: int, b: int) -> int:
        def gcd(x: int, y: int) -> int:
            while y:
                x, y = y, x % y
            return x
        
        common_divisor = gcd(a, b)
        count = 0
        
        for i in range(1, common_divisor + 1):
            if common_divisor % i == 0:
                count += 1
        
        return count
```实现首先定义一个辅助函数来使用欧几里德算法计算最大公约数。 

欧几里德算法反复替换：```python
(x, y)
```和：```python
(y, x % y)
```直到`y`变为零。 那时，`x`包含GCD。 

计算 GCD 后，代码会迭代以下每个整数`1`到`common_divisor`。 

每当一个数字整除 GCD 时，它就被视为有效的公因数。 

最后，该函数返回总计数。 

该实现遵循算法演练中描述的确切逻辑，并且仅使用恒定的额外空间。 

## 解决方案```go
func commonFactors(a int, b int) int {
    gcd := func(x int, y int) int {
        for y != 0 {
            x, y = y, x%y
        }
        return x
    }

    commonDivisor := gcd(a, b)
    count := 0

    for i := 1; i <= commonDivisor; i++ {
        if commonDivisor%i == 0 {
            count++
        }
    }

    return count
}
```Go 的实现与 Python 解决方案非常相似。 

Go 不支持像 Python 那样的嵌套命名函数，因此 GCD 帮助器被实现为分配给变量的匿名函数。 

整数溢出不是问题，因为约束非常小。 该解决方案仅使用整数运算和常量额外内存。

 ## 边缘情况

 ### 两个数字都是 1

 当`a = 1`和`b = 1`，唯一可能的公因数是`1`。 

有错误的实现可能会错误地返回`0`如果它假设因子搜索开始于`2`。 此实现正确地从以下位置开始检查`1`，所以答案就变成了`1`。 

### 互质数

 当两个数的 GCD 为互质时`1`。 

例如：```
a = 17
b = 19
```唯一的共同因素是`1`。 

误解公因子概念的幼稚实现可能期望公因子为零。 算法正确计数`1`因为每个正整数至少共享因子`1`。 

### 相同的数字

 当两个数字相同时，该数字的每个因数自动成为公因数。 

例如：```
a = 10
b = 10
```这些因素是：```
1, 2, 5, 10
```该实现自然地处理了这个问题，因为：$\gcd(n,n)=n$因此该算法只是简单地计算数字本身的所有除数。
