 # 字符串的最大删除次数

 ## 问题理解

 问题给了我们一个字符串`s`仅由小写英文字母组成。 我们希望使用尽可能多的操作来完全删除字符串。 

在一次操作中，我们有两种可能的操作：

 1. 立即删除整个剩余字符串。 
2.仅删除第一个`i`字符，但前提是：

 -`1 <= i <= len(s) / 2`- 第一个`i`字符与下一个字符完全相等`i`人物。 

第二个操作是有趣的。 这意味着我们只能删除字符串以两个相同的连续块开头的前缀。 

例如：```
s = "ababxyz"
```我们可以删除`"ab"`因为：```
first 2 chars  = "ab"
next 2 chars   = "ab"
```删除后，字符串变为：```
"abxyz"
```目标不是最小化操作。 相反，我们希望在字符串变空之前执行尽可能多的操作。 

约束条件很重要：```
1 <= s.length <= 4000
```4000 的长度对于指数递归或在嵌套循环内使用简单切片进行重复子字符串比较来说太大。 我们需要一个算法`O(n²)`。 

一些边缘情况很重要：

 - 没有重复相邻前缀的字符串，例如`"abcdef"`，只能在一次操作中删除。 
- 含有很多重复字符的字符串，例如`"aaaaa"`，允许许多小的删除。 
- 重叠重复模式可以创建多个有效选择，因此贪婪决策并不总是最佳的。 
- 如果简单地实现，重复的子字符串比较可能会变得昂贵。 

这个问题本质上是一个与高效子串比较相结合的动态规划问题。 

## 方法

 ### 蛮力方法

 暴力解决方案会递归地尝试每个有效的删除。 

假设我们当前处于字符串`s[i:]`。 我们测试每一个可能的长度`k`这样：```
s[i:i+k] == s[i+k:i+2k]
```如果条件成立，我们递归地求解剩余的后缀：```
solve(i + k)
```我们还始终可以选择在一次操作中删除整个剩余字符串。 

递归变为：```
dp[i] = 1 + max(dp[i+k]) for every valid k
```问题是子串比较成本。 

如果我们直接比较子字符串：```
s[i:i+k] == s[i+k:i+2*k]
```每次比较的成本`O(k)`。 

有`O(n²)`可能的`(i, k)`对，因此总复杂度变为：```
O(n³)
```和`n = 4000`，这太慢了。 

### 关键见解

 昂贵的部分是重复检查两个子字符串是否相等。 

我们可以预处理信息，使我们能够有效地回答子字符串相等查询，而不是每次都逐个字符地比较子字符串。 

这里一个非常有效的技术是计算最长公共前缀，缩写为 LCP。 

定义：```
lcp[i][j]
```作为以下之间最长公共前缀的长度：```
s[i:]
and
s[j:]
```例如：```
s = "aaabaab"

lcp[0][1]
```表示以下之间的公共前缀长度：```
"aaabaab"
"aabaab"
```这是`2`。 

一旦我们知道`lcp[i][j]`，我们可以判断两个子串的长度是否相同`k`在常数时间内相等：```
s[i:i+k] == s[j:j+k]
iff
lcp[i][j] >= k
```这会将昂贵的子字符串比较转换为`O(1)`检查。 

我们可以计算整个 LCP 表`O(n²)`从右到左使用动态规划。 

然后我们运行另一个 DP 来计算最大删除量。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|

 ## 算法演练

 ### 第 1 步：定义 DP 状态

 让：```
dp[i]
```表示删除后缀所需的最大操作次数：```
s[i:]
```我们的最终答案将是：```
dp[0]
```### 第 2 步：构建 LCP 表

 我们创建一个二维数组：```
lcp[n][n]
```在哪里：```
lcp[i][j]
```存储以下之间的公共前缀的长度：```
s[i:]
and
s[j:]
```我们从右下角到左上角填充表格。 

如果：```
s[i] == s[j]
```然后：```
lcp[i][j] = 1 + lcp[i+1][j+1]
```否则：```
lcp[i][j] = 0
```这是可行的，因为如果当前字符相等，匹配前缀会进一步扩展一个字符。 

### 步骤 3：初始化 DP 阵列

 通过删除整个剩余字符串，始终可以在一次操作中删除每个后缀。 

所以最初：```
dp[i] = 1
```为所有人`i`。 

### 步骤 4：尝试每个有效的前缀长度

 对于每个起始位置`i`,尝试每一个可能的前缀长度`k`。 

前缀和后面的子字符串是：```
s[i:i+k]
s[i+k:i+2k]
```如果满足以下条件，这些子串相等：```
lcp[i][i+k] >= k
```如果为真，我们可以删除第一个块并继续：```
i + k
```所以：```
dp[i] = max(dp[i], 1 + dp[i+k])
```### 第 5 步：返回答案

 结果是：```
dp[0]
```因为它代表整个字符串所需的最大操作数。 

### 为什么它有效

 该算法之所以有效，是因为`dp[i]`探索后缀中每个有效的第一个删除`s[i:]`。 

对于每个有效的删除长度`k`，剩下的问题就变成了后缀上完全相同的问题`s[i+k:]`。 这种最优子结构使得动态规划变得适用。 

LCP 表保证正确的子串相等性检查。 自从：```
lcp[i][j]
```存储两个位置的匹配字符的确切数量，条件：```
lcp[i][j] >= k
```相当于说下一个`k`字符是相同的。 

因此，DP 考虑所有合法操作并始终选择产生最大删除数的序列。 

## Python 解决方案```python
class Solution:
    def deleteString(self, s: str) -> int:
        n = len(s)

        # lcp[i][j] = longest common prefix length
        # between s[i:] and s[j:]
        lcp = [[0] * (n + 1) for _ in range(n + 1)]

        # Build LCP table from bottom-right
        for i in range(n - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                if s[i] == s[j]:
                    lcp[i][j] = 1 + lcp[i + 1][j + 1]

        # dp[i] = maximum deletions for s[i:]
        dp = [1] * n

        # Process from right to left
        for i in range(n - 1, -1, -1):

            # Try every possible deletion length
            for length in range(1, (n - i) // 2 + 1):

                # Check whether:
                # s[i:i+length] == s[i+length:i+2*length]
                if lcp[i][i + length] >= length:
                    dp[i] = max(dp[i], 1 + dp[i + length])

        return dp[0]
```实现首先构建 LCP 表。 该表是从右到左构建的，因为每个状态都取决于`lcp[i+1][j+1]`。 

如果两个字符匹配，我们将公共前缀长度扩展一。 否则，公共前缀为零。 

接下来，我们创建 DP 数组。 每个位置都以价值开始`1`因为删除整个剩余后缀总是可能的。 

对于每个索引`i`，我们尝试所有有效的前缀长度。 最大有效长度为`(n - i) // 2`因为我们需要空间容纳两个相等的连续块。 

条件：```python
lcp[i][i + length] >= length
```检查两个相邻的子串是否相等。 

如果相等，我们可以进行一次删除，然后继续求解`i + length`。 

最后，`dp[0]`包含完整字符串的最大操作数。 

## 解决方案```go
func deleteString(s string) int {
	n := len(s)

	// lcp[i][j] = longest common prefix length
	// between s[i:] and s[j:]
	lcp := make([][]int, n+1)
	for i := range lcp {
		lcp[i] = make([]int, n+1)
	}

	// Build LCP table
	for i := n - 1; i >= 0; i-- {
		for j := n - 1; j >= 0; j-- {
			if s[i] == s[j] {
				lcp[i][j] = 1 + lcp[i+1][j+1]
			}
		}
	}

	// dp[i] = maximum deletions for s[i:]
	dp := make([]int, n)

	// Every suffix can always be deleted in one operation
	for i := range dp {
		dp[i] = 1
	}

	// Fill DP from right to left
	for i := n - 1; i >= 0; i-- {

		// Try every possible deletion length
		for length := 1; length <= (n-i)/2; length++ {

			// Check substring equality
			if lcp[i][i+length] >= length {
				if 1+dp[i+length] > dp[i] {
					dp[i] = 1 + dp[i+length]
				}
			}
		}
	}

	return dp[0]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于 LCP 表的 2D 切片的显式分配。 Go 字符串是字节索引的，这里可以正常工作，因为输入仅包含小写英文字母。 

不需要对整数溢出进行特殊处理，因为所有值都受以下限制`n <= 4000`。

 ## 边缘情况

 ### 单字符串

 像这样的字符串：```
"a"
```无法执行任何部分删除，因为没有第二个块可供比较。 

有缺陷的实现可能会错误地尝试超出范围的子字符串比较。 我们的实现避免了这种情况，因为循环：```
for length in range(1, (n - i) // 2 + 1)
```当可能的块少于两个时从不执行。 

### 完全不重复的字符串

 考虑：```
"abcdef"
```任何地方都不存在相邻的相等子串。 

一些不正确的解决方案意外地允许不相邻的匹配或重叠的比较。 我们的实现仅检查：```
s[i:i+length]
and
s[i+length:i+2*length]
```这保证了块是连续的。 

结果仍然正确`1`。 

### 高度重复的字符串

 字符串例如：```
"aaaaaaaa"
```创建许多有效的删除选择。 

贪婪策略可能会立即删除大块并错过最佳答案。 例如，删除`"aaaa"`第一个操作比删除操作少`"a"`一次。 

DP 解决方案通过评估每个有效的删除长度并选择最大可能的操作来避免这个问题。
