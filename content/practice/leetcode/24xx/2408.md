[LeetCode 问题 2408](https://leetcode.com/problems/design-sql/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、设计

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个轻量级的内存数据库系统，支持多表的四个核心操作：

 1. 在表中插入一行
 2.根据id删除一行
 3. 选择单个单元格值
 4. 以 CSV 样式格式导出所有行

 每个表都有固定数量的列。 构造函数接收两个数组：

 -`names[i]`是表名
 -`columns[i]`是该表中的列数

 每个插入的行都会自动接收一个整数 id。 这些 id 是特定于表的，并且针对每个表独立地自动递增。 

一条微妙但重要的规则是删除的 ID 永远不会被重复使用。 假设一个表插入带有 id 的行`1`,`2`， 和`3`，然后行`2`被删除。 下一个插入的行仍必须接收 id`4`， 不是`2`。 

这些操作的行为如下：

 -`ins(name, row)`如果表存在并且列数完全匹配，则插入一行。 
-`rmv(name, rowId)`删除一行（如果存在）。 
-`sel(name, rowId, columnId)`检索特定单元格值。 
-`exp(name)`按插入顺序导出所有现有行，格式为以行 ID 开头的逗号分隔字符串。 

限制相对较小：

 - 至多`2000`插入和删除
 - 至多`10^4`select operations
 - 至多`500`export operations

 这些限制告诉我们，我们不需要非常先进的数据库索引结构。 精心设计的基于哈希图的解决方案就足够了。 

There are several important edge cases:

 - 插入到不存在的表中
 - Inserting a row with the wrong number of columns
 - Selecting from a deleted row
 - Selecting an invalid column index
 - Exporting a table after deletions
 - Ensuring deleted ids are never reused

 A naive implementation can easily fail the auto increment requirement if it computes the next id from the current row count instead of tracking the last assigned id separately.

 ## 方法

 ### 蛮力方法

 A straightforward implementation would store each table as a simple list of rows. Every inserted row would append to the list along with its generated id.

 For removal, we could linearly search through the rows until we find the matching id and then remove it.

 For selection, we could again linearly scan the list to locate the row id, then retrieve the desired column.

 For export, we iterate through all rows and format them into CSV strings.

 This approach is correct because every operation directly searches through the actual stored rows. However, selection and removal become inefficient because they require scanning the entire table.

 在最坏的情况下：

 -`rmv`变成`O(n)`-`sel`变成`O(n)`对于许多查询，重复的线性扫描是不必要的并且效率低下。 

### 最佳方法

 关键的观察结果是每个表中的行 ID 都是唯一的。 这使得哈希映射成为行查找的理想选择。 

我们不只将行存储在列表中，而是维护：

 - 从表名到表元数据的哈希映射
 - 对于每张桌子：

 - 预期列数
 - 下一个可用的自动增量ID
 - 从行 ID 到行数据的哈希映射

 这立即改善：

 -`sel`到`O(1)`-`rmv`到`O(1)`-`ins`到`O(1)`唯一仍需要遍历行的操作是`exp`, because it must return every existing row.

 关于稀疏表的后续内容强烈建议使用哈希映射而不是按行 id 索引的密集数组。 如果发生多次删除，密集数组会浪费内存来存储空槽，而哈希映射仅存储活动行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n)`每个选择/删除|`O(n)`| 使用线性扫描行 |
 | 最佳|`O(1)`插入/选择/删除的平均值|`O(n)`| 使用哈希映射进行直接查找 |

 ## 算法演练

 1.为每个表名创建一个表结构。 

每个表存储：

 - 预期的列数
 - 下一个可用行 ID
 - 从行 ID 到行内容的哈希映射

 我们将下一个 id 初始化为`1`。 
2. 对于插入，首先验证表是否存在。 

如果表名无效，则返回`False`。 
3. 验证插入的行具有正确的列数。 

If the size does not match the table definition, return`False`。 
4. Assign the current auto increment id to the row.

 Store the row in the table's row map using this id.
 5. 增加下一个可用的 id。 

This guarantees ids are never reused, even after deletions.
 6. 要删除，请验证该表是否存在。 

If it does, remove the row id from the hash map if present.
 7. 对于选择，请验证：

 - The table exists
 - The row exists
 - 列索引在范围内

 如果任何检查失败，则返回`"<null>"`。 
8. 如果所有验证均通过，则返回正确的列值。 

注意`columnId`索引为 1，因此我们访问`row[columnId - 1]`。 
9. 对于导出，验证表是否存在。 

如果没有，则返回一个空列表。 
10. 按行 ID 升序遍历所有存储的行。 

对于每一行：

 - 将id转换为字符串
 - 使用逗号将其与所有列值连接起来
 11. 返回 CSV 格式行的结果列表。 

### 为什么它有效

 正确性依赖于维护行 ID 和存储行之间的直接映射。 由于每个插入的行都会收到一个唯一的递增 ID，因此查找是明确的。 删除仅从哈希映射中删除条目，而不会影响下一个 id 计数器，这保证了自动递增规则的保留。 

## Python 解决方案```python
from typing import List, Dict

class Table:
    def __init__(self, column_count: int):
        self.column_count = column_count
        self.next_id = 1
        self.rows: Dict[int, List[str]] = {}

class SQL:

    def __init__(self, names: List[str], columns: List[int]):
        self.tables: Dict[str, Table] = {}

        for name, column_count in zip(names, columns):
            self.tables[name] = Table(column_count)

    def ins(self, name: str, row: List[str]) -> bool:
        if name not in self.tables:
            return False

        table = self.tables[name]

        if len(row) != table.column_count:
            return False

        row_id = table.next_id
        table.rows[row_id] = row
        table.next_id += 1

        return True

    def rmv(self, name: str, rowId: int) -> None:
        if name not in self.tables:
            return

        table = self.tables[name]

        if rowId in table.rows:
            del table.rows[rowId]

    def sel(self, name: str, rowId: int, columnId: int) -> str:
        if name not in self.tables:
            return "<null>"

        table = self.tables[name]

        if rowId not in table.rows:
            return "<null>"

        row = table.rows[rowId]

        if columnId < 1 or columnId > table.column_count:
            return "<null>"

        return row[columnId - 1]

    def exp(self, name: str) -> List[str]:
        if name not in self.tables:
            return []

        table = self.tables[name]
        exported_rows = []

        for row_id in sorted(table.rows.keys()):
            row = table.rows[row_id]
            exported_rows.append(",".join([str(row_id)] + row))

        return exported_rows
```该实现将表元数据分离到专用的`Table`班级。 这提高了可读性，因为每个表自然拥有它的：

 - 列数
 - 自动递增计数器
 - 存储的行

 构造函数从表名构建一个字典`Table`目的。 

插入在存储行之前会验证表是否存在和列数。 目前的`next_id`成为行 ID，然后计数器立即递增。 

删除只是从字典中删除行 ID（如果存在）。 

选择在访问请求的列之前执行所有必需的有效性检查。 

Export 按排序顺序迭代现有行 ID，并将每行格式化为以行 ID 开头的 CSV 字符串。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

type Table struct {
	columnCount int
	nextID      int
	rows        map[int][]string
}

type SQL struct {
	tables map[string]*Table
}

func Constructor(names []string, columns []int) SQL {
	sql := SQL{
		tables: make(map[string]*Table),
	}

	for i, name := range names {
		sql.tables[name] = &Table{
			columnCount: columns[i],
			nextID:      1,
			rows:        make(map[int][]string),
		}
	}

	return sql
}

func (this *SQL) Ins(name string, row []string) bool {
	table, exists := this.tables[name]
	if !exists {
		return false
	}

	if len(row) != table.columnCount {
		return false
	}

	rowID := table.nextID
	table.rows[rowID] = row
	table.nextID++

	return true
}

func (this *SQL) Rmv(name string, rowId int) {
	table, exists := this.tables[name]
	if !exists {
		return
	}

	delete(table.rows, rowId)
}

func (this *SQL) Sel(name string, rowId int, columnId int) string {
	table, exists := this.tables[name]
	if !exists {
		return "<null>"
	}

	row, exists := table.rows[rowId]
	if !exists {
		return "<null>"
	}

	if columnId < 1 || columnId > table.columnCount {
		return "<null>"
	}

	return row[columnId-1]
}

func (this *SQL) Exp(name string) []string {
	table, exists := this.tables[name]
	if !exists {
		return []string{}
	}

	result := []string{}

	for rowID := 1; rowID < table.nextID; rowID++ {
		row, exists := table.rows[rowID]
		if !exists {
			continue
		}

		values := append([]string{strconv.Itoa(rowID)}, row...)
		result = append(result, strings.Join(values, ","))
	}

	return result
}
```Go 实现密切反映了 Python 逻辑，但使用结构和映射而不是类和字典。 

一个显着的区别是出口实施。 由于 Go 映射是无序的，我们从`1`到`nextID - 1`并检查每一行是否仍然存在。 这自然会保留插入顺序，同时跳过已删除的行。 

Go 切片用于行存储，内置`delete`函数可以有效地从地图中删除行。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |

 | 空间|`O(n)`| 存储所有活动行 |

 主要的存储成本来自于将所有行保留在内存中。 哈希映射允许通过行 ID 进行高效的直接访问，这使得插入、删除和查找速度更快。 导出仍必须迭代所有行，因为每一行都必须出现在输出中。

 ## 边缘情况

 ### 删除行而不重用 ID

 一个容易犯的错误是使用当前行计数生成下一行 id。 删除后会失败，因为 id 会被重用。 例如，插入行后`1`和`2`，然后删除`2`，下一次插入仍必须接收 id`3`。 

该实现通过维护专用的解决方案来解决这个问题`next_id`计数器只会增加，不会减少。 

### 选择无效列

 该问题使用 1 个索引列 ID。 这很容易因访问数组时的一个错误而引起。 

实施验证：```
1 <= columnId <= column_count
```访问之前：```
row[columnId - 1]
```这保证了安全索引。 

### 多次删除后的稀疏表

 如果删除了许多行，则使用直接按行 id 索引的数组会浪费内存，因为删除的位置仍为空。 

基于哈希图的设计仅存储活动行。 删除的行完全从内存中消失，即使表变得稀疏，也可以提高实现效率。 这直接解决了后续问题，并且是真正数据库（如工作负载）的首选方法。
