 # LeetCode 2447 - GCD 等于 K 的子数组数量

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 我们需要计算有多少个连续子数组的最大公约数 (GCD) 恰好等于`k`。 

子数组是数组的任何非空连续段。 对于每个可能的子数组，我们计算其中所有元素的 GCD。 如果 GCD 等于`k`，我们算一下。 

例如，如果子数组包含其公约数恰好为`k`，并且没有更大的整数可以整除所有这些，那么该子数组就可以得出答案。 

约束条件很重要：

 -`1 <= nums.length <= 1000`-`1 <= nums[i], k <= 10^9`数组长度相对较小，最多只有 1000。这表明`O(n²)`解决方案可能是可以接受的，同时`O(n³)`可能会太慢。 

这些值本身可能非常大，最多可达`10^9`，这意味着我们不能依赖频率数组或基于值的预处理。 相反，我们应该利用 GCD 运算的数学特性。 

有几种边缘情况值得考虑：

 - 包含不能被整除的元素的数组`k`。 
- 每个元素都相等的数组`k`。 
- 单元素数组。 
- 不存在有效子数组的情况。 
- GCD快速下降到以下的情况`k`，允许提前终止。 

## 方法

 ### 蛮力

 最直接的方法是枚举每个可能的子数组。 

对于每个起始索引，我们生成每个结束索引并从头开始计算该子数组内所有元素的 GCD。 如果所得的 GCD 等于`k`，我们增加答案。 

这种方法是正确的，因为它显式地检查每个可能的子数组。 然而，独立计算每个子阵列的 GCD 成本很高。 

有`O(n²)`子数组，计算子数组的 GCD 可能需要最多`O(n)`工作。 因此总复杂度变为`O(n³)`。 

和`n = 1000`，在最坏的情况下这将需要大约十亿次操作，这太慢了。 

### 关键见解

 关键的观察结果是 GCD 具有增量属性：$$\gcd(a,b,c)=\gcd(\gcd(a,b),c)$$当将子数组扩展一个元素时，我们不需要重新计算整个 GCD。 我们可以仅使用先前的 GCD 和新元素来更新当前的 GCD。 

对于每个起始位置：

 - 将当前GCD初始化为0。 
- 一次扩展子数组一个元素。 
- 更新正在运行的GCD。 

另一个重要的观察结果是，随着添加更多元素，GCD 值只会降低或保持不变。 

如果当前 GCD 变得小于`k`，它永远不会再增加。 因此，从同一位置开始的子数组的 GCD 不再等于`k`。 

这样可以尽早休息，从而显着减少不必要的工作。

## 算法演练

 ### 最优算法

 1. 初始化`answer = 0`。 
2. 迭代每个可能的起始索引`left`。 
3. 对于每个起始索引，初始化`current_gcd = 0`。 
4. 通过移动结束索引来扩展子数组`right`从`left`到数组的末尾。 
5. 更新正在运行的GCD：$$current\_gcd = \gcd(current\_gcd,\ nums[right])$$使用`0`最初有效是因为：$$\gcd(0,x)=x$$6. 如果`current_gcd == k`，增加答案，因为当前子数组满足要求。 
7.如果`current_gcd < k`，停止延伸这个起始位置并移动到下一个。 由于添加更多元素时 GCD 永远不会增加，因此达到以下值`k`意味着它永远不可能成为`k`再次。 
8. 处理完所有起始位置后，返回答案。 

### 为什么它有效

 对于固定的起始索引，该算法仅检查每个可能的结束索引一次，并使用 GCD 的关联属性维护该子数组的精确 GCD。 由于考虑了每个子数组，因此对每个有效子数组进行计数。 

提前终止是有效的，因为随着元素的添加，GCD 值形成一个不递增的序列。 一旦GCD降到以下`k`，它永远不能回到`k`，因此未来的扩展无法生成有效的子数组。 

## Python 解决方案```python
from typing import List
from math import gcd

class Solution:
    def subarrayGCD(self, nums: List[int], k: int) -> int:
        answer = 0
        n = len(nums)

        for left in range(n):
            current_gcd = 0

            for right in range(left, n):
                current_gcd = gcd(current_gcd, nums[right])

                if current_gcd == k:
                    answer += 1
                elif current_gcd < k:
                    break

        return answer
```实现直接遵循算法。 

外循环选择每个可能的起始位置。 对于每个起始位置，内部循环一次将子数组扩展一个元素。 

变量`current_gcd`存储当前子数组的 GCD。 我们不是从头开始重新计算 GCD，而是使用 Python 的内置函数逐步更新它`gcd`功能。 

每当运行的 GCD 恰好变为`k`，我们计算子数组。 当跌破以下时`k`，我们立即停止处理该起始位置，因为没有进一步的扩展可以将 GCD 恢复为`k`。 

这样就达到了想要的效果`O(n² log M)`复杂性，同时仅使用恒定的额外空间。 

## 解决方案```go
func subarrayGCD(nums []int, k int) int {
	ans := 0
	n := len(nums)

	for left := 0; left < n; left++ {
		currentGCD := 0

		for right := left; right < n; right++ {
			currentGCD = gcd(currentGCD, nums[right])

			if currentGCD == k {
				ans++
			} else if currentGCD < k {
				break
			}
		}
	}

	return ans
}

func gcd(a, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}
```Go 实现与 Python 版本几乎相同。 

Go 在标准库中没有为此用例提供内置的整数 GCD 函数，因此我们手动实现欧几里德算法。 

不需要对 nil 切片进行特殊处理，因为该问题保证至少有一个元素。 整数溢出不是问题，因为 GCD 计算永远不会超过原始输入值。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n² log M) | O(n² log M) | 每个子数组扩展执行一次 GCD 计算 |

 外循环运行`n`次，内循环最多可以运行`n`次，生产`O(n²)`迭代。 每次迭代执行一次GCD运算，其复杂度为`O(log M)`使用欧几里得算法。 因此总复杂度为`O(n² log M)`。

 ## 边缘情况

 ### 单元素数组

 当数组仅包含一个元素时，答案完全取决于该元素是否等于`k`。 有缺陷的实现可能会意外地假设每个有效子数组的长度至少为 2。 所提出的解决方案自然地处理这个问题，因为每个元素本身形成一个子数组。 

### GCD 早早跌破 K

 考虑`nums = [9, 3, 1]`和`k = 3`。 处理完第三个元素后，GCD 变为`1`。 由于GCD值只能减小，所以没有理由继续扩展子数组。 该实现正确地突破了内部循环，提高了效率，并且不会丢失任何有效答案。 

### 不能被 K 整除的元素

 考虑`nums = [4]`和`k = 7`。 GCD立即变为`4`，它已经小于`7`。 未来的延期不会将 GCD 增加至`7`。 该算法正确地提前终止并返回零。 

### 所有元素都等于 K

 对于`nums = [k, k, k]`，每个可能的子数组的 GCD 等于`k`。 该实现对每一项进行计数，因为正在运行的 GCD 仍然准确无误`k`贯穿每一个扩展。 这验证了算法是否正确处理最大数量的有效子数组。 

### GCD 总是大于 K

 考虑`nums = [8, 16, 32]`和`k = 4`。 每个子数组至少有 GCD`8`。 该算法永远不会增加答案，因为运行的 GCD 永远不会精确地变为`4`，这是所需的条件。
