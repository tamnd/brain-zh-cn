[LeetCode 问题 2476](https://leetcode.com/problems/closest-nodes-queries-in-a-binary-search-tree/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、树、深度优先搜索、二分搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉搜索树（缩写为 BST）的根，以及查询值列表。 对于每个查询，我们必须确定两个数字：

 - BST 中小于或等于查询的最大值。 
- BST 中大于或等于查询的最小值。 

如果其中一个值不存在，我们返回`-1`对于那个职位。 

最终结果是一个二维数组，其中每个查询生成一对`[mini, maxi]`。 

二叉搜索树有一个非常重要的属性：

 - 左子树中的每个值都小于当前节点。 
- 右子树中的每个值都大于当前节点。 

由于这种排序属性，如果我们执行中序遍历，BST 的值就会被排序。 

例如，考虑这个 BST：```
        6
      /   \
     2     13
    / \    / \
   1   4  9  15
             /
            14
```其中序遍历为：```
[1, 2, 4, 6, 9, 13, 14, 15]
```现在假设查询是`5`。 

- 最大值小于或等于`5`是`4`。 
- 最小值大于或等于`5`是`6`。 

所以答案是`[4, 6]`。 

限制条件很大：

 - 最多`10^5`树节点。 
- 最多`10^5`查询。 

这些限制立即告诉我们，为每个查询扫描整个树的简单解决方案将太慢。 二次型方法可以达到`10^10`的操作，远远超出了可接受的范围。 

重要的边缘情况包括：

 - 小于树中每个节点的查询。 
- 大于树中每个节点的查询。 
- 查询完全等于节点值。 
- 非常倾斜的树，其行为类似于链表。 
- 大量查询。 

该问题保证输入树是有效的 BST，这是实现高效搜索的关键属性。 

## 方法

 ### 蛮力方法

 最直接的方法是通过遍历整个树来独立处理每个查询。 

对于每个查询：

 1. 访问BST中的每个节点。 
2. 跟踪小于或等于查询的最大值。 
3. 跟踪大于或等于查询的最小值。 

这是有效的，因为最终我们会检查每个节点，因此我们不会错过有效的候选节点。 

然而，复杂性极差。 

如果树包含`m`节点并且有`n`查询：

 - 每个查询都需要`O(m)`工作。 
- 总复杂度变为`O(m * n)`。 

两个值可能等于`10^5`，这可以变成`10^10`运营。 

这种方法是正确的，但太慢了。 

### 最佳方法

 关键的观察是 BST 通过中序遍历产生排序值。 

一旦我们将 BST 转换为有序数组，问题就变成了：

 > 对于每个查询，查找：
 >
 >
 >
 >
 > - 最右边小于或等于查询的值。 
> - 最左边的值大于或等于查询。 

这正是二分搜索的设计目的。 

优化后的流程为：

 1. 进行中序遍历，创建有序数组。 
2. 对每个查询使用二分搜索。 

由于二分搜索以对数时间运行，因此每个查询都变得高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n) | O(h) | 为每个查询遍历整个树 |
 | 最佳 | O(m + n log m) | O(m + n log m) | O(米) | 中序遍历加二分查找|

 这里：

-`m`= 树节点数
 -`n`= 查询数
 -`h`= 树高

 ## 算法演练

 ### 步骤1：进行中序遍历

 使用中序遍历来遍历 BST：

 1. 访问左子树。 
2. 访问当前节点。 
3. 访问右子树。 

因为树是 BST，所以中序遍历自然会产生按排序顺序的值。 

对于示例树：```
        6
      /   \
     2     13
    / \    / \
   1   4  9  15
             /
            14
```遍历变成：```
[1, 2, 4, 6, 9, 13, 14, 15]
```我们存储这个数组是因为二分搜索需要排序的输入。 

### 第 2 步：独立处理每个查询

 对于每个查询值：

 - 找到可以放置查询的插入位置，同时保持数组排序。 
- 使用相邻指数来确定下限和上限值。 

我们使用两种二分搜索：

 1.`bisect_right`- 查找严格大于查询的第一个位置。 
- 该位置之前的元素是小于或等于查询的最大值。 
2.`bisect_left`- 查找第一个大于或等于查询的位置。 
- 该元素是大于或等于查询的最小值。 

### 步骤 3：计算下限值

 假设：```
values = [1, 2, 4, 6, 9]
query = 5
```

`bisect_right(values, 5)`回报指数`3`。 

这意味着：```
values[2] = 4
```最后一个值小于或等于`5`。 

所以：```
mini = 4
```如果返回的索引是`0`，则不存在更小的值。 

### 步骤 4：计算上限值

 使用相同的示例：```
bisect_left(values, 5)
```回报指数`3`。 

这对应于：```
values[3] = 6
```所以：```
maxi = 6
```如果返回的索引等于数组长度，则不存在更大的值。 

### 步骤 5：存储结果

 附加：```
[mini, maxi]
```每个查询的答案列表。 

### 为什么它有效

 正确性取决于两个属性。 

首先，BST 的中序遍历总是会产生排序序列。 这保证了二分查找可以正确应用。 

其次，二分查找精确识别插入边界：

 -`bisect_right`标识最后一次出现小于或等于查询之后的位置。 
-`bisect_left`标识第一个大于或等于查询的匹配项。 

这些位置直接对应于所需的下限和上限值，确保每个查询都得到正确回答。 

## Python 解决方案```python
from bisect import bisect_left, bisect_right
from typing import List, Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def closestNodes(
        self,
        root: Optional[TreeNode],
        queries: List[int]
    ) -> List[List[int]]:

        sorted_values = []

        def inorder(node: Optional[TreeNode]) -> None:
            if not node:
                return

            inorder(node.left)
            sorted_values.append(node.val)
            inorder(node.right)

        inorder(root)

        answer = []

        for query in queries:

            right_index = bisect_right(sorted_values, query)

            if right_index == 0:
                mini = -1
            else:
                mini = sorted_values[right_index - 1]

            left_index = bisect_left(sorted_values, query)

            if left_index == len(sorted_values):
                maxi = -1
            else:
                maxi = sorted_values[left_index]

            answer.append([mini, maxi])

        return answer
```实现从中序遍历辅助函数开始。 这会按排序顺序递归地遍历 BST 并将所有节点值存储在其中`sorted_values`。 

遍历完成后，树已有效地转换为排序数组。 

对于每个查询，代码执行两次二分搜索：

 -`bisect_right`确定楼层候选人。 
-`bisect_left`确定上限候选者。 

边界检查是必要的，因为二分查找可能会返回有效范围之外的位置：

 - 如果不存在更小的值，则返回`-1`。 
- 如果不存在更大的值，则返回`-1`。 

每个结果对都附加到`answer`，最后返回。 

## 解决方案```go
package main

import "sort"

/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func closestNodes(root *TreeNode, queries []int) [][]int {
    values := []int{}

    var inorder func(node *TreeNode)

    inorder = func(node *TreeNode) {
        if node == nil {
            return
        }

        inorder(node.Left)
        values = append(values, node.Val)
        inorder(node.Right)
    }

    inorder(root)

    result := make([][]int, 0, len(queries))

    for _, query := range queries {

        rightIndex := sort.Search(len(values), func(i int) bool {
            return values[i] > query
        })

        mini := -1
        if rightIndex > 0 {
            mini = values[rightIndex-1]
        }

        leftIndex := sort.Search(len(values), func(i int) bool {
            return values[i] >= query
        })

        maxi := -1
        if leftIndex < len(values) {
            maxi = values[leftIndex]
        }

        result = append(result, []int{mini, maxi})
    }

    return result
}
```Go 版本遵循与 Python 解决方案相同的算法结构。 

主要区别在于 Go 不提供内置的`bisect_left`和`bisect_right`帮手。 相反，我们使用`sort.Search`，它对索引范围执行二分搜索。 

使用两个单独的搜索：

 - 搜索第一个大于查询的值。 
- 搜索第一个大于或等于查询的值。 

Go 切片与 Python 列表类似，动态调整大小，因此存储中序遍历值非常简单。 

树遍历需要 Nil 检查，因为 Go 使用指针作为树节点。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m + n log m) | O(m + n log m) | 中序遍历需要O(m)，每次查询都使用二分查找|
 | 空间| O(米) | 将所有 BST 值存储在排序数组中 |

 中序遍历只访问每个节点一次，产生相对于树节点数量的线性复杂度。 

每个查询对已排序的数组执行两次二分搜索。 二分查找需要`O(log m)`时间，所以`n`查询需要`O(n log m)`总工作量。 

主要的额外内存使用来自于将所有 BST 值存储在有序数组中。

 ## 边缘情况

 ### 查询小于每个节点

 假设 BST 值为：```
[4, 7, 10]
```查询是：```
2
```树中没有值小于或等于`2`。 

如果我们盲目访问的话很容易产生索引下溢的bug`index - 1`二分查找后。 该实现通过检查插入位置是否是来防止这种情况发生`0`。 如果是，则返回`-1`为下限值。 

### 查询大于每个节点

 假设 BST 值为：```
[4, 7, 10]
```查询是：```
20
```没有值大于或等于`20`。 

二分查找返回等于数组长度的插入索引。 尝试访问该索引将导致越界错误。 该实现显式检查此条件并返回`-1`为上限值。 

### 查询完全等于某个节点值

 如果查询已存在于 BST 中，则两个答案都应等于查询本身。 

例如：```
values = [1, 3, 5, 7]
query = 5
```一个常见的错误是意外返回相邻值而不是完全匹配的值。 使用`bisect_left`和`bisect_right`正确地保证正确处理精确匹配。 

### 高度不平衡的 BST

 BST 可能会变得完全倾斜，表现得像链表。 

例子：```
1
 \
  2
   \
    3
     \
      4
```如果重复多次，每个查询的简单递归搜索可能会变得低效。 我们的方法仅执行树的一次遍历，然后依赖于高效的二分搜索，无论树的形状如何，都可以快速处理查询。
