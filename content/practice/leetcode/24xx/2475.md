 **难度：** 🟢简单
 **主题：** 数组、哈希表、排序

 ## 解决方案

 ## 问题理解

 该问题给了我们一个 0 索引的整数数组`nums`，我们必须数出有多少个三胞胎`(i, j, k)`满足两个条件。 

首先，指数必须严格递增：```
0 <= i < j < k < nums.length
```其次，这些指数的值必须彼此不同：```
nums[i] != nums[j]
nums[i] != nums[k]
nums[j] != nums[k]
```这意味着我们正在寻找三个选定数字成对不同的位置的三元组。 

输入数组包含正整数，数组长度介于`3`和`100`。 由于最大尺寸相当小，即使是三次解在技术上也是可接受的，因为：```
100^3 = 1,000,000
```一百万次操作是可以管理的。 然而，这个问题仍然是思考如何使用计数和组合减少不必要的工作的好机会。 

输出是一个整数，表示有效三元组的总数。 

一个重要的细节是，指数的顺序仅在头寸增加时才重要。 三胞胎`(0, 2, 4)`是有效的，但是`(2, 0, 4)`并不是因为指数没有严格递增。 

需要考虑一些重要的边缘情况：

 - 所有数字都相同的数组，因为不存在有效的三元组。 
- 所有数字都不同的数组，因为三个索引的每个组合都是有效的。 
- 具有重复值组的数组，我们必须小心避免过度计数。 
- 长度非常小的数组`3`，其中只有一个可能的三元组。 

这些约束保证输入始终包含至少三个元素，因此我们永远不需要处理太短的数组。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是尝试每一个可能的三元组`(i, j, k)`。 

我们使用三个嵌套循环：

 - 第一个循环选择索引`i`- 第二个循环选择索引`j`- 第三次循环选择索引`k`对于每个三元组，我们检查是否：```
nums[i] != nums[j]
nums[i] != nums[k]
nums[j] != nums[k]
```如果所有三个条件都为真，我们就会增加答案。 

这种方法是正确的，因为它显式地检查每个可能的有效索引组合并精确计算满足条件的三元组。 

然而，时间复杂度为：```
O(n^3)
```因为我们检查每个三元组。 

尽管这在问题约束范围内，但它执行了不必要的重复比较。 

### 最佳方法

 关键的观察是我们实际上并不关心单独的位置。 重要的是每个不同值出现的次数。 

假设我们知道每个数字的频率。 

如果我们逐一处理不同的值，我们可以将每个值视为三元组的“中间组”。 

对于具有频率的特定值`count`:

 -`left`表示有多少元素属于较小的处理组
 -`right`表示未处理的组中剩余多少元素

 那么使用这个值组的三元组的数量是：```
left * count * right
```为什么这有效？ 

- 我们从左侧选择一个元素
 - 当前值组中的一个元素
 - 从右侧算起一个元素

 由于所有三个组代表不同的值，因此每个构造的三元组自动包含不同的数字。 

这将问题从检查单个三元组转换为计算频率组之间的组合。

 ## 算法演练

 ### 最优频率计数算法

 1. 首先，统计每个数字在数组中出现的次数。 

我们使用哈希映射，其中：

 - 钥匙=数字
 - 值 = 该数字出现的频率

 例如：```
nums = [4,4,2,4,3]
```产生：```
{
    4: 3,
    2: 1,
    3: 1
}
```2.初始化三个变量：

 -`left = 0`-`right = len(nums)`-`answer = 0`这里：

-`left`跟踪有多少元素属于已处理的值组
 -`right`跟踪有多少元素尚未处理
 3. 迭代哈希图中的每个频率。 

对于每个频率`count`:

 - 删除当前组`right`- 计算有多少个三胞胎使用该组作为中间组
 - 将结果添加到答案中
 - 将当前组添加到`left`4、使用的公式为：```
answer += left * count * right
```这是有效的，因为：

 -`left`选择来自先前处理的不同值
 -`count`选择来自于当前值
 -`right`选择来自于未来独特的价值观
 5. 继续，直到处理完所有频率组。 
6. 返回最终答案。 

### 为什么它有效

 该算法将数组划分为相等值的组。 每个有效的三元组必须从三个不同的组中选择元素。 

处理一个频率组时：

 -`left`包含早期不同组中的所有元素
 -`count`包含当前不同组中的所有元素
 -`right`包含后来不同组中的所有元素

 将这些计数相乘即可得出使用这三个区域的唯一三元组的确切数量。 由于每个三元组都属于一个这样的分区，因此每个有效的三元组都被精确计数一次。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def unequalTriplets(self, nums: List[int]) -> int:
        frequency = Counter(nums)

        left = 0
        right = len(nums)
        answer = 0

        for count in frequency.values():
            right -= count

            answer += left * count * right

            left += count

        return answer
```实现首先使用构建频率图`Counter`。 这使我们能够快速确定每个不同值出现的次数。 

变量`right`最初包含数组中元素的总数。 当我们处理每个频率组时，我们从`right`因为这些元素不再被视为未来群体的一部分。 

公式：```python
answer += left * count * right
```使用以下方法计算可以形成多少个有效的三元组：

 - 来自先前处理组的一个元素，
 - 当前组中的一个元素，
 - 来自未来群体的一个元素。 

最后，我们将当前频率添加到`left`所以未来的迭代可以使用它。 

该实现很紧凑，因为组合洞察消除了对嵌套循环的需要。 

## 解决方案```go
package main

func unequalTriplets(nums []int) int {
	frequency := make(map[int]int)

	for _, num := range nums {
		frequency[num]++
	}

	left := 0
	right := len(nums)
	answer := 0

	for _, count := range frequency {
		right -= count

		answer += left * count * right

		left += count
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`用于存储频率。 Go 映射以任意顺序迭代，但这并不重要，因为计数公式适用于不同组的任何顺序。 

Go 整数就足够了，因为在给定的约束下，三元组的最大数量很小。

 ## 边缘情况

 当所有数字都相同时，就会出现一种重要的边缘情况。 例如：```
[1,1,1,1]
```如果仅检查部分不同条件，幼稚的实现可能会意外地计算三元组。 我们的实现正确处理了这个问题，因为频率图只包含一组，所以要么`left`或者`right`总是为零，使得每一个贡献都为零。 

另一个重要的情况是所有数字都不同。 例如：```
[1,2,3,4]
```在这种情况下，每个可能的三元组都是有效的。 该算法自然地计算出正确的组合总数，因为每个频率都是`1`，因此该公式有效地计算了三个不同位置的所有组合。 

第三个重要的边缘情况是整个数组中只有两个不同的值。 例如：```
[1,1,2,2]
```不存在有效的三元组，因为每个三元组都必须重复这两个值之一。 该实现会自动处理此问题，因为乘法公式需要三个单独的组来提供非零值。 

另一个微妙的情况涉及不均匀的频率分布，例如：```
[5,5,5,5,6,7]
```当一个值多次出现时，很容易意外地少算或多算。 该公式正确地考虑了多重性，因为选择了四个中的一个`5`s 创建四个不同的有效索引组合。
