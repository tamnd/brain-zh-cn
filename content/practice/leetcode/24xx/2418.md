 # LeetCode 2418，对人进行排序

 ## 问题理解

 这个问题给了我们两个长度相等的数组：

 -`names[i]`代表一个人的名字
 -`heights[i]`代表同一个人的身高

 两个数组按索引对齐，即索引处的人`i`有两个名字`names[i]`和高度`heights[i]`。 

目标是返回`names`数组按照对应的高度降序排列。 换句话说，最高的人应该首先出现，其次是第二高的人，依此类推。 

例如：```
names   = ["Mary","John","Emma"]
heights = [180,165,170]
```玛丽身高 180，约翰身高 165，艾玛身高 170。 

按高度降序排序得出：```
180 -> Mary
170 -> Emma
165 -> John
```所以最终的结果就变成了：```
["Mary","Emma","John"]
```限制很小：

 -`n <= 1000`- 高度不同
 - 高度为正整数

 最重要的保证是所有高度都是不同的。 这意味着排序时没有联系，这简化了逻辑，因为每个人在排序顺序中都有唯一的位置。 

一些值得考虑的边缘情况包括：

 - 输入中只有一个人
 - 已经排序的高度
 - 反向排序高度
 - 不同高度的重复名字
 - 约束内非常小或非常大的高度值

 简单的实现可能会在排序时意外丢失姓名和身高之间的关系。 关键的挑战是正确保存该映射。 

## 方法

 ### 蛮力方法

 一种简单的方法是反复查找剩余最高的人并将他们的名字附加到结果中。 

该算法的工作原理如下：

 1. 扫描`heights`数组来查找最大高度。 
2. 在答案中添加相应的名称。 
3. 删除该人员或将该人员标记为已处理。 
4. 重复此操作，直至处理完所有人员。 

这是有效的，因为每次迭代都会选择下一个最高的未处理人员。 然而，每次选择都需要再次扫描剩余的数组。 

如果有`n`人：

 - 首次扫描费用`O(n)`- 第二次扫描费用`O(n - 1)`- 第三次扫描费用`O(n - 2)`这导致总时间复杂度为`O(n²)`。 

虽然`n <= 1000`足够小以使其通过，但这不是最有效或最优雅的解决方案。 

### 最佳方法

 更好的解决方案是直接按照身高对人进行排序。 

关键的见解是我们应该在排序时将每个人的姓名和身高放在一起。 我们不是单独对高度进行排序，而是将相关数据组合成对：```
(height, name)
```然后我们按高度降序对这些对进行排序。 

因为现代排序算法是高度优化的，所以这种方法运行在`O(n log n)`时间。 

高度保证是不同的，因此排序始终是明确的。

 ## 算法演练

 ### 最优排序算法

 1. 创建身高和姓名对。 

我们将两个数组组合起来，以便每个人的数据在排序过程中保持连接。 

例子：```
heights = [180,170,165]
names   = ["Mary","Emma","John"]
```变成：```
[(180, "Mary"), (170, "Emma"), (165, "John")]
```2. 按高度降序对这些对进行排序。 

由于问题要求从最高到最矮，因此我们使用高度值以相反的顺序进行排序。 

排序后：```
[(180, "Mary"), (170, "Emma"), (165, "John")]
```如果输入未排序，排序将正确地重新排列这些对。 
3. 从排序对中提取名称。 

一旦人们按照身高正确排序，我们只需要名字即可得到最终答案。 

例子：```
["Mary", "Emma", "John"]
```4. 返回结果列表。 

### 为什么它有效

 该算法之所以有效，是因为排序重新排列了整个`(height, name)`配对在一起。 这保留了每个人与其身高之间的关系。 由于排序是按高度降序执行的，因此结果名称的顺序与所需的从高到低的排列完全匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortPeople(self, names: List[str], heights: List[int]) -> List[str]:
        people = list(zip(heights, names))

        people.sort(reverse=True)

        sorted_names = [name for _, name in people]

        return sorted_names
```实施开始于使用`zip()`将身高和姓名组合成对。 每对都包含一个高度及其相应的名称。```python
people = list(zip(heights, names))
```这确保了排序过程中人与其身高之间的关系保持不变。 

接下来，列表按降序排序：```python
people.sort(reverse=True)
```由于高度是每个元组的第一个元素，Python 自动首先按高度排序。 

排序后，列表理解仅提取名称：```python
sorted_names = [name for _, name in people]
```最后，返回排序后的姓名列表。 

## 解决方案```go
package main

import "sort"

func sortPeople(names []string, heights []int) []string {
	type Person struct {
		name   string
		height int
	}

	people := make([]Person, len(names))

	for i := 0; i < len(names); i++ {
		people[i] = Person{
			name:   names[i],
			height: heights[i],
		}
	}

	sort.Slice(people, func(i, j int) bool {
		return people[i].height > people[j].height
	})

	result := make([]string, len(names))

	for i := 0; i < len(people); i++ {
		result[i] = people[i].name
	}

	return result
}
```Go 解决方案遵循与 Python 版本相同的整体逻辑，但 Go 需要自定义结构体来存储相关数据。 

一个`Person`struct 将每个名称与其高度关联起来：```go
type Person struct {
    name   string
    height int
}
```该解决方案使用`sort.Slice`使用自定义比较函数按高度降序排序。 

与Python不同，Go没有内置的元组排序，因此必须显式编写比较逻辑。 

Go 切片自然会正确处理空和非空情况，因此不需要特殊处理。

 ## 边缘情况

 ### 单元素输入

 如果只有一个人，算法应该简单地返回该人的姓名不变。 

有缺陷的实现可能会在排序或索引时意外地假设存在多个元素。 此实现可以自然地处理这种情况，因为对单元素列表进行排序是有效的并且会生成相同的列表。 

### 重复的名字

 该问题不保证名称唯一。 两个或两个以上的人可能有相同的名字，但身高不同。 

使用按名称键入的字典的有缺陷的解决方案可能会覆盖条目并丢失信息。 此实现通过存储完整的内容来避免该问题`(height, name)`成对而不是唯一地映射名称。 

### 已排序或反向排序的输入

 当对初始排序做出假设时，某些排序实现会表现不正确。 

例如：```
heights = [300, 200, 100]
```已经正确排序，同时：```
heights = [100, 200, 300]
```需要完全逆转。 

该实现完全依赖于排序算法，而不是尝试根据当前顺序进行优化，因此两种情况都能正确处理。 

### 极端高度值

 约束允许高度小至`1`和一样大`100000`。 

执行不必要的算术转换的解决方案可能会在某些语言中存在溢出风险。 此实现仅直接比较整数，因此它可以安全地处理完整范围的有效高度值。
