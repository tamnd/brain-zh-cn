[LeetCode 问题 2483](https://leetcode.com/problems/minimum-penalty-for-a-shop/)

 **难度：** 🟡 中等
 **主题：** 字符串、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们确定关闭商店的最佳时间，以最大程度地减少因顾客到达而造成的损失。 输入是一个字符串`customers`其中每个字符代表一个小时：`'Y'`意味着顾客到达，并且`'N'`意味着没有顾客到达。 该商店可以在任何时间关闭`0`到`n`（含），罚金计算如下：店铺营业每小时无顾客，罚金为`1`，并且商店每关门一小时，顾客到来也会受到罚款`1`。 

预期产量是商店应关闭并遭受最低处罚的**最早时间**。 这个问题受到以下事实的限制：输入字符串可以长达`10^5`，这意味着任何重新计算每个可能的关闭时间的惩罚的蛮力方法都将太慢。 重要的边缘情况包括全天都有客户的情况（`"YYYY"`），没有时间有顾客（`"NNNN"`)，或者当多个小时产生相同的最小惩罚时，在这种情况下必须返回最早的小时。 

## 方法

 **暴力方法**计算每个可能的关闭时间的处罚。 每小时`j`，我们迭代第一个`j`小时数来计算开放但空的处罚，并迭代剩余的时间来计算关闭但繁忙的处罚。 这给出了正确的答案，但效率低下，时间复杂度为 O(n²)，这对于`n = 10^5`。 

**最佳方法**利用前缀和式计算。 我们不是重新计算每个关闭小时的罚分，而是通过遍历字符串一次来维护运行的**罚分**。 我们从假设的商店在 0 小时关门开始，这将产生等于`'Y'`在字符串中。 当我们迭代时，我们调整惩罚：开始一个小时`'N'`将惩罚增加 1，同时开放一小时`'Y'`惩罚减少 1，因为它从封闭变为开放。 我们在此迭代期间跟踪最小惩罚及其最早的索引。 这将时间复杂度降低到 O(n)，空间复杂度降低到 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 通过重复迭代所有时间来计算每个可能的关闭时间的惩罚 |
 | 最佳| O(n) | O(1) | O(1) | 使用前缀求和式更新进行运行惩罚计数的单次传递 |

 ## 算法演练

 1. 初始化`penalty`到总数`'Y'`在`customers`。 这表示如果商店在 0 点关门，则将受到处罚，因为所有有顾客的时间都会受到处罚。 
2. 设置`min_penalty`到这个初始的`penalty`和`best_hour`至 0。 
3. 使用索引迭代字符串`i`从 0 到 n-1。 
4. 每小时：

 - 如果`customers[i]`是`'Y'`, 递减`penalty`增加 1。这说明了这一小时从关闭时间改为开放时间，从而减少了处罚。 
- 如果`customers[i]`是`'N'`, 增量`penalty`1. 这说明是开放但空的，增加了惩罚。 
5. 调整后，如果`penalty`小于`min_penalty`， 更新`min_penalty`并设置`best_hour`到`i + 1`。 
6. 继续直到字符串末尾。 返回`best_hour`。 

**为什么有效**：在每一步中，`penalty`如果商店在当前时间之后立即关门，变量正确地表示了惩罚。 通过跟踪最小值及其第一次出现，我们确保返回惩罚最小的最早小时。 

## Python 解决方案```python
class Solution:
    def bestClosingTime(self, customers: str) -> int:
        penalty = customers.count('Y')
        min_penalty = penalty
        best_hour = 0
        
        for i, c in enumerate(customers):
            if c == 'Y':
                penalty -= 1
            else:  # c == 'N'
                penalty += 1
            
            if penalty < min_penalty:
                min_penalty = penalty
                best_hour = i + 1
        
        return best_hour
```该代码首先假设商店在 0 点关门，并对所有商店进行计数`'Y'`作为处罚。 当我们迭代每个小时时，惩罚会根据当前小时的客户状态进行调整。 如果找到新的最低刑罚，`best_hour`更新为当前时间之后的一小时，因为商店在这个时间**之后**关门。 

## 解决方案```go
func bestClosingTime(customers string) int {
    penalty := 0
    for _, c := range customers {
        if c == 'Y' {
            penalty++
        }
    }
    
    minPenalty := penalty
    bestHour := 0
    
    for i, c := range customers {
        if c == 'Y' {
            penalty--
        } else { // c == 'N'
            penalty++
        }
        
        if penalty < minPenalty {
            minPenalty = penalty
            bestHour = i + 1
        }
    }
    
    return bestHour
}
```Go 版本反映了 Python 解决方案。 主要区别在于使用`range`迭代字符串并显式处理符文比较。 更新惩罚和跟踪最小值的逻辑保持相同。

 ## 边缘情况

 **所有顾客到达（'YYYY'）**：最佳策略是全天候营业。 我们的代码正确地计算了每个的惩罚减量`'Y'`并返回`n`。 

**所有时间都是空的（'NNNN'）**：最佳策略是立即关闭。 我们的代码从零惩罚开始，然后逐个递增`'N'`正确，结果为 0 小时。 

**多个最佳时间**：当超过一个关闭时间产生相同的最小惩罚时，算法必须选择最早的一个。 通过更新`best_hour`只有当严格找到新的最小值时，我们自然会保留最早的索引。 

这些案例涵盖了主要的潜在陷阱，并证明了单遍方法的正确性。
