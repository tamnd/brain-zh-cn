[LeetCode 问题 2410](https://leetcode.com/problems/maximum-matching-of-players-with-trainers/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们在球员的能力不能超过教练员的训练能力的情况下，最大化球员和教练员的匹配次数。 换句话说，一个玩家`i`只能分配给训练师`j`如果`players[i] <= trainers[j]`。 此外，每位选手和每位教练最多可以参加一场比赛**。 

输入由两个整数数组组成：`players`和`trainers`。 每个数组可以很大，最多`10^5`元素，每个值最多可达`10^9`。 这告诉我们，**检查每个可能的配对的嵌套循环会太慢**，因此我们需要一种通过排序线性或近线性扩展的方法。 

输出是一个整数，表示可能的**有效匹配的最大数量**。 

需要记住的边缘情况包括：

 - 一个阵列比另一个阵列长得多（例如，许多玩家但只有一名教练）。 
- 具有相同能力或能力的球员或教练。 
- 所有球员都比所有教练都强，导致零场比赛。 

## 方法

 ### 蛮力方法

 一个幼稚的方法是迭代每个球员并尝试找到一个可以适应他们的教练。 一旦匹配，该训练师将被排除在外。 这种方法保证了正确性，但需要针对每个训练员检查每个玩家，从而给出 **O(n*m)** 时间复杂度。 考虑到约束条件（`n, m <= 10^5`），这种方法太慢了。 

### 最佳方法

 最佳方法利用**排序和两指针技术**。 关键的见解是，如果我们按升序对两个数组进行排序，我们可以将满足能力条件的**最小的可用玩家与最小的可用训练师**相匹配。 这确保了我们不会不必要地将更强的训练师浪费在较弱的玩家身上，从而最大化比赛总数。 

步骤如下：对两个数组进行排序，初始化两个指针`players`和`trainers`，并迭代它们。 如果当前玩家可以与当前训练师匹配，则增加指针和匹配计数。 如果无法匹配玩家，则将训练员指针向前移动，直至找到合适的训练员。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 检查每位球员与所有教练的情况； 大输入速度慢 |
 | 最佳| O(n log n + m log m) | O(n log n + m log m) | O(1) | O(1) | 对数组进行排序并使用两个指针进行线性扫描 |

 ## 算法演练

 1. 排序`players`数组按升序排列。 
2. 排序`trainers`数组按升序排列。 
3.初始化两个指针`i = 0`（对于玩家）和`j = 0`（针对培训师）和柜台`matches = 0`。 
4. 当两个指针都在数组边界内时：

 1. 比较`players[i]`和`trainers[j]`。 
2.如果`players[i] <= trainers[j]`，表示可以匹配到该玩家。 两者都增加`i`和`j`，并增加`matches`1.
 3. 否则，如果`players[i] > trainers[j]`， 移动`j`期待找到一位能够容纳该球员的教练。 
5. 一旦任一指针到达末尾，返回`matches`。 

**为什么有效：** 排序确保我们始终尝试使用**能力最差的教练**，但他仍然可以容纳玩家。 这为更强的玩家保留了更强的训练师，保证了最大程度的匹配，而不会跳过潜在的比赛。 

## Python 解决方案```python
from typing import List

class Solution:
    def matchPlayersAndTrainers(self, players: List[int], trainers: List[int]) -> int:
        players.sort()
        trainers.sort()
        
        i, j = 0, 0
        matches = 0
        
        while i < len(players) and j < len(trainers):
            if players[i] <= trainers[j]:
                matches += 1
                i += 1
                j += 1
            else:
                j += 1
        
        return matches
```Python 实现完全遵循该算法。 排序可确保最小的玩家与尽可能最小的训练员相匹配，并且两指针循环可以有效地计算匹配次数，而无需进行不必要的检查。 

## 解决方案```go
import "sort"

func matchPlayersAndTrainers(players []int, trainers []int) int {
    sort.Ints(players)
    sort.Ints(trainers)
    
    i, j := 0, 0
    matches := 0
    
    for i < len(players) && j < len(trainers) {
        if players[i] <= trainers[j] {
            matches++
            i++
            j++
        } else {
            j++
        }
    }
    
    return matches
}
```在 Go 中，实现是类似的。 我们使用`sort.Ints`对切​​片进行排序，整数运算确保不存在溢出风险。 空切片会被自然处理，因为循环条件立即失败。

 ## 边缘情况

 **空数组：** 两者`players`或者`trainers`可以为空。 该算法正确返回 0，因为循环从未执行。 

**所有玩家都比训练员强：** 如果每个玩家的能力都比所有训练员都高，则算法将迭代训练员，而不会增加比赛计数器。 这正确地导致零匹配。 

**重复的能力和容量：** 具有相同值的多个玩家或训练师自然会被处理。 排序可确保每个玩家尝试与第一个满足条件的可用教练进行匹配，确保不会跳过或重复计算重复项。
