 # LeetCode 2460 - 对数组应用操作

 ## 问题理解

 这个问题给了我们一个 0 索引的数组`nums`包含非负整数。 我们必须对相邻元素执行一系列操作，然后通过将所有零移到末尾来重新排列结果数组。 

第一阶段包括从左到右处理数组。 对于每个索引`i`从`0`到`n - 2`，我们比较`nums[i]`和`nums[i + 1]`。 

如果两个值相等，我们：

 1. 将值加倍`nums[i]`2. 设置`nums[i + 1]`到`0`如果值不相等，我们什么也不做并继续前进。 

一个关键细节是操作是**顺序**应用的。 一项操作期间所做的更改会影响后续操作。 我们不是与原始数组进行比较，而是与先前修改后数组的当前状态进行比较。 

毕竟`n - 1`操作已处理完毕，我们执行第二阶段，其中所有零都移至数组末尾，同时保留非零元素的相对顺序。 

输出是两个阶段之后的最终数组。 

限制相对较小：

 -`2 <= nums.length <= 2000`-`0 <= nums[i] <= 1000`由于数组最多包含 2000 个元素，因此即使是二次解在技术上也会通过。 然而，该问题自然承认线性时间解决方案，这是首选方法。 

一些边缘情况很重要：

 - 相邻的相等值可以创建参与以后比较的零。 
- 多个连续相等的值需要仔细的顺序处理。 
- 包含许多零的数组仍必须遵循运算规则，因为`0 == 0`。 
- 合并后已经没有零的数组仍然需要零移位阶段。 
- 没有相等相邻元素的数组应该简单地将现有的零移动到末尾。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是首先完全按照描述模拟所有合并操作。 之后，通过扫描数组并将零与后面的非零元素交换，重复将零移向末尾。 

这种方法是正确的，因为它直接遵循问题陈述。 然而，零偏移步骤可能变得低效。 在最坏的情况下，每个零可能需要跨多个位置移动，导致时间复杂度呈二次方。 

尽管约束足够小，这仍然有效，但它不是最有效的解决方案。 

### 最佳方法

 关键的观察是问题自然地分为两个阶段。 

首先，我们完全按照要求模拟所有合并操作。 这需要单次遍历数组。 

其次，我们使用双指针压缩技术，而不是重复交换零。 我们将所有非零值写入数组的前面，同时保留它们的顺序。 放置所有非零值后，我们用零填充剩余位置。 

这使得整个解决方案能够在线性时间内运行。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 模拟操作，然后通过交换重复移动零 |
 | 最佳 | O(n) | O(1) | O(1) | 模拟操作，然后使用两个指针压缩非零值 |

 ## 算法演练

 ### 最优算法

 1. 迭代索引`0`到`n - 2`。 
2. 对于每个索引`i`，检查是否`nums[i] == nums[i + 1]`。 
3. 如果值相等，则加倍`nums[i]`并设置`nums[i + 1]`到`0`。 
4. 继续从左到右处理数组，直到完成所有合并操作。 
5. 创建一个写指针，初始化为`0`。 该指针表示应放置非零值的下一个位置。 
6. 再次从左到右扫描阵列。 
7.每当发现非零值时，将其复制到位置`write`和增量`write`。 
8. 写入所有非零值后，从`write`到数组末尾应包含`0`。 
9. 用零填充剩余位置。 
10. 返回修改后的数组。 

### 为什么它有效

 第一遍准确地再现了问题陈述所需的顺序操作。 因为我们按升序处理索引并立即更新数组，所以以后的每次比较都会看到正确的当前状态。 

在第一阶段之后，唯一剩下的任务是将所有零移到末尾，同时保留非零元素的顺序。 两指针压缩过程保持了之前位置的不变量`write`按原始顺序包含所有先前遇到的非零值。 因此，一旦扫描完成，数组的前部将包含正确的非零元素序列，并且用零填充剩余部分将准确产生所需的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def applyOperations(self, nums: List[int]) -> List[int]:
        n = len(nums)

        # Apply merge operations
        for i in range(n - 1):
            if nums[i] == nums[i + 1]:
                nums[i] *= 2
                nums[i + 1] = 0

        # Move non-zero elements forward
        write = 0
        for num in nums:
            if num != 0:
                nums[write] = num
                write += 1

        # Fill remaining positions with zeros
        while write < n:
            nums[write] = 0
            write += 1

        return nums
```实现直接遵循算法。 

第一个循环执行所需的顺序合并操作。 每当两个相邻值相等时，左侧值加倍，右侧值变为零。 

第二个循环执行压缩步骤。 变量`write`跟踪非零值的下一个可用位置。 当我们扫描数组时，每个非零值都会被复制到最早的可用位置。 

最后，最后一个非零元素之后的任何位置都用零填充。 生成的数组满足所有零出现在末尾的要求，同时保留非零元素的相对顺序。 

## 解决方案```go
func applyOperations(nums []int) []int {
	n := len(nums)

	// Apply merge operations
	for i := 0; i < n-1; i++ {
		if nums[i] == nums[i+1] {
			nums[i] *= 2
			nums[i+1] = 0
		}
	}

	// Move non-zero values forward
	write := 0
	for _, num := range nums {
		if num != 0 {
			nums[write] = num
			write++
		}
	}

	// Fill remaining positions with zeros
	for write < n {
		nums[write] = 0
		write++
	}

	return nums
}
```Go 的实现与 Python 解决方案非常相似。 由于切片是可变的，因此所有修改都发生在适当的位置。 在给定的约束下，整数溢出不是问题，因为值可以轻松地保持在 Go 的整数范围内。 不需要对 nil 切片进行特殊处理，因为该问题保证数组长度至少为 2。

 ## 边缘情况

 ### 连续相等值

 输入如`[2,2,2]`可能会很棘手，因为操作是连续的。 处理后指标`0`，数组变为`[4,0,2]`。 指标比较`1`那么介于`0`和`2`，不在原始值之间。 尝试同时处理所有相等对的解决方案会产生错误的结果。 当数组从左向右移动时，实现会正确更新数组。 

### 包含许多零的数组

 像这样的输入`[0,0,0,0]`证明零像任何其他值一样参与比较。 自从`0 == 0`，发生合并操作，尽管加倍零仍然产生零。 实现完全遵循问题陈述，因此可以正确处理这些情况。 

### 现有零与非零值混合

 输入如`[1,0,0,2]`包含在任何操作发生之前已经存在的零。 合并阶段之后，数组可能包含额外的零。 两指针压缩步骤保留非零元素的顺序，同时将每个零移动到末尾，确保最终排列正确。 

### 没有合并机会

 像这样的输入`[1,2,3,4]`不包含相邻的相等值。 第一阶段使阵列保持不变。 第二阶段只是将相同的非零值重写回其原始位置。 结果保持不变，与预期行为相符。 

### 在开始或结束处进行单一合并

 输入如`[5,5,1,2]`或者`[1,2,5,5]`验证数组边界附近的合并是否得到正确处理。 该循环对每个有效的相邻对恰好处理一次，确保边缘位置得到与中间位置相同的处理。
