 # LeetCode 2470，LCM 等于 K 的子数组数量

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 我们必须计算有多少个连续子数组的最小公倍数 LCM 恰好等于`k`。 

子数组是数组的任何连续段。 对于每个可能的子数组，我们计算其所有元素的 LCM。 如果 LCM 等于`k`，我们增加答案。 

一组整数的最小公倍数是可被该组中每个数字整除的最小正整数。 例如：

-`LCM(2, 3) = 6`-`LCM(3, 6) = 6`-`LCM(2, 4) = 4`限制相对较小：

 -`1 <= nums.length <= 1000`-`1 <= nums[i], k <= 1000`由于数组长度只有1000，`O(n^2)`该解决方案是可以接受的，因为最多有大约一百万个子数组。 然而，一个`O(n^3)`解决方案将变得低效，因为从头开始为每个子阵列重新计算 LCM 会增加另一个因素`n`。 

一些边缘情况很重要：

 - 元素大于`k`如果它们不相除，则永远不能参与有效的子数组`k`- 一旦运行的LCM超过`k`，它永远不会再减少
 - 单个元素子数组本身可能相等`k`- 数组包含`1`需要小心处理，因为`LCM(x,1) = x`- 如果没有子数组的 LCM 等于`k`，答案应该是`0`了解 LCM 的单调行为是最优解决方案的关键观察。 

## 方法

 ### 蛮力方法

 蛮力方法考虑每个可能的子数组。 对于每个子数组，我们从头开始重新计算其所有元素的 LCM。 

假设我们选择一个起始索引`i`和结束索引`j`。 我们迭代所有元素`i`到`j`并增量计算 LCM。 如果最终的 LCM 等于`k`，我们计算该子数组。 

这种方法是正确的，因为它显式地评估每个可能的子数组并直接检查所需的条件。 

但复杂度太高：

 - 有`O(n^2)`子数组
 - 从头开始计算每个子阵列的 LCM 需要`O(n)`时间

 因此，总复杂度变为`O(n^3)`。 

和`n = 1000`，这可能会变得太慢。 

### 最佳方法

 关键的见解是我们不需要从头开始为每个子阵列重新计算 LCM。 

当从左向右扩展子数组时，我们可以增量地维护正在运行的 LCM：$$LCM(a,b)=\frac{a \times b}{GCD(a,b)}$$如果我们已经知道 LCM`nums[i..j-1]`，我们可以计算 LCM`nums[i..j]`在恒定的时间内。 

另一个重要的观察结果是，当我们添加更多元素时，LCM 只能保持不变或增加。 它永远不会减少。 

这给了我们一个强大的剪枝条件：

 - 如果运行的 LCM 变得大于`k`，我们可以停止扩展当前子数组
 - 如果`k % current_lcm != 0`，当前的 LCM 永远无法精确地变为`k`后来

 这大大减少了不必要的工作。

 ## 算法演练

 ### 第 1 步：定义 LCM 辅助函数

 我们需要一个助手来计算：$$LCM(a,b)=\frac{a \times b}{GCD(a,b)}$$我们使用最大公约数，因为它可以避免重复因式分解。 

### 第 2 步：迭代所有起始位置

 对于每个索引`start`，我们从该位置开始形成子数组。 

我们初始化：```
current_lcm = 1
```该变量将存储当前子数组的 LCM。 

### 步骤 3：向右扩展子数组

 对于每个结束索引`end >= start`，我们更新：```
current_lcm = lcm(current_lcm, nums[end])
```这可以有效地增量维护 LCM。 

### 步骤 4：检查修剪条件

 如果以下任一条件成立：```
current_lcm > k
```或者```
k % current_lcm != 0
```从这个起点我们停止探索更长的子数组。 

这是有效的，因为添加更多数字只能保持 LCM 相同或增加它。 

### 步骤 5：计算有效子数组的数量

 每当：```
current_lcm == k
```我们增加答案。 

### 步骤 6：继续，直到处理完所有启动

 我们对每个可能的起始索引重复该过程并返回总计数。 

### 为什么它有效

 该算法之所以有效，是因为每个子数组都通过其起始索引和结束索引被探索一次。 正在运行的 LCM 始终正确地表示当前子数组的 LCM，因为：$$LCM(a,b,c)=LCM(LCM(a,b),c)$$由于 LCM 是单调的，因此剪枝条件有效。 一旦 LCM 超过`k`或停止分裂`k`，未来的扩展无法将其精确地恢复到`k`。 

## Python 解决方案```python
from typing import List
from math import gcd

class Solution:
    def subarrayLCM(self, nums: List[int], k: int) -> int:
        def lcm(a: int, b: int) -> int:
            return (a * b) // gcd(a, b)

        n = len(nums)
        answer = 0

        for start in range(n):
            current_lcm = 1

            for end in range(start, n):
                current_lcm = lcm(current_lcm, nums[end])

                if current_lcm == k:
                    answer += 1

                if current_lcm > k or k % current_lcm != 0:
                    break

        return answer
```实施从导入开始`gcd`来自Python的`math`模块。 由于 LCM 公式依赖于 GCD，这为我们提供了高效且可靠的原始操作。 

辅助函数`lcm(a, b)`使用标准数学恒等式计算最小公倍数：$$LCM(a,b)=\frac{a \times b}{GCD(a,b)}$$外层循环选择子数组的起始索引。 对于每个新的起始位置，正在运行的 LCM 都会重置为`1`。 

内部循环一次扩展子数组一个元素。 我们不是重新计算整个子数组的 LCM，而是使用之前的结果增量更新它。 

每次更新后，我们检查当前的 LCM 是否等于`k`。 如果是，我们就增加答案。 

修剪条件对于效率极其重要。 一旦电流 LCM 超过`k`，或者不再划分`k`，进一步扩展是没有意义的，因为 LCM 以后无法减小。 

最后，返回有效子数组的总数。 

## 解决方案```go
package main

func gcd(a, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func lcm(a, b int) int {
	return (a * b) / gcd(a, b)
}

func subarrayLCM(nums []int, k int) int {
	n := len(nums)
	answer := 0

	for start := 0; start < n; start++ {
		currentLCM := 1

		for end := start; end < n; end++ {
			currentLCM = lcm(currentLCM, nums[end])

			if currentLCM == k {
				answer++
			}

			if currentLCM > k || k%currentLCM != 0 {
				break
			}
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 不提供内置的`gcd`函数，所以我们手动实现欧几里得算法。 这`lcm`helper 使用整数运算，与 Python 解决方案完全相同。 

由于约束很小，因此这里不必担心整数溢出，因为所有值最多为 1000。 

Go 中的切片对于数组遍历的表现很自然，因此对于空数组不需要特殊处理，因为该问题保证至少有一个元素。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 由于任意数字的 LCM 大于`1`不能成为`1`，只有完全由以下组成的子数组`1`s 有效。 这很容易暴露实现中的错误，这些错误会错误地初始化正在运行的 LCM 或错误处理乘法。 该实现自然地处理了这个问题，因为正在运行的 LCM 仍然存在`1`仅当所有包含的元素也都`1`。 

另一个重要的情况发生在元素不能整除时`k`。 例如，如果`k = 6`我们遇到`7`，正在运行的 LCM 立即变得不兼容`k`。 简单的解决方案可能会继续不必要地扩展子数组。 修剪条件：```
k % current_lcm != 0
```正确地立即停止进一步处理。 

第三种边缘情况涉及重复的有效 LCM 值。 考虑`[2,2,2]`和`k = 2`。 每个可能的子数组的 LCM 等于`2`。 某些实现会意外地跳过对重叠子数组的计数或错误地重置正在运行的 LCM。 嵌套循环结构确保每个连续范围都被独立评估并正确计数。 

当运行的 LCM 超过`k`。 由于 LCM 是单调的，一旦它变得大于`k`，它永远不会收缩。 如果没有这种观察，算法就会浪费时间探索不可能的扩展。 在这些情况下，实现会提前正确终止，从而提高效率，同时保持正确性。
