 # LeetCode 2495 - 具有偶数积的子数组的数量

 ## 问题理解

 问题给了我们一个整数数组`nums`并要求我们计算有多少个连续子数组具有偶数乘积。 

子数组是数组的连续段。 对于每个可能的子数组，我们计算其所有元素的乘积。 如果该乘积是偶数，则子数组有助于最终答案。 

关键的数学观察是，当且仅当乘积中至少有一个数字是偶数时，乘积才是偶数。 这个属性完全改变了我们思考问题的方式。 我们不需要将数字相乘，这可能会变得昂贵且不必要，我们只需要确定子数组是否包含偶数。 

输入约束很重要：

 -`1 <= nums.length <= 10^5`-`1 <= nums[i] <= 10^5`大小的数组`10^5`意味着一个`O(n^2)`在最坏的情况下，解决方案将太慢。 大致有`10^10`在这种情况下可能的子数组，这在计算上是不可行的。 

该问题保证所有数字都是正整数，因此我们不需要担心零、负值或浮点行为。 

一些边缘情况很重要：

 - 仅包含奇数的数组，因为答案应该是`0`- 仅包含偶数的数组，因为每个子数组都是有效的
 - 具有单个元素的数组
 - 偶数稀疏出现的数组
 - 非常大的阵列，其中性能非常重要

 显式计算每个乘积的简单实现效率极低，并且在某些语言中还可能面临整数溢出的风险。 

## 方法

 ### 蛮力方法

 强力解决方案检查每个可能的子数组。 

对于每个起始索引`i`，我们将子数组一次向右扩展一个元素。 我们对运行中的产品进行维护并检查其是否均匀。 

这种方法是正确的，因为它显式地评估每个可能的连续子数组并精确计算乘积为偶数的子数组。 

然而，性能较差。 有`O(n^2)`子数组，即使使用增量乘法，该算法仍然需要二次时间。 和`n = 10^5`，这变得不切实际。 

另一个问题是，反复乘以值会产生不必要的工作。 由于奇偶性仅决定乘积是否均匀，因此计算完整的乘积是浪费的。 

### 最佳方法

 关键的见解是：

 如果子数组包含至少一个偶数，则乘积为偶数。 

这意味着我们根本不需要计算乘积。 

相反，对于数组中的每个位置，我们确定有多少个以该位置结尾的子数组包含偶数。 

假设我们在索引处`i`：

- 如果`nums[i]`是偶数，那么每个子数组结束于`i`具有均匀的乘积，因为当前元素本身保证了均匀性。 
- 如果`nums[i]`是奇数，那么只有已经包含先前偶数的子数组仍然有效。 

我们可以跟踪最近遇到的偶数索引。 一旦我们知道最新的偶数位置，我们就立即知道有多少以当前索引结尾的子数组是有效的。 

这导致了一个简单的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 枚举所有子数组并检查产品 |
 | 最佳 | O(n) | O(1) | O(1) | 跟踪最近的偶数索引 |

 ## 算法演练

 1. 初始化变量`last_even_index`到`-1`。 

该变量存储迄今为止看到的最新偶数的索引。 如果还没有出现偶数，则保留`-1`。 
2. 初始化变量`answer`到`0`。 

这将累积有效子数组的总数。 
3.使用索引从左到右遍历数组`i`。 
4. 对于每个元素：

 - 如果`nums[i]`为偶数，更新`last_even_index = i`。 
- 这意味着每个子数组都以`i`并从任何地方开始`0`到`i`将包含至少一个偶数。 
5. 添加`last_even_index + 1`到答案。 

为什么这有效？ 

- 如果最新的偶数位于索引处`k`，然后每个子数组结束于`i`并从任意位置开始`0`通过`k`包含该偶数。 
- 正好有`k + 1`这样的起始位置。 
6. 继续，直到处理完整个数组。 
7. 返回累计答案。 

### 为什么它有效

 该算法保持不变式`last_even_index`始终存储当前位置之前或当前位置的最新偶数。 

对于每个索引`i`，结束于的子数组`i`当且仅当其范围包含至少一个偶数时，才有偶数乘积。 由于最新的偶数足以确定所有有效的起始位置，因此计数`last_even_index + 1`精确计算所有以以下结尾的有效子数组`i`。 

由于每个有效子数组都只计算一次，因此该算法会产生正确的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def evenProduct(self, nums: List[int]) -> int:
        last_even_index = -1
        total_subarrays = 0

        for index, value in enumerate(nums):
            if value % 2 == 0:
                last_even_index = index

            total_subarrays += last_even_index + 1

        return total_subarrays
```该实现紧密遵循前面描述的算法。 

变量`last_even_index`跟踪偶数出现的最新位置。 最初，它被设置为`-1`因为没有看到偶数。 

当我们迭代数组时，每个偶数值都会更新该索引。 

对于每个位置，我们添加`last_even_index + 1`到总计数。 这直接表示以当前位置结束的子数组中有多少个至少包含一个偶数。 

该实现仅使用恒定的额外内存，并且仅处理该数组一次。 

## 解决方案```go
func evenProduct(nums []int) int64 {
    lastEvenIndex := -1
    var totalSubarrays int64 = 0

    for i, value := range nums {
        if value%2 == 0 {
            lastEvenIndex = i
        }

        totalSubarrays += int64(lastEvenIndex + 1)
    }

    return totalSubarrays
}
```Go 实现非常接近地反映了 Python 解决方案。 

一个重要的区别是返回类型。 该函数返回`int64`因为子数组的数量可能会变得非常大。 对于大小的数组`10^5`，子数组的总数可以超出标准 32 位整数的范围。 

Go 切片天然地代表动态数组，因此内存分配不需要特殊处理。

 ## 边缘情况

 当数组仅包含奇数时，会出现一种重要的边缘情况。 在这种情况下，任何子数组都不能有偶数乘积，因为奇数相乘总是会产生另一个奇数。 该实现自然地处理了这个问题，因为`last_even_index`遗迹`-1`，导致每一步都添加零。 

另一个关键的边缘情况是每个数字都是偶数。 在这种情况下，每个可能的子数组都是有效的。 该算法正确计算所有子数组，因为每个位置都会更新`last_even_index`，并且以每个索引结尾的所有子数组都变得有效。 

第三种重要情况是数组中只有一个偶数。 这可能很棘手，因为只应计算包含该特定索引的子数组。 该实现通过记住最新的偶数位置并计算直到该索引的所有起始位置来有效地处理这个问题。 

大输入也很重要，因为二次解会超时。 由于该实现只处理每个元素一次并使用恒定的额外内存，因此它可以有效地扩展到最大约束大小`10^5`。
