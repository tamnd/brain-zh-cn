[LeetCode 问题 2491](https://leetcode.com/problems/divide-players-into-teams-of-equal-skill/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、两个指针、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们将给定的玩家技能水平列表划分为恰好由两名玩家组成的团队，以便每个团队都具有**相同的总技能**。 一支球队的化学反应被定义为两名球员技能的产物，如果可能的话，我们被要求返回所有球队化学反应的总和。 如果无法将玩家分为总技能相等的队伍，我们必须返回`-1`。 

输入是一个列表`skill`长度均匀的`n`，其中每个元素代表玩家的技能水平。 由于列表长度是偶数，因此可以保证我们可以将所有玩家配对，但挑战是使每对的技能总和相同。 约束条件，`2 <= skill.length <= 10^5`和`1 <= skill[i] <= 1000`，表明我们需要一个比 O(n^2) 更快的算法，因为简单的暴力方法会太慢。 

重要的边缘情况包括：两名玩家的最小输入、所有玩家都具有相同技能的输入以及不可能将玩家分为同等技能团队的输入。 

## 方法

 ### 蛮力

 暴力方法将尝试所有可能的方法将玩家配对并检查每对的总和是否相等。 这涉及生成配对的所有排列并验证总和约束，然后计算化学反应。 虽然这保证了正确性，但配对的数量随着`n`，导致时间复杂度为 O(n!)，这对于`n`最多 10^5。 

### 最佳方法

 更快解决方案的关键在于，如果每个团队的总技能相同，则排序数组中的最小技能和最大技能之和应等于该总数。 对数组进行排序允许我们将最小的技能与最大的技能配对，将第二小的技能与第二大的技能配对，依此类推。 如果在任何时候一对的总和不等于预期的总和，就不可能组成同等技能的团队。 

通过使用这种方法，我们只需要对数组进行排序 (O(n log n))，然后迭代一半数组来计算化学 (O(n))。 这产生了高效且可扩展的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 检查所有可能的玩家配对。 对于大型来说不切实际`n`。 |
 | 最佳| O(n log n) | O(n log n) | O(1) | O(1) | 对数组进行排序，将最小与最大配对，并检查和。 计算化学。 |

 ## 算法演练

 1. **对数组进行排序`skill`** 按升序排列。 排序使我们能够系统地将最小和最大技能的球员配对，以最大限度地提高平等球队的机会。 
2. **通过对排序数组中的第一个和最后一个元素求和来确定预期的团队总技能**。 这是所有配对必须相等的总技能。 
3. **初始化一个变量`total_chemistry`** 到 0，这将累加每对的乘积。 
4. **使用两个指针迭代**，一个从数组的开头开始（`left`）和最后一个（`right`），并执行以下操作：

 1. 计算该对的总和：`skill[left] + skill[right]`。 
2. 如果总和不等于预期总数，则返回`-1`立即地。 
3. 否则，计算乘积（化学）并将其添加到`total_chemistry`。 
4. 移动`left`指针向前和`right`指针向后。 
5.迭代完成后，**返回`total_chemistry`**。 

**为什么有效：** 对最小与最大进行排序和配对可确保如果存在有效除法，则此策略将找到它。 如果任何一对违反了预期的总技能，就不可能创建同等技能的团队。 此方法使用以下不变量：对于任何有效的同等技能对集合，最小值和最大值必须组成一个团队。 

## Python 解决方案```python
from typing import List

class Solution:
    def dividePlayers(self, skill: List[int]) -> int:
        skill.sort()
        n = len(skill)
        total_skill = skill[0] + skill[-1]
        total_chemistry = 0
        
        left, right = 0, n - 1
        while left < right:
            if skill[left] + skill[right] != total_skill:
                return -1
            total_chemistry += skill[left] * skill[right]
            left += 1
            right -= 1
            
        return total_chemistry
```**实现演练：** 代码首先对`skill`大批。`total_skill`是所有对的目标总和。 两个指针从数组的末端向中心迭代，验证总和并累积化学反应。 如果任何对的总和不正确，函数将返回`-1`。 

## 解决方案```go
import "sort"

func dividePlayers(skill []int) int64 {
    sort.Ints(skill)
    n := len(skill)
    totalSkill := skill[0] + skill[n-1]
    var totalChemistry int64 = 0
    
    left, right := 0, n-1
    for left < right {
        if skill[left]+skill[right] != totalSkill {
            return -1
        }
        totalChemistry += int64(skill[left]) * int64(skill[right])
        left++
        right--
    }
    
    return totalChemistry
}
```**Go 特定注释：** 我们使用`int64`为了`totalChemistry`处理可能超过的大型产品`int`。 排序是通过标准完成的`sort.Ints`。 两指针迭代的工作方式与 Python 类似，具有乘法的显式类型转换。 

## 工作示例

 **示例1：**`skill = [3,2,5,1,3,4]`| 步骤| 左| 对| 技能[左]+技能[右]| 产品 | 总化学 |
 | ---| ---| ---| ---| ---| ---|
 | 初始排序：[1,2,3,3,4,5] | 0 | 5 | 1+5=6 | 5 | 5 |
 | 迭代 2 | 1 | 4 | 2+4=6 | 8 | 13 |
 | 迭代 3 | 2 | 3 | 3+3=6 | 9 | 22 | 22

 返回`22`。 

**示例2：**`skill = [3,4]`排序：`[3,4]`，总和 = 7，乘积 = 12。返回`12`。 

**示例3：**`skill = [1,1,2,3]`排序：`[1,1,2,3]`，第一对 1+3=4，第二对 1+2=3 ≠ 4，返回`-1`。

 ## 边缘情况

 1. **最小输入：** 当`skill`只有两名球员，算法正确地将化学反应计算为两个值的乘积。 排序不会改变数组，并且总和检查也很简单。 
2. **所有玩家都具有相同的技能：** 如果每个玩家都具有相同的技能，那么每一对的总和自然会相同。 该算法可以正确处理这个问题，因为总和检查总是通过并且化学反应正确累积。 
3. **不可能的团队划分：** 任何对的组合都不能产生相等的团队总和的数组（例如，`[1,1,2,3]`) 被正确处理，因为两指针和检查在某些时候会失败，返回`-1`。 这可以防止返回无效的化学总和。 

该解决方案对于所有指定的约束都是稳健的，并且可以有效地处理极值。
