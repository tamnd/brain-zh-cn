[LeetCode 问题 2401](https://leetcode.com/problems/longest-nice-subarray/)

 **难度：** 🟡 中等
 **主题：** 数组、位操作、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题给出一个正整数数组，并要求被认为“好的”的最长连续子数组的长度。 

当子数组中每对不同的元素都按位与等于`0`。 换句话说，对于子数组中的任意两个不同的数字：```
a & b == 0
```这种情况意味着两个数字不能共享任何设置的位位置。 如果一个数字有`1`在特定的二进制位置，子数组中的每个其他数字都必须具有`0`在同一个位置。 

例如：```
3  = 0011
8  = 1000
48 = 110000
```这些数字在它们的设置位中都不重叠，因此每个成对的 AND 都是`0`。 

输入数组最多可以包含`10^5`元素，每个值可以大到`10^9`。 这些限制立即表明`O(n^2)`解决方案可能会太慢，因为在最坏的情况下检查所有子数组或子数组内的所有对将需要数十亿次操作。 

该问题保证所有数字都是正整数。 这很重要，因为我们不需要担心负数位表示或符号位。 

一些边缘情况很重要：

 - 长度数组`1`，答案总是`1`。 
- 每对都冲突的数组，答案仍然存在`1`。 
- 所有数字都相互兼容的数组，答案就是整个数组的长度。 
- 冲突看起来相距甚远的情况，需要小心缩小窗口。 
- 具有多个设置位的数字，因为冲突可能同时发生在多个位置。 

关键的挑战是有效地确定不断增长的子数组是否仍然满足成对 AND 条件。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组。 

对于每个起始索引，我们一次扩展子数组一个元素，并检查新形成的子数组是否仍然很好。 为了验证这一点，我们将使用按位 AND 将新元素与当前子数组中的所有先前元素进行比较。 

例如：```
nums = [1,3,8,48,10]
```从索引开始`0`:

 -`[1]`有效
 -`[1,3]`无效，因为`1 & 3 != 0`从索引开始`1`:

 -`[3]`有效
 -`[3,8]`有效
 -`[3,8,48]`有效
 -`[3,8,48,10]`无效，因为`8 & 10 != 0`这种方法是正确的，因为它显式检查每个可能的子数组并准确验证所需的条件。 

然而，由于限制，它太慢了。 在最坏的情况下：

 - 有`O(n^2)`子数组。 
- 每次验证可能需要最多`O(n)`配对检查。 

这导致`O(n^3)`时间以朴素的形式，或者`O(n^2)`通过增量优化，这两种方法对于`n = 10^5`。 

### 最佳解决方案的关键见解

 重要的观察是，一个好的子数组不能包含重叠的设置位。 

假设我们维护一个当前很好的滑动窗口。 因为没有两个数字共享一个设置位，所以我们可以使用按位或组合窗口中的所有数字：```
window_mask = nums[left] | nums[left+1] | ... | nums[right]
```由于没有位重叠，因此每个设置位`window_mask`恰好属于窗口中的一个数字。 

现在考虑添加一个新号码`nums[right]`。 

如果：```
window_mask & nums[right] == 0
```那么新数字不与窗口中任何现有数字共享任何位，因此窗口保持良好状态。 

否则，就会发生冲突。 我们必须从左边缩小窗口，直到冲突消失。 

这自然会导致滑动窗口方法，其中：

 - 该窗口始终保持有效。 
- 我们贪婪地扩大右边界。 
- 我们仅在必要时缩小左边界。 

由于每个元素最多进入和离开窗口一次，因此该算法以线性时间运行。

 ## 算法演练

 1.初始化两个指针，`left`和`right`，代表当前的滑动窗口。 
2. 维护一个名为`window_mask`。 这存储当前窗口内所有元素的按位或。 
3. 使用迭代遍历数组`right`。 
4.添加前`nums[right]`进入窗口，检查是否与当前窗口冲突：```
window_mask & nums[right]
```如果结果非零，则某些位与窗口中的现有数字重叠，因此子数组将不再合适。 
5. 当存在冲突时，删除窗口左侧的元素。 

由于有效窗口内的每一位都属于一个元素，因此我们可以使用 XOR 安全地删除一个数字：```
window_mask ^= nums[left]
```然后递增`left`。 
6. 冲突消失后，将新号码添加到掩码中：```
window_mask |= nums[right]
```7. 计算当前窗口长度：```
right - left + 1
```如果此窗口较大，则更新最大答案。 
8. 继续，直到处理完所有元素。 

### 为什么它有效

 滑动窗口始终保持窗口内没有两个数字共享一组位的不变性。 因此，当前窗口始终是有效的 Nice 子数组。 

当出现冲突时，从左侧收缩会删除冲突位，直到恢复不变量。 由于每个元素都添加一次并删除一次，因此该算法可以有效地处理数组，同时保证考虑每个最大有效窗口。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestNiceSubarray(self, nums: List[int]) -> int:
        left = 0
        window_mask = 0
        max_length = 0

        for right in range(len(nums)):
            while window_mask & nums[right] != 0:
                window_mask ^= nums[left]
                left += 1

            window_mask |= nums[right]

            current_length = right - left + 1
            max_length = max(max_length, current_length)

        return max_length
```其实现直接遵循滑动窗口算法。 

变量`left`存储当前窗口的开头。 循环变量`right`一次将窗口展开一个元素。`window_mask`存储当前窗口内所有数字的 OR 组合。 由于窗口始终保持有效，因此其元素之间没有位重叠。 

这`while`循环处理冲突。 如果新数字与当前掩码共享任何位，则会从左侧删除元素，直到重叠消失。 

删除使用 XOR 而不是重新计算整个掩码。 这是可行的，因为每个设置位都属于有效窗口中的一个元素。 

冲突解决后，使用 OR 将新号码合并到窗口中。 然后计算当前窗口长度并用于更新答案。 

## 解决方案```go
func longestNiceSubarray(nums []int) int {
    left := 0
    windowMask := 0
    maxLength := 0

    for right := 0; right < len(nums); right++ {
        for (windowMask & nums[right]) != 0 {
            windowMask ^= nums[left]
            left++
        }

        windowMask |= nums[right]

        currentLength := right - left + 1
        if currentLength > maxLength {
            maxLength = currentLength
        }
    }

    return maxLength
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用显式变量声明和标准`for`循环而不是Python的`range`。 整数溢出不是问题，因为约束完全适合 LeetCode 平台上 Go 的默认整数类型。 

位运算的行为与 Python 相同，因为所有值都是正整数。

 ## 边缘情况

 一种重要的边缘情况是只有一个元素的数组。 由于子数组的长度`1`总是很好，答案一定是`1`。 某些实现意外地错误地初始化了结果，或者无法正确处理最小输入大小。 此实现自然可以处理这种情况，因为第一次迭代创建了一个长度的窗口`1`。 

当每对数字发生冲突时，就会出现另一个重要的情况。 例如：```
[7,7,7]
```每个数字都与其他数字共享位，因此有效子数组的长度不超过`1`存在。 滑动窗口反复收缩回单个元素，确保最大长度永远不会超过`1`。 

第三个棘手的情况涉及没有重叠的长有效窗口，例如：```
[1,2,4,8,16]
```每个数字都使用唯一的位位置，因此整个数组都是有效的。 该算法正确地保持扩大窗口而不缩小，产生完整的数组长度作为答案。 

另一个微妙的边缘情况是在多次有效添加后出现冲突。 例如：```
[1,2,4,3]
```前三个数字可以毫无问题地共存，但是`3`与两者重叠`1`和`2`。 该算法必须反复缩小窗口，直到所有冲突消失。 这`while`循环确保在添加新数字之前删除每个冲突元素。
