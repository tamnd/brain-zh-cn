[LeetCode 问题 2452](https://leetcode.com/problems/words-within-two-edits-of-dictionary/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、Trie

 ## 解决方案

 ## 问题理解

 该问题要求我们识别其中的单词`queries`可以转换为单词的列表`dictionary`最多包含**两个字符编辑**的列表。 每次编辑都包括将单个字符更改为另一个小写英文字母。 保证两个数组中的单词具有相同的长度，这简化了比较，因为我们不需要处理插入或删除，只需处理替换。 

输入是：

 -`queries`：表示候选词的字符串列表。 
-`dictionary`：表示我们要匹配的有效单词的字符串列表。 

预期的输出是来自的字符串列表`queries`这可以成为一个词`dictionary`使用 **0、1 或 2 次编辑**，保留它们出现的顺序`queries`。 

约束告诉我们：

 - 两个数组最多有 100 个元素，每个单词的长度最多为 100。这意味着每个查询与每个字典单词的强力比较是可行的，因为在最坏的情况下会进行 100 * 100 = 10,000 次比较。 每次比较最多涉及 100 个字符检查。 
- 所有字符串均由小写字母组成，因此字符级比较非常简单。 

重要的边缘情况包括：

 - 词典中已有的单词（需要 0 次编辑）。 
- 恰好相差 1 或 2 个字符的单词。 
- 需要两次以上编辑且不应包含的单词。 
- 最小输入大小（长度为 1 的字符串或单元素列表）。 

## 方法

 ### 暴力方法

 暴力方法将每个查询与每个字典单词进行比较。 对于每一对，计算有多少个字符不同。 如果不同字符的数量为 0、1 或 2，则将查询包含在结果中。 这种方法是正确的，因为它会详尽地检查所有可能的匹配项，但如果输入大小较大，则可能会很慢。 

### 最佳方法的关键见解

 考虑到这些限制，暴力方法已经很有效了。 不需要额外的数据结构。 关键的见解是，我们只需要进行简单的逐字符比较，并在检测到 2 个以上差异时尽早退出。 这避免了不必要的检查并稍微提高了运行时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(Q * D * n) | O(Q) | 将每个查询与每个字典单词进行比较； n 是字长 |
 | 最佳| O(Q * D * n) | O(Q) | 3 次不匹配后提前退出会减少常数因子，否则与暴力破解相同 |

 ## 算法演练

 1.初始化一个空列表`result`存储有效的查询。 
2. 迭代每个单词`query`在`queries`。 
3. 对于每个`query`，迭代每个单词`word`在`dictionary`。 
4. 初始化计数器`diff`至 0。 
5. 比较每个索引处的字符`query`和`word`。 增量`diff`对于每一个不匹配。 
6. 如果在任何时候`diff`超过 2，则尽早中断内部循环，因为该字典单词无法匹配。 
7. 如果比较所有字符后`diff`小于或等于 2，则追加`query`到`result`并中断到下一个查询。 
8. 返回`result`处理完所有查询后。 

**为什么有效：** 该算法会根据每个字典单词检查每个查询，最多允许两次编辑。 提前终止可确保效率。 由于每个查询都会与所有可能的匹配项进行比较，因此不会遗漏任何有效单词。 

## Python 解决方案```python
from typing import List

class Solution:
    def twoEditWords(self, queries: List[str], dictionary: List[str]) -> List[str]:
        result = []
        for query in queries:
            for word in dictionary:
                diff = 0
                for c1, c2 in zip(query, word):
                    if c1 != c2:
                        diff += 1
                        if diff > 2:
                            break
                if diff <= 2:
                    result.append(query)
                    break
        return result
```**实现说明：** 我们迭代每个查询和每个字典单词，计算不匹配的字符。 使用`zip`简化了逐个字符的比较。 如果不匹配超过 2 个，我们立即停止计数，以节省不必要的计算。 一旦找到匹配项，查询就会添加到`result`我们继续下一个查询。 

## 解决方案```go
func twoEditWords(queries []string, dictionary []string) []string {
    var result []string
    for _, query := range queries {
        for _, word := range dictionary {
            diff := 0
            for i := 0; i < len(query); i++ {
                if query[i] != word[i] {
                    diff++
                    if diff > 2 {
                        break
                    }
                }
            }
            if diff <= 2 {
                result = append(result, query)
                break
            }
        }
    }
    return result
}
```**Go 特定注释：** Go 版本使用标准`for`循环进行字符比较，因为 Go 字符串是字节切片。`append`用于动态构建结果切片。 无需处理`nil`切片作为输入约束保证非空列表。 

## 工作示例

 **示例1：**```
queries = ["word","note","ants","wood"]
dictionary = ["wood","joke","moat"]
```单步执行`query = "word"`:

 - 比较`"wood"`: 差异 = 1 ('r' -> 'o')，追加`"word"`。 
-`"note"`: 与比较`"joke"`: 差异 = 2 ('n' -> 'j', 't' -> 'k'), 追加`"note"`。 
-`"ants"`：与所有词典单词比较，差异超过2，跳过。 
-`"wood"`：匹配`"wood"`确切地说，附加`"wood"`。 

结果=`["word","note","wood"]`。 

**示例2：**```
queries = ["yes"]
dictionary = ["not"]
```-`"yes"`与`"not"`：差异= 3，超过2，跳过。 

结果=`[]`。

 ## 边缘情况

 1. **字典中完全匹配的查询：** 这些需要 0 次编辑。 无需额外逻辑即可实现正确识别它们，因为差值计数器将为零，即 ≤ 2。 
2. **仅相差 2 个字符的查询：** 这些是边界情况。 该算法通过计算不匹配次数来处理它们，只要计数≤2，该单词就包含在结果中。 
3. **需要两次以上编辑的查询：** 应排除此类单词。 提前退出机制确保一旦`diff > 2`，内部循环中断并且不添加查询。 
4. **单字符单词：** 由于单词的长度可以为1，因此我们必须正确处理这些单词，包括零次或一次编辑。 该解决方案之所以有效，是因为它逐个字符进行比较并且约束允许`n = 1`。 
5. **空列表：** 算法处理空列表`queries`或者`dictionary`优雅地，返回一个空结果，没有错误。
