[LeetCode 问题 2458](https://leetcode.com/problems/height-of-binary-tree-after-subtree-removal-queries/)

 **难度：** 🔴难
 **主题：** 数组、树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们回答二叉树上的多个独立查询。 对于每个查询，我们暂时删除以特定节点为根的整个子树，然后计算剩余树的高度。 

二叉树包含`n`节点，并且每个节点都有一个唯一的值`1`到`n`。 查询数组包含节点值。 对于每个查询值`q`，我们删除以节点为根的子树`q`，意味着该节点及其所有后代从树中消失。 

删除子树后，我们必须确定剩余树的高度。 高度定义为从根到任何剩余节点的最长路径中的边数。 

一个重要的细节是所有查询都是独立的。 完成一个查询后，树会在处理下一个查询之前返回到其原始形式。 我们不会永久修改这棵树。 

限制条件很大：

 -`n`可以大到`100000`-`queries.length`可以达到`10000`这些限制立即告诉我们，为每个查询从头开始重新计算树高会太慢。 为每个查询遍历树的简单解决方案很容易变成`O(n * m)`，可能达到`10^9`最坏情况下的操作。 

另一个重要的观察结果是查询永远不会删除根本身。 因此，生成的树始终是非空的。 

有几种边缘情况值得考虑：

 - 删除叶节点通常不会影响整体高度，除非该叶节点位于唯一的最深路径上。 
- 删除内部节点可能会断开非常大的子树，从而显着降低高度。 
- 移除后最深的路径可能会转移到完全不同的分支。 
- 高度倾斜树的行为与平衡树不同，因为几乎每个节点都位于最大深度路径上。 

核心挑战是在排除每个可能的子树后有效地确定剩余树的高度。 

## 方法

 ### 蛮力方法

 最直接的方法是独立处理每个查询。 

对于每个查询：

 1. 假设以查询节点为根的子树不存在。 
2. 从根运行 DFS 或 BFS。 
3. 计算所有剩余节点中的最大深度。 
4. 返回该深度作为结果高度。 

这是有效的，因为它显式地重建了每个查询的答案。 

然而，性能较差。 每个查询可能需要遍历几乎整棵树，这会花费`O(n)`。 由于最多可以有`10^4`查询，总复杂度变为`O(n * m)`。 

和`n = 100000`和`m = 10000`，这种方法太慢了。 

### 最佳解决方案的关键见解

 我们可以预先计算足够的信息来在恒定时间内回答每个查询，而不是在每次删除后重新计算树高。 

关键的观察是：

 删除以节点为根的子树时`u`，剩余的树高一定来自于某条不进入的路径`u`的子树。 

因此对于每个节点，我们想知道：

 > 如果不使用该节点的子树，可实现的最大高度是多少？ 

这成为一个重生型树DP问题。 

我们计算两个重要的值：

 1.`subtree_height[node]`- 以该节点为根的子树的高度。 
- 使用后序 DFS 计算。 
2.`answer[node]`- 删除该节点的子树后剩余树的高度。 
- 使用第二个 DFS 计算。 

第二个 DFS 将信息从父级传播到子级。 当从父树移动到一个子树时，我们计算避开该子树的最佳可能高度。 这可以来自：

 - 父级之上的路径
 - 通过兄弟子树的路径

 通过仔细传播这些值，每个查询都可以得到回答`O(1)`预处理后的时间。

 ## 算法演练

 ### 步骤 1：计算子树高度

 我们首先从根运行 DFS 来计算：```
subtree_height[node]
```这表示以`node`。 

对于一个节点：```
subtree_height[node] =
1 + max(left subtree height, right subtree height)
```由于高度是按边缘测量的，因此我们使用`-1`对于空节点，以便叶节点正确获得高度`0`。 

这个 DFS 是后序的，因为我们必须在计算父母的身高之前知道孩子的身高。 

### 步骤 2：定义answer[node] 的含义

 对于每个节点：```
answer[node]
```存储删除该节点的子树后树的高度。 

这正是查询所要求的。 

### 步骤 3：运行第二个 DFS 来传播外部高度

 现在我们从根执行另一个 DFS。 

对于每个节点，我们传递：```
best_without_current_subtree
```该值表示无需输入当前节点的子树即可获得的最佳树高度。 

处理子项时，有两个可能的来源会影响新的高度：

 1. 祖传之道
 2.经过兄弟子树的路径

 假设我们在父级`p`有深度`d`。 

如果我们进入左孩子，那么最好的替代路径可能来自：

 - 上面已有的任何内容`p`- 的右子树`p`使用兄弟子树的候选高度变为：```
depth(parent) + 1 + subtree_height[sibling]
```我们采取所有可用替代方案中的最大值并将其传递给孩子。 

### 第 4 步：存储答案

 访问节点时`u`，传播的值已经代表移除后的高度`u`的子树。 

所以：```
answer[u] = propagated_value
```### 第 5 步：回答问题

 预处理后，每个查询变为：```
return answer[q]
```这提供了恒定时间的查询解析。 

### 为什么它有效

 该算法之所以有效，是因为每个根到节点的路径要么：

 - 输入已删除的子树，或
 - 完全避免它

 删除以节点为根的子树时`u`，每条有效的剩余路径必须避免`u`。 

第二个 DFS 通过考虑所有替代路由，正确传播排除每个子树的最佳可能路径长度：

 - 通过祖先
 - 通过兄弟子树

 因此，`answer[u]`始终等于删除后剩余树的高度`u`的子树。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, List
from collections import defaultdict

class Solution:
    def treeQueries(
        self,
        root: Optional[TreeNode],
        queries: List[int]
    ) -> List[int]:

        subtree_height = {}
        answer = {}

        def compute_heights(node: Optional[TreeNode]) -> int:
            if not node:
                return -1

            left_height = compute_heights(node.left)
            right_height = compute_heights(node.right)

            subtree_height[node.val] = 1 + max(left_height, right_height)

            return subtree_height[node.val]

        compute_heights(root)

        def dfs(
            node: Optional[TreeNode],
            depth: int,
            best_without_subtree: int
        ) -> None:

            if not node:
                return

            answer[node.val] = best_without_subtree

            left_subtree_height = (
                subtree_height[node.left.val]
                if node.left else -1
            )

            right_subtree_height = (
                subtree_height[node.right.val]
                if node.right else -1
            )

            if node.left:
                candidate = depth + 1 + right_subtree_height
                new_best = max(best_without_subtree, candidate)

                dfs(node.left, depth + 1, new_best)

            if node.right:
                candidate = depth + 1 + left_subtree_height
                new_best = max(best_without_subtree, candidate)

                dfs(node.right, depth + 1, new_best)

        dfs(root, 0, 0)

        return [answer[q] for q in queries]
```实现分为两次DFS遍历。 

第一个 DFS 计算每个子树的高度。 由于子树的高度取决于子树的高度，因此这种遍历自然是后序的。 返回空节点`-1`，允许叶节点接收高度`0`。 

这`subtree_height`字典存储每个节点值的计算高度。 

第二个DFS执行重新生根过程。 参数`best_without_subtree`表示在不进入当前节点子树的情况下可获得的最大树高。 

在每个节点，我们立即将该值存储到`answer[node.val]`，因为这正是删除该子树后剩余的高度。 

当下降到子树时，我们使用兄弟子树计算替代路径。 例如，当探索左子树时，最长的替代路径可能会穿过右子树。 

最大值：

 - 以前可用的高度
 - 基于兄弟姐妹的身高

 是向下传播的。 

最后，通过直接查找预先计算的结果，在恒定时间内回答查询。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func treeQueries(root *TreeNode, queries []int) []int {
    subtreeHeight := make(map[int]int)
    answer := make(map[int]int)

    var computeHeights func(node *TreeNode) int

    computeHeights = func(node *TreeNode) int {
        if node == nil {
            return -1
        }

        leftHeight := computeHeights(node.Left)
        rightHeight := computeHeights(node.Right)

        if leftHeight > rightHeight {
            subtreeHeight[node.Val] = leftHeight + 1
        } else {
            subtreeHeight[node.Val] = rightHeight + 1
        }

        return subtreeHeight[node.Val]
    }

    computeHeights(root)

    var dfs func(node *TreeNode, depth int, bestWithoutSubtree int)

    dfs = func(node *TreeNode, depth int, bestWithoutSubtree int) {
        if node == nil {
            return
        }

        answer[node.Val] = bestWithoutSubtree

        leftSubtreeHeight := -1
        rightSubtreeHeight := -1

        if node.Left != nil {
            leftSubtreeHeight = subtreeHeight[node.Left.Val]
        }

        if node.Right != nil {
            rightSubtreeHeight = subtreeHeight[node.Right.Val]
        }

        if node.Left != nil {
            candidate := depth + 1 + rightSubtreeHeight

            newBest := bestWithoutSubtree
            if candidate > newBest {
                newBest = candidate
            }

            dfs(node.Left, depth+1, newBest)
        }

        if node.Right != nil {
            candidate := depth + 1 + leftSubtreeHeight

            newBest := bestWithoutSubtree
            if candidate > newBest {
                newBest = candidate
            }

            dfs(node.Right, depth+1, newBest)
        }
    }

    dfs(root, 0, 0)

    result := make([]int, len(queries))

    for i, q := range queries {
        result[i] = answer[q]
    }

    return result
}
```Go 的实现与 Python 解决方案非常相似。 

使用地图而不是字典来存储子树高度和答案。 由于 Go 不像 Python 那样自然地支持嵌套函数声明，因此函数变量首先声明，然后赋值。 

在访问子指针之前需要进行 Nil 检查。 整数溢出不是问题，因为树的高度受以下限制`n`，这最多是`100000`。 

切片用于最终的查询结果。

 ## 边缘情况

 ### 删除叶节点

 叶节点没有子节点，因此删除其子树只会删除该单个节点。 这种情况可能很棘手，因为树高可能会也可能不会改变，具体取决于叶子是否位于最深的路径上。 

该实现自然地处理了这个问题，因为重新根传播总是跟踪已删除子树之外的最佳替代高度。 

### 高度倾斜的树

 完全倾斜的树的行为类似于链表。 在此结构中，删除根附近的节点会极大地改变高度。 

这种情况很重要，因为递归深度会变大。 该算法仍然可以正常工作，因为每个节点都存储不包括其子树的最佳剩余高度。 

### 删除包含最深路径的子树

 有时，树中最深的路径完全穿过被删除的子树。 在这种情况下，新的答案必须来自另一个分支。 

重根 DFS 明确考虑兄弟子树和祖先路径，确保算法正确切换到下一个最佳剩余路径。 

### 只剩下一根树枝的树

 删除子树后，剩余的树可能仅包含来自根的单个链。 

该算法正确地计算了结果高度，因为所有传播的值都表示有效的根到节点路径长度，避免了删除的子树。
