[LeetCode 问题 2412](https://leetcode.com/problems/minimum-money-required-before-transactions/)

 **难度：** 🔴难
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们确定以**任意顺序**完成所有交易所需的**最低初始资金**。 每笔交易的定义是`[costi, cashbacki]`，这意味着执行交易至少需要`costi`钱，完成后，我们收到`cashbacki`后退。 

换句话说，我们必须选择一个起始金额，这样无论我们如何排序交易，我们都不会在任何交易过程中耗尽资金。 输出是一个表示最低初始资金的整数。 

输入约束表明我们最多可以有`10^5`交易，每笔成本或现金返还可以大到`10^9`。 这排除了尝试所有交易排列的暴力方法，因为阶乘时间解决方案是不可行的。 我们还知道所有数字都是非负数，因此我们不必处理负成本或现金返还值。 

重要的边缘情况包括交易`costi`等于`cashbacki`，零成本交易，以及其中的交易`cashbacki`超过`costi`。 

## 方法

 ### 蛮力

 暴力方法将尝试每一种可能的交易排列，计算运行余额以查看给定的起始资金是否足够。 对于每个排列，我们检查当前资金是否足以用于每笔交易，并在应用成本和现金返还后更新资金。 最低起始资金将是在所有排列中成功的最小金额。 

这种方法理论上是正确的，但不切实际。 高达`10^5`交易，排列数为`10^5!`，这是一个天文数字。 即使检查单个排列也需要 O(n)，因此暴力方法是完全不可行的。 

### 最佳方法

 关键的见解是单独考虑每笔交易，并根据它们是否**亏损**（`costi > cashbacki`) 或 **赚钱** (`costi <= cashbacki`）。 

交易地点`costi > cashbacki`是有风险的，因为执行它们会减少您的资金，因此您必须确保有足够的资金来预先支付费用。 每笔交易的**临界值**是所有交易的最大值`min(costi, costi - cashbacki)`因为这代表了每笔交易的最坏情况。 

简单来说，所需的最低初始资金可以计算为`costi - cashbacki`对于所有交易，其中`costi > cashbacki`加上**最大交易成本，其中`costi <= cashbacki`**。 这保证您可以完成所有交易，无论订单如何。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 检查所有排列； 对于大 n | 不可行
 | 最佳| O(n) | O(1) | O(1) | 线性扫描； 计算总和和最大值； 使用贪婪分类 |

 ## 算法演练

 1.初始化两个变量：`sum_loss`存储交易的总“损失”，其中`costi > cashbacki`， 和`max_gain_cost`存储最大交易成本，其中`costi <= cashbacki`。 
2. 迭代每笔交易`[c, r]`。 如果`c > r`， 添加`(c - r)`到`sum_loss`。 否则，更新`max_gain_cost`是其当前值的最大值并且`c`。 
3. 处理完所有交易后，最低起始资金为`sum_loss + max_gain_cost`。 
4. 返回该值。 

**为什么有效：** 该算法之所以有效，是因为它将交易分为“风险”（亏损）和“安全”（盈利或中性资金）。 通过总结所有风险损失并确保您有足够的资金进行最大的安全交易，您可以保证有足够的初始资金以任何顺序完成每笔交易。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumMoney(self, transactions: List[List[int]]) -> int:
        sum_loss = 0
        max_gain_cost = 0
        
        for cost, cashback in transactions:
            if cost > cashback:
                sum_loss += cost - cashback
            else:
                max_gain_cost = max(max_gain_cost, cost)
        
        return sum_loss + max_gain_cost
```该实现首先将每个交易分为“损失”或“收益”类型。 它累计所有风险交易的净损失，并单独跟踪收益交易中最大的成本。 最终结果保证所有交易以任何顺序完成。 

## 解决方案```go
func minimumMoney(transactions [][]int) int64 {
    var sumLoss int64 = 0
    var maxGainCost int64 = 0
    
    for _, t := range transactions {
        cost := int64(t[0])
        cashback := int64(t[1])
        
        if cost > cashback {
            sumLoss += cost - cashback
        } else {
            if cost > maxGainCost {
                maxGainCost = cost
            }
        }
    }
    
    return sumLoss + maxGainCost
}
```在 Go 中，我们明确使用`int64`处理高达`10^9`并避免求和时整数溢出。 该逻辑反映了 Python 解决方案。

 ## 边缘情况

 **边缘情况 1：所有交易均为收益或中性**

 如果`costi <= cashbacki`对于所有交易，初始资金只需覆盖其中最大的成本即可。 该算法通过跟踪来处理这个问题`max_gain_cost`。 

**边缘情况2：所有交易都是损失**

 如果每笔交易都减少资金，算法必须将所有净损失相加，以保证起始资金足够。 这是通过`sum_loss`。 

**边缘案例 3：零成本交易**

 零成本、非零返现的交易是安全的，不会增加所需的起始资金。 该算法正确地忽略了这些`sum_loss`但考虑到他们的成本`max_gain_cost`如果适用。 

这种方法对于成本和现金返还值的所有组合都是稳健的，并且保证了正确性。
