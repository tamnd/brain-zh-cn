 **难度：** 🟢简单
 **主题：** 数组、哈希表、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们识别整数数组中最常见的**偶**数`nums`。 如果多个偶数共享最高频率，我们应该返回其中的**最小**。 如果数组不包含偶数，则该函数应返回`-1`。 

输入数组`nums`最多可以有 2000 个元素，每个元素的范围从 0 到 105。这告诉我们该数组相对较小，因此线性或接近线性的解决方案是可行的。 这些约束还保证非负整数，这简化了与负数相关的边缘情况处理。 

重要的边缘情况包括没有偶数的数组、多个偶数具有相同最高频率的数组以及所有数字都是偶数或所有数字都是奇数的数组。 正确处理领带并归还`-1`当不存在偶数时对于正确性至关重要。 

## 方法

 暴力方法将涉及迭代数组中的每个偶数以计算其出现次数，然后比较计数以找到最大频率。 这将涉及嵌套迭代，考虑到约束和使用哈希表进行计数的能力，这是不必要的。 

最佳解决方案使用哈希映射（Python 中的字典或 Go 中的映射）来计算单次遍历中每个偶数的频率。 构建频率图后，我们对其进行迭代以确定频率最高的偶数，通过选择最小的数字来打破平局。 这种方法利用哈希图的计数特性来进行有效的频率跟踪。

 ## 算法演练

 1. 初始化一个空的哈希映射来存储偶数的频率。 
2. 迭代数组中的每个数字。 对于每个数字，检查它是否是偶数。 
3. 如果数字是偶数，则增加其在哈希映射中的计数。 忽略奇数。 
4.初始化两个变量：`max_freq`跟踪观察到的最大频率，以及`result`存储具有该频率的最小偶数。 
5. 迭代哈希图。 对于每个键值对，将频率与`max_freq`。 
6. 如果频率高于`max_freq`， 更新`max_freq`并设置`result`到当前号码。 
7. 如果频率等于`max_freq`并且当前数量小于`result`， 更新`result`到当前号码。 
8. 遍历地图后，检查是否`result`已更新。 如果没有找到偶数，则返回`-1`。 否则，返回`result`。 

**为什么有效**：该算法之所以有效，是因为它对所有偶数精确计数一次并有效地存储它们的频率。 通过跟踪最大频率和平局情况下的最小数量，它可以保证正确性，同时保持线性时间复杂度。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def mostFrequentEven(self, nums: List[int]) -> int:
        freq = defaultdict(int)
        for num in nums:
            if num % 2 == 0:
                freq[num] += 1

        max_freq = 0
        result = -1
        for num, count in freq.items():
            if count > max_freq or (count == max_freq and num < result):
                max_freq = count
                result = num

        return result
```Python 解决方案首先使用以下方法构建频率图`defaultdict(int)`以避免关键错误。 对输入数组的迭代可确保仅计算偶数。 构建地图后，我们遍历地图以找到最高频率并通过选择最小的数字来解决联系问题。 返回`-1`如果不存在偶数，则处理没有偶数的数组的边缘情况。 

## 解决方案```go
func mostFrequentEven(nums []int) int {
    freq := make(map[int]int)
    for _, num := range nums {
        if num%2 == 0 {
            freq[num]++
        }
    }

    maxFreq := 0
    result := -1
    for num, count := range freq {
        if count > maxFreq || (count == maxFreq && (result == -1 || num < result)) {
            maxFreq = count
            result = num
        }
    }

    return result
}
```在 Go 中，我们使用映射来跟踪偶数的出现频率。 关键的区别在于 Go 需要显式处理最小数的初始状态，因此我们检查是否`result`是`-1`在比较尺寸之前。 否则，逻辑反映了 Python 解决方案。

 ## 边缘情况

 一种重要的边缘情况是当数组包含**不包含偶数**时，例如`[1,3,5]`。 如果不小心处理，算法可能会错误地返回`0`或一些未初始化的值。 我们的解决方案显式初始化`result`到`-1`并且只更新偶数，以确保正确的输出。 

另一个边缘情况是当**多个偶数共享最大频率**时。 例如，`[2,2,4,4]`2 和 4 之间有平局。该算法通过选择最小的偶数正确地解决了这个问题。 

第三种边缘情况是**具有单个元素的数组**，无论是偶数还是奇数。 该算法可以自然地处理这些问题，因为计数循环和最终选择逻辑对于长度为 1 的数组具有鲁棒性。`[0]`它返回`0`，并且对于`[1]`它返回`-1`。 这确保了非常小的数组不需要特殊的分支。
