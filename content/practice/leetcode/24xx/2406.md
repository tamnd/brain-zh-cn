[LeetCode 问题 2406](https://leetcode.com/problems/divide-intervals-into-minimum-number-of-groups/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、贪婪、排序、堆（优先级队列）、前缀和

 ## 解决方案

 ## 问题理解

 该问题为我们提供了包含区间的列表，其中每个区间表示为`[left, right]`。 我们必须将所有区间分组，使得同一组内的两个区间不相交。 

重要的细节是间隔是包含在内的。 这意味着两个间隔重叠，即使它们只共享一个端点。 例如，`[1, 5]`和`[5, 8]`相交，因为两者都包含值`5`。 

我们想要确定所需的最小组数，以便每个间隔恰好属于一个组，并且没有组包含重叠的间隔。 

思考这个问题的另一种方式是这样的：

 - 每个组的行为就像一个时间表，其中间隔不能重叠。 
- 如果多个间隔同时重叠，则它们必须属于不同的组。 
- 因此，答案等于任意点同时活动的最大间隔数。 

约束条件很重要：

 - 最多可以有`10^5`间隔。 
- 间隔端点可以大到`10^6`。 

由于输入大小很大，任何二次解（例如将每个间隔与每个其他间隔进行比较）都会太慢。 我们需要一个解决方案`O(n log n)`。 

有几个重要的边缘情况需要记住：

 - 在端点处接触的间隔仍然重叠，因为间隔是包含的。 
- 多个相同的间隔全部相互重叠。 
- 应该返回一组完全不重叠的间隔`1`。 
- 嵌套间隔，例如`[1,10]`,`[2,9]`,`[3,8]`需要多个组。 
- 大输入尺寸需要高效的基于排序或基于扫描线的方法。 

## 方法

 ### 蛮力方法

 一个简单的想法是逐个处理间隔并尝试将每个间隔放入现有组中。 

对于每个间隔：

 1. 检查每个现有组。 
2. 确定该间隔是否与该组中已有的任何间隔重叠。 
3. 如果不重叠，请将其放置在那里。 
4. 否则，创建一个新组。 

为了验证一个区间是否适合一个组，我们可能需要将它与该组内已有的许多区间进行比较。 

这种方法之所以有效，是因为它显式地构建有效的组，同时确保组内不会发生重叠。 然而，它的效率很低，因为每次插入可能需要扫描许多组以及这些组内的许多间隔。 

在最坏的情况下，这会变成`O(n^2)`。 

和`10^5`间隔，这太慢了。 

### 最佳方法

 关键的观察结果是，任何时刻组的最小数量等于重叠间隔的最大数量。 

这将问题转化为重叠计数问题。 

我们可以使用排序和最小堆有效地解决它：

 1. 按起始位置对间隔进行排序。 
2. 使用最小堆来跟踪当前活动组的结束时间。 
3. 对于每个间隔：

 - 如果最小结束时间严格小于当前开始时间，则该组变为可用。 
- 否则，我们需要一个新的小组。 
4. 将当前间隔的末尾推入堆中。 

任意时刻的堆大小代表当前正在使用的组数。 

处理期间的最大堆大小是所需的最小组数。 

关键的细节是包含重叠规则：

 - 两个区间重叠，如果`end >= start`。 
- 因此，只有在以下情况下才能重复使用组：`previous_end < current_start`。

 ## 算法演练

 1. 按起始点对所有区间进行排序。 

排序确保我们按时间顺序从左到右处理间隔。 这使得可以有效地确定是否可以重用现有组。 
2. 创建一个最小堆来存储间隔结束时间。 

堆跟踪每个活动组的最终值。 最小的结束时间始终位于顶部，这有助于我们快速识别最先可用的组。 
3. 迭代排序后的区间。 

对于每个间隔`[start, end]`，我们检查最早结束的活动组是否可以接受这个间隔。 
4. 检查堆中最小的结束值。 

如果最小最终值严格小于`start`，则区间不重叠，因为区间包含在内。 

例子：

-`[1, 3]`和`[4, 5]`不重叠，因为`3 < 4`-`[1, 3]`和`[3, 5]`重叠，因为两者都包括`3`5. Reuse a group if possible.

 如果`heap[0] < start`，从堆中弹出结束时间，因为该组现在可用。 
6. 将当前间隔的末尾插入堆中。 

这将该组标记为已占用，直到`end`。 
7. 继续，直到处理完所有间隔。 

堆大小代表当前需要的活动组的数量。 
8. 返回观察到的最大堆大小。 

在此实现中，处理所有间隔后的堆大小已经等于所需的最大值，因为组仅在可重用时才会被删除。 

### 为什么它有效

 该算法始终重用最早可用的组。 这种贪婪策略是最优的，因为它为未来的时间间隔保留了尽可能多的空间。 

堆保持包含所有当前活动组的结束时间的不变性。 每当某个间隔无法放入任何现有组时，就必须创建一个新组。 因此，同时活动间隔的最大数量等于所需的最小组数。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minGroups(self, intervals: List[List[int]]) -> int:
        intervals.sort()

        min_heap = []

        for start, end in intervals:
            if min_heap and min_heap[0] < start:
                heapq.heappop(min_heap)

            heapq.heappush(min_heap, end)

        return len(min_heap)
```实现首先根据间隔的起始值对间隔进行排序。 Python 的默认列表排序可以正常工作，因为间隔存储为`[start, end]`。 

然后使用最小堆来跟踪活动组结束时间。 最小结束时间始终可以在`O(1)`时间经过`min_heap[0]`。 

对于每个间隔：

 - 如果最早结束的组在当前间隔开始之前完成，则可以重复使用该组。 
- 我们从堆中删除该组的结束时间。 
- 然后我们将当前间隔的结束时间推入堆中。 

最后，堆包含每个活动组的一个条目，其大小等于所需的最小组数。 

使用`< start`而不是`<= start`非常重要，因为间隔是包含在内的。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	val := old[n-1]
	*h = old[:n-1]
	return val
}

func minGroups(intervals [][]int) int {
	sort.Slice(intervals, func(i, j int) bool {
		if intervals[i][0] == intervals[j][0] {
			return intervals[i][1] < intervals[j][1]
		}
		return intervals[i][0] < intervals[j][0]
	})

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	for _, interval := range intervals {
		start := interval[0]
		end := interval[1]

		if minHeap.Len() > 0 && (*minHeap)[0] < start {
			heap.Pop(minHeap)
		}

		heap.Push(minHeap, end)
	}

	return minHeap.Len()
}
```Go 解决方案遵循与 Python 版本相同的算法，但需要显式堆实现，因为 Go 的标准库堆实用程序通过接口进行操作。 

习俗`MinHeap`类型实现了`heap.Interface`。 

排序步骤使用`sort.Slice`，允许自定义比较逻辑。 

Go 切片是动态的，因此堆会随着间隔的处理而自然增长。 

不存在整数溢出问题，因为间隔值的边界为`10^6`，完全在 Go 的范围内`int`范围。

 ## 边缘情况

 一种重要的边缘情况涉及在端点处接触的间隔。 因为区间是包含在内的，`[1,5]`和`[5,10]`重叠。 一个常见的错误是使用`<=`而不是`<`当检查一个组是否可以重用时。 这个实现正确地使用了`heap[0] < start`，确保端点共享间隔保留在单独的组中。 

另一个关键的边缘情况是所有间隔完全重叠。 例如，`[[1,10],[1,10],[1,10]]`需要三组。 堆增长到大小为 3，因为没有间隔可以重用现有组。 这验证了算法是否正确跟踪同时重叠。 

第三个重要的情况是间隔从不重叠。 输入如`[[1,2],[3,4],[5,6]]`应该只需要一组。 该算法反复从堆中删除最小结束时间并有效地重用同一组。 

嵌套间隔也很重要。 在诸如此类的情况下`[[1,10],[2,9],[3,8]]`，每个区间都与所有其他区间重叠。 该算法正确地识别出每个间隔都需要自己的组，因为没有堆条目满足重用条件。 

最后，该实现可以有效地处理非常大的输入。 由于该解决方案仅执行排序和对数堆操作，因此它可以轻松地扩展到最大约束`10^5`间隔。
