[LeetCode 问题 2448](https://leetcode.com/problems/minimum-cost-to-make-array-equal/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、贪心、排序、前缀和

 ## 解决方案

 本指南将使用加权中值优化方法，这是在约束条件下有效解决此问题的关键见解。 

## 问题理解

 问题给了我们两个数组，`nums`和`cost`，每个长度`n`。 

这`nums[i]`value 表示索引处的当前数字`i`， 和`cost[i]`表示将该数字更改为多少成本`1`。 我们可以反复增加或减少任何数量一个单位，并支付`cost[i]`对于每个单位的变化。 

我们的目标是让**所有元素`nums`相等**，同时最小化**总累计成本**。 

换句话说，我们要选择一些目标值`x`并将每个数字转换为`x`。 索引成本`i`变成：$$|nums[i] - x| \times cost[i]$$选定目标的总成本`x`是：$$\sum |nums[i] - x| \times cost[i]$$我们必须返回尽可能小的总成本。 

约束条件很重要：

 -`n`可以大到`10^5`-`nums[i]`和`cost[i]`可以大到`10^6`尝试每一个可能的目标值并直接计算成本的简单方法会太慢。 由于值可能高达一百万，并且数组大小可能非常大，因此我们需要一种能够有效扩展的算法。 

该问题保证：

 - 所有数字均为正整数
 -`nums`和`cost`长度相等
 - 答案符合`2^53 - 1`，这对于具有固定大小整数类型的语言尤其重要

 一些边缘情况在前期很重要。 

如果所有数字都相等，则答案应该是`0`，因为不需要任何操作。 

当一个元素与其他元素相比具有极大的成本时，最佳目标通常会成为该数字的值，因为移动它的成本太高。 

重复值也可能很重要，因为多个元素可能已经与强加权中心对齐。 

如果整数运算处理不仔细，幼稚的实现也可能会溢出，特别是在 Go 中，我们必须使用`int64`。 

## 方法

 ### 蛮力方法

 最直接的方法是尝试每一个可能的目标值，并计算将所有数字转换为该目标的总成本。 

对于每个可能的目标`x`，我们计算：$$\sum |nums[i] - x| \times cost[i]$$然后我们返回所有候选者中的最小成本。 

因为`nums[i]`可以大到`10^6`，我们可以尝试中最小值和最大值之间的每个整数`nums`。 

这是有效的，因为最佳答案必须对应于某个整数目标。 通过详尽评估每种可能性，我们保证正确性。 

然而，这种方法太慢了。 

如果取值范围约为`10^6`，对于我们扫描的每个候选人`n = 10^5`元素，总复杂度变为：$$O(n \times range)$$这太贵了。 

### 最佳方法的关键见解

 总成本函数为：$$f(x) = \sum |nums[i] - x| \times cost[i]$$这是一个**加权绝对距离最小化问题**。 

对于常规绝对距离，中位数最小化：$$\sum |a_i - x|$$当每个点都有权重时，最小化点就成为**加权中位数**。 

加权中位数是累积重量至少达到总重量一半的值。 

为什么这有效？ 

Imagine moving the target value left or right.

 如果一侧存在过多的加权质量，则向该侧移动会减少总加权距离。 在平衡状态下，两个方向都不会改善答案。 该平衡点正是加权中位数。 

So instead of checking every target value, we:

1. Pair each number with its cost.
 2. 按编号排序。 
3. Find the weighted median.
 4. 计算将所有内容转换为该中位数的总成本。 

This produces the optimal answer efficiently.

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × 范围) | O(1) | O(1) | Try every possible target value |
 | 最佳| O(n log n) | O(n log n) | O(n) | Sort and use weighted median |

 ## 算法演练

 ### Optimal Algorithm Using Weighted Median

 1. 结合`nums`和`cost`成对。 

我们希望每个数字与其相应的修改成本保持关联，因此我们创建如下对：`(nums[i], cost[i])`2. 按编号对对进行排序。 

由于加权中位数取决于排序，因此我们按中的值排序`nums`。 
3. 计算总重量。 

将所有值添加到`cost`:$$totalWeight = \sum cost[i]$$4. 求加权中位数。 

遍历已排序的对，同时累积成本。 

一旦累计重量至少达到：$$\frac{totalWeight + 1}{2}$$我们停下来。 

相应的数字成为加权中位数。 
5. 计算最终的最小成本。 

对于每个数字：$$|nums[i] - median| \times cost[i]$$将所有这些值相加。 
6. 返回总数。 

这保证是尽可能最低的成本。 

### 为什么它有效

 目标函数是凸函数，因为它是加权绝对值项的总和。 向左或向右移动会根据每侧存在的重量改变总成本。 加权中位数恰好是向任一方向移动都不能减少总加权距离的平衡点。 因此，选择加权中位数可以保证总成本最小。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCost(self, nums: List[int], cost: List[int]) -> int:
        pairs = sorted(zip(nums, cost))

        total_cost_weight = sum(cost)
        half_weight = (total_cost_weight + 1) // 2

        current_weight = 0
        target = 0

        for num, c in pairs:
            current_weight += c
            if current_weight >= half_weight:
                target = num
                break

        minimum_cost = 0

        for num, c in zip(nums, cost):
            minimum_cost += abs(num - target) * c

        return minimum_cost
```### 实施演练

 实现首先使用将每个数字与其相应的成本配对`zip(nums, cost)`。 我们立即对这些对进行排序，因为找到加权中位数需要按排序顺序处理数字。 

接下来，我们通过将所有值相加来计算总重量`cost`。 由于加权中位数是累积权重超过总数一半的点，因此我们计算：```
half_weight = (total_cost_weight + 1) // 2
```这可以确保当总重量为奇数时正确处理。 

然后，我们扫描排序后的对，同时保持运行的累积权重。 一旦累计总和至少达到总重量的一半，我们就停止。 该数字成为最佳目标。 

最后，我们通过求和来计算总转换成本：```
abs(num - target) * cost
```对于每个元素。 这直接对问题陈述中的成本定义进行建模。 

## 解决方案```go
package main

import "sort"

func minCost(nums []int, cost []int) int64 {
	type pair struct {
		num  int
		cost int
	}

	n := len(nums)
	pairs := make([]pair, n)

	for i := 0; i < n; i++ {
		pairs[i] = pair{
			num:  nums[i],
			cost: cost[i],
		}
	}

	sort.Slice(pairs, func(i, j int) bool {
		return pairs[i].num < pairs[j].num
	})

	var totalWeight int64

	for _, c := range cost {
		totalWeight += int64(c)
	}

	halfWeight := (totalWeight + 1) / 2

	var currentWeight int64
	target := 0

	for _, p := range pairs {
		currentWeight += int64(p.cost)

		if currentWeight >= halfWeight {
			target = p.num
			break
		}
	}

	var minimumCost int64

	for i := 0; i < n; i++ {
		diff := nums[i] - target
		if diff < 0 {
			diff = -diff
		}

		minimumCost += int64(diff) * int64(cost[i])
	}

	return minimumCost
}
```### Go 特定的实现差异

 Go 实现使用自定义`pair`struct 在排序过程中将数字与其成本相关联。 

与 Python 不同，Go 整数可能会溢出，具体取决于平台大小，因此我们明确使用`int64`用于累积权重和最终成本计算。 当将大距离乘以大成本时，这可以防止溢出。 

Go 也没有提供内置的整数绝对值函数，因此我们手动处理负差。 

无需特殊处理`nil`与空切片相比是必要的，因为该问题保证了有效的输入长度。

 ## 边缘情况

 ### 所有元素都已经相等

 当每个数字在`nums`是相同的，答案应该是`0`。 如果实现不必要地修改值或错误地计算成本，则这可能是错误的来源。 在我们的实现中，加权中位数等于共享值，因此每个绝对差自动变为零。 

### 一个元素的成本非常大

 考虑：```
nums = [1, 100]
cost = [1000, 1]
```天真的直觉可能会选择中点，但移动第一个元素的成本极其昂贵。 加权中位数自然有利于权重较大的位置，从而产生最佳结果。 由于累积成本决定了目标，因此算法正确选择`1`。 

### 数量和成本非常大

 因为两者`nums[i]`和`cost[i]`可能大到`10^6`，中间乘法可能变得非常大。 这在 Go 中尤其危险。 该实现通过使用来防止溢出`int64`用于累计金额和成本计算。 

### 多个有效中位数

 在某些情况下，多个目标值可能会产生相同的最低成本。 当加权中位数位于某个范围内时，就会发生这种情况。 该算法只是选择遍历期间遇到的第一个有效加权中值。 由于该区间内的所有值都是最优的，因此结果仍然正确。
