[LeetCode 问题 2434](https://leetcode.com/problems/using-a-robot-to-print-the-lexicographyally-smallest-string/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、堆栈、贪婪

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给定一个字符串`s`和一个管理另一个临时字符串的机器人`t`。 最初，`t`是空的。 机器人重复执行两个允许的操作之一：

 首先，它可能会删除第一个字符`s`并将其附加到末尾`t`。 

其次，它可能会删除最后一个字符`t`并将其附加到最终输出字符串，即写在纸上的字符串。 

目标是确定在两者之后可以产生的按字典顺序最小的可能输出字符串`s`和`t`变得空虚。 

重要的细节是`t`其行为与堆栈完全相同。 字符被推入`t`从前面`s`，并从末尾弹出`t`到结果上。 因此，我们不能随意对字符进行重新排序。 我们只能通过将字符保留在堆栈中来延迟写入字符。 

词典顺序与词典顺序的工作方式相同。 如果在两个字符串不同的第一个位置包含较小的字符，则该字符串较小。 例如：

-`"abc"`小于`"acb"`-`"addb"`小于`"bdda"`约束允许的字符串长度可达`10^5`，因此任何探索许多可能的操作序列的解决方案都会太慢。 我们需要一种有效的贪婪策略来准确决定何时应将字符写入答案。 

一些边缘情况很重要：

 - 已经排序的字符串，例如`"abc"`- 字符串按相反顺序排列，例如`"cba"`- 包含许多重复字母的字符串
 - 最小字符出现较晚的字符串
 - 只有一个字符的字符串

 该问题保证所有字符都是小写英文字母，这非常有用，因为只有 26 个可能的字符值。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试每个有效的操作序列。 在每一步，如果`s`非空，我们可以从`s`进入`t`。 如果`t`非空，我们可以从`t`进入答案。 

这创建了一个巨大的决策树。 不同的操作顺序会产生不同的输出，我们需要比较所有生成的字符串以找到最小的一个。 

蛮力方法是正确的，因为它详尽地探索了每个有效的操作序列。 然而，它很快就变得不可行。 可能的操作序列的数量随着字符串长度呈指数增长。 

为了`n = 10^5`，这种做法是完全不可能的。 

### 关键见解

 关键的观察是，我们应该尽早写字，但只有在不损害字典顺序的情况下才这样做。 

假设栈顶`t`包含字符`'c'`。 如果未读部分中没有剩余更小的字符，我们应该立即弹出它`s`。 

为什么？ 

因为耽误了`'c'`只会将其稍后放置在结果字符串中。 如果不存在更小的未来字符，则写`'c'`现在总是最佳的。 

这表明了一种贪婪策略：

 - 从左到右处理字符
 - 将字符压入堆栈
 - 跟踪未读后缀中仍然存在的最小剩余字符
 - 当堆栈顶部小于或等于最小的剩余字符时，将其弹出到结果中

 为了有效地知道剩余的最小字符，我们维护了剩余字符的频率计数`s`。

 ## 算法演练

 1、创建一个大小为26的频数数组，统计每个字符出现的次数`s`。 
2.初始化一个空栈`t`。 这代表机器人的临时存储空间。 
3.初始化一个空列表`result`有效地构建最终答案。 
4. 迭代中的每个字符`s`。 
5. 将当前字符压入堆栈，因为访问未来字符的唯一方法是按顺序移动字符串。 
6. 减少当前字符的频率计数，因为它不再是未读后缀的一部分。 
7. 确定剩余未​​读部分中仍然存在的最小字符`s`。 我们通过扫描频率阵列来做到这一点`'a'`到`'z'`。 
8. 当堆栈不为空时，检查顶部字符是否可以安全地写入结果。 
9. 如果栈顶小于或等于最小的剩余字符，则将其从栈中弹出并追加到结果中。 这是贪婪的，因为较早放置较小或相同的字符总是会改善或保留字典顺序。 
10. 否则，停止弹出。 更小的未来角色仍然存在，所以我们应该等待。 
11.处理完所有字符后`s`，将堆栈中剩余的每个字符弹出到结果中。 
12. 将结果列表连接成字符串并返回。 

### 为什么它有效

 不变的是，只有当未读后缀中仍然存在严格较小的字符时，我们才会延迟字符。 如果不存在更小的未来字符，则将当前字符保留在堆栈中永远无法改善字典顺序。 

因此，每个弹出操作在发生时都是贪婪最优的。 由于字典顺序首先取决于较早的位置，因此始终写入尽可能小的可用字符会产生全局最佳答案。 

## Python 解决方案```python
class Solution:
    def robotWithString(self, s: str) -> str:
        remaining = [0] * 26
        
        for ch in s:
            remaining[ord(ch) - ord('a')] += 1
        
        stack = []
        result = []
        
        smallest_index = 0
        
        for ch in s:
            stack.append(ch)
            
            idx = ord(ch) - ord('a')
            remaining[idx] -= 1
            
            while smallest_index < 26 and remaining[smallest_index] == 0:
                smallest_index += 1
            
            while stack:
                top_index = ord(stack[-1]) - ord('a')
                
                if smallest_index == 26 or top_index <= smallest_index:
                    result.append(stack.pop())
                else:
                    break
        
        return "".join(result)
```该实现首先计算每个字符在字符串中出现的次数。 这使我们能够知道哪些字符仍未读取。 

这`stack`变量模拟机器人的临时字符串`t`。 当我们处理输入时，字符被推入其中。 

这`smallest_index`指针跟踪未读后缀中仍保留的按字典顺序最小的字符。 我们不会从头开始重复重新扫描所有 26 个字符，而是仅在字符计数变为零时才推进此指针。 

对于每个字符：

 - 我们将其压入堆栈
 - 将其从剩余频率计数中删除
 - 更新剩余的最小字符
 - 在安全的情况下从堆栈中弹出

 条件：```python
top_index <= smallest_index
```表示当前堆栈顶部不大于任何未来的字符。 因此，现在写是最佳的。 

最后，将结果列表连接到最终字符串中。 

## 解决方案```go
func robotWithString(s string) string {
	remaining := make([]int, 26)

	for _, ch := range s {
		remaining[ch-'a']++
	}

	stack := make([]byte, 0)
	result := make([]byte, 0)

	smallestIndex := 0

	for i := 0; i < len(s); i++ {
		ch := s[i]

		stack = append(stack, ch)

		remaining[ch-'a']--

		for smallestIndex < 26 && remaining[smallestIndex] == 0 {
			smallestIndex++
		}

		for len(stack) > 0 {
			top := stack[len(stack)-1]
			topIndex := int(top - 'a')

			if smallestIndex == 26 || topIndex <= smallestIndex {
				result = append(result, top)
				stack = stack[:len(stack)-1]
			} else {
				break
			}
		}
	}

	return string(result)
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

切片用于堆栈和结果生成器。 从堆栈中弹出是通过重新切片来处理的：```go
stack = stack[:len(stack)-1]
```由于输入仅包含小写英文字母，因此不必担心整数溢出。 该算法还通过使用字节切片构建答案来避免不必要的字符串连接。

 ## 边缘情况

 一种重要的边缘情况是输入仅包含一个字符。 在这种情况下，堆栈恰好接收一次压入和一次弹出。 某些实现在弹出后意外地错误地处理了空堆栈情况。 此实现可以安全地处理这种情况，因为所有堆栈操作都受到保护`while stack:`检查。 

另一个重要的情况是当最小的字符出现在字符串中很晚的时候，例如`"zzzzza"`。 天真的贪婪算法可能会错误地提前弹出`'z'`字符太快了。 我们的实现正确地延迟了弹出，因为剩余的后缀仍然包含`'a'`，小于`'z'`。 

第三个棘手的情况是重复相同的字符，例如`"aaaa"`。 某些解决方案在决定是否弹出时错误地使用严格比较而不是非严格比较。 条件：```
top_index <= smallest_index
```是必不可少的。 相同的字符也应该立即弹出，因为延迟它们不能改善字典顺序。 

另一个微妙的情况是反向排序输入，例如`"edcba"`。 在这里，每个字符都必须保留在堆栈中直到最后。 该实现自然地处理了这个问题，因为较小的未来字符始终存在，直到最后一步。
