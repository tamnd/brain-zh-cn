[LeetCode 问题 2405](https://leetcode.com/problems/optimal-partition-of-string/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、贪婪

 ## 解决方案

 ## 问题理解

 该问题要求我们划分给定的字符串`s`到**最小数量的子字符串**，使得**每个子字符串仅包含唯一字符**。 换句话说，在单个子字符串中，任何字符都不能出现多次。 

我们得到一串小写英文字母，必须将其分成连续的部分。 原始字符串中的每个字符必须恰好属于一个子字符串，并且字符的顺序不能改变。 挑战在于找到产生**尽可能少的子字符串**的分区。 

思考这个问题的另一种方法是：我们从左到右扫描字符串，并不断构建子字符串，只要所有字符保持唯一。 当添加新字符会在当前子字符串中创建重复字符时，我们必须剪切分区并开始一个新的子字符串。 

例如，在`"abacaba"`:

 - 开始于`"a"`- 添加`"b"`→`"ab"`有效
 - 添加`"a"`→ 出现重复，所以我们必须在此之前拆分`a`- 继续类似操作，直到处理完完整的字符串

 输出是一个整数，表示所需的**有效子字符串的最小数量**。 

这些约束告诉我们有关预期效率的重要信息：

 -`1 <= s.length <= 10^5`-`s`仅包含小写英文字母

 由于输入大小可以大到`100,000`，任何具有二次复杂度的解决方案，例如`O(n²)`可能会太慢。 理想情况下，我们应该以线性时间解决方案为目标`O(n)`。 

该字符串仅包含小写英文字母这一事实也很重要。 由于只有`26`可能的字符，我们可以使用哈希集甚至位掩码有效地跟踪唯一性。 

一些边缘情况值得预先识别。 应返回只有一个字符的字符串`1`因为不需要分区。 每个字符都是唯一的字符串，例如`"abcdef"`，也应该返回`1`。 在另一个极端，一串重复的字符，例如`"ssssss"`强制每个字符进入其自己的子字符串，从而导致`6`。 经常出现重复的情况，例如`"abac"`，如果分区没有在正确的时刻创建，可能会导致幼稚的实现失败。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试探索所有可能的方法来对字符串进行分区，然后确定哪个有效分区使用最少的子字符串。 

对于一个长度的字符串`n`， 有`2^(n-1)`可能的分割点，因为字符之间的每个间隙都可以包含分割，也可以不包含分割。 对于每个可能的分区，我们将验证每个子字符串是否包含唯一字符。 如果有效，我们将计算子字符串的数量并跟踪最小值。 

这种方法保证了正确性，因为它检查了每种可能的分区排列。 然而，这在计算上是不可行的`n = 10^5`。 即使对于中等大小的输入，指数数量的可能性也变得无法处理。 

稍微改进的暴力版本可能会使用动态编程来尝试每个结束位置，但反复检查唯一性仍然可以将复杂性推向`O(n²)`。 

### 最优贪心法

 关键的观察是**我们应该在分割之前使每个子串尽可能大**。 

假设我们正在构建一个子字符串并遇到当前子字符串中已存在的字符。 那一刻，我们别无选择，只能分手。 等待更长时间是不可能的，因为当前子字符串已经违反了唯一性规则。 

这自然暗示了一种**贪婪策略**：

 - 继续扩展当前子字符串，同时字符保持唯一。 
- 维护当前子字符串中已使用的一组字符。 
- 如果出现重复字符，则立即开始一个新的子字符串。 
- 重置新子字符串的跟踪。 

这是有效的，因为每次分裂都是被迫的。 较早的分割只会产生不必要的额外子串，而较晚的分割则会违反约束。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n * n)`|`O(n)`| 尝试所有可能的分区并验证每个分区 |
 | 最优贪心 |`O(n)`|`O(1)`| Greedily extends substrings until duplication occurs |

 ## 算法演练

 1. Initialize a counter for the number of substrings.

 Since at least one substring is required for any non-empty string, initialize the answer as`1`。 
2. 创建一个数据结构来跟踪当前子字符串中的字符。 

哈希集是一个自然的选择，因为它提供了平均值`O(1)`插入和查找时间。 
3. 逐个字符地遍历字符串。 

对于每个字符，检查它是否已存在于当前子字符串中。 
4. 如果该字符不存在于集合中，则添加它。 

这意味着当前子串仍然满足唯一性条件，因此我们继续扩展它。 
5. 如果该字符已存在，则创建一个新的子字符串。 

由于不允许重复，因此我们必须在该字符之前立即进行分割。 增加子字符串计数，清除跟踪结构，并以当前字符开始新的子字符串。 
6. 继续，直到处理完整个字符串。 

子字符串计数器将包含有效分区的最小数量。 

### 为什么它有效

 该算法依赖于贪婪不变量：**当前子字符串始终是我们可以从当前位置构建的最长有效子字符串**。 

每当出现重复字符时，分割就成为强制性的，因为保留该字符会违反唯一性规则。 提前分割永远不会减少子串的数量，只会不必要地增加子串的数量。 因此，贪婪地最大化每个子串可以保证分区总数最小。 

## Python 解决方案```python
class Solution:
    def partitionString(self, s: str) -> int:
        partitions = 1
        current_chars: set[str] = set()

        for char in s:
            if char in current_chars:
                partitions += 1
                current_chars.clear()

            current_chars.add(char)

        return partitions
```实现直接遵循贪心算法。 

我们首先初始化`partitions = 1`因为非空字符串总是需要至少一个子字符串。 我们还创造`current_chars`，存储当前存在于活动子字符串中的所有字符的集合。 

当我们遍历字符串时，我们检查当前字符是否已存在于`current_chars`。 

如果该字符已经存在，则我们遇到了重复的字符。 由于子字符串内禁止重复，因此我们增加分区计数并清除集合以开始跟踪新的子字符串。 

处理重复的情况后，我们将当前字符添加到集合中。 这可以正常工作，因为即使在拆分之后，当前字符也属于新创建的子字符串。 

在迭代结束时，`partitions`变量包含所需的最小数量的子字符串。 

## 解决方案```go
func partitionString(s string) int {
	partitions := 1
	currentChars := make(map[rune]bool)

	for _, ch := range s {
		if currentChars[ch] {
			partitions++
			currentChars = make(map[rune]bool)
		}

		currentChars[ch] = true
	}

	return partitions
}
```Go 实现遵循与 Python 版本相同的贪婪逻辑。 

Go 使用的不是 Python 集，而是`map[rune]bool`跟踪当前子字符串中的字符。 当遇到重复字符时，我们增加分区计数并重新创建映射以表示新的子字符串。 

不用担心整数溢出，因为最大答案最多是`n = 10^5`，它很容易适合 Go 的内部`int`类型。 由于输入仅包含小写英文字母，因此迭代符文可以安全且正确地进行。

 ## 边缘情况

 ### 单字符串

 像这样的字符串`"a"`是最小可能的有效输入。 有缺陷的实现可能会意外地将分区计数初始化为`0`并忘记至少有一个子串始终存在。 此实施开始于`partitions = 1`，确保返回正确的答案。 

### 所有角色都是独一无二的

 像这样的字符串`"abcdef"`永远不需要分裂。 某些实现在检查重复项时会错误地创建不必要的分区。 由于没有字符重复，因此集合继续增长并且分区计数保持不变`1`。 

### 所有字符重复

 像这样的字符串`"ssssss"`代表相反的极端。 第一个字符之后的每个字符立即强制分裂。 一个常见的错误是在清除字符集后忘记重新插入重复字符。 此实现正确地清除集合，然后将当前字符添加到新形成的子字符串中。 

### 长前缀后出现重复

 考虑`"abcdefghijklmnopqrstuvwxyza"`。 决赛`a`重复一个早先看到的角色。 仅检查最近字符的简单实现在这里会失败。 由于该算法在当前子字符串中维护了完整的字符集，因此无论位置如何，它都可以正确检测重复项。
