[LeetCode 问题 2492](https://leetcode.com/problems/minimum-score-of-a-path- Between-two-cities/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、并查找、图论

 ## 解决方案

 ## 问题理解

 该问题要求我们找到城市之间路径的最小可能得分`1`和城市`n`在由以下定义的图中`n`城市和`roads`。 每条道路双向连接两个城市并具有相关的距离。 路径的**分数**定义为该路径中所有道路之间的**最小距离**。 与考虑总和的传统最短路径问题不同，这里我们关心的是路径中最小的道路。 该图可能包含循环，并且该路径可以多次重访城市或道路。 我们保证城市之间至少存在一条路径`1`和城市`n`。 

输入包括：

 -`n`, 城市数量（最多 10^5）
 -`roads`，具有距离的道路连接列表（最多 10^5 条）

 预期输出是一个整数：从城市出发的任何路径上可达到的最低可能分数`1`到城市`n`。 

关于约束的主要观察结果：

 - 城市编号为`1`到`n`，因此索引必须考虑到这一点。 
- 距离是正整数，因此最小值始终≥1。 
- 由于没有重复的边，因此可以使用简单的邻接表。 
- 图可能不是完全连接的，而是之间有一条路径`1`和`n`存在，所以我们只需要考虑包含 city 的连通分量`1`。 

边缘情况包括具有两个城市和一条道路的最小图、具有不同最小距离的多条路径，以及如果处理不当可能影响路径选择的循环。 

## 方法

 ### 蛮力方法

 蛮力方法将尝试生成城市之间所有可能的路径`1`和城市`n`，计算每条路径的分数（沿该路径的最小距离），并返回最小分数。 这种方法原则上是正确的，但生成最多 10^5 个节点和 10^5 条边的图中的所有路径在计算上是不可行的。 即使使用DFS来枚举路径也会导致指数时间复杂度，这远远超出了实际限制。 

### 最佳方法

 关键的观察结果是，**从城市 1 到城市 n 的任何路径都必须位于城市 1** 的连通部分内。 在此组件中，所遇到的任何道路的最小距离是最低分数的候选者。 因此，我们可以使用 BFS 或 DFS 探索连接的组件，并跟踪遇到的所有边的最小距离。 无需显式枚举路径，因为每条路径都受到组件中的边的约束。 组件中的最小边保证了沿任何连接路径的最小可能得分`1`和`n`。 

这种方法通过简单的边权重聚合将问题简化为**图遍历**问题，给出相对于图大小的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 枚举所有路径，计算每个路径的最小值 |
 | 最佳| O(n + m) | O(n + m) | 遍历连通分量，跟踪最小边 |

 ## 算法演练

 1. 建立一个邻接表`roads`大批。 每个城市映射到一个包含邻近城市和连接道路距离的元组列表。 
2. 初始化一个`visited`设置跟踪已经探索过的城市。 
3. 初始化一个`min_score`具有无穷大的变量来存储所看到的最小距离。 
4.从城市开始进行BFS或DFS`1`。 
5. 对于访问的每个城市，迭代其邻居：

 - 如果邻居尚未被访问过，则将其添加到队列/堆栈中。 
- 更新`min_score`为当前的最小值`min_score`和边缘的距离。 
6. 继续遍历，直到所有可到达的城市`1`被访问。 
7. 返回`min_score`结果。 

**为什么有效：** 从城市出发的任何有效路径`1`到城市`n`必须完全位于城市的互联组成部分内`1`。 因此，该组件中的最小道路保证是来自`1`到`n`，使其成为可能的最低分数。 

## Python 解决方案```python
from typing import List
from collections import deque, defaultdict

class Solution:
    def minScore(self, n: int, roads: List[List[int]]) -> int:
        # Build adjacency list
        graph = defaultdict(list)
        for a, b, distance in roads:
            graph[a].append((b, distance))
            graph[b].append((a, distance))
        
        visited = set()
        min_score = float('inf')
        queue = deque([1])
        visited.add(1)
        
        # BFS traversal
        while queue:
            node = queue.popleft()
            for neighbor, distance in graph[node]:
                min_score = min(min_score, distance)
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.append(neighbor)
        
        return min_score
```**说明：** 邻接列表可以有效地查找邻近城市。 BFS 确保所有可到达的城市都被访问而不会无限循环，使用`visited`跟踪进度。 在遍历过程中，我们保持所看到的最小距离，这最终给出了从`1`到`n`。 

## 解决方案```go
package main

func minScore(n int, roads [][]int) int {
	graph := make([][][2]int, n+1)
	for _, road := range roads {
		a, b, dist := road[0], road[1], road[2]
		graph[a] = append(graph[a], [2]int{b, dist})
		graph[b] = append(graph[b], [2]int{a, dist})
	}

	visited := make([]bool, n+1)
	minScore := 1<<31 - 1

	queue := []int{1}
	visited[1] = true

	for len(queue) > 0 {
		node := queue[0]
		queue = queue[1:]
		for _, pair := range graph[node] {
			neighbor, dist := pair[0], pair[1]
			if dist < minScore {
				minScore = dist
			}
			if !visited[neighbor] {
				visited[neighbor] = true
				queue = append(queue, neighbor)
			}
		}
	}
	return minScore
}
```**去注意：**我们使用切片`[2]int`存储邻居和距离。 布尔切片跟踪访问过的城市。 BFS队列通过切片操作进行管理，并且`minScore`使用较高的初始值来跟踪最小距离。
