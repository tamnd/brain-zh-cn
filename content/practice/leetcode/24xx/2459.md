[LeetCode 问题 2459](https://leetcode.com/problems/sort-array-by-moving-items-to-empty-space/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、排序

 ## 解决方案

 ## 问题理解

 该数组包含来自的每个整数`0`到`n - 1`正好一次。 价值`0`代表空白空间，而每个其他数字代表最终应按排序顺序出现的项目。 

与正常的数组排序问题相比，该操作很不寻常。 一步操作中，我们可以取出任何物品并将其放入当前的空位置。 由于空位置在每次移动后都会发生变化，因此该过程的行为类似于将元素与`0`。 

该数组被认为是按两种配置排序的：

 -`[0,1,2,...,n-1]`-`[1,2,3,...,n-1,0]`这意味着空白区域可能位于开头或末尾，但不会在其他地方。 

任务是计算将初始排列转换为这两个有效目标配置之一所需的最少操作数。 

约束条件很重要：

 -`n`可以大到`10^5`- 所有值都是唯一的
 - 该数组是一个排列`[0, n-1]`这些限制立即排除了指数搜索或模拟重的强力方法。 我们需要一种接近线性时间的算法。 

一些边缘情况尤其重要：

 - 数组可能已经以一种有效形式排序。 
- 空白空间可能已经处于其最终位置，但其他元素还没有。 
- 排列可能包含不涉及的循环`0`。 
- 在不了解循环结构的情况下贪婪地移动元素可能会产生不必要的操作。 

唯一性保证非常有用，因为它允许我们将数组视为索引和值之间的排列映射。 

## 方法

 ### 蛮力方法

 暴力策略会尝试使用 BFS 或 DFS 搜索所有可能的移动序列。 每个状态代表当前排列，每个操作通过将项目移动到空位置来生成新状态。 

这种方法保证找到最少的操作数，因为 BFS 逐级探索状态。 然而，排列的数量是`n!`，即使对于中等强度的情况来说，这也会变得天文数字般大`n`。 

即使是为了`n = 10`，已经有超过 300 万种可能的状态。 自从`n`可以达到`100000`，穷举搜索是完全不可行的。 

另一个稍微好一点的蛮力想法是重复贪婪地放置错位的元素。 不幸的是，贪婪的局部决策可能无法实现最小操作数，因为循环不涉及`0`需要特殊处理。 

### 关键见解

 重要的观察是该数组形成了一个排列图。 

对于任何目标排列，每个索引都恰好有一个正确值。 如果索引当前包含错误值，则它属于循环。 

空旷的空间`0`发挥着特殊的作用：

 - 如果一个循环已经包含`0`，我们可以直接求解循环。 
- 如果一个循环不包含`0`，我们首先需要带`0`进入循环，解决它，然后移动`0`退出。 

这就产生了循环计数解决方案。 

由于只有两个有效的目标数组，我们计算：

 1. 转型成本`[0,1,2,...,n-1]`2. 转型成本`[1,2,3,...,n-1,0]`然后我们返回最小值。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n!) | 详尽地探索排列状态 |
 | 最佳 | O(n) | O(n) | 使用置换循环分解 |

 ## 算法演练

 我们定义一个辅助函数，用于计算将当前数组转换为特定目标排列所需的最少操作。 

### 第 1 步：构建目标位置映射

 对于选定的目标配置，确定每个值应位于的位置。 

例如：

 - 目标`[0,1,2,3,4]`- 价值`0`属于索引`0`- 价值`1`属于索引`1`- 等

 或者：

 - 目标`[1,2,3,4,0]`- 价值`1`属于索引`0`- 价值`2`属于索引`1`- 价值`0`属于索引`n-1`这种映射让我们可以确定每个元素是否已经处于正确的位置。 

### 步骤 2：将数组解释为排列

 对于每个索引`i`，确定当前值应该去哪里。 

如果索引`i`包含价值`v`， 和`v`属于索引`target_pos[v]`，则存在有向边：```
i -> target_pos[v]
```这会产生不相交的循环。 

### 步骤 3：遍历循环

 使用访问过的数组查找所有循环。 

如果索引已经正确或已访问过，则跳过它。 

否则，遵循排列，直到循环结束。 

曲目：

 - 周期长度
 - 循环中是否包含空白区域`0`### 步骤 4：计算每个周期的成本

 假设一个循环有长度`k`。 

####情况1：循环包含`0`这个循环可以精确地固定为：```
k - 1
```运营。 

每一次移动都会将一个元素放置到正确的位置。 

####情况2：循环不包含`0`我们需要两个额外的操作：

 1. 携带`0`进入循环
 2. 删除`0`固定周期后

 所以总数变为：```
k + 1
```运营。 

### 步骤 5：总成本

 添加每个周期的成本。 

### 第 6 步：尝试两个有效目标

 计算：

 - 操作`[0,1,2,...,n-1]`- 操作`[1,2,3,...,n-1,0]`返回最小值。 

### 为什么它有效

 每个放错位置的元素都属于一个置换循环。 一个循环包含`0`可以通过反复将正确的物品交换到空位置来最佳地解决。 一个循环没有`0`需要暂时引入空白空间，这恰好需要两次额外的操作。 由于周期是独立的，因此将每个周期的最佳成本相加即可得出全局最小值。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortArray(self, nums: List[int]) -> int:
        n = len(nums)

        def solve(target: List[int]) -> int:
            target_pos = [0] * n

            for index, value in enumerate(target):
                target_pos[value] = index

            visited = [False] * n
            operations = 0

            for start in range(n):
                if visited[start]:
                    continue

                if nums[start] == target[start]:
                    visited[start] = True
                    continue

                cycle_length = 0
                contains_zero = False

                current = start

                while not visited[current]:
                    visited[current] = True
                    cycle_length += 1

                    if nums[current] == 0:
                        contains_zero = True

                    next_index = target_pos[nums[current]]
                    current = next_index

                if cycle_length > 0:
                    if contains_zero:
                        operations += cycle_length - 1
                    else:
                        operations += cycle_length + 1

            return operations

        target_front = list(range(n))
        target_back = list(range(1, n)) + [0]

        return min(solve(target_front), solve(target_back))
```实现首先定义一个名为的辅助函数`solve`，它计算特定目标排列所需的最少操作。 

里面`solve`， 这`target_pos`数组存储每个值的正确目标索引。 这允许恒定时间查找每个数字应该移动的位置。 

然后该算法使用循环分解遍历排列。 这`visited`数组确保每个索引只处理一次。 

对于每个尚未正确的未访问索引，代码会通过重复移动到当前值所属的索引来遍历循环。 

在遍历期间，实现跟踪：

 - 周期长度
 - 循环是否包含`0`循环结束后，应用适当的公式：

 -`cycle_length - 1`如果`0`在里面
 -`cycle_length + 1`否则

 最后，代码评估两个有效的目标数组并返回较小的结果。 

## 解决方案```go
package main

func sortArray(nums []int) int {
	n := len(nums)

	solve := func(target []int) int {
		targetPos := make([]int, n)

		for i, v := range target {
			targetPos[v] = i
		}

		visited := make([]bool, n)
		operations := 0

		for start := 0; start < n; start++ {
			if visited[start] {
				continue
			}

			if nums[start] == target[start] {
				visited[start] = true
				continue
			}

			cycleLength := 0
			containsZero := false

			current := start

			for !visited[current] {
				visited[current] = true
				cycleLength++

				if nums[current] == 0 {
					containsZero = true
				}

				nextIndex := targetPos[nums[current]]
				current = nextIndex
			}

			if cycleLength > 0 {
				if containsZero {
					operations += cycleLength - 1
				} else {
					operations += cycleLength + 1
				}
			}
		}

		return operations
	}

	targetFront := make([]int, n)
	for i := 0; i < n; i++ {
		targetFront[i] = i
	}

	targetBack := make([]int, n)
	for i := 0; i < n-1; i++ {
		targetBack[i] = i + 1
	}
	targetBack[n-1] = 0

	answer1 := solve(targetFront)
	answer2 := solve(targetBack)

	if answer1 < answer2 {
		return answer1
	}

	return answer2
}
```Go 实现遵循与 Python 版本相同的循环分解逻辑。 

切片用于数组，例如`targetPos`和`visited`。 由于约束保证值适合标准整数，因此不需要特殊的溢出处理。 

Go 不像 Python 那样方便地支持嵌套命名函数，但分配给变量的匿名函数在这里可以很好地工作。 该实现还使用循环显式构造两个目标数组。

 ## 边缘情况

 当数组已经排序时，会出现一种重要的边缘情况。 由于问题允许双方`[0,1,2,...]`和`[1,2,3,...,0]`，实施必须检查两个目标。 仅检查一种配置的解决方案将错误地为数组返回非零答案，例如`[1,2,3,4,0]`。 

当循环不包含时会发生另一个棘手的情况`0`。 许多不正确的解决方案假设每个周期的长度`k`成本`k - 1`运营。 仅当空白空间直接参与循环时才有效。 如果没有，我们必须花费额外的两步才能带来`0`进入循环并随后将其移除。 该实现显式跟踪是否`0`出现在每个周期中。 

第三个重要的边缘情况涉及非常大的数组。 自从`n`可以达到`100000`，递归 DFS 实现存在堆栈溢出风险。 该解决方案使用循环和访问数组进行迭代遍历，即使对于最大的输入也能确保安全执行。
