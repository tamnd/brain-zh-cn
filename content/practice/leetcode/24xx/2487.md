[LeetCode 问题 2487](https://leetcode.com/problems/remove-nodes-from-linked-list/)

 **难度：** 🟡 中等
 **主题：** 链表、堆栈、递归、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表的头，并要求我们删除在其右侧某处具有严格更大值的每个节点。 

换句话说，对于每个节点，我们必须判断链表中是否存在另一个值更大的节点。 如果存在这样的节点，则应删除当前节点。 否则，该节点应保留在最终链表中。 

例如，考虑以下列表：```
5 -> 2 -> 13 -> 3 -> 8
```节点`5`应该被删除，因为`13`出现较晚且大于`5`。 

节点`2`也应该被删除，因为`13`更大。 

节点`13`保留，因为其右侧不存在更大的值。 

节点`3`被删除是因为`8`更大并且出现得更晚。 

节点`8`保留，因为它是最终节点。 

结果列表变为：```
13 -> 8
```约束条件很重要：

 - 该列表最多可以包含`10^5`节点。 
- 节点值也可以大到`10^5`。 

这些限制立即告诉我们，`O(n^2)`在最坏的情况下，解决方案可能会太慢。 二次算法`100000`元素需要大约`10^10`操作，这远远超出了 LeetCode 可接受的范围。 

输入保证至少包含一个节点，因此我们不需要从问题约束中处理完全空的列表，尽管健壮的实现仍然可以安全地支持`None`或者`nil`。 

一些边缘情况很重要：

 - 严格递增的列表，例如`[1,2,3,4]`，其中除了最后一个节点之外的所有节点都必须被删除。 
- 严格递减的列表，例如`[9,7,5,3]`，其中没有节点被删除。 
- 重复值，例如`[5,5,5]`，其中没有节点被删除，因为条件需要严格更大的值。 
- 单节点列表，节点始终保留在其中。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个节点并搜索其右侧的所有节点以确定是否存在更大的值。 

对于每个节点：

 1. 遍历列表的剩余部分。 
2. 如果发现更大的值，则删除当前节点。 
3. 否则，保留。 

这种方法简单明了并且显然是正确的，因为它明确地检查每个节点的问题状况。 

然而，其性能较差。 对于每个节点，我们可以扫描列表的几乎整个剩余部分。 如果列表包含`n`节点，总工作量变为：```
(n - 1) + (n - 2) + ... + 1
```这是`O(n^2)`。 

高达`100000`节点，这个解决方案太慢了。 

### 最佳方法

 关键的观察是，只有当节点大于或等于其右侧的每个值时，才应保留该节点。 

这意味着如果我们从右向左遍历列表，我们可以跟踪到目前为止看到的最大值。 

- 如果当前节点的值小于右侧看到的最大值，我们将其删除。 
- 否则，我们保留它并更新最大值。 

挑战在于单链表不支持反向遍历。 

有几种方法可以解决这个问题：

 - 先反转链表
 - 使用递归
 - 使用单调堆栈

 一个非常干净有效的方法是：

 1. 反转链表。 
2. 从左向右遍历，同时保持目前看到的最大值。 
3. 删除小于该最大值的节点。 
4. 再次反转列表以恢复原始顺序。 

这给出了一个`O(n)`解决方案，因为每个节点都被处理固定次数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 对于每个节点，扫描右侧的所有节点 |
 | 最佳| O(n) | O(1) | O(1) | 反转列表，从右侧跟踪最大值 |

 ## 算法演练

 ### 最优反向过滤算法

 1. 反转链表。 

由于我们需要右侧节点的信息，因此反转列表将问题转化为从原始右侧向左侧处理节点。 

例子：```
Original:  5 -> 2 -> 13 -> 3 -> 8
Reversed:  8 -> 3 -> 13 -> 2 -> 5
```2. 初始化目前为止看到的最大值。 

反转列表中的第一个节点始终保留，因为原始列表中其右侧不存在任何内容。 

我们存储：```
max_value = reversed_head.val
```3. 遍历反转列表。 

对于每个节点：

 - 如果下一个节点的值小于`max_value`，将其删除。 
- 否则，保留并更新`max_value`。 

这有效是因为`max_value`表示当前节点右侧原本的最大值。 
4. 通过跳过指针删除节点。 

由于这是一个单链表，因此删除是通过更改：```
current.next = current.next.next
```5. 再次反转过滤后的列表。 

其余节点目前处于相反的顺序。 再次反转即可恢复原来的从左到右的顺序。 
6. 返回最终头。 

### 为什么它有效

 该算法在遍历反向列表时保持不变：

 >`max_value`在反向遍历中始终存储所有先前访问过的节点中的最大值。 

由于反转交换了左右关系，因此反转列表中先前访问过的节点与最初位于右侧的节点完全对应。 

因此：

 - 如果节点的值小于`max_value`，其右侧原来存在一个更大的节点，因此必须将其删除。 
- 否则，它应该保留。 

这保证了每个节点的正确性。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def removeNodes(self, head: Optional[ListNode]) -> Optional[ListNode]:
        
        def reverse(node: Optional[ListNode]) -> Optional[ListNode]:
            prev = None
            current = node
            
            while current:
                next_node = current.next
                current.next = prev
                prev = current
                current = next_node
            
            return prev
        
        # Reverse the list
        head = reverse(head)
        
        # Remove nodes smaller than max seen so far
        max_value = head.val
        current = head
        
        while current and current.next:
            if current.next.val < max_value:
                current.next = current.next.next
            else:
                current = current.next
                max_value = current.val
        
        # Reverse again to restore order
        return reverse(head)
```实现从一个名为的辅助函数开始`reverse`，它使用三个指针迭代地反转单链表：

 -`prev`-`current`-`next_node`该助手使用两次，一次在过滤之前，一次在过滤之后。 

反转列表后，第一个节点会自动生存，因为它的右侧原本没有节点。 它的值初始化`max_value`。 

主要遍历检查`current.next`而不是`current`。 这使得节点删除变得更简单，因为我们可以通过更新指针直接删除下一个节点。 

如果`current.next.val`小于`max_value`，该节点被跳过。 否则，该节点将成为最终列表的一部分，因此我们前进`current`并更新`max_value`。 

最后，将过滤后的反转列表再次反转，恢复原来的排序。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func removeNodes(head *ListNode) *ListNode {
    
    reverse := func(node *ListNode) *ListNode {
        var prev *ListNode
        current := node
        
        for current != nil {
            nextNode := current.Next
            current.Next = prev
            prev = current
            current = nextNode
        }
        
        return prev
    }
    
    // Reverse the list
    head = reverse(head)
    
    // Remove nodes smaller than max seen so far
    maxValue := head.Val
    current := head
    
    for current != nil && current.Next != nil {
        if current.Next.Val < maxValue {
            current.Next = current.Next.Next
        } else {
            current = current.Next
            maxValue = current.Val
        }
    }
    
    // Reverse again to restore order
    return reverse(head)
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

一个显着的区别是 Go 的显式指针处理。 而不是`None`, Go 使用`nil`。 指针更新在其他方面是相同的。 

反转助手使用局部指针变量和迭代遍历，这避免了递归深度问题。 

由于节点值最多为`10^5`，整数溢出不是 Go 标准中的问题`int`类型。

 ## 边缘情况

 ### 单节点列表

 仅包含一个节点的列表是一个重要的边界条件。 由于右侧不存在节点，因此该节点必须始终保留。 

有缺陷的实现可能会在反转或过滤期间意外删除它。 此实现可以自然地处理这种情况，因为遍历循环永远不会删除唯一的节点。 

### 严格递增列表

 考虑：```
1 -> 2 -> 3 -> 4
```除最后一个节点外，每个节点的右侧都有更大的值。 

这种情况很有用，因为它迫使算法删除许多连续的节点。 不正确的指针更新很容易破坏这里的列表结构。 

该实现通过更新安全地删除节点`current.next`不前进`current`删除后。 

### 重复值

 考虑：```
5 -> 5 -> 5
```该条件需要严格大于的值，而不是大于或等于的值。 

一个常见的错误是使用`<=`而不是`<`，这会错误地删除相等的值。 

此实现仅在以下情况下删除节点：```
current.next.val < max_value
```相同的值会正确保留在列表中。 

### 严格递减列表

 考虑：```
9 -> 7 -> 5 -> 3
```没有节点的右侧具有更大的值，因此整个列表应保持不变。 

此边缘情况验证了算法不会删除不必要的节点并正确更新`max_value`随着遍历的进行。
