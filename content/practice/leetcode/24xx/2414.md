[LeetCode 问题 2414](https://leetcode.com/problems/length-of-the-longest-alphabetical-continuous-substring/)

 **难度：** 🟡 中等
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们找到给定字符串中最长子字符串的长度`s`其中字符按连续字母顺序出现。 

字母连续子串意味着每对相邻的字符在字母表中相差正好一个。 例如：

-`"abc"`有效，因为：

 -`'b'`紧随其后`'a'`-`'c'`紧随其后`'b'`-`"cde"`也有效
 -`"abd"`无效，因为`'d'`不立即跟随`'b'`-`"za"`无效，因为字母表不环绕

 输入是一个小写英文字符串，长度介于`1`和`10^5`。 这个约束很重要，因为它告诉我们低效的子串枚举方法可能会变得太慢。 在最坏的情况下，二次算法可能需要数十亿次运算。 

预期输出是一个整数，表示所有有效字母连续子串中的最大长度。 

一些重要的观察有助于澄清问题：

 - 每个字符都是长度有效的连续子串`1`- 我们只关心连续的子串，而不关心子序列
 - 字母表每一步必须向前增加一个字符
 - 序列不从`'z'`到`'a'`一些可能导致错误的边缘情况包括：

 - 一个长度的字符串`1`- 没有相邻字符连续的字符串
 - 整个输入已经连续的字符串
 - 由无效转换分隔的多个连续段
 - 重复的字符，例如`"aaabbb"`这应该打破连续性

 ## 方法

 ### 蛮力方法

 暴力解决方案考虑每个可能的子串并检查它是否形成按字母顺序排列的连续字符串。 

对于每个起始索引`i`，我们可以将子字符串向右扩展一次一个字符。 对于每个子串`s[i:j]`，我们验证所有相邻字符是否完全不同`1`。 

例如，给定`"abcde"`:

 - 从索引开始`0`-`"a"`有效
 -`"ab"`有效
 -`"abc"`有效
 -`"abcd"`有效
 -`"abcde"`有效
 - 从索引开始`1`-`"b"`有效
 -`"bc"`有效
 - 等等

 此方法是正确的，因为它详尽地检查每个子字符串并跟踪最长的有效子字符串。 

然而，对于大输入来说它太慢了。 一个长度的字符串`n`包含`O(n^2)`子字符串，验证每个子字符串可能需要长达`O(n)`时间。 即使进行了优化，运行时也变得不切实际`n = 10^5`。 

### 最佳方法

 关键的观察是我们实际上不需要独立检查每个子串。 

如果每个相邻对满足以下条件，则子串是按字母顺序连续的：```
ord(s[i]) - ord(s[i - 1]) == 1
```这意味着我们可以扫描一次字符串，同时保持当前有效连续段的长度。 

在每个位置：

 - 如果当前字符按字母顺序排列在前一个字符之后，我们将扩展当前的连胜
 - 否则，我们将条纹长度重置为`1`我们不断追踪迄今为止看到的最大条纹长度。 

这将问题转化为简单的线性扫描。

 ## 算法演练

 ### 第 1 步：初始化跟踪变量

 创建两个变量：

 -`current_length`，表示当前连续子串长度
 -`max_length`，代表迄今为止看到的最佳答案

 两者都开始于`1`因为任何单个字符都是有效的。 

### 步骤 2：遍历字符串

 从索引开始迭代字符串`1`。 

在每个位置，将当前字符与前一个字符进行比较。 

### 步骤 3：检查字母顺序连续性

 如果：```
ord(s[i]) - ord(s[i - 1]) == 1
```那么当前字符继续序列，所以递增`current_length`。 

否则，连续性会中断，因此重置`current_length`到`1`。 

### 步骤 4：更新最大值

 处理完每个字符后，更新：```
max_length = max(max_length, current_length)
```这确保我们始终记住遇到的最长有效段。 

###第五步：返回结果

 遍历完成后返回`max_length`。 

### 为什么它有效

 该算法保持一个不变量：

 -`current_length`始终存储以当前索引结尾的最长有效连续子字符串的长度

 只要连续字符相差一，扩展子字符串就是有效的。 否则，以当前索引结尾的任何更长的子字符串都会变得无效，因此重置为`1`是正确的。 

由于每个字符都被处理一次并且在扫描期间考虑了每个有效段，因此该算法正确地找到了全局最大值。 

## Python 解决方案```python
class Solution:
    def longestContinuousSubstring(self, s: str) -> int:
        max_length = 1
        current_length = 1

        for i in range(1, len(s)):
            if ord(s[i]) - ord(s[i - 1]) == 1:
                current_length += 1
            else:
                current_length = 1

            max_length = max(max_length, current_length)

        return max_length
```实现首先初始化两个`max_length`和`current_length`到`1`。 这是有效的，因为每个单个字符都形成一个有效的连续子字符串。 

循环从索引处开始`1`因为每个字符都必须与其前一个字符进行比较。 

表达式：```python
ord(s[i]) - ord(s[i - 1]) == 1
```检查当前字符是否紧跟在字母表中的前一个字符之后。 

如果条件为真，则当前序列继续，因此我们递增`current_length`。 

如果条件为假，则序列中断并且我们重置`current_length`回到`1`。 

每次更新后，我们都会比较`current_length`和`max_length`保持迄今为止找到的最佳答案。 

最后，函数返回`max_length`。 

## 解决方案```go
func longestContinuousSubstring(s string) int {
    maxLength := 1
    currentLength := 1

    for i := 1; i < len(s); i++ {
        if s[i]-s[i-1] == 1 {
            currentLength++
        } else {
            currentLength = 1
        }

        if currentLength > maxLength {
            maxLength = currentLength
        }
    }

    return maxLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是 Go 字符串内部是字节切片，因此访问`s[i]`直接返回一个字节。 由于所有字符都是小写英文字母，因此字节算术在这里是完全安全的。 

不需要额外的内存分配，并且整数溢出不是问题，因为最大子字符串长度最多为`10^5`。

 ## 边缘情况

 一个重要的边缘情况是单字符字符串，例如`"a"`。 由于每个单独的字符自动成为有效的字母连续子串，因此正确的答案必须是`1`。 错误初始化计数器的实现可能会意外返回`0`。 该解决方案通过将两个跟踪变量初始化为`1`。 

另一个重要的情况是重复的字符，例如`"aaaa"`。 连续的字母顺序连续性需要精确的差异`1`， 不是`0`。 因此，重复的字符必然会破坏顺序。 实施正确重置`current_length`每当差异条件失败时。 

第三个重要的情况是降序或非连续字符，例如`"zyx"`或者`"acdf"`。 某些实现错误地仅检查字符是否不同，而不是按字母顺序递增检查它们是否相差正好 1。 该解决方案专门检查：```
ord(s[i]) - ord(s[i - 1]) == 1
```这保证只有严格增加的连续字符才能扩展序列。 

另一个微妙的边缘情况涉及中断，然后是新的有效序列，例如`"abxyzabc"`。 算法必须在无效转换后正确重置并重新开始计数。 由于实施重置`current_length`到`1`每当连续性中断时，它自然会正确处理多个独立的连续段。
