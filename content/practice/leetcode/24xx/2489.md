[LeetCode 问题 2489](https://leetcode.com/problems/number-of-substrings-with-fixed-ratio/)

 **难度：** 🟡 中等
 **主题：** 哈希表、数学、字符串、前缀和

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`，以及两个互质整数`num1`和`num2`。 我们需要计算包含多少个非空子字符串`0`沙`1`s 的精确比例`num1 : num2`。 

如果子字符串包含：

 -`zeroCount`零点
 -`oneCount`那些

 那么它仅在以下情况下有效：$$\frac{zeroCount}{oneCount} = \frac{num1}{num2}$$因为这两个数是互质的，所以这个条件等价于：$$zeroCount \times num2 = oneCount \times num1$$输入大小可以大到`10^5`，它立即告诉我们显式检查每个子字符串会太慢。 有`O(n^2)`长度字符串中的子字符串`n`，并且迭代所有这些都会超出时间限制。 

输出应该是满足要求比例的子串总数。 

一些边缘情况很重要：

 - 一个字符串只能包含`0`或仅`1`s。 
- 可能根本没有有效的子字符串。 
- 许多子串可能具有相同的比率。 
- 有效比率可能需要大量计数，例如`3:5`或者`7:2`。 
- 由于答案可能很大，因此我们必须在 Go 中使用 64 位整数类型。 

关键的挑战是找到一种有效计算有效子串的方法，而无需枚举每个可能的子串。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个子字符串。 

对于每个起始索引`i`，我们将子字符串向右扩展，每次一个字符。 在扩张的同时，我们坚持：

 - 零的数量
 - 的数量

 在每一步中，我们都会检查是否：$$zeroCount \times num2 = oneCount \times num1$$如果等式成立，我们就增加答案。 

这种方法是正确的，因为每个子字符串都被检查一次，因此不会错过任何有效的子字符串。 

然而，有`O(n^2)`子串，并且每个子串更新仍然需要处理字符。 即使采用增量计数，总体复杂性仍然是二次的。 

为了`n = 10^5`，这太慢了。 

### 最优前缀和+哈希图方法

 关键的观察是子串比率条件通常可以转换为前缀关系。 

认为：

-`zeros[i]`是索引之前结尾的前缀中零的数量`i`-`ones[i]`是索引之前结尾的前缀中的个数`i`对于来自的子串`l`到`r`：$$substringZeros = zeros[r+1] - zeros[l]$$

$$substringOnes = ones[r+1] - ones[l]$$如果满足以下条件，则子字符串有效：$$(substringZeros) \times num2 = (substringOnes) \times num1$$替换前缀和：$$(zeros[r+1] - zeros[l]) \times num2 = (ones[r+1] - ones[l]) \times num1$$重新排列：$$zeros[r+1] \times num2 - ones[r+1] \times num1 = zeros[l] \times num2 - ones[l] \times num1$$这是至关重要的见解。 

如果两个前缀产生相同的值：$$zeros \times num2 - ones \times num1$$那么它们之间的子串就具有所需的比例。 

因此，我们不是直接检查子字符串，而是在每个位置计算这个转换后的前缀值，并计算每个值之前出现的次数。 

这将问题转化为可在线性时间内解决的标准前缀频率计数问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 显式检查每个子字符串 |
 | 最佳| O(n) | O(n) | 将转换后的前缀和与哈希图一起使用 |

 ## 算法演练

 1. 初始化 0 和 1 计数器。 

我们在从左到右扫描字符串的同时保持运行计数。 
2. 定义转换后的前缀值。 

在每个位置，计算：$$key = zeros \times num2 - ones \times num1$$该值唯一地表示有效子串所需的余额。 
3. 使用哈希图来存储频率。 

哈希图每次存储多少次`key`到目前为止已经出现了。 

最初：

-`key = 0`有频率`1`这表示处理任何字符之前的空前缀。 
4. 逐字符处理字符串。 

对于每个字符：

 - 增量`zeros`如果角色是`'0'`- 增量`ones`如果角色是`'1'`然后重新计算当前`key`。 
5. 计算以当前位置结尾的有效子字符串。 

如果一样的话`key`出现较早`k`次，那么有`k`以当前位置结尾的有效子字符串。 

为什么？ 

因为相同变换后的前缀值的每个较早出现都形成满足比率条件的子串。 
6. 更新哈希图。 

使用当前的后`key`，增加其在地图中的频率。 
7. 继续，直到处理完整个字符串。 
8. 返回累计答案。 

### 为什么它有效

 该算法依赖于两个前缀具有相同变换值的不变式：$$zeros \times num2 - ones \times num1$$定义一个子串，其零与一的比率等于`num1 : num2`。 

每个有效子字符串恰好对应于一对相等的转换前缀值，并且每个这样的对都定义一个有效子字符串。 因此，正确计算相等前缀状态就可以计算所有有效子串。 

## Python 解决方案```python
from collections import defaultdict

class Solution:
    def fixedRatio(self, s: str, num1: int, num2: int) -> int:
        prefix_frequency = defaultdict(int)
        prefix_frequency[0] = 1

        zeros = 0
        ones = 0
        answer = 0

        for ch in s:
            if ch == '0':
                zeros += 1
            else:
                ones += 1

            key = zeros * num2 - ones * num1

            answer += prefix_frequency[key]

            prefix_frequency[key] += 1

        return answer
```该实现遵循算法演练中描述的确切逻辑。 

我们首先创建一个名为的哈希图`prefix_frequency`。 这存储每个转换后的前缀值出现的次数。 

条目`prefix_frequency[0] = 1`很重要，因为它表示处理任何字符之前的空前缀。 如果没有这个初始化，子字符串从索引开始`0`将无法正确计算。 

当我们遍历字符串时：

 - 我们更新要么`zeros`或者`ones`- 计算转换后的前缀值
 - 将该值之前出现的次数添加到答案中
 - 将当前前缀状态存储在地图中

 使用`defaultdict(int)`简化了频率处理，因为丢失的键会自动默认为零。 

由于每个字符被处理一次并且每个哈希映射操作平均时间为常数，因此该解决方案以线性时间运行。 

## 解决方案```go
func fixedRatio(s string, num1 int, num2 int) int64 {
	prefixFrequency := make(map[int]int64)
	prefixFrequency[0] = 1

	zeros := 0
	ones := 0
	var answer int64 = 0

	for _, ch := range s {
		if ch == '0' {
			zeros++
		} else {
			ones++
		}

		key := zeros*num2 - ones*num1

		answer += prefixFrequency[key]

		prefixFrequency[key]++
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 

一个`map[int]int64`使用它是因为有效子串的数量可能超出 32 位整数的范围。 

转换后的前缀值存储为`int`，而频率和最终答案使用`int64`。 

与Python不同`defaultdict`，Go 映射会自动为缺失的键返回零值，因此显式初始化超出`prefixFrequency[0] = 1`是不必要的。

 ## 边缘情况

 当字符串仅包含一种类型的字符时，会出现一种重要的边缘情况。 例如，`"00000"`不包含`1`s。 任何比率至少需要一个`1`是不可能满足的。 幼稚的实现可能会意外地除以零或错误地将此类子字符串视为有效。 此实现完全避免了除法，而是使用变换后的线性方程，因此这些情况可以自然处理。 

另一个重要的情况是从索引开始的子字符串`0`。 如果没有正确初始化频率图，许多前缀和解决方案都会失败。 该行：```
prefix_frequency[0] = 1
```确保只要当前前缀本身满足所需的比率，就会正确计数。 

第三种边缘情况涉及许多重叠的有效子串。 例如，`"010101"`与比例`1:1`包含许多共享端点和重叠的平衡子串。 基于频率的计数方法可以正确计算所有匹配的转换前缀状态对，确保没有遗漏或重复计算有效子串。 

最后一个微妙的情况是大输出。 既然可以有`O(n^2)`高度重复的字符串中的有效子字符串，答案可能会变得非常大。 因此，Go 解决方案使用`int64`的答案和频率以避免溢出。
