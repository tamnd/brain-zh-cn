 # LeetCode 2450 - 应用运算后不同二进制字符串的数量

 ## 问题理解

 我们得到一个二进制字符串`s`长度`n`和一个整数`k`。 操作包括选择任意长度的连续子串`k`并翻转该子串中的每一位。 一个`0`变成`1`，和一个`1`变成`0`。 

该操作可以应用任意次数，包括零次。 由于我们可能会重复选择不同的子字符串，因此可能会生成许多不同的二进制字符串。 任务是确定从原始字符串可以访问多少个不同的字符串。 

答案可能会变得非常大，因此必须以模数形式返回`10^9 + 7`。 

关键的观察是实际内容`s`并不像最初看起来那么重要。 问题从根本上问，通过允许的翻转操作的组合可以达到多少种不同的状态。 

限制条件很大：

 -`1 <= k <= n <= 100000`对所有可能的字符串进行状态空间搜索是不可能的，因为最多有`2^100000`可能的二进制字符串。 任何显式生成可达字符串的解决方案都将立即变得不可行。 

一些重要的边缘情况包括：

 -`k = 1`，其中每个单独的位都可以独立翻转。 
-`k = n`，其中唯一可能的操作是翻转整个字符串。 
- 接近最大约束的非常大的字符串。 
- 字符串完全由以下组成`0`或全部`1`s。 
- 多个操作序列产生相同的最终字符串的情况。 

理解运算的代数结构是有效解决问题的关键。 

## 方法

 ### 蛮力

 一个自然的第一个想法是将每个二进制字符串视为图中的一个状态。 

从给定的状态中，我们可以选择任意长度的子串`k`，翻转它，然后移动到一个新状态。 开始于`s`，我们可以执行 BFS 或 DFS 并计算所有可达字符串。 

这种方法是正确的，因为它明确地探索了每个可到达的配置。 

然而，这是完全不切实际的。 一个长度的字符串`n`最多有`2^n`可能的状态。 即使对于中等值`n`，状态空间变得非常大。 自从`n`可以达到`100000`，穷举探索是不可能的。 

### 关键见解

 每个操作都是其自身的逆操作。 

如果我们将二进制字符串表示为 GF(2) 上的向量，则翻转长度-`k`子串对应于与固定向量的异或：

 - 所选子串位置包含`1`。 
- 所有其他职位均包含`0`。 

让它有`m = n - k + 1`可能长度的子串`k`。 

每个子串操作对应一个生成向量。 多次应用运算相当于将这些生成器向量的某些子集异或在一起。 两次应用相同的操作会抵消。 

因此，每个可达字符串都具有以下形式：```
original_string XOR linear_combination_of_generators
```不同的可达字符串的数量等于这些子字符串向量生成的向量空间的大小。 

如果生成向量的秩是`r`，则不同可达字符串的数量为：```
2^r
```所以问题归结为找到所有长度的排名 -`k`区间向量。 

一个显着的特性是这些向量总是具有秩：```
n - k + 1
```要了解原因，请考虑向量：```
1110000...
0111000...
0011100...
...
```每个向量从不同的位置开始。 从左到右看，每个新向量都会引入一个新的前导位置，这是先前向量无法产生的。 因此向量是线性无关的。 

由于正好有`n-k+1`这样的向量，秩为：```
r = n - k + 1
```因此答案很简单：```
2^(n-k+1) mod (10^9+7)
```## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 探索每个可到达的二进制字符串 |
 | 最佳| O(log n) | O(1) | O(1) | 使用区间翻转向量空间的秩 |

 ## 算法演练

 1.让`n`是字符串的长度。 
2. 计算可能的长度数量-`k`子串：```
n - k + 1
```每个这样的子串对应于一个生成器向量。 
3. 观察到所有生成向量在 GF(2) 上线性无关。 
4. 因此生成的向量空间的秩为：```
rank = n - k + 1
```5. 秩向量空间`r`确切包含：```
2^r
```不同的向量。 
6. 因此，不同的可达字符串的数量为：```
2^(n-k+1)
```7. 返回该值的模数`10^9 + 7`使用快速模幂。 

### 为什么它有效

 每个操作对应于固定长度的异或运算`k`区间向量。 由于 XOR 是 GF(2) 中的加法，因此所有可达状态的集合形成了由这些区间向量生成的仿射空间。 区间向量是线性独立的，因为每个向量都有一个唯一的最左边位置，其中包含`1`以后的向量都无法产生。 因此，排名正好是`n-k+1`。 秩向量空间`r`包含`2^r`元素，给出最终答案`2^(n-k+1)`。 

## Python 解决方案```python
class Solution:
    def countDistinctStrings(self, s: str, k: int) -> int:
        MOD = 10**9 + 7
        return pow(2, len(s) - k + 1, MOD)
```该实现直接应用上面导出的数学结果。 

首先，我们计算区间翻转向量空间的秩，即`len(s) - k + 1`。 由于每个独立的生成器都会使可达状态的数量加倍，因此答案是`2^(len(s)-k+1)`。 

Python 的内置`pow(base, exponent, mod)`在对数时间内执行快速模幂运算，使其成为有效处理非常大的指数的理想选择。 

## 解决方案```go
func countDistinctStrings(s string, k int) int {
	const mod int64 = 1000000007

	exp := len(s) - k + 1
	var result int64 = 1
	var base int64 = 2

	for exp > 0 {
		if exp&1 == 1 {
			result = (result * base) % mod
		}
		base = (base * base) % mod
		exp >>= 1
	}

	return int(result)
}
```Go版本手动实现二进制求幂，因为Go没有提供相当于Python三参数的内置模幂函数`pow`。 

所有算术运算均使用`int64`以避免在取模之前的乘法过程中溢出。

 ## 边缘情况

 ### 边缘情况 1：`k = 1`什么时候`k = 1`，每个操作都恰好翻转一位。 因此，每个位置都可以独立于所有其他位置进行切换。 排名变为：```
n - 1 + 1 = n
```答案是`2^n`。 一个常见的错误是试图对不存在的操作之间的交互进行建模。 该公式自然可以处理这种情况。 

### 边缘情况 2：`k = n`什么时候`k`等于整个字符串长度，只有一种可能的操作，同时翻转每一位。 排名是：```
n - n + 1 = 1
```因此只有两个字符串是可访问的：原始字符串及其补码。 执行正确返回`2`。 

### 边缘情况 3：最大约束值

 对于`n = 100000`，任何基于模拟的方法都是不可能的。 该解决方案完全避免构造状态并计算单个模幂。 即使在最大输入大小的情况下，这也可以使内存使用量和运行时间保持极小。 

### 边缘情况 4：字符串内容并不重要

 很容易假设该模式`0`沙`1`s 影响答案。 实际上，所有可达状态都是通过将原始字符串与生成的子空间中的向量进行异或来获得的。 该子空间的大小仅取决于`n`和`k`，不在初始位上。 因此，该实现从不检查单个字符`s`。
