[LeetCode 问题 2423](https://leetcode.com/problems/remove-letter-to-equalize-Frequency/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们确定是否可以从字符串中删除**恰好一个字符**`word`这样字符串中所有剩余的字符都具有**相同的频率**。 输入字符串由小写英文字母组成，长度在 2 到 100 之间。输出是一个布尔值，指示此转换是否可行。 

重申一下，我们需要检查删除单个字符是否可以使所有不同字符的计数相等。 输入字符串可能包含频率不同的多个字符，我们必须删除**恰好一个**字符，这意味着什么也不做不是一种选择。 

重要的边缘情况包括以下字符串：

 - 除一个字符外，所有字符均已具有相同的频率。 
- 一个字符只出现一次，删除它可以平衡频率。 
- 由于存在多个差异，删除任何字符都无法均衡频率。 
- 字符串只有两个字符，这是最小长度。 

约束很小（`word.length <= 100`），如果有必要，它允许复杂度为 O(n²) 的方法，尽管可以实现线性解决方案。 

## 方法

 ### 蛮力

 暴力方法会迭代字符串中的每个字符，将其删除，并检查结果字符串中的所有字符是否具有相同的频率。 对于每次移除，我们可以使用频率计数器并验证所有计数是否相等。 这保证了正确性，因为它明确地检查所有可能性。 缺点是这种方法需要 O(n²) 时间，因为需要重新计算 n 个移除中每一个的频率，考虑到较小的约束，这是不必要的。 

### 最佳方法

 关键的见解是我们**不需要模拟每次删除**。 相反，我们可以计算每个字符的频率一次，然后分析频率计数：

 1. 使用哈希映射计算每个字符出现的次数。 
2. 使用另一个散列图计算这些频率的出现次数。 
3. 只有少数情况下删除单个字符可以平衡频率：

 - 一个字符只出现一次并且可以被删除。 
- 一个角色比其他角色出现的次数多； 删除一个实例可以平衡计数。 
- 除了一个出现一次的字符外，所有字符都已经具有相同的频率。 

通过检查频率的分布及其计数，我们可以在 O(n) 时间内决定是否可以删除单个字符来均衡频率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 删除每个字符并明确检查频率 |
 | 最佳| O(n) | O(1) | O(1) | 无需删除字符即可计算频率并分析频率分布 |

 ## 算法演练

 1. 创建哈希图`freq`计算每个字符出现的次数`word`。 
2. 创建另一个哈希图`countFreq`计算每个频率有多少个字符。 
3.如果`countFreq`只有一个键并且该键为 1，返回 true（所有字符都是唯一的，删除任何字符都会留下相同的频率）。 
4.如果`countFreq`正好有两个键，检查两种可能性：

 - 一个频率是 1 并且出现一次（我们可以完全删除该字符）。 
- 另一个频率恰好比另一个高 1，并且出现一次（我们可以删除该字符的一个实例）。 
5. 在所有其他情况下，返回 false，因为没有任何一次移除可以使频率相等。 

工作原理：该算法之所以有效，是因为对于平衡频率的单次删除，频率计数最多只能相差 1，并且其中一个频率必须恰好出现一次。 通过检查频率分布，我们可以有效地确定是否存在这种删除。 

## Python 解决方案```python
class Solution:
    def equalFrequency(self, word: str) -> bool:
        from collections import Counter
        
        freq = Counter(word)
        countFreq = Counter(freq.values())
        
        if len(countFreq) == 1:
            # Case: all characters have the same frequency
            key = list(countFreq.keys())[0]
            if key == 1 or len(freq) == 1:
                return True
            return False
        
        if len(countFreq) == 2:
            f1, f2 = countFreq.keys()
            c1, c2 = countFreq[f1], countFreq[f2]
            
            # Case 1: One frequency is 1 and occurs once
            if (f1 == 1 and c1 == 1) or (f2 == 1 and c2 == 1):
                return True
            
            # Case 2: One frequency is higher by 1 and occurs once
            if (f1 - f2 == 1 and c1 == 1) or (f2 - f1 == 1 and c2 == 1):
                return True
        
        return False
```Python 代码首先计算每个字符的频率，然后计算有多少个字符共享每个频率。 通过分析不同频率的数量及其计数，我们有效地检查了删除单个字符可以平衡频率的两种场景。 

## 解决方案```go
func equalFrequency(word string) bool {
    freq := make(map[rune]int)
    for _, ch := range word {
        freq[ch]++
    }

    countFreq := make(map[int]int)
    for _, v := range freq {
        countFreq[v]++
    }

    if len(countFreq) == 1 {
        for k := range countFreq {
            if k == 1 || len(freq) == 1 {
                return true
            }
        }
        return false
    }

    if len(countFreq) == 2 {
        var f1, f2, c1, c2 int
        i := 0
        for k, v := range countFreq {
            if i == 0 {
                f1, c1 = k, v
            } else {
                f2, c2 = k, v
            }
            i++
        }

        if (f1 == 1 && c1 == 1) || (f2 == 1 && c2 == 1) {
            return true
        }

        if (f1-f2 == 1 && c1 == 1) || (f2-f1 == 1 && c2 == 1) {
            return true
        }
    }

    return false
}
```Go 实现反映了 Python 逻辑。 主要区别在于迭代映射（Go 中没有保证顺序）以及显式处理整数键和值。 

## 工作示例

 示例1：`word = "abcc"`- 计算字符数：`{'a':1, 'b':1, 'c':2}`- 计数频率：`{1:2, 2:1}`- 存在两个频率：1 出现 2 次，2 出现 1 次
 - 频率 2 出现一次，删除一个“c”使所有频率等于 1
 - 返回真

 示例2：`word = "aazz"`- 计算字符数：`{'a':2, 'z':2}`- 计数频率：`{2:2}`- 仅存在一个频率 (2)，无法删除单个字符来均衡
 - 返回错误

 ## 边缘情况

 1. **单字符串**：`"a"`- 删除它会留下一个空字符串，这基本上是平衡的。 通过检查频率键是否为 1 来处理。 
2. **所有字符只出现一次**：`"abc"`- 删除任何字符仍然会导致其余字符出现相同的频率。 已处理，因为频率图显示计数为 1。 
3. **一个角色出现的次数比其他角色多得多**：`"aaab"`- 该算法检测到删除出现频率较高的字符可以平衡其余字符。 

These edge cases ensure that the implementation correctly handles strings where removal affects either rare or frequent characters and that the analysis of frequency counts is robust.
