[LeetCode 问题 2474](https://leetcode.com/problems/customers-with-strictly-increasing-purchases/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`Orders`表，其中每行代表客户进行的购买。 每个订单都有一个`order_id`, 一个`customer_id`， 一个`order_date`，和一个`price`。 

我们需要找到从第一个购买年到最后一个购买年，年度总购买量严格增加的所有客户。 

关键的细节是，我们必须考虑客户的第一个订单年份和最后一个订单年份之间的每一年，即使客户在某些年份没有下订单。 对于那些缺失的年份，考虑年度购买总额`0`。 

例如，假设客户仅在 2015 年和 2017 年下了订单：

 - 2015 → 700
 - 2016 → 0
 - 2017 → 1000

 序列变为`[700, 0, 1000]`，这不是严格增加，因为`0`不大于`700`。 

“严格增加”是指每年的总数必须大于上一年的总数：```
year_1 < year_2 < year_3 < ...
```平等是不允许的。 

输入表可能包含同一客户在同一年的多个订单，因此我们必须先汇总年度总计，然后再检查递增情况。 

预期输出是一个仅包含`customer_id`满足条件的值。 

一个重要的观察是，年份之间的差距很重要。 幼稚的实现可能只比较存在购买的年份，但这是不正确的，因为缺失的年份必须算作零。 

一些重要的边缘情况包括：

 - 购买年份之间存在差距的客户
 - 多年来总数保持相等的客户
 - 总数减少的客户
 - 仅购买一年的客户
 - 同一年多个订单
 - 由于没有购买而导致隐性零总数的年份

 该问题保证了`order_id`是唯一的，因此我们不需要处理重复的行。 

## 方法

 ### 蛮力方法

 强力解决方案将独立处理每个客户。 

对于每一位客户，我们可以：

 1. 提取属于该客户的所有订单。 
2. 确定第一次和最后一次购买年份。 
3. 建立这些界限之间的完整年份列表。 
4. 每年，再次扫描所有订单以计算年度总计。 
5. 比较连续年度总数以验证严格增长。 

这种方法是正确的，因为它明确计算了每个所需的年度总计，包括贡献的缺失年份`0`。 

然而，它的效率很低，因为对于每个客户和每年，我们都会重复扫描订单以重新计算总数。 如果表很大，这种重复扫描就会变得昂贵。 

### 关键见解

 重要的优化是认识到年度总计应该只聚合一次。 

我们可以：

 1. 订单分组依据`(customer_id, year)`2. 每年计算一次总和
 3. 使用窗口函数，例如`LAG()`将每年与前一年进行比较
 4. 检测任何违反严格递增条件的情况

 另一个重要的见解是正确处理缺失的年份。 由于缺失的年份算作`0`，我们必须为每个客户生成第一个和最后一个购买年份之间的所有年份。 这通常需要递归 CTE 或数字表。 

一旦每个客户-年份组合都存在，问题就变成了一个简单的顺序比较问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(C × Y × N) | O(Y) | 反复扫描每个客户和年份的订单 |
 | 最佳 | O(N + C × Y) | O(C × Y) | 聚合一次并高效使用 SQL 窗口函数 |

 这里：

-`N`= 订单数量
 -`C`= 顾客数量
 -`Y`= 第一次购买与最后一次购买之间的平均年数

 ## 算法演练

 ### 最优 SQL 策略

 1. 首先，按客户和年份汇总所有订单。 

我们计算：```sql
SUM(price)
```分组依据：```sql
customer_id, YEAR(order_date)
```这为我们提供了每个客户的年度购买总额。 
2. 接下来，确定每个客户的第一个和最后一个购买年份。 

我们计算：```sql
MIN(year), MAX(year)
```对于每个客户。 
3. 第一年和最后一年之间每年生成。 

此步骤至关重要，因为缺少年份必须算作零购买。 

我们使用递归 CTE 来生成所有中间年份。 
4. 将生成的年份与年度总计连接起来。 

某些生成的年份可能不存在于聚合总计表中。 这些年来，我们使用：```sql
COALESCE(total, 0)
```所以缺失的年份变为零。 
5. 将每年的总数与上一年的总数进行比较。 

我们使用窗函数：```sql
LAG(total)
```按客户划分并按年份订购。 
6. 发现违规行为。 

如果任何一年有：```sql
current_total <= previous_total
```那么客户不符合严格增加条件。 
7. 回访客户无违规行为。 

### 为什么它有效

 该算法之所以有效，是因为它显式地构造了问题定义所需的精确序列：

 - 每年从第一次购买到最后一次购买
 - 包括零购买的年份

 构建序列后，`LAG()`比较检查每个相邻的对。 当且仅当每次比较都满足严格增加时，客户才是有效的。 

因为每个所需的年份都被精确地表示一次，并且每个相邻的年份都被精确地检查一次，所以该解决方案是正确的。 

## Python 解决方案

 LeetCode 数据库问题是使用 SQL 解决的，但以下 Python 实现通过算法演示了相同的逻辑。```python
from collections import defaultdict
from typing import List

class Solution:
    def strictlyIncreasingPurchases(
        self,
        orders: List[List[int]]
    ) -> List[int]:

        yearly_totals = defaultdict(lambda: defaultdict(int))

        for order_id, customer_id, year, price in orders:
            yearly_totals[customer_id][year] += price

        result = []

        for customer_id, year_map in yearly_totals.items():
            first_year = min(year_map.keys())
            last_year = max(year_map.keys())

            previous_total = -1
            valid = True

            for year in range(first_year, last_year + 1):
                current_total = year_map.get(year, 0)

                if current_total <= previous_total:
                    valid = False
                    break

                previous_total = current_total

            if valid:
                result.append(customer_id)

        return result
```### 实现说明

 该解决方案使用嵌套字典结构：```
yearly_totals[customer_id][year]
```存储每个客户年份对的总购买量。 

第一个循环通过求和价格来汇总年度总计。 

接下来，对于每个客户，我们确定第一次和最后一次购买年份。 这些界限定义了必须检查的确切年份范围。 

循环：```
for year in range(first_year, last_year + 1):
```确保自动包含缺失的年份。 

当字典中不存在年份时：```
year_map.get(year, 0)
```回报`0`，匹配问题要求。 

变量`previous_total`存储上一年的总计。 如果当年的总额不严格大于该客户，则该客户立即失效。 

最后，返回所有有效的客户 ID。 

## 解决方案```go
package main

import "sort"

type Order struct {
	OrderID    int
	CustomerID int
	Year       int
	Price      int
}

func strictlyIncreasingPurchases(orders []Order) []int {
	yearlyTotals := map[int]map[int]int{}

	for _, order := range orders {
		customer := order.CustomerID
		year := order.Year

		if yearlyTotals[customer] == nil {
			yearlyTotals[customer] = map[int]int{}
		}

		yearlyTotals[customer][year] += order.Price
	}

	result := []int{}

	for customer, yearMap := range yearlyTotals {
		firstYear := int(^uint(0) >> 1)
		lastYear := -1

		for year := range yearMap {
			if year < firstYear {
				firstYear = year
			}

			if year > lastYear {
				lastYear = year
			}
		}

		prevTotal := -1
		valid := true

		for year := firstYear; year <= lastYear; year++ {
			currentTotal := yearMap[year]

			if currentTotal <= prevTotal {
				valid = false
				break
			}

			prevTotal = currentTotal
		}

		if valid {
			result = append(result, customer)
		}
	}

	sort.Ints(result)

	return result
}
```### Go 特定注释

 Go 解决方案密切反映了 Python 逻辑。 

使用嵌套映射代替 Python`defaultdict`:```
map[int]map[int]int
```在 Go 中，从映射中读取不存在的键会自动返回零值，这很有用，因为缺失的年份应该算作`0`。 

该解决方案手动初始化缺失的内部映射，因为 Go 不会自动创建嵌套映射。 

结果在返回之前进行排序，因此输出顺序是确定的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N + C × Y) | 汇总订单一次，然后扫描年度范围 |
 | 空间| O(C × Y) | 存储所有客户年份对的年度总计 |

 聚合阶段将每个订单处理一次，这会花费`O(N)`。 

验证阶段在每个客户的第一个购买年份和最后一个购买年份之间每年都会迭代。 如果平均范围大小是`Y`，这花费了`O(C × Y)`全面的。 

空间复杂度来自于在嵌套哈希映射中存储年度总计。

 ## 边缘情况

 ### 购买之间缺失的年份

 客户可能会在非连续年份下订单。 这是最重要的边缘情况，因为缺少年份必须算作零购买。 

例如：```
2020 -> 500
2022 -> 1000
```必须解释为：```
2020 -> 500
2021 -> 0
2022 -> 1000
```仅比较现有年份的幼稚实现会错误地得出结论：`500 < 1000`并将客户标记为有效。 该实现通过在整个范围内迭代每年来避免此错误。 

### 连续总数相等

 严格递增意味着每个值都必须大于前一个值。 平等是不允许的。 

例如：```
2020 -> 900
2021 -> 900
```应该失败。 

实现使用：```
if current_total <= previous_total:
```它正确地拒绝了相等和递减的总数。 

### 仅购买一年的客户

 如果客户仅在一年内进行了购买，则没有相邻年份可供比较。 

例如：```
2020 -> 500
```这应该被认为是有效的，因为没有违反严格增加条件。 

该实现自然地处理了这个问题，因为循环运行一次并且永远不会遇到失败的比较。
