[LeetCode 问题 2400](https://leetcode.com/problems/number-of-ways-to-reach-a-position-after-exactly-k-steps/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划、组合学

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算从`startPos`到`endPos`在无限数轴上使用 **exactly`k`步骤**。 在每一步中，我们可以向左移动一个位置（`-1`) 或右侧一个位置 (`+1`）。 

重要的细节是**顺序很重要**。 如果左右移动的顺序不同，则认为两个移动顺序不同。 例如，移动`right, left, right`不同于`left, right, right`，即使两者结束于同一位置。 

我们得到三个整数：

 -`startPos`, 数轴上的起始位置
 -`endPos`, 目标位置
 -`k`，我们必须采取的确切步骤数

 目标是返回有效运动序列的总数模`10^9 + 7`，因为结果可能会变得非常大。 

思考这个问题的一个有用方法是关注**净位移**。 认为：```
distance = endPos - startPos
```每一个正确的举动都有贡献`+1`，每一次向左移动都有贡献`-1`。 

如果我们采取：

 -`r`正确的举动
 -`l`向左移动

 那么：```
r + l = k
r - l = distance
```求解这些方程得出：```
r = (k + distance) / 2
l = (k - distance) / 2
```这立即揭示了一个重要的限制：

 1. 我们必须能够实际达到目标，这意味着`abs(distance) <= k`。 
2.奇偶校验必须匹配，含义`(k + distance)`必须是均匀的。 

如果任一条件不成立，则答案为`0`。 

限制相对较小：```
1 <= startPos, endPos, k <= 1000
```自从`k`至多是`1000`，动态规划和组合方法都是可行的。 然而，暴力枚举所有可能的路径是完全不切实际的，因为路径的数量呈指数增长。 

一些边缘情况可能会导致简单的实现失败。 如果目标距离比可用步数更远，则不可能到达。 同样，奇偶校验不匹配也很重要。 例如，从位置移动`2`到`5`正好在`10`步骤是不可能的，因为奇偶校验不起作用。 另一种边缘情况发生在`startPos == endPos`，其中只有步数为偶数的路径才能返回到同一位置。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是递归地尝试每一个可能的移动序列。 在每一步中，我们可以向左或向右移动，这意味着每一步有两个选择。 

我们可以定义一个递归函数：```
dfs(position, remainingSteps)
```在每次通话中，我们都会分为：

 -`position - 1`-`position + 1`什么时候`remainingSteps == 0`，我们检查当前位置是否等于`endPos`。 

这种方法是正确的，因为它明确地探索了每一个可能的运动序列，并且只计算那些在恰好完成之后到达目标的运动序列。`k`步骤。 

然而，可能性的数量呈指数级增长：```
2^k
```自从`k`可以是`1000`，这太慢了。 

### 最优方法，组合学

 关键的见解是我们**不**关心沿途访问的确切位置。 我们只关心存在多少个左右移动。 

假设我们需要净位移：```
distance = endPos - startPos
```如果我们做`r`正确的动作和`l`向左移动：```
r + l = k
r - l = distance
```由代数可知：```
r = (k + distance) / 2
```Once we know how many right moves are required, the problem becomes:

 > 在`k`总仓位，我们可以通过多少种方式选择正确的移动发生的位置？ 

这只是一个组合问题：```
C(k, r)
```我们计算二项式系数模`10^9 + 7`。 

自从`k <= 1000`，我们可以使用基于帕斯卡三角的动态规划有效地计算组合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^k) | O(2^k) | O(k) | 探索每一种可能的运动顺序 |
 | 最佳| O(k²) | O(k²) | 使用组合数学与帕斯卡三角形 |

 ## 算法演练

 1. 计算所需的位移。 

我们首先计算：```
distance = abs(endPos - startPos)
```我们使用绝对值，因为向左或向右移动是对称的。 
2. 检查是否可以到达目的地。 

有两个条件使得答案不可能：

 -`distance > k`，表示目标距离太远
 -`(k - distance) % 2 != 0`，表示奇偶校验不匹配

 如果任一条件失败，则返回`0`。 
3. 计算所需向右移动的次数。 

自从：```
r = (k + distance) / 2
```我们计算：```
right_moves = (k + distance) // 2
```4. 搭建帕斯卡三角形。 

我们创建一个动态规划表，其中：```
dp[n][r] = C(n, r)
```使用递归式：```
C(n, r) = C(n - 1, r - 1) + C(n - 1, r)
```这是有效的，因为每个组合要么包含或排除当前元素。 
5. 返回最终组合。 

答案变成：```
C(k, right_moves)
```模数`10^9 + 7`。 

### 为什么它有效

 该算法之所以有效，是因为每条有效路径都包含一定数量的左右移动。 一旦这些计数被固定，唯一剩下的问题是正确的动作出现在**哪里**`k`步骤。 每个不同的位置对应一个唯一的路径，并且每个有效路径恰好对应一个位置。 因此，对组合进行计数可以给出有效序列的准确数量。 

## Python 解决方案```python
class Solution:
    def numberOfWays(self, startPos: int, endPos: int, k: int) -> int:
        MOD = 10**9 + 7

        distance = abs(endPos - startPos)

        # Impossible to reach
        if distance > k or (k - distance) % 2 != 0:
            return 0

        right_moves = (k + distance) // 2

        # Pascal's Triangle for combinations
        dp = [[0] * (right_moves + 1) for _ in range(k + 1)]

        for i in range(k + 1):
            dp[i][0] = 1

        for i in range(1, k + 1):
            limit = min(i, right_moves)

            for j in range(1, limit + 1):
                if j == i:
                    dp[i][j] = 1
                else:
                    dp[i][j] = (
                        dp[i - 1][j - 1] +
                        dp[i - 1][j]
                    ) % MOD

        return dp[k][right_moves]
```实现首先计算起始位置和结束位置之间所需的距离。 在进行任何昂贵的计算之前，它会检查不可能性条件。 如果目的地太远或奇偶校验不匹配，函数立即返回`0`。 

接下来，代码计算需要多少次右移动。 由于每条有效路径必须恰好包含这么多正确的移动，因此问题简化为计算二项式系数。 

为了在模算术下有效地计算组合，该实现使用动态编程构建帕斯卡三角形。 第一列初始化为`1`因为：```python
C(n, 0) = 1
```对于每一行，递归关系都会用较小的组合构造较大的组合。 最后，答案存储在`dp[k][right_moves]`被返回。 

## 解决方案```go
func numberOfWays(startPos int, endPos int, k int) int {
	const mod = 1_000_000_007

	distance := endPos - startPos
	if distance < 0 {
		distance = -distance
	}

	// Impossible to reach
	if distance > k || (k-distance)%2 != 0 {
		return 0
	}

	rightMoves := (k + distance) / 2

	// Pascal's Triangle
	dp := make([][]int, k+1)

	for i := 0; i <= k; i++ {
		dp[i] = make([]int, rightMoves+1)
		dp[i][0] = 1
	}

	for i := 1; i <= k; i++ {
		limit := i
		if limit > rightMoves {
			limit = rightMoves
		}

		for j := 1; j <= limit; j++ {
			if j == i {
				dp[i][j] = 1
			} else {
				dp[i][j] = (dp[i-1][j-1] + dp[i-1][j]) % mod
			}
		}
	}

	return dp[k][rightMoves]
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 一个区别是 Go 没有内置的`abs()`函数用于整数，因此我们手动将负值转换为正值。 

动态规划表是使用切片的切片来实现的。 由于需要模运算，因此每次更新都适用`% mod`立即防止溢出并将值保持在范围内。

 ## 边缘情况

 当目的地比可用步数更远时，就会出现一种重要的边缘情况。 例如：```
startPos = 1
endPos = 10
k = 3
```即使每一步都朝着正确的方向前进，也不可能到达目的地。 幼稚的实现可能仍然会尝试不必要的动态编程。 我们的实现立即处理这个问题：```
distance > k
```并返回`0`。 

另一个微妙的边缘情况涉及奇偶校验不匹配。 认为：```
startPos = 2
endPos = 5
k = 10
```所需位移为奇数 (`3`)，但总移动次数是偶数 (`10`）。 由于每次不必要的移动都必须取消左右对，因此奇偶校验必须匹配。 该实现使用以下方法正确检测到这一点：```
(k - distance) % 2 != 0
```并返回`0`。 

第三个重要的情况发生在`startPos == endPos`。 要返回到相同位置，每次向右移动最终都必须被向左移动取消。 因此，只有偶数值`k`是有效的。 例如：```
startPos = 5
endPos = 5
k = 4
```有效，但是：```
startPos = 5
endPos = 5
k = 3
```没有。 奇偶校验自然可以处理这种情况，而不需要任何特殊的逻辑。
