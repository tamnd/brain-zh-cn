[LeetCode 问题 2454](https://leetcode.com/problems/next-greater-element-iv/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、堆栈、排序、堆（优先级队列）、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们为数组中的每个元素计算其右侧的“第二个较大元素”。 

对于一个索引`i`，我们对位于之后的元素感兴趣`i`。 Among those elements, we only care about values strictly greater than`nums[i]`。 

第二个更大的元素的定义非常精确：

 - 我们需要一个索引`j > i`-`nums[j] > nums[i]`- 之间`i`和`j`，必须恰好有一个元素大于`nums[i]`另一种思考这个问题的方法是：

 - 查找右侧的所有元素`nums[i]`比它更大的
 - 按位置排序
 - 第二个更大的元素只是遇到的第二个这样的元素

 例如，考虑：```
nums = [2,4,0,9,6]
```为了`2`在索引处`0`:

 - First greater element is`4`- 第二个更大的元素是`9`所以索引的答案`0`是`9`。 

为了`0`在索引处`2`:

 - 右边更大的元素是`9`和`6`- 第二个遇到的是`6`所以答案是`6`。 

如果右侧存在的较大元素少于两个，则答案为`-1`。 

约束条件很重要：

 -`nums.length`可以达到`100000`- 二次解的性能可达`10^10`最坏情况下的操作，速度太慢

 这立即告诉我们，我们需要一个近线性的解决方案，通常`O(n)`或者`O(n log n)`。 

一些边缘情况很重要：

 - 具有所有相等值的数组，例如`[3,3,3]`- 严格递减数组，不存在更大的元素
 - 严格递增数组，其中存在许多第二大元素
 - 重复值，因为条件要求严格更大的值
 - 非常大的阵列，排除了嵌套扫描方法

 该问题保证：

 - 所有数字均为非负数
 - 数组长度至少为`1`- 值适合标准整数类型

 ## 方法

 ### 蛮力方法

 最直接的解决方案是对每个索引进行独立处理。 

对于每个索引`i`:

 1. 向右扫描所有元素
 2. 计算有多少个元素大于`nums[i]`3. 一旦找到第二个更大的元素，记录它
 4. 如果扫描在找到两个更大的元素之前完成，则返回`-1`例如：```
nums = [2,4,0,9,6]
```对于索引`0`:

 -`4 > 2`, count = 1
 -`0`被忽略
 -`9 > 2`，计数 = 2，答案 = 9

 This works because it directly follows the definition of the problem.

 However, its performance is poor.

 对于每个元素，我们可以扫描数组的几乎整个剩余部分。 和`n = 100000`，这变得太慢了。 

### 最佳方法

 关键的观察是我们实际上不需要重复地重新扫描数组。 

这个问题类似于经典的“下一个更大元素”问题，通常用单调堆栈来解决。 然而，这里我们需要第二个更大的元素，而不是第一个。 

重要的见解是：

 - 一些元素仍在等待它们的第一个更大的元素
 - 一些元素已经找到了它们的第一个更大元素，现在正在等待它们的第二个更大元素

 我们可以分别跟踪这两个状态。 

我们使用：

 - 等待第一个更大元素的元素的单调递减堆栈
 - 已经找到第一个更大元素并且现在正在等待第二个元素的另一种结构

 优雅的解决方案使用：

 - 称为递减堆栈`first_stack`- 另一个递减堆栈称为`second_stack`当我们处理每个数字时：

 - 元素弹出`second_stack`现在已经找到了第二个更大的元素
 - 元素弹出`first_stack`刚刚找到了他们的第一个更大的元素，所以他们进入`second_stack`这使得每个元素仅在该过程中移动少量次，从而导致线性复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 扫描右侧的每个索引 |
 | 最佳 | O(n) | O(n) | 使用两个单调堆栈 |

 ## 算法演练

 ### 最优二栈算法

 1. 初始化结果数组`-1`。 

每个索引默认为`-1`因为有些元素可能永远找不到第二个更大的元素。 
2. 创建两个堆栈。 

第一个堆栈存储等待其第一个较大元素的索引。 

第二个堆栈存储已经找到其第一个较大元素并且现在正在等待其第二个较大元素的索引。 
3. 从左到右迭代数组。 

在每个位置，将当前值视为较早索引的可能更大元素。 
4. 首先，处理第二个堆栈。 

而当前数字大于中顶部索引表示的值`second_stack`，我们找到了该索引的第二个更大的元素。 

将当前值记录在答案数组中。 
5. 接下来，处理第一个堆栈。 

而当前数字大于中顶部索引表示的值`first_stack`，这些指数现在已经找到了第一个更大的元素。 

Remove them from`first_stack`。 
6. Transfer those removed indices into`second_stack`。 

这意味着他们现在正在等待第二个更大的元素。 

传输顺序很重要，因为我们希望正确保留单调行为。 
7. 将当前索引压入`first_stack`。 

当前元素还没有找到第一个更大的元素。 
8. 继续，直到处理完所有元素。 
9. 返回答案数组。 

### 为什么它有效

 该算法保持了两个明显的不变量：

 -`first_stack`包含尚未遇到任何更大元素的索引
 -`second_stack`包含恰好遇到一个更大元素的索引

 当新值到达时：

 - 从中删除的任何索引`second_stack`现在已经看到了两个更大的元素，所以当前值就是它的答案
 - 从中删除的任何索引`first_stack`现在已经看到了它的第一个更大的元素，所以它转变为`second_stack`

Each index moves through the states in order:

```
waiting for first greater
→ waiting for second greater
→ completed
```由于每个索引仅被压入和弹出固定次数，因此总工作量是线性的。 

## Python 解决方案```python
from typing import List

class Solution:
    def secondGreaterElement(self, nums: List[int]) -> List[int]:
        n = len(nums)

        answer = [-1] * n

        first_stack = []
        second_stack = []

        for current_index, current_value in enumerate(nums):

            # Resolve second greater elements
            while second_stack and nums[second_stack[-1]] < current_value:
                index = second_stack.pop()
                answer[index] = current_value

            # Elements that just found their first greater element
            moved = []

            while first_stack and nums[first_stack[-1]] < current_value:
                moved.append(first_stack.pop())

            # Preserve correct order when moving
            while moved:
                second_stack.append(moved.pop())

            # Current element waits for first greater
            first_stack.append(current_index)

        return answer
```该实现遵循前面描述的确切状态转换。 

这`answer`数组初始化为`-1`，它会自动处理永远找不到第二个更大值的元素。`first_stack`存储等待其第一个更大元素的索引。 堆栈按值的递减顺序维护。 

每当当前数字大于顶部元素时`first_stack`, those indices have now encountered their first greater element. 它们被移除并暂时存储在`moved`。 

临时的`moved`数组很重要，因为插入的顺序`second_stack`很重要。 颠倒顺序可以正确保留单调性。`second_stack`contains indices that already found one greater element. When the current value exceeds the top of this stack, the current value becomes the second greater element for that index.

 Every index is pushed and popped at most once from each stack, which guarantees linear runtime.

 ## 解决方案```go
func secondGreaterElement(nums []int) []int {
	n := len(nums)

	answer := make([]int, n)

	for i := 0; i < n; i++ {
		answer[i] = -1
	}

	firstStack := []int{}
	secondStack := []int{}

	for currentIndex, currentValue := range nums {

		// Resolve second greater elements
		for len(secondStack) > 0 &&
			nums[secondStack[len(secondStack)-1]] < currentValue {

			index := secondStack[len(secondStack)-1]
			secondStack = secondStack[:len(secondStack)-1]

			answer[index] = currentValue
		}

		moved := []int{}

		// Resolve first greater elements
		for len(firstStack) > 0 &&
			nums[firstStack[len(firstStack)-1]] < currentValue {

			index := firstStack[len(firstStack)-1]
			firstStack = firstStack[:len(firstStack)-1]

			moved = append(moved, index)
		}

		// Move into second stack in reverse order
		for len(moved) > 0 {
			secondStack = append(secondStack, moved[len(moved)-1])
			moved = moved[:len(moved)-1]
		}

		firstStack = append(firstStack, currentIndex)
	}

	return answer
}
```Go 实现密切反映了 Python 逻辑。 

Slices are used as stacks. 追加会推送一个元素，而重新切片会删除顶部。 

结果数组必须显式初始化为`-1`因为 Go 整数切片默认为`0`。 

There are no integer overflow concerns because the constraints fit within Go's standard`int`类型。

 ## 边缘情况

 ### Arrays With Duplicate Values

 比较必须严格大于，而不是大于或等于。 

例如：```
[3,3,3]
```没有一个元素大于另一个，所以每个答案都是`-1`。 

一个常见的错误是意外使用`<=`而不是`<`比较堆栈元素时。 该实现正确地使用了严格的不等式。 

### 严格递减数组

 考虑：```
[5,4,3,2,1]
```没有任何元素会遇到甚至第一个更大的值。 

This means all indices remain in`first_stack`直到最后，结果完全保持不变`-1`。 

该实现自然地处理了这个问题，因为未解析的条目永远不会被覆盖。 

### 只有一个更大值的元素

 考虑：```
[1,2]
```元素`1`它的右侧只有一个更大的值，而不是两个。 

有缺陷的实现可能会错误地将第一个较大的值视为答案。 

该解决方案明确区分：

 - 等待第一个更大的
 - 等待第二个更大的

 一个元素只有在两种状态转换后才会被分配一个答案。 

### 大型递增数组

 对于像这样的数组：```
[1,2,3,4,5,...]
```许多索引在堆栈之间快速转换。 

一个简单的嵌套循环将变成二次循环。 

单调堆栈方法确保每个索引仅在系统中移动一次，即使对于约束允许的最大输入也能保持线性复杂性。
