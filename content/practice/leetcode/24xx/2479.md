[LeetCode 问题 2479](https://leetcode.com/problems/maximum-xor-of-two-non-overlapping-subtrees/)

 **难度：** 🔴难
 **主题：** 树、深度优先搜索、图论、Trie

 ## 解决方案

 ## 问题理解

 这个问题给了我们一棵有根的树`n`节点，以节点为根`0`。 每个节点都有一个数值，子树的总和定义为该子树内所有节点值的总和，包括子树的根和所有后代。 

我们被要求选择两棵不重叠的子树，这意味着它们根本不共享节点。 对于每对有效的非重叠子树，我们计算：$$\text{subtreeSum}_1 \oplus \text{subtreeSum}_2$$在哪里`⊕`是按位异或运算符。 

我们的目标是最大化这个异或值。 

输入包括：

 -`n`, 节点数
 -`edges`，描述无向树
 -`values`，分配给每个节点的值

 因为树的根是`0`，每个节点恰好定义一个子树，即它本身以及从它向下可达的所有后代。 

约束条件极其重要：

 -`n`可以大到`5 * 10^4`- 子树总和可能变得非常大，因为节点值可以达到`10^9`- 所有子树对的简单成对比较会太慢

 主要挑战是有效确定：

 1. 每个节点的子树和
 2、两棵子树是否重叠
 3. 所有有效对之间的最大异或

 一些边缘情况很重要：

 - 链状树可能会使 Python 中的递归深度变得危险
 - 可能根本不存在两棵不相交的子树，例如长度为2的路径
 - 大型子树和需要 64 位整数处理
 - 两个兄弟子树始终不重叠
 - 祖先-后代子树对总是重叠的，不能被考虑

 关键的困难是有效检查非重叠，同时最大化异或。 

## 方法

 ### 蛮力方法

 暴力解决方案首先计算每个节点的子树和。 

之后，我们考虑每对节点`(u, v)`并判断它们的子树是否重叠。 如果一个节点是另一个节点的祖先，则两棵子树重叠。 

如果它们不重叠，我们计算：$$\text{subtreeSum}[u] \oplus \text{subtreeSum}[v]$$并跟踪最大值。 

为了有效地确定祖先关系，我们可以运行 DFS Euler 巡演并记录进入和退出时间：

 -`u`是的祖先`v`如果：$$tin[u] \le tin[v] \le tout[u]$$即使进行了有效的重叠检查，仍然存在`O(n^2)`子树对。 和`n = 5 * 10^4`，这变得太慢了。 

### 最佳方法

 关键的见解是 XOR 最大化问题通常使用二进制 trie 来解决。 

如果我们以仔细的 DFS 顺序处理子树和，我们可以确保 trie 只包含来自其子树不与当前节点重叠的节点的子树和。 

重要的观察是：

 - 当探索节点的子节点时，先前处理的同级子树保证是不相交的
 - 后代子树重叠，因此不能太早插入

 我们执行 DFS 并一次处理一个子进程。 

对于每个子子树：

 1. 根据已经存储在 trie 中的总和查询该子节点内的所有子树总和
 2. trie 只包含先前完成的兄弟子树的子树和
 3. 因此保证每个查询对不重叠
 4、查询完毕后，将从此child开始的所有子树和插入到trie中

 这完全避免了显式重叠检查。 

trie 允许我们找到一个数的最大异或伙伴`O(log MAX_VALUE)`时间。 

由于子树和大约可容纳 46 位：$$5 \times 10^4 \times 10^9 = 5 \times 10^{13}$$每个 trie 操作大约需要 46 个步骤。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 检查每个子树对 |
 | 最佳 | O(n log M) | O(n log M) | O(n log M) | O(n log M) | 使用 DFS 排序和二进制 trie |

 这里，`M`是最大子树和值。 

## 算法演练

 ### 第 1 步：构建树

 将边列表转换为邻接列表。 

这允许从根开始进行高效的 DFS 遍历。 

### 步骤 2：计算所有子树总和

 从节点开始运行 DFS`0`。 

对于每个节点：

 1、从自身价值入手
 2. 递归计算所有子项的总和
 3. 将子项总和添加到当前总和中
 4. 将结果存储在`subtree_sum[node]`最后，每个节点都知道其子树的总和。 

### 步骤 3：创建二进制 Trie

 trie 存储子树和的二进制表示。 

每个 trie 节点包含：

 - 孩子一点`0`- 孩子一点`1`最大化异或：

 - 对于每一位，我们更喜欢采用相反的位（如果有）

 这种贪婪的位选择最大化了 XOR 值。 

### 步骤 4：再次进行 DFS 处理不重叠的子树

 我们现在执行另一个 DFS。 

对于一个节点：

 1、对孩子进行一一处理
 2. 在将子树插入到 trie 之前，根据当前 trie 查询该子树内的每个子树总和
 3. trie 只包含来自较早子节点的完整兄弟子树
 4. 因此每个异或候选都是有效的

 查询后：

 - 将来自该子节点的每个子树总和插入到 trie 中

 这种增量排序可以自动保证不重叠。 

### 步骤5：查询最大异或

 对于每个子树总和：

 1. 从最高到最低遍历 trie 位
 2. 尽可能选择相反的位
 3. 贪心构造最大异或值

 每当发现更大的 XOR 时就更新全局答案。 

### 第 6 步：返回最终答案

 如果不存在有效对，则答案保持不变`0`。 

否则返回找到的最大 XOR。 

### 为什么它有效

 正确性来自于DFS处理顺序。 

处理子子树时，特里树仅包含先前完成的同级子树的子树和。 树中的兄弟子树总是不相交的，因为它们属于不同的分支。 

由于直到查询后才会插入后代子树，因此永远不会考虑重叠的祖先-后代对。 

二叉树保证对于每个子树和，我们有效地找到最大化异或的插入子树和。 

因此，每个候选者都是有效的，并且返回所有有效候选者中的最大值。 

## Python 解决方案```python
from typing import List
import sys

sys.setrecursionlimit(1 << 20)

class TrieNode:
    def __init__(self):
        self.children = {}

class Trie:
    def __init__(self):
        self.root = TrieNode()
        self.HIGH_BIT = 50

    def insert(self, num: int) -> None:
        node = self.root

        for bit in range(self.HIGH_BIT, -1, -1):
            current = (num >> bit) & 1

            if current not in node.children:
                node.children[current] = TrieNode()

            node = node.children[current]

    def query(self, num: int) -> int:
        node = self.root

        if not node.children:
            return 0

        result = 0

        for bit in range(self.HIGH_BIT, -1, -1):
            current = (num >> bit) & 1
            opposite = 1 - current

            if opposite in node.children:
                result |= (1 << bit)
                node = node.children[opposite]
            else:
                node = node.children[current]

        return result

class Solution:
    def maxXor(self, n: int, edges: List[List[int]], values: List[int]) -> int:
        graph = [[] for _ in range(n)]

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)

        subtree_sum = [0] * n
        subtree_nodes = [[] for _ in range(n)]

        def compute_subtree(node: int, parent: int) -> int:
            total = values[node]
            subtree_nodes[node].append(node)

            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                total += compute_subtree(neighbor, node)
                subtree_nodes[node].extend(subtree_nodes[neighbor])

            subtree_sum[node] = total
            return total

        compute_subtree(0, -1)

        trie = Trie()
        answer = 0

        def process(node: int, parent: int) -> None:
            nonlocal answer

            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                for descendant in subtree_nodes[neighbor]:
                    current_sum = subtree_sum[descendant]
                    answer = max(answer, trie.query(current_sum))

                for descendant in subtree_nodes[neighbor]:
                    trie.insert(subtree_sum[descendant])

                process(neighbor, node)

        process(0, -1)

        return answer
```实现首先构建树的邻接表表示。 

第一个 DFS 计算子树和。 在此遍历过程中，我们还收集属于每个子树的所有后代。 这允许稍后迭代分支内的每个子树总和。 

trie 实现支持两种操作：

 -`insert`，它逐位存储子树和
 -`query`，贪婪地搜索产生最大 XOR 的数字

 第二个 DFS 是非重叠逻辑出现的地方。 

对于每个子子树：

 1. 根据现有的 trie 查询所有子树和
 2. 之后插入子树和

 这种排序至关重要，因为它确保 trie 只包含先前完成的同级分支的子树和。 

每当发现更大的 XOR 值时，答案就会不断更新。 

## 解决方案```go
package main

type TrieNode struct {
	children [2]*TrieNode
}

type Trie struct {
	root    *TrieNode
	highBit int
}

func NewTrie() *Trie {
	return &Trie{
		root:    &TrieNode{},
		highBit: 50,
	}
}

func (t *Trie) Insert(num int64) {
	node := t.root

	for bit := t.highBit; bit >= 0; bit-- {
		current := (num >> bit) & 1

		if node.children[current] == nil {
			node.children[current] = &TrieNode{}
		}

		node = node.children[current]
	}
}

func (t *Trie) Query(num int64) int64 {
	node := t.root

	if node.children[0] == nil && node.children[1] == nil {
		return 0
	}

	var result int64 = 0

	for bit := t.highBit; bit >= 0; bit-- {
		current := (num >> bit) & 1
		opposite := 1 - current

		if node.children[opposite] != nil {
			result |= (1 << bit)
			node = node.children[opposite]
		} else {
			node = node.children[current]
		}
	}

	return result
}

func maxXor(n int, edges [][]int, values []int) int64 {
	graph := make([][]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	subtreeSum := make([]int64, n)
	subtreeNodes := make([][]int, n)

	var computeSubtree func(int, int) int64

	computeSubtree = func(node int, parent int) int64 {
		total := int64(values[node])
		subtreeNodes[node] = append(subtreeNodes[node], node)

		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			total += computeSubtree(neighbor, node)
			subtreeNodes[node] = append(subtreeNodes[node], subtreeNodes[neighbor]...)
		}

		subtreeSum[node] = total
		return total
	}

	computeSubtree(0, -1)

	trie := NewTrie()
	var answer int64 = 0

	var process func(int, int)

	process = func(node int, parent int) {
		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			for _, descendant := range subtreeNodes[neighbor] {
				currentSum := subtreeSum[descendant]
				answer = max64(answer, trie.Query(currentSum))
			}

			for _, descendant := range subtreeNodes[neighbor] {
				trie.Insert(subtreeSum[descendant])
			}

			process(neighbor, node)
		}
	}

	process(0, -1)

	return answer
}

func max64(a, b int64) int64 {
	if a > b {
		return a
	}
	return b
}
```Go 的实现紧密遵循 Python 逻辑。 

主要区别在于显式使用`int64`因为子树总和可能超过 32 位整数限制。 

Go 数组是固定大小的，因此 trie 子节点存储为：```go
children [2]*TrieNode
```而不是 Python 字典。 

递归 DFS 行为在其他方面是相同的。

 ## 边缘情况

 ### 链状树

 线性链是一种重要的边缘情况，因为每个子树都与其他子树重叠。 没有兄弟分支，因此没有两个子树可以不相交。 

幼稚的实现可能会错误地比较后代子树并产生无效的答案。 此解决方案中的 DFS 排序可以防止这种情况发生，因为在查询期间后代子树永远不会同时出现在 trie 中。 

### 非常大的子树和

 由于节点值可能达到`10^9`并且可以有`5 * 10^4`节点，子树和可能会变得非常大。 

该实现通过以下方式安全地处理这个问题：

 - 使用Python整数，它是任意精度的
 - 使用`int64`在围棋中

 trie 使用 51 位来安全地表示所有可能的和。 

### 只有一个分支点的树

 考虑一棵树，其中只有一个节点有两个子节点，其余节点形成链。 

这很容易暴露特里结构意外包含重叠后代子树的错误。 

该解决方案通过仅在当前同级子树的所有查询完成后才插入子树总和来避免这种情况。 这保证了 trie 中只存在已经完成的兄弟分支。
