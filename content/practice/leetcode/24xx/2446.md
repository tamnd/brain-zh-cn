[LeetCode 问题 2446](https://leetcode.com/problems/define-if-two-events-have-conflict/)

 **难度：** 🟢简单
 **主题：** 数组、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定同一天的两个事件在时间上是否重叠。 每个事件都以一对字符串的形式给出`HH:MM`表示开始和结束时间的格式。 输出应该是一个布尔值：`true`两个事件之间是否有重叠，以及`false`否则。 

输入保证每个事件的开始时间始终小于或等于结束时间，并且时间格式正确，从而简化了验证。 需要注意的边缘情况包括完全接触其端点的事件，例如`["01:00","02:00"]`和`["02:00","03:00"]`，这应该算作重叠，因为问题将事件定义为包含的。 另一种边缘情况是一个事件完全包含在另一个事件中。 

约束是最小的——只有两个固定长度数组的事件——所以效率不是主要考虑的问题。 挑战在于正确比较时间。 

## 方法

 暴力方法将涉及生成每个事件涵盖的所有分钟并检查是否有任何交叉点。 虽然正确，但由于输入量较小，这种方法不必要地复杂。 它需要将每个时间字符串解析为分钟，然后迭代可能长达 1440 分钟的一整天。 这可行，但太过分了。 

最佳方法基于一个简单的观察：两个间隔`[start1, end1]`和`[start2, end2]`重叠当且仅当`start1 <= end2`和`start2 <= end1`。 这是可行的，因为如果一个事件在另一事件结束之后开始，则不存在交集，而在所有其他情况下，则存在交集。 这种方法避免了不必要的迭代并直接比较时间边界。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(1) | O(1) | O(1) | O(1) | 将时间转换为分钟并迭代以查找重叠； 对于两个事件来说是不必要的 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用字符串比较或分钟转换直接比较开始和结束时间 |

 ## 算法演练

 1. 提取两个事件的开始和结束时间。 
2. 比较第一个事件的开始时间和第二个事件的结束时间。 
3. 将第二个事件的开始时间与第一个事件的结束时间进行比较。 
4. 如果两个条件都满足`start1 <= end2`和`start2 <= end1`保持、返回`true`。 
5.否则返回`false`。 

为什么它有效：这里的不变性是，只有当一个间隔严格地在另一个结束之后开始时，间隔才不会重叠。 检查这两个条件可确保检测到任何部分或完全重叠，包括端点处的触摸。 

## Python 解决方案```python
from typing import List

class Solution:
    def haveConflict(self, event1: List[str], event2: List[str]) -> bool:
        start1, end1 = event1
        start2, end2 = event2
        return start1 <= end2 and start2 <= end1
```该实现直接解包事件时间并使用字符串比较。 在`HH:MM`格式，字符串比较可以正确工作，因为这些字符串的字典顺序与时间的时间顺序相匹配。 这避免了任何整数转换，使解决方案保持简单高效。 

## 解决方案```go
func haveConflict(event1 []string, event2 []string) bool {
    start1, end1 := event1[0], event1[1]
    start2, end2 := event2[0], event2[1]
    return start1 <= end2 && start2 <= end1
}
```Go 解决方案反映了 Python 解决方案。 Go字符串可以直接比较，`<=`运算符正确工作于`HH:MM`格式。 这种方法很简洁，并且避免了将字符串解析为整数。 

## 工作示例

 **示例1：**```

```**示例2：**```

 ## 边缘情况

 **情况 1：开始和结束时间完全相同：** 在同一时刻开始和结束的两个事件应视为重叠。 该算法处理这个问题是因为这两个条件`start1 <= end2`和`start2 <= end1`是真的。 

**情况 2：事件在端点处接触：** 如果一个事件恰好在另一个事件开始时结束，则由于包容性定义，这将被视为冲突。 该算法处理这个问题是因为`<=`比较体现了平等。 

**情况 3：最小或最大时间值：** 从“00:00”开始或在“23:59”结束的事件有效。 该算法无需任何转换即可工作，因为字符串比较`HH:MM`格式遵循时间顺序，因此不需要对日期边界进行特殊处理。
