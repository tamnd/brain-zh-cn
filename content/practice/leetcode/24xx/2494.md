[LeetCode 问题 2494](https://leetcode.com/problems/merge-overlapping-events-in-the-same-hall/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们将同一大厅中重叠的事件合并起来。 的每一行`HallEvents`表代表特定大厅中的事件`start_day`和一个`end_day`。 如果事件至少有一天相同，则被视为重叠。 目标是返回合并事件表，以便同一大厅中的两个事件不会重叠。 

输入是一个包含可能重复行的关系表。 输出是一个合并事件表，其中解决了每个大厅内的重叠问题。 主要限制包括：活动是特定于大厅的，可能存在重复，并且日期包括在内。 边缘情况包括连续事件（其中一个事件的结束日期是另一个事件的开始日期）和完全包含在另一个事件中的事件。 

了解这些限制清楚地表明我们必须独立处理每个大厅并考虑包容性重叠。 

## 方法

 蛮力方法将涉及将大厅中的每个事件与同一大厅中的每个其他事件进行比较。 如果它们重叠，我们将它们合并到一个新事件中并重复，直到没有重叠为止。 这在逻辑上可行，但效率低下，每个大厅可能进行 O(n²) 次比较，这对于大型数据集来说很慢。 

最佳方法依赖于对事件进行排序`start_day`每个大厅。 排序后，我们可以迭代事件，如果连续事件重叠，则合并它们。 排序确保我们每个大厅只需要一次通过，因为任何重叠都必须与下一个事件或一系列后续事件发生。 这降低了复杂性并简化了逻辑。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 将每个事件与同一大厅中的每个其他事件进行比较，迭代合并 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 按每个大厅的开始日期对活动进行排序并一次性合并 |

 ## 算法演练

 1. 将所有事件分组`hall_id`独立处理每个大厅。 这确保了仅在同一大厅内考虑重叠。 
2. 对于每个大厅，按以下顺序对其事件进行排序`start_day`。 排序使我们能够保证连续事件不会发生任何重叠，从而简化合并。 
3. 初始化一个空列表来保存当前大厅的合并事件。 
4. 迭代排序的事件。 如果合并事件列表为空，则添加第一个事件。 否则，比较`start_day`当前事件的`end_day`最后合并事件的。 
5. 如果当前事件与最后合并的事件（包括）重叠或触及，则更新`end_day`最后合并事件的数量为最后合并事件的最大值`end_day`和当前的`end_day`。 
6. 如果没有重叠，则将当前事件追加为新的合并事件。 
7. 处理完大厅中的所有事件后，将合并结果添加到最终输出列表中。 
8. 对每个大厅重复步骤 2-7，并返回合并结果。 

**为什么有效：** 排序保证重叠事件是连续的。 通过始终扩展`end_day`当重叠发生时，我们确保所有重叠事件都正确组合。 非重叠事件自然会启动一个新的合并事件，从而保持正确性。 

## Python 解决方案```python
from typing import List
import collections

class Solution:
    def mergeEvents(self, hallEvents: List[List[str]]) -> List[List[str]]:
        # Group events by hall_id
        events_by_hall = collections.defaultdict(list)
        for hall_id, start_day, end_day in hallEvents:
            events_by_hall[hall_id].append([start_day, end_day])
        
        merged_result = []
        for hall_id, events in events_by_hall.items():
            # Sort events by start_day
            events.sort(key=lambda x: x[0])
            merged = []
            for start, end in events:
                if not merged or merged[-1][1] < start:
                    merged.append([start, end])
                else:
                    merged[-1][1] = max(merged[-1][1], end)
            for start, end in merged:
                merged_result.append([hall_id, start, end])
        
        return merged_result
```**说明：** 首先，我们使用字典按大厅对事件进行分组。 排序确保我们每个大厅只需要一次通过即可合并重叠的间隔。 合并逻辑更新`end_day`发生重叠时最后一个间隔的值，如果没有重叠则附加一个新间隔。 最后，我们用相应的事件重建合并事件`hall_id`。 

## 解决方案```go
package main

import (
    "sort"
)

type Event struct {
    hallID   int
    startDay string
    endDay   string
}

func mergeEvents(hallEvents [][]interface{}) [][]interface{} {
    eventsByHall := make(map[int][][2]string)
    
    for _, event := range hallEvents {
        hallID := event[0].(int)
        startDay := event[1].(string)
        endDay := event[2].(string)
        eventsByHall[hallID] = append(eventsByHall[hallID], [2]string{startDay, endDay})
    }
    
    result := [][]interface{}{}
    
    for hallID, events := range eventsByHall {
        sort.Slice(events, func(i, j int) bool {
            return events[i][0] < events[j][0]
        })
        
        merged := [][2]string{}
        for _, e := range events {
            if len(merged) == 0 || merged[len(merged)-1][1] < e[0] {
                merged = append(merged, e)
            } else {
                if e[1] > merged[len(merged)-1][1] {
                    merged[len(merged)-1][1] = e[1]
                }
            }
        }
        
        for _, m := range merged {
            result = append(result, []interface{}{hallID, m[0], m[1]})
        }
    }
    
    return result
}
```**说明：** Go 版本反映了 Python 方法。 事件在地图中分组并按以下顺序排序`startDay`。 我们通过将当前事件与合并切片中的最后一个事件进行比较来合并重叠。 切片和类型断言的使用反映了 Go 的类型系统，与 Python 的动态类型略有不同。 

## 工作示例

 **示例1：**

 输入大厅1：```
["2023-01-13", "2023-01-14"]
["2023-01-14", "2023-01-17"]
["2023-01-18", "2023-01-25"]
```排序给出相同的顺序。 合并：

 1. 第一个区间 ["2023-01-13", "2023-01-14"] → 添加到合并中
 2.第二个区间 ["2023-01-14", "2023-01-17"] → 重叠，合并到 ["2023-01-13", "2023-01-17"]
 3. 第三个区间 ["2023-01-18", "2023-01-25"] → 无重叠，作为新添加

 结果：[“2023-01-13”，“2023-01-17”]，[“2023-01-18”，“2023-01-25”]

 2号馆：```
["2022-12-09", "2022-12-23"]
["2022-12-13", "2022-12-17"]
```合并到 ["2022-12-09", "2022-12-23"]

 3号馆：单间隔不变。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 每个大厅的活动排序占主导地位； n 是事件总数 |
 | 空间| O(n) | 用于存储分组事件和合并结果 |

 排序对于确保线性合并是必要的。 按大厅分组可确保正确性，并且不会超过 O(n) 额外空间。
