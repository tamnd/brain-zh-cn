[LeetCode 问题 2424](https://leetcode.com/problems/longest-uploaded-prefix/)

 **难度：** 🟡 中等
 **主题：** 哈希表、二分查找、并查、设计、二叉索引树、线段树、堆（优先级队列）、有序集

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个数据结构，跟踪上传的视频并持续报告最长上传前缀的长度。 

上传视频的前缀意味着每个视频来自`1`通过`i`已经上传。 目标是返回最大此类`i`。 

例如，假设上传的视频是：```
[1, 2, 3]
```那么最长上传的前缀是`3`，因为视频`1`,`2`， 和`3`都在场。 

如果上传的视频是：```
[2, 3, 4]
```那么最长上传的前缀是`0`，因为视频`1`缺失，因此没有从以下位置开始的有效前缀`1`。 

输入流由上传操作组成，其中每个上传的视频编号都是唯一的并且位于范围内`1`到`n`。 

该类必须支持三种操作：

 1. 初始化`n`2. Uploading a video
 3.查询最长上传前缀

 约束条件很重要：

 -`n`可以大到`100000`- 最多可以有`200000`total calls
 - 视频编号不同

 这些限制告诉我们，低效的扫描方法可能会变得太慢。 我们需要接近恒定时间的操作。 

一个重要的观察结果是上传以任意顺序到达。 我们不能假设视频是按顺序上传的。 

例如：```
upload(5)
upload(1)
upload(2)
upload(4)
upload(3)
```最长的前缀变化如下：```
0 -> 1 -> 2 -> 2 -> 5
```主要挑战是有效跟踪序列中第一个丢失的视频。 

重要的边缘情况包括：

 - 上传视频完全乱序
 - 视频前查询`1`已上传
 - 上传所有视频
 - 尽可能小的输入，其中`n = 1`该问题保证上传是不同的，因此我们不需要处理重复上传。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是维护一组上传的视频。 每当`longest()`被称为，我们从`1`并向上扫描，直到找到第一个丢失的视频。 

例如：```
Uploaded: {1, 2, 3, 5}
```我们检查：```
1 -> present
2 -> present
3 -> present
4 -> missing
```所以答案是`3`。 

这种方法是正确的，因为最长上传前缀的定义直接需要检查连续存在`1`。 

然而，当许多人这样做时，这会变得低效`longest()`拨打电话。 在最坏的情况下，每个查询可能会扫描最多`n`元素。 

高达`200000`操作，这可能导致时间复杂度接近`O(n * q)`，这太慢了。 

### 最佳方法

 关键的观察是最长的上传前缀仅向前移动，而不会向后移动。 

假设当前最长前缀为：```
current = 3
```这意味着视频`1`,`2`， 和`3`已上传。 

当新视频上传时，我们唯一需要检查的是视频是否`4`现在可用。 如果是，我们可以尽可能向前扩展前缀。 

这建议维持：

 - 用于跟踪上传视频的布尔数组或哈希集
 - 代表当前最长前缀的指针

 每当上传视频时：

 1. 将其标记为已上传
 2. 当序列中的下一个视频存在时，向前移动指针

 每个视频在指针前进期间最多处理一次，从而使所有操作的总工作呈线性。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 |`O(n)`每`longest()`|`O(n)`| 反复扫描自`1`向上|
 | 最佳|`O(1)`每次操作摊销|`O(n)`| 使用移动指针并上传跟踪 |

 ## 算法演练

 ### 最优算法

 1. 创建一个布尔数组，名为`uploaded`尺寸的`n + 2`。 

我们使用这个数组来快速判断视频是否已经上传。 指数`i`对应视频`i`。 
2. 维护一个整数指针，称为`longest_prefix`。 

这存储了当前已知的已完全上传的最大前缀。 
3. 最初设置：```
longest_prefix = 0
```由于尚未上传视频，因此最长前缀长度为零。 
4. 什么时候`upload(video)`称为：

 - 将视频标记为已上传：```
uploaded[video] = True
```- 然后反复检查下一个需要的视频是否存在：```
while uploaded[longest_prefix + 1]:
    longest_prefix += 1
```5. 什么时候`longest()`称为：

 - 只需返回`longest_prefix`### 为什么它有效

 不变的是所有视频来自`1`通过`longest_prefix`已上传，并且`longest_prefix + 1`未上传。 

每当发生新上传时，唯一可能的变化是前缀可以向前扩展。 由于指针仅向前移动，并且每个视频最多使指针前进一次，因此该算法保持高效，同时始终保持正确的前缀长度。 

## Python 解决方案```python
class LUPrefix:

    def __init__(self, n: int):
        self.uploaded = [False] * (n + 2)
        self.longest_prefix = 0

    def upload(self, video: int) -> None:
        self.uploaded[video] = True

        while self.uploaded[self.longest_prefix + 1]:
            self.longest_prefix += 1

    def longest(self) -> int:
        return self.longest_prefix

# Your LUPrefix object will be instantiated and called as such:
# obj = LUPrefix(n)
# obj.upload(video)
# param_2 = obj.longest()
```该实现使用一个名为的布尔数组`uploaded`记录每个视频是否已上传。 

数组大小为`n + 2`这样检查`longest_prefix + 1`上传所有视频时绝不会导致越界错误。 

变量`longest_prefix`存储当前有效的前缀长度。 

里面`upload`，上传的视频被标记为`True`。 然后`while`只要下一个所需视频存在，循环就会尝试向前扩展前缀。 

重要的效率细节是`longest_prefix`永远不会减少。 每个视频在整个执行过程中最多只对指针前进一次做出贡献。 

这`longest()`方法变得非常高效，因为它只返回已经维护的前缀长度。 

## 解决方案```go
type LUPrefix struct {
	uploaded      []bool
	longestPrefix int
}

func Constructor(n int) LUPrefix {
	return LUPrefix{
		uploaded:      make([]bool, n+2),
		longestPrefix: 0,
	}
}

func (this *LUPrefix) Upload(video int) {
	this.uploaded[video] = true

	for this.uploaded[this.longestPrefix+1] {
		this.longestPrefix++
	}
}

func (this *LUPrefix) Longest() int {
	return this.longestPrefix
}

/**
 * Your LUPrefix object will be instantiated and called as such:
 * obj := Constructor(n);
 * obj.Upload(video);
 * param_2 := obj.Longest();
 */
```Go 的实现与 Python 版本非常相似。 

上传的跟踪结构是使用布尔切片实现的。 由于 Go 切片是零初始化的，因此所有条目都以`false`。 

这`for`使用循环代替Python的循环`while`。 

不存在整数溢出问题，因为相对于 Go 的整数范围来说，约束很小。

 之后`upload(2)`：

 初始状态：```
longest_prefix = 1
```查看：```
uploaded[2] == True
```进步：```
longest_prefix = 2
```再次检查：```
uploaded[3] == True
```进步：```
longest_prefix = 3
```再次检查：```
uploaded[4] == False
```停止。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(1)`摊销| 每个视频最多使指针前进一次 |
 | 空间|`O(n)`| 布尔数组存储上传状态 |

 虽然`upload`方法包含一个`while`循环中，指针在对象的整个生命周期中仅向前移动。 由于最多有`n`总指针增量，所有操作的总工作量为`O(n)`。 

这给出了每次操作的摊余常数时间。

 ## 边缘情况

 ### 上传视频完全乱序

 幼稚的实现可能会错误地假设上传是按顺序发生的。 例如：```
upload(5)
upload(4)
upload(3)
```最长的前缀仍必须保留`0`因为视频`1`失踪了。 

该实现可以正确处理此问题，因为指针仅在下一个所需视频存在时前进。 

### 前缀一次扩展多个位置

 考虑：```
upload(2)
upload(3)
upload(4)
upload(5)
upload(1)
```当视频`1`终于上传了，前缀应该立即跳转`0`到`5`。 

这`while`循环通过重复推进指针直到找到第一个丢失的视频来正确处理此问题。 

### 所有视频已上传

 每个视频上传完毕后，指针就会到达`n`。 

那时：```
longest_prefix = n
```该实现可以安全地处理这个问题，因为布尔数组分配了大小`n + 2`，检查时防止越界访问`longest_prefix + 1`。
