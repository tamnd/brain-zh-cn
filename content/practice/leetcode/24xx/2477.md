[LeetCode 问题 2477](https://leetcode.com/problems/minimum-fuel-cost-to-report-to-the-capital/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、广度优先搜索、图论

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个形成树的乡村道路网络。 树是一个没有环的连通图，这意味着任意两个城市之间只有一条路径。 城市编号从`0`到`n - 1`，和城市`0`永远是首都。 

每个城市只有一名代表，必须前往首都参加会议。 每个城市都有一辆车，每辆车都有相同数量的座位，由下式给出`seats`。 

无论车内有多少乘客，沿着一条道路行驶只花费一升燃油。 代表们可以换车和拼车。 目标是最大限度地减少燃料消耗总量，以便每个代表都能到达首都。 

输入包括：

 -`roads`，表示树的无向边列表
 -`seats`, 每辆车的座位数

 输出是所需燃料的最小总升数。 

约束条件很重要：

 -`n`可以大到`10^5`- 该图保证是一棵有效的树
 - 比线性或接近线性时间慢的解决方案可能会超时

 因为图是一棵树，所以从每个城市到首都都只有一条路线。 这消除了寻路的歧义，并强烈建议使用基于遍历的解决方案，例如 DFS 或 BFS。 

有几个重要的边缘情况：

 - 一个只有首都的国家，`roads = []`。 不需要旅行，所以答案是`0`。 
-`seats = 1`，这意味着没有人可以共享乘车。 每位代表实际上都是独立出行。 
- 座位数量非常多，许多代表可以合并到一辆车中，然后再向上移动。 
- 深层树结构，如果不小心实现，可能会暴露递归深度或遍历问题。 

关键的观察是，每个代表最终都必须沿着独特的树形路径向上到达首都，因此优化完全来自于将乘客智能地分组在一起。 

## 方法

 ### 蛮力方法

 暴力策略将尝试模拟代表在前往首都的途中组合汽车和共享乘车的所有可能方式。 

对于每个城市，我们可以考虑：

 - 代表是否单独驾驶
 - 他们在哪个中间城市合并
 - 之后他们继续乘坐哪辆车

 这很快就会变得具有爆炸性，因为每个子树都可以以多种不同的方式组合代表。 

即使我们尝试对子集进行动态规划或探索所有分组组合，可能性的数量也会随着城市数量呈指数增长。 这种方法对于`n = 10^5`。 

蛮力方法是正确的，因为它明确地检查所有有效的运输安排，但它太慢了。 

### 最佳洞察力

 关键的见解是，在一棵树中，每个代表都有一条通往首都的路径。 

这意味着我们不需要决定人们采取哪条路线。 当代表从子树向上移动到其父树时，唯一的决定是“需要多少辆车”。 

假设一个子树包含`k`代表。 为了将它们全部向上移动到首都，我们需要：$\left\lceil \frac{k}{\text{seats}} \right\rceil$汽车穿过那条边缘。 

每次这样的跨越需要花费一升燃料。 

因此，对于树中的每条边，最优成本仅取决于有多少代表必须穿过该边。 

这自然会导致后序 DFS：

 1. 计算每个子树中的代表数。 
2. 对于每个非首都节点：

 - 确定需要多少辆车才能将其子树代表向上移动。 
- 将这个数字添加到答案中。 

这是有效的，因为子树内的代表在离开子树之前总是可以最佳地合并。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 尝试所有拼车组合 |
 | 最优 DFS | O(n) | O(n) | 聚合子树代表自下而上|

 ## 算法演练

 ### 第 1 步：构建邻接表

 转换`roads`边列表转换为邻接列表表示。 

因为该图是无向的，所以每条路`[a, b]`是在两个方向上添加的。 

这使得可以高效地穿越邻近城市。 

### 第2步：从首都启动DFS

 我们从城市开始进行深度优先遍历`0`。 

DFS函数将返回当前子树中的代表总数。 

每个城市都会贡献一名代表，即它自己。 

### 步骤3：遍历子子树

 对于每个邻近城市：

 - 跳过父城市以避免重访节点
 - 递归处理子子树
 - 接收来自该子树的代表数量

 这给了我们最终需要通过连接子节点到当前节点的边向上移动的总人数。 

### 步骤 4：计算子子树的燃料成本

 如果一个子子树包含`people`代表，那么将他们向上移动一级所需的汽车数量为：$\left\lceil \frac{\text{people}}{\text{seats}} \right\rceil$每辆穿过边缘的汽车消耗一升燃料。 

因此，我们将此值添加到全局答案中。 

### 第 5 步：积累代表

 处理完所有子项后，返回：

 -`1`现任城市代表
 - 加上子子树的所有代表

 该值向上传播到首都。 

###第六步：完成遍历

 资金本身不需要向上流动，所以我们从不对节点收取燃料费`0`。 

累积的全球答案是最低燃料成本。 

### 为什么它有效

 该算法依赖于这样一个事实：每个代表必须穿过通往首都的唯一路径上的每条边恰好一次。 

对于任何子树，唯一重要的是有多少代表离开该子树。 由于汽车在向上交叉之前可以在子树内自由重组，因此最佳策略始终是尽可能完整地包装汽车。 

DFS 只计算一次子树大小，并为每条边计算向上运输这些代表所需的最小汽车数量。 由于每个边缘贡献都是独立最优的，因此总燃料成本是全局最优的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
import math

class Solution:
    def minimumFuelCost(self, roads: List[List[int]], seats: int) -> int:
        n = len(roads) + 1
        
        graph = defaultdict(list)
        
        for a, b in roads:
            graph[a].append(b)
            graph[b].append(a)
        
        fuel_cost = 0
        
        def dfs(node: int, parent: int) -> int:
            nonlocal fuel_cost
            
            representatives = 1
            
            for neighbor in graph[node]:
                if neighbor == parent:
                    continue
                
                people = dfs(neighbor, node)
                
                fuel_cost += math.ceil(people / seats)
                
                representatives += people
            
            return representatives
        
        dfs(0, -1)
        
        return fuel_cost
```实现首先使用构造邻接表`defaultdict(list)`。 由于该图是无向的，因此每条边都在两个方向上插入。 

变量`fuel_cost`存储运行总答案。 

DFS 函数返回以当前节点为根的子树中包含的代表数。 

每个节点最初贡献一个代表，即它自己。 然后我们递归地处理每个子子树。 

对于每个孩子：

 - 我们递归地计算该子树中的代表数量。 
- 我们通过使用上限划分来确定需要多少辆汽车才能将这些代表向上移动。 
- 我们将燃料成本添加到全球答案中。 
- 我们将代表累积到当前子树总数中。 

最后，DFS从首都开始`0`。 由于资本不向上移动，因此不收取燃料费用。 

## 解决方案```go
package main

func minimumFuelCost(roads [][]int, seats int) int64 {
	n := len(roads) + 1

	graph := make([][]int, n)

	for _, road := range roads {
		a, b := road[0], road[1]

		graph[a] = append(graph[a], b)
		graph[b] = append(graph[b], a)
	}

	var fuelCost int64

	var dfs func(int, int) int

	dfs = func(node int, parent int) int {
		representatives := 1

		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			people := dfs(neighbor, node)

			fuelCost += int64((people + seats - 1) / seats)

			representatives += people
		}

		return representatives
	}

	dfs(0, -1)

	return fuelCost
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个重要的区别是整数处理。 最终答案可能超出32位整数的范围，因此结果存储为`int64`。 

而不是使用`math.Ceil`，Go 执行上限除法：```go
(people + seats - 1) / seats
```为了获得更好的性能，邻接列表用切片的切片而不是哈希图表示。

 ## 边缘情况

 ### 单一首都城市

 当`roads = []`，该国家仅包含城市`0`。 

这很容易处理不当，因为许多图算法假设至少存在一条边。 在这种情况下，没有代表去任何地方，所以答案一定是`0`。 

该实现自然地处理了这个问题，因为 DFS 从节点开始`0`，找不到邻居，并且永远不会增加燃料成本。 

### 座位数等于 1

 当`seats = 1`，拼车变得不可能。 

每个代表实际上都需要自己的汽车来进行每次边缘遍历。 这会产生最大可能的燃料消耗，并可能暴露不正确的分组逻辑。 

该实施仍然有效，因为：$\left\lceil \frac{k}{1} \right\rceil = k$因此，每一个跨越边缘的代表都贡献了一个燃料单位。 

### 深度线性树

 链状树，例如：```
0 - 1 - 2 - 3 - 4
```可以暴露递归深度或累积错误。 

在这种结构中，代表们在向上移动的过程中逐步融合。 不正确的子树计数会产生错误的结果。 

DFS 实现正确地自下而上聚合代表，确保每个子树向其父边缘贡献正确数量的汽车。
