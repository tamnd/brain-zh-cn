 **难度：** 🟡 中等
 **主题：** 数组、矩阵、前缀和

 ## 解决方案

 ## 问题理解

 该问题提供了一个`m x n`整数矩阵`grid`并要求矩阵内**沙漏**形状的最大总和。 沙漏被定义为 3x3 结构，顶部和底部行完全包含在内，并且仅包含中间行的中心元素。 具体来说，如果`i`和`j`表示沙漏的左上角坐标，沙漏总和为：```
grid[i][j] + grid[i][j+1] + grid[i][j+2]
          + grid[i+1][j+1] +
grid[i+2][j] + grid[i+2][j+1] + grid[i+2][j+2]
```矩阵尺寸保证至少为 3x3，因此始终至少有一个有效的沙漏。 限制条件`3 <= m, n <= 150`和`0 <= grid[i][j] <= 10^6`表明迭代所有可能的沙漏位置的简单暴力解决方案是可行的，但如果需要，我们还应该考虑使用预先计算的总和进行优化。 

要考虑的边缘情况包括尽可能小的矩阵`3x3`（恰好一个沙漏）和所有值都相同的矩阵（测试代码是否正确识别最大值，即使总和相同）。 

## 方法

 **暴力方法**迭代每个可能的左上角位置`(i, j)`3x3 沙漏。 对于每个位置，它显式地对 7 个相关元素求和。 这种方法保证了正确性，因为它确实检查每个有效的沙漏，但它可能会在重叠的沙漏上执行冗余计算。 时间复杂度为`O((m-2)*(n-2)*7)`这简化为`O(m*n)`并且对于给定的约束是可以接受的。 空间复杂度为`O(1)`因为不需要额外的数据结构。 

**最佳方法**使用相同的强力扫描，但利用了这样一个事实：以固定的 3x3 模式对各个元素求和很简单，并且考虑到较小的常数因子，不需要前缀求和等高级技术。 对于较大的沙漏状问题或可变大小，可以使用前缀和来更有效地计算行或子矩阵和，但这里的简单性和固定模式使直接计算成为最佳选择。

 | ---| ---| ---| ---|
 | 蛮力 | O(m*n) | O(1) | O(1) | 迭代沙漏的所有左上角位置，并对每个位置的 7 个元素求和 |
 | 最佳| O(m*n) | O(1) | O(1) | 与暴力破解相同； 常数因子很小，不需要额外的存储|

 ## 算法演练

 1. 初始化变量`max_sum`为 0 或负无穷大以跟踪找到的最大沙漏总和。 使用负无穷大可以确保正确性，如果`grid`只能包含零。 
2. 迭代所有有效的左上角位置`(i, j)`沙漏的。 有效位置满足`0 <= i <= m-3`和`0 <= j <= n-3`。 
3. 对于每个`(i, j)`，使用上面的公式显式计算沙漏总和。 
4. 将计算出的总和与`max_sum`，并更新`max_sum`如果新的总和更大。 
5.迭代完成后，返回`max_sum`作为最终结果。 

**为什么有效**：该算法仅检查矩阵中每个可能的沙漏一次。 由于每个沙漏的总和已正确计算并与运行最大值进行比较，因此最终值`max_sum`保证是矩阵中最大可能的沙漏总和。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSum(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        max_sum = 0
        
        for i in range(m - 2):
            for j in range(n - 2):
                current_sum = (
                    grid[i][j] + grid[i][j+1] + grid[i][j+2] +
                    grid[i+1][j+1] +
                    grid[i+2][j] + grid[i+2][j+1] + grid[i+2][j+2]
                )
                if i == 0 and j == 0:
                    max_sum = current_sum
                else:
                    max_sum = max(max_sum, current_sum)
                    
        return max_sum
```**说明**：我们首先确定尺寸`m`和`n`。 外循环遍历 3x3 沙漏适合的所有位置。 沙漏的总和是使用索引显式计算的，包括顶行、中间中心和底行。 每一步都会更新最大总和。 我们初始化`max_sum`即使所有值都为零，也可以在第一个沙漏上确保正确性。 

## 解决方案```go
func maxSum(grid [][]int) int {
    m, n := len(grid), len(grid[0])
    maxSum := 0
    first := true

    for i := 0; i <= m-3; i++ {
        for j := 0; j <= n-3; j++ {
            currentSum := grid[i][j] + grid[i][j+1] + grid[i][j+2] +
                          grid[i+1][j+1] +
                          grid[i+2][j] + grid[i+2][j+1] + grid[i+2][j+2]
            if first {
                maxSum = currentSum
                first = false
            } else if currentSum > maxSum {
                maxSum = currentSum
            }
        }
    }
    return maxSum
}
```**Go 特定注释**：我们使用布尔值仔细处理初始化`first`因为 Go 的整数没有负无穷大。 除了语法差异之外，逻辑与 Python 版本相同。 不存在零切片的风险，因为问题约束保证了有效的矩阵。
