 # LeetCode 2449 - 使数组相似的最少操作数

 ## 问题理解

 我们有两个数组，`nums`和`target`，长度相等。 在一次操作中，我们选择两个不同的索引并添加`2`减去一个元素`2`来自另一个元素。 

此操作保留了数组的总和，因为每个`+2`由相应的平衡`-2`。 更重要的是，每个元素的奇偶性都被保留。 偶数多次相加或相减后仍为偶数`2`，且奇数仍为奇数。 

目标不是使数组的当前顺序相等。 相反，我们需要使`nums`类似于`target`，这意味着经过一些操作序列后，两个数组都包含完全相同的值的多重集。 职位并不重要。 

约束条件非常大，最多可达`10^5`元素。 任何直接模拟操作或探索可能状态的解决方案都是不可行的。 我们需要一个运行时间大约为`O(n log n)`时间。 

一些重要的观察立即浮现出来。 

由于奇偶校验永远不会改变，因此中的每个奇数`nums`最终必须对应于奇数`target`，以及中的每个偶数`nums`必须对应于偶数`target`。 

问题保证了解决方案总是存在。 因此，两个数组之间的奇数和偶数元素的计数必须已经兼容。 

另一个微妙之处是，一次操作传输的总量为`2`从一个元素到另一个元素。 因此，如果一个元素需要增加`6`，这需要三个单位的转移价值，但这三个单位可以来自不同的元素。 

边缘情况包括已经相似的数组、完全由奇数或完全由偶数组成的数组、重复值以及效率变得至关重要的非常大的数组。 

## 方法

 ### 蛮力

 强力策略将尝试直接对数组转换进行建模。 

人们可以重复查找相对于某种所需排列来说太小的元素和太大的元素，然后执行操作直到所有值匹配。 不幸的是，有许多可能的配对和操作顺序。 状态空间随着数组大小呈指数增长。 

即使我们以某种方式确定了正确的目标排列，模拟每个单独的操作也会太慢，因为值差异可能高达近一百万。 

虽然这种方法最终会找到答案，但对于`n = 10^5`。 

### 关键见解

 关键的观察结果是奇偶性得以保留。 

因为加或减`2`奇偶性永远不会改变，奇数只能转化为奇数，偶数只能转化为偶数。 

因此，我们可以将两个数组分成：

 - 奇怪的元素
 - 偶数元素

 在每个奇偶校验组中，最佳策略是对两个列表进行排序并匹配相应的元素。 

为什么排序有效？ 

假设我们有两个已排序的奇偶校验组。 将最小的源值与最小的目标值相匹配，将第二小的值与第二小的值相匹配，依此类推，可以最大限度地降低总调整成本。 这是一维值的标准最佳匹配属性。 

匹配后，考虑一对：```
nums_value -> target_value
```如果`nums_value < target_value`，该元素必须获得：```
target_value - nums_value
```由于组内所有数字都具有相同的奇偶性，因此该差异始终可以除以`2`。 

每个操作都会增加一个元素`2`。 因此所需的增加单位数为：```
(target_value - nums_value) / 2
```将这些正调整加起来就得出必须转移的总金额。 

然而，单个操作会同时增加一个元素并减少另一个元素。 因此，每次操作贡献一个增加单位和一个减少单位。 

结果，答案是：```
(sum of all positive differences) / 2
```可以计算为：```
Σ(max(0, target[i] - nums[i]) / 2) / 2
```一个等效且更常见的公式是将所有正差异相加并除以`4`。

 ## 算法演练

 1. 创建四个数组：

 - 奇怪的元素来自`nums`- 甚至元素来自`nums`- 奇怪的元素来自`target`- 甚至元素来自`target`2. 对所有四个数组进行排序。 

排序使我们能够在每个奇偶校验组内对元素进行最佳配对。 
3. 对于奇数组，排序后比较对应的元素。 

每当目标值大于当前值时，计算：```
target_value - nums_value
```将这个正差值添加到总计中。 
4. 对偶数组重复相同的过程。 
5. 令累计正差和为：```
total_diff
```6、每一次操作有效贡献`4`对于这个金额：

 - 一种元素增益`2`- 另一个元素丢失`2`因此返回：```
total_diff // 4
```### 为什么它有效

 该操作保留奇偶校验，因此奇数和偶数元素形成独立的组。 对每个组进行排序并匹配相应的元素可以最大限度地减少所需的总调整。 每个正差异都代表必须转移到该元素中的价值。 由于每个操作都准确传输`2`单位从一个地点到另一个地点，每次操作都占`4`正差之和的单位。 因此，将总正差除以`4`产生最少的操作数。 

## Python 解决方案```python
from typing import List

class Solution:
    def makeSimilar(self, nums: List[int], target: List[int]) -> int:
        nums_odd = sorted(x for x in nums if x % 2)
        nums_even = sorted(x for x in nums if x % 2 == 0)

        target_odd = sorted(x for x in target if x % 2)
        target_even = sorted(x for x in target if x % 2 == 0)

        total_diff = 0

        for a, b in zip(nums_odd, target_odd):
            if b > a:
                total_diff += b - a

        for a, b in zip(nums_even, target_even):
            if b > a:
                total_diff += b - a

        return total_diff // 4
```实现首先将两个数组划分为奇数和偶数值。 由于奇偶校验在任何操作期​​间都不会改变，因此可以独立处理这些组。 

每个组都已排序。 排序后，相应的位置代表源值和目标值之间的最佳匹配。 

然后代码扫描奇数组和偶数组。 每当目标值超过相应的源值时，该增加就会导致必须转移的价值量。 

累积的正差值存储在`total_diff`。 最后除以`4`将所需调整总量转换为操作数，因为每个操作都会贡献`2`增加单位和`2`减少单位。 

## 解决方案```go
package main

import "sort"

func makeSimilar(nums []int, target []int) int64 {
	numsOdd := make([]int, 0)
	numsEven := make([]int, 0)

	targetOdd := make([]int, 0)
	targetEven := make([]int, 0)

	for _, x := range nums {
		if x%2 == 0 {
			numsEven = append(numsEven, x)
		} else {
			numsOdd = append(numsOdd, x)
		}
	}

	for _, x := range target {
		if x%2 == 0 {
			targetEven = append(targetEven, x)
		} else {
			targetOdd = append(targetOdd, x)
		}
	}

	sort.Ints(numsOdd)
	sort.Ints(numsEven)
	sort.Ints(targetOdd)
	sort.Ints(targetEven)

	var totalDiff int64

	for i := 0; i < len(numsOdd); i++ {
		if targetOdd[i] > numsOdd[i] {
			totalDiff += int64(targetOdd[i] - numsOdd[i])
		}
	}

	for i := 0; i < len(numsEven); i++ {
		if targetEven[i] > numsEven[i] {
			totalDiff += int64(targetEven[i] - numsEven[i])
		}
	}

	return totalDiff / 4
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 主要区别在于 Go 使用切片和显式循环而不是生成器表达式。 

结果存储在`int64`匹配所需的返回类型并安全地处理最大可能的累积差异。

 ## 边缘情况

 一种重要的边缘情况是数组已经相似。 幼稚的实现可能仍然会执行不必​​要的工作或错误地计算调整。 对奇偶校验组进行排序后，每个匹配对都相等，因此累积差值保持为零，并且算法正确返回零运算。 

当所有数字属于同一奇偶校验类别时，会发生另一个重要情况。 由于该解决方案将奇数和偶数分开，因此它必须正确处理其中一组为空的情况。 该实现自然会处理这个问题，因为对空列表进行排序和迭代是安全的。 

第三种边缘情况涉及重复值。 多个相同的数字可以创建许多有效的匹配。 如果不进行排序，贪婪配对可能会产生比必要的更大的调整成本。 排序可确保尽可能对齐相等的值，并保证最小的总调整量。 

最后一个边缘情况是输入尺寸非常大。 高达`10^5`元素，任何二次比较策略都会超时。 该实现仅在排序后执行线性扫描，将整体复杂度保持在`O(n log n)`，它很适合约束条件。
