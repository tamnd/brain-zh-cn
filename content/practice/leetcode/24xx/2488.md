[LeetCode 问题 2488](https://leetcode.com/problems/count-subarrays-with-median-k/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个连续子数组的中位数等于给定值`k`。 

数组`nums`包含来自的每个整数`1`到`n`恰好一次，这意味着所有元素都是不同的。 该细节非常重要，因为它可以消除相对于值进行比较时的歧义`k`。 

对于偶数长度的数组来说，这里使用的中位数的定义有点不寻常。 对子数组进行排序后：

 - 如果长度是奇数，则中位数是中间的元素。 
- 如果长度是偶数，则中位数是左中间元素。 

例如：

-`[1,2,3]`有中位数`2`-`[1,2,3,4]`也有中位数`2`我们需要计算中位数恰好为的每个非空连续子数组`k`。 

限制条件很大：

 -`n`可以大到`100000`- 二次或三次解无法及时完成
 - 我们需要接近线性时间的东西

 一个简单的实现将检查每个子数组，对其进行排序，并计算其中值。 那太慢了。 

有几个重要的观察结果和边缘情况：

 - 由于所有数字都是不同的，因此每个数字要么小于`k`，等于`k`，或大于`k`- 任何有效的子数组必须包含`k`- 单元素子数组`[k]`始终有效
 - 由于“左中”中值定义，偶数长度和奇数长度子数组的行为略有不同
 - 数组，其中`k`接近开头或结尾很容易造成相差一的错误
 - 余额计数必须正确处理奇数和偶数子数组长度

 关键的挑战是将中值条件转换为我们可以有效计数的东西。 

## 方法

 ### 蛮力方法

 暴力解决方案在概念上很简单。 

我们生成每个可能的子数组。 对于每个子数组：

 1. 检查是否包含`k`2. 对子数组进行排序
 3.根据问题定义计算中位数
 4. 计算中位数是否相等`k`这是有效的，因为它直接模拟中位数的定义。 

然而，表现却很糟糕。 

有`O(n^2)`子数组。 对每个子数组进行排序需要花费`O(n log n)`。 总复杂度大约变为`O(n^3 log n)`在最坏的情况下。 

即使我们优化了中值提取，该解决方案仍然太慢`n = 100000`。 

### 最佳解决方案的关键见解

 关键的观察是我们实际上并不关心元素的确切顺序。 我们只关心元素是否：

 - 小于`k`- 大于`k`- 等于`k`假设我们像这样转换数组：

 - 数字大于`k`变得`+1`- 数字小于`k`变得`-1`-`k`本身就变成了`0`现在考虑一个包含`k`。 

为了`k`为中位数：

 - 元素数量大于`k`元素数量必须等于小于`k`, 或
 - 由于偶数长度的左中规则，恰好可以有一个额外的较大元素

 这意味着转换后的子数组必须具有以下任一余额：

 -`0`-`1`这将问题转换为前缀和计数问题。 

我们将一切都围绕着`k`，然后计算有多少左右平衡组合产生有效总计。

 ## 算法演练

 ### 第 1 步：找到 的位置`k`首先，找到索引所在的位置`nums[i] == k`。 

每个有效的子数组都必须包含该索引，因为中位数必须是字面上的值`k`。 

这使我们能够将整个计算集中在该位置周围。 

### 步骤 2：定义平衡转换

 我们定义运行余额：

 - 添加`+1`对于大于的值`k`- 添加`-1`对于小于的值`k`我们不包括`k`本身处于平衡之中。 

余额代表：```
(# greater than k) - (# less than k)
```对于有效中位数：

 - 奇数长度子数组需要平衡`0`- 偶数长度子数组需要平衡`1`### 步骤 3：处理右侧

 从索引开始`k`，向右移动。 

每一步：

 - 更新余额
 - 在哈希图中存储每个余额发生的次数

 这张地图告诉我们有多少右侧部分产生了特定的平衡。 

我们用以下方法初始化地图：```
balance 0 occurs once
```这表示不向右取任何元素。 

### 步骤 4：处理左侧

 现在从 的位置开始向左移动`k`。 

对于每个左侧余额，我们希望总子数组余额变为：

 -`0`-`1`假设当前剩余余额为`leftBalance`。 

那么有效的权利余额是：```
-rightBalance = leftBalance
or
-rightBalance = leftBalance - 1
```等效地：```
rightBalance = -leftBalance
or
rightBalance = 1 - leftBalance
```我们在哈希图中查找这些并将它们的频率添加到答案中。 

###第五步：返回结果

 处理完所有左侧扩展后，累积的答案就是有效子数组的总数。 

### 为什么它有效

 转换后的平衡精确地跟踪了大于的元素之间的关系`k`和元素小于`k`。 

子数组有中位数`k`恰好在以下时间：

 - 计数相等，平衡`0`- 或者还有一个额外的更重要的元素，平衡`1`通过分割数组`k`，我们可以使用前缀和和哈希图有效地计算所有有效的余额组合。 

由于每个子数组通过其左右扩展只被考虑一次，因此该算法在时间复杂度上既正确又呈线性。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def countSubarrays(self, nums: List[int], k: int) -> int:
        n = len(nums)
        k_index = nums.index(k)

        balance_count = defaultdict(int)
        balance_count[0] = 1

        balance = 0

        # Process right side including k
        for i in range(k_index + 1, n):
            if nums[i] > k:
                balance += 1
            else:
                balance -= 1

            balance_count[balance] += 1

        answer = 0
        balance = 0

        # Process left side including k
        for i in range(k_index, -1, -1):
            if nums[i] > k:
                balance += 1
            elif nums[i] < k:
                balance -= 1

            answer += balance_count[-balance]
            answer += balance_count[1 - balance]

        return answer
```实现首先定位索引`k`。 由于每个有效子数组必须包含`k`，该索引成为计算的中心。 

这`balance_count`哈希图存储从右侧开始的余额频率。 使用以下变换计算余额：

 -`+1`对于大于的值`k`-`-1`对于小于的值`k`第一个循环处理紧随其后开始的所有后缀`k`。 每个平衡频率都会被记录。 

第二个循环从左侧向左走`k`。 在每一步中，我们都会计算当前的左侧余额，并确定有多少右侧余额可以与其组合以形成有效的总余额`0`或者`1`。 

表达式：```python
balance_count[-balance]
```计算子数组的总余额`0`。 

表达式：```python
balance_count[1 - balance]
```计算子数组的总余额`1`。 

最终答案累积了所有此类有效组合。 

## 解决方案```go
package main

func countSubarrays(nums []int, k int) int {
	n := len(nums)

	kIndex := 0
	for i, v := range nums {
		if v == k {
			kIndex = i
			break
		}
	}

	balanceCount := map[int]int{}
	balanceCount[0] = 1

	balance := 0

	// Process right side
	for i := kIndex + 1; i < n; i++ {
		if nums[i] > k {
			balance++
		} else {
			balance--
		}

		balanceCount[balance]++
	}

	answer := 0
	balance = 0

	// Process left side
	for i := kIndex; i >= 0; i-- {
		if nums[i] > k {
			balance++
		} else if nums[i] < k {
			balance--
		}

		answer += balanceCount[-balance]
		answer += balanceCount[1-balance]
	}

	return answer
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

主要区别在于 Go 使用原生`map[int]int`而不是Python的`defaultdict`。 缺少的键会自动返回整数的零值，这简化了查找逻辑。 

由于余额和计数的约束条件非常适合 32 位整数范围，因此标准`int`类型就足够了。 

由于 Go 数组是固定大小的，对于动态问题不太方便，因此很自然地使用切片。

 该算法执行两次线性扫描：

 - 一次扫描即可建立右侧平衡
 - 一次扫描即可评估左侧组合

 期望进行哈希映射操作`O(1)`时间，因此总复杂度保持线性。 

余额值可能有所不同`-n`到`+n`，这意味着哈希映射可能包含最多`O(n)`条目。

 ## 边缘情况

 当数组仅包含一个元素时，会出现一种重要的边缘情况。 在这种情况下，单个元素必须等于`k`，唯一有效的子数组是数组本身。 许多实现意外地错误地处理了空平衡图或跳过单例子数组。 这个实现很自然地处理它，因为平衡图以`{0:1}`，左侧遍历包括`k`索引本身。 

另一个关键的边缘情况是`k`出现在数组的开头或结尾。 前缀和算法经常在边界情况下引入相差一的错误。 在这里，循环的结构经过精心设计，因此右侧处理从`k_index + 1`，而左侧遍历直接从`k_index`。 这保证了所有包含的有效子数组`k`只被考虑一次。 

偶数长度子数组是另一个微妙的错误来源。 由于该问题将中位数定义为左中元素，因此有效余额不限于`0`。 平衡为`1`也是有效的。 忘记这个条件会导致许多解决方案低估偶数长度子数组，例如`[4,5]`在第一个例子中。 该实现使用以下方式明确计算两种可能性：```
balance_count[-balance]
balance_count[1 - balance]
```最后，周围分布高度不平衡的阵列`k`可以产生许多负余额或正余额。 使用哈希映射而不是索引数组可以避免负索引的问题，并保持实现的干净和高效。
