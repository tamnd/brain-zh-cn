[LeetCode 问题 2436](https://leetcode.com/problems/minimum-split-into-subarrays-with-gcd-greater-than-one/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、动态规划、贪心、数论

 ## 解决方案

 ## 问题理解

 该问题需要将给定的正整数数组拆分为**连续的子数组**，使得每个子数组的**最大公约数 (GCD)** 严格大于 1。目标是**最小化拆分后子数组的数量**。 

简单来说，我们需要将数组划分为最少的连续段，其中每个段至少共享一个大于 1 的公因数。输入是一个数组`nums`长度可达 2000，元素可达$10^9$。 输出是一个整数，表示满足 GCD 条件的子数组的最小数量。 

重要的限制和观察：

 - 每个元素都 ≥ 2，因此每个元素单独使用时的 GCD ≥ 2。 
- 由于子数组组合的指数数量，考虑每个可能的分割的天真的方法会太慢。 
- 边缘情况包括所有元素共享一个公共因子的数组（仅需要一个子数组）和连续元素互质的数组（每个元素可能需要是自己的子数组）。 

## 方法

 **暴力方法**会尝试数组的每一个可能的分割并计算每个子数组的 GCD。 对于每个分割，如果所有子数组的 GCD > 1，它会跟踪子数组的最小数量。 虽然正确，但这种方法是不可行的，因为分割数量随着数组长度呈指数增长，导致时间复杂度$O(2^n \cdot n)$。 

**最佳解决方案的关键见解**基于动态规划或使用 GCD 属性的贪婪方法：

 1. 从左到右迭代数组，保持**当前子数组的 GCD**。 
2. 如果添加下一个元素导致 GCD 为 1，则意味着我们无法进一步扩展当前子数组。 此时，我们**分割**并开始一个新的子数组。 
3. 如果添加下一个元素使 GCD > 1，则继续扩展当前子数组。 

这是可行的，因为 GCD 在这种情况下是关联且单调的：如果子数组的 GCD 变为 1，则任何进一步的扩展都无法将其修复为 >1。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 尝试所有分割，每次计算 GCD |
 | 最佳| O(n) | O(1) | O(1) | 单遍维持当前 GCD，每当 GCD=1 时就分割 |

 ## 算法演练

 1. 初始化变量`splits = 1`计算子数组的数量。 从第一个元素开始作为当前子数组。 
2. 初始化`current_gcd`作为数组的第一个元素。 
3. 从第二个元素开始迭代数组：

 1. 更新`current_gcd = gcd(current_gcd, nums[i])`。 
2.如果`current_gcd`变为 1：

 1. 增量`splits`加 1 因为我们需要一个新的子数组，从`nums[i]`。 
2. 重置`current_gcd = nums[i]`为新的子数组。 
4. 继续此过程直到数组末尾。 
5. 返回`splits`作为子数组的最小数量。 

**为什么有效：**

 该算法确保每个子数组的 GCD > 1。通过维护正在运行的 GCD 并在其变为 1 时进行分割，我们保证了最小分割，因为我们仅在绝对必要时进行分割。 这利用了向 GCD 已经为 1 的子数组添加元素无法提高 GCD 的属性。 

## Python 解决方案```python
from typing import List
from math import gcd

class Solution:
    def minimumSplits(self, nums: List[int]) -> int:
        splits = 1
        current_gcd = nums[0]
        
        for num in nums[1:]:
            current_gcd = gcd(current_gcd, num)
            if current_gcd == 1:
                splits += 1
                current_gcd = num
        
        return splits
```**实施说明：**

 我们开始数数`splits`从 1 开始，因为第一个元素始终形成子数组。`current_gcd`跟踪当前子数组的 GCD。 当我们迭代时，我们更新`current_gcd`与新元素。 如果变为1，则子数组无法进一步扩展，因此我们递增`splits`并从当前元素开始一个新的子数组。 

## 解决方案```go
import "math"

func gcd(a, b int) int {
    for b != 0 {
        a, b = b, a%b
    }
    return a
}

func minimumSplits(nums []int) int {
    splits := 1
    currentGCD := nums[0]
    
    for i := 1; i < len(nums); i++ {
        currentGCD = gcd(currentGCD, nums[i])
        if currentGCD == 1 {
            splits++
            currentGCD = nums[i]
        }
    }
    
    return splits
}
```**Go 特定注释：**

 我们实施`gcd`手动，因为 Go 没有标准库 GCD 函数。 整数算术就足够了，因为问题约束保证所有数字都在界限内。 切片用于迭代和初始化`splits`遵循与 Python 相同的逻辑。

 ## 边缘情况

 1. **单元素数组：** 对于`nums = [2]`，算法正确返回 1，因为单个元素的 GCD 已经 >1。 期望至少有两个元素的天真的方法可能会失败。 
2. **所有元素互质：** 对于素数数组，例如`[2,3,5,7]`，每个元素都需要自己的子数组。 每当 GCD 变为 1 时，算法就会分裂。 
3. **统一因子数组：** 数组如`[8,16,32]`都可以被 2 整除。该算法正确地将它们保留为单个子数组，因为运行的 GCD 永远不会下降到 1。这验证了避免了不必要的分割。 

这种方法平衡了正确性、效率和简单性，同时直接利用 GCD 属性来实现最小分割。
