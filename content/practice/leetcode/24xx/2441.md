 **难度：** 🟢简单
 **主题：** 数组、哈希表、两个指针、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们找到最大的正整数`k`在给定数组中`nums`这样它的负对应物`-k`也存在于数组中。 换句话说，对于数组中的每个正整数，我们需要检查它的负整数是否存在。 如果多个正整数满足此属性，我们返回最大的一个。 如果不存在，我们返回`-1`。 

输入数组包含范围内的整数`[-1000, 1000]`并明确排除零。 数组长度最多可达 1000，这个长度足够小，可以实现简单的解决方案，但我们可以进一步优化。 约束保证不存在零，因此我们不需要将零作为特殊情况来处理。 重要的边缘情况包括所有整数均为正数、全部为负数的数组，或者存在正/负对但仅适用于较小值的数组。 

## 方法

 暴力方法涉及检查数组中的每个正整数并查看其负整数是否存在。 这保证了正确性，因为它显式地验证每个可能的候选者，但效率很低，因为对于每个元素，我们可能必须扫描整个数组，从而导致 O(n²) 时间复杂度。 

更优化的方法利用哈希集。 通过将所有数字存储在一个集合中，我们可以检查是否存在`-num`对于每个正整数，在恒定时间内`num`。 然后我们跟踪满足此条件的最大正整数。 这将时间复杂度降低到 O(n)，同时使用 O(n) 额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个正数与数组其余部分的负数 |
 | 最佳| O(n) | O(n) | 使用哈希集进行 O(1) 负值查找 |

 ## 算法演练

 1.初始化一个空集`num_set`存储输入数组中的所有整数。 这允许 O(1) 成员资格检查。 
2. 遍历数组并将每个数字添加到`num_set`。 这确保我们可以有效地检查任何数字的负数。 
3. 初始化变量`max_k`到`-1`。 这将存储存在负数的最大正整数。 
4. 再次遍历数组。 对于每个数字`num`，检查是否`num`是正数，如果`-num`存在于`num_set`。 
5. 如果两个条件都满足，则更新`max_k`成为最大的`max_k`和`num`。 
6.处理完所有数字后，返回`max_k`。 

为什么它有效：该算法保持了以下不变式：`max_k`始终存储迄今为止找到的最大正整数，该正整数在数组中具有相应的负数。 通过对所有数字进行一次精确检查并使用一组进行快速负查找，我们保证了 O(n) 时间内的正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaxK(self, nums: List[int]) -> int:
        num_set = set(nums)
        max_k = -1
        for num in nums:
            if num > 0 and -num in num_set:
                max_k = max(max_k, num)
        return max_k
```在这个实现中，我们首先填充一个集合`num_set`允许恒定时间查找。 然后，我们迭代这些数字，检查集合中是否有对应的负值。 我们更新`max_k`仅当找到更大的有效数字时。 最后，`max_k`返回，包含最大的有效整数或`-1`如果不存在。 

## 解决方案```go
func findMaxK(nums []int) int {
    numSet := make(map[int]bool)
    for _, num := range nums {
        numSet[num] = true
    }

    maxK := -1
    for _, num := range nums {
        if num > 0 {
            if _, exists := numSet[-num]; exists {
                if num > maxK {
                    maxK = num
                }
            }
        }
    }
    return maxK
}
```Go 实现反映了 Python 解决方案。 我们使用地图`numSet`for O(1) lookups. 检查正数并更新的逻辑`maxK`保持相同。 Go 需要使用以下方法显式处理地图存在检查`_, exists := map[key]`句法。

 ## 边缘情况

 第一个边缘情况是全部为正数或全部为负数的数组。 幼稚的实现可能会错误地假设存在有效的 k，但我们的算法正确返回`-1`因为负的对应物缺失了。 

第二种边缘情况涉及重复的数字。 例如，`[1,1,-1,-1]`仍然产生`1`因为重复项不会影响最大正整数搜索。 哈希集自然会处理重复项。 

第三种边缘情况是允许范围的极端数字，例如`[-1000,1000]`。 我们的解决方案可以正确识别`1000`作为最大的有效整数，因为它可以处理范围内的任何整数而不会溢出。
