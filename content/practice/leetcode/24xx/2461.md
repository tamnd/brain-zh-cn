# LeetCode 2461 - 长度为 K 的不同子数组的最大和

 ## 问题理解

 该问题要求我们检查所有长度连续的子数组`k`并确定其中哪个满足一个重要的约束：子数组中的每个元素都必须是不同的。 在所有有效子数组中，我们必须返回最大可能的总和。 如果不存在有效的子数组，则答案是`0`。 

换句话说，我们正在滑动一个固定大小的长度窗口`k`遍历数组并检查每个位置的两个条件。 首先，子数组必须恰好包含`k`不同的数字，意味着不允许重复。 其次，我们计算该窗口内数字的总和。 我们的目标是找到此类总和的最大值。 

输入由一个整数数组组成`nums`和一个整数`k`。 该数组包含正整数，并且`k`指定我们可以考虑的子数组的确切大小。 输出是表示最大有效子数组和的单个整数。 

约束条件很重要：

 -`1 <= k <= nums.length <= 10^5`-`1 <= nums[i] <= 10^5`由于数组最多可以包含`100,000`元素，任何比粗略更糟糕的解决方案`O(n log n)`可能会太慢。 重复扫描子数组的强力方法效率很低。 这强烈表明我们需要一个线性时间策略。 

一些边缘情况立即脱颖而出。 如果每个窗口都包含重复项，则答案应保留`0`。 如果`k = 1`，每个元素形成一个有效的不同子数组，因此答案成为最大元素。 如果`k`等于整个数组长度，我们只有一个候选窗口，它必须包含所有唯一值或返回`0`。 

## 方法

 ### 蛮力方法

 一种简单的方法是生成每个长度的子数组`k`，检查所有元素是否不同，并计算其总和。 

对于每个起始位置，我们可以：

 1.提取size的子数组`k`。 
2. 使用集合来验证唯一性。 
3. 计算子数组的和。 
4. 如果子数组有效，则更新最大值。 

此方法是正确的，因为它显式检查每个可能的候选窗口并保证不会遗漏任何有效答案。 

然而，它的效率很低。 有`O(n)`windows，并且每个都需要`O(k)`努力建立一个集合并计算总和。 在最坏的情况下，这会变成`O(n * k)`，当两者都时太慢`n`和`k`可以大到`100,000`。 

### 最佳方法

 关键的见解是长度的相邻子数组`k`严重重叠。 从一个窗口移动到下一个窗口时，我们仅删除一个元素并添加一个新元素。 从头开始重新计算一切会浪费工作量。 

这种观察自然会导致**滑动窗口**技术。 

我们维持：

 - 当前窗口的运行总和。 
- 存储窗口内元素频率的哈希图。 

哈希映射允许我们确定所有元素是否不同。 如果唯一键的数量等于`k`，那么窗口中的每个元素都恰好出现一次。 

当窗口滑动时：

 - 删除最左边的元素。 
- 添加新的最右边元素。 
- 有效更新频率。 
- 调整恒定时间内的运行总和。 

这将复杂性降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * k) | O(k) | 重新计算每个窗口的总和和唯一性 |
 | 最佳 | O(n) | O(k) | 带有频率图的滑动窗口 |

 ## 算法演练

 1. 初始化哈希映射以跟踪当前窗口内的元素频率。 还初始化当前窗口总和和最大有效总和的变量。 
2. 构建第一个大小的窗口`k`。 对于每个元素：

 - 将其添加到运行总和中。 
- 增加其在哈希图中的频率。 
3.构造完第一个窗口后，检查该窗口是否包含`k`独特的元素。 当频率图中的键数等于时，我们知道这是真的`k`。 如果有效，则更新最大总和。 
4. 开始从左向右滑动窗口。 对于每个新职位：

 - 从左侧移除输出元件。 
- 降低其频率。 
- 如果它的频率变为零，请将其从地图上完全删除。 
- 在右侧添加传入元素。 
- 增加其频率。 
- 通过减去传出值并加上传入值来更新运行总和。 
5. 每次滑动后，检查窗口是否准确`k`独特的元素。 如果是这样，请将当前总和与最大值进行比较，并根据需要进行更新。 
6. 继续，直到处理完所有窗口。 

### 为什么它有效

 滑动窗口总是精确地表示一个连续的长度子数组`k`。 运行总和确保我们可以在恒定时间内计算子数组总和，而频率图则准确跟踪重复项。 当唯一元素的数量等于时，窗口恰好有效`k`，保证每个元素都是不同的。 由于每个可能的窗口都会被检查一次，因此算法不会错过最佳答案。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def maximumSubarraySum(self, nums: List[int], k: int) -> int:
        frequency = defaultdict(int)
        current_sum = 0
        max_sum = 0

        # Build the first window
        for i in range(k):
            current_sum += nums[i]
            frequency[nums[i]] += 1

        # Check the first window
        if len(frequency) == k:
            max_sum = current_sum

        # Slide the window
        for right in range(k, len(nums)):
            left = right - k

            outgoing = nums[left]
            incoming = nums[right]

            current_sum -= outgoing
            frequency[outgoing] -= 1

            if frequency[outgoing] == 0:
                del frequency[outgoing]

            current_sum += incoming
            frequency[incoming] += 1

            if len(frequency) == k:
                max_sum = max(max_sum, current_sum)

        return max_sum
```实现首先使用创建频率图`defaultdict(int)`因此丢失的密钥会自动从零开始。 我们还初始化两个变量：`current_sum`对于活动窗口和`max_sum`迄今为止找到的最佳答案。 

第一个循环构造大小的初始窗口`k`。 我们不会在以后重新计算总和，而是在元素进入和离开窗口时维护一个运行总计。 

一旦初始窗口准备好，我们检查其唯一元素的数量是否等于`k`。 如果为真，则窗口不包含重复项并成为候选答案。 

第二个循环处理窗口移动。 每次迭代都会从左侧删除一个元素并在右侧添加一个元素。 频率会相应更新，并且计数达到零的元素将从地图中删除。 此删除步骤很重要，因为`len(frequency)`必须准确反映不同元素的数量。 

最后，每个有效窗口都会更新`max_sum`，并返回答案。 

## 解决方案```go
func maximumSubarraySum(nums []int, k int) int64 {
	frequency := make(map[int]int)
	var currentSum int64
	var maxSum int64

	// Build the first window
	for i := 0; i < k; i++ {
		currentSum += int64(nums[i])
		frequency[nums[i]]++
	}

	// Check the first window
	if len(frequency) == k {
		maxSum = currentSum
	}

	// Slide the window
	for right := k; right < len(nums); right++ {
		left := right - k

		outgoing := nums[left]
		incoming := nums[right]

		currentSum -= int64(outgoing)
		frequency[outgoing]--

		if frequency[outgoing] == 0 {
			delete(frequency, outgoing)
		}

		currentSum += int64(incoming)
		frequency[incoming]++

		if len(frequency) == k && currentSum > maxSum {
			maxSum = currentSum
		}
	}

	return maxSum
}
```Go 实现遵循相同的逻辑，但使用`map[int]int`用于频率计数。 由于子数组和可能会变大，因此我们使用`int64`对于两者`currentSum`和`maxSum`。 这可以防止溢出并匹配所需的函数签名。 与 Python 不同，Go 需要使用显式删除键`delete()`当频率达到零时。

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 在这种情况下，每个单元素子数组都会自动包含不同的值，因为只有一个元素。 有缺陷的实现可能仍会执行不必​​要的重复检查，但该算法自然可以处理它，因为每个频率图都包含一个键。 

当所有值都重复时会发生另一个重要情况，例如`[4,4,4,4]`。 由于每个窗口都包含重复项，因此不存在有效的子数组。 执行正确返回`0`因为`max_sum`初始化为零并且仅针对有效窗口进行更新。 

当出现第三种边缘情况时`k`等于数组长度。 只有一个可能的子数组需要计算。 如果所有元素都是唯一的，我们返回总和。 否则，我们返回`0`。 该实现无缝地处理了这个问题，因为第一个窗口构造已经覆盖了整个数组，并且之后不会发生滑动。
