[LeetCode 问题 2438](https://leetcode.com/problems/range-product-queries-of-powers/)

 **难度：** 🟡 中等
 **主题：** 数组、位操作、前缀和

 ## 解决方案

 ## 问题理解

 该问题定义了一个特殊的数组，称为`powers`。 该数组是根据二进制表示构建的`n`。 

每个正整数都可以唯一地表示为 2 的幂和。 例如：

-`15 = 1 + 2 + 4 + 8`-`13 = 1 + 4 + 8`-`10 = 2 + 8`数组`powers`恰好包含出现在二进制分解中的 2 的幂`n`，按非降序排列。 

例如：

 - 如果`n = 15`， 然后`powers = [1, 2, 4, 8]`- 如果`n = 13`， 然后`powers = [1, 4, 8]`“2 的最小幂数”这句话很重要。 我们不允许不必要地分割权力。 例如，`8`应该保留`8`， 不是`4 + 4`。 因为二进制表示是唯一的，所以只有一个有效的`powers`大批。 

每个查询`[left, right]`询问产品：$$powers[left] \times powers[left+1] \times \cdots \times powers[right]$$答案可能会变得非常大，因此每个结果都必须以模数形式返回：$$10^9 + 7$$这些约束提供了重要的见解：

 -`n <= 10^9`-`queries.length <= 10^5`虽然可能有很多查询，但大小`powers`其实很小。 自从`n <= 10^9`，其二进制表示最多有 30 位。 这意味着`powers.length <= 30`。 

这极大地改变了问题。 由于数组很小，即使是简单的每次查询操作也变得负担得起。 

一些重要的边缘情况包括：

 -`n`是 2 的一次幂，例如`n = 8`- 仅涵盖一个元素的查询
 - 覆盖整个数组的查询
 - 大量查询
 - 包含空白的权力，例如`n = 10`生产`[2, 8]`该问题保证所有查询索引都是有效的。 

## 方法

 ### 蛮力方法

 最直接的解决办法是：

 1. 构建`powers`大批。 
2. 对于每个查询，将其中的所有元素相乘`left`到`right`。 
3. 乘法后应用模。 

例如，如果：```
powers = [1, 2, 4, 8]
query = [1, 3]
```我们计算：```
2 × 4 × 8 = 64
```这是正确的，因为它直接遵循查询的定义。 

但是，如果我们通过迭代请求的范围来处理每个查询，则总复杂度将变为：$$O(q \times m)$$在哪里：

-`q`是查询数
 -`m`的长度是`powers`虽然`m`这里很小，我们仍然可以使用前缀乘积或数学观察来改进解。 

### 关键见解

 中的每个元素`powers`本身就是二的幂。 

认为：```
powers = [2^a, 2^b, 2^c]
```然后：$$2^a \times 2^b \times 2^c = 2^{a+b+c}$$我们可以使用指数，而不是重复地乘以大数。 

例如：```
powers = [1, 2, 4, 8]
         [2^0, 2^1, 2^2, 2^3]
```一个查询`[1, 3]`对应于：$$2^1 \times 2^2 \times 2^3 = 2^{1+2+3} = 2^6 = 64$$那么问题就变成了：

 1. 提取所有设置位的指数`n`2. 构建指数前缀和
 3. 对于每个查询：

 - 计算 O(1) 中的指数和
 - 计算$2^{sum} \mod (10^9+7)$这样更干净、更高效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(q × m) | O(米) | 将每个查询的每个元素相乘 |
 | 最佳| O(m + q) | O(米) | 使用指数前缀和和快速模幂 |

 这里：

-`m = powers.length`-`q = queries.length`自从`m <= 30`，两者都是可以接受的，但最佳方法更加优雅和可扩展。 

## 算法演练

 1. 初始化一个空列表，名为`exponents`。 

该列表将存储设置位的位置`n`。 

例如：```
n = 13 = 1101₂
```设置位出现在以下位置：```
0, 2, 3
```所以：```
exponents = [0, 2, 3]
```2. 提取所有设置位`n`。 

从低到高迭代位位置。 

如果位`i`已设置，追加`i`到`exponents`。 

这是有效的，因为：```
2^i
```恰好对应于该位贡献的功率。 
3. 在指数上构建前缀和数组。 

认为：```
exponents = [0, 1, 2, 3]
```然后：```
prefix = [0, 0, 1, 3, 6]
```额外的前导零简化了范围计算。 
4. 处理每个查询。 

供查询`[left, right]`，计算：```
exponent_sum = prefix[right + 1] - prefix[left]
```这给出了该范围贡献的总指数。 
5. 计算最终产品。 

自从：$$2^a \times 2^b = 2^{a+b}$$答案是：$$2^{exponent\_sum} \mod (10^9+7)$$通过 Python 的内置功能使用快速模幂运算`pow`。 
6. 将结果附加到答案列表中。 
7. 返回最终答案列表。 

### 为什么它有效

 中的每个元素`powers`唯一地表示为$2^k$。 2 的幂相乘加上它们的指数：$$2^a \times 2^b = 2^{a+b}$$因此，每个查询乘积都可以简化为对一定范围内的指数求和。 前缀和允许在恒定时间内计算这些范围和，并且模幂有效地计算最终值。 

由于二元分解是唯一的，构造`powers`数组总是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def productQueries(self, n: int, queries: List[List[int]]) -> List[int]:
        MOD = 10**9 + 7

        exponents = []

        bit_position = 0
        while n > 0:
            if n & 1:
                exponents.append(bit_position)
            n >>= 1
            bit_position += 1

        prefix = [0]

        for exponent in exponents:
            prefix.append(prefix[-1] + exponent)

        answers = []

        for left, right in queries:
            exponent_sum = prefix[right + 1] - prefix[left]
            answers.append(pow(2, exponent_sum, MOD))

        return answers
```该实现首先从提取设置位`n`。 每个设置的位对应于 2 的幂，其位位置成为存储在`exponents`大批。 

循环：```python
while n > 0:
```从最低有效位到最高有效位处理二进制表示。 每当：```python
n & 1
```为 true，则设置当前位。 

接下来，代码构造一个前缀和数组。 额外的初始零使范围总和计算变得简单。 

对于每个查询，代码计算所请求的子数组贡献的总指数。 它不是单独乘幂，而是直接计算：```python
2^(sum of exponents)
```使用 Python 的高效模幂运算：```python
pow(base, exponent, mod)
```这使得实现简洁高效。 

## 解决方案```go
package main

func productQueries(n int, queries [][]int) []int {
	const MOD int = 1_000_000_007

	exponents := []int{}

	bitPosition := 0

	for n > 0 {
		if n&1 == 1 {
			exponents = append(exponents, bitPosition)
		}

		n >>= 1
		bitPosition++
	}

	prefix := make([]int, len(exponents)+1)

	for i, exponent := range exponents {
		prefix[i+1] = prefix[i] + exponent
	}

	answers := make([]int, 0, len(queries))

	for _, query := range queries {
		left := query[0]
		right := query[1]

		exponentSum := prefix[right+1] - prefix[left]

		answers = append(answers, modPow(2, exponentSum, MOD))
	}

	return answers
}

func modPow(base, exponent, mod int) int {
	result := 1

	base %= mod

	for exponent > 0 {
		if exponent&1 == 1 {
			result = (result * base) % mod
		}

		base = (base * base) % mod
		exponent >>= 1
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法。 由于 Go 没有提供与 Python 等效的内置模幂函数`pow(base, exp, mod)`，我们手动实现二进制求幂`modPow`。 

切片用于指数列表和前缀和。 由于最大位数非常小，因此内存使用量仍然很小。 

所有算术都安全地适合 Go 的内部`int`类型，因为中间值按模减少`1e9+7`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n`本身已经是2的幂了。 例如：```
n = 8
```这`powers`数组变为：```
[8]
```有缺陷的实现可能会错误地将其分成更小的权力，例如`[4, 4]`或者`[2, 2, 2, 2]`。 我们的实现避免了这种情况，因为它直接从二进制表示中提取设置位，这自然保留了最小分解。 

另一种重要的情况是查询恰好涵盖一个元素。 例如：```
queries = [[2, 2]]
```在这种情况下，乘积应该简单地等于该单一功率。 前缀和可以干净地处理这个问题，因为：```
prefix[right + 1] - prefix[left]
```仍然会产生单个位置的正确指数。 

第三种边缘情况涉及稀疏二进制表示，例如：```
n = 10
```二进制：```
1010₂
```powers 数组变为：```
[2, 8]
```指数之间存在间隙。 假设连续权力的幼稚实现在这里会失败。 我们的算法仅正确记录设置的位位置，因此稀疏表示自然有效。 

最后，该问题最多允许`10^5`查询。 在问题的较大变体中，为每个查询从头开始重新计算乘积可能会变得低效。 使用前缀和可确保每个查询在恒定时间内得到答复。
