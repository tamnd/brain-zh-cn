[LeetCode 问题 2445](https://leetcode.com/problems/number-of-nodes-with-value-one/)

 **难度：** 🟡 中等
 **主题：** 数组、树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题中的树不是通过边列表显式给出的。 相反，该结构是通过数学定义的。 每个节点`v`有父母`floor(v / 2)`，它创建与二叉堆相同的结构。 

例如：

 - 节点`2`和节点`3`是节点的子节点`1`- 节点`4`和节点`5`是节点的子节点`2`- 节点`6`和节点`7`是节点的子节点`3`该树包含标记为的节点`1`到`n`。 

最初，每个节点都存储值`0`。 

每个查询告诉我们翻转以特定节点为根的子树内的每个值。 翻转的意思：

 -`0 -> 1`-`1 -> 0`处理完所有查询后，我们必须返回有多少个节点包含值`1`。 

关键细节是查询影响整个子树，而不仅仅是单个节点。 由于一个节点可能属于多个查询子树，因此它的值取决于它被翻转的次数：

 - 翻转偶数次 -> 最终值`0`- 翻转奇数次 -> 最终值`1`约束条件很重要：

 -`n <= 10^5`-`queries.length <= 10^5`为每个查询显式遍历每个子树的简单方法可能会变得非常慢。 在最坏的情况下，子树可以包含几乎所有节点，产生接近的时间复杂度`O(n * q)`。 

该问题保证：

 - 树有效且已连接
 - 节点标签是连续的`1`到`n`- 每个查询都引用一个现有节点

 重要的边缘情况包括：

 - 对根节点的查询，翻转整个树
 - 同一节点上的重复查询
 - 叶节点查询
 - 附近非常深的节点`n`- 树不完整，因为`n`可能不是以下形式`2^k - 1`## 方法

 ### 蛮力方法

 最直接的解决方案是显式模拟每个查询。 

对于每个查询：

 1.查找以查询节点为根的子树中的所有节点
 2. 翻转该子树内的每个节点

 我们可以使用 DFS 或 BFS 来发现子树节点。 由于树遵循堆索引规则：

 - 的左孩子`x`是`2 * x`- 的右孩子`x`是`2 * x + 1`我们可以递归遍历所有后代。 

这种方法是正确的，因为它直接按照问题陈述中描述的方式执行操作。 

然而，它太慢了。 

考虑：

-`n = 100000`-`100000`查询
 - 许多针对大型子树的查询

 每个查询可能会访问几乎所有节点，导致大致`O(n * q)`操作，可以达到`10^10`。 

### 最佳方法

 重要的观察是我们实际上并不需要立即翻转子树节点。 

相反，我们可以从每个节点的角度思考：

 节点的最终值取决于有多少个查询子树包含该节点。 

一个节点属于它所有祖先的子树，包括它自己。 

所以对于一个节点`x`，它的值对于每个查询的祖先都会改变一次`x`。 

这导致了一个更有效的策略：

 1.统计每个节点在查询中出现的次数
 2.从根执行DFS
 3.向下遍历的同时，保持继承自祖先的累计翻转次数
 4、如果累计翻转次数为奇数，则当前节点结束为`1`这是可行的，因为子树翻转通过祖先关系自然向下传播。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * q) | O(n) | 显式翻转每个子树 |
 | 最佳| O(n + q) | O(n) | 在 DFS 期间使用累积翻转传播 |

 ## 算法演练

 1. 创建一个名为`flip_count`尺寸的`n + 1`。`flip_count[x]`存储有多少个直接针对节点的查询`x`。 
2. 处理所有查询。 

对于每个查询节点`q`，增量：```
flip_count[q] += 1
```我们还没有翻转任何东西。 我们只记录每个节点发生的翻转次数。 
3.从根节点启动DFS`1`。 

在DFS期间，维护一个名为`current_flips`。 

这表示到目前为止遇到的所有祖先影响当前节点的翻转次数。 
4. 访问节点时`x`，计算：```
total_flips = current_flips + flip_count[x]
```这包括：

 - 继承自祖先的翻转
 - 在当前节点发起翻转
 5. 确定节点的最终值`x`。 

如果`total_flips`为奇数，节点以 value 结尾`1`。 

如果是偶数，则节点以值结束`0`。 
6. 递归访问孩子。 

由于这是一棵堆式树：

 - 左孩子=`2 * x`- 右孩子=`2 * x + 1`仅当子标签为时才递归`<= n`。 
7. 通过`total_flips`向下。 

每个后代都会继承影响当前节点的所有翻转。 
8. 计算有多少节点以奇数翻转计数结束。 

DFS 完成后返回此计数。 

### 为什么它有效

 子树翻转会影响查询节点的所有后代，包括其自身。 在 DFS 期间，每个节点都会累积源自其祖先的所有翻转。 由于节点恰好属于以其祖先为根的子树，因此累积翻转计数恰好等于该节点应翻转的次数。 节点结束为`1`当且仅当该计数为奇数时。 

## Python 解决方案```python
from typing import List

class Solution:
    def numberOfNodes(self, n: int, queries: List[int]) -> int:
        flip_count = [0] * (n + 1)

        for node in queries:
            flip_count[node] += 1

        result = 0

        def dfs(node: int, inherited_flips: int) -> None:
            nonlocal result

            if node > n:
                return

            total_flips = inherited_flips + flip_count[node]

            if total_flips % 2 == 1:
                result += 1

            dfs(node * 2, total_flips)
            dfs(node * 2 + 1, total_flips)

        dfs(1, 0)

        return result
```该实现首先计算每个节点发起的翻转操作数。 该算法不会立即模拟子树更新，而是将所有工作推迟到 DFS 遍历为止。 

递归DFS函数接收两个参数：

 -`node`,当前节点标签
 -`inherited_flips`，从祖先遗传下来的翻转次数

 在每个节点，该算法使用以下方式添加本地启动的翻转：```python
total_flips = inherited_flips + flip_count[node]
```如果`total_flips`为奇数，节点以值结束`1`，因此结果计数器增加。 

然后，递归将更新的翻转计数传播给两个子级。 因为每个后代都会继承所有祖先翻转，所以这自然会模拟子树操作，而无需显式修改子树节点。 

每当节点标签超过时，递归就会停止`n`，因为树中不存在这样的节点。 

## 解决方案```go
func numberOfNodes(n int, queries []int) int {
    flipCount := make([]int, n+1)

    for _, node := range queries {
        flipCount[node]++
    }

    result := 0

    var dfs func(int, int)

    dfs = func(node int, inheritedFlips int) {
        if node > n {
            return
        }

        totalFlips := inheritedFlips + flipCount[node]

        if totalFlips%2 == 1 {
            result++
        }

        dfs(node*2, totalFlips)
        dfs(node*2+1, totalFlips)
    }

    dfs(1, 0)

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一些特定于 Go 的细节：

 - 使用切片代替 Python 列表
 - 递归函数使用函数变量声明
 - 整数溢出不是问题，因为值保持在标准整数限制内
 - Go 没有`nonlocal`， 所以`result`被闭包自然捕获

 ## 边缘情况

 查询根节点时会出现一种重要的边缘情况。 由于根的子树包含整个树，因此每个节点都必须翻转。 幼稚的实现可能会重复遍历整个树来进行此类查询，从而导致严重的性能问题。 优化的解决方案自然地处理了这个问题，因为根的翻转计数在 DFS 期间简单地传播到所有后代。 

另一个重要的情况涉及同一节点上的重复查询。 由于翻转两次会抵消，直接切换值的实现可能会变得容易出错或效率低下。 该算法通过数学方式跟踪翻转计数并使用检查奇偶校验来完全避免此问题`total_flips % 2`。 

当出现第三种边缘情况时`n`不能形成完美的二叉树。 例如，`n = 10`意味着一些潜在的孩子不存在。 每当子标签超过时，递归遍历必须小心停止`n`。 该实现在处理节点之前显式检查此条件，以防止无效访问。 

最后一个微妙的情况涉及叶节点。 叶子子树仅包含节点本身。 某些实现错误地假设每个节点都有子节点，并且可能会尝试无效的递归。 边界条件`if node > n: return`确保不存在的孩子被安全地忽略。
