[LeetCode 第 2296 题](https://leetcode.com/problems/design-a-text-editor/)

 **难度：** 🔴难
 **主题：** 链表、字符串、堆栈、设计、模拟、双向链表

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个简化的文本编辑器，支持四种操作：

 1. 在当前光标位置插入文本
 2.删除光标左侧的字符
 3. 向左移动光标
 4. 向右移动光标

 光标的行为与普通文本编辑器中的光标完全相同。 它始终位于字符之间，并且其位置必须保持在文本的有效范围内。 

例如：

-`"abc|"`表示光标在末尾
 -`"|abc"`表示光标在开头
 -`"ab|cd"`表示光标位于`b`和`c`重要的细节是所有编辑操作都是相对于光标进行的。 

这`addText(text)`操作在光标位置插入给定字符串，然后将光标移动到插入文本的末尾。 

这`deleteText(k)`操作模拟按退格键最多`k`次。 只能删除光标左侧的字符。 该函数返回实际删除的字符数。 

这`cursorLeft(k)`操作最多将光标向左移动`k`职位。 如果光标到达文本的开头，它将停在那里。 移动后，我们必须返回光标左侧最后存在的 10 个字符。 

这`cursorRight(k)`操作的行为类似，只是光标向右移动。 

限制相对较小：

 - 每个插入的字符串长度最多为 40
 - 每个移动或删除参数最多为40个
 - 至多`2 * 10^4`操作发生

 尽管约束并不大，但该问题明确要求`O(k)`后续每个操作解决方案。 这强烈表明我们应该避免重复重建整个字符串。 

一些边缘情况很重要：

 - 删除的字符多于光标左侧存在的字符
 - 将光标移到开头之外
 - 将光标移到末尾
 - 当左侧较短时返回少于 10 个字符
 - 在最初为空的编辑器上操作

 使用重复字符串切片的简单实现可能会在这些约束下工作，但它在概念上效率低下，并且不能满足预期的后续复杂性。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将整个文本存储为单个字符串并维护一个整数游标索引。 

对于插入：

 - 将字符串拆分为光标周围的左右部分
 - 在中间插入新文本
 - 重建整个字符串

 对于删除：

 - 删除最多`k`光标前的字符
 - 再次重建字符串

 对于光标移动：

 - 更新光标索引
 - 提取左侧最后 10 个字符

 这种方法很容易理解和实施。 每个操作都直接操作实际的文本表示。 

然而，字符串在 Python 和 Go 中是不可变的。 重复重建字符串会导致大量的复制开销。 如果文本变大，每次插入和删除可能都需要复制整个字符串。 

尽管给定的约束足够小，可以通过，但它不符合预期的后续复杂性。 

### 最佳方法

 关键的观察是光标自然地将文本分为两半：

 - 光标左侧的字符
 - 光标右侧的字符

 我们可以维护两个堆栈，而不是存储一个大字符串：

 -`left`，包含光标左侧的字符
 -`right`，包含光标右侧的字符

 从概念上讲，光标位于这两个堆栈之间。 

例如：```
left = ['a', 'b', 'c']
right = ['f', 'e', 'd']
```代表：```
abc|def
```请注意，右侧堆栈以相反的顺序存储，因此我们可以有效地在堆栈之间移动字符。 

这种设计使每个操作都本地化：

 - 插入内容附加到`left`- 删除弹出`left`- 向左移动将字符从`left`到`right`- 向右移动将字符从`right`到`left`每个操作仅涉及受影响的字符，这给出了`O(k)`复杂。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次操作 O(n) | O(n) | 重复重建整个字符串 |
 | 最佳| 每次操作 O(k) | O(n) | 在光标周围使用两个堆栈 |

 ## 算法演练

 ### 数据结构设计

 我们维护两个堆栈：

 -`left`, 光标前的字符
 -`right`, 光标后的字符，按倒序存储

 光标始终存在于它们之间。 

如果：```
left = ['l', 'e', 'e', 't']
right = ['e', 'd', 'o', 'c']
```那么实际的文本是：```
leet|code
```### 逐步算法

 1. 初始化两个空堆栈。 

编辑器开始时没有文本，因此光标两侧都是空的。 
2. 手柄`addText(text)`。 

对于每一个角色`text`，将其附加到`left`。 

这是有效的，因为插入的文本总是出现在光标之前，并且插入后光标移动到新文本的末尾。 
3. 手柄`deleteText(k)`。 

重复弹出字符`left`直到：

 -`k`字符被删除
 -`left`变空

 计算实际删除了多少个字符并返回该值。 
4. 手柄`cursorLeft(k)`。 

通过传输字符将光标向左移动`left`到`right`。 

每个动作：

 - 从中弹出一个字符`left`- 将其推到`right`如果出现以下任一情况，请停止：

 -`k`动作已完成
 -`left`变空
 5. 手柄`cursorRight(k)`。 

通过传输字符向右移动光标`right`到`left`。 

每个动作：

 - 从中弹出一个字符`right`- 将其推到`left`如果出现以下任一情况，请停止：

 -`k`动作已完成
 -`right`变空
 6. 返回光标左侧的最后 10 个字符。 

自从`left`以正确的顺序存储光标之前的所有字符，答案很简单：```
''.join(left[-10:])
```### 为什么它有效

 不变量是：

 -`left`始终包含光标之前的字符
 -`right`始终精确包含光标后的字符（按相反顺序）

 每个操作都保留这个不变量：

 - 插入仅延伸左侧
 - 删除仅从左侧删除
 - 光标移动在两侧之间传输字符而不改变文本顺序

 由于不变量始终成立，因此每次操作后编辑器状态都保持正确。 

## Python 解决方案```python
class TextEditor:

    def __init__(self):
        self.left = []
        self.right = []

    def addText(self, text: str) -> None:
        for ch in text:
            self.left.append(ch)

    def deleteText(self, k: int) -> int:
        deleted = 0

        while self.left and deleted < k:
            self.left.pop()
            deleted += 1

        return deleted

    def cursorLeft(self, k: int) -> str:
        moves = 0

        while self.left and moves < k:
            self.right.append(self.left.pop())
            moves += 1

        return ''.join(self.left[-10:])

    def cursorRight(self, k: int) -> str:
        moves = 0

        while self.right and moves < k:
            self.left.append(self.right.pop())
            moves += 1

        return ''.join(self.left[-10:])
```实现直接遵循两栈设计。 

构造函数初始化两个充当堆栈的空列表。 

这`addText`方法将字符附加到`left`，因为插入的文本立即出现在光标之前。 

这`deleteText`方法反复弹出`left`。 这自然会删除光标左侧的字符，就像退格行为一样。 

光标移动方法在两个堆栈之间传输字符。 向左移动会从左侧删除一个字符并将其放置在右侧。 向右移动执行相反的操作。 

最后，两种移动方法都会返回最后 10 个字符`left`， 自从`left`始终存储光标之前的确切文本。 

## 解决方案```go
type TextEditor struct {
	left  []byte
	right []byte
}

func Constructor() TextEditor {
	return TextEditor{
		left:  []byte{},
		right: []byte{},
	}
}

func (this *TextEditor) AddText(text string) {
	for i := 0; i < len(text); i++ {
		this.left = append(this.left, text[i])
	}
}

func (this *TextEditor) DeleteText(k int) int {
	deleted := 0

	for len(this.left) > 0 && deleted < k {
		this.left = this.left[:len(this.left)-1]
		deleted++
	}

	return deleted
}

func (this *TextEditor) CursorLeft(k int) string {
	moves := 0

	for len(this.left) > 0 && moves < k {
		ch := this.left[len(this.left)-1]
		this.left = this.left[:len(this.left)-1]
		this.right = append(this.right, ch)
		moves++
	}

	start := 0
	if len(this.left) > 10 {
		start = len(this.left) - 10
	}

	return string(this.left[start:])
}

func (this *TextEditor) CursorRight(k int) string {
	moves := 0

	for len(this.right) > 0 && moves < k {
		ch := this.right[len(this.right)-1]
		this.right = this.right[:len(this.right)-1]
		this.left = append(this.left, ch)
		moves++
	}

	start := 0
	if len(this.left) > 10 {
		start = len(this.left) - 10
	}

	return string(this.left[start:])
}
```Go 实现密切反映了 Python 逻辑。 

Go 使用的不是 Python 列表`[]byte`切片作为堆栈。 由于输入仅包含小写英文字母，因此字节就足够了，并且比符文切片更高效。 

从切片末尾添加和删除可以提供高效的堆栈行为。 

子串提取是通过切片来处理的`left[start:]`并将其转换为字符串。 

Go 在这里不需要对整数溢出进行任何特殊处理，因为所有约束都很小。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每次操作 O(k) | 每个操作最多移动、插入或删除`k`人物 |
 | 空间| O(n) | 所有字符在两个堆栈中只存储一次 |

 重要的观察是每个操作仅操作直接受影响的角色。 我们永远不会重建整个文本字符串。 因为每次光标移动或删除最多处理`k`字符，每个操作都以相对于请求的工作量的线性时间运行。 

总空间使用量与总文本大小呈线性关系，因为每个字符恰好存在于两个堆栈之一中。

 ## 边缘情况

 当删除的字符多于光标左侧存在的字符时，会出现一种重要的边缘情况。 有缺陷的实现可能会尝试删除不存在的字符并导致崩溃。 我们的实现通过一旦删除就停止删除来避免这种情况`left`堆栈变空。 返回值准确反映了实际删除的字符数。 

当将光标移动到文本边界之外时会发生另一个重要情况。 例如，调用`cursorLeft(100)`当左侧仅存在 3 个字符时。 一旦没有更多的角色可用，该算法就会安全地停止移动。 同样的逻辑对称地适用于`cursorRight`。 

一个微妙的边缘情况涉及将最后 10 个字符返回到光标左侧。 如果存在的字符少于 10 个，我们必须仅返回可用的字符。 切片操作`left[-10:]`在 Python 中自然可以正确处理这个问题，并且 Go 实现在切片之前计算一个安全的起始索引。 

最后一个重要的情况是在现有内容的中间插入文本。 两堆栈结构自然地处理了这个问题，因为光标位置是由堆栈之间的分割表示的。 新插入的字符只是附加到`left`，这会将它们精确地放置在光标位置，而无需重建整个文本。
