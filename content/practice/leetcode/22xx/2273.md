[LeetCode 问题 2273](https://leetcode.com/problems/find-resultant-array-after-removing-anagrams/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们在两个**相邻单词互为字母异位词**时重复从数组中删除单词。 

我们被赋予了一个`0-indexed`字符串数组`words`，其中每个字符串仅包含小写英文字母。 在每次操作过程中，我们可以选择一个索引`i`这样这个词在`words[i]`是紧接在其之前的单词的变位词，`words[i - 1]`。 当这个条件成立时，我们删除`words[i]`从数组中。 

该过程持续进行，直到没有相邻的单词对形成字谜关系。 

重要的细节是，该问题保证**最终结果与删除顺序无关**。 这意味着我们不需要模拟每个可能的删除序列。 相反，我们只需要确定哪些单词在最终数组中保留下来。 

简单地说，我们想要扫描单词并仅保留一个单词**不是最近保留的单词的字谜**。 

输入包括：

 -`words`，小写字符串列表。 

预期输出是：

 - 包含重复删除相邻字谜后保留的单词的新列表。 

限制非常小：

 -`1 <= words.length <= 100`-`1 <= words[i].length <= 10`由于单词数量和单词长度都很小，因此即使有些低效的方法也可以工作。 然而，我们仍然应该寻求一个干净、高效的解决方案。 

预先考虑几个边缘情况很重要。 连续的字谜链可能很棘手，因为删除一个单词会改变邻接关系。 例如，`["abba","baba","bbaa"]`应该减少到仅`["abba"]`，因为所有单词都是彼此的字谜。 另一种情况是根本没有发生任何删除操作，例如`["a","b","c"]`。 我们还需要正确处理重复的相同单词，因为相同的字符串也是字谜词，例如`["cd","cd"]`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是重复模拟删除过程。 

我们可以重复扫描数组并查找相邻的字谜词。 每当我们找到一个单词时，我们都会删除第二个单词并重新开始扫描。 为了确定两个单词是否是字谜词，我们对它们的字符进行排序并比较排序后的版本。 

这种方法是正确的，因为它完全遵循问题陈述，重复删除相邻的字谜，直到没有有效的移动剩余。 

然而，它的效率很低，因为每次删除都会移动数组元素，并且重复重新扫描会增加总工作量。 在最坏的情况下，我们可能会在每次删除后重复遍历几乎整个列表。 

### 最佳解决方案的关键见解

 关键的观察是**我们只关心最近保存的单词**。 

假设我们已经构建了结果数组。 处理新单词时：

 - 如果它是最近保留的单词的字谜，它最终会被删除。 
- 否则，它会生存并成为最终结果的一部分。 

因为最终答案与删除顺序无关，所以我们不需要模拟删除。 相反，我们可以贪婪地从左到右构建答案。 

为了有效地比较单词，我们为每个单词计算一个**规范表示**。 最简单的选择是字符串的排序版本。 当且仅当两个单词的排序形式相同时，它们才是字谜词。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²·k log k) | O(n²·k log k) | O(n) | 反复删除相邻的字谜并重新扫描 |
 | 最佳| O(n·k log k) | O(n·k log k) | O(n) | 单次通过，仅与之前保存的单词进行比较 |

 这里：

-`n`是单词数。 
-`k`是最大字长。 

自从`k <= 10`，对每个单词进行排序的成本非常低。 

## 算法演练

 1. 创建一个空结果列表来存储存活下来的单词。 
2. 遍历每个单词`words`从左到右。 
3. 对于当前单词，计算其排序表示。 这充当其字谜签名。 例如：

-`"abba"`变成`"aabb"`-`"baba"`变成`"aabb"`4. 如果结果列表为空，则添加当前单词，因为没有之前的单词可供比较。 
5. 否则，将当前单词的签名与最近保留的单词的签名进行比较。 

- 如果它们匹配，则当前单词是前一个保留单词的变位词，因此跳过它。 
- 如果它们不同，则将单词附加到结果列表中。 
6. 继续，直到处理完所有单词。 
7. 返回结果列表。 

### 为什么它有效

 核心不变性是结果列表始终包含迄今为止处理的数组部分的正确最终单词。 

每当一个单词是最近保留的单词的变位词时，它最终都会被问题的运算规则删除，因此跳过它是安全的。 如果它不是字谜词，则不能被任何较早的单词删除，因此它必须保留。 由于最终结果与删除顺序无关，因此贪婪地构建结果会产生相同的最终数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def removeAnagrams(self, words: List[str]) -> List[str]:
        def get_signature(word: str) -> str:
            return "".join(sorted(word))

        result = []
        previous_signature = ""

        for word in words:
            current_signature = get_signature(word)

            if current_signature != previous_signature:
                result.append(word)
                previous_signature = current_signature

        return result
```实现首先定义一个辅助函数`get_signature`，它将单词转换为其排序的字符形式。 由于字谜词共享相同的排序表示，这为我们提供了一个简单的比较机制。 

然后我们初始化一个空的`result`列表和一个`previous_signature`多变的。 该变量存储最近保存的单词的签名。 

当我们迭代每个单词时，我们计算它的签名。 如果它与之前保留的签名不同，则该单词将保留并附加到结果中。 我们还更新了`previous_signature`。 

如果签名匹配，则该单词是前一个保留单词的字谜，最终将被删除，因此我们跳过它。 

该实现遵循算法演练中描述的精确贪婪逻辑，并一次性处理输入。 

## 解决方案```go
import (
	"sort"
)

func removeAnagrams(words []string) []string {
	getSignature := func(word string) string {
		chars := []rune(word)

		sort.Slice(chars, func(i, j int) bool {
			return chars[i] < chars[j]
		})

		return string(chars)
	}

	result := []string{}
	prevSignature := ""

	for _, word := range words {
		currentSignature := getSignature(word)

		if currentSignature != prevSignature {
			result = append(result, word)
			prevSignature = currentSignature
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于Go没有内置的字符串排序功能，因此我们将单词转换为符文切片并使用`sort.Slice`。 

结果存储在切片中，并且`prevSignature`跟踪最后一个幸存单词的字谜签名。 

由于输入仅包含小写英文字母和非常短的字符串，因此无需担心整数溢出或内存压力。 Go 自然会处理空切片和 nil 切片，即使结果开始为空，追加也能正常工作。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n·k log k) | O(n·k log k) | 每个单词排序一次 |
 | 空间| O(n) | 结果列表加上临时排序的字符串 |

 该算法对每个单词只处理一次。 对于每个单词，我们对其字符进行排序，这会花费`O(k log k)`在哪里`k`是字长。 由于有`n`换句话说，总时间复杂度变为`O(n · k log k)`。 

空间复杂度为`O(n)`因为结果列表可能包含最坏情况下的每个单词。 用于排序的附加临时存储与字长成正比。

 ## 边缘情况

 ### 单字输入

 当输入仅包含一个单词时，没有可比较的相邻元素。 粗心的实现可能会错误地假设至少存在两个单词并尝试进行无效的比较。 

例如：```
["hello"]
```该实现自然地处理了这个问题，因为第一个单词总是添加到结果列表中。 

### 长链连续字谜

 许多连续单词都是字谜词的序列可能会很棘手，因为重复删除会改变邻接关系。 

例如：```
["ab", "ba", "ab", "ba"]
```A naive simulation may become complicated due to repeated list modifications. The greedy approach handles this cleanly by keeping only the first word and skipping every subsequent word whose signature matches the previous kept word.

 ### Non-Adjacent Anagrams

The problem only removes **adjacent** anagrams, not all anagrams in the array.

 例如：```
["abc", "xyz", "zyx", "abc"]
```尽管第一个和最后一个单词是字谜词，但它们并不相邻。 移除后`"zyx"`，最后一个`"abc"`仅与`"xyz"`并生存下来。 该实现仅与最近保留的单词进行正确比较。
