[LeetCode 问题 2201](https://leetcode.com/problems/count-artifacts-that-can-be-extracted/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、模拟

 ## 解决方案

 ## 问题理解

 该问题模拟了正方形上的挖掘过程`n x n`网格。 网格中埋藏着多个矩形工件，每个工件占据一个或多个单元。 每个工件都由四个整数描述：

 -`(r1, c1)`代表左上角
 -`(r2, c2)`代表右下角

 这意味着伪影占据了该矩形区域内的每个单元格。 

您还会获得数组中挖掘出的单元格的列表`dig`。 每个条目`[r, c]`意味着细胞`(r, c)`已经被挖出来并被发现了。 

只有挖掘出文物所占据的每个单元格后才能提取文物。 您的任务是计算有多少工件满足此条件。 

重要的细节是工件永远不会重叠。 这保证了一个单元最多属于一个工件，从而显着简化了逻辑。 

这些约束告诉我们一些重要的事情：

 -`n`可以大到`1000`，因此网格最多可以包含`1,000,000`细胞。 
-`artifacts.length`和`dig.length`每个都可以大到`100,000`。 
- 每个神器最多覆盖`4`细胞。 

最后一个限制非常重要。 尽管网格可能非常大，但每个工件都很小。 这使我们能够直接检查工件的所有单元，而不必担心过多的工作。 

输入保证：

 - 没有重叠的工件
 - 独特的挖掘位置
 - 有效坐标
 - 矩形形状正确

 一些边缘情况值得预先考虑。 

工件可能占据单个单元。 在这种情况下，提取它只需要一个单元格出现在`dig`。 

有些文物可能只挖掘了部分区域。 这些一定不能算在内。 

网格本身可能很大，但挖掘得非常稀疏。 扫描整个网格的简单解决方案会浪费大量的时间和内存。 

另一个微妙的情况是根本无法提取任何工件。 该算法仍应正确返回`0`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是模拟整个网格。 

我们可以创建一个完整的`n x n`代表挖掘细胞的矩阵。 然后，对于每个工件，迭代其矩形内的每个单元并验证是否所有单元都被挖掘。 

这种方法是正确的，因为它直接检查提取所需的条件：每个占用的单元格必须出现在`dig`。 

然而，当`n`很大。 构建和扫描大型网格会浪费内存，因为大多数单元格都是不相关的。 

例如，当`n = 1000`，网格包含一百万个单元。 尽管这在某些语言中是可以管理的，但这是不必要的，因为工件仅覆盖极少数的单元格。 

### 最佳方法

 关键的观察是我们永远不需要处理整个网格。 

相反，我们只关心挖掘的位置和文物占据的单元格。 

我们可以将每个挖掘的单元存储在哈希集中，以进行恒定时间查找。 然后，对于每个工件，我们检查它所占据的每个单元格是否存在于集合中。 

因为每个工件最多覆盖`4`细胞，这种验证非常便宜。 

这将问题转化为有效的成员资格测试：

 - 转换`dig`到一个哈希集合中
 - 对于每个神器：

 - 枚举其单元格
 - 检查集合中是否全部存在

 这种方法避免了构建完整的网格并有效地扩展到问题约束。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² + A × S) | O(n²) | 构建并扫描完整网格 |
 | 最佳| O(D + A × S) | O(D) | 使用哈希集进行恒定时间查找 |

 在哪里：

-`A`= 工件数量
 -`D`= 挖出的细胞数
 -`S`= 每个工件最多的最大单元数`4`自从`S`受常数限制，最优复杂度实际上变为线性。 

## 算法演练

 ### 步骤 1：将所有挖掘出的单元存储在哈希集中

 我们首先将每个坐标转换为`dig`放入元组并将其插入哈希集。 

这允许恒定时间的成员资格检查。 

例如：```
dig = [[0,0], [0,1]]
```变成：```
dug_cells = {(0,0), (0,1)}
```使用哈希集很重要，因为我们反复需要回答：

 > “这个牢房已经被挖掘出来了吗？”

 一组给出平均值`O(1)`查找时间。 

### 步骤 2：独立处理每个工件

 每个工件的定义如下：```
[r1, c1, r2, c2]
```这意味着工件占据了每个单元格：```
r1 <= r <= r2
c1 <= c <= c2
```我们迭代这个矩形中的所有单元格。 

### 步骤 3：验证是否所有单元格均已挖掘

 对于工件占用的每个单元，我们检查它是否存在于哈希集中。 

即使缺少一个细胞，也无法提取工件。 

如果所有单元格都存在，我们就增加答案。 

### 第 4 步：返回最终计数

 处理完每个工件后，累积计数代表可提取工件的数量。 

### 为什么它有效

 该算法直接检查提取所需的确切条件。 

当且仅当属于文物的每个单元都被挖掘出来时，文物才是可提取的。 哈希集准确地记录了所有挖掘的单元，并且我们验证每个工件的每个占用的单元。 

由于工件不重叠，因此可以独立评估每个工件。 因此，计算所有完全出土的文物就可以得出正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def digArtifacts(self, n: int, artifacts: List[List[int]], dig: List[List[int]]) -> int:
        dug_cells = set()

        for row, col in dig:
            dug_cells.add((row, col))

        extracted_count = 0

        for r1, c1, r2, c2 in artifacts:
            can_extract = True

            for row in range(r1, r2 + 1):
                for col in range(c1, c2 + 1):
                    if (row, col) not in dug_cells:
                        can_extract = False
                        break

                if not can_extract:
                    break

            if can_extract:
                extracted_count += 1

        return extracted_count
```实现首先将`dig`数组放入名为的哈希集`dug_cells`。 这在检查单元格是否已被挖掘时提供了恒定的时间查找。 

接下来，我们迭代每个工件。 对于每个工件，我们枚举其矩形边界内的所有单元。 

嵌套循环：```python
for row in range(r1, r2 + 1):
    for col in range(c1, c2 + 1):
```访问每个被占用的单元格。 

如果任何细胞不存在于`dug_cells`，无法提取该工件，因此我们立即停止检查该工件。 

如果所有单元都通过了成员资格测试，我们就增加`extracted_count`。 

最后，我们返回完全挖掘的文物总数。 

## 解决方案```go
func digArtifacts(n int, artifacts [][]int, dig [][]int) int {
	dugCells := make(map[[2]int]bool)

	for _, cell := range dig {
		row, col := cell[0], cell[1]
		dugCells[[2]int{row, col}] = true
	}

	extractedCount := 0

	for _, artifact := range artifacts {
		r1, c1 := artifact[0], artifact[1]
		r2, c2 := artifact[2], artifact[3]

		canExtract := true

		for row := r1; row <= r2 && canExtract; row++ {
			for col := c1; col <= c2; col++ {
				if !dugCells[[2]int{row, col}] {
					canExtract = false
					break
				}
			}
		}

		if canExtract {
			extractedCount++
		}
	}

	return extractedCount
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

Go 使用固定大小的长度数组，而不是 Python 元组`2`作为地图键：```go
map[[2]int]bool
```这是可行的，因为数组在 Go 中是可比较的，因此可以用作哈希映射键。 

嵌套循环迭代每个工件的矩形，与 Python 版本中完全相同。 

Go 不需要对整数溢出进行任何特殊处理，因为所有值都在标准整数范围内。

 ## 边缘情况

 一个重要的边缘情况是单细胞伪影。 由于工件恰好占据一个坐标，因此提取完全取决于该坐标是否出现在`dig`。 某些实现意外地假设工件始终跨越多个单元，但此解决方案统一处理这两个单元，因为每个工件都是通过相同的嵌套循环逻辑处理的。 

另一个重要案例是部分出土的多细胞文物。 例如，一个`2 x 2`文物可能包含三个被挖掘的单元和一个缺失的单元。 如果有缺陷的实现仅跟踪全局挖掘单元的数量而不是检查确切的坐标，则可能会错误地计算它。 此实现通过单独验证每个占用的单元来避免该问题。 

第三种边缘情况是一个非常大的网格，其中挖掘的单元很少。 构建一个完整的`1000 x 1000`在这种情况下，矩阵是不必要的且效率低下。 哈希集方法仅存储实际挖掘的坐标，因此内存使用量取决于挖掘的数量而不是总网格大小。 

当无法提取伪影时，会出现另一种微妙的边缘情况。 某些实现可能会意外地错误地初始化计数器或在完全验证所有单元之前过早地增加结果。 此实现仅在确认哈希集中存在每个占用的坐标后才增加答案。
