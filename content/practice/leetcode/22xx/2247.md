[LeetCode 问题 2247](https://leetcode.com/problems/maximum-cost-of-trip-with-k-highways/)

 **难度：** 🔴难
 **主题：** 动态规划、位操作、图论、位掩码

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个无向加权图`n`城市和高速公路列表。 每条高速公路连接两个城市并有相关的通行费。 我们必须找到一次行程的最大可能总通行费，该行程恰好使用`k`高速公路。 

有两个重要的限制：

 1.我们可以从任何城市开始。 
2. 每个城市最多只能访问一次。 

第二个条件意味着行程必须是一条简单的路径，而不是具有重复顶点的行走。 由于正好遍历`k`高速公路意味着行程恰好包含`k + 1`不同的城市，我们正在有效地寻找长度最大的权重简单路径`k`。 

输入包括：

 -`n`, 城市数量
 -`highways`，其中每个条目`[u, v, w]`意味着之间存在无向边`u`和`v`有重量`w`-`k`，必须遍历的确切边数

 输出是：

 - 准确使用所有有效路径中的最大可能总通行费`k`高速公路
 -`-1`如果不存在这样的路径

 约束条件是选择算法最重要的线索：

 -`n <= 15`-`highways.length <= 50`-`k <= 50`的小值`n`立即表明涉及子集或位掩码的指数算法是可行的。 自从`2^15 = 32768`，子集上的动态规划变得实用。 

同时，`k`可以大到`50`，它比`n - 1`。 因为我们无法重访城市，所以最长的有效路径最多包含`n - 1`边缘。 因此：

 - 如果`k >= n`，答案自动`-1`一些边缘情况很重要：

 - 图表可能已断开。 
- 可能没有完全包含的路径`k`边缘。 
- 最佳路径可能从任何城市开始。 
- 某些边缘可能具有零成本。 
- 由于城市无法重复，因此禁止骑自行车，即使这会增加成本。 

探索所有简单路径的朴素 DFS 很快就会变得太慢，因为可能的简单路径的数量呈指数增长。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用深度优先搜索尝试所有可能的简单路径。 

我们可以从每个城市启动DFS。 在搜索过程中：

 - 跟踪访问过的城市
 - 跟踪已使用的高速公路数量
 - 累计当前的通行费
 - 每当准确时更新全局最大值`k`使用高速公路

 这种方法是正确的，因为它显式枚举了每个长度有效的简单路径`k`。 

然而，复杂性极高。 在最坏的情况下，图是密集的，每个递归调用都可能分支到许多未访问的邻居。 简单路径的数量大致呈阶乘增长。 

为了`n = 15`，这变得不切实际。 

### 最优方法，位掩码动态规划

 关键的观察是`n`非常小。 

每当我们看到`n <= 15`，子集动态规划成为强有力的候选者。 由于我们无法重新访问城市，因此访问过的城市完全代表了该州的重要组成部分。 

我们基于以下条件定义 DP 状态：

 - 已经访问过哪些城市
 - 我们目前在哪个城市

 具体来说：

 -`dp[mask][u]`表示一条路径的最大通行费：

 - 准确访问以下城市`mask`- 结束于城市`u`中的每一位`mask`表示是否访问过某个城市。 

来自一个州`(mask, u)`，我们尝试将路径扩展到每个未访问过的邻居`v`。 

这是有效的，因为：

 - 禁止重访条件自然由位掩码强制执行
 - 每个有效的简单路径都对应于一个转换序列
 - 状态数量是可控的：

 -`2^15 * 15 ≈ 500,000`我们只关心设置位数等于的掩码`k + 1`，因为一条路径`k`边包含`k + 1`城市。

 ## 算法演练

 ### 第 1 步，构建图表

 将高速公路列表转换为邻接列表。 

对于每一条高速公路`[u, v, w]`：

- 添加`(v, w)`到`u`- 添加`(u, w)`到`v`由于图是无向的，因此两个方向都必须存在。 

### 步骤 2，尽早处理不可能的情况

 有效路径`k`高速公路需要`k + 1`不同的城市。 

由于只有`n`城市：

 - 如果`k >= n`， 返回`-1`不存在有效的简单路径。 

### 步骤 3，定义 DP 状态

 我们创造：```
dp[mask][u]
```这存储路径的最大成本：

 - 准确访问以下城市`mask`- 结束于城市`u`如果状态不可达，则存储`-1`。 

掩码是一个二进制数：

 - 位`i`是`1`如果城市`i`已被访问过

 示例：```
mask = 10101
```意味着城市`0`,`2`， 和`4`被访问。 

### 步骤4，初始化单城市路径

 每个城市都可以作为起点。 

对于每个城市`i`：```
dp[1 << i][i] = 0
```仅包含一个城市的路径有成本`0`。 

### 步骤 5，状态之间的转换

 对于每个州`(mask, u)`：

 - 尝试每个邻居`(v, w)`的`u`- 如果`v`已访问过，跳过
 - 否则：

 - 创建：```
new_mask = mask | (1 << v)
```- 更新：```
dp[new_mask][v] =
    max(dp[new_mask][v], dp[mask][u] + w)
```这将当前路径延伸了一个边缘。 

### 第 6 步，提取答案

 一条完全符合的路径`k`高速公路恰好包含`k + 1`城市。 

因此：

 - 迭代所有蒙版
 - 仅考虑带有`k + 1`设置位
 - 检查每个结局城市

 这些状态中的最大值就是答案。 

如果不存在有效状态，则返回`-1`。 

### 为什么它有效

 DP 状态完全捕获继续构建有效路径所需的所有信息：

 - 访问过的集合保证不会再次访问任何城市
 - 结束城市决定接下来可以采取哪些边

 每个简单路径恰好对应于一个 DP 转换序列，并且每个 DP 转换都会生成一条有效的简单路径。 由于我们在转换期间最大化总成本，因此最终答案是所有长度有效路径中的最大可能费用`k`。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumCost(self, n: int, highways: List[List[int]], k: int) -> int:
        if k >= n:
            return -1

        graph = [[] for _ in range(n)]

        for u, v, w in highways:
            graph[u].append((v, w))
            graph[v].append((u, w))

        size = 1 << n

        dp = [[-1] * n for _ in range(size)]

        for city in range(n):
            dp[1 << city][city] = 0

        for mask in range(size):
            for u in range(n):
                if dp[mask][u] == -1:
                    continue

                for v, w in graph[u]:
                    if mask & (1 << v):
                        continue

                    new_mask = mask | (1 << v)

                    dp[new_mask][v] = max(
                        dp[new_mask][v],
                        dp[mask][u] + w
                    )

        answer = -1

        for mask in range(size):
            if mask.bit_count() != k + 1:
                continue

            for city in range(n):
                answer = max(answer, dp[mask][city])

        return answer
```实现从处理不可能的情况开始，其中`k >= n`。 既然我们无法重游城市，那么一条比`n - 1`边不能存在。 

接下来，该图被转换为邻接表。 这允许在 DP 转换期间有效地遍历邻近城市。 

DP表初始化为`-1`，表示无法到达的状态。 然后将每个城市初始化为具有成本的起点`0`。 

主要嵌套循环迭代所有子集掩码和结束城市。 每当找到可达状态时，算法都会尝试将路径扩展到每个未访问的邻居。 

转换步骤更新新状态的已知成本。 

最后，该算法扫描所有包含精确内容的掩码`k + 1`城市。 由于路径与`k`边必须包含`k + 1`不同的顶点，这些正是有效的最终状态。 

## 解决方案```go
package main

import (
	"math/bits"
)

func maximumCost(n int, highways [][]int, k int) int {
	if k >= n {
		return -1
	}

	type Edge struct {
		to   int
		cost int
	}

	graph := make([][]Edge, n)

	for _, h := range highways {
		u, v, w := h[0], h[1], h[2]

		graph[u] = append(graph[u], Edge{v, w})
		graph[v] = append(graph[v], Edge{u, w})
	}

	size := 1 << n

	dp := make([][]int, size)

	for i := range dp {
		dp[i] = make([]int, n)

		for j := range dp[i] {
			dp[i][j] = -1
		}
	}

	for city := 0; city < n; city++ {
		dp[1<<city][city] = 0
	}

	for mask := 0; mask < size; mask++ {
		for u := 0; u < n; u++ {
			if dp[mask][u] == -1 {
				continue
			}

			for _, edge := range graph[u] {
				v := edge.to
				w := edge.cost

				if (mask & (1 << v)) != 0 {
					continue
				}

				newMask := mask | (1 << v)

				if dp[mask][u]+w > dp[newMask][v] {
					dp[newMask][v] = dp[mask][u] + w
				}
			}
		}
	}

	answer := -1

	for mask := 0; mask < size; mask++ {
		if bits.OnesCount(uint(mask)) != k+1 {
			continue
		}

		for city := 0; city < n; city++ {
			if dp[mask][city] > answer {
				answer = dp[mask][city]
			}
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的 DP 逻辑。 

A custom`Edge`struct 用于邻接表。 DP表是手动初始化的，因为Go切片默认为`0`，而无法到达的状态需要`-1`。 

这`math/bits`套餐提供`bits.OnesCount`，它有效地计算掩码中设置位的数量。 

Integer overflow is not a concern because the maximum total toll is small:```go
Maximum cost <= 14 * 100 = 1400

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k >= n`。 由于有效的旅行不能重访城市，因此路径`k`边缘需要`k + 1`不同的城市。 如果没有足够的可用城市，则答案必须是`-1`。 该实现会立即通过提前返回来处理此问题，从而避免不必要的 DP 计算。 

另一个棘手的情况是断开连接的图。 如果全局存在足够的边，幼稚的实现可能会错误地假设某些路径始终存在。 然而，所需路径所跨越的城市可能比任何连接的组件所包含的城市还要多。 DP 自然会处理这个问题，因为仍然存在无法到达的状态`-1`。 

第三个重要的例子涉及循环。 由于重新访问城市是被禁止的，因此算法决不允许转移回已经访问过的节点。 位掩码检查：```
if mask & (1 << v):
    continue
```保证每条路径都保持简单。 

零成本优势也很重要。 一些实现不正确地使用`0`意思是“无法到达”。 该解决方案使用`-1`对于无法到达的状态，因此具有总成本的有效路径`0`都得到正确处理。
