[LeetCode 问题 2238](https://leetcode.com/problems/number-of-times-a-driver-was-a-passenger/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题提供了一个表格`Rides`记录司机和乘客之间的行程。 每行都有一个独特的`ride_id`, 一个`driver_id`，和一个`passenger_id`。 任务是确定每个司机作为乘客出现在表中的次数。 换句话说，对于每个独特的`driver_id`，我们计算他们的 ID 出现在`passenger_id`柱子。 

输入表可以为同一司机或乘客提供多次乘车服务，并且司机永远不能自己开车（即，`driver_id != passenger_id`）。 预期输出是一个包含两列的表：`driver_id`和`cnt`， 在哪里`cnt`代表该司机作为乘客的次数。 结果可以按任意顺序返回。 

重要的限制和观察包括：`ride_id`是独一无二的，该表可以包含许多行程，主要挑战是有效地计算所有司机的乘客数量，而不会遗漏任何司机或重复计算。 

可能导致简单解决方案失败的边缘情况包括司机从未以乘客身份出现（计数应为零）、同一名乘客多次乘坐，以及`Rides`表是空的。 该解决方案必须考虑到乘客数量为零的司机。 

## 方法

 暴力方法将迭代所有唯一的驱动程序，并针对每个驱动程序扫描整个驱动程序`passenger_id`用于计数匹配项的列。 这种方法之所以有效，是因为它直接遵循问题描述，但效率低下，需要对表进行嵌套扫描，这会导致 O(n*m) 时间复杂度，其中 n 是唯一司机的数量，m 是乘车总数。 

最佳方法依赖于使用聚合。 首先，使用 a 计算每个乘客 ID 出现的次数`GROUP BY`询问。 然后，将此聚合与唯一驾驶员列表连接起来，以获取每个驾驶员作为乘客出现的次数。 这种方法非常高效，因为它利用数据库聚合和连接操作而不是嵌套循环，从而显着降低了计算复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(1) | O(1) | 迭代每个司机，在乘客列中进行计数 |
 | 最佳| O(米) | O(n) | 汇总乘客数量，加入独特的司机|

 ## 算法演练

 1. 识别所有独特的驱动程序`Rides`表使用`SELECT DISTINCT driver_id`。 
2. 所有行程中每位乘客 ID 的合计计数`GROUP BY passenger_id`获取每个人乘坐乘客的次数。 
3. 在唯一司机和乘客计数之间执行左连接。 这确保了所有司机都会出现在结果中，即使是那些从来不是乘客的司机。 
4. 对于从未作为乘客出现过的司机，将空计数替换为 0。 
5. 返回包含列的结果表`driver_id`和`cnt`。 

为什么有效：左连接保证每个驱动程序都包含在结果中。 聚合步骤可确保正确计算乘客出现次数。 将 null 替换为 0 可保证从未成为乘客的驾驶员的正确性。 

## Python 解决方案```python
import pandas as pd

def count_passenger_occurrences(rides: pd.DataFrame) -> pd.DataFrame:
    # Step 1: Find all unique drivers
    drivers = rides[['driver_id']].drop_duplicates()
    
    # Step 2: Count how many times each driver appears as a passenger
    passenger_counts = rides.groupby('passenger_id').size().reset_index(name='cnt')
    
    # Step 3: Join the counts with the drivers
    result = drivers.merge(passenger_counts, how='left', left_on='driver_id', right_on='passenger_id')
    
    # Step 4: Replace null counts with 0
    result['cnt'] = result['cnt'].fillna(0).astype(int)
    
    # Step 5: Select only required columns
    return result[['driver_id', 'cnt']]
```该实现反映了算法步骤。 首先，它提取所有独特的驱动程序。 然后，它使用`groupby`有效地统计乘客的出现情况。 左连接确保包含所有驱动程序，并且`fillna`处理零发生率的驱动程序。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
    "fmt"
)

func CountPassengerOccurrences(db *sql.DB) ([]struct {
    DriverID int
    Cnt      int
}, error) {
    query := `
        SELECT d.driver_id, IFNULL(p.cnt, 0) AS cnt
        FROM (SELECT DISTINCT driver_id FROM Rides) d
        LEFT JOIN (
            SELECT passenger_id, COUNT(*) AS cnt
            FROM Rides
            GROUP BY passenger_id
        ) p
        ON d.driver_id = p.passenger_id
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var results []struct {
        DriverID int
        Cnt      int
    }

    for rows.Next() {
        var r struct {
            DriverID int
            Cnt      int
        }
        if err := rows.Scan(&r.DriverID, &r.Cnt); err != nil {
            return nil, err
        }
        results = append(results, r)
    }

    return results, nil
}
```在 Go 中，该解决方案使用 SQL 查询来利用聚合和连接，类似于 Python 逻辑。 处理空值`IFNULL`确保正确处理计数为零的驱动程序。 

## 工作示例

 对于输入：```
Rides table:
+---------+-----------+--------------+
| ride_id | driver_id | passenger_id |
+---------+-----------+--------------+
| 1       | 7         | 1            |
| 2       | 7         | 2            |
| 3       | 11        | 1            |
| 4       | 11        | 7            |
| 5       | 11        | 7            |
| 6       | 11        | 3            |
```第 1 步：独特的驱动程序 → {7, 11}

 第 2 步：乘客计数 → {1:2, 2:1, 3:1, 7:2}

 步骤 3：左连接 → {7:2, 11:null}

 步骤 4：替换 null → {7:2, 11:0}

 最终输出：```
+-----------+-----+
| driver_id | cnt |
+-----------+-----+
| 7         | 2   |
| 11        | 0   |
+-----------+-----+
```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(米) | 统计乘客数量需要扫描所有游乐设施一次，加入与独特司机的数量成正比 |

 ## 边缘情况

 司机从不成为乘客是错误的常见来源。 如果连接后的空值没有被0替换，输出将不正确。 该实现明确用 0 填充 null。 

一个空的`Rides`表是另一个边缘情况。 该算法通过返回空结果集来优雅地处理这个问题。 

多次作为乘客出现的司机必须正确计算其计数。 聚合与`GROUP BY`确保正确计算多次出现而不会重复。 

这种综合方法可确保典型、空和极端输入场景的正确性
