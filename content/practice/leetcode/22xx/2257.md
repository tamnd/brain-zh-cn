[LeetCode 问题 2257](https://leetcode.com/problems/count-unguarded-cells-in-the-grid/)

 **难度：** 🟡 中等
 **主题：** 数组、矩阵、模拟

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`m x n`网格包含三种类型的单元格：

 1. 保卫细胞
 2. 壁细胞
 3. 空单元格

 每个警卫可以在四个基本方向观察牢房：

 - 向上
 - 向下
 - 左
 - 右

 守卫会继续观察某个方向的细胞，直到视野被以下任一因素阻挡：

 - 一堵墙
 - 另一名守卫

 任务是计算有多少个空单元格：

 - 没有守卫占据
 - 没有被墙占据
 - 任何守卫都看不到

 网格的索引为 0，这意味着左上角的单元格是`(0, 0)`。 

例如，如果一名警卫在`(2, 3)`，那么警卫可以扫描：

 - 向上通过`(1, 3)`,`(0, 3)`- 向下穿过`(3, 3)`等
 - 向左
 - 向右

 一旦遇到墙壁或其他守卫，扫描就会立即停止。 

约束条件极其重要：

 -`m * n <= 10^5`这告诉我们单元总数最多为 100,000 个，这对于线性或近线性算法来说是可以管理的。 

然而：

-`guards.length`和`walls.length`每个都可以大到`5 * 10^4`这意味着我们无法承担极其昂贵的每卫扫描方法，这种方法会不必要地重复访问许多单元。 

如果每个警卫都独立扫描几乎整个网格，那么简单的实现可能会变得太慢。 

一些重要的边缘情况包括：

 - 靠近墙壁的守卫
 - 守卫互相阻挡
 - 单行或单列网格
 - 几乎每个单元格都被占用的网格
 - 多个守卫都可以看到牢房
 - 完全被墙壁包围的空白区域

 该问题保证了所有守卫和墙的位置都是唯一的，因此我们永远不需要处理守卫和墙之间的重叠。 

## 方法

 ### 蛮力方法

 一种简单的方法是单独处理每个空单元格。 

对于每个空单元格：

 1. 向上看，直到：

 - 发现一堵墙
 - 发现一名守卫
 - 到达边界
 2. 重复以下操作：

 - 向下
 - 向左
 - 向右

 如果任何方向在阻挡物体之前遇到守卫，则该牢房被守卫。 

否则，牢房就无人看守。 

这种方法是正确的，因为它直接遵循问题陈述中可见性的定义。 

然而，性能较差。 

假设网格包含`m * n`单元格，对于每个空单元格，我们可能会扫描整个行和列。 在最坏的情况下，每次查找都会花费`O(m + n)`。 

这导致：

 -`O(m * n * (m + n))`高达`10^5`细胞，这可能会变得太慢。 

### 最佳方法

 关键的观察结果是可见性以直线传播。 

而不是问：

 > “守卫能看到这个牢房吗？”

 对于每个空单元格，我们独立地反转该过程：

 > “从每个守卫开始，标记每个可见的单元格。”

 这避免了对相同单元的重复定向扫描。 

我们构建一个网格表示，其中：

 -`0`= 空
 -`1`= 守卫
 -`2`= 守卫
 -`3`= 墙

 然后，对于每个守卫，我们向四个方向向外扫描，直到击中：

 - 一堵墙
 - 另一名守卫

 每个经过的空单元格都会受到保护。 

最后，我们计算仍然为空的单元格。 

因为每次定向遍历只接触单元格直到被阻塞，并且总网格大小最多为`10^5`，这种方法足够有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * (m + n)) | O(m * n * (m + n)) | O(m * n) | 重新检查每个空单元格的可见性 |
 | 最佳 | O(m * n) | O(m * n) | 直接从守卫处标记受看守的牢房 |

 ## 算法演练

 1. 创建一个大小的网格`m x n`初始化为`0`。 

我们使用数字状态来有效跟踪每个单元格的类型。 

-`0`= 空
 -`1`= 守卫
 -`2`= 守卫
 -`3`= 墙
 2. 将所有防护装置放入网格中。 

对于每个位置`guards`， 放：```
grid[row][col] = 2
```3. 将所有墙壁放入网格中。 

对于每个位置`walls`， 放：```
grid[row][col] = 3
```4. 定义四个移动方向。 

这些是：

 - 向上`(-1, 0)`- 向下`(1, 0)`- 左边`(0, -1)`- 正确的`(0, 1)`5. 对于每个警卫，从所有四个方向扫描。 

从守卫的相邻牢房开始：

 - 在网格内继续移动
 - 如果出现以下情况，请立即停止：

 - 遇到另一个守卫
 - 遇到一堵墙
 - 否则将单元格标记为受保护
 6. 标记受保护的单元格。 

如果遍历的单元格为空（`0`），将其更改为受保护的（`1`）。 

我们仍然继续扫描已经被守卫的单元之外的区域，因为可见度会延伸到它们之中。 
7. 计算剩余的空单元格。 

当所有警卫完成扫描后，每个无人看守的空单元格中仍然包含`0`。 

计算这些细胞并返回结果。 

### 为什么它有效

 该算法之所以有效，是因为守卫可见性是有方向的并且不间断，直到出现阻挡对象为止。 

通过严格按照问题规则从每个守卫向外扫描，每个可见单元都被标记为受守卫。 由于墙壁和警卫立即停止扫描，因此不会标记无效单元格。 

所有守卫处理完毕后：

 - 每个受保护的空单元格都有价值`1`- 每个真正无人看守的空牢房仍然存在`0`因此，计算剩余`0`细胞给出了正确答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def countUnguarded(
        self,
        m: int,
        n: int,
        guards: List[List[int]],
        walls: List[List[int]]
    ) -> int:

        EMPTY = 0
        GUARDED = 1
        GUARD = 2
        WALL = 3

        grid = [[EMPTY] * n for _ in range(m)]

        # Place guards
        for row, col in guards:
            grid[row][col] = GUARD

        # Place walls
        for row, col in walls:
            grid[row][col] = WALL

        directions = [
            (-1, 0),  # up
            (1, 0),   # down
            (0, -1),  # left
            (0, 1)    # right
        ]

        # Spread visibility from each guard
        for row, col in guards:

            for dr, dc in directions:

                r = row + dr
                c = col + dc

                while 0 <= r < m and 0 <= c < n:

                    # Stop if blocked
                    if grid[r][c] == GUARD or grid[r][c] == WALL:
                        break

                    # Mark as guarded
                    if grid[r][c] == EMPTY:
                        grid[r][c] = GUARDED

                    r += dr
                    c += dc

        # Count unguarded empty cells
        unguarded = 0

        for row in range(m):
            for col in range(n):
                if grid[row][col] == EMPTY:
                    unguarded += 1

        return unguarded
```实现首先构建网格的矩阵表示。 使用数字常量而不是字符串，因为整数比较对于状态管理来说更快、更清晰。 

首先插入防护装置和墙壁，以便扫描阶段可以立即识别阻塞细胞。 

这`directions`数组集中了运动逻辑。 这避免了向上、向下、向左、向右遍历的重复代码。 

对于每个警卫，该算法都会执行定向扫描。 每次扫描都会持续进行，直到出现以下情况：

 - 到达网格边界
 - 遇到一堵墙
 - 遇到另一个守卫

 遍历期间遇到的空单元格被标记为受保护的。 

最后，最后一次遍历网格以计算仍然为空的单元格。 

## 解决方案```go
func countUnguarded(m int, n int, guards [][]int, walls [][]int) int {
	const (
		EMPTY   = 0
		GUARDED = 1
		GUARD   = 2
		WALL    = 3
	)

	grid := make([][]int, m)

	for i := 0; i < m; i++ {
		grid[i] = make([]int, n)
	}

	// Place guards
	for _, g := range guards {
		row, col := g[0], g[1]
		grid[row][col] = GUARD
	}

	// Place walls
	for _, w := range walls {
		row, col := w[0], w[1]
		grid[row][col] = WALL
	}

	directions := [][]int{
		{-1, 0}, // up
		{1, 0},  // down
		{0, -1}, // left
		{0, 1},  // right
	}

	// Spread visibility
	for _, g := range guards {
		row, col := g[0], g[1]

		for _, d := range directions {
			dr, dc := d[0], d[1]

			r := row + dr
			c := col + dc

			for r >= 0 && r < m && c >= 0 && c < n {

				if grid[r][c] == GUARD || grid[r][c] == WALL {
					break
				}

				if grid[r][c] == EMPTY {
					grid[r][c] = GUARDED
				}

				r += dr
				c += dc
			}
		}
	}

	// Count unguarded cells
	unguarded := 0

	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if grid[i][j] == EMPTY {
				unguarded++
			}
		}
	}

	return unguarded
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

2D 切片用于网格表示。 常量提高了可读性并消除了整个代码中的幻数。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有计数都保持在标准范围内`int`范围。 

与 Python 不同，Go 使用显式的基于索引的循环和切片初始化。

from typing import List

class Solution:
    def countUnguarded(
        self,
        m: int,
        n: int,
        guards: List[List[int]],
        walls: List[List[int]]
    ) -> int:

        EMPTY = 0
        GUARDED = 1
        GUARD = 2
        WALL = 3

        grid = [[EMPTY] * n for _ in range(m)]

        for r, c in guards:
            grid[r][c] = GUARD

        for r, c in walls:
            grid[r][c] = WALL

        directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

        for r, c in guards:

            for dr, dc in directions:

                nr = r + dr
                nc = c + dc

                while 0 <= nr < m and 0 <= nc < n:

                    if grid[nr][nc] == GUARD or grid[nr][nc] == WALL:
                        break

                    if grid[nr][nc] == EMPTY:
                        grid[nr][nc] = GUARDED

                    nr += dr
                    nc += dc

        return sum(
            grid[r][c] == EMPTY
            for r in range(m)
            for c in range(n)
        )

 ## 边缘情况

 ### 紧邻墙壁的守卫

 当实施错误地允许警卫看穿墙壁时，就会出现一个常见的错误。 

例如：```
G W .
```警卫不应该看到最后一个牢房。 

该实现可以正确处理此问题，因为一旦遇到壁单元，扫描就会立即停止。 

### 守卫阻挡其他守卫

 当警卫出现在同一行或同一列时，会发生另一种微妙的情况。 

例如：```
G . . G
```左卫兵的视野不应超出右卫兵的范围。 

当遇到另一个守卫时，该算法会明确停止扫描，从而防止错误传播。 

### 单行或单列网格

 定向遍历逻辑经常在退化网格中中断，例如：```
1 x n
```或者```
m x 1
```该实现可以安全地处理这个问题，因为每个移动在访问网格之前都会检查边界。 

### 多个守卫看到同一个牢房

 一个牢房可能同时对几个守卫可见。 

有缺陷的实现可能会错误地重复处理或覆盖单元格。 

这个实现只是将单元格标记为`GUARDED`一次。 通过已受保护的单元的额外扫描将正常继续，不会影响正确性。
