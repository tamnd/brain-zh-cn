[LeetCode 第 2281 题](https://leetcode.com/problems/sum-of-total-strength-of-wizards/)

 **难度：** 🔴难
 **主题：** 数组、堆栈、单调堆栈、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算输入数组的每个可能的连续子数组**的总强度之和`strength`。 

对于任何选定的子阵列，其**总强度**定义为：$$\text{minimum value in subarray} \times \text{sum of values in subarray}$$我们必须评估**所有非空连续子数组**的这个数量，然后将所有结果加在一起。 

例如，如果：```
strength = [1,3,1,2]
```那么有效的子数组包括：```
[1]
[3]
[1,3]
[3,1]
[1,3,1]
[1,3,1,2]
```以及许多其他人。 对于每一个，我们计算：```
minimum(subarray) * sum(subarray)
```最后，我们将所有这些值相加。 

挑战来自于限制：```
1 <= strength.length <= 100000
1 <= strength[i] <= 1000000000
```长度为`10^5`立即排除任何显式枚举所有子数组的方法。 

有：$$O(n^2)$$size 数组中的子数组`n`。 

即使有效地计算每个子数组的总和和最小值仍然变得太慢，因为：$$O(n^2)$$为了`n = 100000`远远超出了实际的限制。 

这意味着我们需要一个接近于：```
O(n log n)
```或者理想情况下：```
O(n)
```另一个重要的复杂问题是正确处理重复值。 当存在多个相等元素时，我们必须仔细定义哪个索引被认为是重叠范围的最小值，否则我们将面临重复计算的风险。 

该问题保证：

 - 数组非空。 
- 所有值均为正整数。 
- 结果可能变得非常大，因此我们必须将其模数返回：$$10^9 + 7$$重要的边缘情况包括：

 - 单个元素数组。 
- 所有值均相等。 
- 严格增加数组。 
- 严格递减数组。 
- 大的重复值。 
- 相同最小值多次出现的情况。 

这些情况通常会暴露单调堆栈边界处理中的错误。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是枚举每个可能的子数组。 

对于每个起始索引`i`，我们迭代每个结束索引`j`。 在扩展子数组时，我们维护：

 - 运行总和
 - 当前最小值

 然后我们计算：```
minimum * subarray_sum
```并将其添加到最终答案中。 

虽然这给出了正确的结果，但速度太慢了。 

有：$$O(n^2)$$子数组。 

即使我们在恒定时间内增量更新最小值和总和，我们仍然必须检查每个子数组。 

和：```
n = 100000
```这变得不可行。 

### 最佳解决方案的关键见解

 我们没有迭代子数组，而是颠倒了思维。 

而不是问：

 > 对于每个子数组，其最小值是多少？ 

我们问：

 > 对于每个元素，它在哪些子数组中最小？ 

这种转变是关键的见解。 

认为`strength[i]`是最小元素。 

我们想要计算该向导在所有子数组中的贡献，其中它是最小值。 

为此，我们确定：

 - 左边最近的较小元素
 - 右边最近的较小或相等的元素

 这些边界准确定义了选择哪些子数组`strength[i]`作为他们的最低限度。 

这是一个经典的**单调堆栈**模式。 

然而，我们还需要：```
minimum × subarray sum
```索引的最小值是固定的`i`，但子数组总和发生变化。 

因此，我们使用**前缀和的前缀和**来有效计算范围内所有子数组和的总和。 

这将总复杂度降低到线性时间。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 直接枚举所有子数组 |
 | 最佳| O(n) | O(n) | 单调堆栈 + 双前缀和 |

 ## 算法演练

 ### 步骤 1：计算先前较小的元素

 我们首先计算左侧最接近的索引，其中值**严格较小**。 

我们使用单调递增堆栈。 

对于每个索引`i`:

 - 当栈顶大于或等于当前值时，弹出。 
- 剩余的顶部成为左边界。 
- 如果不存在更小的元素，则边界变为`-1`。 

我们在左侧使用**严格较小的**以避免重复计数。 

### 步骤 2：计算下一个较小或相等的元素

 接下来，我们计算右侧最接近的索引，其中值**较小或等于**。 

同样，我们使用单调递增堆栈。 

对于每个从右向左移动的索引：

 - 当堆栈顶部严格大于当前值时，弹出。 
- 剩余的顶部成为右边界。 
- 如果不存在，则边界变为`n`。 

这种不对称性：```
left = strictly smaller
right = smaller or equal
```确保重复的最小值恰好计数一次。 

### 步骤 3：构建前缀和数组

 我们建造：```
prefix[i]
```在哪里：```
prefix[i]
```存储第一个的总和`i`元素。 

这允许：```
sum(l:r)
```在常数时间内计算。 

### 步骤 4：构建前缀和的前缀

 我们还建造：```
prefix_of_prefix
```这使我们能够有效地计算许多范围总和的总和。 

如果没有这一步，我们仍然会花费太多时间来聚合子数组和。 

### 步骤 5：计算每个元素的贡献

 假设索引`i`有价值：```
x = strength[i]
```让：```
l = left[i]
r = right[i]
```然后：

 - 左边的选择=`i - l`- 正确的选择=`r - i`我们计算：```
positive_part
```对于右扩展和```
negative_part
```用于左扩展。 

公式变为：$$\text{totalSubarraySum} = (\text{rightContribution} \times \text{leftCount}) - (\text{leftContribution} \times \text{rightCount})$$然后乘以：```
strength[i]
```因为这个向导是最小的。 

对结果求模：$$10^9+7$$### 第 6 步：返回最终答案

 处理完每个索引后，返回：```
answer % MOD
```### 为什么它有效

 对于每个索引`i`，单调堆栈唯一标识所有子数组，其中`strength[i]`是最小值。 由于不对称比较规则，不会遗漏任何子数组，也不会重复计算任何子数组。 

双前缀和保证可以在恒定时间内计算每个索引的所有候选子数组的总和。 由于每个元素最多从堆栈中压入和弹出一次，因此整个算法以线性时间运行。 

## Python 解决方案```python
from typing import List

class Solution:
    def totalStrength(self, strength: List[int]) -> int:
        MOD = 10**9 + 7
        n = len(strength)

        left = [-1] * n
        right = [n] * n

        stack = []

        # Previous strictly smaller
        for i in range(n):
            while stack and strength[stack[-1]] >= strength[i]:
                stack.pop()

            left[i] = stack[-1] if stack else -1
            stack.append(i)

        stack.clear()

        # Next smaller or equal
        for i in range(n - 1, -1, -1):
            while stack and strength[stack[-1]] > strength[i]:
                stack.pop()

            right[i] = stack[-1] if stack else n
            stack.append(i)

        # Prefix sums
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = (prefix[i] + strength[i]) % MOD

        # Prefix of prefix sums
        prefix_prefix = [0] * (n + 2)
        for i in range(n + 1):
            prefix_prefix[i + 1] = (
                prefix_prefix[i] + prefix[i]
            ) % MOD

        result = 0

        for i in range(n):
            left_idx = left[i]
            right_idx = right[i]

            left_count = i - left_idx
            right_count = right_idx - i

            positive_sum = (
                prefix_prefix[right_idx + 1]
                - prefix_prefix[i + 1]
            ) % MOD

            negative_sum = (
                prefix_prefix[i + 1]
                - prefix_prefix[left_idx + 1]
            ) % MOD

            total_sum = (
                positive_sum * left_count
                - negative_sum * right_count
            ) % MOD

            contribution = (
                strength[i] * total_sum
            ) % MOD

            result = (result + contribution) % MOD

        return result
```实现首先计算每个向导可以充当最小值的有效跨度。 这`left`数组存储最近的严格较小的元素，而`right`存储最近的小于或等于的元素。 

发现边界后，我们构建一个普通的前缀和数组，以便可以在恒定时间内查询范围和。 

重要的优化是`prefix_prefix`，它存储累积前缀和。 这使得能够同时快速聚合多个子数组和。 

对于每个索引，我们计算该向导最小的所有子数组总和，然后乘以该向导的强度并添加到答案中。 

始终应用模运算以避免溢出并保持正确性。 

## 解决方案```go
func totalStrength(strength []int) int {
	const MOD int64 = 1_000_000_007

	n := len(strength)

	left := make([]int, n)
	right := make([]int, n)

	for i := range right {
		right[i] = n
		left[i] = -1
	}

	stack := []int{}

	// Previous strictly smaller
	for i := 0; i < n; i++ {
		for len(stack) > 0 &&
			strength[stack[len(stack)-1]] >= strength[i] {
			stack = stack[:len(stack)-1]
		}

		if len(stack) > 0 {
			left[i] = stack[len(stack)-1]
		}

		stack = append(stack, i)
	}

	stack = []int{}

	// Next smaller or equal
	for i := n - 1; i >= 0; i-- {
		for len(stack) > 0 &&
			strength[stack[len(stack)-1]] > strength[i] {
			stack = stack[:len(stack)-1]
		}

		if len(stack) > 0 {
			right[i] = stack[len(stack)-1]
		}

		stack = append(stack, i)
	}

	// Prefix sums
	prefix := make([]int64, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = (
			prefix[i] + int64(strength[i])
		) % MOD
	}

	// Prefix of prefix sums
	prefixPrefix := make([]int64, n+2)

	for i := 0; i <= n; i++ {
		prefixPrefix[i+1] = (
			prefixPrefix[i] + prefix[i]
		) % MOD
	}

	var result int64 = 0

	for i := 0; i < n; i++ {
		leftIdx := left[i]
		rightIdx := right[i]

		leftCount := int64(i - leftIdx)
		rightCount := int64(rightIdx - i)

		positiveSum := (
			prefixPrefix[rightIdx+1] -
				prefixPrefix[i+1] +
				MOD,
		) % MOD

		negativeSum := (
			prefixPrefix[i+1] -
				prefixPrefix[leftIdx+1] +
				MOD,
		) % MOD

		totalSum := (
			positiveSum*leftCount -
				negativeSum*rightCount,
		) % MOD

		if totalSum < 0 {
			totalSum += MOD
		}

		contribution := (
			int64(strength[i]) * totalSum,
		) % MOD

		result = (result + contribution) % MOD
	}

	return int(result)
}
```Go 实现遵循与 Python 相同的算法结构，但使用`int64`广泛以避免溢出。 由于强度可以大到`10^9`，中间乘法可以超出标准范围`int`。 

切片用作堆栈，并且只要减法可能产生负结果，就会应用模校正。

 ## 边缘情况

 ### 单元素数组

 当输入仅包含一个向导时，唯一的子数组就是向导本身。 

例如：```
[7]
```答案变成：```
7 × 7 = 49
```这种情况可能会暴露前缀索引或边界初始化中的差一错误。 我们的实现可以正确处理它，因为边界默认为`-1`和`n`。 

### 重复值

 同等价值观尤其危险。 

例如：```
[2,2,2]
```如果没有仔细的边界处理，多个索引可能会声明相同的子数组作为它们的最小值，从而导致重复计算。 

该实现通过使用以下方式避免了这种情况：```
left: strictly smaller
right: smaller or equal
```这保证了每个子数组都被精确地分配给一个最小索引。 

### 严格递增或递减数组

 数组如：```
[1,2,3,4]
```或者```
[4,3,2,1]
```强调单调堆栈逻辑。 

在递增数组中，大多数右边界延伸得很远。 

在递减数组中，大多数左侧边界很快就会崩溃。 

不正确的堆栈条件通常会在这里失败。 由于每个比较方向都是有意选择的，因此实现可以正确处理两种模式。 

### 大值和溢出

 数值可以达到：```
10^9
```并且子数组的数量是巨大的。 

中间计算变得非常大。 

Python 版本自然处理大整数，而 Go 版本明确使用`int64`并始终应用模运算以防止溢出并保持正确性。
