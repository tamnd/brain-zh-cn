## 问题理解

 该问题为我们提供了一组不相交的白色瓷砖间隔和固定长度的地毯。 每个区间`[li, ri]`表示每个图块位置`li`通过`ri`是白色的。 地毯可以放置在数轴上的任何位置，并覆盖一段连续的长度`carpetLen`。 

我们的目标是确定通过最佳放置地毯可以覆盖的白色瓷砖的最大数量。 

一个关键细节是图块表示为间隔，而不是单个位置。 由于坐标可以大到`10^9`，我们无法构造显式的图块数组。 相反，我们必须以数学方式推理区间。 

例如，如果一个区间是`[10, 15]`，它包含：`15 - 10 + 1 = 6`白色瓷砖。 

地毯还覆盖了一个间隔。 如果地毯开始于位置`x`，它涵盖：```
[x, x + carpetLen - 1]
```我们希望最大限度地增加与该地毯系列重叠的白色瓷砖数量。 

输入约束强烈影响解决方案设计：

 - 最多可以有`5 * 10^4`平铺间隔。 
- 平铺坐标可以达到`10^9`。 
- 保证间隔不重叠。 

保证间隔不重叠简化了问题，因为覆盖率计算在间隔之间变得独立。 

较大的坐标范围使得暴力破解变得不可能。 我们无法模拟每个瓷砖位置或每个地毯放置。 

有几个重要的边缘情况需要考虑：

 - 地毯可以完全覆盖多个间隔。 
- 地毯可能会部分覆盖其到达的最后一个间隔。 
- 地毯可能比整个间隔簇更长。 
- 最佳放置可以在图块间隔内开始，而不是恰好在其开始处。 
- 由于区间不重叠但不一定排序，所以排序是必要的。 

## 方法

 ### 蛮力方法

 蛮力策略会尝试每一种可能的地毯放置方式，并计算覆盖了多少块白色瓷砖。 

对蛮力的一种合理解释是将地毯放置在每个有意义的起始位置，例如每个图块起始点，然后扫描所有间隔以计算重叠。 

对于每个间隔开始`tiles[i][0]`，我们可以：

 1. 计算地毯结束位置。 
2. 迭代每个图块间隔。 
3. 在地毯范围和每个间隔之间添加重叠。 

之间的重叠公式：```
[a, b]
```和```
[c, d]
```是：```
max(0, min(b, d) - max(a, c) + 1)
```这给出了正确的答案，因为每个候选人的安置都经过准确评估。 

然而，这变得太慢了。 

如果我们测试每个间隔开始并再次扫描每个间隔：```
O(n²)
```和`n = 5 * 10^4`，这太贵了。 

### 最佳解决方案的关键见解

 重要的观察是间隔是不重叠的并且可以排序。 

如果我们从一个间隔的开头开始放置地毯，那么当我们移动到下一个间隔时，有效覆盖区域只会向前移动。 

这使得该问题适合滑动窗口方法。 

我们可以将地毯视为覆盖物：```
[start, start + carpetLen - 1]
```对于每个起始间隔：

 - 一些连续的间隔被完全覆盖。 
- 最多有一个区间被部分覆盖。 

由于间隔永远不会重叠并且覆盖范围只会向前移动，因此我们可以维护一个移动窗口，而不是从头开始重新计算所有内容。 

滑动窗口有效跟踪：

 - 完全覆盖间隔。 
- 部分覆盖下一个间隔。 

这将复杂性降低到：```
O(n log n)
```因为排序在运行时占据主导地位。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 尝试每个间隔开始并扫描所有间隔是否重叠 |
 | 最佳| O(n log n) | O(n log n) | O(1) | O(1) | 对区间进行排序并使用滑动窗口 |

 ## 算法演练

 ### 最优滑动窗口算法

 1. **按起始位置对间隔进行排序**

 由于间隔不重叠但不保证排序，因此我们首先对它们进行排序。 这确保我们可以按升序处理间隔并且仅向前移动指针。 
2. **初始化两个指针**

 我们维持：

 -`left`, 地毯开始的间隔
 -`right`，完全覆盖的最远区间

 我们还维护：

 -`covered_tiles`, 当前窗口内完全覆盖的图块总数
 -`max_covered`，迄今为止看到的最佳答案
 3. **将地毯固定在`tiles[left][0]`**

 地毯跨度：```
[tiles[left][0], tiles[left][0] + carpetLen - 1]
```4. **展开右侧指针**

 当间隔完全在地毯范围内时：```
tiles[right][1] <= carpet_end
```将其整个长度添加到`covered_tiles`。 

间隔长度为：```
tiles[right][1] - tiles[right][0] + 1
```5. **处理部分重叠**

 一旦我们到达一个没有完全覆盖的区间，它仍然可能部分重叠。 

重叠是：```
carpet_end - tiles[right][0] + 1
```但前提是：```
carpet_end >= tiles[right][0]
```6. **更新最大值**

 总覆盖范围等于：```
covered_tiles + partial_overlap
```更新最佳答案。 
7. **移动左指针**

 前进之前：

 - 删除完全覆盖的贡献`tiles[left]`。 

这使滑动窗口保持一致。 
8. **重复直到处理完所有间隔**

 ### 为什么它有效

 关键的不变量是窗口始终包含完全被地毯覆盖的间隔，从`tiles[left][0]`。 由于区间是排序且不重叠的，因此一旦某个区间不再被完全覆盖，后面的区间就不会突然被完全覆盖。 因此，`right`指针仅向前移动。 

在每个位置，我们都会评估所有可能的完全覆盖区间和一个部分覆盖区间。 由于任何最佳地毯放置都可以转移到从瓷砖开始处开始，而不会失去最佳性，因此检查每个间隔开始可以保证正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumWhiteTiles(self, tiles: List[List[int]], carpetLen: int) -> int:
        tiles.sort()

        n = len(tiles)
        left = 0
        right = 0

        covered_tiles = 0
        max_covered = 0

        while left < n:
            carpet_end = tiles[left][0] + carpetLen - 1

            while right < n and tiles[right][1] <= carpet_end:
                covered_tiles += (
                    tiles[right][1] - tiles[right][0] + 1
                )
                right += 1

            partial_cover = 0

            if right < n and tiles[right][0] <= carpet_end:
                partial_cover = (
                    carpet_end - tiles[right][0] + 1
                )

            max_covered = max(
                max_covered,
                covered_tiles + partial_cover
            )

            covered_tiles -= (
                tiles[left][1] - tiles[left][0] + 1
            )

            left += 1

        return max_covered
```该实现首先对间隔进行排序，以便滑动窗口可以从左到右单调移动。 

这`left`指针确定地毯的起始位置。 对于每一个`left`，我们计算地毯结束坐标。 

这`right`当区间被完全覆盖时，指针会扩展。 它们的长度累计为`covered_tiles`。 

当下一个间隔未完全覆盖时，我们计算任何部分重叠。 由于区间不重叠，因此只能部分覆盖一个区间。 

我们使用以下方法更新最大答案：```python
fully covered tiles + partially covered tiles
```最后，在搬家之前`left`，我们减去它的区间长度`covered_tiles`，保持滑动窗口准确。 

因为两个指针都只向前移动，所以排序后遍历仍然是线性的。 

## 解决方案```go
package main

import "sort"

func maximumWhiteTiles(tiles [][]int, carpetLen int) int {
	sort.Slice(tiles, func(i, j int) bool {
		return tiles[i][0] < tiles[j][0]
	})

	n := len(tiles)

	left := 0
	right := 0

	coveredTiles := 0
	maxCovered := 0

	for left < n {
		carpetEnd := tiles[left][0] + carpetLen - 1

		for right < n && tiles[right][1] <= carpetEnd {
			coveredTiles += tiles[right][1] -
				tiles[right][0] + 1
			right++
		}

		partialCover := 0

		if right < n &&
			tiles[right][0] <= carpetEnd {
			partialCover =
				carpetEnd -
					tiles[right][0] + 1
		}

		current := coveredTiles +
			partialCover

		if current > maxCovered {
			maxCovered = current
		}

		coveredTiles -=
			tiles[left][1] -
				tiles[left][0] + 1

		left++
	}

	return maxCovered
}
```Go 实现遵循与 Python 相同的逻辑。 主要区别在于排序，它使用`sort.Slice`。 

Go 没有 Python 的动态列表行为，因此间隔长度和指针更新是显式处理的。 

整数溢出不是问题，因为最大坐标是`10^9`，它安全地适合 Go 的内部`int`在 LeetCode 环境中。 

切片自然地用于区间存储，空切片与零切片在这里无关紧要，因为约束保证至少有一个区间。

 ## 边缘情况

 ### 地毯比所有瓷砖都长

 如果地毯长度超过白色瓷砖的总跨度，简单的实现可能会过多计算间隔之间的空白间隙。 由于此实现仅计算与白色间隔的重叠，因此间隙没有任何贡献。 该算法正确返回白色瓷砖的总数。 

### 最后一个区间的部分覆盖

 当地毯伸入某个间隔但未完全覆盖它时，就会出现常见的错误。 实现可能会意外地忽略部分重叠或计数太多。 

该解决方案明确计算：```
carpet_end - interval_start + 1
```用于完全覆盖后的下一个间隔，确保准确的部分覆盖。 

### 未排序的输入

 该问题保证间隔不重叠，但不保证排序。 未排序数据上的简单滑动窗口将会失败，因为指针移动假定坐标递增。 

此实现首先对间隔进行排序，确保无论输入顺序如何都正确。 

### 单间隔输入

 当仅存在一个区间时，指针逻辑有时会因边界条件而中断。 该解决方案可以自然地处理这种情况，因为窗口逻辑仍然适用，并且可以正确计算部分或全部覆盖。 

### 大坐标值

 坐标可能达到`10^9`，使得逐块模拟变得不可能。 由于该算法完全使用区间算术而不是显式位置，因此即使在最大限制下，它仍然保持高效和内存安全。
