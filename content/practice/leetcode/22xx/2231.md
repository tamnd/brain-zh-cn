[LeetCode 问题 2231](https://leetcode.com/problems/largest-number-after-digit-swaps-by-parity/)

 **难度：** 🟢简单
 **主题：** 排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 问题给了我们一个正整数`num`并且仅当两个数字具有相同的奇偶校验时才允许我们交换数字。 换句话说，奇数位只能与另一个奇数位交换，偶数位只能与另一个偶数位交换。 

目标是返回执行任意数量的有效交换后可以形成的最大可能整数。 

为了更清楚地理解该限制，想象一下数字的数字被固定在位置上。 在每个位置，最初占据该位置的数字的奇偶校验有效地限制了可以到达那里的数字。 如果某个位置原来包含奇数位，则只有其他位置的奇数位可以替换它。 同样，最初包含偶数位的位置只能包含偶数位。 

例如，在`1234`，奇数位是`1`和`3`，而偶数位是`2`和`4`。 由于奇数位之间可以自由交换，因此我们可以按降序重新排列奇数位（`3,1`）。 同样，偶数位可以按降序重新排列（`4,2`）。 在保留奇偶校验位置的同时重构数字给出`3412`，这是最大可能的结果。 

输入由单个整数组成`num`， 在哪里`1 <= num <= 10^9`。 由于上限仅为 10 亿，因此该数字最多包含 10 位数字。 这是一个非常小的输入大小，这意味着即使是效率较低的算法也可能会通过。 然而，这个问题的目的是测试观察和贪婪推理，而不是原始性能。 

有几个重要的边缘情况需要记住。 仅包含奇数位或仅包含偶数位的数字应简单地按降序排序，因为每个数字都可以与其他数字交换。 单位数字应返回不变，因为不可能进行交换。 奇偶校验频繁交替的数字也可能很棘手，因为我们无法自由地重新排序整个数字，只能对同一奇偶校验组内的数字进行重新排序。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的有效交换序列并确定可获得的最大数量。 

思考这个问题的一种方法是将其视为图搜索问题。 每个数字配置成为一种状态，并且每个有效的奇偶校验交换产生另一种状态。 我们可以使用广度优先搜索或深度优先搜索来探索所有可达的数字，并跟踪遇到的最大值。 

这种方法是正确的，因为它详尽地探索了通过保留奇偶性互换可以获得的每一种有效安排。 由于它考虑了所有可能性，因此它不会错过最佳答案。 

然而，这种方法效率低下，因为排列的数量随着数字的数量呈阶乘增长。 尽管位数很少，但生成和检查每个可达排列是不必要的，而且计算成本很高。 

### 最优贪心法

 关键的观察结果是奇偶位置是固定的。 

假设一个位置最初包含奇数位。 由于我们只能与其他奇数位交换，因此该位置永远不能包含偶数位。 同样的逻辑也适用于偶数位置。 因此，我们唯一的自由就是决定哪个奇数位占据奇数位置，哪个偶数位占据偶数位置。 

为了最大化结果数字，我们应该从最左边的数字开始，贪婪地在每个位置放置正确奇偶校验的最大可用数字。 由于较早的数字对最终数值的贡献更大，因此始终选择本地最大的有效数字也会产生全局最佳答案。 

该算法的工作原理如下：

 1. 提取所有奇数位和所有偶数位。 
2. 按降序对两个组进行排序。 
3. 从左到右重建数字。 
4. 对于每个原始数字：

 - 如果是奇数，则放置剩余的最大奇数位。 
- 如果是偶数，则放置剩余的最大偶数。 

这保证了最大可能的数量。

 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n!) | 探索所有有效的奇偶保留排列 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 对奇数位和偶数位独立排序，然后重建 |

 ## 算法演练

 1. 将整数转换为字符串，以便我们可以轻松处理单个数字。 
2. 遍历数字并根据奇偶性将其分为两组。 一个列表存储奇数位，另一个列表存储偶数位。 我们这样做是因为数字只能在同一奇偶校验类别内交换。 
3. 按降序对两个列表进行排序。 这确保了每个奇偶校验的最大剩余数字始终首先可用。 
4. 初始化两个指针，一个用于奇数列表，一个用于偶数列表。 这些指针跟踪接下来应该使用哪个数字。 
5. 从左到右迭代原始数字。 对于每个数字：

 - 如果数字是奇数，则附加最大的未使用的奇数。 
- 如果数字是偶数，则附加最大的未使用偶数。 

这个贪心步骤之所以有效，是因为前面放置的数字在最终数字中具有更大的位置意义。 
6. 将所选数字组合成字符串并将其转换回整数。 

### 为什么它有效

该算法依赖于每个位置只能接收与其原始数字具有相同奇偶校验的数字的不变量。 由于奇偶校验位置是固定的，因此最大化数量减少为独立地最大化分配给奇数和偶数时隙的数字。 

在每个位置，选择最大的可用有效数字是最佳选择，因为前面的数字比后面的数字对总价值的贡献更大。 无论未来的位置如何，在更重要的位置上进行的任何较小的选择都必然会产生较小的总数。 

## Python 解决方案```python
class Solution:
    def largestInteger(self, num: int) -> int:
        digits = list(str(num))

        odd_digits = sorted(
            [digit for digit in digits if int(digit) % 2 == 1],
            reverse=True
        )

        even_digits = sorted(
            [digit for digit in digits if int(digit) % 2 == 0],
            reverse=True
        )

        odd_index = 0
        even_index = 0
        result = []

        for digit in digits:
            if int(digit) % 2 == 1:
                result.append(odd_digits[odd_index])
                odd_index += 1
            else:
                result.append(even_digits[even_index])
                even_index += 1

        return int("".join(result))
```实现首先将数字转换为数字字符列表，使迭代变得简单。 

接下来，它将奇数和偶数分成两个独立的集合。 每个集合都按降序排序，以便始终首先访问最大的可用数字。 

然后该算法迭代原始数字。 它不使用原始数字，而是用相同奇偶校验的最大剩余数字替换它。 两个索引跟踪每个排序列表中已经使用了多少位。 

最后，将重建的数字连接在一起并转换回整数。 

## 解决方案```go
import (
	"sort"
	"strconv"
)

func largestInteger(num int) int {
	numStr := strconv.Itoa(num)

	var oddDigits []int
	var evenDigits []int

	for _, ch := range numStr {
		digit := int(ch - '0')

		if digit%2 == 0 {
			evenDigits = append(evenDigits, digit)
		} else {
			oddDigits = append(oddDigits, digit)
		}
	}

	sort.Sort(sort.Reverse(sort.IntSlice(oddDigits)))
	sort.Sort(sort.Reverse(sort.IntSlice(evenDigits)))

	oddIndex := 0
	evenIndex := 0
	result := ""

	for _, ch := range numStr {
		digit := int(ch - '0')

		if digit%2 == 0 {
			result += strconv.Itoa(evenDigits[evenIndex])
			evenIndex++
		} else {
			result += strconv.Itoa(oddDigits[oddIndex])
			oddIndex++
		}
	}

	answer, _ := strconv.Atoi(result)
	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑结构。 由于 Go 没有内置的切片降序排序，因此我们使用`sort.Reverse(sort.IntSlice(...))`。 

Go 不是将数字存储为字符串，而是将它们存储为整数。 重建期间，`strconv.Itoa()`将数字转换回字符串以进行串联。 

整数溢出不是问题，因为该问题保证`num <= 10^9`，它很容易适合 Go 的内部`int`类型。

 ## 边缘情况

 ### 单位数字

 当`num`仅包含一位数字，无法进行交换，因为没有任何内容可交换。 幼稚的实现可能会意外地使这种情况变得过于复杂，但算法自然可以处理它。 奇数或偶数列表包含一个元素，并且重建简单地再现相同的数字。 

### 只有一个奇偶校验的数字

 如果所有数字都是奇数或所有数字都是偶数，则每个数字都可以与其他数字交换。 在这种情况下，最佳答案就是按降序排列的数字。 该实现会自动处理此问题，因为一个奇偶校验列表变为空，而另一个奇偶校验列表包含所有数字。 

例如，`2486`变成`8642`， 和`13579`变成`97531`。 

### 包含零的数字

 零值得特别注意，因为它是偶数。 不正确的实现可能会以不同的方式对待它或意外地将其移动到奇怪的插槽中。 

例如，在`10203`，偶数位是`[0, 2, 0]`，奇数位是`[1, 3]`。 按奇偶校验排序和重构给出`30201`，同时保留有效的奇偶校验约束。 由于零的行为与任何其他偶数一样，因此实现可以正确处理它，而不需要特殊的逻辑。
