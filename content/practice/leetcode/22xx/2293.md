[LeetCode 第 2293 题](https://leetcode.com/problems/min-max-game/)

 **难度：** 🟢简单
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们重复变换一个数组，直到只剩下一个数字。 在每一轮中，我们使用交替的方法将数组的大小减少一半`min`和`max`对相邻对的操作。 

更具体地说，我们从`0-indexed`大批`nums`其长度保证为`2`。 在每次迭代期间，我们创建一个新数组`newNums`大小的`n / 2`， 在哪里`n`是当前长度`nums`。 

对于每个索引`i`在`newNums`：

- 如果`i`是偶数，我们取这对中的最小值`nums[2*i]`和`nums[2*i + 1]`。 
- 如果`i`是奇数，我们取这对中的最大值`nums[2*i]`和`nums[2*i + 1]`。 

一次`newNums`已建成，它取代了`nums`，并且重复该过程，直到只剩下一个元素。 最终的剩余价值就是答案。 

输入表示一个整数数组，其中每个数字参与重复的成对缩减。 预期输出是所有归约完成后剩下的最终单个整数。 

这些约束告诉我们有关该问题的一些有用的信息：

 -`nums.length`至多是`1024`，相对较小。 
- 长度始终是`2`，这意味着重复减半将始终顺利进行，直到我们达到单个元素。 
- 每个值可以大到`10^9`，但我们只是比较值，而不是执行有溢出风险的算术。 

最重要的边缘情况是数组仅包含一个元素时。 在这种情况下，不需要任何处理，我们只需立即返回该值即可。 错误的另一个可能来源是正确地交替`min`和`max`基于新数组中的索引，而不是原始数组。 该问题保证了输入长度有效，因此我们永远不需要担心配对不均匀。 

## 方法

 ### 蛮力方法

 暴力解决方案直接完全按照书面形式模拟问题陈述。 在每一轮中，我们分配一个新的大小数组`n / 2`，迭代相邻对，应用任一`min`或者`max`根据新索引的奇偶校验，然后替换旧数组。 

这种方法是正确的，因为它精确地遵循问题中定义的转换规则。 的每一个元素`newNums`完全按照要求进行计算，并重复该过程直到保留一个值以保证正确的结果。 

尽管这在技术上是一种强力模拟，但由于输入量非常小，所以它已经足够高效了。 不需要更高级的优化。 

### 最佳方法

 关键的观察结果是，该问题在每次迭代期间自然地将输入大小缩小一半。 由于数组长度始终是`2`，我们可以重复模拟该过程，直到只剩下一个元素。 

在每个级别：

 - 我们一次处理所有元素。 
- 数组大小变为一半。 
- 总工作量呈递减顺序：$$n + \frac{n}{2} + \frac{n}{4} + \cdots$$这个几何级数总和为`O(n)`，使得模拟非常高效。 

我们可以通过重用相同的变量引用来进一步优化空间`nums`并在每轮之后将其分配给新构造的数组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 使用新数组直接模拟每个转换 |
 | 最佳| O(n) | O(n) | 相同的模拟，高效，因为数组大小每轮减半 |

 ## 算法演练

 1. 首先检查当前数组长度。 如果长度已经是`1`，立即返回唯一的元素，因为不需要任何操作。 
2. 当数组包含多个元素时，创建一个新的空数组，名为`new_nums`其大小最终将是当前数组的一半。 
3. 迭代索引`0`到`(len(nums) // 2) - 1`。 各指标`i`对应于当前数组中的一对元素。 
4. 对于每个`i`，计算配对索引：

 - 第一个元素：`nums[2 * i]`- 第二个元素：`nums[2 * i + 1]`5. 判断是否`i`是偶数还是奇数：

 - 如果`i`是偶数，使用附加两个值中较小的一个`min()`。 
- 如果`i`是奇数，使用以下方法附加两个值中较大的一个`max()`。 
6. 处理完所有对后，替换`nums`和`new_nums`。 这代表完成一整轮游戏。 
7. 重复该过程，直到数组大小变为`1`。 
8. 返回剩余元素。 

### 为什么它有效

 该算法之所以有效，是因为每次迭代都准确地再现了问题陈述中描述的转换。 下一个数组中的每个位置都是使用正确的运算计算的，或者`min`或者`max`，基于新索引的奇偶性。 由于数组长度保证是`2`，重复减半最终产生一个元素，这正是所需要的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def minMaxGame(self, nums: List[int]) -> int:
        while len(nums) > 1:
            new_nums = []

            for i in range(len(nums) // 2):
                first = nums[2 * i]
                second = nums[2 * i + 1]

                if i % 2 == 0:
                    new_nums.append(min(first, second))
                else:
                    new_nums.append(max(first, second))

            nums = new_nums

        return nums[0]
```该实现紧密遵循前面描述的算法。 当数组的长度大于一时，我们会重复处理该数组。 

在每次迭代中，我们创建一个名为的新数组`new_nums`。 我们循环遍历每对元素并决定是否应用`min`或者`max`根据是否有索引`i`是偶数还是奇数。 

使用变量`first`和`second`通过明确正在处理的对来提高可读性。 完成一轮后，我们分配`nums = new_nums`，有效缩小问题规模。 

Finally, when only one element remains, we return`nums[0]`。 

## 解决方案```go
func minMaxGame(nums []int) int {
    for len(nums) > 1 {
        newNums := make([]int, len(nums)/2)

        for i := 0; i < len(nums)/2; i++ {
            first := nums[2*i]
            second := nums[2*i+1]

            if i%2 == 0 {
                if first < second {
                    newNums[i] = first
                } else {
                    newNums[i] = second
                }
            } else {
                if first > second {
                    newNums[i] = first
                } else {
                    newNums[i] = second
                }
            }
        }

        nums = newNums
    }

    return nums[0]
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片和显式分配`make()`。 

我们不是动态追加元素，而是预先分配`newNums`与长度`len(nums)/2`并直接按索引赋值。 这避免了切片的重复增长，并且在 Go 中更为惯用。 

对于整数溢出没有特别的担忧，因为该问题仅比较值而不是对大数执行算术运算。 由于约束保证至少存在一个元素，因此访问`nums[0]`最后总是安全的。

 ## 边缘情况

 ### 单元素数组

 输入如`nums = [3]`是一个重要的边缘情况，因为不应发生任何转换。 幼稚的实现可能仍会尝试创建新的数组或进程对，从而导致索引错误。 此实现正确处理了这种情况，因为`while len(nums) > 1`条件立即失败，并返回单个元素。 

### 最小有效长度

 恰好有两个元素的数组，例如`[1, 2]`，可以揭示索引错误。 由于仅存在一对，因此仅应应用偶数索引规则，这意味着我们必须使用`min`。 该实现正确处理了这个问题，因为`i = 0`是均匀的。 

### 相等的值

 输入如`[5, 5]`或者包含重复数字的数组可能会暴露逻辑错误，其中比较错误地偏向一侧。 自从`min(5, 5)`和`max(5, 5)`都返回`5`，实现行为一致并保持正确性。 

### 多个减少级别

 更大的输入，例如`[1,3,5,2,4,8,2,2]`需要多轮收缩。 在迭代之间重新分配工作数组时经常会出现错误。 此实现通过替换来避免该问题`nums`和`new_nums`每轮之后，确保每个级别都在最新的转换数组上运行。
