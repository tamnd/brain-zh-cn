[LeetCode 问题 2242](https://leetcode.com/problems/maximum-score-of-a-node-sequence/)

 **难度：** 🔴难
 **主题：** 数组、图论、排序、枚举

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个无向图`n`节点。 每个节点都有一个分数，图边定义哪些节点直接连接。 我们必须找到一个由四个不同节点组成的有效序列，使得序列中的每个相邻对之间都有一条边。 

有效的序列如下所示：```
a - b - c - d
```这意味着：

-`(a, b)`必须是一个边缘
 -`(b, c)`必须是一个边缘
 -`(c, d)`必须是一个边缘
 - 所有四个节点必须不同

 该序列的得分为：```
scores[a] + scores[b] + scores[c] + scores[d]
```我们必须返回长度为 4 的所有有效序列中的最大可能分数。如果不存在这样的序列，我们返回`-1`。 

该图是无向的，所以如果`[u, v]`存在于`edges`，则允许从以下地点出发旅行：`u`到`v`和来自`v`到`u`。 

约束在这里非常重要：

 -`n`可以达到`5 * 10^4`-`edges.length`也可以达到`5 * 10^4`这些限制立即排除了对所有四元组节点的强力枚举。 枚举所有可能的 4 节点序列的成本太高。 

该图相对稀疏，因为边的数量最多可达`5 * 10^4`， 不是`n^2`。 这暗示基于边缘的策略可能会很有效。 

一些边缘情况很重要：

 - 该图可能不包含任何长度为 3 的路径，因此答案可能是`-1`。 
- 多个高分节点可能重叠，需要仔细检查清晰度。 
- 某些节点可能具有非常大的度数，因此天真地迭代所有邻居组合可能会变得昂贵。 
- 最佳序列可能不是唯一的。 
- 因为分数可以达到`10^8`，总序列分数可能会变大，但它仍然安全地适合 32 位有符号整数范围，因为`4 * 10^8`下面是`2^31 - 1`。 

## 方法

 ### 蛮力方法

 一个简单的强力解决方案将枚举四个不同节点的每个可能的有序序列：```
(a, b, c, d)
```对于每个序列，我们将检查：

 - 所有节点是否不同
 - 是否有边缘`(a,b)`,`(b,c)`， 和`(c,d)`存在

 如果有效，我们计算总分并跟踪最大值。 

这种方法是正确的，因为它明确地检查每个可能的候选序列。 

然而，其复杂性是灾难性的。 最多有：```
O(n^4)
```可能是四倍。 和`n = 5 * 10^4`，这是完全不可行的。 

即使使用邻接集优化边缘查找，枚举本身在时间限制内也是不可能的。 

### 最佳方法

 关键的观察是每个有效序列都有一个中间边缘：```
a - b - c - d
      ^
    middle edge
```如果我们修复中间边缘`(b, c)`， 然后：

-`a`必须是邻居`b`-`d`必须是邻居`c`- 所有四个节点必须不同

 我们不是探索每个四元组，而是迭代每个边缘作为序列的中心。 

现在问题变成：

 > 对于每条边`(b, c)`，找到最好的邻居`b`和最好的邻居`c`不违反独特性。 

进一步优化使解决方案变得高效：

 对于每个节点，我们只保留其得分最高的 3 个邻居。 

为什么这就足够了？ 

有效的序列每侧只需要一个邻居。 即使一些顶级邻居由于重复节点而发生冲突，拥有最好的 3 个邻居也能保证我们仍然有足够的候选者来测试所有有效的组合。 

这极大地减少了搜索空间。

 | ---| ---| ---| ---|
 | 蛮力 | O(n^4) | O(n^4) | O(1) | O(1) | 枚举所有可能的 4 节点序列 |
 | 最佳| O(E) | O(E) | 使用顶部邻居和以边缘为中心的枚举 |

 这里，`E`表示边的数量。 

## 算法演练

 1. 为图构建邻接结构。 

对于每个节点，我们存储其邻居。 然而，我们最终只关心得分最高的前 3 个邻居，而不是无限期地保留所有邻居。 
2. 对于每一个边缘`[u, v]`， 添加：

-`v`作为候选邻居`u`-`u`作为候选邻居`v`每个候选人都会根据邻居的分数进行评估。 
3. 对于每个节点，按照邻居得分降序排列其邻居列表。 

然后只保留前 3 个邻居。 

这种优化至关重要，因为它将未来的枚举工作限制在一个微小的恒定大小。 
4. 将答案初始化为`-1`。 

如果我们从未发现有效的序列，则该值将保持不变。 
5.迭代每条边`(b, c)`。 

将此边视为中间连接：```
a - b - c - d
```6. 对于每个候选邻居`a`的`b`以及每一个候选邻居`d`的`c`：

 - 确保所有四个节点都是不同的
 - 具体来说：

 -`a != c`-`d != b`-`a != d`7. 如果序列有效，则计算：```
scores[a] + scores[b] + scores[c] + scores[d]
```更新最大答案。 
8. 处理完所有边后，返回找到的最大分数。 

### 为什么它有效

 每个有效序列必须包含一些中间边缘`(b, c)`。 通过迭代每条边，我们保证考虑每一个可能的有效序列。 

对于每个节点，仅保留前 3 个邻居就足够了，因为最多有几个候选节点由于重叠约束而变得无效。 如果存在有效的最佳序列，那么这些最佳候选序列之一仍然可用。 

因此，该算法探索所有相关的高值组合，同时避免不必要的枚举。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumScore(self, scores: List[int], edges: List[List[int]]) -> int:
        n = len(scores)

        # Store neighbors for each node
        neighbors = [[] for _ in range(n)]

        for u, v in edges:
            neighbors[u].append(v)
            neighbors[v].append(u)

        # Keep only top 3 neighbors by score
        for node in range(n):
            neighbors[node].sort(key=lambda x: scores[x], reverse=True)
            neighbors[node] = neighbors[node][:3]

        answer = -1

        # Try every edge as the middle edge
        for b, c in edges:
            for a in neighbors[b]:
                for d in neighbors[c]:
                    # All four nodes must be distinct
                    if a == c or d == b or a == d:
                        continue

                    total = scores[a] + scores[b] + scores[c] + scores[d]
                    answer = max(answer, total)

        return answer
```实现首先为图构建邻接表。 每个节点存储其邻居节点。 

接下来，每个邻居列表按邻居得分降序排序。 然后我们将列表截断为仅前 3 个邻居。 这确保了未来的处理每个边缘的时间保持恒定。 

主循环将每个边缘视为可能序列的中间边缘。 对于边缘的每一侧，我们迭代顶部邻居候选者。 

独特性检查确保没有节点在序列中出现多次。 

每当找到有效序列时，就会计算其分数并与当前最佳答案进行比较。 

最后返回最高分，或者`-1`如果不存在有效序列。 

## 解决方案```go
package main

import "sort"

func maximumScore(scores []int, edges [][]int) int {
	n := len(scores)

	neighbors := make([][]int, n)

	for _, edge := range edges {
		u, v := edge[0], edge[1]

		neighbors[u] = append(neighbors[u], v)
		neighbors[v] = append(neighbors[v], u)
	}

	// Keep only top 3 neighbors by score
	for i := 0; i < n; i++ {
		sort.Slice(neighbors[i], func(a, b int) bool {
			return scores[neighbors[i][a]] > scores[neighbors[i][b]]
		})

		if len(neighbors[i]) > 3 {
			neighbors[i] = neighbors[i][:3]
		}
	}

	answer := -1

	// Try every edge as the middle edge
	for _, edge := range edges {
		b, c := edge[0], edge[1]

		for _, a := range neighbors[b] {
			for _, d := range neighbors[c] {

				// All four nodes must be distinct
				if a == c || d == b || a == d {
					continue
				}

				total := scores[a] + scores[b] + scores[c] + scores[d]

				if total > answer {
					answer = total
				}
			}
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

主要区别在于使用`sort.Slice`对邻居列表进行排序。 排序后切片被截断为长度3。 

Go 整数可以安全地处理最大可能分数，因为总和永远不会超过`4 * 10^8`。

class Solution:
    def maximumScore(self, scores: List[int], edges: List[List[int]]) -> int:
        n = len(scores)

        neighbors = [[] for _ in range(n)]

        for u, v in edges:
            neighbors[u].append(v)
            neighbors[v].append(u)

        for node in range(n):
            neighbors[node].sort(key=lambda x: scores[x], reverse=True)
            neighbors[node] = neighbors[node][:3]

        answer = -1

        for b, c in edges:
            for a in neighbors[b]:
                for d in neighbors[c]:
                    if a == c or d == b or a == d:
                        continue

                    answer = max(
                        answer,
                        scores[a] + scores[b] + scores[c] + scores[d]

        return answer

 ## 边缘情况

 当图不包含任何长度为 3 的路径时，就会出现一种重要的边缘情况。图可能包含许多节点和边，但仍然无法生成有效的 4 节点序列。 星图是一个典型的例子，因为每条路径都必须重复经过中心节点，违反了唯一性要求。 实现自然地处理了这个问题，因为答案仍然存在`-1`除非发现有效的组合。 

另一个重要的情况涉及重叠的高分邻居。 假设中间边两侧的最佳邻居候选者是同一个节点。 粗心的实现可能会意外地重复使用该节点两次。 显式的唯一性检查：```
if a == c or d == b or a == d:
```防止此问题并保证所有四个节点保持唯一。 

第三种微妙的边缘情况涉及非常高的节点。 一些节点可能连接到数千个邻居。 对所有邻居进行简单的嵌套迭代会变得太慢。 仅存储前 3 个邻居的优化可保持运行时高效，同时仍保持正确性。 即使某些候选者发生冲突，三个选项也足以确保仍然探索所有有效的高分组合。
