[LeetCode 问题 2224](https://leetcode.com/problems/minimum-number-of-operations-to-convert-time/)

 **难度：** 🟢简单
 **主题：** 字符串、贪婪

 ## 解决方案

 ## 问题理解

 该问题要求我们计算转换一个 24 小时时间字符串所需的最少操作次数，`current`，进入另一个，`correct`。 两个输入的格式为`"HH:MM"`， 在哪里`HH`小时数是从`00`到`23`和`MM`距`00`到`59`。 每个操作都允许我们将当前时间增加 **1、5、15 或 60 分钟**，并且我们可以根据需要多次执行这些操作。 目标是找到所需的最少操作数。 

输入约束保证`current`小于或等于`correct`，因此我们永远不必处理负时差或午夜过后的环绕。 因此，以分钟为单位的最大可能差异是`23*60 + 59 = 1439`分钟。 重要的边缘情况包括`current`等于`correct`（需要零操作）、差异较小时（1-4 分钟）、差异较大时（需要多个 60 分钟增量）。 

## 方法

 暴力方法会以所有可能的顺序重复尝试每个操作，直到达到`correct`。 虽然这最终会产生正确的结果，但效率非常低且不必要，特别是因为序列的数量随着时间的差异呈指数增长。 

最佳解决方案的关键见解是**每一步贪婪地选择最大可能的操作**。 通过始终应用不会超过剩余差异的最大增量，我们可以最大限度地减少操作数量。 这是有效的，因为所有允许的操作都是彼此的除数或因数，确保将较大的差异分解为较小的步骤始终与允许的操作匹配。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^n) | O(4^n) | O(n) | 递归探索所有操作序列 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 由于可整性，最大运算的贪心减法有效 |

 ## 算法演练

 1. **将时间字符串转换为分钟**：同时转换两者`current`和`correct`从`"HH:MM"`自午夜以来的整数分钟。 这简化了差异的算术。 
2. **计算差值**：减去总分钟数`current`从`correct`。 这给出了我们需要完成操作的总分钟数。 
3. **应用贪婪运算**：定义运算数组`[60, 15, 5, 1]`。 对于每个操作：

 - 将剩余差值除以操作即可得出可以应用的次数。 
- 按此商增加操作计数。 
- 使用模运算减少剩余差异。 
4. **返回总操作数**：处理完所有操作后，总和就是达到的最小步数`correct`。 

**为什么有效：** 在每一步中，我们使用最大的可用增量消耗尽可能多的剩余差异。 由于操作是较小操作的倍数，因此这种贪婪方法保证了最少的步骤。 

## Python 解决方案```python
class Solution:
    def convertTime(self, current: str, correct: str) -> int:
        def time_to_minutes(t: str) -> int:
            hours, minutes = map(int, t.split(':'))
            return hours * 60 + minutes
        
        current_minutes = time_to_minutes(current)
        correct_minutes = time_to_minutes(correct)
        diff = correct_minutes - current_minutes
        operations = 0
        for op in [60, 15, 5, 1]:
            operations += diff // op
            diff %= op
        return operations
```该实现首先将时间转换为分钟以便于计算。 然后，它计算差异，按降序迭代允许的增量，计算每个增量可以应用的次数，并减少差异。 最后，它返回操作总数。 

## 解决方案```go
func convertTime(current string, correct string) int {
    timeToMinutes := func(t string) int {
        hours := (int(t[0]-'0')*10 + int(t[1]-'0'))
        minutes := (int(t[3]-'0')*10 + int(t[4]-'0'))
        return hours*60 + minutes
    }

    diff := timeToMinutes(correct) - timeToMinutes(current)
    operations := 0
    for _, op := range []int{60, 15, 5, 1} {
        operations += diff / op
        diff %= op
    }
    return operations
}
```在 Go 中，我们使用 ASCII 算术手动处理字符串到整数的转换，这避免了导入额外的库。 除此之外，逻辑与 Python 完全一致。 应用贪婪策略，按降序迭代操作片段。 

## 工作示例

 **示例 1：当前 =“02:30”，正确 =“04:35”**

 | 步骤| 差异| 操作=60 | 操作=15 | 操作=5 | 操作=1 | 运营|
 | --- | --- | --- | --- | --- | --- | --- |
 | 初始| 125 | 125 2 | 0 | 1 | 0 | 3 |

 解释： 125 分钟的差异。 使用 2x60（120 分钟），然后使用 1x5（5 分钟）。 总操作 = 3。 

**示例 2：当前 =“11:00”，正确 =“11:01”**

 | 步骤| 差异| 操作=60 | 操作=15 | 操作=5 | 操作=1 | 运营|
 | --- | --- | --- | --- | --- | --- | --- |
 | 初始| 1 | 0 | 0 | 0 | 1 | 1 |

 解释：只有1分钟的差别，所以1次操作1分钟。

 ## 边缘情况

 一个重要的边缘情况是当`current`等于`correct`。 这里，差值为零，算法正确返回零操作，而无需进入循环。 当差异小于最小操作增量（例如 1-4 分钟）时，会出现另一种边缘情况。 贪心算法可以处理这个问题，因为 1 分钟的操作可以确保覆盖任何小的余数。 第三种边缘情况是当差异恰好是 60 分钟的倍数时，应该只使用小时运算。 该算法自然地通过除以 60 并余数为零来处理此问题。 所有这些边缘情况都可以通过转换为分钟和降序贪婪应用操作来正确处理。
