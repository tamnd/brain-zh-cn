[LeetCode 问题 2245](https://leetcode.com/problems/maximum-trailing-zeros-in-a-cornered-path/)

 **难度：** 🟡 中等
 **主题：** 数组、矩阵、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们在矩阵中找到一条路径，其乘积包含最大可能数量的尾随零。 

数字中的尾随零是由 10 的因数创建的，每个 10 的因数都来自一个 2 的因数与一个 5 的因数配对。因此，乘积中尾随零的数量为：$$\min(\text{count of factor 2}, \text{count of factor 5})$$网格包含正整数，我们可以构造一条直线移动或恰好转一圈的路径。 该路径无法重新访问单元格。 

因此，路径形状是以下之一：

 - 水平直
 - 直线垂直
 - L形车削一次

 运动可以发生在任何方向：

 - 向左然后向上
 - 向左然后向下
 - 然后就起来
 - 马上下来

 对于每条有效的有角路径，我们计算沿路径的所有数字的乘积，并确定该乘积包含多少个尾随零。 我们必须返回最大可能的值。 

约束条件很重要：

 -$1 \le m \times n \le 10^5$- 每个值最多为 1000

 对每条路径和每件产品进行强力模拟的成本太高，因为可能的路径数量非常大。 

一个关键的观察是我们永远不需要完整的产品。 我们只需要：

 - 2 的因数总数
 - 因数总数为 5

 由于每个数字最多为 1000，因此因式分解非常便宜。 

重要的边缘情况包括：

 - 只有一行或一列的网格
 - 没有转弯的路径
 - 不包含 2 或 5 因子的细胞
 - 像 1 这样的值，没有任何贡献
 - 避免重复计算转动单元

 ## 方法

 ### 蛮力

 暴力解决方案将枚举所有可能的拐角路径。 

对于每个单元格，我们可以尝试：

 - 向左/向右延伸
 - 向上/向下延伸
 - 将线段组合成 L 形路径

 对于每条路径，我们将所有值相乘或动态维护素因数计数。 

这种方法是正确的，因为它明确地评估每条有效路径。 然而，它太慢了。 即使我们避免大整数乘法，可能的路径数量也大致为：$$O(mn(m+n))$$反复重新计算因子计数变得低效。 

### 关键见解

 尾随零仅取决于 2 和 5 的计数。 

我们不直接处理产品，而是将每个细胞转化为：

 - 2 的因数个数
 - 5 的因数个数

 然后我们为行和列构建前缀和。 

使用前缀和可以让我们计算恒定时间内沿任何水平或垂直段的 2 和 5 的总数。 

然后可以通过组合以下方式在恒定时间内评估每个拐角路径：

 - 一个水平段
 - 一个垂直段
 - 减去一次转动单元，因为它属于两个段

 这将问题减少到检查每个单元的四个 L 形配置。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|

 ## 算法演练

 1. 预先计算每个单元格的 2 和 5 因子的数量。 

对于网格中的每个值，重复除以 2 和 5，以计算每个质因数出现的次数。 

例如：

 - 20 贡献两个 2 和一个 5
 - 40 贡献 3 个 2 和 1 个 5
 2. 构建行前缀和。 

对于每一行，维护以下累积计数：

 - 2 的因数
 - 5 的因数

 这使我们能够在恒定时间内查询任何水平段。 
3. 构建列前缀和。 

同样，垂直计算每列的累积计数。 

这允许恒定时间垂直段查询。 
4、把每一个细胞都当作转折点。 

每个有效的拐角路径都可以通过选择来表示：

 - 一个水平方向
 - 一个垂直方向

 有四种可能：

 - 向上+向左
 - 向上+向右
 - 向下+向左
 - 向下+向右
 5. 计算每个形状的因子总计。 

对于每个配置：

 - 检索水平段计数
 - 检索垂直段计数
 - 减去转动细胞一次，因为它被计数了两次
 6. 计算尾随零。 

尾随零的数量为：$$\min(\text{total twos}, \text{total fives})$$更新全局最大值。 
7. 返回最大结果。 

### 为什么它有效

 每条拐角路径均由在转向单元处相交的一个水平段和一个垂直段组成。 前缀和让我们能够准确有效地计算两个段。 由于尾随零仅取决于 2 和 5 的计数，因此评估每个单元格的所有四个方向组合可以保证我们检查每个可能的有效路径。 因此，算法总是能找到最优答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxTrailingZeros(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])

        twos = [[0] * n for _ in range(m)]
        fives = [[0] * n for _ in range(m)]

        def count_factor(x: int, factor: int) -> int:
            count = 0
            while x % factor == 0:
                x //= factor
                count += 1
            return count

        # Count factors of 2 and 5 for each cell
        for r in range(m):
            for c in range(n):
                value = grid[r][c]
                twos[r][c] = count_factor(value, 2)
                fives[r][c] = count_factor(value, 5)

        # Row prefix sums
        row2 = [[0] * (n + 1) for _ in range(m)]
        row5 = [[0] * (n + 1) for _ in range(m)]

        for r in range(m):
            for c in range(n):
                row2[r][c + 1] = row2[r][c] + twos[r][c]
                row5[r][c + 1] = row5[r][c] + fives[r][c]

        # Column prefix sums
        col2 = [[0] * n for _ in range(m + 1)]
        col5 = [[0] * n for _ in range(m + 1)]

        for c in range(n):
            for r in range(m):
                col2[r + 1][c] = col2[r][c] + twos[r][c]
                col5[r + 1][c] = col5[r][c] + fives[r][c]

        answer = 0

        for r in range(m):
            for c in range(n):
                cell2 = twos[r][c]
                cell5 = fives[r][c]

                left2 = row2[r][c + 1]
                left5 = row5[r][c + 1]

                right2 = row2[r][n] - row2[r][c]
                right5 = row5[r][n] - row5[r][c]

                up2 = col2[r + 1][c]
                up5 = col5[r + 1][c]

                down2 = col2[m][c] - col2[r][c]
                down5 = col5[m][c] - col5[r][c]

                paths = [
                    (left2 + up2 - cell2, left5 + up5 - cell5),
                    (left2 + down2 - cell2, left5 + down5 - cell5),
                    (right2 + up2 - cell2, right5 + up5 - cell5),
                    (right2 + down2 - cell2, right5 + down5 - cell5),
                ]

                for total2, total5 in paths:
                    answer = max(answer, min(total2, total5))

        return answer
```实现首先将每个网格值转换为其因子 2 和 5 的贡献。此预处理步骤至关重要，因为尾随零仅取决于这两个素数。 

接下来，该解决方案构造行和列前缀和。 这些数组允许恒定时间检索任何水平或垂直段总数。 

对于每个单元格，代码计算：

 - 左段总计
 - 右段总计
 - 向上分段总计
 - 向下段总计

 当前单元格属于每个 L 形中的两个段，因此其因子计数会被减去一次以避免重复计算。 

最后，该解决方案评估所有四种可能的角配置并更新尾随零的最大数量。 

## 解决方案```go
func maxTrailingZeros(grid [][]int) int {
	m := len(grid)
	n := len(grid[0])

	twos := make([][]int, m)
	fives := make([][]int, m)

	for i := 0; i < m; i++ {
		twos[i] = make([]int, n)
		fives[i] = make([]int, n)
	}

	countFactor := func(x int, factor int) int {
		count := 0
		for x%factor == 0 {
			x /= factor
			count++
		}
		return count
	}

	for r := 0; r < m; r++ {
		for c := 0; c < n; c++ {
			value := grid[r][c]
			twos[r][c] = countFactor(value, 2)
			fives[r][c] = countFactor(value, 5)
		}
	}

	row2 := make([][]int, m)
	row5 := make([][]int, m)

	for i := 0; i < m; i++ {
		row2[i] = make([]int, n+1)
		row5[i] = make([]int, n+1)
	}

	for r := 0; r < m; r++ {
		for c := 0; c < n; c++ {
			row2[r][c+1] = row2[r][c] + twos[r][c]
			row5[r][c+1] = row5[r][c] + fives[r][c]
		}
	}

	col2 := make([][]int, m+1)
	col5 := make([][]int, m+1)

	for i := 0; i <= m; i++ {
		col2[i] = make([]int, n)
		col5[i] = make([]int, n)
	}

	for c := 0; c < n; c++ {
		for r := 0; r < m; r++ {
			col2[r+1][c] = col2[r][c] + twos[r][c]
			col5[r+1][c] = col5[r][c] + fives[r][c]
		}
	}

	maxVal := func(a, b int) int {
		if a > b {
			return a
		}
		return b
	}

	minVal := func(a, b int) int {
		if a < b {
			return a
		}
		return b
	}

	answer := 0

	for r := 0; r < m; r++ {
		for c := 0; c < n; c++ {

			cell2 := twos[r][c]
			cell5 := fives[r][c]

			left2 := row2[r][c+1]
			left5 := row5[r][c+1]

			right2 := row2[r][n] - row2[r][c]
			right5 := row5[r][n] - row5[r][c]

			up2 := col2[r+1][c]
			up5 := col5[r+1][c]

			down2 := col2[m][c] - col2[r][c]
			down5 := col5[m][c] - col5[r][c]

			candidates := [][]int{
				{left2 + up2 - cell2, left5 + up5 - cell5},
				{left2 + down2 - cell2, left5 + down5 - cell5},
				{right2 + up2 - cell2, right5 + up5 - cell5},
				{right2 + down2 - cell2, right5 + down5 - cell5},
			}

			for _, pair := range candidates {
				answer = maxVal(answer, minVal(pair[0], pair[1]))
			}
		}
	}

	return answer
}
```Go 实现遵循与 Python 解决方案相同的结构。 由于 Go 没有为整数提供内置的最小和最大帮助器，因此显式定义了帮助器函数。 

切片用于所有前缀和数组。 整数溢出不是问题，因为我们从不计算实际的乘积，只计算质因数。

 ## 边缘情况

 ### 单行或单列

 只有一行或一列的网格无法形成传统的L形，因为没有第二维可供转动。 然而，直线路径仍然有效，因为该问题允许路径最多有一圈。 

如果实现假设每条路径都必须弯曲，这很容易导致错误。 前缀和方法自然可以处理这些情况，因为水平或垂直段的长度可能仅为一。 

### 对转动单元进行双重计数

 当组合水平和垂直段时，转动单元属于这两个段。 忘记减去一次会导致因子计数膨胀和错误答案。 

组合两个片段后，该实现显式地减去当前单元格的因子贡献。 

### 没有 5 因数的网格

 如果乘积同时包含 2 的因数和 5 的因数，则它只能有尾随零。某些网格可能包含许多偶数，但不包含 5 的倍数。 

仅关注 2 的幂的幼稚实现可能会错误地报告正的尾随零。 由于该算法总是计算：$$\min(\text{twos}, \text{fives})$$只要缺少一种因子类型，结果就会正确地变为零。 

### 值等于 1

 数字 1 不贡献 2 或 5 的因子。包含许多 1 的长路径仍然是最佳的，因为它们连接有用的单元而不减少总数。 

该实现自然地处理了这个问题，因为 1 的因子计数为零。
