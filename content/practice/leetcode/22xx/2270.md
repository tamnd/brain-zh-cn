[LeetCode 问题 2270](https://leetcode.com/problems/number-of-ways-to-split-array/)

 **难度：** 🟡 中等
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们确定分割给定 **0 索引** 数组的方法数`nums`分成两个非空连续子数组，使得第一部分的总和**大于或等于**第二部分的总和。 形式上，在索引处进行分割`i`有效，如果`sum(nums[0:i+1]) >= sum(nums[i+1:n])`和`0 <= i < n-1`确保右子数组中至少有一个元素。 

输入`nums`是一个具有长度的整数数组`n`之间`2`和`10^5`，元素的范围可以是`-10^5`到`10^5`。 输出是一个整数，表示有效分割索引的计数。 

主要观察结果包括：我们需要一种有效计算子数组总和的方法，因为每个分割的简单求和对于大型数组来说太慢了。 允许使用负数，这意味着总和可能会不可预测地减少或增加，因此我们不能假设排序值或正值。 这些约束保证总是至少存在一种可能的分裂，因为`n >= 2`。 

边缘情况包括全部为负数的数组、仅包含两个元素的数组以及具有交替较大正值和负值的数组，这些值可能会影响总和比较。 

## 方法

 蛮力方法很简单。 对于每个有效的分割索引`i`从`0`到`n-2`,计算左子数组的和`nums[0:i+1]`以及右子数组的和`nums[i+1:n]`，然后进行比较。 这种方法是正确的，因为它显式检查每个索引的拆分条件。 然而，由于反复重新计算总和，其时间复杂度为 O(n^2)，这对于`n = 10^5`。 

最佳方法利用**前缀和**。 首先，计算数组的总和。 然后，迭代该数组，维护左子数组的运行总和。 右子数组和可以计算为`total_sum - left_sum`时间复杂度为 O(1)。 每次比较`left_sum >= right_sum`可以在恒定时间内完成，给出总体线性时间复杂度 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 显式计算每个分割的左右总和 |
 | 最佳| O(n) | O(1) | O(1) | 使用运行和和总和有效计算右子数组和 |

 ## 算法演练

 1. 计算数组的总和`nums`并将其存储在`total_sum`。 这代表所有元素的总和。 
2. 初始化`left_sum`到 0 和一个计数器`valid_splits`至 0。 
3. 使用索引迭代数组`i`从`0`到`n-2`。 对于每个元素，添加`nums[i]`到`left_sum`。 
4. 计算`right_sum`作为`total_sum - left_sum`。 这给出了索引右侧剩余元素的总和`i`。 
5. 如果`left_sum >= right_sum`, 增量`valid_splits`。 
6. 继续直到循环结束。 返回`valid_splits`作为最终答案。 

为什么它有效：在每一步，`left_sum`维护直到当前索引的元素总和，并且`right_sum`使用总和有效地计算剩余金额。 比较完全按照问题中指定的条件进行检查，确保正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def waysToSplitArray(self, nums: List[int]) -> int:
        total_sum = sum(nums)
        left_sum = 0
        valid_splits = 0
        
        for i in range(len(nums) - 1):
            left_sum += nums[i]
            right_sum = total_sum - left_sum
            if left_sum >= right_sum:
                valid_splits += 1
        
        return valid_splits
```在实施过程中，`total_sum`存储整个数组的总和。 循环迭代直到`n-2`因为最后一个元素不能是有效的分割。 在每次迭代中，我们都会更新`left_sum`并计算`right_sum`使用总和。 如果条件成立，我们增加`valid_splits`柜台。 最后，我们返回计数。 

## 解决方案```go
func waysToSplitArray(nums []int) int {
    totalSum := 0
    for _, num := range nums {
        totalSum += num
    }

    leftSum := 0
    validSplits := 0

    for i := 0; i < len(nums)-1; i++ {
        leftSum += nums[i]
        rightSum := totalSum - leftSum
        if leftSum >= rightSum {
            validSplits++
        }
    }

    return validSplits
}
```在 Go 中，我们使用一个标准`for`循环计算`totalSum`首先，然后迭代数组直到`len(nums)-1`。 我们有效地使用整数算术和切片，保持`leftSum`和`rightSum`每一步都会更新。 此实现反映了 Python 逻辑。

 ## 边缘情况

 首先，具有两个元素的最小可能数组`[a, b]`。 这是一种边缘情况，因为只有一种可能的分裂。 该代码通过仅迭代来正确处理它`n-2`，单次比较就保证了正确性。 

二、全负数的数组，如`[-5, -2, -3, -1]`。 当我们在其中包含更多元素时，负和可能会减少`left_sum`。 算法正确计算`left_sum`和`right_sum`使用有符号整数，即使总和为负数也能确保正确的比较。 

第三，由于正数和负数交替而导致总和振荡的数组，例如，`[5, -5, 5, -5, 5]`。 如果假设总和单调增加，则幼稚的实现可能会失败。 前缀和方法可以正确处理这个问题，因为每次比较都是动态地与运行总和和总和进行的，与数字模式无关。
