[LeetCode 第 2298 题](https://leetcode.com/problems/tasks-count-in-the-weekend/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个数据库表，名为`Tasks`，其中每一行代表一个已提交的任务。 每个任务包含三个字段：

 -`task_id`，任务的唯一标识符
 -`assignee_id`, 分配给任务的用户
 -`submit_date`, 任务提交日期

 目标是计算两个聚合计数：

 -`weekend_cnt`, 周六或周日提交的任务数
 -`working_cnt`，周一至周五提交的任务数

 输出应包含具有这两个值的单行。 

问题的重要部分是确定给定日期是周末还是工作日。 SQL 提供了日期函数，允许我们从日期中提取星期几，这使得分类变得简单。 

输入大小没有明确限制，但由于这是一个数据库聚合问题，因此预期的解决方案应该在一次扫描中有效地处理所有行。 我们不需要单独存储每个任务的中间结果。 

需要考虑一些重要的边缘情况：

 - 所有任务都可能落在周末，这意味着`working_cnt`应该成为`0`。 
- 所有任务都可能落在工作日，这意味着`weekend_cnt`应该成为`0`。 
- 该表可能只包含一行。 
- 多个任务可以共享相同的提交日期。 
- 该解决方案必须根据 SQL 数据库的工作日编号系统正确识别星期六和星期日。 

因为问题只要求计数，所以我们不需要排序、按受让人分组或任何复杂的连接。 

## 方法

 ### 蛮力方法

 蛮力的想法是单独处理每一行并手动确定日期是否对应于周末或工作日。 一种可能的实现是从表中提取所有行，计算每个任务的工作日，并维护两个计数器。 

这是有效的，因为每个任务只对周末计数或工作日计数贡献一次。 

然而，在真实的数据库系统中，将所有行移出数据库引擎是低效的。 它会增加内存使用量并阻止数据库优化器在内部执行聚合。 尽管渐近复杂度仍然是线性的，但它不是首选的 SQL 方法。 

### 最佳方法

 关键的观察结果是 SQL 聚合函数可以在单个查询中计算这两个计数。 

我们可以使用条件聚合：

 - 如果提交日是周六或周日，请贡献`1`到`weekend_cnt`- 否则，贡献`1`到`working_cnt`使用`SUM(CASE WHEN ...)`允许数据库引擎扫描一次表并有效地计算两个总数。 

在 MySQL 中，`WEEKDAY()`函数特别有用：

 - 星期一 = 0
 - 星期二 = 1
 - 星期三 = 2
 - 星期四 = 3
 - 星期五 = 4
 - 星期六 = 5
 - 周日 = 6

 因此：

 -`WEEKDAY(submit_date) >= 5`识别周末
 -`WEEKDAY(submit_date) < 5`确定工作日

 ## 算法演练

 1. 扫描所有行`Tasks`桌子。 
2. 对于每一行，使用以下方法确定工作日`WEEKDAY(submit_date)`。 
3. 如果工作日值为`5`或者`6`，将任务分类为周末任务。 
4. 否则，将该任务分类为工作日任务。 
5. 使用条件聚合`SUM(CASE WHEN ...)`增加适当的计数器。 
6. 以单行结果表形式返回最终聚合计数。 

### 为什么它有效

 每个任务都属于两个互斥类别之一：

 - 周末
 - 工作日

 的`CASE`表达式确保每行只对正确的计数器贡献一次。 由于查询扫描每一行并聚合所有贡献，因此最终计数保证是正确的。 

## Python 解决方案

 LeetCode 数据库问题是使用 SQL 而不是可执行的 Python 代码来解决的。 以下解决方案是应提交的确切查询。```python
SELECT
    SUM(CASE WHEN WEEKDAY(submit_date) >= 5 THEN 1 ELSE 0 END) AS weekend_cnt,
    SUM(CASE WHEN WEEKDAY(submit_date) < 5 THEN 1 ELSE 0 END) AS working_cnt
FROM Tasks;
```该查询使用两个条件聚合表达式。 

第一个表达式计算`weekend_cnt`。 对于每一行：

 - 如果工作日是星期六或星期日，请捐款`1`- 否则，贡献`0`第二个表达式计算`working_cnt`。 对于每一行：

 - 如果工作日是周一至周五，请贡献`1`- 否则，贡献`0`由于两种聚合都发生在同一个表扫描期间，因此该解决方案高效且简洁。

 ## 边缘情况

 当所有任务在工作日内提交时，就会出现一种重要的边缘情况。 有错误的实现可能会错误地返回`NULL`或者无法正确初始化周末计数器。 此解决方案避免了该问题，因为每一行都贡献`1`或者`0`通过`CASE`表达式。 

另一个重要的情况是所有任务都在周末提交。 如果工作日计数器处理不当，也可能会发生类似的错误。 由于查询始终独立计算两个聚合，因此结果保持准确。 

错误的一个微妙来源是误解返回的编号`WEEKDAY()`。 在 MySQL 中，星期一开始于`0`周日结束于`6`。 关于此编号的错误假设可能会导致周五或周日被错误分类。 实施明确检查`>= 5`对于周末，它仅正确识别周六和周日。 

最后的边缘情况涉及在同一天提交的多个任务。 由于查询聚合行而不是不同的日期，因此每个任务都会单独贡献计数。 这完全符合问题要求。
