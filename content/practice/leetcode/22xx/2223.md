[LeetCode 问题 2223](https://leetcode.com/problems/sum-of-scores-of-built-strings/)

 **难度：** 🔴难
 **主题：** 字符串、二分查找、滚动哈希、后缀数组、字符串匹配、哈希函数

 ## 解决方案

 ## 问题理解

 问题给了我们一个最终的字符串`s`并描述了通过在前面重复添加字符来构建字符串的过程。 这意味着每个中间字符串`si`实际上是最终字符串的后缀`s`。 

例如，如果：```
s = "abaca"
```然后：```
s1 = "a"
s2 = "ca"
s3 = "aca"
s4 = "baca"
s5 = "abaca"
```请注意，每个`si`简直就是最后一个`i`的字符`s`。 

各人的分数`si`定义为之间的**最长公共前缀**的长度`si`和最后的字符串`sn = s`。 

简单来说，对于每个后缀`s`，我们想知道：

 > 从开头开始有多少个字符与前缀匹配`s`？ 

然后我们将所有这些分数相加。 

另一种思考问题的方式是：

 对于每个后缀`s`，用完整字符串计算**最长公共前缀（LCP）**`s`，然后返回总数。 

例如：```
s = "babab"
```后缀：```
"b"      → LCP = 1
"ab"     → LCP = 0
"bab"    → LCP = 3
"abab"   → LCP = 0
"babab"  → LCP = 5
```全部的：```
1 + 0 + 3 + 0 + 5 = 9
```约束条件很重要：```
1 <= s.length <= 10^5
```一个长度的字符串`100,000`立即告诉我们二次算法可能会超时。 任何逐字符比较每个后缀的子字符串的方法都会太慢。 

该问题还保证：

 - 字符串仅包含小写英文字母。 
- 输入长度至少为`1`，这意味着我们永远不会有空字符串。 
- 每个中间字符串`si`是一个后缀`s`。 

重要的边缘情况包括具有所有相同字符的字符串、没有重复前缀的字符串以及非常短的输入（例如长度）`1`。 这些情况可能会暴露子字符串匹配逻辑中的错误或出现一个错误。 

## 方法

 ### 蛮力方法

 最直接的想法是生成每个后缀并将其与原始字符串逐个字符进行比较。 

对于从索引开始的每个后缀`i`:

 1. 比较`s[0]`和`s[i]`2. 比较`s[1]`和`s[i+1]`3. 继续直到字符不同或一个字符串结束
 4. 将匹配的长度添加到答案中

 例如：```
s = "babab"
```在索引处`2`:```
s = "babab"
suffix = "bab"
```比较：```
b == b
a == a
b == b
```分数=`3`。 

这是有效的，因为它显式地计算每个后缀所需的最长公共前缀。 

然而，最坏的情况会变得极其昂贵。 

考虑：```
s = "aaaaaaaaaa..."
```每个后缀几乎与整个前缀匹配。 

工作变成：```
n + (n-1) + (n-2) + ...
```这是：```
O(n²)
```为了`n = 100,000`，这太慢了。 

### 最优方法，Z 算法

 关键的观察是，问题是在暗中询问：

 > 对于每个后缀，找到与整个字符串匹配的最长前缀。 

这正是 **Z 算法** 的计算结果。 

字符串的 Z 数组存储：```
z[i] = longest substring starting at i
       that matches the prefix of s
```例如：```
s = "babab"
```Z 数组：```
[0, 0, 3, 0, 1]
```意义：```
index 0 → ignored
index 1 → match length 0
index 2 → "bab" matches prefix
index 3 → match length 0
index 4 → "b" matches prefix
```完整的字符串本身贡献：```
len(s)
```所以答案就变成了：```
sum(z) + n
```Z 算法在**线性时间内**计算所有前缀匹配，使其非常适合`10^5`人物。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 逐个字符比较每个后缀 |
 | 最优 Z 算法 | O(n) | O(n) | 一次性计算所有后缀的最长前缀匹配 |

 ## 算法演练

 我们使用 **Z 算法** 来有效地计算前缀匹配。 

### 第 1 步：初始化 Z 数组

 创建一个数组：```
z = [0] * n
```在哪里：```
z[i]
```存储以下之间的最长公共前缀：```
s
```和：```
s[i:]
```我们还维护一个匹配窗口：```
[left, right]
```该窗口表示当前已知与前缀匹配的子字符串。 

### 第 2 步：遍历字符串

 对于每个索引：```sql
i from 1 to n-1
```我们计算`z[i]`。 

指数`0`被跳过，因为完整的字符串与自身简单匹配。 

### 步骤 3：重用 Z-box 内之前的工作

 如果：```
i <= right
```那么我们就在一个已经匹配的区域内。 

我们可以重用以前的结果：```
z[i] = min(right - i + 1, z[i - left])
```这避免了多余的比较。 

这个想法是：

 由于我们已经知道某个段与前缀匹配，因此我们可以从较早的位置复制信息。 

### 第 4 步：延长比赛时间

 重用信息后，我们尝试进一步扩展匹配：```
while i + z[i] < n and s[z[i]] == s[i + z[i]]:
    z[i] += 1
```仅在必要时才继续进行字符比较。 

### 步骤5：更新匹配窗口

 如果新的比赛延续过去`right`:```
i + z[i] - 1 > right
```更新：```
left = i
right = i + z[i] - 1
```这会创建一个更大的可重用匹配区域。 

### 第 6 步：计算答案

 Z 数组存储除完整字符串本身之外的每个后缀的分数。 

自从：```
s == s
```最终字符串贡献：```
n
```返回：```
sum(z) + n
```### 为什么它有效

 Z 算法保证`z[i]`等于字符串前缀和后缀之间最长的公共前缀`i`。 由于每`si`是一个后缀`s`，每个所需分数恰好是一个 Z 值。 唯一缺失的情况是整个字符串本身，其分数等于`n`。 因此，将所有值相加即可得出正确的总分。 

## Python 解决方案```python
class Solution:
    def sumScores(self, s: str) -> int:
        n = len(s)
        z = [0] * n

        left = 0
        right = 0

        for i in range(1, n):
            if i <= right:
                z[i] = min(right - i + 1, z[i - left])

            while i + z[i] < n and s[z[i]] == s[i + z[i]]:
                z[i] += 1

            if i + z[i] - 1 > right:
                left = i
                right = i + z[i] - 1

        return sum(z) + n
```### 实现说明

 我们首先创建 Z 数组并初始化匹配边界`left`和`right`。 

变量：```
left, right
```表示当前的 Z-box，表示已知与前缀匹配的子字符串。 

对于每个索引`i`，我们首先检查它是否位于 Z 盒内。 如果是这样，我们可以重用之前的计算，而不是再次比较字符。 

接下来，我们使用以下命令手动扩展匹配`while`环形。 这确保存储的 Z 值成为最长的可能前缀匹配。 

每当找到更大的匹配区域时，我们就会更新 Z 框边界。 

最后，我们将所有 Z 值相加并添加`n`因为整个字符串完全匹配自身。 

## 解决方案```go
func sumScores(s string) int64 {
	n := len(s)
	z := make([]int, n)

	left, right := 0, 0

	for i := 1; i < n; i++ {
		if i <= right {
			z[i] = min(right-i+1, z[i-left])
		}

		for i+z[i] < n && s[z[i]] == s[i+z[i]] {
			z[i]++
		}

		if i+z[i]-1 > right {
			left = i
			right = i + z[i] - 1
		}
	}

	var total int64 = int64(n)

	for _, value := range z {
		total += int64(value)
	}

	return total
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```### Go 特定的实现差异

 Go 中的主要区别在于整数处理。 

返回类型为：```
int64
```因为总分会变大。 

例如：```
s = "aaaaaa..."
```总和接近：```
n * (n + 1) / 2
```为了`n = 100000`，这超出了标准 32 位整数限制。 

我们还定义了一个助手`min()`函数，因为 Go 在标准库中没有提供整数函数。 

切片用于 Z 数组，其行为类似于 Python 中的动态数组。

 ## 边缘情况

 ### 单字符串

 如果：```
s = "a"
```没有合适的后缀可供比较。 

唯一的字符串是：```
"a"
```其得分为`1`，因为字符串与自身完全匹配。 

这种情况很重要，因为循环从索引开始`1`永远不执行。 我们的实现通过返回来自然地处理它：```
sum(z) + n
```变成：```
0 + 1 = 1
```### 所有字符都相同

 考虑：```
s = "aaaaa"
```每个后缀与完整字符串共享一个长前缀：```
5 + 4 + 3 + 2 + 1
```这对于简单的方法来说是最坏的情况，因为几乎每次比较都会成功。 

Z 算法仍然高效，因为它通过 Z 盒重用先前的匹配信息，而不是重新计算每个字符比较。 

### 没有匹配的前缀

 对于：```
s = "abcdef"
```除了完整字符串之外的每个后缀都会立即不匹配：```
z = [0, 0, 0, 0, 0, 0]
```只有完整的字符串才能得出答案。 

这种情况确保实现正确处理即时不匹配，而不会错误地扩展 Z 盒。 

### 重复模式

 字符串如：```
"abababab"
```可能会很棘手，因为匹配重叠严重。 

简单的实现可能会重复地重新计算相同的比较。 

Z 算法通过从 Z 盒内部复制先前计算的匹配长度来避免此问题，即使对于高度重复的输入也能保持线性性能。
