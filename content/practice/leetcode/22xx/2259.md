 # LeetCode 2259 - 从数字中删除数字以最大化结果

 ## 问题理解

 问题给了我们一个名为`number`，代表一个正整数，一个字符`digit`，保证在内部至少出现一次`number`。 

我们的任务是删除恰好出现的一个`digit`from the string so that the resulting number is as large as possible. 结果还必须以字符串形式返回。 

Since the input is provided as a string instead of an integer, we should think in terms of string manipulation and lexicographical comparison. 由于所有字符都是数字，并且所有候选结果在删除后具有相同的长度，因此字典比较与数字比较的工作方式相同。 

例如，如果：```
number = "1231"
digit = "1"
```我们有两种可能的删除方式：

 - 删除第一个`'1'`→`"231"`- 删除第二个`'1'`→`"123"`自从`"231"`代表较大的数，正确答案是`"231"`。 

限制非常小：

 -`2 <= number.length <= 100`- 数字仅来自`'1'`到`'9'`-`digit`总是存在于`number`因为字符串长度最多为 100，所以即使是暴力解决方案也是完全可以接受的。 然而，这个问题的目的是奖励识别贪婪的观察，使我们能够有效地选择最佳的去除。 

一些边缘情况很重要：

 - 目标数字只能出现一次。 
- 多次删除可能会产生相同的结果。 
- 最好的移除可能不是第一次出现。 
- 最好的删除可能不是最后一次发生。 
- 相邻的相同数字可以建立平局。 
- 删除靠近前面的数字通常会比删除靠近末尾的数字产生更大的影响。 

了解数字位置如何影响最终值是最佳解决方案背后的关键见解。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试删除所有出现的`digit`。 

对于每个索引，其中`number[i] == digit`，我们通过跳过该字符来创建一个新字符串：```
candidate = number[:i] + number[i+1:]
```然后，我们比较所有生成的候选者并保留最大的候选者。 

这是有效的，因为我们明确评估了每一种有效的可能性。 由于这些可能性之一必须是最佳的，因此取最大值可以保证正确的答案。 

时间复杂度可以接受，因为字符串长度最多为100。如果有`n`字符，我们最多可以生成`n`候选字符串，以及每个字符串的构建成本`O(n)`，给出总复杂度`O(n²)`。 

### 最优贪心法

 贪婪洞察力来自于理解数字位置如何影响结果数字。 

比较两个相同长度的数字时，前面的数字比较后面的数字更重要。 因此，我们希望数字的左边尽早变得尽可能大。 

假设我们正在查看一个事件的发生`digit`在位置`i`。 

如果下一个数字，`number[i + 1]`，大于`digit`，那么删除当前发生的事件是有益的。 为什么？ 

因为删除较小的数字可以让较大的后续数字向左移动到更重要的位置。 

例如：```
number = "1231"
digit = "1"
```在索引 0 处：```
1 2 3 1
^
```下一个数字是`2`，大于`1`。 

删除这个`1`给出：```
231
```这比删除后面的更大`1`。 

因此，贪心规则为：

 - 删除下一个数字大于的第一个匹配项`digit`- 如果不存在这样的情况，则删除最后一次出现的`digit`这是有效的，因为延迟删除仅在后面的数字不大于时才有帮助。

 ## 算法演练

 1. 从左到右迭代字符串。 
2. 每当当前字符等于`digit`，检查下一个字符是否存在。 
3. 如果下一个字符大于`digit`，立即删除当前出现的位置并返回结果字符串。 
4. 这种删除是最佳的，因为将较大的数字移动到较早的位置可以尽早增加总数。 
5. 如果没有满足此条件的事件，则继续扫描直至结束。 
6. 循环结束后，删除最后出现的`digit`。 
7. 返回最终构造的字符串。 

### 为什么它有效

 该算法依赖于十进制数的位置意义。 前面的数字比较后面的数字对值的贡献更大。 如果删除一个数字可以使更大的数字更早地向左移动，那么该选择将主导以后的所有可能性。 

如果没有出现的下一个数字较大，则删除较早的出现将暴露较小或相等的数字，这无法改善结果。 在这种情况下，尽可能长时间地保持左侧不变是最好的，因此我们删除最后一个出现的位置。 

## Python 解决方案```python
class Solution:
    def removeDigit(self, number: str, digit: str) -> str:
        last_index = -1

        for i in range(len(number)):
            if number[i] == digit:
                last_index = i

                if i + 1 < len(number) and number[i + 1] > digit:
                    return number[:i] + number[i + 1:]

        return number[:last_index] + number[last_index + 1:]
```该实现首先跟踪最后一次出现的`digit`。 这是必要的，因为如果没有找到贪婪删除条件，我们必须删除最后一个出现的情况。 

在迭代过程中，每次我们遇到`digit`，我们更新`last_index`。 

临界贪心条件为：```python
number[i + 1] > digit
```如果下一个数字更大，我们立即删除当前数字并返回结果。 这种早期返回之所以有效，是因为第一次出现这种情况总是最佳的。 

如果循环完成时没有找到有益的删除点，则算法将使用存储的索引删除最后一个出现的位置。 

字符串切片有效地创建新结果并保持实现简洁。 

## 解决方案```go
func removeDigit(number string, digit byte) string {
    lastIndex := -1

    for i := 0; i < len(number); i++ {
        if number[i] == digit {
            lastIndex = i

            if i+1 < len(number) && number[i+1] > digit {
                return number[:i] + number[i+1:]
            }
        }
    }

    return number[:lastIndex] + number[lastIndex+1:]
}
```Go 实现遵循与 Python 解决方案相同的贪婪逻辑。 

一个重要的区别是 Go 字符串是使用字节进行索引的。 由于输入仅包含 ASCII 数字，因此直接字节索引是完全安全且高效的。 

Go 中的字符串切片与 Python 切片类似，允许我们通过将删除的字符之前的子字符串与其之后的子字符串连接来构造结果。 

不需要整数转换，因为数字字节之间的字符比较保留数字顺序。

 ## 边缘情况

 当目标数字仅出现一次时，就会出现一种重要的边缘情况。 在这种情况下，无需做出任何决定，因为只有一次删除是可能的。 有缺陷的实现可能仍会尝试超出范围的贪婪比较或错误地跟踪多个候选者。 当前的实现自然地处理了这个问题，因为循环存储唯一的出现，如果没有更早的返回发生，则在最后将其删除。 

另一个关键的边缘情况是该数字的所有出现都产生相同的结果。 例如：```
number = "551"
digit = "5"
```删除任一`'5'`产生`"51"`。 一些实现可能不必要地使平局处理过于复杂。 贪婪方法可以正确工作，因为删除最后一次出现的情况仍然会产生最佳结果。 

第三个重要的情况是最好的移除位置靠近琴弦的前部。 较早的位置具有较大的位置价值，因此删除暴露较大后续数字的数字可以显着增加数字。 例如：```
"1231", digit = "1"
```删除第一个`'1'`产生`"231"`，它比`"123"`。 该实现显式检查此条件并在找到后立即返回。 

当相邻数字等于目标数字时，会出现另一种微妙的边缘情况。 例如：```
number = "1111"
digit = "1"
```每次删除都会产生相同的结果。 该算法正确地扫描所有出现的情况，并在发现没有有利位置后删除最后一个。
