[LeetCode 第 2297 题](https://leetcode.com/problems/jump-game-viii/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、堆栈、图论、单调堆栈、最短路径

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算从索引移动所需的最小总成本`0`索引`n - 1`在一个数组中。 移动规则很不寻常，因为跳转是否有效不仅取决于起始索引和目标索引的值，还取决于中间的每个元素。 

我们有两个数组：

 -`nums[i]`描述索引处的值`i`-`costs[i]`描述登陆索引时支付的成本`i`您从索引开始`0`，而且你不付钱`costs[0]`因为你从那里开始。 每次跳转到另一个索引时`j`，你付钱`costs[j]`。 

从索引跳转`i`索引`j`在哪里`i < j`如果满足以下条件之一，则有效：

 1.`nums[i] <= nums[j]`，并且它们之间的每个值都严格小于`nums[i]`2.`nums[i] > nums[j]`，并且它们之间的每个值都大于或等于`nums[i]`面临的挑战是确定达到最终指数的最小可能总着陆成本。 

约束条件很重要：

 -`n`可以大到`100000`- 一个简单的图表结构，检查每一对`(i, j)`需要`O(n^2)`工作
 - 因此我们需要一种接近线性或`O(n log n)`关键的困难是有效地确定哪些跳跃是有效的。 

一些边缘情况很重要：

 - 严格增加数组
 - 严格递减数组
 - 具有重复值的数组
 - 许多索引看起来可达的情况
 - 非常大的输入，二次处理会超时

 该问题保证所有值都非负并且数组具有相等的长度。 

## 方法

 ### 蛮力方法

 最直接的解释是将问题建模为图表。 

每个索引都是一个节点。 对于每对`(i, j)`和`i < j`，我们检查跳转条件是否满足。 如果跳转有效，我们添加一条有向边`i`到`j`有重量`costs[j]`。 

构建图后，我们可以运行最短路径算法，例如 Dijkstra 算法或 DAG 上的动态规划。 

这种方法是正确的，因为它明确地对每个合法的移动进行建模，并通过图表计算最小路径成本。 

问题是验证所有对需要`O(n^2)`检查。 更糟糕的是，每次检查可能会扫描之间的子数组`i`和`j`，产生更大的复杂性。 

和`n = 100000`，这是完全不可行的。 

### 关键见解

 跳转规则实际上描述了可以使用单调堆栈发现的可见性关系。 

对于每个索引，只有某些附近的元素很重要：

 - 下一个大于或等于的元素
 - 下一个较小的元素

 这些是经典的单调堆栈模式。 

关键的观察是，如果跳转跳过另一个候选者，则跳过的候选者会阻止未来的跳转，因为跳转条件要求所有中间元素遵守严格的排序约束。 

这意味着每个索引只需要通过单调堆栈发现的少量相邻索引的边。 

一旦我们有效地识别这些有效的转换，问题就变成了最短路径动态规划问题。 

我们从左到右处理索引并维护：

 - 单调递减堆栈
 - 单调递增堆栈
 - DP 数组，其中`dp[i]`是达到索引的最小成本`i`每个堆栈操作都会创建有效的转换，同时保留跳转条件。

 ## 算法演练

 1.创建DP阵列`dp`长度`n`。`dp[i]`表示达到指标所需的最低成本`i`。 

将每个值初始化为无穷大，除了`dp[0] = 0`因为我们从索引开始`0`无需支付任何费用。 
2. 保持递减的单调堆栈。 

该堆栈存储索引，其`nums`值严格递减。 

处理索引时`i`， 如果`nums[stack[-1]] <= nums[i]`，然后我们可以从该堆栈索引跳转到`i`。 

为什么这有效？ 

因为它们之间的每个元素都小于源值。 否则，堆栈结构可能已经提前删除了源索引。 
3. 对于从递减堆栈中弹出的每个索引，更新：`dp[i] = min(dp[i], dp[popped] + costs[i])`这意味着我们正在考虑从`popped`到`i`。 
4.出栈后，如果栈仍非空，则栈顶元素还可以跳转到`i`。 

这表示满足第二个跳转条件的最接近左侧的较大元素。 
5.推送当前索引`i`到递减堆栈上。 
6. 类似地保持递增的单调堆栈。 

该堆栈存储索引，其`nums`值严格递增。 

尽管`nums[stack[-1]] > nums[i]`、流行指数和尝试转换。 
7. 对于递增堆栈中的每个弹出索引，更新：`dp[i] = min(dp[i], dp[popped] + costs[i])`8. 出栈后，如果栈仍非空，其栈顶也可以过渡到`i`。 
9. 将当前索引压入递增堆栈。 
10. 继续，直到处理完所有索引。 
11. 返回`dp[n - 1]`。 

### 为什么它有效

 单调堆栈保证跳转规则隐含的每个有效转换都被仅考虑一次。 

递减堆栈处理目标大于或等于源值的跳转。 递增的堆栈处理目标较小的跳转。 

堆栈不变量确保自动排除任何被阻止或无效的转换。 由于每个有效边都被处理，并且 DP 递归始终保持可实现的最小成本，因此最终答案是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCost(self, nums: List[int], costs: List[int]) -> int:
        n = len(nums)

        dp = [float("inf")] * n
        dp[0] = 0

        decreasing_stack = []
        increasing_stack = []

        for i in range(n):

            while decreasing_stack and nums[decreasing_stack[-1]] <= nums[i]:
                prev = decreasing_stack.pop()
                dp[i] = min(dp[i], dp[prev] + costs[i])

            if decreasing_stack:
                dp[i] = min(dp[i], dp[decreasing_stack[-1]] + costs[i])

            decreasing_stack.append(i)

            while increasing_stack and nums[increasing_stack[-1]] > nums[i]:
                prev = increasing_stack.pop()
                dp[i] = min(dp[i], dp[prev] + costs[i])

            if increasing_stack:
                dp[i] = min(dp[i], dp[increasing_stack[-1]] + costs[i])

            increasing_stack.append(i)

        return dp[-1]
```实现直接遵循算法。 

这`dp`数组存储到达每个位置的最小成本。 最初，除了索引之外的每个索引都是不可访问的`0`。 

同时维护两个单调堆栈。 

递减堆栈处理目标值大于或等于源值的转换。 While the top element is less than or equal to the current value, it can legally jump to the current index, so we pop it and update the DP state.

 出栈阶段后，剩余的顶部元素是最左边的较大值，这也满足交替跳转条件。 

对于目标值较小的转换，递增堆栈对称地工作。 

每个索引最多从每个堆栈中压入和弹出一次，这保证了线性时间复杂度。 

## 解决方案```go
func minCost(nums []int, costs []int) int64 {
	n := len(nums)

	const INF int64 = 1 << 60

	dp := make([]int64, n)
	for i := range dp {
		dp[i] = INF
	}
	dp[0] = 0

	decreasingStack := []int{}
	increasingStack := []int{}

	for i := 0; i < n; i++ {

		for len(decreasingStack) > 0 &&
			nums[decreasingStack[len(decreasingStack)-1]] <= nums[i] {

			prev := decreasingStack[len(decreasingStack)-1]
			decreasingStack = decreasingStack[:len(decreasingStack)-1]

			if dp[prev]+int64(costs[i]) < dp[i] {
				dp[i] = dp[prev] + int64(costs[i])
			}
		}

		if len(decreasingStack) > 0 {
			prev := decreasingStack[len(decreasingStack)-1]

			if dp[prev]+int64(costs[i]) < dp[i] {
				dp[i] = dp[prev] + int64(costs[i])
			}
		}

		decreasingStack = append(decreasingStack, i)

		for len(increasingStack) > 0 &&
			nums[increasingStack[len(increasingStack)-1]] > nums[i] {

			prev := increasingStack[len(increasingStack)-1]
			increasingStack = increasingStack[:len(increasingStack)-1]

			if dp[prev]+int64(costs[i]) < dp[i] {
				dp[i] = dp[prev] + int64(costs[i])
			}
		}

		if len(increasingStack) > 0 {
			prev := increasingStack[len(increasingStack)-1]

			if dp[prev]+int64(costs[i]) < dp[i] {
				dp[i] = dp[prev] + int64(costs[i])
			}
		}

		increasingStack = append(increasingStack, i)
	}

	return dp[n-1]
}
```Go 解决方案密切反映了 Python 逻辑。 

一个重要的区别是返回类型是`int64`，因此 DP 数组也使用`int64`以避免累积成本时出现溢出问题。 

Go 切片用作堆栈。 弹出是通过重新切片来实现的`stack[:len(stack)-1]`。 

与 Python 不同，Go 不提供整数的无穷大值，因此使用一个非常大的常量来代替。

 ## 边缘情况

 ### 单元素数组

 如果`n = 1`，我们已经从目标索引开始。 不需要跳跃，因此最小成本必须是`0`。 

如果实现假设至少发生一次转换，则很容易处理不当。 DP 初始化正确处理了这个问题，因为`dp[0]`开始于`0`并且循环永远不会改变它。 

### 重复值

 具有重复值的数组很微妙，因为跳转条件同时使用`<`和`<=`。 

例如：```
nums = [2,2,2]
```单调堆栈条件必须小心地保持相等行为。 递减堆栈使用`<=`而增加的堆栈使用`>`以便一致地处理相同的值并且不会丢失有效的转换。 

### 严格单调数组

 严格增加和严格减少阵列对一个堆栈造成很大压力，而另一堆栈则大部分未使用。 

对于递增数组，递减堆栈会重复弹出元素。 对于递减数组，递增堆栈会重复弹出元素。 

有缺陷的实现可能会意外地产生二次行为，但单调堆栈方法保证每个索引仅在每个堆栈中处理一次，从而保留线性复杂性。
