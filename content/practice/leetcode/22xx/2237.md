[LeetCode 问题 2237](https://leetcode.com/problems/count-positions-on-street-with-required-brightness/)

 **难度：** 🟡 中等
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 该问题描述了一条由位置代表的街道`0`到`n - 1`。 有多个路灯，每个路灯都由其位置和范围定义。 位置上有一盏灯`p`有范围`r`照亮所有位置`max(0, p - r)`到`min(n - 1, p + r)`，包含在内。 某个位置的**亮度**是覆盖该位置的灯的数量。 

我们还得到了一个数组`requirement`在哪里`requirement[i]`表示该位置所需的最小亮度`i`。 我们的目标是计算有多少位置达到或超过其亮度要求。 

输入约束告诉我们`n`灯的数量可以多达`10^5`。 迭代每个灯的所有位置的简单解决方案可能是 O(n * m)，这太慢了。 该问题保证位置和范围有效，并且`requirement`数组与街道长度匹配。 

边缘情况包括只有一个位置的街道、零范围的灯、没有被任何灯覆盖的位置以及要求为零的位置。 

## 方法

 **强力方法**将迭代每个灯并增加其覆盖的每个位置的亮度。 然后，针对每个位置，检查亮度是否满足要求。 虽然这是正确的，但效率很低，因为每个灯可能会影响最多`O(n)`位置，导致时间复杂度为 O(n * m)`m`灯，这对于大输入是不可接受的。 

**最佳方法**使用前缀和技术，也称为差异数组方法。 我们不是单独增加每个灯的每个位置，而是增加范围的开始并在范围结束后减少位置。 处理完所有灯后，单遍计算累积和，有效地给出每个位置的亮度。 这将时间复杂度降低到 O(n + m)，适合输入限制。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(n) | 增加每个灯每个位置的亮度 |
 | 最佳| O(n + m) | O(n) | 使用前缀和/差数组高效计算亮度 |

 ## 算法演练

 1.初始化一个数组`brightness`尺寸的`n + 1`全为零。 我们使用`n + 1`简化范围递减操作。 
2. 迭代每个灯`[position, range]`：

 - 将覆盖范围的开始计算为`max(0, position - range)`。 
- 将覆盖范围的结束计算为`min(n - 1, position + range)`。 
- 增量`brightness[start]`1.
 - 递减`brightness[end + 1]`减 1，如果`end + 1 < n`。 
3. 转换`brightness`通过从左到右迭代并保持运行总和，将差异数组转换为实际亮度值。 
4. 计算位置`brightness[i] >= requirement[i]`。 
5. 返回计数。 

**为什么有效：** 使用差异数组可确保我们仅对每个灯执行两次更新，而不是更新每个覆盖位置。 运行总和将差异数组转换为实际亮度，给出覆盖每个位置的灯的正确数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def meetRequirement(self, n: int, lights: List[List[int]], requirement: List[int]) -> int:
        brightness = [0] * (n + 1)
        
        for position, r in lights:
            start = max(0, position - r)
            end = min(n - 1, position + r)
            brightness[start] += 1
            if end + 1 < n:
                brightness[end + 1] -= 1
        
        # Compute prefix sum to get actual brightness
        for i in range(1, n):
            brightness[i] += brightness[i - 1]
        
        count = 0
        for i in range(n):
            if brightness[i] >= requirement[i]:
                count += 1
        
        return count
```该实现首先构建差异数组，然后计算前缀和以获得每个位置的实际亮度。 最后的循环计算满足要求的位置。 

## 解决方案```go
func meetRequirement(n int, lights [][]int, requirement []int) int {
    brightness := make([]int, n+1)

    for _, light := range lights {
        pos, r := light[0], light[1]
        start := pos - r
        if start < 0 {
            start = 0
        }
        end := pos + r
        if end >= n {
            end = n - 1
        }
        brightness[start] += 1
        if end+1 < n {
            brightness[end+1] -= 1
        }
    }

    // Prefix sum to compute actual brightness
    for i := 1; i < n; i++ {
        brightness[i] += brightness[i-1]
    }

    count := 0
    for i := 0; i < n; i++ {
        if brightness[i] >= requirement[i] {
            count++
        }
    }

    return count
}
```在 Go 中，我们使用大小的切片`n + 1`处理差异数组。 边缘情况如`end + 1`数组之外的内容都会被仔细处理，类似于 Python。 

## 工作示例

 **示例1：**`n = 5`,`lights = [[0,1],[2,1],[3,2]]`,`requirement = [0,2,1,4,1]`一步一步：

 1. 初始化`brightness = [0,0,0,0,0,0]`。 
2. 工艺灯`[0,1]`→`start=0`,`end=1`→`brightness = [1,0,-1,0,0,0]`。 
3. 工艺灯`[2,1]`→`start=1`,`end=3`→`brightness = [1,1,-1,-1,-0,0]`。 
4. 工艺灯`[3,2]`→`start=1`,`end=4`→`brightness = [1,2,-1,-1,-1,0]`。 
5. 前缀和 →`brightness = [1,3,2,1,0]`。 
6. 比较`requirement`→ 位置 0,1,2,4 满足要求 → 结果`4`。 

**示例2：**`n = 1`,`lights = [[0,1]]`,`requirement = [2]`1. 初始化`brightness = [0,0]`。 
2. 灯`[0,1]`→`start=0`,`end=0`→`brightness = [1,0]`。 
3. 前缀和 →`brightness = [1]`。 
4. 比较`requirement`→ 1 < 2 → 结果`0`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) | 构建差异数组的一次传递 (O(m))、前缀和的一次传递 (O(n))、计数位置的一次传递 (O(n)) |
 | 空间| O(n) | 大小为 n+1 的差分数组 |

 即使对于最大的约束，该算法也是有效的（`n, m <= 10^5`), as it uses linear time and space.

 ## 边缘情况

 1. **单一位置街道**：街道只有一个位置。 This is tricky because the algorithm must handle arrays of size 1 correctly. Both Python and Go implementations handle this naturally, including the difference array edge.
 2. **Lamp with zero range**: Lamps may illuminate only their own position. This tests whether the algorithm correctly calculates`start = end = position`并正确更新差异数组。 
3. **要求为 0 的位置**：要求为零的位置应始终计数，无论灯的数量有多少。 实现处理这个问题是因为我们直接比较`brightness[i] >= requirement[i]`。
