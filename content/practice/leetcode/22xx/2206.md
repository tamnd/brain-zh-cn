[LeetCode 问题 2206](https://leetcode.com/problems/divide-array-into-equal-pairs/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、位操作、计数

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`确切地包含`2 * n`元素。 我们的任务是确定是否可以将数组拆分为`n`有效对，其中每对包含两个相同的数字。 

简单来说，数组中的每个数字都必须与另一个相同数字的出现相匹配。 由于每个元素只能属于一对，因此每个不同的数字必须出现偶数次。 即使一个值出现奇数次，总会有一个剩余元素无法配对，从而得出答案`false`。 

例如，如果`nums = [3,2,3,2,2,2]`, 数量`3`出现两次并且`2`出现四次。 由于两个频率都是偶数，我们可以形成像这样的对`(3,3)`,`(2,2)`， 和`(2,2)`，所以答案是`true`。 

另一方面，如果`nums = [1,2,3,4]`，每个数字只出现一次。 由于它们都没有匹配的重复项，因此不可能形成等值对，所以答案是`false`。 

这些约束很重要，因为它们决定了哪些类型的解决方案是实用的：

 -`nums.length == 2 * n`，意味着数组长度始终是偶数。 
-`1 <= n <= 500`，所以最大数组大小是`1000`。 
-`1 <= nums[i] <= 500`，意义值相对较小。 

由于数组大小适中且数量有限，因此计算频率是一种非常自然且有效的解决方案。 该问题保证输入长度始终是偶数，因此我们永远不需要处理具有奇数个元素的格式错误的输入。 

一些重要的边缘情况值得尽早认识。 如果一个数字出现奇数次，配对立即变得不可能。 应返回所有值都相同的数组`true`，因为每个元素都可以自然配对。 如果缺少重复项，具有许多唯一数字的数组很快就会失败。 单对输入，例如`[5,5]`，也应该正常工作。 

## 方法

 ### 蛮力方法

 A straightforward brute force strategy is to repeatedly search for a matching partner for each element. We could iterate through the array, pick an unused number, and scan the remaining elements to find an identical unused value. 一旦找到，两个元素都被标记为配对。 

This approach works because it explicitly attempts to build the required equal pairs. If every element finds a partner, the array can be divided successfully. If at any point a number has no matching unused value, the answer is`false`。 

然而，这种方法效率很低，因为对于每个元素，我们可能会扫描剩余数组的大部分来找到一对。 在最坏的情况下，这会导致二次时间复杂度，与基于计数的方法相比，这会变得不必要的慢。 

### 最优方法，频率计数

 关键的观察是，只有当每个不同的数字出现偶数次时，配对才有可能。 

我们可以简单地计算每个数字出现的次数，而不是物理地形成对。 一旦我们知道了频率，我们就检查每个计数是否可以被整除`2`。 如果所有计数都是偶数，则保证有效配对。 如果任何计数为奇数，则配对变得不可能。 

这是有效的，因为配对相同的数字仅取决于数量。 出现一个值`2`,`4`， 或者`6`时间总是可以划分为相同的对。 出现一个值`1`,`3`， 或者`5`时代总是留下一个不匹配的元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复搜索匹配的未使用元素 |
 | 最佳 | O(n) | O(n) | 计算频率并验证所有频率都是偶数 |

 ## 算法演练

 1. 创建一个哈希映射来计算每个数字的出现次数。 

哈希映射是理想的，因为它平均允许恒定时间插入和查找。 键代表数组中的数字，值代表每个数字出现的次数。 
2. 遍历数组一次并更新频率计数。 

对于每个数字`nums`，增加其在哈希图中的计数。 在此过程之后，我们确切地知道每个不同值出现的次数。 
3. 迭代所有频率值。 

检查存储在哈希映射中的每个计数。 
4. 检查各频率是否均匀。 

如果任何频率为奇数，则立即返回`False`因为有一个元素将保持不匹配状态。 
5. 返回`True`如果所有计数都是偶数。 

如果每个数字出现偶数次，则总是可以形成等值对。 

### 为什么它有效

 正确性依赖于一个简单的不变量：一个数字只有出现偶数次才能分成相等的对。 由于元素只能与相同的值配对，因此每个有效的解决方案都需要均匀的频率。 相反，如果每个频率都是偶数，我们总是可以将出现的次数划分为相同数字对。 因此，检查频率奇偶性既是必要的也是充分的。 

## Python 解决方案```python
from typing import List

class Solution:
    def divideArray(self, nums: List[int]) -> bool:
        frequency = {}

        for num in nums:
            frequency[num] = frequency.get(num, 0) + 1

        for count in frequency.values():
            if count % 2 != 0:
                return False

        return True
```实现首先创建一个名为的字典`frequency`存储出现次数。 在第一个循环中，中的每个数字`nums`使用更新其相应的计数`get(num, 0)`安全地处理看不见的值。 

计数完成后，第二个循环将迭代所有存储的频率。 条件`count % 2 != 0`检查计数是否为奇数。 如果存在奇数计数，该函数立即返回`False`因为平等配对变得不可能。 

如果循环结束时没有找到任何奇数频率，则每个值都可以成功配对，因此函数返回`True`。 

## 解决方案```go
func divideArray(nums []int) bool {
	frequency := make(map[int]int)

	for _, num := range nums {
		frequency[num]++
	}

	for _, count := range frequency {
		if count%2 != 0 {
			return false
		}
	}

	return true
}
```Go 的实现与 Python 版本非常相似。 一个`map[int]int`用于存储频率。 Go 映射自动将缺失的整数值初始化为`0`，这使得增量变得简单`frequency[num]++`。 

与 Python 不同，不需要`get()`方法，因为缺少的键默认为零。 整数溢出在这里不是问题，因为最大数组大小仅为`1000`。 空数组也不需要显式处理，因为约束保证至少有两个元素。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 一次通过计算频率，另一次检查计算 |
 | 空间| O(n) | 哈希图存储不同数字的频率 |

 该算法处理数组一次以构建频率图，然后迭代不同的值以验证奇偶性。 由于这两个操作都是线性的，因此总体时间复杂度为`O(n)`。 

空间复杂度为`O(n)`在最坏的情况下，当所有数字都是不同的并且每个数字都需要一个单独的哈希映射条目时。 尽管值之间存在界限`1`和`500`，一般复杂度相对于输入大小保持线性。

 ## 边缘情况

 一个重要的边缘情况是当数组仅包含一对时，例如`[5,5]`。 幼稚的实现可能会使逻辑过于复杂或假设存在多个值。 频率计数方法可以自然地处理这个问题，因为`5`appears exactly twice, which is even.

 另一种关键的边缘情况是当一个数字出现奇数次时，例如`[2,2,2,3,3,3]`。 如果实现尝试在不全局验证计数的情况下贪婪地配对元素，这种情况很容易引入错误。 基于频率的解决方案正确识别了两者`2`和`3`出现三次，无法配对。 

第三种边缘情况涉及所有值都相同的数组，例如`[8,8,8,8,8,8]`。 某些实现可能会意外地采用唯一值，或者当重复出现次数非常高时会失败。 由于该算法仅检查奇偶性，因此它正确地确定了六次出现可以形成三个相等的对。 

最后，具有所有唯一值的数组，例如`[1,2,3,4]`，是另一种常见的故障情况。 由于每个数字都只出现一次，因此无法配对。 该实现可以快速检测奇数频率并返回`False`立即地。
