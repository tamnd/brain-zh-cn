[LeetCode 问题 2233](https://leetcode.com/problems/maximum-product-after-k-increments/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题要求我们在执行最多之后最大化非负整数数组的乘积`k`增量操作，其中每个操作将任何单个元素增加`1`。 换句话说，给定一个数组`nums`和一个整数`k`，我们想要分发这些`k`的元素递增`nums`使得所有元素的乘积尽可能大。 最后，我们返回乘积模`10^9 + 7`因为涉及的数字可能会变得非常大。 

输入`nums`是一个非负整数数组，并且`k`是一个正整数，最多`10^5`。 数组长度也可以达到`10^5`，各个元素可以大到`10^6`。 这表明模拟每个可能增量的强力方法在计算上是不可行的，因为`k`可能非常大，数组最多可达`100,000`元素。 

要考虑的边缘情况包括所有元素均为零的数组、具有非常大元素的数组或以下情况`k`大于均衡所有元素所需的差值。 该问题保证非负整数，因此我们不需要处理负值。 

## 方法

 蛮力方法涉及一次增加一个元素，总是尝试每种可能的选择来增加哪个元素。 在每一步中，我们都会计算乘积并跟踪最大值。 这种方法是正确的，因为最终考虑了所有可能的增量分布，但对于输入限制来说太慢了，因为它需要`O(k * n)`时间。 

最佳方法依赖于一个关键的见解：为了最大化数字的乘积，我们应该始终增加数组中的**最小元素**。 这是因为，考虑到乘法的性质，较小数字增加时的乘积增长速度比较大数字增加时的乘积增长得更快。 使用**最小堆**（优先级队列）使我们能够有效地提取最小元素，增加它，然后重新插入它，重复这个过程`k`次。 这确保了操作在`O(log n)`每次增量的时间，导致`O(k log n)`总体时间来说，在约束条件下是可行的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(k * n) | O(1) | O(1) | 通过每次检查所有元素来增加最小元素 |
 | 最佳| O(k log n) | O(k log n) | O(n) | 使用最小堆高效查找并递增最小元素 |

 ## 算法演练

 1.插入所有元素`nums`进入最小堆。 这使我们能够在每一步快速识别和提取最小的元素。 
2. 重复以下操作`k`次数：

 1. 从堆中取出最小的元素。 
2. 将此元素增加`1`。 
3. 将增加的值推回到堆中。 
3. 执行完所有操作后`k`增量，计算堆中剩余的所有元素的乘积。 
4. 返回乘积的模数`10^9 + 7`以防止溢出。 

为什么有效：通过始终增加最小元素，我们可以最大化产品的增长。 该策略保证产生最大乘积，因为增加较小的数字比增加较大的数字具有更高的乘法影响，这是根据算术几何平均不等式得出的。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def maximumProduct(self, nums: List[int], k: int) -> int:
        MOD = 10**9 + 7
        heapq.heapify(nums)
        
        for _ in range(k):
            smallest = heapq.heappop(nums)
            heapq.heappush(nums, smallest + 1)
        
        result = 1
        for num in nums:
            result = (result * num) % MOD
        
        return result
```代码首先转换`nums`进入最小堆，这样可以有效地检索最小元素。 这`for`循环适用`k`递增，始终到最小元素。 最后，计算数组的乘积`10^9 + 7`处理大量数据。 

## 解决方案```go
package main

import (
    "container/heap"
)

func maximumProduct(nums []int, k int) int {
    const MOD = 1_000_000_007
    
    h := IntHeap(nums)
    heap.Init(&h)
    
    for i := 0; i < k; i++ {
        smallest := heap.Pop(&h).(int)
        heap.Push(&h, smallest+1)
    }
    
    result := 1
    for _, num := range h {
        result = (result * num) % MOD
    }
    
    return result
}

type IntHeap []int

func (h IntHeap) Len() int            { return len(h) }
func (h IntHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h IntHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *IntHeap) Push(x any)         { *h = append(*h, x.(int)) }
func (h *IntHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[0 : n-1]
    return x
}
```Go 特定的差异：堆操作稍微详细一些，需要自定义`IntHeap`实现的类型`heap.Interface`。 与Python类似，溢出是通过模运算来处理的。 这里不需要考虑 Nil 切片，因为输入保证至少有一个元素。

 ## 边缘情况

 1. **单元素数组：** 当`nums`仅包含一个元素，所有`k`增量适用于该元素。 该算法正确地处理了这一问题，因为堆仅包含一个元素，并且直接应用重复增量。 
2. **全零：** 如果所有元素都为零，则重复增量必须一次提高一个元素。 堆确保最小的元素（最初始终为零）首先递增，从而生成正确的最大乘积，而无需除以零或负数。 
3. **大`k`相对于数组大小：** 如果`k`远大于元素的数量，增量可以重复应用于同一元素。 堆确保增量始终针对最小元素，即使在这种极端情况下也能有效地重新分配增量。 
4. **大数字：** 如果`nums`包含非常大的数字，计算乘积可能会溢出
