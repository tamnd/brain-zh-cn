[LeetCode 问题 2225](https://leetcode.com/problems/find-players-with-zero-or-one-losses/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、排序、计数

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个匹配结果列表。 每场比赛都表示为一对：```
[winner, loser]
```这意味着玩家`winner`击败了玩家`loser`。 

我们的目标是返回两个单独的列表：

 1. 所有从未输过比赛的球员。 
2. 所有只输掉一场比赛的球员。 

两个列表必须按升序排序。 

一个重要的细节是我们只考虑至少参加过一场比赛的球员。 从未出现过任何地方的玩家不应包含在答案中。 

限制条件很大：

 - 最多`10^5`比赛
 - 玩家ID也可以达到`10^5`正因为如此，我们需要一个有效的解决方案。 任何重复扫描每个玩家的整个比赛列表的算法都会变得太慢。 

该问题还保证：

 -`winner != loser`- 每场比赛都是独一无二的

 这消除了诸如重复匹配记录或自我匹配等复杂情况。 

一些边缘情况很重要：

 - 玩家只能以胜利者的身份出现，而不能以失败者的身份出现。 
- 一个玩家可能会输多次。 
- 任何玩家都不可能只输一场。 
- 一名球员可能会在比赛中出现多次。 
- 不保证玩家按排序顺序出现。 

正确的解决方案必须正确跟踪所有玩家并准确计算损失。 

## 方法

 ### 蛮力方法

 暴力解决方案将首先收集所有独特的玩家。 然后，对于每个玩家，我们可以扫描整个比赛数组并计算该玩家作为失败者出现的次数。 

如果损失计数为：

 -`0`, 将播放器添加到第一个列表
 -`1`, 将玩家添加到第二个列表中

 这是有效的，因为我们明确计算了每个玩家损失的确切数量。 

然而，这种方法效率低下。 假设有`n`匹配和`p`玩家。 对于每个玩家，我们扫描所有比赛，得出大约：```
O(p * n)
```在最坏的情况下，两个值都可能接近`10^5`，使得解决方案太慢。 

### 最佳方法

 关键的观察是我们只关心每个玩家的损失数量。 

我们可以只处理一次每个匹配并维护一个哈希图，而不是重复扫描匹配：```
loss_count[player] = number of losses
```对于每场比赛：```
[winner, loser]
```我们：

 - 确保获胜者存在于地图中
 - 增加失败者的损失计数

 处理完所有匹配后，我们只需迭代地图即可：

 - 玩家有`0`损失进入第一个结果列表
 - 玩家有`1`损失进入第二个结果列表

 最后，我们对两个列表进行排序。 

这是高效的，因为每个匹配都被处理一次，并且哈希映射操作大约是`O(1)`。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(p × n) | O(p) | 重复扫描每位玩家的所有比赛 |
 | 最佳| O(n + p log p) | O(n + p log p) | O(p) | 一次计算损失，然后对结果进行排序 |

 在哪里：

-`n`= 匹配数
 -`p`= 独特玩家数量

 ## 算法演练

 ### 第 1 步：创建丢失计数的哈希图

 我们使用哈希映射，其中：```
key = player ID
value = number of losses
```这允许恒定的时间更新和查找。 

### 步骤 2：处理每场比赛一次

 对于每场比赛：```
[winner, loser]
```我们执行两个操作：

 1. 确保获胜者存在于地图中。 

如果获胜者以前从未输过，那么他们可能还不存在于地图中。 我们用以下方法初始化它们`0`。 
2. 增加失败者的损失计数。 

由于失败者输掉了这场比赛，我们将他们的计数增加一。 

### 第 3 步：构建结果列表

 处理完所有比赛后，哈希图包含每个玩家及其总损失。 

我们迭代地图：

 - 如果损失== 0，则追加到`zero_losses`- 如果损失 == 1，则追加到`one_loss`输掉一场以上的玩家将被忽略。 

### 步骤 4：对两个列表进行排序

 该问题需要增加顺序，因此我们在返回结果列表之前对它们进行排序。 

###第五步：返回最终答案

 返回：```
[zero_losses, one_loss]
```### 为什么它有效

 该算法保持了不变性，即在处理每场比赛后，哈希图存储迄今为止看到的每个玩家的确切损失数。 

由于每场比赛都会为一名球员带来一场损失，因此每场比赛增加一次失败者的计数可以保证准确的总数。 

任何比赛中出现的每位玩家都会被添加到地图中，无论是获胜者还是失败者，确保不会错过任何有效玩家。 

最后，根据玩家的确切损失数对他们进行分类，即可得出所需的答案。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def findWinners(self, matches: List[List[int]]) -> List[List[int]]:
        loss_count = defaultdict(int)

        for winner, loser in matches:
            # Ensure winner exists in the map
            if winner not in loss_count:
                loss_count[winner] = 0

            # Increment loser loss count
            loss_count[loser] += 1

        zero_losses = []
        one_loss = []

        for player, losses in loss_count.items():
            if losses == 0:
                zero_losses.append(player)
            elif losses == 1:
                one_loss.append(player)

        zero_losses.sort()
        one_loss.sort()

        return [zero_losses, one_loss]
```实施首先创建一个`defaultdict(int)`被称为`loss_count`。 这会自动初始化丢失的条目`0`。 

我们对每场比赛都迭代一次。 对于每场比赛，我们首先确保获胜者存在于地图中。 这是必要的，因为从未失败过的胜利者永远不会出现在字典中。 

接下来，我们增加失败者的损失计数。 

处理完所有比赛后，字典将包含每位参加比赛的球员的总损失。 

然后，我们迭代字典条目并将玩家分成两个列表：

 -`zero_losses`-`one_loss`最后，对两个列表进行排序，因为问题需要增加顺序。 

该解决方案简洁高效，同时直接匹配前面描述的算法。 

## 解决方案```go
package main

import "sort"

func findWinners(matches [][]int) [][]int {
	lossCount := make(map[int]int)

	for _, match := range matches {
		winner := match[0]
		loser := match[1]

		// Ensure winner exists in the map
		if _, exists := lossCount[winner]; !exists {
			lossCount[winner] = 0
		}

		// Increment loser loss count
		lossCount[loser]++
	}

	zeroLosses := []int{}
	oneLoss := []int{}

	for player, losses := range lossCount {
		if losses == 0 {
			zeroLosses = append(zeroLosses, player)
		} else if losses == 1 {
			oneLoss = append(oneLoss, player)
		}
	}

	sort.Ints(zeroLosses)
	sort.Ints(oneLoss)

	return [][]int{zeroLosses, oneLoss}
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`商店损失计数。 由于 Go 映射会针对丢失的键返回零值，因此自然会增加失败者的计数。 

一个重要的细节是确保获胜者被明确地插入到具有价值的地图中`0`。 否则，在最后的迭代中不会出现从未输过的获胜者。 

切片用于存储结果列表，标准库`sort.Ints`函数按升序对它们进行排序。

 ## 边缘情况

 ### 只赢的玩家

 玩家可能只以胜利者的身份出现，而绝不会以失败者的身份出现。 这很重要，因为此类玩家永远不会获得损失计数增量。 

有缺陷的实现可能会意外地完全忽略这些播放器。 

该解决方案通过将每个获胜者显式插入具有损失计数的哈希映射来处理此问题`0`如果他们还没有出现。 

### 多次失败的玩家

 有些玩家可能会输掉很多场比赛。 该算法必须确保这些玩家被排除在两个结果列表之外，除非他们的总损失完全相等`0`或者`1`。 

该实现正确地处理了这个问题，因为每个损失都会增加计数一次，并且最终的过滤检查是否与`0`或者`1`。 

### 空一败结果

 没有玩家可能只输一次。 

例如：```
[[1,2],[3,2]]
```玩家`2`输了两次，而球员`1`和`3`永远不会失去。 

该实现自然会处理这个问题，因为没有玩家满足`losses == 1`条件，因此第二个列表仍为空。 

### 输入顺序是任意的

 不保证比赛按顺序排列，并且玩家 ID 可以按任何顺序出现。 

假设插入顺序已排序的简单解决方案将会失败。 

该实现在返回结果列表之前显式对它们进行排序，从而保证正确的输出排序，而不管输入顺序如何。
