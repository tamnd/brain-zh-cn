[LeetCode 问题 2204](https://leetcode.com/problems/distance-to-a-cycle-in-undirected-graph/)

 **难度：** 🔴难
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个连通的无向图`n`节点并且准确地`n`边缘。 连通图与`n`节点通常形成一棵树，当它有`n - 1`边缘。 由于该图有一条额外的边，因此它恰好包含一个循环。 

我们的目标是为每个节点计算从该节点到属于循环的任何节点的最小距离。 

该图是无向的，因此每条边都可以在两个方向上遍历。 两个节点之间的距离只是连接它们的路径上的最小边数。 

对于属于循环本身一部分的节点，答案是`0`，因为它们已经在循环中了。 对于环外的节点，我们必须确定它们距离最近的环节点有多少条边。 

约束条件很重要：

 -`n`可以大到`100000`- 图形已连接
 - 恰好有一个周期

 这些约束立即告诉我们，我们需要一个近线性的解决方案。 任何具有二次复杂度的算法都会太慢。 

最重要的结构属性是，不在循环上的每个节点都属于附加到循环上的树。 由于恰好存在一个循环，因此删除该循环将留下几棵以循环节点为根的独立树。 

一些边缘情况很重要：

 - 整个图本身可能只是一个循环，在这种情况下，每个答案都是`0`- 某些节点可能是从环中延伸出来的长链
 - 循环可能很小，例如三角形
 - 图表可能极度倾斜，产生非常深的分支
 - 对于大输入，递归 DFS 可能会溢出堆栈，因此迭代方法更安全

 ## 方法

 ### 蛮力方法

 暴力解决方案首先确定哪些节点属于循环，然后对每个节点执行 BFS 来查找最近的循环节点。 

一种可能的实现是：

 1.检测所有循环节点
 2. 对于每个节点：

 - 运行 BFS
 - 一旦到达循环节点就停止
 - 记录距离

 这是可行的，因为未加权图中的 BFS 总是能找到最短路径。 

然而，这太昂贵了。 从每个节点运行 BFS 的成本`O(n * (n + e))`，这变成`O(n^2)`自从`e = n`。 

和`n = 100000`，这是不可行的。 

### 最佳方法

 关键的见解是，不在循环上的节点的行为就像附加到循环上的树中的叶子一样。 

如果我们反复删除叶子节点，最终只剩下循环节点。 

这类似于拓扑修剪：

 - 有度数的节点`1`不能属于一个循环
 - 去除所有叶子
 - 他们的邻居可能会成为树叶
 - 继续，直到不再有叶子存在

 经过这个过程，剩下的节点就是循环节点。 

一旦我们知道了循环节点，我们就可以同时从所有循环节点开始执行多源 BFS。 

该 BFS 计算线性时间内从每个节点到最近的循环节点的最短距离。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 从每个节点运行 BFS |
 | 最佳 | O(n) | O(n) | 剪叶+多源BFS |

 ## 算法演练

 ### 第 1 步，构建图表

 为图创建邻接表并计算每个节点的度。 

邻接列表允许有效遍历邻居，度数组有助于识别叶子。 

### 步骤 2，找到初始叶子

 任意有度的节点`1`绝对不是循环的一部分。 

将所有此类节点推入队列。 

这些节点形成修剪过程的起始层。 

### 步骤 3，反复修剪叶子

 处理队列：

 1.删除一个叶子节点
 2.将其标记为不属于循环
 3. 降低其所有邻居的度
 4.如果邻居成为学位`1`,将其推入队列

 这个过程将树的外层一层一层剥掉。 

最终，仅保留循环节点，因为循环节点始终至少保持度数`2`在剩余的图表中。 

### 步骤 4，从循环节点初始化 BFS

 修剪完成后：

 - 未移除的节点为循环节点
 - 他们的距离是`0`将所有循环节点推入 BFS 队列。 

### 步骤 5，运行多源 BFS

 同时从所有循环节点开始执行 BFS。 

对于每个弹出的节点：

 1.拜访邻居
 2. 如果邻居尚未分配距离：

 - 设置距离 = 当前距离 + 1
 - 将邻居推入队列

 由于BFS逐级扩展，第一次访问节点时给出的到循环的距离最短。 

### 为什么它有效

 修剪阶段正确识别了循环节点，因为循环之外的任何节点在重复去除外层后最终都会成为叶子。 

循环节点永远不会被删除，因为每个循环节点始终在循环内保留至少两个邻居。 

多源 BFS 是正确的，因为未加权图中的 BFS 计算最短路径距离。 同时从所有循环节点启动 BFS 可以保证每个节点收到到任意循环节点的最小距离。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def distanceToCycle(self, n: int, edges: List[List[int]]) -> List[int]:
        graph = [[] for _ in range(n)]
        degree = [0] * n

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)
            degree[u] += 1
            degree[v] += 1

        queue = deque()

        for node in range(n):
            if degree[node] == 1:
                queue.append(node)

        in_cycle = [True] * n

        while queue:
            node = queue.popleft()
            in_cycle[node] = False

            for neighbor in graph[node]:
                degree[neighbor] -= 1

                if degree[neighbor] == 1:
                    queue.append(neighbor)

        distance = [-1] * n
        queue = deque()

        for node in range(n):
            if in_cycle[node]:
                distance[node] = 0
                queue.append(node)

        while queue:
            node = queue.popleft()

            for neighbor in graph[node]:
                if distance[neighbor] == -1:
                    distance[neighbor] = distance[node] + 1
                    queue.append(neighbor)

        return distance
```实现首先构建邻接表并计算节点度。 

第一个 BFS 风格的过程执行叶子修剪。 每个节点都有度`1`被移除，并且其邻居的度数降低。 在这个过程中幸存下来的节点正是循环节点。 

第二个 BFS 计算最短距离。 由于所有循环节点最初都是按距离插入的`0`，BFS自然地向外逐层扩展，为每个非循环节点分配最小距离。 

使用迭代队列可以避免深度图可能出现的递归深度问题。 

## 解决方案```go
package main

import "container/list"

func distanceToCycle(n int, edges [][]int) []int {
	graph := make([][]int, n)
	degree := make([]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)

		degree[u]++
		degree[v]++
	}

	queue := list.New()

	for i := 0; i < n; i++ {
		if degree[i] == 1 {
			queue.PushBack(i)
		}
	}

	inCycle := make([]bool, n)

	for i := 0; i < n; i++ {
		inCycle[i] = true
	}

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		node := front.Value.(int)
		inCycle[node] = false

		for _, neighbor := range graph[node] {
			degree[neighbor]--

			if degree[neighbor] == 1 {
				queue.PushBack(neighbor)
			}
		}
	}

	distance := make([]int, n)

	for i := 0; i < n; i++ {
		distance[i] = -1
	}

	queue = list.New()

	for i := 0; i < n; i++ {
		if inCycle[i] {
			distance[i] = 0
			queue.PushBack(i)
		}
	}

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		node := front.Value.(int)

		for _, neighbor := range graph[node] {
			if distance[neighbor] == -1 {
				distance[neighbor] = distance[node] + 1
				queue.PushBack(neighbor)
			}
		}
	}

	return distance
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于队列管理。 Go 没有像 Python 那样内置双端队列，所以`container/list`用于 BFS 队列。 

切片用于邻接列表和数组。 由于所有距离都以`n`，整数溢出不是问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每条边和节点都会被处理固定次数 |
 | 空间| O(n) | 邻接表、度数数组、队列和距离数组 |

 该图准确包含`n`边，因此边的数量与节点的数量成线性关系。 

在叶子修剪期间，每个节点最多进入队列一次，并且每条边最多检查两次。 

在 BFS 期间，每个节点和边最多再次处理一次。 

因此，整体复杂度保持线性。

 ## 边缘情况

 当整个图是一个循环时，就会出现一种重要的边缘情况。 在这种情况下，没有节点有度`1`，因此修剪队列开始为空。 该算法正确地将每个节点识别为循环的一部分，并且 BFS 将所有距离初始化为`0`。 

另一个重要的情况是与循环相连的非常深的分支。 当深度接近时，递归 DFS 实现可能会溢出调用堆栈`100000`。 此实现通过使用迭代队列进行修剪和 BFS 完全避免了该问题。 

第三个重要的边缘情况涉及循环放置。 环可以出现在图中的任何位置，并不一定涉及节点`0`。 一些不正确的解决方案意外地假设循环在遍历开始附近开始。 该算法避免了这样的假设，因为它纯粹通过度数减少来识别循环节点。 

当删除一个叶子导致另一个节点成为叶子时，就会出现微妙的边缘情况。 如果算法不动态更新度数并将新形成的叶子入队，则一些非循环节点将错误地保持标记为循环节点。 该实现通过在修剪期间立即减少邻居度来正确处理这个问题。
