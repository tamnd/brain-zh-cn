[LeetCode 问题 2256](https://leetcode.com/problems/minimum-average-difference/)

 **难度：** 🟡 中等
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个`0-indexed`整数数组`nums`，并且对于每个索引`i`，我们必须计算称为“平均差”的东西。 

对于特定的索引`i`，数组分为两部分：

 - 左侧部分包含索引中的元素`0`通过`i`- 右侧部分包含索引中的元素`i + 1`穿过数组的末尾

 然后我们计算：

 1. 左边部分的平均值
 2. 右侧部分的平均值
 3. 这两个平均值之间的绝对差

 所有平均值均使用整数除法，这意味着结果会自动向下舍入。 

目标是返回平均差异最小的索引。 如果多个索引产生相同的最小差异，我们必须返回其中最小的索引。 

输入数组最多可以包含`10^5`元素，每个值也可以大到`10^5`。 这些约束很重要，因为它们立即排除了低效的重复求和方法。 任何重复扫描子数组以查找每个索引的解决方案都会变得太慢。 

另一个重要的细节是零元素的平均值定义为`0`。 这很重要，当`i`是数组中的最后一个索引，因为右侧变为空。 

例如：

 - 如果`i = n - 1`- 左侧包含整个数组
 - 右侧包含零个元素
 - 因此右平均值必须被视为`0`一些边缘情况很重要：

 - 只有一个元素的数组
 - 所有值都相同的数组
 - 最小差异出现多次的数组
 - 需要高效处理的大型阵列
 - 使用整数截断仔细处理除法

 该问题保证：

 - 数组总是至少包含一个元素
 - 所有数字均为非负整数

 这些保证简化了处理，因为我们永远不需要处理负和或空输入数组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立计算每个指标的平均差异。 

对于每个位置`i`：

 1. 计算左子数组的和`nums[0:i+1]`2. 计算右子数组的和`nums[i+1:n]`3. 计算两个平均值
 4. 计算它们的绝对差
 5. 追踪最小差值及对应索引

 这种方法是正确的，因为它直接遵循问题的定义。 

然而，它的效率很低。 重复计算子数组和会导致大量的冗余工作。 对于每个索引，我们可能会再次扫描数组的大部分内容。 

如果数组有`n`要素：

 - 有`n`指数
 - 每个索引可能需要`O(n)`计算总和

 这导致`O(n^2)`时间复杂度，对于`n = 10^5`。 

### 使用前缀和的最佳方法

 关键的观察是我们不需要重复重新计算总和。 

如果我们知道：

 - 数组的总和
 - 迭代时运行的前缀和

 然后我们可以计算：

 - 立即从前缀总和中留下总和
 - 正确求和为`totalSum - leftSum`这完全消除了重复扫描。 

在每个索引处：

 - 左平均值 =`leftSum // leftCount`- 右平均值 =`rightSum // rightCount`- 如果右侧为空，则右平均值为`0`因为每个索引只处理一次，所以解变成线性的。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复重新计算子数组和 |
 | 最佳 | O(n) | O(1) | O(1) | 使用运行前缀和和总和 |

 ## 算法演练

 1. 计算整个数组的总和。 

这允许我们在任何索引处导出右侧总和，而无需重新扫描数组。 
2.初始化变量：

 -`prefixSum = 0`-`minimumDifference = infinity`-`answerIndex = 0`当我们迭代时，前缀和将跟踪左侧的累积和。 
3. 从左到右迭代数组。 

对于每个索引`i`：

- 添加`nums[i]`到`prefixSum`- 使用以下方法计算左侧平均值：`leftAverage = prefixSum // (i + 1)`4. 计算右侧总和。 

因为我们已经知道数组总和：`rightSum = totalSum - prefixSum`5. 计算右侧平均值。 

右侧的元素个数为：`rightCount = n - i - 1`如果`rightCount > 0`：`rightAverage = rightSum // rightCount`否则：`rightAverage = 0`6. 计算绝对差。`difference = abs(leftAverage - rightAverage)`7. 如有必要，更新答案。 

如果当前差异小于迄今为止看到的最佳差异：

 - 更新`minimumDifference`- 存储当前索引

 由于我们只更新严格较小的差异，因此关系会自动保留最小的索引。 
8. 继续，直到处理完所有索引。 
9. 返回存储的答案索引。 

### 为什么它有效

 该算法之所以有效，是因为每个指标都是根据问题定义精确评估的。 

前缀和不变量保证处理索引后`i`,`prefixSum`等于以下元素的总和`0`通过`i`。 由于总和是固定的，减去前缀和总是会产生正确的右侧和。 

因此，每个平均差异都会被正确计算，并且通过跟踪遇到的最小差异，算法最终返回正确的索引。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumAverageDifference(self, nums: List[int]) -> int:
        total_sum = sum(nums)
        prefix_sum = 0

        minimum_difference = float("inf")
        answer_index = 0

        n = len(nums)

        for i in range(n):
            prefix_sum += nums[i]

            left_average = prefix_sum // (i + 1)

            right_count = n - i - 1
            right_sum = total_sum - prefix_sum

            if right_count > 0:
                right_average = right_sum // right_count
            else:
                right_average = 0

            difference = abs(left_average - right_average)

            if difference < minimum_difference:
                minimum_difference = difference
                answer_index = i

        return answer_index
```实现首先计算数组的总和。 这是至关重要的，因为它允许在迭代期间以恒定的时间计算右侧总和。 

变量`prefix_sum`跟踪数组左侧部分的累积和。 当我们迭代每个索引时，当前值将添加到此运行总和中。 

对于每个索引：

 - 左平均值是使用前缀和计算的
 - 正确的总和来自`total_sum - prefix_sum`- 正确的平均值经过仔细计算，并对空白的右侧进行了特殊处理

 然后计算两个平均值之间的绝对差。 

每当发现较小的差异时，算法都会更新最小差异和答案索引。 

由于循环只处理每个元素一次，因此解决方案可以在线性时间内高效运行。 

## 解决方案```go
package main

import "math"

func minimumAverageDifference(nums []int) int {
	n := len(nums)

	totalSum := 0
	for _, num := range nums {
		totalSum += num
	}

	prefixSum := 0
	minDifference := math.MaxInt64
	answerIndex := 0

	for i := 0; i < n; i++ {
		prefixSum += nums[i]

		leftAverage := prefixSum / (i + 1)

		rightCount := n - i - 1
		rightSum := totalSum - prefixSum

		rightAverage := 0
		if rightCount > 0 {
			rightAverage = rightSum / rightCount
		}

		difference := leftAverage - rightAverage
		if difference < 0 {
			difference = -difference
		}

		if difference < minDifference {
			minDifference = difference
			answerIndex = i
		}
	}

	return answerIndex
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但有一些特定于语言的注意事项。 

Go 不像 Python 那样提供内置的整数绝对值函数，因此代码手动将负差转换为正值。 

变量`minDifference`初始化使用`math.MaxInt64`以确保在第一次比较期间任何有效的计算差异都会更小。 

Go 整数除法会自动截断为零，这符合问题对楼层除法的要求，因为所有数字都是非负数。 

该实现还通过仅使用标量变量来避免额外的内存分配。

 ## 边缘情况

 ### 单元素数组

 仅包含一个元素的数组是一种重要的边缘情况，因为右侧立即变空。 

例如：```
[7]
```在索引处`0`：

 - 左平均值是`7`- 右平均值必须被视为`0`一个常见的错误是在计算右侧平均值时尝试除以零。 该实现通过显式检查右侧计数是否为零来避免这种情况。 

### 多个最小差异

 多个指数有可能产生相同的最小平均差异。 

例如：```
[1,1,1,1]
```每个指标都可能产生相同的差值。 

在这种情况下，问题需要返回最小的索引。 该实现通过仅在发现严格较小的差异时更新答案来正确处理此问题。 相等差异不会覆盖较早的索引。 

### 最后索引处理

 处理最终索引时：

 - 左侧包含整个数组
 - 右侧包含零个元素

 这种情况特别容易处理不当，因为右边的分母变为零。 

该实现使用以下方法安全地处理这种情况：```
if right_count > 0:
    right_average = right_sum // right_count
else:
    right_average = 0
```这直接遵循问题定义并防止划分错误。
