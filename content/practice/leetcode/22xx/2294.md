[LeetCode 问题 2294](https://leetcode.com/problems/partition-array-such-that-maximum-difference-is-k/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 我们必须将数组分成一个或多个子序列，使得每个数字都恰好属于一个子序列，并且对于每个子序列，其最大值和最小值之间的差异最多为`k`。 

目标是最小化子序列的数量。 

一个非常重要的细节是子序列不需要保持连续。 由于我们可以自由选择任何元素，同时保留相对顺序，因此元素的实际顺序变得不如它们的值重要。 这一观察结果是最优解决方案的关键。 

对于任意子序列：

 -`max(subsequence) - min(subsequence) <= k`我们希望在尊重此约束的同时将尽可能多的值组合在一起。 

例如：```
nums = [3,6,1,2,5], k = 2
```如果我们对值进行排序：```
[1,2,3,5,6]
```我们可以分组：```
[1,2,3]
[5,6]
```第一组有差异`3 - 1 = 2`，和第二个有区别`6 - 5 = 1`。 

因此答案是`2`。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 值也可以大到`10^5`这立即告诉我们指数或二次划分方法会太慢。 我们需要一些接近的东西`O(n log n)`或更好。 

有几个重要的边缘情况需要记住：

 - 只有一个元素的数组
 -`k = 0`，其中只有相等的值才能属于同一子序列
 - 所有值都已适合一个有效子序列的数组
 - 每个元素必须成为其自己的子序列的数组
 - 重复值
 - 未排序的输入

 该问题保证数组非空，因此我们永远不需要处理空输入。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试探索将数组划分为子序列的所有可能方法。 

对于每个元素，我们可以尝试将其放入每个现有的子序列中，使其保持有效，或者启动一个新的子序列。 我们将递归地探索每种可能的分组并跟踪所使用的最小子序列数。 

这种方法是正确的，因为它详尽地检查了每个有效分区。 

然而，这在计算上是不可行的。 可能的分区数量随着数组的大小呈指数增长。 即使对于中等大小的输入，运行时间也会变得巨大。 

自从`n`可以是`100000`，蛮力是完全不切实际的。 

### 关键见解

 关键的观察是只有子序列内的最小值和最大值才重要。 

如果我们对数组进行排序，那么靠近的值自然属于同一个子序列。 

假设我们已经排序了值：```
a <= b <= c
```如果：```
c - a <= k
```then all three can safely belong to the same subsequence.

 但如果：```
current_value - group_min > k
```那么当前值不能属于当前子序列，我们必须开始一个新的子序列。 

这导致了贪婪策略：

 1. 对数组进行排序。 
2. 从剩余最小数开始一个子序列。 
3. 继续添加数字，同时与子序列最小值的差值保持在`k`。 
4. 一旦差异超过`k`，开始一个新的子序列。 

这是有效的，因为排序确保贪婪地扩展当前组始终是最佳的。

 ## 算法演练

 1. 对数组进行非降序排序。 

排序使我们能够按从小到大的顺序处理值。 排序后，每个有效子序列都对应于按排序顺序的连续范围。 
2. 初始化子序列计数。 

我们从一个子序列开始，因为第一个元素必须属于某个地方。 
3. 跟踪当前子序列的最小值。 

让`group_start`表示当前子序列中的最小值。 
4. 迭代已排序的数组。 

对于每个数字：

 - 如果：```
current_number - group_start <= k
```那么该数字可以安全地属于当前子序列。 
- 否则，当前数字无法放入现有子序列中，因此我们：

 - 开始一个新的子序列
 - 增加答案
 - 设置`group_start`到当前号码
 5. 返回形成的子序列的总数。 

### 为什么它有效

 排序后，子序列的最小值和最大值之间的所有数字都会自然地分组在一起。 

贪心策略总是在开始新子序列之前最大化当前子序列的大小。 提前开始一个新的子序列只会增加组的数量，而不会带来任何好处。 

因此，贪婪划分产生尽可能少的子序列。 

## Python 解决方案```python
from typing import List

class Solution:
    def partitionArray(self, nums: List[int], k: int) -> int:
        nums.sort()

        subsequences = 1
        group_start = nums[0]

        for num in nums:
            if num - group_start > k:
                subsequences += 1
                group_start = num

        return subsequences
```实现首先对数组进行排序。 这是最重要的一步，因为它将问题转化为将附近的值分组在一起。 

我们初始化`subsequences`到`1`因为非空数组至少需要一个子序列。 

变量`group_start`存储当前子序列的最小值。 由于数组已排序，因此除非我们开始一个新的子序列，否则该值永远不会改变。 

当我们迭代排序后的数字时，我们检查当前数字是否仍然适合当前子序列：```python
num - group_start <= k
```如果条件失败，我们必须创建一个新的子序列。 我们增加答案并重置`group_start`。 

在最后，`subsequences`包含最小数量的有效子序列。 

## 解决方案```go
package main

import "sort"

func partitionArray(nums []int, k int) int {
	sort.Ints(nums)

	subsequences := 1
	groupStart := nums[0]

	for _, num := range nums {
		if num-groupStart > k {
			subsequences++
			groupStart = num
		}
	}

	return subsequences
}
```Go 实现遵循与 Python 版本完全相同的贪婪逻辑。 

主要区别在于使用：```go
sort.Ints(nums)
```将切片排序到位。 

Go 切片的行为与动态数组类似，因此这里的内存管理不需要特殊处理。 

整数溢出不是问题，因为值仅限于`10^5`。

 ## 边缘情况

 ### 单元素数组

 如果数组只包含一个数字，则答案必须始终是`1`因为单个值自动满足：```
max - min = 0
```粗心的实现可能会错误地初始化答案`0`，但该解决方案正确地从一个子序列开始。 

###`k = 0`什么时候`k`is zero, every subsequence must contain only identical values.

 例如：```
[2,2,4,5]
```必须成为：```
[2,2], [4], [5]
```该实现自然地处理这个问题，因为任何大于零的差异都会强制产生一个新的子序列。 

### 整个数组适合一个子序列

 如果：```
max(nums) - min(nums) <= k
```那么整个数组属于一个子序列。 

例如：```
nums = [1,2,3,4]
k = 10
```该算法永远不会触发开始新组的条件，因此答案仍然正确`1`。 

### 每个元素都需要它自己的子序列

 如果相邻排序值相差超过`k`，每个元素都必须成为其自己的子序列。 

例如：```
nums = [1,4,7,10]
k = 2
```每次迭代都会触发新子序列的创建。 

每次超出允许的范围时，实现都会正确地递增计数器。
