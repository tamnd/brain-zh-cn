[LeetCode 问题 2260](https://leetcode.com/problems/minimum-consecutive-cards-to-pick-up/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、滑动窗口

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`cards`，其中每个数字代表卡片上写的值。 如果两张牌包含相同的值，则认为它们是匹配的。 

我们必须找到需要挑选的连续卡片的最小数量，以便所选组中至少包含一对匹配的卡片。 换句话说，我们正在寻找包含两个相等值的最短连续子数组。 

假设相同的值出现在索引处`i`和`j`， 在哪里`i < j`。 然后是连续的段`i`到`j`包含两张卡，其长度为：$j-i+1$因此，我们的任务相当于找到两个相等值之间的最小距离，测量为`j - i + 1`。 

约束条件很重要：

 - 数组长度可以大到`10^5`- 卡面值可高达`10^6`由于输入可能非常大，任何慢于线性或接近线性时间的算法都可能太慢。 特别是，一个`O(n^2)`对于大小的数组，解决方案无法很好地扩展`100000`。 

一些边缘情况很重要：

 - 应该返回没有重复值的数组`-1`- 重复卡相邻的数组应该返回`2`- 包含许多重复值的数组要求我们正确跟踪最接近的出现次数
 - 长度数组`1`永远不能包含一对

 该问题保证有效的整数输入和非空数组。 

## 方法

 ### 蛮力方法

 一种简单的方法是检查每个可能的子数组并检查它是否包含重复值。 

对于每个起始索引，我们可以一次扩展子数组一个元素，同时跟踪该子数组中已经看到的值。 当我们遇到重复项时，我们计算子数组长度并更新答案。 

这是有效的，因为每个可能的连续段都会被检查，因此最终会找到最小的有效段。 

然而，这种方法太慢了。 有`O(n^2)`可能的子阵列，即使进行了优化，重复扫描范围也会变得昂贵`n = 100000`。 

### 关键见解

 重要的观察是我们实际上不需要检查所有子数组。 

如果索引处出现两张相同的牌`i`和`j`，那么包含两者的最小连续段正是它们之间的范围。 

因此，我们不需要检查每个子数组，而只需跟踪每个卡值之前出现的位置。 

当我们遍历数组时：

 - 如果我们第一次看到一个值，我们记录它的索引
 - 如果我们再次看到该值，我们会计算当前索引与前一个索引之间的距离
 - 我们保持最小距离

 哈希映射在这里是理想的，因为它允许恒定时间查找最近出现的值。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 显式检查许多子数组 |
 | 最佳 | O(n) | O(n) | 使用哈希映射来跟踪先前的索引 |

 ## 算法演练

 1. 初始化一个名为的哈希图`last_seen`。 

该映射存储每个卡值出现的最新索引。 键是卡的值，值是其最新的索引。 
2. 初始化变量`minimum_length`与无穷大。 

该变量跟踪迄今为止找到的最小有效子数组长度。 
3. 使用索引迭代数组`i`和价值`card`。 

在每一步中，我们都会处理当前的卡值。 
4. 检查当前卡值是否已经存在于哈希图中。 

如果是，那么我们就找到了匹配对。 
5. 计算子数组长度。 

如果上一次出现在索引处`previous_index`，则连续段长度为：$i-previous\_index+1$1.更新最低答案。 

将新计算的长度与当前最佳答案进行比较，并保留较小的值。 
2. 更新哈希图。 

将当前索引存储为该卡值最近出现的位置。 
3.处理完所有元素后，返回结果。 

- 如果没有发现重复项，则返回`-1`- 否则，返回最小长度

 ### 为什么它有效

 该算法之所以有效，是因为任何有效答案都必须以两张相同的牌值开始和结束。 对于每个重复值，包含该对的最小可能子数组是连续出现之间的范围。 

通过始终存储每个值的最新出现，我们保证所考虑的每个候选段都是该重复值的最短可能值。 因此，在所有重复值中取最小值会产生全局最优答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumCardPickup(self, cards: List[int]) -> int:
        last_seen = {}
        minimum_length = float("inf")

        for index, card in enumerate(cards):
            if card in last_seen:
                current_length = index - last_seen[card] + 1
                minimum_length = min(minimum_length, current_length)

            last_seen[card] = index

        return minimum_length if minimum_length != float("inf") else -1
```实现首先创建一个名为的字典`last_seen`。 该字典将每个卡值映射到它出现的最新索引。 

变量`minimum_length`被初始化为无穷大，以便以后找到的任何有效子数组长度都将替换它。 

该循环使用以下方式迭代数组`enumerate`，给出当前索引和卡值。 

每当当前卡之前出现过时，代码就会计算当前索引与上一次出现之间的距离。 添加`1`将索引差转换为实际的子数组长度。 

答案已更新使用`min`，确保我们始终保留迄今为止找到的最小有效段。 

最后，当前索引存储在字典中，以便将来的重复项可以将其用作最新出现的索引。 

最后：

 - 如果没有发现重复项，`minimum_length`保持无穷大，因此函数返回`-1`- 否则，返回最小有效长度

 ## 解决方案```go
import "math"

func minimumCardPickup(cards []int) int {
    lastSeen := make(map[int]int)
    minimumLength := math.MaxInt32

    for index, card := range cards {
        if previousIndex, exists := lastSeen[card]; exists {
            currentLength := index - previousIndex + 1

            if currentLength < minimumLength {
                minimumLength = currentLength
            }
        }

        lastSeen[card] = index
    }

    if minimumLength == math.MaxInt32 {
        return -1
    }

    return minimumLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`用于存储每个卡值的最新索引。 变量`minimumLength`初始化为`math.MaxInt32`作为无穷大的替代。 

Go 映射在查找期间返回两个值：```go
value, exists := map[key]
```布尔值`exists`指示密钥是否已经存在。 

与 Python 不同，Go 没有内置的整数无穷大值，因此使用非常大的整数常量。 

该算法的其他行为与 Python 解决方案相同。

 ## 边缘情况

 一种重要的边缘情况是没有重复值的数组。 粗心的实现可能会返回未初始化的值或非常大的数字，而不是返回`-1`。 此实现通过将答案初始化为无穷大并在返回之前显式检查它是否更改来避免该问题。 

另一个重要的边缘情况是当重复的卡片相邻时，例如`[5,5]`。 最短的有效答案是`2`，因为两张连续的相同牌已经形成了匹配对。 该算法正确计算：$1-0+1=2$当一个值多次出现时，就会出现第三种重要的边缘情况，例如`[1,2,1,2,1]`。 有缺陷的实现可能只比较第一次和最后一次出现的情况，从而产生比必要的更大的答案。 此实现不断更新哈希图中的最新出现，确保始终考虑连续重复项之间的最短距离。 

最后的边缘情况涉及接近约束极限的非常大的输入。 由于该算法仅处理每个元素一次并使用恒定时间哈希映射操作，因此即使对于具有`100000`元素。
