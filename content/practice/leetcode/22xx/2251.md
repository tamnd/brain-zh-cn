[LeetCode 第 2251 题](https://leetcode.com/problems/number-of-flowers-in-full-bloom/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、二分查找、排序、前缀和、有序集

 ## 解决方案

 ## 问题理解

 该问题要求我们确定，对于在特定时间到达的人员列表，在他们到达时有多少朵花正在盛开。 每朵花都有一个开始和结束时间，代表它盛开的时间，包括两个端点。 输入由二维数组组成`flowers`， 在哪里`flowers[i] = [starti, endi]`，和一个数组`people`指示每个人的到达时间。 输出是一个数组`answer`， 在哪里`answer[i]`是此时盛开的花朵数量`people[i]`到达。 

约束表明最多可以有`50,000`鲜花和`50,000`人，时间可以到`10^9`。 这告诉我们，检查每个人的每朵花的简单方法会太慢，因为它需要最多`2.5 * 10^9`最坏情况下的比较。 边缘情况包括多朵花同时开始和结束、人们在任何花开花之前到达以及人们恰好在花的开始或结束时间到达。 

该问题保证开始和结束时间有效（`starti <= endi`）并且两个数组都非空。 

## 方法

 **暴力方法**很简单：对于每个人，迭代所有花并检查该人的到达时间是否在花的绽放间隔内。 虽然这工作正常，但它的时间复杂度为`O(n * m)`， 在哪里`n`是人数，并且`m`是花的数量。 考虑到限制，这种方法太慢了。 

**最佳方法**依赖于这样的观察：如果我们将花的开始时间和结束时间分成两个排序数组，我们就可以确定任意时间盛开的花的数量`t`通过计算已经开始的花朵数量`t`并减去之前已经结束的数字`t`。 这将问题简化为排序和使用二分搜索，这对于大型输入非常有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(1) | O(1) | 检查每个人的每朵花 |
 | 最佳| O(n log n + m log m) | O(n log n + m log m) | O(n + m) | 对开始和结束时间进行排序，每人使用二分搜索 |

 ## 算法演练

 1. 提取所有开始时间和所有结束时间`flowers`分成单独的数组`starts`和`ends`。 
2. 对两者进行排序`starts`和`ends`数组按升序排列。 这使我们能够稍后执行有效的二分搜索。 
3.初始化一个空数组`answer`存储每个人的结果。 
4. 每个人的到达时间`p`在`people`：

 1. 使用二分查找（`bisect_right`) 查找开始时间小于或等于的花数`p`。 这给出了已经开始绽放的花朵的数量`p`。 
2. 使用二分查找（`bisect_right`) 找出结束时间小于的花的数量`p`。 这给出了之前已经结束的花的数量`p`。 
3. 从第一个计数中减去第二个计数，即可得到当时盛开的花朵数`p`。 
4. 将此值附加到`answer`。 
5. 返回`answer`大批。 

**为什么它有效：** 这里的不变性是在任何时候`p`，盛开的花朵数量等于开始绽放的花朵数量`p`减去之前已经结束的`p`。 排序使我们能够通过二分搜索有效地对这些进行计数。 

## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def fullBloomFlowers(self, flowers: List[List[int]], people: List[int]) -> List[int]:
        starts = sorted(f[0] for f in flowers)
        ends = sorted(f[1] for f in flowers)
        answer = []
        
        for p in people:
            started = bisect_right(starts, p)
            ended = bisect_right(ends, p - 1)
            answer.append(started - ended)
        
        return answer
```该解决方案首先对开始时间和结束时间进行排序。 对于每个人的到来，`bisect_right`用于查找在该时间之前开始绽放的花朵数量以及在该时间之前结束的花朵数量。 差异将附加到结果数组中。 

## 解决方案```go
import (
    "sort"
)

func fullBloomFlowers(flowers [][]int, people []int) []int {
    n := len(flowers)
    starts := make([]int, n)
    ends := make([]int, n)
    for i, f := range flowers {
        starts[i] = f[0]
        ends[i] = f[1]
    }
    sort.Ints(starts)
    sort.Ints(ends)

    answer := make([]int, len(people))
    for i, p := range people {
        started := sort.SearchInts(starts, p+1)
        ended := sort.SearchInts(ends, p)
        answer[i] = started - ended
    }
    return answer
}
```在围棋中，`sort.SearchInts`被用来代替`bisect_right`。`SearchInts(arr, x)`返回索引，其中`x`将被插入以保留`arr`排序，对应元素个数≤`x-1`取决于我们如何调整`x`。 我们处理与Python相同的计算逻辑。

 ## 边缘情况

 首先，一个人**在任何花朵盛开之前**到达。 该算法正确地计算了零开始的花朵和零结束的花朵，从而导致零开花。 

其次，一个人**恰好在花的开始或结束时间**到达。 由于开始是包含在内的，因此二分搜索将这朵花算作开始。 结束时间处理为`< p`，所以结束于`p`不会减少计数，从而保留了包容性。 

第三，**多朵花同时开始和结束**。 排序可确保二分查找对所有花进行一致计数，即使它们的间隔完全重叠，因此重复项不会导致相差一错误。 

由于仔细使用包含/排除比较与排序的二进制搜索相结合，该算法正确地处理了所有这些边缘情况。
