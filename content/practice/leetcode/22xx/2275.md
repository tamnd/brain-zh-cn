[LeetCode 问题 2275](https://leetcode.com/problems/largest-combination-with-bitwise-and-greater-than-zero/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、位操作、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们从数组中找到最大可能的数字组`candidates`数组，使得该组中每个数字的按位与大于`0`。 

按位 AND 运算仅保留设置为的位`1`在每一个参与的号码中。 例如：```
6  = 110
14 = 1110
10 = 1010
--------------
AND = 0010 = 2
```结果大于零，因为在组合所有数字后至少有一位位置保持不变。 

这个观察是问题的核心。 对于 AND 大于的数字组合`0`，必须存在至少一个位位置，其中该组合中的每个数字都有一个`1`。 

输入是一个正整数数组，称为`candidates`。 我们可以选择这些数字的任何子集，只要该子集非空。 在所有这些 AND 结果为正的子集中，我们必须返回最大可能的子集大小。 

约束条件很重要：

 -`1 <= candidates.length <= 10^5`-`1 <= candidates[i] <= 10^7`该数组最多可以包含十万个数字，这立即排除了任何指数子集枚举方法。 另外，数字最多为`10^7`，它适合 24 位，因为：```
2^24 = 16,777,216
```这意味着我们只需要检查少量固定数量的位位置。 

一些边缘情况很重要：

 - 应该返回只有一个元素的数组`1`，因为任何正数与其自身进行“与”运算后仍为正数。 
- 每个数字共享一个公共位的数组应返回完整的数组大小。 
- 没有两个数字共享任何公共设置位的数组应该返回`1`。 
- 重复值必须独立计数，因为组合基于索引，而不是唯一值。 

## 方法

 ### 蛮力方法

 强力解决方案将生成数组的每个可能的子集，计算该子集的按位 AND，并跟踪 AND 大于零的最大子集。 

这种方法是正确的，因为它明确地检查所有可能的组合。 然而，数组的子集数`n`元素是：```
2^n
```和`n = 100000`，这变得完全不可行。 

即使对于小得多的值，重复计算所有子集的 AND 值也会非常昂贵。 

### 关键见解

 关键的观察结果是，当且仅当组合的每个数字中至少存在一个设置的位位置时，按位 AND 才大于零。 

假设我们关注单个位位置，例如 bit`k`。 

If a number has bit`k`设置，然后它可以参与一个有效的组合，其 AND 保留位`k`。 

因此，位的最大有效组合`k`只是设置了该位的数字的计数。 

我们可以对每个位位置重复此操作并获取最大计数。 

由于每个数最多是`10^7`，我们只需要检查大约24位。 这将问题从指数复杂性转变为简单的计数问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × n) | O(2^n × n) | O(1) | O(1) | 枚举每个子集并计算 AND |
 | 最佳| O(n × 24) | O(1) | O(1) | 计算每个位包含多少个数字 |

 ## 算法演练

 1. 初始化变量`max_size`存储迄今为止找到的最大有效组合。 
2. 迭代每个可能的位位置`0`到`23`。 我们使用 24 因为`10^7`适合 24 位以内。 
3. 对于每个位位置，初始化一个名为`count`。 
4.遍历整个`candidates`大批。 
5. 对于每个数字，检查当前位是否已设置：```
number & (1 << bit)
```如果结果非零，则递增`count`。 
6. After processing all numbers for the current bit,`count`代表有多少个数字共享该位。 
7. Since every one of those numbers contains the same set bit, their collective AND will keep that bit and therefore remain greater than zero.
 8. 更新`max_size`其当前值的最大值和`count`。 
9. 检查完所有位位置后，返回`max_size`。 

### 为什么它有效

 当对所有数字进行“与”运算后至少有一个位位置保持置位时，组合的按位与大于零。 只有当组合中的每个数字都设置了该位时才会发生这种情况。 

因此，对于每个位位置，最大的有效组合是包含该位的所有数字的集合。 取所有位位置的最大值保证了最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestCombination(self, candidates: List[int]) -> int:
        max_size = 0

        for bit in range(24):
            count = 0

            for number in candidates:
                if number & (1 << bit):
                    count += 1

            max_size = max(max_size, count)

        return max_size
```The implementation directly follows the counting strategy described earlier.

 The outer loop iterates through all relevant bit positions. 由于最大可能值为`10^7`，检查 24 位就足够了。 

在内部循环中，我们使用位掩码测试每个数字中是否存在当前位。 表达式：```python
number & (1 << bit)
```创建一个仅设置一位的掩码，并检查该位是否存在于`number`。 

如果该位被设置，我们将递增计数器，因为该数字可以参与在 AND 运算后保留该位的组合。 

在处理特定位的所有数字后，我们更新全局最大值。 

由于位数是固定的且很小，因此即使对于最大允许的输入大小，该算法也能高效运行。 

## 解决方案```go
func largestCombination(candidates []int) int {
    maxSize := 0

    for bit := 0; bit < 24; bit++ {
        count := 0

        for _, number := range candidates {
            if number&(1<<bit) != 0 {
                count++
            }
        }

        if count > maxSize {
            maxSize = count
        }
    }

    return maxSize
}
```Go 的实现非常接近地反映了 Python 的逻辑。 

Go 使用显式整数运算并且不需要类型提示。 基于范围的循环用于有效地迭代切片。 

不存在溢出问题，因为所有值都适合 Go 的标准整数范围。 

该解决方案使用恒定的额外空间并且仅执行简单的位操作。

 ## 边缘情况

 当数组仅包含一个数字时，会出现一种重要的边缘情况。 由于输入中的每个数字都保证为正数，因此单元素组合的 AND 始终大于零。 该实现自然会处理这个问题，因为数字中的至少一位将被计数一次。 

另一个重要的情况是没有两个数字共享任何设置位。 例如：```
[1,2,4,8]
```每个数字都有唯一的位模式，因此任何组合都不会大于大小`1`可以保持正与结果。 算法正确返回`1`因为每一位计数恰好等于一。 

第三种边缘情况涉及重复的数字。 例如：```
[8,8,8,8]
```所有数字共享相同的设置位，因此最大的有效组合包括每个元素。 由于该算法计算出现次数而不是不同值，因此可以正确处理重复项。 

最后的微妙边缘情况涉及接近上限的大位位置。 数字接近`10^7`可以使用超出通常小示例的更高位。 该实现安全地检查所有 24 个相关位位置，确保不会遗漏任何有效组合。
