## 问题理解

 该问题要求我们设计一个类来模拟视频共享平台。 每个视频都表示为一串数字，其中每个数字对应于特定分钟的内容。 该平台需要跟踪每个视频的**观看次数、喜欢和不喜欢**。 用户可以**上传、删除、观看、喜欢、不喜欢**以及查询视频的统计信息。 

关于平台的几个要点：

 - **视频ID：**上传时，平台分配**最小的可用整数`videoId`从0**开始。 删除的视频 ID 可以重新使用。 
- **观看视频：** 返回来自的子字符串`startMinute`到`endMinute`，包含在内。 如果`endMinute`超过视频长度，上限为`video.length - 1`。 
- **喜欢和不喜欢：** 每个操作仅影响视频（如果存在）； 否则，查询返回`-1`或者`[-1]`。 
- **限制：** 每个视频最多可以`10^5`个字符，所有上传的总长度≤`10^5`，且运算次数≤`10^5`。 这确保我们的解决方案必须**高效**，特别是对于查找最小的可用视频 ID 等操作。 

需要考虑的边缘情况包括：

 - 删除不存在的视频或与不存在的视频进行交互。 
- 观看与`endMinute`大于视频长度。 
- 删除后上传（重复使用ID）。 
- 启动时系统为空。 

## 方法

 ### 蛮力

 一种简单的方法是使用视频的**列表**，将每个视频存储在等于视频 ID 的索引处。 上传视频将附加到列表中。 要重用 ID，我们需要**扫描第一个空槽**。 每次删除都会简单地将插槽设置​​为`None`。 观看次数、喜欢和不喜欢可以与视频字符串一起存储在元组或字典中。 

这是可行的，但由于扫描空 ID，在最坏的情况下上传速度为 **O(n)**，这对于`10^5`运营。 

### 最佳方法

 关键的见解是我们需要**快速访问最小的可用 videoId**。 使用**最小堆**（优先级队列）允许我们存储可用的 ID 并在 **O(log n)** 时间内检索最小的 ID。 同时，我们维护一个**哈希映射**（Python 中的字典，Go 中的映射）映射`videoId`视频的数据（内容、观看次数、喜欢、不喜欢）。 

操作：

 - 上传：从最小堆中弹出或使用下一个新ID。 
- 删除：从哈希映射中删除并将 ID 推入最小堆。 
- 观看/喜欢/不喜欢/获取统计数据：直接使用哈希图。 

这种方法确保所有操作都在 **O(log n)** 或 **O(1)** 时间内运行，这对于约束来说是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次上传 O(n) | O(n) | 扫描列表以查找最小的可用 ID |
 | 最佳 | 每次上传 O(log n)，其他操作 O(1) | O(n) | 使用哈希映射 + 最小堆来获得最小的可用 videoId |

 ## 算法演练

 1. 使用以下命令初始化类：

 - **哈希映射**`videos`映射`videoId`→ 视频数据（`video`,`views`,`likes`,`dislikes`）。 
- **最小堆**`available_ids`跟踪可重复使用的视频 ID。 
- 一个柜台`next_id`下一个新的 videoId。 
2. **上传（视频）**：

 - 如果`available_ids`不为空，弹出最小的videoId。 否则，使用`next_id`并增加它。 
- 存储包含视频字符串的字典，`views=0`,`likes=0`,`dislikes=0`在所选视频 ID 下的哈希映射中。 
- 返回视频 ID。 
3. **删除（视频 ID）**：
 - 如果hash映射中存在videoId，则将其删除并将ID压入`available_ids`。 
4. **观看(videoId, startMinute, endMinute)**:

 - 如果 videoId 存在：

 - 增量`views`。 
- 计算`actual_end = min(endMinute, len(video)-1)`。 
- 返回`video[startMinute:actual_end+1]`。 
- 否则，返回“-1”。 
5. **喜欢（videoId）/不喜欢（videoId）**：

 - 如果 videoId 存在，则分别增加喜欢或不喜欢。 否则，什么也不做。 
6. **GetLikesAndDislikes(videoId)**：

 - 返回`[likes, dislikes]`如果视频存在； 否则，`[-1]`。 
7. **GetViews(videoId)**:

 - 返回`views`如果视频存在； 否则，`-1`。 

**为什么有效：**

 哈希映射确保除上传之外的所有操作对视频数据的访问都是**O(1)**。 最小堆保证每个新视频获得**最小的可用ID**，从而有效地处理重用。 这种设计尊重约束并有效支持所需的查询。 

## Python 解决方案```python
from typing import List
import heapq

class VideoSharingPlatform:

    def __init__(self):
        self.videos = {}
        self.available_ids = []
        self.next_id = 0

    def upload(self, video: str) -> int:
        if self.available_ids:
            videoId = heapq.heappop(self.available_ids)
        else:
            videoId = self.next_id
            self.next_id += 1
        self.videos[videoId] = {'video': video, 'views': 0, 'likes': 0, 'dislikes': 0}
        return videoId

    def remove(self, videoId: int) -> None:
        if videoId in self.videos:
            del self.videos[videoId]
            heapq.heappush(self.available_ids, videoId)

    def watch(self, videoId: int, startMinute: int, endMinute: int) -> str:
        if videoId not in self.videos:
            return "-1"
        video_data = self.videos[videoId]
        video_data['views'] += 1
        actual_end = min(endMinute, len(video_data['video']) - 1)
        return video_data['video'][startMinute:actual_end + 1]

    def like(self, videoId: int) -> None:
        if videoId in self.videos:
            self.videos[videoId]['likes'] += 1

    def dislike(self, videoId: int) -> None:
        if videoId in self.videos:
            self.videos[videoId]['dislikes'] += 1

    def getLikesAndDislikes(self, videoId: int) -> List[int]:
        if videoId not in self.videos:
            return [-1]
        v = self.videos[videoId]
        return [v['likes'], v['dislikes']]

    def getViews(self, videoId: int) -> int:
        if videoId not in self.videos:
            return -1
        return self.videos[videoId]['views']
```**解释：**

-`videos`字典存储所有视频元数据。 
-`available_ids`min-heap 允许有效地重用 ID。 
- 每个操作都会在 **O(1)** 时间内修改或查询哈希图，但上传除外，由于堆的原因，上传的时间为 **O(log n)** 。
