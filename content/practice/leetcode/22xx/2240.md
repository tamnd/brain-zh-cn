[LeetCode 第 2240 题](https://leetcode.com/problems/number-of-ways-to-buy-pens-and-pencils/)

 **难度：** 🟡 中等
 **主题：** 数学、枚举

 ## 解决方案

 ## 问题理解

 该问题要求我们确定花费给定金额的不同方式的数量，`total`，钢笔和铅笔，每种都有固定成本，`cost1`用于钢笔和`cost2`用于铅笔。 您可以购买任何非负数的每件商品，包括零，只要总成本不超出您的预算。 

输入是三个正整数：`total`,`cost1`， 和`cost2`。 输出是一个整数，表示可以购买的钢笔和铅笔的独特组合的数量。 

约束条件的主要观察结果是`total`,`cost1`， 和`cost2`最多可以达到 1,000,000，因此任何简单地迭代所有可能组合的解决方案（例如，钢笔和铅笔的双循环）都可能太慢。 重要的边缘情况包括总成本小于两种物品成本的情况，这应该只产生一种有效组合：购买零支钢笔和零支铅笔。 

该问题保证所有输入都是正整数，因此不需要处理零或负成本。 

## 方法

 **暴力方法**迭代您可以购买的所有可能数量的钢笔（从 0 到`total // cost1`）并且对于每个铅笔，迭代可以满足剩余预算的所有可能数量的铅笔。 这种方法保证产生正确的答案，因为它显式枚举了所有有效的组合。 然而，它的效率很低：如果`total`很大并且`cost1`和`cost2`很小，迭代次数可能约为数百万，这对于 LeetCode 约束来说可能太慢。 

**最佳方法**使用数学观察。 对于每种可能的笔数，`p`，您可以购买的最大铅笔数量是`(total - p * cost1) // cost2`。 This means we only need a single loop iterating over possible pen counts, and for each, we compute the pencil count in constant time rather than using a nested loop. 这显着降低了时间复杂度，同时仍然计算所有有效组合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(总计/成本1 * 总计/成本2) | O(1) | O(1) | 双环钢笔和铅笔|
 | 最佳| O(总计/成本1) | O(1) | O(1) | 单圈过笔，直接计算铅笔 |

 ## 算法演练

 1. 初始化变量`ways`为 0，这将存储有效购买组合的总数。 
2. 循环遍历所有可能数量的笔，`num_pens`，从 0 到最大可能值（`total // cost1`）。 这确保我们考虑所有不超出预算的笔数量。 
3. 对于每个`num_pens`，计算买笔后剩余的钱：`remaining = total - num_pens * cost1`。 
4. 计算剩余的钱最多可以购买多少支铅笔：`max_pencils = remaining // cost2`。 
5. 每种组合`num_pens`与 0 到`max_pencils`铅笔是有效的，所以增加`ways`经过`max_pencils + 1`。 
6.循环结束后，返回`ways`。 

**为什么有效：** 该算法枚举所有有效的笔数，并且对于每个笔数，它直接计算有效的笔数范围。 这保证了所有有效组合都被精确地计算一次。 整数除法的使用确保我们永远不会超出预算。 

## Python 解决方案```python
class Solution:
    def waysToBuyPensPencils(self, total: int, cost1: int, cost2: int) -> int:
        ways = 0
        max_pens = total // cost1
        for num_pens in range(max_pens + 1):
            remaining = total - num_pens * cost1
            max_pencils = remaining // cost2
            ways += max_pencils + 1
        return ways
```Python 实现遵循最佳方法。 我们首先确定可以购买的钢笔的最大数量。 对于每支笔的数量，我们计算剩余的钱，然后确定剩余预算中可以容纳多少支铅笔。 添加`max_pencils + 1`考虑了所有可能的铅笔数量，包括零。 

## 解决方案```go
func waysToBuyPensPencils(total int, cost1 int, cost2 int) int64 {
    var ways int64 = 0
    maxPens := total / cost1
    for numPens := 0; numPens <= maxPens; numPens++ {
        remaining := total - numPens*cost1
        maxPencils := remaining / cost2
        ways += int64(maxPencils + 1)
    }
    return ways
}
```在 Go 中，我们使用`int64`因为组合的数量可能超过`int`对于大总数。 该逻辑反映了 Python 解决方案，具有显式类型转换，可对大值进行安全算术。

 ## 边缘情况

 1. **买不起任何物品：** 当两者都`cost1`和`cost2`大于`total`，仅零次购买有效。 对于这种情况，实现正确地加了 1。 
2. **总和可被一个成本整除，但不能被另一个成本整除：** 这测试了正确的整数除法计算以确定每个笔计数的铅笔数量。 该算法使用以下方法计算最大铅笔数`//`正确处理整数除法。 
3. **总量大，成本小：** 迭代次数可能非常大。 使用整数运算可确保不存在浮点精度问题，并且内存使用量保持恒定。 Go 版本明确使用`int64`处理大量组合而不会溢出。
