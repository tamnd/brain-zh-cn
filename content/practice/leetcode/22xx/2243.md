[LeetCode 问题 2243](https://leetcode.com/problems/calculate-digit-sum-of-a-string/)

 **难度：** 🟢简单
 **主题：** 字符串、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们重复变换一个数字字符串，直到它的长度小于或等于给定的整数`k`。 

我们有两个输入：

 -`s`，仅由数字字符组成的字符串 (`'0'`通过`'9'`）
 -`k`，一个整数，决定每轮转换期间使用的组的大小

 该过程重复进行。 在每一轮中，我们将字符串分成连续的大小块`k`。 大多数团体都会有确切的`k`字符，但如果字符串长度不能被整除，那么最终的组可能会更小`k`。 

对于每个组，我们计算其数字的总和，并将该组替换为总和的十进制字符串表示形式。 处理完所有组后，我们将所有结果总和连接成一个新字符串。 如果这个新形成的字符串的长度仍然大于`k`，我们重复这个过程。 

目标是在长度小于或等于时返回最终字符串`k`。 

例如，如果`s = "346"`和`k = 3`，整个字符串形成一组。 数字和为：`3 + 4 + 6 = 13`所以`"346"`变成`"13"`。 

一个重要的细节是数字和可能会产生多位数字。 例如，对数字求和可能会导致`"13"`或者`"27"`，而不仅仅是一个数字。 这意味着最终的字符串长度可能会缓慢收缩，这就是为什么需要重复循环的原因。 

限制非常小：

 -`1 <= s.length <= 100`-`2 <= k <= 100`由于字符串长度最多为`100`，效率不是主要问题。 即使是简单的模拟也足够快。 然而，我们仍然想要一个干净且最佳的实施。 

一些边缘情况很重要：

 - 如果`s.length <= k`最初，不需要回合，我们返回`s`立即地。 
- 最后一组可能包含少于`k`数字，所以我们必须正确处理不完整的组。 
- 数字和可以产生多位数的值，这会影响下一轮的分组。 
- 包含许多零的字符串，例如`"00000000"`，应在结果字符串中保留前导零，因为每个组和在串联之前都是独立转换的。 

## 方法

 ### 蛮力方法

 蛮力解决方案直接模拟问题陈述。 

在每一轮中，我们以大小块的形式迭代字符串`k`。 对于每个块，我们通过迭代每个字符并将其转换为整数来计算其数字之和。 然后，我们将总和转换回字符串并将其附加到临时结果中。 

处理完所有组后，我们将替换`s`使用新构造的字符串并重复直到`s.length <= k`。 

这种方法是正确的，因为它完全遵循问题陈述中描述的规则。 每轮转型均按要求执行。 

虽然这被称为强力方法，但它已经足够高效了，因为最大输入大小非常小。 字符串的重复重建和重复的数字求和仍然很便宜。 

### 最佳方法

 关键的观察是该问题本质上是一个模拟问题。 不需要快捷公式或高级数据结构，因为每次转换都取决于上一轮的结果。 

因此，最佳解决方案是仔细且高效地模拟该过程。 我们不是重复低效地创建许多中间字符串，而是使用列表（或等效的字符串生成器）在每一轮中以线性时间构造下一个字符串。 

每轮：

 1. 按大小块处理字符串`k`。 
2. 计算每个块的数字和。 
3. 将总和作为字符串附加。 
4. 将所有片段合并到下一个版本中`s`。 

由于绳子会随着时间的推移而收缩，因此总工作量仍然很小。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 直接模拟每一轮并重复字符串重建 |
 | 最佳| O(n²) | O(n) | 使用线性弦结构进行高效模拟 |

 这里，`n`表示字符串的最大长度。 自从`n <= 100`，这很容易足够快。 

## 算法演练

 ### 最优算法

 1. 开始一个循环，持续的长度为`s`大于`k`。 

我们仅在需要时执行转型轮次。 如果`s.length <= k`，该过程立即停止。 
2. 创建一个空列表（或字符串生成器）来构造字符串的下一个版本。 

增量构建字符串比重复串联更有效。 
3. 迭代`s`以尺寸为步长`k`。 

对于每个位置`i`，从中取出子字符串`i`到`i + k`。 最后一组自然可能会更小。 
4. 计算当前组的数字和。 

遍历组中的每个字符并通过减去来添加其数值`'0'`或转换为整数。 
5. 将计算出的总和转换为字符串并将其附加到结果生成器。 

这可以正确保留多位数和。 
6. 处理完所有组后，将各个片段合并成一个新字符串。 

代替`s`有了这个新生成的值。 
7. 重复直到`len(s) <= k`。 
8. 返回最终的字符串。 

### 为什么它有效

 该算法之所以有效，是因为它在每一轮都保留了问题的精确转换规则。 每次迭代都正确地将字符串划分为连续的大小组`k`，计算每个组的数字总和，将这些总和转换为字符串，然后按顺序连接它们。 

不变量是在每次循环迭代之后，`s`正是一轮有效问题所需的转换版本。 由于字符串最终变得足够短，因此该过程以正确答案终止。 

## Python 解决方案```python
class Solution:
    def digitSum(self, s: str, k: int) -> str:
        while len(s) > k:
            next_parts = []

            for i in range(0, len(s), k):
                group = s[i:i + k]

                digit_sum = 0
                for digit in group:
                    digit_sum += int(digit)

                next_parts.append(str(digit_sum))

            s = "".join(next_parts)

        return s
```实现完全遵循算法。 

这`while`循环确保只要字符串长度超过，我们就继续处理轮次`k`。 在每一轮比赛中，`next_parts`存储每个组的转换结果。 

这`for`循环按大小块处理字符串`k`使用Python切片。 表达式`s[i:i+k]`自动安全地处理最后一个部分组。 

对于每个组，我们计算`digit_sum`通过迭代每个字符并将其转换为整数使用`int(digit)`。 

计算总和后，我们将其转换回字符串并将其附加到`next_parts`。 处理完所有组后，`"".join(next_parts)`有效地构造新字符串。 

最终，循环停止时`len(s) <= k`, and the final string is returned.

 ## 解决方案```go
import (
	"strconv"
	"strings"
)

func digitSum(s string, k int) string {
	for len(s) > k {
		var builder strings.Builder

		for i := 0; i < len(s); i += k {
			end := i + k
			if end > len(s) {
				end = len(s)
			}

			sum := 0
			for j := i; j < end; j++ {
				sum += int(s[j] - '0')
			}

			builder.WriteString(strconv.Itoa(sum))
		}

		s = builder.String()
	}

	return s
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用`strings.Builder`用于高效的字符串构建。 

由于 Go 不支持自动对越界端点进行 Python 风格的切片行为，因此我们手动计算`end`并将其限制为`len(s)`安全地处理最后一个较小的群体。 

数字转换是通过以下方式完成的：```go
int(s[j] - '0')
```这可以有效地将字节字符转换为其数值。`strconv.Itoa()`在将计算出的总和附加到构建器之前将其转换回字符串。 

不用担心整数溢出，因为最大数字和非常小。 均匀求和`100`的数字`9`只生产`900`。

 ## 边缘情况

 ### 字符串长度已经小于或等于`k`一个常见的错误是即使不应该发生轮次也不必要地处理字符串。 

例如：```
s = "123"
k = 3
```自从`len(s) == k`，答案应该立即是`"123"`。 

该实现自然地处理了这个问题，因为`while len(s) > k`条件永远不会执行。 

### 最终组小于`k`最后一组不保证完全包含`k`人物。 

例如：```
s = "12345"
k = 3
```这些团体变成：```
"123", "45"
```有缺陷的实现可能会意外地忽略最后一个不完整的组或访问超出范围的索引。 

我们的解决方案通过在 Python 中安全切片并在 Go 中显式限制结束索引来正确处理此问题。 

### 多位数和

 数字和可以产生多个数字。 

例如：```
s = "999"
k = 2
```第一轮变成：```
"99" → 18
"9" → 9
```结果：```
"189"
```不正确的解决方案可能会假设每个组都产生一个数字，并在未来的轮次中错误地处理分组。 

我们的实现将每个总和转换为其完整的字符串表示形式，确保后续轮次正常工作。
