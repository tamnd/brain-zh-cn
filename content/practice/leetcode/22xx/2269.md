[LeetCode 第 2269 题](https://leetcode.com/problems/find-the-k-beauty-of-a-number/)

 **难度：** 🟢简单
 **主题：** 数学、字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定整数的 **k-beauty**`num`。 为此，我们对待`num`作为字符串并检查每个可能的**连续子串**长度`k`。 对于每个子字符串，我们将其解释为整数并检查它是否能整除原始数字`num`均匀。 最终的答案就是满足该整除条件的有效子串的数量。 

换句话说，我们正在滑动一个大小的窗口`k`跨字符串表示`num`。 每个窗口都给我们一个子串`k`数字。 我们将该子字符串转换为数字并检查两个条件：

 1. 子串值不能是`0`，因为除以零是未定义的。 
2. 子串值必须整除`num`均匀的意思`num % substring_value == 0`。 

输入包括：

 -`num`，我们要计算其 k-beauty 的整数。 
-`k`，所需的子串长度。 

输出是一个整数，表示有多少个有效长度-`k`子串是以下的约数`num`。 

限制相对较小：

 -`1 <= num <= 10^9`-`1 <= k <= len(str(num))`自从`num`至多是`10^9`，其字符串表示形式最多包含 10 位数字。 这意味着我们检查的子串总数非常小。 即使一个简单的解决方案也足够高效，但我们仍然可以编写一个干净的滑动窗口实现。 

有几种边缘情况值得预先考虑。 子串的计算结果可能是`0`， 例如`"00"`或者`"0"`，并且我们必须明确避免被零除。 允许使用前导零，这意味着像这样的子字符串`"04"`有效且应被解释为整数`4`。 我们还必须正确处理以下情况：`k`等于整个长度`num`，这意味着只有一个子字符串需要检查。 最后，如果重复的子串出现在不同的位置，则应单独计数。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是生成每个长度的子串`k`，将其转换为整数，并测试它是否能整除`num`。 

我们首先转换`num`到一个字符串中，这样我们就可以轻松地提取子字符串。 然后，对于每个起始索引`i`，我们取子串`s[i:i+k]`，将其转换为整数，并检查：

 - 值非零吗？ 
- 是否可以划分`num`均匀？ 

如果这两个条件都成立，我们就会增加我们的答案。 

这种方法是正确的，因为它明确地检查每个可能的子字符串一次并直接应用问题定义。 由于最大长度为`num`只有10位左右，这已经足够高效了。 

唯一的低效率来自于重复地对字符串进行切片并将子字符串转换为整数。 然而，考虑到限制，这一成本可以忽略不计。 

### 最佳方法的关键见解

 这个问题自然符合**滑动窗口**模式，因为我们检查每个固定长度的连续子串`k`。 

我们可以考虑移动一个大小的窗口，而不是将任务视为重复生成独立的子字符串`k`跨字符串表示`num`。 在每个位置，我们评估当前窗口并向前移动一个字符。 

尽管由于输入大小很小，我们在实践中仍然使用子字符串切片，但从概念上讲，这是一个滑动窗口问题，因为我们只处理所有固定长度的连续段一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × k) | O(n × k) | O(k) | 独立提取并转换每个子字符串 |
 | 最佳| O(n × k) | O(n × k) | O(k) | 固定大小子串上的滑动窗口 |

 这里，`n`表示中的位数`num`。 自从`n <= 10`，运行时间在实践中实际上是恒定的。 

## 算法演练

 1. 转换`num`到一个字符串中，这样我们就可以访问它的数字并轻松提取子字符串。 
2. 初始化计数器`count = 0`。 该变量将跟踪有多少子字符串满足除数条件。 
3. 遍历长度的每个可能的起始位置`k`子串。 由于子串长度是固定的，所以有效范围是从index开始`0`到`len(num_string) - k`。 
4.使用切片提取当前子字符串，`num_string[i:i+k]`。 
5. 将子字符串转换为整数。 这会自动正确处理前导零。 例如，`"04"`变成`4`。 
6. 检查子字符串值是否非零。 此步骤可防止除以零错误。 
7. 如果该值非零，检查它是否能整除`num`均匀地使用模运算符：`num % substring_value == 0`8. 如果条件为真，则递增计数器。 
9. 处理完所有子串后，返回最终计数。 

### 为什么它有效

 该算法之所以有效，是因为它系统地检查**每个长度有效的子串`k`正好一次**。 对于每个子串，它直接验证问题定义所需的确切条件，即子串是否表示的非零除数`num`。 由于没有子串被跳过或多次错误计数，因此最终计数保证等于 k-beauty`num`。 

## Python 解决方案```python
class Solution:
    def divisorSubstrings(self, num: int, k: int) -> int:
        num_string = str(num)
        count = 0

        for i in range(len(num_string) - k + 1):
            substring_value = int(num_string[i:i + k])

            if substring_value != 0 and num % substring_value == 0:
                count += 1

        return count
```实现从转换开始`num`到一个字符串中，使我们能够轻松提取连续的子字符串。 然后我们初始化`count`跟踪我们找到了多少个有效除数。 

该循环迭代长度子字符串的每个可能的起始位置`k`。 在每一步中，我们提取子字符串并将其转换为整数。 这种转换自然会处理前导零，这是问题明确允许的。 

在执行整除性测试之前，我们检查子字符串值是否为零。 这可以防止无效的除法运算。 如果子串非零并且可以整除`num`均匀地，我们增加答案。 

最后，检查完所有子字符串后，我们返回累计计数。 

## 解决方案```go
func divisorSubstrings(num int, k int) int {
	numStr := strconv.Itoa(num)
	count := 0

	for i := 0; i <= len(numStr)-k; i++ {
		substringValue, _ := strconv.Atoi(numStr[i : i+k])

		if substringValue != 0 && num%substringValue == 0 {
			count++
		}
	}

	return count
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 我们使用以下方法将整数转换为字符串`strconv.Itoa`，然后迭代所有有效的子字符串位置。 

Go 特有的一个细节是整数解析。 我们使用`strconv.Atoi`将子字符串转换为整数。 返回的错误将被安全地忽略，因为每个子字符串仅包含原始数字中的数字字符。 

要在 LeetCode 中成功编译，请记住包含：```go
import "strconv"
```与 Python 不同，Go 没有内置的整数到字符串转换功能`str()`，所以我们明确地使用`strconv`包裹。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n × k) | O(n × k) | 我们检查`n - k + 1`子串，每次切片和转换成本高达`O(k)`|

 运行时间取决于子字符串的数量以及将每个子字符串转换为整数的成本。 由于每个子串最多包含`k`数字，转换需要`O(k)`时间。 然而，因为`num`最多有 10 位数字，这个运行时间在实践中非常小。 

辅助空间复杂度为`O(k)`因为子字符串提取最多会创建长度为临时的字符串`k`。

 ## 边缘情况

 当子串的计算结果为时，会出现一种重要的边缘情况`0`。 由于零不能整除任何数字，因此尝试`num % 0`会导致错误。 这可能会发生在以下输入中：`430043`，其中子串`"00"`出现。 实施明确检查`substring_value != 0`在尝试分裂之前，确保安全执行。 

另一个重要的情况是**前导零**。 该问题允许像这样的子字符串`"04"`或者`"001"`。 粗心的实现可能会错误地拒绝这些或将它们视为字符串而不是数值。 通过使用将子字符串转换为整数`int()`在 Python 中或`strconv.Atoi()`在围棋中，`"04"`正确地变成`4`，允许有效的整除性检查。 

当出现第三种边缘情况时`k`等于中的总位数`num`。 在这种情况下，仅存在一个子字符串，即整个数字本身。 由于任何非零数都会自除，因此结果始终是`1`。 循环边界自然地处理这个问题，因为`len(num_string) - k + 1`变成`1`，恰好产生一次迭代。
