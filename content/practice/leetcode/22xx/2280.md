 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到了不同日期的股票价格列表。 中的每个元素`stockPrices`是一对：```
[day, price]
```这代表二维图表上的一个点，其中：

 - X 轴是日期
 - Y轴为当日股价

 折线图是将连续的点按日排序后连接而成。 

任务是确定表示整个图表所需的最少直线段数。 

重要的细节是位于同一条直线上的连续点可以由单个线段表示。 每当坡度发生变化时，我们就需要开始一条新的线段。 

例如，假设点是：```
(1,1), (2,2), (3,3), (4,5)
```前三个点都位于同一条斜线上`1`，因此它们可以用一个线段来表示。 斜率变化之间`(3,3)`和`(4,5)`，所以我们需要另一条线段。 答案就变成了`2`。 

输入约束很大：

 - 最多`10^5`点
 - 坐标高达`10^9`这些限制立即告诉我们：

 - 安`O(n^2)`解决方案会太慢
 - 我们需要一些接近的东西`O(n log n)`或者`O(n)`另一个重要的观察结果是，不能保证日期是排序的。 由于图表按时间顺序连接点，因此我们必须在处理之前按天对点进行排序。 

A subtle issue involves comparing slopes. 使用浮点除法是危险的，因为精度错误可能会导致不正确的比较。 例如：```
1/3 != 2/6 using floating point precision in some cases
```相反，我们应该使用叉乘来比较斜率：```
dy1 / dx1 == dy2 / dx2

becomes

dy1 * dx2 == dy2 * dx1
```这完全避免了精度问题。 

一些边缘情况很重要：

 - 如果只有一个点，则不需要任何线，因为没有任何东西可以连接。 
- 多个连续的线段可以共享相同的斜率，并且应算作一条线。 
- 带坡度的水平线`0`必须正确处理。 
- 非常大的坐标值需要小心处理以避免在某些语言中溢出。 

## 方法

 ### 蛮力方法

 强力解决方案将首先按天对点进行排序，然后重复尝试尽可能远地延伸每个线段。 

对于每个起点，我们可以计算到下一个点的斜率，并继续检查未来的点以查看它们是否位于同一条线上。 一旦坡度发生变化，我们就开始另一段。 

这种方法是正确的，因为它明确验证每个连续的点组是否属于同一条线。 然而，重复检查未来点会导致重复工作。 

在最坏的情况下，对于每个点，我们可能会扫描许多后面的点，从而导致二次复杂度。 

和`10^5`点，一个`O(n^2)`解决方案太慢了。 

### 最佳方法

 关键的见解是我们只需要比较连续的斜率。 

对点进行排序后：

 - 计算点之间的斜率`i-1`并点`i`- 计算点之间的斜率`i`并点`i+1`- 如果斜率相同，则当前路段继续
 - 如果坡度不同，我们必须开始一条新线

 我们不使用除法来计算斜率，而是使用交叉乘法来比较它们：```
(y2 - y1) * (x3 - x2) == (y3 - y2) * (x2 - x1)
```这让我们可以在排序后一次性处理数组。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复检查未来点是否在同一条线上 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(log n) | 排序一次，然后一次比较连续的斜率 |

 ## 算法演练

 1. 按天对积分进行排序。 

该图表按时间顺序连接点，因此我们必须按日的升序处理这些点。 
2. 处理只有一个点的特殊情况。 

如果数组长度是`1`，没有可绘制的线段，因此返回`0`。 
3. 初始化答案`1`。 

一旦我们至少有两个点，我们总是需要至少一条线段。 
4. 从索引开始迭代排序点`2`。 

在每一步中，比较：

 - 点之间的斜率`(i-2)`和`(i-1)`- 点之间的斜率`(i-1)`和`i`5. 使用交叉乘法比较斜率。 

认为：```
dx1 = x2 - x1
dy1 = y2 - y1

dx2 = x3 - x2
dy2 = y3 - y2
```如果满足以下条件，则斜率相等：```
dy1 * dx2 == dy2 * dx1
```这避免了浮点精度问题。 
6. 如果斜率不同，则增加答案。 

坡度变化意味着当前线段无法继续，因此我们必须开始新的线段。 
7. 返回最终计数。 

### 为什么它有效

 该算法保持了属于当前线段的所有连续点在相邻对之间具有相同斜率的不变性。 

如果两个连续的斜率相等，则涉及的三个点共线，这意味着当前线可以继续。 如果坡度不同，当前路段必须结束，新的路段必须开始。 

由于每个斜率变化都会被检测一次，因此该算法会生成所需的最少数量的线段。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumLines(self, stockPrices: List[List[int]]) -> int:
        n = len(stockPrices)

        if n == 1:
            return 0

        stockPrices.sort()

        lines = 1

        for i in range(2, n):
            x1, y1 = stockPrices[i - 2]
            x2, y2 = stockPrices[i - 1]
            x3, y3 = stockPrices[i]

            dx1 = x2 - x1
            dy1 = y2 - y1

            dx2 = x3 - x2
            dy2 = y3 - y2

            if dy1 * dx2 != dy2 * dx1:
                lines += 1

        return lines
```实现首先检查是否只有一个点。 在这种情况下，不需要线段。 

接下来，使用以下方法按天对点进行排序：```python
stockPrices.sort()
```由于每个条目都是`[day, price]`，Python 自然会首先按日期值排序。 

变量`lines`开始于`1`因为一旦至少有两个点，则至少需要一个线段。 

循环从索引处开始`2`因为我们一次比较两个连续的斜率，这需要三个点。 

循环内部：

 - 第一段使用积分`(i-2)`和`(i-1)`- 第二段使用积分`(i-1)`和`i`该实现不执行除法，而是使用叉乘来比较斜率：```python
dy1 * dx2 != dy2 * dx1
```如果等式失败，则斜率会发生变化，并且需要新的线段。 

最后，返回段的总数。 

## 解决方案```go
package main

import "sort"

func minimumLines(stockPrices [][]int) int {
	n := len(stockPrices)

	if n == 1 {
		return 0
	}

	sort.Slice(stockPrices, func(i, j int) bool {
		return stockPrices[i][0] < stockPrices[j][0]
	})

	lines := 1

	for i := 2; i < n; i++ {
		x1, y1 := stockPrices[i-2][0], stockPrices[i-2][1]
		x2, y2 := stockPrices[i-1][0], stockPrices[i-1][1]
		x3, y3 := stockPrices[i][0], stockPrices[i][1]

		dx1 := int64(x2 - x1)
		dy1 := int64(y2 - y1)

		dx2 := int64(x3 - x2)
		dy2 := int64(y3 - y2)

		if dy1*dx2 != dy2*dx1 {
			lines++
		}
	}

	return lines
}
```Go 解决方案遵循与 Python 实现相同的算法结构。 

Go 特有的一个重要细节是使用`int64`乘法期间：```go
int64(y2 - y1)
```由于坐标可以达到`10^9`，乘法可能会超出 32 位整数的范围。 使用`int64`防止交叉乘法期间溢出。 

排序步骤使用`sort.Slice`，按天对点进行排序。 

与 Python 不同，Go 不会自动支持任意大小的整数，因此显式类型转换对于正确性非常重要。

 ## 边缘情况

 ### 单点

 如果只有一个点，则没有可连接的相邻点。 一个常见的错误是返回`1`因为开发人员认为至少需要一个部分。 然而，单个点需要零线。 实现立即处理这个问题：```
if n == 1:
    return 0
```### 未排序的输入

 输入的日期是不同的，但不保证排序。 如果我们按原始顺序处理点，则构建的图表将是不正确的，因为该问题按时间顺序定义邻接关系。 该实现通过在任何斜率计算之前对数组进行排序来避免此问题。 

### 浮点精度错误

 由于舍入问题，使用浮点除法进行斜率比较可能会导致结果不正确。 例如：```
1/3 and 2/6
```在浮点运算中可能无法比较完全相等。 

该实现完全避免了除法，而是使用叉乘来比较斜率：```
dy1 * dx2 == dy2 * dx1
```这保证了数学上精确的比较。 

### 大坐标值

 坐标可以大到`10^9`。 差值相乘时，结果可能会超出 32 位整数限制。 

在Python中，整数会自动扩展，因此溢出不是问题。 然而，在 Go 中，明确`int64`为了安全地处理乘法而不溢出，必须进行转换。
