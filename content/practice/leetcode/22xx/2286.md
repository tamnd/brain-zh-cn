[LeetCode 问题 2286](https://leetcode.com/problems/booking-concert-tickets-in-groups/)

 **难度：** 🔴难
 **主题：** 二分搜索、设计、二叉索引树、线段树

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个音乐厅的门票预订系统。 大厅内有`n`行，每行恰好包含`m`座位。 每排座位从左到右编号为`0`。 

我们必须支持两种不同的操作：

 第一次手术，`gather(k, maxRow)`，尝试保留`k`同一排的连续座位。 行数最多只能是`maxRow`。 在所有有效选择中，我们必须始终选择尽可能小的行索引。 在该排中，我们必须选择最左边的可用座位区。 如果没有行来自`0`通过`maxRow`有`k`连续的空座位，我们返回一个空数组。 

第二次手术，`scatter(k, maxRow)`，限制较少。 这`k`人们不需要坐在一起。 我们只需要保证至少有`k`各排空座位总数`0`通过`maxRow`。 如果可能，首先使用最小的行号贪婪地分配座位，并且在每行中，首先使用最小的座位号。 该方法返回`true`如果分配成功并且`false`否则。 

一个关键的观察结果是，每排的座位总是从左到右被填满。 我们从不在一排内创造间隙。 这个属性变得非常重要，因为它意味着我们只需要跟踪每排已经使用了多少个座位。 

限制条件很大：

 -`n <= 5 * 10^4`- 至多`5 * 10^4`运营
-`m`和`k`可以大到`10^9`单独检查每个座位的简单模拟会太慢。 如果不小心，即使重复遍历所有行也会变得昂贵。 

主要挑战是有效地重复回答两个问题：

 1.是否有人划船`maxRow`至少有`k`连续空座位？ 
2. 总共有多少个空座位`maxRow`？ 

这些要求强烈建议使用线段树，因为我们需要高效的范围查询和更新。 

重要的边缘情况包括：

 - 一行可能会完全满。 
-`gather`必须始终选择最小的有效行。 
-`scatter`可能部分填充几行。 
-`k`可以超过任何单行的容量，使得`gather`立即不可能。 
- 经过多次操作后，大厅可能几乎已满，因此有必要有效地跳过耗尽的行。 

## 方法

 ### 蛮力方法

 最直接的解决方案是明确跟踪每排剩余的座位数。 

为了`gather(k, maxRow)`，我们扫描行`0`到`maxRow`并检查该行是否至少有`k`提供连续座位。 由于座位总是从左到右分配，这意味着检查剩余容量是否至少为`k`。 

为了`scatter(k, maxRow)`，我们首先计算各排剩余的座位数`0`通过`maxRow`。 如果存在足够的座位，我们将逐行迭代并消耗座位，直到所有座位`k`观众已就座。 

这种方法在逻辑上是正确的，因为它直接遵循问题规则。 然而，性能较差。 在最坏的情况下，每个操作可能会扫描最多`O(n)`行，并且可以有`5 * 10^4`运营。 这导致大约`2.5 * 10^9`在最坏的情况下进行行检查，这太慢了。 

### 最佳方法

 关键的见解是我们反复需要行范围内的两种类型的聚合信息：

 1. 任意排剩余座位的最大数量，对于`gather`2. 各排剩余座位总数，`scatter`线段树是理想的选择，因为它有效地支持范围聚合和点更新。 

我们维持：

 -`maxTree[node]`，该航段的最大剩余座位数
 -`sumTree[node]`，该部分的剩余席位总数

 每行最初包含`m`可用座位。 

为了`gather`，我们使用最大线段树来定位最左边的行至少`k`可用座位。 

为了`scatter`，我们使用和线段树来确定是否存在足够的总座位数。 如果是这样，我们就会贪婪地消耗最小排的座位。 

每次更新只影响一行，因此线段树更新需要`O(log n)`时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次操作 O(n) | O(n) | 重复扫描行 |
 | 最佳| 聚集为 O(log n)，分散为 O(log n + 受影响的行) | O(n) | 使用线段树进行高效聚合 |

 ## 算法演练

 ### 数据结构

 我们维护三个重要的状态：

 -`used[row]`, 每排已占用的座位数
 -`maxTree`，存储每个航段的最大剩余座位数
 -`sumTree`，存储每个航段的剩余座位总数

 最初：

 -`used[row] = 0`- 每行都有`m`可用座位

 ### 采集操作

 1.首先检查是否有行在范围内`[0, maxRow]`至少有`k`免费座位。 
2. 我们查询该范围内的线段树最大值。 如果最大值小于`k`，聚集是不可能的。 
3. 否则，我们递归地在线段树中查找剩余容量至少为的最左边行`k`。 
4. 一旦找到该排，起始座位索引就很简单`used[row]`，因为座位总是从左到右分配。 
5. 我们增加`used[row]`经过`k`。 
6. 我们更新该行的线段树值：

 - 剩余座位变为`m - used[row]`- 最大值和总和值都通过树向上刷新
 7. 返回`[row, startingSeat]`。 

### 分散操作

 1. 首先，计算各排剩余座位总数`[0, maxRow]`。 
2. 如果总数小于`k`， 返回`false`。 
3. 否则，我们开始从最小的可用行开始贪婪地分配座位。 
4. 对于每一行：

 - 确定剩余座位数
 - 分配尽可能多的
 - 更新`used[row]`- 更新线段树
 5. 继续，直到全部`k`观众已就座。 
6. 返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为线段树始终维护每个行范围的准确聚合信息。 

这`maxTree`不变性保证我们可以有效地确定某行是否可以容纳连续的大小块`k`，并找到最左边的该行。 

这`sumTree`不变性保证我们可以正确地确定是否存在足够的总席位`scatter`。 

由于座位总是从左到右分配，并且行按升序处理，因此该实现完全符合所需的平局打破规则。 

## Python 解决方案```python
from typing import List

class BookMyShow:

    def __init__(self, n: int, m: int):
        self.n = n
        self.m = m

        self.used = [0] * n

        size = 4 * n
        self.max_tree = [0] * size
        self.sum_tree = [0] * size

        self._build(1, 0, n - 1)

        self.scatter_row = 0

    def _build(self, node: int, left: int, right: int) -> None:
        if left == right:
            self.max_tree[node] = self.m
            self.sum_tree[node] = self.m
            return

        mid = (left + right) // 2

        self._build(node * 2, left, mid)
        self._build(node * 2 + 1, mid + 1, right)

        self.max_tree[node] = self.m
        self.sum_tree[node] = (right - left + 1) * self.m

    def _update(self, node: int, left: int, right: int, idx: int) -> None:
        if left == right:
            remaining = self.m - self.used[idx]
            self.max_tree[node] = remaining
            self.sum_tree[node] = remaining
            return

        mid = (left + right) // 2

        if idx <= mid:
            self._update(node * 2, left, mid, idx)
        else:
            self._update(node * 2 + 1, mid + 1, right, idx)

        self.max_tree[node] = max(
            self.max_tree[node * 2],
            self.max_tree[node * 2 + 1]
        )

        self.sum_tree[node] = (
            self.sum_tree[node * 2]
            + self.sum_tree[node * 2 + 1]
        )

    def _query_max(
        self,
        node: int,
        left: int,
        right: int,
        ql: int,
        qr: int
    ) -> int:
        if ql <= left and right <= qr:
            return self.max_tree[node]

        mid = (left + right) // 2
        result = 0

        if ql <= mid:
            result = max(
                result,
                self._query_max(node * 2, left, mid, ql, qr)
            )

        if qr > mid:
            result = max(
                result,
                self._query_max(node * 2 + 1, mid + 1, right, ql, qr)
            )

        return result

    def _query_sum(
        self,
        node: int,
        left: int,
        right: int,
        ql: int,
        qr: int
    ) -> int:
        if ql <= left and right <= qr:
            return self.sum_tree[node]

        mid = (left + right) // 2
        total = 0

        if ql <= mid:
            total += self._query_sum(
                node * 2,
                left,
                mid,
                ql,
                qr
            )

        if qr > mid:
            total += self._query_sum(
                node * 2 + 1,
                mid + 1,
                right,
                ql,
                qr
            )

        return total

    def _find_row(
        self,
        node: int,
        left: int,
        right: int,
        max_row: int,
        k: int
    ) -> int:
        if left == right:
            return left

        mid = (left + right) // 2

        if (
            left <= max_row
            and self.max_tree[node * 2] >= k
        ):
            return self._find_row(
                node * 2,
                left,
                mid,
                max_row,
                k
            )

        return self._find_row(
            node * 2 + 1,
            mid + 1,
            right,
            max_row,
            k
        )

    def gather(self, k: int, maxRow: int) -> List[int]:
        if self._query_max(1, 0, self.n - 1, 0, maxRow) < k:
            return []

        row = self._find_row(1, 0, self.n - 1, maxRow, k)

        seat = self.used[row]

        self.used[row] += k

        self._update(1, 0, self.n - 1, row)

        return [row, seat]

    def scatter(self, k: int, maxRow: int) -> bool:
        available = self._query_sum(1, 0, self.n - 1, 0, maxRow)

        if available < k:
            return False

        row = self.scatter_row

        while k > 0 and row <= maxRow:
            remaining = self.m - self.used[row]

            if remaining == 0:
                row += 1
                continue

            take = min(k, remaining)

            self.used[row] += take

            self._update(1, 0, self.n - 1, row)

            k -= take

            if self.used[row] == self.m:
                row += 1

        self.scatter_row = row

        return True
```该实现首先构建一个线段树，其中每行最初都有`m`可用座位。 

这`_build`方法初始化树。 每片叶子对应一行。 内部节点聚合来自子节点的信息。 

这`_update`分配座位后，方法会刷新一行。 由于一次仅更改一行，因此更新可以有效地向上传播。 

这`_query_max`方法确定范围中的某些行是否可以满足`gather`要求。 

这`_query_sum`方法计算总剩余容量`scatter`。 

这`_find_row`方法对线段树结构本身执行二分搜索。 它总是首先探索左孩子，保证我们找到最小的有效行。 

这`scatter_row`指针是一种优化。 一旦一行完全满了，未来的分散操作就不需要重新访问它。 

## 解决方案```go
package main

type BookMyShow struct {
	n          int
	m          int
	used       []int
	maxTree    []int
	sumTree    []int64
	scatterRow int
}

func Constructor(n int, m int) BookMyShow {
	bms := BookMyShow{
		n:          n,
		m:          m,
		used:       make([]int, n),
		maxTree:    make([]int, 4*n),
		sumTree:    make([]int64, 4*n),
		scatterRow: 0,
	}

	bms.build(1, 0, n-1)

	return bms
}

func (this *BookMyShow) build(node int, left int, right int) {
	if left == right {
		this.maxTree[node] = this.m
		this.sumTree[node] = int64(this.m)
		return
	}

	mid := (left + right) / 2

	this.build(node*2, left, mid)
	this.build(node*2+1, mid+1, right)

	this.maxTree[node] = this.m
	this.sumTree[node] = int64(right-left+1) * int64(this.m)
}

func (this *BookMyShow) update(
	node int,
	left int,
	right int,
	idx int,
) {
	if left == right {
		remaining := this.m - this.used[idx]
		this.maxTree[node] = remaining
		this.sumTree[node] = int64(remaining)
		return
	}

	mid := (left + right) / 2

	if idx <= mid {
		this.update(node*2, left, mid, idx)
	} else {
		this.update(node*2+1, mid+1, right, idx)
	}

	if this.maxTree[node*2] > this.maxTree[node*2+1] {
		this.maxTree[node] = this.maxTree[node*2]
	} else {
		this.maxTree[node] = this.maxTree[node*2+1]
	}

	this.sumTree[node] =
		this.sumTree[node*2] +
			this.sumTree[node*2+1]
}

func (this *BookMyShow) queryMax(
	node int,
	left int,
	right int,
	ql int,
	qr int,
) int {
	if ql <= left && right <= qr {
		return this.maxTree[node]
	}

	mid := (left + right) / 2
	result := 0

	if ql <= mid {
		val := this.queryMax(node*2, left, mid, ql, qr)
		if val > result {
			result = val
		}
	}

	if qr > mid {
		val := this.queryMax(node*2+1, mid+1, right, ql, qr)
		if val > result {
			result = val
		}
	}

	return result
}

func (this *BookMyShow) querySum(
	node int,
	left int,
	right int,
	ql int,
	qr int,
) int64 {
	if ql <= left && right <= qr {
		return this.sumTree[node]
	}

	mid := (left + right) / 2
	var total int64 = 0

	if ql <= mid {
		total += this.querySum(node*2, left, mid, ql, qr)
	}

	if qr > mid {
		total += this.querySum(node*2+1, mid+1, right, ql, qr)
	}

	return total
}

func (this *BookMyShow) findRow(
	node int,
	left int,
	right int,
	maxRow int,
	k int,
) int {
	if left == right {
		return left
	}

	mid := (left + right) / 2

	if mid >= left &&
		this.maxTree[node*2] >= k &&
		left <= maxRow {

		return this.findRow(
			node*2,
			left,
			mid,
			maxRow,
			k,
		)
	}

	return this.findRow(
		node*2+1,
		mid+1,
		right,
		maxRow,
		k,
	)
}

func (this *BookMyShow) Gather(
	k int,
	maxRow int,
) []int {
	if this.queryMax(1, 0, this.n-1, 0, maxRow) < k {
		return []int{}
	}

	row := this.findRow(1, 0, this.n-1, maxRow, k)

	seat := this.used[row]

	this.used[row] += k

	this.update(1, 0, this.n-1, row)

	return []int{row, seat}
}

func (this *BookMyShow) Scatter(
	k int,
	maxRow int,
) bool {
	available := this.querySum(1, 0, this.n-1, 0, maxRow)

	if available < int64(k) {
		return false
	}

	row := this.scatterRow

	for k > 0 && row <= maxRow {
		remaining := this.m - this.used[row]

		if remaining == 0 {
			row++
			continue
		}

		take := remaining
		if k < take {
			take = k
		}

		this.used[row] += take

		this.update(1, 0, this.n-1, row)

		k -= take

		if this.used[row] == this.m {
			row++
		}
	}

	this.scatterRow = row

	return true
}
```Go 实现密切反映了 Python 逻辑，但有一些特定于语言的细节值得注意。 

座位总数可以超过 32 位整数范围，因为`n * m`可能大到`5 * 10^13`。 为此原因，`sumTree`用途`int64`。 

Go 没有像 Python 那样的动态列表，因此返回空结果为`[]int{}`。 

方法是通过指针接收器实现的，因此更新可以正确修改共享结构。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 聚集时为 O(log n)，分散时为摊销 O(log n) | 线段树查询和更新占主导地位 |

 线段树包含`O(n)`节点。 

每个`gather`操作执行：

 - 一次最大查询
 - 沿着树向下搜索一次
 - 一项更新

 每一步的成本`O(log n)`。 

为了`scatter`，行仅向前推进，因为`scatter_row`指针。 在所有操作中，每行最多变满一次。 因此，总的额外扫描工作在整个执行过程中线性摊销。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k`超过每行的容量。 由于聚集请求需要一排中的连续座位，因此即使多排中仍有许多总座位，也无法进行分配。 该实现自然地处理了这个问题，因为线段树最大查询立即确定没有行具有足够的剩余容量。 

当行完全满时，会发生另一个棘手的情况。 幼稚的分散实现可能会反复重新访问耗尽的行，从而导致严重的性能下降。 该解决方案使用以下方法避免了这个问题`scatter_row`指针，它永久跳过已经满的行。 

第三个重要的边缘情况涉及打破平局。 该问题要求始终选择尽可能小的排，然后选择尽可能小的座位数。 如果不仔细控制搜索顺序，这很容易错误地实现。 线段树搜索总是首先探索左孩子，保证发现的第一个有效行是最小的有效行。 由于座位是从左到右分配的，因此起始座位索引也始终是最小的。
