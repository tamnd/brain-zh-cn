[LeetCode 问题 2220](https://leetcode.com/problems/minimum-bit-flips-to-convert-number/)

 **难度：** 🟢简单
 **主题：** 位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们确定转换整数所需的**最小位翻转次数**`start`变成另一个整数`goal`。 位翻转定义为将数字的二进制表示中的单个位从`0`到`1`或来自`1`到`0`。 输入由两个非负整数组成`start`和`goal`，两者的范围都可以达到$10^9$。 预期输出是一个整数，表示所需的最小翻转次数。 

本质上，问题是要求二进制表示中的位置数`start`和`goal`其中位不同。 这相当于计算两个数字之间的**汉明距离**。 

关键考虑因素包括处理具有不同位长度的数字、相等的数字（导致零翻转）以及高达 30 位的非常大的数字（因为$10^9 < 2^{30}$）。 边缘情况可能包括`start`或者`goal`为零或一个明显大于另一个。 

## 方法

 **暴力方法**涉及转换两者`start`和`goal`转换为它们的二进制字符串表示形式，对齐它们的长度，然后迭代每个位以计算差异。 虽然这可行，但它涉及字符串操作和逐位比较，这是不必要的，因为可以使用按位运算符。 这种方法相对于位数具有线性时间复杂度，但由于字符串操作的开销，它并不是最佳的。 

**最佳方法**利用按位异或运算。 两个位之间的异或是`1`如果位不同并且`0`如果它们是相同的。 因此，`start ^ goal`产生一个数字，其中每个`1`代表需要翻转的位。 计算数量`1`该 XOR 结果中的 s 给出了最小翻转次数。 这是高效的，因为它直接在位级别工作，无需任何转换为​​字符串。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(B) | O(B) | 将数字转换为二进制字符串并比较每一位 |
 | 最佳| O(B) | O(1) | O(1) | 使用 XOR 来识别不同的位并对设置的位进行计数 |

 这里，$B$表示表示数字所需的位数，对于给定的约束最多为 30。 

## 算法演练

 1. 计算 XOR`start`和`goal`。 这给出了一个数字，其中每个`1`表示两个数字之间的差异位。 
2. 初始化计数器`flips`为零以跟踪不同位数。 
3. 当异或结果大于零时，重复删除最低有效位`1`使用`xor &= xor - 1`。 增量`flips`每次。 该技术有效地计算设置位的数量。 
4.一次全部`1`s 已被删除，计数器`flips`包含所需的最小位翻转次数。 
5. 返回`flips`结果。 

为什么有效：XOR 产生一个二进制数，其中每个`1`表示不同的位置`start`和`goal`。 算上所有这样的`1`s 给出需要翻转的确切位数。 该物业`x & (x - 1)`有效地清除最低设置位，确保所有不同的位都被计数。 

## Python 解决方案```python
class Solution:
    def minBitFlips(self, start: int, goal: int) -> int:
        xor = start ^ goal
        flips = 0
        while xor:
            xor &= xor - 1
            flips += 1
        return flips
```Python 实现计算 XOR`start`和`goal`识别不同的位。 然后，它使用具有高效的循环来计算设置位的数量`xor &= xor - 1`诡计。 每次迭代都会删除一个设置位并递增`flips`计数器，直到没有剩余的设置位。 

## 解决方案```go
func minBitFlips(start int, goal int) int {
    xor := start ^ goal
    flips := 0
    for xor != 0 {
        xor &= xor - 1
        flips++
    }
    return flips
}
```Go 中的实现与 Python 中基本相同。 Go 使用`int`对于整数，按位运算直接对整数起作用。 该循环使用相同的有效位清除方法对 XOR 结果中的设置位进行计数。 

## 工作示例

 **示例1：**`start = 10`,`goal = 7`二进制表示：`10 = 1010`,`7 = 0111`1. 异或：`1010 ^ 0111 = 1101`2. 计算设置位`1101`: 3

 结果：`3`翻转。 

**示例2：**`start = 3`,`goal = 4`二进制表示：`3 = 011`,`4 = 100`1. 异或：`011 ^ 100 = 111`2. 计算设置位`111`: 3

 结果：`3`翻转。 

| 步骤| 异或值 | 翻转次数 |
 | --- | --- | --- |
 | 初始| 1010^0111=1101| 0 |
 | 删除最低 1 | 1100 | 1100 1 |
 | 删除最低 1 | 1000 | 1000 2 |
 | 删除最低 1 | 0000 | 0000 3 |

 ## 边缘情况

 1. **开始和目标是相同的：** 如果实现错误地计算翻转次数，即使数字相等，这也是一个潜在的错误源。 正确的输出是零翻转，因为两个相同数字的异或为零。 
2. **二进制表示中带有前导零的数字：** 基于字符串的简单解决方案可能会忽略前导零，从而导致计数不正确。 按位异或方法本质上处理所有位，包括前导零，以确保正确性。 
3. **最大可能值：** 数字可达$10^9$，XOR 结果最多可以有 30 位。 该解决方案必须有效地处理位计数，而无需转换为字符串或使用大型数组。 这`xor &= xor - 1`技术保证了大投入的效率。
