[LeetCode 问题 2255](https://leetcode.com/problems/count-prefixes-of-a-given-string/)

 **难度：** 🟢简单
 **主题：** 数组、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定数组中有多少个字符串`words`是目标字符串的前缀`s`。 字符串的前缀定义为从第一个字符开始并持续任意长度直至字符串本身长度的任何子字符串。 例如，`"ab"`是一个前缀`"abc"`， 但`"bc"`不是因为它不是从第一个字符开始。 输入数组`words`包含多个候选字符串，我们必须检查每个候选字符串`s`。 

输入约束表明`words`最多可以有 1000 个字符串，每个字符串包括`s`，最多可以有 10 个字符。 这是相对较小的，因此具有嵌套迭代的算法`words`小字符串比较将有效运行。 需要注意的是，字符串中的`words`可以重复，如果是有效前缀，则每次出现都应单独计数。 边缘情况包括长度为 1 的字符串、重复条目以及没有字符串作为前缀匹配的情况。 

## 方法

 蛮力方法很简单：迭代中的每个字符串`words`并检查它是否是前缀`s`。 这可以使用子字符串比较来完成。 这种方法是正确的，因为它显式检查前缀的定义。 考虑到输入限制，这种方法实际上足够有效，但从概念上讲，它涉及单独检查每个单词，这就是为什么它被认为是暴力破解的原因。 

稍微更优化的方法利用了以下事实：字符串`words`很短（长度 <= 10）。 一旦单词长度超过，我们就可以停止检查`s`，我们只需要比较第一个`len(word)`的字符`s`。 这减少了不必要的比较，并且概念上更清晰，但实际上，由于输入大小较小，时间复杂度保持相似。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 使用子字符串比较单独检查每个单词，其中 n = len(words)，m = 单词的最大长度 |
 | 优化| O(n * m) | O(1) | O(1) | 停止检查长于 s 的单词，只比较所需的字符 |

 ## 算法演练

 1.初始化一个计数器`count`到 0 来跟踪有多少个单词是前缀`s`。 
2. 遍历列表中的每个单词`words`大批。 
3. 对于每个单词，首先检查其长度是否小于或等于`s`。 如果较长，请跳过它，因为它不能是前缀。 
4. 将单词与子串进行比较`s`从索引 0 到`len(word)`。 如果匹配，则增加计数器`count`1.
 5. 继续迭代，直到处理完所有单词。 
6. 返回值`count`。 

为什么它有效：该算法之所以有效，是因为对于每个单词，我们直接检查作为前缀的必要条件。 比较仅检查相关的字符，确保正确性，同时避免对不可能匹配的单词进行不必要的工作。 

## Python 解决方案```python
from typing import List

class Solution:
    def countPrefixes(self, words: List[str], s: str) -> int:
        count = 0
        for word in words:
            if len(word) <= len(s) and s[:len(word)] == word:
                count += 1
        return count
```该实现紧密遵循算法。 我们初始化一个计数器，迭代每个单词，并使用切片直接比较前缀。 长度检查确保我们不会尝试切片超出字符串的范围，从而防止运行时错误。 

## 解决方案```go
func countPrefixes(words []string, s string) int {
    count := 0
    for _, word := range words {
        if len(word) <= len(s) && s[:len(word)] == word {
            count++
        }
    }
    return count
}
```Go 解决方案反映了 Python 逻辑。 Go 类似地对字符串进行切片，我们使用以下方法比较子字符串`==`。 长度检查确保安全切片。 与 Python 不同，Go 需要显式处理切片，并且不能使用动态类型系统，但整体逻辑保持不变。

 ## 边缘情况

 一种边缘情况是当`words`数组为空。 该函数必须返回 0，而不尝试任何子字符串比较，我们的实现通过迭代空数组来自然地处理它。 

另一个边缘情况是当所有单词都在`words`长于`s`。 在这种情况下，长度检查可以防止任何越界切片并确保不计算错误匹配。 

第三种边缘情况是当`words`包含重复项。 我们的算法正确地分别计算每个出现的次数，因为每个单词都是独立检查的`s`。 此行为与问题陈述一致并避免计数不足。
