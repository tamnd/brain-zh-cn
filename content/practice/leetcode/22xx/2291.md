[LeetCode 第 2291 题](https://leetcode.com/problems/maximum-profit-from-trading-stocks/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们两个数组，`present`和`future`，其中每个指数代表一只股票。 价值`present[i]`是购买的价格`i-th`今天有货，同时`future[i]`是同一股票一年后可以出售的价格。 

我们还得到了有限的`budget`，代表我们今天可以花多少钱购买股票。 每只股票最多可以购买一次**，这意味着这是一个选择问题，我们要么购买股票，要么跳过它。 

目标是最大化**利润**，而不是未来总价值。 如果我们以当前价格购买股票`present[i]`然后卖给`future[i]`，利润贡献为：$$future[i] - present[i]$$我们可以选择任何股票子集，前提是总购买成本不超过`budget`。 任务是返回可实现的**最大总利润**。 

一个重要的观察是，非正利润的股票永远没有用处。 如果：$$future[i] \le present[i]$$那么购买股票的利润为零或负，因此它永远不会改善答案。 我们可以安全地忽略此类股票。 

这些约束告诉我们很多关于预期解决方案的信息：

 -`n <= 1000`-`budget <= 1000`对所有子集的强力搜索需要检查：$$2^{1000}$$可能的组合，这是完全不可行的。 

然而，相对较小的预算强烈建议采用**超出预算的动态规划**方法。 既然两者`n`和`budget`至多是`1000`， 一个`O(n × budget)`解决方案很实用。 

需要记住的一些重要的边缘情况是：

 -`budget = 0`，无法进行购买。 
- 所有股票的利润都是负数或零，这意味着答案应该是`0`。 
- 股票的成本超过了整个预算，这意味着无法购买。 
- 存在多种盈利股票，但购买单个最好的股票并不是全局最优的。 我们必须考虑组合。 
- 股票有`present[i] = 0`，可以免费购买，并且可以在不影响预算的情况下创造利润。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试所有可能的股票子集。 

对于每只股票，我们有两种选择：

 1.购买股票。 
2.跳过库存。 

这自然就形成了二叉决策树。 对于每个子集，我们计算：

 - 总购买成本。 
- 总利润。 

如果总成本不超过预算，我们会将利润与迄今为止看到的最佳答案进行比较。 

这种方法是正确的，因为它详尽地探索了每种有效的购买组合，保证找到最大利润。 

然而，子集的数量呈指数增长：$$2^n$$和`n = 1000`，这在时间限制内是不可能计算的。 

### 最优方法，0/1 背包动态规划

 关键的见解是这个问题实际上是一个 **0/1 背包问题**。 

每只股票的行为就像一个物品：

 - **重量（成本）** =`present[i]`- **价值（利润）** =`future[i] - present[i]`我们希望在保持固定预算的情况下最大化总价值。 

由于每只股票只能购买一次，所以这具体是一个**0/1背包**，而不是无界背包。 

我们定义：`dp[b] = maximum profit achievable using budget b`对于每只盈利的股票，我们**向后**迭代预算，以便每只股票最多使用一次。 

向后迭代至关重要。 如果我们向前迭代，同一只股票可能会意外地被多次计数，从而将问题变成无界背包。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2ⁿ) | O(n) | 尝试股票的每个子集|
 | 最佳| O(n × 预算) | O（预算）| 使用0/1背包动态规划 |

 ## 算法演练

 ### 最优动态规划算法

 1. **初始化DP数组**

 创建一个数组`dp`尺寸的`budget + 1`。`dp[b]`将存储最多使用可实现的最大利润`b`美元。 

最初，所有值都是`0`因为不购买总是带来零利润。 
2. **处理每个库存**

 对于每只股票`i`:

 - 计算：`cost = present[i]`

`profit = future[i] - present[i]`如果`profit <= 0`，跳过股票，因为购买它不能改善答案。 
3. **向后更新DP数组**

 对于每个预算值`budget`下降到`cost`:

 检查购买这只股票是否会提高利润：```
dp[b] = max(dp[b], dp[b - cost] + profit)
```这里：

-`dp[b]`意味着跳过股票。 
-`dp[b - cost] + profit`意味着购买它。 

我们选择利润更高的那个。 
4. **继续所有股票**

 对每只盈利的股票重复此更新过程。 
5. **返回答案**

 最终的答案是：```
dp[budget]
```这代表在可用预算内可实现的最大利润。 

### 为什么它有效

 该算法之所以有效，是因为它保持了一个不变量：

 > 处理完第一条后`i`股票,`dp[b]`存储使用具有预算的股票可实现的最大利润`b`。 

对于每只股票，我们都会考虑两种可能性：买入或跳过。 由于我们向后迭代预算，因此股票最多对任何状态转换做出一次贡献。 因此，每个有效组合只会被考虑一次，这保证了找到最佳解决方案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumProfit(self, present: List[int], future: List[int], budget: int) -> int:
        dp = [0] * (budget + 1)

        for current_price, future_price in zip(present, future):
            profit = future_price - current_price

            # Ignore non-profitable stocks
            if profit <= 0:
                continue

            # 0/1 knapsack update
            for current_budget in range(budget, current_price - 1, -1):
                dp[current_budget] = max(
                    dp[current_budget],
                    dp[current_budget - current_price] + profit
                )

        return dp[budget]
```### 实现说明

 该解决方案首先创建一个大小为 的一维 DP 数组`budget + 1`。 每个指数代表一个可能的支出限额，而存储的价值是在该限额内可实现的最佳利润。 

然后我们使用迭代遍历每只股票`zip(present, future)`以便将买入价格和未来价格一起处理。 

对于每只股票，我们计算其利润：```
profit = future_price - current_price
```如果利润不是正数，则跳过该股票，因为购买它不能增加总收益。 

对于盈利的股票，我们执行标准的 0/1 背包转换。 该循环向后迭代预算范围：```
for current_budget in range(budget, current_price - 1, -1):
```这种向后遍历可确保库存最多使用一次。 如果我们向前迭代，同一只股票可能会在单次迭代中多次贡献。 

过渡：```
dp[current_budget] = max(
    dp[current_budget],
    dp[current_budget - current_price] + profit
)
```比较两个选择：

 - 跳过库存并保留现有价值。 
- 购买股票并将其利润添加到先前可实现的最佳状态。 

所有库存处理完毕后，`dp[budget]`包含最优利润。 

## 解决方案```go
func maximumProfit(present []int, future []int, budget int) int {
	dp := make([]int, budget+1)

	for i := 0; i < len(present); i++ {
		cost := present[i]
		profit := future[i] - present[i]

		// Ignore non-profitable stocks
		if profit <= 0 {
			continue
		}

		// 0/1 knapsack update
		for currentBudget := budget; currentBudget >= cost; currentBudget-- {
			candidate := dp[currentBudget-cost] + profit
			if candidate > dp[currentBudget] {
				dp[currentBudget] = candidate
			}
		}
	}

	return dp[budget]
}
```### Go 具体注释

 Go 实现遵循与 Python 版本完全相同的动态编程策略。 

Go 使用切片而不是 Python 列表：```go
dp := make([]int, budget+1)
```由于Go没有内置的`max`对于整数函数，我们使用手动比较值`if`陈述。 

整数溢出在这里不是一个问题，因为：

 -`future[i] <= 100`-`n <= 1000`最大可能的利润仍然在 Go 的范围内`int`范围。 

Nil 切片也不是问题，因为 LeetCode 保证相同长度的有效输入数组。

 ## 边缘情况

 ### 预算为零

 当`budget = 0`，无论盈利能力如何，都不能购买股票。 有缺陷的实现可能会意外地错误地包含零成本股票或尝试建立无效的索引。 

该实现自然地处理了这个问题，因为 DP 数组有大小`1`，并且预算循环永远不会执行，除非库存成本是`0`。 答案仍然正确初始化为`0`。 

### 所有股票都是非盈利的

 如果每只股票都有：```
future[i] <= present[i]
```那么购买任何股票要么赔钱，要么没有收益。 

幼稚的实施可能仍然包括零利润或负利润交易，浪费预算并降低结果。 我们的实现明确跳过这些股票：```
if profit <= 0:
    continue
```这保证了只考虑有利的交易。 

### 库存成本超出预算

 有些股票可能利润丰厚，但仍然买不起。 

例如：```
present = [20]
future = [50]
budget = 10
```内循环：```
range(budget, cost - 1, -1)
```永远不会执行如果`cost > budget`，这意味着股票将被自动忽略，无需特殊情况逻辑。 

### 选择组合而不是贪婪的选择

 贪婪的策略可能会因为总是选择单个利润最高的股票而失败。 

例如：```
present = [4, 5, 6]
future = [7, 9, 10]
budget = 9
```最好的个股带来利润`4`，但是购买前两只股票会得到：```
3 + 4 = 7
```动态规划方法可以正确评估所有可行的组合并避免这种常见错误。
