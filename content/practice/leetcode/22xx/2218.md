[LeetCode 2218 题](https://leetcode.com/problems/maximum-value-of-k-coins-from-piles/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大化从多个堆中收集的硬币的总价值，同时遵循严格的清除规则。 每堆硬币都是从上到下排序的，这意味着我们不能随意挑选一堆硬币。 我们只能从顶部取出硬币，一次一枚。 如果我们想要一枚硬币更深，我们必须首先移除上面的所有硬币。 

输入由二维数组组成`piles`， 在哪里`piles[i]`代表`i-th`一堆硬币。 每堆包含正整数值，从上到下排序。 我们还得到一个整数`k`，代表我们必须挑选的硬币的确切数量。 

关键细节是我们必须选择**准确**`k`硬币，最多不是`k`。 在所有有效的方法中，要准确地采取`k`所有硬币堆中的硬币，我们希望总价值尽可能大。 

例如，如果有一堆`[1, 100, 3]`，取`100`单独的硬币是不可能的，因为它被埋在地下`1`。 访问`100`，我们必须首先采取`1`，这意味着拿走前两枚硬币总共会产生`101`。 

这些约束提供了有关预期解决方案的重要提示：

 - 桩的数量可以大到`1000`。 
- 所有堆中的硬币总数最多为`2000`。 
-`k`也可以大到`2000`。 

对每种可能的硬币选择进行强力搜索在计算上是不可行的，因为组合的数量呈指数级增长。 然而，相对较小的上限`2000`对于总硬币数量表明基于硬币数量的动态规划方法是可行的。 

一个重要的观察是，对于每一堆，唯一有意义的选择是选择第一个`0`,`1`,`2`, ...,`m`硬币，哪里`m`是该堆的大小。 由于必须从顶部取出硬币，因此每堆硬币只有前缀选择。 

一些边缘情况值得预先考虑。 一种情况是当`k = 1`，我们只需要从所有堆的顶部取出最高的可访问硬币。 另一种情况发生时`k`等于硬币总数，迫使我们拿走所有东西。 当一堆硬币在堆栈深处包含非常大的值时，就会出现一种棘手的情况，需要先取出较小的硬币才能解锁更好的回报。 该问题保证至少有一个有效的解决方案，因为`k <= sum(piles[i].length)`。 

## 方法

 ### 蛮力方法

 暴力解决方案将递归地尝试从每堆中取出所有可能数量的硬币。 

对于每一堆，我们可以决定采取`0`,`1`,`2`，...，直到所有可用的硬币。 然后，我们递归处理剩余的硬币，同时跟踪还有多少硬币可供选择。 

这种方法是正确的，因为它探索了跨堆前缀选择的每种合法组合，并评估每种可能性的总价值。 最终，最大有效总和恰好使用`k`发现硬币。 

然而，这种策略变得太慢了。 假设每一堆都允许多种选择。 递归分支的数量呈指数增长，因为每一堆都引入了多种可能性。 高达`1000`堆积如山，彻底的探索变得不可能。 

### 最佳解决方案的关键见解

 关键的见解是这个问题具有**重叠的子问题**，使其非常适合动态规划。 

在任何时候，我们的决定仅取决于：

 1.我们加工了多少堆。 
2. 我们已经拿走了多少硬币。 

我们可以存储中间结果，而不是重复重新计算最佳答案。 

另一个关键的优化来自**前缀和**。 由于我们只能从一堆硬币的顶部取出硬币，因此唯一相关的值是前缀总数：

 - 采取`0`硬币→价值`0`- 先拿`1`硬币 → 前缀和
 - 先拿`2`硬币 → 前缀和
 - 等等

 这使我们能够快速计算从获取中获得的价值`x`一堆硬币。 

然后我们使用类似于背包问题的动态规划：

 -`dp[c]`表示精确使用可实现的最大值`c`处理一定数量的硬币后。 
- 对于每一堆，我们通过尝试从该堆中获取所有可能数量的硬币来更新 DP 数组。 

这将指数搜索转换为多项式时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) 递归 | 为每一堆尝试所有可能的前缀选择 |
 | 最优动态规划| O(n × k × m) | O(k) | 使用前缀和和背包式 DP |

 这里，`m`代表平均堆大小。 由于硬币总数的边界为`2000`，这种复杂性是实用的。 

## 算法演练

 ### 第 1 步：创建 DP 阵列

 我们维护一个一维动态规划数组：```
dp[c] = maximum value obtainable using exactly c coins
```最初：```
dp[0] = 0
```其他一切都开始于`0`因为我们还没有处理任何堆。 

DP 尺寸为`k + 1`因为我们只关心硬币数量`0`到`k`。 

### 步骤 2：独立处理每一堆

 对于每一堆，我们计算前缀和。 

假设堆是：```
[1, 100, 3]
```其前缀和变为：```
[0, 1, 101, 104]
```这意味着：

 - 服用`0`硬币给`0`- 服用`1`硬币给`1`- 服用`2`硬币给`101`- 服用`3`硬币给`104`我们预先计算这些值，以便每次查找都成为恒定时间。 

### 步骤 3：使用临时 DP 阵列

 对于每一堆，我们创建当前 DP 数组的副本。 

这可以防止覆盖转换期间仍然需要的值。 

如果我们更新了`dp`直接地，我们可能会不小心多次重复使用同一堆硬币。 

### 步骤 4：尝试所有有效的硬币选择

 对于每个目标硬币数量`c`从`1`到`k`，我们尝试采取：```
0, 1, 2, ..., min(c, pile_size)
```当前一堆硬币。 

转移公式变为：```
new_dp[c] =
max(
    new_dp[c],
    dp[c - x] + prefix_sum[x]
)
```在哪里：

-`x`= 从当前堆中取出的硬币
 -`dp[c - x]`= 之前最好的结果
 -`prefix_sum[x]`= 从当前堆获得的价值

 我们评估所有有效的选择并保留最好的一个。 

### 步骤 5：更换 DP 阵列

 处理完一堆后：```
dp = new_dp
```现在`dp[c]`反映了使用处理过的桩的最佳可能答案。 

###第6步：返回最终结果

 最后：```
dp[k]
```包含精确使用可实现的最大值`k`硬币。 

### 为什么它有效

 该算法之所以有效是因为最优子结构。 对于每一堆，我们都会详尽地考虑可以从中取出的每一个有效数量的硬币。 如果服用`x`当前一堆硬币是最优解的一部分，那么剩余的`k - x`硬币还必须在先前处理的硬币堆中形成最佳解决方案。 动态规划保证这些较小的最优答案已经存储在`dp`，因此将它们组合起来总是会产生正确的全局最优值。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxValueOfCoins(self, piles: List[List[int]], k: int) -> int:
        dp = [0] * (k + 1)

        for pile in piles:
            prefix_sums = [0]

            current_sum = 0
            for coin in pile:
                current_sum += coin
                prefix_sums.append(current_sum)

            new_dp = dp[:]

            pile_size = len(pile)

            for coins_taken in range(1, k + 1):
                max_take = min(coins_taken, pile_size)

                for take in range(1, max_take + 1):
                    new_dp[coins_taken] = max(
                        new_dp[coins_taken],
                        dp[coins_taken - take] + prefix_sums[take]
                    )

            dp = new_dp

        return dp[k]
```实现首先初始化一个大小为动态编程的数组`k + 1`。 每个位置都存储了确切数量的所选硬币的最佳可实现价值。 

对于每一堆，我们首先计算前缀和。 这个预处理步骤使我们能够立即确定第一个的总价值`x`那堆硬币。 

DP 阵列的副本创建为`new_dp`。 这很重要，因为当前堆的转换必须仅取决于先前处理的堆的结果。 

然后，我们迭代我们想要最终获得的所有可能数量的硬币，从`1`到`k`。 对于每次计数，我们尝试从当前堆中取出所有可行数量的硬币。 DP 转换更新最大可获得值。 

最后，处理完所有桩后，`dp[k]`包含最优答案。 

## 解决方案```go
func maxValueOfCoins(piles [][]int, k int) int {
	dp := make([]int, k+1)

	for _, pile := range piles {
		prefixSums := []int{0}

		currentSum := 0
		for _, coin := range pile {
			currentSum += coin
			prefixSums = append(prefixSums, currentSum)
		}

		newDP := make([]int, k+1)
		copy(newDP, dp)

		pileSize := len(pile)

		for coinsTaken := 1; coinsTaken <= k; coinsTaken++ {
			maxTake := pileSize
			if maxTake > coinsTaken {
				maxTake = coinsTaken
			}

			for take := 1; take <= maxTake; take++ {
				candidate := dp[coinsTaken-take] + prefixSums[take]

				if candidate > newDP[coinsTaken] {
					newDP[coinsTaken] = candidate
				}
			}
		}

		dp = newDP
	}

	return dp[k]
}
```Go 实现遵循与 Python 相同的动态编程策略。 一个区别是切片处理。 由于 Go 切片是对底层数组的引用，因此我们显式分配一个新的`newDP`使用切片和复制值`copy()`。 

Go 整数在这里是安全的，因为最大可能的答案仍然在整数限制内。 由于硬币的价值最多为`10^5`总硬币数最多为`2000`，最大总和约为`2 × 10^8`，它很适合 Go 的`int`。 

与 Python 列表不同，Go 需要显式边界处理，因此我们手动计算`maxTake`。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k × 总币数) | 每堆都考虑每个可行的硬币数量和前缀选择 |
 | 空间| O(k) | 只维护一维DP数组|

空间复杂度仅为`O(k)`因为我们重用一维 DP 数组而不是维护完整的二维表。

 ## 边缘情况

 ### 边缘案例 1：一堆有价值的硬币

 一个常见的错误是假设我们可以自由选择任何硬币。 考虑：```
[[1, 1, 100]]
k = 1
```答案是`1`， 不是`100`，因为如果不先移除大硬币上方的硬币，就无法访​​问大硬币。 我们的实现仅通过考虑前缀和来正确处理这个问题，这意味着永远不会独立选择更深的硬币。 

### 边缘情况 2：`k`等于硬币总数

 当`k`等于可用硬币的总数，算法没有自由，它必须采取一切。 

例子：```
[[1,2],[3,4]]
k = 4
```答案很简单，就是所有硬币的总和。 由于 DP 会评估每个有效的前缀组合，因此它自然会收敛到完全获取所有桩。 

### 边缘情况 3：许多小堆

 高达`1000`堆，递归方法可能会变得低效或存在堆栈开销的风险。 

例子：```
[[1],[2],[3],[4],...]
```我们的迭代动态规划解决方案仅使用一次处理一堆`O(k)`内存，即使堆的数量非常大，也可以扩展。 

### 边缘情况 4：从一堆硬币中取出零枚硬币

 有时，最佳选择是完全跳过一堆。 

例子：```
[[1,2,3],[100]]
k = 1
```正确答案是`100`。 

我们的实现会自动处理这个问题，因为`new_dp`以副本开始`dp`，隐含地表示从当前一堆硬币中取出零个硬币的选项。
