[LeetCode 第 2279 题](https://leetcode.com/problems/maximum-bags-with-full-capacity-of-rocks/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 问题呈现`n`每个袋子都有规定的最大容量和当前的岩石数量。 输入由两个数组组成：`capacity`和`rocks`， 在哪里`capacity[i]`是岩石袋的最大数量`i`可以容纳，并且`rocks[i]`是当前袋子里有多少块石头。 另外，你会得到一个整数`additionalRocks`，代表您可以在任何袋子中自由分配的岩石。 

目标是在分配这些额外的岩石后最大限度地增加达到满负荷的袋子数量。 输出是一个整数，表示满包的最大数量。 

约束表明潜在的大输入（`n`最多 50,000 个，岩石数量最多 10^9），这排除了对所有分布的暴力枚举。 该问题保证了每个`rocks[i]`小于或等于`capacity[i]`，因此最初没有袋子装满。 

关键的边缘情况包括已经装满的袋子、只需要一块石头来填充的袋子以及数量有限的情况。`additionalRocks`超过所有赤字的总和或为零。 

## 方法

 蛮力方法将涉及尝试所有分布组合`additionalRocks`并检查哪种组合可以使装满的行李数量最大化。 虽然原则上是正确的，但这在计算上是不可行的，因为可能的分布数量与`n`和`additionalRocks`。 

最佳方法的关键观察是填充袋子的顺序很重要，为了最大限度地装满袋子，最好首先填充需要最少石头的袋子。 这种见解导致了一个贪婪的解决方案：计算填充每个袋子所需的岩石数量（`capacity[i] - rocks[i]`），将这些值按升序排序，然后从最小的需求开始使用额外的岩石，直到用完为止。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O( (additionalRocks + n)! / (additionalRocks! * n!) ) | O(n) | 尝试其他岩石的所有分布 |
 | 最优（贪心 + 排序）| O(n log n) | O(n log n) | O(n) | 对赤字进行排序并从最小的赤字开始贪婪地装满袋子 |

 ## 算法演练

 1. 计算每个袋子的不足量，定义为达到满容量所需的岩石数量：`deficit[i] = capacity[i] - rocks[i]`。 
2. 排序`deficit`数组按升序排列。 这使我们能够优先填充需要较少岩石的袋子。 
3. 初始化计数器`fullBags`为零。 这将跟踪达到满载容量的行李数量。 
4. 迭代排序后的内容`deficit`大批。 对于每一项赤字`d`，检查是否剩余`additionalRocks`大于或等于`d`。 如果是，则减去`d`从`additionalRocks`并增加`fullBags`。 如果没有，请打破循环，因为无法再填充更多的袋子。 
5. 返回`fullBags`作为满载行李的最大数量。 

原理：通过始终首先填充需要最少石块的袋子，该算法可以利用有限的额外石块最大限度地增加达到容量的袋子数量。 任何其他订单要么会留下较小的缺口未填补，要么会在需要超过必要数量的袋子上浪费石头。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumBags(self, capacity: List[int], rocks: List[int], additionalRocks: int) -> int:
        deficits = [capacity[i] - rocks[i] for i in range(len(capacity))]
        deficits.sort()
        fullBags = 0
        
        for d in deficits:
            if additionalRocks >= d:
                additionalRocks -= d
                fullBags += 1
            else:
                break
        
        return fullBags
```该代码首先计算所有行李的缺陷，并对它们进行排序，以优先考虑最小的行李。 然后它迭代这些缺陷，使用`additionalRocks`装满尽可能多的袋子。 一旦没有足够的岩石来填充下一个袋子，循环就会停止，并返回结果。 

## 解决方案```go
import "sort"

func maximumBags(capacity []int, rocks []int, additionalRocks int) int {
    n := len(capacity)
    deficits := make([]int, n)
    for i := 0; i < n; i++ {
        deficits[i] = capacity[i] - rocks[i]
    }
    
    sort.Ints(deficits)
    fullBags := 0
    
    for _, d := range deficits {
        if additionalRocks >= d {
            additionalRocks -= d
            fullBags++
        } else {
            break
        }
    }
    
    return fullBags
}
```Go 实现反映了 Python 逻辑。 主要区别是显式切片分配`deficits`并使用`sort.Ints`用于排序。 迭代使用 Go 的范围构造，但贪婪逻辑是相同的。

 ## 边缘情况

 第一个边缘情况是袋子已经满了。 该算法通过计算赤字来解决这个问题； 首先对零的缺陷进行分类，并立即将其计为满袋，而无需使用任何额外的岩石。 

第二个边缘情况是当`additionalRocks`超过所有赤字的总和。 该循环将填补每个袋子的缺口，留下未使用的岩石，这不会影响正确性。 

第三种边缘情况是当`additionalRocks`为零。 该算法仅将已经具有零赤字的袋子正确地计数为已满，忽略需要岩石的袋子，并在遇到非零赤字时立即终止。 

由于其贪婪和排序的赤字方法，这种方法可以无缝地处理这些场景。
