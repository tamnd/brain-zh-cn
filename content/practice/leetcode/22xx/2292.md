[LeetCode 问题 2292](https://leetcode.com/problems/products-with- Three-or-more-orders-in-two-consecutive-years/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个名为`Orders`，其中每一行代表一个购买事件。 每个订单包含一个`order_id`, 一个`product_id`, 购买的`quantity`，以及`purchase_date`。 

目标是识别同时满足两个条件的所有产品：

 1. 该产品一年内至少被订购3次。 
2. 同一产品在上一年或下一年至少被订购过 3 次。 

“连续两年”是关键要求。 这意味着我们并不是在寻找在多个不相关的年份中仅拥有三个订单的产品。 年份必须相差整整一年。 

需要注意的是，问题计算的是订单，而不是数量。 即使单笔订单数量较大，也仅算作一次订单。 因此，`quantity`列与解决问题无关。 

例如，如果产品出现：

 - 2020年3次
 - 2021年3次

 那么它就符合资格，因为 2020 年和 2021 年是连续的年份。 

但是，如果产品出现：

 - 2020年3次
 - 2022年3次

 那么它就不符合条件，因为年份不是连续的。 

预期输出是一个仅包含符合条件的表`product_id`价值观。 输出行的顺序并不重要。 

输入保证`order_id`值是唯一的，因此每一行代表一个不同的订单事件。 由于问题仅询问每年订单数是否至少达到 3，因此我们可以通过以下方式聚合订单：`(product_id, year)`并随后忽略个别订单详细信息。 

需要考虑一些重要的边缘情况：

 - 一种产品可能在一年内有很多订单，但相邻年份的订单少于三个。 
- 一种产品可能在多个连续年份中符合资格。 
- 一种产品可能连续几年恰好有三个订单，这仍然符合资格。 
- 一种产品可能有许多订单分布在非连续年份，这不符合资格。 
- 多个产品可以同时满足条件。 

## 方法

 ### 蛮力方法

 强力解决方案将独立检查每个产品并比较该产品的每一对年份。 

首先，我们将收集每种产品的所有订单，并统计每年发生的订单数量。 然后，对于每个产品，我们将迭代所有年份对并检查是否：

 - 两年都至少有三个订单
 - 年份相差整整一年

 这种方法是正确的，因为它明确地验证了问题所需的条件。 但是，它会执行不必​​要的比较。 如果一个产品有许多不同的年份，那么检查每一个可能的年份就会变得低效。 

例如，如果产品出现在`k`年，比较每一对需要`O(k²)`该产品的时间。 

### 最佳方法

 关键的观察是我们只关心相邻的年份。 没有必要每一年都进行比较。 

相反，我们可以：

 1.统计每个订单的数量`(product_id, year)`一对。 
2. 仅保留数量至少为三的那些对。 
3. 对于每个排位赛`(product_id, year)`，检查是否`(product_id, year + 1)`也存在。 

这将问题转换为使用哈希集或分组聚合的简单查找问题。 

在 SQL 中，这自然是使用以下方式实现的：

 -`GROUP BY`统计每年的订单
 - 比较连续年份的自加入

 这种方法避免了二次比较，并且仅有效地检查必要的相邻年份。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | ---| ---| --- |
 | 蛮力 | O(n + k²) | O(n + k²) | O(k) | 比较每种产品的所有年份对 |
 | 最佳 | O(n) | O(k) | 使用分组计数和直接连续年份查找 |

 这里：

-`n`是订单数量
 -`k`是唯一的数量`(product_id, year)`对

 ## 算法演练

 1. 从每个中提取年份`purchase_date`。 

由于条件基于每年的订单计数，因此我们首先将每个订单日期转换为其相应的年份。 
2. 记录分组依据`(product_id, year)`。 

对于每个产品和年份组合，计算该年发生的订单数量。 
3. 过滤至少具有三阶的组。 

我们只关心产品被订购三次或以上的年份。 任何较小的计数永远无法得出有效的答案。 
4. 创建一个仅包含符合条件的派生表`(product_id, year)`对。 

过滤后，每一行代表产品满足最低订单要求的年份。 
5. 自连接派生表。 

使用以下方法将表与其自身连接起来：

 - 相同`product_id`- 连续年份条件：`year1 + 1 = year2`这直接检查产品是否满足相邻年份的要求。 
6. 返回不同的产品 ID。 

产品可以满足多个连续年份对的条件，但输出应仅包含每个产品一次。 

### 为什么它有效

 该算法之所以有效，是因为它首先确定每年有哪些产品独立满足“三个或更多订单”条件。 之后，只需判断任意两个合格年份是否连续即可。 自加入保证仅返回具有相邻合格年份的产品。 

## Python 解决方案```python
# complete solution here

import pandas as pd

def find_products(orders: pd.DataFrame) -> pd.DataFrame:
    # Extract year from purchase_date
    orders["year"] = pd.to_datetime(orders["purchase_date"]).dt.year

    # Count orders per product per year
    yearly_counts = (
        orders.groupby(["product_id", "year"])
        .size()
        .reset_index(name="order_count")
    )

    # Keep only years with at least 3 orders
    qualified_years = yearly_counts[yearly_counts["order_count"] >= 3]

    # Self join on consecutive years
    merged = qualified_years.merge(
        qualified_years,
        left_on=["product_id", "year"],
        right_on=["product_id", "year"],
        suffixes=("_left", "_right")
    )

    # Filter consecutive years
    result = merged[
        merged["year_right"] == merged["year_left"] + 1
    ]

    # Return distinct product IDs
    return result[["product_id"]].drop_duplicates()
```实现首先从提取年份部分开始`purchase_date`。 这使得该解决方案能够按年度汇总数据。 

接下来，代码按两者对记录进行分组`product_id`和`year`。 这`.size()`操作计算有多少订单属于每个组。 

计算年度计数后，该解决方案会过滤掉订单数少于三的任何组，因为这些年份无法得出有效答案。 

自连接是核心步骤。 它与属于同一产品的合格年份相匹配。 最终过滤器检查第二年是否比第一年正好大一年。 

最后，在返回结果之前删除重复的产品 ID。 

## 解决方案```go
// complete solution here

SELECT DISTINCT t1.product_id
FROM (
    SELECT
        product_id,
        YEAR(purchase_date) AS year,
        COUNT(*) AS order_count
    FROM Orders
    GROUP BY product_id, YEAR(purchase_date)
    HAVING COUNT(*) >= 3
) t1
JOIN (
    SELECT
        product_id,
        YEAR(purchase_date) AS year,
        COUNT(*) AS order_count
    FROM Orders
    GROUP BY product_id, YEAR(purchase_date)
    HAVING COUNT(*) >= 3
) t2
ON t1.product_id = t2.product_id
AND t1.year + 1 = t2.year;
```这个问题是数据库问题，所以“Go解决方案”部分实际上是使用SQL来实现的。 该查询使用两个相同的派生表并将它们连接到：

 - 相同的产品
 - 连续多年

 的`DISTINCT`关键字确保每个合格产品在最终结果中仅出现一次。

 ## 边缘情况

 当一种产品在几年内有许多订单，但没有一个符合资格的年份是连续的时，就会出现一种重要的边缘情况。 例如，某个产品可能在 2019 年有三个订单，在 2021 年有三个订单。仅检查多个合格年份的简单实现可能会错误地包含它。 自加入条件`year + 1`可以防止这个错误。 

另一个极端情况涉及连续每年恰好有三个订单的产品。 一些实现错误地使用`>`而不是`>=`过滤过程中。 这会错误地拒绝有效产品。 该解决方案明确使用`HAVING COUNT(*) >= 3`，确保阈值包含在内。 

当产品在多个连续年份对中合格时，就会出现第三种重要情况。 例如，产品可能具有：

 - 2020年3个订单
 - 2021 年 3 个订单
 - 2022 年 3 个订单

 这会产生两个有效对：

 -`(2020, 2021)`-`(2021, 2022)`没有`DISTINCT`，产品可能会在结果中出现多次。 该解决方案通过在返回最终输出之前删除重复项来正确处理此问题。
