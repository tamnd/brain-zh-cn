 # LeetCode 2274 - 没有特殊楼层的最大连续楼层

 ## 问题理解

 这个问题为我们提供了建筑物中一系列租用的楼层，从`bottom`到`top`，包含在内。 在此范围内，部分楼层被标记为特殊楼层，不能算作普通办公楼层。 

我们的任务是确定不包含任何特殊楼层的连续楼层的最大数量。 

例如，假设爱丽丝租用了楼层`2`通过`9`，特殊楼层是`[4, 6]`。 

有效的非特殊范围变为：

 - 楼层`2`到`3`- 地面`5`- 楼层`7`到`9`在这些范围中，最长的连续段包含`3`楼层，所以答案是`3`。 

重要的细节是，我们正在寻找连续的楼层序列，以避免每个特殊楼层。 

输入约束很大：

 -`special.length`可以达到`10^5`- 楼层数可以大到`10^9`这些约束立即告诉我们，当范围极大时，我们无法单独迭代每个楼层。 尽管特殊楼层的数量是可以管理的，但总楼层数却可能无法管理。 

该问题还保证：

 - 每个特殊楼层都位于`[bottom, top]`- 所有特殊楼层都是独一无二的

 这些保证简化了实现，因为我们不需要处理重复值或无效值。 

一些边缘情况很重要：

 - 每一个租用的楼层可能都是特别的，产生的答案是`0`- 第一个特殊楼层之前可能有很长的有效范围
 - 最后一个特殊楼层之后可能会有很长的有效范围
 - 的`special`数组可能未排序

 如果简单的实现仅检查特殊楼层之间的间隙，则很容易错过开始或结束段。 

## 方法

 ### 蛮力方法

 一个简单的方法是遍历每个楼层`bottom`到`top`并检查是否特殊。 

我们可以将所有特殊楼层存储在哈希集中`O(1)`会员资格检查。 然后我们会逐层扫描，维持当前连续非特殊楼层的连续扫描，并在遇到特殊楼层时更新最大连续扫描。 

这种方法是正确的，因为它明确地检查每个租用的楼层并直接跟踪连续的有效段。 

然而，对于给定的约束来说它太慢了。 楼层总数可以大到：$$10^9$$迭代十亿层是不可行的。 

### 最佳方法

 关键的观察结果是，只有特殊楼层的位置才重要。 

我们可以对特殊楼层进行排序并计算它们之间的间隙，而不是单独检查每个楼层。 

假设排序后的特殊楼层为：$$[s_1, s_2, s_3, \dots]$$那么有效的连续范围是：

 - 来自`bottom`到`s1 - 1`- 连续特殊楼层之间
 - 来自`lastSpecial + 1`到`top`两个连续特殊楼层之间的间隙大小`a`和`b`是：$$b - a - 1$$因为两个端点本身都很特殊，不能包含在内。 

通过检查所有这些间隙，我们可以有效地确定最大连续序列。 

排序在运行时占主导地位，使得该解决方案适用于`10^5`元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(顶部 - 底部 + 1) | O(n) | 单独扫描每个楼层 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(log n) 取决于排序 | 对特殊楼层进行排序并计算间隙 |

 ## 算法演练

 1. 排序`special`数组按升序排列。 

排序使我们能够从左到右处理特殊地板并正确测量它们之间的间隙。 
2. 计算第一个特殊楼层之前的间隙。 

第一个特殊楼层之前的连续非特殊楼层为：$$special[0] - bottom$$因为第一特殊楼层本身是不能算的。 
3. 用第一个间隙初始化答案。 

这确保我们正确处理最长段出现在开头的情况。 
4. 迭代相邻的特殊楼层对。 

对于每对：$$special[i - 1], special[i]$$它们之间的有效楼层数为：$$special[i] - special[i - 1] - 1$$如果此差距较大，则更新最大答案。 
5. 计算最后一个特殊楼层之后的间隙。 

最后一个特殊楼层之后的有效连续楼层为：$$top - special[-1]$$6. 返回找到的最大间隙。 

### 为什么它有效

 排序后，每个特殊楼层将租赁楼层划分为独立的区间。 任何有效的连续段必须位于以下任一位置：

 - 第一层特殊楼层之前
 - 两个连续的特殊楼层之间
 - 最后一个特殊楼层之后

 该算法仅检查所有三种可能性一次。 由于每个可能的有效段都属于这些间隔之一，因此计算出的最大间隙保证是正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxConsecutive(self, bottom: int, top: int, special: List[int]) -> int:
        special.sort()

        max_consecutive = special[0] - bottom

        for i in range(1, len(special)):
            gap = special[i] - special[i - 1] - 1
            max_consecutive = max(max_consecutive, gap)

        max_consecutive = max(max_consecutive, top - special[-1])

        return max_consecutive
```实现首先对`special`以便可以正确测量连续的间隙。 

变量`max_consecutive`使用第一个特殊楼层之前的间隙进行初始化。 这处理了最长段开始于的可能性`bottom`。 

该循环处理每对相邻的特殊楼层。 对于每一对，我们使用以下方法严格计算它们之间的楼层数：```python
special[i] - special[i - 1] - 1
```减法为`1`是必要的，因为两个端点都是特殊楼层，无法包含在内。 

最后，该实现检查最后一个特殊楼层之后的尾随段并返回遇到的最大间隙。 

## 解决方案```go
package main

import "sort"

func maxConsecutive(bottom int, top int, special []int) int {
	sort.Ints(special)

	maxConsecutive := special[0] - bottom

	for i := 1; i < len(special); i++ {
		gap := special[i] - special[i-1] - 1

		if gap > maxConsecutive {
			maxConsecutive = gap
		}
	}

	lastGap := top - special[len(special)-1]

	if lastGap > maxConsecutive {
		maxConsecutive = lastGap
	}

	return maxConsecutive
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于 Go 需要显式排序`sort.Ints`。 由于 Go 没有提供内置的`max`整数函数，比较是手动处理的`if`声明。 

这些约束保证所有值都符合 Go 的标准`int`类型。

 ## 边缘情况

 当每个租用的楼层都很特殊时，就会出现一种重要的边缘情况。 在这种情况下，根本不存在有效的非特殊楼层，因此正确答案是`0`。 有缺陷的实现可能会意外返回负间隙或无法正确处理零长度间隔。 此实现可以自然地处理这种情况，因为每个计算的间隙都变为零。 

当最大有效段出现在第一个特殊楼层之前时，会出现另一个关键边缘情况。 例如：```
bottom = 1
top = 10
special = [8]
```正确答案是`7`，对应楼层`1`通过`7`。 仅检查特殊楼层之间间隙的实现将完全忽略这一点。 该解决方案在处理内部间隙之前显式计算前缀间隙。 

当最大的段出现在最后一个特殊楼层之后时，也会出现类似的问题。 例如：```
bottom = 10
top = 20
special = [11, 12]
```最长的一段来自`13`到`20`。 该实现通过在循环后单独计算后缀间隙来正确处理此问题。 

另一个微妙的边缘情况涉及未排序的输入。 由于该问题并不能保证`special`已排序，不排序直接计算间隙会产生错误的结果。 该实现通过在进行任何计算之前对数组进行排序来避免此问题。
