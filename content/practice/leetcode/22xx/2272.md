[LeetCode 问题 2272](https://leetcode.com/problems/substring-with-largest-variance/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、动态规划、枚举

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到给定字符串的所有子字符串之间的最大可能方差。 该字符串仅包含小写英文字母，子字符串的方差定义为该子字符串中同时出现的任意两个字符的计数之间的最大差异。 

重要的细节是要比较的两个字符必须都存在于子字符串中。 例如，如果一个子字符串包含四个`b`人物和一个`a`字符，则方差为`4 - 1 = 3`。 但是，如果子字符串仅包含`b`字符，其方差为`0`，因为没有第二个字符可供比较。 

输入是单个字符串`s`长度可达`10^4`。 预期输出是一个整数，表示每个可能的子串之间的最大方差。 

一种天真的解释可能会建议检查每个子字符串并计算每个子字符串的字符频率。 由于有`O(n^2)`子串并且每个子串可能需要频率分析，这很快就会变得太慢`n = 10^4`。 

一些边缘情况很重要：

 - 所有字符都是唯一的字符串，例如`"abcde"`，总是产生方差`0`。 
- 仅具有一个不同字符的字符串也会产生方差`0`。 
- 最佳子串可能不包含全局最频繁的字符。 
- 字符的顺序很重要，因为我们处理的是子字符串，而不是子序列。 
- 方差的有效子字符串必须至少包含两个所选字符一次。 

主要挑战是有效地找到每对字符的最佳子字符串。 

## 方法

 ### 蛮力方法

 蛮力解决方案考虑了每个可能的子串`s`。 对于每个子字符串，我们计算所有字符的频率，并计算同时出现的任意两个字符计数之间的最大差异。 

有`O(n^2)`子串。 每个子串的计算频率最多可能需要`O(26)`如果使用前缀和，或者`O(n)`无需预处理。 即使进行了优化，总的复杂性也会变得太大。 

这种方法是正确的，因为它显式检查每个子字符串并直接计算所需的方差。 然而，对于长度的字符串来说这是不切实际的`10^4`。 

### 最佳方法

 关键的见解是方差一次仅取决于两个字符。 

假设我们选择两个角色：

 -`major`, 出现频率较高的字符
 -`minor`，出现频率较低的字符

 对于包含这两个字符的子字符串，方差变为：```
count(major) - count(minor)
```这类似于 Kadane 算法解决的经典最大子数组问题。 

我们可以将字符串转换为值：

 -`+1`为了`major`-`-1`为了`minor`- 忽略所有其他字符

 现在我们想要包含至少一个的最大子数组和`minor`。 

棘手的部分是确保子字符串包含这两个字符。 我们不能允许子字符串仅包含`major`特点。 

我们迭代所有有序的不同字符对。 由于只有 26 个小写字母，因此最多给出`26 * 26 = 676`成对，这是可以管理的。 

对于每一对，我们对字符串运行修改后的 Kadane 扫描。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² × 26) | O(26) | 枚举每个子串并计算频率 |

 ## 算法演练

 ### 步骤 1：迭代所有有序字符对

 我们考虑每一个订购的对`(major, minor)`两个字符不同的地方。 

顺序很重要，因为方差是有方向的：```
count(major) - count(minor)
```子串最大化`a - b`与最大化不同`b - a`。 

### 步骤 2：初始化 Kadane 风格的变量

 对于每对：

 -`major_count`跟踪出现的情况`major`-`minor_count`跟踪出现的情况`minor`我们从左到右扫描字符串。 

### 步骤 3：忽略不相关的字符

 如果当前字符既不是`major`也不`minor`，它不会影响这对的方差，所以我们跳过它。 

### 步骤 4：更新计数

 当我们遇到：

 -`major`, 增量`major_count`-`minor`, 增量`minor_count`当前候选方差变为：```
major_count - minor_count
```### 步骤 5：仅当两个字符都存在时才更新答案

 有效的子串必须至少包含一个`minor`。 

因此，我们仅在以下情况下更新全局答案：```
minor_count > 0
```### 第6步：当平衡变得不利时重置

 如果：```
major_count < minor_count
```那么当前的子字符串对于将来的扩展是有害的。 

这正是 Kadane 原理。 任何未来的子串在这一点之后重新开始都会表现得更好。 

所以我们重置：```
major_count = 0
minor_count = 0
```### 步骤 7：处理未来的次要角色

 有一个微妙的问题。 

假设我们在看到未成年人多于专业人后立即重置。 稍后我们可能会失去形成有效子串的可能性。 

为了解决这个问题，我们跟踪是否有额外的`minor`字符保留在字符串的前面。 我们只会重置，如果另一个`minor`以后依然存在。 

### 为什么它有效

 对于每个有序字符对，该算法有效地计算最大子数组总和，其中：

 -`major`贡献`+1`-`minor`贡献`-1`重置条件遵循与 Kadane 算法相同的正确性参数。 一旦运行余额变为负数，继续当前子串对未来的结果无济于事。 

通过检查所有有序字符对，我们保证考虑每种可能的方差配置。 

## Python 解决方案```python
class Solution:
    def largestVariance(self, s: str) -> int:
        answer = 0
        
        for major in range(26):
            for minor in range(26):
                if major == minor:
                    continue
                
                major_char = chr(ord('a') + major)
                minor_char = chr(ord('a') + minor)
                
                remaining_minor = s.count(minor_char)
                
                major_count = 0
                minor_count = 0
                
                for ch in s:
                    if ch != major_char and ch != minor_char:
                        continue
                    
                    if ch == major_char:
                        major_count += 1
                    else:
                        minor_count += 1
                        remaining_minor -= 1
                    
                    if minor_count > 0:
                        answer = max(answer, major_count - minor_count)
                    
                    if major_count < minor_count and remaining_minor > 0:
                        major_count = 0
                        minor_count = 0
        
        return answer
```实现直接遵循算法。 

外部两个循环枚举所有有序字符对。 由于只允许使用小写英文字母，因此对的总数很小且固定。 

对于每一对，我们使用 Kadane 风格的运行窗口来维护`major_count`和`minor_count`。 

与当前对无关的字符将被忽略，因为它们不会影响所选字符之间的方差。 

变量`remaining_minor`对于正确性很重要。 它追踪有多少未来`minor`人物仍然存在。 如果当前余额变为负值并且未来的次要字符仍然存在，我们将重置运行计数。 否则，我们保留当前计数，因为这可能是包含 a 的唯一有效子字符串`minor`。 

答案仅在以下情况下更新`minor_count > 0`，确保两个字符都存在于子字符串中。 

## 解决方案```go
func largestVariance(s string) int {
    answer := 0

    for major := 0; major < 26; major++ {
        for minor := 0; minor < 26; minor++ {
            if major == minor {
                continue
            }

            majorChar := byte('a' + major)
            minorChar := byte('a' + minor)

            remainingMinor := 0
            for i := 0; i < len(s); i++ {
                if s[i] == minorChar {
                    remainingMinor++
                }
            }

            majorCount := 0
            minorCount := 0

            for i := 0; i < len(s); i++ {
                ch := s[i]

                if ch != majorChar && ch != minorChar {
                    continue
                }

                if ch == majorChar {
                    majorCount++
                } else {
                    minorCount++
                    remainingMinor--
                }

                if minorCount > 0 {
                    variance := majorCount - minorCount
                    if variance > answer {
                        answer = variance
                    }
                }

                if majorCount < minorCount && remainingMinor > 0 {
                    majorCount = 0
                    minorCount = 0
                }
            }
        }
    }

    return answer
}
```Go 的实现与 Python 版本非常相似。 

由于 Go 字符串是 ASCII 字符的字节切片，因此我们使用以下方式访问字符`s[i]`直接作为`byte`价值观。 这是有效的，因为该问题仅保证小写英文字母。 

与 Python 不同，Go 不提供内置的`max`函数用于整数，因此比较是手动编写的。 

不需要对 nil 或空值进行特殊处理，因为约束保证至少有一个字符。

 ## 边缘情况

 ### 仅具有一个不同字符的字符串

 考虑：```
"aaaaaa"
```幼稚的实现可能会错误地返回计数`a`因为它出现了很多次。 但是，方差要求子字符串中存在两个字符。 

该实现可以正确处理此问题，因为只有在以下情况下才会更新答案`minor_count > 0`。 

### 所有字符都是唯一的字符串

 考虑：```
"abcdef"
```每个包含两个字符的子字符串具有相同的计数：```
1 - 1 = 0
```该算法仍然扫描所有字符对，但没有任何对产生正方差。 最终答案依然存在`0`。 

### 当运行余额变为负数时重置逻辑

 考虑：```
"bbaaab"
```幼稚的 Kadane 重置可能会过于激进地丢弃未来有用的子串。 

该实现使用以下方法避免了这个问题`remaining_minor`。 我们仅在另一个时重置`minor`字符稍后仍存在于字符串中。 这保留了有效的子字符串，这些子字符串可能在扫描结束时变得最佳。
