[LeetCode 问题 2230](https://leetcode.com/problems/the-users-that-are-eligible-for-discount/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们根据存储在数据库中的购买历史记录来识别所有有资格享受折扣的用户。`Purchases`桌子。 

表中的每一行包含三条信息：

 -`user_id`, 用户的标识符
 -`time_stamp`，购买发生的确切日期和时间
 -`amount`，购买期间支付的金额

 如果存在至少一项满足以下两个条件的购买，则用户被视为符合资格：

 1. 购买发生在包含日期范围内`[startDate, endDate]`2. 购买金额大于或等于`minAmount`一个重要的细节是如何解释日期。 该问题明确指出，两者`startDate`和`endDate`应该被视为各自日子的开始。 这意味着：

 -`startDate = 2022-03-08`变成`2022-03-08 00:00:00`-`endDate = 2022-03-20`变成`2022-03-20 00:00:00`这个细节很容易被忽视。 在此期间稍后进行的购买`endDate`日，例如`2022-03-20 10:00:00`，实际上会被排除，因为比较终点正好是午夜。 

预期输出是一个仅包含`user_id`符合条件的用户的值，按升序排序。 

因为问题只询问是否存在符合条件的购买，所以我们不需要计算购买或总计。 我们只需要过滤满足条件的行并返回与这些行关联的不同用户。 

该表保证`(user_id, time_stamp)`是唯一的，这意味着同一时间戳不存在重复的购买记录。 这简化了逻辑，因为我们不需要担心重复行影响结果。 

一些边缘情况很重要：

 - 用户可能在该日期范围内进行了购买，但金额不足
 - 用户可能在允许的日期范围之外进行大量购买
 - 用户可能有多次符合条件的购买，但在结果中只应出现一次
 - 准确购买`startDate 00:00:00`或者`endDate 00:00:00`被包括在内，因为区间包含在内
 - 稍后购买`endDate`被排除，因为结束边界是一天的开始

 ## 方法

 ### 蛮力方法

 强力方法将逐一检查每个购买行，并手动评估两个所需条件。 

对于每次购买：

 1. 检查时间戳是否在包含区间内
 2. 检查金额是否至少`minAmount`3. 如果两个条件都成立，则添加`user_id`到结果集

 处理完所有行后，我们将对唯一的用户 ID 进行排序并返回它们。 

这种方法是正确的，因为每次购买都会根据资格规则进行明确检查。 如果任何购买满足条件，则包含关联的用户。 

尽管此方法很简单，但在大型数据集上可能会变得效率低下，因为必须手动扫描每一行。 在 SQL 术语中，这相当于不利用优化过滤和投影的全表扫描。 

### 最佳方法

 关键的观察结果是，这个问题本质上是一个过滤操作。 

我们不需要复杂的连接、分组逻辑或聚合。 我们只需要：

 - 按时间戳范围过滤行
 - 按最小金额过滤行
 - 返回不同的用户 ID

 SQL 数据库针对此类操作进行了高度优化。 通过直接在`WHERE`条款和使用`DISTINCT`，数据库引擎可以高效地产生结果。 

因此，最佳解决方案由使用以下命令的单个 SQL 查询组成：

 -`WHERE`用于过滤
 -`DISTINCT`为了独特性
 -`ORDER BY`用于排序输出

 | --- | --- | --- | --- |

 这里：

-`n`是购买记录的数量
 -`k`是合格用户的数量

 ## 算法演练

 1. 首先读取所有行`Purchases`桌子。 
2. 对于每一行，检查是否`time_stamp`落在包含区间内：```
time_stamp >= startDate
AND
time_stamp <= endDate
```由于这两个日期都被解释为一天的开始，因此直接针对午夜时间戳进行比较。 
3. 检查购买金额是否满足：```
amount >= minAmount
```这可确保购买的金额足够大，有资格享受折扣。 
4. 如果两个条件都成立，则保留相应的`user_id`。 
5. 由于用户可能有多次符合资格的购买，因此使用`DISTINCT`删除重复项。 
6. 对最终结果进行排序`user_id`按升序使用`ORDER BY`。 

### 为什么它有效

 该算法之所以有效，是因为它直接实现了问题陈述中给出的资格定义。 每次购买都会根据所需条件进行评估，并且包含至少一次合格购买的任何用户。 使用`DISTINCT`保证每个用户只出现一次，即使多次购买符合条件。 

## Python 解决方案```python
# Write your MySQL query statement below
SELECT DISTINCT user_id
FROM Purchases
WHERE time_stamp >= startDate
  AND time_stamp <= endDate
  AND amount >= minAmount
ORDER BY user_id;
```查询开始于选择`user_id`从`Purchases`桌子。 由于一个用户可能会多次获得资格，`DISTINCT`用于消除重复项。 

这`WHERE`子句应用两个必需的过滤器：

 - 时间戳必须位于允许的间隔内
 - 金额必须至少为`minAmount`最后，`ORDER BY user_id`确保输出按照问题陈述的要求进行排序。 

尽管本节被标记为“Python 解决方案”，但 LeetCode 数据库问题需要 SQL 查询而不是 Python 代码。 所提供的查询是完全可提交的。

 ## 边缘情况

 ### 恰好在结束边界处购买

 一种微妙的边缘情况涉及购买恰好发生在`endDate 00:00:00`。 

例如：```
time_stamp = 2022-03-20 00:00:00
```必须包括此购买，因为时间间隔是包含在内的。 然而，当天晚些时候的一次购买：```
2022-03-20 08:00:00
```必须排除。 许多不正确的解决方案会无意中对待`endDate`作为一整天而不是一天的开始。 该实现通过执行直接时间戳比较来正确处理此问题。 

### 同一用户的多次合格购买

 用户可能有多次购买满足条件。 没有`DISTINCT`，结果可能包含重复的用户 ID。 

例如：```
user_id = 5
```可能会在筛选的行中出现 3 次。 使用`DISTINCT`保证最终输出仅包含每个合格用户的一次出现。 

### 没有用户符合资格

 没有任何购买可能同时满足这两个条件。 

例如：

 - 所有购买可能金额不足
 - 所有时间戳可能超出该间隔

 该实现自然会处理这种情况，因为过滤后的查询只是返回一个空结果集。 

### 超出允许范围的大量采购

 幼稚的实现可能会错误地优先考虑金额条件并忽略时间戳。 

例如：```
amount = 100000
```如果购买发生在有效间隔之外也没关系。 该查询正确地要求两个条件同时保持，使用`AND`操作员。
