 # LeetCode 2211 - 计算道路上的碰撞次数

 ## 问题理解

 该问题描述了一条一维道路，其中包含从左到右排列的汽车。 每辆车都有以下三种可能状态之一：

 -`'L'`，意味着汽车向左移动
 -`'R'`，意味着汽车向右移动
 -`'S'`，意味着汽车保持静止

 所有移动的汽车都以相同的速度行驶。 每当汽车相遇时，就会根据特定规则发生碰撞：

 - 左侧行驶的汽车和右侧行驶的汽车相撞会产生影响`2`由于两辆行驶中的汽车都停下来而发生碰撞。 
- 移动的汽车与静止的汽车相撞会产生影响`1`碰撞，因为只有一辆行驶中的汽车停下来。 

碰撞后，每辆涉事车辆都会永远静止。 

目标是计算所有运动解决后最终发生的碰撞总数。 

输入是一个字符串`directions`，其中每个字符代表一辆车的方向或状态。 输出是一个表示碰撞总数的整数。 

约束条件很重要：

 - 长度可以大到`10^5`- 这排除了随着时间的推移重复更新位置的昂贵模拟方法
 - 我们需要一个线性或接近线性的解决方案

 一个关键的观察结果是，汽车只沿着一条线移动，每次碰撞最终都会产生静止的汽车，从而引发额外的碰撞。 

一些边缘情况很重要：

 - 一开始向左行驶的汽车可以离开道路而不会发生碰撞
 - 在最后端向右移动的汽车也可以在不发生碰撞的情况下离开
 - 连续静止的汽车不应增加碰撞
 - 向右移动的汽车链最终都可能与静止的障碍物相撞
 - 在初始碰撞创建静止汽车后，多次碰撞可能会级联

 ## 方法

 ### 蛮力方法

 直接模拟方法可以对每辆车随时间的运动进行建模。 在每个时间步，我们都会更新位置，检测碰撞，将碰撞的汽车转换为静止的汽车，然后继续，直到不再有运动为止。 

这种方法是正确的，因为它确实遵循问题陈述。 然而，对于给定的限制来说，它太慢了。 由于汽车在发生碰撞之前可能需要进行多次更新，因此重复模拟运动可能会变得二次或更糟。 

例如，与`10^5`汽车，重复扫描和更新位置会超出时间限制。 

### 最佳方法

 关键的见解是我们实际上并不需要随着时间的推移模拟头寸。 

汽车仅在两种情况下避免碰撞：

 - 最左边左侧行驶的车辆逃离道路
 - 最右边行驶的汽车逃离道路

 所有其他移动的汽车最终都会相撞。 

我们可以考虑最终的稳定配置而不是模拟运动。 

如果我们删除：

 - 全部领先`'L'`汽车
 - 所有尾随`'R'`汽车

 那么剩下的每辆移动的汽车都必须在某个时刻发生碰撞。 

在这个修剪过的部分内：

 - 每个`'L'`造成一次碰撞
 - 每个`'R'`造成一次碰撞
 -`'S'`无贡献

 因此，答案就是有效碰撞区域内非静止汽车的数量。 

这给出了一个非常干净的线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(n) | 逐步模拟汽车运动|
 | 最佳 | O(n) | O(1) | O(1) | 修剪逃逸车辆，计算剩余移动车辆 |

 ## 算法演练

 1. 从字符串的左侧开始，跳过每一个前导`'L'`。 

这些汽车永远向左行驶，永远不会遇到另一辆车，因为它们的左边没有任何东西。 
2. 从字符串的右侧开始并跳过所有尾随`'R'`。 

这些汽车永远向右行驶，永远不会遇到另一辆车，因为它们的右侧没有任何东西。 
3. 修剪两侧后，剩余的每辆移动的汽车最终都必须发生碰撞。 

发生这种情况是因为：

 - 剩余`'R'`最终会撞到静止的汽车或向左行驶的汽车
 - 剩余`'L'`最终一定会遇到左边的东西
 4. 迭代剩余的子字符串。 
5. 计算每个不是的字符`'S'`。 

每辆移动的汽车恰好产生一次碰撞：

 -`'R'`最终在碰撞后停止
 -`'L'`最终在碰撞后停止
 6. 返回总计数。 

### 为什么它有效

 关键的不变量是，只有逃离道路的汽车才能避免碰撞。 领先的左行驶车辆和尾随的右行驶车辆是唯一逃脱的车辆。 所有其他移动的汽车都被困在其他汽车或静止障碍物之间，因此它最终必须恰好碰撞一次才能静止。 因此，计算修剪区域中所有非静止汽车的数量即可得出准确的碰撞次数。 

## Python 解决方案```python
class Solution:
    def countCollisions(self, directions: str) -> int:
        n = len(directions)

        left = 0
        while left < n and directions[left] == 'L':
            left += 1

        right = n - 1
        while right >= 0 and directions[right] == 'R':
            right -= 1

        collisions = 0

        for i in range(left, right + 1):
            if directions[i] != 'S':
                collisions += 1

        return collisions
```该实现首先找到左侧第一辆无法自由逃脱的汽车。 每一个领导`'L'`被跳过，因为这些汽车离开道路而没有交互。 

接下来，代码从右侧扫描并跳过所有尾随`'R'`汽车也出于同样的原因。 

一旦识别出有效的碰撞区域，算法就会简单地计算该范围内每辆移动的汽车。 任何`'L'`或者`'R'`在该区域内最终必须因碰撞而停止，因此每个区域都为最终答案贡献了 1。 

该解决方案仅使用几个整数变量，并且从每一侧最多扫描一次字符串，使其非常高效。 

## 解决方案```go
func countCollisions(directions string) int {
	n := len(directions)

	left := 0
	for left < n && directions[left] == 'L' {
		left++
	}

	right := n - 1
	for right >= 0 && directions[right] == 'R' {
		right--
	}

	collisions := 0

	for i := left; i <= right; i++ {
		if directions[i] != 'S' {
			collisions++
		}
	}

	return collisions
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 字符串是字节索引的并且输入仅包含 ASCII 字符 (`'L'`,`'R'`,`'S'`），直接索引安全高效。 

不需要对整数溢出进行特殊处理，因为最大碰撞次数最多为`10^5`，它很容易适合 Go 的内部`int`类型。

 | 时间 | O(n) | 每个字符最多被扫描一次 |

 ## 边缘情况

 ### 引导左行驶的汽车

 像这样的序列`"LLLR"`很容易混淆幼稚的模拟。 左侧行驶的汽车永远不会发生碰撞，因为它们左侧没有汽车。 只有决赛`'R'`存在，并且它也逃逸。 该实现通过修剪所有前导来处理这个问题`'L'`在计算碰撞次数之前的汽车。 

### 尾随右行驶的汽车

 像这样的序列`"SRRR"`包含永远离开道路的正确行驶的汽车。 幼稚的计数方法可能会错误地假设它们最终会发生碰撞。 该算法正确地删除了所有尾随`'R'`处理碰撞区域之前的汽车。 

### 整个字符串没有冲突

 输入如`"LLRR"`或者`"SSSS"`很重要，因为根本不会发生碰撞。 修剪掉逃逸的汽车后，有效区域变空或仅包含静止的汽车。 执行自然返回`0`在这些情况下。 

### 初始碰撞后的连锁反应

 类似的情况`"RRRL"`很棘手，因为第一次碰撞会产生一个静止的障碍物，导致其后面发生额外的碰撞。 幼稚的实施可能只计算第一次影响。 最佳洞察力通过认识到被困在中间区域的每辆移动汽车最终都会造成一次碰撞，从而完全避免模拟。
