[LeetCode 问题 2299](https://leetcode.com/problems/strong-password-checker-ii/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的密码字符串是否满足一组安全要求。 我们得到一个字符串，`password`，我们必须返回`true`如果满足每个条件，否则返回`false`。 

仅当满足以下所有条件时，密码才被视为强密码：

 - 长度至少为 8 个字符。 
- 至少有一个小写英文字母。 
- 至少有一个大写英文字母。 
- 至少有一位数字。 
- 精确集合中至少有一个特殊字符`"!@#$%^&*()-+"`。 
- 没有两个相邻的字符是相同的。 

输入大小非常小，因为最大密码长度仅为 100。这意味着性能不是传统意义上的问题，即使效率较低的解决方案也可以在限制内舒适地工作。 然而，目标仍然是设计一个干净且最佳的解决方案。 

最重要的细节是必须同时检查所有条件。 即使缺少一项要求也会导致密码无效。 

尽早考虑几个边缘情况很重要：

 - 少于 8 个字符的密码应立即失败。 
- 相邻的重复字符可以出现在字符串中的任何位置，包括特殊字符，例如`"++"`或类似数字`"11"`。 
- 密码可能包含所有必需的字符类型，但由于相邻字符重复而仍然失败。 
- 如果满足所有其他条件，则恰好 8 个字符的密码仍应通过。 
- 有效特殊字符集受到限制。 仅字符来自`"!@#$%^&*()-+"`数数。 

## 方法

 ### 蛮力方法

 暴力式解决方案将单独扫描字符串多次。 一次可以检查小写字母，另一次可以检查大写字母，另一次可以检查数字，另一次可以检查特殊字符，还有另一次可以检查相邻的重复项。 

这种方法很简单，因为每个条件都是独立的。 通过重复迭代字符串并一次检查一项要求，我们最终可以确定密码是否有效。 

该解决方案是正确的，因为每条规则都经过明确验证。 然而，它的效率很低，因为不必要地多次遍历字符串。 尽管约束足够小，这种低效率实际上并不重要，但从设计角度来看仍然不理想。 

### 最佳方法

 关键的观察结果是，在单次密码遍历期间可以检查每个条件。 

当我们迭代每个字符时：

 - 我们可以追踪是否看到了小写字母。 
- 我们可以追踪是否看到了大写字母。 
- 我们可以追踪是否看到了数字。 
- 我们可以追踪是否看到了特殊角色。 
- 我们可以将当前字符与前一个字符进行比较以检测相邻的重复项。 

通过维护一些布尔标志，我们可以一次性验证所有条件。 这减少了不必要的重复工作并产生干净、高效的实施。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(5n) | O(5n) | O(1) | O(1) | 多次传递字符串以进行不同的检查 |
 | 最佳| O(n) | O(1) | O(1) | 单次遍历同时检查所有条件 |

 ## 算法演练

 1、首先检查密码长度是否至少为8，如果长度小于8，则立即返回`false`因为密码不可能太强。 
2. 创建一个包含所有允许的特殊字符的集合。 集合很有用，因为成员资格检查非常快并且代码变得更清晰。 
3. 初始化四个布尔变量：

 -`has_lower`-`has_upper`-`has_digit`-`has_special`这些变量跟踪是否已遇到每个所需类别。 
4. 逐个字符遍历密码字符串。 
5. 对于每个角色：

 - 如果是小写，则设置`has_lower = True`。 
- 如果是大写，则设置`has_upper = True`。 
- 如果是数字，则设置`has_digit = True`。 
- 如果属于特殊字符集，则设置`has_special = True`。 
6. 迭代时，还将当前字符与前一个字符进行比较。 如果相等则立即返回`false`因为不允许相邻的重复字符。 
7. 循环完成后，返回所有四个布尔标志的逻辑与。 仅当满足每个类别要求时，密码才有效。 

### 为什么它有效

 该算法之所以有效，是因为在遍历过程中每个密码规则都被检查一次。 布尔标志保证每个所需的字符类别出现在密码中的某处，而相邻比较保证没有连续的字符是相同的。 由于该算法会立即拒绝无效密码并仅在所有条件成立时才接受，因此结果始终是正确的。 

## Python 解决方案```python
class Solution:
    def strongPasswordCheckerII(self, password: str) -> bool:
        if len(password) < 8:
            return False

        special_characters = set("!@#$%^&*()-+")

        has_lower = False
        has_upper = False
        has_digit = False
        has_special = False

        for index, char in enumerate(password):
            if index > 0 and password[index] == password[index - 1]:
                return False

            if char.islower():
                has_lower = True
            elif char.isupper():
                has_upper = True
            elif char.isdigit():
                has_digit = True

            if char in special_characters:
                has_special = True

        return (
            has_lower
            and has_upper
            and has_digit
            and has_special
        )
```实施从长度检查开始，因为短于 8 个字符的密码会自动失败。 

集合用于特殊字符，因为检查集合中的成员资格既高效又富有表现力。 

四个布尔标志跟踪每个所需类别是否已出现。 在遍历期间，将当前字符与前一个字符进行比较，以立即检测相邻的重复项。 

字符分类使用 Python 字符串辅助方法：

 -`islower()`检查小写字母。 
-`isupper()`检查大写字母。 
-`isdigit()`检查数字。 

最后，函数返回`True`仅当所有必需的条件都得到满足时。 

## 解决方案```go
func strongPasswordCheckerII(password string) bool {
	if len(password) < 8 {
		return false
	}

	specialCharacters := map[rune]bool{
		'!': true,
		'@': true,
		'#': true,
		'$': true,
		'%': true,
		'^': true,
		'&': true,
		'*': true,
		'(': true,
		')': true,
		'-': true,
		'+': true,
	}

	hasLower := false
	hasUpper := false
	hasDigit := false
	hasSpecial := false

	for i, ch := range password {
		if i > 0 && rune(password[i]) == rune(password[i-1]) {
			return false
		}

		if ch >= 'a' && ch <= 'z' {
			hasLower = true
		} else if ch >= 'A' && ch <= 'Z' {
			hasUpper = true
		} else if ch >= '0' && ch <= '9' {
			hasDigit = true
		}

		if specialCharacters[ch] {
			hasSpecial = true
		}
	}

	return hasLower && hasUpper && hasDigit && hasSpecial
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 由于 Go 没有提供像`islower()`或者`isdigit()`，字符分类是使用 ASCII 范围比较来执行的。 

一个`map[rune]bool`用于存储允许的特殊字符。 这提供了类似于 Python 集的恒定时间成员资格检查。 

Go 字符串是 UTF-8 编码的，但这个问题只包含 ASCII 字符，因此在这里对字符串进行索引是安全的。

 ## 边缘情况

 一种重要的边缘情况是长度恰好为 8 个字符的密码。 很容易意外地编写需要超过 8 个而不是至少 8 个的代码。实现正确检查`len(password) < 8`，这意味着接受长度 8。 

另一个重要的边缘情况是重复相邻的特殊字符，例如`"Aa1!!abc"`。 某些实现仅检查重复的字母字符，但该规则适用于每种字符类型。 该解决方案直接比较原始字符，因此无论它们是字母、数字还是符号，都会检测到重复项。 

第三种边缘情况是密码包含不受支持的符号。 该问题保证输入仅包含有效的允许字符，但实现仍然仅针对显式允许集安全地检查特殊字符。 这确保只有所需的特殊字符才算满足条件。 

最后一个微妙的边缘情况是，字符串中的所有要求都已满足，但相邻的重复项稍后出现。 该实现继续扫描整个密码，如果发现任何重复对，则立即拒绝。 即使大多数条件已经满足，这也保证了正确性。
