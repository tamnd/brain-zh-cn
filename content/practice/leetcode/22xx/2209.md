[LeetCode 问题 2209](https://leetcode.com/problems/minimum-white-tiles-after-covering-with-carpets/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划、前缀和

 ## 解决方案

 ## 问题理解

 问题呈现一个**二进制字符串`floor`** 代表一排瓷砖，其中`'0'`对应于黑色瓷砖并且`'1'`对应于白色瓷砖。 目标是使用有限数量的固定长度的**黑色地毯**覆盖其中一些瓷砖，从而最大限度地减少**仍然可见的白色瓷砖的数量**。 你被给予`numCarpets`和`carpetLen`，代表地毯的数量及其长度。 地毯可以重叠，这意味着您可以根据需要多次覆盖相同的瓷砖，但这样做不会产生额外的好处。 

输出是一个整数，表示最佳放置地毯后可见的**最小白色瓷砖数量**。 

约束在这里很重要：

 -`1 <= carpetLen <= floor.length <= 1000`告诉我们输入对于动态编程方法来说足够小，但对于所有地毯放置的简单强力排列检查来说太大。 
-`1 <= numCarpets <= 1000`意味着地毯的数量可能很大，因此任何解决方案都必须在两个维度上进行扩展：瓷砖的数量和地毯的数量。 
-`floor[i]`是`'0'`或者`'1'`，因此仅存在两种图块类型，从而简化了计数逻辑。 

可能导致幼稚实现失败的边缘情况包括：

 - 情况`numCarpets * carpetLen >= floor.length`，可以覆盖整个地板。 
- 地板全黑或白。 
-`carpetLen = 1`，它测试最小覆盖粒度。 
-`numCarpets = 1`，这严重限制了放置选择。 

## 方法

 **强力方法**将尝试递归或迭代地将每个地毯放置在每个可能的位置，从而生成所有组合。 对于每种组合，我们都会计算可见白色瓷砖的数量。 这种方法是正确的，但在计算上不可行，因为有`O(floor.length ^ numCarpets)`组合，即使对于很小的投入，也会很快变得天文数字。 

**最佳方法**使用**动态规划（DP）**。 关键的观察结果是，该问题表现出**最佳子结构**：第一个可见的白色瓷砖的最小数量`i`瓷砖与`k`地毯仅取决于第一个的选择`i-1`瓷砖。 

我们定义一个DP状态`dp[i][k]`作为第一个可见的白色瓷砖的最小数量`i`瓷砖使用最多`k`地毯。 递推关系为：

 1. 如果我们**不铺地毯**到瓷砖为止`i`，我们添加tile的值`i`（0 为黑色，1 为白色）至`dp[i-1][k]`。 
2. 如果我们**放置一块地毯**，尽头是瓷砖`i`，我们考虑瓷砖`i-carpetLen`返回并取最小值`dp[i-carpetLen][k-1]`。 我们覆盖了中间的所有图块，因此它们对白色图块的贡献变为 0。 

为了高效地实现，我们可以**使用前缀和**来在 O(1) 时间内计算一个范围内的白色瓷砖的数量。 我们还通过使用二维数组来优化空间`dp[i][k]`或滚动数组。

 ## 算法演练

 1. **计算地板字符串的白色瓷砖的前缀和**，其中`prefix[i]`存储索引中白色瓷砖的数量`0`到`i-1`。 
2. **初始化一个DP表**`dp`在哪里`dp[i][k]`表示第一个可见的白色瓷砖的最小数量`i`瓷砖与`k`地毯。 
3. 迭代图块`i`从 1 到`n`：

 1. 迭代`k`从 0 到`numCarpets`：

 - 如果没有铺地毯`i`， 放`dp[i][k] = dp[i-1][k] + (1 if floor[i-1] == '1' else 0)`。 
- 如果地毯覆盖了最后一个`carpetLen`瓷砖结束于`i`， 更新`dp[i][k] = min(dp[i][k], dp[max(0, i-carpetLen)][k-1])`。 
4. 返回`dp[n][numCarpets]`。 

**为什么有效**：DP 确保对于每个地板前缀和使用的地毯数量，我们都保持最少的可见白色瓷砖。 通过考虑放置地毯和不放置地毯，可以有效地探索所有可能性，而无需多余的计算。 

## Python 解决方案```python
class Solution:
    def minimumWhiteTiles(self, floor: str, numCarpets: int, carpetLen: int) -> int:
        n = len(floor)
        # dp[i][k]: min white tiles for first i tiles using up to k carpets
        dp = [[float('inf')] * (numCarpets + 1) for _ in range(n + 1)]
        dp[0] = [0] * (numCarpets + 1)
        
        for i in range(1, n + 1):
            is_white = 1 if floor[i - 1] == '1' else 0
            for k in range(numCarpets + 1):
                # Option 1: Do not place carpet at this tile
                dp[i][k] = dp[i-1][k] + is_white
                # Option 2: Place carpet ending at this tile
                if k > 0:
                    dp[i][k] = min(dp[i][k], dp[max(0, i - carpetLen)][k-1])
        
        return dp[n][numCarpets]
```**说明**：外循环遍历每个图块，内循环遍历地毯的数量。`dp[i][k]`通过添加白色瓷砖（如果未覆盖）或用地毯覆盖一段来更新。`max(0, i-carpetLen)`处理地毯长度超过当前前缀的情况。 

## 解决方案```go
func minimumWhiteTiles(floor string, numCarpets int, carpetLen int) int {
    n := len(floor)
    dp := make([][]int, n+1)
    for i := range dp {
        dp[i] = make([]int, numCarpets+1)
        for j := range dp[i] {
            dp[i][j] = 1 << 30 // infinity
        }
    }
    for k := 0; k <= numCarpets; k++ {
        dp[0][k] = 0
    }
    
    for i := 1; i <= n; i++ {
        isWhite := 0
        if floor[i-1] == '1' {
            isWhite = 1
        }
        for k := 0; k <= numCarpets; k++ {
            // Option 1: Do not place carpet
            dp[i][k] = dp[i-1][k] + isWhite
            // Option 2: Place carpet ending at i
            if k > 0 {
                prev := i - carpetLen
                if prev < 0 {
                    prev = 0
                }
                if dp[prev][k-1] < dp[i][k] {
                    dp[i][k] = dp[prev][k-1]
                }
            }
        }
    }
    
    return dp[n][numCarpets]
}
```**Go Notes**：与Python类似。 我们使用`1 << 30`作为无穷大。 Go 中的切片索引是从零开始的，因此我们进行调整`i-1`并使用`max(0, i-carpetLen)`等价逻辑。
