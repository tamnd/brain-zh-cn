[LeetCode 问题 2252](https://leetcode.com/problems/dynamic-pivoting-of-a-table/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题需要以编程方式实现 SQL 风格的透视操作。 输入是一个名为的表`Products`有柱子`product_id`,`store`， 和`price`，其中每行代表特定商店中产品的价格。 该表具有复合主键`(product_id, store)`最多30家独特商店。 

目标是重新组织数据，使每一行对应一个`product_id`，以及每列（除了`product_id`) 对应一个商店。 每个商店列中的值是该商店中产品的价格，或者`null`如果该产品不在那里销售。 存储列必须按**字典顺序**排序。 结果表可以按任何行顺序返回。 

约束表明存储数量很小（≤30），这使我们能够使用旋转技术而不必担心过多的内存或性能成本。 关键边缘情况包括仅在一部分商店中销售的产品、没有产品的商店或在同一商店子集中销售的多种产品。 

## 方法

 蛮力方法是手动迭代所有产品和所有可能的商店，填写价格或`null`如果商店中缺少该产品。 虽然这可行，但它需要嵌套循环：一个用于产品，一个用于商店，导致 O(n*m) 时间复杂度，其中`n`是产品数量，`m`是商店的数量。 这在这里是可以接受的，因为数据集很小，但它不优雅或可扩展。 

最佳方法首先识别所有唯一商店并按字典顺序对它们进行排序，从而利用动态旋转。 然后，我们使用类似字典的结构或 SQL 样式的条件表达式来汇总每种产品的价格。 这确保我们只迭代数据集一次，并直接将商店名称映射到输出中的价格值，从而使解决方案干净、可维护且高性能。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n*m) | O(n*m) | 迭代产品和商店，手动分配价格 |
 | 最佳| O(n + m*log m) | O(n + m*log m) | O(n*m) | 提取存储、按字典顺序排序、使用字典映射透视数据 |

 ## 算法演练

 1. **从表中提取唯一商店**并按字典顺序对它们进行排序。 这可确保输出列按所需的顺序显示。 
2. **分别初始化一个字典映射**`product_id`到另一个将商店名称映射到价格的字典。 这允许快速查找和分配。 
3. **迭代输入表的每一行**，并填充相应的内部字典`product_id`和那家商店的价格。 
4. **通过迭代所有生成输出表**`product_id`s。 对于每个产品，构建一行以`product_id`接下来是按排序顺序的每个商店的价格，使用`null`如果商店没有入口。 
5. **返回结果表**，该表现在具有与排序的商店名称相对应的动态列数。 

为什么有效：该算法保证每个产品都获得一行，每个商店获得一列。 字典结构确保快速访问和默认处理丢失的存储条目，从而保持正确性。 按字典顺序对存储进行排序可以保证列顺序要求。 

## Python 解决方案```python
from typing import List, Optional

class Solution:
    def PivotProducts(self, products: List[List]) -> List[List[Optional[int]]]:
        # Step 1: Extract unique stores and sort lexicographically
        stores = sorted({row[1] for row in products})
        
        # Step 2: Build product_id -> store -> price mapping
        product_map = {}
        for product_id, store, price in products:
            if product_id not in product_map:
                product_map[product_id] = {}
            product_map[product_id][store] = price
        
        # Step 3: Construct the pivoted table
        result = []
        for product_id in product_map:
            row = [product_id]
            for store in stores:
                row.append(product_map[product_id].get(store, None))
            result.append(row)
        
        return result
```Python 实现紧密遵循该算法。 首先，我们提取商店并对其进行排序。 然后我们填充一个嵌套字典，其中外键是`product_id`内键是商店名称，映射到价格。 最后，我们通过迭代排序的存储并使用来构造每一行`.get()`将缺失的价格处理为`None`。 

## 解决方案```go
package main

func PivotProducts(products [][]interface{}) [][]interface{} {
    storeSet := make(map[string]bool)
    productMap := make(map[int]map[string]int)
    
    // Step 1: Collect stores and map products
    for _, row := range products {
        productID := row[0].(int)
        store := row[1].(string)
        price := row[2].(int)
        storeSet[store] = true
        if _, exists := productMap[productID]; !exists {
            productMap[productID] = make(map[string]int)
        }
        productMap[productID][store] = price
    }
    
    // Step 2: Sort stores lexicographically
    stores := make([]string, 0, len(storeSet))
    for store := range storeSet {
        stores = append(stores, store)
    }
    sort.Strings(stores)
    
    // Step 3: Build pivoted table
    result := make([][]interface{}, 0, len(productMap))
    for productID, storePrices := range productMap {
        row := make([]interface{}, 0, len(stores)+1)
        row = append(row, productID)
        for _, store := range stores {
            if price, ok := storePrices[store]; ok {
                row = append(row, price)
            } else {
                row = append(row, nil)
            }
        }
        result = append(result, row)
    }
    
    return result
}
```Go 需要显式类型处理。 我们使用`interface{}`用于整数的通用处理和`nil`。 字典结构通过嵌套映射实现，缺失的条目被分配`nil`。 排序使用标准库`sort.Strings`。 

## 工作示例

 对于提供的示例，我们首先提取商店：`{"Shop", "LC_Store", "Nozama", "Souq"}`。 按字典顺序排序给出`["LC_Store", "Nozama", "Shop", "Souq"]`。 

建设中`product_map`：

 | 产品 ID | LC_商店 | 野泽 | 店铺 | 集市 |
 | ---| ---| ---| ---| ---|
 | 1 | 100 | 100 空 | 110 | 110 空 |
 | 2 | 空 | 200 | 200 空 | 190 | 190
 | 3 | 空 | 空 | 1000 | 1000 1900 | 1900

 迭代每个产品，我们使用排序的存储顺序构建行，分配`null`对于缺失的商店。 结果与预期输出相符。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m*log m) | O(n + m*log m) | O(n) 用于构建产品地图，O(m*log m) 用于对商店进行排序（m ≤ 30，可忽略） |
 | 空间| O(n*m) | 嵌套字典存储每种产品和每个商店的价格 |

 时间复杂度主要由产品数量决定`n`和商店`m`。 由于商店规模较小，分类商店可以忽略不计`m`。 空间与产品数量乘以商店数量成正比。
