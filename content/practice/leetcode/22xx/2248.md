[LeetCode 问题 2248](https://leetcode.com/problems/intersection-of-multiple-arrays/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、排序、计数

 ## 解决方案

 ## 问题理解

 问题是要求我们找到多个数组的交集。 具体来说，给定一个二维数组`nums`，其中每个`nums[i]`是一个由**不同正整数**组成的非空数组，我们想要识别哪些整数出现在**每个数组**中`nums`。 结果应按升序排序。 

简而言之，如果您将每一行想象为一组数字，我们需要所有组中的公共数字。 输入`nums`保证包含唯一整数的数组，并且所有数组中的整数总数最多为 1000。每个整数都在 1 到 1000 之间。这意味着我们正在处理小到中等的输入大小，而不必担心极大的数字或巨大的数组。 

边缘情况包括根本没有公共元素、所有数组都相同或只有一个数组（在这种情况下，交集只是数组本身）。 

## 方法

 **暴力方法**是根据所有其他数组检查第一个数组的每个元素。 我们将迭代第一个数组中的每个元素，并验证它在每个后续数组中的存在。 这种方法之所以有效，是因为元素必须出现在所有数组中才能成为交集的一部分。 然而，它的效率很低：如果有`m`数组与`n`每个元素，这会导致 O(m * n^2) 时间复杂度，对于上限来说可能太慢。 

**更好的方法**使用哈希映射（或计数数组，考虑到整数范围有限）。 我们可以计算所有数组中每个数字的频率。 计数后，每个数组中都存在任何计数等于数组总数的数字。 这利用了数字在 1 到 1000 之间的约束，并且比重复检查每个元素要快得多。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m * n^2) | O(m * n^2) | O(1) | O(1) | 对照所有其他数组检查第一个数组中的每个元素 |
 | 最佳| O(m * n) | O(1001) | 使用固定大小的数组或哈希映射计算出现次数，然后收集所有数组中存在的数字 |

 ## 算法演练

 1.初始化一个计数数组`count`大小为 1001（因为数字范围从 1 到 1000），全为零。 
2. 对于每个数组`nums`，迭代其元素并增加相应的索引`count`1.
 3.处理完所有数组后，迭代`count`从索引 1 到 1000。如果`count[i]`等于数组的数量 (`len(nums)`）， 然后`i`存在于每个数组中。 
4. 将所有这些数字收集到结果列表中。 
5. 返回结果列表，该列表已经排序，因为我们按升序迭代索引。 

**工作原理：** 计数阵列充当所有阵列的频率跟踪器。 通过将频率与数组总数进行比较，我们可以保证只包含出现在所有数组中的元素。 按数字顺序迭代可确保结果排序。 

## Python 解决方案```python
from typing import List

class Solution:
    def intersection(self, nums: List[List[int]]) -> List[int]:
        count = [0] * 1001
        for arr in nums:
            for num in arr:
                count[num] += 1
        result = [i for i in range(1, 1001) if count[i] == len(nums)]
        return result
```在这个实现中，我们首先创建一个`count`数组来跟踪每个数字的频率。 对于每个数组中的每个数字，我们递增其计数。 处理完所有数组后，我们构建`result`通过收集计数等于数组数量的数字来列表，确保这些数字存在于所有数组中。 从 1 到 1000 的迭代保证升序。 

## 解决方案```go
func intersection(nums [][]int) []int {
	count := make([]int, 1001)
	for _, arr := range nums {
		for _, num := range arr {
			count[num]++
		}
	}
	result := []int{}
	for i := 1; i <= 1000; i++ {
		if count[i] == len(nums) {
			result = append(result, i)
		}
	}
	return result
}
```Go 解决方案反映了 Python 解决方案。 我们使用 1001 个整数的固定大小切片进行计数。 从 1 到 1000 的最终迭代确保升序，并且我们附加出现在所有数组中的数字。 Go 可以高效地处理切片，因此附加操作是安全的并且可以保持顺序。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m * n) | 遍历每个数组的每个元素一次； m = 数组数量，n = 数组的平均长度 |
 | 空间| O(1001) | 无论输入大小如何，固定大小的计数数组 |

 时间复杂度的原因是我们只迭代所有数组的所有元素一次。 空间复杂度是恒定的，因为计数数组大小固定为 1001，与输入数组的数量或其大小无关。

 ## 边缘情况

 一种重要的边缘情况是当**只有一个数组**时`nums`。 在这种情况下，交集就是数组本身，因为没有其他东西可以比较。 我们的实现自然会处理这个问题，因为计数数组将匹配该单个数组中所有元素的数组数量 (1)。 

另一个边缘情况是当**没有元素在数组中是通用的**时，如`[[1,2,3],[4,5,6]]`。 简单的实现可能会错误地返回第一个数组中的元素，但我们的计数数组可确保仅包含每个数组中出现的元素。 由于没有元素满足要求，因此返回空列表。 

最后，包含**允许的最大和最小整数**（1 和 1000）的数组对于使用索引的实现来说可能很棘手。 我们通过使用大小为 1001 的计数数组并直接按数字值进行索引来正确处理此问题，因此 1 和 1000 都会正确计数并包含在所有数组中（如果存在）。
