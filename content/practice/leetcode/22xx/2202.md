[LeetCode 问题 2202](https://leetcode.com/problems/maximize-the-topmost-element-after-k-moves/)

 **难度：** 🟡 中等
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一堆表示为数组的整数`nums`， 在哪里`nums[0]`是当前堆的顶部元素。 我们必须准确执行`k`移动，并且在每个移动中我们可以执行以下两个操作之一：

 1. 从堆中移除当前顶部元素。 
2. 将之前移除的任何元素添加回堆的顶部。 

目标是在恰好之后最大化最顶层元素的值`k`移动。 

关键细节是，一旦删除元素，它就永远可用于将来的添加操作。 我们不限于恢复最近删除的元素。 我们可以选择任何删除的元素。 

数组大小可以大到`10^5`， 尽管`k`可以大到`10^9`。 这些约束立即告诉我们，我们无法模拟所有可能的移动序列。 我们需要直接的数学或贪婪的观察。 

另一个重要的观察结果是，每个删除操作都会暴露堆栈中更深层次的元素。 如果我们删除足够多的元素，以前隐藏的元素可能会成为新的顶部，而不需要添加任何东西回来。 

该问题要求恰好在之后的最大可能的顶部元素`k`最多不会动`k`移动。 这种区别产生了几个重要的边缘情况。 

当堆只有一个元素时，就会出现一种特别棘手的情况。 如果`k`是奇数，在最后一次操作之后堆变空，因为删除和恢复交替奇偶校验。 尤其：

-`nums = [x], k = 1`给出`-1`-`nums = [x], k = 3`可以结束于`x`-`nums = [x], k = 2`也可以以`x`另一个重要的情况是当`k = 0`。 不允许进行任何操作，因此答案只是当前的顶部元素。 

我们还需要谨慎处理以下情况`k`超过数组长度。 由于删除的元素始终可以重新插入，因此大`k`价值观通常仍然是可控的。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的操作序列。 在每一步中，我们可以：

 - 如果堆非空，则删除当前顶部元素。 
- 重新插入之前移除的任何元件。 

这创造了一个巨大的分支因素。 可能的状态数量呈指数增长`k`。 

对于每个递归状态，我们需要跟踪：

 - 当前桩内容
 - 被移除元素的集合
 - 剩余步数

 虽然这保证了正确性，因为每个可能的移动序列都被探索了，但对于给定的约束来说这是完全不切实际的。 即使对于小数组和中等值`k`，状态数量变得太多。 

### 最优贪婪观察

 关键的见解是，在准确之后`k`移动时，最终的顶部元素只能来自两个来源：

 1. 第一个`k - 1`删除了我们选择放回顶部的元素。 
2、准确去除后自然露出的元件`k`元素，即`nums[k]`。 

假设我们希望某个元素成为最终的顶部`k`移动。 

如果我们在最后一步将一个元素放回堆中，那么我们必须花费之前的时间`k - 1`移动删除元素。 因此，任何第一个`k - 1`元素可能会成为最终答案。 

或者，如果我们在最后一次移动期间从未添加元素，那么在完全删除之后`k`元素，新的顶部变成`nums[k]`。 

因此，答案很简单：

 - 第一个中的最大值`k - 1`元素
 - 或者`nums[k]`， 如果`k < len(nums)`这将问题简化为简单的贪婪最大计算。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 探索所有操作顺序 |
 | 最佳| O(min(n,k)) | O(1) | O(1) | 使用关于可到达顶部元素的贪婪观察 |

 ## 算法演练

 1. 首先，处理数组仅包含一个元素的特殊情况。 

如果`len(nums) == 1`，然后堆根据奇偶校验在空和非空之间交替`k`。 

- 如果`k`是奇数，堆结束时是空的，所以返回`-1`。 
- 如果`k`是偶数，我们可以恢复元素，所以返回`nums[0]`。 
2. 处理以下情况`k == 0`。 

不执行任何操作，因此当前顶部保持不变。 返回`nums[0]`。 
3. 计算第一个中的最大值`k - 1`元素。 

这些是我们可以在第一个过程中删除的元素`k - 1`移动，然后在最后移动时放回顶部。 

具体来说，我们检查：```
nums[0 : min(n, k - 1)]
```4.如果`k < len(nums)`，还考虑`nums[k]`。 

这代表了我们花费所有的场景`k`移动删除元素。 紧邻已删除部分下方的元素将成为新的顶部。 
5. 返回以下值之间的较大值：

 - 最好的可拆卸和可重新插入的元件
 - 直接暴露的元素`nums[k]`### 为什么它有效

 恰好之后`k`移动，最终的操作决定顶部元素。 如果最后一个移动是插入，那么插入的元素一定是之前被删除的，这意味着它来自第一个`k - 1`职位。 如果最后一步是移除，那么恰好`k`元素已被删除，新的顶部变为`nums[k]`。 在恰好之后，没有其他元素可能出现在顶部`k`移动。 因此，在这些候选者中取最大值总是会产生最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumTop(self, nums: List[int], k: int) -> int:
        n = len(nums)

        # Special case: only one element
        if n == 1:
            if k % 2 == 1:
                return -1
            return nums[0]

        # No moves
        if k == 0:
            return nums[0]

        answer = -1

        # Any of the first k - 1 elements can be reinserted
        limit = min(n, k - 1)

        for i in range(limit):
            answer = max(answer, nums[i])

        # If we remove exactly k elements,
        # nums[k] becomes the new top
        if k < n:
            answer = max(answer, nums[k])

        return answer
```该实现首先检查单元素边缘情况，因为它的行为与较大数组不同。 对于一个元素，每次删除都会清空堆，因此奇偶校验决定堆是否可以非空结束。 

接下来，代码处理`k == 0`，其中初始顶部保持不变。 

变量`answer`存储最佳可实现的最高值。 我们计算第一个中的最大值`k - 1`元素，因为这些元素可以被删除，然后作为最终移动恢复。 

最后，如果`k < n`，该算法还考虑`nums[k]`，它代表精确删除后的顶部`k`元素而不恢复任何东西。 

该实现仅使用单个循环和恒定的额外内存。 

## 解决方案```go
func maximumTop(nums []int, k int) int {
	n := len(nums)

	// Special case: only one element
	if n == 1 {
		if k%2 == 1 {
			return -1
		}
		return nums[0]
	}

	// No moves
	if k == 0 {
		return nums[0]
	}

	answer := -1

	// Maximum among first k - 1 elements
	limit := k - 1
	if limit > n {
		limit = n
	}

	for i := 0; i < limit; i++ {
		if nums[i] > answer {
			answer = nums[i]
		}
	}

	// Consider nums[k]
	if k < n && nums[k] > answer {
		answer = nums[k]
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置的`max`整数函数，比较是手动完成的`if`声明。 

Go 中的切片的行为类似于索引访问的数组，因此除了边界检查之外不需要特殊处理。 

整数溢出不是问题，因为所有值都适合 Go 的标准`int`类型。

 ## 边缘情况

 当数组仅包含单个元素时，会出现一种重要的边缘情况。 这种情况下的行为有所不同，因为每次移除都会完全清空堆。 如果`k`很奇怪，最后一步让堆空了，答案就出来了`-1`。 许多不正确的解决方案忘记了这种奇偶校验行为并错误地返回原始元素。 

另一个棘手的情况是当`k`等于数组长度。 在这种情况下，`nums[k]`不存在，因为删除所有元素会清空堆。 唯一有效的策略是恢复先前删除的元素之一。 该实现通过检查来安全地处理这个问题`if k < n`访问之前`nums[k]`。 

第三种微妙的情况发生在`k`大于数组大小。 幼稚的实现可能会错误地假设答案无效。 然而，由于被移除的元素可能会被重复重新插入，所以我们仍然可以以非空堆结束。 该算法通过考虑可移除元素中的最大值并忽略无效索引来正确处理此问题。 

另一个边缘情况涉及`k = 0`。 由于不允许移动，因此答案必须是原始的顶部元素。 即使没有发生任何操作，某些实现也会错误地尝试删除逻辑。 

最后，重复的值也会导致混乱。 由于该问题仅要求最大可能的顶部值，因此重复项不需要特殊处理。 该算法自然有效，因为它只跟踪最大的可达候选者。
