[LeetCode 问题 2226](https://leetcode.com/problems/maximum-candies-allocated-to-k-children/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 这个问题要求我们在给定一堆糖果和许多孩子的情况下，确定**每个孩子可以平等收到的最大糖果数量**`k`。 

我们得到一个整数数组`candies`， 在哪里`candies[i]`代表的大小`i-th`桩。 我们可以**将一堆糖果分成更小的子堆**，但我们**不允许将不同堆中的糖果组合起来**。 这一限制非常重要，因为这意味着每个孩子必须从单堆或子堆中获得所有糖果。 

目标是将糖果准确地分发给`k`孩子们这样：

 1. 每个孩子都会收到**相同数量的糖果**。 
2. 每个孩子都会收到**仅一堆**的糖果。 
3. 桩可以分成多个较小的桩。 
4. 部分桩可能未使用。 

我们希望最大限度地增加每个孩子收到的糖果数量。 

例如，如果我们尝试给每个孩子`x`糖果，那么每一堆贡献：$$\left\lfloor \frac{\text{pile size}}{x} \right\rfloor$$孩子们，因为一堆大小`8`可以生产`2`大小组`4`， 或者`1`组大小`5`， 等等。 

约束条件尤其重要：

 -`candies.length <= 10^5`-`candies[i] <= 10^7`-`k <= 10^12`简单的模拟会太慢，因为答案的搜索空间可能大到`10^7`，并且可能有`10^5`桩。 这强烈表明我们需要比单独测试每种可能的糖果数量更有效的方法。 

一个重要的观察是答案是有界的：

 - 最小可能的答案是`0`。 
- 最大可能答案不能超过最大堆大小。 

有几种边缘情况需要预先考虑。 如果糖果总数小于`k`，那么不可能给每个孩子一颗糖果，所以答案一定是`0`。 当只有一堆时，会发生另一种棘手的情况，因为所有孩子都必须来自该单堆的分裂。 极大值`k`, 直至`10^12`，也意味着我们必须避免与`k`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试每个孩子的所有可能的糖果数量`1`最多`max(candies)`。 

对于每个候选人金额`x`，我们计算可以服务多少个孩子：$$\sum \left\lfloor \frac{\text{candies}[i]}{x} \right\rfloor$$如果总数至少为`k`， 然后`x`是可行的。 否则，就不是。 

我们将跟踪最大的可行值。 

这种方法是正确的，因为它详尽地检查了每一个可能的答案并选择最大的有效答案。 然而，对于问题的限制来说，它太慢了。 

认为：

-`max(candies) = 10^7`-`n = 10^5`那么复杂度就变成了：$$O(n \cdot \max(candies))$$可以达到：$$10^5 \times 10^7 = 10^{12}$$操作，显然不可行。 

### 关键见解：对答案进行二分搜索

 关键的观察结果是这个问题具有**单调性**。 

如果可以给每个孩子`x`糖果，那么也可以给每个孩子**任何小于的值**`x`。 

例如：

 - 如果`5`每个孩子的糖果有效，那么`4`,`3`,`2`， 和`1`也会起作用。 
- 如果`5`不起作用，那么`6`,`7`，并且更大的值也不起作用。 

这创建了一个单调搜索空间：```
feasible feasible feasible feasible infeasible infeasible
```每当我们有单调条件时，**二分搜索**就适用。 

我们不是检查每个可能的答案，而是在范围内进行二分搜索：$$[1, \max(candies)]$$对于每个中点`mid`，我们计算有多少个孩子可以收到`mid`糖果。 

- 如果至少`k`可以为孩子提供服务，然后`mid`是可行的，我们尝试更大的值。 
- 否则，`mid`太大，所以我们尝试较小的值。 

这大大减少了搜索。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × max(糖果)) | O(1) | O(1) | 检查所有可能的糖果数量 |
 | 最佳| O(n log(最大(糖果))) | O(1) | O(1) | 在答案空间上使用二分搜索 |

 ## 算法演练

 1. 计算最大桩尺寸。 

由于没有孩子可以获得比最大堆更多的糖果，因此这成为我们搜索范围的上限。 
2. 初始化二分查找范围。 

放：

-`left = 1`-`right = max(candies)`我们从`1`因为分配`0`candies 是微不足道的，只有在不存在有效的肯定答案时才需要。 
3. 执行二分查找。 

尽管`left <= right`:

 - 计算中间值：$$mid = (left + right) // 2$$这代表每个孩子的候选糖果数量。 
4. 计算可以服务多少个孩子。 

对于每堆：$$\text{pile} // mid$$告诉我们有多少个子堆的大小`mid`可以被创建。 

将所有桩中的这些值相加。 
5. 检查可行性。 

如果服务的儿童总数至少为`k`:

 -`mid`是可行的。 
- 将其记录为候选答案。 
- 搜索更大的值：```
left = mid + 1
```否则：

-`mid`太大了。 
- 搜索较小的值：```
right = mid - 1
```6. 返回结果。 

二分搜索最终收敛到最大可行糖果数。 

### 为什么它有效

 正确性依赖于可行性的单调性。 如果`x`每个孩子的糖果是可以实现的，那么任何较小的值也是可以实现的，因为我们总是可以将一堆糖果分成更小的组。 相反，如果`x`不可能，任何更大的值也是不可能的。 二分查找正确地找到可行值和不可行值之间的边界，保证返回最大的有效答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumCandies(self, candies: List[int], k: int) -> int:
        left = 1
        right = max(candies)
        answer = 0

        while left <= right:
            mid = (left + right) // 2

            children_served = 0
            for pile in candies:
                children_served += pile // mid

            if children_served >= k:
                answer = mid
                left = mid + 1
            else:
                right = mid - 1

        return answer
```该实现直接遵循前面描述的二分搜索策略。 

我们首先确定搜索范围。 最小的有意义值是`1`，而最大可能的答案是最大的堆大小。 

在二分搜索循环内，`mid`代表每个孩子的候选糖果数量。 然后我们遍历每一堆并计算有多少个孩子可以收到`mid`使用整数除法从那堆糖果中取出糖果。 

如果服务的儿童总数至少为`k`，则候选值是可行的。 我们将其记录在`answer`并继续搜索更大的值，因为我们想要最大可能的分布。 

如果少于`k`可以为孩子提供服务，然后`mid`太大了，我们将搜索空间缩小到更小的值。 

一旦搜索结束，`answer`包含最大可行糖果数。 

## 解决方案```go
func maximumCandies(candies []int, k int64) int {
	left := 1
	right := 0

	for _, pile := range candies {
		if pile > right {
			right = pile
		}
	}

	answer := 0

	for left <= right {
		mid := left + (right-left)/2

		var childrenServed int64 = 0

		for _, pile := range candies {
			childrenServed += int64(pile / mid)
		}

		if childrenServed >= k {
			answer = mid
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑，但有一些特定于语言的注意事项。 

自从`k`可以大到`10^12`，我们使用`int64`计数时`childrenServed`。 使用标准`int`在某些系统上可能存在溢出风险。 

中点计算使用：```go
mid := left + (right-left)/2
```而不是`(left + right) / 2`以避免潜在的整数溢出，即使在此问题中边界是安全的。 

Go 切片自然地用于迭代糖果堆，不需要额外的内存结构。

 ## 边缘情况

 当糖果总数小于`k`。 在这种情况下，即使给每个孩子一颗糖果也是不可能的。 幼稚的实现可能会意外返回`1`如果不仔细验证可行性。 二分搜索自然地处理这个问题，因为即使`mid = 1`可行性检查失败，答案为`0`。 

另一个棘手的情况涉及单堆。 由于堆不能合并，因此所有孩子都必须从同一堆的细分中获得糖果。 例如，`candies = [10]`和`k = 3`应该返回`3`， 不是`10 // 3 = 3.33`或者`4`。 该实现正确地使用整数除法来仅计算完整的组。 

第三个重要的边缘情况是极大的值`k`, 直至`10^12`。 由于时间复杂性，任何试图单独模拟儿童的算法都会失败。 二分查找解决方案避免了对`k`完全并且仅对堆大小执行算术运算。 

最后，围绕可行性的边界值很容易引入相差一的错误。 例如，当`mid`是可行的，我们必须继续向右搜索，因为更大的答案可能仍然存在。 同时，我们保留当前的可行值`answer`。 这确保算法返回最大有效糖果数量，而不仅仅是任何有效数量。
