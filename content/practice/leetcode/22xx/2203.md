 # LeetCode 2203 - 具有所需路径的最小加权子图

 ## 问题理解

 这个问题给了我们一个加权有向图`n`节点和有向边列表。 每条边都有一个正权重。 我们还给出了两个源节点，`src1`和`src2`，以及目标节点`dest`。 

目标是找到一个子图，其总边权重尽可能小，同时仍然允许`src1`和`src2`达到`dest`。 

一个关键细节是两条路径允许共享边。 由于子图的权重仅对每条边进行一次计数，因此共享部分是有益的，因为它们降低了总成本。 这意味着我们不会最小化两条独立最短路径的总和。 相反，我们最小化两条路径使用的边并集的总权重。 

另一个重要的观察结果是该图是有向的。 存在于的路径`u`到`v`并不意味着存在一条路径`v`到`u`。 

限制条件很大：

 - 最多`10^5`节点
 - 最多`10^5`边缘

 这些限制立即排除了昂贵的图算法，例如 Floyd-Warshall 或每个节点的重复 DFS/BFS。 我们需要一些接近的东西`O((V + E) log V)`。 

图权重均为正，这强烈暗示了 Dijkstra 的最短路径算法。 

一些边缘情况很重要：

 - 一个或两个源可能无法到达目的地。 
- 图表可能包含断开连接的组件。 
- 同一对节点之间可能存在多条边。 
- 最佳解决方案可能涉及两条路径在到达之前在某个中间节点合并`dest`。 
- 最佳解决方案也可能由两条完全独立的路径组成。 

该问题保证了`src1`,`src2`， 和`dest`是不同的节点，这简化了处理琐碎的自路径。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试枚举所有可能的交汇点和所有可能的路径组合`src1`和`src2`到`dest`。 

思考这个问题的一种方法是：

 - 选择每个可能的节点`x`作为合并点。 
- 查找所有路径`src1`到`x`。 
- 查找所有路径`src2`到`x`。 
- 查找所有路径`x`到`dest`。 
- 计算所选边的并集成本。 

这种方法是正确的，因为每个有效的子图都对应于最终到达的路径的某种组合`dest`。 

然而，图中可能的路径数量可能是指数级的。 对于具有以下性质的图，即使尝试枚举它们也是不可行的`10^5`节点和边。 

一个不太天真的暴力想法是使用 Floyd-Warshall 计算每对节点之间的最短路径，然后测试每个合并节点。 虽然这避免了路径枚举，但 Floyd-Warshall 要求`O(n^3)`时间，这是不可能的`n = 10^5`。 

### 关键见解

 关键的观察是，如果两个源最终在某个节点合并`x`，那么最优结构如下：

 - 从最短路径`src1`到`x`- 从最短路径`src2`到`x`- 从最短路径`x`到`dest`由于所有边权重均为正，因此用较短路径替换任何部分只能改进解决方案。 

因此，对于每个节点`x`，我们想要：```
dist(src1 -> x) + dist(src2 -> x) + dist(x -> dest)
```所有节点的最小值就是答案。 

挑战在于有效计算从每个节点到`dest`。 

对于有向图，可以通过反转所有边并从以下位置运行 Dijkstra 来计算到达目的地的最短路径`dest`。 这会改变：```
x -> dest
```进入：```
dest -> x
```在反转图中。 

因此，我们执行了 3 次 Dijkstra 运行：

 1. 来自`src1`在原图上
 2. 来自`src2`在原图上
 3. 来自`dest`在反转图上

 然后我们测试每个节点作为潜在的合并点。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|

 | 最佳 |`O((V + E) log V)`|`O(V + E)`| 使用三个 Dijkstra 运行并检查所有合并点 |

 ## 算法演练

 1. 构建原始邻接表。 

由于图稀疏且大，因此邻接列表比邻接矩阵更有效。 每个节点都存储其输出边。 
2. 构建逆邻接表。 

对于每条边：```
u -> v
```添加：```
v -> u
```到反转图。 

这使我们能够计算到的最短距离`dest`通过运行 Dijkstra`dest`在反转图上。 
3. 运行 Dijkstra`src1`。 

这计算：```sql
dist1[x] = shortest distance from src1 to x
```4. 运行 Dijkstra`src2`。 

这计算：```sql
dist2[x] = shortest distance from src2 to x
```5. 运行 Dijkstra`dest`在反转图上。 

这计算：```sql
distDest[x] = shortest distance from x to dest
```因为遍历反向边`dest`对应于遍历原始边缘`dest`。 
6. 尝试将每个节点作为交汇点。 

对于每个节点`x`：

 - 如果三个距离中有任何一个无法到达，则跳过它。 
- 否则计算：```
total = dist1[x] + dist2[x] + distDest[x]
```保留最小值。 
7.返回答案。 

如果不存在有效节点，则返回`-1`。 

### 为什么它有效

 假设最优子图允许两个源都达到`dest`。 在某些时候，这两条路线可能会合并。 设第一个共享节点为`x`。 

然后子图可以分解为：

 - 一条路径从`src1`到`x`- 一条路径从`src2`到`x`- 共享路径`x`到`dest`用尽可能短的版本替换这些部分中的任何一个只能减少或保持总重量。 因此，某个最优解必须完全由最短路径组成。 

通过评估每个可能的合并节点`x`，我们保证考虑全局最优配置。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minimumWeight(
        self,
        n: int,
        edges: List[List[int]],
        src1: int,
        src2: int,
        dest: int
    ) -> int:

        graph = [[] for _ in range(n)]
        reverse_graph = [[] for _ in range(n)]

        for u, v, w in edges:
            graph[u].append((v, w))
            reverse_graph[v].append((u, w))

        def dijkstra(start: int, adjacency: List[List[tuple]]) -> List[int]:
            INF = float('inf')

            distances = [INF] * n
            distances[start] = 0

            min_heap = [(0, start)]

            while min_heap:
                current_dist, node = heapq.heappop(min_heap)

                if current_dist > distances[node]:
                    continue

                for neighbor, weight in adjacency[node]:
                    new_dist = current_dist + weight

                    if new_dist < distances[neighbor]:
                        distances[neighbor] = new_dist
                        heapq.heappush(
                            min_heap,
                            (new_dist, neighbor)
                        )

            return distances

        dist1 = dijkstra(src1, graph)
        dist2 = dijkstra(src2, graph)
        dist_dest = dijkstra(dest, reverse_graph)

        INF = float('inf')
        answer = INF

        for node in range(n):
            if (
                dist1[node] != INF and
                dist2[node] != INF and
                dist_dest[node] != INF
            ):
                total_weight = (
                    dist1[node] +
                    dist2[node] +
                    dist_dest[node]
                )

                answer = min(answer, total_weight)

        return -1 if answer == INF else answer
```实现首先构建两个邻接表。 第一个存储原始有向图，第二个存储反转图。 

这`dijkstra`辅助函数计算距起始节点的最短距离。 它使用最小堆优先级队列，以便处理的下一个节点始终是当前已知距离最小的节点。 

陈旧条目检查：```python
if current_dist > distances[node]:
    continue
```很重要，因为堆中可能存在同一节点的多个条目。 只应处理最好的一个。 

运行 Dijkstra 三次后，算法会迭代每个节点并将其视为潜在的合并点。 如果所有三个所需距离都存在，则计算组合成本并用于更新答案。 

最后，如果不存在有效的合并点，函数返回`-1`。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

type Edge struct {
	to     int
	weight int
}

type State struct {
	node int
	dist int64
}

type PriorityQueue []State

func (pq PriorityQueue) Len() int {
	return len(pq)
}

func (pq PriorityQueue) Less(i, j int) bool {
	return pq[i].dist < pq[j].dist
}

func (pq PriorityQueue) Swap(i, j int) {
	pq[i], pq[j] = pq[j], pq[i]
}

func (pq *PriorityQueue) Push(x interface{}) {
	*pq = append(*pq, x.(State))
}

func (pq *PriorityQueue) Pop() interface{} {
	old := *pq
	n := len(old)
	item := old[n-1]
	*pq = old[:n-1]
	return item
}

func dijkstra(start int, graph [][]Edge) []int64 {
	n := len(graph)

	dist := make([]int64, n)

	for i := range dist {
		dist[i] = math.MaxInt64
	}

	dist[start] = 0

	pq := &PriorityQueue{}
	heap.Init(pq)

	heap.Push(pq, State{
		node: start,
		dist: 0,
	})

	for pq.Len() > 0 {
		current := heap.Pop(pq).(State)

		if current.dist > dist[current.node] {
			continue
		}

		for _, edge := range graph[current.node] {
			newDist := current.dist + int64(edge.weight)

			if newDist < dist[edge.to] {
				dist[edge.to] = newDist

				heap.Push(pq, State{
					node: edge.to,
					dist: newDist,
				})
			}
		}
	}

	return dist
}

func minimumWeight(
	n int,
	edges [][]int,
	src1 int,
	src2 int,
	dest int,
) int64 {

	graph := make([][]Edge, n)
	reverseGraph := make([][]Edge, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]
		w := edge[2]

		graph[u] = append(graph[u], Edge{
			to:     v,
			weight: w,
		})

		reverseGraph[v] = append(reverseGraph[v], Edge{
			to:     u,
			weight: w,
		})
	}

	dist1 := dijkstra(src1, graph)
	dist2 := dijkstra(src2, graph)
	distDest := dijkstra(dest, reverseGraph)

	answer := int64(math.MaxInt64)

	for i := 0; i < n; i++ {
		if dist1[i] == math.MaxInt64 ||
			dist2[i] == math.MaxInt64 ||
			distDest[i] == math.MaxInt64 {
			continue
		}

		total := dist1[i] + dist2[i] + distDest[i]

		if total < answer {
			answer = total
		}
	}

	if answer == math.MaxInt64 {
		return -1
	}

	return answer
}
```Go 版本遵循与 Python 解决方案相同的逻辑，但需要使用 Go 的显式堆实现`container/heap`包裹。 

一个重要的区别是整数处理。 由于路径总和可能会变大，因此实现使用`int64`距离和最终答案。 

Go 也没有提供内置的优先级队列，因此需要自定义堆类型来实现所需的接口方法。

 ## 边缘情况

 ### 无法到达的目的地

 最重要的边缘情况之一发生在以下任一情况`src1`或者`src2`无法到达`dest`。 

幼稚的实现可能会意外地将无限距离视为有效值，或者在将它们加在一起时溢出。 

此实现在将节点视为合并点之前显式检查所有三个所需距离是否都是有限的：```
if (
    dist1[node] != INF and
    dist2[node] != INF and
    dist_dest[node] != INF
):
```如果不存在有效节点，算法正确返回`-1`。 

### 同一节点之间的多条边

 该图可以包含连接具有不同权重的同一对节点的多个有向边。 

有缺陷的实现可能会覆盖边缘或错误地假定唯一性。 

使用邻接表自然可以处理这种情况，因为所有边都是独立存储的。 Dijkstra 在放松期间自动选择最便宜的选项。 

### 永不合并的路径

 某些解决方案错误地假设两个源路径必须共享边。 

实际上，最优子图可能由两条完全独立的路径组成，它们仅在`dest`，或者在目的地之前根本不重叠。 

此实现正确处理了这种情况，因为每个节点，包括`dest`本身被视为潜在的合并点。 如果最佳配置直到最后都使用单独的路由，则选择`dest`因为合并节点自然地代表该结构。
