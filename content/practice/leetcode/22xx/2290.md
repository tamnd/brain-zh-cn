 # LeetCode 2290，最少清除障碍物到达拐角

 ## 问题理解

 这个问题给了我们一个二维网格，其中每个单元格要么是空的，要么被障碍物阻挡。 值为`0`意味着我们可以在单元格中自由移动，而值为`1`表示该单元格包含可以移除的障碍物。 

我们从左上角开始`(0, 0)`并想要到达右下角`(m - 1, n - 1)`。 从任何单元格，我们都可以朝四个方向移动：

 - 向上
 - 向下
 - 左
 - 右

 重要的细节是输入具有值的单元格`1`清除障碍物需要花费一笔费用。 输入含有值的单元格`0`无需花费任何费用。 

目标不是最小化步骤数。 相反，我们必须尽量减少沿途清除的障碍物总数。 

这本质上是图上的最短路径问题：

 - 每个单元格都是一个节点
 - 移动到相邻小区是一个优势
 - 边权重为：

 -`0`如果邻居是空的
 -`1`如果邻居是障碍

 约束条件非常重要：

 -`m * n <= 10^5`- 因此网格可以非常大
 - 任何指数或重复的详尽搜索都会超时

 该问题保证：

 - 起始单元格为空
 - 目标单元格为空
 - 网格值仅`0`或者`1`这些保证简化了实现，因为我们永远不需要删除起始或结束单元格。 

一些边缘情况很重要：

 - 不需要移除障碍物的网格
 - 几乎每一步移动都需要消除障碍的网格
 - 非常窄的网格，例如`1 x n`或者`m x 1`- 具有相同移除计数的多个不同路径
 - 最短几何路径不是最便宜的障碍路径的情况

 一个最小化步骤而不是移除的简单 BFS 将会失败，因为更少的移动并不一定意味着移除的障碍更少。 

## 方法

 ### 蛮力方法

 强力解决方案将探索从起点到目的地的每条可能路径，并计算每条路径消除了多少障碍。 

考虑这个问题的一种方法是使用带回溯的 DFS：

 - 在所有四个方向上递归移动
 - 保持已移除障碍物的数量
 - 跟踪访问过的单元格以避免循环
 - 每当到达目的地时更新最小答案

 这种方法是正确的，因为它最终会探索所有有效路径，因此不会错过最佳路径。 

然而，这在计算上是不可行的。 可能的路径数量随着网格大小呈指数增长。 即使是中等的网格也会产生巨大的搜索空间。 

因为网格可能包含最多`100000`细胞，暴力探索是完全不切实际的。 

### 最佳方法，0-1 BFS

 关键的观察是边权重只是`0`或者`1`。 

这意味着这个问题非常适合**0-1 BFS**，这是一种专门针对边权重限制为的图的最短路径算法`0`和`1`。 

这个想法是：

 - 搬进空房间的费用`0`- 进入障碍物的成本`1`我们使用双端队列而不是普通队列：

 - 如果搬到邻居有费用`0`,将其推到前面
 - 如果搬到邻居有费用`1`，把它推到后面

 这种排序保证了首先处理具有较小去除成本的单元，类似于 Dijkstra 算法，但对于二进制权重来说更有效。 

该算法保持到达每个单元格所需的最小障碍物清除量。 

由于每个节点和边都得到有效处理，因此解决方案以相对于网格大小的线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^(m*n)) | O(4^(m*n)) | O(m*n) | 递归探索所有可能的路径 |
 | 最优，0-1 BFS | O(m*n) | O(m*n) | 使用基于双端队列的最短路径进行二进制边权重 |

 ## 算法演练

 1. 创建一个距离矩阵`dist`。`dist[r][c]`存储到达单元格时移除的障碍物的最小数量`(r, c)`。 

将除起始单元格之外的所有值初始化为无穷大：```
dist[0][0] = 0
```2. 创建双端队列用于BFS 处理。 

双端队列允许在两端进行高效插入。 

首先插入左上角的单元格：```
deque = [(0, 0)]
```3. 定义四个移动方向。 

我们可能会搬迁：

 - 向上
 - 向下
 - 左
 - 右
 4. 重复处理双端队列前面的单元格。 

前面总是包含当前最便宜的状态，因为：

 - 零成本动作插在前面
 - 一次性费用动作插在后面
 5. 对于当前单元格，检查所有四个邻居。 

对于每个有效邻居：

 - 判断是否为障碍物
 - 计算新的移除成本```
new_cost = current_cost + grid[nr][nc]
```6. 如果新成本改善了该邻居的已知距离，则更新它。```
if new_cost < dist[nr][nc]:
    dist[nr][nc] = new_cost
```7. 决定将邻居插入双端队列中的位置。 

- 如果邻居是空的（`0`），插入前面。 
- 如果邻居是障碍物（`1`），插入后面。 

这保留了最短路径排序。 
8. 继续，直到双端队列变空或到达目的地。 
9. 返回存储在目标单元格中​​的最小移除计数。 

### 为什么它有效

 0-1 BFS 实际上是 Dijkstra 算法的优化版本，适用于边权重限制为`0`和`1`。 

双端队列排序保证每当处理一个节点时，我们就已经知道该节点可能的最小障碍去除成本。 通过将零成本转换推到前面，可以立即优先考虑，而一成本转换则可以通过将它们推到后面来推迟。 

由于每次放松只会改善距离，并且节点以非递减成本顺序处理，因此该算法可以正确计算到达目的地所需的最小障碍物移除量。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def minimumObstacles(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        dist = [[float("inf")] * cols for _ in range(rows)]
        dist[0][0] = 0

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        dq = deque([(0, 0)])

        while dq:
            row, col = dq.popleft()

            for dr, dc in directions:
                nr = row + dr
                nc = col + dc

                if 0 <= nr < rows and 0 <= nc < cols:
                    new_cost = dist[row][col] + grid[nr][nc]

                    if new_cost < dist[nr][nc]:
                        dist[nr][nc] = new_cost

                        if grid[nr][nc] == 0:
                            dq.appendleft((nr, nc))
                        else:
                            dq.append((nr, nc))

        return dist[rows - 1][cols - 1]
```实现首先初始化网格的尺寸并创建`dist`矩阵。 每个单元都以无限的成本开始，因为我们还没有发现任何通往这些单元的路径。 

起始位置`(0, 0)`已分配成本`0`因为我们从这里开始，没有删除任何东西。 

这`deque`是0-1 BFS的核心数据结构。 与普通队列不同的是，它支持在常数时间内前后插入。 

在遍历过程中，每个邻居都会被评估：

 - 输入空单元格会增加零成本
 - 进入障碍物会增加一项成本

 如果找到更好的路径，则更新距离矩阵。 

关键的优化是：

 - 零成本邻居走在前线
 - 花费一邻居去后面

 这种顺序确保始终首先处理成本较低的状态。 

最后，该算法返回存储在右下单元格中的最小成本。 

## 解决方案```go
package main

import "container/list"

func minimumObstacles(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	const INF = int(1e9)

	dist := make([][]int, rows)
	for i := 0; i < rows; i++ {
		dist[i] = make([]int, cols)
		for j := 0; j < cols; j++ {
			dist[i][j] = INF
		}
	}

	dist[0][0] = 0

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	deque := list.New()
	deque.PushFront([2]int{0, 0})

	for deque.Len() > 0 {
		front := deque.Front()
		deque.Remove(front)

		cell := front.Value.([2]int)
		row, col := cell[0], cell[1]

		for _, dir := range directions {
			nr := row + dir[0]
			nc := col + dir[1]

			if nr >= 0 && nr < rows && nc >= 0 && nc < cols {
				newCost := dist[row][col] + grid[nr][nc]

				if newCost < dist[nr][nc] {
					dist[nr][nc] = newCost

					if grid[nr][nc] == 0 {
						deque.PushFront([2]int{nr, nc})
					} else {
						deque.PushBack([2]int{nr, nc})
					}
				}
			}
		}
	}

	return dist[rows-1][cols-1]
}
```Go 的实现与 Python 解决方案非常相似。 

而不是Python内置的`deque`, Go 使用`container/list`实现双端队列。 

距离矩阵是手动初始化的，因为 Go 没有为整数提供内置的无穷大值。 大常数`INF`被用来代替。 

单元格使用固定大小的数组表示`[2]int`，它有效地存储行和列坐标。 

由于 Go 切片是引用类型，因此网格本身可以高效传递，无需复制。

 | --- | --- | --- |
 | 时间 | O(m*n) | 每个cell通过0-1 BFS高效处理 |

与标准 Dijkstra 算法不同，标准 Dijkstra 算法需要优先级队列并产生`O(E log V)`复杂度，0-1 BFS 利用受限的边权重来实现线性复杂度。 

距离矩阵需要每个单元格一个值，给出`O(m*n)`辅助空间。

 ## 边缘情况

 一种重要的边缘情况是不需要移除障碍物的网格。 幼稚的实现可能仍然会不必要地探索昂贵的路径或错误地计算删除量。 0-1 BFS 解决方案自然地处理了这个问题，因为零成本移动总是通过将它们插入双端队列的前面来确定优先级。 

另一个重要的情况是非常窄的网格，例如单行或单列。 在这些情况下，实际上只有一条可能的路线。 某些实现意外地假设两个维度都大于一维或错误处理边界检查。 该解决方案在处理所有相邻坐标之前安全地验证它们。 

当就移动计数而言最短路径不是就障碍物移除而言最便宜的路径时，就会出现第三种关键边缘情况。 标准 BFS 在这里会失败，因为 BFS 最小化了步骤，而不是加权成本。 0-1 BFS 算法根据障碍物数量正确对状态进行优先级排序，确保找到全局最优解。 

最后一个重要的例子是几乎完全充满障碍的网格。 在这些情况下，许多路径可能会以更好的成本反复重新访问小区。 距离矩阵可以防止不必要的重新处理，因为只有在发现严格较小的障碍物数量时才会进行更新。
