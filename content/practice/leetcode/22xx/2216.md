[LeetCode 问题 2216](https://leetcode.com/problems/minimum-deletions-to-make-array-beautiful/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、贪婪

 ## 解决方案

 ## 问题理解

 该问题要求我们转换给定的整数数组`nums`使用最少的删除次数变成**美丽的数组**。 一个漂亮的数组满足两个条件：它的长度是偶数，并且偶数索引处的两个连续元素不相等（`nums[i] != nums[i + 1]`为所有人`i % 2 == 0`）。 执行删除时，右侧的元素向左移动，而左侧的元素保持不变。 

输入是一个整数列表，最多可达`10^5`元素，每个元素的范围为`0`到`10^5`。 预期输出是一个整数，表示实现漂亮数组所需的最小删除次数。 空数组通常被认为是美丽的。 

关键的边缘情况包括已经很漂亮的数组、具有重复连续元素的数组以及长度为 1 的数组（需要删除才能成为偶数长度）。 该问题保证数组非空，但我们必须小心处理小数组。 

## 方法

 **暴力方法**会尝试生成数组的所有子序列并检查每个子序列是否美观。 这是正确的，但在计算上不可行，因为子序列的数量随着数组长度呈指数增长，导致`O(2^n)`时间复杂度。 

最佳方法的**关键见解**是我们只需要检查偶数索引处的相邻元素对。 通过在迭代数组时保持“虚拟”长度并仅添加不违反美观条件的元素，我们可以贪婪地计算需要删除的元素数量。 处理后，我们还需要确保最终数组的长度为偶数，如有必要，可能会删除最后一个元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 生成所有子序列并检查每个子序列是否美观 |
 | 最佳| O(n) | O(1) | O(1) | 贪婪遍历，根据相邻重复项和最终长度奇偶校验来计算删除次数 |

 ## 算法演练

 1. 初始化变量`deletions`到`0`计算删除的元素数量。 
2. 初始化变量`length`到`0`代表正在构建的“虚拟”美丽数组的长度。 
3. 迭代每个元素`num`在`nums`。 
4. 对于每个元素，检查它是否违反了 beautiful 属性：如果当前`length`是偶数并且`num`等于虚拟数组中最后一个附加元素，增量`deletions`并跳过附加。 
5. 否则，增加`length`包括`num`虚拟阵列中。 
6. 迭代完所有元素后，检查是否`length`很奇怪。 如果是这样，则增加`deletions`删除最后一个元素以确保长度均匀。 
7. 返回`deletions`作为所需的最小删除次数。 

**为什么它有效：** 通过在一次传递中处理数组并确保没有偶数索引对违反美丽条件，我们贪婪地维护了一个有效的数组。 最后对长度的调整保证了完整性，保证了最少的删减。 

## Python 解决方案```python
from typing import List

class Solution:
    def minDeletion(self, nums: List[int]) -> int:
        deletions = 0
        length = 0  # length of the virtual beautiful array
        
        for num in nums:
            if length % 2 == 0 and length > 0 and nums[length - deletions - 1] == num:
                deletions += 1
            else:
                length += 1
        
        if length % 2 == 1:
            deletions += 1
        
        return deletions
```该实现使用单次传递`nums`，保持虚拟数组长度`length`并递增`deletions`每当一个元素违反了美丽的属性时。 最终的奇偶校验确保生成的数组具有偶数长度。 

## 解决方案```go
func minDeletion(nums []int) int {
    deletions := 0
    length := 0

    for _, num := range nums {
        if length%2 == 0 && length > 0 && nums[length-deletions-1] == num {
            deletions++
        } else {
            length++
        }
    }

    if length%2 == 1 {
        deletions++
    }

    return deletions
}
```Go 解决方案镜像了 Python 版本。 Go 中的切片允许直接索引。 这`length-deletions-1`计算确保我们将当前元素与虚拟数组中的最后一个元素进行比较，类似于 Python。 

## 工作示例

 **示例1：**`nums = [1,1,2,3,5]`| 步骤| 编号 | 长度| 删除| 笔记|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 0 | 追加第一个元素 |
 | 2 | 1 | 1 | 1 | 在偶数索引处重复，删除|
 | 3 | 2 | 2 | 1 | 追加|
 | 4 | 3 | 3 | 1 | 追加|
 | 5 | 5 | 4 | 1 | 追加|

 最终的`length`是偶数，所以没有多余的删除。 结果：`1`。 

**示例2：**`nums = [1,1,2,2,3,3]`| 步骤| 编号 | 长度| 删除| 笔记|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 0 | 追加|
 | 2 | 1 | 1 | 1 | 删除重复|
 | 3 | 2 | 2 | 1 | 追加|
 | 4 | 2 | 2 | 2 | 删除重复|
 | 5 | 3 | 3 | 2 | 追加|
 | 6 | 3 | 3 | 3 | 删除重复|

 最终的`length`为奇数，再删去一项，使之为偶数。 结果：`2`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|

 | 时间 | O(n) | 单次遍历数组 |

 ## 边缘情况

 一种重要的边缘情况是单元素数组。 由于美丽的数组必须具有偶数长度，因此任何单元素数组都需要删除。 实现通过最终奇偶校验来处理这个问题。 

另一个边缘情况是具有交替重复项的数组，例如`[1,1,2,2,3,3,...]`。 这些需要在多个点进行删除； 贪心方法确保我们只在必要时删除而不会过度删除。 

第三种边缘情况是一个已经很漂亮的偶数数组。 该算法正确地跳过所有元素并且不增加删除，保留最小删除属性。
