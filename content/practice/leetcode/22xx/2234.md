[LeetCode 第 2234 题](https://leetcode.com/problems/maximum-total-beauty-of-the-gardens/)

 **难度：** 🔴难
 **主题：** 数组、两个指针、二分查找、贪婪、排序、枚举、前缀和

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有几个花园，其中`flowers[i]`代表已经种植了多少朵花`i-th`花园。 我们还获得了数量有限的额外鲜花，`newFlowers`，以便我们可以在花园中分发。 

The goal is to maximize the total beauty score after planting at most`newFlowers`花朵。 

如果一个花园至少包含`target`花朵。 每个完整的花园都有贡献`full`美丽点。 

不完整的花园被认为是不完整的。 在所有不完整的花园中，我们取最少的花朵数并将其乘以`partial`。 这有助于增加额外的美感。 

最终的美容公式为：

 -`(number of complete gardens) * full`- 加`(minimum flowers among incomplete gardens) * partial`如果每个花园都变得完整，那么就不存在不完整的花园，并且部分贡献变成`0`。 

重要的细节是，花只能添加，不能删除。 

限制条件非常大：

 - 最多`10^5`花园
 -`newFlowers`可以大到`10^10`这立即排除了暴力分配策略。 我们需要一个有效的算法，可能大约`O(n log n)`。 

一些边缘情况很重要：

 - 一些花园最初可能已经完工。 
- 最好不要完成每个花园。 
- 最大化不完整花园的最小价值可能比创建额外的完整花园更好。 
- 如果所有花园都已完成，则部分贡献消失。 
- 花园的花朵数量已大于或等于`target`应有效限制在`target`，因为超出了额外的花朵`target`不提供额外的好处。 

主要挑战是平衡两个相互竞争的目标：

 - 完成更多花园`full`点
 - 提高不完整花园的最小价值`partial`点

 ## 方法

 ### 蛮力方法

 暴力策略会尝试一切可能的方式来分发`newFlowers`穿过所有花园。 

对于每个发行版，我们将：

 1. 计算有多少花园已完工。 
2. 找出不完整花园中的最小值。 
3. 计算最终的美感。 
4. 跟踪最大结果。 

这种方法显然是正确的，因为它探索了每一种可能的分配。 

然而，这是完全不可行的。 

即使我们只考虑每朵花是否进入其中一朵`n`花园中，可能性的数量呈指数级增长。 和`newFlowers`最多`10^10`, exhaustive search is impossible.

 稍微好一点的蛮力方法可以枚举有多少个花园变得完整，然后尝试所有方法来最大化不完整的最小值。 但如果没有额外的优化，即使这样也会变得太慢。 

### 关键见解

 关键的观察是完整的花园和不完整的花园可以分开处理。 

Suppose we decide that exactly`k`花园将会完工。 

然后：

 - 我们可以贪婪地选择最便宜的花园来完成。 
- 其余的花园尚未完工。 
- 在不完整的花园中，我们希望最大化它们的最小值。 

这将问题转化为：

 1. 列举完整花园的数量。 
2. 使用剩余的花朵来最大化最小不完整花园价值。 

另一个重要的观察结果是，对于不完整的花园，最佳策略是均匀地种植较小的花园。 这是一个经典的前缀均衡问题，可以通过排序和前缀和来有效解决。 

然后二分查找可以确定最高可实现的最小不完整值。

 ## 算法演练

 ### 第 1 步：将所有花园盖上`target`任何超越的花`target`没关系，因为花园已经完成了。 

所以我们替换：```
flowers[i] = min(flowers[i], target)
```这简化了后面的计算。 

### 第 2 步：对花园进行排序

 排序使我们能够：

 - 有效地确定最便宜的花园来完成
 - 有效平衡较小的不完整花园
 - 使用前缀和进行快速范围成本计算

 ### 步骤 3：构建前缀和数组

 我们计算：```
prefix[i] = sum of flowers[0:i]
```这让我们可以计算出在恒定时间内将一系列花园提高到选定水平需要多少朵花。 

### 步骤 4：从右侧计算完成成本

 创建完整花园的最便宜的方法是完成已经最接近的花园`target`。 

我们从最大到最小的花园迭代并计算累计完成成本。 

例如：```
cost to complete flowers[i]
= target - flowers[i]
```我们保持完成最大所需的花朵总数`k`花园。 

### 步骤 5：枚举完整花园的数量

 对于每一个可能的数字`k`完整的花园：

 1. 计算完成它们所需的花朵。 
2. 如果成本超过`newFlowers`， 跳过。 
3. 否则，使用剩余的花来最大化不完全最小值。 

###第六步：二分查找最佳不完全最小值

 假设不完整的花园是：```
flowers[0:m-1]
```我们想要最高的价值`x < target`这样所有不完整的花园至少可以提高到`x`。 

使用二分查找：

 - 对于每位候选人`x`- 找出下面有多少个花园`x`- 计算提高它们的成本
 - 检查成本是否适合剩余的花朵

 ### 第 7 步：计算美度

 对于每个配置：```
beauty = complete_gardens * full + incomplete_minimum * partial
```跟踪最大值。 

### 为什么它有效

 该算法之所以有效，是因为：

 - 从最大值贪婪地完成花园可以最大限度地降低完成成本。 
- 对于不完整的花园，始终通过向上均匀地平整较小的花园来最大化最小值。 
- 排序确保这两种操作都能以最佳方式执行。 
- 枚举完整花园的所有可能数量保证我们不会错过之间的最佳平衡`full`和`partial`贡献。 

## Python 解决方案```python
from typing import List
import bisect

class Solution:
    def maximumBeauty(
        self,
        flowers: List[int],
        newFlowers: int,
        target: int,
        full: int,
        partial: int
    ) -> int:

        n = len(flowers)

        flowers = [min(x, target) for x in flowers]
        flowers.sort()

        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + flowers[i]

        # cost_complete[k] = flowers needed to make
        # the largest k gardens complete
        cost_complete = [0] * (n + 1)

        for k in range(1, n + 1):
            idx = n - k
            cost_complete[k] = (
                cost_complete[k - 1]
                + (target - flowers[idx])
            )

        def max_partial_value(end_index: int, remaining: int) -> int:
            """
            We consider flowers[0:end_index+1] as incomplete gardens.
            Return the maximum achievable minimum value.
            """

            if end_index < 0:
                return 0

            left = flowers[0]
            right = target - 1

            best = left

            while left <= right:
                mid = (left + right) // 2

                pos = bisect.bisect_left(
                    flowers,
                    mid,
                    0,
                    end_index + 1
                )

                needed = mid * pos - prefix[pos]

                if needed <= remaining:
                    best = mid
                    left = mid + 1
                else:
                    right = mid - 1

            return best

        answer = 0

        for complete_count in range(n + 1):

            complete_cost = cost_complete[complete_count]

            if complete_cost > newFlowers:
                continue

            remaining = newFlowers - complete_cost

            incomplete_end = n - complete_count - 1

            partial_value = max_partial_value(
                incomplete_end,
                remaining
            )

            total_beauty = (
                complete_count * full
                + partial_value * partial
            )

            answer = max(answer, total_beauty)

        return answer
```实施首先将所有花园封顶`target`，因为任何大于的值`target`出于评分目的，行为相同。 

然后对数组进行排序，从而实现高效的贪婪运算和二分搜索。 

前缀总和数组允许快速计算将多个花园提升到选定级别所需的花朵数量。 

这`cost_complete`数组预先计算需要多少朵花才能形成最大的花`k`花园竣工。 由于最大的花园需要最少的额外花卉，因此这始终是最佳选择。 

辅助函数`max_partial_value`对最佳可实现的最小不完整花园值执行二分搜索。 对于候选值`mid`，它计算需要多少朵花才能将所有较小的花园提高到至少`mid`。 

最后，我们枚举了所有可能的完整花园数量，并计算了该选择可实现的最佳美感。 

## 解决方案```go
package main

import (
	"sort"
)

func maximumBeauty(flowers []int, newFlowers int64, target int, full int, partial int) int64 {
	n := len(flowers)

	for i := 0; i < n; i++ {
		if flowers[i] > target {
			flowers[i] = target
		}
	}

	sort.Ints(flowers)

	prefix := make([]int64, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + int64(flowers[i])
	}

	costComplete := make([]int64, n+1)

	for k := 1; k <= n; k++ {
		idx := n - k
		costComplete[k] = costComplete[k-1] +
			int64(target-flowers[idx])
	}

	maxPartialValue := func(endIndex int, remaining int64) int64 {
		if endIndex < 0 {
			return 0
		}

		left := flowers[0]
		right := target - 1

		best := int64(left)

		for left <= right {
			mid := (left + right) / 2

			pos := sort.Search(
				endIndex+1,
				func(i int) bool {
					return flowers[i] >= mid
				},
			)

			needed := int64(mid*pos) - prefix[pos]

			if needed <= remaining {
				best = int64(mid)
				left = mid + 1
			} else {
				right = mid - 1
			}
		}

		return best
	}

	var answer int64 = 0

	for completeCount := 0; completeCount <= n; completeCount++ {

		completeCost := costComplete[completeCount]

		if completeCost > newFlowers {
			continue
		}

		remaining := newFlowers - completeCost

		incompleteEnd := n - completeCount - 1

		partialValue := maxPartialValue(
			incompleteEnd,
			remaining,
		)

		totalBeauty := int64(completeCount*full) +
			partialValue*int64(partial)

		if totalBeauty > answer {
			answer = totalBeauty
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的结构。 

最重要的区别是整数处理。 自从`newFlowers`可能达到`10^10`，所有的累计和和美容计算都使用`int64`。 

Go 没有提供内置的`bisect_left`， 所以`sort.Search`用于二分查找第一个至少具有值的索引`mid`。 

切片自然地用来代替 Python 列表，并且前缀和存储在`int64`切片以避免溢出。

 ## 边缘情况

 当所有花园都完工时，就会出现一种重要的边缘情况。 在这种情况下，不存在不完整的花园，因此部分贡献必须为零。 有缺陷的实现可能会错误地添加部分分数。 该解决方案自然地处理了这个问题，因为辅助函数返回`0`当没有不完整的花园时。 

当一些花园已经超过`target`。 由于值超出`target`不提供额外的好处，如果不限制它们可能会扭曲前缀总和和完成成本。 该实现显式地将每个值替换为`min(flowers[i], target)`加工前。 

第三个重要的边缘情况发生在`partial`远大于`full`。 在这种情况下，最优策略可能会故意让一个花园不完整，同时最大化其最小值。 总是试图最大化完整花园的贪婪策略在这里会失败。 通过枚举完整花园的所有可能数量，算法正确地考虑了这两种可能性。 

最终出现的微妙边缘情况非常大`newFlowers`。 自从`newFlowers`可能大到`10^10`，使用普通的 32 位整数可能会在多种语言中溢出。 因此，Go 实现使用`int64`用于所有累积计算和美容计算。
