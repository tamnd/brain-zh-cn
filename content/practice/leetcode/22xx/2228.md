[LeetCode 问题 2228](https://leetcode.com/problems/users-with-two-purchases-within-seven-days/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题需要识别在 7 天内至少进行过两次购买的用户。 我们被赋予了一个`Purchases`表与`purchase_id`,`user_id`， 和`purchase_date`。 每行代表用户进行的一次购买。 目标是返回有两次或多次购买的用户的 ID，其中任何两次购买之间的差异**最多 7 天**，包括两次购买发生在同一天的情况。 

输入代表所有用户的所有购买事件，其中`purchase_id`是独一无二的，同时`user_id`可能会出现多次。 预期输出是一个单列表`user_id`，按升序排序，仅包含满足 7 天内购买两次条件的用户。 

主要限制因素包括：

 1.`purchase_date`是一个`DATE`类型，因此日期算术必须考虑精确的日差。 
2、用户同一天可以有多次购买，即满足7天条件。 
3. 该表可能包含许多行，因此比较所有用户的所有购买对的简单方法可能会太慢。 

重要的边缘情况是：

 - 仅购买过一次的用户应被忽略。 
- 应包括同一天多次购买的用户。 
- 多次购买间隔超过 7 天的用户应被忽略。 

## 方法

 暴力方法需要将同一用户的每次购买与其他购买进行比较。 对于每个用户，我们将迭代所有的购买对，计算天差，并检查是否最多为 7。这种方法是正确的，因为它检查所有可能的对，但效率很低，特别是在用户有很多购买的情况下，因为它会导致每个用户进行 O(n²) 次比较。 

最佳解决方案的关键洞察是利用 SQL 中的**自连接**。 通过加入`Purchases`桌子本身在`user_id`并过滤`purchase_date`0和7之间的差异，我们可以高效地找到7天内的所有购买对。 使用`DISTINCT`确保每个用户在输出中仅出现一次。 订购方式`user_id`满足问题的要求。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个用户 O(n²) | O(1) | O(1) | 比较每个用户的所有购买对 |
 | 最优（自连接）| O(n log n) | O(n log n) | O(n) | 根据 user_id 将表与自身连接并按日期差异过滤 |

 ## 算法演练

 1. 首先选择`Purchases`表并将其别名为`p1`。 
2. 执行自连接`Purchases`作为`p2`条件是`p1.user_id = p2.user_id`。 
3. 过滤连接`p2.purchase_date >= p1.purchase_date`以避免重复或颠倒对。 
4. 添加一个额外的过滤器来区分`p2.purchase_date`和`p1.purchase_date`介于 0 到 7 天之间。 这可确保仅考虑 7 天内的购买。 
5. 选择不同的`user_id`来自过滤连接的值以删除重复项。 
6. 对结果进行排序`user_id`按升序排列。 

工作原理：这种方法保证给定用户的所有购买对都被检查一次，并且通过将日期差异限制在 0-7 天，我们只捕获满足问题要求的用户。 使用`DISTINCT`确保每个用户在结果中只出现一次，即使存在多个符合条件的对。 

## Python 解决方案```python
import sqlite3

def users_with_two_purchases_within_seven_days(conn: sqlite3.Connection):
    query = """
    SELECT DISTINCT p1.user_id
    FROM Purchases p1
    JOIN Purchases p2
      ON p1.user_id = p2.user_id
     AND p2.purchase_date >= p1.purchase_date
     AND julianday(p2.purchase_date) - julianday(p1.purchase_date) <= 7
    ORDER BY p1.user_id
    """
    return conn.execute(query).fetchall()
```Python 解决方案使用 SQLite 语法`julianday()`用于日期差异计算。 自连接识别每个用户的所有合格购买对，并且`DISTINCT`确保每个用户在输出中仅出现一次。 最后，`ORDER BY`对结果进行排序`user_id`。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
    "fmt"
)

func UsersWithTwoPurchasesWithinSevenDays(db *sql.DB) ([]int, error) {
    query := `
    SELECT DISTINCT p1.user_id
    FROM Purchases p1
    JOIN Purchases p2
      ON p1.user_id = p2.user_id
     AND p2.purchase_date >= p1.purchase_date
     AND julianday(p2.purchase_date) - julianday(p1.purchase_date) <= 7
    ORDER BY p1.user_id
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var result []int
    for rows.Next() {
        var userID int
        if err := rows.Scan(&userID); err != nil {
            return nil, err
        }
        result = append(result, userID)
    }
    return result, nil
}
```在 Go 中，我们执行相同的 SQL 自连接。 主要区别在于使用 Go`database/sql`包来执行查询并迭代`rows`扫描`user_id`值放入切片中。 错误处理和资源清理是显式完成的。

 **逐步执行**

 - 与 2022-03-13 比较 → 差异 0 ≤ 7 → 匹配

 2.`p1`=行（用户2，2022-03-20），`p2`= 2022-06-08 → 差异 > 7 → 丢弃
 3.`p1`= 行（用户 5）→ 仅购买一次→ 丢弃
 4.`p1`=行（用户7，2022-06-19），`p2`= 2022-06-19 → 差异 0 → 匹配

 ## 边缘情况

 第一个边缘情况是用户在同一天进行多次购买。 如果代码错误地要求严格的正差值，则可能会处理不当。 通过允许`p2.purchase_date >= p1.purchase_date`和 0day 差异，实现正确处理它。 

第二个边缘情况是用户恰好有两次购买，一次在第 1 天，一次在第 8 天。简单的实现可能包括它们，但日期差异过滤器正确地≤7 天
