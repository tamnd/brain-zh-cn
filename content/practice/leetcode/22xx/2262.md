[LeetCode 问题 2262](https://leetcode.com/problems/total-appeal-of-a-string/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、动态编程

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定字符串的**所有子字符串**的总吸引力`s`。 字符串的**吸引力**定义为它包含的**不同字符**的数量。 换句话说，对于每个可能的子串`s`，我们需要计算它有多少个唯一字母，并将所有子字符串中的这些计数相加。 

输入是单个字符串`s`由小写英文字母组成，长度可达`10^5`。 输出是一个整数，表示所有子字符串的吸引力总和。 

需要理解的要点：

 - 子字符串是连续的字符序列。 例如，`"abc"`有子串`"a"`,`"b"`,`"c"`,`"ab"`,`"bc"`,`"abc"`。 
- 生成所有子字符串并计算不同字符的简单方法会太慢，因为可能有大约`O(n^2)`长度字符串的子字符串`n`，并且计算每个子字符串中的不同字符需要额外的时间。 
- 边缘情况包括具有所有相同字符的字符串、单字符字符串以及每个字符都是唯一的字符串。 

目标是找到一种有效的方法来避免显式生成所有子字符串。 

## 方法

 **暴力方法**

 蛮力方法会生成每个子串`s`并通过使用一组来跟踪不同的字符来计算其吸引力。 这个方法是正确的，因为它直接统计了所有子串的吸引力。 然而，它的复杂性是`O(n^3)`最坏的情况：有`O(n^2)`子字符串并计算每个子字符串中的唯一字符最多需要`O(n)`。 

**最佳方法**

 最佳解决方案利用了我们可以**直接**计算每个字符对包含该字符的所有子字符串的贡献的见解。 具体来说，如果一个字符`c`出现在索引处`i`，那么它会影响在上一次出现之后开始的所有子字符串`c`并结束于或之后`i`。 使用哈希映射来跟踪每个字符的**最后一次出现**使我们能够计算线性时间内的总贡献。 这将复杂性降低到`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 生成所有子字符串并计算不同字符 |
 | 最佳 | O(n) | O(1) | O(1) | 跟踪每个字符的最后一次出现以计算贡献 |

 ## 算法演练

 1. 初始化哈希图`last_occurrence`存储每个字符出现的最后一个索引。 初始化`total_appeal`到`0`和`current_sum`到`0`。 
2. 迭代每个字符`c`在索引处`i`在字符串中。 
3. 计算包含的新子串的数量`c`作为一个新的独特角色：这是`(i - last_occurrence[c])`。 
4. 更新`current_sum`通过添加新子字符串的数量。`current_sum`表示以索引结尾的所有子字符串的总吸引力`i`。 
5. 更新`last_occurrence[c]`到`i`。 
6. 添加`current_sum`到`total_appeal`。 
7. 遍历字符串后，`total_appeal`包含所有子串的总吸引力。 

**为什么它有效**

 关键的不变量是`current_sum`始终反映以当前索引结尾的所有子字符串的吸引力总和。 通过添加新的不同事件的贡献，我们对每个子串仅进行一次计算。 跟踪最后一次出现可确保重复字符不会错误地增加计数。 

## Python 解决方案```python
class Solution:
    def appealSum(self, s: str) -> int:
        last_occurrence = {}
        total_appeal = 0
        current_sum = 0
        
        for i, c in enumerate(s):
            prev_index = last_occurrence.get(c, -1)
            current_sum += (i - prev_index)
            last_occurrence[c] = i
            total_appeal += current_sum
            
        return total_appeal
```**解释**

 我们使用`last_occurrence`跟踪每个字符的最后一个索引。 对于索引处的每个字符`i`，它作为新的不同字符贡献的子字符串的数量是`(i - prev_index)`。 我们将其积累在`current_sum`表示所有以 结尾的子串的吸引力总和`i`。 添加`current_sum`到`total_appeal`每一步都会给出最终结果。 

## 解决方案```go
func appealSum(s string) int64 {
    lastOccurrence := [26]int{}
    for i := range lastOccurrence {
        lastOccurrence[i] = -1
    }
    
    var totalAppeal int64 = 0
    var currentSum int64 = 0
    
    for i, c := range s {
        index := c - 'a'
        prevIndex := lastOccurrence[index]
        currentSum += int64(i - prevIndex)
        lastOccurrence[index] = i
        totalAppeal += currentSum
    }
    
    return totalAppeal
}
```**解释**

 Go 使用固定大小的数组`lastOccurrence`26个小写字母。 我们将所有条目初始化为`-1`处理尚未出现的字符。 其余逻辑反映了 Python 版本，其中`int64`用于防止大字符串溢出。

 ## 边缘情况

 **单个字符串**

 包含一个字符的字符串应返回上诉值 1，因为只有一个子字符串。 该算法正确地处理了这个问题，因为`last_occurrence`默认确保`(i - prev_index)`计算为`1`。 

**所有字符都相同**

 当字符串仅包含一个重复的唯一字符时，每个新字符仅对以其位置结尾的每个新子字符串贡献一次。 该算法线性计算贡献并正确求和，无需重复计算。 

**交错重复字符**

 对于像这样的字符串`"abac"`，重复的字符由其他字符分隔。 跟踪最后一次出现可确保重复字符的贡献仅考虑新出现的子字符串，并正确调整`current_sum`。
