[LeetCode 问题 2208](https://leetcode.com/problems/minimum-operations-to-halve-array-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 这个问题要求我们不断地减少数组中的数字，直到数组的总和减少**至少一半**，同时使用**最小操作次数**。 

在一次操作中，我们可以选择**当前数组中的任何数字**并将其替换为其值的一半。 重要的是，减少的数字保留在数组中，并且可以稍后再次选择。 这意味着诸如`20`可以成为`10`， 然后`5`， 然后`2.5`， 等等。 

输入是一个整数数组`nums`，其中每个值都是正数。 我们被要求返回所需的**最小减半操作次数**，以便总和的减少至少是原始总和的一半。 

思考这个问题的另一种方式是这样的：

 - 让`original_sum`是所有数字的总和。 
- 我们希望将总和至少减少`original_sum / 2`。 
- 每次操作都会贡献一些减少量。 
- 我们希望尽量减少操作次数。 

例如，如果原始总和是`40`，那么我们至少需要删除`20`从总数。 如果将一个数减半`x`将总和减少`x / 2`，那么选择较大的数字会立即产生较大的减少。 

### 了解限制

 限制条件很大：

 -`1 <= nums.length <= 10^5`-`1 <= nums[i] <= 10^7`重复扫描整个数组以查找最大数字的简单模拟会太慢，因为每个操作可能都需要一个`O(n)`搜索，并且可能需要许多操作。 

这些约束强烈表明我们需要一种有效的方法来重复检索和更新最大元素。 这是使用**堆（优先级队列）**的经典信号。 

### 重要的边缘案例

 一个重要的边缘情况是数组仅包含单个元素，例如`[10]`。 减半以来`10`一旦将总数减少`5`，恰好是原始总数的一半，答案是`1`。 

另一种情况是当所有数字都相等时，例如`[4,4,4,4]`。 幼稚的实现可能会低效地重复选择任意元素，而最佳解决方案应始终选择最大的可用值。 

一个特别棘手的情况是当一个数字在数组中占主导地位时，例如`[10000000,1,1,1]`。 反复将最大数减半显然是最佳选择，并且实现必须有效地处理对同一值的重复更新。 

该问题保证所有数字都是正整数。 这种保证很重要，因为每次减半操作总是将总和减少一个正数，这意味着实现目标的进展得到保证。 

## 方法

 ### 蛮力方法

 暴力解决方案将重复执行以下操作：

 1. 通过扫描整个数组，找到数组中最大的数。 
2.减半。 
3.更新运行缩减。 
4. 继续，直到至少删除原始金额的一半。 

这种方法是正确的，因为选择最大的可用值总是可以最大化从单个操作中获得的减少量。 然而，重复扫描数组以找到最大值的成本很高。 

假设有`k`运营。 寻找最大的元素成本`O(n)`每次都会导致总的复杂性`O(k * n)`。 自从`n`可以是`10^5`，这很快就会变得太慢。 

### 关键见解

 关键的观察是**每一步的最佳举措是将最大可用数字减半**。 

为什么？ 

将一个数字减半`x`总和减少`x / 2`。 因此，较大的数字会在单次操作中产生较大的减少量。 

这给了我们一个贪婪的策略：

 > 始终将当前最大值减半。 

剩下的挑战是在每次操作后有效地检索和更新最大数量。 

**最大堆**解决了这个问题：

 - 提取当前最大值`O(log n)`。 
- 重新插入其减半的值也需要`O(log n)`。 

Python 提供了最小堆，因此我们使用负数模拟最大堆。 在 Go 中，我们使用以下方法实现自定义最大堆`container/heap`。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k·n) | O(1) | O(1) | 重复扫描数组以查找最大值 |
 | 最佳 | O((n + k) log n) | O((n + k) log n) | O(n) | 使用最大堆有效跟踪最大元素 |

 这里，`k`表示执行的操作数。 

## 算法演练

 ### 最优贪心+堆算法

 1. 计算数组的总和并确定目标缩减量。 

让`total_sum`是所有元素的总和。 我们需要将总数至少减少`total_sum / 2`。 
2. 构建一个包含所有数字的最大堆。 

由于我们反复需要最大的数字，因此堆可以让我们有效地检索它。 在Python中，我们将负值推入最小堆以模拟最大堆行为。 
3.保持持续减量。 

我们不是在每次操作后重新计算数组总和，而是跟踪累计了多少总减少量。 
4. 反复从堆中移除最大值。 

这种贪婪的选择最大化了当前操作中获得的减少。 
5. 将所选数字减半。 

如果最大值是`x`，那么：

 - 获得的减少量为`x / 2`- 更新后的值变为`x / 2`6. 将减少量添加到运行总计中。 

我们继续下去，直到累计减少量至少达到`total_sum / 2`。 
7. 将减半的数字推回堆中。 

由于稍后可以再次选择该号码，因此它必须保持可用。 
8. 计算每次操作。 

一旦实现足够的减少，返回操作计数。 

### 为什么它有效

 正确性来自贪婪性质。 

在任何一步，将数字减半`x`总和减少`x / 2`。 由于较大`x`总是会产生更大的减少，就最小化操作而言，选择除最大可用值之外的任何值都不会更好。 

堆保证我们始终有效地选择最佳的可用选择。 由于每个操作都会最大限度地立即实现目标，因此该算法实现了最少的操作数。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def halveArray(self, nums: List[int]) -> int:
        total_sum = sum(nums)
        target_reduction = total_sum / 2

        max_heap = [-num for num in nums]
        heapq.heapify(max_heap)

        reduction = 0.0
        operations = 0

        while reduction < target_reduction:
            largest = -heapq.heappop(max_heap)

            halved = largest / 2
            reduction += halved

            heapq.heappush(max_heap, -halved)
            operations += 1

        return operations
```实施过程首先计算总和和所需的减少目标。 由于我们只关心将总和减少至少一半，因此不需要重复重新计算完整的数组总和。 

最大堆是使用负数创建的，因为 Python 的`heapq`模块仅支持最小堆。 通过存储`-num`，最小的负值对应于最大的原始数。 

在循环内部，最大的元素被提取并减半。 由于价值减半`x`将总和减少`x / 2`，我们直接将该金额添加到`reduction`。 

减半的值会被插入回堆中，因为在以后的操作中可以再次选择它。 循环继续，直到满足所需的减少阈值。 

## 解决方案```go
package main

import "container/heap"

type MaxHeap []float64

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(float64))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func halveArray(nums []int) int {
	totalSum := 0.0

	h := &MaxHeap{}

	for _, num := range nums {
		totalSum += float64(num)
		*h = append(*h, float64(num))
	}

	heap.Init(h)

	targetReduction := totalSum / 2
	reduction := 0.0
	operations := 0

	for reduction < targetReduction {
		largest := heap.Pop(h).(float64)

		halved := largest / 2
		reduction += halved

		heap.Push(h, halved)
		operations++
	}

	return operations
}
```Go 实现遵循相同的逻辑，但需要显式实现堆接口`container/heap`。 

与Python不同，Go不提供内置的最大堆，因此我们定义了一个自定义的`MaxHeap`输入并反转比较`Less()`通过使用`>`而不是`<`。 

由于减半后数值变成小数，`float64`是必要的。 使用整数会失去精度并产生不正确的结果。

 ## 边缘情况

 ### 单元素数组

 输入如`[10]`很重要，因为只有一种可能的选择。 有错误的实现可能会使逻辑过于复杂或无法正确终止。 减半以来`10`立即将总和减少`5`，正好是原始总数的一半，算法正确返回`1`。 

### 极大的主导价值

 像这样的数组`[10000000,1,1,1]`测试算法是否正确地优先考虑最大的数字。 糟糕的策略可能会浪费先减少少量数量的行动。 基于堆的贪心方法总是选择最大值，立即减半`10000000`，这已经超过了所需的减少阈值。 

### Repeated Selection of the Same Number

 一个案例如`[20,1,1]`很微妙，因为同一个数字应该被选择多次。 减半后`20`进入`10`，它可能仍然是最大值，应该重新选择。 一些不正确的实现忘记将减半的值推回到堆中，从而产生错误的结果。 该解决方案重新插入每个减半的数字，确保重复选择正确工作。 

### 相等的值

 数组如`[4,4,4,4]`确保实施正确处理联系。 由于每个数字都提供相同的减少，因此顺序并不重要。 堆自然会处理相同的优先级，并且算法仍然会产生最少数量的操作。
