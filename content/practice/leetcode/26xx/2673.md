 # LeetCode 2673 - 使二叉树中路径的成本相等

 ## 问题理解

 这个问题给了我们一个**完美的二叉树**`n`节点，其中每个节点都有关联的成本。 该树遵循严格的索引规则：节点`i`有一个左孩子在`2 * i`和一个右孩子`2 * i + 1`。 由于树是完美的，因此每个非叶节点恰好有两个子节点，并且所有叶节点都位于相同的深度。 

目标是使**每个根到叶路径的成本相等**。 路径成本只是从根到叶遇到的节点值的总和。 

我们可以将任何节点的成本增加`1`，任意次数。 挑战在于确定所需的**最小增量总数**，以便所有根到叶路径总和变得相同。 

一个重要的细节是我们只能**增加**值，而不能减少它们。 这意味着我们必须通过提高较小的路径来匹配较大的路径来仔细平衡路径总和。 由于增量会影响节点的所有后代路径，因此决定在何处增量对于最小化总成本至关重要。 

这些约束揭示了有关预期解决方案的重要信息。 自从`n`可以大到`10^5`，任何比线性或接近线性时间更差的解决方案都可能会超时。 反复调整路径的强力模拟成本太高。 事实上，树是**完美的**并且隐式地表示为数组，这表明可能存在自下而上的动态编程或贪婪结构可用。 

一些边缘情况值得预先考虑。 最小的有效树仅包含三个节点，这意味着只有两条路径可供比较。 另一个重要的情况是当所有路径和已经相等时，在这种情况下答案应该是`0`。 我们还应该考虑高度不平衡的子树成本，其中一侧需要许多增量才能匹配另一侧。 幸运的是，该问题保证了一个有效的完美二叉树，因此我们永远不需要处理丢失的子节点。 

## 方法

 ### 蛮力方法

 一个简单的策略是显式计算每个根到叶路径的总和，并重复增加较小路径中的节点，直到所有路径与最大路径匹配。 

一种方法是：

 1. 计算每个根到叶的路径总和。 
2. 求最大路径和。 
3. 对于每条较小的路径，确定需要多少增量。 
4. 尝试在节点之间分配增量，同时最小化重叠。 

这种方法很快就会变得困难，因为内部节点的增量同时影响多个路径。 对所有可能的增量组合进行强力搜索将是指数级的。 

即使基于模拟的方法也会变得昂贵，因为可能有多达`O(n)`叶子路径，每个路径都有`O(log n)`高度，并且反复重新计算路径总和会导致过多的开销。 

蛮力方法在概念上是正确的，因为它最终找到了有效的均衡，但对于`n = 10^5`。 

### 最优贪婪自下而上方法

 关键的见解是我们应该**从叶子向上**处理树。 

在每个内部节点，我们比较其左子树和右子树的总路径成本。 

如果一棵子树的路径和较小，我们必须将其增加到足以匹配较大的子树。 由于我们只能增加值，因此这种调整是不可避免的并且是局部最优的。 

假设：

 - 左子树路径成本=`L`- 右子树路径成本 =`R`然后：

 - 我们添加`abs(L - R)`到答案。 
- 家长贡献：```
cost[parent] + max(L, R)
```因为均衡后，两个子路径都等于较大的路径。 

这是可行的，因为每个子树在向上移动之前都可以独立平衡。 一旦子树被固定，从其父级查看时，它的行为就像单个均衡分支。 

这自然会导致使用数组表示进行自下而上的遍历。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数级或更差于 O(n²) | O(n) | 尝试显式调整路径总和，成本太高 |
 | 最佳| O(n) | O(1) | O(1) | 使用子树和自下而上贪婪平衡 |

 ## 算法演练

 1. 从最后一个内部节点开始，向上向根移动。 

由于叶子不需要处理，我们从索引开始`n // 2 - 1`在从零开始的索引中。 
2. 对于每个内部节点，识别其左子节点和右子节点。 

使用数组索引：

 - 左孩子 =`2 * i + 1`- 右孩子=`2 * i + 2`3. 比较左右子树的总成本。 

此时，两个子节点已经代表完全平衡的子树路径和，因为我们是自下而上处理的。 
4. 计算子子树总和之间的差。 

该节点所需的最小增量为：```
abs(left_sum - right_sum)
```必须将此金额添加到答案中，因为必须增加较小的一侧以匹配较大的一侧。 
5.更新当前节点的有效子树成本。 

由于两个子子树现在都等于较大的值，因此父子树的贡献变为：```
cost[i] += max(left_sum, right_sum)
```6. 继续直到到达根部。 

当我们完成时，每棵子树都已经平衡，累积的答案就是最小的增量数。 

### 为什么它有效

 正确性来自贪婪不变量。 

当处理一个节点时，两个子子树在内部已经完全平衡。 因此，唯一剩下的问题是平衡两个子路径总和。 

由于成本只会增加，因此使两个值相等的最低方法是提高较小的值以匹配较大的值。 任何其他策略都至少需要同样多的增量。 

因为每个子树在向上移动之前都已得到最优解，所以整个树是最优平衡的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minIncrements(self, n: int, cost: List[int]) -> int:
        total_increments = 0

        # Process from last internal node up to root
        for node_index in range(n // 2 - 1, -1, -1):
            left_child = 2 * node_index + 1
            right_child = 2 * node_index + 2

            left_cost = cost[left_child]
            right_cost = cost[right_child]

            # Add required increments to equalize children
            total_increments += abs(left_cost - right_cost)

            # Update current node with balanced subtree sum
            cost[node_index] += max(left_cost, right_cost)

        return total_increments
```实现直接遵循自下而上的思想。 

我们维护一个名为`total_increments`跟踪所需的最少操作。 

循环从最后一个内部节点开始向上移动。 由于树是完美的，每个内部节点总是有两个子节点，因此子节点索引很简单。 

对于每个节点，我们比较存储在其子节点处的子树成本。 因为我们自下而上处理，所以子值已经代表完全平衡的子树路径总和。 

我们将左子树和右子树之和之间的差值添加到答案中，因为必须增加较小的子树。 

最后，我们通过添加较大的子树总和来更新当前节点的成本。 这有效地将子树压缩为父树的单个平衡路径成本。 

当根被处理时，答案包含最小的总增量。 

## 解决方案```go
func minIncrements(n int, cost []int) int {
	totalIncrements := 0

	// Process from last internal node to root
	for nodeIndex := n/2 - 1; nodeIndex >= 0; nodeIndex-- {
		leftChild := 2*nodeIndex + 1
		rightChild := 2*nodeIndex + 2

		leftCost := cost[leftChild]
		rightCost := cost[rightChild]

		// Add increments needed to equalize children
		diff := leftCost - rightCost
		if diff < 0 {
			diff = -diff
		}

		totalIncrements += diff

		// Update parent subtree sum
		if leftCost > rightCost {
			cost[nodeIndex] += leftCost
		} else {
			cost[nodeIndex] += rightCost
		}
	}

	return totalIncrements
}
```Go 的实现与 Python 版本非常相似。 

由于 Go 没有内置`abs()`或者`max()`对于整数函数，我们手动计算绝对差并使用条件语句来选择较大的子树成本。 

该解决方案修改了`cost`就地切片，就像Python版本修改列表一样。 不需要额外的内存分配。 

这里整数溢出不是问题，因为最大累积路径成本仍然在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况是树已经平衡。 例如：```
cost = [5,3,3]
```有缺陷的实现可能会意外添加不必要的增量或错误地重新计算子树总和。 我们的实现正确地计算了差异`0`，所以答案保持不变。 

另一个重要的情况是严重不平衡的子树。 考虑：```
cost = [1,10,1]
```左子树比右子树大得多。 由于我们只能增加成本，因此算法必须提高较小的子树。 使用`abs(left - right)`保证添加准确所需的量。 

第三个重要的边缘情况是必须在多个级别同时进行平衡。 例如：```
cost = [1,5,2,2,3,3,1]
```该算法首先修复较低的子树，然后向上传播平衡和。 自上而下的实现可能会做出次优的决策，因为它还不知道最终的子树成本。 自下而上的处理确保每个家长都能收到准确的平衡值。 

最后，最小有效输入大小为`n = 3`值得注意的是。 由于只有一个内部节点，因此该算法仅运行一次迭代，并且无需特殊处理即可正确运行。
