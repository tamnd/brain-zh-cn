[LeetCode 问题 2646](https://leetcode.com/problems/minimize-the-total-price-of-the-trips/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、树、深度优先搜索、图论

 ## 解决方案

 ## 问题理解

 这个问题给了我们一棵无向树`n`节点。 每个节点都有一个与之相关的价格，并且我们还给出了节点对之间的多次旅行。 由于图是一棵树，因此任意两个节点之间都存在一条简单路径。 

对于每次旅行，我们都会沿着起始节点和结束节点之间的唯一路径行驶。 该行程的总成本是该路径上所有节点的价格之和。 

在任何旅行开始之前，我们可以选择一些节点并将其价格减半。 然而，有一个重要的限制：树中任何两个选定的节点都不能相邻。 这将问题转化为涉及独立节点选择的树优化问题。 

我们的目标是最大限度地降低所有行程的总成本。 

输入包括：

 -`n`, 节点数
 -`edges`，描述树结构
 -`price`， 在哪里`price[i]`是节点的价格`i`-`trips`，其中每个行程指定一个起始节点和结束节点

 输出是最优选择哪些非相邻节点应将其价格减半后的最小总价格。 

限制相对较小：

 -`n <= 50`-`trips.length <= 100`这些约束很重要，因为它们允许我们重复执行 DFS 遍历而无需担心性能问题。 一个复杂的解决方案`O(n^2)`或者`O(n^3)`是完全可以接受的。 

有几个重要的观察结果和边缘情况：

 - 因为图是一棵树，所以任意两个节点之间只有一条路径。 
- 一个节点可能会出现在多次行程中，因此将经常使用的节点减半可以产生大量节省。 
- 邻接限制意味着我们不能贪婪地将每个昂贵的节点减半。 
- 行程可以在同一节点开始和结束，从而产生长度为一的路径。 
- 由于所有价格都是偶数整数，减半总是产生整数值。 

关键的挑战是平衡全球储蓄，同时尊重非相邻约束。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试满足非相邻条件的每个可能的节点子集。 

对于每个有效子集：

 1、所选节点价格减半。 
2. 计算每次旅行的费用。 
3. 将所有旅行费用相加。 
4. 跟踪最小总数。 

为了检查子集是否有效，我们确保没有边连接两个选定的节点。 

为了计算行程成本，我们可以运行 DFS 来查找每次行程的唯一路径。 

这种方法是正确的，因为它详尽地探索了所有合法的节点选择。 最终，它将评估最佳配置。 

然而，它太慢了。 有`2^n`节点的子集。 虽然`n = 50`对于多项式算法来说很小，对于指数枚举来说却很大。 

### 最佳方法

 重要的见解是，行程仅与每个节点使用的次数有关。 

假设节点`i`出现在所有旅行路径中`freq[i]`次。 然后：

 - 无需减半，节点`i`贡献：`freq[i] * price[i]`- 减半，节点`i`贡献：`freq[i] * (price[i] / 2)`那么问题就变成了：

 > 选择一组不相邻的节点以最大化总节省。 

这是一个经典的树动态规划问题，特别是“树上的最大加权独立集”模式。 

我们首先计算每个节点在所有行程路径中出现的次数。 然后我们进行树DP：

 -`dp[node][0]`= 如果该节点未减半，则最小成本
 -`dp[node][1]`= 该节点减半时的最小成本

 如果一个节点被减半，则它的子节点都不能被减半。 

这将问题转换为干净的 DFS 动态规划解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n × n × 行程) | O(n) | 枚举所有有效子集 |
 | 最佳 | O(n × 行程 + n) | O(n) | 计算节点频率，然后执行树DP|

 ## 算法演练

 ### 第 1 步：构建邻接表

 由于输入图是一棵树，因此我们使用邻接表来表示它。 

这允许在连接的节点之间进行高效的 DFS 遍历。 

### 步骤2：统计每个节点被使用的次数

 我们创建一个数组：```
frequency[i]
```这存储了经过节点的行程次数`i`。 

对于每次旅行：

 1. 运行 DFS`start`到`end`2.恢复唯一路径
 3. 增加该路径上每个节点的频率

 因为图是一棵树，所以 DFS 总是准确地找到一条有效的简单路径。 

### 步骤3：将节点使用量转换为总贡献量

 一旦频率已知：

 - 节点正常成本：`frequency[node] * price[node]`- 成本减半：`frequency[node] * price[node] // 2`现在旅行本身不再重要。 我们只关心最小化总节点贡献。 

### 第四步：给树生根

 我们在节点处任意建立树根`0`。 

这使我们能够干净地执行父子 DP 转换。 

### 步骤 5：执行树 DP

 对于每个节点，计算两个状态：

 -`not_halved`-`halved`如果当前节点没有减半：

 - 儿童可以减半或不减半
 - 为每个孩子取两个状态的最小值

 如果当前节点减半：

 - 孩子不能减半
 - 只使用儿童`not_halved`状态

 ### 第 6 步：返回最小值

 从根本上来说：```
min(not_halved, halved)
```这就是全局最优答案。 

### 为什么它有效

 该算法之所以有效，是因为总行程成本可以分解为独立的节点贡献。 

统计节点频率后，每个节点贡献固定金额，仅取决于是否减半。 节点之间唯一的交互是邻接限制。 

这将问题转化为在具有父子约束的树上选择最小成本配置，这正是树 DP 最佳解决的问题。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumTotalPrice(
        self,
        n: int,
        edges: List[List[int]],
        price: List[int],
        trips: List[List[int]]
    ) -> int:
        
        graph = [[] for _ in range(n)]
        
        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)
        
        frequency = [0] * n
        
        def find_path(node: int, parent: int, target: int, path: List[int]) -> bool:
            path.append(node)
            
            if node == target:
                return True
            
            for neighbor in graph[node]:
                if neighbor == parent:
                    continue
                
                if find_path(neighbor, node, target, path):
                    return True
            
            path.pop()
            return False
        
        for start, end in trips:
            path = []
            find_path(start, -1, end, path)
            
            for node in path:
                frequency[node] += 1
        
        def dfs(node: int, parent: int):
            not_halved = frequency[node] * price[node]
            halved = frequency[node] * (price[node] // 2)
            
            for neighbor in graph[node]:
                if neighbor == parent:
                    continue
                
                child_not_halved, child_halved = dfs(neighbor, node)
                
                not_halved += min(child_not_halved, child_halved)
                
                halved += child_not_halved
            
            return not_halved, halved
        
        return min(dfs(0, -1))
```实现首先构建树的邻接表表示。 

接下来，该算法计算节点频率。 对于每次行程，DFS 都会找到起始节点和结束节点之间的唯一路径。 该路径上的每个节点的频率都会增加。 

一旦频率已知，算法就会使用另一个 DFS 遍历来执行树 DP。 

对于每个节点：

 -`not_halved`当该节点保持其原始价格时，存储最小子树成本。 
-`halved`存储当该节点的价格减半时的最小子树成本。 

当一个节点减半时，它的子节点不能减半，因为相邻的折扣节点是被禁止的。 

最后，根返回两种可能状态中的最小值。 

## 解决方案```go
package main

func minimumTotalPrice(n int, edges [][]int, price []int, trips [][]int) int {
	graph := make([][]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	frequency := make([]int, n)

	var findPath func(int, int, int, *[]int) bool

	findPath = func(node int, parent int, target int, path *[]int) bool {
		*path = append(*path, node)

		if node == target {
			return true
		}

		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			if findPath(neighbor, node, target, path) {
				return true
			}
		}

		*path = (*path)[:len(*path)-1]
		return false
	}

	for _, trip := range trips {
		start := trip[0]
		end := trip[1]

		path := []int{}

		findPath(start, -1, end, &path)

		for _, node := range path {
			frequency[node]++
		}
	}

	var dfs func(int, int) (int, int)

	dfs = func(node int, parent int) (int, int) {
		notHalved := frequency[node] * price[node]
		halved := frequency[node] * (price[node] / 2)

		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			childNotHalved, childHalved := dfs(neighbor, node)

			if childNotHalved < childHalved {
				notHalved += childNotHalved
			} else {
				notHalved += childHalved
			}

			halved += childNotHalved
		}

		return notHalved, halved
	}

	a, b := dfs(0, -1)

	if a < b {
		return a
	}

	return b
}
```Go 的实现与 Python 版本非常相似。 

主要区别在于 DFS 路径构建期间的显式切片管理。 由于切片是按值传递的，因此路径切片是按指针传递的，因此可以正确保留递归修改。 

Go 还缺乏元组语法，因此多个返回值用于 DP 状态。 

整数溢出不是一个问题，因为最大可能的答案相对于 Go 的整数范围来说很小。

 ## 边缘情况

 一个重要的边缘情况是起始节点和结束节点相同的行程。 在这种情况下，路径仅包含一个节点。 有缺陷的实现可能会错误地假设路径始终包含边缘。 该解决方案中的 DFS 路径构造正确地处理了这个问题，因为当当前节点等于目标时它会立即返回。 

另一个重要的例子是链形树。 在线性结构中，除了末端之外的每个节点都有两个邻居，这使得邻接约束更具限制性。 贪婪策略在这里经常会失败，因为将一个节点减半会阻止相邻高价值节点减半。 树 DP 通过其父子状态转换自然地处理这个问题。 

第三种关键边缘情况是一个节点出现在多次行程中。 这些节点对总成本的贡献不成比例，使它们成为有吸引力的减半候选者。 然而，如果相邻节点也有很大的贡献，选择局部最大的节省可能不会产生全局最优。 DP 探索每个子树的两种可能性，确保找到全局最小配置。
