 ## 解决方案

 ## 问题理解

 这个问题要求我们实现一种机制来运行一个产生承诺的生成器，并具有随时取消执行的额外能力。 关键任务是以等待每个产生的 Promise 并将其结果发送回生成器的方式来管理生成器的异步执行。 如果任何 Promise 被拒绝，则必须将错误扔回生成器，生成器可以选择处理它。 

功能`cancellable`返回一个元组：a`cancel`函数和一个`promise`。 这`cancel`函数在调用时应该注入一个`"Cancelled"`错误进入生成器。 如果生成器捕获它，则可以继续执行； 如果未捕获，返回的承诺将立即拒绝。 返回的承诺`cancellable`使用生成器的返回值进行解析，或者使用生成器抛出的第一个未捕获的错误进行拒绝，包括取消。 

输入始终是产生承诺的生成器对象。 生成器可能会立即返回、依次生成多个 Promise 或抛出错误。 生成器还可以在内部捕获错误，从而允许在取消时返回部分结果。 这些约束确保我们只需要处理产生承诺的生成器，并且取消会在合理的时间范围内发生（`0 ≤ cancelledAt ≤ 1000`）。 

重要的边缘情况包括：立即返回的生成器、立即抛出的生成器、在承诺中发生取消以及生成器内捕获的错误与未捕获的错误。 

## 方法

 蛮力方法是使用手动顺序消耗生成器`.next()`和`.throw()`，在继续之前等待每个承诺。 取消时，我们可以抛出`"Cancelled"`直接报错。 虽然这在功能上可行，但手动管理异步排序可能会变得冗长且容易出错。 这种方法本质上是模仿什么`async/await`已经这样做了，但没有一个干净的抽象。 

最佳方法使用递归`nextStep`处理每个承诺解决或拒绝并将结果传播到生成器的函数。 我们维护一个取消标志，所以如果`cancel()`被调用时，我们立即将取消错误抛出到生成器中。 这种方法保证了正确处理承诺解决、拒绝和捕获的异常，而无需除了简单标志之外的额外簿记。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 顺序迭代生成器并手动处理 Promise 解析 |
 | 最佳 | O(n) | O(1) | O(1) | 使用取消标志递归处理产生的承诺并正确传播错误 |

 ## 算法演练

 1. 初始化一个`cancelled`标记为`false`跟踪取消函数是否已被调用。 
2. 定义一个`cancel`设置的函数`cancelled = true`。 
3.定义异步函数`nextStep(value, isError)`它接受下一个值发送到生成器和一个指示是否应将其作为错误抛出的标志。 
4. 内部`nextStep`，致电`generator.next(value)`或者`generator.throw(value)`根据`isError`。 
5. 如果生成器完成，则使用其返回值解析外部 Promise。 
6. 如果生成器产生承诺，请附加`.then()`和`.catch()`处理程序：

 - 开`.then()`,递归调用`nextStep`与解析值。 
- 在`.catch()`,递归调用`nextStep`与错误和`isError=true`。 
7. 继续之前，检查`cancelled`旗帜。 如果设置，请致电`nextStep("Cancelled", true)`。 如果生成器捕获它，则继续； 否则，拒绝承诺。 
8.返回一个元组`[cancel, promise]`， 在哪里`promise`将第一个调用包装到`nextStep()`并适当地解决/拒绝。 

为什么它有效：在任何时候，生成器一次只处理一个 Promise。 错误（包括取消）会作为异常或解析值正确传播，具体取决于生成器是否处理它们。 这保证了最终返回的 Promise 始终反映正确的最终状态。 

## Python 解决方案```python
from typing import Any, Tuple, Callable, Generator
import asyncio

def cancellable(generator: Generator) -> Tuple[Callable[[], None], asyncio.Future]:
    cancelled = False
    loop = asyncio.get_event_loop()
    result_future = loop.create_future()

    def cancel():
        nonlocal cancelled
        cancelled = True

    async def next_step(value: Any = None, is_error: bool = False):
        nonlocal cancelled
        try:
            if is_error:
                yielded = generator.throw(value)
            else:
                yielded = generator.send(value) if value is not None else next(generator)
        except StopIteration as e:
            if not result_future.done():
                result_future.set_result(e.value)
            return
        except Exception as e:
            if not result_future.done():
                result_future.set_exception(e)
            return

        if cancelled:
            await next_step("Cancelled", True)
            return

        try:
            result = await yielded
            await next_step(result, False)
        except Exception as e:
            await next_step(e, True)

    asyncio.ensure_future(next_step())
    return cancel, result_future
```这个实现首先定义了一个`cancel`设置标志的函数。 这`next_step`函数管理发送值或向生成器抛出错误。 每一个兑现的承诺都在等待。 如果发生取消，`"Cancelled"`被扔进发电机。 外层`Future`一旦生成器完成或抛出未捕获的异常，就会解决或拒绝。 

## 解决方案```go
package main

import (
    "errors"
    "sync"
)

type Generator interface {
    Next(interface{}) (interface{}, bool, error)
    Throw(error) (interface{}, bool, error)
}

func Cancellable(generator Generator) (func(), chan interface{}) {
    cancelled := false
    var mu sync.Mutex
    done := make(chan interface{}, 1)

    cancel := func() {
        mu.Lock()
        cancelled = true
        mu.Unlock()
    }

    go func() {
        var value interface{}
        var isErr bool
        for {
            mu.Lock()
            if cancelled {
                value, isErr, _ = generator.Throw(errors.New("Cancelled"))
                cancelled = false
            } else if isErr {
                value, isErr, _ = generator.Throw(value.(error))
            } else {
                value, isErr, _ = generator.Next(value)
            }
            mu.Unlock()

            if !isErr {
                done <- value
                return
            }
        }
    }()

    return cancel, done
}
```在 Go 中，我们使用`Generator`与接口`Next`和`Throw`方法。 Goroutine 按顺序处理产生的值和错误。 互斥体确保安全访问`cancelled`旗帜。 这`done`通道携带最终解析值。
