 # LeetCode 2668 - 查找最新工资

 ## 问题理解

 这个问题给了我们一个名为`Salary`that stores employee salary records. 每个员工可能会出现多次，因为较早的工资记录仍保留在表中。 关键的观察是，工资每年都会增加，这意味着员工的最大工资值必须代表他们最近的工资。 

The table contains the following columns:

 | 专栏 | 意义|
 | ---| ---|
 |`emp_id`| 唯一的员工标识符 |
 |`firstname`| 员工名字 |
 |`lastname`| 员工姓氏 |
 |`salary`| 员工薪资|
 |`department_id`| 部门标识符|

 主键是`(emp_id, salary)`，这意味着同一员工不能有重复的工资值。 

目标是为每个员工返回一行，特别是包含该员工最新工资的行。 由于工资只会随着时间的推移而增加，因此最新工资只是与每个相关的最高工资`emp_id`。 

输出必须包括：

 -`emp_id`-`firstname`-`lastname`-`salary`-`department_id`结果还必须按以下方式排序`emp_id`按升序排列。 

重要的细节是`salary`列存储为`varchar`，不是整数。 在 SQL 中，这有时会产生问题，因为字符串比较是按字典顺序而不是数字进行比较。 例如：

-`"90000"`大于`"79632"`- 但`"100000"`如果未正确转换，可能会错误地与较小长度的字符串进行比较

 因此，一个稳健的解决方案应该在找到最大值时对工资进行数字化处理。 

需要考虑一些重要的边缘情况：

 - 只有一份工资记录的员工
 - 拥有多个薪资记录的员工
 - 以字符串形式存储的工资
 - 薪资价值高
 - 属于不同部门的员工

 该问题保证工资严格地随着时间的推移而增加，因此最高工资唯一地标识最新记录。 

## 方法

 ### 蛮力方法

 暴力解决方案将独立检查每个员工并扫描整个表格以找到他们的最高薪水。 

该算法的工作原理如下：

 1. 收集所有不同的员工 ID。 
2. 对于每个员工 ID，扫描表中的每一行。 
3. 跟踪该员工遇到的最高工资。 
4. 输出包含最高工资的行。 

这种方法是正确的，因为每个员工的最新工资是与该员工相关的最大工资值。 通过检查每个员工的所有行，我们保证最终找到最大值。 

然而，这种解决方案效率低下，因为表被重复扫描。 如果有`n`行和`k`员工，复杂性变成`O(n * k)`。 在最坏的情况下，几乎每一行都属于不同的员工，这种方法`O(n²)`。 

### 最佳方法

 关键的见解是 SQL 数据库已经针对分组和聚合操作进行了优化。 

我们可以：

 1. 行分组依据`emp_id`2.计算每个员工的最高工资
 3. 将结果连接回原表以检索剩余的列

 这种方法在聚合过程中只处理一次数据，使其显着更加高效和干净。 

由于最新工资始终是最高工资，因此聚合会直接识别每个员工的正确行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描表中的每个员工 |
 | 最佳| O(n) | O(n) | 使用分组和聚合有效地找到最高工资 |

 ## 算法演练

 ### 最优 SQL 算法

 1. 首先，将所有行分组`emp_id`。 

分组使我们能够独立处理每个员工。 每个员工可能有多条工资记录，但我们只想要最新的一条。 
2. 对于每个员工组，计算最高工资。 

由于工资随着时间的推移而增加，因此最高工资必须与最新记录相对应。 
3. 如有必要，将工资值转换为数字形式。 

这`salary`列存储为字符串（`varchar`）。 数字比较可确保正确的排序。 
4. 将结果存储为临时派生表。 

该表包含：

 -`emp_id`-`max_salary`5. 将派生表与原始表连接起来`Salary`桌子。 

这使我们能够检索包含以下内容的完整行：

 - 名字
 - 姓氏
 - 部门编号
 - 工资
 6. 使用以下两者来匹配行：

 -`emp_id`- 最高工资
 7. 对最终输出进行排序`emp_id`上升。 

### 为什么它有效

 该算法依赖于员工工资始终随时间增加的保证。 因此，最新工资始终是该员工的最高工资。 按员工分组并选择最高工资唯一标识所需的行。 连接回原始表可恢复剩余的员工详细信息。 

## Python 解决方案

 尽管这是一个数据库问题并且预期提交的是 SQL，但以下 Python 实现以编程方式演示了相同的逻辑。```python
from typing import List, Dict

class Solution:
    def findLatestSalaries(self, salary_records: List[Dict]) -> List[Dict]:
        latest_salary = {}

        for record in salary_records:
            emp_id = record["emp_id"]
            salary = int(record["salary"])

            if (
                emp_id not in latest_salary
                or salary > int(latest_salary[emp_id]["salary"])
            ):
                latest_salary[emp_id] = record

        result = list(latest_salary.values())
        result.sort(key=lambda record: record["emp_id"])

        return result
```该实现使用一个字典作为键`emp_id`。 

当我们迭代每条记录时：

 - 我们将工资转换为整数
 - 我们将其与当前存储的工资进行比较
 - 如果新的工资更大，我们将替换存储的记录

 最后：

 - 字典包含每位员工的最新薪资记录
 - 我们将字典值转换为列表
 - 我们对结果进行排序`emp_id`这反映了 SQL 聚合解决方案中使用的相同逻辑。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
)

type SalaryRecord struct {
	EmpID        int
	Firstname    string
	Lastname     string
	Salary       string
	DepartmentID string
}

func findLatestSalaries(records []SalaryRecord) []SalaryRecord {
	latestSalary := make(map[int]SalaryRecord)

	for _, record := range records {
		currentSalary, _ := strconv.Atoi(record.Salary)

		existing, exists := latestSalary[record.EmpID]

		if !exists {
			latestSalary[record.EmpID] = record
			continue
		}

		existingSalary, _ := strconv.Atoi(existing.Salary)

		if currentSalary > existingSalary {
			latestSalary[record.EmpID] = record
		}
	}

	result := make([]SalaryRecord, 0, len(latestSalary))

	for _, record := range latestSalary {
		result = append(result, record)
	}

	sort.Slice(result, func(i, j int) bool {
		return result[i].EmpID < result[j].EmpID
	})

	return result
}
```Go 实现遵循与 Python 版本相同的总体策略。 

一些特定于 Go 的细节包括：

 - 使用`map[int]SalaryRecord`用于员工查找
 - 使用`strconv.Atoi()`将工资字符串转换为整数
 - 使用`sort.Slice()`对最终结果进行排序
 - 记录存储的显式结构定义

 Go 比 Python 需要更显式的类型处理，但底层算法保持不变。 

## SQL 解决方案```sql
SELECT 
    s.emp_id,
    s.firstname,
    s.lastname,
    s.salary,
    s.department_id
FROM Salary s
JOIN (
    SELECT 
        emp_id,
        MAX(CAST(salary AS UNSIGNED)) AS max_salary
    FROM Salary
    GROUP BY emp_id
) latest
ON s.emp_id = latest.emp_id
AND CAST(s.salary AS UNSIGNED) = latest.max_salary
ORDER BY s.emp_id;
```该解决方案首先计算每个员工的最高工资，然后将结果连接回原始表以检索相应的员工信息。 

这`CAST(... AS UNSIGNED)`确保工资按数字而不是按字典顺序进行比较。

 ## 边缘情况

 ### 只有一份工资记录的员工

 有些员工在表中只出现一次。 幼稚的实现可能会错误地假设每个员工都有多行，并意外地排除单记录员工。 

此实现可以自然地处理这种情况，因为第一个遇到的记录成为该员工的当前最高工资。 

### 工资存储为字符串

 的`salary`列是一个`varchar`，这产生了一个微妙但重要的问题。 字符串比较的行为与数字比较不同。 

例如：

-`"90000"`>`"79632"`工作正常
 - 但是`"100000"`按字典顺序比较可能会产生不正确的结果

 该实现通过在比较之前显式地将工资值转换为整数来避免此问题。 

### 记录未按时间排序

 不保证行按时间顺序出现。 假设最后一行是最新行的简单解决方案将会失败。 

此实现不依赖于输入顺序。 相反，它始终以数字方式计算最高工资，无论行顺序如何，都保证正确性。 

### 多名员工享有相同的薪水

 不同的员工可能有相同的工资金额。 有缺陷的分组策略可能会意外地错误地合并员工。 

实施组严格按`emp_id`，即使工资值重叠，也确保每个员工都得到独立处理。
