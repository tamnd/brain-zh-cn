[LeetCode 问题 2644](https://leetcode.com/problems/find-the-maximum-divisibility-score/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们从除数列表中识别相对于给定数字数组具有**最大整除分数**的整数。 除数的整除分数定义为中元素的数量`nums`可以被该除数整除。 简单来说，对于每个除数，我们计算数组中有多少个数字`nums`可以被它整除。 在所有除数中，我们想要计数最高的除数，如果存在平局，我们返回最小的除数。 

输入由两个整数数组组成：`nums`和`divisors`。 每个整数最大可以为 10^9，但数组的长度上限为 1000。约束足够小，可以通过暴力解决方案检查每个数字`nums`尽管优化的解决方案很简单，但针对每个除数都是可行的。 

关键边缘情况包括除数没有匹配`nums`，具有相同最大分数的多个除数，以及所有数字都在的情况`nums`可以被一个除数整除。 该问题保证非空数组和正整数，因此我们不需要处理零或空输入。 

## 方法

 **暴力方法**迭代每个除数并检查中的每个数字`nums`看看它是否可以整除。 这是正确的，因为它直接计算每个除数的整除分数。 然而，这需要 O(n * m) 次操作，其中 n 是`nums`m 是长度`divisors`。 给定约束（均最多 1000），这会导致最多 1,000,000 次检查，这对于该问题来说是可以接受的。 

**最佳方法**本质上与蛮力相同，因为问题规模很小。 不需要像筛选或散列这样复杂的技术，因为直接的双重迭代就足够了。 关键是在迭代时保持最大分数和相应的最小除数，确保正确处理平局。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(1) | O(1) | 检查每个除数与所有数字`nums`, 追踪最高分 |
 | 最佳 | O(n * m) | O(1) | O(1) | 与蛮力法相同，但具有最小除数的决胜逻辑 |

 ## 算法演练

 1.初始化两个变量：`max_score`为零以跟踪迄今为止发现的最高整除分数，并且`best_divisor`到一个很大的数字，以确保第一次比较会更新它。 
2. 迭代每个除数`divisors`。 
3. 对于当前除数，将计数器初始化为零。 
4. 迭代中的每个数字`nums`如果该数字可以被当前除数整除，则增加计数器。 
5. 计数结束后，将计数器与`max_score`。 如果更高，请更新`max_score`并设置`best_divisor`到当前除数。 如果相等则更新`best_divisor`仅当当前除数小于现有除数时`best_divisor`。 
6. 继续此过程，直到计算完所有除数。 
7. 返回`best_divisor`结果。 

**为什么有效：** 在每一步中，我们都会维护最大整除分数和实现该分数的最小除数。 这个不变量确保在处理完所有除数后，`best_divisor`根据问题的要求包含正确的值。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxDivScore(self, nums: List[int], divisors: List[int]) -> int:
        max_score = 0
        best_divisor = float('inf')
        
        for divisor in divisors:
            count = 0
            for num in nums:
                if num % divisor == 0:
                    count += 1
            
            if count > max_score or (count == max_score and divisor < best_divisor):
                max_score = count
                best_divisor = divisor
        
        return best_divisor
```**实现演练：**我们从初始化开始`max_score`和`best_divisor`。 对于每个除数，我们计算它能整除多少个数字。 如果这个计数超过了当前的最大值，我们就会更新这两个值`max_score`和`best_divisor`。 如果有平局，我们只更新`best_divisor`如果新除数较小，则确保正确的平局打破行为。 

## 解决方案```go
func maxDivScore(nums []int, divisors []int) int {
    maxScore := 0
    bestDivisor := int(1e9 + 1) // initialize larger than any possible divisor
    
    for _, divisor := range divisors {
        count := 0
        for _, num := range nums {
            if num % divisor == 0 {
                count++
            }
        }
        if count > maxScore || (count == maxScore && divisor < bestDivisor) {
            maxScore = count
            bestDivisor = divisor
        }
    }
    return bestDivisor
}
```**Go 特定注释：** 我们使用`1e9 + 1`初始化`bestDivisor`以确保第一个除数更新它。 Go 不需要切片的显式类型提示，我们将所有数字处理为`int`因为约束在安全范围内。

 ## 边缘情况

 一个重要的边缘情况是当**所有除数的得分为零**时，这意味着其中没有数字`nums`可以被任何除数整除。 由于平局决胜逻辑，该实现正确返回最小除数，当计数相等（包括零）时会触发该逻辑。 

另一个边缘情况是**多个除数共享最大分数**。 如果不仔细处理，简单的实现可能会返回最后遇到的除数。 通过显式检查`divisor < best_divisor`当分数相同时，我们确保选择最小的一个。 

第三种边缘情况涉及 **非常大的数字**，接近 10^9。 Python 原生处理大整数，因此不存在溢出风险。 在 Go 中，解决方案使用`int`，可以安全地容纳
