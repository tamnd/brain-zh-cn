 ## 解决方案

 ## 问题理解

 这个问题要求我们围绕异步函数实现一个**时间限制的包装器**。 我们给定一个输入函数`fn`返回一个 Promise 和一个时间限制`t`以毫秒为单位。 任务是返回一个执行的新函数`fn`但强制执行最大执行时间。 如果`fn`之前解决`t`毫秒，包装器应解析为相同的值。 如果`fn`需要比`t`毫秒，包装器应该拒绝`"Time Limit Exceeded"`。 

输入`fn`可以接受任意数量的参数（`inputs`数组），它可能会解析或拒绝。 时间限制`t`可以为零，这意味着如果执行没有立即完成，函数应该立即拒绝。 限制很小，最多有 10 个参数，最大时间限制为 1000 毫秒，因此性能并不是一个大问题。 

重要的边缘情况包括`fn`立即投掷，`fn`精确地在边界处求解`t`,`t = 0`， 和`fn`被无参数地调用。 该问题保证了`fn`总是返回一个 Promise，所以我们不需要直接处理同步返回值。 

## 方法

 天真的方法是重复轮询 Promise 或在内部手动设置超时`fn`检查是否能及时解决。 这可行，但很麻烦、容易出错并且不必要地复杂。 它也没有利用 Promise 的本机并发机制。 

最佳方法是使用`Promise.race`。 这个内置方法允许我们同时运行两个 Promise，并以先完成者为准来解决或拒绝。 我们可以和原来的赛车比赛`fn`Promise 反对超时 Promise 在超时后拒绝`t`毫秒。 这提供了一个简洁而强大的解决方案，无需手动跟踪经过的时间或重复检查。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(1) | O(1) | O(1) | O(1) | 手动轮询或跟踪经过的时间以强制超时，冗长且容易出错 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用`Promise.race`运行`fn`和超时同时发生，在所有情况下都能正确解决 |

 ## 算法演练

 1. 定义一个新函数`limitedFn`其参数与`fn`。 
2. 内部`limitedFn`，创建一个 **超时承诺** 并拒绝`"Time Limit Exceeded"`后`t`毫秒。 这可以使用以下方法完成`setTimeout`。 
3.调用原件`fn`与提供的参数。 这会返回一个正常解析或拒绝的 Promise。 
4. 使用`Promise.race`同时运行原函数的 Promise 和超时 Promise。 谁先解决就决定结果。 
5. 返回结果`Promise.race`作为结果`limitedFn`。 
6. 正常处理所有决议和拒绝； 不需要额外的逻辑，因为`Promise.race`确保只有第一个解决的 Promise 才是重要的。 

**为什么它有效：** 关键的不变量是`Promise.race`保证使用第一个结算 Promise。 通过创建一个超时 Promise，在恰好之后拒绝`t`毫秒，我们确保任何函数花费的时间超过`t`会被自动拒绝。 解决速度更快的函数会成功，因此所有要求都得到满足。 

## Python 解决方案```python
from typing import Any, Callable
import asyncio

def timeLimit(fn: Callable[..., asyncio.Future], t: int) -> Callable[..., asyncio.Future]:
    async def limited_fn(*args: Any) -> Any:
        timeout_task = asyncio.create_task(asyncio.sleep(t / 1000))
        func_task = asyncio.create_task(fn(*args))
        done, pending = await asyncio.wait(
            {timeout_task, func_task}, return_when=asyncio.FIRST_COMPLETED
        )
        for task in pending:
            task.cancel()
        if func_task in done:
            return await func_task
        else:
            raise Exception("Time Limit Exceeded")
    return limited_fn
```实现首先转换超时时间`t`到秒因为`asyncio.sleep`预计秒。 函数调用和超时都包装在任务中并传递给`asyncio.wait`和`FIRST_COMPLETED`。 一旦其中一个完成，另一个就会被取消。 如果函数先完成，我们等待它的结果。 否则，我们提出一个`"Time Limit Exceeded"`例外。 

## 解决方案```go
package main

import (
    "errors"
    "time"
)

func TimeLimit(fn func(...any) (any, error), t int) func(...any) (any, error) {
    return func(args ...any) (any, error) {
        result := make(chan any, 1)
        errChan := make(chan error, 1)

        go func() {
            res, err := fn(args...)
            if err != nil {
                errChan <- err
            } else {
                result <- res
            }
        }()

        select {
        case res := <-result:
            return res, nil
        case err := <-errChan:
            return nil, err
        case <-time.After(time.Duration(t) * time.Millisecond):
            return nil, errors.New("Time Limit Exceeded")
        }
    }
}
```在Go中，通道用于收集函数结果或错误。 一个`select`语句等待函数结果、错误或超时。 超时是通过以下方式强制执行的`time.After`。 这可以处理所有边缘情况，而不需要额外的同步原语。 

## 工作示例

 **示例1：**`fn`100ms后解决，时间限制50ms。 超时Promise首先拒绝，所以输出是`{"rejected":"Time Limit Exceeded","time":50}`。 

**示例2：**`fn`100ms后解决，时间限制150ms。 Promise 函数首先解析，因此输出为`{"resolved":25,"time":100}`。 

**示例3：**`fn`120ms后解决，时间限制150ms。 Promise 函数首先解析，输出为`{"resolved":15,"time":120}`。 

**示例4：**`fn`立即抛出。 Promise 函数立即拒绝，因此输出为`{"rejected":"Error","time":0}`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(1) | O(1) | Python asyncio 和 Go select 都是并发运行的； 只需要一个结果。 超时不会添加循环。 |

## 测试用例```python
import asyncio

async def test():
    async def fn1(n):
        await asyncio.sleep(0.1)
        return n * n

    async def fn2(a, b):
        await asyncio.sleep(0.12)
        return a + b

    async def fn3():
        raise Exception("Error")

    limited1 = timeLimit(fn1, 50)
    try:
        await limited1(5)
    except Exception as e:
        assert str(e) == "Time Limit Exceeded"  # Timeout triggered

    limited2 = timeLimit(fn1, 150)
    assert await limited2(5) == 25  # Resolved normally

    limited3 = timeLimit(fn2, 150)
    assert await limited3(5, 10) == 15  # Resolved normally

    limited4 = timeLimit(fn3, 1000)
    try:
        await limited4()
    except Exception as e:
        assert str(e) == "Error"  # Immediate rejection

    limited5 = timeLimit(fn1, 0)
    try:
        await limited5(5)
    except Exception as e:
        assert str(e) == "Time Limit Exceeded"  # Zero timeout edge case

asyncio.run(test())

 ## 边缘情况

 一个重要的边缘情况是当`t = 0`。 在这种情况下，该函数几乎应该总是拒绝，因为即使是最快的函数调用也将花费几微秒。 我们的实施转换`t`毫秒并相应地安排超时，这样就可以处理了。 

另一个边缘情况是当`fn`立即抛出异常。 仅检查经过时间的简单实现可能不会传播此错误。 通过将函数承诺与超时承诺竞争，可以正确返回立即拒绝。 

最后，`fn`精确地在超时边界处解析是很微妙的。 竞争保证如果函数首先解析，即使晚了 1 毫秒，也会返回结果。 如果超时 Promise 首先触发，则会发生拒绝。 这确保了严格执行时限，没有任何含糊之处。
