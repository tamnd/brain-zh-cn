 # LeetCode 2664 - 骑士之旅

 ## 问题理解

 这个问题要求我们构建一个完整的骑士之旅`m x n`棋盘。 马的巡演是一系列马的移动，使得棋盘上的每个单元格都被访问一次。 

我们得到：

 -`m`, 行数
 -`n`, 列数
 -`(r, c)`, 马的起始位置

 我们必须返回一个二维矩阵，其中每个单元格存储骑士访问该位置的顺序。 起始单元格必须包含`0`，下一个访问的单元格必须包含`1`，依此类推，直到所有`m * n`单元格已分配。 

骑士以L形移动。 从位置`(x, y)`，骑士可以移动到以下八个相对位置中的任何一个：

 -`(x + 2, y + 1)`-`(x + 2, y - 1)`-`(x - 2, y + 1)`-`(x - 2, y - 1)`-`(x + 1, y + 2)`-`(x + 1, y - 2)`-`(x - 1, y + 2)`-`(x - 1, y - 2)`仅当目的地仍在棋盘内时，该移动才有效。 

约束在这里非常重要：

 -`1 <= m, n <= 5`- 细胞总数最多为`25`- 该问题保证至少存在一个有效的旅行

 这些小限制强烈表明回溯解决方案是可行的。 在较大的骑士巡回问题中，朴素的回溯变得非常昂贵，但对于最多 25 个单元，通过修剪进行穷举搜索可以轻松地工作。 

有几种边缘情况值得考虑：

 - A`1 x 1`棋盘，骑士永远不会移动的地方
 - 棋盘非常狭窄，合法的骑士移动次数受到限制
 - 骑士在某一步骤只有一个有效延续的棋盘
 - 早期错误的举动导致后来陷入死胡同的情况

 解决方案存在的保证简化了实施，因为我们不需要处理不可能的输入。 

## 方法

 ### 暴力回溯

 最直接的方法是递归地尝试每一个可能的马棋动作。 

开始于`(r, c)`，我们用当前的移动编号标记当前单元格。 然后我们尝试所有有效的骑士移动，以到达未访问过的单元格。 对于每一步，我们都会递归地继续构建游览。 

如果在任何时候我们达到在访问所有单元格之前无法进一步移动的状态，我们会通过取消标记当前单元格并尝试不同的路径来回溯。 

这种方法是正确的，因为它系统地探索了每一个可能的有效的骑士动作序列。 最终，如果存在解，递归就会找到它。 

然而，搜索空间呈指数增长。 每个位置都可以分支为几个可能的动作，从而产生大量的候选路径。 

### 使用 Warnsdorff 式启发式优化回溯

 关键的观察结果是，许多递归分支失败，因为它们将骑士困在一个没有未来出口的区域。 

解决马的巡回问题的一个经典启发法是优先考虑具有最少后续选择的动作。 这是受到沃恩斯多夫规则的启发。 

推理很直观：

 - 流动性非常有限的细胞是危险的
 - 如果我们推迟拜访他们，以后可能就无法联系到他们了
 - 尽早访问受限单元可减少出现死胡同的机会

 因此，在探索下一步行动之前，我们会根据候选职位的前进次数对他们进行排序。 

这极大地减少了不必要的分支，并使搜索对于给定的约束极其有效。

 ## 算法演练

 1. 创建一个`m x n`板初始化为`-1`。 

价值`-1`表示未访问的单元格。 一旦访问了一个单元格，我们就将移动编号存储在其中。 
2. 标记起始位置`(r, c)`和`0`。 

这代表了骑士的第一步。 
3. 定义八种可能的马走法。 

这些代表了所有合法的相对骑士位移。 
4. 创建递归 DFS 函数。 

该函数接收：

 - 当前行
 - 当前列
 - 当前移动索引

 移动索引指示已经访问了多少个小区。 
5. 检查是否所有小区都被访问过。 

如果`move_index == m * n`，那么每个单元格都已被成功分配，所以我们返回`True`。 
6. 生成所有有效的下一步动作。 

对于每个骑士方向：

 - 计算新位置
 - 确保其保持在界限内
 - 确保目的地未被访问过
 7. 计算每个候选移动的程度。 

对于每个候选单元格，计算它有多少可用的未来有效移动。 

这实现了启发式：

 - 度数越小意味着限制越多
 - 应该更早访问更多受限的单元格
 8. 按程度对候选动作进行排序。 

这种排序极大地提高了搜索效率。 
9. 递归地尝试每个候选者。 

对于每个动作：

 - 指定当前移动索引
 - 递归
 - 如果递归成功，则返回`True`- 否则撤消移动并继续
 10. 递归成功后，返回完成的棋盘。 

### 为什么它有效

 该算法保持每个被访问的单元都包含唯一的移动编号并且没有单元被访问超过一次的不变性。 

回溯保证了正确性，因为除非更早发现有效的旅行，否则最终会探索每个合法的延续。 启发式不会删除有效的解决方案，它只会改变探索顺序。 因此，如果存在有效的游览，算法就会找到一个。 

## Python 解决方案```python
from typing import List

class Solution:
    def tourOfKnight(self, m: int, n: int, r: int, c: int) -> List[List[int]]:
        board = [[-1] * n for _ in range(m)]

        directions = [
            (2, 1),
            (2, -1),
            (-2, 1),
            (-2, -1),
            (1, 2),
            (1, -2),
            (-1, 2),
            (-1, -2),
        ]

        def is_valid(row: int, col: int) -> bool:
            return (
                0 <= row < m
                and 0 <= col < n
                and board[row][col] == -1
            )

        def count_onward_moves(row: int, col: int) -> int:
            count = 0

            for dr, dc in directions:
                nr = row + dr
                nc = col + dc

                if is_valid(nr, nc):
                    count += 1

            return count

        def dfs(row: int, col: int, move_index: int) -> bool:
            if move_index == m * n:
                return True

            candidates = []

            for dr, dc in directions:
                nr = row + dr
                nc = col + dc

                if is_valid(nr, nc):
                    degree = count_onward_moves(nr, nc)
                    candidates.append((degree, nr, nc))

            candidates.sort()

            for _, nr, nc in candidates:
                board[nr][nc] = move_index

                if dfs(nr, nc, move_index + 1):
                    return True

                board[nr][nc] = -1

            return False

        board[r][c] = 0
        dfs(r, c, 1)

        return board
```实现首先通过初始化板子开始`-1`，代表未访问的单元格。 

这`directions`数组存储所有八个骑士动作。 使用预定义的列表可以使移动生成保持简洁并避免重复的代码。 

这`is_valid`助手检查棋盘边界和访问状态。 这集中了验证逻辑并防止整个递归过程中出现重复的条件。 

这`count_onward_moves`助手实现启发式。 对于候选人职位，它会计算未来还有多少可用的合法行动。 该值充当用于移动排序的节点度。 

这`dfs`函数执行递归回溯。 当移动索引等于单元格总数时，就会发生基本情况，这意味着游览已完成。 

在递归中，我们收集所有合法的下一步及其程度。 对候选人进行排序可确保首先尝试最受限制的职位。 

对于每位候选人：

 - 标记移动编号
 - 更深层次地递归
 - 如果递归失败则撤消移动

 一旦找到成功的路径，递归立即传播`True`向上。 

## 解决方案```go
package main

import "sort"

func tourOfKnight(m int, n int, r int, c int) [][]int {
	board := make([][]int, m)

	for i := 0; i < m; i++ {
		board[i] = make([]int, n)

		for j := 0; j < n; j++ {
			board[i][j] = -1
		}
	}

	directions := [][]int{
		{2, 1},
		{2, -1},
		{-2, 1},
		{-2, -1},
		{1, 2},
		{1, -2},
		{-1, 2},
		{-1, -2},
	}

	isValid := func(row int, col int) bool {
		return row >= 0 &&
			row < m &&
			col >= 0 &&
			col < n &&
			board[row][col] == -1
	}

	var countOnwardMoves func(int, int) int

	countOnwardMoves = func(row int, col int) int {
		count := 0

		for _, d := range directions {
			nr := row + d[0]
			nc := col + d[1]

			if isValid(nr, nc) {
				count++
			}
		}

		return count
	}

	type Candidate struct {
		degree int
		row    int
		col    int
	}

	var dfs func(int, int, int) bool

	dfs = func(row int, col int, moveIndex int) bool {
		if moveIndex == m*n {
			return true
		}

		candidates := []Candidate{}

		for _, d := range directions {
			nr := row + d[0]
			nc := col + d[1]

			if isValid(nr, nc) {
				degree := countOnwardMoves(nr, nc)

				candidates = append(candidates, Candidate{
					degree: degree,
					row:    nr,
					col:    nc,
				})
			}
		}

		sort.Slice(candidates, func(i, j int) bool {
			return candidates[i].degree < candidates[j].degree
		})

		for _, candidate := range candidates {
			board[candidate.row][candidate.col] = moveIndex

			if dfs(candidate.row, candidate.col, moveIndex+1) {
				return true
			}

			board[candidate.row][candidate.col] = -1
		}

		return false
	}

	board[r][c] = 0
	dfs(r, c, 1)

	return board
}
```Go 实现密切反映了 Python 逻辑。 

定制`Candidate`struct 存储用于排序目的的度数和坐标。 Go 不像 Python 那样方便地支持元组排序，因此使用结构可以保持实现的简洁。 

该板是通过嵌套循环手动初始化的，因为 Go 切片默认为零值而不是`-1`。 

递归 DFS 使用闭包作为辅助函数。 由于最大板尺寸仅为`25`单元格，递归深度是完全安全的。

from typing import List

def validate_knight_tour(board: List[List[int]]) -> bool:
    m = len(board)
    n = len(board[0])

    positions = [None] * (m * n)

    for i in range(m):
        for j in range(n):
            positions[board[i][j]] = (i, j)

    for k in range(m * n - 1):
        r1, c1 = positions[k]
        r2, c2 = positions[k + 1]

        dr = abs(r1 - r2)
        dc = abs(c1 - c2)

        if not ((dr == 1 and dc == 2) or (dr == 2 and dc == 1)):
            return False

    return True

 ## 边缘情况

 ### 单电池板

 一个`1 x 1`board 是尽可能小的输入。 没有可用的骑士移动，但游览已经完成，因为起始单元算作已访问。 

如果实现假设必须发生至少一次递归移动，则这很容易导致错误。 我们的解决方案可以自然地处理它，因为 DFS 基本情况在分配后立即成功`0`。 

### 高度受限的董事会

 小棋盘通常给骑士提供非常有限的移动选择。 早期的错误选择可能会迅速困住骑士并使剩余的单元格无法到达。 

这正是天真的回溯变得低效的原因。 基于程度的启发式方法通过首先优先考虑受约束的单元来解决这个问题，从而显着减少死胡同探索。 

### 任意起始位置

 马可以从棋盘上的任何地方开始，包括角落、边缘或中心单元。 

角位的合法动作通常较少，而中心位置则有更多的分支可能性。 在这些情况下，不正确的边界检查很容易导致索引错误。 

这`is_valid`helper 集中所有边界和访问检查，确保在递归进行之前每个生成的移动都是安全的。
