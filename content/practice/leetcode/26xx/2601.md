[LeetCode 问题 2601](https://leetcode.com/problems/prime-subtraction-operation/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、二分查找、贪心、数论

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`并询问是否可以通过执行特殊操作将数组转换为**严格递增序列**。 

对于任意索引`i`，我们可以选择该索引**最多一次**并减去**素数**`p`从`nums[i]`， 在哪里`p`必须**严格小于`nums[i]`**。 自从`p < nums[i]`，每个结果值都保持正值。 我们还可以选择完全跳过索引并保持其值不变。 

目标是确定在执行零次或多次此类操作后，最终数组是否满足：```
nums[0] < nums[1] < nums[2] < ...
```关键的限制是每个索引只能修改一次，并且只允许我们减去素数。 这意味着我们无法自由地将值调整为我们想要的任何值。 相反，每个元素都有一组有限的可实现值。 

输入包括：

 - 整数数组`nums`- 长度`n`， 在哪里`1 <= n <= 1000`- 值在哪里`1 <= nums[i] <= 1000`预期输出是：

 -`true`如果我们可以将数组转换为严格递增数组
 -`false`否则

 这些约束揭示了有关问题规模的几个重要信息。 

自从`nums[i] <= 1000`，可能的素数的范围非常小。 我们可以预先计算所有素数`1000`有效地使用筛子或简单的素性测试。 还，`n <= 1000`，这意味着即使是`O(n log M)`或者`O(n * M)`解决方案是可以接受的，其中`M`就在附近`1000`。 

一些边缘情况立即脱颖而出。 

根据定义，单元素数组始终严格递增，因为不存在违反规则的相邻比较。 

已经严格递增的数组应该返回`true`无需任何操作。 

包含非常小的数字的数组，例如`1`或者`2`可能很棘手，因为很少有或根本没有比它们小的有效素数。 例如，`1`根本无法修改。 

当一个元素必须变得小于前一个元素以保持递增顺序时，会发生另一种微妙的情况，但没有有效的素数减法可以达到所需的值。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试每个索引的所有有效素数减法选择。 

对于每个元素，我们可以：

 1. 保持不变
 2. 减去任何小于该数的有效素数

 这将创建一个分支决策树。 由于每个元素可能有多个素数选择，因此可能的变换数组的数量呈指数增长。 

例如，如果一个元素有大约 20 个素数选择，我们有`n`元素，总搜索空间变得巨大。 我们可以使用回溯来测试每个可能的转换配置并检查是否有任何排列变得严格增加。 

这是有效的，因为它详尽地探索了所有有效的操作，因此保证了正确性。 然而，这在计算上是不切实际的，因为组合的数量呈指数级增长。 

### 最佳解决方案的关键见解

 关键的观察是我们应该**从左到右贪婪地处理数组**。 

在每个位置，我们希望当前数字尽可能**小，同时仍然大于前一个数字**。 

为什么？ 

使元素变小可以为未来的元素提供更多空间来保持严格增加。 如果我们留下不必要的大数字，后面的元素可能无法修复。 

假设之前选择的值为`prev`。 对于当前值`num`，我们想要：```
new_value > prev
```因为我们只能减去素数：```
new_value = num - prime
```重新排列：```
prime < num - prev
```因此，我们要减去小于的**最大素数`num - prev`**。 这会最小化当前数字，同时仍保持大于`prev`。 

如果没有这样的转变：```
new_value > prev
```那么答案就是立即`false`。 

因为素数是有序的，所以我们可以使用**二分查找**来有效地找到最大的有效素数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 尝试所有质数减法组合 |
 | 最佳| O(n log P + P log log P) | O(n log P + P log log P) | O(P)| 贪婪从左到右对素数进行二分搜索 |

 这里，`P = 1000`，这是最大可能的数值。 

## 算法演练

 1. 预先计算直到`1000`。 

由于每个数字在`nums`至多是`1000`，我们只需要这个范围内的素数。 我们生成并按排序顺序存储它们。 
2. 初始化变量`prev = 0`。 

这会跟踪严格递增序列中先前固定的数字。 
3. 从左到右迭代数组。 

在每一步中，我们都会考虑当前值`num`。 
4. 计算我们可以减去的最大素数。 

我们需要：```
num - prime > prev
```重新排列：```
prime < num - prev
```所以我们搜索严格小于的最大素数：```
num - prev
```5. 使用二分查找找到最大的有效素数。 

由于素数列表已排序，二分搜索可以有效地找到最佳减法候选者。 
6. 减去所选质数（如果存在）。 

如果存在有效素数，则将其减去`num`。 否则，保持号码不变。 
7. 验证严格的递增顺序。 

如果结果值不大于`prev`， 返回`false`立即，因为恢复是不可能的。 
8. 更新`prev`。 

将新固定的值存储为下一次迭代的先前值。 
9. 完成遍历。 

如果每个元素都满足条件，则返回`true`。 

### 为什么它有效

 贪婪策略之所以有效，是因为使每个数字尽可能小可以为未来元素保留最大的灵活性。 

在每一步，算法都会选择仍然满足增加条件的最小可行值。 任何更大的选择只会让未来的约束变得更加困难。 由于未来的数字必须超过当前的数字，因此最小化早期的值永远不会有坏处，只会有帮助。 因此，如果贪心方法失败，则不存在有效的安排。 

## Python 解决方案```python
from typing import List
import bisect

class Solution:
    def primeSubOperation(self, nums: List[int]) -> bool:
        def generate_primes(limit: int) -> List[int]:
            is_prime = [True] * (limit + 1)
            is_prime[0] = is_prime[1] = False

            for i in range(2, int(limit ** 0.5) + 1):
                if is_prime[i]:
                    for multiple in range(i * i, limit + 1, i):
                        is_prime[multiple] = False

            return [i for i in range(2, limit + 1) if is_prime[i]]

        primes = generate_primes(1000)

        prev = 0

        for num in nums:
            limit = num - prev

            index = bisect.bisect_left(primes, limit) - 1

            if index >= 0:
                num -= primes[index]

            if num <= prev:
                return False

            prev = num

        return True
```该实现首先生成直到`1000`使用埃拉托斯特尼筛法。 由于约束保证`nums[i] <= 1000`，这个预处理步骤对于每个测试用例来说都足够了。 

然后我们维护一个名为`prev`，表示严格递增序列中先前确定的值。 

对于数组中的每个数字，我们计算：```python
limit = num - prev
```这代表我们可以减去的素数的上限。 我们需要一个严格小于该值的素数。 

使用`bisect_left`，我们找到插入点`limit`在已排序的素数列表中。 减一给出严格小于的最大素数的索引`limit`。 

如果存在这样的素数，我们将其减去以最小化当前值。 之后，我们验证结果数字仍然严格大于`prev`。 

如果没有，我们立即返回`False`。 否则，我们更新`prev`并继续。 

如果整个遍历成功，我们返回`True`。 

## 解决方案```go
package main

import "sort"

func primeSubOperation(nums []int) bool {
	primes := generatePrimes(1000)

	prev := 0

	for _, num := range nums {
		limit := num - prev

		index := sort.Search(len(primes), func(i int) bool {
			return primes[i] >= limit
		}) - 1

		if index >= 0 {
			num -= primes[index]
		}

		if num <= prev {
			return false
		}

		prev = num
	}

	return true
}

func generatePrimes(limit int) []int {
	isPrime := make([]bool, limit+1)

	for i := 2; i <= limit; i++ {
		isPrime[i] = true
	}

	for i := 2; i*i <= limit; i++ {
		if isPrime[i] {
			for multiple := i * i; multiple <= limit; multiple += i {
				isPrime[multiple] = false
			}
		}
	}

	primes := []int{}

	for i := 2; i <= limit; i++ {
		if isPrime[i] {
			primes = append(primes, i)
		}
	}

	return primes
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 主要区别在于二分查找。 

而不是`bisect_left`, Go 使用`sort.Search`，它返回条件成立的第一个索引。 我们寻找第一个大于或等于的素数`limit`，然后减一以获得严格小于的最大素数`limit`。 

Go 切片自然会处理空数组，因此不需要特殊的 nil 处理。 整数溢出也不是问题，因为值永远不会超过`1000`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(P log log P + n log P) | O(P log log P + n log P) | 素数生成加上每个元素的二分搜索 |
 | 空间| O(P)| 存储素列表和筛子 |

 这里，`P = 1000`。 

筛子要求`O(P log log P)`产生素数的时间。 对于每个`n`元素，我们对素数列表执行一次二分搜索，其成本`O(log P)`。 

自从`P`固定在`1000`，该解在实践中实际上是线性的。

 ## 边缘情况

 一种重要的边缘情况是**单元素数组**。 由于没有要比较的相邻元素，因此根据定义，数组已经严格递增。 有缺陷的实现可能会错误地尝试不必要的素数减法。 我们的实现自然地处理了这个问题，因为循环会顺利完成。 

当**数字太小而无法减去素数**时，就会出现另一个棘手的情况。 例如：```
[2, 2]
```数量`2`没有严格小于它的素数。 因此，第一个元素保持不变`2`，并且第二个元素不能大于`2`。 我们的实现在以下情况下可以正确检测到这一点：```
num <= prev
```并返回`False`。 

第三个重要的边缘情况涉及**仍然可以修复的相同或减少的元素**。 考虑：```
[10, 10, 10]
```幼稚的解决方案可能会过早地拒绝相同的数量。 然而，素数减法允许变换：```
[3, 5, 7]
```贪婪策略之所以成功，是因为它在保持递增顺序的同时最小化每个数字。 

最后，**在约束附近具有非常大的值**的数组，例如`[1000, 1000]`如果素数生成实施不当，可能会暴露效率低下的情况。 通过仅预处理素数一次直至`1000`，我们的解决方案仍然高效且轻松适应限制。
