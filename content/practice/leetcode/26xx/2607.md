 **难度：** 🟡 中等
 **主题：** 数组、数学、贪心、排序、数论

 ## 解决方案

 ## 问题理解

 该问题要求我们转换一个**循环整数数组**，以便每个长度的子数组`k`有相同的总和。 循环数组意味着末尾环绕到开头，因此子数组可以跨越数组的边界。 允许的操作是将任何元素增加或减少 1，目标是**最小化操作总数**。 

简单来说，您需要使所有的总和相等`k`-length 子数组，对元素进行尽可能少的单个单元调整。 数组长度最大可达`10^5`和值高达`10^9`，因此任何解决方案都必须高效，并且不能尝试检查每个可能的数组修改。 

重要的限制和观察包括：

 - 数组是循环的，因此索引环绕。 例如，在长度为 4 的数组中`k=2`，从索引开始的子数组`[0,1,2,3]`是`[0,1]`,`[1,2]`,`[2,3]`,`[3,0]`。 
- 每个元素都贡献于多个子数组。 具体来说，元素`arr[i]`贡献于所有包含索引的子数组`i`。 
- 边缘情况包括`k=1`（每个元素单独必须相等）并且`k=arr.length`（整个数组的总和必须相等，微不足道）。 
- 值很大，因此需要仔细处理算术以避免溢出。 

## 方法

 ### 蛮力

 暴力方法将涉及尝试所有可能的方法来调整元素，以便所有子数组和都匹配。 这在计算上是不可行的，因为它可能需要检查最多`10^9`每个元素都会发生变化，并且有`n`元素。 此外，由于子数组重叠，调整一个元素可能会影响多个子数组，导致组合爆炸。 

### 最佳方法

 关键的观察结果是，该问题具有由下式确定的**循环模式**：`k`。 元素是`k`分开是互连的，形成**组模`k`**。 对于每个组，所有元素需要收敛到相同的值才能有效地均衡总和。 因此，我们可以：

 1. 将数组划分为`k`组： 指数`i, i+k, i+2k,...`。 
2. 对于每组，确定**中值**。 中位数使绝对差之和最小化，这直接对应于最小运算。 
3. 将组中的所有元素调整至该中位数。 将所有组中的这些调整相加即可得出答案。 

这种见解大大降低了复杂性，因为我们只需要处理`n`元素分组为`k`集，而不是探索每个子数组配置。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O（非常大）| O(n) | 尝试所有可能的元素修改； 对于较大的 n 或值来说不切实际 |
 | 最佳| O(n log(n)) | O(n log(n)) | O(n) | 分为 k 组，计算每组的中位数，求绝对差值总和 |

 ## 算法演练

 1. 初始化列表`k`空列表。 每个列表将存储一组元素的值，这些元素由`k`。 
2. 迭代数组。 对于索引处的每个元素`i`，将其附加到组中`i % k`。 
3. 对于每组：

 1. 对组值进行排序。 
2. 找出该组的中值。 
3. 计算每个元素与中位数之间的绝对差之和。 
4. 将各组之间的所有差异相加，得到总的最小操作数。 
5. 返回这笔金额。 

**为什么它有效：** 数组是圆形的，每个元素都属于一个特定的模组`k`。 单独均衡每个组可确保长度的所有重叠子数组`k`具有相等的金额。 选择中位数可以最大限度地减少该组中所有元素所需的总移动量。 

## Python 解决方案```python
from typing import List

class Solution:
    def makeSubKSumEqual(self, arr: List[int], k: int) -> int:
        n = len(arr)
        groups = [[] for _ in range(k)]
        
        for i in range(n):
            groups[i % k].append(arr[i])
        
        total_operations = 0
        
        for group in groups:
            group.sort()
            median = group[len(group) // 2]
            total_operations += sum(abs(x - median) for x in group)
        
        return total_operations
```**Explanation:**

 我们首先将数组元素分配到`k`基于其索引模的组`k`。 对每个组进行排序可以让我们选择中位数。 然后，我们将每个元素与中位数之间的绝对差相加，以计算该组的最少操作。 对所有组求和即可给出答案。 

## 解决方案```go
import (
    "sort"
    "math"
)

func makeSubKSumEqual(arr []int, k int) int64 {
    n := len(arr)
    groups := make([][]int, k)
    for i := 0; i < k; i++ {
        groups[i] = []int{}
    }
    
    for i := 0; i < n; i++ {
        groups[i % k] = append(groups[i % k], arr[i])
    }
    
    var total int64 = 0
    for _, group := range groups {
        sort.Ints(group)
        median := group[len(group)/2]
        for _, val := range group {
            total += int64(int(math.Abs(float64(val - median))))
        }
    }
    
    return total
}
```**Go 特定说明：** Go 需要对绝对值和和进行显式类型转换，以安全地处理大数。 对切​​片进行排序是通过`sort.Ints`。 

## 工作示例

 **示例1：**`arr = [1,4,1,3]`,`k = 2`团体：

 - 第 0 组：索引 0,2 →`[1,1]`→ 中位数`1`→ 差异`0`- 第 1 组：索引 1,3 →`[4,3]`→ 中位数`3`→ 差异`1`总操作 = 0 + 1 = 1

 **示例2：**`arr = [2,5,5,7]`,`k = 3`团体：

 - 第 0 组：索引 0,3 →`[2,7]`→ 中位数`7`→ 差异`5`- 第 1 组：索引 1 →`[5]`→ 中位数`5`→ 差异`0`- 第 2 组：索引 2 →`[5]`→ 中位数`5`→ 差异`0`总操作 = 5 + 0 + 0 = 5

 ## 边缘情况

 1. **k = 1：** 每个元素形成自己的子数组。 如果每个元素都被单独视为子数组，则无需进行任何更改。 该解决方案正确划分为单元素组，如果元素已经相等，则返回 0。 
2. **k = arr.length:** 只有一个子数组覆盖了整个数组。 所有元素的贡献相等，因此只需要所有元素的中位数即可最小化运算。 
3. **大元素值：**元素可以高达10^9。 在 Python 中使用整数运算很自然，但在 Go 中，显式类型转换为`int64`需要防止在求和绝对差值时溢出。 

这种方法通过利用模分组和中值计算策略来干净地处理所有这些边缘情况。
