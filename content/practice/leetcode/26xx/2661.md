[LeetCode 问题 2661](https://leetcode.com/problems/first-completely-painted-row-or-column/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、矩阵

 ## 解决方案

 ## 问题理解

 问题是要求我们在 2D 矩阵上模拟绘画过程。 我们得到一个 **1D 数组`arr`** 整数和 **`m x n`矩阵`mat`**，两者都包含来自的所有整数`1`到`m * n`正好一次。 对于中的每个整数`arr`（按顺序），我们“绘制”单元格`mat`包含该整数。 我们的任务是找到**最小的索引`i`在`arr`这样，在绘画之后`arr[i]`，至少有一整行或一列`mat`已完全涂漆**。 

输入`arr`代表绘画顺序。 每个整数准确地告诉我们接下来要绘制哪个单元格以及矩阵`mat`告诉我们每个数字的位置。 输出是一个整数 - 第一行或第一列完全绘制的移动索引。 

约束告诉我们矩阵可以很大：最多 105 行和列，但元素总数最多为 105。每个数字都是唯一的，并且在两者中都只出现一次`arr`和`mat`。 这种独特性保证我们永远不会对同一个单元进行两次绘制，从而简化了我们的记账。 

重要的边缘情况包括：

 - 1x1 矩阵（答案始终为 0，因为唯一的单元格首先被绘制）。 
- 单行或单列矩阵。 
- 最后一个元素`arr`完成行或列。 

## 方法

 ### 暴力方法

 天真的方法迭代中的每个元素`arr`。 对于每个数字，我们搜索它在`mat`（O(mn) 搜索），将其标记为已绘制，然后检查每一行和每一列以查看是否已完全绘制。 这种方法工作正常，但速度非常慢：搜索每个数字需要 O(mn)，检查所有行和列每一步的时间复杂度为 O(m + n)，导致总时间复杂度为 **O((mn)^2)**。 对于大量输入，这是不可接受的。 

### 最佳方法

 关键的观察是我们**不需要每次都检查整个矩阵**。 相反，我们可以预先计算每个数字的位置`mat`使用从数字→（行，列）的哈希映射。 然后我们维护两个数组：`rowCount`和`colCount`，表示每行和每列中还有多少个单元格需要绘制。 每次绘制一个单元格时，我们都会减少该行和列的计数。 如果任何计数达到零，我们就已经完全绘制了一行或一列。 这将每次移动的操作减少到 **O(1)**，并将总体时间复杂度减少到 **O(m * n)**。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((m * n)^2) | O((m * n)^2) | O(m * n) | 每次移动时重复检查所有单元格 |
 | 最佳| O(m * n) | O(m * n) | 使用哈希映射作为行和列的位置和计数器 |

 ## 算法演练

 1. 初始化哈希图`pos`将每个数字映射到`mat`到它的坐标`(row, col)`。 
2.初始化两个数组`rowCount`长度`m`和`colCount`长度`n`存储每行和每列中剩余多少个未绘制的单元格。 最初，`rowCount[r] = n`和`colCount[c] = m`。 
3. 迭代每个索引`i`在`arr`。 
4. 检索坐标`(r, c)`的`arr[i]`从`pos`。 
5. 减量`rowCount[r]`和`colCount[c]`减 1，因为该单元格现已被绘制。 
6. 检查是否`rowCount[r]`或者`colCount[c]`已达到0。如果是，则返回`i`当此移动完成一行或一列时立即。 
7. 继续，直到找到第一个完全绘制的行或列。 

**为什么有效：** 每个单元格都只绘制一次。 通过维护每行和每列的计数器，我们可以有效地跟踪进度。 当任何计数器达到零时，该行或该列中的所有单元格都已被绘制，以保证正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def firstCompleteIndex(self, arr: List[int], mat: List[List[int]]) -> int:
        m, n = len(mat), len(mat[0])
        pos = {}  # maps number to (row, col)
        for r in range(m):
            for c in range(n):
                pos[mat[r][c]] = (r, c)

        rowCount = [n] * m
        colCount = [m] * n

        for i, num in enumerate(arr):
            r, c = pos[num]
            rowCount[r] -= 1
            colCount[c] -= 1
            if rowCount[r] == 0 or colCount[c] == 0:
                return i
        return -1
```在这个实现中，我们首先构建`pos`映射以立即定位每个数字`mat`。 我们维持`rowCount`和`colCount`跟踪有多少单元格仍未着色。 每次迭代都会在恒定时间内处理一次移动，递减计数器并检查行或列是否完整。 

## 解决方案```go
func firstCompleteIndex(arr []int, mat [][]int) int {
    m, n := len(mat), len(mat[0])
    pos := make(map[int][2]int)
    for r := 0; r < m; r++ {
        for c := 0; c < n; c++ {
            pos[mat[r][c]] = [2]int{r, c}
        }
    }

    rowCount := make([]int, m)
    colCount := make([]int, n)
    for i := range rowCount {
        rowCount[i] = n
    }
    for i := range colCount {
        colCount[i] = m
    }

    for i, num := range arr {
        r, c := pos[num][0], pos[num][1]
        rowCount[r]--
        colCount[c]--
        if rowCount[r] == 0 || colCount[c] == 0 {
            return i
        }
    }
    return -1
}
```Go 解决方案反映了 Python 逻辑。 主要区别在于使用数组和切片而不是列表，并且元组被替换为定长数组`[2]int`。 地图访问和切片操作仍然高效且简单。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m * n) | 我们迭代一遍`mat`一次构建位置图，然后结束`arr`一次绘制，每次操作都以恒定的时间进行。 |
 | 空间| O(m * n) | 存储每个单元格的位置图和行/列计数器。 |

 由于元素的最大数量是`m * n ≤ 10^5`，这个解决方案是有效的。
