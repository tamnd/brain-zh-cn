 **难度：** 🟡 中等
 **主题：** 数组、排序、堆（优先级队列）、矩阵、模拟

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二维整数矩阵`nums`。 每行包含几个整数，我们重复执行特殊的删除过程，直到每个元素都被删除。 

在每次操作期间，我们都会做两件事：

 1. 从每一行中删除最大的剩余元素。 
2. 在本轮所有被移除的元素中，取最大值并添加到总分中。 

我们继续这个过程直到矩阵为空，然后返回累积分数。 

重要的观察结果是，每一行在每一轮中都贡献了一个元素。 由于示例和约束中所有行都具有相同的列数，因此经过足够的轮次后，每个元素最终都会被删除。 

例如，考虑：```
[[7,2,1],
 [6,4,2],
 [6,5,3],
 [3,2,1]]
```在第一轮中：

 - 从每行中删除最大的：

 - 7
 - 6
 - 6
 - 3
 - 删除的值中的最大值是`7`- 分数变为`7`在第二轮中：

 - 剩余行数：

 - [2,1]
 - [4,2]
 - [5,3]
 - [2,1]
 - 删除：

 - 2
 - 4
 - 5
 - 2
 - 最大值为`5`- 分数变为`12`在最后一轮中：

 - 删除：

 - 1
 - 2
 - 3
 - 1
 - 最大值为`3`- 最终得分变为`15`约束条件很重要：

 - 最多`300`行
 - 最多`500`列
 - 值高达`1000`元素总数可以达到`300 × 500 = 150,000`，所以我们需要一些相当有效的东西。 重复搜索每一行中的最大值的简单模拟可能会变得不必要的昂贵。 

一些边缘情况很重要：

 - 仅包含一个元素的矩阵
 - 具有重复值的行
 - 已排序或完全未排序的行
 - 所有值都相等
 - 大型矩阵，重复最大搜索的成本很高

 该问题保证有效的非空输入，因此我们不需要处理空矩阵。 

## 方法

 ### 蛮力方法

 直接模拟方法将完全按照描述重复执行操作。 

每轮：

 1. 扫描每一行以查找其当前最大值。 
2. 从行中删除该值。 
3. 跟踪所有行中删除的最大值。 
4. 将其添加到分数中。 

这是正确的，因为它从字面上遵循问题陈述。 

然而，它的效率很低，因为从未排序的行中查找和删除最大值需要每次扫描整个行。 如果一行有`n`元素，我们执行大小的扫描`n`， 然后`n-1`， 然后`n-2`， 等等。 

对于一行，这变为：```
n + (n - 1) + (n - 2) + ... + 1 = O(n²)
```对于所有行，复杂性对于约束而言变得太大。 

### 最佳方法

 关键的见解是删除顺序完全是通过对每一行进行排序来确定的。 

如果我们按升序对每一行进行排序：```
[1,2,7]
[2,4,6]
[3,5,6]
[1,2,3]
```那么每行最大的元素总是在最后。 

更重要的是，在每一轮中，我们都有效地比较每行中具有相同相对排名的元素：

 - 最大的元素
 - 第二大元素
 - 第三大元素
 - 等等

 排序后，我们可以简单地逐列处理。 

对于每个列索引：

 1. 取该索引处所有行中的最大值。 
2. 将其添加到分数中。 

这完全避免了重复的最大搜索和删除。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m × n²) | O(1) | O(1) | 重复扫描行以查找并删除最大值 |
 | 最佳| O(m × n log n) | O(m × n log n) | O(1) 或 O(log n) 取决于排序 | 对行进行一次排序，然后有效地处理列 |

 在哪里：

-`m`= 行数
 -`n`= 列数

 ## 算法演练

 1. 按升序对每一行进行排序。 

排序将重复的“删除最大元素”操作转换为可预测的结构。 排序后，行中最大的元素位于最后一个索引，第二大的元素位于倒数第二个索引，依此类推。 
2. 初始化变量`score = 0`。 

该变量存储累积答案。 
3. 从左到右迭代每个列索引。 

由于行按升序排序，因此同一列中的元素表示跨行具有相同相对排名的值。 
4. 对于当前列，查找所有行中的最大值。 

这模拟了该轮移除期间的增加值。 
5. 将此最大值添加到分数中。 

该问题指出，从每一行中删除一个值后，我们将删除的最大值添加到总分中。 
6. 继续，直到处理完所有列。 

每列对应一个完整的去除轮。 
7. 返回最终得分。 

### 为什么它有效

 对每一行进行排序可以保留模拟过程中发生的确切移除顺序。 首先删除最大的元素，然后删除第二大的元素，依此类推。 

排序后，列中的所有元素`j`对应于同一轮中删除的元素。 取该列中的最大值与问题定义的分数贡献完全匹配。 

因此，处理排序列会产生与原始模拟相同的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def matrixSum(self, nums: List[List[int]]) -> int:
        # Sort every row in ascending order
        for row in nums:
            row.sort()

        rows = len(nums)
        cols = len(nums[0])

        score = 0

        # Process each column
        for col in range(cols):
            current_max = 0

            for row in range(rows):
                current_max = max(current_max, nums[row][col])

            score += current_max

        return score
```实现首先对每一行进行排序。 这个预处理步骤是关键的优化，因为它将重复的最大删除转换为简单的列遍历。 

接下来，我们确定行数和列数。 迭代需要矩阵维度。 

外循环一次处理一列。 每列代表排序后的一轮移除。 

在循环内，我们计算当前列的所有行中的最大值。 这模拟了在该轮中选择最大的移除值。 

最后，我们将列最大值添加到总分中，并在处理完所有列后返回结果。 

## 解决方案```go
package main

import "sort"

func matrixSum(nums [][]int) int {
    // Sort each row
    for _, row := range nums {
        sort.Ints(row)
    }

    rows := len(nums)
    cols := len(nums[0])

    score := 0

    // Process columns
    for col := 0; col < cols; col++ {
        currentMax := 0

        for row := 0; row < rows; row++ {
            if nums[row][col] > currentMax {
                currentMax = nums[row][col]
            }
        }

        score += currentMax
    }

    return score
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

主要区别在于 Go 使用`sort.Ints()`对切​​片进行适当排序。 最大跟踪是使用手动实现的`if`条件而不是内置`max()`Python 中可用的函数。 

由于所有值都很小且约束条件有限，因此标准`int`足够了，不存在溢出问题。

 ## 边缘情况

 ### 单元素矩阵

 像这样的矩阵`[[1]]`是最小可能的有效输入。 有缺陷的实现可能会错误地假设存在多行或多列。 该解决方案可以自然地处理它，因为对单元素行进行排序是有效的，并且列迭代恰好运行一次。 

### 重复值

 行可能包含重复的数字，例如：```
[[5,5],
 [5,5]]
```该问题明确指出，删除最大元素时，关系并不重要。 排序可以正确保留重复项，并且列最大值仍然代表正确的删除轮次。 

### 单行矩阵

 当只有一行时，每个删除的值都会自动成为该轮的最大值。 例如：```
[[1,2,3]]
```排序后，算法直接处理列并对所有值正确求和。 

### 单列矩阵

 如果每一行仅包含一个值，则只有一轮删除。 该算法正确计算该单列中所有行的最大值。 

### 完全未排序的输入

 行可以按任意顺序出现：```
[[3,1,2],
 [6,4,5]]
```算法的正确性首先取决于排序。 如果没有排序，列将不对应于移除轮次。 通过在处理之前对每一行进行排序，该实现保证了删除的正确对齐。
