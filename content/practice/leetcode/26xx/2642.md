[LeetCode 问题 2642](https://leetcode.com/problems/design-graph-with-shortest-path-calculator/)

 **难度：** 🔴难
 **主题：** 图论、设计、堆（优先级队列）、最短路径

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个高效支持两种操作的图数据结构：

 1.动态添加有向加权边。 
2. 寻找两个节点之间的最短路径成本。 

我们得到一个有向加权图`n`节点标记为`0`到`n - 1`。 该图最初包含一个边列表，其中每条边表示为：```sql
[from, to, edgeCost]
```这意味着有一个有向边`from`到`to`旅行费用为`edgeCost`。 

我们需要实施一个`Graph`具有以下方法的类：

 -`Graph(n, edges)`初始化图表。 
-`addEdge(edge)`插入新的有向边。 
-`shortestPath(node1, node2)`计算从以下地点出发的最低总成本`node1`到`node2`。 

如果两个节点之间没有有效路径，我们必须返回`-1`。 

一个重要的细节是该图是**有向**的，这意味着一条边来自`u -> v`并不意味着有优势`v -> u`。 

例如：```
0 -> 1 (cost 2)
1 -> 2 (cost 1)
```允许从`0`到`2`有成本`3`，但不一定来自`2`到`0`。 

该图也是**加权**，这意味着边具有不同的遍历成本。 因此，最短路径不一定是边数最少的路径。 相反，我们必须最小化**边权重之和**。 

这些约束提供了有关问题规模的重要提示：

 -`n <= 100`，这是非常小的。 
- 至多`100`打电话给`addEdge`。 
- 至多`100`打电话给`shortestPath`。 

由于图尺寸很小，我们在算法选择上具有灵活性。 我们不一定需要理论上最优化的大规模解决方案。 相反，我们应该选择一种平衡简单性和性能的方法。 

如果重复探索所有可能的路径，幼稚的实现可能会变得低效。 然而，由于边权重为正，最短路径算法（例如 **Dijkstra 算法**）效果非常好。 

一些边缘情况值得预先考虑：

 - **不存在路径**：我们必须返回`-1`。 
- **断开连接的图**：某些节点可能永远无法访问。 
- **图表更新**：新添加的边可能会创建更短的路线。 
- **单节点可达性**：当`node1 == node2`，最短路径成本应该是`0`。 
- **多条替代路线**：我们必须选择总重量最小的，而不是边数最少的。 
- **密集图**：由于图可以包含几乎所有可能的有向边，因此邻接表示很重要。 

因为边权重严格为正（`>= 1`），Dijkstra算法保证正确工作。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试枚举所有可能的路径`node1`到`node2`使用深度优先搜索（DFS）或广度优先搜索（BFS）。 

这个想法很简单：

 - 开始于`node1`。 
- 探索每一条可到达的路径。 
- 跟踪累积路径成本。 
- 返回遇到的最小成本。 

这种方法是正确的，因为它最终会检查所有有效路径，确保找到最小成本路径。 

然而，它的效率极低。 在具有许多节点和边的图中，可能的路径数量可以呈指数增长。 由于循环可能存在，因此需要仔细记账以避免无限递归。 

在最坏的情况下，强力路径枚举变得非常昂贵。 

### 最优方法，Dijkstra 邻接表算法

 关键的观察结果是：

 - 所有边权重均为**正**。 
- 我们反复需要**最短路径查询**。 

正边权重使 **Dijkstra 算法**成为自然选择。 

Dijkstra 没有探索所有路径，而是贪婪地扩展当前最便宜的节点。 优先级队列（最小堆）确保我们始终处理具有最小已知距离的下一个节点。 

我们将图存储为**邻接表**，因为：

 - 添加边缘变得高效。 
- 邻居遍历速度很快。 
- 空间使用量与边数成正比。 

什么时候`shortestPath(node1, node2)`称为：

 1. 从以下位置启动 Dijkstra`node1`。 
2. 使用最小堆优先考虑较小的路径成本。 
3. 放松相邻的边缘。 
4.早停一次`node2`已达到。 

自从`n <= 100`，这个解决方案很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(V) | 探索每一条可能的路径 |
 | 最佳| 每个查询 O((V + E) log V) | O(V + E) | Dijkstra 使用邻接表和最小堆 |

 ## 算法演练

 ### 最优算法，Dijkstra 最小堆

 1. **初始化图形表示**

 将图存储为邻接列表。 

每个节点映射到一个列表：```
(neighbor, edgeCost)
```这使得遍历传出边缘变得高效。 
2. **构建初始图**

 构建过程中，迭代`edges`并将每条边添加到邻接表中。 

例子：```
[0,1,2]
```变成：```
graph[0].append((1,2))
```3. **手柄边缘插入**

 当`addEdge()`称为：

 - 提取物`from`,`to`， 和`cost`- 将边直接附加到邻接表中

 由于该问题保证没有重复的边，因此我们不需要验证逻辑。 
4. **开始最短路径搜索**

 当`shortestPath(node1, node2)`称为：

 创建一个最小堆，初始化为：```
(0, node1)
```这表示以成本到达源节点`0`。 
5. **追踪已知距离**

 维护距离数组：```
dist[node]
```初始化为无穷大。 

放：```
dist[node1] = 0
```这可以防止重复访问成本更差的节点。 
6. **按成本递增顺序处理节点**

 重复从堆中弹出最小距离条目。 

如果我们已经找到了到该节点的更短路径，请跳过它。 

这种惰性删除方法避免了昂贵的堆更新。 
7. **提前终止**

 如果当前节点等于`node2`，立即返还费用。 

由于 Dijkstra 按距离递增的顺序处理节点，因此我们第一次弹出`node2`，我们已经找到了最优答案。 
8. **放松邻近的边缘**

 对于每个出边：```
current -> neighbor
```计算：```
newCost = currentCost + edgeWeight
```如果这改善了已知距离：

 - 更新`dist[neighbor]`- 将新状态推入堆中
 9. **处理不可达节点**

 如果堆在到达之前变空`node2`， 返回`-1`。 

### 为什么它有效

 Dijkstra 算法依赖于以下不变量：一旦节点从优先级队列中删除，其最短距离就确定了。 

由于所有边权重均为正，因此到达该节点的任何未来路径的成本必须等于或更大。 因此，当`node2`从堆中弹出，我们知道不存在更短的路径，从而保证正确性。 

## Python 解决方案```python
from typing import List
import heapq

class Graph:

    def __init__(self, n: int, edges: List[List[int]]):
        self.graph = [[] for _ in range(n)]

        for source, destination, cost in edges:
            self.graph[source].append((destination, cost))

    def addEdge(self, edge: List[int]) -> None:
        source, destination, cost = edge
        self.graph[source].append((destination, cost))

    def shortestPath(self, node1: int, node2: int) -> int:
        if node1 == node2:
            return 0

        n = len(self.graph)
        distances = [float("inf")] * n
        distances[node1] = 0

        min_heap = [(0, node1)]

        while min_heap:
            current_cost, current_node = heapq.heappop(min_heap)

            if current_node == node2:
                return current_cost

            if current_cost > distances[current_node]:
                continue

            for neighbor, edge_cost in self.graph[current_node]:
                new_cost = current_cost + edge_cost

                if new_cost < distances[neighbor]:
                    distances[neighbor] = new_cost
                    heapq.heappush(
                        min_heap,
                        (new_cost, neighbor)
                    )

        return -1

# Your Graph object will be instantiated and called as such:
# obj = Graph(n, edges)
# obj.addEdge(edge)
# param_2 = obj.shortestPath(node1, node2)
```该实现紧密遵循前面描述的算法。 

构造函数初始化一个大小为的邻接表`n`。 每个索引都存储来自该节点的传出边。 

这`addEdge()`方法只是将新的有向边附加到邻接列表中。 由于该问题不允许重复的边，因此我们不需要替换逻辑。 

这`shortestPath()`方法为每个查询从头开始运行 Dijkstra 算法。 一个`distances`数组存储每个节点的最已知成本。 

最小堆确保我们始终首先处理已知距离最小的节点。 每当我们发现到邻居的更便宜的路线时，我们都会更新其距离并将其推入堆中。 

该行：```python
if current_cost > distances[current_node]:
    continue
```跳过过时的堆条目。 这很重要，因为一个节点可能会以不同的成本被多次推送。 

最后，我们返回`-1`如果无法到达目的地。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

type Edge struct {
	to   int
	cost int
}

type State struct {
	cost int
	node int
}

type PriorityQueue []State

func (pq PriorityQueue) Len() int {
	return len(pq)
}

func (pq PriorityQueue) Less(i, j int) bool {
	return pq[i].cost < pq[j].cost
}

func (pq PriorityQueue) Swap(i, j int) {
	pq[i], pq[j] = pq[j], pq[i]
}

func (pq *PriorityQueue) Push(x interface{}) {
	*pq = append(*pq, x.(State))
}

func (pq *PriorityQueue) Pop() interface{} {
	old := *pq
	n := len(old)
	item := old[n-1]
	*pq = old[:n-1]
	return item
}

type Graph struct {
	graph [][]Edge
}

func Constructor(n int, edges [][]int) Graph {
	graph := make([][]Edge, n)

	for _, edge := range edges {
		from := edge[0]
		to := edge[1]
		cost := edge[2]

		graph[from] = append(
			graph[from],
			Edge{to: to, cost: cost},
		)
	}

	return Graph{
		graph: graph,
	}
}

func (this *Graph) AddEdge(edge []int) {
	from := edge[0]
	to := edge[1]
	cost := edge[2]

	this.graph[from] = append(
		this.graph[from],
		Edge{to: to, cost: cost},
	)
}

func (this *Graph) ShortestPath(
	node1 int,
	node2 int,
) int {

	if node1 == node2 {
		return 0
	}

	n := len(this.graph)

	distances := make([]int, n)
	for i := range distances {
		distances[i] = math.MaxInt32
	}

	distances[node1] = 0

	pq := &PriorityQueue{}
	heap.Init(pq)

	heap.Push(pq, State{
		cost: 0,
		node: node1,
	})

	for pq.Len() > 0 {
		current := heap.Pop(pq).(State)

		currentCost := current.cost
		currentNode := current.node

		if currentNode == node2 {
			return currentCost
		}

		if currentCost > distances[currentNode] {
			continue
		}

		for _, edge := range this.graph[currentNode] {
			newCost := currentCost + edge.cost

			if newCost < distances[edge.to] {
				distances[edge.to] = newCost

				heap.Push(pq, State{
					cost: newCost,
					node: edge.to,
				})
			}
		}
	}

	return -1
}

/**
 * Your Graph object will be instantiated and called as such:
 * obj := Constructor(n, edges);
 * obj.AddEdge(edge);
 * param_2 := obj.ShortestPath(node1,node2);
 */
```Go 实现在概念上反映了 Python 解决方案，但 Go 需要使用显式优先级队列实现`container/heap`包裹。 

与Python内置的不同`heapq`，Go 需要一个自定义堆结构来实现：

 -`Len()`-`Less()`-`Swap()`-`Push()`-`Pop()`邻接表存储为：```go
[][]Edge
```其中每个节点维护其传出边缘。 

Go 整数就足够了，因为最大路径成本安全地保持在整数限制内。

 ## 边缘情况

 ### 源和目标是同一个节点

 如果`node1 == node2`，最短路径应该是`0`。 

这种情况很容易被忽视，尤其是当不存在边缘时。 幼稚的实现可能会错误地返回`-1`如果它从未穿过任何边。 

我们的实现立即处理这个问题：```
if node1 == node2:
    return 0
```这避免了不必要的计算并保证了正确性。 

### 不存在路径

 该图可能已断开连接，这意味着从源到目的地没有有效的路线。 

例如：```
0 -> 1
2 -> 3
```查询：```
shortestPath(0,3)
```应该返回`-1`。 

我们的实现自然会处理这个问题。 如果 Dijkstra 耗尽了优先级队列而没有到达目的地，我们返回：```
return -1
```### 新添加的边缘创建更短的路线

 一个重要的挑战是图表会随着时间的推移而变化。 

以前不可能的路径，调用后可能变得可达`addEdge()`。 

例子：```
0 -> 1
```最初：```
0 -> 2
```无法到达。 

后：```
addEdge([1,2,5])
```一条新路线可用。 

由于我们总是在当前邻接列表上运行 Dijkstra，因此该实现会自动考虑新插入的边。 

### 多个竞争路径

 最短路径可能不是边数最少的路径。 

例子：```
0 -> 1 (100)
0 -> 2 (1)
2 -> 1 (1)
```最优路线是：```
0 -> 2 -> 1
```有成本`2`，不是直接边成本`100`。 

Dijkstra 保证找到最小加权路径，因为它总是首先扩展当前最便宜的部分路径。
