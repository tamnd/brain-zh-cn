 **难度：** 🟡 中等
 **主题：** 字符串、动态规划、堆栈、贪婪

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定转换给定字符串所需的**最小插入次数**`word`转换成**有效的字符串**。 有效字符串被定义为可以通过连接序列形成的字符串`"abc"`一次或多次。 换句话说，每个有效字符串都遵循重复模式：```
abcabcabc...
```我们可以插入字符`'a'`,`'b'`， 或者`'c'`字符串中的任何位置，我们可以根据需要插入任意数量的字符。 目标是计算所需的最小插入次数，以便最终字符串遵循重复的字符串`"abc"`结构。 

输入由单个字符串组成`word`，其长度范围为`1`到`50`。 The string contains only the characters`'a'`,`'b'`， 和`'c'`。 由于输入大小非常小，即使效率较低的方法在技术上也可能通过，但问题的设计是为了奖励识别有效结构中的模式并有效地解决它。 

关键的挑战是理解角色如何适应重复的场景`"abc"`循环。 由于允许在任何地方插入，因此我们不需要保留块边界。 相反，我们想要确定丢失了多少个字符以使序列与重复一致`"abc"`组。 

预先识别一些边缘情况很重要。 只包含一个字符的字符串，例如`"a"`或者`"b"`，需要插入缺失的字母来完成`"abc"`堵塞。 字符串像`"aaa"`很棘手，因为重复的相同字母不能共存于同一个字母中`"abc"`组，意思是每个`'a'`有效地启动一个新组。 另一个重要的情况是当输入已经有效时，例如`"abc"`或者`"abcabc"`，答案应该是`0`。 

## 方法

 ### 蛮力方法

 暴力方法将尝试构造每个可能的有效字符串并确定所需的最小插入次数`word`它的一个子序列。 

由于有效的字符串总是由重复的`"abc"`段，我们可以生成如下字符串：```
abc
abcabc
abcabcabc
...
```对于每个生成的候选者，我们将检查是否`word`可以嵌入其中，同时保持顺序。 插入的数量就是：```
candidate_length - len(word)
```我们将继续，直到找到可以包含的最小有效候选者`word`。 

这种方法是正确的，因为它彻底搜索所有有效的目标字符串并保证找到最小的可行转换。 然而，它的效率很低，因为搜索空间不必要地增长，并且重复检查子序列会带来本可以避免的工作。 

### 最佳方法的关键见解

 重要的观察是有效的字符串始终遵循循环顺序：```
a → b → c → a → b → c
```我们可以通过检查相邻字符之间的转换来贪婪地处理字符串。 

假设我们当前处于一个角色并移动到下一个：

 - 如果下一个字符按字母顺序排列较晚（`a → b`,`b → c`），我们仍然在同一个地方`"abc"`堵塞。 
- 如果下一个字符小于或等于 (`c → a`,`b → a`,`a → a`），我们必须开始一个**新的`"abc"`堵塞**。 

一旦我们知道有多少`"abc"`需要分组，计算答案就变得简单：```
insertions = total_required_characters - existing_characters
```如果有`k`组，最终有效字符串的长度必须为：```
3 * k
```因此：```
answer = (3 * k) - len(word)
```### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 生成候选有效字符串并重复检查子序列 |
 | 最佳 | O(n) | O(1) | O(1) | 数数有多少个`"abc"`需要使用贪婪转换来进行组 |

 ## 算法演练

 ### 最优贪心算法

 1.初始化数量`"abc"`组到`1`。 

即使是单个角色也至少属于一个群体。 例如，`"a"`还需要一个`"abc"`堵塞。 
2. 从索引处开始，从左到右遍历字符串`1`。 

在每个位置，将当前字符与前一个字符进行比较。 
3. 检查是否必须开始新组。 

如果：```
current_character <= previous_character
```那么序列不能在同一个范围内继续`"abc"`堵塞。 

示例：

 -`"a" → "b"`留在同一个街区
 -`"b" → "c"`留在同一个街区
 -`"c" → "a"`开始一个新的块
 -`"a" → "a"`开始一个新的块
 -`"b" → "a"`开始一个新的块

 每当发生这种情况时，请增加组计数。 
4. 计算所需的总长度。 

每个小组的贡献准确无误`3`人物：```
total_length = groups * 3
```5. 减去原始字符串长度。 

差异代表缺少多少个字母：```
answer = total_length - len(word)
```### 为什么它有效

 核心不变量是每个有效字符串都必须遵守顺序`"a" → "b" → "c"`每个组内。 每当顺序减少或保持不变时，两个字符就不可能属于同一个`"abc"`段，因此必须开始一个新段。 通过贪婪地计算所需组的最小数量，我们保证了尽可能短的有效字符串，这直接最小化了插入。 

## Python 解决方案```python
class Solution:
    def addMinimum(self, word: str) -> int:
        groups = 1

        for index in range(1, len(word)):
            if word[index] <= word[index - 1]:
                groups += 1

        return groups * 3 - len(word)
```实现首先假设至少有一个`"abc"`团体。 然后它遍历字符串并将每个字符与前一个字符进行比较。 

每当排序不严格增加时，就需要一个新的组。 这与有效的贪婪观察相匹配`"abc"`块必须按升序进行。 

计算总组数后，代码计算所需有效字符串的总长度：`groups * 3`。 最后，它减去原始长度以确定需要插入多少次。 

实现是简洁的，因为贪婪的洞察力消除了动态编程或插入的显式模拟的需要。 

## 解决方案```go
func addMinimum(word string) int {
    groups := 1

    for i := 1; i < len(word); i++ {
        if word[i] <= word[i-1] {
            groups++
        }
    }

    return groups*3 - len(word)
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 字符串可以直接作为字节进行索引，因此字符比较很简单，因为输入仅包含 ASCII 字符（`'a'`,`'b'`,`'c'`）。 

不用担心整数溢出，因为最大输入大小仅为`50`，使得所有计算在 Go 的整数范围内都非常安全。

 ## 边缘情况

 ### 单字符输入

 单个字符，例如`"a"`,`"b"`， 或者`"c"`它本身永远无法形成有效的字符串，因为每个有效块都必须包含所有三个字母。 有缺陷的实现可能会忘记考虑隐式的第一组并错误地返回`0`。 我们的解决方案初始化`groups = 1`，确保至少一个`"abc"`块始终存在。 

### 重复字符

 输入如`"aaa"`或者`"cccc"`很容易误处理，因为重复的字符不能属于同一个`"abc"`团体。 由于有效的组需要严格递增的顺序，因此相等的相邻字符会强制创建一个新组。 条件：```
word[i] <= word[i - 1]
```正确捕获此行为。 

### 降序转换

 案例如`"ba"`或者`"cab"`包含序列按字母顺序向后移动的转换。 幼稚的实现可能会错误地将它们视为同一组的一部分。 我们的贪婪逻辑认识到任何减少都意味着当前`"abc"`段已结束并相应增加组计数。 

### 已经有效的字符串

 字符串像`"abc"`或者`"abcabc"`应该返回`0`。 由于相邻字符在每个块内严格增加并且仅在之后重置`'c'`，该算法自然会保持组数最少，从而不会产生不必要的插入。
