 # LeetCode 2659 - 将数组清空

 ## 问题理解

 该问题为我们提供了一个不同整数的数组，并定义了两种可能的操作：

 1. 如果第一个元素当前是数组中的最小值，则将其删除。 
2. 否则，我们将第一个元素移动到数组的末尾。 

我们继续执行操作，直到数组变空。 目标是计算所需的操作总数。 

重要的细节是数组的行为就像一个旋转队列。 在每一步中，我们只检查前面的元素。 如果它不是剩余元素中的最小值，我们将其旋转到后面。 最终，最小的元素到达前面并被删除。 

限制条件很大：

 -`n`可以达到`10^5`- 所有数字都是不同的
 - 值可能为负

 由于数组规模较大，直接重复模拟旋转速度会太慢。 简单的队列模拟很容易变成`O(n^2)`在最坏的情况下。 

所有数字都是不同的这一事实极其重要。 它保证在每一时刻都只有一个最小的剩余元素，这大大简化了逻辑。 

一些重要的边缘情况包括：

 - 数组已经按升序排序
 - 数组按降序排序
 - 具有负值的数组
 - 大小的数组`1`- 每次移除前发生多次旋转的情况

 这些情况可能会暴露简单实现中的低效率或索引错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用队列来模拟该过程。 

每次操作时：

 - 找到最小剩余价值
 - 与前面的元素进行比较
 - 如果匹配则删除它
 - 否则将前面的元素旋转到后面

 这种方法是正确的，因为它完全遵循问题陈述。 

然而，反复寻找最小值的成本很高。 即使我们使用双端队列进行高效的前后台操作，确定最小的剩余价值成本`O(n)`每次。 

在最坏的情况下，我们可能会执行大致`O(n^2)`操作，并且每个操作可能需要扫描最小值。 这对于`10^5`元素。 

### 关键见解

 我们不应该明确地模拟每次旋转，而应该考虑删除元素的顺序。 

由于接下来总是删除最小的剩余元素，因此删除顺序很简单：

 - 按值对元素进行排序
 - 从最小到最大删除它们

 真正的挑战是确定每次移除之前需要旋转多少次。 

假设我们知道元素的原始索引。 按排序顺序删除元素时：

 - 如果下一个索引位于上一个删除的索引的右侧，我们可以直接移动到那里。 
- 如果下一个索引绕到左侧，我们将有效地再次遍历剩余的循环数组。 

这就变成了计算位置之间仍然存在多少活动元素的问题。 

二叉索引树（也称为 Fenwick 树）非常适合此目的：

 - 它有效地跟踪哪些索引仍然有效。 
- 支持前缀和查询`O(log n)`。 
- 它支持删除`O(log n)`。 

使用这个结构，我们可以计算到达每个下一个最小元素需要多少次操作。

 ## 算法演练

 ### 使用 Fenwick 树的最优算法

 1. 将每个数字及其原始索引存储在一起。 

我们创建配对`(value, index)`这样在按值排序后我们仍然知道每个元素最初出现的位置。 
2. 按值对对进行排序。 

由于元素是按递增顺序删除的，因此排序为我们提供了准确的删除顺序。 
3. 初始化大小为 Fenwick 树`n`。 

最初每个索引都是活跃的，所以每个位置都存储`1`。 
4. 从总操作数等于`n`。 

每个元素删除本身都算作一次操作。 由于有`n`移除，我们至少已经知道`n`发生操作。 
5. 按排序顺序处理元素。 

对于每个下一个元素，将其原始索引与先前删除的索引进行比较。 
6. 如果下一个索引大于前一个索引：

 我们继续前行，不绕弯子。 

所需的旋转次数等于两个索引之间仍然活动的元素的数量。 
7. 如果下一个索引小于前一个索引：

 我们环绕圆形阵列。 

所需的旋转变为：

 - 从上一个索引到末尾的活动元素
 - 加上从开始到下一个索引的活动元素
 8. 将所需的旋转添加到答案中。 
9. 从 Fenwick 树中删除当前索引。 

我们通过减去来更新树`1`在那个位置，因为该元素不再存在。 
10. 继续，直到处理完所有元素。 

### 为什么它有效

 关键的不变量是芬威克树总是代表圆形数组中当前活动的元素。 

当从一个移除目标移动到下一个移除目标时，交叉的每个活动元素恰好对应于一个队列轮换。 由于删除的元素不再参与旋转，因此仅计算活动索引即可给出所需操作的确切数量。 

由于元素严格按照递增值顺序删除，因此排序序列与问题中描述的过程完美匹配。 

## Python 解决方案```python
from typing import List

class FenwickTree:
    def __init__(self, size: int):
        self.size = size
        self.tree = [0] * (size + 1)

    def update(self, index: int, delta: int) -> None:
        index += 1

        while index <= self.size:
            self.tree[index] += delta
            index += index & -index

    def query(self, index: int) -> int:
        index += 1
        result = 0

        while index > 0:
            result += self.tree[index]
            index -= index & -index

        return result

    def range_query(self, left: int, right: int) -> int:
        if left > right:
            return 0

        return self.query(right) - (
            self.query(left - 1) if left > 0 else 0
        )

class Solution:
    def countOperationsToEmptyArray(self, nums: List[int]) -> int:
        n = len(nums)

        sorted_pairs = sorted((value, index) for index, value in enumerate(nums))

        fenwick = FenwickTree(n)

        for i in range(n):
            fenwick.update(i, 1)

        operations = n

        previous_index = sorted_pairs[0][1]
        fenwick.update(previous_index, -1)

        for i in range(1, n):
            current_index = sorted_pairs[i][1]

            if current_index > previous_index:
                rotations = fenwick.range_query(
                    previous_index + 1,
                    current_index
                )
            else:
                rotations = (
                    fenwick.range_query(previous_index + 1, n - 1)
                    + fenwick.range_query(0, current_index)
                )

            operations += rotations

            fenwick.update(current_index, -1)

            previous_index = current_index

        return operations
```实现首先定义一个 Fenwick Tree 类。 该结构支持对数时间内高效的前缀和查询和点更新。 

这`update`方法改变特定位置的值，而`query`方法计算前缀和。 这`range_query`helper 计算范围内活动元素的数量。 

主要解决方案内部：

 - 我们按值对元素进行排序，同时保留原始索引。 
- 每个位置最初都被标记为活跃并具有价值`1`。 
- 答案开始于`n`因为每次删除本身都算作一次操作。 
- 我们按排序顺序处理元素。 
- 对于索引之间的每次转换，我们都会计算必须交叉的活动元素数量。 
- 删除元素后，我们更新芬威克树，以便将来的计数忽略它。 

这直接实现了演练中描述的逻辑。 

## 解决方案```go
package main

import "sort"

type FenwickTree struct {
	tree []int
	size int
}

func NewFenwickTree(size int) *FenwickTree {
	return &FenwickTree{
		tree: make([]int, size+1),
		size: size,
	}
}

func (f *FenwickTree) Update(index int, delta int) {
	index++

	for index <= f.size {
		f.tree[index] += delta
		index += index & -index
	}
}

func (f *FenwickTree) Query(index int) int {
	index++

	result := 0

	for index > 0 {
		result += f.tree[index]
		index -= index & -index
	}

	return result
}

func (f *FenwickTree) RangeQuery(left int, right int) int {
	if left > right {
		return 0
	}

	result := f.Query(right)

	if left > 0 {
		result -= f.Query(left - 1)
	}

	return result
}

func countOperationsToEmptyArray(nums []int) int64 {
	n := len(nums)

	type Pair struct {
		value int
		index int
	}

	pairs := make([]Pair, n)

	for i, value := range nums {
		pairs[i] = Pair{value, i}
	}

	sort.Slice(pairs, func(i, j int) bool {
		return pairs[i].value < pairs[j].value
	})

	fenwick := NewFenwickTree(n)

	for i := 0; i < n; i++ {
		fenwick.Update(i, 1)
	}

	var operations int64 = int64(n)

	previousIndex := pairs[0].index
	fenwick.Update(previousIndex, -1)

	for i := 1; i < n; i++ {
		currentIndex := pairs[i].index

		var rotations int

		if currentIndex > previousIndex {
			rotations = fenwick.RangeQuery(
				previousIndex+1,
				currentIndex,
			)
		} else {
			rotations =
				fenwick.RangeQuery(previousIndex+1, n-1) +
					fenwick.RangeQuery(0, currentIndex)
		}

		operations += int64(rotations)

		fenwick.Update(currentIndex, -1)

		previousIndex = currentIndex
	}

	return operations
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个重要的区别是整数处理。 由于答案可能超过`2^31 - 1`，最终结果使用`int64`。 

Go 还需要显式的结构定义和方法接收器来实现 Fenwick Tree。

## 测试用例```python
from typing import List

class Solution:
    def countOperationsToEmptyArray(self, nums: List[int]) -> int:
        from sortedcontainers import SortedList

        n = len(nums)
        indexed = sorted((v, i) for i, v in enumerate(nums))

        alive = SortedList(range(n))

        ans = 0
        current_pos = 0

        for _, target_index in indexed:
            idx_in_alive = alive.bisect_left(target_index)

            if idx_in_alive >= current_pos:
                steps = idx_in_alive - current_pos
            else:
                steps = len(alive) - current_pos + idx_in_alive

            ans += steps + 1

            alive.remove(target_index)

            if alive:
                current_pos = idx_in_alive % len(alive)

        return ans

solver = Solution()

assert solver.countOperationsToEmptyArray([3, 4, -1]) == 5  # sample case with wraparound

assert solver.countOperationsToEmptyArray([1, 2, 3]) == 3  # already sorted

assert solver.countOperationsToEmptyArray([5]) == 1  # single element

assert solver.countOperationsToEmptyArray([3, 2, 1]) == 5  # reverse sorted

assert solver.countOperationsToEmptyArray([-5, -10, 0]) == 4  # negative values

assert solver.countOperationsToEmptyArray([2, 1]) == 3  # smallest element starts second

assert solver.countOperationsToEmptyArray([4, 1, 3, 2]) == 6  # multiple wraparounds

 ## 边缘情况

 ### 单元素数组

 当数组仅包含一个元素时，该元素自动成为最小值并立即被删除。 

如果实现假设索引之间的转换始终存在，那么这种情况很容易处理不当。 提供的解决方案自然地处理了这个问题，因为后面的元素的循环永远不会执行。 

### 已经排序的数组

 如果数组已经按升序排序，则每个前面的元素始终是最小的剩余值。 

没有发生旋转，答案等于`n`。 

此案例验证了该算法在向前遍历索引时不会意外增加额外的移动成本。 

### 反向排序数组

 反向排序的数组会强制进行多次旋转，因为最小的剩余元素会重复出现在后面。 

这强调了环绕逻辑和循环遍历计算的正确性。 Fenwick Tree 解决方案通过分别计算数组末尾和开头的活动元素来正确处理此问题。 

### 负值

 该问题允许值小至`-10^9`。 

由于该算法仅依赖于排序和索引，因此负数不需要特殊处理。 无论符号如何，排序都能正确进行，并且芬威克树存储的是位置而不是值。
