[LeetCode 问题 2682](https://leetcode.com/problems/find-the-losers-of-the-circular-game/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、模拟

 ## 解决方案

 ## 问题理解

 这个问题描述了一个循环传球游戏`n`好友编号从`1`到`n`。 球总是从朋友开始`1`，每转一圈就会增加顺时针步数的倍数`k`。 

更具体地说：

 - 在第一回合，当前球员传球`1 * k`顺时针步骤。 
- 在第二回合，下一个玩家通过它`2 * k`顺时针步骤。 
- 在第三回合，下一个玩家通过它`3 * k`顺时针步骤。 
- 这种模式一直持续到有人第二次接球为止。 

任务是确定哪些朋友在比赛期间从未接过球。 这些朋友被称为失败者。 

输入包括：

 -`n`, 坐成一圈的朋友总数
 -`k`，每轮使用的步长乘数

 输出应该是一个好友号码列表，按升序排序，代表所有从未碰过球的好友。 

因为朋友们围成一圈，所以运动是环绕的。 如果我们超越朋友`n`，我们再继续朋友的`1`。 这自然是使用模运算来处理的。 

限制非常小：

 -`1 <= k <= n <= 50`这告诉我们几个重要的事情：

 - 效率不是主要问题，因为输入大小很小。 
- 直接模拟是完全可以接受的。 
- 我们不需要高级的数学优化。 
- 我们可以使用数组或集合安全地跟踪访问过的玩家。 

一些重要的边缘情况包括：

 -`n = 1`，只有一个朋友，这意味着游戏立即结束。 
-`k = n`，其中每个动作都精确地绕到相同的位置。 
- 只有一小部分球员接球的情况。 
- 循环重复得非常快的情况。 

幼稚的实现很容易在索引方面犯错误，因为该问题使用从 1 开始的编号，而大多数编程语言在内部使用从 0 开始的索引。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是完全按照描述来模拟游戏。 

我们从朋友开始`1`持球。 每回合：

 1. 将当前好友标记为已访问。 
2. 使用当前回合数和步长计算下一个朋友`k`。 
3. 继续，直到找到已经收到球的朋友。 

最后，每一个未拜访过的朋友都是失败者。 

这种方法保证有效，因为游戏规则是确定性的。 由于只有`n`朋友们，最终某个朋友必须再次收到球，导致进程终止。 

尽管这在技术上是蛮力模拟，但约束非常小，已经足够高效了。 

### 最佳解决方案的关键见解

 关键的观察是我们只需要跟踪哪些朋友已经收到了球。 

由于游戏结束前每个好友只能访问一次，因此模拟最多执行一次`n`迭代。 

使用布尔数组或哈希集允许我们：

 - 有效检测重复访问
 - 将玩家标记为在恒定时间内被访问过
 - 之后收集未访问过的玩家

 因此，最佳解决方案就是使用访问跟踪进行干净的模拟。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 可能会低效地重复扫描结构 |
 | 最佳| O(n) | O(n) | 通过访问跟踪进行直接模拟 |

 ## 算法演练

 1. 创建一个布尔数组，名为`visited`尺寸的`n`，初始化为`False`。 

这个数组记录了每个朋友是否已经接到球。 指数`0`对应于朋友`1`， 指数`1`给朋友`2`， 等等。 
2. 从索引处的当前玩家开始`0`。 

由于好友编号从`1`，使用索引`0`内部简化了模运算。 
3. 将转动计数器初始化为`1`。 

第一关移动`1 * k`步骤，第二遍移动`2 * k`步骤等等。 
4. 在当前玩家尚未被访问过的情况下继续模拟。 

如果我们遇到已经接球的球员，比赛立即结束。 
5. 将当前玩家标记为已访问。 

这记录了球员现在已经接到球了。 
6. 使用圆周运动计算下一个玩家。 

公式为：```
next_position = (current_position + turn * k) % n
```模运算可确保运动正确环绕圆。 
7. 增加转动计数器。 

每一轮都会将距离增加另一个倍数`k`。 
8. 循环结束后，迭代`visited`大批。 

每一个价值依然存在的球员`False`从未接到球，因此是失败者。 
9. 按升序返回失败者列表。 

由于我们从左到右迭代，结果自然是排序的。 

### 为什么它有效

 该算法完全遵循游戏规则。 每次迭代都会模拟一次球的传球。 这`visited`array 保证我们在球员第二次接球时停止。 由于每个被访问的玩家都被精确记录一次，所以剩下的未访问的玩家恰好是失败者。 

## Python 解决方案```python
from typing import List

class Solution:
    def circularGameLosers(self, n: int, k: int) -> List[int]:
        visited = [False] * n

        current = 0
        turn = 1

        while not visited[current]:
            visited[current] = True

            current = (current + turn * k) % n
            turn += 1

        losers = []

        for i in range(n):
            if not visited[i]:
                losers.append(i + 1)

        return losers
```该实现首先分配一个名为的布尔数组`visited`。 每个位置对应一位好友。 

变量`current`使用从 0 开始的索引来存储当前玩家的索引。 变量`turn`跟踪到目前为止发生了多少次传递。 

这`while`只要当前球员之前从未接过球，循环就会继续。 在循环内，我们首先将玩家标记为已访问。 然后我们使用圆周运动公式计算下一个位置。 

模拟结束后，我们遍历所有玩家并收集那些从未访问过的玩家。 由于索引内部是从 0 开始的，我们添加`1`在构建最终答案时。 

## 解决方案```go
func circularGameLosers(n int, k int) []int {
    visited := make([]bool, n)

    current := 0
    turn := 1

    for !visited[current] {
        visited[current] = true

        current = (current + turn*k) % n
        turn++
    }

    losers := []int{}

    for i := 0; i < n; i++ {
        if !visited[i] {
            losers = append(losers, i+1)
        }
    }

    return losers
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

布尔切片用于访问跟踪。 结果存储在一个动态增长的切片中，名为`losers`。 

不存在整数溢出问题，因为约束非常小。 Go 切片自然地处理动态附加，使结果构造变得简单。

class Solution:
    def circularGameLosers(self, n: int, k: int) -> List[int]:
        visited = [False] * n

        current = 0
        turn = 1

        while not visited[current]:
            visited[current] = True

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n = 1`。 在这种情况下，圈子里只有一个朋友。 球从朋友开始`1`，并且第一个传球立即返回到同一玩家。 由于该球员已经接到球，因此比赛立即结束。 没有失败者，因为唯一的朋友参加了。 该实现自然地处理了这个问题，因为循环在第一次重复访问后停止。 

另一个重要的情况发生在`k`正好等于`n`。 在这种情况下，每一个动作`k`步骤导致没有有效的移动，因为`(current + n) % n`返回相同的位置。 这意味着首发球员立即再次接球。 错误的实现可能会忘记模运算并产生超出范围的索引，但模算术可以正确地环绕圆圈。 

第三种边缘情况涉及在重复之前访问所有玩家的循环。 例如，通过某些组合`n`和`k`，每个朋友最终都会收到球。 在这种情况下，答案应该是一个空列表。 该实现正确地处理了这个问题，因为它只添加了以下玩家`visited`价值依然存在`False`。 

错误的另一个微妙来源是索引。 问题陈述使用从 1 开始的编号，而 Python 和 Go 中的数组是从 0 开始的。 不正确的转换可能会在运动计算和结果构造中产生相差一的错误。 该实现通过在内部使用基于 0 的索引执行所有计算并仅在构建最终答案时转换回基于 1 的编号来避免这种情况。
