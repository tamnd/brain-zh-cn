[LeetCode 问题 2672](https://leetcode.com/problems/number-of-adjacent-elements-with-the-same-color/)

 **难度：** 🟡 中等
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`colors`长度`n`。 最初，每个元素都是`0`，它代表未着色的位置。 

然后我们处理一系列查询。 每个查询包含两个整数：

 -`indexi`，我们要更新的位置
 -`colori`，分配给该位置的新颜色

 应用每个查询后，我们必须确定数组中有多少相邻对具有相同的非零颜色。 

相邻对意味着两个相邻索引：

 -`(0, 1)`-`(1, 2)`-`(2, 3)`- 等等

 例如，如果数组变为：```
[2, 2, 1, 1]
```那么有两个有效的相邻等色对：

 -`(0, 1)`因为`2 == 2`-`(2, 3)`因为`1 == 1`所以答案是`2`。 

一个关键细节是颜色可以被覆盖。 一个位置可能已经包含一种颜色，稍后会收到不同的颜色。 每个查询都会修改数组的当前状态。 

约束条件很重要：

 -`n <= 100000`-`queries.length <= 100000`这意味着我们必须有效地处理多达十万个更新。 任何在每次查询后扫描整个数组的解决方案都会太慢。 

输入保证：

 - 索引始终有效
 - 颜色是正整数
 - 仅`0`代表“无色”

 一些边缘情况很重要：

 - 长度数组`1`，其中不可能存在相邻对
 - 使用与已有颜色相同的颜色对位置重新着色
 - 更改颜色时破坏现有的相邻对
 - 更新后创建一两个新的相邻对
 - 在数组边界处更新，其中仅存在一个邻居

 这些边缘情况正是错误计数逻辑通常出现的地方。 

## 方法

 ### 蛮力方法

 最直接的解决方案是模拟每次查询并从头开始重新计算相邻等色对的数量。 

应用查询后：

 1. 更新`colors[index]`2. 迭代整个数组
 3. 统计有多少个相邻位置满足：

 -`colors[i] != 0`-`colors[i] == colors[i + 1]`这种方法是正确的，因为它在每次更新后显式检查每个相邻对。 

然而，它太慢了。 

如果有`q`查询，每个查询都会扫描所有`n`元素，复杂度变为：```
O(n * q)
```两个值可能等于`100000`，这可能需要最多`10^10`的操作，远远超出了可接受的范围。 

### 最佳方法

 关键的观察结果是，更改一个索引只会影响涉及该索引的相邻对。 

当我们更新位置时`i`，只有这些对可以改变：

 -`(i - 1, i)`-`(i, i + 1)`没有其他相邻对受到影响。 

这意味着我们不需要在每次查询后重新计算整个数组。 相反，我们维护有效相邻等色对的运行计数。 

对于每次更新：

 1. 删除旧颜色关系的贡献
 2.改变颜色
 3. 添加新颜色关系的贡献

 由于每个查询最多只检查两个邻居，因此每个查询都以恒定的时间运行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × q) | O(n) | 每次查询后重新计算所有相邻对 |
 | 最佳| O(q) | O(n) | 仅更新受影响的相邻对 |

 ## 算法演练

 ### 第 1 步：初始化颜色数组

 创建一个数组`colors`长度`n`充满`0`。```
colors = [0] * n
```这代表初始未着色状态。 

我们还维护：```
adjacent_pairs = 0
```该变量存储当前有效的相邻等色对的数量。 

### 第 2 步：处理每个查询

 对于每个查询`[index, new_color]`，我们更新数组并调整计数。 

### 步骤 3：删除旧对贡献

 更改颜色之前`index`，我们必须删除当前涉及该位置的任何相邻的等色对。 

我们检查左邻居：```
if index > 0 and colors[index] != 0 and colors[index] == colors[index - 1]:
```如果为真，则减少计数。 

然后检查右邻居：```
if index < n - 1 and colors[index] != 0 and colors[index] == colors[index + 1]:
```如果为 true，则再次递减。 

我们首先这样做是因为旧颜色即将消失。 

### 第 4 步：应用新颜色

 更新数组：```
colors[index] = new_color
```### 步骤 5：添加新的配对贡献

 现在检查新颜色是否与邻居形成相等的相邻对。 

检查左邻居：```
if index > 0 and colors[index] == colors[index - 1]:
```如果为真，则增加计数。 

检查右邻居：```
if index < n - 1 and colors[index] == colors[index + 1]:
```如果为 true，则再次递增。 

### 第 6 步：存储当前答案

 追加当前值`adjacent_pairs`到结果数组。 

### 为什么它有效

 该算法之所以有效，是因为在查询后只有接触更新索引的相邻对才能更改。 

每个查询只修改一个位置。 因此：

 - 所有不相关的相邻对保持不变
 - 仅`(i - 1, i)`和`(i, i + 1)`可能被创建或销毁

 通过在更新之前删除旧的贡献并在更新之后添加新的贡献，运行计数始终保持准确。 

这个不变量保证每次查询后的正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def colorTheArray(self, n: int, queries: List[List[int]]) -> List[int]:
        colors = [0] * n
        adjacent_pairs = 0
        answer = []

        for index, new_color in queries:
            current_color = colors[index]

            # Remove old contributions
            if current_color != 0:
                if index > 0 and colors[index - 1] == current_color:
                    adjacent_pairs -= 1

                if index < n - 1 and colors[index + 1] == current_color:
                    adjacent_pairs -= 1

            # Apply update
            colors[index] = new_color

            # Add new contributions
            if index > 0 and colors[index - 1] == new_color:
                adjacent_pairs += 1

            if index < n - 1 and colors[index + 1] == new_color:
                adjacent_pairs += 1

            answer.append(adjacent_pairs)

        return answer
```实现直接遵循算法。 

这`colors`数组存储每次查询后的当前状态。 变量`adjacent_pairs`维护有效相邻等色对的运行计数。 

在更新位置之前，代码会删除涉及该索引处当前颜色的任何现有对贡献。 这可以防止重新着色后过时的对保留在计数中。 

分配新颜色后，代码检查更新的位置现在是否与其邻居形成等色对。 任何新形成的对都会添加回计数中。 

每个查询最多涉及两个邻居，这使每个操作的运行时间保持不变。 

## 解决方案```go
func colorTheArray(n int, queries [][]int) []int {
    colors := make([]int, n)
    adjacentPairs := 0
    answer := make([]int, 0, len(queries))

    for _, query := range queries {
        index := query[0]
        newColor := query[1]

        currentColor := colors[index]

        // Remove old contributions
        if currentColor != 0 {
            if index > 0 && colors[index-1] == currentColor {
                adjacentPairs--
            }

            if index < n-1 && colors[index+1] == currentColor {
                adjacentPairs--
            }
        }

        // Apply update
        colors[index] = newColor

        // Add new contributions
        if index > 0 && colors[index-1] == newColor {
            adjacentPairs++
        }

        if index < n-1 && colors[index+1] == newColor {
            adjacentPairs++
        }

        answer = append(answer, adjacentPairs)
    }

    return answer
}
```Go 实现密切反映了 Python 逻辑。 

使用切片而不是动态 Python 列表。 这`answer`切片的初始化容量等于查询数量，以减少重新分配。 

Go 整数就足够了，因为相邻对的最大数量最多为`n - 1`，很容易符合标准`int`。 

不需要对 nil 值进行特殊处理，因为数组会自动用零初始化。

 ## 边缘情况

 ### 长度为 1 的数组

 当`n = 1`，根本不存在相邻位置。 粗心的实现可能会尝试访问邻居并导致索引错误。 

该解决方案通过在访问邻居之前检查边界条件来避免这种情况：```
if index > 0
if index < n - 1
```由于这两个条件对于单元素数组都不成立，因此不会发生邻居检查。 

### 用相同的颜色重新着色位置

 假设数组包含：```
[5,5]
```我们应用另一个查询将第二个位置设置为`5`再次。 

有缺陷的实现可能会意外地重复计算相邻对。 该解决方案首先删除现有贡献，然后在更新后重新添加它们，保持计数不变且正确。 

### 更新连接两个相等线段的位置

 考虑：```
[1,0,1]
```如果我们将中间位置更新为`1`，同时创建两个相邻对：```
[1,1,1]
```现在两者`(0,1)`和`(1,2)`是有效的。 

该算法可以正确处理此问题，因为它在更新后独立检查两个邻居，并增加每个匹配边的计数。
