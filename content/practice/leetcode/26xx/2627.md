[LeetCode 问题 2627](https://leetcode.com/problems/debounce/)

 **难度：** 🟡 中等
 **主题：** —

 ## 解决方案

 ## 问题理解

 这个问题要求我们实现一个实用函数，称为`debounce`。 该函数接收两个输入：

 - 一个函数`fn`- 延迟值`t`以毫秒为单位

 目标是返回一个新函数，称为去抖版本`fn`。 

去抖函数的行为非常具体。 每次调用返回的函数时，它不会立即执行。 相反，它安排执行`t`未来的几毫秒。 

但是，如果在等待期结束之前再次调用去抖函数，则必须取消先前计划的执行并替换为新的执行。 

这意味着，如果在去抖窗口内发生多个调用，则只有最近的调用才能幸存。 

换句话说：

 - 每次通话都会重置计时器
 - 只有在一段安静的时间后的最后一次通话`t`实际上执行
 - 执行的调用必须使用提供的最新参数

 该问题从根本上讲是关于使用计时器管理异步计时行为。 

考虑这个序列：```
t = 50

Call at 30ms
Call at 60ms
Call at 100ms
```第一个调用安排在 80 毫秒执行。 

但是第二次调用在 60ms 处到达，在 80ms 之前到达，因此第一次执行被取消。 第二个调用现在安排在 110 毫秒执行。 

然后第三次调用在 100ms 处到达，在 110ms 之前到达，因此第二次执行被取消。 第三次调用安排在 150 毫秒执行。 

结果，仅执行最后的调用。 

限制非常小：

 -`0 <= t <= 1000`- 示例中最多调用 10 次

 小的限制告诉我们性能并不是主要的挑战。 真正的挑战是正确理解计时器取消和关闭行为。 

有几个重要的边缘情况：

 - 计时器到期前发生多次呼叫
 - 调用恰好在另一个计时器执行时发生
 -`t = 0`，其中执行应立即发生，但仍遵循取消语义
 - 接收多个参数的函数
 - 重复的快速调用，只有最后的调用才能生存

 该问题保证有效的输入，并且不需要处理无效的计时器值或格式错误的函数参数。 

## 方法

 ### 蛮力方法

 强力方法将尝试独立跟踪每个计划的执行。 

对于每个函数调用：

 1.创建一个新的定时器
 2. 将所有活动定时器存储在列表中
 3.每当有新呼叫到来时取消旧计时器
 4. 只执行最近的定时器

 这是有效的，因为去抖动行为只需要删除过时的计划执行。 

然而，维护定时器集合是不必要的。 在任何时刻，只有一个计时器真正重要，即最近安排的计时器。 当新的调用发生时，较旧的计时器总是立即取消。 

这种方法引入了额外的簿记和不必要的内存使用。 

### 最佳方法

 关键的观察是去抖动只需要记住一个待处理的计时器。 

当有新电话到来时：

 - 如果计时器已经存在，则取消它
 - 使用最新的参数创建一个新的计时器
 - 存储计时器参考，以便以后可以取消

 这非常有效，因为每次新的调用都会使之前的挂起执行无效。 

这里使用的主要工具是`setTimeout`与...一起`clearTimeout`。 

我们还依赖闭包，以便返回的函数可以记住调用之间的活动计时器。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 不必要地存储多个计时器 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 仅维护一个活动计时器 |

 ## 算法演练

 1. 创建一个名为`timer`在返回的函数之外。 

该变量存储当前计划的超时。 因为它存在于外部作用域中，所以它通过闭包行为在函数调用之间持续存在。 
2. 返回一个接受任意数量参数的新函数。 

去抖函数的行为必须与原始函数类似，并且支持任意参数。 
3. 每当调用 debounced 函数时，首先检查计时器是否已经存在。 

如果前一个定时器仍然挂起，则表示执行请求已过时。 
4. 使用以下命令取消之前的计时器`clearTimeout(timer)`。 

这可以确保旧的计划执行永远不会发生。 
5. 使用创建一个新计时器`setTimeout`。 

新的定时器安排执行`fn`后`t`毫秒。 
6. 在超时回调中，执行`fn(...args)`。 

这可确保使用最新的参数。 
7. 将新的超时参考存储回`timer`。 

这允许将来的调用在必要时取消它。 

### 为什么它有效

 该算法保持了一个不变量，即任何时间最多有一个执行处于挂起状态。 

每一次新的调用都会使之前安排的执行失效，并用新的执行代替。 因此，只有在一段安静的时间间隔后才进行最近的调用`t`可以执行。 

由于计时器总是在每次调用时重置，因此该实现与去抖语义完全匹配。 

## Python 解决方案```python
from typing import Any, Callable
import threading

class Solution:
    def debounce(self, fn: Callable[..., Any], t: int) -> Callable[..., None]:
        timer = None

        def debounced(*args):
            nonlocal timer

            if timer is not None:
                timer.cancel()

            timer = threading.Timer(t / 1000, lambda: fn(*args))
            timer.start()

        return debounced
```实施首先创建一个`timer`外部作用域中的变量。 该变量存储当前活动的计时器对象。 

内部`debounced`函数接受任意位置参数`*args`。 这允许去抖版本反映原始函数的行为。 

这`nonlocal`关键字是必要的，因为我们需要修改外部`timer`嵌套函数内部的变量。 

每当去抖动函数执行时，它首先检查计时器是否已经存在。 如果是这样，则该计时器将立即取消，因为其执行不再有效。 

接下来，使用创建一个新计时器`threading.Timer`。 由于 Python 计时器以秒为单位运行，而问题则以毫秒为单位，因此我们将`t`经过`1000`。 

最后，新的计时器开始运行并成为活动的挂起执行。 

## 解决方案```go
package main

import (
	"time"
)

func debounce(fn func(...interface{}), t int) func(...interface{}) {
	var timer *time.Timer

	return func(args ...interface{}) {
		if timer != nil {
			timer.Stop()
		}

		timer = time.AfterFunc(
			time.Duration(t)*time.Millisecond,
			func() {
				fn(args...)
			},
		)
	}
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用 Go 的`time`包裹。 

这`time.Timer`type 存储当前活动的计划执行。 当新呼叫到达时，现有计时器将在创建替代计时器之前停止。 

Go 通过以下方式使用可变参数`...interface{}`支持任意论点。 

与 Python 不同，Go 不需要`nonlocal`关键字，因为闭包通过引用自动捕获外部变量。

 ## 边缘情况

 ### 同一去抖动窗口内的多个调用

 这是问题的中心边缘情况。 如果在计时器到期之前发生了多个调用，则只有最新的调用应该存活。 

幼稚的实现可能会意外地允许多个计时器执行，因为它忘记取消较早的计时器。 

此实现通过始终调用来避免该问题`clearTimeout`或者`timer.cancel()`在创建新计时器之前。 

### 零毫秒延迟

 当`t = 0`，该函数应在调度后立即执行。 

这可能会暴露实施不良的解决方案中的竞争条件，因为计时器取消仍然必须正确发生。 

该实现之所以有效，是因为即使零持续时间超时仍然会创建可取消的计划任务。 

### 具有多个参数的函数

 原始函数可以接受任意数量的参数。 

有缺陷的实现可能只支持单个参数，或者在重新调度期间丢失参数。 

该解决方案使用以下方法处理任意参数：```
*args
```在 Python 中和：```
args ...interface{}
```在围棋中。 

最新的参数在新安排的回调中捕获，确保正确的执行行为。
