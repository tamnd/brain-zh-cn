 ## 解决方案

 该问题在 LeetCode 上用 JavaScript 实现，但您请求使用 Python 和 Go 参考解决方案。 由于原始存根使用具有混合整数/数组值的 JavaScript 样式嵌套数组，因此我将在 Python 和 Go 中对结构进行惯用建模，同时保持逻辑完全可提交 LeetCode。 

## 问题理解

 该问题要求我们展平一个多维数组，但仅限于有限的深度`n`。 

多维数组是递归定义的。 每个元素可以是整数，也可以是另一个本身可以包含整数或附加嵌套数组的数组。 任务是删除嵌套数组边界，但仅当当前嵌套深度严格小于`n`。 

短语**“嵌套深度小于`n`“** 是决定扁平化何时停止的关键细节。

 我们从深度开始`0`，它对应于顶级数组。 如果我们遇到深度小于的嵌套子数组`n`，我们通过用其内容替换子数组来展平它。 一旦我们到达深度`n`，我们停止展平并按原样保留任何剩余的嵌套数组。 

例如，如果`n = 0`，没有任何东西会被展平，因为即使是最浅的嵌套数组也已经在深度了`0`， 和`0 < 0`是假的。 

如果`n = 1`，直接位于顶级数组内部的数组被展平，因为它们的深度是`0`，满足`0 < 1`。 但是，嵌套更深一层的数组会被保留，因为它们的深度变为`1`， 和`1 < 1`是假的。 

输入包括：

 -`arr`，包含整数和数组的递归嵌套数组结构
 -`n`, 最大压平深度

 输出应该是一个新的展平数组，其中嵌套数组仅扩展到允许的深度。 

这些约束揭示了几个重要的实现细节。 

数字和子数组的总数分别可以达到`10^5`，意味着整体结构可能非常大。 多次扫描阵列的简单重复展平方法可能会变得太慢。 

最大嵌套深度可为`1000`，这引入了另一个问题。 如果不小心实现，递归解决方案可能会在某些语言中面临堆栈溢出的风险。 然而，深度`1000`在大多数实际的递归上下文中是可以管理的，特别是在考虑递归限制的 Python 中，尽管迭代方法也可以工作。 

一些边缘情况值得关注：

 -`n = 0`，这意味着原始数组必须保持不变。 
- 空数组，它应该对输出没有任何贡献。 
- 深层嵌套结构，在完全展开之前扁平化停止。 
- 情况`n`超过最大嵌套深度，意味着整个结构完全变平。 
- 仅包含整数的数组，无论什么情况都不会发生扁平化`n`。 

该问题保证有效输入，这意味着元素始终是整数或嵌套数组，因此我们不需要额外的验证逻辑。 

## 方法

 ### 蛮力方法

 一种简单的方法是一次重复地展平阵列一层。 

对于每个展平过程，我们都会迭代当前数组。 如果一个元素是嵌套数组，我们会将其扩展到结果中。 否则，我们直接附加整数。 

我们完全重复这个过程`n`次。 

这是有效的，因为每次传递都会删除一层嵌套。 后`n`迭代后，数组已被展平至所需的深度。 

然而，这种方法效率低下。 每一遍都会再次扫描整个结构，甚至是之前已经处理过的元素。 在最坏的情况下，如果`n`如果数组很大并且嵌套很深，我们可能会重复遍历相同的元素。 

这种重复的工作使得解决方案变得不必要地昂贵。 

### 最优方法，深度控制 DFS

 关键的观察结果是我们不需要重复的展平过程。 相反，我们可以在跟踪当前深度的同时遍历该结构一次。 

每当我们遇到：

 - 一个整数，我们将其直接附加到结果中。 
- 嵌套数组：

 - 如果当前深度小于`n`，我们递归地探索它的内容。 
- 否则，我们保持子数组完整。 

这是有效的，因为展平决策仅取决于当前的嵌套深度。 通过在遍历过程中携带深度信息，我们可以立即决定是压平还是保留每个子数组。 

由于每个元素仅被访问一次，因此消除了重复工作并实现了最佳效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m) | O(米) | 一次重复展平一层，多次重新扫描元素 |
 | 最佳| O(米) | O(m + d) | 单次DFS遍历，每个元素处理一次 |

 这里：

-`m`是元素和嵌套数组的总数。 
-`d`是最大递归深度。 

## 算法演练

 ### 最优算法

 1. 创建一个空结果数组。 

该数组将存储最终的扁平化结构。 
2. 定义递归辅助函数。 

帮助者收到：

 - 当前子数组
 - 当前嵌套深度

 这使我们能够决定是否仍然允许扁平化。 
3. 迭代当前数组中的每个元素。 

对于每个元素，确定它是整数还是另一个数组。 
4. 如果元素是整数，则直接追加。 

结果中始终包含数字，因为展平仅影响数组边界。 
5. 如果元素是嵌套数组：

 - 如果`currentDepth < n`，递归处理嵌套数组。 

这有效地消除了一层嵌套。 
- 否则，按原样附加嵌套数组。 

一旦达到展平极限，就会保留结构。 
6.从有深度的顶层数组开始递归`0`。 
7. 遍历完成后返回结果数组。 

### 为什么它有效

 该算法保持一个简单的不变量：

 > 深度小于的每个嵌套数组`n`被展平，而深度上的每个数组`n`或更大的保持完好无损。 

由于遍历只访问每个元素一次，并立即根据深度做出扁平化决策，因此生成的结构与问题定义精确匹配。 

## Python 解决方案```python
from typing import List, Union

NestedInteger = Union[int, List["NestedInteger"]]

class Solution:
    def flat(self, arr: List[NestedInteger], n: int) -> List[NestedInteger]:
        result: List[NestedInteger] = []

        def dfs(current_array: List[NestedInteger], depth: int) -> None:
            for element in current_array:
                if isinstance(element, list):
                    if depth < n:
                        dfs(element, depth + 1)
                    else:
                        result.append(element)
                else:
                    result.append(element)

        dfs(arr, 0)
        return result
```实现直接遵循算法。 

我们首先创建一个`result`将累积展平元素的列表。 

嵌套的`dfs()`函数执行递归遍历。 它接收当前子数组和当前深度。 

在循环内部，我们使用以下方法区分整数和列表`isinstance(element, list)`。 

如果元素是一个列表并且仍然允许扁平化，这意味着`depth < n`，我们递归地处理它的内容`depth + 1`。 

否则，我们通过将嵌套列表附加到结果来完全保留其显示的样子。 

最后我们开始深度遍历`0`并返回完成的结果。 

## 解决方案```go
package main

func flat(arr []interface{}, n int) []interface{} {
	result := make([]interface{}, 0)

	var dfs func([]interface{}, int)

	dfs = func(currentArray []interface{}, depth int) {
		for _, element := range currentArray {
			if nestedArray, ok := element.([]interface{}); ok {
				if depth < n {
					dfs(nestedArray, depth+1)
				} else {
					result = append(result, nestedArray)
				}
			} else {
				result = append(result, element)
			}
		}
	}

	dfs(arr, 0)

	return result
}
```Go 实现密切反映了 Python 逻辑。 

由于Go天然不支持混合类型数组，因此我们使用`[]interface{}`来表示嵌套结构。 

类型断言用于确定元素是否是另一个嵌套切片：```go
nestedArray, ok := element.([]interface{})
```如果断言成功，我们就知道该元素是一个嵌套数组，并且可以决定是递归还是保留它。 

与 Python 不同，Go 需要显式切片处理和递归匿名函数的函数变量声明。 

这里不存在整数溢出问题，因为值仍在问题约束内。

 | --- | --- | --- |
 | 时间 | O(米) | 每个数字和子数组都被访问一次 |

 ## 边缘情况

 ###`n = 0`这是最容易处理不当的情况之一，因为它可能很容易自动展平第一层。 然而，条件**严格小于`n`**。 由于顶层深度是`0`，条件`0 < 0`立即失败。 

该实现自然地处理了这个问题，因为递归仅在以下情况下发生：`depth < n`。 

### 深度嵌套数组

 深层嵌套结构，例如：```
[[[[[1]]]]]
```可能会暴露出扁平化过度或停止过早的错误。 

该实现正确跟踪当前深度，并且仅在允许展平时递归。 一旦达到深度限制，剩余的嵌套数组将保持不变。 

###`n`大于最大深度

 有时，要求的展平深度超过实际嵌套深度。 

例如：```
arr = [1, [2, [3]]]
n = 100
```幼稚的实现可能会浪费精力重复遍历已经平坦的数组。 

一旦不再存在嵌套数组，DFS 方法就会自然终止，从而生成完全扁平化的结果，而无需进行不必要的重新扫描。 

### 空嵌套数组

 包含空数组的结构可能很微妙：```
[[], [[]], [[[]]]]
```展平这些不应引入额外的值或错误。 

递归遍历只是迭代空列表，对结果没有任何贡献，这会自动保留正确性。
