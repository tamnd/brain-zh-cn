 ## 解决方案

 ## 问题理解

 问题是要求我们为给定的函数实现 **currying**。 柯里化是一种函数式编程技术，其中具有多个参数的函数被转换为一系列函数，每个函数接受原始参数的子集。 本质上，您可以使用更少的参数多次调用函数，而不是一次使用其所有参数调用函数，并且一旦提供了所有参数，它就会返回最终结果。 

这个问题的输入是一个函数`fn`具有固定数量的参数，可以使用以下方式获得`fn.length`。 预期输出是柯里化版本`fn`可以使用任意参数组合调用它，直到提供了所有必需的参数。 一旦参数完成，柯里化函数将返回与原始函数相同的结果。 例如，一个函数`sum(a, b, c)`可以称为`curriedSum(1)(2)(3)`或者`curriedSum(1, 2)(3)`甚至`curriedSum()(1, 2, 3)`。 

约束告诉我们输入的数量是合理的（`1 <= inputs.length <= 1000`），函数参数的数量是可管理的（`0 <= fn.length <= 1000`），所有参数均为整数（`0 <= inputs[i][j] <= 10^5`）。 我们保证参数的总数`inputs`匹配的数量`fn`，这简化了验证。 边缘情况包括零参数函数（应立即返回结果）和使用空数组调用的函数（在函数准备好执行之前仍应累积参数）。 

关键观察结果：该函数可能会使用不同数量的参数被多次调用。 不累积参数的幼稚实现将因以下调用而失败`curriedSum(1)(2, 3)`。 另一个潜在的陷阱是多次调用带有空参数的函数，这不应破坏参数积累。 

## 方法

 暴力方法将尝试通过检查每次收到的参数数量并手动决定是否返回结果或嵌套函数来显式处理每个特定的调用模式。 这种方法既麻烦又容易出错，因为它需要考虑参数拆分的每种组合，从而使代码变得复杂且难以维护。 

最佳方法利用**闭包和论证积累**。 我们定义一个递归函数，每次调用时都会收集参数。 如果收集的参数总数少于原始函数的数量，则该函数返回一个接受更多参数的新函数。 如果收集的参数与数量匹配，则使用所有收集的参数执行原始函数。 这种方法很优雅，因为它自然地处理参数调用的任意组合，包括空调用。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 会尝试列举所有争论的分歧； 对于大 n | 效率低下
 | 最佳| 每次调用 O(1) | O(n) | 使用闭包来累积参数； 执行`fn`仅当收集所有参数时才执行一次 |

 ## 算法演练

 1. 首先定义一个函数`curry`接受原始函数`fn`。 
2. 内部`curry`，定义一个辅助函数`curried`维护一个列表`args`积累至今。 
3.每次`curried`被调用，将新参数附加到现有参数列表中。 
4.检查累计参数总数是否小于arity`fn`（IE。，`fn.length`）。 如果是，则返回一个将继续累积参数的新函数。 
5. 如果累积参数的数量等于或超过 arity`fn`， 称呼`fn`包含所有收集到的参数并返回结果。 
6.返回初始值`curried`函数来自`curry`。 

**为什么它有效：** 不变的是`curried`始终跟踪迄今为止提供的所有参数。 由于可以使用任意数量的参数调用 JavaScript 和 Python 函数，因此我们可以增量累积它们。 一旦参数总数与原始函数的预期计数匹配，我们就知道执行该函数是安全的。 这保证了任何有效的函数调用序列的正确结果。 

## Python 解决方案```python
from typing import Callable, Any

def curry(fn: Callable) -> Callable:
    def curried(*args_so_far):
        if len(args_so_far) >= fn.__code__.co_argcount:
            return fn(*args_so_far)
        return lambda *next_args: curried(*args_so_far, *next_args)
    return curried
```这`curry`函数定义了一个内部函数`curried`它需要可变数量的参数。 它检查累积参数的总数是否至少等于原始函数的元数。 如果是，则执行原始函数。 否则，它返回一个新的 lambda 函数，该函数继续累积参数。 使用`*args`允许柯里化函数在每次调用时接受任意数量的参数，包括零。 

## 解决方案```go
package main

import "reflect"

func Curry(fn interface{}) interface{} {
    fnValue := reflect.ValueOf(fn)
    fnType := fnValue.Type()
    arity := fnType.NumIn()

    var curried func([]reflect.Value) reflect.Value
    curried = func(argsSoFar []reflect.Value) reflect.Value {
        if len(argsSoFar) >= arity {
            result := fnValue.Call(argsSoFar)
            return result[0]
        }
        return reflect.MakeFunc(reflect.FuncOf(fnType.In(len(argsSoFar):), fnType.Out(), fnType.IsVariadic()), func(newArgs []reflect.Value) []reflect.Value {
            return []reflect.Value{curried(append(argsSoFar, newArgs...))}
        })
    }

    return curried([]reflect.Value{})
}
```在 Go 中，我们使用`reflect`包来一般处理函数，因为 Go 是静态类型的，并且本身不支持可变参数柯里化。 这`curried`函数将参数累积在切片中`reflect.Value`。 当收集到所需数量的参数时，它会使用以下命令调用原始函数`Call`。 否则，它返回一个新函数`reflect.MakeFunc`不断积累争论。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每次调用 O(1) | 每个柯里化调用仅附加参数并可能返回 lambda； 执行`fn`发生一次 |
 | 空间| O(n) | 在闭包中累积参数直到执行； 需要的空间与功能数量成正比|

 复杂性是有效的，因为参数积累是轻量级的，并且函数仅执行一次。 递归深度对应于柯里化函数被调用的次数，但这受限于`fn.length`。 

## 测试用例```python
def test_curry():
    def sum3(a, b, c):
        return a + b + c
    csum = curry(sum3)
    assert csum(1)(2)(3) == 6  # sequential calls
    assert csum(1, 2)(3) == 6  # partial arguments
    assert csum()(1, 2, 3) == 6  # empty calls
    def life():
        return 42
    clife = curry(life)
    assert clife() == 42  # zero-parameter function
    def add4(a, b, c, d):
        return a + b + c + d
    cadd4 = curry(add4)
    assert cadd4(1, 2)(3, 4) == 10
    assert cadd4()(1)(2)(3)(4) == 10
    assert cadd4(1)(2, 3, 4) == 10
test_curry()
