[LeetCode 问题 2615](https://leetcode.com/problems/sum-of-distances/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算每个索引`i`在数组中`nums`，之间的总距离`i`和所有其他索引`j`在哪里`nums[j] == nums[i]`。 

更正式地说，对于每个职位`i`，我们需要计算：$$\sum |i - j|$$对于所有指数`j`这样：

 -`nums[j] == nums[i]`-`j != i`如果没有其他匹配值，那么该索引的答案很简单`0`。 

简单来说，想象一下将包含相同值的所有索引分组在一起。 对于组中的每个索引，我们想知道所有其他匹配索引的距离有多远，并对这些距离求和。 

例如，考虑：```
nums = [1,3,1,1,2]
```价值`1`出现在索引处`[0,2,3]`。 

对于索引`0`，距离总和为：```
|0 - 2| + |0 - 3| = 5
```对于索引`2`：```
|2 - 0| + |2 - 3| = 3
```对于索引`3`：```
|3 - 0| + |3 - 2| = 4
```价值观`3`和`2`只出现一次，所以它们的距离是`0`。 

约束条件很重要：

 -`1 <= nums.length <= 10^5`-`0 <= nums[i] <= 10^9`该数组最多可以包含十万个元素，这立即排除了昂贵的二次解。 由于值可以大到`10^9`，我们不能依赖按值索引的频率数组。 相反，我们需要一个哈希映射来有效地对相同的数字进行分组。 

主要挑战是避免重复的距离计算。 一个幼稚的实现会将每个索引与每个其他索引进行比较，这对于大输入来说变得太慢。 

一些边缘情况值得尽早识别：

 - 每个值都是唯一的数组，每个结果都应该是`0`。 
- 所有值都相同的数组，每个索引必须计算到所有其他位置的距离。 
- 大型重复组，其中简单的重复求和变得非常昂贵。 
- 单元素数组，答案必须始终是`[0]`。 

## 方法

 ### 蛮力方法

 解决这个问题最直接的方法就是遍历每个索引`i`并将其与其他所有指标进行比较`j`。 

对于每对：

 - 如果`nums[i] == nums[j]`- 和`i != j`我们添加`|i - j|`到`arr[i]`。 

这种方法是正确的，因为它明确检查每个有效对并累积所需的距离。 

然而，它的效率极低。 由于我们将每个索引与其他每个索引进行比较，因此时间复杂度变为`O(n²)`。 

和`n = 10^5`，这可能需要：```
10^10 operations
```这太慢了。 

### 最佳方法，分组+前缀总和洞察

 关键的观察是，只有具有相同值的指数才重要。 

我们首先按值对索引进行分组，而不是重复扫描整个数组。 

例如：```
nums = [1,3,1,1,2]

groups:
1 -> [0,2,3]
3 -> [1]
2 -> [4]
```现在考虑一组索引：```
[0,2,3]
```对于索引`2`，我们想要：```
(2 - 0) + (3 - 2)
```我们可以使用前缀和，而不是单独重新计算每个距离。 

认为：```
positions = [0,2,3]
total_sum = 5
```对于职位`pos`在索引处`i`：

 左贡献：```
i * pos - left_sum
```正确的贡献：```
right_sum - (count_right * pos)
```这是有效的，因为：

 - 所有左边的位置都较小
 - 所有右边的位置都更大

 由于位置自然地按索引排序，因此绝对值消失在简单的减法中。 

这让我们可以在线性时间内计算每个组的答案。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 比较每对索引 |
 | 最佳| O(n) | O(n) | 对索引进行分组并使用前缀和 |

 ## 算法演练

 1. 创建一个哈希映射，其中每个数字映射到其索引列表。 

例如：```
nums = [1,3,1,1,2]

map:
1 -> [0,2,3]
3 -> [1]
2 -> [4]
```这使我们能够仅一起处理匹配的元素。 
2. 初始化一个用零填充的答案数组。 

由于仅出现一次的索引自动具有距离`0`，这给了我们正确的默认值。 
3. 独立处理每组指标。 

假设我们有：```
positions = [0,2,3]
```4. 计算持仓总数。 

例如：```
total_sum = 0 + 2 + 3 = 5
```我们将使用它来有效地计算右侧贡献。 
5. 维护一个运行的前缀和，称为`left_sum`。 

最初：```
left_sum = 0
```6. 迭代组中的每个位置。 

对于每个位置`pos`在索引处`i`在组中：

 计算左侧贡献：```
left_distance = i * pos - left_sum
```这给出了到所有较早位置的总距离。 
7. 计算右侧贡献。 

首先计算：```
right_sum = total_sum - left_sum - pos
```然后：```
right_distance =
    right_sum - (remaining_count * pos)
```8. 添加两项贡献。```
answer[pos] =
    left_distance + right_distance
```9. 更新前缀和。```
left_sum += pos
```10. 对每组重复此操作。 

### 为什么它有效

 对于任何一组匹配索引，位置都会自然排序，因为我们在数组扫描期间以升序遇到它们。 

对于给定的位置`pos`：

 - 左边的每个索引都有贡献`pos - left_index`- 右边的每个索引都有贡献`right_index - pos`使用前缀和可以让我们以数学方式聚合这些距离，而不是单独求和。 

由于每个索引在其组内只处理一次，并且每个距离贡献只计算一次，因此该算法始终计算正确的总距离。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def distance(self, nums: List[int]) -> List[int]:
        positions_map = defaultdict(list)

        # Group indices by value
        for index, value in enumerate(nums):
            positions_map[value].append(index)

        result = [0] * len(nums)

        # Process each group
        for positions in positions_map.values():
            total_sum = sum(positions)
            left_sum = 0
            group_size = len(positions)

            for i, position in enumerate(positions):
                left_distance = i * position - left_sum

                right_sum = total_sum - left_sum - position
                right_count = group_size - i - 1
                right_distance = right_sum - (
                    right_count * position
                )

                result[position] = (
                    left_distance + right_distance
                )

                left_sum += position

        return result
```该实现首先构建一个存储每个值的所有索引的哈希图。 由于只有相同的值才重要，因此此分组步骤可以让我们避免不必要的比较。 

然后我们创建用零填充的结果数组。 这自然会处理只出现一次的值。 

对于每组匹配位置，我们计算索引的总和。 在迭代过程中，`left_sum`跟踪所有以前见过的位置。 

在每个位置：

 -`left_distance`计算早期指数的贡献。 
-`right_distance`计算后来指数的贡献。 

通过将两者结合起来，我们可以得到该索引在恒定时间内的总距离。 

最后我们更新一下`left_sum`所以未来的计算包括当前位置。 

由于每个索引在分组后只处理一次，因此该解决方案可以在线性时间内高效运行。 

## 解决方案```go
func distance(nums []int) []int64 {
	n := len(nums)

	positionsMap := make(map[int][]int)

	// Group indices by value
	for i, value := range nums {
		positionsMap[value] = append(
			positionsMap[value],
			i,
		)
	}

	result := make([]int64, n)

	// Process each group
	for _, positions := range positionsMap {
		var totalSum int64

		for _, pos := range positions {
			totalSum += int64(pos)
		}

		var leftSum int64
		groupSize := len(positions)

		for i, pos := range positions {
			position := int64(pos)

			leftDistance :=
				int64(i)*position - leftSum

			rightSum :=
				totalSum - leftSum - position

			rightCount :=
				int64(groupSize - i - 1)

			rightDistance :=
				rightSum -
					(rightCount * position)

			result[pos] =
				leftDistance + rightDistance

			leftSum += position
		}
	}

	return result
}
```Go 实现遵循完全相同的算法，但包含一些特定于 Go 的注意事项。 

返回类型是`[]int64`，这是问题签名所必需的。 由于距离总和可能会变大，因此使用`int64`避免溢出风险。 

与 Python 整数不同，Go 整数具有固定大小。 因此，所有涉及加法和乘法的算术都显式转换为`int64`。 

切片用于分组位置，因为它们动态增长并有效存储索引。

 ## 边缘情况

 ### 单元素数组

 单元素数组是最小的有效输入：```
nums = [7]
```没有其他匹配索引，因此结果必须是：```
[0]
```有缺陷的实现可能会意外地假设每个组都包含多个元素。 我们的实现自然地处理了这个问题，因为单元素组产生的左和右贡献为零。 

### 所有元素都是唯一的

 考虑：```
nums = [1,2,3,4]
```每个值都只出现一次。 

简单的分组算法可能仍会尝试不必要的计算或错误地计算距离。 由于我们的答案数组是用零初始化的，并且每个单元素组没有贡献任何内容，因此会自动返回正确的输出。 

### 所有元素都相同

 考虑：```
nums = [5,5,5,5]
```每个索引都必须计算与每个其他索引的距离。 

这种情况很容易暴露二次解中的性能问题，因为每个元素都与其他元素相互作用。 

我们的前缀和方法可以在线性时间内有效地处理这个问题，计算所有距离和而无需重复的成对比较。 

### 大稀疏距离

 考虑：```
nums = [1,0,0,0,1]
```匹配值可能相差很远。 

在计算较大索引差距的绝对差异时，粗心的实现可能会出错。 我们使用左右贡献的数学公式可以统一且正确地处理附近和远处的位置。
