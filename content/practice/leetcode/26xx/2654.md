[LeetCode 问题 2654](https://leetcode.com/problems/minimum-number-of-operations-to-make-all-array-elements-equal-to-1/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、数论

 ## 解决方案

 ## 问题理解

 该问题给了我们一个正整数数组，`nums`。 在一次操作中，我们可以选择两个相邻的元素，`nums[i]`和`nums[i+1]`，并用最大公约数替换其中之一，`gcd`，这对中的。 

目标是使数组中的每个元素都等于`1`使用最少的操作次数。 如果连一个都无法生产`1`，那么答案一定是`-1`。 

重要的细节是每个操作仅影响相邻元素。 我们不能直接改变任意立场。 然而，gcd 运算有一个非常有用的属性：

 - 数字的gcd只能保持不变或减少。 
- 一旦`1`出现后，它变得极其强大，因为`gcd(1, x) = 1`对于任意正整数`x`。 

这意味着如果我们可以创建一个`1`，我们可以逐渐传播`1`通过对相邻元素重复应用 gcd 操作来遍及整个数组。 

限制相对较小：

 -`2 <= nums.length <= 50`-`1 <= nums[i] <= 10^6`由于数组长度最多为`50`，二次甚至三次解都是可行的。 我们不需要高度优化的高级数据结构。 

一些边缘情况很重要：

 - 如果数组已经包含一个或多个`1`s，我们不需要创建一个新的`1`。 我们只需要把现有的`1`s 到剩余位置。 
- 如果整个数组的gcd大于`1`，那么不可能产生`1`，因为 gcd 操作永远不能降低到所有元素的 gcd 以下。 
- 如果没有`1`初始存在，我们首先要找到gcd为的最短子数组`1`，因为这提供了创建第一个的最便宜的方法`1`。 

## 方法

 ### 蛮力方法

 强力解决方案将使用广度优先搜索或穷举递归来模拟所有可能的操作序列。 

在每一步中，我们都可以尝试每个相邻对和每个替换选择，生成许多可能的新数组。 最终我们将搜索将数组转换为所有内容所需的最少操作数`1`s。 

这种方法在理论上是正确的，因为它探索了每一种可能的操作顺序。 然而，它很快在计算上变得不可行。 每个状态都可以分支成许多新状态，并且可能的数组总数呈指数增长。 

即使只有`50`元素，详尽的状态探索成本太高。 

### 最佳观察

 关键的见解来自于理解 gcd 的行为方式。 

如果数组已经包含`1`，那么每个非一个元素都可以转换为`1`通过与相邻的 gcd 进行精确的一次操作`1`。 

因此：

 - 如果已经有`k`那些，我们正是需要`n - k`运营。 

当没有`1`最初。 

创造第一个`1`，我们需要一些连续的子数组，其 gcd 变为`1`。 假设最短的子数组有长度`L`。 

减少子数组的长度`L`转换为单个值需要`L - 1`GCD操作。 之后，我们将拥有一个`1`数组中的某处。 

然后我们需要另一个`n - 1`传播该信息的行动`1`到其他所有位置。 

所以总数变为：$$(L - 1) + (n - 1)$$因此，问题简化为寻找 gcd 等于的最短子数组`1`。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 探索所有可能的操作顺序 |
 | 最佳| O(n² log M) | O(n² log M) | O(1) | O(1) | 使用 gcd 1 | 查找最短子数组 |

 这里，`M`是数组中的最大值，因为 gcd 计算需要对数时间。 

## 算法演练

 1.首先统计数组中有多少个元素已经等于`1`。 
2. 如果至少有一个`1`已经存在，那么我们可以将每个非一个元素转换为`1`每个操作一次。 返回`n - count_of_ones`。 
3. 否则，增量计算整个数组的 gcd。 
4. 如果整个数组的gcd大于`1`，那么就不可能创建一个`1`。 返回`-1`。 
5. 如果创建一个`1`可能的话，搜索 gcd 等于的最短子数组`1`。 
6. 对于每个起始索引`i`, 初始化`current_gcd = nums[i]`。 
7. 使用索引一次扩展子数组一个元素`j`。 更新：$$current\_gcd = gcd(current\_gcd, nums[j])$$8. 一旦`current_gcd`变成`1`,记录子数组长度`j - i + 1`并停止扩展这个起始位置，因为任何更长的子数组都不会更好。 
9. 跟踪所有起始位置的最小长度。 
10. 如果最短有效子数组长度是`L`， 然后：

-`L - 1`运营创造第一`1`-`n - 1`运营将其扩散到各个岗位

 1、退货：$$(L - 1) + (n - 1)$$### 为什么它有效

 该算法之所以有效，是因为对相邻元素的 gcd 操作有效地允许我们将连续子数组减少为其累积 gcd。 子数组只能产生`1`如果它的 gcd 是`1`。 

具有 gcd 的最短子数组`1`最大限度地降低创建第一个的成本`1`。 一次一个`1`存在，每个剩余元素都需要一次额外的操作，因为`gcd(1, x) = 1`。 

因此，该算法始终计算尽可能少的操作数。 

## Python 解决方案```python
from typing import List
from math import gcd

class Solution:
    def minOperations(self, nums: List[int]) -> int:
        n = len(nums)

        ones_count = nums.count(1)

        # If we already have ones, spread them
        if ones_count > 0:
            return n - ones_count

        # Check if it is impossible
        overall_gcd = nums[0]
        for value in nums[1:]:
            overall_gcd = gcd(overall_gcd, value)

        if overall_gcd > 1:
            return -1

        # Find shortest subarray with gcd 1
        min_length = float("inf")

        for left in range(n):
            current_gcd = 0

            for right in range(left, n):
                current_gcd = gcd(current_gcd, nums[right])

                if current_gcd == 1:
                    min_length = min(min_length, right - left + 1)
                    break

        # Operations:
        # (min_length - 1) to create first 1
        # (n - 1) to spread it everywhere
        return (min_length - 1) + (n - 1)
```实现从计算有多少个开始`1`已经存在了。 这是一个重要的优化，因为现有的`1`大大简化了问题。 

如果至少有一个`1`存在，答案立即`n - ones_count`，因为每个非一个元素都可以单独转换。 

如果没有`1`存在，代码计算整个数组的 gcd。 如果 gcd 大于`1`，函数返回`-1`因为创建一个`1`在数学上是不可能的。 

然后，嵌套循环搜索最短子数组，其 gcd 变为`1`。 内部循环增量更新 gcd，而不是从头开始重新计算，这保持了实现的效率。 

最后，公式：```python
(min_length - 1) + (n - 1)
```结合了创建第一个的成本`1`并将其分散到整个阵列中。 

## 解决方案```go
package main

func gcd(a, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func minOperations(nums []int) int {
	n := len(nums)

	onesCount := 0
	for _, value := range nums {
		if value == 1 {
			onesCount++
		}
	}

	// If there are already ones
	if onesCount > 0 {
		return n - onesCount
	}

	// Compute gcd of entire array
	overallGCD := nums[0]
	for i := 1; i < n; i++ {
		overallGCD = gcd(overallGCD, nums[i])
	}

	// Impossible to create 1
	if overallGCD > 1 {
		return -1
	}

	// Find shortest subarray with gcd 1
	const INF = int(1e9)
	minLength := INF

	for left := 0; left < n; left++ {
		currentGCD := 0

		for right := left; right < n; right++ {
			currentGCD = gcd(currentGCD, nums[right])

			if currentGCD == 1 {
				length := right - left + 1
				if length < minLength {
					minLength = length
				}
				break
			}
		}
	}

	return (minLength - 1) + (n - 1)
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于Go没有提供内置的gcd函数，因此我们手动实现Euclid算法。 

直接使用Go切片，整数溢出不是问题，因为问题约束很小。 除了一些变量之外，该解决方案仅使用恒定的额外空间。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n² log M) | O(n² log M) | 子数组上的嵌套循环，每个 gcd 需要对数时间 |

该算法使用恒定的辅助空间，因为不需要与输入大小成比例的额外数据结构。

 ## 边缘情况

 当数组已包含一个或多个时，会出现一种重要的边缘情况`1`s。 幼稚的实现可能仍然会尝试不必要地搜索 gcd-1 子数组。 然而，一旦`1`存在，每个相邻元素都可以变成`1`在一次操作中。 实现立即处理这个问题：```
if ones_count > 0:
    return n - ones_count
```另一个重要的边缘情况是整个数组的 gcd 大于`1`。 在这种情况下，任何 gcd 操作序列都不会产生`1`。 这是因为 gcd 操作永远无法降低到所有元素共享的 gcd 以下。 实现在尝试任何子数组搜索之前显式检查这一点。 

第三个棘手的边缘情况是当最短的 gcd-1 子数组的长度大于`2`。 一些不正确的解决方案假设任何与 gcd 的配对`1`就足够了。 然而，数组像`[6,10,15]`需要使用整个子数组来将 gcd 减少到`1`。 嵌套循环正确检查每个可能的连续子数组并找到最小有效长度。
