[LeetCode 问题 2616](https://leetcode.com/problems/minimize-the-maximum-difference-of-pairs/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、动态规划、贪心、排序

 ## 解决方案

 ## 问题理解

 问题要求我们准确选择`p`数组中不相交的对`nums`使得所有选定对之间的最大差异尽可能小。 

对于每对`(i, j)`，对差值定义为：$$|nums[i] - nums[j]|$$目标不是最小化差异之和，而是最小化所有选定对的最大差异。 

每个索引只能属于一对，这意味着所选对必须是不相交的。 

输入包括：

 -`nums`，整数数组
 -`p`，我们必须形成的对的数量

 输出是一个整数，表示最大对差异的最小可能值。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 里面的价值观`nums`可以达到`10^9`这些限制立即排除了指数或二次配对策略。 我们需要一些接近的东西`O(n log n)`。 

一个重要的观察结果是，对数组进行排序后，配对差异变得更容易推理。 一旦排序，附近的元素往往会产生最小的差异。 

有几种边缘情况值得考虑：

 -`p = 0`，我们根本不需要任何对。 答案一定是`0`。 
- 包含重复值的数组，其中零差值对是可能的。 
- 数字之间存在较大差距，这可能会导致最大差异更大。 
- 贪婪地选择局部最小对的情况可能会显得有风险，除非仔细证明是合理的。 
- 具有奇数和偶数长度的数组。 

该问题保证：

 -`0 <= p <= nums.length / 2`- 因此，总是可以形成`p`不相交的对。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试一切可能的方式来形成`p`不相交的对，计算每种排列的最大差异，然后在所有可能性中取最小值。 

例如，如果我们有：```
nums = [1,2,3,4]
p = 2
```我们将枚举所有有效的对组合：

 -`(1,2)`和`(3,4)`-`(1,3)`和`(2,4)`-`(1,4)`和`(2,3)`对于每种排列，我们计算最大的配对差异并保留最小结果。 

这种方法是正确的，因为它详尽地检查了所有可能性。 

然而，配对组合的数量呈指数增长。 即使对于中等大小的数组，这在计算上也是不可能的。 自从`n`可以达到`100000`，暴力破解是完全行不通的。 

### 关键见解

 关键的观察是我们不需要直接构建最佳配对安排。 

相反，我们可以二分查找答案。 

Suppose we guess a value`maxDiff`。 

问题变成：

 > 我们能至少组成`p`不相交的对，使得每对差异最多`maxDiff`？ 

这将优化问题转化为决策问题。 

对数组进行排序后，最大化有效对数量的最佳方法是，只要相邻元素的差异足够小，就贪婪地对它们进行配对。 

为什么相邻元素？ 

因为在排序数组中，相邻元素总是产生尽可能小的差异。 将不相邻的元素配对只会增加差异，并可能浪费较小的配对机会。 

这给了我们：

 1. 对数组进行排序。 
2.二分查找最小可行最大差值。 
3. 使用贪婪扫描来检查可行性。 

这种组合产生了有效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 尝试每一种可能的配对组合 |
 | 最佳| O(n log n + n log M) | O(n log n + n log M) | O(1) 或 O(log n) 取决于排序 | 通过贪婪可行性检查对答案进行二分搜索 |

 这里，`M`represents the range of values in the array.

 ## 算法演练

 1. 对数组进行排序。 

Sorting places close values next to each other. 由于需要小的差异，因此相邻元素成为自然的配对候选者。 
2. Define the binary search range.

 The smallest possible maximum difference is`0`。 

最大可能的最大差异是：```
nums[-1] - nums[0]
```排序后。 
3. 对答案进行二分查找。 

对于每个中点`mid`，将其视为候选最大允许差异。 
4. 贪婪地检查可行性。 

从左到右遍历排序后的数组。 

每当：```
nums[i + 1] - nums[i] <= mid
```形成一对并跳过这两个元素。 

否则，移至下一个元素。 
5. 计算形成了多少对。 

如果我们至少可以形成`p`对，那么`mid`是可行的。 

尝试通过向左移动二分查找来找到更小的答案。 
6. 否则，如果少于`p`成对是可能的，增加允许的差异。 
7. 继续直到二分查找收敛。 
8. 返回最小的可行最大差值。 

### 为什么它有效

 正确性依赖于两个属性。 

首先，二分搜索之所以有效，是因为可行性是单调的。 如果我们能够形成`p`具有最大差异的对`x`，那么我们也可以形成`p`与任何大于的值配对`x`。 

其次，排序后贪婪配对策略是最优的。 配对相邻的有效元素可以保留尽可能多的未来配对机会。 任何具有更宽间隙的替代配对都不能增加可实现配对的数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimizeMax(self, nums: List[int], p: int) -> int:
        if p == 0:
            return 0

        nums.sort()

        def can_form_pairs(max_diff: int) -> bool:
            pair_count = 0
            index = 0

            while index < len(nums) - 1:
                if nums[index + 1] - nums[index] <= max_diff:
                    pair_count += 1
                    index += 2
                else:
                    index += 1

                if pair_count >= p:
                    return True

            return False

        left = 0
        right = nums[-1] - nums[0]

        while left < right:
            mid = (left + right) // 2

            if can_form_pairs(mid):
                right = mid
            else:
                left = mid + 1

        return left
```实施从提前返回开始`p == 0`。 由于不需要对，因此空集的最大差值定义为零。 

然后对数组进行排序，以便附近的元素可以有效地配对。 

辅助函数`can_form_pairs`检查给定的最大差异是否可行。 它贪婪地扫描数组并将相邻元素配对，只要它们的差异不超过`max_diff`。 

当形成一对时，两个索引都会被跳过，因为索引不能重复使用。 

然后对可能答案的范围应用二分搜索。 如果候选差异是可行的，我们会尝试进一步减少它。 否则，我们会增加允许的差异。 

最终，`left`收敛到最小的可行最大差值。 

## 解决方案```go
package main

import "sort"

func minimizeMax(nums []int, p int) int {
	if p == 0 {
		return 0
	}

	sort.Ints(nums)

	canFormPairs := func(maxDiff int) bool {
		pairCount := 0
		index := 0

		for index < len(nums)-1 {
			if nums[index+1]-nums[index] <= maxDiff {
				pairCount++
				index += 2
			} else {
				index++
			}

			if pairCount >= p {
				return true
			}
		}

		return false
	}

	left := 0
	right := nums[len(nums)-1] - nums[0]

	for left < right {
		mid := left + (right-left)/2

		if canFormPairs(mid) {
			right = mid
		} else {
			left = mid + 1
		}
	}

	return left
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于可行性函数使用 Go 闭包。 Go 还使用`sort.Ints(nums)`用于排序。 

二分查找中点计算如下：```go
mid := left + (right-left)/2
```这避免了整数范围固定的语言中潜在的整数溢出。 

Go 中的切片的行为与动态数组类似，因此不需要额外的内存处理。

 排序步骤成本`O(n log n)`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`p = 0`。 在这种情况下，不需要对，因此空集上的最大差值定义为零。 粗心的实现可能仍然会尝试二分搜索或不必要的配对逻辑。 该实现会立即处理此问题并提前返回。 

另一个关键情况涉及重复值。 数组如：```
[2,2,2,2]
```允许零差对。 某些实现会意外地跳过最佳重复配对或错误处理相等比较。 贪婪可行性检查正确使用`<= max_diff`，确保在允许时配对相等的值。 

当数组的值之间存在较大间隙时，就会出现第三种重要的边缘情况。 例如：```
[1,100,200,300]
```错误地选择对会很快产生不必要的大的最大差异。 排序和相邻贪婪配对确保尽可能最小的局部差异始终被优先考虑。 

当数组长度为奇数时，会出现微妙的边缘情况。 由于并非必须使用每个元素，因此算法必须在有益时正确地跳过元素。 贪婪扫描自然会处理这个问题，因为它仅在满足当前最大差异约束时才形成一对。 

最后，具有最大约束的数组需要效率。 自从`n`可以是`100000`，二次动态规划或详尽配对会超时。 二分搜索加贪婪可行性策略即使在最大输入大小下也能保证可接受的性能。
