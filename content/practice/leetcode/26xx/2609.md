[LeetCode 问题 2609](https://leetcode.com/problems/find-the-longest-balanced-substring-of-a-binary-string/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`，这意味着字符串仅包含字符`'0'`和`'1'`。 我们需要找到被认为平衡的最长子串的长度。 

当满足两个条件时，子串是平衡的：

 1. 所有零出现在所有一之前。 
2. 0 的数量等于 1 的数量。 

这意味着每个有效的平衡子串必须具有以下结构：```
000...111...
```其中 0 和 1 的数量完全相同。 

例如：

-`"0011"`是平衡的，因为它包含两个零，后面跟着两个一。 
-`"000111"`是平衡的，因为它包含三个零，后跟三个一。 
-`"0101"`不平衡，因为字符交替出现，而不是将所有零分组在一个之前。 
-`"011"`不平衡，因为计数不同。 

任务是返回所有平衡子串中最大可能的长度。 如果不存在非空平衡子串，则返回`0`。 该问题明确指出空子串是平衡的，这保证了答案总是至少`0`。 

限制非常小：

 -`1 <= s.length <= 50`由于输入大小很小，从性能角度来看，即使是暴力解决方案也是可以接受的。 然而，目标仍然是设计一个干净高效的算法。 

一些边缘情况很重要：

 - 一个字符串只包含`'1'`字符，例如`"111"`，没有有效的非空平衡子串。 
- 一个字符串只包含`'0'`字符也没有有效的平衡子字符串，因为没有与零匹配的子字符串。 
- 具有多个组的字符串，例如`"0001110011"`，需要仔细检查转换，因为最佳答案可能出现在中间。 
- 像这样的字符串`"010101"`包含许多短的有效子字符串，但不包含长的子字符串。 

关键的观察是每个平衡子串必须围绕从`'0'`到`'1'`。 

## 方法

 ### 蛮力方法

 暴力解决方案检查每个可能的子串`s`。 

对于每个子字符串，我们验证是否：

 1. 所有零都在所有一之前。 
2. 0 的数量等于 1 的数量。 

为了执行验证，我们可以逐个字符地扫描子字符串。 我们计算零和一，同时也确保一旦遇到`'1'`，我们再也见不到另一个`'0'`。 

如果子字符串满足所有条件，我们将更新最大长度。 

这种方法是正确的，因为它显式地评估每个可能的子串并直接测试平衡子串的定义。 然而，它的效率很低，因为有很多子字符串需要检查。 

带有长度的字符串`n`：

- 有`O(n²)`子串。 
- 验证每个子字符串需要`O(n)`时间。 

这产生了总体复杂度`O(n³)`。 

虽然`n <= 50`使这一点可以接受，我们可以做得更好。 

### 最佳方法

 重要的观察是每个平衡子串都包含：

 - 连续的零块
 - 紧接着是一个连续的块

 例如：```
000111
```如果我们知道：

 - 转换前连续零的数量
 - 转换后连续的数量

 那么以该转换为中心的最大平衡子串的长度为：```
2 * min(zero_count, one_count)
```为什么这有效？ 

假设我们有：```
0000111
```有 4 个零和 3 个一。 我们只能匹配 3 对，所以最长的平衡子串是：```
000111
```与长度`6`。 

我们可以通过跟踪连续的字符组一次性解决该问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 检查每个子字符串并直接验证它 |
 | 最佳| O(n) | O(1) | O(1) | 计算连续的零组和一组 |

 ## 算法演练

 1.初始化三个变量：

 -`previous_zero_count`-`current_one_count`-`max_length`这些变量有助于跟踪当前的零组和一组。 
2. 从左到右遍历字符串。 
3. 当我们遇到一组零时，计算出现了多少个连续的零。 
4. 零组结束后，立即计算其后面有多少个连续的。 
5. 对两组进行计数后：

 - 使用这些组的最大平衡子串的长度为：```
2 * min(zero_count, one_count)
```1. 更新`max_length`如果这个平衡子串大于当前答案。 
2. 继续扫描字符串的其余部分，直到遍历完成。 
3. 返回`max_length`。 

### 为什么它有效

 每个有效的平衡子字符串必须由连续的零和后跟的连续的 1 组成。 因此，每个平衡子串完全由一对相邻的组确定：```
000...111...
```限制因素是较小的组，因为我们需要相同数量的 0 和 1。 服用：```
2 * min(zero_count, one_count)
```保证该转换有最大可能的平衡子串。 由于该算法仅检查每个此类转换一次，因此它总是找到全局最大值。 

## Python 解决方案```python
class Solution:
    def findTheLongestBalancedSubstring(self, s: str) -> int:
        n = len(s)
        max_length = 0
        i = 0

        while i < n:
            zero_count = 0
            one_count = 0

            while i < n and s[i] == '0':
                zero_count += 1
                i += 1

            while i < n and s[i] == '1':
                one_count += 1
                i += 1

            max_length = max(max_length, 2 * min(zero_count, one_count))

        return max_length
```该实现使用单个索引`i`遍历字符串。 

在每一步中，算法首先计算一组连续的零。 之后，它会计算紧随这些零之后的连续一组。 

一旦知道两个计数，算法就会计算该组对可能的最大平衡子串。 由于需要相同数量的零和一，因此较小的计数决定了我们可以形成多少个匹配对。 

表达式：```python
2 * min(zero_count, one_count)
```给出当前段的最大平衡子串的长度.

 该算法重复此过程，直到处理完整个字符串。 

## 解决方案```go
func findTheLongestBalancedSubstring(s string) int {
	n := len(s)
	maxLength := 0
	i := 0

	for i < n {
		zeroCount := 0
		oneCount := 0

		for i < n && s[i] == '0' {
			zeroCount++
			i++
		}

		for i < n && s[i] == '1' {
			oneCount++
			i++
		}

		currentLength := 2 * min(zeroCount, oneCount)

		if currentLength > maxLength {
			maxLength = currentLength
		}
	}

	return maxLength
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有为普通整数提供内置的整数最小值函数，因此我们定义了一个助手`min`功能。 

Go 中的字符串可以直接使用索引`s[i]`因为输入仅包含 ASCII 字符`'0'`和`'1'`。 不需要额外的 Unicode 处理。 

该算法仅使用整数变量和常量额外内存。

 ## 边缘情况

 一个重要的边缘情况是仅包含一种类型字符的字符串，例如`"0000"`或者`"1111"`。 幼稚的实现可能会错误地假设任何重复模式都有助于平衡子串。 然而，平衡子串需要零和一。 该实现自然地处理了这个问题，因为其中一个计数变为零，使得：```
2 * min(zero_count, one_count)
```等于零。 

另一个重要的情况是零和一的计数不相等，例如`"0001111"`。 该算法必须正确地仅使用较小的计数，因为平衡子字符串需要两个字符的数量相等。 该实现通过取两个计数中的最小值来处理这个问题，产生：```
2 * min(3,4) = 6
```而不是错误地返回`7`。 

第三个棘手的情况是交替模式，例如`"010101"`。 很容易错误地将多个独立的平衡区域组合成一个更大的答案。 但是，平衡子字符串必须在所有 1 之前包含所有 0。 该实现一次处理一个连续的零组和一个连续的一组，防止无效组合并正确返回`2`。 

当平衡子串出现在字符串中间时，会出现另一种微妙的边缘情况，例如`"100011"`。 仅关注前缀或后缀的幼稚实现可能会错过这一点。 线性扫描检查每个相邻的零组和一组对，确保正确考虑字符串中任何位置的平衡子串。
