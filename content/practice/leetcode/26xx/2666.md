 ## 解决方案

 ## 问题理解

 这个问题要求我们围绕现有函数创建一个包装器`fn`这样包装后的版本只能执行原始函数一次。 

换句话说，我们有一个函数`fn`，并且我们必须返回一个新函数。 这个返回函数的行为与`fn`在第一次调用期间，这意味着它接受相同的参数并返回相同的结果。 但是，在第一次成功执行之后，以后的每个调用都必须立即返回`undefined`不打电话`fn`再次。 

关键要求是原始函数最多只能执行一次。 这意味着我们需要某种方法来记住该函数是否已经被调用。 

输入由一个函数组成`fn`，它可以采用任意参数。 这些示例显示函数接收多个参数，但我们的解决方案必须适用于任意数量的参数，因为 JavaScript 函数很灵活。 返回的函数应通过将所有收到的参数转发到`fn`。 

预期输出不是直接值，而是修改后的函数。 当第一次调用这个返回函数时，它会执行`fn`并返回结果。 之后的每个调用都会返回`undefined`。 

限制非常小。 调用次数介于`1`和`10`，并且参数列表相对较短。 因此，效率并不是主要问题。 然而，问题是测试对函数闭包和状态持久性的理解，而不是算法性能。 

有几个重要的边缘情况需要考虑。 包装的函数只能被调用一次，这意味着我们仍然应该毫无问题地返回正确的结果。 包装的函数还可能在以后的调用中接收不同的参数，但这些参数应该被忽略，因为`fn`绝不能再次执行。 另一个重要的细节是`fn`可以返回任何有效的 JavaScript 值，包括`0`,`false`， 或者`null`，因此我们无法通过检查返回值来确定该函数是否已经被调用。 相反，我们必须显式跟踪执行状态。 

## 方法

 ### 蛮力方法

 解决这个问题的一个强力方法是将所有先前的调用存储在一个集合中，并在再次运行之前检查该函数是否已经执行过。 

例如，我们可以维护先前调用的数组。 每次执行返回的函数时，我们都会检查该数组是否为空。 如果它是空的，我们调用`fn`，保存有关调用的信息，并返回结果。 否则，我们返回`undefined`。 

这种方法是正确的，因为它确保`fn`只执行一次。 然而，它使用了不必要的存储和簿记。 由于我们只关心该函数是否已经被调用，因此存储调用历史记录是过多的。 

### 最佳方法

 关键的观察是我们只需要一条信息：是否`fn`已经被执行了。 

一个简单的布尔变量就足够了。 我们可以初始化一个标志，例如`called = false`。 返回的函数在运行时检查此标志：

 - 如果`called`是`false`，将其标记为`true`， 执行`fn`，并返回结果。 
- 如果`called`已经是`true`， 返回`undefined`。 

这是有效的，因为闭包允许返回的函数记住周围范围中的变量，即使在外部函数完成执行之后也是如此。 布尔状态在调用之间持续存在。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(1) | O(1) | O(1) | O(1) | 存储不必要的通话记录或额外的簿记 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用带有布尔标志的闭包 |

 尽管这两种方法在实践中都具有恒定的复杂性，但最佳解决方案更清晰并且仅使用最少的必要状态。 

## 算法演练

 1.定义一个布尔变量，如`called`，并将其初始化为`false`。 该变量跟踪是否`fn`已经执行了。 
2. 返回一个接受任意参数的新函数。 这确保了包装器的行为与原始函数类似，无论参数数量如何。 
3. 在返回的函数中，检查`called`旗帜。 如果已经是`true`，立即返回`undefined`。 这可以防止将来执行`fn`。 
4.如果`called`是`false`，将其设置为`true`打电话之前`fn`。 首先更新标志可以保证即使`fn`行为异常，未来的呼叫仍被阻止。 
5. 执行`fn`使用提供的参数并返回其结果。 

### 为什么它有效

 正确性来自于维护一个简单的不变量：一旦`called`变成`true`，它永远不会变回`false`。 由于闭包在函数调用之间保留变量，因此返回函数的每次调用都会看到更新的状态。 所以，`fn`只执行一次，后面的所有调用都返回`undefined`。 

## Python 解决方案

 由于这是 LeetCode 上的 JavaScript 函数问题，因此下面的 Python 等效问题在 Python 语法中演示了相同的基于闭包的逻辑。```python
from typing import Callable, Any

class Solution:
    def once(self, fn: Callable[..., Any]) -> Callable[..., Any]:
        called = False

        def wrapper(*args, **kwargs):
            nonlocal called

            if called:
                return None  # Python equivalent of undefined

            called = True
            return fn(*args, **kwargs)

        return wrapper
```实现首先定义一个名为的布尔变量`called`并将其设置为`False`。 该变量存在于外部作用域中`once`方法并充当持久状态。 

嵌套的`wrapper`函数接受任意位置和关键字参数`*args`和`**kwargs`。 这反映了 JavaScript 函数的灵活性，并允许包装器支持任何函数签名。 

里面`wrapper`， 这`nonlocal`关键字允许修改`called`在封闭范围内定义的变量。 如果`called`已经是`True`，函数立即返回`None`，它相当于 JavaScript 的 Python 等价物`undefined`。 

如果该函数尚未执行，则该标志将更新为`True`， 和`fn`使用提供的参数调用。 结果`fn`则直接返回。 

## 解决方案

 Go 不以同样的方式支持 JavaScript 风格的可变参数动态类型，但闭包的工作原理类似。 我们可以使用返回函数捕获的布尔变量。```go
package main

func once(fn func(...interface{}) interface{}) func(...interface{}) interface{} {
	called := false

	return func(args ...interface{}) interface{} {
		if called {
			return nil
		}

		called = true
		return fn(args...)
	}
}
```Go 实现使用闭包`called`多变的。 由于 Go 中的函数可以从其周围范围捕获变量，因此布尔状态在调用过程中保持不变。 

而不是返回`undefined`, Go 返回`nil`，这是最接近的等价物。 该函数接受`...interface{}`以便可以传递任意参数，类似于 JavaScript 灵活的参数系统。

class Solution:
    def once(self, fn: Callable[..., Any]) -> Callable[..., Any]:
        called = False

        def wrapper(*args, **kwargs):
            nonlocal called

            if called:
                return None

            called = True
            return fn(*args, **kwargs)

        return wrapper

solution = Solution()

# Example 1: addition function

assert once_fn(2, 3, 6) is None  # second call blocked

# Example 2: multiplication function

assert once_fn(2, 3, 6) is None  # second call blocked
assert once_fn(4, 6, 8) is None  # third call blocked

once_fn = solution.once(lambda x: x * 2)

assert once_fn() is False  # valid boolean result
assert once_fn() is None  # second call blocked

once_fn = solution.once(lambda: 42)
assert once_fn() == 42  # works without parameters
assert once_fn() is None  # blocked afterward

 ## 边缘情况

 一个重要的边缘情况是原始函数返回一个虚假值，例如`0`,`False`， 或者`None`。 幼稚的实现可能会错误地使用返回值来确定该函数是否已被调用。 例如，检查存储的结果是否存在将失败`0`或者`False`。 此实现通过使用专用布尔标志跟踪执行来完全避免该问题。 

当包装函数仅被调用一次时，会发生另一个重要的情况。 某些实现意外地假设了多次调用，并且可能会错误地处理初始化或状态转换。 在此实现中，第一个调用只是正常执行并更新标志，因此单个调用无需特殊处理即可工作。 

第三种边缘情况是稍后的调用使用完全不同的参数。 由于该问题保证函数只能执行一次，因此必须完全忽略后面的参数。 该实现在尝试执行任何操作之前检查布尔标志，确保后续输入无效。 

最后，必须正确处理具有不同数量参数的函数。 某些函数可能采用零个参数，而其他函数可能采用多个参数。 通过使用`*args`和`**kwargs`在 Python 中，以及 Go 中的可变参数，该实现无需修改即可支持任何函数签名。
