 **难度：** 🔴难
 **主题：** 数组、数学、动态规划、排序、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算每个可能的非空英雄子集的总“力量”。 

对于任何选定的英雄组，其力量定义为：$$(\text{maximum strength in the group})^2 \times (\text{minimum strength in the group})$$我们得到一个数组`nums`，其中每个值代表一个英雄的强度。 我们必须考虑该数组的每个非空子集，计算该子集的幂，并将所有这些幂相加。 

最终答案可能会变得非常大，因为最多有：$$2^n - 1$$可能的非空子集。 自从`n`可以大到`10^5`，暴力枚举是不可能的。 因此，必须以模数返回答案：$$10^9 + 7$$约束是需要优化组合或动态规划方法的关键指标：

 -`nums.length <= 10^5`意味着任何指数或二次子集处理都是不可行的。 
-`nums[i] <= 10^9`意味着整数溢出必须小心处理。 
- 我们需要一些接近的东西`O(n log n)`或者`O(n)`。 

一些边缘情况很重要：

 - 具有所有相同值的数组，因为许多子集产生相同的最小值和最大值。 
- 仅包含一个元素的数组，其中子集仅由该英雄组成。 
- 严格递增数组，每个新添加的值都会更改最大值。 
- 大值接近`10^9`，这需要在整个计算过程中进行模运算。 

最大的挑战是避免显式子集枚举，同时仍然正确地考虑每个子集的贡献。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个非空子集`nums`。 

对于每个子集：

 1. 求最小值。 
2. 找到最大值。 
3. 计算：$$\text{max}^2 \times \text{min}$$1. 将其添加到答案中。 

这种方法是正确的，因为它确实遵循问题定义。 

然而，子集的数量是指数级的：$$2^n - 1$$即使是为了`n = 30`，这变得不切实际。 和`n = 10^5`，暴力破解是完全不可能的。 

此外，计算每个子集的最小值和最大值会进一步增加开销。 

### 最佳解决方案的关键见解

 关键的观察是我们可以对数组进行排序并系统地计算贡献，而不是显式地生成子集。 

假设数组已排序：$$a_0 \le a_1 \le a_2 \le \dots \le a_{n-1}$$现在考虑一些值`a[i]`充当子集的最大元素。 

如果`a[i]`是最大值，那么每个选择的元素必须来自索引`< i`。 

子集幂变为：$$a[i]^2 \times (\text{minimum chosen element})$$所以真正的挑战变成了：

 对于每一个`a[i]`，有效计算以结尾的子集之间所有可能的最小值的总和`i`。 

这导致了动态积累模式。 

从左到右处理值时：

 - 每个先前的值可以出现在子集中，也可以不出现在子集中。 
- 每次我们添加新数字时，之前的贡献都会翻倍，因为每个现有子集都可以包含或排除新的中间元素。 

这将创建一个前缀重复：$$\text{prefix} = 2 \times \text{prefix} + a[i]$$前缀变量有效地跟踪当前数量为最大值的所有子集的最小贡献之和。

 ## 算法演练

 1. 对数组进行非降序排序。 

排序使我们能够按照从最小到最大的顺序处理元素。 排序后，当我们处理时`nums[i]`，我们知道它是该步骤中考虑的每个子集的最大元素。 
2.初始化三个变量：

 -`MOD = 10^9 + 7`-`answer = 0`-`prefix = 0`这`prefix`变量存储由先前处理的元素形成的所有可能的子集最小值的累积贡献。 
3. 迭代已排序的数组。 

设当前值为`x`。 
4. 计算贡献，其中`x`是最大值。 

每个子集结束于`x`贡献：$$x^2 \times (\text{sum of all possible minimums})$$最低捐款总额等于：$$x + \text{prefix}$$独立式`x`对应于仅包含的子集`x`。 

所以贡献就变成了：$$x^2 \times (x + \text{prefix})$$将其添加到答案中。 

1.更新前缀贡献。 

加工后`x`，未来的元素可能至少会使用它。 

每个先前的子集都可以包含或排除`x`，所以之前的贡献加倍。 

此外，`x`本身形成一个新的单例子集。 

所以：$$\text{prefix} = 2 \times \text{prefix} + x$$1. 每次算术更新后应用模运算。 

这可以防止溢出并满足问题要求。 
2. 返回最终答案。 

### 为什么它有效

 排序后，每个子集都有一个唯一确定的最大元素，即最大选择值。 

加工时`nums[i]`，所有有效子集，其中`nums[i]`最大值是通过将其与先前元素的任意子集组合而形成的。 

这`prefix`变量紧凑地表示这些子集中所有可能的最小值的总贡献。 因为每个新元素都会使先前最小值出现的方式数量加倍，所以递归自然会出现。 

因此，每个子集在其最大元素下仅计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def sumOfPower(self, nums: List[int]) -> int:
        MOD = 10**9 + 7

        nums.sort()

        answer = 0
        prefix = 0

        for x in nums:
            contribution = (x * x) % MOD
            contribution = (contribution * (x + prefix)) % MOD

            answer = (answer + contribution) % MOD

            prefix = (2 * prefix + x) % MOD

        return answer
```该实现首先对数组进行排序，以便每个元素都可以被视为该迭代中处理的所有子集的最大值。 

变量`prefix`存储使用先前处理的元素形成的所有子集的累积最小贡献。 

对于每个值`x`：

 -`x * x`计算最大值的平方。 
-`(x + prefix)`表示所有子集的总最小贡献，其中`x`是最大的。 
- 他们的乘积给出了所有这些子集的总贡献。 

将贡献添加到最终答案后，前缀重现：```python
prefix = 2 * prefix + x
```更新未来迭代的运行子集最小总数。 

始终应用模运算以避免溢出并遵守问题约束。 

## 解决方案```go
package main

import (
	"sort"
)

func sumOfPower(nums []int) int {
	const MOD int64 = 1_000_000_007

	sort.Ints(nums)

	var answer int64 = 0
	var prefix int64 = 0

	for _, value := range nums {
		x := int64(value)

		contribution := (x * x) % MOD
		contribution = (contribution * ((x + prefix) % MOD)) % MOD

		answer = (answer + contribution) % MOD

		prefix = (2*prefix + x) % MOD
	}

	return int(answer)
}
```Go 实现遵循与 Python 版本完全相同的数学逻辑。 

一些特定于 Go 的细节很重要：

 -`int64`用于所有算术，因为中间值可能超出 32 位整数限制。 
-`sort.Ints(nums)`对切​​片进行就地排序。 
- 显式输入常量以避免乘法期间的溢出问题。 
- 最终结果转换回`int`因为 LeetCode 签名需要它。

 ## 边缘情况

 一种重要的边缘情况是单元素数组。 在这种情况下，只有一个子集，即元素本身。 最小值和最大值相等，因此幂变为：$$x^2 \times x = x^3$$该实现自然地处理了这个问题，因为`prefix`从零开始，做出贡献：$$x^2 \times (x + 0)$$另一个重要的边缘情况涉及重复值。 当许多元素相等时，多个子集共享相同的最小值和最大值。 幼稚的计数策略可能会意外地多算或少算这些组合。 由于该算法通过贡献累积而不是显式的唯一性逻辑来处理子集，因此可以正确处理重复项，而无需任何特殊情况。 

第三个关键边缘情况是附近非常大的值`10^9`。 这些数字的平方超出了 32 位整数限制。 两种实现在整个计算过程中都使用模块化算术，并且 Go 版本明确使用`int64`以避免在进行模数减少之前溢出。 

最后，未排序的输入是错误的另一个常见来源。 整个贡献逻辑依赖于以非递减顺序处理值，从而保证当前元素是子集最大值。 该算法立即对数组进行排序，确保无论输入顺序如何都正确。
