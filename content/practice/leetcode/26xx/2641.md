[LeetCode 问题 2641](https://leetcode.com/problems/cousins-in-binary-tree-ii/)

 **难度：** 🟡 中等
 **主题：** 哈希表、树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉树的根，并要求我们将每个节点的值替换为其所有表兄弟的值的总和。 

如果满足以下条件，则两个节点被视为表兄弟：

 - 它们在树的同一深度
 - 他们不属于同一个父母

 根的深度为`0`，它的孩子们在深度`1`，深度孙子`2`， 等等。 

对于每个节点，我们需要计算：```
sum of all nodes at the same depth
minus
sum of nodes that share the same parent
```结果应该直接覆盖树中的原始节点值，并且我们必须返回修改后的根。 

例如，假设一个级别包含节点：```
[1, 10, 7]
```如果`1`和`10`是兄弟姐妹并且`7`属于另一位父母：

 - 节点`1`应该成为`7`- 节点`10`应该成为`7`- 节点`7`应该成为`1 + 10 = 11`约束条件很重要：

 - 最多`10^5`节点
 - 节点值高达`10^4`二次解是不可能的，因为对每个节点重复遍历树会太慢。 我们需要一种在线性时间内处理树的算法。 

一些边缘情况很重要：

 - 一棵只有一个节点的树
 - 完全倾斜的树
 - 只有一个子节点
 - 仅包含兄弟姐妹且不包含表兄弟姐妹的关卡
 - 在某些语言中递归深度可能很重要的大树

 该问题保证输入是一棵有效的二叉树并且至少包含一个节点。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是：

 1. 对于每个节点，确定其深度和父节点。 
2. 再次遍历整棵树，找到相同深度的每个节点。 
3. 对父节点不同的节点的值求和。 
4. 将节点的值替换为该总和。 

这是有效的，因为它直接遵循表兄弟姐妹的定义。 

然而，这种方法效率极低。 如果我们对每个节点执行遍历，则总复杂度大约为`O(n^2)`in the worst case.

 和`10^5`节点，这太慢了。 

### 关键见解

 关键的观察结果是表兄弟关系仅依赖于同一级别内的节点。 

对于一个节点：```
cousin sum =
(total sum of current level)
-
(sum of sibling group)
```我们可以逐层处理树，而不是单独计算表兄弟和。 

在每个深度：

 1. 计算下一级所有子节点的总和。 
2. 对于每个父项，计算其自己的子项之和。 
3. 分配每个孩子：```
next_level_sum - sibling_sum
```这避免了重复遍历，并允许在线性时间内处理整个树。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复扫描每个节点的级别 |
 | 最佳| O(n) | O(n) | 具有级别和的级别顺序遍历 |

 ## 算法演练

 ### 最优 BFS 算法

 1. 从使用队列的广度优先遍历开始。 

广度优先遍历是理想的，因为表兄弟关系是由深度定义的。 BFS 自然地逐级处理节点。 
2. 将根值设置为`0`。 

根没有表兄弟，因为深度没有其他节点`0`。 
3. 对于每个级别，计算下一个级别中所有子级的总价值。 

当我们处理当前级别时，我们检查每个节点的左子节点和右子节点并将它们的值累积到`next_level_sum`。 
4. 对于每个父节点，计算其自己的子节点之和。 

该兄弟组总和为：```
child_sum = left_child_value + right_child_value
```5. 替换每个子项的值。 

每个孩子都应该成为：```
next_level_sum - child_sum
```这会删除兄弟姐妹的值，同时保留所有表兄弟姐妹的值。 
6. 将子项添加到队列中。 

更新值后，将子级推入队列，以便下一次 BFS 迭代处理下一个深度级别。 
7. 继续，直到队列变空。 

### 为什么它有效

 在每个深度级别，所有表兄弟节点都是该级别中不包括兄弟节点的节点。 

该算法计算：```
all nodes at level
minus
nodes with same parent
```由于每个节点都属于一个兄弟组，因此减去兄弟组总和仅留下表兄弟值。 BFS 保证我们处理按深度正确分组的节点，因此每次替换都是使用原始级别结构计算的。 

## Python 解决方案```python
from collections import deque
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def replaceValueInTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        queue = deque([root])

        root.val = 0

        while queue:
            level_size = len(queue)
            next_level_sum = 0

            # First pass, compute total sum of next level
            current_level_nodes = []

            for _ in range(level_size):
                node = queue.popleft()
                current_level_nodes.append(node)

                if node.left:
                    next_level_sum += node.left.val

                if node.right:
                    next_level_sum += node.right.val

            # Second pass, update child values
            for node in current_level_nodes:
                sibling_sum = 0

                if node.left:
                    sibling_sum += node.left.val

                if node.right:
                    sibling_sum += node.right.val

                cousin_sum = next_level_sum - sibling_sum

                if node.left:
                    node.left.val = cousin_sum
                    queue.append(node.left)

                if node.right:
                    node.right.val = cousin_sum
                    queue.append(node.right)

        return root
```该实现使用标准 BFS 队列`collections.deque`。 

根值立即设置为`0`因为它没有表兄弟姐妹。 

对于每个级别，算法首先计算下一个级别中所有节点的总和。 这是在修改任何子值之前完成的，确保我们仍然使用原始值。 

当前层的节点暂存于`current_level_nodes`。 这允许我们执行第二遍，计算每个兄弟组总和并正确更新子值。 

每个孩子的表兄弟总和是：```python
next_level_sum - sibling_sum
```更新子项的值后，子项将被添加到队列中以供将来处理。 

由于每个节点都被访问一次，因此该解决方案以线性时间运行。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func replaceValueInTree(root *TreeNode) *TreeNode {
    queue := []*TreeNode{root}

    root.Val = 0

    for len(queue) > 0 {
        levelSize := len(queue)
        nextLevelSum := 0

        currentLevel := make([]*TreeNode, 0, levelSize)

        // First pass, compute next level sum
        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]

            currentLevel = append(currentLevel, node)

            if node.Left != nil {
                nextLevelSum += node.Left.Val
            }

            if node.Right != nil {
                nextLevelSum += node.Right.Val
            }
        }

        // Second pass, update children
        for _, node := range currentLevel {
            siblingSum := 0

            if node.Left != nil {
                siblingSum += node.Left.Val
            }

            if node.Right != nil {
                siblingSum += node.Right.Val
            }

            cousinSum := nextLevelSum - siblingSum

            if node.Left != nil {
                node.Left.Val = cousinSum
                queue = append(queue, node.Left)
            }

            if node.Right != nil {
                node.Right.Val = cousinSum
                queue = append(queue, node.Right)
            }
        }
    }

    return root
}
```Go 实现遵循与 Python 版本相同的 BFS 策略。 

队列是使用切片来实现的`*TreeNode`。 

Go 使用`nil`检查而不是 Python 真实性检查。 

整数溢出不是问题，因为最大可能的级别总和仍然安全地保持在 Go 的范围内`int`给定约束下的范围。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 队列可以存储树的整个级别|

 BFS 遍历每个节点一次。 遍历中的所有操作都是恒定时间，因此总运行时间与节点数量呈线性关系。 

队列一次最多可以包含一个完整的树级别。 在完全二叉树的最坏情况下，这大约可以是`n / 2`， 导致`O(n)`辅助空间。 

## 测试用例```python
from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(values):
    if not values:
        return None

    root = TreeNode(values[0])
    queue = deque([root])
    index = 1

    while queue and index < len(values):
        node = queue.popleft()

        if index < len(values) and values[index] is not None:
            node.left = TreeNode(values[index])
            queue.append(node.left)
        index += 1

        if index < len(values) and values[index] is not None:
            node.right = TreeNode(values[index])
            queue.append(node.right)
        index += 1

    return root

def tree_to_list(root):
    if not root:
        return []

    result = []
    queue = deque([root])

    while queue:
        node = queue.popleft()

        if node:
            result.append(node.val)
            queue.append(node.left)
            queue.append(node.right)
        else:
            result.append(None)

    while result and result[-1] is None:
        result.pop()

    return result

# Example 1
root = build_tree([5,4,9,1,10,None,7])
result = Solution().replaceValueInTree(root)
assert tree_to_list(result) == [0,0,0,7,7,None,11]  # standard example

# Example 2
root = build_tree([3,1,2])
result = Solution().replaceValueInTree(root)
assert tree_to_list(result) == [0,0,0]  # no cousins exist

# Single node
root = build_tree([1])
result = Solution().replaceValueInTree(root)
assert tree_to_list(result) == [0]  # root has no cousins

# Left-skewed tree
root = build_tree([1,2,None,3,None,4])
result = Solution().replaceValueInTree(root)
assert tree_to_list(result) == [0,0,None,0,None,0]  # every level has one node

# Complete binary tree
root = build_tree([1,2,3,4,5,6,7])
result = Solution().replaceValueInTree(root)
assert tree_to_list(result) == [0,0,0,13,13,9,9]  # cousin sums across full levels

# Nodes with one child
root = build_tree([1,2,3,4,None,None,5])
result = Solution().replaceValueInTree(root)
assert tree_to_list(result) == [0,0,0,5,None,None,4]  # asymmetric structure

 ## 边缘情况

 ### 单节点树

 仅包含根的树是一个重要的边缘情况，因为根没有表兄弟。 有缺陷的实现可能会意外地保留原始值而不是替换为`0`。 

此实现通过显式设置正确处理这种情况：```
root.val = 0
```在开始 BFS 处理之前。 

### 倾斜的树

 完全左偏或右偏的树的行为几乎就像链表一样。 每个级别都包含一个节点，这意味着不存在表兄弟。 

某些实现错误地假设同级组始终包含两个子级。 该解决方案可以安全地检查丢失的子节点，并仅根据现有节点计算总和。 

### 有一个孩子的父母

 某些节点可能只有左子节点或只有右子节点。 

例如：```
    1
   /
  2
```同级组总和必须仅包括现有的子级。 实现仔细计算：```
if node.left:
    sibling_sum += node.left.val
```对于右边的孩子也是如此。 

这可以确保失踪儿童不会错误地缴纳款项。
