[LeetCode 问题 2671](https://leetcode.com/problems/Frequency-tracker/)

 **难度：** 🟡 中等
 **主题：** 哈希表、设计

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个数据结构，`FrequencyTracker`，可以有效地跟踪数字的频率并回答有关是否存在特定频率的数字的查询。 操作是`add`，这会增加数字的计数；`deleteOne`，减少数字的计数（如果存在）； 和`hasFrequency`，它检查任何数字是否恰好出现`frequency`次。 

输入表示范围内的整数`1 <= number <= 10^5`从数据结构中添加或删除以及查询`hasFrequency`为了`1 <= frequency <= 10^5`。 操作总数限制为`2 * 10^5`，因此需要一个有效的解决方案来避免超时。 

重要的边缘情况包括检查`hasFrequency`在空结构上，删除不存在的数字，并以相同的频率处理多个数字。 为每个查询扫描整个数据集的简单解决方案会太慢，因为它可能导致每个查询的时间为 O(n)，其中 n 是元素的数量。 

## 方法

 蛮力方法涉及维护所有数字的列表并迭代它以计算每次的频率`hasFrequency`被称为。 这是正确的但效率低下，因为`hasFrequency`每个查询可能需要 O(n) 时间，这对于大输入来说是不可接受的。 

最佳方法使用两个哈希图。 第一个地图跟踪每个数字的计数（`number -> count`）。 第二张地图跟踪有多少个数字具有特定计数（`count -> number of numbers with this count`）。 这允许`add`和`deleteOne`在 O(1) 时间内更新两个地图`hasFrequency`检查 O(1) 是否有任何数字具有查询的频率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O(n) | O(n) | 维护列表并按需计算频率 |
 | 最佳| 每次操作 O(1) | O(n) | 使用两个哈希图来跟踪计数和频率 |

 ## 算法演练

 1.初始化两个哈希图：`count_map`用于存储每个数字的频率和`freq_map`用于存储有多少个数字具有给定频率。 
2. **添加（号码）**：

 - 检索当前的数字计数`count_map`。 
- 如果该数字已经存在，则减少其旧频率`freq_map`。 
- 增加数字的计数`count_map`。 
- 增加新频率`freq_map`。 
3. **删除一个（数字）**：

 - 检查该号码是否存在于`count_map`。 如果没有，则不执行任何操作。 
- 检索当前计数并减少相应的频率`freq_map`。 
- 减少数字的计数`count_map`。 
- 如果新计数大于零，则增加新频率`freq_map`。 
- 如果计数变为零，则删除该数字`count_map`。 
4. **HasFrequency(频率)**:

 - 只需检查是否`freq_map[frequency] > 0`。 

**为什么有效：**`count_map`始终反映每个数字的当前计数，并且`freq_map`跟踪具有特定频率的数字的计数。 这确保了`hasFrequency`查询准确且 O(1)，而更新则保持两个映射的一致性。 

## Python 解决方案```python
class FrequencyTracker:

    def __init__(self):
        self.count_map = {}
        self.freq_map = {}

    def add(self, number: int) -> None:
        current_count = self.count_map.get(number, 0)
        if current_count > 0:
            self.freq_map[current_count] -= 1
        new_count = current_count + 1
        self.count_map[number] = new_count
        self.freq_map[new_count] = self.freq_map.get(new_count, 0) + 1

    def deleteOne(self, number: int) -> None:
        if number not in self.count_map:
            return
        current_count = self.count_map[number]
        self.freq_map[current_count] -= 1
        new_count = current_count - 1
        if new_count > 0:
            self.count_map[number] = new_count
            self.freq_map[new_count] = self.freq_map.get(new_count, 0) + 1
        else:
            del self.count_map[number]

    def hasFrequency(self, frequency: int) -> bool:
        return self.freq_map.get(frequency, 0) > 0
```此实现通过维护两个同步哈希映射来确保所有操作都是 O(1)。 添加或删除数字会相应地更新两个映射，而查询频率只需检查频率映射。 

## 解决方案```go
type FrequencyTracker struct {
	countMap map[int]int
	freqMap  map[int]int
}

func Constructor() FrequencyTracker {
	return FrequencyTracker{
		countMap: make(map[int]int),
		freqMap:  make(map[int]int),
	}
}

func (this *FrequencyTracker) Add(number int) {
	currentCount := this.countMap[number]
	if currentCount > 0 {
		this.freqMap[currentCount]--
	}
	newCount := currentCount + 1
	this.countMap[number] = newCount
	this.freqMap[newCount]++
}

func (this *FrequencyTracker) DeleteOne(number int) {
	currentCount, exists := this.countMap[number]
	if !exists {
		return
	}
	this.freqMap[currentCount]--
	newCount := currentCount - 1
	if newCount > 0 {
		this.countMap[number] = newCount
		this.freqMap[newCount]++
	} else {
		delete(this.countMap, number)
	}
}

func (this *FrequencyTracker) HasFrequency(frequency int) bool {
	return this.freqMap[frequency] > 0
}
```Go 实现镜像了 Python 逻辑，使用映射而不是字典，并使用内置的处理删除`delete`功能。

 ## 边缘情况

 第一个边缘情况是查询`hasFrequency`在空的`FrequencyTracker`。 如果假设至少存在一个元素，这可能会导致幼稚的实现失败。 我们的实现通过返回来处理它`False`因为`freq_map`不包含任何计数。 

第二种边缘情况涉及删除结构中不存在的数字。 幼稚的实现可能会引发错误或减少未定义的计数。 在我们的解决方案中，我们在执行任何删除之前检查是否存在，以确保稳定性。 

第三种边缘情况是多个数字具有相同的频率。 例如，两个数字可能分别出现 3 次，从其中删除 1 次会减少该频率的计数，但不会完全删除它。 我们的`freq_map`跟踪数字的数量
