 ## 解决方案

 ## 问题理解

 该问题要求我们实现给定函数的**记忆版本**`fn`。 记忆函数是一种缓存先前调用结果的函数，如果再次传递相同的输入，则返回缓存的结果。 关键要求是输入被认为是相同的**只有当它们严格相等时（`===`)**，不仅仅是它们具有相同的内容。 这种区别对于 JavaScript 中的对象或数组等引用类型很重要，其中具有相同内容的两个对象**不相等，除非它们是完全相同的实例**。 

输入是一个函数`fn`它可以接受任意数量和类型的参数，包括基元、对象，甚至其他函数。 输出应该是一个记忆版本`fn`这样具有相同输入的重复调用不会触发新的计算。 该函数还必须跟踪实际调用的次数`fn`用于诊断目的。 

约束表示输入集的数量最多可达`10^5`，并且所有集合中的单独输入总数也高达`10^5`。 这表明在每次调用时深入比较输入的简单方法会太慢。 相反，缓存必须基于**引用相等性**，即每个参数比较的 O(1) 时间复杂度。 

重要的边缘情况包括：

 1. **原始参数**，其值相等，但类型或表示不同。 
2. **具有相同内容但不同引用的对象或数组**。 每个新实例都应被视为唯一的输入。 
3. **重复引用**同一对象，该对象应该命中缓存。 

## 方法

 暴力方法是存储每个输入集并将传入参数与每个缓存集进行比较。 这保证了正确性，因为我们显式检查所有先前的调用，但效率很低：每个函数调用可能需要迭代所有先前的输入，在最坏的情况下导致 O(n²) 时间复杂度。 这不会扩展到`10^5`来电。 

最佳解决方案的关键见解是使用**嵌套映射（哈希表）结构**，通过每个参数的引用进行键控。 在 JavaScript 中，一个`Map`允许对象密钥并维护基于身份的平等。 通过嵌套一个`Map`对于函数签名中的每个参数，我们可以根据参数序列遍历结构。 然后在 O（参数数量）时间内检测到缓存命中。 这种方法与独特参数组合的数量成线性比例。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² * 米) | O(n) | 将每个调用与之前的所有调用进行比较，其中`n`是呼叫次数，`m`是参数的数量 |
 | 最佳| O(n * m) | O(n * m) | 使用嵌套映射存储参数序列和结果以进行基于引用的缓存 |

 ## 算法演练

 1.初始化一个**root Map**作为顶层缓存。 
2. 定义接受任意参数的记忆函数包装器。 
3. 从根Map开始，按顺序遍历以每个参数为键的嵌套Map结构。 
4. 对于每个参数，检查 Map 是否具有该确切参数引用的键。 
5. 如果不存在，则在该级别创建一个新地图并继续。 
6. 处理完所有参数后，检查最后一级是否已存储结果。 
7. 如果有结果，则立即返回，无需调用`fn`。 
8. 如果没有结果，则调用原始结果`fn`使用参数，将结果存储在最终的 Map 级别，并递增调用计数器。 
9. 返回存储的结果。 

**为什么有效：** 通过嵌套 Map 的每条路径都唯一对应于一系列参数引用。 因为 Map 键使用引用相等，所以这保证了只有具有完全相同参数的调用才会命中缓存。 所有其他调用都会重新计算并缓存以供将来使用。 

## Python 解决方案```python
from typing import Any, Callable

def memoize(fn: Callable) -> Callable:
    cache = {}
    call_count = {"calls": 0}

    def memoized(*args):
        current = cache
        for arg in args:
            if id(arg) not in current:
                current[id(arg)] = {}
            current = current[id(arg)]
        if "result" not in current:
            current["result"] = fn(*args)
            call_count["calls"] += 1
        return {"val": current["result"], "calls": call_count["calls"]}

    return memoized
```在此 Python 实现中，我们通过使用来模拟 JavaScript 引用相等性`id(arg)`作为嵌套字典中的键。 每个函数调用都会根据参数 ID 的序列遍历字典。 如果该路径不存在，我们将创建它。 调用计数器仅跟踪实际执行`fn`。 

## 解决方案```go
package main

import "sync"

type MemoizedFn struct {
	cache map[interface{}]interface{}
	mu    sync.Mutex
	calls int
	fn    func(args ...interface{}) interface{}
}

func Memoize(fn func(args ...interface{}) interface{}) func(args ...interface{}) map[string]interface{} {
	m := &MemoizedFn{
		cache: make(map[interface{}]interface{}),
		fn:    fn,
	}

	var memo func([]interface{}, map[interface{}]interface{}) map[interface{}]interface{}
	memo = func(args []interface{}, current map[interface{}]interface{}) map[interface{}]interface{} {
		if len(args) == 0 {
			return current
		}
		if _, exists := current[args[0]]; !exists {
			current[args[0]] = make(map[interface{}]interface{})
		}
		return memo(args[1:], current[args[0]].(map[interface{}]interface{}))
	}

	return func(args ...interface{}) map[string]interface{} {
		m.mu.Lock()
		defer m.mu.Unlock()
		current := memo(args, m.cache)
		if _, exists := current["result"]; !exists {
			current["result"] = m.fn(args...)
			m.calls++
		}
		return map[string]interface{}{
			"val":   current["result"],
			"calls": m.calls,
		}
	}
}
```在 Go 中，我们使用以下方法处理引用相等性`interface{}`地图中的键。 同步于`sync.Mutex`确保线程安全。 嵌套映射表示参数序列，调用计数器跟踪实际的函数执行。 

## 工作示例

 **示例1：`fn(a, b) = a + b`有输入`[[2,2],[2,2],[1,2]]`**

 | 输入| 遍历 | 结果 | 来电 |
 | --- | --- | --- | --- |
 | (2,2) | 缓存清空→新路径| 4 | 1 |
 | (2,2) | 路径存在 | 4 | 1 |
 | (1,2) | 新路径| 3 | 2 |

 **示例 2：对象`[{},{},{}]`**

 每个对象通过引用都是不同的，因此每次调用都是缓存未命中，每次都会增加调用计数器。 

**示例 3：同一对象`o`重复**

 引用是相同的，因此第一次命中缓存后的所有调用都不会增加调用计数器。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * m) | 每次调用都会遍历`m`嵌套 Map 结构中的参数，并且有`n`来电 |
 | 空间| O(n * m) | 每个唯一的参数组合都会在缓存中创建一个嵌套路径 |

 复杂性与调用次数和每次调用的参数数量呈线性关系。 只有独特的序列才会消耗额外的空间。

 ## 边缘情况

 1. **空参数**：没有参数的函数仍应正确记忆。 嵌套缓存减少为单个键，并且在第一次调用后始终返回相同的结果。 
2. **嵌套对象**：深度嵌套对象仅通过引用进行比较，避免昂贵的深度相等检查。 这确保了大型结构的性能。 
3. **大容量通话**：最多`10^5`调用和输入，天真的暴力比较会太慢。 使用嵌套 Map 结构可保证每个参数的访问时间为 O(1)，从而保持性能可接受。
