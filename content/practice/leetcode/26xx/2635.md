 ## 解决方案

 ## 问题理解

 这个问题要求我们实现一个自定义版本的数组转换操作，类似于JavaScript的`Array.map`，但不使用内置的`Array.map`方法。 

我们有两个输入：

 1. 整数数组`arr`2. 映射函数`fn`目标是返回一个**新数组**，其中每个元素都是应用函数的结果`fn`到相应的元素`arr`。 

更正式地说，对于每个索引`i`，我们必须计算：```
returnedArray[i] = fn(arr[i], i)
```这意味着转换函数接收两条信息：

 - 当前数组元素，`arr[i]`- 该元素的索引，`i`该函数可以使用这些输入中的一个或两个来确定转换后的值。 

例如，如果`arr = [1,2,3]`该函数为每个元素加一，转换后的数组变为`[2,3,4]`。 

如果函数依赖于索引，比如添加`i`对于每个值，则：```
arr[0] + 0 = 1
arr[1] + 1 = 3
arr[2] + 2 = 5
```导致`[1,3,5]`。 

这些约束告诉我们有关问题规模的几个重要信息：

 - 数组长度最多为`1000`，相对较小。 
- 数组值的范围可以是`-10^9`到`10^9`，意味着值可能非常大或为负值。 
- 转换函数始终返回一个整数。 

由于数组规模较小，因此性能不是主要瓶颈。 然而，我们仍然想要一个高效、干净的实施。 

一个重要的细节是我们必须创建一个**新数组**而不是就地修改输入数组。 这保证了原始数组保持不变。 

一些边缘情况值得尽早识别：

 - 输入数组可能为空（`[]`），在这种情况下结果也应该是一个空数组。 
- 该函数可能完全忽略该值并始终返回一个常量。 
- 该函数可能依赖于索引，因此我们必须同时传递两者`arr[i]`和`i`正确。 
- 可能会出现负数和非常大的整数，因此实现必须避免有关正性的假设。 

因为该问题保证了有效的输入和有效的转换函数，所以我们不需要处理无效的情况。 

## 方法

 ### 蛮力方法

 强力解决方案是一次迭代一个元素，对每个元素调用转换函数，并将结果附加到新创建的数组中。 

对于每个索引`i`，我们计算：```
fn(arr[i], i)
```并将结果存储在单独的输出数组中。 

这种方法是正确的，因为问题明确地将输出定义为独立地将变换函数应用于每个元素。 由于每个元素必须只处理一次，因此迭代整个数组可以保证正确性。 

尽管这被称为强力方法，但对于给定的约束来说它已经足够有效了。 没有不必要的重复工作，因为每个元素只需要一次转换。 

### 最佳方法

 关键的观察是每个元素转换都独立于其他每个元素。 索引之间不存在需要额外计算或高级数据结构的关系。 

由于每个数组元素只需访问一次，因此最佳解决方案是在构造新结果数组时简单地遍历数组。 

这是有效的，因为：

 - 每个输出元素仅依赖于一个输入元素及其索引。 
- 无需排序、搜索或记忆。 
- 当我们遍历数组时，我们可以立即计算结果。 

因此，最好的解决方案是简单的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 迭代数组并将转换后的值存储在新数组中 |
 | 最佳| O(n) | O(n) | 单遍转换，这实际上与暴力破解相同，因为每个元素都必须被访问 |

 ## 算法演练

 1. 创建一个空结果数组来存储转换后的值。 
2. 使用以下索引迭代输入数组`0`到`len(arr) - 1`。 
3. 对于每个位置`i`, 检索当前值`arr[i]`。 
4. 调用变换函数为`fn(arr[i], i)`。 
5. 将返回的转换值附加到结果数组中。 
6. 继续，直到处理完输入数组中的每个元素。 
7. 返回完成的结果数组。 

### 为什么它有效

 该算法之所以有效，是因为它直接遵循问题定义。 对于每个索引`i`，我们精确计算：```
returnedArray[i] = fn(arr[i], i)
```由于我们对每个有效索引只处理一次并以相同的顺序存储相应的转换结果，因此最终的数组与所需的输出精确匹配。 执行期间保持的不变量是处理索引后`i`，结果数组正确包含来自的所有位置的转换值`0`通过`i`。 

## Python 解决方案```python
from typing import List, Callable

class Solution:
    def map(self, arr: List[int], fn: Callable[[int, int], int]) -> List[int]:
        transformed_array = []

        for index in range(len(arr)):
            transformed_value = fn(arr[index], index)
            transformed_array.append(transformed_value)

        return transformed_array
```实现首先创建一个名为的空列表`transformed_array`，它将保存转换后的值。 

然后，我们使用索引迭代输入数组，而不是直接迭代值。 这很重要，因为转换函数需要当前元素及其索引。 

在循环内部，我们调用：```python
fn(arr[index], index)
```返回值存储在`transformed_value`并附加到结果列表中。 

处理完所有元素后，该函数将返回新构建的数组。 

该实现完全反映了前面描述的算法，并避免使用内置的`Array.map`方法，满足问题要求。 

## 解决方案```go
func map(arr []int, fn func(int, int) int) []int {
	result := make([]int, 0, len(arr))

	for index, value := range arr {
		transformedValue := fn(value, index)
		result = append(result, transformedValue)
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但使用 Go 习惯用法。 

我们不是创建没有容量的空切片，而是使用等于的容量初始化结果切片`len(arr)`：```go
make([]int, 0, len(arr))
```此优化减少了附加时的内存重新分配。 

Go 切片自然会处理空数组，所以如果`arr`为空，循环执行零次并返回一个空切片。 

在正常的 LeetCode 执行下，整数溢出不是问题，因为 Go`int`对于问题约束而言，值足够大。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |

 | 空间| O(n) | 一个新的大小数组`n`已创建 |

 时间复杂度是线性的，因为我们迭代数组一次，对每个元素执行恒定量的工作。 

空间复杂度也是线性的，因为问题需要返回新创建的转换数组。 在最坏的情况下，结果数组包含与输入相同数量的元素。

 ## 边缘情况

 ### 空数组

 如果实现假设至少存在一个元素，则空输入数组很容易导致错误。 例如，访问`arr[0]`如果不检查长度就会失败。 

此实现可以自然地处理这种情况，因为循环执行零次。 结果数组保持为空并立即返回。 

### 忽略输入值的函数

 某些转换函数可能会完全忽略数组值或索引，并始终返回相同的常量。 

例如：```
fn() = 42
```幼稚的实现可能会意外地依赖于输入值。 我们的实现始终为每个索引独立调用该函数，因此常量转换可以正常工作。 

### 索引相关转换

 错误的常见来源是忘记将索引传递到函数中或传递错误的索引。 

例如：```
fn(n, i) = n + i
```如果实现仅传递值而省略索引，则输出将不正确。 由于我们的解决方案明确调用：```
fn(arr[i], i)
```始终提供正确的索引。 

### 负整数和大整数

 由于数组值的范围可能是`-10^9`到`10^9`，对积极性做出假设的实现可能会失败。 

我们的解决方案本身不执行算术，只是将值转发到转换函数，因此可以安全正确地处理负整数和大整数。
