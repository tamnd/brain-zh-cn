[LeetCode 问题 2669](https://leetcode.com/problems/count-artist-occurrences-on-spotify-ranking-list/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个数据库表，名为`Spotify`其中包含有关 Spotify 排名列表中出现的歌曲的信息。 每行代表一个排名曲目并包含三列：

 -`id`，行的唯一标识符
 -`track_name`, 歌名
 -`artist`，表演该曲目的艺术家的名字

 任务是确定每个艺术家在排行榜中出现的次数。 换句话说，我们必须计算与每个不同艺术家相关的行数。 

最终结果应包含：

 - 艺术家姓名
 - 该艺术家出现的总次数

 输出必须遵循两个排序规则：

 1.按照出现次数降序排列
 2. 如果多个艺术家出现次数相同，则按字母升序对这些艺术家进行排序

 重要的观察是，这从根本上来说是一个分组和计数问题。 每一行都为其艺术家贡献了一次出现。 

输入表示平面关系表，预期输出是聚合汇总表。 自从`id`保证是唯一的，我们不需要担心重复的主键或不明确的行。 

该问题被归类为“简单”，因为 SQL 聚合操作直接解决此类任务。 

需要考虑一些重要的边缘情况：

 - 多个艺术家可能具有相同的出现次数，需要按字母顺序进行二次排序。 
- 一位艺术家只能出现一次。 
- 该表可能只包含一行。 
- 每行都可以属于同一位艺术家。 
- 艺术家姓名被视为精确的字符串，这意味着不同的拼写或大小写将单独计数，除非明确规范化，而此问题并不要求这样做。 

因为该问题保证了有效的表行和主键，所以我们不需要处理格式错误的数据或丢失的标识符。 

## 方法

 ### 蛮力方法

 强力解决方案将迭代每个艺术家并重复扫描整个表以计算该艺术家出现的次数。 

例如，假设有`n`行。 对于每一行，我们可以计算有多少其他行共享相同的艺术家姓名。 这会产生正确的频率计数，因为每次出现都会被明确检查。 

然而，这种方法效率低下，因为它会重复扫描表中相同的艺术家姓名。 如果有很多行，重复的全表扫描就会变得不必要的昂贵。 

用伪代码术语来说：

 1. 选择一位艺术家
 2. 扫描全表
 3. 统计匹配行数
 4. 对每位艺术家重复

 在最坏的情况下，这会导致二次时间复杂度。 

### 最佳方法

 最佳解决方案使用 SQL 聚合`GROUP BY`。 

关键在于 SQL 数据库是专门为高效聚合记录而设计的。 我们可以按艺术家对行进行一次分组并计算每个组的计数，而不是重复扫描每个艺术家的表。 

这`COUNT(*)`聚合函数确定有多少行属于每个艺术家组。 

分组后，我们进行排序：

 - 首先按出现次数降序排列
 - 然后按艺术家姓名升序

 这种方法既简洁又高效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 反复扫描表格中的每位艺术家|
 | 最佳| O(n log n) | O(n log n) | O(k) | 使用分组和排序，其中`k`是独特艺术家的数量|

 ## 算法演练

 1. 读取所有行`Spotify`桌子。 
2. 按以下条件对行进行分组`artist`柱子。 

这为每个不同的艺术家创建了一个组。 属于同一艺术家的每一行都成为同一收藏的一部分。 
3. 使用以下命令计算每个组内的行数`COUNT(*)`。 

由于每一行代表在排名列表中的一次出现，因此行数直接等于艺术家的出现次数。 
4. 将计算计数列重命名为`occurrences`。 

这与所需的输出格式匹配。 
5. 对结果进行排序：

 -`occurrences`按降序排列
 -`artist`按关系升序排列
 6. 返回最终结果表。 

### 为什么它有效

 该算法之所以有效，是因为分组保证了同一艺术家的所有行都收集在一起。 正在申请`COUNT(*)`每个组正确计算该艺术家出现在排名列表中的次数。 然后使用 SQL 排序规则直接强制执行排序条件。 

## Python 解决方案

 虽然这是一个数据库问题并且通常用 SQL 解决，但 LeetCode 数据库解决方案通常直接编写为 SQL 查询。```python
# Write your MySQL query statement below

SELECT
    artist,
    COUNT(*) AS occurrences
FROM Spotify
GROUP BY artist
ORDER BY occurrences DESC, artist ASC;
```该解决方案包含三个主要逻辑部分。 

这`GROUP BY artist`子句将属于同一艺术家的所有行收集到一个组中。 如果没有分组，数据库将独立处理每一行。 

这`COUNT(*)`聚合函数计算每个组内存在的行数。 由于每一行对应一个 Spotify 排名条目，因此计数等于该艺术家的出现次数。 

最后，`ORDER BY`子句应用所需的排序规则。 该查询首先按出现次数降序排序，因此最常出现的艺术家首先出现。 如果两个艺术家共享相同的计数，则查询将按艺术家姓名的字母顺序升序排序。 

## 解决方案

 LeetCode数据库问题不需要Go实现，因为预期的提交格式是SQL。 然而，如果我们使用内存数据结构来模拟 Go 中的逻辑，实现将如下所示：```go
package main

import (
	"fmt"
	"sort"
)

type Spotify struct {
	ID        int
	TrackName string
	Artist    string
}

type Result struct {
	Artist     string
	Occurrences int
}

func countArtistOccurrences(records []Spotify) []Result {
	frequency := make(map[string]int)

	for _, record := range records {
		frequency[record.Artist]++
	}

	results := make([]Result, 0)

	for artist, count := range frequency {
		results = append(results, Result{
			Artist:     artist,
			Occurrences: count,
		})
	}

	sort.Slice(results, func(i, j int) bool {
		if results[i].Occurrences == results[j].Occurrences {
			return results[i].Artist < results[j].Artist
		}
		return results[i].Occurrences > results[j].Occurrences
	})

	return results
}

func main() {
	records := []Spotify{
		{303651, "Heart Won't Forget", "Sia"},
		{1046089, "Shape of you", "Ed Sheeran"},
		{33445, "I'm the one", "DJ Khalid"},
		{811266, "Young Dumb & Broke", "DJ Khalid"},
		{505727, "Happier", "Ed Sheeran"},
	}

	results := countArtistOccurrences(records)

	for _, result := range results {
		fmt.Println(result.Artist, result.Occurrences)
	}
}
```Go 解决方案使用哈希图来有效地计算艺术家频率。 地图键是艺术家姓名，值是出现次数。 

计数后，将结果转换为切片并使用排序`sort.Slice`。 自定义比较器强制执行与 SQL 查询相同的排序规则。 

与 Python 字典不同，Go 映射会针对缺失的键自动返回零值，这简化了增量操作。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 分组处理所有行，排序随后占主导地位 |
 | 空间| O(k) | 商店分组计数`k`独特的艺术家|

 分组阶段扫描表一次，产生与行数相关的线性工作。 排序阶段取决于不同艺术家的数量，可能最多`n`在最坏的情况下。 因此，排序有助于`O(n log n)`整体复杂性。 

空间复杂性取决于存在多少不同的艺术家，因为分组结果必须为每个艺术家存储一个条目。

 ## 边缘情况

 ### 多名艺术家数量相等

 错误的一个常见来源是忘记辅助排序规则。 如果两位艺术家出现的次数相同，则输出必须按艺术家姓名的字母顺序排序。 

例如：

 | 艺术家 | 计数|
 | ---| ---|
 | 阿黛尔| 2 |
 | 布鲁诺·马尔斯 | 2 |

 仅按计数排序的解决方案可能会产生不一致的排序。 该实现使用以下方式正确处理此问题：```
ORDER BY occurrences DESC, artist ASC
```### 表中只有一位艺术家

 如果每一行都属于同一艺术家，则分组步骤仅生成一个结果行。 

示例：

 | 艺术家 | 事件 |
 | ---| ---|
 | 德雷克 | 5 |

 一些不正确的实现可能会不必要地重复行或无法正确聚合。 这`GROUP BY`条款保证每个独特的艺术家恰好一行。 

### 单行输入

 最小的有效输入仅包含一行。 该算法仍然有效，因为对单行进行分组会产生一个具有计数的组`1`。 

示例：

 | 艺术家 | 事件 |
 | ---| ---|
 | 西亚| 1 |

 这验证了计数逻辑不依赖于存在的多行。
