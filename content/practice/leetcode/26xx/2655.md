 # LeetCode 2655 - 找到最大的未覆盖范围

 ## 问题理解

 问题给了我们一个整数`n`，表示一个概念数组`nums`长度`n`，索引自`0`到`n - 1`。 我们还得到了包含范围的列表，其中每个范围将数组中的位置标记为已覆盖。 

我们的任务是确定数组中每个最大的未覆盖部分。 

未覆盖范围是不包含在任何给定覆盖范围中的连续索引块。 术语“最大”在这里很重要。 这意味着如果两个未覆盖区间相邻，则必须将它们合并为一个更大的未覆盖区间。 换句话说，最终答案应该包含最大可能的连续未覆盖片段。 

例如，如果`n = 10`覆盖范围是`[3,5]`和`[7,8]`，那么覆盖的索引为：

 -`3,4,5`-`7,8`未覆盖的指数是：

 -`0,1,2`-`6`-`9`由于这些未覆盖的组被覆盖的单元格分开，因此它们保持独立的最大未覆盖范围：```
[[0,2],[6,6],[9,9]]
```约束条件非常重要：

 -`n`可以大到`10^9`-`ranges.length`可以大到`10^6`这些限制立即告诉我们，我们无法显式构建整个数组。 任何尝试创建大小布尔数组的解决方案`n`在时间和记忆上都是不可行的。 

相反，解决方案必须直接对间隔本身进行操作。 

有几个重要的边缘情况需要及早识别：

 - 范围可能会严重重叠。 
- 范围可能已经覆盖整个阵列。 
- 范围列表可能为空，这意味着整个数组未被覆盖。 
- 相邻的覆盖间隔应该有效地表现得像一个合并间隔，因为它们之间没有留下未覆盖的空间。 
- 未覆盖的区间可能出现在第一个覆盖范围之前或最后一个覆盖范围之后。 

该问题保证所有范围都有效且在界限内，因此我们不需要额外的验证逻辑。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是模拟整个阵列。 

我们可以创建一个长度的布尔数组`n`，最初将每个位置标记为未覆盖。 然后，对于每个范围`[l, r]`，我们标记所有索引`l`通过`r`如所覆盖。 

处理完所有范围后，我们扫描数组以收集最大的连续未覆盖段。 

这可以正常工作，因为每个位置都被明确跟踪。 然而，对于给定的约束，复杂性是不可接受的。 

自从`n`可以达到`10^9`，构造这样的数组在实践中是不可能的。 

### 最佳方法

 关键的观察是，我们实际上永远不需要表示单个单元，除非它们是间隔的边界。 

相反，我们可以：

 1. 按起始位置对所有范围进行排序。 
2. 合并重叠或相邻的覆盖范围。 
3. 跟踪合并的覆盖区间之间的间隙。 

这些间隙正是最大的未覆盖范围。 

例如：```
ranges = [[2,4],[0,3]]
```排序后：```
[[0,3],[2,4]]
```合并后：```
[[0,4]]
```现在我们可以很容易地看到未被覆盖的部分是：```
[5,6]
```这种基于区间的方法非常有效，因为它只处理给定的范围而不是整个概念数组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n + 覆盖单元总数) | O(n) | 显式标记每个数组位置 |
 | 最佳| O(m log m) | O(米) | 对间隔进行排序和合并，其中 m 是范围的数量 |

 这里，`m = ranges.length`。 

## 算法演练

 1. 首先，按起始坐标对范围进行排序。 

排序允许我们从左到右处理间隔并有效地合并重叠。 
2. 初始化一个空结果列表来存储未覆盖的范围。 
3. 维护一个名为`current_end`。 

该变量表示迄今为止处理的最远覆盖位置。 

最初：```
current_end = -1
```这意味着尚未涵盖任何内容。 
4. 逐一迭代排序后的范围。 

对于每个间隔`[start, end]`，将其与`current_end`。 
5. 如果`start > current_end + 1`，那么之前覆盖的区域和当前区间之间存在间隙。 

未覆盖区间为：```
[current_end + 1, start - 1]
```将此间隔添加到答案中。 
6. 更新`current_end`。 

由于间隔可能重叠，我们使用以下方法扩展覆盖区域：```
current_end = max(current_end, end)
```7. 处理完所有范围后，数组末尾可能仍然存在未覆盖的后缀。 

如果：```
current_end < n - 1
```那么剩余的未覆盖区间为：```
[current_end + 1, n - 1]
```8. 返回收集的未覆盖区间。 

### 为什么它有效

 该算法保持不变式`current_end`始终表示所有已处理间隔中覆盖最远的索引。 

由于范围是按排序顺序处理的，因此之间的任何间隙`current_end`并且下一个间隔的开始必须代表最大的未覆盖段。 

合并重叠可确保不会对任何覆盖区域进行两次计数，并且不会引入人为间隙。 

因此，每个未覆盖的区间都被恰好找到一次，并且所有返回的区间都是最大的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaximalUncoveredRanges(
        self,
        n: int,
        ranges: List[List[int]]
    ) -> List[List[int]]:
        
        if not ranges:
            return [[0, n - 1]]

        ranges.sort()

        uncovered = []
        current_end = -1

        for start, end in ranges:

            if start > current_end + 1:
                uncovered.append([current_end + 1, start - 1])

            current_end = max(current_end, end)

        if current_end < n - 1:
            uncovered.append([current_end + 1, n - 1])

        return uncovered
```实现从处理最简单的边缘情况开始。 如果没有覆盖范围，则整个数组都未被覆盖，因此我们立即返回`[0, n - 1]`。 

接下来，对范围进行排序。 Python默认的列表排序自然是先按第一个元素排序，然后按第二个元素排序，这正是我们所需要的。 

变量`current_end`跟踪迄今为止遇到的最远的覆盖位置。 

在迭代过程中，如果下一个间隔严格晚于`current_end + 1`，则存在真正的未覆盖间隙。 该差距已附加到答案列表中。 

之后我们更新`current_end`使用最大值自然地合并重叠间隔。 

最后，处理完所有范围后，我们检查数组末尾是否仍有未覆盖的后缀。 

## 解决方案```go
package main

import "sort"

func findMaximalUncoveredRanges(n int, ranges [][]int) [][]int {

	if len(ranges) == 0 {
		return [][]int{{0, n - 1}}
	}

	sort.Slice(ranges, func(i, j int) bool {
		if ranges[i][0] == ranges[j][0] {
			return ranges[i][1] < ranges[j][1]
		}
		return ranges[i][0] < ranges[j][0]
	})

	result := [][]int{}
	currentEnd := -1

	for _, interval := range ranges {
		start := interval[0]
		end := interval[1]

		if start > currentEnd+1 {
			result = append(result, []int{currentEnd + 1, start - 1})
		}

		if end > currentEnd {
			currentEnd = end
		}
	}

	if currentEnd < n-1 {
		result = append(result, []int{currentEnd + 1, n - 1})
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

主要区别在于 Go 需要使用显式排序逻辑`sort.Slice`。 我们还在构建结果时显式管理切片附加。 

不存在整数溢出问题，因为约束安全地符合 Go 的标准整数范围。 

Go 切片自然地处理结果间隔的动态增长。

 ## 边缘情况

 当范围列表为空时，会出现一种重要的边缘情况。 在这种情况下，没有覆盖任何位置，因此整个数组来自`0`到`n - 1`必须作为单个最大未覆盖间隔返回。 幼稚的实现可能会意外返回空列表，因为它从未进入处理循环。 实现在开始时就明确地处理了这个问题。 

另一个重要的情况涉及重叠间隔，例如`[[1,4],[2,6]]`。 如果重叠未正确合并，算法可能会错误地识别间隔之间虚假的未覆盖间隙。 该解决方案通过维护来避免这种情况`current_end`作为迄今为止看到的最远的覆盖位置。 

相邻间隔是另一个微妙的情况。 例如：```
[[0,2],[3,5]]
```尽管这些间隔不重叠，但它们之间没有留下未覆盖的单元格。 有缺陷的实现可能会错误地在之间创建一个未覆盖的间隔`2`和`3`。 条件：```
start > current_end + 1
```正确地防止了这个问题，因为邻接不会产生间隙。 

最后，阵列开头或结尾处未覆盖的区域很容易被错过。 该实现通过初始值自然地处理开始`current_end = -1`，并在处理完所有间隔后通过最终的后处理检查来处理后缀。
