[LeetCode 问题 2608](https://leetcode.com/problems/shortest-cycle-in-a-graph/)

 **难度：** 🔴难
 **主题：** 广度优先搜索、图论

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个无向图`n`顶点标记为`0`到`n - 1`。 该图使用边列表表示，其中每条边在两个方向上连接两个顶点。 

我们的任务是找到图中最短循环的长度。 循环是在同一顶点开始和结束且不重复使用任何边的路径。 由于该图是无向的，因此遍历一条边`u`到`v`与遍历相同`v`到`u`。 

输入包括：

 - 一个整数`n`，顶点数。 
- 一份清单`edges`，其中每个元素`[u, v]`表示无向边。 

输出应该是：

 - 如果至少存在一个周期，则最短周期的长度。 
-`-1`如果图是非循环的。 

限制相对较小：

 -`n <= 1000`-`edges.length <= 1000`这些限制强烈表明，即使重复多次，诸如广度优先搜索（BFS）之类的图遍历算法也是可行的。 

从问题保证中得出几个重要的观察结果：

 - 不存在自循环，因此循环长度`1`是不可能的。 
- 不存在重复的边，因此长度是循环的`2`也是不可能的。 
- 该图可能是断开的，因此我们必须考虑所有连接的组件。 
- 最短循环可以完全存在于一个组件内，而其他组件则为树。 

重要的边缘情况包括：

 - 完全没有循环的图表。 
- 多个断开连接的组件。 
- 不同长度的多个周期。 
- 多个循环重叠的密集局部结构。 
- 非常小的图，其中不可能存在循环。 

## 方法

 ### 蛮力方法

 一个简单的解决方案会尝试枚举图中所有可能的循环并跟踪遇到的最小长度。 

一种可能的暴力策略是：

 - 从每个节点启动 DFS。 
- 探索所有可能的路径。 
- 检测路径何时返回起始节点。 
- 记录周期长度。 

这种方法是正确的，因为它最终探索了每一个可能的循环。 然而，它的效率极低，因为图中简单路径的数量呈指数增长。 即使进行了修剪，重复的探索也会变得非常昂贵。 

对于最多有 1000 个顶点的图，穷举循环枚举是不切实际的。 

### 关键见解

 重要的观察是 BFS 自然地在未加权图中找到最短路径。 

假设我们从起始节点运行 BFS`start`。 

在BFS期间，如果我们遇到一个先前访问过的邻居，但它不是当前节点的父节点，那么我们就找到了一个环。 

为什么这有效？ 

- BFS逐层探索节点。 
- 因此，第一次通过非父边重新连接时，我们可以使用已经发现的距离来计算有效的循环长度。 

对于节点之间检测到的循环`u`和`v`：```
cycle_length = dist[u] + dist[v] + 1
```这是有效的，因为：

 -`dist[u]`是最短距离`start`到`u`-`dist[v]`是最短距离`start`到`v`- 边缘`(u, v)`关闭循环

 通过从每个节点运行 BFS，我们确保考虑每个可能的最短周期。

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 枚举所有可能的循环 |

 这里：

-`n`是顶点数
 -`e`是边数

 由于两者都最多为 1000，因此 BFS 解决方案足够高效。 

## 算法演练

 ### 最优 BFS 算法

 1. 为图构建邻接表。 

由于图是无向的，所以每条边`[u, v]`是在两个方向上添加的。 
2. 初始化变量`shortest_cycle`到无穷大。 

该变量跟踪所有 BFS 遍历中找到的最小循环长度。 
3. 从每个节点开始运行 BFS。 

我们这样做是因为最短周期可能不会涉及每个节点，并且可能存在断开连接的组件。 
4.对于每次BFS遍历，维护：

 - A`distance`数组初始化为`-1`- A`parent`数组初始化为`-1`- BFS 的队列

 的`distance`数组存储距起始节点的最短距离。 

这`parent`数组可防止错误地将紧邻的反向沿检测为循环。 
5. 从当前源节点启动BFS。 

放：```
distance[start] = 0
```然后将节点推入队列。 
6. 逐级处理节点。 

对于每个当前节点`u`，检查每个邻居`v`。 
7. 如果`v`尚未访问过：

 - 设置其距离
 - 记录其父级
 - 将其推入队列
 8. 否则，如果`v`已经被访问过并且`v`不是 的父级`u`：

 我们发现了一个循环。 

计算：```
cycle_length = distance[u] + distance[v] + 1
```然后更新全局最小值。 
9. 所有 BFS 遍历完成后：

 - 返回找到的最小循环长度
 - 如果没有发现循环，则返回`-1`### 为什么它有效

 BFS 保证未加权图中的最短路径距离。 当 BFS 遇到已访问过的非父节点时，当前边关闭一个循环。 

计算出的循环长度正确地表示了该循环中的边数，因为：

 - 一条最短路径将源连接到`u`- 另一条最短路径将源连接到`v`- 边缘`(u, v)`完成循环

 从每个节点运行 BFS 可保证最终发现全局最短周期。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def findShortestCycle(self, n: int, edges: List[List[int]]) -> int:
        graph = [[] for _ in range(n)]

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)

        shortest_cycle = float("inf")

        for start in range(n):
            distance = [-1] * n
            parent = [-1] * n

            queue = deque([start])
            distance[start] = 0

            while queue:
                current = queue.popleft()

                for neighbor in graph[current]:
                    if distance[neighbor] == -1:
                        distance[neighbor] = distance[current] + 1
                        parent[neighbor] = current
                        queue.append(neighbor)

                    elif parent[current] != neighbor:
                        cycle_length = (
                            distance[current]
                            + distance[neighbor]
                            + 1
                        )

                        shortest_cycle = min(
                            shortest_cycle,
                            cycle_length
                        )

        return shortest_cycle if shortest_cycle != float("inf") else -1
```### 实现说明

 第一步构造图的邻接表表示。 由于该图是无向的，因此每条边被插入两次。 

外循环从每个节点运行 BFS。 这保证了每个可能的循环都可以被检测到。 

每个 BFS 内部：

 -`distance[node]`存储从起始节点开始的最短边数。 
-`parent[node]`存储我们第一次到达该节点的节点。 

家长跟踪至关重要。 在无向图中，每条边出现两次。 如果不检查父关系，遍历就会错误地将反向遍历边解释为循环。 

当我们遇到先前访问过的不是父级的邻居时，我们使用以下方法计算循环长度：```
distance[current] + distance[neighbor] + 1
```这个公式计算：

 - 从起点到终点的最短路径`current`- 从起点到终点的最短路径`neighbor`- 它们之间的连接边

 最后，如果没有找到循环，答案仍然是无穷大，我们返回`-1`。 

## 解决方案```go
package main

import "container/list"

func findShortestCycle(n int, edges [][]int) int {
	graph := make([][]int, n)

	for _, edge := range edges {
		u, v := edge[0], edge[1]
		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	const INF int = 1 << 30
	shortestCycle := INF

	for start := 0; start < n; start++ {
		distance := make([]int, n)
		parent := make([]int, n)

		for i := 0; i < n; i++ {
			distance[i] = -1
			parent[i] = -1
		}

		queue := list.New()
		queue.PushBack(start)
		distance[start] = 0

		for queue.Len() > 0 {
			front := queue.Front()
			queue.Remove(front)

			current := front.Value.(int)

			for _, neighbor := range graph[current] {
				if distance[neighbor] == -1 {
					distance[neighbor] = distance[current] + 1
					parent[neighbor] = current
					queue.PushBack(neighbor)
				} else if parent[current] != neighbor {
					cycleLength := distance[current] + distance[neighbor] + 1

					if cycleLength < shortestCycle {
						shortestCycle = cycleLength
					}
				}
			}
		}
	}

	if shortestCycle == INF {
		return -1
	}

	return shortestCycle
}
```### Go 特定注释

 Go 解决方案密切反映了 Python 实现。 

一些特定于语言的细节值得注意：

 - Go不提供内置的双端队列，所以`container/list`用于BFS队列操作。 
- 数组是显式初始化的，因为 Go 不支持 Python 风格的列表乘法。 
- 一个大常数`INF`使用浮点无穷大。 
- 切片用于邻接列表，因为它们随着邻居的添加而动态增长。 

不存在整数溢出问题，因为最大循环长度最多为`n`，这只是`1000`。

O(n × (n + e))
```在给定的约束下，这在实践中足够有效。

 ## 边缘情况

 ### 无环图

 一棵树或断开的森林根本不包含循环。 这是一个重要的边缘情况，因为简单的实现可能会意外地将父边缘解释为无向图中的循环。 

该实现通过在 BFS 期间跟踪每个节点的父节点来避免这种情况。 当重新访问一个节点时，如果邻居不是父节点，算法仅将其视为一个循环。 

如果没有找到循环，结果将保持无穷大并且函数正确返回`-1`。 

### 断开的图

 该图可能包含多个断开连接的组件。 某些组件可能包含循环，而其他组件则可能不包含。 

有缺陷的实现可能只能从节点运行 BFS`0`并错过其他组件中的周期。 

该解决方案从每个节点开始运行 BFS，保证所有组件都被完全探索。 

### 重叠循环

 图可能包含多个共享边或顶点的循环。 

例如：```
0 - 1
| X |
2 - 3
```这种情况很棘手，因为不同的遍历顺序可能会首先发现更长的周期。 

由于 BFS 始终计算未加权图中的最短距离，因此每个检测到的循环长度都是有效的，并且采用全局最小值保证返回最短循环。
