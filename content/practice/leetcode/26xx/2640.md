[LeetCode 问题 2640](https://leetcode.com/problems/find-the-score-of-all-prefixes-of-an-array/)

 **难度：** 🟡 中等
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 该问题需要计算数组所有前缀的**分数**。 给定一个整数数组`nums`，我们首先为任何前缀定义一个**转换数组**`nums`。 转换数组是通过将前缀中的每个元素添加到**迄今为止在该前缀中看到的最大元素**来构造的。 前缀的**分数**是其转换数组的总和。 我们需要返回一个数组`ans`在哪里`ans[i]`是前缀的分数`nums[0..i]`。 

输入数组`nums`**0索引**，其长度可达100,000，元素可达10亿。 这意味着任何解决方案都必须是**时间线性**才能有效处理最大的输入。 大数字还表明我们需要使用可以处理超过 32 位整数的和的数字类型。 

重要的观察结果包括：前缀结构允许我们**增量计算分数**，并且跟踪**当前最大值**避免重复扫描数组。 要考虑的边缘情况是长度为 1 的数组、所有元素都相等的数组、严格递增数组和严格递减数组。 

## 方法

 **暴力方法**迭代每个前缀，并通过扫描前缀的最大值来显式构造转换数组。 然后，它对转换数组求和。 虽然正确，但这种方法的时间复杂度为$O(n^2)$对于大的输入将会失败。 

**最佳方法**利用**增量计算**。 我们维护一个变量，而不是每次重新计算前缀最大值`current_max`当我们迭代时。 对于每个元素`nums[i]`，转换值为`nums[i] + current_max`，前缀分数就是之前的前缀分数加上这个转换值。 这将时间复杂度降低到 **O(n)**，同时保持输出的空间复杂度呈线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 计算每个前缀的前缀最大值和转换总和 |
 | 最佳| O(n) | O(n) | 维护运行前缀总和和最大值以增量计算分数 |

 ## 算法演练

 1.初始化一个空列表`ans`存储前缀分数。 
2. 初始化`current_max`为 0 来跟踪迄今为止看到的最大元素。 
3. 初始化`prefix_score`设置为 0 来跟踪当前前缀的累积分数。 
4. 迭代每个元素`num`在`nums`：

 1. 更新`current_max`作为最大值`current_max`和`num`。 
2. 计算转化价值`conversion = num + current_max`。 
3. 更新`prefix_score`通过添加`conversion`。 
4. 追加`prefix_score`到`ans`。 
5.循环结束后，返回`ans`。 

**为什么有效：** 在每一步，`current_max`正确存储前缀的最大值。 添加`num`到`current_max`给出当前的转换值，并将这些值增量求和以确保正确累积前缀分数。 

## Python 解决方案```python
from typing import List

class Solution:
    def findPrefixScore(self, nums: List[int]) -> List[int]:
        ans: List[int] = []
        current_max: int = 0
        prefix_score: int = 0

        for num in nums:
            current_max = max(current_max, num)
            conversion = num + current_max
            prefix_score += conversion
            ans.append(prefix_score)

        return ans
```Python 实现紧密遵循该算法。`current_max`保留所见的最大数字，`conversion`计算转换数组值，并且`prefix_score`累积前缀的总和。 每个前缀分数都附加到`ans`，最后返回。 

## 解决方案```go
func findPrefixScore(nums []int) []int64 {
    n := len(nums)
    ans := make([]int64, n)
    var currentMax int64 = 0
    var prefixScore int64 = 0

    for i, num := range nums {
        num64 := int64(num)
        if num64 > currentMax {
            currentMax = num64
        }
        conversion := num64 + currentMax
        prefixScore += conversion
        ans[i] = prefixScore
    }

    return ans
}
```在 Go 中，我们必须显式处理 64 位整数以避免溢出，因为`nums[i]`可以大到$10^9$并且总和可以超过 32 位限制。 其余逻辑反映了 Python 解决方案。 片`ans`直接存储前缀分数，并使用以下方式维护运行总计`currentMax`和`prefixScore`。

 ## 边缘情况

 一种重要的边缘情况是**单元素数组**，其中前缀和转换数组仅包含一个元素。 该算法通过初始化自然地处理这个问题`current_max`和`prefix_score`。 

另一个边缘情况是**具有所有相同元素的数组**，如果未正确更新，可能会导致朴素的最大计算失败。 这里，`current_max`保持不变，每个元素的转换值加倍，我们的解决方案可以正确处理。 

第三种边缘情况涉及**大数**，因为转换数组的总和可能超过 32 位整数限制。 在 Python 中，整数是任意精度的，但在 Go 中，我们明确使用`int64`以防止溢出。 我们的解决方案通过将输入转换为 64 位整数来解决这个问题
