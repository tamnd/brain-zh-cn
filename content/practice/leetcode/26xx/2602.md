[LeetCode 问题 2602](https://leetcode.com/problems/minimum-operations-to-make-all-array-elements-equal/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、排序、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和另一个数组`queries`。 对于每个查询值`q`，我们必须计算使每个元素成为所需的最少操作数`nums`等于`q`。 

一个操作包括将单个元素精确地增加或减少`1`。 由于每次操作都会改变一个步骤的值，因此转换一个值所需的操作次数`x`进入`q`很简单：```
|x - q|
```对于查询`q`，因此总成本为：```
sum(|nums[i] - q| for all i)
```重要的细节是，处理完一个查询后，数组将重置为其原始状态。 这意味着查询是相互独立的。 我们不会永久修改`nums`。 

限制条件非常大：

 -`n`和`m`每个都可以达到`100000`- 值可以大到`10^9`对于每个查询循环遍历整个数组的简单解决方案需要：```
O(n * m)
```在最坏的情况下，这会变成：```
100000 * 100000 = 10^10
```这太慢了。 

这些约束强烈表明我们需要预处理和高效的查询处理。 由于该问题涉及对有序数值的重复计算，因此排序和前缀和是自然的选择。 

一些边缘情况很重要：

 - 查询小于中的每个数字`nums`- 查询大于中的每个数字`nums`- 查询完全匹配现有值
 - 包含重复值的数组
 - 大小的数组`1`- 在某些语言中非常大的值可能会溢出 32 位整数

 该问题保证所有数字都是正整数并且两个数组都非空。 

## 方法

 ### 蛮力方法

 最简单的解决方案是独立处理每个查询。 

对于每个查询`q`，迭代中的每个数字`nums`并计算：```
abs(nums[i] - q)
```将所有这些差异加在一起并存储结果。 

这是可行的，因为将一个数字转换为另一个数字所需的最少运算次数正是它们的绝对差。 

然而，这种方法执行完整扫描`nums`对于每个查询。 

如果：

-`n = 100000`-`m = 100000`那么总的操作就变成：```
O(n * m) = O(10^10)
```这太慢了。 

### 最佳方法

 关键的观察结果是，对数组进行排序后，所有小于查询的数字都以一种可预测的方式贡献，所有大于查询的数字以另一种可预测的方式贡献。 

假设查询是`q`。 

对于所有小于`q`：```
cost = q - nums[i]
```对于所有大于`q`：```
cost = nums[i] - q
```如果数组是有序的，我们可以使用二分查找来找到之间的分界点：

 - 价值观`< q`- 价值观`>= q`一旦我们知道每一侧有多少个元素，前缀和就可以让我们计算恒定时间内的总贡献。 

对于左侧：```
q * countLeft - sumLeft
```对于右侧：```
sumRight - q * countRight
```这减少了每个查询`O(n)`到`O(log n)`因为二分查找。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(1) | O(1) | 计算每个元素和每个查询的绝对差异 |
 | 最佳| O(n log n + m log n) | O(n log n + m log n) | O(n) | 使用排序、前缀和和二分搜索 |

 ## 算法演练

 ### 第 1 步：对数组进行排序

 排序`nums`按升序排列。 

这很重要，因为二分搜索仅适用于排序数据。 排序还将较小和较大的值分组在一起，使范围计算变得容易。 

例子：```
nums = [3,1,6,8]
sorted = [1,3,6,8]
```### 步骤 2：构建前缀和数组

 创建一个前缀和数组，其中：```
prefix[i]
```存储第一个的总和`i`元素。 

我们通常让前缀数组大小`n + 1`以便：```
prefix[0] = 0
```例子：```
nums   = [1,3,6,8]
prefix = [0,1,4,10,18]
```含义：

 - 前 0 个元素之和为 0
 - 前 1 个元素之和为 1
 - 前 2 个元素之和为 4
 - 前 3 个元素之和为 10
 - 前 4 个元素之和为 18

 这允许恒定时间范围总和计算。 

### 步骤 3：处理每个查询

 对于每个查询`q`，使用二分查找查找第一个索引，其中：```
nums[index] >= q
```该索引将数组分为：

 - 左侧：值小于`q`- 右侧：值大于或等于`q`认为：```
index = k
```然后：

 - 剩余计数 =`k`- 正确计数 =`n - k`### 步骤 4：计算左贡献

 左边的所有值必须增加到`q`。 

他们的总成本是：```
(q * leftCount) - leftSum
```在哪里：```
leftSum = prefix[k]
```### 步骤 5：计算正确贡献

 右侧的所有值必须减少到`q`。 

他们的总成本是：```
rightSum - (q * rightCount)
```在哪里：```
rightSum = prefix[n] - prefix[k]
```### 第 6 步：添加两种成本

 查询的答案是：```
leftCost + rightCost
```将其存储在结果数组中。 

### 为什么它有效

 该算法之所以有效，是因为一旦数组排序，绝对差可以分为两种线性形式。 

对于小于的元素`q`：```
|x - q| = q - x
```对于大于的元素`q`：```
|x - q| = x - q
```排序使我们能够通过二分搜索有效地识别这两个组。 然后，前缀和可以快速计算每组的总和。 由于每个元素对总操作计数都有独立的贡献，因此将这些贡献相加即可得出确切的最小操作数。 

## Python 解决方案```python
from bisect import bisect_left
from typing import List

class Solution:
    def minOperations(self, nums: List[int], queries: List[int]) -> List[int]:
        nums.sort()
        n = len(nums)

        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + nums[i]

        result = []

        total_sum = prefix[n]

        for query in queries:
            index = bisect_left(nums, query)

            left_count = index
            right_count = n - index

            left_sum = prefix[index]
            right_sum = total_sum - left_sum

            left_cost = query * left_count - left_sum
            right_cost = right_sum - query * right_count

            result.append(left_cost + right_cost)

        return result
```实现从排序开始`nums`。 这使得二分搜索和比每个查询更小和更大的值的干净分离成为可能。 

接下来，构造前缀和数组。 每个条目存储截至该点的累积和，从而允许恒定时间范围和检索。 

对于每个查询，`bisect_left`查找可以插入查询的第一个位置，同时保持排序顺序。 该位置将数组分为两个逻辑区域。 

左侧区域包含小于查询的值。 这些值需要增加，因此它们的总调整成本使用以下公式计算：```python
query * left_count - left_sum
```右侧区域包含大于或等于查询的值。 这些值需要减少，因此它们的总调整成本为：```python
right_sum - query * right_count
```将这两个成本相加即可得出该查询所需的最少操作。 

## 解决方案```go
package main

import (
	"sort"
)

func minOperations(nums []int, queries []int) []int64 {
	sort.Ints(nums)

	n := len(nums)

	prefix := make([]int64, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + int64(nums[i])
	}

	totalSum := prefix[n]

	result := make([]int64, 0, len(queries))

	for _, query := range queries {
		index := sort.SearchInts(nums, query)

		leftCount := int64(index)
		rightCount := int64(n - index)

		leftSum := prefix[index]
		rightSum := totalSum - leftSum

		leftCost := int64(query)*leftCount - leftSum
		rightCost := rightSum - int64(query)*rightCount

		result = append(result, leftCost+rightCost)
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个重要的区别是整数处理。 由于总运算计数可能超出 32 位整数范围，因此所有前缀和和运算计算都使用`int64`。 

Go 使用`sort.SearchInts`而不是Python的`bisect_left`用于二分查找。 

结果切片的初始化容量等于查询数量，以实现高效追加。

 ## 边缘情况

 ### 查询小于每个元素的查询

 考虑：```
nums = [10,20,30]
query = 1
```每个值都必须减少。 二分查找索引变为`0`，意味着左侧是空的。 

一个常见的错误是错误处理空范围或负索引。 这个实现自然地处理它，因为：```
leftCount = 0
leftSum = 0
```只有右边的公式才能得出答案。 

### 查询大于每个元素

 考虑：```
nums = [1,2,3]
query = 10
```现在每个值都必须增加。 二分查找索引变为`n`。 

该实现正确地处理了这个问题，因为：```
rightCount = 0
rightSum = 0
```只有左侧公式有贡献。 

### 具有重复值的数组

 考虑：```
nums = [2,2,2,2]
query = 2
```答案应该是`0`。 

使用`bisect_left`正确地将分割放在第一次出现之前`2`。 这些公式仍然有效，因为等于查询的元素贡献零成本。 

这可以防止在使用二分搜索处理重复项时经常发生的差一错误。 

### 非常大的值

 数值可以达到`10^9`，并且可能有`10^5`元素。 

因此，总操作数可能超过：```
10^14
```这比 32 位整数可以存储的要大。 

Go 解决方案使用`int64`对于所有求和和计算，确保不会发生溢出。 Python 整数会自动扩展，因此不需要额外的处理。
