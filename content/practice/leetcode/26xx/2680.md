[LeetCode 第 2680 题](https://leetcode.com/problems/maximum-or/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、位操作、前缀和

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出一个整数数组`nums`和一个整数`k`。 我们最多可以表演`k`操作，其中每个操作选择一个元素并将其乘以`2`。 

乘以`2`二进制相当于将所有位向左移动一位。 例如：

-`5`二进制是`101`-`5 * 2 = 10`，即`1010`执行完后达到`k`操作时，我们必须计算所有数组元素的按位或并返回最大可能值。 

表达式：```
nums[0] | nums[1] | ... | nums[n - 1]
```组合任何元素中设置的所有位。 最终结果中的一点变成`1`如果至少有一个数字包含该位。 

关键的挑战是决定把钱花在哪里`k`加倍运算。 我们可以将操作分布在多个元素上，或者将所有操作应用于单个元素。 

约束条件很重要：

 -`n`可以大到`10^5`-`nums[i]`可以达到`10^9`-`k`至多是`15`大数组意味着我们需要接近线性时间的算法。 二次解会太慢。 

一个重要的观察结果是，将一个元素左移`k`位置可以创建非常大的高位，通常比在许多数字上分配移位对最终的 OR 贡献更大。 

有几种边缘情况值得考虑：

 - 只有一个元素的数组
 - 非常大的值已经包含许多高位
 - 移位较小数字会产生更有用的高位的情况
 - 将所有运算应用于一个数字是最佳的情况
 - 多个数字在二进制表示中已经严重重叠的数组

 该问题保证：

 - 数组非空
 - 每个值都是正值
 -`k >= 1`这避免了涉及空数组或负整数的复杂情况。 

## 方法

 ### 蛮力方法

 蛮力策略会尝试一切可能的方式来分配`k`数组元素之间的运算。 

例如，如果`k = 3`，我们可以尝试：

 - 对索引的所有 3 个操作`0`- 索引中有两个`0`, 索引一`1`- 三个指数各一个
 - 许多其他组合

 对于每个发行版，我们将：

 1.申请轮班
 2. 计算最终的 OR
 3. 跟踪最大值

 这种方法是正确的，因为它探索了每一种可能的有效状态。 

然而，这在计算上是不可行的。 分配方式数量`k`之间的操作`n`元素组合增长。 虽然`k <= 15`,`n`可以达到`10^5`，使得穷举搜索变得不可能。 

### 关键见解

 关键的观察结果是“或”运算从创建新的高阶位中获益最多。 

对同一个数字应用多次左移会产生指数级更大的值，因为：```
x * 2^k
```向左添加更多位。 

如果我们在多个元素之间拆分操作，我们通常会创建重叠的较低位，而不是引入全新的较高位。 

这会带来最佳的洞察力：

 > 我们只需要考虑应用所有`k`只对一个元素进行操作。 

对于每个索引`i`：

 1. 转变`nums[i]`留下来`k`2. 将其与所有其他未更改的元素进行“或”运算
 3. 计算结果值

 剩下的挑战是计算除索引之外的所有元素的或`i`高效。 

我们使用前缀 OR 和后缀 OR 数组来解决这个问题。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 尝试每种操作分布 |
 | 最佳| O(n) | O(n) | 使用前缀和后缀 OR 数组 |

 ## 算法演练

 ### 第 1 步：构建前缀 OR 数组

 创建一个数组`prefix`在哪里：```
prefix[i]
```存储索引中所有元素的或`0`通过`i`。 

例子：```
nums = [8,1,2]

prefix[0] = 8
prefix[1] = 8 | 1 = 9
prefix[2] = 9 | 2 = 11
```这使我们能够快速检索任何索引之前的元素的或。 

### 步骤 2：构建后缀 OR 数组

 创建另一个数组`suffix`在哪里：```
suffix[i]
```存储索引中所有元素的或`i`通过`n - 1`。 

例子：```
suffix[2] = 2
suffix[1] = 1 | 2 = 3
suffix[0] = 8 | 3 = 11
```这让我们可以有效地检索任意索引后元素的“或”运算。 

### 步骤 3：尝试将每个元素作为移位元素

 对于每个索引`i`：

 1. 计算之前所有元素的或`i`2. 计算之后所有元素的或`i`3. 转变`nums[i]`留下来`k`4. 或者将所有内容放在一起

 候选值变为：```
left_or | (nums[i] << k) | right_or
```### 步骤 4：跟踪最大结果

 保持所有候选人的运行最大值。 

由于每个指标都是独立评估的，因此我们最终找到最优答案。 

### 为什么它有效

 正确性依赖于左移以指数方式增加位数的事实。 高阶位比重复设置已经存在的低位更能主导“或”结果。 

因为 OR 只关心一位是否至少出现一次，所以将所有移位集中在一个元素上可以最大限度地提高引入新的更高位的机会。 前缀和后缀 OR 数组确保我们可以有效地将移位的元素与数组的其余部分组合起来。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumOr(self, nums: List[int], k: int) -> int:
        n = len(nums)

        prefix = [0] * n
        suffix = [0] * n

        prefix[0] = nums[0]
        for i in range(1, n):
            prefix[i] = prefix[i - 1] | nums[i]

        suffix[n - 1] = nums[n - 1]
        for i in range(n - 2, -1, -1):
            suffix[i] = suffix[i + 1] | nums[i]

        answer = 0

        for i in range(n):
            left_or = prefix[i - 1] if i > 0 else 0
            right_or = suffix[i + 1] if i < n - 1 else 0

            shifted_value = nums[i] << k

            candidate = left_or | shifted_value | right_or

            answer = max(answer, candidate)

        return answer
```实现首先构建前缀 OR 数组。 每个条目都会累加所有先前元素（包括当前元素）的或。 

接下来，以相反的顺序构建后缀 OR 数组。 这允许恒定时间访问任意位置右侧元素的“或”运算。 

主循环将每个索引评估为接收所有索引的元素`k`运营。 移位值的计算方法为：```python
nums[i] << k
```这相当于乘以`2^k`。 

对于每个位置，我们结合：

 - 索引之前的所有元素的或
 - 移动当前元素
 - 索引后所有元素的或

 最后返回最大候选者。 

## 解决方案```go
func maximumOr(nums []int, k int) int64 {
	n := len(nums)

	prefix := make([]int64, n)
	suffix := make([]int64, n)

	prefix[0] = int64(nums[0])
	for i := 1; i < n; i++ {
		prefix[i] = prefix[i-1] | int64(nums[i])
	}

	suffix[n-1] = int64(nums[n-1])
	for i := n - 2; i >= 0; i-- {
		suffix[i] = suffix[i+1] | int64(nums[i])
	}

	var answer int64 = 0

	for i := 0; i < n; i++ {
		var leftOr int64 = 0
		var rightOr int64 = 0

		if i > 0 {
			leftOr = prefix[i-1]
		}

		if i < n-1 {
			rightOr = suffix[i+1]
		}

		shiftedValue := int64(nums[i]) << k

		candidate := leftOr | shiftedValue | rightOr

		if candidate > answer {
			answer = candidate
		}
	}

	return answer
}
```Go 的实现与 Python 版本非常相似。 

一个重要的区别是使用`int64`。 由于将值左移最多`15`位置可以超出 32 位整数的范围，我们明确使用`int64`以避免溢出。 

切片用于前缀和后缀数组，按位运算的行为与 Python 类似。

 ## 边缘情况

 一个重要的边缘情况是仅包含单个元素的数组。 在这种情况下，没有其他元素对 OR 值有贡献，因此答案就是该元素左移了`k`。 该实现自然地处理了这个问题，因为`left_or`和`right_or`变得`0`。 

当许多元素已经共享相同的设置位时，会出现另一种棘手的情况。 例如：```
[7,7,7]
```由于 OR 会忽略重复位，因此将操作分布在多个元素上几乎没有增加任何价值。 该实现正确地识别出尽可能多地移位一个元素会产生最佳的高阶位。 

第三个重要的边缘情况涉及非常大的转变。 自从`k`可以达到`15`，左移可能会产生大于 32 位整数限制的值。 Python 自动处理任意大的整数，但 Go 解决方案明确使用`int64`以防止溢出。 

最后一个微妙的情况是最大的数字元素不一定是移动的最佳候选者。 有时，较小的值在移位后会产生更有益的新位。 由于该算法独立评估每个指标，因此它从不假设最大当前值自动是最优的。
