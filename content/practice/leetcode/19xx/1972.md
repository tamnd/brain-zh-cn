[LeetCode 1972 题](https://leetcode.com/problems/first-and-last-call-on-the-same-day/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个电话呼叫记录表，其中每行包含呼叫者、接收者和时间戳。 每个呼叫都是双向的，因为两个参与者都被视为同时发出和接收呼叫。 目标是识别在至少一个日历日内第一次呼叫和最后一次呼叫涉及同一对应用户的所有用户。 

更准确地说，对于每个用户以及他们至少参与一次通话的每一天，我们必须考虑当天涉及该用户的通话顺序（无论他们是呼叫者还是接收者）。 如果当天最早的呼叫和当天最晚的呼叫都涉及同一个其他用户，则该用户有资格获得结果。 

输入是呼叫事件的关系数据集。 输出是一组经过去重处理的用户 ID，表示至少一天满足条件的用户。 

尽管该问题被定义为数据库任务，但它从根本上需要按用户和日期对事件进行分组，按时间排序，并检查边界条件。 

这些约束意味着潜在的大输入大小，因此根据索引策略，预计会出现 O(n log n) 或 O(n) 分组解决方案。 将每个调用与其他每个调用进行天真的比较会太慢。 

重要的边缘情况包括用户一天仅进行一次呼叫、与不同合作伙伴进行多次呼叫、跨越多天的呼叫以及确保呼叫者和接收者之间的对称性。 另一个微妙的情况是，即使用户在其他日子没有资格，也可能在某一天符合资格，而我们只需要至少一个符合资格的日子。 

## 方法

 蛮力方法从字面上模拟了问题。 对于每个用户和每一天，我们都会收集涉及该用户的所有呼叫，按时间对它们进行排序，并比较第一个和最后一个呼叫伙伴。 然而，通过重复扫描完整数据集来为每个用户日对独立执行此操作会导致冗余工作和高计算成本。 

最佳方法认识到每个调用都会贡献两个用户，并且我们可以将所有事件预处理为按 (user_id, date) 分组的结构。 在每个组中，我们只需要跟踪呼叫的时间顺序并比较端点。 这避免了重复的全扫描，并将问题减少到高效分组和排序。

 | 蛮力 | O(U × D × N log N) | O(U × D × N log N) | O(N) | 对于每个用户日，重新扫描和排序呼叫 |
 | 最佳分组 | O(N log N) | O(N log N) | O(N) | 按用户日分组，在组内排序 |

 ## 算法演练

 最佳解决方案的理念是将每个呼叫转换为两个定向事件，以便每个用户都可以独立分析自己的呼叫时间线。

1. 首先，我们迭代每条通话记录。 对于给定时间戳的呼叫者和接收者之间的每次呼叫，我们创建两个事件：一个用于呼叫者，一个用于接收者。 这种规范化确保每个用户都可以完整地查看自己的通话历史记录，而无需推理方向性。 
2. 我们从时间戳中提取日期部分，因为条件是按日历日评估的。 这使我们能够将呼叫分组到每个用户独立的每日存储桶中。 
3. 我们将这些事件存储在以 (user_id, date) 为键的字典中。 每个值都是 (time, other_user) 对的列表，表示用户交互的时间以及与谁交互。 
4. 构建结构后，我们迭代每个 (user_id, date) 组。 我们按时间对事件进行排序，以重建该用户当天的呼叫时间顺序。 
5. 排序后，我们检查列表中的第一个和最后一个条目。 如果两个位置中的“other_user”相同，则意味着当天的第一个和最后一个调用涉及同一个人，因此我们将该用户包含在结果集中。 
6. 最后，我们返回所有符合条件的用户 ID（已删除重复数据）。 

### 为什么它有效

 关键的不变量是，对每个用户每天的事件列表进行排序可以重建该用户参与的确切时间顺序。 由于我们仅显式检查第一次和最后一次交互，因此我们直接验证问题条件，而无需检查中间调用。 

## Python 解决方案```python
from typing import List, Tuple, Dict
from collections import defaultdict
from datetime import datetime

class Solution:
    def firstLastCall(self, calls: List[Tuple[int, int, str]]) -> List[int]:
        user_day_map: Dict[Tuple[int, str], List[Tuple[str, int]]] = defaultdict(list)

        for caller, recipient, call_time in calls:
            date = call_time.split(" ")[0]

            user_day_map[(caller, date)].append((call_time, recipient))
            user_day_map[(recipient, date)].append((call_time, caller))

        result = set()

        for (user_id, date), events in user_day_map.items():
            events.sort(key=lambda x: x[0])

            if events[0][1] == events[-1][1]:
                result.add(user_id)

        return list(result)
```### 代码说明

 该解决方案首先构建一个字典，按用户和日期对呼叫事件进行分组。 每个调用都会贡献两个条目，以便两个参与者都维护自己的时间表。 

日期是从时间戳字符串中提取的，这已经足够了，因为一天内的排序仍然按完整时间戳按字典顺序保留。 

分组后，每个事件列表均按时间戳排序，以确保时间顺序的正确性。 然后我们比较第一个和最后一个“其他参与者”值。 如果它们匹配，则该用户满足当天的条件。 

我们使用一组来避免重复，因为用户可能会在多天内满足条件。 

## 解决方案```go
package main

import (
    "sort"
    "strings"
)

type Event struct {
    time   string
    other  int
}

func firstLastCall(calls [][]string) []int {
    type key struct {
        user int
        date string
    }

    groups := make(map[key][]Event)

    for _, c := range calls {
        caller := atoi(c[0])
        recipient := atoi(c[1])
        time := c[2]

        date := strings.Split(time, " ")[0]

        groups[key{caller, date}] = append(groups[key{caller, date}], Event{time, recipient})
        groups[key{recipient, date}] = append(groups[key{recipient, date}], Event{time, caller})
    }

    resSet := make(map[int]bool)

    for k, events := range groups {
        sort.Slice(events, func(i, j int) bool {
            return events[i].time < events[j].time
        })

        if len(events) > 0 && events[0].other == events[len(events)-1].other {
            resSet[k.user] = true
        }
    }

    res := make([]int, 0, len(resSet))
    for id := range resSet {
        res = append(res, id)
    }

    return res
}

func atoi(s string) int {
    n := 0
    for i := 0; i < len(s); i++ {
        n = n*10 + int(s[i]-'0')
    }
    return n
}
```### Go 特定注释

 Go 需要显式类型定义来对键进行分组，因此结构体用于 (user, date)。 排序是通过`sort.Slice`，字符串分割用于提取日期。 由于 Go 在这个简化的代码片段中缺乏内置的字符串到整数的转换，因此需要一个手册`atoi`功能已包含在内。 映射用于分组和重复数据删除。 

## 工作示例

 考虑用户 8 在同一天有多个呼叫的输入。 我们首先展开调用：

 呼叫（17:46 8 → 4）变为：

 用户 8: (17:46, 4)

 用户 4: (17:46, 8)

 呼叫（19:57 4 → 8）变为：

 用户 8: (19:57, 4)

 用户 4: (19:57, 8)

 对于2021-08-24的用户8，排序后：

 (17:46, 4), (19:57, 4)

 第一个伙伴 = 4，最后一个伙伴 = 4，因此用户 8 符合资格。 

对于同一天的用户 4：

 (17:46, 8), (19:57, 8)

 第一个伙伴 = 8，最后一个伙伴 = 8，因此用户 4 符合资格。 

对于像用户 1 和 5 这样的单次通话日：

 每个用户仅存在一个事件，因此第一个事件和最后一个事件在定义上是相同的，并且都符合条件。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N log N) | O(N log N) | 每个调用都会处理两次，并按用户日组进行排序 |
 | 空间| O(N) | 为双方参与者存储扩展事件 |

 主导因素是在分组呼叫列表中进行排序。 虽然分组本身是线性的，但排序会带来每个组的对数开销，在最坏的情况下会产生总体 O(N log N) 行为。

 ## 边缘情况

 一个重要的边缘情况是用户一天内只有一个呼叫。 在这种情况下，该呼叫同时是第一个和最后一个呼叫，因此用户应该始终符合资格。 该实现自然地处理这个问题，因为事件列表包含单个元素，并且两个端点是相同的。 

另一种边缘情况涉及与同一合作伙伴但与其他合作伙伴交错的多个呼叫。 排序严格按照时间进行，因此即使用户重复呼叫同一个人，第一个和最后一个呼叫仍然必须匹配同一个伙伴； 否则，取消资格。 排序可确保我们正确捕获此顺序。 

第三个边缘情况是确保双向包容。 必须对双方参与者的通话进行录音，否则互动的一侧将会丢失，结果也会不正确。 通过显式插入调用者和接收者的镜像事件，我们保证了对称性。 

最后的边缘情况涉及每个用户多个资格日。 该解决方案正确使用了一组，确保每个用户仅包含一次，无论他们满足条件多少天。
