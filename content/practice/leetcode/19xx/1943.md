[LeetCode 1943 题](https://leetcode.com/problems/describe-the-painting/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、排序、前缀和

 ## 解决方案

 ## 问题理解

 该问题描述了放置在数轴上的一幅画。 绘画的每个部分都表示为半闭区间`[start, end)`并涂有独特的色彩价值。 由于多个片段可能重叠，因此不同的颜色可以同时存在于同一区域上。 

我们不需要返回每个区域的实际颜色集，而只需返回该时间间隔内当前活动颜色的总和。 

目标是将整条绘制线分割成最少数量的不重叠的半闭区间，使得每个区间具有恒定的混合颜色和。 

一个关键细节是区间是半闭的。 该段`[a, b)`包括`a`但不包括`b`。 This means when one segment ends exactly where another begins, they do not overlap at that point.

 输入是：```
segments[i] = [starti, endi, colori]
```在哪里：

-`starti`是该段的包含开头
 -`endi`是排他性的结束
 -`colori`是分配给该段的唯一颜色

 输出应该是：```
[left, right, mixedColorSum]
```对于混合颜色总和保持恒定的每个连续绘制区域。 

约束条件很重要：

 - 最多`2 * 10^4`细分市场
 - 坐标高达`10^5`- 颜色高达`10^9`如果简单地实现的话，对每个坐标进行强力模拟会太慢，特别是因为坐标可能很大并且颜色是很大的整数。 

一些边缘情况很重要：

 - 多个线段可以在同一坐标处开始或结束
 - 相邻间隔可以具有相同的颜色总和，但仍代表不同的颜色集
 - 某些区域可能会变得未绘制，不应出现在答案中
 - Segments can overlap partially or completely
 - 坐标稀疏，因此不需要迭代每个整数点

 The fact that colors are unique is also useful. 它保证可以使用前缀和样式更新来干净地处理添加和删除颜色。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是在整个数轴上模拟绘画。 

我们可以创建一个代表每个坐标位置的数组`0`到`10^5`。 对于每个细分市场`[start, end, color]`，我们将迭代该区间内的所有位置并添加`color`到那个位置。 

处理完所有段后，我们将扫描数组并合并具有相同颜色和的连续位置。 

这种方法是正确的，因为每个单位间隔都会明确存储那里活动的确切混合颜色总和。 

然而，它的效率很低，因为每个段可能覆盖最多`10^5`职位。 和`2 * 10^4`段，最坏情况下的运行时间变得太大。 

### 最佳方法

 关键的观察结果是混合颜色总和仅在段边界处发生变化。 

如果两个坐标之间没有段开始或结束，则活动颜色集在整个该间隔内保持不变。 

这意味着我们不需要单独处理每个坐标。 相反，我们可以使用具有前缀和样式事件的扫描线算法。 

对于每个细分：

 - 添加`+color`在`start`- 添加`-color`在`end`然后我们对所有事件坐标进行排序并从左到右扫描，同时保持当前活动的颜色总和。 

两个连续坐标之间：

 - 如果有效总和非零，则该区间有助于得出答案
 - 活跃总和在整个时间间隔内保持恒定

 这将问题简化为仅处理边界点而不是每个坐标。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 最大坐标) | O(最大坐标) | 显式绘制每个坐标 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用差异事件扫线|

 ## 算法演练

 1. 创建差异图。 

我们使用哈希图，其中每个坐标存储活动颜色和在该点的变化情况。 

对于每个细分市场`[start, end, color]`：

- 添加`color`在`start`- 减法`color`在`end`例子：```
[1,4,5]
```产生：```
diff[1] += 5
diff[4] -= 5
```2. 对所有事件坐标进行排序。 

活动混合颜色只能在这些坐标处发生变化，因此我们按升序处理它们。 
3. 扫描排序后的坐标。 

维持：

-`current_sum`，有效混合颜色总和
 -`prev_position`, 前一个坐标
 4. 在当前坐标处应用更新之前，创建一个间隔。 

Suppose we move from`prev_position`到`position`。 

如果`current_sum > 0`，则区间：```
[prev_position, position)
```具有恒定的混合颜色和等于`current_sum`。 

将其添加到答案中。 
5. 应用差异更新。 

更新：```
current_sum += diff[position]
```这将激活或停用从此坐标开始的颜色。 
6. 继续，直到处理完所有坐标。 

由于最后一个坐标后面没有间隔，所以扫描自然终止。 

### 为什么它有效

 该算法依赖于两个连续事件坐标之间的不变量，活动段的集合永远不会改变。 

由于颜色仅在事件点处开始或结束，因此混合颜色总和在事件点之间的整个间隔内保持恒定。 

通过在从左到右扫描的同时保持活动颜色的运行总和，我们可以使用恒定的混合颜色总和正确地重建每个最大间隔。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def splitPainting(self, segments: List[List[int]]) -> List[List[int]]:
        diff = defaultdict(int)

        for start, end, color in segments:
            diff[start] += color
            diff[end] -= color

        sorted_positions = sorted(diff.keys())

        result = []
        current_sum = 0
        prev_position = sorted_positions[0]

        for position in sorted_positions:
            if current_sum > 0 and prev_position < position:
                result.append([prev_position, position, current_sum])

            current_sum += diff[position]
            prev_position = position

        return result
```实现首先构建差异图。 每个片段在开始时提供正更新，在结束时提供负更新。 

然后对发生变化的坐标进行排序。 这些坐标定义了所有可能的区间边界。 

扫描线遍历保持当前活动的混合颜色和。 在对当前坐标应用更新之前，算法会记录前一个坐标和当前坐标之间的间隔，因为活动颜色集在整个该区域中保持不变。 

条件：```python
current_sum > 0
```确保未绘制的区间被排除在结果之外。 

条件：```python
prev_position < position
```防止零长度间隔。 

最后，处理完所有坐标后，返回构建的列表。 

## 解决方案```go
package main

import (
	"sort"
)

func splitPainting(segments [][]int) [][]int64 {
	diff := make(map[int]int64)

	for _, segment := range segments {
		start := segment[0]
		end := segment[1]
		color := int64(segment[2])

		diff[start] += color
		diff[end] -= color
	}

	positions := make([]int, 0, len(diff))
	for pos := range diff {
		positions = append(positions, pos)
	}

	sort.Ints(positions)

	result := [][]int64{}

	var currentSum int64 = 0
	prevPosition := positions[0]

	for _, position := range positions {
		if currentSum > 0 && prevPosition < position {
			result = append(result, []int64{
				int64(prevPosition),
				int64(position),
				currentSum,
			})
		}

		currentSum += diff[position]
		prevPosition = position
	}

	return result
}
```Go 实现遵循与 Python 版本相同的扫描线逻辑。 

一个重要的区别是使用`int64`。 由于颜色可以大到`10^9`并且可能有很多重叠的段，总和可能超出标准32位整数的范围。 

Go 地图还需要显式初始化`make`，与 Python 不同`defaultdict`。 

结果类型是`[][]int64`因为 LeetCode 签名需要 64 位整数。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 对所有事件坐标进行排序主导运行时 |
 | 空间| O(n) | 差异图最多存储2n个坐标|

 每个片段恰好贡献两个事件，一个开始事件和一个结束事件。 

如果有`n`段，最多有`2n`不同的坐标。 对这些坐标进行排序需要`O(n log n)`时间。 

扫描本身与事件点的数量呈线性关系，因此不会改变整体复杂性。

 ## 边缘情况

 当多个线段在同一坐标处开始或结束时，会出现一种重要的边缘情况。 有缺陷的实现可能会单独处理这些事件，并意外地创建零长度间隔或不正确的转换。 差异图方法在继续扫描之前自然地将所有更新组合在同一坐标处，这保证了正确性。 

另一个重要的情况是接触间隔，例如`[1,3)`和`[3,5)`。 由于区间是半闭的，因此它们不会重叠。 幼稚的实现可能会错误地合并它们。 扫线方法可以正确处理此问题，因为在坐标处删除了一种颜色`3`在下一个间隔开始之前。 

当两个相邻间隔具有相同的数值和但基础颜色集不同时，会发生第三种棘手的情况。 例如：```
[1,4) -> {5,7}
[4,7) -> {1,11}
```两者总和相等`12`，但它们代表不同的颜色混合。 该算法仍然将它们分开，因为间隔边界是由事件坐标确定的，而不是由相邻总和是否恰好匹配确定的。 

另一个微妙的情况是未绘制的区域。 所有活动颜色消失后，当前总和变为零。 该实现显式地跳过间隔`current_sum == 0`，确保结果中不包含空白区域。
