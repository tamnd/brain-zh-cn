 # LeetCode 1964，找到每个位置最长的有效障碍路线

 ## 问题理解

 问题给出了一个数组`obstacles`，其中每个值代表障碍物的高度。 对于每个职位`i`，我们必须确定正好在索引处结束的最长有效障碍路线的长度`i`。 

有效的障碍训练场必须满足几个条件：

 - 我们只能使用指数中的障碍`0`通过`i`- 索引处的障碍物`i`必须包括在内
 - 障碍物必须保持原来的顺序
 - 高度必须是非递减的，这意味着下一个障碍物都大于或等于前一个障碍物

 这与经典的最长递增子序列问题非常相似，但有一个重要的区别：

 - LIS要求严格增加值
 - 这个问题允许相等的值

 这种变化会影响二分搜索条件，也是使这个问题变得棘手的核心细节。 

输出是一个数组`ans`在哪里：

-`ans[i]`等于结束于的最长非递减子序列的长度`i`限制条件很大：

 -`n`可以达到`100000`- 高度可达`10^7`一个`O(n^2)`动态规划解决方案会太慢。 我们周围需要一些东西`O(n log n)`。 

一些边缘情况很重要：

 - 具有所有相等值的数组
 - 严格递减数组
 - 严格增加数组
 - 重复值与增加和减少的段混合
 - 单元素数组

 该实现必须正确处理重复的高度，因为子序列中允许相等。 

## 方法

 ### 暴力动态规划

 一种直接的方法是使用动态规划。 

定义：```
dp[i] = length of the longest valid obstacle course ending at i
```对于每个索引`i`,检查所有之前的索引`j < i`。 

如果：```
obstacles[j] <= obstacles[i]
```然后障碍`i`可以扩展结束于的序列`j`。 

所以：```
dp[i] = max(dp[i], dp[j] + 1)
```这是有效的，因为我们明确地检查了每个有效的先前障碍。 

然而，时间复杂度为`O(n^2)`，这对于`n = 100000`。 

### 最佳二分搜索方法

 关键的见解来自最长递增子序列优化技术。 

维护一个名为的数组，而不是存储每个子序列`tails`。`tails[length - 1]`存储该长度的非递减子序列的最小可能结束值。 

这种结构允许二分搜索有效地确定当前障碍物所属的位置。 

关键的细节是我们需要一个非递减的子序列，而不是严格递增的子序列。 

因此：

 - 我们搜索第一个严格大于当前障碍的值
 - 这相当于`upper_bound`为什么？ 

因为允许相等的值来扩展序列。 

对于每个障碍：

 - 使用二分查找查找插入位置
 - 该位置加一给出了该索引的答案
 - 更新`tails`这将复杂性降低到`O(n log n)`。

 ## 算法演练

 ### 最优算法

 1. 创建一个名为的空列表`tails`。`tails[k]`将表示有效的非递减长度子序列的最小可能结束障碍物高度`k + 1`。 
2. 创建答案数组`ans`。 
3. 从左到右处理每个障碍物。 
4.获取当前障碍物高度`x`，执行二分查找`tails`。 

我们搜索第一个位置：```
tails[pos] > x
```这是上限搜索。 

我们这样做是因为子序列中允许相同的高度。 
5. 插入位置决定了在此障碍物处结束的最长有效子序列。 

如果插入位置是`pos`， 然后：```
ans[i] = pos + 1
```6. 更新`tails`。 

- 如果`pos`等于大小`tails`, 追加`x`- 否则更换`tails[pos]`和`x`替换使子序列的结束值尽可能小，从而最大化未来的扩展机会。 
7. 继续，直到处理完所有障碍。 

### 为什么它有效

 不变量是：```
tails[k] = smallest possible ending value of a valid subsequence of length k + 1
```最终值越小越好，因为它们允许更多的未来障碍来扩展子序列。 

使用上限确保相等的值可以扩展序列，这符合非递减的要求。 

由于每个障碍物都放置在其可以延伸的最长有效位置，因此计算出的长度对于每个索引都是最佳的。 

## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def longestObstacleCourseAtEachPosition(self, obstacles: List[int]) -> List[int]:
        tails = []
        answer = []

        for height in obstacles:
            position = bisect_right(tails, height)

            if position == len(tails):
                tails.append(height)
            else:
                tails[position] = height

            answer.append(position + 1)

        return answer
```该实现使用Python的内置`bisect_right`，它执行我们需要的确切上限行为。`tails`维护每个子序列长度的最小可能结束值。 

对于每个障碍：

 -`bisect_right`查找第一个大于当前高度的元素
 - 插入索引决定子序列长度
 - 我们要么追加要么替换`tails`替换值不会丢失有效的解决方案。 它通过将最终值保持在最低限度来提高未来的可能性。 

每个位置的答案都会立即记录，因为插入位置直接代表以该位置结束的最长有效子序列。 

## 解决方案```go
package main

import "sort"

func longestObstacleCourseAtEachPosition(obstacles []int) []int {
	tails := []int{}
	answer := make([]int, len(obstacles))

	for i, height := range obstacles {
		position := sort.Search(len(tails), func(j int) bool {
			return tails[j] > height
		})

		if position == len(tails) {
			tails = append(tails, height)
		} else {
			tails[position] = height
		}

		answer[i] = position + 1
	}

	return answer
}
```Go版本使用`sort.Search`实现上限行为。 

条件：```go
tails[j] > height
```找到第一个严格大于当前障碍物的值，完全匹配`bisect_right`在Python中。 

Go 中的切片动态扩展`append`，使它们适合维护`tails`。 

整数溢出不是问题，因为序列长度最多是`100000`。

 ## 边缘情况

 ### 所有元素都相等

 考虑：```
[2,2,2,2]
```一个常见的错误是在二分搜索期间使用下界而不是上限。 下界将防止相等的值扩展序列，从而产生不正确的结果。 

该实现使用`bisect_right`或上限行为，允许每个相等的值正确扩展子序列。 

### 严格递减数组

 考虑：```
[5,4,3,2,1]
```每个障碍只能形成一个长度子序列`1`。 

该算法正确替换`tails[0]`在不增加尺寸的情况下重复`tails`。 

这验证了替换逻辑是否得到正确处理。 

### 严格递增数组

 考虑：```
[1,2,3,4,5]
```每个新的障碍都会扩展当前最长的子序列。 

该算法不断追加`tails`，产生答案：```
[1,2,3,4,5]
```这验证了当扩展始终可能时，算法可以正确地增长子序列结构。
