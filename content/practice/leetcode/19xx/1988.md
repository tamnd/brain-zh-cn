 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算每所学校的**最低分数要求（截止分数）**，以便达到或超过该分数的学生人数不超过学校的容量，同时也使该数字尽可能大。 

这`Exam`表没有列出个别学生，而是提供汇总数据：对于每个分数阈值，它告诉我们有多少学生得分至少为该值。 重要的是，这是一个单调的结构：随着分数的增加，合格学生的数量减少或保持不变。 

对于每所学校，我们必须从以下分数中选择一个分数：`Exam`如果学校将该分数作为其录取门槛，则符合资格的学生人数将小于或等于其容量。 在所有这些有效分数中，我们必须选择允许**最大数量的申请人**的分数，这意味着尽可能多的分数`student_count`仍然没有超出容量。 如果多个分数产生相同的有效分数`student_count`，我们选择其中最小的分数。 

如果没有得分`Exam`表可以保证可行性（或者如果由于缺少高分信息而导致所有选择都没有受到充分的约束），我们返回`-1`。 

问题中嵌入的关键约束是`Exam`表是单调的`student_count`相对于分数，它可以实现高效搜索或线性扫描而无需重新计算。 边缘案例包括容量非常小的学校、容量小于最小容量的学校`student_count`，以及仅存在低分行的情况，使得高分行为不确定。 

## 方法

 暴力方法会尝试每所学校的每一个可能的分数。 对于每所学校，我们评估`Exam`表并检查该分数是否有效。 这是有效的，因为`Exam`表在概念约束上足够小，但是当两个表都很大时，它会变得低效，因为它会重复重新计算可行性。 

最佳方法利用排序和前缀推理。 由于较高的分数对应于较少或相等的学生人数，因此我们可以将`Exam`表作为单调决策空间。 对于每个学校的容量，我们使用线性扫描或预先计算的排序找到**最佳有效分数**，确保我们始终选择最高的可行学生计数，同时保持有效性。 这通过利用单调结构避免了对每所学校的重复扫描。

 | --- | --- | --- | --- |
 | 蛮力 | O(S × E) | O(1) | O(1) | 独立查看每所学校的每项考试成绩 |

 ## 算法演练

 我们首先排序`Exam`按分数降序排列，以便我们首先考虑更严格的要求。 这种排序确保了当我们扫描时，当我们向下移动时，我们总是会遇到更小的或相等的student_count值，从而保持单调性。 

接下来，对于每所学校，我们尝试找到最佳的有效截止点。 我们迭代排序的考试行并选择第一个分数`student_count`小于或等于学校的容量。 因为我们是从最高分向下扫描，这确保了我们最大限度地增加申请人数量，同时在有效候选人中选择尽可能小的分数。 

如果不存在这样的分数，我们返回`-1`对于那所学校。 

### 编号步骤

 1. 排序`Exam`按分数降序排列表，以便首先评估较高的阈值，从而保留贪婪选择的单调结构。 
2. 对于每所学校，将结果占位符初始化为`-1`，表示尚未找到有效分数。 
3. 迭代已排序的考试行并检查是否`student_count <= capacity`对于现在的学校。 
4. 第一次满足此条件时，记录相应的分数并停止进一步扫描，因为较早的行代表更高或相等的申请人数。 
5. 存储学校的结果并继续进行下一项。 
6. 返回所有计算结果。 

### 为什么它有效

 正确性依赖于score 和student_count 之间的单调关系。 由于较高的分数对应于较少或相等的学生，因此按分数降序扫描可保证遇到的第一个可行分数在最大化申请者的同时仍满足容量限制方面是最佳的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findScore(self, schools: List[List[int]], exam: List[List[int]]) -> List[List[int]]:
        exam_sorted = sorted(exam, key=lambda x: x[0], reverse=True)

        result = []

        for school_id, capacity in schools:
            chosen_score = -1

            for score, student_count in exam_sorted:
                if student_count <= capacity:
                    chosen_score = score
                    break

            result.append([school_id, chosen_score])

        return result
```实现首先对`Exam`表中按分数降序排列。 这确保我们首先评估更严格的阈值。 然后，对于每所学校，我们扫描已排序的考试行，并选择 Student_count 不超过学校容量的第一个分数。 由于排序，第一个有效匹配保证了最优性。 如果不存在有效分数，则默认`-1`保持不变。 

## 解决方案```go
package main

import "sort"

type Solution struct{}

func (s *Solution) FindScore(schools [][]int, exam [][]int) [][]int {
	sort.Slice(exam, func(i, j int) bool {
		return exam[i][0] > exam[j][0]
	})

	result := make([][]int, 0, len(schools))

	for _, school := range schools {
		schoolID := school[0]
		capacity := school[1]

		chosen := -1

		for _, e := range exam {
			score := e[0]
			count := e[1]

			if count <= capacity {
				chosen = score
				break
			}
		}

		result = append(result, []int{schoolID, chosen})
	}

	return result
}
```在 Go 中，我们明确使用`sort.Slice`按分数降序排列考试行。 使用切片而不是数组，因为输入大小是动态的。 逻辑与 Python 版本完全一致。 整数溢出不是问题，因为所有值都在典型的数据库整数范围内。 我们还显式地构建结果切片`append`，这是 Go 中的惯用语。

 ## 边缘情况

 一个重要的边缘情况是当一所学校的容量小于最小容量时`student_count`在`Exam`桌子。 在这种情况下，没有分数可以满足约束，正确的输出是`-1`。 该实现自然地处理这个问题，因为扫描永远不会找到有效的行。 

当所有考试行对学校都有效时，就会出现另一种边缘情况，这意味着即使是最严格的分数，产生的学生也少于容量。 在这种情况下，我们必须确保选择使 Student_count 最大化的分数，而不一定是最高分数。 这是通过正确优先考虑可行性的排序和选择逻辑来处理的。 

第三个边缘情况涉及关系`student_count`跨越不同的分数。 由于多个分数可能对应相同数量的申请人，因此我们必须确保选择其中最小的分数。 这是通过按排序顺序迭代来处理的，并且仅在找到严格更好的候选者时才更新。 

最后的边缘情况是数据集在高分覆盖范围内稀疏。 尽管该表是单调的，但缺少极值可能会使推理不完整。 该算法通过严格依赖仅提供的行并返回来确保安全`-1`当无法保证有效映射时。
