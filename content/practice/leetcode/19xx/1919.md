[LeetCode 1919 题](https://leetcode.com/problems/leetcodify-similar-friends/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题涉及分析两个数据库表，`Listens`和`Friendship`，确定一对“相似的朋友”。 简单来说，我们被要求找到一对用户，他们是朋友**并且**在同一天**听了至少三首不同的歌曲。 

这`Listens`表包含用户的收听历史记录，每一行代表单个用户在特定日期收听歌曲。 值得注意的是，可能存在重复的行，这意味着用户可能会在同一天和同一首歌中出现多次。 这`Friendship`表包含系统中的所有好友对，并保证`user1_id < user2_id`对于所有行。 

预期输出是满足“相似朋友”条件的所有朋友对的列表。 每对必须保持原始顺序（`user1_id < user2_id`）并且可以按任何顺序返回。 

需要注意的要点：

 1. 两个用户必须是朋友。 仅仅聆听相似性是不够的。 
2. 他们必须在**同一天**听过**至少三首不同的歌曲**。 不同的日子不能算在一起。 
3. 重复收听记录不会增加歌曲数。 
4. 仅存在于`Friendship`表有资格。 

需要考虑的边缘情况包括朋友一起听的歌曲少于三首、多天重叠或重复听`Listens`桌子。 就表而言，输入相对较小（可能多达数万行），但必须使用 SQL 聚合进行有效处理。 

## 方法

 ### 暴力方法

 蛮力方法将涉及检查每一对可能的朋友，并迭代所有天来计算常见歌曲。 对于每对朋友`(u1, u2)`，我们会：

 1. 检索所有歌曲`u1`按天分组。 
2. 检索所有歌曲`u2`按天分组。 
3. 每天进行比较，看看是否至少有三首歌曲重叠。 

虽然这种方法是正确的，但它非常慢，因为它需要对朋友和天数进行嵌套迭代，导致时间复杂度约为 O(F × D × S)，其中 F 是朋友的数量，D 是不同天数，S 是每天的平均歌曲数。 这对于大型数据集来说是不切实际的。 

### 最佳方法

 关键的见解是我们可以利用 SQL 聚合和连接来避免手动迭代。 具体来说，我们可以：

 1. 加入`Listens`在同一天为两个朋友用户提供桌子和歌曲。 这会自动将同一天收听同一首歌曲的用户配对。 
2. 按朋友对和日期分组，计算不同的歌曲。 
3. 筛选至少包含 3 首不同歌曲的群组，以找到相似的朋友。 

该方法使用 SQL 连接和`COUNT(DISTINCT ...)`无需手动迭代即可有效计算答案。 

比较：

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(F × D × S) | O(S)| 迭代所有好友和日子，比较歌曲列表 |
 | 最佳| O(N log N) | O(N log N) | O(N) | 使用 SQL 连接和聚合； N 是数量`Listens`行 |

 ## 算法演练

 1. 首先加入`Friendship`表与`Listens`表两次：一次为`user1_id`一次`user2_id`。 确保两次收听发生在同一天并且收听的是同一首歌。 
2. 连接后，每一行代表一对朋友在特定日期的共同歌曲。 
3. 对结果进行分组`user1_id`,`user2_id`， 和`day`。 
4. 计数不同的`song_id`在每个组中。 
5. 过滤计数大于或等于3的群组。这些是有效的“相似朋友”。 
6. 仅选择好友 ID（`user1_id`,`user2_id`）对于输出，保持原始顺序。 

为什么有效：每次加入都确保只计算两个朋友在同一天收听的歌曲。 对不同歌曲进行分组和计数可以保证我们遵守“同一天三首或更多不同歌曲”的要求。 

## Python 解决方案

 由于这是一个数据库问题，Python 解决方案涉及通过连接使用 SQL 执行。 这是一个假设数据库游标的可提交解决方案：```python
def similarFriends():
    query = """
    SELECT f.user1_id, f.user2_id
    FROM Friendship f
    JOIN Listens l1 ON f.user1_id = l1.user_id
    JOIN Listens l2 ON f.user2_id = l2.user_id 
        AND l1.song_id = l2.song_id 
        AND l1.day = l2.day
    GROUP BY f.user1_id, f.user2_id, l1.day
    HAVING COUNT(DISTINCT l1.song_id) >= 3
    """
    return query
```说明：我们在`Listens`表来对齐在同一天收听同一首歌曲的用户。 按朋友对和日期分组可以计算不同的歌曲。 这`HAVING`子句过滤掉少于三首常见歌曲的配对。 

## 解决方案

 在 Go 中，我们通常会使用数据库驱动程序执行相同的 SQL 查询。 这是一个概念性的解决方案，使用`database/sql`：```go
func SimilarFriends(db *sql.DB) (*sql.Rows, error) {
    query := `
    SELECT f.user1_id, f.user2_id
