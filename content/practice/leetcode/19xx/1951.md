[LeetCode 1951 题](https://leetcode.com/problems/all-the-pairs-with-the-maximum-number-of-common-followers/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个名为的关系表`Relations`，其中每一行表示有向跟随关系：由以下标识的用户`follower_id`关注另一个由以下标识的用户`user_id`。 换句话说，每个`user_id`拥有一组关注者，同一个关注者可以关注多个用户。 

任务是找到所有不同用户对`(user1_id, user2_id)`这样他们在所有可能的用户对中共享最大数量的共同关注者。 共同关注者是同时关注两者的用户`user1_id`和`user2_id`。 输出必须仅包含对，其中`user1_id < user2_id`以避免重复和颠倒对。 

输入规模没有明确说明，但由于这是 LeetCode 中型数据库问题，我们通常假设最多有几千行。 这强烈表明，对所有用户对进行简单的二次比较在 SQL 引擎中可能仍然可接受，但在应用程序级逻辑中效率低下。 

关键边缘情况包括用户根本没有关注者的情况、多个对共享相同最大重叠的情况以及仅存在单个对的情况。 另一个微妙的边缘情况是当所有用户都具有不相交的追随者集时，在这种情况下，每对都有零个公共追随者，并且必须返回所有绑定为零的对。 

## 方法

 暴力方法是首先计算每个用户的关注者集，然后通过计算关注者集的交集来比较每个可能的用户对。 虽然这在概念上很简单并且保证了正确性，但计算成本很高，因为每对都会重复交集运算。 

最佳方法是扭转观点。 我们不是成对地比较用户，而是按关注者进行分组。 对于每个关注者，我们会考虑他们关注的所有用户，并生成该组内的所有用户对。 每个这样的对都共享该追随者，因此我们为该对增加一个计数器。 处理完所有关注者后，我们只需找到最大计数并返回与其匹配的所有对。 这避免了冗余的集合交集计算并显着降低了复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(U² × F) | O(U × F) | 使用集合交集比较每对用户 |
 | 最佳 | O(F × K²) | O(P)| 构建每个关注者的配对计数，其中 K 是每个用户的平均关注者，P 是活跃对的数量 |

 ## 算法演练

 最佳解决方案基于通过为每个关注者生成用户对来间接计算共享关注者。 

1. 首先，我们构建从每个用户到他们拥有的关注者集的映射。 此步骤重新组织数据，以便我们可以有效地推断哪些用户通过共享关注者进行连接。 
2. 一旦我们有了这个映射，我们就会迭代每个关注者的关注用户列表。 对于每个关注者，我们检索该关注者关注的所有用户。 
3. 对于每个关注者的用户列表，我们生成所有可能的唯一对`(u1, u2)`在哪里`u1 < u2`。 每对代表共享该关注者的两个用户。 
4. 我们维护一个名为的哈希图（字典）`pair_count`其中键是一个元组`(u1, u2)`该值是他们之间共享的关注者数量。 每次我们遇到关注者组中的一对时，我们都会增加其计数。 
5. 处理完所有关注者后，我们扫描`pair_count`映射以确定在所有对中观察到的共享关注者的最大数量。 
6. 最后，我们收集计数等于该最大值的所有对，并根据需要按排序或以任何顺序返回它们。 

我们强制执行的原因`u1 < u2`在配对生成期间是为了确保唯一性并避免计数`(u2, u1)`分开，这会扭曲结果。 

### 为什么它有效

 正确性依赖于每个普通关注者对其连接的每个用户对的计数仅贡献一次的不变性。 因此，在处理完所有追随者之后，任何对的计数器`(u1, u2)`正好等于他们之间共享追随者的数量，保证选择最大值会产生正确的答案集。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def usersWithMostCommonFollowers(self, relations: List[List[int]]) -> List[List[int]]:
        user_to_followers = defaultdict(set)

        for user_id, follower_id in relations:
            user_to_followers[user_id].add(follower_id)

        pair_count = defaultdict(int)

        users = list(user_to_followers.keys())
        n = len(users)

        for i in range(n):
            for j in range(i + 1, n):
                u1, u2 = users[i], users[j]

                common = user_to_followers[u1] & user_to_followers[u2]
                if common:
                    pair_count[(u1, u2)] = len(common)

        if not pair_count:
            return []

        max_common = max(pair_count.values())

        result = []
        for (u1, u2), cnt in pair_count.items():
            if cnt == max_common:
                result.append([u1, u2])

        return result
```该实现首先构建一个字典，将每个用户映射到他们的关注者集。 然后，它迭代所有用户对并计算集合交集以确定共享关注者。 存储每对的交集大小，最后提取最大值来过滤结果。 

这是一个简单但不太理想的解决方案，因为它会重复重新计算交叉点。 

## 解决方案```go
package main

type pair struct {
	u1 int
	u2 int
}

func findAllPairsWithMaxCommonFollowers(relations [][]int) [][]int {
	userToFollowers := make(map[int]map[int]bool)

	for _, r := range relations {
		user := r[0]
		follower := r[1]

		if userToFollowers[user] == nil {
			userToFollowers[user] = make(map[int]bool)
		}
		userToFollowers[user][follower] = true
	}

	users := make([]int, 0, len(userToFollowers))
	for u := range userToFollowers {
		users = append(users, u)
	}

	pairCount := make(map[pair]int)

	for i := 0; i < len(users); i++ {
		for j := i + 1; j < len(users); j++ {
			u1 := users[i]
			u2 := users[j]

			count := 0
			for f := range userToFollowers[u1] {
				if userToFollowers[u2][f] {
					count++
				}
			}

			if count > 0 {
				pairCount[pair{u1, u2}] = count
			}
		}
	}

	maxCommon := 0
	for _, c := range pairCount {
		if c > maxCommon {
			maxCommon = c
		}
	}

	result := make([][]int, 0)
	for p, c := range pairCount {
		if c == maxCommon {
			result = append(result, []int{p.u1, p.u2})
		}
	}

	return result
}
```在 Go 中，我们使用地图的地图来表示追随者集合。 由于 Go 没有内置的集合类型，`map[int]bool`被使用。 使用结构键来处理对计数。 通过迭代一组并检查另一组中的成员资格来手动计算交集。 

## 工作示例

 使用示例输入：

 关系：

 (1,3)、(2,3)、(7,3)、(1,4)、(2,4)、(7,4)、(1,5)、(2,6)、(7,5)

 首先我们建立关注者集：

 用户 1 → {3,4,5}

 用户 2 → {3,4,6}

 用户 7 → {3,4,5}

 现在计算两两交集：

 对 (1,2)：{3,4} → 2

 对 (1,7)：{3,4,5} → 3

 对 (2,7)：{3,4} → 2

 我们跟踪pair_count：

 | 配对 | 普通追随者 |
 | --- | --- |
 | (1,2) | 2 |
 | (1,7) | 3 |
 | (2,7) | 2 |

 最大值为 3，因此仅返回 (1,7)。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|

 复杂性主要由用户关注者集的成对比较决定。 在最坏的情况下，每个交集运算可能需要花费 O(F)。

 ## 边缘情况

 一种重要的边缘情况是只有一个用户或只有一个关系。 在这种情况下，不存在有效的对，因此该函数必须返回一个没有错误的空结果。 这是通过在计算最大值之前检查是否生成了任何对计数来处理的。 

当所有用户都有完全不相交的关注者集时，会出现另一种边缘情况。 在这种情况下，每对都有零个共同追随者。 根据解释，正确的输出是所有对都连接为零，但许多实现错误地返回空列表，因为它们只跟踪正计数。 正确的实现必须根据是否存在任何对来决定是否包含零计数对。 

第三种边缘情况涉及大型重叠组，其中许多用户共享相同的关注者。 没有仔细使用配对生成`u1 < u2`，会发生重复的对计数，导致结果夸大和最大值不正确。 排序约束确保共享追随者计数的确定性和正确聚合。
