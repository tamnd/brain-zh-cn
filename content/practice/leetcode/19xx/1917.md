[LeetCode 1917 题](https://leetcode.com/problems/leetcodify-friends-recommendations/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题需要根据Leetcodify平台上用户的收听习惯为用户生成好友推荐。 我们有两张表：`Listens`和`Friendship`。 这`Listens`表记录用户在特定日期收听特定歌曲的情况，并且可能包含重复项。 这`Friendship`表列出了所有已经是朋友的用户对。 

目标是推荐用户`x`给用户`y`如果他们**还不是朋友**并且他们**在同一天听过三首或更多相同的歌曲**。 建议是**单向的**，这意味着如果用户`x`推荐给用户`y`, it does not automatically imply the reverse unless the condition also holds in the other direction. The output should be a list of recommendations with no duplicates.

 关键点包括：比较是**特定于日期的**，仅计算当天唯一的歌曲，并且友谊对是对称的，但存储为`user1_id < user2_id`。 边缘情况包括用户在不同的日子听相同的歌曲，重复的条目`Listens`，以及没有重叠歌曲的用户。 

考虑到典型的 LeetCode 数据库问题，规模是中到大的，因此每天比较每对用户的简单解决方案可能太慢了。 

## 方法

 **暴力方法**将涉及加入`Listens`桌子本身在`day`和`song_id`查找在同一天听同一首歌的所有用户对。 然后，我们将按用户对进行分组，并对不同的歌曲进行计数，看看它们是否满足三首的阈值。 最后，我们会过滤掉已经是朋友的配对。 虽然正确，但这种方法涉及许多自连接，并且对于大型数据集可能会变得非常慢，因为它会检查用户和歌曲的每种组合。 

**最佳方法**依赖于我们可以首先聚合的关键洞察，计算每个用户对每天共享的歌曲数量。 通过按天和用户对进行分组，我们将问题从二次组合减少到仅那些实际收听相同歌曲的组合。 在识别出具有三首或更多共享歌曲的对后，我们执行左连接`Friendship`表以排除现有好友。 最后，我们生成单向推荐。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N^2 * M) | O(N^2 * M) | O(N^2) | O(N^2) | 加入`Listens`每个用户对都有其自身； N = 用户，M = 每天歌曲 |
 | 最佳| O(N * M + F) | O(N^2) | O(N^2) | 每天聚合分享歌曲，过滤≥3，则排除好友； F = 好友数量 |

 ## 算法演练

 1. **友谊正常化**：转换`Friendship`将两个方向都存在的表成对（以便于排除）。 这确保了`user1_id -> user2_id`和`user2_id -> user1_id`可以过滤。 
2. **生成同一天听同一首歌的用户对**：加入`Listens`桌子本身在`day`和`song_id`，确保`user_id`第一个表与第二个表不同（`user_id_1 != user_id_2`）。 这为所有每天至少共享一首歌曲的用户对提供了机会。 
3. **计算每天每个用户对共享的歌曲**：分组依据`user1_id`,`user2_id`， 和`day`，然后计算不同的`song_id`s。 仅保留与`count >= 3`。 
4. **排除现有的友谊**：将结果与规范化的友谊表进行左连接。 仅保留友谊表中不存在的对。 这为非好友用户对提供了足够的歌曲重叠。 
5. **生成单向建议**：将两个方向上的每个有效对输出为单独的行。 这确保了推荐是单向的。 
6. **返回结果**：如有必要，删除任何重复项并返回`user_id`和`recommended_id`。 

这是有效的，因为分组确保只考虑在同一天至少共享三首歌曲的用户。 过滤掉现有的好友可以保证我们只推荐非好友。 

## Python 解决方案```python
import pandas as pd

def recommend_friends(listens: pd.DataFrame, friendship: pd.DataFrame) -> pd.DataFrame:
    # Step 1: Self-join listens to get user pairs listening to the same song on the same day
    merged = listens.merge(
        listens,
        on=['day', 'song_id'],
        suffixes=('_1', '_2')
    )
    merged = merged[merged['user_id_1'] < merged['user_id_2']]

    # Step 2: Count distinct shared songs per day per user pair
    shared_counts = merged.groupby(['user_id_1', 'user_id_2', 'day'])['song_id'].nunique().reset_index()
    shared_counts = shared_counts[shared_counts['song_id'] >= 3]

    # Step 3: Remove existing friendships
    # Normalize friendship for easy lookup
    friendships = pd.concat([
        friendship.rename(columns={'user1_id':'user_id_1','user2_id':'user_id_2'}),
        friendship.rename(columns={'user1_id':'user_id_2','user2_id':'user_id_1'})
    ])
    shared_counts = shared_counts.merge(
        friendships,
        on=['user_id_1', 'user_id_2'],
        how='left',
        indicator=True
    )
    shared_counts = shared_counts[shared_counts['_merge'] == 'left_only']

    # Step 4: Generate unidirectional recommendations
    recommendations = pd.concat([
        shared_counts[['user_id_1','user_id_2']].rename(columns={'user_id_1':'user_id','user_id_2':'recommended_id'}),
        shared_counts[['user_id_2','user_id_1']].rename(columns={'user_id_2':'user_id','user_id_1':'recommended_id'})
    ]).drop_duplicates().reset_index(drop=True)

    return recommendations
```该代码合并了`Listens`表与自身查找在同一天共享歌曲的配对，计算每天不同的歌曲，过滤掉现有的朋友，然后通过连接每对的两个方向来生成单向推荐。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
)

func recommendFriends(db *sql.DB) (*sql.Rows, error) {
    query := `
    WITH user_pairs AS (
        SELECT l1.user_id AS user_id_1, l2.user_id AS user_id_2, l1.day
        FROM Listens l1
        JOIN Listens l2 ON l1.day = l2.day AND l1.song_id = l2.song_id
        WHERE l1.user_id < l2.user_id
    ),
    shared_songs AS (
        SELECT user_id_1, user_id_2
        FROM user_pairs
        GROUP BY user_id_1, user_id_2, day
        HAVING COUNT(DISTINCT song_id) >= 3
    ),
    filtered_pairs AS (
        SELECT ss.user_id_1, ss.user_id_2
        FROM shared_songs ss
        LEFT JOIN (
            SELECT user1_id AS u1, user2_id AS u2 FROM Friendship
            UNION
            SELECT user2_id AS u1, user1_id AS u2 FROM Friendship
        ) f ON ss.user_id_1 = f.u1 AND ss.user_id_2 = f.u2
        WHERE f.u1 IS NULL
    )
    SELECT user_id_1 AS user_id, user_id_2 AS recommended_id FROM filtered_pairs
    UNION
    SELECT user_id_2 AS user_id, user_id_1 AS recommended_id FROM filtered_pairs;
    `
    return db.Query(query)
}
```Go 解决方案使用单个 SQL 查询来有效地处理所有事情。 与 Python 的区别包括完全依赖 SQL 并使用`UNION`产生单向建议。 Go 函数返回一个`*sql.Rows`可以迭代以检索结果。
