[LeetCode 问题 1909](https://leetcode.com/problems/remove-one-element-to-make-the-array-strictly-increasing/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题给了我们一个 0 索引的整数数组`nums`并询问是否可以在恰好删除一个元素后使数组严格递增。 严格递增数组意味着每个元素都必须大于前一个元素。 形式上，对于每个有效索引`i`，条件`nums[i - 1] < nums[i]`必须持有。 

重要的细节是我们只能删除一个元素。 如果数组已经严格递增，答案仍然是`true`因为我们可以删除任何单个元素，而剩余的序列将保持严格递增。 

输入是一个整数数组，长度介于`2`和`1000`。 由于约束相当小，即使是二次解在技术上也是可行的，但问题的目的是测试我们是否可以有效地推理递增顺序的违规行为。 

预期输出是一个布尔值：

 - 返回`true`如果删除一个元素可以产生一个严格递增的数组。 
- 返回`false`否则。 

尽早识别几个边缘情况很重要：

 - 已经严格递增的数组。 
- 具有重复值的数组，因为相等的相邻值违反了严格的递增顺序。 
- 具有多个违规的数组，因为一次删除可能还不够。 
- 数组开头或结尾附近的违规，此时边界检查变得很重要。 
- 非常短的数组，尤其是长度`2`，因为删除一个元素总是会留下一个微不足道的递增数组。 

例如：

-`[1,2,10,5,7]`通过移除而变得增加`10`。 
-`[2,3,1,2]`无法通过一次移除来修复。 
-`[1,1,1]`删除后仍然包含重复项。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试一一删除所有可能的元素。 对于每次删除：

 1. 创建一个不包含该元素的新数组。 
2. 检查结果数组是否严格递增。 
3. 如果任何删除有效，请返回`true`。 

这种方法是正确的，因为它明确地测试了每种有效的删除可能性。 由于问题询问至少一次删除是否可以产生严格递增的数组，因此详尽的检查可以保证正确性。 

然而，这种方法效率低下，因为对于每个索引，我们可能需要再次扫描整个剩余数组。 如果数组有长度`n`，我们执行`n`检查，每项成本`O(n)`， 导致`O(n^2)`时间复杂度。 

虽然`n <= 1000`小到足以让这个通过，我们可以做得更好。 

### 最佳方法

 关键的见解是，如果可以通过删除单个元素来修复严格递增数组，则该数组最多可以包含一个违规。 

当出现以下情况时，就会发生违规：```
nums[i] >= nums[i + 1]
```当我们遇到这样的违规行为时，我们只有两种可能的修复方法：

 - 删除`nums[i]`- 消除`nums[i + 1]`我们不需要实际从数组中删除元素。 相反，我们可以通过检查跳过两个元素之一是否保留递增属性来模拟决策。 

如果我们遇到不止一次违规，那么一次删除是不够的，所以我们立即返回`false`。 

这一观察结果使我们能够一次性解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 尝试删除每个元素并验证结果 |
 | 最佳| O(n) | O(1) | O(1) | 统计违规行为并确定一次删除是否可以解决这些问题 |

 ## 算法演练

 1. 初始化一个名为`violations`跟踪递增顺序被破坏的次数。 
2. 从索引处开始从左到右遍历数组`1`。 
3. 对于每个索引`i`， 比较`nums[i - 1]`和`nums[i]`。 
4.如果`nums[i - 1] < nums[i]`，序列在这个位置仍然是严格递增的，所以继续。 
5. 否则，我们发现违规，因为前一个元素大于或等于当前元素。 
6. 增加`violations`柜台。 如果计数器变得大于`1`，立即返回`false`因为仅删除一个元素无法修复多个违规行为。 
7. 当发现违规时，确定是否可以修复：

 - 如果`i == 1`，我们总是可以删除第一个元素。 
- 如果`i == len(nums) - 1`，我们总是可以删除最后一个元素。 
- 否则，检查这两种可能性：

 - 删除`nums[i - 1]`，如果满足以下条件则有效：```
nums[i - 2] < nums[i]
```- 消除`nums[i]`，如果满足以下条件则有效：```
nums[i - 1] < nums[i + 1]
```8. 如果两个删除选项均不起作用，则返回`false`。 
9. 如果遍历成功完成，则返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为严格递增序列中的每个违规都必须通过删除涉及违规的两个元素之一来解决。 没有其他的可能性。 通过检查任一局部删除是否保留递增属性，我们保证剩余序列仍然有效。 由于我们只允许一次移除，因此超过一次违规行为会立即导致任务无法完成。 

## Python 解决方案```python
from typing import List

class Solution:
    def canBeIncreasing(self, nums: List[int]) -> bool:
        violations = 0
        n = len(nums)

        for i in range(1, n):
            if nums[i - 1] >= nums[i]:
                violations += 1

                if violations > 1:
                    return False

                remove_previous = (
                    i == 1 or nums[i - 2] < nums[i]
                )

                remove_current = (
                    i == n - 1 or nums[i - 1] < nums[i + 1]
                )

                if not remove_previous and not remove_current:
                    return False

        return True
```该实现遵循算法演练中描述的确切逻辑。 

变量`violations`跟踪我们在扫描数组时遇到的排序问题的数量。 遍历过程中，每当`nums[i - 1] >= nums[i]`，我们知道严格增加的属性已被侵犯。 

然后，代码检查删除前一个元素或当前元素是否可以在本地修复序列。 条件：```python
nums[i - 2] < nums[i]
```测试删除前一个元素是否保持递增顺序。 

条件：```python
nums[i - 1] < nums[i + 1]
```测试删除当前元素是否保持递增顺序。 

谨慎处理边界情况：

 - 如果违规发生在开头，则删除第一个元素始终有效。 
- 如果违规发生在末尾，则删除最后一个元素始终有效。 

如果两个选项都不起作用，则该函数立即返回`False`。 

如果循环完成时未发现多个不可修复的违规，则该函数返回`True`。 

## 解决方案```go
func canBeIncreasing(nums []int) bool {
    violations := 0
    n := len(nums)

    for i := 1; i < n; i++ {
        if nums[i-1] >= nums[i] {
            violations++

            if violations > 1 {
                return false
            }

            removePrevious := i == 1 || nums[i-2] < nums[i]
            removeCurrent := i == n-1 || nums[i-1] < nums[i+1]

            if !removePrevious && !removeCurrent {
                return false
            }
        }
    }

    return true
}
```Go 的实现与 Python 解决方案非常相似。 由于 Go 没有 Python 风格的负索引，因此在访问相邻元素之前必须显式执行边界检查。 

Go 中的切片本质上是对数组的动态引用，因此不需要额外的复制。 整数溢出不是问题，因为约束非常小。

 ## 边缘情况

 一种重要的边缘情况是数组已经严格递增。 幼稚的实现可能会错误地假设必须存在一个有问题的元素。 然而，问题明确指出已经增加的数组应该返回`true`。 我们的实现自然会处理这个问题，因为在遍历过程中没有检测到违规行为。 

另一个重要的边缘情况涉及重复值，例如`[1,2,2,3]`。 由于条件要求严格的升序，所以相邻元素相等是无效的。 一些实现错误地使用`>`而不是`>=`当发现违规行为时。 我们的解决方案可以正确地将重复项识别为违规，因为它会检查：```
nums[i - 1] >= nums[i]
```侵犯边界也很棘手。 考虑`[10,1,2,3]`或者`[1,2,3,0]`。 在这些情况下，可移动元素位于数组的开头或结尾。 不小心访问邻居可能会导致索引错误。 我们的实现通过显式检查安全地处理这个问题：```
i == 1
```和```
i == n - 1
```这些条件保证了正确评估边缘去除，而不会出现无效索引。
