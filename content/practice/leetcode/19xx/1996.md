[LeetCode 1996 题](https://leetcode.com/problems/the-number-of-weak-characters-in-the-game/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、贪婪、排序、单调堆栈

 ## 解决方案

 ## 问题理解

 在这个问题中，游戏中的每个角色都有两个属性：

 -`attack`-`defense`输入是一个二维数组，称为`properties`， 在哪里：```
properties[i] = [attacki, defensei]
```代表统计数据`i-th`特点。 

如果存在另一个具有以下特征的字符，则该字符被视为**弱**：

 - 严格更大的攻击
 - 严格加强防御

 两个条件必须同时成立。 

例如：```
A = [2, 3]
B = [5, 4]
```特点`A`是弱的，因为：```
5 > 2
4 > 3
```攻击和防御都严格更大。 

然而：```
A = [2, 5]
B = [5, 4]
```并不弱，因为攻击虽然大，但防御却并不弱。 

目标是计算有多少角色较弱。 

约束条件很重要：```
2 <= properties.length <= 100000
```这意味着我们可能需要处理多达十万个字符。 比较每对字符的二次解需要：```
O(n^2)
```操作，对于大量输入来说变得太慢。 

攻击和防御的值也可以大到`100000`，但这主要影响存储，而不是算法选择。 

一些边缘情况很重要：

 - 多个角色可以具有相同的攻击值。 
- 多个角色可以具有相同的防御值。 
- 只有当另一个角色的两个属性值都严格更大时，该角色才会变弱。 
- 攻击值相等的角色不能错误地认为对方是弱者。 
- 排序顺序对于正确性变得极其重要。 

例如：```
[[5,5], [5,6]]
```两个角色都不弱，因为尽管其中一个防御力更大，但攻击值相同。 

正确处理相等的攻击值是该问题的核心挑战。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将每个角色与其他每个角色进行比较。 

对于每个角色`i`，我们扫描所有其他字符`j`并检查：```
attackj > attacki AND defensej > defensei
```如果存在这样的字符，则字符`i`很弱。 

这种方法是正确的，因为它明确地检查问题陈述中每对字符的确切条件。 

但时间复杂度太大。 

如果有`n`角色，我们大致执行：```
n * n
```比较。 

和`n = 100000`，这大约变为：```
10^10
```的操作，远远超出了可接受的范围。 

### 最优贪心+排序方法

 关键的观察是，在对角色进行正确排序后，我们可以一次性处理它们，同时跟踪迄今为止看到的最大防御。 

关键细节是我们如何排序：

 - 按攻击降序排列
 - 如果攻击值相等，则按防御升序排列

 为什么这有帮助？ 

当我们排序后从左到右处理字符时：

 - 每个先前看到的角色的攻击力都大于或等于当前的攻击力。 
- 由于相同的攻击值是按防御力升序排列的，因此具有相同攻击力的角色不会错误地将彼此标记为弱。 

在迭代过程中，我们保持：```
max_defense_seen
```如果当前角色的防御力小于`max_defense_seen`，那么我们已经遇到了一个字符：

 - 严格更大的攻击
 - 更大的防御

 所以，现在的性格是弱的。 

这在排序后将问题转化为单个线性扫描。

 ## 算法演练

 1. 对字符进行排序：

 - 攻击按降序排列
 - 当攻击相等时，防御按升序排列

 这个顺序是必要的。 

降序攻击确保先前处理的字符始终具有大于或等于当前字符的攻击。 

相同攻击的防御力提升可以防止具有相同攻击的角色被错误地视为弱者。 
2.初始化：

 -`max_defense = 0`-`weak_count = 0`

`max_defense`追踪迄今为止攻击力较高的角色中遇到的最高防御值。 
3. 从左到右迭代排序后的数组。 
4. 对于每个字符：

 - 如果其防御力小于`max_defense`，则性格较弱。 
- 增量`weak_count`。 
5. 否则，更新：```
max_defense = current_defense
```因为这个防御是目前为止见过的最大的。 
6. 继续，直到处理完所有字符。 
7. 返回`weak_count`。 

### 为什么它有效

 排序后，每个先前处理的字符的攻击力都大于或等于当前字符。 

对于攻击力相等的角色，按防御升序排序可以保证攻击力相等的角色不会错误地将另一个角色标记为弱。 同等攻击中更大的防御出现得更晚，而不是更早。 

因此，如果当前防御力小于目前看到的最大防御力，则对应的早期角色必须具有：

 - 严格更大的攻击
 - 严格的更大防守

 这完全符合弱角色的定义。 

## Python 解决方案```python
from typing import List

class Solution:
    def numberOfWeakCharacters(self, properties: List[List[int]]) -> int:
        properties.sort(key=lambda p: (-p[0], p[1]))

        max_defense = 0
        weak_count = 0

        for attack, defense in properties:
            if defense < max_defense:
                weak_count += 1
            else:
                max_defense = defense

        return weak_count
```实现首先使用自定义键对数组进行排序。```python
key=lambda p: (-p[0], p[1])
```这意味着：

 - 更高的攻击优先
 - 同等攻击力下防御优先

 这种排序顺序是算法正确性的基础。 

排序后，算法扫描数组一次。`max_defense`存储先前处理的字符中遇到的最大防御。 

对于每个字符：```python
if defense < max_defense:
```我们知道一个更强的角色已经存在，所以这个角色是弱的。 

否则，我们更新：```python
max_defense = defense
```因为这成为迄今为止看到的新的最强防御。 

该算法在排序后只需要一次遍历，对于问题约束来说足够高效。 

## 解决方案```go
package main

import "sort"

func numberOfWeakCharacters(properties [][]int) int {
    sort.Slice(properties, func(i, j int) bool {
        if properties[i][0] == properties[j][0] {
            return properties[i][1] < properties[j][1]
        }
        return properties[i][0] > properties[j][0]
    })

    maxDefense := 0
    weakCount := 0

    for _, character := range properties {
        defense := character[1]

        if defense < maxDefense {
            weakCount++
        } else {
            maxDefense = defense
        }
    }

    return weakCount
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于排序语法。 Go 使用：```go
sort.Slice()
```具有自定义比较器功能。 

Go 切片是引用类型，因此排序会直接修改原始输入，类似于 Python 的就地排序。 

不存在整数溢出问题，因为这些值完全在 Go 的整数范围内。 

除了输入数组之外，该算法仅使用几个整数变量。

 ## 边缘情况

 当多个角色具有相同的攻击值时，会出现一种重要的边缘情况。 

例如：```
[[5,5],[5,6]]
```即使一个角色的防御力较高，但由于攻击值相等，所以两个角色都不弱。 天真的排序顺序可能会错误地将一个视为弱。 按防御升序对同等攻击进行排序可以防止此问题，因为同等攻击角色永远不会错误地主导较早的攻击角色。 

另一个重要的情况是防御值降低而攻击值增加。 

例子：```
[[1,5],[2,4],[3,3],[4,2]]
```每个角色的攻击力都比前一个角色更强，但防御力却较弱。 没有一个角色能够同时满足这两个严格的不等式。 该算法可以正确处理这个问题，因为`max_defense`永远不会以产生误报的方式超过早期的大防御值。 

第三种边缘情况涉及重复字符。 

例子：```
[[2,2],[2,2],[2,2]]
```所有字符都是相同的。 由于进攻和防守都需要严格的不平等，所以没有一个是弱的。 排序和比较逻辑自然地保留了这种行为，因为没有防御变得严格小于`max_defense`以获得更强的攻击值。 

最后一个重要的边缘情况是几乎每个角色都很弱。 

例子：```
[[1,1],[2,2],[3,3],[4,4]]
```除了最强的角色之外，每个角色都很弱。 这验证了算法正确累积了迄今为止看到的最大防御并正确识别了所有主导角色。
