[LeetCode 1900 题](https://leetcode.com/problems/the-earliest-and-latest-rounds-where-players-compete/)

 **难度：** 🔴难
 **主题：** 动态规划、记忆化

 ## 解决方案

 ## 问题理解

 比赛以淘汰赛的形式进行。 每轮比赛中，选手从当前阵容的两端对称配对。 第一个玩家面对最后一个玩家，第二个玩家面对倒数第二个玩家，依此类推。 如果玩家人数为奇数，则中间玩家自动晋级，不玩。 

重要的细节是，每轮结束后，幸存的玩家都会按照原来的编号重新排序。 这意味着锦标赛状态完全取决于玩家的生存，而不是比赛的进行顺序。 

这两位特殊的球员，`firstPlayer`和`secondPlayer`，比其他人都强。 他们在面对面之前永远不会输给其他玩家。 其他每场比赛的结果都是灵活的，这意味着我们可以自由选择有助于产生最早或最晚可能的比赛轮次的获胜者。 

任务是计算两个值：

 - 两位特殊玩家最早见面的回合
 - 他们可以见面的最新一轮

 约束足够小以允许基于状态的动态编程：

 -`2 <= n <= 28`- 只有两名球员被固定为不可战胜
 - 所有其他比赛都可以有任意获胜者

 小上限为`n`强烈表明压缩状态的记忆是可行的。 然而，暴力破解每个锦标赛结果仍然太大，因为可能的锦标赛分支的数量呈指数级增长。 

一些边缘情况很重要：

 - 两名选手可能已经在第一轮中相遇
 - 一名或两名球员可能会在奇数轮中轮空
 - 不同的幸存者选择可以极大地改变未来的位置
 - 可以通过多种路径达到相同的逻辑锦标赛状态，这使得记忆变得至关重要

 ## 方法

 ### 蛮力

 暴力解决方案将逐轮模拟所有可能的锦标赛结果。 

每轮：

 - 确定所有配对
 - 力量`firstPlayer`和`secondPlayer`赢得比赛
 - 对于每场其他比赛，分为两种可能性
 - 递归到下一轮配置

 最终，一个分支将产生每一轮可能的会议。 

这种方法是正确的，因为它明确列举了每一个合法锦标赛的演变。 然而，这在计算上是不可行的。 每场非特殊比赛都会使状态数量加倍，从而产生指数爆炸。 

即使对于中等值`n`，比赛结果的数量变得巨大。 

### 带记忆的最优动态规划

 关键的观察是普通玩家的确切身份并不重要。 重要的只是：

 - 剩余玩家数量
 - 的职位`firstPlayer`- 的职位`secondPlayer`由于这两个特殊玩家总是存活到相遇，所以我们可以将锦标赛状态简洁地描述为：```
(players_remaining, position_of_first, position_of_second)
```从这个状态开始，我们递归地为两名玩家生成所有有效的下一轮位置。 

另一个重要的对称性观察是：

 - 如果`firstPlayer + secondPlayer == n + 1`，他们将在本轮比赛中立即对阵。 

否则，我们会列举其他比赛可以解决的所有方法，同时保留两名特殊球员。 

由于许多递归分支达到相同的状态，记忆化大大减少了重复工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 枚举每场比赛的结果 |
 | 最佳| 大约 O(n^4) | O(n^3) | O(n^3) | 压缩状态下的记忆 DP |

 ## 算法演练

 1.定义递归函数`dfs(players, left, right)`。 

这里：

-`players`是剩余玩家的数量
 -`left`是当前位置`firstPlayer`-`right`是当前位置`secondPlayer`位置是 1 索引的。 
2. 规范化状态，使得`left < right`。 

这避免了重复的对称状态并提高了记忆效率。 
3. 检查两位选手是否在本轮比赛中相遇。 

在一轮中与`players`参与者、职位`i`和`players - i + 1`面对面。 

因此，如果：$left + right = players + 1$然后两名特殊选手立即进行比赛。 

在这种情况下，返回：```
(1, 1)
```因为最早和最晚的会议轮次都是当前轮次。 
4. 列举所有可能的下一轮位置。 

我们模拟下一轮中每个特殊玩家面前出现的获胜者数量。 

重要的想法是我们不需要跟踪确切的玩家。 我们只需要知道回合结束后，在特殊玩家之前还剩下多少幸存者。 
5. 确定下一轮的规模。 

幸存者人数为：$\left\lceil \frac{players}{2} \right\rceil$这成为`players`递归调用的值。 
6. 对于每对有效的下一轮位置`(newLeft, newRight)`：

 - 递归地解决较小的子问题
 - 将两个返回值加 1，因为一轮已经过去
 - 更新全局最小值和最大值
 7. 记住结果。 

由于许多锦标赛分支产生相同的`(players, left, right)`状态，缓存可以防止重复计算。 
8. 返回存储的对：```
(earliest_round, latest_round)
```### 为什么它有效

 该算法之所以有效，是因为锦标赛的演变仅取决于两个不可战胜的玩家的相对位置。 其他玩家的身份无关紧要，因为他们的比赛可以任意选择。 

递归过渡详尽地列举了周围玩家生存的所有可能方式，同时保留了两个特殊玩家。 因此，每个可到达的未来状态都只会被探索一次。 记忆化保证重复状态重用已经计算出的答案。 

由于递归考虑了所有有效的锦标赛演变，因此最小会议深度是最早的回合，最大会议深度是最新的回合。 

## Python 解决方案```python
from typing import List
from functools import lru_cache

class Solution:
    def earliestAndLatest(
        self,
        n: int,
        firstPlayer: int,
        secondPlayer: int
    ) -> List[int]:

        @lru_cache(None)
        def dfs(players: int, left: int, right: int):
            if left + right == players + 1:
                return (1, 1)

            if left > right:
                left, right = right, left

            next_players = (players + 1) // 2

            earliest = float("inf")
            latest = 0

            # Enumerate all possible next positions
            # of the two special players.
            #
            # i = survivors before left
            # j = survivors between left and right

            for i in range((left + 1) // 2):
                for j in range((right - left + 1) // 2):

                    new_left = i + 1
                    new_right = i + j + 2

                    if new_left < new_right:
                        e, l = dfs(next_players, new_left, new_right)

                        earliest = min(earliest, e + 1)
                        latest = max(latest, l + 1)

            return (earliest, latest)

        return list(dfs(n, firstPlayer, secondPlayer))
```实现从记忆递归助手开始`dfs`。 缓存至关重要，因为许多递归分支会导致相同的锦标赛状态。 

基本情况检查两个特殊玩家是否在当前回合中配对。 由于配对从两端对称，因此当它们的位置总和为`players + 1`。 

递归部分计算晋级下一轮的玩家数量。 然后，嵌套循环会枚举其他玩家在这两个特殊玩家周围生存的所有有效方式。 

变量：

 -`i`代表之前出现过多少幸存者`left`-`j`代表之间出现了多少幸存者`left`和`right`根据这些计数，我们重建下一轮的位置。 

每个递归结果都会向最早的值和最新的值添加一轮。 最后，记忆确保了重叠子问题的有效重用。 

## 解决方案```go
package main

func earliestAndLatest(n int, firstPlayer int, secondPlayer int) []int {
	type Pair struct {
		earliest int
		latest   int
	}

	memo := make(map[[3]int]Pair)

	var dfs func(int, int, int) Pair

	dfs = func(players int, left int, right int) Pair {
		if left > right {
			left, right = right, left
		}

		if left+right == players+1 {
			return Pair{1, 1}
		}

		key := [3]int{players, left, right}

		if val, exists := memo[key]; exists {
			return val
		}

		nextPlayers := (players + 1) / 2

		earliest := 1 << 30
		latest := 0

		for i := 0; i < (left+1)/2; i++ {
			for j := 0; j < (right-left+1)/2; j++ {

				newLeft := i + 1
				newRight := i + j + 2

				if newLeft < newRight {
					res := dfs(nextPlayers, newLeft, newRight)

					if res.earliest+1 < earliest {
						earliest = res.earliest + 1
					}

					if res.latest+1 > latest {
						latest = res.latest + 1
					}
				}
			}
		}

		answer := Pair{earliest, latest}
		memo[key] = answer

		return answer
	}

	result := dfs(n, firstPlayer, secondPlayer)

	return []int{result.earliest, result.latest}
}
```Go 实现遵循与 Python 版本相同的递归记忆结构。 由于 Go 不提供内置的记忆化装饰器，因此我们将结果显式存储在由固定大小数组键控的映射中。 

递归函数返回一个自定义的`Pair`包含最早和最新会议轮次的结构。 

Go 切片用于最终返回值。 整数溢出不是问题，因为在问题约束下所有值仍然非常小。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 大约 O(n^4) | 记忆状态数乘以转换枚举 |
 | 空间| O(n^3) | O(n^3) | 锦标赛状态记忆表|

 唯一状态的数量受以下限制：

 -`players`范围从`1`到`28`-`left`和`right`的边界是`players`这大致给出了`O(n^3)`州。

在实践中，实际可达状态的数量要小得多，使得解决方案对于约束限制来说足够快。

 ## 边缘情况

 当两个特殊玩家最初配对时，会出现一个重要的边缘情况。 每当他们的头寸总和达到时就会发生这种情况`n + 1`。 幼稚的实现可能不必要地进一步递归，但正确的行为是立即返回`[1, 1]`。 在任何递归工作发生之前，实现会使用基本情况条件来处理此问题。 

当玩家数量为奇数时，会出现另一个微妙的情况。 在这些回合中，中间玩家无需竞争即可自动晋级。 对该规则处理不当可能会错误地改变未来的头寸。 该实现通过直接推理幸存者数量和下一轮位置来避免明确的再见模拟，这自然地包含了中间玩家的进步。 

第三个重要的边缘情况涉及对称状态。 例如，`(players=8, left=2, right=5)`和`(players=8, left=5, right=2)`代表相同的锦标赛配置。 如果没有标准化，记忆效率就会受到影响，并且会发生重复计算。 实现总是交换位置，以便`left < right`在访问缓存之前。 

最后的边缘情况涉及接近最大约束的非常大的分支可能性`n = 28`。 暴力方法会呈指数级爆炸并且变得不可行。 记忆状态压缩确保每个逻辑配置仅求解一次，即使在上限下也能保持算法的效率。
