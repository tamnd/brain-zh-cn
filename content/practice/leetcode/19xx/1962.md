[LeetCode 1962 题](https://leetcode.com/problems/remove-stones-to-minimize-the-total/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`piles`，其中每个元素代表一堆石头的数量。 我们还得到一个整数`k`，代表我们必须执行的确切操作数。 

在一次操作中，我们选择一堆并移除`floor(pile / 2)`石头从它。 由于我们移除了向下舍入的一半堆，剩余的堆变成：$$pile - \left\lfloor \frac{pile}{2} \right\rfloor$$这相当于：$$\left\lceil \frac{pile}{2} \right\rceil$$例如：

 - 如果一堆有`9`石头，我们移除`4`，离开`5`- 如果一堆有`6`石头，我们移除`3`，离开`3`- 如果一堆有`1`石头，我们移除`0`，所以它保持`1`目标是最大限度地减少精确后剩余的石子总数`k`运营。 

重要的细节是我们可以多次选择同一堆。 这意味着如果有益的话，我们可以自由地反复减少当前最大的一堆。 

限制条件很大：

 - 最多`10^5`桩
 - 最多`10^5`运营
 - 每堆最多可包含`10^4`石头

 因为两者`n`和`k`可能非常大，任何重复扫描整个数组以获取最大值的解决方案都可能太慢。 

一些边缘情况很重要：

 - 一堆有价值的东西`1`永远不会改变，因为`floor(1 / 2) = 0`-`k`可能大于桩的数量，所以我们可能会多次重新访问桩
 - 每一步的最优选择取决于当前最大的桩，而不是原来最大的桩
 - 多个桩可能具有相同的尺寸

 理解我们总是希望立即最大程度地减少是导致最佳贪婪解决方案的关键见解。 

## 方法

 ### 蛮力方法

 一个简单的方法是模拟所有`k`直接操作。 

对于每个操作：

 1. 扫描整个数组，找到最大的一堆
 2. 删除`floor(pile / 2)`来自它的石头
 3.更新桩
 4. 重复

 这是有效的，因为从最大的一堆石头中移除石头总是能立即最大程度地减少石头。 然而，通过扫描阵列来找到最大的一堆成本`O(n)`每次操作的时间。 

既然我们表演`k`操作，总复杂度变为：$$O(n \times k)$$两者都有`n`和`k`可能等于`10^5`，这可能需要最多`10^{10}`操作，这太慢了。 

### 最优方法，贪婪 + 最大堆

 关键的观察是，在每一步中，最好的举动始终是减少当前最大的一堆。 

假设我们有两堆：

 - A 堆 = 20
 - 桩 B = 8

 变径桩A移除`10`石头，同时减少堆 B 仅移除`4`石头。 选择较大的一堆总是可以最大程度地减少总和。 

这种贪婪的选择在每次操作后仍然是最佳的，因为唯一重要的是最大化当前步骤的减少。 

为了有效地重复检索最大堆，我们使用最大堆。 

堆允许我们：

 - 提取最大的一堆`O(log n)`- 将更新后的桩插入`O(log n)`这大大降低了整体复杂性。 

自从Python的`heapq`是最小堆，我们通过存储负值来模拟最大堆。

 ## 算法演练

 1. 计算初始的棋子总数。 

跟踪总数可以让我们避免在最后再次对数组求和。 
2. 构建包含所有堆大小的最大堆。 

由于Python仅提供最小堆，因此我们存储负值，因此最大的堆首先出现。 
3. 准确重复操作`k`次。 

在每次迭代中：

 - 从堆中删除最大的堆
 - 计算移除了多少块石头：$$removed = \left\lfloor \frac{largest}{2} \right\rfloor$$- 减法`removed`从运行总计
 - 计算更新后的桩尺寸：$$newPile = largest - removed$$- 将更新后的堆推回到堆中
 4. 所有操作完成后，返回总计。 

### 为什么它有效

 贪心策略是最优的，因为每个操作在最大化减少方面都是独立的。 从最大的一堆中移走石子总是至少与从任何较小的一堆中移走一样多的石子。 

堆保证我们总是有效地选择当前最大的堆。 由于每个操作都会做出局部最优选择，并且未来的操作无法弥补之前浪费的减少机会，因此该算法会产生尽可能小的总数。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minStoneSum(self, piles: List[int], k: int) -> int:
        total_stones = sum(piles)

        # Python heapq is a min heap, so use negative values
        max_heap = [-pile for pile in piles]
        heapq.heapify(max_heap)

        for _ in range(k):
            largest_pile = -heapq.heappop(max_heap)

            removed_stones = largest_pile // 2
            remaining_pile = largest_pile - removed_stones

            total_stones -= removed_stones

            heapq.heappush(max_heap, -remaining_pile)

        return total_stones
```该实现首先计算所有堆中石子的总数。 这使得算法能够增量地更新答案，而不是重复地重新计算总和。 

接下来，代码构造一个最大堆。 因为Python的`heapq`模块仅支持最小堆，每个堆存储为负数。 这个技巧会导致最大的原始堆显示为最小的负值。 

在循环内，算法移除最大的一堆，计算移除了多少块石头，更新总数，并将减少的堆插入回堆中。 

堆始终保持堆的当前状态，确保每次操作都有效地选择最大的可用堆。 

## 解决方案```go
package main

import (
	"container/heap"
)

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)

	item := old[n-1]
	*h = old[:n-1]

	return item
}

func minStoneSum(piles []int, k int) int {
	totalStones := 0

	h := &MaxHeap{}

	for _, pile := range piles {
		totalStones += pile
		*h = append(*h, pile)
	}

	heap.Init(h)

	for i := 0; i < k; i++ {
		largestPile := heap.Pop(h).(int)

		removedStones := largestPile / 2
		remainingPile := largestPile - removedStones

		totalStones -= removedStones

		heap.Push(h, remainingPile)
	}

	return totalStones
}
```Go 实现使用`container/heap`包，它需要定义一个实现堆接口方法的自定义堆类型。 

与 Python 不同，Go 允许我们通过自定义来直接定义最大堆`Less`函数，以便较大的值具有较高的优先级。 

其余逻辑完全反映了 Python 解决方案。 

Go 整数足以解决这个问题，因为最大可能的总数是：$$10^5 \times 10^4 = 10^9$$它可以安全地放入 32 位有符号整数内。

 ## 边缘情况

 当一堆石头仅包含一颗石头时，就会出现一个重要的边缘情况。 自从：$$\left\lfloor \frac{1}{2} \right\rfloor = 0$$堆永远不会改变。 有缺陷的实现可能会意外地将其减少到零或进入不必要的处理循环。 基于堆的解决方案可以自然地处理这个问题，因为删除零石只是重新插入该值`1`。 

另一个重要的情况是当`k`远大于堆的数量。 由于同一桩可能会被重复选择，因此算法必须继续正确更新和重新插入桩。 堆结构自然支持这一点，因为每个更新的堆都会被推迟以供将来考虑。 

第三种边缘情况涉及多个具有相同尺寸的桩。 该算法仍然必须在每一步中一致地选择最大的一堆之一。 由于所有同样大的牌堆提供相同的减少量，因此任何打破平局的顺序都是有效的。 堆实现会自动处理关系，而不会影响正确性。 

当操作完成之前所有堆变得非常小时，就会出现最后一个微妙的边缘情况。 最终，每一堆都可能变成`1`，此后不可能进一步减少。 该算法仍然继续执行剩余的操作，但每次操作都会删除零个石子，而总数不变。
