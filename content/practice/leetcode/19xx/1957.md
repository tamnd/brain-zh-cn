[LeetCode 1957 题](https://leetcode.com/problems/delete-characters-to-make-fancy-string/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们将给定的字符串转换为“奇特的字符串”。 花式字符串被定义为在字符串中任何位置都不包含三个连续相同字符的字符串。 

我们可以从原始字符串中删除字符，我们的目标是删除尽可能少的字符。 执行最少的删除后，我们返回结果字符串。 

输入由单个字符串组成`s`仅包含小写英文字母。 字符串的长度可以大到`10^5`，这意味着解决方案必须是有效的。 对于最坏的情况，任何具有二次时间复杂度的算法都可能太慢。 

重要的观察是我们只关心重复字符的运行。 允许两个连续的相同字符，但必须删除第三个连续的相同字符。 例如：

-`"aa"`有效
 -`"aaa"`无效
 -`"aabaa"`有效
 -`"baaaab"`无效，因为它包含四个连续的`'a'`人物

 该问题保证最终答案是唯一的。 发生这种情况是因为最小删除策略是确定性的：每当出现第三个相同的连续字符时，就必须删除该字符。 

需要考虑一些重要的边缘情况：

 - 长度小于 3 的字符串总是很漂亮。 
- 没有重复字符的字符串不需要删除。 
- 每个字符都相同的字符串，例如`"aaaaaa"`，需要重复删除。 
- 长时间连续出现相同的字符，例如`"bbbbbbbb"`，必须精确地减少为两个连续字符。 

## 方法

 ### 蛮力方法

 暴力方法可以重复扫描字符串，查找三个连续相同字符的出现。 每当找到这样的序列时，我们就删除一个字符并重新开始扫描。 

例如：

 - 开始于`"aaabaaaa"`- 探测`"aaa"`并删除一个字符
 - 重新开始扫描
 - 检测另一个无效序列
 - 继续直到字符串变得有效

 这种方法之所以有效，是因为最终所有无效的三元组都会被删除。 但是，从字符串中间删除字符的成本很高，并且反复重新扫描字符串会导致性能不佳。 

在最坏的情况下，每次删除都可能需要重建字符串，并且我们可能会执行多次删除。 这可能导致二次时间复杂度。 

### 最佳方法

 关键的见解是我们不需要重复修改和重新扫描字符串。 相反，我们可以逐步构建答案，同时确保不会创建无效序列。 

当我们处理每个字符时：

 - 如果添加当前字符会创建三个连续的相同字符，我们会跳过它。 
- 否则，我们将其附加到结果中。 

这种贪婪策略是最优的，因为：

 - 尽可能保留字符以最大程度地减少删除。 
- 我们必须删除字符的唯一时间是当它会创建无效的三元组时。 

我们可以使用列表或字符串构建器一次性有效地构建结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 反复重新扫描并重建字符串 |
 | 最佳| O(n) | O(n) | 单遍贪婪构造 |

 ## 算法演练

 1. 创建一个空的结果容器。 

我们将逐个字符地构建奇特的字符串。 使用列表非常高效，因为追加操作是 O(1) 的操作。 
2. 迭代输入字符串中的每个字符。 

对于每个字符，确定是否可以安全地将其添加到结果中。 
3. 检查结果中已有的最后两个字符。 

如果结果已经以当前字符的两个副本结束，则添加另一个副本将创建三个连续的相同字符。 
4. 跳过无效字符。 

如果当前字符将创建一个三元组，则不要附加它。 
5. 附加有效字符。 

否则，将当前字符添加到结果中。 
6. 将结果容器转换回字符串。 

处理完所有字符后，构造的字符串保证满足花式字符串条件。 

### 为什么它有效

 该算法保持了部分构造的结果始终是有效的花哨字符串的不变性。 每个新字符只有在不违反三个连续相同字符的规则时才会添加。 

因为我们只在绝对必要时删除字符，所以删除的次数被最小化。 因此，生成的字符串既有效又最佳。 

## Python 解决方案```python
class Solution:
    def makeFancyString(self, s: str) -> str:
        result = []

        for char in s:
            if len(result) >= 2 and result[-1] == char and result[-2] == char:
                continue

            result.append(char)

        return "".join(result)
```该实现使用一个名为的列表`result`有效地构建最终的字符串。 

对于输入字符串中的每个字符：

 - 代码检查最后两个字符是否已存储在`result`等于当前字符。 
- 如果是，则附加当前字符将创建三个连续的相同字符，因此该字符将被跳过。 
- 否则，将附加该字符。 

在最后，`"".join(result)`将列表转换为最终字符串。 

此实现直接遵循前面描述的贪婪算法，并在一次传递中处理输入。 

## 解决方案```go
func makeFancyString(s string) string {
    result := make([]byte, 0, len(s))

    for i := 0; i < len(s); i++ {
        char := s[i]

        n := len(result)

        if n >= 2 && result[n-1] == char && result[n-2] == char {
            continue
        }

        result = append(result, char)
    }

    return string(result)
}
```Go 实现使用字节切片来有效构建结果字符串。 

与 Python 列表不同，Go 切片需要显式的长度管理。 该代码检查最后两个元素`result`在附加新字符之前进行切片。 

由于输入仅包含小写英文字母，因此使用`byte`是充足且高效的。

 ## 边缘情况

 ### 非常短的字符串

 长度为 1 或 2 的字符串永远不能包含三个连续的相同字符。 有缺陷的实现可能会在不首先检查当前长度的情况下错误地尝试访问最后两个字符。 

此实现安全地检查`len(result) >= 2`在检查最后两个字符之前。 

### 同一角色的长时间运行

 输入如`"aaaaaaaa"`很重要，因为它们包含许多无效的三元组。 一种幼稚的实现可能只会删除一个额外的字符，但仍然会留下无效的序列。 

该算法在第二次连续出现后连续跳过每个字符，确保最终结果变为`"aa"`。 

### 多个单独的重复组

 输入如`"aaabbbcccaaa"`包含几个独立的重复部分。 一些不正确的解决方案可能只处理第一个无效序列。 

由于该算法独立处理每个字符，同时保持奇特的字符串不变性，因此在一次遍历中可以正确处理所有重复的组。
