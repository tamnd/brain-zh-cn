[LeetCode 1911 题](https://leetcode.com/problems/maximum-alternating-subsequence-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定数组的任何子序列的最大可能交替和。 

从索引开始重新索引所选子序列后，计算交替和`0`。 子序列中偶数位置的元素被相加，而奇数位置的元素被减去。 

例如，如果我们选择子序列`[4,2,5]`，那么：

 - 索引`0`：`+4`- 指数`1`：`-2`- 指数`2`：`+5`交替总和变为：```
4 - 2 + 5 = 7
```重要的细节是子序列在选择后会重新索引。 原始索引在`nums`一旦子序列形成就无关紧要了。 只有元素的顺序必须保持不变。 

输入包括：

 -`nums`，正整数数组
 -`1 <= nums.length <= 10^5`-`1 <= nums[i] <= 10^5`这些约束足够大，指数或二次解将无法有效地工作。 任何实际的解决方案都必须以线性时间或接近线性时间运行。 

因为所有数字都是正数，所以出现了一些有趣的行为：

 - 有时最好只保留一个大数字。 
- 有时，收益和损失的交替会产生更大的总数。 
- 最优子序列不一定是连续的。 

一些边缘情况很重要：

 - 具有单个元素的数组
 - 严格增加数组
 - 严格递减数组
 - 跳过许多元素是最佳的数组
 - 非常大的数组需要有效的内存使用

 该问题保证至少有一个元素，因此我们永远不需要处理空输入数组。 

## 方法

 ### 蛮力方法

 强力解决方案将生成数组的每个可能的子序列。 对于每个子序列，我们将计算其交替和并跟踪找到的最大值。 

对于长度的数组`n`， 有`2^n`可能的子序列。 计算每个子序列的交替和可能需要`O(n)`时间。 

这保证了正确性，因为每个有效的子序列都会被检查。 然而，这对于`n = 10^5`。 

即使是为了`n = 30`，子序列的数量已经超过十亿。 

### 最佳解决方案的关键见解

 关键的观察是，在每个位置我们只关心两个状态：

 - 当前子序列长度为偶数时的最佳交替和
 - 当前子序列长度为奇数时的最佳交替和

 另一种思考这个问题的方法是：

 -`even`表示减去下一个选择的数字时的最佳值
 -`odd`表示添加下一个所选数字时的最佳值

 处理新号码时`num`，我们有两个选择：

 - 跳过它
 - 将其包含在子序列中

 如果我们包括它：

 - 添加`num`偶数长度子序列创建奇数长度子序列
 - 减法`num`从奇数长度子序列创建偶数长度子序列

 这自然会导致仅具有恒定内存的动态编程转换。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × 2^n) | O(n × 2^n) | O(n) | 枚举所有子序列 |
 | 最优动态规划| O(n) | O(1) | O(1) | 仅跟踪两个 DP 状态 |

 ## 算法演练

 1.初始化两个变量：

 -`even = 0`-`odd = 0`这里：

-`even`存储偶数长度子序列的最佳交替和
 -`odd`存储奇数长度子序列的最佳交替和
 2. 迭代每个数字`num`在`nums`。 
3. 计算新值`odd`。 

如果我们包括`num`作为偶数长度子序列之后的下一个元素，它将被添加：```
even + num
```我们还可以选择跳过`num`， 所以：```
new_odd = max(odd, even + num)
```4. 计算新值`even`。 

如果我们包括`num`在奇数长度的子序列之后，它将被减去：```
odd - num
```我们也可以跳过这个数字：```
new_even = max(even, odd - num)
```5. 同时更新两个状态。 
6. 继续，直到处理完所有元素。 
7. 返回`odd`。 

最终答案始终存储在`odd`因为积极贡献的子序列是从加法开始的。 

### 为什么它有效

 该算法保持动态规划不变式：

 -`odd`始终存储使用子序列长度为奇数的已处理元素可实现的最大交替和。 
-`even`始终存储使用子序列长度为偶数的已处理元素可实现的最大交替和。 

在每一步中，算法都会考虑两种可能性，采用或跳过当前数字，并保留最佳可实现值。 由于每个有效子序列都可以通过这些转换来表示，因此最终的`odd`值保证是最优的。 

## Python 解决方案```python
from typing import List

class Solution:

    def maxAlternatingSum(self, nums: List[int]) -> int:
        even = 0
        odd = 0

        for num in nums:
            new_odd = max(odd, even + num)
            new_even = max(even, odd - num)

            odd = new_odd
            even = new_even

        return odd
```实现直接遵循动态规划公式。 

变量`odd`和`even`存储两个可能的子序列奇偶校验状态的最佳结果。 

对于每个数字：

 -`new_odd`表示处理当前数后的最佳奇数长度子序列。 
-`new_even`表示处理当前数字后的最佳偶数长度子序列。 

过渡考虑了两种选择：

 - 跳过当前号码
 - 包括当前号码

 使用临时变量很重要，因为两次更新都取决于前一次迭代的值。 

该算法只处理数组一次，并且仅使用恒定的额外空间。 

## 解决方案```go
func maxAlternatingSum(nums []int) int64 {
    var even int64 = 0
    var odd int64 = 0

    for _, num := range nums {
        value := int64(num)

        newOdd := max64(odd, even+value)
        newEven := max64(even, odd-value)

        odd = newOdd
        even = newEven
    }

    return odd
}

func max64(a, b int64) int64 {
    if a > b {
        return a
    }
    return b
}
```Go 的实现与 Python 解决方案非常相似。 

一个重要的区别是使用`int64`。 问题约束允许总和可能超出标准 32 位整数范围，因此使用`int64`确保正确性。 

Go 没有提供内置的`max`整数函数，因此是一个辅助函数`max64`已实施。 

该函数安全地处理所有有效输入，包括具有单个元素的数组。

 ## 边缘情况

 一种重要的边缘情况是单元素数组。 由于子序列只能包含一个数字，因此答案必须是该元素本身。 有缺陷的实现可能会错误地初始化状态并返回零。 当前的实现自然地处理这个问题，因为第一次迭代更新`odd`到元素值。 

另一个重要的边缘情况是严格递增的数组，例如`[1,2,3,4,5]`。 天真的贪婪策略可能会尝试包含许多元素，但减去中间值可能会减少总收益。 动态编程转换正确评估采用或跳过每个值是否会产生最佳结果。 

第三种边缘情况是最佳解决方案跳过大多数元素的数组，例如`[1,100,1]`。 包括周边`1`s 会降低交替总和。 该算法通过以下方式正确保留了先前的最佳状态`max`操作，使其忽略有害的选择。 

另一个微妙的边缘情况涉及重复的相等值，例如`[2,2,2,2]`。 多个子序列产生相同的结果，并且实现必须避免通过不必要的转换意外地降低状态。 由于每次更新总是与现有状态进行比较，因此可以正确保留最佳值。 

最后，非常大的数组需要高效的内存使用。 由于约束允许最多`10^5`元素，存储大型 DP 表将是不必要的开销。 该实现仅使用两个变量，确保无论输入大小如何都有恒定的额外空间。
