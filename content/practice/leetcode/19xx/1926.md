[LeetCode 1926 题](https://leetcode.com/problems/nearest-exit-from-entrance-in-maze/)

 **难度：** 🟡 中等
 **主题：** 数组、广度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们一个由二维网格表示的矩形迷宫。 每个单元格包含：

 -`'.'`，意味着单元格是空的并且可以在上面行走
 -`'+'`，意味着单元格是一堵墙，无法跨越

 我们还得到了一个坐标`entrance`细胞。 入口保证是一个空牢房。 

从任何单元格，我们都可以朝四个方向移动：

 - 向上
 - 向下
 - 左
 - 右

 每一步只花费一步。 

目标是找到到达最近出口所需的最少步数。 出口定义为：

 1. 空单元格
 2.位于迷宫的边界
 3. 不等于入口单元格本身

 如果不存在可到达的出口，我们返回`-1`。 

重要的细节是入口不能算作出口，即使它位于边界上。 这种情况是错误的常见来源。 

限制相对较小：

 -`1 <= m, n <= 100`这意味着迷宫最多包含`10,000`细胞。 由于这并不是很大，因此诸如广度优先搜索之类的图遍历算法是非常可行的。 

从概念上讲，迷宫形成一个未加权的图：

 - 每个空单元格都是一个节点
 - 相邻的空单元格通过边缘连接
 - 每一次行动都有相同的成本

 因为每一步都只花费一步，所以最短路径问题自然建议广度优先搜索。 

一些边缘情况很重要：

 - 入口可能已经位于边界上，但仍然不能被视为出口。 
- 可能根本就没有出口。 
- 可能存在无法到达的出口，因为墙壁挡住了路径。 
- 迷宫可能只包含一个单元格。 
- 可能存在多个出口，我们必须返回最近的一个。 

## 方法

 ### 蛮力方法

 蛮力策略是：

 1. 识别迷宫中的每个有效出口。 
2. 对于每个出口，从入口运行单独的搜索以确定最短路径长度。 
3. 返回最小可达距离。 

这是可行的，因为最终每个出口都会被检查，并选择最短的可达出口。 

然而，这种方法效率低下，因为我们为每个出口重复遍历迷宫。 在最坏的情况下，迷宫可能包含许多边界单元，并且每次搜索都可以访问几乎所有单元。 

如果有`E`退出并且`m * n`细胞，复杂度大致变为：

 -`O(E * m * n)`自从`E`本身可以正比于`m + n`，这会变得不必要的昂贵。 

### 最佳方法

 关键的观察结果是所有的行动都有相同的成本。 

每当我们需要未加权图中的最短移动次数时，广度优先搜索就是理想的工具。 

广度优先搜索逐级探索单元格：

 - 首先是远处的所有单元格`1`- 然后所有细胞都在远处`2`- 然后所有细胞都在远处`3`- 等等

 因此，BFS过程中遇到的第一个出口一定是最近的出口。 

我们不是单独搜索每个出口，而是从入口开始一个 BFS，并在遇到第一个有效出口时立即停止。 

这保证了最多访问每个单元一次的最优性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(E × m × n) | O(m × n) | 搜索每个可能的出口 |
 | 最佳| O(m × n) | O(m × n) | 单次BFS遍历立即找到最近的出口 |

 ## 算法演练

 ### 步骤 1：初始化 BFS 结构

 我们创造：

 - 用于BFS遍历的队列
 - 访问过的结构以避免再次访问单元格

 队列存储：

 - 当前行
 - 当前栏目
 - 距入口的距离

 我们首先插入带有距离的入口`0`。 

### 第 2 步：将入口标记为已访问

 我们立即将入口标记为已访问过。 

这可以防止以后重新访问它并避免无限循环。 

### 步骤 3：定义四个方向

 我们定义运动向量：

 - 向上
 - 向下
 - 左
 - 右

 这简化了邻居遍历。 

### 步骤 4：处理队列

 当队列不为空时：

 1. 拆下前面的电池
 2. 探索所有四个相邻单元格

 对于每个邻居：

 - 检查边界
 - 确保它不是墙
 - 确保尚未被访问过

 如果有效：

 - 标记已访问
 - 计算其距离
 - 将其添加到队列中

 ### 步骤 5：检测出口

 移动到有效的相邻小区后，检查是否：

 - 它位于边境
 - 这不是入口

 如果两个条件都成立，我们立即返回当前距离加一。 

因为 BFS 按距离递增的顺序进行探索，所以这保证是最近的出口。 

### 步骤 6：处理无法到达的出口

 如果 BFS 完成而没有找到任何出口，则返回`-1`。 

### 为什么它有效

 广度优先搜索按照距起点的距离严格递增的顺序探索节点。 

这意味着：

 - 每个较早到达的单元格的路径长度都比较晚到达的单元格的路径长度短或相等。 
- 因此，发现的第一个出口必须是最近的出口。 

访问集确保每个单元最多被处理一次，从而防止循环和冗余工作。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def nearestExit(self, maze: List[List[str]], entrance: List[int]) -> int:
        rows = len(maze)
        cols = len(maze[0])

        start_row, start_col = entrance

        queue = deque()
        queue.append((start_row, start_col, 0))

        visited = set()
        visited.add((start_row, start_col))

        directions = [
            (-1, 0),  # up
            (1, 0),   # down
            (0, -1),  # left
            (0, 1)    # right
        ]

        while queue:
            row, col, steps = queue.popleft()

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                # Check boundaries
                if (
                    new_row < 0
                    or new_row >= rows
                    or new_col < 0
                    or new_col >= cols
                ):
                    continue

                # Skip walls
                if maze[new_row][new_col] == '+':
                    continue

                # Skip visited cells
                if (new_row, new_col) in visited:
                    continue

                # Check whether this cell is an exit
                is_border = (
                    new_row == 0
                    or new_row == rows - 1
                    or new_col == 0
                    or new_col == cols - 1
                )

                if is_border:
                    return steps + 1

                visited.add((new_row, new_col))
                queue.append((new_row, new_col, steps + 1))

        return -1
```实现首先确定迷宫尺寸并提取入口坐标。 

一个`deque`使用 BFS 是因为 BFS 会重复从前面删除元素并将新元素追加到后面。 对于双端队列来说，这两种操作都是高效的。 

这`visited`设置防止重新访问单元格。 如果没有它，搜索可能会在单元格之间重复循环，从而导致不必要的工作或无限循环。 

每个队列元素存储：

 - 行索引
 - 列索引
 - 距入口的当前距离

 在 BFS 循环内，我们检查当前单元的所有四个邻居。 

我们跳过邻居：

 - 掉到迷宫外面
 - 是墙壁
 - 已经被访问过

 对于每个有效的未访问的空单元格，我们检查它是否位于边界上。 如果是，我们立即返回路径长度，因为 BFS 保证这是最短路径。 

如果 BFS 完成而没有找到出口，则该函数返回`-1`。 

## 解决方案```go
package main

func nearestExit(maze [][]byte, entrance []int) int {
	rows := len(maze)
	cols := len(maze[0])

	type State struct {
		row   int
		col   int
		steps int
	}

	queue := []State{
		{entrance[0], entrance[1], 0},
	}

	visited := make([][]bool, rows)
	for i := 0; i < rows; i++ {
		visited[i] = make([]bool, cols)
	}

	visited[entrance[0]][entrance[1]] = true

	directions := [][]int{
		{-1, 0},
		{1, 0},
		{0, -1},
		{0, 1},
	}

	for len(queue) > 0 {
		current := queue[0]
		queue = queue[1:]

		for _, dir := range directions {
			newRow := current.row + dir[0]
			newCol := current.col + dir[1]

			// Boundary check
			if newRow < 0 || newRow >= rows || newCol < 0 || newCol >= cols {
				continue
			}

			// Wall check
			if maze[newRow][newCol] == '+' {
				continue
			}

			// Visited check
			if visited[newRow][newCol] {
				continue
			}

			isBorder := (
				newRow == 0 ||
				newRow == rows-1 ||
				newCol == 0 ||
				newCol == cols-1
			)

			if isBorder {
				return current.steps + 1
			}

			visited[newRow][newCol] = true

			queue = append(queue, State{
				newRow,
				newCol,
				current.steps + 1,
			})
		}
	}

	return -1
}
```Go 实现遵循与 Python 解决方案完全相同的 BFS 逻辑。 

Go 没有使用 Python 元组，而是使用`State`存储结构：

 - 行
 - 专栏
 - 步数统计

 访问的结构是使用 2D 布尔切片而不是哈希集来实现的，这是有效的，因为迷宫尺寸是预先知道的。 

Go 切片通过使用以下方法删除第一个元素来自然地支持队列行为：```go
queue = queue[1:]
```这里不存在整数溢出问题，因为最大路径长度受单元数量限制，最多为`10,000`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m × n) | 每个单元格最多被访问一次 |
 | 空间| O(m × n) | 队列和访问结构可以存储所有单元 |

 BFS 遍历对每个可达单元处理一次。 每次邻居检查都是恒定时间，因此总运行时间与迷宫中的单元格数量成正比。 

在最坏的情况下，队列和访问的结构都可以增长到包含每个单元，从而提供线性的辅助空间使用。 

## 测试用例```python
from typing import List

class Solution:
    def nearestExit(self, maze: List[List[str]], entrance: List[int]) -> int:
        from collections import deque

        rows = len(maze)
        cols = len(maze[0])

        queue = deque([(entrance[0], entrance[1], 0)])
        visited = {(entrance[0], entrance[1])}

        directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

        while queue:
            row, col, steps = queue.popleft()

            for dr, dc in directions:
                nr = row + dr
                nc = col + dc

                if nr < 0 or nr >= rows or nc < 0 or nc >= cols:
                    continue

                if maze[nr][nc] == '+':
                    continue

                if (nr, nc) in visited:
                    continue

                if nr == 0 or nr == rows - 1 or nc == 0 or nc == cols - 1:
                    return steps + 1

                visited.add((nr, nc))
                queue.append((nr, nc, steps + 1))

        return -1

sol = Solution()

# Example 1
assert sol.nearestExit(
    [["+", "+", ".", "+"],
     [".", ".", ".", "+"],
     ["+", "+", "+", "."]],

) == 1  # nearest exit directly above

# Example 2

    [1, 0]
) == 2  # entrance on border does not count

# Example 3

    [[".", "+"]],
    [0, 0]
) == -1  # no exits exist

# Single cell maze

    [["."]],
    [0, 0]
) == -1  # entrance is only cell

# Exit reachable in one move

    [["+", "."],

# Multiple exits, choose nearest

     [".", ".", "."]],
    [1, 0]
) == 1  # nearest border exit

) == -1  # surrounded by walls

 ## 边缘情况

 ### 边境入口

 当入口本身位于迷宫边界时，就会发生最重要的边缘情况之一。 

一个幼稚的实现可能会立即返回`0`，错误地将入口视为出口。 

该问题明确指出入口不算作出口。 我们的实现正确地处理了这个问题，因为它只检查新访问的相邻小区的退出状态。 入口本身永远不会被评估为候选出口。 

### 没有有效出口的迷宫

 另一个重要的情况是当不存在可到达的边界单元时。 

发生这种情况的原因是：

 - 所有边界单元都是墙
 - 路径被墙壁挡住
 - 迷宫仅包含入口

 在这种情况下，BFS 最终会耗尽所有可达单元，队列变空。 然后算法正确返回`-1`。 

### 循环和重新访问单元格

 开放迷宫可能包含循环，可以通过多条路径到达同一个单元格。 

如果没有访问过的结构，BFS 可能会重复访问相同的单元，从而导致过多的工作或无限循环。 

该实现通过在将单元添加到队列时立即标记已访问的单元来防止这种情况。 这保证了每个单元最多被处理一次。 

### 单行或单列迷宫

 非常狭窄的迷宫可能会暴露索引错误和边界条件错误。 

例如：```
[[".", ".", "."]]
```每个细胞都位于边界上。 

该实现可以安全地处理这些情况，因为边界检测使用简单的行和列比较，无论迷宫尺寸如何，这些比较都保持有效。
