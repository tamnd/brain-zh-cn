[LeetCode 1928 题](https://leetcode.com/problems/minimum-cost-to-reach-destination-in-time/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、图论

 ## 解决方案

 ## 问题理解

 该问题要求我们找到**在给定时间限制内从城市 0 到城市 n-1** 的最低旅行成本，`maxTime`，其中成本由与访问的每个城市相关的**通行费**定义。 国家有`n`由**双向道路**连接的城市，旅行时间各不相同。 同一对城市之间可能存在多条具有不同旅行时间的道路，但没有一条道路将城市与其自身连接起来。 

输入包括`edges`，表示道路及其行驶时间的二维数组，以及`passingFees`，一个数组，其中`passingFees[i]`是城市的费用`i`。 输出是到达城市的**最低总通行费**`n-1`在`maxTime`分钟或更短。 如果没有路线满足时间限制，该函数应该返回`-1`。 

主要限制和影响：

 -`maxTime <= 1000`和`n <= 1000`表明立方复杂度 (O(n3)) 的算法可能很慢，但 O(n * maxTime) 左右的算法是可行的。 
- 行程时间和费用为正整数，可防止负循环。 
- 城市之间有多条道路意味着简单的最短路径算法可能需要单独考虑所有边。 
- 目标是**时间受限的成本最小化**，而不是仅按时间或成本计算的最短路径，这与经典的 Dijkstra 问题不同。 

重要的边缘情况：

 - 内部不存在路径`maxTime`。 
- 存在多种路径，有些更快但更昂贵，有些更慢但更便宜。 
- 只有两个城市的小图表。 
- 尽管时间较长，但经过更多城市的路径可以降低成本。 

## 方法

 ### 蛮力

 暴力方法是探索从城市 0 到城市 n-1 的**所有可能的路径**。 对于每条路径，我们计算总时间和成本。 如果时间超过`maxTime`，该路径被丢弃。 最后，我们返回有效路径中的最小成本。 

这种方法是正确的，因为它考虑了**每条可能的路线**。 然而，这是不切实际的，因为路径的数量随着`n`和边的数量。 即使进行修剪，解决方案对于`n = 1000`。 

### 最佳方法

 关键的见解是，这是一个**时间受限的最短路径问题**，其中成本是最小化的指标，但我们不能超过`maxTime`。 标准 Dijkstra 可以通过**同时跟踪时间和成本**进行调整。 

我们可以使用**优先队列**来探索城市，优先考虑**迄今为止成本最低的州**。 对于每个城市，我们维持**在给定时间内到达该城市的最低成本**。 如果一条新路径比之前记录的**更快或更便宜**到达城市，则会将其添加到队列中。 

这种方法利用**动态规划和 Dijkstra 式探索**，确保我们永远不会忽略在时间限制下可能可行的路径。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 探索所有路径，剪枝超过maxTime的路径 |
 | 最佳| O(E * 最大时间) | O(n * 最大时间) | 优先级队列+DP表跟踪每次最小成本|

 ## 算法演练

 1. **图构建**：转换`edges`列表到邻接列表中，其中每个城市都映射到其邻居以及相关的旅行时间。 这允许有效的邻居查找。 
2. **初始化状态**：使用优先级队列（min-heap）来存储元组`(currentCost, currentTime, cityIndex)`，开始于`(passingFees[0], 0, 0)`。 
3. **DP Table**：维护一个2D表`dp[city][time]`代表达到的最低成本`city`恰好在`time`分钟。 将除时间 0 时的起始城市之外的所有条目初始化为无穷大。 
4. **优先队列探索**：当队列不为空时，弹出**当前成本最低的状态**。 对于每个邻居，计算`newTime = currentTime + travelTime`和`newCost = currentCost + passingFees[neighbor]`。 
5. **状态更新**：如果`newTime <= maxTime`和`newCost < dp[neighbor][newTime]`，更新DP表并推送`(newCost, newTime, neighbor)`进入队列。 
6. **结果提取**：队列耗尽后，检查`dp[n-1][0..maxTime]`并选择**最低成本**。 如果所有条目都是无穷大，则返回`-1`。 

**为什么有效**：优先级队列确保首先探索成本较低的状态。 DP表可以防止冗余探索并保证考虑所有可行的时间成本组合。 该方法正确地识别了时间限制内的最小成本路径。 

## Python 解决方案```python
from typing import List
import heapq
import math

class Solution:
    def minCost(self, maxTime: int, edges: List[List[int]], passingFees: List[int]) -> int:
        n = len(passingFees)
        
        # Build graph
        graph = [[] for _ in range(n)]
        for u, v, t in edges:
            graph[u].append((v, t))
            graph[v].append((u, t))
        
        # DP table: min cost to reach city i at exactly time t
        dp = [ [math.inf] * (maxTime + 1) for _ in range(n) ]
        dp[0][0] = passingFees[0]
        
        # Priority queue: (currentCost, currentTime, city)
        pq = [(passingFees[0], 0, 0)]
        
        while pq:
            cost, time, city = heapq.heappop(pq)
            
            if city == n - 1:
                continue  # we will check DP table later
            
            for neighbor, travelTime in graph[city]:
                newTime = time + travelTime
                if newTime > maxTime:
                    continue
                
                newCost = cost + passingFees[neighbor]
                if newCost < dp[neighbor][newTime]:
                    dp[neighbor][newTime] = newCost
                    heapq.heappush(pq, (newCost, newTime, neighbor))
        
        minCost = min(dp[n-1])
        return minCost if minCost != math.inf else -1
```该代码为图构造邻接表，初始化 DP 表和优先级队列，并迭代地探索路径。 DP 表确保我们仅在允许的时间内找到更便宜的路径时进行更新，从而防止不必要的重新计算。 最后，它扫描最后一行以找到最小有效成本。 

## 解决方案```go
package main

import (
    "container/heap"
    "math"
)

type State struct {
    cost int
    time int
    city int
}

type PriorityQueue []State

func (pq PriorityQueue) Len() int { return len(pq) }
func (pq PriorityQueue) Less(i, j int) bool { return pq[i].cost < pq[j].cost }
func (pq PriorityQueue) Swap(i, j int) { pq[i], pq[j] = pq[j], pq[i] }
func (pq *PriorityQueue) Push(x interface{}) { *pq = append(*pq, x.(State)) }
func (pq *PriorityQueue) Pop() interface{} {
    old := *pq
    n := len(old)
    item := old[n-1]
    *pq = old[0 : n-1]
    return item
}

func minCost(maxTime int, edges [][]int, passingFees []int) int {
    n := len(passingFees)
    
    graph := make([][][2]int, n)
    for _, e := range edges {
        u, v, t := e[0], e[1], e[2]
        graph[u] = append(graph[u], [2]int{v, t})
        graph[v] = append(graph[v], [2]int{u, t})
    }
    
    dp := make([][]int, n)
    for i := 0; i < n; i++ {
        dp[i] = make([]int, maxTime+1)
        for j := 0; j <= maxTime; j++ {
            dp[i][j] = math.MaxInt32
        }
    }
    dp[0][0] = passingFees[0]
    
    pq := &PriorityQueue{}
    heap.Init(pq)
    heap.Push(pq, State{passingFees[0], 0, 0})
    
    for pq.Len() > 0 {
        s := heap.Pop(pq).(State)
        if s.city == n-1 {
            continue
        }
        for _, neighbor := range graph[s.city] {
            nextCity, travelTime := neighbor[0], neighbor[1]
            newTime := s.time + travelTime
            if newTime > maxTime {
                continue
            }
            newCost := s.cost + passingFees[nextCity]
            if newCost < dp[nextCity][newTime] {
                dp[nextCity][newTime] = newCost
                heap.Push(pq, State{newCost, newTime, nextCity})
            }
        }
    }
    
    minCost := math.MaxInt32
    for _, c := range dp[n-1] {
        if c < minCost {
            minCost = c
        }
    }
    if minCost == math.MaxInt32 {
        return -1
    }
    return minCost
}
