[LeetCode 1954 题](https://leetcode.com/problems/minimum-garden-perimeter-to-collect-enough-apples/)

 **难度：** 🟡 中等
 **主题：** 数学、二分查找

 ## 解决方案

 ## 问题理解

 该问题描述了一个无限二维网格，其中每个整数坐标`(i, j)`包含一棵苹果树。 一棵树上苹果的数量由距原点的曼哈顿距离决定：$$|i| + |j|$$我们想购买一块以`(0, 0)`且其边与坐标轴平行。 目标是找到这样一个正方形的最小可能周长，使得正方形内部或边界上的苹果总数至少为`neededApples`。 

关键细节是正方形始终以原点为中心。 如果正方形从`[-n, n]`在两个轴上，则其边长为：$$2n$$它的周长是：$$4 \times (2n) = 8n$$所以真正的挑战是确定最小的`n`使得正方形内的苹果总数至少为`neededApples`。 

约束非常重要：$$1 \le neededApples \le 10^{15}$$这立即告诉我们，对坐标进行强力模拟是不可能的。 即使遍历一个大正方形中的每个点也太慢了。 

重要的边缘情况包括非常小的值，例如`neededApples = 1`，其中第一个有效方块已包含比所需数量多得多的苹果。 另一个重要的情况是附近非常大的值`10^15`，其中整数溢出在某些语言中成为一个问题。 我们还需要确保实现正确处理一个方块大小不足但下一个方块有效的过渡点。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是逐层扩大正方形。 

对于选定的半径`n`，正方形覆盖所有坐标：$$-n \le x \le n$$

$$-n \le y \le n$$我们可以迭代正方形内的每个坐标，计算：$$|x| + |y|$$对于每个点，将所有苹果相加，并在总数达到后停止`neededApples`。 

这种方法是正确的，因为它直接遵循问题定义。 然而，这在计算上是不可行的。 半径的平方`n`包含：$$(2n+1)^2$$点，以及`n`本身可以变得非常大`10^{15}`苹果。 运行时间很快就会爆炸。 

### 关键见解

 我们不应该枚举坐标，而应该推导一个半径平方内苹果总数的数学公式`n`。 

如果我们仔细分析生长模式，则正方形内的苹果总数为：$$2n(n+1)(2n+1)$$这使我们能够计算任意的苹果总数`n`在恒定的时间内。 

那么问题就变成了寻找最小的`n`满意：$$2n(n+1)(2n+1) \ge neededApples$$由于该公式单调增加为`n`增加，二分搜索成为一种自然的优化技术。

 ## 算法演练

 1.观察每个有效的正方形都可以用半径表示`n`。 

广场的跨度从`[-n, n]`在两个轴上。 它的边长是`2n`，所以周长是：$$8n$$2. 求出正方形内苹果的总数。 

数学求和简化为：$$total(n) = 2n(n+1)(2n+1)$$该公式给出了以原点为中心的正方形内苹果的确切数量。 
3. 使用二分查找找到最小有效值`n`。 

自从`total(n)`严格增加为`n`增加，我们可以有效地搜索满足以下条件的最小半径：$$total(n) \ge neededApples$$4. 初始化二分查找范围。 

从以下开始：

 -`left = 1`-`right = 100000`对于问题约束来说，上限足够安全。 
5. 重复计算中点。 

对于每个中点`mid`，计算：$$apples = 2 \times mid \times (mid + 1) \times (2 \times mid + 1)$$6. 检查中点是否足够。 

- 如果`apples >= neededApples`， 店铺`mid`作为候选答案并继续搜索较小的值。 
- 否则，搜索更大的值。 
7. 二分查找完成后，返回周长。 

周长是：$$8 \times n$$### 为什么它有效

 苹果总数随着平方半径的增加而单调增加。 因此，一旦半径足够了，每个更大的半径也足够了。 这种单调性质保证了二分查找正确地找到最小有效半径。 

## Python 解决方案```python
class Solution:
    def minimumPerimeter(self, neededApples: int) -> int:
        def total_apples(n: int) -> int:
            return 2 * n * (n + 1) * (2 * n + 1)

        left = 1
        right = 100000

        while left < right:
            mid = (left + right) // 2

            if total_apples(mid) >= neededApples:
                right = mid
            else:
                left = mid + 1

        return left * 8
```实现首先定义一个辅助函数`total_apples`。 该函数计算半径平方内的苹果总数`n`使用导出的数学公式。 

二分搜索维持可能值的搜索范围`n`。 在每次迭代中，都会测试中点。 

如果中点已经提供了足够的苹果，它可能仍然不是最小的，因此算法继续搜索左半部分。 

如果中点不能提供足够的苹果，则需要更大的方块，因此算法会搜索右半部分。 

当循环终止时，`left`包含最小有效半径。 最终答案是将半径乘以周长`8`。 

## 解决方案```go
func minimumPerimeter(neededApples int64) int64 {
    totalApples := func(n int64) int64 {
        return 2 * n * (n + 1) * (2*n + 1)
    }

    var left int64 = 1
    var right int64 = 100000

    for left < right {
        mid := left + (right-left)/2

        if totalApples(mid) >= neededApples {
            right = mid
        } else {
            left = mid + 1
        }
    }

    return left * 8
}
```Go 的实现与 Python 解决方案非常相似。 主要区别是显式使用`int64`安全地处理高达`10^15`。 

中点计算使用：```go
mid := left + (right-left)/2
```这避免了二分搜索实现中常见的潜在溢出模式。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`neededApples`非常小，例如`1`。 幼稚的实现可能会错误地假设平方小于半径`1`是可能的。 然而，第一个有效方块已经包含`12`苹果。 二分查找正确识别半径`1`作为最小有效解。 

另一个关键的边缘情况恰好发生在层边界处。 例如，半径`1`准确地产生`12`苹果，而半径`2`准确地产生`60`。 如果实现使用了错误的比较运算符，例如`>`而不是`>=`，它可能会错误地移动到下一个半径。 该解决方案通过显式检查来避免这种情况：```
total_apples(mid) >= neededApples
```附近大量投入`10^15`是错误的另一个常见来源。 中间乘法值变得非常大，尤其是在 Go 或 Java 中，较小的整数类型可能会出现整数溢出。 Go 实现使用`int64`，它安全地处理问题约束所需的所有算术。
