[LeetCode 1995 题](https://leetcode.com/problems/count-special-quadruplets/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、枚举

 ## 解决方案

 ## 问题理解

 该问题要求我们计算**不同四胞胎**的数量`(a, b, c, d)`在给定数组中`nums`使得前三个元素的总和等于第四个元素，即`nums[a] + nums[b] + nums[c] == nums[d]`，并且指数满足`a < b < c < d`。 

简而言之，我们扫描数组以查找四个索引的每个组合，其中前三个数字与数组中后面的数字精确相加。 该数组是 **0 索引**，因此索引约束确保我们只考虑匹配数字之前的总和。 

输入`nums`是一个长度在 4 到 50 之间的整数数组。每个元素保证在 1 到 100 之间。这个约束告诉我们该数组足够小，O(n^3) 解决方案是可行的。 由于四元组需要四个元素，因此最小数组长度为 4。该问题还保证正整数，从而避免负和边缘情况。 

重要的边缘情况包括所有数字都相等的数组、没有有效四元组的数组以及多个组合产生相同总和的数组。 

## 方法

 蛮力方法很简单：枚举每个四元组`(a, b, c, d)`使用四个嵌套循环。 对于每个组合，检查前三个组合的总和是否等于第四个组合。 这保证是正确的，因为它检查了所有可能的四联体。 然而，时间复杂度为 O(n^4)，对于较大的数组来说可能太慢，尽管在这个问题中，n 的上限为 50，因此它可能仍然在可接受的限制内运行，但不是最佳的。 

更好的方法利用**哈希映射**来减少不必要的计算。 我们可以迭代第四个元素，而不是直接检查所有四元组`d`并记录所有可能的金额`nums[a] + nums[b]`对于指数`a < b < c`前`c`。 对于每个`c`，我们可以计算出有多少个之前见过的和匹配`nums[d] - nums[c]`。 这将时间复杂度降低到 O(n^3)，因为我们只需要三个嵌套循环和一个哈希映射查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^4) | O(n^4) | O(1) | O(1) | 直接枚举所有四元组 |
 | 最佳 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 使用哈希图存储对的总和以进行快速查找 |

 ## 算法演练

 1. 初始化变量`count`为 0 以跟踪有效四元组的数量。 
2. 使用索引的外循环迭代数组`c`从2开始到n-2。 这是四元组中的第三个元素。 
3. 初始化哈希图`sum_counts`存储对和的频率`(nums[a] + nums[b])`为了`a < b < c`。 
4. 对于每个`d`从`c+1`到 n-1，计算该对所需的目标总和`(a, b)`作为`target = nums[d] - nums[c]`。 
5. 检查是否`target`存在于`sum_counts`。 如果是，则增加`count`通过与相关的值`target`。 
6、后处理`d`对于当前的`c`， 更新`sum_counts`与所有金额`(nums[a] + nums[c])`为了`a < c`。 
7. 重复此操作，直至处理完所有索引。 

**为什么有效：** 该算法保持了以下不变式：`sum_counts`始终包含所有有效对的总和`(a, b)`在当前之前`c`。 通过这样做，我们可以有效地计算四联体，而无需多余的检查。 这确保所有四元组都满足`nums[a] + nums[b] + nums[c] == nums[d]`和`a < b < c < d`只计算一次。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countQuadruplets(self, nums: List[int]) -> int:
        n = len(nums)
        count = 0
        
        for c in range(2, n - 1):
            sum_counts = defaultdict(int)
            
            for a in range(c):
                sum_counts[nums[a] + nums[c]] += 1
            
            for d in range(c + 1, n):
                target = nums[d]
                count += sum_counts.get(target, 0)
        
        return count
```Python实现首先定义长度`n`并初始化`count`。 对于每个可能的第三个元素`c`，它使用字典来存储所有对的总和`(nums[a] + nums[c])`对于之前的指数`a`。 然后，它检查是否`nums[d]`可以由这些和中的任何一个组成。 这种方法确保我们不需要四个嵌套循环并避免冗余计算。 

## 解决方案```go
func countQuadruplets(nums []int) int {
    n := len(nums)
    count := 0

    for c := 2; c < n-1; c++ {
        sumCounts := make(map[int]int)
        
        for a := 0; a < c; a++ {
            sum := nums[a] + nums[c]
            sumCounts[sum]++
        }
        
        for d := c + 1; d < n; d++ {
            if val, exists := sumCounts[nums[d]]; exists {
                count += val
            }
        }
    }

    return count
}
```在 Go 中，我们使用`map[int]int`来存储金额。 其逻辑与 Python 非常相似。 Go 在从映射中检索时需要显式的存在性检查，我们使用`if val, exists := sumCounts[nums[d]]; exists`。 Go 不像 Python 那样有内置的 defaultdict，因此这种模式确保了正确性。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^3) | O(n^3) | 三个嵌套循环：对于每个`c`，我们迭代`a`和`d`。 每个内循环最多运行 n 次。 |
 | 空间| O(n^2) | O(n^2) | 哈希映射存储对的总和`(nums[a] + nums[c])`为所有人`a < c`。 |

 考虑到 n <= 50，立方时间复杂度是可以接受的。空间复杂度由哈希映射决定，它最多可以存储 n*(n-1)/2 个和。
