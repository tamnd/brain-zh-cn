 # LeetCode 1991 - 查找数组中的中间索引

 ## 问题理解

 该问题给了我们一个 0 索引的整数数组，称为`nums`。 我们需要找到一个索引，使得该索引左侧所有元素的总和等于该索引右侧所有元素的总和。 

更正式地说，对于索引`i`:

 - 左总和 =`nums[0] + nums[1] + ... + nums[i-1]`- 右和 =`nums[i+1] + nums[i+2] + ... + nums[n-1]`如果这两个和相等，那么`i`被认为是有效的中间索引。 

该问题特别要求最左边的有效索引，这意味着如果多个索引满足条件，我们将返回最小的一个。 如果不存在有效索引，我们返回`-1`。 

一个重要的细节是如何处理边缘位置：

 - 如果`i == 0`，左边不包含任何元素，所以左边的和是`0`- 如果`i == n - 1`，右边不包含任何元素，所以右边的和是`0`限制相对较小：

 -`1 <= nums.length <= 100`-`-1000 <= nums[i] <= 1000`尽管输入大小足够小，足以让暴力解决方案通过，但问题本质上是一个前缀和问题，并且有一个更高效、更优雅的干净线性时间解决方案。 

有几种边缘情况很容易导致错误：

 - 只有一个元素的数组
 - 中间索引位于位置的数组`0`- 中间索引位于最后位置的数组
 - 包含负数的数组
 - 具有多个有效中间索引的数组，其中仅应返回最左边的索引
 - 没有有效答案的数组

 正确的实现必须仔细处理所有这些场景。 

## 方法

 ### 暴力方法

 最直接的解决方案是单独检查每个索引。 

对于每个索引`i`，我们计算：

 - 之前所有元素的总和`i`- 之后所有元素的总和`i`如果两个总和相等，我们立即返回`i`。 

这种方法是正确的，因为它直接遵循问题定义。 检查每个可能的索引，并返回第一个有效的索引。 

然而，效率低下来自于反复重新计算总和。 对于每个索引，我们可能会再次扫描数组的大部分。 如果数组长度是`n`，那么每个索引可能需要`O(n)`工作，导致整体复杂性`O(n²)`。 

尽管约束足够小，该解决方案在实践中可行，但它并不是最佳的。 

### 最优前缀和方法

 关键的观察是我们不需要重复重新计算总和。 

如果我们知道：

 - 数组的总和
 - 左侧元素的运行总和

 然后我们就可以立即计算出正确的总和。 

认为：

-`left_sum`是索引之前元素的总和`i`-`total_sum`是整个数组的总和
 -`nums[i]`是当前元素

 然后：```
right_sum = total_sum - left_sum - nums[i]
```这是有效的，因为：

 -`total_sum`包含一切
 - 减去`left_sum`删除左侧
 - 减去`nums[i]`删除当前元素
 - 剩余的值是右侧的总和

 现在我们可以判断是否索引`i`在常数时间内有效。 

这将总复杂度降低到`O(n)`。

 ## 算法演练

 ### 最优前缀和算法

 1. 使用以下方法计算数组的总和`sum(nums)`。 

这给了我们数组中每个元素的总和。 我们将使用它来有效地导出右侧总和。 
2. 初始化一个名为`left_sum`到`0`。 

在开始迭代之前，索引左侧没有元素`0`。 
3. 使用索引和值迭代数组。 

在每个位置，我们要确定当前索引是否满足中间索引条件。 
4. 计算右侧总和。 

公式为：```
right_sum = total_sum - left_sum - current_value
```这将从总数中删除左侧部分和当前元素，只留下右侧。 
5. 比较`left_sum`和`right_sum`。 

如果相等，则立即返回当前索引。 

由于我们从左到右迭代，找到的第一个有效索引自动成为最左边的有效答案。 
6. 更新`left_sum`。 

将当前值添加到`left_sum`在进入下一个迭代之前。 
7. 如果循环结束时没有找到有效索引，则返回`-1`。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 处理索引前`i`,`left_sum`始终等于严格左边的所有元素的总和`i`。 

使用总和，我们可以在常数时间内导出精确的右侧和。 由于每个索引都被检查一次并且立即返回第一个有效索引，因此该算法正确地找到了最左边的中间索引。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMiddleIndex(self, nums: List[int]) -> int:
        total_sum = sum(nums)
        left_sum = 0

        for index, value in enumerate(nums):
            right_sum = total_sum - left_sum - value

            if left_sum == right_sum:
                return index

            left_sum += value

        return -1
```实现首先计算数组的总和。 这使得算法无需重复扫描数组即可导出右侧和。 

变量`left_sum`跟踪当前索引之前元素的累积和。 最初，它是`0`因为索引左侧没有元素`0`。 

该循环只对每个元素处理一次。 对于每个位置，代码使用以下公式计算右侧总和：```python
right_sum = total_sum - left_sum - value
```如果左右总和匹配，则立即返回当前索引。 因为迭代是从左到右进行的，所以这保证了返回的索引是最左边的有效答案。 

检查条件后，将当前值添加到`left_sum`以便它正确地表示下一次迭代的左侧总和。 

如果没有找到有效的索引，函数返回`-1`。 

## 解决方案```go
func findMiddleIndex(nums []int) int {
    totalSum := 0

    for _, value := range nums {
        totalSum += value
    }

    leftSum := 0

    for index, value := range nums {
        rightSum := totalSum - leftSum - value

        if leftSum == rightSum {
            return index
        }

        leftSum += value
    }

    return -1
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

由于 Go 没有提供内置的`sum()`对于切片函数，总和是使用循环手动计算的。 

Go 切片是基于引用的结构，但由于该算法仅读取值并使用一些整数变量，因此除了常量空间之外不需要额外的内存分配。 

约束很小，因此整数溢出不是这个问题的问题。

 该算法对数组执行两次线性遍历：

 - 一次计算总和

该算法不使用任何与输入大小成比例的辅助数据结构，因此空间复杂度是恒定的。

 ## 边缘情况

 ### 单元素数组

 仅包含一个元素的数组是一种非常重要的边界情况。 例如：```
[5]
```在索引处`0`，两边都没有元素，所以左边和右边的和都是`0`。 因此正确答案是`0`。 

有缺陷的实现可能会错误地假设双方都必须包含元素。 当前的解决方案可以自然地处理这个问题，因为：```
right_sum = total_sum - left_sum - value
```变成：```
5 - 0 - 5 = 0
```与左边的总和相匹配。 

### 开头的中间索引

 考虑：```
[2, 1, -1]
```在索引处`0`:

 - 左总和 =`0`- 右和 =`1 + (-1) = 0`因此答案应该是`0`。 

这种情况可能会暴露出相差一的错误，特别是如果实现错误地将当前元素包含在左侧计算中。 该解决方案通过更新来避免这种情况`left_sum`仅在检查当前索引后。 

### 多个有效中间索引

 考虑：```
[0, 0, 0]
```每个索引都满足条件，因为左和右总和总是`0`。 

然而，该问题需要最左边的有效索引，即`0`。 

该实现可以正确处理此问题，因为它从左到右迭代并立即返回遇到的第一个有效索引。 

### 负数数组

 负值会使平衡条件不太直观。 例如：```
[-1, -1, -1, 0, 1, 1]
```有效答案是`0`。 

天真的直觉可能会假设总和必须单调增长，但负数会使该假设无效。 前缀和方法仍然完全正确，因为它使用精确的算术而不是依赖于排序属性。
