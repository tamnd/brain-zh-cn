[LeetCode 1948 题](https://leetcode.com/problems/delete-duplicate-folders-in-system/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、字符串、Trie、哈希函数

 ## 解决方案

 ## 问题理解

 该问题给出了一个表示为绝对路径列表的分层文件系统，其中每个路径都是从根文件夹到叶文件夹的文件夹名称数组。 从这些路径中，我们必须重建文件夹的隐式树结构，其中每个节点代表一个文件夹，边代表父子关系。 

如果两个文件夹的整个子树结构相同，则认为它们是相同的，这意味着它们递归地包含具有相同结构的同一组子文件夹。 如果两个或多个文件夹相同，则必须删除所有文件夹，包括其子树中的所有文件夹。 重要的是，删除是基于树的初始快照，这意味着一旦识别并标记相同的文件夹，删除就会发生一次，并且删除后我们不会重新计算身份。 

输出必须是删除后剩余的文件夹路径，重建为字符串列表。 

约束表明输入可能很大，最多有 20,000 条路径，总字符总数最多为 200,000 个，因此任何解决方案在总节点数上都必须接近线性或接近线性。 简单的子树比较方法会太慢。 

重要的边缘情况包括没有重复的树、深度嵌套的单链、不同级别的多个相同子树，以及删除仅影响子树的一部分而不影响其祖先的情况，除非明确标记。 同样重要的是，文件夹标识取决于结构，而不仅仅是单个级别的名称。 

关键保证是没有两条路径通向同一文件夹，并且每个非根文件夹都有其父文件夹，这确保可以直接构建有效的树。 

## 方法

 暴力方法将构建完整的树，并且对于每个节点，通过序列化或递归检查结构相等性将其子树与每个其他节点的子树进行比较。 这导致多次重复遍历大型子树，在最坏的情况下导致指数或二次行为。 

优化的关键见解是可以使用结构序列化唯一地表示子树身份，并且相同的子树将共享相同的序列化字符串。 通过自下而上计算每个子树的规范签名并使用哈希图来计算出现次数，我们可以在单次遍历中识别重复的子树。 一旦识别出重复项，第二次遍历就可以标记要删除的节点。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N²·S) | O(N) | 将每个子树与所有其他子树进行比较 |
 | 最优（Trie + 序列化 + 哈希）| O(N·S) | O(N·S) | O(N·S) | O(N·S) | 构建树、序列化子树、散列重复项 |

 这里，N 是节点数，S 是子树表示的平均大小。 

## 算法演练

 最佳解决方案依赖于从文件夹路径构建树 (trie)，然后计算每个子树的唯一结构签名。

1. 首先，我们构建一个类似于 trie 的树，其中每个节点代表一个文件夹，边代表子文件夹关系。 每个节点将其子节点存储在以文件夹名称为键的字典中。 这种结构使我们能够从路径列表中有效地重建层次结构。 
2. 树构建完成后，我们执行后序遍历来计算每个子树的序列化字符串。 序列化对子级的结构和身份进行编码。 例如，具有子“a”和“b”的节点将具有基于排序的子签名的签名，以确保确定性表示。 
3. 在遍历过程中，我们维护一个哈希图，用于计算每个子树序列化在整个树中出现的次数。 这很重要，因为只有出现多次的子树才被视为重复。 
4. 计算完所有子树签名后，我们执行第二次 DFS 遍历。 任何序列化频率大于 1 的节点都被标记为已删除。 当节点被标记为删除时，其整个子树将从输出中排除。 
5. 最后，我们执行另一次遍历，收集从根节点到叶节点的所有剩余有效路径（未标记为已删除），构建输出列表。 

为什么有效：序列化确保两个子树相同当且仅当它们的结构表示相同。 因为我们是自下而上计算的，所以每个子树都由其子树的结构唯一标识，从而可以通过散列直接检测到重复项。 

## Python 解决方案```python
from typing import List, Dict
from collections import defaultdict

class Solution:
    def deleteDuplicateFolder(self, paths: List[List[str]]) -> List[List[str]]:
        class Node:
            def __init__(self):
                self.children: Dict[str, "Node"] = {}
                self.deleted = False
                self.sig = ""

        root = Node()

        for path in paths:
            cur = root
            for folder in path:
                if folder not in cur.children:
                    cur.children[folder] = Node()
                cur = cur.children[folder]

        freq = defaultdict(int)

        def build_sig(node: Node) -> str:
            if not node.children:
                node.sig = "()"
                freq[node.sig] += 1
                return node.sig

            parts = []
            for name in sorted(node.children.keys()):
                child_sig = build_sig(node.children[name])
                parts.append(name + child_sig)

            node.sig = "(" + "".join(parts) + ")"
            freq[node.sig] += 1
            return node.sig

        build_sig(root)

        def mark(node: Node):
            if node != root and freq[node.sig] > 1:
                node.deleted = True
                return
            for child in node.children.values():
                mark(child)

        mark(root)

        res = []

        def collect(node: Node, path: List[str]):
            if node.deleted:
                return
            if path:
                res.append(path[:])
            for name, child in node.children.items():
                collect(child, path + [name])

        collect(root, [])

        return res
```该代码首先构建一个表示文件夹结构的 trie。 然后，它使用后序 DFS 计算子树签名。 每个签名都是排序子项的字符串编码，确保结构唯一性。 频率图计算每个签名出现的次数。 然后，第二个 DFS 将具有重复签名的节点标记为已删除。 最后，第三次遍历收集剩余的有效路径。 

## 解决方案```go
package main

import (
	"sort"
	"strings"
)

type Node struct {
	children map[string]*Node
	sig      string
	deleted  bool
}

func newNode() *Node {
	return &Node{
		children: make(map[string]*Node),
	}
}

func deleteDuplicateFolder(paths [][]string) [][]string {
	root := newNode()

	for _, path := range paths {
		cur := root
		for _, folder := range path {
			if _, ok := cur.children[folder]; !ok {
				cur.children[folder] = newNode()
			}
			cur = cur.children[folder]
		}
	}

	freq := make(map[string]int)

	var buildSig func(*Node) string
	buildSig = func(node *Node) string {
		if len(node.children) == 0 {
			node.sig = "()"
			freq[node.sig]++
			return node.sig
		}

		keys := make([]string, 0, len(node.children))
		for k := range node.children {
			keys = append(keys, k)
		}
		sort.Strings(keys)

		var sb strings.Builder
		sb.WriteString("(")
		for _, k := range keys {
			childSig := buildSig(node.children[k])
			sb.WriteString(k)
			sb.WriteString(childSig)
		}
		sb.WriteString(")")

		node.sig = sb.String()
		freq[node.sig]++
		return node.sig
	}

	buildSig(root)

	var mark func(*Node)
	mark = func(node *Node) {
		if node != root && freq[node.sig] > 1 {
			node.deleted = true
			return
		}
		for _, child := range node.children {
			mark(child)
		}
	}

	mark(root)

	var res [][]string
	var collect func(*Node, []string)
	collect = func(node *Node, path []string) {
		if node.deleted {
			return
		}
		if len(path) > 0 {
			tmp := make([]string, len(path))
			copy(tmp, path)
			res = append(res, tmp)
		}
		for name, child := range node.children {
			collect(child, append(path, name))
		}
	}

	collect(root, []string{})

	return res
}
```在 Go 中，我们显式管理映射和键排序，因为映射迭代是不确定的。 我们使用`strings.Builder`用于高效的字符串连接。 与Python不同的是，我们在存储结果时必须手动复制切片以避免突变问题。 

## 工作示例

 ### 示例 1

 输入：`[["a"],["c"],["d"],["a","b"],["c","b"],["d","a"]]`树结构创建：

 -a->b
 -c->b
 -d->a

 子树签名：

 - “b”出现在“a”和“c”下 → 检测到相同的子树
 - 因此，a和c子树被删除

 遍历标记：

 - sig（“b”）=“（）”
 - sig("a") = "(b())"
 - sig("c") = "(b())"
 - freq("(b())") = 2 → 删除 a 和 c

 剩余：

 -d
 - 日/日

 输出：`[["d"],["d","a"]]`### 示例 2

 我们自下而上计算子树签名。 关键的重复模式是：

 - 以“/a/b/x”为根的子树与以“/w”为根的子树匹配

 因此两者都被标记。 

标记后，不执行重新计算，因此除非最初标记，否则新的相同结构不会被删除。 

剩余文件夹：

 -c、c/b
 -a、a/b

 ### 示例 3

 所有文件夹都会产生唯一的子树签名，因此每个签名的频率为1。不会发生删除，所有路径都会保留。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N·log N + N) | O(N·log N + N) | 对每个节点的子节点进行排序加上 DFS 遍历 |
 | 空间| O(N·S) | O(N·S) | trie节点和子树签名的存储 |

 主要成本是构建子树签名并在每个节点对子树进行排序。 由于每个节点都被处理一次并且总字符数受到限制，因此该解决方案保持高效。

 ## 边缘情况

 一种重要的边缘情况是文件夹名称相同但结构不同。 该算法可以正确处理此问题，因为身份基于子树序列化，而不仅仅是名称。 

另一个边缘情况是深度嵌套，其中只有叶节点是相同的。 由于序列化是自下而上计算的，因此首先比较叶节点并正确向上传播，确保准确检测。 

第三种边缘情况是删除子树会使父文件夹随后变得相同。 该问题明确指出，基于初始标记，删除仅发生一次，并且此实现通过将标记与集合分离而无需重新计算来尊重这一点。
