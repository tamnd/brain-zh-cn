[LeetCode 1946 题](https://leetcode.com/problems/largest-number-after-mutating-substring/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、贪婪

 ## 解决方案

 ## 问题理解

 该问题要求我们在输入字符串的一个连续子字符串上选择性地应用单个转换操作后构造字典顺序上最大的可能数字字符串`num`。 中的每一位数字`num`可以使用固定映射数组独立变换`change`， 在哪里`change[d]`定义数字的替换数字`d`。 

我们最多可以选择一个子字符串，并将转换应用于该子字符串内的每个数字一次。 所选子字符串之外的数字保持不变。 目标是选择子字符串边界以及是否应用该操作，以使结果字符串表示按字典顺序排列的最大可能整数。 

输入约束表明`num`长度可达 100,000，这强烈表明任何二次或更差的解决方案都是不可行的。 这`change`数组的大小固定为 10，这意味着数字转换是恒定时间查找。 

一些边缘情况很重要。 如果数字变换没有改善数字，则正确答案是原始字符串。 如果多个子串可以改善结果，我们必须确保在只能改变一个连续片段的约束下，选择一个能够最大化最终值的子串。 当转换最初增加数字值但后来减少它时，会发生另一种微妙的情况，这定义了有效子字符串的边界。 

## 方法

 蛮力方法考虑了每个可能的子串`num`。 对于每个子字符串，我们模拟应用数字转换并构造一个新字符串。 然后我们比较所有结果并按字典顺序选择最大值。 这是有效的，因为它详尽地检查了所有有效操作，确保了正确性。 然而，它太慢了，因为有 O(n^2) 个子字符串，并且每个转换成本为 O(n)，导致在简单实现中为 O(n^3) 或最多为 O(n^2)，这对于 n = 100,000 来说都太大了。 

关键的见解是我们不需要尝试所有子字符串。 相反，我们观察到，一旦我们决定在某个位置开始变异，只要变换不减少数字值，我们就应该继续变异。 一旦变换变得比原来的数字更差，我们就必须停止，因为进一步扩展只会使数字更小，而且我们只允许有一个连续的段。 

因此，最优解是贪婪的：我们找到第一个应用的位置`change`提高数字，从那里开始突变，并在保持不减少的情况下继续。 这确保了最大的词典编纂增益。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 尝试所有子字符串并模拟转换 |
 | 最优贪心 | O(n) | O(n) | 单次寻找最佳有效突变窗口 |

 ## 算法演练

 最佳算法基于扫描一次字符串并仔细决定突变段的开始和结束位置。 

1. 转换字符串`num`到一个字符列表中，这样我们就可以有效地修改它。 这避免了重复的字符串连接，这在 Python 中是昂贵的。 
2. 初始化布尔标志`started`追踪我们是否已经开始应用突变。 最初我们没有开始，是因为我们没有找到有利的起点。 
3. 迭代每个索引`i`从左到右的字符串。 在每个位置，比较原始数字`num[i]`及其转化后的价值`change[num[i]]`。 
4. 如果我们还没有开始突变并且转换后的数字大于原始数字，我们就从这个索引开始突变。 从现在开始，我们将变换应用于每个数字，直到我们决定停止。 
5. 一旦突变开始，我们就会继续应用它，只要`change[num[i]]`大于或等于`num[i]`。 这确保我们不会减少数字的值。 
6. 如果我们遇到一个数字，其中`change[num[i]]`严格小于`num[i]`，我们立即停止突变。 从这一点开始，所有剩余的数字保持不变，因为只允许有一个连续的子字符串。 
7. 处理整个字符串后，将字符列表转换回字符串并返回。 

其工作原理：该算法强制执行单个连续段，以实现最大效益。 贪婪的选择确保我们尽早开始以获得最大的词典编纂增益，并且在继续会损害结果时准确地停止。 这创建了一个无法通过移动边界来改进的最佳窗口。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumNumber(self, num: str, change: List[int]) -> str:
        digits = list(num)
        started = False

        for i in range(len(digits)):
            d = ord(digits[i]) - ord('0')
            transformed = change[d]

            if not started:
                if transformed > d:
                    started = True
                    digits[i] = str(transformed)
            else:
                if transformed >= d:
                    digits[i] = str(transformed)
                else:
                    break

        return "".join(digits)
```实现直接遵循贪婪策略。 我们对字符串进行一次迭代，决定何时开始突变，并在它保持非递减的情况下应用转换。 这`started`flag 确保我们维护单个连续段约束。 

## 解决方案```go
func maximumNumber(num string, change []int) string {
	runes := []byte(num)
	started := false

	for i := 0; i < len(runes); i++ {
		d := int(runes[i] - '0')
		transformed := change[d]

		if !started {
			if transformed > d {
				started = true
				runes[i] = byte(transformed + '0')
			}
		} else {
			if transformed >= d {
				runes[i] = byte(transformed + '0')
			} else {
				break
			}
		}
	}

	return string(runes)
}
```在 Go 中，我们使用字节切片而不是字符串，因为字符串是不可变的。 转换为字节切片允许就地修改。 该逻辑完全反映了 Python 解决方案，具有用于数字处理的显式整数到字节转换。

 ### 示例 1

 输入：`num = "132"`,`change = [9,8,5,0,3,6,4,2,6,8]`我们一步步处理：

 在索引 0 处，数字是`1`，变换后为`8`。 由于 8 > 1，我们从这里开始变异。 

在索引 0 处：

 | --- | --- | --- | --- |
 | 0 | 1 | 8 | 开始，替换为 8 |

 | 1 | 3 | 0 | 停止，因为 0 < 3 |

 最终字符串变为`"832"`。

 输入：`num = "021"`,`change = [9,4,3,5,7,2,1,9,0,6]`在索引 0 处，数字`0`映射到`9`，这是有益的，所以我们立即开始。 

在索引 0 处：

 | --- | --- | --- | --- |
 | 0 | 0 | 9 | 启动、替换 |

 在索引 1 处：

 | 我| 数字| 改变[d] | 行动|
 | --- | --- | --- | --- |
 | 1 | 2 | 3 | 继续 |

 在索引 2 处：

 | 我| 数字| 改变[d] | 行动|
 | --- | --- | --- | --- |
 | 2 | 1 | 4 | 继续 |

 最终结果是`"934"`。 

### 示例 3

 输入：`num = "5"`,`change = [1,4,7,5,3,2,5,6,9,4]`在索引 0 处，数字`5`映射到`2`，这更糟。 我们从不开始突变。

 ## 边缘情况

 One important edge case is when no digit in the string can be improved by its mapping. 在这种情况下，算法绝不能启动变异窗口，并且原始字符串必须不变地返回。 这`started`flag 确保了这一点，因为它仅在发现严格改进时才设置。 

当改进从第一个字符开始并持续到整个字符串时，会出现另一种边缘情况。 发生这种情况时`change[d] >= d`对于第一个有利开始后的所有数字。 该算法通过从不遇到中断条件来自然地处理这个问题。 

第三种边缘情况涉及早期改进，然后映射值突然下降。 这很重要，因为它定义了正确的停止边界。 该算法明确地在第一个位置处中断，其中`change[d] < d`变异开始后，确保我们不违反单子串约束或减少结果的词典价值。
