 # LeetCode 1969，数组元素的最小非零积

 ## 问题理解

 问题给了我们一个整数`p`并定义一个包含每个数字的数组`1`到`2^p - 1`。 每个数字都使用精确的二进制表示`p`位。 

我们被允许重复执行一项特殊操作。 在一次操作中，我们选择两个数字并在它们之间交换一位位置。 交换必须发生在两个数字的相同位索引处。 

目标是使所有数字的乘积尽可能小，同时确保乘积仍然不为零。 由于数字可能变得非常大，我们返回模数的答案`10^9 + 7`。 

重要的细节是模数仅在最后应用。 我们必须首先最小化实际的数学乘积。 

约束条件`1 <= p <= 60`非常重要。 数组大小为`2^p - 1`，即使对于中等值，它也会变得天文数字般大`p`。 例如：

-`p = 20`给出超过一百万个数字
 -`p = 60`给出超过`10^18`数字

 这立即告诉我们，我们无法显式构建或操作该数组。 解决方案必须依赖数学推理。 

另一个关键观察结果是，交换位保留了整个数组中每个位位置处设置位的总数。 我们不能任意改变集合的二进制表示，只能在数字之间重新分配位。 

最重要的边缘情况是：

 -`p = 1`，其中数组仅包含`[1]`- 非常大`p`，其中直接计算会溢出正常整数范围
 - 确保产品永远不会变为零，因为引入了`0`使结果无效

 ## 方法

 ### 蛮力方法

 强力解决方案将尝试模拟所有可能的交换并搜索最小的产品排列。 

该数组包含`2^p - 1`元素，并且每个元素都有`p`位。 每个操作都可以选择：

 - 任意一对数字
 - 任意位位置

 可到达状态的数量呈指数增长。 即使对于小`p`，搜索空间变得大得不可思议。 

此外，评估每个州的产品成本很高，因为数字本身就很大。 

这种方法在理论上是正确的，因为它探索了所有可能的配置，但在计算上是不可行的。 

### 关键见解

 关键的数学见解是最小非零乘积发生在以下情况：

 - 一个数保持尽可能大，即`2^p - 1`- 剩余的数字配对，以便大多数成为：

 -`1`-`2^p - 2`最优排列变为：

 - 一份`2^p - 1`-`(2^(p-1) - 1)`的副本`2^p - 2`-`(2^(p-1) - 1)`的副本`1`这导致了以下公式：$$(2^p - 1) \times (2^p - 2)^{(2^{p-1} - 1)}$$其工作原理来自 AM-GM 风格的直觉，即对于固定的位分布，当值被推向极端而不是保持平衡时，乘积会变小。 

我们必须使用模幂有效地计算它。 

最终公式为：$(2^p-1)\cdot(2^p-2)^{(2^{p-1}-1)}$## 方法比较

 ## 算法演练

 1. 计算数组中的最大值。 

最大的数是：$$2^p - 1$$这是二进制表示包含所有内容的数字`1`s。 
2. 计算第二大值。 

价值：$$2^p - 2$$已设置除最低有效位之外的所有位。 
3. 确定该值出现的次数。 

指数变为：$$2^{p-1} - 1$$这来自最佳重新分配模式中的配对数字。 
4. 使用模幂运算。 

直接计算幂是不可能的，因为指数可能超过`10^18`。 

相反，使用快速求幂：

 - 反复将底座摆正
 - 每一步将指数减半
 - 当指数位被设置时乘以结果
 5. 将最终分量相乘。 

答案是：$$(2^p - 1) \times (2^p - 2)^{(2^{p-1}-1)} \mod (10^9+7)$$### 为什么它有效

 允许的交换保留每个位置的设置位总数。 为了最小化非零乘积，我们希望尽可能多的数字变小，同时将剩余的位集中到更少的大数字中。 

最佳配置将这些值推向极限：

 - 许多数字变成`1`- 许多数字变成`2^p - 2`- 还剩下一个号码`2^p - 1`这种布置满足位计数约束，同时产生尽可能最小的非零乘积。 

## Python 解决方案```python
class Solution:
    def minNonZeroProduct(self, p: int) -> int:
        MOD = 10**9 + 7

        max_value = (1 << p) - 1
        second_max = max_value - 1
        exponent = (1 << (p - 1)) - 1

        return (max_value * pow(second_max, exponent, MOD)) % MOD
```实现直接遵循数学公式。 

首先，我们计算`max_value = 2^p - 1`使用位移位。 自从`1 << p`等于`2^p`，减一产生全 1 的二进制数。 

下一个，`second_max`变成`2^p - 2`。 

指数计算如下`2^(p-1) - 1`。 

Python 提供了内置的模幂函数：```python
pow(base, exponent, mod)
```这在对数时间内在内部执行快速求幂，这对于有效处理非常大的指数至关重要。 

最后，我们乘以剩余的因子`max_value`并对结果取模`10^9 + 7`。 

## 解决方案```go
func minNonZeroProduct(p int) int {
	const MOD int64 = 1_000_000_007

	maxValue := (int64(1) << p) - 1
	secondMax := maxValue - 1
	exponent := (int64(1) << (p - 1)) - 1

	power := modPow(secondMax, exponent, MOD)

	return int((maxValue * power) % MOD)
}

func modPow(base, exponent, mod int64) int64 {
	result := int64(1)

	base %= mod

	for exponent > 0 {
		if exponent&1 == 1 {
			result = (result * base) % mod
		}

		base = (base * base) % mod
		exponent >>= 1
	}

	return result
}
```Go 解决方案使用自定义模幂帮助器，因为 Go 没有提供与 Python 的三参数等效的内置函数`pow`。 

实现使用`int64`贯穿始终，因为诸如此类的价值观`2^60`超出标准 32 位整数的范围。 

求幂循环反复对底数进行平方并将指数减半，以确保对数运行时间。

 ## 边缘情况

 ### 边缘情况 1，`p = 1`这是可能的最小输入。 该数组仅包含`[1]`，因此不可能进行交换。 一个常见的错误是指数处理不当：$$2^{p-1} - 1 = 0$$实现正确计算`pow(0, 0, MOD)`作为`1`，给出正确的最终答案`1`。 

### 边缘案例 2，非常大`p`什么时候`p = 60`，值如`2^60`超过 32 位整数限制。 使用常规整数的简单实现可能会溢出。 

Python 解决方案自然支持任意精度整数。 Go 解决方案明确使用`int64`安全地处理这些值。 

### 边缘情况 3，避免零乘积

 如果互换产生哪怕一个零值，总乘积也将变为零，这是该问题所禁止的。 

数学推导保证了最优排列使每个数字都为正。 最小值变为`1`， 绝不`0`，确保产品保持非零。
