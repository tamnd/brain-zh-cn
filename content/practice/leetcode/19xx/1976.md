[LeetCode 1976 题](https://leetcode.com/problems/number-of-ways-to-arrive-at-destination/)

 **难度：** 🟡 中等
 **主题：** 动态规划、图论、拓扑排序、最短路径

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个加权的无向图。 每个交叉路口都是一个节点，每条道路都是一条有行程时间的边。 我们从十字路口开始`0`想要到达十字路口`n - 1`。 

重要的细节是我们不只是寻找最短距离。 我们必须计算有多少条不同的路径达到了最短旅行时间。 

例如，假设从节点出发的最短旅行时间`0`到节点`6`是`7`。 可能有几条不同的路线，其总边权重总计为`7`。 任务是计算所有此类最短路径。 

该图保证是连通的，这意味着每个节点都可以从其他每个节点到达。 道路是双向的，因此如果有一条道路从`u`到`v`，我们还可以从`v`到`u`以相同的成本。 

约束条件很重要：

 -`n <= 200`- 边权重可以非常大，最多可达`10^9`- 该图可能很稠密，最多可达`n * (n - 1) / 2`边缘

 由于边权重为正，因此强烈建议使用 Dijkstra 算法来实现最短路径。 

棘手的部分是在计算最小距离时计算存在多少条最短路径。 

一些边缘情况很重要：

 - 多条最短路径可能通向同一节点。 
- 在某些语言中，非常大的边权重需要仔细处理整数溢出。 
- 答案可能会变大，所以我们必须将其模数返回`10^9 + 7`。 
- 从源到目的地可能存在直接边缘，但也可能存在总成本相同的间接路径。 
- 由于图是连接的，我们永远不需要处理不可达的节点。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试枚举来自节点的每条可能的路径`0`到节点`n - 1`。 对于每条路径，我们将计算其总行程时间并将其与当前最短距离进行比较。 

这种方法是正确的，因为最终每条有效路径都会被探索。 探索完所有路径后，我们可以确定：

 1.最短的总行程时间。 
2. 达到该最小值的路径数量。 

然而，这种方法是完全不切实际的。 

一个图可以包含指数级多的路径。 即使只有 200 个节点，简单路径的数量也可能变得巨大。 DFS 回溯解决方案很快就会超出时间限制。 

此外，由于该图包含循环，因此我们需要额外的簿记以避免无限递归。 

### 最佳方法

 关键的见解是，这从根本上来说是一个具有正边权重的最短路径问题，这使得 Dijkstra 算法非常理想。 

通常，Dijkstra 仅计算到每个节点的最小距离。 我们稍微扩展它，以便它还跟踪到达每个节点的最短路径的数量。 

我们维护两个数组：

 -`dist[i]`= 距节点的最短已知距离`0`到节点`i`-`ways[i]`= 达到的最短路径数`dist[i]`在 Dijkstra 期间放松边缘时：

 - 如果我们找到到节点的严格较短的路径，我们会更新其距离并替换其路径计数。 
- 如果我们找到另一条具有完全相同的最短距离的路径，我们会添加从当前节点开始的路径数。 

由于 Dijkstra 按非递减距离顺序处理节点，因此每个最短路径贡献都会正确累积。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 探索所有可能的路径 |
 | 最佳| O((V + E) log V) | O(V + E) | Dijkstra 与路径计数 |

 ## 算法演练

 1. 为图构建邻接表。 

由于该图是无向的，因此每条路`[u, v, time]`是在两个方向上添加的。 邻接列表允许有效地遍历邻居。 
2. 初始化最短距离数组。 

创建一个`dist`数组，其中每个值都以无穷大开始。 放`dist[0] = 0`因为从源到自身的距离为零。 
3. 初始化路径计数数组。 

创建一个`ways`数组初始化为零。 放`ways[0] = 1`因为只有一种方法可以留在起始节点。 
4. 创建优先级队列。 

使用最小堆存储对`(distance, node)`。 从推开始`(0, 0)`。 

堆确保我们始终处理当前已知距离最小的节点。 
5. 使用Dijkstra算法处理节点。 

重复从堆中弹出最小距离条目。 

如果弹出的距离大于存储的最短距离，则跳过它，因为它代表过时的堆条目。 
6. 放松所有相邻的边缘。 

对于每个邻居：

 - 计算`new_distance = current_distance + edge_weight`。 
- 如果`new_distance < dist[neighbor]`：

- 更新`dist[neighbor]`- 放`ways[neighbor] = ways[current_node]`- 将更新后的状态推送到堆中
 - 否则如果`new_distance == dist[neighbor]`：

 - 添加当前的路数：`ways[neighbor] += ways[current_node]`- 应用模数`10^9 + 7`7. 继续，直到堆为空。 

在最后，`ways[n - 1]`包含到达目的地的最短路径的数量。 

### 为什么它有效

 Dijkstra 算法保证当节点以其最小距离进行处理时，该距离是最终的，因为所有边权重都是正的。 

这`ways`数组保持不变式`ways[i]`始终存储实现的最短路径数`dist[i]`。 

每当我们发现：

 - 严格更好的距离，旧路径不相关并被替换。 
- 同样短的距离，我们找到了额外的最短路径并添加它们。 

因此，在处理整个图之后，目标节点包含正确的最短路径计数。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def countPaths(self, n: int, roads: List[List[int]]) -> int:
        MOD = 10**9 + 7

        # Build adjacency list
        graph = [[] for _ in range(n)]

        for u, v, time in roads:
            graph[u].append((v, time))
            graph[v].append((u, time))

        # Shortest distance array
        dist = [float('inf')] * n
        dist[0] = 0

        # Number of shortest ways
        ways = [0] * n
        ways[0] = 1

        # Min heap: (distance, node)
        heap = [(0, 0)]

        while heap:
            current_dist, node = heapq.heappop(heap)

            # Skip outdated entries
            if current_dist > dist[node]:
                continue

            for neighbor, weight in graph[node]:
                new_dist = current_dist + weight

                # Found shorter path
                if new_dist < dist[neighbor]:
                    dist[neighbor] = new_dist
                    ways[neighbor] = ways[node]

                    heapq.heappush(heap, (new_dist, neighbor))

                # Found another shortest path
                elif new_dist == dist[neighbor]:
                    ways[neighbor] = (
                        ways[neighbor] + ways[node]
                    ) % MOD

        return ways[n - 1]
```该实现首先构建一个邻接列表，因为具有可变数量邻居的图可以通过这种方式有效地表示。 

这`dist`数组跟踪到每个节点的最小已知距离。 最初，除了源之外，每个值都是无穷大。 

这`ways`数组存储每个节点存在多少条最短路径。 最初只有节点`0`有一条有效路径。 

优先级队列驱动 Dijkstra 算法。 每个堆条目包含与节点配对的当前最短已知距离。 

在主循环内，过时的堆条目将被忽略。 发生这种情况是因为一个节点在其最终最短距离确定之前可能会被插入多次。 

对于每个邻居，我们计算潜在的新距离。 

如果新距离更小，我们将替换最短距离和路径计数，因为这条路线绝对更好。 

如果新距离等于现有最短距离，我们会累积额外的最短路径。 

最后，我们返回到节点的最短路径的数量`n - 1`。 

## 解决方案```go
package main

import (
	"container/heap"
)

const MOD int = 1e9 + 7

type Pair struct {
	node int
	dist int64
}

type PriorityQueue []Pair

func (pq PriorityQueue) Len() int {
	return len(pq)
}

func (pq PriorityQueue) Less(i, j int) bool {
	return pq[i].dist < pq[j].dist
}

func (pq PriorityQueue) Swap(i, j int) {
	pq[i], pq[j] = pq[j], pq[i]
}

func (pq *PriorityQueue) Push(x interface{}) {
	*pq = append(*pq, x.(Pair))
}

func (pq *PriorityQueue) Pop() interface{} {
	old := *pq
	n := len(old)

	item := old[n-1]
	*pq = old[:n-1]

	return item
}

func countPaths(n int, roads [][]int) int {
	graph := make([][][2]int, n)

	for _, road := range roads {
		u, v, t := road[0], road[1], road[2]

		graph[u] = append(graph[u], [2]int{v, t})
		graph[v] = append(graph[v], [2]int{u, t})
	}

	dist := make([]int64, n)
	ways := make([]int, n)

	const INF int64 = 1<<62

	for i := 0; i < n; i++ {
		dist[i] = INF
	}

	dist[0] = 0
	ways[0] = 1

	pq := &PriorityQueue{}
	heap.Init(pq)

	heap.Push(pq, Pair{node: 0, dist: 0})

	for pq.Len() > 0 {
		current := heap.Pop(pq).(Pair)

		node := current.node
		currentDist := current.dist

		if currentDist > dist[node] {
			continue
		}

		for _, edge := range graph[node] {
			neighbor := edge[0]
			weight := int64(edge[1])

			newDist := currentDist + weight

			if newDist < dist[neighbor] {
				dist[neighbor] = newDist
				ways[neighbor] = ways[node]

				heap.Push(pq, Pair{
					node: neighbor,
					dist: newDist,
				})

			} else if newDist == dist[neighbor] {
				ways[neighbor] = (ways[neighbor] + ways[node]) % MOD
			}
		}
	}

	return ways[n-1]
}
```Go 实现遵循与 Python 解决方案相同的算法结构，但一些特定于语言的细节很重要。 

去的`container/heap`包需要手动实现堆接口，包括`Len`,`Less`,`Swap`,`Push`， 和`Pop`。 

距离存储为`int64`而不是`int`因为当多条道路上的边权重相加时，边权重可能会变得非常大。 使用`int64`避免溢出。 

邻接表使用固定大小数组的切片`[2]int`有效地存储邻居和权重对。 

与 Python 的动态整数不同，Go 整数具有固定宽度，因此在组合距离和权重时需要仔细进行类型转换。

 ## 边缘情况

 当多条不同的路线产生完全相同的最短距离时，就会出现一种重要的边缘情况。 简单的 Dijkstra 实现可能会覆盖现有的路径计数，而不是累积其他路径。 此实现通过检查正确处理该问题`new_dist == dist[neighbor]`并添加方法的数量。 

另一个重要的情况涉及过时的堆条目。 在 Dijkstra 的执行过程中，一个节点可能会被多次推入堆中，然后才能确定其最终的最短距离。 如果我们处理过时的条目，我们可能会执行不必​​要的工作，甚至损坏路径计数。 条件`if current_dist > dist[node]: continue`安全地跳过过时的状态。 

大边权重是错误的另一个常见来源。 由于每条边的权重可能大到`10^9`，当组合许多边时，总的最短距离可能超过正常的 32 位整数范围。 Go 实现使用`int64`距离以避免溢出，而Python自然支持任意大的整数。 

最后的边缘情况涉及可以以相同的总成本直接和间接到达目的地的图。 该算法正确地计算了所有此类路线，因为每条同等最优的松弛都会有助于目的地的`ways`数数。
