[LeetCode 1934 题](https://leetcode.com/problems/confirmation-rate/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算系统中每个用户的**确认率**，用户可以在注册后请求确认消息。 我们有两张表：`Signups`和`Confirmations`。 这`Signups`表包含所有注册的用户，具有唯一的`user_id`和一个`time_stamp`的注册。 这`Confirmations`表包含用户提出的每个确认请求的记录，以及`action`指示该请求是否是的字段`'confirmed'`或者`'timeout'`。 

目标是将每个用户的确认率计算为`'confirmed'`请求数除以发出的请求总数。 如果用户没有请求任何确认，那么他们的确认率为`0`。 结果应四舍五入到**两位小数**并以表格形式返回`user_id`和`confirmation_rate`。 

需要注意的要点是：

 1. 中的每个用户`Confirmations`表保证存在于`Signups`由于外键。 
2. 没有确认请求的用户应该以 0 的速率出现在输出中。 
3. 的`action`列只能是`'confirmed'`或者`'timeout'`。 
4. 可以按任意顺序返回结果。 
5. 主要挑战是正确处理零确认请求的用户并确保正确舍入。 

重要的边缘情况包括没有确认的用户、只有确认的用户`'timeout'`操作，用户只需`'confirmed'`操作以及两者兼而有之的用户。 

## 方法

 ### 蛮力

 蛮力方法将涉及迭代所有用户，并为每个用户计算用户的数量`'confirmed'`操作和确认请求总数。 对于没有确认的用户，费率设置为 0。这种方法有效，但需要扫描`Confirmations`每个用户的表，如果用户或确认的数量很大，可能会导致很高的时间复杂度。 

### 最佳方法

 最佳方法是在 SQL 中使用**聚合和连接**。 我们可以将`Confirmations`表格依据`user_id`统计每个用户的总请求数和已确认的请求数。 然后我们执行 **LEFT JOIN** 与`Signups`表以确保包含每个用户，包括那些没有确认请求的用户。 最后，我们计算确认率并将其四舍五入到小数点后两位。 

该方法确保单次扫描`Confirmations`表并利用 SQL 的聚合函数来提高效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(U * C) | O(U) | 迭代所有用户并扫描每个用户的确认信息 |
 | 最佳| O(C + U) | O(U) | 按用户汇总确认、加入注册、计算费率 |

 ## 算法演练

 1. 汇总`Confirmations`表格依据`user_id`计算总请求数（`COUNT(*)`）和确认的请求（`SUM(CASE WHEN action = 'confirmed' THEN 1 ELSE 0 END)`）。 
2. 执行`LEFT JOIN`与`Signups`表包含没有任何确认请求的用户。 
3. 对于每个用户，将确认率计算为`confirmed_count / total_count`。 使用`0`如果`total_count`为空（没有请求）。 
4.使用SQL将确认率四舍五入到小数点后两位`ROUND`功能。 
5. 返回结果表`user_id`和`confirmation_rate`。 

该算法之所以有效，是因为它确保所有用户都包含在内，并正确处理用户确认请求为零的情况。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def confirmation_rate(conn: sqlite3.Connection) -> List[Tuple[int, float]]:
    query = """
    WITH counts AS (
        SELECT
            user_id,
            COUNT(*) AS total_requests,
            SUM(CASE WHEN action = 'confirmed' THEN 1 ELSE 0 END) AS confirmed_count
        FROM Confirmations
        GROUP BY user_id
    )
    SELECT
        s.user_id,
        ROUND(COALESCE(c.confirmed_count, 0) * 1.0 / COALESCE(c.total_requests, 1), 2) AS confirmation_rate
    FROM Signups s
    LEFT JOIN counts c
    ON s.user_id = c.user_id;
    """
    cursor = conn.cursor()
    cursor.execute(query)
    return cursor.fetchall()
```在此实现中，我们首先在名为的 CTE 中聚合确认数据`counts`。 这`LEFT JOIN`确保没有任何确认请求的用户出现的确认率为`0`。 我们使用`COALESCE`处理连接中的空值，防止被空值除。 乘以`1.0`确保浮点数除法，四舍五入到小数点后两位符合问题要求。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func ConfirmationRate(db *sql.DB) (*sql.Rows, error) {
    query := `
    WITH counts AS (
        SELECT
            user_id,
            COUNT(*) AS total_requests,
            SUM(CASE WHEN action = 'confirmed' THEN 1 ELSE 0 END) AS confirmed_count
        FROM Confirmations
        GROUP BY user_id
    )
    SELECT
        s.user_id,
        ROUND(COALESCE(c.confirmed_count, 0) * 1.0 / COALESCE(c.total_requests, 1), 2) AS confirmation_rate
    FROM Signups s
    LEFT JOIN counts c
    ON s.user_id = c.user_id;
    `
    return db.Query(query)
}
```Go 实现密切反映了 Python SQL 逻辑。 我们返回`*sql.Rows`直接，可以被呼叫者扫描。 关键的区别是Go使用database/sql包； SQL 查询本身保持不变。 

## 工作示例

 对于提供的输入：

 | 用户 ID | 已确认 | 请求总数 | 评分 |
 | --- | --- | --- | --- |
 | 6 | 0 | 0 | 0.00 | 0.00
 | 3 | 0 | 2 | 0.00 | 0.00
 | 7 | 3 | 3 | 1.00 |
 | 2 | 1 | 2 | 0.50 | 0.50

 1. 汇总确认：

 - 用户 2→confirmed_count = 1，total_requests = 2
 - 用户 3→confirmed_count = 0，total_requests = 2
 - 用户 7→confirmed_count = 3，total_requests = 3
 2. 加入`Signups`：用户6没有确认→total_requests = 0，confirmed_count = 0
 3. 计算confirmation_rate=confirmed_count/total_requests，对于没有请求的用户使用0。 
4. 四舍五入至小数点后两位。

 线性复杂度确保解决方案即使对于大型数据集也能很好地扩展。

 ## 边缘情况

 1. **没有确认请求的用户**：存在于`Signups`但不在`Confirmations`确认率应为 0。这是通过 LEFT JOIN 处理的，并且`COALESCE`在 SQL 查询中。 
2. **仅执行超时操作的用户**：请求确认但未得到确认的用户的确认率应为 0。聚合逻辑正确计算已确认的操作并除以总请求数。 
3. **舍入精度**：问题需要四舍五入到小数点后两位。 使用SQL
