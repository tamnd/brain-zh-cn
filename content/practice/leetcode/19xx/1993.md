 # LeetCode 1993 - 树的操作

 ## 问题理解

 该问题要求我们设计一个基于树的可变数据结构，支持三种操作：`lock`,`unlock`， 和`upgrade`。 树中的每个节点都可以由一个用户解锁或锁定。 这些操作必须遵循有关节点何时可以更改状态的严格规则。 

输入树用`parent`大批。 对于每个节点`i`,`parent[i]`给出该节点的父节点。 由于该结构保证是一棵有效的树，因此除根之外的每个节点都只有一个父节点，并且不存在循环。 根节点始终是节点`0`，它的父级是`-1`。 

这`lock(num, user)`操作尝试为用户锁定节点。 只有当前未锁定的节点才能被锁定。 如果成功，该节点将与该用户关联。 

这`unlock(num, user)`操作尝试解锁节点。 节点只能由最初锁定该节点的同一用户解锁。 如果其他用户尝试解锁，操作将失败。 

这`upgrade(num, user)`操作最为复杂。 它同时锁定目标节点并解锁所有锁定的后代。 然而，只有满足所有三个条件，它才能成功：

 1.节点本身当前已解锁。 
2. 节点的至少一个后代被锁定。 
3. 没有一个节点的祖先被锁定。 

如果满足这些条件，则每个锁定的后代都会解锁，并且目标节点将被请求用户锁定。 

在决定实施的复杂程度时，约束非常重要。 树的大小最大为`2000`节点数，操作总数也最多为`2000`。 这些限制相对较小。 这意味着`O(n)`操作期间的遍历是完全可以接受的，因为即使在最坏的情况下，我们总共也只执行几百万次操作。 

一些边缘情况很重要：

 - 尝试锁定已锁定的节点一定会失败。 
- 尝试使用错误的用户 ID 解锁节点一定会失败。 
- 如果节点本身已被锁定，则升级操作必定失败。 
- 如果没有后代被锁定，升级操作必定失败。 
- 如果任何祖先被锁定，升级操作必定失败。 
- 不同用户锁定的后代在升级时必须全部解锁。 
- 根节点没有祖先，因此祖先检查必须正确停止。 

该问题保证树是有效的并且所有节点索引都在范围内。 

## 方法

 ### 蛮力方法

 直接的暴力实现将在每次操作期间重复扫描整个树结构。 

对于`lock`和`unlock`操作，这很简单，因为我们只需要检查当前节点状态。 

对于`upgrade`操作时，暴力策略将：

 1. 向上遍历父级以验证没有锁定祖先。 
2. 遍历以目标节点为根的整个子树，找到锁定的后代。 
3. 解锁每个锁定的后代。 
4. 锁定当前节点。 

这种方法是正确的，因为它明确地检查问题陈述所需的每条规则。 由于检查了每个相关的祖先和后代，因此不会发生无效升级。 

尽管这被称为暴力方法，但实际上对于给定的约束来说它已经足够快了，因为`n <= 2000`。 然而，如果不提前组织子关系，子树遍历就会变得低效，因为我们会通过扫描整个父数组来重复搜索子树。 

### 最佳方法

 关键的观察是树结构永远不会改变。 我们可以将父数组预处理为子数组的邻接列表。 这允许使用 DFS 或 BFS 进行有效的后代遍历。 

我们维持：

 - 原来的`parent`祖先遍历的数组。 
- A`children`子树遍历的邻接表。 
- A`locked`存储当前拥有每个节点的用户的数组，或者`-1`如果解锁。 

改进来自于组织树，因此后代操作变成自然的图遍历，而不是重复的全局扫描。 

由于约束很小，我们不需要像线段树或欧拉之旅这样的高级数据结构。 干净的基于 DFS 的解决方案既高效又易于推理。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 重复子树扫描的最坏情况为 O(n²) | O(n) | 重复扫描父数组以查找后代 |
 | 最佳 | 每次操作 O(n) | O(n) | 使用邻接表进行高效的后代遍历 |

 ## 算法演练

 1. 储存`parent`数组直接在类内部，因为祖先遍历需要从一个节点反复向上移动。 
2. 建立一个`children`初始化期间的邻接表。 对于每个节点`i`, 追加`i`到`children[parent[i]]`。 这允许快速遍历后代。 
3. 保持`locked`数组其中：

 -`locked[i] = -1`表示节点`i`已解锁。 
-`locked[i] = userId`表示节点`i`已被该用户锁定。 
4. 对于`lock(num, user)`操作：

 - 检查是否`locked[num]`已被占用。 
- 如果已经锁定，则返回`False`。 
- 否则存储用户ID并返回`True`。 
5. 对于`unlock(num, user)`操作：

 - 验证节点当前是否被同一用户锁定。 
- 如果没有，请返回`False`。 
- 否则将节点重置为`-1`并返回`True`。 
6. 对于`upgrade(num, user)`操作：

 - 首先验证节点本身是否已解锁。 
- 然后使用父数组向上遍历祖先。 
- 如果任何祖先被锁定，则返回`False`。 
7.使用DFS或BFS遍历所有后代：

 - 跟踪是否存在至少一个锁定的后代。 
- 每当发现锁定的后代时，立即将其解锁。 
8.遍历后：

 - 如果没有找到锁定的后代，则返回`False`。 
- 否则用给定用户锁定当前节点并返回`True`。 

### 为什么它有效

 该算法之所以有效，是因为每个操作都直接执行问题陈述中描述的规则。 

锁定和解锁操作仅在所需所有权条件成立时修改节点。 

对于升级，该算法通过在发生任何修改之前检查所有祖先来保证正确性，确保不存在锁定的祖先。 后代遍历保证每个锁定的后代都被发现并解锁。 由于只有在这些条件成功后目标节点才会被锁定，因此最终状态始终满足所需的升级语义。 

## Python 解决方案```python
from typing import List
from collections import deque

class LockingTree:

    def __init__(self, parent: List[int]):
        self.parent = parent
        self.children = [[] for _ in range(len(parent))]
        
        for node in range(1, len(parent)):
            self.children[parent[node]].append(node)
        
        self.locked = [-1] * len(parent)

    def lock(self, num: int, user: int) -> bool:
        if self.locked[num] != -1:
            return False
        
        self.locked[num] = user
        return True

    def unlock(self, num: int, user: int) -> bool:
        if self.locked[num] != user:
            return False
        
        self.locked[num] = -1
        return True

    def upgrade(self, num: int, user: int) -> bool:
        if self.locked[num] != -1:
            return False

        ancestor = self.parent[num]
        
        while ancestor != -1:
            if self.locked[ancestor] != -1:
                return False
            ancestor = self.parent[ancestor]

        found_locked_descendant = False

        queue = deque([num])

        while queue:
            current = queue.popleft()

            for child in self.children[current]:
                queue.append(child)

                if self.locked[child] != -1:
                    found_locked_descendant = True
                    self.locked[child] = -1

        if not found_locked_descendant:
            return False

        self.locked[num] = user
        return True

# Your LockingTree object will be instantiated and called as such:
# obj = LockingTree(parent)
# param_1 = obj.lock(num, user)
# param_2 = obj.unlock(num, user)
# param_3 = obj.upgrade(num, user)
```构造函数将树预处理为子邻接表。 这使得后代遍历变得高效，因为我们可以直接访问节点的所有子节点，而不用重复搜索父数组。 

这`locked`阵列充当中央状态跟踪器。 使用`-1`对于未锁定的节点，检查保持简单高效。 

这`lock`仅当节点当前解锁时方法才会成功。 否则立即返回`False`。 

这`unlock`方法在解锁之前验证所有权。 这确保只有锁定用户才能释放节点。 

这`upgrade`方法分为三个阶段。 首先它检查当前节点是否解锁。 其次，它向上遍历祖先以确保没有一个被锁定。 第三，它对后代执行 BFS 遍历，以定位并解锁所有锁定的节点。 如果不存在锁定的后代，则操作失败。 否则当前节点将被锁定。 

## 解决方案```go
package main

type LockingTree struct {
	parent   []int
	children [][]int
	locked   []int
}

func Constructor(parent []int) LockingTree {
	n := len(parent)

	children := make([][]int, n)

	for i := 1; i < n; i++ {
		p := parent[i]
		children[p] = append(children[p], i)
	}

	locked := make([]int, n)

	for i := 0; i < n; i++ {
		locked[i] = -1
	}

	return LockingTree{
		parent:   parent,
		children: children,
		locked:   locked,
	}
}

func (this *LockingTree) Lock(num int, user int) bool {
	if this.locked[num] != -1 {
		return false
	}

	this.locked[num] = user
	return true
}

func (this *LockingTree) Unlock(num int, user int) bool {
	if this.locked[num] != user {
		return false
	}

	this.locked[num] = -1
	return true
}

func (this *LockingTree) Upgrade(num int, user int) bool {
	if this.locked[num] != -1 {
		return false
	}

	ancestor := this.parent[num]

	for ancestor != -1 {
		if this.locked[ancestor] != -1 {
			return false
		}
		ancestor = this.parent[ancestor]
	}

	foundLockedDescendant := false

	queue := []int{num}

	for len(queue) > 0 {
		current := queue[0]
		queue = queue[1:]

		for _, child := range this.children[current] {
			queue = append(queue, child)

			if this.locked[child] != -1 {
				foundLockedDescendant = true
				this.locked[child] = -1
			}
		}
	}

	if !foundLockedDescendant {
		return false
	}

	this.locked[num] = user
	return true
}
```Go 实现遵循与 Python 版本相同的逻辑结构。 切片用于邻接列表和队列。 由于 Go 不提供内置双端队列，因此基于切片的队列实现足以满足这些约束。 

这`locked`切片用途`-1`表示未锁定的节点，与 Python 解决方案完全相同。 整数溢出不是问题，因为所有值都非常小。

 ## 边缘情况

 当尝试使用错误的用户 ID 解锁节点时，会出现一种重要的边缘情况。 这是错误的常见来源，因为很容易只检查节点是否被锁定，而不是验证所有权。 该实现通过要求正确处理这个问题`locked[num] == user`解锁前。 

另一个重要的边缘情况是在祖先已被锁定的节点上执行升级。 幼稚的实现可能只检查后代并完全忘记祖先验证。 该解决方案在进行任何修改之前显式地向上遍历父链，确保升级不会违反锁定层次结构规则。 

当在没有锁定后代的节点上请求升级时，会发生第三种重要的边缘情况。 即使节点本身被解锁并且所有祖先都被解锁，操作仍然会失败。 BFS 遍历使用以下方法跟踪是否遇到至少一个锁定的后代：`found_locked_descendant`旗帜。 如果没有找到，该方法返回`False`而不改变树的状态。
