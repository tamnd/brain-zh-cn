[LeetCode 1921 题](https://leetcode.com/problems/eliminate-maximum-number-of-monsters/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定在任何一只怪物到达城市之前我们可以消灭多少只怪物。 

每个怪物都从距离城市一定距离的地方开始，并以恒定的速度向城市移动。 我们还获得了一种每分钟可以消灭一个怪物的武器。 武器在某个时间开始充满电`0`，这意味着我们可以在任何移动发生之前立即消灭一只怪物。 

重要的细节是失败条件：

 - 如果怪物恰好在武器再次可用时到达城市，我们仍然会在开火前失败。 
- 这意味着怪物准时到达`t`必须在分钟之前已经被消除`t`开始。 

输入由两个数组组成：

 -`dist[i]`代表怪物的起始距离`i`-`speed[i]`代表怪物的速度有多快`i`动作

 对于每个怪物，我们可以计算它到达城市的确切时间：$$\text{arrival time} = \frac{\text{dist}[i]}{\text{speed}[i]}$$由于我们每分钟只能消灭一个怪物，所以关键问题就变成了：

 我们可以安排消除，以便每个怪物在到达时间之前就被消灭吗？ 

约束条件很重要：

 -`n`可以大到`10^5`- 二次模拟太慢
 - 我们需要一个算法`O(n log n)`或更好

 一些边缘情况立即脱颖而出：

 - 多个怪物可能会同时到达
 - 怪物可能会在几分钟前到达`1`，迫使我们立即消除它
 - 有些怪物可能会在武器充电时恰好到达城市，这仍然算作失败
 - 如果怪物的到达时间足够分散，则所有怪物都可能被消灭

 该问题保证：

 - 所有距离和速度均为正整数
 - 数组的长度相等
 - 至少有一个怪物

 ## 方法

 ### 蛮力方法

 一种直接的方法是逐分钟模拟游戏。 

每分钟：

 1.计算每个活着的怪物的剩余距离
 2.检查是否有怪物已经到达城市
 3.选择一只怪物进行消灭
 4. 时间提前一分钟

 为了最大限度地提高生存率，我们可能会消灭第一个到达城市的怪物。 

虽然这会产生正确的答案，但效率很低，因为每分钟都需要扫描所有剩余的怪物。 在最坏的情况下，这会导致重复重新计算位置和到达优先级。 

高达`10^5`怪物，重复更新怪物状态变得太昂贵。 

### 关键见解

 关键的观察是实际的运动模拟是不必要的。 

怪物完全由一个值表征：$$\text{arrival minute} = \frac{\text{dist}[i]}{\text{speed}[i]}$$我们不关心怪物在中间时间在哪里。 我们只关心它什么时候到达城市。 

如果我们按照怪物到达时间对怪物进行排序，那么最优策略就变得显而易见：

 - 始终消灭最早到达的怪物

 假设排序后的到达时间为：$$t_0 \le t_1 \le t_2 \le \dots$$分钟`0`，我们消灭第一个怪物。 

分钟`1`，我们消灭第二个怪物。 

分钟`2`，我们消灭第三个怪物。 

对于分钟安排的怪物`i`，我们必须有：$$t_i > i$$如果`t_i <= i`，那个怪物在我们可以再次开火之前或恰好在我们可以再次开火的时候到达城市，所以我们输了。 

这将问题转化为简单的贪心调度问题。

 ## 算法演练

 1. 创建一个数组来存储每个怪物的到达时间。 

对于怪物`i`，到达时间为：$$\frac{\text{dist}[i]}{\text{speed}[i]}$$我们可以直接计算上限分钟，而不是使用浮点值：$$\left\lceil \frac{\text{dist}[i]}{\text{speed}[i]} \right\rceil$$在整数运算中：$$\frac{\text{dist}[i] + \text{speed}[i] - 1}{\text{speed}[i]}$$这告诉我们怪物到达城市的第一分钟。 
2. 按到达时间升序排列。 

这确保我们始终首先考虑最紧急的怪物。 
3. 迭代排序后的到达时间。 

分钟`i`，我们试图消除`i`按顺序排列的第 3 个怪物。 
4.检查当前怪物是否提前到达。 

如果：$$\text{arrivalTime}[i] \le i$$然后怪物在武器可用之前或恰好在武器可用时到达城市。 

我们立即返回`i`，因为我们成功地消除了`i`失败前的怪物。 
5.如果所有怪物都通过检查，则返回`n`。 

这意味着所有怪物都可以在到达城市之前被消灭。 

### 为什么它有效

 按到达时间排序可确保我们始终首先处理最紧急的怪物。 如果推迟到达时间较早的怪物，而先消灭较晚的怪物，则较早的怪物可能会不必要地提早到达城市。 

不变量是：

 - 消除后`i`怪物，所有剩余的怪物必须严格在分钟后到达`i`。 

如果这个条件失败了，没有其他的顺序可以拯救我们，因为剩下的每个怪物都不晚于当前的怪物到达。 

因此，贪心策略是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def eliminateMaximum(self, dist: List[int], speed: List[int]) -> int:
        arrival_times = []

        for d, s in zip(dist, speed):
            minute = (d + s - 1) // s
            arrival_times.append(minute)

        arrival_times.sort()

        for minute, arrival in enumerate(arrival_times):
            if arrival <= minute:
                return minute

        return len(dist)
```实现首先计算每个怪物的到达分钟。 表达式：```python
(d + s - 1) // s
```计算上限`d / s`使用整数运算，避免浮点精度问题。 

收集所有到达时间后，算法按升序对它们进行排序。 这确保了最早到达城市的怪物会被首先处理。 

循环：```python
for minute, arrival in enumerate(arrival_times):
```代表发射时间表。 分钟`0`，我们消灭第一个怪物。 分钟`1`，我们消除第二个，依此类推。 

条件：```python
if arrival <= minute:
```检测到故障。 如果怪物在当前分钟或之前到达，它就会在我们开火之前到达城市。 

如果循环成功完成，所有怪物都会被消除，因此该函数返回怪物的总数。 

## 解决方案```go
package main

import "sort"

func eliminateMaximum(dist []int, speed []int) int {
	n := len(dist)

	arrivalTimes := make([]int, n)

	for i := 0; i < n; i++ {
		arrivalTimes[i] = (dist[i] + speed[i] - 1) / speed[i]
	}

	sort.Ints(arrivalTimes)

	for minute, arrival := range arrivalTimes {
		if arrival <= minute {
			return minute
		}
	}

	return n
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

切片用于存储到达时间，并且`sort.Ints`有效地对它们进行排序。 

Go 中的整数除法自然会向零截断，因此上限公式：```go
(dist[i] + speed[i] - 1) / speed[i]
```完全按照预期工作。 

由于所有约束都适合标准整数范围，因此不需要特殊的溢出处理。

 ## 边缘情况

 ### 多个怪物同时到来

 最容易犯的错误之一就是对同一时间到达的怪物处理不当。 

例如：```
dist = [1,1,1]
speed = [1,1,1]
```所有怪物都在几分钟内到达`1`。 我们一分钟只能消除一个`0`，然后剩余的怪物在武器充能之前到达城市。 

该实现可以正确处理此问题，因为排序后的到达时间变为：```
[1,1,1]
```分钟`1`，条件：```
arrival <= minute
```立即检测到故障。 

### 武器充电时怪物正好到达

 问题明确指出这仍然算作损失。 

例如：```
dist = [1,2]
speed = [1,2]
```到达时间为：```
[1,1]
```第二只怪物在几分钟内到达城市`1`，当武器再次可用时。 由于比赛在开火之前就结束了，所以我们输了。 

这就是该算法使用的原因：```
arrival <= minute
```而不是：```
arrival < minute
```这种平等检查至关重要。 

### 非常大的输入大小

 与`10^5`怪物，低效的模拟变得太慢。 

反复更新怪物位置的简单方法可能会花费二次时间。 

该实现通过将每个怪物转换为单个到达时间并排序一次来完全避免这种情况。 这确保了算法即使在最大约束下也保持高效。
