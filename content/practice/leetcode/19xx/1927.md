[LeetCode 1927 题](https://leetcode.com/problems/sum-game/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串、贪心、博弈论

 ## 解决方案

 ## 问题理解

 该问题描述了在偶数长度的数字字符串上玩的两人游戏。 该字符串包含数字，可能还包含一些`'?'`人物。 爱丽丝和鲍勃轮流替换一个`'?'`带有一个数字`'0'`到`'9'`。 爱丽丝先行动。 

比赛结束时，每`'?'`已被替换。 绳子被分成相等的两半。 只有当左半部分的数字之和等于右半部分的数字之和时，鲍勃才获胜。 如果总和不同，爱丽丝获胜。 

任务是确定爱丽丝是否获胜，假设两个玩家都发挥最佳。 

重要的观察是实际的最终数字不是任意的。 由于两个玩家都在战略上做出选择，所以游戏就变成了爱丽丝是否可以迫使两半以不同的总和结束的问题，或者鲍勃是否总是可以抵消爱丽丝的举动并迫使双方平等的问题。 

输入大小可以大到`10^5`，这立即排除了所有可能的游戏状态的任何指数模拟。 即使具有大常数的多项式算法也会存在风险，因此预期的解决方案必须对游戏进行数学分析，而不是显式模拟回合。 

一些边缘情况很重要：

 - 该字符串可能已经不包含`'?'`人物。 
- 一半可能比另一半包含更多的未知数。 
- 当前的数字总和可能已经有很大差异。 
- 总数`'?'`characters is always even because the string length is even and both players alternate until all are filled.
 - A naive implementation may incorrectly assume players independently maximize or minimize sums without considering alternating turns.

 The key challenge is understanding how optimal play affects the balance between the two halves.

 ## 方法

 ### 蛮力方法

 A brute force solution would recursively simulate every possible move for both players.

 在每个回合：

 1. 选择剩余的任何一个`'?'`。 
2. Try every digit from`0`到`9`。 
3. Recursively evaluate the resulting game state.

 由于两个玩家都处于最佳状态，因此递归变成了极小极大博弈树：

 - 爱丽丝试图强行得到不平等的最终金额。 
- 鲍勃试图强制平等。 

这种方法是正确的，因为它探索了每一个可能的合法移动序列并应用了最佳的游戏规则。 然而，这是完全不切实际的。 

如果有`k`问号，那么每一步最多有`10k`最初的可能性，然后`10(k-1)`， 等等。 总状态空间呈指数增长。 

和`k`可能接近`10^5`，暴力是不可能的。 

### 最优贪心和数学观察

 关键的见解是，确切的移动顺序并不重要，重要的是：

 - 当前左右总和之间的差异。 
- 有多少`'?'`字符保留在每一半中。 

让：

-`leftSum`= 左半部分的已知数字和
 -`rightSum`= 右半部分的已知数字和
 -`leftQ`= 数量`'?'`在左半部分
 -`rightQ`= 数量`'?'`在右半部分

 鲍勃希望最终的金额相等。 

每对未来动作最多可以有效贡献`9`差异是因为一名玩家可以放置`9`而另一个可以放置`0`。 

一个非常优雅的观察出现了：

 - 如果可以从额外的总调整中`'?'`字符完全补偿了当前的总和差异，鲍勃获胜。 
- 否则，爱丽丝获胜。 

最终条件变为：```
2 * (leftSum - rightSum) == 9 * (rightQ - leftQ)
```如果这种平等成立，鲍勃可以强制平等，所以爱丽丝输了。 

否则，爱丽丝可以强迫不平等，所以爱丽丝获胜。

 ## 算法演练

 1. 计算字符串的长度并确定中点。 

由于弦的长度始终是偶数，因此中点将两半完全分开。 
2. 遍历左半部分。 

对于每个字符：

 - 如果是的话`'?'`, 增量`leftQ`。 
- 否则，将其数字值添加到`leftSum`。 

这会收集与左侧相关的所有信息。 
3. 遍历右半部分。 

同样：

 - 计算问号`rightQ`。 
- 将已知数字添加到`rightSum`。 
4. 计算当前总差。```
diff = leftSum - rightSum
```正值表示左侧当前领先。 
5. 分析剩余情况`'?'`位置可以影响比赛。 

每对不匹配的问号都有助于潜在的调整`9`。 

例如：

 - 爱丽丝可以放置`9`- 鲍勃可以回应`0`反之亦然。 
6. 应用获胜条件。 

只有在以下情况下，Bob 才能强制平等：```
2 * diff == 9 * (rightQ - leftQ)
```如果此条件成立，则返回`False`因为鲍勃赢了。 

否则，返回`True`因为爱丽丝赢了。 

### 为什么它有效

 比赛简化为平衡两个半场之间可实现的总得分调整。 

两半对称出现的问号相互抵消，因为鲍勃可以模仿爱丽丝的动作。 只有问号中的不平衡才是重要的。 

每个不匹配的问号对贡献的有效差异容量为`9`。 如果当前的数字差完全匹配这个补偿能力，Bob 可以强制相等。 否则，爱丽丝总能保持非零差异。 

这个不变量完全表征了游戏结果。 

## Python 解决方案```python
class Solution:
    def sumGame(self, num: str) -> bool:
        n = len(num)
        half = n // 2

        left_sum = 0
        right_sum = 0
        left_q = 0
        right_q = 0

        for i in range(half):
            if num[i] == '?':
                left_q += 1
            else:
                left_sum += int(num[i])

        for i in range(half, n):
            if num[i] == '?':
                right_q += 1
            else:
                right_sum += int(num[i])

        diff = left_sum - right_sum

        return 2 * diff != 9 * (right_q - left_q)
```实现直接遵循数学推导。 

代码的前半部分收集左侧的统计信息：

 - 已知数字的总和
 - 未知位置的计数

 第二个循环对右侧执行相同的工作。 

计算当前总和差后，最后一行检查关键平衡条件。 如果相等成立，Bob 可以强制最终的总和匹配，因此函数返回`False`。 否则，Alice 可以强制不平等，因此函数返回`True`。 

该实现仅使用几个整数变量并扫描一次字符串，使其对于大型输入非常高效。 

## 解决方案```go
func sumGame(num string) bool {
	n := len(num)
	half := n / 2

	leftSum := 0
	rightSum := 0
	leftQ := 0
	rightQ := 0

	for i := 0; i < half; i++ {
		if num[i] == '?' {
			leftQ++
		} else {
			leftSum += int(num[i] - '0')
		}
	}

	for i := half; i < n; i++ {
		if num[i] == '?' {
			rightQ++
		} else {
			rightSum += int(num[i] - '0')
		}
	}

	diff := leftSum - rightSum

	return 2*diff != 9*(rightQ-leftQ)
}
```Go 实现几乎完全反映了 Python 解决方案。 

Go 的一个具体细节是使用以下方法将数字字符转换为整数：```go
int(num[i] - '0')
```由于所有算术值都保持在标准整数范围内，因此不存在溢出问题。 

该解决方案使用恒定的额外空间，因为只存储了几个计数器和总和。

 ## 边缘情况

 ### 没有问号

 当字符串已经不包含任何内容时，就会出现一个重要的边缘情况`'?'`人物。 在这种情况下，游戏根本没有任何动作。 获胜者完全由现有的数字和决定。 

有缺陷的实现可能会错误地假设玩家总是采取行动或无法正确处理零未知数。 数学条件自然可以处理这种情况，因为两个问号计数都为零。 

### 所有字符都是问号

 考虑像这样的输入`"??"`或者`"????"`。 

这些情况很棘手，因为不存在初始数字信息。 天真的贪婪模拟可能会错误地得出结论：爱丽丝有优势，因为她先移动。 

然而，对称性允许鲍勃反映爱丽丝的影响力和力量平等。 该公式正确地检测到了这一点，因为当前总和差为零并且问号计数是平衡的。 

### 问号分布不均匀

 类似的情况`"25??"`是微妙的，因为一半比另一半包含更多的灵活性。 

幼稚的实现可能会错误地仅比较当前的总和，而不考虑未来的调整潜力。 

最佳解决方案明确地考虑了每一半中剩余多少个未知位置。 的因素为`9`捕获每个不匹配的配对可以创造的最大贡献，确保正确处理这些不对称情况。
