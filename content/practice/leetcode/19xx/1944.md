[LeetCode 1944 题](https://leetcode.com/problems/number-of-visible-people-in-a-queue/)

 **难度：** 🔴难
 **主题：** 数组、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 问题给出了一个队列`n`人们从左到右站立，每个人都有不同的高度。 对于每个人`i`，我们需要确定他们可以看到右侧有多少人。 

一个人`i`可以看到一个人`j`（和`j > i`）如果他们之间的每个人都严格低于两个端点，这意味着区间内最高的人`(i+1 ... j-1)`小于`min(heights[i], heights[j])`。 简单来说，只有当两个端点之间存在高于或等于限制高度的中间人时，可见性才会被阻挡。 

输出是一个数组`answer`在哪里`answer[i]`代表索引右边有多少人`i`在此规则下可见。 

限制因素很重要：`n`可以达到`10^5`，所以一个`O(n^2)`解决办法太慢了。 高度是不同的，这简化了比较，因为我们不需要处理关系。 

重要的边缘情况包括严格递减序列（其中每个人可以看到许多其他人）和严格递增序列（其中每个人只能看到第一个较高的人）。 另一个关键的边缘情况是最后一个元素，它总是看到零人，因为没有人在右边。 

## 方法

 ### 蛮力方法

 蛮力方法从每个索引迭代`i`向右，扫描每个`j > i`并检查是否`j`是可见的。 为了确定可见性，我们保持之间可见的最大高度`i`和`j`，并确保它永远不会超过`min(heights[i], heights[j])`。 如果可见性成立，我们增加计数`i`。 

这种方法是正确的，因为它直接模拟了可见性的定义。 然而，对于每个`i`，我们可以扫描到`n`元素，并且维持中间最大值会导致重复工作，使得对于大输入而言速度太慢。 

### 最佳方法：从右到左单调堆栈

 关键的见解是对于每个人`i`，只有右边的某些人可以为可见性做出贡献：

 1. 第一个人比`heights[i]`始终可见（因为它们之间不存在更高的阻挡物）。 
2、之后，矮个子的人也可能会被看到，但他们会被连锁地“消耗”。 
3. 单调递减堆栈（从右到左视角）有助于有效跟踪可见或块可见性的候选者。 

我们从右向左遍历，维护一堆高度递减的索引。 对于每个人`i`，我们反复从堆栈中弹出矮个子，将他们算作可见。 如果之后堆栈不为空，则顶部元素也是可见的（第一个较高的阻挡者），因此我们也对其进行计数。 

这是有效的，因为一旦矮个子被弹出，他们就无法阻挡更左边的任何人，而较高的人自然会主导可见性边界。

 ## 算法演练

 1. 初始化一个空堆栈，用于存储右侧人员的索引。 堆栈将保持高度递减的结构，这意味着从上到下的高度严格递减。 这种结构确保我们始终有效地了解最近的较高候选人。 
2. 创建一个用零初始化的答案数组。 这将存储每个人的可见性计数。 
3. 从右向左迭代数组。 我们从右到左，因为我们希望逐步建立每个人在已经处理过的人中可以看到的内容的知识。 
4. 对于每个人`i`,初始化本地计数器`count = 0`。 该计数器将跟踪有多少人`i`可以看到。 
5. 当栈不为空且当前人比栈顶的人高时，弹出栈并自增`count`。 每个弹出的人都是可见的，因为之间不存在更高的阻挡者`i`和那个人。 
6. 如果弹出后堆栈仍然不为空，则表示有一个更高的人挡住了进一步的视线，但仍然可见`i`。 增量`count`再次说明第一个更高的人。 
7.推送当前索引`i`到堆栈上，因此它成为较早元素的潜在可见候选者。 
8. 商店`count`在`answer[i]`。 

### 为什么它有效

 该算法依赖于堆栈始终保持从上到下高度递减序列的不变量。 这确保了在处理新元素时，所有较短的元素立即可见并可移除，并且第一个剩余的较高元素是下一个阻塞边界。 每个元素最多被压入和弹出一次，从而保持正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def canSeePersonsCount(self, heights: List[int]) -> List[int]:
        n = len(heights)
        stack = []
        answer = [0] * n

        for i in range(n - 1, -1, -1):
            count = 0

            while stack and heights[i] > heights[stack[-1]]:
                stack.pop()
                count += 1

            if stack:
                count += 1

            stack.append(i)
            answer[i] = count

        return answer
```### 代码说明

 该解决方案从右向左迭代，确保处理索引时`i`，右侧所有相关候选项均已在堆栈中。 堆栈按高度递减的顺序存储索引。 这`while`循环删除所有矮个子，每个人都可见`i`。 此后，如果剩下任何更高的人，他们将被计算一次，因为他们是第一个被阻挡但可见的人。 最后，`i`被推送到未来的迭代，并存储其计算出的可见性计数。 

## 解决方案```go
func canSeePersonsCount(heights []int) []int {
	n := len(heights)
	stack := make([]int, 0, n)
	answer := make([]int, n)

	for i := n - 1; i >= 0; i-- {
		count := 0

		for len(stack) > 0 && heights[i] > heights[stack[len(stack)-1]] {
			stack = stack[:len(stack)-1]
			count++
		}

		if len(stack) > 0 {
			count++
		}

		stack = append(stack, i)
		answer[i] = count
	}

	return answer
}
```### Go 特定注释

 Go 实现密切反映了 Python 逻辑。 主要区别是显式切片操作来模拟堆栈行为。 堆栈是索引的切片，弹出是通过重新切片完成的。 由于 Go 整数在此范围内是安全的，因此不存在溢出问题。 逻辑在结构上保持相同并保证 O(n) 性能。

 ## 边缘情况

 一种重要的边缘情况是单元素输入。 由于右侧不存在元素，因此输出必须始终是`[0]`。 该算法自然地处理这个问题，因为循环使用空堆栈处理最后一个元素。 

另一个边缘情况是严格降低高度。 在这种情况下，每个人都可以看到自己右侧的所有人。 堆栈将连续弹出每个元素，并且不会存在阻塞的更高元素，从而导致最大可见性计数。 

严格递增的序列也很重要。 每个人只能看到下一个人，因为所有后续的人都被第一个更高的人挡住了。 在这种情况下，堆栈永远不会弹出许多元素，确保每个索引只有一个可见的人（除了最后一个）。 

最后，大输入高达`10^5`要求算法避免二次行为。 单调堆栈保证每个元素被处理一次，防止超时并确保可扩展性。
