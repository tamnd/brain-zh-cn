[LeetCode 1904 题](https://leetcode.com/problems/the-number-of-full-rounds-you-have-played/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串

 ## 解决方案

 ## 问题理解

 该问题描述了一场在线国际象棋锦标赛，每 15 分钟就会开始一轮新的比赛。 只有当玩家在该轮的整个持续时间内都在场时，才能获得整轮的积分。 

输入由两个时间字符串组成：

 -`loginTime`, 玩家登录的那一刻
 -`logoutTime`, 玩家退出的那一刻

 两者都给出了`"hh:mm"`24 小时格式。 

任务是计算玩家完全参与了多少个完整的 15 分钟回合。 

仅当出现以下情况时，一轮才被视为满轮：

 - 玩家在回合开始之前或恰好在回合开始时登录
 - 玩家在回合结束后或恰好在回合结束时退出

 例如，如果一轮从`09:45`到`10:00`，那么：

 - 登录于`09:44`是可以接受的
 - 登录于`09:46`不是
 - 注销于`10:00`是可以接受的
 - 注销于`09:59`不是

 问题的棘手部分是处理过夜游戏。 如果`logoutTime`早于`loginTime`，这意味着会话已过午夜。 

例如：

 - 登录：`21:30`- 注销：`03:00`表示玩家保持连接状态`21:30`到`24:00`，然后继续从`00:00`到`03:00`。 

限制非常小，因为一天只有 24 小时，但问题的根本在于仔细的时间算术和间隔对齐。 主要挑战是正确地将登录时间向上舍入到下一个 15 分钟边界，并将注销时间向下舍入到前一个 15 分钟边界。 

重要的边缘情况包括：

 - 午夜登录和注销
 - 严格按照 15 分钟界限登录
 - 恰好在 15 分钟界限内注销
 - 间隔时间短于 15 分钟
 - 包含零整轮的会话
 - 几乎完成一轮但错过一分钟的会话

 该问题保证了`loginTime != logoutTime`，因此会话持续时间永远不会正好是 24 小时。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是模拟一天中每一个可能的回合。 

总共只有 96 轮，因为：$$24 \times 4 = 96$$每轮持续 15 分钟。 我们可以生成每个回合间隔并检查玩家的会话是否完全覆盖该间隔。 

为此：

 1. 将登录和注销时间转换为分钟。 
2. 如果需要，可通过将注销时间延长 1440 分钟来处理过夜会话。 
3. 迭代每个可能的回合开始时间。 
4. 检查玩家是否完全覆盖该轮。 

这是有效的，因为每个有效的整轮都经过显式验证。 

然而，这种方法做了不必要的工作。 我们实际上不需要单独检查每一轮，因为每一轮都在固定的 15 分钟边界上完美对齐。 

### 最佳方法

 关键的见解是，只有一致的 15 分钟界限才重要。 

我们可以直接计算：

 - 玩家可以完全参与的最早回合开始
 - 玩家可以完全参与的最新回合结束

 我们通过以下方式实现这一目标：

 - 将登录时间向上舍入到 15 的下一个倍数
 - 将注销时间向下舍入为之前 15 的倍数

 那么完整的轮数就很简单：$$\frac{\text{adjustedLogout} - \text{adjustedLogin}}{15}$$如果会话超过午夜，我们会在执行计算之前将注销时间添加 1440 分钟。 

这将问题转化为简单的算术问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(96) | O(1) | O(1) | 明确检查每个可能的回合 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用算术和边界对齐 |

 ## 算法演练

 1. 将两个时间转换为从午夜算起的总分钟数。 

例如：

-`"09:31"`变成`571`-`"10:14"`变成`614`这简化了以后的所有计算，因为使用整数比操作字符串更容易。 
2. 处理通宵会议。 

如果`logoutMinutes < loginMinutes`，会议已过午夜。 在这种情况下，添加`1440`距离注销时间还有几分钟。 

例如：

 - 登录：`21:30`→`1290`- 注销：`03:00`→`180`自从`180 < 1290`，将注销转换为：$$180 + 1440 = 1620$$3. 将登录时间向上舍入到下一个 15 分钟边界。 

玩家只能参加登录后开始的回合。 

公式为：$$\left(\frac{login + 14}{15}\right) \times 15$$整数除法有效地执行上限运算。 
4. 将注销时间向下舍入到之前的 15 分钟界限。 

玩家必须保持连接直到回合结束。 

公式为：$$\left(\frac{logout}{15}\right) \times 15$$5. 计算调整后的时间之间的差值。 

如果调整后的注销早于调整后的登录，则完整轮次为零。 

否则：$$\frac{adjustedLogout - adjustedLogin}{15}$$6. 返回计算值。 

### 为什么它有效

 每个有效回合以 15 分钟的倍数开始。 通过向上舍入登录时间，我们保证玩家在回合开始前就在场。 通过向下舍入注销时间，我们保证玩家保持连接直到回合结束。 

这两个调整后的边界之间的每 15 分钟间隔恰好对应一个完整的回合。 因此，计算这些间隔就可以得出正确的答案。 

## Python 解决方案```python
class Solution:
    def numberOfRounds(self, loginTime: str, logoutTime: str) -> int:
        def to_minutes(time_str: str) -> int:
            hours, minutes = map(int, time_str.split(":"))
            return hours * 60 + minutes

        login_minutes = to_minutes(loginTime)
        logout_minutes = to_minutes(logoutTime)

        # Handle overnight session
        if logout_minutes < login_minutes:
            logout_minutes += 24 * 60

        # Round login up to next 15-minute boundary
        adjusted_login = ((login_minutes + 14) // 15) * 15

        # Round logout down to previous 15-minute boundary
        adjusted_logout = (logout_minutes // 15) * 15

        # No valid full rounds
        if adjusted_logout < adjusted_login:
            return 0

        return (adjusted_logout - adjusted_login) // 15
```实现从一个辅助函数开始，该函数将`"hh:mm"`从午夜算起的总分钟数。 这将所有计算标准化为整数算术。 

接下来，代码检查会话是否已经过了午夜。 如果是这样，它会将注销时间延长一整天，从而使间隔保持连续。 

登录时间向上舍入，因为一轮开始时的部分参与不计算在内。 注销时间向下舍入，因为最后的部分参与也不计算在内。 

最后，通过将对齐的间隔长度除以 15 来计算整轮数。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

func numberOfRounds(loginTime string, logoutTime string) int {
	toMinutes := func(timeStr string) int {
		parts := strings.Split(timeStr, ":")
		hours, _ := strconv.Atoi(parts[0])
		minutes, _ := strconv.Atoi(parts[1])
		return hours*60 + minutes
	}

	loginMinutes := toMinutes(loginTime)
	logoutMinutes := toMinutes(logoutTime)

	// Handle overnight session
	if logoutMinutes < loginMinutes {
		logoutMinutes += 24 * 60
	}

	// Round login up
	adjustedLogin := ((loginMinutes + 14) / 15) * 15

	// Round logout down
	adjustedLogout := (logoutMinutes / 15) * 15

	if adjustedLogout < adjustedLogin {
		return 0
	}

	return (adjustedLogout - adjustedLogin) / 15
}
```Go 的实现与 Python 版本非常相似。 时间解析使用`strings.Split`和`strconv.Atoi`。 

由于 Go 整数除法会自动截断为零，因此舍入公式可以自然地工作，无需额外的辅助函数。 

无需担心整数溢出，因为最大可能值仅略高于 1440 分钟。

 ## 边缘情况

 当会话跨越午夜时，会出现一种重要的边缘情况。 幼稚的实现可能会假设注销总是在同一天晚些时候发生，从而导致负持续时间或不正确的回合计数。 该实现通过在注销时间在数值上小于登录时间时添加 1440 分钟来处理此问题。 

当登录时间不符合 15 分钟界限时，就会出现另一个棘手的情况。 例如，登录`09:31`意味着玩家错过了开始的回合`09:30`。 实现正确向上舍入为`09:45`，确保只计算完全覆盖的回合。 

第三个重要的边缘情况涉及一轮结束前发生的注销时间。 例如，在以下位置注销`10:14`不应该算`10:00`到`10:15`圆形的。 通过将注销时间向下舍入到之前的 15 分钟边界，该实现保证排除不完整的结束回合。 

另一个微妙的情况是间隔短于 15 分钟。 即使玩家已连接，也可能没有足够的时间完全参与任何一轮。 该实现自然会处理这个问题，因为调整后的注销时间变得小于调整后的登录时间，从而产生零轮。
