[LeetCode 1974 题](https://leetcode.com/problems/minimum-time-to-type-word-using-special-typewriter/)

 **难度：** 🟢简单
 **主题：** 字符串、贪婪

 ## 解决方案

 ## 问题理解

 该问题描述了一台包含所有小写英文字母的圆形打字机`'a'`到`'z'`。 指针围绕这个圆形排列移动，最初指针从`'a'`。 

要键入字符，指针当前必须指向该字符。 每个动作只花费一秒钟。 只有两种可能的操作：

 1. 顺时针或逆时针移动指针一步。 
2. 键入当前字符。 

目标是确定输入整个字符串所需的最少秒数`word`。 

重要的细节是字母排列成一个圆圈。 这意味着从`'a'`到`'z'`逆时针只需要一步，而不是顺时针二十五步。 对于每对连续字符，我们必须选择较短的旋转方向。 

输入是单个字符串`word`，输出是键入所有字符所需的最小总秒数。 

限制非常小：

 -`1 <= word.length <= 100`- 只出现小写英文字母

 由于只有 26 个字母，单词长度最多为 100，因此性能不是问题。 即使是低效的解决方案也可能会被通过。 然而，问题主要是关于认识圆距离优化。 

一些边缘情况很重要：

 - 重复输入相同的字符，例如`"aaa"`，第一个字符之后不需要移动。 
- 穿过圆形边界，例如从`'a'`到`'z'`或来自`'z'`到`'a'`。 
- 仅包含一个字符的单词。 
- 逆时针运动比顺时针运动短的情况。 

## 方法

 ### 蛮力方法

 蛮力风格的解决方案将明确模拟每个角色转换的顺时针和逆时针运动。 对于每个目标角色，我们可以在两个方向上重复一步步移动，直到到达目标，计算每条路径的步数，并选择较小的值。 

这是可行的，因为打字机仅包含 26 个字母，因此每个可能的移动路径都是有限的且易于模拟。 

然而，这种方法执行了不必要的工作，因为可以使用算术直接计算圆距离。 我们可以通过数学方式计算顺时针距离和逆时针距离，而不是一次一步地模拟移动。 

### 最优贪心法

 关键的观察结果是，对于任意两个字母，最小移动成本很简单：

 - 它们的字母索引之间的直接距离。 
- 或通过圆形边界的环绕距离。 

如果当前指针位于字符处`current`我们想搬到`target`， 然后：

-`direct_distance = abs(target - current)`-`wrap_distance = 26 - direct_distance`最小移动成本为：```
min(direct_distance, wrap_distance)
```在支付了移动成本之后，我们总是要多花一秒钟的时间来输入字符。 

这种贪婪的决定是最优的，因为每个角色转换都是完全独立的。 没有理由采取更长的路线，因为移动成本是累加的，并且没有未来的惩罚或奖励。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * 26) | O(1) | O(1) | 逐步模拟顺时针和逆时针运动 |
 | 最佳| O(n) | O(1) | O(1) | 直接使用算术计算圆距离 |

 ## 算法演练

 1. 初始化指针位置为`'a'`。 

打字机总是从`'a'`，所以这是我们最初的当前角色。 
2. 初始化一个变量来存储总时间。 

该变量累计移动时间和打字时间。 
3. 遍历每个字符`word`。 

对于每个目标字符，确定指针必须移动多远。 
4. 将字符转换为数字位置。 

我们可以使用 ASCII 值将字母映射到整数：

 -`'a' -> 0`-`'b' -> 1`- ...
 -`'z' -> 25`这使得算术距离计算变得容易。 
5. 计算直接字母距离。```
direct_distance = abs(target_position - current_position)
```6. 计算环绕距离。 

由于字母形成一个大小为 26 的圆：```
wrap_distance = 26 - direct_distance
```7. 添加较小的移动成本。 

指针可以顺时针或逆时针移动，因此我们选择最小值。 
8. 增加输入字符的时间。 

每个字符都需要一次打字操作。 
9. 更新当前指针位置。 

输入字符后，指针现在停留在该字符上。 
10. 继续，直到处理完所有字符。 
11. 返回累计总时间。 

### 为什么它有效

 对于角色之间的每次转换，最短的可能移动要么是直接路径，要么是围绕圆圈的环绕路径。 由于转换之间的移动成本是独立的，因此为每个步骤选择局部最小移动也会最大限度地减少全局总时间。 每个字符增加一秒来满足所需的打字操作。 

## Python 解决方案```python
class Solution:
    def minTimeToType(self, word: str) -> int:
        current_position = 0  # 'a'
        total_time = 0

        for char in word:
            target_position = ord(char) - ord('a')

            direct_distance = abs(target_position - current_position)
            wrap_distance = 26 - direct_distance

            total_time += min(direct_distance, wrap_distance)

            # One second to type the character
            total_time += 1

            current_position = target_position

        return total_time
```实现直接遵循算法。 

变量`current_position`跟踪指针当前在圆形键盘上的位置。 由于指针开始于`'a'`，初始值为`0`。 

对于输入单词中的每个字符，代码使用以下方法将字符转换为其字母索引：```python
ord(char) - ord('a')
```然后代码计算两个可能的移动距离：

 - 直接字母距离。 
- 通过圆形边界的环绕距离。 

两个值中较小的一个将添加到总时间中。 移动后，会额外添加一秒来输入字符本身。 

最后，更新当前指针位置，以便下一次迭代从正确的位置开始。 

## 解决方案```go
func minTimeToType(word string) int {
	currentPosition := 0
	totalTime := 0

	for _, char := range word {
		targetPosition := int(char - 'a')

		directDistance := targetPosition - currentPosition
		if directDistance < 0 {
			directDistance = -directDistance
		}

		wrapDistance := 26 - directDistance

		if directDistance < wrapDistance {
			totalTime += directDistance
		} else {
			totalTime += wrapDistance
		}

		// One second to type the character
		totalTime++

		currentPosition = targetPosition
	}

	return totalTime
}
```Go 实现密切反映了 Python 逻辑。 

一个显着的区别是 Go 不提供内置的`abs()`函数用于整数，因此必须手动计算绝对值。 

该循环使用 Go runes 迭代字符串，尽管此问题仅包含小写 ASCII 字母。 整数溢出不是问题，因为最大可能的答案非常小。

 ## 边缘情况

 ### 重复字符

 像这样的输入`"aaa"`可能会暴露错误，即使指针已经位于正确的字符上，实现也会错误地增加移动成本。 

在这种情况下，直接距离为零，因此算法仅添加每个字符的打字成本。 该实现自然地处理了这个问题，因为：```
abs(target_position - current_position)
```当两个位置相同时，计算结果为零。 

### 圆形边界运动

 最重要的边缘情况是之间的移动`'a'`和`'z'`。 一个简单的实现可能会顺时针移动二十五步，而不是逆时针移动一步。 

该算法通过计算显式地处理这个问题：```
wrap_distance = 26 - direct_distance
```这可确保始终选择较短的圆形路径。 

### 单字符输入

 一个字符输入，例如`"a"`或者`"z"`是最小可能的输入大小。 

该算法仍然可以正常工作，因为循环只处理一个字符。 为了`"a"`，移动成本为零，打字成本为一。 为了`"z"`，算法正确地识别出逆时针移动一步比顺时针移动二十五步便宜。
