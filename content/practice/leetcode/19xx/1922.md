 # LeetCode 1922，数好数字

 ## 问题理解

 该问题要求我们计算长度有多少个数字字符串`n`满足特定的位置规则。 

在以下情况下，数字字符串被视为“良好”：

 - 每个数字都放在偶数索引处，即索引`0, 2, 4, ...`，本身必须是偶数。 
- 每个数字都放在奇数索引处，即索引`1, 3, 5, ...`, 必须是素数。 

有效的偶数位是：```
0, 2, 4, 6, 8
```所以有`5`每个偶数索引的选择。 

有效的素数数字是：```
2, 3, 5, 7
```所以有`4`每个奇数索引的选择。 

输入`n`表示数字串的长度。 我们必须返回有效字符串的总数模数：```
10^9 + 7
```约束非常重要：```
1 <= n <= 10^15
```这立即告诉我们显式生成字符串是不可能的。 甚至迭代`n`次是可以接受的，但是任何指数级的事情都是完全不可行的。 自从`n`可以大到一千万亿，我们需要一个对数时间的数学解。 

还有几个重要的边缘情况：

 -`n = 1`, 唯一索引`0`存在，所以只有偶数才重要。 
- 非常大的值`n`，其中直接乘法会溢出许多语言中的正常整数范围。 
- 奇数和偶数长度的行为略有不同，因为偶数索引位置和奇数索引位置的数量不相等`n`很奇怪。 

对于一个长度`n`：

 - 偶数索引的数量 =`(n + 1) // 2`- 奇数索引的数量 =`n // 2`最终计数变为：```
5^(even_positions) * 4^(odd_positions)
```计算模数`10^9 + 7`。 

## 方法

 ### 蛮力方法

 蛮力方法将生成每个可能的长度的数字字符串`n`并检查是否满足条件。 

对于每个位置：

 - 如果位置是偶数，请验证该数字是以下之一`{0,2,4,6,8}`。 
- 如果位置是奇数，请验证该数字是以下之一`{2,3,5,7}`。 

由于每个位置可以包含`10`位数，字符串总数为：$10^n$即使对于适度的值，这也会变得天文数字般大`n`。 

例如：

-`n = 20`已经给出了`10^20`的可能性。 
- 约束条件允许`n = 10^15`，使得暴力破解完全不可能。 

蛮力方法是正确的，因为它会检查每个可能的字符串，但它太慢了。 

### 最佳方法

 关键的观察是每个位置都是独立的。 

在每个偶数索引处：

 - 正好有`5`有效的选择。 

在每个奇数索引处：

 - 正好有`4`有效的选择。 

如果我们知道存在多少个偶数和奇数位置，我们可以直接使用乘法计算答案。 

让：```
even_positions = (n + 1) // 2
odd_positions = n // 2
```那么好字符串的总数为：$5^{\lfloor\frac{n+1}{2}\rfloor} \times 4^{\lfloor\frac{n}{2}\rfloor}$然而，这些指数非常大，因此我们必须使用快速求幂（也称为二进制求幂）有效地计算幂。 

二进制求幂计算：$a^b \bmod m$在`O(log b)`时间而不是`O(b)`时间。

 ## 算法演练

 1. 定义模常数。 

该问题要求所有结果取模`10^9 + 7`，所以我们存储：```
MOD = 1_000_000_007
```2. 计算存在多少个偶数索引位置。 

指数起始于`0`，因此对于奇数长度，有一个额外的偶数索引。 

我们计算：```
even_positions = (n + 1) // 2
```3. 计算存在多少个奇数索引位置。 

每个剩余位置都是奇数索引的：```
odd_positions = n // 2
```4. 计算偶数位置的贡献。 

每个偶数位置有`5`选择：```
5^(even_positions)
```因为指数可能很大，所以我们计算它的模`MOD`使用快速求幂。 
5. 计算奇数位置的贡献。 

每个奇数位置有`4`选择：```
4^(odd_positions)
```我们再次使用模幂。 
6. 将两个结果相乘。 

由于选择是独立的，我们将它们相乘：```
answer = (even_part * odd_part) % MOD
```7. 返回最终结果。 

### 为什么它有效

 该算法之所以有效，是因为每个索引对有效字符串总数的贡献是独立的。 

每个偶数索引总是恰好有`5`有效的选择，无论其他地方出现什么。 每个奇数索引总是恰好有`4`有效的选择。 根据组合学的乘法原理，有效字符串的总数等于每个位置的选择的乘积。 

快速求幂可保证有效计算非常大的幂，同时保持模运算下的正确性。 

## Python 解决方案```python
class Solution:
    def countGoodNumbers(self, n: int) -> int:
        MOD = 1_000_000_007

        even_positions = (n + 1) // 2
        odd_positions = n // 2

        even_count = pow(5, even_positions, MOD)
        odd_count = pow(4, odd_positions, MOD)

        return (even_count * odd_count) % MOD
```该实现直接遵循先前开发的数学观察。 

首先，代码计算存在多少个偶数索引和奇数索引位置。 因为索引从零开始，所以偶数位置的数量在以下情况下会稍大一些：`n`很奇怪。 

Python 内置的`pow(base, exponent, mod)`在内部执行快速模幂运算。 这是非常高效的并且以对数时间运行。 

偶数位置和奇数位置的结果分别计算，然后乘以模`MOD`。 

这个解决方案很简洁，因为 Python 已经提供了优化的模幂运算。 

## 解决方案```go
func countGoodNumbers(n int64) int {
	const MOD int64 = 1_000_000_007

	evenPositions := (n + 1) / 2
	oddPositions := n / 2

	evenCount := modPow(5, evenPositions, MOD)
	oddCount := modPow(4, oddPositions, MOD)

	return int((evenCount * oddCount) % MOD)
}

func modPow(base, exponent, mod int64) int64 {
	result := int64(1)

	base %= mod

	for exponent > 0 {
		if exponent%2 == 1 {
			result = (result * base) % mod
		}

		base = (base * base) % mod
		exponent /= 2
	}

	return result
}
```Go 版本手动实现二进制求幂，因为 Go 没有像 Python 那样提供内置的模块化幂函数。 

所有计算均使用`int64`以避免乘法过程中出现溢出问题。 每次乘法后都会应用模运算，因此值保持有界。 

算法逻辑在其他方面与 Python 实现相同。

 ## 边缘情况

 ### 边缘情况 1，最小长度

 当`n = 1`，只有索引`0`，这是一个偶数索引。 不存在奇怪的位置。 

一个常见的错误是错误地假设一半位置是奇数，一半是偶数。 实现正确计算：```
even_positions = (1 + 1) // 2 = 1
odd_positions = 1 // 2 = 0
```这产生了正确的答案`5`。 

### 边缘情况 2，奇数长度字符串

 对于奇数值`n`，偶数索引位置总是比奇数索引位置多一个，因为索引从零开始。 

例如：```
n = 5
indices = 0 1 2 3 4
```甚至指数是：```
0, 2, 4
```奇数索引是：```
1, 3
```有缺陷的实现可能会使用`n // 2`对于这两项计算，都会错过一个位置。 该实现通过使用来避免这种情况`(n + 1) // 2`对于偶数位置。 

### 边缘情况 3，极大的输入

 该约束允许：```
n <= 10^15
```直接乘法循环或递归扩展会太慢。 

该实现使用二进制求幂正确处理这个问题，从而将复杂性降低到`O(log n)`。 即使对于最大可能的输入，计算也能很快完成。 

### 边缘情况 4，整数溢出

 中间值如：```
5^(10^15)
```都大得难以想象。 

如果在求幂期间不应用模运算，那么在 Go 或 Java 等固定宽度整数语言中就会发生整数溢出。 

该实现在每个乘法步骤中应用模运算，确保所有值在整个计算过程中保持在安全范围内。
