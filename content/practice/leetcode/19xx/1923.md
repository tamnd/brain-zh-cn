[LeetCode 1923 题](https://leetcode.com/problems/longest-common-subpath/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、滚动哈希、后缀数组、哈希函数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到出现在每个朋友的旅行路径中的连续城市序列的最大长度。 

每个朋友都有一条表示为城市 ID 数组的路径。 子路径只是该数组的连续段。 我们需要确定所有路径共享的最长子路径。 

例如，如果一条路径是：```
[0,1,2,3,4]
```那么有效的子路径包括：```
[0]
[1,2]
[2,3,4]
[0,1,2,3]
```但不是：```
[0,2,4]
```因为子路径必须保持连续。 

输入包含：

 -`n`, 城市总数
 -`paths`，路径列表，每个朋友一个

 输出是一个整数，表示每个路径中出现的公共子路径的最大可能长度。 

约束条件极其重要：

 - 所有路径的总长度最多为`10^5`- 路径数量也可以很大
 - 个别路径可能很长

 这些限制立即排除了简单的子串比较方法。 任何在路径长度上具有二次或三次行为的算法都会超时。 

另一个重要的观察结果是答案必须介于`0`和最短路径的长度。 公共子路径不能比最小路径长。 

有几种边缘情况值得考虑：

 - 完全没有共同城市的路径，答案是`0`- 只有单个城市重叠的路径，答案是`1`- 路径内有多个重复的城市
 - 需要高效散列的非常大的路径
 - 候选子路径较多，需要快速比较的情况

 该问题保证没有城市连续出现在同一条路径上，但这个细节不会显着改变核心算法。 

## 方法

 ### 蛮力方法

 一种简单的方法是从一个路径生成每个可能的子路径，然后检查它是否存在于所有其他路径中。 

假设第一条路径有长度`L`。 

子路径的数量为：```
O(L^2)
```对于每个候选子路径，我们需要搜索所有其他路径以确定它是否出现。 

简单的子字符串搜索本身可能需要线性时间，从而使总复杂性变得巨大。 

这种方法是正确的，因为它显式检查每个可能的公共子路径，但对于给定的约束来说它太慢了。 

### 关键见解

 关键的观察是该问题要求最大可能的长度，这强烈建议对答案进行二分搜索。 

如果存在长度为的公共子路径`k`，那么每个更小的长度也是可能的。 

这创建了一个单调属性：```
possible(k) => possible(k-1)
```这允许对子路径长度进行二分搜索。 

剩下的挑战是有效地检查是否存在给定长度的公共子路径。 

为此，我们使用滚动哈希。 

对于固定长度`k`：

 - 计算所有长度子路径的哈希值`k`在每条路径中
 - 将它们存储在集合中
 - 使所有路径的集合相交
 - 如果交集非空，则存在公共子路径

 滚动哈希允许我们在预处理后在恒定时间内计算子路径哈希。 

使用双重散列显着降低了冲突概率。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(长×米) | O(L²) | 直接生成并比较所有子路径 |
 | 最佳| O(T log M) | O(T log M) | O(T)| 使用滚动哈希进行二分搜索 |
 | | | |`T = total path length`,`M = shortest path length`|

 ## 算法演练

 ### 第 1 步：确定搜索范围

 答案不能超过最短路径长度。 

所以我们在以下之间进行二分搜索：```
0 and min(len(path))
```这最小化了搜索空间。 

### 步骤 2：预计算滚动哈希的幂

 滚动哈希需要所选基数的权力。 

我们预先计算：```
base^0, base^1, ..., base^maxLength
```对大素数取模。 

我们使用两个 mod 值进行双重哈希：```
mod1 = 1_000_000_007
mod2 = 1_000_000_009
```双散列大大降低了碰撞风险。 

### 步骤 3：子路径长度二分查找

 对于每个中点`mid`：

 - 检查是否存在长度相同的公共子路径`mid`存在
 - 如果是，请尝试更大的长度
 - 否则尝试更小的长度

 这是由于单调性而有效的。 

### 步骤 4：计算滚动哈希

 对于路径：```
[a,b,c,d,e]
```我们计算前缀哈希：```
H[i]
```因此可以在恒定时间内提取任何子路径哈希。 

对于子路径`[l:r]`：$hash(l,r)=H[r]-H[l]\cdot base^{(r-l)}$所有运算均以所选质数为模进行。 

### 步骤 5：构建哈希集

 对于第一条路径：

 - 计算所有长度的哈希值`mid`- 将它们存储在一组中

 对于所有其他路径：

 - 计算所有长度的哈希值`mid`- 与当前候选集相交

 如果该集合变空，则不存在公共子路径。 

### 第 6 步：返回最终答案

 二分查找完成后，返回找到的最大有效长度。 

### 为什么它有效

 二分查找是有效的，因为如果公共子路径的长度`k`存在，那么每个更小的长度也存在。 

滚动哈希保证有效的子路径比较。 我们不直接比较数组，而是比较紧凑的哈希表示。 

通过交叉所有路径上的哈希集，我们确保只有出现在每个路径中的子路径才能生存。 

因此，当交集非空时，该长度存在公共子路径。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestCommonSubpath(self, n: int, paths: List[List[int]]) -> int:
        min_len = min(len(path) for path in paths)

        base = 100001
        mod1 = 1_000_000_007
        mod2 = 1_000_000_009

        max_len = max(len(path) for path in paths)

        pow1 = [1] * (max_len + 1)
        pow2 = [1] * (max_len + 1)

        for i in range(1, max_len + 1):
            pow1[i] = (pow1[i - 1] * base) % mod1
            pow2[i] = (pow2[i - 1] * base) % mod2

        def get_hashes(path: List[int], length: int):
            if length == 0:
                return {(0, 0)}

            n_path = len(path)

            prefix1 = [0] * (n_path + 1)
            prefix2 = [0] * (n_path + 1)

            for i in range(n_path):
                prefix1[i + 1] = (prefix1[i] * base + path[i] + 1) % mod1
                prefix2[i + 1] = (prefix2[i] * base + path[i] + 1) % mod2

            hashes = set()

            for i in range(n_path - length + 1):
                j = i + length

                hash1 = (
                    prefix1[j]
                    - prefix1[i] * pow1[length]
                ) % mod1

                hash2 = (
                    prefix2[j]
                    - prefix2[i] * pow2[length]
                ) % mod2

                hashes.add((hash1, hash2))

            return hashes

        def exists(length: int) -> bool:
            common = get_hashes(paths[0], length)

            for i in range(1, len(paths)):
                current_hashes = get_hashes(paths[i], length)
                common &= current_hashes

                if not common:
                    return False

            return True

        left = 0
        right = min_len
        answer = 0

        while left <= right:
            mid = (left + right) // 2

            if exists(mid):
                answer = mid
                left = mid + 1
            else:
                right = mid - 1

        return answer
```实现首先找到最小路径长度，因为答案不能超过它。 

接下来，代码预先计算两个模的滚动哈希基的幂。 这允许稍后进行恒定时间子字符串哈希提取。 

这`get_hashes`函数计算单个路径内固定长度子路径的所有滚动哈希值。 它使用前缀哈希，因此每个子路径哈希都会在恒定时间内提取。 

这`exists`函数判断是否存在特定长度的公共子路径。 它从第一个路径中的所有哈希开始，然后与其余路径中的哈希重复相交。 如果交叉点变空，则该长度不存在公共子路径。 

最后，二分查找找到最大的有效长度。 

## 解决方案```go
package main

func longestCommonSubpath(n int, paths [][]int) int {
	minLen := len(paths[0])

	maxLen := 0

	for _, path := range paths {
		if len(path) < minLen {
			minLen = len(path)
		}
		if len(path) > maxLen {
			maxLen = len(path)
		}
	}

	const base int64 = 100001
	const mod1 int64 = 1_000_000_007
	const mod2 int64 = 1_000_000_009

	pow1 := make([]int64, maxLen+1)
	pow2 := make([]int64, maxLen+1)

	pow1[0] = 1
	pow2[0] = 1

	for i := 1; i <= maxLen; i++ {
		pow1[i] = (pow1[i-1] * base) % mod1
		pow2[i] = (pow2[i-1] * base) % mod2
	}

	type Pair struct {
		a int64
		b int64
	}

	getHashes := func(path []int, length int) map[Pair]struct{} {
		hashes := make(map[Pair]struct{})

		if length == 0 {
			hashes[Pair{0, 0}] = struct{}{}
			return hashes
		}

		nPath := len(path)

		prefix1 := make([]int64, nPath+1)
		prefix2 := make([]int64, nPath+1)

		for i := 0; i < nPath; i++ {
			prefix1[i+1] = (prefix1[i]*base + int64(path[i]+1)) % mod1
			prefix2[i+1] = (prefix2[i]*base + int64(path[i]+1)) % mod2
		}

		for i := 0; i+length <= nPath; i++ {
			j := i + length

			hash1 := (prefix1[j] - prefix1[i]*pow1[length]) % mod1
			hash2 := (prefix2[j] - prefix2[i]*pow2[length]) % mod2

			if hash1 < 0 {
				hash1 += mod1
			}

			if hash2 < 0 {
				hash2 += mod2
			}

			hashes[Pair{hash1, hash2}] = struct{}{}
		}

		return hashes
	}

	exists := func(length int) bool {
		common := getHashes(paths[0], length)

		for i := 1; i < len(paths); i++ {
			current := getHashes(paths[i], length)

			nextCommon := make(map[Pair]struct{})

			for key := range common {
				if _, ok := current[key]; ok {
					nextCommon[key] = struct{}{}
				}
			}

			common = nextCommon

			if len(common) == 0 {
				return false
			}
		}

		return true
	}

	left := 0
	right := minLen
	answer := 0

	for left <= right {
		mid := (left + right) / 2

		if exists(mid) {
			answer = mid
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return answer
}
```Go 版本遵循与 Python 实现相同的逻辑。 

一个重要的区别是处理模减法。 在围棋中，`%`可能会产生负值，因此我们在必要时显式添加模数。 

Go 解决方案还使用自定义`Pair`用于在映射内存储双散列的结构。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(T log M) | O(T log M) | 对长度进行二分搜索，每次检查都会扫描所有路径 |
 | 空间| O(T)| 哈希集和前缀数组 |
 | | |`T = total path length`,`M = shortest path length`|

 对于每个二分搜索迭代，每个路径都被处理一次以计算滚动哈希。 由于二分查找执行`log M`迭代后，整体复杂度变为`O(T log M)`。 

空间使用主要来自存储哈希集和前缀数组。

 ## 边缘情况

 当根本没有共享城市时，就会出现一种重要的边缘情况。 在这种情况下，即使子路径长度`1`失败。 有缺陷的实现可能会错误地假设由于哈希冲突或不正确的集处理而存在一些重叠。 双散列方法和显式集合交集保证了正确性。 

另一个关键的边缘情况涉及重复的模式，例如：```
[1,2,1,2,1]
```滚动哈希实现可能会意外地错误处理重叠窗口或计算不正确的前缀范围。 该实现使用前缀哈希独立地仔细计算每个固定长度的子路径，确保正确处理重叠序列。 

当所有路径都相同时，会出现第三种重要情况。 正确答案应该等于完整路径长度。 因此，二分搜索必须允许测试上边界本身。 使用：```
while left <= right
```确保考虑最大可能值。 

最后，长度差异很大的路径可能会产生微妙的错误。 由于公共子路径不能超过最短路径，因此该算法明确将二分搜索限制为最小路径长度。 这可以防止无效的窗口计算和不必要的工作。
