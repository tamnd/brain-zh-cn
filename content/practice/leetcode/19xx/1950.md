[LeetCode 1950 题](https://leetcode.com/problems/maximum-of-minimum-values-in-all-subarrays/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 这个问题要求我们为每个可能的子数组大小计算该大小的所有子数组中的最佳可能最小值。 

给定一个数组`nums`长度`n`，我们必须评估每个窗口大小`1`到`n`。 对于每个尺寸`k`，我们考虑长度的所有连续子数组`k`。 每个这样的子数组都有一个最小元素。 在所有这些最小值中，我们选择最大值。 

输出数组`ans`有长度`n`， 在哪里：

-`ans[0]`对应于大小的子数组`1`-`ans[1]`对应于大小的子数组`2`-`ans[i]`对应于大小的子数组`i + 1`关键的难点在于约束条件较大：

 -`n`可以达到`100000`- 简单的嵌套窗口解决方案变得太慢

 显式计算所有子数组的强力方法需要二次或三次工作，这在这种规模下是不可行的。 

重要的观察是每个元素都可以充当一系列子数组的最小值。 我们可以确定特定元素保持最小值的最大窗口大小，而不是迭代每个子数组。 这将问题转化为单调堆栈问题。 

一些边缘情况很重要：

 - 具有所有相等值的数组
 - 严格增加数组
 - 严格递减数组
 - 包含重复最小值的数组
 - 大小的数组`1`正确处理重复项尤其重要，因为单调堆栈中不正确的不等式选择可能会产生重叠范围或丢失窗口。 

## 方法

 ### 蛮力方法

 最直接的解决方案是评估每个可能的子数组。 

适用于每种窗户尺寸`k`：

 1.枚举所有length的子数组`k`2. 计算每个子数组中的最小值
 3. 跟踪这些最小值中的最大值

 例如，与`nums = [0,1,2,4]`和`k = 2`：

 -`[0,1] -> min = 0`-`[1,2] -> min = 1`-`[2,4] -> min = 2`尺寸的答案`2`是`2`。 

此方法是正确的，因为它显式检查每个所需的子数组。 然而，它太慢了。 

如果我们天真地计算最小值，那么：

 - 有`O(n)`窗户尺寸
 - 每个尺寸都有`O(n)`子数组
 - 每个最小计算成本`O(n)`总复杂度变为`O(n^3)`。 

即使使用滑动窗口优化，单独获得所有答案仍然会导致过多的工作。 

### 最佳方法

 最佳解决方案使用单调堆栈。 

中心见解是这样的：

 而不是问：

 >“每个子数组的最小值是多少？”

 我们问：

 >“给定元素最小的是哪个子数组？”

 对于每个元素`nums[i]`，我们确定：

 - 左边最近的较小元素
 - 右侧最近的较小元素

 这些边界告诉我们最大的窗口`nums[i]`保持最小值。 

如果：

-`left[i]`是前一个较小元素的索引
 -`right[i]`是下一个较小元素的索引

 然后`nums[i]`是内部所有窗口的最小值：```
(left[i], right[i])
```最大窗口长度为：```
right[i] - left[i] - 1
```这意味着：

-`nums[i]`可以作为该尺寸窗口的最小值
 - 因此它是该窗口长度的候选答案

 我们使用单调堆栈在线性时间内计算这些范围。 

填充候选答案后，我们向后传播值，因为如果一个值适用于较大的窗口，它也会限制较小的窗口。

 ## 算法演练

 ### 步骤 1：计算先前较小的元素

 我们维持一个不断增加的单调堆栈。 

对于每个索引`i`：

 - 当栈顶大于或等于时弹出元素`nums[i]`- 剩余的顶部成为先前较小的元素
 - 如果堆栈为空，则使用`-1`这给出了左边界`nums[i]`不再是最小值。 

### 步骤 2：计算下一个较小的元素

 我们从右到左重复这个过程。 

对于每个索引`i`：

 - 当顶部大于或等于时弹出元素`nums[i]`- 剩余的顶部成为下一个较小的元素
 - 如果不存在，则使用`n`这给出了正确的边界。 

### 步骤 3：确定每个元素的最大窗口大小

 对于每个索引`i`：```
window_size = right[i] - left[i] - 1
```这是最大的子数组长度，其中`nums[i]`是最小值。 

我们更新：```
ans[window_size - 1] = max(ans[window_size - 1], nums[i])
```因为我们想要每个窗口大小的最大可能最小值。 

### 步骤 4：填写缺失的条目

 某些窗口大小可能保持未设置状态。 

例子：```
[50, 0, 10, 0]
```随着窗口大小的增加，答案一定不会增加。 

如果一个值适用于较大的窗口，它也会限制较小的窗口。 

所以我们从右向左处理：```
ans[i] = max(ans[i], ans[i + 1])
```这将正确填充所有缺失值。 

### 为什么它有效

 对于每个元素，单调堆栈标识该元素为最小值的最大连续范围。 完全在该范围内的任何子数组都将该元素作为其最小值。 

因此，每个元素都准确地影响了它可以作为最小值的窗口大小。 对每个窗口大小取最大贡献可以保证正确的答案。 

反向传播步骤之所以有效，是因为答案序列是单调的：```
ans[i] >= ans[i + 1]
```较大的窗口不能比较小的窗口具有更大的最大最小值。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaximums(self, nums: List[int]) -> List[int]:
        n = len(nums)

        left = [-1] * n
        right = [n] * n

        stack = []

        # Previous smaller element
        for i in range(n):
            while stack and nums[stack[-1]] >= nums[i]:
                stack.pop()

            if stack:
                left[i] = stack[-1]

            stack.append(i)

        stack.clear()

        # Next smaller element
        for i in range(n - 1, -1, -1):
            while stack and nums[stack[-1]] >= nums[i]:
                stack.pop()

            if stack:
                right[i] = stack[-1]

            stack.append(i)

        ans = [0] * n

        # Assign values to window sizes
        for i in range(n):
            window_size = right[i] - left[i] - 1
            ans[window_size - 1] = max(
                ans[window_size - 1],
                nums[i]
            )

        # Fill missing values
        for i in range(n - 2, -1, -1):
            ans[i] = max(ans[i], ans[i + 1])

        return ans
```该实现首先计算每个位置两侧最近的较小元素。 单调堆栈确保每个元素最多被压入和弹出一次，从而提供线性复杂性。 

这`left`数组存储前一个较小元素的索引。 这`right`数组存储下一个较小的元素。 

一旦知道这些边界，代码就会计算每个元素保持最小值的最大窗口。 该窗口大小决定了该元素贡献于哪个应答槽。 

最后，向后传递填补了空白并增强了答案的单调性。 

## 解决方案```go
func findMaximums(nums []int) []int {
	n := len(nums)

	left := make([]int, n)
	right := make([]int, n)

	for i := 0; i < n; i++ {
		left[i] = -1
		right[i] = n
	}

	stack := []int{}

	// Previous smaller element
	for i := 0; i < n; i++ {
		for len(stack) > 0 && nums[stack[len(stack)-1]] >= nums[i] {
			stack = stack[:len(stack)-1]
		}

		if len(stack) > 0 {
			left[i] = stack[len(stack)-1]
		}

		stack = append(stack, i)
	}

	stack = []int{}

	// Next smaller element
	for i := n - 1; i >= 0; i-- {
		for len(stack) > 0 && nums[stack[len(stack)-1]] >= nums[i] {
			stack = stack[:len(stack)-1]
		}

		if len(stack) > 0 {
			right[i] = stack[len(stack)-1]
		}

		stack = append(stack, i)
	}

	ans := make([]int, n)

	// Assign values to window sizes
	for i := 0; i < n; i++ {
		windowSize := right[i] - left[i] - 1

		if nums[i] > ans[windowSize-1] {
			ans[windowSize-1] = nums[i]
		}
	}

	// Fill missing values
	for i := n - 2; i >= 0; i-- {
		if ans[i+1] > ans[i] {
			ans[i] = ans[i+1]
		}
	}

	return ans
}
```Go 实现遵循与 Python 版本相同的算法结构。 

切片用于堆栈是因为追加和截断效率很高。 整数溢出不是问题，因为值的边界为`10^9`，它安全地适合 Go 的内部`int`在标准 LeetCode 环境中。 

数组用哨兵值初始化：

 -`-1`对于缺少左边界
 -`n`缺少右边界

 这简化了窗口长度的计算。

from typing import List

class Solution:
    def findMaximums(self, nums: List[int]) -> List[int]:
        n = len(nums)

        left = [-1] * n
        right = [n] * n

        stack = []

        for i in range(n):
            while stack and nums[stack[-1]] >= nums[i]:
                stack.pop()

            if stack:
                left[i] = stack[-1]

            stack.append(i)

        stack.clear()

        for i in range(n - 1, -1, -1):
            while stack and nums[stack[-1]] >= nums[i]:
                stack.pop()

            if stack:
                right[i] = stack[-1]

            stack.append(i)

        ans = [0] * n

        for i in range(n):
            size = right[i] - left[i] - 1
            ans[size - 1] = max(ans[size - 1], nums[i])

        for i in range(n - 2, -1, -1):
            ans[i] = max(ans[i], ans[i + 1])

        return ans

 ## 边缘情况

 一个重要的边缘情况是包含所有相同值的数组，例如`[2,2,2,2]`。 重复处理是单调堆栈问题中错误的常见来源。 如果堆栈比较使用不一致的不等式，则元素可能会错误地重叠范围或留下间隙。 该实现始终使用`>=`弹出时，确保正确处理重复项并且每个窗口都收到正确的答案。 

另一个重要的情况是严格递增的数组，例如`[1,2,3,4,5]`。 在这种情况下，每个元素都成为所有向左延伸的窗口的最小值。 该算法正确地识别逐渐变大的范围，并产生答案`[5,4,3,2,1]`。 

严格递减数组，例如`[5,4,3,2,1]`也很重要，因为每个新元素都会立即成为迄今为止看到的最小元素。 这严重强调了堆栈弹出逻辑。 由于每个索引仍然只被压入和弹出一次，因此该算法保持线性复杂度。 

最小的有效输入，一个单元素数组，例如`[5]`，也必须正确工作。 该元素成为唯一可能的窗口大小的最小值`1`，所以答案很简单`[5]`。 边界初始化为`-1`和`n`确保此案例无需特殊处理即可自然运行。
