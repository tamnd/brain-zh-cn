 # LeetCode 1920，从排列构建数组

 ## 问题理解

 该问题为我们提供了一个从零开始的排列数组，称为`nums`。 排列意味着每个整数`0`到`n - 1`恰好出现一次，其中`n`是数组的长度。 由于数组包含不同的值并覆盖整个范围，因此中的每个值`nums`也是同一数组的有效索引。 

我们必须构造一个新数组，称为`ans`这样：```
ans[i] = nums[nums[i]]
```对于每个有效索引`i`。 

换句话说，对于每个位置`i`，我们首先查找`nums[i]`，然后使用该结果作为另一个索引`nums`，并将结果值存储到`ans[i]`。 

例如，如果：```
nums = [0,2,1,5,3,4]
```然后：

-`ans[0] = nums[nums[0]] = nums[0] = 0`-`ans[1] = nums[nums[1]] = nums[2] = 1`-`ans[2] = nums[nums[2]] = nums[1] = 2`等等。 

限制相对较小：

 -`1 <= nums.length <= 1000`- 每个元素都是独特的
 - 每个值都在有效索引范围内

 这些限制告诉我们一些重要的事情：

 - 我们不需要运行时的高级优化，因为`n = 1000`很小。 
- 简单的线性解决方案就足够了。 
- 由于每个值都保证是有效的索引，因此我们在访问时不需要边界检查`nums[nums[i]]`。 
- 因为输入保证是排列，所以不存在与重复相关的边缘情况。 

主要的边缘情况涉及非常小的数组，尤其是长度数组`1`，以及元素指向自身或形成循环的排列。 幸运的是，排列保证确保所有访问保持有效。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是新建一个数组`ans`并独立计算每个值。 

对于每个索引`i`：

 1. 阅读`nums[i]`2. 使用该值作为索引`nums`3. 将结果存储在`ans[i]`这是有效的，因为问题定义直接告诉我们每个元素应该如何构造。 

对于给定的约束，蛮力方法已经足够有效，因为每次查找都需要恒定的时间，并且我们对每个索引执行一次计算。 

### 最佳解决方案的关键见解

 后续询问我们是否可以使用以下方法解决问题`O(1)`额外的内存。 

重要的观察是，每个值`nums`小于`n`。 这允许我们临时对同一数组元素内的两个值进行编码。 

我们可以存储：

 - 原始值
 - 新的转换值

 使用模运算在一个整数内。 

具体来说：```
nums[i] = original + new * n
```之后：

-`original = nums[i] % n`-`new = nums[i] // n`这是有效的，因为所有原始值都严格小于`n`。 

通过仔细地编码和解码值，我们可以就地修改数组，而不会丢失未来计算所需的原始信息。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用单独的结果数组 |
 | 最佳| O(n) | O(1) | O(1) | 就地编码旧值和新值 |

 ## 算法演练

 ### 最佳就地算法

 1.让`n`是数组的长度。 

我们需要`n`因为它将充当编码基础。 由于每个原始值都小于`n`，模运算安全运行。 
2. 从左到右遍历数组。 

对于每个索引`i`，我们要存储新值`nums[nums[i]]`同时仍然保留数组的原始内容。 
3. 提取原始值`nums[i]`。 

由于某些值可能已经在早期迭代中被修改，我们使用以下方法恢复原始值：```
nums[i] % n
```4. 计算目标值。 

所需的新值为：```
nums[nums[i]]
```但由于该目标位置也可能已经包含编码数据，因此我们再次使用模：```
nums[nums[i]] % n
```5. 将两个值编码到当前位置。 

店铺：```
nums[i] += (new_value % n) * n
```现在该元素包含两者：

 - 下部的原始值
 - 较高部分的新值
 6. 对阵列执行第二次遍历。 

使用整数除法提取最终的转换值：```
nums[i] //= n
```7. 返回修改后的数组。 

### 为什么它有效

 该算法之所以有效，是因为每个原始值都在范围内`[0, n - 1]`。 

当我们编码时：```
encoded = original + new * n
```模运算返回原始值：```
encoded % n = original
```整数除法检索新值：```
encoded // n = new
```这个不变量保证了即使在修改元素之后，原始信息在整个计算过程中仍然是可恢复的。 

## Python 解决方案```python
from typing import List

class Solution:
    def buildArray(self, nums: List[int]) -> List[int]:
        n = len(nums)

        # Encode both old and new values into nums[i]
        for i in range(n):
            new_value = nums[nums[i]] % n
            nums[i] += new_value * n

        # Extract the new values
        for i in range(n):
            nums[i] //= n

        return nums
```实现首先计算数组长度`n`，用作编码基础。 

在第一个循环期间，每个元素都会转换为包含原始值和所需新值的编码值。 模运算确保我们始终检索原始值，即使元素已经更新。 

第二个循环通过将每个元素整数除以来删除原始组件`n`。 此时，每个位置都准确包含所需的答案。 

最后返回修改后的数组。 

## 解决方案```go
func buildArray(nums []int) []int {
	n := len(nums)

	// Encode old and new values together
	for i := 0; i < n; i++ {
		newValue := nums[nums[i]] % n
		nums[i] += newValue * n
	}

	// Extract the new values
	for i := 0; i < n; i++ {
		nums[i] /= n
	}

	return nums
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 中的切片的行为类似于动态数组，因此修改`nums`直接更新底层数据结构。 

整数溢出不是问题，因为：```go
n <= 1000
```最大编码值大约为：```go
999 + 999 * 1000 = 999999
```它很容易适合 Go 的整数类型。 

Go 也自然地处理空切片，尽管问题约束保证至少有一个元素。

 ## 边缘情况

 ### 单元素数组

 最小的有效输入是：```
[0]
```粗心的实现可能会假设至少存在两个元素，或者意外地错误处理索引逻辑。 在这种情况下：```
ans[0] = nums[nums[0]] = nums[0] = 0
```该实现自然地处理了这个问题，因为循环仍然正确执行`n = 1`。 

### 身份排列

 身份排列如下所示：```
[0,1,2,3]
```每个值都指向自身，因此输出应该保持不变。 

这种情况很重要，因为它验证了算法在就地编码和解码期间不会意外损坏值。 

### 循环排列

 数组如：```
[1,2,0]
```形成循环。 

这些情况对于就地方法尤其重要，因为值被多次重用为索引。 有缺陷的实现可能会过早覆盖信息并丢失原始映射。 

模运算确保原始值在整个处理过程中保持可恢复，即使在循环结构中也保证了正确性。
