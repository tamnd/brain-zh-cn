[LeetCode 1989 问题](https://leetcode.com/problems/maximum-number-of-people-that-can-be-caught-in-tag/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、贪婪

 ## 解决方案

 ## 问题理解

 该问题描述了用二进制数组表示的一行人`team`，其中每个索引对应一个人。 值为`1`表示一个人是“it”，并且值为`0`表示不是“它”的人。 每个“it”人最多可以捕获一个非“it”人，并且前提是该目标位于对称距离窗口内`[i - dist, i + dist]`。 

目标是最大化捕获的非“it”人的总数，因为每个“it”人只能捕获一个目标，并且每个非“it”人最多可以捕获一次。 这自然会引入类似二分匹配的约束，但结构是线性的，这允许贪婪的双指针策略。 

输入是一个大小可达的数组`10^5`，所以一个`O(n^2)`解决办法太慢了。 整数`dist`定义了一个本地交互窗口，这意味着每个`1`只能“看到”有限范围的指数。 

边缘情况包括没有的情况`1`有或没有`0`s，所有情况`0`s 位于所有有效窗口之外，并且存在多个`1`s 竞争相同的`0`，需要仔细的贪婪分配以避免早期匹配不理想。 

## 方法

 蛮力思想会尝试每一种可能的配对：对于每一个`1`，扫描其有效范围并选择一个未捕获的`0`。 这在逻辑上是可行的，因为它尊重约束，但效率很低，因为每个`n`位置最多可扫描`2 * dist`甚至`n`元素，在最坏的情况下导致二次行为。 

优化的关键见解是，问题本质上是关于在区间约束下匹配排序位置。 如果我们提取所有的索引`0`和所有`1`s，我们可以使用两个指针贪婪地匹配它们，总是分配最早可能的有效指针`0`对每个`1`。 这确保了未来的分配不会被不必要地阻塞，这是区间匹配问题的标准贪婪最优原则。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n·距离) 到 O(n²) | O(1) 额外 | 尝试每一个`1`反对所有可达的`0`s |
 | 最优贪心二指针 | O(n) | O(n) | 匹配排序索引`1`沙`0`贪婪地|

 ## 算法演练

 最佳解决方案的工作原理是将问题分为两个排序序列：一个包含所有属于“它”的人的索引，另一个包含所有不属于“它”的人的索引。 一旦我们有了这两个列表，我们就会在有效性约束下贪婪地匹配它们。 

1.首先我们扫描`team`数组并收集两个列表：`ones`，它存储所有具有价值的位置的索引`1`， 和`zeros`，它存储所有具有价值的位置的索引`0`。 这种转换将问题简化为匹配两个已排序的整数数组。 
2.我们初始化两个指针，`i`用于迭代`ones`和`j`用于迭代`zeros`。 我们还设有柜台`result`跟踪成功的比赛。 
3. 对于每个`ones[i]`，我们试图找到最早有效的`zeros[j]`位于其可捕获范围内。 有效条件为`abs(ones[i] - zeros[j]) <= dist`。 
4.如果`zeros[j]`太左了（即`zeros[j] < ones[i] - dist`)，那么它就不能与这个或任何未来匹配`ones[i]`这是更右边的，所以我们增加`j`。 
5. 如果`zeros[j]`在范围内，我们分配这个`0`到目前的`1`，增加两个指针，并增加结果计数器。 
6. 如果`zeros[j]`太右了，我们转到下一个`1`因为当前`0`还无法匹配。 
7. 我们继续，直到用尽任一列表。 

贪心选择总是分配最左边可用的有效值`0`到目前的`1`，确保我们为未来的比赛保留更大的灵活性。 

### 为什么它有效

 正确性依赖于贪婪不变量：在每一步，我们都匹配最左边的可行的`0`与当前的`1`按排序顺序。 这可以防止“浪费”关闭`0`在稍后的`1`何时可以更早使用它，否则会减少总匹配数。 由于两个列表都是按顺序处理的，因此任何替代分配都可以转换为这种贪婪解决方案，而无需减少匹配数，从而建立最优性。 

## Python 解决方案```python
from typing import List

class Solution:
    def catchMaximumAmountofPeople(self, team: List[int], dist: int) -> int:
        ones = []
        zeros = []

        for i, v in enumerate(team):
            if v == 1:
                ones.append(i)
            else:
                zeros.append(i)

        i = 0
        j = 0
        result = 0

        while i < len(ones) and j < len(zeros):
            if zeros[j] < ones[i] - dist:
                j += 1
            elif zeros[j] > ones[i] + dist:
                i += 1
            else:
                result += 1
                i += 1
                j += 1

        return result
```实现首先提取两个类别的索引列表。 然后，它使用两指针遍历来贪婪地匹配有效对。 如果一个`0`太靠左，则将其丢弃以供将来考虑。 如果有效，我们立即进行匹配。 如果太右了，我们就提前`1`寻找更好候选人的指针。 

## 解决方案```go
func catchMaximumAmountofPeople(team []int, dist int) int {
    ones := make([]int, 0)
    zeros := make([]int, 0)

    for i, v := range team {
        if v == 1 {
            ones = append(ones, i)
        } else {
            zeros = append(zeros, i)
        }
    }

    i, j := 0, 0
    result := 0

    for i < len(ones) && j < len(zeros) {
        if zeros[j] < ones[i]-dist {
            j++
        } else if zeros[j] > ones[i]+dist {
            i++
        } else {
            result++
            i++
            j++
        }
    }

    return result
}
```在 Go 中，使用切片而不是动态列表，但逻辑保持不变。 整数算术是安全的，因为索引和约束符合标准`int`。 不需要对 nil 切片进行特殊处理，因为附加到 nil 切片在 Go 中是有效的。

 ## 边缘情况

 一种重要的边缘情况是数组仅包含零或仅包含一。 在这两种情况下，都不可能进行匹配，因为二分结构是简并的。 该实现自然地处理了这个问题，因为列表之一（`ones`或者`zeros`) 将为空，并且两指针循环将永远不会执行。 

另一种边缘情况发生在`dist`为零。 在这种情况下，只允许精确的索引对齐。 该算法仍然可以正确工作，因为条件`zeros[j] >= ones[i] - dist`和`zeros[j] <= ones[i] + dist`折叠为相等，并且仅匹配相同的索引。 

第三种边缘情况是当`dist`相对于数组大小来说非常大。 在这种情况下，每个`1`可以匹配任何`0`，算法将贪婪地将它们一对一配对，直到耗尽一个列表。 正确性成立是因为贪心策略确保了完全连接的二分区间图中的最大基数匹配。
