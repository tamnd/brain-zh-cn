 **难度：** 🟡 中等
 **主题：** 数组、二分查找、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定未排序的数组中有多少数字仍然可以保证通过随机二分搜索过程找到。 

数组`nums`包含唯一的整数。 搜索过程从当前剩余序列中重复选择一个随机主元元素。 根据主元是小于还是大于目标，部分序列将被丢弃。 与标准二分搜索不同，序列不一定是排序的，因此消除过程可能会意外删除目标，即使目标存在。 

我们必须确定哪些值是“二进制可搜索的”。 如果无论在过程中如何选择主元，算法最终都能找到它，则该值是可二分搜索的。 

重要的短语是“对于每一个可能的枢轴选择”。 我们有时不会检查是否可以找到该值。 我们正在检查随机过程是否不可能错误地消除它。 

输入大小可以大到`10^5`，它立即告诉我们任何二次或三次模拟都会太慢。 我们需要一种以线性或接近线性时间运行的算法。 

该数组包含唯一值，这简化了比较，因为我们永远不必担心不同索引之间的相等性。 后续问题分别询问重复项。 

一些边缘情况很重要：

 - 单元素数组始终只有一个可搜索的数字。 
- 完全排序的数组使每个数字都可以搜索。 
- 完全颠倒的数组通常会留下很少的可搜索数字。 
- 如果右侧存在较小的数字或左侧存在较大的数字，则靠近中间的数字可能会失败。 
- 由于值是唯一的，严格比较就足够了。 

## 方法

 ### 蛮力方法

 强力解决方案将检查数组中的每个数字，并确定随机过程是否会因该目标而失败。 

对于一个目标`nums[i]`，我们需要递归地模拟所有可能的主元选择。 在每一步中，枢轴可以是任何剩余元素。 如果存在甚至一个错误地删除目标的主元选择序列，则该数字不可搜索。 

这种方法是正确的，因为它直接遵循问题定义。 然而，这在计算上是不可行的。 主元选择序列的数量随着数组大小呈指数增长。 

即使是检查所有子数组或重复模拟消除的简化蛮力方法对于`n = 10^5`。 

### 关键见解

 一个数字`nums[i]`保证能找到当且仅当：

 - 它左边的每个元素都比它小。 
- 它右边的每个元素都比它大。 

为什么这是真的？ 

假设左侧存在一个更大的数字。 如果在搜索时选择较大的数字作为主元`nums[i]`，算法将删除枢轴及其右侧的所有内容，其中包括目标。 目标就永远丢失了。 

同样，假设右侧存在一个较小的数字。 如果那个较小的数字成为主元，算法将删除主元及其左侧的所有内容，再次消除目标。 

所以：

-`nums[i]`必须大于它之前的所有元素。 
-`nums[i]`必须小于其后的所有元素。 

这将问题转化为前缀/后缀比较问题。 

我们可以预先计算：

 -`prefix_max[i]`= 索引的最大值`0`到`i-1`-`suffix_min[i]`= 索引的最小值`i+1`到`n-1`然后`nums[i]`如果满足以下条件，则可搜索：```
prefix_max[i] < nums[i] < suffix_min[i]
```我们可以在线性时间内计算它。

 ## 算法演练

 1. 创建数组`left_max`在哪里`left_max[i]`存储索引之前出现的最大值`i`。 

这有助于确定左侧是否存在更大的值`nums[i]`。 
2. 从左到右遍历数组。 

维持运行最大值称为`current_max`。 

对于每个索引：

 - 商店`current_max`进入`left_max[i]`- 更新`current_max = max(current_max, nums[i])`3. 创建数组`right_min`在哪里`right_min[i]`存储索引后出现的最小值`i`。 

这有助于确定右侧是否存在任何较小的值。 
4. 从右向左遍历数组。 

维持运行最小值称为`current_min`。 

对于每个索引：

 - 商店`current_min`进入`right_min[i]`- 更新`current_min = min(current_min, nums[i])`5. 最后一次遍历数组。 

对于每个索引`i`，检查是否：```
left_max[i] < nums[i] < right_min[i]
```如果为真，则增加答案。 
6. 返回最终计数。 

### 为什么它有效

 只有当不正确的支点无法消除目标时，目标才能在所有可能的支点选择中幸存下来。 

当选择作为枢轴时，左侧较大的值可以删除目标。 右侧较小的值也可以删除目标。 因此，当所有左值都较小并且所有右值都较大时，目标正是安全的。 

前缀最大值捕获是否存在较大的左侧元素，后缀最小值捕获是否存在较小的右侧元素。 它们共同完美地描述了可搜索数字的特征。 

## Python 解决方案```python
from typing import List

class Solution:
    def binarySearchableNumbers(self, nums: List[int]) -> int:
        n = len(nums)

        left_max = [float("-inf")] * n
        current_max = float("-inf")

        for i in range(n):
            left_max[i] = current_max
            current_max = max(current_max, nums[i])

        right_min = [float("inf")] * n
        current_min = float("inf")

        for i in range(n - 1, -1, -1):
            right_min[i] = current_min
            current_min = min(current_min, nums[i])

        searchable_count = 0

        for i in range(n):
            if left_max[i] < nums[i] < right_min[i]:
                searchable_count += 1

        return searchable_count
```实现直接遵循算法。 

第一个循环构建`left_max`大批。 对于每个位置，我们存储当前索引之前看到的最大值。 最初，左侧没有元素，因此使用负无穷大。 

第二个循环构建`right_min`大批。 对于每个位置，我们存储当前索引之后看到的最小值。 正无穷大用于最后一个位置，因为其右侧不存在任何元素。 

最后一个循环检查当前值是否大于其左侧的所有值并且小于其右侧的所有值。 如果两个条件都成立，则保证该号码是可搜索的。 

## 解决方案```go
func binarySearchableNumbers(nums []int) int {
	n := len(nums)

	leftMax := make([]int, n)
	currentMax := -(1 << 60)

	for i := 0; i < n; i++ {
		leftMax[i] = currentMax

		if nums[i] > currentMax {
			currentMax = nums[i]
		}
	}

	rightMin := make([]int, n)
	currentMin := 1 << 60

	for i := n - 1; i >= 0; i-- {
		rightMin[i] = currentMin

		if nums[i] < currentMin {
			currentMin = nums[i]
		}
	}

	answer := 0

	for i := 0; i < n; i++ {
		if leftMax[i] < nums[i] && nums[i] < rightMin[i] {
			answer++
		}
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 

由于 Go 不提供内置的整数无穷大值，因此使用较大的标记值。 约束保证值保持在`[-10^5, 10^5]`，所以使用`±(1 << 60)`是完全安全的。 

切片用于前缀和后缀数组，算法仍然以线性时间运行。

 ## 边缘情况

 单元素数组是一种重要的边缘情况，因为算法必须正确地将唯一元素视为可搜索。 没有左或右元素可以消除它。 该实现自然地处理了这个问题，因为比较变成了`-inf < value < inf`。 

完全颠倒的数组很容易暴露不正确的逻辑。 在这样的阵列中，几乎每个主元选择都可能错误地消除目标。 该实现正确地识别出没有元素同时满足前缀和后缀条件。 

包含负数的数组是另一个常见的错误来源，尤其是在使用标记值时。 该实现通过在 Python 中使用正无穷大和负无穷大以及在 Go 中使用极大的哨兵值来避免问题。 

当一个元素大于所有先前的元素但在其右侧某处仍然具有较小的值时，会发生另一种微妙的边缘情况。 仅检查前缀条件的幼稚实现会错误地将其视为可搜索。 后缀最小数组可以防止这种错误。
