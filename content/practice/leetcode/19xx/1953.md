[LeetCode 1953 题](https://leetcode.com/problems/maximum-number-of-weeks-for-which-you-can-work/)

 **难度：** 🟡 中等
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`milestones`，其中每个值代表有多少个里程碑属于特定项目。 每周，我们必须准确完成一个项目的一个里程碑。 然而，有一个重要的限制：我们不能连续两周从事同一个项目。 

我们的目标是确定在遵守此规则的情况下我们可以继续工作的最长周数。 

输入数组代表独立的项目。 例如，如果：```
milestones = [1, 2, 3]
```那么：

 - 项目 0 有 1 个里程碑
 - 项目 1 有 2 个里程碑
 - 项目 2 有 3 个里程碑

 输出是我们可以安排工作的最大周数，而无需连续几周选择同一项目。 

约束条件很重要：

 -`n`可以大到`10^5`- 每个里程碑计数可以大到`10^9`这立即告诉我们，任何涉及使用优先级队列或回溯进行每周调度的模拟在最坏的情况下都会太慢。 里程碑的总数可能非常巨大，可能高达`10^14`，所以我们无法明确地构建时间表。 

关键的挑战是了解日程安排限制何时会阻止我们完成所有里程碑。 

最重要的边缘情况是一个项目包含的里程碑远多于所有其他项目的总和。 例如：```
[10, 1, 1]
```尽管总共有 12 个里程碑，但我们无法全部完成，因为最终大型项目将被迫连续出现。 

另一个重要的边缘情况是里程碑足够平衡，我们可以无限期地交替项目。 那样的话，我们就能完成每一个里程碑。 

该问题保证：

 - 每个项目至少有一个里程碑
 - 数组非空
 - 所有值均为正整数

 这简化了实施，因为我们永远不需要处理空项目。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试逐周明确地模拟时间表。 

一种可能的实现是：

 1. 始终选择与之前选择的项目不同的剩余里程碑数最多的项目。 
2.减少其数量。 
3. 继续，直到没有有效的项目剩余。 

最大堆可以帮助有效地选择下一个项目。 

这种方法是正确的，因为它贪婪地尝试通过首先消耗大型项目同时避免连续重复来最大化未来的灵活性。 

然而，里程碑的总数可能非常大。 考虑：```
milestones[i] = 10^9
```总周数可能超过`10^14`。 因此每周进行模拟会太慢。 

即使使用堆，复杂性也会与里程碑总数成正比，这是不可行的。 

### 关键见解

 这个问题实际上是由一个简单的数学条件决定的。 

认为：

-`total`= 里程碑总数
 -`maxMilestone`= 最大项目规模
 -`rest`= 所有其他项目的总和

 唯一可能造成麻烦的项目是最大的项目。 

为了避免同一项目连续几周发生，最大项目的里程碑必须与其他项目的里程碑分开。 

如果最大的项目有：```
maxMilestone <= rest + 1
```然后其他项目提供足够的分隔符，我们就可以完成所有里程碑。 

例如：```
[3,2,1]
```最大的项目 = 3

 休息 = 3

 可能的安排：```
A B A C A B
```所有里程碑均已完成。 

但如果：```
maxMilestone > rest + 1
```最终，最大的项目用完了分离器。 

例如：```
[5,2,1]
```最大的项目 = 5

 休息 = 3

 我们可以安排：```
A B A B A C A
```此时，只有一个`A`仍然存在，但放置它会创建连续的`A`是。 
最长可行周数变为：```
2 * rest + 1
```因为每个非最大的里程碑都可以将两个里程碑与最大的项目分开。 

这一观察将整个问题简化为简单的算术。

 | --- | --- | --- | --- |
 | 蛮力 | O(总里程碑 log n) | O(n) | 使用堆模拟每周调度 |
 | 最佳| O(n) | O(1) | O(1) | 使用对最大项目的数学观察|

 ## 算法演练

 1. 计算所有项目的里程碑总数。 

这代表了如果每个里程碑都能完成的话理论上的最大周数。 
2. 找到里程碑数量最多的项目。 

这是唯一可能违反调度规则的项目。 
3. 计算所有剩余里程碑的总和。```
rest = total - maxMilestone
```这些里程碑充当最大项目的里程碑之间的分隔符。 
4. 检查最大的项目是否可以完全交错。 

如果：$maxMilestone \leq rest + 1$然后我们就可以成功地安排每个里程碑。 
5. 如果条件成立，则返回里程碑总数。 

由于存在足够的分隔符，因此每个里程碑都可以完成。 
6. 否则，最大的项目会占据主导地位。 

在这种情况下，可实现的最大调度长度为：$2 \cdot rest + 1$因为除了开始或结束时的一个额外的最大项目里程碑之外，每个剩余的里程碑都可以将最大项目与两个里程碑分开。 

### 为什么它有效

 正确性取决于交错属性。 

为了避免对同一项目进行连续选择，最大项目的里程碑必须用其他项目的里程碑分隔开。 如果分隔符的数量足够，所有里程碑都可以安全地安排。 

当分离器不足时，时间表不可避免地会以同一最大项目的两个连续里程碑结束。 最大有效排列尽可能长地交替，从而准确地产生：```
largest, other, largest, other, ...
```这产生`2 * rest + 1`总周数。 

因此，该公式始终计算最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def numberOfWeeks(self, milestones: List[int]) -> int:
        total_milestones = sum(milestones)
        max_milestone = max(milestones)

        remaining = total_milestones - max_milestone

        if max_milestone <= remaining + 1:
            return total_milestones

        return 2 * remaining + 1
```实施首先计算里程碑总数并确定最大的项目。 

接下来，它计算有多少个里程碑属于所有其他项目的总和。 这些里程碑是防止最大项目连续工作所需的分隔符。 

条件：```python
max_milestone <= remaining + 1
```检查是否可以进行完全交错。 

如果是，我们将返回里程碑总数，因为每个项目都可以完成。 

否则，我们应用数学极限：```python
2 * remaining + 1
```它代表最长的有效交替时间表。 

该实现非常紧凑，因为困难的调度行为已经被简化为简单的计数参数。 

## 解决方案```go
func numberOfWeeks(milestones []int) int64 {
    var total int64 = 0
    var maxMilestone int64 = 0

    for _, value := range milestones {
        current := int64(value)

        total += current

        if current > maxMilestone {
            maxMilestone = current
        }
    }

    remaining := total - maxMilestone

    if maxMilestone <= remaining+1 {
        return total
    }

    return 2*remaining + 1
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 特有的一个重要细节是使用`int64`。 里程碑的总数可能变得非常大，可能超出标准 32 位整数的范围。 使用`int64`防止溢出。 

算法本身保持不变：

 - 计算总里程碑
 - 找到最大的项目
 - 确定是否可以进行完全交错
 - 返回完整的总长度或限制的最大计划长度

 ## 边缘情况

 ### 单个项目

 如果只有一个项目，无论有多少个里程碑，我们都只能工作一周。 

例如：```
[10]
```完成一个里程碑后，下周将需要连续从事同一个项目，这是被禁止的。 

该公式自然地处理了这个问题：```
remaining = 0
answer = 2 * 0 + 1 = 1
```### 最大的项目完全适合

 考虑：```
[4,1,1,1]
```这里：```
maxMilestone = 4
remaining = 3
```条件变为：$4 \leq 3 + 1$这是完全正确的，这意味着存在完美的交错。 

有效的时间表是：```
A B A C A D A
```该实现正确返回所有 7 个里程碑。 

### 最大的项目太大

 考虑：```
[10,1,1]
```最大的项目在日程安排中占主导地位。 

即使使用所有较小的项目作为分隔符：```
A B A C A
```我们仍然无法放置剩余的`A`在不违反规则的情况下实现里程碑。 

实现正确地将结果限制为：$2 \cdot 2 + 1 = 5$而不是错误地返回总里程碑计数。
