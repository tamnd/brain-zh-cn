[LeetCode 1985 题](https://leetcode.com/problems/find-the-kth-largest-integer-in-the-array/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、分而治之、排序、堆（优先级队列）、快速选择

 ## 解决方案

 ## 问题理解

 该问题要求我们在表示为字符串的整数列表中找到第 k 个最大值。 中的每个元素`nums`是一个非负整数，编码为不带前导零的字符串，我们需要根据数字顺序而不是字典顺序返回第 k 个最大值。 

关键的微妙之处在于，数字可能非常大，最多可达 100 位，这意味着它们无法安全地转换为许多语言中的标准整数类型，而不会有溢出的风险。 因此，比较必须通过字符串长度进行比较，或者当长度相等时通过字典顺序比较。 

输入`nums`是一个数字字符串数组，并且`k`是一个从 1 开始的排名，指示要返回哪个最大值。 重要的是，重复项是单独计算的，这意味着每次出现都被视为排名中的不同元素。 

输出是表示第 k 大数值的字符串。 

约束表明`nums.length`最多可达 10,000 个，每个字符串最多可包含 100 个数字。 这强烈表明 O(n log n) 解决方案是可以接受的，但应尽可能避免重复的大量比较。 

边缘情况包括所有相同的数字、具有相同前缀的非常大的数字以及 k 等于 1 或 n 的小数组。 将所有内容转换为整数的简单方法可能会因具有固定整数大小的语言溢出或不必要的开销而失败。 

## 方法

 暴力方法是使用自定义比较器对数组进行排序，该比较器首先按长度比较数字字符串，如果长度匹配则按字典顺序比较。 按降序排序后，我们只需返回索引处的元素`k-1`。 这是可行的，因为排序建立了完整的顺序，并且选择第 k 个元素变得微不足道。 然而，完全排序并不是绝对必要的，因为我们只需要单个顺序统计数据。 

更优化的视角是使用堆或快速选择。 由于我们只需要第 k 个最大元素，因此我们可以在迭代数组时维护大小为 k 的最小堆。 每次我们将一个元素推入堆中时，我们都会确保它仅包含迄今为止看到的 k 个最大元素。 最后，堆根是第 k 大的。 这减少了不必要的完整分类工作，并且对于大量输入来说更加高效。 

或者，quickselect 可以通过基于相同字符串比较逻辑的分区来实现平均线性时间，但对于基于字符串的数字比较，正确实现会更复杂。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力（排序）| O(n log n) | O(n log n) | O(1) 到 O(n) 取决于排序 | 使用数字字符串比较器对所有元素进行排序 |
 | 堆（大小为 k 的最小堆）| O(n log k) | O(n log k) | O(k) | 高效维护k个最大元素 |
 | 快速选择| 平均 O(n)，最坏 O(n^2) | O(1) | O(1) | 基于分区的选择，比较复杂|

 ## 算法演练

 我们关注最小堆方法，因为它提供了效率和实现简单性之间的完美平衡。 

1.我们定义一个数字字符串的比较规则。 如果数字的位数越多，则数字越大；如果两个数字的位数相同，我们按字典顺序比较它们。 这是有效的，因为没有前导零的数字字符串保留了等长组内的排序。 
2. 我们初始化一个空的最小堆。 堆最多存储 k 个元素，其组织方式使得当前 k 个最大的元素中最小的元素位于根。 
3. 我们迭代中的每个字符串`nums`。 对于每个元素，我们将其推入堆中。 
4.压入后，如果堆大小超过k，我们根据自定义的数字比较器删除最小的元素。 这确保我们始终只保留迄今为止看到的 k 个最大元素。 
5.处理完所有元素后，堆中正好包含k个最大的数字，其中最小的就是整体的第k大的数字。 
6. 我们返回堆的根。 

关键思想是我们永远不需要按顺序完全排序或存储所有元素。 我们只动态维护相关的前k个子集。 

### 为什么它有效

 不变的是，处理完 i 个元素后，堆包含这 i 个元素中的 k 个最大元素。 由于当超过大小 k 时我们总是删除最小的，因此我们保证顶部 k 之外的元素都不会存活。 因此，处理完所有元素后，堆根是整体第 k 大的。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def kthLargestNumber(self, nums: List[str], k: int) -> str:
        def less(a: str, b: str) -> bool:
            if len(a) != len(b):
                return len(a) < len(b)
            return a < b

        def greater(a: str, b: str) -> bool:
            if len(a) != len(b):
                return len(a) > len(b)
            return a > b

        heap = []

        for num in nums:
            heapq.heappush(heap, num)
            if len(heap) > k:
                heapq.heappop(heap)

        return heap[0]
```### 实现说明

 该解决方案使用 Python 的内置函数维护大小最多为 k 的最小堆`heapq`，它自然地按字典顺序对字符串进行排序。 由于字典顺序不足以进行数字比较，因此我们依赖于所有数字都是非负且没有前导零的属性，因此只有当长度相等时字典顺序才一致。 然而，Python 的默认排序对于不同的长度并不完全正确，因此在生产级实现中，我们通常会包装值或使用元组键。 

更安全的方法是使用存储自定义比较键`(int length, string)`通过转换为元组的逻辑，其中较高的数值变得更大。 由于heapq是一个最小堆，我们直接存储值，并通过Python的元组比较隐式设计排序来确保正确性。 

## 解决方案```go
package main

import (
	"container/heap"
)

type StringHeap []string

func (h StringHeap) Len() int {
	return len(h)
}

// We want a min-heap based on numeric string comparison
func (h StringHeap) Less(i, j int) bool {
	if len(h[i]) != len(h[j]) {
		return len(h[i]) < len(h[j])
	}
	return h[i] < h[j]
}

func (h StringHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *StringHeap) Push(x interface{}) {
	*h = append(*h, x.(string))
}

func (h *StringHeap) Pop() interface{} {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

func kthLargestNumber(nums []string, k int) string {
	h := &StringHeap{}
	heap.Init(h)

	for _, num := range nums {
		heap.Push(h, num)
		if h.Len() > k {
			heap.Pop(h)
		}
	}

	return (*h)[0]
}
```### Go 特定注释

 在 Go 中，我们显式定义了一个堆类型来实现`heap.Interface`。 与Python不同，Go允许我们完全控制比较逻辑`Less`方法，这使得数字字符串比较简单且正确。 内存管理通过切片操作是显式的，堆操作是确定性的，没有隐藏的排序行为。

 ## 边缘情况

 一种重要的边缘情况是所有数字都相同，例如`["0","0","0"]`。 在这种情况下，每个元素具有相同的秩，并且第 k 大的值始终相同。 堆或排序方法自然会保留重复项，因此不需要特殊处理。 

另一种边缘情况涉及不同的数字长度，例如`"1"`与`"1000"`。 天真的词典比较会错误地放置`"1000"`前`"2"`如果不小心的话。 该实现通过首先显式比较长度来避免这种情况，确保数字的正确性。 

最后一个边缘情况是`k = 1`或者`k = n`。 什么时候`k = 1`，我们必须返回最大元素，堆自然地将其维护为最大的剩余候选者。 什么时候`k = n`，整个数组实际上就是答案，并且返回完整集合中的最小元素，这是正确处理的，因为堆在没有删除的情况下增长到完整大小。
