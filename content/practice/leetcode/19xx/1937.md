[LeetCode 1937 题](https://leetcode.com/problems/maximum-number-of-points-with-cost/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`m x n`矩阵称为`points`。 我们必须从每一行中恰好选择一个单元格。 所选单元格的值将添加到我们的分数中。 

然而，连续行之间存在移动惩罚。 如果我们选择列`c1`在行中`r`和列`c2`在行中`r + 1`，我们输了`abs(c1 - c2)`点。 这意味着在行之间水平移动得更远会变得更加昂贵。 

目标是在添加所有选定的单元格值并减去所有移动惩罚后最大化最终得分。 

更正式地说，如果我们选择列：```
c0, c1, c2, ..., c(m-1)
```那么分数就变成：```
points[0][c0]
+ points[1][c1]
+ ...
+ points[m-1][c(m-1)]
- abs(c0 - c1)
- abs(c1 - c2)
- ...
- abs(c(m-2) - c(m-1))
```我们需要计算最大可能值。 

约束条件极其重要：

 -`m * n <= 100000`- 每个维度可以单独大到`100000`这意味着我们无法承担像这样复杂的算法`O(m * n^2)`在最坏的情况下。 即使是一个矩阵`1 x 100000`或者`100000 x 1`是可能的。 

该问题保证：

 - 每行都有相同数量的列。 
- 值是非负的。 
- 至少存在一行和一列。 

一些边缘情况立即很重要：

 - 只有一行的矩阵，没有移动惩罚。 
- 具有一列的矩阵，其中移动成本始终为零。 
- 大型矩阵，所有列对之间的简单转换变得太慢。 
- 转移到高价值的远程纵队仍然值得支付罚款的情况。 

这个问题本质上是一个动态规划优化问题。 

## 方法

 ### 暴力动态规划

 第一个自然的想法是动态规划。 

定义：```
dp[r][c]
```作为我们在列结束时可获得的最高分数`c`在行中`r`。 

过渡变为：```
dp[r][c] =
points[r][c] +
max over all previous columns k:
(
    dp[r-1][k] - abs(k - c)
)
```这种递归是正确的，因为每个有效的解决方案都达到`(r, c)`必须来自某个列`k`在前一行。 

不幸的是，直接计算这种转变是昂贵的。 

对于每一行：

 - 我们迭代所有当前列`c`- 对于每个`c`，我们扫描所有之前的列`k`这给出：```
O(m * n^2)
```和`n`最多`100000`，这太慢了。 

### 优化的关键见解

 昂贵的部分是：```
max(dp[k] - abs(k - c))
```绝对值产生两种情况：```
k <= c:
dp[k] - (c - k)
= (dp[k] + k) - c
```和```
k >= c:
dp[k] - (k - c)
= (dp[k] - k) + c
```这是批判性的观察。 

对于每一列`c`，我们需要：```
max(
    max(dp[k] + k) - c,
    max(dp[k] - k) + c
)
```我们可以用两次线性扫描来预处理它们，而不是重复地重新计算这些最大值：

 - 从左到右的扫描手柄`dp[k] + k`- 从右到左的扫描手柄`dp[k] - k`这减少了每行转换`O(n^2)`到`O(n)`。 

总体复杂度变为：```
O(m * n)
```符合约束条件。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 暴力DP | O(m * n²) | O(n) 或 O(m * n) | 检查每个当前列的每个先前列 |
 | 两次扫描的最佳 DP | O(m * n) | O(n) | 使用左右最大传播 |

 ## 算法演练

 ### 步骤 1：初始化第一行的 DP

 第一行没有前一行，因此没有移动惩罚。 

所以：```
dp[c] = points[0][c]
```这代表行中每列结束的最佳分数`0`。 

### 步骤 2：逐行处理

 对于每个后续行，我们计算一个新的 DP 数组。 

我们需要：```
new_dp[c] =
points[row][c] +
max(previous_dp[k] - abs(k - c))
```直接计算这个成本太高了。 

### 步骤 3：从左到右扫描

 我们创建一个名为的数组`left`。 

从左到右扫描时，我们保持：```
max(previous_dp[k] + k)
```对于所有职位`k <= c`。 

在位置`c`：```
left[c] =
max(left[c-1], previous_dp[c] + c)
```这让我们可以计算：```
max(previous_dp[k] - (c - k))
```有效地为：```
left[c] - c
```### 步骤 4：从右到左扫描

 我们创建另一个数组，名为`right`。 

从右向左扫描时，我们保持：```
max(previous_dp[k] - k)
```对于所有职位`k >= c`。 

在位置`c`：```
right[c] =
max(right[c+1], previous_dp[c] - c)
```这让我们可以计算：```
max(previous_dp[k] - (k - c))
```有效地为：```
right[c] + c
```### 步骤 5：计算最佳转换

 对于每一列`c`：```
best_previous =
max(
    left[c] - c,
    right[c] + c
)
```然后：```
new_dp[c] =
points[row][c] + best_previous
```### 第 6 步：移至下一行

 处理行后：```
dp = new_dp
```重复此操作，直到处理完所有行。 

### 步骤 7：返回最大值

 最终的答案是：```
max(dp)
```因为最佳路径可能以最后一行的任何列结束。 

### 为什么它有效

 该算法之所以有效，是因为每个转移成本仅取决于列距离。 通过将绝对值分成两个方向的情况，我们将二次转换转换为两个线性扫描。 

左扫描正确捕获左侧列的所有转换，而右扫描捕获右侧列的转换。 取两者中的最大值给出每列的精确最佳过渡值。 

由于每个行转换都是最优计算的，因此 DP 不变量成立：```
dp[c] always stores the maximum achievable score ending at column c for the current row.
```因此，处理完所有行后，最终DP数组中的最大值就是全局最优值。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxPoints(self, points: List[List[int]]) -> int:
        rows = len(points)
        cols = len(points[0])

        dp = [value for value in points[0]]

        for row in range(1, rows):
            left = [0] * cols
            right = [0] * cols

            left[0] = dp[0]
            for col in range(1, cols):
                left[col] = max(left[col - 1] - 1, dp[col])

            right[cols - 1] = dp[cols - 1]
            for col in range(cols - 2, -1, -1):
                right[col] = max(right[col + 1] - 1, dp[col])

            new_dp = [0] * cols

            for col in range(cols):
                best_previous = max(left[col], right[col])
                new_dp[col] = points[row][col] + best_previous

            dp = new_dp

        return max(dp)
```该实现一次仅存储一行 DP，从而保持内存使用效率。 

变量`dp`表示前一行中每列可达到的最佳分数。 

这`left`扫描从左到右传播值。 向正确的成本迈出一步`1`，因此我们将传播值递减`1`每一步：```python
left[col] = max(left[col - 1] - 1, dp[col])
```这简洁地表示：```python
max(dp[k] - (col - k))
```为所有人`k <= col`。 

这`right`扫描从右到左执行对称操作：```python
right[col] = max(right[col + 1] - 1, dp[col])
```这代表：```python
max(dp[k] - (k - col))
```为所有人`k >= col`。 

最后，对于每一列，我们选择两个方向转换中较好的一个并添加当前单元格值。 

## 解决方案```go
func maxPoints(points [][]int) int64 {
    rows := len(points)
    cols := len(points[0])

    dp := make([]int64, cols)

    for c := 0; c < cols; c++ {
        dp[c] = int64(points[0][c])
    }

    for r := 1; r < rows; r++ {
        left := make([]int64, cols)
        right := make([]int64, cols)

        left[0] = dp[0]
        for c := 1; c < cols; c++ {
            candidate := left[c-1] - 1
            if dp[c] > candidate {
                left[c] = dp[c]
            } else {
                left[c] = candidate
            }
        }

        right[cols-1] = dp[cols-1]
        for c := cols - 2; c >= 0; c-- {
            candidate := right[c+1] - 1
            if dp[c] > candidate {
                right[c] = dp[c]
            } else {
                right[c] = candidate
            }
        }

        newDP := make([]int64, cols)

        for c := 0; c < cols; c++ {
            bestPrevious := left[c]
            if right[c] > bestPrevious {
                bestPrevious = right[c]
            }

            newDP[c] = int64(points[r][c]) + bestPrevious
        }

        dp = newDP
    }

    answer := dp[0]
    for _, value := range dp {
        if value > answer {
            answer = value
        }
    }

    return answer
}
```Go 解决方案使用`int64`因为当许多大值跨行累积时，总分可能会超出 32 位整数的范围。 

使用切片而不是固定大小的数组，因为矩阵维度仅在运行时已知。 

与 Python 整数不同，Go 整数不会自动扩展，因此显式`int64`转换是必要的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m * n) | 每行均通过两次线性扫描进行处理 |
 | 空间| O(n) | 仅存储一行的 DP 数组 |

 该算法以恒定的次数处理每个单元格。 对于每一行，我们执行：

 - 左扫一扫
 - 右扫一扫
 - 一张 DP 施工通行证

 每次传递与列数呈线性关系。 

不存在嵌套的列到列转换循环，这避免了二次瓶颈。

 ## 边缘情况

 ### 单排

 如果矩阵仅包含一行，则不会有移动惩罚，因为行之间不会发生转换。 

有缺陷的实现可能仍会尝试执行转换逻辑或意外地减少成本。 此实现可以自然地处理这种情况，因为 DP 数组直接从第一行初始化，并且转换循环从不执行。 

### 单列

 当只有一列时，每个选择都必须保留在列中`0`。 

移动惩罚始终为：```
abs(0 - 0) = 0
```编写得不好的解决方案可能仍会尝试不必要的扫描或错误地访问相邻索引。 此实现可以正常工作，因为即使在以下情况下，两种扫描也可以安全运行`cols == 1`。 

### 大幅移动处罚

 有时，最好的解决方案涉及跳过许多列，因为目标值非常大。 

例如：```
[
    [1, 100],
    [100, 1]
]
```最优路径可能会故意付出移动成本来获得更大的奖励。 

仅最小化移动的贪婪解决方案在这里会失败。 DP 公式正确评估所有可能的转换并选择全局最优路径。 

### 非常大的输入

 自从`m * n`可以达到`100000`，二次解变得不可行。 

简单的转换循环在大型宽矩阵上会超时。 优化的两次扫描技术保证每行的线性工作，确保算法在问题限制内有效扩展。
