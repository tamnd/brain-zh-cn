 # LeetCode 1915，精彩子串的数量

 ## 问题理解

 该问题要求我们计算给定字符串中有多少个非空子字符串被认为是“精彩的”。 

如果子字符串中最多有一个字符出现奇数次，则该子字符串非常好。 该字符串仅包含以下字符`'a'`到`'j'`，这意味着只涉及 10 个可能的字母。 

为了更清楚地了解情况：

 - 每个字符出现偶数次的子字符串非常棒。 
- 恰好一个字符出现奇数次的子字符串也很棒。 
- 两个或多个字符出现奇数次的子字符串并不好。 

例如：

-`"abba"`很精彩，因为所有角色都出现了偶数次。 
-`"aba"`太棒了，因为`'b'`出现一次，这很奇怪，而`'a'`出现两次。 
-`"ab"`这并不美妙，因为两者`'a'`和`'b'`出现一次，因此两个字符的频率为奇数。 

输入是单个字符串`word`长度可达`10^5`。 这个约束非常重要，因为它立即排除了昂贵的子串枚举方法。 一个长度的字符串`10^5`大约有`5 * 10^9`子字符串太多，无法直接处理。 

仅 10 个不同字符的限制是实现高效解决方案的关键观察结果。 由于每个字符只能有奇数或偶数频率，因此我们可以使用 10 位位掩码来表示所有字符的奇偶校验状态。 

一些重要的边缘情况包括：

 - 单字符字符串，每一个单字符子串都很精彩。 
- 所有字符都相同的字符串，几乎每个子字符串都变得很棒，因为只有一个字符可以是奇数。 
- 具有许多交替字符的字符串，这可能经常创建多个奇数计数。 
- 非常长的字符串，效率变得至关重要。 
- 所有计数均为偶数的子字符串，也必须正确计数。 

## 方法

 ### 蛮力方法

 最直接的方法是生成每个可能的子串并检查它是否精彩。 

对于每个子字符串，我们可以统计所有字符的频率，并确定有多少个字符出现了奇数次。 如果奇数计数最多为 1，我们就增加答案。 

这种方法是正确的，因为它直接遵循问题定义。 每个子字符串都被检查一次，并且每个子字符串都被准确验证。 

然而，对于限制而言，性能太慢了。 有`O(n^2)`子串，检查每个子串需要额外的工作来计算频率。 即使采用前缀频率优化，总复杂度对于`n = 10^5`。 

### 最佳方法

 关键的见解是我们只关心每个字符计数是奇数还是偶数，而不是确切的计数本身。 

奇偶校验可以使用位掩码来表示：

 - 位`0`代表性格`'a'`- 少量`1`代表性格`'b'`- ...
- 少量`9`代表性格`'j'`如果有一点是：

 -`0`，字符数为偶数
 -`1`，字符数为奇数

 当我们从左到右扫描字符串时，我们维护一个前缀奇偶校验掩码。 

认为：

-`prefixMask[i]`表示奇偶校验状态直至索引`i`-`prefixMask[j]`表示奇偶校验状态直至索引`j`那么它们之间的子串具有奇偶性：```
prefixMask[i] XOR prefixMask[j]
```如果此 XOR 结果包含以下内容，则子字符串很棒：

 - 置零位，意味着所有计数都是偶数
 - 恰好一个设置位，意味着恰好存在一个奇数计数

 因此，对于每个当前掩码，我们需要计算：

 - 之前的相同面具
 - 之前的掩码仅相差一位

 这将问题转换为使用哈希图或频率数组的有效前缀状态计数问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × 10) | O(10) | 枚举所有子字符串并检查奇数计数 |
 | 最佳| O(n × 10) | O(2^⁰) | 使用前缀奇偶校验位掩码和频率计数 |

 ## 算法演练

 1. 初始化一个频率图来计算每个奇偶校验掩码出现的次数。 

最初，面膜`0`出现过一次，因为在处理任何字符之前，所有计数都是偶数。 
2. 维护一个名为`current_mask`。 

这个10位整数存储当前前缀的奇偶校验状态。 
3. 一次一个字符地遍历字符串。 

对于每个字符：

 - 确定哪个位对应于该字符。 
- 使用 XOR 翻转该位。 

例如：```
current_mask ^= (1 << char_index)
```如果该位是`0`，就变成`1`。 

如果是的话`1`，就变成`0`。 
4. 计算所有字符数均为偶数的子字符串。 

如果前面的前缀具有完全相同的掩码，则它们之间的子字符串具有奇偶校验`0`。 

添加：```
frequency[current_mask]
```到答案。 
5. 计算恰好有一个字符具有奇数频率的子字符串。 

我们尝试分别翻转 10 位中的每一位：```
candidate_mask = current_mask ^ (1 << bit)
```如果该候选掩码之前出现过，则这些前缀之间的子字符串正好相差一个奇数字符。 

将所有此类频率添加到答案中。 
6. 统计到当前位置结束的有效子串后，将当前掩码记录在频率图中。 
7. 继续，直到处理完整个字符串。 
8. 返回累计答案。 

### 为什么它有效

 该算法依赖于两个前缀奇偶校验掩码之间的异或给出它们之间的子字符串的奇偶校验状态的属性。 

如果子串的奇偶校验掩码最多包含一组位，则该子串是很好的。 因此：

 - 相同的掩码产生零奇数
 - 相差一位的掩码恰好产生一个奇数计数

 通过有效地计算先前看到的掩码，我们可以确定在恒定时间内在每个位置结束的有效子串的数量。 

## Python 解决方案```python
class Solution:
    def wonderfulSubstrings(self, word: str) -> int:
        mask_frequency = {0: 1}
        
        current_mask = 0
        wonderful_count = 0
        
        for char in word:
            bit_index = ord(char) - ord('a')
            
            current_mask ^= (1 << bit_index)
            
            # Case 1: all character counts are even
            wonderful_count += mask_frequency.get(current_mask, 0)
            
            # Case 2: exactly one character count is odd
            for bit in range(10):
                candidate_mask = current_mask ^ (1 << bit)
                wonderful_count += mask_frequency.get(candidate_mask, 0)
            
            mask_frequency[current_mask] = (
                mask_frequency.get(current_mask, 0) + 1
            )
        
        return wonderful_count
```该实现紧密遵循前面描述的算法。 

字典`mask_frequency`存储每个前缀奇偶校验掩码出现的次数。 条目`{0: 1}`很重要，因为它表示处理任何字符之前的空前缀。 

变量`current_mask`跟踪直到当前位置的字符频率奇偶性。 每个字符使用 XOR 翻转其相应位。 

更新掩码后，代码首先对所有字符计数均为偶数的子字符串进行计数。 当当前掩码与之前看到的掩码匹配时，就会发生这种情况。 

接下来，代码检查所有仅相差一位的掩码。 这些对应于恰好有一个字符具有奇数频率的子串。 

最后，当前掩码被添加到频率图中，以便将来的子串可以使用它。 

因为只有 10 位，所以内循环总是恰好运行 10 次，使得算法非常高效。 

## 解决方案```go
func wonderfulSubstrings(word string) int64 {
	maskFrequency := make([]int64, 1<<10)

	maskFrequency[0] = 1

	currentMask := 0
	var wonderfulCount int64 = 0

	for _, char := range word {
		bitIndex := int(char - 'a')

		currentMask ^= (1 << bitIndex)

		// Case 1: all counts are even
		wonderfulCount += maskFrequency[currentMask]

		// Case 2: exactly one odd count
		for bit := 0; bit < 10; bit++ {
			candidateMask := currentMask ^ (1 << bit)
			wonderfulCount += maskFrequency[candidateMask]
		}

		maskFrequency[currentMask]++
	}

	return wonderfulCount
}
```Go 实现使用固定大小的切片而不是哈希图，因为只有`2^10 = 1024`可能的面具。 这既更快又更高效。 

答案存储为`int64`因为子串的数量可能超出标准 32 位整数的范围。 

除了这些特定于语言的细节之外，逻辑与 Python 实现相同。

 ## 边缘情况

 一种重要的边缘情况是单字符字符串。 每个单个字符子串自然都是精彩的，因为只有一个字符出现一次。 有缺陷的实现可能会忘记正确初始化空前缀掩码频率，从而导致丢失这些子字符串。 初始化`frequency[0] = 1`确保此类案件得到妥善处理。 

另一个重要的情况是所有字符都相同，例如`"aaaaa"`。 在这种情况下，每个子串都很好，因为永远不会有超过一个具有奇数频率的字符。 奇偶校验掩码在两种状态之间重复交替，并且该算法有效地计算所有匹配的前缀，而无需显式枚举子字符串。 

当多个字符同时具有奇数频率时，会出现更微妙的边缘情况。 例如，`"ab"`不应该算精彩，因为两个角色都出现过一次。 该算法可以正确处理这一问题，因为它只接受具有零个不同位或正好一个不同位的掩码。 任何产生两个或多个不同位的子串都会被自动排除。 

最后一个重要的边缘情况涉及接近约束极限的非常长的输入。 暴力方法会超时，因为子串的数量呈二次方增长。 位掩码前缀技术确保解决方案即使对于长度的字符串也保持高效`100000`。
