[LeetCode 1978 问题](https://leetcode.com/problems/employees-whose-manager-left-the-company/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题是要求我们在公司中找到满足两个特定条件的员工。 首先，他们的工资必须严格低于 30,000 美元。 其次，他们的经理已离开公司，这意味着该经理在公司中没有对应的行`Employees`表即使`manager_id`员工记录中的字段仍然引用该经理。 输入是一个名为的 SQL 表`Employees`其中包含以下列`employee_id`,`name`,`manager_id`， 和`salary`。 有些员工可能没有经理，在这种情况下`manager_id`为空。 预期输出是一个仅包含`employee_id`满足这两个条件的员工数量，按升序排列。 

要点包括认识到“经理离开公司”并不意味着`manager_id`为空； 这意味着`manager_id`参考文献`employee_id`表中不再存在。 该表可能包含多个没有经理的员工、经理仍在公司的员工以及经理已离开公司的员工。 边缘情况涉及 null 的员工`manager_id`、收入恰好为 30,000 美元的员工，以及经理 ID 指向不存在的员工的员工。 该问题保证了`employee_id`是唯一的，并且每个员工的记录都包含有效的整数字段`employee_id`,`manager_id`， 和`salary`。 

## 方法

 蛮力方法包括检查每个收入低于 30,000 美元的员工，然后扫描整个员工`Employees`表看看他们是否`manager_id`存在。 如果经理不存在，则员工满足条件。 这可以正常工作，因为它明确验证经理是否已离开。 然而，它的效率很低，因为它需要对每个员工进行嵌套检查，随着表的增长，这会变得成本高昂。 

最佳方法利用 SQL`LEFT JOIN`之间的`Employees`表和它本身。 通过加入`employee.manager_id = manager.employee_id`，我们可以通过检查连接结果中的空值来识别哪些员工缺少经理。 这避免了多次扫描表并使用数据库索引高效执行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 检查每个员工与所有员工的关系，看看该经理是否存在 |
 | 最佳| O(n) | O(n) | 使用自连接直接识别一个查询中缺失的经理 |

 ## 算法演练

 1. 选择工资严格低于30,000美元的员工。 这会立即过滤掉任何不能满足薪资条件的员工。 
2. 执行`LEFT JOIN`于`Employees`表与自身匹配`employee.manager_id`到`manager.employee_id`。 此连接允许我们查看表中是否存在该经理。 
3. 在连接结果中，查找其中的行`manager.employee_id`为空。 这些代表其经理已离开公司的员工。 
4. 仅选择`employee_id`过滤结果中的列，因为这是所需的输出格式。 
5. 对最终结果进行排序`employee_id`按升序排列以满足问题的要求。 

为什么有效：自连接可确保每个员工的经理都根据表中的现有员工进行显式检查。 加入的经理列中的空值表示经理不再存在，从而正确识别经理已离开的员工。 薪资过滤器确保只考虑低于 30,000 美元的员工，因此这两个条件同时满足。 

## Python 解决方案```python
# This problem is SQL-based, but if we were to simulate it in Python
from typing import List, Dict

class Solution:
    def employeesWithManagerLeft(self, employees: List[Dict]) -> List[int]:
        # Build a set of existing employee_ids for quick lookup
        existing_ids = {emp['employee_id'] for emp in employees}
        
        result = []
        for emp in employees:
            if emp['salary'] < 30000 and emp['manager_id'] is not None:
                if emp['manager_id'] not in existing_ids:
                    result.append(emp['employee_id'])
        return sorted(result)
```此 Python 实现模拟 SQL 方法。 首先，它构造一组所有当前员工 ID，这允许 O(1) 查找。 然后，它遍历每个员工，检查工资是否低于 30,000 美元以及`manager_id`不在当前员工集中。 任何匹配的员工 ID 都会附加到结果列表中，最终在返回之前进行排序。 

## 解决方案```go
package main

import "sort"

type Employee struct {
    EmployeeID int
    Name       string
    ManagerID  *int
    Salary     int
}

func EmployeesWithManagerLeft(employees []Employee) []int {
    existingIDs := make(map[int]bool)
    for _, emp := range employees {
        existingIDs[emp.EmployeeID] = true
    }

    var result []int
    for _, emp := range employees {
        if emp.Salary < 30000 && emp.ManagerID != nil {
            if !existingIDs[*emp.ManagerID] {
                result = append(result, emp.EmployeeID)
            }
        }
    }

    sort.Ints(result)
    return result
}
```在 Go 中，我们使用指针处理可为空的管理器 ID。 地图`existingIDs`允许快速查找现有员工。 仅当员工满足这两个条件时，我们才会迭代员工切片并将 ID 附加到结果切片。 最后，我们对 ID 切片进行排序。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 构建集合/映射和迭代员工都需要线性时间 |
 | 空间| O(n) | 我们将所有现有员工 ID 存储在集合/映射中，以便快速查找 |

 线性时间复杂度的产生是因为每个员工只被检查一次，并且在集合或映射中的查找需要恒定的时间。 空间复杂度是线性的，因为集合/映射存储了所有员工 ID。
