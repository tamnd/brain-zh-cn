[LeetCode 1987 题](https://leetcode.com/problems/number-of-unique-good-subsequences/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算一个二进制字符串有多少个**不同的子序列**被认为是“好的”。 子序列是通过删除零个或多个字符而不改变剩余字符的相对顺序而形成的任何序列。 然而，并非每个子序列都适用于此问题。 

如果子序列不为空且不包含前导零，则该子序列被定义为“**好**”，但有一个例外：单字符子序列`"0"`是允许的。 

这意味着我们正在计算可以根据这些规则形成为子序列的唯一二进制字符串，其中字符串如`"01"`或者`"00"`无效，因为它们以零开头，除非整个字符串完全正确`"0"`。 

输入是长度可达的二进制字符串`100,000`，仅由`'0'`和`'1'`。 输出是唯一的好子序列的数量模`1e9 + 7`。 

关键的挑战是子序列的数量呈指数增长，但我们必须有效地仅计算唯一的有效子序列。 

重要的边缘情况包括全零的字符串、没有零的字符串以及零出现在 1 之后的字符串，因为零只有出现在前导之后才有效。`1`或形成单一`"0"`子序列。 

## 方法

 ### 蛮力方法

 一个简单的解决方案将使用递归或位掩码生成所有可能的子序列，将它们存储在一个集合中，并仅过滤那些有效的“好子序列”。 对于每个子序列，我们将检查它是否有前导零（除非它恰好是`"0"`），然后将其插入到哈希集中以确保唯一性。 

这种方法原则上是正确的，因为它显式枚举了所有子序列并直接应用定义。 然而，一个长度的字符串`n`有`2^n`子序列，这使得这种方法不可行`n = 100,000`。 

### 优化的关键见解

 核心观察是我们不需要显式构造子序列。 相反，我们可以使用动态编程来计算不同的子序列，同时仔细处理前导零限制。 

我们将问题分为两个概念部分：

 首先，我们计算所有以 ** 开头的不同子序列`'1'`**，因为无论内部零如何，它们始终有效。 

其次，我们单独考虑特殊子序列`"0"`，如果至少有一个则有效`'0'`存在于字符串中。 

困难在于如何有效地计算不同的子序列而不重复计算。 我们维护一个 DP 值，表示以 开头的不同有效子序列的数量`'1'`。 处理每个字符时，我们根据是否可以将字符附加到现有子序列或开始新子序列来更新此计数。

 | 最佳DP | O(n) | O(1) | O(1) | 跟踪子序列结束逻辑而不进行枚举 |

 ## 算法演练

 我们维护两个变量：

 一个变量`dp1`表示 ** 开头的不同良好子序列的数量`'1'`**。 

另一个变量`has_zero`追踪我们是否至少见过一个`'0'`，它恰好贡献了一个有效子序列`"0"`。 

我们逐个字符地迭代字符串并更新这些值。 

1. 初始化`dp1 = 0`和`has_zero = 0`。 还为大结果定义模量常数。 
2. 对于每个角色`c`在二进制字符串中，我们考虑它如何影响现有的子序列：

 如果`c == '1'`，每个现有的子序列都可以包含或排除这个`'1'`，将现有集合加倍。 另外，我们可以开始一个新的子序列`"1"`，所以我们再添加一个。 所以，`dp1 = 2 * dp1 + 1`。 
3.如果`c == '0'`，我们再次考虑每个现有的有效子序列可以包含或排除这个`'0'`， 所以`dp1 = 2 * dp1`。 我们不会创建以以下开头的新的有效子序列`'0'`因为只有`"0"`在该类别中是允许的。 
4.如果`c == '0'`，我们还设置`has_zero = 1`，因为子序列`"0"`变得可用。 
5. 我们取模`1e9 + 7`每次更新后以避免溢出。 
6.最后的结果是`dp1 + has_zero`。 

### 为什么它有效

 不变的是`dp1`始终表示以以下方式开头的不同子序列的数量`'1'`由处理后的前缀组成。 每次我们读取一个字符时，我们要么扩展所有现有的子序列，要么创建新的有效子序列，确保通过加倍逻辑保留唯一性。 这`has_zero`flag 单独说明了唯一有效的仅零子序列，它不能在内部表示`dp1`。 

## Python 解决方案```python
from typing import *

class Solution:
    def numberOfUniqueGoodSubsequences(self, binary: str) -> int:
        MOD = 10**9 + 7
        
        dp1 = 0
        has_zero = 0
        
        for c in binary:
            if c == '1':
                dp1 = (2 * dp1 + 1) % MOD
            else:
                dp1 = (2 * dp1) % MOD
                has_zero = 1
        
        return (dp1 + has_zero) % MOD
```### 实现说明

 Python 解决方案维护两个计数器。 这`dp1`变量跟踪以以下开头的所有有效子序列`'1'`，使用每个角色的加倍逻辑进行更新。 当遇到`'1'`，我们还考虑了由单个字符本身形成的新子序列。 

这`has_zero`标志确保如果至少有一个`'0'`出现在字符串中，我们包含单个有效子序列`"0"`。 最终的总和结合了两个独立的部分。 

## 解决方案```go
func numberOfUniqueGoodSubsequences(binary string) int {
    const MOD = 1000000007

    dp1 := 0
    hasZero := 0

    for i := 0; i < len(binary); i++ {
        c := binary[i]

        if c == '1' {
            dp1 = (2*dp1 + 1) % MOD
        } else {
            dp1 = (2 * dp1) % MOD
            hasZero = 1
        }
    }

    return (dp1 + hasZero) % MOD
}
```### Go 特定注释

 Go 实现几乎完全反映了 Python 逻辑。 我们使用`int`对于状态变量，因为值始终保持在模数之下。 与 Python 不同，Go 需要对字符串进行显式索引。 模运算的逻辑是相同的，除了应用之外，不需要对溢出进行特殊处理`% MOD`在每一步。

 ## 边缘情况

 一个重要的边缘情况是完全由以下内容组成的字符串`'0'`。 在这种情况下，没有以以下开头的子序列`'1'`存在，所以`dp1`保持为零。 唯一有效的输出是`"0"`，并且实现正确返回`1`通过`has_zero`旗帜。 

另一个边缘情况是完全由以下内容组成的字符串`'1'`。 这里，每个子序列都是有效的，并且不同的子序列对应于包含或排除的组合。 DP 递归自然地捕获了这种指数增长，同时删除了等效子序列的重复数据。 

第三种边缘情况是交替模式，例如`"010101"`，其中零出现在 1 之前和之后。 该算法正确地处理了这个问题，因为零仅使现有子序列加倍，但绝不会创建新的前导零无效状态，而`"0"`作为一个独特的实体单独跟踪。
