[LeetCode 1963 题](https://leetcode.com/problems/minimum-number-of-swaps-to-make-the-string-balanced/)

 **难度：** 🟡 中等
 **主题：** 两个指针、字符串、堆栈、贪婪

 ## 解决方案

 ## 问题理解

 该问题要求我们将给定的括号字符串转换为具有最少交换次数的**平衡字符串**。 输入字符串`s`包括`n`字符，其中`n`是偶数，并且正好有`n / 2`左括号`'['`和`n / 2`右括号`']'`。 如果每个左括号都有一个匹配的右括号，并且括号根据格式良好的序列规则正确嵌套，则字符串是平衡的。 

换句话说，在从字符串的开头到结尾的任何点上，遇到的左括号的数量**决不**少于遇到的右括号的数量。 如果违反了这个条件，我们需要执行交换来修复它。 输出是一个整数，表示实现此平衡所需的最小交换次数。 

约束表明`n`可以非常大，最多`10^6`，这意味着解决方案的复杂性比`O(n)`可能不可行。 该问题保证了左括号和右括号的数量相等，因此我们不需要处理计数不匹配的字符串，从而简化了实现。 

重要的边缘情况包括已经平衡的字符串、完全反转的字符串，例如`"]][["`，以及在开头或结尾仅需要一次交换的字符串。 

## 方法

 暴力方法会尝试找到每个不平衡的位置并将其替换为正确的支架。 例如，我们可以遍历字符串，每当出现右括号而左侧没有匹配的左括号时，我们向前扫描以找到要交换的左括号。 虽然这种方法最终会产生一个平衡的字符串，但它需要重复扫描和交换，导致 **O(n^2)** 时间复杂度，这对于`n = 10^6`。 

最佳解决方案的关键在于我们**不需要模拟每次交换**。 当我们从左到右迭代时，我们只需要跟踪字符串的平衡。 定义一个`balance`计数器增加 1`'['`并减少 1`']'`。 每当`balance`变为负数，这意味着此时我们的右括号比左括号多，这将需要交换来修复。 每次`balance`降至零以下，我们增加 a`swaps`计数器并将赤字重置为零以进行下一步。 最终答案可以直接从**遇到的最大赤字**得出，它对应于所需的最小掉期次数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 扫描错位的括号并交换； 正确但对于大输入来说太慢 |
 | 最佳| O(n) | O(1) | O(1) | 跟踪余额和最大赤字； 每项赤字都需要互换； 非常高效|

 ## 算法演练

 1.初始化两个变量：`balance = 0`跟踪左括号的净数量，以及`max_deficit = 0`跟踪遇到的最大负余额。 
2. 迭代每个字符`c`在字符串中`s`。 
3.如果`c`是`'['`, 增量`balance`1.
 4.如果`c`是`']'`, 递减`balance`1.
 5.更新后`balance`，如果为负数，则表明该位置的右括号多于左括号。 更新`max_deficit`到电流的绝对值`balance`如果大于当前`max_deficit`。 
6. 在迭代结束时，`max_deficit`表示需要与未来的左括号交换的不匹配的右括号的数量。 由于每次交换固定两个括号，因此**所需的最小交换次数**为`(max_deficit + 1) // 2`。 

**为什么起作用**：平衡计数器保持不变，即在任何有效点，左括号的数量减去右括号的数量应该是非负的。 每当余额低于零时，它就会识别出一个不匹配的结束括号。 因此，最大赤字代表最严重的不平衡，并直接对应于纠正字符串所需的最小掉期。 
该问题给了我们一个仅由左括号组成的字符串`'['`和右括号`']'`。 字符串的长度始终是偶数，并且保证左括号和右括号的数量相等。 

我们的目标是使用最少的交换次数使字符串保持平衡。 交换可以发生在任意两个索引之间，不一定是相邻索引之间。 这很重要，因为在一次操作中交换远距离字符使问题比相邻交换变体容易得多。 

平衡括号字符串遵循与有效括号表达式相同的规则。 每个左括号最终都必须与右括号相匹配，并且从左到右扫描时，右括号的数量决不能超过左括号的数量。 

例如：

-`"[]"`是平衡的
 -`"[[]]"`是平衡的
 -`"[][]"`是平衡的
 -`"][]["`不平衡，因为它以右括号开头

 输出应该是将字符串转换为任何有效的平衡排列所需的最小交换次数。 

约束条件尤其重要：

 - 长度可以大到`10^6`- 这立即排除了昂贵的模拟或重复的字符串重建
 - 我们需要一个具有线性时间复杂度的算法
 - 理想情况下，内存使用量应该是恒定的或非常小

 该问题还保证：

 - 字符串长度是偶数
 - 数量`'['`等于`']'`这种保证意味着平衡的安排始终是可能的。 

一些边缘情况很重要：

 - 字符串可能已经平衡
 - 字符串可以以许多连续的右括号开头
 - 字符串可能会在有效和无效状态之间交替
 - 极大的输入需要高效的一次性解决方案

 重复搜索交换位置或在大字符串上物理执行交换的简单实现可能会变得太慢。 

## 方法

 ### 蛮力方法

 暴力解决方案将直接模拟平衡过程。 

每当我们遇到无效状态，即右括号的数量超过左括号的数量时，我们就可以向前搜索下一个状态`'['`字符并将其交换到当前位置。 

这种方法之所以有效，是因为每个无效前缀最终都必须通过在字符串中较早引入左括号来修复。 

然而，实现效率低下，因为每次校正可能需要在字符串中向前扫描以定位下一个可用的`'['`。 在最坏的情况下，这种重复搜索会导致二次时间复杂度。 

例如，在如下字符串中：```
]]]]....[[[[
```每个修复操作可能会扫描几乎整个剩余的字符串。 

自从`n`可以达到`10^6`， 一个`O(n^2)`解决方案太慢了。 

### 最优贪婪观察

 关键的见解是我们实际上不需要执行交换。 

相反，我们只需要计算从左到右扫描时字符串无效的次数。 

我们维护一个余额计数器：

 -`'['`增加平衡
 -`']'`减少平衡

 如果余额变为负数，则意味着到目前为止我们的右括号比左括号多。 如果没有交换，则无法平衡此前缀。 

那一刻：

 - 需要进行一次交换
 - 交换后，余额实际上变为`1`为什么`1`？ 

因为交换左括号会将无效前缀更改为有效前缀，并剩余一个不匹配的左括号。 

这种贪婪的观察使我们能够在一次传递中计算答案，而无需物理交换字符。

 ## 算法演练

 ### 最优贪心算法

 1.初始化两个变量：

 -`balance = 0`-`swaps = 0`这`balance`变量表示当前存在多少个不匹配的左括号。 
2. 从左到右遍历字符串。 
3. 如果当前字符是`'['`, 增量`balance`。 

这意味着我们多了一个可用的开括号。 
4. 如果当前字符是`']'`, 递减`balance`。 

该右括号尝试匹配前一个左括号。 
5. 更新余额后，检查是否`balance < 0`。 

负余额意味着我们在当前前缀中遇到的右括号多于左括号。 该前缀无效，必须使用交换来修复。 
6. 什么时候`balance < 0`:

 1. 增量`swaps`2. 重置`balance = 1`这模拟了交换当前的`']'`有一些未来`'['`。 

交换后：

 - 当前位置变为`'['`- 我们有效地获得了一个无与伦比的开局
 7. 继续处理字符串的其余部分。 
8、遍历完成后，返回`swaps`。 

### 为什么它有效

 不变的是`balance`始终表示应用迄今为止所需的最小交换后不匹配的左括号的数量。 

每当平衡变为负数时，如果不在字符串中前面引入左括号，则当前前缀不可能平衡。 与未来的一次交换`'['`总是足以修复该无效前缀。 

因为我们只在绝对必要时才进行掉期，并且每个负余额都需要至少一次掉期，所以贪婪策略是最优的。 

## Python 解决方案```python
class Solution:
    def minSwaps(self, s: str) -> int:
        balance = 0
        max_deficit = 0
        
        for c in s:
            if c == '[':
                balance += 1
            else:  # c == ']'
                balance -= 1
            if balance < 0:
                max_deficit = max(max_deficit, -balance)
        
        return (max_deficit + 1) // 2
```在此实现中，我们迭代字符串，同时保持运行平衡。 每次余额变为负数时，我们都会记录最大赤字。 最后一步将最大赤字除以 2 并向上舍入，因为每次交换可以在一次操作中修复两个括号。 
掉期 = 0

 对于 s 中的 char：
 如果字符=='['：
 余额+=1
 其他：
 余额 -= 1

 如果余额 < 0：
 掉期 += 1
 余额 = 1

 返回掉期```

The implementation follows the greedy algorithm directly.

The `balance` variable tracks the current bracket validity state while scanning the string.

When we see an opening bracket, we increase balance because it can potentially match a future closing bracket.

When we see a closing bracket, we decrease balance because it consumes one unmatched opening bracket.

The important logic occurs when `balance < 0`. This indicates an invalid prefix. At that moment:

- We count one swap
- We reset balance to `1`

This reset simulates bringing a future `'['` into the current position.

The algorithm never physically swaps characters because the exact swap locations do not matter. Only the number of required corrections matters.

Since the string is traversed exactly once and only constant extra memory is used, the solution is highly efficient.

## Edge Cases

### Already Balanced Strings

Inputs such as:

```“[]”
 “[[]]”
 “[][]”```

never cause the balance to become negative.

A buggy implementation might still attempt unnecessary swaps or miscount balance transitions. This implementation correctly returns `0` because the `balance < 0` condition is never triggered.

### Strings Starting with Many Closing Brackets

Inputs like:

```“]]][[[”
 ````

 特别危险，因为余额立即变为负值。 

幼稚的实现可能会错误地将余额重置为`0`交换后。 然而，在交换左括号后，应该保留一个不匹配的左括号，因此正确的重置值为`1`。 

这个实现正确地处理了这个问题。 

### 极大的输入

 该约束允许字符串达到`10^6`人物。 

任何重复向前搜索、构造新字符串或物理执行交换的实现都可能会超时或消耗过多内存。 

此实现使用恒定的额外内存一次处理字符串，即使对于最大的有效输入也能高效。
