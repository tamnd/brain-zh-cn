[LeetCode 1956 题](https://leetcode.com/problems/minimum-time-for-k-virus-variants-to-spread/)

 **难度：** 🔴难
 **主题：** 数组、数学、二分查找、几何、枚举

 ## 解决方案

 ## 问题理解

 该问题描述了在无限二维网格中传播的多种病毒变体。 每一种病毒都从自己的起源点开始`0`。 每天，病毒都会向四个基本方向传播一步，这意味着之后`d`天，病毒可以到达距其起源曼哈顿距离最多为 的每个点`d`。 

两点之间的曼哈顿距离`(x1, y1)`和`(x2, y2)`是：$$|x1 - x2| + |y1 - y2|$$网格上的一个点当天包含病毒变种`d`如果病毒能够在短时间内到达该点`d`步骤。 

我们得到：

 -`points[i] = [xi, yi]`, 的起始位置`i-th`病毒
 - 一个整数`k`我们必须确定最小天数，使得至少存在一个网格单元包含至少`k`同时不同的病毒变种。 

一个重要的细节是，多个病毒变种可能源自同一坐标。 尽管坐标可能重复，但病毒变种本身被认为是不同的。 

限制相对较小：

 -`n <= 50`- 坐标最多为`100`这告诉我们，如果仔细优化，指数或重几何方法可能仍然是可以接受的。 由于答案代表最小可行天数，因此二分搜索成为强有力的候选者。 

一些边缘情况很重要：

 - 多种病毒可能在一天中已经重叠`0`-`k`可能等于`n`，这意味着我们需要一个所有变体都可以到达的点
 - 病毒可能相距极远
 - 可能有很多候选交叉区域
 - 最佳交汇点不一定与原始病毒位置一致

 无限网格听起来很吓人，但曼哈顿距离的几何形状为问题提供了我们可以利用的强大结构。 

## 方法

 ### 蛮力方法

 直接的暴力解决方案将模拟日常的病毒传播并跟踪哪些病毒到达每个细胞。 

固定天数`d`，每个病毒覆盖一个菱形区域：$$|x - xi| + |y - yi| \le d$$一种强力策略将枚举足够大的边界框内的所有网格单元，并计算每个点包含多少个病毒区域。 

这是有效的，因为如果任何点至少被覆盖`k`病毒，那么`d`是可行的。 

然而，这种方法变得低效，因为：

 - 网格是无限的
 - 覆盖区域随距离呈二次方增长
 - 长距离的边界框变得巨大
 - 对二分搜索重复此操作将非常昂贵

 即使坐标限制接近`100`，答案可能会大大超出该范围。 

### 关键见解

 关键的观察是曼哈顿距离约束可以转化为线性不等式。 

一点`(x, y)`满足：$$|x - xi| + |y - yi| \le d$$当且仅当以下条件全部成立时：$$x + y \le xi + yi + d$$

$$x + y \ge xi + yi - d$$

$$x - y \le xi - yi + d$$

$$x - y \ge xi - yi - d$$因此，每个病毒在变换后的坐标中定义一个矩形：

 -`u = x + y`-`v = x - y`对于固定的`d`，我们需要确定是否存在至少被覆盖的点`k`这样的矩形。 

自从`n <= 50`，我们可以通过扫描候选边界来间接枚举子集。 

我们二分查找答案：

 - 如果一天算数`d`是可行的，更大的值也是可行的
 - 这种单调性使得二分查找有效

 对于每位候选人`d`，我们从几何角度检验可行性。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(R² × n × log R) | O(R²) | 枚举大边界框中的网格单元 |
 | 最佳| O(log M × n3) | O(log M × n3) | O(n²) | 具有几何交集检查的二分搜索 |

 这里，`M`是最大可能的答案范围。 

## 算法演练

 ### 步骤 1，二分查找答案

 答案是单调的。 

如果有可能的话`k`病毒重叠后`d`天，那么之后也有可能`d + 1`因为每个病毒区域只会扩大。 

这允许在最小可行日内进行二分搜索。 

我们初始化：

 -`left = 0`-`right = 200`更大的上限，例如`400`或者`1000`也可以安全工作。 

### 步骤2，转换每个病毒区域

 对于固定的日子`d`，每种病毒涵盖：$$|x - xi| + |y - yi| \le d$$变换坐标：$$u = x + y$$

$$v = x - y$$那么病毒覆盖率就变成：$$xi + yi - d \le u \le xi + yi + d$$

$$xi - yi - d \le v \le xi - yi + d$$这是一个轴对齐的矩形`(u, v)`空间。 

### 步骤 3，枚举候选交叉点

 我们需要知道至少是否`k`矩形重叠。 

标准的几何技巧是任何重叠区域边界必须来自矩形边界。 

我们收集所有候选人`u`坐标来自：

 - 下限
 - 上限

 同样对于`v`。 

然后我们测试每个候选人`(u, v)`一对。 

对于每个候选点：

 - 计算有多少个矩形包含它
 - 如果计数达到`k`，那么日`d`是可行的

 ### 步骤 4，可行性检查

 对于每个病毒矩形：

 - 检查是否：$$u_{min} \le u \le u_{max}$$和$$v_{min} \le v \le v_{max}$$如果为 true，则矩形包含该点。 

如果至少`k`矩形包含点，返回`True`。 

### 步骤5，完成二分查找

 如果有一天`mid`是可行的：

 - 存储答案
 - 搜索较小的值

 否则：

 - 搜索更大的值

 最终二分搜索收敛到最小可行日。 

### 为什么它有效

 转换后的几何形状将菱形曼哈顿区域转换为轴对齐的矩形。 矩形之间的任何重叠区域都必须具有源自矩形边缘的边界。 因此，如果尺寸重叠至少`k`存在，则存在我们将枚举的候选边界点。 

二分搜索是有效的，因为病毒区域只会随着时间的推移而增长，使得可行性变得单调。 

## Python 解决方案```python
from typing import List

class Solution:
    def minDayskVariants(self, points: List[List[int]], k: int) -> int:
        n = len(points)

        def can(days: int) -> bool:
            rectangles = []

            u_values = set()
            v_values = set()

            for x, y in points:
                u_min = x + y - days
                u_max = x + y + days

                v_min = x - y - days
                v_max = x - y + days

                rectangles.append((u_min, u_max, v_min, v_max))

                u_values.add(u_min)
                u_values.add(u_max)

                v_values.add(v_min)
                v_values.add(v_max)

            for u in u_values:
                for v in v_values:
                    count = 0

                    for u_min, u_max, v_min, v_max in rectangles:
                        if u_min <= u <= u_max and v_min <= v <= v_max:
                            count += 1

                    if count >= k:
                        return True

            return False

        left = 0
        right = 400

        while left < right:
            mid = (left + right) // 2

            if can(mid):
                right = mid
            else:
                left = mid + 1

        return left
```实现首先定义一个辅助函数`can(days)`决定是否至少`k`病毒可以在给定的天数后重叠。 

在这个助手中，每个病毒区域都被转换成一个矩形`(u, v)`坐标。 我们存储：

 - 最小值和最大值`u`- 最小值和最大值`v`我们还将所有矩形边界收集到候选坐标集中。 

接下来，我们枚举每个候选人`(u, v)`一对。 对于每一对，我们计算有多少个矩形包含该点。 如果计数达到`k`，配置可行。 

外部二分查找重复调用该可行性函数。 由于可行性是单调的，二分查找可以正确找到最小的有效天数。 

## 解决方案```go
func minDayskVariants(points [][]int, k int) int {
	can := func(days int) bool {
		type Rect struct {
			uMin int
			uMax int
			vMin int
			vMax int
		}

		rectangles := []Rect{}

		uSet := map[int]bool{}
		vSet := map[int]bool{}

		for _, p := range points {
			x := p[0]
			y := p[1]

			uMin := x + y - days
			uMax := x + y + days

			vMin := x - y - days
			vMax := x - y + days

			rectangles = append(rectangles, Rect{
				uMin: uMin,
				uMax: uMax,
				vMin: vMin,
				vMax: vMax,
			})

			uSet[uMin] = true
			uSet[uMax] = true

			vSet[vMin] = true
			vSet[vMax] = true
		}

		uValues := []int{}
		for val := range uSet {
			uValues = append(uValues, val)
		}

		vValues := []int{}
		for val := range vSet {
			vValues = append(vValues, val)
		}

		for _, u := range uValues {
			for _, v := range vValues {
				count := 0

				for _, rect := range rectangles {
					if rect.uMin <= u && u <= rect.uMax &&
						rect.vMin <= v && v <= rect.vMax {
						count++
					}
				}

				if count >= k {
					return true
				}
			}
		}

		return false
	}

	left := 0
	right := 400

	for left < right {
		mid := (left + right) / 2

		if can(mid) {
			right = mid
		} else {
			left = mid + 1
		}
	}

	return left
}
```Go 的实现与 Python 方法非常相似。 

由于Go没有元组，我们定义一个`Rect`结构体来存储矩形边界。 哈希集是使用以下实现的`map[int]bool`。 

切片用于候选坐标枚举。 整数溢出不是问题，因为坐标和距离仍然很小。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(log M × n3) | O(log M × n3) | 二分查找乘以矩形重叠检查|
 | 空间| O(n²) | 存储矩形和候选边界 |

 对于每次二分搜索迭代：

 - 我们创造`n`矩形
 - 我们最多枚举`2n`候选人`u`价值观
 - 我们最多枚举`2n`候选人`v`价值观
 - 对于每个候选对，我们扫描所有`n`矩形

 这给出：$$O((2n)(2n)n) = O(n^3)$$二分查找加一个乘法`log M`因素。 

自从`n <= 50`，这很容易足够快。

 ## 边缘情况

 ### 多个病毒从同一点开始

 不同的病毒变种可能源自相同的坐标。 有缺陷的实现可能会意外地删除它们的重复项并丢失变体。 

此实现永远不会删除重复项。 每个病毒都会产生自己的矩形，因此如果多个变体一起开始，重叠计数会立即反映这一点。 因此，答案可以是正确的`0`。 

### 要求所有病毒重叠

 当`k = n`，每种病毒必须同时覆盖一些共同点。 这是最严格的要求。 

矩形交集逻辑自然地处理这个问题，因为我们只是计算有多少个矩形包含候选点。 该算法不区分部分重叠和完全重叠。 

### 最佳点不等于任何病毒起源

 幼稚的实现可能只检查原始病毒坐标。 但这会失败，因为最佳重叠点可能位于完全不同的地方。 

变换坐标矩形方法通过边界枚举间接正确地搜索所有可能的交叉区域，确保不会遗漏有效的重叠点。
