## 问题理解

 这个问题要求我们在多次调整动态数组大小时最大限度地减少**总浪费空间**。 我们得到一个 0 索引的数组`nums`在哪里`nums[i]`表示此时需要放入数组的元素数量`i`。 我们最多可以调整数组的大小`k`次，任意时刻数组的大小必须至少为`nums[i]`。 每个时间步的**浪费的空间**是数组大小和`nums[i]`。 

目标是选择调整点和数组大小，以便最小化所有时间步上浪费的空间总和。 

输入要点：

 -`1 <= nums.length <= 200`，因此如果使用动态规划进行优化，数组对于 O(n³) 解决方案来说足够小。 
-`1 <= nums[i] <= 10^6`，这意味着简单的预计算或大量内存使用的解决方案可能不可行。 
-`0 <= k <= nums.length - 1`，表示允许调整大小的数量以数组长度减一为界。 

重要的边缘情况包括：

 1.`k = 0`，意味着不允许调整大小。 该数组在任何时候都必须是一种大小。 
2. 全部`nums[i]`相等，因此无论大小如何调整，浪费的空间都是 0。 
3.`nums`严格增加或减少，这可能会使天真的贪婪方法失败。 

## 方法

 **蛮力：**

 蛮力方法会尝试调整大小操作的所有可能组合。 我们可以在每个位置递归地决定是否调整大小并跟踪所有数组大小和浪费的空间。 虽然这保证了正确性，但其时间复杂度是指数级的，因为每个`n`位置可以调整大小，也可以不调整大小，从而导致 O(2^n) 的可能性。 显然，这对于`n`最多 200 个。 

**最佳方法：**

 关键的见解是，连续段的**空间被浪费**`nums`如果该段期间的数组大小是该段中的**最大元素**，则最小化。 这意味着我们在考虑调整大小时只需要计算子数组的最大值，这使我们能够预先计算这些值。 

然后我们可以使用**动态规划**，其中`dp[i][k]`表示第一个的最小浪费空间`i`最多使用的元素`k`调整大小操作。 对于每个位置`i`以及允许的调整大小次数`k`，我们尝试在每个可能的点分割前一段`j < i`，添加新段的预先计算的浪费空间，并更新`dp[i][k]`。 这将指数复杂度降低到 O(n² * k)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试所有调整大小组合 |
 | 最佳| O(n² * k) | O(n² + n*k) | O(n² + n*k) | 具有预先计算段最大值和浪费空间的 DP |

 ## 算法演练

 1. **预先计算段最大值和浪费的空间：**

 创建二维表`waste[i][j]`表示如果我们使用单个固定大小（最大`nums[i:j+1]`) 为子数组`nums[i:j+1]`。 这可以通过嵌套循环来完成：对于每个`i`，跟踪运行最大值并计算所有废物的总浪费`j >= i`。 
2. **初始化DP表：**

 让`dp[i][r]`是第一个的最小浪费空间`i`最多有的元素`r`调整大小。 将所有值初始化为无穷大。 基本情况：`dp[0][0] = 0`。 
3. **填充 DP 表：**

 对于每个`i`从 1 到`n`，对于每个允许的调整大小次数`r`从 0 到`k`，迭代所有可能的先前分割点`j`从 0 到`i-1`。 更新：`dp[i][r] = min(dp[i][r], dp[j][r-1] + waste[j][i-1])`。 
4. **返回答案：**

 整个数组最多使用的最小浪费空间`k`调整大小是`dp[n][k]`。 

**为什么有效：**

 不变的是 DP 表始终包含第一个的最小浪费空间`i`给出的元素`r`调整大小。 通过预先计算所有连续段的浪费空间，我们避免了重新计算并确保每个子问题得到最优解决，从而保证了全局最优性。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSpaceWastedKResizing(self, nums: List[int], k: int) -> int:
        n = len(nums)
        # Precompute wasted space for all segments
        waste = [[0] * n for _ in range(n)]
        for i in range(n):
            max_val = nums[i]
            total = 0
            for j in range(i, n):
                max_val = max(max_val, nums[j])
                total += max_val - nums[j]
                waste[i][j] = total

        # DP table: dp[i][r] = min wasted space for first i elements with r resizes
        dp = [[float('inf')] * (k + 1) for _ in range(n + 1)]
        dp[0][0] = 0

        for i in range(1, n + 1):
            for r in range(k + 1):
                for j in range(i):
                    if r > 0 or j == 0:
                        dp[i][r] = min(dp[i][r], dp[j][r - 1] + waste[j][i - 1] if r > 0 else waste[j][i - 1])

        return dp[n][k]
```该实现首先为浪费的空间构建一个二维数组，然后迭代地填充 DP 表。 内部循环检查所有可能的段分割并更新给定大小调整次数的最小浪费空间。 边缘情况如`k = 0`自然处理，因为不允许调整大小，并且只计算基本浪费。 

## 解决方案```go
func minSpaceWastedKResizing(nums []int, k int) int {
    n := len(nums)
    waste := make([][]int, n)
    for i := range waste {
        waste[i] = make([]int, n)
        maxVal := nums[i]
        total := 0
        for j := i; j < n; j++ {
            if nums[j] > maxVal {
                maxVal = nums[j]
            }
            total += maxVal - nums[j]
            waste[i][j] = total
        }
    }

    dp := make([][]int, n+1)
    for i := range dp {
        dp[i] = make([]int, k+1)
        for j := range dp[i] {
            dp[i][j] = 1<<60
        }
    }
    dp[0][0] = 0

    for i := 1; i <= n; i++ {
        for r := 0; r <= k; r++ {
            for j := 0; j < i; j++ {
                if r > 0 || j == 0 {
                    val := waste[j][i-1]
                    if r > 0 {
                        val += dp[j][r-1]
                    }
                    if val < dp[i][r] {
                        dp[i][r] = val
                    }
                }
            }
        }
    }
    return dp[n][k]
}
```Go 小心地处理切片初始化以避免 nil 错误。 由于 Go 没有`float('inf')`，一个大整数（`1<<60`）被使用。 否则，逻辑会反映 Python 版本。
