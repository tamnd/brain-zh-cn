[LeetCode 1925 题](https://leetcode.com/problems/count-square-sum-triples/)

 **难度：** 🟢简单
 **Topics:** Math, Enumeration

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算所有有序三元组的数量`(a, b, c)`这样：

 -`1 <= a, b, c <= n`-`a² + b² = c²`这就是经典的毕达哥拉斯定理关系。 任何满足此条件的三元组在问题陈述中称为平方三元组。 

重要的细节是三元组是有序的。 这意味着`(3,4,5)`和`(4,3,5)`被视为不同的三元组，并且两者必须单独计算。 

输入由单个整数组成`n`，它定义了最大可能值`a`,`b`， 和`c`。 输出是有效有序三元组的总数。 

限制非常小：

 -`1 <= n <= 250`因为`n`只有 250，即使相对低效的枚举方法也是可以接受的。 然而，我们仍然希望设计一个干净、高效的解决方案。 

有几个重要的观察结果和边缘情况：

 - 非常小的值`n`， 例如`1`或者`2`，无法形成任何有效的三元组，因为最小的毕达哥拉斯三元组是`(3,4,5)`。 
- 该问题计算有序对，因此对称性很重要。 
- 我们只关心整数平方关系。 
- 自从`n`很小，整数溢出在 Python 或 Go 中都不是问题。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是尝试各种可能的组合`(a, b, c)`。 

我们可以使用三个嵌套循环：

 - 迭代`a`从`1`到`n`- 迭代`b`从`1`到`n`- 迭代`c`从`1`到`n`对于每个三元组，计算：```
a² + b² == c²
```如果方程成立，则增加答案。 

这种方法是正确的，因为它明确地检查每个可能的候选三元组。 任何有效的解决方案都不能被遗漏。 

但时间复杂度非常高：

 - 有`n³`组合。 
- 和`n = 250`，这变成了`15,625,000`检查。 

虽然这仍然符合该问题的实际限制，但其成本却不必要地昂贵。 

### 最优枚举方法

 关键的观察是一旦`a`和`b`被选择，值`c²`完全确定：```
c² = a² + b²
```而不是迭代所有可能的`c`值，我们可以直接计算是否`a² + b²`是一个完美的正方形。 

改进后的策略是：

 - 枚举所有`(a, b)`对
 - 计算`sumSquares = a² + b²`- 计算`c = sqrt(sumSquares)`- 检查是否`c * c == sumSquares`- 还要确保`c <= n`这降低了复杂性`O(n³)`到`O(n²)`。 

由于约束很小，因此该解决方案既简单又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 检查所有可能的情况`(a,b,c)`组合|
 | 最佳| O(n²) | O(1) | O(1) | 计算`c`直接使用平方根|

 ## 算法演练

 1. 初始化变量`count`存储有效平方三元组的数量。 
2. 迭代`a`从`1`到`n`。 每个有效的三元组必须包含一个值`a`，所以我们系统地检查所有可能性。 
3. 在循环内进行迭代`b`从`1`到`n`。 由于有序对很重要，因此我们必须考虑每一个`(a,b)`分别组合。 
4. 计算：```
sumSquares = a² + b²
```该值表示所需的平方值`c²`。 
5. 计算整数平方根`sumSquares`。 

我们这样做是因为如果`sumSquares`是完全平方数，则存在一个整数`c`满意：```
c² = sumSquares
```6. 验证平方根是否准确：```
c * c == sumSquares
```这证实了`sumSquares`是一个完美的正方形。 
7. 另请验证：```
c <= n
```因为问题将所有值限制在范围内`[1, n]`。 
8. 如果两个条件都成立，则递增`count`。 
9.所有循环结束后，返回`count`。 

### 为什么它有效

 该算法检查每个可能的有序对`(a,b)`。 对于每一对，该方程唯一确定什么`c²`必须相等。 通过检查该值是否是允许范围内的完美平方，我们可以准确地识别每个有效的平方三元组一次。 既然一切可能`(a,b)`对已处理，不会错过任何有效的解决方案。 

## Python 解决方案```python
class Solution:
    def countTriples(self, n: int) -> int:
        count = 0

        for a in range(1, n + 1):
            for b in range(1, n + 1):
                sum_squares = a * a + b * b

                c = int(sum_squares ** 0.5)

                if c * c == sum_squares and c <= n:
                    count += 1

        return count
```实现直接遵循前面描述的算法。 

变量`count`存储有效三元组的总数。 

外部两个循环枚举每个有序对`(a,b)`。 由于问题处理`(3,4,5)`和`(4,3,5)`作为不同的三元组，我们有意不限制`b`相对于`a`。 

对于每一对，我们计算`sum_squares`，它代表所需的值`c²`。 

然后我们使用以下方法计算整数平方根：```python
c = int(sum_squares ** 0.5)
```支票：```python
c * c == sum_squares
```确保`sum_squares`是一个完美的正方形。 浮点平方根可能会产生非整数值，因此此验证步骤至关重要。 

最后，我们确保`c <= n`在数三倍之前。 

## 解决方案```go
package main

import "math"

func countTriples(n int) int {
    count := 0

    for a := 1; a <= n; a++ {
        for b := 1; b <= n; b++ {
            sumSquares := a*a + b*b

            c := int(math.Sqrt(float64(sumSquares)))

            if c*c == sumSquares && c <= n {
                count++
            }
        }
    }

    return count
}
```Go 实现与 Python 版本几乎相同。 

一个显着的区别是 Go 的`math.Sqrt`函数运行于`float64`，所以我们必须在整数和浮点类型之间显式转换：```go
c := int(math.Sqrt(float64(sumSquares)))
```转换回整数后，我们使用以下方法验证完全平方条件：```go
c*c == sumSquares
```这避免了浮点精度引起的问题。 

整数溢出不是问题，因为最大值是：```go
250² + 250² = 125000
```它很容易符合 Go 的整数范围。

 ## 边缘情况

 ### 非常小的输入

 输入如`n = 1`,`n = 2`,`n = 3`， 和`n = 4`无法产生任何有效的平方三元组。 如果完美平方检查不正确，幼稚的实现可能会意外地计算出无效组合。 此实现安全返回`0`因为没有`(a,b)`对产生一个有效的整数`c`范围内。 

### 有序对对称性

 该问题计算有序三元组，意思是`(3,4,5)`和`(4,3,5)`都是不同的答案。 一个常见的错误是将循环限制为`b >= a`，这会错误地消除有效的有序组合。 该实现独立地循环遍历所有值`a`和`b`，确保两个订单都被计算在内。 

### 浮点平方根精度

 平方根计算使用浮点运算，有时会引入精度问题。 有缺陷的实现可能仅仅依赖于检查平方根是否看起来像整数。 该解决方案通过验证以下内容来避免该问题：```
c * c == sum_squares
```即使内部发生浮点舍入，这种精确的整数比较也能保证正确性。
