[LeetCode 1981 问题](https://leetcode.com/problems/minimize-the-difference- Between-target-and-chosen-elements/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们从给定的每一行中精确选择一个元素`m x n`整数矩阵`mat`使得所选元素的总和尽可能接近给定的整数`target`。 目标是**最小化所选元素之和与目标之间的绝对差异**。 

简单来说，我们试图从矩阵中求和，每行选择一个数字，以便该和接近目标。 输入保证矩阵维度`m`和`n`都在1到70之间，矩阵的每个元素和目标值都是正整数。 这告诉我们，尝试所有组合的强力解决方案（可能最多`70^70`最坏情况下的可能性）是不可行的。 

需要注意的关键点包括边缘情况，其中目标远小于最小可能总和或远大于最大可能总和，或者矩阵只有一行或一列。 如果这些情况假设有更多行或数字均匀分布，则可能会导致简单的实现失败。 

## 方法

 ### 蛮力

 暴力方法会枚举从每一行中选择一个元素的**所有可能的组合**，计算它们的总和，并跟踪与`target`。 虽然这种方法是正确的，但对于给定的约束，它在计算上是不可行的，因为组合的数量随着行数呈指数增长，`O(n^m)`。 

### 最佳方法

 最佳解决方案的关键洞察是使用**动态规划**。 我们不是明确地跟踪所有组合，而是在处理每一行后维护一组所有可能的总和。 对于每一行，我们通过将行中的每个元素添加到前一行的每个总和中来更新总和集。 处理完所有行后，我们扫描所有总和以找到最接近目标的总和。 

为了保持状态的可管理性，我们可以使用 **set** 来自动处理重复项，因为多个路径可能会导致相同的总和。 蟒蛇的`set`或 Go 的`map[int]struct{}`在这里运作良好。 这种方法很有效，因为最大可能的总和是有界的 (`m * max(mat[i][j]) ≤ 4900`），它足够小，可以处理集合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^m) | O(n^m) | O(1) | O(1) | 枚举所有可能的组合； 指数且不可行 |
 | 动态规划| O(m * n * S) | O(S)| 迭代地维持可达到的总和； S 是上限总和范围`m*70`|

 ## 算法演练

 1.初始化一组`possible_sums`只包含`0`，表示处理任何行之前的总和。 
2. 迭代矩阵中的每一行。 
3. 对于当前行，创建一个新集合`next_sums`存储包含该行中的一个元素后可能的所有总和。 
4. 对于每笔金额`s`在`possible_sums`，添加每个元素`num`从当前行到`s`，并将结果添加到`next_sums`。 
5.处理完该行后，更新`possible_sums`到`next_sums`。 
6. 处理完所有行后，求总和`possible_sums`的绝对差值最小`target`。 
7. 返回该最小绝对差值。 

**为什么有效**：该算法逐行跟踪所有可达到的总和。 通过使用集合，可以删除重复项，从而防止不必要的计算。 处理完所有行后，该集合包含通过每行选取一个元素可实现的所有可能的总和，从而保证找到最小的绝对差。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimizeTheDifference(self, mat: List[List[int]], target: int) -> int:
        possible_sums = {0}
        for row in mat:
            next_sums = set()
            for s in possible_sums:
                for num in row:
                    next_sums.add(s + num)
            possible_sums = next_sums
        return min(abs(s - target) for s in possible_sums)
```Python 实现使用集合来有效地存储可达总和。 对于每一行，我们通过将每个行元素添加到集合中已有的每个总和来计算新的总和。 最后，我们通过迭代最终集合来计算最小绝对差。 

## 解决方案```go
func minimizeTheDifference(mat [][]int, target int) int {
    possibleSums := map[int]struct{}{0: {}}
    
    for _, row := range mat {
        nextSums := make(map[int]struct{})
        for s := range possibleSums {
            for _, num := range row {
                nextSums[s+num] = struct{}{}
            }
        }
        possibleSums = nextSums
    }
    
    minDiff := 1 << 30 // large initial value
    for s := range possibleSums {
        diff := s - target
        if diff < 0 {
            diff = -diff
        }
        if diff < minDiff {
            minDiff = diff
        }
    }
    
    return minDiff
}
```在 Go 中，映射用于模拟集合。 该算法与 Python 相同，但使用标准整数算术显式处理绝对差异。 

## 工作示例

 ### 示例 1：`mat = [[1,2,3],[4,5,6],[7,8,9]], target = 13`- 最初的`possible_sums = {0}`- 第一行之后：`{1, 2, 3}`- 第二行之后：`{5,6,7,8,9}`- 第三排之后：`{12,13,14,15,16,17,18}`- 最小绝对差为 13：`0`（总和 = 13）

 ### 示例 2：`mat = [[1],[2],[3]], target = 100`- 最初的`possible_sums = {0}`- 每行之后：`{1}`,`{3}`,`{6}`- 最小绝对差为 100：`94`（总和 = 6）

 ### 示例 3：`mat = [[1,2,9,8,7]], target = 6`- 只有一行，可能的总和：`{1,2,7,8,9}`- 最小绝对差为 6：`1`（总和 = 7）

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m * n * S) | 对于每一行 (m) 和每个元素 (n)，我们更新一组总和，其中 S 的边界为 m*70 |
 | 空间| O(S)| 我们存储所有可达的总和，最多为 m * max(mat[i][j]) |

 复杂性是可控的，因为 S（最大可能和）被限制为 70 * 70 = 4900，并且集合避免了冗余计算。

 ## 边缘情况

 1. **单行矩阵**：如果矩阵只有一行，则结果只是最接近目标的元素。 该算法通过处理一行并计算最小绝对差来处理此问题。 
2. **目标小于最小总和**：如果目标小于每行最小元素的总和，则该算法仍然有效，因为可能的总和集捕获了所有可实现的总和，并且最小绝对差值被正确计算。 
3. **目标大于最大总和**：同样，如果目标超过最大可能总和，则最终集合将包含最大可实现总和，并且最小绝对差被正确计算为`target - max_sum`。 该算法本身就考虑了这种情况，无需额外检查。
