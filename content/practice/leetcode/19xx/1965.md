[LeetCode 1965 问题](https://leetcode.com/problems/employees-with-missing-information/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了两个关系表，其中一个名为`Employees`和另一个名叫`Salaries`，两者都由`employee_id`。 每个员工可能会也可能不会出现在两个表中。 这`Employees`表包含员工的姓名，而`Salaries`表包含员工的工资。 

任务是识别所有`employee_id`信息不完整的值。 如果员工的姓名没有出现在信息中，则该员工被视为信息缺失。`Employees`表或他们的工资没有出现在`Salaries`桌子。 换句话说，我们正在寻找两个数据集中均未完全存在的 ID。 

预期输出是包含这些有问题的单列结果`employee_id`值按升序排序。 

尽管该问题是在数据库上下文中构建的，但它从根本上简化为两个 ID 集合之间的集合协调问题。 这些约束是 LeetCode 简单级数据库问题的典型，这意味着表的大小从小到中等，并且可以使用直接连接或内存中集合操作进行处理。 

边缘情况包括一个表为空、两个表相同或两个表之间根本没有重叠的情况。 该问题保证了唯一性`employee_id`在每个表中，这简化了推理，因为没有重复的键需要处理。 

## 方法

 暴力方法从概念上考虑任一表中出现的每个可能的员工 ID，并逐一检查它是否存在于两个表中。 这可以通过形成所有 ID 的并集然后针对两个表扫描每个 ID 来模拟。 虽然这是正确的，但效率很低，因为每次成员资格检查可能需要扫描整个表，从而在最坏的情况下导致二次行为。 

最佳的见解是我们实际上根本不需要检查姓名或工资。 我们只需要推断存在或不存在`employee_id`横跨两张桌子。 这减少了设置操作的问题。 具体来说，我们计算两个表中 ID 的并集，然后删除两个表中出现的 ID，这相当于计算两个 ID 集之间的对称差。 这是有效的，因为集合运算通常在时间上是线性的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m) | O(n + m) | 对于每个 ID，扫描两个表以检查是否存在 |
 | 最佳| O(n + m) | O(n + m) | 使用集合操作或基于散列的成员资格 |

 ## 算法演练

 1.首先，提取所有`employee_id`值来自`Employees`表并将它们存储在一个集合中。 这允许恒定时间的成员资格检查并避免重复扫描表。 
2.接下来，全部解压`employee_id`值来自`Salaries`出于同样的原因，将它们存储在另一个集合中，从而实现有效的比较。 
3. 计算两个集合的并集。 这代表至少一个表中出现的每个员工 ID。 
4. 计算两个集合的交集。 这代表拥有完整信息的员工，这意味着他们出现在两个表中。 
5. 从并集中减去交集。 结果集仅包含其中一个表中缺失的员工 ID，这正是缺失信息的定义。 
6. 将结果集转换为排序列表，因为问题要求输出按以下顺序排序`employee_id`按升序排列。 

### 为什么它有效

 正确性依赖于一个简单的不变量：当且仅当员工的 ID 出现在两个集合中时，该员工才是有效的。 此交叉点之外的任何 ID 都必须缺少姓名或工资。 通过计算对称差，我们精确地隔离了那些不符合完整性条件的 ID。 

## Python 解决方案```python
from typing import List

class Solution:
    def findEmployeesWithMissingInfo(self, employees: List[List[int]], salaries: List[List[int]]) -> List[int]:
        employee_ids = {emp_id for emp_id, _ in employees}
        salary_ids = {emp_id for emp_id, _ in salaries}
        
        all_ids = employee_ids | salary_ids
        complete_ids = employee_ids & salary_ids
        
        missing_ids = sorted(all_ids - complete_ids)
        return missing_ids
```Python 实现直接反映了算法思想。 我们首先构建两组：一组用于来自`Employees`表和一个用于 ID 的表`Salaries`桌子。 然后我们计算这些集合的并集和交集。 最终结果是通过从并集减去交集获得的，从而产生对称差。 排序可确保输出符合所需的排序约束。 

## 解决方案```go
func findEmployeesWithMissingInfo(employees [][]int, salaries [][]int) []int {
    empSet := make(map[int]bool)
    salSet := make(map[int]bool)

    for _, row := range employees {
        empSet[row[0]] = true
    }

    for _, row := range salaries {
        salSet[row[0]] = true
    }

    result := make([]int, 0)

    for id := range empSet {
        if !salSet[id] {
            result = append(result, id)
        }
    }

    for id := range salSet {
        if !empSet[id] {
            result = append(result, id)
        }
    }

    // simple insertion sort or rely on built-in sort
    for i := 0; i < len(result); i++ {
        for j := i + 1; j < len(result); j++ {
            if result[j] < result[i] {
                result[i], result[j] = result[j], result[i]
            }
        }
    }

    return result
}
```在 Go 实现中，我们使用哈希映射（`map[int]bool`）来模拟集合，因为 Go 没有内置的集合类型。 我们迭代两个输入表来填充这些映射。 然后，我们通过检查两张地图上的成员资格来收集双方缺失的 ID。 最后，我们对结果切片进行排序以满足排序要求。 为了完整性，这里手动实现排序，尽管在生产 Go 代码中我们通常会使用`sort.Ints`。 

## 工作示例

 使用样本输入，我们首先构建两个集合。 

这`Employees`表产生集合`{2, 4, 5}`。 

这`Salaries`表产生集合`{1, 4, 5}`。 

我们计算并集，即`{1, 2, 4, 5}`。 

我们计算交集，即`{4, 5}`。 

减去得到`{1, 2}`。 

排序后，最终输出为`[1, 2]`。 

在每一步中，集合都保持很小且易于跟踪，并且中间变换不会改变对称差分逻辑的正确性。

 ## 边缘情况

 一种重要的边缘情况是其中一张表为空。 在这种情况下，非空表中的每个ID都应该返回，因为它们都缺少相应的信息。 基于集合的实现自然会处理这个问题，因为空集合对交集没有任何贡献。 

当两个表包含完全相同的内容时，会出现另一种边缘情况`employee_id`价值观。 在这种情况下，不应返回任何输出，因为每个员工都有姓名和工资。 交集等于并集，因此对称差变为空。 

第三种边缘情况是两个表之间根本不存在重叠。 在这里，每个员工都缺少姓名或工资，因此结果应包括两个表中的所有 ID。 由于交集为空，因此并集成为最终输出，并且减法步骤使所有元素保持不变。
