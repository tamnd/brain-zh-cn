[LeetCode 第 1288 题](https://leetcode.com/problems/remove-covered-intervals/)

 **难度：** 🟡 中等
 **主题：** 数组、排序

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个间隔列表，其中每个间隔表示为`[li, ri]`，对应半开区间`[li, ri)`。 我们需要删除列表中另一个区间完全覆盖的每个区间。 

一个区间`[a, b)`被认为涵盖于`[c, d)`如果：

-`c <= a`-`b <= d`这意味着整个区间`[a, b)`位于里面`[c, d)`。 

任务不是返回剩余间隔本身。 相反，我们只需要返回删除所有覆盖的区间后剩余的区间数。 

例如，如果我们有：```
[[1,4],[3,6],[2,8]]
```间隔`[3,6]`完全包含在里面`[2,8]`， 因为：

-`2 <= 3`-`6 <= 8`所以`[3,6]`被删除，留下两个间隔。 

限制相对较小：

 - 最多`1000`间隔
 - 间隔端点可达`100000`由于输入大小适中，即使是`O(n^2)`解决方案在技术上会通过。 然而，该问题旨在奖励更优雅的基于排序的方法。 

需要考虑一些重要的边缘情况：

 - 具有相同起点的间隔
 - 间隔深深嵌套在另一个间隔内
 - 重叠但未被覆盖的区间
 - 单一间隔输入
 - 间隔已经排序或完全未排序

 该问题还保证所有间隔都是唯一的，从而消除了重复间隔的歧义。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将每个间隔与其他间隔进行比较。 

对于每个间隔`i`，我们检查是否存在另一个区间`j`这样：```
j.start <= i.start
j.end >= i.end
```如果存在这样的区间，则区间`i`已被覆盖，不应计算在内。 

这种方法是正确的，因为它明确测试了每对区间的覆盖范围定义。 然而，它需要检查所有对，导致时间复杂度为二次方。 

和`n`间隔，我们执行最多`n * n`比较，给出时间复杂度`O(n^2)`。 

### 最佳方法

 关键的见解是，对间隔进行排序使我们能够在一次传递中检测覆盖的间隔。 

我们使用两个规则对间隔进行排序：

 1.按照起点升序排序
 2. 如果两个区间有相同的起点，则按终点降序排序

 第二条规则极其重要。 

考虑：```
[1,4], [1,6]
```如果我们按升序对末尾进行排序，`[1,4]`会首先出现，使得更难识别它被覆盖`[1,6]`。 

通过按降序对末尾进行排序，较大的间隔排在前面：```
[1,6], [1,4]
```现在我们只需要跟踪迄今为止看到的最大终点。 

当我们扫描排序的间隔时：

 - 如果当前间隔的结束时间小于或等于迄今为止看到的最大结束时间，则将其覆盖
 - 否则不覆盖，我们更新最大结束

 这将问题简化为排序后的单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 将每个间隔与其他间隔进行比较 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(log n) | 对间隔进行排序，然后扫描一次以计算未覆盖的间隔 |

 ## 算法演练

 1. 按起点升序对区间进行排序。 

这确保了从左到右处理间隔。 
2. 当两个区间起点相同时，按终点降序排序。 

这保证了较大的间隔出现在较小的包含间隔之前。 如果没有这条规则，则可能会错过具有相同起点的覆盖间隔。 
3.初始化两个变量：

 -`remaining_intervals`， 最初`0`-`max_end`， 最初`0`

`max_end`跟踪迄今为止遇到的最远终点。 
4. 逐一迭代排序后的区间。 
5. 对于每个间隔`[start, end]`：

- 如果`end <= max_end`，则该区间被先前处理的区间覆盖。 
- 否则，该区间不被覆盖：

 - 增量`remaining_intervals`- 更新`max_end = end`6.处理完所有区间后，返回`remaining_intervals`。 

### 为什么它有效

 排序后，每个先前处理的区间的起点都小于或等于当前区间的起点。 

由于起点相等的区间是按终点递减排序的，因此任何能够覆盖当前区间的区间都必须出现在遍历的较早位置。 

因此，如果当前间隔的结尾小于或等于迄今为止看到的最大结尾，则某些较早的间隔会完全覆盖它。 

这个不变量保证了整个扫描的正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def removeCoveredIntervals(self, intervals: List[List[int]]) -> int:
        intervals.sort(key=lambda interval: (interval[0], -interval[1]))

        remaining_intervals = 0
        max_end = 0

        for start, end in intervals:
            if end > max_end:
                remaining_intervals += 1
                max_end = end

        return remaining_intervals
```实现首先根据所需的顺序对间隔进行排序。 lambda 键首先按起始位置升序排序，然后按结束位置降序排序。 

变量`max_end`存储迄今为止遇到的最右端点。 遍历过程中，如果当前区间结束于`max_end`，它不能被之前的任何区间覆盖，所以我们对其进行计数并更新`max_end`。 

如果当前间隔在以下时间或之前结束`max_end`，那么之前处理的区间已经完全包含它，所以它被跳过。 

排序后的整个算法是一次线性扫描。 

## 解决方案```go
package main

import "sort"

func removeCoveredIntervals(intervals [][]int) int {
	sort.Slice(intervals, func(i, j int) bool {
		if intervals[i][0] == intervals[j][0] {
			return intervals[i][1] > intervals[j][1]
		}
		return intervals[i][0] < intervals[j][0]
	})

	remainingIntervals := 0
	maxEnd := 0

	for _, interval := range intervals {
		end := interval[1]

		if end > maxEnd {
			remainingIntervals++
			maxEnd = end
		}
	}

	return remainingIntervals
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于使用`sort.Slice`提供用于排序间隔的自定义比较器。 

Go 切片是类似引用的结构，因此排序会直接修改原始切片。 由于区间端点最多被限制为`100000`，整数溢出不是问题。 

该算法仅使用几个整数变量，因此内存使用量仍然很少。

 ## 边缘情况

 当多个间隔共享相同的起点时，会出现一种重要的边缘情况。 例如：```
[[1,5],[1,4]]
```一种对终点升序进行排序的朴素排序策略可以处理`[1,4]`首先，很难意识到它被覆盖了。 按降序对结束点进行排序可确保较大的间隔首先出现，从而使算法能够正确检测覆盖范围。 

另一个重要的情况是未涵盖的重叠间隔：```
[[1,4],[3,6]]
```这些间隔重叠，但都不完全包含对方。 有缺陷的实现可能会仅仅因为存在重叠而错误地删除一个间隔。 该算法通过仅检查是否`end <= max_end`。 

深度嵌套间隔是错误的另一个常见来源：```
[[1,10],[2,9],[3,8],[4,7]]
```除第一个间隔之外的每个间隔都被覆盖。 该算法可以有效地处理这个问题，因为`max_end`遗迹`10`在整个扫描过程中，导致后面的每个间隔都被立即识别为覆盖。 

最终的边缘情况涉及尽可能小的输入：```
[[1,2]]
```由于不存在其他区间来覆盖它，所以答案必须是`1`。 该算法自然地处理这个问题，因为第一个间隔总是增加`max_end`并被计算在内。
