 # LeetCode 1268 - 搜索建议系统

 ## 问题理解

 这个问题要求我们建立一个类似于电子商务搜索栏中出现的产品推荐系统。 我们有两个输入：

 -`products`，一组唯一的产品名称
 -`searchWord`，用户逐个字符输入的单词

 输入每个字符后，我们必须返回最多三个以当前前缀开头的产品名称。 建议必须是：

 1.当前输入字符串的前缀匹配
 2.按字典顺序排序
 3. 最多限制三个结果

 因此，输出是一个列表，其中：

 - 第一个元素包含输入第一个字符后的建议
 - 第二个元素包含输入前两个字符后的建议
 - 依此类推，直到整个`searchWord`已输入

 例如，如果搜索词是`"mouse"`:

 - 输入后`"m"`，我们返回从以下位置开始的最佳匹配`"m"`- 输入后`"mo"`，我们返回从以下位置开始的最佳匹配`"mo"`- 输入后`"mou"`，我们进一步缩小匹配范围

 约束条件很重要：

 - 多达 1000 个产品
 - 所有产品的字符总数最多为`2 * 10^4`- 搜索字长可达1000

 这些限制并不是很大，但它们足够大，以至于重复扫描每个产品的每个前缀将变得低效。 

该问题保证：

 - 所有产品名称都是唯一的
 - 所有字符串仅包含小写英文字母

 这简化了实现，因为我们不需要处理重复或特殊字符。 

一些边缘情况很重要：

 - 仅存在一种产品
 - 某些前缀后没有匹配的产品
 - 许多产品共享相同的前缀
 - 搜索词变得更加具体并减少匹配
 - 产品名称可能比搜索词长得多

 简单的实现很容易浪费时间重复扫描完整的产品列表中的每个前缀。 

## 方法

 ### 蛮力方法

 最简单的解决方案是生成每个前缀`searchWord`并扫描整个`products`每次都数组。 

对于每个前缀：

 1.检查每件产品
 2. 保留名称以前缀开头的产品
 3. 按字典顺序对匹配项进行排序
 4. 取前三件产品

 这种方法是正确的，因为它明确评估每个前缀的每个可能的候选者。 

然而，它的效率很低，因为相同的产品会针对每个前缀重复扫描和排序。 如果搜索词有长度`m`并且有`n`产品中，我们重复执行昂贵的前缀检查和排序操作。 

### 最佳方法

 关键的观察是字典顺序在这里非常有用。 

如果我们一开始就对产品进行排序：

 - 具有相同前缀的产品被分组在一起
 - 最小的词典产品自然首先出现

 然后，对于每个前缀，我们可以使用二分搜索来定位第一个可以匹配该前缀的产品。 

由于匹配的产品按排序顺序连续出现，因此我们只需检查二分查找结果后的接下来的几个产品即可。 由于我们最多只需要三个建议，因此我们最多检查三个候选者。 

这大大减少了重复工作。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * log n) | O(m * n * log n) | O(n) | 反复扫描并排序匹配的产品 |
 | 最佳 | O(n log n + m log n) | O(n log n + m log n) | O(1) 不包括输出 | 排序一次，然后对每个前缀使用二分搜索 |

 在哪里：

-`n`是产品数量
 -`m`的长度是`searchWord`## 算法演练

 ### 最优算法

 1. 排序`products`按字典顺序排列。 

这是最重要的预处理步骤。 排序后，具有相同前缀的所有产品在数组中变得连续，并且字典顺序最小的产品自动首先出现。 
2. 初始化一个空的结果列表。 

此结果列表中的每个条目将对应于输入一个附加字符后的建议。 
3. 逐步构建前缀。 

从空字符串开始。 对于每一个角色`searchWord`，将其附加到当前前缀。 

例如：

-`"m"`-`"mo"`-`"mou"`-`"mous"`-`"mouse"`4. 使用二分查找查找当前前缀的插入位置。 

由于数组是有序的，二分查找可以快速定位到前缀可能出现的最左边位置。 

在 Python 中，这是通过以下方式完成的`bisect_left`。 

在 Go 中，我们使用手动实现二分搜索`sort.SearchStrings`。 
5. 收集最多三个匹配的产品。 

从二分查找索引开始：

 - 检查当前产品
 - 验证是否以前缀开头
 - 如果匹配的话将其添加到建议中
 - 收集三个建议后停止

 由于匹配产品按排序顺序是连续的，因此前三个有效匹配保证是正确答案。 
6. 将建议列表附加到最终结果中。 
7. 继续，直到处理完所有前缀。 

### 为什么它有效

 该算法之所以有效，是因为字典排序保证所有共享相同前缀的字符串连续出现。 二分查找有效地找到第一个可能的匹配位置，向前扫描按排序顺序检索最小的匹配产品。 由于我们只需要三个建议，因此检查一些附近的元素就足够了。 

## Python 解决方案```python
from bisect import bisect_left
from typing import List

class Solution:
    def suggestedProducts(self, products: List[str], searchWord: str) -> List[List[str]]:
        products.sort()

        result = []
        prefix = ""

        for char in searchWord:
            prefix += char

            start_index = bisect_left(products, prefix)

            suggestions = []

            for i in range(start_index, min(start_index + 3, len(products))):
                if products[i].startswith(prefix):
                    suggestions.append(products[i])

            result.append(suggestions)

        return result
```实现首先对产品数组进行排序。 这确保了字典顺序并将匹配的前缀分组在一起。 

变量`prefix`随着字符的处理而逐渐构建`searchWord`。 对于每个新的前缀，`bisect_left`执行二分查找来定位前缀可能出现的第一个位置。 

根据该指标，我们最多检查三种产品。 由于数组已排序，前三个有效匹配自动成为正确的建议。 

这`startswith`检查仍然是必要的，因为二分查找仅保证插入位置，并不能保证乘积实际上与前缀匹配。 

最后，每个建议列表都会附加到结果中。 

## 解决方案```go
package main

import (
	"sort"
	"strings"
)

func suggestedProducts(products []string, searchWord string) [][]string {
	sort.Strings(products)

	result := [][]string{}
	prefix := ""

	for _, ch := range searchWord {
		prefix += string(ch)

		startIndex := sort.SearchStrings(products, prefix)

		suggestions := []string{}

		for i := startIndex; i < len(products) && i < startIndex+3; i++ {
			if strings.HasPrefix(products[i], prefix) {
				suggestions = append(suggestions, products[i])
			}
		}

		result = append(result, suggestions)
	}

	return result
}
```Go 解决方案遵循与 Python 实现相同的策略。 

主要区别在于 Go 没有内置的`bisect_left`等价，所以我们使用`sort.SearchStrings`，它对排序后的切片执行二分搜索。 

前缀检查是使用完成的`strings.HasPrefix`。 

Go 中的切片在附加建议时自然会处理动态增长。

 ## 边缘情况

 ### 没有匹配的产品

 当没有产品与前缀匹配时，会出现一个常见错误。 某些实现可能会不必要地继续扫描或意外地包含不相关的产品。 

例如：```
products = ["apple", "banana"]
searchWord = "cat"
```二分查找找到了插入位置，但是`startswith`检查可防止添加不相关的产品。 该实现正确返回所有前缀的空列表。 

### 少于三个建议

 该问题要求最多返回三个建议，而不是正好三个。 

例如：```
products = ["mouse", "mousepad"]
searchWord = "mouse"
```仅存在两种匹配的产品。 当算法到达数组边界或用完匹配的产品时，算法自然停止。 

### 前缀中途停止匹配

 当早期前缀匹配但后来的前缀不匹配时，会发生另一种棘手的情况。 

例如：```
products = ["hello", "help", "helmet"]
searchWord = "hex"
```前缀`"h"`和`"he"`匹配多种产品，但是`"hex"`没有匹配。 

该实现可以正确处理此问题，因为每个前缀都会执行新的二分搜索并独立验证匹配。 

### 字典顺序

 简单的实现可能会按照原始输入顺序而不是字典顺序收集匹配的产品。 

在开始时对数组进行一次排序可以保证遇到的第一个匹配产品始终是字典顺序最小的有效建议。
