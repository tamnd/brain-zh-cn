[LeetCode 第 1277 题](https://leetcode.com/problems/count-square-submatrices-with-all-ones/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们一个大小为的二进制矩阵`m x n`，其中每个单元格包含`0`或者`1`。 我们必须计算有多少个方子矩阵只包含 1。 

方形子矩阵是矩阵内任何连续的方形区域。 正方形可以有边长`1`,`2`,`3`等等，只要它保持在矩阵边界内。 

例如，单个单元格包含`1`算作有效的大小平方`1 x 1`。 一个`2 x 2`仅当所有四个单元格都为时，区域才算数`1`。 同样，一个`3 x 3`仅当区域内的每个单元都满足时才算数`1`。 

输出是每个可能大小的有效方形子矩阵的总数。 

约束条件很重要：

 -`1 <= m, n <= 300`- 每个单元格要么`0`或者`1`一个`300 x 300`矩阵最多包含`90,000`细胞。 这意味着具有三次或四次复杂度的算法可能会变得太慢。 我们需要一些接近的东西`O(m * n)`。 

一些边缘情况很重要：

 - 应该返回一个完全由零填充的矩阵`0`- 完全由 1 填充的矩阵会产生许多重叠的正方形
 - 单行或单列矩阵只能包含`1 x 1`正方形
 - 具有孤立矩阵的稀疏矩阵不应错误地形成更大的正方形
 - 大型连通区域必须正确计算所有可能的正方形大小

 关键的挑战是有效地确定较大的正方形是否有效，而无需重复扫描其中的每个单元格。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试每一个可能的方格。 

对于矩阵中的每个单元格，我们将其视为潜在正方形的左上角。 然后我们尝试适合矩阵内部的所有可能的边长。 对于每个候选方格，我们扫描该方格内的所有单元格以验证每个值是否是`1`。 

如果所有单元格都是 1，我们就增加答案。 

这种方法是正确的，因为它明确地检查每个可能的方形子矩阵。 然而，它的效率很低，因为验证每个方块都需要重复扫描其内容。 

假设矩阵维度为`m x n`。 大约有`O(m * n * min(m, n))`可能的正方形，并验证每个可能需要`O(k^2)`边长时间`k`。 在最坏的情况下，复杂度大致变为`O(m * n * min(m, n)^3)`，对于高达以下的矩阵来说太慢了`300 x 300`。 

### 动态规划洞察

 关键的观察是，如果我们已经知道以相邻单元格结尾的最大正方形，我们可以有效地确定以当前单元格结尾的最大正方形。 

定义：`dp[i][j]`= 右下角位于的最大正方形的大小`(i, j)`。 

如果`matrix[i][j] == 0`，那么没有正方形可以在那里结束，所以：```
dp[i][j] = 0
```如果`matrix[i][j] == 1`，则正方形大小取决于三个相邻单元格：

 - 顶部：`dp[i-1][j]`- 左边：`dp[i][j-1]`- 左上角对角线：`dp[i-1][j-1]`当前的方格只有在所有三个邻近区域都能够支撑的情况下才能扩展。 所以：$dp[i][j]=1+\min(dp[i-1][j],dp[i][j-1],dp[i-1][j-1])$这是有效的，因为最小的相邻方块限制了当前方块的大小。 

每一个`dp[i][j]`value 直接告诉我们有多少个有效方块在该单元格处结束：

 - 如果`dp[i][j] = 1`,有一个正方形
 - 如果`dp[i][j] = 2`, 有两个正方形
 - 如果`dp[i][j] = 3`,共有三个正方形

 所以我们简单地将所有 DP 值相加。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * 分钟(m, n)^3) | O(1) | O(1) | 明确检查每个可能的方块 |
 | 最优动态规划| O(m * n) | O(m * n) | 重用以前的计算来有效地构建更大的正方形 |

 ## 算法演练

 1. 创建一个与输入矩阵维度相同的DP表。 

每个`dp[i][j]`存储以单元格结尾的最大正方形的大小`(i, j)`。 
2. 初始化变量`total_squares = 0`。 

该变量累加有效方形子矩阵的总数。 
3. 逐行、逐列遍历矩阵。 

在每个单元格处，确定一个正方形是否可以在那里结束。 
4. 处理包含以下内容的单元格`0`。 

如果`matrix[i][j] == 0`，那么没有任何正方形可以在这个位置结束。 放：```
dp[i][j] = 0
```5. 单独处理边界单元。 

如果细胞含有`1`位于第一行或第一列，最大可能的正方形的边长`1`。```
dp[i][j] = 1
```6. 处理内部细胞。 

对于不在边界上的单元格，如果`matrix[i][j] == 1`，计算：$dp[i][j]=1+\min(dp[i-1][j],dp[i][j-1],dp[i-1][j-1])$最小的相邻正方形决定了我们是否可以扩展到更大的正方形。 
7. 添加`dp[i][j]`到答案。 

如果`dp[i][j] = k`，那么正好有`k`有效方格结束于`(i, j)`。 
8. 继续，直到处理完所有细胞。 
9. 返回`total_squares`。 

### 为什么它有效

 DP 状态保持一个重要的不变量：`dp[i][j]`始终等于结束于的最大全一正方形的边长`(i, j)`。 

一个正方形的边长`k`仅当满足以下条件时才能存在：

 - 顶邻居至少支持`k-1`- 左邻居至少支持`k-1`- 对角邻居至少支持`k-1`如果其中任何一个较小，则正方形无法进一步扩大。 采取最小保证正确性。 

由于每个有效方格都有唯一的右下角，因此对所有 DP 值求和只会对每个方格计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def countSquares(self, matrix: List[List[int]]) -> int:
        rows = len(matrix)
        cols = len(matrix[0])

        dp = [[0] * cols for _ in range(rows)]
        total_squares = 0

        for row in range(rows):
            for col in range(cols):

                if matrix[row][col] == 0:
                    dp[row][col] = 0

                elif row == 0 or col == 0:
                    dp[row][col] = 1

                else:
                    dp[row][col] = 1 + min(
                        dp[row - 1][col],
                        dp[row][col - 1],
                        dp[row - 1][col - 1]
                    )

                total_squares += dp[row][col]

        return total_squares
```实现首先确定矩阵维度。 分配一个大小相等的 DP 表，其中每个条目存储以该位置结束的最大方格。 

嵌套循环只对每个单元格迭代一次。 

如果当前单元格包含`0`，没有方格可以终止于此处，因此 DP 值保持不变`0`。 

如果当前单元格位于顶行或最左边的列并且包含`1`，最大可能的正方形的大小`1`。 

对于所有其他包含`1`，该解计算顶部、左侧和对角邻居中的最小值，然后添加`1`。 这有效地确定了最大的可扩展正方形。 

计算每个 DP 值后，它会立即添加到运行总计中，因为每个 DP 值代表以该单元格结尾的有效方格的数量。 

最后，该函数返回累计计数。 

## 解决方案```go
func countSquares(matrix [][]int) int {
    rows := len(matrix)
    cols := len(matrix[0])

    dp := make([][]int, rows)

    for i := 0; i < rows; i++ {
        dp[i] = make([]int, cols)
    }

    totalSquares := 0

    for row := 0; row < rows; row++ {
        for col := 0; col < cols; col++ {

            if matrix[row][col] == 0 {
                dp[row][col] = 0

            } else if row == 0 || col == 0 {
                dp[row][col] = 1

            } else {
                dp[row][col] = 1 + min(
                    dp[row-1][col],
                    min(
                        dp[row][col-1],
                        dp[row-1][col-1],
                    ),
                )
            }

            totalSquares += dp[row][col]
        }
    }

    return totalSquares
}

func min(a int, b int) int {
    if a < b {
        return a
    }

    return b
}
```Go 实现遵循与 Python 版本相同的 DP 逻辑。 由于 Go 没有提供内置整数`min`对于此用例，手动定义辅助函数。 

DP 表是使用切片的切片创建的。 每行都是独立初始化的。 

Go 整数足以解决这个问题，因为最大可能的答案完全在 32 位整数范围内。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m * n) | 每个单元仅被处理一次 |
 | 空间| O(m * n) | DP 表每个单元存储一个值 |

 该算法对每个矩阵单元执行恒定的工作。 不会发生嵌套重新扫描，这使得运行时与单元格数量呈线性关系。 

DP 表需要与矩阵大小成正比的额外存储空间。 虽然空间优化`O(n)`如果可能的话，完整的表格可以提高可读性和清晰度。

 ## 边缘情况

 一种重要的边缘情况是仅包含零的矩阵。 如果不仔细验证每个单元格，幼稚的实现可能会意外地计算无效方块。 在此实现中，任何包含`0`立即产生`dp[i][j] = 0`，确保没有方块可以在那里结束。 

另一个重要的情况是单行或单列矩阵。 较大的正方形需要高度和宽度，因此只需`1 x 1`正方形是可能的。 该实现自然地处理了这个问题，因为边界单元被分配了值`1`当它们包含 1 时，并且不会发生更大的扩展。 

第三种关键边缘情况涉及用零分隔的孤立情况。 例如：```
[
  [1,0,1],
  [0,1,0],
  [1,0,1]
]
```有缺陷的实现可能会错误地将附近的方块组合成更大的方块。 DP 转换可以防止这种情况发生，因为扩展一个正方形需要所有三个相邻的 DP 状态都支持扩展。 一个零会立即阻碍增长。 

第四种微妙的情况发生在大的完全连接的区域中。 在这些情况下，重叠方块的数量迅速增加。 DP 方法可以有效地处理此问题，因为每个单元计算都会重用先前计算的信息，而不是重复重新扫描整个子矩阵。
