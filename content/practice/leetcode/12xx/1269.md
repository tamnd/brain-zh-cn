[LeetCode 第 1269 题](https://leetcode.com/problems/number-of-ways-to-stay-in-the-same-place-after-some-steps/)

 **难度：** 🔴难
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算一个指针可以有多少种不同的方式回到索引处`0`准确服用后`steps`在长度数组内移动`arrLen`。 

我们从位于索引处的指针开始`0`。 对于每一步，我们都有三种可能的操作：

 1. 向左移动一个位置。 
2. 向右移动一个位置。 
3. 留在当前位置。 

然而，有一个重要的限制：指针永远不能离开数组的边界。 这意味着我们不能从索引向左移动`0`，并且我们不能从索引向右移动`arrLen - 1`。 

输入由两个整数组成：

 -`steps`，它准确地告诉我们必须进行多少步操作。 
-`arrLen`，它表示数组的大小。 

输出是导致指针返回索引处的不同有效移动序列的数量`0`恰好在之后`steps`移动。 

由于答案可能变得非常大，我们返回结果模`10^9 + 7`。 

这些限制揭示了一个重要的挑战：

 -`1 <= steps <= 500`-`1 <= arrLen <= 10^6`非常大的上限`arrLen`这表明我们无法负担与整个数组大小成比例的算法。 然而，`steps`只是`500`，这暗示数组的可达区域实际上比`arrLen`。 

一个重要的观察是，之后`steps`移动时，指针永远不能比`steps`远离指数的仓位`0`。 事实上，因为我们最终必须回到`0`，超越`steps // 2 + 1`职位毫无意义。 这极大地减少了有效搜索空间。 

一些边缘情况很重要：

 - 如果`arrLen = 1`，指针不能向左或向右移动，因此唯一有效的操作是每一步都保持在原位。 
- 如果`steps = 1`，保持索引不变的唯一方法`0`就是留下来。 
- 什么时候`arrLen`是巨大的，例如`10^6`，我们必须避免创建该大小的 DP 数组，因为大多数位置是无法到达的。 
- 指针靠近边界的情况需要小心处理以避免无效索引。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是递归地探索每个可能的移动序列。 在每一步中，我们都会分为三种可能性：

 - 向左移动
 - 向右移动
 - 留下来

 我们继续这个递归直到恰好`steps`已采取行动。 如果指针在索引处结束`0`，我们将该路径视为有效。 

这种方法是正确的，因为它详尽地考虑了每个可能的有效操作序列。 

然而，运行时变得非常昂贵。 由于每个步骤最多引入三个选择，因此路径总数呈指数增长。 

时间复杂度大致变为`O(3^steps)`，这是不可能的`steps = 500`。 

我们可以使用记忆来稍微改进暴力，因为许多状态会重复。 具体来说，同样`(remaining_steps, position)`状态可以被计算多次。 

### 最佳解决方案的关键见解

 该问题具有重叠的子问题和最优子结构，使其成为动态规划的有力候选者。 

让我们定义：`dp[i][j] = number of ways to be at index j after i steps`从任何位置`j`，我们可以通过三种方式到达那里：

 - 入住`j`- 向右移动`j - 1`- 向左移动`j + 1`因此：`dp[i][j] = dp[i-1][j] + dp[i-1][j-1] + dp[i-1][j+1]`我们还注意到一个重要的优化：

 我们永远不需要考虑大于以下的头寸：`min(arrLen - 1, steps // 2 + 1)`为什么？ 

因为如果我们向右移动太远，我们将没有足够的剩余步数返回`0`。 

这种优化极大地减少了状态空间。 

我们可以使用滚动数组来代替完整的 2D DP 表，因为每一行仅依赖于前一行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(3^steps)`|`O(steps)`| 递归尝试每个运动序列 |
 | 最优动态规划|`O(steps × min(arrLen, steps))`|`O(min(arrLen, steps))`| 使用滚动 DP 和可达状态剪枝 |

 ## 算法演练

 ### 最优动态规划算法

 1. **确定最大可达位置**

 我们只关心能够切实贡献有效指数回报的指数`0`。 

我们计算：```
max_position = min(arrLen - 1, steps // 2 + 1)
```这可以避免在无法访问的索引上浪费内存。 
2. **初始化DP数组**

 我们创建一个 DP 数组，其中：```
dp[position]
```存储在当前步数之后到达该位置的方法数。 

最初：```
dp[0] = 1
```因为我们从索引开始`0`。 
3. **迭代每个步骤**

 对于每一步，创建一个名为的新数组`next_dp`。 

该数组表示额外移动一次后到达每个位置的方式数。 
4. **更新转换**

 对于每个可达到的位置`pos`:

 - 留在原地：```
next_dp[pos] += dp[pos]
```- 向左移动：```
next_dp[pos - 1] += dp[pos]
```- 向右移动：```
next_dp[pos + 1] += dp[pos]
```我们只执行在界限内的动作。 
5. **应用模运算**

 由于值增长得非常快，因此每次更新都以模数执行：```
10^9 + 7
```6. **更换旧的 DP 阵列**

 处理完一步后：```
dp = next_dp
```7. **返回答案**

 恰好之后`steps`迭代，返回：```
dp[0]
```### 为什么它有效

 该算法在处理后保持了不变量`i`步骤，`dp[j]`代表该位置的有效站立方式的确切数量`j`。 

通过递归关系，每个合法动作都被精确地计算一次。 由于转换仅来自前一步，并且由于排除了无效边界移动，因此每个计数的路径都是有效的，并且每个有效路径都会被计数。 

因此，在处理完所有步骤后，`dp[0]`包含精确返回索引的方法数`0`。 

## Python 解决方案```python
class Solution:
    def numWays(self, steps: int, arrLen: int) -> int:
        MOD = 10**9 + 7

        max_position = min(arrLen - 1, steps // 2 + 1)

        dp = [0] * (max_position + 1)
        dp[0] = 1

        for _ in range(steps):
            next_dp = [0] * (max_position + 1)

            for pos in range(max_position + 1):
                ways = dp[pos]

                if ways == 0:
                    continue

                # Stay
                next_dp[pos] = (next_dp[pos] + ways) % MOD

                # Move left
                if pos > 0:
                    next_dp[pos - 1] = (
                        next_dp[pos - 1] + ways
                    ) % MOD

                # Move right
                if pos < max_position:
                    next_dp[pos + 1] = (
                        next_dp[pos + 1] + ways
                    ) % MOD

            dp = next_dp

        return dp[0]
```实现首先计算可能重要的有效最大位置。 此优化可防止按比例分配内存`arrLen`，可能大到一百万。 

这`dp`数组存储在当前步数之后到达每个位置的方式数。 最初，只有位置`0`是可达的。 

对于每一步，我们构建`next_dp`，它代表下一层状态。 对于每个位置，我们传播其对停留、向左移动和向右移动的贡献，同时尊重边界。 

模运算确保数字保持可管理性并满足问题要求。 

在所有迭代结束时，`dp[0]`掌握着最终的答案。 

## 解决方案```go
func numWays(steps int, arrLen int) int {
	const mod = 1000000007

	maxPosition := steps/2 + 1
	if arrLen-1 < maxPosition {
		maxPosition = arrLen - 1
	}

	dp := make([]int, maxPosition+1)
	dp[0] = 1

	for step := 0; step < steps; step++ {
		nextDP := make([]int, maxPosition+1)

		for pos := 0; pos <= maxPosition; pos++ {
			ways := dp[pos]

			if ways == 0 {
				continue
			}

			// Stay
			nextDP[pos] = (nextDP[pos] + ways) % mod

			// Move left
			if pos > 0 {
				nextDP[pos-1] = (nextDP[pos-1] + ways) % mod
			}

			// Move right
			if pos < maxPosition {
				nextDP[pos+1] = (nextDP[pos+1] + ways) % mod
			}
		}

		dp = nextDP
	}

	return dp[0]
}
```Go 的实现与 Python 的逻辑非常相似。 切片用于动态数组，并且在每次更新期间执行整数模运算。 

与 Python 不同，Go 使用固定整数类型，但整数溢出不是这里的问题，因为每个操作都会减少模数`10^9 + 7`。 

滚动 DP 优化是相同的，这意味着空间使用仍然高效。

 ## 边缘情况

 ### 边缘情况 1：`arrLen = 1`当数组长度为1时，索引`0`是唯一有效的位置。 指针无法向左或向右移动。 

有缺陷的实现可能仍会尝试访问相邻位置并产生索引错误。 

这个实现可以自然地处理它，因为：```
max_position = 0
```DP数组只有一个元素，并且只有“stay”转换有效。 

### 边缘情况 2：非常大`arrLen`该约束允许：```
arrLen = 10^6
```使用完整数组大小的简单 DP 会浪费大量内存和时间。 

优化：```
min(arrLen - 1, steps // 2 + 1)
```确保我们只考虑实际可以达到的职位。 

自从`steps <= 500`，即使在`arrLen`是巨大的。 

### 边缘情况 3：步骤少

 当`steps`非常小，比如`1`，指针几乎没有灵活性。 

例如：```
steps = 1
arrLen = 2
```留在索引的唯一有效方法`0`是：```
Stay
```DP 转换正确地产生了这个，因为向右移动会将指针留在索引处`1`，这对最终答案没有贡献。 

### 边缘情况 4：边界位置

 每当指针位于索引处时`0`，左移无效。 同样，从最后一个有效位置向右移动也是无效的。 

实现明确检查：```
if pos > 0
```和```
if pos < max_position
```以防止越界转换。 这保证了数组边界附近的正确性。
