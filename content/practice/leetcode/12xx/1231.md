[LeetCode 第 1231 题](https://leetcode.com/problems/divide-chocolate/)

 **难度：** 🔴难
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们将巧克力棒分成`k + 1`连续的碎片，这样我们就可以最大化这些碎片中的最小总甜度。 输入数组中的每个元素`sweetness`代表单个块的甜度。 我们的目标是找到一种最佳方法`k`切得尽可能大，这样当我们吃甜度最小的那块时，我们得到的最小块就尽可能大。 

换句话说，如果我们想象与人分享巧克力`k`朋友们，我们希望最差的一块（我们得到的那块）尽可能好。 输出是一个整数，表示我们可以获得的最小块的最大可能总甜度。 

约束表明数组最多可达`10^4`长度，每块的甜度可达`10^5`。 这排除了尝试所有可能的削减的任何暴力解决方案，因为这将是组合爆炸性的。 重要的边缘情况包括`k = 0`（我们吃掉整块巧克力）什么时候`k = sweetness.length - 1`（每一块都变成一块）。 该问题保证所有值都是正的，因此我们不必处理零或负的甜度。 

## 方法

 蛮力方法需要尝试各种组合`k`切割并计算所得碎片中的最小总甜度。 对于每个组合，我们将跟踪最小的部分，然后在所有组合中取最大的部分。 这是正确的，因为它显式地检查了所有可能性，但由于组合爆炸，它是不可行的 - 对于长度的数组`n`和`k`削减，组合数量大致为`C(n-1, k)`，对于`n = 10^4`。 

最佳方法利用了以下关键见解：这是一个具有单调属性的**划分问题**：如果我们能够实现的最小甜度`x`每件，我们还可以实现任何小于`x`。 这允许我们对最小甜度值使用**二分搜索**。 对于每个候选值`mid`，我们模拟贪婪地切割巧克力，每当累积的甜度达到或超过时就形成新的一块`mid`。 如果我们至少可以做到`k + 1`以此方式分割，然后`mid`是可行的； 否则，它太高了。 通过根据可行性调整二分搜索边界，我们找到了可实现的最大最小甜度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n-1, k) * n) | O(C(n-1, k) * n) | O(n) | 显式尝试所有可能的 k 切割，对于大 n | 不可行
 | 最佳| O(n log S) | O(n log S) | O(1) | O(1) | 最小甜度二分搜索`S`贪心验证|

 这里，`S`是数组中所有甜度值的总和。 

## 算法演练

 1. 初始化二分查找的搜索空间。 让`left`是可能的最小片甜度，即`min(sweetness)`或 1，并且`right`是最大可能的片甜度，即`sum(sweetness) // (k + 1)`因为我们得到的甜度不能超过所有部分的总甜度。 
2. 虽然`left <= right`, 计算`mid = (left + right) // 2`。 这代表了每块候选的最小甜度。 
3. 模拟贪婪切割：迭代数组，积累甜度。 当累计达到或超过`mid`，将其算作一块并重置运行总计。 
4. 迭代结束后，检查是否至少可以得到`k + 1`件。 如果是，则意味着`mid`是可行的，所以移动`left`到`mid + 1`寻找更高的可行值。 如果没有，请移动`right`到`mid - 1`寻找更小的可行值。 
5. 继续，直到搜索空间耗尽。 最大可行`mid`就是答案。 

为什么它有效：关键的不变量是最小甜度的可行性是单调的：如果可以实现甜度值，则所有较小的值也可以实现。 这使得二分搜索能够有效地收敛于最大可能的最小甜度。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximizeSweetness(self, sweetness: List[int], k: int) -> int:
        def can_divide(min_sweet: int) -> bool:
            count, curr_sum = 0, 0
            for s in sweetness:
                curr_sum += s
                if curr_sum >= min_sweet:
                    count += 1
                    curr_sum = 0
            return count >= k + 1

        left, right = min(sweetness), sum(sweetness) // (k + 1)
        answer = left

        while left <= right:
            mid = (left + right) // 2
            if can_divide(mid):
                answer = mid
                left = mid + 1
            else:
                right = mid - 1

        return answer
```在Python解决方案中，我们定义了一个辅助函数`can_divide`模拟贪婪地切巧克力。 我们对可能的最小甜度值进行二分搜索。 每次迭代更新`left`或者`right`基于可行性。 这`answer`变量跟踪迄今为止发现的最大可行的最小甜度。 

## 解决方案```go
func maximizeSweetness(sweetness []int, k int) int {
    canDivide := func(minSweet int) bool {
        count, currSum := 0, 0
        for _, s := range sweetness {
            currSum += s
            if currSum >= minSweet {
                count++
                currSum = 0
            }
        }
        return count >= k+1
    }

    left, right := 1, 0
    for _, s := range sweetness {
        right += s
    }
    right /= (k + 1)
    answer := 1

    for left <= right {
        mid := (left + right) / 2
        if canDivide(mid) {
            answer = mid
            left = mid + 1
        } else {
            right = mid - 1
        }
    }

    return answer
}
```Go 解决方案反映了 Python 解决方案。 我们定义一个内联函数`canDivide`为了可行性。 Go 需要仔细处理整数除法并初始化`right`总和除以`k + 1`。 计算件数的贪婪逻辑是相同的。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log S) | O(n log S) | 每次二分搜索迭代都需要 O(n) 进行贪婪切割，二分搜索有 O(log S) 次迭代，其中 S 是 sum(sweetness) |

 二分搜索确保了效率，避免了对所有可能的削减的暴力探索。
