 ## 解决方案

 ## 问题理解

 这个问题要求我们生成一份完整的报告，显示每个学生参加每个科目考试的次数。 

我们得到三个数据库表：

 -`Students`，存储每个学生的 ID 和姓名。 
-`Subjects`，它存储学校提供的所有科目。 
-`Examinations`，记录每个考试出勤条目。 

重要的细节是`Examinations`表可能包含重复的行。 每行代表一个出勤实例，而不是唯一的学生-科目对。 如果一名学生在同一科目中出现多次，则意味着该学生多次参加该考试。 

输出必须包含：

 - 每个学生
 - 每个科目
 - 学生参加该科目考试的次数

 这意味着我们必须生成所有可能的学生-科目组合，即使学生从未参加过考试。 在这些情况下，出席人数应为`0`。 

最终结果必须按以下顺序排序：

 1.`student_id`2.`subject_name`主要的挑战是`Examinations`表不包含所有组合。 有些学生可能永远不会参加某些考试，或者可能根本不会参加任何考试。 因此，我们不能仅仅依赖于现有的行`Examinations`。 

该问题保证：

 -`student_id`是独一无二的`Students`-`subject_name`是独一无二的`Subjects`-`Examinations`可能包含重复项
 - 每个学生在概念上都会选修每一门科目，即使出勤率为零

 一个重要的边缘情况是根本没有考试的学生。 另一个是没人参加的科目。 第三个是同一学生和科目的重复出勤记录。 任何正确的解决方案仍然必须输出所有学生-科目对并正确计算重复项。 

## 方法

 ### 蛮力方法

 强力解决方案将生成每个可能的学生-受试者对，然后对于每一对，扫描整个`Examinations`表来计算匹配行数。 

例如：

 - 选择一名学生
 - 选择一个主题
 - 迭代所有检查行
 - 计算有多少行与学生和主题匹配
 - 对每个可能的组合重复

 这种方法是正确的，因为每一对都根据所有出勤记录进行明确检查。 

然而，由于检查台被重复扫描，因此效率低下。 如果：

-`S`= 学生人数
 -`C`= 科目数
 -`E`= 检查记录数

 那么总复杂度就变成了`O(S × C × E)`。 

随着数据的增长，重复扫描检查表变得不必要的昂贵。 

### 最佳方法

 关键的见解是，一旦使用聚合，就可以预先计算检查计数。 

而不是扫描`Examinations`重复表，我们可以：

 1. 使用 a 生成所有学生-科目组合`CROSS JOIN`2. 使用聚合检查计数`GROUP BY`3. 使用 a 组合两个结果`LEFT JOIN`这很有效，因为：

 -`CROSS JOIN`产生每个所需的对
 -`GROUP BY`计算一次出勤计数
 -`LEFT JOIN`确保丢失的匹配项变为`NULL`-`COALESCE`皈依者`NULL`到`0`这避免了重复扫描并以关系数据库友好的方式直接生成结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(S × C × E) | O(1) | O(1) | 重复扫描每对检查 |
 | 最佳 | O(S × C + E) | O(E) | 高效使用聚合和连接 |

 ## 算法演练

 1. 从`Students`表和`Subjects`桌子。 

即使不存在考试记录，我们也需要每一种可能的学生与科目组合。 一个`CROSS JOIN`正是创建了这个笛卡尔积。 
2. 创建所有可能的学生-科目对。 

如果有 4 个学生和 3 个科目，结果将包含 12 行。 每一行代表一个所需的输出行。 
3. 汇总`Examinations`桌子。 

使用`GROUP BY student_id, subject_name`并计算：```
COUNT(*)
```这给出了每对现有的出席人数。 
4. 将生成的组合与聚合计数连接起来。 

使用一个`LEFT JOIN`因为某些学生-科目组合可能不存在于汇总考试结果中。 
5. 将缺失的计数替换为零。 

如果一对没有匹配的检查行，则连接计数变为`NULL`。 使用：```
COALESCE(count, 0)
```将其转换为`0`。 
6. 对最终结果进行排序。 

订购方式：```
student_id, subject_name
```根据问题陈述的要求。 

### 为什么它有效

 该算法之所以有效，是因为`CROSS JOIN`保证每个所需的学生-科目组合在中间结果中仅存在一次。 分组考试计数提供了现有对的出勤记录的确切数量。 这`LEFT JOIN`保留所有组合，包括那些没有出勤记录的组合，以及`COALESCE`正确地将缺失值转换为零。 因此，每个所需的输出行都会以正确的出勤计数生成。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT
    s.student_id,
    s.student_name,
    sub.subject_name,
    COALESCE(e.attended_exams, 0) AS attended_exams
FROM Students s
CROSS JOIN Subjects sub
LEFT JOIN (
    SELECT
        student_id,
        subject_name,
        COUNT(*) AS attended_exams
    FROM Examinations
    GROUP BY student_id, subject_name
) e
ON s.student_id = e.student_id
AND sub.subject_name = e.subject_name
ORDER BY s.student_id, sub.subject_name;
```查询首先使用一个生成每个可能的学生-主题组合`CROSS JOIN`。 这保证了即使是缺失的出勤对也会出现在最终结果中。 

接下来，子查询聚合`Examinations`桌子。 这`GROUP BY`子句按两者对行进行分组`student_id`和`subject_name`， 尽管`COUNT(*)`计算每次考试参加的次数。 

一个`LEFT JOIN`然后将完整的组合列表与聚合计数相结合。 由于某些组合可能不存在于检查数据中，因此连接可以产生`NULL`价值观。 

最后，`COALESCE`转换那些`NULL`值转化为`0`，并将结果按照要求的顺序进行排序。

 ## 边缘情况

 ### 无考试记录的学生

 学生可能永远不会出现在`Examinations`桌子。 天真的内部联接会将该学生从结果中完全删除。 该实现首先生成所有学生-科目组合，然后使用`LEFT JOIN`。 缺失的检查行变为`NULL`，它们被转换为`0`。 

### 重复的考试条目

 的`Examinations`表明确允许重复。 这意味着同一对学生-科目可能会出现多次。 有缺陷的实现可能会意外使用`DISTINCT`或仅计算唯一对。 使用`COUNT(*)`正确分组后统计每条考勤记录。 

### 从来没有人参加过的科目

 有些科目可能在整个表中的考试记录为零。 由于解决方案是从学生和科目的笛卡尔积开始的，而不是从考试表本身开始，因此每个科目仍然会为每个学生显示，计数为`0`。 

### 单身学生或单一科目

 当其中一张表仅包含一行时，笛卡尔积仍然表现正确。 查询自然会生成所有所需的组合，无需任何特殊处理。 

### 订购要求

 SQL 查询没有`ORDER BY`不保证输出顺序。 该实现显式排序`student_id`和`subject_name`所以结果总是符合所需的格式。
