[LeetCode 第 1224 题](https://leetcode.com/problems/maximum-equal-Frequency/)

 **难度：** 🔴难
 **主题：** 数组、哈希表

 ## 解决方案

 ## 问题理解

 问题给出了一个数组`nums`由正整数组成。 我们必须找到数组的最长前缀，以便从该前缀中删除一个元素后，每个剩余的数字出现相同的次数。 

前缀表示从索引开始的子数组`0`并以某个索引结束`i`。 我们可以自由选择任何前缀长度，并且我们想要尽可能大的长度。 

重要的细节是我们只删除一个元素，而不是一个不同的值。 我们删除某个数字的单个出现。 删除后，前缀中仍然存在的所有剩余号码必须具有相同的频率。 

例如，考虑前缀：```
[2,2,1,1,5,3,3]
```频率是：```
2 -> 2
1 -> 2
5 -> 1
3 -> 2
```如果我们删除单个`5`，其余频率变为：```
2 -> 2
1 -> 2
3 -> 2
```所有剩余的数字现在恰好出现两次，因此该前缀有效。 

限制条件很大：

 -`nums.length`可以达到`10^5`- 值也可以高达`10^5`这些约束立即排除了对每个前缀进行昂贵的重新计算。 任何比粗略更糟糕的解决方案`O(n log n)`可能会超时。 预期的解决方案是线性时间。 

一些边缘情况很重要：

 - 每个数字出现一次的前缀始终有效，因为删除任何一个元素都会使所有剩余频率相等。 
- 仅具有一个不同数字的前缀始终有效，因为删除一个匹配项仍然会留下有效的配置。 
- 有效的前缀可能需要删除频率最高的元素。 
- 有效的前缀可能需要删除唯一具有频率的元素`1`。 
- 即使频率已经相等，我们也必须恰好删除一个元素。 

挑战在于，在每个前缀的恒定时间内识别当前频率分布在一次删除后是否可以变得均匀。 

## 方法

 ### 蛮力方法

 暴力解决方案将检查数组的每个可能的前缀。 

对于每个前缀：

 1. 统计每个数字出现的频率。 
2. 尝试删除每个不同数字的一次出现。 
3. 每次假设删除后，检查所有剩余频率是否相等。 
4. 如果任何删除有效，则前缀有效。 

这种方法是正确的，因为它直接模拟了问题定义。 对于每个前缀，它都会详尽地测试所有可能的删除并验证生成的频率。 

然而，它太慢了。 

假设数组长度为`n`。 有`O(n)`前缀。 对于每个前缀，我们可能有`O(n)`不同的数字。 对于每次删除尝试，我们可能会再次扫描频率以验证相等性。 

总复杂度可以轻松达到`O(n^2)`或者更糟，这是不可行的`n = 10^5`。 

### 最佳方法

 关键的见解是我们不需要完全重新计算每个前缀的频率。 相反，我们可以增量地维护两条信息：

 1.`count[num]`- 每个数字出现的次数。 
2.`freq[f]`- 当前有多少个数字准确出现`f`次。 

第二种结构是关键的优化。 

例如：```
count:
1 -> 2
2 -> 2
3 -> 1

freq:
1 -> 1
2 -> 2
```这意味着：

 - 一个数字出现一次
 - 两个数字出现两次

 使用这些汇总统计数据，我们可以识别唯一可能的有效模式。 

如果满足以下条件之一，则前缀有效：

 1. 每个数字出现一次。 
2. 恰好有一个数字出现一次，所有其他数字都出现相同的较高频率。 
3. 恰好有一个数字的出现频率比所有其他数字大一。 

在处理一次数组时，可以在恒定时间内检查这些条件。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n2) 到 O(n3) | O(n) | 重新计算并验证每个前缀的频率 |
 | 最佳| O(n) | O(n) | 增量维护频率计数 |

 ## 算法演练

 1. 创建两个哈希图：

 -`count[num]`存储每个数字出现的次数。 
-`freq[f]`存储当前有多少个数字出现频率`f`。 
2.初始化：

 -`max_frequency = 0`-`best = 0`

`max_frequency`跟踪当前前缀中看到的最大频率。 
3. 一次遍历数组中的一个元素。 
4. 对于当前号码：

 - 设其旧频率为`old_freq`。 
- 减少`freq[old_freq]`因为这个数字即将移动到更高的频率。 
- 增加其计数`count`。 
- 设新频率为`new_freq`。 
- 增加`freq[new_freq]`。 
5. 更新`max_frequency`如果需要的话。 
6.设：

 -`length = current index + 1`我们现在测试在删除一个元素后当前前缀是否可以变得统一。 
7. 检查第一个有效模式：

 - 每个数字只出现一次。 

这意味着：```
max_frequency == 1
```例子：```
[1,2,3,4]
```删除任何元素都会留下所有剩余的数字与频率`1`。 
8. 检查第二个有效模式：

 - 一个数字出现一次。 
- 所有其他数字均出现`max_frequency`次。 

这个条件是：```
freq[1] == 1
and
freq[max_frequency] * max_frequency + 1 == length
```例子：```
[1,1,2,2,3]
```频率：```
1 -> 2
2 -> 2
3 -> 1
```去除`3`使所有剩余频率相等。 
9. 检查第三个有效模式：

 - 恰好有一个数字有频率`max_frequency`。 
- 所有其他数字都有频率`max_frequency - 1`。 

这个条件是：```
freq[max_frequency] == 1
and
freq[max_frequency - 1] * (max_frequency - 1) + max_frequency == length
```例子：```
[1,1,1,2,2,2,3,3,3,4]
```频率：```
1 -> 3
2 -> 3
3 -> 3
4 -> 1
```从频率最高的数字中删除一次出现可以恢复一致性。 
10. 如果任何条件为真：

 - 更新`best = length`。 
11. 继续直到数组末尾。 
12. 返回`best`。 

### 为什么它有效

 在任何前缀处，在删除一个元素后，只有非常小的一组频率分布可以变得完全均匀。 

要么：

 - 所有频率都已经`1`,
 - 一个值出现的次数太少，
 - 或者一个值出现次数过多。 

该算法直接使用跟踪频率分布`freq`，允许在恒定时间内验证每个前缀的这些模式。 由于每种可能的有效配置都必须与这些情况之一匹配，因此该算法是正确的。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def maxEqualFreq(self, nums: List[int]) -> int:
        count = defaultdict(int)
        freq = defaultdict(int)

        max_frequency = 0
        best = 0

        for i, num in enumerate(nums):
            old_freq = count[num]

            if old_freq > 0:
                freq[old_freq] -= 1

            count[num] += 1
            new_freq = count[num]

            freq[new_freq] += 1

            max_frequency = max(max_frequency, new_freq)

            length = i + 1

            # Case 1:
            # Every number appears exactly once
            if max_frequency == 1:
                best = length

            # Case 2:
            # One number appears once,
            # all others appear max_frequency times
            elif (
                freq[1] == 1
                and freq[max_frequency] * max_frequency + 1 == length
            ):
                best = length

            # Case 3:
            # One number appears max_frequency times,
            # all others appear max_frequency - 1 times
            elif (
                freq[max_frequency] == 1
                and (
                    freq[max_frequency - 1] * (max_frequency - 1)
                    + max_frequency
                    == length
                )
            ):
                best = length

        return best
```该实现紧密遵循前面描述的算法。`count`跟踪每个数字的频率。 每当处理一个数字时，其旧频率桶就会递减，而新频率桶就会递增。`freq`是关键的优化。 它不是重复扫描所有计数，而是告诉我们当前有多少数字共享相同的频率。`max_frequency`跟踪当前前缀中的最大频率。 这使得算法能够有效地评估三种有效配置。 

这三个条件块完全对应于三种有效的结构模式：

 - 所有频率等于`1`- 一个单例值
 - 一个值比其他值恰好出现一次

 每当满足这些条件之一时，当前前缀长度就成为候选答案。 

由于每个元素都被处理一次并且每次更新都是恒定时间，因此整个算法以线性时间运行。 

## 解决方案```go
package main

func maxEqualFreq(nums []int) int {
	count := make(map[int]int)
	freq := make(map[int]int)

	maxFrequency := 0
	best := 0

	for i, num := range nums {
		oldFreq := count[num]

		if oldFreq > 0 {
			freq[oldFreq]--
		}

		count[num]++
		newFreq := count[num]

		freq[newFreq]++

		if newFreq > maxFrequency {
			maxFrequency = newFreq
		}

		length := i + 1

		// Case 1:
		// Every number appears exactly once
		if maxFrequency == 1 {
			best = length

		} else if freq[1] == 1 &&
			freq[maxFrequency]*maxFrequency+1 == length {

			// Case 2:
			// One number appears once,
			// all others appear maxFrequency times
			best = length

		} else if freq[maxFrequency] == 1 &&
			freq[maxFrequency-1]*(maxFrequency-1)+maxFrequency == length {

			// Case 3:
			// One number appears maxFrequency times,
			// all others appear maxFrequency - 1 times
			best = length
		}
	}

	return best
}
```Go 实现几乎完全反映了 Python 逻辑。 

Go 使用内置地图而不是`defaultdict`，所以丢失的键自然会返回`0`，它非常适合频率计数。 

所有整数运算都保持在安全范围内，因为最大数组长度仅为`10^5`。 

维护频率桶和验证三种结构模式的逻辑与Python解决方案相同。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个元素都通过恒定时间哈希映射更新处理一次 |
 | 空间| O(n) | 频率图最多可存储 O(n) 个不同值 |

 ## 边缘情况

 当每个数字都只出现一次时，就会出现一种重要的边缘情况。 例如：```
[1,2,3,4]
```天真的实现可能会错误地认为不需要删除。 然而，该问题需要恰好删除一个元素。 删除任何元素后，所有剩余的数字仍然只出现一次。 该实现使用以下条件处理此问题：```
max_frequency == 1
```当只有一个不同的值时，会出现另一种重要的边缘情况。 例如：```
[5,5,5,5]
```删除任何单个出现的叶子：```
[5,5,5]
```这仍然是完全统一的。 某些实现错误地假设需要多个不同的数字。 基于频率的条件自然可以正确处理这种情况。 

当一个数字的频率比其他数字恰好大一时，就会出现第三种棘手的边缘情况。 例如：```
[1,1,2,2,2]
```频率是：```
1 -> 2
2 -> 3
```删除一个`2`使两个频率等于`2`。 该实现使用以下方式显式检查此结构：```
freq[max_frequency] == 1
```结合总长度验证公式。 

另一个微妙的情况是前缀已经完美平衡，例如：```
[1,1,2,2]
```尽管所有频率都相等，但删除一个元素就会破坏这种相等性。 因此该前缀无效。 该实现避免了此错误，因为三个有效的结构条件都不匹配此配置。
