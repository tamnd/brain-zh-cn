[LeetCode 第 1248 题](https://leetcode.com/problems/count-number-of-nice-subarrays/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个连续子数组恰好包含`k`奇数。 

我们得到一个整数数组`nums`和一个整数`k`。 子数组是数组的任何连续段，这意味着元素必须按原始顺序彼此相邻出现。 如果子数组恰好包含`k`奇数整数。 

任务不是找到子数组本身，而是返回有效子数组的总数。 

例如，在数组中`[1,1,2,1,1]`和`k = 3`，有效的子数组是：

 -`[1,1,2,1]`-`[1,2,1,1]`所以答案是`2`。 

约束条件很重要：

 - 该数组最多可以包含`50,000`元素。 
- 每个值可以大到`10^5`。 

由于输入量很大，复杂度为二次方的算法，`O(n^2)`，在最坏的情况下会太慢。 我们需要一个更接近线性时间的解决方案。 

一个重要的观察是偶数的实际值并不重要。 唯一重要的是每个数字是奇数还是偶数。 这使我们能够将问题转化为对累积奇数等于的子数组进行计数`k`。 

有几种边缘情况值得考虑：

 - 根本没有奇数的数组。 
- 每个数字都是奇数的数组。 
- 情况`k`等于`1`。 
- 整个数组完全包含的情况`k`奇数。 
- 奇数之前、之后或之间的长段偶数。 

这些情况很容易因滑动窗口或前缀和实现中的一个错误而暴露出来。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组。 

对于每个起始索引，我们一次一步扩展结束索引，并计算该子数组中出现了多少个奇数。 每当奇数计数恰好变为`k`，我们增加答案。 

这种方法是正确的，因为它显式检查每个连续的子数组并计算所有有效的子数组。 

然而，有`O(n^2)`可能的子数组。 和`n = 50,000`，这变得太慢了。 即使进行了一些小的优化，最坏的情况仍然是二次的。 

### 最优方法，前缀和与哈希图

 关键的见解是，我们并不关心确切的数字，只关心到目前为止出现了多少个奇数。 

我们定义：

 -`prefixOddCount`= 从开始到当前索引看到的奇数元素的数量。 

如果在某个索引处当前前缀包含`x`奇数，然后是任何较早的前缀`x - k`奇数形成一个子数组，恰好包含`k`奇数。 

这将问题转化为前缀和计数问题。 

我们使用哈希映射来存储每个前缀奇数出现的次数。 当我们遍历数组时：

 - 更新当前奇数计数。 
- 检查以前的前缀有多少个`currentOddCount - k`。 
- 将频率添加到答案中。 
- 将当前前缀计数存储在哈希映射中。 

这给出了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个可能的子数组 |
 | 最佳 | O(n) | O(n) | 使用前缀和和哈希映射 |

 ## 算法演练

 1. 初始化一个名为的哈希图`prefix_counts`。 

该映射存储每个前缀奇数计数出现的次数。 我们从以下开始：```
prefix_counts[0] = 1
```这表示处理任何元素之前的空前缀。 
2.初始化三个变量：

 -`current_odd_count = 0`-`nice_subarrays = 0`-`prefix_counts = {0: 1}`3. 一次一个数字地遍历数组。 
4. 对于每个数字，判断它是否是奇数。 

如果`num % 2 == 1`, 增量`current_odd_count`。 
5. 计算：```
needed = current_odd_count - k
```如果我们之前见过一个前缀`needed`奇数，则该前缀和当前索引之间的子数组恰好包含`k`奇数。 
6.添加频率`needed`从哈希映射到答案。```
nice_subarrays += prefix_counts.get(needed, 0)
```7. 记录哈希图中当前的前缀奇数计数。```
prefix_counts[current_odd_count] += 1
```8. 继续，直到处理完整个数组。 
9. 返回最终计数。 

### 为什么它有效

 该算法之所以有效，是因为两个前缀奇数计数之间的差等于它们之间的子数组内奇数元素的数量。 

如果：```
current_odd_count - previous_odd_count = k
```那么这两个位置之间的子数组恰好包含`k`奇数。 

通过存储每个前缀计数出现的次数，我们可以有效地计算以每个索引结尾的所有有效子数组。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def numberOfSubarrays(self, nums: List[int], k: int) -> int:
        prefix_counts = defaultdict(int)
        prefix_counts[0] = 1
        
        current_odd_count = 0
        nice_subarrays = 0
        
        for num in nums:
            if num % 2 == 1:
                current_odd_count += 1
            
            needed = current_odd_count - k
            
            nice_subarrays += prefix_counts[needed]
            
            prefix_counts[current_odd_count] += 1
        
        return nice_subarrays
```该实现严格遵循上述算法。 

我们使用`defaultdict(int)`所以丢失的钥匙会自动返回`0`。 这避免了重复的存在检查。 

变量`current_odd_count`跟踪遍历数组时迄今为止出现的奇数个数。 

对于每个元素：

 - 如果数字是奇数，则增加前缀奇数计数。 
- 计算有多少个较早的前缀将创建一个完全包含的子数组`k`奇数。 
- 将匹配前缀的数量添加到答案中。 
- 存储当前的前缀计数以供将来的子数组使用。 

初始化：```python
prefix_counts[0] = 1
```非常重要。 它允许子数组从索引开始`0`才能正确计数。 

## 解决方案```go
func numberOfSubarrays(nums []int, k int) int {
    prefixCounts := make(map[int]int)
    prefixCounts[0] = 1

    currentOddCount := 0
    niceSubarrays := 0

    for _, num := range nums {
        if num%2 == 1 {
            currentOddCount++
        }

        needed := currentOddCount - k

        if count, exists := prefixCounts[needed]; exists {
            niceSubarrays += count
        }

        prefixCounts[currentOddCount]++
    }

    return niceSubarrays
}
```Go 实现在概念上与 Python 版本几乎相同。 

主要区别在于 Go 映射在查找期间返回两个值：```go
value, exists := map[key]
```这用于安全地检查所需的前缀计数是否存在。 

Go 整数足以解决这个问题，因为子数组的最大数量完全在 32 位有符号整数范围内，尽管 Go 的`int`type 已经在现代系统上轻松处理了这个问题。

 ## 边缘情况

 当数组根本不包含奇数时，就会出现一种重要的边缘情况。 在这种情况下，前缀奇数计数永远不会增加。 有缺陷的实现可能会错误地计算子数组，即使没有一个满足要求。 当前的解决方案可以正确处理这个问题，因为`current_odd_count - k`永远不会匹配任何有效的前缀计数`k > 0`。 

当每个数字都是奇数时，就会发生另一种棘手的情况。 在这种情况下，前缀奇数计数每一步都会增加。 这测试实现是否正确地计算重叠子数组。 由于该算法纯粹依赖于前缀差异，因此它自然可以处理重叠范围而无需重复计算。 

第三个重要的边缘情况涉及奇数周围的大片偶数。 例如：```
[2,2,2,1,2,2,1,2,2]
```有效子数组来自左边界和右边界的许多组合。 幼稚的实现常常会错过这些组合。 前缀总和方法会自动对所有这些前缀进行计数，因为每个匹配的较早前缀都会贡献另一个有效的起始位置。 

当有效子数组从索引处开始时，会出现最后一个微妙的边缘情况`0`。 没有初始化：```
prefix_counts[0] = 1
```这些子数组永远不会被计算在内。 初始化表示数组开始之前的空前缀，并确保本身完全包含的前缀的正确性`k`奇数。
