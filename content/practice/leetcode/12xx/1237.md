 **难度：** 🟡 中等

 ## 解决方案

 ## 问题理解

 这个问题让我们可以访问一个隐藏的函数`f(x, y)`通过一个接口。 我们不被允许知道或直接执行该公式。 相反，我们只能用正整数调用函数`x`和`y`并观察结果。 

重要的属性是函数在两个变量中都是严格递增的：

 - 增加`x`同时保持`y`固定总是会增加输出。 
- 增加`y`同时保持`x`固定总是会增加输出。 

我们的目标是找到每对正整数`(x, y)`这样：```
f(x, y) == z
```函数实现被判断隐藏，但保证所有测试用例的单调性。 

输入包括：

 - 可调用的`CustomFunction`对象
 - 一个整数`z`输出必须是所有正整数对的列表`[x, y]`满足方程。 

约束足够小，暴力破解在技术上是可行的：

 -`1 <= z <= 100`- 所有有效的解决方案都保证在`1 <= x, y <= 1000`然而，该问题是专门为奖励利用单调行为而设计的。 由于函数随着任一变量的增加而增加，因此我们可以有效地消除大部分搜索空间。 

一个重要的观察结果是可能存在：

 - 多个有效对
 - 没有有效的配对
 - 只有一对有效

 输出顺序并不重要。 

一些可能在简单实现中导致问题的边缘情况包括：

 - 增长非常快的函数，例如乘法或类似指数的行为
 - 仅存在一对的情况
 - 不存在解决方案的情况
 - 重复遍历同一搜索空间
 - 低效的嵌套循环对昂贵的隐藏函数进行不必要的调用

 单调保证是允许优化的关键属性。 

## 方法

 ### 蛮力方法

 最简单的方法是尝试每一种可能的配对`(x, y)`两个值的范围都从`1`到`1000`。 

对于每对：

 1. 打电话`f(x, y)`2. 将结果与`z`3. 如果相等，则存储该对

 因为约束保证所有有效答案都在这个范围内，所以蛮力总能找到每个解决方案。 

主要问题是效率。 有：```
1000 * 1000 = 1,000,000
```可能的对。 

这意味着对隐藏函数的调用多达一百万次。 虽然这在当前的限制下仍然可以通过，但它忽略了问题最重要的属性，即单调性。 

### 关键见解

 由于当任一变量增加时函数也会增加，因此我们可以使用双指针策略。 

假设我们从以下位置开始：```
x = 1
y = 1000
```现在评价`f(x, y)`。 

- 如果结果太大，则增加`x`只会让它变大，所以我们必须减少`y`。 
- 如果结果太小，则减少`y`只会让它变得更小，所以我们必须增加`x`。 
- 如果结果等于`z`，我们记录该对并通过增加对角线移动`x`并减少`y`。 

这与搜索排序矩阵完全相同。 

在每一步中，我们都会消除：

 - 整行
 - 或整列

 这最多可将总工作量减少到`2000`函数调用。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(1000²) = O(1,000,000) | O(k) | 检查每一个可能的对 |
 | 最优两指针 | O(1000) | O(k) | 使用单调性消除行和列 |

 这里，`k`表示有效解的数量。 

## 算法演练

 1.初始化两个指针：

 -`x = 1`-`y = 1000`我们从概念搜索网格的右上角开始。 
2. 创建一个空结果列表。 
3.同时`x <= 1000`和`y >= 1`：

评价：```
value = f(x, y)
```4. 如果`value == z`：

- 添加`[x, y]`到结果列表
 - 增加`x`- 减少`y`我们沿对角线移动是因为：

 - 增加`x`使未来价值更大
 - 减少`y`使未来值更小
 - 由于严格的单调性，留在同一行或同一列不能再次产生相同的值
 5.如果`value < z`：

增加`x`。 

由于函数随着更大的增加而增加`x`，这是可能达到的唯一途径`z`。 
6. 如果`value > z`：

减少`y`。 

由于函数随着更大的增加而增加`y`，减少`y`是减少结果的唯一方法。 
7. 继续，直到指针移出界限。 
8. 返回收集到的结果列表。 

### 为什么它有效

 该算法之所以有效，是因为搜索空间的行为类似于排序矩阵。 

在任何位置`(x, y)`:

 - 下面的所有内容都有更大的值
 - 左边的所有内容都有较小的值

 因此：

 - 如果当前值太大，则下面的所有位置也太大
 - 如果当前值太小，则左侧的所有位置也太小

 每一步都会安全地消除不可能的区域，而不会丢失有效的解决方案。 

由于该函数在两个维度上都严格递增，因此无法跳过任何有效对。 

## Python 解决方案```python
from typing import List

"""
   This is the custom function interface.
   You should not implement it, or speculate about its implementation
   class CustomFunction:
       # Returns f(x, y) for any given positive integers x and y.
       # Note that f(x, y) is increasing with respect to both x and y.
       # i.e. f(x, y) < f(x + 1, y), f(x, y) < f(x, y + 1)
       def f(self, x, y):
  
"""

class Solution:
    def findSolution(self, customfunction: 'CustomFunction', z: int) -> List[List[int]]:
        result = []

        x = 1
        y = 1000

        while x <= 1000 and y >= 1:
            value = customfunction.f(x, y)

            if value == z:
                result.append([x, y])
                x += 1
                y -= 1
            elif value < z:
                x += 1
            else:
                y -= 1

        return result
```该实现遵循前面描述的精确的两指针策略。 

我们初始化`x`以尽可能小的值和`y`以尽可能大的值。 这将我们置于概念矩阵的右上角。 

在循环内部，我们每次迭代都会评估隐藏函数一次。 

当值匹配时`z`，我们记录该对并沿对角线移动。 这可以防止重复工作，因为严格的单调性保证同一行或同一列中不会出现重复的值。 

当值太小时，我们增加`x`因为更大`x`产生更大的函数值。 

当值太大时，我们减少`y`因为更小`y`产生较小的函数值。 

一旦任一指针移出有效范围，循环就会终止。 

## 解决方案```go
/**
 * This is the declaration of customFunction API.
 * @param  x    int
 * @param  y    int
 * @return      Returns f(x, y) for any given positive integers x and y.
 *              Note that f(x, y) is increasing with respect to both x and y.
 *              i.e. f(x, y) < f(x + 1, y), f(x, y) < f(x, y + 1)
 */

func findSolution(customFunction func(int, int) int, z int) [][]int {
    result := [][]int{}

    x := 1
    y := 1000

    for x <= 1000 && y >= 1 {
        value := customFunction(x, y)

        if value == z {
            result = append(result, []int{x, y})
            x++
            y--
        } else if value < z {
            x++
        } else {
            y--
        }
    }

    return result
}
```Go 的实现与 Python 解决方案非常相似。 

结果存储为整数切片的切片，`[][]int`。 

Go 在这里不需要特殊的溢出处理，因为所有值都保证适合 32 位有符号整数，并且 Go 的`int`type 在 LeetCode 平台上轻松支持该范围。 

与 Python 列表不同，Go 切片需要使用显式追加`append`。 

循环逻辑和指针移动在其他方面是相同的。 

## 工作示例

 ### 示例 1

 输入：```
f(x, y) = x + y

```初始状态：```
x = 1

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(1000) | 每次迭代仅移动 x 或 y 一次 |
 | 空间| O(k) | 仅存储有效的解对 |

 重要的观察是`x`只会增加和`y`只会减少。 

-`x`最多可以移动`1000`次
 -`y`最多可以移动`1000`次

 因此迭代总数的界限为`2000`，这简化为`O(1000)`。 

该算法比暴力破解更有效，因为它永远不会重新访问任何状态。

 ## 边缘情况

 ### 不存在有效对

 某些函数和目标值无法产生有效的解决方案。 例如：```
f(x, y) = x² + y²
z = 3
```不存在平方和为的正整数`3`。 

有缺陷的实现可能会错误地循环或意外返回无效的对。 我们的实现安全终止，因为在每次迭代期间都有一个指针移动，从而保证了进度。 

### 仅存在一对有效的

 对于以下情况：```
f(x, y) = x * y
z = 1
```唯一有效的对是`[1,1]`。 

某些实现在匹配后移动指针时会意外地跳过解决方案。 我们的解决方案在更新两个指针之前记录该对，确保不会丢失解决方案。 

### 大面积无效值

 当`y`开始于`1000`，许多函数值最初可能远大于`z`。 

一个幼稚的解决方案仍然会单独检查每一对。 双指针方法通过重复递减有效地消除整列`y`直到搜索区域变得相关。 

这是使算法高效的关键优化。
