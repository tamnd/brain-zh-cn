[LeetCode 第 1252 题](https://leetcode.com/problems/cells-with-odd-values-in-a-matrix/)

 **难度：** 🟢简单
 **主题：** 数组、数学、模拟

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`m x n`每个单元最初包含的矩阵`0`。 我们还得到了一个名为`indices`，其中每个元素是一对`[ri, ci]`。 

对于每对`[ri, ci]`，我们必须执行两个操作：

 1. 增加行中的每个值`ri`经过`1`2. 增加列中的每个值`ci`经过`1`处理完所有操作后，我们需要计算矩阵中有多少个单元格包含奇数。 

重要的细节是每个操作同时影响整行和整列。 因此，单元可以在不同的操作中多次递增。 单元格最终是奇数还是偶数仅取决于奇偶校验，这意味着应用于它的增量总数是奇数还是偶数。 

输入包括：

 -`m`, 行数
 -`n`, 列数
 -`indices`，行列递增操作列表

 输出是一个整数，表示所有操作完成后具有奇数值的单元格数量。 

限制很小：

 -`1 <= m, n <= 50`-`indices.length <= 100`这些限制意味着即使是直接矩阵模拟也可以在时间限制内顺利进行。 然而，后续要求仅使用更优化的解决方案`O(m + n)`额外的空间并尽可能避免全矩阵模拟。 

需要考虑一些重要的边缘情况：

 - 多个操作可能重复针对同一行或同一列
 - 行或列可以增加偶数次，使其贡献在奇偶校验方面有效地抵消
 - 像这样的小矩阵`1 x 1`可以暴露奇偶校验错误
 - 操作可能会影响每一行和每一列
 - 我们只关心奇数与偶数，而不关心实际的数值

 ## 方法

 ### 蛮力方法

 最直接的解决方案是显式模拟矩阵。 

我们创建一个`m x n`用零初始化的矩阵。 对于每一个`[ri, ci]`在`indices`，我们迭代整行`ri`并递增每个值。 然后我们迭代整个列`ci`并递增每个值。 

处理完所有操作后，我们遍历整个矩阵并计算有多少个单元格包含奇数值。 

这种方法很容易理解，直接遵循问题陈述，使得正确性直观。 每个操作都完全按照描述进行。 

但是，此方法会执行不必​​要的工作。 即使我们只关心最终结果是奇数还是偶数，我们也会重复修改矩阵值。 除了奇偶校验之外，实际数值并不重要。 

时间复杂度变为：

 - 每个操作都会更新`n`行单元格和`m`柱状细胞
 - 总复杂度：`O(indices.length * (m + n))`- 最终遍历添加`O(m * n)`尽管这对于给定的约束是可以接受的，但我们可以在概念上做得更好。 

### 最佳方法

 关键的观察是我们只关心奇偶校验。 

一个细胞`(r, c)`递增：

 - 每次操作定位行一次`r`- 每次操作目标栏一次`c`因此，单元格的最终值为：```
rowIncrements[r] + colIncrements[c]
```如果一部分为奇数，另一部分为偶数，则和为奇数。 

我们可以简单地跟踪，而不是模拟整个矩阵：

 - 每行是否已增加奇数次或偶数次
 - 每列是否已增加奇数次或偶数次

 然后对于每个单元格：

 - 奇数行+偶数列=奇数
 - 偶数行 + 奇数列 = 奇数

 我们可以直接计算结果，而不需要存储矩阵值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(索引.长度 × (m + n) + m × n) | O(m × n) | 显式模拟整个矩阵 |
 | 最佳 | O(索引.长度 + m × n) | O(m + n) | 仅跟踪行和列奇偶校验 |

 ## 算法演练

 1.创建两个数组：

 -`row_parity`尺寸的`m`-`col_parity`尺寸的`n`每个值表示该行或列是否已增加奇数次。 我们可以将其存储为`0`对于偶数和`1`为奇数。 
2. 处理每一个操作`[ri, ci]`在`indices`。 

对于每个操作：

 - 切换`row_parity[ri]`- 切换`col_parity[ci]`我们切换是因为每个增量都会改变奇偶校验：

 - 偶数变为奇数
 - 奇数变为偶数

 使用 XOR 可以有效地完成此操作`1`。 
3. 初始化一个名为`odd_count`。 
4. 遍历每个单元格`(r, c)`在矩阵中。 

对于每个单元格：

 - 计算`row_parity[r] + col_parity[c]`- 如果总和是奇数，则递增`odd_count`这是有效的，因为：

 -`0 + 1 = 1`， 奇怪的
-`1 + 0 = 1`， 奇怪的
-`0 + 0 = 0`， 甚至
-`1 + 1 = 2`, 甚至
 5. 返回`odd_count`。 

### 为什么它有效

 每个操作都为特定行中的所有单元格和特定列中的所有单元格贡献一个增量。 单元格的最终值仅取决于其行和列增加的次数。 

奇偶性完全决定了一个数是奇数还是偶数。 由于将两个奇数相加会产生偶数结果，而将一个奇数和一个偶数相加会产生奇数结果，因此仅跟踪奇偶校验就足以正确确定最终答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def oddCells(self, m: int, n: int, indices: List[List[int]]) -> int:
        row_parity = [0] * m
        col_parity = [0] * n

        for row, col in indices:
            row_parity[row] ^= 1
            col_parity[col] ^= 1

        odd_count = 0

        for row in range(m):
            for col in range(n):
                if (row_parity[row] + col_parity[col]) % 2 == 1:
                    odd_count += 1

        return odd_count
```该实现首先创建两个数组来跟踪每行和列的奇偶校验状态。 我们不存储完整的增量计数，而是只存储增量数当前是奇数还是偶数。 

加工时`indices`，代码使用 XOR 切换相应的行和列值。 异或与`1`是一种方便的方式来切换`0`和`1`。 

处理完所有操作后，解决方案将迭代每个矩阵位置。 对于每个单元格，它检查行奇偶校验和列奇偶校验之和是否为奇数。 如果是这样，该单元格就可以得出答案。 

该解决方案完全避免构建实际矩阵，从而减少内存使用并使逻辑集中于奇偶校验。 

## 解决方案```go
func oddCells(m int, n int, indices [][]int) int {
	rowParity := make([]int, m)
	colParity := make([]int, n)

	for _, index := range indices {
		row := index[0]
		col := index[1]

		rowParity[row] ^= 1
		colParity[col] ^= 1
	}

	oddCount := 0

	for row := 0; row < m; row++ {
		for col := 0; col < n; col++ {
			if (rowParity[row]+colParity[col])%2 == 1 {
				oddCount++
			}
		}
	}

	return oddCount
}
```Go 实现遵循与 Python 版本相同的逻辑。 使用切片而不是 Python 列表来跟踪行和列奇偶校验。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有值都非常小。 空切片与 nil 切片也无关紧要，因为问题保证了有效的输入大小和至少一项操作。

 ## 边缘情况

 一个重要的边缘情况是`1 x 1`矩阵。 在这种情况下，增加行`0`和列`0`影响同一个细胞两次。 幼稚的实现可能会错误地将此视为奇数，因为它看到两个独立影响单元的操作。 该实现正确处理了这个问题，因为奇偶校验是由总增量计数确定的，并且`2`是均匀的。 

另一个重要的情况是对同一行和同一列的重复操作。 例如，申请`[0,0]`两次应该完全抵消奇偶校验的变化。 XOR 切换逻辑自然会处理此问题，因为切换两次会将奇偶校验返回到偶数。 

当只有行或只有列有效贡献奇奇偶校验时，会出现第三种重要的边缘情况。 例如，如果每列都切换偶数次，但某些行切换奇数次，则这些行中的每个单元格都会变为奇数。 该实现使用行和列的组合奇偶校验来正确评估每个单元。 

最后一个微妙的情况涉及重叠增量。 每个操作都会增加一整行和一整列，这意味着交集单元格在该操作期间会收到两个增量。 直接模拟可以自然地处理这个问题，但基于奇偶校验的解决方案如果没有正确组合行和列奇偶校验，可能会意外地误算。 公式`(row_parity[row] + col_parity[col]) % 2`保证正确处理这种重叠。
