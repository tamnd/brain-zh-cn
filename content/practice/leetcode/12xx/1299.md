[LeetCode 第 1299 题](https://leetcode.com/problems/replace-elements-with-greatest-element-on-right-side/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`arr`并要求我们用出现在其右侧某处的最大值替换每个元素。 数组中的最后一个元素的右侧没有元素，因此它必须始终变为`-1`。 

换句话说，对于每个索引`i`，我们要计算：

 - 所有元素中的最大值`i + 1`到数组末尾
 - 更换`arr[i]`具有该值

 最后一个索引没有要检查的有效范围，因此它的替换值为`-1`。 

例如，考虑：```
arr = [17,18,5,4,6,1]
```对于索引`0`，右边的元素是`[18,5,4,6,1]`，最大值为`18`。 

对于索引`1`，右边的元素是`[5,4,6,1]`，最大值为`6`。 

继续这个过程会产生：```
[18,6,6,6,1,-1]
```限制相对较小：

 -`1 <= arr.length <= 10^4`-`1 <= arr[i] <= 10^5`一个`O(n^2)`从技术上讲，解决方案仍然可以通过`10^4`在许多环境中，但这是低效且不必要的。 该问题有一个干净的线性时间解决方案。 

一些边缘情况很重要：

 - 单元素数组，例如`[400]`- 数组已经按降序排列
 - 数组已经按升序排列
 - 许多元素相等的数组
 - 非常小的数组，索引处理错误很常见

 该问题保证数组至少包含一个元素，因此我们永远不需要处理空数组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是对每个索引进行独立处理。 

对于每个职位`i`，我们扫描右侧的所有元素`i`并手动计算最大值。 找到最大值后，我们将其存储为替换值`arr[i]`。 

对于最后一个索引，我们只需分配`-1`。 

这种方法是正确的，因为它明确检查每个位置右侧的每个有效候选者。 但是，它会重复扫描阵列的重叠部分。 

例如：```
Index 0 scans almost the entire array
Index 1 scans almost the entire remaining array
Index 2 scans slightly less
```这种重复的工作导致了二次时间复杂度。 

### 最佳方法

 关键的观察是，如果我们从右向左处理数组，则可以增量地维护索引右侧的最大值。 

假设我们站在索引处`i`。 

如果我们已经知道迄今为止在右侧元素中看到的最大值，那么：

 - 该值正是`arr[i]`应该成为
 - 处理后索引`i`，我们使用原始值更新运行最大值`arr[i]`这是有效的，因为当从右向左遍历时，我们始终拥有有关当前索引右侧所有内容的完整信息。 

我们维护一个变量，而不是重复地重新扫描后缀：```
max_right
```该变量始终存储在数组中向后移动时迄今为止遇到的最大值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 对于每个索引，扫描右侧的所有元素 |
 | 最佳 | O(n) | O(1) | O(1) | 从右向左移动，同时保持最大跑动 |

 ## 算法演练

 1. 初始化一个名为`max_right`到`-1`。 

该变量表示迄今为止在当前位置右侧看到的最大元素。 我们从`-1`因为最后一个元素应该变成`-1`。 
2. 从右向左遍历数组。 

我们向后移动，因为每个位置都取决于来自其右侧的信息。 当我们到达索引时，我们已经知道所有后面元素中的最大值。 
3. 暂时存储当前元素。 

覆盖之前`arr[i]`，我们必须保存它的原始值，因为它可能成为更左边元素的新最大值。 
4. 更换`arr[i]`和`max_right`。 

此时此刻，`max_right`包含严格位于索引右侧的所有元素中的最大值`i`。 
5. 更新`max_right`。 

将保存的原始值与当前值进行比较`max_right`并保留较大的一个。 
6. 继续，直到到达数组的开头。 

每个元素最终都会包含其右侧的最大值。 

### 为什么它有效

 该算法保持一个不变量：```
Before processing index i,
max_right equals the maximum value among all elements to the right of i.
```因为我们从右到左处理索引，所以这个不变量始终为真。 我们使用`max_right`作为替换值，然后使用原始当前元素更新它，以便不变量在下一次迭代中保持有效。 

这保证了每个索引的正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def replaceElements(self, arr: List[int]) -> List[int]:
        max_right = -1

        for i in range(len(arr) - 1, -1, -1):
            current = arr[i]
            arr[i] = max_right
            max_right = max(max_right, current)

        return arr
```实现遵循最优的从右到左遍历策略。 

变量`max_right`跟踪在数组中向后移动时迄今为止遇到的最大值。 最初，它是`-1`因为最后一个元素必须变成`-1`。 

循环从最终索引向下迭代到索引`0`。 对于每个位置：

 - 原始值存储在`current`- 数组元素被替换为`max_right`-`max_right`使用原始值更新

 在覆盖之前保存原始值至关重要。 否则，我们将丢失更新运行最大值所需的信息。 

该解决方案会就地修改数组，从而保持空间复杂度不变。 

## 解决方案```go
func replaceElements(arr []int) []int {
    maxRight := -1

    for i := len(arr) - 1; i >= 0; i-- {
        current := arr[i]
        arr[i] = maxRight

        if current > maxRight {
            maxRight = current
        }
    }

    return arr
}
```Go 实现与 Python 版本几乎相同。 

Go 中的切片是可变的，因此该函数直接更新输入切片。 不需要额外的数组分配。 

不存在整数溢出问题，因为与 Go 的整数范围相比，约束非常小。 

该算法还自然地处理单元素数组，因为循环运行一次，将唯一的值替换为`-1`。

 ## 边缘情况

 ### 单元素数组

 单元素数组是最小的有效输入。 由于右边没有元素，所以答案一定是`[-1]`。 

这种情况通常会导致假设至少存在一个右侧元素的解决方案出现错误。 该实现自然地处理它，因为循环运行一次`max_right = -1`。 

### 严格递增数组

 考虑：```
[1,2,3,4]
```每个元素都应该成为最终元素`4`，除了最后一个位置。 

这种情况很重要，因为向后遍历时运行最大值会反复变化。 算法正确更新`max_right`每一步之后。 

### 严格递减数组

 考虑：```
[4,3,2,1]
```每个元素的替换只是其右侧的下一个元素。 

此案例验证了算法没有错误地保留过时的最大值。 由于运行最大值在每一步都会发生变化，因此正确性取决于正确的更新顺序。 

### 具有重复值的数组

 考虑：```
[7,7,7,7]
```右边的最大值仍然存在`7`除最后一个位置外的所有位置。 

一些不正确的实现意外地使用了严格的更大比较，从而错误地处理了重复项。 该实现使用`max()`正确，因此可以正确保留相等的值。
