[LeetCode 问题 1267](https://leetcode.com/problems/count-servers-that-communicate/)

 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、广度优先搜索、并查找、矩阵、计数

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个代表服务器中心的二维网格。 每个单元格包含：

 -`1`，意味着该位置有一个服务器
 -`0`，表示单元格为空

 如果一台服务器位于同一行或同一列，则这两个服务器可以与另一台服务器通信。 

任务是计算有多少服务器可以与至少一台其他服务器通信。 

换句话说，对于网格中的每个服务器，我们需要确定是否存在另一个服务器：

 - 同一行的其他地方，或者
 - 在同一列的其他地方

 如果是，则该服务器应包含在最终计数中。 

输出是一个整数，表示能够通信的服务器数量。 

约束条件很重要：

 -`1 <= m, n <= 250`- 因此网格大小最多可以包含`250 * 250 = 62,500`细胞

 这个值足够大，以至于低效的重复扫描可能会变得昂贵，但又足够小，以至于线性或接近线性的矩阵遍历是完全可以接受的。 

需要考虑一些重要的边缘情况：

 - 不应计算单个孤立服务器。 
- 充满服务器的整行或整列应计算这些行或列中的所有服务器。 
- 服务器可以通过其行或列进行通信。 只需要一个连接。 
- 没有服务器的网格应该返回`0`。 
- 每个服务器都隔离的网格也应该返回`0`。 

例如：```
[[1,0],
 [0,1]]
```两台服务器都是隔离的，因为既不与另一台服务器共享行也不共享列，所以答案是`0`。 

相比之下：```
[[1,0],
 [1,1]]
```所有三个服务器都进行通信，因为：

 - 列中的两台服务器`0`沟通
 - 排中的两台服务器`1`沟通

 所以答案是`3`。 

## 方法

 ### 蛮力方法

 最直接的解决方案是单独检查每台服务器。 

对于包含服务器的每个单元：

 1. 扫描整行，查看是否存在其他服务器。 
2. 扫描整列，查看是否存在其他服务器。 
3. 如果任一扫描发现另一台服务器，则对当前服务器进行计数。 

这种方法是正确的，因为它直接检查每个服务器的通信定义。 

然而，它的效率很低。 

假设网格包含`m * n`细胞。 对于每台服务器，我们可以扫描：

 - 最多`n`其行中的单元格
 - 最多`m`其列中的单元格

 In the worst case, every cell contains a server, so the total complexity becomes:```
O(m * n * (m + n))
```尺寸可达`250 x 250`，这可能会变得不必要的昂贵。 

### 最佳方法

 关键的观察结果是，通信仅取决于每行和每列中存在多少个服务器。 

服务器在以下情况下进行通信：```
row_count[row] > 1
OR
column_count[col] > 1
```因此，我们可以进行预处理，而不是重复扫描每个服务器的行和列：

 - 每行有多少台服务器
 - 每列中有多少个服务器

 然后我们第二次遍历网格并计算行数或列数超过的服务器`1`。 

这避免了重复工作并降低了矩阵线性遍历的复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * (m + n)) | O(m * n * (m + n)) | O(1) | O(1) | 重复扫描每台服务器的行和列 |
 | 最佳 | O(m * n) | O(m + n) | 使用行频和列频计数 |

 ## 算法演练

 ### 第 1 步：创建行数和列数数组

 我们创造：

 -`row_counts`尺寸的`m`-`col_counts`尺寸的`n`这些数组存储每行和每列中出现的服务器数量。 

此预处理允许稍后进行恒定时间通信检查。 

### 步骤 2：遍历网格并填充计数

 我们迭代矩阵中的每个单元格。 

每当我们遇到服务器（`grid[r][c] == 1`）：

 - 增量`row_counts[r]`- 增量`col_counts[c]`在此经过之后：

 -`row_counts[r]`告诉我们行中有多少台服务器`r`-`col_counts[c]`告诉我们列中有多少台服务器`c`### 第三步：再次遍历网格

 我们现在再次检查每台服务器。 

对于位置处的每个服务器`(r, c)`：

- 如果`row_counts[r] > 1`，服务器通信
 - 如果`col_counts[c] > 1`，服务器通信

 如果任一条件为真，我们会将服务器添加到答案中。 

### 步骤 4：返回总数

 处理完所有服务器后，累计计数就是最终答案。 

### 为什么它有效

 该算法之所以有效，是因为当且仅当同一行或同一列中存在另一台服务器时，服务器才会进行通信。 

预处理步骤精确计算以下信息：

 - 具有多个服务器的行
 - 具有多个服务器的列

 在第二遍期间，将根据这些计数检查每个服务器。 因此，每个正在通信的服务器都只计数一次，并且排除孤立的服务器。 

## Python 解决方案```python
from typing import List

class Solution:
    def countServers(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        row_counts = [0] * rows
        col_counts = [0] * cols

        # Count servers in each row and column
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 1:
                    row_counts[r] += 1
                    col_counts[c] += 1

        communicating_servers = 0

        # Count servers that can communicate
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 1:
                    if row_counts[r] > 1 or col_counts[c] > 1:
                        communicating_servers += 1

        return communicating_servers
```实现直接遵循算法。 

首先，我们确定矩阵维度并初始化两个计数数组：```python
row_counts = [0] * rows
col_counts = [0] * cols
```第一个嵌套循环遍历矩阵并记录每行和每列存在多少个服务器。 

第二个嵌套循环分别检查每个服务器。 如果出现以下情况，服务器就会贡献答案：```python
row_counts[r] > 1 or col_counts[c] > 1
```该条件与问题陈述中的通信规则完全匹配。 

最后，返回通信服务器的总数。 

## 解决方案```go
func countServers(grid [][]int) int {
    rows := len(grid)
    cols := len(grid[0])

    rowCounts := make([]int, rows)
    colCounts := make([]int, cols)

    // Count servers in each row and column
    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            if grid[r][c] == 1 {
                rowCounts[r]++
                colCounts[c]++
            }
        }
    }

    communicatingServers := 0

    // Count communicating servers
    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            if grid[r][c] == 1 {
                if rowCounts[r] > 1 || colCounts[c] > 1 {
                    communicatingServers++
                }
            }
        }
    }

    return communicatingServers
}
```Go 的实现与 Python 解决方案非常相似。 

切片用于`rowCounts`和`colCounts`，初始化使用`make`。 

Go 在这里不需要对整数溢出进行特殊处理，因为最大服务器数量仅为`62,500`，它很容易适合 Go 的`int`类型。 

假设矩阵非空，因为问题约束保证至少一行和一列。

 ## 边缘情况

 ### 单一隔离服务器

 像这样的网格：```
[[1]]
```包含在同一行或同一列中没有相邻服务器的服务器。 

有缺陷的实现可能会错误地计算任何现有服务器。 我们的解决方案避免了这种情况，因为：```
row_count = 1
col_count = 1
```都不超过`1`，因此服务器被正确排除。 

### 仅通过列连接的服务器

 考虑：```
[[1],
 [1],
 [0]]
```服务器不在同一行，但共享一列。 

仅关注行的幼稚实现在这里会失败。 我们的算法分别跟踪行计数和列计数，因此可以正确检测列通信。 

### 密集服务器网格

 考虑：```
[[1,1,1],
 [1,1,1]]
```每个服务器都与许多其他服务器通信。 

反复重新扫描行和列的强力实现将执行不必要的工作。 我们的计数方法可以有效地处理这个问题，因为每行和列的计数仅计算一次。 

### 空网格区域

 网格可以包含许多零单元：```
[[0,0,0],
 [0,1,0],
 [0,0,0]]
```该算法必须完全忽略空单元格。 

我们的实施检查：```
if grid[r][c] == 1
```在执行任何通信逻辑之前，确保空单元格永远不会影响计数或结果。
