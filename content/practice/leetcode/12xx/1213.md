[LeetCode 问题 1213](https://leetcode.com/problems/intersection-of- Three-sorted-arrays/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、二分查找、计数

 ## 解决方案

 ## 问题理解

 该问题给了我们三个整数数组，`arr1`,`arr2`， 和`arr3`。 每个数组都已严格按升序排序。 严格递增意味着同一数组内不存在重复值，并且每个下一个元素都大于前一个元素。 

我们的任务是返回一个新的排序数组，其中仅包含同时出现在所有三个数组中的数字。 换句话说，我们正在寻找三个数组的交集。 

例如，如果一个数字存在于`arr1`和`arr2`但不在`arr3`，它不应该出现在结果中。 仅当值存在于每个数组中时才包含该值。 

问题陈述中的重要细节是：

 - 数组已经排序。 
- 数组内部包含唯一值，因为它们严格递增。 
- 输出也必须保持排序。 
- 数组长度最多为 1000，因此输入大小相对较小，但我们仍然应该寻求有效的解决方案。 

排序后的属性尤其重要，因为它使我们能够避免昂贵的重复搜索。 我们可以以协调的方式在数组中移动，而不是将每个元素与其他元素进行比较。 

考虑几个边缘情况很重要：

 - 可能根本没有公共元素，在这种情况下我们返回一个空数组。 
- 一个或多个数组可能只包含一个元素。 
- 所有三个阵列可以相同。 
- 通用值可能仅出现在数组末尾附近。 
- 因为数组是严格递增的，所以我们永远不需要担心同一数组内的重复处理。 

这些保证大大简化了实施。 

## 方法

 ### 蛮力方法

 一种简单的解决方案是对照其他两个数组检查一个数组中的每个元素。 

对于每个值`arr1`，我们可以在里面搜索这个值`arr2`和`arr3`。 如果两个数组中都存在该值，我们将其添加到结果中。 

由于数组是排序的，因此简单的暴力实现可能仍然使用线性搜索来进行成员资格检查。 这总共会产生三个嵌套扫描。 

例如：

 - 遍历每个值`arr1`- 对于每个值，扫描`arr2`- 如果找到，请扫描`arr3`这种方法是正确的，因为每个候选元素都针对所有数组进行显式验证。 然而，它执行不必要的重复比较。 

如果每个数组都有长度`n`，时间复杂度变为`O(n^2)`在实践中，因为每个成员资格测试可能需要全面扫描。 

### 最佳方法

 关键的观察结果是所有三个数组都已排序。 

当需要比较多个排序数组时，多指针技术变得非常有效。 我们只需在数组中移动一次，而不是重复重新启动搜索。 

我们维护三个指针：

 -`i`为了`arr1`-`j`为了`arr2`-`k`为了`arr3`每一步：

 - 如果所有三个当前值都相等，我们就找到了一个共同元素。 
- 否则，我们将指针前进到最小值。 

为什么这有效？ 

假设当前值为：```
arr1[i] = 2
arr2[j] = 5
arr3[k] = 7
```由于数组已排序，因此值`2`永远无法匹配其他数组中的未来值，因为所有未来值都更大。 因此，我们安全地移动指针`i`向前。 

这保证了每个指针仅向前移动而绝不会向后移动，从而产生线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描数组中的每个元素 |
 | 最佳 | O(n) | O(1) | O(1) | 在排序数组上使用三个指针 |

 ## 算法演练

 1.初始化三个指针，`i`,`j`， 和`k`，全部从索引开始`0`。 这些指针跟踪每个数组中的当前位置。 
2. 创建一个空结果数组来存储公共元素。 
3. 当所有三个指针仍在各自的数组内时继续处理。 一旦一个数组耗尽，循环就会停止，因为此后不再存在公共元素。 
4. 比较当前值：

 -`arr1[i]`-`arr2[j]`-`arr3[k]`5. 如果三个值都相等，则该数字存在于所有数组中：

 - 将其添加到结果中
 - 将所有三个指针向前移动，因为该值已被处理
 6. 否则，确定哪个当前值最小：

 - 如果`arr1[i]`是最小的，增量`i`- 否则如果`arr2[j]`是最小的，增量`j`- 否则，增加`k`7. 我们只移动最小的指针的原因是较小的值不可能出现在其他数组中。 由于数组是排序的，未来的元素只会变得更大。 
8. 继续，直到一个指针到达其数组的末尾。 
9. 返回结果数组。 

### 为什么它有效

 该算法保持了当前指针之前的每个值都已被完全处理并且永远不能参与未来匹配的不变性。 

当最小值被提前时，不会跳过任何可能的公共元素，因为其他数组已经包含更大的值。 由于指针仅向前移动，因此每个元素最多检查一次，从而保证正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def arraysIntersection(
        self,
        arr1: List[int],
        arr2: List[int],
        arr3: List[int]
    ) -> List[int]:
        
        i = 0
        j = 0
        k = 0
        
        result = []
        
        while i < len(arr1) and j < len(arr2) and k < len(arr3):
            
            if arr1[i] == arr2[j] == arr3[k]:
                result.append(arr1[i])
                i += 1
                j += 1
                k += 1
            
            else:
                minimum_value = min(arr1[i], arr2[j], arr3[k])
                
                if arr1[i] == minimum_value:
                    i += 1
                elif arr2[j] == minimum_value:
                    j += 1
                else:
                    k += 1
        
        return result
```实现直接遵循三指针算法。 

我们首先初始化三个索引，每个索引对应一个数组。 这些索引始终指向当前正在比较的候选值。 

这`while`仅当每个指针保持有效时循环才会继续。 一旦任何指针到达其数组的末尾，进一步的交集就不可能了。 

在循环内部，第一个条件检查所有三个值是否相等。 如果是，则该值属于交集结果，因此我们将其追加并前进所有指针。 

如果值不相等，我们计算三个当前元素中的最小值。 与该最小值对应的指针前进。 这是有效的，因为排序顺序保证了较小的值以后不会再次出现。 

该算法从不重新访问元素，这就是它实现线性时间复杂度的原因。 

## 解决方案```go
func arraysIntersection(arr1 []int, arr2 []int, arr3 []int) []int {
    i := 0
    j := 0
    k := 0

    result := []int{}

    for i < len(arr1) && j < len(arr2) && k < len(arr3) {

        if arr1[i] == arr2[j] && arr2[j] == arr3[k] {
            result = append(result, arr1[i])

            i++
            j++
            k++
        } else {

            minimumValue := arr1[i]

            if arr2[j] < minimumValue {
                minimumValue = arr2[j]
            }

            if arr3[k] < minimumValue {
                minimumValue = arr3[k]
            }

            if arr1[i] == minimumValue {
                i++
            } else if arr2[j] == minimumValue {
                j++
            } else {
                k++
            }
        }
    }

    return result
}
```Go 实现在结构上与 Python 解决方案相同。 

一个小小的区别是 Go 没有提供内置的`min()`函数以与 Python 相同的方式处理多个整数，因此我们手动计算最小值。 

结果存储在初始化为空切片的切片中。 返回空切片自然可以处理不存在交集的情况。 

不存在整数溢出问题，因为约束非常小，值上限为 2000。

 ## 边缘情况

 当根本没有共同元素时，就会出现一种重要的边缘情况。 有错误的实现可能会继续进行不必要的扫描或意外地包含部分匹配项。 三指针方法自然地处理了这个问题，因为指针不断前进，直到一个数组耗尽，此时循环终止并返回一个空结果。 

另一种重要的情况是数组仅包含一个元素。 小输入通常会因一个错误或不正确的循环条件而暴露。 由于循环在每次比较之前检查指针边界，因此该实现可以安全地处理长度为 1 的数组。 

第三个重要的边缘情况是公共元素仅出现在数组末尾附近。 一些不正确的实现可能会在多次不匹配后过早停止搜索。 该算法继续系统地进行，因为最小的指针总是前进，直到检查了所有可能的匹配。 

第四种微妙的情况是一个数组比其他数组短得多。 由于一旦任何指针到达末尾循环就会停止，因此该实现避免了不必要的工作并且仍然保证了正确性。
