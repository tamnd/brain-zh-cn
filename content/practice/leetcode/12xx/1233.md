[LeetCode 问题 1233](https://leetcode.com/problems/remove-sub-folders-from-the-filesystem/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、深度优先搜索、Trie

 ## 解决方案

 ## 问题理解

 这个问题要求我们处理文件夹路径列表并删除所有**子文件夹**，仅返回顶级文件夹。 一个文件夹`"/a/b"`被视为子文件夹`"/a"`因为它嵌套在其中。 关键细节是子文件夹必须以父文件夹路径开头，后跟`'/'`。 这可以确保我们避免文件夹名称可能部分匹配的误报，例如`"/ab"`**不是** 的子文件夹`"/a"`。 

输入是唯一文件夹字符串的列表，其中每个字符串代表一个以 开头的有效 Unix 样式路径`'/'`并由小写字母组成。 预期的输出是文件夹列表，其中没有文件夹是另一个文件夹的子文件夹，并且文件夹的顺序并不重要。 

约束告诉我们输入可以很大，最多 40,000 个文件夹，每个文件夹最多 100 个字符长。 这表明朴素的成对比较 (O(n²)) 可能太慢，我们需要一种更结构化的方法。 边缘情况包括具有共同前缀但没有嵌套的文件夹、深度嵌套的文件夹以及具有相同父级但不同子级的文件夹。 

## 方法

 **暴力方法**将涉及将每个文件夹与其他每个文件夹进行比较，以检查它是否是子文件夹。 这很简单，但效率很低。 对于每个文件夹，我们将扫描其余文件夹以查看文件夹路径是否以当前文件夹加上`'/'`。 此方法的时间复杂度为 O(n² * k)，其中`n`是文件夹的数量，`k`是文件夹字符串的平均长度，不适合输入的上限。 

**最佳方法**依赖于对文件夹进行排序，然后使用前缀检查来消除子文件夹。 如果我们按字典顺序对文件夹进行排序，则所有子文件夹将直接显示在其父文件夹之后。 然后我们可以遍历排序列表并维护最后添加的顶级文件夹。 对于每个新文件夹，如果它以前一个文件夹开头加上`'/'`，是子文件夹，跳过； 否则，将其添加到结果列表中。 这种方法非常有效，因为排序会将潜在的子文件夹分组在一起，并减少重复比较的需要。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² * k) | O(n) | 将每个文件夹与其他每个文件夹进行比较以检查前缀 |
 | 最佳| O(n * k log n) | O(n * k log n) | O(n * k) | 通过前缀比较对文件夹进行排序并删除子文件夹 |

 ## 算法演练

 1. **按字典顺序对文件夹进行排序**。 这可确保任何子文件夹都紧随其父文件夹之后。 
2. **初始化一个结果列表**来保存顶级文件夹和变量`prev`跟踪最后添加的文件夹。 
3. **遍历已排序的文件夹**：

 - 对于每个文件夹，检查它是否以`prev + '/'`。 
- 如果是，则它是一个子文件夹并被跳过。 
- 如果没有，则将该文件夹追加到结果列表中并更新`prev`到这个文件夹。 
4. **返回包含所有顶级文件夹的结果列表**。 

**为什么有效：** 排序可保证所有子文件夹立即跟随其父文件夹。 通过维护最后添加的顶级文件夹（`prev`），我们可以有效地检查当前文件夹是否嵌套，而无需扫描整个列表，在保持正确性的同时降低时间复杂度。 

## Python 解决方案```python
from typing import List

class Solution:
    def removeSubfolders(self, folder: List[str]) -> List[str]:
        folder.sort()
        result = []
        prev = ""
        for f in folder:
            if not prev or not f.startswith(prev + "/"):
                result.append(f)
                prev = f
        return result
```在此实现中，首先对文件夹进行排序，以将潜在的子文件夹与其父文件夹分组。 这`prev`变量存储最后添加到的顶级文件夹`result`。 对于每个文件夹，我们检查它是否以`prev + "/"`。 如果没有，则它是一个新的顶级文件夹并添加到结果中。 这可确保不添加子文件夹。 

## 解决方案```go
import (
    "sort"
    "strings"
)

func removeSubfolders(folder []string) []string {
    sort.Strings(folder)
    result := []string{}
    prev := ""
    for _, f := range folder {
        if prev == "" || !strings.HasPrefix(f, prev+"/") {
            result = append(result, f)
            prev = f
        }
    }
    return result
}
```Go 实现镜像了 Python 版本。 排序是使用完成的`sort.Strings`。 这`strings.HasPrefix`函数检查文件夹是否是以下文件夹的子文件夹`prev`。 这`prev`变量跟踪最后添加的顶级文件夹，结果切片累积最终文件夹。 

## 工作示例

 **示例1：**`folder = ["/a","/a/b","/c/d","/c/d/e","/c/f"]`排序后：`["/a", "/a/b", "/c/d", "/c/d/e", "/c/f"]`迭代：

 | 文件夹| 上一页 | 行动| 结果|
 | ---| ---| ---| ---|
 | /a | “” | 添加| [“/a”] |
 | /a/b | “/a” | 跳过| [“/a”] |
 | /c/d | “/a” | 添加| [“/a”，“/c/d”] |
 | /c/d/e | “/c/d” | 跳过| [“/a”，“/c/d”] |
 | /c/f | “/c/d” | 添加| [“/a”，“/c/d”，“/c/f”] |

 输出：`["/a", "/c/d", "/c/f"]`**示例2：**`folder = ["/a","/a/b/c","/a/b/d"]`排序：`["/a", "/a/b/c", "/a/b/d"]`迭代：仅`"/a"`被添加，其他被跳过。 

**示例3：**`folder = ["/a/b/c","/a/b/ca","/a/b/d"]`排序：`["/a/b/c","/a/b/ca","/a/b/d"]`迭代：没有一个是彼此的子文件夹，全部添加。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * k log n) | O(n * k log n) | 排序需要 O(n log n)，每个文件夹的前缀检查需要 O(k) |

 排序在时间复杂度上占主导地位。 前缀检查与文件夹数量和平均文件夹长度呈线性关系。

 ## 边缘情况

 一种边缘情况是输入中的单个文件夹。 该算法可以自然地处理它，因为对单个项目进行排序并迭代将其添加到结果中。 另一个边缘情况是具有相似前缀但不是真正的子文件夹的文件夹，例如，`"/a"`和`"/ab"`。 该算法可以正确地区分它们，因为它会检查`prev + "/"`。 最后，深层嵌套的文件夹，例如，`"/a/b/c/d"`，都被正确处理，因为仅存储顶级文件夹，并且在迭代期间跳过所有嵌套子文件夹。 排序和前缀检查的组合可确保这些场景的正确性。
