[LeetCode 第 1243 题](https://leetcode.com/problems/array-transformation/)

 **难度：** 🟢简单
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 该问题需要根据简单的局部规则模拟连续几天内数组的转换。 每天，数组的每个元素（第一个和最后一个除外）都会与其紧邻的元素进行比较。 如果一个元素小于两个邻居，则增加 1。如果大于两个邻居，则减少 1。既不是峰也不是谷的元素保持不变。 模拟继续进行，直到数组在几天之间停止变化，此时返回最终数组。 

输入，`arr`，是表示数组起始状态的整数列表。 预期输出是代表数组稳定后的另一个整数列表。 约束告诉我们，数组相对较小，最多有 100 个元素，所有值都在 1 到 100 之间。这表明简单的模拟是可行的，无需考虑性能问题。 

边缘情况包括已经稳定的数组、具有防止任何更改的相同相邻元素的数组，以及重复转换将更改从一侧传播到另一侧的数组。 该问题保证第一个和最后一个元素永远不会改变，从而简化了边界处理。 

## 方法

 蛮力方法是对问题中描述的规则的直接模拟。 每天，都会根据前一天构建一个新数组，将每个元素与其邻居进行比较并应用递增或递减规则。 重复此过程，直到没有发生任何变化。 虽然这很简单且易于实现，但它涉及重复扫描阵列，理论上这可能需要花费`O(max(arr) * n)`如果元素逐渐收敛，则步骤。 

更优化方法的关键见解是问题规模很小（`n <= 100`）并且值有界（`arr[i] <= 100`）。 这使我们能够使用直接的模拟，而不必担心效率，因为稳定之前的迭代次数是有限的。 因此，除了仔细模拟之外，不需要进行高级优化。 重点应该是正确应用规则，而不是在迭代中间修改数组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力/模拟| O(n * m) | O(n) |`n`是数组长度，`m`是距离稳定的天数。 小输入允许这种方法|
 | 最佳 | O(n * m) | O(n) | 相同的模拟方法，每次迭代都仔细复制数组以避免就地修改问题 |

 ## 算法演练

 1. 初始化一个循环来重复变换，直到数组不再发生变化。 
2. 在每次迭代时，创建当前数组的副本以存储更改。 这确保更新不会影响同一天内的邻居比较。 
3. 从第二个元素到倒数第二个元素迭代数组。 
4. 对于每个元素，将其与其左右邻居进行比较。 如果它比两者都小，则在副本中增加它。 如果它比两者都大，则在副本中减少它。 
5. 处理完所有元素后，检查新数组是否与当前数组相同。 
6. 如果相同，则断开循环； 否则，用新数组替换当前数组并重复。 
7. 返回最终稳定的数组。 

工作原理：该算法保留了每天的转换仅取决于前一天的值的不变性。 通过使用单独的副本进行更新，邻居比较始终保持一致。 由于所有值都是整数且有界，并且每个元素都趋向平衡，因此保证数组在有限步数后稳定。 

## Python 解决方案```python
from typing import List

class Solution:
    def transformArray(self, arr: List[int]) -> List[int]:
        changed = True
        n = len(arr)
        while changed:
            changed = False
            new_arr = arr[:]
            for i in range(1, n - 1):
                if arr[i] < arr[i - 1] and arr[i] < arr[i + 1]:
                    new_arr[i] += 1
                    changed = True
                elif arr[i] > arr[i - 1] and arr[i] > arr[i + 1]:
                    new_arr[i] -= 1
                    changed = True
            arr = new_arr
        return arr
```实现首先初始化一个`changed`标记以跟踪一天内是否发生任何更新。 我们循环直到不进行任何更改。 在每次迭代时，都会生成数组的副本`new_arr`被创建。 然后，对于每个非边界元素，代码应用基于邻居的递增/递减规则。 如果发生任何变化，则设置该标志。 处理后，当前数组将被更新后的副本替换。 这一直持续到阵列稳定为止，确保正确性。 

## 解决方案```go
func transformArray(arr []int) []int {
    n := len(arr)
    changed := true
    for changed {
        changed = false
        newArr := make([]int, n)
        copy(newArr, arr)
        for i := 1; i < n-1; i++ {
            if arr[i] < arr[i-1] && arr[i] < arr[i+1] {
                newArr[i]++
                changed = true
            } else if arr[i] > arr[i-1] && arr[i] > arr[i+1] {
                newArr[i]--
                changed = true
            }
        }
        arr = newArr
    }
    return arr
}
```在 Go 中，我们使用`make`和`copy`每次迭代创建一个新切片，确保我们在处理过程中不会覆盖原始值。 逻辑与 Python 相同，但要特别注意索引和切片复制。 不用担心由于输入限制而导致整数溢出。

 ## 边缘情况

 第一个边缘情况是所有元素都相等的数组。 在这种情况下，任何元素都不会比其邻居更小或更大，因此数组已经稳定。 该实现通过检查更改并立即返回来正确处理此问题。 

第二种边缘情况涉及数组，其中元素形成严格的单调序列。 在这里，内部元素永远不是局部最大值或最小值，因此不会发生更新。 这验证了算法没有执行不必要的操作。 

第三种边缘情况是一个数组，其中交替的峰和谷在多次迭代中传播变化。 每个元素可能需要多次调整才能达到平衡。 使用单独的数组进行更新可确保中间更改不会影响同一迭代中的邻居比较，从而使算法能够正确收敛。
