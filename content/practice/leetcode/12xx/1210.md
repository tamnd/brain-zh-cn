[LeetCode 问题 1210](https://leetcode.com/problems/minimum-moves-to-reach-target-with-rotations/)

 **难度：** 🔴难
 **主题：** 数组、广度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 该问题模拟了网格上的最短路径搜索，但移动对象不是单个单元格。 相反，该对象是一条蛇，恰好占据两个相邻的单元格。 蛇从以下位置开始水平方向`(0,0)`和`(0,1)`，目标是将其移动到右下角，使其占据`(n-1,n-2)`和`(n-1,n-1)`。 

网格仅包含两个值：

 -`0`代表蛇可能占据的空单元格。 
-`1`代表蛇无法进入的被封锁的单元格。 

根据当前的方向，蛇可以执行四种不同的动作：

 - 向右移动
 - 向下移动
 - 从水平到垂直顺时针旋转
 - 从垂直逆时针旋转到水平

 每一个有效的动作都只花费一步。 任务是计算达到目标配置所需的最小移动次数。 如果不存在有效的移动序列，则答案是`-1`。 

重要的细节是蛇的状态是由它的位置和方向决定的。 头部坐标相同但方向不同的两个状态是完全不同的配置。 

对于图遍历来说约束足够小：

 -`2 <= n <= 100`- 网格大小最多为`100 x 100`简单的递归探索会多次重新访问相同的状态，并很快呈指数级增长。 然而，不同蛇状态的总数是可控的。 对于每个单元格，蛇可能是水平的或垂直的，大致给出`2 * n^2`可能的状态。 这强烈建议使用图搜索方法，例如广度优先搜索。 

一些边缘情况很重要：

 - 由于墙壁阻挡了所有路径，目标可能无法到达。 
- 旋转需要同时检查两个单元，这很容易错误地实现。 
- 边界附近的移动可能会导致出界错误。 
- 可以通过多个路径重新访问配置，因此访问状态跟踪至关重要。 
- 同一锚点位置的水平和垂直状态必须分开处理。 

## 方法

 ### 蛮力方法

 强力解决方案将从起始配置递归地探索每个可能的移动序列。 在每个状态，我们都会尝试所有有效的操作：

 - 向右移动
 - 向下移动
 - 旋转

 递归将继续，直到达到目标或不可能进一步移动。 

这种方法是正确的，因为它最终会探索每个可到达的配置。 然而，它的效率极低，因为可以通过许多不同的路径到达相同的状态。 如果没有记忆或访问跟踪，该算法会重复重新计算相同的子问题。 

即使有记忆，深度优先策略自然也不能保证最短路径。 我们仍然需要额外的簿记以确保最少的移动计数。 

可能的移动序列的数量呈指数增长，使得暴力破解对于大到不切实际的网格`100 x 100`。 

### 最优方法，广度优先搜索

 关键的观察是，这个问题本质上是隐式图上的最短路径问题。 

每个蛇配置代表一个图节点：

 - 蛇的位置
 - 蛇的方向

 每个有效的移动代表一条具有均匀权重的边`1`。 

当所有边的成本相等时，广度优先搜索就能保证最短路径。 BFS 逐级探索状态，这意味着我们第一次达到目标配置时，我们就找到了最小移动次数。 

状态总数大约为`2 * n^2`，对于 BFS 来说足够小。 

最重要的设计选择是如何表示状态。 一个干净的表示是：

 -`(row, col, orientation)`在哪里`(row, col)`代表蛇的左上角或最上面的单元格：

 - 水平：占据`(row,col)`和`(row,col+1)`- 垂直：占据`(row,col)`和`(row+1,col)`这种紧凑的表示使转换和边界检查变得简单。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 递归探索所有移动序列 |
 | 最优 BFS | O(n²) | O(n²) | 所有有效蛇状态的最短路径搜索

 ## 算法演练

 1. 将每个蛇配置表示为一个状态`(row, col, orientation)`。 

方向可以编码为：

 -`0`用于水平
 -`1`垂直用

 如果蛇是水平的，它占据：

 -`(row,col)`-`(row,col+1)`如果是垂直的，它占据：

 -`(row,col)`-`(row+1,col)`2. 使用起始状态初始化 BFS 队列。 

蛇的水平起点为：

 -`(0,0)`-`(0,1)`所以初始状态是：

 -`(0,0,0)`我们还初始化访问集以避免重新访问状态。 
3. 使用 BFS 逐级处理状态。 

每个 BFS 层代表在相同移动次数下可到达的所有状态。 该属性保证了最短路径的正确性。 
4. 对于每个出列状态，检查其是否与目标匹配。 

目标配置水平位于：

 -`(n-1,n-2)`-`(n-1,n-1)`因此目标状态是：

 -`(n-1,n-2,0)`5. 生成所有有效的下一个状态。 

如果蛇是水平的：

 - 向右移动：

 - 检查`(row,col+2)`位于边界内且为空。 
- 向下移动：

 - 检查下面的两个单元格是否为空。 
- 顺时针旋转：

 - 与向下移动的条件相同。 
- 过渡到垂直方向。 
6. 处理垂直方向的过渡。 

如果蛇是垂直的：

 - 向下移动：

 - 检查`(row+2,col)`是空的。 
- 向右移动：

 - 检查右侧的两个单元格是否为空。 
- 逆时针旋转：

 - 与向右移动相同的条件。 
- 过渡到水平方向。 
7. 将未访问的有效状态添加到队列中。 

每个新发现的状态在入队之前都会被标记为已访问。 这可以防止重复处理。 
8. 继续 BFS，直到：

 - 达到目标状态，返回移动计数。 
- 队列变空，返回`-1`。 

### 为什么它有效

 广度优先搜索以移动计数递增的顺序探索状态。 该状态图中的每条边都有统一的成本`1`，所以BFS第一次到达目标状态一定对应着最小的移动次数。 

访问集保证每个状态最多处理一次，防止循环和冗余工作。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def minimumMoves(self, grid: List[List[int]]) -> int:
        n = len(grid)

        # orientation:
        # 0 = horizontal
        # 1 = vertical

        target = (n - 1, n - 2, 0)

        queue = deque([(0, 0, 0, 0)])
        visited = {(0, 0, 0)}

        while queue:
            row, col, orientation, moves = queue.popleft()

            if (row, col, orientation) == target:
                return moves

            if orientation == 0:
                # Move right
                if (
                    col + 2 < n
                    and grid[row][col + 2] == 0
                ):
                    next_state = (row, col + 1, 0)

                    if next_state not in visited:
                        visited.add(next_state)
                        queue.append((row, col + 1, 0, moves + 1))

                # Move down
                if (
                    row + 1 < n
                    and grid[row + 1][col] == 0
                    and grid[row + 1][col + 1] == 0
                ):
                    next_state = (row + 1, col, 0)

                    if next_state not in visited:
                        visited.add(next_state)
                        queue.append((row + 1, col, 0, moves + 1))

                    # Rotate clockwise
                    next_state = (row, col, 1)

                    if next_state not in visited:
                        visited.add(next_state)
                        queue.append((row, col, 1, moves + 1))

            else:
                # Move down
                if (
                    row + 2 < n
                    and grid[row + 2][col] == 0
                ):
                    next_state = (row + 1, col, 1)

                    if next_state not in visited:
                        visited.add(next_state)
                        queue.append((row + 1, col, 1, moves + 1))

                # Move right
                if (
                    col + 1 < n
                    and grid[row][col + 1] == 0
                    and grid[row + 1][col + 1] == 0
                ):
                    next_state = (row, col + 1, 1)

                    if next_state not in visited:
                        visited.add(next_state)
                        queue.append((row, col + 1, 1, moves + 1))

                    # Rotate counterclockwise
                    next_state = (row, col, 0)

                    if next_state not in visited:
                        visited.add(next_state)
                        queue.append((row, col, 0, moves + 1))

        return -1
```其实现直接遵循前面描述的 BFS 算法。 

队列存储四个值：

 -`row`-`col`-`orientation`-`moves`前三个唯一地标识状态，而`moves`跟踪 BFS 深度。 

访问集可防止重新访问配置。 由于 BFS 保证最短路径排序，因此我们第一次访问某个状态总是最优的。 

逻辑分为两个分支：

 - 水平蛇处理
 - 垂直蛇处理

 每个分支都会检查该方向的所有合法转换。 

对于移动操作，边界检查和障碍物检查可确保蛇永远不会与阻挡的单元格重叠或退出网格。 

旋转逻辑值得特别注意。 旋转需要检查`2 x 2`围绕蛇形成正方形，因为在旋转过程中涉及的两个单元格都必须是空的。 

## 解决方案```go
package main

import "container/list"

func minimumMoves(grid [][]int) int {
	n := len(grid)

	type State struct {
		row         int
		col         int
		orientation int
		moves       int
	}

	targetRow := n - 1
	targetCol := n - 2

	queue := list.New()
	queue.PushBack(State{0, 0, 0, 0})

	visited := make(map[[3]int]bool)
	visited[[3]int{0, 0, 0}] = true

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		current := front.Value.(State)

		row := current.row
		col := current.col
		orientation := current.orientation
		moves := current.moves

		if row == targetRow && col == targetCol && orientation == 0 {
			return moves
		}

		if orientation == 0 {
			// Move right
			if col+2 < n && grid[row][col+2] == 0 {
				next := [3]int{row, col + 1, 0}

				if !visited[next] {
					visited[next] = true
					queue.PushBack(State{row, col + 1, 0, moves + 1})
				}
			}

			// Move down and rotate clockwise
			if row+1 < n &&
				grid[row+1][col] == 0 &&
				grid[row+1][col+1] == 0 {

				down := [3]int{row + 1, col, 0}

				if !visited[down] {
					visited[down] = true
					queue.PushBack(State{row + 1, col, 0, moves + 1})
				}

				rotate := [3]int{row, col, 1}

				if !visited[rotate] {
					visited[rotate] = true
					queue.PushBack(State{row, col, 1, moves + 1})
				}
			}

		} else {
			// Move down
			if row+2 < n && grid[row+2][col] == 0 {
				next := [3]int{row + 1, col, 1}

				if !visited[next] {
					visited[next] = true
					queue.PushBack(State{row + 1, col, 1, moves + 1})
				}
			}

			// Move right and rotate counterclockwise
			if col+1 < n &&
				grid[row][col+1] == 0 &&
				grid[row+1][col+1] == 0 {

				right := [3]int{row, col + 1, 1}

				if !visited[right] {
					visited[right] = true
					queue.PushBack(State{row, col + 1, 1, moves + 1})
				}

				rotate := [3]int{row, col, 0}

				if !visited[rotate] {
					visited[rotate] = true
					queue.PushBack(State{row, col, 0, moves + 1})
				}
			}
		}
	}

	return -1
}
```Go 的实现与 Python 解决方案非常相似。 

一个`State`struct 存储 BFS 状态信息。 Go 没有像 Python 那样的元组，所以我们使用固定大小的数组`[3]int`作为访问过的州的地图键。 

队列是使用以下方式实现的`container/list`，提供高效的正面移除和背面插入。 

由于所有值都适合标准整数范围，因此不必担心整数溢出。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n²) | 每个状态最多处理一次 |
 | 空间| O(n²) | 几乎所有州都排队并光顾过设置商店|

 最多有`2 * n²`可能的蛇状态，因为每个单元都可以与两个方向之一配对。 

对于每个状态，我们仅执行恒定时间转换检查。 因此，总处理时间与状态数量成正比。 

队列和访问集还存储了大多数可到达的状态，从而给出`O(n²)`空间复杂度。

 ## 边缘情况

 一种重要的边缘情况发生在网格边界附近。 当蛇尝试向右或向下移动时，很容易意外访问网格外的索引。 例如，最右边缘的水平蛇无法进一步向右移动，因为它的第二个单元格将超出网格边界。 该实现在访问网格单元之前仔细检查边界。 

另一个关键的边缘情况涉及旋转。 仅当整个旋转都有效时，旋转才有效`2 x 2`参与旋转的区域是空的。 一个常见的错误是仅检查目标单元格而不是两个必需的单元格。 该实现在允许旋转之前显式检查水平蛇形下方的两个单元格以及垂直蛇形右侧的两个单元格。 

第三个重要的边缘情况是重新审视各州。 通常可以通过多个路径到达相同的板配置。 如果没有访问集，BFS 将重复处理相同的状态，从而导致严重的低效率和潜在的无限循环。 该实现在状态入队时立即将状态标记为已访问，确保每个状态只处理一次。 

另一个微妙的例子是区分方向。 各州`(r,c,H)`和`(r,c,V)`即使它们共享相同的锚坐标，也是不可互换的。 将它们视为相同会错误地消除有效路径。 该实现将方向存储为访问状态键的一部分，保证正确的行为。
