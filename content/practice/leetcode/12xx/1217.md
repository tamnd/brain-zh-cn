[LeetCode 第 1217 题](https://leetcode.com/problems/minimum-cost-to-move-chips-to-the-same-position/)

 **难度：** 🟢简单
 **主题：** 数组、数学、贪心

 ## 解决方案

 ## 问题理解

 问题要求我们移动`n`芯片位于沿一维线的不同位置，以便它们最终都位于同一位置。 每个芯片可以以 0 成本移动 2 个单位，也可以以 1 成本移动 1 个单位。输入是一个整数数组，`position`， 在哪里`position[i]`表示的位置`i`-th 芯片。 输出是一个整数，表示将所有筹码移动到公共位置所需的最小成本。 

约束告诉我们数组长度适中（`1 <= position.length <= 100`），但头寸本身可能非常大（`1 <= position[i] <= 10^9`）。 这表明我们不能依赖迭代最小和最大筹码位置之间的每个可能位置的算法，因为范围可能非常大。 相反，我们需要利用动作本身的一些特性。 

重要的边缘情况包括所有芯片都已位于同一位置的阵列（最小成本 = 0）、只有一个芯片的阵列、芯片位于极远位置的阵列（例如，`[1, 1000000000]`），以及所有芯片都位于偶数或奇数位置的数组。 

关键的观察是，将芯片移动 2 个单位的成本为 0，这意味着芯片可以在相同奇偶性（偶数↔偶数或奇数↔奇数）的位置之间自由移动，而不会产生任何成本。 在偶数和奇数位置之间移动的成本为 1。这种奇偶性洞察力是有效解决问题的关键。 

## 方法

 暴力方法会考虑数组的最小值和最大值之间的每个位置，并计算将所有芯片移动到该位置的总成本。 对于每个芯片，如果差异为偶数，则成本将为 0；如果差异为奇数，成本将为 1。 虽然正确，但这种方法效率低下，因为位置值可能高达`10^9`，使得迭代每个可能的位置都不可行。 

最佳方法利用奇偶校验属性。 我们只需要统计有多少个筹码在偶数位置，有多少个筹码在奇数位置。 将所有筹码移动到偶数位置会产生等于奇数位置筹码数量的成本，将所有筹码移动到奇数位置会产生等于偶数位置筹码数量的成本。 因此，最小成本就是两个计数中较小的一个。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((最大(位置)-最小(位置)) * n) | O(1) | O(1) | 迭代每个仓位并对成本求和，这对于大型仓位来说是不可行的 |
 | 最佳 | O(n) | O(1) | O(1) | 计算偶数和奇数位置的筹码，然后取最小计数 |

 ## 算法演练

 1. 初始化两个计数器：`even_count`和`odd_count`为零。 这些将分别跟踪偶数和奇数位置的芯片数量。 
2. 迭代`position`大批。 
3. 对于每个`pos`，检查它是偶数还是奇数。 如果`pos % 2 == 0`, 增量`even_count`。 否则，增加`odd_count`。 
4. 迭代完所有芯片后，计算最小成本为`min(even_count, odd_count)`。 
5.返回最低成本。 

原理：筹码可以零成本在相同奇偶性的位置之间自由移动。 因此，唯一的成本来自于移动芯片跨越奇偶校验边界。 通过计算每个奇偶校验组中的芯片数量，我们可以准确地知道有多少芯片必须产生成本才能将所有芯片统一为单个奇偶校验，从而保证最低成本的解决方案。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCostToMoveChips(self, position: List[int]) -> int:
        even_count = 0
        odd_count = 0
        
        for pos in position:
            if pos % 2 == 0:
                even_count += 1
            else:
                odd_count += 1
        
        return min(even_count, odd_count)
```实现直接遵循算法。 我们迭代每个芯片，计算偶数和奇数位置的芯片数量。 结果只是两个计数中较小的一个，代表必须跨越奇偶校验边界的芯片的最小数量。 

## 解决方案```go
func minCostToMoveChips(position []int) int {
    evenCount := 0
    oddCount := 0
    
    for _, pos := range position {
        if pos%2 == 0 {
            evenCount++
        } else {
            oddCount++
        }
    }
    
    if evenCount < oddCount {
        return evenCount
    }
    return oddCount
}
```在 Go 中，我们迭代切片并为偶数和奇数位置维护两个整数计数器。 由于 Go 缺少内置的 if 语句，因此 min 比较是使用简单的 if 语句完成的`min`整数函数。 由于限制，像空切片这样的边缘情况是不可能的。

 ## 边缘情况

 关键的边缘情况是所有芯片都已位于同一位置。 在这种情况下，要么所有筹码都是偶数，要么都是奇数，我们的计数器反映了这一点，导致最低成本为零。 

另一种边缘情况是芯片占据极大的位置但数量仍然很少，例如`[1, 1000000000]`。 我们的算法只关心奇偶校验，因此数字的大小不会影响正确性，避免了性能问题。 

第三种边缘情况是所有芯片都在一个奇偶校验组中，而一个芯片在另一奇偶校验组中。 例如，`[2,4,6,1]`。 最小成本应为 1，对应于将单个奇数筹码移动到偶数位置。 该算法自然地处理这个问题，因为它只取最小计数。
