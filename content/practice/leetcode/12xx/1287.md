[LeetCode 问题 1287](https://leetcode.com/problems/element-appearing-more-than-25-in-sorted-array/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个按非降序排序的整数数组。 我们保证只有一个元素在数组中出现的次数超过 25%，因此我们需要返回该元素。 

换句话说，在数组中的所有数字中，有一个值的频率严格大于`n / 4`， 在哪里`n`是数组的长度。 由于数组已经排序，因此相等的值会一起出现在连续的块中。 这个排序属性是让我们能够有效解决问题的关键观察结果。 

输入是：

 - 已排序的数组`arr`- 之间的长度`1`和`10^4`- 值之间`0`和`10^5`输出是：

 - 出现次数超过 25% 的单个整数

 约束相对较小，因此即使`O(n)`或者`O(n log n)`解决方案很容易通过。 然而，输入的排序性质使我们能够避免不必要的工作并产生非常干净的解决方案。 

尽早考虑几个边缘情况很重要：

 - 长度数组`1`，其中唯一的元素必须是答案
 - 频繁元素出现在开头的数组
 - 频繁元素出现在末尾的数组
 - 频繁元素仅超过 25% 阈值的数组
 - 具有所有相同元素的数组

 该问题还保证存在一个有效答案，因此我们永远不需要处理歧义或缺失结果。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是使用哈希图来计算每个数字的频率。 

我们迭代数组，将计数存储在字典中，然后检查哪个数字的频率大于`n // 4`。 

这种方法之所以有效，是因为我们明确计算了每个值的确切频率。 一旦频率已知，识别有效元素就很简单了。 

但是，该解决方案忽略了数组已排序的事实。 即使排序顺序已经将相等的值分组在一起，它也会为哈希映射使用额外的内存。 

### 最佳方法

 关键的见解来自排序的属性。 

如果某个元素出现的次数超过 25%，则在任何大小的块内`n / 4`，该元素必须重复。 更具体地说，对于某些索引`i`，值在`arr[i]`必须等于`arr[i + n/4]`。 

由于相同的元素在排序数组中是连续的，因此检查此条件足以识别特殊元素。 

例如：```
arr = [1,2,2,6,6,6,6,7,10]
n = 9
threshold = 9 // 4 = 2
```元素`6`出现四次。 如果我们比较：```
arr[3] == arr[5]
6 == 6
```然后我们立即知道`6`跨度超过`threshold`职位。 

这让我们能够在具有恒定额外空间的线性时间内解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 使用哈希图计算频率 |
 | 最佳| O(n) | O(1) | O(1) | 利用排序顺序和距离检查 |

 ## 算法演练

 ### 最优算法

 1. 计算数组的长度，`n`。 
2. 计算阈值距离：```
threshold = n // 4
```如果一个元素出现的次数超过 25%，则必须存在两个相等的元素，其间隔至少为该距离。 
3. 从索引处迭代数组`0`到`n - threshold - 1`。 

在每个索引处`i`， 比较：```
arr[i] and arr[i + threshold]
```4. 如果这两个值相等，则立即返回该值。 

这是可行的，因为排序数组中的相等值形成一个连续块。 如果相同的值出现在由`threshold`，那么它的频率必须超过25%。 
5. 由于问题保证只有一个有效答案，因此算法总是会找到并返回一个结果。 

### 为什么它有效

 正确性依赖于排序数组中相等值的连续性。 

假设一个值出现超过`n / 4`次。 那么它的块长度严格大于`threshold = n // 4`。 因此，在该块内，必须存在索引`i`和`i + threshold`包含相同的值。 

相反，如果`arr[i] == arr[i + threshold]`，那么该值的范围超过`threshold`位置，这意味着它出现的时间超过 25%。 

因为问题保证恰好存在一个这样的元素，所以我们找到的第一个匹配就是正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findSpecialInteger(self, arr: List[int]) -> int:
        n = len(arr)
        threshold = n // 4

        for i in range(n - threshold):
            if arr[i] == arr[i + threshold]:
                return arr[i]

        return -1
```实现首先计算数组长度和阈值`n // 4`。 

循环仅在 while 时运行`i + threshold`保留在数组边界内。 在每个位置，我们将当前值与值进行比较`threshold`位置领先。 

如果两个值相等，则排序属性保证该值占据足够大的连续范围以超过 25% 的频率。 

该函数立即返回匹配值，因为该问题保证存在一个有效答案。 

决赛`return -1`在问题限制下，技术上是不必要的，但它被作为安全后备措施包括在内。 

## 解决方案```go
func findSpecialInteger(arr []int) int {
	n := len(arr)
	threshold := n / 4

	for i := 0; i < n-threshold; i++ {
		if arr[i] == arr[i+threshold] {
			return arr[i]
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 中的切片已经提供了类似于数组的索引访问，因此不需要额外的数据结构。 整数除法自动截断为零，从而正确计算`n / 4`。 

和Python的解决方案一样，最终的`return -1`只是一个后备方案，永远不应该在有效的问题约束下执行。

 ## 边缘情况

 一个重要的边缘情况是单元素数组，例如`[5]`。 由于唯一的元素 100% 出现，因此它一定是答案。 该实现自然地处理了这个问题，因为阈值变为`0`，第一次比较立即成功。 

另一个重要的情况是当频繁元素出现在数组的开头或结尾时。 一些实现错误地假设频繁块必须出现在中间。 例如，`[2,2,2,3,4,5]`和`[1,2,3,4,4,4]`两者都能正常工作，因为算法会检查每个有效的起始索引。 

当阈值变为零时，会发生微妙的边缘情况，这种情况发生在非常小的数组（例如长度）上`1`,`2`， 或者`3`。 在这些情况下，比较就变成了`arr[i] == arr[i]`，这始终是正确的。 这仍然是正确的，因为问题保证存在一个有效答案，因此返回第一个元素是有效的。 

另一个重要的情况是当所有元素都相同时，例如`[7,7,7,7]`。 该算法立即检测阈值距离上的相等性并返回重复值，无需任何特殊处理。
