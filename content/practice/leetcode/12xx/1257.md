[LeetCode 1257 题](https://leetcode.com/problems/smallest-common-region/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、树、深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题描述了地理区域之间的层次关系。 每个列表中`regions`表示父子关系，其中第一个元素是父区域，列表中的每个剩余元素都直接包含在该父区域中。 

例如，列表：```
["North America", "United States", "Canada"]
```意味着`"North America"`直接包含`"United States"`和`"Canada"`。 

层次结构形成树形结构。 除根之外的每个区域都只有一个父区域，因为该问题保证一个区域不能直接包含在多个区域中。 还保证有一个间接包含所有其他区域的顶级区域。 

目标是找到包含两者的最小区域`region1`和`region2`。 在树术语中，这是最低共同祖先，通常缩写为 LCA。 

例如：

-`"Quebec"`属于`"Canada"`-`"Canada"`属于`"North America"`-`"New York"`属于`"United States"`-`"United States"`属于`"North America"`包含两者的最小区域`"Quebec"`和`"New York"`因此是`"North America"`。 

这些约束告诉我们一些重要的事情：

 -`regions.length <= 10^4`, which means we need an efficient solution
 - 每个区域名称都很短，因此字符串操作成本低廉
 - 每个节点至多有一个父节点，这强烈暗示了树结构
 - 答案肯定存在，所以我们永远不需要处理断开连接的图

 Important edge cases include situations where:

 - One region is an ancestor of the other
 - The common ancestor is the root region
 - 这棵树很深
 - 这些地区属于完全不同的分支

 对于深层树来说，重复搜索层次结构的简单实现可能会变得低效，因此我们需要一种快速追踪祖先关系的方法。 

## 方法

 ### 蛮力方法

 暴力解决方案将反复搜索整个`regions`列表以确定父母关系。 

对于从`region1`，我们可以扫描所有列表以查找包含它的区域。 然后我们可以做同样的事情`region2`。 生成两个祖先链后，我们可以比较它们以找到第一个共同区域。 

这种方法之所以有效，是因为最终两条路径都到达根，并且第一个共享祖先是最小的公共区域。 

然而，问题是效率。 每次我们想要找到父级时，我们可能需要扫描整个输入。 由于层次结构最多可以包含`10^4`区域，重复扫描变得不必要的昂贵。 

### 最佳方法

 关键的观察结果是，层次结构形成一棵树，其中每个节点都只有一个父节点。 

我们可以将输入预处理为哈希映射，而不是重复搜索父母：```
child -> parent
```一旦我们有了直接的父级查找，我们就可以有效地向上遍历树。 

算法变为：

 1. 构建父图
 2. 向上走`region1`并将所有祖先存储在一个集合中
 3. 向上走`region2`4. 始祖`region2`出现在集合中的就是答案

 这是有效的，因为祖先遍历自然地从较小的区域移动到较大的区域。 因此，遇到的第一个共享祖先必定是最小的公共区域。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(N) | 反复扫描地区列表寻找家长|
 | 最佳 | O(N) | O(N) | 使用父哈希映射进行直接祖先遍历 |

 ## 算法演练

 1. 创建一个名为的哈希图`parent`。 

该映射存储每个子区域的直接父区域。 对于中的每个列表`regions`，第一个元素是父元素，其余元素是子元素。 

例子：```
["North America", "United States", "Canada"]
```产生：```
"United States" -> "North America"
"Canada" -> "North America"
```使用哈希映射允许恒定时间父级查找。 
2. 向上遍历`region1`。 

开始于`region1`并使用地图重复移动到其父级。 

将每个访问过的区域存储在一个名为的集合中`ancestors`。 

这个集合代表了整个祖先链`region1`，包括它自己。 
3. 向上遍历`region2`。 

开始于`region2`并反复向上移动。 

在每一步中，检查当前区域是否存在于`ancestors`放。 

第一个匹配是最小的公共区域，因为我们从最深的可能节点向上移动。 
4. 返回匹配区域。 

由于问题保证存在有效答案，因此遍历总是会找到共同的祖先。 

### 为什么它有效

 树属性保证每个节点都有一条到根的路径。 通过存储所有祖先`region1`，我们创建包含它的每个区域的完整记录。 然后，当从`region2`，出现在集合中的第一个祖先必须是最低的共享祖先，因为遍历是从较小的区域向较大的区域进行的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findSmallestRegion(
        self,
        regions: List[List[str]],
        region1: str,
        region2: str
    ) -> str:

        parent = {}

        # Build child -> parent mapping
        for region_list in regions:
            parent_region = region_list[0]

            for i in range(1, len(region_list)):
                child_region = region_list[i]
                parent[child_region] = parent_region

        # Store all ancestors of region1
        ancestors = set()

        current = region1

        while current:
            ancestors.add(current)
            current = parent.get(current)

        # Find first common ancestor while traversing region2
        current = region2

        while current not in ancestors:
            current = parent.get(current)

        return current
```实现首先构建`parent`字典。 每个子区域直接指向其包含区域，这允许在每步恒定时间内向上遍历层次结构。 

接下来，代码从`region1`。 每个访问过的区域都被插入到`ancestors`放。 这包括`region1`它本身、它的父区域、祖父母区域，以及最终的根区域。 

第二次遍历开始于`region2`。 在每一步中，算法都会检查当前区域是否已存在于祖先集中。 第一个匹配项会立即返回，因为它代表最低的共同祖先。 

使用`parent.get(current)`避免到达根时出现错误，因为根没有父条目。 

## 解决方案```go
func findSmallestRegion(regions [][]string, region1 string, region2 string) string {
	parent := make(map[string]string)

	// Build child -> parent mapping
	for _, regionList := range regions {
		parentRegion := regionList[0]

		for i := 1; i < len(regionList); i++ {
			childRegion := regionList[i]
			parent[childRegion] = parentRegion
		}
	}

	// Store all ancestors of region1
	ancestors := make(map[string]bool)

	current := region1

	for current != "" {
		ancestors[current] = true
		current = parent[current]
	}

	// Find first common ancestor
	current = region2

	for !ancestors[current] {
		current = parent[current]
	}

	return current
}
```Go 解决方案遵循与 Python 版本相同的逻辑，但有一些特定于语言的细节值得注意。 

当键不存在时，Go 映射返回零值。 对于字符串，零值是空字符串`""`。 当根区域没有父区域时，此行为自然终止遍历。 

祖先集是使用以下实现的`map[string]bool`因为 Go 没有内置的集合类型。 

与 Python 不同，Go 需要显式变量声明并使用切片作为嵌套区域列表。

 ## 边缘情况

 当一个区域已经是另一区域的祖先时，就会出现一种重要的边缘情况。 例如，如果`region1 = "China"`和`region2 = "Beijing"`， 然后`"China"`本身就是最小的公共区域。 一些不正确的实现会不必要地继续向上遍历并返回更大的祖先。 这个实现避免了这个错误，因为所有的祖先`region1`，包括它自己，在遍历之前被插入到集合中`region2`。 

另一个重要的情况是唯一的共享祖先是根区域。 当两个区域属于层次结构的完全独立的分支时，就会发生这种情况。 有缺陷的实现可能会提前终止或无法继续遍历到根。 由于该算法继续向上直到找到匹配项，因此它可以正确处理答案是全局根的情况。 

第三种边缘情况涉及极深的层次结构。 如果树变得很深，递归 DFS 解决方案可能会面临堆栈溢出的风险。 此实现使用迭代父遍历而不是递归，即使对于长区域链也使其安全高效。 

一个微妙的情况涉及没有显式父条目的区域。 根节点永远不会作为子节点出现，因此它不存在于父映射中。 使用`parent.get(current)`在 Python 中并依赖 Go 的零值行为可确保遍历在根处干净地停止，而不会引发错误。
