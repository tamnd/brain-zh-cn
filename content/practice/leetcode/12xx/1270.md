[LeetCode 问题 1270](https://leetcode.com/problems/all-people-report-to-the-given-manager/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们识别公司中直接或间接向公司负责人汇报的所有员工，其`employee_id`是 1。输入是一个表`Employees`包含三列：`employee_id`,`employee_name`， 和`manager_id`。 每行定义一名员工和他们汇报的经理。 预期输出是一个表格，列出了`employee_id`拥有向公司负责人汇报的员工人数。 

这些限制规定公司规模较小，最多只能向领导层间接报告三级。 这意味着我们不需要处理非常深或复杂的层次结构，但我们确实需要正确遍历长度最多为三的链。 

重要的边缘情况包括向自己报告的员工（如负责人）、循环（尽管由于问题设置而不太可能）、向负责人链条之外的经理报告的员工以及没有直接报告的经理。 

## 方法

 蛮力方法是迭代每个员工并递归或迭代地遵循`manager_id`连锁直到我们到达公司的负责人（`employee_id = 1`）或联系链外的经理。 虽然这种方法可以正常工作，但它可能涉及重复遍历相同的链，特别是如果多个员工共享共同的管理者，这使得大型数据集效率低下。 

最佳方法利用了最多三个级别的报告这一事实。 我们可以编写一个显式连接的 SQL 查询`Employees`表最多三次，检查直接报告、二级报告和三级报告。 这避免了重复遍历并利用关系数据库连接来有效地计算结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 迭代每个员工，递归检查经理链； 可以重复工作|
 | 最佳 | O(n) | O(n) | 使用最多三个联接来查找在三个级别内报告的员工； 利用 SQL 连接 |

 ## 算法演练

 1. 通过筛选行来识别直接向公司负责人报告的员工`manager_id = 1`。 
2. 确定通过二级经理间接向主管汇报的员工。 加入`Employees`表及其自身位于第一个表的位置`manager_id`等于第二个表的`employee_id`，第二个表向头部报告。 
3. 确定通过三级经理间接向主管汇报的员工。 使用相同的模式再次连接第三级的表。 
4. 使用合并所有结果`UNION`以确保独特`employee_id`价值观。 这捕获了最多三名级别的员工报告。 
5、返回单列结果表`employee_id`。 

这是有效的，因为每个员工最多只能距头部三步远。 通过明确加入每个级别，我们保证层次结构中的所有员工都得到考虑，不会遗漏任何人或重复计算。

## SQL 解决方案```sql
SELECT employee_id
FROM Employees
WHERE manager_id = 1

UNION

SELECT e1.employee_id
FROM Employees e1
JOIN Employees e2 ON e1.manager_id = e2.employee_id
WHERE e2.manager_id = 1

UNION

SELECT e1.employee_id
FROM Employees e1
JOIN Employees e2 ON e1.manager_id = e2.employee_id
JOIN Employees e3 ON e2.manager_id = e3.employee_id
WHERE e3.manager_id = 1;
```此 SQL 查询有效地检索直接或间接向主管报告的所有员工。 第一个`SELECT`捕获直接报告。 第二个`SELECT`捕获第二级报告，第三级报告`SELECT`捕获第三级报告。`UNION`确保唯一性。

```**第 1 步：** 直接报告（`manager_id = 1`)→employee_id 2 和 77。 

**第2步：**二级报告（`manager_id`匹配直接下属的employee_id）→employee_id 4（manager_id = 2）。 

**步骤 3：** 三级报告（`manager_id`匹配二级报表的employee_id）→employee_id 7（manager_id = 4）。 

结果表：```
+-------------+
| employee_id |
+-------------+
| 2           |
| 77          |
| 4           |
| 7           |
+-------------+
```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个连接扫描表一次，连接数量恒定 (3)，总 O(n) |
 | 空间| O(n) | 存储中间连接结果需要相对于员工数量的线性空间 |

 原因是公司规模小，最大层级深度有限。 每个连接都会添加一次线性传递，而不是指数传递。

 ## 边缘情况

 1. **员工向自己汇报**：主管已`manager_id = 1`。 我们的加入和`UNION`通过在输出中不包含负责人，仅包含向他们报告的员工来处理此问题。 
2. **领导层级之外的员工**：一些员工可能向最终与领导没有联系的经理汇报。 我们的查询本质上排除了这些，因为连接条件要求报告链终止于`manager_id = 1`。 
3. **最大间接深度**：正确包含距主管间接报告三个级别的员工，因为查询最多连接三个级别。 任何超过三个级别的员工都不会被包括在内，这符合问题约束。 

该解决方案非常强大，可以处理所有预期的报告场景，并且可以有效地使用数据库，而无需递归或过程逻辑。
