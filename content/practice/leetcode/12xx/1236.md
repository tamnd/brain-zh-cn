[LeetCode 第 1236 题](https://leetcode.com/problems/web-crawler/)

 **难度：** 🟡 中等
 **主题：** 字符串、深度优先搜索、广度优先搜索、交互

 ## 解决方案

 ## 问题理解

 该问题要求我们实现一个简化的网络爬虫。 我们获得了一个起始 URL 并可以访问`HtmlParser`可以检索从给定网页链接的所有 URL 的接口。 我们的任务是从以下位置开始遍历网络图`startUrl`，但有两个重要的限制：

 1. 我们只能访问与以下主机名相同的 URL`startUrl`。 
2.我们绝不能多次抓取同一个URL。 

最终结果应包含同一主机名下的每个可到达的 URL，以任何顺序返回。 

URL 由多个部分组成，但与此问题相关的唯一部分是主机名。 例如：```
http://news.yahoo.com/news/topics/
```有主机名：```
news.yahoo.com
```仅当两个 URL 的主机名完全匹配时，它们才会被视为同一网站的一部分。 

这`HtmlParser.getUrls(url)`方法给出页面的所有传出链接。 从概念上讲，URL 形成一个有向图：

 - 每个URL都是一个节点
 - 每个超链接都是一个有向边

 爬虫开始于`startUrl`并探索可到达的节点，同时过滤掉具有不同主机名的 URL。 

限制相对较小：

 - 最多存在 1000 个 URL
 - URL 长度最多 300 个字符

 这些限制强烈表明图遍历算法（例如深度优先搜索（DFS）或广度优先搜索（BFS））是合适的。 由于图表可能包含循环，因此我们必须跟踪访问的 URL 以避免无限循环。 

一个重要的细节是，带有和不带有尾部斜杠的 URL 被认为是不同的：```
http://example.com
http://example.com/
```这些必须被视为单独的节点。 

一些边缘情况很重要：

 - 起始 URL 不得链接到任何同一主机页面
 - 图表可能包含循环
 - 外部 URL 可能会频繁出现，必须忽略
 - 多个页面可以链接到同一个 URL
 - 除非我们正确跟踪访问过的节点，否则爬虫可能会通过不同的路径重新访问 URL

 该问题保证了 URL 在库中是唯一的，从而简化了重复处理。 

## 方法

 ### 蛮力方法

 一个幼稚的策略是重复抓取每个发现的 URL，而不跟踪它是否已经被访问过。 每当我们遇到新页面时，我们都会调用`getUrls()`并继续递归。 

这种方法在概念上很简单，因为它盲目地探索每一个传出边缘。 然而，网络图表经常包含循环：```
A -> B
B -> C
C -> A
```如果没有访问集，爬虫将永远循环。 

即使我们人为限制递归深度，相同的 URL 也会被重复处理，造成大量冗余。 在最坏的情况下，同一页面可能会通过不同的路径以指数形式爬行多次。 

因此，暴力方法既低效又可能无法终止。 

### 最佳方法

 关键的见解是 URL 形成了图遍历问题。 由于我们只需要访问每个有效 URL 一次，因此我们应该将 DFS 或 BFS 与已访问 URL 的哈希集一起使用。 

该算法的工作原理如下：

 1. 提取主机名`startUrl`2.开始遍历`startUrl`3. 对于每个发现的 URL：

 - 如果已经访问过则跳过它
 - 如果主机名不同则跳过
 - 否则：

 - 标记已访问
 - 继续探索其传出链接

 使用哈希集可保证每个 URL 最多被处理一次。 

DFS 和 BFS 在这里工作得同样好。 DFS 的递归实现稍微简单一些，而 BFS 则避免了递归深度问题。 由于限制很小，任何一个都是可以接受的。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下呈指数 | 无界| 反复重访节点，可能会永远循环 |
 | 最优 DFS/BFS | O(N + E) | O(N) | 每个 URL 和边缘最多访问一次 |

 这里：

-`N`= 可到达的 URL 数量
 -`E`= 它们之间的链接数

 ## 算法演练

 我们将对已访问的集合使用深度优先搜索。 

### 第 1 步：提取主机名

 主机名是后面的部分`"http://"`并在下一个之前`"/"`。 

例如：```
http://news.yahoo.com/news
```变成：```
news.yahoo.com
```我们存储的主机名`startUrl`因为每个爬取的 URL 都必须匹配它。 

### 步骤2：初始化访问集

 我们创建一个名为的哈希集`visited`。 

这有两个目的：

 - 防止循环图中的无限循环
 - 防止同一页面的冗余抓取

 哈希集提供平均 O(1) 的查找和插入。 

### 第三步：开始DFS遍历

 我们定义一个接受 URL 的递归 DFS 函数。 

当DFS访问URL时：

 - 添加到`visited`- 使用检索所有传出链接`htmlParser.getUrls(url)`### 步骤 4：过滤 URL

 对于每个发现的 URL：

 - 如果已经访问过则跳过它
 - 如果主机名与起始主机名不同，则跳过它

 这确保我们只抓取有效页面一次。 

### 步骤5：继续递归

 如果 URL 通过了两项检查：

 - 在该 URL 上递归调用 DFS

 这将持续下去，直到探索完每个可到达的同一主机 URL。 

### 第 6 步：返回结果

 遍历完成后，所有有效 URL 都会存储在`visited`。 

将它们作为列表返回。 

### 为什么它有效

 该算法保持了以下不变式：`visited`:

 1. 具有相同的主机名`startUrl`2. 已经被充分探索

 由于每个 URL 仅被访问一次，因此即使存在循环，遍历也会终止。 

DFS 通过传出链接系统地探索每个可到达的有效 URL，因此不会错过任何符合条件的页面。 

## Python 解决方案```python
from typing import List, Set

# """
# This is HtmlParser's API interface.
# You should not implement it, or speculate about its implementation
# """
# class HtmlParser(object):
#     def getUrls(self, url):
#         """
#         :type url: str
#         :rtype List[str]
#         """

class Solution:
    def crawl(self, startUrl: str, htmlParser: 'HtmlParser') -> List[str]:
        def get_hostname(url: str) -> str:
            return url.split("/")[2]

        target_hostname = get_hostname(startUrl)
        visited: Set[str] = set()

        def dfs(url: str) -> None:
            visited.add(url)

            for next_url in htmlParser.getUrls(url):
                if next_url in visited:
                    continue

                if get_hostname(next_url) != target_hostname:
                    continue

                dfs(next_url)

        dfs(startUrl)

        return list(visited)
```实现从辅助函数开始`get_hostname()`提取 URL 的主机名部分。 由于所有 URL 都使用`http`协议且不存在端口，按`"/"`就足够了。 

然后我们存储主机名`startUrl`作为`target_hostname`。 每个爬网 URL 都必须与该值匹配。 

这`visited`set 跟踪所有已处理的 URL。 这可以防止重复爬行并避免循环图中的无限递归。 

递归`dfs()`函数执行图遍历。 当访问 URL 时，它会立即添加到集合中。 然后我们使用以下命令检索所有相邻的 URL`htmlParser.getUrls(url)`。 

对于每个邻居：

 - 如果已经访问过，我们会跳过它
 - 如果其主机名不同，我们会跳过它
 - 否则，我们递归地探索它

 最后，DFS 完成后，访问的 URL 将作为列表返回。 

## 解决方案```go
/**
 * // This is HtmlParser's API interface.
 * // You should not implement it, or speculate about its implementation
 * type HtmlParser struct {
 *     func GetUrls(url string) []string {}
 * }
 */

func crawl(startUrl string, htmlParser HtmlParser) []string {
	getHostname := func(url string) string {
		parts := strings.Split(url, "/")
		return parts[2]
	}

	targetHostname := getHostname(startUrl)

	visited := make(map[string]bool)

	var dfs func(string)

	dfs = func(url string) {
		visited[url] = true

		for _, nextURL := range htmlParser.GetUrls(url) {
			if visited[nextURL] {
				continue
			}

			if getHostname(nextURL) != targetHostname {
				continue
			}

			dfs(nextURL)
		}
	}

	dfs(startUrl)

	result := make([]string, 0, len(visited))

	for url := range visited {
		result = append(result, url)
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于 Go 使用`map[string]bool`而不是哈希集。 如果该 URL 已被访问过，则映射中存在一个键。 

DFS 函数被实现为分配给变量的递归闭包，它允许自递归。 

Go 切片的大小是动态调整的，因此我们通过迭代映射键来构建最终结果切片。 

一个重要的细节是该解决方案需要：```go
import "strings"
```因为主机名提取使用`strings.Split`。 

## 工作示例

 ### 示例 1

 输入：```
startUrl = "http://news.yahoo.com/news/topics/"
```目标主机名：```
news.yahoo.com
```### 遍历过程

 | 步骤| 当前网址 | 发现的 URL | 访问集 |
 | ---| ---| ---| ---|
 | 1 | 主题/ | 主页、新闻 | {主题/} |
 | 2 | 主页 | 我们| {主题/，主页} |
 | 3 | 我们| 无 | {主题/，主页，我们} |
 | 4 | 新闻 | 无 | {主题/、主页、我们、新闻} |

 最终结果：```
[
  "http://news.yahoo.com",
  "http://news.yahoo.com/news",
  "http://news.yahoo.com/news/topics/",
  "http://news.yahoo.com/us"
]
```由于主机名不同，Google URL 将被忽略。 

### 示例 2

 输入：```
startUrl = "http://news.google.com"
```目标主机名：```
news.google.com
```### 遍历过程

 | 步骤| 当前网址 | 发现的 URL | 行动|
 | ---| ---| ---| ---|
 | 1 | 谷歌.com | 雅虎网址 | 全部忽略|
 | 2 | 完成 | 无 | 遍历结束|

 最终结果：```
["http://news.google.com"]
```所有相邻的 URL 都被过滤掉，因为它们属于另一个主机名。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N + E) | 每个 URL 和边最多处理一次 |
 | 空间| O(N) | 访问集和递归堆栈存储可到达的 URL |

 由于访问集的原因，DFS 遍历仅访问每个有效 URL 一次。 在遍历过程中，每个传出边都被检查一次，总时间复杂度与可达子图中的节点和边的数量成正比。 

空间复杂度主要来自访问集。 在最坏的情况下，所有可访问的 URL 都属于同一主机名，并且必须存储。 在深度连接的链中，递归堆栈还可以增长到 O(N)。

 ## 边缘情况

 ### 循环链接

 图遍历问题中错误的一个主要来源是页面之间的循环引用。 例如：```
A -> B -> C -> A
```如果不跟踪访问的 URL，递归将永远不会终止。 

此实现通过将每个 URL 添加到`visited`在探索邻居之前设置。 一旦看到某个 URL，它就会被永久跳过。 

### 外部主机名

 一个页面可能链接到许多外部网站。 天真的爬虫可能会继续遍历整个互联网图。 

例如：```
http://news.yahoo.com
    -> http://google.com
```该解决方案通过在递归发生之前提取主机名并将其与原始主机名进行比较来防止这种情况发生。 

### 多个传入链接

 不同的页面可能链接到相同的目的地：```
A -> C
B -> C
```没有访问过的集合，页面`C`会被抓取多次。 

该实现保证每个 URL 被处理一次，因为成员资格`visited`在递归之前检查。 

### 尾部斜杠差异

 该问题明确指出：```
http://example.com
http://example.com/
```是不同的 URL。 

某些实现错误地将它们标准化为同一字符串。 该解决方案根本不修改 URL，它会比较精确的字符串，因此两者都会作为不同的页面正确处理。
