 **难度：** 🟢简单
 **主题：** 数组、哈希表、矩阵、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们在一台计算机上模拟井字棋游戏。`3 x 3`给定一系列移动的网格。 每次移动都会指定当前玩家放置标记的行和列。 玩家`A`总是先播放并使用`'X'`，而玩家`B`用途`'O'`。 目标是在序列中的所有移动之后确定游戏的结果：是否`A`获胜，`B`获胜、比赛平局或仍悬而未决。 

输入是一个移动列表，其中每个元素`[row, col]`代表当前玩家选择的网格上的方块。 约束保证所有移动都是有效的（没有重复的方块，所有索引都在`[0, 2]`）并且第一个玩家总是`A`。 最大移动次数为`9`因为网格有 9 个方格。 

重要的边缘情况包括游戏在所有方格都被填满之前结束的情况，例如玩家提前获胜，以及最后一步填满网格从而导致平局的情况。 该问题保证没有无效的移动，因此我们不需要检查越界索引或已经填充的方块。 

## 方法

 **暴力方法**是在`3 x 3`矩阵。 每次移动后，我们都会更新网格并检查所有可能的获胜条件：三行、三列和两条对角线。 这种方法之所以有效，是因为它直接对游戏进行建模，但在每次移动后检查所有行、列和对角线是重复的。 对于一个`3 x 3`grid 这仍然是可以接受的，但是如果网格尺寸更大，它就不可扩展。 

**最佳方法**利用计数器而不是维护完整的网格。 我们跟踪每个玩家在每行、每列和两条对角线上的标记数。 每当进行移动时，我们都会增加该玩家的相应计数器。 如果任何计数器达到`3`，玩家立即获胜。 这避免了重复扫描整个网格并保持代码整洁和高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 8) = O(n) | O(1) | O(1) | 模拟网格并检查每步棋后的 8 个获胜条件 |
 | 最佳 | O(n) | O(1) | O(1) | 为每个玩家使用行、列和对角线计数器，每次移动更新 |

 ## 算法演练

 1. 为双方玩家初始化计数器：`rows[3]`,`cols[3]`,`diag`， 和`anti_diag`。 这些代表每个玩家在每行、每列和对角线上有多少个标记。 
2. 迭代动作。 对于每个动作，确定哪个玩家正在玩。 玩家`A`是偶数指数移动，`B`是奇数索引的移动。 
3. 增加与移动的行、列和对角线相对应的计数器（如果适用）。 
4. 递增后，检查是否有计数器达到`3`。 如果是这样，该玩家获胜，我们返回`"A"`或者`"B"`。 
5. 如果所有步数都没有找到获胜者，请检查是否已完成所有 9 步。 如果是，则返回`"Draw"`。 
6.如果还有空格，则返回`"Pending"`。 

为什么有效：通过维护行、列和对角线计数器，我们捕获所有可能的获胜配置，而无需重复扫描整个网格。 计数器精确跟踪每个玩家的潜在获胜条件，确保正确检测获胜。 

## Python 解决方案```python
from typing import List

class Solution:
    def tictactoe(self, moves: List[List[int]]) -> str:
        rows = [0] * 3
        cols = [0] * 3
        diag = 0
        anti_diag = 0

        for i, (r, c) in enumerate(moves):
            player = 1 if i % 2 == 0 else -1
            rows[r] += player
            cols[c] += player
            if r == c:
                diag += player
            if r + c == 2:
                anti_diag += player
            if abs(rows[r]) == 3 or abs(cols[c]) == 3 or abs(diag) == 3 or abs(anti_diag) == 3:
                return "A" if player == 1 else "B"

        if len(moves) == 9:
            return "Draw"
        return "Pending"
```此 Python 代码使用整数计数器，其中`+1`代表玩家`A`和`-1`代表玩家`B`。 每次移动后，它都会更新行、列和对角线计数器，并立即检查是否获胜。 该代码可以有效地处理早期获胜和全部平局，而无需存储网格。 

## 解决方案```go
func tictactoe(moves [][]int) string {
    rows := [3]int{}
    cols := [3]int{}
    diag, antiDiag := 0, 0

    for i, move := range moves {
        player := 1
        if i%2 == 1 {
            player = -1
        }
        r, c := move[0], move[1]
        rows[r] += player
        cols[c] += player
        if r == c {
            diag += player
        }
        if r+c == 2 {
            antiDiag += player
        }
        if abs(rows[r]) == 3 || abs(cols[c]) == 3 || abs(diag) == 3 || abs(antiDiag) == 3 {
            if player == 1 {
                return "A"
            }
            return "B"
        }
    }

    if len(moves) == 9 {
        return "Draw"
    }
    return "Pending"
}

func abs(x int) int {
    if x < 0 {
        return -x
    }
    return x
}
```Go 的差异：Go 使用固定大小的数组作为行和列计数器，并使用显式的`abs`函数，因为 Go 没有内置的`abs`对于旧版本中的整数。 其逻辑与 Python 相似，但存在类型差异。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 迭代所有动作一次，每次动作恒定时间操作 |
 | 空间| O(1) | O(1) | 仅使用固定数量的计数器（行、列、diag、anti_diag）|

 尽管蛮力方法对于 3x3 网格来说是可以接受的，但最佳计数器方法更干净，避免重复扫描，并且在概念上可以更好地扩展。
