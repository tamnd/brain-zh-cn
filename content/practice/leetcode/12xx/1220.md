[LeetCode 第 1220 题](https://leetcode.com/problems/count-vowels-permutation/)

 **难度：** 🔴难
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个长度有效的字符串`n`可以仅使用五个小写元音组成：

 -`'a'`-`'e'`-`'i'`-`'o'`-`'u'`然而，字符串不是任意的。 每个元音对于哪些元音可以紧随其后出现有严格的规则。 

转换规则为：

 -`'a'`只能跟随`'e'`-`'e'`只能跟随`'a'`或者`'i'`-`'i'`后面可以跟任何东西，除了`'i'`-`'o'`只能跟随`'i'`或者`'u'`-`'u'`只能跟随`'a'`我们必须计算长度有效字符串的总数`n`，并且因为结果可能变得非常大，所以我们返回模数的答案`10^9 + 7`。 

输入由单个整数组成`n`，表示所需的字符串长度。 输出是一个整数，表示该长度的所有有效元音排列的计数。 

约束条件`1 <= n <= 2 * 10^4`非常重要。 生成每个可能的字符串的强力解决方案是完全不可行的，因为组合的数量呈指数增长。 甚至`5^20`已经是巨大的了，并且`5^(20000)`是天文数字无法列举的。 

这立即告诉我们，我们需要一个动态编程解决方案，可以重用以前计算的结果，而不是重新计算重叠的子问题。 

一些边缘情况很重要：

 -`n = 1`是可能的最小输入。 每个元音单独有效，所以答案应该是`5`。 
- 大值`n`需要高效的时间复杂度和仔细的模处理。 
- 转换规则是有方向性的。 例如，`'a' -> 'e'`是允许的，但是`'e' -> 'a'`是必须独立处理的单独规则。 
- 自从`'i'`可以转换为四个不同的元音，它对状态增长有很大贡献，并且很容易错误地实现。 

## 方法

 ### 蛮力方法

 强力解决方案将递归地生成每个可能的长度字符串`n`。 

在每个位置，我们都会尝试根据转换规则允许的每个元音。 一旦字符串达到长度`n`，我们将其视为一种有效排列。 

这种方法是正确的，因为它明确地探索了每一种有效的可能性。 然而，它太慢了，因为可能的递归路径的数量呈指数增长。 

即使基于转移规则进行修剪，分支因子仍然足够大，以至于总运行时间对于`n = 20000`。 

### 最佳解决方案的关键见解

 关键的观察是下一个字符仅取决于当前字符。 

这意味着我们不需要存储整个字符串。 相反，我们只需要知道：

 - 当前有多少个有效字符串结尾`'a'`- 有多少个结尾`'e'`- 有多少个结尾`'i'`- 有多少个结尾`'o'`- 有多少个结尾`'u'`这是一个经典的动态规划模式。 

对于每个字符串长度，我们使用前一个长度的计数来计算以每个元音结尾的方式数。 

例如：

 - 结尾为的字符串`'a'`只能来自`'e'`,`'i'`， 或者`'u'`- 结尾为的字符串`'e'`只能来自`'a'`或者`'i'`通过重复更新这五个计数，我们可以在线性时间内迭代地构建答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(4^n) | O(4^n) | O(n) | 递归生成所有有效字符串 |
 | 最优动态规划| O(n) | O(1) | O(1) | 音轨仅计算每个结尾元音 |

 ## 算法演练

 1. 初始化五个变量，表示以每个元音结尾的有效字符串的数量。 

对于长度`1`，每个元音本身都是有效的：

 -`a = 1`-`e = 1`-`i = 1`-`o = 1`-`u = 1`2. 从长度迭代`2`直到长度`n`。 

对于每个新的字符串长度，使用转换规则计算下一个计数。 
3. 计算以 结尾的字符串的数量`'a'`。 

字符串可以以以下形式结尾`'a'`仅当前一个字符是：

 -`'e'`-`'i'`-`'u'`所以：```
next_a = e + i + u
```4. 计算以 结尾的字符串的数量`'e'`。 

前一个字符必须是：

 -`'a'`-`'i'`所以：```
next_e = a + i
```5. 计算以结尾的字符串的数量`'i'`。 

前一个字符必须是：

 -`'e'`-`'o'`所以：```
next_i = e + o
```6. 计算以结尾的字符串的数量`'o'`。 

前一个字符必须是：

 -`'i'`所以：```
next_o = i
```7. 计算以结尾的字符串的数量`'u'`。 

前一个字符必须是：

 -`'i'`-`'o'`所以：```
next_u = i + o
```8. 应用模数`10^9 + 7`到每一次更新。 

这可以防止整数溢出并满足问题要求。 
9. 用新计算的计数替换旧的计数。 
10. 完成所有迭代后，返回所有五个元音计数的模数之和`10^9 + 7`。 

### 为什么它有效

 该算法保持不变式，即每个变量存储当前长度以特定元音结尾的有效字符串的数量。 

因为每个长度有效的字符串`k`只能按照给定的规则进行转移，递归关系正确地统计了所有的可能性，没有重复或遗漏。 

由于每次更新仅取决于先前的长度，因此迭代`1`到`n`最终计算长度有效字符串的确切数量`n`。 

## Python 解决方案```python
class Solution:
    def countVowelPermutation(self, n: int) -> int:
        MOD = 10**9 + 7

        a = e = i = o = u = 1

        for _ in range(1, n):
            next_a = (e + i + u) % MOD
            next_e = (a + i) % MOD
            next_i = (e + o) % MOD
            next_o = i % MOD
            next_u = (i + o) % MOD

            a, e, i, o, u = next_a, next_e, next_i, next_o, next_u

        return (a + e + i + o + u) % MOD
```其实现直接遵循动态规划递推关系。 

我们首先初始化长度字符串的计数`1`。 每个元音恰好贡献一个有效字符串。 

循环运行`n - 1`次因为长度`1`已经初始化了。 在每次迭代期间，我们根据转换规则计算下一个状态值。 

临时变量如`next_a`和`next_e`是必要的，因为所有更新都必须使用先前迭代的值。 如果我们立即更新变量，以后的计算将错误地使用部分更新的数据。 

计算所有新计数后，我们使用元组分配同时替换旧值。 

最后，我们对所有可能的结尾元音求和，因为有效的字符串可能以任何元音结尾。 

## 解决方案```go
func countVowelPermutation(n int) int {
    const MOD int = 1000000007

    a, e, i, o, u := 1, 1, 1, 1, 1

    for step := 1; step < n; step++ {
        nextA := (e + i + u) % MOD
        nextE := (a + i) % MOD
        nextI := (e + o) % MOD
        nextO := i % MOD
        nextU := (i + o) % MOD

        a, e, i, o, u = nextA, nextE, nextI, nextO, nextU
    }

    return (a + e + i + o + u) % MOD
}
```Go 实现几乎完全反映了 Python 逻辑。 

一个重要的区别是显式整数类型。 我们定义`MOD`作为`int`常数并始终使用整数算术。 

Go 不自动支持 Python 风格的任意精度整数，但因为我们在每次迭代期间应用模数，所以所有中间值都保持在安全范围内。 

Go 中的元组分配允许同时更新所有五个元音计数器，类似于 Python。

 ## 边缘情况

 一个重要的边缘情况是`n = 1`。 许多实现意外地立即进入 DP 循环并产生不正确的计数，因为它们假设至少发生了一次转换。 我们的实现初始化长度计数`1`直接并完全跳过循环`n = 1`，产生正确答案`5`。 

另一个重要的边缘情况涉及大值`n`，特别是靠近`20000`。 有效字符串的数量增长得非常快，因此在每次迭代期间不应用模的实现可能会溢出固定大小的整数类型。 我们的解决方案在每个更新步骤中应用模数，确保所有中间值保持有界。 

一个微妙的边缘情况来自于转换规则`'i'`。 问题指出`'i'`可能不会被另一个跟随`'i'`，这意味着它可以过渡到四个不同的元音。 这很容易被误解或部分实现。 我们的递归关系仔细地对所有允许的前驱和后继进行编码，确保每个有效的转换都被精确地计算一次。 

最后一个边缘情况是同时状态更新。 如果我们更新了`a`，然后使用更新后的值来计算`e`，我们会破坏递归关系，因为一些计算将使用旧值，而另一些计算将使用新值。 使用临时变量，例如`next_a`和`next_e`保证每次更新都一致地使用前一次迭代的状态。
