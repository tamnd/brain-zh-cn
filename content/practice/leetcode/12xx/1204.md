[LeetCode 1204 题](https://leetcode.com/problems/last-person-to-fit-in-the-bus/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为`Queue`代表等待登上公共汽车的人们。 每行包含一个人的 ID、姓名、体重和登机顺序。 这`turn`列决定了人们尝试登上公交车的确切顺序。 

巴士有严格的重量限制`1000`公斤。 人们一次登上一名乘客，按照递增的顺序`turn`。 一旦再加上一个人就会导致总重量超过`1000`，该人无法登机，并且在他们之后也没有人登机，因为登机是按顺序发生的。 

任务是确定最后一个在不违反重量限制的情况下成功登上公交车的人的姓名。 

重要的细节是，我们不会被要求送回所有适合的乘客。 相反，我们只需要最终的人，其纳入仍使累积权重等于或低于`1000`。 

输入表表示：

 | 专栏 | 意义|
 | ---| ---|
 |`person_id`| 每个人的唯一标识符 |
 |`person_name`| 乘客姓名 |
 |`weight`| 乘客体重（公斤）|
 |`turn`| 登机顺序 |

 预期输出是包含以下内容的单行`person_name`最后一位有效乘客的。 

这些约束告诉我们有关输入结构的一些有用的信息：

 -`turn`值是唯一的，范围为`1`到`n`- 登机顺序完全确定
 - 保证第一位乘客适合
 - 只有累计重量才重要

 这从根本上来说是一个运行总体问题。 我们需要按顺序处理行并不断计算权重之和。 

一些边缘情况很重要：

 - 总重量可能精确达到`1000`，这仍然有效
 - 只有第一位乘客可以容纳
 - 每位乘客都适合
 - 超过限制的人不应被包括在内
 - 订购方式`turn`至关重要，以任意顺序处理行会给出不正确的结果

 ## 方法

 ### 蛮力方法

 一种简单的方法是手动模拟登机过程。 

我们首先按他们的喜好对所有人进行排序`turn`。 然后，对于每个人，我们计算从开始到该人的所有乘客的累积重量。 如果累计重量仍然小于或等于`1000`，该乘客当前是最后一个有效乘客。 一旦总数超过`1000`，我们停下来。 

在 SQL 中，简单的暴力解决方案可以使用相关子查询重复计算总和。 对于每一行，我们计算所有行的总权重`turn`小于或等于当前行的轮次。 

这种方法是正确的，因为它直接对登机过程进行建模，完全按照问题中的描述进行。 然而，重复地重新计算每行的总和是低效的。 

### 最佳方法

 关键的见解是，这是一个累积总和或运行总计的问题。 

我们可以使用 SQL 窗口函数在一次遍历有序行的过程中有效地计算运行权重，而不是重复地重新计算总计。 

使用：```
SUM(weight) OVER (ORDER BY turn)
```我们可以计算每个乘客上车后的累积巴士重量。 

一旦我们有了运行总计，我们只需过滤累积权重小于或等于的行`1000`，然后选择最大的乘客`turn`。 

这种方法高效、简洁，并且自然地映射到问题需求。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复重新计算累积和 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用窗口函数进行总计 |

 这`O(n log n)`因素来自排序`turn`，尽管如果存在索引，许多数据库引擎可能会进一步优化这一点。 

## 算法演练

 1. 按乘客的身份对所有乘客进行排序`turn`值，因为登机必须按照确切的队列顺序进行。 
2. 使用窗函数计算乘客重量的运行总计。 对于每一行，计算从队列开头到当前乘客的所有重量的总和。 
3. 只保留累计重量小于或等于的乘客`1000`。 这些都是能够成功上车的乘客。 
4. 在所有有效乘客中，选择最大的乘客`turn`价值，因为他们最后登机。 
5. 返回该乘客的`person_name`。 

### 为什么它有效

 处理旅客后的运行金额`i`准确地表示乘客登上后的巴士总重量。 如果运行总计小于或等于`1000`，该旅客即可合法登机。 因此，最后一位乘客是最后一位能登上巴士的乘客。 由于乘客严格按照顺序登机，一旦超过限制，后面的乘客就无法登机。 

## Python 解决方案

 虽然这是一个 SQL 数据库问题，但我们仍然可以用 Python 来演示逻辑，以便于算法理解。```python
from typing import List

class Solution:
    def lastPersonToFit(self, queue: List[List]) -> str:
        queue.sort(key=lambda person: person[3])

        current_weight = 0
        last_person = ""

        for person_id, person_name, weight, turn in queue:
            if current_weight + weight > 1000:
                break

            current_weight += weight
            last_person = person_name

        return last_person
```该实施首先使用以下方法根据乘客的登机顺序对乘客进行排序：`turn`场地。 这保证了我们完全按照公交车上车顺序的要求处理乘客。 

我们维护一个名为`current_weight`跟踪公交车上已有的累积重量。 另一个变量，`last_person`，存储最近成功登机的乘客。 

对于每位乘客，我们都会检查其体重的增加是否会超出巴士的限制。 如果是这样，我们会立即停止，因为没有其他乘客可以登机。 

否则，我们更新累计重量，并将当前乘客记录为最新有效乘客。 

在最后，`last_person`包含符合限制的最后一位乘客。 

### LeetCode 的 SQL 解决方案```sql
SELECT person_name
FROM (
    SELECT
        person_name,
        turn,
        SUM(weight) OVER (ORDER BY turn) AS total_weight
    FROM Queue
) AS running_totals
WHERE total_weight <= 1000
ORDER BY turn DESC
LIMIT 1;
```该查询首先使用窗口函数计算累积权重。 然后，它会过滤有效的登机状态并选择其中转弯次数最高的乘客。 

## 解决方案```go
package main

import (
	"sort"
)

type Person struct {
	personID   int
	personName string
	weight     int
	turn       int
}

func lastPersonToFit(queue []Person) string {
	sort.Slice(queue, func(i, j int) bool {
		return queue[i].turn < queue[j].turn
	})

	currentWeight := 0
	lastPerson := ""

	for _, person := range queue {
		if currentWeight+person.weight > 1000 {
			break
		}

		currentWeight += person.weight
		lastPerson = person.personName
	}

	return lastPerson
}
```Go 实现遵循与 Python 版本相同的逻辑。 我们使用`sort.Slice`轮流排序乘客。 累积重量通过整数变量进行跟踪，一旦超出限制，我们就会停止处理。 

Go没有Python风格的元组解包，所以我们定义一个`Person`结构体清晰地存储乘客数据。 整数溢出在这里不是一个问题，因为总重量仍然很小。 

### LeetCode 的 SQL 解决方案```sql
SELECT person_name
FROM (
    SELECT
        person_name,
        turn,
        SUM(weight) OVER (ORDER BY turn) AS total_weight
    FROM Queue

ORDER BY turn DESC

 ## 边缘情况

 当累积权重正好变为`1000`。 一个常见的错误是使用严格的不平等检查，例如`< 1000`而不是`<= 1000`。 该实施正确地允许添加导致总重量等于限制的乘客。 

另一个关键的边缘情况是只有第一位乘客可以登机。 由于该问题保证第一位乘客始终适合，因此即使第二位乘客立即超出限制，算法仍必须返回第一位乘客。 该实现自然地处理了这个问题，因为`last_person`每次成功登机后都会更新。 

第三种边缘情况涉及未排序的输入行。 数据库表不保证按物理顺序排序`turn`。 按插入顺序处理行的简单实现会产生不正确的结果。 Python 模拟和 SQL 解决方案都显式排序`turn`，无论输入顺序如何，都确保正确性。 

当每个乘客都在限制范围内时，就会出现最后一个微妙的边缘情况。 某些实施错误地提前停止或未能更新最终有效乘客。 由于算法更新`last_person`每次成功登机后，当整个队列都填满时，最后一位乘客就会正确返回。
