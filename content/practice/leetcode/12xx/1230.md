 **难度：** 🟡 中等
 **主题：** 数组、数学、动态规划、概率与统计

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算当抛掷一组硬币时，恰好有特定数量的硬币出现正面的概率。 每个硬币都有自己的正面朝上的概率，该概率在输入数组中给出`prob`。 整数`target`代表我们感兴趣的头的确切数量。 

输入`prob`是一个介于 0 和 1 之间的浮点数数组，其中`prob[i]`表示的概率`i`-th 硬币着陆头。 预期输出是一个浮点数，表示准确的概率`target`如果所有硬币都被抛掷一次，则硬币正面朝上。 该输出必须在容差范围内准确`10^-5`。 

关键约束表明该数组最多可以有 1000 个硬币。 枚举所有可能结果的简单解决方案是不可行的，因为组合的数量呈指数增长`2^n`。 要考虑的边缘情况包括`target`为 0（全部为尾），`target`等于`len(prob)`（全部正面），或者硬币的概率恰好为 0 或 1。 

## 方法

 暴力方法会枚举所有可能的抛掷结果`n`硬币。 对于每个结果，我们将计算正面的数量，并将计数等于的这些结果的概率相加`target`。 虽然这是正确的，但时间复杂度为 O(2^n)，这对于`n`最多 1000 个。 

最佳方法使用动态规划。 关键的观察结果是，出现的概率`k`头后`i`硬币仅取决于拥有的概率`k`或者`k-1`头后`i-1`硬币。 我们定义`dp[i][j]`作为拥有的概率`j`抛完第一个球后的头`i`硬币。 我们可以迭代地构建这个表：

 - 对于`i`第-枚硬币，如果正面朝上，则正面数量增加 1。 
- 如果出现反面，则正面的数量保持不变。 

这会导致重复出现：```
dp[i][j] = dp[i-1][j] * (1 - prob[i-1]) + dp[i-1][j-1] * prob[i-1]  (if j > 0)
dp[i][0] = dp[i-1][0] * (1 - prob[i-1])
```为了优化空间，我们可以将 2D 表缩减为 1D 数组，因为每一行仅依赖于前一行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 列举所有可能的结果； 对于大 n | 不可行
 | 动态规划| O(n * 目标) | O（目标）| 使用先前的结果迭代构建概率 |

 ## 算法演练

 1.初始化一个大小为1D的DP数组`target + 1`全为零并设置`dp[0] = 1.0`。 这表示在抛掷任何硬币之前出现零头的概率。 
2. 迭代中的每个硬币`prob`大批。 
3. 对于每个硬币，从`target`降至 1. 更新`dp[j]`使用公式：`dp[j] = dp[j] * (1 - prob[i]) + dp[j-1] * prob[i]`。 向后迭代可确保我们正确使用前一行的值。 
4. 更新`dp[0]`分别计算不添加新头的概率：`dp[0] = dp[0] * (1 - prob[i])`。 
5.处理完所有硬币后，`dp[target]`持有精确得到的概率`target`头。 

为什么有效：每个`dp[j]`总是代表正确的概率`j`处理完当前一枚硬币后的头。 通过向后迭代，我们可以防止覆盖当前更新所需的概率。 这样就保持了不变性`dp[j] = probability of j heads using first i coins`。 

## Python 解决方案```python
from typing import List

class Solution:
    def probabilityOfHeads(self, prob: List[float], target: int) -> float:
        dp = [0.0] * (target + 1)
        dp[0] = 1.0  # base case: 0 heads initially
        
        for p in prob:
            # iterate backwards to avoid overwriting values we still need
            for j in range(target, 0, -1):
                dp[j] = dp[j] * (1 - p) + dp[j-1] * p
            dp[0] *= (1 - p)
        
        return dp[target]
```该实现首先初始化基本情况。 然后，对于每个硬币，它以相反的顺序更新所有可能的人头计数的概率。 反向更新可确保我们始终使用上一步中的值，保持正确性。 

## 解决方案```go
func probabilityOfHeads(prob []float64, target int) float64 {
    dp := make([]float64, target+1)
    dp[0] = 1.0
    
    for _, p := range prob {
        for j := target; j >= 1; j-- {
            dp[j] = dp[j]*(1-p) + dp[j-1]*p
        }
        dp[0] *= (1 - p)
    }
    
    return dp[target]
}
```在 Go 中，我们使用切片作为 DP 数组。 其逻辑与 Python 完全一致。 请注意，Go 处理切片的方式与 Python 列表不同，但这里的差异不会影响算法。 我们还通过反向更新来避免使用额外的内存。 

## 工作示例

 **示例1：**`prob = [0.4], target = 1`初始DP：`[1.0, 0.0]`加工硬币`0.4`:

 -`dp[1] = dp[1]*0.6 + dp[0]*0.4 = 0*0.6 + 1*0.4 = 0.4`-`dp[0] = dp[0]*0.6 = 1*0.6 = 0.6`最终DP：`[0.6, 0.4]`输出：`0.4`**示例2：**`prob = [0.5,0.5,0.5,0.5,0.5], target = 0`初始DP：`[1.0]`迭代更新`dp[0]`仅有的：`dp[0] *= 0.5`五次→`0.5^5 = 0.03125`输出：`0.03125`## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * 目标) | 我们迭代每个硬币，并且对于每个硬币，更新到`target`DP 中的条目 |
 | 空间| O（目标）| 只有大小的一维数组`target + 1`需要，减少 O(n*target) | 的空间

 即使对于`n = 1000`和`target = 1000`因为`n*target`最多 1,000,000 次操作。 使用单个一维阵列有效优化空间。

 ## 边缘情况

 一个重要的边缘情况是当`target = 0`，这意味着我们想要所有的尾巴。 实现正确更新`dp[0]`分别累加这个概率。 

另一个边缘情况是当`target = len(prob)`，需要所有头。 该算法自然地处理这个问题，因为`dp[target]`只有当所有币都贡献了头时才会更新。 

第三种边缘情况是硬币有概率`0`或者`1`。 为了`0`，它永远不会对头部做出贡献，并且对于`1`，总会贡献一个头。 DP 更新公式可以无缝处理这两者，确保概率保持准确。
