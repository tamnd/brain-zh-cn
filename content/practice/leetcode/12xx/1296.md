[LeetCode 第 1296 题](https://leetcode.com/problems/divide-array-in-sets-of-k-consecutive-numbers/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪心、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 我们需要确定是否可以将数组中的所有数字分为以下组：

 - 每组均包含`k`数字
 - 每组内的数字都是连续的整数
 - 数组中的每个元素必须完全属于一个组

 重要的细节是输入数组中允许重复，并且如果相同的数字在数组中出现多次，则可能会出现在多个组中。 

例如，如果我们有：```
nums = [1,2,3,3,4,4,5,6], k = 4
```我们可以把它分成：```
[1,2,3,4]
[3,4,5,6]
```两组都包含连续的长度数字`4`，并且每个元素都只使用一次。 

输出应该是：

 -`true`如果这样的分区是可能的
 -`false`否则

 约束条件很重要：

 -`nums.length`可以大到`10^5`- 里面的价值观`nums`可以达到`10^9`这些限制立即告诉我们，低效的重复扫描方法可能会超时。 我们需要一个接近的算法`O(n log n)`。 

一个直接的观察结果是，如果元素总数不能被`k`，那么形成相等大小的组是不可能的。 这成为早期拒绝的条件。 

另一个重要的见解是连续序列提出了排序要求。 由于序列取决于相邻值，因此排序或维护有序访问变得必要。 

一些边缘情况可能会导致简单的解决方案失败：

 - 长度不能被整除的数组`k`- 大量重复计数
 - 序列中缺少中间值
 - 多个重叠序列竞争相同的数字
 -`k = 1`，其中每个数字单独构成一个有效组
 - 稀疏大整数，例如`[1000000,1000001,1000002]`该问题仅保证正整数，因此我们不需要处理负数或空数组。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是重复：

 1. 对数组进行排序
 2. 选择最小的未使用的数字
 3.尝试构建一个连续的长度序列`k`4. 从考虑中删除这些数字
 5. 重复直到使用完所有数字

 例如：```
[1,2,3,3,4,4,5,6]
```我们挑选`1`，然后搜索`2`,`3`,`4`。 

删除它们后：```
[3,4,5,6]
```然后我们重复。 

这种方法是正确的，因为每个有效分组都必须包含最小的剩余数字作为某个连续序列的开始。 然而，重复删除和重复扫描变得非常昂贵。 

如果通过重复列表删除或线性搜索来实现，复杂度可能会降低到`O(n^2)`。 

和`n`最多`100000`，这太慢了。 

### 最优贪心法

 关键的观察是：

 如果我们总是从小到大处理数字，那么每当我们遇到剩余频率的数字时，它必须开始一个新的序列。 

为什么？ 

因为较小的数字已经被处理了。 如果当前数字应该出现在序列的中间，那么该序列早就已经消耗掉了它。 

这自然会导致贪婪策略：

 1.统计每个数字出现的频率
 2. 按排序顺序处理数字
 3. 当一个数字仍有剩余出现次数时：

 - 从这个数字开始许多序列
 - 确保下一步`k - 1`连续的数字也以足够的频率存在
 - 减少他们的数量

 哈希图非常适合频率计数，排序可确保数字按有效顺序进行处理。 

这种方法避免了重复的重新扫描并实现了高效的性能。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复搜索和删除成本太高 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用排序加上贪心频率计数 |

 ## 算法演练

 1.首先检查数组长度是否能被整除`k`。 

如果`len(nums) % k != 0`，那么形成相同大小的组是不可能的。 我们可以立即返回`false`。 
2. 统计每个数字出现的频率。 

我们使用哈希映射，其中：```
frequency[number] = count
```这允许恒定时间的查找和更新。 
3. 对数组进行排序。 

按升序处理数字至关重要。 我们总是希望从最小的可用数字开始序列。 
4. 按排序顺序迭代每个数字。 

对于每个数字：

 - 如果它的频率已经为零，则它已经在之前的序列中使用过，所以我们跳过它。 
- 否则，该数字必须成为一个或多个新的连续组的开始。 
5. 确定必须从此处开始有多少个序列。 

认为：```
frequency[current] = count
```那么我们必须准确地创建`count`序列开始于`current`。 
6.检查下一个`k`连续的数字。 

对于每个值：```
current, current + 1, ..., current + k - 1
```我们验证它的频率至少是`count`。 

如果任何数字没有足够的出现次数，则不可能形成有效的组。 
7. 减少频率。 

一旦验证通过，减去`count`从每个连续的数字。 

这代表将这些数字消耗到新形成的组中。 
8. 继续，直到处理完所有号码。 

如果不矛盾则返回`true`。 

### 为什么它有效

 正确性来自于始终首先处理剩余的最小数。 

如果当我们遇到一个数字时仍然有未使用的出现次数，那么这些出现次数不能属于较早开始的序列，因为较早的序列已经消耗了它们。 因此，他们必须开始新的序列。 

贪婪的选择是被迫的，而不是可选的。 通过立即验证和使用下一个连续数字，我们确保每个形成的组都是有效的，并且以后不会违反较小数字的依赖性。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def isPossibleDivide(self, nums: List[int], k: int) -> bool:
        n = len(nums)

        if n % k != 0:
            return False

        frequency = Counter(nums)

        for number in sorted(nums):
            if frequency[number] == 0:
                continue

            group_count = frequency[number]

            for next_number in range(number, number + k):
                if frequency[next_number] < group_count:
                    return False

                frequency[next_number] -= group_count

        return True
```实现从早期的可分性检查开始。 如果元素总数不能均匀地分成不同大小的组`k`，没有理由继续。 

接下来，`Counter`对象存储每个值的频率。 这在验证连续序列时提供了高效的恒定时间访问。 

然后按排序顺序处理该数组。 排序保证我们总是首先遇到剩余的最小未使用数字。 

在循环内部，如果当前数字的频率已经为零，则意味着前面的组已经消耗了该数字的所有副本，因此我们跳过它。 

否则，剩余频率决定有多少组必须以此数字开头。 然后我们验证所有必需的连续数字是否以足够的频率存在。 

如果所需数量缺失或不足，我们会立即退回`False`。 

否则，我们会减少频率来表示将这些元素分组。 

如果整个循环成功完成，则每个数字都已正确分组，因此我们返回`True`。 

## 解决方案```go
package main

import (
	"sort"
)

func isPossibleDivide(nums []int, k int) bool {
	n := len(nums)

	if n%k != 0 {
		return false
	}

	frequency := make(map[int]int)

	for _, num := range nums {
		frequency[num]++
	}

	sort.Ints(nums)

	for _, num := range nums {
		if frequency[num] == 0 {
			continue
		}

		groupCount := frequency[num]

		for nextNum := num; nextNum < num+k; nextNum++ {
			if frequency[nextNum] < groupCount {
				return false
			}

			frequency[nextNum] -= groupCount
		}
	}

	return true
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

主要区别在于手动地图处理而不是 Python 的`Counter`。 Go 中缺失的键映射默认为零，这自然支持频率检查。 

该数组使用排序`sort.Ints(nums)`。 

Go 整数可以安全地处理给定的约束，因为值保持在标准 32 位整数限制内，并且 Go 的`int`类型就足够了。

 ## 边缘情况

 当数组长度不能被整除时，会出现一种重要的边缘情况`k`。 这是最简单的不可能的场景，但很容易被忽视。 如果没有此检查，算法可能会在最终失败之前执行不必要的处理。 实现立即处理这个问题：```
if len(nums) % k != 0:
    return False
```另一个关键的边缘情况涉及连续数不足的重复值。 考虑：```
[1,1,2,2,2,3,3]
```和`k = 3`。 

有两份`1`，这意味着我们必须创建两个序列，从`1`。 每份需要两份`2`和`3`。 虽然有足够的`3`s，频率关系稍后可能会变得不一致。 频率图保证了精确的统计并防止过度使用值。 

第三个重要的情况是具有较大间隙的稀疏值，例如：```
[1,2,3,10,11,12]
```该算法可以正确处理断开的有效范围，因为它独立处理每个最小的剩余数字。 连续验证仅适用于每个所需组内的本地。 

另一个微妙的边缘情况是`k = 1`。 在这种情况下，每个单独的数字已经形成一个大小为 1 的有效连续组。 实现自然会处理这个问题，因为每次迭代只检查当前数字本身。 

最后，大整数值在某些语言中可能会引起关注，但该算法最多不会执行除加法之外的算术运算`k`到一个数字。 由于约束保持在标准整数限制内，Python 和 Go 都可以安全地处理所有有效输入。
