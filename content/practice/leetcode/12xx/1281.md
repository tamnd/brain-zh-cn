[LeetCode 第 1281 题](https://leetcode.com/problems/subtract-the-product-and-sum-of-digits-of-an-integer/)

 **难度：** 🟢简单
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题要求我们对整数的数字进行简单的数学变换。 给定一个整数`n`，我们需要求其各位数字与其各位数字之和的乘积，然后返回差值：`product - sum`。 换句话说，对于像这样的数字`234`，数字是`2`,`3`， 和`4`。 他们的产品是`2 * 3 * 4 = 24`，它们的总和是`2 + 3 + 4 = 9`。 最终的答案是`24 - 9 = 15`。 

输入`n`保证是 1 到 100,000 之间的正整数。 这保证了该数字最多有 5 位数字，因此我们不必担心大多数现代语言中的大规模性能或整数溢出。 输出是一个整数，表示乘积与数字之和之间的差。 

重要的边缘情况包括数字为零的数字，例如`101`，其中乘以零将使乘积为零，或者只有一位数的数字，其中乘积和总和相等，导致差值为零。 该问题保证了`n`总是正数，所以我们不需要处理负数。 

## 方法

 暴力方法涉及将数字转换为字符串或数字数组，然后分别计算数字的乘积和总和。 虽然这可以正常工作，但它有点冗长并且没有必要，因为我们可以直接使用整数算术。 考虑到输入量较小，这种方法就足够了，但它不是最优雅的。 

最佳方法是使用数字的直接算术运算。 我们可以使用模除法和整数除法运算提取每个数字。 这种方法避免了将数字转换为字符串，实现简单，并且内存效率高。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(d) | O(d) | 将数字转换为字符串/数字数组，计算乘积和总和 |
 | 最佳 | O(d) | O(1) | O(1) | 使用整数算术提取数字、动态计算乘积和总和 |

 这里，`d`表示中的位数`n`。 自从`n <= 10^5`,`d <= 5`，因此时间复杂度实际上是恒定的。 

## 算法演练

 1.初始化两个变量，`digit_product`到 1 和`digit_sum`到 0。这些将存储累积乘积和数字之和。 
2. 虽然`n`大于零，重复以下步骤：

 1. 使用提取最后一位数字`digit = n % 10`。 
2. 乘法`digit_product`经过`digit`并添加`digit`到`digit_sum`。 
3. 删除最后一位数字`n`使用整数除法`n = n // 10`。 
3. 处理完所有数字后，计算差异`digit_product - digit_sum`。 
4. 返回结果。 

为什么它有效：该算法维护两个不变量：`digit_product`始终保存所有已处理数字的乘积，并且`digit_sum`持有总和。 通过对所有数字精确地迭代一次，可以保证差异反映整个数字。 

## Python 解决方案```python
class Solution:
    def subtractProductAndSum(self, n: int) -> int:
        digit_product = 1
        digit_sum = 0
        while n > 0:
            digit = n % 10
            digit_product *= digit
            digit_sum += digit
            n //= 10
        return digit_product - digit_sum
```此实现初始化了两个变量：乘积和总和。 然后，它使用模迭代提取最后一位数字，更新乘积和总和，并使用整数除法删除最后一位数字。 处理完所有数字后，它会返回差值。 

## 解决方案```go
func subtractProductAndSum(n int) int {
    digitProduct := 1
    digitSum := 0
    for n > 0 {
        digit := n % 10
        digitProduct *= digit
        digitSum += digit
        n /= 10
    }
    return digitProduct - digitSum
}
```Go 版本密切反映了 Python 逻辑。 它使用整数除法和取模来提取数字并维护累积积和和。 Go 可以安全地处理这些小数字的整数运算，因此不需要特殊考虑。

 ## 边缘情况

 一种边缘情况是一位数，例如`n = 1`。 此处，乘积和和相同，导致差值为零。 该算法可以正确处理这个问题，因为它初始化了`digit_product`到 1 和`digit_sum`至 0。 

另一种边缘情况是包含零的数字，例如`n = 101`。 乘以零会将乘积设置为零，并且总和仍将计算所有数字。 算法正确计算`0 - (1+0+1) = -2`。 

第三个边缘情况是允许的最大数量，`n = 100000`。 尽管它有六位数字，但其中只有五位非零。 该算法自然扩展，完全按照预期执行，没有溢出或错误。 这确保了输入约束的正确性。
