[LeetCode 问题 1241](https://leetcode.com/problems/number-of-comments-per-post/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们分析一个名为`Submissions`并确定每个帖子有多少条独特的评论。 

该表包含两列：

 | 专栏 | 意义|
 | ---| ---|
 |`sub_id`| 当前提交的 ID |
 |`parent_id`| 家长提交 ID |

 一行代表一篇文章或一条评论：

 - 如果`parent_id`是`NULL`，该行是一个帖子。 
- 如果`parent_id`不是`NULL`，该行是一条评论，其父级是另一个提交。 

目标是生成一个结果表，其中包含：

 | 专栏 | 意义|
 | ---| ---|
 |`post_id`| 帖子ID |
 |`number_of_comments`| 属于该帖子的独特评论数量 |

 有几个细节使得这个问题比简单的计数稍微复杂一些。 

首先，表可能包含重复的行。 如果同一个帖子出现多次，我们仍将其视为单个帖子。 同样，如果同一条评论出现多次，则只算一次。 

其次，并不是每一条评论都应该被计算在内。 评论仅在以下情况下才算数：`parent_id`指的是表中存在的实际帖子。 如果评论引用了已删除或不存在的帖子，我们将完全忽略它。 

输出必须按以下顺序排序`post_id`按升序排列。 

主要观察结果是：

 - 帖子是行，其中`parent_id IS NULL`- 注释是行，其中`parent_id IS NOT NULL`- 计算之前必须删除重复的评论
 - 重复的帖子也必须被视为一篇帖子
 - 指向不存在帖子的评论必须被忽略

 输入大小没有明确给出，但由于这是一个归类为“简单”的数据库问题，我们仍然应该致力于使用分组和不同计数来进行有效的查询，而不是昂贵的重复扫描。 

一些边缘情况很重要：

 - 帖子可能有零评论
 - 同一条评论可能会出现多次
 - 同一个帖子可能会出现多次
 - 评论可能会引用已删除的帖子
 - 多个评论可能属于同一个帖子
 - 该表可能仅包含帖子或仅包含评论

 一个简单的实现，仅对按以下分组的行进行计数`parent_id`会错误地计算重复项和已删除的帖子引用。 

## 方法

 ### 蛮力方法

 强力解决方案首先会识别每个不同的帖子。 然后，对于每个帖子，我们将扫描整个表格并计算有多少评论引用该帖子。 

从概念上讲，该算法的工作原理如下：

 1. 提取所有独特的帖子。 
2. 对于每个帖子：

 - 迭代整个表。 
- 检查每一行是否是属于当前帖子的评论。 
- 将唯一的评论 ID 存储在临时集中。 
3. 输出最终计数。 

这种方法是正确的，因为每个帖子都会明确检查所有可能的评论。 可以使用临时集删除重复的注释。 

然而，这种方法效率低下，因为每个帖子都会重复扫描表。 如果有`P`帖子和`N`总行数，复杂度大约变为`O(P × N)`。 

### 最佳方法

 更好的解决方案是使用 SQL 分组和聚合。 

关键的见解是 SQL 旨在有效聚合相关行。 我们可以：

 1. 提取所有不同的帖子。 
2. 使用以下命令将评论加入到这些帖子中`parent_id`。 
3. 计算每个帖子的不同评论 ID。 

使用`COUNT(DISTINCT sub_id)`自动删除重复评论。 

使用`LEFT JOIN`确保零评论的帖子仍然出现在结果中。 

这将问题转化为单个分​​组聚合查询，这在 SQL 中更加高效和惯用。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(P × N) | O(C)| 重复扫描表格中的每个帖子 |
 | 最佳| 大约 O(N log N) | O(N) | 有效地使用分组和不同聚合 |

 ## 算法演练

 1. 首先，通过选择其中的行来识别所有唯一的帖子`parent_id IS NULL`。 

这些行代表有效的帖子。 由于可能存在重复的帖子，我们使用`DISTINCT`to ensure each post appears only once.
 2. Next, identify all comments.

 注释是行，其中`parent_id IS NOT NULL`。 这`parent_id`告诉我们该评论属于哪个帖子。 
3. 执行`LEFT JOIN`帖子和评论之间。 

我们匹配：

 -`posts.sub_id`-`comments.parent_id`这会将每个帖子与引用该帖子的所有评论相关联。 
4. 使用`COUNT(DISTINCT comments.sub_id)`。 

重复的注释可能会在表中出现多次。 使用`DISTINCT`确保每个评论 ID 只计算一次。 
5. 按帖子 ID 分组。 

这会为每个帖子生成一行及其唯一评论总数。 
6. 对结果进行排序`post_id`按升序排列。 

### 为什么它有效

 该解决方案之所以有效，是因为首先显式提取每个有效帖子，并且仅当评论成功加入其中一个帖子时才会计入评论。 使用删除重复的帖子`DISTINCT`，使用删除重复注释`COUNT(DISTINCT ...)`，并且没有评论的帖子将通过`LEFT JOIN`。 

## Python 解决方案

 虽然这本质上是一个 SQL 问题，但 LeetCode 数据库问题通常是用算法来解释的。 以下 Python 实现模拟了相同的逻辑。```python
from typing import List, Optional
from collections import defaultdict

class Solution:
    def numberOfComments(self, submissions: List[List[Optional[int]]]) -> List[List[int]]:
        posts = set()
        
        for sub_id, parent_id in submissions:
            if parent_id is None:
                posts.add(sub_id)

        comments_per_post = defaultdict(set)

        for sub_id, parent_id in submissions:
            if parent_id is not None and parent_id in posts:
                comments_per_post[parent_id].add(sub_id)

        result = []

        for post_id in sorted(posts):
            result.append([post_id, len(comments_per_post[post_id])])

        return result
```实现首先将所有有效帖子收集到一个集合中。 使用集合会自动删除重复的帖子。 

接下来，我们创建一个字典，其中每个帖子都映射到一组唯一的评论 ID。 集合很重要，因为重复的注释可能会在输入中出现多次。 

然后我们再次迭代所有行。 如果一行代表一条评论且其父级作为有效帖子存在，我们会将评论 ID 插入到该帖子的评论集中。 

最后，我们迭代排序后的帖子并计算每个评论集的大小。 

这直接反映了 SQL 逻辑：

 -`posts`对应于不同的帖子
 -`comments_per_post`对应分组评论
 -`set()`对应于`DISTINCT`- 排序对应于`ORDER BY`## 解决方案```go
package main

import (
	"sort"
)

func numberOfComments(submissions [][]*int) [][]int {
	posts := make(map[int]bool)

	for _, row := range submissions {
		subID := *row[0]
		parentID := row[1]

		if parentID == nil {
			posts[subID] = true
		}
	}

	commentsPerPost := make(map[int]map[int]bool)

	for _, row := range submissions {
		subID := *row[0]
		parentID := row[1]

		if parentID != nil {
			parent := *parentID

			if posts[parent] {
				if commentsPerPost[parent] == nil {
					commentsPerPost[parent] = make(map[int]bool)
				}

				commentsPerPost[parent][subID] = true
			}
		}
	}

	postIDs := make([]int, 0, len(posts))

	for postID := range posts {
		postIDs = append(postIDs, postID)
	}

	sort.Ints(postIDs)

	result := [][]int{}

	for _, postID := range postIDs {
		count := 0

		if commentsPerPost[postID] != nil {
			count = len(commentsPerPost[postID])
		}

		result = append(result, []int{postID, count})
	}

	return result
}
```Go 版本遵循与 Python 解决方案相同的逻辑，但存在一些特定于语言的差异。 

由于 Go 没有内置的集合类型，因此使用带有布尔值的映射来模拟集合。 

输入使用`*int`指针使得`nil`可以代表SQL`NULL`。 

Go 还需要使用显式排序`sort.Ints()`在生成最终结果之前。

 ## 边缘情况

 当表包含重复注释时，会出现一种重要的边缘情况。 一个简单的计数解决方案使用`COUNT(*)`会错误地增加评论数量。 此实现通过将评论 ID 存储在一个集合中来避免该问题，该集合会自动删除重复项。 

另一个重要的边缘情况是引用已删除或不存在的帖子的评论。 例如，像这样的行`(6, 7)`如果发帖则不应算作`7`不存在。 该实现在计算评论之前显式检查父帖子是否存在于有效帖子集中。 

第三个边缘情况是零评论的帖子。 许多不正确的解决方案意外地排除了此类帖子，因为它们使用内部联接而不是左联接。 此实现正确地包含每个有效的帖子，并在不存在评论时分配计数为零。 

第四个微妙的情况涉及重复的帖子行。 由于该表可能多次包含相同的帖子，因此未能对帖子进行重复数据删除将产生重复的输出行。 使用帖子集可以保证每个帖子在最终结果中恰好出现一次。
