 # LeetCode 1278 - 回文分区 III

 ## 问题理解

 问题给了我们一个字符串`s`和一个整数`k`。 我们可以修改字符串中的字符，我们的目标是将字符串准确地划分为`k`非空子串，使得每个子串在修改后都成为回文。 

回文是向前和向后读相同的字符串。 例如，`"aba"`和`"aa"`是回文，而`"abc"`不是。 

重要的细节是我们不需要保留原始字符。 我们可以将任何字符更改为任何小写英文字母。 目标是最小化所有子字符串中字符更改的总数。 

例如，如果`s = "abc"`和`k = 2`，我们可以将字符串拆分为`"ab"`和`"c"`。 子串`"ab"`不是回文，但可以改变`'a'`到`'b'`或者`'b'`到`'a'`使其合而为一。 这仅需要一项修改，所以答案是`1`。 

The constraints are small enough to strongly suggest a dynamic programming solution:

 -`1 <= k <= s.length <= 100`- 字符串仅包含小写英文字母。 

由于最大字符串长度仅为`100`，三次复杂度的算法是可以接受的。 然而，指数暴力解决方案仍然太慢。 

一些边缘情况很重要：

 - 当`k == s.length`，每个字符都可以形成自己的子串，所以答案总是`0`。 
- 什么时候`k == 1`，整个字符串必须成为一个回文。 
- 某些子串可能已经是回文，不需要更改。 
- 分区位置显着影响总成本，因此贪婪策略可能会失败。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试一切可能的方法将字符串分为`k`子串。 对于每个分区，我们将计算需要多少个字符修改才能使每个子串成为回文。 

为了计算子字符串的回文成本，我们从两端向中心比较字符。 每一个不匹配的对都会贡献一个所需的修改。 

主要问题是可能的分区数量。 选择`k - 1`分割位置`n - 1`可能的位置会导致组合爆炸。 尽管检查每个分区的成本相对较低，但可能性的总数变得不切实际。 

这种方法是正确的，因为它详尽地评估了所有有效分区，但对于`n = 100`。 

### 最优动态规划方法

 关键的观察结果是，许多子串回文成本在不同的分区中重复使用。 

我们可以将问题分成两个较小的子问题：

 1. 预先计算将每个子串转换为回文的成本。 
2. 使用动态规划求出最小划分成本。 

对于第一步，定义：

 -`cost[i][j]`= 需要进行的最少更改`s[i:j+1]`一个回文。 

这可以使用间隔 DP 有效地计算。 

对于第二步，定义：

 -`dp[i][p]`= 从索引处开始划分子字符串的最小成本`i`准确地进入`p`回文部分。 

我们尝试第一个分区的每个可能的结束位置，然后递归地解决剩余的后缀。 

由于重叠子问题被大量重用，动态编程大大降低了复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(k) | 尝试每个分区配置 |
 | 最优动态规划| O(n3 + kn2) | O(n² + kn) | 预先计算回文成本并使用 DP |

 ## 算法演练

 ### 步骤 1：预先计算回文转换成本

 创建一个二维数组`cost`在哪里：

-`cost[i][j]`表示转换子字符串所需的最小更改`s[i:j+1]`成回文。 

计算这个：

 1.如果`i >= j`，子串有长度`0`或者`1`，所以成本是`0`。 
2.否则：

 - 比较`s[i]`和`s[j]`- 如果不同，则需要进行一项修改
 - 添加内部子串的成本

 递归变为：$cost[i][j] = cost[i+1][j-1] + [s_i \neq s_j]$我们通过增加长度来处理子字符串，因此已经计算出更小的间隔。 

### 步骤 2：定义 DP 状态

 创建DP表：

 -`dp[i][p]`= 划分子串的最小成本`s[i:]`准确地进入`p`回文子串。 

最终答案将是：$dp[0][k]$### 步骤 3：状态之间的转换

 对于每个州`(i, p)`:

 1. 尝试每一个可能的端点`j`对于第一个分区。 
2. 第一个子串是`s[i:j+1]`。 
3. 其回文转换成本为`cost[i][j]`。 
4. 剩下的后缀开始于`j + 1`并且必须划分为`p - 1`部分。 

过渡：$dp[i][p] = \min_{j \ge i}(cost[i][j] + dp[j+1][p-1])$### 步骤 4：基本案例

 如果只剩下一个分区：

 -`dp[i][1] = cost[i][n-1]`这意味着剩余的整个后缀必须成为一个回文。 

### 第 5 步：返回答案

 答案是`dp[0][k]`。 

### 为什么它有效

 该算法之所以有效，是因为每个有效分区都可以分解为：

 1. 第一个回文子串。 
2. 剩余后缀的最优划分。 

DP 递归检查所有可能的第一次切割并选择最小的总成本。 由于每个子问题都得到最优解决并一致地重用，因此最终结果是全局最优的。 

## Python 解决方案```python
class Solution:
    def palindromePartition(self, s: str, k: int) -> int:
        n = len(s)

        # cost[i][j] = minimum changes needed
        # to make s[i:j+1] a palindrome
        cost = [[0] * n for _ in range(n)]

        # Build costs by substring length
        for length in range(2, n + 1):
            for left in range(n - length + 1):
                right = left + length - 1

                if left + 1 <= right - 1:
                    cost[left][right] = cost[left + 1][right - 1]

                if s[left] != s[right]:
                    cost[left][right] += 1

        INF = float('inf')

        # dp[i][p] = minimum cost to partition
        # s[i:] into p palindromic substrings
        dp = [[INF] * (k + 1) for _ in range(n + 1)]

        # Base case
        dp[n][0] = 0

        for i in range(n - 1, -1, -1):
            dp[i][1] = cost[i][n - 1]

        # Fill DP table
        for parts in range(2, k + 1):
            for start in range(n):
                # Ensure enough characters remain
                for end in range(start, n - parts + 1):
                    dp[start][parts] = min(
                        dp[start][parts],
                        cost[start][end] + dp[end + 1][parts - 1]
                    )

        return dp[0][k]
```该实现首先预先计算所有子串的回文转换成本。 这避免了在分区期间重复重新计算不匹配计数。 

子字符串长度上的嵌套循环确保较小的间隔先于较大的间隔处理。 这是必要的，因为`cost[left][right]`取决于`cost[left + 1][right - 1]`。 

预处理后，算法初始化动态规划表。 每个条目表示将后缀划分为特定数量的回文部分的最小成本。 

该转换会迭代第一个分区的每个可能的结束索引。 对于每个候选分割，该算法结合：

 1. 将当前子串转换为回文的成本。 
2. 划分剩余后缀的最优成本。 

最后，`dp[0][k]`包含最小修改总数。 

## 解决方案```go
func palindromePartition(s string, k int) int {
	n := len(s)

	// cost[i][j] = minimum changes needed
	// to make s[i:j+1] a palindrome
	cost := make([][]int, n)
	for i := range cost {
		cost[i] = make([]int, n)
	}

	// Build palindrome costs
	for length := 2; length <= n; length++ {
		for left := 0; left+length-1 < n; left++ {
			right := left + length - 1

			if left+1 <= right-1 {
				cost[left][right] = cost[left+1][right-1]
			}

			if s[left] != s[right] {
				cost[left][right]++
			}
		}
	}

	const INF = int(1e9)

	// dp[i][p] = minimum cost to partition
	// s[i:] into p palindromic substrings
	dp := make([][]int, n+1)
	for i := range dp {
		dp[i] = make([]int, k+1)

		for j := range dp[i] {
			dp[i][j] = INF
		}
	}

	dp[n][0] = 0

	for i := n - 1; i >= 0; i-- {
		dp[i][1] = cost[i][n-1]
	}

	for parts := 2; parts <= k; parts++ {
		for start := 0; start < n; start++ {
			for end := start; end <= n-parts; end++ {
				candidate := cost[start][end] + dp[end+1][parts-1]

				if candidate < dp[start][parts] {
					dp[start][parts] = candidate
				}
			}
		}
	}

	return dp[0][k]
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片而不是列表。 

由于 Go 没有为整数提供无穷大常数，因此较大的哨兵值，例如`1e9`被使用。 

DP 数组是显式初始化的，因为 Go 不支持 Python 风格的列表推导式。 否则，算法结构和递归关系保持相同。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n3 + kn2) | 用于预处理的 O(n²) 子串，以及分区 DP 转换 |
 | 空间| O(n² + kn) | 存储回文成本和 DP 状态 |

 回文预处理需要检查所有子串间隔，这需要`O(n²)`州。 每个状态都执行持续的工作。 

分区 DP 有`O(nk)`州，每个州可以尝试最多`O(n)`分区端点，导致`O(kn²)`总体时间。 

自从`n <= 100`，这种复杂性很容易在限制范围内。

 ## 边缘情况

 ### 案例 1：`k == s.length`当每个字符成为其自己的子串时，每个子串自动成为回文。 有缺陷的实现可能仍然会尝试不必要的修改或无效的转换。 

此实现可以自然地处理这种情况，因为 DP 允许长度分区`1`，其回文成本始终为`0`。 

### 情况 2：整个字符串必须保留在一个分区中

 当`k == 1`，算法必须计算整个字符串所需的最小修改量。 

预处理表通过以下方式直接支持这一点：```
dp[i][1] = cost[i][n-1]
```这避免了递归或转换期间的任何特殊情况逻辑。 

### 情况3：分区分布不均匀

 有些字符串需要高度不平衡的分区才能获得最佳答案。 例如，一个分区可能包含大部分字符，而其他分区则包含单个字母。 

贪心方法可能会因过早选择局部最优回文子串而失败。 DP 解决方案避免了这个问题，因为它在选择最小总成本之前会评估每个可能的分区端点。
