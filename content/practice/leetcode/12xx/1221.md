 # LeetCode 1221 - 将字符串拆分为平衡字符串

 ## 问题理解

 这个问题给了我们一个字符串`s`仅包含字符`'L'`和`'R'`。 该字符串保证已经总体平衡，这意味着字符串的总数`'L'`字符数等于总数`'R'`人物。 

我们的任务是将这个字符串分割成尽可能多的非空子串，使得每个子串也是平衡的。 当一个子串包含相同数量的子串时，该子串被认为是平衡的`'L'`和`'R'`人物。 

重要的细节是我们不是简单地检查整个字符串是否平衡。 我们必须确定可以将其分成多少个平衡的部分，同时最大化这些部分的数量。 

例如，在字符串中`"RLRRLLRLRL"`:

 -`"RL"`是平衡的
 -`"RRLL"`是平衡的
 -`"RL"`是平衡的
 -`"RL"`是平衡的

 这总共给出了 4 个平衡子串，这是可能的最大值。 

输入尺寸很小，因为`s.length <= 1000`。 这意味着即使效率较低的解决方案在技术上也可以工作，但问题的结构允许具有线性时间复杂度的非常干净的贪婪解决方案。 

一些重要的观察结果直接来自约束：

 - 该字符串仅包含两个可能的字符。 
- 保证整个字符串是平衡的。 
- 每个有效的分割必须保留字符顺序。 
- 我们想要最大数量的平衡子串，因此较小的有效平衡块通常更好。 

一些边缘情况值得尽早考虑：

 - 像这样的字符串`"LR"`或者`"RL"`已经是可能的最小平衡子串。 
- 像这样的字符串`"LLLLRRRR"`整体上是平衡的，但不能分割成更小的平衡部分。 
- 交替字符串，例如`"RLRLRL"`产生许多平衡子串。 
- 由于输入保证平衡，我们永远不需要处理计数不匹配的无效最终状态。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试一切可能的方法将字符串拆分为子字符串。 对于每个分区，我们将验证每个子字符串是否包含相同数量的`'L'`和`'R'`。 

这种方法是正确的，因为它探索了所有可能的分割组合并选择具有最大数量平衡块的分区。 

然而，这种策略的效率极低。 一个长度的字符串`n`有指数级多种可能的分区方式。 对于每个分区，我们还需要计算每个子字符串内的字符数。 

尽管约束只有 1000 个字符，但指数分区生成仍然太慢。 

### 最优贪心法

 关键的见解是，每当我们遇到一个前缀时，其中的数量`'L'`和`'R'`字符变得相等，我们应该立即在那里拆分。 

为什么这种贪婪的选择是最优的？ 

平衡前缀可以安全地成为其自己的子字符串，因为它已经满足要求。 延迟分割只会将其与后面的字符合并，从而减少我们可以形成的子字符串的总数。 

因此，最好的策略是：

 - 遍历字符串一次。 
- 保持跑步平衡。 
- 增加一种字符类型的余额并减少另一种字符类型的余额。 
- 每当余额变为零时，我们就找到了一个平衡子串。 

这是有效的，因为零余额意味着我们看到了相同数量的`'L'`和`'R'`。

 ## 算法演练

 1.初始化两个变量：

 -`balance = 0`-`balanced_count = 0`这`balance`变量跟踪数量之间的差异`'R'`和`'L'`目前为止看到的角色。 
2. 逐个字符地遍历字符串。 
3. 对于每个字符：

 - 如果角色是`'R'`, 增量`balance`。 
- 如果角色是`'L'`, 递减`balance`。 

我们可以反转这些操作，算法仍然有效。 重要的是一致性。 
4. 更新余额后，检查是否`balance == 0`。 

余额为零意味着当前段包含相同数量的`'L'`和`'R'`。 
5. 每当余额变为零时：

 - 增量`balanced_count`。 
- 从概念上讲，从下一个字符开始一个新的子字符串。 
6. 继续直到字符串末尾。 
7. 返回`balanced_count`。 

### 为什么它有效

 该算法保持不变式`balance`表示计数之间的差异`'R'`和`'L'`在当前正在形成的子字符串中。 

每当余额达到零时，就保证当前子串是平衡的。 立即拆分始终是最佳选择，因为使用尽可能小的有效平衡子字符串可以留下更多字符，以便稍后形成其他平衡子字符串。 

因此，在每个零平衡处贪婪地分裂可以最大化平衡子串的数量。 

## Python 解决方案```python
class Solution:
    def balancedStringSplit(self, s: str) -> int:
        balance = 0
        balanced_count = 0

        for char in s:
            if char == 'R':
                balance += 1
            else:
                balance -= 1

            if balance == 0:
                balanced_count += 1

        return balanced_count
```实现直接遵循贪心算法。 

变量`balance`跟踪之间的运行差异`'R'`和`'L'`。 每个`'R'`增加平衡，而每个`'L'`减少它。 

当我们从左到右扫描字符串时，每当余额变为零时，我们就知道我们已经完成了一个平衡子字符串。 此时，我们增加`balanced_count`。 

该算法永远不需要显式存储子字符串，因为只有计数很重要。 这使内存使用量保持恒定。 

## 解决方案```go
func balancedStringSplit(s string) int {
    balance := 0
    balancedCount := 0

    for _, char := range s {
        if char == 'R' {
            balance++
        } else {
            balance--
        }

        if balance == 0 {
            balancedCount++
        }
    }

    return balancedCount
}
```Go 实现与 Python 版本几乎相同。 

Go 使用 a 迭代字符串`range`循环，返回 Unicode 符文值。 由于输入仅包含 ASCII 字符`'L'`和`'R'`，符文处理很简单。 

不需要额外的切片或数组，因此该解决方案保持恒定的额外空间使用。

 ## 边缘情况

 一种重要的边缘情况是最小的有效输入，例如`"RL"`或者`"LR"`。 有缺陷的实现可能会错误地需要更长的子字符串或错误地处理第一次余额重置。 此实现正确识别处理两个字符后余额达到零并返回`1`。 

另一个重要的情况是当整个字符串是平衡的但不能提前拆分时，例如`"LLLLRRRR"`或者`"RRRLLL"`。 一些不正确的贪婪实现可能会在不检查实际平衡条件的情况下尝试过早分裂。 该解决方案仅在余额恰好为零时才分裂，因此它会正确返回`1`。 

第三个重要的边缘情况是高度交替的字符串，例如`"RLRLRLRL"`。 这些输入创建了许多微小的平衡子串。 延迟分割的实现会产生太少的子串。 因为每当余额达到零时，该算法就会立即贪婪地分裂，因此它正确地最大化了平衡子串的数量。
