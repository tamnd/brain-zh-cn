[LeetCode Problem 1214](https://leetcode.com/problems/two-sum-bsts/)

 **难度：** 🟡 中等
 **Topics:** Two Pointers, Binary Search, Stack, Tree, Depth-First Search, Binary Search Tree, Binary Tree

 ## 解决方案

 ## 问题理解

 The problem gives us two binary search trees,`root1`和`root2`，以及一个整数`target`。 我们必须确定第一棵树中是否存在一个节点以及第二棵树中是否存在一个节点，使得它们的值加起来正好等于`target`。 

二叉搜索树（BST）具有重要的排序属性。 对于每个节点，左子树中的所有值都小于该节点值，右子树中的所有值都大于该节点值。 与常规二叉树相比，此排序属性允许更有效的搜索。 

输入由两个树根和一个整数目标组成。 每棵树包含 1 到 5000 个节点，因此两棵树的节点总数是可以管理的，但足够大，以至于二次暴力解决方案变得低效。 节点值和目标可能为负数，这意味着解决方案必须正确处理涉及负数和大整数范围的和。 

预期输出是一个布尔值。 我们返回`true`如果存在至少一对节点，每棵树一个，其总和等于目标。 否则，我们返回`false`。 

一些重要的边缘案例立即脱颖而出。 一棵树可能包含非常小的负值，而另一棵树可能包含很大的正值。 匹配对可能涉及树之间的重复值。 有效对可能直接涉及根节点，也可能涉及深度嵌套的节点。 另一个重要的考虑因素是树保证非空，因此我们永远不需要处理完全空的输入树。 由于值可能大到`10^9`，我们还必须避免关于小整数范围的假设。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将第一棵树中的每个节点与第二棵树中的每个节点进行比较。 我们可以遍历第一棵树，并且对于每个节点值`x`，遍历第二棵树寻找等于的节点值`target - x`。 

真正简单的版本将对第一棵树中的每个节点执行第二棵树的完整遍历。 如果第一棵树包含`n`节点和第二棵树包含`m`节点，这导致`O(n * m)`时间复杂度。 

这种方法是正确的，因为它检查两棵树上每一个可能的节点对。 如果存在任何有效的对，暴力法最终会找到它。 然而，它的效率很低，因为它完全忽略了 BST 属性。 

### 最佳方法

 关键在于 BST 支持高效搜索。 我们可以使用 BST 查找操作，而不是扫描整个第二棵树来查找第一棵树中的每个节点。 

我们使用 DFS 遍历第一棵树。 对于每个节点值`x`，我们计算所需的补集`target - x`。 然后，我们使用标准 BST 搜索逻辑在第二个 BST 中搜索该补集。 

因为 BST 搜索需要`O(h)`时间、地点`h`是树的高度，每次查找都比完全遍历快得多。 在平衡 BST 中，这是`O(log m)`平均而言。 

这种方法之所以有效，是因为每个有效对必须包含第一棵树中的一个值和第二棵树中的一个值。 通过系统地检查补码，我们保证不会遗漏任何有效的对。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(h1 + h2) | O(h1 + h2) | 比较每个节点对 |
 | 最佳 | O(n * h2) 平均 | O(h1 + h2) | O(h1 + h2) | 在第一棵树上进行 DFS，在第二棵树上进行 BST 搜索 |

 这里，`h1`和`h2`代表两棵树的高度。 

## 算法演练

 1. 开始对第一个 BST 进行深度优先遍历。 我们访问每个节点，因为任何节点都可能参与目标总和。 
2. 对于第一棵树中的每个节点，计算第二棵树所需的补值。 如果当前节点值为`x`，所需的补集是`target - x`。 
3. 使用标准 BST 查找逻辑在第二个 BST 中搜索该补集。 因为第二棵树是 BST，所以我们可以根据补集是否小于或大于当前节点来有效地向左或向右移动。 
4. 如果第二棵树中存在补集，则立即返回`true`。 我们找到了一个有效的对，其总和等于目标。 
5. 如果未找到补集，则继续 DFS 遍历第一棵树中当前节点的左子节点和右子节点。 
6. 如果遍历整个第一棵树没有找到有效的对，则返回`false`。 

该算法使用递归，因为递归 DFS 自然适合树遍历问题。 通过递归或迭代遍历，BST 搜索操作也变得非常简洁和可读。 

### 为什么它有效

 该算法之所以有效，是因为它系统地检查第一棵树中的每个可能的候选者。 对于每个候选值`x`，它验证是否精确补集`target - x`存在于第二棵树中。 由于 BST 查找可以正确确定平均对数时间内是否存在某个值，因此可以有效地检查每个有效对。 如果存在有效的对，算法最终将在第一棵树中遇到相应的节点，并在第二棵树中成功找到其补集。 

## Python 解决方案```python
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def twoSumBSTs(
        self,
        root1: Optional['TreeNode'],
        root2: Optional['TreeNode'],
        target: int
    ) -> bool:

        def search_bst(node: Optional['TreeNode'], value: int) -> bool:
            while node:
                if node.val == value:
                    return True
                elif value < node.val:
                    node = node.left
                else:
                    node = node.right
            return False

        def dfs(node: Optional['TreeNode']) -> bool:
            if not node:
                return False

            complement = target - node.val

            if search_bst(root2, complement):
                return True

            return dfs(node.left) or dfs(node.right)

        return dfs(root1)
```该实现分为两个辅助函数。 

这`search_bst`函数执行标准 BST 查找。 从第二棵树的根开始，它反复比较目标值和当前节点值。 如果目标较小，则向左移动。 如果较大，则向右移动。 这利用了 BST 排序属性来实现高效搜索。 

这`dfs`函数使用深度优先搜索遍历第一棵树。 在每个节点，它计算所需的补集并在第二棵树中搜索它。 如果找到则立即返回`True`。 否则，继续递归遍历两个子树。 

最后的 return 语句从第一棵树的根开始 DFS。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func twoSumBSTs(root1 *TreeNode, root2 *TreeNode, target int) bool {

    var searchBST func(node *TreeNode, value int) bool

    searchBST = func(node *TreeNode, value int) bool {
        for node != nil {
            if node.Val == value {
                return true
            } else if value < node.Val {
                node = node.Left
            } else {
                node = node.Right
            }
        }
        return false
    }

    var dfs func(node *TreeNode) bool

    dfs = func(node *TreeNode) bool {
        if node == nil {
            return false
        }

        complement := target - node.Val

        if searchBST(root2, complement) {
            return true
        }

        return dfs(node.Left) || dfs(node.Right)
    }

    return dfs(root1)
}
```Go 的实现与 Python 版本非常相似。 一个显着的区别是 Go 需要在递归赋值之前显式函数变量声明。 因此我们声明`searchBST`和`dfs`使用`var`在分配匿名函数之前。 

Go 使用`nil`而不是Python的`None`，并且树节点引用需要指针语法。 整数溢出在这里不是一个问题，因为 Go 的`int`type 轻松支持约束范围。 

## 工作示例

 ### 示例 1

 输入：```
root1 = [2,1,4]
root2 = [1,0,3]
target = 5
```第一个 BST 包含值`{1,2,4}`。 

第二个 BST 包含值`{0,1,3}`。 

我们在第一棵树上开始 DFS。 

| 当前节点| 需要补充| root2 中的搜索结果 |
 | ---| ---| ---|
 | 2 | 3 | 发现 |

 在第一个节点本身，补码`3`存在于第二个 BST 中。 

自从`2 + 3 = 5`，算法立即返回`true`。 

### 示例 2

 输入：```
root1 = [0,-10,10]
root2 = [5,1,7,0,2]
target = 18
```第一棵树的值为`{-10,0,10}`。 

第二棵树的值为`{0,1,2,5,7}`。 

我们遍历第一棵树。 

| 当前节点| 需要补充| 存在于 root2 |
 | ---| ---| ---|
 | 0 | 18 | 18 没有 |
 | -10 | 28 | 28 没有 |
 | 10 | 10 8 | 没有 |

 任何节点值都不存在补集。 

遍历完全结束，算法返回`false`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * h2) 平均 | 通过第一棵树进行 DFS 并在第二棵树中进行 BST 搜索 |
 | 空间| O(h1 + h2) | O(h1 + h2) | 递归调用栈和BST遍历|

 如果第二棵树是平衡的，`h2`变成`O(log m)`，平均复杂度为`O(n log m)`。 在最坏的情况下，如果树完全倾斜，`h2`变成`O(m)`并且复杂性降级为`O(n * m)`。 

空间复杂度主要来自递归深度。 在平衡树中，递归深度是对数的。 在倾斜的树中，它变成线性的。

 ## 边缘情况

 一个重要的边缘情况是两棵树仅包含一个节点。 这是最小可能的有效输入。 粗心的实现可能会采用更大的树结构或错误地处理递归终止。 当前的实现可以自然地处理这个问题，因为 DFS 和 BST 搜索都可以正确处理单节点树。 

另一个关键的边缘情况涉及负值。 由于节点值和目标可能为负，因此该算法不能依赖于关于正性的假设。 例如，一个有效的对可以是`-5 + 2 = -3`。 该实现使用直接算术比较，因此无论符号如何都能正常工作。 

第三个重要的边缘情况是高度不平衡的树。 形状像链表的 BST 会导致查找操作从对数时间降级为线性时间。 递归深度也变得更大。 该实现仍然会产生正确的结果，因为即使在倾斜的树中，BST 遍历逻辑仍然有效，尽管性能会降低到最坏情况的复杂性。 

当匹配对使用来自不同树的相同值时，会出现最终的微妙边缘情况。 例如，`4`在第一棵树和`4`在第二棵树中的总和可能是`8`。 该实现正确地独立处理两棵树中的节点，因此处理相同的值不会出现问题。
