[LeetCode 第 1293 题](https://leetcode.com/problems/shortest-path-in-a-grid-with-obstacles-elimination/)

 **难度：** 🔴难
 **主题：** 数组、广度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到从网格的左上角移动到右下角所需的最少步数。 网格包含两种单元：

 -`0`，代表一个可以自由输入的空单元格
 -`1`, 代表障碍物

 通常，障碍物会阻碍运动。 但是，我们最多可以消除`k`旅途中的障碍。 消除障碍意味着我们可以穿过那个被封锁的单元格，同时消​​耗我们的障碍消除预算中的一个单位。 

运动仅限于四个基本方向：

 - 向上
 - 向下
 - 左
 - 右

 每一步只花费一步。 目标是尽量减少到达目的地所需的总步数。 

输入包括：

 -`grid`， 一个`m x n`矩阵
-`k`，我们可以移除的最大障碍数

 输出是：

 - 达到目标所需的最少步数`(m - 1, n - 1)`-`-1`如果不存在有效路径

 这些约束很重要，因为它们引导我们采取适当的算法策略。 

-`m, n <= 40`- 因此，网格最多包含`1600`细胞
 -`k`可能大到`m * n`对所有可能路径的强力搜索将导致组合爆炸并且变得不可行。 然而，网格尺寸足够小，具有精心管理状态的图遍历算法可以有效地工作。 

一个微妙但关键的细节是，以不同的剩余消除到达相同的单元代表不同的状态。 例如：

 - 到达`(2,3)`和`5`剩下的消除绝对比到达那里要好`1`剩余消除
 - 因此，仅位置不足以代表访问过的国家

 还有一些值得注意的边缘情况：

 - 网格可能已经是一个单元格，这意味着答案是`0`。 
- 除非移除障碍物，否则最短几何路径可能是不可能的。 
- 多个路径可能会以不同的消除计数到达同一单元格。 
- 如果`k`非常大，我们可以有效地忽略许多障碍并采取近乎直接的最短路线。 

## 方法

 ### 蛮力方法

 一个简单的解决方案会尝试使用深度优先搜索来探索从起点到目的地的每条可能的路径。 

在每一步中，我们都会：

 - 向四个方向移动
 - 如果遇到障碍，可选择消除障碍
 - 继续递归直到到达目的地

 这种方法是正确的，因为它最终探索了每条有效路径。 在所有成功的路径中，我们可以跟踪最小路径长度。 

然而，可能的路径数量呈指数增长。 即使在相对较小的网格上，搜索空间也会变得巨大，因为：

 - 路径可以重新访问单元格
 - 相同的单元格可能会通过不同的剩余消除到达
 - 许多分支通向死胡同

 如果没有积极的修剪，这种方法在计算上就变得不可行。 

### 最优方法，带有状态跟踪的广度优先搜索

 关键的观察结果是，这本质上是未加权图上的最短路径问题。 

每次移动只花费一步，这使得广度优先搜索成为理想的选择，因为 BFS 保证我们第一次到达目标时，我们使用了最少的步数。 

挑战在于，国家不仅仅是当前的立场。 

完整的状态包括：

 - 当前行
 - 当前列
 - 剩余障碍消除

 为什么这是必要的？ 

假设我们两次到达同一个单元格：

 - 曾经与`0`剩余消除额
 - 曾经与`3`剩余消除额

 这些不是等效的状态。 严格来说，第二种状态更强大，因为它允许消除未来的障碍。 

因此，我们不能用简单的`visited[row][col]`结构。 

相反，我们存储每个单元格的最大剩余消除量。 如果我们重新访问一个剩余消除次数比以前少的单元格，则该状态处于主导状态并且可以跳过。 

这种优化极大地减少了冗余探索。

 | 蛮力 | 指数| 指数| 递归探索所有可能的路径 |
 | 最优 BFS | O(m * n * k) | O(m * n * k) | 增强状态空间上的 BFS |

 ## 算法演练

 1. 初始化维度并处理琐碎的情况。 

如果网格只包含一个单元格，那么我们已经到达目的地，所以答案是`0`。 
2. 应用重要的优化。 

一个路径中的最短路径`m x n`不走弯路的网格是：`m + n - 2`如果`k`至少是这个值，那么我们总是可以直接走向目的地，同时消除遇到的任何障碍。 

在这种情况下，我们立即返回：`m + n - 2`3. 创建BFS队列。 

每个队列条目存储：

 - 当前行
 - 当前列
 - 剩余的消除
 - 迄今为止采取的步骤

 我们从以下开始：

 - 位置`(0,0)`-`k`剩余消除额
 -`0`步骤
 4. 高效跟踪访问过的状态。 

而不是存储每个`(row, col, remaining_k)`分别组合，我们维持：`visited[row][col] = maximum remaining eliminations seen`这是有效的，因为以更少的剩余消除到达相同的单元格永远不会更好。 
5. 进行BFS级别遍历。 

反复从队列中弹出状态。 

对于每个州：

 - 尝试所有四个方向
 - 跳过越界单元格
 - 判断进入下一个单元格是否消耗消除
 6. 更新剩余的抵销。 

如果下一个单元格包含障碍物：

 - 从剩余淘汰数中减去一

 如果剩余消除额变为负值：

 - 此动作无效
 7. 检查目的地。 

如果下一个单元格位于右下角：

 - 返回`steps + 1`因为 BFS 按距离递增的顺序探索状态，所以这保证是最短路径。 
8. 修剪占主导地位的州。 

在将新状态推入队列之前：

 - 将其剩余消除量与该单元格先前记录的最佳值进行比较

 如果我们已经到达具有相同或更大剩余预算的单元格：

 - 跳过此状态

 否则：

 - 更新`visited`- 将新状态加入队列
 9. 如果 BFS 完成但未达到目标：

 返回`-1`### 为什么它有效

 广度优先搜索按路径长度递增的顺序探索状态。 因此，第一次到达目的地必须对应最少的步数。 

剪枝规则也是正确的，因为在同一位置上，剩余淘汰数较多的州严格支配淘汰数较少的州。 任何来自较弱国家的未来路径也可以从较强国家获得。 

这些属性共同保证了正确性和效率。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def shortestPath(self, grid: List[List[int]], k: int) -> int:
        rows = len(grid)
        cols = len(grid[0])

        if rows == 1 and cols == 1:
            return 0

        # If we can eliminate enough obstacles to walk directly
        # to the destination, return the Manhattan distance.
        if k >= rows + cols - 2:
            return rows + cols - 2

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        queue = deque([(0, 0, k, 0)])

        # visited[row][col] stores the maximum remaining
        # eliminations seen at this cell.
        visited = [[-1] * cols for _ in range(rows)]
        visited[0][0] = k

        while queue:
            row, col, remaining_k, steps = queue.popleft()

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    new_row < 0
                    or new_row >= rows
                    or new_col < 0
                    or new_col >= cols
                ):
                    continue

                new_remaining_k = remaining_k - grid[new_row][new_col]

                if new_remaining_k < 0:
                    continue

                if new_row == rows - 1 and new_col == cols - 1:
                    return steps + 1

                # Skip dominated states.
                if visited[new_row][new_col] >= new_remaining_k:
                    continue

                visited[new_row][new_col] = new_remaining_k

                queue.append(
                    (
                        new_row,
                        new_col,
                        new_remaining_k,
                        steps + 1,
                    )
                )

        return -1
```实现首先提取网格尺寸并处理单细胞情况。 当起点已经是目的地时，这可以避免不必要的 BFS 工作。 

下一个优化检查是否`k`足够大，可以忽略直接最短路径上的所有障碍。 因为最短几何距离总是`rows + cols - 2`，至少有那么多消除可以保证沿着直接路径取得成功。 

BFS队列存储完整的遍历状态：

 - 当前坐标
 - 剩余的消除
 - 当前路径长度

 一个`deque`使用 BFS 是因为 BFS 在恒定时间内重复从前面删除元素并将新状态追加到后面。 

这`visited`矩阵存储观察到的每个细胞的最佳剩余消除计数。 这是防止重复探索的关键优化。 

在遍历过程中，会检查每个邻居：

 - 跳过无效坐标
 - 障碍消耗一次消除
 - 剩余淘汰数为负数的州将被丢弃

 如果到达目的地，算法立即返回当前距离加一步。 

在对新状态进行排队之前，算法会检查是否已以相同或更好的剩余消除计数到达相同的单元。 如果是这样，新状态将被支配并被忽略。 

如果 BFS 耗尽所有状态而没有找到目的地，则函数返回`-1`。 

## 解决方案```go
package main

import "container/list"

type State struct {
	row        int
	col        int
	remainingK int
	steps      int
}

func shortestPath(grid [][]int, k int) int {
	rows := len(grid)
	cols := len(grid[0])

	if rows == 1 && cols == 1 {
		return 0
	}

	if k >= rows+cols-2 {
		return rows + cols - 2
	}

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	queue := list.New()
	queue.PushBack(State{0, 0, k, 0})

	visited := make([][]int, rows)
	for i := 0; i < rows; i++ {
		visited[i] = make([]int, cols)

		for j := 0; j < cols; j++ {
			visited[i][j] = -1
		}
	}

	visited[0][0] = k

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		current := front.Value.(State)

		for _, dir := range directions {
			newRow := current.row + dir[0]
			newCol := current.col + dir[1]

			if newRow < 0 || newRow >= rows ||
				newCol < 0 || newCol >= cols {
				continue
			}

			newRemainingK := current.remainingK - grid[newRow][newCol]

			if newRemainingK < 0 {
				continue
			}

			if newRow == rows-1 && newCol == cols-1 {
				return current.steps + 1
			}

			if visited[newRow][newCol] >= newRemainingK {
				continue
			}

			visited[newRow][newCol] = newRemainingK

			queue.PushBack(
				State{
					newRow,
					newCol,
					newRemainingK,
					current.steps + 1,
				},
			)
		}
	}

	return -1
}
```Go 解决方案遵循与 Python 实现相同的算法结构。 

定制`State`struct 用于干净地存储 BFS 状态。 BFS队列是使用Go的实现的`container/list`封装，因为它提供高效的正面移除和背面插入。 

与 Python 不同，Go 不提供动态元组结构，因此显式结构字段提高了可读性和类型安全性。 

这`visited`矩阵是手动初始化的`-1`值，因为 Go 切片默认为`0`，这会错误地暗示单元已经被访问过，剩余的消除为零。 

不存在整数溢出问题，因为在问题约束下所有值仍然很小。

 该算法探索由以下定义的状态：```
(row, col, remaining_k)
```最多有：```
m * n * (k + 1)
```不同的状态。 

对于每个状态，我们尝试四个方向的移动，这是一项持续的工作。 因此，总运行时间与可达状态的数量成正比。 

队列和访问跟踪一起还需要与总状态空间成比例的存储。

    def shortestPath(self, grid: List[List[int]], k: int) -> int:

        rows = len(grid)
        cols = len(grid[0])

        if rows == 1 and cols == 1:
            return 0

        if k >= rows + cols - 2:
            return rows + cols - 2

 ## 边缘情况

 一个重要的边缘情况是单单元网格，例如`[[0]]`。 在这种情况下，起点和目的地是同一个单元格。 有缺陷的实现可能会错误地执行 BFS 并返回`1`而不是`0`。 该实现会立即处理此问题，并在任何遍历开始之前提前返回。 

当以不同的剩余消除计数多次到达同一单元格时，会发生另一种微妙的情况。 仅基于坐标的天真访问结构会错误地修剪潜在的最佳状态。 例如，较晚到达具有更多剩余消除的单元格可能会缩短未来的路线。 该实现通过存储每个单元观察到的最大剩余消除来解决这个问题。 

第三个重要的边缘情况发生在`k`相对于网格尺寸来说非常大。 如果不进行优化，BFS 仍然会不必要地探索巨大的状态空间。 该实现认识到如果`k >= rows + cols - 2`，我们总是可以直接到达目的地，同时消除沿途的障碍。 在这种情况下，答案就是曼哈顿距离。 

另一个棘手的情况涉及不可能的网格，其中所有路线都需要比可用的消除更多的消除。 有缺陷的实现可能会无限循环或错误地假设每个网格都是可解的。 这个解决方案自然可以处理这种情况，因为 BFS 最终会耗尽所有可达状态并返回`-1`。 

最后，边界移动是网格问题中错误的常见来源。 每个邻居扩展必须在访问网格之前验证行和列限制。 该实现在处理邻居之前显式检查边界，以防止无效的内存访问和不正确的遍历。
