 # LeetCode 1238 - 二进制表示中的循环排列

 ## 问题理解

 这个问题要求我们构造一个所有整数的特殊排序`0`到`2^n - 1`。 排序必须满足循环格雷码序列的属性。 

我们有两个整数：

 -`n`，它确定排列中存在多少个数字
 -`start`，它指定序列中的第一个数字

 由于有`2^n`可能的二进制值完全使用`n`位，最终排列必须包含范围内的每个整数`[0, 2^n - 1]`正好一次。 

重要的条件是，在二进制表示中，每对相邻的数字必须相差一位。 这包括由最后一个元素和第一个元素形成的最后对，因为该序列是循环的。 

例如，如果两个数字是：

 -`0101`-`0111`它们仅在一位位置上不同，因此此转换是有效的。 

然而：

-`0101`-`0011`两个位位置不同，因此该转换无效。 

限制相对较小：

 -`1 <= n <= 16`- 最大序列大小为`2^16 = 65536`这立即表明生成整个序列在时间和内存上都是可行的。 然而，暴力排列生成仍然是不可能的，因为`65536!`是一个天文数字。 

该问题保证有效答案始终存在。 这很重要，因为我们不需要处理不可能的情况。 

有几种边缘情况值得考虑：

 -`n = 1`，其中序列仅包含两个数字
 -`start = 0`，直接对应于标准格雷码排序
 - 大值`n`，效率很重要
 - 确保序列是循环的，这意味着最后一个和第一个元素也有一位不同

 关键的挑战是有效地构建序列，同时保留一位差异属性。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试生成以下数字的所有排列`0`到`2^n - 1`，然后测试每个相邻对是否仅相差一位。 

要检查两个数字是否相差一位，我们可以计算：```
x ^ y
```如果结果恰好包含一组位，则数字相差一位。 

尽管这种方法在概念上很简单，但完全不切实际。 即使是为了`n = 4`， 有`16!`排列，这已经是巨大的了。 为了`n = 16`，暴力是不可能的。 

蛮力方法确实保证了正确性，因为它详尽地搜索了所有可能的排列，但运行时间呈阶乘增长。 

### 最佳方法

 关键的观察是，问题从根本上要求格雷码序列。 

格雷码是一种数字排序，其中相邻值仅相差一位。 更好的是，标准二进制反射格雷码已经是循环的，这意味着第一个和最后一个元素也有一位不同。 

标准格雷码公式为：$G(i)=i\oplus(i\gg1)$该公式生成`i-th`格雷码值。 

例如，与`n = 2`:

 | 我| 二进制我 | 格雷码|
 | ---| ---| ---|
 | 0 | 00 | 00 00 | 00
 | 1 | 01 | 01 |
 | 2 | 10 | 10 11 | 11
 | 3 | 11 | 11 10 | 10

 结果序列：```
0, 1, 3, 2
```每个相邻对相差一位，包括从`2`回到`0`。 

剩下的挑战是序列必须以`start`。 

格雷码的一个美丽特性可以立即解决这个问题：

 如果我们将格雷码序列中的每个元素与相同的值进行异或，则邻接关系保持不变。 

因此，我们可以简单地生成标准格雷码序列并对每个值进行异或`start`。 

这会逻辑地旋转序列，以便：```
0 XOR start = start
```因此，序列自动开始于`start`。

 ## 算法演练

 1. 计算序列中值的总数。 

由于有`n`位，不同整数的总数为：$2^n$我们将其存储为：```
total = 1 << n
```2. 生成标准格雷码序列。 

对于每个整数`i`从`0`到`2^n - 1`，计算：```
gray = i ^ (i >> 1)
```这产生了规范的格雷码排序。 
3. 移动序列，使其开始于`start`。 

我们将每个格雷码值与`start`:```
value = gray ^ start
```由于 XOR 保留了位差异，因此邻接属性仍然有效。 
4. 将每个转换后的值附加到结果列表中。 

由于格雷码生成已经对每个数字恰好访问一次，因此变换后的序列也形成有效的排列。 
5. 返回最终序列。 

### 为什么它有效

 标准格雷码序列保证每个相邻对恰好相差一位，包括第一个和最后一个元素。 

与固定值进行异或可保留汉明距离。 如果两个数字在 XOR 之前相差一位，那么在异或之后它们仍然相差一位。 

因此，用 XOR 变换每个格雷码值可以保留循环邻接属性，同时确保第一个元素变为`start`。 

## Python 解决方案```python
from typing import List

class Solution:

    def circularPermutation(self, n: int, start: int) -> List[int]:
        total_numbers = 1 << n
        result = []

        for i in range(total_numbers):
            gray_code = i ^ (i >> 1)
            result.append(gray_code ^ start)

        return result
```该实现首先使用位移位计算序列中值的总数。 自从`2^n`等于`1 << n`，这既高效又惯用。 

循环遍历每个索引`0`到`2^n - 1`。 对于每个索引，标准格雷码公式都会生成一个与之前的格雷码相差一位的值。 

然后使用 XOR 对该序列进行转换`start`。 这确保第一个元素变成`start`因为：```python
0 ^ start == start
```转换后的值将附加到结果列表中并返回。 

该实现很紧凑，因为格雷码属性自动处理所有邻接要求。 

## 解决方案```go
func circularPermutation(n int, start int) []int {
    totalNumbers := 1 << n
    result := make([]int, 0, totalNumbers)

    for i := 0; i < totalNumbers; i++ {
        grayCode := i ^ (i >> 1)
        result = append(result, grayCode^start)
    }

    return result
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

结果切片用容量初始化`totalNumbers`以避免追加期间重复重新分配。 Go 整数足以满足给定的约束，因为最大值是`2^16 - 1`，很容易符合标准`int`。 

与 Python 不同，Go 需要显式切片分配，并且不透明地支持动态列表增长，因此预分配容量是一种有用的优化。

 ## 边缘情况

 一个重要的边缘情况是当`n = 1`。 在这种情况下，只存在两个数字：`0`和`1`。 该序列必须仍然是循环的，这意味着两个转换必须相差一位。 有缺陷的实现可能会错误地处理循环要求，但格雷码构造自然会产生`[0, 1]`，满足条件。 

另一个重要的边缘情况是当`start = 0`。 在这种情况下，异或变换不起作用，因此输出变为标准格雷码序列。 某些实现尝试手动旋转序列，这可能会导致索引错误。 基于 XOR 的方法完全避免了这种复杂性。 

第三个重要的边缘情况是`start`等于最大可能值，例如`2^n - 1`。 具有许多设置位的大二进制值可能会暴露位操作逻辑中的错误。 由于无论设置的位数有多少，XOR 在数学上都是一致的，因此实现可以正确处理这些情况，而无需任何特殊处理。 

最后，大值`n`， 尤其`n = 16`，是重要的性能边缘情况。 递归回溯解决方案可能会变慢或消耗过多的内存。 格雷码公式在恒定时间内生成每个值，因此即使在上约束边界，实现也可以有效地扩展。
