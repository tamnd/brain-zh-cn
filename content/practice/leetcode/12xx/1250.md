 ## 解决方案

 ## 问题理解

 此问题询问是否可以创建号码`1`使用数组中的整数，其中每个选定的数字可以乘以任何整数（包括负整数），然后将所有结果相加。 

更正式地说，给定一个数组`nums`，我们想知道是否存在整数：$$x_1, x_2, x_3, \dots, x_n$$这样：$$nums[0] \cdot x_1 + nums[1] \cdot x_2 + \dots + nums[n-1] \cdot x_n = 1$$系数可以是正数、负数或零。 我们还可以通过将元素乘以来忽略元素`0`。 

输入包括：

 - 正整数数组
 - 数组长度可达`10^5`- 每个值高达`10^9`输出应该是：

 -`True`如果我们可以构造`1`-`False`否则

 约束在这里极其重要。 由于数组最多可以包含十万个数字，因此任何指数或组合搜索都是不可能的。 即使是二次解也可能变得太慢。 我们需要接近线性时间的东西。 

关键的数学观察是，这个问题与数论中的贝祖恒等式直接相关。 

重要的边缘情况包括：

 - 具有单个元素的数组
 - 每个数字都有一个大于的公约数的数组`1`- 数组已经包含`1`- 非常大的数字
 - 长数组，其中答案仅取决于累积最大公约数

 例如：

 -`[1]`总是好的，因为`1 * 1 = 1`-`[2,4,6]`不好，因为每个组合都可以被整除`2`-`[6,10,15]`很好，因为它们的最大公约数是`1`## 方法

 ### 蛮力方法

 强力解决方案将尝试尝试每个选定元素的所有可能的子集和所有可能的整数系数。 

对于每个子集，我们可以尝试组合，例如：$$a_1x_1 + a_2x_2 + \dots + a_kx_k$$并检查任何组合是否等于`1`。 

这种方法在理论上是正确的，因为它探索了问题陈述所允许的每一个有效构造。 

然而，这是完全不可行的：

 - 有`2^n`子集
 - 每个系数可以是无穷多个整数
 - 搜索空间是无限的

 即使将系数限制在有限范围内，仍然会产生指数爆炸。 

这种方法不适用于`n = 10^5`。 

### 最佳方法

 关键的见解来自贝祖特的身份。 

对于任意整数：$$a_1, a_2, \dots, a_n$$可通过以下方式获得的所有值的集合：$$a_1x_1 + a_2x_2 + \dots + a_nx_n$$恰好是以下各项的倍数集：$$\gcd(a_1, a_2, \dots, a_n)$$因此：

 - 我们可以组建`1`当且仅当数组的整体最大公约数是`1`- 如果 gcd 大于`1`，每个可能的总和都可以被该 gcd 整除，因此形成`1`是不可能的

 所以整个问题归结为计算：$$\gcd(nums[0], nums[1], \dots, nums[n-1])$$并检查它是否等于`1`。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 尝试子集和系数组合 |
 | 最佳 | O(n log M) | O(n log M) | O(1) | O(1) | 计算整个数组的累积 gcd |

 这里，`M`是数组中的最大值。 

## 算法演练

 ### 第 1 步：初始化正在运行的 gcd

 从数组中的第一个数字开始作为当前的 gcd。 

随着我们处理更多的数字，这个值会逐渐缩小。 

### 第 2 步：迭代数组

 对于每个数字：

 1. 计算当前gcd与新数之间的gcd
 2.更新运行gcd

 数学上：$$current\_gcd = \gcd(current\_gcd, nums[i])$$这是有效的，因为 gcd 是关联的：$$\gcd(a,b,c) = \gcd(\gcd(a,b),c)$$### 步骤 3：提前停止优化

 如果在任何时候 gcd 变成`1`，我们可以立即返回`True`。 

一旦gcd达到`1`，增加更多的数字不能进一步减少它。 

### 第四步：返回结果

 处理完所有元素后：

 - 返回`True`如果 gcd 是`1`- 否则返回`False`### 为什么它有效

 Bézout 恒等式保证数组元素的所有整数线性组合都是数组 gcd 的倍数。 

如果 gcd 等于`1`，那么一定会产生一些整数组合`1`。 

如果 gcd 大于`1`，每个组合都可以被该 gcd 整除，因此产生`1`是不可能的。 

因此，检查数组 gcd 是否等于`1`既是必要的又是充分的。 

## Python 解决方案```python
from typing import List
from math import gcd

class Solution:
    def isGoodArray(self, nums: List[int]) -> bool:
        current_gcd = 0

        for num in nums:
            current_gcd = gcd(current_gcd, num)

            if current_gcd == 1:
                return True

        return False
```实施开始于`current_gcd = 0`。 这很方便，因为：$$\gcd(0, x) = x$$所以第一次迭代自然会初始化正在运行的 gcd。 

循环处理每个数字并不断更新累积的gcd。 这`math.gcd`函数内部使用欧几里德算法，效率极高。 

当 gcd 变为`1`。 由于 gcd 不能降低到以下`1`，进一步处理变得不必要。 

最后，如果循环结束但未到达`1`，函数返回`False`。 

## 解决方案```go
func gcd(a, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func isGoodArray(nums []int) bool {
	currentGCD := 0

	for _, num := range nums {
		currentGCD = gcd(currentGCD, num)

		if currentGCD == 1 {
			return true
		}
	}

	return false
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

由于Go标准库中没有提供内置的整数gcd函数，因此我们手动实现欧几里得算法。 

该解决方案使用正在运行的 gcd 变量，并在迭代切片时更新它。 

Go 整数可以安全地处理问题约束，因为值最多是`10^9`，非常适合标准`int`。 

## 工作示例

 ### 示例 1

 输入：```
nums = [12,5,7,23]
```加工步骤：

 | 步骤| 当前号码 | 运行 GCD |
 | ---| ---| ---|
 | 开始| - | 0 |
 | 1 | 12 | 12 gcd(0,12) = 12 | gcd(0,12) = 12 |
 | 2 | 5 | gcd(12,5) = 1 |

 gcd 变为`1`，所以我们立即返回`True`。 

这与示例表达式匹配：$$5 \times 3 + 7 \times (-2) = 1$$### 示例 2

 输入：```
nums = [29,6,10]
```加工步骤：

 | 步骤| 当前号码 | 运行 GCD |
 | ---| ---| ---|
 | 开始| - | 0 |
 | 1 | 29 | 29 29 | 29
 | 2 | 6 | gcd(29,6) = 1 |

 gcd 变为`1`，所以这个数组很好。 

有效的组合是：$$29 \times 1 + 6 \times (-3) + 10 \times (-1) = 1$$### 示例 3

 输入：```
nums = [3,6]
```加工步骤：

 | 步骤| 当前号码 | 运行 GCD |
 | ---| ---| ---|
 | 开始| - | 0 |
 | 1 | 3 | 3 |
 | 2 | 6 | gcd(3,6) = 3 |

 最终的gcd为`3`， 不是`1`。 

每个可能的组合都可以被整除`3`，因此产生`1`是不可能的。 

返回`False`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log M) | O(n log M) | 每次 gcd 计算都需要 O(log M) |
 | 空间| O(1) | O(1) | 仅使用了几个变量 |

 欧几里得算法可以非常有效地计算 gcd。 对于每个元素，gcd 计算需要相对于所涉及数字的大小的对数时间。 

由于我们处理所有`n`元素一次，总复杂度变为：$$O(n \log M)$$在哪里`M`是数组中最大的数字。 

该算法使用恒定的额外空间，因为它只存储运行的 gcd。

 ## 边缘情况

 ### 单元素数组

 单个数字数组很容易导致错误的假设。 例如：```
[1]
```很好，因为：$$1 \times 1 = 1$$然而：```
[7]
```不好，因为每个倍数`7`仍然可以整除`7`。 

该实现自然地处理了这个问题，因为运行的 gcd 本身就变成了单个值。 

### 具有公约数的数组

 数组如：```
[4, 8, 12]
```所有人都共享一个gcd`4`。 

有缺陷的实现可能会错误地假设组合许多数字最终可以创建`1`，但 Bézout 的恒等式证明每个组合仍然可以被整除`4`。 

gcd 检查保证了这里的正确性。 

### 大数字

 约束允许值高达`10^9`。 

尝试系数搜索的简单暴力方法在计算上将变得不可能。 

欧几里得算法可以有效地处理大值，因为 gcd 计算以对数时间运行。 

即使具有十万个大数字的阵列仍然可以通过这种方法进行管理。
