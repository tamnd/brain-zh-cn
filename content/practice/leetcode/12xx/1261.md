[LeetCode 问题 1261](https://leetcode.com/problems/find-elements-in-a-contaminate-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 哈希表、树、深度优先搜索、广度优先搜索、设计、二叉树

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二叉树，其中每个节点值都被污染并替换为`-1`。 然而，我们知道最初生成树中值的确切规则。 

原始树遵循以下规则：

 - 根节点总是有价值的`0`- 如果一个节点有价值`x`:

 - 它的左孩子有价值`2 * x + 1`- 它的右孩子有价值`2 * x + 2`我们被要求设计一个名为`FindElements`恢复树并有效地回答有关恢复的树中是否存在目标值的查询。 

构造函数接收受污染的根节点。 在初始化过程中，我们必须恢复原始值。 然后，`find(target)`方法应该返回`True`如果恢复的树包含`target`， 否则`False`。 

约束很重要，因为它们指导设计：

 - 树最多可以包含`10^4`节点
 - 最多还可以有`10^4`打电话给`find()`- 目标值可以大到`10^6`在最坏的情况下，对每个查询在树中进行天真的搜索将过于昂贵。 由于许多`find()`可能会发生调用，构建过程中对树进行一次预处理是关键的优化。 

一些边缘情况很重要：

 - 树可能只包含根节点
 - 树可能严重偏向一侧
 - 某些节点可能会丢失，这意味着并非所有数学上可能的值实际上都存在
 - 查询可能要求远大于树中任何值的值
 - 高度可以达到20，这意味着递归DFS在Python和Go中仍然是安全的

 ## 方法

 ### 蛮力方法

 一个简单的解决方案是在构建期间恢复树，然后每次执行一次树遍历`find(target)`被称为。 

构造函数将使用 DFS 或 BFS 恢复所有节点值。 然后，每个`find()`操作将遍历树搜索目标值。 

这种方法是正确的，因为恢复规则唯一确定每个节点值，并且遍历最终检查每个节点。 

然而，当进行大量查询时，这会变得低效。 如果树包含`n`节点，我们执行`q`查询，总复杂度变为`O(n * q)`在最坏的情况下。 当两个值都达到`10^4`，这可能会变得太慢。 

### 最佳方法

 关键的观察是，恢复树后，我们反复需要快速存在性检查。 

哈希集非常适合这种情况。 

在恢复树时，我们将每个恢复的值存储在一个集合中。 然后，每个`find(target)`操作变成恒定时间哈希查找。 

恢复遍历本身只需要访问每个节点一次，因此预处理成本`O(n)`。 之后，每个查询都是`O(1)`平均而言。 

这将重复的昂贵搜索转变为快速的会员资格检查。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次查找 O(n) | O(h) 递归堆栈 | 为每个查询遍历树|
 | 最佳 | O(n) 预处理 + O(1) 每次查找 | O(n) | 使用哈希集进行快速查找 |

 ## 算法演练

 1. 初始化一个空的哈希集来存储所有恢复的节点值。 
2. 将根值设置为`0`因为这个问题保证了原始根值始终是`0`。 
3. 从根开始DFS遍历。 
4. 对于每个访问过的节点：

 - 将其恢复的值插入到哈希集中
 - 如果该节点有左子节点：

 - 使用恢复左子值`2 * current + 1`- 继续对左孩子进行DFS
 - 如果该节点有右子节点：

 - 使用恢复右子值`2 * current + 2`- 继续对右孩子进行DFS
 5. 预处理完成后，该集合包含树中的每个有效值。 
6. 对于每个`find(target)`致电：

 - 返回是否`target`存在于哈希集中

 选择哈希集是因为它提供了平均值`O(1)`成员资格测试，非常适合重复查询。 

### 为什么它有效

 恢复规则从其父值中唯一确定每个节点值。 由于已知根是`0`，递归地应用左右公式重建精确的原始树值。 

DFS 恰好访问每个现有节点一次，因此每个有效的恢复值都会插入到集合中。 因此，该集合精确地表示了恢复的树的内容。 任何目标当且仅当它存在于集合中时才存在于树中。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class FindElements:

    def __init__(self, root: Optional[TreeNode]):
        self.values = set()
        self.root = root

        if self.root:
            self._recover(self.root, 0)

    def _recover(self, node: Optional[TreeNode], value: int) -> None:
        if not node:
            return

        node.val = value
        self.values.add(value)

        if node.left:
            self._recover(node.left, 2 * value + 1)

        if node.right:
            self._recover(node.right, 2 * value + 2)

    def find(self, target: int) -> bool:
        return target in self.values

# Your FindElements object will be instantiated and called as such:
# obj = FindElements(root)
# param_1 = obj.find(target)
```实现首先创建一个名为的哈希集`values`。 该集合存储每个恢复的节点值以进行快速查找。 

构造函数保存根引用并开始从值恢复`0`。 辅助方法`_recover()`执行DFS遍历，同时分配正确的值。 

里面`_recover()`，当前节点值被恢复并插入到集合中。 然后，算法使用问题的公式递归计算子值。 

这`find()`方法变得极其简单，因为所有预处理都已经完成。 它仅检查目标是否存在于集合中。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

type FindElements struct {
    values map[int]bool
}

func Constructor(root *TreeNode) FindElements {
    obj := FindElements{
        values: make(map[int]bool),
    }

    if root != nil {
        obj.recover(root, 0)
    }

    return obj
}

func (this *FindElements) recover(node *TreeNode, value int) {
    if node == nil {
        return
    }

    node.Val = value
    this.values[value] = true

    if node.Left != nil {
        this.recover(node.Left, 2*value+1)
    }

    if node.Right != nil {
        this.recover(node.Right, 2*value+2)
    }
}

func (this *FindElements) Find(target int) bool {
    return this.values[target]
}

/**
 * Your FindElements object will be instantiated and called as such:
 * obj := Constructor(root);
 * param_1 := obj.Find(target);
 */
```Go 的实现与 Python 版本非常相似。 

而不是Python的`set`, Go 使用`map[int]bool`模拟哈希集。 地图中的存在表明该值存在于恢复的树中。 

Go 需要显式的`nil`递归之前检查。 递归辅助方法附在`FindElements`结构。 

整数溢出不是问题，因为约束将值安全地保持在 Go 的标准整数范围内。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) 预处理，O(1) 每次查找 | DFS 访问每个节点一次，设置查找为常数时间 |
 | 空间| O(n) | 哈希集存储每个恢复的值 |

 构造函数对所有节点执行一次DFS遍历，因此恢复成本`O(n)`时间。 每个节点值都会被插入到哈希集中一次。 

每个`find()`调用使用哈希表成员资格测试，即`O(1)`平均而言。 

空间复杂度为`O(n)`因为每个恢复的值都存储在哈希集中。 递归堆栈还使用`O(h)`空间，哪里`h`是树的高度。

 ## 边缘情况

 ### 树只包含根

 最小的可能树只包含一个节点。 由于根必须恢复价值`0`，唯一有效的目标是`0`。 

有缺陷的实现可能会忘记正确初始化根或错误处理空子项。 该解决方案显式地开始从价值恢复`0`，因此根始终能够正确恢复。 

### 稀疏的树木和失踪的孩子

 该树可能包含一个间隙，其中一个子节点存在而另一个不存在。 这很重要，因为数学上可能的值不能保证存在。 

例如，节点可能有右子节点而没有左子节点。 该实现仅通过检查来恢复现有节点`if node.left`和`if node.right`，因此不存在的节点永远不会被错误地插入到集合中。 

### 非常大的目标查询

 查询可能要求比树中存在的任何值都大得多的值。 

基于简单遍历的解决方案仍然会扫描整个树以查找每个此类查询。 哈希集方法避免了这种低效率，因为成员资格测试立即返回`False`当该值不存在时。
