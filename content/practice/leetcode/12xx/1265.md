[LeetCode 问题 1265](https://leetcode.com/problems/print-immutable-linked-list-in-reverse/)

 **难度：** 🟡 中等
 **主题：** 链表、两个指针、堆栈、递归

 ## 解决方案

 ## 问题理解

 这个问题为我们提供了一种特殊类型的链表，称为不可变链表。 与普通的链表问题不同，我们不允许直接访问节点字段。 相反，我们只能通过两个提供的 API 与列表进行交互：

 -`printValue()`，打印当前节点的值
 -`getNext()`，返回下一个节点

 任务是以相反的顺序打印所有节点值。 

例如，如果链表是：```
1 -> 2 -> 3 -> 4
```所需的输出是：```
4 3 2 1
```重要的限制是链表是不可变的。 我们不能：

 - 修改指针
 - 反转列表
 - 将值存储回节点
 - 直接访问内部节点结构

 我们只能使用向前遍历`getNext()`。 

限制比较小，最多1000个节点。 这意味着即使递归解决方案在大多数语言中也是安全的，因为递归深度仍然是可管理的。 然而，后续要求更高级的复杂性优化，包括：

 - 持续的额外空间
 - 具有亚线性额外内存的线性运行时间

 这些后续行动表明面试官希望了解多种技术，而不仅仅是最简单的堆栈解决方案。 

一些边缘情况很重要：

 - 单个节点列表
 - 负值
 - 重复值
 - 接近递归限制的长列表
 - 确保我们永远不会尝试直接访问字段

 该问题保证列表长度至少为1，因此头始终有效。 

## 方法

 ### 蛮力方法

 最直接的做法是从头到尾遍历链表，并将每个节点存储到数组或堆栈等辅助数据结构中。 

由于我们只能向前遍历不可变列表，因此在遍历过程中我们自然无法逆序打印。 通过首先存储节点，我们可以稍后向后迭代存储的集合并调用`printValue()`在每个节点上。 

这种方法很简单：

 1. 遍历一次列表
 2. 将每个节点压入堆栈
 3. 逐一弹出节点并打印

 这是有效的，因为堆栈由于其后进先出行为而自然地颠倒顺序。 

主要缺点是额外的内存使用。 我们储存所有`n`节点，因此空间复杂度变为线性。 

### 最佳方法

 更优雅的解决方案使用递归。 

递归遍历时，每次递归调用都会深入列表，直到到达末尾。 然后，当递归调用返回时，节点会自动以相反的顺序进行处理。 

例如：```
dfs(1)
  dfs(2)
    dfs(3)
      dfs(4)
```一次节点`4`到达基本情况，递归展开：```
print 4
print 3
print 2
print 1
```这自然会产生相反的顺序，而无需在堆栈中显式存储节点。 

递归调用堆栈本身就像一个堆栈数据结构。 

虽然仍然使用递归`O(n)`由于调用堆栈的空间，实现简洁干净。 考虑到最多 1000 个节点的小约束，该解决方案是实用的并且被普遍接受为标准解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力堆栈 | O(n) | O(n) | 将所有节点存储在堆栈中，然后向后打印 |
 | 递归DFS | O(n) | O(n) | 使用递归栈自然地反转遍历顺序 |

 ## 算法演练

 ### 递归反向打印算法

 1. 从头节点开始，定义一个递归辅助函数。 

辅助函数将当前节点作为输入。 其目的是在打印当前节点之前先处理所有后面的节点。 
2. 检查当前节点是否存在。 

如果节点是`None`，立即返回。 这成为递归基本情况。 
3、先递归访问下一个节点。 

调用辅助函数`node.getNext()`在打印当前节点之前。 

这是关键思想。 通过将打印延迟到更深层次的递归调用完成之后，节点将以相反的顺序打印。 
4. 在递归展开期间打印当前节点值。 

一旦所有后面的节点都已被处理，调用`node.printValue()`。 
5. 继续递归展开。 

在打印完所有后续节点后，每个返回的递归帧都会打印其节点。 

### 为什么它有效

 递归保证较深的节点在较早的节点之前得到完全处理。 由于每个节点在打印之前都会等待其后继节点完成，因此输出顺序完全相反。 

从概念上讲，递归创建一个隐式堆栈：```
1 -> 2 -> 3 -> 4
```变成：```
push 1
push 2
push 3
push 4
```然后递归展开：```
pop 4
pop 3
pop 2
pop 1
```它正确地产生相反的顺序。 

## Python 解决方案```python
# """
# This is the ImmutableListNode's API interface.
# You should not implement it, or speculate about its implementation.
# """
# class ImmutableListNode:
#     def printValue(self) -> None:
#         # print the value of this node.
#
#     def getNext(self) -> 'ImmutableListNode':
#         # return the next node.

class Solution:
    def printLinkedListInReverse(self, head: 'ImmutableListNode') -> None:
        
        def dfs(node: 'ImmutableListNode') -> None:
            if not node:
                return
            
            dfs(node.getNext())
            node.printValue()
        
        dfs(head)
```实现直接遵循递归策略。 

内部辅助函数`dfs`执行链表的深度优先遍历。 它不是立即打印，而是首先递归访问下一个节点。 

只有处理完所有后面的节点后，当前节点才会打印其值。 这种处理顺序的反转会产生所需的反向输出。 

基本情况安全地处理列表的末尾。 什么时候`getNext()`最终返回`None`，递归停止。 

外部函数只是从头节点开始递归。 

## 解决方案```go
/*   Below is the interface for ImmutableListNode, which is already defined for you.
 *
 *   type ImmutableListNode struct {
 *
 *   }
 *
 *   func (this *ImmutableListNode) getNext() ImmutableListNode {
 *      // return the next node.
 *   }
 *
 *   func (this *ImmutableListNode) printValue() {
 *      // print the value of this node.
 *   }
 */

func printLinkedListInReverse(head ImmutableListNode) {

    var dfs func(ImmutableListNode)

    dfs = func(node ImmutableListNode) {
        next := node.getNext()

        if next != nil {
            dfs(next)
        }

        node.printValue()
    }

    dfs(head)
}
```Go 实现遵循与 Python 解决方案相同的递归结构。 

一个重要的区别是如何`nil`处理工程。 在提供的Go接口中，当前节点本身是保证有效的，因此我们递归地检查是否`getNext()`回报`nil`在进行另一个递归调用之前。 

Go 还使用函数变量进行递归闭包，这就是为什么`dfs`在赋值之前声明。

 ## 边缘情况

 ### 单节点列表

 仅包含一个节点的链表是最小的有效输入。 有缺陷的实现可能会错误地递归经过节点或无法打印任何内容。 在此解决方案中，递归在单个节点之后立即到达基本情况，然后在展开期间正确打印该节点。 

### 重复值

 一些实现在调试或存储节点时意外地依赖值的唯一性。 此问题不保证唯一值。 递归解决方案处理节点本身而不是值，因此可以正确且独立地打印重复项。 

### 最大长度列表

 该列表最多可以包含 1000 个节点。 具有非常深的递归的递归解决方案有时会导致堆栈溢出问题。 然而，约束足够小，标准递归深度在实践中对于这个问题仍然是安全的。 该实现仅对每个节点处理一次并有效地处理长链。 

### 负数

 节点值可能为负。 由于该算法从不对节点值进行算术运算，而只是直接打印它们，因此负值不需要特殊处理，自然受到支持。
