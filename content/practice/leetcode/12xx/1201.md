[LeetCode 第 1201 题](https://leetcode.com/problems/ugly-number-iii/)

 **难度：** 🟡 中等
 **主题：** 数学、二分查找、组合学、数论

 ## 解决方案

 ## 问题理解

 该问题将“丑数”定义为可被三个给定整数中的至少一个整除的任何正整数`a`,`b`， 或者`c`。 

我们有四个整数：

 -`n`，代表我们想要找到哪个丑数
 -`a`,`b`， 和`c`，代表整除条件

 任务是返回`nth`能被整除的正整数`a`,`b`， 或者`c`。 

例如，如果`a = 2`,`b = 3`， 和`c = 5`，那么丑陋的数字是：`2, 3, 4, 5, 6, 8, 9, 10, ...`第三个丑数是`4`。 

重要的细节是数字只需被其中一个值整除。 如果一个数字可以被多个值整除，它仍然只计算一次。 例如，`6`可以被两者整除`2`和`3`，但它被算作一个丑陋的数字。 

约束条件极其重要：

 -`n`,`a`,`b`， 和`c`每个都可以大到`10^9`-`a * b * c`可以大到`10^18`这些限制立即告诉我们，一一生成丑陋的数字是不可行的。 在最坏的情况下，即使迭代所有整数直到得到答案也会太慢。 

该问题还保证最终答案符合范围`[1, 2 * 10^9]`。 这为我们提供了二分搜索的安全上限。 

一些边缘情况在这里很重要：

 - 一些除数可能会严重重叠，例如`a = 2`,`b = 4`,`c = 8`- 两个或所有三个除数可能相等
 - 计算最小公倍数时，较大的值可能会导致溢出
 - 能被多个除数整除的数字不得重复计算

 主要挑战是有效地计算有多少个丑数小于或等于某个值`x`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是迭代从以下位置开始的正整数`1`并计算有多少个数字可以被整除`a`,`b`， 或者`c`。 

对于每个整数：

 - 检查它是否能被整除`a`- 或除以`b`- 或除以`c`如果任何条件为真，则增加丑数计数。 

一旦计数达到`n`，返回当前数字。 

这种方法是正确的，因为它直接模拟了丑数的定义。 然而，对于给定的限制来说，它太慢了。 如果答案很接近`2 * 10^9`，迭代数十亿个整数是不可行的。 

### 最佳方法

 关键的观察是我们不需要明确地生成丑陋的数字。 

相反，我们可以回答这个问题：

 > “有多少个丑数小于或等于`x`？”

 如果我们可以有效地计算它，那么我们就可以二分查找最小的`x`使得至少有`n`丑数小于或等于`x`。 

计算丑数最多`x`，我们使用包含排除原则。 

可除以的数字计数：

 -`a`是`x // a`-`b`是`x // b`-`c`是`x // c`但能被两者整除的数`a`和`b`计算了两次，所以我们减去：

 -`x // lcm(a, b)`-`x // lcm(a, c)`-`x // lcm(b, c)`然后，可被全部三个整除的数字被减去了太多次，所以我们加回来：

 -`x // lcm(a, b, c)`公式变为：$count(x)=\left\lfloor\frac{x}{a}\right\rfloor+\left\lfloor\frac{x}{b}\right\rfloor+\left\lfloor\frac{x}{c}\right\rfloor-\left\lfloor\frac{x}{\mathrm{lcm}(a,b)}\right\rfloor-\left\lfloor\frac{x}{\mathrm{lcm}(a,c)}\right\rfloor-\left\lfloor\frac{x}{\mathrm{lcm}(b,c)}\right\rfloor+\left\lfloor\frac{x}{\mathrm{lcm}(a,b,c)}\right\rfloor$该计数函数是单调的。 作为`x`增加，丑数的数量小于或等于`x`永远不会减少。 这使得二分搜索适用。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O（答案）| O(1) | O(1) | 迭代每个整数，直到第 n 个难看的数字 |
 | 最佳 | O(log(2 × 10^9)) | O(log(2 × 10^9)) | O(1) | O(1) | 使用包含排除计数的二分搜索 |

 ## 算法演练

 1. 计算包含-排除所需的最小公倍数。 

我们需要：

 -`lcm(a, b)`-`lcm(a, c)`-`lcm(b, c)`-`lcm(a, b, c)`这些值帮助我们正确计算重叠。 
2. 定义计数函数。 

对于给定的数字`x`，计算有多少个整数`1`到`x`至少可以被以下之一整除`a`,`b`， 或者`c`。 

包含-排除原则确保数字只计算一次。 
3. 初始化二分查找边界。 

最小可能的答案是`1`。 

最大可能的答案保证最多是`2 * 10^9`，所以我们用它作为上限。 
4. 执行二分查找。 

在每次迭代时：

 - 计算`mid`- 数一数有多少个丑数`<= mid`如果计数至少为`n`，那么答案可能是`mid`或更小，因此将右边界向左移动。 

否则，丑数还不够，所以将左边界向右移动。 
5. 继续直到搜索收敛。 

二分查找停止时`left == right`。 

该值是至少包含的最小整数`n`丑陋的数字，这意味着它正是`nth`丑陋的数字。 

### 为什么它有效

 计数函数是单调的。 如果`x1 < x2`，那么丑数的数量最多为`x1`不能超过最多的数量`x2`。 

二分搜索适用于单调函数，因为我们可以在每一步消除一半的搜索空间。 

即使发生可整除性重叠，包含-排除原则也能保证每个有效数字都被精确计数一次。 

因此，算法正确地识别出计数达到的最小数`n`，这正是`nth`丑陋的数字。 

## Python 解决方案```python
import math

class Solution:
    def nthUglyNumber(self, n: int, a: int, b: int, c: int) -> int:
        
        def lcm(x: int, y: int) -> int:
            return x * y // math.gcd(x, y)
        
        ab = lcm(a, b)
        ac = lcm(a, c)
        bc = lcm(b, c)
        abc = lcm(ab, c)
        
        def count_ugly(x: int) -> int:
            return (
                x // a +
                x // b +
                x // c -
                x // ab -
                x // ac -
                x // bc +
                x // abc
            )
        
        left = 1
        right = 2 * 10**9
        
        while left < right:
            mid = (left + right) // 2
            
            if count_ugly(mid) >= n:
                right = mid
            else:
                left = mid + 1
        
        return left
```实现首先定义一个`lcm`使用 GCD 和 LCM 之间关系的辅助函数：$\mathrm{lcm}(x,y)=\frac{x\cdot y}{\gcd(x,y)}$然后我们预先计算所有成对和三重最小公倍数。 这些在二分查找过程中会重复使用，因此预计算可以避免冗余计算。 

这`count_ugly`函数应用包含-排除原理来确定最多存在多少个有效数字`x`。 

然后二分查找缩小答案范围。 如果当前中点已经至少包含`n`数字丑陋，解可能更小，因此搜索向左移动。 否则，它向右移动。 

当循环结束时，`left`是满足条件的最小值，即`nth`丑陋的数字。 

## 解决方案```go
package main

func nthUglyNumber(n int, a int, b int, c int) int {

	gcd := func(x, y int64) int64 {
		for y != 0 {
			x, y = y, x%y
		}
		return x
	}

	lcm := func(x, y int64) int64 {
		return x / gcd(x, y) * y
	}

	A := int64(a)
	B := int64(b)
	C := int64(c)

	ab := lcm(A, B)
	ac := lcm(A, C)
	bc := lcm(B, C)
	abc := lcm(ab, C)

	countUgly := func(x int64) int64 {
		return (
			x/A +
				x/B +
				x/C -
				x/ab -
				x/ac -
				x/bc +
				x/abc
		)
	}

	left := int64(1)
	right := int64(2 * 1000000000)

	for left < right {
		mid := left + (right-left)/2

		if countUgly(mid) >= int64(n) {
			right = mid
		} else {
			left = mid + 1
		}
	}

	return int(left)
}
```Go 实现与 Python 版本非常相似，但有一些重要的特定于语言的细节。 

Go 整数比 Python 整数更容易溢出，因为 Python 自动支持任意精度整数。 由于中间 LCM 计算可能超出 32 位整数限制，因此实现使用`int64`贯穿整个计算逻辑。 

二分查找中点的计算方法为：```go
mid := left + (right-left)/2
```这种形式避免了可能发生的潜在溢出`(left + right) / 2`。 

匿名辅助函数用于`gcd`,`lcm`， 和`countUgly`，这使实现保持紧凑且独立。

 ## 边缘情况

 当所有除数都相同时，就会出现一种重要的边缘情况。 例如，`a = b = c = 3`。 一个幼稚的实现可能会计算多个`3`三次并产生不正确的结果。 包含-排除原则正确地处理了这个问题，因为重叠的计数被适当地减去。 序列简单地变成`3, 6, 9, 12, ...`。 

当一个除数是另一个除数的倍数时，会出现另一种棘手的情况，例如`a = 2`,`b = 4`,`c = 8`。 的每一个倍数`4`和`8`已经是的倍数`2`。 如果不仔细进行重叠校正，重复项的数量就会急剧增加。 最小公倍数计算可确保正确删除这些重复计数。 

大的输入值也很关键。 自从`a`,`b`， 和`c`可能会接近`10^9`，LCM 计算期间的中间乘法可能会溢出某些语言中的标准整数类型。 Go 实现使用`int64`特别是为了防止溢出。 Python 自动避免了这个问题，因为整数具有任意精度。 

当一个除数等于时，就会出现最后的边缘情况`1`。 在这种情况下，每个正整数都是丑陋的，因为所有数字都可以被整除`1`。 该算法仍然可以自然地工作，因为计数函数变为`count(x) = x`，二分查找正确返回`n`。
