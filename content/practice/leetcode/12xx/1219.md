[LeetCode 第 1219 题](https://leetcode.com/problems/path-with-maximum-gold/)

 **难度：** 🟡 中等
 **主题：** 数组、回溯、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个代表金矿的二维网格。 每个细胞含有正量的金或`0`，这意味着单元格为空。 我们可以从任何含有黄金的单元格开始，并沿网格移动并收集黄金。 

移动仅限于四个基本方向：上、下、左、右。 我们不可以斜向移动。 一旦我们访问了一个单元格，我们就无法在同一路径上再次访问它。 我们也被禁止进入含有以下内容的牢房：`0`。 

目标是确定可以从任何有效路径收集的最大黄金量。 

一个关键细节是我们可以在任何地方开始和停止，只要起始单元包含金。 这意味着我们必须将每个黄金单元视为潜在的起点。 

这些约束强烈影响预期的解决策略：

 - 网格尺寸可以大到`15 x 15`- 不过最多有`25`含有金的细胞

 第二个约束是最重要的观察结果。 尽管网格本身最多可以包含`225`细胞，实际上只有一小部分是可穿越的。 这使得通过修剪进行详尽的探索变得可行。 

一些重要的边缘情况包括：

 - 只有一个金格的网格
 - 所有单元格所在的网格`0`- 多个互不相连的黄金区域
 - 贪婪地获取最大相邻黄金值不会导致最佳总和的路径
 - 由金细胞形成的循环，需要仔细访问跟踪以避免重新访问细胞

 该问题保证移动仅在有效的网格单元之间进行，并且黄金值是非负整数。 

## 方法

 ### 蛮力方法

 强力解决方案将从每个金单元开始尝试所有可能的路径。 在每一步中，算法都会递归地尝试在所有四个方向上移动，同时跟踪访问过的单元格。 

这种方法是正确的，因为它探索每条有效路径并计算为每条路径收集的黄金。 因此，所有探索路径中的最大值必定是最佳答案。 

然而，可能的路径数量呈指数增长。 如果有`k`在黄金单元中，每个递归调用最多可以分支到四个方向。 在最坏的情况下，这会产生大约`O(4^k)`递归状态。 

虽然最多的约束`25`黄金细胞可以防止这种情况变得完全不可行，没有修剪或回溯优化的朴素递归仍然会执行不必​​要的重复工作。 

### 最优方法，回溯深度优先搜索

 关键的观察结果是含金细胞的数量很少。 由于每条路径不能重新访问单元格，因此每条路径都对应于对黄金单元格的唯一遍历。 

这自然表明了回溯深度优先搜索方法。 

对于每个金细胞：

 1. 开始一次DFS遍历
 2. 将当前单元格标记为已访问
 3. 探索所有有效的相邻黄金单元格
 4. 计算每次延续可获得的最大金币
 5. 通过取消标记单元格来回溯

 回溯在这里是理想的，因为在递归探索期间访问的状态会动态变化。 探索一个分支后，我们必须恢复网格状态，以便其他路径可以重用相同的单元格。 

该算法有效地枚举所有有效路径，同时通过递归探索确保正确性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(4^k) | O(4^k) | O(k) | 探索每条可能的路径而不进行优化 |
 | 最佳 | O(4^k) | O(4^k) | O(k) | 通过高效的访问处理回溯 DFS |

 这里，`k`代表含金细胞的数量，其中`k <= 25`。 

## 算法演练

 1. 将网格尺寸存储在变量中`rows`和`cols`。 
2. 定义四种可能的移动方向：

 - 向上
 - 向下
 - 左
 - 右
 3. 创建接受当前行和列的递归 DFS 函数。 
4. DFS函数内部：

 - 存储当前单元格的黄金值
 - 通过将其值设置为来临时将单元格标记为已访问`0`- 初始化一个变量来跟踪相邻路径中最好的黄金收藏品
 5. 探索所有四个相邻单元格：

 - 计算邻居坐标
 - 检查边界条件
 - 确保邻近的细胞含有金
 - 递归计算该邻居的最大黄金
 6.探索完各个方向后：

 - 恢复当前单元格中的原始金币值
 - 返回当前单元格的黄金加上最好的相邻结果
 7、在主函数中：

 - 遍历网格中的每个单元格
 - 如果单元格包含黄金，则从该单元格启动 DFS
 - 跟踪所有起始位置的最大结果
 8.返回全球收集到的最大金币。 

### 为什么它有效

 DFS 完全按照问题约束的定义探索每条有效路径。 由于单元在递归期间被标记为已访问，因此没有路径可以重新访问同一单元。 回溯会在每个递归分支后恢复网格状态，确保独立探索所有可能性。 因为每个起始位置和每个有效延续都会被检查，所以该算法保证找到最大可能的黄金收集。 

## Python 解决方案```python
from typing import List

class Solution:
    def getMaximumGold(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1)
        ]

        def dfs(row: int, col: int) -> int:
            current_gold = grid[row][col]

            # Mark as visited
            grid[row][col] = 0

            best_next = 0

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    0 <= new_row < rows
                    and 0 <= new_col < cols
                    and grid[new_row][new_col] > 0
                ):
                    best_next = max(
                        best_next,
                        dfs(new_row, new_col)
                    )

            # Backtrack
            grid[row][col] = current_gold

            return current_gold + best_next

        maximum_gold = 0

        for row in range(rows):
            for col in range(cols):
                if grid[row][col] > 0:
                    maximum_gold = max(
                        maximum_gold,
                        dfs(row, col)
                    )

        return maximum_gold
```该实现首先存储网格尺寸并定义四个移动方向。 这些方向简化了 DFS 期间的邻居遍历。 

递归`dfs`函数执行核心回溯逻辑。 在暂时将单元格设置为`0`。 这充当就地访问标记并避免需要额外的访问矩阵。 

然后，该函数会探索每个有效的相邻黄金单元。 对于每个邻居，它递归地计算从该点开始可收集的最大黄金。 

所有邻居处理完后，恢复原来的金币值。 此回溯步骤至关重要，因为其他 DFS 路径稍后可能会重用此单元。 

最后，主循环从每个含金单元开始 DFS，并跟踪总体最大结果。 

## 解决方案```go
func getMaximumGold(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	var dfs func(int, int) int

	dfs = func(row int, col int) int {
		currentGold := grid[row][col]

		// Mark as visited
		grid[row][col] = 0

		bestNext := 0

		for _, dir := range directions {
			newRow := row + dir[0]
			newCol := col + dir[1]

			if newRow >= 0 &&
				newRow < rows &&
				newCol >= 0 &&
				newCol < cols &&
				grid[newRow][newCol] > 0 {

				candidate := dfs(newRow, newCol)

				if candidate > bestNext {
					bestNext = candidate
				}
			}
		}

		// Backtrack
		grid[row][col] = currentGold

		return currentGold + bestNext
	}

	maximumGold := 0

	for row := 0; row < rows; row++ {
		for col := 0; col < cols; col++ {
			if grid[row][col] > 0 {
				candidate := dfs(row, col)

				if candidate > maximumGold {
					maximumGold = candidate
				}
			}
		}
	}

	return maximumGold
}
```Go 的实现与 Python 版本非常相似。 一个显着的区别是使用函数变量进行递归，因为 Go 中的匿名递归函数必须在赋值之前首先声明。 

Go 切片用于存储移动方向。 整数溢出不是问题，因为最大可能的金币被限制为`25 * 100 = 2500`，它很容易符合 Go 的整数范围。 

回溯逻辑相同，只是将当前单元格暂时设置为`0`后来又恢复了。

from typing import List

class Solution:
    def getMaximumGold(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        def dfs(row: int, col: int) -> int:
            current = grid[row][col]
            grid[row][col] = 0

            best = 0

            for dr, dc in directions:
                nr = row + dr
                nc = col + dc

                if (
                    0 <= nr < rows
                    and 0 <= nc < cols
                    and grid[nr][nc] > 0
                ):
                    best = max(best, dfs(nr, nc))

            grid[row][col] = current

            return current + best

        answer = 0

        for r in range(rows):
            for c in range(cols):
                if grid[r][c] > 0:
                    answer = max(answer, dfs(r, c))

        return answer

solver = Solution()

 ## 边缘情况

 当网格仅包含`0`价值观。 在这种情况下，没有有效的起始位置。 幼稚的实现可能会错误地从每个单元尝试 DFS，或者因为没有发生遍历而失败。 该实现自然地处理了这个问题，因为 DFS 仅从黄金大于零的单元开始。 因此最终答案仍然是`0`。 

另一个重要的例子是带有单个金单元的网格。 由于没有可供探索的相邻单元格，DFS 应立即返回该单元格的值。 递归结构正确地处理了这个问题，因为邻居探索循环没有找到有效的动作，只是返回当前的黄金数量。 

更微妙的边缘情况涉及由连接的金电池形成的循环。 如果没有适当的访问跟踪，DFS 可能会无限地重新访问同一个单元格或多次计算其黄金数。 该实现通过临时将访问的单元设置为来防止这种情况发生`0`。 由于有效的举动需要正的黄金价值，因此在当前路径中重新访问变得不可能。 

当局部最大的邻近黄金值不能产生全局最优解时，会出现另一个棘手的情况。 A greedy algorithm would fail in such cases. 由于此实现通过回溯 DFS 探索所有有效路径，因此无论本地选择如何，它都可以正确识别真实的最大总数。
