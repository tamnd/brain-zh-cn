 # LeetCode 1266 - 访问所有点的最短时间

 ## 问题理解

 该问题给出了二维坐标平面上的一系列点。 每个点都表示为`[x, y]`， 在哪里`x`和`y`是整数坐标。 您的任务是确定按照输入数组中出现的确切顺序访问每个点所需的最短秒数。 

移动规则在这里极其重要。 一秒钟内，您可以：

 - 水平移动一个单位
 - 垂直移动一个单位
 - 对角移动一个单位

 对角线移动会改变`x`和`y`同时由一个单位坐标。 例如，从`(1,1)`到`(2,2)`正好需要一秒钟，因为它是对角线移动。 

关键细节是必须按顺序访问点。 您无法重新排列点来优化路线。 但是，您可以在稍后正式访问未来点之前通过它们。 

输入尺寸很小，最多有`100`点，坐标范围为`-1000`到`1000`。 这些约束告诉我们，性能不是主要问题，但问题仍然期望我们找到直接给出最小行程时间的数学捷径。 

幼稚的实现可能会错误地假设应该使用欧几里得距离或曼哈顿距离来计算距离。 对于这个运动系统来说，这两种情况都不正确。 对角线移动显着改变了成本结构。 

一些边缘情况很重要：

 - 单点要求零移动，所以答案是`0`。 
- 积分可能已经共享相同的`x`坐标或相同`y`坐标，意味着只需要垂直或水平移动。 
- 坐标可能为负。 
- 连续的点甚至可以是相同的，该段需要零时间。 

该问题保证了有效的输入结构，因此我们不需要处理格式错误的数组。 

## 方法

 ### 蛮力方法

 蛮力的想法是在每对连续点之间一次模拟一秒钟的运动。 

假设我们要从`(x1, y1)`到`(x2, y2)`。 每当两个坐标仍然不同时，我们都会尝试对角线移动。 一旦一个坐标与目标匹配，我们就继续水平或垂直移动，直到到达目的地。 

例如：

 - 来自`(1,1)`到`(4,3)`- 对角线移动到`(2,2)`- 对角线移动到`(3,3)`- 水平移动至`(4,3)`此模拟是正确的，因为对角线移动同时减少了两个坐标差异，使它们尽可能成为最有效的移动。 

然而，显式模拟每个步骤是不必要的。 尽管约束很小，但模拟方法会执行额外的工作并掩盖问题背后的数学见解。 

### 最佳方法

 关键的观察是对角线移动使我们能够减少`x`和`y`同时存在差异。 

就两点来说：

 - 水平距离=`abs(x2 - x1)`- 垂直距离=`abs(y2 - y1)`我们可以执行对角线移动，直到一个坐标对齐。 可能的对角线移动次数是两个差值中较小的一个。 

之后，只剩下直线移动。 

这意味着总的最短时间很简单：$$\max(|x2 - x1|, |y2 - y1|)$$较大的差异决定了总时间，因为对角线移动同时减少了两个坐标。 

例如：

 - 来自`(1,1)`到`(4,3)`-`dx = 3`-`dy = 2`- 两次对角线移动都会减少两者
 - 仍保留一水平移动
 - 总时间=`max(3,2) = 3`所以算法就变成了：

 1. 迭代连续的点对。 
2. 计算`dx`和`dy`。 
3.添加`max(dx, dy)`到答案。 

这样可以有效、直接地产生最短的旅行时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(总移动距离) | O(1) | O(1) | 一步一步模拟每一个动作 |
 | 最佳 | O(n) | O(1) | O(1) | 使用最大坐标差公式 |

 ## 算法演练

 1. 初始化一个名为`total_time`到`0`。 

该变量将累积每对连续点之间的最短行程时间。 
2. 从索引开始迭代点数组`1`。 

每次迭代都会考虑从前一个点到当前点的移动。 
3. 计算水平差。 

计算：$$dx = |x2 - x1|$$这表示如果不存在对角线移动，则需要多少次水平移动。 
4. 计算垂直差。 

计算：$$dy = |y2 - y1|$$这代表独立需要多少次垂直移动。 
5. 确定该段的最短时间。 

由于一次对角线移动会同时减少两个坐标，因此最佳策略是使用尽可能多的对角线移动。 

因此，所需时间为：$\max(|x_2-x_1|,|y_2-y_1|)$6.将此值添加到`total_time`。 

每个部分都独立地对最终答案做出贡献。 
7. 处理完所有连续对后，返回`total_time`。 

### 为什么它有效

 对角线移动同时将水平和垂直距离减少一倍。 因此，最佳策略始终是在两个坐标仍然不同时执行对角线移动。 

一旦一个坐标对齐，就只剩下直线移动。 因此，移动总数等于较大的坐标差，因为较小的差可以完全被对角线移动吸收。 

将所有连续点对的该值相加即可得出全局最短时间。 

## Python 解决方案```python
from typing import List

class Solution:
    def minTimeToVisitAllPoints(self, points: List[List[int]]) -> int:
        total_time = 0

        for i in range(1, len(points)):
            x1, y1 = points[i - 1]
            x2, y2 = points[i]

            dx = abs(x2 - x1)
            dy = abs(y2 - y1)

            total_time += max(dx, dy)

        return total_time
```实现从初始化开始`total_time`，它存储累积答案。 

循环从索引开始`1`因为每次迭代都会将当前点与前一个点进行比较。 为了便于阅读，我们将这两个点解压缩为坐标变量。 

接下来，我们使用以下方法计算绝对水平和垂直差异`abs()`。 这两点之间的最短行进时间是两个差值中较大的一个，因为对角线移动可以同时减小两个维度。 

该值被添加到`total_time`，处理完所有对后，返回最终答案。 

该解决方案直接反映了前面描述的数学见解。 

## 解决方案```go
func minTimeToVisitAllPoints(points [][]int) int {
    totalTime := 0

    for i := 1; i < len(points); i++ {
        x1, y1 := points[i-1][0], points[i-1][1]
        x2, y2 := points[i][0], points[i][1]

        dx := abs(x2 - x1)
        dy := abs(y2 - y1)

        if dx > dy {
            totalTime += dx
        } else {
            totalTime += dy
        }
    }

    return totalTime
}

func abs(x int) int {
    if x < 0 {
        return -x
    }
    return x
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置整数`abs`对于这个确切的用例，我们在标准库中定义了一个辅助函数。 

而不是使用`max()`，该解决方案使用简单的条件比较`dx`和`dy`。 

切片自然地用于输入结构，并且整数溢出不是问题，因为最大可能的答案相对于 Go 的整数限制非常小。

 ## 边缘情况

 一种重要的边缘情况是输入仅包含单个点。 由于无处可移动，因此所需的最短时间为`0`。 有缺陷的实现可能会错误地尝试访问不存在的前一点或假设至少存在一个移动段。 此实现自然地处理这种情况，因为循环从索引处开始`1`，因此不会发生迭代。 

另一个重要的情况是两个连续点相同时。 例如，从`(2,2)`到`(2,2)`需要零秒。 某些实现可能会错误地添加一个移动步骤或错误处理零差异。 在这里，两者`dx`和`dy`变得`0`， 所以`max(dx, dy)`也是`0`。 

当运动完全水平或完全垂直时，会出现第三种重要的边缘情况。 例如，从`(0,0)`到`(0,5)`不允许对角线移动，因为`x`坐标已经对齐。 该公式仍然可以正确运行，因为最大差值等于所需的直线移动次数。 

负坐标是错误的另一个潜在来源。 由于解决方案始终使用绝对差，因此坐标符号并不重要。 搬家自`(-3,-2)`到`(1,4)`其处理方式与正坐标之间的移动完全相同。
