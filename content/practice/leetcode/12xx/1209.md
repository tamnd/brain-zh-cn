[LeetCode 问题 1209](https://leetcode.com/problems/remove-all-adjacent-duplicates-in-string-ii/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们反复删除恰好的组`k`字符串中相邻的相同字符，直到不再存在这样的组。 

删除操作的工作原理如下：

 - 查找`k`全部相同的连续字符。 
- 从字符串中删除这些字符。 
- 将剩余的左右部分连接在一起。 
- 继续再次检查，因为移除后可能会形成新的相邻组。 

重要的细节是，搬迁可以为未来的搬迁创造新的机会。 因此，我们不能简单地扫描一次字符串并独立删除组。 

例如，在：```
"deeedbbcccbdaa", k = 3
```去除`"eee"`创建：```
"ddbbcccbdaa"
```然后删除`"ccc"`创建：```
"ddbbbdaa"
```现在`"bbb"`变得可移动，之后`"ddd"`也变得可移动。 

输入包括：

 - 一根绳子`s`包含小写英文字母
 - 一个整数`k`表示需要删除多少个相邻的相等字符

 输出是执行所有可能的删除后的最终字符串。 

约束条件很重要：

 -`s.length`可以大到`100000`-`k`可以大到`10000`这些限制立即排除了低效的重复重新扫描方法。 对于最大的输入，具有二次复杂度的解决方案可能会超时。 

该问题还保证了最终答案是唯一的。 这意味着概念上执行删除的顺序不会影响最终结果。 

需要考虑一些重要的边缘情况：

 - 没有可移动组的字符串
 - 删除触发级联删除的字符串
 - 整个字符串消失的字符串
 - 同一角色的长时间运行
 -`k = 2`，这会导致频繁的删除
 - 在先前分离的段之间的边界处发生移除的情况

 正确的解决方案必须在处理字符时有效地维护邻接信息。 

## 方法

 ### 蛮力方法

 一种简单的方法是重复扫描字符串以查找组`k`相邻的相等字符。 

实现这一点的一种方法是：

 1. 从左到右扫描字符串。 
2. 统计连续相同的字符。 
3. 当计数达到`k`，删除这些字符。 
4. 重新启动扫描，因为删除操作可能会创建新的可删除组。 

这种方法是正确的，因为它明确地模拟了问题陈述。 每次出现有效组时，都会将其删除，并且该过程将继续，直到无法再删除为止。 

然而，这种方法效率低下。 每次删除可能都需要重建字符串，并且每次修改后我们可能需要再次重新扫描整个字符串。 

在最坏的情况下，这会导致二次复杂度。 

例如：```
s = "aaaaaaaaaa...."
```重复删除会强制进行多次重新扫描和重复的字符串复制操作。 

输入大小可达`100000`，这太慢了。 

### 最佳方法

 关键的观察是我们只关心连续的字符组及其计数。 

堆栈是一个自然的选择，因为：

 - 字符从左到右处理
 - 只有最近的群组才能与当前角色互动
 - 删除后，前一组自动变为相邻组

 我们不是独立存储每个单独的字符，而是存储：```
(character, count)
```对于每个字符：

 - 如果它与堆栈顶部字符匹配，则增加计数。 
- 如果计数变为`k`，立即删除该组。 
- 否则，将新组压入堆栈。 

这可以有效地模拟单次传递中的所有级联删除。 

由于每个字符最多被压入和弹出一次，因此该算法以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 字符串的反复重新扫描和重建 |
 | 最佳 | O(n) | O(n) | Stack 高效跟踪字符组并计数 |

 ## 算法演练

 ### 第 1 步：初始化堆栈

 创建一个空堆栈，其中每个元素存储：```
(character, frequency)
```堆栈表示到目前为止处理完所有删除操作后字符串的当前压缩状态。 

### 步骤 2：从左到右处理字符

 迭代字符串中的每个字符。 

对于每个字符：

 - 如果堆栈为空，则开始一个新组。 
- 如果当前字符与堆栈顶部字符匹配，则增加计数。 
- 否则，推送新的`(character, 1)`一对。 

这自然地将连续的相同字符组合在一起。 

### 步骤 3：当计数达到时删除组`k`增加计数后：

 - 如果计数恰好变为`k`，弹出堆栈。 

这模拟从字符串中删除这些字符。 

重要的见解是弹出会自动重新连接周围的组，这与问题行为完美匹配。 

### 第 4 步：继续处理

 继续处理剩余的字符。 

由于删除会立即发生，因此级联删除会自然处理，无需重新扫描。 

### 步骤 5：重建最终字符串

 处理完所有字符后：

 - 每个堆栈条目包含一个字符及其剩余频率。 
- 根据计数重复每个字符。 
- 将所有组连接在一起。 

这会产生最终的字符串。 

### 为什么它有效

 堆栈始终表示已处理字符串前缀的完全简化形式。 

每当处理一个字符时，它要么扩展最近的组，要么开始一个新的组。 如果一个团体达到规模`k`，立即删除它是安全的，因为该问题保证只要存在这样的组就可以进行删除。 

由于每次可能的删除一旦可用就会立即执行，因此堆栈不变式在整个处理过程中保持正确。 到最后，堆栈恰好包含最终的缩减字符串。 

## Python 解决方案```python
class Solution:
    def removeDuplicates(self, s: str, k: int) -> str:
        stack: list[list[str | int]] = []

        for char in s:
            if stack and stack[-1][0] == char:
                stack[-1][1] += 1

                if stack[-1][1] == k:
                    stack.pop()
            else:
                stack.append([char, 1])

        result = []

        for char, count in stack:
            result.append(char * count)

        return "".join(result)
```该实现使用一个堆栈，其中每个元素存储：```python
[character, count]
```当我们迭代字符串时，我们将当前字符与堆栈顶部进行比较。 

如果字符匹配，我们就会增加计数，因为连续组已经增长。 如果计数达到`k`，我们立即使用删除该组`pop()`。 

如果该字符与顶部堆栈条目不匹配，我们将开始一个包含 count 的新组`1`。 

处理完所有字符后，堆栈仅包含从未删除的剩余组。 我们根据存储的计数重复每个字符来重建最终的字符串。 

该实现是高效的，因为每个字符最多参与一次入栈和一次出栈操作。 

## 解决方案```go
func removeDuplicates(s string, k int) string {
	type Pair struct {
		char  byte
		count int
	}

	stack := []Pair{}

	for i := 0; i < len(s); i++ {
		char := s[i]

		if len(stack) > 0 && stack[len(stack)-1].char == char {
			stack[len(stack)-1].count++

			if stack[len(stack)-1].count == k {
				stack = stack[:len(stack)-1]
			}
		} else {
			stack = append(stack, Pair{char, 1})
		}
	}

	result := make([]byte, 0)

	for _, pair := range stack {
		for i := 0; i < pair.count; i++ {
			result = append(result, pair.char)
		}
	}

	return string(result)
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用结构体来存储字符计数对。 

切片用作堆栈。 删除顶部元素是通过以下方式完成的：```go
stack = stack[:len(stack)-1]
```为了提高效率，最终的字符串是使用字节切片构建的，因为输入仅包含小写英文字母。 

与 Python 字符串不同，Go 字符串是不可变的，因此使用字节切片增量构建结果可以避免重复分配。

 ## 边缘情况

 当整个字符串被删除时，就会出现一种重要的边缘情况。 例如：```
s = "aaa", k = 3
```有缺陷的实现可能会留下未处理的空堆栈或错误返回`None`。 基于堆栈的解决方案可以自然地处理这个问题，因为一旦组的计数达到，就会弹出该组`k`，留下一个空堆栈，该堆栈可重构为空字符串。 

另一个重要的案例是级联删除。 考虑：```
s = "deeedbbcccbdaa", k = 3
```删除一组会创建新的相邻组，这些组也可以删除。 幼稚的实现有时会失败，因为它们只处理每个位置一次。 堆栈解决方案会自动处理级联行为，因为删除会立即暴露堆栈顶部的前一个组。 

第三个棘手的情况涉及多次删除后剩余的字符。 例如：```
s = "aaaaaaaa", k = 3
```前六个字符被分成两组，每组三个，但仍保留两个字符。 不正确的实现可能会意外删除所有字符或错误处理剩余计数。 堆栈正确跟踪精确的频率，因此只有完整的大小组`k`被删除。 

当移除发生在组之间的边界处时，会发生另一种微妙的情况。 在：```
s = "baaab", k = 3
```去除`"aaa"`树叶`"bb"`。 该实现可以正确处理此问题，因为堆栈在弹出操作后会自然地重新连接先前分离的组。
