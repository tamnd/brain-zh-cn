[LeetCode 第 1279 题](https://leetcode.com/problems/traffic-light-control-intersection/)

 **难度：** 🟢简单
 **主题：** 并发

 ## 解决方案

 ## 问题理解

 这个问题要求我们为汽车从两条不同道路同时到达的道路交叉口设计一个线程安全的交通灯系统。 挑战不在于按顺序处理汽车，而在于正确同步多个线程，以便来自不同道路的汽车永远不会同时穿过十字路口。 

有两条路：

 - **A路**（`roadId = 1`），交通流向为南北和南北
 - **B路** (`roadId = 2`），交通流向为东西向和东西向

 在任何时刻，只有一条路可能亮绿灯。 如果A路有绿灯，B路一定有红灯，反之亦然。 最初，道路 A 开始为绿色，道路 B 开始为红色。 

每辆车到达都会触发一个呼叫：```
carArrived(carId, roadId, direction, turnGreen, crossCar)
```参数代表：

 -`carId`：汽车的唯一标识符
 -`roadId`：汽车属于哪条路
 -`direction`：汽车行驶方向
 -`turnGreen()`：将汽车所在道路的交通灯更改为绿色的回调
 -`crossCar()`：允许汽车通过路口的回调

 目标是保证：

 1.不同道路上的汽车永远不会同时交叉。 
2.解决方案无死锁。 
3. 灯光仅在必要时改变。 
4. 通话`turnGreen()`在已经是绿色的道路上行驶被认为是不正确的。 

并发方面是这里的重要挑战。 多辆汽车可能几乎同时从不同的线程到达。 如果来自不同道路的两辆车都试图同时修改交通信号灯，则可能会出现竞争情况。 

约束条件很小，最多`20`汽车，但这并没有降低同步的重要性。 由于这是一个并发问题，因此正确性远比原始性能更重要。 输入保证到达时间不减且汽车 ID 唯一，但实际线程执行顺序可能仍会有所不同。 

预先考虑一些边缘情况很重要。 同一条道路上可能会有多辆汽车连续到达，这种情况下，信号灯不应重复切换。 来自不同道路的汽车可能会同时到达，需要适当的同步以避免碰撞。 不加锁的简单实现可能会导致对面道路上的两辆车同时穿越，从而违反规则。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试通过重复检查或忙碌等待来手动协调汽车。 例如，线程可以连续轮询当前交通灯状态，直到其道路变绿。 

每当汽车到达时，它会：

 1、持续检查道路是否绿化。 
2. 如果不是绿色，请尝试切换它。 
3. 等待交叉路口可用。 
4. 穿过十字路口。 

这种方法在理论上是正确的，因为每辆车最终都会在穿越之前等待安全状态。 然而，它带来了不必要的复杂性和低效率。 繁忙的等待会浪费 CPU 周期，并且如果没有适当的锁定，竞争条件仍然可能发生。 两个线程可能会同时观察到相同的状态并错误地开关灯或交叉在一起。 

由于同步原语专门用于互斥，因此无需手动协调线程访问。 

### 最优方法，带锁互斥

 关键的观察结果是整个交叉路口的行为就像**关键部分**。 在任何时刻，都应该只允许一个线程检查或修改交通灯状态并让一辆车通过。 

这自然建议使用**互斥锁**。 

我们维护一个共享变量：```
current_green_road
```它跟踪当前哪条路有绿灯。 

当汽车到达时：

 1. 获取锁。 
2. 检查其道路是否已经绿灯。 
3. 如果没有，它会使用以下命令安全地开关灯`turnGreen()`。 
4.它调用`crossCar()`。 
5. 释放锁。 

由于整个操作受到互斥保护，来自不同道路的两辆车不能互相干扰。 一次只能有一辆车进入临界区。 

这个解决方案既简单又正确。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(等待时间) | O(1) | O(1) | 采用重复轮询或协调，效率低且容易出错 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 使用互斥锁和一个共享的红绿灯状态 |

 ## 算法演练

 1. 初始化红绿灯状态。 

由于问题表明道路 A 开始为绿色，因此我们初始化一个变量：```
current_green_road = 1
```这意味着 A 路最初处于活动状态。 
2. 创建互斥锁。 

因为多个线程可能会调用`carArrived()`同时，我们需要同步。 锁确保一次只有一个线程可以操作交通灯系统。 
3. 当汽车到达时，获取锁。 

检查信号灯、可能切换信号灯以及穿过十字路口的整个过程必须以原子方式进行。 
4. 检查到达车辆的道路是否已经绿灯。 

如果：```
roadId == current_green_road
```那么不需要改变灯光。 

否则，该车行驶的道路目前已红灯。 
5. 仅在必要时才开关灯。 

如果当前道路与绿色道路不同：

 - 打电话`turnGreen()`- 更新`current_green_road`这确保我们永远不会错误地调用`turnGreen()`在已经是绿色的道路上。 
6.让车通过。 

一旦正确的道路亮起绿灯，请致电：```
crossCar()
```7. 松开锁。 

汽车完成穿越后，另一个等待线程可能会继续进行。 

### 为什么它有效

 关键的不变量是**一次只有一个线程可以修改或检查相交状态**。 由于每辆车在与交通信号灯交互之前都会获取相同的互斥体，因此来自不同道路的两辆车不能同时穿过。 

此外，`current_green_road`始终准确反映哪条路有绿灯。 自从`turnGreen()`仅当请求的道路与当前的绿色道路不同时才调用，永远不会发生不必要或无效的灯光变化。 

这保证了死锁自由和正确性。 

## Python 解决方案```python
from threading import Lock
from typing import Callable

class TrafficLight:
    def __init__(self):
        self.current_green_road = 1
        self.lock = Lock()

    def carArrived(
        self,
        carId: int,
        roadId: int,
        direction: int,
        turnGreen: 'Callable[[], None]',
        crossCar: 'Callable[[], None]'
    ) -> None:
        with self.lock:
            if self.current_green_road != roadId:
                turnGreen()
                self.current_green_road = roadId

            crossCar()
```实施从导入开始`Lock`来自Python的`threading`模块。 此锁保证互斥，以便一次只有一个线程与交集交互。 

里面`__init__()`，我们初始化`current_green_road = 1`因为问题明确指出 A 路开始是绿色的。 我们还创建了一个互斥锁。 

这`carArrived()`方法将关键部分包装在里面：```python
with self.lock:
```这会自动安全地获取和释放锁。 

在关键部分内，我们比较`roadId`反对`current_green_road`。 如果它们不同，则到达的汽车在红灯道路上，所以我们打电话`turnGreen()`并更新内部状态。 

最后，我们调用`crossCar()`让车辆通过。 由于锁仍处于锁定状态，对面道路上的另一辆车无法同时通过。 

## 解决方案```go
package main

import "sync"

type TrafficLight struct {
	currentGreenRoad int
	mutex             sync.Mutex
}

func Constructor() TrafficLight {
	return TrafficLight{
		currentGreenRoad: 1,
	}
}

func (this *TrafficLight) CarArrived(
	carId int,
	roadId int,
	direction int,
	turnGreen func(),
	crossCar func(),
) {
	this.mutex.Lock()
	defer this.mutex.Unlock()

	if this.currentGreenRoad != roadId {
		turnGreen()
		this.currentGreenRoad = roadId
	}

	crossCar()
}
```Go 解决方案镜像了 Python 实现，但使用`sync.Mutex`用于同步。 

Go 没有使用 Python 的上下文管理器语法，而是使用以下方式显式锁定和解锁互斥体：```go
this.mutex.Lock()
defer this.mutex.Unlock()
```使用`defer`确保互斥锁始终被释放，即使函数意外退出也是如此。 

Go 在这里不需要对整数溢出或 nil 值进行特殊处理，因为逻辑只比较小整数道路标识符。 该结构直接存储共享状态，指针接收器确保更新在方法调用之间持续存在。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(1) | O(1) | 每次调用都会执行恒定数量的操作 |
 | 空间| O(1) | O(1) | 只存储一把锁和一个整型状态变量 |

 每次调用`carArrived()`仅执行一些恒定时间操作：锁获取、一次比较、可选状态更新和函数调用。 不使用循环或辅助数据结构。 

内存使用量也是恒定的，因为我们只存储互斥锁和当前的绿色道路标识符。

from threading import Thread

def test_same_road_no_switch():
    tl = TrafficLight()
    actions = []

    def green():
        actions.append("green")

    def cross():
        actions.append("cross")

    tl.carArrived(1, 1, 2, green, cross)
    tl.carArrived(2, 1, 1, green, cross)

    assert actions == ["cross", "cross"]  # same road, no switch needed

def test_switch_road():
    tl = TrafficLight()
    actions = []

    def green():
        actions.append("green")

    def cross():
        actions.append("cross")

    tl.carArrived(1, 2, 4, green, cross)

    assert actions == ["green", "cross"]  # road B requires switch

def test_multiple_switches():
    tl = TrafficLight()
    actions = []

    def green():
        actions.append("green")

    def cross():
        actions.append("cross")

    tl.carArrived(1, 2, 3, green, cross)
    tl.carArrived(2, 1, 2, green, cross)
    tl.carArrived(3, 2, 4, green, cross)

    assert actions == [
        "green", "cross",
        "green", "cross",
        "green", "cross"
    ]  # alternating roads

def test_single_car():
    tl = TrafficLight()
    crossed = []

    tl.carArrived(
        1,
        1,
        1,
        lambda: crossed.append("green"),
        lambda: crossed.append("cross"),
    )

    assert crossed == ["cross"]  # simplest boundary case

def test_concurrent_arrivals():
    tl = TrafficLight()
    crossed = []

    def make_car(road):
        tl.carArrived(
            1,
            road,
            1,
            lambda: crossed.append(f"green_{road}"),
            lambda: crossed.append(f"cross_{road}")
        )

    threads = [
        Thread(target=make_car, args=(1,)),
        Thread(target=make_car, args=(2,))
    ]

    for t in threads:
        t.start()

    for t in threads:
        t.join()

    assert len([x for x in crossed if "cross" in x]) == 2
    # both cars cross safely without deadlock

test_same_road_no_switch()
test_switch_road()
test_multiple_switches()
test_single_car()
test_concurrent_arrivals()

 ## 边缘情况

 当许多汽车连续到达同一条道路时，就会出现一种重要的边缘情况。 有错误的实现可能会重复调用`turnGreen()`即使灯已经是绿灯，而问题明确禁止这样做。 我们的实现通过检查来防止这种情况发生：```
if self.current_green_road != roadId:
```在改变灯光之前。 

另一个重要的情况发生在对面道路上的汽车同时到达时。 如果没有同步，两个线程都可能观察到过时状态并同时交叉，从而违反了问题约束。 互斥锁确保一次只有一个线程执行关键部分，从而消除了竞争条件。 

第三种边缘情况涉及道路之间的快速交替。 例如，汽车可能按 A → B → A → B 的顺序到达。有缺陷的实现可能会忘记在切换后更新共享交通灯状态。 我们的解决方案立即更新`current_green_road`后`turnGreen()`，保证未来的汽车观察到正确的状态。 

最后，最小的边界情况是一辆到达的汽车。 由于道路 A 最初是绿色的，因此道路 A 的车辆会立即穿越而无需切换，而道路 B 的车辆在穿越前只执行一次有效的切换。 该实现可以正确处理两者，无需特殊的分支逻辑。
