[LeetCode 问题 1203](https://leetcode.com/problems/sort-items-by-groups-respecting-dependencies/)

 **难度：** 🔴难
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们排序`n`项，同时满足两种不同的约束。 

第一个约束来自项目之间的依赖关系。 如果项目`a`出现在`beforeItems[b]`，然后项`a`必须出现在项目之前`b`在最终的排序中。 这是一个经典的依赖排序问题，它自然地建议在有向图上进行拓扑排序。 

第二个限制是关于群体的。 每个项目要么完全属于一个组，要么根本不属于任何组。 属于同一组的项目必须在最终答案中连续出现。 换句话说，如果一个组包含项目`{2, 5, 7}`，那么这些项必须在输出中显示为一个连续块。 其他组不能在它们之间交错。 

输入包括：

 -`n`，项目数量。 
-`m`，初始组数。 
-`group[i]`，它告诉我们哪个组项目`i`属于. 如果`group[i] == -1`，该项目最初不属于任何组。 
-`beforeItems[i]`，必须位于 item 之前的项目列表`i`。 

输出应该是满足以下条件的所有项目的有效排序：

 1.所有依赖约束。 
2.所有同组邻接约束。 

如果不存在这样的排序，我们必须返回一个空列表。 

限制条件很大：

 -`n`可以大到`3 * 10^4`- 依赖图可以包含许多边

 这立即排除了指数或强力排列生成方法。 我们需要一种接近线性时间的算法，理想情况下与项目数量加上依赖边数量成正比。 

问题的一个微妙方面是如何处理物品`group[i] == -1`。 由于每个组必须显示为连续的块，因此未分组的项目不能简单地自由浮动。 标准技巧是为每个未分组的项目分配其自己的唯一组。 这将问题转换为每个项目都属于一个组的问题。 

一些边缘情况很重要：

 - 项目之间的循环使得订购变得不可能。 
- 组之间的循环也使得排序变得不可能。 
- 组只能包含一项。 
- 有些组可能根本不包含任何项目。 
- 依赖关系可能存在于同一组内部和不同组之间。 
- 可能存在多个有效答案。 

核心挑战是以干净有效的方式将拓扑排序与分组约束结合起来。 

## 方法

 ### 蛮力方法

 暴力解决方案将生成项目的所有可能排列，并检查每个排列是否满足这两个条件：

 1. 依赖性约束。 
2. 组的连续性约束。 

对于每个排列，我们都会验证：

 - 对于每个依赖项`u -> v`， 物品`u`出现在之前`v`。 
- 同一组的所有项目一起出现。 

这种方法是正确的，因为它详尽地检查了每种可能的排序并返回满足所有约束的排序。 

然而，排列的数量是`n!`，即使对于中等值，它也变得不可能大`n`。 自从`n`可以达到`30000`，暴力破解是完全行不通的。 

### 最佳方法

 关键的见解是该问题实际上包含两个级别的排序：

 1. 组间排序。 
2. 每组内的项目之间的排序。 

我们可以将两个级别建模为有向图。 

首先，我们为所有未分组的项目分配唯一的组。 然后：

 - 构建项目依赖图。 
- 构建组依赖图。 

如果项目`u`必须出现在项目之前`v`:

 - 如果它们属于同一组，则这将成为项目图中的一条边。 
- 如果它们属于不同的组，这也会在两个组之间创建依赖关系。 

然后我们执行两个单独的拓扑排序：

 1. 对组进行拓扑排序。 
2. 对项目进行拓扑排序。 

一旦我们知道了物品的顺序，我们就可以按组收集物品，同时保留其内部顺序。 然后我们根据组拓扑顺序输出组。 

这是有效的，因为：

 - 组拓扑顺序保证有效的组间依赖关系。 
- 项目拓扑顺序保证有效的组内依赖关系。 
- 分组输出保证连续的组块。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n!) | 生成所有排列 |
 | 最佳 | O(n + e) | O(n + e) | 使用对偶拓扑排序 |

 这里，`e`是依赖边的总数。 

## 算法演练

 1. 将唯一组分配给未分组的项目。 

任何带有`group[i] == -1`被分配一个新的唯一组 ID，从`m`。 

这简化了问题，因为现在每个项目都属于一个组。 
2. 构建项目图。 

创建：

 - 项目依赖关系的邻接列表。 
- 项目的入度数组。 

对于每个依赖项`prev -> curr`:

 - 添加一条边`prev`到`curr`。 
- 增量`curr`的入度。 
3. 构建组图。 

如果两个依赖项属于不同的组：

 - 添加一条边`group[prev]`到`group[curr]`。 
- 增加的入度`group[curr]`。 

我们使用集合来避免重复的组边。 
4. 对项目进行拓扑排序。 

使用卡恩算法：

 - 从所有具有入度的项开始`0`。 
- 反复从队列中删除节点。 
- 减少邻居的入度。 
- 将新的零入度节点添加到队列中。 

如果我们无法处理所有项目，则存在循环，因此返回一个空列表。 
5. 对组进行拓扑排序。 

对组重复相同的过程。 

如果不是所有组都可以处理，则组之间存在循环，因此返回空列表。 
6. 根据项目顺序对项目进行分组。 

遍历拓扑排序的项列表。 

对于每个项目：

 - 将其附加到与其组关联的列表中。 

由于项目按照有效的依赖顺序进行处理，因此每个组列表都保留有效的内部顺序。 
7. 构建最终答案。 

按拓扑顺序遍历组。 

对于每组：

 - 附加属于该组的所有项目。 

这保证：

 - 组连续性。 
- 有效的依赖顺序。 

### 为什么它有效

 该算法将全局排序与局部排序分开。 

组拓扑排序保证了跨越组边界的所有依赖关系都得到尊重。 项目拓扑排序保证所有项目级依赖关系得到尊重。 由于项目是按组收集的，同时保留项目拓扑顺序，因此每个依赖项仍然有效，并且来自同一组的所有项目连续出现。 

如果任一图包含循环，则不存在有效的排序，并且算法正确返回空列表。 

## Python 解决方案```python
from collections import defaultdict, deque
from typing import List

class Solution:
    def sortItems(
        self,
        n: int,
        m: int,
        group: List[int],
        beforeItems: List[List[int]]
    ) -> List[int]:

        # Assign unique groups to ungrouped items
        next_group_id = m

        for item in range(n):
            if group[item] == -1:
                group[item] = next_group_id
                next_group_id += 1

        total_groups = next_group_id

        # Graphs and indegrees
        item_graph = defaultdict(list)
        item_indegree = [0] * n

        group_graph = defaultdict(list)
        group_indegree = [0] * total_groups

        # Avoid duplicate group edges
        group_edges = set()

        # Build graphs
        for curr in range(n):
            for prev in beforeItems[curr]:

                # Item graph
                item_graph[prev].append(curr)
                item_indegree[curr] += 1

                prev_group = group[prev]
                curr_group = group[curr]

                # Group graph
                if prev_group != curr_group:
                    edge = (prev_group, curr_group)

                    if edge not in group_edges:
                        group_edges.add(edge)
                        group_graph[prev_group].append(curr_group)
                        group_indegree[curr_group] += 1

        def topological_sort(nodes: List[int], graph, indegree):
            queue = deque()

            for node in nodes:
                if indegree[node] == 0:
                    queue.append(node)

            order = []

            while queue:
                node = queue.popleft()
                order.append(node)

                for neighbor in graph[node]:
                    indegree[neighbor] -= 1

                    if indegree[neighbor] == 0:
                        queue.append(neighbor)

            if len(order) != len(nodes):
                return []

            return order

        # Topological sort items
        item_order = topological_sort(
            list(range(n)),
            item_graph,
            item_indegree[:]
        )

        if not item_order:
            return []

        # Topological sort groups
        group_order = topological_sort(
            list(range(total_groups)),
            group_graph,
            group_indegree[:]
        )

        if not group_order:
            return []

        # Group items according to item order
        ordered_group_items = defaultdict(list)

        for item in item_order:
            ordered_group_items[group[item]].append(item)

        # Build final result
        result = []

        for grp in group_order:
            result.extend(ordered_group_items[grp])

        return result
```实施首先为所有未分组的项目分配唯一的组 ID。 这将问题转化为更清晰的结构，其中每个项目都属于一个组。 

接下来，构建两个图。 项目图捕获项目之间的直接依赖关系，而组图捕获组之间的依赖关系。 当依赖关系跨越组边界时，组图仅接收边。 

这`topological_sort`辅助函数实现了卡恩算法。 它首先处理所有零入度节点，并逐渐从图中删除依赖关系。 如果某些节点仍未处理，则存在循环。 

项目拓扑排序确保满足所有项目依赖性。 组拓扑排序可确保组以有效的全局顺序出现。 

最后，项目根据其拓扑项目顺序进行分组，并根据拓扑组顺序发出组。 

## 解决方案```go
package main

func sortItems(n int, m int, group []int, beforeItems [][]int) []int {

	// Assign unique groups to ungrouped items
	nextGroupID := m

	for i := 0; i < n; i++ {
		if group[i] == -1 {
			group[i] = nextGroupID
			nextGroupID++
		}
	}

	totalGroups := nextGroupID

	// Item graph
	itemGraph := make([][]int, n)
	itemIndegree := make([]int, n)

	// Group graph
	groupGraph := make([][]int, totalGroups)
	groupIndegree := make([]int, totalGroups)

	// Avoid duplicate group edges
	groupEdges := make(map[[2]int]bool)

	// Build graphs
	for curr := 0; curr < n; curr++ {
		for _, prev := range beforeItems[curr] {

			// Item graph
			itemGraph[prev] = append(itemGraph[prev], curr)
			itemIndegree[curr]++

			prevGroup := group[prev]
			currGroup := group[curr]

			// Group graph
			if prevGroup != currGroup {
				edge := [2]int{prevGroup, currGroup}

				if !groupEdges[edge] {
					groupEdges[edge] = true
					groupGraph[prevGroup] = append(groupGraph[prevGroup], currGroup)
					groupIndegree[currGroup]++
				}
			}
		}
	}

	topologicalSort := func(nodes []int, graph [][]int, indegree []int) []int {

		queue := make([]int, 0)

		for _, node := range nodes {
			if indegree[node] == 0 {
				queue = append(queue, node)
			}
		}

		order := make([]int, 0)
		head := 0

		for head < len(queue) {
			node := queue[head]
			head++

			order = append(order, node)

			for _, neighbor := range graph[node] {
				indegree[neighbor]--

				if indegree[neighbor] == 0 {
					queue = append(queue, neighbor)
				}
			}
		}

		if len(order) != len(nodes) {
			return []int{}
		}

		return order
	}

	// Topological sort items
	itemNodes := make([]int, n)

	for i := 0; i < n; i++ {
		itemNodes[i] = i
	}

	itemOrder := topologicalSort(itemNodes, itemGraph, append([]int(nil), itemIndegree...))

	if len(itemOrder) == 0 {
		return []int{}
	}

	// Topological sort groups
	groupNodes := make([]int, totalGroups)

	for i := 0; i < totalGroups; i++ {
		groupNodes[i] = i
	}

	groupOrder := topologicalSort(groupNodes, groupGraph, append([]int(nil), groupIndegree...))

	if len(groupOrder) == 0 {
		return []int{}
	}

	// Collect items by group
	groupedItems := make(map[int][]int)

	for _, item := range itemOrder {
		grp := group[item]
		groupedItems[grp] = append(groupedItems[grp], item)
	}

	// Build final result
	result := make([]int, 0)

	for _, grp := range groupOrder {
		result = append(result, groupedItems[grp]...)
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构，但使用切片和映射而不是 Python 集合。 

一个重要的细节是在拓扑排序之前复制入度数组。 由于卡恩算法的变化程度不同，我们使用：```go
append([]int(nil), itemIndegree...)
```创建副本。 

队列是使用带有移动的切片来实现的`head`指针，避免了低效的前端删除。 

Go 切片自然会处理空组，因为附加 nil 切片是安全的。

from typing import List

class Solution:
    def sortItems(self, n: int, m: int, group: List[int], beforeItems: List[List[int]]) -> List[int]:
        from collections import defaultdict, deque

        next_group_id = m

        for i in range(n):
            if group[i] == -1:
                group[i] = next_group_id
                next_group_id += 1

        total_groups = next_group_id

        item_graph = defaultdict(list)
        item_indegree = [0] * n

        group_graph = defaultdict(list)
        group_indegree = [0] * total_groups

        group_edges = set()

        for curr in range(n):
            for prev in beforeItems[curr]:

                item_graph[prev].append(curr)
                item_indegree[curr] += 1

                g1 = group[prev]
                g2 = group[curr]

                if g1 != g2:
                    edge = (g1, g2)

                    if edge not in group_edges:
                        group_edges.add(edge)
                        group_graph[g1].append(g2)
                        group_indegree[g2] += 1

        def topo(nodes, graph, indegree):
            q = deque()

            for node in nodes:
                if indegree[node] == 0:
                    q.append(node)

            order = []

            while q:
                node = q.popleft()
                order.append(node)

                for nei in graph[node]:
                    indegree[nei] -= 1

                    if indegree[nei] == 0:
                        q.append(nei)

            return order if len(order) == len(nodes) else []

        item_order = topo(list(range(n)), item_graph, item_indegree[:])

        if not item_order:
            return []

        group_order = topo(list(range(total_groups)), group_graph, group_indegree[:])

        if not group_order:
            return []

        grouped = defaultdict(list)

        for item in item_order:
            grouped[group[item]].append(item)

        result = []

        for grp in group_order:
            result.extend(grouped[grp])

        return result

sol = Solution()

 | 跨组依赖| 验证组拓扑排序 |
 | 存在空组 | 确保未使用的组不会破坏逻辑 |

 ## 边缘情况

 ### 在项目之间循环

 最重要的边缘情况之一是项目之间的依赖循环。 例如：```
0 -> 1 -> 2 -> 0
```在这种情况下，不存在有效的排序，因为每个项目都依赖于循环中的另一个项目。 幼稚的实现可能会永远循环或产生无效的部分排序。 

该实现通过检查拓扑排序是否处理所有节点来处理此问题。 如果某些节点仍未处理，则存在循环，并且算法返回空列表。 

### 未分组的项目

 项目与`group[i] == -1`如果处理不仔细，很容易引入错误。 由于组中的所有项目必须保持连续，因此未分组的项目会产生歧义。 

该实现通过为每个未分组的项目分配一个唯一的人工组来解决此问题。 这将问题转换为统一的结构，其中每个项目都属于一个组。 

### 重复的组依赖关系

 假设多个项目依赖关系创建相同的组依赖关系：```
item 1 -> item 5
item 2 -> item 6
```如果两个依赖项对应于：```
group 0 -> group 1
```那么重复添加重复的边会错误地增加入度并破坏拓扑排序。 

该实现通过在将组边插入到图中之前将组边存储在集合中来避免这种情况。 

### 空组

 有些组可能根本不包含任何项目。 粗心的实施可能会假设每个小组都对结果做出了贡献。 

当前的解决方案可以安全地处理空组，因为使用空列表扩展结果没有任何效果。 拓扑排序仍然正确地处理这些组。 

### 独立组件

 依赖图可能包含完全断开连接的组件。 例如：```
0 -> 1

2 -> 3
```在这种情况下存在多个有效的拓扑排序。 

卡恩算法自然地通过从所有零入度节点开始来处理这个问题，允许以任何有效的顺序处理独立分量。
