 # LeetCode 1207 - 唯一出现次数

 ## 问题理解

 问题给了我们一个整数数组`arr`并询问每个不同的数字是否出现唯一的次数。 

换句话说，我们首先计算每个值在数组中出现的次数。 获得所有频率后，我们必须验证没有两个不同的值共享相同的频率。 

例如，考虑：```
arr = [1,2,2,1,1,3]
```频率是：

 -`1`出现3次
 -`2`出现2次
 -`3`出现1次

 自从计数`{3, 2, 1}`都是不同的，答案是`true`。 

现在考虑：```
arr = [1,2]
```两个都`1`和`2`恰好出现一次。 由于两个不同的值共享相同的出现次数，因此答案是`false`。 

输入数组可以包含正整数和负整数。 限制相对较小：

 -`1 <= arr.length <= 1000`-`-1000 <= arr[i] <= 1000`这些限制告诉我们一些重要的事情：

 - 阵列足够小，即使效率较低的解决方案也可能通过。 
- 但是，预期的解决方案仍应使用有效的计数技术。 
- 由于值可以重复多次，因此频率计数是核心操作。 
- 负数不会改变逻辑，因为哈希映射自然地处理它们。 

还有一些值得尽早识别的边缘情况：

 - 每个值都是唯一的数组，这意味着每个频率都是`1`- 所有元素都相同的数组
 - 包含负值的数组
 - 两个不同数字意外共享相同计数的数组
 - 长度数组`1`，它应该总是返回`true`该问题保证数组非空，因此我们永远不需要处理完全空的输入。 

## 方法

 ### 蛮力方法

 强力解决方案将通过重复扫描数组来手动计算每个元素的出现次数。 

对于每个不同的值，我们可以：

 1、遍历整个数组，统计出现的次数。 
2. 存储该计数。 
3. 将其与所有先前处理的值的计数进行比较。 

这种方法是正确的，因为每个值的频率都是明确计算和比较的。 但是，它会对数组执行多次重复扫描。 

如果有`n`元素，并且我们重复扫描数组以获取计数，总工作量可能会增长到`O(n²)`。 

虽然`n <= 1000`足够小以至于这仍然可以通过，这是低效且不必要的。 

### 最佳方法

 关键的观察是我们只需要两条信息：

 1. 各值出现的频率
 2. 任意频率是否出现多次

 哈希图非常适合计算频率，因为它允许恒定的平均时间插入和查找。 

一旦我们构建了频率图，我们就可以将所有频率值放入哈希集中。 由于集合仅存储唯一值，因此我们可以比较：

 - 不同元素的数量
 - 不同频率的数量

 如果这些计数相等，则每个出现计数都是唯一的。 

这将解决方案缩短为线性时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 重复扫描数组以计算频率 |
 | 最佳 | O(n) | O(n) | 使用哈希映射进行计数并使用集合进行唯一性检查 |

 ## 算法演练

 1. 创建一个名为的哈希图`frequency_map`。 

该映射存储每个整数在数组中出现的次数。 键是整数值，值是其出现次数。 
2. 遍历数组一次。 

对于每个数字：

 - 如果它已存在于地图中，则增加其计数。 
- 否则，将其计数初始化为`1`。 

在此步骤之后，映射包含每个不同值的频率。 
3. 提取所有频率计数。 

哈希图的值代表我们关心的出现次数。 
4. 将频率插入哈希集中。 

集合会自动删除重复项。 如果两个数字具有相同的出现次数，则集合大小将小于映射条目的数量。 
5. 比较尺寸。 

- 如果集合中的频率数等于映射中的键数，则所有频率都是唯一的。 
- 否则，至少两个值共享相同的频率。 
6. 返回结果。 

### 为什么它有效

 该算法之所以有效，是因为每个不同的数字都贡献了一个频率计数。 集合仅保留唯一值，因此如果两个数字共享相同的出现次数，则重复频率将折叠到一个集合条目中。 因此：

 - 大小相等意味着所有频率都是唯一的。 
- 不同的大小意味着至少有一个频率是重复的。 

这直接符合问题要求。 

## Python 解决方案```python
from typing import List

class Solution:
    def uniqueOccurrences(self, arr: List[int]) -> bool:
        frequency_map = {}

        for number in arr:
            frequency_map[number] = frequency_map.get(number, 0) + 1

        frequencies = set(frequency_map.values())

        return len(frequencies) == len(frequency_map)
```实现首先创建一个名为的字典`frequency_map`。 该字典存储每个数字在数组中出现的次数。 

循环遍历中的每个元素`arr`。 对于每个数字，计数使用以下方式更新：```python
frequency_map.get(number, 0) + 1
```如果数字已经存在，则检索当前计数，或者使用`0`如果没有，则作为默认值。 

计数完成后，将字典值转换为集合：```python
frequencies = set(frequency_map.values())
```由于集合仅包含唯一元素，因此重复出现的计数将被自动删除。 

最后通过代码对比：```python
len(frequencies) == len(frequency_map)
```如果这些大小匹配，则每个频率都是唯一的。 

## 解决方案```go
func uniqueOccurrences(arr []int) bool {
	frequencyMap := make(map[int]int)

	for _, number := range arr {
		frequencyMap[number]++
	}

	frequencySet := make(map[int]bool)

	for _, frequency := range frequencyMap {
		if frequencySet[frequency] {
			return false
		}

		frequencySet[frequency] = true
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`用于计算频率。 Go 自动将缺失的整数映射值初始化为`0`，因此递增：```go
frequencyMap[number]++
```自然有效。 

Go 没有使用专用的集合类型，而是通过以下方式模拟集合：```go
map[int]bool
```如果频率已存在于集合图中，则该函数立即返回`false`。 

Go 在这里不需要对空切片和 nil 切片进行特殊处理，因为该问题保证至少有一个元素。 整数溢出也不是问题，因为最大频率仅为`1000`。

 ## 边缘情况

 一种重要的边缘情况是仅包含一个元素的数组。 在这种情况下，只有一个频率，该频率自动是唯一的。 粗心的实现可能会使逻辑过于复杂或错误地假设至少存在两个不同的值。 当前的解决方案自然地处理了这一问题，因为映射和集合都只包含一个条目。 

另一个重要的情况是每个数字都只出现一次。 例如：```
[1,2,3,4]
```所有频率都变成`1`，这意味着集合仅包含一个值，而映射包含四个键。 一些不正确的实现仅检查相邻值或忘记全局验证重复项。 使用一组可以保证检测到所有重复的频率。 

第三种边缘情况涉及负数和零。 由于数组值的范围是`-1000`到`1000`，实现必须正确地将负整数计数为哈希映射键。 Python 字典和 Go 映射都完全支持负整数键，因此不需要额外的逻辑。 

当许多不同的数字共享相同的频率时，最后一个微妙的情况就会发生。 例如：```
[1,1,2,2,3,3]
```每个值出现两次。 幼稚的实现可能会过早停止检查或无法比较所有计数。 基于集合的方法立即揭示了这个问题，因为所有三个频率都崩溃为单个设定值。
