[LeetCode 第 1255 题](https://leetcode.com/problems/maximum-score-words-formed-by-letters/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、字符串、动态规划、回溯、位操作、计数、位掩码

 ## 解决方案

 ## 问题理解

 这个问题要求我们选择可以使用有限的字母来构建的单词子集，从而使所有所选单词的总分最大化。 

我们得到三个输入：

 -`words`，字符串数组
 -`letters`，可用字符的多集
 -`score`，一个由 26 个整数组成的数组，其中`score[i]`代表角色的价值`'a' + i`每个单词可以选择一次或根本不选择。 仅当剩余字母供应中提供了该单词所需的每个字符时，才可以使用该单词。 中的每一个字母`letters`在所有选定的单词中只能使用一次。 

目标是通过选择任何有效的单词子集来计算可实现的最大总分。 

重要的观察是，这从根本上来说是一个子集选择问题。 对于每个单词，我们有两种选择：

 - 包括这个词
 - 跳过这个词

 自从`words.length <= 14`，子集总数最多为：$$2^{14} = 16384$$这足够小，可以通过修剪或回溯进行详尽的探索。 

这些约束还告诉我们一些有用的信息：

 - 单词数量非常少，强烈建议子集枚举或回溯。 
- 单词长度足够小，计算字符频率的成本很低。 
- 字母总数可以更大，但只有 26 个小写字母，因此频率数组是有效的。 

一些边缘情况很重要：

 - 有些单词即使单独使用也可能无法组成。 
- 如果高分单词消耗了更好组合所需的字母，则最佳解决方案可能会跳过它们。 
- 答案可以是`0`如果无法形成有效的单词。 
- 多个单词可能会竞争相同的有限字母。 
- 字母分数可以为零，这意味着某些字母没有任何贡献。 

天真的贪婪策略会失败，因为局部决策不能保证全局最优子集。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的单词子集。 

对于每个子集：

 1. 计算所需字母的总频率。 
2. 将这些频率与可用字母进行比较。 
3. 如果有效，计算总分。 
4. 追踪最高分。 

这是有效的，因为每个可能的组合都会被评估，保证考虑最佳子集。 

然而，这种方法会重复地从头开始计算每个子集的频率和分数。 虽然子集的总数是可以管理的，但冗余计算会降低实现效率。 

### 最优方法，增量状态回溯

 更好的解决方案是使用回溯。 

我们不是独立地重建每个子集的计数，而是一次处理一个单词并增量地维护当前字母的使用。 

在每个索引处：

 - 跳过当前单词
 - 如果剩余足够的字母，请尝试包含当前单词

 这将创建一个决策树，最多包含$2^n$州。 

关键的见解是：

 - 字数非常少
 - 字母大小固定为26
 - 我们可以在递归过程中有效地保持字母频率

 通过增量更新计数，我们避免重复重新计算并实现高效的穷举搜索。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × n × 26) | O(2^n × n × 26) | O(26) | 重新计算每个子集的频率 |
 | 最佳 | O(2^n × 26) | O(2^n × 26) | O(26 + n) | O(26 + n) | 使用增量频率跟踪进行回溯 |

 这里，`n`是单词数。 

## 算法演练

 ### 第 1 步：计算可用字母

 创建一个大小为 26 的频率数组，表示每个字母可用的次数。 

例如：```
letters = ["a","a","c","d","d","d","g","o","o"]
```变成：```
a -> 2
c -> 1
d -> 3
g -> 1
o -> 2
```使用固定大小的数组比哈希映射更快、更简单，因为只存在小写英文字母。 

### 步骤 2：预先计算单词信息

 对于每个单词：

 - 计算其字母频率数组
 - 计算其总分

 这避免了在递归期间重新计算它们。 

为了`"dad"`:```
d -> 2
a -> 1
score = 5 + 1 + 5 = 11
```### 步骤 3：定义递归决策函数

 我们按索引递归地处理单词。 

在每个位置，我们都有两种选择：

 1. 跳过这个词
 2. 如果剩余字母足够，请包含该单词

 递归函数返回从当前索引开始可达到的最大分数。 

### 步骤 4：尝试跳过当前单词

 我们首先计算结果而不使用当前单词：```
best = dfs(index + 1)
```这将探索排除当前单词的所有子集。 

###第五步：检查该词是否可以使用

 将单词的字母要求与剩余的可用字母进行比较。 

如果任何所需的计数超出了可用的数量，则不能包含该单词。 

### 第 6 步：包含单词

 如果该词有效：

 1. 从可用计数中减去其字母
 2.添加其分数
 3.递归到下一个索引
 4. 之后恢复计数

 此恢复步骤至关重要，因为回溯对不同分支重复使用相同的频率阵列。 

### 第 7 步：返回最佳结果

 返回以下之间的最大分数：

 - 跳过这个词
 - 包括这个词

 ### 为什么它有效

 该算法通过递归包含和排除决策来探索单词的每个有效子集。 因为每个子集恰好对应于递归树中的一条路径，所以保证检查最优子集。 

频率数组始终正确地表示剩余的可用字母，因为每次递归包含都会减去计数，并且每次回溯都会恢复它们。 这个不变量保证了有效性检查总是准确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxScoreWords(
        self,
        words: List[str],
        letters: List[str],
        score: List[int]
    ) -> int:
        
        available = [0] * 26
        
        for ch in letters:
            available[ord(ch) - ord('a')] += 1

        word_counts = []
        word_scores = []

        for word in words:
            counts = [0] * 26
            total_score = 0

            for ch in word:
                idx = ord(ch) - ord('a')
                counts[idx] += 1
                total_score += score[idx]

            word_counts.append(counts)
            word_scores.append(total_score)

        n = len(words)

        def dfs(index: int) -> int:
            if index == n:
                return 0

            best = dfs(index + 1)

            can_use = True
            counts = word_counts[index]

            for i in range(26):
                if counts[i] > available[i]:
                    can_use = False
                    break

            if can_use:
                for i in range(26):
                    available[i] -= counts[i]

                best = max(
                    best,
                    word_scores[index] + dfs(index + 1)
                )

                for i in range(26):
                    available[i] += counts[i]

            return best

        return dfs(0)
```实施从构建`available`输入字母的频率数组。 这允许恒定时间访问剩余的字母计数。 

接下来，该解决方案对每个单词进行预处理。 创建了两个数组：

 -`word_counts`，存储每个单词的频率数组
 -`word_scores`，存储每个单词的总分

 这种预处理可以防止递归期间的重复工作。 

递归`dfs`函数探索所有子集选择。 当所有单词都已处理完毕时，就会出现基本情况。 

对于每个单词，该函数首先计算跳过它所获得的结果。 然后它检查是否可以使用当前可用的字母组成该单词。 

如果该单词有效，则将其字母暂时从频率数组中删除，继续递归，然后恢复字母。 这个恢复就是核心的回溯机制。 

最后，该函数返回包含和排除选项之间较大的分数。 

## 解决方案```go
func maxScoreWords(words []string, letters []byte, score []int) int {
	available := make([]int, 26)

	for _, ch := range letters {
		available[ch-'a']++
	}

	n := len(words)

	wordCounts := make([][]int, n)
	wordScores := make([]int, n)

	for i, word := range words {
		counts := make([]int, 26)
		totalScore := 0

		for _, ch := range word {
			idx := ch - 'a'
			counts[idx]++
			totalScore += score[idx]
		}

		wordCounts[i] = counts
		wordScores[i] = totalScore
	}

	var dfs func(int) int

	dfs = func(index int) int {
		if index == n {
			return 0
		}

		best := dfs(index + 1)

		counts := wordCounts[index]
		canUse := true

		for i := 0; i < 26; i++ {
			if counts[i] > available[i] {
				canUse = false
				break
			}
		}

		if canUse {
			for i := 0; i < 26; i++ {
				available[i] -= counts[i]
			}

			withCurrent := wordScores[index] + dfs(index+1)

			if withCurrent > best {
				best = withCurrent
			}

			for i := 0; i < 26; i++ {
				available[i] += counts[i]
			}
		}

		return best
	}

	return dfs(0)
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片而不是 Python 列表。 

一个显着的区别是 Go 使用显式整数比较而不是 Python 的内置比较`max()`功能。 

频率数组表示为`[]int`长度为 26 的切片。由于切片是可变引用，因此回溯恢复步骤对于避免破坏递归分支之间的共享状态尤其重要。 

Go 整数足以解决这个问题，因为最大可能得分相对于整数限制来说很小。

 - 深度的递归栈`n`自从`n <= 14`，递归深度仍然很小。

 ## 边缘情况

 ### 不能单独组成的单词

 单词可能需要可用池中不存在的字母。 例如：```
words = ["zzz"]
letters = ["a","b","c"]
```有缺陷的实现可能仍会尝试包含该单词或产生负频率计数。 该解决方案通过在包含之前验证每个所需的字母计数来防止这种情况发生。 

### 最优解不使用所有单词

 贪婪地包含每个有效单词可能很诱人，但这可能会产生次优结果，因为单词会竞争有限的字母。 

例如：```
words = ["aaa", "aa", "a"]
letters = ["a","a","a"]
```最好的答案是`"aaa"`得分 3，不`"aa" + "a"`由于得分相同，而在其他评分设置中，贪婪的选择可能会完全失败。 

递归搜索保证每个子集都被评估。 

### 零分字母

 有些字母可能对总分没有任何贡献。 粗心的实现可能会错误地优先考虑较长的单词，即使它们的额外字母的值为零。 

例如：```
score = [0] * 26
```每个有效子集都应返回分数 0。 

此实现计算精确的基于字母的总计，因此自然且正确地处理零值字母。
