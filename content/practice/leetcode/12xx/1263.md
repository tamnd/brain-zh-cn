[LeetCode 问题 1263](https://leetcode.com/problems/minimum-moves-to-move-a-box-to-their-target-location/)

 **难度：** 🔴难
 **主题：** 数组、广度优先搜索、堆（优先级队列）、矩阵

 ## 解决方案

 ## 问题理解

 该问题是经典“推箱子”难题的变体。 给你一个代表仓库的网格，玩家可以在其中`'S'`必须推一个盒子`'B'`到目标位置`'T'`。 玩家可以在空闲的地砖上向四个方向移动`'.'`但不能穿墙`'#'`或盒子本身。 盒子只能通过玩家从相邻单元格推动它来移动，并且每次推动都计入答案。 任务是计算将盒子移动到目标所需的**最小推动次数**。 如果盒子因墙壁或无法到达的位置而无法到达目标，则返回`-1`。 

输入保证只有一名玩家、一个盒子和一个目标，这简化了跟踪位置。 网格大小被限制为`m, n <= 20`，这意味着基于 BFS 的搜索是可行的，但由于指数状态空间，尝试所有玩家移动的简单暴力方法会太慢。 

主要观察结果包括玩家必须能够到达盒子后面的单元格才能推动它，因此每个潜在的盒子移动仅在玩家可以访问相应的单元格时才有效。 这引入了两级搜索：一个用于盒子位置，另一个用于检查玩家的可达性。 

重要的边缘情况包括盒子被墙壁阻挡、玩家完全无法到达盒子后面或盒子已经在目标上的情况。 这些案件必须返回`-1`或者`0`适当地。 

## 方法

 **暴力方法**会递归地尝试玩家移动和盒子推动的每个序列，跟踪玩家和盒子的所有位置。 在每一步中，算法都会探索所有四个移动方向并检查是否可以进行推动。 虽然这保证了正确性，但它是不可行的，因为状态数量随着`O((m*n)^2)`对于玩家-盒子组合并探索每个运动序列可能会导致指数级的运行时间。 

**最佳方法**使用 BFS，其中主要状态是 **盒子位置和玩家位置**，并且转换对应于有效的盒子推动。 在推箱子之前，我们执行二次 BFS（或 DFS），以确保玩家能够在不穿过墙壁或箱子本身的情况下到达所需的推位置。 这允许尽早修剪无效状态并确保每个状态最多被访问一次。 使用 BFS 可以保证我们第一次到达目标框位置时的推动次数最少。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^(m*n)) | O(4^(m*n)) | O((m*n)^2) | O((m*n)^2) | 探索玩家移动和推动的所有序列； 对于 m, n ~ 20 来说不切实际 |
 | 最优 BFS | O(m * n * m * n * 4) | O((m*n)^2) | O((m*n)^2) | 盒子玩家状态上的 BFS； 对于每个方块移动，BFS 检查玩家的可达性 |

 ## 算法演练

 1. **定位初始位置**：扫描网格找到玩家的坐标`'S'`， 盒子`'B'`，和目标`'T'`。 
2. **定义BFS状态**：将每个状态表示为`(box_x, box_y, player_x, player_y)`并跟踪推送次数。 
3. **队列初始化**：使用起始状态和访问集初始化 BFS 队列，以防止重新访问相同的盒子播放器配置。 
4. **方向向量**：定义推动盒子的四种可能的移动方向：上、下、左、右。 
5. **BFS遍历**：当队列不为空时，弹出一个状态。 对于每个方向，计算盒子被推动时的新盒子位置。 
6. **检查推送的有效性**：确保新框位置在边界内并且是空闲单元。 确定盒子后面的单元格（与推动相对），并检查玩家是否可以使用避开墙壁和盒子本身的 BFS 到达该单元格。 
7. **状态转换**：如果推送有效并且结果状态尚未被访问过，则将其添加到队列中`pushes + 1`。 
8. **检查目标**：如果盒子到达目标位置，则返回推动次数。 
9. **穷举搜索**：如果BFS完成但没有到达目标，则返回`-1`。 

**为什么有效**：BFS 确保按照增加推送的顺序探索状态。 通过仅在玩家实际到达所需位置时才推动，我们可以避免无效的移动。 访问集保证我们永远不会重新计算状态，从而确保效率。 

## Python 解决方案```python
from collections import deque
from typing import List, Tuple, Set

class Solution:
    def minPushBox(self, grid: List[List[str]]) -> int:
        m, n = len(grid), len(grid[0])
        directions = [(-1,0),(1,0),(0,-1),(0,1)]
        
        def in_bounds(x: int, y: int) -> bool:
            return 0 <= x < m and 0 <= y < n
        
        def can_player_reach(sx: int, sy: int, tx: int, ty: int, box: Tuple[int,int]) -> bool:
            """Check if player can reach (tx, ty) without crossing walls or the box."""
            visited = set()
            queue = deque([(sx, sy)])
            visited.add((sx, sy))
            while queue:
                x, y = queue.popleft()
                if (x, y) == (tx, ty):
                    return True
                for dx, dy in directions:
                    nx, ny = x + dx, y + dy
                    if in_bounds(nx, ny) and (nx, ny) not in visited and grid[nx][ny] != '#' and (nx, ny) != box:
                        visited.add((nx, ny))
                        queue.append((nx, ny))
            return False
        
        # Locate player, box, and target
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 'S':
                    player = (i,j)
                elif grid[i][j] == 'B':
                    box = (i,j)
                elif grid[i][j] == 'T':
                    target = (i,j)
        
        queue = deque([(box, player, 0)]) # box_pos, player_pos, pushes
        visited: Set[Tuple[Tuple[int,int], Tuple[int,int]]] = set()
        visited.add((box, player))
        
        while queue:
            (bx, by), (px, py), pushes = queue.popleft()
            if (bx, by) == target:
                return pushes
            for dx, dy in directions:
                nbx, nby = bx + dx, by + dy
                px_required, py_required = bx - dx, by - dy
                if in_bounds(nbx, nby) and grid[nbx][nby] != '#' and in_bounds(px_required, py_required) and grid[px_required][py_required] != '#':
                    if can_player_reach(px, py, px_required, py_required, (bx, by)):
                        new_state = ((nbx, nby), (bx, by))
                        if new_state not in visited:
                            visited.add(new_state)
                            queue.append(((nbx, nby), (bx, by), pushes + 1))
        return -1
```Python 实现紧密遵循该算法。 这`can_player_reach`功能确保玩家可以在推动之前移动到盒子后面。 每次 BFS 迭代都会考虑所有四个方向，更新盒子和玩家位置，并仅针对有效移动增加推动计数。
