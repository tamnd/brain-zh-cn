[LeetCode 问题 2344](https://leetcode.com/problems/minimum-deletions-to-make-array-divisible/)

 **难度：** 🔴难
 **主题：** 数组、数学、排序、堆（优先级队列）、数论

 ## 解决方案

 ## 问题理解

 该问题给了我们两个正整数数组，`nums`和`numsDivide`。 我们可以删除任意数量的元素`nums`，我们的目标是使**最小的剩余元素`nums`将每个数字除以`numsDivide`**。 

这里的关键词是**最小剩余元素**。 删除后，剩下的最小值`nums`变得特殊，因为该值必须均匀地除以中的每个元素`numsDivide`。 

换句话说，假设删除一些值后，剩下的最小数`nums`是`x`。 然后为了使解决方案有效：```
numsDivide[i] % x == 0
```对于中的每个元素`numsDivide`。 

我们希望最大限度地减少实现此条件所需的删除次数。 如果没有元素在`nums`能满足整除性要求，那么答案是`-1`。 

每个输入数组最多可以包含`10^5`元素，值可以大到`10^9`。 这些限制立即排除了昂贵的暴力解决方案。 具有二次复杂度的算法，例如`O(n × m)`如果两个数组都很大，速度就会太慢。 

一个重要的观察是候选最小数必须除以**每个元素**`numsDivide`。 这意味着它必须除以它们的**最大公约数 (GCD)**。 这种数学特性极大地减少了搜索空间。 

预先考虑几个边缘情况很重要。 如果`nums`包含重复项，删除一个出现项可能还不够，因为最小的剩余元素很重要。 如果没有元素在`nums`将所有元素分为`numsDivide`，答案一定是`-1`。 如果排序顺序中的最小元素已经起作用，则不需要删除。 大值还意味着我们应该避免对每个可能的候选者进行因式分解或昂贵的整除性检查。 

## 方法

 ### 蛮力方法

 一个简单的方法是尝试每一个可能的候选者`nums`作为最小的剩余元素。 

我们可以排序`nums`，然后对于每个唯一的数字`x`，检查是否`x`将每个值除以`numsDivide`。 如果是，计算需要删除多少个较小的元素，以便`x`成为最小的剩余值。 

这种方法是正确的，因为它明确地检查了每一个有效的可能性。 如果一个数字可以成为最小有效除数，我们就准确计算需要删除多少次并取最小值。 

然而，问题来自于效率。 对于每个候选人`nums`，我们扫描所有`numsDivide`。 

如果：

-`n = len(nums)`-`m = len(numsDivide)`那么时间复杂度就变成：```
O(n × m)
```两个阵列都可能达到`10^5`，这可能需要`10^10`在最坏的情况下，操作速度太慢了。 

### 最佳方法

 关键的数学见解是，有效的最小元素必须除以**中的每个数字`numsDivide`**。 

我们可以计算中所有数字的 **GCD，而不是重复检查每个元素的整除性`numsDivide`**。 

为什么这有帮助？ 

如果一个数字`x`将每个元素分为`numsDivide`， 然后`x`必须除：```
gcd(numsDivide)
```相反，如果`x`除以 GCD，则`x`自动除以每个数字`numsDivide`。 

这将问题转化为：

 > 找到排序后的最小元素`nums`将 GCD 划分为`numsDivide`。 

排序后`nums`，我们从最小到最大扫描。 我们遇到的第一个有效数字是最佳的，因为：

 1. 最大限度地减少删除。 
2. 必须删除任何较小的数字，使其成为最小值。 

如果有效数字出现在索引处`i`按排序顺序，那么我们必须准确删除`i`元素。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(1) | O(1) | 根据中的所有元素检查每个候选者`numsDivide`|
 | 最佳| O(m log V + n log n) | O(m log V + n log n) | O(1) 或 O(log n) | 使用 GCD 归约和排序 |

 这里，`V`表示最大数值，因为欧几里得的 GCD 算法以对数时间运行。 

## 算法演练

 ### 步骤 1：计算中所有元素的 GCD`numsDivide`我们首先减少`numsDivide`化为一个数字：```
g = gcd(numsDivide[0], numsDivide[1], ..., numsDivide[n-1])
```这是有效的，因为任何有效的最小元素必须除以所有数字，这意味着它必须除以它们的 GCD。 

### 第 2 步：排序`nums`我们排序`nums`按升序排列。 

排序的原因是问题取决于**剩余的最小元素**。 通过从小到大处理数字，第一个有效候选者会自动产生最小的删除数。 

### 第 3 步：扫描已排序的内容`nums`对于每个数字`num`按排序顺序：

 检查：```
g % num == 0
```如果为真，那么`num`划分 GCD，这意味着它将划分中的每个元素`numsDivide`。 

那一刻：

 - 每个较早的元素都小于`num`- 那些较小的元素必须被删除
 - 因此，指数`num`等于删除的次数

 立即返回该索引。 

### 第 4 步：返回`-1`如果不存在有效除数

 如果我们完成扫描`nums`如果没有找到任何有效的除数，则任何删除序列都不能满足要求。 

返回：```
-1
```### 为什么它有效

 正确性来自两个属性。 

首先，一个数字除以所有元素`numsDivide`当且仅当它除以他们的 GCD 时。 这意味着我们只需要对每个候选人进行一次可分性检查。 

其次，排序保证了最优性。 由于我们从小到大进行扫描，因此第一个有效除数可以最大程度地减少删除。 任何较晚的有效除数都需要删除更多元素，因为所有较早的值仍需要删除。 

## Python 解决方案```python
from math import gcd
from typing import List

class Solution:
    def minOperations(self, nums: List[int], numsDivide: List[int]) -> int:
        # Compute GCD of numsDivide
        overall_gcd = numsDivide[0]

        for num in numsDivide[1:]:
            overall_gcd = gcd(overall_gcd, num)

        # Sort nums so we can find the first valid smallest element
        nums.sort()

        # Find first number that divides the GCD
        for index, num in enumerate(nums):
            if overall_gcd % num == 0:
                return index

        return -1
```实现首先计算所有元素的 GCD`numsDivide`。 我们不是重复检查每个数字的整除性，而是将整除性条件压缩为一个称为`overall_gcd`。 

接下来我们排序`nums`。 排序是必不可少的，因为答案取决于哪个元素成为删除后剩余的最小数。 

然后我们遍历排序后的数组。 对于每个值，我们测试它是否能整除 GCD。 第一个有效数字立即给出答案，因为必须删除每个较小的数字。 

如果没有找到有效的除数，函数返回`-1`。 

## 解决方案```go
package main

import "sort"

func gcd(a, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func minOperations(nums []int, numsDivide []int) int {
	// Compute GCD of numsDivide
	overallGCD := numsDivide[0]

	for i := 1; i < len(numsDivide); i++ {
		overallGCD = gcd(overallGCD, numsDivide[i])
	}

	// Sort nums
	sort.Ints(nums)

	// Find first valid divisor
	for i, num := range nums {
		if overallGCD%num == 0 {
			return i
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于Go在整数标准库中不包含内置的GCD函数，因此我们手动实现Euclid算法。 

排序是使用`sort.Ints(nums)`。 通过排序切片的迭代反映了 Python 的迭代`enumerate`。 

整数溢出不是问题，因为对于给定的约束，所有值都保持在 Go 的整数限制内，并且 GCD 操作只会减少数字。

 ## 边缘情况

 当最小元素已经满足条件时，就会出现一种重要的边缘情况。 例如：```
nums = [2,4,6]
numsDivide = [8,16]
```有缺陷的实现可能仍会执行不必​​要的删除。 自从`2`已经划分了每个元素，正确答案是`0`。 我们的实现处理了这个问题，因为排序扫描立即在索引处成功`0`。 

另一个棘手的情况是有效除数之前出现重复项。 考虑：```
nums = [2,2,2,3]
numsDivide = [9,18]
```最大公约数是`9`， 和`2`不分开`9`。 全部三份`2`必须在之前删除`3`成为最小元素。 因为我们排序并返回第一个有效索引，所以重复项会自动正确计数。 

当不存在有效除数时，会发生第三种边缘情况。 例如：```
nums = [4,6,8]
numsDivide = [9,15]
```最大公约数是`3`，并且没有任何值`nums`划分`3`。 幼稚的实现可能会意外返回错误的删除计数或假设某些子集有效。 我们的算法安全地扫描每个候选人并返回`-1`当没有人划分 GCD 时。 

最后，GCD 等于的情况`1`值得关注。 由于仅`1`划分`1`， 如果`nums`不包含`1`，答案一定是`-1`。 我们的实现自然会处理这个问题，因为只有`1`通过可分性检查`gcd_value % num == 0`当 GCD 为`1`。
