[LeetCode 第 2356 题](https://leetcode.com/problems/number-of-unique-subjects-taught-by-each-teacher/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题需要计算大学中每位教师教授的**独特科目的数量，给定一个将教师映射到科目和院系的表格。 中的每一行`Teacher`表代表教师、学科和部门的特定组合。 一个老师可能会在多个系教授同一科目，但对于这个问题，我们只关心**每个老师对每个科目计数一次**，而与系无关。 

输入是一个 SQL 表`Teacher`三列：`teacher_id`,`subject_id`， 和`dept_id`。 主键是`(subject_id, dept_id)`，这意味着同一系中任何两行都不能有相同的科目，但多个教师可以在不同系中教授同一科目。 

预期输出是一个包含两列的表：`teacher_id`和`cnt`， 在哪里`cnt`代表教师教授的**独特科目**的数量。 行的顺序并不重要。 

重要的边缘考虑因素包括跨多个系教授多个科目的教师、仅教授一门科目的教师，以及同一教师的重复科目系条目每个科目只能计算一次。 

## 方法

 ### 蛮力

 一个天真的方法是迭代整个`Teacher`表，并为每位教师维护他们所教授的所有科目的列表。 处理完所有行后，从每位教师的科目列表中删除重复项，然后计算唯一科目的数量。 这是有效的，因为我们明确地计算不同的主题，但它效率低下，因为它需要额外的数据结构来存储所有主题，并可能重复扫描重复项。 

### 最佳方法

 最佳方法利用 SQL`COUNT(DISTINCT ...)`聚合函数。 我们可以分组，而不是手动删除重复项或逐行迭代`teacher_id`并直接计算唯一的数量`subject_id`为每位老师。 这是高效的，因为 SQL 引擎针对不同值的分组和计数进行了优化。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 迭代表、将主题存储在列表中、删除重复项 |
 | 最佳 | O(n) | O(n) | 使用SQL`GROUP BY`和`COUNT(DISTINCT subject_id)`有效地计算结果 |

 ## 算法演练

 1. **按教师分组**：我们需要处理每个教师的数据。 SQL`GROUP BY teacher_id`允许对每位教师进行聚合。 
2. **计算独特的主题**：在每组中，计算不同主题的数量`subject_id`使用`COUNT(DISTINCT subject_id)`。 这可确保多个部门中重复的主题条目仅计算一次。 
3. **返回结果**：输出两列：`teacher_id`计算出的计数为`cnt`。 SQL 将处理排序； 由于该问题允许任何顺序，因此我们不需要明确的`ORDER BY`。 

**为什么它有效**：`GROUP BY`确保每位教师都得到独立考虑，并且`COUNT(DISTINCT subject_id)`保证跨部门重复的科目只计算一次。 因此，每个教师的行正确地反映了他们所教授的独特科目的数量。 

## Python 解决方案

 由于这是一个数据库问题，Python 解决方案通常会使用 ORM 或执行原始 SQL。 以下是通过 Python 使用 SQLite 的示例：```python
import sqlite3
from typing import List, Tuple

def number_of_unique_subjects_teachers(conn: sqlite3.Connection) -> List[Tuple[int, int]]:
    query = """
    SELECT teacher_id, COUNT(DISTINCT subject_id) AS cnt
    FROM Teacher
    GROUP BY teacher_id
    """
    cursor = conn.cursor()
    cursor.execute(query)
    result = cursor.fetchall()
    return result
```**说明**：Python代码执行算法中描述的SQL查询。 查询按以下方式对行进行分组`teacher_id`并使用 SQL 对不同主题进行计数`COUNT(DISTINCT subject_id)`。 结果以元组列表的形式获取并返回，其中每个元组包含一个教师 ID 及其唯一的科目数。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
    "log"
)

type TeacherCount struct {
    TeacherID int
    Count     int
}

func NumberOfUniqueSubjectsTeachers(db *sql.DB) ([]TeacherCount, error) {
    query := `
    SELECT teacher_id, COUNT(DISTINCT subject_id) AS cnt
    FROM Teacher
    GROUP BY teacher_id
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var results []TeacherCount
    for rows.Next() {
        var t TeacherCount
        if err := rows.Scan(&t.TeacherID, &t.Count); err != nil {
            return nil, err
        }
        results = append(results, t)
    }
    return results, nil
}
```**Go Notes**：此 Go 解决方案镜像了 Python 解决方案，但使用了 Go 的`database/sql`包裹。 我们定义一个结构体`TeacherCount`来存储结果。 这`rows.Next()`迭代获取每一行，并且`rows.Scan()`提取教师 ID 和计数。 Go 手柄`nil`优雅地返回值和空结果，如果不存在行则返回空切片。

 ## 边缘情况

 **边缘情况 1：没有科目的教师**

 如果系统中存在教师但没有分配科目，SQL`GROUP BY`自然就会排除他们。 该实现正确地仅返回至少具有一门科目的教师。 

**边缘情况 2：重复的学科系条目**

 主键保证没有重复的主题部门行。 这可以防止过度计数。 计算不同的主题仍然可以稳健地处理任何重复项。 

**边缘情况 3：大型数据集**

 该解决方案拥有数千名教师和科目，利用 SQL 引擎的优化聚合。 Python 和 Go 实现都依赖数据库进行计算，确保可扩展性，而无需将所有行加载到应用程序内存中。
