[LeetCode 问题 2390](https://leetcode.com/problems/removing-stars-from-a-string/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们重复处理一个包含小写英文字母和星号字符的字符串（`*`）。 每颗星代表一次移除操作。 当我们遇到星星时，我们必须去掉两件事：

 1. 恒星本身。 
2. 紧邻其左侧的最近的非明星字符。 

我们继续这个过程，直到所有星星都被移除。 最终结果是应用每次删除操作后剩余的字符串。 

思考这个问题的另一种方式是，每个星星的行为都像“删除前一个字符”指令。 如果我们从左到右扫描字符串，每个普通字符都会添加到结果中，而每个星号会删除最近添加的字符。 

输入由单个字符串组成`s`，其长度可以大到`10^5`。 该字符串包含小写英文字母和星号。 输出是一个新字符串，表示所有星型操作完成后剩下的内容。 

约束在这里很重要。 由于字符串长度可能达到`100,000`，我们需要一个有效的解决方案。 任何重复重建字符串或向后扫描每颗恒星的方法都可能变得太慢。 二次时间解将难以达到上限。 

一些边缘情况值得预先考虑。 字符串可能包含许多连续的星号，这意味着必须按顺序删除先前添加的多个字符。 整个字符串可能会消失，产生空结果。 如果左边没有可移动的字符，星形永远不会出现，因为该问题保证每个操作都是有效的。 这种保证简化了实施，因为我们不需要对无效删除进行防御性检查。 

## 方法

 ### 蛮力方法

 一种简单的方法是完全按照描述模拟移除。 每次遇到星号时，我们都会向左搜索以找到最近的非星号字符，删除该字符和星号，然后重建字符串。 

例如，与`"leet**cod*e"`：

- 消除`t`和第一个`*`- 消除`e`和第二个`*`- 消除`d`和决赛`*`这种方法是正确的，因为它从字面上遵循问题陈述。 然而，它的效率很低。 每个星号可能需要向后扫描字符串，并且重复从字符串中删除字符的成本很高，因为字符串在许多语言中是不可变的。 

在最坏的情况下，例如有多次删除的长字符串，这种重复扫描和重建会导致`O(n²)`时间复杂度。 

### 最优方法，堆栈模拟

 关键的见解是，每个星星总是删除尚未删除的**最近的有效字符**。 

这种行为自然与**堆栈**相匹配。 堆栈遵循后进先出原则：

 - 当我们看到一个普通字符时，我们将其压入堆栈。 
- 当我们看到一颗星星时，我们通过从堆栈中弹出来删除最近添加的字符。 

在遍历结束时，堆栈恰好包含所有删除后仍然存在的字符。 我们只需将它们连接到最终的字符串中即可。 

这可以有效地工作，因为每个字符最多被推送一次并最多弹出一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复扫描并重建字符串 |
 | 最佳 | O(n) | O(n) | 使用堆栈有效地模拟移除 |

 ## 算法演练

 1. 初始化一个空堆栈。 

堆栈将存储当前属于结果字符串的字符。 我们选择堆栈是因为每个星都会删除最近添加的有效字符。 
2. 从左到右遍历字符串。 

我们一次处理一个字符，以便按照自然顺序模拟操作。 
3. 如果当前字符是字母，则将其压入堆栈。 

这意味着该字符当前是幸存字符串的一部分，除非稍后被星号删除。 
4. 如果当前角色是星星（`*`)，从堆栈中弹出顶部字符。 

堆栈顶部表示最靠近左侧且尚未删除的非星号字符。 这个问题保证了这样的角色永远存在。 
5. 继续，直到处理完整个字符串。 

至此，所有移除均已模拟。 
6. 将堆栈中的所有字符连接成一个字符串。 

堆栈现在包含按正确顺序排列的最后剩余字符。 

### 为什么它有效

 该算法保持了一个重要的不变量：在处理完第一个`i`字符，堆栈恰好包含在应用这些字符中的所有星号删除后保留的结果字符串`i`人物。 

当我们遇到一个普通字符时，将其添加到堆栈中与将其附加到不断变化的字符串相匹配。 当我们遇到星号时，删除堆栈顶部匹配会删除左侧最接近的幸存非星号字符。 由于每个操作都是正确且按顺序模拟的，因此最终堆栈必须等于唯一的最终答案。 

## Python 解决方案```python
class Solution:
    def removeStars(self, s: str) -> str:
        stack: list[str] = []

        for char in s:
            if char == "*":
                stack.pop()
            else:
                stack.append(char)

        return "".join(stack)
```实现直接遵循算法。 我们首先创建一个名为的空列表`stack`。 In Python, a list works efficiently as a stack because`append()`和`pop()`从最后开始，两者都以恒定的时间运行。 

我们迭代输入字符串中的每个字符。 如果该角色是星星，我们使用以下命令删除最近添加的角色`pop()`。 否则，我们将字符追加到堆栈中。 

遍历完成后，堆栈中仅按顺序包含幸存的字符。 由于堆栈是单个字符的列表，因此我们使用`"".join(stack)`有效地构建最终的字符串。 

实现很简洁，因为问题保证确保每个星操作都是有效的，这意味着`pop()`永远不会在空堆栈上调用。 

## 解决方案```go
func removeStars(s string) string {
	stack := make([]byte, 0, len(s))

	for i := 0; i < len(s); i++ {
		if s[i] == '*' {
			stack = stack[:len(stack)-1]
		} else {
			stack = append(stack, s[i])
		}
	}

	return string(stack)
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用字节切片作为堆栈。 由于输入仅包含小写英文字母并且`*`， 使用`[]byte`效率很高并且避免了不必要的字符串操作。 

而不是`pop()`，Go 使用切片截断删除最后一个元素：```go
stack = stack[:len(stack)-1]
```附加字符使用`append()`，最后的字节片使用以下命令转换回字符串`string(stack)`。 

与 Python 不同，Go 字符串是不可变的字节序列，因此使用可变切片是有效实现堆栈行为的自然方法。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符处理一次，每个字符最多压入和弹出一次 |
 | 空间| O(n) | 在最坏的情况下，堆栈存储所有字符 |

 时间复杂度是线性的，因为我们只遍历字符串一次。 尽管发生了弹出操作，但每个字符只能移除一次，因此总工作量仍与`n`。 

空间复杂度为`O(n)`因为，在没有星星的最坏情况下，所有字符都会保留在堆栈中。

 ## 边缘情况

 ### 整个字符串被删除

 像这样的输入`"erase*****"`删除每个字符。 有缺陷的实现可能会错误地留下残留字符，或者在堆栈变空时失败。 我们的实现自然地处理了这个问题，因为每个星号恰好删除了一个字符，并且最终的连接操作正确地生成了一个空字符串。 

### 连续星星

 输入如`"ab**c"`包含多个连续的星星。 如果未正确跟踪先前的删除，幼稚的实现可能会意外删除错误的字符。 堆栈结构干净地解决了这个问题，因为每个`pop()`总是删除最近幸存的字符。 

### 没有星星在场

 像这样的输入`"abcdef"`不包含删除操作。 某些实现可能会使逻辑过于复杂或意外修改字符串。 在我们的解决方案中，每个字符都被简单地推入堆栈并原样返回。 

### 非常大的输入

 自从`s.length`可以大到`100,000`，低效的字符串重建可能会成为性能问题。 在最坏的输入情况下，二次解可能会超时。 我们基于堆栈的方法处理每个字符一次，使其对于最大约束大小而言足够高效。
