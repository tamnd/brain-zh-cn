 **难度：** 🟡 中等
 **主题：** 数组、字符串、分而治之、排序、堆（优先级队列）、基数排序、快速选择

 ## 解决方案

 ## 问题理解

 该问题提供了一个表示为字符串的数字列表，所有数字的长度都相等。 任务是回答多个查询，其中每个查询在将列表中的每个数字修剪到最后一个数字后，都要求**第 k 个最小数字**的索引`trimi`数字。 重要的是，如果两个修剪后的数字相等，则**原始索引较低**的数字被认为较小。 每次查询后，数字必须重置为其原始形式以供下一次查询。 

输入由一个列表组成`nums`仅包含数字的字符串，长度最多为 100，以及一个查询列表，每个查询都有一个`k`值和修剪长度。 预期输出是与每个查询结果对应的索引列表。 

关键点是：从**右侧**开始修剪，**按字典顺序**进行数字比较，维护**原始索引**以打破平局，以及有效处理多个查询。 潜在的边缘情况包括带有前导零的数字、请求完整数字而不进行修剪的查询以及多个相同的修剪数字。 

## 方法

 暴力方法很简单：对于每个查询，修剪列表中的每个数字，对修剪后的数字进行排序，同时跟踪原始索引，然后选择第 k 个最小的数字。 这种方法有效，但效率可能较低，因为它需要对每个查询进行独立排序。 

最佳方法利用**按修剪长度进行预处理**。 我们可以存储每个可能的修剪长度的修剪数字并对它们进行一次排序，然后使用预先计算的结果在**恒定时间**中回答每个查询。 这减少了冗余计算，并使我们能够有效地处理多个查询。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(Q * N log N) | O(Q * N log N) | O(N) | 独立地对每个查询进行修剪和排序 |
 | 最佳| O(N * L + Q) | O(N * L) | 预先计算所有修剪长度的排序索引，然后快速回答查询 |

 这里，N是数字的数量，L是每个数字的长度，Q是查询的数量。 

## 算法演练

 1. 根据数字的长度确定最大可能的修剪长度。 
2. 为从 1 到全长的每个可能的修剪长度预先计算 **修剪数字**。 
3. 对于每个修剪长度，将每个修剪后的数字与其原始索引配对，并按**字典顺序**对列表进行排序，按索引打破平局。 
4. 仅将每个修剪长度的**排序索引**存储在字典或数组中，以便快速查找。 
5. 对于每个查询`[k, trim]`，检索给定修剪长度的预先计算的排序索引并选择`(k-1)`-th 索引作为答案。 
6. 将所有查询结果收集到最终答案列表中并返回。 

为什么有效：用原始索引对修剪后的数字进行排序可确保正确断开平局。 对所有修剪长度进行预计算，避免了相同修剪长度查询的冗余计算，保证了正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def smallestTrimmedNumbers(self, nums: List[str], queries: List[List[int]]) -> List[int]:
        n = len(nums)
        l = len(nums[0])
        trimmed_indices = {}
        
        # Precompute sorted indices for each trim length
        for trim in range(1, l + 1):
            trimmed_list = [(num[-trim:], idx) for idx, num in enumerate(nums)]
            trimmed_list.sort()  # Sorts by string first, then index due to tuple ordering
            trimmed_indices[trim] = [idx for _, idx in trimmed_list]
        
        answer = []
        for k, trim in queries:
            answer.append(trimmed_indices[trim][k-1])
        
        return answer
```这个 Python 实现首先为每个可能的修剪长度预先计算排序索引。 每个修剪后的号码都与其原始索引配对，确保平局决胜正确。 排序后，仅存储索引以实现快速查询响应。 每个查询只是查找适当的预先计算的列表并检索第 k 个最小的索引。 

## 解决方案```go
import (
    "sort"
    "strconv"
)

func smallestTrimmedNumbers(nums []string, queries [][]int) []int {
    n := len(nums)
    l := len(nums[0])
    
    trimmedIndices := make(map[int][]int)
    
    // Precompute sorted indices for each trim length
    for trim := 1; trim <= l; trim++ {
        type pair struct {
            val string
            idx int
        }
        trimmedList := make([]pair, n)
        for i, num := range nums {
            trimmedList[i] = pair{num[len(num)-trim:], i}
        }
        sort.Slice(trimmedList, func(i, j int) bool {
            if trimmedList[i].val == trimmedList[j].val {
                return trimmedList[i].idx < trimmedList[j].idx
            }
            return trimmedList[i].val < trimmedList[j].val
        })
        sortedIdx := make([]int, n)
        for i, p := range trimmedList {
            sortedIdx[i] = p.idx
        }
        trimmedIndices[trim] = sortedIdx
    }
    
    answer := make([]int, len(queries))
    for i, q := range queries {
        k, trim := q[0], q[1]
        answer[i] = trimmedIndices[trim][k-1]
    }
    
    return answer
}
```在 Go 中，解决方案是类似的。 主要区别包括使用结构来配对值和索引，以及`sort.Slice`用于自定义排序。 映射按修剪长度存储预先计算的排序索引，然后访问这些索引以有效地回答查询。

 ## 边缘情况

 **前导零**：像“001”这样的数字必须保留修剪规则和正确的比较。 该实现使用字符串比较，它可以正确处理前导零。 

**单元素列表**：对单元素数组的查询应始终返回索引 0。该解决方案自然会处理此问题，因为对一个元素进行排序是微不足道的。 

**按索引决胜**：当多个修剪号码相同时，应选择**原始索引较小**的号码。 通过存储对`(trimmed_number, index)`以及对元组进行排序，实现会自动遵守此规则。
