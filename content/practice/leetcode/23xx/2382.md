[LeetCode 问题 2382](https://leetcode.com/problems/maximum-segment-sum-after-removals/)

 **难度：** 🔴难
 **主题：** 数组、并查、前缀和、有序集

 ## 解决方案

 ## 问题理解

 问题给了我们两个数组，`nums`和`removeQueries`, 两者的长度`n`。 

这`nums`数组包含正整数。 最初，所有元素都存在，形成一个连续的片段。 然后，按照定义的顺序，将元素一一删除`removeQueries`。 

每次删除后，数组都会分为一个或多个剩余正整数的连续段。 删除的元素实际上充当分隔符。 对于每个删除操作，我们必须确定所有当前有效的连续段中的**最大段总和**。 

目标是返回一个数组`answer`， 在哪里`answer[i]`表示执行后最大的段和`i-th`移动。 

为了更清楚地理解这个过程，假设我们删除现有段中间的一个元素。 该部分分为两个较小的部分。 如果我们删除边缘处的元素，该段就会缩小。 每次这样的修改之后，我们必须有效地确定哪个剩余段具有最大的总和。 

约束是选择算法最重要的线索：

 -`n`可以大到`10^5`-`nums[i]`可以大到`10^9`- 所有去除指数都是唯一的

 每次删除后进行直接模拟的成本太高，因为重复重新计算段总和可能会导致二次复杂度。 

一个重要的观察结果是所有数字都是**正**。 这意味着较大的段总是具有较大或相等的总和，并且可以增量地维护段总和，而不必担心负值会减少总数。 

有几种边缘情况需要记住：

 - 当所有元素都被移除后，答案一定会变成`0`因为没有剩下任何片段。 
- 从段的开头或结尾删除的行为与从中间删除的行为不同。 
- 单个剩余元素本身形成有效段。 
- 自从`nums[i]`可以达到`10^9`，段和可能会超过 32 位整数限制，因此我们必须使用 64 位整数。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是直接模拟移除过程。 

每次删除后：

 1. 标记已删除的索引。 
2. 从左到右扫描整个数组。 
3. 识别未删除元素的连续段。 
4. 计算每个段的总和。 
5. 跟踪最大段总和。 

这种方法之所以有效，是因为它完全遵循问题定义。 每个查询都会重新计算数组的当前状态并评估所有段。 

然而，它太慢了。 

对于每次删除，我们可以扫描整个长度的数组`n`。 由于有`n`删除，总复杂度变为`O(n²)`。 

和`n = 10^5`，这可能需要大约`10^10`的操作，远远超出了实际的限制。 

### 最佳方法的关键见解

 困难的部分是**删除元素会分割段**，这很难有效维护。 

我们可以**向后**，而不是向前思考。 

我们可以从一个空数组开始，然后**以相反的顺序添加元素**，而不是一次删除一个元素。 

这将困难的拆分问题转化为更容易的**合并问题**。 

为什么合并更容易？ 

当我们重新添加一个元素时：

 - 它作为一个新的段开始。 
- 如果它的左邻居存在，我们与左段合并。 
- 如果它的右邻居存在，我们与右段合并。 

高效合并正是**Union-Find（不相交集并集，DSU）**的设计目的。 

我们维持：

 - A`parent`DSU 结构数组
 - A`segment_sum`数组存储每个分量的总和
 - 安`active`数组来跟踪索引是否存在
 - 跑步`max_segment_sum`在每个反向步骤中：

 1. 将元素添加回来。 
2. 合并相邻的活动组件。 
3. 更新最大分段总和。 

由于每个并集和查找操作的时间几乎恒定，因此该解决方案变得足够高效`10^5`元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n²)`|`O(n)`| 每次删除后重新计算所有段 |
 | 最佳|`O(n α(n))`|`O(n)`| 使用 Union-Find 合并进行逆向处理 |

 这里，`α(n)`是阿克曼反函数，它的增长速度非常缓慢，以至于在实践中它的表现就像一个常数。 

## 算法演练

 ### 使用逆向处理+并查的最优算法

 1.用size初始化答案数组`n`。 

我们将以相反的顺序填充它，因为我们正在处理添加而不是删除。 
2. 创建并查结构。 

我们维持：

 -`parent[i]`, 代表一个组件
 -`segment_sum[i]`，以根为根的连接分量的总和`i`-`active[i]`, 是否索引`i`目前存在

 最初，所有元素都是不活动的，因为我们从完全删除的数组开始。 
3. 维护一个变量`max_sum`。 

这存储当前存在的最大段总和。 

最初：```
max_sum = 0
```因为不存在任何段。 
4. 流程`removeQueries`以相反的顺序。 

在恢复元素之前，记录当前元素`max_sum`到答案数组中。 

为什么？ 

因为反转删除意味着当前状态与原始顺序中_删除后_的数组完全对应。 
5. 激活当前索引。 

让：```
idx = removeQueries[i]
```将其标记为活动并初始化：```
segment_sum[idx] = nums[idx]
parent[idx] = idx
```这形成单元件段。 
6. 检查左邻居。 

如果`idx - 1`存在并且处于活动状态，合并两个组件。 

这恢复了相邻元素之间的连续性。 
7. 检查右邻居。 

如果`idx + 1`存在并且处于活动状态，再次合并。 

这可确保增量重建更大的段。 
8. 更新最大段总和。 

合并后，检索根并更新：```
max_sum = max(max_sum, component_sum)
```9. 继续，直到所有元素都恢复。 

由于我们进行了反向处理，答案数组已经包含了正确顺序的结果。 

### 为什么它有效

 关键的不变量是在处理反向步骤之后`i`，并查结构准确地表示了合并后的数组状态`i-th`按原来的顺序删除。 

处理删除直接导致段分裂，难以高效维护。 通过反转该过程，每个操作都成为相邻段之间的合并，Union-Find 自然可以处理这一点。 

因为每次合并都会保留精确的段总和`max_sum`总是存储最大的连通分量和，算法总是产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumSegmentSum(
        self,
        nums: List[int],
        removeQueries: List[int]
    ) -> List[int]:
        n = len(nums)

        parent = list(range(n))
        segment_sum = [0] * n
        active = [False] * n
        answer = [0] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(x: int, y: int) -> int:
            root_x = find(x)
            root_y = find(y)

            if root_x == root_y:
                return root_x

            parent[root_y] = root_x
            segment_sum[root_x] += segment_sum[root_y]

            return root_x

        max_sum = 0

        for i in range(n - 1, -1, -1):
            answer[i] = max_sum

            index = removeQueries[i]

            active[index] = True
            segment_sum[index] = nums[index]

            if index > 0 and active[index - 1]:
                union(index, index - 1)

            if index < n - 1 and active[index + 1]:
                union(index, index + 1)

            root = find(index)
            max_sum = max(max_sum, segment_sum[root])

        return answer
```实现严格遵循算法。 

我们首先初始化并查数据结构。 这`parent`数组存储组件代表，而`segment_sum`跟踪每个连接段的总和。 

这`find`函数使用路径压缩通过展平树结构来加速未来的查找。 

这`union`函数合并两个相邻组件并更新组合的段和。 由于我们只关心总和，因此我们只需将一个根附加到另一个根上即可。 

主循环流程`removeQueries`相反。 在恢复元素之前，我们将当前最大段和存储到`answer[i]`。 这对应于原始序列中移除后的阵列状态。 

每个恢复的索引都以一个单元素段开始。 然后，我们与活动邻居合并（如果存在），重建正确的段结构，并更新运行最大值。 

最后，我们返回完整的答案数组。 

## 解决方案```go
func maximumSegmentSum(nums []int, removeQueries []int) []int64 {
	n := len(nums)

	parent := make([]int, n)
	segmentSum := make([]int64, n)
	active := make([]bool, n)
	answer := make([]int64, n)

	for i := 0; i < n; i++ {
		parent[i] = i
	}

	var find func(int) int
	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}

	union := func(x, y int) int {
		rootX := find(x)
		rootY := find(y)

		if rootX == rootY {
			return rootX
		}

		parent[rootY] = rootX
		segmentSum[rootX] += segmentSum[rootY]

		return rootX
	}

	var maxSum int64 = 0

	for i := n - 1; i >= 0; i-- {
		answer[i] = maxSum

		index := removeQueries[i]

		active[index] = true
		segmentSum[index] = int64(nums[index])

		if index > 0 && active[index-1] {
			union(index, index-1)
		}

		if index < n-1 && active[index+1] {
			union(index, index+1)
		}

		root := find(index)
		if segmentSum[root] > maxSum {
			maxSum = segmentSum[root]
		}
	}

	return answer
}
```Go 实现与 Python 版本非常相似，但存在一些特定于语言的差异。 

最大的区别是整数处理。 由于段总和可能超过 32 位限制，我们使用`int64`为了`segmentSum`,`maxSum`，以及返回类型。 

Go还使用切片而不是Python列表，并且使用递归来进行路径压缩`find`。 

与 Python 不同，Go 没有内置的任意精度整数，因此使用`int64`是避免溢出所必需的。

 ## 边缘情况

 ### 单元素数组

 当`n = 1`，删除唯一的元素不会留下任何段。 

这种情况很容易处理不当，因为某些实现假设存在相邻元素。 我们的实现在尝试联合之前安全地检查边界，因此不会发生无效访问。 

例子：```
nums = [5]
removeQueries = [0]
```输出：```
[0]
```### 删除分割大段的元素

 删除段中间的元素会创建两个断开连接的部分。 

正向模拟必须仔细维护分割段，这很容易出错。 我们的逆向处理方法完全避免了分裂。 相反，仅合并段，Union-Find 可以有效地处理这一点。 

例子：```
nums = [10,20,30]
removeQueries = [1,0,2]
```正在删除索引`1`分裂`[10,20,30]`进入`[10]`和`[30]`。 

### 非常大的数字

 自从`nums[i]`可以是`10^9`并且可能有`10^5`元素，总段和可以达到：```
10^14
```这超出了 32 位整数限制。 

该实现通过使用 Python 的任意精度整数来正确处理这个问题`int64`在围棋中。 这可以防止溢出并确保大输入的正确结果。
