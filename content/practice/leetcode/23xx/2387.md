 # LeetCode 2387.按行排序矩阵的中值

 ## 问题理解

 我们被赋予了一个`m × n`矩阵`grid`其中每一行都已按非降序排序。 矩阵中元素的总数保证为奇数，因为`m`和`n`很奇怪。 

任务是找到矩阵中包含的所有值的中位数。 

如果我们从概念上将矩阵展平为单个列表并对所有元素进行排序，则中位数就是中间元素。 由于元素总数为奇数，因此只有一个中间位置。 

例如：```
[[1,1,2],
 [2,3,3],
 [1,3,4]]
```包含：```
1,1,2,2,3,3,1,3,4
```排序后：```
1,1,1,2,2,3,3,3,4
```中间的元素是`2`，所以答案是`2`。 

重要的挑战是时间复杂度要求。 一个简单的解决方案是收集每个值，对它们进行排序，然后返回中间元素。 然而，这至少需要`O(m * n log(m * n))`时间，这违反了解决方案速度快于的要求`O(m * n)`。

 ## 方法

 ### 蛮力方法

 最直接的解决方案是将矩阵压平为单个数组，对数组进行排序，然后返回中间元素。 

由于有`m * n`元素，排序需要：```
O((m*n) log(m*n))
```时间。 

这种方法是正确的，因为对所有元素进行显式排序给出了它们的确切顺序，使得选择中位数变得很简单。 

然而，该问题特别要求比以下更快的解决方案`O(m*n)`，因此对所有元素进行排序是不可接受的。 

### 关键见解

 请注意，每一行都已排序。 

我们可以搜索中位数的值，而不是搜索索引中中位数的位置。 

假设我们猜测一个值`x`。 

我们可以有效地计算有多少个矩阵元素小于或等于`x`。 

由于每行都已排序，因此可以通过每行内部的二分查找来获得此计数。 

这给了我们一个单调属性：

 - 如果元素太少`≤ x`，那么中位数一定更大。 
- 如果有足够的元素`≤ x`，那么中位数最多为`x`。 

这种单调行为使我们能够对值范围而不是矩阵位置执行二分搜索。 

由于值介于`1`和`10^6`，值空间二分搜索非常有效。 
最直接的解决方案是将矩阵展平为单个数组，对其进行排序，然后返回中间元素。 

我们迭代每一行并将所有元素附加到一个列表中。 对列表进行排序后，中位数就是中间的元素。 

这是有效的，因为排序会产生矩阵中所有元素的精确全局排序。 

然而，这种方法对于预期的限制来说太慢了。 如果有`k = m * n`元素，排序需要：```
O(k log k)
```高达`250000`元素，这变得比必要的要昂贵得多。 

### 最佳方法

 重要的见解是我们实际上不需要对矩阵进行完全排序。 我们只需要确定哪个值是中位数。 

由于每行都已排序，因此我们可以有效地计算有多少元素小于或等于所选值`x`。 

对于任何候选人号码`x`:

 - 如果少于一半的元素`<= x`，那么中位数一定更大
 - 否则，中位数小于或等于`x`这创建了一个单调条件，允许对值范围而不是索引进行二分搜索。 

我们在最小可能矩阵值和最大可能矩阵值之间进行二分搜索。 对于每个中点：

 - 在每一行中使用二分搜索来计算元素数量`<= mid`- 将计数与所需的中间位置进行比较
 - 相应地缩小搜索空间

 正在排序的行使得这种方式变得高效。

```2. 计算目标中位位置。

```4. 计数小于或等于的元素`mid`。 

因为每一行都已排序，所以我们可以在每一行内使用二分搜索。 

在Python中，`bisect_right(row, mid)`返回元素的数量`<= mid`。 

将所有行的总和得出总计数。 
5. 决定保留哪一半。

 该算法依赖于单调性。

中位数是元素计数的最小值`<= value`超过矩阵大小的一半。 二分查找正确地识别了这个边界。 

## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def matrixMedian(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        low = min(row[0] for row in grid)
        high = max(row[-1] for row in grid)

        target = (rows * cols) // 2

        target = (rows * cols) // 2

        low = min(row[0] for row in grid)
        high = max(row[-1] for row in grid)

        while low < high:
            mid = (low + high) // 2

            count = 0

            for row in grid:
                count += bisect_right(row, mid)

            if count <= target:
                low = mid + 1
            else:
                high = mid

        return low
```### 实现说明

变量`target`存储中值索引：```
(rows * cols) // 2

## 解决方案```go
package main

import "sort"

func matrixMedian(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	target := (rows * cols) / 2

	low := grid[0][0]
	high := grid[0][cols-1]

	for _, row := range grid {
		if row[0] < low {
			low = row[0]
		}

		if row[cols-1] > high {
			high = row[cols-1]
		}
	}

	target := (rows * cols) / 2

	for low < high {
		mid := low + (high-low)/2

		count := 0

		for _, row := range grid {
			count += sort.SearchInts(row, mid+1)
		}

		if count <= target {
			low = mid + 1
		} else {
			high = mid
		}
	}

	return low
}
```### Go 特定注释

 Go 没有提供与 Python 直接等效的功能`bisect_right`， 但`sort.SearchInts(row, mid+1)`产生相同的结果。 它返回第一个位置`mid + 1`可以插入，这恰好是小于或等于的元素数`mid`。 

二分查找中点计算如下：
 Go 的实现与 Python 解决方案非常相似。 

主要区别在于使用`sort.SearchInts`而不是`bisect_right`。```go
sort.SearchInts(row, mid+1)
```返回插入位置`mid + 1`，相当于对元素进行计数`<= mid`。 

仔细计算二分查找中点：```go

```这避免了潜在的整数溢出，尽管在给定的约束下溢出不是一个实际问题。 
这可以避免整数具有固定大小的语言中潜在的整数溢出。

## Edge Cases

### Single Element Matrix

A matrix containing only one value is the smallest valid input. A naive implementation might assume multiple rows or columns exist and accidentally access invalid indices. The algorithm handles this naturally because `low` and `high` are initialized to the same value, causing the binary search loop to terminate immediately and return that element.

### Large Number of Duplicate Values

Many matrices contain repeated values, including cases where the median appears several times. An incorrect implementation might search for the first occurrence or a specific index rather than the median value itself. Using `bisect_right` counts every occurrence of a value correctly, ensuring duplicates are handled exactly.

### Single Row or Single Column

When `m = 1` or `n = 1`, the matrix effectively becomes a sorted array. Some matrix-specific algorithms can fail because they assume multiple rows and columns. This solution still works because every count operation is performed row by row, and binary search within a row remains valid regardless of how many rows exist.

### Extremely Large Value Range

Values may range from `1` to `10^6`. Searching directly among all possible values could appear expensive, but binary search reduces the number of iterations to roughly `log2(10^6) ≈ 20`. Therefore the algorithm remains efficient even when the minimum and maximum values are very far apart.

### Median Appearing Multiple Times

The median value may occupy several consecutive positions in the sorted order. The algorithm searches for the smallest value whose cumulative count exceeds half of the elements. This lower-bound behavior guarantees that the correct median value is returned even when many equal values surround the median position.

 ## 边缘情况

 一种重要的边缘情况是只有一个元素的矩阵。 在这种情况下，该单一值就是中位数。 某些实现意外地假设存在多行或多列，这可能会导致索引错误。 此实现可以自然地处理这种情况，因为二分搜索范围立即变成单个值。 

另一个重要的情况是所有矩阵值都相同。 例如：```
[
  [7,7,7],
  [7,7,7],
  [7,7,7]
]
```如果边界未正确更新，则实施不佳的二分搜索可能会陷入无限循环。 在此解决方案中，搜索安全地收敛，因为每次迭代的间隔都会缩小。 

重复矩阵过多是错误的另一个常见来源。 考虑：```
[
  [1,2,2],
  [2,2,3],
  [3,3,4]
]
```中值出现多次。 使用`bisect_left`而不是`bisect_right`会产生不正确的计数，因为我们特别需要元素的数量`<= mid`。 该实现正确地使用了上限样式二分搜索。 

单列矩阵也很重要：```
[
  [1],
  [2],
  [3]
]
```即使每一行的长度为一，该算法仍然有效，因为单元素行上的二分搜索仍然有效。 该实现不依赖于具有多个元素的行。 

最后，中位数位于数值极值附近的矩阵测试值空间二分搜索的正确性。 由于该算法搜索实际值而不是索引，因此它可以正确处理允许范围内的任何值`10^6`。
