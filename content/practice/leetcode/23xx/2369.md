 # LeetCode 2369 - 检查是否有有效分区

 ## 问题理解

 问题给了我们一个整数数组`nums`，并且我们必须确定是否可以将数组分成连续的组，以便每个组都满足三个有效模式之一。 

有效的组可以是：

 1. 恰好两个相等的数，例如`[5,5]`2. 恰好三个相等的数，例如`[7,7,7]`3. 恰好三个连续递增的数字，例如`[3,4,5]`分区必须覆盖整个阵列，没有间隙，也没有重叠。 每个元素必须恰好属于一个有效的子数组。 

重要的细节是子数组必须是连续的。 我们无法重新排列元素或跳过元素。 我们只能将原始数组分割成连续的块。 

输出应该是：

 -`true`如果至少存在一个有效分区
 -`false`否则

 限制条件很大：

 -`2 <= nums.length <= 10^5`-`1 <= nums[i] <= 10^6`由于数组长度可以达到十万，指数或二次解不实用。 我们需要一种接近线性时间的算法。 

一些边缘情况很重要：

 - 长度数组`2`仅当两个元素相等时才有效。 
- 长度数组`3`可以满足“全部相等”条件或“连续递增”条件。 
- 本地有效的组可能会导致全局无效的分区。 例如，贪婪地获取第一个有效段并不总是有效。 
- 某些数组包含多个有效的分区路径，因此算法必须有效地探索可能性。 
- 具有无法形成有效组的剩余元素的数组必须正确返回`false`。 

## 方法

 ### 蛮力方法

 一种简单的方法是递归地尝试每个可能的分区。 

从索引开始`0`，我们可以尝试：

 - 如果接下来的两个元素相等，则取它们
 - 如果接下来的三个元素相等，则取它们
 - 如果接下来的三个元素形成连续递增的值，则取它们

 对于每个有效的选择，我们从下一个索引递归地继续。 

这种暴力解决方案是正确的，因为它探索了每个可能的有效分区。 如果任何递归路径成功到达数组末尾，则存在有效分区。 

然而，这种方法非常慢，因为许多子问题重复出现。 例如，多个递归路径可能会反复询问后缀是否从index开始`i`可以分区。 在最坏的情况下，递归树呈指数增长。 

和`n = 10^5`，指数复杂度不可能在时间限制内运行。 

### 最优动态规划方法

 关键的观察是分区的有效性仅取决于较早的位置。 

假设我们定义：

 -`dp[i] = true`如果第一个`i`元素可以形成有效的分区

 然后，计算`dp[i]`，我们只需要检查最后一个有效组是否以位置结束`i - 1`满足允许的模式之一。 

只有三种可能：

 1. 最后两个元素相等，并且`dp[i - 2]`是真的
 2. 最后三个元素相等，并且`dp[i - 3]`是真的
 3. The last three elements are consecutive increasing, and`dp[i - 3]`是真的

 Since each position only checks a constant number of previous states, the algorithm runs in linear time.

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | Recursively explores all partition combinations |
 | 最优动态规划| O(n) | O(n) | Uses previous computed states to avoid repeated work |

 ## 算法演练

 1.创建布尔DP数组`dp`尺寸的`n + 1`。 

的含义`dp[i]`是是否第一个`i`的元素`nums`可以有效分区。 
2. 初始化`dp[0] = true`。 

这代表空前缀。 It is important because valid groups can build on top of this base case.
 3. 从左到右迭代数组。 

对于每个位置`i`，我们确定有效分区是否可以在索引处结束`i - 1`。 
4. 检查二等元素条件。 

如果：

-`i >= 2`-`nums[i - 1] == nums[i - 2]`-`dp[i - 2]`是真的

 那么我们可以形成一个有效的分区，结尾为`i - 1`，所以设`dp[i] = true`。 
5. 检查三等元条件。 

如果：

-`i >= 3`-`nums[i - 1] == nums[i - 2] == nums[i - 3]`-`dp[i - 3]`是真的

 then set`dp[i] = true`。 
6. 检查连续递增条件。 

如果：

-`i >= 3`-`nums[i - 3] + 1 == nums[i - 2]`-`nums[i - 2] + 1 == nums[i - 1]`-`dp[i - 3]`是真的

 然后设置`dp[i] = true`。 
7. 继续，直到处理完所有位置。 
8. 返回`dp[n]`。 

这告诉我们整个数组是否可以有效分区。 

### 为什么它有效

 该算法之所以有效，是因为每个有效分区都必须以三种允许的组类型之一结束。 DP状态`dp[i]`存储前缀是否在索引之前结尾`i`是可以解决的。 通过检查所有有效的最终组配置，我们保证每个可能的有效分区仅被考虑一次。 由于每个状态仅依赖于较小的已计算状态，因此该解决方案既正确又高效。 

## Python 解决方案```python
from typing import List

class Solution:
    def validPartition(self, nums: List[int]) -> bool:
        n = len(nums)

        dp = [False] * (n + 1)
        dp[0] = True

        for i in range(2, n + 1):
            # Case 1: two equal elements
            if nums[i - 1] == nums[i - 2] and dp[i - 2]:
                dp[i] = True

            # Cases involving three elements
            if i >= 3:
                # Case 2: three equal elements
                if (
                    nums[i - 1] == nums[i - 2] ==
                    nums[i - 3] and dp[i - 3]
                ):
                    dp[i] = True

                # Case 3: three consecutive increasing elements
                if (
                    nums[i - 3] + 1 == nums[i - 2] and
                    nums[i - 2] + 1 == nums[i - 1] and
                    dp[i - 3]
                ):
                    dp[i] = True

        return dp[n]
```实施直接遵循DP的制定。 

变量`n`存储数组长度。 这`dp`数组有大小`n + 1`因为`dp[i]`代表第一个的有效性`i`元素。 

基本情况`dp[0] = True`至关重要，因为它允许从数组的开头形成第一个有效组。 

循环开始于`i = 2`因为最小的有效组大小是二。 

在循环内，代码检查三种允许的分区类型：

 - 两个相等的元素
 - 三个相等的元素
 - 三个连续递增元素

 每当满足这些条件之一并且较早的前缀已经有效时，当前的前缀也将变得有效。 

最后算法返回`dp[n]`，表示整个数组是否可以分区。 

## 解决方案```go
func validPartition(nums []int) bool {
	n := len(nums)

	dp := make([]bool, n+1)
	dp[0] = true

	for i := 2; i <= n; i++ {
		// Case 1: two equal elements
		if nums[i-1] == nums[i-2] && dp[i-2] {
			dp[i] = true
		}

		if i >= 3 {
			// Case 2: three equal elements
			if nums[i-1] == nums[i-2] &&
				nums[i-2] == nums[i-3] &&
				dp[i-3] {
				dp[i] = true
			}

			// Case 3: three consecutive increasing elements
			if nums[i-3]+1 == nums[i-2] &&
				nums[i-2]+1 == nums[i-1] &&
				dp[i-3] {
				dp[i] = true
			}
		}
	}

	return dp[n]
}
```Go 的实现与 Python 解决方案非常相似。 

DP 数组是使用以下命令创建的`make([]bool, n+1)`。 Go initializes boolean slices to`false`自动地，所以仅`dp[0]`必须明确设置为`true`。 

Go 切片的零索引与 Python 列表完全相同，因此适用相同的索引逻辑。 

不存在整数溢出问题，因为这些值仅存在差异`1`，并且约束仍然在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况是两个元素的最小输入大小。 由于长度为 2 的唯一有效分区是一对相等的数字，因此像这样的数组`[5,5]`必须返回`true`， 尽管`[5,6]`必须返回`false`。 该实现自然地处理了这个问题，因为循环开始于`i = 2`并立即检查两个相等元素的条件。 

另一个重要的边缘情况是具有有效前缀但无效剩余部分的数组。 例如，`[1,1,1,1,1]`最初看起来很有希望，因为存在几个有效的群体。 然而，每个可能的分区都会留下一个不匹配的元素。 DP 公式正确地处理了这个问题，因为状态只会变成`true`如果整个早期前缀有效。 

第三个重要的边缘情况涉及重叠分区的可能性。 考虑`[4,4,4,4]`。 前三个元素形成有效的三元组，但使用该分区会留下一个无效的剩余元素。 正确的解决方案是分成两对：`[4,4]`和`[4,4]`。 贪婪算法可能会在这里失败，但动态规划会成功，因为它会评估到达每个前缀的所有有效方法。 

另一个微妙的边缘情况是几乎可以工作的连续序列，例如`[1,2,4]`。 尽管数字在增加，但它们并不是连续的，因为之间的差异`2`和`4`不是`1`。 该实现显式检查两个相邻差异，确保正确拒绝此类情况。
