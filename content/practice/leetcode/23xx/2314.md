[LeetCode 问题 2314](https://leetcode.com/problems/the-first-day-of-the-maximum-recorded- Degree-in-each-city/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`Weather`它存储 2022 年特定日期不同城市的温度读数。 

每行包含三个值：

 -`city_id`，它标识了城市
 -`day`，代表测量日期
 -`degree`，代表记录的温度

 这对`(city_id, day)`保证是唯一的，这意味着一个城市不能在同一天有多个温度记录。 

任务是找到每个城市记录到最高气温的日期。 如果同一城市多次出现相同的最高气温，我们必须返回这些出现中最早的一天。 

输出应包含：

 -`city_id`-`day`-`degree`最终结果必须按以下顺序排序`city_id`按升序排列。 

这个问题的关键细节是平局打破规则。 仅仅找到最大程度是不够的。 如果多行共享相同的最大度数，我们必须选择最早的日期。 

例如，假设一个城市有：

 | 城市ID | 日 | 学位|
 | ---| ---| ---|
 | 2 | 2022-08-07 | 37 | 37
 | 2 | 2022年8月17日 | 37 | 37

 两行的最高温度均为`37`，但正确答案是`2022-08-07`因为时间比较早。 

这些限制意味着我们正在使用关系数据库操作而不是内存中的算法结构。 这意味着解决方案应该有效地使用 SQL 功能，特别是聚合和排名。 

一些边缘情况很重要：

 - 一个城市可能只有一个天气记录
 - 多行可以共享相同的最大度数
 - 度数可以为负数
 - 必须在关系中正确选择最早的日期
 - 不同城市完全独立，必须单独处理

 因为主键保证唯一`(city_id, day)`对，我们永远不需要担心同一城市和日期的重复行。 

## 方法

 ### 蛮力方法

 蛮力策略将独立处理每个城市。 

对于每个城市，我们首先可以通过扫描属于该城市的所有行来确定最大度数。 然后我们可以再次扫描相同的行以查找与最大度数匹配的最早日期。 

从概念上讲，这是可行的，因为：

 1.第一遍确定目标温度
 2. 第二关适用平局规则

 在 SQL 中，这可能涉及嵌套子查询或重复扫描表。 

尽管这种方法是正确的，但效率很低，因为它会重复搜索相同的数据。 如果有很多城市，每个城市有很多记录，数据库引擎会执行不必​​要的重复工作。 

### 最佳方法

 更好的解决方案使用窗口函数，具体来说`ROW_NUMBER()`。 

关键的见解是我们可以根据以下条件对每个城市内的行进行排名：

 1. 最高学历优先
 2. 最早的一天在前

 如果我们以这种方式对行进行排序，那么每个城市分区中的第一行正是我们想要的答案。 

这非常有效，因为：

 - 订购方式`degree DESC`确保最高温度首先出现
 - 订购方式`day ASC`通过选择最早的日期来解决关系
 -`ROW_NUMBER()`让我们为每个城市选择一行

 这种方法非常高效，因为数据库在数据分区的单次传递中即可处理分组、排序和排名。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 每个城市重复扫描 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用窗口函数和分区排序 |

 ## 算法演练

 1. 按以下方式对行进行分区`city_id`。 

这确保了每个城市都是独立处理的。 不同城市的天气记录不应相互影响。 
2. 在每个城市分区内，对行进行排序`degree`按降序排列。 

这使得分区顶部的温度最高。 
3. 如果多行具有相同的度数，则对这些行进行排序`day`按升序排列。 

这保证了在相同的最高温度中，最早的日期在前。 
4. 应用`ROW_NUMBER()`窗函数。 

每个分区中的第一行接收排名`1`，第二行获得排名`2`， 等等。 
5. 仅选择行号等于的行`1`。 

由于行已经正确排序，因此具有排名的行`1`这正是那个城市想要的答案。 
6. 对最终结果进行排序`city_id`。 

这满足了问题陈述中的输出要求。 

### 为什么它有效

 正确性来自每个城市分区内使用的排序标准。 

通过首先按温度降序排序，我们确保最大度数始终出现在较小值之前。 通过使用升序日期对关系进行排序，我们确保最早出现的最大度数首先出现。 

因此，分配的行`ROW_NUMBER() = 1`一定是该城市唯一的正确答案。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT city_id, day, degree
FROM (
    SELECT
        city_id,
        day,
        degree,
        ROW_NUMBER() OVER (
            PARTITION BY city_id
            ORDER BY degree DESC, day ASC
        ) AS rn
    FROM Weather
) ranked_weather
WHERE rn = 1
ORDER BY city_id;
```该查询首先创建一个名为的派生表`ranked_weather`。 

在这个派生表中，`ROW_NUMBER()`窗口函数为每个城市内的每个天气记录分配一个排名。 这`PARTITION BY city_id`条款确保每个城市重新开始排名。 

排序规则是解决方案中最重要的部分：```python
ORDER BY degree DESC, day ASC
```首先优先考虑较高的温度，然后使用较早的日期解决关系。 

对所有行进行排序后，外部查询将结果过滤为仅包含以下位置的行：`rn = 1`。 这些行代表根据问题要求每个城市的最佳候选者。 

最后对结果进行排序`city_id`按升序排列。

 ## 边缘情况

 当一个城市只有一项天气记录时，就会出现一种重要的边缘情况。 在这种情况下，该行必须自动成为答案，因为它既是最大次数又是最早出现的。 该实现自然地处理了这个问题，因为`ROW_NUMBER()`分配等级`1`到分区中的唯一行。 

当多行共享相同的最大度数时，会发生另一个关键的边缘情况。 一个简单的解决方案，只计算`MAX(degree)`可能会意外返回多行或选择任意行。 该实现通过使用以下方法对绑定行进行排序来避免这种情况`day ASC`，确保最早的日期始终获得排名`1`。 

负温度也很重要。 一些不正确的实现可能会假设温度为非负值或错误处理涉及负数的比较。 由于 SQL 数字比较对于负整数可以正确工作，因此排序依据`degree DESC`即使所有值都低于零，仍然可以正确识别最大温度值。 

最后一个边缘案例涉及全年分布有许多记录的城市。 最高温度可能出现在数据集的开头、中间或结尾附近。 由于该解决方案使用分区排序而不是依赖插入顺序，因此无论行出现在表中的哪个位置，它都能正确识别最大值。
