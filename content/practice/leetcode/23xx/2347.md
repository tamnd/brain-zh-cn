[LeetCode 第 2347 题](https://leetcode.com/problems/best-poker-hand/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、计数

 ## 解决方案

 ## 问题理解

 这个问题给了我们正好五张扑克牌。 每张卡片由两条信息表示：

 -`ranks[i]`代表卡牌的数字等级，从`1`到`13`-`suits[i]`代表该牌的花色，使用以下字符`'a'`到`'d'`我们需要确定这五张牌可以组成的最强扑克牌。 可能的牌按从最强到最弱的顺序排列：

 1.`"Flush"`, 所有五张牌的花色相同
 2.`"Three of a Kind"`, 至少三张牌具有相同的等级
 3.`"Pair"`, 至少两张牌具有相同的等级
 4.`"High Card"`，以上条件均不适用

 关键细节是我们只需要返回可能的最佳类别，而不是形成手牌的实际牌。 

例如：

 - 如果所有套装都相同，我们立即返回`"Flush"`，无论排名。 
- 如果我们不能形成同花，但某个排名至少出现了三次，我们返回`"Three of a Kind"`。 
- 如果以上都不存在，但某个排名出现两次，我们返回`"Pair"`。 
- 否则，答案是`"High Card"`。 

限制非常小：

 - 总是有确切的`5`牌。 
- 排名值范围为`1`到`13`。 
- 套装价值范围为`'a'`到`'d'`。 

由于输入大小是固定的且很小，因此性能不是问题。 然而，我们仍然想要一个干净且逻辑正确的解决方案。 

一个重要的保证是没有两张牌具有相同的等级和相同的花色，这意味着不会出现重复的物理牌。 

一些边缘情况很重要：

 - 所有花色相同，即使有重复的等级，仍然应该返回`"Flush"`因为它有更高的优先级。 
- 四张相同点数的牌也算作`"Three of a Kind"`因为问题只问是否存在至少三个相等的等级。 
- 多对仍应返回`"Pair"`。 
- 完全不同的等级和套装应该回归`"High Card"`。 

## 方法

 ### 蛮力方法

 强力解决方案将明确地独立测试每个可能的手牌类别。 

我们可以：

 1. 将每种花色与其他花色进行比较，检查是否同花。 
2. 比较每对排名以计算相等的值。 
3. 枚举牌的组合，看看是否有任何三张牌具有相同的等级。 
4. 再次枚举对以检测对。 

因为只有五张牌，所以这种做法是完全可行的。 比较的总数很少。 

然而，这种方法会变得混乱，因为它会重复扫描相同的信息。 该逻辑也更难维护，因为我们手动检查许多组合，而不是使用结构化计数策略。 

### 最佳方法

 关键的见解是扑克手牌检测完全取决于频率计数。 

- 同花取决于所有花色是否相同。 
- 同类中的三个取决于某个排名是否至少出现三次。 
- 一对取决于某个排名是否至少出现两次。 

我们可以使用哈希图来计算每个排名出现的次数，而不是手动检查组合。 

算法变得非常简单：

 1. 检查所有花色是否匹配。 
2. 计算排名频率。 
3. 找出排名中的最大频率。 
4. 根据最大​​频率返回正确的手型。 

这种方法更清晰、更容易推理，并且直接对问题的结构进行建模。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(1) | O(1) | O(1) | O(1) | 手动比较卡片组合 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用频率计数进行排名 |

 尽管由于输入大小固定为五张卡，两者在技术上都是恒定时间，但最佳解决方案在设计上更加优雅和可扩展。 

## 算法演练

 1. 首先检查所有花色是否相同。 

我们存储第一个花色并将所有其他花色与它进行比较。 如果每种花色都匹配，那么这手牌就是`"Flush"`。 

我们首先这样做是因为`"Flush"`是这个问题中最强的一手牌。 
2. 创建哈希图来计算排名频率。 

键是卡牌等级，值是每个等级出现的次数。 

例如：```
ranks = [4,4,2,4,4]
```产生：```
{
    4: 4,
    2: 1
}
```3. 计算最大排名频率。 

我们迭代频率图并跟踪最大计数。 

这告诉我们最强的匹配排名模式：

 - 最大频率 >= 3 意味着`"Three of a Kind"`- 最大频率 == 2 意味着`"Pair"`- 否则`"High Card"`4. 根据优先顺序返回最好的牌。 

由于先检查flush，所以我们只需要随后进行排名分析。 

### 为什么它有效

 该算法之所以有效，是因为问题的手牌定义完全取决于两个属性：

 - 所有套装是否相同
 - 同等等级的最大数量

 同花条件与等级无关，其余手牌类别仅由最高等级频率决定。 由于该算法正确计算了这两个属性并应用从最强到最弱的手牌排名顺序，因此它总是返回正确的最佳手牌。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def bestHand(self, ranks: List[int], suits: List[str]) -> str:
        # Check for Flush
        if all(suit == suits[0] for suit in suits):
            return "Flush"

        # Count rank frequencies
        rank_count = Counter(ranks)

        max_frequency = max(rank_count.values())

        if max_frequency >= 3:
            return "Three of a Kind"

        if max_frequency == 2:
            return "Pair"

        return "High Card"
```该实现首先检查每个花色是否与第一个花色匹配。 这`all()`function 使得这个简洁易读。 

如果存在同花，我们立即返回`"Flush"`因为在这个问题上它比其他所有可能的牌都重要。 

接下来，我们使用`Counter`来自Python的`collections`模块来计算每个排名出现的次数。 这会自动构建频率表。 

然后我们计算最大频率值。 如果最大频率至少为 3，我们返回`"Three of a Kind"`。 如果正好是两个，我们返回`"Pair"`。 否则，不存在重复的排名，所以答案是`"High Card"`。 

## 解决方案```go
func bestHand(ranks []int, suits []byte) string {
    // Check for Flush
    isFlush := true

    for i := 1; i < len(suits); i++ {
        if suits[i] != suits[0] {
            isFlush = false
            break
        }
    }

    if isFlush {
        return "Flush"
    }

    // Count rank frequencies
    rankCount := make(map[int]int)

    maxFrequency := 0

    for _, rank := range ranks {
        rankCount[rank]++

        if rankCount[rank] > maxFrequency {
            maxFrequency = rankCount[rank]
        }
    }

    if maxFrequency >= 3 {
        return "Three of a Kind"
    }

    if maxFrequency == 2 {
        return "Pair"
    }

    return "High Card"
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

而不是Python的`Counter`, Go 使用`map[int]int`手动跟踪频率。 

一个小的优化是我们更新了`maxFrequency`在构建地图时，避免通过频率计数进行第二次迭代。 

由于输入大小是固定的且很小，因此无需担心溢出或内存使用。

 ## 边缘情况

 一种重要的边缘情况是所有五种花色都相同，而等级也包含重复项。 幼稚的实现可能会错误地优先考虑重复的排名和返回`"Three of a Kind"`或者`"Pair"`。 正确答案一定还是`"Flush"`因为问题明确地将其定义为更强的手。 该实现通过在任何排名分析之前检查刷新来处理这个问题。 

另一个重要的情况是四张牌具有相同的等级。 该问题不包括单独的`"Four of a Kind"`类别。 This means any frequency of three or greater must return`"Three of a Kind"`。 实现正确使用`>= 3`而不是`== 3`。 

当有两个独立的对时，会出现第三种边缘情况，例如`[8,8,3,3,5]`。 问题没有定义`"Two Pair"`作为有效类别。 正确答案很简单`"Pair"`。 由于算法只检查最大频率，所以自然会返回`"Pair"`。 

另一个微妙的情况是所有牌的点数和花色都完全不同。 在这种情况下，频率图仅包含`1`，并且套装并不相同。 该算法正确地落入`"High Card"`在所有更强大的条件失败之后。
