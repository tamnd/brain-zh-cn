[LeetCode 问题 2352](https://leetcode.com/problems/equal-row-and-column-pairs/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、矩阵、模拟

 ## 解决方案

 ## 问题理解

 该问题给了我们一个方阵`grid`尺寸的`n x n`，其中每个元素都是整数。 我们需要数一下有多少个`(row, column)`对完全相等。 

更具体地说，对于每一行`ri`和每一列`cj`，我们将该行中的元素序列与该列中的元素序列进行比较。 如果它们包含相同顺序的相同值，则该对将被视为一个有效匹配。 

例如，假设一行是：```
[2, 7, 7]
```还有一列：```
[2, 7, 7]
```由于每个元素出现的位置和顺序相同，因此它们被认为是相等的。 

输入是方阵：

 -`grid[i]`代表`i-th`排。 
-`grid[j][i]`代表行的值`j`和列`i`。 

输出是一个整数，表示相等的行列对的总数。 

约束条件很重要：

 -`1 <= n <= 200`-`1 <= grid[i][j] <= 10^5`自从`n`至多是`200`，矩阵最多包含`40,000`细胞。 这并不是很大，但是逐个元素将每一行与每一列进行比较仍然会变得昂贵。 一个简单的解决方案可能会在一定范围内发挥作用，但我们仍然应该寻找一种更清洁、更有效的方法。 

还有一些重要的观察结果和边缘情况：

 - 可能存在多个相同的行，并且它们应分别对计数做出贡献。 
- 也可能存在多个相同的列。 
- 大小矩阵`1 x 1`有效，意味着唯一的行和唯一的列必须始终匹配。 
- 矩阵保证是正方形的，所以我们永远不需要处理矩形矩阵。 
- 值始终是正整数，因此我们不需要考虑丢失或无效的条目。 

一个常见的错误是忘记重复的行或重复的列会多次贡献。 如果行模式出现两次并且匹配的列模式出现三次，那么它们贡献`2 × 3 = 6`有效对。 

## 方法

 ### 蛮力方法

 最直接的解决方案是比较每一行和每一列。 

我们有`n`行和`n`列。 对于每对`(row, column)`，我们比较所有`n`元素一一呈现。 

该过程的工作原理如下：

 1. 迭代每一行。 
2. 迭代每一列。 
3. 构建或模拟列值。 
4. 逐个元素比较行和列。 
5. 如果答案相同，则增加答案。 

这是有效的，因为问题定义很简单。 我们简单地测试每一个可能的对并计算有效的对。 

然而，它变得低效，因为：

 - 有`n²`行-列对。 
- 每次比较需要`O(n)`时间。 

这导致`O(n³)`时间复杂度。 

自从`n = 200`，最坏的情况大约是`8,000,000`操作，这仍然是可管理的，但我们可以在概念上做得更好，并使实现更清晰。 

### 最佳解决方案的关键见解

 关键的观察是我们重复检查列之间是否存在行序列。 

我们可以将行和列视为可哈希序列，而不是单独比较每一行和每一列。 

如果我们将每一行转换为一个元组并将其频率存储在哈希图中，那么对于每一列，我们只需要检查行之间是否存在相同的序列。 

例如：```
Rows:
[2,4,2,2]
[2,4,2,2]
```我们可以存储：```
(2,4,2,2) -> 2
```然后当我们遇到该列时：```
[2,4,2,2]
```我们立即知道有`2`匹配的行。 

这避免了重复比较，并将序列匹配转变为高效的哈希查找。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 逐个元素比较每一行和每一列 |
 | 最佳| O(n²) | O(n²) | 使用哈希映射对行模式进行计数并匹配列 |

 ## 算法演练

 ### 最优算法

 1. 创建哈希映射来存储行频率。 

我们将每一行转换为一个元组，因为列表是可变的并且不能用作 Python 中的字典键。 元组表示允许我们有效地存储行模式。 
2. 迭代矩阵中的所有行。 

对于每一行，将其转换为元组并增加其在哈希映射中的计数。 

例如：```
Row map:
(3,1,2,2) -> 1
(1,4,4,5) -> 1
(2,4,2,2) -> 2
```3. 初始化变量`equal_pairs = 0`。 

该变量将累积匹配行列对的总数。 
4. 迭代每一列。 

要构建专栏，请收集：```
grid[0][col]
grid[1][col]
...
grid[n-1][col]
```将此列转换为元组。 
5. 检查行频图中是否存在该列元组。 

如果存在，请将其频率添加到答案中。 

这很重要，因为重复的行很重要。 

例如：```
Column = (2,4,2,2)
Frequency in rows = 2
```我们添加`2`因为两行形成有效对。 
6. 返回最终计数。 

### 为什么它有效

 该算法之所以有效，是因为每一行和每一列都由精确排序的值序列表示。 通过将行频率存储在哈希图中，我们可以保留每个行模式出现的次数。 然后，对于每一列，我们只需计算有多少行共享相同的序列。 

由于相等被定义为以相同顺序匹配元素，因此使用元组作为键可以保证精确的序列匹配。 每个有效的行列对都只计算一次。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def equalPairs(self, grid: List[List[int]]) -> int:
        n = len(grid)

        # Count occurrences of each row pattern
        row_count = Counter(tuple(row) for row in grid)

        equal_pairs = 0

        # Build each column and check for matching rows
        for col in range(n):
            column = tuple(grid[row][col] for row in range(n))
            equal_pairs += row_count[column]

        return equal_pairs
```该实现首先使用以下命令创建行的频率图`Counter`。 每行都转换为一个元组，因此可以用作字典键。 

例如：```python
grid = [
    [2,4,2,2],
    [2,4,2,2]
]
```变成：```python
{
    (2,4,2,2): 2
}
```接下来，我们迭代每个列索引。 对于每一列，我们通过垂直收集矩阵中的元素来构造一个元组。 

我们不是手动比较每一行，而是直接查找列元组`row_count`。 如果该模式存在，则其频率将添加到答案中。 

这使得实现简洁高效，同时自然地处理重复行。 

## 解决方案```go
func equalPairs(grid [][]int) int {
	n := len(grid)

	// Count row frequencies
	rowCount := make(map[string]int)

	for _, row := range grid {
		key := serialize(row)
		rowCount[key]++
	}

	equalPairs := 0

	// Build each column and check matches
	for col := 0; col < n; col++ {
		column := make([]int, n)

		for row := 0; row < n; row++ {
			column[row] = grid[row][col]
		}

		key := serialize(column)
		equalPairs += rowCount[key]
	}

	return equalPairs
}

func serialize(nums []int) string {
	result := ""

	for _, num := range nums {
		result += fmt.Sprintf("%d,", num)
	}

	return result
}
```在 Go 中，切片不能用作映射中的键，因为它们不具有可比性。 为了解决这个问题，我们将每一行和每一列序列化为字符串表示形式。 

例如：```go
[2,4,2,2]
```变成：```go
"2,4,2,2,"
```该序列化字符串充当映射内的哈希键。 

与 Python 不同，Go 没有内置的元组类型或`Counter`，所以我们使用手动维护频率图`map[string]int`。 

这里不存在整数溢出问题，因为有效对的最大数量是`200 × 200 = 40,000`，它很容易适合 Go 的内部`int`。

 ## 边缘情况

 ### 单细胞矩阵

 一个`1 x 1`矩阵始终具有一对有效的对，因为唯一的行和唯一的列包含相同的单个值。 

例如：```
[[7]]
```实现自然地处理了这个问题。 行元组`(7,)`存储一次，并且唯一的列产生相同的元组，从而产生一个匹配。 

### 重复的行和列

 这是最容易犯错误的地方之一。 假设我们有：```
[
    [1,1],
    [1,1]
]
```有两个相同的行和两个相同的列。 每一行都匹配每一列：```
2 × 2 = 4
```仅检查存在而不检查频率的幼稚实现可能会错误地返回`2`。 我们的实现正确地将频率存储在哈希图中并添加总计数。 

### 没有匹配对

 有些矩阵根本不包含相等的行列对。 

例如：```
[
    [1,2],
    [3,4]
]
```行：```
(1,2)
(3,4)
```栏目：```
(1,3)
(2,4)
```没有序列匹配。 

该实现正确地处理了这个问题，因为失败的哈希查找只会造成影响`0`至总数。 

### 行内重复值

 行或列可能包含重复的数字：```
[2,2,2]
```有缺陷的实现可能会意外地比较序列的集合或排序版本，这会丢失排序信息。 

我们的方法通过存储元组来保留精确的顺序，因此：```
[1,2,2]
```和```
[2,1,2]
```被视为不同的模式，完全按照问题陈述的要求。
