[LeetCode 问题 2303](https://leetcode.com/problems/calculate-amount-paid-in-taxes/)

 **难度：** 🟢简单
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们模拟累进税制。 我们得到了一份税级列表，其中每个税级指定了收入上限和税率。 我们的任务是计算给定收入的应缴税总额，并考虑到每个等级仅对该等级内的收入部分征税。 

换句话说，第一个括号对第一个括号征税`upper0`美元在`percent0`，第二个括号对下一个括号征税`upper1 - upper0`美元在`percent1`， 等等。 括号按其上限排序，最后一个括号始终涵盖总收入。 预期输出是一个浮点数，代表所欠税款总额，精确到`10^-5`。 

约束告诉我们输入大小很小：最多 100 个括号，收入最多 1000。这确保了即使是简单的基于循环的解决方案也能高效运行。 重要的边缘情况包括零收入、零百分比的税级或收入恰好在税级边界上。 该问题保证了唯一的上限，并且最后一个括号涵盖了收入，因此我们不需要处理缺失的覆盖范围。 

## 方法

 强力方法是模拟每一美元收入的税收。 每美元从 1 到`income`，我们会找到它属于哪个档次并添加相应的税。 虽然这在概念上很简单，但没有必要，因为我们可以使用算术一次计算整个类别的税收，从而避免按美元计算。 

最佳方法利用了这样一个事实：每个等级仅对收入征税至其上限。 对于每个括号，我们将应税金额计算为括号宽度的最小值（`upperi - upperi-1`）和剩余收入。 将其乘以税率，累积总税额，并在处理完所有收入后停止。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(收入 * n) | O(1) | O(1) | 模拟每一美元的税收，对于大收入来说效率低下 |
 | 最佳| O(n) | O(1) | O(1) | 直接处理各个档次并累加税款 |

 ## 算法演练

 1. 初始化变量`tax`为 0 以存储所欠税总额。 
2. 初始化变量`prev_upper`到 0 以跟踪前一个括号的上限。 
3. 循环遍历每个括号`[upper, percent]`在括号列表中。 
4. 对于当前括号，计算`taxable_income`作为最小值`income - prev_upper`和`upper - prev_upper`。 这确保我们只对属于这个范围内的收入征税。 
5. 乘法`taxable_income`经过`percent / 100`并将结果添加到`tax`。 
6. 更新`prev_upper`到`upper`移动到下一个括号。 
7. 如果`prev_upper`达到或超过`income`，打破循环，因为所有收入都已纳税。 
8. 返回`tax`作为最终欠款金额。 

为什么有效：在每一步中，我们都会准确计算属于当前范围内的收入部分并应用正确的税率。 因为括号已排序并涵盖了整个收入，所以这保证了我们将所有收入都计算一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def calculateTax(self, brackets: List[List[int]], income: int) -> float:
        tax = 0.0
        prev_upper = 0
        
        for upper, percent in brackets:
            if income <= prev_upper:
                break
            taxable_income = min(income - prev_upper, upper - prev_upper)
            tax += taxable_income * (percent / 100)
            prev_upper = upper
        
        return tax
```在这个实现中，`tax`累计所欠税款总额。 这`prev_upper`变量跟踪最后一个括号的上限以计算当前括号内的收入切片。 我们使用以下方法计算应税部分`min`处理收入未完全覆盖该范围的情况。 如果所有收入都已纳税，则循环提前终止。 

## 解决方案```go
func calculateTax(brackets [][]int, income int) float64 {
    tax := 0.0
    prevUpper := 0

    for _, bracket := range brackets {
        upper := bracket[0]
        percent := bracket[1]

        if income <= prevUpper {
            break
        }

        taxableIncome := upper - prevUpper
        if income-prevUpper < taxableIncome {
            taxableIncome = income - prevUpper
        }

        tax += float64(taxableIncome) * float64(percent) / 100.0
        prevUpper = upper
    }

    return tax
}
```在 Go 中，我们遵循与 Python 相同的逻辑。 我们将整数转换为`float64`计算税收时以避免整数除法问题。 提早休息可以确保我们在所有收入纳税后停止。

 ## 边缘情况

 第一个重要的边缘情况是**零收入**。 如果收入为 0，则无需纳税。 我们的算法自然地处理这个问题，因为`taxable_income = min(0 - prev_upper, upper - prev_upper)`计算结果为 0，并且循环退出而不添加任何税。 

第二个边缘情况是**收入恰好位于括号边界**。 如果收入等于某个等级的上限，则该等级的应税金额恰好是与前一个等级的差额。 使用`min(income - prev_upper, upper - prev_upper)`确保计算正确。 

第三种边缘情况是**零百分比括号**。 一个等级的税率可以为 0%，无论该等级的收入多少，都应缴纳 0 税。 该算法将应税收入乘以`percent/100`，因此 0% 的税率自然对总税收没有贡献。 这可以防止在简单实现中可能出现的潜在除法或计算错误。
