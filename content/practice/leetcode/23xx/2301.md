[LeetCode 问题 2301](https://leetcode.com/problems/match-substring-after-replacement/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、字符串、字符串匹配

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`, 目标字符串`sub`，以及称为的字符替换规则列表`mappings`。 

每个映射`[old, new]`意味着一个字符`old`里面`sub`可以替换为`new`。 替换是可选的，并且每个字符`sub`最多可以更换一次。 重要的是，更换仅适用于`old`到`new`，而不是相反。 

我们的任务是确定在对中的字符应用零个或多个有效替换后是否`sub`，结果字符串可以作为连续子字符串出现在`s`。 

重要的细节是替换是概念性的，我们实际上不需要生成所有可能的转换版本`sub`。 相反，我们只需要检查之间是否存在某种对齐`sub`和一个子串`s`其中每个字符都匹配：

 1.直接的意思`sub[i] == s[j]`2.通过有效的替换映射，意义`sub[i]`可以成为`s[j]`约束条件很重要：

 -`s.length`和`sub.length`至多是`5000`-`mappings.length`至多是`1000`一种强力解决方案，可生成每个可能的转换版本`sub`会组合爆炸。 即使是中等数量的可替换字符也可能产生大量的候选字符串。 

然而，字符串的大小足够小，可以检查每个可能的起始位置`s`是可行的，只要每次比较都是有效的。 

一些重要的边缘情况包括：

 - 没有提供映射
 -`sub`已经出现在`s`无需更换
 - 同一角色存在多个映射
 - 中的一个角色`sub`无法替换成所需的字符
 - 大写和小写字符不同
 - 数字和字母可能同时出现
 - 更换方向非常重要

 例如，如果我们有映射`["o", "0"]`， 然后`o -> 0`是允许的，但是`0 -> o`不是。 

## 方法

 ### 蛮力方法

 一种天真的方法会尝试生成每个可能的转换版本`sub`使用替换映射。 

假设一个字符在`sub`有多种可能的替换选项。 然后该字符的每次出现都会产生分支的可能性。 我们可以递归地尝试：

 - 保留原有角色
 - 将其替换为其映射的字符之一

 生成每个可能的转换字符串后，我们将检查它是否作为子字符串存在`s`。 

这种方法是正确的，因为它明确地探索了所有有效的转换版本`sub`。 如果任何转换后的版本出现在`s`，答案是`true`。 

问题是这会变得非常昂贵。 如果有多个位置`sub`每个都有多种替换选择，生成的字符串数量呈爆炸式增长。 

例如，如果 20 个字符每个都有 2 种可能性，我们已经有：$$2^{20}$$可能的字符串。 

对于给定的约束，这是完全不可行的。 

### 最佳方法

 关键的观察是我们根本不需要生成转换后的字符串。 

相反，我们可以直接比较`sub`针对每个子串窗口`s`具有相同的长度。 

对于每对对齐的字符：

 - 如果字符相等，则位置匹配
 - 否则，我们检查替换映射是否允许该字符来自`sub`成为角色`s`如果每个字符位置都符合这些规则，那么我们就找到了一个有效的转换后的子字符串。 

这是有效的，因为每个字符替换都是独立的。 我们永远不需要跟踪复杂的状态或转换序列。 位置要么直接匹配，要么通过映射匹配，要么失败。 

我们将映射预处理为哈希集以进行恒定时间查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 生成所有转换版本`sub`|
 | 最佳| O((n - m + 1) × m) | O(k) | 使用哈希查找检查每个子字符串窗口 |

 在哪里：

-`n = len(s)`-`m = len(sub)`-`k = len(mappings)`## 算法演练

 1. 创建一个哈希集来存储所有有效的替换映射。 

每个映射都存储为一对`(old_char, new_char)`。 使用哈希集允许在子字符串比较期间进行恒定时间查找。 
2. 遍历每个可能的起始位置`s`。 

自从`sub`有长度`m`，最后一个有效的起始索引是：$$n - m$$对于每个起始位置，我们尝试匹配整个`sub`。 
3.一一比较字符。 

对于每个索引`j`里面`sub`：

- 让`sub_char = sub[j]`- 让`s_char = s[start + j]`如果满足以下任一条件，则该职位有效：

 -`sub_char == s_char`-`(sub_char, s_char)`存在于映射集中
 4. 尽早停止不匹配。 

如果两个条件都不成立，则当前子字符串窗口无法工作，因此我们立即移动到下一个起始位置。 
5. 返回`true`如果整个窗口匹配。 

如果一个窗口中的所有字符都满足匹配规则，则`sub`可以转换为该子字符串。 
6. 返回`false`如果没有窗户工作。 

检查完所有可能的位置后，如果没有匹配成功，则无法进行转换。 

### 为什么它有效

 该算法检查每个可能的子串`s`可以匹配的`sub`。 对于每个对齐的字符对，它准确地验证问题允许的条件：

 - 完全平等
 - 一份有效的替代品

 由于替换对于每个字符都是独立的并且最多应用一次，因此独立检查位置就足够了。 因此，如果算法找到完全匹配的窗口，则存在有效的变换子串。 如果所有窗口都失败，则没有有效的转换可以产生以下子串`s`。 

## Python 解决方案```python
from typing import List, Set, Tuple

class Solution:
    def matchReplacement(
        self,
        s: str,
        sub: str,
        mappings: List[List[str]]
    ) -> bool:

        allowed: Set[Tuple[str, str]] = set()

        for old_char, new_char in mappings:
            allowed.add((old_char, new_char))

        n = len(s)
        m = len(sub)

        for start in range(n - m + 1):

            match = True

            for j in range(m):

                sub_char = sub[j]
                s_char = s[start + j]

                if sub_char == s_char:
                    continue

                if (sub_char, s_char) not in allowed:
                    match = False
                    break

            if match:
                return True

        return False
```该实现首先将所有映射预处理为一个名为的哈希集`allowed`。 这让我们可以检查替换在恒定时间内是否有效。 

接下来，我们计算长度`s`和`sub`。 然后我们迭代每个可能的子字符串窗口`s`其长度与`sub`。 

对于每个窗口，我们逐个位置地比较字符位置。 如果字符已经匹配，我们立即继续。 否则，我们检查映射集中是否存在该对。 

如果发生无法通过替换修复的不匹配，我们会使用以下方法提前停止检查当前窗口`break`。 

如果我们完成整个窗口的检查而没有失败，我们立即返回`True`。 

如果所有窗口都失败，该函数返回`False`。 

## 解决方案```go
func matchReplacement(s string, sub string, mappings [][]byte) bool {
	allowed := make(map[byte]map[byte]bool)

	for _, mapping := range mappings {
		oldChar := mapping[0]
		newChar := mapping[1]

		if allowed[oldChar] == nil {
			allowed[oldChar] = make(map[byte]bool)
		}

		allowed[oldChar][newChar] = true
	}

	n := len(s)
	m := len(sub)

	for start := 0; start <= n-m; start++ {
		match := true

		for j := 0; j < m; j++ {
			subChar := sub[j]
			sChar := s[start+j]

			if subChar == sChar {
				continue
			}

			if allowed[subChar] == nil || !allowed[subChar][sChar] {
				match = false
				break
			}
		}

		if match {
			return true
		}
	}

	return false
}
```Go 实现使用嵌套映射结构而不是元组哈希集，因为 Go 没有内置 Python 风格的元组哈希。 

结构：```go
map[byte]map[byte]bool
```存储所有有效的替换关系。 

其余逻辑与 Python 版本密切相关。 Go 中的字符串索引直接对字节进行操作，它可以正常工作，因为该问题仅保证 ASCII 字符。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n - m + 1) × m) | 我们检查每个子串窗口并比较`m`人物 |
 | 空间| O(k) | 映射哈希集存储所有替换对 |

 在哪里：

-`n = len(s)`-`m = len(sub)`-`k = len(mappings)`最坏的情况是在失败之前必须彻底检查每个子字符串窗口。 由于有`n - m + 1`窗户和每个可能需要`m`比较起来，在最坏的情况下，总运行时间是二次的。 

空间复杂度仅与哈希结构中存储的映射对的数量成正比。

 ## 边缘情况

 当未提供映射时，会出现一种重要的边缘情况。 在这种情况下，问题简化为正常的子字符串搜索。 有缺陷的实现可能会错误地假设替换总是可用的。 我们的解决方案自然地处理这个问题，因为映射集只是空的，所以只有直接字符相等才能成功。 

另一个重要的边缘情况是替换方向。 映射`["o", "0"]`允许`o -> 0`，但不是`0 -> o`。 一个常见的错误是意外地将映射视为双向。 我们的实现将映射完全存储为有序对，并且仅检查是否`(sub_char, s_char)`存在，保持正确的方向性。 

重复的字符也会产生微妙的问题。 认为`sub = "aaaa"`和每一个`a`必须转变为`1`。 有缺陷的实现可能会错误地认为映射只能全局使用一次。 然而，该问题仅说明每个单独的角色最多只能被替换一次。 不同的位置可以独立地应用相同的映射。 我们的算法独立检查每个位置，因此重复使用可以正常工作。 

区分大小写是另一个潜在的错误来源。 由于大写和小写字母是不同的 ASCII 字符，`"A"`和`"a"`除非明确映射，否则不可互换。 我们的实现完全按照给定的方式比较字符，因此会自动保留区分大小写的行为。
