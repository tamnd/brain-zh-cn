[LeetCode 问题 2337](https://leetcode.com/problems/move-pieces-to-obtain-a-string/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个字符串，`start`和`target`，两者具有相同的长度。 字符串中的每个位置包含三个字符之一：

 -`'L'`，代表只能向左移动的棋子
 -`'R'`，代表只能向右移动的棋子
 -`'_'`, 代表一个空的空间

 移动包括将一个棋子滑入相邻的空白区域，但须遵守移动限制：

 -`'L'`只能向左移动
 -`'R'`只能向右移动

 任务是判断是否可以转型`start`进入`target`使用任意数量的有效移动。 

重要的细节是棋子不能互相跳过。 每一次移动都会一步一步地进入相邻的空白区域。 因此，非空白块的相对顺序永远不会改变。 

例如，如果非空白序列`start`是`"LRR"`和非空白序列`target`是`"RLR"`，变换是不可能的，因为片段的顺序不同。 

约束条件很重要：

 -`n`可以大到`10^5`- 这排除了昂贵的模拟方法
 - 我们需要一个线性或近线性算法

 几种边缘情况可能会导致幼稚实现中的错误：

 - 安`'L'`试图向右移动
 - 安`'R'`试图向左移动
 - 非空白件的不同排序
 - 仅包含空格的字符串
 - 多个连续的空格
 - 棋子被其他棋子阻挡

 该问题保证两个字符串仅包含`'L'`,`'R'`， 和`'_'`，并且它们的长度相等。 

## 方法

 ### 蛮力方法

 暴力解决方案将模拟所有可能的有效动作`start`字符串直到：

 - 我们到达`target`- 不可能有更多的状态

 这可以在所有可达配置上使用 BFS 或 DFS 来实现。 

这种方法是正确的，因为它探索了每一个法律转变。 如果`target`是可达的，最终搜索会发现它。 

然而，这种方法效率极低。 每个位置都可能生成多个未来状态，并且配置的数量随着字符串长度呈指数增长。 为了`n = 10^5`，这是完全不可行的。 

蛮力方法也浪费工作，因为它重复模拟可以直接使用位置约束来推理的运动。 

### 最佳两指针方法

 关键的观察结果是非空白块的相对顺序永远不会改变。 

如果我们删除所有`'_'`人物：

-`start`和`target`必须包含相同的序列`'L'`和`'R'`- 否则转型是不可能的

 接下来我们分析运动约束：

 -`'L'`只能向左移动，因此其目标索引必须小于或等于其起始索引
 -`'R'`只能向右移动，因此其目标索引必须大于或等于其起始索引

 我们可以使用两个指针有效地验证这些条件：

 - 一键扫描`start`- 一键扫描`target`- 两者都跳过空格
 - 找到碎片后，比较它们的类型和位置

 这完全避免了模拟并以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 探索所有可到达的状态 |
 | 最佳 | O(n) | O(1) | O(1) | 使用带有两个指针的位置约束 |

 ## 算法演练

 1.初始化两个指针，`i`为了`start`和`j`为了`target`。 
2. 移动指针`i`向前，直到它指向非空白字符或到达字符串末尾。 这会跳过不影响件排序的位置。 
3. 移动指针`j`向前直到它指向非空白字符或到达末尾。 
4. 如果两个指针同时到达末尾，则所有棋子都匹配成功，因此返回`True`。 
5. 如果只有一个指针到达末尾，则字符串包含的块数不同，因此返回`False`。 
6. 比较字符`start[i]`和`target[j]`。 

- 如果它们不同，则棋子的顺序会改变，这是不可能的。 
- 返回`False`。 
7. 如果角色是`'L'`，验证`i >= j`。 

-`'L'`只能向左移动。 
- 如果`i < j`，该棋子需要向右移动，这是无效的。 
8. 如果角色是`'R'`，验证`i <= j`。 

-`'R'`只能向右移动。 
- 如果`i > j`，该棋子需要向左移动，这是无效的。 
9. 向前移动两个指针并重复该过程。 
10. 如果所有棋子都满足约束条件，则返回`True`。 

### 为什么它有效

 该算法依赖于两个不变量：

 - 非空白块的相对顺序永远不会改变
 - 每个棋子类型都有严格的移动方向

 通过匹配相应的非空白块并检查它们允许的位置移动，我们充分表征了变换是否可能。 不需要实际的运动模拟。 

## Python 解决方案```python
class Solution:
    def canChange(self, start: str, target: str) -> bool:
        n = len(start)

        i = 0
        j = 0

        while i < n or j < n:
            while i < n and start[i] == '_':
                i += 1

            while j < n and target[j] == '_':
                j += 1

            if i == n and j == n:
                return True

            if i == n or j == n:
                return False

            if start[i] != target[j]:
                return False

            if start[i] == 'L' and i < j:
                return False

            if start[i] == 'R' and i > j:
                return False

            i += 1
            j += 1

        return True
```该实现遵循算法演练中描述的确切逻辑。 

变量`i`和`j`扫描通过`start`和`target`。 空格会被跳过，因为它们不代表实际的棋子。 

找到相应的块后，代码首先检查字符是否匹配。 这确保了非空白块的顺序是相同的。 

接下来，验证运动约束：

 -`'L'`无法向右移动
 -`'R'`无法向左移动

 如果违反任何约束，该函数立即返回`False`。 

如果所有部分都通过了检查，则可以进行转换并且函数返回`True`。 

## 解决方案```go
func canChange(start string, target string) bool {
	n := len(start)

	i := 0
	j := 0

	for i < n || j < n {
		for i < n && start[i] == '_' {
			i++
		}

		for j < n && target[j] == '_' {
			j++
		}

		if i == n && j == n {
			return true
		}

		if i == n || j == n {
			return false
		}

		if start[i] != target[j] {
			return false
		}

		if start[i] == 'L' && i < j {
			return false
		}

		if start[i] == 'R' && i > j {
			return false
		}

		i++
		j++
	}

	return true
}
```Go 实现与 Python 版本几乎相同。 

由于 Go 字符串是字节可索引的并且输入仅包含 ASCII 字符，因此使用索引`start[i]`和`target[j]`安全高效。 

不需要额外的内存分配，因此该解决方案保持恒定的辅助空间。

 ## 边缘情况

 ### 不同的非空白排序

 一个常见的错误是只检查棋子是否可以物理移动到目标位置而不验证订单保存。 

例如：```
start  = "RL"
target = "LR"
```即使两个字符串都包含一个`'L'`和一个`'R'`，变换是不可能的，因为碎片不能互相穿过。 

该实现通过在遍历期间直接比较相应的非空白字符来处理这个问题。 

###`'L'`向右移动

 安`'L'`棋子只能向左移动。 

例子：```
start  = "L_"
target = "_L"
```目标位置位于起始位置的右侧，这违反了移动规则。 

实施检查：```
if start[i] == 'L' and i < j:
    return False
```这立即否定了非法的右倾运动。 

###`'R'`向左移动

 安`'R'`棋子只能向右移动。 

例子：```
start  = "_R"
target = "R_"
```目标位置位于起始位置的左侧。 

该实现使用以下方式检测这一点：```
if start[i] == 'R' and i > j:
    return False
```这可以防止无效的向左移动。 

### 仅包含空格的字符串

 另一个微妙的边缘情况是当两个字符串只包含`'_'`。 

例子：```
start  = "___"
target = "___"
```没有可比较的部分，因此转换是非常有效的。 

该实现正确地处理了这个问题，因为两个指针最终同时到达末尾，导致算法返回`True`。
