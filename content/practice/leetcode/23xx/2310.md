[LeetCode 问题 2310](https://leetcode.com/problems/sum-of-numbers-with-units-digit-k/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划、贪心、枚举

 ## 解决方案

 ## 问题理解

 这个问题要求我们构造一组**正整数**，使得：

 1. 集合中的每个数字都有一个**个位数等于`k`**。 
2. **所有数字之和等于`num`**。 
3. 我们希望集合中的**尽可能少的整数**。 

如果不可能创建这样的集合，我们返回`-1`。 

一个重要的细节是数字可以重复。 这意味着我们不限于独特的价值观。 例如，如果`k = 5`，我们可以使用`[5, 5, 15]`甚至`[25, 25]`，只要每个数字都以`5`它们的总和等于`num`。 

该问题还明确指出**空集有总和`0`**，这创建了一个重要的特殊情况。 如果`num = 0`，我们可以立即返回`0`，无论其值如何`k`。 

### 重述问题

 我们需要确定**以数字结尾的整数的最小数量`k`其总和等于`num`**。 

关键的观察结果是，只有**最后一位**重要，而不是考虑每个数字的整个值。 由于每个数字都以`k`，总和的个位数仅取决于我们选择的此类数字的数量。 

例如：

 - 如果`k = 9`我们选择两个数字，他们的最后一位数字贡献`9 + 9 = 18`，其个位数为`8`。 
- 如果`num = 58`，其最后一位数字是`8`，那么使用两个数字可能是有效的。 

限制很小：

 -`0 <= num <= 3000`-`0 <= k <= 9`虽然`num`不是很大，这个问题实际上比完全动态规划或子集和问题简单得多。 可能的个位数字的小范围允许数学观察有效地解决它。 

### 重要的边缘案例

 有几种情况很容易导致简单的实现失败。 

如果`num = 0`，答案总是`0`因为空集是有效的。 

如果`k = 0`，每个选择的数字必须以`0`，意味着每个数字都可以被整除`10`。 在这种情况下，只有可被整除的总和`10`是可能的。 

如果`num < k`，我们不能简单地拒绝这个答案。 例如，`num = 12`和`k = 2`有效是因为`[12]`是有效的，尽管`num < 20`。 重要的是是否存在有效的结束数字组合。 

我们还必须处理不存在解决方案的情况，例如`num = 37`和`k = 2`。 没有结尾的整数个数`2`可以产生一个以`7`。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的数字计数，并确定是否以某种结尾的整数组合`k`可以总结为`num`。 

这可以类似于**无界背包**或**动态规划**问题进行建模。 我们可以生成所有以`k`最多`num`：```
k, k + 10, k + 20, ...
```然后尝试找到此类值的最小数量，总和为`num`。 

例如，如果`num = 58`和`k = 9`，候选人是：```
9, 19, 29, 39, 49
```我们可以使用动态规划来计算每个中间和的最小计数。 

这是有效的，因为它系统地探索了所有有效的可能性。 然而，它的成本不必要地高，因为该问题具有更强的数学结构。 我们实际上并不关心选择的确切数字，只关心它们的最终数字贡献。 

### 最佳解决方案的关键见解

 关键的观察是**只有个位数字重要**。 

假设我们选择`x`数字。 由于每个数字都以`k`，其和的个位数为：```
(x * k) % 10
```为了使总和相等`num`，个位数字必须匹配：```
(x * k) % 10 == num % 10
```我们还必须确保总金额不超过`num`：```
x * k <= num
```因为每个选择的数字至少是`k`。 

由于个位数字每重复一次`10`乘法，我们只需要测试：```
x = 1 to 10
```如果我们找到一个有效的`x`，它自动是最小值，因为我们按升序检查。 

这就把问题变成了一个非常小的枚举问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(num²) | O(数字) | 对可能总和的动态规划 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 最多尝试 10 种可能的计数 |

 ## 算法演练

 1. **处理特殊情况`num = 0`.**

 如果目标和为零，则空集有效，因此返回`0`。 
2. **尝试其中所有可能数量的元素`1`到`10`.**

 我们只需要测试十种可能性，因为个位数字重复模数`10`。 十次乘法之后，该模式开始重复。 
3. **检查个位是否匹配。**

 对于每个候选人计数`count`，计算：```
(count * k) % 10
```如果这等于`num % 10`，则满足最后一位数字的要求。 
4. **检查总的最小金额是否可行。**

 由于每个数字必须是正数并且以`k`，我们可以选择的最小可能数是`k`本身。 所以：```
count * k <= num
```必须持有。 
5. **返回第一个有效计数。**

 因为我们从最小到最大迭代，所以第一个有效计数保证是最小的。 
6. **返回`-1`如果没有计数有效。**

 如果十种可能性中没有一个满足这两个条件，则不存在有效的集合。 

### 为什么它有效

 关键的不变量是**和的个位数字仅取决于其组成部分的个位数**。 由于每个选定的数字都以`k`，选择`x`数字总是贡献个位数：```
(x * k) % 10
```模循环每重复一次`10`，所以检查超出`10`计数只会重复以前的模式。 可行性条件`x * k <= num`保证通过将某些数字增加数倍实际上可以达到所需的总和`10`。 因此，第一个有效的`x`找到的总是最小的答案。 

## Python 解决方案```python
class Solution:
    def minimumNumbers(self, num: int, k: int) -> int:
        if num == 0:
            return 0

        for count in range(1, 11):
            if (count * k) % 10 == num % 10 and count * k <= num:
                return count

        return -1
```### 实现说明

 第一个条件检查是否`num`为零。 由于允许空集且总和为零，因此我们立即返回`0`。 

接下来，我们迭代`1`到`10`，测试所有可能的集合大小。 我们只需要十次迭代，因为模`10`算术重复。 

对于每位候选人`count`，我们验证两个条件。 

第一个条件：```
(count * k) % 10 == num % 10
```确保总和的个位与`num`。 

第二个条件：```
count * k <= num
```确保可行性。 由于最小的数字结尾为`k`是`k`本身，可实现的最小总和`count`数字是`count * k`。 

一旦这两个条件都满足，我们就返回`count`。 由于我们按升序搜索，因此这保证是最小可能的大小。 

如果不存在有效计数，我们返回`-1`。 

## 解决方案```go
func minimumNumbers(num int, k int) int {
	if num == 0 {
		return 0
	}

	for count := 1; count <= 10; count++ {
		if (count*k)%10 == num%10 && count*k <= num {
			return count
		}
	}

	return -1
}
```### Go 特定的实现差异

 Go 实现遵循与 Python 版本完全相同的逻辑。 由于约束很小，因此不必担心整数溢出。 

与 Python 不同，Go 使用显式的`for`使用整数变量循环：```go
for count := 1; count <= 10; count++
```不需要额外的数据结构，因此实现保持恒定的空间。

 ## 边缘情况

 ###`num = 0`这是最重要的特殊情况。 由于该问题将空集定义为具有总和`0`，正确答案始终是`0`。 幼稚的实现可能会意外返回`-1`因为它从不考虑使用零元素。 实现立即处理这个问题：```
if num == 0:
    return 0
```###`k = 0`什么时候`k = 0`，每个数字必须以`0`，这意味着每个选择的数字都是`10`。 这意味着只有以`0`是可能的。 例如：```
num = 11, k = 0
```无法工作，因为个位不匹配。 模检查自然地处理这种情况，无需任何特殊逻辑。 

＃＃＃ 小的`num`相比`k`一个常见的错误是假设如果`num < k`，答案一定是不可能的。 这是不正确的，因为有效数字可能大于`k`虽然仍然结束于`k`。 

例如：```
num = 12, k = 2
```有效是因为`[12]`是有效的。 该实现正确地检查个位数字关系，而不是仅比较幅度。 

### 没有有效的单位数字组合

 有些输入是不可能的，因为重复添加`k`永远不会产生所需的个位数。 

例如：```
num = 37, k = 2
```产生重复个位数字：```
2, 4, 6, 8, 0
```并且永远不会达到`7`。 算法安全返回`-1`在检查了所有十种可能性之后。
