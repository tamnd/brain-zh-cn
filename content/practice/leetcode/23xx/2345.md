 # LeetCode 2345 - 找出可见山脉的数量

 ## 问题理解

 每座山峰都由一个峰点表示`(x, y)`。 因为山是一个有坡度的直角等腰三角形`+1`和`-1`，它的形状完全由它的峰值决定。 

对于一座有峰的山`(x, y)`：

 - 左边界接触 x 轴`x - y`- 右边界与 x 轴相交的位置为`x + y`所以每座山都可以表示为一个区间：$$[x - y,\ x + y]$$如果一座山的山峰不在另一座山的内部或边界上，则该山被认为是可见的。 

就是山的意思`A`隐藏山`B`如果：$$A.left \le B.left \quad \text{and} \quad A.right \ge B.right$$在区间术语中，一个区间完全包含另一个区间。 

输入是一个数组`peaks`，其中每个元素包含山峰的坐标。 输出是考虑所有重叠和包含后仍然可见的山脉数量。 

约束条件很重要：

 - 最多`10^5`山
 - 坐标高达`10^5`一个`O(n^2)`解决方案需要检查每一对山，而且速度太慢。 我们需要更接近的东西`O(n log n)`。 

有几种棘手的边缘情况：

 - 完全相同的山脉，例如`[[1,3],[1,3]]`- 只触及边界的山脉
 - 山脉嵌套在更大的山脉中
 - 左边界相同但右边界不同的山脉

 声明明确表示，位于边界的山峰也被认为是隐藏的，因此在遏制检查期间平等很重要。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将每座山与其他山进行比较。 

首先，将每座山转换为区间：$$[left,\ right] = [x-y,\ x+y]$$然后对于每座山`i`，扫描所有其他山脉`j`并检查是否：$$left_j \le left_i \quad \text{and} \quad right_j \ge right_i$$如果存在这样一座山，那么山`i`被隐藏。 

这是可行的，因为区间包含与几何可见性条件完全匹配。 

然而，这种方法需要检查每一对山，从而导致`O(n^2)`时间复杂度。 和`n = 100000`，这变得太慢了。 

### 最佳方法

 关键的见解是排序后可以有效地检测区间包含。 

假设我们按以下方式对山脉进行排序：

 1.增加左边界
 2. 当左边界相等时减少右边界

 为什么要减少关系的右边界？ 

考虑：

-`[1,10]`-`[1,7]`较大的间隔必须先出现，否则在我们处理较大的包含间隔之前，较小的间隔可能会错误地显示为可见。 

排序后，我们从左向右扫描，同时跟踪迄今为止看到的最大右边界。 

如果当前山的右边界小于或等于已经遇到的最大右边界，则某些较早的山完全包含它，因此它被隐藏。 

我们还需要对重复的山脉进行特殊处理，因为相同的山脉相互隐藏。 如果一座山出现多次，则这些副本都不可见。

 ## 算法演练

 1. 将每座山转换为一个区间。 

对于每个峰`(x, y)`：$$left = x - y$$

$$right = x + y$$存储这些间隔以供以后处理。 
2. 计算重复间隔。 

如果相同的间隔出现多次，则所有副本都是不可见的，因为它们的峰值相互重叠。 

频率图可以让我们快速识别重复项。 
3. 对间隔进行排序。 

排序使用：

 - 增加`left`- 减少`right`用于领带

 这种排序保证了当它们共享相同的左边界时，较大的包含间隔出现在较小的嵌套间隔之前。 
4. 扫描已排序的间隔。 

维持：

-`max_right`，迄今为止看到的最大右边界

 对于每个间隔：

 - 如果`right <= max_right`，该区间包含在先前处理的山内
 - 否则，它可能是可见的
 5. 排除重复项。 

即使一个区间不被另一个区间包含，如果它的频率大于 1，它仍然是不可见的。 
6. 计算有效的可见山脉。 

仅在以下情况下增加答案：

 - 不包含区间
 - 间隔是唯一的

 ### 为什么它有效

 排序后，每一个可能包含的山脉都会出现在它可能包含的山脉之前。 扫描不变量是`max_right`始终代表所有先前处理的山脉中最右边的端点。 

如果当前区间的右端点不超过`max_right`，则前一个区间完全包含它。 由于排序的原因，前一个间隔的开始时间也不晚于当前间隔，因此可以保证遏制。 

重复的间隔被单独处理，因为相等的间隔相互隐藏。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def visibleMountains(self, peaks: List[List[int]]) -> int:
        intervals = []
        
        for x, y in peaks:
            left = x - y
            right = x + y
            intervals.append((left, right))
        
        freq = Counter(intervals)
        
        intervals.sort(key=lambda interval: (interval[0], -interval[1]))
        
        visible_count = 0
        max_right = float("-inf")
        
        for left, right in intervals:
            if right > max_right:
                if freq[(left, right)] == 1:
                    visible_count += 1
                
                max_right = right
        
        return visible_count
```实现首先将每座山转换为其区间表示。 这将几何问题简化为区间包含问题。 

一个`Counter`存储每个间隔的频率，以便可以有效地识别重复项。 

然后通过增加左端点和减少右端点对间隔进行排序。 这种排序至关重要，因为它保证当左边界匹配时，较大的间隔会在较小的包含间隔之前被处理。 

扫荡过程中，`max_right`跟踪迄今为止遇到的最右端点。 如果当前间隔超出`max_right`，那么它不包含在任何先前的山之内。 

在将其计数为可见之前，实现会检查该间隔是否恰好出现一次。 重复的区间被排除，因为相同的山脉相互隐藏。 

## 解决方案```go
package main

import (
	"sort"
)

func visibleMountains(peaks [][]int) int {
	type Interval struct {
		left  int
		right int
	}

	intervals := make([]Interval, 0, len(peaks))
	freq := make(map[Interval]int)

	for _, peak := range peaks {
		x, y := peak[0], peak[1]

		interval := Interval{
			left:  x - y,
			right: x + y,
		}

		intervals = append(intervals, interval)
		freq[interval]++
	}

	sort.Slice(intervals, func(i, j int) bool {
		if intervals[i].left == intervals[j].left {
			return intervals[i].right > intervals[j].right
		}
		return intervals[i].left < intervals[j].left
	})

	visibleCount := 0
	maxRight := -1

	for _, interval := range intervals {
		if interval.right > maxRight {
			if freq[interval] == 1 {
				visibleCount++
			}
			maxRight = interval.right
		}
	}

	return visibleCount
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 定制`Interval`使用结构体，因此间隔可以作为频率计数映射中的键。 

去的`sort.Slice`用于实现自定义排序顺序。 由于坐标为正且有界，因此使用`-1`作为初始的`maxRight`价值是安全的。 

与 Python 元组不同，Go 需要结构类型才能在映射中干净地使用复合键。

 ## 边缘情况

 ### 重复的山脉

 当两座或多座山峰具有相同的山峰时，它们就会产生相同的间隔。 根据问题陈述，山峰位于另一座山边界上的山是不可见的。 因此，相同的山脉相互隐藏。 

一个常见的错误是将一份副本计为可见，因为它在排序过程中首先出现。 该实现通过存储间隔频率并仅计算恰好出现一次的间隔来避免这种情况。 

### 相同的左边界

 考虑如下间隔：```
[1,10]
[1,7]
```如果排序不正确，则可能会先处理较小的间隔并错误地将其计为可见。 

通过增加左边界和减少右边界进行排序可保证较大的间隔首先出现，从而允许扫描逻辑正确地将较小的间隔识别为隐藏。 

### 边境遏制

 该问题表明位于边界的山峰也被隐藏了。 这意味着平等很重要。 

例如：```
[1,9]
[3,9]
```第二个间隔恰好在第一个间隔结束的地方结束。 它仍然被认为是隐藏的。 

这就是该算法使用的原因：```
right > max_right
```而不是：```
right >= max_right
```平等必须被视为遏制。
