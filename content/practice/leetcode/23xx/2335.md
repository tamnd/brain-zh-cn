 **难度：** 🟢简单

 ## 解决方案

 ## 问题理解

 问题给了我们一个数组`amount`长度`3`。 每个索引代表特定水类型需要填充的杯子数量：

 -`amount[0]`代表冷水杯
 -`amount[1]`代表温水杯
 -`amount[2]`代表热水杯

 每一秒，机器都可以执行以下操作之一：

 1. 填充任意类型的杯子
 2. 同时填充两个杯子，但前提是它们是不同类型的

 目标是确定装满所有杯子所需的最短秒数。 

重要的细节是，当仍然有两种不同的水类型时，机器会变得更加高效。 如果至少有两个类别仍然包含杯子，我们应该尽可能在一秒钟内装满两个杯子。 

限制非常小：

 - 数组长度始终为`3`- 每个值都介于`0`和`100`由于输入量很小，几乎任何合理的算法都会快速运行。 然而，问题主要是关于识别确定最佳答案的数学观察。 

一些边缘情况很重要：

 - 一个类别可能主导所有其他类别，例如`[10,1,1]`- 某些类别可能已经为空，例如`[5,0,0]`- 所有类别都可以是平衡的，例如`[4,4,4]`- 所有值都可以为零，例如`[0,0,0]`当一个类别比其他类别大得多时，简单的实现可能会犯错误。 即使我们有效地配对杯子，最终最大的类别可能仍然需要单独的填充操作。 

## 方法

 ### 蛮力方法

 简单的模拟方法每秒重复执行尽可能最佳的操作。 

每一步：

 1. 对三个金额进行排序
 2. 如果两个最大值都是正数，则将两者都递减
 3. 否则减少单个剩余正值
 4. 计算用了多少秒

 这种贪婪的模拟之所以有效，是因为我们每一秒都试图通过尽可能地装满两个杯子来最大限度地提高效率。 

尽管这种方法完全有效，但它在每次操作期间都会重复对数组进行排序或扫描。 由于值很小，因此运行速度仍然足够快，但这不是最优雅的解决方案。 

### 最佳解决方案的关键见解

 最佳解决方案来自于观察答案的两个下限。 

首先，每秒最多可以装满两个杯子。 所以：$$\text{minimum time} \geq \left\lceil \frac{\text{total cups}}{2} \right\rceil$$如果杯子总数是`sum`，那么即使在最好的情况下，我们也至少需要一半的秒数。 

其次，最大的类别创造了另一个下限。 假设一种类型包含的杯子比其他两种类型的杯子总和还要多。 最终，较小类别的杯子将会用完，而最大类别的剩余杯子必须一次装满一个。 

所以：$$\text{minimum time} \geq \max(amount)$$值得注意的是，答案只是这两个界限中较大的一个：$$\text{answer} = \max\left(\max(amount), \left\lceil \frac{\sum amount}{2} \right\rceil\right)$$这是有效的，因为：

 - 如果罩杯足够平衡，则配对操作占主导地位，因此答案基于罩杯总数
 - 如果一个类别占主导地位，则答案基于最大的一堆

 ## 算法演练

 ### 最优算法

 1. 通过将所有三个值相加来计算杯子总数。 

这告诉我们必须完成多少总工作。 
2. 计算三个类别中的最大值。 

这可以确定一种水类型是否主导其他水类型。 
3. 根据总杯数计算可能的最短时间。 

由于一秒钟最多可以装满两个杯子，因此我们至少需要：$$\left\lceil \frac{\text{total}}{2} \right\rceil$$在整数算术中，这可以写成：$$\frac{total + 1}{2}$$4. 返回以下值之间的较大值：

 - 最大的类别
 - 总杯数的一半向上取整

 这保证了两个约束都得到满足。 

### 为什么它有效

 有两个不可避免的限制。 

第一个限制来自吞吐量。 由于每秒最多可以填充两个杯子，因此总工作量在几秒钟内至少需要一半的杯子。 

第二个限制来自不平衡。 如果一个类别包含的杯子比其他类别多得多，最终其他类别就会消失，迫使剩余的杯子被一个接一个地处理。 

最优策略总是达到较大的下界，这证明了公式是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def fillCups(self, amount: List[int]) -> int:
        total_cups = sum(amount)
        largest_group = max(amount)

        minimum_by_pairing = (total_cups + 1) // 2

        return max(largest_group, minimum_by_pairing)
```实现直接遵循数学推导。 

首先，我们使用以下方法计算杯子总数`sum(amount)`。 这给出了总工作量。 

接下来，我们使用计算最大类别`max(amount)`。 这捕获了不平衡约束。 

表达式`(total_cups + 1) // 2`对整数执行上限除法。 例如：

-`5`变成`3`-`6`变成`3`最后，我们返回两个下界中较大的一个。 

该实现非常紧凑，因为主要挑战是识别问题背后的数学属性。 

## 解决方案```go
func fillCups(amount []int) int {
	totalCups := amount[0] + amount[1] + amount[2]

	largestGroup := amount[0]
	if amount[1] > largestGroup {
		largestGroup = amount[1]
	}
	if amount[2] > largestGroup {
		largestGroup = amount[2]
	}

	minimumByPairing := (totalCups + 1) / 2

	if largestGroup > minimumByPairing {
		return largestGroup
	}

	return minimumByPairing
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 不提供内置的`max`或者`sum`切片的函数，因此我们手动计算它们。 

Go 中的整数除法会自动截断为零，因此`(totalCups + 1) / 2`正确执行正整数的上限除法。 

不存在溢出问题，因为所有值最多都是`100`，使得总数最多`300`。

 ## 边缘情况

 ### 只有一个非零类别

 像这样的输入`[5,0,0]`很重要，因为配对操作是不可能的。 有缺陷的实现可能会错误地假设两个杯子始终可以一起处理。 

该公式自然地处理了这个问题，因为最大的类别成为主导下界。 答案正确变为`5`。 

### 完美平衡的类别

 像这样的输入`[4,4,4]`代表理想的配对场景。 每秒可处理两个杯子，直至完成。 

杯子总数为`12`，所以答案就变成：$$12 / 2 = 6$$该实现正确地识别出吞吐量限制占主导地位。 

### 一个类别大于其他类别的总和

 像这样的输入`[10,1,1]`是逻辑错误的常见根源。 

最初，一些杯子可以配对：

 -`10`和`1`-`9`和`1`之后，只剩下一个类别，迫使对剩余的杯子进行单独处理。 

公式正确返回`10`，因为最大的类别超过了总工作量的一半。 

### 所有值均为零

 像这样的输入`[0,0,0]`检查实现是否正确处理空工作。 

总杯数和最大类别都为零，所以答案是零。 该实现自然地返回此值，无需任何特殊处理。
