[LeetCode 问题 2348](https://leetcode.com/problems/number-of-zero-filled-subarrays/)

 **难度：** 🟡 中等
 **主题：** 数组、数学

 ## 解决方案

 ## 问题理解

 该问题要求我们计算整数数组中连续子数组的数量`nums`完全由零组成。 子数组定义为原始数组中任意连续的元素序列。 输入数组可以包含范围内的任何整数`-10^9`到`10^9`，数组长度可达`10^5`，这很重要，因为它排除了具有二次或更高复杂度的算法。 

输出是一个整数，表示仅由零组成的子数组的总数。 每个连续的零序列贡献多个子数组。 例如，长度的序列`k`零贡献`1 + 2 + ... + k = k*(k+1)/2`子数组。 

重要的边缘情况包括根本没有零的数组、全零的数组以及出现在数组开头或结尾的零序列。 该问题保证数组中至少有一个元素，因此空输入不需要处理。 

## 方法

 **暴力方法**涉及检查数组中每个可能的子数组，并在所有元素都为零时对其进行计数。 具体来说，可以使用嵌套循环：外部循环从索引处开始子数组`i`，内部循环将子数组扩展到索引`j`同时检查所有元素是否来自`i`到`j`为零。 虽然这种方法是正确的，但对于大型数组来说太慢了，因为它有`O(n^2)`最坏情况下的时间复杂度，其中`n`是数组的长度。 

**最佳方法**依赖于零形成连续块的观察。 我们可以计算每个连续零块的长度，而不是单独检查所有子数组。 如果零块的长度`k`，它贡献的零填充子数组的数量是`k*(k+1)/2`。 我们迭代数组一次，维护连续零的运行计数，并将以每个零结尾的子数组的计数添加到结果中。 当遇到非零元素时，我们重置运行计数。 这种方法在时间上是线性的并且使用恒定的空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 检查所有可能的子数组，对于大数组来说太慢 |
 | 最佳| O(n) | O(1) | O(1) | 有效计算连续零块并对子数组求和 |

 ## 算法演练

 1.初始化两个变量：`total`存储零填充子数组的累积计数和`current_zeros`存储当前连续零块的长度。 
2. 遍历数组中的每个元素`nums`。 
3. 如果当前元素是`0`, 增量`current_zeros`1. 添加`current_zeros`到`total`。 这是有效的，因为索引为零`i`将所有先前的零子数组扩展一，并且还计算仅由该零组成的子数组。 
4. 如果当前元素非零，则重置`current_zeros`至 0。 
5. 继续此过程直到数组末尾。 
6. 返回`total`。 

**为什么有效：** 连续序列中的每个零都会贡献多个子数组，并且运行计数`current_zeros`捕获这种增量贡献。 通过求和`current_zeros`在每一步中，我们都会考虑所有可能的零填充子数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def zeroFilledSubarray(self, nums: List[int]) -> int:
        total = 0
        current_zeros = 0
        for num in nums:
            if num == 0:
                current_zeros += 1
                total += current_zeros
            else:
                current_zeros = 0
        return total
```该代码循环访问数组一次。 对于每个零，它都会增加`current_zeros`计数器并将其添加到`total`。 对于非零元素，计数器被重置。 这直接实现了最佳方法，有效地计算所有零填充的子数组。 

## 解决方案```go
func zeroFilledSubarray(nums []int) int64 {
    var total int64 = 0
    var currentZeros int64 = 0
    for _, num := range nums {
        if num == 0 {
            currentZeros += 1
            total += currentZeros
        } else {
            currentZeros = 0
        }
    }
    return total
}
```在 Go 中，我们使用`int64`为了`total`和`currentZeros`处理大额金额而不会溢出。 循环逻辑反映了 Python 解决方案，迭代每个元素并增量计数零填充的子数组。

 ## 边缘情况

 一种重要的边缘情况是单元素数组。 如果元素为零，函数应返回 1； 如果它非零，则函数应返回 0。实现通过简单地遵循相同的迭代逻辑来处理此问题。 

另一种边缘情况是完全由零组成的数组。 这可以产生大量的子数组，最多`n*(n+1)/2`。 使用运行计数器可确保算法正确计算所有子数组，而无需显式存储它们。 

第三种边缘情况是出现在数组开头或结尾的零。 因为我们仅在遇到非零元素时重置计数器，所以两端的零序列都会被正确计数，从而保持所有位置的正确性。
