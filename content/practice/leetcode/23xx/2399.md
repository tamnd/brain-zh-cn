[LeetCode 问题 2399](https://leetcode.com/problems/check-distances- Between-same-letters/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 这个问题要求我们验证一个字符串在重复字符之间是否遵循非常特定的间距规则。 

我们得到一个字符串`s`仅包含小写英文字母。 字符串中出现的每个字符恰好出现两次。 我们还给出了一个整数数组`distance`尺寸的`26`，其中每个索引对应于字母表中的一个字母：

 -`distance[0]`对应于`'a'`-`distance[1]`对应于`'b'`- 依此类推，直到`'z'`对于字符串中出现的每个字符，我们必须检查其两次出现之间的字符数是否与字符串中的预期值匹配`distance`大批。 

例如，假设角色`'a'`出现在索引处`2`和`5`。 

它们之间的字符数为：```
5 - 2 - 1 = 2
```所以`'a'`仅当以下情况下才有效`distance[0] == 2`。 

目标是返回：

 -`true`如果每个字符都满足其所需的间距
 -`false`否则

 限制非常小：

 - 最大字符串长度为`52`- 仅使用小写英文字母
 - 每个字母恰好出现两次

 由于输入很小，几乎任何合理的方法都会通过。 然而，这个问题对于练习索引、散列和字符映射仍然有用。 

一个重要的细节是字符串中不存在的字母应该被完全忽略。 即使`distance[i]`包含一些值，除非相应的字符出现在`s`。 

有几种边缘情况值得考虑：

 - 两个相同的字母可能会彼此相邻出现，这意味着所需的距离是`0`- 字符在字符串中可能出现的距离很远
 - 第一个不匹配应该立即返回`false`- 由于每个字符恰好出现两次，因此我们永远不需要处理同一字母两次以上的出现

 ## 方法

 ### 蛮力方法

 强力解决方案将检查每个字符并搜索字符串的其余部分以查找其第二次出现。 

对于每个索引`i`:

 1. 塑造性格`s[i]`2. 向前搜索，直到找到相同的字符
 3. 计算它们之间的字母数量
 4. 与所需值进行比较`distance`这种方法之所以有效，是因为它直接检查问题陈述中定义的条件。 

然而，搜索第二次出现可能需要重复扫描字符串的大部分内容。 如果字符串长度为`n`，最坏情况的复杂度变为`O(n²)`。 

尽管约束足够小，该解决方案可以通过，但与我们可以实现的目标相比，它的效率较低。 

### 最佳方法

 关键的观察是我们只需要记住每个字符出现的第一个位置。 

当我们第一次遇到一个字符时，我们存储它的索引。 

当我们再次遇到它时：

 1. 检索第一个索引
 2. 计算两个位置之间的字符数
 3. 与预期距离比较

 哈希映射或固定大小的数组在这里完美工作，因为只有`26`小写字母。 

这将时间复杂度降低到线性时间，`O(n)`。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复向前扫描以查找匹配的字符 |
 | 最佳| O(n) | O(1) | O(1) | 存储每个字符的首次出现索引 |

 ## 算法演练

 ### 最优算法

 1. 创建一个数据结构来存储每个字符第一次出现的索引。 

由于只有`26`小写字母，我们可以使用：

 - 哈希映射
 - 长度固定的数组`26`数组稍微简单一些并且速度更快。 
2. 将所有位置初始化为`-1`。 

价值`-1`表示该角色尚未出现。 
3. 从左到右遍历字符串。 
4. 对于每个字符：

 - 使用以下方法将字符转换为整数索引：```
ord(character) - ord('a')
```5. 检查该字符以前是否出现过。 

- 如果没有，则将当前索引存储为它的第一次出现。 
- 如果是，计算出现次数之间的距离。 
6. 计算两个位置之间的字母数。 

如果第一次出现在`firstIndex`当前索引是`i`， 然后：```
actualDistance = i - firstIndex - 1
```7. 比较`actualDistance`与预期值`distance`大批。 

- 如果不同，则返回`false`立即地。 
- 否则继续扫描。 
8. 如果整个字符串处理完毕没有不匹配，则返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为每个字符恰好出现两次。 通过存储每个字符的第一次出现，我们可以精确计算第二次出现时的间距。 

每隔一次，算法就会验证问题所需的确切条件。 如果所有字符都满足条件，则字符串间隔良好。 如果任何字符失败，则该字符串的间距不合适。 

## Python 解决方案```python
from typing import List

class Solution:
    def checkDistances(self, s: str, distance: List[int]) -> bool:
        first_seen = [-1] * 26

        for index, char in enumerate(s):
            char_index = ord(char) - ord('a')

            if first_seen[char_index] == -1:
                first_seen[char_index] = index
            else:
                actual_distance = index - first_seen[char_index] - 1

                if actual_distance != distance[char_index]:
                    return False

        return True
```实现首先创建一个名为的数组`first_seen`。 每个位置对应于字母表中的一个字母，存储的值表示该字符出现的第一个索引。 

当我们迭代字符串时，我们使用 ASCII 算术将每个字符转换为其字母表索引。 

如果该字符之前没有出现过，我们存储当前索引。 

如果它已经出现，我们计算两次出现之间的字符数，并将其与中所需的值进行比较`distance`。 

一旦我们检测到不匹配，我们就返回`False`。 这种提前终止可以避免不必要的工作。 

如果循环成功完成，则每个字符都满足间距规则，因此我们返回`True`。 

## 解决方案```go
func checkDistances(s string, distance []int) bool {
	firstSeen := make([]int, 26)

	for i := 0; i < 26; i++ {
		firstSeen[i] = -1
	}

	for i, char := range s {
		charIndex := int(char - 'a')

		if firstSeen[charIndex] == -1 {
			firstSeen[charIndex] = i
		} else {
			actualDistance := i - firstSeen[charIndex] - 1

			if actualDistance != distance[charIndex] {
				return false
			}
		}
	}

	return true
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个小区别是 Go 数组和切片默认为`0`，所以我们显式地将所有条目初始化为`-1`代表看不见的字符。 

这`range`字符串上的循环返回符文位置和符文值。 由于输入仅包含小写英文字母，因此符文处理在这里既简单又安全。 

不存在整数溢出问题，因为最大字符串长度仅为`52`。

 ## 边缘情况

 ### 相邻的相同字符

 像这样的字符串`"aa"`是一个重要的边缘情况，因为两次出现之间的距离是`0`。 一个常见的错误是忘记`-1`计算索引之间的字符数时。 

实现正确计算：```
1 - 0 - 1 = 0
```这符合预期的定义。 

### 字符出现的距离很远

 字符可能出现在字符串的开头和结尾附近。 在这些情况下，不正确的索引逻辑很容易产生相差一的错误。 

The formula:```
secondIndex - firstIndex - 1
```正确地只计算严格位于两个位置之间的字符。 

### 字符串中不存在的字符

 的`distance`数组总是有`26`值，但许多字母可能根本不会出现在字符串中。 

有缺陷的实现可能会错误地尝试验证每个字母字符。 

这个实现只检查遍历过程中遇到的字符，因此未使用的字母自然会被忽略，完全按照问题陈述的要求。
