[LeetCode 问题 2367](https://leetcode.com/problems/number-of-arithmetic-triplets/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、两个指针、枚举

 ## 解决方案

 ## 问题理解

 该问题要求我们在严格递增的整数数组中找到算术三元组的数量。 算术三元组`(i, j, k)`满足条件`i < j < k`,`nums[j] - nums[i] == diff`， 和`nums[k] - nums[j] == diff`。 本质上，我们正在寻找数组中三个元素的序列，其中连续元素之间的差异恰好是`diff`。 

输入是严格递增的数组`nums`，保证没有重复的数字并确保所有差异都是正数。 输出是一个整数，表示有效三元组的计数。 约束表明`nums`最多有 200 个元素，值在 0 到 200 之间，并且`diff`介于 1 到 50 之间。考虑到这些限制，多次迭代数组的简单解决方案是可行的，但我们可以使用哈希集进行常量时间查找来进一步优化。 

重要的边缘情况包括非常小的数组，其中不存在三元组，情况`diff`大于数组中的最大差值，并且多个三元组共享一些元素的数组。 

## 方法

 暴力方法涉及三个嵌套循环。 我们迭代所有可能的三元组`(i, j, k)`并检查它们是否满足算术条件。 这保证了正确性，但时间复杂度为 O(n^3)，这对于`n <= 200`。 

最佳方法利用哈希集进行恒定时间查找。 我们迭代每个元素`num`在数组中并检查是否两者`num - diff`和`num - 2*diff`存在于先前见过的数字集合中。 如果两者都存在，那么`num`完成算术三元组。 这将时间复杂度降低到 O(n)，并且需要 O(n) 额外的空间来存储该集合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 显式检查所有可能的三元组 |
 | 最佳| O(n) | O(n) | 使用哈希集来检查恒定时间的差异 |

 ## 算法演练

 1.初始化一组`seen`跟踪我们已经处理过的所有数字。 
2. 初始化计数器`count`为零以跟踪有效三元组的数量。 
3. 迭代每个数字`num`在数组中`nums`。 
4.对于当前`num`，检查是否两者`num - diff`和`num - 2*diff`存在于`seen`。 
5. 如果两个数字都存在于`seen`, 增量`count`减 1 因为`num`完成一个有效的算术三元组。 
6. 添加`num`到`seen`设置为将来检查。 
7.处理完所有数字后，返回值`count`。 

**为什么有效：** 该算法有效是因为对于任何数字`num`要形成有效的三元组，前面的两个数字用`diff`一定已经出现了。 使用集合可确保这些查找是恒定时间的，并且由于我们只对每个元素检查一次有效序列，因此可以避免重复计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def arithmeticTriplets(self, nums: List[int], diff: int) -> int:
        seen = set()
        count = 0
        for num in nums:
            if (num - diff) in seen and (num - 2 * diff) in seen:
                count += 1
            seen.add(num)
        return count
```实现迭代通过`nums`同时保留一组以前见过的数字。 对于每个`num`，它检查是否两者`num - diff`和`num - 2*diff`都在集合中。 如果是这样，它就会增加计数器。 然后将该数字添加到`seen`用于后续迭代。 这直接对应于算法演练。 

## 解决方案```go
func arithmeticTriplets(nums []int, diff int) int {
    seen := make(map[int]bool)
    count := 0
    for _, num := range nums {
        if seen[num - diff] && seen[num - 2*diff] {
            count++
        }
        seen[num] = true
    }
    return count
}
```在 Go 中，我们使用整数到布尔值的映射来模拟集合。 逻辑与Python版本相同。 地图跟踪已​​处理的数字，当在地图中找到两个所需的差异时，我们会增加计数器。

 ## 边缘情况

 一个重要的边缘情况是最小数组长度为 3。在这里，算法可以正确识别是否存在单个三元组，而无需进行不必要的迭代。 另一个边缘情况是当`diff`大于数组中任何可能的差异。 在这种情况下，算法自然找不到三元组，因为集合查找失败。 第三种边缘情况涉及重叠的三元组，其中相同的数字构成多个三元组。 该算法正确地处理了这个问题，因为它只检查集合中的相对差异并对每个有效序列精确计数一次。 由于严格递增的性质，所有其他可能的无效序列都会被自动忽略`nums`。
