[LeetCode 问题 2373](https://leetcode.com/problems/largest-local-values-in-a-matrix/)

 **难度：** 🟢简单
 **主题：** 数组、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`n x n`方阵称为`grid`，其中每个单元格包含一个整数值。 我们的任务是构建一个新的矩阵，称为`maxLocal`，其尺寸为`(n - 2) x (n - 2)`。 

对于输出矩阵中的每个有效位置，我们检查一个连续的`3 x 3`子矩阵在`grid`。 这个的中心`3 x 3`窗口对应行`i + 1`和列`j + 1`， 在哪里`(i, j)`的位置是`maxLocal`。 我们必须确定其中的**最大值**`3 x 3`区域并将其放入`maxLocal[i][j]`。 

简单来说，想象滑动一个`3 x 3`从左到右、从上到下穿过矩阵的窗口。 对于该窗口的每个可能位置，我们记录其中的最大数量。 

例如，如果矩阵是`4 x 4`，只有`2 x 2`有效的`3 x 3`窗口，因为窗口不能延伸到边界之外。 这解释了为什么结果矩阵总是有维度`(n - 2) x (n - 2)`。 

这些约束告诉我们一些重要的事情：

 -`3 <= n <= 100`，意味着矩阵相对较小。 
- 每个值都介于`1`和`100`。 
- 矩阵始终是方阵。 

自从`n`至多是`100`，即使具有嵌套循环的解决方案也是完全可以接受的。 我们不需要非常高级的优化。 

有几个重要的边缘情况需要考虑。 最小有效矩阵大小是`3 x 3`，这意味着恰好存在一个可能的窗口，并且输出变为`1 x 1`矩阵。 另一个重要的情况是所有数字都相同，因为每个输出单元都应该具有相同的值。 我们还需要处理最大值位于边缘或角落的情况`3 x 3`窗口，确保我们检查该区域的每个单元格，而不仅仅是中心。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代所有可能的`3 x 3`子矩阵并显式检查其中的所有九个元素。 

对于每个有效的左上角`(row, col)`的一个`3 x 3`窗口，我们扫描整个`3 x 3`面积，计算最大值，并将其放入输出矩阵。 

这种方法是正确的，因为每个输出单元完全对应于一个连续的`3 x 3`区域，通过检查该区域内的每个元素，我们保证找到最大值。 

缺点是我们重复检查重叠区域。 邻接`3 x 3`窗口共享许多单元格，因此某些值会被多次重新访问。 不过，由于矩阵尺寸很小，这种重复工作是没有问题的。 

### 最佳方法

 关键的观察是问题约束足够小，可以直接扫描每个`3 x 3`window 已经很高效了。 

我们不需要尝试复杂的预处理或滑动窗口最大优化，而是简单地迭代每个有效的中心位置并计算周围的最大值`3 x 3`堵塞。 

由于每个块恰好包含`9`细胞，每个窗口的工作是恒定的。 窗口数量为`(n - 2)^2`，因此总运行时间仍然有效。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × 9) | O((n - 2)²) | 显式扫描每个中的所有 9 个单元`3 x 3`窗口|
 | 最佳| O(n²) | O((n - 2)²) | 相同的实用策略，因为每个窗口大小都是恒定的 |

 尽管两种描述看起来很相似，但重要的区别是所谓的暴力运行时简化为`O(n²)`因为`3 x 3`大小是固定且恒定的。 

## 算法演练

 1.确定输入矩阵的大小`n`。 
2. 创建一个具有维度的空结果矩阵`(n - 2) x (n - 2)`。 该矩阵将存储每个的最大值`3 x 3`地区。 
3. 遍历 a 的每个有效的左上角位置`3 x 3`子矩阵。 自从一个`3 x 3`窗口必须保持在边界内，行索引范围为`0`到`n - 3`，并且列索引遵循相同的范围。 
4. 对于每个位置`(row, col)`，初始化一个变量来跟踪当前的最大值。 
5. 使用两个嵌套循环来检查所有`9`内的细胞`3 x 3`地区：

 - 行范围从`row`到`row + 2`- 列范围从`col`到`col + 2`6. 当发现更大的数字时更新最大值。 
7. 将计算出的最大值存储到`result[row][col]`。 
8. 处理完每个有效窗口后，返回完成的结果矩阵。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的输出位置恰好对应于一个连续的`3 x 3`原始网格中的子矩阵。 通过详尽地检查每个子矩阵内的所有九个单元格，我们保证记录的值是真正的最大值。 由于每个有效窗口都被处理一次，因此每个输出单元都被正确计算。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestLocal(self, grid: List[List[int]]) -> List[List[int]]:
        n = len(grid)

        result = [[0] * (n - 2) for _ in range(n - 2)]

        for row in range(n - 2):
            for col in range(n - 2):
                local_max = 0

                for r in range(row, row + 3):
                    for c in range(col, col + 3):
                        local_max = max(local_max, grid[r][c])

                result[row][col] = local_max

        return result
```实现首先确定矩阵大小`n`。 由于输出尺寸始终为`(n - 2) x (n - 2)`，我们初始化`result`具有正确大小的零的矩阵。 

外部两个循环迭代 a 的每个可能的左上角位置`3 x 3`窗户。 对于每个窗口，`local_max`跟踪遇到的最大值。 

内部嵌套循环正好扫描九个单元格，覆盖完整的`3 x 3`地区。 在此扫描过程中，我们反复更新`local_max`使用Python的内置`max()`功能。 

检查整个区域后，我们将计算出的最大值放入相应的输出位置。 处理完每个窗口后，将返回最终矩阵。 

## 解决方案```go
func largestLocal(grid [][]int) [][]int {
	n := len(grid)

	result := make([][]int, n-2)
	for i := range result {
		result[i] = make([]int, n-2)
	}

	for row := 0; row < n-2; row++ {
		for col := 0; col < n-2; col++ {
			localMax := 0

			for r := row; r < row+3; r++ {
				for c := col; c < col+3; c++ {
					if grid[r][c] > localMax {
						localMax = grid[r][c]
					}
				}
			}

			result[row][col] = localMax
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 主要区别在于内存分配。 在 Go 中，我们使用显式分配二维结果切片`make()`。 

而不是使用内置的`max()`函数，Go 手动将值与`if`陈述。 整数溢出不是问题，因为最大网格值只是`100`。 Since the input constraints guarantee at least a`3 x 3`矩阵，我们不需要额外的边界验证。

 ## 边缘情况

 ### 最小矩阵大小，`n = 3`最小的有效输入恰好包含 1`3 x 3`地区。 如果循环边界不正确，这可能会导致差一错误。 我们的实现自然地处理了这个问题，因为`n - 2 = 1`，因此结果矩阵变为`1 x 1`，并且只处理一个窗口。 

### 最大显示在窗口边框上

 一个常见的错误是无意中忽略了边界单元并仅关注中心或内部。 由于该问题要求求任意位置的最大值`3 x 3`区域中，最大值可能出现在角落或边缘。 我们的嵌套循环显式扫描所有九个位置，确保没有跳过任何单元格。 

### 重复或相同的值

 如果所有数字都相同，则每个输出条目都应与该重复值匹配。 某些实现可能会错误地重置窗口之间的状态或错误处理比较。 因为我们独立地重新计算每个窗口的最大值，所以重复的值会被正确处理。 

### 高度重叠的窗口

 邻近`3 x 3`窗口共享许多单元格，这有时会导致移动窗口时出现索引错误。 我们的实现通过独立迭代每个有效的左上角坐标并显式扫描周围的坐标来避免此问题`3 x 3`每次区域。
