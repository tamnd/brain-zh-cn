[LeetCode 问题 2328](https://leetcode.com/problems/number-of-increasing-paths-in-a-grid/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、深度优先搜索、广度优先搜索、图论、拓扑排序、记忆化、矩阵

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出一个二维矩阵，称为`grid`。 每个单元格包含一个正整数。 从任何单元格，我们可以向四个方向移动：上、下、左或右。 不允许对角移动。 

目标是计算整个网格中存在多少条严格递增路径。 如果路径中的每个下一个单元格包含比当前单元格更大的值，则该路径被视为严格递增。 

路径可以：

 - 从任何单元格开始
 - 在任意单元格结束
 - 长度为 1，意味着单个单元格本身算作有效路径

 如果两条路径的访问单元序列在任何位置不同，则认为两条路径不同。 

答案可能会变得非常大，因为可能的路径数量增长很快，因此我们必须返回模数结果：$10^9 + 7$约束条件很重要：

 -`m * n <= 100000`- 每个单元格值介于`1`和`100000`这立即告诉我们指数暴力搜索是行不通的。 尽管每个单元最多有四个邻居，但增加的路径数量可能会组合爆炸。 

一个关键的观察结果是，严格增加运动会创建一个有向无环图，缩写为 DAG。 由于值必须严格递增，因此我们永远无法通过循环返回到之前访问过的值。 这种非循环结构使得动态编程和记忆成为可能。 

一些边缘情况很重要：

 - 应该返回只有一个单元格的网格`1`- 所有值都相等的网格应准确返回单元格数量，因为不存在多单元格增加路径
 - 长增长链必须有效处理而无需重新计算
 - 接近最大约束的大型网格需要接近线性的复杂性

 ## 方法

 ### 蛮力方法

 一个简单的解决方案是从每个单元开始深度优先搜索，并递归地探索所有严格递增的邻居。 

对于每条路径，我们都会向所有有效方向扩展搜索。 每次我们访问一个单元序列时，我们都会将其视为一条有效路径。 

这种方法是正确的，因为它明确地枚举了每条递增路径。 然而，它太慢了。 

主要问题是子问题重叠。 假设许多路径最终到达同一个单元格。 从该单元格开始，剩余的增加路径是相同的，但强力解决方案会重复重新计算它们。 

在最坏的情况下，增加路径的数量呈指数增长，使得这种方法对于具有高达`100000`细胞。 

### 最佳方法，DFS + 记忆

 关键的见解是，从一个单元开始的增加路径的数量仅取决于其较大的邻居。 

定义：

-`dp[r][c]`= 从单元格开始的递增路径数`(r, c)`每个细胞至少贡献一条路径，即细胞本身。 

然后我们尝试所有四个方向。 如果相邻像元包含更大的值，我们可以将路径延伸到该邻居。 

这给出了递归式：$dp(r,c)=1+\sum dp(nr,nc)$其中总和是所有严格较大的相邻单元的总和。 

由于增加移动永远不会形成循环，因此记忆保证每个单元格仅计算一次。 

这将指数搜索转换为网格上的线性动态规划解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(路径长度) | 多次重新计算相同的子问题 |
 | 最佳| O(m * n) | O(m * n) | 具有记忆功能的 DFS 对每个单元计算一次 |

 ## 算法演练

 1. 创建一个名为的记忆表`memo`与网格具有相同的尺寸。 

每个条目存储从该单元格开始的递增路径的数量。 最初，所有条目都是未计算的。 
2. 定义四个移动方向。 

我们需要检查：

 - 向上
 - 向下
 - 左
 - 右
 3. 编写DFS函数`dfs(r, c)`。 

该函数返回从单元格开始的严格递增路径的数量`(r, c)`。 
4. 检查当前单元格是否已经被计算过。 

如果`memo[r][c]`非零，立即返回存储的结果。 

这避免了多次重新计算同一子问题。 
5. 将当前单元格的答案初始化为`1`。 

每个单元本身形成一条有效的长度路径`1`。 
6. 探索所有四个相邻单元格。 

对于每个邻居：

 - 验证它位于网格内
 - 验证其值严格大于当前单元格

 如果两个条件都成立，则递归计算从该邻居开始的路径数，并将它们添加到当前答案中。 
7. 每次加法后应用模运算。 

由于路径的数量可能变得非常大，我们总是对值进行模计算：$10^9 + 7$8. 将计算结果存储在`memo[r][c]`。 

未来的 DFS 调用可以立即重用该值。 
9. 迭代网格中的每个单元格。 

称呼`dfs(r, c)`对于每个单元格并累积结果。 
10. 返回最终总模数`10^9 + 7`。 

### 为什么它有效

 该算法之所以有效，是因为严格增加运动保证了非循环依赖结构。 一个单元只依赖于具有较大值的邻居，因此递归总是向较大的数字移动，并且永远不会无限循环。 

记忆化确保每个单元格的结果只计算一次。 由于从单元格开始的每条递增路径都被精确计数一次，并且每个单元格都是独立处理的，因此最终的总和正确地计算了网格中的所有递增路径。 

## Python 解决方案```python
from typing import List

class Solution:
    def countPaths(self, grid: List[List[int]]) -> int:
        MOD = 10**9 + 7

        rows = len(grid)
        cols = len(grid[0])

        memo = [[0] * cols for _ in range(rows)]

        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1)
        ]

        def dfs(r: int, c: int) -> int:
            if memo[r][c] != 0:
                return memo[r][c]

            total_paths = 1

            for dr, dc in directions:
                nr = r + dr
                nc = c + dc

                if (
                    0 <= nr < rows and
                    0 <= nc < cols and
                    grid[nr][nc] > grid[r][c]
                ):
                    total_paths += dfs(nr, nc)
                    total_paths %= MOD

            memo[r][c] = total_paths
            return total_paths

        answer = 0

        for r in range(rows):
            for c in range(cols):
                answer += dfs(r, c)
                answer %= MOD

        return answer
```实现首先定义常量并确定网格尺寸。 

这`memo`表存储先前计算的结果。 值为`0`表示单元格尚未被处理。 

这`directions`list 简化了邻居遍历。 我们不是为每个方向编写单独的逻辑，而是迭代方向偏移。 

这`dfs`函数执行核心动态规划计算。 如果单元格已被求解，则立即返回存储的值。 

每个单元本身至少贡献一条有效路径，因此`total_paths`开始于`1`。 

然后 DFS 检查所有相邻小区。 仅探索具有严格更大值的邻居。 对于每个有效邻居，我们递归地添加从那里开始的递增路径的数量。 

计算完成后，将结果存储在`memo[r][c]`所以以后的调用会重用缓存的值。 

最后，外层循环从每个单元格开始 DFS 并累加总计数。 

## 解决方案```go
func countPaths(grid [][]int) int {
    const MOD int = 1e9 + 7

    rows := len(grid)
    cols := len(grid[0])

    memo := make([][]int, rows)
    for i := range memo {
        memo[i] = make([]int, cols)
    }

    directions := [][]int{
        {1, 0},
        {-1, 0},
        {0, 1},
        {0, -1},
    }

    var dfs func(int, int) int

    dfs = func(r int, c int) int {
        if memo[r][c] != 0 {
            return memo[r][c]
        }

        totalPaths := 1

        for _, dir := range directions {
            nr := r + dir[0]
            nc := c + dir[1]

            if nr >= 0 &&
                nr < rows &&
                nc >= 0 &&
                nc < cols &&
                grid[nr][nc] > grid[r][c] {

                totalPaths += dfs(nr, nc)
                totalPaths %= MOD
            }
        }

        memo[r][c] = totalPaths
        return totalPaths
    }

    answer := 0

    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            answer += dfs(r, c)
            answer %= MOD
        }
    }

    return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 

记忆表是使用嵌套切片创建的。 递归 DFS 函数是使用函数变量声明的，因此它可以递归地引用自身。 

模运算是使用 Go 整数执行的。 由于最终值仍然受模数限制，标准`int`足以满足 LeetCode 的约束。 

使用 Go 切片代替 Python 列表，但动态编程结构保持相同。

 ## 边缘情况

 ### 单细胞网格

 仅包含一个单元格的网格是最小的有效输入。 幼稚的实现可能会意外返回`0`如果它只计算运动形成的路径。 然而，单个单元格本身就是一条有效的长度递增路径`1`。 

该实现正确地处理了这个问题，因为每个 DFS 都以以下内容开头：```
total_paths = 1
```即使不存在邻居，该单元也会贡献一条有效路径。 

### 所有值都相等

 如果所有单元格包含相同的值，则不允许移动，因为路径必须严格递增。 

例如：```
[
    [2, 2],
    [2, 2]
]
```正确答案是`4`，每个单元格一个。 

实施正确地检查：```
grid[nr][nc] > grid[r][c]
```拒绝相等的值，以防止无效转换。 

### 长链不断增加

 考虑一条跨越许多细胞的大蛇状增长路径。 如果没有记忆，递归将多次重复重新计算相同的后缀路径。 

记忆表可以防止这个问题。 一旦计算出单元格的结果，以后的每个 DFS 调用都会立即重用存储的值。 

这种优化将复杂性从指数时间降低到线性时间。
