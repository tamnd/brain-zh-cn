[LeetCode 问题 2320](https://leetcode.com/problems/count-number-of-ways-to-place-houses/)

 **难度：** 🟡 中等
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 问题提出了一条街道`n`每边都有图，总共`2 * n`地块。 目标是计算在这些地块上放置房屋的方式数量，使得没有两栋房屋相邻**在街道的同一侧**。 允许将房屋放置在街道相对两侧的同一索引处，并且不违反相邻规则。 

输入是单个整数`n`，代表街道一侧的地块数量。 由于潜在的数字很大，输出是有效房屋布局配置的总数**模 1_000_000_007**。 

约束表明`1 <= n <= 10^4`, which means a brute-force approach that generates all possible arrangements (which would be exponential in size) is infeasible. 边缘情况包括非常小的`n`价值观像`1`或非常大的值，例如`10^4`。 正确的解决方案必须有效地处理这些问题。 

## 方法

 ### 蛮力

 蛮力方法将尝试生成所有可能的位置`n`每边的地块，然后过滤掉房屋相邻的无效配置。 一方面，有`2^n`可能性，并且对于双方来说，都有`(2^n)^2 = 4^n`总配置。 检查每个配置的邻接性是线性的`n`。 这种方法是正确的，但不可行，因为`n`可以大到`10^4`， 制作`4^n`天文数字般大。 

### 最佳方法

 关键的见解是街道的两侧是独立的。 如果我们首先计算**一侧**的有效排列数量，则街道的排列总数就是**该数字的平方**，因为另一侧可以独立地具有任何有效配置。 

计算一侧的排列可以简化为经典的动态规划问题：“计算将房屋放置在一条线上且没有两个相邻房屋的方法的数量。” 让`dp[i]`是布置房屋的方式的数量`i`地块。 其递归式为：```
dp[i] = dp[i-1] + dp[i-2]
```这种递归之所以有效，是因为对于`i`情节，我们要么把它留空（`dp[i-1]`方式）或在那里放置房屋（`dp[i-2]`方式，因为之前的情节必须是空的）。 基本情况是`dp[0] = 1`（没有情节）和`dp[1] = 2`（空房子或一间房子）。 

最后，总配置数为`dp[n] * dp[n] % MOD`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(4^n) | O(4^n) | O(2^n) | O(2^n) | 生成所有展示位置并过滤无效的展示位置，对于大 n | 不可行
 | 最佳| O(n) | O(1) | O(1) | DP 计算一侧的有效排列，然后对结果求平方 |

 ## 算法演练

 1.定义一个常量`MOD = 10^9 + 7`处理大量数据。 
2.初始化两个变量`prev2 = 1`和`prev1 = 2`，代表`dp[0]`和`dp[1]`分别。 这些存储了在 0 和 1 地块上放置房屋的方式数量。 
3. 迭代`i`从 2 到`n`。 对于每个`i`，计算排列数`i`绘制为`current = (prev1 + prev2) % MOD`。 这实现了斐波那契式递归。 
4. 更新`prev2`到`prev1`和`prev1`到`current`用于下一次迭代。 循环结束后，`prev1`包含`dp[n]`。 
5. 计算双方的排列总数为`(prev1 * prev1) % MOD`。 
6. 返回结果。 

**为什么有效**：DP 递归通过考虑每个图的两种可能性来正确计算单侧的排列。 对结果求平方是有效的，因为两侧是独立的。 模运算确保数字不会溢出。 

## Python 解决方案```python
class Solution:
    def countHousePlacements(self, n: int) -> int:
        MOD = 10**9 + 7
        if n == 0:
            return 1
        
        prev2, prev1 = 1, 2  # dp[0] = 1, dp[1] = 2
        for _ in range(2, n + 1):
            current = (prev1 + prev2) % MOD
            prev2, prev1 = prev1, current
        
        return (prev1 * prev1) % MOD
```该实现首先处理基本情况`n = 0`。 它使用两个变量而不是完整的 DP 数组来节省空间。 循环计算一侧有效排列的数量，最终返回值对其取模进行平方`10^9 + 7`来兼顾双方。 

## 解决方案```go
func countHousePlacements(n int) int {
    const MOD = 1000000007
    if n == 0 {
        return 1
    }
    
    prev2, prev1 := 1, 2
    for i := 2; i <= n; i++ {
        current := (prev1 + prev2) % MOD
        prev2, prev1 = prev1, current
    }
    
    return (prev1 * prev1) % MOD
}
```Go 版本与 Python 几乎相同。 我们使用`const MOD`和用于 DP 计算的整数变量。 Go 通过模运算处理整数溢出，类似于 Python。 不需要切片，因为我们只跟踪最后两个 DP 值。

 ## 边缘情况

 1. **n = 0**：零地块，只有一种方法（没有房子）。 这可能会导致幼稚的实现失败，假设`n >= 1`。 由直接基本案例处理。 
2. **最大 n = 10^4**：确保解决方案可扩展。 仅使用两个变量进行 DP 可确保内存效率。 
3. **所有房屋都空着与所有房屋都填满**：第一个和最后一个地块可以是空的或填满的，测试边界条件。 DP 递归自然地处理这个问题，无需特殊的外壳。 

该实现有效且正确地处理所有这些边缘情况。
