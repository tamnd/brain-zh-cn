[LeetCode 问题 2364](https://leetcode.com/problems/count-number-of-bad-pairs/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们计算数组中**坏对**的数量。 我们得到一个 **0-indexed** 整数数组`nums`，和一对索引`(i, j)`如果出现以下情况，则被视为**不好**：

 -`i < j`-`j - i != nums[j] - nums[i]`换句话说，对于第一个索引在第二个索引之前的每对索引，我们需要确定索引之间的差异是否**不等于**这些索引处的值之间的差异。 

乍一看，这听起来像是一个简单的配对比较问题。 因为每一个可能的对`(i, j)`和`i < j`可能会很糟糕，天真的解释可能会建议单独检查每一对。 然而，输入大小使得这变得不切实际。 

输入是一个整数数组`nums`， 在哪里：

-`nums.length`可以大到`10^5`- 每个值`nums[i]`可以大到`10^9`输出是一个整数，表示数组中**坏对的总数**。 

约束条件`nums.length <= 10^5`尤为重要。 由于数组中的总对数为`n`大约是`n² / 2`，具有二次复杂度的强力解决方案将大致执行`5 × 10^9`最坏情况下的比较，这对于 LeetCode 时间限制来说太慢了。 

一个重要的观察是，问题定义了**坏对**，但有时更容易计算相反的**好对**，并间接得出答案。 

一对`(i, j)`如果满足以下条件，则**好**：```
j - i == nums[j] - nums[i]
```重新整理这个方程：```
j - nums[j] == i - nums[i]
```这种转变是实现高效解决方案的关键见解。 

一些边缘情况值得预先考虑。 只有一个元素的数组根本不包含对，所以答案一定是`0`。 所有转换后的值的数组`i - nums[i]`相同不会产生坏对，因为每对都会变成好对。 具有完全不同的转换值的数组会产生最大数量的坏对。 大输入大小还需要注意 Go 等语言中的整数溢出，因为对的总数可能超出 32 位整数的范围。 

## 方法

 ### 蛮力方法

 最直接的方法是检查每一个可能的对`(i, j)`在哪里`i < j`。 

对于每一对，我们计算：```
j - i
```并将其与：```
nums[j] - nums[i]
```如果两个值不同，我们就会增加坏对计数器。 

该方法保证是正确的，因为它显式地评估每个有效对的条件。 没有跳过任何对，并且严格遵循问题定义。 

然而，问题是性能。 由于有`O(n²)`可能的对，算法变得非常慢`n = 10^5`。 

### 最佳方法，用哈希图计算好对

 我们不直接计算坏对，而是计算**好对**。 

从一对好配对的条件开始：```
j - i == nums[j] - nums[i]
```我们重新排列一下：```
j - nums[j] == i - nums[i]
```这告诉我们，如果两个指数具有相同的值，则它们构成良好的对：```
index - nums[index]
```现在问题变得简单多了。 当我们迭代数组时，我们计算：```
key = i - nums[i]
```我们维护一个哈希图，存储每个键出现的次数。 

对于当前索引：

 - 如果出现相同的键`k`次之前，然后形成当前索引`k`新的好对。 
- 我们将此计数添加到好对总数中。 
- 然后我们更新当前密钥的频率。 

最后：```
bad_pairs = total_pairs - good_pairs
```在哪里：```
total_pairs = n * (n - 1) / 2
```这将复杂性从二次时间降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 单独检查每对 |
 | 最佳| O(n) | O(n) | 使用哈希映射来计算匹配的转换值 |

 ## 算法演练

 1. 计算可能对的总数。 

由于每对都必须满足`i < j`，长度数组中对的总数`n`是：```
n × (n - 1) / 2
```稍后我们将从总数中减去好的对。 
2. 创建哈希映射来跟踪转换值的频率。 

我们使用哈希映射，其中：```
key = i - nums[i]
```该值是该键迄今为止出现的次数。 
3. 从左到右迭代数组。 

在每个索引处`i`，计算：```
current_key = i - nums[i]
```4. 计算新的好对。 

如果`current_key`已经存在于哈希映射中，之前的每个出现都与当前索引形成良好的配对。 

例如，如果密钥已经出现`3`次，那么当前指数贡献`3`新的好对。 
5.更新频率图。 

计算好对后，增加当前键的频率，以便将来的索引可以与其匹配。 
6. 计算坏对。 

迭代完成后：```
bad_pairs = total_pairs - good_pairs
```返回结果。 

### 为什么它有效

 正确性来自变换后的方程：```
j - i == nums[j] - nums[i]
```简化为：```
j - nums[j] == i - nums[i]
```这意味着当且仅当两个指数具有相同的转换值时，一对才是好的。 哈希映射保证每个先前的匹配索引都被精确计数一次，因此所有好的对都被正确计数。 由于每对都不是好就是坏，从总数中减去好对就可以得到坏对的确切数量。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countBadPairs(self, nums: List[int]) -> int:
        n = len(nums)
        total_pairs = n * (n - 1) // 2

        frequency = defaultdict(int)
        good_pairs = 0

        for index, value in enumerate(nums):
            key = index - value

            good_pairs += frequency[key]
            frequency[key] += 1

        return total_pairs - good_pairs
```实现首先使用组合公式计算可能对的总数：```python
n × (n - 1) / 2
```然后我们初始化一个名为的哈希图`frequency`，它跟踪每个转换值的次数`index - value`已经出现了。 

当我们使用迭代遍历数组时`enumerate`，我们计算当前位置的键。 如果该键已存在于哈希映射中，则所有先前出现的元素都与当前元素形成良好的对。 我们将此计数添加到`good_pairs`。 

对匹配进行计数后，我们增加当前键的频率，以便将来的元素可以与其配对。 

最后，由于每对要么好，要么坏，我们从总对数中减去好对的数量并返回结果。 

## 解决方案```go
func countBadPairs(nums []int) int64 {
	n := len(nums)
	totalPairs := int64(n*(n-1)) / 2

	frequency := make(map[int]int64)
	var goodPairs int64 = 0

	for index, value := range nums {
		key := index - value

		goodPairs += frequency[key]
		frequency[key]++
	}

	return totalPairs - goodPairs
}
```Go 实现遵循与 Python 版本完全相同的逻辑，但有一些特定于语言的细节值得注意。 

由于对的数量可能超出 32 位整数的范围，因此我们使用`int64`为了`totalPairs`,`goodPairs`和哈希图频率。 如果没有这个，大输入可能会发生溢出。 

当键不存在时，Go 映射会自动返回零值，这意味着`frequency[key]`安全返回`0`无需进行存在性检查。 

Go 中的切片自然会处理空或单元素输入，因此不需要特殊情况处理。

 ## 边缘情况

 单元素数组是一个重要的边缘情况，因为没有有效的对`(i, j)`存在时`n = 1`。 粗心的实现可能会意外地执行无效计算或返回不正确的非零结果。 这个实现自然地处理它，因为：```
n × (n - 1) / 2
```变成`0`，并且循环没有产生好的对。 

所有对都良好的数组是另一个重要的场景。 例如：```
[1,2,3,4,5]
```每个索引都会产生相同的转换值：```
i - nums[i] = -1
```这意味着每个可能的对都是好的，所以坏对的数量应该是`0`。 哈希映射正确地累积所有匹配的键并从总数中减去它们。 

每对都不好的数组也可能暴露错误。 考虑：```
[5,5,5,5]
```每个转换后的值都是唯一的：```
-5, -4, -3, -2
```由于变换后的值没有重复，因此没有好的对。 执行正确离开`good_pairs = 0`，使答案等于可能对的总数。 

最后，非常大的输入很重要，因为可能的对的数量呈二次方增长。 为了`n = 100000`，对的数量接近于`5 × 10^9`，超出了 32 位整数限制。 Go 实现通过使用避免溢出`int64`，确保最大约束大小的正确性。
