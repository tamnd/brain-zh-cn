[LeetCode 问题 2330](https://leetcode.com/problems/valid-palindrome-iv/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`仅包含小写英文字母。 我们可以执行将任何单个字符更改为任何其他小写字符的操作。 目标是确定在执行一次操作或两次操作后字符串是否可以成为回文。 

回文是向前和向后读相同的字符串。 这意味着对于每个位置`i`，字符位于`s[i]`必须与镜像位置的字符匹配`s[n - 1 - i]`。 

重要的细节是该问题恰好需要一到两次操作，而不是零次操作。 即使字符串已经是回文，我们仍然必须执行至少一项操作。 幸运的是，我们总是可以以保留回文性质的方式修改字符。 例如，在像这样的回文中`"aa"`，我们可以将两个字符更改为`"bb"`使用两个操作。 

输入大小可以大到`10^5`，这意味着我们需要一个有效的线性时间解决方案。 任何显式尝试许多字符替换的方法都会变得太慢。 

关键的观察结果是，每个不匹配的镜像对都需要至少一次操作来修复。 如果不匹配太多，那么两次操作是不够的。 

一些边缘情况很重要：

 - 长度的字符串`1`已经是回文，一次操作就可以使它们保持回文。 
- 已经是回文的字符串必须仍然允许精确的一到两个操作。 
- 具有许多不匹配对的字符串无法在两次操作内修复。 
- 奇数长度的字符串有一个不需要匹配的中间字符。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试一切可能的方法来更改一两个字符，然后检查生成的字符串是否是回文。 

对于一项操作，我们可以：

 1. 选择每个索引。 
2. 将其替换为所有可能的小写字母。 
3. 检查结果字符串是否为回文。 

对于两个操作，我们将：

 1. 选择每对索引。 
2. 尝试每一对替换字符。 
3. 检查结果是否为回文。 

这种方法是正确的，因为它明确地探索了所有有效的可能性。 然而，它太慢了。 

如果字符串长度为`n`，那么：

 - 一次操作的可能性大致为`26 * n`- 两种操作的可能性大致是`(26 * n)^2`这对于`n = 10^5`。 

### 最佳方法

 更好的解决方案来自于分析阻止字符串成为回文的因素。 

回文只关心镜像字符对。 对于每对：

 - 如果字符已经匹配，则无需执行任何操作。 
- 如果它们不同，则至少需要一次操作来修复该对。 

这意味着不匹配的镜像对的数量直接告诉我们所需的最小操作数。 

例如：

-`"abca"`有一对不匹配：`b`与`c`-`"abcdef"`有三个不匹配对

 由于我们最多允许进行两种操作：

 - 如果不匹配`<= 2`，答案是`true`- 否则，答案是`false`已经是回文的字符串也可以工作，因为：

 - 一次操作即可修改奇数回文的中心字符
 - 两次对称运算可以保留偶数长度的回文

 因此，整个问题归结为计算不匹配的镜像对。

 ## 算法演练

 1. 初始化两个指针，一个在字符串的开头，一个在字符串的结尾。 
2. 初始化一个名为`mismatches`到`0`。 该计数器跟踪有多少镜像对不同。 
3. 当左指针小于右指针时：

 1. 比较两个指针处的字符。 
2. 如果字符不同，则递增`mismatches`。 
3. 向前移动左指针。 
4. 向后移动右指针。 
4. 扫描完所有镜像对后：

 1.如果`mismatches`大于`2`， 返回`False`。 
2.否则返回`True`。 

这样做的原因是，每个不匹配的对始终可以通过更改其中一个字符以匹配另一个字符来仅通过一次操作来修复。 

### 为什么它有效

 每个不匹配的镜像对独立地需要一次操作来修复。 任何单个操作都无法修复多个不匹配对，因为每个操作仅更改一个字符。 因此，所需的最小操作次数等于不匹配对的数量。 

如果失配数最多为`2`，我们总是可以执行一两个操作来创建回文。 如果超过`2`，那么至少需要三个操作，所以答案一定是`false`。 

## Python 解决方案```python
class Solution:
    def makePalindrome(self, s: str) -> bool:
        left = 0
        right = len(s) - 1
        mismatches = 0

        while left < right:
            if s[left] != s[right]:
                mismatches += 1

            left += 1
            right -= 1

        return mismatches <= 2
```实现直接遵循两指针策略。 

变量`left`和`right`跟踪字符串中的镜像位置。 在每次迭代期间，算法都会比较相应的字符。 

每当角色不同时，`mismatches`计数器增加。 每个不匹配代表一个需要操作来修复的镜像对。 

处理完所有镜像对后，算法检查不匹配计数是否超过 2。 如果是这样，则不可能在允许的操作限制内修复字符串。 

该实现使用恒定的额外内存，因为它只存储几个整数变量。 

## 解决方案```go
func makePalindrome(s string) bool {
    left := 0
    right := len(s) - 1
    mismatches := 0

    for left < right {
        if s[left] != s[right] {
            mismatches++
        }

        left++
        right--
    }

    return mismatches <= 2
}
```Go 实现与 Python 版本几乎相同。 

Go字符串内部是字节切片，由于问题只保证小写英文字母，所以直接字节索引是安全高效的。 

不需要额外的数组或切片。 该解决方案完全使用整数索引和不匹配计数器来运行。

 ## 边缘情况

 ### 已经是回文字符串

 一个常见的错误是假设字符串已经是回文意味着不需要任何操作，因此答案应该是`false`。 然而，该问题恰好允许一到两个操作，并且我们在修改字符时始终可以保留回文结构。 

例如：

-`"aa"`可以成为`"bb"`在两次操作中。 
-`"aba"`可以成为`"aca"`通过更改中间字符在一次操作中。 

该实现自然地处理了这个问题，因为零不匹配仍然满足`mismatches <= 2`。 

### 奇数长度字符串

 奇数长度字符串包含没有镜像伙伴的中心字符。 幼稚的实现可能会错误地将其与自身进行比较或错误处理指针移动。 

该解决方案通过仅运行来避免此问题`left < right`。 中间的字符会被自动忽略，因为它永远不会影响回文对称性。 

### 需要两次以上修复的字符串

 错误的一个主要来源是误解单个操作可以修复多少个不匹配。 一次操作只能修改一个字符，因此只能修复一对镜像不匹配对。 

例如：

-`"abcdef"`有三对不匹配。 
- 即使最佳的字符替换也无法仅通过两次操作修复所有对。 

该实现正确地独立地计算不匹配对并返回`false`每当计数超过二时。
