[LeetCode 问题 2317](https://leetcode.com/problems/maximum-xor-after-operations/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、位操作

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`，并且我们可以执行任意多次特殊操作。 在一次操作中，我们选择一个索引`i`和任何非负整数`x`，然后替换：```
nums[i] = nums[i] AND (nums[i] XOR x)
```我们的目标是在执行尽可能多的操作后，最大化数组中所有元素的按位异或。 

关键的挑战是理解这个操作实际上允许我们对每个数字做什么。 乍一看，该表达式看起来很复杂，因为它结合了 XOR 和 AND。 然而，一旦我们仔细分析位行为，问题就会变得简单得多。 

输入大小可能非常大：

 -`nums.length`可以达到`10^5`- 每个数字可以大到`10^8`这些限制立即排除了任何暴力模拟操作。 因为有无限多种选择`x`，直接尝试所有操作是不可能的。 相反，我们需要导出该操作的数学属性。 

一个重要的观察结果是，该操作仅从数字中删除位，而不会创建新的位`1`位。 因此，随着时间的推移，每个数字只会丢失一些位。 

一些重要的边缘情况包括：

 - 仅包含零的数组
 - 具有单个元素的数组
 - 具有完全不相交位模式的数字
 - 数字共享许多重叠位
 - 非常大的阵列，效率很重要

 该问题保证所有数字都是非负的，因此我们只处理标准二进制位操作，而不用担心符号位。 

## 方法

 ### 蛮力方法

 暴力策略将尝试模拟阵列上的操作。 对于每个索引，我们可以尝试许多可能的值`x`，生成新的数组状态，计算所得的异或，并搜索最大可能的答案。 

这种方法在理论上是正确的，因为它探索的是可达状态。 然而，这是完全不切实际的。 

问题是：

 -`x`可以是任何非负整数
 - 可能的操作数量是巨大的
 - 状态空间呈指数增长
 - 数组最多可以包含`100000`元素

 即使对于非常小的阵列，详尽的探索也是不可行的。 

蛮力方法失败了，因为操作空间实际上是无限的。 

### 最佳方法

 关键的洞察来自于对操作的一点一滴的分析。 

考虑单个位位置`nums[i]`。 

如果有点在`nums[i]`已经是`0`，运算后的结果将一直保留`0`。 

如果有点在`nums[i]`是`1`，那么：

 - 我们可以选择`x`以便`(nums[i] XOR x)`有`0`或者`1`在那个位置
 - 由于最终运算是与原始位进行“与”运算`1`，我们可以将该位保留为`1`或者把它变成`0`因此，该操作允许我们独立地从数字中删除任何设置的位。 

这意味着每个数字都可以转换为其原始位的任何子集。 

现在考虑最终的异或。 

如果至少有一个数字最初包含该位，则该位位置可以出现在最终的 XOR 中。 由于我们可以有选择地从数字中删除位，因此只要它存在于数组中的某个位置，我们总是可以安排一个位来对最终的 XOR 做出贡献。 

这意味着最大可能的异或仅包含至少一个数字中出现的每一位。 

这正是所有元素的按位或。 

所以答案是：```
nums[0] OR nums[1] OR nums[2] OR ...
```这将问题转化为简单的线性扫描。

 ## 算法演练

 1. 初始化一个名为`result`到`0`。 

This variable will accumulate every bit that appears anywhere in the array.
 2. 迭代中的每个数字`nums`。 

对于每个数字，将其与`result`使用按位或。 
3.更新：```
result = result OR current_number
```OR 运算可确保任何元素中出现的每一位都成为最终答案的一部分。 
4. 继续，直到处理完所有元素。 
5. 返回`result`。 

该值表示任意次数的操作后可实现的最大 XOR。 

### 为什么它有效

 该操作允许我们从单个数字中删除位，但永远不会添加新位。 因此，只有当该位至少存在于一个原始数中时，该位才能出现在最终的 XOR 中。 

由于我们可以有选择地保留位以使它们的 XOR 贡献为奇数，因此可以使每个现有位出现在最终的 XOR 中。 因此，可实现的最大异或包含出现在数组中任何位置的所有位，这正是所有数字的按位或。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumXOR(self, nums: List[int]) -> int:
        result = 0
        
        for num in nums:
            result |= num
        
        return result
```由于数学观察消除了模拟的需要，因此实现极其简洁。 

变量`result`开始于`0`。 当我们迭代数组时，我们不断应用按位或运算符。 

表达式：```python
result |= num
```是以下形式的简写：```python
result = result | num
```这会累加任意数字中出现的每一位。 

在循环结束时，`result`包含数组中所有设置位的并集，这是可实现的最大 XOR。 

## 解决方案```go
func maximumXOR(nums []int) int {
    result := 0

    for _, num := range nums {
        result |= num
    }

    return result
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 使用`|=`用于按位或赋值的运算符，就像 Python 一样。 

由于这些约束非常适合 Go 的`int`类型，不存在溢出问题。 该解决方案还使用恒定的额外内存，因为仅维护单个累加器变量。

 ## 边缘情况

 一种重要的边缘情况是仅包含零的数组。 由于没有数字包含任何设置位，因此按位或保持为零。 有缺陷的实现可能会错误地假设操作可以创建新位，但该操作仅删除位。 该实现自然地处理了这个问题，因为“或”零总是产生零。 

另一个重要的情况是单元素数组。 由于最终的 XOR 等于单个剩余值，因此可实现的最大答案就是原始数字本身。 该算法可以正确工作，因为一个数字的“或”就是该数字。 

第三个重要的边缘情况涉及重叠的位模式，例如`[7, 7, 7]`。 多个数字可以共享相同的位，但可实现的最大异或仍然只包括每个位一次。 OR 运算自然地捕获了这种行为，而无需重复计算位。 

最后一个重要的情况是不同的数字贡献完全不同的位，例如`[1, 2, 4, 8]`。 在这种情况下，每个比特位置都可以同时出现在最终答案中。 该算法正确地将所有位组合成最大值`15`。
