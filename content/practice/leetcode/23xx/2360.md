[LeetCode 2360 题](https://leetcode.com/problems/longest-cycle-in-a-graph/)

 **难度：** 🔴难
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个由数组表示的有向图，称为`edges`。 该图包含`n`节点标记为`0`到`n - 1`。 每个节点最多有一个出边。 

数组的含义很简单：

 - 如果`edges[i] = j`，有一条来自节点的有向边`i`到节点`j`- 如果`edges[i] = -1`, 节点`i`没有出边

 任务是找到图中最长循环的长度。 如果图表不包含循环，我们返回`-1`。 

当遵循有向边最终将我们带回到当前遍历路径中先前访问过的节点时，就会发生循环。 例如：```
2 -> 4 -> 3 -> 2
```这是一个长度的循环`3`。 

该图的一个重要特征是每个节点至多有一个出边。 与一般有向图相比，这极大​​地简化了结构。 每个连接的组件的行为就像一条链，最终可能终止或进入一个循环。 

限制条件很大：

 -`n`可以大到`100000`- 二次解会太慢
 - 我们需要一个接近线性时间的算法

 该问题还保证：

 -`edges[i] != i`，所以不存在自循环
 - 传出边是有效的节点索引或`-1`一些边缘情况很重要：

 - 根本没有循环的图表
 - 多个断开连接的组件
 - 多个周期，我们必须选择最长的
 - 形成循环的长链
 - 之前的遍历已经处理过的节点
 - 投入非常大，重复工作会导致时间限制问题

 由于每个节点至多有一个出边，因此我们可以通过跟踪遍历顺序并检测何时在同一遍历中重新访问节点来有效地处理图。 

## 方法

 ### 蛮力方法

 暴力解决方案将从每个节点独立地开始遍历。 

对于每个起始节点：

 1. 逐一跟随出边
 2. 跟踪该遍历所访问的节点
 3. 如果我们重新访问当前路径中已经见过的节点，我们发现了一个循环
 4. 计算周期长度
 5. 对每个节点重复

 这是有效的，因为最终会发生以下两种情况之一：

 - 我们到达`-1`，意味着该路径中不存在循环
 - 我们重新访问一个节点，意味着存在一个循环

 这种方法的问题是重复工作。 考虑一个长节点链。 如果我们分别从每个节点开始，我们可能会多次遍历同一条路径。 

在最坏的情况下，每次遍历可能需要`O(n)`时间，我们为所有人表演`n`节点。 这导致`O(n²)`复杂性，这对于`n = 100000`。 

### 最佳方法

 关键的见解是，一旦节点被完全处理，我们就不需要再次处理它。 

由于每个节点至多有一个出边，因此遍历是确定性的。 从任何节点开始，只有一条可能的前进路径。 

我们可以通过维护以下内容来利用这一点：

 - 一个全球性的`visited`数组以避免重新处理节点
 - 存储当前遍历期间访问的节点的步骤索引的映射

 当我们遇到当前遍历中已经见过的节点时，我们立即知道存在循环。 周期长度为：```
current_step - first_seen_step
```这种方法确保每个节点最多在全局范围内处理一次，从而为我们提供线性时间复杂度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 从多个起始节点重复遍历工作 |
 | 最佳 | O(n) | O(n) | 每个节点最多处理一次 |

 ## 算法演练

 1. 创建全局`visited`大小数组`n`，初始化为`False`。 

该数组跟踪节点是否已在任何遍历中完全处理。 一旦一个节点被标记为已访问，我们就不需要再次从它开始。 
2. 初始化`longest_cycle`到`-1`。 

这存储了迄今为止找到的最大周期长度。 如果不存在循环，则仍然存在`-1`。 
3. 遍历每个节点`0`到`n - 1`。 

对于每个节点：

 - 如果已经被全局访问，则跳过它
 - 否则，从该节点开始新的遍历
 4. 对于每次遍历，创建一个名为的字典`distance`。 

这本词典映射：```
node -> step index
```它仅记录当前遍历期间第一次访问每个节点的时间。 
5. 开始沿着输出边缘向前移动。 

每一步：

 - 将节点标记为全局访问的
 - 记录其步骤编号`distance`- 使用移动到下一个节点`edges[current]`6. 继续遍历，直到出现以下三种情况之一。 

案例一：```
current == -1
```这意味着路径终止并且不存在循环。 

案例2：```
current was globally visited before
```如果该节点不在当前遍历的节点中`distance`map，则属于之前处理过的遍历，不会形成新的循环。 

案例3：```
current exists in distance
```这意味着我们在同一次遍历中重新访问了一个节点，因此我们找到了一个循环。 
7. 计算周期长度。 

认为：```
distance[current] = first_seen
current_step = step
```然后：```
cycle_length = step - first_seen
```8. 更新`longest_cycle`如果新发现的周期更大。 
9. 继续，直到处理完所有节点。 

### 为什么它有效

 该算法之所以有效，是因为每个节点至多有一个出边，这保证了从每个起始节点开始的唯一遍历路径。 

这`distance`map 仅标识当前遍历期间访问的节点。 因此，重新访问该映射内的节点意味着我们已经关闭了一个循环。 遍历步骤的差异给出了精确的循环长度。 

全球`visited`array 通过确保没有节点总体上被处理超过一次来保证效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestCycle(self, edges: List[int]) -> int:
        n = len(edges)
        visited = [False] * n
        longest_cycle = -1

        for start in range(n):
            if visited[start]:
                continue

            current = start
            step = 0
            distance = {}

            while current != -1 and not visited[current]:
                visited[current] = True
                distance[current] = step

                step += 1
                current = edges[current]

            if current != -1 and current in distance:
                cycle_length = step - distance[current]
                longest_cycle = max(longest_cycle, cycle_length)

        return longest_cycle
```实施首先创建`visited`数组并初始化结果变量。 

外层循环遍历所有节点。 如果某个节点已经被处理过，我们会立即跳过它以避免重复工作。 

对于每个新的遍历，我们初始化：

 -`current`作为起始节点
 -`step`计算遍历深度
 -`distance`记录当前遍历中访问节点的顺序

 里面的`while`循环，我们继续遍历直到：

 - 我们到达`-1`- 我们遇到一个全局访问的节点

 每个节点都被立即标记为全局访问，以确保将来的遍历跳过它。 

这`distance`字典存储当前遍历过程中第一次看到节点时的步骤索引。 如果我们稍后重新访问该字典内的节点，我们会发现完全在当前遍历路径内的循环。 

周期长度的计算方法为：```python
current_step - first_seen_step
```最后，我们更新迄今为止找到的最大周期长度。 

## 解决方案```go
func longestCycle(edges []int) int {
	n := len(edges)
	visited := make([]bool, n)
	longestCycle := -1

	for start := 0; start < n; start++ {
		if visited[start] {
			continue
		}

		current := start
		step := 0
		distance := make(map[int]int)

		for current != -1 && !visited[current] {
			visited[current] = true
			distance[current] = step

			step++
			current = edges[current]
		}

		if current != -1 {
			if firstSeen, exists := distance[current]; exists {
				cycleLength := step - firstSeen
				if cycleLength > longestCycle {
					longestCycle = cycleLength
				}
			}
		}
	}

	return longestCycle
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`用于代替 Python 字典来跟踪遍历距离。 

Go 切片本质上是动态引用，因此`visited`布尔切片有效地跟踪全局处理的节点。 

整数溢出不是问题，因为最大循环长度受以下限制`n`，这最多是`100000`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点最多被处理一次 |
 | 空间| O(n) | 访问数组和遍历图一起存储最多n个节点|

 关键的优化是全局的`visited`大批。 如果没有它，节点可能会从不同的起点重复访问。 由于每个节点只被全局访问一次，因此整个算法的遍历工作总量是线性的。 

这`distance`每次遍历期间使用的字典也仅临时存储节点，并且在所有遍历中其总大小永远不会超过`n`。

 ## 边缘情况

 一个重要的边缘情况是完全没有循环的图。 在这种情况下，每次遍历最终都会到达`-1`。 有缺陷的实现可能会错误地将重新访问全局访问的节点视为循环。 此实现通过检查重复节点是否存在于当前遍历的内部来避免这种情况`distance`地图。 只有在相同的遍历期间重新访问的节点才算作周期。 

另一个关键的边缘情况是导致循环的长链。 例如：```
0 -> 1 -> 2 -> 3 -> 4 -> 2
```这里，循环仅包含节点`2`,`3`， 和`4`。 幼稚的实现可能会错误地计算整个遍历长度。 该解决方案正确计算：```
current_step - distance[current]
```它仅测量周期部分。 

第三个重要的边缘情况涉及多个断开连接的组件。 有些组件可能包含循环，而其他组件则不包含。 该算法自然地处理这个问题，因为外循环从每个未访问的节点开始遍历。 每个连接的组件都被独立处理，并返回所有组件的最大循环长度。 

最后一个微妙的边缘情况是遇到已经从早期遍历处理过的节点。 没有全局的`visited`数组时，算法会重复遍历相同的结构并变得低效。 通过标记立即全局访问的节点，该实现保证每个节点被处理一次，从而保持线性复杂性。
