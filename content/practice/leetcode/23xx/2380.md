[LeetCode Problem 2380](https://leetcode.com/problems/time-needed-to-rearrange-a-binary-string/)

 **难度：** 🟡 中等
 **Topics:** String, Dynamic Programming, Simulation

 ## 解决方案

 ## 问题理解

 这个问题要求我们根据一个非常具体的规则重复转换一个二进制字符串。 During each second, every occurrence of the substring`"01"`同时被替换为`"10"`。 

重要的细节是所有替换都是同时发生的。 这意味着我们不会从左到右一次处理一个事件。 相反，每个`"01"`字符串中的对在一秒钟内同时交换。 

我们继续执行这些转换，直到字符串不再包含`"01"`。 那时，所有`'1'`字符必须已经位于所有字符之前`'0'`字符，因为`"01"`代表一种情况，其中`'1'`仍然可以相对于 a 向左移动`'0'`。 

目标是返回不再需要的秒数`"01"`子串存在。 

例如，给定：```
"0110101"
```这个过程是这样演变的：```
0110101
1011010
1101100
1110100
1111000
```4秒后，没有剩余`"01"`模式，所以答案是`4`。 

约束比较小，最多是字符串长度`1000`。 这意味着即使是`O(n²)`解决方案可能会通过。 然而，后续明确询问我们是否可以解决它`O(n)`时间，这强烈表明存在避免重复模拟的观察。 

预先识别一些边缘情况很重要。 一个已经不包含任何内容的字符串`"01"`模式，例如`"11100"`，应该立即返回`0`。 一根完全由`'0'`或完全是`'1'`还要求`0`秒。 交替图案如`"010101"`很棘手，因为许多交换同时发生，这可能会误导天真的顺序模拟。 由 0 和 1 组成的长链也需要仔细推理，因为单个`'1'`可能需要几秒钟才能越过多个零。 

## 方法

 ### 暴力模拟

 最直接的方法是完全按照所描述的方式模拟该过程。 

我们每秒扫描字符串并替换每个`"01"`和`"10"`同时地。 由于同时替换很重要，因此我们不能在迭代期间简单地交换字符，因为较早的交换会错误地影响后面的字符。 相反，我们会每秒构造一个新字符串。 

我们重复这个过程，直到字符串不再包含`"01"`并计算需要多少次迭代。 

这种方法是正确的，因为它忠实地再现了问题陈述中给出的确切转换规则。 每一秒对应于一次完整的同时替换。 

然而，它的效率很低。 在最坏的情况下，我们可能需要`O(n)`秒，每一秒都需要扫描整个长度的字符串`n`。 因此，总时间复杂度变为`O(n²)`。 

### 最佳观察，计算延迟

 关键的见解是我们实际上不需要每一秒都进行模拟。 

每个`'1'`想要向左移动跨越零。 每当一个`'1'`在它之前遇到一个零，它最终会交换过去。 如果有`k`a 之前的零`'1'`，那么`'1'`至少需要`k`秒完全向左移动。 

然而，还有一个额外的复杂情况。 多种的`'1'`角色可以互相阻挡。 即使一个`'1'`有足够的零可以交叉，可能需要等待更早`'1'`首先完成移动的角色。 

我们从左到右处理字符串并跟踪：

 -`zero_count`，到目前为止遇到的零的数量
 -`seconds`, 到目前为止所需的最长时间

 当我们看到一个`'0'`，我们增加`zero_count`。 

当我们看到一个`'1'`，如果它前面有零，则这`'1'`必须移动。 所需时间变为：```
max(seconds + 1, zero_count)
```该公式捕获了两个约束：

 -`zero_count`，因为`'1'`必须跨越那么多零
 -`seconds + 1`，因为连续`'1'`characters may need to wait one extra second behind previous ones

 这让我们可以一次性计算出答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 通过重建字符串来模拟每一秒 |
 | 最佳| O(n) | O(1) | O(1) | 一次跟踪零计数和运动延迟 |

 ## 算法演练

 1.初始化两个变量：

 -`zero_count = 0`，代表到目前为止出现了多少个零。 
-`seconds = 0`，表示迄今为止重新排列所需的最长时间。 
2. 从左到右逐个字符地遍历字符串。 
3. 如果当前字符是`'0'`, 增量`zero_count`。 这很重要，因为每个未来`'1'`最终必须超越这些零。 
4. 如果当前字符是`'1'`和`zero_count > 0`， 这`'1'`必须向左移动超过之前的零。 
5. 计算所需时间`'1'`:```
seconds = max(seconds + 1, zero_count)
```这保证了两个条件：

 - 的`'1'`跨越所有前面的零，至少需要`zero_count`秒。 
- 如果以前`'1'`角色已经在移动，这`'1'`无法超越他们，因此可能需要再等待一秒钟。 
6. 继续，直到处理完整个字符串。 
7. 返回`seconds`，表示所需的总秒数。 

### 为什么它有效

 不变的是`seconds`始终代表完全安排所有内容所需的最短时间`'1'`到目前为止已处理的字符。 对于每个`'1'`，该算法既考虑其自身的移动要求（由其前面有多少个零决定），也考虑由较早的零引起的任何等待时间`'1'`人物。 由于每`'1'`仅处理一次并考虑其运动依赖性，最终`seconds`value 正是所需的同时交换轮数。 

## Python 解决方案```python
class Solution:
    def secondsToRemoveOccurrences(self, s: str) -> int:
        zero_count = 0
        seconds = 0

        for char in s:
            if char == '0':
                zero_count += 1
            elif zero_count > 0:
                seconds = max(seconds + 1, zero_count)

        return seconds
```实现严格遵循最优算法。 

我们首先初始化`zero_count`和`seconds`。 当我们扫描字符串时，每个`'0'`增加`zero_count`，因为它为未来制造了障碍`'1'`人物。 

当我们遇到一个`'1'`，我们检查它前面是否有零。 如果`zero_count > 0`， 这`'1'`最终必须移动。 我们更新`seconds`使用：```python
max(seconds + 1, zero_count)
```这`zero_count`期限确保`'1'`有足够的时间通过所有前面的零。 这`seconds + 1`term 确保它尊重先前的移动顺序`'1'`角色，并且不会不切实际地超越他们。 

最后，处理完整个字符串后，我们返回`seconds`。 

## 解决方案```go
func secondsToRemoveOccurrences(s string) int {
    zeroCount := 0
    seconds := 0

    for _, char := range s {
        if char == '0' {
            zeroCount++
        } else if zeroCount > 0 {
            if seconds+1 > zeroCount {
                seconds = seconds + 1
            } else {
                seconds = zeroCount
            }
        }
    }

    return seconds
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

由于 Go 没有内置的`max`整数函数，我们显式比较`seconds + 1`和`zeroCount`使用一个`if`陈述。 Go 中的字符串作为符文进行迭代，但由于输入仅包含`'0'`和`'1'`，这样可以高效、安全地工作。 

不用担心整数溢出，因为最大字符串长度仅为`1000`，这意味着答案仍然很小。

 ## 边缘情况

 ### 已经稳定的字符串

 像这样的字符串`"11100"`已经拥有了所有`'1'`之前的字符`'0'`人物。 由于没有`"01"`子串，答案应该是`0`。 有缺陷的实现可能会不必要地模拟交换或误算移动。 我们的算法自然地处理这个问题，因为没有`'1'`曾经遇到过前面的零。 

### 单字符输入

 输入如`"0"`或者`"1"`是最小的有效字符串。 由于不存在相邻对，因此不可能进行交换。 执行正确返回`0`因为循环要么递增`zero_count`一次或完全跳过运动逻辑。 

### 多个连续等待

 像这样的案例`"00111"`很微妙，因为后来`'1'`角色可能需要在前面的角色后面等待。 虽然每个`'1'`看到相同数量的前面的零，它们不能在没有干扰的情况下同时移动。 这`max(seconds + 1, zero_count)`公式正确地模拟了这种等待行为，防止计数不足。 

### 交替模式

 字符串如`"010101"`包含许多同时交换。 简单的顺序交换实现可能会意外地一次处理一个交换并产生不正确的中间状态。 由于最佳解决方案以数学方式推理运动而不是直接模拟交换，因此可以正确处理同时行为。
