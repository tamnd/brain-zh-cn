 ## 解决方案

 ## 问题理解

 The problem gives us a linked list and asks us to place its values into an`m x n`矩阵按顺时针螺旋顺序排列。 

我们从矩阵的左上角开始填充，即位置`(0, 0)`。 遍历方向遵循标准螺旋模式：

 1. 从左向右移动穿过顶行
 2. 沿右栏从上到下移动
 3. 从右向左移动穿过底行
 4. 沿左栏从下到上移动
 5.向内重复，直至矩阵处理完毕

 链表中的每个值都被写入下一个螺旋位置。 如果在矩阵完全填充之前链表用完节点，则每个剩余​​的空单元格必须包含`-1`。 

输入包括：

 -`m`, 行数
 -`n`, 列数
 -`head`，单链表的头节点

 输出是一个完全构建的`m x n`矩阵。 

约束条件很重要：

 -`1 <= m * n <= 10^5`- 链表长度最多为`m * n`这告诉我们细胞总数最多是`100000`，所以一个`O(m * n)`解决方案是完全可以接受的。 然而，任何更糟糕的事情，例如重复扫描下一个有效位置，都可能变得低效。 

一些边缘情况很重要：

 - 链表包含的值可能少于矩阵单元的数量
 - 矩阵可能只有一行
 - 矩阵可能只有一列
 - 链表可以完全填满矩阵
 - 当奇数大小的矩阵中边界重叠时，螺旋遍历必须正确停止

 如果不仔细处理螺旋方向的变化，简单的实现很容易覆盖单元格或移动到矩阵边界之外。 

## 方法

 ### 蛮力方法

 强力解决方案将逐个单元地模拟运动，同时反复检查下一个位置是否有效。 

一种可能的实现是：

 - 保持当前方向
 - 一次移动一步
 - 如果下一个位置在矩阵之外或已经填充，则旋转方向
 - 继续直到链表耗尽

 这种方法可以正确工作，因为它明确地模拟了螺旋遍历顺序。 然而，如果实施不当，它可能会重复搜索有效单元或执行过多的边界检查。 

尽管整体复杂性仍然可以接受，但逻辑变得更容易出错且结构性较差。 

### 最佳方法

 更好的解决方案使用经典的螺旋边界技术。 

我们不动态检测访问的单元格，而是维护四个边界：

 -`top`-`bottom`-`left`-`right`每个阶段：

 1. 填充顶行
 2. 增量`top`3. 填写右栏
 4. 减量`right`5. 填充底行
 6. 减量`bottom`7. 填写左栏
 8. 增量`left`该方法保证每个单元按照螺旋顺序被恰好访问一次。 

关键的见解是螺旋遍历自然地逐层向内收缩。 通过在完成每一侧后更新边界，我们可以避免重新访问单元格并消除额外访问跟踪的需要。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m × n) | O(m × n) | 通过重复有效性检查来模拟运动 |
 | 最佳| O(m × n) | O(m × n) | 有效利用收缩螺旋边界 |

 ## 算法演练

 1. 创建一个`m x n`矩阵初始化为`-1`。 

初始化为`-1`如果链接列表提前结束，则自动处理未使用的单元格。 
2. 初始化四个螺旋边界：

 -`top = 0`-`bottom = m - 1`-`left = 0`-`right = n - 1`这些边界定义了当前未填充的矩形区域。 
3. 将链表指针存储在`current`。 

该指针跟踪要放入矩阵中的下一个值。 
4. 继续处理，同时：

 -`current`不是`None`- 边界仍然有效
 5. 从左向右穿过顶行。 

对于之间的每一列`left`和`right`：

 - 放置当前链表值
 - 推进链表指针

 如果链表变空，立即停止。 
6. 增量`top`。 

顶行现已完全处理，不应重新访问。 
7. 沿着右列从上到下遍历。 

重复相同的放置逻辑。 
8. 减量`right`。 

右栏已完成。 
9. 如果边界仍然有效，则从右向左遍历底行。 

此条件可防止单行情况下的重复遍历。 
10. 减量`bottom`。 
11. 如果边界仍然有效，则沿着左列从下到上遍历。 

此条件可防止单列情况下的重复遍历。 

1. 增量`left`。 
2. 重复直到：

 - 链表已耗尽，或者
 - 所有矩阵单元均已处理

 1. 返回完成的矩阵。 

### 为什么它有效

 该算法保持了当前边界之外的所有单元都已按正确的螺旋顺序填充的不变性。 每次遍历都完全处理剩余矩形的一侧，之后相应的边界向内收缩。 由于边界仅向内移动，并且每个单元恰好属于一层，因此每个单元最多被访问一次，并且按照正确的顺时针螺旋顺序。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import List, Optional

class Solution:
    def spiralMatrix(
        self,
        m: int,
        n: int,
        head: Optional[ListNode]
    ) -> List[List[int]]:
        
        matrix = [[-1] * n for _ in range(m)]

        top = 0
        bottom = m - 1
        left = 0
        right = n - 1

        current = head

        while current and top <= bottom and left <= right:

            # Left to right
            for col in range(left, right + 1):
                if not current:
                    break

                matrix[top][col] = current.val
                current = current.next

            top += 1

            # Top to bottom
            for row in range(top, bottom + 1):
                if not current:
                    break

                matrix[row][right] = current.val
                current = current.next

            right -= 1

            # Right to left
            if top <= bottom:
                for col in range(right, left - 1, -1):
                    if not current:
                        break

                    matrix[bottom][col] = current.val
                    current = current.next

                bottom -= 1

            # Bottom to top
            if left <= right:
                for row in range(bottom, top - 1, -1):
                    if not current:
                        break

                    matrix[row][left] = current.val
                    current = current.next

                left += 1

        return matrix
```实现首先创建一个矩阵，其中填充`-1`。 这很重要，因为任何未填充的单元格都应该保留`-1`遍历结束后自动。 

四个边界变量定义当前活动的螺旋层。 完成螺旋的一侧后，相应的边界向内移动。 

链表指针`current`每次将值写入矩阵时都会前进。 每次插入之前，代码都会检查链表是否仍包含节点。 这可以防止解除引用`None`。 

底行和左列遍历之前的条件检查是必不可少的。 如果没有它们，单行或单列图层可能会被处理两次。 

该算法一直持续到：

 - 所有链表值都被消耗，或者
 - 螺旋边界完全崩溃

 ## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func spiralMatrix(m int, n int, head *ListNode) [][]int {

    matrix := make([][]int, m)

    for i := 0; i < m; i++ {
        matrix[i] = make([]int, n)

        for j := 0; j < n; j++ {
            matrix[i][j] = -1
        }
    }

    top := 0
    bottom := m - 1
    left := 0
    right := n - 1

    current := head

    for current != nil && top <= bottom && left <= right {

        // Left to right
        for col := left; col <= right && current != nil; col++ {
            matrix[top][col] = current.Val
            current = current.Next
        }

        top++

        // Top to bottom
        for row := top; row <= bottom && current != nil; row++ {
            matrix[row][right] = current.Val
            current = current.Next
        }

        right--

        // Right to left
        if top <= bottom {
            for col := right; col >= left && current != nil; col-- {
                matrix[bottom][col] = current.Val
                current = current.Next
            }

            bottom--
        }

        // Bottom to top
        if left <= right {
            for row := bottom; row >= top && current != nil; row-- {
                matrix[row][left] = current.Val
                current = current.Next
            }

            left++
        }
    }

    return matrix
}
```Go 实现遵循与 Python 版本相同的螺旋边界逻辑。 

一个重要的区别是矩阵初始化。 在 Go 中，整数切片默认为`0`，所以我们必须显式地将每个单元格设置为`-1`。 

另一个区别是链表处理。 Go 使用`nil`而不是Python的`None`，以及链表字段访问使用`Val`和`Next`。 

遍历循环包括`current != nil`直接在循环条件中，这避免了额外的嵌套检查。

 ## 边缘情况

 ### 单行矩阵

 只有一行的矩阵很容易造成重复遍历的bug。 完成顶行遍历后，底行遍历可能会意外地重新访问同一行。 

该实现通过检查来防止这种情况：```
if top <= bottom:
```在遍历底行之前。 

### 单列矩阵

 类似地，只有一列的矩阵可能会导致左列遍历重新访问右列遍历期间已填充的单元格。 

该实现通过以下方式避免了这种情况：```
if left <= right:
```然后沿着左侧向上移动。 

### 链表比矩阵容量短

 链表可以在所有矩阵单元被填充之前结束。 有错误的解决方案可能会继续遍历并尝试访问`current.val`当指针变为`None`。 

此实现检查是否`current`在每次插入之前都存在。 由于矩阵开始完全初始化`-1`，任何未触及的单元格都会自动包含所需的值。 

### 奇怪尺寸的螺旋层

 在奇维矩阵中，例如`3 x 3`或者`5 x 5`，螺旋最终塌陷为单个中心单元。 

不正确的边界更新可能会跳过或覆盖此中心位置。 算法中的边界条件确保每层正确收缩并且中心单元仅被处理一次。
