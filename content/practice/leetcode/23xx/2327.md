[LeetCode 问题 2327](https://leetcode.com/problems/number-of-people-aware-of-a-secret/)

 **难度：** 🟡 中等
 **主题：** 动态规划、队列、模拟

 ## 解决方案

 ## 问题理解

 该问题描述了秘密如何随着时间的推移而传播。 当天`1`，只有一个人知道这个秘密。 每个得知这个秘密的人都遵循两条规则行事：

 1.他们必须等待`delay`距离他们可以开始分享这个秘密还有几天。 
2.他们忘记了秘密`forget`一旦他们忘记了，他们就无法再分享了。 

每个符合资格的人每天都会与一个新人分享这个秘密。 

任务是确定最终有多少人仍然知道这个秘密`n`。 

重要的细节是一个人可以在特定的时间范围内分享秘密。 假设有人在那天得知了这个秘密`d`：

 - 他们当天开始分享`d + delay`- 他们忘记了这一天`d + forget`- 因此，他们可以在这些日子里分享：```
[d + delay, d + forget - 1]
```答案算在当天还记得这个秘密的每个人身上`n`，包括最近学习但还没有开始分享的人。 

限制相对较小：

 -`2 <= n <= 1000`-`1 <= delay < forget <= n`因为`n`至多是`1000`， 一个`O(n^2)`动态规划解决方案是完全可以接受的。 然而，简单的逐人模拟仍然可能变得不必要的复杂和低效。 

一些边缘情况很重要：

 - 人们可能很快就会知道这个秘密`n`，这意味着他们永远没有机会分享它。 
- 什么时候`delay = 1`，第二天立即开始分享，造成快速指数级增长。 
- 什么时候`forget`仅略大于`delay`，人们的共享窗口非常短。 
- 在某一天忘记秘密的人不能在同一天分享它。 

仔细处理确切的包含和排除日期范围是该问题的关键挑战。 

## 方法

 ### 蛮力方法

 直接模拟方法将对每个人单独建模。 

每当有人得知这个秘密时，我们就可以存储：

 - 他们学会的那天
 - 他们将分享的日子
 - 他们忘记的那一天

 然后，我们每天都会迭代所有现有人员并确定：

 - 他们是否还记得这个秘密
 - 目前是否允许他们分享

 如果他们可以分享，我们会创建一个新的人员条目。 

这种方法是正确的，因为它明确地模拟了流程的确切规则。 然而，人数增长得非常快，尤其是当`delay = 1`。 在最坏的情况下，模拟个体的数量呈指数级增长。 

虽然`n <= 1000`，单独维护每个人是低效且不必要的。 

### 最优动态规划方法

 关键的见解是我们不需要跟踪个人。 相反，我们只需要知道：```
How many people first learned the secret on each day
```定义：```
dp[i] = number of people who learn the secret on day i
```现在考虑一下人们如何为未来做出贡献。 

如果有人在那天得知了这个秘密`j`，他们将在几天内分享：```
[j + delay, j + forget - 1]
```这意味着在未来的某一天`i`, 每个较早的一天`j`有助于`dp[i]`如果：```
j + delay <= i < j + forget
```等效地：```
i - forget < j <= i - delay
```所以，对于每一天`i`，我们对当前活跃共享者的所有人员进行汇总。 

这将问题转化为干净的动态规划过程。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 分别模拟每个人 |
 | 最佳| O(n²) | O(n) | 追踪每天有多少人了解这个秘密 |

 ## 算法演练

 1.创建动态规划数组`dp`尺寸的`n + 1`。`dp[i]`代表当天最先得知秘密的人数`i`。 
2. 初始化启动条件。 

当天`1`，一个人知道这个秘密：```
dp[1] = 1
```3. 处理未来的每一天`2`到`n`。 

对于每一天`day`，确定当前有多少人能够共享该秘密。 
4. 迭代所有之前的日子`prev_day`。 

一个得知这个秘密的人`prev_day`可以分享`day`如果：```
prev_day + delay <= day < prev_day + forget
```5. 如果条件为真，则添加`dp[prev_day]`今天有多少新人了解这个秘密。 

每个符合资格的共享者都会创建一个新人。 
6. 将结果存储在`dp[day]`。 

这给出了当天首先发现这个秘密的人数。 
7. 填充DP数组后，计算最终答案。 

一个人还记得那天的秘密`n`如果：```
n - forget < learned_day <= n
```8. 总和`dp[day]`那些还没有忘记的人们的价值观。 
9. 返回模数结果`10^9 + 7`。 

### 为什么它有效

 该算法之所以有效，是因为每个人在第一次得知这个秘密的那一天就已经完全具备了特征。 从那天起，他们的分享行为就具有确定性。 

DP 转换正确地计算了在某一天积极共享的所有人员，并且每个活跃共享者恰好贡献了一个新通知的人员。 由于每个新获悉信息的人都会被准确记录一次`dp`，没有人被遗漏或重复计算。 

最终的总结正确地排除了任何已经忘记这个秘密的人。 

## Python 解决方案```python
class Solution:
    def peopleAwareOfSecret(self, n: int, delay: int, forget: int) -> int:
        MOD = 10**9 + 7

        dp = [0] * (n + 1)
        dp[1] = 1

        for day in range(2, n + 1):
            total_new_people = 0

            for prev_day in range(1, day):
                if prev_day + delay <= day < prev_day + forget:
                    total_new_people += dp[prev_day]

            dp[day] = total_new_people % MOD

        answer = 0

        for day in range(1, n + 1):
            if day + forget > n:
                answer += dp[day]

        return answer % MOD
```实现直接遵循动态规划策略。 

这`dp`数组存储每天有多少人首先了解这个秘密。 初始化`dp[1] = 1`代表原来的人。 

对于未来的每一天，代码都会扫描之前的所有日子并检查这些人当前是否在其共享窗口中。 条件：```python
prev_day + delay <= day < prev_day + forget
```确保：

 - 他们已经等了足够长的时间才开始分享
 - 他们还没有忘记

 所有符合资格的共享者每人贡献一名新人。 

经过一整天的计算后，最后的循环只计算当天仍然记得这个秘密的人`n`。 任何人的遗忘日在之后`n`还在算。 

使用模运算是因为人数可能会变得非常大。 

## 解决方案```go
func peopleAwareOfSecret(n int, delay int, forget int) int {
    const MOD int = 1_000_000_007

    dp := make([]int, n+1)
    dp[1] = 1

    for day := 2; day <= n; day++ {
        totalNewPeople := 0

        for prevDay := 1; prevDay < day; prevDay++ {
            if prevDay+delay <= day && day < prevDay+forget {
                totalNewPeople += dp[prevDay]
                totalNewPeople %= MOD
            }
        }

        dp[day] = totalNewPeople
    }

    answer := 0

    for day := 1; day <= n; day++ {
        if day+forget > n {
            answer += dp[day]
            answer %= MOD
        }
    }

    return answer
}
```Go 实现在结构上与 Python 版本相同。 

使用切片而不是 Python 列表。 由于 Go 整数在较大的计算中可能会溢出，因此在累加期间应用模归约。 确定活跃共享者和最终幸存者的逻辑仍然完全相同。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`delay = 1`。 在这种情况下，每个新获悉信息的人都可以在第二天立即开始共享。 这导致人口数量增长非常迅速。 简单的递归模拟可能会变得极其低效。 DP 解决方案自然地处理了这个问题，因为它只跟踪每天的计数而不是个人。 

另一个棘手的情况发生在`forget = delay + 1`。 在这里，人们只有一天的时间可以分享这个秘密。 在这种情况下，相差一的错误很常见。 条件：```
prev_day + delay <= day < prev_day + forget
```正确模拟共享窗口的包含开始和排除结束。 

最后一个重要的边缘情况发生在时间线末尾附近。 有些人可能会在天前不久得知这个秘密`n`并且永远没有机会分享它。 这些人仍然必须算在最终答案中，因为他们记得这个秘密。 该实现通过对所有遗忘日严格晚于之后的人进行求和来处理此问题`n`。
