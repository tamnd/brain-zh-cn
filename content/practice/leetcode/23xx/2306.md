[LeetCode 问题 2306](https://leetcode.com/problems/naming-a-company/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、字符串、位操作、枚举

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个名为的唯一字符串列表`ideas`。 我们必须重复选择两个不同的字符串，交换它们的第一个字符，并确定新形成的字符串是否都不在原始列表中。 

如果两个新生成的名称尚不存在于`ideas`，然后是有序对`(ideaA, ideaB)`形成有效的公司名称。 我们返回的结果是不同的有效有序对的总数。 

重要的细节是顺序很重要。 如果`(coffee, donuts)`是有效的，那么`(donuts, coffee)`是单独计算的。 

例如：

-`"coffee"`和`"donuts"`- 交换第一个字母：

 -`"coffee"`变成`"doffee"`-`"donuts"`变成`"conuts"`- 如果两者都不是`"doffee"`也不`"conuts"`存在于原始列表中，该对有效。 

限制条件很大：

 - 最多`5 * 10^4`字符串
 - 每个字符串长度可达`10`对每一对和每个生成的字符串进行天真的比较会变得太慢，因为可能有大约`1.25 * 10^9`最坏情况下成对。 

该问题保证所有原始字符串都是唯一的，这简化了成员资格检查，因为我们可以安全地将所有内容存储在哈希集中。 

一些边缘情况很重要：

 - 两个字符串在交换后可能已经成为现有单词。 
- 不同的字符串可以共享相同的后缀。 
- 交换可能会生成完全相同的原始字符串。 
- 某些起始字母可能根本没有兼容的交换。 
- 答案可能会变得很大，所以在 Go 中我们必须使用`int64`。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试每对有序的不同想法。 

对于每对：

 1. 交换第一个字符。 
2. 构造两个新字符串。 
3. 检查原始字符串中是否存在新字符串。 
4. 如果两者都不存在，则增加答案。 

这是有效的，因为它明确地模拟了问题中描述的操作。 

然而，复杂性太高。 

如果有`n`字符串，有`O(n^2)`对。 每对还需要字符串构造和哈希查找。 和`n = 5 * 10^4`，这变得不可行。 

### 关键见解

 第一个字符是唯一被交换的部分。 

假设我们将每个单词分成：

 - 第一个字母
 - 后缀，表示第一个字符之后的所有内容

 示例：

 | 词| 第一封信 | 后缀 |
 | ---| ---| ---|
 | 咖啡| c | 咖啡 |
 | 甜甜圈| d | 上坚果|
 | 时间 | t | 时间 |

 现在考虑一下是什么导致交换无效。 

如果我们交换两个单词之间的第一个字母：

 -`c + onuts`-`d + offee`如果任一生成的单词已经存在，则交换失败。 

请注意，存在完全取决于后缀是否已出现在另一个起始字母下方。 

这建议按第一个字符对单词进行分组。 

对于每个起始字母：

 - 存储与该字母相关的所有后缀

 然后分为两组`i`和`j`：

 - 找出有多少后缀是共享的
 - 共享后缀不能参与有效交换
 - 独特的后缀可以自由配对

 如果：

 -`unique_i`= 仅在组中的后缀`i`-`unique_j`= 仅在组中的后缀`j`那么这些组贡献的有效有序对的数量为：```
unique_i * unique_j * 2
```乘以`2`帐户用于订购。 

由于只有 26 个小写字母，因此我们只比较 26 组，从而提高了解决方案的效率。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² * L) | O(n) | 明确测试每一对 |
 | 最佳| O(n + 26² * S) | O(n) | 按第一个字符对后缀进行分组 |

 这里：

-`n`= 想法数量
 -`L`= 平均字符串长度
 -`S`= 平均后缀集比较成本

 由于只有 26 个字母，因此实际中最佳解决方案实际上是线性的。 

## 算法演练

 ### 第 1 步：按起始字母对后缀进行分组

 创建 26 组。 

每个集合存储属于以特定字符开头的单词的后缀。 

例子：```
coffee -> c : offee
donuts -> d : onuts
time -> t : ime
toffee -> t : offee
```结果：```
c -> {offee}
d -> {onuts}
t -> {ime, offee}
```我们使用集合是因为：

 - 成员资格检查是 O(1)
 - 交叉路口操作变得容易
 - 自动避免重复

 ### 步骤 2：比较每对起始字母

 只有26个小写英文字母。 

对于每对`(i, j)`在哪里`i < j`：

 1. 计算共享后缀的数量。 
2. 共享后缀无法安全交换。 

认为：```
Group i size = A
Group j size = B
Shared suffixes = C
```然后：```
Unique to i = A - C
Unique to j = B - C
```组中每个独特的后缀`i`可以与组中的每个独特后缀配对`j`。 

这给出：```
(A - C) * (B - C)
```无序对。 

由于该问题计算有序对：```
2 * (A - C) * (B - C)
```将其添加到答案中。 

### 第三步：返回最终答案

 处理完所有 26 个字母对后，返回累计总数。 

### 为什么它有效

 当生成的名称都不存在时，交换才是有效的。 

如果生成的名称的后缀已属于目标起始字母组，则该名称存在。 

因此：

 - 共享后缀总是产生无效的交换
 - 非共享后缀总是产生有效的交换

 通过仅计算每个组特有的后缀，我们可以准确计算有效组合并避免重复计算。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def distinctNames(self, ideas: List[str]) -> int:
        groups = [set() for _ in range(26)]

        for idea in ideas:
            first_index = ord(idea[0]) - ord('a')
            suffix = idea[1:]
            groups[first_index].add(suffix)

        answer = 0

        for i in range(26):
            for j in range(i + 1, 26):
                common_suffixes = len(groups[i] & groups[j])

                unique_i = len(groups[i]) - common_suffixes
                unique_j = len(groups[j]) - common_suffixes

                answer += 2 * unique_i * unique_j

        return answer
```该实现首先创建 26 个集合，每个小写字母一组。 每个单词将其后缀贡献到与其起始字符相对应的集合中。 

嵌套循环迭代每对起始字母组。 由于只有 26 个字母，因此这个循环非常小且高效。 

相交运算：```python
groups[i] & groups[j]
```查找两个组共享的后缀。 这些共享后缀将在交换后重新创建现有单词，因此它们无法构成有效名称。 

从每个组大小中减去共享后缀计数后，我们获得每个组特有的后缀数。 将这些计数相乘即可得到有效无序对的数量，乘以 2 将它们转换为有序对。 

最后返回累积的答案。 

## 解决方案```go
func distinctNames(ideas []string) int64 {
	groups := make([]map[string]bool, 26)

	for i := 0; i < 26; i++ {
		groups[i] = make(map[string]bool)
	}

	for _, idea := range ideas {
		first := int(idea[0] - 'a')
		suffix := idea[1:]
		groups[first][suffix] = true
	}

	var answer int64 = 0

	for i := 0; i < 26; i++ {
		for j := i + 1; j < 26; j++ {
			common := 0

			for suffix := range groups[i] {
				if groups[j][suffix] {
					common++
				}
			}

			uniqueI := len(groups[i]) - common
			uniqueJ := len(groups[j]) - common

			answer += int64(2 * uniqueI * uniqueJ)
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用`map[string]bool`来模拟集合。 

答案使用`int64`因为有效有序对的数量可能超出标准 32 位整数的范围。 

与 Python 不同，Go 不提供内置的集合交集运算，因此我们通过迭代一个映射并检查另一个映射中的成员资格来手动计算共享后缀。

 ## 边缘情况

 一种重要的边缘情况是多个单词共享相同的后缀。 例如：```
["lack", "back", "hack"]
```这三个词共享`"ack"`作为后缀。 交换第一个字母只是重新创建现有单词，因此每次交换都是无效的。 幼稚的实现可能会意外地将这些视为有效，除非它显式检查后缀重叠。 集合交集逻辑自然地处理这个问题，因为共享后缀被排除在考虑范围之外。 

另一个重要的边缘情况涉及单字符字符串，例如：```
["a", "b"]
```两个单词的后缀都是空字符串`""`。 交换第一个字母会重新创建已经存在的相同单词。 该实现正确存储空后缀并将它们像任何其他后缀一样对待，从而防止错误计数。 

当几乎每个交换都有效时，就会出现第三种边缘情况。 例如：```
["abc", "def", "ghi", "jkl"]
```所有后缀都是唯一的，因此每一对都充分贡献。 这可以产生很大的答案，尤其是在约束上限附近。 Go 实现使用`int64`以避免整数溢出，而 Python 整数会根据需要自动扩展。
