[LeetCode 问题 2389](https://leetcode.com/problems/longest-subsequence-with-limited-sum/)

 **难度：** 🟢简单
 **主题：** 数组、二分搜索、贪心、排序、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定，对于每个查询，我们可以从数组中选择的最大元素数`nums`使得它们的总和不超过给定值。 我们不需要维护连续的元素，只需要维护子序列的相对顺序，但在这个问题中，相对顺序不会影响总和，因为我们可以选择元素的任意组合。 输入是两个整数数组，`nums`长度`n`和`queries`长度`m`，两者的值范围都是从 1 到 10^6。 输出是一个整数数组，其中每个条目对应于相应查询和约束下可实现的最大子序列长度。 

重要的边缘情况包括小于中最小元素的查询`nums`（生成长度为 0 的子序列）、大于所有元素总和的查询（生成完整数组）以及只有一个元素的数组。 约束条件（`n, m <= 1000`）表明我们可以轻松地提供 O(n log n) 或 O(n * m) 解决方案，但 O(2^n) 强力解决方案是不可行的。 

## 方法

 蛮力方法将涉及生成所有子序列`nums`对于每个查询并计算它们的总和。 然后，我们将选择总和不超过查询的最长子序列。 虽然这保证了正确性，但它的速度呈指数级缓慢 (O(2^n * m))，并且对于`n = 1000`。 

最佳方法利用了这样的观察：总和约束下的最大长度子序列是通过首先选择最小的数字来获得的。 这导致排序`nums`按升序排列并使用前缀和快速计算第一个的总和`k`数字。 对于每个查询，我们找到最大的`k`这样第一个的前缀和`k`元素小于或等于查询。 二分查找可以有效地确定`k`对于每个查询。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * 2^n) | O(m * 2^n) | O(n) | 为每个查询生成所有子序列，对于 n > 20 不可行 |
 | 最佳 | O(n log n + m log n) | O(n log n + m log n) | O(n) | 对数组进行排序，计算前缀和，对每个查询使用二分搜索 |

 ## 算法演练

 1. 排序`nums`数组按升序排列。 这确保了顺序添加元素将最大化我们可以包含的元素数量而不超过总和。 
2. 计算前缀和`nums`。 让`prefix[i]`代表第一个的总和`i+1`元素。 这允许从头开始对任何连续子集进行恒定时间求和计算。 
3.对于每个查询，在前缀和数组上使用二分查找来找到最大的索引`i`这样`prefix[i] <= query`。 该索引 + 1 给出最大子序列长度。 
4. 将所有查询的结果收集到输出数组中并返回。 

工作原理：排序可确保首先考虑最小的数字，从而在总和限制下最大化计数。 前缀和允许我们有效地检查第一个的和`k`元素。 二分查找保证我们找到最大值`k`有效地处理每个查询。 

## Python 解决方案```python
from typing import List
import bisect

class Solution:
    def answerQueries(self, nums: List[int], queries: List[int]) -> List[int]:
        nums.sort()
        prefix_sums = [0] * len(nums)
        prefix_sums[0] = nums[0]
        for i in range(1, len(nums)):
            prefix_sums[i] = prefix_sums[i - 1] + nums[i]
        
        answer = []
        for query in queries:
            index = bisect.bisect_right(prefix_sums, query)
            answer.append(index)
        return answer
```Python 实现首先对数组进行排序并计算前缀和。 然后我们迭代每个查询，使用`bisect_right`找到查询将超过前缀和的插入点。 该索引正是该查询的最大子序列长度。 使用`bisect_right`即使查询与前缀和完全匹配，也能确保正确性。 

## 解决方案```go
import "sort"

func answerQueries(nums []int, queries []int) []int {
    sort.Ints(nums)
    prefixSums := make([]int, len(nums))
    prefixSums[0] = nums[0]
    for i := 1; i < len(nums); i++ {
        prefixSums[i] = prefixSums[i-1] + nums[i]
    }

    answer := make([]int, len(queries))
    for i, query := range queries {
        left, right := 0, len(prefixSums)
        for left < right {
            mid := (left + right) / 2
            if prefixSums[mid] <= query {
                left = mid + 1
            } else {
                right = mid
            }
        }
        answer[i] = left
    }
    return answer
}
```在Go中，我们手动实现二分查找来找到最大的索引`i`和`prefixSums[i] <= query`。 这避免了使用额外的包进行二等分操作。 逻辑反映了 Python 版本，但我们显式处理切片和索引。 

## 工作示例

 **示例1：`nums = [4,5,2,1], queries = [3,10,21]`**

 排序后，`nums = [1,2,4,5]`。 前缀和：`[1,3,7,12]`。 

| 查询 | 二分查找结果 | 说明|
 | --- | --- | --- |
 | 3 | 2 | 前缀和 ≤ 3 为`[1,3]`，长度 = 2 |
 | 10 | 10 3 | 前缀和 ≤ 10 是`[1,3,7]`，长度= 3 |
 | 21 | 21 4 | 前缀和 ≤ 21 为`[1,3,7,12]`，长度= 4 |

 **示例2：`nums = [2,3,4,5], queries = [1]`**

 排序：`[2,3,4,5]`。 前缀和：`[2,5,9,14]`。 查询1小于最小元素，所以结果是`0`。

 ## 边缘情况

 一种边缘情况是当所有元素都在`nums`大于查询。 在这种情况下，最大子序列长度为 0。排序和二分搜索可以正确处理此问题，因为第一个前缀和超出了查询。 

当查询大于中所有元素的总和时，会出现另一种边缘情况`nums`。 该算法返回完整长度`nums`，因为二分搜索将越过最后一个索引。 

第三种边缘情况是当`nums`包含重复的数字。 排序和前缀和自然会累积重复项，并且二分搜索正确地解释了它们，确保长度计算包括所有可用元素。 

该解决方案可以有效、正确地处理所有这些边缘情况。
