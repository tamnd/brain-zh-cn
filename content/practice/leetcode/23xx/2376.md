 # LeetCode 2376 - 计算特殊整数

 ## 问题理解

 该问题要求我们计算范围内有多少个整数`[1, n]`仅包含不同的数字。 如果一个数字在其十进制表示形式中没有出现多次，则该数字被视为特殊数字。 

例如，数字`135`很特别，因为数字`1`,`3`， 和`5`都是不同的。 然而，`131`并不特殊，因为数字`1`出现两次。 

输入由单个正整数组成`n`，并且我们必须返回所有小于或等于的特殊整数的计数`n`。 

约束条件`1 <= n <= 2 * 10^9`非常重要。 自从`n`可以大到 20 亿，迭代其中的每个数字`1`到`n`并且检查数字唯一性会太慢。 甚至一个`O(n)`对于最大的输入，算法无法及时完成。 

这立即表明我们需要一种基于组合或动态编程的方法来计算有效数字，而无需显式生成所有数字。 

一些边缘情况很重要：

 - 很早就出现重复数字的数字，例如`11`或者`100`，如果不仔细处理重复项，很容易导致计数错误。 
- 带有前导零的数字不得被视为实际数字表示中的有效数字。 
- 上限附近的大值，例如`2 * 10^9`，需要有效的逐位计数策略。 
- 个位数总是特殊的，因为没有数字重复。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代每个整数`1`到`n`并检查所有数字是否不同。 

对于每个数字：

 1. 提取其数字。 
2. 将数字存储在一组中。 
3. 如果一个数字出现两次，则该数字不特殊。 
4. 否则，增加答案。 

这种方法是正确的，因为它显式验证特殊整数的定义属性。 

然而，复杂性太大了。 如果`n = 2 * 10^9`，我们可能会检查数十亿个数字。 尽管检查每个数字只需要位数的对数时间，但总运行时间变得不切实际。 

### 最优方法，组合数学的数字DP

 关键的见解是我们不需要单独枚举每个有效数字。 

相反，我们计算可以逐位组成多少个有效数字。 

最优策略分两个阶段进行：

 1. 统计所有位数少于的特殊数字`n`。 
2. 统计与以下位数相同的特殊数字`n`，同时确保构建的数量永远不会超过`n`。 

这是一个经典的数字 DP 或组合计数问题。 

在每个数字位置：

 - 我们尝试放置一个较小的未使用数字。 
- 然后计算剩余的有效完成次数。 
- 我们跟踪哪些数字已被使用。 

由于最大位数只有 10 位，因此这种方法非常有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(log n) | 单独检查每个数字 |
 | 最佳| O(d²) | O(d) | 使用组合数学和逐位计数 |

 这里，`d`是数字的个数`n`， 和`d <= 10`。 

## 算法演练

 ### 第 1 步：转换`n`到数字数组中

 我们首先转换`n`转换为字符串或数字列表，以便我们可以从左到右单独处理每个数字。 

例如：```
n = 135
digits = ['1', '3', '5']
```这使我们能够将构建的数字与`n`一个数字一个数字。 

### 步骤2：统计所有位数较少的特殊数字

 任何位数少于`n`自动小于`n`。 

对于每个可能的长度：

 - 第一个数字不能为零。 
- 其余数字必须全部不同。 

例如，对于 2 位数字：

 - 第一个数字：9 个选择（`1-9`）
 - 第二位数字：9 个选择（`0-9`除使用的数字外）

 总计：```
9 × 9 = 81
```对于 3 位数字：```
9 × 9 × 8 = 648
```我们使用排列来计算这些计数。 

### 步骤3：处理数字长度相同的数字

 现在我们计算与以下位数相同的有效数字`n`。 

我们从左到右处理每个数字位置。 

在每个位置：

 - 尝试放置一个较小的未使用的数字。 
- 计算后面的位置还剩下多少条有效路径。 
- 然后继续使用实际数字`n`如果尚未使用。 

### 第 4 步：跟踪使用过的数字

 我们维护一组已使用的数字。 

例如，如果我们已经使用了`{1, 3}`，那么：

 - 我们不能放置`1`或者`3`再次。 
- 未来的所有选择都必须避免这些数字。 

这保证了所有构造的数字都保持特殊。 

### 步骤 5：如果出现重复数字则停止

 如果当前数字为`n`已经被使用过，那么：

 - 沿着这条路径不能形成更多的有效数字。 
- 我们提前终止。 

例如：```
n = 131
```最后一位数字：

 -`1`已被使用。 
- 所以不存在有效的延续。 

### 第 6 步：包含`n`本身（如果有效）

 如果我们成功地处理每个数字而不重复，那么`n`本身很特殊，所以我们给答案加1。 

## 为什么它有效

 该算法系统地对每个有效数字仅计数一次。 

位数较少的数字使用排列独立计数。 数字长度相同的数字将按数字进行计数，同时保留上限约束。 

在每个位置：

 - 我们只使用未使用的数字。 
- 我们只构造小于或等于相应前缀的前缀`n`。 

因此：

 - 每个计数的数字都是有效的。 
- 每个有效数字只计算一次。 

这样就保证了正确性。 

## Python 解决方案```python
class Solution:
    def countSpecialNumbers(self, n: int) -> int:
        digits = list(map(int, str(n)))
        length = len(digits)

        def permutations(m: int, k: int) -> int:
            result = 1
            for i in range(k):
                result *= (m - i)
            return result

        answer = 0

        # Count numbers with fewer digits
        for digits_count in range(1, length):
            count = 9
            available = 9

            for _ in range(digits_count - 1):
                count *= available
                available -= 1

            answer += count

        used = set()

        # Count numbers with same length
        for index in range(length):
            current_digit = digits[index]

            for digit in range(0 if index > 0 else 1, current_digit):
                if digit in used:
                    continue

                remaining_positions = length - index - 1
                remaining_digits = 10 - (index + 1)

                answer += permutations(
                    remaining_digits,
                    remaining_positions
                )

            if current_digit in used:
                return answer

            used.add(current_digit)

        return answer + 1
```实现从转换开始`n`到一个数字数组中，以便我们可以单独处理数字。 

辅助函数`permutations(m, k)`计算：```python
P(m, k) = m × (m - 1) × ...
```这表示使用不同数字填充剩余位置的方法数量。 

第一个循环计算所有位数少于的特殊数字`n`。 由于这些数字总是小于`n`，不需要进行上限检查。 

第二个循环处理与以下数字长度相同的数字`n`。 

在每个数字位置：

 - 我们尝试所有较小的有效数字。 
- 对于每个选择，我们计算可以形成多少个有效后缀。 
- 然后我们继续使用实际的数字`n`。 

这`used`设置确保没有数字重复。 

如果重复的数字出现在`n`本身，算法会立即停止，因为该前缀不能存在更多有效数字。 

如果循环成功完成，则`n`它本身很特殊，所以我们最后添加一个计数。 

## 解决方案```go
func countSpecialNumbers(n int) int {
	digits := []int{}
	temp := n

	for temp > 0 {
		digits = append([]int{temp % 10}, digits...)
		temp /= 10
	}

	length := len(digits)

	permutations := func(m int, k int) int {
		result := 1

		for i := 0; i < k; i++ {
			result *= (m - i)
		}

		return result
	}

	answer := 0

	// Count numbers with fewer digits
	for digitsCount := 1; digitsCount < length; digitsCount++ {
		count := 9
		available := 9

		for i := 0; i < digitsCount-1; i++ {
			count *= available
			available--
		}

		answer += count
	}

	used := make(map[int]bool)

	// Count numbers with same length
	for index := 0; index < length; index++ {
		currentDigit := digits[index]

		start := 0
		if index == 0 {
			start = 1
		}

		for digit := start; digit < currentDigit; digit++ {
			if used[digit] {
				continue
			}

			remainingPositions := length - index - 1
			remainingDigits := 10 - (index + 1)

			answer += permutations(
				remainingDigits,
				remainingPositions,
			)
		}

		if used[currentDigit] {
			return answer
		}

		used[currentDigit] = true
	}

	return answer + 1
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用`map[int]bool`而不是使用 Python 设置来跟踪已使用的数字。 

因为 Go 没有内置的排列助手，所以我们手动将其实现为闭包。 

Go 中的数字提取步骤也更加明确。 我们重复除以 10 并将数字添加到切片中。 

所有计算都安全地适合 Go 的范围`int`类型，因为特殊整数的总数最多为`10!`，这完全在整数限制内。

 ## 边缘情况

 一个重要的边缘情况是当`n`本身很早就包含重复的数字，例如`11`或者`100`。 即使在重复发生后，有缺陷的实现也可能会继续处理后面的数字。 一旦检测到重复的数字，我们的实现就会立即终止，因为除了该前缀之外不能存在有效的数字。 

另一个重要的情况涉及前导零。 计算数字长度相同的数字时，第一位数字不能为零。 如果忘记了这条规则，无效的较短数字将被意外地计算多次。 我们的实现通过从第一个数字循环开始来处理这个问题`1`，而后面的位置可能会使用`0`。 

第三个棘手的情况发生在十的幂附近，例如`1000`。 这些值包含重复的零，这通常会暴露排列计数逻辑中的错误。 我们的实现首先正确地计算所有较小的有效数字，然后在前缀中出现重复时终止。 

最后，每个数字都是唯一的数字，例如`123456789`，要求包括`n`本身就在最终的答案中。 仅当全数字扫描完成且不重复时，我们的实现才会添加 1。
