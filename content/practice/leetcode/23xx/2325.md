[LeetCode 问题 2325](https://leetcode.com/problems/decode-the-message/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串

 ## 解决方案

 ## 问题理解

 这个问题要求我们使用由密钥字符串定义的替换密码来解码秘密消息。 键字符串可以包含空格并且包含英文字母表中的每个小写字母至少一次。 每个字母在键中首次出现的顺序决定了到常规字母表的映射。 例如，键中的第一个唯一字母映射到`'a'`，第二个独特的字母`'b'`， 等等。 消息中的空格保持不变。 输入`key`最多可包含 2000 个字符，并且`message`can also have up to 2000 characters, so efficiency matters but we are not dealing with extremely large inputs. Edge cases to consider include keys with repeated letters and messages consisting entirely of spaces.

 The expected output is a fully decoded string where each letter has been substituted according to the mapping defined by the key. 这些约束保证密钥始终包含所有 26 个字母，并且两个字符串均由小写字母和空格组成，这简化了问题，因为我们不需要处理意外字符。 

## 方法

 强力方法需要多次迭代密钥字符串以确定每个字母的映射，然后使用此映射替换消息中的每个字母。 虽然这种方法有效，但效率很低，因为重复扫描每个字母的第一次出现可能会导致不必要的重复工作，尤其是在密钥很长的情况下。 

The optimal approach leverages a hash map to record the first appearance of each letter in a single pass. We maintain a mapping from the letters in the key to`'a'`通过`'z'`。 一旦建立了映射，解码消息就很简单：对于消息中的每个字符，如果它是字母，我们使用哈希映射来替换它，如果它是空格，我们则保持不变。 这将操作减少为一次密钥扫描和一次消息扫描，从而导致相对于输入字符串长度的线性时间复杂度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(26 * 密钥长度 + 消息长度) | O(26) | Repeatedly scan key to find first occurrences, then decode message |
 | 最佳| O(key.length + message.length) | O(key.length + message.length) | O(26) | Single pass to build mapping, single pass to decode message |

 ## 算法演练

 1. Initialize an empty dictionary (hash map) to store the mapping from key letters to the regular alphabet. Also, maintain a variable to track the current letter in the alphabet starting from`'a'`。 
2. Iterate through each character in the key string. 如果该字符是空格，则跳过它。 If the character has not been seen before in the mapping, map it to the current alphabet letter and advance the alphabet letter by one.
 3. After scanning the key, the dictionary now contains a complete substitution table for all 26 letters.
 4. Initialize an empty list to build the decoded message. Iterate over each character in the message string. If the character is a space, append a space to the list. Otherwise, look up the character in the dictionary and append the corresponding decoded letter.
 5. Join all characters in the list to form the final decoded string and return it.

 为什么有效：通过记录每个字母的第一次出现并将其按顺序映射到字母表，我们完全按照所描述的方式保留替换规则。 Spaces are left unchanged, and every message character is guaranteed to have a mapping because the key includes all letters.

 ## Python 解决方案```python
class Solution:
    def decodeMessage(self, key: str, message: str) -> str:
        mapping = {}
        current_char = 'a'
        
        for char in key:
            if char == ' ':
                continue
            if char not in mapping:
                mapping[char] = current_char
                current_char = chr(ord(current_char) + 1)
                if current_char > 'z':
                    break
        
        decoded_chars = []
        for char in message:
            if char == ' ':
                decoded_chars.append(' ')
            else:
                decoded_chars.append(mapping[char])
        
        return ''.join(decoded_chars)
```Python 实现完全遵循该算法。 它使用字典来记录字母的第一次出现，确保在构建映射时跳过空格，并在加入字符串之前使用列表有效地构造解码消息。 之后的中断条件`'z'`是可选的，但如果密钥比所需的长度长，则会稍微提高效率。 

## 解决方案```go
func decodeMessage(key string, message string) string {
    mapping := make(map[rune]rune)
    currentChar := 'a'
    
    for _, char := range key {
        if char == ' ' {
            continue
        }
        if _, exists := mapping[char]; !exists {
            mapping[char] = currentChar
            currentChar++
            if currentChar > 'z' {
                break
            }
        }
    }
    
    decoded := make([]rune, len(message))
    for i, char := range message {
        if char == ' ' {
            decoded[i] = ' '
        } else {
            decoded[i] = mapping[char]
        }
    }
    
    return string(decoded)
}
```Go 实现镜像了 Python 逻辑，但显式处理符文，因为 Go 字符串是 UTF-8 编码的。 映射用于替换表，符文切片用于在将解码消息转换为字符串之前有效地构建解码消息。

 ## 边缘情况

 一种边缘情况是密钥在覆盖所有字母之前包含许多重复的字母。 该实现正确地跳过重复项，仅映射第一次出现的位置，确保使用正确的顺序字母表。 

另一种边缘情况是消息完全由空格组成。 由于空格已被显式处理，因此输出可以正确保留它们而无需映射。 

第三种边缘情况是消息包含字母表末尾的字母，例如`'z'`，并且键将它们映射到最后。 该实现保证在解码之前映射所有字母，因此无论密钥中的字母位置如何，消息都会正确解码。
