 # LeetCode 2362 - 生成发票

 ## 问题理解

 这是一个涉及两个表的 SQL 数据库问题：

 ### 产品

 | 产品 ID | 价格|
 | --- | --- |
 | 唯一的产品标识符| 产品单价|

 ### 购买

 | 发票 ID | 产品 ID | 数量 |
 | --- | --- | --- |
 | 发票标识符 | 购买的产品 | 购买的单位数量 |

 中的每一行`Purchases`代表发票中包含的一种产品。 自从`(invoice_id, product_id)`是主键，同一产品不能在同一张发票中出现两次。 

发票的总价值通过求和计算：$$\text{quantity} \times \text{price}$$对于该发票中包含的每件产品。 

任务由两部分组成：

 1. 计算每张发票的总价。 
2. 查找总价最高的发票。 

- 如果多张发票的最高价格相同，则选择最小的一张`invoice_id`。 
3. 返回属于该选定发票的所有产品系列。 
4. 对于每个退回的产品，输出：

 -`product_id`-`quantity`-`price`， 在哪里`price = quantity × unit_price`输出可以按任何顺序返回。 

### 示例解释

 对于发票 2：

 | 产品 ID | 数量 | 单价|
 | --- | --- | --- |
 | 1 | 4 | 100 | 100
 | 2 | 3 | 200 | 200

 行总数为：

 - 产品 1：4 × 100 = 400
 - 产品 2：3 × 200 = 600

 发票总额：

 400 + 600 = 1000

 如果这是最高发票值，这两行将成为输出。 

### 重要的边缘案例

 有几种情况很容易引入错误：

 - 多张发票可以共享相同的最大总价值。 最小的`invoice_id`必须被选择。 
- 一张发票只能包含一种产品。 
- 不同的发票可能具有相同的总计，但产品数量不同。 
- 返回的行必须包含行项目价格（`quantity × unit_price`)，而不是发票总额。 
- 输出顺序未指定，因此无需排序。 

因为这是一个数据库问题，所以效率来自于使用聚合和连接，而不是过程迭代。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是：

 1. 加入`Purchases`和`Products`。 
2. 计算每个行项目的成本。 
3. 按发票分组并计算发票总额。 
4. 扫描所有发票以找到最大的总额。 
5. 通过选择最小的发票 ID 来处理平局。 
6. 再次查询所选发票以检索其行项目。 

这种方法在逻辑上是正确的，因为它在选择最佳候选者之前显式计算每张发票总额。 

然而，编写单独的中间计算并重复处理相同的数据是不必要的。 SQL聚合可以在单个查询结构中更优雅地执行这些操作。 

### 关键见解

 重要的观察是发票总额可以直接使用以下方法计算：```
SUM(quantity * price)
```分组依据`invoice_id`。 

一旦我们有了发票总额：

 - 按总价降序排序。 
- 按发票 ID 升序排序以打破平局。 
- 拿走第一张发票。 

识别该发票后，连接回购买行并计算每个产品的贡献：```
quantity * price
```这自然会产生所需的输出。

 | --- | --- | --- | --- |
 | 蛮力 | O(P)| O(P)| 购买记录的多重逻辑传递 |
 | 最佳 | O(P)| O(P)| 直接在 SQL 中执行聚合和选择 |
 | 其中 P = 购买行数 | | | |

 ## 算法演练

 ### 最优 SQL 算法

 1. 加入`Purchases`和`Products`使用`product_id`。 

这样可以访问计算成本所需的购买数量和单价。 
2. 对连接的行进行分组`invoice_id`。 

对于每张发票，计算：```sql
SUM(quantity * price)
```这给出了发票总价值。 
3. 对发票总额进行排序。 

排序依据：

 - 总价值递减
 - 发票 ID 升序

 这保证了最高价值的发票首先出现，并且使用最小的发票 ID 解决平局。 
4. 选择第一张发票。 

这将成为必须返回其详细信息的目标发票。 
5. 将所选发票连接回原始采购行。 

检索属于该发票的所有产品。 
6. 计算每个行项目的价格。 

对于所选发票中的每个产品：```sql
quantity * unit_price
```7、退货：

 -`product_id`-`quantity`- 计算的行项目价格

 ### 为什么它有效

 分组步骤计算每张发票的确切总价值。 按总价值降序排序可保证最大发票出现在所有其他发票之前。 按发票 ID 升序排序可确保当多个发票共享相同的总值时，选择最小的发票 ID。 一旦识别出正确的发票，返回属于该发票的所有行将准确产生问题所需的输出。 

## SQL 解决方案```sql
WITH invoice_totals AS (
    SELECT
        p.invoice_id,
        SUM(p.quantity * pr.price) AS total_price
    FROM Purchases p
    JOIN Products pr
        ON p.product_id = pr.product_id
    GROUP BY p.invoice_id
),
best_invoice AS (
    SELECT invoice_id
    FROM invoice_totals
    ORDER BY total_price DESC, invoice_id ASC
    LIMIT 1
)
SELECT
    p.product_id,
    p.quantity,
    p.quantity * pr.price AS price
FROM Purchases p
JOIN Products pr
    ON p.product_id = pr.product_id
JOIN best_invoice b
    ON p.invoice_id = b.invoice_id;
```### 实现说明

 第一个公共表表达式，`invoice_totals`，计算每张发票的总货币价值。 这是通过将每个购买行与其产品价格连接起来并求和来完成的`quantity * price`每张发票。 

第二个公共表表达式，`best_invoice`，选择应退回的发票。 发票按总价值降序排列，因此价值最高的发票首先出现。 按发票 ID 进行二次排序可确保正确打破平局。 

最后，将所选发票与购买记录和产品价格连接起来。 对于每个购买的产品，查询使用以下方法计算行项目价格`quantity * unit_price`并返回所需的列。

 ## 边缘情况

 ### 多张发票共享最大总计

 这是问题中最重要的边缘情况。 仅查找最大发票金额的解决方案可能会返回任何匹配的发票。 该问题明确要求选择最小的`invoice_id`。 这`ORDER BY total_price DESC, invoice_id ASC`条款保证正确的平局解决。 

### 发票仅包含一种产品

 某些发票可能包含单个采购行。 聚合仍然可以正常工作，因为发票总额成为该单个行项目的值。 无需特殊处理。 

### 每张发票的产品数量不同

 一张发票可能包含多种产品，而另一张发票只包含一种产品。 获胜者仅由所有行项目值的总和决定。 分组操作在比较之前正确累积属于同一发票的所有产品。 

### 返回的价格是订单项价格

 一个常见的错误是返回每行的发票总额。 输出需要所选发票中每种产品的价格贡献。 计算`quantity * unit_price`在最终查询中确保为每一行返回正确的值。
