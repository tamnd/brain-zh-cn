[LeetCode 问题 2304](https://leetcode.com/problems/minimum-path-cost-in-a-grid/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们一个矩阵，称为`grid`和`m`行和`n`列。 每个单元格包含一个唯一的整数`0`到`m * n - 1`。 我们可以从第一行中的任何单元格开始，一次向下移动一行，直到到达最后一行。 

移动规则非常灵活。 如果我们当前处于位置`(r, c)`，我们可以移动到下一行中的任何列，这意味着从`(r, c)`我们可以搬到`(r + 1, 0)`,`(r + 1, 1)`，依此类推，直到`(r + 1, n - 1)`。 

每一次搬家都会产生额外的费用。 此成本不是基于坐标，而是基于当前单元格和目标列中存储的值。 具体来说：

 - 假设当前单元格包含值`v`- 假设我们进入列`nextCol`下一行的
 - 那么移动成本是`moveCost[v][nextCol]`总路径成本包含两个组成部分：

 1.访问过的所有网格单元值的总和
 2. 行间所有移动成本的总和

 我们必须计算所有有效的自上而下路径中可能的最小总成本。 

约束很重要，因为它们告诉我们搜索空间可以变得有多大：

 -`m`和`n`每个最多`50`- 网格最多包含`2500`细胞
 - 从每个细胞我们可以分支到`50`可能的下一个单元格

 简单的递归探索可能会检查指数数量的路径。 由于每一行转换都会增加可能性的数量，因此暴力很快就变得不可行。 

该问题保证：

 - 所有网格值都是不同的
 - 网格值范围为`0`到`m*n - 1`- 每次移动成本查找均有效
 - 总是至少有两行和两列

 重要的边缘情况包括：

 - 非常小的网格，例如`2 x 2`- 由于移动成本占主导地位，最便宜的下一个单元格值不属于最佳路径的情况
 - 大单元格值仍然是最佳的情况，因为它可以在以后实现非常便宜的转换
 - 产生相似中间成本的多条路径

 这些观察结果强烈建议采用动态编程方法，因为达到某个状态的最小成本仅取决于先前计算的状态。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试从第一行到最后一行的所有可能路径。 

从第一行中的每个单元格开始，我们递归地探索下一行中所有可能的列选择。 对于每个转换，我们添加：

 - 当前单元格值
 - 搬家费用
 - 未来的路径成本

 最终我们到达最后一行，在其中添加最终的单元格值并终止递归。 

这种方法是正确的，因为它显式检查每条有效路径并返回最小总成本。 

然而，它太慢了。 如果有`n`每行转换的选择和`m`行，则路径数大约为：$$n^{m-1}$$和`n = 50`和`m = 50`，这变得天文数字般大。 

### 最优动态规划方法

 关键的见解是许多路径在子问题中重叠。 

假设我们已经知道到达行中每个单元格的最小成本`r`。 然后我们可以计算行中每个单元格的最小成本`r + 1`。 

定义：$$dp[r][c]$$作为到达细胞的最低成本`(r, c)`。 

过渡到`(r + 1, nextCol)`从`(r, c)`:$$dp[r][c] + moveCost[grid[r][c]][nextCol] + grid[r+1][nextCol]$$我们取前面所有可能的列中的最小值。 

由于每个状态仅取决于前一行，因此动态规划有效地避免了重复计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^(m-1)) | O(n^(m-1)) | O(米) | 递归探索每条可能的路径 |
 | 最优动态规划| O(m * n²) | O(n) | 逐行计算最小成本 |

 ## 算法演练

 1.让`m`是行数并且`n`是列数。 
2. 创建一个 DP 数组，表示到达当前行中每个单元格的最小成本。 

最初，第一行成本只是网格值本身，因为尚未进行任何移动。```
dp[c] = grid[0][c]
```3. 从上到下逐行处理。 
4. 对于每个新行，创建一个临时数组`next_dp`初始化为无穷大。 

该数组将存储到达下一行中每一列的最小成本。 
5. 对于每一列`c`在当前行中：

 - 让`currentValue = grid[row][c]`- 当前累计成本为`dp[c]`6. 尝试从此单元格移至每一列`nextCol`在下一行。 

新的成本变为：$$dp[c] + moveCost[currentValue][nextCol] + grid[row+1][nextCol]$$7.更新：```
next_dp[nextCol] = min(next_dp[nextCol], newCost)
```8. 处理完当前行的所有转换后，替换`dp`和`next_dp`。 
9.处理完最后一行后，答案就是里面的最小值`dp`。 

### 为什么它有效

 该算法保持不变式`dp[c]`始终存储到达列的最小可能成本`c`在当前行中。 

进入下一行的每个有效路径都必须来自前一行中的某个单元格。 通过检查所有转换并取最小值，我们保证最优子结构属性成立。 由于每个状态都是根据已经最优的先前状态计算的，因此最终答案是全局最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minPathCost(self, grid: List[List[int]], moveCost: List[List[int]]) -> int:
        m = len(grid)
        n = len(grid[0])

        dp = grid[0][:]

        for row in range(m - 1):
            next_dp = [float("inf")] * n

            for col in range(n):
                current_value = grid[row][col]
                current_cost = dp[col]

                for next_col in range(n):
                    total_cost = (
                        current_cost
                        + moveCost[current_value][next_col]
                        + grid[row + 1][next_col]
                    )

                    next_dp[next_col] = min(
                        next_dp[next_col],
                        total_cost
                    )

            dp = next_dp

        return min(dp)
```实现首先存储网格的尺寸。 这`dp`数组使用第一行中的值进行初始化，因为从一个单元格开始花费的正是该单元格的值。 

对于每一行转换，都有一个新的`next_dp`数组已创建。 每个元素都从无穷大开始，因为我们正在寻找最小成本。 

嵌套循环代表所有可能的转换：

 - 当前行中的当前列
 - 下一行的目标列

 对于每次转换，算法都会计算总累积路径成本并更新目标列的最佳已知值。 

处理完一行的所有转换后，`dp`被替换为`next_dp`。 这是可行的，因为未来的行仅依赖于前一行。 

最后，处理完所有行后，将得到最小值`dp`表示在最后一行任意位置结束的最便宜路径。 

## 解决方案```go
package main

import "math"

func minPathCost(grid [][]int, moveCost [][]int) int {
	m := len(grid)
	n := len(grid[0])

	dp := make([]int, n)

	for col := 0; col < n; col++ {
		dp[col] = grid[0][col]
	}

	for row := 0; row < m-1; row++ {
		nextDP := make([]int, n)

		for i := 0; i < n; i++ {
			nextDP[i] = math.MaxInt32
		}

		for col := 0; col < n; col++ {
			currentValue := grid[row][col]
			currentCost := dp[col]

			for nextCol := 0; nextCol < n; nextCol++ {
				totalCost := currentCost +
					moveCost[currentValue][nextCol] +
					grid[row+1][nextCol]

				if totalCost < nextDP[nextCol] {
					nextDP[nextCol] = totalCost
				}
			}
		}

		dp = nextDP
	}

	answer := dp[0]

	for i := 1; i < n; i++ {
		if dp[i] < answer {
			answer = dp[i]
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有为整数提供内置的无穷大值，`math.MaxInt32`用于用非常大的值初始化 DP 数组。 

切片用于动态数组。 算法更新`nextDP`逐行然后重新分配`dp = nextDP`。 

整数溢出在这里不是一个问题，因为在给定的约束下，最大可能的路径成本保持在 32 位整数范围内。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m * n²) | 对于每个行转换，每一列都会尝试所有接下来的列 |

空间优化之所以有效，是因为每个 DP 行仅依赖于前一行，因此无需存储整个 DP 表。

 ## 边缘情况

 一个重要的边缘情况是尽可能最小的网格，其中`m = 2`和`n = 2`。 在这种情况下，只有一个行转换。 当实现假设存在更多行或错误地初始化 DP 状态时，经常会出现错误。 此实现可以自然地处理这种情况，因为循环只运行一次并计算所有有效的转换。 

当最小的网格值不能产生最便宜的路径时，会发生另一个重要的情况。 贪心方法可能会错误地选择当前最小的单元值，但移动成本可以完全改变最优决策。 DP 解决方案正确评估总累计成本，而不仅仅是本地选择。 

第三种边缘情况涉及汇聚到同一目标小区的多条路径。 简单的递归解决方案可能会重复重新计算相同的状态，从而导致指数运行时间。 动态编程解决方案通过存储每行中每列的最小已知成本并有效地重用这些计算值来避免这种情况。
