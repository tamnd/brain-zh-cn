[LeetCode 问题 2383](https://leetcode.com/problems/minimum-hours-of-training-to-win-a-competition/)

 **难度：** 🟢简单
 **主题：** 数组，贪婪

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个起始值，`initialEnergy`和`initialExperience`，代表玩家在进入一系列比赛之前的统计数据。 我们还给出了两个数组，`energy`和`experience`，其中每个索引对应一个对手。 

为了打败对手`i`，玩家在战斗开始的那一刻必须满足两个严格的条件：

 - 当前能量必须严格大于`energy[i]`- 当前经验必须严格大于`experience[i]`击败对手后：

 - 玩家的能量减少`energy[i]`- 玩家的经验增加`experience[i]`比赛开始前，选手可以进行任意小时的训练。 每个小时的训练都可以增加能量或经验`1`。 目标是确定所需的最少总训练时间，以便玩家能够按顺序击败每个对手。 

关键细节是战斗是按顺序发生的。 在比赛中能量会永久减少，而经验会在每次胜利后增长。 由于经验会随着时间的推移而积累，因此可能没有必要从一开始就进行足够的训练来单独击败每个对手。 

限制很小：

 -`n <= 100`- 所有值最多为`100`这些限制意味着即使是简单的模拟也足够有效。 我们不需要先进的优化技术或复杂的数据结构。 

一些边缘情况很重要：

 - 玩家可能已经有足够的精力和经验，需要零训练。 
- 因为条件严格大于，所以相等是不够的。 如果当前能量等于对手能量，则需要多训练一小时。 
- 能量不断减少，所以我们必须保证足够的总能量来度过所有的战斗。 
- 每次胜利后经验都会增加，因此早期训练可能会消除后期训练的需要。 

## 方法

 ### 蛮力方法

 暴力方法会模拟不同量的训练并测试玩家是否可以击败所有对手。 例如，我们可以每小时重复增加能量或经验，直到模拟成功。 

模拟本身很简单：

 1. 从当前的精力和经验开始。 
2.按顺序处理对手。 
3. 如果任一统计数据不严格大于对手的统计数据，则模拟失败。 
4.否则，战斗结束后更新能量和经验。 

这种方法是正确的，因为它直接检查选定的训练量是否有效。 然而，尝试所有可能的训练分布是低效且不必要的。 尽管限制很小，但探索能量和经验的所有组合都会快速增长。 

### 最优贪心法

 重要的观察是能量和经验可以独立处理。 

对于能源：

 - 每场战斗都会永久消耗能量。 
- 要击败所有对手，初始能量必须严格大于消耗的总能量。 

如果所有对手能量的总和是`totalEnergy`，那么我们需要：$$initialEnergy + trainedEnergy > totalEnergy$$所以：$$trainedEnergy = \max(0, totalEnergy + 1 - initialEnergy)$$对于经验：

 - 每次胜利后经验都会增加。 
- 我们可以按顺序处理对手，并且只在必要时进行训练。 

对于每个对手：

 - 如果当前经验并不严格大于对手的经验，则训练足够使其大一即可。 
- 然后击败对手并获得他们的经验。 

这种贪婪策略是最优的，因为在任何步骤中进行超过必要的训练永远不会减少未来的训练要求。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(K × n) | O(1) | O(1) | 尝试多种训练分布并模拟战斗 |
 | 最佳 | O(n) | O(1) | O(1) | 直接计算所需能量并贪婪地处理经验|

 这里，`K`表示通过暴力方法探索的候选训练配置的数量。 

## 算法演练

 1. 计算在所有战斗中生存所需的总能量。 

由于能量只会在战斗中减少，因此玩家开始时的能量必须严格高于所有对手能量的总和。 
2. 计算额外的能量训练时间。 

如果`initialEnergy`已经大于所需的总能量，不需要进行能量训练。 否则，进行足够的训练，以便：$$currentEnergy = totalEnergy + 1$$3. 初始化当前体验。 

设置一个变量来跟踪玩家在比赛期间的当前体验。 
4.一一处理对手。 

对于每个对手：

 - 检查当前经验是否严格大于对手经验。 
- 如果没有，计算需要多少额外时间：$$needed = opponentExperience - currentExperience + 1$$- 将此值添加到答案中。 
- 相应增加当前经验。 
5.模拟击败对手。 

战斗获胜后，根据对手的经验值增加当前经验。 
6. 返回总训练时数。 

### 为什么它有效

 该算法之所以有效，是因为两种资源的行为不同。 

能量只会减少，所以唯一重要的是所有战斗所需的总量。 除了在序列中生存之外，较早拥有额外的能量不会提供额外的战略优势。 

然而，每次胜利后经验都会增长。 仅在必要时进行训练的贪婪策略是最佳的，因为之前执行的任何额外训练都可以简单地推迟到需要时为止。 因此，通过在每一步精确添加缺失量来实现最小总训练量。 

## Python 解决方案```python
from typing import List

class Solution:
    def minNumberOfHours(
        self,
        initialEnergy: int,
        initialExperience: int,
        energy: List[int],
        experience: List[int]
    ) -> int:
        
        total_training_hours = 0

        # Energy requirement
        total_energy_needed = sum(energy)

        if initialEnergy <= total_energy_needed:
            total_training_hours += (
                total_energy_needed + 1 - initialEnergy
            )

        # Experience requirement
        current_experience = initialExperience

        for opponent_experience in experience:
            if current_experience <= opponent_experience:
                extra_training = (
                    opponent_experience - current_experience + 1
                )

                total_training_hours += extra_training
                current_experience += extra_training

            current_experience += opponent_experience

        return total_training_hours
```实施过程首先计算所有战斗所需的总能量。 由于玩家在每次战斗前必须始终拥有严格的更大能量，因此所需的起始能量比总能量消耗大一。 

接下来，代码贪婪地处理经验。 变量`current_experience`跟踪玩家在整个比赛过程中的体验。 

对于每个对手：

 - 如果当前经验不足，代码会计算所需的确切训练小时数，以使其严格更大。 
- 这些培训时间已添加到答案中。 
- 更新了玩家的体验。 
- 击败对手后，对手的经验会添加到玩家的经验中。 

这直接反映了前面描述的算法。 

## 解决方案```go
package main

func minNumberOfHours(initialEnergy int, initialExperience int, energy []int, experience []int) int {
	totalTrainingHours := 0

	// Energy requirement
	totalEnergyNeeded := 0
	for _, value := range energy {
		totalEnergyNeeded += value
	}

	if initialEnergy <= totalEnergyNeeded {
		totalTrainingHours += totalEnergyNeeded + 1 - initialEnergy
	}

	// Experience requirement
	currentExperience := initialExperience

	for _, opponentExperience := range experience {
		if currentExperience <= opponentExperience {
			extraTraining := opponentExperience - currentExperience + 1

			totalTrainingHours += extraTraining
			currentExperience += extraTraining
		}

		currentExperience += opponentExperience
	}

	return totalTrainingHours
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一些特定于 Go 的细节值得注意：

 - Go 切片用于`energy`和`experience`数组。 
- 整数溢出不是问题，因为所有值都非常小。 
- 不需要对 nil 切片进行特殊处理，因为该问题保证了有效的输入数组。 
- 实施使用`range`循环以实现简洁的迭代。

 ## 边缘情况

 当玩家的统计数据与对手的统计数据完全相等时，就会出现一种重要的边缘情况。 该问题要求玩家的值严格大于，而不是大于或等于。 这很容易引入相差一的错误。 实现通过检查正确处理这个问题`<=`并添加`+1`当计算需要培训时。 

另一个重要的情况是当玩家已经有足够的能量和经验来击败每个对手时。 粗心的实现可能仍然会增加不必要的训练，因为它在增加值之前没有正确检查条件。 该解决方案通过仅在当前值不足时进行训练来避免这种情况。 

第三个边缘情况涉及比赛早期的大量经验跳跃。 假设玩家一开始的经验非常低，但击败一个强大的对手将为以后的所有战斗提供足够的经验。 幼稚的方法可能会通过独立考虑对手来高估训练。 贪婪模拟正确地考虑了每次胜利后积累的经验，确保只添加最少的必要训练。
