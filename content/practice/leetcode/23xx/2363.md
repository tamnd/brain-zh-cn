[LeetCode 问题 2363](https://leetcode.com/problems/merge-similar-items/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、排序、有序集

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个项目集合，`items1`和`items2`，其中每个项目都表示为一对：```
[value, weight]
```这`value`其作用就像一个项目的唯一标识符，而`weight`代表该物品的相关重量。 在每个单独的数组中，值保证是唯一的，这意味着内部没有值出现两次`items1`，并且内部没有任何值出现两次`items2`。 

我们的目标是将这两个集合合并为一个结果，其中具有相同的项目`value`被合并。 当两个数组中存在相同的值时，我们将它们的权重相加。 如果某个值仅出现在一个数组中，则其权重保持不变。 

结果必须作为列表返回`[value, totalWeight]`对按升序排序`value`。 

例如：```
items1 = [[1,1],[4,5],[3,8]]
items2 = [[3,1],[1,5]]
```价值`1`出现在两个数组中，因此它的总重量变为`1 + 5 = 6`。 

价值`3`也出现在两个数组中，因此它的总重量变为`8 + 1 = 9`。 

价值`4`仅出现在`items1`，所以仍然是`5`。 

最终结果变成：```
[[1,6],[3,9],[4,5]]
```这些约束提供了有关预期解决方案的重要提示。 每个数组最多可以包含`1000`items 相对较小，但仍然足够大，以至于低效的嵌套循环解决方案变得不那么有吸引力。 自从`valuei`和`weighti`的边界是`1000`，我们知道输入大小是可以管理的，但值的唯一性强烈建议使用哈希映射来进行有效聚合。 

一些重要的保证简化了实施。 我们在同一个数组中永远不会有重复的值，因此我们不需要重复合并来自单个源的条目。 每一项始终包含两个整数，并且两个数组都保证至少包含一个元素。 

有几种边缘情况值得预先考虑。 一种情况是当值之间没有重叠时`items1`和`items2`，在这种情况下，我们只需组合所有项目并对它们进行排序。 另一种情况是每个值都重叠，这意味着必须对每个权重求和。 第三种重要情况是，当一个数组仅包含一项而另一个数组包含多项时，确保实现正确处理高度不平衡的输入大小。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是迭代中的每个项目`items1`并在里面搜索匹配的值`items2`。 

对于中的每个项目`items1`，我们扫描整个`items2`查看是否存在相同的值。 如果找到，我们将权重相加。 完成此过程后，我们还必须扫描`items2`再次包含从未出现过的值`items1`。 

最后，我们按值对合并结果进行排序。 

这种方法是正确的，因为它显式检查两个数组之间的每个可能的匹配。 然而，它执行了多余的工作。 对于一个数组中的每一项，我们重复扫描另一个数组，导致时间复杂度呈二次方。 

### 最优方法，哈希图聚合

 关键的观察是，问题从根本上要求我们按以下方式对权重进行分组：`value`。 

我们可以使用哈希映射，而不是重复搜索匹配值，其中：```
key = value
value = total weight
```我们对两个数组都处理一次。 对于每个项目，我们将其权重添加到哈希映射中的相应条目。 

处理完两个数组后，哈希映射包含每个唯一值的正确总权重。 然后我们将哈希映射转换为所需的输出格式并按值排序。 

这很有效，因为哈希映射提供了平均值`O(1)`插入和查找时间，消除重复扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m + k log k) | O(n × m + k log k) | O(k) | 重复扫描一个数组以查找另一个数组中的匹配值 |
 | 最佳| O(n + m + k log k) | O(n + m + k log k) | O(k) | 使用哈希图有效聚合权重 |

 这里：

-`n = len(items1)`-`m = len(items2)`-`k = number of unique values`排序步骤有助于`O(k log k)`复杂。 

## 算法演练

 ### 最优算法

 1. Create an empty hash map called`weight_map`。 

该地图将存储每个唯一值的总累积权重。```
weight_map[value] = totalWeight
```2. 迭代`items1`。 

对于每个`[value, weight]`，将权重添加到地图上：```
weight_map[value] += weight
```如果该值尚不存在，则将其初始化为`0`添加之前。 
3. 迭代`items2`。 

重复相同的过程，将每个权重添加到相同的哈希映射中。 

这会自动合并重叠值并保留不重叠的值。 
4. 将哈希图转换为结果列表。 

对于每一个`(value, totalWeight)`在地图中配对，创建：```
[value, totalWeight]
```5. 按值升序对结果列表进行排序。 

由于该问题明确需要排序输出，因此最后一步可确保正确性。 
6. 返回排序后的结果。 

### 为什么它有效

 正确性来自处理两个数组后的不变量，`weight_map[v]`始终等于与值相关的所有权重之和`v`。 

每个项目只向其相应的映射条目贡献一次，并且因为我们永远不会错误地覆盖值，所以最终的映射包含精确的合并总数。 随后对结果进行排序可确保符合所需的升序。 

## Python 解决方案```python
from typing import List

class Solution:
    def mergeSimilarItems(
        self,
        items1: List[List[int]],
        items2: List[List[int]]
    ) -> List[List[int]]:

        weight_map = {}

        # Process first array
        for value, weight in items1:
            weight_map[value] = weight_map.get(value, 0) + weight

        # Process second array
        for value, weight in items2:
            weight_map[value] = weight_map.get(value, 0) + weight

        # Build and sort result
        result = []

        for value, total_weight in weight_map.items():
            result.append([value, total_weight])

        result.sort(key=lambda item: item[0])

        return result
```实现严格遵循算法。 

我们首先创建`weight_map`，存储按值索引的累积权重的字典。 这`get(value, 0)`调用简化了插入，因为它返回`0`对于看不见的值。 

我们处理`items1`首先将每个权重添加到地图上。 然后我们重复相同的逻辑`items2`。 由于两个数组都写入同一个字典，因此重复的值自然会通过加法合并。 

聚合完成后，我们将字典转换为所需的列表列表格式。 最后，我们使用以下方法进行排序：```python
key=lambda item: item[0]
```按值字段排序，满足问题要求。 

## 解决方案```go
func mergeSimilarItems(items1 [][]int, items2 [][]int) [][]int {
	weightMap := make(map[int]int)

	// Process items1
	for _, item := range items1 {
		value := item[0]
		weight := item[1]
		weightMap[value] += weight
	}

	// Process items2
	for _, item := range items2 {
		value := item[0]
		weight := item[1]
		weightMap[value] += weight
	}

	// Build result
	result := make([][]int, 0, len(weightMap))

	for value, totalWeight := range weightMap {
		result = append(result, []int{value, totalWeight})
	}

	// Sort by value
	sort.Slice(result, func(i, j int) bool {
		return result[i][0] < result[j][0]
	})

	return result
}
```Go 实现反映了 Python 方法，但有一些特定于语言的细节。 

Go 映射会自动返回缺失键的零值，因此：```go
weightMap[value] += weight
```无需显式存在检查即可工作。 

与 Python 不同，Go 不提供内置的列表排序以及切片切片的关键函数，因此我们使用：```go
sort.Slice()
```具有自定义比较功能。 

整数溢出在这里不是一个问题，因为最大可能的总权重相对于 Go 的整数限制仍然很小。

 ## 边缘情况

 ### 没有重叠值

 当两个数组包含完全不同的值时，就会出现一种重要的边缘情况。 幼稚的实现可能会错误地假设每个项目都有匹配项，并意外地跳过不匹配的条目。 

例如：```
items1 = [[1,2]]
items2 = [[3,4]]
```该实现可以正确处理这个问题，因为每个项目都是独立插入到哈希映射中的。 由于没有值重叠，因此不会发生添加，并且两个条目都保持不变。 

### 每个值都重叠

 另一个重要的情况是每个值都出现在两个数组中。 有缺陷的实现可能会意外地覆盖权重而不是对它们求和。 

例如：```
items1 = [[1,2],[2,3]]
items2 = [[1,5],[2,4]]
```字典更新逻辑：```
weight_map[value] = weight_map.get(value, 0) + weight
```确保权重被累加而不是被替换，从而产生正确的总数。 

### 已经未排序的输入

 不保证输入数组已排序。 幼稚的实现可能会意外地按插入顺序返回项目，这将违反问题要求。 

例如：```
items1 = [[5,1],[1,2]]
items2 = [[3,4]]
```即使以任意顺序遇到值，最终的排序步骤也保证输出始终按值的升序返回。 

### 输入大小高度不平衡

 一个数组可能只包含一项，而另一个数组可能包含多项。 某些实现可能会意外地假设平衡迭代。 

由于该解决方案独立处理每个阵列，因此无论大小差异如何，它都能正常工作。 每个项目只对哈希映射贡献一次，即使一个数组比另一个数组大得多，也能确保正确性。
