[LeetCode 问题 2307](https://leetcode.com/problems/check-for-contradictions-in-equations/)

 **难度：** 🔴难
 **主题：** 数组、深度优先搜索、并查找、图论

 ## 解决方案

 ## 问题理解

 这个问题给我们提供了以下形式的方程组：$$A_i / B_i = value_i$$每个变量都表示为一个字符串，每个方程定义两个变量之间的乘法关系。 

任务是确定所有方程是否可以同时成立。 如果至少一个方程与其他方程冲突，我们返回`true`因为存在矛盾。 否则，我们返回`false`。 

例如，如果我们知道：$$a / b = 2$$和$$b / c = 3$$那么逻辑上：$$a / c = 6$$如果另一个方程说：$$a / c = 5$$那么系统是不一致的，所以就存在矛盾。 

重要的观察是这些方程形成了比率图。 每个变量都可以通过乘法关系与其他变量连接。 每当两个变量已经连接时，它们的比率就已经由先前处理的方程暗示。 如果一个新方程与该隐含比率不一致，我们就发现了矛盾。 

约束相对较小，最多有 100 个方程，因此即使是图遍历方法也是可行的。 然而，我们仍然需要一个高效、干净的解决方案。 

有几个重要的边缘情况：

 - 变量可能在输入中的任何点首次出现。 
- 可能存在多个不相连的方程组。 
- 矛盾可能会立即发生，或者只有在许多方程链接在一起之后才会发生。 
- 浮点精度很重要，因此比较必须使用 epsilon 容差`1e-5`。 
- 方程可能间接暗示长变量链之间的比率。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将方程视为图形，并且对于每个新方程，运行 DFS 或 BFS 以查看两个变量之间是否已存在路径。 

如果路径存在，我们通过乘以沿路径的边权重来计算隐含比率。 然后我们将该隐含比率与新方程的值进行比较。 

如果它们的差异超过`1e-5`，我们发现了一个矛盾。 

如果不存在路径，我们只需将方程添加到图中即可。 

这种方法是正确的，因为图遍历探索了早期方程所隐含的所有乘法关系。 

然而，重复搜索图表中的每个方程是低效的。 和$n$方程中，每个 DFS 可能访问许多节点和边，导致二次复杂度。 

### 最优方法，加权并查

 关键的见解是，这个问题从根本上讲是关于维护变量之间的连接组件和相对比率。 

Union-Find 非常适合高效跟踪连接的组件。 加权并查找通过存储节点及其父节点之间的乘法权重来扩展这个想法。 

对于每个变量：

 -`parent[x]`存储代表父级。 
-`weight[x]`存储比率：$$x / parent[x]$$使用路径压缩，我们可以得出：$$x / root$$对于每个变量。 

处理方程时：$$a / b = value$$有两种情况：

 1.`a`和`b`属于不同的组件。 

我们合并组件，同时保留比例关系。 
2.`a`和`b`已经属于同一个组件。 

那么它们的比率已经由前面的方程隐含了。 我们计算隐含比率并将其与`value`。 

这种方法既优雅又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 每个方程的 DFS/BFS |
 | 最佳| O(n α(n)) | O(n α(n)) | O(n) | 具有路径压缩的加权并查找 |

 ## 算法演练

 1. 创建两个哈希图：

 -`parent[x]`存储变量的父级`x`-`weight[x]`存储比率：$$x / parent[x]$$1.当变量第一次出现时，初始化：

 -`parent[x] = x`-`weight[x] = 1.0`这意味着每个变量最初形成其自己的组件。 
2. 实施`find(x)`功能。 

该函数递归地寻找根`x`。 

在路径压缩期间，我们更新权重，以便压缩后：$$weight[x] = x / root$$这很重要，因为它可以让我们快速计算连接变量之间的比率。 

1. 处理各方程：$$a / b = value$$1. 寻找根源`a`和`b`。 

让：

-`rootA`是...的根`a`-`rootB`是...的根`b`2. 如果根相同，则它们之间的比率`a`和`b`是已知的。 

自从：$$a / root = weight[a]$$和$$b / root = weight[b]$$然后：$$a / b = weight[a] / weight[b]$$将计算出的比率与`value`。 

如果绝对差值超过`1e-5`， 返回`true`。 

1. 如果根不同，则合并组件。 

我们将一个根附加到另一个根下，同时保留方程关系。 

假设我们附加`rootA`在下面`rootB`。 

我们需要：$$a / b = value$$自从：$$a / rootA = weight[a]$$和$$b / rootB = weight[b]$$我们得出：$$rootA / rootB = \frac{value \cdot weight[b]}{weight[a]}$$将此比率存储在`weight[rootA]`。 

1. 如果所有方程都处理完毕且没有冲突，则返回`false`。 

### 为什么它有效

 并查结构在每个节点与其组件根之间保持一致的乘法关系。 

任何时刻：$$weight[x] = x / root(x)$$因此，对于任何连接变量：$$x / y = \frac{x/root}{y/root}$$当新方程连接已经相关的变量时，算法会检查隐含比率是否与提供的比率匹配。 如果不是，则方程不一致。 

由于路径压缩正确地保留了这些关系，因此所有比率计算在整个执行过程中都保持有效。 

## Python 解决方案```python
from typing import List

class Solution:
    def checkContradictions(self, equations: List[List[str]], values: List[float]) -> bool:
        parent = {}
        weight = {}

        def find(x: str) -> str:
            if parent[x] != x:
                original_parent = parent[x]
                root = find(original_parent)

                weight[x] *= weight[original_parent]
                parent[x] = root

            return parent[x]

        for (a, b), value in zip(equations, values):

            if a not in parent:
                parent[a] = a
                weight[a] = 1.0

            if b not in parent:
                parent[b] = b
                weight[b] = 1.0

            root_a = find(a)
            root_b = find(b)

            if root_a == root_b:
                implied = weight[a] / weight[b]

                if abs(implied - value) >= 1e-5:
                    return True
            else:
                parent[root_a] = root_b

                weight[root_a] = (
                    value * weight[b] / weight[a]
                )

        return False
```实现首先维护两个字典，`parent`和`weight`。 

这`find`函数执行路径压缩，同时更新乘法权重。 这是该解决方案中最重要的部分，因为它确保压缩后，每个节点直接存储其相对于根的比率。 

在方程处理过程中，新变量在第一次遇到时会被延迟初始化。 

如果两个变量已经属于同一连接分量，则该算法使用以下方法计算隐含比率：$$weight[a] / weight[b]$$并检查它是否在允许的容差范围内与提供的值匹配。 

如果变量属于不同的组件，则并集步骤会合并树，同时保留根之间的乘法关系。 

最后，如果处理完所有方程后没有发现矛盾，则函数返回`False`。 

## 解决方案```go
package main

import "math"

func checkContradictions(equations [][]string, values []float64) bool {
	parent := make(map[string]string)
	weight := make(map[string]float64)

	var find func(string) string

	find = func(x string) string {
		if parent[x] != x {
			originalParent := parent[x]
			root := find(originalParent)

			weight[x] *= weight[originalParent]
			parent[x] = root
		}

		return parent[x]
	}

	for i, eq := range equations {
		a := eq[0]
		b := eq[1]
		value := values[i]

		if _, exists := parent[a]; !exists {
			parent[a] = a
			weight[a] = 1.0
		}

		if _, exists := parent[b]; !exists {
			parent[b] = b
			weight[b] = 1.0
		}

		rootA := find(a)
		rootB := find(b)

		if rootA == rootB {
			implied := weight[a] / weight[b]

			if math.Abs(implied-value) >= 1e-5 {
				return true
			}
		} else {
			parent[rootA] = rootB

			weight[rootA] = value * weight[b] / weight[a]
		}
	}

	return false
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go requires explicit map initialization and existence checks using the two-value map lookup syntax.

 递归`find`函数是使用函数变量实现的，因此它可以递归地引用自身。 

浮点比较用途`math.Abs`。 

由于 Go 映射对于缺失键返回零值，因此在初始化之前显式存在检查非常重要。 

## 工作示例

 ### 示例 1

 输入：```
equations = [["a","b"],["b","c"],["a","c"]]
values = [3,0.5,1.5]
```初始状态：

 | 变量| 家长 | 重量 |
 | ---| ---| ---|
 | 无 | 无 | 无 |

 ＃＃＃ 加工`a / b = 3`初始化变量。 

| 变量| 家长 | 重量 |
 | ---| ---| ---|
 | 一个 | 一个 | 1 |
 | 乙| 乙| 1 |

 联盟`a`在下面`b`。$$weight[a] = 3 \times 1 / 1 = 3$$更新状态：

 | 变量| 家长 | 重量 |
 | ---| ---| ---|
 | 一个 | 乙| 3 |
 | 乙| 乙| 1 |

 这意味着：$$a / b = 3$$＃＃＃ 加工`b / c = 0.5`初始化`c`。 

| 变量| 家长 | 重量 |
 | ---| ---| ---|
 | c | c | 1 |

 联盟`b`在下面`c`。$$weight[b] = 0.5$$更新状态：

 | 变量| 家长 | 重量 |
 | ---| ---| ---|
 | 一个 | 乙| 3 |
 | 乙| c | 0.5 | 0.5
 | c | c | 1 |

 现在：$$a / c = 3 \times 0.5 = 1.5$$＃＃＃ 加工`a / c = 1.5`查找压缩路径：$$weight[a] = 1.5$$计算比率：$$a / c = weight[a] / weight[c] = 1.5 / 1 = 1.5$$符合预期值。 

不存在矛盾。 

返回`false`。 

### 示例 2

 输入：```
equations = [["le","et"],["le","code"],["code","et"]]
values = [2,5,0.5]
```＃＃＃ 加工`le / et = 2`联合组件。 

＃＃＃ 加工`le / code = 5`现在我们推导：$$code / et = 2/5 = 0.4$$＃＃＃ 加工`code / et = 0.5`两个变量已经属于同一个组件。 

计算比率：$$0.4$$预期比例：$$0.5$$差异超过`1e-5`。 

返回`true`。

 ## 边缘情况

 当两个变量以前从未见过时，就会出现一种重要的边缘情况。 有缺陷的实现可能会在初始化之前尝试访问父项或权重信息，从而导致错误或不正确的比率。 该解决方案通过在每个变量第一次出现时延迟初始化它来解决这个问题。 

另一个关键的边缘情况是已连接变量之间的重复方程。 例如：$$a / b = 2$$随后是：$$a / b = 3$$盲目合并集合的天真的并查找实现会错过矛盾。 只要两个变量已经共享相同的根，此实现就会显式检查隐含比率。 

浮点精度也是错误的常见来源。 乘以多个小数比可能会导致较小的数值误差。 因此，直接的相等比较是不可靠的。 该问题明确指示我们使用 epsilon 阈值进行比较`1e-5`，实施过程中要仔细遵循。 

最后一个重要的边缘情况涉及长传递链。 考虑：$$a / b = 2,\ b / c = 3,\ c / d = 4$$该算法必须正确推断：$$a / d = 24$$加权并查结构通过累积权重和路径压缩有效地维护这些关系。
