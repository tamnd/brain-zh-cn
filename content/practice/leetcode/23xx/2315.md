[LeetCode 第 2315 题](https://leetcode.com/problems/count-asterisks/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`包含小写英文字母、竖线`'|'`、和星号`'*'`。 关键规则是每两个连续的垂直条形成一对。 计数时必须忽略位于一对的两个条之间的任何星号。 

我们的任务是仅计算这些成对条形部分之外的星号。 

思考该问题的另一种方法是字符串在两种模式之间交替：

 - 在一对酒吧外面，`'*'`应该计算字符数
 - 在一对酒吧内，`'*'`应忽略字符

 每次我们遇到竖线`'|'`，我们在这两种模式之间切换。 

例如，考虑：```
l|*e*et|c**o|*de|
```子串`*e*et`位于第一对条形之间，因此其星号将被忽略。 子串`*de`位于第二对条形之间，因此它们也被忽略。 只有两个星号`c**o`被计算在内。 

限制很小：

 -`1 <= s.length <= 1000`- 字符串仅包含小写字母，`|`， 和`*`- 保证竖条的数量是偶数

 由于最大长度仅为 1000，因此效率较低的方法也可以工作。 然而，这个问题自然建议采用简单的线性扫描解决方案。 

一些重要的边缘情况包括：

 - 根本没有星号的字符串
 - 没有竖线的弦
 - 所有星号都在条对内的字符串
 - 所有星号都在小节对之外的字符串
 - 连续的小节对之间没有字符
 - 以小节开头或结尾的字符串

 保证条数为偶数很重要，因为它确保每个开盘部分都有匹配的收盘部分。 

## 方法

 ### 蛮力方法

 强力解决方案可以首先识别每对垂直条并记录所有应忽略的字符范围。 确定这些排除的区间后，我们可以再次迭代字符串并仅计算不在任何排除范围内的星号。 

一种可能的实现是：

 1. 存储所有的索引`'|'`人物。 
2. 将它们分成两人一组。 
3. Mark all indices inside those pairs as excluded.
 4. 遍历字符串并计算有效值`'*'`人物。 

这种方法是正确的，因为每个被忽略的区域在计数开始之前都被明确识别。 

然而，该方法过于复杂。 它还可能需要额外的空间来存储排除的范围或标记。 尽管约束足够小，这仍然可以通过，但是通过一次就可以更优雅地解决问题。 

### 最佳方法

 关键的观察是我们实际上不需要存储柱之间的范围。 我们只需要知道当前位置是在柱对内部还是外部。 

我们可以维护一个布尔标志：

 -`inside_bars = False`最初
 - 每次我们相遇`'|'`, 切换标志
 - 如果我们遇到`'*'`尽管`inside_bars`是`False`，增加答案

 这是有效的，因为条形图总是成对出现。 每个`'|'`翻转当前计数状态。 

该解决方案变成了具有恒定额外空间的简单线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 在计数之前存储柱位置或排除范围 |
 | 最佳| O(n) | O(1) | O(1) | 使用布尔状态的单遍 |

 ## 算法演练

 1.初始化一个计数器变量`asterisk_count`到`0`。 这将存储条对之外的有效星号的数量。 
2. 初始化布尔变量`inside_bars`到`False`。 该变量跟踪当前字符是否位于成对的小节内。 
3. 逐个字符地遍历字符串。 
4. 对于每个字符：

 - 如果角色是`'|'`，切换值`inside_bars`。 

- 如果我们在一对之外，我们现在进入一对。 
- 如果我们在一对内，我们现在退出该对。 
- 否则如果角色是`'*'`和`inside_bars`是`False`, 增量`asterisk_count`。 
- 所有小写字母都可以被忽略，因为它们不会影响答案。 
5.处理完整个字符串后，返回`asterisk_count`。 

### 为什么它有效

 该算法保持不变式`inside_bars`正确表示当前位置是否位于一对匹配的垂直条之间。 

由于每`'|'`恰好属于一对，切换每个条形的状态可以正确跟踪当前是否应忽略或计算星号。 因此，每个计数的星号都在所有条形对之外，而每个被忽略的星号都在条形对内部。 

## Python 解决方案```python
class Solution:
    def countAsterisks(self, s: str) -> int:
        asterisk_count = 0
        inside_bars = False

        for char in s:
            if char == '|':
                inside_bars = not inside_bars
            elif char == '*' and not inside_bars:
                asterisk_count += 1

        return asterisk_count
```实现直接遵循前面描述的算法。 

变量`asterisk_count`存储最终答案。 布尔值`inside_bars`跟踪当前扫描位置是否位于一对匹配的垂直条之间。 

当我们遍历字符串时：

 - 相遇`'|'`翻转状态
 - 相遇`'*'`仅当我们当前位于柱对之外时才增加答案
 - 字母被忽略，因为它们不影响计数

 实现很简洁，因为问题自然地映射到单次遍历期间的状态跟踪。 

## 解决方案```go
func countAsterisks(s string) int {
    asteriskCount := 0
    insideBars := false

    for _, char := range s {
        if char == '|' {
            insideBars = !insideBars
        } else if char == '*' && !insideBars {
            asteriskCount++
        }
    }

    return asteriskCount
}
```Go 实现与 Python 版本几乎相同。 

特定于语言的一个细微差别是 Go 使用以下方式迭代字符串`range`，它返回符文。 由于此问题中的所有字符都是 ASCII，因此符文处理不会带来任何复杂性。 

不需要对 nil 或空输入进行特殊处理，因为约束保证至少有一个字符。

 ## 边缘情况

 一个重要的边缘情况是根本没有竖线的字符串，例如`"***"`或者`"abc"`。 假设条形始终存在的幼稚实现可能会失败或使逻辑不必要地复杂化。 当前的实现可以自然地处理这个问题，因为`inside_bars`遗迹`False`对于整个遍历，因此所有星号都被正确计数。 

另一个重要的边缘情况是当所有星号都在一对条形内时，例如`"|***|"`。 如果状态转换逻辑不正确，很容易意外计数这些。 在第一个之后，实现正确地切换到忽略模式`'|'`第二次后退出`'|'`，确保跳过所有内部星号。 

第三个重要的边缘情况是相邻或空的条对，例如`"||***"`或者`"|*||*|"`。 这些情况可能会暴露实现中的错误，错误地假设条之间必须有字符。 由于只要出现条形，该算法就会简单地切换状态，因此可以正确处理空部分，而不需要任何特殊逻辑。 

最后一种边缘情况是以小节开头或结尾的字符串。 例如，`"|abc|"`或者`"*|abc|"`。 不正确的实现可能会意外地计算最后一个小节后的字符或错误地处理初始转换。 布尔状态方法可以干净地处理这两种情况，因为每个条形始终翻转当前模式。*
