[LeetCode 问题 2388](https://leetcode.com/problems/change-null-values-in-a-table-to-the-previous-value/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们处理一个数据库表，`CoffeeShop`，其中包含两列：`id`和`drink`。 每行代表一份饮品订单。 一些`drink`值可能是`NULL`。 任务是替换每一个`NULL`在`drink`列有最新的非`NULL`来自前一行的值，保留由给定的行的顺序`id`表中的顺序。 

换句话说，我们正在对`drink`列，类似于在时间序列数据中经常执行的填充缺失值的操作。 该问题保证第一行总是有一个非`NULL`值，所以我们永远不必处理`NULL`没有先前的值可供参考。 

预期输出是同一张表，所有`NULL`值被最近的先前非值替换`NULL`喝，保持原来的行序不变。 

关键的约束和考虑因素是表可以具有任意顺序`id`s，因此需要简单的顺序扫描，并且我们必须处理连续的`NULL`正确。 

重要的边缘情况包括连续的`NULL`是，最后一行是`NULL`和最小表格（一行或两行）。 保证第一行不是`NULL`简化了我们的处理。 

## 方法

 蛮力方法将迭代每一行，并且对于每个`NULL`遇到，执行另一次向后扫描以找到最近的先前非`NULL`喝。 这种方法是正确的，因为它确保了每一个`NULL`被替换为前一个值，但是效率很低，因为它可能需要扫描几乎整个表来查找每个`NULL`，导致最坏情况下的时间复杂度为 O(n²)。 

最佳方法利用前向传递，使用一个简单的变量来跟踪最后一个非`NULL`喝遇到的。 当我们按顺序迭代行时，如果一行的饮料不是`NULL`，我们更新这个变量。 如果是的话`NULL`，我们立即将其替换为存储的最后一个非`NULL`喝。 这避免了重复的向后扫描，并且在恒定额外空间的情况下将时间复杂度降低到 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 对于每个 NULL，向后扫描以查找先前的值 |
 | 最佳 | O(n) | O(1) | O(1) | 正向扫描存储最后一个非 NULL 值 |

 ## 算法演练

 1. 初始化变量`last_drink`到`NULL`。 该变量将跟踪最近的非`NULL`我们一边扫描一边喝水。 
2. 迭代每一行`CoffeeShop`表按出现顺序排列（id 顺序保留在输入中）。 
3. 对于每一行，检查是否`drink`值为`NULL`。 
4. 如果`drink`不是`NULL`， 更新`last_drink`到这个值。 
5. 如果`drink`是`NULL`，将其替换为存储在中的值`last_drink`。 
6. 继续，直到处理完所有行。 
7. 返回修改后的表，保留原始顺序。 

为什么它有效：前向扫描不变量确保在每一步，`last_drink`包含最新的非`NULL`迄今为止看到的价值。 这保证了每个`NULL`被替换为正确的先前值，而不需要任何向后扫描。 

## Python 解决方案```python
import pandas as pd

def change_nulls(coffee_shop: pd.DataFrame) -> pd.DataFrame:
    last_drink = None
    drinks = coffee_shop['drink'].tolist()
    for i in range(len(drinks)):
        if drinks[i] is not None:
            last_drink = drinks[i]
        else:
            drinks[i] = last_drink
    coffee_shop['drink'] = drinks
    return coffee_shop
```在这个实现中，我们首先将`drink`列到列表以允许就地修改。 我们迭代列表，更新`last_drink`每当我们遇到非`NULL`价值。 当一个`NULL`一经发现，立即更换。 最后，我们更新 DataFrame 列并返回结果。 

## 解决方案```go
package main

type CoffeeShop struct {
    Id    int
    Drink *string
}

func changeNulls(coffeeShop []CoffeeShop) []CoffeeShop {
    var lastDrink string
    for i := 0; i < len(coffeeShop); i++ {
        if coffeeShop[i].Drink != nil {
            lastDrink = *coffeeShop[i].Drink
        } else {
            coffeeShop[i].Drink = &lastDrink
        }
    }
    return coffeeShop
}
```在 Go 中，我们使用切片`CoffeeShop`结构。 这`Drink`字段是一个指向`string`容纳`NULL`价值观。 当我们迭代时，我们更新`lastDrink`当非变量`nil`遇到值并替换`nil`带有引用的指针`lastDrink`为了`NULL`条目。

## 测试用例```python
import pandas as pd

# Basic provided example
df = pd.DataFrame({
    'id': [9,6,7,3,1,2],
    'drink': ['Rum and Coke', None, None, 'St Germain Spritz', 'Orange Margarita', None]
})
result = change_nulls(df)
assert result['drink'].tolist() == ['Rum and Coke', 'Rum and Coke', 'Rum and Coke', 'St Germain Spritz', 'Orange Margarita', 'Orange Margarita']

# Single row
df = pd.DataFrame({'id':[1], 'drink':['Latte']})
result = change_nulls(df)
assert result['drink'].tolist() == ['Latte']

# All drinks non-null
df = pd.DataFrame({'id':[1,2,3], 'drink':['Espresso','Cappuccino','Mocha']})
result = change_nulls(df)

# Consecutive nulls after first

 ## 边缘情况

 一个边缘情况是当第一行非`NULL`但所有后续行都是`NULL`。 我们的算法通过不断填充来处理这个问题`last_drink`，产生正确的输出。 

另一种边缘情况是只有一行的表。 这是有效的，因为第一行保证非`NULL`。 该算法将使该行保持不变，这是正确的。 

第三种边缘情况涉及交替`NULL`和非`NULL`价值观。 算法正确更新`last_drink`每当一个非`NULL`出现，确保所有`NULL`之间的 s 被替换为适当的前面的值。 这可以防止幼稚的实现每次向后扫描可能错过的错误。
