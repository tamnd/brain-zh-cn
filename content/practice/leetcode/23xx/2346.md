[LeetCode 问题 2346](https://leetcode.com/problems/compute-the-rank-as-a-percentage/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题提供了一个名为`Students`，其中每行代表一个学生并包含三个字段：

 -`student_id`，学生的唯一标识符
 -`department_id`, 学生所属院系
 -`mark`, 学生的考试成绩

 目标是计算每个学生在其部门内的排名百分比。 

排名基于降序分数。 分数较高的学生会获得更好的排名，这意味着排名`1`对应最高分。 如果多个学生的分数相同，则他们享有相同的排名。 此行为符合 SQL`RANK()`窗函数，不是`DENSE_RANK()`。 

确定排名后，我们使用以下公式计算百分比：$\frac{(\text{rank}-1)\times100}{(\text{department\_size}-1)}$结果必须四舍五入到小数点后两位。 

输出应包含：

 -`student_id`-`department_id`-`percentage`行的顺序并不重要。 

一个非常重要的细节是分母是`(department_size - 1)`。 这意味着我们将学生相对于系里其他学生的位置进行比较。 最好的学生总是会得到`0.0`，最差的学生得到`100.0`。 

该问题保证学生属于院系并且分数为整数。 由于允许出现平局，多个学生可以获得相同的百分比。 

一种极端情况是某个系的所有学生得分相同。 在这种情况下，他们都会获得排名`1`，所以每个百分比都变成`0.0`。 

另一个重要的边缘情况是只包含一名学生的部门。 该公式将除以零，因为`(1 - 1) = 0`。 在实践中，SQL 解决方案使用条件逻辑仔细处理这个问题，例如`CASE WHEN count = 1 THEN 0`。 

## 方法

 ### 蛮力方法

 蛮力法将每个学生与同一系内的其他学生进行比较。 

对于每个学生：

 1. 查找同一系的所有学生。 
2. 计算有多少学生获得严格较高的分数。 
3. 等级变为：```
higher_scores + 1
```4. 统计该系的学生总数。 
5. 应用百分比公式。 

这种方法是正确的，因为排名完全是由部门内的相对顺序定义的。 通过直接计算较高的分数，我们重现了准确的排名定义。 

然而，这种方法效率低下，因为每个学生都可能扫描该系中的所有其他学生。 如果有`n`学生们，复杂性变成了二次方。 

### 最佳方法

 关键的观察结果是 SQL 窗口函数已经提供了有效的排序和分区功能。 

我们可以使用：

 -`RANK() OVER (PARTITION BY department_id ORDER BY mark DESC)`-`COUNT(*) OVER (PARTITION BY department_id)`这`RANK()`函数自动正确处理关系。 分数相同的学生获得相同的排名，随后对跳过的数字进行适当的排名。 

这`COUNT()`窗口函数给出该系的学生总数，无需单独的连接或子查询。 

一旦这两个值可用，我们只需计算百分比公式并对结果进行四舍五入即可。 

这种方法高效、简洁，并且直接映射到问题定义。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 将每个学生与系里的其他学生进行比较 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用 SQL 窗口函数进行排名和部门计数 |

 ## 算法演练

 1. 对学生进行划分`department_id`。 

这确保了每个部门的排名都是独立计算的。 不同院系的学生不应该影响彼此的排名。 
2. 对每个院系内的学生进行排序`mark`按降序排列。 

分数越高，排名越高，因此需要降序排列。 
3. 使用以下方法计算排名`RANK()`。 

分数相同的学生获得相同的排名。 如果两个学生排名并列`1`，下一个学生获得排名`3`。 
4. 计算每个部门的学生总数`COUNT(*)`。 

该值是百分比公式的分母所必需的。 
5. 处理单个学生部门的边缘情况。 

如果一个部门只有一名学生，`(count - 1)`变为零。 在这种情况下，百分比应该是`0.0`。 
6. 应用百分比公式。 

计算：$\frac{(rank-1)\times100}{(count-1)}$7. 将结果四舍五入到小数点后两位。 
SQL`ROUND()`函数确保所需的格式。 

### 为什么它有效

 该算法之所以有效，是因为`RANK()`与问题的排名定义完全匹配。 按部门划分可确保排名独立，按分数降序排序可确保分数越高，排名越小。 百分比公式直接将排名位置映射到之间的标准化范围`0`和`100`。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT
    student_id,
    department_id,
    ROUND(
        CASE
            WHEN department_count = 1 THEN 0
            ELSE (student_rank - 1) * 100.0 / (department_count - 1)
        END,
        2
    ) AS percentage
FROM (
    SELECT
        student_id,
        department_id,
        RANK() OVER (
            PARTITION BY department_id
            ORDER BY mark DESC
        ) AS student_rank,
        COUNT(*) OVER (
            PARTITION BY department_id
        ) AS department_count
    FROM Students
) ranked_students;
```该解决方案首先创建一个名为的派生表`ranked_students`。 

在这个子查询中：

 -`RANK()`计算学生在其部门内的职位。 
-`COUNT(*)`计算该系的学生总数。 

外部查询应用百分比公式。 

这`CASE`语句可防止仅包含一名学生的院系被零除。 

最后，`ROUND(..., 2)`完全按照要求将结果格式化为小数点后两位。

 ## 边缘情况

 ### 只有一名学生的部门

 包含单个学生的院系是最重要的边缘情况，因为分母变为零：$count-1=0$如果没有特殊处理，查询将引发除零错误。 该实现使用以下方法来防止这种情况发生`CASE`直接返回的语句`0`。 

### 多名学生获得相同的最高分

 当多名学生并列最高分时，他们都必须获得排名`1`。 这意味着每个并列的学生都应该获得百分比`0.0`。 

一个常见的错误是使用`ROW_NUMBER()`而不是`RANK()`。`ROW_NUMBER()`会错误地将不同的排名分配给并列的学生。 使用`RANK()`确保行为与问题陈述完全匹配。 

### 跳过排名数字的领带

 假设标记为：

 | 标记|
 | ---|
 | 100 | 100
 | 90 | 90
 | 90 | 90
 | 80|

 排名变为：

 | 标记| 等级 |
 | ---| ---|
 | 100 | 100 1 |
 | 90 | 90 2 |
 | 90 | 90 2 |
 | 80| 4 |

 通知等级`3`被跳过。 这是正确的行为`RANK()`。 解决方案使用`DENSE_RANK()`会错误地分配最后一个学生排名`3`，产生错误的百分比。
