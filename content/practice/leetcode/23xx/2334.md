[LeetCode 问题 2334](https://leetcode.com/problems/subarray-with-elements-greater-than-variing-threshold/)

 **难度：** 🔴难
 **主题：** 数组、堆栈、并查、单调堆栈

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到一个连续的子数组，其元素相对于子数组长度都足够大。 

更具体地说，对于长度为的子数组`k`，该子数组中的每个元素都必须满足：$$\text{element} > \frac{\text{threshold}}{k}$$我们可以退回尺寸`k`任何有效的子数组。 If no such subarray exists, we return`-1`。 

重要的细节是条件适用于子数组中的每个元素。 这意味着子数组中的最小元素决定整个子数组是否有效。 如果子数组中的最小值是`m`，则条件变为：$$m > \frac{\text{threshold}}{k}$$重新排列可以得出：$$m \times k > \text{threshold}$$或等价地：$$k > \frac{\text{threshold}}{m}$$这一观察结果是最优解决方案的关键。 

输入约束很大：

 -`nums.length`可以达到`10^5`-`nums[i]`和`threshold`可以达到`10^9`这些限制立即排除了昂贵的方法，例如检查所有子数组。 一个`O(n^2)`对于大小的数组，解决方案会超时`100000`。 

一些边缘情况很重要：

 - 不存在有效子数组的数组
 - 单个元素已满足条件的数组
 - 具有重复值的数组
 - 严格递增或严格递减数组
 - 有效子数组几乎跨越整个数组的情况
 - 最小元素出现多次的情况

 该问题保证数组非空并且所有值都是正整数，这简化了一些推理，因为我们从不处理零或负值。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查每个可能的子数组。 

对于每个起始索引，我们一次扩展子数组一个元素，同时跟踪当前窗口内的最小值。 对于每个子数组长度`k`，我们检查是否：$$\text{minimum} > \frac{\text{threshold}}{k}$$如果为真，我们返回`k`。 

这种方法是正确的，因为它显式检查每个可能的子数组。 然而，有`O(n^2)`子数组，即使使用有效的最小跟踪，总运行时间也会变得太大`n = 100000`。 

### 关键见解

 关键的观察是每个元素都可以充当某个最大子数组的最小值。 

认为`nums[i] = x`。 

如果我们可以确定每个值至少为的最大连续范围`x`，然后在该范围内，`x`是最小元素。 如果范围长度是`k`，则子数组有效，如果：$$x > \frac{\text{threshold}}{k}$$因此，我们不是检查所有子数组，而是处理每个元素一次并确定：

 - 在遇到较小的元素之前它可以向左延伸多远
 - 在遇到较小的元素之前它可以向右延伸多远

 这正是经典的“直方图中最大矩形”模式，可以使用单调递增堆栈有效地解决该问题。 

对于每个索引：

 - 找到前一个较小的元素
 - 找到下一个较小的元素
 - 计算有效范围的宽度
 - 检查元素是否满足该宽度的阈值条件

 这将运行时间减少到线性时间。

 ## 算法演练

 ### 最优单调堆栈算法

 1. 创建一个空的单调递增堆栈。 

堆栈将以值的递增顺序存储元素的索引。 这使我们能够有效地确定每个位置的前一个较小元素和下一个较小元素。 
2. 从左到右迭代数组。 

我们将每个元素处理为某个子数组的候选最小值。 
3. 当当前值小于栈顶值时，从栈中弹出。 

当一个元素被弹出时，我们发现了它的下一个更小的元素。 当前索引充当该弹出元素的右边界。 
4. 计算弹出元素的最大宽度。 

假设索引`mid`被弹出。 

- 当前指数`i`是右边第一个较小的元素
 - 新的栈顶是左边前一个较小的元素
 - 因此最大有效宽度为：$$\text{width} = i - \text{leftBoundary} - 1$$5. 检查弹出的元素是否满足条件。 

如果：$$nums[mid] > \frac{threshold}{width}$$然后返回`width`。 
6. 将当前索引压入堆栈。 

这保持了单调递增的性质。 
7. 完成数组后，继续弹出剩余元素。 

对于这些元素，右边界变为`n`。 
8. 如果没有找到有效的子数组，则返回`-1`。 

### 为什么它有效

 对于每个元素，该算法计算该元素为最小值的最大连续区域。 该区域内任何较小的子数组只会减少长度并使条件更难满足。 因此，检查每个元素的最大可能宽度就足够了。 

单调堆栈保证我们在线性时间内正确识别两侧最近的较小元素。 

## Python 解决方案```python
from typing import List

class Solution:
    def validSubarraySize(self, nums: List[int], threshold: int) -> int:
        n = len(nums)
        stack = []

        for i in range(n + 1):
            current = nums[i] if i < n else 0

            while stack and nums[stack[-1]] > current:
                mid = stack.pop()

                left_smaller = stack[-1] if stack else -1
                width = i - left_smaller - 1

                if nums[mid] > threshold / width:
                    return width

            stack.append(i)

        return -1
```该实现使用单调递增的索引堆栈。 

循环运行自`0`通过`n`。 额外的迭代在`n`使用哨兵值`0`，这会强制弹出并处理所有剩余元素。 

每当我们从堆栈中弹出一个索引时，我们立即知道：

 - 它的下一个较小的元素是当前索引
 - 其先前较小的元素是新的堆栈顶部

 使用这两个边界，我们计算弹出元素最小的最大子数组。 

然后我们测试这个宽度是否满足阈值条件。 如果是，我们立即返回，因为该问题允许返回任何有效大小。 

如果处理完所有元素后不存在有效的子数组，我们返回`-1`。 

## 解决方案```go
func validSubarraySize(nums []int, threshold int) int {
	n := len(nums)
	stack := []int{}

	for i := 0; i <= n; i++ {
		current := 0
		if i < n {
			current = nums[i]
		}

		for len(stack) > 0 && nums[stack[len(stack)-1]] > current {
			mid := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			leftSmaller := -1
			if len(stack) > 0 {
				leftSmaller = stack[len(stack)-1]
			}

			width := i - leftSmaller - 1

			if nums[mid] > threshold/width {
				return width
			}
		}

		stack = append(stack, i)
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的逻辑。 

切片用作堆栈。 哨兵迭代是通过分配来处理的`current = 0`什么时候`i == n`。 

Go 中的整数除法会自动截断，这与预期的比较相匹配。 由于所有值都符合 LeetCode 约束的标准整数范围，因此不会出现溢出问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个索引最多被压入和弹出一次 |
 | 空间| O(n) | 最坏情况下堆栈可能保存所有索引 |

 该算法是线性的，因为每个元素最多参与一次入栈操作和一次出栈操作。 即使存在内部 while 循环，整个算法的堆栈操作总数也受以下限制：`2n`。 

空间复杂度是线性的，因为当数组严格递增时，堆栈可能包含所有索引。

 ## 边缘情况

 一种重要的边缘情况是不存在有效的子数组。 例如，`nums = [1,1,1]`和`threshold = 100`。 幼稚的实现可能会由于整数除法错误或不正确的比较而意外返回宽度。 单调堆栈解决方案正确检查每个候选宽度并最终返回`-1`。 

另一个重要的情况是单元素有效子数组。 例如，`nums = [8]`和`threshold = 7`。 由于子数组长度为`1`，条件变为`8 > 7`。 该算法自然会处理这个问题，因为宽度为`1`当元素从堆栈中弹出时计算。 

重复值也很棘手。 考虑`nums = [5,5,5,5]`。 对单调堆栈内的相等性处理不正确可能会产生错误的边界。 此实现在弹出期间使用严格的更大比较，这可以正确保留相等的值并准确计算最大宽度。 

严格增加数组形成了另一个微妙的场景。 在此类数组中，元素保留在堆栈上，直到哨兵迭代结束。 如果没有额外的哨兵通道，许多候选子数组将永远不会被评估。 该实现通过使用合成值迭代一个额外步骤来解决这个问题`0`。 

最后，在某些语言中，非常大的整数值可能会暴露溢出错误。 该实现避免了乘法，例如`nums[mid] * width`，这可能在其他环境中溢出。 相反，它使用除法进行比较：$$nums[mid] > threshold / width$$这在问题限制内仍然是安全的。
