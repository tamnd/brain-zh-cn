[LeetCode 问题 2391](https://leetcode.com/problems/minimum-amount-of-time-to-collect-garbage/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、前缀和

 ## 解决方案

 ## 问题理解

 此问题模拟了具有三辆独立垃圾车的垃圾收集系统：

 - 一辆卡车收集金属垃圾，代表为`'M'`- 一辆卡车收集纸质垃圾，代表为`'P'`- 一辆卡车收集玻璃垃圾，代表为`'G'`输入数组`garbage`描述每所房子里的垃圾。 例如，如果`garbage[i] = "GMP"`，然后是房子`i`包含玻璃、金属和纸质垃圾各一单位。 

每个单位的垃圾恰好需要`1`分钟收集。 

这`travel`数组描述了相邻房屋之间的旅行时间。 具体来说：

-`travel[i]`是离开家所需的时间`i`到房子`i + 1`所有三辆卡车都从家里出发`0`。 卡车只需行驶到最后一个装有其垃圾类型的房屋即可。 例如，如果房子后没有纸质垃圾`4`，那么纸车永远不需要超出房子`4`。 

一个重要的细节是，在任何给定时刻只有一辆卡车可以运行。 然而，这种限制实际上并不会使计算复杂化，因为卡车在时间上永远不会重叠。 总的答案就是以下各项的总和：

 - 所有垃圾收集时间
 - 每辆卡车的所有必要的行驶时间

 限制条件很大：

 - 最多`10^5`房屋
 - 每个房子的字符串长度最多为`10`这告诉我们解决方案必须接近线性时间。 任何二次模拟都会太慢。 

一些边缘情况很重要：

 - 垃圾类型可能根本不会出现
 - 垃圾类型可能只出现在家里`0`，意味着不需要旅行
 - 多种垃圾类型可能共用同一房屋
 - 反复求和时，行程时间可能会变长

 该问题保证了有效的输入大小和有效的垃圾字符，因此我们不需要防御性验证逻辑。 

## 方法

 ### 蛮力方法

 一种简单的方法是独立处理每种垃圾类型。 

对于每辆卡车：

 1. 扫描所有房屋以找到包含该垃圾类型的每个位置
 2. 对于每个相关房屋：

 - 添加接送时间
 - 重新计算从家出发的旅行时间`0`到那所房子

 例如，如果玻璃车需要上门拜访`5`，我们可以总结：```
travel[0] + travel[1] + ... + travel[4]
```每次我们遇到玻璃屋。 

这种方法是正确的，因为每辆卡车都独立贡献其取货和运输成本。 然而，反复重新计算旅行前缀效率很低。 

如果有`n`房屋，反复总结旅行距离可能会导致`O(n^2)`最坏情况下的复杂性。 

和`n = 10^5`，这太慢了。 

### 最佳方法

 关键的观察是每辆卡车只需要行驶到最后一个包含其垃圾类型的房子。 

例如：

 - 如果最后一个金属垃圾在家里`7`，金属卡车只需要从家出发的行驶时间`0`到房子`7`- 有多少中间房屋含有金属垃圾并不重要，因为卡车自然会经过它们

 这导致了两个重要的优化：

 1. 直接计算所有垃圾单位，因为每个单位的成本都是准确的`1`分钟
 2. 预先计算旅行时间的前缀总和，以便我们可以立即确定前往任何房屋的旅行成本

 使用前缀和：```sql
prefix[i] = total travel time from house 0 to house i
```然后：

 - 回家的路费`i`变成`prefix[i]`- 我们只为每个垃圾类型添加一次，使用最后一次出现的情况

 这将整个解决方案缩短为线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复重新计算行驶距离 |
 | 最佳 | O(n) | O(n) | 使用前缀和并跟踪最后一次出现的情况 |

 ## 算法演练

 1. 初始化变量`total_time`存储最终答案。 
2. 通过迭代每个房屋字符串并将其长度添加到来计算所有垃圾收集时间`total_time`。 

这是有效的，因为每个垃圾字符代表一个需要一分钟来收集的单元。 
3. 构建行程时间的前缀和数组。 

让：```sql
prefix[i] = total travel time from house 0 to house i
```自从房子`0`无需出差：```
prefix[0] = 0
```然后：```
prefix[i] = prefix[i - 1] + travel[i - 1]
```4. 跟踪每种垃圾类型的最后一次出现。 

创建变量：```
last_m
last_p
last_g
```将它们初始化为`0`。 
5. 扫描每栋房子。 

对于每栋房子：

 - 如果`'M'`出现，更新`last_m`- 如果`'P'`出现，更新`last_p`- 如果`'G'`出现，更新`last_g`扫描后，每个变量存储卡车必须访问的最远房屋。 
6. 添加必要的差旅费用。 

自从`prefix[i]`代表从家出发的旅行费用`0`到房子`i`:```
total_time += prefix[last_m]
total_time += prefix[last_p]
total_time += prefix[last_g]
```7. 返回`total_time`。 

### 为什么它有效

 该算法之所以有效，是因为每辆卡车只需要行驶到包含其垃圾类型的最远的房子。 早期房屋中的任何垃圾都会沿途自动收集。 

拾取时间就是垃圾单元的总数，因为每个单元总是花费一分钟。 

前缀和数组保证在恒定时间内正确有效地计算到任何房屋的旅行时间。 

这些属性共同确保算法计算出准确的最小总时间。 

## Python 解决方案```python
from typing import List

class Solution:
    def garbageCollection(self, garbage: List[str], travel: List[int]) -> int:
        n = len(garbage)

        # Total pickup time
        total_time = sum(len(house) for house in garbage)

        # Prefix travel times
        prefix = [0] * n

        for i in range(1, n):
            prefix[i] = prefix[i - 1] + travel[i - 1]

        # Last occurrence of each garbage type
        last_m = 0
        last_p = 0
        last_g = 0

        for i, house in enumerate(garbage):
            if 'M' in house:
                last_m = i

            if 'P' in house:
                last_p = i

            if 'G' in house:
                last_g = i

        # Add travel costs
        total_time += prefix[last_m]
        total_time += prefix[last_p]
        total_time += prefix[last_g]

        return total_time
```实现直接遵循算法。 

首先，代码使用以下方法计算接送时间：```python
sum(len(house) for house in garbage)
```这会将每个垃圾单元精确计数一次。 

接下来，构造前缀和数组。 值在`prefix[i]`存储到达家所需的总行程时间`i`从家里`0`。 

然后，该算法扫描所有房屋并记录每种垃圾类型最后出现的位置。 会员资格检查，例如：```python
'M' in house
```工作效率很高，因为每个房子的字符串长度最多为`10`。 

最后，使用前缀和将三辆卡车的行驶成本相加。 

该解决方案以线性时间运行并轻松满足问题约束。 

## 解决方案```go
func garbageCollection(garbage []string, travel []int) int {
	n := len(garbage)

	// Total pickup time
	totalTime := 0
	for _, house := range garbage {
		totalTime += len(house)
	}

	// Prefix travel times
	prefix := make([]int, n)

	for i := 1; i < n; i++ {
		prefix[i] = prefix[i-1] + travel[i-1]
	}

	// Last occurrence of each garbage type
	lastM, lastP, lastG := 0, 0, 0

	for i, house := range garbage {
		for _, ch := range house {
			if ch == 'M' {
				lastM = i
			} else if ch == 'P' {
				lastP = i
			} else if ch == 'G' {
				lastG = i
			}
		}
	}

	// Add travel costs
	totalTime += prefix[lastM]
	totalTime += prefix[lastP]
	totalTime += prefix[lastG]

	return totalTime
}
```Go 的实现与 Python 解决方案非常相似。 

Go 版本没有像 Python 那样使用子字符串成员资格检查，而是使用`for range`环形。 

所有计算都安全地适合 Go 的内部`int`输入，因为最大可能的答案完全在整数限制内。 

切片自然地用于`travel`数组和前缀和数组。

 ## 边缘情况

 当垃圾类型根本不出现时，就会出现一种重要的边缘情况。 例如，城市中的任何地方可能都没有金属垃圾。 有缺陷的实施仍可能会不必要地增加金属卡车的行驶时间。 这个解决方案自然地避免了这个问题，因为最后一次发生的事情仍然在家里`0`， 和`prefix[0]`等于`0`。 

另一个重要的情况是当所有垃圾只存在于家里时`0`。 在这种情况下，任何卡车都不应行驶。 该实现可以正确处理此问题，因为所有最后出现的索引都保留`0`，因此不增加差旅费用。 

第三个重要的边缘情况是稀疏的垃圾放置。 例如，家里可能会出现金属垃圾`1`, 家里的纸`50`，还有家里的玻璃`99`。 幼稚的实现可能会重复地重新计算行进路径或意外地重复计算距离。 前缀和结构确保每个所需的行进距离在恒定时间内精确计算一次。 

最后一个微妙的边缘情况涉及空的房子弦乐。 有些房子可能根本没有垃圾。 该算法仍然可以正确处理它们，因为空字符串贡献零拾取时间并且不影响最后出现的跟踪。
