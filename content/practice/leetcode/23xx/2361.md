[LeetCode 问题 2361](https://leetcode.com/problems/minimum-costs-using-the-train-line/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 此问题模拟了一个场景，您正在穿越一条有两条平行路线的火车线路：常规路线和快速路线。 每条路线都有一系列连续的站点，从一个站点移动到下一站点的成本在数组中提供`regular`和`express`。 你总是在停止时开始`0`在常规路线上，您的目标是计算**到达每个站点**的最低成本**`0`，考虑两条路线以及从常规路线转乘快速路线的成本（`expressCost`）。 

关键细节是：

 -`regular[i]`和`express[i]`描述**从车站出发的成本`i-1`停止`i`**。 在该问题中，两个数组在概念上都是 1 索引的。 
- 从快速路线转回常规路线不需要任何费用。 
- 从普通转为特快需要付费`expressCost`。 
- 你的输出应该是一个 1 索引数组`costs`在哪里`costs[i]`是到达停靠点的最低成本`i`。 

限制条件：

 -`1 <= n <= 10^5`表明简单的递归解决方案会太慢； 需要一种有效的方法。 
- 成本是正整数，因此成本累积中不存在负循环或未定义的行为。 

重要的边缘情况：

 -`n = 1`，最小输入大小。 
- 所有成本均等，这测试了转账处理的正确性。 
-`expressCost`非常大，因此切换路线可能永远不是最佳的。 
-`expressCost`非常小，使得频繁的路由切换成为最佳选择。 

## 方法

 ### 蛮力

 暴力方法会尝试考虑所有可能的移动序列，计算每条路径长度的总成本`n`。 在每个站点，您会考虑继续沿同一条路线行驶，或者在允许的情况下切换路线。 虽然这会产生正确的最小成本，但可能的路线序列的数量呈指数增长（`O(2^n)`），这对于`n`最多 10^5。 

### 最佳方法

 关键的见解是**到达终点站的成本`i`仅取决于到达停靠点的最低成本`i-1`在任一路线上**。 这允许**动态编程**解决方案：

 - 维持两项运行成本：`cost_reg`和`cost_exp`表示在常规路线和快速路线上到达当前站点的最低成本。 
- 对于每个站点，更新：

 -`new_cost_reg = min(cost_reg + regular[i], cost_exp + regular[i])`因为你可以到达车站`i`乘坐常规路线，可以从上一个常规站点出发，也可以从快车换乘（换回无需付费）。 
-`new_cost_exp = min(cost_exp + express[i], cost_reg + express[i] + expressCost)`因为到达快车路线可以从前一个快车站过来或者通过付费`expressCost`从常规站点出发。 
- 计算停止后`i`，存储**最小值`new_cost_reg`和`new_cost_exp`** 在结果数组中。 

这是高效的，因为每个停靠点都会在`O(1)`时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 考虑路线选择的所有顺序 |
 | 最佳 | O(n) | O(n) | 动态规划，仅跟踪每次停靠的成本 |

 ## 算法演练

 1.初始化两个变量`cost_reg`和`cost_exp`跟踪到达站点的最低成本`0`。 最初，`cost_reg = 0`（从这里开始）和`cost_exp = infinity`（我们不能在不付款的情况下开始快递`expressCost`）。 
2. 创建结果数组`costs`长度`n`。 
3. 迭代自`i = 0`到`n-1`：

 1. 计算到达终点的最低成本`i+1`在常规路线上`new_cost_reg = min(cost_reg + regular[i], cost_exp + regular[i])`。 
2. 计算到达终点的最低成本`i+1`在快速路线上`new_cost_exp = min(cost_exp + express[i], cost_reg + express[i] + expressCost)`。 
3. 商店`min(new_cost_reg, new_cost_exp)`在`costs[i]`。 
4. 更新`cost_reg`和`cost_exp`到`new_cost_reg`和`new_cost_exp`分别用于下一次迭代。 
4. 返回`costs`。 

**为什么有效**：在每一步，算法都会考虑到达每条路线上停靠点的两种可能性。 通过始终保持每条路线的运行最小成本，它保证了维持和传播最小总成本。 这种动态规划方法可确保在线性时间内正确计算每个停靠点的全局最小值。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumCosts(self, regular: List[int], express: List[int], expressCost: int) -> List[int]:
        n = len(regular)
        costs = [0] * n
        cost_reg = 0
        cost_exp = float('inf')
        
        for i in range(n):
            new_cost_reg = min(cost_reg + regular[i], cost_exp + regular[i])
            new_cost_exp = min(cost_exp + express[i], cost_reg + express[i] + expressCost)
            costs[i] = min(new_cost_reg, new_cost_exp)
            cost_reg, cost_exp = new_cost_reg, new_cost_exp
        
        return costs
```**实现说明**：我们初始化`cost_reg`和`cost_exp`表示当前到达每条路线上一站的最佳成本。 对于每个站点，我们计算沿每条路线前进的成本，考虑停留在同一条路线上或从另一条路线切换。 然后我们更新成本并将该停靠点的最低成本存储在`costs`。 

## 解决方案```go
func minimumCosts(regular []int, express []int, expressCost int) []int64 {
    n := len(regular)
    costs := make([]int64, n)
    var costReg int64 = 0
    var costExp int64 = 1<<60
    
    for i := 0; i < n; i++ {
        r := int64(regular[i])
        e := int64(express[i])
        
        newCostReg := min(costReg+r, costExp+r)
        newCostExp := min(costExp+e, costReg+e+int64(expressCost))
        
        costs[i] = min(newCostReg, newCostExp)
        costReg, costExp = newCostReg, newCostExp
    }
    return costs
}

func min(a, b int64) int64 {
    if a < b {
        return a
    }
    return b
}
```**Go 特定注释**：我们使用`int64`以避免大额整数溢出。 最大`n`成本值可以达到`10^5 * 10^5 = 10^10`，这超过了`int32`。 否则，该算法将镜像 Python 版本。
