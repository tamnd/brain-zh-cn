[LeetCode 问题 1000](https://leetcode.com/problems/minimum-cost-to-merge-stones/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、前缀和

 ## 解决方案

 ## 问题理解

 问题要求我们合并`n`根据非常具体的合并规则，将一堆石头合并成一堆。 每堆都表示为数组中的一个整数`stones`， 在哪里`stones[i]`是里面的石头数量`i-th`桩。 我们被允许完全合并`k`一次连续堆，合并的成本是这些堆中石子的总和`k`桩。 每次合并后，`k`一堆石头以其总数量成为一堆。 目标是计算将所有桩合并为一桩的**最小总成本**。 如果不可能减少到给定的单堆`k`，该函数应该返回`-1`。 

约束告诉我们数组长度`n`最多 30 个，每堆最少 1 颗石子，最多 100 颗石子。 这种小的输入大小暗示具有三次时间复杂度的动态规划解决方案是可行的。 

一个关键的观察是，**不可能**以单堆结束，除非`(n - 1) % (k - 1) == 0`。 这是因为每次合并都会减少堆的数量`k - 1`。 如果不满足这个条件，就不可能合并成一堆。 

重要的边缘情况包括数组，其中`k`等于`n`（可以一次全部合并），`k`大于合并期间的任何剩余段或数组，其中`(n - 1) % (k - 1) != 0`，这使得任务不可能完成。 

## 方法

 ### 蛮力

 暴力方法将递归地尝试所有有效的合并序列，并对每个序列的成本求和。 在每次递归调用时，我们都会尝试合并每个可能的组`k`连续堆，计算成本，减少数组，继续递归。 虽然正确，但这种方法具有**指数复杂性**，因为它探索了每种可能的合并顺序，即使对于`n = 30`。 

### 最佳方法

 关键的见解是使用**带有前缀和的动态规划**。 定义`dp[i][j]`作为从索引合并宝石的最低成本`i`到`j`分成尽可能少的堆。 过渡考虑了所有可能的分裂`m`在`[i, j)`有步骤`k - 1`, 计算`dp[i][m] + dp[m+1][j]`。 仅当范围内的桩数可以减少到恰好为 1 时（即，`(j - i) % (k - 1) == 0`）我们是否将石子的总和添加到`[i, j]`作为最终合并的成本。 使用前缀和可以让我们在 O(1) 时间内计算任意区间内的石子总数。 

该 DP 解决方案利用了约束`n <= 30`，给出可接受的立方时间复杂度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^n) | O(n^n) | O(n) | 递归探索所有合并顺序，太慢 |
 | 最佳| O(n^3 / k) | O(n^3 / k) | O(n^2) | O(n^2) | 具有前缀和和基于 k 的受限分割的 DP |

 ## 算法演练

 1. **检查可行性：** 如果`(n - 1) % (k - 1) != 0`， 返回`-1`立即，因为合并成一堆是不可能的。 
2. **计算前缀和：** 构造`prefix[i]`作为第一个的总和`i`石头。 这允许 O(1) 计算任何区间的总和。 
3. **初始化DP表：**令`dp[i][j]`表示合并的最低成本`stones[i..j]`分成尽可能少的堆。 初始化`dp[i][i] = 0`因为单堆不需要任何成本。 
4. **填写 DP 表：** 对于所有长度间隔`l`从 2 到`n`，迭代所有可能的分割`m`这样`m = i + t * (k - 1)`为了`t = 1, 2, ...`以确保有效的分割。 更新`dp[i][j] = min(dp[i][m] + dp[m+1][j])`。 
5. **如果可能的话合并间隔：** 如果`(j - i) % (k - 1) == 0`, 区间`[i..j]`可以合并成一个堆。 将区间内的石子总数相加`dp[i][j]`。 
6. **返回结果：**`dp[0][n-1]`包含将整个数组合并为一堆的最小总成本。 

**为什么有效：** DP 表维护了以下不变式：`dp[i][j]`是合并区间的最小成本`[i..j]`分成尽可能少的堆。 通过考虑以`k - 1`，我们尊重合并规则，确保不发生非法合并。 前缀和保证了区间和的 O(1) 计算，保证了正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def mergeStones(self, stones: List[int], k: int) -> int:
        n = len(stones)
        if (n - 1) % (k - 1) != 0:
            return -1
        
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i+1] = prefix[i] + stones[i]
        
        dp = [[0] * n for _ in range(n)]
        
        for length in range(2, n + 1):
            for i in range(n - length + 1):
                j = i + length - 1
                dp[i][j] = float('inf')
                for m in range(i, j, k - 1):
                    dp[i][j] = min(dp[i][j], dp[i][m] + dp[m+1][j])
                if (length - 1) % (k - 1) == 0:
                    dp[i][j] += prefix[j+1] - prefix[i]
        
        return dp[0][n-1]
```Python 解决方案首先检查可行性，计算区间和的前缀和，并初始化 DP 表。 然后，它根据以下条件考虑所有有效的分割来填充 DP 表：`k - 1`。 最终结果读取自`dp[0][n-1]`。 

## 解决方案```go
func mergeStones(stones []int, k int) int {
    n := len(stones)
    if (n-1)%(k-1) != 0 {
        return -1
    }
    
    prefix := make([]int, n+1)
    for i := 0; i < n; i++ {
        prefix[i+1] = prefix[i] + stones[i]
    }
    
    dp := make([][]int, n)
    for i := 0; i < n; i++ {
        dp[i] = make([]int, n)
    }
    
    for length := 2; length <= n; length++ {
        for i := 0; i <= n-length; i++ {
            j := i + length - 1
            dp[i][j] = 1<<31 - 1
            for m := i; m < j; m += k - 1 {
                if dp[i][m]+dp[m+1][j] < dp[i][j] {
                    dp[i][j] = dp[i][m] + dp[m+1][j]
                }
            }
            if (length-1)%(k-1) == 0 {
                dp[i][j] += prefix[j+1] - prefix[i]
            }
        }
    }
    
    return dp[0][n-1]
}
```Go 解决方案反映了 Python 逻辑。 Go 需要仔细的切片初始化和整数最大值的显式处理。 前缀和和DP更新遵循相同的模式，确保正确性。
