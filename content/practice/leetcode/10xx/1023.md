[LeetCode 第 1023 题](https://leetcode.com/problems/camelcase-matching/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、字符串、Trie、字符串匹配

 ## 解决方案

 ## 问题理解

 该问题为我们提供了查询字符串列表和目标驼峰式大小写模式。 对于每个查询，我们必须确定是否可以通过在模式中仅插入小写英文字母来形成查询。 

重要的限制是我们只能插入小写字母。 我们不允许插入大写字母、删除字符、重新排序字符或更改字母大小写。 

这意味着查询的大写结构必须与模式隐含的大写结构完全对齐。 

例如，如果模式是`"FB"`:

 -`"FooBar"`匹配是因为我们可以插入小写字母：

 -`"F"`+`"oo"`+`"B"`+`"ar"`-`"FootBall"`还匹配：

 -`"F"`+`"oot"`+`"B"`+`"all"`-`"FooBarTest"`不匹配，因为多了一个大写字母`'T'`无法插入。 我们只允许插入小写字母。 

输入包括：

 -`queries`，字符串数组
 -`pattern`，目标驼峰模式

 输出是一个布尔数组，其中每个元素指示相应的查询是否与模式匹配。 

限制相对较小：

 - 最多 100 个查询
 - 每串长度最多100

 这意味着即使是`O(n * m)`解，其中`m`是查询长度，是完全可以接受的。 

一些边缘情况很重要：

 - 带有额外大写字母的查询应该立即失败。 
- 短于模式的查询无法匹配。 
- 查询可能包含许多额外的小写字母，这是允许的。 
- 模式本身可能包含小写字母，因此匹配不仅仅是大写字符。 
- 精确匹配也应该返回`true`。 

## 方法

 ### 蛮力方法

 一个强力的想法是显式尝试所有可能的方式将小写字母插入到模式中，并检查结果字符串是否等于查询。 

从概念上讲，对于每个查询：

 1. 从图案开始。 
2. 尝试在每个可能的位置插入小写字母。 
3. 生成所有可能的候选字符串。 
4. 检查生成的字符串是否等于查询。 

这是有效的，因为匹配的定义实际上是基于将小写字母插入到模式中。 

然而，这种方法在计算上是不可行的，因为插入组合的数量随着查询长度呈指数增长。 即使对于中等大小的字符串，生成的候选者的数量也会变得巨大。 

尽管约束很小，但指数生成仍然是不必要的且效率低下。 

### 最佳两指针方法

 关键的观察是我们实际上不需要生成字符串。 

相反，我们只需要验证查询是否可以遍历，同时按顺序使用模式字符。 

规则是：

 - 如果当前查询字符与当前模式字符匹配，则使两个指针都前进。 
- 如果查询字符是小写且不匹配，我们可能会跳过它，因为允许小写插入。 
- 如果查询字符为大写且不匹配，则查询立即无效，因为大写字母不能任意插入。 

最后：

 - 所有模式字符必须匹配。 
- 任何剩余的查询字符必须全部小写。 

这自然会导致线性两指针扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 生成所有可能的小写插入 |
 | 最佳 | O(Q × L) | O(1) | O(1) | 每个查询的两个指针扫描 |

 这里：

-`Q`= 查询数
 -`L`= 最大查询长度

 ## 算法演练

 ### 最优两指针算法

 1. 遍历每个查询`queries`。 

我们独立处理每个查询，因为匹配条件仅取决于当前查询和共享模式。 
2. 初始化两个指针。 

使用：

-`i`对于查询
 -`j`对于图案

 两者都开始于`0`。 
3. 从左到右遍历查询。 

在每一步中，比较`query[i]`和`pattern[j]`。 
4. 如果字符匹配，则使两个指针都前进。 

这意味着当前模式字符已按顺序成功匹配。 
5. 如果字符不匹配，检查是否`query[i]`是小写的。 

如果是小写，则仅前进跳过它`i`。 

这相当于在模式中插入一个额外的小写字符。 
6. 如果字符不匹配并且`query[i]`为大写，返回`false`。 

除非与模式显式匹配，否则大写字母不会出现。 
7. 继续，直到处理完整个查询。 
8. 遍历结束后，验证整个模式是否匹配。 

这意味着`j == len(pattern)`。 

如果没有，则永远找不到某些所需的模式字符。 
9. 存储当前查询的结果。 
10. 返回最终的布尔数组。 

### 为什么它有效

 该算法保持了指针之前的所有字符的不变性`j`模式中的内容已按查询中的顺序进行匹配。 

小写查询字符可能始终会被跳过，因为该问题允许在模式中的任何位置插入小写字母。 

无法跳过大写查询字符，因为不允许插入大写字符。 因此，查询中的每个大写字母必须与模式字符完全对应。 

由于算法在执行这些规则时按顺序检查所有字符，因此它可以正确确定是否可以根据模式形成查询。 

## Python 解决方案```python
from typing import List

class Solution:
    def camelMatch(self, queries: List[str], pattern: str) -> List[bool]:
        def matches(query: str, pattern: str) -> bool:
            pattern_index = 0
            pattern_length = len(pattern)

            for char in query:
                if pattern_index < pattern_length and char == pattern[pattern_index]:
                    pattern_index += 1
                elif char.isupper():
                    return False

            return pattern_index == pattern_length

        return [matches(query, pattern) for query in queries]
```该实现定义了一个名为的辅助函数`matches`检查单个查询是否与模式匹配。 

变量`pattern_index`跟踪模式中已经匹配了多少个字符。 

该循环遍历查询中的每个字符：

 - 如果当前查询字符与下一个所需的模式字符匹配，我们前进`pattern_index`。 
- 否则，如果查询字符为大写，则查询立即无效。 
- 小写不匹配将被忽略，因为允许小写插入。 

处理整个查询后，该函数验证是否已使用所有模式字符。 如果不是，则查询无法完全匹配。 

最后，主函数将此帮助器应用于每个查询并返回结果布尔列表。 

## 解决方案```go
func camelMatch(queries []string, pattern string) []bool {
	result := make([]bool, len(queries))

	for i, query := range queries {
		result[i] = matches(query, pattern)
	}

	return result
}

func matches(query string, pattern string) bool {
	patternIndex := 0
	patternLength := len(pattern)

	for _, char := range query {
		if patternIndex < patternLength && byte(char) == pattern[patternIndex] {
			patternIndex++
		} else if char >= 'A' && char <= 'Z' {
			return false
		}
	}

	return patternIndex == patternLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个小的区别是大写字母检测。 而不是使用像这样的内置助手`isupper()`，代码检查符文是否位于`'A'`和`'Z'`。 

该解决方案使用辅助函数来保持逻辑模块化和可读性。 

由于约束很小并且只涉及英文字母，因此对模式使用字节索引是完全安全的。

 ## 边缘情况

 当模式完全匹配后查询包含额外的大写字母时，就会出现一种重要的边缘情况。 例如，`"FooBarTest"`有图案`"FB"`应该失败，因为尾随大写`'T'`无法插入。 一旦模式匹配并错误返回，幼稚的实现可能会停止`true`。 此实现继续扫描剩余的查询字符并拒绝任何不匹配的大写字母。 

另一个重要的边缘情况是查询比模式短。 例如，查询`"FB"`和图案`"FooBar"`无法匹配，因为从未找到某些模式字符。 该实现通过在最后验证每个模式字符是否已被消耗来处理这个问题。 

第三个重要的边缘情况涉及小写字母不匹配。 例如，`"FooooBaaaar"`应该匹配`"FB"`即使匹配字符之间出现许多额外的小写字母。 有缺陷的实现可能需要连续匹配。 只要小写字符与当前模式字符不匹配，此解决方案就会正确地跳过它们。 

当大写字母对齐不正确时，会出现第四种边缘情况。 例如，`"ForceFeedBack"`不匹配`"FB"`因为第二个大写字母是`'F'`而不是`'B'`。 该实现立即拒绝大写不匹配，保证驼峰式结构验证的正确性。
