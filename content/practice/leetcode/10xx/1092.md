 ## 解决方案

 # 最短公共超序列

 ## 问题理解

 该问题要求我们构建包含两者的最短字符串`str1`和`str2`作为子序列。 

子序列不要求字符连续出现。 相反，字符只需要以相同的相对顺序出现即可。 例如，`"abc"`是一个子序列`"axbxc"`因为我们可以删除多余的字符。 

我们有两个输入字符串：

 -`str1`-`str2`我们必须返回一个字符串，这样：

 1.`str1`是结果的子序列。 
2.`str2`也是结果的子序列。 
3. 在所有有效的可能性中，返回的字符串具有最小长度。 

如果存在多个最短答案，则返回其中任何一个都是可以接受的。 

关键的挑战是避免不必要的字符重复。 如果两个字符串共享公共子序列，我们应该重用这些共享字符而不是插入重复项。 

约束条件很重要：

 -`1 <= str1.length, str2.length <= 1000`- 两个字符串都包含小写英文字母。 

由于每个字符串的长度可达 1000，因此暴力生成所有超序列是完全不可行的。 需要一个有效的动态规划解决方案。 

一些边缘情况很重要：

 - 字符串可能已经相同。 
- 一个字符串可能已经是另一个字符串的子序列。 
- 字符串可能根本不共享公共字符。 
- 大量重复字符输入可能会导致低效的实现。 

该问题强烈表明与最长公共子序列问题的关系，因为共享子序列允许我们最大限度地减少重复。 

## 方法

 ### 蛮力方法

 一种简单的解决方案是尝试生成两个字符串的所有可能的超序列，然后选择最短的有效超序列。 

考虑这个问题的一种方法是递归地决定是否从`str1`，下一个字符`str2`，或者两者都匹配（如果它们匹配）。 

这最终探索了指数级的可能性，因为每次不匹配都会产生分支递归。 对于长度为 1000 的字符串来说，即使记忆结果字符串仍然过于昂贵。 

蛮力方法是正确的，因为它探索每个有效的超序列并选择最小长度的超序列。 然而，它的运行时间呈指数增长，并且对于给定的约束变得不可能。 

### 关键见解

 重要的观察是，我们只需要避免重复两个字符串已经共享的字符即可。 

这立即将这个问题与最长公共子序列（通常缩写为 LCS）联系起来。 

认为：

-`len(str1) = n`-`len(str2) = m`-`LCS length = k`那么最短公共超序列长度为：$|SCS| = n + m - k$为什么？ 

因为LCS字符可以在两个字符串之间共享而不是重复。 

所以最优策略变为：

 1. 计算 LCS。 
2. 合并 LCS 字符周围的两个字符串。 
3. 按顺序包含两个字符串中的非常见字符。 

这将问题转化为具有多项式复杂度的标准动态规划解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(n+m)) | O(2^(n+m)) | O(n+m) 递归 | 探索所有可能的超序列 |
 | 最佳| O(n × m) | O(n × m) | 使用 LCS 动态规划 |

 ## 算法演练

 ### 第 1 步：构建 LCS DP 表

 创建一个 2D DP 表，其中：

 -`dp[i][j]`表示 LCS 的长度：

 -`str1[:i]`-`str2[:j]`其递归式为：

 - 如果字符匹配：

 -`dp[i][j] = dp[i-1][j-1] + 1`- 否则：

-`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`该表告诉我们两个字符串之间的最大可重用子序列。 

### 第 2 步：重建濒海战斗舰

 开始于`dp[n][m]`并在桌子上向后移动。 

如果字符匹配：

 - 该角色属于 LCS。 
- 沿对角线移动。 

否则：

 - 向较大的DP值移动。 
- 这遵循最佳子序列路径。 

最后反转收集的字符，因为重建是向后发生的。 

### 步骤 3：合并 LCS 周围的字符串

 现在我们构造最短公共超序列。 

维护两个指针：

 -`i`为了`str1`-`j`为了`str2`对于每个角色`c`在濒海战斗舰中：

 1. 添加所有字符`str1`前`c`。 
2. 添加所有字符`str2`前`c`。 
3. 添加`c`一次。 
4. 使两个指针都前进。 

这保留了两个字符串的相对顺序，同时避免了共享字符的重复。 

### 步骤 4：附加剩余字符

 处理完完整的 LCS 后：

 - 附加剩余字符`str1`- 附加剩余字符`str2`这些字符不共享，因此必须出现在最终答案中。 

### 为什么它有效

 该算法之所以有效，是因为 LCS 代表两个字符串之间可以共享的最大字符数。 

LCS 之外的每个字符必须单独出现在超序列中。 通过合并共享 LCS 字符周围的两个字符串，我们保证：

 - 两个字符串仍保留子序列。 
- 共享角色仅包含一次。 
- 不能存在更短的有效超序列。 

因此，构建的字符串是最优的。 

## Python 解决方案```python
class Solution:
    def shortestCommonSupersequence(self, str1: str, str2: str) -> str:
        n = len(str1)
        m = len(str2)

        # Step 1: Build LCS DP table
        dp = [[0] * (m + 1) for _ in range(n + 1)]

        for i in range(1, n + 1):
            for j in range(1, m + 1):
                if str1[i - 1] == str2[j - 1]:
                    dp[i][j] = dp[i - 1][j - 1] + 1
                else:
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

        # Step 2: Reconstruct LCS
        i = n
        j = m
        lcs_chars = []

        while i > 0 and j > 0:
            if str1[i - 1] == str2[j - 1]:
                lcs_chars.append(str1[i - 1])
                i -= 1
                j -= 1
            elif dp[i - 1][j] >= dp[i][j - 1]:
                i -= 1
            else:
                j -= 1

        lcs = "".join(reversed(lcs_chars))

        # Step 3: Build shortest common supersequence
        result = []

        i = 0
        j = 0

        for char in lcs:
            while str1[i] != char:
                result.append(str1[i])
                i += 1

            while str2[j] != char:
                result.append(str2[j])
                j += 1

            result.append(char)
            i += 1
            j += 1

        # Step 4: Append remaining characters
        result.append(str1[i:])
        result.append(str2[j:])

        return "".join(result)
```实现首先构建标准 LCS 动态规划表。 每个单元格存储截至该点的最佳公共子序列的长度。 

表格完成后，代码通过向后遍历表格来重建实际的 LCS。 只要找到匹配的字符，它们就会被添加到 LCS 中。 

一旦知道 LCS，算法就会合并两个字符串。 下一个 LCS 字符之前出现的字符将直接复制到答案中。 当到达 LCS 字符时，仅添加一次。 

最后，附加所有剩余的后缀。 

这保证了结果字符串包含两个原始字符串作为子序列，同时保持尽可能短。 

## 解决方案```go
func shortestCommonSupersequence(str1 string, str2 string) string {
	n := len(str1)
	m := len(str2)

	// Step 1: Build LCS DP table
	dp := make([][]int, n+1)
	for i := range dp {
		dp[i] = make([]int, m+1)
	}

	for i := 1; i <= n; i++ {
		for j := 1; j <= m; j++ {
			if str1[i-1] == str2[j-1] {
				dp[i][j] = dp[i-1][j-1] + 1
			} else {
				if dp[i-1][j] > dp[i][j-1] {
					dp[i][j] = dp[i-1][j]
				} else {
					dp[i][j] = dp[i][j-1]
				}
			}
		}
	}

	// Step 2: Reconstruct LCS
	i := n
	j := m
	lcsChars := []byte{}

	for i > 0 && j > 0 {
		if str1[i-1] == str2[j-1] {
			lcsChars = append(lcsChars, str1[i-1])
			i--
			j--
		} else if dp[i-1][j] >= dp[i][j-1] {
			i--
		} else {
			j--
		}
	}

	// Reverse LCS
	for left, right := 0, len(lcsChars)-1; left < right; {
		lcsChars[left], lcsChars[right] = lcsChars[right], lcsChars[left]
		left++
		right--
	}

	// Step 3: Build SCS
	result := []byte{}

	i = 0
	j = 0

	for _, ch := range lcsChars {
		for str1[i] != ch {
			result = append(result, str1[i])
			i++
		}

		for str2[j] != ch {
			result = append(result, str2[j])
			j++
		}

		result = append(result, byte(ch))
		i++
		j++
	}

	// Step 4: Append remaining characters
	result = append(result, str1[i:]...)
	result = append(result, str2[j:]...)

	return string(result)
}
```Go 实现遵循与 Python 解决方案完全相同的算法结构。 

主要区别在于手动处理切片和字节数组。 由于 Go 中的字符串是不可变的，`[]byte`slice 用于有效构建 LCS 和最终答案。 

不存在整数溢出问题，因为最大 DP 值最多为 1000。

def is_subsequence(sub, s):
    it = iter(s)
    return all(c in it for c in sub)

 ## 边缘情况

 ### 相同的字符串

 如果两个字符串完全相同，则最短公共超序列就是原始字符串本身。 

这种情况可能会暴露一些错误，即实现在合并期间意外地重复共享字符。 我们的实现自然地处理了这个问题，因为 LCS 变成了整个字符串，所以每个字符都被共享一次。 

### 没有常见字符

 考虑：```
str1 = "abc"
str2 = "def"
```濒海战斗舰是空的。 

在这种情况下，两个字符串中的每个字符都必须独立出现在结果中。 由于不存在共享合并点，该实现正确地附加了两个字符串中的所有字符。 

### 一个字符串已经包含另一个字符串

 考虑：```
str1 = "abc"
str2 = "abdbc"
```这里，`"abc"`已经是`"abdbc"`。 

有缺陷的实现可能会在合并时不必要地重复字符。 我们的方法避免了这种情况，因为 LCS 重建正确地识别了所有可重用字符，从而允许较长的字符串保持不变。 

### 重复字符

 在 LCS 重建过程中，重复的字符常常会产生歧义。 

例如：```
str1 = "aaaab"
str2 = "baaab"
```有多种有效的濒海战斗舰选择。 DP重建确保一致地选择有效的LCS，并且无论选择哪条有效的LCS路径，合并过程仍然产生最优的最短超序列。
