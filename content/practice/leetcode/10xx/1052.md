[LeetCode 问题 1052](https://leetcode.com/problems/grumpy-bookstore-owner/)

 **难度：** 🟡 中等
 **主题：** 数组、滑动窗口

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大化书店中满意顾客的数量`n`分钟。 我们有两个数组：`customers`，表示每分钟有多少顾客到达，以及`grumpy`，它指示书店老板在每分钟内是否脾气暴躁 (1) 或不脾气暴躁 (0)。 如果老板脾气暴躁，那一分钟的顾客就会不满意； 否则，他们就满意了。 另外，主人可以使用一次秘技，避免因暴躁而暴躁。`minutes`连续分钟。 

目标是通过战略性地使用此技术来确定尽可能多的满意客户。 

约束告诉我们，输入数组可以长达 20,000 个元素，每个客户的数量最多可以达到 1000。这表明，检查所有可能间隔的低效强力解决方案`minutes`可能太慢了。 边缘情况包括所有者从不脾气暴躁的情况，其中`minutes`等于`n`，或者所有客户计数为零的情况。 

## 方法

 ### 蛮力

 暴力方法会考虑所有可能的情况`minutes`- 所有者可以使用该技术的长度间隔。 对于每个时间间隔，我们将计算满意的客户总数：不脾气暴躁分钟内所有客户的总和加上所选时间间隔内所有客户的总和（我们将其从脾气暴躁转换为不脾气暴躁）。 这种方法是正确的，但效率低下，因为它需要计算最多`n - minutes + 1`时间复杂度为 O(n * 分钟)，最坏情况下可能高达 4 * 10^8。 

### 最佳方法

 关键的见解是该问题可以简化为**滑动窗口问题**。 首先，我们计算当店主不脾气暴躁时已经满意的顾客总数。 然后，我们滑动一个长度的窗口`minutes`在整个阵列中，跟踪如果我们将该技术应用于该窗口就可以满足的其他客户。 任何窗口中最大的额外满意客户，添加到最初满意的客户中，就给出了答案。 这种方法的运行时间为 O(n)，因为每个元素都被处理两次，一次进入窗口，一次离开窗口。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * 分钟) | O(1) | O(1) | 检查每个可能的长度区间`minutes`|
 | 最佳 | O(n) | O(1) | O(1) | 滑动窗口方法寻找最大程度额外满意的客户|

 ## 算法演练

 1. 初始化`base_satisfied`存储在不脾气暴躁的时间内已经满意的顾客数量。 迭代一遍`customers`和`grumpy`数组，添加`customers[i]`到`base_satisfied`如果`grumpy[i]`是 0。 
2. 创建长度的滑动窗口`minutes`。 初始化`extra_satisfied`如果应用该技术，则存储额外满意客户的数量。 对于第一个`minutes`元素，添加`customers[i]`到`extra_satisfied`仅当`grumpy[i]`是 1。 
3. 初始化`max_extra_satisfied`的值`extra_satisfied`。 
4. 从索引处滑动窗口`minutes`到`n-1`。 在每一步中，减去离开窗口的第一个元素`extra_satisfied`（如果这是一个脾气暴躁的分钟）并添加进入窗口的新元素（如果这是一个脾气暴躁的分钟）。 更新`max_extra_satisfied`如果`extra_satisfied`超过它。 
5、最终结果是`base_satisfied + max_extra_satisfied`。 

**为什么它有效：** 保持的不变性是在每一步中，`extra_satisfied`正确计算当前窗口内可以满足的额外客户数量`minutes`。 通过使用滑动窗口有效地检查所有窗口，我们确保找到尽可能多的额外满意客户。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSatisfied(self, customers: List[int], grumpy: List[int], minutes: int) -> int:
        n = len(customers)
        base_satisfied = 0
        for i in range(n):
            if grumpy[i] == 0:
                base_satisfied += customers[i]

        extra_satisfied = 0
        for i in range(minutes):
            if grumpy[i] == 1:
                extra_satisfied += customers[i]

        max_extra_satisfied = extra_satisfied

        for i in range(minutes, n):
            if grumpy[i - minutes] == 1:
                extra_satisfied -= customers[i - minutes]
            if grumpy[i] == 1:
                extra_satisfied += customers[i]
            max_extra_satisfied = max(max_extra_satisfied, extra_satisfied)

        return base_satisfied + max_extra_satisfied
```**说明：** 我们首先计算不使用该技术而感到满意的客户。 然后，我们使用大小为的滑动窗口`minutes`计算可以满足的最大额外客户数。 在每一步中，窗口都会有效地更新额外满意的客户，而无需从头开始重新计算金额。 

## 解决方案```go
func maxSatisfied(customers []int, grumpy []int, minutes int) int {
    n := len(customers)
    baseSatisfied := 0
    for i := 0; i < n; i++ {
        if grumpy[i] == 0 {
            baseSatisfied += customers[i]
        }
    }

    extraSatisfied := 0
    for i := 0; i < minutes; i++ {
        if grumpy[i] == 1 {
            extraSatisfied += customers[i]
        }
    }

    maxExtraSatisfied := extraSatisfied

    for i := minutes; i < n; i++ {
        if grumpy[i-minutes] == 1 {
            extraSatisfied -= customers[i-minutes]
        }
        if grumpy[i] == 1 {
            extraSatisfied += customers[i]
        }
        if extraSatisfied > maxExtraSatisfied {
            maxExtraSatisfied = extraSatisfied
        }
    }

    return baseSatisfied + maxExtraSatisfied
}
```**Go 特定说明：** 逻辑与 Python 相同，但我们显式管理切片索引。 不需要动态数组或类型提示，并且考虑到约束，整数算术是安全的。 

## 工作示例

 **示例1：**`customers = [1,0,1,2,1,1,7,5]`,`grumpy = [0,1,0,1,0,1,0,1]`,`minutes = 3`1.`base_satisfied = 1 + 1 + 1 + 7 = 10`2. 初始窗口`[1,2,1]`（指数1-3），额外满意=2+1=3
 3.向右滑窗，超满意更新：

 -`[2,1,1]`= 2 + 1 + 1 = 4
 -`[1,1,7]`= 1 + 1 + 0 = 2
 -`[1,7,5]`= 1 + 0 + 5 = 6（最大）

 结果：`10 + 6 = 16`**示例2：**`customers = [1]`,`grumpy = [0]`,`minutes = 1`- 基础满意度 = 1
 - 滑动窗口不会增加满意度
 - 结果 = 1
