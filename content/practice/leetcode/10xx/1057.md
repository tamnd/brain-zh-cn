 # LeetCode 1057 - 校园自行车

 ## 问题理解

 该问题在二维网格上模拟工人和自行车之间的匹配过程。 每个工人和每辆自行车都有一个唯一的坐标，每个工人最终必须收到一辆自行车。 由于自行车的数量至少等于工人的数量，因此始终可以完成完整的分配。 

关键的细节是，分配不是为每个工人独立进行的。 相反，该问题定义了一个全局过程：

 1. 在所有当前未分配的工人和当前可用的自行车中，选择曼哈顿距离最小的一对。 
2. 将那辆自行车分配给该工人。 
3. 将两者从未来的考虑中删除。 
4. 重复此过程，直到每个工人都有自行车。 

两点之间的曼哈顿距离为：$$|x_1 - x_2| + |y_1 - y_2|$$该问题还定义了严格的平局打破规则。 如果多个工作自行车对具有相同的距离：

 1. 选择工人索引较小的对。 
2. 如果工人指数也相同，则选择较小的自行车指数。 

输出是一个数组，其中`answer[i]`是分配给工人的自行车的索引`i`。 

约束对于选择算法很重要。 工人和自行车的数量最多可以达到 1000 辆。这意味着最多可以有：$$1000 \times 1000 = 1,000,000$$可能的工人自行车对。 任何在每次分配后重复扫描所有对的解决方案都会变得太慢。 

尽早识别一些边缘情况很重要：

 - 多对可能共享相同的曼哈顿距离，因此必须严格按照规定实施平局决胜。 
- 一辆自行车只能分配一次，即使它是多个工人最接近的选择。 
- 一名工人只能收到一辆自行车。 
- 一些工人附近可能有很多自行车，而其他工人的选择非常有限，因此一名工人的贪婪选择会影响所有后续任务。 
- 由于所有坐标都是唯一的，因此我们永远不会有重复的点，但相等的距离仍然很常见。 

## 方法

 ### 蛮力方法

 直接模拟方法将重复搜索当前有效的每个工作自行车对，以找到最佳分配。 

每一步：

 1. 检查每一位未分配的工人。 
2. 检查每辆未使用的自行车。 
3. 计算曼哈顿距离。 
4. 根据以下条件跟踪最佳配对：

 - 最小距离
 - 那么最小的工人索引
 - 那么最小的自行车索引
 5. 分配该对。 
6. 重复此操作，直至分配完所有工作人员。 

这种方法是正确的，因为它完全遵循问题陈述。 然而，它的效率很低，因为每次分配后都会重复完整的搜索。 

如果有`n`工人和`m`自行车，那么每个分配步骤可能会检查几乎`n * m`配对，我们执行这个过程`n`次。 

这大致导致：$$O(n^2 \times m)$$当两个维度都接近 1000 时，成本就变得太高了。 

### 最佳方法

 关键的观察是排序规则是完全确定的。 每个工作自行车对都可以表示为：$$(distance,\ workerIndex,\ bikeIndex)$$如果我们生成所有可能的对并根据这些规则对它们进行排序，那么我们就可以按排序顺序处理这些对。 

每当我们遇到一对时：

 - 如果工人仍未分配
 - 自行车还没用过

 然后我们执行任务。 

由于这些对是按照问题所需的确切优先级顺序全局处理的，因此遇到的第一个有效对始终是正确的下一个分配。 

这避免了重复地重新扫描所有可能性。

 ## 算法演练

 ### 第 1 步：生成所有可能的对

 对于每个工人和每辆自行车：

 1. 计算曼哈顿距离。 
2. 存储一个包含以下内容的元组：

 - 距离
 - 工人指数
 - 自行车指数

 这将创建所有可能分配的完整列表。 

我们使用元组是因为 Python 和 Go 排序自然地按字典顺序比较值，这完全符合平局打破规则。 

### 第 2 步：对对进行排序

 按升序对所有元组进行排序。 

排序顺序变为：

 1.先减小距离
 2.较小的工人指数优先
 3.首先是较小的自行车索引

 排序后，这些对完全按照问题陈述所需的顺序出现。 

### 第 3 步：跟踪作业

 维护：

 - 答案数组初始化为`-1`- 跟踪二手自行车的集合或布尔数组
 - 指定工人的柜台

 这使我们能够有效地确定工人或自行车是否已被占用。 

### 步骤 4：按排序顺序处理对

 迭代排序列表。 

对于每对：

 1. 检查工人是否已有自行车。 
2. 检查自行车是否已被使用。 
3. 如果两者都是免费的：

 - 分配自行车
 - 将自行车标记为已使用
 - 增加分配的计数

 由于对按优先级顺序处理，因此第一个有效的分配始终是正确的。 

### 第 5 步：尽早停止

 一旦分配了每个工作人员，就终止循环并返回结果。 

这避免了对剩余对的不必要的处理。 

### 为什么它有效

 该算法之所以有效，是因为对所有对进行全局排序可以重现问题所需的精确选择顺序。 

在该过程中的任何时刻，按排序顺序的下一个有效对正是问题陈述将选择的对：

 - 最小距离
 - 然后是最小工人指数
 - 然后是最小自行车指数

 由于只有当工人和自行车都可用时才会进行分配，因此模拟完全符合所需的贪婪过程。 

## Python 解决方案```python
from typing import List

class Solution:
    def assignBikes(self, workers: List[List[int]], bikes: List[List[int]]) -> List[int]:
        pairs = []

        # Generate all worker-bike pairs
        for worker_index, (wx, wy) in enumerate(workers):
            for bike_index, (bx, by) in enumerate(bikes):
                distance = abs(wx - bx) + abs(wy - by)
                pairs.append((distance, worker_index, bike_index))

        # Sort by:
        # 1. distance
        # 2. worker index
        # 3. bike index
        pairs.sort()

        result = [-1] * len(workers)
        used_bikes = set()
        assigned_workers = 0

        # Process pairs in priority order
        for _, worker_index, bike_index in pairs:
            if result[worker_index] != -1:
                continue

            if bike_index in used_bikes:
                continue

            result[worker_index] = bike_index
            used_bikes.add(bike_index)
            assigned_workers += 1

            if assigned_workers == len(workers):
                break

        return result
```实现首先生成每个可能的工作自行车对。 对于每一对，计算曼哈顿距离并将其与工人和自行车索引一起存储。 

这`pairs.sort()`打电话尤其重要。 Python 按字典顺序对元组进行排序，因此元组的形式为：```python
(distance, worker_index, bike_index)
```自动遵循所需的平局打破规则。 

这`result`数组跟踪每个工人收到的自行车。 最初，每个值都是`-1`，表示未分配。 

这`used_bikes`set 确保没有自行车被分配多次。 

主处理循环迭代排序对。 如果工人已经拥有自行车或者自行车已经被使用过，则跳过这对自行车。 否则，立即执行分配。 

一旦分配完所有工作人员，循环就会停止，从而避免不必要的额外工作。 

## 解决方案```go
package main

import "sort"

func assignBikes(workers [][]int, bikes [][]int) []int {
	type Pair struct {
		distance int
		worker   int
		bike     int
	}

	pairs := []Pair{}

	// Generate all worker-bike pairs
	for wi, worker := range workers {
		for bi, bike := range bikes {
			distance := abs(worker[0]-bike[0]) + abs(worker[1]-bike[1])

			pairs = append(pairs, Pair{
				distance: distance,
				worker:   wi,
				bike:     bi,
			})
		}
	}

	// Sort according to problem rules
	sort.Slice(pairs, func(i, j int) bool {
		if pairs[i].distance != pairs[j].distance {
			return pairs[i].distance < pairs[j].distance
		}

		if pairs[i].worker != pairs[j].worker {
			return pairs[i].worker < pairs[j].worker
		}

		return pairs[i].bike < pairs[j].bike
	})

	result := make([]int, len(workers))
	for i := range result {
		result[i] = -1
	}

	usedBikes := make([]bool, len(bikes))
	assignedWorkers := 0

	// Process pairs in sorted order
	for _, pair := range pairs {
		if result[pair.worker] != -1 {
			continue
		}

		if usedBikes[pair.bike] {
			continue
		}

		result[pair.worker] = pair.bike
		usedBikes[pair.bike] = true
		assignedWorkers++

		if assignedWorkers == len(workers) {
			break
		}
	}

	return result
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}
```Go 解决方案遵循与 Python 实现相同的整体结构，但存在一些特定于语言的差异。 

Go 不像 Python 那样内置元组排序，所以我们定义一个`Pair`包含距离、工人索引和自行车索引的结构。 

排序是用`sort.Slice`，使用明确实现平局打破规则的自定义比较器。 

Go 解决方案使用布尔切片，而不是使用集合进行自行车跟踪。 由于自行车指数范围为`0`到`m - 1`，直接索引高效且简单。 

结果切片初始化为`-1`值，以便我们可以区分已分配的工人和未分配的工人。 

这里整数溢出不是问题，因为坐标值很小并且曼哈顿距离仍然在 Go 的整数范围内。

 ## 边缘情况

 当许多工作自行车对共享相同的曼哈顿距离时，就会出现一种重要的边缘情况。 如果排序不严格遵循所有平局打破规则，则很容易产生不正确的结果。 该实现通过存储按顺序存储的元组或结构来处理此问题`(distance, workerIndex, bikeIndex)`，确保确定性排序。 

另一个重要的情况发生在多个工人争夺同一辆自行车时。 如果不仔细跟踪分配状态，幼稚的实现可能会意外地多次分配同一辆自行车。 该解决方案通过维护一个来防止这种情况发生`used_bikes`结构并立即跳过已经分配的自行车。 

第三种边缘情况涉及距离很远的工人或自行车。 大坐标值可能会暴露出不正确的距离计算或某些语言中的溢出问题。 由于曼哈顿距离仅使用 1000 以下的值的加法和减法，因此 Python 和 Go 都可以安全地处理这些计算，而无需担心溢出。 

当一名工人最近的自行车因另一名工人较早认领而变得不可用时，就会出现最后一个微妙的边缘情况。 该算法可以正确处理这个问题，因为分配是按排序顺序全局进行的，而不是针对每个工作人员独立进行的。 这保证了每个赋值都与问题陈述中描述的精确贪婪过程相匹配。
