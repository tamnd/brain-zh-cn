[LeetCode 问题 1043](https://leetcode.com/problems/partition-array-for-maximum-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`arr`和一个整数`k`。 我们可以将数组划分为连续的子数组，其中每个子数组的长度最多`k`。 

选择分区后，分区内的每个元素都将替换为该分区中的最大值。 最终得分是变换后的数组的总和，我们的目标是最大化这个总和。 

例如，假设我们选择一个分区`[1, 15, 7]`。 该分区内的最大值为`15`，因此分区变为`[15, 15, 15]`。 它对最终答案的贡献变为：```
15 * 3 = 45
```挑战在于决定将分区边界放置在哪里，以使转换后的总和尽可能大。 

输入包括：

 -`arr`，原始整数数组
 -`k`, 允许的最大分区大小

 输出是一个整数，表示执行最佳分区后可实现的最大总和。 

约束条件很重要：

 -`arr.length <= 500`-`k <= arr.length`500 的数组长度对于二次动态规划解决方案来说足够小，但对于尝试每种可能的分区排列的穷举递归来说太大了。 

另一个重要的细节是数组值可以大到`10^9`，因此中间的总和可能会变大。 然而，该问题保证最终答案适合 32 位整数。 

一些边缘情况值得尽早识别：

 - 长度为1的数组
 -`k = 1`，意味着不可能进行有意义的分组
 -`k = n`，意味着整个数组可能成为一个分区
 - 严格增加数组，其中较大的后续值鼓励更大的分区
 - 严格减少数组，其中较小的分区大小可能更好
 - 包含零的数组

 简单的实现可以轻松地多次重新计算重叠的子问题，从而导致指数级的复杂性。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的分区配置。 

在每个位置，我们可以创建一个长度的分区：```
1, 2, 3, ..., k
```只要分区保留在数组边界内即可。 

对于每个选定的分区：

 1. 找到该分区内的最大值
 2. 计算贡献：```
partition_length * partition_max
```3.递归求解数组剩余后缀

 这保证了正确性，因为它探索了每个有效的分区排列。 

然而，相同的后缀子数组会被重复重新计算。 例如，索引的最佳答案`5`可以从许多不同的递归路径计算。 

分区组合的数量呈指数增长，使得这种方法太慢。 

### 最佳解决方案的关键见解

 关键的观察是该问题具有重叠的子问题。 

定义：```
dp[i] = maximum sum obtainable for the first i elements
```计算`dp[i]`，我们考虑以索引结尾的每个可能的分区`i - 1`。 

假设最终分区的长度`len`。 

然后：

 - 分区开始于：```
i - len
```- 我们跟踪该分区内的最大值
 - 它的贡献变为：```
partition_max * len
```- 分区之前的所有内容都已通过以下方式得到最佳解决：```
dp[i - len]
```所以：```
dp[i] = max(
    dp[i - len] + partition_max * len
)
```对于所有有效的分区长度。 

这将指数递归转换为多项式时间动态规划解决方案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(k^n) | O(k^n) | O(n) | 递归尝试每个分区组合 |
 | 最优动态规划| O(n * k) | O(n) | 使用 DP 逐步构建最佳答案 |

 ## 算法演练

 1.创建DP阵列`dp`尺寸的`n + 1`。`dp[i]`将代表使用第一个可实现的最大总和`i`数组的元素。 

初始化：```
dp[0] = 0
```因为空数组的和为零。 
2. 从左到右迭代数组。 

对于每个位置`i`，我们要计算第一个的最佳答案`i`元素。 
3. 考虑以位置结束的每个可能的分区`i - 1`。 

分区可以有长度：```
1 to k
```只要起始索引仍然有效。 
4. 向后扩展分区的同时，保持迄今为止看到的最大元素。 

这很重要，因为重复重新计算最大值会不必要地增加复杂性。 

例如：```
partition = arr[j:i]
```持续更新：```
current_max = max(current_max, arr[j])
```5. 计算当前分区的贡献。 

如果分区长度为：```
length = i - j
```那么它的转换后的贡献就变成了：```
current_max * length
```6. 将分区贡献与分区前的最佳解决方案结合起来。 

总候选值变为：```
dp[j] + current_max * length
```7. 取所有有效分区长度中的最大值。 

这确保我们为位置选择最佳的最终分区`i`。 
8、填写完DP表后，返回：```
dp[n]
```它代表整个数组的最佳答案。 

### 为什么它有效

 动态规划递归之所以有效，是因为每个有效的解决方案都可以被视为：```
(best solution before final partition) +
(contribution of final partition)
```一旦边界确定，分区就是独立的。 自从`dp[j]`已经存储了最终分区之前结尾的前缀的最佳解决方案，将其与每个可能的最终分区结合起来可以保证我们检查所有有效的最佳结构。 

因为我们采用所有分区长度的最大值，所以最终答案必须是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSumAfterPartitioning(self, arr: List[int], k: int) -> int:
        n = len(arr)

        dp = [0] * (n + 1)

        for i in range(1, n + 1):
            current_max = 0

            for j in range(i - 1, max(-1, i - k - 1), -1):
                current_max = max(current_max, arr[j])

                partition_length = i - j

                dp[i] = max(
                    dp[i],
                    dp[j] + current_max * partition_length
                )

        return dp[n]
```实现首先创建一个 DP 数组，其中`dp[i]`使用第一个存储可能的最佳答案`i`元素。 

外循环迭代每个可能的前缀长度。 对于每个`i`，我们计算该前缀的最佳值。 

内循环从索引处向后走`i - 1`至多`k`后面的元素。 这种向后遍历表示尝试每个可能的最终分区`i - 1`。`current_max`在向后扩展分区的同时增量更新。 这避免了重复地重新扫描分区。 

对于每个候选分区：```python
arr[j:i]
```我们计算：```python
dp[j] + current_max * partition_length
```这代表：

 - 划分前的最优解
 - 加上当前分区贡献的转换值

 最后，`dp[n]`包含整个数组的最佳答案。 

## 解决方案```go
func maxSumAfterPartitioning(arr []int, k int) int {
	n := len(arr)

	dp := make([]int, n+1)

	for i := 1; i <= n; i++ {
		currentMax := 0

		start := i - k
		if start < 0 {
			start = 0
		}

		for j := i - 1; j >= start; j-- {
			if arr[j] > currentMax {
				currentMax = arr[j]
			}

			partitionLength := i - j

			candidate := dp[j] + currentMax*partitionLength

			if candidate > dp[i] {
				dp[i] = candidate
			}
		}
	}

	return dp[n]
}
```Go 实现遵循与 Python 解决方案完全相同的动态编程逻辑。 

一个区别是 Go 不提供内置的`max()`函数用于整数，因此使用手动执行比较`if`声明。 

切片用于 DP 数组，所有整数都可以安全地放入 Go 中`int`在问题约束下键入。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 在这种情况下，每个分区必须恰好包含一个元素。 没有任何转换实际上会更改数组，因为每个分区最大值等于元素本身。 有缺陷的实现可能仍会尝试更大的分区或错误地更新 DP 转换。 当前的实现可以自然地处理这个问题，因为内部循环仅考虑大小为 1 的分区。 

另一个关键的边缘情况是`k = n`。 在这种情况下，整个阵列可能成为单个分区。 该算法正确评估所有分区长度直至完整数组大小，使其能够发现将整个数组转换为全局最大值是否会产生最佳结果。 

包含重复或相同值的数组也可能暴露逻辑错误。 如果最大跟踪实施不正确，算法在向后扩展时可能无法保留正确的分区最大值。 该实现通过增量更新避免了这个问题`current_max`在向后遍历的过程中。 

最后一个微妙的边缘情况涉及包含零的数组。 由于分区贡献可能变为零，因此错误初始化 DP 值或最大值的实现可能会产生无效结果。 该算法安全初始化`current_max`为零并始终使用有效的分区范围计算候选者。
