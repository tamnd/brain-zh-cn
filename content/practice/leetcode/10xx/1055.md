[LeetCode 问题 1055](https://leetcode.com/problems/shortest-way-to-form-string/)

 **难度：** 🟡 中等
 **主题：** 两个指针、字符串、二分查找、贪婪

 ## 解决方案

 ## 问题理解

 问题要求我们构造字符串`target`使用字符串的尽可能少的子序列`source`。 

子序列保留相对顺序，但字符不需要是连续的。 例如，`"ace"`是一个子序列`"abcde"`因为我们可以删除`"b"`和`"d"`同时保持其余字符的顺序。 

我们被允许重复使用`source`多次。 每次我们重用它时，我们都可以从中选择任何子序列。 目标是确定此类子序列的最小数量，这些子序列的串联形成了整个序列`target`。 

例如：

-`source = "abc"`-`target = "abcbc"`我们可以形成：

 -`"abc"`从第一次通过`source`-`"bc"`从第二遍开始

 所以答案是`2`。 

重要的细节是每个子序列必须尊重字符的顺序`source`。 我们无法重新排列字符。 

限制相对较小：

 -`1 <= source.length, target.length <= 1000`- 仅限小写英文字母

 这意味着即使是`O(n * m)`解决方案是完全可以接受的，其中：

 -`n = len(source)`-`m = len(target)`然而，指数或高度递归的强力解决方案仍然不切实际。 

一些边缘情况很重要：

 - 一个角色存在于`target`但不在`source`，在这种情况下答案是立即`-1`。 
-`target`可能需要多次重置`source`指针。 
-`source`可能包含重复的字符。 
- 最佳解决方案是贪婪的，但前提是仔细实施。 

关键的挑战是确定我们何时必须开始一个新的子序列以及如何最大化`target`每次通过时都匹配`source`。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试生成所有可能的子序列`source`并反复尝试它们的组合以形成`target`。 

对于一个长度的字符串`n`， 有`2^n`可能的子序列。 即使与`n = 1000`，这是一个天文数字，完全不可行。 

另一个稍微好一点的蛮力想法是：

 1.从头开始`target`2. 扫描`source`3.匹配尽可能多的字符
 4. 重新开始扫描`source`5. 继续直到`target`完全匹配

 这已经类似于最佳贪婪方法，而且重要的是，它避免显式生成子序列。 

这种贪心方法起作用的原因是在每次遍历期间`source`，跳过有助于匹配当前目标字符的字符永远不会有任何好处。 由于我们想要最小数量的子序列，因此每次传递应该消耗尽可能多的`target`尽可能。 

### 关键见解

 The core observation is:

 > 在一次遍历期间`source`，我们应该贪婪地匹配尽可能多的字符`target`尽可能。 

如果我们到达终点`source`完全匹配之前`target`，我们必须开始另一个子序列。 

这是有效的，因为：

 - 每个子序列对应一次遍历`source`- 最大化每次传球的匹配次数可以最小化传球总数

 我们可以用两个指针有效地实现这一点：

 - 一个指针`source`- 一个指针`target`每当一个字符匹配时，我们就前进目标指针。 

如果整个经过`source`即使一个新的目标字符都无法匹配，则当前目标字符不存在于`source`，答案是`-1`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 显式生成子序列 |
 | 最优贪心二指针 | O(n * m) | O(1) | O(1) | 每次通过时贪婪地消耗目标|

 ## 算法演练

 ### 最优贪心二指针算法

 1. 初始化一个指针`target_index`到`0`。 

该指针跟踪有多少个字符`target`我们已经建造好了。 
2. 初始化计数器`subsequence_count`到`0`。 

每一次完整的通过`source`表示使用一个子序列。 
3.同时`target_index`还在里面`target`，开始新的遍历`source`。 

增量`subsequence_count`因为我们正在开始另一个子序列。 
4. 存储当前值`target_index`扫描前`source`。 

这有助于检测我们在此过程中是否取得了任何进展。 
5. 遍历`source`从左到右。 

对于每个字符：

 - 如果匹配`target[target_index]`， 进步`target_index`- 继续扫描贪婪地消耗尽可能多的`target`尽可能
 6. 完成后通过`source`，检查是否`target_index`改变了。 

如果它没有改变，则当前目标位置中不存在字符`source`。 

在这种情况下，返回`-1`。 
7. 重复直到`target_index == len(target)`。 

至此，所有目标人物已经成型。 
8. 返回`subsequence_count`。 

### 为什么它有效

 贪心策略是最优的，因为每个子序列都对应于一次完整的从左到右的遍历`source`。 在遍历过程中，匹配较少的字符永远无法帮助减少后面的子序列总数。 因此，在每次传递过程中贪婪地消耗尽可能多的目标字符总是可以最小化所需的传递次数。 

该算法还可以正确检测不可能的情况，因为如果整个扫描通过`source`未能推进目标指针，则所需的字符不存在于`source`。 

## Python 解决方案```python
class Solution:
    def shortestWay(self, source: str, target: str) -> int:
        target_index = 0
        subsequence_count = 0

        while target_index < len(target):
            previous_index = target_index

            for char in source:
                if target_index < len(target) and char == target[target_index]:
                    target_index += 1

            if previous_index == target_index:
                return -1

            subsequence_count += 1

        return subsequence_count
```实现直接遵循贪心二指针策略。 

变量`target_index`跟踪当前字符`target`仍然需要匹配。 

外层`while`循环表示重复使用的子序列`source`。 每次迭代对应一次完整的遍历`source`。 

在循环内部，我们存储`previous_index`扫描前`source`。 这使我们能够检测是否取得了任何进展。 

这`for char in source`循环贪婪地按顺序匹配字符。 每当当前源字符与当前目标字符匹配时，我们就前进`target_index`。 

扫描后：

 - 如果`target_index`没有改变，当前目标字符不存在于`source`，所以我们返回`-1`- 否则，我们成功形成了目标的一部分，因此我们递增`subsequence_count`一次`target_index`到达末尾`target`，整个目标字符串已经构建完成。 

## 解决方案```go
func shortestWay(source string, target string) int {
    targetIndex := 0
    subsequenceCount := 0

    for targetIndex < len(target) {
        previousIndex := targetIndex

        for i := 0; i < len(source); i++ {
            if targetIndex < len(target) &&
                source[i] == target[targetIndex] {
                targetIndex++
            }
        }

        if previousIndex == targetIndex {
            return -1
        }

        subsequenceCount++
    }

    return subsequenceCount
}
```Go 实现几乎完全反映了 Python 逻辑。 

由于 Go 字符串内部是字节切片，因此索引为`source[i]`和`target[targetIndex]`工作效率很高，因为输入仅包含小写英文字母。 

不需要对 Unicode 进行特殊处理。 

Go 也不需要在循环内进行显式边界检查，因为我们已经通过以下方式保护访问：```go
targetIndex < len(target)
```空间复杂度保持不变，因为只使用了几个整数变量。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`target`包含一个不存在的字符`source`。 例如：```
source = "abc"
target = "abd"
```幼稚的实现可能会进入无限循环重复扫描`source`没有取得进展。 此实现通过存储来避免该错误`previous_index`在每次传递之前验证是否至少有一个目标字符匹配。 

另一个重要的情况是字符顺序强制出现许多子序列。 例如：```
source = "abc"
target = "cba"
```尽管所有角色都存在于`source`，他们所需的顺序`target`与顺序冲突`source`。 该算法在必要时正确地重新启动扫描并产生`3`。 

第三个棘手的情况涉及重复的字符。 考虑：```
source = "a"
target = "aaaaaa"
```每一次经过`source`只能匹配一个字符。 某些实现错误地假设一次传递可以多次重复使用字符。 该解决方案将每个子序列正确地建模为单个从左到右的遍历`source`，所以它返回`6`。 

当整个目标已经可以在一次通过中形成时，会出现另一种微妙的边缘情况。 例如：```
source = "abcde"
target = "ace"
```算法在第一次遍历时贪婪地匹配所有可能的字符并正确返回`1`没有不必要的额外通行证。
