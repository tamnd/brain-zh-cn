[LeetCode 问题 1045](https://leetcode.com/problems/customers-who-bought-all-products/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们识别购买了列表中列出的每种产品的所有客户`Product`桌子。 换句话说，如果对于每个客户，客户就有资格获得输出`product_key`在`Product`表中存在对应行`Customer`该客户购买该产品的表。 

输入由两个关系表组成。 这`Customer`表记录了可能重复的单独购买，这意味着客户可能多次购买相同的产品。 这`Product`表列出了所有可用产品，每种产品都有一个独特的`product_key`。 

预期输出是一个列表`customer_id`代表购买了所有产品的客户的值。 输出的顺序并不重要。 

主要限制和观察包括：`Customer`table may contain duplicates, so counting unique purchases per customer is essential. 每一个`product_key`在`Customer`保证引用有效的产品`Product`桌子。 可能会出现一些边缘情况，即没有客户购买了所有产品，或者`Product`表中只有一个项目，这使得购买该项目的任何客户都能轻松解决该问题。 

## 方法

 ### 暴力方法

 蛮力方法涉及迭代每个客户并逐一检查他们是否购买了该产品中的所有产品。`Product`桌子。 这可以通过收集每个客户购买的产品组并将其与所有产品组进行比较来完成。 

虽然该方法是正确的，但效率较低，因为它需要多次扫描数据。 为了`n`客户和`m`产品，设定的比较步骤可以导致`O(n * m)`操作，并为所有客户构建集合需要额外的内存开销。 

### 最佳方法

 关键的见解是利用聚合。 我们可以计算每个客户购买的**不同产品**的数量，并将其与产品总数进行比较`Product`桌子。 如果计数匹配，则保证客户购买了所有产品。 这种方法减少了重复集合比较的需要，并允许数据库引擎使用以下方法有效地计算结果：`GROUP BY`和`HAVING`条款。 

此方法可以有效地处理重复项，因为计算不同的值`product_key`确保多次购买同一产品不会增加计数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(n * m) | 将每个客户购买的产品与完整的产品列表进行比较。 对于大表来说效率低下。 |
 | 最佳 | O(c + p) | O(c) | 计算每个客户的不同产品并与总产品进行比较。 高效聚合。 |

 这里，`c`是行数`Customer`和`p`是行数`Product`。 

## 算法演练

 1. 通过计算所有行来确定产品总数`Product`桌子。 这给出了每个客户必须购买的产品的目标数量。 
2. 查询`Customer`表，分组依据`customer_id`，并计算不同的`product_key`每个客户的价值。 这可确保重复项不会增加计数。 
3. 使用`HAVING`子句仅过滤那些不同产品数量与产品总数相匹配的客户。 
4. 返回`customer_id`这些客户的价值观。 

**为什么有效：** 这里的不变量是，任何不同产品数量等于产品总数的客户都必须购买了每件产品。 重复项不会影响计数，因为我们只考虑每个客户的不同产品。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def customers_who_bought_all_products(conn: sqlite3.Connection) -> List[Tuple[int]]:
    query = """
    SELECT customer_id
    FROM Customer
    GROUP BY customer_id
    HAVING COUNT(DISTINCT product_key) = (SELECT COUNT(*) FROM Product)
    """
    cursor = conn.cursor()
    cursor.execute(query)
    return cursor.fetchall()
```在此实现中，我们使用单个 SQL 查询来执行聚合。 这`GROUP BY`条款对采购进行分组`customer_id`,`COUNT(DISTINCT product_key)`确保忽略重复项，并且`HAVING`子句仅过滤那些购买了所有产品的客户。 子查询`(SELECT COUNT(*) FROM Product)`计算产品总数。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func CustomersWhoBoughtAllProducts(db *sql.DB) ([]int, error) {
    query := `
        SELECT customer_id
        FROM Customer
        GROUP BY customer_id
        HAVING COUNT(DISTINCT product_key) = (SELECT COUNT(*) FROM Product)
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var result []int
    for rows.Next() {
        var customerID int
        if err := rows.Scan(&customerID); err != nil {
            return nil, err
        }
        result = append(result, customerID)
    }
    return result, nil
}
```在 Go 中，我们执行相同的 SQL 查询。 差异包括迭代`rows.Next()`收集结果并明确处理错误`Query`和`Scan`。 切片用于动态存储结果。

 **逐步执行：**

 1. 计算产品总数：2 (`5`和`6`）。 
2. 计算每个客户的不同产品数量：

 - 顾客 1: {5, 6} → 2
 - 顾客 2：{6} → 1
 - 顾客 3: {5, 6} → 2
 3. 与总产品比较：

 - 客户 1 → 2 == 2 → 包括
 - 客户 2 → 1 != 2 → 排除
 - 客户 3 → 2 == 2 → 包括

 ## 边缘情况

 一个重要的边缘情况是当`Customer`表是空的。 在这种情况下，查询必须返回空结果，我们的方法可以正确处理该结果，因为没有客户满足所需的产品数量。 

另一个边缘情况是当`Product`表仅包含一种产品。 购买该产品的每个客户都应该包括在内，算法通过与总数 1 进行比较来处理这个问题。 

第三种边缘情况是在`Customer`桌子。 如果顾客多次购买同一产品，天真的计数可能会多算。 使用`COUNT(DISTINCT product_key)`确保重复不会影响结果。 

这些案例表明，基于聚合的解决方案非常强大，可以自然地处理输入的变化。
