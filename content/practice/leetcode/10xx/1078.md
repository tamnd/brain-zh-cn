[LeetCode 第 1078 题](https://leetcode.com/problems/occurrences-after-bigram/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`text`和两个目标词，`first`和`second`。 我们必须找到单词按精确顺序连续出现的每个出现位置：```
first second third
```对于每次出现这样的情况，我们返回的值`third`。 

重要的细节是单词必须按顺序紧邻出现。 我们不会搜索出现在字符串后面任何位置的单词。 该模式必须由三个连续的单词组成。 

例如，考虑：```
"alice is a good girl she is a good student"
```和：```
first = "a"
second = "good"
```有效的三元组是：```
"a good girl"
"a good student"
```对应的第三个词是：```
["girl", "student"]
```保证输入文本仅包含小写英文字母和单词之间的单个空格。 没有前导或尾随空格，这意味着我们可以安全地用空格分割字符串以获得干净的单词列表。 

限制很小：

 -`text.length <= 1000`- 每个单词长度最多`10`由于输入尺寸很小，即使是简单的线性扫描也足够高效。 不需要高级字符串匹配算法，例如 KMP 或基于 trie 的搜索。 

一些边缘情况很重要：

 - 文本可能包含少于三个单词，这意味着不存在有效的三元组。 
- 多个比赛可能会重叠。 
- 同一个词可能会出现多次。 
- 如果模式从未出现，结果可能为空。 
- 第三个词本身可以等于`first`或者`second`。 

正确的解决方案必须仔细扫描连续的单词三元组并收集每个有效的第三个单词。 

## 方法

 ### 蛮力方法

 蛮力的想法是检查文本中三个连续单词的每个可能序列。 

首先，将文本拆分为单词数组。 然后，对于每个索引`i`，检查是否：```
words[i] == first
words[i + 1] == second
```如果两个条件都成立，则附加：```
words[i + 2]
```到答案列表。 

这种方法是正确的，因为该模式的每个有效出现都必须在数组中的某个位置显示为三个连续的单词。 通过检查所有可能的三元组，我们保证不会遗漏任何有效的事件。 

尽管这对于问题约束来说已经足够有效，但我们仍然可以将其描述为基线强力解决方案，因为它独立地显式检查每个可能的三元组。 

### 最佳方法

 最佳方法实际上是相同的线性扫描，但更仔细地视为单词上的滑动窗口。 

关键的观察是我们一次只需要检查三个连续的单词。 由于单词已经用空格分隔，因此我们可以在分割文本后一次处理文本。 

我们只需遍历数组一次并直接比较相邻的单词，而不是重复构造子字符串或执行昂贵的搜索。 

这为我们提供了一个干净的线性时间解决方案，并且开销最小。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 检查连续单词的每个三元组 |
 | 最佳 | O(n) | O(n) | 使用连续字比较的单线性扫描 |

 这里，`n`表示文本中的单词数。 

## 算法演练

 1.分割输入字符串`text`放入一个名为`words`使用空格作为分隔符。 

这将问题从字符串处理转变为数组处理。 由于该问题保证单个空格并且没有前导或尾随空格，因此拆分操作会生成一个干净的单词列表。 
2. 创建一个空结果列表。 

该列表将存储我们发现的每个有效的第三个单词。 
3. 从索引处迭代数组`0`到`len(words) - 3`。 

我们停在`len(words) - 3`因为每项检查都需要访问：

 -`words[i]`-`words[i + 1]`-`words[i + 2]`4. 对于每个索引`i`， 比较：

-`words[i]`和`first`-`words[i + 1]`和`second`这两个比较确定当前位置是否开始有效模式。 
5. 如果两个单词匹配，则追加`words[i + 2]`到结果列表。 

紧随该对之后的第三个单词正是问题要求我们收集的内容。 
6. 继续扫描，直到检查完所有有效的三元组。 
7. 返回结果列表。 

### 为什么它有效

 该算法之所以有效，是因为模式的每次有效出现`"first second third"`必须占据字数组中的三个连续位置。 通过对所有连续三元组进行一次扫描，我们保证收集到每个有效的第三个单词，并且不包含无效单词。 

## Python 解决方案```python
from typing import List

class Solution:
    def findOcurrences(self, text: str, first: str, second: str) -> List[str]:
        words = text.split()
        result = []

        for i in range(len(words) - 2):
            if words[i] == first and words[i + 1] == second:
                result.append(words[i + 2])

        return result
```实现首先将输入文本拆分为单个单词的列表。 这允许直接索引访问连续的单词，而无需复杂的字符串操作。 

这`result`列表存储所有匹配的第三个单词。 

循环运行直到`len(words) - 2`因为我们必须安全地访问每个索引的接下来的两个位置。 在循环内部，算法检查当前单词是否等于`first`下一个单词等于`second`。 

每当该对匹配时，算法就会将紧随其后的单词附加到结果列表中。 

最后，该方法返回完成的结果列表。 

## 解决方案```go
package main

import "strings"

func findOcurrences(text string, first string, second string) []string {
	words := strings.Split(text, " ")
	result := []string{}

	for i := 0; i < len(words)-2; i++ {
		if words[i] == first && words[i+1] == second {
			result = append(result, words[i+2])
		}
	}

	return result
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 使用以下命令将文本拆分为单词`strings.Split`，算法扫描每个连续的三元组。 

Go 特有的一个细节是切片处理。 结果切片被初始化为空切片：```go
result := []string{}
```追加元素会根据需要动态增长切片。 

由于输入大小非常小，因此不存在整数溢出问题。

 ## 边缘情况

 当文本包含的单词少于三个时，就会出现一种重要的边缘情况。 由于所需的模式恰好包含三个连续的单词，因此不可能存在有效的出现。 盲目访问的幼稚实现`words[i + 2]`可能会产生索引错误。 该实现通过仅迭代最多来避免这种情况`len(words) - 2`。 

另一个重要的情况涉及重叠匹配。 考虑：```
"a a a a"
```和：```
first = "a"
second = "a"
```有两个有效的三元组：```
"a a a"
"a a a"
```从不同的位置开始。 某些实现在找到匹配后由于过于激进地前进而意外地跳过了重叠的匹配。 该解决方案正确检查每个连续的起始位置。 

当文本中任何地方都不存在匹配对时，就会出现第三种边缘情况。 该算法必须返回一个空列表而不是`None`或错误。 由于结果列表被初始化为空并且仅在成功匹配时追加，因此该实现自然会正确处理这种情况。 

当第三个词与任一词相同时，就会出现另一种微妙的情况`first`或者`second`。 该算法不假设单词之间的唯一性，只要前两个位置与目标对匹配，就简单地记录第三个单词。 即使使用重复或相同的单词，这也能保证正确的行为。
