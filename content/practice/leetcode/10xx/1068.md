 ## 解决方案

 ## 问题理解

 这个问题要求我们合并两个数据库表中的信息，`Sales`和`Product`，并生成包含每个销售记录的产品名称、销售年份和销售价格的结果。 

这`Sales`表存储事务信息。 每行代表特定年份的产品销售情况。 该表包含：

 -`sale_id`, 销售的标识符
 -`product_id`，正在销售的产品
 -`year`, 销售年份
 -`quantity`, 售出了多少单位
 -`price`，每单位的价格

 的`Product`表存储有关产品的元数据。 每行映射一个`product_id`到其对应的`product_name`。 

任务是报告：

 -`product_name`-`year`-`price`对于每一行`Sales`桌子。 

重要的细节是`product_name`不存在于`Sales`直接上表。 相反，两个表之间的关系是通过`product_id`柱子。 这意味着我们需要使用 SQL 合并两个表中的行`JOIN`。 

该问题保证：

 -`product_id`在`Sales`引用有效行`Product`-`product_id`是独一无二的`Product`-`(sale_id, year)`唯一标识行`Sales`由于这些保证，每个销售行将与一个产品行完全匹配。 

一个重要的边缘情况是同一产品有多个销售。 幼稚的实现可能会意外折叠行或聚合结果。 但是，该问题需要每个销售记录有一个输出行，因此每个匹配的销售必须保持独立。 

另一个边缘情况是现有的产品`Product`表没有对应的销售额。 这些产品不应出现在输出中，因为查询是由`Sales`桌子。 

## 方法

 ### 蛮力方法

 蛮力方法将手动比较中的每一行`Sales`表中的每一行`Product`桌子。 对于每笔销售：

 1. 迭代所有产品。 
2. 找到产品`product_id`匹配。 
3. 输出所需字段。 

这是有效的，因为最终每个销售行都会找到其匹配的产品行。 然而，这需要扫描整个`Product`每次销售都要重复表。 

如果有`N`销售行和`M`产品行，复杂性变为`O(N × M)`。 

虽然 LeetCode 数据库问题中的表通常很小，但这种方法效率低下，并且扩展性不好。 

### 最佳方法

 关键的观察结果是，关系数据库是专门为使用连接有效解决此类查找问题而设计的。 

自从`Sales.product_id`参考`Product.product_id`，我们可以使用`INNER JOIN`直接组合两个表中的匹配行。 

数据库引擎内部优化连接操作，通常使用索引或散列连接，使得操作比手动嵌套迭代效率显着提高。 

查询很简单：

 1. 加入`Sales`和`Product`2. 匹配行，其中`product_id`是平等的
 3. 选择所需的列

 ### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N × M) | O(1) | O(1) | 将每个销售行与每个产品行进行比较 |
 | 最佳 | O(N + M) 平均 | O(1) 或数据库管理 | 使用 SQL JOIN 高效匹配行 |

 ## 算法演练

 ### 最佳 SQL 连接算法

 1. 从`Sales`表，因为每个输出行对应于一次销售。 
2. 使用`INNER JOIN`连接`Sales`表与`Product`桌子。 加入条件为：```sql
Sales.product_id = Product.product_id
```这可确保每个销售行与其相应的产品信息相匹配。 
3. 仅选择所需的列：

 -`product_name`从`Product`桌子
-`year`从`Sales`桌子
-`price`从`Sales`表
 4. 以任意顺序返回结果行，因为问题明确指出顺序并不重要。 

### 为什么它有效

 该解决方案有效是因为`product_id`充当两个表之间的外键关系。 每条销售记录都引用一个有效的产品行。 通过加入`product_id`，我们保证每次销售都搭配正确的产品名称。 由于查询直接从匹配的行中选择字段，而不进行聚合或过滤，因此每个销售在输出中只出现一次。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT
    p.product_name,
    s.year,
    s.price
FROM Sales s
JOIN Product p
ON s.product_id = p.product_id;
```该解决方案将表别名为`s`和`p`使查询更短且更易于阅读。 

这`JOIN`操作合并行，其中`product_id`价值观匹配。 连接完成后，查询选择：

 -`product_name`从`Product`桌子
-`year`从`Sales`桌子
-`price`从`Sales`表

 因为问题不需要排序，所以没有`ORDER BY`条款是必要的。

 ## 边缘情况

 ### 同一产品多次销售

 一种产品可能会出现在不同年份的多个销售行中。 有错误的解决方案可能会意外地将行分组在一起或错误地返回重复数据。 此实现完全避免了聚合，因此每个销售行在结果中保持独立。 

### 未销售的产品

 的`Product`表可能包含从未售出的产品。 由于查询使用`Sales`表作为驱动表并执行`INNER JOIN`，没有匹配销售行的产品将自动从输出中排除。 

### 不同年份不同价格

 同一产品在不同的销售记录中可能有不同的价格。 实现正确检索`price`直接来自每个单独的销售行，而不是假设固定的产品价格。 这确保每个输出行都反映存储在的准确交易数据`Sales`。
