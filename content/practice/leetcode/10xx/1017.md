[LeetCode 问题 1017](https://leetcode.com/problems/convert-to-base-2/)

 **难度：** 🟡 中等
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 这道题要求我们转换一个非负整数`n`使用 **base 进入其表示形式`-2`**，代替通常的正碱基如碱基`2`， 根据`10`，或基数`16`。 

在标准二进制表示中，数字被写为`2`。 例如：$$13 = 1 \times 2^3 + 1 \times 2^2 + 0 \times 2^1 + 1 \times 2^0$$这变成`"1101"`。 

然而，在这个问题中，基数是**负**，具体来说`-2`。 这意味着每个位置代表一种力量`-2`:$$(-2)^0 = 1,\quad (-2)^1 = -2,\quad (-2)^2 = 4,\quad (-2)^3 = -8$$等等。 

例如：$$2 = (-2)^2 + (-2)^1$$因为：$$4 + (-2) = 2$$所以答案是`"110"`。 

输入由单个整数组成`n`， 在哪里：$$0 \leq n \leq 10^9$$输出必须是表示的**二进制字符串**`n`在基地`-2`，仅使用数字`'0'`和`'1'`。 

该问题明确指出返回的字符串**不得包含前导零**，除非结果本身是`"0"`。 

约束条件`n <= 10^9`告诉我们输入大小并不是很大，但我们仍然需要一种有效的数学方法。 由于类似二进制的表示形式相对于数字大小呈对数增长，因此我们的目标应该是`O(log n)`解决方案。 

一些边缘情况值得预先关注。 最重要的是`n = 0`，因为重复除法否则会产生空结果，但所需的输出是`"0"`。 另一个微妙的问题来自于基数为负这一事实。 在普通基数转换中，重复除法自然会产生非负余数。 使用负基数时，除法会产生负余数，这将违反仅二进制数字的要求`0`和`1`。 我们必须仔细调整商和余数以确保有效数字。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试生成可能的二进制字符串并检查哪个字符串的计算结果是`n`在基地`-2`。 

例如，我们可以枚举如下字符串：

 -`"0"`-`"1"`-`"10"`-`"11"`-`"100"`并使用以下方法评估它们的十进制值：$$\sum digit_i \times (-2)^i$$直到我们找到正确的表示。 

这是有效的，因为每个有效的基地`-2`表示唯一对应于十进制数。 

然而，这种方法很快就变得不切实际。 候选二进制字符串的数量随着字符串长度呈指数增长。 自从`n`可以大到`10^9`，该表示可能需要数十位，使得穷举搜索过于昂贵。 

因此，蛮力方法在计算上是不可行的。 

### 最佳方法，重复除以`-2`关键的观察结果是，即使使用负基数，**基数转换仍然可以使用重复除法**进行工作。 

在普通的基数转换中：

 - 除以基数
 - 记录余数
 - 继续商

 例如，转换为基数`2`反复除以`2`。 

我们可以在这里使用 base 应用相同的原理`-2`。 

每一步：$$n = (-2) \times quotient + remainder$$余数必须始终是`0`或者`1`，因为我们正在构建一个二进制表示。 

挑战在于除以负数会产生负余数。 例如：$$1 \div (-2)$$可能会导致无效的余数，例如`-1`。 

为了解决这个问题，每当余数变为负数时，我们就对其进行调整：

 - 添加`2`到剩余的
 - 添加`1`到商

 这保留了方程，同时确保余数保持在`{0, 1}`。 

由于每次除法大致将数字的大小减半，因此该算法以对数时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^k × k) | O(2^k × k) | O(k) | 枚举可能的二进制字符串并评估每个字符串 |
 | 最佳 | O(log n) | O(log n) | 重复除以`-2`余数调整 |

 这里，`k`是基数中的位数`-2`表示。 

## 算法演练

 1.处理特殊情况`n == 0`。 

由于重复除法不会产生数字，因此直接返回`"0"`。 
2. 创建一个列表来存储数字。 

我们从最低有效位到最高有效位构建数字，就像普通的基数转换一样。 列表允许高效的附加。 
3. 重复同时`n != 0`。 

每次迭代提取基数的一位数字`-2`表示。 
4. 计算商和余数。 

使用：```
quotient = n // -2
remainder = n % -2
```由于 Python 和负数除法可能会产生负余数，因此该余数并不总是有效。 
5. 修正负余数。 

如果`remainder < 0`：

- 添加`2`到剩余的
 - 添加`1`到商

 这保证了余数变成`0`或者`1`。 
6. 附加数字。 

将余数转换为字符串并存储。 
7. 更新`n`。 

放：```
n = quotient
```继续处理剩余的高位数字。 
8. 将收集到的数字反转。 

由于数字是从最低有效位到最高有效位生成的，因此在加入最终字符串之前将它们反转。 

### 为什么它有效

 该算法保持不变式：$$n = (-2) \times quotient + remainder$$在每次迭代中，余数始终是`0`或者`1`。 

每次迭代精确提取一个有效碱基`-2`数字，同时减少幅度`n`，保证最终终止。 因为每个余数都对应一个有效的二进制数字，并且表示形式是从最低有效位到最高有效位构建的，因此反转数字会产生正确的基数`-2`表示。 

## Python 解决方案```python
class Solution:
    def baseNeg2(self, n: int) -> str:
        if n == 0:
            return "0"

        digits: list[str] = []

        while n != 0:
            quotient = n // -2
            remainder = n % -2

            if remainder < 0:
                remainder += 2
                quotient += 1

            digits.append(str(remainder))
            n = quotient

        return "".join(reversed(digits))
```实现从处理特殊情况开始`n == 0`，因为必须返回零`"0"`直接地。 

然后我们创建一个名为的列表`digits`存储生成的二进制数字。 在每次迭代期间，我们划分`n`经过`-2`并计算余数。 

因为负除法可能会产生无效的负余数，所以我们检查是否`remainder < 0`。 如果是，我们将余数移入有效范围`{0, 1}`通过添加`2`，并通过增加商来补偿`1`。 

每个有效余数都成为答案的一位数字，附加到列表中。 由于首先生成最低有效数字，因此我们在将所有内容连接到最终字符串之前反转列表。 

该实现直接反映了基数转换的数学定义，同时仔细考虑了负基数。 

## 解决方案```go
func baseNeg2(n int) string {
	if n == 0 {
		return "0"
	}

	digits := []byte{}

	for n != 0 {
		quotient := n / -2
		remainder := n % -2

		if remainder < 0 {
			remainder += 2
			quotient++
		}

		digits = append(digits, byte(remainder)+'0')
		n = quotient
	}

	// Reverse digits
	left, right := 0, len(digits)-1
	for left < right {
		digits[left], digits[right] = digits[right], digits[left]
		left++
		right--
	}

	return string(digits)
}
```Go 实现遵循与 Python 版本相同的逻辑，但存在一些特定于语言的差异。 

我们不存储字符串，而是使用`[]byte`切片以有效地构建字符。 每个余数通过添加转换为一个字符`'0'`。 

由于Go没有提供内置的切片反转操作，因此我们使用两指针交换方法手动反转字节切片。 

整数溢出在这里不是问题，因为问题约束仅取决于`10^9`，完全在 Go 的范围内`int`范围。

 ## 边缘情况

 ### 案例 1：`n = 0`零是最重要的边缘情况，因为重复的除法永远不会执行，给我们留下一个空的数字列表。 返回空字符串是不正确的，因为问题明确要求`"0"`。 

实现立即处理这个问题：```
if n == 0:
    return "0"
```这保证了进入主循环之前的正确性。 

### 情况 2：除法时余数为负

 与普通基数转换不同，除以负基数会产生负余数。 例如：$$1 \% (-2) = -1$$负余数将违反仅二进制数字的要求`0`和`1`。 

该实现通过调整解决了这个问题：```
if remainder < 0:
    remainder += 2
    quotient += 1
```这保留了数学等式，同时确保了有效数字。 

### 情况 3：前导零

 如果算法附加额外的数字或错误处理终止条件，很容易意外生成前导零。 

由于循环恰好在以下时间停止`n == 0`，不添加不必要的高位数字。 反转收集到的数字自然会产生不带前导零的表示形式，特殊情况除外`"0"`分开处理。
