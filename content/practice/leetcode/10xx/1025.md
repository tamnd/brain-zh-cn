 ## 解决方案

 ## 问题理解

 该问题描述了 Alice 和 Bob 之间的两人回合制游戏。 游戏以单个整数开始`n`写在黑板上。 爱丽丝总是先走第一个回合。 

每回合，当前玩家必须选择一个正整数`x`这样：

 -`0 < x < n`-`x`划分`n`均匀的意思`n % x == 0`选择后`x`，玩家替换当前号码`n`和`n - x`。 

游戏继续进行，直到玩家无法做出有效的动作为止。 无法移动的玩家将立即失败。 

目标是确定如果两个玩家都发挥最佳状态，Alice 是否可以保证获胜。 “最佳”意味着每个玩家总是采取最好的行动来最大化自己获胜的机会。 

输入由单个整数组成`n`， 在哪里：```
1 <= n <= 1000
```这个约束相对较小，这意味着即使是模拟或动态规划方法也是可行的。 然而，该问题被标记为数学和博弈论问题，因为有一个更简单的观察可以得出恒定时间的解决方案。 

输出是一个布尔值：

 -`true`如果爱丽丝能强行获胜
 -`false`否则

 立即考虑几个边缘情况很重要。 

什么时候`n = 1`, Alice 没有有效的移动，因为没有整数`x`满意的`0 < x < 1`。 因此，爱丽丝立刻就输了。 

什么时候`n = 2`,爱丽丝可以选择`x = 1`，留给鲍勃`1`。 那么鲍勃没有有效的动作，所以爱丽丝获胜。 

另一个重要的观察涉及奇偶校验。 由于除数和减法会影响结果的偶数或奇数，因此了解奇偶校验转换成为有效解决问题的关键。 

## 方法

 ### 蛮力方法

 一种简单的方法是递归地模拟所有可能的游戏状态。 

对于每个当前值`n`，我们尝试每个有效除数`x`。 选择后`x`，游戏进入状态`n - x`。 如果至少存在一着棋导致对手输，那么当前状态就是赢。 

这自然会导致递归游戏状态探索：

 - 如果至少有一个州正在失败，则该州正在获胜
 - 如果所有接下来的州都获胜，则一个州正在失败

 例如：

 -`n = 1`因为没有有效的动作而失败
 -`n = 2`因为选择而获胜`1`树叶`1`，正在失去
 -`n = 3`正在失败，因为唯一的举动会导致`2`，这是获胜的

 如果没有记忆，这种递归解决方案会重复重新计算相同的状态并且变得低效。 

通过记忆或动态编程，复杂性变得易于管理`n <= 1000`，但解决方案仍然比必要的更复杂。 

### 关键见解

 关键的观察是，答案完全取决于是否`n`是偶数还是奇数。 

如果`n`势均力敌，爱丽丝总能强行获胜。 

如果`n`奇怪的是，爱丽丝总是会输。 

为什么？ 

奇数的每个约数也是奇数。 如果 Alice 以奇数开头：

 - 她必须减去一个奇数除数
 - 奇数减奇数等于偶数
 - 因此，她总是给鲍勃一个偶数

 现在考虑一个偶数：

 - 偶数总是有约数`1`- 减法`1`从偶数产生奇数
 - 因此，偶数的玩家总是可以迫使对手变成奇数

 这会创建一个重复模式：

 - 奇数为失败状态
 - 偶数为获胜州

 由于爱丽丝先开始，所以她赢的时间恰好是`n`是均匀的。

 ## 算法演练

 ### 最优算法

 1. 检查是否`n`是均匀的。 

整个博弈可以简化为平价`n`。 如果`n`可以整除`2`，Alice 总是可以迫使 Bob 的游戏进入奇怪的状态。 
2. 返回`true`如果`n`是均匀的。 

偶数保证获胜策略，因为爱丽丝总是可以做减法`1`，它是每个整数的有效除数。 
3. 返回`false`如果`n`很奇怪。 

奇数肯定会失败，因为每个有效除数都是奇数，这意味着对手的结果值总是偶数。 

### 为什么它有效

 不变量是每个偶数都是获胜状态，每个奇数都是失败状态。 

这可以归纳证明：

 - 基本情况：

 -`1`正在失去
 -`2`正在获胜
 - 归纳步骤：

 - 如果`n`是偶数，减去`1`给对手一个奇数
 - 如果`n`是奇数，每个除数都是奇数，所以每一步都会给对手一个偶数

 因此，最佳游戏保证了收到奇数的玩家最终会失败。 

## Python 解决方案```python
class Solution:
    def divisorGame(self, n: int) -> bool:
        return n % 2 == 0
```该实现非常紧凑，因为数学观察完全消除了递归或动态编程的需要。 

表达式`n % 2 == 0`检查是否`n`是均匀的。 

- 如果结果是`True`，爱丽丝获胜。 
- 如果结果是`False`，爱丽丝输了。 

这直接编码了算法演练中得出的经过验证的博弈论结果。 

## 解决方案```go
func divisorGame(n int) bool {
    return n%2 == 0
}
```Go 实现与 Python 版本几乎相同。 

Go 使用`%`与 Python 完全相同的模运算运算符。 由于约束非常小，因此不必担心整数溢出。 

不需要额外的内存结构，函数立即返回奇偶校验结果。

 ## 边缘情况

 ### 边缘情况 1：`n = 1`这是最小的可能输入，并且立即处于失败状态。 幼稚的实现可能会错误地假设每个数字至少有一个比其自身小的除数。 

在这种情况下，没有有效的`x`满意：```
0 < x < 1
```因此，爱丽丝立刻就输了。 该实现正确处理了这个问题，因为：```
1 % 2 == 1
```返回`False`。 

### 边缘情况 2：小偶数

 价值观如`2`和`4`之所以重要，是因为它们展示了核心制胜策略。 

为了`2`, 爱丽丝减去`1`并立即获胜。 

为了`4`,爱丽丝可以减去`1`离开`3`，这是一种失败状态。 

有缺陷的递归实现可能无法正确分类这些基本情况。 基于奇偶校验的解决方案完全避免了这个问题。 

### 边缘情况 3：大奇数

 大奇数，例如`999`可能看起来很困难，因为它们有很多除数。 

然而，奇数的每个约数也是奇数。 从奇数中减去任何奇数除数总是会产生偶数。 

因此，无论选择哪一步棋，当前玩家总是将偶数交给对手，这对对手来说是获胜状态。 

该实现通过单个奇偶校验统一处理所有奇数。
