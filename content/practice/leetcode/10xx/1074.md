[LeetCode 问题 1074](https://leetcode.com/problems/number-of-submatrices-that-sum-to-target/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、矩阵、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算 2D 矩阵内有多少个非空矩形子矩阵的总和等于给定值`target`。 

子矩阵是矩阵内任何连续的矩形区域。 如果我们选择两个行边界和两个列边界，则该矩形内的每个元素都属于子矩阵。 任务不是返回子矩阵本身，而是返回其元素总和恰好为的所有有效子矩阵的总数`target`。 

输入包括：

 - 二维整数矩阵`matrix`- 一个整数`target`输出是一个整数，表示总和等于的不同子矩阵的数量`target`。 

约束条件很重要：

 - 矩阵维度最多为`100 x 100`- 值可能为负
 - 目标也可能是负数

 负数的存在很重要，因为它阻止了依赖单调性的滑动窗口等技术的使用。 有效的解决方案必须正确处理任意正值和负值。 

简单的暴力解决方案将检查每个可能的子矩阵并独立计算其总和。 然而，一个子矩阵的数量`m x n`矩阵已经是`O(m^2 * n^2)`，并且反复重新计算总和变得太慢。 

重要的边缘情况包括：

 - 包含负数的矩阵
 - 用零填充的矩阵
 - 单细胞基质
 - 存在许多重叠子矩阵的大矩阵
 - 多个不同子矩阵产生相同目标总和的情况

 该问题保证矩阵非空，因此我们不需要处理空输入数组。 

## 方法

 ### 蛮力方法

 蛮力方法考虑每个可能的子矩阵。 

子矩阵由下式唯一确定：

 - 顶排
 - 底排
 - 左栏
 - 右栏

 这意味着有`O(m^2 * n^2)`可能的子矩阵。 

对于每个子矩阵，我们可以迭代矩形内的所有单元格并直接计算其总和。 由于一个矩形最多可以包含`O(m * n)`细胞，总复杂度变为：```
O(m^3 * n^3)
```即使使用前缀和，检查每个矩形仍然需要：```
O(m^2 * n^2)
```对于矩阵高达`100 x 100`，这可以逼近`10^8`操作，这在 Python 中太慢并且不必要地昂贵。 

暴力方法是正确的，因为它显式地检查每个可能的子矩阵，但它不能有效地扩展。 

### 最佳方法

 关键的见解是我们可以将二维问题简化为多个一维子数组和问题。 

假设我们修复两个行边界：

 -`top`-`bottom`对于每一列，我们计算这两行之间的元素之和。 这会将矩阵带转换为一维数组。 

现在问题变成：

 > 这个一维数组中有多少个子数组之和`target`？ 

这是一个经典的前缀和加哈希图问题。 

对于一维数组：

 - 让`prefixSum`是运行累计总和。 
- 如果`prefixSum - target`之前已经出现过，那么这些位置之间的子数组之和为`target`。 

使用哈希映射可以让我们在线性时间内计算有效子数组的数量。 

由于有`O(m^2)`行对，每对处理中的所有列`O(n)`，最终复杂度变为：```
O(m^2 * n)
```这对于约束来说足够有效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m2 * n2 * m * n) 或 O(m3 * n3) | O(1) | O(1) | 枚举每个子矩阵并直接对单元格求和 |

 ## 算法演练

 ### 最优算法

 1、首先确定矩阵的行数和列数。 
2. 遍历每个可能的起始行`top`。 
3. 对于每个`top`，创建一个数组，名为`columnSums`用零初始化。 该数组将累加当前行对之间每一列的总和。 
4. 使用另一个循环逐行扩展底部边界`bottom`。 
5. 对于每一列`c`， 添加`matrix[bottom][c]`进入`columnSums[c]`。 在此刻，`columnSums[c]`表示列中所有元素的总和`c`行与行之间`top`和`bottom`。 
6.现在问题变成：

 找出有多少个子数组`columnSums`总和为`target`。 
7. 对哈希映射使用前缀和技术：

 - 初始化哈希映射`{0: 1}`- 维护一个运行的前缀和
 - 对于每个值：

 - 将其添加到运行总和中
 - 检查是否`(currentSum - target)`存在于地图中
 - 如果存在，请将其频率添加到答案中
 - 将当前前缀和存储在地图中
 8. 对每对行重复此过程。 
9. 返回累计答案。 

### 为什么它有效

 修复顶行和底行可保证这些行之间的每个有效子矩阵与跨列的连续子数组精确对应。 

前缀和属性确保：```
prefix[j] - prefix[i] = target
```这意味着之间的子数组`i+1`和`j`总和为`target`。 

通过计算所有先前出现的`prefixSum - target`，我们有效地计算以当前位置结尾的所有有效子数组。 由于每个子矩阵通过某些行对和列间隔仅表示一次，因此该算法可以正确计算所有有效子矩阵。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def numSubmatrixSumTarget(
        self,
        matrix: List[List[int]],
        target: int
    ) -> int:
        
        rows = len(matrix)
        cols = len(matrix[0])

        total_count = 0

        # Fix the top row
        for top in range(rows):

            column_sums = [0] * cols

            # Expand the bottom row
            for bottom in range(top, rows):

                # Update compressed column sums
                for col in range(cols):
                    column_sums[col] += matrix[bottom][col]

                # Count subarrays with sum == target
                prefix_count = defaultdict(int)
                prefix_count[0] = 1

                current_sum = 0

                for value in column_sums:
                    current_sum += value

                    total_count += prefix_count[current_sum - target]

                    prefix_count[current_sum] += 1

        return total_count
```实现直接遵循算法。 

外循环选择顶部边界行。 对于每一顶行，我们初始化`column_sums`为零，因为我们将逐渐建立垂直条带总和。 

内环向下扩展底部边界。 每次我们包含另一行时，我们都会将其值添加到`column_sums`。 这有效地压缩了之间的二维区域`top`和`bottom`成一维数组。 

一旦我们有了这个压缩数组，我们就解决了经典的“子数组和等于 k”问题。 

哈希图`prefix_count`存储每个前缀和出现的次数。 正在初始化`{0: 1}`是必不可少的，因为前缀本身可能等于目标。 

每当：```python
current_sum - target
```存在于映射中，这意味着某个较早的前缀创建了一个以当前位置结尾的子数组，其总和等于`target`。 

该算法会累积每个行对中的所有此类匹配。 

## 解决方案```go
package main

func numSubmatrixSumTarget(matrix [][]int, target int) int {
	rows := len(matrix)
	cols := len(matrix[0])

	totalCount := 0

	for top := 0; top < rows; top++ {

		columnSums := make([]int, cols)

		for bottom := top; bottom < rows; bottom++ {

			for col := 0; col < cols; col++ {
				columnSums[col] += matrix[bottom][col]
			}

			prefixCount := map[int]int{
				0: 1,
			}

			currentSum := 0

			for _, value := range columnSums {
				currentSum += value

				totalCount += prefixCount[currentSum-target]

				prefixCount[currentSum]++
			}
		}
	}

	return totalCount
}
```Go 的实现与 Python 版本非常相似。 

Go 使用切片而不是 Python 列表，使用映射而不是字典。 与Python不同`defaultdict`，Go 映射会自动返回缺失键的零值，这简化了逻辑。 

整数溢出在这里不是问题，因为最大可能的矩阵和仍然在 Go 的范围内`int`问题约束下的范围。

 ## 边缘情况

 ### 包含负数的矩阵

 负数尤其重要，因为它们破坏了许多更简单的技术，例如滑动窗口。 在滑动窗口方法中，扩展窗口通常会增加总和，但负值会使该假设无效。 

此实现可以正确处理负数，因为它依赖于前缀和和精确的差异匹配而不是单调行为。 

### 全零矩阵

 填充零的矩阵会创建大量有效的子矩阵。 这可能会暴露计数逻辑中的错误，特别是在未正确跟踪重复前缀和的情况下。 

哈希映射存储前缀和的频率而不仅仅是存在，确保每个有效的起始位置正确地贡献于总计数。 

### 单行或单列矩阵

 当矩阵只有一行或一列时，问题实际上变成了标准的一维子数组和问题。 

该实现自然地处理了这个问题，因为即使只有一个可能的行对，固定行边界仍然可以正常工作。 

### 大重叠子矩阵

 一些矩阵包含许多重叠的有效子矩阵。 有缺陷的实现可能会意外地重复计算或错过一些矩形。 

该解决方案避免了重复，因为每个子矩阵都通过以下方式精确表示一次：

 - 一对独特的行边界
 - 一个唯一的连续列间隔

 因此，每个有效矩形只对答案贡献一次。
