[LeetCode 第 1098 题](https://leetcode.com/problems/unpopular-books/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们从以下位置识别书籍：`Books`根据去年的销售额（相对于固定的“今天”日期）被认为**不受欢迎**的表格`2019-06-23`。 具体来说，如果一本书在这段时间内售出**少于 10 册**，则该书不受欢迎。`2018-06-23`到`2019-06-23`。 此外，我们必须排除之前**不到一个月**发售的书籍。`2019-06-23`。 

输入由两个表组成。 这`Books`表包含`book_id`,`name`，以及该书可用的日期（`available_from`）。 这`Orders`表包含`order_id`,`book_id`（作为外键），`quantity`每个订单的，以及`dispatch_date`。 输出是一个表格`book_id`和`name`所有符合上述条件的书籍。 

关键边缘情况包括从未售出的书籍、仅售出 10 册的书籍、上市时间不到一个月的书籍以及订单超出一年窗口的书籍。 该问题保证了`book_id`是独一无二的`Books`还有那个`book_id`在`Orders`参考`Books`，所以我们不必处理丢失的引用。 

## 方法

 蛮力方法将涉及通过迭代去年的所有订单来计算每本书的销量，并对`quantity`，然后过滤掉销量低于 10 的书籍。我们还必须检查`available_from`每本书的日期。 这可以正常工作，但效率低下，因为它单独处理所有订单并分多个步骤执行过滤。 

最佳方法是使用 SQL 聚合和过滤。 我们首先过滤`Books`表排除一个月前可用的书籍。 然后，我们加入它`Orders`使用左连接来处理零阶书籍。 我们汇总了每本书去年的销售额，并使用`HAVING`子句来选择总销量低于 10 的书籍。这种方法利用 SQL 的基于集合的操作，减少冗余扫描并提供单一查询解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(B * O) | O(B) | 迭代每本书以及相关订单的总数量； 对于大表来说很慢|
 | 最佳 | O(B + O) | O(B) | 使用 LEFT JOIN 和 GROUP BY 在单个查询中聚合销售额； 对大型数据集高效 |

 ## 算法演练

 1. **按可用性过滤书籍**：排除任何其`available_from`晚于参考日期前一个月`2019-06-23`。 这确保我们只考虑已经上市足够长的书籍来积累有意义的销售数据。 
2. **过滤去年订单**：限制`Orders`给那些有`dispatch_date`参考日期之前一年内，即`2018-06-23`到`2019-06-23`。 这确保我们只计算最近的销售额。 
3. **将书籍与相关订单连接**：对过滤后的书籍进行左连接`Books`带过滤的`Orders`包括去年销量可能为零的书籍。 
4. **每本书的总销量**：使用`SUM(quantity)`分组依据`book_id`计算去年每本书的总销量。 如果一本书没有订单，则将其总销量视为零。 
5. **过滤不受欢迎的书籍**：使用`HAVING`选择总销量小于10的书籍。 
6. **选择结果列**：返回`book_id`和`name`已过滤的书籍。 

**为什么有效**：该方法确保所有条件仅应用一次。 因太新而被排除的书籍永远不会进入联接。 使用左连接聚合可确保包含零订单的书籍。 过滤`SUM(quantity) < 10`正确识别不受欢迎的书籍。 

## Python 解决方案```python
import sqlite3

def unpopular_books(conn: sqlite3.Connection):
    query = """
    WITH FilteredBooks AS (
        SELECT book_id, name
        FROM Books
        WHERE available_from <= date('2019-06-23', '-1 month')
    ),
    LastYearOrders AS (
        SELECT book_id, SUM(quantity) AS total_sold
        FROM Orders
        WHERE dispatch_date BETWEEN date('2019-06-23', '-1 year') AND '2019-06-23'
        GROUP BY book_id
    )
    SELECT fb.book_id, fb.name
    FROM FilteredBooks fb
    LEFT JOIN LastYearOrders lyo ON fb.book_id = lyo.book_id
    WHERE COALESCE(lyo.total_sold, 0) < 10
    """
    cursor = conn.cursor()
    cursor.execute(query)
    return cursor.fetchall()
```**解释**：`FilteredBooks`CTE 删除了可用时间少于 1 个月的书籍。 这`LastYearOrders`CTE 汇总了去年的订单。 左连接可确保包含所有书籍，即使销量为零。`COALESCE`处理没有订单的图书的空值，将其视为零销量。 这`WHERE`条款过滤销售量少于 10 册的书籍。 

## 解决方案```go
package main

import (
    "database/sql"
)

func UnpopularBooks(db *sql.DB) (*sql.Rows, error) {
    query := `
    WITH FilteredBooks AS (
        SELECT book_id, name
        FROM Books
        WHERE available_from <= date('2019-06-23', '-1 month')
    ),
    LastYearOrders AS (
        SELECT book_id, SUM(quantity) AS total_sold
        FROM Orders
        WHERE dispatch_date BETWEEN date('2019-06-23', '-1 year') AND '2019-06-23'
        GROUP BY book_id
    )
    SELECT fb.book_id, fb.name
    FROM FilteredBooks fb
    LEFT JOIN LastYearOrders lyo ON fb.book_id = lyo.book_id
    WHERE COALESCE(lyo.total_sold, 0) < 10
    `
    return db.Query(query)
}
```**Go 特定注释**：主要区别在于使用`*sql.Rows`用于返回结果。 我们依靠数据库来计算聚合和连接。 Go 不需要在查询级别显式处理 null，因为`COALESCE`处理它。
