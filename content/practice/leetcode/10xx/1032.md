[LeetCode 1032 题](https://leetcode.com/problems/stream-of-characters/)

 **难度：** 🔴难
 **主题：** 数组、字符串、设计、Trie、数据流

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种数据结构，一次处理一个字符流。 在每个新添加的字符之后，我们必须确定流的任何后缀是否与预定义字典中的单词之一匹配。 

后缀表示流的结束部分。 例如，如果流是`"axyz"`，那么它的后缀是：

 -`"z"`-`"yz"`-`"xyz"`-`"axyz"`如果我们的字典包含`"xyz"`，然后在收到最终的`'z'`，查询应该返回`true`。 

重要的细节是我们没有检查整个流是否与某个单词匹配。 我们只关心流是否以有效的字典单词结尾。 

输入包括：

 - 一个数组`words`，包含所有有效单词
 - 一系列`query(letter)`调用，每次向流中添加一个字符

 对于每个查询，我们返回：

 -`true`如果当前流中至少存在一个后缀`words`-`false`否则

 约束足够大，以至于简单的解决方案变得低效：

 - 最多 2000 字
 - 每个单词的长度最多为 200
 - 多达 40,000 条查询

 对照当前流重复检查每个单词的简单实现会执行太多重复工作。 

一个极其重要的观察结果是最大单词长度仅为 200。这意味着任何长度超过 200 个字符的后缀永远无法匹配单词。 这使我们能够限制保留多少流历史记录。 

一些边缘情况很重要：

 - 单字词，例如`"f"`必须紧跟在相应的查询之后匹配。 
- 多个单词可以共享后缀或前缀。 
- 流可能会变得非常长，但只有最近的 200 个字符才重要。 
- 单词可以在匹配模式中重叠。 
- 查询可以产生`true`连续多次使用不同的后缀。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将完整流维护为字符串。 每次查询后，我们都会迭代中的每个单词`words`并检查流是否以该单词结尾。 

例如：```
words = ["cd", "f", "kl"]
stream = "abcd"
```我们会测试：

 - 确实`"abcd"`结束于`"cd"`？ 
- 做`"abcd"`结束于`"f"`？ 
- 做`"abcd"`结束于`"kl"`？ 

如果任何检查成功，我们返回`true`。 

这种方法是正确的，因为它根据当前流后缀显式检查每个可能的字典单词。 

然而，它太慢了。 

假设：

 - 2000字
 - 每个单词长度最多200
 - 40,000 次查询

 在最坏的情况下，每个查询可能会与所有单词进行比较，大致产生：```
40,000 × 2,000 × 200
```这变得太昂贵了。 

### 最佳解决方案的关键见解

 关键的观察是我们只关心流的后缀。 

通常，尝试是向前构建的以支持前缀匹配。 这里我们需要后缀匹配，所以我们反转思路：

 - 在插入 trie 之前反转每个单词
 - 查询期间向后遍历流

 例如：```
word = "cd"
reversed = "dc"
```如果流变成：```
"...cd"
```然后从最新的字符向后遍历给出：```
d -> c
```它与反向特里树路径匹配。 

这将后缀问题转化为 trie 内部的前缀遍历问题。 

特里树允许我们在路径不再存在时提前停止，避免不必要的比较。 

我们也只需要保留最新的`maxWordLength`流中的字符，因为较长的后缀无法匹配任何内容。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(Q × 宽 × 长) | O(S)| 每次查询后根据流检查每个单词 |
 | 最优 Trie 解决方案 | O(Q × L) | O(总单词字符数 + L) | 使用反向特里树和有界流历史记录 |

 在哪里：

-`Q`= 查询数
 -`W`= 字数
 -`L`= 最大字长
 -`S`= 总流长度

 ## 算法演练

 ### 1. 构建一个反向特里树

 我们创建一个字典树，其中每个单词都以相反的顺序插入。 

例如：```
"cd" -> "d" -> "c"
"kl" -> "l" -> "k"
```每个 trie 节点存储：

 - 子指针
 - 一个布尔值，指示完整的单词是否在此结束

 反转单词至关重要，因为我们希望有效地匹配流后缀。 

### 2. 跟踪最大字长

 在插入单词时，我们计算：```
max_word_length
```这告诉我们可能重要的最长后缀。 

任何早于此限制的字符都可以安全地丢弃。 

### 3. 维护直播

 对于每个查询：

 - 将新字符附加到流中
 - 如果流超过`max_word_length`, 删除最旧的字符

 这使内存受到限制。 

### 4. 向后遍历流

 添加字符后，我们从 trie 根开始，以相反的顺序扫描流。 

例如：```
stream = "abcd"
```我们检查：```
d -> c -> b -> a
```每一步：

 - 如果当前字符不存在于trie中，则立即停止并返回`false`- 否则深入到 trie 中
 - 如果我们到达标记为单词结尾的节点，则返回`true`### 5. 返回结果

 如果遍历结束后没有找到完整的单词，则返回`false`。 

### 为什么它有效

 特里树包含反转形式的每个字典单词。 向后遍历流意味着我们可以同时有效地检查每个可能的后缀。 

每当遍历到标记为完整单词的节点时，就意味着流中存在相应的后缀。 

因为 trie 只遵循有效的字典路径，所以避免了不必要的比较。 

## Python 解决方案```python
from typing import List
from collections import deque

class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

class StreamChecker:

    def __init__(self, words: List[str]):
        self.root = TrieNode()
        self.stream = deque()
        self.max_length = 0

        for word in words:
            self.max_length = max(self.max_length, len(word))

            node = self.root

            for char in reversed(word):
                if char not in node.children:
                    node.children[char] = TrieNode()

                node = node.children[char]

            node.is_word = True

    def query(self, letter: str) -> bool:
        self.stream.append(letter)

        if len(self.stream) > self.max_length:
            self.stream.popleft()

        node = self.root

        for char in reversed(self.stream):
            if char not in node.children:
                return False

            node = node.children[char]

            if node.is_word:
                return True

        return False

# Your StreamChecker object will be instantiated and called as such:
# obj = StreamChecker(words)
# param_1 = obj.query(letter)
```该实现从包含子字典的 trie 节点类和指示单词是否在该节点终止的布尔标志开始。 

在初始化期间，每个单词都以相反的顺序插入。 反转单词可以在查询期间实现高效的后缀检查。 

流本身是使用`deque`，允许在末端高效插入并从前面移除。 

这`query`方法附加新字符，必要时修剪流，然后在遍历 trie 的同时向后遍历流。 

如果遍历到达一个trie节点标记为`is_word`，我们立即返回`True`因为已找到后缀匹配。 

如果遍历遇到缺失的 trie 边，我们可以提前停止，因为不再有后缀可以匹配。 

## 解决方案```go
package main

type TrieNode struct {
	children [26]*TrieNode
	isWord   bool
}

type StreamChecker struct {
	root      *TrieNode
	stream    []byte
	maxLength int
}

func Constructor(words []string) StreamChecker {
	root := &TrieNode{}
	maxLength := 0

	for _, word := range words {
		if len(word) > maxLength {
			maxLength = len(word)
		}

		node := root

		for i := len(word) - 1; i >= 0; i-- {
			index := word[i] - 'a'

			if node.children[index] == nil {
				node.children[index] = &TrieNode{}
			}

			node = node.children[index]
		}

		node.isWord = true
	}

	return StreamChecker{
		root:      root,
		stream:    []byte{},
		maxLength: maxLength,
	}
}

func (this *StreamChecker) Query(letter byte) bool {
	this.stream = append(this.stream, letter)

	if len(this.stream) > this.maxLength {
		this.stream = this.stream[1:]
	}

	node := this.root

	for i := len(this.stream) - 1; i >= 0; i-- {
		index := this.stream[i] - 'a'

		if node.children[index] == nil {
			return false
		}

		node = node.children[index]

		if node.isWord {
			return true
		}
	}

	return false
}

/**
 * Your StreamChecker object will be instantiated and called as such:
 * obj := Constructor(words);
 * param_1 := obj.Query(letter);
 */
```Go 实现遵循与 Python 版本相同的算法结构，但对 trie 子节点使用长度为 26 的固定大小数组，而不是哈希映射。 这提高了性能，因为字母表仅包含小写英文字母。 

该流被维护为字节片。 当流超过最大相关长度时，最旧的字符将通过切片删除。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有值都保持在标准整数限制内。

 ## 边缘情况

 当字典包含单字符单词时，就会出现一种重要的边缘情况。 有缺陷的实现可能只检查较长的后缀或延迟验证，直到存在多个字符。 在此解决方案中，每个查询都会立即检查第一个遍历的 trie 节点是否被标记为单词结尾，因此单字符匹配可以正常工作。 

另一个棘手的情况是极长的流。 由于可能会发生多达 40,000 个查询，因此无限期地存储整个流会浪费内存并减慢遍历速度。 该实现通过仅保留最后一个来避免这种情况`max_word_length`人物。 任何较旧的字符都无法构成有效的后缀匹配。 

重叠的单词是错误的另一个常见来源。 考虑这样的词`"a"`,`"ab"`， 和`"abc"`。 天真的遍历可能会过早停止，或者在遍历较长的有效匹配时无法识别较短的有效匹配。 此实施检查`is_word`遍历期间在每个 trie 节点处，确保正确检测到所有有效后缀。 

当遍历部分匹配 trie 路径但随后失败时，会发生最后一个微妙的情况。 例如，如果 trie 包含`"abcd"`流结束于`"abce"`，遍历成功几个字符后失败`'e'`。 执行立即返回`false`一旦 trie 边丢失，可以防止不必要的工作，同时保持正确性。
