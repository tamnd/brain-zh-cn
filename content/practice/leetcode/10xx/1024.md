 **难度：** 🟡 中等
 **主题：** 数组、动态规划、贪心

 ## 解决方案

 ## 问题理解

 问题要求我们报道一场持续的体育赛事`time`使用一组视频剪辑几秒钟。 每个剪辑由其开始和结束时间定义，`[starti, endi]`，并且剪辑可以相互重叠或延伸。 我们可以自由地将剪辑切成更小的片段，这意味着如果剪辑覆盖`[0,7]`，我们可以使用`[0,1]`,`[1,3]`,`[3,7]`，或任何填补空白的细分。 

目标是确定覆盖整个间隔所需的**最小剪辑数量**`[0, time]`。 如果不可能覆盖整个区间，我们应该返回`-1`。 

输入约束是可控的（`clips.length <= 100`,`time <= 100`），这使我们能够考虑 O(n²) 或 O(n*maxTime) 的解决方案，而不会出现性能问题。 重要的边缘情况包括不从 0 开始的剪辑、剪辑之间的间隙、重叠剪辑以及完全覆盖或超出所需间隔的剪辑。 

该问题保证每个剪辑都有`0 <= starti <= endi <= 100`和`time <= 100`，因此我们没有负时间或过大的输入，从而简化了范围的处理。 

## 方法

 ### 蛮力

 一种天真的暴力方法会尝试尝试每种剪辑组合来覆盖`[0, time]`。 我们可以从 0 开始递归选择剪辑，跟踪它们覆盖的片段，并尝试每个可能的序列来覆盖该间隔。 这保证了正确性，因为我们探索所有组合，但时间复杂度是指数级的（`O(2^n)`），使其不切实际`n = 100`。 

### 最佳方法

 关键的见解是认识到这类似于**跳跃游戏**问题。 我们希望迭代地选择覆盖范围最远的剪辑。 如果我们按开始时间对剪辑进行排序，我们可以贪婪地选择在当前覆盖范围之前或之后开始的剪辑，并尽可能地延长结尾。 每个选择都代表向解决方案添加一个剪辑。 

这种贪婪的方法之所以有效，是因为在每一步我们总是最大化覆盖范围，从而最大限度地减少剪辑数量。 不需要动态编程，因为贪婪选择保证了最少的剪辑数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试所有组合以覆盖`[0, time]`|
 | 贪婪/最优| O(n + 时间) | O(时间) | 使用数组`maxEnd`要跟踪从每个起点开始的最远距离，请线性迭代以计算剪辑 |

 ## 算法演练

 1. 创建数组`maxEnd`尺寸的`time + 1`初始化为 0。这将存储每秒`t`，从 或之前开始的任何剪辑可以到达的最远末端`t`。 
2. 迭代每个剪辑`[start, end]`并更新`maxEnd[start] = max(maxEnd[start], end)`。 这确保了从给定的开始时间开始，我们知道可以延伸多远。 
3.初始化三个变量：`clipsUsed = 0`,`currentEnd = 0`， 和`nextEnd = 0`。`currentEnd`表示当前剪辑数量的覆盖结束，`nextEnd`是下一个剪辑可到达的最远点。 
4. 迭代`i`从 0 到`time - 1`。 对于每一秒`i`：

- 更新`nextEnd = max(nextEnd, maxEnd[i])`。 
- 如果`i`达到`currentEnd`，这意味着我们需要添加一个新的剪辑来继续覆盖：

 - 增量`clipsUsed`。 
- 放`currentEnd = nextEnd`。 
- 如果`i`超过`nextEnd`在任何时候，返回`-1`因为覆盖是不可能的。 
5. 迭代结束后，`clipsUsed`包含所需的最少剪辑数量。 

**为什么它有效**

 在每一步中，我们都会选择能够最大程度扩展覆盖范围的剪辑（或重叠剪辑的组合）。 这种贪婪的选择保证了没有任何解决方案可以使用更少的剪辑来达到相同的覆盖范围。 如果在任何时候都不可能进行下一次延期，则不可能报道该赛事。 

## Python 解决方案```python
from typing import List

class Solution:
    def videoStitching(self, clips: List[List[int]], time: int) -> int:
        maxEnd = [0] * (time + 1)
        for start, end in clips:
            if start <= time:
                maxEnd[start] = max(maxEnd[start], min(end, time))
        
        clipsUsed = 0
        currentEnd = 0
        nextEnd = 0
        
        for i in range(time):
            nextEnd = max(nextEnd, maxEnd[i])
            if i == currentEnd:
                if nextEnd == currentEnd:
                    return -1
                clipsUsed += 1
                currentEnd = nextEnd
        
        return clipsUsed
```**解释**

 我们首先将剪辑预处理为`maxEnd`了解每次出发的最远距离。 该循环迭代目标间隔的每一秒。 如果我们到达当前覆盖范围的末尾，我们将添加一个剪辑以将覆盖范围扩展到`nextEnd`。 如果在任何时候我们无法进一步延长（`nextEnd == currentEnd`），我们返回`-1`。 

## 解决方案```go
func videoStitching(clips [][]int, time int) int {
    maxEnd := make([]int, time+1)
    for _, clip := range clips {
        start, end := clip[0], clip[1]
        if start <= time {
            if end > time {
                end = time
            }
            if end > maxEnd[start] {
                maxEnd[start] = end
            }
        }
    }

    clipsUsed := 0
    currentEnd := 0
    nextEnd := 0

    for i := 0; i < time; i++ {
        if maxEnd[i] > nextEnd {
            nextEnd = maxEnd[i]
        }
        if i == currentEnd {
            if nextEnd == currentEnd {
                return -1
            }
            clipsUsed++
            currentEnd = nextEnd
        }
    }

    return clipsUsed
}
```**解释**

 Go 实现反映了 Python 逻辑。 我们使用切片`maxEnd`。 更新中`nextEnd`并计数`clipsUsed`工作原理相同。 Go 需要显式处理切片索引，但不会产生额外的复杂性。
