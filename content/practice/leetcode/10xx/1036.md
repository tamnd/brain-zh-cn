[LeetCode 1036 题](https://leetcode.com/problems/escape-a-large-maze/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 这个问题给我们带来了巨大的`1,000,000 x 1,000,000`网格。 每个单元格由坐标标识`(x, y)`，并且允许在四个方向上移动：上、下、左、右。 有些细胞被封锁了，这意味着我们无法踩到它们。 

我们得到三个输入：

 -`blocked`，阻塞坐标列表
 -`source`，起始坐标
 -`target`, 目的地坐标

 目标是确定是否存在任何有效路径`source`到`target`无需走出网格或进入阻塞的单元格。 

乍一看，这看起来像一个标准的图遍历问题，其中每个单元格都是一个节点，相邻单元格通过边连接。 通常，广度优先搜索或深度优先搜索可以轻松解决这个问题。 

然而，这些约束从根本上改变了问题：

 - 网格最多包含`10^12`细胞
 -`blocked.length <= 200`网格之大堪称天文数字，不可能穿越整个空间。 网格上的天真的 BFS 永远不会在时间或内存中完成。 

重要的观察是，尽管网格很大，但被阻挡的单元数量却极少。 最多有200个封锁单元，封锁区域只能包围有限的区域。 

一些边缘情况很重要：

 - 源头可能被阻塞的细胞完全困住
 - 目标可能被完全困住
 - 可能根本没有阻塞的细胞
 - 源和目标可能相距极远
 - 被堵塞的细胞可能会形成部分墙壁，看起来很危险，但实际上并没有包围任何东西

 该问题保证既不`source`也不`target`被阻止，并且它们是不同的坐标。 

## 方法

 ### 蛮力方法

 蛮力的想法很简单：

 - 启动 BFS 从`source`- 探索所有可到达的单元格
 - 返回`true`如果我们最终达到`target`- 返回`false`如果 BFS 穷尽所有可能性

 这是可行的，因为 BFS 只探索每个可达状态一次，从而保证正确性。 

不幸的是，这种方法完全不可行。 

网格包含`10^12`细胞。 即使路径很短，BFS 也可能需要探索网格的很大一部分。 单独使用内存将变得不可能。 

关键问题是搜索空间太大。 

### 关键见解

 关键的观察是最多只有`200`阻塞的细胞。 

少量的阻塞单元不能包围任意大的区域。 事实上，最大封闭面积是有界的。 

如果我们能够证明搜索逃离了源周围的潜在封闭区域，那么源就不会被捕获。 同样的逻辑也适用于目标。 

这就转化了问题：

 我们不需要搜索整个网格。 

我们只需要确定任一端点是否被阻塞单元包围。 

为了`n`被阻挡的单元格，最大封闭面积约为：$\frac{n(n-1)}{2}$和`n <= 200`，这个值最多是`19,900`。 

因此：

 - 如果 BFS 扩展超出此限制，我们就知道起点未包含在内
 - 如果源和目标均未封闭，则开放网格中它们之间必须存在路径

 这允许有界 BFS 快速终止。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(10^12) | O(10^12) | O(10^12) | O(10^12) | 尝试直接探索庞大的网格|
 | 最佳| O(B²) | O(B²) | 使用阻塞单元格的有界包围属性 |

 这里，`B = len(blocked)`。 

## 算法演练

 ### 步骤 1：将阻塞单元转换为哈希集

 我们将所有被阻止的坐标存储在哈希集中，以进行恒定时间查找。 

这很重要，因为在 BFS 期间我们需要不断检查相邻小区是否被阻塞。 

一个元组就像`(x, y)`用作密钥。 

### 步骤 2：计算最大可能的封闭面积

 如果有`n`被阻挡的细胞，它们可以完全包围的最大区域是：$\frac{n(n-1)}{2}$这个值就成为我们的 BFS 探索极限。 

如果 BFS 访问的单元数超过这么多，那么搜索就逃脱了任何可能的封闭范围。 

### 步骤 3：从源运行有界 BFS

 我们执行 BFS 开始于`source`。 

对于每个位置：

 1. 从队列中删除一个单元
 2.检查它的四个邻居
 3.忽略邻居：

 - 在网格之外
 - 被封锁
 - 已经被访问过
 4. 将有效邻居添加到队列中

 BFS 在两种情况下提前停止：

 - 我们直接到达目标
 - 我们访问的牢房数量超出了围栏限制

 如果超过限制，我们就知道源头没有被困住。 

### 步骤 4：从目标运行有界 BFS

 我们从以下位置开始重复相同的过程`target`。 

这一步是必要的，因为：

 - 来源可能未附上
 - 但目标仍然可以被包围

 两个端点都必须能够脱离其本地区域。 

### 步骤 5：合并结果

 最终的答案是：

 -`true`如果两次搜索都成功
 -`false`否则

 如果满足以下条件，则搜索成功：

 - 它到达另一个端点
 - 或者它超出了最大封闭边界

 ### 为什么它有效

 正确性依赖于几何属性：

 由于最多有 200 个被阻挡的单元，它们可以完全包围的区域有严格的上限。 

如果 BFS 扩展超出该界限，则搜索必定已逃离任何可能的受困区域。 

由于封闭区域之外的无限开放区域是相连的，如果源和目标都没有被捕获，则它们之间一定存在路径。 

## Python 解决方案```python
from collections import deque
from typing import List, Set, Tuple

class Solution:
    def isEscapePossible(
        self,
        blocked: List[List[int]],
        source: List[int],
        target: List[int]
    ) -> bool:

        BLOCK_LIMIT = len(blocked) * (len(blocked) - 1) // 2
        GRID_SIZE = 10**6

        blocked_set: Set[Tuple[int, int]] = {
            (x, y) for x, y in blocked
        }

        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1)
        ]

        def bfs(start: List[int], finish: List[int]) -> bool:
            queue = deque()
            queue.append((start[0], start[1]))

            visited = set()
            visited.add((start[0], start[1]))

            while queue and len(visited) <= BLOCK_LIMIT:
                x, y = queue.popleft()

                if [x, y] == finish:
                    return True

                for dx, dy in directions:
                    nx = x + dx
                    ny = y + dy

                    if not (0 <= nx < GRID_SIZE and 0 <= ny < GRID_SIZE):
                        continue

                    if (nx, ny) in blocked_set:
                        continue

                    if (nx, ny) in visited:
                        continue

                    visited.add((nx, ny))
                    queue.append((nx, ny))

            return len(visited) > BLOCK_LIMIT

        return bfs(source, target) and bfs(target, source)
```该实现首先将被阻止的单元转换为一组以进行快速查找。 由于 BFS 会重复检查相邻小区是否被阻塞，因此恒定时间成员资格检查对于性能至关重要。 

变量`BLOCK_LIMIT`表示由阻挡单元形成的最大可能封闭区域。 该值决定了 BFS 何时可以安全地得出其已逃脱限制的结论。 

辅助函数`bfs`执行有界广度优先搜索。 它探索邻近的细胞，同时保持`visited`设置为防止重新访问状态。 

关键的优化出现在循环条件中：```python
while queue and len(visited) <= BLOCK_LIMIT:
```一旦访问的单元格数量超过包围限制，由于无法捕获起始点，因此搜索立即成功。 

该算法执行两次 BFS：

 - 从源到目标
 - 从目标到源

 这保证了两个端点都不被封闭。 

## 解决方案```go
package main

import "container/list"

func isEscapePossible(blocked [][]int, source []int, target []int) bool {
	blockLimit := len(blocked) * (len(blocked) - 1) / 2
	gridSize := 1000000

	blockedSet := make(map[[2]int]bool)

	for _, cell := range blocked {
		blockedSet[[2]int{cell[0], cell[1]}] = true
	}

	directions := [][2]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	bfs := func(start []int, finish []int) bool {
		queue := list.New()
		queue.PushBack([2]int{start[0], start[1]})

		visited := make(map[[2]int]bool)
		visited[[2]int{start[0], start[1]}] = true

		for queue.Len() > 0 && len(visited) <= blockLimit {
			front := queue.Front()
			queue.Remove(front)

			cell := front.Value.([2]int)
			x, y := cell[0], cell[1]

			if x == finish[0] && y == finish[1] {
				return true
			}

			for _, d := range directions {
				nx := x + d[0]
				ny := y + d[1]

				if nx < 0 || nx >= gridSize || ny < 0 || ny >= gridSize {
					continue
				}

				next := [2]int{nx, ny}

				if blockedSet[next] {
					continue
				}

				if visited[next] {
					continue
				}

				visited[next] = true
				queue.PushBack(next)
			}
		}

		return len(visited) > blockLimit
	}

	return bfs(source, target) && bfs(target, source)
}
```Go 实现遵循与 Python 版本相同的逻辑，但有一些特定于语言的细节。 

Go 没有内置的元组哈希，因此固定大小的数组如`[2]int`用作哈希映射键。 

BFS队列的实现使用`container/list`，因为 Go 切片对于重复的前面删除效率很低。 

访问集和阻塞集都被实现为映射`[2]int`到`bool`。 

整数溢出不是问题，因为所有计算都保持在 Go 的整数范围内。

 ## 边缘情况

 ### 源头被困在边界处

 当源靠近网格边缘并且被阻挡的单元覆盖唯一有效的出口时，会发生特别棘手的情况。 

例如：```
source = [0,0]
blocked = [[0,1],[1,0]]
```粗心的实现可能会假设总是有四个相邻的移动可用。 然而，两个方向都是无效的，因为它们离开了网格。 

该实现在探索邻居之前正确检查边界条件：```
0 <= nx < GRID_SIZE and 0 <= ny < GRID_SIZE
```这可以防止无效位置进入 BFS 队列。 

### 目标完全封闭

 另一个微妙的问题是，源可能成功逃脱，而目标仍被困住。 

如果我们只从源头运行 BFS，我们可能会错误地得出逃逸是可能的结论。 

例如：```
source = open area
target = enclosed pocket
```该解决方案通过从两个端点运行有界 BFS 来避免此错误。 

只有当两次搜索都确认逃脱时我们才会返回`true`。 

### 没有阻塞的单元格

 当`blocked`为空时，封闭限制变为零。 

幼稚的实现可能会在不探索任何内容的情况下意外地立即终止。 

该算法自然地处理这个问题：

 - 起始单元格本身算作已访问
 -`len(visited) > 0`- 因此 BFS 立即证明起点未封闭

 这正确返回`true`对于开放网格中的任意两个不同的坐标。
