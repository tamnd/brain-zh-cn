[LeetCode 问题 1065](https://leetcode.com/problems/index-pairs-of-a-string/)

 **难度：** 🟢简单
 **主题：** 数组、字符串、Trie、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`text`和一个字典单词列表`words`。 我们必须找到里面的每个子串`text`that exactly matches one of the words in the dictionary.

 对于每个有效的匹配，我们返回该对`[i, j]`， 在哪里：

-`i`是子字符串的起始索引
 -`j`是子字符串的结束索引，包括在内

 The output must contain all matching index pairs, sorted first by the starting index and then by the ending index.

 例如，如果：```
text = "ababa"
words = ["aba", "ab"]
```然后：

-`"ab"`从索引中出现`0`到`1`-`"aba"`从索引中出现`0`到`2`-`"ab"`从索引中再次出现`2`到`3`-`"aba"`从索引中再次出现`2`到`4`所以答案就变成了：```
[[0,1],[0,2],[2,3],[2,4]]
```一个重要的细节是允许重叠匹配。 子串位于`[0,2]`和子串`[2,4]`都使用索引`2`，并且两者都必须包括在内。 

限制相当小：

 -`text.length <= 100`-`words.length <= 20`-`words[i].length <= 50`这些限制告诉我们，即使效率较低的解决方案也是可以接受的。 我们不需要后缀自动机或 Aho-Corasick 等非常先进的优化技术。 干净的基于 Trie 的解决方案或直接匹配解决方案将在限制范围内舒适地工作。 

有几种边缘情况值得尽早识别：

 - 多个匹配可以从同一索引开始。 
- 比赛可能会重叠。 
- 有些词可能永远不会出现在文本中。 
- 单字符词有效。 
- 整个文本本身可能是一个有效的单词。 
- 不同的单词可能共享前缀，这使得 Trie 结构特别有用。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子字符串`text`。 

对于每个起始索引`i`，我们可以尝试每个结束索引`j`,提取子串`text[i:j+1]`，并检查字典中是否存在。 

为了提高查找效率，我们将所有单词放入哈希集中。 

该算法之所以有效，是因为每个可能的子字符串都被检查一次。 如果一个子串属于`words`，我们记录它的指数。 

然而，这种方法会重复创建子字符串，效率较低。 尽管约束足够小，可以通过，但它会做不必要的工作，因为许多子字符串不可能与任何字典单词匹配。 

### 最优方法，基于 Trie 的搜索

 更好的解决方案是使用 Trie。 

Trie 很有用，因为许多单词可能共享前缀。 我们不是独立生成每个子字符串，而是从每个索引开始`text`并逐个字符地遍历 Trie。 

每一步：

 - 如果当前字符不存在于 Trie 中，我们立即停止。 
- 如果我们到达一个标记为完整单词的 Trie 节点，我们会记录一个有效的索引对。 

这可以避免探索不可能与任何单词匹配的子字符串。 

关键的见解是 Trie 允许我们逐步验证前缀，而不是重复构建完整的子字符串。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(米) | 检查每个子字符串并重复创建子字符串对象 |
 | 最佳| O(n × L) | O(单词总数) | Trie 可以在匹配过程中提前停止 |

 在哪里：

-`n`的长度是`text`-`L`是最大字长
 -`m`是单词数

 ## 算法演练

 ### 特里结构

 我们首先根据字典中的所有单词构建一个 Trie。 

每个 Trie 节点包含：

 - 儿童角色地图
 - 一个布尔标志，指示路径是否形成完整的单词

 例如，如果单词是：```
["ab", "aba"]
```然后 Trie 存储：```
a -> b (word)
       -> a (word)
```### 搜索过程

 我们现在迭代每个起始位置`text`。 

### 逐步算法

 1. 创建一个空的Trie根节点。 
2. 将每个单词插入 Trie 树中。 

对于每个字符：

 - 如果子节点不存在，则创建它。 
- 移动到子节点。 

在最后一个字符之后，将节点标记为完整的单词。 
3. 初始化一个空的结果列表。 
4. 对于每个起始索引`start`在`text`:

 - 从 Trie 根开始遍历。 
- 逐个字符地向前移动`text`。 
5. 对于每个结束索引`end`开始于`start`:

 - 检查是否`text[end]`作为一个子元素存在于 Trie 树中。 
- 如果不存在，则停止从此起始索引开始搜索，因为不再有子字符串可以匹配。 
- 否则，移动到相应的子节点。 
6. 如果当前 Trie 节点标记单词的结尾：

 - 添加`[start, end]`到结果列表。 
7. 继续，直到处理完所有起始位置。 
8. 返回结果列表。 

### 为什么它有效

 Trie 保证每次遍历都对应于至少一个字典单词的有效前缀。 每当我们到达标记为完整单词的节点时，来自的子字符串`start`到`end`与字典中的单词完全匹配。 

因为我们从每个起始索引开始遍历`text`，考虑每个可能的有效子字符串。 由于当前缀无效时遍历会立即停止，因此不会探索不必要的子字符串。 

因此，该算法仅按排序顺序返回所有有效索引对一次。 

## Python 解决方案```python
from typing import List

class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

class Solution:
    def indexPairs(self, text: str, words: List[str]) -> List[List[int]]:
        root = TrieNode()

        # Build Trie
        for word in words:
            node = root

            for char in word:
                if char not in node.children:
                    node.children[char] = TrieNode()

                node = node.children[char]

            node.is_word = True

        result = []

        # Search from every starting index
        for start in range(len(text)):
            node = root

            for end in range(start, len(text)):
                char = text[end]

                if char not in node.children:
                    break

                node = node.children[char]

                if node.is_word:
                    result.append([start, end])

        return result
```实现首先定义一个`TrieNode`班级。 每个节点存储：

 -`children`，将字符映射到子节点的字典
 -`is_word`，表示当前路径是否构成一个完整的单词

 Trie 是通过逐个字符插入每个单词来构建的。 共享前缀自动重用现有节点。 

构造完成后，算法从每个可能的起始索引中进行搜索`text`。 

对于每个起始索引：

 - 从 Trie 根开始遍历。 
- 角色一次被消耗一个。 
- 如果 Trie 中不存在下一个字符，则遍历立即停止。 
- 如果当前节点代表一个完整的单词，则将相应的索引对添加到答案中。 

由于外循环按升序处理起始索引，内循环按升序处理结束索引，因此输出自然会根据需要进行排序。 

## 解决方案```go
package main

type TrieNode struct {
	children map[byte]*TrieNode
	isWord   bool
}

func newTrieNode() *TrieNode {
	return &TrieNode{
		children: make(map[byte]*TrieNode),
	}
}

func indexPairs(text string, words []string) [][]int {
	root := newTrieNode()

	// Build Trie
	for _, word := range words {
		node := root

		for i := 0; i < len(word); i++ {
			char := word[i]

			if _, exists := node.children[char]; !exists {
				node.children[char] = newTrieNode()
			}

			node = node.children[char]
		}

		node.isWord = true
	}

	result := [][]int{}

	// Search from every starting index
	for start := 0; start < len(text); start++ {
		node := root

		for end := start; end < len(text); end++ {
			char := text[end]

			nextNode, exists := node.children[char]

			if !exists {
				break
			}

			node = nextNode

			if node.isWord {
				result = append(result, []int{start, end})
			}
		}
	}

	return result
}
```Go 的实现紧密遵循 Python 版本。 

Trie 使用：

 -`map[byte]*TrieNode`对于子指针
 - 一个布尔值`isWord`领域

 由于输入仅包含小写英文字母，因此使用`byte`是充足且高效的。 

结果存储为整数切片的切片，`[][]int`。 

Go 切片自然会在追加操作期间处理动态调整大小，因此不需要特殊的内存管理。

 ## 边缘情况

 ### 重叠匹配

 最重要的边缘情况之一是重叠子字符串。 

例如：```
text = "ababa"
words = ["aba"]
```这个词`"aba"`出现在两个`[0,2]`和`[2,4]`。 

有错误的实现可能会在找到第一个出现后跳过第二个出现。 我们的算法避免了这个问题，因为它独立地从文本中的每个索引开始 Trie 遍历。 

### 共享前缀

 单词可能共享长前缀：```
words = ["ab", "abc", "abcd"]
```幼稚的实现可能会重复地重新处理相同的前缀字符。 

Trie 自然地处理这个问题，因为所有单词共享相同的前缀路径。 遍历时，每个节点可以同时表示：

 - 中间前缀
 - 一个完整的单词
 - 较长单词的开头

 这样可以有效地发现所有匹配项。 

### 早期不匹配终止

 考虑：```
text = "xyzabc"
words = ["abc"]
```在指数上`0`,`1`， 和`2`，遍历立即失败，因为这些字符在 Trie 根中不存在。 

如果不提前终止，实现可能会继续检查不必要的子字符串。 一旦前缀无效，基于 Trie 的方法就会立即停止，从而保持算法的效率。
