[LeetCode 问题 1015](https://leetcode.com/problems/smallest-integer-divisible-by-k/)

 **难度：** 🟡 中等
 **主题：** 哈希表、数学

 ## 解决方案

 ## 问题理解

 该问题要求我们找到满足两个条件的最小正整数的长度：

 1. 整数只包含数字`1`2. 整数可以被整除`k`此类数字通常称为重新单位。 示例包括：

 -`1`-`11`-`111`-`1111`关键细节是我们不需要返回数字本身。 我们只返回它的长度。 

例如，如果`k = 3`，可被整除的最小重单位`3`是`111`，所以答案是`3`。 

约束条件是`n`可能不适合 64 位有符号整数，这一点极其重要。 它告诉我们，我们实际上无法直接构造这些巨大的整数。 即使对于中等值`k`，回报可能会变得天文数字般巨大。 

输入由单个整数组成`k`， 在哪里：```
1 <= k <= 10^5
```这意味着算法必须足够高效才能处理高达十万的值。 

还有一些重要的数学边缘情况。 任何完全由`1`s 总是以数字结尾`1`，所以它永远不能被整除`2`或者`5`。 因此：

 - 如果`k`可以整除`2`，不存在解
 - 如果`k`可以整除`5`，不存在解

 这些案件必须立即返回`-1`。 

另一个重要的观察结果是，只有`k`除以时可能的余数`k`。 这一事实成为最优解决方案的基础。 

## 方法

 ### 蛮力方法

 蛮力方法反复构造重聚：```
1
11
111
1111
...
```在每一步中，我们都会检查当前数字是否可以被整除`k`。 

例如：```
current = 1
current = 11
current = 111
current = 1111
```这种方法是正确的，因为最终：

 - 我们发现一个reunit可被整除`k`- 或者数字永远增长但没有成功

 然而，这种方法很快就变得不切实际，因为数量变得巨大。 对于大输入来说，甚至存储整数也是不可能的。 在得出答案之前很久就会发生整数溢出。 

时间复杂度也很差，因为每个新数字都会变得更大并且操作成本更高。 

### 最佳方法

 关键的见解是我们永远不需要完整的数字本身。 我们只关心除以的余数`k`。 

假设我们已经知道：```
remainder = current_number % k
```当我们附加另一个数字时`1`，新的数字变为：```
new_number = current_number * 10 + 1
```所以：```
new_remainder = (remainder * 10 + 1) % k
```这使我们能够仅使用余数来模拟重新单位的增长，余数始终保持在范围内`[0, k-1]`。 

因为只有`k`distinct remainders, one of two things must happen:

 - 我们最终到达余数`0`，意思是整除性
 - 或者重复余数，形成一个循环

 如果在到达之前发生循环`0`，不存在解。 

由于最多有`k`唯一的余数，我们最多只需要`k`迭代。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) 或更糟 | O(n) | 直接构造巨大的整数 |
 | 最佳 | O(k) | O(1) | O(1) | 仅使用模算术和余数 |

 ## 算法演练

 ### 最优算法

 1.首先检查是否`k`可以整除`2`或者`5`。 

任何只包含数字的数字`1`总是以`1`，所以它永远不能被整除`2`或者`5`。 如果任一条件为真，则立即返回`-1`。 
2. 初始化一个名为`remainder`到`0`。 

该变量表示除以当前 reunit 后的余数`k`。 
3. 从长度迭代`1`最多`k`。 

我们最多只需要`k`迭代，因为只有`k`可能有不同的余数。 
4. 在每次迭代中，附加另一个数字`1`使用模运算。 

不构建实际数字，而是计算：```
remainder = (remainder * 10 + 1) % k
```这模拟添加一个新的`1`数字到当前重新单元的末尾。 
5. 更新余数后，检查是否等于`0`。 

如果余数变为`0`，当前的 reunit 可以被除以`k`，因此返回当前长度。 
6. 如果循环结束但未到达余数`0`， 返回`-1`。 

这意味着余数进入了一个循环并且不存在有效的重新分配。 

### 为什么它有效

 该算法之所以有效，是因为模运算保留了整除性。 步步，`remainder`完全匹配当前 reunit 除以的余数`k`。 

由于只有`k`可能的余数，该过程必须：

 - 达到余数`0`- 或者重复之前的余数

 重复余数意味着该过程进入了一个循环，并且将永远持续下去，永远不会到达`0`。 因此，如果没有出现任何解决方案`k`迭代，不存在解。 

## Python 解决方案```python
class Solution:
    def smallestRepunitDivByK(self, k: int) -> int:
        if k % 2 == 0 or k % 5 == 0:
            return -1

        remainder = 0

        for length in range(1, k + 1):
            remainder = (remainder * 10 + 1) % k

            if remainder == 0:
                return length

        return -1
```实现从数学不可能性检查开始：`2`或者`5`。 这可以避免对永远不会成功的情况进行不必要的计算。 

变量`remainder`存储当前 reunit 模数`k`。 最初，在添加任何数字之前，余数是`0`。 

循环运行自`1`通过`k`包容性，因为最多可以有`k`不同的余数。 

在循环内部，表达式：```python
remainder = (remainder * 10 + 1) % k
```模拟附加数字`1`到当前的重聚。 这是避免构造巨大整数的核心优化。 

每当余数变为`0`，当前的 reunit 可以被除以`k`，因此立即返回当前长度。 

如果循环结束而没有找到余数`0`，函数返回`-1`。 

## 解决方案```go
func smallestRepunitDivByK(k int) int {
    if k%2 == 0 || k%5 == 0 {
        return -1
    }

    remainder := 0

    for length := 1; length <= k; length++ {
        remainder = (remainder*10 + 1) % k

        if remainder == 0 {
            return length
        }
    }

    return -1
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 整数是固定宽度的，因此避免构建实际的 reunit 更为重要。 模算术使所有中间值保持安全界限。 

Go 在这里不需要对溢出进行特殊处理，因为：```go
(remainder*10 + 1)
```总是保持足够小，因为`remainder < k`和`k <= 10^5`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k`可以整除`2`。 任何重新单位总是以数字结尾`1`，这意味着它总是奇数。 幼稚的实现可能会永远继续搜索，但优化的解决方案会立即检测到这种情况并返回`-1`。 

另一个关键的边缘情况是`k`可以整除`5`。 能整除的数字`5`必须结束于`0`或者`5`，但重聚总是以`1`。 如果没有早期检查，算法就会浪费时间探索不可能的状态。 该实现通过返回正确地处理了这个问题`-1`立即地。 

第三个重要的边缘情况涉及大值`k`，特别是靠近`10^5`。 构造实际的重新单位整数会溢出标准数字类型或消耗过多的内存。 该实现通过仅存储余数来完全避免这种情况。 由于余数总是小于`k`，所有计算仍然高效且安全。 

另一个微妙的边缘情况是进入重复余数循环的可能性。 由于只有`k`可能的余数，重复一个意味着序列将永远循环而不会达到整除性。 该实现通过将循环限制为最多来隐式处理此问题`k`迭代。
