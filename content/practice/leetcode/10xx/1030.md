[LeetCode 1030 题](https://leetcode.com/problems/matrix-cells-in-distance-order/)

 **难度：** 🟢简单
 **主题：** 数组、数学、几何、排序、矩阵

 ## 解决方案

 ## 问题理解

 该问题要求我们返回矩阵中的每个单元格，并按其与给定中心单元格的曼哈顿距离排序。 

我们有四个整数：

 -`rows`，矩阵的行数
 -`cols`，矩阵中的列数
 -`rCenter`, 参考单元格的行索引
 -`cCenter`, 参考单元格的列索引

 矩阵维度为`rows x cols`，意味着有效的行索引范围为`0`到`rows - 1`，有效的列索引范围为`0`到`cols - 1`。 

对于每个细胞`(r, c)`在矩阵中，我们计算它与中心单元的距离`(rCenter, cCenter)`使用曼哈顿距离公式：$$|r - rCenter| + |c - cCenter|$$目标是返回从最小距离到最大距离排序的所有坐标。 如果多个单元具有相同的距离，则它们的相对顺序并不重要，因为该问题明确允许等距离单元之间的任何有效排序。 

例如，如果中心是`(0, 0)`在一个`1 x 2`矩阵，距离为：

 -`(0,0)`→`0`-`(0,1)`→`1`所以正确的顺序是`[[0,0],[0,1]]`。 

限制很小：

 -`1 <= rows, cols <= 100`- 至多`100 × 100 = 10,000`细胞存在

 这告诉我们，即使是`O(n log n)`排序解决方案是完全可以接受的，其中`n = rows × cols`。 自从`n ≤ 10,000`，排序仍然有效。 

有几种边缘情况值得预先考虑。 一个`1 x 1`矩阵只包含中心本身，所以答案很简单。 具有单行或单列的矩阵减少了一维的移动，这可能会暴露索引错误。 当许多单元与中心的距离相同时，会发生另一种微妙的情况。 由于等序不受限制，我们只需要保证非递减的距离顺序，而不是唯一的排列。 该问题还保证中心坐标始终有效，因此我们永远不需要输入中心的边界验证。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成矩阵中的每个单元格，计算其距中心的曼哈顿距离，然后根据该距离对所有单元格进行排序。 

我们迭代每个行和列的组合，生成坐标`(r, c)`。 对于每个坐标，我们计算：$$|r - rCenter| + |c - cCenter|$$然后我们根据这个值对所有单元格进行排序。 

这是有效的，因为排序保证了单元格按距离递增的顺序出现。 由于每个矩阵单元只包含一次，因此结果是完整且正确的。 

缺点是排序引入了`O(n log n)`时间成本，其中`n`是细胞的数量。 虽然这对于问题约束来说足够有效，但我们可以在概念上做得更好。 

### 最佳方法

 关键的见解是曼哈顿距离在中心周围形成不断扩大的菱形层。 

我们可以按距离对单元格进行存储，而不是显式排序。 网格中最大可能的曼哈顿距离是有限的：$$(rows - 1) + (cols - 1)$$我们可以遍历每个单元格一次，计算其距离，并将其放入与该距离相对应的存储桶中。 然后，我们从最小距离到最大距离连接桶。 

这完全避免了排序。 由于距离值是有界的，因此遍历桶是线性的。 

这个推理是有效的，因为曼哈顿距离是离散且有界的。 每个单元都属于一个距离级别，按升序迭代距离自然会产生所需的排序。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n log n)`|`O(n)`| 生成所有单元格并按曼哈顿距离排序 |
 | 最佳 |`O(n)`|`O(n)`| 按距离对单元格进行分组，然后按升序收集 |

 这里，`n = rows × cols`。 

## 算法演练

 我们将使用基于桶的最优解决方案。 

1. 计算矩阵中最大可能的曼哈顿距离。 

由于最远的单元格可以位于对角，因此最大距离为：`maxDistance = (rows - 1) + (cols - 1)`这告诉我们需要多少个桶。 
2. 为每个可能的距离创建桶。 

我们创建一个列表，其中每个索引对应于曼哈顿距离。 每个桶存储距离等于该索引的坐标。 
3. 遍历每个矩阵单元。 

对所有行和列索引使用嵌套循环：

 - 行自`0`到`rows - 1`- 专栏来自`0`到`cols - 1`这保证了每个矩阵单元都被访问一次。 
4. 计算每个像元的曼哈顿距离。 

对于一个细胞`(r, c)`:```
distance = abs(r - rCenter) + abs(c - cCenter)
```这决定了单元属于哪个存储桶。 
5. 将单元添加到正确的存储桶中。 

附加`[r, c]`到`buckets[distance]`。 

多个小区可以共享相同的距离，并且它们之间的任何顺序都是可以接受的。 
6. 构建最终答案。 

从最小距离到最大距离迭代存储桶，将所有存储的坐标附加到结果列表中。 
7. 返回结果。 

由于桶是按距离升序处理的，因此最终列表自动满足问题要求。 

### 为什么它有效

 该算法之所以有效，是因为每个像元到中心的曼哈顿距离正好是一个。 通过将每个单元格放入按其距离索引的桶中，我们将矩阵划分为距离层。 远程处理桶`0`up保证所有返回的单元格以非递减距离顺序出现。 由于每个单元格都只插入一次，然后又恰好收集一次，因此结果是完整且排序正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def allCellsDistOrder(
        self,
        rows: int,
        cols: int,
        rCenter: int,
        cCenter: int
    ) -> List[List[int]]:
        max_distance = (rows - 1) + (cols - 1)

        buckets = [[] for _ in range(max_distance + 1)]

        for row in range(rows):
            for col in range(cols):
                distance = abs(row - rCenter) + abs(col - cCenter)
                buckets[distance].append([row, col])

        result = []

        for bucket in buckets:
            result.extend(bucket)

        return result
```该实现首先计算矩阵中可能的最大曼哈顿距离。 这决定了所需的桶数。 

然后我们初始化`buckets`，其中索引`i`存储曼哈顿距离等于的所有单元格`i`。 

嵌套循环迭代每个矩阵坐标。 对于每个像元，曼哈顿距离是使用行和列位置的绝对差计算的。 电池立即被放入其匹配的桶中。 

将所有单元格分组后，我们通过按升序迭代存储桶并使用存储在每个存储桶内的所有坐标扩展结果列表来构建最终答案。 

该实现直接反映了算法演练。 不需要显式排序，因为桶索引已经代表排序的距离顺序。 

## 解决方案```go
func allCellsDistOrder(rows int, cols int, rCenter int, cCenter int) [][]int {
	maxDistance := (rows - 1) + (cols - 1)

	buckets := make([][][]int, maxDistance+1)

	for row := 0; row < rows; row++ {
		for col := 0; col < cols; col++ {
			distance := abs(row-rCenter) + abs(col-cCenter)
			buckets[distance] = append(
				buckets[distance],
				[]int{row, col},
			)
		}
	}

	result := make([][]int, 0, rows*cols)

	for _, bucket := range buckets {
		result = append(result, bucket...)
	}

	return result
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置整数`abs`函数，我们定义一个辅助函数。 

桶结构表示为`[][][]int`，其中每个桶存储一片坐标对。 结果切片已预先分配容量`rows * cols`，这避免了附加时不必要的重新分配。 

与 Python 列表不同，Go 切片受益于显式容量管理以提高性能。 由于约束很小，因此不必担心整数溢出。

 ## 边缘情况

 ### 单细胞矩阵

 一个`1 x 1`矩阵仅包含中心单元本身。 粗心的实施可能会意外地跳过中心或错误地处理存储桶大小。 我们的实现正确计算了最大距离`0`，创建一个存储桶，插入中心单元格，然后返回`[[0,0]]`。 

### 单行或单列

 当任一维度等于`1`，运动实际上变成一维的。 这可以揭示索引错误或行和列移动都存在的假设。 由于我们的实现只是迭代有效坐标并一般计算曼哈顿距离，因此不需要特殊处理。 

### 等距离的多个单元格

 多个小区可能共享相同的曼哈顿距离。 例如，在一个`3 x 3`矩阵中心为`(1,1)`, 四个相邻单元都有距离`1`。 有缺陷的实现可能会错误地假设严格的排序要求。 该问题明确允许等距离单元格之间的任何顺序，并且我们的桶方法自然地保留插入顺序而不违反正确性。 

### 位于角落中心

 当中心位于角落时，矩阵上的距离增长不均匀。 一些假设对称的算法可能会在这里失败。 因为我们单独计算每个单元格的距离，所以该实现以与中间位置完全相同的方式处理角中心，从而确保不对称布局的正确性。
