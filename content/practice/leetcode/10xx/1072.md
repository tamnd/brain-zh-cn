 # LeetCode 1072 - 翻转列以获得最大相等行数

 ## 问题理解

 这个问题给了我们一个`m x n`二元矩阵，其中每个元素都是`0`或者`1`。 我们可以选择任何一组列并翻转它们。 翻转一列意味着改变每一列`0`在该栏中`1`，以及每一个`1`到`0`。 

我们的目标是在执行这些翻转后最大化成为“相等行”的行数。 如果该行中的所有值都相同，则该行被视为有效。 换句话说，翻转后，该行中的每个值都必须是`0`或全部`1`s。 

重要的细节是翻转全局应用于整个列，而不是单独应用于每行。 如果我们翻转列`j`，影响该位置的每一行`j`。 

例如，考虑以下行：```
[0,1]
[1,0]
```如果我们翻转第一列，它们就会变成：```
[1,1]
[0,0]
```现在，两行本身都包含相同的值，因此两行都很重要。 

约束告诉我们两个维度都可以大到`300`。 这意味着矩阵最多可以包含`90,000`细胞。 这足够小`O(m * n)`或者`O(m * n log m)`解决方案，但尝试所有可能的列翻转组合是不可能的，因为有`2^n`可能的翻转配置。 

一些边缘情况很重要：

 - 行可能已包含所有相等的值，而无需任何翻转。 
- 有些行可能彼此完全相反，并且这些行在适当翻转后可以同时变得相等。 
- 可能只有一行或一列。 
- 多个相同的行应该全部算在一起。 
- 简单的方法可能会错误地仅将相同的行视为兼容，但互补的行也是兼容的。 

关键的观察是了解哪些行在同一组列翻转下可以变得均匀。 

## 方法

 ### 蛮力方法

 一个简单的方法是尝试每一种可能的列翻转组合。 

由于有`n`列，每列可以翻转或不翻转。 这创造了`2^n`可能的配置。 对于每个配置：

 1. 应用翻转。 
2. 检查每一行。 
3. 计算有多少行变成全部`0`或全部`1`s。 
4. 跟踪最大值。 

这种方法是正确的，因为它详尽地检查了每个有效的翻转模式。 然而，它很快就变得不可行。 和`n = 300`，配置的数量是天文数字。 

即使对于相对较小的值，例如`n = 30`,`2^30`已经有超过十亿种可能性。 

### 最佳观察

 关键的见解是，当且仅当两行满足以下任一条件时，它们才能变得一致：

 - 完全相同
 - 彼此精确互补

 为什么？ 

假设我们根据一行决定要翻转哪些列。 

如果一行开头为：```
[0,1,0,1]
```我们可以翻转列`1`和`3`做到这一点：```
[0,0,0,0]
```现在考虑另一行：```
[1,0,1,0]
```应用完全相同的翻转会产生：```
[1,1,1,1]
```因此互补的行在一起变得均匀。 

这意味着我们可以将每一行标准化为规范表示。 一种常见的技术是：

 - 如果第一个元素是`0`，保持该行不变。 
- 如果第一个元素是`1`，反转整行。 

可以统一的行将共享相同的标准化形式。 

然后我们可以使用哈希图来计算归一化模式的频率。

 ## 算法演练

 1. 创建哈希映射来对标准化行模式进行计数。 
2. 迭代矩阵中的每一行。 
3. 对于每一行，判断其第一个元素是否为`0`或者`1`。 
4. 如果第一个元素是`0`，保持该行不变，因为它已经代表了规范形式。 
5. 如果第一个元素是`1`，反转行中的每个值。 这会将互补行转换为相同的表示形式。 
6. 将规范化的行转换为Python中的元组，或Go中的字符串键，因此它可以用作哈希映射键。 
7. 增加该标准化模式的频率计数。 
8. 跟踪迄今为止看到的最大频率。 
9. 处理完所有行后，返回最大频率。 

### 为什么它有效

 该算法之所以有效，是因为列翻转是全局操作。 任意行都可以转化为全部`0`通过精确翻转该行包含的列`1`s。 

如果另一行相同，则相同的翻转也会产生所有`0`s。 

如果另一行是补码，则相同的翻转会产生所有`1`s。 

因此，相同的行和互补的行属于同一等价类。 规范化保证同一类中的所有行映射到相同的键，从而允许我们计算最大的兼容组。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def maxEqualRowsAfterFlips(self, matrix: List[List[int]]) -> int:
        pattern_count = defaultdict(int)
        max_rows = 0

        for row in matrix:
            if row[0] == 0:
                normalized = tuple(row)
            else:
                normalized = tuple(1 - value for value in row)

            pattern_count[normalized] += 1
            max_rows = max(max_rows, pattern_count[normalized])

        return max_rows
```实现首先创建一个名为的哈希图`pattern_count`。 这存储每个标准化行模式出现的次数。 

对于每一行，我们检查第一个值。 如果是的话`0`，我们保持该行不变。 如果是的话`1`，我们反转行中的每一位。 

此标准化步骤保证互补行产生相同的标准化模式。 

规范化行被转换为元组，因为列表不能用作 Python 中的字典键。 

然后我们增加该模式的计数并更新运行最大值。 

最后，返回最大频率，因为它代表在一些列翻转后可以同时变得均匀的最大行组。 

## 解决方案```go
func maxEqualRowsAfterFlips(matrix [][]int) int {
	patternCount := make(map[string]int)
	maxRows := 0

	for _, row := range matrix {
		pattern := make([]byte, len(row))

		if row[0] == 0 {
			for i, value := range row {
				pattern[i] = byte(value + '0')
			}
		} else {
			for i, value := range row {
				pattern[i] = byte((1 - value) + '0')
			}
		}

		key := string(pattern)

		patternCount[key]++

		if patternCount[key] > maxRows {
			maxRows = patternCount[key]
		}
	}

	return maxRows
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

由于切片不能用作 Go 中的映射键，因此我们将标准化行转换为字符串表示形式。 字节切片用于有效构造字符串密钥。 

标准化过程是相同的：

 - 行开头为`0`保持不变。 
- 行开头为`1`are inverted.

 The map tracks frequencies, and the maximum frequency is returned.

 Go does not require special handling for integer overflow here because all counts remain well within standard integer limits.

 ## 边缘情况

 当矩阵仅包含一行时，会出现一种重要的边缘情况。 无论行内容如何，​​我们始终可以通过翻转相应的列来使该行统一。 该实现自然地处理了这个问题，因为标准化模式计数变为`1`，返回的最大频率也是`1`。 

另一个重要的情况是行彼此互补而不是相同。 简单的实现可能无法将这些行分组在一起。 例如，`[0,1,0]`和`[1,0,1]`应该属于同一组，因为相同的翻转可以使一个全部`0`s 和其他所有`1`s。 规范化步骤正确地将两者转换为相同的规范形式。 

第三种边缘情况涉及所有行都已经相同的矩阵。 在这种情况下，不需要翻转，答案应该等于行数。 由于所有行都归一化为相同的模式，因此哈希映射会正确计算每次出现的次数。 

当存在多个大小相等的组时，会出现另一种微妙的边缘情况。 该算法不依赖于识别唯一的最佳组。 相反，它会持续跟踪迄今为止看到的最大频率，确保即使多个组都达到最大值时也能返回正确的答案。
