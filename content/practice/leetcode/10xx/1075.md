 # LeetCode 1075，项目员工 I

 ## 问题理解

 本题提供了两个数据库表，`Project`和`Employee`。 

这`Project`表表示哪些员工被分配到哪些项目。 每行包含一个`project_id`和一个`employee_id`。 自从这对`(project_id, employee_id)`是主键，同一员工在同一项目中不能出现多次。 

这`Employee`表存储有关员工的信息，包括他们的多年经验`experience_years`柱子。 

任务是计算从事每个项目的员工的平均经验水平。 结果每个项目必须包含一行：

 -`project_id`-`average_years`，四舍五入至小数点后两位

 为了解决这个问题，我们需要将员工连接到他们的项目，检索他们的经验值，按项目对员工进行分组，并计算每个组的平均值。 

例如，如果项目`1`拥有具有经验值的员工`3`,`2`， 和`1`，则平均值为：$$(3 + 2 + 1) / 3 = 2.00$$重要的观察是经验值并不直接存储在`Project`桌子。 我们必须加入`Project`表与`Employee`表使用`employee_id`。 

由于这是一个数据库聚合问题，因此输入大小由 SQL 引擎内部处理。 主要挑战是了解如何正确组合表并应用聚合函数。 

一些边缘情况很重要：

 - 一个项目可能只包含一名员工，因此平均值等于该员工的经验。 
- 多个项目可能共享同一名员工。 
- 经验值保证非空，因此我们不需要特殊的空处理。 
- 结果可以按任何顺序返回，即没有`ORDER BY`除非明确要求，否则条款是必需的。 

## 方法

 ### 蛮力方法

 强力方法将独立处理每个项目。 

对于每一个独特的`project_id`，我们可以：

 1. 查找分配给该项目的所有员工`Project`桌子。 
2. 对于每个员工，搜索`Employee`表来检索他们的经验。 
3. 总结经验值。 
4.除以员工人数。 
5. 对结果进行四舍五入。 

这种方法在逻辑上是正确的，因为它直接遵循问题定义。 但是，它会重复扫描表并执行不必要的重复查找。 

如果项目较多，人员较多，则反复查找`Employee`每个分配的表变得低效。 

### 最佳方法

 更好的解决方案是使用 SQL`JOIN`与聚合相结合。 

关键的见解是 SQL 数据库是专门为此类关系聚合问题而设计的。 

我们可以：

 1. 加入`Project`和`Employee`在`employee_id`。 
2. 行分组依据`project_id`。 
3. 使用`AVG()`计算平均体验的聚合函数。 
4. 使用`ROUND(..., 2)`正确格式化结果。 

该解决方案非常高效，因为数据库引擎在优化的内部操作中执行联接和聚合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(P × E) | O(1) | O(1) | 重复扫描每个项目的员工记录 |
 | 最佳 | O(N) | O(N) | 高效使用 SQL 连接和分组 |

 这里：

-`P`代表项目分配的数量
 -`E`代表员工人数
 -`N`表示连接的行总数

 ## 算法演练

 ### 最优 SQL 算法

 1. 从`Project`表，因为它包含项目和员工之间的映射。 
2. 加入`Employee`使用共享表`employee_id`柱子。 这使我们能够附加每个员工的`experience_years`到每个项目分配行。 
3. 连接后，行现在包含：

 -`project_id`-`employee_id`-`experience_years`4. 对所有行进行分组`project_id`。 这会为每个项目创建一个组。 
5. 对于每组，计算平均值`experience_years`使用 SQL`AVG()`功能。 
6. 申请`ROUND(..., 2)`因此输出与所需的格式匹配，具有两位小数。 
7. 返回最终结果表。 

### 为什么它有效

 该算法之所以有效，是因为每个项目分配行都通过连接条件与正确的员工进行匹配。 分组依据`project_id`确保属于同一项目的所有员工都聚集在一起。 自从`AVG()`计算所有分组行的算术平均值，所得值正是该项目的平均员工体验。 

## Python 解决方案

 尽管这是一个数据库问题并且通常仅使用 SQL 来解决，但以下 Python 字符串代表了正确的 LeetCode SQL 提交。```python
class Solution:
    def projectEmployeesI(self):
        return """
        SELECT
            p.project_id,
            ROUND(AVG(e.experience_years), 2) AS average_years
        FROM Project p
        JOIN Employee e
            ON p.employee_id = e.employee_id
        GROUP BY p.project_id
        """
```该解决方案在之间执行内连接`Project`和`Employee`使用`employee_id`。 

加入后，分配给项目的所有员工都会与其经验值相关联。 这`GROUP BY`子句将属于同一项目的行收集在一起。 

这`AVG()`函数计算每个项目组内的平均经验，以及`ROUND(..., 2)`完全按照要求将输出格式设置为小数点后两位。 

别名`p`和`e`用于使查询更短且更易于阅读。

 ## 边缘情况

 ### 只有一名员工的项目

 一个项目可能只包含一名员工。 在这种情况下，平均经验应直接等于该员工的经验值。 

如果实现假设每个组存在多行，这有时会暴露错误。 SQL`AVG()`函数自然地处理这个问题，因为对单个值求平均值只是返回该值。 

### 从事多个项目的员工

 一名员工可能会出现在多个不同的项目中。 幼稚的实施可能会意外地在全球范围内删除重复的员工，从而产生不正确的结果。 

加入和分组策略避免了这个问题，因为每个`(project_id, employee_id)`对独立对待。 同一名员工分别为其所属的每个项目做出贡献。 

### 舍入精度

 平均值可能会产生具有许多小数位的浮点值。 该问题明确要求小数点后恰好两位数。 

没有`ROUND(..., 2)`，某些 SQL 引擎可能会返回长十进制表示形式。 该实现通过在返回结果之前将结果显式四舍五入到小数点后两位来正确处理此问题。
