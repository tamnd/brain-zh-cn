 ## 解决方案

 ## 问题理解

 此问题要求我们检查输入数组中的**最小数字**，并确定其**数字之和**是奇数还是偶数。 

我们得到一个整数数组`nums`。 该任务包括三个明确的步骤：

 1. 找到数组中的**最小整数**。 
2. 计算**其数字之和**。 
3、退货：

 -`1`如果数字和是**偶数**
 -`0`如果数字和是**奇数**

 例如，如果数组是`[34,23,1,24,75,33,54,8]`，最小的数是`1`。 其各位数字之和也是`1`，这很奇怪，所以我们返回`0`。 

限制很小：

 -`nums.length`范围从`1`到`100`-`nums[i]`范围从`1`到`100`这些约束告诉我们一些有用的事情。 首先，保证数组至少包含一个元素，因此我们永远不需要处理空输入。 其次，数字非常小，这意味着任何简单的解决方案都可以轻松地在时间限制内完成。 由于值最多是`100`, digit summation is extremely cheap.

 有一些重要的边缘情况需要记住。 单元素数组是有效的，这意味着该元素自动为最小值。 Numbers may contain multiple digits, such as`99`或者`100`，需要正确的数字提取而不是假设一位数字。 我们还需要正确处理数字和恰好为偶数或奇数的情况。 

## 方法

 ### 蛮力方法

 A brute-force solution would first sort the array to find the minimum element, then compute the sum of its digits, and finally check whether that sum is odd or even.

 排序保证第一个元素成为最小数。 识别后，我们使用模（`% 10`) 和整数除法 (`// 10`) 来计算数字和。 最后，我们使用以下命令检查奇偶校验`% 2`。 

这种方法是正确的，因为排序保证我们找到最小的数字。 然而，排序是不必要的工作，因为我们只需要最小元素，而不是数组的整个排序。 

### 最佳方法

 关键的观察是我们只关心**最小值**，因此对整个数组进行排序是浪费的。 相反，我们可以使用一次遍历数组来直接计算最小值。 

一旦找到最小数字，我们就重复提取数字：

 - 使用最后一位数字`% 10`- 将其添加到运行总和中
 - 使用整数除以删除最后一位数字`10`计算数字和后，我们检查它是偶数还是奇数：

 - 偶数总和 → 返回`1`- 奇数和 → 返回`0`这完全避免了排序，并将工作减少为简单的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(1) 或 O(n) | 对数组进行排序只是为了找到最小值 |
 | 最佳| O(n) | O(1) | O(1) | 一次性找到最小值，然后对数字求和 |

 ## 算法演练

 1. 使用以下方法查找数组中的最小值`min(nums)`Python 中或 Go 中的简单循环。 这是可行的，因为问题仅取决于最小的元素。 
2. 初始化变量`digit_sum`到`0`。 This variable will store the cumulative sum of the digits.
 3. Repeatedly process the minimum number while it is greater than`0`:

 - 使用提取最后一位数字`% 10`- 添加到`digit_sum`- 使用整数除法删除处理后的数字`10`4. 处理完所有数字后，检查是否`digit_sum`甚至正在使用`% 2`。 
5. 返回`1`如果总和是偶数，否则返回`0`。 

### 为什么它有效

 该算法之所以有效，是因为它直接准确地计算出问题的要求。 最小元素是从数组中唯一确定的，重复的模加除运算可以正确地将任何整数分解为其数字。 由于奇偶性由下式决定`digit_sum % 2`，返回`1`对于偶数和`0`对于 odd 总是产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def sumOfDigits(self, nums: List[int]) -> int:
        minimum_number = min(nums)
        digit_sum = 0

        while minimum_number > 0:
            digit_sum += minimum_number % 10
            minimum_number //= 10

        return 1 if digit_sum % 2 == 0 else 0
```实现首先使用查找数组中的最小数字开始`min(nums)`。 由于保证输入至少包含一个数字，因此该操作始终有效。 

接下来我们初始化`digit_sum`跟踪所有数字的总和。 这`while`循环重复提取最后一位数字`% 10`，将其添加到运行总计中，并使用整数除法删除数字 (`// 10`）。 

最后，使用以下命令检查数字和的奇偶校验`% 2`。 如果结果是`0`，总和是偶数，我们返回`1`; 否则，我们返回`0`。 

## 解决方案```go
func sumOfDigits(nums []int) int {
	minimumNumber := nums[0]

	for _, num := range nums {
		if num < minimumNumber {
			minimumNumber = num
		}
	}

	digitSum := 0

	for minimumNumber > 0 {
		digitSum += minimumNumber % 10
		minimumNumber /= 10
	}

	if digitSum%2 == 0 {
		return 1
	}

	return 0
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置的`min()`对于切片，我们手动扫描数组以找到最小值。 

数字提取过程以同样的方式使用整数运算，`%`对于最后一位数字和`/= 10`将其删除。 整数溢出不是问题，因为值非常小，最多`100`，并且最大可能的数字和很小。 

因为该问题保证至少有一个元素，所以访问`nums[0]`是安全的。

 ## 边缘情况

 单元素数组是一种重要的边缘情况，因为最小元素自动成为唯一元素。 有缺陷的实现可能会假定存在多个值或意外地错误处理初始化。 由于该算法使用`min(nums)`在Python中并初始化`nums[0]`在 Go 中，这种情况自然有效。 

多位数字也可能是错误的来源。 幼稚的实现可能会错误地将数字视为单个值，而不是对各个数字求和。 例如，`33`应该产生`3 + 3 = 6`， 不是`33`。 重复的模和除运算保证每个数字被单独处理。 

价值观如`100`是另一个有用的边缘情况，因为它们包含零。 粗心的实现可能会错误地停止或忽略内部零。 在这里，数字提取正确进行：`100 → 10 → 1 → 0`，产生数字和`1`。 

最后，奇偶校验本身可能是错误的一个微妙来源，因为该问题使用了不寻常的返回约定：`1`对于偶数和`0`为奇数。 许多实现可能会意外地颠倒此逻辑。 明确检查`digit_sum % 2 == 0`避免混乱并确保正确性。
