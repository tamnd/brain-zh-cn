 ## 解决方案

 ## 问题理解

 该问题要求我们识别**仅**在 2019 年第一季度销售的产品，即`2019-01-01`和`2019-03-31`，包含在内。 我们提供了两张表：`Product`和`Sales`。 这`Product`表列出了所有产品及其 ID 和单价，而`Sales`表列出了与`product_id`,`sale_date`，以及其他与销售相关的信息。 

输出应该是一个表格`product_id`和`product_name`适用于**仅在 2019 年第一季度销售中出现的所有产品**。 在此期限之外销售的产品应排除在外。 如果产品从未售出，则它不应出现在结果中。 

重要的边缘情况包括从未售出的产品、恰好在边界上售出的产品（`2019-01-01`或者`2019-03-31`），并且产品在本季度多次销售。 该解决方案应正确处理重复的销售条目。 

## 方法

 一种暴力方法是扫描`Sales`表并检查每个产品，看看其所有销售额是否都落在 2019 年第一季度内。我们可以使用多个嵌套循环或聚合来验证条件。 虽然这可行，但它需要多次检查每一行，这对于大型数据集来说可能效率低下。 

最佳解决方案的关键洞察是将销售分组`product_id`并检查每个产品的两件事：是否有**第一季度之外的任何销售**，以及是否有**第一季度内至少有一次销售**。 SQL 提供了类似的工具`GROUP BY`和`HAVING`有效地执行此聚合，而无需多次扫描每个产品的数据。 

最佳方法是使用聚合来过滤产品，使用最小和最大销售日期的条件或通过计算季度内和季度外的销售额来过滤产品。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(n) | 扫描每种产品的所有销售情况以检查日期； n = #产品，m = #销售 |
 | 最佳| O(米) | O(n) | 按product_id分组，使用sale_date上的条件聚合进行过滤 |

 ## 算法演练

 1. **按第一季度和季度外过滤销售额**：对于每种产品，计算第一季度发生的销售额以及第一季度以外发生的销售额。 
2. **按product_id分组**：使用SQL`GROUP BY`to aggregate all sales rows for each product.
 3. **使用条件聚合**：统计季度外的销售数量。 季度外销量为零且本季度至少有一次销量的产品满足我们的标准。 
4. **加入产品表**：一旦我们获得了合格的产品 ID，请将它们与`Product`表来得到`product_name`。 
5. **返回结果**：选择`product_id`和`product_name`对于满足上述条件的所有产品。 顺序并不重要。 

为什么有效：通过对销售额进行分组`product_id`并统计季度外的销售额，我们确保只选择第一季度内独家销售的产品。 聚合可保证每个产品的所有销售都被准确考虑一次。 

## Python 解决方案```python
# LeetCode 1084: SQL problem; for Python we simulate using pandas or SQLAlchemy style
import sqlite3
from typing import List, Tuple

def sales_analysis_iii(connection: sqlite3.Connection) -> List[Tuple[int, str]]:
    query = """
    SELECT p.product_id, p.product_name
    FROM Product p
    JOIN (
        SELECT product_id
        FROM Sales
        GROUP BY product_id
        HAVING SUM(CASE WHEN sale_date < '2019-01-01' OR sale_date > '2019-03-31' THEN 1 ELSE 0 END) = 0
           AND SUM(CASE WHEN sale_date >= '2019-01-01' AND sale_date <= '2019-03-31' THEN 1 ELSE 0 END) > 0
    ) AS sq
    ON p.product_id = sq.product_id
    """
    cursor = connection.cursor()
    cursor.execute(query)
    return cursor.fetchall()
```该实现使用子查询来分组`Sales`经过`product_id`and applies conditional sums to filter products. 在第一季度之外有任何销售的产品都被排除在外，并且只保留在该季度内至少有一次销售的产品。 Finally, we join with the`Product`表来检索`product_name`。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
    "fmt"
)

func SalesAnalysisIII(db *sql.DB) ([]struct{ ProductID int; ProductName string }, error) {
    query := `
    SELECT p.product_id, p.product_name
    FROM Product p
    JOIN (
        SELECT product_id
        FROM Sales
        GROUP BY product_id
        HAVING SUM(CASE WHEN sale_date < '2019-01-01' OR sale_date > '2019-03-31' THEN 1 ELSE 0 END) = 0
           AND SUM(CASE WHEN sale_date >= '2019-01-01' AND sale_date <= '2019-03-31' THEN 1 ELSE 0 END) > 0
    ) AS sq
    ON p.product_id = sq.product_id
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var results []struct {
        ProductID   int
        ProductName string
    }

    for rows.Next() {
        var r struct {
            ProductID   int
            ProductName string
        }
        if err := rows.Scan(&r.ProductID, &r.ProductName); err != nil {
            return nil, err
        }
        results = append(results, r)
    }
    return results, nil
}
```在 Go 中，我们通过将每一行扫描到一个结构体中来处理查询结果。 Go 需要显式处理行和错误，这与 Python 不同，Python 允许更直接的获取。 SQL 查询的逻辑保持不变。

 ## 边缘情况

 一种边缘情况是一种从未售出的产品。 该算法正确地排除了它，因为`SUM`没有行结果为空或零，并且条件`sum_inside > 0`失败。 

另一个边缘情况是销售恰好在`2019-01-01`或者`2019-03-31`。 该解决方案使用包含比较运算符 (`>=`和`<=`），因此这些边界销售被计入季度内。 

第三种边缘情况是产品在季度内多次销售但从未在外部销售。 聚合正确地汇总了所有季度内销售额和零季度外销售额
