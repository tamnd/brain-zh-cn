[LeetCode 第 1095 题](https://leetcode.com/problems/find-in-mountain-array/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、交互

 ## 解决方案

 ## 问题理解

 这个问题给了我们一种特殊类型的数组，称为山数组。 山阵严格增加，直到达到单个峰值元素，然后严格减少。 

例如：```
1 2 3 5 4 2
```增加到`5`，然后减小。 

挑战在于这是一个交互式问题。 我们无法直接访问该数组。 相反，我们只能使用两个 API 方法：```
mountainArr.get(index)
mountainArr.length()
```目标是找到值等于的最小索引`target`。 如果目标出现多次，我们必须返回最左边的出现位置。 如果不存在，我们返回`-1`。 

山体结构创建了两个排序区域：

 1.从起点到顶峰的上升部分
 2.从峰顶到终点的下降部分

 这种结构非常重要，因为排序区域允许二分搜索。 

限制因素也很重要：

 - 数组长度最大可达`10^4`- 我们最多仅限于`100`打电话给`get()`简单的线性扫描可能需要最多`10^4`API 调用，这将立即使交互约束失效。 因此，我们需要一种主要基于二分搜索的算法。 

有几个重要的边缘情况需要记住：

 - 目标可能出现在峰的两侧
 - 目标可能根本不存在
 - 目标可能是峰本身
 - 目标可能只出现在下半部分
 - 因为我们必须返回最小索引，所以我们必须先搜索升半部分
 - 保证峰值存在，因为输入保证是有效的山数组

 ## 方法

 ### 蛮力方法

 最简单的解决方案是从左到右迭代每个索引并调用：```
mountainArr.get(i)
```如果该值等于目标，则立即返回索引。 

这是有效的，因为最终每个位置都会被检查，所以如果目标存在，我们将首先找到最左边的出现位置。 

然而，这种方法对于交互限制而言过于昂贵。 在最坏的情况下，我们会让`O(n)`打电话给`get()`，可能高达`10^4`调用，而问题只允许`100`。 

因此，我们需要一个对数解。 

### 最佳方法

 关键的见解是 mountain 数组包含两个排序区域：

 - 增加部分
 - 减少部分

 二分查找适用于排序后的数据，因此我们可以多次使用它。 

该算法分为三个主要阶段：

 1.使用二分查找找到峰值索引
 2.二分查找升半部分
 3. 如果没有找到，则二分查找降半部分

 找到峰值之所以有效，是因为：

 - 如果`arr[mid] < arr[mid + 1]`，我们处于渐增的斜率，因此峰值位于右侧
 - 否则，我们处于下降斜率或处于峰值，因此峰值位于`mid`或向左

 一旦找到峰值：

 - 左边是严格递增的，所以我们使用普通的二分查找
 - 右侧是严格递减的，因此我们使用修改后的二分查找和反向比较

 由于每个阶段都使用二分搜索，因此总复杂度保持对数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 依次扫描每个元素 |
 | 最佳 | O(log n) | O(1) | O(1) | 对峰值和两个排序的一半使用二分搜索 |

 ## 算法演练

 1.首先，确定山阵的长度`mountainArr.length()`。 
2. 使用二分查找法定位峰值元素。 在每个中点：

 - 比较`mountainArr.get(mid)`和`mountainArr.get(mid + 1)`- 如果右边的值更大，我们仍然向上爬，所以将左边界移动到`mid + 1`- 否则，我们正在下降或已经到达顶峰，因此将右边界移至`mid`3. 继续，直到左右指针相遇。 该位置就是峰值指数。 
4. 对索引的升序部分执行标准二分搜索`0`到`peak`。 

- 如果中点值小于目标值，则向右移动
 - 如果较大，则向左移动
 - 如果相等，立即返回

 我们先搜索这一边，因为问题要求最小索引。 
5. 如果在左侧没有找到目标，则从降序部分再次执行二分查找`peak + 1`到`n - 1`。 

由于这一半是按降序排序的：

 - 如果中点值大于目标值，则向右移动
 - 如果中点值小于目标值，则向左移动
 6. 如果两次搜索都没有找到目标，则返回`-1`。 

### 为什么它有效

 正确性来自山阵属性。 

峰值搜索总是正确收敛，因为每次比较都会告诉我们位于峰值的哪一侧。 递增和递减区域是严格单调的，因此二分查找在两半上都有效。 

首先搜索升序半部分可以保证，如果目标在两个半部分中都存在，我们将返回较小的索引。 

## Python 解决方案```python
# """
# This is MountainArray's API interface.
# You should not implement it, or speculate about its implementation
# """
# class MountainArray:
#     def get(self, index: int) -> int:
#     def length(self) -> int:

from typing import Protocol

class Solution:
    def findInMountainArray(
        self,
        target: int,
        mountainArr: 'MountainArray'
    ) -> int:

        n = mountainArr.length()

        # Find peak index
        left = 0
        right = n - 1

        while left < right:
            mid = (left + right) // 2

            if mountainArr.get(mid) < mountainArr.get(mid + 1):
                left = mid + 1
            else:
                right = mid

        peak = left

        # Binary search on increasing side
        left = 0
        right = peak

        while left <= right:
            mid = (left + right) // 2
            value = mountainArr.get(mid)

            if value == target:
                return mid

            if value < target:
                left = mid + 1
            else:
                right = mid - 1

        # Binary search on decreasing side
        left = peak + 1
        right = n - 1

        while left <= right:
            mid = (left + right) // 2
            value = mountainArr.get(mid)

            if value == target:
                return mid

            if value > target:
                left = mid + 1
            else:
                right = mid - 1

        return -1
```实现首先使用二分搜索定位峰值元素。 该算法不是直接检查某个位置是否是峰值，而是比较相邻元素来确定搜索当前是在递增还是递减的斜率上。 

一旦识别出峰值，代码就会在左半部分执行标准的二分搜索，因为该区域是严格递增的。 

如果在那里没有找到目标，算法将搜索右半部分。 由于右侧严格递减，因此比较方向相反。 

该实现仅使用恒定的额外空间并保留`get()`称为对数。 

## 解决方案```go
/**
 * // This is the MountainArray's API interface.
 * // You should not implement it, or speculate about its implementation
 * type MountainArray struct {
 * }
 *
 * func (this *MountainArray) get(index int) int {}
 * func (this *MountainArray) length() int {}
 */

func findInMountainArray(target int, mountainArr *MountainArray) int {
	n := mountainArr.length()

	// Find peak index
	left, right := 0, n-1

	for left < right {
		mid := left + (right-left)/2

		if mountainArr.get(mid) < mountainArr.get(mid+1) {
			left = mid + 1
		} else {
			right = mid
		}
	}

	peak := left

	// Binary search on increasing side
	left, right = 0, peak

	for left <= right {
		mid := left + (right-left)/2
		value := mountainArr.get(mid)

		if value == target {
			return mid
		}

		if value < target {
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	// Binary search on decreasing side
	left, right = peak+1, n-1

	for left <= right {
		mid := left + (right-left)/2
		value := mountainArr.get(mid)

		if value == target {
			return mid
		}

		if value > target {
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的算法结构。 

Go 特有的一个重要细节是中点计算：```go
mid := left + (right-left)/2
```这种形式避免了潜在的整数溢出，这是 Go 和其他静态类型语言中常见的二分搜索最佳实践。 

Go 还使用显式变量声明和指针接收器来进行交互`MountainArray`界面。

 ## 边缘情况

 当目标出现在山阵的两半时，就会出现一种重要的边缘情况。 例如：```
[1,2,3,5,3,1]
```有目标`3`。 

粗心的实现可能会先搜索降半部分并错误地返回索引`4`而不是索引`2`。 此实现通过始终在减少的一半之前搜索增加的一半来避免该问题。 

另一个重要的边缘情况是当目标等于峰值元素本身时。 由于峰值属于升序搜索范围，因此第一次二分搜索可以正确检测并立即返回它。 这可以防止错过峰值或随后搜索不必要的范围。 

第三种边缘情况涉及非常小的有效山数组，例如：```
[1,2,1]
```峰值搜索仍然可以正常工作，因为二分搜索逻辑仅依赖于相邻比较。 即使数组仅包含三个元素，该算法也能安全收敛。 

另一个微妙的情况是目标仅存在于下半部分。 标准二分搜索假定升序，因此重用相同的比较逻辑将会失败。 此实现显式反转了下降部分的比较方向，确保了正确性。
