 ## 解决方案

 ## 问题理解

 问题给出了一个数组`stones`表示石头在 X 轴上的位置，其中每个位置都是唯一的。 目标是移动**端点石子**（位于最小和最大位置的石子），以便最终所有石子占据 X 轴上的连续位置。 终点石在移动后只能移动到**本身不是终点**的位置。 

输出是一个数组`[minMoves, maxMoves]`在哪里`minMoves`是使棋子连续所需的最少移动次数，并且`maxMoves`是规则下可能的最大移动次数。 

关键限制是至少有 3 个棋子且不超过 10,000 个，并且棋子位置可以非常大，最多 10^9。 该数组保证包含唯一的位置。 

需要注意的边缘情况包括已经连续的棋子、两端有较大间隙的棋子，或者需要先移动一个端点才能允许后续移动的配置。 

## 方法

 **暴力方法**将涉及模拟移动端点石子的所有可能序列。 这涉及递归选择一个端点，将其移动到每个可能的有效位置，并检查棋子是否连续。 虽然这保证了正确性，但它具有指数时间复杂度，因为序列的数量随着石子和间隙的数量而组合增长。 对于大小为 10,000 的数组，这是完全不可行的。 

最佳方法的**关键见解**是认识到：

 1. 对于**最大移动**，我们总是可以从一端向内移动棋子，始终将另一端作为端点。 当我们将所有棋子一颗一颗地移向最大可能的连续线段时，就会出现最大移动，即`max(stones) - min(stones) + 1 - len(stones)`。 
2. 对于**最小移动**，我们可以在排序的棋子上使用**滑动窗口**。 我们尝试在大小等于石头数量的窗口中放入尽可能多的石头。 最小移动量本质上是该窗口之外的棋子数量。 需要特别注意的是，除了一颗棋子之外，所有棋子都是连续的，而且一招不能直接生成连续棋子； 在这种情况下，最小移动次数变为 2。 

这导致使用排序和滑动窗口技术的线性或线性算术解决方案。

 ## 算法演练

 1. **按升序对石头进行排序**。 排序简化了滑动窗口计算和查找最大间隙。 
2. **计算最大移动**如下`max(stones) - min(stones) + 1 - len(stones)`。 这会计算最小和最大棋子之间的所有空位置减去已存在的棋子数量。 
3. **使用滑动窗口**来计算最小移动：

 - 初始化两个指针，`left`和`right`，代表一扇石头窗户。 
- 扩张`right`只要窗户内的石头数量适合长度`n`（石头总数）。 
- 当前窗口的最小移动量是`n - number of stones in window`。 
- 检查窗户覆盖的特殊边缘情况`n-1`石头，总范围是`n-2`（一端间隙 1）。 这需要 2 次移动而不是 1 次。 
4. **返回结果**为`[minMoves, maxMoves]`。 

**为什么有效：** 排序可以保证石头是有序的，因此我们可以有效地计算间隙。 滑动窗口确保我们找到最大的连续或接近连续的棋子簇，从而最大限度地减少移动次数。 最大移动公式利用了最远的石子总是可以向内移动而不违反端点规则的性质。 

## Python 解决方案```python
from typing import List

class Solution:
    def numMovesStonesII(self, stones: List[int]) -> List[int]:
        stones.sort()
        n = len(stones)
        maxMoves = max(stones[-1] - stones[1] - n + 2, stones[-2] - stones[0] - n + 2)
        
        minMoves = n
        left = 0
        for right in range(n):
            while stones[right] - stones[left] + 1 > n:
                left += 1
            if right - left + 1 == n - 1 and stones[right] - stones[left] + 1 == n - 1:
                minMoves = min(minMoves, 2)
            else:
                minMoves = min(minMoves, n - (right - left + 1))
        
        return [minMoves, maxMoves]
```该实现首先对石头进行排序以简化距离计算。`maxMoves`是使用最外面的间隙导出的。 滑动窗口计算一段长度内最大的石块簇`n`, 给予`minMoves`。 当由于单个间隙而导致一次移动不够时，会处理特殊情况。 

## 解决方案```go
import "sort"

func numMovesStonesII(stones []int) []int {
    sort.Ints(stones)
    n := len(stones)
    maxMoves := max(stones[n-1]-stones[1]-n+2, stones[n-2]-stones[0]-n+2)
    
    minMoves := n
    left := 0
    for right := 0; right < n; right++ {
        for stones[right]-stones[left]+1 > n {
            left++
        }
        if right-left+1 == n-1 && stones[right]-stones[left]+1 == n-1 {
            if minMoves > 2 {
                minMoves = 2
            }
        } else {
            if minMoves > n-(right-left+1) {
                minMoves = n - (right - left + 1)
            }
        }
    }
    
    return []int{minMoves, maxMoves}
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```在 Go 中，排序和切片操作类似于 Python。 我们显式处理特殊的边缘情况并定义一个辅助函数`max`。 

## 工作示例

 **示例1：**`stones = [7,4,9]`排序：`[4,7,9]`

`maxMoves = max(9-7-3+2, 7-4-3+2) = max(1, 2) = 2`滑动窗口用于`minMoves`： 窗户`[4,7]`有 2 颗宝石 →`minMoves = 1`输出：`[1,2]`**示例2：**`stones = [6,5,4,3,10]`排序：`[3,4,5,6,10]`

`maxMoves = max(10-4-5+2, 6-3-5+2) = max(3, 0) = 3`滑动窗口用于`minMoves`： 窗户`[3,4,5,6]`有 4 颗宝石 →`minMoves = 5-4 = 1`但特殊情况适用 →`minMoves = 2`输出：`[2,3]`## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
