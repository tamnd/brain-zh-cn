[LeetCode 问题 1005](https://leetcode.com/problems/maximize-sum-of-array-after-k-neegations/)

 **难度：** 🟢简单
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 问题是要求我们在精确执行后最大化整数数组的总和`k`否定。 否定操作包括选择一个索引`i`并更换`nums[i]`和`-nums[i]`。 此操作可以多次应用于同一元素。 输入由整数数组组成`nums`和一个整数`k`代表否定的数量。 期望的输出是之后可以获得的数组的最大和`k`此类操作。 

约束条件告诉我们`nums`可以相当大，最多 10,000 个元素，每个元素都在 [-100, 100] 范围内。 操作次数`k`也可以达到 10,000。 这些限制表明尝试所有否定组合的强力方法不够有效。 

重要的边缘情况包括数组全部为正数、全部为负数、零或当`k`大于负元素的数量。 该问题保证非空数组和至少一个操作，因此我们不需要处理空数组或零操作。 

## 方法

 蛮力方法会尝试每一个可能的序列`k`求反并计算结果数组的总和。 虽然这种方法保证了正确性，但其时间复杂度随着`k`，使得对于大数组或大值不可行`k`。 具体来说，需要探索`n^k`的可能性，这对于`n`和`k`最多 10,000 个。 

最佳方法利用了两个关键的观察结果。 首先，为了最大化总和，我们应该优先考虑对最小（负数最大）的数取负，因为将大负数变成正数使总和增加最多。 其次，将所有负数翻转后，如果`k`仍然大于零，对最小绝对值元素重复求反将使总和的减少最小化，因为翻转最小元素引入的负面影响最小。 

最佳解决方案包括对数组进行排序以有效访问最小元素，首先翻转负数，然后处理任何剩余的元素`k`根据需要翻转最小的绝对值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^k) | O(n^k) | O(n) | 尝试所有否定序列，指数时间 |
 | 最佳| O(n log n) | O(n log n) | O(1) | O(1) | 对数组进行排序，翻转负数，处理具有最小绝对值的剩余 k |

 ## 算法演练

 1. 对数组进行排序`nums`按升序排列。 这确保了负数排在第一位并且可以轻松找到最小的绝对值。 
2. 迭代数组。 对于每个负数，将其翻转（乘以 -1）并递减`k`1. 继续，直到所有负数都翻转或`k`达到零。 
3.如果`k`第一次遍历后仍然大于零，找到数组中绝对值最小的元素。 如果`k`为奇数，则翻转该元素一次。 如果`k`是偶数，不需要进一步的操作，因为翻转两次会抵消。 
4. 返回修改后的数组的总和。 

为什么有效：该算法保持了不变性，即在每一步中，数组都以最大程度地增加总和的方式进行修改。 首先翻转负数可确保获得最大可能的收益，然后处理剩余的`k`如果仍然存在奇数翻转，则具有最小的绝对值可确保最小的损失。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestSumAfterKNegations(self, nums: List[int], k: int) -> int:
        nums.sort()
        for i in range(len(nums)):
            if k > 0 and nums[i] < 0:
                nums[i] = -nums[i]
                k -= 1
        if k % 2 == 1:
            nums.sort()
            nums[0] = -nums[0]
        return sum(nums)
```此 Python 实现首先对数组进行排序，以优先考虑负数。 然后它会翻转尽可能多的负数`k`。 如果`k`仍然是奇数，它翻转最小的绝对值数以最小化总和的减少。 最后，它返回修改后的数组的总和。 

## 解决方案```go
import "sort"

func largestSumAfterKNegations(nums []int, k int) int {
    sort.Ints(nums)
    for i := 0; i < len(nums) && k > 0; i++ {
        if nums[i] < 0 {
            nums[i] = -nums[i]
            k--
        }
    }
    if k%2 == 1 {
        sort.Ints(nums)
        nums[0] = -nums[0]
    }
    sum := 0
    for _, v := range nums {
        sum += v
    }
    return sum
}
```The Go version mirrors the Python logic. 排序和翻转操作就地完成。 区别在于使用 for-range 循环进行显式求和计算，因为 Go 没有内置的`sum`切片函数。 

## 工作示例

 **示例1：**`nums = [4,2,3], k = 1`排序后：`[2,3,4]`。 没有负数，`k`为奇数，翻转最小元素 2 →`[-2,3,4]`。 总和 = 5。 

**示例2：**`nums = [3,-1,0,2], k = 3`排序后：`[-1,0,2,3]`。 翻转-1 →`[1,0,2,3]`,`k = 2`。 没有更多的负面影响。 最小绝对值 = 0，翻转不起作用。`k`仍然是 2 → 偶数，总和 = 6。 

**示例3：**`nums = [2,-3,-1,5,-4], k = 2`排序后：`[-4,-3,-1,2,5]`。 翻转-4 →`[4,-3,-1,2,5]`,`k = 1`。 翻转-3 →`[4,3,-1,2,5]`,`k = 0`。 总和 = 13。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 排序占主导地位，在数组上迭代一次是 O(n) |
 | 空间| O(1) | O(1) | 就地排序和修改，无需额外结构 |

 排序是关键操作。 所有其他步骤都是线性扫描，因此总体复杂性主要由`O(n log n)`。

 ## 边缘情况

 一种重要的边缘情况是所有数字均为正且`k`很奇怪。 翻转任何数字都会减少总和，因此算法必须选择最小的数字以最小化损失。 

另一种边缘情况是数组包含零时。 翻转零不会改变总和，如果`k`是奇数，因为它允许满足操作计数而不减少总和。 

第三种边缘情况是当`k`大于负数的个数。 翻转所有底片后，算法需要正确处理剩余的翻转。 如果`k`是均匀的，不需要采取进一步的行动； 如果是奇数，则翻转最小绝对值元素以尽量减少影响。 Python 和 Go 实现中的最终条件检查都可以正确处理这一问题。
