[LeetCode 1051 题](https://leetcode.com/problems/height-checker/)

 **难度：** 🟢简单
 **主题：** 数组、排序、计数排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`heights`，其中每个值代表排队的学生的身高。 学校希望学生按非递减顺序排列，这意味着身高应从最小到最大出现，允许重复。 

我们需要确定与正确排序的顺序相比，目前有多少学生站在错误的位置。 

换句话说，我们需要：

 1. 创建数组的正确排序版本。 
2. 将原始数组与排序后的版本进行比较。 
3. 计算有多少个索引包含不同的值。 

例如，如果：```
heights  = [1,1,4,2,1,3]
expected = [1,1,1,2,3,4]
```然后指数`2`,`4`， 和`5`不同，所以答案是`3`。 

限制很小：

 - 数组长度最多为`100`- 每个高度介于`1`和`100`这些限制告诉我们一些重要的事情：

 - 标准排序解决方案是完全可以接受的。 
- 由于高度值被限制在一个小的固定范围内，计数排序也是一种非常自然的优化。 
- 内存使用不是这个问题的关注点。 

有几种边缘情况值得考虑：

 - 数组可能已经排序，产生的答案为`0`。 
- 每个位置都可能不正确。 
- 多个学生可以具有相同的身高，因此重复处理必须正确进行。 
- 数组只能包含一个元素。 

## 方法

 ### 蛮力方法

 解决该问题的一种简单方法是生成每种可能的非递减排列并将其与输入数组进行比较。 从技术上讲，这将使我们能够找到预期的排序并计数不匹配的情况。 

然而，生成排列的效率极低，因为排列的数量随着数组的大小呈阶乘增长。 尽管限制很小，但阶乘增长很快就变得不切实际。 

稍微好一点的强力解释是使用基于比较的排序算法简单地对数组的副本进行排序，然后逐个索引地比较原始数组和已排序的数组。 

这是可行的，因为排序后的数组直接代表了学生的预期排列。 

### 关键见解

 关键的观察是我们不需要重新排列原始数组。 我们只需要知道正确的排序顺序是什么样的。 

一旦我们有了排序版本：

 - 如果`heights[i] == expected[i]`，该学生已经处于正确的位置。 
- 否则，该索引有助于答案。 

由于高度值被限制为`1`通过`100`，我们可以有效地使用计数排序。 

计数排序在这里效果很好，因为：

 - 值范围非常小并且固定。 
- 计数频率是线性时间。 
- 重建排序顺序也是线性时间。 

这为我们提供了最佳的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 使用标准排序进行暴力破解 | O(n log n) | O(n log n) | O(n) | 对副本进行排序，然后比较索引 |
 | 使用计数排序进行优化 | O(n + k) | O(k) | 使用有界高度范围，其中`k = 100`|

 ## 算法演练

 ### 最优计数排序算法

 1.创建大小为的频率数组`101`。 

由于高度范围为`1`到`100`，我们可以存储每个高度出现的次数。 指数`i`代表高度`i`。 
2. 统计每个高度的出现频率。 

遍历`heights`数组一次并增加相应的计数器。 
3. 隐式重建预期的排序顺序。 

我们不是立即创建一个完全排序的数组，而是迭代可能的高度`1`到`100`。 
4. 与原始数组进行比较。 

维护指向原始的指针`heights`大批。 对于频率数组中出现的每个高度值：

 - 将该高度放入概念排序顺序中。 
- 将其与当前值进行比较`heights`。 
- 如果它们不同，则增加不匹配计数器。 
5. 继续，直到所有频率都用完。 

最后，不匹配计数器就是答案。 

### 为什么它有效

 计数数组准确存储每个高度在排序排列中必须出现的次数。 按升序迭代计数可重建问题所需的唯一非递减排序。 每次比较都会检查原始位置是否已与正确的排序值匹配。 因此，每一次不匹配都恰好对应于站在错误位置的学生。 

## Python 解决方案```python
from typing import List

class Solution:
    def heightChecker(self, heights: List[int]) -> int:
        frequency = [0] * 101

        # Count occurrences of each height
        for height in heights:
            frequency[height] += 1

        mismatch_count = 0
        index = 0

        # Reconstruct sorted order and compare
        for height in range(1, 101):
            while frequency[height] > 0:
                if heights[index] != height:
                    mismatch_count += 1

                index += 1
                frequency[height] -= 1

        return mismatch_count
```该实现首先创建一个足够大的频率数组来存储每个可能高度的计数`1`到`100`。 

第一个循环计算每个高度出现的次数。 这取代了基于比较的排序算法的需要。 

变量`index`跟踪我们在原始文件中的当前位置`heights`大批。 然后我们按升序迭代高度。 对于每次出现的高度，我们将预期的排序值与同一索引处的原始值进行比较。 

每当值不同时，我们就增加`mismatch_count`。 

因为我们按升序处理高度，所以重建的序列与问题所需的排序顺序完全匹配。 

## 解决方案```go
func heightChecker(heights []int) int {
	frequency := make([]int, 101)

	// Count occurrences of each height
	for _, height := range heights {
		frequency[height]++
	}

	mismatchCount := 0
	index := 0

	// Reconstruct sorted order and compare
	for height := 1; height <= 100; height++ {
		for frequency[height] > 0 {
			if heights[index] != height {
				mismatchCount++
			}

			index++
			frequency[height]--
		}
	}

	return mismatchCount
}
```Go 实现遵循与 Python 版本相同的逻辑。 

频率数组是使用创建的`make([]int, 101)`。 Go 切片会自动初始化为零，因此所有频率都从零开始。 

嵌套循环直接根据计数重建排序顺序。 由于最大高度仅为`100`，整数溢出不是问题。 

Go 切片自然一致地处理空和非空输入，尽管这个问题保证了至少一个元素。

 ## 边缘情况

 ### 已排序的输入

 已经排序的数组可能会暴露错误，其中算法在重建过程中错误地计算不匹配。 例如：```
[1,2,3,4,5]
```每次比较都应该完美匹配，从而得出`0`。 该实现可以正确处理此问题，因为仅当值不同时才会计算不匹配。 

### 所有元素相同

 数组例如：```
[2,2,2,2]
```可能会导致排序逻辑实施不当出现问题，尤其是在重复处理不正确的情况下。 计数排序方法自然可以处理重复项，因为频率准确地表示重复值。 

### 逆序排列

 降序数组，例如：```
[5,4,3,2,1]
```最大化无序并测试是否每个位置都被独立检查。 该实现重建完全排序的顺序并比较每个索引，确保正确计算所有不匹配。 

### 边界高度值

 该问题允许高度从`1`到`100`。 Inputs like:```
[100,1,100,1]
```验证频率数组索引在有效范围的两个极端处是否正常工作。 由于实现分配了一个大小的数组`101`, 指数`1`通过`100`可以安全访问。
