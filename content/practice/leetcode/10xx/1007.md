[LeetCode 问题 1007](https://leetcode.com/problems/minimum-domino-rotations-for-equal-row/)

 **难度：** 🟡 中等
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 问题给了我们两个数组，`tops`和`bottoms`，代表多米诺骨牌序列。 每张多米诺骨牌都有两个值，一个在上半部分，一个在下半部分。 对于`i`第一张多米诺骨牌，顶部值为`tops[i]`底部值为`bottoms[i]`。 

我们可以单独旋转任何多米诺骨牌。 旋转多米诺骨牌会交换其顶部和底部值。 目标是确定所需的最小旋转次数，以便：

 - 中的每个值`tops`行变得相同，或者
 - 中的每个值`bottoms`行变得相同。 

如果不可能使任一行统一，我们返回`-1`。 

关键细节是我们并不试图同时使两行相等。 我们只需要一行来包含相同的值。 

约束条件很重要：

 - 数组的长度可以大到`2 * 10^4`- 每个多米诺骨牌值都介于`1`和`6`小值范围强烈暗示该问题可能具有紧凑的贪婪或基于计数的解决方案。 尝试多种旋转组合的强力方法很快就会变得不可行，因为每个多米诺骨牌都有两种可能的状态，从而导致指数增长。 

一些边缘情况值得尽早识别：

 - 数组可能已经包含统一的行，需要`0`轮换。 
- 一些多米诺骨牌可能已经包含双方的目标值。 
- 这可能是不可能的，因为至少有一张多米诺骨牌完全缺乏所需的目标值。 
- 可能出现多个目标值，但只有一个目标值会产生最小旋转数。 
- 最小有效输入大小是`2`，所以我们应该确保没有假设依赖于更大的数组。 

该问题保证两个数组具有相同的长度并且仅包含来自`1`到`6`。 

## 方法

 ### 蛮力方法

 一个简单的暴力解决方案将尝试以下每个可能的目标值`1`通过`6`。 对于每个目标，我们将检查是否可以使所有顶部值等于该目标或所有底部值等于该目标。 

对于每张多米诺骨牌：

 - 如果双方都不包含目标值，则尝试立即失败。 
- 否则，我们计算需要多少次旋转。 

这种方法是正确的，因为只有六个可能的值可以成为最终的统一值。 通过详尽地检查所有这些，我们保证找到最小有效轮换计数。 

尽管这被称为“暴力”，但实际上它足够有效，因为值范围很小。 然而，我们可以利用重要的观察结果进一步优化。 

### 关键见解

 如果存在解，则最终统一值必须是：

 -`tops[0]`， 或者
-`bottoms[0]`为什么？ 

考虑第一张多米诺骨牌。 在任何有效的最终配置中，所选的统一值必须出现在该多米诺骨牌上的某个位置。 由于第一张多米诺骨牌仅包含`tops[0]`和`bottoms[0]`，没有其他值可能成为最终的统一值。 

这一观察结果极大地将搜索空间从六个可能的候选者减少到最多两个候选者。 

对于每个候选值，我们计算：

 - 需要旋转以使顶行均匀
 - 需要旋转以使底行均匀

 然后我们取最小有效结果。 

这给出了具有线性时间复杂度的干净贪婪解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(6n) | O(6n) | O(1) | O(1) | 尝试从 1 到 6 的所有可能的多米诺骨牌值 |
 | 最佳| O(n) | O(1) | O(1) | 只检查第一张多米诺骨牌上的候选者 |

 ## 算法演练

 1. 选择两个可能的候选值：

 -`tops[0]`-`bottoms[0]`任何有效的最终值都必须出现在第一张多米诺骨牌上，因此这些是唯一值得检查的候选值。 
2. 创建一个辅助函数来评估一个候选值。 

该函数确定：

 - 需要多少次旋转才能使所有最高值等于候选值
 - 需要多少次旋转才能使所有底部值等于候选值
 3. 遍历每张多米诺骨牌。 

对于每个索引`i`：

 - 如果两者都不是`tops[i]`也不`bottoms[i]`等于候选人，那么这个候选人是不可能的。 
- 否则：

 - 如果`tops[i]`不是候选人，我们需要一轮轮换才能将候选人置于首位
 - 如果`bottoms[i]`不是候选人，我们需要一次轮换才能将候选人放在底部
 4.处理完所有多米诺骨牌后：

 - 该候选人的最小轮换是：`min(top_rotations, bottom_rotations)`5. 评估第一张多米诺骨牌上的两个候选者。 
6.返回最小有效结果：

 - 如果两位候选人均失败，则返回`-1`- 否则返回较小的旋转计数

 ### 为什么它有效

 正确性取决于一个简单的不变量：

 对于一个值`x`为了成为最终的统一值，每个多米诺骨牌必须包含`x`至少在一侧。 

由于第一张多米诺骨牌仅包含`tops[0]`和`bottoms[0]`，任何有效的解决方案都必须使用这两个值之一。 检查两个候选者可以保证完整性。 对于每个候选者，每个多米诺骨牌的旋转计数都是贪婪且独立地计算的，这是最优的，因为每个多米诺骨牌决策都是局部的并且不会影响其他多米诺骨牌决策。 

## Python 解决方案```python
from typing import List

class Solution:
    def minDominoRotations(self, tops: List[int], bottoms: List[int]) -> int:
        def rotations_needed(target: int) -> int:
            top_rotations = 0
            bottom_rotations = 0

            for top, bottom in zip(tops, bottoms):
                if top != target and bottom != target:
                    return float('inf')

                if top != target:
                    top_rotations += 1

                if bottom != target:
                    bottom_rotations += 1

            return min(top_rotations, bottom_rotations)

        candidate1 = tops[0]
        candidate2 = bottoms[0]

        result = min(
            rotations_needed(candidate1),
            rotations_needed(candidate2)
        )

        return -1 if result == float('inf') else result
```实现首先定义一个名为的辅助函数`rotations_needed`。 此函数检查给定的目标值是否可以使任一行统一。 

维护两个计数器：

 -`top_rotations`计算需要多少次交换才能使顶行等于目标。 
-`bottom_rotations`计算需要多少次交换才能使底行等于目标。 

对于每张多米诺骨牌：

 - 如果双方都没有包含目标，则候选者立即变得不可能。 
- 如果顶边不等于目标，则需要旋转以将目标放置在顶部。 
- 同样，如果底边不等于目标，则需要旋转以将目标放置在底部。 

扫描完所有多米诺骨牌后，我们返回两个旋转计数中较小的一个，因为该问题只需要一行变得均匀。 

主函数仅检查第一张多米诺骨牌中的两个有效候选者。 最后，如果两位候选人都失败了，我们返回`-1`。 

## 解决方案```go
package main

import "math"

func minDominoRotations(tops []int, bottoms []int) int {
	rotationsNeeded := func(target int) int {
		topRotations := 0
		bottomRotations := 0

		for i := 0; i < len(tops); i++ {
			top := tops[i]
			bottom := bottoms[i]

			if top != target && bottom != target {
				return math.MaxInt32
			}

			if top != target {
				topRotations++
			}

			if bottom != target {
				bottomRotations++
			}
		}

		if topRotations < bottomRotations {
			return topRotations
		}

		return bottomRotations
	}

	candidate1 := tops[0]
	candidate2 := bottoms[0]

	result1 := rotationsNeeded(candidate1)
	result2 := rotationsNeeded(candidate2)

	result := result1
	if result2 < result {
		result = result2
	}

	if result == math.MaxInt32 {
		return -1
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有`float('inf')`，我们使用`math.MaxInt32`作为代表不可能配置的哨兵值。 

直接使用切片，无需额外分配，保持空间复杂度恒定。 整数溢出不是问题，因为最大旋转次数受以下限制`2 * 10^4`。

 ## 边缘情况

 当行已经统一时，就会出现一种重要的边缘情况。 例如：```
tops = [2,2,2]
bottoms = [1,1,1]
```有缺陷的实现可能仍然会执行不必​​要的轮换或错误地计算交换。 此实现正确地检测到不需要旋转，因为顶行已经与各处的候选值匹配。 

另一个重要的情况是多米诺骨牌两边都不包含候选值。 例如：```
tops = [1,2,3]
bottoms = [1,2,4]
```如果我们尝试使每个值等于`1`，第二张多米诺骨牌阻止了解决方案，因为双方都不包含`1`。 实现会立即处理此问题，条件如下：```
if top != target and bottom != target:
```这保证了不可能的候选人会提前失败。 

第三种边缘情况涉及多米诺骨牌，其中双方都已经等于目标值。 例如：```
tops = [2,2,2]
bottoms = [2,2,2]
```在这种情况下，旋转不会改变任何内容，并且不应增加旋转计数。 该实现自然会处理这个问题，因为当双方都已经匹配目标时，旋转计数器都不会增加。 

最后一个微妙的情况是第一张多米诺骨牌上的两个候选者都是相同的。 例如：```
tops = [3,1,2]
bottoms = [3,3,3]
```两位候选人都成为`3`。 该实现仍然可以正常工作，因为两次评估相同的候选者不会影响正确性，只是运行时的一个可以忽略不计的常数因素。
