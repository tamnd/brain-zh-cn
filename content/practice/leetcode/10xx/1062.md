[LeetCode 1062 题](https://leetcode.com/problems/longest-repeating-substring/)

 **难度：** 🟡 中等
 **主题：** 字符串、二分查找、动态规划、滚动哈希、后缀数组、哈希函数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到给定字符串中至少出现两次的最长子字符串的长度`s`。 

子字符串是字符串内连续的字符序列。 重复的子串可能会相互重叠，这是一个重要的细节。 例如，在字符串中`"aaaa"`, 子串`"aaa"`如果允许重叠，则出现两次：一次从索引处开始`0`一旦从索引开始`1`。 

我们不会被要求返回子字符串本身，只返回它的最大长度。 

例如，如果`s = "abbaba"`, 子串`"ab"`和`"ba"`每个出现不止一次，并且它们的长度是`2`。 子串不再重复，所以答案是`2`。 

输入由单个小写英文字符串组成`s`， 在哪里：

-`1 <= s.length <= 2000`- 字符仅为小写英文字母。 

相对较小的极限`2000`表明二次或轻度三次解可能仍然可以接受，但极其昂贵的蛮力方法可能会很困难。 由于问题涉及检查重复的子串并找到最大有效长度，这自然建议二分查找与高效子串匹配相结合。 

一些边缘情况值得尽早识别：

 - 没有重复字符的字符串，例如`"abcd"`，应该返回`0`。 
- 包含所有相同字符的字符串，例如`"aaaaa"`，产生许多重叠的重复子串。 
- 非常短的字符串，尤其是长度`1`, 不能包含重复的子字符串。 
- Overlapping repetitions must be handled correctly. A naive implementation might incorrectly reject overlapping matches.

 ## 方法

 ### 蛮力方法

 A straightforward way to solve this problem is to generate every possible substring and count how many times it appears.

 We can iterate over all possible substring lengths from largest to smallest. 对于每个长度`L`，我们生成该长度的每个子字符串并将其存储在一个集合中。 如果我们再次遇到相同的子串，那么我们就知道存在重复的子串，并且可以立即返回`L`。 

例如，对于`"abbaba"`：

- 长度`5`: 没有重复
 - 长度`4`: 没有重复
 - 长度`3`: 没有重复
 - 长度`2`:`"ab"`出现两次，返回`2`这种方法之所以有效，是因为我们系统地检查每个可能的子字符串长度，并通过从最大到最小搜索来保证正确性。 

然而，子串提取本身的成本`O(L)`，并且我们检查许多长度的许多子串。 在最坏的情况下，它会变成立方体。 

### 最优方法，二分搜索+滚动哈希

 关键的观察是，如果长度的重复子串`L`存在，那么每个较小长度的重复子串也必须存在。 

例如：

 - 如果重复子串的长度`5`存在，
 - 然后重复长度前缀`4`,`3`,`2`， 和`1`也一定存在。 

这种单调性质使得该问题适合子字符串长度上的**二分搜索**。 

我们不是按顺序检查每个长度，而是对最大有效长度进行二分搜索。 

高效判断长度是否重复的子串`L`存在，我们使用**滚动哈希**。 我们不是逐个字符地比较子字符串，而是在预处理后在恒定时间内计算每个子字符串的哈希值。 

我们滑动一个大小的窗口`L`穿过字符串：

 - 计算每个子字符串的哈希值。 
- 将哈希值存储在集合中。 
- 如果相同的散列再次出现，则存在重复的子字符串。 

这减少了子字符串比较`O(L)`到`O(1)`平均时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n²) | 显式检查每个子字符串 |
 | 最优二分搜索 + 滚动哈希 | O(n log n) | O(n log n) | O(n) | 使用长度二分搜索和散列来快速检测重复项 |

 ## 算法演练

 ### 最优算法，二分查找+滚动哈希

 1. **初始化二分查找边界**

 由于子串长度范围为`1`到`n - 1`，我们设置：

 -`left = 1`-`right = len(s) - 1`我们还维护`answer = 0`。 
2. **对子串长度进行二分查找**

 计算：```
mid = (left + right) // 2
```这表示我们要测试的候选子串长度。 
3. **检查是否存在重复长度的子串`mid`存在**

 我们创建一个辅助函数来扫描所有长度的子字符串`mid`。 

我们不是重复提取原始子字符串，而是计算滚动哈希值。 
4. **滚动哈希的预计算能力**

 我们使用多项式滚动哈希：```
hash = (previous_hash * base + new_char) % mod
```我们还预先计算：```
base^L % mod
```这样我们就可以有效地删除离开滑动窗口的字符。 
5. **滑动窗户**

 对于每个长度的子串`L`:

 - 计算其哈希值
 - 检查哈希是否已存在于集合中
 - 如果是，请返回`True`- 否则，将其插入集合中
 6. **更新二分查找范围**

 如果长度存在重复的子串`mid`：

- 店铺`mid`作为有效答案
 - 搜索更长的子字符串```
left = mid + 1
```否则：```
right = mid - 1
```7. **返回最终答案**

 二分查找结束后，`answer`存储最大有效重复子串长度。 

### 为什么它有效

 正确性依赖于单调性。 

如果重复子串的长度`L`存在，那么每个较小长度的重复子串也必须存在。 这保证了搜索空间是有序的，使得二分搜索有效。 

滚动哈希保证了有效的重复检测，因为相等的子字符串会产生相同的哈希值。 由于我们只关心是否存在重复项，因此将哈希值存储在集合中可以让我们有效地检查重复。 

## Python 解决方案```python
class Solution:
    def longestRepeatingSubstring(self, s: str) -> int:
        n = len(s)

        def has_repeating_substring(length: int) -> bool:
            base = 26
            mod = 10**9 + 7

            current_hash = 0
            base_power = pow(base, length, mod)

            seen_hashes = set()

            for i in range(length):
                current_hash = (
                    current_hash * base
                    + (ord(s[i]) - ord('a'))
                ) % mod

            seen_hashes.add(current_hash)

            for i in range(length, n):
                current_hash = (
                    current_hash * base
                    - (ord(s[i - length]) - ord('a')) * base_power
                    + (ord(s[i]) - ord('a'))
                ) % mod

                if current_hash in seen_hashes:
                    return True

                seen_hashes.add(current_hash)

            return False

        left, right = 1, n - 1
        answer = 0

        while left <= right:
            middle = (left + right) // 2

            if has_repeating_substring(middle):
                answer = middle
                left = middle + 1
            else:
                right = middle - 1

        return answer
```实现首先定义一个名为的辅助函数`has_repeating_substring()`。 它的职责是确定是否存在特定长度的重复子串。 

在辅助函数内部，使用了滚动哈希。 我们首先计算初始窗口大小的哈希值`length`。 这用作起始子字符串。 

集合存储所有以前见过的哈希值。 当滑动窗口在字符串上移动时，我们会在恒定时间内更新哈希值，而不是从头开始重新计算。 

当哈希值已经存在于集合中时，我们立即返回`True`，表示找到了重复的子串。 

main 函数对子字符串长度执行二分搜索。 如果某个长度有效，我们会尝试更大的长度。 如果失败，我们会搜索较小的。 变量`answer`始终存储迄今为止发现的最佳有效长度。 

## 解决方案```go
func longestRepeatingSubstring(s string) int {
	n := len(s)

	hasRepeatingSubstring := func(length int) bool {
		const base = 26
		const mod = 1000000007

		currentHash := 0
		basePower := 1

		for i := 0; i < length; i++ {
			basePower = (basePower * base) % mod
		}

		seenHashes := make(map[int]bool)

		for i := 0; i < length; i++ {
			currentHash = (
				currentHash*base +
					int(s[i]-'a'),
			) % mod
		}

		seenHashes[currentHash] = true

		for i := length; i < n; i++ {
			currentHash = (
				currentHash*base -
					int(s[i-length]-'a')*basePower +
					int(s[i]-'a'),
			) % mod

			if currentHash < 0 {
				currentHash += mod
			}

			if seenHashes[currentHash] {
				return true
			}

			seenHashes[currentHash] = true
		}

		return false
	}

	left, right := 1, n-1
	answer := 0

	for left <= right {
		middle := left + (right-left)/2

		if hasRepeatingSubstring(middle) {
			answer = middle
			left = middle + 1
		} else {
			right = middle - 1
		}
	}

	return answer
}
```Go 实现遵循与 Python 相同的逻辑，但使用`map[int]bool`而不是 Python 集。 

Go 特定的一个重要细节是模行为。 在 Python 中，模自动保持正值。 在 Go 中，负模值仍然为负，因此我们显式添加`mod`必要时对哈希值进行标准化。 

另一个小区别是计算`basePower`手动使用循环而不是Python的内置循环`pow()`具有模数支持。

 ## 边缘情况

 ### 单字符串

 一个长度的字符串`1`不可能包含重复的子字符串。 如果二分搜索范围不正确，这很容易发生错误处理。 我们的实现安全地初始化：```
left = 1
right = n - 1
```什么时候`n = 1`,`right = 0`，因此二分查找永远不会运行并且函数正确返回`0`。 

### 重叠重复子串

 允许重叠匹配，这可能会导致幼稚的实现失败。 

例如：```
"aaaa"
```子串`"aaa"`出现两次：

 - 索引`0`- 指数`1`由于滑动窗口独立地检查每个位置，因此重叠的子串自然会被包含并正确检测到。 

### 无重复子串

 有些字符串根本不包含重复。 

例子：```
"abcdef"
```在这种情况下，每个二分查找检查都会失败，所以`answer`遗迹`0`。 返回初始化的默认值可确保正确性。 

### 所有字符都相同

 字符串如：```
"aaaaaa"
```产生许多重复的子串和许多重叠。 暴力解决方案变得昂贵，因为它反复比较相似的子串。 

滚动哈希方法可以有效地处理这个问题，因为子字符串比较通过哈希匹配变成恒定时间，从而使运行时间保持在接近`O(n log n)`。
