[LeetCode 问题 1059](https://leetcode.com/problems/all-paths-from-source-lead-to-destination/)

 **难度：** 🟡 中等
 **主题：** 图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个有向图`n`节点标记为`0`到`n - 1`。 每个有向边`[a, b]`表示从节点有一条单向路径`a`到节点`b`。 

我们还给出了两个特殊的节点：

 -`source`，每条路径的起点
 -`destination`，其中每条有效路径最终都必须结束

 任务是确定**所有可能的路径**是否从`source`同时满足三个条件：

 1. 至少存在一条路径`source`到`destination`2. 每条路径最终终止于`destination`3. 可能的路径总数是有限的

 第三个条件非常重要，因为它排除了可以从以下位置到达的循环：`source`。 如果我们可以进入一个循环并一直遍历下去，那么可能的路径数量是无限的，这立即得出答案`false`。 

The graph may contain:

 - Cycles
 - Self loops
 - Parallel edges
 - Dead end nodes

 死端节点是没有传出边的节点。 根据问题陈述，唯一有效的死胡同是`destination`。 如果可以从任何其他终端节点访问`source`，答案一定是`false`。 

限制条件是：

 - 最多`10^4`节点
 - 最多`10^4`边缘

 这告诉我们我们需要一个接近线性时间的算法。 指数路径枚举是不可能的，因为路径数量增长得非常快。 

一些边缘情况很重要：

 -`source`本身可能是一个死胡同
 - 图表可能包含可达循环
 -`destination`可能仍然有传出边缘，这可能会创建无效路径
 - 某些节点可能完全断开连接
 - 无法到达的循环`source`没关系

 关键的观察是我们不需要枚举所有路径。 相反，我们需要验证两个属性：

 - 除了`destination`- 不存在可达循环

 这自然表明深度优先搜索和循环检测。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试枚举从以下位置开始的所有可能路径：`source`。 

该算法将递归地探索每个传出边缘并跟踪当前的遍历路径。 如果到达死端节点，它检查该节点是否等于`destination`。 如果遇到循环，则必须确定存在无限多条路径。 

这种方法理论上是正确的，因为它直接检查每条可能的路径。 然而，它很快就变得不切实际。 

问题在于有向图中不同路径的数量可能呈指数增长。 即使在非循环图中，路径总数也可能是巨大的。 如果存在循环，则朴素遍历可能永远不会终止。 

例如，考虑一个分层图，其中每个节点分支为多个后继节点。 路径数量呈组合爆炸式增长。 

因为约束允许最多`10^4`节点和边，强力路径枚举太慢了。 

### 最佳方法

 最佳解决方案使用带有节点着色的深度优先搜索，也称为 DFS 状态标记。 

关键的见解是我们不需要单独生成每条路径。 相反，我们只需要验证每个可达节点是否满足所需的条件即可。 

对于每个节点，我们将其分为三种状态之一：

 - 未访问过
 - 目前正在探索中
 - 完全验证

 如果 DFS 到达当前正在探索的节点，那么我们找到了一个可到达的循环`source`，这意味着存在无限多条路径。 

如果 DFS 到达没有出边的节点，则该节点必须等于`destination`。 

一旦节点被完全验证，我们就会记住结果，这样将来的 DFS 调用就不会重新计算相同的子树。 

这将问题转化为线性图遍历。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(路径长度) | 枚举所有可能的路径 |
 | 最佳 | O(V + E) | O(V + E) | 具有循环检测和记忆功能的 DFS |

 ## 算法演练

 1. 从边列表构建邻接列表。 

我们需要快速访问每个节点的所有传出邻居。 邻接表是稀疏图的标准表示形式，可提供高效的遍历性能。 
2. 检查是否`destination`有传出边缘。 

如果`destination`有传出边缘，则有效路径可以继续经过假定的结束节点。 由于每条路径必须终止于`destination`，这会立即使图表无效。 
3. 维护一个访问状态数组。 

我们使用三种状态：

 -`0`= 未访问过
 -`1`= 当前访问
 -`2`= 完全处理和验证

 这允许有效的循环检测。 
4. 启动DFS`source`。 

DFS函数判断从当前节点出发的所有路径是否最终都通向`destination`。 
5. 如果当前节点没有出边，则验证其是否等于`destination`。 

仅当死胡同恰好是目标节点时才有效。 
6. 如果我们重新访问当前标记为访问的节点，我们会发现一个循环。 

这意味着无限多条路径是可能的，所以返回`false`。 
7. 如果一个节点已经被完全处理，则返回`true`。 

记忆可以防止重复工作并保证线性复杂性。 
8. 递归地验证每个邻居。 

每个传出边都必须通向有效的子树。 如果有一个邻居违反了规则，则当前节点无效。 
9. 当所有邻居都成功后，将该节点标记为已完全处理。 

这意味着该节点已经过验证并且可以在以后安全地重用。 
10.返回从以下位置开始的DFS结果`source`。 

### 为什么它有效

 该算法保持了一个不变量，即标记为完全处理的节点已被证明满足问题条件。 

循环检测保证不存在可到达的无限长路径`source`。 死端验证保证所有终止路径准确结束于`destination`。 由于 DFS 递归地检查每个可到达的传出边缘，因此每个可能的路径`source`被验证。 

因此，该算法正确地确定了所有路径是否来自`source`导致`destination`。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def leadsToDestination(
        self,
        n: int,
        edges: List[List[int]],
        source: int,
        destination: int
    ) -> bool:

        graph = defaultdict(list)

        for u, v in edges:
            graph[u].append(v)

        # Destination must be a terminal node
        if graph[destination]:
            return False

        # 0 = unvisited
        # 1 = visiting
        # 2 = verified
        state = [0] * n

        def dfs(node: int) -> bool:
            # Dead end node
            if not graph[node]:
                return node == destination

            # Cycle detected
            if state[node] == 1:
                return False

            # Already verified
            if state[node] == 2:
                return True

            state[node] = 1

            for neighbor in graph[node]:
                if not dfs(neighbor):
                    return False

            state[node] = 2

            return True

        return dfs(source)
```实现首先使用构建邻接表`defaultdict(list)`。 这允许每个节点有效地访问传出邻居。 

在DFS启动之前，代码检查是否`destination`有传出边缘。 如果是这样，那么路径可能会继续超出目的地，从而违反问题要求。 

这`state`数组跟踪循环检测和记忆的遍历进度。 节点标记为`1`当前位于递归堆栈中。 再次遇到这样的节点，说明是一个循环。 

在 DFS 函数内部，第一个检查处理死端节点。 如果一个节点没有出边，则只有当它等于`destination`。 

第二次检查检测循环。 第三次检查重用之前验证的结果。 

将当前节点标记为访问后，算法递归地验证所有邻居。 每个出边都必须满足条件。 如果任何递归调用返回`False`，当前节点无效。 

一旦所有邻居都成功，该节点将被标记为已验证并且 DFS 返回`True`。 

## 解决方案```go
func leadsToDestination(n int, edges [][]int, source int, destination int) bool {
	graph := make([][]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]
		graph[u] = append(graph[u], v)
	}

	// Destination must not have outgoing edges
	if len(graph[destination]) > 0 {
		return false
	}

	// 0 = unvisited
	// 1 = visiting
	// 2 = verified
	state := make([]int, n)

	var dfs func(int) bool

	dfs = func(node int) bool {
		// Dead end node
		if len(graph[node]) == 0 {
			return node == destination
		}

		// Cycle detected
		if state[node] == 1 {
			return false
		}

		// Already verified
		if state[node] == 2 {
			return true
		}

		state[node] = 1

		for _, neighbor := range graph[node] {
			if !dfs(neighbor) {
				return false
			}
		}

		state[node] = 2

		return true
	}

	return dfs(source)
}
```Go 实现遵循与 Python 版本相同的逻辑。 邻接列表使用切片的切片来表示。 

Go 没有具有自动默认值的 Python 风格字典，因此我们初始化`graph`作为`make([][]int, n)`。 

DFS 函数被声明为一个闭包，使用`var dfs func(int) bool`。 

状态跟踪使用与 Python 版本完全相同的整数切片。 

由于 Go 切片默认为`nil`, 检查`len(graph[node]) == 0`即使切片从未初始化，也可以正确进行死端检测。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(V + E) | Each node and edge is processed at most once |
 | 空间| O(V + E) | 邻接表加递归栈和状态数组 |

 邻接表将每条边恰好存储一次，要求`O(E)`空间。 状态数组需要`O(V)`空间。 

在DFS期间，每个节点仅在状态之间转换一次，并且在递归期间每条边被遍历一次。 因此，总运行时间与图的大小成线性关系。 

递归堆栈可能会增长到`O(V)`在深度图的最坏情况下。

from typing import List

class Solution:
    def leadsToDestination(
        self,
        n: int,
        edges: List[List[int]],
        source: int,
        destination: int
    ) -> bool:

        from collections import defaultdict

        graph = defaultdict(list)

        for u, v in edges:
            graph[u].append(v)

        if graph[destination]:
            return False

        state = [0] * n

        def dfs(node: int) -> bool:
            if not graph[node]:
                return node == destination

            if state[node] == 1:
                return False

            if state[node] == 2:
                return True

            state[node] = 1

            for neighbor in graph[node]:
                if not dfs(neighbor):
                    return False

            state[node] = 2

            return True

        return dfs(source)

 ## 边缘情况

 一种重要的边缘情况发生时`source`节点本身就是一个死胡同。 如果`source`没有出边，那么答案仅在以下情况下有效`source == destination`。 幼稚的实现可能会错误地返回`true`只是因为遍历立即结束。 DFS 实现通过死端检查正确处理此问题。 

另一个重要的情况涉及可达周期。 循环意味着有无限多种可能的路径，因为遍历可以永远持续下去。 如果实现仅检查某些路径是否到达目的地，则很容易错过这一点。 访问状态数组在 DFS 期间正确检测到后沿并立即返回`false`。 

第三种微妙的情况是当`destination`本身有传出边缘。 即使每条路最终都到达`destination`，传出边的存在意味着路径可以继续经过它。 由于该问题要求所有路径终止于`destination`，这种情况必须返回`false`。 实现在 DFS 开始之前显式检查这一点。 

第四个重要的边缘情况涉及断开的图形组件。 该图可能包含与以下内容完全无关的循环或死胡同`source`。 这些应该不会影响答案。 由于 DFS 只探索可到达的节点`source`，不可达的组件自然会被忽略。 

最后一个棘手的情况是平行边。 该图可以包含两个节点之间的多个相同的有向边。 DFS 实现独立处理每条边，但记忆化确保节点不会被冗余地重新计算，因此保留了正确性和效率。
