[LeetCode 第 1088 题](https://leetcode.com/problems/confusing-number-ii/)

 **难度：** 🔴难
 **主题：** 数学、回溯

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给定一个整数`n`，我们必须计算该范围内有多少个数字`[1, n]`被认为是令人困惑的数字。 

如果将每个数字旋转后，一个数字就会变成令人困惑的数字`180`度，结果数字是：

 1. 轮换后有效
 2、与原号码不同

 轮换后只有五位数字仍然有效：

 | 原创| 旋转|
 | ---| ---|
 | 0 | 0 |
 | 1 | 1 |
 | 6 | 9 |
 | 8 | 8 |
 | 9 | 6 |

 数字`2`,`3`,`4`,`5`， 和`7`无效，因为它们在旋转后不会形成可识别的数字。 

旋转过程也会自然地反转数字位置。 例如：

-`16`变成`91`-`89`变成`68`-`8000`变成`0008`，这被视为`8`任务不是生成旋转的数字本身，而是计算有多少个有效的混淆数字存在`1`通过`n`。 

约束条件`1 <= n <= 10^9`非常重要。 自从`n`可以大到十亿，迭代每个数字并检查它是否令人困惑可能会变得昂贵。 需要更智能的发电策略。 

一些边缘情况很重要：

 - 包含无效数字的号码必须立即被拒绝。 
- 像这样的数字`11`,`88`， 或者`69`旋转到自身，因此不会造成混乱。 
- 必须正确忽略旋转后的前导零。 
- 号码`0`本身不包括在内，因为范围从`1`。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代每个整数`1`到`n`。 

对于每个数字：

 1. 提取每个数字。 
2. 确认所有数字均可旋转。 
3. 通过反转数字顺序并应用旋转映射来构建旋转数。 
4. 将旋转后的数字与原始数字进行比较。 
5. 计算它们是否不同。 

这种方法是正确的，因为它明确地检查每个可能的候选者。 

然而，它的效率很低。 如果`n = 10^9`，我们可能需要检查十亿个数字。 尽管每次检查只需要`O(log n)`时间，总运行时间变得太大。 

### 最优方法，回溯生成

 关键的观察是只有数字组成的数字`{0,1,6,8,9}`可能是有效的。 

而不是检查来自的所有数字`1`到`n`，我们只生成包含有效数字的数字。 

这极大地减少了搜索空间。 

例如：

 - 9 位数字通常有`10^9`的可能性。 
- 仅使用 5 个有效数字最多给出`5^9 = 1,953,125`的可能性。 

这要小得多且易于管理。 

我们使用深度优先搜索（DFS）或回溯来逐位构造有效数字。 

对于每个生成的数字：

 1. 确保不超过`n`2.检查旋转后的形状是否与原来不同
 3.如果混淆就数一下
 4. 继续用更多有效数字扩展它

 这避免了完全探索不可能的候选者。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(log n) | 单独检查每个数字 |
 | 最佳| O(5^d × d) | O(5^d × d) | O(d) | 仅生成有效的候选者，其中`d`是位数 |

 自从`n <= 10^9`，最大位数为`10`，使回溯解决方案变得高效。 

## 算法演练

 ### 第 1 步，存储有效旋转

 我们首先定义旋转映射：```
{
    0: 0,
    1: 1,
    6: 9,
    8: 8,
    9: 6
}
```这使我们能够有效地轮换任何有效数字。 

### 步骤 2，定义 DFS 生成

 我们仅使用有效数字递归地构建数字。 

在每次递归调用时：

 - 我们有一个部分建成的号码
 - 我们尝试再追加一位有效数字
 - 如果数量超过，我们就会停止`n`这确保了所有生成的数字在轮换后都可能有效。 

### 步骤 3，跳过前导零

 我们从不以`0`。 

否则我们会生成重复项，例如：

 -`01`-`001`-`0001`所有这些都代表相同的数字。 

### 步骤 4，检查数字是否令人困惑

 对于每个生成的数字：

 1. 旋转每一位数字
 2. 颠倒数字顺序
 3.构造旋转数
 4. 与原版比较

 如果旋转的数字不同，则该数字会令人困惑。 

### 步骤5，继续递归

 处理完当前数字后，继续递归附加更多数字。 

这探索了整个有效的搜索空间。 

## 为什么它有效

 该算法生成旋转后可能有效的每个数字，因为它仅使用可旋转的数字。 

不会遗漏有效的候选数字，因为 DFS 会探索有效数字的每个组合，最多可达`n`。 

不包括无效候选者，因为永远不会生成包含无效数字的数字。 

混淆检查保证我们只计算旋转形式与原始形式不同的数字。 

因此，该算法正确地计算了所有令人困惑的数字`[1, n]`。 

## Python 解决方案```python
class Solution:
    def confusingNumberII(self, n: int) -> int:
        rotation = {
            0: 0,
            1: 1,
            6: 9,
            8: 8,
            9: 6
        }

        valid_digits = [0, 1, 6, 8, 9]

        def is_confusing(num: int) -> bool:
            original = num
            rotated = 0

            while num > 0:
                digit = num % 10
                rotated = rotated * 10 + rotation[digit]
                num //= 10

            return rotated != original

        def dfs(current: int) -> int:
            count = 0

            if current > n:
                return 0

            if current != 0 and is_confusing(current):
                count += 1

            for digit in valid_digits:
                if current == 0 and digit == 0:
                    continue

                next_number = current * 10 + digit

                if next_number <= n:
                    count += dfs(next_number)

            return count

        return dfs(0)
```该解决方案首先存储旋转映射和有效数字列表。 

这`is_confusing()`辅助函数计算数字的旋转版本。 它从右到左处理数字并逐步构建旋转数字。 

例如：

-`16`- 过程`6 → 9`- 过程`1 → 1`- 结果变成`91`DFS 函数递归地生成所有有效数字。 

递归开始于`0`， 但`0`其本身永远不会被计算在内。 

对于每个生成的数字：

 1. 如果超过`n`，递归停止。 
2. 如果令人困惑，请增加答案。 
3. 附加每个有效数字并继续搜索。 

前导零检查可防止重复构造。 

因为只使用有效数字，所以每个生成的数字都保证可旋转。 

## 解决方案```go
func confusingNumberII(n int) int {
    rotation := map[int]int{
        0: 0,
        1: 1,
        6: 9,
        8: 8,
        9: 6,
    }

    validDigits := []int{0, 1, 6, 8, 9}

    var isConfusing func(int) bool

    isConfusing = func(num int) bool {
        original := num
        rotated := 0

        for num > 0 {
            digit := num % 10
            rotated = rotated*10 + rotation[digit]
            num /= 10
        }

        return rotated != original
    }

    var dfs func(int) int

    dfs = func(current int) int {
        if current > n {
            return 0
        }

        count := 0

        if current != 0 && isConfusing(current) {
            count++
        }

        for _, digit := range validDigits {
            if current == 0 && digit == 0 {
                continue
            }

            nextNumber := current*10 + digit

            if nextNumber <= n {
                count += dfs(nextNumber)
            }
        }

        return count
    }

    return dfs(0)
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于 Go 使用显式函数变量进行递归闭包。 

旋转映射是使用以下实现的`map[int]int`，DFS 递归返回所有分支累积的计数。 

Go 整数可以安全地处理问题约束，因为`n <= 10^9`。

 ## 边缘情况

 一种重要的边缘情况是数字会自行旋转。 例子包括`1`,`8`,`11`， 和`69`。 幼稚的实现可能会仅仅因为它们包含有效数字而错误地计算它们。 该算法通过显式构造旋转值并检查它是否与原始数字不同来避免这种情况。 

另一个重要的情况涉及旋转后的前导零。 例如，`10`旋转成`01`，应解释为`1`。 如果实现直接比较数字字符串，它可能会错误地处理`"01"`不同于`1`。 数字结构自然会删除前导零，因此比较仍然正确。 

第三个重要的边缘情况是在 DFS 生成期间防止数字带有前导零。 如果没有这个限制，递归可能会生成重复项，例如`01`,`001`， 和`0001`。 该实现通过跳过数字来防止这种情况`0`构造数字的第一位数字时。 

最后，上约束`n = 10^9`需要仔细修剪。 当当前数量超过时，DFS立即停止递归`n`，确保算法即使在最大输入大小下也保持高效。
