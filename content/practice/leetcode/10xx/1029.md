[LeetCode 问题 1029](https://leetcode.com/problems/two-city-scheduling/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有一个数组叫做`costs`，其中每个元素代表一个人到两个不同城市的旅行成本。 具体来说，`costs[i] = [aCosti, bCosti]`方法：

-`aCosti`是飞行人员的成本`i`前往A市
 -`bCosti`是飞行人员的成本`i`前往B市

 正好有`2n`人，我们必须准确地发送`n`人们到 A 市并且准确地`n`人到B市。 

目标是在满足均等分配要求的同时，最小化总旅行成本。 

例如，如果一个人发送到A城市的费用比B城市低得多，我们会更愿意将其发送到A城市。但是，我们不能简单地为每个人选择更便宜的城市，因为我们必须保持两个城市之间的人数平衡。 

限制相对较小：

 -`2 <= costs.length <= 100`-`costs.length`总是均匀的
 - 成本为正整数

 尽管输入量并不大，但问题本质上是组合性的，因为每个人都有两个选择。 一个简单的解决方案可以尝试所有可能的分配，但组合的数量呈指数级增长。 

需要考虑一些重要的边缘情况：

 - 多个人在两个城市的费用可能相同。 
- 有些人可能会强烈喜欢一个城市而不是另一个城市。 
- 对一个人来说最便宜的本地决策可能会妨碍全局最优平衡分配。 
- 由于每个城市都有一半的人必须前往，因此我们必须仔细跟踪计数。 

该问题保证了有效的输入，因此我们不需要处理格式错误的数组或奇数长度。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试将人员分配到城市的所有可能方式，同时确保每个城市都有一半的人员分配。 

对于每个人来说，我们有两个选择：

 - 把他们送到A市
 - 把他们送到B市

 这创造了`2^(2n)`总共可能的任务。 然后我们将过滤准确发送的作业`n`人们到每个城市并计算最小总成本。 

这种方法保证找到正确的答案，因为它详尽地检查了每个有效的排列。 然而，由于组合的数量呈指数级增长，计算量很快就会变得昂贵。 

即使只有 100 人，暴力破解也是完全不切实际的。 

### 最佳解决方案的关键见解

 重要的观察是，重要的不是每个城市的绝对成本，而是派人去城市 A 和城市 B 之间的_差异_。 

对于每个人，计算：$$aCost - bCost$$该值告诉我们城市 A 与城市 B 相比便宜或贵了多少。 

- 较大的负值意味着城市 A 便宜得多。 
- 较大的正值意味着城市 B 便宜得多。 

如果我们按照这种差异对人进行排序：

 - 强烈喜欢A城市的人首先出现。 
- 强烈喜欢B城市的人最后出现。 

然后我们可以：

 - 发送第一个`n`人到A市
 - 发送剩余的`n`前往B市的人

 这种贪婪策略之所以有效，是因为按成本差异排序可以确保对 A 城市具有最大优势的人首先被分配到那里。

 ## 算法演练

 1. 对于每个人，计算他们飞往城市 A 和城市 B 之间的差异。 

区别在于：$$aCost - bCost$$负差意味着 A 城市更便宜。 正差值意味着 B 城市更便宜。 
2. 根据这种差异对人员进行排序。 

排序后：

 - 人们一开始就非常喜欢A城市。 
- 最后的人强烈喜欢B城市。 
3、将排序好的前半部分人送到A市。 

由于这些人的差异最小，所以将他们分配到A市最省钱。 
4、将排序后的后半部分人员送往B市。 

这些人要么更喜欢B城市，要么去那里损失最少的钱。 
5. 将所有选定的旅行费用相加并返回总额。 

### 为什么它有效

 贪心财产来自比较相对储蓄。 

假设两个人分配不正确：

 - 一名非常喜欢A城市的人被派往B城市。 
- 另一个强烈喜欢B城市的人被送到A城市。 

交换他们的任务总是会降低总成本。 

按差异排序`aCost - bCost`保证首先选择对A市利益最大的人。 因此，排序后不存在更好的重新分配。 

## Python 解决方案```python
from typing import List

class Solution:
    def twoCitySchedCost(self, costs: List[List[int]]) -> int:
        costs.sort(key=lambda person: person[0] - person[1])

        n = len(costs) // 2
        total_cost = 0

        for i in range(n):
            total_cost += costs[i][0]

        for i in range(n, 2 * n):
            total_cost += costs[i][1]

        return total_cost
```该实现首先使用城市 A 和城市 B 的成本差异对数组进行排序。```python
person[0] - person[1]
```该值决定了一个人对城市 A 的偏好程度超过对城市 B 的偏好程度。 

排序后，数组的前半部分包含最适合 A 城市的人，后半部分包含最适合 B 城市的人。 

我们计算`n`作为人数的一半。 然后：

 - 第一个循环增加了城市 A 的第一个循环成本`n`人们。 
- 第二个循环增加了城市 B 的剩余成本`n`人们。 

最后返回总的最小成本。 

## 解决方案```go
import "sort"

func twoCitySchedCost(costs [][]int) int {
	sort.Slice(costs, func(i, j int) bool {
		return (costs[i][0] - costs[i][1]) < (costs[j][0] - costs[j][1])
	})

	n := len(costs) / 2
	totalCost := 0

	for i := 0; i < n; i++ {
		totalCost += costs[i][0]
	}

	for i := n; i < 2*n; i++ {
		totalCost += costs[i][1]
	}

	return totalCost
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

主要区别在于使用`sort.Slice`使用自定义比较器函数对二维切片进行排序。 

Go 切片是类似引用的结构，因此排序会就地修改原始切片。 

整数溢出不是问题，因为最大可能的总成本完全在 Go 的整数范围内。

 ## 边缘情况

 当多个人在两个城市的成本相同时，就会出现一种重要的边缘情况。 在这种情况下，差异`aCost - bCost`对于许多条目来说变为零。 有缺陷的实现可能会错误地认为严格的排序是必要的。 基于排序的解决方案自然地处理了这个问题，因为等差人员之间的任何分配都会产生相同的总贡献。 

另一个重要的边缘情况是每个人都强烈喜欢同一个城市。 例如，每个人发送到城市 A 的费用可能要便宜得多。总是选择每人最便宜的城市的天真的贪婪解决方案将会失败，因为它违反了每个城市有一半的人去的要求。 实现的算法通过均匀排序和拆分来正确平衡分配。 

最小输入大小也很重要。 当只有两个人时，每个城市必须有一个人去。 小输入的分区逻辑中经常出现差一错误。 实现正确计算：```
n = len(costs) // 2
```并使用精确的环路边界来确保每个城市恰好接待一个人。 

最后一个边缘情况涉及巨大的成本差异。 有些人可能会因为走错城市而受到巨额处罚。 按差异排序可确保算法首先优先考虑那些影响较大的决策，从而防止代价高昂的错误分配。
