[LeetCode 问题 1081](https://leetcode.com/problems/smallest-subsequence-of-distinct-characters/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、贪婪、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们构造一个字符串的字典顺序最小的子序列，其中每个不同的字符恰好包含一次。 

子序列是通过删除零个或多个字符而不改变剩余字符的相对顺序而形成的。 这很重要，因为我们不允许任意重新排列字符。 最终答案必须保留字符在原始字符串中出现的顺序。 

我们得到一个字符串`s`仅由小写英文字母组成。 有些字符可能会出现多次。 我们的目标是删除重复项，同时准确保留每个不同字符的一次出现，但我们必须以一种产生尽可能最小的词典结果的方式来实现。 

词典顺序与词典中使用的顺序相同。 例如：

-`"abc"`小于`"acb"`-`"acdb"`小于`"adbc"`限制相对较小：

 -`1 <= s.length <= 1000`- 只出现小写英文字母

 尽管输入大小不是很大，但由于子序列的数量呈指数级增长，暴力方法很快就变得不可行。 

有几个重要的观察结果和边缘情况：

 - 一个角色可能出现多次，但最终答案只能包含一次。 
- 我们不能简单地对不同的字符进行排序，因为必须保留原始字符串的相对顺序。 
- 有时，如果较早出现的字符稍后再次出现，我们应该删除该字符，并且替换它会创建较小的词典结果。 
- 顺序已经递增的字符串，例如`"abc"`，应保持不变。 
- 具有重复递减模式的字符串，例如`"cbacdcbc"`，需要仔细的堆栈操作才能获得最佳答案。 

关键的挑战是同时平衡两个要求：

 1. 每个不同的字符必须恰好出现一次。 
2. 生成的子序列必须是字典顺序最小的。 

## 方法

 ### 蛮力方法

 强力解决方案将生成字符串的所有可能的子序列并过滤那些：

 1. 每个不同的字符只包含一次。 
2. 保留后续顺序。 
3. 正确的长度等于不同字符的数量。 

在所有有效的子序列中，我们会选择字典顺序最小的一个。 

这种方法是正确的，因为它详尽地检查了每一个可能的候选者。 然而，一个长度的字符串`n`有`2^n`子序列。 即使对于中等大小的输入，这在计算上也是不可能的。 

例如，如果`n = 1000`，子序列的数量是天文数字。 

### 最优贪婪+单调堆栈方法

 有效的解决方案依赖于贪婪策略与堆栈的结合。 

主要的见解是：

 从左到右构建答案时，如果当前字符小于堆栈顶部的字符，并且顶部字符稍后再次出现，则删除较大的字符现在会导致按字典顺序更小的结果，而不会永久丢失该字符。 

这一观察使我们能够在每一步贪婪地维护尽可能小的子序列。 

我们使用：

 - 用于构建结果的堆栈
 - 频率计数器可了解某个字符是否稍后出现
 - 一组用于跟踪已包含的字符

 堆栈的行为就像一个单调结构，只要安全且有益，我们就会删除较大的字符。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 生成所有子序列并过滤有效子序列 |
 | 最佳 | O(n) | O(1) | O(1) | 带有字符跟踪的贪婪单调堆栈 |

 ## 算法演练

 1. 统计字符串中每个字符出现的频率。 

我们需要知道某个角色稍后是否会再次出现。 此信息确定从堆栈中删除字符是否安全。 
2. 初始化一个空堆栈。 

堆栈存储我们当前最佳子序列的字符。 
3. 初始化一个名为`in_stack`。 

这有助于我们避免在结果中添加重复的字符。 
4. 迭代字符串中的每个字符。 

对于每个角色：

 - 减少其剩余频率，因为我们当前正在处理一个事件。 
- 如果该字符已经在堆栈中，则跳过它，因为我们只想出现一次。 
5. 当堆栈不为空时，检查当前字符是否应替换顶部字符。 

如果所有三个条件都成立，我们将删除顶部字符：

 - 堆栈不为空。 
- 当前字符按字典顺序小于顶部字符。 
- 顶部的角色稍后会再次出现。 

如果所有条件都成立，则删除顶部字符可以改善字典顺序，并且仍然安全，因为我们可以稍后重新插入该字符。 
6. 将当前字符压入堆栈。 

删除任何较大的不必要字符后，我们将当前字符添加到子序列中。 
7. 将字符标记为存在于堆栈中。 
8.处理完所有字符后，将堆栈加入成字符串。 

这会产生最终的字典顺序最小的子序列。 

### 为什么它有效

 该算法保持了这样的不变性：堆栈始终表示仍然可以完成为有效的最终答案的最小字典顺序子序列。 

每当较大的字符出现在较小的字符之前，并且较大的字符稍后仍可以使用时，将其删除会立即改善答案。 由于我们永远不会删除某个字符，除非它稍后再次出现，因此我们永远不会失去一次包含所有不同字符的能力。 

这种贪婪的选择总是最优的，因为字典顺序是从左到右确定的。 使早期的字符尽可能小可以保证全局最小的答案。 

## Python 解决方案```python
class Solution:
    def smallestSubsequence(self, s: str) -> str:
        remaining_count = {}

        for char in s:
            remaining_count[char] = remaining_count.get(char, 0) + 1

        stack = []
        in_stack = set()

        for char in s:
            remaining_count[char] -= 1

            if char in in_stack:
                continue

            while (
                stack
                and char < stack[-1]
                and remaining_count[stack[-1]] > 0
            ):
                removed_char = stack.pop()
                in_stack.remove(removed_char)

            stack.append(char)
            in_stack.add(char)

        return "".join(stack)
```该实现首先计算每个字符在字符串中出现的次数。 这允许算法确定是否可以安全地从堆栈中删除字符并稍后重新插入。 

这`stack`存储当前正在构建的子序列。 这`in_stack`set 确保每个字符在堆栈中最多出现一次。 

对于输入字符串中的每个字符，算法首先减少其剩余计数，因为现在已经处理了一个出现的字符。 

如果该字符已存在于堆栈中，则立即跳过。 这强制要求每个不同的字符只出现一次。 

否则，算法检查当前字符是否应替换当前子序列末尾附近的较大字符。 这`while`循环重复删除堆栈元素，只要：

 - 堆栈不为空。 
- 当前字符较小。 
- 删除的角色稍后会再次出现。 

这种贪婪的改进确保了词典编纂的最小性。 

最后，该字符被推入堆栈并标记为存在。 

最后，加入堆栈会产生最终答案。 

## 解决方案```go
func smallestSubsequence(s string) string {
	remainingCount := make(map[byte]int)

	for i := 0; i < len(s); i++ {
		remainingCount[s[i]]++
	}

	stack := make([]byte, 0)
	inStack := make(map[byte]bool)

	for i := 0; i < len(s); i++ {
		char := s[i]
		remainingCount[char]--

		if inStack[char] {
			continue
		}

		for len(stack) > 0 &&
			char < stack[len(stack)-1] &&
			remainingCount[stack[len(stack)-1]] > 0 {

			removedChar := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			delete(inStack, removedChar)
		}

		stack = append(stack, char)
		inStack[char] = true
	}

	return string(stack)
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个`map[byte]int`存储剩余频率，因为字符串仅包含小写英文字母。 堆栈是使用字节片实现的，它提供高效的追加和弹出操作。 

这`inStack`map 跟踪堆栈中是否已存在字符。 

Go 中的一个实现细节是堆栈弹出。 由于切片没有内置的弹出操作，因此代码使用以下方法删除最后一个元素：```go
stack = stack[:len(stack)-1]
```最后的字节片在返回​​之前被转换回字符串。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符最多被压入和弹出一次 |
 | 空间| O(1) | O(1) | 最多存储26个小写英文字母 |

 该算法对每个字符只处理一次。 虽然内在`while`循环可能显得昂贵，每个字符在整个执行过程中只能被压入和弹出一次。 因此，总工作量保持线性。 

从技术上讲，空间复杂度受字母表大小的限制。 由于只允许使用小写英文字母，因此不同字符的最大数量为 26，这是恒定的空间。

 ## 边缘情况

 当所有字符都相同时会出现一种重要的边缘情况，例如`"aaaa"`。 幼稚的实现可能会意外地包含同一字符的多个副本。 该算法使用以下方法正确处理这个问题`in_stack`set，这可以防止将重复项插入到堆栈中。 

另一个棘手的情况是严格递减序列，例如`"cba"`。 将字符重新排列成`"abc"`，但这会违反子序列排序规则。 由于字符必须保留其原始相对位置，因此正确答案仍然存在`"cba"`。 该算法自然地尊重这一点，因为它只会在字符稍后再次出现时删除它们。 

当不应删除较大的字符时，会出现更微妙的边缘情况，因为它以后不会再出现。 例如，在`"cbacdcbc"`, 处理时`'b'`，堆栈包含`'d'`。 虽然`'b'`按字典顺序小于`'d'`，去除`'d'`会永远失去它，因为没有未来`'d'`存在。 条件：```
remaining_count[stack[-1]] > 0
```防止这种错误并保证正确性。 

另一个重要的场景涉及已经最优的字符串，例如`"abc"`。 该算法不应不必要地修改序列。 由于后来没有出现更小的字符来证明弹出是合理的，因此堆栈只是按顺序增长并返回原始字符串不变。
