[LeetCode 问题 1053](https://leetcode.com/problems/previous-permutation-with-one-swap/)

 **难度：** 🟡 中等
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 该问题要求我们仅使用一次交换操作来找到按字典顺序排列且仍小于给定数组的最大排列。 

如果在两个数组不同的第一个位置，新数组具有较小的值，则排列被认为按字典顺序较小。 例如：

-`[3,1,2]`小于`[3,2,1]`因为在索引处`1`,`1 < 2`-`[1,7,4,6,9]`小于`[1,9,4,6,7]`因为在索引处`1`,`7 < 9`重要的是我们不想要任何较小的排列。 我们希望通过一次交换获得所有较小排列中可能最大的排列。 

输入数组可以包含重复值，这会带来一个重要的复杂性。 如果我们交换错误的重复出现，我们可能会产生比所需的更小的排列。 

限制条件是：

 -`1 <= arr.length <= 10^4`-`1 <= arr[i] <= 10^4`由于数组长度可以大到`10^4`，比二次时间更差的算法变得有风险。 我们的目标应该是`O(n)`或者`O(n log n)`解决方案。 

一些边缘情况很重要：

 - 数组可能已经是最小可能的排列，例如`[1,1,5]`- 数组可能包含重复项
 - 下降点可能出现在开头或结尾附近
 - 选择错误的重复元素进行交换可能会产生非最佳答案

 关键的挑战是找到一种单一交换，既能尽可能少地减少排列，又能使其更小。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试每对可能的索引`(i, j)`在哪里`i < j`，交换元素，并检查结果数组按字典顺序是否小于原始数组。 

在所有有效的较小排列中，我们将保留最大的排列。 

这种方法是正确的，因为它详尽地评估了每一种可能的交换排列。 由于考虑了每一个合法的交换，因此不会错过最佳答案。 

然而，时间复杂度是昂贵的。 有`O(n^2)`可能的交换，并比较排列成本`O(n)`。 这导致了整体的复杂性`O(n^3)`。 

和`n = 10^4`，这太慢了。 

### 最优贪心法

 重要的观察是，词典顺序由最早的不同位置主导。 

要创建仍然小于原始数组的最大排列：

 1.我们应该将数组修改得尽可能靠右
 2. 在该位置，我们应该将值减少尽可能小的量

 这与查找“先前的排列”非常相似。 

我们从右向左扫描寻找第一个索引`i`在哪里：```
arr[i] > arr[i + 1]
```这确定了我们可以使排列更小的第一个位置。 

一旦我们找到这样的索引：

 - 我们必须交换`arr[i]`其右侧的最大值仍小于`arr[i]`- 如果存在重复项，我们应该在相同的候选者中选择最左边的出现者

 重复处理很微妙但很关键。 与最左边的重复项交换会得到按字典顺序排列的最大结果。 

这种贪婪策略在线性时间内有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 尝试每次交换并比较所有排列 |
 | 最佳 | O(n) | O(1) | O(1) | 从右向左贪婪扫描 |

 ## 算法演练

 1. 从倒数第二个元素开始向数组开头扫描。 

我们寻找第一个索引`i`这样：```
arr[i] > arr[i + 1]
```这是数组停止从右到左非递减的第一个位置。 如果不存在这样的索引，则该数组已经是最小排列，因此我们将其原封不动地返回。 
2. 一旦枢轴索引`i`找到后，向右搜索`i`寻找最佳的交换元素。 

我们需要小于的最大值`arr[i]`。 
3. 搜索时，小心处理重复项。 

假设几个元素具有相同的候选值。 我们应该选择该值最左边出现的位置。 

这最大化了所得的排列。 
4. 交换两个元素。 

交换后，数组立即成为通过一次交换可实现的字典顺序最大的较小排列。 
5. 返回修改后的数组。 

### 为什么它有效

 词典顺序在很大程度上取决于前面的位置。 要获得小于原始排列的最大排列：

 - 我们尽可能推迟变更
 - 在该位置，我们将值减少尽可能小的量

 从右侧第一个递减的位置正是最佳变化必须发生的位置。 与最大的较小值交换可确保减少最小。 选择最左边的重复项会保留后缀中较早的较大值，从而最大化结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def prevPermOpt1(self, arr: List[int]) -> List[int]:
        n = len(arr)

        # Step 1: Find the first decreasing position from the right
        i = n - 2

        while i >= 0 and arr[i] <= arr[i + 1]:
            i -= 1

        # Already the smallest permutation
        if i < 0:
            return arr

        # Step 2: Find the largest element smaller than arr[i]
        j = n - 1

        while arr[j] >= arr[i]:
            j -= 1

        # Step 3: Handle duplicates
        while j > 0 and arr[j] == arr[j - 1]:
            j -= 1

        # Step 4: Swap
        arr[i], arr[j] = arr[j], arr[i]

        return arr
```实现直接遵循贪婪策略。 

首先，我们从右向左扫描以找到枢轴索引`i`。 这是第一个可以按字典顺序缩减数组的地方。 

如果不存在主元，则数组已按非降序排序，这意味着它已经是最小可能的排列。 

接下来，我们从数组末尾开始查找，找出小于的最大值`arr[i]`。 从末尾开始确保我们首先遇到最大的有效候选者。 

重复处理循环至关重要。 如果存在多个相等的候选者，我们向左移动到该重复块的第一次出现。 这会产生按字典顺序排列的最大有效结果。 

最后，我们将主元与选定的候选者交换并返回数组。 

## 解决方案```go

	// Step 1: Find first decreasing position from the right
	i := n - 2

	for i >= 0 && arr[i] <= arr[i+1] {
		i--
	}

	// Already smallest permutation
	if i < 0 {
		return arr
	}

	// Step 2: Find largest element smaller than arr[i]
	j := n - 1

		j--
	}

		j--
	}

	// Step 4: Swap

```Go 的实现与 Python 解决方案非常相似。 

Go 中的切片是可变的，因此该函数直接修改输入切片并返回它。 

不需要特殊的溢出处理，因为所有操作都是问题约束内整数的简单比较和交换。 

与 Python 不同，Go 内部不提供元组解包，但 Go 支持同时赋值以干净地交换值。

 ## 边缘情况

 当数组已经是可能的最小排列时，就会出现一种重要的边缘情况，例如`[1,1,5]`或者`[1,2,3,4]`。 在这些情况下，没有索引`i`在哪里`arr[i] > arr[i+1]`。 有错误的实现可能仍会尝试交换或访问无效索引。 该算法通过检查主元索引是否存在来处理此问题。 如果不是，它立即返回原始数组不变。 

另一个微妙的边缘情况涉及重复值。 考虑`[3,1,1,3]`。 如果我们交换`3`与最右边的`1`，我们得到`[3,1,1,3] -> [3,1,1,3]`，这是不正确的。 我们必须与相同候选者中最左边的出现位置进行交换，以最大化结果排列。 重复的跳过循环确保了这种行为。 

当主元接近数组末尾时，会发生第三种重要的边缘情况，例如`[5,4,3,2,1]`。 这里，只有最后两个元素需要交换。 一些实现错误地继续搜索更复杂的重新排列。 该算法正确识别最右边的主元并执行一次最佳交换。 

最后一种边缘情况涉及长度为一的数组。 由于不可能进行交换，因此数组必须按原样返回。 该实现自然会处理这个问题，因为主元搜索立即失败。
