[LeetCode 问题 1003](https://leetcode.com/problems/check-if-word-is-valid-after-substitutions/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们判断给定的字符串是否可以通过重复插入子串来构造`"abc"`进入一个最初为空的字符串。 

操作非常具体。 在任何时候，我们都可以获取当前字符串并插入`"abc"`在任何位置。 由于插入可能发生在任何地方，因此有效字符串可能包含并非立即显而易见的嵌套或交错模式。 

例如：

 - 从`""`- 插入`"abc"`→`"abc"`- 插入`"abc"`中间→`"aabcbc"`输入仅包含字符`'a'`,`'b'`， 和`'c'`，字符串长度可以大到`2 * 10^4`。 这立即表明指数或重复重新扫描方法可能会变得太慢。 

预期输出是：

 -`true`如果字符串可以完全通过 valid 形成`"abc"`插入
 -`false`否则

 一个重要的观察是，每个有效的插入最终都会创建减少回的组`"abc"`。 如果我们能够反复识别并去除`"abc"`模式直到没有任何剩余，则该字符串是有效的。 

一些边缘情况很重要：

 - 长度不能被 3 整除的字符串永远不会有效，因为每个操作都恰好添加 3 个字符。 
- 包含错误顺序字符的字符串，例如`"acb"`或者`"abccba"`，必须返回`false`。 
- 具有不完整序列的字符串，例如`"ab"`或者`"aabbcc"`均无效。 
- 嵌套结构如`"aabcbc"`或者`"abcabcababcc"`仍然必须被认为是有效的。 

面临的挑战是在不生成所有可能的插入序列的情况下有效验证结构。 

## 方法

 ### 蛮力方法

 一个简单的方法是反复搜索`"abc"`放在字符串中并将其删除。 

例如：

-`"aabcbc"`- 消除`"abc"`→`"abc"`- 消除`"abc"`→`""`如果字符串最终变空，则它是有效的。 

这是有效的，因为每个有效字符串都是由插入的`"abc"`块，因此通过删除来反转该过程`"abc"`重复重建空字符串。 

然而，这种方法效率低下。 每次删除可能需要扫描整个字符串，并且字符串重建本身很昂贵，因为字符串在许多语言中是不可变的。 在最坏的情况下，我们可能会执行许多扫描和许多重建操作。 

最大长度为`20,000`，重复的全字符串操作可能会降低到二次时间复杂度。 

### 最佳方法

 关键的见解是有效的字符串总是形成`"abc"`模式逐渐增加。 

我们可以使用堆栈从左到右处理字符串，而不是重复从整个字符串中删除子字符串。 

这个想法是：

 - 将字符压入堆栈。 
- 每当前三名角色变成`"abc"`，立即将其删除。 

这模拟了有效结构一出现就减少的情况。 

例如：

 - 阅读`'a'`→ 堆栈 =`['a']`- 读`'b'`→ 堆栈 =`['a', 'b']`- 读`'c'`→ 堆栈 =`['a', 'b', 'c']`- 顶部是`"abc"`→ 弹出所有三个
 - 堆栈变空

 如果处理了整个字符串并且堆栈为空，则每个字符都参与了有效的`"abc"`顺序。 

这种方法对每个字符处理一次，并且仅执行恒定时间的堆栈操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复搜索、删除`"abc"`子串|
 | 最佳| O(n) | O(n) | 使用堆栈来减少有效`"abc"`立即组 |

 ## 算法演练

 1. 初始化一个空堆栈。 

栈中存储的是尚未形成完整字符的字符`"abc"`顺序。 
2. 迭代字符串中的每个字符。 

我们从左到右处理字符串，因为有效序列是增量构建的。 
3. 将当前字符压入堆栈。 

每个字符都会被临时存储，直到我们知道它是否完成了有效的模式为止。 
4.压入后，检查栈顶3个元素是否为`"a"`,`"b"`， 和`"c"`。 

这是关键的一步。 每当形成有效序列时，我们立即将其删除。 这模仿了反转一个插入操作。 
5. 如果前三个字符形成`"abc"`，将它们从堆栈中弹出。 

删除它们会使堆栈仅代表未解析的字符。 
6. 继续，直到处理完所有字符。 
7、最后检查栈是否为空。 

如果为空，则每个角色都参与了有效的`"abc"`顺序。 否则，会保留一些无效的结构。 

### 为什么它有效

 堆栈始终维护字符串中尚未还原为有效的部分`"abc"`组。 每次我们遇到`"abc"`在堆栈顶部，我们将其删除，因为该序列恰好对应于一个有效的插入操作。 

如果字符串有效，重复减少最终将删除所有内容。 如果字符串无效，一些不匹配的字符将保留在堆栈中。 

这个不变量保证了正确性。 

## Python 解决方案```python
class Solution:
    def isValid(self, s: str) -> bool:
        stack: list[str] = []

        for char in s:
            stack.append(char)

            if len(stack) >= 3:
                if stack[-3] == 'a' and stack[-2] == 'b' and stack[-1] == 'c':
                    stack.pop()
                    stack.pop()
                    stack.pop()

        return len(stack) == 0
```该实现紧密遵循前面描述的算法。 

我们首先创建一个空堆栈。 在 Python 中，列表是理想的选择，因为从末尾开始的追加和弹出操作都是 O(1)。 

当我们迭代每个字符时：

 - 该字符被追加到堆栈中。 
- 然后我们检查最后三个元素是否形成`"abc"`。 

如果他们这样做，这三个人都会立即被删除。 这样在遍历过程中不断减少有效段，而不是等到结束。 

最后，我们返回栈是否为空。 空堆栈意味着每个字符都成功形成有效的一部分`"abc"`图案。 

## 解决方案```go
func isValid(s string) bool {
    stack := make([]byte, 0)

    for i := 0; i < len(s); i++ {
        stack = append(stack, s[i])

        n := len(stack)

        if n >= 3 &&
            stack[n-3] == 'a' &&
            stack[n-2] == 'b' &&
            stack[n-1] == 'c' {

            stack = stack[:n-3]
        }
    }

    return len(stack) == 0
}
```Go 实现使用字节片作为堆栈，因为输入仅包含 ASCII 字符。 

而不是打电话`pop()`与 Python 一样，Go 使用以下方法多次缩短切片：```go
stack = stack[:n-3]
```这有效地删除了最后三个元素。 

与 Python 不同，Go 没有内置的堆栈类型，但切片非常适合追加和截断操作。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符被推入一次并最多弹出一次 |
 | 空间| O(n) | 最坏情况下堆栈可能保存所有字符 |

 该算法是线性的，因为每个字符都参与恒定数量的堆栈操作。 没有嵌套扫描或重复的子字符串搜索。 

最坏的空间使用情况发生在没有有效的`"abc"`序列可以减少到末尾，导致堆栈暂时保存整个字符串。

 ## 边缘情况

 ### 长度不能被三整除

 每个操作恰好插入三个字符。 因此，任何有效字符串的长度都必须能被 3 整除。 

例子如`"ab"`或者`"abca"`永远不可能变得有效。 虽然实现没有显式检查此条件，但堆栈自然无法减少整个字符串，从而留下剩余字符。 

### 字符顺序不正确

 字符串如`"acb"`或者`"abccba"`包含正确的字母，但排列无效。 

简单的解决方案可能会错误地计算字符频率并假设有效性。 堆栈方法避免了这个错误，因为它强制执行精确的顺序结构。 仅连续`"abc"`地层被移除。 

### 嵌套有效结构

 类似的情况`"aabcbc"`很棘手，因为有效的`"abc"`群体最初并不明显。 

堆栈通过减少新形成的内容来自然地处理这个问题`"abc"`序列一出现。 这种增量减少允许嵌套结构正确折叠。 

### 部分缩减后的剩余字符

 有些字符串部分减少，但仍然留下无效的残余部分。 

例如：```
"abca"
```第一个`"abc"`减少成功，但是一`'a'`保留在堆栈中。 最终的空堆栈检查正确地将字符串识别为无效。
