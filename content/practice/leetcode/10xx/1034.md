[LeetCode 1034 题](https://leetcode.com/problems/coloring-a-border/)

 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、广度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个二维网格，其中每个单元格都包含一个代表颜色的整数。 我们也得到了一个起始位置，`(row, col)`，以及新的颜色值。 

细胞位于`grid[row][col]`属于某个连通分量。 连接组件由以下单元组成：

 - 与原来的颜色相同
 - 通过上、下、左、右移动连接

 任务不是重新着色整个组件。 相反，我们只重新着色该组件的边框单元。 

如果出现以下情况，则单元格被视为边框的一部分：

 - 它位于网格的外边缘
 - 其四个邻居中至少有一个不属于同一连接组件

 组件内的每个非边框单元格都必须保持其原始颜色。 

输出应该是仅对边界单元重新着色后修改后的网格。 

限制相对较小：

 -`m, n <= 50`- 细胞总数最多为`2500`这意味着诸如深度优先搜索（DFS）或广度优先搜索（BFS）之类的图遍历解决方案是完全可行的。 甚至一个`O(m * n)`遍历足够高效。 

有几个重要的边缘情况需要考虑。 

如果连接的组件仅包含一个单元，则该单元自动成为边界，因为它接触组件的边界。 必须重新着色。 

如果整个组件填充整个网格，则仅外环被重新着色，而内部单元保持不变。 

如果新颜色与原始颜色相同，我们仍然需要正确识别边界单元，尽管最终的网格在视觉上可能保持不变。 

当我们在遍历时重新着色单元格时，会发生另一种微妙的情况。 如果我们立即覆盖单元格值，我们可能会意外地破坏未来的连接检查。 因此，我们必须：

 - 保留一个单独的访问结构
 - 延迟重新着色直到遍历之后
 - 小心使用临时标记

 ## 方法

 ### 蛮力方法

 强力策略将尝试确定网格中的每个单元是否属于连接的组件以及是否是边界。 

一种可能的实现是：

 1. 从`(row, col)`并收集连接组件中的所有单元格。 
2. 对于组件中的每个单元，检查其四个邻居。 
3. 如果任何邻居位于网格之外或具有不同的颜色，则将该单元格标记为边界。 
4. 重新着色所有标记的边框单元格。 

这种方法实际上对于约束来说已经足够有效了，因为网格很小。 然而，如果简单地实现，它可能会重复扫描单元或执行冗余连接检查。 

例如，设计不当的强力方法可能会从每个单元运行新的 DFS 来验证连接性，从而导致复杂性显着降低。 

### 最佳方法

 关键的观察结果是，该问题本质上是一个图遍历问题。 

可以使用 DFS 或 BFS 直接探索连接的组件，从`(row, col)`。 在遍历过程中，我们可以判断每个访问过的单元格是否是边界。 

如果满足以下条件，则单元格是边框：

 - 它位于矩阵的边缘
 - 或者它的邻居之一具有不同的原始颜色

 最优解决方案执行组件的单次遍历并单独存储边界单元。 遍历完成后，只有那些边界单元格被重新着色。 

这可以避免在遍历期间修改网格，从而保持邻居检查的准确性。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((m * n)^2) | O((m * n)^2) | O(m * n) | 可能会反复重新计算连接性|
 | 最佳| O(m * n) | O(m * n) | 组件的单次DFS/BFS遍历 |

 ## 算法演练

 ### 第 1 步：存储原始颜色

 我们首先保存起始单元格的颜色：```
original_color = grid[row][col]
```这很重要，因为连接组件中的每个单元格都必须匹配该颜色。 

### 第 2 步：创建支撑结构

 我们维持：

 - A`visited`矩阵以避免重新访问细胞
 - 一个名为`borders`储存必须重新着色的细胞

 访问矩阵可以防止无限递归和冗余工作。 

### 第三步：开始DFS遍历

 我们运行 DFS 从`(row, col)`。 

对于每个访问过的单元格：

 1. 将其标记为已访问。 
2. 检查所有四个相邻方向。 

### 步骤4：判断单元格是否为边框

 对于每个邻居：

 - 如果邻居在网格之外，则当前单元格是边界。 
- 如果邻居存在但颜色不同，则当前单元格也是边界。 
- 如果邻居具有相同的原始颜色并且没有被访问过，则继续DFS进入它。 

我们使用布尔标志，例如`is_border`。 

### 步骤 5：记录边界单元

 检查完所有邻居后：

 - 如果`is_border`为 true，将单元格坐标附加到`borders`。 

我们不会立即重新着色，因为过早更改值可能会干扰以后的邻居检查。 

### 第 6 步：重新着色边界单元

 DFS完成后：

 - 遍历存储在的所有单元格`borders`- 将每个单元格设置为新颜色

 ### 第 7 步：返回网格

 最后返回修改后的网格。 

### 为什么它有效

 DFS 只访问连接组件中的每个单元一次。 对于每个访问过的单元格，我们通过检查邻接条件来正确确定它是否属于边界。 

内部单元永远不会重新着色，因为所有四个邻居都属于同一组件并保留在网格内。 边界单元会重新着色，因为它们要么接触网格边界，要么接触组件外部的单元。 

由于重新着色仅在遍历完成后发生，因此所有连接检查都使用原始网格值，保证正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def colorBorder(
        self,
        grid: List[List[int]],
        row: int,
        col: int,
        color: int
    ) -> List[List[int]]:

        rows = len(grid)
        cols = len(grid[0])

        original_color = grid[row][col]

        visited = [[False] * cols for _ in range(rows)]
        borders = []

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        def dfs(r: int, c: int) -> None:
            visited[r][c] = True

            is_border = False

            for dr, dc in directions:
                nr = r + dr
                nc = c + dc

                # Outside the grid
                if nr < 0 or nr >= rows or nc < 0 or nc >= cols:
                    is_border = True

                # Different color neighbor
                elif grid[nr][nc] != original_color:
                    is_border = True

                # Continue DFS
                elif not visited[nr][nc]:
                    dfs(nr, nc)

            if is_border:
                borders.append((r, c))

        dfs(row, col)

        for r, c in borders:
            grid[r][c] = color

        return grid
```该实现首先存储网格的尺寸和原始组件颜色。 该原始颜色充当连接组件的标识符。 

一个`visited`矩阵用于确保每个组成单元仅被处理一次。 这`borders`列表存储最终应重新着色的坐标。 

DFS 函数递归地探索相邻单元。 对于每个邻居，它都会检查邻居是否位于网格之外或具有不同的颜色。 任何一个条件都意味着当前单元格属于边界。 

如果相邻单元共享相同的原始颜色并且尚未被访问，则 DFS 继续进入该邻居。 

重要的是，该算法不会在遍历过程中对单元重新着色。 相反，它首先记录边界单元，然后重新着色。 这保证了所有连通性检查都使用原始网格状态。 

最后，每个记录的边框单元格都会更新为目标颜色，并返回修改后的网格。 

## 解决方案```go
func colorBorder(grid [][]int, row int, col int, color int) [][]int {
	rows := len(grid)
	cols := len(grid[0])

	originalColor := grid[row][col]

	visited := make([][]bool, rows)
	for i := range visited {
		visited[i] = make([]bool, cols)
	}

	borders := make([][2]int, 0)

	directions := [][2]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	var dfs func(int, int)

	dfs = func(r int, c int) {
		visited[r][c] = true

		isBorder := false

		for _, dir := range directions {
			nr := r + dir[0]
			nc := c + dir[1]

			if nr < 0 || nr >= rows || nc < 0 || nc >= cols {
				isBorder = true
			} else if grid[nr][nc] != originalColor {
				isBorder = true
			} else if !visited[nr][nc] {
				dfs(nr, nc)
			}
		}

		if isBorder {
			borders = append(borders, [2]int{r, c})
		}
	}

	dfs(row, col)

	for _, cell := range borders {
		r := cell[0]
		c := cell[1]
		grid[r][c] = color
	}

	return grid
}
```Go 实现遵循与 Python 版本相同的逻辑结构。 主要区别在于 Go 需要显式分配`visited`矩阵并使用切片而不是 Python 列表。 

DFS 函数作为闭包实现，因此它可以递归访问共享变量，例如`grid`,`visited`， 和`borders`。 

坐标存储为固定大小的数组`[2]int`，这是一种轻量级且高效的表示形式。 

整数溢出不是问题，因为网格尺寸非常小。

 ## 边缘情况

 ### 单细胞组件

 如果算法假设每个单元格都有相同颜色的邻居，则仅包含一个单元格的组件很容易被错误处理。 实际上，单个孤立的单元格始终是边界，因为它要么接触网格边缘，要么接触不同颜色的相邻单元格。 

该实现自然地处理这个问题，因为任何丢失或不同的邻居集`is_border = True`。 

### 整个网格是一个组件

 当每个单元都属于同一个连接组件时，只有外层应该重新着色。 内部单元格必须保持不变。 

有缺陷的实现可能会重新着色所有单元格，因为它们都属于该组件。 我们的边界检测逻辑通过在将单元标记为边界之前要求出界邻居或不同颜色的邻居来避免这种情况。 

### 遍历期间重新着色

 最常见的错误之一是在 DFS 期间立即对细胞重新着色。 如果发生这种情况，以后的邻居检查可能会错误地认为重新着色的单元属于不同的组件。 

此实现通过推迟重新着色直到遍历完全完成来避免该问题。 原始网格值在整个 DFS 中保持不变，确保准确的连接检查。
