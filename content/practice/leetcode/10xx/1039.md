 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们以最小化总三角测量分数的方式对凸多边形进行三角测量。 

我们得到一个数组`values`，其中每个元素表示分配给多边形顶点的值。 多边形是凸多边形，顶点按顺时针顺序列出。 三角剖分使用现有顶点之间的对角线将多边形划分为不重叠的三角形。 任何有效的三角剖分`n`边多边形总是精确地产生`n - 2`三角形。 

每个三角形贡献的分数等于其三个顶点值的乘积。 最终的三角测量分数是三角测量中所有三角形的分数之和。 我们的目标是找到所有有效三角测量中可能的最小总分。 

例如，如果我们有：```
values = [3,7,4,5]
```有两种可能的三角剖分：

 1.使用对角线分割`(0,2)`2. 使用对角线分割`(1,3)`每个三角剖分都会创建一组不同的三角形，从而导致不同的总分。 我们必须计算其中的最小值。 

约束条件很重要：

 -`3 <= n <= 50`-`1 <= values[i] <= 100`自从`n`只有 50，这强烈表明`O(n^3)`动态规划解决方案是可以接受的。 探索每个三角剖分的强力递归解决方案将呈指数增长并且变得太慢。 

保证多边形是凸的，这大大简化了问题。 在凸多边形中，每条对角线都完全位于多边形内部，因此每个三角剖分选择都是有效的。 我们不需要执行几何有效性检查。 

有几个边缘情况值得注意：

 - 三角形已经有一个三角剖分，因此长度为 3 的数组是最小的有效输入。 
- 多个三角测量可以产生非常不同的分数，因此贪婪的局部决策不起作用。 
- 大的顶点值可能会产生非常大的三角形成本，因此优化划分非常重要。 
- 由于每个三角剖分都会递归地将多边形划分为更小的多边形，因此自然会出现重叠子问题。 

这种结构使该问题成为经典的区间动态规划问题。 

## 方法

 ### 蛮力方法

 蛮力方法递归地尝试每一种可能的三角测量。 

假设我们想要对由索引中的顶点形成的多边形进行三角剖分`i`索引`j`。 我们可以选择任意顶点`k`它们之间作为三角形的第三个顶点`(i, k, j)`。 

该三角形贡献：```
values[i] * values[k] * values[j]
```形成这个三角形后，多边形分成两个较小的子问题：

 - 三角测量`(i, k)`- 三角测量`(k, j)`我们递归地计算这两个部分并添加它们的成本。 

递归变为：```
cost(i, j) =
    min over k:
        cost(i, k)
        + cost(k, j)
        + values[i] * values[k] * values[j]
```这种强力解决方案是正确的，因为每个三角剖分都必须选择一些中间顶点`k`形成一个有端点的三角形`i`和`j`。 

然而，相同的子问题会被重复重新计算。 三角剖分的数量根据加泰罗尼亚数增长，呈指数增长。 这很快就变得不可行了`n = 50`。 

### 最优动态规划方法

 关键的观察结果是该问题具有重叠的子问题和最优子结构。 

如果我们已经知道较小多边形间隔的最小三角测量分数，我们可以重用它们而不是重新计算它们。 

我们定义：```
dp[i][j]
```作为由顶点形成的多边形的最小三角剖分分数`i`到`j`。 

如果`j - i < 2`，多边形的顶点少于 3 个，因此无法形成三角形，得分为 0。 

对于每个间隔`(i, j)`，我们尝试所有可能的中间顶点`k`:```
dp[i][j] =
    min(
        dp[i][k]
        + dp[k][j]
        + values[i] * values[k] * values[j]
    )
```We compute smaller intervals first, then build larger intervals from them.

 This avoids repeated computation and reduces the complexity to cubic time.

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) 递归堆栈 | 递归地探索每个三角剖分 |
 | 最优动态规划| O(n³) | O(n²) | 存储间隔结果并重用它们 |

 ## 算法演练

 1. 创建一个二维DP表，名称为`dp`。`dp[i][j]`将存储从顶点开始的多边形间隔的最小三角测量分数`i`到顶点`j`。 
2. 将所有条目初始化为`0`。 

少于三个顶点的区间无法形成三角形，因此它们的三角剖分成本自然为零。 
3. 按长度递增的顺序处理间隔。 

我们从长度为 3 的间隔开始，因为三角形是贡献分数的最小多边形。 
4. 对于每个间隔`(i, j)`，将答案初始化为无穷大。 

我们将尝试每一个可能的中间顶点`k`之间`i`和`j`。 
5. 计算三角形贡献。 

选择`k`形成三角形：```
(i, k, j)
```其得分为：```
values[i] * values[k] * values[j]
```6. 合并两个子问题。 

总成本变为：```
dp[i][k]
+ dp[k][j]
+ values[i] * values[k] * values[j]
```7. 取所有有效值中的最小值`k`。 

这保证了我们选择区间的最佳三角剖分`(i, j)`。 
8. 继续，直到处理完整个多边形。 

最终的答案是：```
dp[0][n - 1]
```### 为什么它有效

 多边形区间的每个三角剖分`(i, j)`必须恰好包含一个使用顶点的三角形`i`和`j`。 该三角形的第三个顶点一定是某个`k`他们之间。 

一旦选择了该三角形，剩余的多边形就会分裂成两个独立的较小多边形。 由于总得分是三角形得分的总和，因此全局最优三角剖分必须包含两个子多边形的最优三角剖分。 

这种最优子结构属性保证动态规划产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def minScoreTriangulation(self, values: List[int]) -> int:
        n = len(values)

        dp = [[0] * n for _ in range(n)]

        for length in range(3, n + 1):
            for left in range(n - length + 1):
                right = left + length - 1

                dp[left][right] = float("inf")

                for mid in range(left + 1, right):
                    score = (
                        dp[left][mid]
                        + dp[mid][right]
                        + values[left] * values[mid] * values[right]
                    )

                    dp[left][right] = min(dp[left][right], score)

        return dp[0][n - 1]
```实现直接遵循区间动态规划策略。 

我们首先确定顶点数`n`，然后创建一个初始化为零的 2D DP 表。 每个条目`dp[i][j]`表示索引之间多边形段的最小三角测量分数`i`和`j`。 

外循环从 3 开始迭代区间长度，因为小于 3 的区间无法形成三角形。 

对于每个间隔`(left, right)`，我们将答案初始化为无穷大，因为我们正在寻找最小值。 

内循环尝试每个可能的中间顶点`mid`。 选择`mid`形成一个带有顶点的三角形`left`和`right`，产生三角形成本：```python
values[left] * values[mid] * values[right]
```然后我们添加左右子多边形的最优成本：```python
dp[left][mid] + dp[mid][right]
```所有选择中的最小值成为该间隔的最佳三角测量分数。 

最后，`dp[0][n - 1]`包含整个多边形的答案。 

## 解决方案```go
package main

import "math"

func minScoreTriangulation(values []int) int {
	n := len(values)

	dp := make([][]int, n)
	for i := range dp {
		dp[i] = make([]int, n)
	}

	for length := 3; length <= n; length++ {
		for left := 0; left <= n-length; left++ {
			right := left + length - 1

			dp[left][right] = math.MaxInt32

			for mid := left + 1; mid < right; mid++ {
				score := dp[left][mid] +
					dp[mid][right] +
					values[left]*values[mid]*values[right]

				if score < dp[left][right] {
					dp[left][right] = score
				}
			}
		}
	}

	return dp[0][n-1]
}
```Go 实现在结构上与 Python 版本相同。 主要区别在于 2D DP 表的显式切片分配。 

Go 的整数没有无穷大值，因此我们用以下命令初始化每个区间结果`math.MaxInt32`。 

约束足够小，因此不必担心整数溢出。 最大可能分数安全地保持在 Go 的整数范围内。

 | 空间| O(n²) | DP 表存储所有间隔的结果 |

 该算法处理每个区间`(i, j)`并尝试每一个可能的分割点`k`在那个区间内。 

有`O(n²)`间隔并且每个间隔可以检查最多`O(n)`分割点，产生总时间复杂度`O(n³)`。 

DP表包含`n × n`条目，导致`O(n²)`空间使用情况。

 ## 边缘情况

 一个重要的边缘情况是可能的最小多边形，其中`n = 3`。 在这种情况下，多边形已经是三角形，因此只有一个三角剖分。 有缺陷的实现可能会错误地尝试额外的递归或间隔分割。 DP 解决方案可以自然地处理这一问题，因为间隔长度恰好为 3，从而产生一个三角形计算。 

当许多顶点都有价值时，就会出现另一个重要的边缘情况`1`。 由于乘以`1`为了保持三角形成本较小，最佳三角剖分通常会重复使用这些顶点。 仅最小化直接三角形成本的贪婪算法可能会失败，因为未来的分割很重要。 区间DP解决方案正确评估所有可能的分区并保证全局最小值。 

第三个重要的边缘情况涉及大顶点值，例如`100`。 三角形产品可以很快变大。 糟糕的三角测量选择可能会产生不必要的昂贵三角形。 DP 解决方案系统地比较每个可能的分割点，并确保尽可能避免昂贵的组合。 

当多个三角测量产生相同的分数时，会出现最后一个微妙的边缘情况。 该问题只要求最低分数，而不要求实际的三角剖分结构。 我们的实现仅存储数字最小值，这已经足够并且避免了不必要的复杂性。
