 **难度：** 🔴难
 **主题：** 数学、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算范围内有多少个整数`[1, n]`至少包含一个重复的数字。 

重复数字意味着某个数字在数字中出现多次。 例如，`11`有重复的`1`,`100`已重复`0`， 和`121`已重复`1`。 另一方面，`123`和`9870`仅包含唯一的数字。 

输入是单个整数`n`，输出是来自的数字计数`1`通过`n`包含重复数字的。 

一个直接的解释是：

 - 计算每个整数`x`在哪里`1 <= x <= n`- 检查是否`x`任何数字出现多次
 - 返回总计数

 约束条件`1 <= n <= 10^9`非常重要。 自从`n`可以大到十亿，迭代每个数字并检查其数字在最坏的情况下效率很低。 暴力解决方案需要处理多达十亿个数字，这远远超出了可接受的运行时间限制。 

关键的观察是，如果我们计算补码，问题就会变得容易得多。 我们不是直接计算具有重复数字的数字，而是计算具有所有唯一数字的数字，然后从`n`。 

正式：```
answer = n - count_of_numbers_with_unique_digits
```这种转换非常强大，因为使用组合数学和数字动态编程思想可以有效地计算唯一数字。 

一些边缘情况很重要：

 - 小值，例如`n = 1`或者`n = 9`，其中不存在重复数字
 - 边界过渡如`10`,`11`,`99`,`100`， 和`101`- 包含重复零的数字，例如`1000`- 重复出现在数字序列中较晚的数字，例如`123451`该问题保证了`n`是正数，所以我们永远不需要处理负值或空输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代每个数字`1`到`n`并检查号码是否包含重复数字。 

对于每个数字：

 1.将其转换为数字
 2. 使用集合来跟踪哪些数字已经出现
 3. 如果一个数字出现两次，则增加答案

 这种方法是正确的，因为每个数字都经过独立且详尽的检查。 

然而，对于大输入来说，运行时间太慢。 如果`n = 10^9`，我们可能会处理十亿个数字，每个数字都需要数字提取和集合运算。 

即使检查一个数字只需要`O(log n)`时间，总运行时间变得不可行。 

### 最佳方法

 关键的见解是，计算具有唯一数字的数字比计算具有重复数字的数字更容易。 

我们不直接计算重复项，而是计算：```
repeated = n - unique
```为了有效地计算唯一数字，我们使用逐位构造。 

我们处理的数字为`n`从左到右，计算可以组成多少个不重复数字的有效数字。 

该算法有两个主要部分：

 1. 计算所有位数少于`n`2. 计算长度相同的唯一数字`n`对于第二部分，我们逐位构建数字，同时跟踪哪些数字已被使用。 

这是有效的，因为在每个位置，我们都可以使用排列来准确确定存在多少剩余有效选择。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(log n) | 单独检查每个数字 |
 | 最佳| O((log n)^2) | O((log n)^2) | O(log n) | 使用组合数学和基于数字的计数 |

 ## 算法演练

 ### 第 1 步：转换`n + 1`转化为数字

 我们与`n + 1`而不是`n`因为它简化了包含计数。 

例如，如果`n = 100`，然后处理`101`允许我们计算所有严格小于的有效数字`101`，相当于数数`<= 100`。 

### 步骤 2：计算位数较少的唯一数字

 假设`n = 5432`。 

在考虑 4 位数字之前，我们使用以下方法计算所有唯一数字：

 - 1 位数字
 - 2 位数字
 - 3 位数字

 对于长度`k`：

 - 第一位数字不能为零
 - 其余数字必须不同

 计数为：```
9 × P(9, k - 1)
```在哪里：

-`9`第一个数字的选择（`1-9`）
 -`P(9, k - 1)`是剩余位置的排列计数

 3 位数字的示例：```
9 × 9 × 8 = 648
```### 第三步：处理相同长度的数字

 现在我们计算与以下位数完全相同的有效数字`n`。 

我们从左到右处理数字。 

在每个位置：

 1. 尝试输入比当前数字更小的数字
 2. 确保该数字尚未被使用
 3. 计算剩余位置可以有多少种填补方式

 我们维护一个名为`used`跟踪已选择的数字。 

### 步骤 4：计算剩余位置的排列

 假设我们正在填充一个 4 位数字并且已经固定了前两位数字。 

如果有`m`剩余未使用的数字和`r`剩余位置，则路数为：```
P(m, r)
```这是迭代计算的。 

### 步骤 5：如果出现重复数字则停止

 在处理数字时`n`，如果我们遇到一个已经存在于`used`，那么当前前缀已经包含重复。 

此时，无法再形成有效的唯一数字，因此我们立即停止。 

### 第 6 步：计算最终答案

 最后：```
answer = n - unique_count
```因为：```
total numbers = unique-digit numbers + repeated-digit numbers
```### 为什么它有效

 该算法系统地对每个有效的唯一数字进行一次计数。 

位数较少的数字使用排列单独计数。 具有相同长度的数字按数字进行计数，同时保留由`n`。 

这`used`set 保证没有数字重复，排列计数确保包含每个剩余的有效后缀。 

由于每个唯一的数字`<= n`只计算一次，减去`n`生成包含重复数字的整数的确切数量。 

## Python 解决方案```python
class Solution:
    def numDupDigitsAtMostN(self, n: int) -> int:
        digits = list(map(int, str(n + 1)))
        length = len(digits)

        def permutation(m: int, k: int) -> int:
            result = 1
            for i in range(k):
                result *= (m - i)
            return result

        unique_count = 0

        # Count numbers with fewer digits
        for digits_count in range(1, length):
            unique_count += 9 * permutation(9, digits_count - 1)

        used = set()

        # Count numbers with same length
        for i in range(length):
            current_digit = digits[i]

            for digit in range(0 if i > 0 else 1, current_digit):
                if digit in used:
                    continue

                remaining_positions = length - i - 1
                available_digits = 10 - (i + 1)

                unique_count += permutation(
                    available_digits,
                    remaining_positions
                )

            if current_digit in used:
                break

            used.add(current_digit)

        return n - unique_count
```实现从转换开始`n + 1`到一个数字数组中。 这允许算法计算所有严格小于的唯一数字`n + 1`，它完全对应于小于或等于的数字`n`。 

这`permutation`助手计算：```python
P(m, k) = m × (m - 1) × ...
```在确定可以形成多少个有效后缀时，会重复使用此值。 

第一个循环计算所有位数少于`n`。 

第二个循环逐位处理相同长度的数字。 在每个位置，它都会尝试每个较小的有效数字并计算剩余可能的完成次数。 

这`used`set 确保当前前缀内没有数字重复。 

如果当前数字已经出现，则算法立即停止，因为每个延续都将包含重复的数字。 

最后减去`unique_count`从`n`产生包含重复数字的整数的数量。 

## 解决方案```go
func numDupDigitsAtMostN(n int) int {
	digits := []int{}
	temp := n + 1

	for temp > 0 {
		digits = append([]int{temp % 10}, digits...)
		temp /= 10
	}

	length := len(digits)

	permutation := func(m, k int) int {
		result := 1
		for i := 0; i < k; i++ {
			result *= (m - i)
		}
		return result
	}

	uniqueCount := 0

	// Count numbers with fewer digits
	for digitsCount := 1; digitsCount < length; digitsCount++ {
		uniqueCount += 9 * permutation(9, digitsCount-1)
	}

	used := make(map[int]bool)

	// Count numbers with same length
	for i := 0; i < length; i++ {
		currentDigit := digits[i]

		start := 0
		if i == 0 {
			start = 1
		}

		for digit := start; digit < currentDigit; digit++ {
			if used[digit] {
				continue
			}

			remainingPositions := length - i - 1
			availableDigits := 10 - (i + 1)

			uniqueCount += permutation(
				availableDigits,
				remainingPositions,
			)
		}

		if used[currentDigit] {
			break
		}

		used[currentDigit] = true
	}

	return n - uniqueCount
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是 Go 不提供内置的集合类型，因此`map[int]bool`用于跟踪已使用的数字。 

另一个区别是数字提取。 由于 Go 缺乏 Python 方便的字符串到数字的转换方式，因此需要使用模和除运算手动提取数字。 

整数溢出不是问题，因为问题约束仅限于`10^9`，并且所有中间排列值都保持在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况是非常小的值，例如`n = 1`或者`n = 9`。 这些数字仅包含一位数字，因此不可能重复。 有缺陷的实现可能会意外地计算前导零或错误处理空排列。 此实现正确返回`0`因为唯一数字计数等于`n`。 

另一个关键的边缘情况涉及重复的零，例如`100`,`1000`， 或者`10000`。 这些很棘手，因为重复不会发生在非零数字之间。 该算法通过跟踪每个使用的数字（包括零）来正确处理这个问题。`used`放。 

当重复出现在数字的后面时，就会出现第三种重要的边缘情况，例如`123451`。 前缀`12345`有效，但最后一位数字重复`1`。 该算法在从左到右的处理过程中立即检测到这一点，并停止进一步计数，因为该前缀的每个延续都必然包含重复的数字。 

第四个微妙的情况是接近十的幂的数字，例如`99`,`100`,`999`， 和`1000`。 These boundaries often cause off-by-one errors in digit DP solutions. 使用`n + 1`而不是`n`简化了包含计数并彻底避免了这些边界错误。
