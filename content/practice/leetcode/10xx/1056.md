[LeetCode 1056 题](https://leetcode.com/problems/confusing-number/)

 **难度：** 🟢简单
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的整数在旋转后是否变成不同的有效数字`180`度。 

并非每个数字在轮换后仍然有效。 仅允许以下映射：

 | 原始数字 | 旋转数字 |
 | ---| ---|
 | 0 | 0 |
 | 1 | 1 |
 | 6 | 9 |
 | 8 | 8 |
 | 9 | 6 |

 数字`2`,`3`,`4`,`5`， 和`7`轮换后无效，这意味着任何包含这些数字之一的数字永远不会是令人困惑的数字。 

重要的细节是旋转也会颠倒数字的顺序。 例如：

-`89`变成`68`-`916`变成`619`发生这种情况是因为当数字物理上颠倒旋转时，最后一位数字将成为旋转结果中的第一位数字。 

如果出现以下情况，则认为数字令人困惑：

 1. 循环后每位数字仍然有效。 
2. 旋转后的号码与原来的号码不同。 

如果旋转后的数字与原始数字相同，则该数字不会混淆。 

输入是单个整数`n`在哪里：

-`0 <= n <= 10^9`由于最大值仅为 10 亿，因此该数字最多包含 10 位数字。 这告诉我们，即使是逐位处理也非常快。 

有几个重要的边缘情况：

 - 包含无效数字的数字，例如`2`或者`7`必须立即返回`false`。 
- 像这样的数字`11`或者`69`旋转到它们自己，所以它们不会混淆。 
- 应忽略旋转结果中的前导零。 例如，`8000`旋转到`0008`，这就是简单的`8`。 
- 价值`0`并不令人困惑，因为它会自行旋转。 

## 方法

 ### 蛮力方法

 暴力式解决方案将通过将数字转换为字符串、反转它、旋转每个数字并构造一个新字符串来模拟整个旋转过程。 

该算法将：

 1. 将数字转换为字符串。 
2. 反转字符串。 
3. 使用旋转映射替换每个数字。 
4. 如果有任何数字无效，则返回`false`。 
5. 将旋转后的字符串转换回整数。 
6. 将其与原始数字进行比较。 

这种方法是正确的，因为它精确地模拟了旋转过程。 

然而，字符串操作会带来额外的开销。 虽然约束足够小，仍然可以有效地工作，但我们可以通过直接数学数字处理做得更好。 

### 最佳方法

 关键的观察是我们可以在从右到左提取数字的同时以数学方式构建旋转数。 

当我们重复使用最后一位数字时`% 10`，我们自然地以相反的顺序处理数字，这完全符合旋转数字的形成方式。 

例如：

 - 原始号码：`89`- 从右到左提取数字：`9`， 然后`8`- 旋转它们：`6`， 然后`8`- 构建结果：`68`这完全避免了字符串转换并且仅使用整数算术。 

我们维持：

 - 包含有效旋转的哈希图
 - 存储旋转数的变量

 如果我们遇到无效数字，我们立即返回`false`。 

最后，我们将旋转后的数字与原始数字进行比较。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(d) | O(d) | 使用字符串转换和反转 |

 这里，`d`表示中的位数`n`。 

## 算法演练

 1. 为所有有效的旋转数字创建映射。 

我们存储：```
{
    0: 0,
    1: 1,
    6: 9,
    8: 8,
    9: 6
}
```这允许对每个数字进行恒定时间查找。 
2. 存储原始号码。 

稍后我们需要原始值，以便我们可以将其与旋转结果进行比较。 
3. 初始化一个变量来构建旋转后的数字。 

从以下开始：```
rotated = 0
```4. 从右到左一位一位地处理数字。 

当数字大于零时：

 - 使用提取最后一位数字`% 10`- 使用删除最后一位数字`// 10`5. 验证数字。 

如果该数字不在旋转图中，则立即返回`false`。 

这可以处理无效数字，例如`2`,`3`,`4`,`5`， 和`7`。 
6. 构建旋转数。 

使用以下命令附加旋转后的数字：```
rotated = rotated * 10 + rotated_digit
```乘以 10 会将现有数字左移，以便可以附加新数字。 
7. 将旋转后的数字与原始数字进行比较。 

如果不同则返回`true`。 

否则返回`false`。 

### 为什么它有效

 该算法从右向左处理数字，这自然与旋转数字引起的反转相匹配。 每个提取的数字都使用有效的旋转映射进行转换，并以正确的顺序附加到新数字。 

如果每个数字都是有效的并且最终旋转的数字与原始数字不同，则该数字满足混淆数字的确切定义。 

## Python 解决方案```python
class Solution:
    def confusingNumber(self, n: int) -> bool:
        rotation_map = {
            0: 0,
            1: 1,
            6: 9,
            8: 8,
            9: 6
        }

        original = n
        rotated = 0

        while n > 0:
            digit = n % 10

            if digit not in rotation_map:
                return False

            rotated = rotated * 10 + rotation_map[digit]
            n //= 10

        return rotated != original
```该解决方案首先定义一个存储有效数字旋转的字典。 该字典有两个用途：验证数字并提供转换后的值。 

我们存储原始数字，因为变量`n`将在数字提取期间修改。 

该循环使用模运算重复提取最后一位数字。 如果数字无效，函数立即返回`False`。 

否则，旋转后的数字将附加到结果中。 由于数字是从右到左处理的，因此构造的数字自动具有正确的旋转顺序。 

最后，将旋转后的数字与原始数字进行比较。 如果它们不同，这个数字就会令人困惑。 

## 解决方案```go
func confusingNumber(n int) bool {
    rotationMap := map[int]int{
        0: 0,
        1: 1,
        6: 9,
        8: 8,
        9: 6,
    }

    original := n
    rotated := 0

    for n > 0 {
        digit := n % 10

        rotatedDigit, exists := rotationMap[digit]
        if !exists {
            return false
        }

        rotated = rotated*10 + rotatedDigit
        n /= 10
    }

    return rotated != original
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用 Go 的映射语法和显式存在检查。 

一个显着的区别是 Go 需要使用以下方法检查映射中是否存在某个键：```go
value, exists := map[key]
```这可以避免意外地将丢失的数字视为有效的零值。 

由于约束很小，因此 Go 中不存在整数溢出问题。

 ## 边缘情况

 一种重要的边缘情况是包含无效数字的数字，例如`2`,`3`,`4`,`5`， 或者`7`。 这些数字没有有效的旋转形式，因此整个数字立即变得无效。 幼稚的实现可能会意外地忽略这些数字或错误地映射它们。 该解决方案通过在构建旋转数字之前检查旋转图中是否存在每个数字来防止这种情况。 

另一个重要的情况是数字自身旋转。 例子包括`11`,`69`,`88`， 和`96`。 即使每个数字都是有效的，问题也要求旋转后的值与原始数字不同。 该实现通过将最终旋转结果与原始输入进行比较来正确处理此问题。 

前导零是错误的另一个微妙来源。 例如，`8000`旋转到`0008`，应解释为`8`。 如果基于字符串的实现保留不必要的零，则可能会错误处理此问题。 这里使用的数学构造自然会忽略前导零，因为整数不存储它们。 

输入`0`也很特别。 由于它自行旋转，因此不会造成混乱。 循环不执行 for`0`，将旋转后的值保留为`0`，最终比较正确返回`False`。
