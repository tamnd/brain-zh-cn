[LeetCode 问题 1031](https://leetcode.com/problems/maximum-sum-of-two-non-overlapping-subarrays/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、滑动窗口

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和两个固定的子数组长度，`firstLen`和`secondLen`。 我们必须恰好选择两个连续的子数组，以便：

 - 一个子数组有长度`firstLen`- 另一个子数组有长度`secondLen`- 两个子数组不重叠
 - 两个子数组内所有元素的总和尽可能大

 子数组的顺序并不重要。 子数组的长度`firstLen`可能出现在长度为的子数组之前`secondLen`，或之后。 唯一的要求是它们保持完全不相交。 

输入数组包含非负整数，这是一个重要的细节。 由于所有数字都是非负数，因此较大的窗口通常会产生较大的总和，并且我们永远不需要担心负值会意外减少总数。 

这些约束告诉我们一些有用的信息：

 -`nums.length <= 1000`-`firstLen + secondLen <= nums.length`- 每个元素都介于`0`和`1000`数组大小 1000 并不是很大，因此即使是`O(n^2)`解决方案可能会通过。 然而，该问题是专门为了奖励优化的滑动窗口和前缀和方法而设计的。 

关键的挑战是正确处理非重叠条件。 幼稚的实现可能会意外地允许两个窗口相交，尤其是在独立检查所有可能的位置时。 

一些边缘情况很重要：

 - 两个子阵列可以直接相互接触，这是允许的，因为接触不重叠。 
- 一个子数组可能完全出现在另一个子数组之前。 
- 最佳解决方案可能会将较小的窗口放在第一位或第二位。 
- 具有许多相等值的数组可以创建多个有效的最佳答案。 
- 非常小的阵列`firstLen + secondLen == len(nums)`只留下一种可能的安排。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试每对可能的子数组。 

我们可以：

 1. 枚举每个长度有效的子数组`firstLen`2. 枚举每个长度有效的子数组`secondLen`3、检查两个窗口是否重叠
 4. 如果它们不重叠，则计算它们的总和
 5. 追踪最大结果

 为了有效地计算子数组和，我们可以使用前缀和，以便在恒定时间内获得每个窗口和。 

这种方法是正确的，因为它显式检查每对有效的子数组，确保最终会考虑最佳答案。 

然而，时间复杂度变成二次方，因为有`O(n)`第一个长度的窗口和`O(n)`第二长度的窗口。 检查每对产生`O(n^2)`组合。 

虽然`n <= 1000`是可以管理的，我们可以做得更好。 

### 最佳方法

 关键的观察是我们不需要反复重新考虑所有以前的窗口。 

假设我们将`secondLen`窗口结束于位置`i`。 那么最好的`firstLen`窗户必须完全位于它的前面。 我们可以维护：

 - 任何有效的最大总和`firstLen`目前看到的窗口
 - 当前`secondLen`窗口总和

 这使我们能够计算每个位置在恒定时间内的最佳总数。 

我们还必须处理相反的顺序：

 -`firstLen`前`secondLen`-`secondLen`前`firstLen`因此，我们将问题解决两次并取最大的结果。 

前缀和进行每个窗口求和计算`O(1)`，对于每个排序来说，一次线性扫描就足够了。

 ## 算法演练

 ### 第 1 步：构建前缀和

 创建一个前缀和数组，其中：```
prefix[i]
```存储索引中元素的总和`0`通过`i - 1`。 

这允许在恒定时间内计算任何子数组总和：```
sum(left, right) = prefix[right + 1] - prefix[left]
```使用前缀和可以防止重复求和工作。 

### 步骤 2：定义辅助函数

 创建一个辅助函数来计算：```
Maximum total when:
A-length window comes before B-length window
```该助手将采用两个参数：

 -`leftLen`-`rightLen`此函数假设左侧窗口出现在右侧窗口之前。 

### 步骤 3：跟踪最佳左侧窗口

 当我们从左到右扫描时，我们保持：```
bestLeft
```它存储任何有效的最大总和`leftLen`到目前为止遇到的窗口。 

在每一步中，这都代表不与当前右窗口重叠的最佳左侧贡献。 

### 第 4 步：评估正确的窗口

 对于每个有效的起始位置`rightLen`窗口：

 1.计算当前右窗口的总和
 2. 更新`bestLeft`使用尽可能最新的左窗口
 3. 组合：```
bestLeft + currentRight
```4.更新全局最大值

 这保证了不重叠，因为总是在当前右窗口开始之前完全选择左窗口。 

### 第 5 步：处理两个订单

 最优的安排可能是：

 -`firstLen`前`secondLen`-`secondLen`前`firstLen`所以我们计算两者：```
helper(firstLen, secondLen)
helper(secondLen, firstLen)
```然后返回较大的值。 

### 为什么它有效

 该算法保持不变式`bestLeft`始终表示在当前右窗口开始之前结束的最大可能左窗口总和。 由于每个右窗口都与最兼容的左窗口配对，因此每个有效排列都被仅考虑一次。 对两种排序运行该过程可确保涵盖所有可能的非重叠配置。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSumTwoNoOverlap(
        self,
        nums: List[int],
        firstLen: int,
        secondLen: int
    ) -> int:

        n = len(nums)

        # Build prefix sums
        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + nums[i]

        def window_sum(left: int, right: int) -> int:
            return prefix[right + 1] - prefix[left]

        def helper(left_len: int, right_len: int) -> int:
            best_left = 0
            answer = 0

            # right_start is the starting index
            # of the right-side window
            for right_start in range(left_len, n - right_len + 1):

                left_end = right_start - 1
                left_start = left_end - left_len + 1

                left_sum = window_sum(left_start, left_end)

                best_left = max(best_left, left_sum)

                right_end = right_start + right_len - 1
                right_sum = window_sum(right_start, right_end)

                answer = max(answer, best_left + right_sum)

            return answer

        return max(
            helper(firstLen, secondLen),
            helper(secondLen, firstLen)
        )
```实现首先构建一个前缀和数组。 此预处理步骤允许在恒定时间内计算每个子数组总和，这对于实现线性总体复杂性至关重要。 

这`window_sum`helper封装了前缀和计算并提高了可读性。 帮助程序集中了逻辑，而不是在整个算法中重复编写前缀算术。 

这`helper`函数处理问题的一种排序。 它假设左窗口有长度`left_len`右边的窗口有长度`right_len`。 

在迭代过程中，`best_left`跟踪迄今为止遇到的最大有效左窗口。 由于循环从左到右扫描可能的右窗口，因此每个存储的左窗口自动不重叠。 

对于每个右侧窗口：

 1. 计算最新的符合条件的左窗口总和
 2. 更新`best_left`3. 计算当前右窗口总和
 4. 将它们组合起来更新答案

 最后，该算法评估两种可能的排序并返回较大的结果。 

## 解决方案```go
func maxSumTwoNoOverlap(nums []int, firstLen int, secondLen int) int {
	n := len(nums)

	// Build prefix sums
	prefix := make([]int, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + nums[i]
	}

	windowSum := func(left int, right int) int {
		return prefix[right+1] - prefix[left]
	}

	max := func(a int, b int) int {
		if a > b {
			return a
		}
		return b
	}

	helper := func(leftLen int, rightLen int) int {
		bestLeft := 0
		answer := 0

		for rightStart := leftLen; rightStart <= n-rightLen; rightStart++ {

			leftEnd := rightStart - 1
			leftStart := leftEnd - leftLen + 1

			leftSum := windowSum(leftStart, leftEnd)

			bestLeft = max(bestLeft, leftSum)

			rightEnd := rightStart + rightLen - 1
			rightSum := windowSum(rightStart, rightEnd)

			answer = max(answer, bestLeft+rightSum)
		}

		return answer
	}

	return max(
		helper(firstLen, secondLen),
		helper(secondLen, firstLen),
	)
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 不提供内置的辅助函数，例如`max`，手动定义一个小的效用函数。 

切片用于前缀和数组，所有计算都使用标准整数。 整数溢出不是问题，因为最大可能的和完全在 Go 的整数范围内：```go
1000 elements × 1000 value = 1,000,000
```与 Python 不同，Go 需要显式变量声明和辅助函数的函数文字。

 ## 边缘情况

 当两个子数组恰好消耗整个数组时，就会出现一种重要的边缘情况。 在这种情况下，数组只有一种可能的分区。 有缺陷的实现可能会错误地跳过有效的触摸窗口，或者意外地需要子阵列之间有额外的间距。 此实现可以正确处理这种情况，因为它只禁止重叠，而不禁止相邻。 

另一个重要的情况是最佳排序被颠倒。 许多不正确的解决方案都假设`firstLen`窗口必须始终出现在`secondLen`窗户。 该问题明确允许任一顺序。 此实现通过运行辅助函数两次（每种可能的排列各一次）来解决该问题。 

包含全零的数组是另一种微妙的情况。 某些算法以假设存在正和的方式错误地初始化跟踪变量。 由于此解决方案安全地初始化最佳值并始终使用有效的窗口总和，因此当每个可能的子数组总和为零时，它会正确返回零。 

另一种边缘情况涉及彼此​​直接相邻的窗口。 由于连续窗口只要不重叠就有效，因此实现会仔细计算边界，以便：```
left_end < right_start
```自然地允许触及边界，从而防止出现相差一分的错误。
