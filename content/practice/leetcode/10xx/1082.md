[LeetCode 1082 题](https://leetcode.com/problems/sales-analysis-i/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们识别产生最高总销售收入的卖家。 

我们有两个数据库表：`Product`和`Sales`。 这`Product`表包含有关产品的信息，包括其 ID、名称和单价。 这`Sales`表记录交易，每行代表一笔销售，包括卖家 ID、买家 ID、数量和总金额等详细信息`price`为了那次销售。 

重要的细节是，我们没有被要求使用以下方法计算收入`quantity * unit_price`从`Product`桌子**。 相反，该问题明确提供了一个`price`栏目中的`Sales`表，它已经代表该交易的总金额。 因此，任务是计算**总和`price`每个卖家的价值**。 

一旦我们知道了每个卖家的总销售收入，我们就必须确定哪个卖家的总收入最大。 如果多个卖家都获得最高价值，我们将全部退回。 

输出应包含单个列：

 | 专栏 | 意义|
 | --- | --- |
 |`seller_id`| 总销售收入最高的卖家 |

 结果可以以**任何顺序**返回，这意味着不需要排序。 

由于这是一个难度等级为“简单”的数据库问题，因此主要挑战是在 SQL 中正确表达聚合逻辑。 我们需要按卖家对销售额进行分组，计算总收入，确定最大收入，然后过滤符合该最大收入的卖家。 

一个重要的观察结果是`Product`表对于解决问题实际上是不必要的。 虽然`product_id`作为外键存在，我们不需要产品名称或单价，因为销售额已经在`Sales.price`柱子。 

### 重要的边缘案例

 幼稚的实现可能会忽略几个重要的场景。 

如果多个卖家的最高总收入相同，则必须全部退回。 这意味着仅选择一个最大行的解决方案将失败。 

卖家可能会出现在多个销售行中。 我们必须汇总该卖家的所有行，而不是独立考虑单个交易。 

这`Sales`表可能包含重复的行，这意味着重复的交易仍应贡献于总收入。 我们不应该删除重复记录。 

该问题保证了`seller_id`值存在于`Sales`表并且模式有效，因此我们不需要处理格式错误的输入。 

## 方法

 ### 蛮力方法

 暴力破解的想法是手动计算每个卖家的总收入，然后反复比较所有卖家以确定最大值。 

我们可以首先使用聚合来计算每个卖家的总销售额。 然后，对于每个卖家，我们将他们的总收入与其他所有卖家进行比较，以检查是否有人具有更高的价值。 如果没有卖家超过当前卖家的收入，则该卖家属于答案。 

这种方法之所以有效，是因为每个卖家都会与所有其他卖家进行详尽的比较，从而保证只返回具有全球最大总数的卖家。 

然而，这种方法效率低下，因为它引入了不必要的重复比较。 如果有`n`对于卖家来说，将每个卖家与其他卖家进行比较会导致二次工作。 

### 最佳方法

 关键的见解是我们不需要成对比较。 相反，我们可以计算一次所有卖家的总金额，确定一次最大总金额，然后返回总金额等于该最大值的所有卖家。 

这自然映射到 SQL 聚合：

 1. 使用`GROUP BY seller_id`计算每个卖家的总收入。 
2. 求最大总收入。 
3. 选择收入等于该最大值的所有卖家。 

常见的 SQL 模式是将分组总计放入子查询或公共表表达式 (CTE) 中。 然后，我们通过将卖家的总数与全球最大值进行比较来筛选卖家。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 计算总数，然后将每个卖家与其他卖家进行比较 |
 | 最佳 | O(n) | O(n) | 聚合一次并按最大总数过滤 |

 这里，`n`代表行数`Sales`桌子。 

## 算法演练

 1. 分组`Sales`表格依据`seller_id`并计算总和`price`对于每个卖家。 这为我们提供了每个卖家产生的总销售收入。 
2. 确定所有卖家的最大总收入。 该值代表最高的销售业绩。 
3. 过滤分组结果，仅包含总收入等于最大值的卖家。 
4. 返回`seller_id`这些卖家的价值观。 由于该问题允许任何顺序，因此不需要排序。 

### 为什么它有效

 该算法之所以有效，是因为每个卖家的总收入都通过聚合精确计算一次。 找到全局最大值后，选择总数与该最大值匹配的卖家可以保证正确性。 任何总金额较小的卖家都被排除在外，而所有排名最高的卖家都被包括在内。 

## Python 解决方案

 LeetCode 数据库问题使用 SQL 而不是 Python 类方法。 下面是一个完整的、可提交 LeetCode 的 SQL 解决方案。```python
SELECT seller_id
FROM (
    SELECT
        seller_id,
        SUM(price) AS total_sales
    FROM Sales
    GROUP BY seller_id
) AS seller_totals
WHERE total_sales = (
    SELECT MAX(total_sales)
    FROM (
        SELECT
            seller_id,
            SUM(price) AS total_sales
        FROM Sales
        GROUP BY seller_id
    ) AS max_totals
);
```解决方案首先将`Sales`表格依据`seller_id`。 对于每个卖家来说，`SUM(price)`计算总销售收入。 

分组结果存储在名为的子查询中`seller_totals`。 这为我们提供了一个表格，其中包含每个卖家的一行及其相应的总收入。 

接下来，我们使用另一个聚合查询计算最高总收入。 内部子查询再次计算卖家总数，并且`MAX(total_sales)`提取最大值。 

最后，外部查询过滤卖家`total_sales`等于这个最大值。 由于允许有领带，因此可能会退回多个卖家。

 ## 边缘情况

 ### 多个卖家并列获得最大收入

 一个容易犯的错误是只返回收入最高的一位卖家。 在示例问题中，卖家双方`1`和卖家`3`有总收入`2800`。 该实现通过过滤总数等于最大值的所有卖家来正确处理此问题，而不是将结果限制为一行。 

### 具有多次交易的卖家

 卖家可能会多次出现在`Sales`桌子。 有缺陷的实现可能只检查单个销售额而不是汇总总数。 使用`SUM(price)`和`GROUP BY seller_id`保证每个卖家的所有交易都累积到一个总额中。 

### 销售表中的重复行

 该问题明确指出可能存在重复的行。 某些实现可能会意外删除重复项或使用`DISTINCT`，产生错误的总数。 该解决方案不会删除重复记录，确保每笔销售都完全按照预期为卖家带来收入。
