[LeetCode 第 1046 题](https://leetcode.com/problems/last-stone-weight/)

 **难度：** 🟢简单
 **主题：** 数组、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 这个问题要求我们反复模拟一个涉及不同重量的石头的过程。 每次，我们都必须选择**两块最重的石头**，将它们粉碎在一起，并根据结果更新集合。 

如果两块最重的石头重量相同，则两者都会被摧毁并从收藏中消失。 如果石头的重量不同，则较小的石头会被破坏，较大的石头会幸存下来，其重量减少等于两者之间的差值。 

我们继续这个过程，直到剩下一颗石头或没有石头剩下。 目标是返回最后一块石头的重量，或者`0`如果每块石头都被摧毁。 

输入是一个整数数组`stones`，其中每个值代表一颗石头的重量。 输出是一个整数，表示最后剩下的石头的重量。 

限制很小：

 -`1 <= stones.length <= 30`-`1 <= stones[i] <= 1000`这些限制告诉我们，石头的数量是非常有限的。 即使是低效的解决方案也可能会通过，但问题的设计是为了引入一种重要的数据结构模式，使用**堆（优先级队列）**来高效地重复检索最大的元素。 

一个重要的观察是，游戏始终取决于**当前的两个最重的石头**，这意味着每次操作后集合都会动态变化。 重复排序或扫描数组的简单实现可以工作，因为输入大小很小，但优先级队列是一种更干净且更具可扩展性的方法。 

一些边缘情况值得尽早识别。 如果只有一块石头，那块石头就已经是答案了。 如果所有棋子完美地相互抵消，结果应该是`0`。 重复的重复值也会创建消除链，因此实现必须在每次粉碎后仔细更新数据结构。 

## 方法

 ### 蛮力方法

 解决这个问题最直接的方法就是对数组进行重复排序。 

在每次迭代中，我们按降序对石头进行排序，以便两个最重的石头出现在前面。 我们取出这两块石头并比较它们的重量。 

如果权重相等，则两者都会消失。 如果它们不同，我们将差异插入回列表中。 然后我们重复这个过程，直到最多剩下一块石头。 

这种方法是正确的，因为排序保证我们总是挑选两个最重的石头，完全符合问题的规则。 然而，每次粉碎后对数组进行排序效率很低，因为排序成本`O(n log n)`时间，我们可能会重复这个操作很多次。 

尽管约束足够小，该解决方案可以通过，但从算法的角度来看，它并不理想。 

### 最佳解决方案的关键见解

 重要的观察是我们反复需要访问**最大的元素**。 

我们可以使用**最大堆**，而不是在每次操作后对整个数组进行排序，它允许我们有效地检索和删除数组中最大的元素`O(log n)`时间。 

堆非常适合这里，因为：

 1. 我们反复需要最大值。 
2. 每次粉碎后，集合会动态变化。 
3.我们只需要本地排序，不需要全排序。 

Python提供了内置的最小堆，因此我们通过存储负值来模拟最大堆。 在 Go 中，我们使用以下方法实现堆`container/heap`打包并定制它以充当最大堆。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 |`O(n² log n)`|`O(1)`或者`O(n)`| 每次粉碎后重复对数组进行排序 |
 | 最佳 |`O(n log n)`|`O(n)`| 使用最大堆进行有效的最大元素检索 |

 ## 算法演练

 1. 初始化一个包含所有石头重量的最大堆。 由于 Python 仅支持最小堆，因此将每个值存储为负数，因此最大权重的行为类似于最小堆值。 
2. 将输入列表转换为堆。 此预处理步骤需要线性时间并为有效删除准备数据结构。 
3. 当堆中至少包含两块石头时，移走两块最重的石头。 这些代表根据问题规则所需的粉碎操作。 
4. 比较两块石头。 如果它们相等，则两者都会被销毁，因此不会将任何内容插入回堆中。 
5. 如果石头的重量不同，请计算它们之间的差值，然后将剩余的石头放回堆中。 
6. 继续此过程，直到堆中最多剩下一颗石头。 
7. 如果还剩下一块石头，则返回其重量。 否则，返回`0`。 

### 为什么它有效

 该算法的正确性来自于维持堆中始终包含当前剩余石子集的不变性。 在每次迭代中，提取两个最大值可以保证我们遵循粉碎两块最重的石头的精确游戏规则。 当重量不相等时，重新插入差异可以正确模拟幸存的石头。 由于每一步都忠实地模拟了游戏的一个合法动作，因此最终的剩余值一定是正确的答案。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def lastStoneWeight(self, stones: List[int]) -> int:
        # Convert to max heap using negative values
        max_heap = [-stone for stone in stones]
        heapq.heapify(max_heap)

        while len(max_heap) > 1:
            heaviest = -heapq.heappop(max_heap)
            second_heaviest = -heapq.heappop(max_heap)

            if heaviest != second_heaviest:
                remaining_stone = heaviest - second_heaviest
                heapq.heappush(max_heap, -remaining_stone)

        return -max_heap[0] if max_heap else 0
```实施过程首先将每块石头的重量转换为负值。 这是必要的，因为 Python 的`heapq`模块实现了最小堆，而我们需要最大堆行为。 

打电话后`heapify`，列表在线性时间内成为有效的堆结构。 

在循环内部，我们通过弹出两个最小的负值来重复删除两个最大的石头。 我们将它们转换回正整数进行比较。 

如果石头不相等，我们计算差异并将幸存的石头推回堆中。 相同的石头自然会消失，因为没有任何东西被添加回来。 

最后，当循环结束时，我们要么返回剩余的石头，要么`0`如果没有留下任何石头。 

## 解决方案```go
package main

import (
	"container/heap"
)

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func lastStoneWeight(stones []int) int {
	maxHeap := MaxHeap(stones)
	heap.Init(&maxHeap)

	for maxHeap.Len() > 1 {
		heaviest := heap.Pop(&maxHeap).(int)
		secondHeaviest := heap.Pop(&maxHeap).(int)

		if heaviest != secondHeaviest {
			heap.Push(&maxHeap, heaviest-secondHeaviest)
		}
	}

	if maxHeap.Len() == 0 {
		return 0
	}

	return heap.Pop(&maxHeap).(int)
}
```Go 实现使用`container/heap`包，它需要定义一个自定义堆类型来实现`heap.Interface`。 

关键的定制发生在`Less`方法。 通过反转比较`<`到`>`，堆表现为**最大堆**，而不是默认的最小堆。 

与 Python 不同，Go 不需要负值，因为可以直接自定义堆排序。 由于约束很小并且石头重量有限，因此整数溢出不是问题。

    def lastStoneWeight(self, stones: List[int]) -> int:

        max_heap = [-stone for stone in stones]
        heapq.heapify(max_heap)

        while len(max_heap) > 1:
            first = -heapq.heappop(max_heap)

 ## 边缘情况

 ### 单石输入

 当输入仅包含一颗石子时，无需执行粉碎操作。 幼稚的实现可能会错误地尝试删除两个元素并导致索引错误。 此实现可以自然地处理这种情况，因为循环仅在至少存在两个石子时运行。 剩下的石头直接退回。 

### 所有宝石取消

 输入如`[2,2]`或者`[5,5,5,5]`从而彻底消除所有结石。 有缺陷的实现可能会假设一块石头总是存活下来并尝试访问空堆。 该解决方案安全地检查堆是否为空并返回`0`如果没有留下任何石头。 

### Unequal Final Smash

Cases like`[10,4]`或者`[8,7]`减去后留下一颗幸存的石头。 一个常见的错误是忘记将剩余权重重新插入数据结构中。 每当两个石头不相等时，此实现都会显式地将差异推回到堆中。 

### 重复的重复值

 具有许多重复权重的输入，例如`[1,1,2]`或者`[5,5,5,5]`，可以触发长链消除。 不正确的实现可能会错误地处理重复项或无法在更新后保留堆排序。 由于堆在每次插入后自动恢复顺序，因此算法在整个执行过程中继续选择正确的两个最重的石头。
