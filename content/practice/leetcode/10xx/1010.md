[LeetCode 问题 1010](https://leetcode.com/problems/pairs-of-songs-with-total-durations-divisible-by-60/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到总持续时间可被 60 整除的歌曲对。具体来说，我们给出一个数组`time`其中每个元素代表歌曲的长度（以秒为单位）。 我们需要计算所有独特的对`(i, j)`在哪里`i < j`和`(time[i] + time[j]) % 60 == 0`。 

输入数组的长度最多为 60,000，每首歌曲的持续时间在 1 到 500 秒之间。 这意味着在最坏的情况下，检查每一对的简单暴力方法将需要大约 18 亿次操作（`n*(n-1)/2`），这太慢了。 

边缘情况包括所有持续时间都是 60 的倍数、所有持续时间相同但不能被 60 整除或数组只有一个元素的情况。 该问题保证至少有一个元素，因此我们不需要处理空数组。 

## 方法

 蛮力方法涉及迭代所有对`(i, j)`并检查它们的总和是否能被 60 整除。这保证了正确性，因为它实际上检查了每个可能的对。 然而，它的时间复杂度是 O(n²)，这对于`n`最多 60,000。 

最佳方法使用模算术和哈希图（或大小为 60 的数组）来计算余数。 关键的见解是对于任意两个数字`a`和`b`,`(a + b) % 60 == 0`当且仅当`(a % 60 + b % 60) % 60 == 0`。 因此，对于每首歌曲，我们可以计算其模 60 的余数，并检查之前看过的歌曲中有多少具有互补余数`(60 - remainder) % 60`。 这使我们能够在一次传递中计算有效对的数量，从而将复杂性降低到 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 显式检查每一对 |
 | 最佳| O(n) | O(60) = O(1) | 使用模数和频率计数来查找互补对 |

 ## 算法演练

 1.初始化一个数组`remainders`大小为 60，用于存储每个可能的余数模 60 的歌曲数。同时初始化一个变量`count`有效对的总数为零。 
2. 迭代每首歌曲的时长`time`。 
3. 对于每个持续时间，计算`remainder = duration % 60`。 
4. 计算可被 60 整除的和所需的余数：`complement = (60 - remainder) % 60`。 
5. 将之前看过的歌曲数与余数相加`count`。 
6. 增加当前余数的计数`remainders`大批。 
7. 迭代完所有歌曲后，返回总数`count`。 

为什么它有效：该算法之所以有效，是因为对于每首歌曲，我们直接计算可以与已看过的歌曲形成的所有有效对。 使用模运算确保我们只检查可被 60 整除的和，并且哈希数组有效地跟踪所有先前的余数。 

## Python 解决方案```python
from typing import List

class Solution:
    def numPairsDivisibleBy60(self, time: List[int]) -> int:
        remainders = [0] * 60
        count = 0
        for t in time:
            remainder = t % 60
            complement = (60 - remainder) % 60
            count += remainders[complement]
            remainders[remainder] += 1
        return count
```Python实现使用固定大小的数组`remainders`计算每个余数以 60 为模的出现次数。对于每首歌曲，它计算达到 60 倍数所需的补数，并立即将此类先前歌曲的数量添加到总数中。 这确保每对都被精确计数一次，并且数组更新确保未来的歌曲可以与其形成有效的对。 

## 解决方案```go
func numPairsDivisibleBy60(time []int) int {
    remainders := make([]int, 60)
    count := 0
    for _, t := range time {
        remainder := t % 60
        complement := (60 - remainder) % 60
        count += remainders[complement]
        remainders[remainder]++
    }
    return count
}
```Go 实现镜像了 Python 版本。 Go 切片有效地处理索引和动态更新。 主要区别在于 Go 需要显式切片初始化`make`。 算法逻辑保持不变。

 ## 边缘情况

 一个重要的边缘情况是当所有持续时间都是 60 的倍数时。每对歌曲形成一个有效的组合，算法会处理这种情况，因为余数 0 的补码本身就是 0，并且数组计数正确地累积了先前的歌曲。 

当一对数字之和恰好为 60 但数字本身不是 60 的倍数时，会出现另一种边缘情况。例如，`[1, 59]`形成一个有效的对。 模运算可确保正确计算此类补数。 

第三种边缘情况是最小输入大小，其中数组只有一首歌曲。 由于不能存在一对，因此该函数会正确返回 0。这对于防止索引或计数错误非常重要。 

这些边缘情况证明了基于余数的计数方法的稳健性。
