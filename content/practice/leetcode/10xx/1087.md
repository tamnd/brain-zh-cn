[LeetCode 1087 题](https://leetcode.com/problems/brace-expansion/)

 **难度：** 🟡 中等
 **主题：** 字符串、回溯、堆栈、广度优先搜索、排序

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到一个表示多个可能单词的字符串。 单词中的每个位置可以包含单个固定字符或一组用大括号括起来的替代字符。 

例如：```
a{b,c}d
```意思是：

 - 第一个字符始终是`'a'`- 第二个字符可以是`'b'`或者`'c'`- 第三个字符始终是`'d'`所以有效的生成词是：```
["abd", "acd"]
```任务是生成通过从每个位置选择一个选项可以形成的每个可能的单词，然后返回按字典顺序排序的结果。 

输入格式有几个可以简化问题的保证：

 - 没有嵌套大括号。 
- 每个大括号组包含不同的小写字母。 
- 该字符串始终有效。 
- 最大长度仅为 50 个字符。 

这些约束告诉我们解析字符串相对简单。 由于没有嵌套大括号，因此我们永远不需要递归解析逻辑或基于堆栈的表达式求值。 我们只需要判断当前位置是否是：

 - 单个字符，或
 - 以逗号分隔的选项组。 

主要挑战是正确且高效地生成所有组合。 

一个重要的观察是，生成的字符串总数可以呈指数增长。 例如：```
{a,b,c}{d,e,f}{g,h,i}
```已经生产：```
3 × 3 × 3 = 27
```结果。 

这意味着任何正确的解决方案最终都必须花费与生成的单词数量成比例的时间。 

一些重要的边缘情况包括：

 - 根本没有大括号的字符串，例如`"abcd"`- 出现在开头或结尾的大括号组
 - 多个连续支架组
 - 单选项组，例如`"{a}"`，尽管不常见
 - 词典排序要求

 该问题保证了有效的语法，因此我们不需要处理格式错误的大括号表达式。 

## 方法

 ### 蛮力方法

 蛮力的想法是直接从原始字符串递归地尝试每种可能的解释，而不进行预处理。 

在每个字符处：

 - 如果该字符是普通字母，则将其附加到当前字符串。 
- 如果角色是`'{'`，向前扫描直到`'}'`，提取所有选项，并为每个选项递归分支。 

这是有效的，因为每个有效单词都对应于每个位置的一个选择序列。 

然而，这种方法在递归期间重复扫描字符串的各个部分。 每个递归分支可能需要搜索右大括号并重复解析逗号分隔的选项。 这会带来不必要的重复工作。 

尽管约束足够小，这仍然可以通过，但这不是最简洁或最有效的设计。 

### 最佳方法

 关键的见解是问题自然分为两个阶段：

 1. 将输入解析为字符选择组
 2.使用回溯生成所有组合

 例如：```
"{a,b}c{d,e}"
```可以先转化为：```
[
    ['a', 'b'],
    ['c'],
    ['d', 'e']
]
```一旦我们有了这个结构，问题就变成了经典的笛卡尔乘积生成问题。 

回溯在这里是理想的选择，因为：

 - 每个位置贡献一个角色
 - 我们逐步构建字符串
 - 每一层递归都对应一个字符位置
 - 我们对每个有效组合都只探索一次

 如果我们在回溯之前对每个选项组进行排序，排序就会变得很容易。 由于递归按顺序探索选择，因此生成的结果会自动按字典顺序排序。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N × K) | O(K) | 在递归过程中反复重新解析字符串的各个部分 |
 | 最佳| O(N + K) | O(K) | 解析一次，然后高效生成组合 |

 在哪里：

-`N`= 输入字符串的长度
 -`K`= 所有生成的输出字符串的总大小

 由于输出生成本身是不可避免的，`K`主导复杂性。 

## 算法演练

 ### 步骤 1：将字符串解析为选项组

 我们从左到右迭代输入字符串。 

如果当前字符是小写字母：

 - 创建包含该字符的单选项组。 

如果当前字符是`'{'`:

 - 继续扫描直到`'}'`- 用逗号分割内容
 - 对提取的选项进行排序
 - 将它们存储为一组

 例如：```
"{a,b}c{d,e}"
```变成：```
[
    ['a', 'b'],
    ['c'],
    ['d', 'e']
]
```此预处理步骤使生成阶段变得更加简单。 

### 第 2 步：使用回溯来构建单词

 我们一次递归地处理一组。 

在递归级别`i`:

 - 从其中选择一个角色`groups[i]`- 将其附加到当前的部分单词
 - 递归到下一组
 - 之后删除角色以回溯

 这探索了每一种可能的组合。 

### 步骤 3：存储完整的单词

 当递归深度等于组数时：

 - 我们从每个位置选择了一个角色
 - 将累积的字符连接成一个完整的单词
 - 将其添加到结果列表中

 ### 第四步：返回结果

 由于组和选项是按排序顺序处理的，因此生成的结果已经按字典顺序排序。 

不需要额外的排序步骤。 

### 为什么它有效

 该算法之所以有效，是因为每个生成的单词都对应于从每个解析组中选择一个选项。 

递归系统地探索所有此类选择，而不重复：

 - 每个递归级别代表最终单词中的一个位置。 
- 探索该职位的每个有效选项。 
- 在尝试下一个选项之前，回溯会正确恢复状态。 

由于所有组合都被探索一次，并且选择按排序顺序处理，因此该算法按字典顺序生成每个有效单词。 

## Python 解决方案```python
from typing import List

class Solution:
    def expand(self, s: str) -> List[str]:
        groups = []
        i = 0

        # Parse the input into groups
        while i < len(s):
            if s[i] == '{':
                j = i

                while s[j] != '}':
                    j += 1

                options = s[i + 1:j].split(',')
                options.sort()

                groups.append(options)
                i = j + 1
            else:
                groups.append([s[i]])
                i += 1

        result = []
        path = []

        # Backtracking
        def backtrack(index: int) -> None:
            if index == len(groups):
                result.append(''.join(path))
                return

            for char in groups[index]:
                path.append(char)
                backtrack(index + 1)
                path.pop()

        backtrack(0)

        return result
```实现首先将字符串解析为组列表。 每组包含最终单词中一个位置的所有有效字符。 

对于大括号表达式，我们扫描直到右大括号，用逗号分隔，对选项进行排序，并将它们存储在一起。 对于普通字母，我们只需创建一个单元素组。 

解析之后，我们使用递归回溯函数。 

这`path`list 存储当前部分构造的单词。 在每个递归级别，我们迭代当前位置的所有可能的字符。 

当我们到达所有组的末尾时，我们将角色加入`path`到一个字符串并将其附加到结果中。 

这`append`和`pop`操作实现经典的回溯状态管理。 每个递归调用都会暂时添加一个字符，探索更深层次的组合，然后恢复之前的状态。 

由于所有选项在递归开始之前都已排序，因此生成的结果自然会按字典顺序出现。 

## 解决方案```go
package main

import (
	"sort"
	"strings"
)

func expand(s string) []string {
	var groups [][]string

	// Parse the input
	for i := 0; i < len(s); {
		if s[i] == '{' {
			j := i

			for s[j] != '}' {
				j++
			}

			options := strings.Split(s[i+1:j], ",")
			sort.Strings(options)

			groups = append(groups, options)
			i = j + 1
		} else {
			groups = append(groups, []string{string(s[i])})
			i++
		}
	}

	var result []string
	var path []string

	var backtrack func(int)

	backtrack = func(index int) {
		if index == len(groups) {
			result = append(result, strings.Join(path, ""))
			return
		}

		for _, ch := range groups[index] {
			path = append(path, ch)
			backtrack(index + 1)
			path = path[:len(path)-1]
		}
	}

	backtrack(0)

	return result
}
```Go 实现遵循与 Python 版本相同的整体算法。 

一个显着的区别是 Go 字符串是不可变的，因此当前单词存储为一个字符串切片，称为`path`。 当构建一个完整的单词时，`strings.Join`结合了人物。 

回溯状态恢复使用切片截断：```go
path = path[:len(path)-1]
```这有效地删除了最后附加的字符。 

解析器使用`strings.Split`提取大括号选项和`sort.Strings`以维持字典顺序。

```### 回溯追踪

 | 步骤| 路径| 行动|
 | ---| ---| ---|
 | 1 |`['a']`| 选择`'a'`|
 | 2 |`['a', 'c']`| 选择`'c'`|
 | 3 |`['a', 'c', 'd']`| 选择`'d'`|
 | 4 |`['a', 'c', 'd', 'f']`| 选择`'f'`|
 | 5 |`"acdf"`| 添加结果 |
 | 6 | 回溯| 消除`'f'`|
 | 7 |`['a', 'c', 'e', 'f']`| 选择`'e'`， 然后`'f'`|
 | 8 |`"acef"`| 添加结果 |
 | 9 | 继续`'b'`分支机构 | 重复过程 |

 最终输出：```
["acdf", "acef", "bcdf", "bcef"]
```### 示例 2

 输入：```
"abcd"
```### 解析阶段

 | 人物 | 解析组|
 | ---| ---|
 |`a`|`['a']`|
 |`b`|`['b']`|
 |`c`|`['c']`|
 |`d`|`['d']`|

 团体：```
[
    ['a'],
    ['b'],
    ['c'],
    ['d']
]
```由于每个组只有一个选项，因此递归遵循一条路径：```
a -> b -> c -> d
```最终输出：```

```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N + K) | 解析需要 O(N)，生成所有输出字符串需要 O(K) |
 | 空间| O(K) | 输出存储主导内存使用|

 在哪里：

-`N`是输入字符串的长度
 -`K`is the total number of characters across all generated strings

The recursive call stack depth is at most the number of character positions, which is bounded by the input length. Since every valid output must be stored, the result list dominates space complexity.

 ## 边缘情况

 ### 输入不带任何大括号

 错误的常见来源是假设每个输入都包含大括号表达式。 对于如下输入：```
"abcd"
```该算法必须仍然正确工作。 

解析器通过将每个字符视为单选项组来自然地处理此问题：```
[['a'], ['b'], ['c'], ['d']]
```然后回溯阶段恰好产生一个结果。 

### 连续支撑组

 输入例如：```
"{a,b}{c,d}"
```可能会暴露索引或递归错误，因为没有固定的字符分隔组。 

解析器独立地正确处理每个大括号块，产生：```
[['a', 'b'], ['c', 'd']]
```然后回溯探索所有笛卡尔积组合。 

### 字典顺序

 该问题需要排序输出，如果按原始顺序处理大括号选项，则可以忽略该输出。 

例如：```
"{c,b,a}"
```必须产生：```
["a", "b", "c"]
```该实现在递归开始之前显式地对每个大括号组的选项进行排序。 由于回溯按排序顺序遍历选择，因此最终结果会自动按字典顺序排序，而无需随后进行单独的排序步骤。
