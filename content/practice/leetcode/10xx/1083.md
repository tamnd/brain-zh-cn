 ## 解决方案

 ## 问题理解

 This problem asks us to identify all buyers who purchased the product named`S8`但从未购买过名为`iPhone`。 

我们有两张表：

 的`Product`表存储有关产品的信息。 每行包含一个唯一的`product_id`, the product name, and its unit price.

 这`Sales`表存储销售交易。 Each row represents a purchase event involving a buyer and a product. A buyer may appear multiple times because they can purchase multiple products or make repeated purchases of the same product.

 The task is not asking for the products themselves. 相反，我们必须返回`buyer_id`同时满足两个条件的值：

 1. The buyer purchased at least one`S8`2. 买家从未购买过`iPhone`输出可以按任何顺序返回。 

重要的细节是产品名称存储在`Product`表，而购买存储在`Sales`桌子。 这意味着我们必须使用连接两个表`product_id`以确定每个买家购买了哪种产品。 

约束相对较小，因为这是一个 Easy SQL 问题，但逻辑挑战是根据包含和排除条件正确过滤买家。 

一些边缘情况很重要：

 买家可能会多次购买同一产品。 我们仍然应该只将该买家退回一次。 

买家可以同时购买`S8`和`iPhone`。 此类买家必须被排除在外。 

买家可能不会购买任何一种产品。 此类买家不应出现在结果中。 

除此之外可能还有多种产品`S8`和`iPhone`。 These extra products should not affect the result.

 The problem guarantees that product names exist in the`Product`表，因此我们不需要处理丢失的产品参考。 

## 方法

 ### 蛮力方法

 暴力解决方案首先将每一行加入`Sales`与相应的产品`Product`。 然后，对于每个买家，我们可以扫描他们的所有购买并维护他们购买的产品列表。 

在为每个买家建立完整的购买历史记录后，我们将检查：

 - 该买家是否购买过`S8`？ 
- 该买家是否购买过`iPhone`？ 

如果第一个答案为“是”，而第二个答案为“否”，我们会将买家包含在结果中。 

这种方法是正确的，因为它明确评估每个买家的每次购买。 然而，它的效率很低，因为它可能会重复扫描购买历史并存储不必要的信息。 

### 最佳方法

 关键的见解是我们只关心两种特定产品：

 -`S8`-`iPhone`我们可以直接按买家对购买进行分组并使用条件聚合，而不是存储每个买家购买的每件产品。 

我们加入`Sales`和`Product`，然后对行进行分组`buyer_id`。 

For each buyer, we compute:

- Whether they bought`S8`- 他们是否购买了`iPhone`这可以使用聚合函数有效地完成，例如`SUM`或者`COUNT`与条件表达式。 

然后我们使用以下条件过滤买家`HAVING`条款：

 -`S8`购买数量必须大于零
 -`iPhone`purchase count must equal zero

This avoids unnecessary processing and keeps the query concise and efficient.

 ## 算法演练

 1. 加入`Sales`表与`Product`表使用`product_id`。 

这一步是必要的，因为`Sales`表只包含产品 ID，而产品名称存储在`Product`。 
2. Group all rows by`buyer_id`。 

分组使我们能够一起评估属于同一买家的所有购买。 
3. 对于每个买家，统计他们购买的次数`S8`。 

这可以使用条件聚合表达式来完成，例如：```
SUM(product_name = 'S8')
```或者```
SUM(CASE WHEN product_name = 'S8' THEN 1 ELSE 0 END)
```4. 对于每个买家，统计他们购买的次数`iPhone`。 

我们使用类似的条件聚合表达式`iPhone`。 
5. 使用`HAVING`子句来过滤组。 

只保留买家：

 -`S8`计数大于零
 -`iPhone`计数为零
 6. 返回`buyer_id`价值观。 

### 为什么它有效

 该算法之所以有效，是因为分组依据`buyer_id`保证买家的所有购买都被一起评估。 条件聚合正确跟踪买家是否购买了特定产品。 这`HAVING`然后精确筛选满足所需纳入和排除条件的买家。 

## Python 解决方案

 虽然这是一个 SQL 问题，但 LeetCode 数据库问题是使用 SQL 查询而不是 Python 类来解决的。 The following is the correct MySQL solution.```python
# This problem is solved using SQL, not Python code.

SELECT s.buyer_id
FROM Sales s
JOIN Product p
ON s.product_id = p.product_id
GROUP BY s.buyer_id
HAVING SUM(CASE WHEN p.product_name = 'S8' THEN 1 ELSE 0 END) > 0
   AND SUM(CASE WHEN p.product_name = 'iPhone' THEN 1 ELSE 0 END) = 0;
```查询首先连接`Sales`和`Product`因此每次销售都可以与其产品名称相关联。 

接下来，它对行进行分组`buyer_id`，确保买家的所有购买都一起处理。 

两人`SUM(CASE WHEN ...)`表达式的作用类似于布尔计数器：

 - 第一个重要`S8`购买
 - 第二个很重要`iPhone`购买

 最后，`HAVING`条款过滤至少购买过一件的买家`S8`和零`iPhone`产品。

 ## 边缘情况

 ### 买家同时购买 S8 和 iPhone

 这是最重要的边缘情况，因为简单的实现可能会在检测到`S8`购买并错误地包含买家。 

该实现通过单独计数来正确处理这个问题`iPhone`购买并明确要求该计数为零。 

### 买家多次购买同一产品

 买家可以购买`S8`几次。 The result should still contain the buyer only once.

 因为查询分组依据`buyer_id`，每个买家最多在输出中出现一次，无论他们购买了多少次。 

### 存在不相关产品

 除了以下内容之外，数据库还可能包含许多产品`S8`和`iPhone`。 

有缺陷的实现可能会意外地包含或排除基于不相关产品的买家。 条件聚合可以防止这种情况，因为只有匹配的行`S8`或者`iPhone`影响计数。
