 **难度：** 🟡 中等
 **主题：** 数组、二分查找、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到只能包含的最长连续子数组的长度`1`最多翻转后 s`k`零变为一。 

输入包括：

 - 二进制数组`nums`，其中每个元素都是`0`或者`1`- 一个整数`k`，代表我们可以翻转的最大零个数

 目标是返回连续段的最大大小，通过改变不超过`k`零。 

例如，假设我们有：```
nums = [1,1,1,0,0,1]
k = 1
```我们可以翻转其中一个零，这使我们能够创建更长的连续零。 问题是要求进行此类翻转后的最大可能长度。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 二次解太慢
 - 我们需要接近线性时间的东西

 由于数组仅包含二进制值，因此我们可以将问题视为维护一个窗口，其中零的数量不超过`k`。 

一些边缘情况很重要：

 -`k = 0`，意味着不允许翻转
 - 该数组仅包含一个
 - 数组仅包含零
 -`k`大于或等于数组中零的数量
 - 非常小的数组，例如长度`1`如果重复扫描子数组或重新计算零计数，简单的实现很容易变得低效。 

## 方法

 ### 蛮力方法

 强力解决方案考虑每个可能的子数组。 

对于每个起始索引，我们一次一步扩展结束索引，并计算子数组内出现的零个数。 如果零的数量超过`k`，子数组变得无效。 否则，我们更新最大长度。 

这种方法是正确的，因为它显式地检查每个连续的段并评估它是否可以转换为最多具有以下内容的所有段：`k`翻转。 

然而，有`O(n^2)`可能的子数组，并且对所有子数组进行计数或维护零对于`n = 10^5`。 

### 最优滑动窗口方法

 关键的观察是我们只关心当前窗口是否最多包含`k`零。 

如果一个窗口是有效的，意味着它最多包含`k`零，那么它里面的每个子数组也是有效的。 这一特性使得该问题非常适合滑动窗口技术。 

我们维护两个指针：

 -`left`, 窗口的开始
 -`right`, 窗口的末端

 当我们向右扩展窗口时：

 - 我们计算里面有多少个零
 - 如果零计数超过`k`，我们从左侧缩小窗口，直到它再次有效
 - 在每一步中，我们都会跟踪最大有效窗口长度

 每个元素最多进入和离开窗口一次，给出`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个可能的子数组 |
 | 最佳| O(n) | O(1) | O(1) | 滑动窗口最多维持`k`零 |

 ## 算法演练

 1.初始化两个指针，`left = 0`和`right = 0`。 

这些指针定义了当前的滑动窗口。 
2. 初始化变量`zero_count = 0`。 

这跟踪当前窗口内存在多少个零。 
3. 初始化`max_length = 0`。 

这存储了迄今为止看到的最长有效窗口的长度。 
4. 使用迭代遍历数组`right`。 

在每个步骤中，包括`nums[right]`进入窗户。 
5.如果`nums[right] == 0`, 增量`zero_count`。 

这反映了这样一个事实：我们需要翻转一次才能得到这个零。 
6.如果`zero_count > k`，窗口无效。 

现在我们从左侧缩小窗口，直到它再次有效。 
7. 收缩时：

 - 如果`nums[left] == 0`, 递减`zero_count`- 增量`left`这将从窗口中一一删除元素。 
8. 一旦窗口再次有效，计算其长度：```
window_length = right - left + 1
```1. 更新`max_length`如果这个窗口比之前的最佳窗口大。 
2. 继续，直到处理完整个数组。 

### 为什么它有效

 该算法保持当前窗口始终最多包含的不变量`k`零。 

每当零的数量超过`k`，左指针向前移动，直到约束恢复。 由于窗口在调整后始终有效，因此记录的每个窗口长度都代表一个可行解。 

因为两个指针都只向前移动，所以每个元素最多被处理两次，一次进入窗口时，一次离开窗口时。 这保证了线性时间复杂度。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestOnes(self, nums: List[int], k: int) -> int:
        left = 0
        zero_count = 0
        max_length = 0

        for right in range(len(nums)):
            if nums[right] == 0:
                zero_count += 1

            while zero_count > k:
                if nums[left] == 0:
                    zero_count -= 1
                left += 1

            current_length = right - left + 1
            max_length = max(max_length, current_length)

        return max_length
```实现直接遵循滑动窗口策略。 

变量`left`跟踪当前有效窗口的开始，而循环变量`right`一次将窗口展开一个元素。 

每当窗口中添加一个零时，`zero_count`增加。 如果零的数量大于`k`，窗口不再有效。 这`while`循环从左侧缩小窗口，直到零的数量再次可接受。 

恢复有效性后，计算当前窗口长度并与迄今为止找到的最佳答案进行比较。 

该算法绝不会在不必要的情况下重新访问元素，这就是它实现线性性能的原因。 

## 解决方案```go
func longestOnes(nums []int, k int) int {
    left := 0
    zeroCount := 0
    maxLength := 0

    for right := 0; right < len(nums); right++ {
        if nums[right] == 0 {
            zeroCount++
        }

        for zeroCount > k {
            if nums[left] == 0 {
                zeroCount--
            }
            left++
        }

        currentLength := right - left + 1
        if currentLength > maxLength {
            maxLength = currentLength
        }
    }

    return maxLength
}
```Go 的实现与 Python 版本非常相似。 

Go 使用显式变量声明和标准`for`循环而不是 Python 的迭代器语法。 由于所有值都适合标准整数范围，因此不存在整数溢出问题。 

Go 中的切片已经表现得像动态数组视图，因此除了正常逻辑之外，不需要对空或 nil 切片进行特殊处理。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 0`。 在这种情况下，我们不允许翻转任何零，因此问题就变成了找到最长的现有序列。 有缺陷的实现可能仍然允许包含零的无效窗口。 该解决方案可以自然地处理这种情况，因为只要出现一个零，窗口就会立即缩小。 

另一个重要的情况是数组仅包含零。 如果`k`小于数组长度，答案应该是`k`，因为我们只能翻转那么多元素。 每当零的数量超过时，滑动窗口就会通过缩小来正确限制窗口大小`k`。 

当发生第三种边缘情况时`k`大于整个数组中零的数量。 在这种情况下，整个数组可以转换为一个。 一些实现错误地继续不必要地缩小窗口，但该算法永远不会缩小，除非`zero_count > k`，因此正确返回完整的数组长度。 

一个微妙的情况涉及非常小的数组，例如长度`1`。 计算窗口大小时，相差一的错误很常见。 使用公式：```
right - left + 1
```即使对于单元素窗口，也确保正确计算窗口长度。
