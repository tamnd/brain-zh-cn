[LeetCode 1089 题](https://leetcode.com/problems/duplicate-zeros/)

 **难度：** 🟢简单
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 该问题要求我们通过复制每个零并将后续元素向右移动来就地修改固定长度整数数组。 问题的关键部分是数组具有固定长度，因此任何超出原始大小的元素都会被丢弃。 例如，如果复制零会将某个元素推到数组边界之外，则该元素就会丢失。 

输入数组`arr`包含之间的整数`0`和`9`，其长度介于`1`和`10^4`。 预期输出是就地修改以反映零重复的同一数组。 这是一个就地问题，因此不应创建新数组。 

要考虑的边缘情况包括没有零的数组（没有任何变化）、完全用零填充的数组（许多元素丢失）、数组末尾的零（复制它们可能会溢出）以及长度为 1 的数组（微不足道但不应失败）。 

## 方法

 简单或暴力的方法从左到右迭代数组，每次遇到零时，它都会将所有后续元素向右移动一个位置，为重复的零腾出空间。 这种方法是正确的，因为它从字面上模拟了问题中描述的过程，但效率低下。 重复移动元素会导致 O(n^2) 时间复杂度，对于长度高达 10,000 的数组来说，这可能非常慢。 

最佳方法使用两次传递策略，并且我们只需要知道在复制零后哪些元素将可见。 首先，我们计算在不超出数组边界的情况下将重复多少个零。 然后，我们从数组末尾向后迭代，以相反的顺序将元素复制到正确的位置。 通过向后迭代，我们可以避免覆盖仍然需要处理的元素。 这种方法在 O(n) 时间和 O(1) 额外空间内就地工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 对于每个零向右移动元素，对于大型数组来说速度较慢 |
 | 最佳| O(n) | O(1) | O(1) | 计算零，向后复制元素以避免覆盖 |

 ## 算法演练

 1. 计算需要重复的零的总数。 从左到右迭代数组，保持零的计数。 如果所需的总位置（原始长度 + 零计数）超过数组长度，请调整计数，以便我们仅复制适合数组边界的零。 
2. 从原数组的最后一个索引开始反向迭代。 维护一个虚拟索引，该索引表示扩展数组中的位置（包括重复项）。 
3. 对于每个元素，如果它是零，则在数组中的正确位置写入两个零（如果它们在界限内）。 对于非零元素，将元素复制到数组中的计算位置。 
4. 递减向后指针并继续，直到到达数组的开头。 

为什么有效：通过向后迭代并使用虚拟索引来表示复制后的位置，我们可以避免覆盖尚未处理的元素。 这保证了就地修改是正确的，并且所有零都根据需要重复。 

## Python 解决方案```python
from typing import List

class Solution:
    def duplicateZeros(self, arr: List[int]) -> None:
        """
        Do not return anything, modify arr in-place instead.
        """
        n = len(arr)
        zeros_to_duplicate = 0
        for num in arr:
            if num == 0:
                zeros_to_duplicate += 1

        i = n - 1
        j = n + zeros_to_duplicate - 1

        while i >= 0:
            if j < n:
                arr[j] = arr[i]
            if arr[i] == 0:
                j -= 1
                if j < n:
                    arr[j] = 0
            i -= 1
            j -= 1
```该实现首先对零进行计数以确定可以容纳多少个重复项。 然后，它使用两个指针向后迭代：`i`对于原始数组和`j`对于“虚拟”扩展数组。 元素被复制到新位置。 如果遇到零，则将其重复，但前提是该位置位于原始数组范围内。 

## 解决方案```go
func duplicateZeros(arr []int)  {
    n := len(arr)
    zerosToDuplicate := 0
    for _, num := range arr {
        if num == 0 {
            zerosToDuplicate++
        }
    }

    i := n - 1
    j := n + zerosToDuplicate - 1

    for i >= 0 {
        if j < n {
            arr[j] = arr[i]
        }
        if arr[i] == 0 {
            j--
            if j < n {
                arr[j] = 0
            }
        }
        i--
        j--
    }
}
```Go 实现镜像了 Python 版本。 Go 切片处理边界检查，因此我们显式检查`j < n`在写作之前。 向后迭代和虚拟索引逻辑保持相同。

 ## 边缘情况

 一种边缘情况是没有零的数组。 总是移动元素的简单实现会不必要地覆盖值。 我们的解决方案可识别零计数并避免不必要的写入。 

另一个边缘情况是数组末尾的零。 尝试复制它们可能会使元素超出范围。 向后迭代确保我们只在有效索引内写入。 

第三种边缘情况是长度为一的数组。 该算法自然地处理这个问题，因为向后循环正确终止，并且不会发生超出数组边界的重复。 即使对于最小的输入，这也保证了正确性。
