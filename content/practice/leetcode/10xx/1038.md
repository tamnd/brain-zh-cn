[LeetCode 问题 1038](https://leetcode.com/problems/binary-search-tree-to-greater-sum-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题给了我们二叉搜索树（Binary Search Tree，缩写为 BST）的根，并要求我们将其转换为大和树。 

在二叉搜索树中，每个节点都遵循重要的排序规则：

 - 左子树中的所有值都小于当前节点。 
- 右子树中的所有值都大于当前节点。 

变换规则为：

 > 将每个节点的值替换为：
 >
 >
 >
 >
 > 当前值 + 树中所有大于它的值的总和。 

这意味着变换后，每个节点包含所有大于或等于自身的原始节点值的总和。 

例如，假设一个节点最初包含值`4`，并且值大于`4`在 BST 中是`5`,`6`,`7`， 和`8`。 

更新后的值变为：```
4 + 5 + 6 + 7 + 8 = 30
```树结构本身不会改变。 仅修改节点内存储的值。 

输入是 BST 的根节点。 所有节点值更新后，输出应该是相同的树根。 

限制相对较小：

 - 树包含之间`1`和`100`节点。 
- 节点值是唯一的。 
- 值范围为`0`到`100`。 

尽管约束足够小，甚至更慢的方法也可以通过，但问题的根本在于识别 BST 属性并有效地利用它。 

一些边缘情况很重要：

 - 一棵只有一个节点的树。 该节点应保持不变，因为没有更大的值。 
- 完全右偏的树，其中值已经在链中增加。 
- 一棵完全左偏的树。 
- 最小可能值`0`。 
- 最大的节点已经没有更大的元素。 
- 遍历期间清空子指针。 

因为值是唯一的，并且树保证是有效的 BST，所以我们可以在遍历过程中安全地依赖 BST 排序。 

## 方法

 ### 蛮力方法

 一种简单的方法是独立处理每个节点。 

对于每个节点：

 1. 遍历整棵树。 
2. 查找所有大于当前节点值的节点值。 
3. 计算它们的总和。 
4. 将该总和添加到节点。 

这是有效的，因为它直接遵循问题的定义。 

然而，它的效率很低。 如果树有`n`节点，对于每个节点我们遍历所有`n`再次节点，总复杂度变为`O(n²)`。 

尽管约束足够小，可以通过，但该方法忽略了 BST 的特殊结构。 

### 关键见解

 关键的观察结果是 BST 的中序遍历按升序访问节点：```
Left -> Node -> Right
```如果我们颠倒遍历顺序：```
Right -> Node -> Left
```然后按降序访问节点。 

这非常有用，因为当按降序访问节点时，我们已经处理了所有更大的值。 

我们可以维护一个运行累积和：

 - 开始于`0`- 首先访问较大的节点
 - 将当前节点值添加到运行总和中
 - 将节点值替换为运行总和

 这使我们能够在一次遍历中转换树。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 对于每个节点，再次遍历整棵树 |
 | 最佳 | O(n) | O(h) | 反向中序遍历处理节点一次 |

 这里，`h`代表树的高度。 

## 算法演练

 ### 最优逆序遍历

 1. 初始化一个名为`running_sum`到`0`。 

该变量存储所有先前访问过的较大节点值的累积总数。 
2. 进行反向中序遍历。 

不要按升序访问节点，而是按降序访问它们：```
Right -> Node -> Left
```3、先递归遍历右子树。 

右子树包含 BST 中所有较大的值。 首先处理它可以确保在更新当前节点之前累积和已经包括所有更大的节点。 
4. 更新当前节点。 

将当前节点的原始值添加到`running_sum`。 

然后用更新后的累积和覆盖节点的值。 
5. 递归遍历左子树。 

左子树包含较小的值，因此这些节点应在其未来的总和中包含更新的当前节点值。 
6. 继续，直到处理完所有节点。 
7.返回原来的根。 

该树已就地修改。 

### 为什么它有效

 逆序遍历是从最大到最小的顺序访问节点。 

在穿越的任何时刻，`running_sum`包含所有先前访问过的节点的总和，这些节点正是大于当前节点的节点。 

将当前节点值添加到`running_sum`并将结果存储回节点，我们正确计算：```
current value + sum of greater values
```因为每个节点都按降序被访问一次，所以整个树的转换是正确的。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def bstToGst(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        running_sum = 0

        def reverse_inorder(node: Optional[TreeNode]) -> None:
            nonlocal running_sum

            if not node:
                return

            # Visit larger values first
            reverse_inorder(node.right)

            # Update running sum and node value
            running_sum += node.val
            node.val = running_sum

            # Visit smaller values
            reverse_inorder(node.left)

        reverse_inorder(root)
        return root
```实现直接遵循逆序遍历策略。 

变量`running_sum`在递归助手外部声明，以便每个递归调用共享相同的累积状态。 

辅助函数首先处理右子树，因为那里存在较大的 BST 值。 

处理完所有较大的值后，将当前节点值添加到`running_sum`，并且节点被更新。 

最后，遍历进入左子树，其中较小的节点应包含新更新的累积和。 

树被就地修改，因此返回原始的根引用。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func bstToGst(root *TreeNode) *TreeNode {
    runningSum := 0

    var reverseInorder func(node *TreeNode)

    reverseInorder = func(node *TreeNode) {
        if node == nil {
            return
        }

        // Visit larger values first
        reverseInorder(node.Right)

        // Update running sum and node value
        runningSum += node.Val
        node.Val = runningSum

        // Visit smaller values
        reverseInorder(node.Left)
    }

    reverseInorder(root)

    return root
}
```Go 的实现与 Python 解决方案非常相似。 

而不是Python的`nonlocal`、Go闭包自动捕获`runningSum`从周围的范围来看。 

Go 使用`nil`检查而不是Python的`None`。 

因为节点值最多是`100`并且最多有`100`节点，整数溢出不是 Go 标准的问题`int`类型。

 | ---| ---| ---|

 该算法对树执行单次 DFS 遍历。 

不使用与节点数量成比例的额外数据结构。 唯一的额外内存来自递归堆栈帧。 

在完全倾斜的树的最坏情况下，高度变为`n`，导致`O(n)`递归空间。 在平衡树中，高度为`O(log n)`。

# Helper utilities for testing

from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(values):
    if not values:
        return None

    nodes = [
        TreeNode(v) if v is not None else None
        for v in values
    ]

    kids = deque(nodes[1:])
    root = nodes[0]

    for node in nodes:
        if node:
            if kids:
                node.left = kids.popleft()
            if kids:
                node.right = kids.popleft()

    return root

def tree_to_list(root):
    if not root:
        return []

    result = []
    queue = deque([root])

    while queue:
        node = queue.popleft()

        if node:
            result.append(node.val)
            queue.append(node.left)
            queue.append(node.right)
        else:
            result.append(None)

    while result and result[-1] is None:
        result.pop()

    return result

class Solution:
    def bstToGst(self, root):
        running_sum = 0

        def reverse_inorder(node):
            nonlocal running_sum

            if not node:
                return

            reverse_inorder(node.right)

            running_sum += node.val
            node.val = running_sum

            reverse_inorder(node.left)

        reverse_inorder(root)
        return root

sol = Solution()

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树是最小的有效输入。 

这种情况可能会暴露出错误，即实现错误地假设每个节点都有更大或更小的邻居。 正确的行为是节点保持不变，因为没有更大的值。 

该实现自然地处理了这个问题，因为遍历访问该节点一次，将其值添加到`running_sum`，并存储相同的值。 

### 完全右偏树

 右偏 BST 的行为类似于具有递增值的链表。 

这种情况很重要，因为逆序遍历会立即首先沿着最深的路径走下去。 不正确的遍历顺序会产生错误的累积和。 

该实现正确地从最大到最小处理节点，确保每个节点在更新之前累积所有更大的值。 

### 完全左偏树

 左偏 BST 仅包含左侧的节点。 

这测试算法是否正确处理右子树频繁出现的树`None`。 

遇到以下情况时，递归助手会安全返回`None`，所以失踪的孩子永远不会造成问题。 

### 最大价值节点

 BST 中的最大节点应保持不变，因为没有更大的值。 

这很重要，因为一些不正确的实现会意外地重复计数值或错误地更新最大节点。 

由于逆序遍历首先访问最大的节点，当`running_sum`仍然是`0`，该节点正确变为：```
0 + original_value
```这使其保持不变。
