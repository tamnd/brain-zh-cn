[LeetCode 第 1094 题](https://leetcode.com/problems/car-pooling/)

 **难度：** 🟡 中等
 **主题：** 数组、排序、堆（优先级队列）、模拟、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定一辆车是否能够在不超过其座位容量的情况下成功完成一系列乘客行程。 

每个行程表示为：`[numPassengers, from, to]`这意味着：

-`numPassengers`乘客在指定地点上车`from`- 这些乘客在指定地点下车`to`重要的细节是汽车只向东移动。 由于车辆永远不会掉头，我们可以按位置顺序处理所有乘客事件。 在每个上车点，乘客上车，在每个下车点，乘客离开。 

目标是回归`true`如果汽车可以完成所有行程且不超过`capacity`，否则返回`false`。 

例如：```
trips = [[2,1,5],[3,3,7]]
capacity = 4
```公里处`1`，两名乘客进入。 

公里处`3`，另外三名乘客进来。 

现在有`5`车内乘客超过载客量`4`，所以答案是`false`。 

这些约束告诉我们一些重要的事情：

 - 最多可以有`1000`旅行。 
- 地点范围从`0`到`1000`。 
- 乘客数量相对较少。 
- 容量可大至`100000`。 

由于位置范围是有界的（`0 <= from < to <= 1000`），我们可以利用这一事实并有效地模拟乘客变化，而不是对照每个其他行程检查每个行程。 

一些边缘情况很重要：

 - 在同一地点发生多次上车和下车。 
- 旅程的终点​​与另一趟旅程的起点完全相同。 
- 准确达到容量，这是有效的。 
- 大量重叠，其中许多行程同时处于活动状态。 
- 最少的输入，例如仅一次行程。 

该问题保证有效的行程范围（`from < to`），所以我们永远不需要处理无效的间隔。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是模拟每行驶一公里并跟踪当前车内有多少乘客。 

我们可以创建一个代表位置的数组`0`到`1000`。 对于每次旅行：

 1. 将乘客添加到之间的每个位置`from`和`to - 1`。 
2. 检查是否有任何一点超出容量。 

例如：```
[2,1,5]
```将增加乘客数量：```
1, 2, 3, 4
```This approach works because it explicitly models the number of passengers at every segment of the journey. However, it performs repeated updates across intervals, making it less efficient than necessary.

 ### 关键见解

 We do not need to track every kilometer individually for every trip.

 Instead, we only care about **where passenger counts change**.

 在上车地点：```
+numPassengers
```在下车地点：```
-numPassengers
```这是一个经典的前缀和或差数组观察。 

我们只标记更改的开始和结束，而不是更新范围内的每个位置。 

对于旅行：```sql
[numPassengers, from, to]
```我们做：```sql
changes[from] += numPassengers
changes[to] -= numPassengers
```然后，通过从左到右扫描位置并维护运行总和，我们始终知道车内当前有多少乘客。 

如果运行总和超过容量，我们立即返回`false`。 

这是有效的，因为位置范围很小且有界。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(米) | 每次行程的每公里都会更新，其中`m = 1001`地点 |
 | 最佳 | O(n + m) | O(米) | 使用差异数组和前缀和 |

 这里：

-`n`= 行程次数
 -`m`= 最大位置 (`1001`）

 ## 算法演练

 1. 创建一个差异数组来表示每个位置的乘客变化。 

由于位置的边界是`1000`，创建一个大小的数组`1001 + 1`安全地处理该位置的下车`1000`。 
2. 处理每一次行程并记录旅客变化。 

对于每次旅行：

 - 在上车点添加乘客。 
- 在下车点带走乘客。 

用代码来说：```sql
changes[from] += passengers
changes[to] -= passengers
```这避免了每中间公里更新一次。 
3. 从西向东遍历地点。 

保持持续的乘客数量。 

在每个地点：```
currentPassengers += changes[location]
```这准确地告诉我们当时车内有多少乘客。 
4. 立即检查容量。 

如果：```
currentPassengers > capacity
```返回`false`。 

没有必要继续，因为行程安排不可能。 
5. 完成所有位置的扫描。 

如果从未超出容量，则返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为差异数组正确记录了每位进出汽车的乘客。 当我们计算前缀总和时，任何位置的运行总数等于当前乘坐的乘客的确切数量。 由于每次容量违规都会出现在该运行总计中，因此在每个位置进行检查可以保证正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def carPooling(self, trips: List[List[int]], capacity: int) -> bool:
        max_location = 1000
        passenger_changes = [0] * (max_location + 1)

        for passengers, start, end in trips:
            passenger_changes[start] += passengers
            passenger_changes[end] -= passengers

        current_passengers = 0

        for change in passenger_changes:
            current_passengers += change

            if current_passengers > capacity:
                return False

        return True
```实现首先创建一个名为的固定大小的差异数组`passenger_changes`。 由于最大位置是`1000`，我们分配一个足够大的数组来表示每一公里。 

对于每次行程，我们仅记录乘客数量的变化。 在上车地点添加乘客。 在下车地点，乘客被带走。 这将间隔更新转换为恒定时间操作。 

处理完所有行程后，我们按升序遍历位置。 变量`current_passengers`充当前缀和，表示当前车内有多少乘客。 

如果乘客人数超过`capacity`在任何时候，函数都会立即返回`False`。 否则，在扫描完所有位置后，函数返回`True`。 

## 解决方案```go
func carPooling(trips [][]int, capacity int) bool {
	maxLocation := 1000
	passengerChanges := make([]int, maxLocation+1)

	for _, trip := range trips {
		passengers := trip[0]
		start := trip[1]
		end := trip[2]

		passengerChanges[start] += passengers
		passengerChanges[end] -= passengers
	}

	currentPassengers := 0

	for _, change := range passengerChanges {
		currentPassengers += change

		if currentPassengers > capacity {
			return false
		}
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 切片用于差异数组，整数运算是安全的，因为约束远低于 Go 的整数限制。 

与 Python 不同，Go 需要从切片中显式提取行程值。 否则，逻辑保持不变。 

无需特殊处理`nil`需要与空切片相对，因为约束保证至少一次行程。

 ## 边缘情况

 一种重要的边缘情况是乘客在新乘客上车的确切位置下车。 有缺陷的实现可能会在下车前处理上车，并暂时错误地超出容量。 差异数组自然地处理这个问题，因为这两个更改发生在同一索引处，并且在评估容量之前正确组合。 

当乘客数量恰好等于汽车的容量时，就会出现另一种边缘情况。 由于仅当计数严格大于容量时条件才无效，因此实现正确地允许相等。 

第三个重要案例是行程高度重叠。 例如，许多行程可能会在同一时间间隔内重叠，并逐渐增加乘客数量。 当重复更新间隔时，幼稚的实现可能会变得效率低下或容易出错。 差异数组方法正确聚合所有更改并使用前缀和有效计算总数。 

最后，覆盖最大范围的行程，例如从`0`到`1000`，可能会导致相差一的错误。 该实现通过为索引分配足够的空间来安全地处理这个问题`1000`并正确对待落车位置。
