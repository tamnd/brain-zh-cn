 # LeetCode 1011，D 天内运送包裹的能力

 ## 问题理解

 该问题要求我们确定在固定天数内运输所有包裹所需的最小船舶运力。 

我们有一个数组叫做`weights`， 在哪里`weights[i]`代表的重量`i-th`传送带上的包裹。 包裹必须按照它们在数组中出现的确切顺序运送。 这种订购限制非常重要，因为我们不允许重新排列包裹以使运输更容易。 

船舶每天可承运的包裹总重量不超过船舶的承载能力。 一旦添加另一个包裹超出容量，当天的运送将停止，剩余的包裹必须等到第二天。 

目标是返回尽可能最小的运输能力，使所有包裹能够在准确的时间内运输`days`天或更短。 

这些约束告诉我们一些重要的事情：

 - 包裹数量最多可达`5 * 10^4`- 每个包裹重量可大至`500`- 对每种可能容量的简单模拟可能会变得太慢

 由于输入量很大，我们需要一个有效的解决方案。 任何比粗略更糟糕的算法`O(n log n)`可能会与上限作斗争。 

有几个重要的边缘情况需要记住：

 - 如果`days == len(weights)`，那么我们每天可以运送一个包裹，所以答案就是最大包裹重量。 
- 如果`days == 1`，那么所有包裹必须在一天内发货，所以答案是所有重量的总和。 
- 船舶容量永远不能小于最重的包裹，否则该包裹将永远无法装载。 
- 顺序限制可以防止贪婪的重新排列技巧。 

## 方法

 ### 蛮力方法

 一种简单的方法是尝试每种可能的船舶容量，从最重的包裹重量到所有重量的总和。 

对于每个候选人的能力：

 1. 模拟日常运输过程。 
2. 计算需要多少天。 
3. 返回在允许的天数内运行的第一个容量。 

这种方法是正确的，因为最终我们将测试最佳容量。 然而，它的效率很低，因为搜索范围可能非常大。 

认为：

-`max(weights) = 500`-`sum(weights)`可以接近`25,000,000`尝试该范围内的所有容量会太慢。 

### 关键见解

 重要的观察是答案空间是单调的。 

如果有容量`C`足以运送所有包裹`days`，那么任何容量大于`C`也会起作用。 

同样：

 - 小容量失败
 - 大容量成功

 这创建了一个经典的二分搜索条件。 

我们可以在范围内进行二分搜索，而不是检查每个可能的容量：

 - 最小可能容量=`max(weights)`- 最大可能容量=`sum(weights)`对于每个中点容量，我们模拟运输并确定其是否有效。 

如果有效的话：

 - 尝试较小的容量

 如果失败：

 - 尝试更大的容量

 这大大降低了复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × S) | O(1) | O(1) | 尝试从最大重量到总重量的所有可能的容量 |
 | 最佳| O(n log S) | O(n log S) | O(1) | O(1) | 在答案空间上使用二分搜索 |

 这里，`n`是包裹数量，`S`是可能的容量范围。 

## 算法演练

 ### 第 1 步：定义搜索空间

 最小有效容量是最重的包装：```
left = max(weights)
```最大有效容量为所有包的总和：```
right = sum(weights)
```任何有效答案都必须在此范围内。 

### 步骤 2：二分查找容量

 我们反复计算：```
mid = (left + right) // 2
```这代表候选船舶的容量。 

然后，我们测试此容量是否可以在要求的天数内运送所有包裹。 

### 第 3 步：模拟运输

 要检查容量：

 1. 从一天开始。 
2. 继续将包裹添加到当天的负载中。 
3. 如果添加的包裹超出容量：

 - 开始新的一天
 - 重置当前负载
 4. 继续，直到处理完所有包。 

该模拟以线性时间运行。 

### 步骤 4：调整搜索范围

 如果模拟使用小于或等于`days`：

 - 容量有效
 - 尝试进一步减少
 - 移动`right = mid`否则：

 - 容量太小
 - 移动`left = mid + 1`### 第 5 步：完成搜索

 最终，`left == right`。 

该值是最小有效容量。 

### 为什么它有效

 正确性依赖于容量的单调性。 

如果一个容量有效，那么每个更大的容量也都有效。 这保证了有效容量在搜索空间中形成连续区域。 因此，二分查找是有效的，因为我们可以在每次检查后安全地消除一半的搜索范围。 

模拟本身是贪婪的，但却是最优的，因为包必须保持有序。 每当当前的包裹超出容量时，除了开始新的一天之外别无选择。 

## Python 解决方案```python
from typing import List

class Solution:
    def shipWithinDays(self, weights: List[int], days: int) -> int:
        def can_ship(capacity: int) -> bool:
            days_needed = 1
            current_load = 0

            for weight in weights:
                if current_load + weight > capacity:
                    days_needed += 1
                    current_load = 0

                current_load += weight

            return days_needed <= days

        left = max(weights)
        right = sum(weights)

        while left < right:
            mid = (left + right) // 2

            if can_ship(mid):
                right = mid
            else:
                left = mid + 1

        return left
```实现首先定义一个名为的辅助函数`can_ship`。 该函数确定给定的船舶容量是否足够。 

在辅助函数内，我们模拟加载过程。 我们维持：

 -`days_needed`, 迄今为止使用的天数
 -`current_load`，当天装载的当前重量

 当我们迭代包裹时，我们尝试将每个包裹添加到当天的发货中。 

如果添加包会超出容量：

 - 我们增加天数
 - 开始新的发货日

 最后，如果总使用天数在允许的范围内，则容量有效。 

然后主函数对答案空间执行二分搜索。 

左边界被初始化为最大包装重量，因为更小的容量无法工作。 

正确的边界被初始化为总重量，因为该容量始终通过在一天内运送所有物品来发挥作用。 

二分查找继续缩小范围，直到只剩下一个有效容量。 

## 解决方案```go
func shipWithinDays(weights []int, days int) int {
    canShip := func(capacity int) bool {
        daysNeeded := 1
        currentLoad := 0

        for _, weight := range weights {
            if currentLoad+weight > capacity {
                daysNeeded++
                currentLoad = 0
            }

            currentLoad += weight
        }

        return daysNeeded <= days
    }

    left := 0
    right := 0

    for _, weight := range weights {
        if weight > left {
            left = weight
        }

        right += weight
    }

    for left < right {
        mid := left + (right-left)/2

        if canShip(mid) {
            right = mid
        } else {
            left = mid + 1
        }
    }

    return left
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

一个小小的区别是二分搜索中点的计算方式：```go
mid := left + (right-left)/2
```这避免了潜在的整数溢出，尽管在这个问题的约束下溢出实际上并不是一个问题。 

Go 切片自然地用于迭代包权重，并且所有变量都使用整数运算。

 ## 边缘情况

 ### 边缘情况 1：每天一包

 考虑：```
weights = [5,5,5,5]
days = 4
```一个常见的错误是高估了所需的容量。 由于我们每天只能运送一个包裹，因此最佳容量就是最大的包裹重量。 

该实现自然地处理了这个问题，因为二分搜索下限从`max(weights)`。 

### 边缘案例 2：一日内所有包裹

 考虑：```
weights = [5,5,5,5]
days = 1
```在这种情况下，船舶必须同时运送所有包裹。 因此，所需容量就是总和。 

该算法正确地处理了这个问题，因为搜索上限被初始化为`sum(weights)`，并且所有较小的容量都无法通过模拟。 

### 边缘情况 3：非常大的单个包装

 考虑：```
weights = [1,1,1,100]
days = 2
```幼稚的实现可能会错误地允许以下容量`100`，即使包裹称重`100`永远无法适应。 

该实现通过设置来防止这种情况：```
left = max(weights)
```这保证了每个测试容量至少可以容纳最重的包裹。 

### 边缘情况 4：订单限制

 考虑：```
weights = [10,1,1,1,10]
days = 2
```如果没有顺序约束，人们可能会尝试以不同的方式平衡负载。 但是，包必须保持顺序。 

模拟通过从左到右迭代数组而不重新排列来准确地尊重原始顺序。
