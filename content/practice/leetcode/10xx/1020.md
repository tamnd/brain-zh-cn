[LeetCode 问题 1020](https://leetcode.com/problems/number-of-enclaves/)

 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、广度优先搜索、并查找、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二元矩阵，称为`grid`， 在哪里：

-`0`代表水
 -`1`代表土地

 我们只能向上、下、左、右四个方向移动。 如果没有从某个陆地单元到网格的任何边界单元的可能路径，则该陆地单元被视为飞地。 

思考这个问题的另一种方式是这样的：

 - 如果陆地区域直接接触边界，或者可以通过连接的陆地单元到达边界，则该区域中的每个单元都不会被封闭。 
- 仅应计算完全被水包围且与所有边界断开的陆地单元。 

任务是返回此类封闭陆地单元的总数。 

约束条件很重要：

 -`m`和`n`每个都可以大到`500`- 因此网格可能包含最多`250,000`细胞

 因此，我们需要一种接近线性时间的算法，理想情况下`O(m * n)`。 任何独立地从多个单元重复执行搜索的解决方案都可能变得太慢。 

一些边缘情况很重要：

 - 只包含水的网格应该返回`0`- 每个陆地单元都接触边界的网格也应该返回`0`- 中间的一个孤立的陆地单元应该返回`1`- 部分接触边界的大连接区域根本不应该计算在内
 - 连接内部陆地和边界的细路径很容易因不正确的实施而被错过

 该问题保证输入始终是有效的矩形矩阵，并且每个值都是`0`或者`1`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是单独检查每个陆地单元。 

对于每个陆地单元：

 1. 从该单元格开始运行 DFS 或 BFS
 2.判断连通分量是否能够到达边界
 3. 如果不能，则将该组件中的所有单元格算作 enclave

 这种方法是正确的，因为它明确地检查每个连接的陆地区域是否可以脱离网格。 

然而，如果简单地实施的话，其效率是低下的。 想象一下网格中心有一个大岛。 从每个陆地单元启动 DFS 可能会多次重复遍历同一组件。 在最坏的情况下，这可能会导致时间复杂度接近`O((m * n)^2)`。 

高达`250,000`细胞，那太慢了。 

### 最佳方法

 关键的见解是扭转观点。 

而不是问：

 > 哪些陆地单元被封闭？ 

我们问：

 > 哪些陆地单元绝对不是封闭的？ 

任何连接到边界的陆地单元都不能是飞地。 

所以我们可以：

 1.从每个边界陆地单元开始DFS或BFS
 2. 将所有可到达的陆地单元标记为安全
 3. 统计剩余未访问的陆地单元

 这是可行的，因为每个非飞地单元必须属于连接到边界的组件。 

我们不会重复检查每个组件，而是最多处理每个单元一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((m * n)^2) | O((m * n)^2) | O(m * n) | 反复探索相同的组件|
 | 最佳 | O(m * n) | O(m * n) | 边界被洪水填满一次 |

 ## 算法演练

 1. 确定网格尺寸。 

我们存储行数和列数，因为它们在整个遍历逻辑中重复使用。 
2. 创建 DFS 或 BFS 辅助函数。 

该助手将标记连接到起始单元的所有陆地单元。 我们用它来移除边界可到达的所有土地。 
3. 遍历所有边界单元。 

边界包括：

 - 第一排
 - 最后一排
 - 第一栏
 - 最后一栏

 这些边缘上的任何陆地单元都不会自动封闭。 
4. 从每个边界陆地单元启动 DFS/BFS。 

遍历过程中：

 - 将访问过的陆地单元标记为水，或将它们存储在访问过的结构中
 - 继续向四个方向探索

 这有效地消除了所有能够逃离网格的陆地区域。 
5. 移除所有边界相连的土地后，再次扫描整个网格。 

任何剩余的`1`单元格保证被封闭，因为：

 - 从边界无法到达
 - 因此其组件被完全包围
 6. 计算所有剩余的陆地单元并返回结果。 

### 为什么它有效

 该算法依赖于一个简单的不变量：

 > 任何连接到边界的陆地单元都不能是飞地。 

通过从边界开始并标记所有可到达的土地，我们消除了每个非飞地单元。 唯一剩下的单元格是那些没有通往边界的路径的单元格，这与飞地的定义完全匹配。 

由于每个单元最多被处理一次，因此该算法既正确又高效。 

## Python 解决方案```python
from typing import List

class Solution:
    def numEnclaves(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        def dfs(row: int, col: int) -> None:
            if (
                row < 0 or row >= rows or
                col < 0 or col >= cols or
                grid[row][col] == 0
            ):
                return

            grid[row][col] = 0

            for dr, dc in directions:
                dfs(row + dr, col + dc)

        for row in range(rows):
            if grid[row][0] == 1:
                dfs(row, 0)

            if grid[row][cols - 1] == 1:
                dfs(row, cols - 1)

        for col in range(cols):
            if grid[0][col] == 1:
                dfs(0, col)

            if grid[rows - 1][col] == 1:
                dfs(rows - 1, col)

        enclave_count = 0

        for row in range(rows):
            for col in range(cols):
                if grid[row][col] == 1:
                    enclave_count += 1

        return enclave_count
```该实现首先存储网格尺寸并定义四个可能的移动方向。 

这`dfs`helper 执行洪水填充操作。 如果当前单元格超出范围或已经是水，则递归立即停止。 否则，该单元格被标记为`0`，有效地将其从未来的考虑中删除。 

下一部分处理每个边界单元。 每当发现边界陆地单元时，DFS 就会删除整个连接的组件。 

在此边界清理步骤之后，每个剩余的`1`单元格必须封闭。 最后的嵌套循环只是对它们进行计数。 

一个重要的实现细节是算法适当地修改输入网格。 这避免了需要额外的访问矩阵并减少了内存使用。 

## 解决方案```go
func numEnclaves(grid [][]int) int {
    rows := len(grid)
    cols := len(grid[0])

    directions := [][]int{
        {1, 0},
        {-1, 0},
        {0, 1},
        {0, -1},
    }

    var dfs func(int, int)

    dfs = func(row int, col int) {
        if row < 0 || row >= rows ||
            col < 0 || col >= cols ||
            grid[row][col] == 0 {
            return
        }

        grid[row][col] = 0

        for _, dir := range directions {
            newRow := row + dir[0]
            newCol := col + dir[1]

            dfs(newRow, newCol)
        }
    }

    for row := 0; row < rows; row++ {
        if grid[row][0] == 1 {
            dfs(row, 0)
        }

        if grid[row][cols-1] == 1 {
            dfs(row, cols-1)
        }
    }

    for col := 0; col < cols; col++ {
        if grid[0][col] == 1 {
            dfs(0, col)
        }

        if grid[rows-1][col] == 1 {
            dfs(rows-1, col)
        }
    }

    enclaveCount := 0

    for row := 0; row < rows; row++ {
        for col := 0; col < cols; col++ {
            if grid[row][col] == 1 {
                enclaveCount++
            }
        }
    }

    return enclaveCount
}
```Go 实现遵循与 Python 版本相同的逻辑。 

区别之一是递归函数声明。 在 Go 中，递归匿名函数需要使用以下方式预先声明变量：```go
var dfs func(int, int)
```该解决方案还就地修改网格，而不是维护单独的访问矩阵。 

由于最大网格大小适中，因此不必担心整数溢出。 切片索引自然而然地可以干净地处理 2D 矩阵结构。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m * n) | 每个单元格最多被访问一次 |
 | 空间| O(m * n) | 递归DFS堆栈可能会增长到所有单元|

 该算法对每个单元执行恒定量的工作。 尽管从边界多次启动 DFS，但不会对陆地单元进行多次处理，因为访问过的单元会立即转换为水。

 ## 边缘情况

 仅包含水的网格是一个重要的边缘情况，因为 DFS 永远不应该启动。 不正确的实现有时会假设至少存在一个陆地单元，并且可能会产生错误或不正确的计数。 此实现可以自然地处理这种情况，因为最终的计数循环只是找到零个剩余的陆地单元。 

单行或单列网格是另一个微妙的场景。 在这些网格中，每个单元格都自动位于边界上。 这意味着任何飞地都不可能存在。 某些实现会意外地双重处理单元格或错误地将内部位置视为封闭的。 这里的边界遍历正确地标记了从边缘可立即到达的每个陆地单元。 

通过狭窄走廊与边界相连的大型岛屿是另一个常见的虫子来源。 幼稚的局部检查可能会错误地将深层内部细胞分类为封闭的。 这种实现避免了这种错误，因为 DFS 从边界探索整个连接的组件，确保删除每个可到达的陆地单元。 

另一个重要的边缘情况是一个被水包围的完全封闭的岛屿。 该算法必须避免在边界洪水填充阶段意外删除它。 由于 DFS 仅从边界陆地单元开始，因此孤立的内部区域保持不变，并在最终遍历中正确计数。
