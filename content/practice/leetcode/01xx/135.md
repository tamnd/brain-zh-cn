 # LeetCode 135，糖果

 ## 问题理解

 这个问题要求我们根据孩子们的评分值向排队的孩子们分发糖果。 每个孩子必须至少收到一颗糖果，任何比相邻邻居评分更高的孩子都必须收到比该邻居更多的糖果。 

输入是一个整数数组`ratings`， 在哪里`ratings[i]`代表了评级`i`第一个孩子。 输出是一个整数，表示满足所有条件所需的最小糖果总数。 

挑战来自这样一个事实：约束是局部的，这意味着每个孩子只与直接邻居进行比较，但糖果分配会在数组中相互影响。 由于左邻居、右邻居或两者的原因，孩子可能需要更多糖果。 

约束条件很重要：

 -`1 <= n <= 2 * 10^4`-`0 <= ratings[i] <= 2 * 10^4`数组大小高达 20,000 个元素意味着低效的重复调整可能会变得太慢。 重复扫描阵列的强力模拟可能会降低到二次时间复杂度，这对于上限来说是不希望的。 

需要考虑一些重要的边缘情况：

 - 单个孩子必须始终收到一颗糖果。 
- 严格提高评级需要从左到右增加糖果数量。 
- 严格降低评级需要从右到左增加糖果数量。 
- 同等等级不强加任何订购要求。 
- 峰和谷可能需要同时满足左约束和右约束。 

当一个方向的约束使另一个方向无效时，简单的实现通常会失败。 例如，从左到右正确分配糖果可能仍然违反右侧的条件。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是用一颗糖果初始化每个孩子，然后重复扫描数组并在违反规则时调整糖果数量。 

对于每个孩子：

 - 如果`ratings[i] > ratings[i - 1]`， 然后`candies[i]`必须大于`candies[i - 1]`。 
- 如果`ratings[i] > ratings[i + 1]`， 然后`candies[i]`必须大于`candies[i + 1]`。 

我们可以重复更新糖果数量，直到不需要更多更改为止。 

这种方法最终会收敛到有效的分布，因为每个违规都会被逐步纠正。 然而，每次更新都可能在其他地方产生新的违规行为，需要多次重复通过。 

在最坏的情况下，例如严格递减的数组，此过程可能需要`O(n)`过去`O(n)`元素，导致`O(n^2)`时间复杂度。 

### 最优贪心法

 关键的见解是约束是方向性的。 

- 如果评分从左到右增加，糖果也必须增加。 
- 如果评级从右向左增加，糖果也必须朝该方向增加。 

我们可以通过两次线性传递来解决问题，而不是重复修复违规行为：

 1.从左向右传递：

 - 确保每个比左边邻居评分更高的孩子都能获得更多糖果。 
2.从右向左传递：

 - 确保每个比正确邻居评分更高的孩子都能获得更多糖果。 

重要的细节是第二遍必须保留第一遍已经建立的约束。 我们通过取现有糖果数量和新要求的值之间的最大值来实现这一点。 

这种贪婪策略之所以有效，是因为每个本地关系在每个方向上都被处理一次。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复修复违规直至稳定|
 | 最佳| O(n) | O(n) | 两个方向的贪婪传递 |

 ## 算法演练

 1. 创建一个`candies`大小数组`n`，初始化为`1`。 

每个孩子必须至少收到一颗糖果，因此这建立了最低有效基线。 
2. 执行从左到右的传递。 

对于每个索引`i`从`1`到`n - 1`：

- 如果`ratings[i] > ratings[i - 1]`， 分配：```
candies[i] = candies[i - 1] + 1
```这确保了从左到右递增的评级序列满足规则。 
3. 执行从右到左的传递。 

对于每个索引`i`从`n - 2`下降到`0`：

- 如果`ratings[i] > ratings[i + 1]`， 分配：```
candies[i] = max(candies[i], candies[i + 1] + 1)
```这`max`操作是至关重要的，因为孩子可能已经从第一遍就得到了足够的糖果。 我们仅在必要时增加价值。 
4. Sum all values in the`candies`大批。 

The resulting total is the minimum valid candy distribution.

 ### 为什么它有效

 The algorithm works because every constraint involves only adjacent children.

 The left-to-right pass guarantees that every child with a higher rating than the left neighbor receives more candies. The right-to-left pass guarantees the same for the right neighbor.

 使用`max`在第二遍期间，保留先前满足的约束，同时强制执行新的约束。 由于在两次传递后每个局部约束都得到满足，因此最终分布是有效的。 因为我们只在必要时增加糖果数量，所以总数很少。 

## Python 解决方案```python
from typing import List

class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)

        candies = [1] * n

        # Left-to-right pass
        for i in range(1, n):
            if ratings[i] > ratings[i - 1]:
                candies[i] = candies[i - 1] + 1

        # Right-to-left pass
        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i + 1]:
                candies[i] = max(candies[i], candies[i + 1] + 1)

        return sum(candies)
```实现首先用一颗糖果初始化每个孩子。 这立即保证了最低要求。 

第一个循环从左到右扫描。 每当当前评分超过前一个评分时，当前孩子必须比前一个孩子多收到一颗糖果。 

第二个循环从右向左扫描。 这可以处理第一遍无法完全解决的递减序列。 这`max`操作可防止覆盖在第一遍期间分配的有效较大值。 

最后，算法对糖果数量进行求和并返回结果。 

## 解决方案```go
func candy(ratings []int) int {
    n := len(ratings)

    candies := make([]int, n)

    for i := 0; i < n; i++ {
        candies[i] = 1
    }

    // Left-to-right pass
    for i := 1; i < n; i++ {
        if ratings[i] > ratings[i-1] {
            candies[i] = candies[i-1] + 1
        }
    }

    // Right-to-left pass
    for i := n - 2; i >= 0; i-- {
        if ratings[i] > ratings[i+1] {
            if candies[i] < candies[i+1]+1 {
                candies[i] = candies[i+1] + 1
            }
        }
    }

    total := 0

    for _, candy := range candies {
        total += candy
    }

    return total
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

Go 没有提供内置的`max`函数用于整数，因此比较是通过手动实现的`if`陈述。 

使用切片而不是数组，因为输入大小是动态的。 整数溢出不是问题，因为最大可能的答案完全符合 Go 的标准整数范围。

 ## 边缘情况

 ### 独生子女

 如果输入仅包含一个孩子，则答案必须是`1`。 这种情况很容易被忽视，因为许多实现都假设邻居存在。 该算法可以自然地处理它，因为糖果数组用一颗糖果初始化，并且两次传递都执行零迭代。 

### 严格降低收视率

 像这样的输入`[5,4,3,2,1]`是错误的常见来源。 仅从左到右的传递就会为每个孩子分配一颗糖果，这违反了约束。 从右到左的传递通过按递减顺序向后传播较大的糖果计数来解决此问题。 

### 相邻评级相等

 相同的评级并不需要不平等的糖果数量。 例如，`[2,2,2]`应该产生`[1,1,1]`，而不是增加值。 有时会使用不正确的实现`>=`而不是`>`，这不必要地增加了糖果分配。 该解决方案仅正确检查严格更高的评级。 

### 峰结构

 具有局部最大值的数组，例如`[1,3,4,5,2]`，要求同时满足来自两个方向的约束。 处于巅峰的孩子必须比两个邻居拥有更多的糖果。 两次传递策略可以正确处理此问题，因为第二次传递使用以下方法保留了先前建立的值`max()`。
