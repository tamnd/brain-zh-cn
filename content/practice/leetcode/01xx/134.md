[LeetCode 第 134 题](https://leetcode.com/problems/gas-station/)

 **难度：** 🟡 中等
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 该问题描述了一条循环路线，其中包含`n`加油站。 各车站`i`，你可以收集`gas[i]`燃料单位。 从车站出发`i`到车站`(i + 1) % n`消耗`cost[i]`燃料单位。 

您必须确定是否存在一个起始站，以便一辆从空油箱开始的汽车可以完成一整圈而不会耗尽汽油。 如果存在这样的站，则问题保证答案是唯一的。 

输入由两个数组组成：

 -`gas[i]`代表你在加油站获得了多少燃料`i`-`cost[i]`代表从车站出发需要多少燃料`i`到下一站

 预期输出是：

 - 如果可以完成赛道，则有效起始站的索引
 -`-1`如果不存在有效的起始站

 约束条件很重要：

 -`1 <= n <= 10^5`-`0 <= gas[i], cost[i] <= 10^4`自从`n`可以大到`100,000`，任何比线性或近线性时间更差的解决方案都可能太慢。 这立即排除了每个站昂贵的嵌套模拟。 

一些边缘情况很重要：

 - 所有站点的总 Gas 量可能低于总成本，导致无法完成
 - 即使整体路线可行，某些站点也可能会立即单独失效
 - 长度数组`1`仍必须正常工作
 - 天然气和成本值都可以为零
 - 经过多次失败的尝试后，有效的开始可能会出现在数组中较晚的位置

 当解决方案存在时，该问题还保证答案的唯一性，这简化了最佳解决方案的推理。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是以每个站为起点进行尝试。 

对于每个起始索引：

 1. 从空罐开始
 2. 模拟绕整条赛道行驶
 3. 各站：

 - 添加可用气体
 - 减去差旅费
 4. 如果水箱变为负值，则该起始站发生故障
 5. 如果我们成功返回到开头，则返回该索引

 这种方法是正确的，因为它明确地检查每个可能的起始位置。 然而，它的效率很低，因为每次模拟可能会遍历几乎整个数组。 

在最坏的情况下：

 - 有`n`出发站
 - 每次模拟费用`O(n)`这导致`O(n^2)`时间复杂度，对于`n = 10^5`。 

### 最优贪心法

 关键的洞察力来自于对失败行为的理解。 

假设我们从车站出发`A`并在车站失败`B`。 这意味着介于`A`和`B`，累积气体变得不足。 

现在考虑之间的任何车站`A`和`B`作为一个潜在的起点。 他们也都无法成功。 

为什么？ 

因为晚一点开始只会在到达故障点之前给我们更少的汽油。 如果较早的启动不能积累足够的燃料，那么较晚的启动也不会更好。 

这一观察结果使我们能够同时跳过许多站点。 

另一个重要的观察是：

 - 如果所有站点的总汽油量小于总成本，则无论起点如何，都不可能完成线路

 所以算法就变成了：

 1. 检查总gas是否至少等于总成本
 2、遍历一次数组
 3. 维持当前的燃料平衡
 4. 每当余额变为负数时：

 - 将余额重置为零
 - 将下一站设置为新候选开始

 这是有效的，因为故障点之前的任何站点都已被证明无效。

 | 蛮力 | O(n²) | O(1) | O(1) | 模拟每个车站的完整行程 |
 | 最佳| O(n) | O(1) | O(1) | 使用基于失败间隔的贪婪跳过 |

 ## 算法演练

 ### 最优贪心算法

 1.初始化两个变量：

 -`total_balance`，跟踪整个路线的总汽油减去总成本
 -`current_balance`, tracks gas remaining while testing the current candidate start
 2. 初始化`start_index = 0`。 
3. 从左到右遍历每个站点。 
4. 各站：

 - 计算`difference = gas[i] - cost[i]`- 将此值添加到两者`total_balance`和`current_balance`5. 如果`current_balance`变为负数：

 - 当前起始站无法工作
 - 当前启动和该故障点之间的任何站点也无法工作
 - 设置`start_index = i + 1`- 重置`current_balance = 0`6. 继续扫描剩余站点。 
7.处理完所有站后：

 - 如果`total_balance < 0`， 返回`-1`- 否则，返回`start_index`### 为什么它有效

 该算法依赖于贪婪不变量：

 如果从车站出发`A`导致车站故障`B`，则之间没有车站`A`和`B`可以是一个有效的起点。 

这是因为所有中间站开始时累积的燃料都比开始时少`A`。 

因此，一旦发生故障，我们可以安全地跳过该区间内的每个站，直接移动到`B + 1`。 

最终候选方案之所以可行，是因为总 Gas 足以覆盖全球总成本。 

## Python 解决方案```python
from typing import List

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        total_balance = 0
        current_balance = 0
        start_index = 0

        for i in range(len(gas)):
            difference = gas[i] - cost[i]

            total_balance += difference
            current_balance += difference

            if current_balance < 0:
                start_index = i + 1
                current_balance = 0

        if total_balance < 0:
            return -1

        return start_index
```其实现紧密遵循贪心算法。`total_balance`确定该旅程是否在全球范围内可行。 如果可用的总汽油量小于总旅行成本，则不存在解决方案。`current_balance`代表评估当前候选起始站时的剩余燃料。 当我们迭代站点时，我们不断更新该值。 

每当`current_balance`变为负值，我们知道当前的起点无法成功。 更重要的是，当前启动点到故障点之间的所有站点也都无效。 因此，我们将候选起点移动到下一站并重置运行平衡。 

遍历结束时，如果总余额非负，则存储`start_index`保证是唯一有效的答案。 

## 解决方案```go
func canCompleteCircuit(gas []int, cost []int) int {
    totalBalance := 0
    currentBalance := 0
    startIndex := 0

    for i := 0; i < len(gas); i++ {
        difference := gas[i] - cost[i]

        totalBalance += difference
        currentBalance += difference

        if currentBalance < 0 {
            startIndex = i + 1
            currentBalance = 0
        }
    }

    if totalBalance < 0 {
        return -1
    }

    return startIndex
}
```Go 实现几乎完全反映了 Python 逻辑。 

Go 使用显式变量声明和整数算术`int`。 由于约束相对较小，因此这里不关心整数溢出。 

直接使用切片，不需要额外分配内存。 该算法保持完全迭代和恒定空间。

 ## 边缘情况

 ### 总 Gas 低于总成本

 一个常见的错误是尝试模拟路线而不首先检查旅程是否在全球范围内可行。 

例如：```
gas  = [2,3,4]
cost = [3,4,5]
```总气体为`9`，而总成本是`12`。 任何起点都不可能成功。 

该实现自然地使用处理这个问题`total_balance`。 如果最终余额为负数，算法立即返回`-1`。 

### 单站阵列

 长度数组`1`由于循环遍历假设，很容易被错误处理。 

例如：```
gas = [5]
cost = [4]
```答案应该是`0`因为汽车可以成功离开并返回同一个车站。 

该算法工作正常，因为循环正常处理单站，并且余额保持非负值。 

### 多次连续启动失败

 考虑：```
gas  = [1,2,3,4]
cost = [3,4,1,2]
```从索引开始`0`立即失败。 开始于`1`也失败了。 

幼稚的实现可能会单独重试每个站点，从而导致复杂性的二次增加。 

贪心解决方案通过证明一旦某个段发生故障，该故障段内的每个站都无效，从而避免了这种低效率。 它直接跳到下一个可能的候选者，保留线性运行时间。
