[LeetCode 第 113 题](https://leetcode.com/problems/path-sum-ii/)

 **难度：** 🟡 中等
 **主题：** 回溯、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们在二叉树中找到**所有根到叶路径**，其中节点值的总和等于给定值`targetSum`。 

二叉树是通过以下方式提供的`root`节点，每个节点包含一个整数值。 我们还得到一个整数`targetSum`。 我们的任务是探索从根节点开始到叶节点结束的每条有效路径，然后仅返回总和等于的路径`targetSum`。 

重要的细节是我们并不是在寻找任何任意的节点序列。 该路径必须满足两个严格条件：

 1. 必须从 **root** 开始。 
2. 它必须以**叶节点**结束，这意味着没有左或右子节点的节点。 

输出应包含**每个有效路径**中节点的值，而不是对节点本身的引用。 由于可能存在多个有效路径，因此我们返回一个列表列表。 

例如，在第一个示例中：```
        5
       / \
      4   8
     /   / \
    11  13  4
   / \      / \
  7   2    5   1
```和`targetSum = 22`，有两个有效的根到叶路径：```
5 → 4 → 11 → 2 = 22
5 → 8 → 4 → 5 = 22
```所以答案就变成了：```
[[5,4,11,2],[5,8,4,5]]
```约束告诉我们，树最多可以包含 **5000 个节点**，这足够大，低效的重复遍历可能会变得昂贵。 节点值和目标总和也可能是负数，这意味着我们不能依赖修剪策略，例如当总和超过目标时提前停止。 由于允许负值，因此较大的总和随后可能会减少，反之亦然。 

预先考虑一些边缘情况很重要。 树可能是空的（`root = None`)，在这种情况下没有路径。 一棵树可能只包含一个节点，这意味着根也是叶子。 负值可能会创建总和意外波动的路径。 最后，可能存在多个有效路径，我们必须确保它们独立存储，而不是意外修改以前保存的路径。 

## 方法

 ### 蛮力方法

 一个简单的暴力解决方案是首先生成树中的**每条从根到叶的路径**，然后计算每条路径的总和。 

为此，我们将递归遍历树并维护路径列表。 每当我们到达叶节点时，我们都会存储完整路径。 收集所有根到叶路径后，我们将迭代它们并计算它们的总和，仅选择等于的路径`targetSum`。 

这种方法之所以有效，是因为它详尽地检查了每条可能的根到叶路径。 由于每个有效答案都必须出现在该集合中，因此保证了正确性。 

然而，它执行了不必要的工作。 我们存储路径，即使它们显然不会对答案做出贡献，并且我们在遍历后重复计算总和，而不是在递归期间维护运行总计。 

### 最优方法，带回溯的深度优先搜索

 关键的见解是我们可以在**遍历树**时评估路径总和，而不是在收集每条路径之后。 

**深度优先搜索（DFS）**自然适合这个问题，因为我们正在探索从根到叶的路径。 在遍历过程中，我们维护：

 - 当前路径
 - 需要达到的剩余金额`targetSum`在每个节点：

 - 将当前节点值添加到路径中。 
- 从剩余目标中减去节点值。 
- 如果我们到达叶节点并且剩余目标变为零，则我们找到了一条有效路径。 
- 通过从路径中删除节点来探索子节点后回溯。 

回溯至关重要，因为在递归调用中会重复使用相同的路径列表。 如果在探索后不删除节点，兄弟分支将错误地继承以前的值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N × H) | O(N × H) | 生成所有根到叶路径，然后重新计算总和 |
 | 最佳| O(N) | O(H) 不包括输出 | DFS 在遍历和回溯过程中高效计算总和 |

 这里：

-`N`是节点数。 
-`H`是树的高度。 

## 算法演练

 1. 从根节点开始深度优先遍历。 

我们递归地探索树，因为每个递归调用自然代表着更深入地进入路径。 
2. 维持`current_path`列表。 

每次我们访问一个节点时，将其值附加到该列表中。 这跟踪从根到当前位置的节点的确切序列。 
3. 跟踪剩余目标。 

不要重复对路径求和，而是从剩余目标总和中减去当前节点值。 

如果原来的目标是`22`当前节点值为`5`，剩余目标变为`17`。 
4. 检查该节点是否为叶子节点。 

如果两个节点都满足，则节点是叶子`left`和`right`是`None`。 

如果我们在叶子上并且剩余目标等于节点值，则整个路径总和等于`targetSum`。 
5. 保存路径的副本。 

我们追加`current_path[:]`到结果列表。 

A copy is necessary because backtracking will later modify`current_path`。 如果不进行复制，所有存储的结果将指向相同的可变列表。 
6. 递归到左孩子和右孩子。 

继续探索更深的路径，同时通过更新的剩余目标。 
7. 递归后回溯。 

从中删除当前节点`current_path`使用`pop()`。 

这会在返回父节点之前恢复状态，从而允许兄弟分支以正确的路径开始。 

### 为什么它有效

 该算法之所以有效，是因为 DFS 只探索每一条从根到叶的路径一次。 在每一个递归步骤中，`current_path`准确地表示从根到当前节点的路径，并且剩余目标正确地跟踪还需要多少总和。 当到达叶节点时，仅当满足剩余和条件时才添加路径。 回溯保证了兄弟分支之间的状态不会泄漏，从而确保了正确性。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> List[List[int]]:
        result = []
        current_path = []

        def dfs(node: Optional[TreeNode], remaining_sum: int) -> None:
            if not node:
                return

            current_path.append(node.val)

            if (
                not node.left
                and not node.right
                and remaining_sum == node.val
            ):
                result.append(current_path[:])
            else:
                dfs(node.left, remaining_sum - node.val)
                dfs(node.right, remaining_sum - node.val)

            current_path.pop()

        dfs(root, targetSum)
        return result
```实现首先创建两个结构：`result`，它存储所有有效路径，以及`current_path`，它跟踪活动的遍历路径。 

嵌套的`dfs()`函数执行递归遍历。 如果节点是`None`，递归立即停止，因为没有路径可供探索。 

当访问一个节点时，它的值被附加到`current_path`。 这确保路径始终代表当前的根到节点序列。 

叶子节点的情况尤为重要。 我们仅在以下情况下才认为路径有效：

 - 该节点没有子节点。 
- 剩余总和恰好等于节点的值。 

如果满足两个条件，我们将路径的**副本**附加到`result`。 

否则，递归将继续进入两个子树，并更新剩余目标。 

最后，`current_path.pop()`执行回溯。 这会将路径恢复到返回父调用之前的先前状态。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func pathSum(root *TreeNode, targetSum int) [][]int {
	var result [][]int
	var currentPath []int

	var dfs func(node *TreeNode, remainingSum int)

	dfs = func(node *TreeNode, remainingSum int) {
		if node == nil {
			return
		}

		currentPath = append(currentPath, node.Val)

		if node.Left == nil &&
			node.Right == nil &&
			remainingSum == node.Val {

			pathCopy := make([]int, len(currentPath))
			copy(pathCopy, currentPath)
			result = append(result, pathCopy)
		} else {
			dfs(node.Left, remainingSum-node.Val)
			dfs(node.Right, remainingSum-node.Val)
		}

		currentPath = currentPath[:len(currentPath)-1]
	}

	dfs(root, targetSum)
	return result
}
```Go 实现与 Python 解决方案非常相似，但需要显式切片处理。 

而不是 Python 列表复制`[:]`, Go 需要使用分配一个新切片`make()`并使用复制元素`copy()`。 这是必要的，因为切片是对底层数组的引用。 如果不创建副本，以后的回溯修改将影响存储的路径。 

Go 还使用`nil`检查缺失的节点，这对应于Python的`None`。 

整数溢出在这里不是一个问题，因为约束仍然在 Go 的整数范围内。

 ## 边缘情况

 ### 空树

 一棵空树（`root = None`）是错误的常见来源，因为递归可能会尝试访问空对象上的属性。 当遇到以下情况时，我们的实现会立即从 DFS 返回`None`，这自然会产生一个空的结果列表。 

### 单节点树

 当树只包含一个节点时，根也是叶子。 幼稚的实现可能会忘记将其视为完整路径。 我们的叶子条件明确检查两个子节点是否都丢失，确保单节点树得到正确处理。 

### 负节点值

 由于节点值可能为负，因此早期剪枝是不安全的。 例如，路径总和可能暂时超过目标，然后由于负数而减少。 我们的实现完全避免了错误的修剪，并探索所有从根到叶的路径，保证了正确性。 

### 可变路径错误

 回溯问题中的一个微妙问题是意外存储对可变路径的引用而不是副本。 如果我们附加`current_path`直接，稍后`pop()`操作将修改已经存储的答案。 通过保存`current_path[:]`在Python中并使用`copy()`在 Go 中，每个结果都是独立且正确的。
