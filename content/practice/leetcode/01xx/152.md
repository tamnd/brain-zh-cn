 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们在整数数组中找到连续的子数组`nums`生产尽可能最大的产品。 与经典的最大子数组和问题不同，乘法引入了额外的复杂性，因为负数可以完全改变结果。 

子数组必须由连续的元素组成。 我们不能跳过元素或重新排列它们。 目标是返回最大乘积的数值，而不是子数组本身。 

输入是一个整数数组，其中：

 - 数组长度介于`1`和`2 * 10^4`- 每个元素都介于`-10`和`10`- 最终答案始终适合有符号的 32 位整数

 相对较大的数组大小立即表明`O(n^2)`或者`O(n^3)`解决方案可能太慢。 自从`n`可以大到`20,000`，如果可能的话，我们应该寻求线性时间解决方案。 

重要的复杂性来自负数和零。 

正数会增加乘积。 负数会翻转乘积的符号。 两个负数相乘又变成正数。 这意味着迄今为止看到的最小负乘积在乘以另一个负数时可能会突然变成最大的正乘积。 

零也很重要，因为任何包含零的乘积都会变为零。 零有效地将数组分成独立的段。 

一些边缘情况很重要：

 - 仅包含一个元素的数组
 - 包含零的数组
 - 具有偶数个负数的数组
 - 具有奇数个负数的数组
 - 最大乘积来自单个元素的数组
 - 最优子数组不是最长子数组的数组

 例如：

 -`[2,3,-2,4]`有答案`6`-`[-2,3,-4]`有答案`24`-`[0,2]`有答案`2`-`[-2]`有答案`-2`了解负值如何影响乘法是有效解决此问题的关键见解。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组并计算其乘积。 

对于每个起始索引`i`，我们可以将子数组一次向右扩展一个元素，从而保持运行的乘积。 每次扩展子数组时，我们都会将当前乘积与全局最大值进行比较。 

这是有效的，因为每个连续子数组都被明确考虑，所以最大乘积不会被错过。 

然而，有`O(n^2)`可能的子数组。 即使我们增量地计算乘积，总运行时间也会变成二次方。 

和`n = 20,000`， 一个`O(n^2)`解决方案可能需要数亿次操作，这对于 LeetCode 约束来说太慢了。 

### 最优动态规划方法

 关键的观察是乘以负数可以完全扭转情况。 

在每个位置，我们关心两个值：

 - 当前位置结束的最大乘积
 - 当前位置结束的最小乘积

 最小乘积很重要，因为将一个大的负值乘以另一个负值可以产生一个巨大的正乘积。 

例如：```
Current number = -4
Previous max = 3
Previous min = -6

New max = max(-4, 3 * -4, -6 * -4)
         = max(-4, -12, 24)
         = 24
```这意味着我们必须同时追踪两个极端。 

在每个元素上：

 - 如果当前数字为正数，则之前的最大值仍然有用
 - 如果当前数字为负数，则之前的最小值可能会成为新的最大值
 - 如果当前数量为零，则链有效地重新启动

 这会导致干净的`O(n)`动态规划解决方案。

 ## 算法演练

 ### 最优动态规划算法

 1. 使用数组的第一个元素初始化三个变量：

 -`current_max`-`current_min`-`global_max`我们使用第一个元素是因为每个子数组必须至少包含一个数字。 
2. 从索引开始迭代数组`1`。 
3. 对于每个数字`num`，首先检查是否为负数。 

如果当前数字为负数，则乘以它会交换最大乘积和最小乘积的角色。 因此，交换：

 -`current_max`-`current_min`4. 计算以当前索引结束的新最大乘积。 

新的最大值可以来自：

 - 开始一个新的子数组`num`- 扩展之前的最大乘积
 - 扩展之前的最小乘积，如果`num`是负数

 所以：```
current_max = max(num, current_max * num)
```5. 计算以当前索引结尾的新的最小乘积。 

相似地：```
current_min = min(num, current_min * num)
```6.更新全局答案。```
global_max = max(global_max, current_max)
```7. 继续直到数组末尾。 
8. 返回`global_max`。 

### 为什么它有效

 该算法保持一个不变量：

 -`current_max`始终存储以当前索引结尾的任何子数组的最大乘积
 -`current_min`始终存储以当前索引结尾的任何子数组的最小乘积

 由于乘以负数会颠倒顺序，因此先前的最小值可能会成为新的最大值。 通过在每一步跟踪这两个值，我们保证考虑每个可能的最佳子阵列乘积。 

由于在每个位置结束的每个子数组都是通过这些转换隐式表示的，因此最终的`global_max`必须是总体上最大的产品。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        current_max = nums[0]
        current_min = nums[0]
        global_max = nums[0]

        for num in nums[1:]:
            if num < 0:
                current_max, current_min = current_min, current_max

            current_max = max(num, current_max * num)
            current_min = min(num, current_min * num)

            global_max = max(global_max, current_max)

        return global_max
```该解决方案首先使用第一个元素初始化所有跟踪变量。 这确保了单元素数组的处理自然而然，以后不需要特殊的逻辑。 

该循环只处理每个剩余元素一次。 

当当前数字为负数时，之前的最大和最小乘积交换角色。 大的正乘积乘以负数成为大的负乘积，而大的负乘积乘以负数成为大的正乘积。 在更新之前交换变量可以大大简化逻辑。 

在可能的交换之后，我们计算：

 - 在此位置结束的最佳积极产品
 - 最差的负面产品在此位置结束

 该算法还考虑在当前元素处启动一个全新的子数组。 这就是为什么`num`其本身包含在`max`和`min`计算。 

最后，`global_max`跟踪阵列中任何地方看到的最大产品。 

## 解决方案```go
func maxProduct(nums []int) int {
	currentMax := nums[0]
	currentMin := nums[0]
	globalMax := nums[0]

	for i := 1; i < len(nums); i++ {
		num := nums[i]

		if num < 0 {
			currentMax, currentMin = currentMin, currentMax
		}

		currentMax = max(num, currentMax*num)
		currentMin = min(num, currentMin*num)

		globalMax = max(globalMax, currentMax)
	}

	return globalMax
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

由于 Go 没有提供内置的`max`和`min`整数函数，辅助函数是手动实现的。 

该问题保证所有乘积都位于 32 位有符号整数内，因此标准 Go`int`算术对于 LeetCode 来说就足够了。 

该数组保证至少包含一个元素，因此访问`nums[0]`总是安全的。

 ## 边缘情况

 ### 包含零的数组

 零尤其重要，因为乘以零会完全重置乘积。 幼稚的实现可能会错误地继续跨越零边界相乘。 

例如：```
[-2, 0, -1]
```子数组`[-2, -1]`无效，因为元素在零之后不连续。 该实现自然地处理这个问题，因为当`num == 0`， 两个都`current_max`和`current_min`变为零，有效地重新开始计算。 

### 具有多个负数的数组

 负值是这个问题的主要挑战。 只跟踪当前最大乘积的天真贪婪策略会失败，因为非常负的乘积可能随后会成为最大的正乘积。 

例如：```
[-2, 3, -4]
```在索引处`1`，运行乘积变为负值。 然而，乘以`-4`然后将其转换为一个大的正值。 

该实现通过跟踪以下两项来解决这个问题：

 - 每个位置结束的最大乘积
 - 每个位置结束的最小乘积

 这保证了未来的负数得到正确处理。 

### 单元素数组

 该数组只能包含一个数字。 

示例：```
[5]
[-2]
[0]
```某些实现错误地将值初始化为`0`或者`1`，这打破了这些情况。 

该解决方案使用以下方式初始化所有跟踪变量`nums[0]`，确保在没有任何特殊条件逻辑的情况下正确处理单个元素输入。
