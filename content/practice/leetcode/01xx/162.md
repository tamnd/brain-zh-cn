[LeetCode 第 162 题](https://leetcode.com/problems/find-peak-element/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`并要求我们找到任何峰值元素的索引。 

峰值元素定义为严格大于其紧邻元素的元素。 对于索引处的元素`i`， 这意味着：

-`nums[i] > nums[i - 1]`-`nums[i] > nums[i + 1]`该问题还定义了数组边界之外的虚值：

 -`nums[-1] = -∞`-`nums[n] = -∞`这个定义很重要，因为它意味着第一个或最后一个元素也可以是峰值。 例如：

 - 在`[3,2,1]`, 第一个元素`3`是一个峰值，因为它大于`2`并且还大于`-∞`。 
- 在`[1,2,3]`,最后一个元素`3`是一个峰值，因为它大于`2`并且还大于`-∞`。 

输入数组保证满足：```
nums[i] != nums[i + 1]
```这种保证极其重要，因为相邻元素永远不会相等。 这意味着相邻元素之间的每次比较都是严格递增或严格递减。 此属性允许二分搜索干净地工作。 

该问题需要一个算法`O(log n)`时间复杂度，这强烈表明需要基于二分搜索的解决方案。 线性扫描在逻辑上可以工作，但它不能满足所需的复杂性。 

一些重要的边缘情况包括：

 - 只有一个元素的数组
 - 严格增加数组
 - 严格递减数组
 - 边界处的峰值
 - 多个有效峰值

 该问题允许返回任何有效峰值的索引，因此我们不需要找到所有峰值或最大元素。 

## 方法

 ### 蛮力方法

 最直接的解决方案是从左到右扫描数组并检查每个元素是否是峰值。 

对于每个索引`i`，我们将当前元素与其左右邻居进行比较。 如果当前元素大于两者，我们返回它的索引。 

这是有效的，因为峰值的定义是局部的。 我们只需要比较相邻元素。 

然而，这种方法需要检查最坏情况下的每个元素，这会导致`O(n)`时间复杂度。 由于问题明确要求`O(log n)`从时间上看，这种方法并不能作为最终的解决方案。 

### 最佳解决方案的关键见解

 重要的观察是，我们可以使用相邻元素之间的斜率来消除一半的搜索空间。 

假设我们在索引处`mid`。 

- 如果`nums[mid] > nums[mid + 1]`，则序列降序为`mid`。 这意味着左侧某处一定有一个峰值，包括`mid`本身。 
- 如果`nums[mid] < nums[mid + 1]`，那么序列升序为`mid`。 这意味着右侧某处一定有一个峰值。 

为什么这是真的？ 

如果数组是升序的，最终会发生以下两种情况之一：

 - 上升停止并创造一个顶峰
 - 上升持续到终点，使最后一个元素成为顶峰

 同样，如果数组是下降的，则左侧一定存在峰值。 

这个属性允许我们执行二分搜索并在每一步将搜索空间减少一半。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描每个元素并检查邻居 |
 | 最佳| O(log n) | O(1) | O(1) | 使用斜率方向进行二分搜索 |

 ## 算法演练

 ### 最优二分查找算法

 1.初始化两个指针，`left = 0`和`right = len(nums) - 1`。 

这些指针定义了保证存在峰值的当前搜索范围。 
2.继续搜索`left < right`。 

当两个指针收敛到单个索引（这将是一个峰值）时，循环停止。 
3. 计算中间索引：```
mid = (left + right) // 2
```4. 比较`nums[mid]`和`nums[mid + 1]`。 

这个比较告诉我们我们是处于上坡还是下坡。 
5. 如果`nums[mid] > nums[mid + 1]`，向左移动搜索空间：```
right = mid
```由于序列是下降的，因此峰值必须存在于`mid`或者左边的某个地方。 
6. 否则，将搜索空间向右移动：```
left = mid + 1
```由于序列是上升的，因此右侧必定存在峰值。 
7.循环结束后，返回`left`。 

在此刻，`left == right`，并且该指数保证是峰值。 

### 为什么它有效

 该算法保持了当前搜索区间内存在至少一个峰值的不变性。 

每一步都比较`nums[mid]`和`nums[mid + 1]`告诉我们哪一边必须包含峰。 因为相邻元素永远不相等，所以我们总是有严格递增或严格递减的斜率。 

通过每次丢弃一半的搜索空间，该算法最终在对数时间内收敛到有效的峰值索引。 

## Python 解决方案```python
from typing import List

class Solution:
    def findPeakElement(self, nums: List[int]) -> int:
        left = 0
        right = len(nums) - 1

        while left < right:
            mid = (left + right) // 2

            if nums[mid] > nums[mid + 1]:
                right = mid
            else:
                left = mid + 1

        return left
```实现首先初始化二分搜索边界`left`和`right`。 

在循环内，我们计算中点并将当前值与下一个值进行比较。 该比较确定斜率是增加还是减少。 

如果坡度是下降的，我们通过设置保留左半部分`right = mid`。 我们包括`mid`因为它本身就可能是顶峰。 

如果坡度是上升的，我们丢弃左半部分并继续在右侧搜索`left = mid + 1`。 

当搜索间隔缩小到单个元素时，循环终止。 由于不变量保证区间中存在峰值，因此剩余索引必须是峰值。 

## 解决方案```go
func findPeakElement(nums []int) int {
    left := 0
    right := len(nums) - 1

    for left < right {
        mid := (left + right) / 2

        if nums[mid] > nums[mid+1] {
            right = mid
        } else {
            left = mid + 1
        }
    }

    return left
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 切片已经提供了高效的索引访问，因此不需要额外的数据结构。 整数溢出在这里不是问题，因为数组大小最多为 1000，尽管在较大的系统中许多开发人员仍然更喜欢：```go
mid := left + (right-left)/2
```两个版本都使用恒定的额外空间并迭代执行二分搜索。

 ## 边缘情况

 单个元素数组是可能的最小输入。 由于数组外的假想邻居是`-∞`，孤立元素自动成为峰值。 许多不正确的实现意外地访问了此处的越界索引。 该解决方案可以自然地处理它，因为二分搜索循环永远不会在以下情况下执行：`left == right`。 

严格递增数组是另一个重要的边缘情况。 在像这样的数组中`[1,2,3,4,5]`，每次比较都会将搜索区间向右移动。 最终，算法收敛于最后一个元素，这是一个有效的峰值，因为右边界的行为类似于`-∞`。 

严格递减数组还可能暴露二分搜索逻辑中的错误。 在`[5,4,3,2,1]`，每次比较都会向左移动搜索区间。 该算法正确收敛于索引`0`，这是一个峰值，因为左边界的行为就像`-∞`。 

具有多个峰值的阵列很重要，因为该问题不需要找到特定的峰值。 幼稚的实现可能会错误地尝试找到全局最大值。 这一解决方案之所以有效，是因为二分搜索不变式保证至少有一个峰值保留在活动搜索范围内，无论总体存在多少个峰值。
