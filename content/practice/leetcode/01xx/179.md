 # LeetCode 179 - 最大数字

 ## 问题理解

 这个问题要求我们重新排列非负整数列表，以便将它们连接在一起时形成尽可能大的数字。 

乍一看，这可能看起来像是一个简单的排序问题，我们只需按降序对数字进行排序即可。 然而，挑战来自这样一个事实：排序取决于数字彼此相邻放置时如何相互作用。 

例如，考虑输入`[3, 30]`。 

如果我们按数字降序排序，我们会放置`30`前`3`，生产`"303"`。 然而，`"330"`大于`"303"`， 意义`3`应该是第一位的。 这说明普通的数值排序是行不通的。 

相反，我们需要确定，对于每对数字`a`和`b`, 是否放置`a`前`b`或者`b`前`a`创造更大的结果。 

输入由一个整数数组组成`nums`，其中：

 - 每个值都是非负整数。 
- 数组的长度介于`1`和`100`。 
- 每个数字可以大到`10^9`。 

预期输出是一个**字符串**，而不是一个整数。 存在此要求是因为生成的串联数字可能变得非常大并超出标准整数限制。 

约束告诉我们输入的大小相对较小，最多`100`数字。 这意味着基于排序的解决方案是实用的。 然而，强力排列生成仍然是不可行的，因为排列是阶乘增长的。 

预先识别一些边缘情况很重要。 

第一个棘手的情况是当所有数字都为零时，例如`[0,0]`。 排序后可能会返回简单的串联`"00"`，但正确答案是`"0"`。 

另一个重要的情况涉及具有共享前缀的号码，例如`3`和`30`， 或者`12`和`121`。 数字排序或字典排序在这里失败，因为最佳排序取决于串联。 

该问题保证所有数字都是非负数，这简化了实现，因为我们不需要处理负号。 

## 方法

 ### 蛮力方法

 强力解决方案将生成所有可能的数字排列，并计算每个排列的最终串联数字。 评估所有排列后，我们返回最大的结果。 

例如，给定`[10,2]`，我们将生成：

 -`"102"`-`"210"`然后选择`"210"`作为最大值。 

这种方法保证是正确的，因为它详尽地检查了每种可能的顺序。 由于最优排列必须存在于所有排列中，所以蛮力总会找到它。 

然而，问题在于排列的数量呈阶乘增长。 为了`n`数，有`n!`可能的安排。 即使只有`100`元素，这在计算上变得不可能。 

### 最佳方法

 关键的观察是我们不需要测试每个排列。 相反，我们可以定义自定义排序规则。 

假设我们有两个表示为字符串的数字，`a`和`b`。 

为了确定哪个应该先出现，我们比较：

 -`a + b`-`b + a`如果`a + b`产生更大的值，那么`a`应该出现在之前`b`。 

例如：

-`a = "3"`-`b = "30"`比较：

-`"330"`-`"303"`自从`"330"`较大，`"3"`应该先来`"30"`。 

这个比较规则为我们提供了一种对整个数组进行贪婪排序的方法。 排序后，我们将所有字符串连接起来以形成答案。 

这样做的原因是每次本地比较都确保全局最优的串联顺序。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n) | O(n! × n) | O(n! × n) | O(n! × n) | 生成每个排列并比较结果 |
 | 最佳| O(n log n × k) | O(n log n × k) | O(n) | 使用基于串联比较的自定义排序 |

 这里，`k`表示数字的平均字符串长度，它很小，因为数字最多`10^9`。 

## 算法演练

 ### 最优算法

 1. 将每个整数转换为字符串。 

我们使用串联来执行比较，因此字符串比整数更容易使用。 例如，`30`变成`"30"`。 
2. 定义自定义比较规则。 

对于任意两个字符串`a`和`b`， 比较`a + b`和`b + a`。 

如果`a + b > b + a`， 然后`a`应该先来`b`。 

例如：

-`a = "9"`-`b = "34"`比较：

-`"934"`-`"349"`自从`"934"`较大，`"9"`首先。 
3. 使用此自定义比较器对字符串数组进行排序。 

排序过程重复比较对并排列它们，以便最终排序最大化串联结果。 
4. 处理全零边缘情况。 

排序后，如果第一个元素是`"0"`，那么每个数字都必须为零。 

例如：

 - 排序：`["0","0","0"]`返回`"000"`是不正确的。 

相反，返回`"0"`。 
5. 连接所有已排序的字符串。 

将字符串连接在一起以产生最终的最大数字。 

### 为什么它有效

 正确性取决于排序规则。 

对于任意两个元素`a`和`b`，将它们按照最大化的顺序排列`a+b`相对`b+a`确保最佳的本地安排。 由于排序在所有相邻元素之间强制执行这种关系，因此最终序列是全局最优的。 

换句话说，如果每个相邻对都以最佳方式排列，则任何交换都无法进一步改善结果。 

## Python 解决方案```python
from typing import List
from functools import cmp_to_key

class Solution:
    def largestNumber(self, nums: List[int]) -> str:
        string_numbers = [str(num) for num in nums]

        def compare(a: str, b: str) -> int:
            if a + b > b + a:
                return -1
            if a + b < b + a:
                return 1
            return 0

        string_numbers.sort(key=cmp_to_key(compare))

        if string_numbers[0] == "0":
            return "0"

        return "".join(string_numbers)
```实现首先将每个整数转换为字符串，因为串联比较是解决方案的核心。 

这`compare`函数定义自定义排序规则。 它不是直接比较数值，而是比较两种可能的串联：

 -`a + b`-`b + a`如果`a + b`更大，我们返回`-1`这样Python就可以放置`a`前`b`在排序过程中。 

Python 的内置排序函数需要一个关键函数而不是比较器。 为了弥补这一差距，我们使用`cmp_to_key`，它将比较器转换为可排序的键。 

排序后，我们检查第一个元素是否是`"0"`。 由于最大的数字总是首先出现，因此这个条件保证每个数字都为零。 

最后，我们将排序后的字符串连接在一起形成最终结果。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
	"strings"
)

func largestNumber(nums []int) string {
	stringNums := make([]string, len(nums))

	for i, num := range nums {
		stringNums[i] = strconv.Itoa(num)
	}

	sort.Slice(stringNums, func(i, j int) bool {
		return stringNums[i]+stringNums[j] >
			stringNums[j]+stringNums[i]
	})

	if stringNums[0] == "0" {
		return "0"
	}

	return strings.Join(stringNums, "")
}
```Go 实现遵循与 Python 版本相同的总体策略，但使用`sort.Slice`具有自定义比较功能。 

与 Python 不同，Go 排序通过布尔函数直接接受比较器。 如果串联`a+b`大于`b+a`，比较器返回`true`， 意义`a`应该先来`b`。 

实现使用`strconv.Itoa()`将整数转换为字符串并且`strings.Join()`有效地连接最终结果。 

Go 切片是数组的动态视图，因此对于空切片和 nil 切片不需要特殊处理，因为该问题保证至少有一个元素。 

整数溢出也不是问题，因为我们从不将最终结果转换为整数。 一切都保持为字符串。

 ## 边缘情况

 ### 所有值均为零

 输入如`[0,0,0]`是错误的常见来源。 排序后，幼稚的实现可能会返回`"000"`，从技术上讲，这是串联，但不是数字的预期表示。 

此实现通过检查第一个排序值是否是来处理该问题`"0"`。 由于排序将最大的元素放在前面，因此如果最大的元素为零，则每个元素也必须为零。 在这种情况下，我们返回`"0"`。 

### 具有共享前缀的数字

 输入如`[3,30]`或者`[12,121]`可以打破简单的数字或字典排序方法。 

例如，数字降序会错误地放置`30`前`3`， 导致`"303"`而不是`"330"`。 

自定义比较逻辑通过比较来解决这个问题`a+b`和`b+a`，确保排序最大化串联结果。 

### 单元素数组

 输入如`[7]`是一种边界情况，因为即使只有一个数字，排序逻辑仍然会执行。 

实现自然会处理这种情况。 字符串转换产生`["7"]`，排序不会改变任何内容，而连接会返回`"7"`正确。
