[LeetCode 第 198 题](https://leetcode.com/problems/house-robber/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题描述了一排房子，每间房子都包含一定数量的钱。 你扮演一名强盗，想要最大化被盗的总金额，但有一个重要的限制，你不能抢劫两栋相邻的房子。 如果您在当晚抢劫邻近房屋，警报系统会通知警方。 

输入是一个整数数组`nums`， 在哪里`nums[i]`代表可用资金量`i-th`房子。 你的任务是确定在不连续抢劫两栋房屋的情况下可以偷走的最大金额。 

思考这个问题的另一种方式是，对于每栋房子，你只有两种选择：

 1.抢当前的房子，也就是说你必须跳过之前的房子。 
2. 跳过当前的房子，这意味着您的总分仍然是迄今为止最好的。 

输出是一个整数，表示在遵守邻接规则的情况下您可以抢劫的最大总金额。 

限制相对较小：

 -`1 <= nums.length <= 100`-`0 <= nums[i] <= 400`由于数组长度最多为 100，因此理论上即使较慢的方法也可以工作。 然而，该问题旨在教授一种重要的动态规划模式，其中局部决策取决于先前的最优决策。 暴力解决方案是可能的，但由于重复计算而效率低下。 

在实施之前有几个重要的边缘情况值得识别。 

独栋房屋是最简单的情况。 如果`nums = [5]`，不存在邻接冲突，所以答案很简单`5`。 

所有房屋都包含的数组`0`仍必须正常工作。 例如，`[0,0,0]`应该返回`0`。 

Cases where robbing many small houses beats one large house can trip up greedy thinking. 例如，`[2,1,1,2]`应该返回`4`，因为抢劫两端的房子比贪婪地获取附近更大的值有更好的结果。 

该问题保证至少有一栋房子存在，因此我们永远不需要处理空数组。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是尝试所有可能的房屋组合，同时执行相邻房屋不能同时被抢劫的规则。 

对于每个房子，我们做出两个递归选择：

 - 抢劫当前的房子并跳过下一个。 
- 跳过当前的房子并移动到下一个。 

这将创建一个决策树，其中每个位置分支为两种可能性。 最终，我们计算出可实现的最大金额。 

例如，与`[2,7,9,3,1]`，递归反复探索重叠的子问题。 数组后面部分的最佳答案会被重新计算多次。 这种重复的工作使得解决方案效率低下。 

暴力递归看起来像这样：$$f(i) = \max(f(i+1), nums[i] + f(i+2))$$问题在于相同的状态会被重复重新计算，导致运行时间呈指数增长。 

### 最优动态规划方法

 关键的观察结果是该问题表现出**最优子结构**。 

在每个房子里`i`，最佳答案仅取决于之前的两种情况：

 - 如果我们跳过房子的最大金额`i`- 抢劫房屋的最高金额`i`假设我们在家`i`。 

如果我们抢劫，我们就无法抢劫`i - 1`，所以我们添加`nums[i]`至最佳答案`i - 2`。 

如果我们跳过它，我们只需将最佳答案保留到`i - 1`。 

这给出了递归式：$$dp[i] = \max(dp[i-1], dp[i-2] + nums[i])$$由于每个状态仅取决于前两个状态，因此我们不需要整个 DP 数组。 我们可以通过仅跟踪两个变量来优化常量内存的空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归地探索每个抢或跳过组合 |
 | 最佳| O(n) | O(1) | O(1) | 仅使用两个变量的动态规划 |

 ## 算法演练

 ### 最优动态规划算法

 1. 初始化两个变量来表示之前的结果。 

我们跟踪：

 -`prev_two`, 可获得的最大金钱`i - 2`-`prev_one`, 可获得的最大金钱`i - 1`最初，两者都是`0`因为在处理任何房屋之前，我们没有抢劫过任何东西。 
2. 遍历每个房子`nums`。 

对于每个房屋价值`money`，我们决定抢劫或跳过是否会产生更大的总数。 
3. 计算新的最佳值。 

有两种可能：

 - 跳过当前的房子，这给出了`prev_one`- 抢劫现在的房子，这给了`prev_two + money`我们采取：$$current = \max(prev_one, prev_two + money)$$4. 改变状态。 

现房处理后：

 -`prev_two`变旧`prev_one`-`prev_one`变成`current`这为我们下一次迭代做好了准备。 
5. 返回最终结果。 

处理完所有房屋后，`prev_one`包含最大可能的数量。 

### 为什么它有效

 该算法保持了一个重要的不变量：`prev_one`总是存储从迄今为止处理的所有房屋中可获得的最大金钱，而`prev_two`存储不包括前一个房屋的结果。 

在每一步中，算法都会比较仅有的两种有效可能性：抢劫或跳过当前房屋。 由于每个决策都是基于先前已经最优的结果，因此最终答案是全局最优的。 这遵循动态规划的原则，其中最优解决方案是根据最优子问题构建的。 

## Python 解决方案```python
from typing import List

class Solution:
    def rob(self, nums: List[int]) -> int:
        prev_two = 0
        prev_one = 0

        for money in nums:
            current = max(prev_one, prev_two + money)
            prev_two = prev_one
            prev_one = current

        return prev_one
```该实现使用两个变量而不是完整的动态编程数组。`prev_two`存储两栋房子之前的最佳结果，而`prev_one`存储前一个房子的最佳结果。 对于每栋房子，我们计算`current`作为两个选择中更好的一个：跳过房子或抢劫它。 

计算后`current`，我们将变量向前移动，以便它们代表下一次迭代的正确状态。 

该实现直接遵循递归关系，同时降低了空间复杂度`O(n)`到`O(1)`。 

## 解决方案```go
func rob(nums []int) int {
	prevTwo := 0
	prevOne := 0

	for _, money := range nums {
		current := max(prevOne, prevTwo+money)
		prevTwo = prevOne
		prevOne = current
	}

	return prevOne
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有提供内置的`max`对于整数函数，我们定义一个辅助函数。 

该解决方案使用整数变量而不是额外的切片，保持空间使用恒定。 Go 切片自然有效地处理输入数组，并且由于约束很小，因此整数溢出不是问题，因为最大可能的总和完全在 Go 的整数范围内。

 ## 边缘情况

 ### 独栋别墅

 当输入仅包含一栋房屋时，不存在邻接冲突。 幼稚的实现可能会错误地假设至少存在两个房屋并尝试建立无效索引。 这种实现完全避免了这个问题，因为循环只处理一个值并返回它。 

### 两栋相邻的房子

 对于输入，例如`[1,2]`，只能抢劫一所房子。 有缺陷的贪婪方法可能会意外地结合这两个值。 动态规划递归正确评估两个合法选项并选择较大的值。 

### 多个零值

 数组就像`[0,0,0,0]`可以暴露逻辑假设存在一些积极收益的错误。 该实现自然地处理了这个问题，因为每个步骤都会比较有效的总数，并且保留最大值`0`。 

### 贪婪陷阱案例

 案例如`[2,1,1,2]`很重要，因为贪婪的策略经常会失败。 选择当地最大的房子并不总是能产生最好的整体结果。 动态规划方法之所以成功，是因为它评估每一步的累积最优结果，而不是做出短视的决策。
