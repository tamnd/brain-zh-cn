 # LeetCode 131，回文分区

 ## 问题理解

 问题给了我们一个字符串`s`并要求我们将其分成子串，使得每个子串都是回文。 回文是向前和向后读相同的字符串。 我们必须返回所有可能的有效方法来分区字符串。 

分区意味着将字符串分成连续的部分。 原始字符串中的每个字符必须恰好属于分区中的一个子字符串，并且子字符串必须按原始顺序出现。 

例如，如果输入是`"aab"`，有两个有效的回文分区：

 -`["a", "a", "b"]`-`["aa", "b"]`第一个分区之所以有效，是因为每个单独的字符都是回文。 第二个有效是因为`"aa"`也是一个回文。 

输入尺寸相对较小，`s.length <= 16`。 这是一个重要的线索。 涉及“返回所有可能的组合”的问题通常具有指数输出大小，并且小的约束通常表明指数探索是可以接受的。 

挑战不仅在于找到回文，还在于有效地探索每个可能的分区，同时避免不必要的重复工作。 

一些边缘情况很重要：

 - 单字符字符串始终是回文，所以答案很简单`[[s]]`。 
- 每个字符都相同的字符串，例如`"aaaa"`，创建许多有效分区。 
- 没有多字符回文的字符串，例如`"abc"`，只允许单个字符的分区。 
- 由于问题保证小写英文字母且最小长度为1，因此我们不需要处理空输入或无效字符。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试一切可能的方法来分割字符串，然后检查该分区中的每个子字符串是否都是回文。 

对于一个长度的字符串`n`， 有`n - 1`可能的分割位置。 每个位置可以包含剪切，也可以不包含剪切，这意味着有`2^(n-1)`可能的分区。 

对于每个分区，我们必须通过检查每个子字符串是否是回文来验证它。 回文检查需要`O(k)`子串长度的时间`k`。 

这种方法是正确的，因为它详尽地探索了每个分区配置。 然而，它执行大量重复的回文检查。 相同的子字符串可能会在不同的递归分支上进行多次测试。 

由于这种冗余，暴力方法变得低效。 

### 最佳方法

 关键的见解是问题自然形成决策树。 

在每个索引处，我们可以选择从该位置开始的任何回文子串，然后递归地求解字符串的剩余后缀。 

我们不是先生成每个分区然后再验证，而是从头开始构建有效的分区。 

我们可以通过预先计算每个子串是否`s[i:j]`是使用动态规划的回文。 

此预处理允许回文检查`O(1)`回溯期间的时间。 

因此，该算法结合了：

 - 快速回文查找的动态编程
 - 回溯生成所有有效分区

 这更加有效，因为我们避免了重复的回文计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × 2^n × n) | O(n × 2^n × n) | O(n × 2^n) | O(n × 2^n) | 生成所有分区并重复检查回文 |
 | 最佳| O(n^2 + n × 2^n) | O(n^2 + n × 2^n) | O(n^2 + n × 2^n) | O(n^2 + n × 2^n) | 使用带回溯的 DP 预处理 |

 ## 算法演练

 ### 步骤 1：预先计算回文子串

 创建二维表`is_palindrome`在哪里：```
is_palindrome[i][j] = True
```如果子串`s[i:j+1]`是一个回文。 

我们从较短的子字符串到较长的子字符串填充此表。 

如果满足以下条件，则子串是回文串：

 - 两端的字符匹配
 - 内部子串也是回文

 正式：```
s[i] == s[j] and is_palindrome[i+1][j-1]
```对于长度为 1 或 2 的子串，匹配末端就足够了。 

### 步骤2：从索引0开始回溯

 我们从字符串的开头开始递归地构建分区。 

在每个位置`start`，我们尝试每一个可能的结束索引`end`。 

如果`s[start:end+1]`是一个回文，我们：

 1.添加到当前分区
 2. 递归继续`end + 1`3.之后删除子串进行回溯

 ### 步骤3：记录完成的分区

 如果`start == len(s)`，我们已经消耗了整个字符串。 

此时，当前分区仅包含回文子串，并且表示有效的解决方案。 

我们将分区的副本添加到结果列表中。 

### 第 4 步：继续探索所有可能性

 回溯确保我们系统地探索每个有效的分区配置。 

因为我们只递归回文子串，所以每个生成的分区都是自动有效的。 

### 为什么它有效

 该算法保持当前存储在分区中的每个子串都是回文的不变量。 

在每个递归步骤中，我们仅使用有效的回文子字符串扩展分区。 由于探索了每一个可能的回文扩展，因此不会遗漏任何有效的分区。 

仅当整个字符串被分区后，递归才会终止，从而保证每个记录的结果都是完整且正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def partition(self, s: str) -> List[List[str]]:
        n = len(s)

        # Precompute palindrome table
        is_palindrome = [[False] * n for _ in range(n)]

        for i in range(n - 1, -1, -1):
            for j in range(i, n):
                if s[i] == s[j]:
                    if j - i <= 2 or is_palindrome[i + 1][j - 1]:
                        is_palindrome[i][j] = True

        result = []
        current_partition = []

        def backtrack(start: int) -> None:
            if start == n:
                result.append(current_partition[:])
                return

            for end in range(start, n):
                if is_palindrome[start][end]:
                    current_partition.append(s[start:end + 1])

                    backtrack(end + 1)

                    current_partition.pop()

        backtrack(0)

        return result
```实施从构建`is_palindrome`桌子。 嵌套循环从右到左迭代起始索引，以便在较大的子字符串依赖它们之前已经计算出较小的子字符串。 

条件：```python
j - i <= 2
```处理长度为 1、2 和 3 的子字符串。这些情况不需要检查内部子字符串。 

预处理后，解决方案使用递归回溯。 

这`current_partition`list 存储到目前为止选择的子字符串。 每当我们找到回文子串时，我们都会将其追加并从下一个位置递归地继续搜索。 

一旦递归返回，我们使用以下方法删除子字符串`pop()`。 这将恢复之前的状态，以便可以探索其他选择。 

该行：```python
result.append(current_partition[:])
```创建当前分区的副本。 如果不进行复制，以后的修改将影响之前存储的结果。 

## 解决方案```go
func partition(s string) [][]string {
	n := len(s)

	isPalindrome := make([][]bool, n)
	for i := range isPalindrome {
		isPalindrome[i] = make([]bool, n)
	}

	// Precompute palindrome table
	for i := n - 1; i >= 0; i-- {
		for j := i; j < n; j++ {
			if s[i] == s[j] {
				if j-i <= 2 || isPalindrome[i+1][j-1] {
					isPalindrome[i][j] = true
				}
			}
		}
	}

	var result [][]string
	var current []string

	var backtrack func(start int)

	backtrack = func(start int) {
		if start == n {
			partitionCopy := make([]string, len(current))
			copy(partitionCopy, current)

			result = append(result, partitionCopy)
			return
		}

		for end := start; end < n; end++ {
			if isPalindrome[start][end] {
				current = append(current, s[start:end+1])

				backtrack(end + 1)

				current = current[:len(current)-1]
			}
		}
	}

	backtrack(0)

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个重要的区别是切片复制。 在 Go 中，切片引用共享的底层数组，因此我们必须在将其附加到结果之前显式创建一个新切片：```go
partitionCopy := make([]string, len(current))
copy(partitionCopy, current)
```如果没有这个副本，以后的修改`current`会影响存储的结果。 

另一个区别是切片回溯：```go
current = current[:len(current)-1]
```这将删除最近添加的子字符串。

 ## 边缘情况

 ### 单字符输入

 长度为 1 的字符串始终是回文。 这种情况很重要，因为递归算法有时会错误地处理最小输入大小或意外生成空分区。 

实现自然地处理了这个问题。 回文表将单个字符标记为有效，选择该字符后递归立即到达基本情况。 

### 没有多字符回文的字符串

 输入如`"abc"`可以暴露算法错误地假设存在较大回文的错误。 

在这种情况下，只有单字符子字符串有效。 该算法仍然有效，因为每个字符都满足回文条件，允许递归一次处理一个字符。 

### 具有许多重叠回文的字符串

 输入如`"aaaa"`生成大量有效分区，因为几乎每个子串都是回文。 

这是具有挑战性的，因为低效的回文检查会重复地重新计算相同的信息。 

DP 预处理通过存储一次回文结果并在整个递归过程中重复使用它们，有效地解决了这个问题。 

### 偶数长度回文

 有些实现意外地只能正确处理奇数长度的回文。 

例如，`"abba"`包含`"bb"`和`"abba"`作为偶数长度的回文。 

条件：```
j - i <= 2
```与匹配边界字符相结合，可以正确处理偶数长度和奇数长度回文情况。
