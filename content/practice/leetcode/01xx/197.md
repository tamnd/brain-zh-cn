[LeetCode 第 197 题](https://leetcode.com/problems/rising-Temperature/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`Weather`存储每日温度记录。 每行包含三个字段：一个唯一的`id`, 一个`recordDate`，以及`temperature`于该日期记录。 

任务是查找温度高于前一个日历日记录的温度的所有行。 换句话说，对于每个日期，我们必须确定表中是否存在昨天以及今天的温度是否严格大于昨天的温度。 如果两个条件都成立，我们返回当前行的`id`。 

例如，假设我们有一行`2015-01-02`有温度`25`，另一行为`2015-01-01`有温度`10`。 自从`25 > 10`，该行为`2015-01-02`符合条件，所以我们将其包括在内`id`。 

一个重要的细节是，比较必须与前一个日历日进行比较，而不仅仅是按排序顺序的前一行。 如果表中缺少日期，则没有有效的“昨天”条目可供比较。 

该问题保证：

 -`id`价值观是独一无二的
 - 没有两行共享相同的行`recordDate`- 每行准确代表一天的温度

 这些保证简化了解决方案，因为我们永远不需要处理重复的日期或不明确的比较。 

问题的规模足够小，即使效率较低的解决方案也可能通过，但目标是编写干净且最佳的 SQL 查询。 

一些边缘情况很重要：

 - 表中最早的日期永远不符合条件，因为它没有前一天。 
- 错过日期很重要。 如果`2015-01-03`存在但是`2015-01-02`不，那么`2015-01-03`无法比较，也不应包含在内。 
- 相同的温度不合格，因为该问题需要严格更高的温度。 
- 该表可能只包含一行，在这种情况下结果为空。 

## 方法

 ### 蛮力方法

 强力解决方案将检查每一行并搜索整个表以查找前一个日历日是否存在行。 一旦找到，它就会比较温度。 

从概念上讲，对于每条记录：

 1. 计算昨天的日期。 
2. 扫描所有行以查找匹配的日期。 
3. 比较温度。 
4.添加当前`id`如果今天的气温再高一点的话。 

这种方法是正确的，因为每一行都明确检查是否存在有效的前一天记录以及温度条件是否成立。 

然而，这种解决方案效率低下，因为每一行可能都需要再次扫描整个表。 如果有`n`行，总工作变为`O(n²)`。 

### 最佳方法

 关键的见解是，这自然是一个自连接问题。 

我们需要将每一行与同一个表中的另一行进行比较，特别是代表昨天的行。 SQL 连接正是为这种类型的关系而设计的。 

我们可以加入`Weather`表及其自身：

 - 一个别名代表今天的天气
 - 另一个别名代表昨天的天气

 然后我们强制执行两个条件：

 1. 日期相差整整一天
 2.今天的气温比昨天的气温高

 由于数据库引擎有效地优化连接，因此这种方法避免了重复的全扫描，并且在概念上更加清晰。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 对于每一行，再次扫描表以查找昨天 |
 | 最佳| O(n) 平均索引 | O(1) | O(1) | 使用自连接直接比较相邻日期 |

 ## 算法演练

 1. 首先创建两个别名`Weather`桌子。 

一个别名代表当天的记录，通常称为`w1`。 第二个别名代表前一天的记录，通常称为`w2`。 
2. 匹配日期相差一天的行。 

我们使用日期函数，例如`DATEDIFF(w1.recordDate, w2.recordDate) = 1`。 

这确保了`w2`正好是昨天相对于`w1`。 
3. 比较温度。 

匹配相邻日期后，检查是否：```
w1.temperature > w2.temperature
```这仅过滤温度升高的行。 
4. 返回当天的`id`。 

问题要求的是`id`对应于温暖的一天，所以我们选择`w1.id`。 

### 为什么它有效

 该算法之所以有效，是因为每个符合条件的行都必须满足两个独立的条件：

 - 存在正好早一个日历日的行
 - 当前温度高于前一天的温度

 自连接保证只比较有效的相邻日对。 然后，温度过滤器确保仅返回上升的温度。 由于每个日期都是唯一的，因此每次比较都是明确的。 

## Python 解决方案

 尽管这是一个数据库问题并且 LeetCode 需要 SQL，但以下 Python 示例以编程方式演示了相同的逻辑。```python
from typing import List, Dict

class Solution:
    def risingTemperature(self, weather: List[Dict]) -> List[int]:
        date_to_temp = {}
        date_to_id = {}

        for record in weather:
            date_to_temp[record["recordDate"]] = record["temperature"]
            date_to_id[record["recordDate"]] = record["id"]

        result = []

        for record in weather:
            current_date = record["recordDate"]
            current_temp = record["temperature"]

            previous_date = current_date.fromordinal(
                current_date.toordinal() - 1
            )

            if previous_date in date_to_temp:
                if current_temp > date_to_temp[previous_date]:
                    result.append(record["id"])

        return result
```在构建从日期到温度和 ID 的哈希映射后，该实现会迭代每条记录并计算前一个日历日。 如果数据集中存在昨天并且今天的温度较高，则当前`id`被添加到结果中。 

哈希图允许恒定时间查找昨天的温度，避免了暴力方法中所需的重复扫描。 

对于实际的LeetCode数据库提交，期望的SQL解决方案是：```python
SELECT w1.id
FROM Weather w1
JOIN Weather w2
    ON DATEDIFF(w1.recordDate, w2.recordDate) = 1
WHERE w1.temperature > w2.temperature;
```This SQL query directly mirrors the algorithmic reasoning discussed earlier.

 ## 解决方案```go
package main

import (
	"time"
)

type WeatherRecord struct {
	ID          int
	RecordDate  time.Time
	Temperature int
}

func risingTemperature(weather []WeatherRecord) []int {
	dateToTemp := make(map[time.Time]int)

	for _, record := range weather {
		dateToTemp[record.RecordDate] = record.Temperature
	}

	result := []int{}

	for _, record := range weather {
		previousDate := record.RecordDate.AddDate(0, 0, -1)

		if previousTemp, exists := dateToTemp[previousDate]; exists {
			if record.Temperature > previousTemp {
				result = append(result, record.ID)
			}
		}
	}

	return result
}
```The Go implementation follows the same strategy as the Python version. 地图可以持续获取昨天的气温。 

Go 特有的一个细节是使用`time.Time`和`AddDate(0, 0, -1)`计算前一天。 切片动态地用于结果列表，Go 的映射查找语法可以方便地返回值以及键是否存在。

 ## 边缘情况

 一个重要的边缘情况是表仅包含一行。 由于没有可用于比较的前一个日历日，因此结果必须为空。 假设每行都有前驱的简单实现可能会失败或产生无效的比较。 该实现通过在比较温度之前显式检查昨天是否存在来正确处理此问题。 

另一个重要的情况是日期缺失。 例如，如果表包含`2020-01-01`和`2020-01-03`，没有有效的比较`2020-01-03`因为`2020-01-02`缺席。 在排序后简单地比较连续行的简单方法会错误地将这些日期视为相邻的。 该实现通过要求精确的一天差异来避免此错误。 

相同的温度也是一种微妙的边缘情况。 该问题要求温度严格更高，而不是大于或等于。 如果昨天的气温是`20`今天的温度也是`20`，不得包含该行。 该实现正确地使用了`>`运算符而不是`>=`。 

最后的边缘情况涉及无序输入。 不保证表中的行按日期排序。 因此，简单的顺序扫描可能会比较错误的行。 哈希映射方法和 SQL 自连接都避免依赖输入顺序，无论记录如何排列都确保正确性。
