[LeetCode 第 187 题](https://leetcode.com/problems/repeated-dna-sequences/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、位操作、滑动窗口、滚动哈希、哈希函数

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到所有固定长度的重复DNA子序列，特别是长度`10`，在给定的 DNA 字符串内。 

输入是一个字符串`s`，其中每个字符代表一个 DNA 核苷酸。 该字符串仅包含四个可能的字符：

 -`'A'`-`'C'`-`'G'`-`'T'`我们必须检查每个长度的子串`10`并确定哪些在 DNA 序列中出现**多次**。 输出应包含每个重复的`10`- 字符序列只出现一次，无论出现多少次。 

例如，如果某个子字符串出现三到四次，它在最终结果中仍然应该只出现一次。 

关键细节是我们正在寻找**大小为 10** 的固定长度窗口，而不是任意重复的子字符串。 这立即表明了滑动窗口样式的方法，因为我们反复检查相同长度的重叠子串。 

约束条件很重要：

 -`1 <= s.length <= 10^5`- 仅存在四个可能的字符

 字符串长度为`10^5`意味着我们无法承担昂贵的重复子串比较或嵌套扫描方法。 我们需要接近线性时间的东西。 

一些边缘情况立即脱颖而出：

 如果`s.length < 10`, 没有有效的`10`-字符子串，所以答案必须为空。 

如果相同的序列重复多次，我们应该只在结果中包含它一次。 例如，`"AAAAAAAAAAAAA"`包含多个重叠出现的`"AAAAAAAAAA"`，但输出仅包含一份副本。 

重叠重复是有效的。 重复序列不需要从不重叠的位置开始。 

## 方法

 ### 蛮力方法

 解决这个问题最简单的方法是生成长度为每个可能的子串`10`并计算每个出现的次数。 

We slide through the string one character at a time. 对于每个位置`i`，我们提取：```
s[i:i+10]
```我们将每个子字符串存储在哈希映射中，其中键是序列，值是其频率。 

处理完所有窗口后，我们迭代频率图并收集每个计数大于的子串`1`。 

这种方法是正确的，因为每一个可能的`10`- 字符序列被显式计数。 如果一个序列出现多次，则其频率将超过`1`。 

然而，子字符串的创建需要时间。 由于每个子串都有长度`10`，这在技术上变成`O(10 × n)`，这简化为`O(n)`因为`10`是恒定的。 在实践中，该解决方案对于问题约束来说已经足够有效。 

尽管如此，我们仍然可以利用 DNA 仅包含四个字符这一事实，在概念上做得更好。 

### 最佳解决方案的关键见解

 由于 DNA 字符仅来自四个可能的值，因此我们可以使用 **2 位** 对每个核苷酸进行编码：

 | 人物 | 二进制|
 | --- | --- |
 | 一个 |`00`|
 | C |`01`|
 | G |`10`|
 | T |`11`|

 长度序列`10`因此只需要：```
10 × 2 = 20 bits
```这意味着每一个`10`-字符DNA子串可以表示为单个整数。 

我们可以维护一个编码为位的滚动哈希，而不是将实际的子字符串存储在哈希集中。 当滑动窗口移动时：

 - 左移 2 位
 - 添加新的核苷酸
 - 删除 20 位窗口之外的位

 这使我们能够在恒定时间内表示每个窗口，而无需重复构造字符串。 

然后我们跟踪：

 - 我们以前见过的编码
 - 编码已添加到答案中

 当我们第二次遇到编码时，我们将实际的子字符串附加到结果中。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 存储实际的子串并计算频率 |

 ## 算法演练

 ### 最优算法，带有位操作的滚动哈希

 1.首先检查输入长度是否小于`10`。 

如果`len(s) < 10`，立即返回一个空列表，因为不存在有效的子字符串。 
2. 创建 DNA 字符的映射。 

由于仅存在四个核苷酸，因此使用两位对它们进行编码：```
A → 00
C → 01
G → 10
T → 11
```这种紧凑的表示允许高效的滚动更新。 
3. 初始化数据结构。 

创建：

 - 一组称为`seen`跟踪已经遇到的哈希值
 - 一组称为`repeated`以避免重复插入
 - 最终答案的结果列表
 4. 构建滚动哈希。 

当我们遍历字符串时：

 - 将当前哈希左移`2`- 添加新字符的编码值
 - 只保留最后一个`20`位

 面具：```
(1 << 20) - 1
```确保我们丢弃当前之外的旧位`10`- 字符窗口。 
5. 第一次开始处理`10`字符可用。 

我们无法在索引之前形成有效的序列`9`。 

对于每个有效窗口：

 - 如果编码序列已经存在于`seen`，表示这个DNA子串以前出现过。 
- 如果尚未添加到`repeated`，将子字符串附加到结果并将其标记为重复。 
- 否则，将编码添加到`seen`。 
6. 继续直到字符串末尾。 

结果列表将包含所有重复的`10`- 字符 DNA 序列。 

### 为什么它有效

 该算法之所以有效，是因为每个`10`- 字符 DNA 序列映射到唯一的 20 位整数。 由于每个字符恰好使用 2 位且仅存在 4 个字符，因此不会发生冲突。 滚动哈希始终代表当前窗口的长度`10`，以及`seen`set 保证我们检测到重复序列。 这`repeated`set 确保每个重复序列都被添加到答案中一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def findRepeatedDnaSequences(self, s: str) -> List[str]:
        sequence_length = 10

        if len(s) < sequence_length:
            return []

        char_to_bits = {
            'A': 0,
            'C': 1,
            'G': 2,
            'T': 3
        }

        seen = set()
        repeated = set()
        result = []

        rolling_hash = 0
        mask = (1 << (2 * sequence_length)) - 1

        for index, char in enumerate(s):
            rolling_hash = (
                (rolling_hash << 2) | char_to_bits[char]
            ) & mask

            if index >= sequence_length - 1:
                if rolling_hash in seen:
                    if rolling_hash not in repeated:
                        result.append(
                            s[index - sequence_length + 1:index + 1]
                        )
                        repeated.add(rolling_hash)
                else:
                    seen.add(rolling_hash)

        return result
```该实现从提前返回短于以下的字符串开始：`10`，因为此类输入不能包含有效的 DNA 序列。 

这`char_to_bits`字典将 DNA 字符转换为紧凑的 2 位表示形式。 这种编码至关重要，因为它使我们能够存储整个`10`- 单个整数内的字符序列。 

变量`rolling_hash`存储当前编码窗口。 在每次迭代中，我们将先前的值左移两位并附加新的核苷酸编码。 该掩码仅确保最新的`20`保留位。 

这`seen`set 存储已经遇到的哈希值。 如果当前哈希已经存在，我们就知道该序列之前已经出现过。 这`repeated`set 可防止重复项多次附加到答案中。 

最后提取重复窗口对应的子串并添加到`result`。 

## 解决方案```go
func findRepeatedDnaSequences(s string) []string {
	const sequenceLength = 10

	if len(s) < sequenceLength {
		return []string{}
	}

	charToBits := map[byte]int{
		'A': 0,
		'C': 1,
		'G': 2,
		'T': 3,
	}

	seen := make(map[int]bool)
	repeated := make(map[int]bool)
	result := []string{}

	rollingHash := 0
	mask := (1 << (2 * sequenceLength)) - 1

	for i := 0; i < len(s); i++ {
		rollingHash = ((rollingHash << 2) | charToBits[s[i]]) & mask

		if i >= sequenceLength-1 {
			if seen[rollingHash] {
				if !repeated[rollingHash] {
					result = append(
						result,
						s[i-sequenceLength+1:i+1],
					)
					repeated[rollingHash] = true
				}
			} else {
				seen[rollingHash] = true
			}
		}
	}

	return result
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个显着的区别是 Go 字符串使用以下方式进行索引`byte`，因此核苷酸编码图谱使用`map[byte]int`。 Go 使用的不是 Python 集合`map[int]bool`模拟会员资格检查。 

Go 不区分`nil`和 LeetCode 提交中针对此问题的空切片，但返回空切片更加明确和一致。 

整数溢出不是问题，因为滚动哈希仅使用`20`位。

 | --- | --- | --- |

 ## 边缘情况

 ### 输入长度小于 10

 如果输入字符串少于`10`字符，没有有效的 DNA 窗口可供检查。 幼稚的实现可能会意外尝试子字符串提取并导致索引问题。 此实现可以通过立即提前返回来防止这种情况发生。 

### 重叠重复序列

 重复的 DNA 序列可以重叠。 例如：```
"AAAAAAAAAAAAA"
```包含许多重叠的`"AAAAAAAAAA"`视窗。 有缺陷的实现可能会在检测到重复后移动得太远，从而意外地忽略重叠。 由于该解决方案处理每个相邻窗口，因此可以自然地处理重叠重复。 

### 重复序列出现多次

 一个序列可能出现两次以上。 例如：```
"AAAAAAAAAAAAAA"
```重复包含相同的序列。 如果没有`repeated`设置后，算法可以将相同的子字符串多次添加到结果中。 该实现通过记录答案中已包含的序列来避免这种情况。 

### 所有独特的序列

 一些输入不包含重复的`10`- 字符子串。 在这些情况下，算法会正确返回空列表，因为不会两次遇到滚动哈希。
