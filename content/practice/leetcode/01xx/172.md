 ## 解决方案

 ## 问题理解

 该问题要求我们确定有多少个尾随零出现在末尾`n!`， 在哪里`n!`代表的阶乘`n`。 

阶乘定义为：$$n! = n \times (n - 1) \times (n - 2) \times \dots \times 2 \times 1$$例如：

-`5! = 5 × 4 × 3 × 2 × 1 = 120`-`120`以一零结尾，所以答案是`1`每当一个数字可以被整除时，就会创建一个尾随零`10`。 自从：$$10 = 2 \times 5$$阶乘中的每个尾随零都来自一对因数`(2, 5)`。 

输入是单个整数`n`，输出应该是尾随零的数量`n!`。 

限制条件是：

 -`0 <= n <= 10^4`尽管输入大小不是很大，但后续明确要求使用对数时间解决方案。 这意味着我们应该避免直接计算阶乘，因为阶乘值增长得非常快并且变得不必要的大。 

一些边缘情况很重要：

 -`n = 0`， 因为`0! = 1`，没有尾随零
 - 小值，例如`1`,`2`,`3`， 和`4`，这也产生零尾随零
 - 包含多个因子的数字`5`， 例如`25`或者`125`，因为它们贡献了多个尾随零
 - 在具有固定整数大小的语言中，直接计算阶乘的值可能会变得低效或溢出

 ## 方法

 ### 蛮力方法

 一个简单的解决方案是直接计算阶乘，然后计算结果数字末尾出现的零个数。 

例如：$$10! = 3628800$$我们可以反复除以`10`而数字结尾为`0`。 

这种方法之所以有效，是因为尾随零实际上是阶乘值末尾的连续零数字的数量。 

然而，由于以下几个原因，这种方法效率低下：

 - 阶乘增长极快
 - 结果数字变得非常大
 - 计算整个阶乘是不必要的，因为我们只关心尾随零的计数
 - 在许多语言中，整数溢出成为大阶乘的问题

 虽然Python支持任意精度整数，但后续特别要求对数解，所以暴力破解是不可接受的。 

### 最优数学观察

 关键的见解是尾随零来自以下因素`10`，以及每一个`10`由一组成`2`和一个`5`。 

在阶乘中，因子为`2`非常常见，因为每个偶数至少贡献一个`2`。 

因素`5`不太常见，因此尾随零的数量完全取决于出现的次数`5`出现在素因数分解中`n!`。 

因此我们计算：

 - 有多少倍`5`存在
 - 有多少倍`25`存在，因为每个人都贡献了额外的`5`- 有多少倍`125`存在，因为每个人都贡献另一个人`5`- 等等

 公式变为：$$\left\lfloor \frac{n}{5} \right\rfloor + \left\lfloor \frac{n}{25} \right\rfloor + \left\lfloor \frac{n}{125} \right\rfloor + \dots$$这产生了非常有效的对数解。

 ## 算法演练

 ### 最优算法

 1. 初始化一个名为`zeroes`到`0`。 

该变量将存储尾随零的总数。 
2、反复划分`n`经过`5`。 

的每一个倍数`5`至少贡献一个因素`5`。 

例如：

-`5`-`10`-`15`-`20`都贡献一个因素`5`。 
3. 添加`n // 5`到结果。 

这计算了之间有多少个数字`1`和`n`至少贡献一个因素`5`。 
4. 继续除以更高的幂`5`。 

有些数字贡献了不止一个因素`5`。 

例如：

-`25 = 5 × 5`-`125 = 5 × 5 × 5`所以我们还必须添加：

 -`n // 25`-`n // 125`- 等等
 5. 当除数大于时停止`n`。 

那时，不存在其他倍数。 
6. 返回累加结果。 

### 为什么它有效

 每个尾随零来自一对`(2, 5)`。 由于阶乘包含更多的因子`2`比因素`5`，尾随零的数量恰好等于`5`。 

该算法计算因子的每次出现`5`在阶乘分解中。 的倍数`5`贡献一个因素的倍数`25`贡献一个额外的因素，倍数`125`贡献另一个额外因素，等等。 因此，最终计数与尾随零的数量完全匹配。 

## Python 解决方案```python
class Solution:
    def trailingZeroes(self, n: int) -> int:
        zeroes = 0
        divisor = 5

        while divisor <= n:
            zeroes += n // divisor
            divisor *= 5

        return zeroes
```实现从初始化结果变量开始`zeroes`到`0`。 

变量`divisor`开始于`5`因为我们正在计算的因素`5`。 

循环内部：

 -`n // divisor`计算有多少个数字贡献了这个力量`5`- 结果被添加到`zeroes`- 除数乘以`5`移动到下一个电源

 例如：

 -`5`-`25`-`125`一旦除数超过，循环终止`n`，因为没有更多的倍数可以贡献因素`5`。 

最后，返回尾随零的总数。 

## 解决方案```go
func trailingZeroes(n int) int {
    zeroes := 0
    divisor := 5

    for divisor <= n {
        zeroes += n / divisor
        divisor *= 5
    }

    return zeroes
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

一个重要的区别是 Go 使用固定宽度整数，这与 Python 的任意精度整数不同。 然而，在给定的约束下，整数溢出不是一个问题，因为`n <= 10^4`。 

Go 中整数除法的使用`/`对于整数，它会自动截断为零，匹配该算法所需的行为。

 ## 边缘情况

 ### 边缘情况 1：`n = 0`这种情况很重要，因为许多实现错误地假设阶乘从`1!`。 

然而：$$0! = 1$$和`1`没有尾随零。 

该实现自然地处理了这个问题，因为循环条件`divisor <= n`立即失败，当`n = 0`，所以函数正确返回`0`。 

### 边缘情况 2：小于 5 的数字

 值如`1`,`2`,`3`， 和`4`不包含以下因素`5`，因此它们的阶乘不能包含尾随零。 

如果没有正确处理小输入，幼稚的实现可能会意外地执行不必要的计算或产生不正确的结果。 

该算法可以正常工作，因为循环永远不会针对这些值执行。 

### 边缘情况 3：5 的幂

 像这样的数字`25`,`125`， 和`625`是错误的简单来源，因为它们会造成多种因素`5`。 

例如：$$25 = 5 \times 5$$如果一个实现只计算`5`，它会错误地返回`5`而不是`6`为了`25!`。 

该算法通过重复除以递增幂来避免这个问题`5`：$$n // 5,\ n // 25,\ n // 125$$这确保了每个因素`5`只计算一次。 

### 边缘情况 4：大输入

 在某些语言中，直接计算大型输入的阶乘可能会变得极其低效，并且可能会溢出固定宽度的整数类型。 

数学计数方法完全避免构建阶乘。 它仅使用除法和加法，即使对于比给定约束大得多的值，也使其既高效又安全。
