[LeetCode 第 127 题](https://leetcode.com/problems/word-ladder/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、广度优先搜索

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定两个单词之间**最短变换序列**的长度，`beginWord`和`endWord`，在严格的变换规则下。 

有效的转换**一次仅更改一个字符**，并且每个中间单词必须存在于提供的内容中`wordList`。 这`beginWord`它本身不需要出现在字典中，但转换序列中它后面的每个单词根据字典必须是有效的。 

目标不是生成所有可能的序列。 相反，我们只关心最短有效路径中的**最小单词数**`beginWord`到`endWord`。 

例如，如果：```
beginWord = "hit"
endWord = "cog"
wordList = ["hot","dot","dog","lot","log","cog"]
```一种有效的转换是：```
hit → hot → dot → dog → cog
```这个序列包含 **5 个单词**，所以答案是`5`。 

问题变得不可能如果`endWord`不存在于`wordList`，因为每个变换后的单词都必须属于字典。 在这种情况下，答案是立即`0`。 

这些约束揭示了有关问题规模的重要信息：

 - 字长最多为`10`-`wordList`包含多达`5000`独特的词
 - 所有单词的长度相同
 - 仅使用小写英文字母

 在这种规模下，比较每对单词的简单图形结构将变得昂贵。 由于每个单词都可能与许多其他单词相关联，因此我们需要一种更有效的策略来查找相邻单词。 

关键的观察结果是，这个问题从根本上来说是一个**未加权图中的最短路径问题**。 每个单词都是一个节点，如果两个单词仅相差一个字母，则它们共享一条边。 

一些边缘情况可能会导致简单的实现失败。 如果`endWord`字典里没有，答案一定是`0`。 如果没有可能的链连接这两个单词，我们也返回`0`。 另一种微妙的情况是，当许多单词仅相差一个字母时，这可能会产生很大的分支因子，并使低效的邻居生成变得极其昂贵。 

## 方法

 ### 蛮力方法

 蛮力的想法是将问题明确建模为图表。 

我们将每个单词视为一个节点，并比较每一对单词以确定它们是否仅相差一个字符。 如果它们存在，我们就会用一条边将它们连接起来。 我们还必须包括`beginWord`在此图中。 

构建图表后，我们从以下位置开始运行 **广度优先搜索 (BFS)**`beginWord`。 由于 BFS 是逐级探索节点的，所以我们第一次遇到`endWord`，我们知道我们已经找到了最短的变换序列。 

这种方法是正确的，因为每条边都代表一个有效的变换，并且 BFS 保证了未加权图中的最短路径。 

然而，图的构建是昂贵的。 如果有`N`单词并且每个单词都有长度`L`，检查每一对需要：```
O(N² × L)
```为了`5000`话说，这变得太慢了。 

### 最优方法，带有模式映射的 BFS

 我们可以有效地生成邻居，而不是比较每对单词。 

关键的见解是，如果两个单词共享一个共同的中间模式，那么它们就会相差一个字母。 

例如：```
hot → *ot, h*t, ho*
dot → *ot, d*t, do*
lot → *ot, l*t, lo*
```请注意`"hot"`,`"dot"`， 和`"lot"`所有人都有相同的模式`*ot`，这意味着它们是一种不同的变换。 

我们预处理所有单词并将每个通配符模式映射到匹配的单词。 

例子：```
*ot → [hot, dot, lot]
h*t → [hot]
do* → [dot, dog]
```现在，我们可以使用这些模式有效地检索邻居，而不是在 BFS 期间检查每个单词。 

在每个 BFS 步骤：

 1. 为当前单词生成通配符模式。 
2. 使用模式图检索邻居。 
3.访问未处理的单词。 
4. 逐级继续，直到达到`endWord`。 

这极大地减少了邻居查找，并使 BFS 即使对于较大的字典也能保持高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N² × L) | O(N²) | 显式构建整个图 |
 | 最佳| O(N × L²) | O(N × L) | 使用通配符模式映射与 BFS |

 在哪里：

-`N`= 字数
 -`L`= 字长

 ## 算法演练

 ### 最优算法，带有通配符模式映射的 BFS

 1. **转换`wordList`进入集合并验证`endWord`存在**

 在进行任何工作之前，请检查是否`endWord`是在字典里面的。 如果缺失则返回`0`立即，因为有效的转换是不可能的。 
2. **构建通配符模式图**

 对于字典中的每个单词，通过一次替换一个字符来生成所有可能的通配符版本`'*'`。 

例子：```
hot → *ot, h*t, ho*
```将这些模式存储在哈希映射中：```
pattern → list of words
```这个预处理步骤使我们能够稍后有效地找到邻近的单词。 
3. **初始化BFS**

 创建一个队列，其中包含：```
(beginWord, 1)
```数量`1`表示变换序列的长度，因为`beginWord`其本身算作序列的一部分。 

还创建一个`visited`设置以避免重新访问单词和创建循环。 
4. **逐级处理队列**

 当队列不为空时：

 - 删除前面的词。 
- 如果匹配`endWord`，返回当前序列长度。 
- 为当前单词生成通配符模式。 
- 从模式图中检索邻近的单词。 
- 将看不见的邻居添加到具有距离的队列中`+1`。 
5. **将单词标记为立即访问**

 一旦单词进入队列，就将其标记为已访问。 

这可以防止重复处理并保证 BFS 首先探索最短路径。 
6. **返回`0`如果 BFS 结束**

 如果队列变空而没有到达`endWord`，不存在有效的变换。 

### 为什么它有效

 正确性依赖于**广度优先搜索**的核心属性。 

BFS 逐层探索节点。 每个 BFS 级别都表示使用相同数量的转换可到达的单词。 由于每个有效的转换都有相同的成本，所以我们第一次遇到`endWord`，它必须通过尽可能短的序列。 

通配符模式图保证我们有效地发现所有有效的相邻单词，而不会错过任何可能性。 

## Python 解决方案```python
from collections import defaultdict, deque
from typing import List

class Solution:
    def ladderLength(
        self,
        beginWord: str,
        endWord: str,
        wordList: List[str]
    ) -> int:
        if endWord not in wordList:
            return 0

        word_length = len(beginWord)

        pattern_map = defaultdict(list)

        for word in wordList:
            for i in range(word_length):
                pattern = word[:i] + "*" + word[i + 1:]
                pattern_map[pattern].append(word)

        queue = deque([(beginWord, 1)])
        visited = {beginWord}

        while queue:
            current_word, steps = queue.popleft()

            if current_word == endWord:
                return steps

            for i in range(word_length):
                pattern = (
                    current_word[:i]
                    + "*"
                    + current_word[i + 1:]
                )

                for neighbor in pattern_map[pattern]:
                    if neighbor not in visited:
                        visited.add(neighbor)
                        queue.append((neighbor, steps + 1))

                pattern_map[pattern] = []

        return 0
```实施以提前退出条件开始。 如果`endWord`字典中缺失，我们立即返回`0`。 

接下来，我们将字典预处理为通配符模式映射。 对于每个单词，我们创建所有可能的单字符通配符转换并将它们映射到原始单词。 

BFS 队列存储以下元组：```python
(current_word, sequence_length)
```这使我们能够跟踪到目前为止已经进行了多少次转换。 

这`visited`设置可以防止循环和重复工作。 我们在将单词放入队列后立即将其标记为已访问，以确保每个单词仅被处理一次。 

这里出现了一个有用的优化：```python
pattern_map[pattern] = []
```一旦通配符模式被处理，我们就清除它的邻居。 这避免了在未来的 BFS 步骤中重复遍历相同的邻接表并提高了效率。 

什么时候`endWord`遇到时，我们立即返回变换长度。 如果 BFS 完成后没有找到，则答案是`0`。 

## 解决方案```go
func ladderLength(beginWord string, endWord string, wordList []string) int {
	wordExists := false

	for _, word := range wordList {
		if word == endWord {
			wordExists = true
			break
		}
	}

	if !wordExists {
		return 0
	}

	wordLength := len(beginWord)

	patternMap := make(map[string][]string)

	for _, word := range wordList {
		for i := 0; i < wordLength; i++ {
			pattern := word[:i] + "*" + word[i+1:]
			patternMap[pattern] = append(
				patternMap[pattern],
				word,
			)
		}
	}

	type Pair struct {
		word  string
		steps int
	}

	queue := []Pair{
		{beginWord, 1},
	}

	visited := map[string]bool{
		beginWord: true,
	}

	for len(queue) > 0 {
		current := queue[0]
		queue = queue[1:]

		if current.word == endWord {
			return current.steps
		}

		for i := 0; i < wordLength; i++ {
			pattern := current.word[:i] +
				"*" +
				current.word[i+1:]

			neighbors := patternMap[pattern]

			for _, neighbor := range neighbors {
				if !visited[neighbor] {
					visited[neighbor] = true
					queue = append(queue, Pair{
						word:  neighbor,
						steps: current.steps + 1,
					})
				}
			}

			patternMap[pattern] = []string{}
		}
	}

	return 0
}
```Go 解决方案遵循与 Python 相同的算法结构，但使用 Go 原生数据结构。 

由于Go没有内置队列，因此使用切片来模拟BFS队列行为。 我们使用以下方法删除元素：```go
queue = queue[1:]
```这`visited`结构是使用以下方式实现的：```go
map[string]bool
```Go 字符串是不可变的，因此子字符串操作对于这个问题大小仍然是安全和高效的。 

这里不存在整数溢出问题，因为最大路径长度受字数限制，最多为`5000`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N × L²) | 每个单词都会生成`L`模式，每个模式创建成本`O(L)`|

 ## 边缘情况

 ###`endWord`字典中不存在

 这是最重要的边缘情况。 由于每个变换后的单词都必须属于`wordList`，达到`endWord`字典之外是不可能的。 

幼稚的实现可能仍然不必要地运行 BFS，浪费时间。 我们的实现在开始时明确检查此条件：```
if endWord not in wordList:
    return 0
```这保证了立即终止。 

### 不存在有效的转换路径

 即使`endWord`存在，可能没有链连接`beginWord`到它。 

例如：```
beginWord = "hit"
endWord = "cog"
wordList = ["hot","dot","tod","hog","cog"]
```图是不连通的，所以BFS最终穷尽所有可能性并返回`0`。 

Our implementation naturally handles this by finishing traversal and returning:```
0
```当队列变空时。 

### 许多类似的词导致过度的重新处理

 具有许多重叠模式的字典可能会导致重复的邻居扫描。 

例如：```
hot, dot, lot, pot, cot, got
```全部分享：```
*ot
```如果不进行优化，可能会为每个 BFS 节点重复扫描相同的邻接列表。 

我们的实现通过清除已处理的模式条目来避免这种低效率：```
pattern_map[pattern] = []
```这确保每个通配符组最多被遍历一次，从而显着提高密集图的性能。
