 **难度：** 🟡 中等
 **主题：** 堆栈、设计

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个自定义堆栈数据结构，其行为类似于普通堆栈，同时还支持称为`getMin()`。 此操作必须返回当前存储在堆栈中的最小值，并且必须在恒定时间内完成，`O(1)`。 

普通堆栈已经有效支持这些标准操作：

 -`push(val)`将一个元素插入到顶部
 -`pop()`删除顶部元素
 -`top()`返回顶部元素

 挑战在于添加`getMin()`同时为每个操作保持恒定的时间复杂度。 

LeetCode 中的输入表示为一系列方法调用。 例如：```
["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]
```这意味着：

 1. 新建一个`MinStack`2. 推`-2`3. 推`0`4. 推`-3`5. 检索最小值
 6.弹出顶部
 7. 检索顶部
 8. 再次检索最小值

 预期输出是：```
[null,null,null,null,-3,null,0,-2]
```约束条件很重要：

 - 最多`3 * 10^4`运营
 - 值的范围可以是`-2^31`到`2^31 - 1`-`pop`,`top`， 和`getMin`总是在非空堆栈上调用

 这些限制告诉我们效率很重要。 每次都扫描整个堆栈的解决方案`getMin()`在最坏的情况下被调用会变得太慢。 

一些边缘情况很重要：

 - 多个相同的最小值
 - 弹出当前最小值
 - 负数
 - 只有一个元素的堆栈
 - 交替按下和弹出，经常改变最小值

 该问题保证了永远不会发生无效操作，因此我们不需要处理从空堆栈中弹出的问题。 

## 方法

 ### 蛮力方法

 最简单的实现使用单个堆栈。 

-`push()`附加值
 -`pop()`删除最后一个值
 -`top()`返回最后一个值
 -`getMin()`扫描整个堆栈并返回最小的元素

 这种方法是正确的，因为扫描每个元素总是能找到真正的最小值。 然而，该问题特别需要恒定时间操作。 扫描堆栈需要`O(n)`时间，违反了要求。 

如果有很多`getMin()`在大堆栈上调用，性能变得低效。 

### 最佳方法

 关键的见解是我们不应该重复重新计算最小值。 相反，我们应该在每个过程中存储足够的信息`push()`操作，以便最小值始终立即可用。 

一种常见的技术是维护第二个堆栈，称为`min_stack`。 

- 主堆栈存储所有值
 - 最小堆栈存储迄今为止在每个深度看到的最小值

 对于每次推送：

 - 将值压入主堆栈
 - 将新的最小值推入最小堆栈

 对于每个流行音乐：

 - 从两个堆栈中弹出

 这可以确保：

 - 主堆栈的顶部始终是当前顶部元素
 - 最小堆栈的顶部始终是当前最小值

 每一次操作都变成`O(1)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`push/pop/top: O(1)`,`getMin: O(n)`|`O(n)`| 使用一个堆栈并扫描最小 |
 | 最佳|`O(1)`对于所有操作|`O(n)`| 使用额外的堆栈来跟踪最小值 |

 ## 算法演练

 1. 初始化两个堆栈。 

第一个堆栈通常存储所有压入的值。 第二堆栈存储每个堆栈深度对应的最小值。 
2. 期间`push(val)`：

推`val`到主堆栈上。 

然后确定新的最小值：

 - 如果最小堆栈为空，`val`变为最小值
 - 否则，比较`val`以当前最小值
 - 将较小的值推入最小堆栈

 这保证了最小堆栈的顶部始终代表该时刻堆栈的最小值。 
3.期间`pop()`:

 从两个堆栈中删除顶部元素。 

由于两个堆栈始终具有相同的大小，因此从两个堆栈中删除可以使它们保持同步。 
4.期间`top()`:

 返回主堆栈中的最后一个元素。 
5.期间`getMin()`:

 返回最小堆栈中的最后一个元素。 

由于最小堆栈存储每个深度的最小值，因此此操作是恒定时间。 

### 为什么它有效

 核心不变量是：

 > 在每个堆栈深度`i`,`min_stack[i]`存储所有元素中的最小值`stack[0:i+1]`。 

因为在每次压入和弹出过程中都会保持这个不变量，所以最小堆栈的顶部始终代表整个堆栈的当前最小元素。 

## Python 解决方案```python
class MinStack:

    def __init__(self):
        self.stack = []
        self.min_stack = []

    def push(self, val: int) -> None:
        self.stack.append(val)

        if not self.min_stack:
            self.min_stack.append(val)
        else:
            current_min = self.min_stack[-1]
            self.min_stack.append(min(val, current_min))

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]

# Your MinStack object will be instantiated and called as such:
# obj = MinStack()
# obj.push(val)
# obj.pop()
# param_3 = obj.top()
# param_4 = obj.getMin()
```该实现使用两个 Python 列表作为堆栈。`self.stack`存储用户推送的实际元素。`self.min_stack`存储每个堆栈位置对应的最小值。 这意味着两个堆栈始终具有相同的长度。 

里面`push()`，我们首先将值追加到主堆栈中。 然后我们将新值与当前最小值进行比较。 较小的值附加到`min_stack`。 

里面`pop()`，两个堆栈一起删除其顶部元素，以便它们保持同步。`top()`简单地返回主堆栈的最后一个元素。`getMin()`返回最小堆栈的最后一个元素，该元素始终是堆栈中当前存在的最小值。 

## 解决方案```go
type MinStack struct {
	stack    []int
	minStack []int
}

func Constructor() MinStack {
	return MinStack{
		stack:    []int{},
		minStack: []int{},
	}
}

func (this *MinStack) Push(val int) {
	this.stack = append(this.stack, val)

	if len(this.minStack) == 0 {
		this.minStack = append(this.minStack, val)
	} else {
		currentMin := this.minStack[len(this.minStack)-1]

		if val < currentMin {
			this.minStack = append(this.minStack, val)
		} else {
			this.minStack = append(this.minStack, currentMin)
		}
	}
}

func (this *MinStack) Pop() {
	this.stack = this.stack[:len(this.stack)-1]
	this.minStack = this.minStack[:len(this.minStack)-1]
}

func (this *MinStack) Top() int {
	return this.stack[len(this.stack)-1]
}

func (this *MinStack) GetMin() int {
	return this.minStack[len(this.minStack)-1]
}

/**
 * Your MinStack object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Push(val);
 * obj.Pop();
 * param_3 := obj.Top();
 * param_4 := obj.GetMin();
 */
```Go 解决方案遵循与 Python 版本相同的逻辑，但使用切片而不是 Python 列表。 

Go 中从堆栈中弹出是通过切片完成的：```go
stack = stack[:len(stack)-1]
```与Python不同，Go不提供内置的堆栈操作，因此切片通常用于有效地模拟堆栈。 

这些约束保证了有效的操作，因此不需要额外的空堆栈检查。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(1)`| 每个操作仅使用直接堆栈访问 |
 | 空间|`O(n)`| 两个堆栈最多可存储`n`元素|

 ## 边缘情况

 ### 重复最小值

 当最小值多次出现时，就会出现一个微妙的问题。 

例如：```
push(2)
push(1)
push(1)
```如果我们只跟踪唯一的最小值，则弹出一个`1`可能会错误地删除最小值，即使另一个`1`仍然存在。 

该实现通过在每个堆栈深度存储最小值来避免此问题。 每次推送都会再次记录当前最小值，即使它没有变化。 

### 突破当前最小值

 当顶部元素也是当前最小值时，会出现另一个常见的错误来源。 

例如：```
push(3)
push(2)
push(1)
pop()
```移除后`1`，最小值应恢复为`2`。 

由于最小堆栈存储每个深度的历史最小值，因此删除顶部会自动正确恢复之前的最小值。 

### 负数和整数限制

 约束允许值小至`-2^31`和一样大`2^31 - 1`。 

某些实现意外地仅假设正数或使用不正确的比较。 

此解决方案适用于所有有效整数值，因为它仅依赖于标准整数比较，并且不执行可能溢出的算术运算。
