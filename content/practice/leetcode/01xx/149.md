[LeetCode 第 149 题](https://leetcode.com/problems/max-points-on-a-line/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、数学、几何

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二维坐标平面上的点列表。 每个点都表示为`[x, y]`， 在哪里`x`和`y`是整数坐标。 我们的任务是确定位于同一条直线上的最大点数。 

换句话说，在使用给定的点可以形成的所有可能的直线中，我们想要找到通过最多点的直线。 

例如，如果点是：```
[[1,1],[2,2],[3,3]]
```所有三个点都在线上`y = x`，所以答案是`3`。 

输入尺寸比较小，最多`300`点，但挑战来自于正确识别多个点何时共线。 浮点运算很容易引入精度误差，特别是在处理像这样的斜率时`1/3`或者`2/6`。 因此，稳健的解决方案必须仔细地表示斜率。 

这些约束还保证所有点都是唯一的。 这简化了实现，因为我们永远不需要处理占据完全相同坐标的重复点。 

一些边缘情况很重要：

 - 垂直线，其中`x2 - x1 = 0`，如果使用除法处理，则会产生未定义的斜率。 
- 水平线，坡度所在的位置`0`，必须一致地表示。 
- 负斜率必须正确标准化，以便等效斜率映射到相同的表示。 
- 多个点可能会产生数学上等效的斜率，例如`2/4`和`1/2`，因此使用 GCD 进行归约是必要的。 
- 非常小的输入，例如单个点，仍然必须返回有效的答案。 

## 方法

 ### 蛮力方法

 一种直接的方法是检查每对可能的点并确定哪些其他点位于同一条线上。 

对于每对`(i, j)`，我们可以计算穿过它们的线。 然后我们迭代所有剩余的点并检查每个点是否位于该线上。 

检查共线性的一种方法是使用面积公式：```
(x2 - x1)(y3 - y1) == (y2 - y1)(x3 - x1)
```如果这个等式成立，则这三个点共线。 

这种方法是正确的，因为每条有效线都由至少两个点确定，并且我们根据每条可能的线明确验证每个点。 

然而，复杂性变得非常大：

 - 有`O(n^2)`点对。 
- 对于每一对，我们可能会扫描所有`n`点。 

这导致`O(n^3)`时间复杂度，这变得低效`n = 300`。 

### 最佳方法

 关键的见解是，如果我们固定一个点作为锚点，那么每个其他点都会确定相对于该锚点的斜率。 

相对于锚点具有相同斜率的点必须位于同一条线上。 

例如，假设锚点是`(1,1)`：

 | 其他点| 坡度|
 | --- | --- |
 | (2,2) | 1 |
 | (3,3) | 1 |
 | (4,5) | 4/3 |

 前两个点具有相同的斜率，这意味着所有三个点共线。 

我们没有明确检查每个三元组，而是：

 1.固定锚点。 
2. 计算每隔一个点的斜率。 
3. 计算每个斜率出现的次数。 
4. 最常见的斜率代表通过该锚点的最大线。 

为了避免浮点精度问题，斜率存储为约化分数：```
dy / dx
```使用最大公约数减少。 

这将问题转化为哈希图频率计数问题。

 | 方法| 时间复杂度| 空间复杂度| 笔记|

 ## 算法演练

 1. 立即处理小输入。 

如果点数是`0`,`1`， 或者`2`，答案只是点数，因为任何最多两个点的集合总是共线的。 
2. 迭代每个点作为锚点。 

对于每一点`points[i]`，我们将计算从该锚点到所有后续点的斜率。 
3. 创建斜率频率的哈希图。 

关键思想是相对于锚点位于同一条线上的点具有相同的斜率。 

哈希映射存储：```
slope -> count
```4. 计算归一化斜率表示。 

就两点来说：```
(x1, y1)
(x2, y2)
```计算：```
dx = x2 - x1
dy = y2 - y1
```然后使用最大公约数来减少两者：```
gcd_value = gcd(dx, dy)
dx /= gcd_value
dy /= gcd_value
```5. 一致地标准化符号。 

斜坡如：```
(-1, -1)
```和```
(1, 1)
```代表同一个方向。 

我们通过强制确保一致性`dx`尽可能保持积极的态度。 
6. 将斜率存储在哈希图中。 

减少的对`(dy, dx)`成为哈希映射键。 

每次我们再次遇到相同的斜率时，我们都会增加其频率。 
7. 跟踪穿过锚点的最大线。 

斜率的最大频率表示有多少点与同一直线上的锚点对齐。 

由于锚点本身不包含在计数中，因此该线上的总点数为：```
frequency + 1
```8. 更新全局最大值。 

对每个锚点重复该过程并保持整体最佳结果。 

### 为什么它有效

 直线由点和斜率唯一确定。 当我们固定一个锚点时，同一直线上的每个点都必须相对于该锚点产生相同的斜率。 通过根据斜率对点进行分组，我们有效地将所有共线点分组在一起。 由于在迭代过程中每条可能的直线都必须经过至少一个锚点，因此算法最终会发现最大共线集。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
from math import gcd

class Solution:
    def maxPoints(self, points: List[List[int]]) -> int:
        n = len(points)

        if n <= 2:
            return n

        max_points = 1

        for i in range(n):
            slopes = defaultdict(int)

            x1, y1 = points[i]

            current_max = 0

            for j in range(i + 1, n):
                x2, y2 = points[j]

                dx = x2 - x1
                dy = y2 - y1

                divisor = gcd(dx, dy)

                dx //= divisor
                dy //= divisor

                # Normalize sign
                if dx < 0:
                    dx *= -1
                    dy *= -1
                elif dx == 0:
                    dy = 1
                elif dy == 0:
                    dx = 1

                slope = (dy, dx)

                slopes[slope] += 1

                current_max = max(current_max, slopes[slope])

            max_points = max(max_points, current_max + 1)

        return max_points
```实现首先处理点数最多为 2 的简单情况。 

外循环选择每个点作为锚点。 对于每个锚点，我们创建一个新的哈希图来计算斜率频率。 

对于每个其他点，我们计算方向向量`(dy, dx)`。 然后我们使用以下方法减少向量`gcd`因此数学上等效的斜率成为相同的哈希映射键。 

例如：```python
(2, 4) -> (1, 2)
(3, 6) -> (1, 2)
```两者代表缩减后相同的斜率。 

归一化步骤确保所有等效斜率共享完全相同的表示。 这对于垂直线和水平线尤其重要。 

哈希图跟踪有多少个点共享每个斜率。 当前锚点的最大斜率频率决定通过该锚点的最大线。 

最后，我们更新全局最大答案。 

## 解决方案```go
package main

func gcd(a, b int) int {
	if b == 0 {
		if a < 0 {
			return -a
		}
		return a
	}
	return gcd(b, a%b)
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func maxPoints(points [][]int) int {
	n := len(points)

	if n <= 2 {
		return n
	}

	result := 1

	for i := 0; i < n; i++ {
		slopes := make(map[[2]int]int)

		x1, y1 := points[i][0], points[i][1]

		currentMax := 0

		for j := i + 1; j < n; j++ {
			x2, y2 := points[j][0], points[j][1]

			dx := x2 - x1
			dy := y2 - y1

			divisor := gcd(dx, dy)

			dx /= divisor
			dy /= divisor

			// Normalize sign
			if dx < 0 {
				dx *= -1
				dy *= -1
			} else if dx == 0 {
				dy = 1
			} else if dy == 0 {
				dx = 1
			}

			slope := [2]int{dy, dx}

			slopes[slope]++

			currentMax = max(currentMax, slopes[slope])
		}

		result = max(result, currentMax+1)
	}

	return result
}
```Go 解决方案遵循与 Python 版本相同的算法结构。 主要的实现差异是 Go 不支持元组作为哈希映射键，因此我们使用固定大小的数组：```go
[2]int{dy, dx}
```作为地图键。 

Go 还需要显式的辅助函数`gcd`和`max`。 

由于所有坐标都适合标准整数范围，因此整数溢出在这里不是问题。

 ## 边缘情况

 ### 垂直线

 垂直线是最常见的错误来源之一，因为斜率公式涉及除以`dx`。 什么时候`dx = 0`，浮点斜率计算会产生被零除的错误。 

这种实现完全避免了划分。 相反，斜率表示为简化的整数对`(dy, dx)`。 所有垂直线均归一化为相同的表示形式：```
(1, 0)
```这保证了哈希的一致性。 

### 不同表示的等效斜率

 不同的点对可以产生数学上相同的斜率：```
2/4
1/2
3/6
```使用 raw 的简单实现`(dy, dx)`配对会错误地将它们视为不同的斜率。 

该算法通过在将两个值存储在哈希映射之前将它们除以它们的最大公约数来解决这个问题。 

### 负方向向量

 同一条线可以用相反的方向向量出现：```
(1,1)
(-1,-1)
```如果没有标准化，这些将成为不同的哈希映射键，即使它们代表相同的斜率。 

该实现通过强制解决了这个问题`dx`尽可能保持积极的态度。 这确保了每个斜率都有独特的规范表示。
