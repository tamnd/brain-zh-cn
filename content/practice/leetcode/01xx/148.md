 ## 解决方案

 ## 问题理解

 该问题要求我们按升序对单链表进行排序并返回排序后的列表的头部。 

输入是链表的头节点。 每个节点包含一个整数值和一个指向下一个节点的指针。 与数组不同，链表不支持直接索引，因此随机访问等操作的成本很高。 这个细节强烈影响排序算法的实用性。 

输出必须是另一个包含相同节点的链表，但排列后节点值按非降序排列。 

约束条件很重要：

 - 该列表最多可以包含`5 * 10^4`节点。 
- 节点值范围为`-10^5`到`10^5`。 

一个天真的`O(n^2)`冒泡排序或插入排序等排序算法可能会传递较小的输入，但对于包含数万个节点的列表来说，它会变得太慢。 后续要求明确要求`O(n log n)`具有恒定辅助内存的解决方案，这强烈暗示了合并排序。 

一些边缘情况很重要：

 - 列表可能为空。 
- 该列表可能只包含一个节点。 
- 列表可能已经排序。 
- 列表可以反向排序。 
- 该列表可能包含重复值。 
- 该列表可能包含负数。 

由于该结构是一个链表，因此需要仔细处理指针以避免循环、丢失节点或断开的链接。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将所有节点值复制到一个数组中，对数组进行排序，然后重建或覆盖链表。 

该算法的工作原理如下：

 1. 遍历链表并将所有值存储在数组中。 
2. 使用内置排序算法对数组进行排序。 
3. 再次遍历链表，并使用排序后的数组覆盖节点值。 

这会产生正确的结果，因为对数组进行排序可保证值按升序排列。 

然而，这种方法使用与列表大小成比例的额外内存。 后续特别要求恒定的额外空间，因此这种方法不能满足最优要求。 

另一种强力的可能性是直接在链表上进行冒泡排序，但这需要`O(n^2)`时间对于大输入来说变得太慢。 

### 最佳方法

 关键的见解是合并排序在链表上表现得非常好。 

归并排序将列表分为两半，对每一半进行递归排序，然后将已排序的两半合并在一起。 

这种方法非常适合链表，因为：

 - 使用慢指针和快指针可以有效地分割链表。 
- 合并两个已排序的链表可以在线性时间内完成，无需额外的数组。 
- 合并排序保证`O(n log n)`时间复杂度。 

与数组不同，链表不支持高效的随机访问，因此像快速排序或堆排序这样的算法不太合适。 归并排序自然地适合链表的顺序结构。

 ## 算法演练

 ### 最优归并排序算法

 1. 处理基本情况。 

如果列表为空或仅包含一个节点，则它已排序。 立即返回头部。 
2. 将链表分成两半。 

使用两个指针：

 -`slow`一次移动一步。 
-`fast`一次移动两步。 

什么时候`fast`到达终点，`slow`将接近中间。 

跟踪之前的节点`slow`因此该列表可以分成两个单独的半部分。 
3. 递归地对左半部分进行排序。 

称呼`sortList`在列表的前半部分。 
4. 递归地对右半部分进行排序。 

称呼`sortList`在列表的后半部分。 
5. 合并已排序的两半。 

使用标准链表合并过程：

 - 比较两个列表中的当前节点。 
- 将较小的节点附加到结果中。 
- 在所选列表中向前移动。 
- 继续，直到用完一个列表。 
- 连接剩余的节点。 
6. 返回合并后的排序列表。 

合并的列表是完全排序的，因为两半列表在合并之前已经递归排序。 

### 为什么它有效

 合并排序之所以有效，是因为分而治之的原则。 

在每个递归级别：

 - 该列表被分成更小的子列表。 
- 最终，每个子列表包含一个节点，该节点是普通排序的。 
- 合并步骤将两个已排序的列表合并为一个更大的排序列表。 

合并操作保留排序顺序，因为它始终从两个输入列表中选择最小的可用元素。 

由于每个级别都处理所有`n`节点并且有`log n`递归级别，总运行时间为`O(n log n)`。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def sortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return head

        # Split the list into two halves
        slow = head
        fast = head
        prev = None

        while fast and fast.next:
            prev = slow
            slow = slow.next
            fast = fast.next.next

        # Disconnect the left half from the right half
        prev.next = None

        # Recursively sort both halves
        left_sorted = self.sortList(head)
        right_sorted = self.sortList(slow)

        # Merge the sorted halves
        return self.merge(left_sorted, right_sorted)

    def merge(
        self,
        list1: Optional[ListNode],
        list2: Optional[ListNode]
    ) -> Optional[ListNode]:

        dummy = ListNode(0)
        current = dummy

        while list1 and list2:
            if list1.val <= list2.val:
                current.next = list1
                list1 = list1.next
            else:
                current.next = list2
                list2 = list2.next

            current = current.next

        if list1:
            current.next = list1
        else:
            current.next = list2

        return dummy.next
```实施从基本案例开始。 如果列表为空或只有一个节点，则它已经排序。 

慢指针和快指针技术标识列表的中点。 这`prev`指针跟踪之前的节点`slow`，允许列表被干净地分成两半。 

分割后，该函数递归地对两半进行排序。 因为递归一直持续到到达单个节点列表，所以每个递归调用最终都会返回一个排序的子列表。 

这`merge`辅助函数组合了两个排序的链表。 虚拟节点通过为合并结果提供稳定的起点来简化指针处理。 

合并逻辑重复选择两个列表之间较小的当前节点。 一旦一个列表耗尽，则直接附加另一个列表中的剩余节点。 

最后，返回合并后的排序列表。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */

func sortList(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head
    }

    // Split the list into two halves
    slow := head
    fast := head
    var prev *ListNode

    for fast != nil && fast.Next != nil {
        prev = slow
        slow = slow.Next
        fast = fast.Next.Next
    }

    // Disconnect the left half
    prev.Next = nil

    // Recursively sort both halves
    leftSorted := sortList(head)
    rightSorted := sortList(slow)

    // Merge sorted halves
    return merge(leftSorted, rightSorted)
}

func merge(list1 *ListNode, list2 *ListNode) *ListNode {
    dummy := &ListNode{}
    current := dummy

    for list1 != nil && list2 != nil {
        if list1.Val <= list2.Val {
            current.Next = list1
            list1 = list1.Next
        } else {
            current.Next = list2
            list2 = list2.Next
        }

        current = current.Next
    }

    if list1 != nil {
        current.Next = list1
    } else {
        current.Next = list2
    }

    return dummy.Next
}
```Go 实现遵循与 Python 版本相同的算法结构。 

Go 使用`nil`而不是`None`对于空指针。 虚拟节点是使用创建的`&ListNode{}`。 递归函数调用很自然地工作，因为链表是基于指针的结构。 

一个重要的细节是使用以下命令显式断开左半部分的连接：`prev.Next = nil`。 如果没有此步骤，递归将无限继续，因为两个递归调用仍将引用列表的重叠部分。

 ## 边缘情况

 ### 空列表

 空链表表示为`head = None`。 这种情况如果不及早处理，很容易导致空指针错误。 该实现在函数开头检查空列表并立即返回`head`。 

### 单节点列表

 仅包含一个节点的列表已排序。 如果没有基本情况，递归将不必要地继续，并可能导致不正确的分割行为。 条件`if not head or not head.next`正确停止单节点列表的递归。 

### 重复值

 具有重复值的列表可能会暴露合并逻辑中的问题，特别是在不仔细处理比较的情况下。 实现使用`<=`在合并期间，这会保留正确的顺序并确保包含所有重复值。 

### 反向排序列表

 反向排序列表代表最无序的可能输入之一。 一些简单的排序算法在这种模式上表现不佳。 归并排序仍然保证`O(n log n)`性能，因为它的运行时仅取决于递归拆分和合并，而不是初始排序。 

### 奇数长度列表

 具有奇数个节点的列表可能会产生不均匀的分割。 慢速和快速指针方法自然地通过将额外的节点放入一半来处理这个问题。 递归排序仍然可以正常工作，因为每一半最终都会到达基本情况。
