 ## 解决方案

 ## 问题理解

 这个问题要求我们编写一个 SQL 函数，返回`nth`最高的不同工资`Employee`桌子。 

该表包含两列：

 | 专栏 | 意义|
 | --- | --- |
 |`id`| 唯一的员工标识符 |
 |`salary`| 员工薪资|

 关键细节是薪水必须**不同**。 多名员工可以享有相同的工资，但在确定排名时，重复的工资值只应计算一次。 

例如，假设工资是：```
100, 200, 200, 300
```不同的薪资是：```
300, 200, 100
```第二高的不同工资是`200`，不是按排序顺序的第二行。 

该问题还要求如果少于`n`不同的工资，该函数必须返回`null`。 

这很重要，因为简单的解决方案只是对行进行排序并选择`n`当存在重复项时，第 3 行将失败。 

预期的输出格式是一个名为：的单列：```
getNthHighestSalary(n)
```在哪里`n`是输入参数。 

由于这是一个数据库问题，因此挑战不在于手动实现循环或数据结构，而在于正确使用 SQL 操作，例如：

 -`DISTINCT`- 排序
 -`LIMIT`-`OFFSET`- 子查询

 最重要的边缘情况是：

 1.重复工资

 多名员工可以享有相同的工资，但重复的员工只算一次。 
2. 少于`n`不同的工资

 结果一定是`null`。 
3.只有一行的表

 如果`n > 1`，答案应该还是`null`。 
4.非连续薪资值

 排名基于顺序，而不是数字差距。 
5. 大数据集

 高效的过滤和排序变得很重要。 

## 方法

 ### 蛮力方法

 暴力解决方案将检索所有工资，按降序对它们进行排序，手动删除重复项，然后选择`n`th 值。 

从概念上讲，该过程如下所示：

 1. 从表中取出每笔工资。 
2. 对所有工资进行降序排序。 
3. 删除重复的薪资值。 
4.返回索引处的工资`n - 1`。 
5. 返回`null`如果该索引不存在。 

这种方法之所以有效，是因为排序保证了正确的排名顺序，而重复删除则确保只计算不同的工资。 

然而，这种方法效率低下，因为它处理的数据多于必要的数据。 如果在数据库引擎外部实现，则需要将所有行传输到应用程序内存中并手动执行额外的工作。 

### 最佳方法

 更好的解决方案直接利用 SQL。 

关键的见解是 SQL 已经提供了以下操作：

 - 删除重复项`DISTINCT`- 排序与`ORDER BY`- 选择特定的排名行`LIMIT`和`OFFSET`删除重复的工资并将其降序排序后，`nth`最高薪水就是职位所在的行`n - 1`。 

例如：```
Distinct salaries descending:
300
200
100
```如果`n = 2`，我们跳过一行（`OFFSET 1`）并采取下一行（`LIMIT 1`）。 

如果该位置不存在行，SQL 会自动返回`NULL`。

 ## 算法演练

 ### 最优 SQL 算法

 1. 从以下列表中选择所有不同的薪资值`Employee`桌子。 

此步骤是必要的，因为重复的工资在排名中只计算一次。 
2. 将不同的工资按降序排列。 

按降序排列，薪水最高的排在前面，第二高的排在后面，依此类推。 
3. 跳过第一个`n - 1`行使用`OFFSET`。 

由于索引从零开始，`nth`跳级后出现最高薪水`n - 1`条目。 
4. 使用以下命令精确检索一行`LIMIT 1`。 

这确保只返回目标工资。 
5. 将查询包装在另一个查询中`SELECT`。 

这允许结果列匹配所需的输出名称：```sql
getNthHighestSalary(n)
```6. 如果偏移量之后不存在行，SQL 返回`NULL`。 

这自然可以处理少于的边缘情况`n`不同的工资。 

### 为什么它有效

 该算法之所以有效，是因为：

 -`DISTINCT`保证薪资独一无二
 -`ORDER BY salary DESC`保证正确的排名顺序
 -`OFFSET n - 1`将查询定位在所请求的确切排名上
 -`LIMIT 1`只返回期望的工资

 这些操作一起精确地实现了`nth`最高的独特工资。 

## Python 解决方案

 虽然这是 LeetCode 上的 SQL 问题，但该平台需要 MySQL 函数。 下面是准确的 LeetCode 可提交的 SQL 解决方案。```python
CREATE FUNCTION getNthHighestSalary(N INT) RETURNS INT
BEGIN
  RETURN (
      SELECT DISTINCT salary
      FROM Employee
      ORDER BY salary DESC
      LIMIT 1 OFFSET N - 1
  );
END
```该函数接受一个整数`N`代表要检索的排名。 

函数内部：

 -`SELECT DISTINCT salary`删除重复的工资
 -`ORDER BY salary DESC`将工资从最高到最低排序
 -`OFFSET N - 1`跳过第一个`N - 1`工资
 -`LIMIT 1`准确检索一份薪水

 如果偏移量超出可用行，MySQL会自动返回`NULL`，满足问题要求。 

## 解决方案

 由于这是一个数据库问题，Go 不适用于传统 LeetCode 意义上的问题。 正确的提交语言是SQL。 然而，从概念上讲，Go 中的相同逻辑如下所示：```go
package main

import (
	"sort"
)

func getNthHighestSalary(salaries []int, n int) *int {
	distinctMap := make(map[int]bool)

	for _, salary := range salaries {
		distinctMap[salary] = true
	}

	distinctSalaries := []int{}

	for salary := range distinctMap {
		distinctSalaries = append(distinctSalaries, salary)
	}

	sort.Sort(sort.Reverse(sort.IntSlice(distinctSalaries)))

	if n > len(distinctSalaries) {
		return nil
	}

	result := distinctSalaries[n-1]
	return &result
}
```Go 实现镜像了 SQL 逻辑：

 - 地图删除重复的工资
 - 不同的工资按降序排列
 - 的`n - 1`返回索引值
 -`nil`代表没有有效答案

 与 SQL 不同，Go 需要显式处理重复删除和可为空性。

 ## 边缘情况

 ### 重复工资

 一个常见的错误是将重复的工资行视为单独的排名。 例如：```
100, 200, 200, 300
```第二高的独特薪资仍然是`200`，不是排序后的第二行。 

该实现通过使用避免了这个错误`DISTINCT`，确保每个薪资值在排名前只出现一次。 

### 少于 N 个不同的薪水

 如果表中包含的不同工资少于要求的工资，则答案必须是`NULL`。 

例如：```
Salaries: 100
n = 2
```应用偏移后，不会保留任何行。 SQL自然返回`NULL`，因此不需要额外的逻辑。 

### 所有工资相同

 当每个员工的工资相同时：```
100, 100, 100
```只有一种独特的薪水。 

幼稚的实现可能会错误地计算重复项，并认为存在第二高的薪水。 使用`DISTINCT`保证只有独特的薪资值参与排名。 

### 非连续薪资值

 薪资排名取决于顺序，而不是算术差距。 

例如：```
1000, 750, 500
```第二高的工资是`750`，无论值之间的数字距离如何。 

降序排序可以正确处理这种情况，无需任何特殊逻辑。
