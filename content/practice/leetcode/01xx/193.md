 **难度：** 🟢简单
 **主题：** 外壳

 ## 解决方案

 ## 问题理解

 该问题要求我们处理一个名为`file.txt`并仅打印与两种有效格式之一匹配的电话号码。 

有效格式为：```
xxx-xxx-xxxx
```和```
(xxx) xxx-xxxx
```在这两种格式中，每个`x`代表一个数字`0`到`9`。 

任务不是转换输入或提取部分匹配。 相反，我们必须验证整行。 仅当整行与所需的电话号码模式之一完全匹配时才应打印该行。 

输入是一个纯文本文件，其中每一行包含一个字符串。 有些行可能包含有效的电话号码，而其他行可能包含无效的格式。 输出应仅包含有效行，并按其显示的样子打印。 

一个非常重要的细节是该问题保证任何行上都没有前导或尾随空格。 这简化了验证，因为我们不需要在检查格式之前修剪空格。 

核心挑战是有效识别结构化文本模式。 由于这是一个 Shell 问题，因此预期的解决方案将正则表达式与标准 Unix 文本处理工具（例如`grep`,`awk`， 或者`sed`。 

一些边缘情况很重要：

 - 必须拒绝在有效模式之前或之后包含额外字符的行。 
- 间距不正确的行必须被拒绝。 
- 缺少括号或连字符放错位置的行必须被拒绝。 
- 包含字母而不是数字的行必须被拒绝。 
- 不应打印部分匹配有效格式的行。 

例如：```
123-456-7890abc
```无效，因为该行在电话号码后面包含额外字符。 

相似地：```
(123)-456-7890
```无效，因为右括号后缺少所需的空格。 

## 方法

 ### 蛮力方法

 强力解决方案将手动逐字符解析每一行，并验证它是否与两种允许的格式之一匹配。 

例如，对于格式`xxx-xxx-xxxx`，我们可以：

 - 检查字符串长度是否正好为 12
 - 验证位置 3 和 7 处的字符是否为连字符
 - 验证所有剩余字符都是数字

 同样，对于`(xxx) xxx-xxxx`，我们可以：

 - 检查字符串长度是否正好为 14
 - 验证括号、空格和连字符的准确位置
 - 验证所有数字位置是否包含数字

 这种方法之所以有效，是因为格式是固定的且很小。 每行都可以被确定性地验证。 

然而，这种方法很冗长并且容易出错。 手动字符检查变得乏味，尤其是当文本模式匹配正是正则表达式的设计目的时。 

### 最佳方法

 更好的解决方案是使用正则表达式。 

正则表达式使我们能够紧凑而准确地描述这两种有效格式。 由于问题本质上是模式匹配，因此正则表达式是自然的工具。 

关键的见解是两种有效格式都是固定模板：

 -`xxx-xxx-xxxx`-`(xxx) xxx-xxxx`我们可以直接在正则表达式中对它们进行编码：```
^(\([0-9]{3}\) [0-9]{3}-[0-9]{4}|[0-9]{3}-[0-9]{3}-[0-9]{4})$
```该表达式确保：

 -`^`标记行的开头
 -`$`标记行尾
 -`[0-9]{3}`正好表示三位数字
 -`[0-9]{4}`正好表示四位数字
 -`⟦PROTECT_18⟧`匹配文字括号
 - 的`|`运算符允许任一有效格式

 使用`grep`使用这个正则表达式给出了一个简洁高效的单行解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m) | O(1) | O(1) | 手动检查每行中的每个字符 |
 | 最佳| O(n × m) | O(1) | O(1) | 使用正则表达式模式与 grep | 匹配

 这里：

-`n`是行数
 -`m`是最大线长度

 ## 算法演练

 1. 逐行读取输入文件。 每一行代表一个可能的候选电话号码。 
2. 对于每一行，将其与描述两种有效电话号码格式的正则表达式模式进行比较。 
3.使用行首锚点`^`以确保匹配从第一个字符开始。 
4.使用线尾锚点`$`以确保匹配在最后一个字符处结束。 这可以防止部分匹配。 
5. 定义第一个有效格式：```
[0-9]{3}-[0-9]{3}-[0-9]{4}
```这匹配三个数字、一个连字符、三个数字、另一个连字符和四个数字。 
6. 定义第二个有效格式：```
\([0-9]{3}\) [0-9]{3}-[0-9]{4}
```这匹配：

 - 左括号
 - 三位数
 - 右括号
 - 一个空间
 - 三位数
 - 连字符
 - 四位数字
 7. 使用交替运算符组合两种格式`|`。 
8. 仅打印与图案完全匹配的线条。 

## Python 解决方案

 尽管这是一个 Shell 问题，但下面是一个等效的 Python 实现，它使用正则表达式验证电话号码。```python
import re
from typing import List

class Solution:
    def validPhoneNumbers(self, phone_numbers: List[str]) -> List[str]:
        pattern = re.compile(
            r"^(\(\d{3}\) \d{3}-\d{4}|\d{3}-\d{3}-\d{4})$"
        )

        valid_numbers = []

        for number in phone_numbers:
            if pattern.match(number):
                valid_numbers.append(number)

        return valid_numbers
```实现从编译正则表达式模式开始。 编译一次正则表达式比为每一行重复重新创建它更有效。 

该模式包含两种选择：

 -`⟦PROTECT_19⟧ \d{3}-\d{4}`-`\d{3}-\d{3}-\d{4}`锚点`^`和`$`保证整个字符串必须完全匹配。 

然后该算法会迭代每个电话号码。 如果正则表达式匹配，则该数字将附加到结果列表中。 

最后，返回有效电话号码列表。 

对于实际的 LeetCode Shell 提交，预期的一行是：```python
grep -E '^(\([0-9]{3}\) [0-9]{3}-[0-9]{4}|[0-9]{3}-[0-9]{3}-[0-9]{4})$' file.txt
```## 解决方案```go
package main

import (
	"regexp"
)

type Solution struct{}

func (s Solution) ValidPhoneNumbers(phoneNumbers []string) []string {
	pattern := regexp.MustCompile(`^(\([0-9]{3}\) [0-9]{3}-[0-9]{4}|[0-9]{3}-[0-9]{3}-[0-9]{4})$`)

	var validNumbers []string

	for _, number := range phoneNumbers {
		if pattern.MatchString(number) {
			validNumbers = append(validNumbers, number)
		}
	}

	return validNumbers
}
```Go 解决方案与 Python 版本非常相似。 这`regexp`包通过以下方式提供正则表达式支持`MustCompile`。 

Go 切片用于动态存储有效的电话号码。 与 Python 列表不同，切片需要通过内置的显式追加操作`append`功能。 

这个问题不存在整数溢出问题，因为我们只处理字符串。

## 边缘情况

 ### 带有额外字符的行

 一个常见的错误是允许部分匹配。 

例如：```
123-456-7890abc
```一个天真的正则表达式没有`^`和`$`可能会错误地接受此行，因为有效的电话号码出现在开头。 

该实现通过将正则表达式锚定到行的开头和结尾来防止这种情况。 

### 括号位置不正确

 考虑：```
(123)-456-7890
```这是无效的，因为所需的格式要求在右括号后有一个空格。 

正则表达式明确强制执行：```
\([0-9]{3}\)
```其中包括空格字符。 

### 非数字字符

 一行例如：```
abc-def-ghij
```必须被拒绝。 

正则表达式使用`[0-9]`或者`\d`要求每个数字位置都有数字，确保字母字符永远不会匹配。 

### 缺少数字

 输入如下：```
123-45-6789
```中间组仅包含两位数字。 

量词`{3}`强制强制使用三位数字，因此该行会被自动拒绝。 

### 空行

 空行不应被视为有效。 

由于正则表达式需要电话号码的完整结构，因此空字符串会立即失败并被正确忽略。
