 # LeetCode 150，评估逆波兰表示法

 ## 问题理解

 该问题要求我们计算用逆波兰表示法（也称为后缀表示法）编写的算术表达式。 逆波兰表示法不是像标准中缀表示法那样将运算符放置在操作数之间，而是将运算符放置在操作数之后。 

例如，中缀表达式：```
(2 + 1) * 3
```变成：```
2 1 + 3 *
```输入以字符串数组形式给出，称为`tokens`。 每个令牌是：

 - 整数值
 - 四个运营商之一：`+`,`-`,`*`,`/`目标是计算整个表达式并返回最终的整数结果。 

一个非常重要的细节是除法的行为方式。 整数除法必须向零截断。 这对于负数尤其重要。 例如：```
6 / -132 = 0
```因为小数结果被截断为零而不是向下舍入。 

该问题保证了几个重要的性质：

 - 表达式始终有效
 - 永远不会被零除
 - 中间结果适合 32 位整数
 - 每个运算符总是有足够的可用操作数

 约束条件`tokens.length <= 10^4`告诉我们解决方案应该是有效的。 对于大输入，二次解会不必要地缓慢，而线性解是理想的。 

一些重要的边缘情况包括：

 - 仅包含单个数字的表达式
 - 负操作数
 - 涉及负数的除法
 - 长的运营链
 - 通过后缀排序隐式表示的嵌套表达式

 幼稚的实现很容易错误地处理减法和除法的操作数顺序。 由于后缀表示法按顺序计算操作数，因此第二个弹出的值实际上是左操作数。 

例如：```
["4", "2", "-"]
```方法：```
4 - 2
```不是：```
2 - 4
```这是这个问题中最常见的错误之一。 

## 方法

 ### 蛮力方法

 暴力策略会重复扫描令牌数组，寻找以下模式：```
number number operator
```每当找到这样的模式时，我们都会计算结果并用计算值替换这三个标记。 

例如：```
["2","1","+","3","*"]
```会变成：```
["3","3","*"]
```然后：```
["9"]
```这种方法之所以有效，是因为在重复评估本地操作后，每个有效的后缀表达式最终都会减少为单个值。 

然而，这种方法效率很低，因为每次归约都可能需要移动数组中的元素，并且我们可能会重复重新扫描列表。 在最坏的情况下，这会导致二次时间复杂度。 

### 最佳方法，堆栈

 关键的观察是逆波兰表示法自然地匹配堆栈行为。 

当我们遇到一个数字时，我们会存储它，因为操作员稍后可能会使用它。 

当我们遇到一个运算符时，我们立即将其应用于最近的两个操作数。 

堆栈非常适合此目的，因为：

 - 最近的操作数始终是下一个需要的操作数
 - 推送操作存储操作数
 - 弹出操作以相反的顺序检索操作数

 这允许我们从左到右一次处理表达式。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复重新扫描并修改token列表 |
 | 最佳| O(n) | O(n) | 使用堆栈进行单遍评估 |

 ## 算法演练

 1. 创建一个空堆栈来存储中间整数值。 
2. 从左到右迭代输入数组中的每个标记。 
3. 对于每个标记，确定它是运算符还是整数。 
4. 如果token是整数：

 - 将其转换为整数
 - 将其压入堆栈

 这会存储操作数，直到将来的运算符需要它为止。 
5. 如果令牌是运算符：

 - 从堆栈中弹出顶部值，这是正确的操作数
 - 从堆栈中弹出下一个值，这是左操作数

 顺序很重要，因为减法和除法不可交换。 
6. 将运算符应用于两个操作数。 

-`+`执行加法
 -`-`执行减法
 -`*`执行乘法
 -`/`执行向零截断的整数除法
 7. 将计算结果压回堆栈。 

这个结果本身可能成为未来操作的操作数。 
8. 继续处理，直到评估完所有令牌。 
9. 处理完成后，堆栈中恰好包含一个值，即最终结果。 返回它。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 处理完标记列表的任何前缀后，堆栈恰好包含计算剩余表达式所需的中间结果。 

每个操作数都被推送一次，并且每个运算符仅消耗两个操作数并产生一个新值。 由于后缀表示法保证操作数出现在其运算符之前，因此在遇到运算符时堆栈始终包含正确的操作数。 

由于保证输入表达式有效，因此算法将以堆栈上仅剩一个值结束，这是正确的最终结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def evalRPN(self, tokens: List[str]) -> int:
        stack = []
        operators = {"+", "-", "*", "/"}

        for token in tokens:
            if token not in operators:
                stack.append(int(token))
            else:
                right = stack.pop()
                left = stack.pop()

                if token == "+":
                    result = left + right
                elif token == "-":
                    result = left - right
                elif token == "*":
                    result = left * right
                else:
                    result = int(left / right)

                stack.append(result)

        return stack[-1]
```实现直接遵循基于堆栈的算法。 

我们首先创建一个空堆栈并定义一个包含有效运算符的集合。 使用集合允许恒定时间操作员检查。 

当我们迭代令牌时：

 - 数字被转换为整数并压入堆栈。 
- 操作员触发评估。 

当运算符出现时，我们从堆栈中弹出两个操作数。 第一个弹出的值是右操作数，第二个弹出的值是左操作数。 

对于除法，我们使用：```python
int(left / right)
```这很重要，因为 Python 的整除运算符`//`对于负数向下舍入，而不是向零截断。 

例如：```python
-3 // 2 == -2
```但问题需要：```python
-3 / 2 == -1
```使用`int(left / right)`正确地截断为零。 

最后，堆栈包含一个值，我们将其作为答案返回。 

## 解决方案```go
package main

import "strconv"

func evalRPN(tokens []string) int {
	stack := []int{}
	operators := map[string]bool{
		"+": true,
		"-": true,
		"*": true,
		"/": true,
	}

	for _, token := range tokens {
		if !operators[token] {
			num, _ := strconv.Atoi(token)
			stack = append(stack, num)
		} else {
			right := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			left := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			var result int

			switch token {
			case "+":
				result = left + right
			case "-":
				result = left - right
			case "*":
				result = left * right
			case "/":
				result = left / right
			}

			stack = append(stack, result)
		}
	}

	return stack[len(stack)-1]
}
```Go 实现与 Python 版本非常相似，但存在一些特定于语言的差异。 

Go 切片用作堆栈。 追加推送一个值，切片删除最后一个元素。 

字符串到整数的转换使用：```go
strconv.Atoi(token)
```Go 整数除法已经向零截断，因此除法不需要特殊处理。 

与 Python 不同，Go 在弹出值时需要显式的堆栈索引管理。

 ## 边缘情况

 ### 单个数字输入

 一个表达式可能只包含一个标记，例如：```
["42"]
```幼稚的实现可能假设每个表达式都包含运算符并尝试无效的堆栈弹出。 

当前的实现自然地处理了这个问题，因为数字只是被压入堆栈，如果没有运算符出现，单个值仍然是最终结果。 

### 负除法

 涉及负数的除法是错误的常见来源，因为编程语言在整数除法的行为方式上有所不同。 

例如：```
["-7", "3", "/"]
```应该产生：```
-2
```不是：```
-3
```蟒蛇的`//`运算符向下舍入，这会给出错误的答案。 使用：```
int(left / right)
```确保截断为零，完全符合问题要求。 

### 减法和除法的操作数顺序

 减法和除法不可交换，因此操作数顺序很重要。 

例如：```
["4", "2", "-"]
```方法：```
4 - 2
```不是：```
2 - 4
```一个常见的错误是反转弹出的操作数。 

该实现通过分配来避免这种情况：```
right = stack.pop()
left = stack.pop()
```然后评估：```
left operator right
```它保留了正确的评估顺序。
