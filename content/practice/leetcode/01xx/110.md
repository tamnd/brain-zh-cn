[LeetCode 第 110 题](https://leetcode.com/problems/balanced-binary-tree/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定给定的二叉树是否是**高度平衡的**。 

如果对于树中的**每个节点**，其左右子树之间的高度差**至多为 1**，则二叉树被认为是高度平衡的。 

简而言之，树在任何时候都不应该严重偏向一侧。 即使根本身看起来是平衡的，如果**任何子树**违反了平衡条件，那么树就不平衡。 

输入是二叉树的根节点。 在示例中，树以级别顺序形式表示，其中`null`表示缺少子节点。 

例如：```
[3,9,20,null,null,15,7]
```代表：```
      3
     / \
    9   20
       /  \
      15   7
```这棵树是平衡的，因为每个节点的左右子树高度最多相差 1。 

预期输出是一个布尔值：

 -`true`如果树是高度平衡的
 -`false`如果任何节点违反平衡条件

 约束告诉我们节点的数量在`0`和`5000`。 

这是相对较小的，但仍然足够大，低效的重复工作可能会成为问题。 在某些情况下，二次时间解可能会通过，但我们仍然应该以线性解为目标。 

节点值本身与平衡条件无关。 只有**树的形状**重要。 

预先考虑一些边缘情况很重要。 

应该返回一棵空树`true`，因为没有节点的树是平凡平衡的。 

一棵只有一个节点的树是平衡的，因为两个子树都有高度`0`。 

高度倾斜的树，例如链表形状的树，很容易违反平衡条件并暴露简单解决方案的低效率。 

另一个微妙的情况是，根看起来是平衡的，但更深的子树却不是。 正确的解决方案必须递归地验证**每个节点**的平衡，而不仅仅是根节点。 

## 方法

 ### 蛮力方法

 一种简单的方法是独立检查每个节点是否满足平衡条件。 

对于每个节点：

 1. 计算左子树的高度。 
2. 计算右子树的高度。 
3、检查高度差是否超过`1`。 
4. 对左右子节点递归地重复此过程。 

主要问题是高度计算被重复重新计算。 

考虑一棵倾斜的树：```
    1
   /
  2
 /
3
/
4
```检查节点`1`，我们计算节点的高度`2`。 

然后，在检查节点时`2`，我们计算节点的高度`3`再次。 

然后节点`3`重新计算节点`4`， 等等。 

这样的反复遍历，造成了大量的重复工作。 

该方法是正确的，因为它明确地验证了每个节点的平衡条件。 然而，由于子树高度被多次重新计算，它变得低效。 

### 最优方法，自下而上的 DFS

 关键的观察是平衡检查和高度计算可以**同时**进行。 

我们可以执行**后序深度优先遍历**，而不是重复计算高度，即在父子树之前处理子子树。 

对于每个节点：

 - 首先判断左子树是否平衡并获取其高度。 
- 然后判断右子树是否平衡并获取其高度。 
- 如果任一子树已经不平衡，则立即传播失败。 
- 如果当前节点违反了高度差规则，则将其标记为不平衡。 
- 否则，返回节点的高度。 

一个有用的优化是返回一个特殊的哨兵值，例如`-1`指示子树不平衡。 

这使我们能够尽早停止不必要的工作。 

而不是只返回高度：```
height(node)
```我们返回：```
-1  -> subtree is unbalanced
>=0 -> subtree height
```这将问题转化为单个遍历。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 反复重新计算子树高度 |
 | 最佳| O(n) | O(h) | 单次DFS遍历一起计算高度和平衡 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 ### 最优自下而上 DFS 算法

 1. 定义一个计算子树高度的辅助函数。 

该助手不只返回高度，而是返回：

 -`-1`如果子树不平衡
 - 否则表示高度的非负整数

 这种设计使我们能够将平衡检查与高度计算结合起来。 
2. 处理基本情况。 

如果当前节点是`None`（或者`nil`在 Go 中），返回高度`0`。 

空子树是平衡的并且不贡献高度。 
3. 递归计算左子树高度。 

呼叫左边孩子的助手。 

如果返回的话`-1`，我们立即传播`-1`向上，因为子树已经不平衡。 
4. 递归计算右子树高度。 

对右边的孩子重复相同的过程。 

再说一遍，如果`-1`返回，提前停止并传播故障。 
5. 检查当前节点的平衡情况。 

计算：```
abs(leftHeight - rightHeight)
```如果差值超过`1`， 返回`-1`。 

这表明当前子树不平衡。 
6. 计算并返回子树高度。 

如果节点平衡，则返回：```
1 + max(leftHeight, rightHeight)
```这`+1`占当前节点。 
7. 评估最终结果。 

调用 root 上的助手。 

如果结果是`-1`， 返回`False`。 

否则，返回`True`。 

### 为什么它有效

 该算法之所以有效，是因为每个节点仅在其子节点已被处理后才进行评估。 

在任何节点，我们已经知道：

 - 左子树是否平衡
 - 右子树是否平衡
 - 两个子树的高度

 这些信息足以判断当前节点是否平衡。 

不变的是辅助函数总是返回平衡树的有效子树高度或`-1`对于不平衡的树。 由于该不变量适用于叶节点并正确向上传播，因此保证根处的最终结果是正确的。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def isBalanced(self, root: Optional[TreeNode]) -> bool:
        def height(node: Optional[TreeNode]) -> int:
            if node is None:
                return 0

            left_height = height(node.left)
            if left_height == -1:
                return -1

            right_height = height(node.right)
            if right_height == -1:
                return -1

            if abs(left_height - right_height) > 1:
                return -1

            return 1 + max(left_height, right_height)

        return height(root) != -1
```实现遵循自下而上的递归策略。 

嵌套的`height()`辅助函数执行真正的工作。 它递归地计算子树高度，同时检查平衡。 

第一个条件处理基本情况。 一个`None`节点贡献高度`0`。 

递归调用首先处理左子节点和右子节点。 这是后序遍历，因为子级在其父级之前被评估。 

如果任一子树返回`-1`，该函数立即向上传播故障。 一旦检测到不平衡，这可以防止不必要的计算。 

该行：```python
if abs(left_height - right_height) > 1:
```检查核心余额要求。 

如果节点平衡，我们返回：```python
1 + max(left_height, right_height)
```它正确计算子树高度。 

最后，main函数检查根结果是否为`-1`。 如果不是，则树是平衡的。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func isBalanced(root *TreeNode) bool {
    var height func(node *TreeNode) int

    height = func(node *TreeNode) int {
        if node == nil {
            return 0
        }

        leftHeight := height(node.Left)
        if leftHeight == -1 {
            return -1
        }

        rightHeight := height(node.Right)
        if rightHeight == -1 {
            return -1
        }

        difference := leftHeight - rightHeight
        if difference < 0 {
            difference = -difference
        }

        if difference > 1 {
            return -1
        }

        if leftHeight > rightHeight {
            return leftHeight + 1
        }

        return rightHeight + 1
    }

    return height(root) != -1
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 不像 Python 那样自由声明嵌套函数，而是使用函数变量：```go
var height func(node *TreeNode) int
```这允许在匿名函数内进行递归。 

Go 使用`nil`而不是`None`对于空节点。 

由于Go没有内置的整数绝对值函数，无需导入包，因此需要手动计算绝对差值：```go
difference := leftHeight - rightHeight
if difference < 0 {
    difference = -difference
}
```其他方面的逻辑保持相同。 帮手回来了`-1`对于不平衡情况和平衡情况下的子树高度。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用堆栈取决于树的高度 |

 这里，`n`是节点数，`h`是树的高度。 

该算法实现了线性时间，因为每个节点只执行一次恒定工作。 

空间复杂度来自于递归。 在平衡树中，递归深度大约为`O(log n)`。 在最坏的情况下，例如倾斜的树，递归深度变为`O(n)`。

 ## 边缘情况

 ### 空树

 空树是一种常见的边缘情况，如果递归设计不正确，很容易被错误处理。 

由于没有节点，因此树是简单平衡的。 实现通过以下方式正确处理这个问题：```
if node is None:
    return 0
```这确保算法立即返回有效的高度。 

### 高度倾斜的树

 形状像链表的树是另一个重要的例子。 

例子：```
1
 \
  2
   \
    3
```幼稚的实现可能会反复重新计算高度，从而导致性能不佳。 

自下而上的方法避免了重复工作，并在子树高度差超过时正确检测不平衡`1`。 

### 子树深处的不平衡

 有时根本身看起来是平衡的，但不平衡存在于树的较低处。 

例子：```
      1
     / \
    2   2
   /
  3
 /
4
```仅检查根的有缺陷的解决方案将错误地返回`true`。 

该实现递归地验证每个子树并传播`-1`向上，确保永远不会错过深度失衡。
