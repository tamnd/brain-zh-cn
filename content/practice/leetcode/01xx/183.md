[LeetCode 第 183 题](https://leetcode.com/problems/customers-who-never-order/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们识别来自一个的所有客户`Customers`从未根据该表下过订单的表`Orders`桌子。 换句话说，我们正在寻找以下条目`Customers`没有对应的`customerId`在`Orders`桌子。 

输入由两个表组成：`Customers`和`Orders`。`Customers`有一个`id`（主键）和`name`（客户姓名），同时`Orders`有一个`id`（主键）和`customerId`（外键引用`Customers.id`）。 预期输出是一个名为的单列表`Customers`列出未出现在任何订单记录中的所有客户名称。 

该问题隐含的约束包括两个表都非空、ID 唯一，并且`customerId`在`Orders`始终指向有效客户。 该问题允许输出以任意顺序返回。 

重要的边缘情况包括没有客户有订单、所有客户都有订单或`Orders`表是空的。 该解决方案应正确处理这些情况，不会产生重复或丢失任何客户。 

## 方法

 蛮力方法将迭代每个客户，并针对每个客户扫描整个`Orders`检查表是否有匹配`customerId`。 这种方法是正确的，因为它直接为每个客户验证订单是否存在。 但这种方式效率较低，时间复杂度为O(C * O)，其中C是顾客数量，O是订单数量，因为每个顾客都需要扫描所有订单。 

最佳方法利用 SQL 集操作或连接。 关键的见解是我们只需要未出现在`Orders`桌子。 这可以使用`LEFT JOIN`之间`Customers`和`Orders`，选择其中的行`Orders.customerId`为 NULL，或者使用`NOT IN`或者`NOT EXISTS`子查询。 这些方法通过使用索引查找而不是重复扫描整个表来减少所需的比较次数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| --- | --- | --- |
 | 蛮力 | O(C * O) | O(1) | O(1) | 检查每个客户的所有订单 |
 | 最佳| O(C + O) | O(O)| 使用`LEFT JOIN`或者`NOT IN`/`NOT EXISTS`用于高效查找的子查询 |

 ## 算法演练

 1. 从`Customers`表作为主表，因为我们需要列出所有客户，包括那些没有订单的客户。 
2. 执行`LEFT JOIN`之间`Customers`和`Orders`在客户 ID 上。 这会将订单信息附加到每个客户（如果存在），如果不存在则为 NULL。 
3. 过滤结果集以仅包含符合条件的行`Orders.customerId`为NULL，表示客户从未下过订单。 
4. 仅选择`name`从这些过滤的行中提取列并将其作为最终结果返回。 

**为什么有效：** 通过使用`LEFT JOIN`，我们保留所有客户记录，仅作废不匹配的订单记录。 过滤 NULL 可保证我们只挑选没有订单的客户。 该查询利用关系数据库索引来提高效率。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def customers_who_never_order(cursor: sqlite3.Cursor) -> List[Tuple[str]]:
    query = """
    SELECT name AS Customers
    FROM Customers c
    LEFT JOIN Orders o ON c.id = o.customerId
    WHERE o.customerId IS NULL
    """
    cursor.execute(query)
    return cursor.fetchall()
```该实现使用一个`LEFT JOIN`将订单数据附加到每个客户。 这`WHERE`子句通过检查 NULL 值来过滤掉所有有订单的客户`Orders.customerId`。 最后，`fetchall`返回从未下过订单的客户姓名。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func CustomersWhoNeverOrder(db *sql.DB) ([]string, error) {
    query := `
    SELECT name AS Customers
    FROM Customers c
    LEFT JOIN Orders o ON c.id = o.customerId
    WHERE o.customerId IS NULL
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var result []string
    for rows.Next() {
        var name string
        if err := rows.Scan(&name); err != nil {
            return nil, err
        }
        result = append(result, name)
    }
    return result, nil
}
```Go 的实现类似，使用`db.Query`执行`LEFT JOIN`SQL 查询。 行被迭代`rows.Next()`并扫描成一段字符串。 我们仔细处理错误并推迟行的关闭。 与 Python 不同，Go 需要显式迭代和切片处理。

 ## 边缘情况

 **空订单表：** 如果`Orders`表中没有条目，每个客户都没有下过订单。 该实现正确返回所有客户，因为`LEFT JOIN`为所有结果生成 NULL`Orders.customerId`。 

**所有客户都有订单：** 如果每个客户至少有一个订单，则`LEFT JOIN`将附加一个非空`customerId`对于每一行。 过滤 NULL 会正确生成空结果，确保不会出现误报。 

**单个客户：** 只有一个客户，解决方案必须根据订单是否存在正确返回该客户或空集。 这测试了该算法不依赖于多行并正确处理最小输入大小。 

这种方法可确保正确性，优雅地处理边缘情况，并通过索引表进行有效扩展。
