 **难度：** 🟡 中等
 **主题：** 外壳

 ## 解决方案

 ## 问题理解

 这个问题要求我们转置文本文件的内容。 转置意味着将行转换为列，将列转换为行。 输入文件中的每个单词都由一个空格分隔，并且每行包含相同数量的列。 

输入是一个名为`file.txt`。 文件中的每一行代表一行数据。 行内的每个单词代表一个列值。 目标是打印文件的转置版本，其中第一个输出行包含第一列中的所有值，第二个输出行包含第二列中的所有值，依此类推。 

例如，考虑以下输入：```
name age
alice 21
ryan 30
```原来的结构是：

 | 行| 价值观 |
 | --- | --- |
 | 0 | 姓名 年龄 |
 | 1 | 爱丽丝 21 |
 | 2 | 瑞安 30 |

 转置后：

 | 专栏 | 价值观 |
 | --- | --- |
 | 0 | 名字爱丽丝瑞恩 |
 | 1 | 年龄 21 30 |

 所以输出变成：```
name alice ryan
age 21 30
```该问题保证每行包含相同数量的列。 这种保证很重要，因为这意味着我们永远不需要处理不规则的行长度或缺失值。 如果没有这种保证，访问每行中的列索引可能会产生错误。 

在 shell 脚本问题中，输入大小通常很小，但效率仍然很重要，因为低效地重复扫描文件或重建字符串会增加运行时间。 

一些重要的边缘情况包括仅包含一行的文件、仅包含一列的文件以及包含许多行和列的文件。 幼稚的实现也可能会错误地处理空格或在行尾产生尾随空白。 

## 方法

 ### 蛮力方法

 强力解决方案将重复扫描文件中的每一列。 首先，我们通过读取第一行来确定存在多少列。 然后，对于每个列索引，我们迭代每一行并使用诸如`awk`或者`cut`。 

这种方法之所以有效，是因为每个输出行完全对应于一个输入列。 通过重复访问每一列的每一行，我们可以重建转置的结构。 

然而，该解决方案对输入数据执行不必要的重复传递。 如果有`m`行和`n`列，可以有效地扫描文件`n`次。 虽然对于小文件来说仍然可以接受，但它比在一次遍历中处理所有内容的效率要低。 

### 最佳方法

 关键的见解是，转置自然地映射到在读取文件一次时存储按列索引分组的值。 

当我们处理每一行时，我们将其分成多个字段。 对于每个场位`i`，我们将值附加到表示`i-th`输出行。 

这使我们能够在一次通过文件的过程中增量地构建转置结果。 处理完所有行后，每个累积字符串已包含一行转置输出。 

这种方法非常高效，因为每个值都只处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n) | O(1) | O(1) | 重复扫描每列的行 |
 | 最佳| O(m × n) | O(n) | 按列分组时处理文件一次 |

 这里，`m`代表行数和`n`代表列数。 

## 算法演练

 1. 逐行读取文件，使内存使用保持可控，并且每行只处理一次。 
2. 使用空格作为分隔符将当前行拆分为多个字段。 在 shell 脚本编写中，类似的工具`awk`自动处理字段分割。 
3. 对于每个字段位置`i`，将字段值追加到列对应的累加器中`i`。 
4. 如果累加器已包含文本，请在附加新值之前添加一个空格。 这可以确保正确的格式，没有前导或尾随空格。 
5. 继续处理，直到读取完所有行。 
6. 处理整个文件后，按顺序打印每个累加器行。 现在，每个累加器代表转置输出的一行。 

这里的主要数据结构是关联数组或索引数组，用于存储按列索引分组的字符串。 这种结构是理想的，因为每列都是在处理行时独立构建的。 

## Python 解决方案

 尽管这是 LeetCode 上的 Shell 问题，但以下 Python 实现清楚地演示了相同的转置逻辑。```python
from typing import List

class Solution:
    def transposeFile(self, lines: List[str]) -> List[str]:
        if not lines:
            return []

        rows = [line.split() for line in lines]
        row_count = len(rows)
        column_count = len(rows[0])

        transposed = []

        for column_index in range(column_count):
            current_row = []

            for row_index in range(row_count):
                current_row.append(rows[row_index][column_index])

            transposed.append(" ".join(current_row))

        return transposed
```该实现首先将每个输入行拆分为单独的字段。 这将创建一个二维结构，其中每个内部列表代表文件的一行。 

接下来，算法逐列迭代。 对于每个列索引，它收集该位置的每一行的值。 这些值用空格连接在一起，形成转置输出的一行。 

最后，完成转置的行以字符串列表的形式返回。 

嵌套循环直接反映了矩阵转置的数学定义。 外循环遍历列，而内循环遍历行。 

## 解决方案```go
package main

import (
	"strings"
)

func transposeFile(lines []string) []string {
	if len(lines) == 0 {
		return []string{}
	}

	rows := make([][]string, len(lines))

	for i, line := range lines {
		rows[i] = strings.Fields(line)
	}

	rowCount := len(rows)
	columnCount := len(rows[0])

	result := make([]string, 0, columnCount)

	for col := 0; col < columnCount; col++ {
		currentRow := make([]string, 0, rowCount)

		for row := 0; row < rowCount; row++ {
			currentRow = append(currentRow, rows[row][col])
		}

		result = append(result, strings.Join(currentRow, " "))
	}

	return result
}
```Go 实现遵循与 Python 版本相同的整体结构。 主要区别在于 Go 需要显式切片分配并使用`strings.Fields`用于将行分割成字段。 

Go 切片是动态调整大小的数组，使其适合增量收集列值。 这`strings.Join`函数有效地构造最终的输出行。 

与 Python 不同，Go 区分`nil`切片和空切片。 在这里，为空输入返回一个空切片，以保持行为明确且可预测。

## 边缘情况

 ### 单行输入

 如果输入仅包含一行：```
a b c
```转置变为：```
a
b
c
```有缺陷的实现可能会错误地假设存在多行。 该解决方案可以自然地处理这种情况，因为无论行数如何，外部循环都会迭代列。 

### 单列输入

 如果输入是：```
a
b
c
```转置变为：```
a b c
```某些实现错误地保留换行符，而不是将值组合到单行中。 该算法正确地将所有第一列值分组在一起。 

### 大量行

 考虑一个包含数千行但只有几列的文件。 重复扫描方法效率低下，因为它会多次重新读取文件。 

最佳解决方案通过单遍处理文件并增量构建输出来避免此问题。 

### 字段之间的额外空格

 如果文件包含不规则间距：```
a    b
c    d
```使用空格感知分割函数，例如`split()`在 Python 中或`strings.Fields()`Go 中正确折叠多个空格并提取干净的字段值。 这可以防止格式错误的输出。
