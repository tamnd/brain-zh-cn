[LeetCode 第 120 题](https://leetcode.com/problems/triangle/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题给了我们一个整数三角形数组，并要求我们计算**从顶行到底行的最小路径和**。 

输入是一个二维数组，称为`triangle`，其中：

 - 第一行恰好包含一个数字。 
- 每个后续行都比前一行多包含一个元素。 
- 从一行中的任何位置，我们只能移动到下一行中的**两个相邻位置**之一。 

如果我们当前处于索引位置`i`在行中`r`，然后在行中`r + 1`我们可能会搬到：

 - 索引`i`- 指数`i + 1`我们的目标是选择一条从三角形顶部到底部的路径，使得所有选定数字的**总和尽可能小**。 

例如，考虑：```
   2
  3 4
 6 5 7
4 1 8 3
```开始于`2`，我们可以在遵守邻接规则的情况下逐行向下移动。 最优路径是：```
2 → 3 → 5 → 1
```其产生：```
2 + 3 + 5 + 1 = 11
```约束条件很重要：

 - 三角形最多可以有 **200 行**。 
- 值可能为负数，范围为`-10^4`到`10^4`。 

由于行数可能相当大，因此对每个可能的路径进行强力搜索很快就会变得过于昂贵。 此外，因为允许负数，所以我们不能依赖贪婪的决策，例如总是采用较小的直接子代，因为局部较小的选择可能会导致以后的总数更大。 

一些边缘情况很重要：

 - 只有一行的三角形，例如`[[-10]]`，其中答案就是该值。 
- 包含负数的三角形，其中最佳路径可能有意包含较大的立即值，以便稍后实现较小的总数。 
- 大三角形，指数递归变得不切实际。 
- 多个路径产生相同的最小总和的情况，其中任何有效的最小值仍应正确计算。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是使用递归从上到下探索**每条可能的路径**。 

在每个位置`(row, col)`，我们只有两个选择：

 1. 移至`(row + 1, col)`2. 移至`(row + 1, col + 1)`我们递归计算两个选项的最小路径和并返回：```
triangle[row][col] + min(left_path, right_path)
```这种方法是正确的，因为它评估所有有效路径并选择其中的最小总数。 

然而，问题是路径数量呈指数增长。 由于每一行引入两个选择，因此递归树变得非常大。 

对于一个三角形`n`行，时间复杂度大约变为`O(2^n)`。 

这对于`n = 200`。 

### 关键见解

 重要的观察是**许多子问题重复**。 

例如，假设两条不同的路径都到达同一单元。 从该单元格开始，最小剩余路径总和始终相同。 反复重新计算是浪费的。 

这使得该问题自然适合**动态规划**。 

我们可以从下往上计算最小成本，而不是重复探索路径。 

关键的重复是：```
dp[col] = triangle[row][col] + min(dp[col], dp[col + 1])
```这里：

-`dp[col]`表示从当前位置向下的最小路径和。 
-`dp[col]`和`dp[col + 1]`存储下面行的结果。 

通过从底行开始向上移动，我们重用已经计算的最优子问题。 

更好的是，我们只需要一个大小的数组`n`（行数），满足后续要求`O(n)`额外的空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n)`|`O(n)`| 递归探索每条可能的路径 |
 | 最优动态规划|`O(n²)`|`O(n)`| 使用单个数组的自下而上 DP |

 ## 算法演练

 ### 最优自下而上动态规划

 1. 创建一个动态编程数组，并使用最后一行的值进行初始化。 

最后一行已经代表从自身到达底部的最小成本，因为没有进一步的移动。 

例子：```
Triangle:
   2
  3 4
 6 5 7
4 1 8 3

Initial dp:
[4, 1, 8, 3]
```2. 从倒数第二行向上处理行。 

对于每个元素，计算：```
current value + minimum of the two reachable children
```3. 就地更新DP阵列。 

对于行`[6,5,7]`：```
dp[0] = 6 + min(4,1) = 7
dp[1] = 5 + min(1,8) = 6
dp[2] = 7 + min(8,3) = 10
```更新：```
[7, 6, 10, 3]
```4. 继续向上直到顶行。 

排`[3,4]`：```
dp[0] = 3 + min(7,6) = 9
dp[1] = 4 + min(6,10) = 10
```更新：```
[9, 10, 10, 3]
```5. 处理顶行。```
dp[0] = 2 + min(9,10) = 11
```6. 返回`dp[0]`。 

处理完所有行后，第一个位置包含从上到下的最小路径和。 

### 为什么它有效

 该算法之所以有效，是因为具有**最佳子结构属性**。 来自单元的最小路径和仅取决于其两个可达子节点的最小路径和。 

处理一行时，DP 数组已包含下一行的正确最小成本。 因此，每次更新都会计算当前行的正确最优值。 通过反复向上移动，顶部单元最终包含全局最小路径和。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumTotal(self, triangle: List[List[int]]) -> int:
        dp = triangle[-1][:]

        for row in range(len(triangle) - 2, -1, -1):
            for col in range(len(triangle[row])):
                dp[col] = triangle[row][col] + min(
                    dp[col],
                    dp[col + 1]
                )

        return dp[0]
```实现首先将最后一行复制到`dp`。 这是基本情况，因为从底行到自身的最小成本就是它自己的值。 

接下来，我们从倒数第二行向上迭代到第一行。 对于每个位置，我们计算当前值加上下面行中两个可到达子级中较小的一个。 

重要的细节是更新**就地**发生。 由于我们从左到右处理，`dp[col]`和`dp[col + 1]`需要时仍然代表前一行的值。 

处理完所有行后，`dp[0]`存储从顶部到底部的最小路径和。 

## 解决方案```go
func minimumTotal(triangle [][]int) int {
	dp := make([]int, len(triangle[len(triangle)-1]))
	copy(dp, triangle[len(triangle)-1])

	for row := len(triangle) - 2; row >= 0; row-- {
		for col := 0; col < len(triangle[row]); col++ {
			if dp[col] < dp[col+1] {
				dp[col] = triangle[row][col] + dp[col]
			} else {
				dp[col] = triangle[row][col] + dp[col+1]
			}
		}
	}

	return dp[0]
}
```Go 实现遵循相同的自下而上的动态编程策略。 

由于切片是基于引用的，因此我们显式创建一个新切片并使用`copy()`以避免修改原来的最后一行`triangle`。 

而不是使用`min()`，Go 使用简单的条件比较，因为没有内置的整数最小值函数。 

整数溢出在这里不是一个问题，因为最大可能的和保持在 Go 的整数范围内。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n²)`| 我们只访问三角形中的每个元素一次 |
 | 空间|`O(n)`| 我们只存储一个大小等于行数的 DP 数组 |

 ## 边缘情况

 ### 单排三角形

 仅包含一行的三角形是最小的有效输入。 幼稚的实现可能会意外地假设行之间至少存在一个转换。 

例如：```
[[-10]]
```该实现自然地处理了这个问题，因为 DP 数组是用最后一行初始化的，并且外部循环永远不会执行。 结果很简单`dp[0]`。 

### 负数

 负值使贪婪策略变得不可靠。 选择较小的直接子代可能不会导致全局最优解。 

例子：```
[
 [5],
 [-2, -3]
]
```该算法使用动态规划正确评估两个可达子级，并选择真正的最小总数。 

### 大三角形

 对于多达 200 行，由于可能路径呈指数增长，强力递归解决方案将变得不可行。 

自下而上的 DP 解决方案对每个元素只处理一次，并且仅使用单个数组，因此即使对于最大的有效输入也足够高效。
