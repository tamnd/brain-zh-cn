 # LeetCode 160，两个链表的交集

 ## 问题理解

 该问题要求我们确定两个单链表是否共享公共节点，如果共享，则返回交集开始的确切节点。 

重要的细节是交集基于节点引用，而不是节点值。 包含相同值的两个节点不被视为相同，除非它们在内存中实际上是相同的对象。 

例如，考虑以下两个列表：

 - 名单A：`4 -> 1 -> 8 -> 4 -> 5`- 名单B：`5 -> 6 -> 1 -> 8 -> 4 -> 5`列表在具有值的节点处相交`8`，因为两个列表最终都指向完全相同的节点对象。 从那时起，每个剩余节点都在两个列表之间共享。 

输入提供两个头指针：

 -`headA`，第一个链表的头
 -`headB`，第二个链表的头

 预期输出是：

 - 相交节点（如果存在）
 -`null`如果列表从不相交

 该问题保证：

 - 两个列表中都没有循环
 - 链表结构必须保持不变
 - 列表可能有不同的长度
 - 交集（如果存在）形成共享后缀

 约束允许最多`3 * 10^4`每个列表中的节点。 这个尺寸足够大，以至于低效的二​​次解可能会出现问题。 后续行动特别要求`O(m + n)`仅使用时间解决方案`O(1)`额外的内存。 

一些边缘情况很重要：

 - 一个或两个列表可能只包含一个节点
 - 列表可能根本不相交
 - 交叉点可能发生在头部本身
 - 一个列表可能比另一个列表长得多
 - 共享尾部可能只包含一个节点

 比较值而不是节点引用的简单实现会产生不正确的结果。 

## 方法

 ### 蛮力方法

 暴力解决方案将列表 A 中的每个节点与列表 B 中的每个节点进行比较。 

对于第一个列表中的每个节点，我们完全遍历第二个列表并检查两个节点引用是否相同。 

如果我们发现：```
nodeA == nodeB
```那么我们就找到了交集节点。 

这种方法是正确的，因为每个可能的节点对都会被检查。 如果存在交集，最终将比较匹配的参考。 

但时间复杂度较差。 如果列表 A 有`m`节点和列表 B 有`n`节点，那么在最坏的情况下我们执行`m * n`比较。 

对于包含数万个节点的列表，这会变得低效。 

### Optimal Two Pointer Approach

 关键的观察是，两个链表相交后，所有剩余的节点都是共享的。 

假设：

 - 列表A的长度是`m`- 列表 B 的长度为`n`- 共享尾长为`k`然后：

 - A 的唯一部分是`m - k`- B 的独特部分是`n - k`挑战在于对齐遍历，以便两个指针同时到达交点。 

一个聪明的技巧优雅地解决了这个问题：

 - 指针A遍历列表A，然后切换到列表B
 - 指针B遍历列表B，然后切换到列表A

 最终，两个指针移动的总距离完全相同：```
m + n
```如果存在交叉点，他们就会在那里相遇。 

如果不存在交集，两者最终都会变成`null`同时地。 

这无需显式计算长度即可工作，并且仅使用恒定的额外内存。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n) | O(1) | O(1) | 将 A 中的每个节点与 B 中的每个节点进行比较 |
 | 最佳| O(m + n) | O(1) | O(1) | 两个指针切换列表以均衡遍历距离 |

 ## 算法演练

 ### 最优两指针算法

 1.初始化两个指针：

 -`pointerA = headA`-`pointerB = headB`每个指针都从其各自列表的头部开始。 
2. 同时遍历两个列表。 

在每次迭代时：

 - 移动`pointerA`向前迈出一步
 - 移动`pointerB`向前迈出一步
 3. 当指针到达列表末尾时：

 - 重定向到相反列表的头部

 具体来说：

 - 如果`pointerA`变成`null`，将其设置为`headB`- 如果`pointerB`变成`null`，将其设置为`headA`4. 继续直至：

 -`pointerA == pointerB`这种等式之所以有效，是因为链表交集取决于节点身份。 
5. 返回会议节点。 

如果列表相交，则该节点是第一个共享节点。 

如果它们不相交，两个指针最终都会变成`null`，算法返回`null`。 

### 为什么它有效

 每个指针经过的总距离完全相同：```
Length(A) + Length(B)
```如果一个列表较长，则切换列表可以补偿长度差异。 在两个指针遍历每个列表的唯一部分之后，它们相对于共享尾部对齐。 

由于两个指针以相同的速度移动并且移动的总距离相等，因此它们必须：

 - 在交叉路口节点集合
 - 达到`null`如果不存在交集，则同时进行

 这个不变量保证了正确性。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None

from typing import Optional

class Solution:
    def getIntersectionNode(
        self,
        headA: ListNode,
        headB: ListNode
    ) -> Optional[ListNode]:

        pointerA = headA
        pointerB = headB

        while pointerA != pointerB:
            if pointerA is None:
                pointerA = headB
            else:
                pointerA = pointerA.next

            if pointerB is None:
                pointerB = headA
            else:
                pointerB = pointerB.next

        return pointerA
```该实现首先创建两个指针，每个指针对应一个链表。 

主循环继续进行，直到两个指针引用同一个节点。 由于链表中的节点相等是引用相等，因此可以正确检测实际的交集节点。 

在循环内部，每个指针通常在其当前列表中前进。 当指针到达末尾时，它会切换到另一个列表的头部。 

这种切换行为是该算法的核心思想。 它确保两个指针最终遍历相同的总距离，消除列表之间的任何长度不平衡。 

当循环退出时，只有两种可能：

 - 两个指针都指向交集节点
 - 两个指针都是`None`返回`pointerA`正确处理这两种情况。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func getIntersectionNode(headA, headB *ListNode) *ListNode {
    pointerA := headA
    pointerB := headB

    for pointerA != pointerB {
        if pointerA == nil {
            pointerA = headB
        } else {
            pointerA = pointerA.Next
        }

        if pointerB == nil {
            pointerB = headA
        } else {
            pointerB = pointerB.Next
        }
    }

    return pointerA
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

主要的语言特定差异是使用`nil`而不是`None`。 

Go 中的指针比较自然会比较内存地址，这正是我们检测链表交集所需要的。 

不需要对整数溢出或切片进行特殊处理，因为该算法仅操作链表指针。

 ## 边缘情况

 ### 列表不相交

 这是最重要的边缘情况之一，因为不正确的实现可能会进入无限循环。 

对于非相交列表，两个指针最终都会完全遍历两个列表并成为`null`同时。 由于循环条件检查：```
pointerA != pointerB
```当两者都为时循环正确终止`None`。 

### 交叉点发生在头部

 如果两个头指针已经引用同一个节点，则列表立即相交。 

在这种情况下：```
pointerA == pointerB
```在循环开始之前就为 true，因此算法会立即返回头节点，而无需进行不必要的遍历。 

### 一个列表比另一个列表长得多

 较大的长度差异通常会导致简单的指针同步方法出现错误。 

指针切换技术自动补偿不平衡。 每个指针只遍历两个列表一次，确保它们在输入共享后缀之前正确对齐。 

这样就无需显式计算长度或手动将一个指针提前到另一个指针之前。
