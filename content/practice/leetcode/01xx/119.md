 # LeetCode 119，帕斯卡三角形 II

 ## 问题理解

 该问题要求我们从帕斯卡三角形返回特定行。 输入，`rowIndex`，表示我们要生成的行的从零开始的索引。 

帕斯卡三角形是数字的三角形排列，其中：

 - 每行的第一个和最后一个数字始终是`1`- 每个内部数字都是其正上方两个数字的总和

 例如，前几行是：```
Row 0: [1]
Row 1: [1, 1]
Row 2: [1, 2, 1]
Row 3: [1, 3, 3, 1]
Row 4: [1, 4, 6, 4, 1]
```如果输入是`3`，我们返回第四行，`[1,3,3,1]`，因为索引开始于`0`。 

约束条件`0 <= rowIndex <= 33`告诉我们输入大小相对较小。 即使效率较低的方法也可以在这些范围内发挥作用。 然而，后续特别要求我们优化空间使用`O(rowIndex)`，这意味着我们应该尽可能避免存储整个三角形。 

有几个重要的边缘情况需要考虑：

 -`rowIndex = 0`，尽可能小的输入，应该返回`[1]`-`rowIndex = 1`，第一行有两个元素，应该返回`[1,1]`- 较大的行需要仔细更新，因为过早覆盖值可能会破坏以后的计算
 - 由于帕斯卡三角形值增长很快，我们必须确保实现正确处理更大的中间值，尽管问题保证所有结果都适合给定约束的标准整数范围内

 ## 方法

 ### 蛮力方法

 最直接的解决方案是从行构建整个帕斯卡三角形`0`最多`rowIndex`，然后返回最后一行。 

我们从第一行开始`[1]`。 对于每个新行，我们创建一个新数组，其第一个和最后一个元素是`1`。 每个中间元素都计算为前一行中两个相邻值的总和。 

这种方法是正确的，因为帕斯卡三角形是递归定义的。 每行完全依赖于它前面的行，因此逐行构造行可以保证正确性。 

但是，即使我们只需要最后一行，此方法也会存储所有行。 这会导致不必要的内存使用。 

### 最佳方法

 关键的观察是每一行仅依赖于前一行。 我们不需要存储整个三角形。 

相反，我们可以维护一个代表当前行的数组并就地更新它。 

重要的细节是更新顺序。 如果我们从左到右更新，我们会覆盖未来计算仍需要的值。 为了避免这种情况，我们从右向左更新。 

例如：```
Current row: [1, 3, 3, 1]
Next update:
index 3 = 3 + 1
index 2 = 3 + 3
index 1 = 1 + 3
```通过向后更新，我们保留前一行的值，直到不再需要它们为止。 

这样就达到了后续的要求`O(rowIndex)`额外的空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(行索引²) | O(行索引²) | 构建整个三角形 |
 | 最佳| O(行索引²) | O(行索引) | 使用就地更新的一个数组 |

 ## 算法演练

 1. 用帕斯卡三角形的第一行初始化结果数组。```
row = [1]
```这代表行`0`。 
2. 从行开始迭代`1`最多`rowIndex`。 

对于每个新行，附加一个`1`到数组的末尾，因为帕斯卡三角形中的每一行都以`1`。 
3. 从右到左更新内部元素。 

对于每个索引`j`从`i - 1`下降到`1`：```
row[j] = row[j] + row[j - 1]
```我们向后移动，以便前一行的值在使用之前不会被覆盖。 
4. 继续，直到完全构建所需的行。 
5. 返回最终的数组。 

### 为什么它有效

 该算法在迭代后保持不变`i`，数组`row`正好代表`i-th`帕斯卡三角形的行。 

帕斯卡三角形中的每个内部元素被定义为其上方两个元素的总和。 通过从右向左更新，我们确保两个所需值在计算时仍然属于前一行。 因此，每次更新都会产生正确的下一行值。 

## Python 解决方案```python
from typing import List

class Solution:
    def getRow(self, rowIndex: int) -> List[int]:
        row = [1]

        for i in range(1, rowIndex + 1):
            row.append(1)

            for j in range(i - 1, 0, -1):
                row[j] = row[j] + row[j - 1]

        return row
```实现首先将第一行初始化为`[1]`。 

外部循环一次生成一行，直到到达目标行。 在每次迭代期间，都会产生一个新的`1`附加是因为每个帕斯卡三角形行都以`1`。 

内部循环从右到左更新内部值。 这种向后遍历至关重要，因为它可以防止覆盖后续计算仍需要的值。 

最后，处理完所有行后，该函数将返回结果数组。 

## 解决方案```go
func getRow(rowIndex int) []int {
    row := []int{1}

    for i := 1; i <= rowIndex; i++ {
        row = append(row, 1)

        for j := i - 1; j >= 1; j-- {
            row[j] = row[j] + row[j-1]
        }
    }

    return row
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 中的切片的行为与动态数组类似，这使得它们非常适合解决这个问题。 这`append`函数用于添加尾随`1`对于每一行。 

Go 使用显式索引和循环语法，但算法在其他方面保持相同。 由于最大行索引仅为`33`，使用Go标准时整数溢出不是问题`int`类型。

1 + 2 + 3 + ... + rowIndex

该算法仅存储当前行，其最大大小为`rowIndex + 1`，所以空间复杂度为`O(rowIndex)`。

 ## 边缘情况

 ### 边缘情况 1，`rowIndex = 0`这是最小的有效输入，很容易暴露差一错误。 假设至少一次迭代的简单实现可能会在这里失败。 

该实现正确处理了这个问题，因为数组开始为`[1]`，它已经代表行`0`。 由于循环开始于`1`，不发生任何更新，并立即返回正确的结果。 

### 边缘情况 2，以错误的方向更新元素

 从左到右更新行时会出现一个常见错误。 这样做会在使用值之前覆盖它们。 

例如：```
[1, 2, 1]
```如果索引`1`先更新，原来的`2`在计算后面的元素之前丢失。 

该实现通过向后迭代来避免此问题，在计算期间保留所有必需的前行值。 

### 边缘情况 3，最大约束值

 最大允许输入是`33`。 尽管这仍然很小，但该行包含相对较大的二项式系数。 

该实现可以安全地处理这个问题，因为 Python 整数和 Go 整数都可以轻松地支持问题约束内的结果值。 该算法还保持高效，因为行长度永远不会超过`34`。
