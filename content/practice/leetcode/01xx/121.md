[LeetCode 第 121 题](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/)

 **难度：** 🟢简单
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定从**单只股票交易**中可以获得的最大利润。 交易包括在一天购买一只股票并在稍后一天出售。 关键限制是卖出日必须在买入日**之后**。 

输入是一个整数数组`prices`， 在哪里`prices[i]`代表股票价格`i-th`天。 由于数组按时间顺序排序，因此索引本身隐式表示时间。 我们的目标是找两天时间`buy < sell`这样利润：```
prices[sell] - prices[buy]
```被最大化。 

预期输出是一笔有效交易的**最大可能利润**。 如果不存在有利可图的交易，意味着价格持续下降或保持不变，我们将返回`0`因为选择不交易比赔钱要好。 

这些约束提供了有关预期解决方案的重要线索：

 -`1 <= prices.length <= 10^5`-`0 <= prices[i] <= 10^4`输入大小可以大到`100,000`，这立即排除了生产质量解决方案的缓慢二次方法。 任何比粗略更糟糕的算法`O(n log n)`存在超时的风险，并且`O(n²)`对于最坏情况的输入来说，解决方案会太慢。 

预先考虑几个边缘情况很重要：

 - 单元素数组，例如`[5]`，其中不可能进行买卖，因为至少需要两天时间。 
- 严格降低价格，例如`[7,6,4,3,1]`，没有利润，答案一定是`0`。 
- 重复值，例如`[5,5,5,5]`，其中利润始终为零。 
- 最低价格出现较早但最大卖出机会出现较晚的情况。 
- 由于购买限制很重要，最畅销日不是全球最高价格的情况。 

该问题保证数组至少包含一个价格，因此我们永远不需要处理空输入。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是尝试**每一种可能的买卖对**。 

对于每一天`i`，我们可以将其视为购买日，然后迭代后面的每一天`j > i`计算利润：```
prices[j] - prices[i]
```我们跟踪所有有效货币对的最大利润。 

这种方法是正确的，因为它详尽地检查了每笔合法交易，因此不会错过最佳答案。 然而，它的表现很差，因为每一天我们都可能与以后的所有日子进行比较。 

如果有`n`天，我们检查大约：```
n × (n - 1) / 2
```对，导致`O(n²)`时间复杂度。 

鉴于`n`可以大到`100,000`，这种方法变得不切实际。 

### 最佳解决方案的关键见解

 关键的观察是，在决定是否在某一天出售时，我们只关心**该天之前看到的最低股价**。 

我们不必重复检查每个较早的购买日，而是可以维护：

 1. **迄今为止遇到的最低价格**，代表最佳买入机会。 
2. **迄今为止找到的最大利润**。 

当我们从左到右扫描数组时：

 - 如果当前价格低于我们记录的最低价格，我们会更新最低价格。 
- 否则，我们将使用之前看到的最低价格计算今天出售的利润。 
- 如果这笔交易更好，我们会更新最佳利润。 

这是有效的，因为每天只取决于之前最便宜的有效购买价格，可以在恒定时间内增量跟踪。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每一个可能的买卖对 |
 | 最佳| O(n) | O(1) | O(1) | 扫描一次即可跟踪最低购买价格 |

 ## 算法演练

 1. 初始化变量`minimum_price`与第一个股票价格。 这是迄今为止我们看到的最便宜的股价，因此是当前最佳的买入机会。 
2. 初始化`maximum_profit`到`0`。 我们从零开始，因为始终允许不进行交易，并且最终答案中的利润永远不会为负。 
3、从第二天开始遍历数组。 对于每个当前价格：

 - 首先，比较一下`minimum_price`。 
- 如果当前价格较低，则更新`minimum_price`因为我们找到了更好的买入机会。 
4、如果当前价格不低于，计算今天卖出的利润：```
current_price - minimum_price
```如果我们当天卖出，这代表了可能获得的最佳利润。 
5. 将此利润与`maximum_profit`。 如果较大则更新`maximum_profit`。 
6. 继续，直到处理完所有日期。 
7. 返回`maximum_profit`。 

### 为什么它有效

 该算法保持一个重要的不变量：在每个索引处`i`,`minimum_price`存储前几天的最低股价`0..i-1`。 

因此，在评估当日卖出时`i`，我们立即知道在此之前可能的最佳购买日。 由于每个有效销售日都被考虑一次，并且我们总是与最便宜的早期价格进行比较，因此该算法保证找到全局最优利润。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        minimum_price = prices[0]
        maximum_profit = 0

        for current_price in prices[1:]:
            if current_price < minimum_price:
                minimum_price = current_price
            else:
                current_profit = current_price - minimum_price
                maximum_profit = max(maximum_profit, current_profit)

        return maximum_profit
```实现首先将第一个股票价格存储为`minimum_price`，因为这是最初唯一可能的购买选择。 

变量`maximum_profit`开始于`0`，确保我们正确处理不存在盈利交易的情况。 

然后我们迭代剩余的价格。 如果我们遇到更便宜的股票价格，我们会更新`minimum_price`，因为未来销售天数应使用最佳可用采购成本。 

如果当前价格大于或等于最低价格，我们计算今天卖出的潜在利润。 我们将其与迄今为止发现的最佳利润进行比较并更新`maximum_profit`如果需要的话。 

最后，处理完所有价格后，我们返回发现的最大利润。 

## 解决方案```go
func maxProfit(prices []int) int {
	minimumPrice := prices[0]
	maximumProfit := 0

	for i := 1; i < len(prices); i++ {
		currentPrice := prices[i]

		if currentPrice < minimumPrice {
			minimumPrice = currentPrice
		} else {
			currentProfit := currentPrice - minimumPrice
			if currentProfit > maximumProfit {
				maximumProfit = currentProfit
			}
		}
	}

	return maximumProfit
}
```Go 实现遵循与 Python 版本完全相同的逻辑，但使用 Go 习惯用法。 

由于约束保证至少一个元素，因此访问`prices[0]`总是安全的。 Go 切片是直接使用的，这里没有 nil 和空切片的区别，因为 LeetCode 保证了有效的输入。 

整数溢出不是问题，因为股票价格受以下限制`10^4`，使利润安全地落在 Go 的范围内`int`类型。

 ## 边缘情况

 **单元素数组**是一种重要的边缘情况，因为不会发生有效的交易。 您不能在只有一天可用的情况下同时进行买卖。 幼稚的实现可能会意外访问无效索引或假设至少存在两个价格。 我们的实现自然地处理了这个问题，因为循环`prices[1:]`变得空虚，离开`maximum_profit`作为`0`。 

**严格递减的价格序列**，例如`[7,6,4,3,1]`，如果算法假设利润必须存在，则很容易引入错误。 在这种情况下，后来的每笔价格都低于前一笔，这意味着每笔交易都会赔钱。 我们的实现正确返回`0`因为`maximum_profit`初始化为零，并且仅在出现正利润时更新。 

**新的最小值出现在数组的最后**，例如`[10,1,10]`，是另一个微妙的情况。 一个幼稚的解决方案可能会错误地锚定第一个值，并错过以后更好的购买机会。 我们的算法不断更新`minimum_price`，确保新发现的更便宜的价格被考虑用于所有未来的交易。 

另一个重要的边缘情况是**重复价格**，例如`[5,5,5,5]`。 由于出售永远不会产生正利润，所以答案应该保持不变`0`。 该实现可以正确处理同等价格，因为利润计算永远不会超过零。
