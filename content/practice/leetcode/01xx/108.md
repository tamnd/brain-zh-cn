[LeetCode 第 108 题](https://leetcode.com/problems/convert-sorted-array-to-binary-search-tree/)

 **难度：** 🟢简单
 **主题：** 数组、分而治之、树、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题给了我们一个排序的整数数组`nums`按照严格递增的顺序，并要求我们将其转换为**高度平衡二叉搜索树（BST）**。 

**二叉搜索树**是一棵二叉树，其中：

 - 左子树中的每个节点都包含小于当前节点的值。 
- 右子树中的每个节点都包含大于当前节点的值。 

**高度平衡**树意味着对于每个节点，其左右子树的高度之差最多为 1。 实际上，树不应该严重偏向一侧，因为偏斜的树的行为更像链表，并且会失去 BST 的效率优势。 

输入是一个排序数组，这很重要，因为排序顺序自然对应于 BST 的中序遍历。 由于 BST 的中序遍历会产生按排序顺序的值，因此面临的挑战是在保留此顺序的同时重建平衡的 BST。 

预期输出是有效高度平衡 BST 的根节点。 重要的是，这个问题**不需要唯一的答案**。 对于同一输入，可能存在多个有效的平衡 BST。 只要生成的树满足 BST 排序和高度平衡条件，它就会被接受。 

这些约束告诉我们一些重要的事情：

 -`1 <= nums.length <= 10^4`意味着输入大小可以适度大，因此应避免低效的方法。 
-`nums`严格递增，意味着没有重复项。 这简化了 BST 构造，因为我们永远不需要决定如何处理相等的值。 
- 值范围为`-10^4`到`10^4`，但值的大小在这里并不是特别重要。 数组的结构比数字本身更重要。 

一些边缘情况值得关注：

 单元素数组，例如`[5]`应该生成一棵只有一个节点的树。 

具有两个元素的数组，例如`[1,3]`可以形成多个有效的平衡BST。 实现不得假设仅存在一种正确的形状。 

当分成左右两半时，非常小的数组是差一错误的常见来源。 

由于保证输入已排序且非空，因此我们不需要验证排序或处理递归基本情况之外的空输入。 

## 方法

 ### 蛮力方法

 一个蛮力的想法是尝试根据给定的数字构造每个可能的 BST，然后检查每棵树是否高度平衡。 

由于数组是有序的，理论上我们可以选择每个元素作为根，递归生成所有可能的左子树和右子树，然后验证生成的树是否平衡并满足 BST 属性。 

这种方法是正确的，因为它探索了整个解决方案空间。 最终，它会找到至少一个有效的平衡 BST。 

然而，这种方法在计算上是不可行的。 可能的 BST 数量按照加泰罗尼亚数字序列呈指数增长。 即使对于中等的输入大小，生成所有可能性也会变得非常昂贵。 

因此，暴力法不适合`n = 10^4`。 

### 最优方法，分而治之

 关键的见解是排序数组已经包含 BST 的中序遍历。 

为了保持树平衡，我们应该将数组的**中间元素**放在根部。 这自然地将剩余元素分成大致相等的两半：

 - 中间左边的元素成为左子树。 
- 右侧的元素成为右子树。 

因为数组是有序的：

 - 左侧元素总是小于根元素。 
- 右侧元素始终大于根元素。 

这会自动满足 BST 排序。 

我们可以对数组的每一半递归地重复相同的过程。 每个递归步骤都会减小问题的大小，从而产生平衡的结构。 

这是一个经典的**分而治之**策略。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 生成许多​​ BST 可能性并验证余额 |
 | 最佳| O(n) | O(log n) | 递归选择中点以保持平衡 |

 ## 算法演练

 ### 最优算法

 1. 定义一个递归辅助函数，该函数使用两个索引作用于子数组范围，`left`和`right`。 

我们不是重复地切片数组，而是传递边界。 这可以避免不必要的复制并保持内存使用效率。 
2. 处理基本情况。 

如果`left > right`，这意味着数组的这一部分中没有剩余元素。 返回`None`（或者`nil`在围棋中）。 
3. 计算中间索引。 

使用：`mid = (left + right) // 2`选择中间元素是因为它可以产生最平衡的分割。 
4. 使用中间元素创建树节点。 

该节点成为当前子树的根。 
5. 递归构造左子树。 

调用左半边的助手：`left`到`mid - 1`由于所有这些值都小于根，因此 BST 排序仍然有效。 
6. 递归构造右子树。 

调用右半部分的助手：`mid + 1`到`right`由于所有这些值都大于根，因此保留了 BST 排序。 
7. 返回构造好的节点。 

递归自然地从下到上组装了完全平衡的 BST。 

### 为什么它有效

 该算法之所以有效，是因为每个递归调用都保留了两个基本的不变量：

 首先，由于数组已排序，因此 BST 排序得以维持。 选择中间元素可确保所有左侧值保持较小且所有右侧值保持较大。 

其次，保持平衡，因为每个子树接收大约一半的剩余元素。 由于递归分割的大小保持接近，子树高度最多相差一，满足高度平衡的要求。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import List, Optional

class Solution:
    def sortedArrayToBST(self, nums: List[int]) -> Optional[TreeNode]:

        def build_tree(left: int, right: int) -> Optional[TreeNode]:
            if left > right:
                return None

            mid = (left + right) // 2

            root = TreeNode(nums[mid])

            root.left = build_tree(left, mid - 1)
            root.right = build_tree(mid + 1, right)

            return root

        return build_tree(0, len(nums) - 1)
```其实现严格遵循前面描述的分而治之的策略。 

嵌套辅助函数`build_tree(left, right)`递归地为数组的特定部分构建子树。 使用索引而不是数组切片可以避免重复分配新列表，从而提高效率。 

基本情况检查当前范围是否无效（`left > right`）。 发生这种情况时，没有要创建的节点，因此`None`被返回。 

选择中间指标以保持平衡。 一个`TreeNode`使用该值创建，然后递归调用使用数组的剩余一半构建左子树和右子树。 

最后从整个数组范围开始递归，`0`到`len(nums) - 1`。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func sortedArrayToBST(nums []int) *TreeNode {

	var buildTree func(left int, right int) *TreeNode

	buildTree = func(left int, right int) *TreeNode {
		if left > right {
			return nil
		}

		mid := (left + right) / 2

		root := &TreeNode{
			Val: nums[mid],
		}

		root.Left = buildTree(left, mid-1)
		root.Right = buildTree(mid+1, right)

		return root
	}

	return buildTree(0, len(nums)-1)
}
```Go 实现遵循与 Python 相同的递归结构。 由于 Go 不直接支持嵌套命名函数，因此函数变量`buildTree`被声明并分配了一个匿名递归函数。 

Go 使用`nil`而不是`None`对于空子指针。 树节点是使用结构体指针来分配的，例如`&TreeNode{}`。 

整数溢出在这里不是问题，因为数组长度限制为`10^4`，但在较大的系统中，一些开发人员更喜欢：```go
mid := left + (right-left)/2
```以避免溢出风险。 

Go 切片是基于引用的，但我们仍然避免重复创建子切片。 传递索引边界可以提高内存效率。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个元素恰好成为一个树节点 |
 | 空间| O(log n) | 平衡树中的递归调用堆栈高度|

 时间复杂度为`O(n)`因为每个数组元素在节点创建期间只被处理一次。 

空间复杂度为`O(log n)`由于递归深度。 由于树保持平衡，递归调用每次大约分成两半，产生对数堆栈使用。 树本身不计为额外空间，因为它是必需的输出。

 ## 边缘情况

 ### 单元素数组

 像这样的输入`[5]`是最小的有效情况。 这很容易暴露递归无法正确终止或子指针处理不当的错误。 

该实现正确处理了这个问题，因为`left == right`，所以中间索引指向单个元素。 创建一个节点，后续的递归调用立即命中该节点`left > right`基本情况。 

### 二元素数组

 输入如`[1,3]`很棘手，因为没有完全居中的中间元素。 不同的中点选择可能会创建不同但仍然有效的平衡树。 

该实现使用整数除法一致地选择一个中点。 无论`1`或者`3`成为根，生成的树保持平衡和有效。 

### 大输入量

 最大输入长度可达`10^4`。 重复对数组进行切片的简单方法可能会产生不必要的内存开销。 

此实现通过传递索引边界完全避免了切片（`left`,`right`）进入递归调用。 这确保了有效的内存使用并维护`O(n)`运行时。 

### 负数和宽值范围

 该数组可能包含负值或非常大的正值。 一些实现意外地依赖于关于积极性的假设。 

该解决方案将值纯粹视为有序整数。 由于 BST 的正确性仅取决于相对顺序，因此负数自然可以工作，无需任何特殊处理。
