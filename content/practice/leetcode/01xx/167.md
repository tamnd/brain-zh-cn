[LeetCode 第 167 题](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个**排序的、1索引的整数数组**，称为`numbers`和一个目标整数`target`。 我们的任务是在数组中找到**恰好两个数字**，其总和等于`target`，然后返回它们的**基于 1 的索引**。 

关键细节是数组已经按**非递减顺序**排序，这意味着值从最小到最大排列，并且允许重复。 与经典的二和问题（其中数组未排序且通常使用哈希映射）不同，此排序属性显着改变了策略。 

输入包括：

 -`numbers`，一个排序的整数数组
 -`target`，我们想要达到的总和

 预期输出是一个长度数组`2`，包含加起来等于目标的两个数字的**从 1 开始的位置**。 

例如：```
numbers = [2,7,11,15], target = 9
```这对`2 + 7 = 9`，它们的指数是`1`和`2`，所以答案是：```
[1,2]
```该问题保证了几个重要的约束：

 - 数组长度最大可达`3 * 10^4`，这意味着低效的二次解可能会变得很慢。 
- 数组已经排序。 
- **只有一个有效的解决方案**。 
- 我们可能**不会重复使用同一元素两次**。 
- 解决方案必须使用**恒定的额外空间**。 

这些保证强烈影响最佳方法。 由于只有一个答案，因此我们不需要处理歧义或多个有效对。 由于数组已排序，我们可以利用排序关系来避免检查每一对。 由于需要恒定的额外空间，因此哈希映射方法虽然在时间上有效，但违反了问题约束。 

一些边缘情况值得预先考虑。 解可能涉及负数，例如`[-1, 0]`。 有效的对可能出现在数组的开头或结尾。 可能存在重复值，例如`[3,3]`，其中相同的数值出现两次，但必须使用不同的索引。 幼稚的实现可能会意外地重用相同的索引，或者在存在重复项时错过有效的对。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试每对可能的数字。 

我们可以使用两个嵌套循环。 对于每个索引`i`，我们检查后面的每个索引`j`并计算：```
numbers[i] + numbers[j]
```如果总和等于`target`, we return the indices.

 这是有效的，因为最终我们会检查每一个可能的对，确保我们找到正确的一对。 由于该问题保证只有一个解决方案，因此当找到一对解决方案时，我们可以立即停止。 

然而，这种方法效率低下。 If the array contains`n`元素，嵌套循环大约检查：```
n * (n - 1) / 2
```最坏情况下成对。 

对于输入大小`30,000`，二次行为变得不必要地昂贵。 

### 最优方法，两个指针

 关键的观察结果是数组已经排序。 

因为数字是有序的，所以我们可以明智地决定如何在数组中移动，而不是检查每一对。 

我们放置：

 - **最左边的元素**有一个指针
 - 一个指针指向**最右边的元素**

 每一步：

 - 计算当前总和
 - 如果总和太小，请将左指针向右移动
 - 如果总和太大，请将右指针向左移动
 - 如果总和与目标匹配，则返回索引

 这是由于排序顺序而起作用的。 

假设总和太小。 由于左值是剩余的最小数字之一，因此减少右指针只会使总和变小。 因此，唯一有意义的举动是增加左指针。 

同样，如果总和太大，则增加左指针将使总和变得更大。 唯一明智的做法是减少右指针。 

这使我们能够有效地消除不可能的候选者，并在线性时间内扫描阵列，同时使用恒定的额外空间。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每对数字 |
 | 最佳| O(n) | O(1) | O(1) | 使用带有两个指针的排序属性 |

 ## 算法演练

 ### 最优算法，两个指针

 1. 初始化两个指针。 

放`left = 0`和`right = len(numbers) - 1`。 

左指针从最小的数字开始，而右指针从最大的数字开始。 
2. 计算当前总和。 

在每次迭代时，计算：```
current_sum = numbers[left] + numbers[right]
```这告诉我们是否低于、高于或正好达到目标。 
3. 将总和与目标进行比较。 

如果`current_sum == target`，我们找到了答案。 

由于问题使用 **1 索引位置**，因此返回：```
[left + 1, right + 1]
```4. 如果总和太小，请移动左指针。 

如果：```
current_sum < target
```那么总和必须增加。 

因为数组是有序的，所以移动`left`向右给我们一个更大的数字。 
5. 如果总和太大，请移动右指针。 

如果：```
current_sum > target
```那么总和必须减少。 

因为数组是有序的，所以移动`right`向左给我们一个较小的数字。 
6. 重复直到找到解决方案。 

由于存在一个有效的解决方案，指针最终将找到它。 

### 为什么它有效

 该算法保持了一个重要的不变量：当前指针范围之外的每一对都已被排除。 

如果总和太小，则使用当前左侧元素和较小右侧元素的任何对也会太小，因此我们可以安全地丢弃当前左侧位置。 

如果总和太大，则使用当前右侧元素与较大左侧元素的任何对也将仍然太大，因此我们可以安全地丢弃当前右侧位置。 

因为我们在不丢失有效解的情况下消除了不可能的候选者，并且因为恰好存在一个解，所以算法保证找到正确的一对。 

## Python 解决方案```python
from typing import List

class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        left = 0
        right = len(numbers) - 1

        while left < right:
            current_sum = numbers[left] + numbers[right]

            if current_sum == target:
                return [left + 1, right + 1]

            if current_sum < target:
                left += 1
            else:
                right -= 1

        return []
```实现首先创建两个指针，`left`和`right`，位于阵列的相对两端。 

在循环内部，我们计算当前指针处的值的总和。 如果这个总和等于目标，我们立即返回调整为**基于 1 的索引**的索引，这是问题所需要的。 

如果总和太小，我们就增加`left`因为较大的值位于排序数组的右侧。 如果总和太大，我们就递减`right`因为较小的值位于左侧。 

循环继续，直到找到正确的对。 尽管该问题保证了有效的解决方案，但最后返回一个空列表使该函数在语法上完整且安全。 

## 解决方案```go
func twoSum(numbers []int, target int) []int {
	left := 0
	right := len(numbers) - 1

	for left < right {
		currentSum := numbers[left] + numbers[right]

		if currentSum == target {
			return []int{left + 1, right + 1}
		}

		if currentSum < target {
			left++
		} else {
			right--
		}
	}

	return []int{}
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

Go 使用切片而不是 Python 列表。 返回的结果是使用以下命令创建的：```go
[]int{left + 1, right + 1}
```对于这个问题的约束来说，Go 整数足够大，因此整数溢出不是问题。 由于该问题保证了一个有效的解决方案，因此后备空切片实际上是无法访问的，但它使函数保持完整。

 ## 边缘情况

 ### 具有重复值的数组

 当存在重复的数字时，会出现常见的错误来源。 例如：```
[3,3], target = 6
```粗心的实现可能会意外地重复使用同一个索引两次。 两指针解决方案避免了这种情况，因为`left`和`right`始终是不同的立场。 即使值相同，指数仍然不同。 

### 负数

 一些实现隐式地假设所有数字都是正数，当出现负数时，这种情况就会中断。 

例如：```
[-1,0], target = -1
```两指针方法仍然有效，因为它仅依赖于排序顺序，而不依赖于正性。 无论符号如何，指针移动决策仍然有效。 

### 边界处的解决方案

 有效对可能涉及第一个和最后一个元素。 

例子：```
[1,2,3,4,10], target = 11
```最佳算法自然会处理这种情况，因为它从两端都有指针开始。 如果最外面的元素形成答案，它会立即返回，而无需进行不必要的工作。 

### 大输入尺寸

 随着数组逼近`30,000`由于二次增长，暴力解决方案变得低效。 

两指针解决方案可有效扩展，因为每个指针仅向内移动一次，即使对于最大的有效输入也能确保线性时间性能。
