[LeetCode 第 102 题](https://leetcode.com/problems/binary-tree-level-order-traversal/)

 **难度：** 🟡 中等
 **主题：** 树、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们对二叉树进行层序遍历。 二叉树是一种分层结构，其中每个节点最多可以有两个子节点，通常称为左子节点和右子节点。 

层序遍历意味着我们从根开始一次访问树的一层。 在同一层内，节点的处理顺序是从左到右。 我们必须返回一个嵌套列表，其中每个内部列表包含特定深度的所有节点值，而不是返回单个平面值列表。 

例如，给定树：```
        3
       / \
      9   20
         /  \
        15   7
```逐级遍历：

 - 0级包含节点`3`- 级别 1 包含节点`9`和`20`- 2 级包含节点`15`和`7`结果变成：```
[[3], [9, 20], [15, 7]]
```输入是二叉树的根节点。 输出必须是列表的列表，其中每个嵌套列表代表树的一层。 

约束告诉我们树最多可以包含 2000 个节点。 这足够小，以至于`O(n)`遍历很容易就足够高效，但又足够大，应该避免低效的重复遍历。 节点值本身对于算法复杂性并不重要，因为它们是小范围内的简单整数。 

一些边缘情况很重要：

 - 树可能是空的，这意味着`root`是`None`在 Python 中或`nil`在围棋中。 在这种情况下，答案应该是一个空列表。 
- 一棵树可能只包含一个节点。 
- 树可能高度不平衡，实际上成为链表。 
- 某些节点可能只有一个子节点。 

正确的实现必须能够无错误地处理所有这些情况。 

## 方法

 ### 蛮力方法

 强力解决方案首先确定树的高度，然后使用递归辅助函数一次处理一个级别。 

该算法的工作原理如下：

 1. 计算树的最大深度。 
2. 对于每个深度`0`到`height - 1`，递归遍历树并收集该深度的所有节点。 
3. 将收集到的节点追加到最终结果中。 

这种方法是正确的，因为每个级别都是独立显式遍历和收集的。 然而，主要缺点是每个级别都会重复遍历树。 

在最坏的情况下，例如高度倾斜的树`n`，每层遍历可能会再次访问几乎所有节点。 这导致`O(n^2)`时间复杂度。 

### 最佳方法

 关键的见解是，级别顺序遍历自然地与广度优先搜索（通常缩写为 BFS）相匹配。 

BFS 按照问题所需的确切顺序处理节点：

 - 访问当前深度的所有节点
 - 然后移动到下一个深度
 - 从左到右处理节点

 队列是 BFS 的理想数据结构，因为它以先进先出的顺序处理元素。 

该算法首先将根放入队列中。 然后，当队列不为空时：

 - 确定有多少个节点属于当前级别
 - 从队列中删除恰好那么多的节点
 - 记录他们的价值观
 - 将他们的孩子添加到下一次迭代的队列中

 每个节点只被访问一次，从而提供高效的`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复遍历树的每一层 |
 | 最佳 | O(n) | O(n) | 使用带有队列的 BFS，访问每个节点一次 |

 ## 算法演练

 ### 最优 BFS 算法

 1. 首先检查树是否为空。 如果根是`None`，立即返回一个空列表，因为没有要遍历的级别。 
2. 创建队列并将根节点插入其中。 队列将帮助按正确的顺序逐级处理节点。 
3. 初始化一个空的结果列表。 这最终将存储树的所有级别。 
4. 开始一个循环，该循环在队列不为空时继续。 该循环的每次迭代只处理树的一层。 
5. 在每次迭代开始时，确定当前队列大小。 该值表示有多少节点属于当前级别，因为当前级别的所有节点都是在上一次迭代期间添加的。 
6. 创建一个名为的空列表`current_level`存储该级别的节点值。 
7. 准确处理`level_size`节点：

 1. 从队列中移除最前面的节点。 
2. 增加其价值`current_level`。 
3. 如果该节点有左子节点，则将其添加到队列中。 
4. 如果该节点有右子节点，则将其添加到队列中。 
8.处理完当前级别的所有节点后，追加`current_level`到结果列表。 
9. 继续直到队列变空，这意味着树中的所有节点都已被处理。 
10.返回最终结果列表。 

### 为什么它有效

 该算法维护一个重要的不变量：在处理级别之前，队列按从左到右的顺序准确包含属于该级别的所有节点。 

通过在处理开始之前记录队列大小，我们确保在迭代期间仅删除当前级别的节点。 处理过程中添加的任何子级都属于下一个级别，并在稍后进行处理。 

由于每个节点都被访问一次并恰好放入一个级别列表中，因此该算法可以正确生成所需的级别顺序遍历。 

## Python 解决方案```python
from collections import deque
from typing import List, Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def levelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if not root:
            return []

        result = []
        queue = deque([root])

        while queue:
            level_size = len(queue)
            current_level = []

            for _ in range(level_size):
                node = queue.popleft()
                current_level.append(node.val)

                if node.left:
                    queue.append(node.left)

                if node.right:
                    queue.append(node.right)

            result.append(current_level)

        return result
```实现首先处理空树的情况。 立即返回可以防止不必要的处理并避免队列错误。 

一个`deque`被使用是因为它提供了有效的`O(1)`从两端插入和移除。 使用普通的 Python 列表进行队列操作会使从前端的删除效率低下。 

队列最初仅包含根节点。 外层`while`循环一次处理一层树。 

在循环内部，`level_size`捕获有多少个节点属于当前级别。 这很关键，因为在遍历期间将添加新的子节点，并且我们不希望它们混合到当前级别中。 

内部循环恰好处理这些节点。 每个节点的值被添加到`current_level`，及其子项将添加到队列中以供将来处理。 

完成关卡后，收集的值将附加到最终结果中。 

一旦队列变空，每个节点都已处理完毕，并返回完整的遍历。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func levelOrder(root *TreeNode) [][]int {
    if root == nil {
        return [][]int{}
    }

    result := [][]int{}
    queue := []*TreeNode{root}

    for len(queue) > 0 {
        levelSize := len(queue)
        currentLevel := []int{}

        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]

            currentLevel = append(currentLevel, node.Val)

            if node.Left != nil {
                queue = append(queue, node.Left)
            }

            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }

        result = append(result, currentLevel)
    }

    return result
}
```Go 实现遵循与 Python 解决方案相同的 BFS 逻辑。 

主要区别在于队列处理。 Go没有提供内置的双端队列结构，因此使用切片作为队列。 删除第一个元素是通过以下方式完成的：```go
queue = queue[1:]
```该实现还明确检查`nil`而不是 Python 的真实性检查。 

Go 切片会随着元素的添加而动态调整大小，使其适合 BFS 遍历队列。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 队列最多可以包含树的一整层 |

 时间复杂度是线性的，因为每个节点只进入和离开队列一次。 

在最坏的情况下，空间复杂度也是线性的。 一棵完全二叉树大致可以有`n/2`最后一级的节点，这意味着队列可以临时存储所有节点的很大一部分。

 ## 边缘情况

 ### 空树

 一棵空树表示为`root = None`在 Python 中或`root == nil`在围棋中。 这种情况很容易被忽视，因为尝试访问空根的子级会导致运行时错误。 

该实现立即通过提前返回来处理此问题：```
if not root:
    return []
```即使没有节点存在，这也保证了安全执行。 

### 高度不平衡的树

 一棵树可能类似于一个链表，其中每个节点只有一个子节点。 例如：```
1
 \
  2
   \
    3
```一些递归方法存在深度递归深度问题的风险，但基于 BFS 队列的解决方案可以自然地处理这个问题。 每个级别只包含一个节点，并且算法仍然只访问每个节点一次。 

### 稀疏的树木和失踪的孩子

 许多二叉树都是不完整的，这意味着某些节点只有一个子节点。 

例如：```
    1
   /
  2
   \
    4
```有缺陷的实现可能会错误地假设两个子级都存在，或者意外地将空值插入队列中。 

此实现在附加每个子项之前显式检查它是否存在：```
if node.left:
    queue.append(node.left)

if node.right:
    queue.append(node.right)
```结果，仅处理有效节点，并且稀疏树正常工作。
