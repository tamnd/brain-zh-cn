[LeetCode 第 174 题](https://leetcode.com/problems/dungeon-game/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定骑士安全穿越地牢并营救公主所需的**最低初始生命值**。 

地牢表示为 2D 网格，其中每个单元格包含一个整数值：

 - **负值**意味着骑士因恶魔而失去生命值。 
- **正值**意味着骑士通过治疗球获得生命值。 
- **零**表示房间没有影响。 

骑士从**左上角**开始，想要到达**右下角**，公主被囚禁在那里。 每次移动，他只能**向右**或**向下**。 

重要的限制是骑士的生命值必须**始终保持严格大于0**。 如果他的健康状况变得`0`或任何时候呈阴性，他都会立即死亡。 

我们没有被要求最大化骑士的剩余生命值。 相反，我们必须确定保证公主一路生存的**最小初始生命值**。 

### 重述问题

 我们想要找到最小的起始 HP，使得遵循最优路径`(0,0)`到`(m-1,n-1)`，骑士永远不死。 

这很微妙，因为最佳路径不一定是总和最高的路径。 如果骑士在到达之前死亡，那么稍后提供大量治疗的路径可能仍然是不可能的。 

例如：```
[-100, +1000]
```即使总收益为正，骑士至少仍需要`101`HP 在第一个房间中生存下来。 

这告诉我们，问题本质上是关于**生存限制**，而不是最大化奖励。 

### 了解限制

 网格尺寸满足：

 -`1 <= m, n <= 200`这意味着最多可以有：```
200 × 200 = 40,000 cells
```强力路径搜索是不可行的，因为可能的右/下路径的数量呈指数增长。 

每个单元格值位于：```
-1000 <= dungeon[i][j] <= 1000
```这些值对于标准整数算术来说足够小。 

约束大小强烈表明我们需要一个**多项式时间动态规划解决方案**，理想情况下大约是`O(m × n)`。 

### 重要的边缘案例

 一些边缘情况很容易破坏一个简单的解决方案。 

**单细胞地牢**很重要，因为骑士在同一个房间里开始和结束。 如果该值为负数，则立即需要额外的生命值。 如果为零或正数，则答案始终是`1`。 

充满**正值**的地牢是另一个关键案例。 尽管骑士到处都能获得生命值，但他至少还需要`1`惠普最初是因为健康必须始终保持积极的态度。 

路径起点附近的大负值是危险的，因为骑士可能会在到达后面的治疗室之前死亡。 

最后，最优路径不一定是总和最大的路径。 具有更好生存能力的路径可以暂时避免大的损害，即使它的总体奖励较小。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试从左上角到右下角的**所有可能的路径**。 

对于每条路径，我们都会模拟骑士的旅程，并确定在特定的房间序列中生存所需的最低初始生命值。 

计算路径所需 HP 的一种方法是跟踪累积的运行状况变化并找到达到的最低点。 如果最小累计和是`-x`，那么我们至少需要`x + 1`开始健康。 

由于骑士只能向右或向下移动，因此路径数为：```
C(m+n-2, m-1)
```对于大型网格来说，这个值呈指数级增长。 

对于一个`200 × 200`网格，蛮力变得完全不切实际。 

### 关键见解

 关键的认识是，**向前思考很困难**，但**向后思考很容易**。 

而不是问：

 > “我现在的生命值是多少？”

 我们问：

 > “进入这个房间时我必须有多少生命值才能安全到达公主身边？”

 这将问题转化为动态规划。 

假设我们站在牢房前`(r, c)`。 

我们可以移动：

 - 有权`(r, c+1)`- 下降到`(r+1, c)`如果我们已经知道这些未来细胞所需的最低健康状况，那么：```
required_health =
min(right_requirement, down_requirement)
```因为我们会选择更便宜的路径。 

然后我们调整当前房间值：```
needed = future_requirement - dungeon[r][c]
```但健康永远不能低于`1`， 所以：```
dp[r][c] = max(1, needed)
```这自然会导致**自下而上的动态编程**解决方案。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(m+n) | 尝试每条有效路径 |
 | 最优动态规划| O(m × n) | O(m × n) | 向后计算所需的最低生命值 |

 ## 算法演练

 ### 最优动态规划策略

 我们定义：```
dp[r][c]
```如：

 > The minimum health required when entering cell`(r, c)`这样骑士最终就能救出公主。 

我们从**右下角到左上角**计算此表。 

1. **初始化DP表**

 创建一个`m × n`表在哪里`dp[r][c]`存储该单元所需的最低 HP。 
2. **处理公主牢房**

 在右下角，骑士必须在房间中幸存下来并仍然活着。 

公式：```
dp[m-1][n-1] =
max(1, 1 - dungeon[m-1][n-1])
```为什么？ 

- 如果房间为负数，则需要额外的生命值。 
- 如果房间为正或零，则仅`1`需要 HP。 
3. **填写最后一行**

 在最后一行，只能向右移动。 

所以：```
dp[r][c] =
max(1, dp[r][c+1] - dungeon[r][c])
```4. **填写最后一栏**

 在最后一列中，运动仅向下。 

所以：```
dp[r][c] =
max(1, dp[r+1][c] - dungeon[r][c])
```5. **填充剩余单元格**

 对于内部电池，我们选择未来两条路径中更便宜的一条：```
min_health_next =
min(dp[r+1][c], dp[r][c+1])
```然后计算：```
dp[r][c] =
max(1, min_health_next - dungeon[r][c])
```6. **返回答案**

 左上角的单元格包含最小初始生命值：```
dp[0][0]
```### 为什么它有效

 不变量是：

 >`dp[r][c]`始终代表进入时所需的最低HP`(r, c)`to guarantee survival to the princess.

 Since every state only depends on already-computed future states, and we always choose the cheaper valid future path, the recurrence guarantees optimality. 这`max(1, ...)`条件确保骑士永远不会在房间死亡或生命值为零的情况下开始。 

## Python 解决方案```python
from typing import List

class Solution:
    def calculateMinimumHP(self, dungeon: List[List[int]]) -> int:
        rows = len(dungeon)
        cols = len(dungeon[0])

        dp = [[0] * cols for _ in range(rows)]

        # Princess cell
        dp[rows - 1][cols - 1] = max(
            1,
            1 - dungeon[rows - 1][cols - 1]
        )

        # Last row
        for col in range(cols - 2, -1, -1):
            dp[rows - 1][col] = max(
                1,
                dp[rows - 1][col + 1] - dungeon[rows - 1][col]
            )

        # Last column
        for row in range(rows - 2, -1, -1):
            dp[row][cols - 1] = max(
                1,
                dp[row + 1][cols - 1] - dungeon[row][cols - 1]
            )

        # Remaining cells
        for row in range(rows - 2, -1, -1):
            for col in range(cols - 2, -1, -1):
                min_health_next = min(
                    dp[row + 1][col],
                    dp[row][col + 1]
                )

                dp[row][col] = max(
                    1,
                    min_health_next - dungeon[row][col]
                )

        return dp[0][0]
```实现直接遵循动态规划策略。 

First, we allocate a`dp`与地牢大小相同的矩阵。 每个条目代表进入该房间之前所需的最低生命值。 

我们初始化公主单元，因为它充当基本情况。 从那里开始，我们分别处理最后一行和最后一列，因为这些位置只有一个有效的移动方向。 

最后，我们以相反的顺序填充剩余的单元格，从右下角到左上角。 在每个单元格中，我们选择更便宜的未来路径并计算在当前房间中生存需要多少生命值。 

答案自然就出现在`dp[0][0]`，代表起始位置所需的最低生命值。 

## 解决方案```go
func calculateMinimumHP(dungeon [][]int) int {
	rows := len(dungeon)
	cols := len(dungeon[0])

	dp := make([][]int, rows)
	for i := range dp {
		dp[i] = make([]int, cols)
	}

	// Princess cell
	dp[rows-1][cols-1] = max(
		1,
		1-dungeon[rows-1][cols-1],
	)

	// Last row
	for col := cols - 2; col >= 0; col-- {
		dp[rows-1][col] = max(
			1,
			dp[rows-1][col+1]-dungeon[rows-1][col],
		)
	}

	// Last column
	for row := rows - 2; row >= 0; row-- {
		dp[row][cols-1] = max(
			1,
			dp[row+1][cols-1]-dungeon[row][cols-1],
		)
	}

	// Remaining cells
	for row := rows - 2; row >= 0; row-- {
		for col := cols - 2; col >= 0; col-- {
			minHealthNext := min(
				dp[row+1][col],
				dp[row][col+1],
			)

			dp[row][col] = max(
				1,
				minHealthNext-dungeon[row][col],
			)
		}
	}

	return dp[0][0]
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有提供内置的`min`和`max`整数函数，辅助函数是手动实现的。 

这`dp`表是使用切片的切片创建的。 由于该问题保证了一个非空网格，因此不需要特殊的 nil 处理。 

整数溢出不是问题，因为最大可能的健康要求安全地保持在 Go 的整数范围内。

 ## 边缘情况

 **单细胞地牢**很容易处理不当，因为骑士在同一个房间里开始和结束。 如果房间包含负值，例如`-5`，骑士必须带着足够的HP进入才能立即生存，这意味着`6`。 该实现通过公主单元的基本情况初始化自然地处理这个问题。 

如果实施假设始终需要额外的生命值，则**只有正值**的地下城可能会导致逻辑错误。 即使每个房间都能治愈骑士，生命值仍必须从零开始。 这`max(1, ...)`条件保证最小答案永远不会低于`1`。 

**早期大量伤害随后得到大量治疗**的案例可以打破贪婪的思维。 例如：```
[-100, 1000]
```即使总增益为正，骑士仍然需要`101`HP 在第一个房间中生存下来。 后向 DP 公式正确地捕捉到了这一点，因为它计算进入每个房间之前所需的最低生命值，而不是关注总累积增益。 

当**总奖励最高的路径不是最佳**时，就会出现另一种微妙的边缘情况。 幼稚的策略可能会最大化获得的总生命值，但生存能力比总和更重要。 通过最大限度地减少每一步所需的未来运行状况，DP 解决方案会自动选择最安全的路径。
