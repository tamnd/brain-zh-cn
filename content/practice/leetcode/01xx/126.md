[LeetCode 第 126 题](https://leetcode.com/problems/word-ladder-ii/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、回溯、广度优先搜索

 ## 解决方案

 ## 问题理解

 这个问题要求我们从以下位置找到**所有最短的变换序列**`beginWord`到`endWord`，其中每个转换恰好改变一个字符，并且每个中间单词必须存在于`wordList`。 

我们可以将问题视为浏览图表。 每个单词都是一个节点，如果两个单词恰好相差一个字符，则将它们连接起来。 开始于`beginWord`，我们想要达到`endWord`使用最少数量的变换。 然而，与更简单的字梯问题不同，我们不仅仅要求最短距离。 我们必须返回**每条可能的最短路径**。 

例如，考虑：```
hit -> hot -> dot -> dog -> cog
```和```
hit -> hot -> lot -> log -> cog
```两条路径均到达`"cog"`使用相同的最小转换次数，因此两者都必须包含在答案中。 

输入包括：

 -`beginWord`，起始词。 
-`endWord`，目标词。 
-`wordList`，有效中间词的字典。 

输出是一个序列列表，其中每个序列代表一个有效的最短变换`beginWord`到`endWord`。 

这些约束告诉我们一些重要的事情：

 - 最多字长很小`5`。 
- 字数最多为`500`。 
- 所有单词均为小写英文字母。 
- 最短序列的总数不超过`10^5`。 

虽然`500`字数不是很大，可能的转换路径的数量可以呈指数级增长。 探索所有可能路径的天真的搜索很快就会变得不切实际。 

一个特别重要的保证是`wordList`包含独特的单词。 另一个重要的细节是`beginWord`**不需要**需要存在于`wordList`。 

有几种边缘情况需要考虑：

 - 如果`endWord`不在`wordList`，不可能进行有效的转换。 
- 可能存在多个最短路径，并且必须返回所有路径。 
- 如果我们不小心重新审视单词，就会出现循环。 
- 如果存在较短的有效路径，则不应包含较长的有效路径。 
-`beginWord`和`endWord`保证是不同的。 

## 方法

 ### 蛮力方法

 一个简单的想法是将其视为回溯问题。 开始于`beginWord`，我们尝试字典中存在的每一种可能的单字母转换，递归地探索所有有效路径，直到达到`endWord`。 

为了避免无限循环，我们为当前路径维护一个访问集。 每当我们到达`endWord`，我们将路径长度与迄今为止找到的最短路径进行比较。 如果当前路径较短，我们将替换结果。 如果它与最短长度相关，我们将其添加到结果列表中。 

这种方法是正确的，因为它探索了每一个可能的有效转换序列。 最终，所有最短路径都被发现。 

然而，它的效率极低。 由于每个单词可能分支成许多邻居，因此搜索树呈指数增长。 在最坏的情况下，我们会在确定最短路径之前探索大量不必要的路径。 

效率低下的关键在于暴力破解不会优先考虑较短的路径。 即使已经存在较短的路线，它也会探索较长的路径。 

### 最佳解决方案的关键见解

 关键的观察是，**广度优先搜索 (BFS)** 自然地发现未加权图中的最短路径。 

由于每个转换只花费一个步骤，因此词图是一个未加权的图。 BFS逐级探索节点，意味着我们第一次到达`endWord`，我们知道我们处于最短距离。 

然而，有一个复杂的情况。 我们不想要一条最短路径，我们想要**所有最短路径**。 

我们不是存储每个单词的单个前身，而是存储**在同一最短级别发现的所有有效父项**。 然后，在 BFS 完成后，我们执行 **DFS 回溯**`endWord`回到`beginWord`重建每个最短序列。 

这给了我们两全其美的好处：

 - BFS保证最短距离。 
- DFS 重建每条最短路径。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 探索每一条转型路径 |
 | 最佳| O(N × L × 26 + P) | O(N + P) | BFS 用于最短路径，DFS 用于重建 |

 在哪里：

-`N`是字数。 
-`L`是字长。 
-`P`是所有最短序列的总大小。 

## 算法演练

 ### 第 1 步：验证输入

 首先，我们转换`wordList`进入哈希集以进行恒定时间查找。 

如果`endWord`该集合中不存在，我们立即返回一个空列表。 由于每个中间词都必须来自`wordList`，到达目的地变得不可能。 

### 步骤 2：准备 BFS 结构

 我们初始化一个 BFS 队列，从`beginWord`。 

我们还维护：

 -`parents`，一个哈希映射，其中每个单词存储可以通过最短路径到达它的所有前驱单词。 
-`visited`，一组全局访问过的单词。 
-`found_end`，一个布尔标志，指示我们是否到达`endWord`。 

这`parents`地图是最重要的结构。 与传统的 BFS 只存储一个父项不同，这里我们存储多个父项，因为多个最短路径可能会收敛到同一个单词。 

例如：```
dog -> cog
log -> cog
```两个都`"dog"`和`"log"`是的父母`"cog"`。 

### 步骤 3：逐级运行 BFS

 我们一次处理一层队列。 

对于每个单词：

 1.改变各个角色的位置。 
2.尝试全部替换`26`小写字母。 
3. 生成候选变换词。 
4. 检查字典中是否存在转换后的单词。 

如果转换后的单词有效：

 - 如果没有被全局访问过，则将其添加到当前级别。 
- 将当前单词记录为父项。 

重要的是，我们延迟将节点标记为全局访问，直到**整个 BFS 级别完成**。 

这可以防止我们意外删除在相同深度发现的替代最短路径。 

例如：```
dot -> dog
lot -> log
dog -> cog
log -> cog
```如果`"cog"`之后立即被标记为已访问`"dog"`发现它，`"log"`将失去注册为另一位最矮父母的机会。 

### 步骤 4：在最短水平后停止

 曾经`endWord`找到后，我们在完成当前关卡后停止 BFS。 

我们不再继续更深的层次，因为 BFS 保证任何更深的层次都会产生更长的路径。 

### 步骤 5：使用 DFS 回溯

 现在我们重建所有最短序列。 

开始于`endWord`，我们使用递归向后移动`parents`地图直到到达`beginWord`。 

因为重建是向后发生的，所以我们在存储之前反转路径。 

例如：```
cog -> dog -> dot -> hot -> hit
```变成：```
hit -> hot -> dot -> dog -> cog
```### 为什么它有效

 正确性来自于 BFS 的属性，即按照距离递增的顺序来探索节点。 因此，达到的第一个级别`endWord`必须表示最小变换长度。 

通过存储在相同 BFS 深度发现的所有有效父节点，我们保留了每条最短路径。 然后，DFS 重建准确地枚举那些最短路径，不再枚举。 

## Python 解决方案```python
from typing import List
from collections import defaultdict, deque

class Solution:
    def findLadders(
        self,
        beginWord: str,
        endWord: str,
        wordList: List[str]
    ) -> List[List[str]]:

        word_set = set(wordList)

        if endWord not in word_set:
            return []

        parents = defaultdict(list)
        queue = deque([beginWord])
        visited = {beginWord}
        found_end = False

        while queue and not found_end:
            level_visited = set()

            for _ in range(len(queue)):
                current_word = queue.popleft()
                word_chars = list(current_word)

                for i in range(len(word_chars)):
                    original_char = word_chars[i]

                    for char_code in range(26):
                        new_char = chr(ord('a') + char_code)

                        if new_char == original_char:
                            continue

                        word_chars[i] = new_char
                        next_word = ''.join(word_chars)

                        if next_word not in word_set:
                            continue

                        if next_word not in visited:
                            if next_word not in level_visited:
                                queue.append(next_word)
                                level_visited.add(next_word)

                            parents[next_word].append(current_word)

                            if next_word == endWord:
                                found_end = True

                    word_chars[i] = original_char

            visited.update(level_visited)

        if not found_end:
            return []

        result = []
        path = [endWord]

        def backtrack(word: str) -> None:
            if word == beginWord:
                result.append(path[::-1])
                return

            for parent in parents[word]:
                path.append(parent)
                backtrack(parent)
                path.pop()

        backtrack(endWord)

        return result
```实现从转换开始`wordList`到一个集合中以进行有效的成员资格检查。 

BFS 阶段构建`parents`图形。 对于每个单词，我们通过用所有可能的小写字母修改每个字符位置来生成相邻单词。 每当找到有效的转换时，我们都会将关系存储在`parents`。 

使用`level_visited`尤为重要。 它确保保留在同一 BFS 级别中发现的多个最短父代。 

一旦 BFS 完成，递归`backtrack`函数重建每条最短路径。 开始于`endWord`，它遵循所有父关系，直到`beginWord`已达到。 

## 解决方案```go
package main

func findLadders(beginWord string, endWord string, wordList []string) [][]string {
	wordSet := make(map[string]bool)

	for _, word := range wordList {
		wordSet[word] = true
	}

	if !wordSet[endWord] {
		return [][]string{}
	}

	parents := make(map[string][]string)

	queue := []string{beginWord}
	visited := map[string]bool{
		beginWord: true,
	}

	foundEnd := false

	for len(queue) > 0 && !foundEnd {
		levelVisited := make(map[string]bool)
		levelSize := len(queue)

		for i := 0; i < levelSize; i++ {
			currentWord := queue[0]
			queue = queue[1:]

			wordChars := []byte(currentWord)

			for j := 0; j < len(wordChars); j++ {
				originalChar := wordChars[j]

				for c := byte('a'); c <= 'z'; c++ {
					if c == originalChar {
						continue
					}

					wordChars[j] = c
					nextWord := string(wordChars)

					if !wordSet[nextWord] {
						continue
					}

					if !visited[nextWord] {
						if !levelVisited[nextWord] {
							queue = append(queue, nextWord)
							levelVisited[nextWord] = true
						}

						parents[nextWord] = append(
							parents[nextWord],
							currentWord,
						)

						if nextWord == endWord {
							foundEnd = true
						}
					}
				}

				wordChars[j] = originalChar
			}
		}

		for word := range levelVisited {
			visited[word] = true
		}
	}

	if !foundEnd {
		return [][]string{}
	}

	result := [][]string{}
	path := []string{endWord}

	var backtrack func(string)

	backtrack = func(word string) {
		if word == beginWord {
			reversed := make([]string, len(path))

			for i := range path {
				reversed[i] = path[len(path)-1-i]
			}

			result = append(result, reversed)
			return
		}

		for _, parent := range parents[word] {
			path = append(path, parent)
			backtrack(parent)
			path = path[:len(path)-1]
		}
	}

	backtrack(endWord)

	return result
}
```Go 的实现与 Python 版本非常相似。 由于Go不提供内置的双端队列，因此使用切片作为队列。 

映射用于恒定时间查找：

 -`wordSet`替换Python集。 
-`parents`存储前任关系。 
-`visited`和`levelVisited`跟踪 BFS 进度。 

重建路径时，Go 需要手动反转，因为切片不支持 Python 风格的切片。 

## 工作示例

 ### 示例 1

```反转：```

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N × L × 26 + P) | BFS 探索单词并生成邻居，DFS 输出最短路径 |
 | 空间| O(N + P) | 父图、访问集、队列和结果存储 |

 这里：

-`N`是字数。 
-`L`是字长。 
-`P`是所有最短序列的总大小。 

对于 BFS 中处理的每个单词，我们尝试`L × 26`转变。 由于在 BFS 中每个有效单词最多被访问一次，因此这部分仍然有效。 

DFS 阶段取决于存在多少条最短路径。 由于问题明确地将总输出大小限制为`10^5`，重建仍然是可控的。

 ## 边缘情况

 ###`endWord`不存在于`wordList`这是最常见的失败案例之一。 幼稚的实现可能仍然运行 BFS 并浪费时间搜索无法到达的转换。 

实现立即处理这个问题：```
if endWord not in word_set:
    return []
```这保证了快速终止。 

### 同一级别的多个最矮父母

 当节点过早被标记为已访问时，就会出现一个微妙的错误。 

认为：```
dog -> cog
log -> cog
```如果`"cog"`之后立即成为全球访问者`"dog"`发现它，`"log"`无法将自己注册为另一个有效的父级。 

该解决方案通过使用延迟访问来解决此问题`level_visited`。 只有在整个 BFS 层完成后，节点才会被标记为全局访问。 

### 存在更长的有效路径

 可能有许多有效的转换序列，但只应返回最短的序列。 

例如：```
aaa -> aab -> abb -> bbb
aaa -> aac -> acc -> ccc -> bbb
```第二条路径有效但更长。 

因为BFS是逐层探索的，到达第一层后就停止了`endWord`，较长的路径永远不会包含在父图中。 

### 变换图中的循环

 词的变换自然会产生循环。 

例如：```
hot -> dot
dot -> hot
```如果没有仔细的访问跟踪，DFS 或 BFS 可能会永远循环。 

这`visited`set 可以防止重新访问已经处理过的 BFS 级别，确保图在最短路径构建方面保持非循环。
