[LeetCode 第 195 题](https://leetcode.com/problems/tenth-line/)

 **难度：** 🟢简单
 **主题：** 外壳

 ## 解决方案

 ## 问题理解

 此问题要求我们准确打印名为的文本文件中的第 10 行`file.txt`。 该文件包含多行纯文本，每行由换行符分隔。 

输入不像许多算法问题那样作为函数参数提供。 相反，该解决方案必须直接使用 shell 脚本环境中的文件。 预期输出是第 10 行的内容，打印的内容与文件中的显示完全相同。 

问题陈述还提出了一个重要问题：如果文件包含的内容少于 10 行，会发生什么情况？ 在这种情况下，正确的行为是不打印任何内容。 当请求的行不存在时，大多数 shell 实用程序自然会以这种方式运行。 

尽管这被标记为“简单”问题，但它旨在测试对标准 Unix 文本处理工具的熟悉程度。 该问题暗示至少存在三种不同的方法，这意味着了解多个 shell 实用程序是有价值的。 

从计算角度来看，关键限制很小，但挑战在于有效且简洁地使用 shell 命令。 由于文件理论上可能很大，因此有效的解决方案应该避免不必要的存储或处理。 

一些边缘情况很重要：

 - 文件包含的行数可能少于 10 行。 
- 文件可能包含空行。 
- 第 10 行可能包含空格或特殊字符。 
- 文件可能非常大，导致完整文件存储效率低下。 

正确的实现必须干净地处理所有这些情况。 

## 方法

 ### 蛮力方法

 暴力的想法是将整个文件读入内存，存储每一行，然后打印索引 9 处的元素，因为行编号从 1 开始，而数组索引从 0 开始。 

例如，脚本可以逐行迭代文件，将每一行附加到一个数组中，最后打印第 10 个条目（如果存在）。 

这种方法之所以有效，是因为每一行都被保留，因此之后访问第 10 行很简单。 然而，对于大文件来说，它的效率很低，因为当只需要一行时，它不必要地存储整个内容。 

时间复杂度是线性的，因为仍然必须读取每一行。 空间复杂度也是线性的，因为所有行都被存储。 

### 最佳方法

 更好的解决方案是将文件作为流处理，并在到达第 10 行时停止。 Unix 工具，例如`sed`,`awk`， 和`head`结合`tail`是理想的选择。 

关键的见解是我们不需要记住之前的所有行。 我们只关心一个特定的行号。 由于 shell 实用程序是为流处理而设计的，因此它们可以顺序读取文件并立即打印所需的行。 

例如：

-`sed -n '10p' file.txt`仅打印第 10 行。 
-`awk 'NR==10' file.txt`当记录数达到 10 时打印该行。 
-`head -n 10 file.txt | tail -n 1`首先提取前 10 行，然后打印其中的最后一行。 

这些解决方案内存效率高，因为它们增量处理文件而不是存储所有内容。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 读取并存储整个文件 |
 | 最佳| O(n) | O(1) | O(1) | 流式传输文件并仅打印第 10 行 |

## Python 解决方案

 尽管最初的问题需要 shell 脚本，但下面是演示相同逻辑的 Python 等效脚本。```python
from typing import Optional

class Solution:
    def tenthLine(self, file_path: str) -> Optional[str]:
        with open(file_path, "r") as file:
            for line_number, line in enumerate(file, start=1):
                if line_number == 10:
                    return line.rstrip("\n")

        return None
```此实现打开文件并使用迭代逐行处理它。 这`enumerate`函数跟踪从 1 开始的当前行号。 

一旦循环到达第 10 行，该方法就会在删除尾随换行符后返回该行。 这避免了存储不必要的数据并反映了 shell 实用程序的高效流行为。 

如果文件在到达第 10 行之前结束，则函数返回`None`，表明请求的行不存在。 

## 解决方案```go
package main

import (
	"bufio"
	"os"
)

func tenthLine(filePath string) string {
	file, err := os.Open(filePath)
	if err != nil {
		return ""
	}
	defer file.Close()

	scanner := bufio.NewScanner(file)
	lineNumber := 0

	for scanner.Scan() {
		lineNumber++

		if lineNumber == 10 {
			return scanner.Text()
		}
	}

	return ""
}
```Go 解决方案使用`bufio.Scanner`增量读取文件。 这是内存高效的，因为它一次处理一行而不是加载整个文件。 

与 Python 不同，Go 在打开文件时需要显式的错误处理。 如果无法打开文件，该函数将返回一个空字符串。 

扫描仪会自动删除换行符，因此不需要额外的修剪。

## 边缘情况

 ### 文件包含的行数少于 10 行

 这是最重要的边缘情况。 幼稚的实现可能会尝试访问不存在的行并产生错误。 

提供的实现可以安全地处理这个问题。`sed`和`awk`当第 10 行不存在时，自然不打印任何内容。 Python解决方案返回`None`，而 Go 版本返回一个空字符串。 

### 文件中的空行

 文件可能包含空行，但它们仍然算作行。 

例如：```
Line 1

Line 3
```空的第二行仍然会增加行计数器。 无论内容如何，​​实现都会正确计算每个换行符分隔的记录。 

### 非常大的文件

 将整个文件存储在内存中的解决方案对于大量输入可能会变得低效。 

最佳解决方案通过增量处理文件来避免此问题。 一次仅在内存中保存一行，使得该方法即使对于非常大的文件也是可扩展的。 

### 特殊字符或空格

 行可能包含空格、制表符或特殊字符。 

命令如`awk`和`sed`与 Python 和 Go 实现一起，保留与写入完全相同的行内容，确保正确的输出，而不会发生意外的格式更改。
