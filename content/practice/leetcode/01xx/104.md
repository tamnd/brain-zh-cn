[LeetCode 第 104 题](https://leetcode.com/problems/maximum-depth-of-binary-tree/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们确定二叉树的**最大深度**。 二叉树由节点组成，其中每个节点最多可以有两个子节点，一个左子节点和一个右子节点。 树的深度定义为从根节点到最远叶节点的最长路径上的节点数。 

简单来说，我们需要找出树中有多少层。 从根节点开始，我们向下移动到子节点，我们想要最深可能路径的长度。 叶节点是没有子节点的节点，因此最大深度对应于从根可到达的最深叶节点。 

输入是`root`的二叉树。 该根节点代表整个树结构的入口点。 每个节点都包含一个值以及对其左右子节点的引用。 输出是一个整数，表示从根到叶的最长路径上遇到的最大节点数。 

约束告诉我们树可以包含以下任意位置`0`到`10^4`节点。 由于输入大小可能变得相当大，因此我们应该避免不必要的昂贵操作。 节点值本身的范围在`-100`和`100`，但这些值与解决问题无关，因为深度仅取决于结构，而不取决于节点内容。 

几个重要的边缘案例立即脱颖而出。 树可能是空的（`root = None`），在这种情况下最大深度是`0`。 树可能只包含一个节点，答案是`1`。 另一个重要的情况是高度不平衡的树，其中节点本质上形成链表。 在这种情况下，递归深度可能会变大，但算法仍然必须正确计算路径长度。 该问题保证了有效的二叉树结构，因此我们不需要处理格式错误的输入。 

## 方法

 ### 蛮力方法

 思考这个问题的一种强力方法是枚举每条从根到叶的路径并显式计算每条路径的长度，然后返回最大值。 我们可以遍历树，记录到叶子的每条完整路径，然后比较它们的长度。 

这种方法是正确的，因为每一条可能的根到叶路径都会被探索，保证找到最长的一条。 然而，它不必要地昂贵，因为即使我们只需要最大深度，我们也存储完整路径信息。 维护所有路径会在内存和实现复杂性方面带来可避免的开销。 

### 最佳方法

 关键的观察是树的深度可以递归地定义。 

对于任意节点：

 - 其子树的最大深度等于：`1 + max(depth(left subtree), depth(right subtree))`这是可行的，因为从当前节点到叶子节点的每条路径都必须继续通过左子节点或右子节点。 因此，如果我们已经知道两个子树的深度，我们可以通过取较大的一个并为当前节点本身加一来确定当前节点的深度。 

这自然表明了**深度优先搜索（DFS）**递归解决方案。 我们递归地计算左子树和右子树的深度，然后返回较大的值加一。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 遍历每个节点并不必要地存储根到叶路径 |
 | 最佳| O(n) | O(h) | DFS递归直接计算深度，其中`h`是树高 |

 ## 算法演练

 我们将使用递归深度优先搜索策略。 

1. **处理空节点的基本情况**

 如果当前节点是`None`， 返回`0`。 这表示深度为零的空子树。 此基本情况可防止无限递归并提供停止条件。 
2. **递归计算左子树深度**

 调用相同的函数`root.left`。 这给出了通过左子节点可到达的最大深度。 
3. **递归计算右子树深度**

 调用该函数`root.right`。 这给出了通过右子节点可达到的最大深度。 
4. **选择更深的子树**

 使用比较左子树和右子树的深度`max()`。 由于最长的路径决定了答案，因此我们只关心更深的分支。 
5. **包含当前节点**

 添加`1`解释当前节点本身并返回结果。 
6. **向上传播答案**

 每个递归调用将其计算的深度返回给其父级，直到根最终接收到最大树深度。 

### 为什么它有效

 该算法之所以有效，是因为二叉树的递归特性。 每个子树本身都是一棵二叉树，这意味着相同的逻辑适用于每个级别。 对于任何节点，最大深度必须等于一加上其子节点的较大深度。 由于递归自下而上正确地计算子树深度，因此根最终接收到整个树的最大深度。 基本情况保证空子树的正确性。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        if root is None:
            return 0

        left_depth = self.maxDepth(root.left)
        right_depth = self.maxDepth(root.right)

        return 1 + max(left_depth, right_depth)
```该实现直接反映了树深度的递归定义。 

第一个条件检查当前节点是否为`None`。 如果是，则返回`0`，因为空树没有贡献深度。 

接下来，该函数递归计算左子树的深度并将其存储在`left_depth`。 它对右子树执行相同的操作`right_depth`。 

最后，该函数比较两个子树深度，选择较大的一个，然后添加`1`包括当前节点。 该值通过递归调用堆栈向上返回，直到根收到最终答案。 

代码保持简洁，因为递归关系与问题定义完美匹配。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func maxDepth(root *TreeNode) int {
    if root == nil {
        return 0
    }

    leftDepth := maxDepth(root.Left)
    rightDepth := maxDepth(root.Right)

    if leftDepth > rightDepth {
        return leftDepth + 1
    }

    return rightDepth + 1
}
```Go 实现遵循与 Python 版本完全相同的递归结构。 主要区别在于如何`nil`被用来代替`None`对于空节点。 

Go 没有提供内置的`max()`整数函数，所以我们手动比较`leftDepth`和`rightDepth`与一个`if`陈述。 

由于问题约束完全保持在标准整数限制内，因此整数溢出不是问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用堆栈存储到树的高度`h`|

 时间复杂度为`O(n)`因为树中的每个节点都只被处理一次。 在每个节点，仅执行恒定时间的工作，即递归调用和比较。 

空间复杂度为`O(h)`， 在哪里`h`是树的高度。 这来自递归堆栈。 在平衡树中，`h = O(log n)`，而在完全倾斜的树的最坏情况下，`h = O(n)`。

 ## 边缘情况

 ### 空树

 当出现空树时`root`是`None`。 如果代码假设节点始终存在并立即尝试访问子指针，则很容易导致错误。 我们的实现通过基本情况安全地处理这个问题：```
if root is None:
    return 0
```这保证了空树正确返回深度`0`。 

### 单节点树

 仅包含一个节点的树是另一种常见的边缘情况。 由于根也是叶子，因此最大深度应该是`1`。 一些实现意外返回`0`如果他们计算边而不是节点。 我们的实现正确返回`1`因为它为当前节点添加了 1。 

### 高度倾斜的树

 每个节点只有一个子节点的树的行为类似于链表。 例如：```
1
 \
  2
   \
    3
```这种情况很重要，因为递归深度等于节点数。 设计不当的实现可能会错误地提前停止或无法一致地探索一侧。 我们的递归 DFS 正确遍历每个节点，并通过在每一层重复添加一个节点来积累适当的深度。
