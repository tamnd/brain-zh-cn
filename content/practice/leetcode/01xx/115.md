[LeetCode 第 115 题](https://leetcode.com/problems/distinct-subsequences/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算一个字符串有多少个**不同的子序列**`s`等于另一个字符串`t`。 

子序列是通过从字符串中删除零个或多个字符**而不改变剩余字符的相对顺序**而形成的。 例如，`"rabbit"`是一个子序列`"rabbbit"`因为我们可以删除三个中的一个`'b'`字符同时保持顺序。 

关键细节是我们正在计算**不同的方式**来形成`t`，不仅仅是检查是否`t`可以形成。 指数的不同选择`s`计为单独的子序列，即使结果字符串看起来相同。 

输入包括：

 -`s`，从中选择子序列的源字符串
 -`t`，我们要匹配的目标字符串

 输出是一个整数，表示不同子序列的总数`s`等于`t`。 

例如：

-`s = "rabbbit"`和`t = "rabbit"`回报`3`因为有三种不同的方式可供选择`'b'`删除。 
-`s = "babgbag"`和`t = "bag"`回报`5`因为多个字符组合保留了所需的顺序。 

约束条件很重要：

 -`1 <= s.length, t.length <= 1000`- 两个字符串都只包含英文字母。 

字符串长度为`1000`立即排除指数暴力解决方案。 由于每个角色都可以包含或排除，因此天真的方法将探索最多`2^1000`的可能性，这在计算上是不可行的。 

一些边缘情况值得预先考虑：

 - 如果`t`长于`s`, 形成`t`是不可能的，所以答案一定是`0`。 
- 如果`s == t`，只有一个有效的子序列，即整个字符串本身。 
- 重复的字符会产生重叠的可能性，并且很容易错误地重复计算。 
- 没有匹配字符的字符串应该正确返回`0`。 

因此，挑战在于如何有效地计算组合，同时避免重新计算。 

## 方法

 ### 蛮力方法

 蛮力的想法是递归地探索每个可能的子序列`s`。 

在每个字符处`s`，我们做出二元选择：

 1. 跳过角色。 
2. 如果该字符与下一个需要的字符匹配，则包含该字符`t`。 

每当我们完成匹配中的所有字符时`t`，我们计算一个有效的子序列。 如果我们耗尽`s`在匹配所有之前`t`，该路径的贡献为零。 

这种方法是正确的，因为它系统地探索每个有效的子序列并精确计算匹配的子序列`t`。 

然而，它太慢了。 由于每个角色`s`创建两个分支选择，最坏情况的复杂性大致呈指数增长`O(2^n)`， 在哪里`n`的长度是`s`。 带有长度的字符串`1000`，这在时间限制内是不可能计算的。 

主要的低效率是重复工作。 相同的子串状态被一次又一次地求解。 例如，这个问题：

 > “有多少种方法可以`s[i:]`形式`t[j:]`？”

 可能会通过不同的递归路径重复出现。 

### 关键见解

 关键的观察结果是，这个问题具有**重叠的子问题**，使其成为**动态规划**的完美候选者。 

我们不是重复地重新计算相同的状态，而是定义：`dp[i][j] = number of ways to form t[:j] using s[:i]`这使我们能够重用之前计算的结果。 

对于每个字符对：

 - 如果`s[i-1] == t[j-1]`，我们有两个选择：

 - 使用此字符匹配
 - 跳过它

 所以：```
dp[i][j] = dp[i-1][j-1] + dp[i-1][j]
```- 如果字符不匹配，我们只能跳过当前字符：```
dp[i][j] = dp[i-1][j]
```这将指数问题转化为多项式问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归地探索每个子序列 |
 | 最优动态规划| O(n × m) | O(米) | 使用滚动 DP 以避免重新计算 |

 在哪里`n = len(s)`和`m = len(t)`。 

## 算法演练

 我们使用**一维动态编程优化**来减少内存使用。 

我们不存储整个 2D 表，而是只保留一行，因为每个状态仅取决于前一行。 

1.创建一个长度为DP的数组`m + 1`， 在哪里`m = len(t)`。`dp[j]`代表形成第一个的方法数`j`的字符`t`。 
2. 初始化基本情况。 

形成空目标字符串的方法只有一种：不选择任何内容。 

所以：```
dp[0] = 1
```所有其他位置开始于`0`。 
3. 迭代中的字符`s`。 

对于每一个角色`s`，我们尝试更新匹配项`t`。 
4. 遍历`t`向后。 

这一步至关重要。 

我们从右向左迭代，因为每次更新都取决于前一行的值。 如果我们从左向右移动，我们就会过早地覆盖信息。 
5.更新匹配的字符。 

如果：```
s[i] == t[j]
```然后：```
dp[j + 1] += dp[j]
```这意味着：

-`dp[j]`计算在当前字符之前形成前缀的方式
 - 我们使用匹配字符扩展这些方式
 6. 继续，直到处理完所有字符。 
7. 返回`dp[m]`。 

这存储形成完整目标字符串的方式总数。 

### 为什么它有效

 The invariant is that after processing the first`i`的字符`s`,`dp[j]`正确存储形成第一个的方法数`j`的字符`t`。 

每个匹配的字符都有两种可能性：使用它或跳过它。 每个不匹配的字符只能被跳过。 因为每个有效子序列都只计算一次，并且 DP 保留所有前缀的计数，所以最终答案是正确的。 

## Python 解决方案```python
class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        n = len(s)
        m = len(t)

        if m > n:
            return 0

        dp = [0] * (m + 1)
        dp[0] = 1

        for char_s in s:
            for j in range(m - 1, -1, -1):
                if char_s == t[j]:
                    dp[j + 1] += dp[j]

        return dp[m]
```实施首先检查是否`t`长于`s`。 如果是，则形成`t`是不可能的。 

这`dp`数组初始化为`m + 1`条目。`dp[0]`设置为`1`因为总是有一种方法来创建空字符串。 

外循环遍历中的每个字符`s`。 对于每个字符，我们向后迭代`t`。 

向后遍历至关重要，因为它可以防止覆盖同一迭代中稍后需要的值。 当字符匹配时，我们扩展所有先前有效的子序列：```python
dp[j + 1] += dp[j]
```在最后，`dp[m]`包含匹配的不同子序列的总数`t`。 

## 解决方案```go
func numDistinct(s string, t string) int {
	n := len(s)
	m := len(t)

	if m > n {
		return 0
	}

	dp := make([]int, m+1)
	dp[0] = 1

	for i := 0; i < n; i++ {
		for j := m - 1; j >= 0; j-- {
			if s[i] == t[j] {
				dp[j+1] += dp[j]
			}
		}
	}

	return dp[m]
}
```Go 实现密切反映了 Python 逻辑。 

DP 切片使用以下命令进行初始化`make([]int, m+1)`。 由于 Go 将整数初始化为`0`自动地，仅`dp[0]`必须明确设置为`1`。 

在 Go 中，向后迭代对于避免意外覆盖同样重要。 

虽然 Go 使用`int`，该问题保证答案符合 32 位有符号整数，因此不必担心溢出。

 ## 边缘情况

 ### 目标比源长

 当`t`长于`s`，不可能形成目标，因为子序列只能删除字符，而不能添加字符。 

例如：```
s = "abc"
t = "abcd"
```幼稚的实现可能仍然会运行不必要的 DP 工作。 我们的解决方案立即处理这个问题：```
if m > n:
    return 0
```这避免了浪费的计算。 

### 重复字符

 重复的字符是这个问题最难的部分，因为它们会产生重叠的组合。 

例如：```
s = "aaaaa"
t = "aa"
```答案是`10`， 不是`1`，因为每一对不同的位置都单独计算。 

简单的递归解决方案很容易重复计算或错过组合。 DP 转换正确地累积了所有可能性：```
dp[j + 1] += dp[j]
```这保证了每个有效组合都被精确计数一次。 

### 没有匹配的字符

 如果`s`不包含任何所需的字符`t`，答案应该是零。 

例如：```
s = "abc"
t = "xyz"
```由于没有发生匹配，DP 数组永远不会更新到以下范围：```
[1,0,0,0]
```算法自然返回`0`没有任何特殊情况的逻辑。 

### 精确匹配

 当`s`和`t`是相同的：```
s = "abc"
t = "abc"
```恰好有一个有效的子序列，选择每个字符。 

DP 公式可以自然地处理这一问题，因为每个匹配字符恰好延伸一条现有路径，从而得出最终的计数`1`。
