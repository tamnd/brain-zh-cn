 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉树的根节点，并要求我们确定从右侧查看树时哪些节点是可见的。 

二叉树是一种分层数据结构，其中每个节点最多可以有两个子节点，称为左子节点和右子节点。 输入作为该结构的根提供。 输出应该是一个节点值列表，表示如果有人站在树的右侧并向树看的话，这些节点将可见。 

在树的每个深度级别，从右侧只能看到一个节点。 具体来说，可见节点是该深度的最右边的节点。 

例如，考虑这棵树：```
        1
       / \
      2   3
       \   \
        5   4
```在深度 0 处，我们看到节点`1`。 

在深度 1 处，节点`2`和`3`存在，但是`3`块`2`从右侧角度来看。 

在深度 2 处，节点`5`和`4`存在，但是`4`更靠右。 

所以结果是：```
[1, 3, 4]
```约束告诉我们树最多包含 100 个节点。 这是相对较小的，因此即使优化程度较低的方法在技术上也可以通过。 然而，我们的目标是设计一个干净、高效的解决方案，可以适当扩展并演示正确的树遍历技术。 

一些边缘情况很重要：

 - 树可能是空的，这意味着`root`是`None`。 在这种情况下，答案应该是一个空列表。 
- 树可能只包含左子树。 即使没有右子节点，每个节点仍然可见，因为没有任何东西从右侧阻挡它。 
- 树可能只包含右子节点。 在这种情况下，每个节点也是可见的。 
- 树可能不平衡，这意味着一个子树比另一棵子树深得多。 
- 节点可以包含负值，但这不影响遍历逻辑。 

## 方法

 暴力方法首先按深度级别对节点进行分组，然后确定每个级别最右侧的节点。 实现此目的的一种方法是执行树的完整遍历，同时存储在每个深度遇到的每个节点。 遍历结束后，我们可以选择每个级别存储的最后一个节点。 

这是有效的，因为在从左到右的遍历过程中，在某个级别访问的最后一个节点是最右边的节点。 然而，这种方法存储的信息超出了必要的范围，因为我们只关心每个级别的一个节点，而不是所有节点。 

更好的解决方案来自于认识到我们可以在遍历树时确定可见节点。 如果我们使用广度优先搜索逐级处理节点，则每个级别处理的最后一个节点将自动成为可见的右侧节点。 

另一个优雅的优化使用深度优先搜索和右优先遍历。 通过在访问左子树之前访问右子树，在每个深度遇到的第一个节点是可见节点。 

这两种方法都是具有线性复杂度的最优方法。 在本指南中，我们将重点关注广度优先搜索解决方案，因为它直接对树中的级别概念进行建模，并且对于此问题非常直观。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 在选择最右边的 | 之前存储每个级别的所有节点
 | 最佳| O(n) | O(n) | 使用 BFS 级别遍历并仅记录每个级别的最后一个节点 |

 ## 算法演练

 我们将使用带有队列的广度优先搜索。 

### 逐步过程

 1.首先检查树是否为空。 

如果`root`是`None`，没有可见节点，因此我们立即返回一个空列表。 
2. 创建队列并以根节点初始化。 

队列非常适合广度优先搜索，因为它按照节点在树中出现的顺序逐级处理节点。 
3. 创建一个空结果列表。 

该列表将存储每个深度的可见节点。 
4. 启动一个循环，该循环在队列不为空时继续。 

该循环的每次迭代恰好处理树的一个深度级别。 
5. 确定当前队列中的节点数。 

该值表示当前深度级别的节点数。 
6. 处理当前层的每个节点。 

从队列中一一删除节点。 

对于每个节点：

 - 将其左子节点添加到队列中（如果存在）。 
- 将其右子节点添加到队列中（如果存在）。 
7. 识别最右边的节点。 

在当前层的循环过程中，由于BFS从左到右处理节点，所以最后处理的节点是最右边的节点。 

当处理该级别的最终节点时，将其值附加到结果列表中。 
8. 继续，直到处理完所有级别。 

一旦队列变空，每个节点都被访问过，并且每个可见节点都被记录下来。 
9. 返回结果列表。 

### 为什么它有效

 广度优先搜索一次处理树一个深度级别。 在每个级别中，节点都是从左到右处理的，因为子节点按照从左到右的顺序添加到队列中。 因此，每一级处理的最终节点始终是最右边的节点。 由于最右边的节点正是从右侧可见的节点，因此在每个级别记录该节点可以保证正确的答案。 

## Python 解决方案```python
from collections import deque
from typing import List, Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        
        result = []
        queue = deque([root])
        
        while queue:
            level_size = len(queue)
            
            for i in range(level_size):
                node = queue.popleft()
                
                if node.left:
                    queue.append(node.left)
                
                if node.right:
                    queue.append(node.right)
                
                if i == level_size - 1:
                    result.append(node.val)
        
        return result
```实现首先处理空树的情况。 如果根是`None`，该函数立即返回一个空列表。 

这`deque`来自Python的`collections`使用模块是因为队列操作，例如`popleft()`在恒定时间内是有效的。 

主循环一次处理一层树。 在迭代一个级别之前，我们将当前队列大小记录在`level_size`。 这确保了在该迭代期间仅处理当前深度的节点。 

在循环内，每个节点都会从队列中删除，并添加其子节点以供将来处理。 关键的观察是当`i == level_size - 1`，我们正在处理当前级别的最终节点。 由于节点是从左到右处理的，因此该节点是可见的最右边的节点。 

最后返回收集到的结果。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func rightSideView(root *TreeNode) []int {
    if root == nil {
        return []int{}
    }

    result := []int{}
    queue := []*TreeNode{root}

    for len(queue) > 0 {
        levelSize := len(queue)

        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]

            if node.Left != nil {
                queue = append(queue, node.Left)
            }

            if node.Right != nil {
                queue = append(queue, node.Right)
            }

            if i == levelSize-1 {
                result = append(result, node.Val)
            }
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的广度优先搜索逻辑。 

Go 没有使用 deque 结构，而是使用切片来模拟队列。 使用以下方法删除前面的元素：```go
queue = queue[1:]
```Go 区分`nil`指针和实际节点，因此子存在检查使用：```go
if node.Left != nil
```与 Python 不同，Go 没有内置的动态列表，例如`deque`，但是切片为问题约束提供了足够有效的行为。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 队列可能包含整个树级别 |

 该算法执行标准的广度优先搜索遍历。 由于每个节点只在队列中插入和删除一次，因此总工作量与节点数量成正比。 

空间复杂度取决于队列中同时存储的最大节点数。 在最坏的情况下，树的最宽层可能包含 O(n) 个节点。

 ## 边缘情况

 ### 空树

 一棵空树表示为`root = None`。 这种情况很容易被忽视，因为遍历代码通常假设至少存在一个节点。 如果没有提前返回，尝试处理队列将导致错误。 

该实现通过以下方式安全地处理此问题：```
if not root:
    return []
```这保证了任何遍历开始之前行为的正确性。 

### 左偏树

 仅包含左子节点的树可能具有欺骗性，因为没有显式的右侧节点。 然而，每个节点从右侧仍然可见，因为没有其他节点在其深度阻挡它。 

例如：```
    1
   /
  2
 /
3
```正确的结果是：```
[1, 2, 3]
```BFS 遍历自然会处理这个问题，因为每一层只包含一个节点，使该节点既是最左边的节点，又是最右边的节点。 

### 不平衡树

 有些树的一个子树可能比另一棵子树深得多。 假设平衡结构的朴素逻辑可能会错过更深层次的可见节点。 

例如：```
        1
       / \
      2   3
     /
    4
   /
  5
```即使右子树提前结束，节点`4`和`5`从右侧更深层次仍然可见。 

层序遍历正确地独立处理每个深度，确保不跳过任何可见节点。 

### 失踪儿童的树

 二叉树通常包含`null`节点之间的间隙。 一个常见的错误是尝试访问子项而不检查它们是否存在。 

该实现通过显式检查来避免这种情况：```
if node.left:
```和```
if node.right:
```仅将有效的子节点添加到队列中，防止运行时错误并确保正确的遍历结构。
