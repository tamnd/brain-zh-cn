[LeetCode 第 146 题](https://leetcode.com/problems/lru-cache/)

 **难度：** 🟡 中等
 **主题：** 哈希表、链表、设计、双向链表

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个遵循最近最少使用（LRU）驱逐策略的高效缓存。 缓存存储有限数量的键值对。 当缓存达到最大容量并且必须插入新项目时，应首先删除最近最少使用的项目。 

该类必须支持两种操作：

 -`get(key)`检索与键关联的值
 -`put(key, value)`插入或更新键值对

 重要的要求是两个操作必须平均运行`O(1)`时间复杂度。 

短语“最近最少使用”意味着每当通过以下任一方式访问密钥时`get`或者`put`，它成为最近使用的项目。 最长未被访问的项目将成为逐出候选者。 

输入由对缓存执行的一系列操作组成。 每个操作要么插入数据、更新数据或检索数据。 每个的输出`get`如果key存在则操作为对应的value，否则`-1`。 

约束条件很重要：

 - 容量最多3000
 - 最多`2 * 10^5`操作可能会发生

 扫描缓存以确定使用顺序的简单实现会变得太慢。 由于可能有 200,000 次操作，因此每次操作的平均时间必须真正恒定。 

一些边缘情况很重要：

 - 访问不存在的密钥应该返回`-1`- 更新现有密钥不应增加缓存大小
 - 访问密钥应刷新其使用状态
 - 插入到完整的缓存中应该恰好逐出最近最少使用的一项
 - 具有容量的缓存`1`特别容易出错，因为每次新插入都会导致驱逐

 ## 方法

 ### 蛮力方法

 一个简单的实现将使用哈希映射来存储键值对和单独的列表来跟踪使用顺序。 

每当访问或更新密钥时，我们都会将其移至使用列表的末尾。 当需要驱逐时，我们从列表的前面删除最近最少使用的键。 

问题是更新普通列表内的使用顺序需要首先搜索密钥。 从列表中删除任意元素需要`O(n)`时间，因为元素必须移动。 

例如：

-`get(key)`需要在使用列表中找到密钥并移动它
 -`put(key, value)`可能还需要列表更新和转移

 当操作次数达到 200,000 次时，效率就会变得很低。 

### 最佳方法

 关键的见解是我们同时需要两种不同的功能：

 1. 快速按键查找
 2.快速插入和从使用顺序中删除

 哈希映射提供`O(1)`平均查找时间，而双向链表提供`O(1)`如果我们已经有一个指向该节点的指针，则插入和删除。 

我们将这两个结构结合起来：

 - 哈希映射：将键映射到链表节点
 - 双向链表：维护使用顺序

 链表按照从最近最少使用到最近使用的顺序存储节点。 

每当访问密钥时：

 - 从列表中删除其节点
 - 将其移至尾部

 每当插入新密钥时：

 - 将其添加到尾部
 - 如果超出容量，删除头节点

 这为两者提供了恒定的时间操作`get`和`put`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次操作 O(n) | O(n) | 列表更新需要扫描和移动|
 | 最佳| 每次操作平均 O(1) | O(n) | 哈希图加双向链表|

 ## 算法演练

 1. 创建一个双向链表来跟踪使用顺序。 

列表的前面代表最近最少使用的项目。 背面代表最近使用的项目。 
2. 使用虚拟头节点和虚拟尾节点。 

虚拟节点简化了插入和删除逻辑，因为我们不需要对空列表或单元素列表进行特殊处理。 
3. 创建从键到链表节点的哈希映射。 

这允许在恒定时间内直接访问任何缓存条目。 
4. 对于`get(key)`操作：

 - 检查哈希映射中是否存在该键
 - 如果没有找到，则返回`-1`- 否则：

 - 从当前位置删除节点
 - 将其移至列表末尾，因为最近使用过
 - 返回存储的值
 5. 对于`put(key, value)`操作：

 - 如果密钥已经存在：

 - 更新其值
 - 将其移到最后，因为最近使用过
 - 否则：

 - 创建一个新节点
 - 将其插入末尾
 - 将其添加到哈希映射中
 6. 插入后，检查容量。 

如果缓存大小超过容量：

 - 从前面删除最近最少使用的节点
 - 从哈希映射中删除其键

 ### 为什么它有效

 哈希映射保证对节点的恒定时间访问。 一旦我们有了节点引用，双向链表就能保证恒定时间的插入和删除。 链表始终保持正确的使用顺序，因为每次访问都会将一个节点移动到尾部。 因此，列表的头部始终是最近最少使用的项目，这确保了正确的驱逐行为。 

## Python 解决方案```python
class Node:
    def __init__(self, key: int = 0, value: int = 0):
        self.key = key
        self.value = value
        self.prev = None
        self.next = None

class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {}

        self.head = Node()
        self.tail = Node()

        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node: Node) -> None:
        prev_node = node.prev
        next_node = node.next

        prev_node.next = next_node
        next_node.prev = prev_node

    def _insert_to_tail(self, node: Node) -> None:
        prev_tail = self.tail.prev

        prev_tail.next = node
        node.prev = prev_tail

        node.next = self.tail
        self.tail.prev = node

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1

        node = self.cache[key]

        self._remove(node)
        self._insert_to_tail(node)

        return node.value

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            node = self.cache[key]
            node.value = value

            self._remove(node)
            self._insert_to_tail(node)
            return

        new_node = Node(key, value)

        self.cache[key] = new_node
        self._insert_to_tail(new_node)

        if len(self.cache) > self.capacity:
            lru_node = self.head.next

            self._remove(lru_node)
            del self.cache[lru_node.key]

# Your LRUCache object will be instantiated and called as such:
# obj = LRUCache(capacity)
# param_1 = obj.get(key)
# obj.put(key,value)
```实施开始于`Node`表示双向链表中的一个缓存条目的类。 每个节点存储：

 - 钥匙
 - 价值
 - 指向前一个节点的指针
 - 指向下一个节点的指针

 缓存本身维护：

 - 一个名为的哈希图`cache`- 由哑元界定的双向链表`head`和`tail`节点

 的`_remove`helper 通过重新连接相邻节点，在恒定时间内将节点从链表中分离出来。 

这`_insert_to_tail`helper 直接在虚拟尾节点之前插入一个节点，使其成为最近使用的项目。 

这`get`方法检查密钥是否存在。 如果是，则该节点将被移动到尾部，因为它最近被访问过。 

这`put`方法首先处理现有密钥的更新。 现有的键被刷新并移动到尾部。 对于新键，节点会被插入到哈希映射和链表中。 

如果超出容量，则最近最少使用的节点始终位于紧接虚拟头节点之后。 该节点将从链表和哈希图中删除。 

## 解决方案```go
type Node struct {
	key   int
	value int
	prev  *Node
	next  *Node
}

type LRUCache struct {
	capacity int
	cache    map[int]*Node
	head     *Node
	tail     *Node
}

func Constructor(capacity int) LRUCache {
	head := &Node{}
	tail := &Node{}

	head.next = tail
	tail.prev = head

	return LRUCache{
		capacity: capacity,
		cache:    make(map[int]*Node),
		head:     head,
		tail:     tail,
	}
}

func (this *LRUCache) remove(node *Node) {
	prevNode := node.prev
	nextNode := node.next

	prevNode.next = nextNode
	nextNode.prev = prevNode
}

func (this *LRUCache) insertToTail(node *Node) {
	prevTail := this.tail.prev

	prevTail.next = node
	node.prev = prevTail

	node.next = this.tail
	this.tail.prev = node
}

func (this *LRUCache) Get(key int) int {
	node, exists := this.cache[key]

	if !exists {
		return -1
	}

	this.remove(node)
	this.insertToTail(node)

	return node.value
}

func (this *LRUCache) Put(key int, value int) {
	if node, exists := this.cache[key]; exists {
		node.value = value

		this.remove(node)
		this.insertToTail(node)

		return
	}

	newNode := &Node{
		key:   key,
		value: value,
	}

	this.cache[key] = newNode
	this.insertToTail(newNode)

	if len(this.cache) > this.capacity {
		lruNode := this.head.next

		this.remove(lruNode)
		delete(this.cache, lruNode.key)
	}
}

/**
 * Your LRUCache object will be instantiated and called as such:
 * obj := Constructor(capacity);
 * param_1 := obj.Get(key);
 * obj.Put(key,value);
 */
```Go 实现遵循与 Python 解决方案相同的设计。 一个显着的区别是通过显式指针处理`*Node`。 Go 映射返回一个值和一个布尔存在标志，用于确定缓存中是否存在某个键。 

与 Python 不同，Go 没有自动`None`语义。 相反，链表指针是通过显式处理的`nil`值，尽管虚拟头节点和尾节点阻止了大多数特殊情况的指针逻辑。 

## 工作示例

 ### 示例 1

 输入：```
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1,1], [2,2], [1], [3,3], [2], [4,4], [1], [3], [4]]
```容量=2

 我们将链表从左到右表示为：```
LRU -> MRU
```| 运营| 缓存状态| 结果 |
 | --- | --- | --- |
 | 把(1,1) | 1 | |
 | 把(2,2) | 1 → 2 | |
 | 得到（1）| 2 → 1 | 1 |
 | 把(3,3) | 1 → 3 | 驱逐 2 |
 | 得到(2) | 1 → 3 | -1 |
 | 把(4,4) | 3 → 4 | 驱逐 1 |
 | 得到（1）| 3 → 4 | -1 |
 | 得到(3) | 4 → 3 | 3 |
 | 得到(4) | 3 → 4 | 4 |

 详细推理：

 之后`get(1)`， 钥匙`1`成为最近使用的，所以关键`2`成为最近最少使用的。 

插入时`3`，容量将变为 3，所以关键`2`被驱逐。 

后来，插入`4`驱逐钥匙`1`因为它现在是最近最少使用的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每次操作平均 O(1) | 哈希图查找和链表更新都是常数时间 |
 | 空间| O（容量）| 缓存最多存储`capacity`节点 |

 哈希映射为每个缓存项存储一个条目，而链表则按使用顺序存储相同的节点。 每个操作仅执行恒定数量的指针更新和哈希图访问，因此两者`get`和`put`以平均恒定时间运行。

 ## 边缘情况

 ### 容量等于一

 有容量的缓存`1`是错误的常见来源，因为第一次插入后的每次插入都会立即触发驱逐。 一些不正确的实现意外地保留了陈旧的节点或无法正确更新使用顺序。 

此实现可以自然地处理这种情况，因为插入总是检查缓存大小是否超出容量。 如果是，则立即删除最近最少使用的节点。 

### 更新现有密钥

 插入已存在的密钥时会出现另一个常见问题。 有缺陷的实现可能会意外地在链表中创建重复的节点或错误地增加缓存大小。 

该解决方案首先检查哈希映射中是否已存在该键。 如果是，则直接更新现有节点的值，并将该节点移动到尾部，而不创建新节点。 

### 重复访问同一密钥

 反复呼唤`get`同一键应不断刷新其新近状态。 一些不正确的解决方案忘记在访问后移动节点，导致最近使用的密钥被错误地驱逐。 

此实现始终删除并重新插入尾部访问的节点，确保链表顺序始终反映真实的新近度。 

### 访问不存在的键

 缓存必须返回`-1`对于不存在的键。 不正确的实现可能会意外取消引用丢失的节点或产生不一致的行为。 

哈希映射查找首先安全地检查密钥是否存在。 如果键不存在，该方法立即返回`-1`而不修改链表。
