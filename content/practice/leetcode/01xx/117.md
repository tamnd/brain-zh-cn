 ## 解决方案

 ## 问题理解

 该问题要求我们填充`next`二叉树中每个节点的指针，使其指向同一级别上紧邻其右侧的节点。 如果不存在这样的节点，则`next`指针应保留`NULL`。 

与该问题的较简单版本不同，该版本保证树是完美的二叉树，而该版本允许任何二叉树结构。 节点可能缺少子节点，级别可能不完整，并且树的形状可能不规则。 这使得问题变得更具挑战性，因为我们不能依赖诸如每个父母都有两个孩子或每个级别都被完全填满的假设。 

输入是二叉树的根节点，其中每个节点有四个字段：```
val   -> node value
left  -> pointer to left child
right -> pointer to right child
next  -> pointer to the next right node
```最初，每`next`指针已经是`NULL`。 我们的工作是更新这些指针。 

预期的输出是相同的树结构，但所有`next`指针逐级正确连接。 实际的树结构没有改变，只是`next`参考。 

约束告诉我们树最多包含`6000`节点。 这个大小足够小，以至于使用队列的广度优先遍历可以有效地工作。 然而，后续要求明确要求**恒定的额外空间**，这意味着我们应该避免分配与节点数量成比例的额外内存。 递归堆栈空间不计入额外空间限制。 

在设计解决方案之前，认识到一些边缘情况很重要。 树可能是空的（`root = []`），在这种情况下我们只需返回`None`。 一个级别可能只包含一个节点，这意味着它的`next`指针应保留`NULL`。 节点可能只有一个子节点，无论是左节点还是右节点，这意味着我们的遍历逻辑不能假设两个子节点都存在。 最后，级别可能是稀疏的并且在结构上是断开的，因此简单的同级链接逻辑可能会失败。 

## 方法

 ### 暴力方法，使用队列进行层序遍历

 最直接的解决方案是使用队列执行广度优先搜索 (BFS)。 

我们一次处理树​​一层。 对于每个级别，我们都会跟踪当前队列中的所有节点。 当我们迭代它们时，我们连接每个节点的`next`指向同一级别中的下一个节点的指针。 该级别的最终节点得到`NULL`。 

在处理节点时，我们将其左子节点和右子节点（如果存在）放入队列。 Since BFS naturally visits nodes level by level, it guarantees correct horizontal connections.

 This approach is correct because every level is processed independently and in left to right order. 然而，缺点是占用空间。 在最坏的情况下，队列可能包含树的整个级别，这可能需要`O(n)`额外的内存。 

### 最佳方法，使用现有的级别遍历`next`指针

 关键的观察是，一旦我们连接了一层中的节点，我们就可以重用这些节点`next`pointers to traverse that level without needing a queue.

 Instead of storing nodes externally, we process one level at a time while building the next level's linked structure.

 我们维持：

 - 指向当前级别的指针
 - A dummy node to build connections for the next level
 - A tail pointer that appends children into the next level chain

 当我们使用当前级别迭代时`next`指针，我们将遇到的每个子节点连接到下一级的链表中。 当前级别完成后，我们将通过以下方式进入下一个级别`dummy.next`。 

这是有效的，因为每个级别都变成一个临时链表，允许我们水平移动而无需额外的内存。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 带队列的BFS，简单但违反了常量空间跟进 |
 | 最佳| O(n) | O(1) | O(1) | 已确定的用途`next`指向遍历级别的指针 |

 ## 算法演练

 ### 最优算法

 1. 立即返回处理空树情况`None`如果`root`是`None`。 没有什么可以连接的。 
2. 初始化一个名为`current_level`到`root`。 该指针表示当前正在处理的级别的最左边的节点。 
3. 启动一个持续 while 的循环`current_level`不是`None`。 每次迭代只处理一个树级别。 
4. 创建一个虚拟节点和`tail`指针。 虚拟节点充当下一级链表的临时头。 这`tail`指针跟踪最近连接的节点。 
5. 使用已经建立的层遍历当前层`next`指针。 开始于`current = current_level`。 
6. 对于当前级别的每个节点：

 - 如果该节点有左子节点，则将其连接到`tail.next`，然后移动`tail`向前。 
- 如果该节点有右子节点，则类似地连接它并移动`tail`向前。 
7. 使用以下命令在当前级别上水平移动：```
current = current.next
```这避免了需要排队。 
8. 完成关卡后，虚拟节点通过以下方式包含下一级的头`dummy.next`。 
9.更新：```
current_level = dummy.next
```这将处理降低了一个级别。 
10. 继续，直到没有更多级别为止。 
11.归还原件`root`，因为所有连接均已就位。 

### 为什么它有效

 关键的不变量是，在处理一个级别之前，该级别中的所有节点已经通过以下方式连接`next`指针。 在遍历这一层的同时，我们从左到右构建下一层的链接结构。 因为孩子们是按照从左到右的自然顺序遇到的，所以生成的`next`链条是正确的。 一旦关卡完成，我们就向下移动并重复该过程。 由于每个节点都被访问一次并且链接正确，因此最终的树满足问题要求。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(
        self,
        val: int = 0,
        left: 'Node' = None,
        right: 'Node' = None,
        next: 'Node' = None
    ):
        self.val = val
        self.left = left
        self.right = right
        self.next = next
"""

class Solution:
    def connect(self, root: 'Node') -> 'Node':
        if not root:
            return root

        current_level = root

        while current_level:
            dummy = Node(0)
            tail = dummy
            current = current_level

            while current:
                if current.left:
                    tail.next = current.left
                    tail = tail.next

                if current.right:
                    tail.next = current.right
                    tail = tail.next

                current = current.next

            current_level = dummy.next

        return root
```实现首先处理空树的情况。 如果根是`None`，我们立即返回。 

这`current_level`指针跟踪当前正在处理的级别的第一个节点。 在外循环内部，我们创建一个临时的`dummy`节点并初始化`tail`指向它。 该对用于构造下一级的链表。 

内循环使用以下方式遍历当前级别`current.next`。 对于每个节点，我们将任何现有的子节点附加到下一级链。 这`tail`指针确保连接以正确的从左到右的顺序发生。 

处理完整个关卡后，`dummy.next`指向下一层的最左边的节点，让算法继续向下。 

由于所有修改都发生在适当的位置，并且我们从不分配与树大小成比例的内存，因此该实现满足了恒定的额外空间要求。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Left *Node
 *     Right *Node
 *     Next *Node
 * }
 */

func connect(root *Node) *Node {
	if root == nil {
		return root
	}

	currentLevel := root

	for currentLevel != nil {
		dummy := &Node{}
		tail := dummy
		current := currentLevel

		for current != nil {
			if current.Left != nil {
				tail.Next = current.Left
				tail = tail.Next
			}

			if current.Right != nil {
				tail.Next = current.Right
				tail = tail.Next
			}

			current = current.Next
		}

		currentLevel = dummy.Next
	}

	return root
}
```Go 的实现与 Python 解决方案非常相似。 由于 Go 明确使用指针，子访问需要`nil`链接节点之前进行检查。 虚拟节点是使用创建的`&Node{}`。 

一种语言特定的差异是指针处理。 在 Python 中，对象自动基于引用，而在 Go 中我们显式操作`*Node`指针。 否则，逻辑保持不变。

 ## 边缘情况

 ### 空树

 空树是最简单的边缘情况。 粗心的实现可能会尝试访问属性`None`，导致运行时错误。 该解决方案立即通过提前返回来处理此问题：```
if not root:
    return root
```这保证了任何遍历开始之前的安全。 

### 儿童失踪的稀疏关卡

 错误的一个常见来源是假设左子节点和右子节点都存在。 在此问题中，节点可能只有一个子节点或根本没有。 例如：```
    1
   / \
  2   3
   \   \
    5   7
```该算法单独检查子项是否存在并附加存在的子项。 这确保了`5`正确连接到`7`，即使他们来自不同的父母。 

### 每级单个节点

 在倾斜树中，每一层可能只包含一个节点：```
1
 \
  2
   \
    3
```简单的 BFS 实现可能仍然有效，但基于指针的解决方案有时会错误地假设同级连接存在。 在这里，虚拟节点机制自然地处理这种情况，因为每一层只是生成一个链表，其中一个节点的节点`next`遗迹`NULL`。 

### 每个级别的最后一个节点

 每个级别的最终节点必须始终指向`NULL`。 容易出现错误的实现可能会意外地留下过时的指针。 由于该算法仅显式地向前连接节点，并且从不为最终节点分配后继节点，因此最后一个节点自然保留其默认值`NULL`价值。
