[LeetCode 第 166 题](https://leetcode.com/problems/fraction-to-recurring-decimal/)

 **难度：** 🟡 中等
 **主题：** 哈希表、数学、字符串

 ## 解决方案

 ## 问题理解

 这个问题要求我们转换一个用整数表示的分数`numerator`和一个整数`denominator`，转换为十进制字符串表示形式。 如果十进制扩展包含重复的小数序列​​，我们必须将重复部分括在括号中。 

例如，分数`1/2`产生`"0.5"`因为它终止了。 分数`1/3`产生`"0.(3)"`因为数字`3`永远重复。 相似地，`4/333`变成`"0.(012)"`因为重复周期是`"012"`。 

输入由两个整数组成：

 -`numerator`, 分数的顶部部分
 -`denominator`, 分数的底部部分

 输出是分数的精确十进制值的字符串表示形式。 

这些约束告诉我们一些重要的事情：

 - 两者`numerator`和`denominator`可能是负数。 
- 值可以大到`2^31 - 1`或小至`-2^31`。 
-`denominator != 0`，因此除以零不是问题。 
- 结果长度保证小于`10^4`，这意味着我们不需要担心产量无限增长。 

关键的挑战是正确识别重复小数。 使用浮点算术的简单实现将会失败，因为浮点数无法精确表示重复小数，并且可能会引入舍入误差。 

一些边缘情况很容易导致实现失败：

 - 负数，结果必须包含正确的符号。 
- 均分的分数，例如`2/1`，应该返回`"2"`而不是`"2.0"`。 
- 重复小数，例如`1/3`或者`2/7`。 
- 接近整数限制的大值，尤其是`-2^31`，如果绝对值处理不正确，在某些语言中可能会发生溢出。 
- 分子为零，结果应该是`"0"`。 

## 方法

 ### 蛮力方法

 强力解决方案将逐位模拟长除法，并无限期地附加十进制数字，直到出现模式。 检测重复的一种简单方法是重复比较生成的十进制字符串的后缀，以查看某些序列是否重复。 

这是有效的，因为长除法最终要么终止，要么进入循环。 由于可能的余数数量有限，循环小数总是重复。 

然而，这种方法效率低下。 通过重复扫描先前生成的数字来检测重复可能会变得昂贵，特别是如果在重复变得明显之前生成了许多数字。 由于每个数字生成可能需要检查现有结果的大部分，因此时间复杂度变得不必要的高。 

### 关键见解

 重要的观察是，由于长除法期间重复的**余数**而出现重复小数。 

除法时，每一步完全取决于当前的余数。 如果相同的余数再次出现，除法过程将从该点开始重复，永远产生相同的数字。 

例如，在`1/3`：

 -`1 ÷ 3 = 0 remainder 1`- 余数乘以`10`：`10 ÷ 3 = 3 remainder 1`剩下的`1`重复，因此数字序列重复。 

这建议使用**哈希映射**来记录结果字符串中每个余数首次出现的位置。 当我们再次遇到相同的余数时，我们确切地知道重复循环从哪里开始，并且可以插入括号。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 模拟除法并低效地重复检查重复模式 |
 | 最佳| O(n) | O(n) | 使用哈希图来跟踪余数并有效地检测循环 |

 这里，`n`表示十进制表示中产生的位数。 

## 算法演练

 ### 最优算法

 1. **立即处理分子为零的情况**

 如果`numerator == 0`， 返回`"0"`立即地。 无论分母如何，零除以任何非零值都为零。 
2. **确定结果的符号**

 如果恰好满足以下条件之一，则结果为负`numerator`或者`denominator`是负数。 这相当于检查它们的符号是否不同。 

我们追加`"-"`仅在必要时才得出结果。 
3. **将值转换为绝对数字**

 由于符号已经被处理，我们将这两个值转换为其绝对形式。 这简化了除法逻辑。 

此步骤对于避免负余数问题尤其重要。 
4. **计算整数部分**

 使用整数除法：```
integer_part = numerator // denominator
```将其附加到结果中。 
5. **计算初始余数**

 使用模：```
remainder = numerator % denominator
```如果余数是`0`，小数结束，所以立即返回结果。 
6. **开始处理小数部分**

 追加`"."`到结果，因为有小数部分。 
7. **使用哈希图来跟踪剩余位置**

 创建字典：```
remainder_position[remainder] = current_index
```键是余数，值是结果中从该余数生成的数字开始的索引。 
8. **模拟长除法**

 虽然余数不为零：

 - 如果余数之前已经出现过：

 - 检索其存储的索引。 
- 插入`"("`在那个位置。 
- 追加`")"`在最后。 
- 返回结果。 
- 否则：

 - 存储当前剩余位置。 
- 余数乘以`10`。 
- 计算下一个数字：```
digit = remainder // denominator
```- 附加数字。 
- 更新：```
remainder = remainder % denominator
```9. **返回完成结果**

 如果余数最终变成`0`，小数自然终止。 

### 为什么它有效

 正确性依赖于长除法的一个基本属性：下一个数字完全由当前余数决定。 由于只有有限多个可能的余数，因此余数最终会变成`0`，产生一个终止小数，或先前看到的余数重复。 当余数重复时，完全相同的操作序列会重复，从而保证重复循环。 通过存储每个余数的第一次出现，我们可以精确地识别重复序列的开始位置并正确插入括号。 

## Python 解决方案```python
class Solution:
    def fractionToDecimal(self, numerator: int, denominator: int) -> str:
        if numerator == 0:
            return "0"

        result = []

        # Handle sign
        if (numerator < 0) ^ (denominator < 0):
            result.append("-")

        numerator = abs(numerator)
        denominator = abs(denominator)

        # Integer part
        integer_part = numerator // denominator
        result.append(str(integer_part))

        remainder = numerator % denominator

        # No fractional part
        if remainder == 0:
            return "".join(result)

        result.append(".")

        # Map remainder -> index in result
        remainder_position = {}

        while remainder != 0:
            if remainder in remainder_position:
                repeat_index = remainder_position[remainder]
                result.insert(repeat_index, "(")
                result.append(")")
                break

            remainder_position[remainder] = len(result)

            remainder *= 10
            digit = remainder // denominator
            result.append(str(digit))

            remainder %= denominator

        return "".join(result)
```实现首先处理分子为零的最简单情况。 这避免了不必要的工作并立即返回`"0"`。 

在将值转换为绝对数之前处理符号。 XOR 运算检查是否恰好有一个值为负，这表示结果为负。 

首先计算整数部分，因为每个十进制表示都以它开头。 如果整数除法后余数为零，则小数结束，无需进一步处理。 

对于循环小数，实现进入长除法循环。 这`remainder_position`字典是算法的核心。 每个余数都映射到其结果数字序列开始的索引。 当余数重复时，算法插入`"("`在存储的索引处并附加`")"`最后，正确标记重复出现的部分。 

使用列表`result`比重复的字符串连接更有效，因为字符串在 Python 中是不可变的。 

## 解决方案```go
func fractionToDecimal(numerator int, denominator int) string {
	if numerator == 0 {
		return "0"
	}

	var result []byte

	// Handle sign
	if (numerator < 0) != (denominator < 0) {
		result = append(result, '-')
	}

	num := int64(numerator)
	den := int64(denominator)

	if num < 0 {
		num = -num
	}
	if den < 0 {
		den = -den
	}

	// Integer part
	integerPart := num / den
	result = append(result, []byte(strconv.FormatInt(integerPart, 10))...)

	remainder := num % den

	// No fractional part
	if remainder == 0 {
		return string(result)
	}

	result = append(result, '.')

	// Map remainder -> index
	remainderPosition := make(map[int64]int)

	for remainder != 0 {
		if pos, exists := remainderPosition[remainder]; exists {
			result = append(result[:pos],
				append([]byte{'('},
					append(result[pos:], ')')...)...)
			break
		}

		remainderPosition[remainder] = len(result)

		remainder *= 10
		digit := remainder / den
		result = append(result, byte('0'+digit))

		remainder %= den
	}

	return string(result)
}
```Go 实现遵循与 Python 相同的算法结构，但有一些特定于语言的注意事项。 

最重要的是，必须小心处理整数溢出。 自从`numerator`和`denominator`可能等于`-2^31`, 采取`abs(-2^31)`32 位整数可能会溢出。 为了避免这种情况，该实现将两个值转换为`int64`在取绝对值之前。 

Go 不支持有效地直接插入字符串，因此解决方案操作`[]byte`片。 余数到位置映射的工作方式与 Python 中完全相同，但使用`map[int64]int`。 

代码中还使用了`strconv.FormatInt`将整数转换为字符串。

 ## 边缘情况

 ### 零分子

 当`numerator = 0`，答案一定是`"0"`与分母无关。 幼稚的实现可能会不必要地进入除法逻辑或意外返回`"0.0"`。 此实现会立即处理该案例并提前返回。 

### 负数

 错误地处理标志是错误的常见来源。 例如，`-1/2`和`1/-2`都应该产生`"-0.5"`， 尽管`-1/-2`应该产生`"0.5"`。 该实现通过首先确定符号，然后将两个值转换为绝对数，将符号处理与算术分开。 

### 重复小数检测

 像这样的分数`1/3`或者`1/7`永不终止。 如果没有循环检测，算法可能会永远运行。 该实现通过将先前看到的余数存储在哈希图中来防止这种情况。 一旦余数重复，就会识别循环周期并将其括在括号中。 

### 整数溢出近界

 输入范围包括`-2^31`，如果`abs()`适用于具有固定宽度整数的语言。 在 Go 中，实现将值转换为`int64`在取绝对值之前，即使对于极端输入也能确保安全算术。
