[LeetCode 第 129 题](https://leetcode.com/problems/sum-root-to-leaf-numbers/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉树的根，其中每个节点都包含来自`0`到`9`。 从根开始到叶节点结束的每条路径通过沿该路径连接数字来形成一个数字。 

例如，考虑路径：```
1 -> 2 -> 3
```该路径代表数字`123`。 

目标是计算树中所有此类根到叶数的总和。 

叶节点被定义为没有左子节点和右子节点的节点。 只有完整的根到叶路径才会计入最终总和。 

输入是二叉树，而不是数字数组。 每个节点为当前形成的数字贡献一位数字。 当我们深入树时，我们有效地将数字附加到当前数字。 将数字附加到十进制数意味着将当前值乘以`10`并添加新数字。 

例如：```
Current number = 49
Next digit = 5

New number = 49 * 10 + 5 = 495
```约束条件很重要：

 - 树最多包含`1000`节点。 
- 树的深度不超过`10`。 
- 每个节点值都是介于`0`和`9`。 

这些约束告诉我们递归是完全安全的，因为最大递归深度非常小。 它们还意味着基于遍历的解决方案足够高效，因为访问每个节点一次只需要花费`O(n)`时间。 

有几种边缘情况值得立即考虑。 

一棵只有一个节点的树应该直接返回该节点的值，因为单个节点既是根又是叶子。 包含零的树可能很棘手，因为前导零或中间零仍然参与数字形成。 例如，路径`1 -> 0 -> 5`代表`105`， 不是`15`。 每个节点只有一个子节点的倾斜树应该仍然可以正常工作，因为仍然只有一条从根到叶的路径。 最后，我们必须确保仅在到达叶节点时才添加数字，而不是中间节点。 

## 方法

 ### 蛮力方法

 一个简单的暴力策略是将每个根到叶路径显式构建为字符串或数字列表。 一旦到达叶节点，我们将收集到的数字转换为整数并将其添加到答案中。 

例如，在遍历期间我们可能会存储：```
[4, 9, 5]
```在叶子处，我们将其转换为`"495"`然后代入整数`495`。 

这种方法之所以有效，是因为它探索了每条可能的根到叶路径，并正确地重建了每条路径所代表的数字。 然而，它执行了不必要的工作，因为每个叶子都需要重建或将整个路径表示转换为数字。 

尽管约束足够小，该解决方案仍然可以通过，但从概念上讲，它的效率很低，因为重复的字符串连接或列表复制会引入额外的开销。 

### 关键见解

 重要的观察是我们不需要显式存储整个路径。 

当我们向下遍历时，我们可以维护当前路径所代表的数值。 当移动到子节点时，我们以数学方式附加子数字：```
new_value = current_value * 10 + child.val
```这意味着我们可以在遍历过程中增量计算路径号。 

一旦到达叶子节点，当前的累加值已经是完整的根到叶子的数量，因此我们只需将其添加到总数中即可。 

这自然会导致深度优先搜索解决方案，因为 DFS 在回溯到另一条路径之前会完全探索一条路径。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × h) | O(h) | 存储路径数字并重复重建数字 |
 | 最佳| O(n) | O(h) | 在 DFS 遍历期间增量构建数字 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 从根节点开始深度优先搜索。 

DFS 是理想的，因为问题本质上是探索完整的根到叶路径。 每个递归调用都表示当前路径更深一层。 
2. 遍历时保持流水号。 

在每个节点上，使用以下命令更新当前数量：$current = current \times 10 + node.val$这会将节点的数字附加到现有数字，与十进制数字的形成方式完全相同。 
3. 检查当前节点是否为叶子节点。 

如果两个节点都满足，则节点是叶子`left`和`right`是`None`。 

如果我们到达一片叶子，当前累加的数字代表一个完整的根到叶子的数字，所以我们返回它。 
4. 递归处理左右子树。 

继续 DFS 到两个子进程中，同时传递更新后的当前数字。 
5. 合并子树结果。 

当前节点贡献的总和等于：```
left_sum + right_sum
```因为每个有效的根到叶路径必须属于左子树或右子树。 
6. 返回最终的累计金额。 

递归调用自然地聚合所有根到叶路径的总数。 

### 为什么它有效

 该算法保持了不变式`current`变量始终等于从根到当前节点的路径所表示的数值。 

每个递归调用都使用小数位算术将路径扩展一位数。 由于 DFS 只访问每条从根到叶的路径一次，并且每片叶都贡献了一个有效数字，因此最终的总和是正确的。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def sumNumbers(self, root: Optional[TreeNode]) -> int:
        
        def dfs(node: Optional[TreeNode], current_number: int) -> int:
            if not node:
                return 0
            
            current_number = current_number * 10 + node.val
            
            # Leaf node
            if not node.left and not node.right:
                return current_number
            
            left_sum = dfs(node.left, current_number)
            right_sum = dfs(node.right, current_number)
            
            return left_sum + right_sum
        
        return dfs(root, 0)
```该实现使用名为的嵌套辅助函数`dfs`。 该函数接收两条信息：当前节点和沿当前路径到目前为止形成的数字。 

底壳手柄`None`通过返回节点`0`。 这简化了递归逻辑，因为丢失的子项对最终总和没有任何贡献。 

在每个节点，当前路径值通过将先前值乘以来更新`10`并添加当前数字。 这反映了十进制数的构造。 

当到达叶节点时，该函数立即返回完整的数字。 否则，该函数递归地计算左子树和右子树的总和并将它们组合起来。 

main函数以初始路径值开始遍历`0`。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func sumNumbers(root *TreeNode) int {
    
    var dfs func(node *TreeNode, currentNumber int) int
    
    dfs = func(node *TreeNode, currentNumber int) int {
        if node == nil {
            return 0
        }
        
        currentNumber = currentNumber*10 + node.Val
        
        // Leaf node
        if node.Left == nil && node.Right == nil {
            return currentNumber
        }
        
        leftSum := dfs(node.Left, currentNumber)
        rightSum := dfs(node.Right, currentNumber)
        
        return leftSum + rightSum
    }
    
    return dfs(root, 0)
}
```Go 解决方案遵循与 Python 版本完全相同的递归结构。 主要区别在于 Go 需要使用显式指针检查`nil`。 

递归函数变量首先声明，然后赋值，因为 Go 中的匿名递归函数需要这种两步声明模式。 

整数溢出不是问题，因为该问题保证最终答案适合 32 位整数。

```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用栈最多存储一条从根到叶的路径 |

 DFS 遍历对每个节点处理一次，并且每个节点仅执行常量时间工作。 因此，总时间复杂度与节点数量呈线性关系。 

空间复杂度完全来自递归深度。 在完全倾斜的树的最坏情况下，递归堆栈可以包含`h`同时呼叫，其中`h`是树的高度。 由于最大深度最多为`10`，递归对于这个问题来说是非常安全的。

 ## 边缘情况

 单节点树是最重要的边缘情况之一。 在这种情况下，根也是叶。 有缺陷的实现可能会不必要地继续递归，或者无法识别单个数字本身形成一个有效的数字。 当前的实现自然地处理了这个问题，因为在更新当前编号后立即检查叶节点条件。 

包含零的树也可能导致微妙的错误。 某些实现意外地将零视为无意义的数字或错误地跳过它们。 但是，零是数字中的有效数字。 例如，路径`1 -> 0 -> 5`必须成为`105`。 公式：$current = current \times 10 + digit$正确地将零保留在正确的小数位置。 

倾斜的树是另一个重要的例子。 如果每个节点只有一个子节点，那么一棵树实际上可以像链表一样运行。 基本情况处理较差的递归解决方案可能会错误地停止遍历或重复计数节点。 此实现可以正常工作，因为每个递归调用都会独立处理存在的子级，并且`None`孩子们只是简单地返回`0`。 

当内部节点不应直接对总和做出贡献时，就会出现另一种微妙的边缘情况。 只有完整的根到叶路径才算在内。 有缺陷的实现可能会在到达叶子之前意外添加中间路径值。 当前的解决方案通过仅当两个子指针都为时才返回累积数来避免这种情况。`None`。
