[LeetCode 第 159 题](https://leetcode.com/problems/longest-substring-with-at-most-two-distinct-characters/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们找到字符串中最长连续子串的长度`s`最多包含两个不同的字符。 

子字符串是原始字符串内的连续字符序列。 短语“至多两个不同的字符”表示子字符串可以包含一个或两个唯一字符，但绝不能包含三个或更多。 

例如，在字符串中`"eceba"`, 子串`"ece"`仅包含字符`'e'`和`'c'`，所以它是有效的。 它的长度是`3`，这是该输入中的最大有效子字符串长度。 

输入是单个字符串`s`，输出是一个整数，表示有效子字符串的最大长度。 

约束条件很重要：

 -`1 <= s.length <= 10^5`- 该字符串仅包含英文字母。 

字符串长度可达`100,000`意味着低效的解决方案不会通过。 任何重复扫描字符串大部分的算法，例如`O(n^2)`或者`O(n^3)`对于最坏的情况，解决方案变得太慢。 这强烈表明我们需要一个线性时间解决方案。 

在设计算法之前考虑几个边缘情况很重要：

 - 只包含一个字符的字符串，例如`"a"`。 
- 所有字符都相同的字符串，例如`"aaaaa"`。 
- 恰好包含两个不同字符的字符串，例如`"ababab"`。 
- 第三个不同字符频繁出现并强制窗口经常缩小的字符串。 
- 非常短的字符串，尤其是长度`1`和`2`。 

该问题保证字符串非空，因此我们永远不需要处理完全空的输入。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是生成每个可能的子字符串并检查它是否最多包含两个不同的字符。 

对于每个起始索引`i`，我们可以扩展到每个结束索引`j`，形成子串`s[i:j+1]`。 对于每个子字符串，我们计算它包含多少个唯一字符。 如果计数小于或等于`2`，我们更新最大长度。 

这种方法是正确的，因为它详尽地检查了每个可能的子字符串，因此它不会错过最佳答案。 

然而，对于大输入来说它太慢了。 有`O(n^2)`子字符串，并且检查不同的字符可能需要长达`O(n)`最坏情况下的时间。 即使进行了优化，蛮力方法仍然是二次的，这对于`n = 10^5`。 

### 最优滑动窗口方法

 关键的观察是我们只关心最多有两个不同字符的连续子字符串。 这是滑动窗口效果很好的经典情况。 

我们维护一个窗口，而不是从头开始重新计算每个子字符串`[left, right]`始终满足最多包含两个不同字符的条件。 

当我们移动时`right`通过字符串：

 - 我们将新角色添加到窗口中。 
- 如果窗口变得无效，意味着它现在包含两个以上不同的字符，我们将移动`left`向前直到窗口再次有效。 
- 在每一步中，我们都会计算窗口长度并更新答案。 

哈希映射用于跟踪当前窗口内字符的频率。 这使我们能够有效地确定当前子字符串中存在多少个不同的字符。 

由于每个字符最多进入和离开窗口一次，因此总运行时间是线性的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 到 O(n) | 显式检查所有子字符串 |
 | 最佳| O(n) | O(1) | O(1) | 带字符频率图的滑动窗口|

 ## 算法演练

 1.初始化两个指针，`left`和`right`，表示当前的滑动窗口。 两者都开始于`0`。 
2. 创建一个名为的哈希图`char_count`存储当前窗口内每个字符的频率。 
3. 初始化变量`max_length`存储迄今为止找到的最佳答案。 
4. 使用迭代遍历字符串`right`作为扩展指针。 
5. 对于每个角色`s[right]`，通过增加其频率计数将其添加到哈希映射中。 
6. 添加字符后，检查窗口现在是否包含两个以上不同的字符。 这是通过检查哈希图的大小来确定的。 
7. 如果有两个以上不同的字符，则该窗口无效。 恢复有效性：

 1. 减少数量`s[left]`。 
2. 如果其频率变为零，则将其从哈希图中完全删除。 
3. 移动`left`向右一步。 
4. 继续缩小，直到窗口再次包含至多两个不同的字符。 
8. 窗口有效后，使用以下方法计算其长度：`right - left + 1`9. 更新`max_length`如果当前窗口大于任何先前看到的有效窗口。 
10. 继续直到`right`到达字符串末尾。 
11. 返回`max_length`。 

### 为什么它有效

 滑动窗口始终保持当前子串最多包含两个不同字符的不变式。 

每当窗口变得无效时，我们都会将其缩小到足以恢复有效性的程度。 由于我们在扩展和收缩期间检查每个可能的有效窗口，因此我们永远不会错过最佳子串。 

由于每个索引最多向前移动一次，因此该算法以线性时间运行。 

## Python 解决方案```python
class Solution:
    def lengthOfLongestSubstringTwoDistinct(self, s: str) -> int:
        left = 0
        max_length = 0
        char_count = {}

        for right in range(len(s)):
            current_char = s[right]
            char_count[current_char] = char_count.get(current_char, 0) + 1

            while len(char_count) > 2:
                left_char = s[left]
                char_count[left_char] -= 1

                if char_count[left_char] == 0:
                    del char_count[left_char]

                left += 1

            current_window_length = right - left + 1
            max_length = max(max_length, current_window_length)

        return max_length
```该实现首先初始化滑动窗口边界和用于频率计数的哈希图。 

这`for`循环使用以下命令一次扩展窗口一个字符`right`指针。 每个新包含的字符都会添加到`char_count`。 

这`while`循环确保窗口保持有效。 如果存在两个以上不同的字符，则窗口的左侧会收缩，直到只剩下两个不同的字符。 

缩小窗口时，最左边字符的计数会减少。 如果其计数变为零，则该字符将从地图中完全删除。 这使得映射中键的数量等于当前窗口内不同字符的数量。 

确保有效性后，计算当前窗口长度并与迄今为止看到的最佳结果进行比较。 

最后返回最大有效子串长度。 

## 解决方案```go
func lengthOfLongestSubstringTwoDistinct(s string) int {
	left := 0
	maxLength := 0

	charCount := make(map[byte]int)

	for right := 0; right < len(s); right++ {
		currentChar := s[right]
		charCount[currentChar]++

		for len(charCount) > 2 {
			leftChar := s[left]
			charCount[leftChar]--

			if charCount[leftChar] == 0 {
				delete(charCount, leftChar)
			}

			left++
		}

		currentWindowLength := right - left + 1

		if currentWindowLength > maxLength {
			maxLength = currentWindowLength
		}
	}

	return maxLength
}
```Go 实现遵循与 Python 版本相同的滑动窗口逻辑。 

一个实现差异是 Go 字符串以字节为索引。 由于该问题仅保证英文字母，因此使用`byte`完全安全高效。 

频率图是使用实现的`map[byte]int`。 

Go 不提供内置的`max`函数用于整数，因此比较是手动完成的`if`陈述。 

不需要对空字符串进行特殊处理，因为约束保证字符串长度至少为`1`。

 ## 边缘情况

 一种重要的边缘情况是仅包含一个不同字符的字符串，例如`"aaaaaa"`。 有缺陷的实现可能会错误地缩小窗口或错误地处理频率删除。 在此实现中，哈希映射始终只包含一个键，因此收缩循环永远不会执行，并且算法会正确返回完整的字符串长度。 

另一个重要的情况是当第三个不同的字符立即出现时，例如`"abc"`。 一个简单的滑动窗口实现可能只缩小一次，并且仍然在窗口内留下三个不同的字符。 该解决方案使用`while`循环而不是`if`语句，保证窗口继续缩小，直到再次有效。 

第三种边缘情况是最佳子串出现在字符串的中间而不是开头或结尾。 例如，`"aabbcc"`具有最优子串`"aabb"`或者`"bbcc"`, 两者的长度`4`。 该算法在遍历过程中检查每个有效窗口，因此无论其位置如何，它都能正确识别最佳子串。 

另一种微妙的情况是重复缩小和扩大，例如`"ababffzzeee"`。 窗口在多个有效和无效状态之间转换。 由于在哈希映射中精确跟踪字符频率，因此算法始终准确地知道字符何时完全离开窗口，从而防止过时的条目破坏不同的字符计数。
