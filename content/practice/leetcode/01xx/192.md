 **难度：** 🟡 中等
 **主题：** 外壳

 ## 解决方案

 ## 问题理解

 这个问题要求我们编写一个shell脚本来读取一个名为的文本文件`words.txt`并计算每个单词出现的次数。 计算出现次数后，脚本必须打印每个唯一的单词及其频率，并按频率降序排列。 

输入表示为纯文本文件而不是函数参数。 该文件仅包含小写英文字母和空格。 保证单词仅包含小写字母，并且单词之间由一个或多个空格字符分隔。 这种保证简化了解析，因为我们不需要担心标点符号、大写转换或特殊字符。 

预期输出由几行组成，其中每行包含一个单词，后跟其计数，并用空格分隔。 这些线路必须按照从最高频率到最低频率的顺序排列。 例如，如果`"the"`出现四次并且`"sunny"`出现两次，`"the 4"`必须出现在之前`"sunny 2"`。 

这些约束告诉我们有关问题本质的一些重要信息。 由于单词由任意空格分隔，因此当存在多个空格或换行符时，仅基于单个空格的简单分割可能会失败。 我们还知道频率计数保证是唯一的，这意味着排序顺序永远不会有联系，因此我们不需要处理二次排序逻辑。 

一些边缘情况值得预先识别。 如果我们假设每个单词都由一个空格分隔，则多个连续空格或换行符可能会导致解析问题。 仅包含一个重复多次的唯一单词的文件应该仍然可以正常工作。 仅包含一个单词的文件必须恰好生成一个输出行。 该问题保证了有效的小写输入，这意味着我们不需要对标点符号或格式错误的单词进行防御性处理。 

## 方法

 ### 蛮力方法

 暴力解决方案将重复扫描文件中的每个唯一单词。 首先，我们可以提取所有单词，然后对于每个单词，再次扫描整个文件并计算该单词出现的次数。 

这种方法之所以有效，是因为每个单词的频率最终都是通过详尽的比较计算出来的。 然而，它的效率很低。 如果有`n`总单词数，对于每个单词，我们对文件执行一次完整的遍历，总工作量变为二次。 

在 shell 脚本中，这可能涉及嵌套循环或重复调用命令，例如`grep`，这会反复重新读取该文件。 由于文件操作的成本相对较高，因此这种方法会执行不必​​要的重复工作。 

### 最佳方法

 关键的观察是我们只需要扫描输入一次即可计算频率。 Unix 命令行实用程序已经提供了用于文本转换、分组和排序的有效工具。 

最佳管道的工作原理如下：

 1. 将所有以空格分隔的单词转换为每行一个单词。 
2. 对单词进行排序，使相同的单词相邻。 
3. 计算连续的重复项。 
4. 再次按频率降序排序。 
5. 重新格式化输出以匹配所需的格式。 

排序很重要的原因是像这样的命令`uniq -c`只计算连续的重复行。 通过首先排序，相同的单词会自动分组在一起。 

一个简洁的单行 Unix 管道解决方案是：```
cat words.txt | tr -s ' ' '\n' | sort | uniq -c | sort -rn | awk '{print $2, $1}'
```我们可以通过避免不必要的事情来稍微改进这一点`cat`用法：```
tr -s ' ' '\n' < words.txt | sort | uniq -c | sort -rn | awk '{print $2, $1}'
```以下是每个命令的作用：

 -`tr -s ' ' '\n'`将空格转换为换行符并压缩重复的空格。 
-`sort`将相同的单词组合在一起。 
-`uniq -c`计算相邻的重复项。 
-`sort -rn`按计数按降序排列。 
-`awk '{print ⟦PROTECT_14⟧1}'`将输出顺序交换为`word count`。

 ## 算法演练

 1. 阅读内容`words.txt`并将输入标准化为每行一个单词。 这是必要的，因为单词可能被空格或换行符分隔，并且像这样的工具`uniq`逐行工作。 
2. 按字母顺序对所有单词进行排序。 这一步至关重要，因为`uniq -c`只计算连续的重复值。 如果不排序，出现在文件不同部分的相同单词将被单独计数。 
3. 使用以下方法计算连续重复的单词`uniq -c`。 在此阶段，每个独特的单词都将与其频率配对。 
4. 根据频率计数以降序对结果进行数字排序。 这可以确保频率最高的单词首先出现。 
5. 将输出重新格式化为所需的格式`word count`格式。 自从`uniq -c`印刷`count word`，我们使用相反的顺序`awk`。 

Unix 管道的选择很重要，因为每个实用程序都专注于一项任务，并且管道允许数据在命令之间有效地流动，而无需创建不必要的中间文件。 

## Python 解决方案

 由于这是一个 Shell 问题，LeetCode 需要 Bash 脚本而不是 Python 实现。 然而，为了反映 Python 中的计数逻辑，等效的实现将如下所示：```python
from collections import Counter

class Solution:
    def wordFrequency(self) -> None:
        with open("words.txt", "r", encoding="utf-8") as file:
            words = file.read().split()

        word_counts = Counter(words)

        sorted_words = sorted(
            word_counts.items(),
            key=lambda item: item[1],
            reverse=True
        )

        for word, count in sorted_words:
            print(word, count)
```此实现读取文件，按空格分割单词，使用以下方法计算频率`Counter`，按频率降序排序，并打印结果。 

代码首先打开`words.txt`并阅读其内容。 呼唤`.split()`足够了，因为它会自动处理一个或多个空白字符，包括空格和换行符。 这`Counter`对象充当哈希映射，跟踪每个单词出现的次数。 统计完毕后，我们使用频率值作为排序键对字典项进行降序排序。 最后，以所需的格式打印结果。 

## 解决方案

 虽然 LeetCode 期望 Bash 来解决这个问题，但在 Go 中也可以实现相同的逻辑进行比较：```go
package main

import (
	"fmt"
	"os"
	"sort"
	"strings"
)

type WordCount struct {
	Word  string
	Count int
}

func wordFrequency() {
	content, err := os.ReadFile("words.txt")
	if err != nil {
		return
	}

	words := strings.Fields(string(content))

	wordCounts := make(map[string]int)

	for _, word := range words {
		wordCounts[word]++
	}

	result := make([]WordCount, 0, len(wordCounts))

	for word, count := range wordCounts {
		result = append(result, WordCount{
			Word:  word,
			Count: count,
		})
	}

	sort.Slice(result, func(i, j int) bool {
		return result[i].Count > result[j].Count
	})

	for _, item := range result {
		fmt.Printf("%s %d\n", item.Word, item.Count)
	}
}
```Go版本使用`os.ReadFile`加载文件内容并`strings.Fields()`使用任意空格分割单词。 映射充当频率表，类似于 Python 的`Counter`。 因为 Go 映射是无序的，所以我们创建一个结构体切片并使用显式排序`sort.Slice()`。 

与 Python 不同，Go 不提供内置的频率计数实用程序，例如`Counter`，因此需要通过地图进行手动计数。 不用担心整数溢出，因为这个问题中的词频仍然在 Go 的整数限制内。

## 边缘情况

 一种重要的边缘情况是单词之间存在多个连续空格或换行符。 仅在单个空格上拆分的简单解析器可能会产生空标记或不正确的计数。 该实现正确处理了这个问题，因为`tr -s`Bash 中压缩重复的空格，而 Python 中的`.split()`和Go的`strings.Fields()`自然地处理任意空白。 

另一种边缘情况是仅包含一个重复多次的唯一单词的文件，例如：```
hello hello hello hello
```如果分组处理不当，糟糕的实现可能会意外打印重复的条目。 排序之后是`uniq -c`保证相同的单词被合并到一个频率计数中。 

第三种边缘情况是只包含一个单词的文件：```
leetcode
```该算法仍然可以正确运行，因为排序和计数适用于单个元素输入。 输出变为：```
leetcode 1
```最后，如果换行符与空格的处理方式不同，跨多行出现的单词可能会出现问题。 由于问题表明单词是由空格字符分隔的，因此使用标准化空格的工具可以确保正确的行为，而不管行格式如何。
