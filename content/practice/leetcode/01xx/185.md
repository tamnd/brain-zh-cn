 ## 解决方案

 ## 问题理解

 这是一个 SQL 数据库问题，我们需要识别属于**每个部门内唯一薪资前三名**的员工。 

输入由两个表组成：

 的`Employee`表存储每个员工的信息，包括：

 -`id`，员工的唯一标识符
 -`name`, 员工姓名
 -`salary`, 雇员的工资
 -`departmentId`，将员工链接到部门

 的`Department`表存储部门信息：

 -`id`, 唯一的部门标识符
 -`name`, 部门名称

 目标是返回包含三列的结果表：

 | 专栏 | 意义|
 | --- | --- |
 | 部门| 部门名称 |
 | 员工| 员工姓名|
 | 薪资| 员工薪资|

 关键要求是理解**前三名薪资**的含义。 它指的是**前三名独特薪资值**，而不是前三名员工。 

例如，假设一个部门的工资：`[90000, 85000, 85000, 70000, 69000]`前三名**独特**工资是：`90000, 85000, 70000`这意味着每一位赚取这些工资的员工都应该包括在内。 两名员工均带薪`85000`符合资格。 

该问题保证不存在具有完全相同的组合的员工`name`,`salary`， 和`department`，这简化了重复的处理。 

一些边缘情况很重要：

 - 一个部门可能包含少于三个不同的工资。 在这种情况下，我们包括所有工资属于可用唯一工资的员工。 
- 多名员工可以分享相同的工资。 由于排名是基于独特的薪资值，因此所有相关员工都应包括在内。 
- 部门可能只有一名员工，这意味着只有一份工资，并且该员工仍必须返回。 
- 一个幼稚的解决方案可能会错误地计算员工而不是不同的工资值，从而在出现平局时产生错误的结果。 

## 方法

 ### 蛮力方法

 暴力策略将检查每个员工并确定他们的薪水是否属于该部门的前三名独特薪水。 

对于每一位员工，我们可以：

 1. 查找同一部门的所有工资。 
2. 提取不同的薪资值。 
3. 按降序排列。 
4、拿工资前三名。 
5. 检查当前员工的工资是否在该集合内。 

这种方法之所以有效，是因为它直接计算每个员工的答案定义。 但是，它会重复重新计算同一部门中许多员工的部门薪资排名。 

如果一个部门有很多员工，重复排序工资就会变得低效。 我们最终为每一行做了多余的工作。 

### 最佳方法

 关键的观察是，我们应该计算排名**每个部门的工资**一次，而不是每个员工一次。 

SQL 窗口函数在这里是理想的选择。 具体来说，`DENSE_RANK()`问题自然就解决了。 

我们按部门对员工进行划分，并按工资降序排列。 

重要的细节是使用`DENSE_RANK()`而不是`RANK()`:

 -`DENSE_RANK()`对独特的薪资值给出连续排名。 
- 同等工资的员工享有相同的职级。 
- 没有引入间隙。 

示例：

 | 薪资| 密集等级 |
 | --- | --- |
 | 90000 | 1 |
 | 85000 | 2 |
 | 85000 | 2 |
 | 70000 | 3 |
 | 69000 | 4 |

 然后我们过滤级别小于或等于的员工`3`。 

这直接模拟了前三名**独特**薪资的要求。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N² log N) | O(N² log N) | O(N) | 重新计算许多员工的排序薪资排名|
 | 最佳| O(N log N) | O(N log N) | O(N) | 使用SQL窗口函数对薪资进行高效排名 |

 ## 算法演练

 ### 最优算法使用`DENSE_RANK()`1. 加入`Employee`和`Department`表，以便每个员工记录包含部门名称。 这是必要的，因为输出需要部门名称而不仅仅是部门 ID。 
2. 按部门划分员工`PARTITION BY departmentId`。 这确保了每个部门的薪资排名是独立计算的。 
3. 按部门内部薪资降序排列。 更高的薪水应该获得更好的排名，所以我们按`salary DESC`。 
4. 使用`DENSE_RANK()`为薪资值分配排名。 薪资相同的员工会获得相同的排名，因为排名是基于独特的薪资值。 
5、过滤级别为的员工`<= 3`。 这些员工属于各自部门中薪资最高的前三名。 
6. 返回部门名称、员工姓名和工资。 

### 为什么它有效

 正确性来自于行为`DENSE_RANK()`。 

每个部门内部，`DENSE_RANK()`将相同的级别分配给相同的薪水值，并且仅当出现新的不同薪水时才增加级别。 因此，排名`1`,`2`， 和`3`与前三名**独特**工资完全对应。 筛选到这些排名可确保包含所有符合条件的员工，并且不会返回前三个唯一薪资值之外的任何员工。 

## Python 解决方案

 LeetCode 数据库问题使用 SQL 而不是 Python 方法。 下面是 LeetCode 可提交的确切 SQL 解决方案。```python
# This problem requires SQL, not Python.
#
# MySQL Solution:

SELECT
    d.name AS Department,
    ranked.name AS Employee,
    ranked.salary AS Salary
FROM (
    SELECT
        name,
        salary,
        departmentId,
        DENSE_RANK() OVER (
            PARTITION BY departmentId
            ORDER BY salary DESC
        ) AS salary_rank
    FROM Employee
) AS ranked
JOIN Department d
    ON ranked.departmentId = d.id
WHERE ranked.salary_rank <= 3;
```该解决方案首先创建一个名为的派生表`ranked`。 在这个子查询中，我们计算其部门内每个员工工资的密集排名。 

这`PARTITION BY departmentId`条款确保每个部门的薪资排名独立重新启动。 如果不进行划分，不同部门的工资就会错误地相互竞争。 

这`ORDER BY salary DESC`条款将较高的工资排在第一位。 

最重要的一块是`DENSE_RANK()`。 相同薪资的员工享有相同的职级，满足前三**独特**薪资的要求。 

排名结束后，我们加入`Department`表来检索部门名称。 最后，我们过滤行`salary_rank <= 3`，确保只返回高收入者。

 ## 边缘情况

 ### 多名员工享有相同的工资

 一个常见的错误是将排名视为基于员工而不是基于工资。 例如，如果两名员工都挣钱`85000`，一个天真的前三名员工解决方案可能会排除其中之一。 使用`DENSE_RANK()`确保相同的薪水获得相同的级别，因此所有捆绑员工都包括在内。 

### 独特薪资少于三个的部门

 有些部门可能只有一两个不同的工资。 脆弱的实现可能只需要三个等级，并且意外地排除了有效的员工。 查询自然会处理这个问题，因为`DENSE_RANK()`只创建现有的薪资水平，并过滤`<= 3`包括一切可用的东西。 

### 超过三名员工但少于三个薪资级别

 考虑工资`[100, 100, 90, 90, 80]`。 员工虽多，但工资独特的只有三人。 限制三名员工的幼稚实施将会失败。 该解决方案对工资值进行排名，而不是对员工人数进行排名，因此每个符合条件的员工都会正确返回。
