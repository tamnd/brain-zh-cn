 ## 解决方案

 ## 问题理解

 这个问题要求我们实现一个`read`使用受限制的 API 调用的函数`read4`。 文件本身对我们来说是隐藏的，访问其内容的唯一方法是重复调用`read4`。 

这`read4`API 将最多 4 个连续字符从文件读取到名为的临时缓冲区中`buf4`。 它返回实际读取的字符数。 如果文件仍有至少 4 个未读字符，则返回值为 4。如果剩余字符少于 4 个，则返回剩余计数。 如果文件指针已经到达文件末尾，则返回0。 

我们的目标是实施：```
read(buf, n)
```这个函数最多应该读取`n`将文件中的字符放入目标缓冲区`buf`，然后返回实际读取的字符数。 

重要的细节是我们不允许直接访问该文件。 我们必须反复调用`read4`直到：

 1.我们已经准确阅读了`n`字符，或
 2. 我们到达文件末尾。 

限制相对较小：

 -`file.length <= 500`-`n <= 1000`这意味着从性能角度来看，效率并不是极其重要，但问题旨在测试仔细的模拟和缓冲区处理。 

一些边缘情况很重要：

 - 文件包含的字符数可能少于`n`-`n`可能不是 4 的倍数
 - 最后一个`read4`调用可能返回少于 4 个字符
 - 我们必须避免将多余的字符复制到`buf`- 读完后必须立即停止`n`字符，即使`read4`返回更多可用数据

 幼稚的实现很容易引入相差一的错误或意外复制太多字符。 

## 方法

 ### 蛮力方法

 暴力方法是反复调用`read4`，将返回的所有内容追加到中间列表或字符串中，然后将结果截断到第一个`n`人物。 

从概念上讲，这是可行的，因为`read4`最终耗尽文件。 收集完所有字符后，我们只需复制第一个字符即可`n`将字符写入目标缓冲区。 

然而，这种方法是浪费的，因为它可能会读取和存储比必要的更多的数据。 例如，如果我们只需要 1 个以上的字符，但是`read4`给我们 4，我们不必要地保留额外的数据，即使问题保证了`read`只被调用一次。 

它还引入了不必要的辅助存储。 

### 最佳方法

 关键的观察是我们可以增量地处理数据。 

每次致电`read4`给我们最多 4 个字符。 我们立即仅将所需的数量复制到目标缓冲区中。 我们维护一个计数器来跟踪已经写入了多少个字符`buf`。 

算法在以下情况下停止：

 - 我们已经完全复制了`n`字符，或
 -`read4`返回少于 4 个字符，这意味着我们到达了文件末尾

 这种方法避免了不必要的存储，并且只处理一次字符。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(文件长度) | O(文件长度) | 在截断之前将所有内容读入临时存储 |
 | 最佳| O(n) | O(1) | O(1) | 将字符直接复制到目标缓冲区 |

 ## 算法演练

 1.创建临时缓冲区`buf4`尺寸为 4。 

需要这个缓冲区是因为`read4`将其结果写入其中。 我们不能直接传递目标缓冲区，因为`read4`始终需要 4 个字符的临时数组。 
2. 维护一个变量`total_read`。 

该变量跟踪有多少字符已被复制到目标缓冲区中`buf`。 
3. 输入一个继续 while 的循环`total_read < n`。 

一旦我们填满了所要求的字符数，我们就会停止。 
4. 打电话`read4(buf4)`。 

该函数返回实际从文件中读取的字符数。 将此值存储在`count`。 
5. 如果`count == 0`，立即停止。 

这意味着文件指针已到达文件末尾，并且没有更多可用字符。 
6. 复制字符`buf4`进入`buf`。 

我们一次复制一个字符，同时：

 - 我们仍然有未读的字符`buf4`- 我们还没有复制`n`整体人物
 7. 增量`total_read`在每个复制的字符之后。 

这确保我们始终知道有多少字符已放入目标缓冲区中。 
8. 继续直到：

 -`total_read == n`-`read4`返回 0
 9. 返回`total_read`。 

这是成功读取的实际字符数。 

### 为什么它有效

 该算法保持不变式`buf[0:total_read]`始终以正确的顺序准确包含迄今为止从文件中读取的字符。 

每次致电`read4`将文件指针前进返回的字符数。 由于我们按顺序复制字符并恰好停在`n`，我们永远不会跳过字符或覆盖以前复制的数据。 

因为循环在读取后终止`n`字符或到达文件结尾后，返回的值始终是正确的。 

## Python 解决方案```python
"""
The read4 API is already defined for you.

    @param buf4, a list of characters
    @return an integer
    def read4(buf4):
"""

from typing import List

class Solution:
    def read(self, buf: List[str], n: int) -> int:
        """
        :type buf: Destination buffer (List[str])
        :type n: Number of characters to read (int)
        :rtype: The number of actual characters read (int)
        """
        
        buf4 = [''] * 4
        total_read = 0
        
        while total_read < n:
            count = read4(buf4)
            
            if count == 0:
                break
            
            for i in range(count):
                if total_read == n:
                    break
                
                buf[total_read] = buf4[i]
                total_read += 1
        
        return total_read
```实现首先分配一个临时缓冲区`buf4`容量为 4。这是必要的，因为`read4`始终写入单独的 4 字符数组。 

变量`total_read`跟踪已将多少字符复制到目标缓冲区中。 

在主循环中，我们反复调用`read4(buf4)`。 返回值告诉我们有多少个有效字符被放入`buf4`。 

如果`read4`返回 0，我们知道我们已经到达文件末尾并且必须停止。 

否则，我们遍历返回的字符并将它们一次一个地复制到目标缓冲区中。 在每次复制之前，我们检查是否已经达到`n`人物。 这可以防止我们在最终的时候复制多余的字符`read4`调用返回的数据多于我们仍然需要的数据。 

最后，我们返回`total_read`，代表成功读取的确切字符数。 

## 解决方案```go
/**
 * The read4 API is already defined for you.
 *
 *     read4 := func(buf4 []byte) int
 */

var solution = func(read4 func([]byte) int) func([]byte, int) int {

    return func(buf []byte, n int) int {

        buf4 := make([]byte, 4)
        totalRead := 0

        for totalRead < n {

            count := read4(buf4)

            if count == 0 {
                break
            }

            for i := 0; i < count && totalRead < n; i++ {
                buf[totalRead] = buf4[i]
                totalRead++
            }
        }

        return totalRead
    }
}
```Go 实现遵循与 Python 版本相同的逻辑，但存在一些特定于语言的差异。 

Go 使用`[]byte`而不是字符数组。 临时缓冲区`buf4`分配使用`make([]byte, 4)`。 

内部循环直接在循环头中组合两个停止条件：```go
for i := 0; i < count && totalRead < n; i++
```这避免了显式嵌套`if`Python 中使用的语句。 

不存在整数溢出问题，因为约束非常小。 切片处理很简单，因为目标缓冲区保证有足够的容量。

 ## 边缘情况

 当文件包含的字符少于`n`。 例如，该文件可能只包含`"abc"`尽管`n = 10`。 有错误的实现可能会永远继续循环或在到达文件末尾后尝试复制无效字符。 我们的实现正确地处理了这个问题，因为`read4`最终返回0，立即终止循环。 

另一个重要的情况发生在`n`小于当前返回的字符数`read4`称呼。 例如，如果我们只需要一个字符，但是`read4`返回 4 个字符，我们必须仅将一个字符复制到目标缓冲区中。 内在条件：```
if total_read == n:
    break
```防止意外的过度复制。 

当文件长度恰好是 4 的倍数时，会出现第三种棘手的情况。在这种情况下，每个`read4`在结束之前调用正好返回 4。一些不正​​确的实现错误地认为需要小于 4 的返回值才能终止。 我们的解决方案会在以下任一情况下终止：`total_read == n`或者`read4`返回 0，因此它可以正确处理精确倍数。 

第四个微妙的情况涉及最后的部分块。 假设文件长度为5。`read4`返回 4，而第二个返回 1。实现必须从第二个缓冲区准确复制一个有效字符并忽略其余未使用的位置。 因为我们只迭代到`count`，我们从不读取垃圾值`buf4`。
