[LeetCode 第 165 题](https://leetcode.com/problems/compare-version-numbers/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们比较两个以字符串表示的软件版本号。 每个版本由一个或多个用点分隔的数字修订版组成（`.`）。 例如，`"1.2.10"`包含三个修订：`1`,`2`， 和`10`。 

重要的细节是修订版本是作为整数而不是字符串进行比较的。 这意味着必须忽略前导零。 例如，`"01"`和`"001"`两者都代表整数`1`，因此它们被认为是相等的。 

比较必须从左到右、逐个修订地进行。 在每个位置：

 - 如果修订于`version1`小于相应的修订版`version2`， 返回`-1`。 
- 如果更大，则返回`1`。 
- 如果相等，则继续比较下一个版本。 

另一个重要规则是缺失的修订被视为`0`。 例如：

-`"1.0"`和`"1.0.0.0"`是相等的，因为缺少的修订`"1.0"`表现得像零。 
-`"1.2"`小于`"1.2.1"`因为缺少第三次修订`"1.2"`被视为`0`。 

输入尺寸比较小，每个版本字符串的长度最多`500`。 由于每个修订版都适合 32 位整数，因此我们无需担心解析极大的数值。 这意味着高效的线性扫描解决方案就足够了。 

有几种边缘情况很容易导致简单的实现失败。 前导零就是这样一种情况，因为字符串比较会错误地考虑`"01"`和`"1"`不同的。 具有不同修订数量的版本是另一个挑战，因为尾随丢失的修订必须被解释为零。 最后，尾随零修订，例如`"1.0.0"`相对`"1"`必须正确处理并平等对待。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将两个版本字符串按点拆分为字符串数组，将每个修订版本转换为整数，然后逐个索引比较它们。 

例如：```
"1.02.10" → [1, 2, 10]
"1.2.3"   → [1, 2, 3]
```我们将迭代较长的数组长度并将任何丢失的元素视为`0`。 

这种方法是正确的，因为它直接遵循问题定义。 每个修订版都被标准化为其整数表示形式，在整数转换期间自然会删除前导零，并且缺失的修订版将变为零。 

但是，拆分字符串会创建额外的数组和临时字符串对象。 虽然约束足够小，仍然可以有效地工作，但我们可以在辅助空间方面做得更好。 

### 关键见解

 我们实际上不需要将版本字符串拆分为数组。 

相反，我们可以使用两个指针处理这两个字符串并动态解析每个修订版本。 由于修订版是用点分隔的，因此我们可以扫描直到下一个点，构建整数值，进行比较，然后继续。 

这是可行的，因为版本比较本质上是顺序的。 我们一次只关心一对修订版。 无需预先存储所有修订。 

这为我们提供了具有恒定额外空间的最佳线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n + m) | O(n + m) | 将字符串拆分为数组并比较修订版 |
 | 最佳| O(n + m) | O(1) | O(1) | 两个指针直接解析修订版本，无需额外存储 |

 这里，`n`和`m`的长度是`version1`和`version2`。 

## 算法演练

 ### 最优两指针算法

 1. 初始化两个指针，每个版本字符串一个。 

这些指针跟踪当前解析位置`version1`和`version2`。 由于修订是从左到右处理的，因此指针使我们能够有效地扫描而无需拆分。 
2. 当任一指针尚未到达其字符串末尾时，提取下一个修订号。 

对于每个版本：

 - 开始于`revision = 0`。 
- 读取数字直到到达一个点（`.`) 或字符串的末尾。 
- 通过重复乘以将修订版本转换为整数`10`并添加数字。 

这会自动忽略前导零，因为整数构造会标准化它们。 
3. 比较提取的修订版本。 

- 如果`revision1 < revision2`， 返回`-1`。 
- 如果`revision1 > revision2`， 返回`1`。 

如果相等，则继续下一次修订。 
4. 将指针移过点分隔符。 

处理修订后，再次增加指针以跳过点（如果存在）。 
5. 继续，直到完全处理两个字符串。 

如果没有发现差异，则返回`0`因为所有修订都匹配。 

### 为什么它有效

 该算法保持了当前指针之前的每个修订都已被正确比较并发现相等的不变性。 在每一步中，它都会根据问题规则精确地比较一个相应的修订对。 缺失的修改自然就变成了`0`因为一旦指针到达其字符串的末尾，其解析的修订版本仍然为零。 由于每个修订都是按顺序处理的，并且任何不相等的修订都会立即确定结果，因此算法保证返回正确的比较。 

## Python 解决方案```python
class Solution:
    def compareVersion(self, version1: str, version2: str) -> int:
        pointer1 = 0
        pointer2 = 0

        length1 = len(version1)
        length2 = len(version2)

        while pointer1 < length1 or pointer2 < length2:
            revision1 = 0
            revision2 = 0

            while pointer1 < length1 and version1[pointer1] != ".":
                revision1 = revision1 * 10 + int(version1[pointer1])
                pointer1 += 1

            while pointer2 < length2 and version2[pointer2] != ".":
                revision2 = revision2 * 10 + int(version2[pointer2])
                pointer2 += 1

            if revision1 < revision2:
                return -1

            if revision1 > revision2:
                return 1

            pointer1 += 1
            pointer2 += 1

        return 0
```该实现首先创建两个跟踪版本字符串中位置的指针。 该算法不分割字符串，而是直接读取修订版本。 

在主循环内，每个修订版本都被逐个字符地解析，直到到达点或字符串末尾。 将当前值乘以`10`添加下一个数字自然会构造整数表示，这也会删除任何前导零。 

提取两个修订版本后，立即对它们进行比较。 如果较大，则立即返回答案，因为版本比较是由第一个不同的修订版确定的。 

如果修订版本相等，则指针前进越过点分隔符并继续处理下一个修订版本。 如果循环结束时没有发现差异，则版本相等并且`0`被返回。 

## 解决方案```go
func compareVersion(version1 string, version2 string) int {
    pointer1 := 0
    pointer2 := 0

    length1 := len(version1)
    length2 := len(version2)

    for pointer1 < length1 || pointer2 < length2 {
        revision1 := 0
        revision2 := 0

        for pointer1 < length1 && version1[pointer1] != '.' {
            revision1 = revision1*10 + int(version1[pointer1]-'0')
            pointer1++
        }

        for pointer2 < length2 && version2[pointer2] != '.' {
            revision2 = revision2*10 + int(version2[pointer2]-'0')
            pointer2++
        }

        if revision1 < revision2 {
            return -1
        }

        if revision1 > revision2 {
            return 1
        }

        pointer1++
        pointer2++
    }

    return 0
}
```Go 实现遵循与 Python 解决方案相同的两指针策略。 由于 Go 字符串内部是字节切片，因此使用以下方法执行数字转换：```go
int(version1[pointer1] - '0')
```这可以有效地将字符数字转换为其数值。 

不需要特殊的溢出处理，因为该问题保证每个修订都适合 32 位整数。 缺少的修订自然会被视为零，因为一旦指针到达字符串的末尾，其修订值就会保持不变`0`。

 ## 边缘情况

 一个重要的边缘情况是**修订版中的前导零**。 天真的字符串比较可能会错误地决定`"01"`和`"1"`之所以不同，是因为它们的文本形式不同。 该实现通过将修订版本解析为整数来避免此问题，这会在转换过程中自动删除前导零。 

另一个关键的边缘情况是**具有不同长度的版本**。 例如，`"1.0"`和`"1.0.0.0"`应该是平等的。 一旦一个字符串结束就停止的简单实现可能会错误地得出它们不同的结论。 该算法通过继续直到两个字符串都用完并将丢失的修订视为`0`。 

第三个微妙的边缘情况是**多位数字比较与字典比较**。 考虑`"1.10"`和`"1.2"`。 字符串比较会错误地说`"10" < "2"`因为`'1' < '2'`。 由于该实现构造了整数值，因此它可以正确评估`10 > 2`。 

最后，**全零尾随修订版**，例如`"0"`相对`"0.0.0"`如果尾随修订未标准化，可能会导致错误。 因为缺少修订默认为`0`，实现正确地将这些版本识别为相同的。
