[LeetCode 第 153 题](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 这个问题要求我们在已经被**旋转**多次的排序数组中找到**最小的元素**。 

按升序排序的数组最初可能如下所示：```
[1,2,3,4,5,6,7]
```旋转后，可能会变成：```
[4,5,6,7,1,2,3]
```或保持不变：```
[1,2,3,4,5,6,7]
```重要的观察是数组最初是排序的，并且旋转后它仍然保留特定的结构。 实际上有**两个排序部分**，最小值标记发生旋转的点。 

输入是一个整数数组`nums`包含**唯一值**，意味着不存在重复项。 保证数组在旋转之前已按升序排序。 输出应该是数组中的**最小元素**。 

最重要的约束是要求在 **O(log n)** 时间内解决问题。 由于对数组进行线性扫描需要 **O(n)** 时间，因此我们立即知道简单的迭代不能作为最佳解决方案。 输入的排序性质强烈建议使用**二分搜索**，因为二分搜索自然会实现对数性能。 

约束条件还告诉我们：

 - 数组大小范围为`1`到`5000`。 
- 值是唯一的，这简化了比较，因为相等的元素之间永远不会有歧义。 
- 数组始终有效并在之间轮换`1`和`n`次。 

一些边缘情况值得关注：

 - 单元素数组，例如`[5]`，其中答案显然是唯一的元素。 
- 已经排序的数组，例如`[11,13,15,17]`，其中不存在有效旋转并且第一个元素已经是最小值。 
- 靠近数组开头或结尾的旋转，例如`[5,1,2,3,4]`或者`[2,3,4,5,1]`。 
- 非常小的数组，例如`[2,1]`，其中二分查找中的相差一错误很常见。 

由于数组包含唯一值并且始终遵循旋转排序结构，因此我们可以依靠排序关系在每一步消除一半的搜索空间。 

## 方法

 ### 蛮力方法

 最直接的解决方案是扫描整个数组并跟踪遇到的最小值。 

我们将变量初始化为第一个元素，并将数组中的每个数字与其进行比较。 每当我们遇到较小的数字时，我们都会更新最小值。 

这是有效的，因为检查每个元素可以保证我们最终看到最小值。 

然而，这种方法需要 **O(n)** 时间，因为可能需要检查每个元素。 由于该问题明确需要 **O(log n)** 解决方案，因此暴力破解是不够的。 

### 最优方法，二分搜索

 关键的见解是，除了旋转点之外，数组**大部分都是排序的**。 

在普通的排序数组中：```
[1,2,3,4,5]
```最小的元素始终位于索引处`0`。 

在旋转数组中：```
[4,5,6,7,1,2,3]
```最小值正好出现在顺序中断的位置。 

重要的观察是：

 - 如果中间元素**大于最右边的元素**，则最小值必须位于**右半部分**。 
- 否则，最小值位于 **左半**，包括中间元素本身。 

例如：```
[4,5,6,7,1,2,3]
```如果`mid = 7`和`right = 3`:```
7 > 3
```这告诉我们最小值不能在左侧，因为左侧部分仍在增加。 因此，我们搜索右半部分。 

二分搜索在这里起作用，因为每次比较都会消除一半的搜索空间，从而产生 **O(log n)** 性能。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描整个数组以找到最小值 |
 | 最佳| O(log n) | O(1) | O(1) | 使用排序区域属性进行二分搜索 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`，到数组的开头和结尾。 

这些指针定义了可能存在最小值的当前搜索空间。 
2.继续搜索`left < right`。 

当两个指针相遇时，我们知道只剩下一个候选者，这必须是最小的。 
3. 计算中间索引：```
mid = left + (right - left) // 2
```这可以安全地找到中点并避免 Go 等语言中的溢出问题。 
4. 比较`nums[mid]`和`nums[right]`。 

这个比较告诉我们哪一侧包含旋转点。 

- 如果`nums[mid] > nums[right]`，最小值必须在**右半部分**。 

自从`mid`本身不能是最小值，移动：```
left = mid + 1
```- 否则，最小值位于**左半部分**，包括`mid`。 

移动：```
right = mid
```我们保留`mid`因为它仍然可能是最小值。 
5. 重复直到`left == right`。 

此时，两个指针都标识了最小元素。 
6. 返回`nums[left]`。 

### 为什么它有效

 该算法保持了最小元素始终在搜索范围内的不变性`[left, right]`。 

什么时候`nums[mid] > nums[right]`，左边到`mid`已正确排序且大于右侧部分，这意味着旋转点必须位于右侧。 

什么时候`nums[mid] <= nums[right]`，右半部分已排序，因此最小值不能超过`mid`，我们安全地继续向左搜索。 

由于每次迭代都会删除剩余范围的一半，同时保留搜索区间内的最小值，因此算法始终会收敛到正确答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMin(self, nums: List[int]) -> int:
        left = 0
        right = len(nums) - 1

        while left < right:
            mid = left + (right - left) // 2

            if nums[mid] > nums[right]:
                left = mid + 1
            else:
                right = mid

        return nums[left]
```实现首先定义搜索边界`left`和`right`。 

这`while left < right`循环继续缩小搜索间隔，直到只剩下一个元素。 

在每次迭代中，我们计算`mid`并比较`nums[mid]`和`nums[right]`。 

如果`nums[mid]`大于`nums[right]`，最小值必须位于右侧`mid`，所以我们移动`left`向前。 

否则，最小值为`mid`或向左移动，所以我们移动`right`到`mid`。 

最终，指针收敛到我们返回的最小元素。 

该实现直接遵循前面描述的算法并满足所需的 **O(log n)** 运行时间。 

## 解决方案```go
func findMin(nums []int) int {
	left := 0
	right := len(nums) - 1

	for left < right {
		mid := left + (right-left)/2

		if nums[mid] > nums[right] {
			left = mid + 1
		} else {
			right = mid
		}
	}

	return nums[left]
}
```Go 实现遵循与 Python 版本完全相同的二分搜索逻辑。 

一个小的实现细节是中点计算：```go
mid := left + (right-left)/2
```这种形式避免了潜在的整数溢出，这在 Go 和许多其他语言中被认为是良好的实践。 

由于该问题保证数组中至少有一个元素，因此不需要额外的空切片处理。 直接使用 Go 切片，索引语义也很简单。

 ## 边缘情况

 ### 单元素数组

 输入如下：```
[7]
```可能是错误的来源，因为二分搜索循环通常假设存在多个元素。 在这种情况下，`left == right`立即执行，因此循环永远不会执行。 执行正确返回`nums[left]`，这是唯一的元素。 

### 已经排序的数组

 一个数组，例如：```
[11,13,15,17]
```不包含有意义的旋转点。 幼稚的实现可能会错误地假设旋转始终存在并且无法返回第一个元素。 在我们的解决方案中，比较不断变化`right`朝向`left`，最终收敛于索引`0`，它正确包含最小值。 

### 边界旋转

 案例如下：```
[5,1,2,3,4]
```或者```
[2,3,4,5,1]
```是差一错误的常见来源。 枢轴发生在开始或结束时，使得很容易引入不正确的中点更新。 我们的实施小心地保留了`mid`必要时使用：```
right = mid
```而不是：```
right = mid - 1
```这确保了有效的最小候选不会被意外丢弃。
