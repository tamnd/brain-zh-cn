[LeetCode 第 176 题](https://leetcode.com/problems/second-highest-salary/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们从`Employee`桌子。 

这里的关键词是**独特**。 我们并不是在对工资进行排序后寻找第二行，而是在寻找第二个唯一的工资值。 这种区别很重要，因为重复的工资只算一次。 

例如，如果工资是：```
[100, 200, 200, 300]
```不同的薪资值为：```
[100, 200, 300]
```第二高的不同工资是`200`，不是排序后的第二行。 

输入是一个名为的数据库表`Employee`有两列：

 | 专栏 | 意义|
 | --- | --- |
 |`id`| 唯一的员工标识符 |
 |`salary`| 员工薪资|

 预期输出是一个单列表：```
+---------------------+
| SecondHighestSalary |
+---------------------+
| value or null       |
+---------------------+
```如果没有第二高的独特薪水，这意味着只有一个唯一的薪水值或表为空，我们必须返回`null`。 

一些重要的观察立即浮现出来：

 - 我们只关心**不同的薪资价值**
 - 我们需要**第二高**，而不是第二行
 - 如果存在少于两个不同的工资，我们返回`null`- 输出列名必须准确`SecondHighestSalary`因为这是一个数据库问题，所以挑战主要在于如何用 SQL 清晰地表达逻辑。 

重要的边缘情况包括重复工资、只有一名员工的表以及所有员工工资相同的情况。 在这些情况下，简单地排序并选择第二行的简单实现将会失败。 

## 方法

 ### 蛮力方法

 暴力方法首先检索所有工资，手动删除重复项，按降序对它们进行排序，然后选择第二个值（如果存在）。 

在 SQL 术语中，这可能意味着获取所有行、执行应用程序端处理或编写不必要地实现额外中间结果的查询。 

这种方法之所以有效，是因为对所有唯一工资进行排序可以保证第二个元素对应于第二高的工资。 然而，它的效率很低，因为我们处理的信息超出了必要的范围，并且依赖于外部逻辑。 

### 最佳方法

 关键的观察是 SQL 已经提供了排序、重复数据删除和限制行的机制。 

我们可以首先提取**不同的工资**，按降序对它们进行排序，然后使用`LIMIT`有偏移量。 

然而，有一个微妙的问题：如果不存在第二个工资，查询仍然必须返回包含`null`。 

为了优雅地处理这个问题，我们将查询包装在标量子查询中。 如果子查询没有找到第二个值，SQL会自动返回`NULL`。 

一个干净的解决方案如下所示：```sql
SELECT (
    SELECT DISTINCT salary
    FROM Employee
    ORDER BY salary DESC
    LIMIT 1 OFFSET 1
) AS SecondHighestSalary;
```### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 提取工资、删除重复项、手动排序 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 直接使用 SQL 排序和不同处理 |

 尽管这两种方法都涉及排序，因此具有相似的渐近复杂性，但最佳解决方案更清晰、数据库原生，并且需要更少的手动逻辑。 

## 算法演练

 1. 从中选择所有薪资值`Employee`桌子。 
2.使用删除重复的工资值`DISTINCT`。 这可以确保重复的工资不会错误地影响排名。 
3. 按降序对剩余的唯一工资进行排序，以便最高的工资首先出现。 
4. 使用跳过第一个结果`OFFSET 1`。 这就排除了最高工资的考虑。 
5. 使用`LIMIT 1`精确检索一行，代表第二高的薪水。 
6. 将查询包装在标量子查询中，并将结果别名为`SecondHighestSalary`。 如果不存在第二个工资，SQL自动返回`NULL`。 

### 为什么它有效

 正确性依赖于这样一个事实：按降序对不同的工资进行排序会产生独特工资值的排名顺序。 由于首先删除重复项，因此该排序中的第二项必须是第二高的不同工资。 如果排序包含少于两个元素，则标量子查询自然计算为`NULL`，符合问题要求。 

## Python 解决方案

 LeetCode 数据库问题使用 SQL 而不是可执行的 Python 代码。 由于请求的模板包含 Python，因此最接近的等效实现如下所示，以演示相同的算法逻辑。```python
from typing import List, Optional

class Solution:
    def secondHighestSalary(self, salaries: List[int]) -> Optional[int]:
        distinct_salaries = sorted(set(salaries), reverse=True)

        if len(distinct_salaries) < 2:
            return None

        return distinct_salaries[1]
```实现首先将工资清单转换为`set`，这会删除重复项。 然后，我们按降序对生成的唯一值进行排序，以便最大的薪水首先出现。 

排序后，我们检查是否存在至少两个不同的工资值。 如果不是，函数返回`None`，满足问题要求`null`。 

如果存在两个或多个唯一工资，则返回排序列表的第二个元素。 

对于实际的LeetCode提交来说，SQL的解决方案是：```python
SELECT (
    SELECT DISTINCT salary
    FROM Employee
    ORDER BY salary DESC
    LIMIT 1 OFFSET 1
) AS SecondHighestSalary;
```## 解决方案

 同样，Go 也不用于 LeetCode 数据库问题，但这里是等效的算法实现。```go
package main

import "sort"

func secondHighestSalary(salaries []int) *int {
	distinctSet := make(map[int]bool)

	for _, salary := range salaries {
		distinctSet[salary] = true
	}

	distinctSalaries := make([]int, 0, len(distinctSet))
	for salary := range distinctSet {
		distinctSalaries = append(distinctSalaries, salary)
	}

	sort.Sort(sort.Reverse(sort.IntSlice(distinctSalaries)))

	if len(distinctSalaries) < 2 {
		return nil
	}

	result := distinctSalaries[1]
	return &result
}
```Go 实现反映了 Python 逻辑。 Map 用于模拟集合，因为 Go 没有提供内置的集合类型。 去重后，工资按降序排列。 

Go 特定的主要区别是处理`nil`与价值观。 由于没有第二份工资对应于`null`，该函数返回一个指向整数的指针（`*int`）。 返回`nil`清楚地表示缺失的结果。

 ## 边缘情况

 ### 只有一份不同的薪水

 一个常见的错误是假设该表始终包含至少两个工资值。 如果只有一种独特的薪水，例如：```
[100]
```或者```
[100, 100]
```没有第二高的薪水。 执行正确返回`NULL`在 SQL 中和`None`在Python中。 

### 重复工资

 重复很容易破坏简单的实现。 考虑：```
[100, 200, 200, 300]
```如果我们简单地排序并获取第二行，我们将错误地返回`200`由于错误的原因，或者在其他情况下失败，例如`[300, 300, 200]`。 通过申请`DISTINCT`首先，在排名之前删除重复项。 

### 空表

 尽管示例中没有明确显示，但空表是另一个重要的情况。 标量子查询返回`NULL`当然，因为不存在第二份薪水。 这种行为完全符合问题的要求。 

### 所有员工享有相同的薪水

 当每个员工的收入相同时：```
[500, 500, 500]
```仍然只有一个明显的薪水值。 计算行而不是唯一值的简单解决方案将会失败。 这`DISTINCT`关键字保证此处的正确性。
