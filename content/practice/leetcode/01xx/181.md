[LeetCode 第 181 题](https://leetcode.com/problems/employees-earning-more-than-their-managers/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为`Employee`。 每行代表一名员工并包含四条信息：

 | 专栏 | 意义|
 | --- | --- |
 |`id`| 员工的唯一标识符 |
 |`name`| 员工姓名|
 |`salary`| 员工薪资|
 |`managerId`| 这`id`该员工的经理的|

 目标是返回工资严格高于经理工资的员工姓名。 

关键的观察是管理器也存储在同一个内部`Employee`桌子。 这意味着该表是自引用的。 我们必须比较同一个表中的行，而不是连接两个不同的表。 

对于每一位员工：

 - 看看他们的`managerId`- 找到经理行`id`匹配那个`managerId`- 比较员工的工资和经理的工资
 - 如果员工收入更高，请将其姓名包含在结果中

 输出应包含一个名为`Employee`。 

该问题保证了`id`是唯一的，因此每个员工最多映射到一位经理。 处于层级最高层的员工可以拥有`NULL`在`managerId`，这意味着他们不向任何人报告。 不应考虑这些员工，因为没有经理工资可供比较。 

尽管这被标记为简单问题，但它引入了最重要的 SQL 概念之一：自连接。 

一些重要的边缘情况包括：

 - 员工`NULL`管理者，他们应该被忽视
 - 员工的收入与其经理完全相同，他们不应该被包括在内，因为条件严格大于
 - 多名员工向同一经理汇报
 - 经理本身就是员工，且其上级有经理
 - 空桌子或没有员工收入超过经理的桌子

 该问题不需要排序，因此可以按任何顺序返回结果。 

## 方法

 ### 蛮力方法

 蛮力方法将手动将每个员工与其他员工进行比较。 

对于每个员工行，我们将再次扫描整个表以找到其经理`id`与员工的相符`managerId`。 一旦找到，我们就会比较工资。 

这是有效的，因为最终每个可能的员工-经理对都会被检查。 如果员工工资超过经理工资，我们会将员工姓名添加到结果中。 

然而，这种方法效率低下，因为对于每个员工，我们可能会再次扫描整个表。 如果有`n`员工，这导致`O(n²)`比较。 

虽然数据库在内部优化了许多操作，但从概念上讲，这仍然是一种嵌套循环策略，对于大型数据集来说效率很低。 

### 最佳方法

 最佳解决方案使用自连接。 

自连接将同一个表视为两个逻辑副本：

 - 一份代表员工
 - 另一个副本代表经理

 我们按照这个条件加入表：```
employee.managerId = manager.id
```建立员工-经理关系后，我们只需过滤以下行：```
employee.salary > manager.salary
```这更加干净和高效，因为关系数据库针对连接进行了优化。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 将每位员工与其他员工进行比较 |
 | 最佳| O(n) 平均索引连接 | O(1) | O(1) | 使用自联接将员工与经理直接匹配 |

 ## 算法演练

 ### 最优 SQL 算法

 1. 首先治疗`Employee`表作为两个单独的逻辑表。 

一个别名代表员工，另一个别名代表经理。 这允许我们比较同一个表中的行。 
2. 为表分配别名。 

例如：

-`e`代表员工
 -`m`代表管理者
 3. 将两个别名连接在一起。 

加入条件为：```sql
e.managerId = m.id
```这意味着每个员工行都与代表其经理的行匹配。 
4. 过滤工资超过经理工资的员工。 

条件是：```sql
e.salary > m.salary
```5. 仅选择员工姓名。 

输出列必须命名`Employee`，所以我们写：```sql
SELECT e.name AS Employee
```6. 返回结果。 

顺序并不重要。 

### 为什么它有效

 自联接保证每个员工行与其正确的经理行配对，因为联接条件匹配`managerId`和`id`。 一旦配对，比较工资就可以直接确定员工的收入高于其经理。 由于每个员工-经理关系都只检查一次，因此查询会正确返回所有有效员工。 

## Python 解决方案

 LeetCode 数据库问题是使用 SQL 而不是可执行的 Python 代码来解决的。 但是，平台仍然期望解决方案部分包含 SQL 查询。```python
# Write your MySQL query statement below

SELECT e.name AS Employee
FROM Employee e
JOIN Employee m
ON e.managerId = m.id
WHERE e.salary > m.salary;
```该查询首先创建同一个表的两个别名：

 -`e`对于员工
 -`m`对于管理者

 的`JOIN`运营部门使用以下方式将员工与其经理联系起来：```python
e.managerId = m.id
```这会创建员工-经理对。 

这`WHERE`子句仅过滤员工工资高于经理工资的那些行。 

最后，`SELECT`语句使用所需的输出列名称返回员工姓名`Employee`。

 ## 边缘情况

 ### 没有经理的员工

 部分员工有`NULL`在`managerId`柱子。 他们是高层经理或高管。 一个常见的错误是试图将他们的薪水与不存在的经理进行比较。 

自连接自然地处理了这个问题。 自从`NULL`无法匹配任何有效的`id`，这些行会自动从连接结果中排除。 

### 同等工资

 该问题特别要求员工的收入高于其经理，而不是大于或等于。 

如果员工的工资与其经理完全相同，则他们不得出现在结果中。 该实现使用以下方法正确处理此问题：```
e.salary > m.salary
```而不是：```
e.salary >= m.salary
```### 多名员工向一名经理汇报

 一个经理可以管理很多员工。 不正确的实施可能会意外地只返回每位经理的一名员工。 

连接操作正确地为每个员工-经理关系创建一行，因此所有符合条件的员工都会独立返回。 

### 经理缺席的员工

 尽管格式正确的数据通常可以保证有效的经理引用，但格式错误的数据集可能包含`managerId`那不存在。 

内部联接安全地排除这些行，因为不存在匹配的管理器行。 这可以防止无效比较并保持结果正确。
