[LeetCode 第 142 题](https://leetcode.com/problems/linked-list-cycle-ii/)

 **难度：** 🟡 中等
 **主题：** 哈希表、链表、两个指针

 ## 解决方案

 ## 问题理解

 该问题要求我们确定单链表是否包含循环，如果包含，则返回该循环开始的确切节点。 

链表通常是一系列节点，其中每个节点都指向下一个节点，最终以`null`。 然而，在这个问题中，`next`某些节点的指针可能指向较早的节点而不是结束。 当这种情况发生时，重复遍历列表将导致我们永远重新访问节点，从而形成一个循环。 

The input consists of the`head`单链表的节点。 LeetCode 在内部提供了一个名为`pos`，它指示尾部连接回列表的位置。 但是，该值仅用于构建测试用例，**不适用于我们的算法**。 我们必须纯粹通过遍历链表结构来确定循环。 

The expected output is the **node object itself** where the cycle begins. If there is no cycle, we return`null`（或者`None`在Python中）。 This distinction is important because we are not returning an index or node value, but the actual linked list node reference.

 The constraints indicate that the linked list contains at most`10^4`节点。 这对于一个足够小的`O(n)`遍历要高效。 后续问题要求`O(1)`额外的内存，这强烈表明使用辅助存储（例如哈希集）的解决方案并不是最佳的。 

预先考虑一些边缘情况很重要。 链表可能为空（`head = null`），这意味着不可能有循环。 该列表可能只包含一个节点，要么指向自身，要么正常结束。 该循环可以从头部开始，这意味着返回第一个节点。 循环也可能在列表深处的几个非循环节点之后开始。 仅检查重复值而不检查重复节点引用的简单实现将会失败，因为多个节点可以具有相同的值。 

## 方法

 ### 蛮力方法，哈希集

 解决这个问题的一个直接方法是遍历链表，同时使用哈希集跟踪我们已经访问过的每个节点。 

当我们浏览列表时，我们检查当前节点是否已经被看到。 如果是，那么我们就知道我们已经循环回循环，并且当前节点一定是循环入口点。 如果我们最终达到`null`，则不存在循环。 

这种方法之所以有效，是因为有效非循环遍历中的每个节点都应该被访问一次。 重新访问一个节点意味着我们遇到了循环。 

虽然正确，但该解决方案使用与访问的节点数量成比例的额外内存。 由于后续明确要求持续的额外内存，因此我们可以做得更好。 

### 最优方法，Floyd 循环检测算法

 关键的见解是我们可以利用指针移动速度来检测周期，而无需额外的内存。 

我们使用两个指针：

 - 一次移动一步的**慢速指针**。 
- 一次移动两步的**快速指针**。 

如果不存在循环，快指针最终会到达`null`。 如果存在循环，则快指针最终将在循环内“搭接”慢指针，使它们相遇。 

更深层次的洞察是，在这次会议发生之后，如何找到周期的**入口点**。 

认为：

-`L`是从头部到循环入口的距离。 
-`C`是周期长度。 
-`X`是从自行车入口到集合点的距离。 

在集合点：

 - 慢速指针距离 =`L + X`- 快指针距离=`L + X + kC`由于快指针的移动速度是快指针的两倍：$$2(L + X) = L + X + kC$$重新排列：$$L + X = kC$$这意味着：$$L = kC - X$$这意味着从头部到循环入口的距离等于从交汇点到循环入口的距离。 

因此，如果我们将一个指针放回头部，并将另一个指针放在交汇点，一次移动一步，它们将恰好在循环入口节点交汇。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用哈希集来跟踪访问过的节点 |
 | 最佳| O(n) | O(1) | O(1) | 使用弗洛伊德的两分球技术 |

 ## 算法演练

 1.初始化两个指针，`slow`和`fast`，都开始于`head`。 慢指针一次移动一个节点，而快指针一次移动两个节点。 
2、遍历链表，同时保证快指针和`fast.next`不是`null`。 此检查可以防止无效的指针访问，并告诉我们列表是否正常结束。 
3. 移动指针：

 -`slow = slow.next`-`fast = fast.next.next`如果没有循环，快指针最终到达`null`。 
4. 每次移动后，检查是否`slow == fast`。 如果它们相遇，则存在循环。 该交汇点由弗洛伊德循环检测算法保证。 
5. 一旦指针相遇，初始化另一个指针，`cycle_start`， 在`head`。 
6. 移动两者`slow`和`cycle_start`一次一步：

 -`slow = slow.next`-`cycle_start = cycle_start.next`7. The node where these two pointers meet is the start of the cycle. 返回该节点。 
8. If the loop ends without the pointers meeting, return`null`因为不存在循环。 

### 为什么它有效

 正确性来自于交汇点和循环入口之间的数学关系。 当慢速和快速指针相遇时，慢速指针已经移动了与循环开始的剩余距离完全对齐的距离。 将一个指针重置到头部可确保两个指针移动相同的剩余距离，从而使它们在循环入口节点处精确相遇。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None

from typing import Optional

class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = head
        fast = head

        # Step 1: Detect if a cycle exists
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            if slow == fast:
                # Step 2: Find the cycle entry point
                cycle_start = head

                while cycle_start != slow:
                    cycle_start = cycle_start.next
                    slow = slow.next

                return cycle_start

        return None
```实现首先初始化两个`slow`和`fast`指向链表头部的指针。 这`while fast and fast.next`条件确保指针移动安全，因为快速指针一次前进两步。 

在循环内部，慢指针前进一个节点，而快指针前进两个节点。 如果列表包含循环，则快指针最终捕获慢指针，证明循环存在。 

检测到交汇点后，算法会创建一个新的指针，称为`cycle_start`位于头部。 两个都`cycle_start`和`slow`然后一次移动一步。 从数学上讲，它们的交汇点保证是循环入口节点，我们立即返回该节点。 

如果循环自然退出，则快指针到达链表末尾，意味着不存在循环，因此函数返回`None`。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func detectCycle(head *ListNode) *ListNode {
    slow := head
    fast := head

    // Step 1: Detect cycle
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next

        if slow == fast {
            // Step 2: Find cycle entry
            cycleStart := head

            for cycleStart != slow {
                cycleStart = cycleStart.Next
                slow = slow.Next
            }

            return cycleStart
        }
    }

    return nil
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于处理方式`nil`明确地代替`None`。 由于 Go 指针是强类型的，我们检查`fast != nil && fast.Next != nil`在移动快速指针之前。 

Go 使用指针相等来比较链表节点，这正是我们想要的，因为问题需要识别相同的节点对象，而不仅仅是匹配值。 

不用担心整数溢出，因为我们只是移动指针而不是对节点值执行算术。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个指针最多遍历列表常数次 |
 | 空间| O(1) | O(1) | 仅使用了很少的指针变量|

 时间复杂度为`O(n)`因为，即使有两个阶段，每个指针在链表中移动的次数也是有限的。 在循环检测阶段，指针移动直到它们相遇或列表结束。 在第二阶段，两个指针都移向循环入口。 总而言之，这与节点数量保持线性关系。 

空间复杂度为`O(1)`因为无论输入大小如何，我们只存储恒定数量的指针引用。

        self.next = None

        fast = head

def build_cycle_list(values, pos):
    if not values:
        return None

    nodes = [ListNode(v) for v in values]

    for i in range(len(nodes) - 1):
        nodes[i].next = nodes[i + 1]

    if pos != -1:
        nodes[-1].next = nodes[pos]

    return nodes[0], nodes

 ## 边缘情况

 ### 空链表

 输入可能是`head = null`。 这是一个很容易被忽视的情况，因为取消引用`fast.next`如果处理不仔细，会立即导致错误。 该实现通过循环条件安全地处理这个问题`while fast and fast.next`，它立即失败并返回`None`。 

### 单节点自循环

 一个节点指向自身的链表是一种特殊但有效的循环。 一些实现错误地假设至少需要两个节点来进行循环检测。 在此实现中，两个指针最终在同一节点上相遇，并且重置第二个指针可以正确地将该节点标识为循环条目。 

### 循环从头部开始

 循环条目可能是第一个节点。 这可能会破坏错误地假设循环之前始终有非循环前缀的实现。 Floyd算法很自然地处理这种情况，因为在相遇点之后，重置指针和慢速指针将直接在头部相遇。 

### 不存在循环

 链表可以正常终止。 如果假设存在循环，则有缺陷的实现可能会永远循环。 这里，快速指针最终变成`null`，导致循环安全停止并返回`None`。 

### 重复的节点值

 多个节点可能包含相同的值。 有缺陷的方法可能会比较节点值而不是节点引用，从而产生误报。 此实现直接比较节点对象，即使值重复也能确保正确性。
