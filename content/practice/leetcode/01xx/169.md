 ## 解决方案

 ## 问题理解

 该问题要求我们识别给定整数数组中的多数元素`nums`。 多数元素定义为在数组中出现次数**超过一半**的数量，即超过`⌊n / 2⌋`时间在哪里`n`是数组的长度。 输入数组可以包含正整数和负整数，长度范围为 1 到 50,000。 该问题保证了多数元素**始终存在**，这简化了解决方案，因为我们不必处理不存在多数的情况。 

换句话说，我们被要求扫描数组并找到在频率上占主导地位的元素。 预期输出是该元素本身。 约束表明数组可能很大，因此低效的解决方案可能不可接受。 关键边缘情况包括具有单个元素的数组、所有元素都相同的数组以及多数元素位于开头、中间或结尾的数组。 

## 方法

 最简单的暴力方法是计算每个元素的频率。 我们可以使用哈希映射（Python 中的字典或 Go 中的映射）来完成此操作，其中键是元素，值是其计数。 计数完毕后，我们遍历map来查找计数超过的元素`n // 2`。 虽然这种方法是正确的，但它需要`O(n)`空间和`O(n)`时间。 

更好的解决方案利用 **Boyer-Moore 投票算法**，该算法依赖于多数元素出现超过一半时间的观察结果。 通过维护候选者和计数器，我们可以遍历数组一次，当当前元素与候选者匹配时递增计数器，否则递减计数器。 如果计数器降至零，我们将选择当前元素作为新的候选元素。 到数组末尾时，保证候选元素成为多数元素。 该方法实现了**O(n)时间**和**O(1)空间**，满足后续要求。

 ## 算法演练

 1. 初始化`candidate`作为`None`和`count`作为`0`。 这设置了一个占位符来跟踪潜在的多数元素。 
2. 迭代每个元素`num`在数组中`nums`。 
3.如果`count`是`0`， 更新`candidate`到目前的`num`。 这意味着我们正在开始新的潜在多数。 
4. 如果`num`等于`candidate`, 增量`count`。 这强化了我们当前的候选人。 
5. 如果`num`不等于`candidate`, 递减`count`。 这会抵消先前出现的不同元素。 
6.遍历整个数组后，返回`candidate`。 该算法保证`candidate`是多数元素，因为多数元素不能被其他元素完全抵消。 

**为什么有效**：由于多数元素出现的次数超过一半，因此每次遇到不同的元素时，计数器只会减一。 由于多数元素出现的次数多于所有其他元素的总和，因此它最终仍将作为候选元素。 

## Python 解决方案```python
from typing import List

class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        candidate = None
        count = 0
        for num in nums:
            if count == 0:
                candidate = num
            count += 1 if num == candidate else -1
        return candidate
```该实现初始化候选者和计数器。 它迭代通过`nums`，每当计数降至零时更新候选，并根据当前元素是否与候选匹配来调整计数器。 最终候选者作为多数元素返回。 

## 解决方案```go
func majorityElement(nums []int) int {
    candidate := 0
    count := 0
    for _, num := range nums {
        if count == 0 {
            candidate = num
        }
        if num == candidate {
            count++
        } else {
            count--
        }
    }
    return candidate
}
```Go 实现镜像了 Python 版本。 我们使用整数变量`candidate`和`count`。 主要区别在于 Go 没有像 Python 那样具有动态调整大小的内置列表，但切片提供了相同的迭代功能。 不需要 nil 处理，因为保证数组至少有一个元素。 

## 工作示例

 **示例 1：nums = [3,2,3]**

 | 步骤| 编号 | 候选人 | 计数| 说明|
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 无 -> 3 | 0 -> 1 | 0 -> 1 count=0, 选择 3 作为候选 |
 | 2 | 2 | 3 | 1 -> 0 | 1 -> 0 2 != 3，递减计数 |
 | 3 | 3 | 2 -> 3 | 2 -> 3 | 0 -> 1 | 0 -> 1 count=0，选择 3 作为新候选者 |

 返回 3.

 **示例 2：nums = [2,2,1,1,1,2,2]**

 | 步骤| 编号 | 候选人 | 计数| 说明|
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 无 -> 2 | 0 -> 1 | 0 -> 1 选择 2 |
 | 2 | 2 | 2 | 1 -> 2 | 1 -> 2 匹配、增量 |
 | 3 | 1 | 2 | 2 -> 1 | 2 -> 1 不匹配，减量|
 | 4 | 1 | 2 | 1 -> 0 | 1 -> 0 不匹配，递减，计数=0 |
 | 5 | 1 | 1 | 0 -> 1 | 0 -> 1 挑选新候选人 1 |
 | 6 | 2 | 1 | 1 -> 0 | 1 -> 0 不匹配，递减，计数=0 |
 | 7 | 2 | 2 | 0 -> 1 | 0 -> 1 挑选新候选人 2 |

 返回2。

 ## 边缘情况

 一个重要的边缘情况是具有单个元素的数组。 该算法可以正确处理这个问题，因为候选者被初始化为 None 并立即更新为单个元素，这通常是多数元素。 另一种边缘情况是所有元素都相同的数组。 在这里，计数器将重复递增而不递减，从而得出正确的多数。 最后，多数元素出现在不规则位置（例如开头、中间或结尾）的数组可能会导致在找到局部最大值后停止的简单算法； Boyer-Moore 算法正确地聚合了整个数组的计数。 在所有这些情况下，算法通过维护运行候选者和计数器不变性来确保正确性。
