 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个单链表的头，其值已经按升序排序。 我们必须将这个链表转换成高度平衡的二叉搜索树，通常缩写为BST。 

二叉搜索树具有以下性质：

 - 左子树中的每个节点都包含小于当前节点的值。 
- 右子树中的每个节点都包含大于当前节点的值。 

高度平衡树意味着对于每个节点，左子树和右子树的高度最多相差一。 这个要求很重要，因为平衡树提供了高效的查找性能。 

链表是排序的，这是关键的观察。 如果我们重复选择排序序列的中间元素作为根，则：

 - 中间之前的所有值自然属于左子树。 
- 中间之后的所有值自然属于右子树。 
- 生成的树保持平衡，因为左半部分和右半部分的大小大致相等。 

输入是单链表，而不是数组。 这种区别很重要，因为链表不支持随机访问。 访问中间元素需要遍历。 

约束告诉我们列表最多可以包含`2 * 10^4`节点。 一个`O(n^2)`在最坏的情况下，解决方案可能会变得太慢，所以我们应该瞄准更接近的东西`O(n log n)`或者理想情况下`O(n)`。 

一些边缘情况很重要：

 - 列表可能为空。 
- 该列表可能只包含一个节点。 
- 该列表可能包含两个节点，如果拆分处理不当，可能会产生不平衡错误。 
- 由于列表是单向链接的，因此将列表切成两半时必须小心。 
- 重复的平衡错误可能会导致树木倾斜，而不是高度平衡的树木。 

## 方法

 ### 蛮力方法

 一个简单的想法是首先将所有链表值复制到一个数组中。 

由于数组支持随机访问，因此我们可以递归地构造 BST，就像经典的“排序数组到 BST”问题一样：

 1. 选择中间元素作为根。 
2. 从左半部分开始递归构建左子树。 
3. 从右半部分开始递归构建右子树。 

这是有效的，因为数组保持排序，并且选择中间元素可以保证平衡。 

缺点是我们必须分配一个包含所有值的附加数组。 虽然这种方法对于约束来说已经足够有效，但它并没有充分利用链表结构。 

### 最佳方法

 更好的方法避免将列表转换为数组。 

关键的见解是 BST 的中序遍历按排序顺序访问节点。 由于链表已经排序，我们可以直接从链表模拟中序构造。 

该过程的工作原理如下：

 1. 计算链表中的节点总数。 
2. 使用索引边界递归构造 BST。 
3. 首先构建左子树。 
4、以当前链表节点为根。 
5. 向前移动链表指针。 
6. 构建右子树。 

该技术确保按照排序顺序从链表中消耗节点，与中序遍历顺序完全匹配。 

由于每个链表节点都被访问一次，因此该解决方案以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 将链表转换为数组，然后递归构建 BST |
 | 最佳| O(n) | O(log n) | 直接在链表上模拟中序遍历 |

 ## 算法演练

 ### 最优中序模拟算法

 1、首先遍历链表一次，统计存在多少个节点。 

我们需要大小，因为我们的递归函数将使用索引范围构建 BST，而不是物理拆分列表。 
2. 将链表头存储在共享指针变量中。 

该指针表示在 inorder 构造过程中应成为下一个 BST 节点的当前节点。 
3. 定义递归函数`build(left, right)`。 

该函数使用概念子数组范围构造一个平衡 BST`left`到`right`。 
4.如果`left > right`， 返回`None`。 

这是表明子树为空的基本情况。 
5. 计算中间索引。 

中间的元素应该成为根以保持平衡。 
6. 首先递归构建左子树。 

这很重要，因为中序遍历按顺序处理节点：

 - 左子树
 - 根
 - 右子树
 7. 构建左子树后，共享链表指针现在指向正确的根值。 

使用此链表节点创建一个树节点。 
8. 将链表指针前进到下一个节点。 

这为构造右子树准备了指针。 
9. 递归构建右子树。 
10. 将左右子节点附加到根节点并返回根节点。 

### 为什么它有效

 该算法之所以有效，是因为它精确地反映了中序遍历。 

在 BST 的中序遍历期间：

 - 首先处理左子树节点。 
- 然后是根。 
- 然后是右子树。 

由于链表已经排序，因此从列表中顺序消费节点自然会匹配中序顺序。 递归边界确保每个段的中间元素成为子树根，从而保证高度平衡。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def sortedListToBST(self, head: Optional[ListNode]) -> Optional[TreeNode]:
        def get_size(node: Optional[ListNode]) -> int:
            size = 0
            
            while node:
                size += 1
                node = node.next
            
            return size
        
        size = get_size(head)
        current = head
        
        def build(left: int, right: int) -> Optional[TreeNode]:
            nonlocal current
            
            if left > right:
                return None
            
            mid = (left + right) // 2
            
            left_subtree = build(left, mid - 1)
            
            root = TreeNode(current.val)
            root.left = left_subtree
            
            current = current.next
            
            root.right = build(mid + 1, right)
            
            return root
        
        return build(0, size - 1)
```实现首先计算链表的大小。 这允许递归构建器在索引范围上操作，而不是重复搜索中间节点。 

这`current`指针跟踪在中序构造期间哪个链表节点应成为下一个 BST 节点。 

递归`build()`函数构造 BST 的方式与中序遍历访问它的方式完全相同。 首先它构建左子树，然后使用链表指针创建当前根节点，然后前进指针，最后构建右子树。 

由于链表指针每个节点只向前移动一次，因此每个列表节点都会被处理一次。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */

/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func sortedListToBST(head *ListNode) *TreeNode {
    size := getSize(head)
    current := head

    var build func(left int, right int) *TreeNode

    build = func(left int, right int) *TreeNode {
        if left > right {
            return nil
        }

        mid := (left + right) / 2

        leftSubtree := build(left, mid-1)

        root := &TreeNode{
            Val: current.Val,
        }

        root.Left = leftSubtree

        current = current.Next

        root.Right = build(mid+1, right)

        return root
    }

    return build(0, size-1)
}

func getSize(head *ListNode) int {
    size := 0

    for head != nil {
        size++
        head = head.Next
    }

    return size
}
```Go 实现遵循与 Python 版本相同的中序模拟策略。 

而不是Python的`nonlocal`关键字，Go 闭包自然捕获`current`来自外部作用域的指针变量。 

Go 使用`nil`而不是`None`，并且树节点是使用指针分配创建的`&TreeNode{}`。

 ## 边缘情况

 ### 空链表

 空链表是最简单的边缘情况。 幼稚的实现可能会尝试访问`head.val`而不检查列表是否存在。 此实现可以安全地处理这种情况，因为大小变为零，并且递归调用立即返回`None`。 

### 单节点列表

 只包含一个节点的列表可能会暴露不正确的递归边界。 如果中点逻辑错误，递归调用可能永远不会正确终止。 在此实现中，范围变为`(0, 0)`，恰好生成一个没有子节点的根节点。 

### 两个节点列表

 两节点输入对于平衡逻辑来说特别棘手。 某些实现意外地重用了节点或创建了倾斜的递归。 在这里，中点选择确保一个节点成为根节点，另一个节点成为子节点，从而保持 BST 排序并避免无限递归。 

### 大链表

 高达`2 * 10^4`节点，重复搜索中间节点会产生过多的开销。 中序模拟方法避免了重复遍历并保证线性运行时间，使其可扩展至最大约束大小。
