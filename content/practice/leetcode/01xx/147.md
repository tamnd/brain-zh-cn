[LeetCode 第 147 题](https://leetcode.com/problems/insertion-sort-list/)

 **难度：** 🟡 中等
 **主题：** 链表、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们使用插入排序算法对单链表进行排序。 与可以通过索引直接访问元素的数组排序问题不同，链表需要顺序遍历，因此插入操作的行为不同，并且需要仔细的指针操作。 

输入是单链表的头节点。 每个节点包含一个整数值和一个指向下一个节点的指针。 目标是重新排列节点，使生成的链表按升序排序，然后返回排序后的链表的头。 

插入排序的工作原理是维护数据中不断增长的排序部分。 在每一步中，从未排序部分中取出一个元素并将其插入已排序部分中的正确位置。 对于数组，这通常涉及移动元素。 对于链表，插入变得更加自然，因为节点可以重新链接而无需移动内存。 

约束告诉我们列表包含 1 到 5000 个节点。 这个值足够小，以至于 O(n²) 算法是可以接受的，这一点很重要，因为在最坏的情况下，插入排序自然会以二次方的时间运行。 节点值的范围从 -5000 到 5000，因此必须正确处理负数和重复项。 

需要考虑一些重要的边缘情况：

 - 只有一个节点的列表已经排序。 
- 已排序的列表应保持不变。 
- 反向排序列表代表插入排序的最坏情况，因为每个新节点都必须插入到开头。 
- 重复值必须保留有效的顺序。 
- 负值必须与正值一起自然处理。 
- 如果指针更新不正确，则在已排序部分的头部插入特别容易错误处理。 

因为这是一个单链表，所以我们不能向后移动。 这意味着每次插入都需要从已排序部分的开头进行扫描以找到正确的插入点。 

## 方法

 ### 蛮力方法

 一种简单的解决方案是将所有节点值提取到一个数组中，使用标准排序算法对数组进行排序，然后使用排序后的值重建链表。 

这种方法之所以有效，是因为数组通过内置算法（例如 Python 中的 Timsort 或 Go 中的 sort.Ints）支持高效的排序操作。 一旦对值进行排序，重建链表就会产生正确的最终排序。 

然而，这种方法忽略了问题的主要意图，即直接在链表上实现插入排序。 它还需要与节点数量成比例的额外内存，因为所有值都必须复制到辅助数组中。 

### 最佳方法

 更好的解决方案是直接对链表本身进行插入排序。 

关键的见解是链表天生适合插入操作。 在数组中，在中间插入一个元素需要移动许多元素。 在链表中，插入只需要在找到插入位置后更新指针。 

我们维护一个单独的排序列表，并一次遍历原始列表一个节点。 对于每个节点：

 1、从原来的遍历中去掉。 
2. 在排序列表中找到正确的位置。 
3. 将其插入该位置。 

虚拟节点在这里非常有用，因为它简化了在列表开头的插入。 如果没有虚拟节点，则在当前头之前插入需要特殊处理。 

尽管时间复杂度仍然是 O(n²)，但这是预期的插入排序实现，并且仅使用 O(1) 额外空间。

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 将值复制到数组、排序数组、重建列表 |
 | 最佳| O(n²) | O(1) | O(1) | 直接对链表进行插入排序|

 ## 算法演练

 ### 最优链表插入排序

 1. 创建一个虚拟节点作为排序列表的头。 

虚拟节点简化了插入逻辑，特别是当必须将节点插入到排序列表的最开头时。 
2. 使用名为的指针开始遍历原始列表`current`。 

该指针表示我们当前插入到已排序部分的节点。 
3. 在修改指针之前保存下一个节点。 

由于插入改变了当前节点的`next`指针，我们必须保留对原始列表其余部分的访问。 
4. 在排序列表中找到插入位置。 

从虚拟节点开始，向前移动，直到到达第一个值大于当前节点值的节点。 
5. 将当前节点插入到排序列表中。 

使用标准链表指针操作执行插入：

 -`current.next = prev.next`-`prev.next = current`6. 移至原始列表中的下一个节点。 

继续处理，直到每个节点都被插入到已排序的部分中。 
7. 返回`dummy.next`。 

虚拟节点本身是人造的，因此真正的排序列表在它之后开始。 

### 为什么它有效

 该算法维护一个不变量，即列表从`dummy.next`每次迭代后总是排序。 

最初，排序列表是空的，因此不变量通常成立。 在每次迭代期间，一个节点被插入到已排序部分中的正确位置。 由于插入是按排序顺序进行的，因此每一步之后不变式都保持为真。 

当所有节点都处理完后，每个节点都属于已排序链表，整个链表就已排序。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def insertionSortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        current = head

        while current:
            next_node = current.next

            prev = dummy
            while prev.next and prev.next.val < current.val:
                prev = prev.next

            current.next = prev.next
            prev.next = current

            current = next_node

        return dummy.next
```实现首先创建一个虚拟节点。 该节点充当列表的已排序部分的稳定入口点。 

这`current`指针每次遍历原始链表一个节点。 在将节点插入排序列表之前，代码存储`current.next`在`next_node`。 这是必要的，因为插入会重新布线`next`指针。 

The inner loop searches for the insertion point. 指针`prev`从虚拟节点开始并前进，直到找到当前节点应插入的正确位置。 

一旦确定了正确的插入位置，就可以通过调整指针来插入节点。 第一的，`current.next`指向之后的节点`prev`。 然后`prev.next`已更新为指向`current`。 

最后，使用保存的继续遍历`next_node`。 

因为每次插入都保留排序顺序，所以最终返回的链表`dummy.next`已完全排序。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func insertionSortList(head *ListNode) *ListNode {
    dummy := &ListNode{}
    current := head

    for current != nil {
        nextNode := current.Next

        prev := dummy
        for prev.Next != nil && prev.Next.Val < current.Val {
            prev = prev.Next
        }

        current.Next = prev.Next
        prev.Next = current

        current = nextNode
    }

    return dummy.Next
}
```Go 实现遵循与 Python 解决方案完全相同的算法结构。 主要区别在于显式指针语法。 

Go 使用`nil`而不是`None`，直接通过指针操作链表节点。 虚拟节点的分配使用`&ListNode{}`。 

由于 Go 不像 Python 那样提供自动可选类型，因此所有链表引用都通过显式处理`*ListNode`。 

这里不存在整数溢出问题，因为节点值被限制在一个小范围内。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 每次插入可能会扫描整个排序部分 |
 | 空间| O(1) | O(1) | 只需几个指针即可就地完成排序 |

 外循环对每个节点只处理一次。 对于每个节点，算法可能需要扫描列表中已排序的部分以找到插入点。 

在最坏的情况下，例如反向排序列表，比较次数变为：```
1 + 2 + 3 + ... + (n - 1)
```总和为 O(n²)。 

无论输入大小如何，该算法仅使用恒定数量的额外指针，因此辅助空间复杂度为 O(1)。

 ## 边缘情况

 ### 单节点列表

 仅包含一个节点的链表已排序。 这种情况有时会暴露出错误，其中指针操作假设存在附加节点。 在此实现中，循环运行一次，将节点插入到排序列表中，然后正确终止。 

### 反向排序列表

 反向排序列表，例如`5 -> 4 -> 3 -> 2 -> 1`是插入排序的最坏情况。 每个新节点必须插入到已排序列表的开头。 头插入处理不正确通常会导致链接断开或节点丢失。 虚拟节点确保这些插入得到统一、安全的处理。 

### 重复值

 如果插入条件写得不正确，包含重复项的列表可能会出现问题。 例如，使用`<=`而不是`<`更改插入排序行为。 该实现使用：```
while prev.next and prev.next.val < current.val:
```这保证了重复插入的一致性，同时保留有效的排序顺序。 

### 在开头插入

 当当前节点小于已排序列表中的所有节点时，它必须成为新的第一个元素。 如果没有虚拟节点，则需要特殊情况的逻辑来更新头指针。 虚拟节点通过使每次插入遵循相同的指针更新模式来消除这种复杂性。
