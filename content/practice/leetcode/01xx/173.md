## 问题理解

 这个问题要求我们为二叉搜索树（BST）设计一个迭代器，它以**中序遍历顺序**返回值。 在 BST 中，中序遍历按升序访问节点，这意味着我们首先访问左子树，然后是当前节点，最后是右子树。 

迭代器必须支持三种操作：

 - 构造函数用 BST 根初始化迭代器。 
-`next()`移动到下一个最小的数字并返回它。 
-`hasNext()`检查遍历中是否存在另一个值。 

该问题保证调用`next()`总是有效的，这意味着我们永远不需要担心在没有剩余值时尝试检索值。 

一个关键细节是迭代器指针从最小元素“之前”的位置开始。 这意味着第一次调用`next()`应该返回 BST 中的最小值。 

约束在这里很重要。 该树最多可以包含`10^5`节点，并且还可能有多达`10^5`打电话给`next()`和`hasNext()`。 对于每个操作都重复遍历树的简单解决方案效率很低。 后续行动特别要求平均实施`O(1)`每次操作的时间和`O(h)`记忆，在哪里`h`是树的高度。 

有几种边缘情况需要考虑。 只有一个节点的树应该表现正确，返回该节点一次，然后报告没有剩余元素。 完全左偏的树会创建尽可能深的遍历堆栈，而右偏的树则测试我们是否正确地遍历右子节点。 大型平衡树也很重要，因为后续专门针对基于高度的内存效率。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是在初始化期间执行完整的中序遍历，将所有值存储在数组中，并维护一个索引指针。 

这是可行的，因为 BST 的中序遍历自然会产生按升序排序的值。 一旦我们存储了完整的遍历序列，`next()`只需增加索引并返回下一个元素，而`hasNext()`检查索引是否已到达数组末尾。 

虽然这种做法是正确的，但并不能满足后续的要求。 它需要`O(n)`内存，因为每个节点值都是预先存储的。 初始化也有成本`O(n)`因为在迭代开始之前必须遍历整个树。 

### 最佳方法

 更好的解决方案是使用**堆栈**来模拟中序遍历。 

关键的见解是，中序遍历只需要记住从根到当前节点的路径。 我们没有提前遍历整个树，而是只将最左边的路径预加载到堆栈中。 堆栈的顶部始终代表下一个最小的节点。 

什么时候`next()`被调用时，我们弹出顶部节点，因为它是下一个最小值。 如果该节点有右子节点，我们将该右子树的整个最左边路径压入堆栈。 

这种设计实现了后续要求，因为每个节点都被推送和弹出一次。 虽然是单身`next()`调用偶尔可能会处理多个节点，所有操作的总工作量是线性的，给出**平均值`O(1)`时间复杂度**。 堆栈仅存储沿根到叶路径的节点，因此内存使用量仍然存在`O(h)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 初始化：`O(n)`,`next()`:`O(1)`,`hasNext()`:`O(1)`|`O(n)`| 预先计算整个中序遍历 |
 | 最佳| 平均的`O(1)`每次操作 |`O(h)`| 使用堆栈的惰性中序遍历 |

 ## 算法演练

 1. 在构造函数中初始化一个空堆栈。 
2. 从根开始，重复向左移动，同时将每个访问过的节点压入堆栈。 这确保了最小的元素被放置在堆栈的顶部。 
3. 什么时候`next()`被调用时，从堆栈中弹出顶部节点。 该节点是按排序顺序的下一个最小值。 
4.弹出一个节点后，检查它是否有右孩子。 如果是，则移入右子树并再次将每个左子孙推入堆栈。 这保留了有序遍历序列。 
5. 返回弹出节点的值。 
6. 什么时候`hasNext()`被调用时，只需检查堆栈是否包含任何节点。 如果是，则剩下另一个元素。 

### 为什么它有效

 该算法维护了一个重要的不变量：**栈顶始终是下一个最小的未访问节点**。 

最初，推送最左边的路径可以保证最小的节点首先可用。 每当删除一个节点时，它的右子树就会成为下一个要探索的区域。 通过推送该子树的最左边路径，我们确保下一个最小的节点恢复到堆栈的顶部。 由于每个节点都按排序顺序处理一次，因此迭代器正确地实现了中序遍历。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class BSTIterator:

    def __init__(self, root: Optional[TreeNode]):
        self.stack = []
        self._push_left_path(root)

    def _push_left_path(self, node: Optional[TreeNode]) -> None:
        while node:
            self.stack.append(node)
            node = node.left

    def next(self) -> int:
        current_node = self.stack.pop()

        if current_node.right:
            self._push_left_path(current_node.right)

        return current_node.val

    def hasNext(self) -> bool:
        return len(self.stack) > 0

# Your BSTIterator object will be instantiated and called as such:
# obj = BSTIterator(root)
# param_1 = obj.next()
# param_2 = obj.hasNext()
```实现首先创建一个堆栈并立即从根推入最左边的路径。 这保证了最小值可供检索。 

辅助方法`_push_left_path()`集中了向左行走和推送节点的逻辑。 这避免了构造函数和构造函数之间的重复代码`next()`。 

里面`next()`，顶部节点被弹出，因为它代表最小的未访问值。 如果弹出的节点有右子树，我们处理它的左边界以保持有序。 

这`hasNext()`方法仍然很简单，因为堆栈本身充当我们的状态跟踪器。 如果栈中还有节点，则存在另一个遍历值。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

type BSTIterator struct {
	stack []*TreeNode
}

func Constructor(root *TreeNode) BSTIterator {
	iterator := BSTIterator{
		stack: []*TreeNode{},
	}

	iterator.pushLeftPath(root)

	return iterator
}

func (this *BSTIterator) pushLeftPath(node *TreeNode) {
	for node != nil {
		this.stack = append(this.stack, node)
		node = node.Left
	}
}

func (this *BSTIterator) Next() int {
	lastIndex := len(this.stack) - 1
	currentNode := this.stack[lastIndex]
	this.stack = this.stack[:lastIndex]

	if currentNode.Right != nil {
		this.pushLeftPath(currentNode.Right)
	}

	return currentNode.Val
}

func (this *BSTIterator) HasNext() bool {
	return len(this.stack) > 0
}

/**
 * Your BSTIterator object will be instantiated and called as such:
 * obj := Constructor(root);
 * param_1 := obj.Next();
 * param_2 := obj.HasNext();
 */
```Go 解决方案遵循与 Python 相同的算法结构。 由于 Go 没有内置的堆栈类型，因此切片`*TreeNode`而是使用指针。 追加模拟推送操作，而切片则删除最后一个元素以实现弹出行为。 

与 Python 的动态类型不同，Go 明确使用指针类型（`*TreeNode`）以避免不必要的树节点复制。 这里不存在整数溢出问题，因为节点值仍在问题约束内。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 平均的`O(1)`| 每个节点都被压入和弹出一次 |
 | 空间|`O(h)`| 堆栈最多存储一条从根到叶的路径 |

 虽然是个人`next()`通话可能偶尔需要`O(h)`在处理深度右子树时，每个节点在整个执行过程中只进入和离开堆栈一次。 因此，摊余复杂度变为`O(1)`每次操作。

 ## 边缘情况

 ### 单节点树

 只有一个节点的 BST 是最小的有效输入。 这种情况可能会暴露初始化假设子项存在或存在的错误`hasNext()`错误地报告附加值。 该实现自然地处理了这个问题，因为构造函数将根推入堆栈，`next()`删除它，并且`hasNext()`正确返回`False`。 

### 完全左偏树

 每个节点只有左子节点的树的行为类似于链表。 这会在初始化期间创建最大可能的堆栈深度。 幼稚的实现可能会低效地重复检索节点，但我们的方法在构造过程中只推送每个节点一次，并按升序弹出它们。 

### 完全右偏树

 每个节点只有右子节点的树测试迭代器是否正确转换到右子树。 每次之后`next()`调用时，实现会推送右子节点的最左边路径。 由于不存在左子节点，因此直接添加每个右节点，从而保留正确的顺序。 

### 大型平衡树

 平衡 BST 最多可达`10^5`节点强调性能和内存使用。 该实现满足后续要求，因为堆栈大小永远不会超过树高，即`O(log n)`对于平衡树，而每个操作仍然摊销`O(1)`。
