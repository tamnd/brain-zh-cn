[LeetCode 第 114 题](https://leetcode.com/problems/flatten-binary-tree-to-linked-list/)

 **难度：** 🟡 中等
 **主题：** 链表、堆栈、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们将二叉树转换为扁平结构，其行为类似于单链表。 转换必须就地进行，这意味着我们不应该创建全新的树或列表结构。 相反，我们必须重新排列树节点内的现有指针。 

展平的结构必须遵循前序遍历的顺序。 在前序遍历中，我们总是按以下顺序访问节点：

 1.当前节点
 2. 左子树
 3. 右子树

 扁平化后，每个节点的`left`指针必须变成`null`，以及`right`指针应指向前序序列中的下一个节点。 

例如，考虑这棵树：```
        1
       / \
      2   5
     / \   \
    3   4   6
```其前序遍历为：```
1 -> 2 -> 3 -> 4 -> 5 -> 6
```所以最终的扁平化结构就变成了：```
1
 \
  2
   \
    3
     \
      4
       \
        5
         \
          6
```输入是二叉树的根节点。 未显式返回输出。 相反，我们直接修改原始树。 

约束告诉我们树最多包含 2000 个节点。 这足够小，即使是递归解决方案在实践中也是可以接受的，尽管后续特别询问我们是否可以实现`O(1)`额外的空间。 

一些边缘情况很重要：

 - 树可能是空的（`root = null`）
 - 树可能只包含一个节点
 - 树可能已经被压扁了
 - 树可能完全左偏
 - 树可能完全右偏

 简单的实现在重新排列指针时很容易丢失对子树的引用，因此仔细的操作顺序至关重要。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是首先执行前序遍历并将所有访问过的节点存储在列表中。 一旦节点的顺序正确，我们就迭代列表并重新连接指针。 

该过程的工作原理如下：

 1.按前序遍历树
 2. 将每个节点存储在一个数组中
 3. 迭代数组
 4.设置各个节点的`left`指向`null`5.设置各个节点的`right`指向数组中下一个节点的指针

 这个解决方案很容易理解，因为它将遍历和重建分开。 由于前序遍历已经给出了所需的顺序，因此重新连接节点会产生正确的扁平结构。 

然而，这种方法使用与节点数量成比例的额外内存，因为所有节点都存储在辅助列表中。 后续具体要求一个具有恒定额外空间的就地解决方案，因此我们需要更好的方法。 

### 最佳方法

 关键的见解是我们可以在遍历期间重新排列树而无需存储所有节点。 

对于每个节点：

 1. 如果该节点有左子树：

 - 找到左子树的最右边的节点
 -将该节点连接到原始右子树
 - 将左子树向右移动
 - 将左指针设置为`null`这是可行的，因为前序遍历总是在处理右子树之前处理左子树。 通过在当前节点和原始右子树之间插入左子树，我们保留了正确的遍历顺序。 

此技术类似于莫里斯遍历，因为它临时重新连接指针并避免使用递归或显式堆栈。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 将前序遍历存储在数组中，然后重新连接节点 |
 | 最佳| O(n) | O(1) | O(1) | 遍历过程中直接重新排列指针 |

 ## 算法演练

 ### 最佳就地算法

 1. 从一个名为`current`初始化为根节点。 
2. 遍历树`current`不是`null`。 
3. 对于每个节点，检查它是否有左子节点。 

如果没有左子节点，则该节点已经针对展平结构正确定位，因此直接移动到`current.right`。 
4. 如果存在左子树，我们需要在当前节点与其原始右子树之间插入左子树。 
5. 查找当前节点左子树中最右边的节点。 

该节点表示前序遍历时左子树中最终访问的节点。 
6. 连接最右边的节点`right`指向当前节点原始右子树的指针。 

这会保留否则会断开连接的节点。 
7. 将左子树移至右侧：```
current.right = current.left
```8. 将左指针设置为`null`因为展平的结构不得包含左子项。 
9. 移动`current`到`current.right`并继续该过程。 
10. 重复此操作，直到处理完所有节点。 

### 为什么它有效

 该算法保持了每个处理节点都已经满足扁平化链表结构的不变量。 

对于每个节点，在前序遍历中，左子树必须紧接在该节点之后出现。 通过将左子树向右移动并将原始右子树附加到移动子树的末尾，我们保留了精确的前序顺序。 

由于每个节点都被重新连接一次，并且我们永远不会丢失对任何子树的引用，因此最终的结构是一个有效的扁平树。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def flatten(self, root: Optional[TreeNode]) -> None:
        """
        Do not return anything, modify root in-place instead.
        """
        
        current = root
        
        while current:
            
            if current.left:
                
                # Find the rightmost node of the left subtree
                predecessor = current.left
                
                while predecessor.right:
                    predecessor = predecessor.right
                
                # Connect original right subtree
                predecessor.right = current.right
                
                # Move left subtree to the right
                current.right = current.left
                current.left = None
            
            # Move to next node
            current = current.right
```该实现使用一个名为`current`迭代遍历树。 

每当一个节点有左子树时，我们就找到该子树内最右边的节点。 该节点很重要，因为它成为移动后的左子树和原始右子树之间的桥梁。 

重新连接指针后，左子树变成右子树，左指针被清除。 

该算法迭代进行，直到每个节点都转变为扁平结构。 

由于直接修改树并且没有使用辅助数据结构，因此该解决方案实现了恒定的额外空间。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func flatten(root *TreeNode) {
    
    current := root
    
    for current != nil {
        
        if current.Left != nil {
            
            // Find rightmost node of left subtree
            predecessor := current.Left
            
            for predecessor.Right != nil {
                predecessor = predecessor.Right
            }
            
            // Connect original right subtree
            predecessor.Right = current.Right
            
            // Move left subtree to right
            current.Right = current.Left
            current.Left = nil
        }
        
        current = current.Right
    }
}
```Go 实现遵循与 Python 版本相同的逻辑。 

而不是`None`, Go 使用`nil`对于空指针。 指针操作是显式的，因为 Go 结构体是通过引用来处理的。 

该算法仍然就地执行所有修改并避免递归或额外的集合。

 ## 边缘情况

 ### 空树

 一棵空树表示为`root = null`。 如果实现假设根始终存在，这种情况很容易导致空指针错误。 

该算法自然地处理这个问题，因为遍历循环只执行 while`current`不是`null`。 如果树为空，函数立即退出，不执行任何操作。 

### 单节点树

 仅包含一个节点的树没有左子节点或右子节点。 某些实现意外地不必要地修改了指针，或者由于对子树存在的错误假设而失败。 

在此实现中，节点仅通过遍历循环一次。 由于没有左子树，因此不会发生重新布线，并且树仍然有效。 

### 完全左偏树

 左偏树是每个节点只有一个左子节点的树：```
1
/
2
/
3
/
4
```这种情况很重要，因为每个节点都需要重新布线。 有缺陷的实现可能会在重新排列指针时丢失对更深节点的引用。 

该算法通过在更改任何指针之前始终找到左子树的最右边节点来安全地处理此问题。 这保证了剩余的子树在整个转换过程中保持连接。 

### 已经压扁的树

 如果树已经右倾斜并且每个左指针都是`null`，算法应保持结构不变。 

因为该实现仅在以下情况下执行重新布线：`current.left`存在时，已压平的树木将不加修改地进行处理。
