[LeetCode 第 178 题](https://leetcode.com/problems/rank-scores/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`Scores`包含两列：`id`和`score`。 每行代表游戏中获得的分数。 这`id`每一行的列都是唯一的，而`score`列可能包含重复值，因为多个玩家或游戏可能具有相同的分数。 

目标是根据特定的排名规则为每个分数分配排名。 最高分应该获得排名`1`。 如果多行得分相同，则它们必须获得相同的排名。 重要的细节是排名必须密集，意味着排名连续上升，没有间隙。 

这种排名方式通常称为“密集排名”。 

例如：

 - 分数：`4.00, 4.00, 3.85, 3.65, 3.65, 3.50`- 排名：`1,    1,    2,    3,    3,    4`请注意，在排名并列之后`1`，下一个等级是`2`， 不是`3`。 同样，两行并列后`3`，下一个等级变为`4`。 

输入表可能包含：

 - 重复分数
 - 带小数点的分数
 - 行的任意顺序

 输出必须：

 - 包括`score`- 包括计算的`rank`- 排序依据`score`按降序排列

 一个重要的观察结果是排名仅取决于不同的分数值。 重复的分数始终具有相同的排名。 

可能导致问题的边缘情况包括：

 - 所有分数都相同
 - 仅存在一行
 - 分数已按升序而不是降序排序
 - 多个重复组
 - 小数比较

 该问题保证了`id`是唯一的，因此各个行没有歧义。 由于这是一个 SQL/数据库问题，因此效率很重要，因为如果简单地实现排名逻辑可能会变得昂贵。 

## 方法

 ### 蛮力方法

 蛮力的想法是独立计算每个分数的排名。 

对于表中的每一行：

 1. 计算有多少个不同的分数严格大于当前分数。 
2.添加`1`到那个数。 
3. 该值成为排名。 

例如，对于分数`3.65`:

 - 不同分数大于`3.65`是`4.00`和`3.85`- 计数 =`2`- 排名=`2 + 1 = 3`此方法之所以有效，是因为密集排名的精确定义为：

 > 排名 = 不同较大分数的数量 + 1

 缺点是每行都会对表执行另一次扫描。 如果表包含`n`行，这在最坏的情况下会产生二次行为。 

### 最佳方法

 关键的观察结果是 SQL 已经提供了专为这种情况设计的排名窗口函数。 

这`DENSE_RANK()`窗口函数：

 - 按分数降序排列行
 - 将相同的排名分配给相同的分数
 - 产生无间隙的连续排名

 这完全符合问题的要求。 

使用窗口函数既干净又高效，因为数据库引擎在内部优化了排序和排名操作。

 ## 算法演练

 ### 最优算法使用`DENSE_RANK()`1. 选择`score`列从`Scores`桌子。 

我们需要最终结果中的原始分数值。 
2. 使用`DENSE_RANK()`窗函数。 

窗口函数会自动计算排名，同时正确处理重复值。 
3. 对排名窗口进行排序`score DESC`。 

由于分数越高，排名数字越小，因此排序必须按降序进行。 
4. 将计算值别名为`rank`。 

这与所需的输出格式匹配。 
5. 对最终结果进行排序`score DESC`。 

该问题明确要求输出按从最高分到最低分的顺序出现。 

### 为什么它有效`DENSE_RANK()`保证：

 - 相同的分数获得相同的排名
 - 仅当出现新的独特分数时排名值才会增加
 - 没有排名数字被跳过

 这些属性与问题所需的密集排名定义完全匹配。 

## Python 解决方案```python
SELECT
    score,
    DENSE_RANK() OVER (ORDER BY score DESC) AS `rank`
FROM Scores
ORDER BY score DESC;
```该解决方案使用 SQL 窗口函数直接在查询内计算排名。 

这`DENSE_RANK()`函数按分数降序处理行。 每次出现新的独特分数时，排名都会增加一分。 如果多行得分相同，它们会自动获得相同的排名。 

这`OVER (ORDER BY score DESC)`子句定义排名顺序。 较高的分数首先出现，因此排名较低。 

最后，外层`ORDER BY score DESC`确保结果表按要求的顺序返回。 

## 解决方案```go
SELECT
    score,
    DENSE_RANK() OVER (ORDER BY score DESC) AS `rank`
FROM Scores
ORDER BY score DESC;
```由于这是一个数据库问题，Python 和 Go 提交都使用完全相同的 SQL 查询。 

不存在特定于语言的实现差异，因为执行完全发生在 SQL 引擎内部，而不是在 Python 或 Go 运行时代码内部。

 ## 边缘情况

 ### 所有分数都相同

 如果每一行都有相同的分数，则每一行都应该获得排名`1`。 

幼稚的实现可能会意外地增加每一行的排名，而不是每个不同的分数。`DENSE_RANK()`可以正确处理这个问题，因为相同的值会自动共享相同的排名数字。 

### 仅存在一行

 当表中仅包含一个分数时，答案必须仍然有效。 唯一的行应该获得排名`1`。 

此边缘情况验证排名逻辑不依赖于与先前行或多个不同值的比较。 

### 多个重复组

 案例如：```
10.0, 9.5, 9.5, 8.0, 8.0
```可能会暴露出在平局后跳过排名的错误实现。 

不正确的排名可能会产生：```
1, 2, 2, 4, 4
```而不是：```
1, 2, 2, 3, 3
```

`DENSE_RANK()`特别防止排名差距，从而保证正确的密集排名行为。 

### 输入尚未排序

 原始表顺序无关紧要。 分数可以以任何顺序出现。 

明确的`ORDER BY score DESC`确保排名计算和最终输出排序都是正确的，无论原始插入顺序如何。
