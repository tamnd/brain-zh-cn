[LeetCode 第 103 题](https://leetcode.com/problems/binary-tree-zigzag-level-order-traversal/)

 **难度：** 🟡 中等
 **主题：** 树、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们执行二叉树的层序遍历，但有所不同。 我们不是总是从左到右遍历每个级别，而是在每个级别交替遍历方向。 

正常的层序遍历，也称为广度优先搜索（BFS），从根开始逐层访问节点。 在这个问题中，从左到右遍历第一层，从右到左遍历第二层，再从左到右遍历第三层，以此类推，以之字形排列。 

输入是二叉树的根节点。 每个节点都包含一个整数值以及对其左子节点和右子节点的引用。 输出应该是一个列表列表，其中每个内部列表包含树的一层节点的值，并根据所需的锯齿方向排列。 

例如，考虑这棵树：```
        3
       / \
      9  20
         / \
        15  7
```遍历的过程如下：

 - 0 级，从左到右：`[3]`- 1 级，从右到左：`[20, 9]`- 2 级，从左到右：`[15, 7]`所以最终的结果就变成了：```
[[3], [20, 9], [15, 7]]
```约束告诉我们树最多可以包含 2000 个节点。 这足够小，以至于`O(n)`遍历很容易就足够高效了。 由于每个节点必须至少被访问一次，因此线性时间是最佳的。 

应立即考虑几个重要的边缘情况：

 - 树可能是空的，这意味着`root = None`。 在这种情况下，答案应该是一个空列表。 
- 一棵树可能只包含一个节点。 
- 树可能严重倾斜，这意味着所有节点仅存在于左侧或右侧。 
- 级别可能包含许多节点，因此实现必须正确反转遍历方向而不破坏顺序。 

该问题保证输入是有效的二叉树，因此我们不需要处理格式错误的结构或循环。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是使用 BFS 执行标准级别顺序遍历。 对于每个级别，我们按从左到右的顺序收集所有节点值。 收集一个级别后，如果当前级别应该以相反的顺序遍历，我们会在将其添加到结果之前显式反转列表。 

这是可行的，因为 BFS 自然地逐级处理节点。 反转每个替代级别会产生所需的之字形排序。 

然而，反复颠倒列表会带来额外的工作。 如果一个级别包含`k`节点，扭转成本`O(k)`。 在所有级别上，这仍然是`O(n)`总体而言，因为每个节点最多参与一次逆转。 虽然限制是可以接受的，但它不是最干净或最有效的实现。 

### 最佳方法

 最佳解决方案也使用 BFS，但我们不是在之后反转列表，而是在处理节点时以正确的顺序将值放入级别列表中。 

关键的见解是 BFS 已经为我们提供了按级别正确的分组。 剩下的唯一挑战是在交替级别上对值进行不同的排序。 

我们可以维护一个布尔标志，例如`left_to_right`，它跟踪当前级别的遍历方向：

 - 如果`left_to_right`是`True`，通常附加值。 
- 如果`left_to_right`是`False`，在级别列表的开头插入值。 

这避免了显式的反转步骤并保持遍历逻辑干净和直接。 

由于每个节点只处理一次，因此该算法以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 标准 BFS，反转每个交替级别 |
 | 最佳| O(n) | O(n) | 带有方向感知插入的 BFS |

 ## 算法演练

 1. 首先处理空树的情况。 如果根是`None`，立即返回一个空列表，因为没有要遍历的级别。 
2. 初始化一个队列，用于BFS遍历。 队列存储仍需要处理的节点。 首先将根节点放入队列中。 
3. 创建一个结果列表，该列表最终将包含锯齿形顺序的所有级别。 
4. 维护一个名为的布尔变量`left_to_right`。 最初将其设置为`True`因为第一层必须从左到右遍历。 
5. 开始 BFS 循环。 当队列不为空时继续处理。 
6. 在每次迭代开始时，通过检查队列大小来确定有多少个节点属于当前级别。 这很重要，因为 BFS 不断追加子节点，因此我们必须逐级隔离处理。 
7. 创建一个名为的空列表`current_level`存储该级别的节点值。 
8. 准确处理`level_size`节点：

 1. 从队列中移除最前面的节点。 
2. 如果从左到右遍历，则将节点的值追加到`current_level`。 
3. 否则，在索引处插入节点的值`0`，以相反的顺序有效地构建关卡。 
4. 将节点的左子节点添加到队列中（如果存在）。 
5. 将节点的右子节点添加到队列中（如果存在）。 
9.处理完关卡中的所有节点后，追加`current_level`到结果。 
10. 通过设置翻转遍历方向：```
left_to_right = not left_to_right
```1. 继续，直到队列变空。 
2. 返回结果列表。 

### 为什么它有效

 BFS保证节点被逐级处理。 在每次迭代中，队列恰好包含属于当前级别的节点。 通过改变值的插入方式`current_level`，我们确保排序符合所需的锯齿形图案。 由于每个节点都被访问一次并被分配到一个级别，因此最终的输出是正确的。 

## Python 解决方案```python
from collections import deque
from typing import List, Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def zigzagLevelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if not root:
            return []

        result = []
        queue = deque([root])
        left_to_right = True

        while queue:
            level_size = len(queue)
            current_level = []

            for _ in range(level_size):
                node = queue.popleft()

                if left_to_right:
                    current_level.append(node.val)
                else:
                    current_level.insert(0, node.val)

                if node.left:
                    queue.append(node.left)

                if node.right:
                    queue.append(node.right)

            result.append(current_level)
            left_to_right = not left_to_right

        return result
```实现首先检查树是否为空。 这可以防止不必要的处理并立即处理最简单的边缘情况。 

一个`deque`用于 BFS 队列，因为它提供了高效的`popleft()`恒定时间内的操作。 使用普通的 Python 列表会使从前面的删除效率低下。 

这`left_to_right`标志控制遍历方向。 当旗帜是`True`，值通常附加。 当它是`False`，值被插入到级别列表的开头，自然地创建反向排序。 

每个级别开始时的队列大小存储在`level_size`。 这确保我们在移动到下一级别之前仅处理当前级别的节点。 

每个级别完成后，方向标志会被切换，以便下一个级别使用相反的遍历顺序。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func zigzagLevelOrder(root *TreeNode) [][]int {
    if root == nil {
        return [][]int{}
    }

    result := [][]int{}
    queue := []*TreeNode{root}
    leftToRight := true

    for len(queue) > 0 {
        levelSize := len(queue)
        currentLevel := []int{}

        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]

            if leftToRight {
                currentLevel = append(currentLevel, node.Val)
            } else {
                currentLevel = append([]int{node.Val}, currentLevel...)
            }

            if node.Left != nil {
                queue = append(queue, node.Left)
            }

            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }

        result = append(result, currentLevel)
        leftToRight = !leftToRight
    }

    return result
}
```Go 解决方案遵循与 Python 版本相同的 BFS 策略。 由于Go没有提供内置的双端队列，因此使用切片作为队列。 

Nil 检查在 Go 中是明确的，因此使用以下方法处理空树情况：```go
if root == nil
```主要的实现差异在于逆序的处理方式。 在Python中，我们使用`insert(0, value)`。 在 Go 中，我们使用以下方式添加值：```go
currentLevel = append([]int{node.Val}, currentLevel...)
```这将创建锯齿形遍历所需的相反顺序。 

不存在整数溢出问题，因为节点值被限制在`-100`和`100`。

 ## 边缘情况

 ### 空树

 空树是最重要的边缘情况之一。 幼稚的 BFS 实现可能会尝试立即处理根而不检查它是否存在，从而导致运行时错误。 该实现通过以下方式安全地处理此问题：```
if not root:
    return []
```这确保算法在空输入时立即终止。 

### 单节点树

 仅包含一个节点的树可能会暴露关卡处理逻辑中的错误，尤其是在切换遍历方向时。 该实现正确地将根处理为单个级别，然后退出，因为没有子级添加到队列中。 

### 高度倾斜的树

 倾斜树的行为几乎就像链表一样。 某些实现意外地假设每个级别都存在多个节点。 在倾斜树中，每一层仅包含一个节点。 BFS 方法自然可以处理这个问题，因为级别是由队列大小决定的，而不是由树形状的假设决定的。 

### 不均匀的树结构

 一些节点可能只有一个子节点，而其他节点可能有两个。 不正确的队列处理可能会意外地错误地跳过节点或处理级别。 该实现在将每个子项添加到队列之前单独安全地检查它：```
if node.left:
    queue.append(node.left)

if node.right:
    queue.append(node.right)
```这保证了所有有效的子项都被处理一次。
