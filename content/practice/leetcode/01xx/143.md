[LeetCode 第 143 题](https://leetcode.com/problems/reorder-list/)

 **难度：** 🟡 中等
 **主题：** 链表、两个指针、堆栈、递归

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个单链表的头，并要求我们以非常特定的交替模式对节点进行重新排序。 

正常的链表如下所示：```
L0 → L1 → L2 → ... → Ln
```我们必须将其转化为：```
L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → ...
```重要的细节是我们不允许更改节点值。 我们必须通过修改来物理地重新排列节点连接`next`指针。 

例如：```
1 → 2 → 3 → 4
```变成：```
1 → 4 → 2 → 3
```另一个例子：```
1 → 2 → 3 → 4 → 5
```变成：```
1 → 5 → 2 → 4 → 3
```输入是单链表的头节点。 该函数就地修改列表并且不返回任何内容。 

约束告诉我们列表最多可以包含`5 * 10^4`节点。 这立即排除了低效的二次解。 由于链表不支持随机访问，重复遍历到链表末尾会变得太慢。 

一些边缘情况很重要：

 - 只有一个节点的列表应保持不变。 
- 具有两个节点的列表已经处于有效的重新排序形式。 
- 奇数长度列表和偶数长度列表在拆分和合并期间的行为略有不同。 
- 由于列表是单向链接的，因此我们无法向后移动，因此反转或访问尾部需要仔细的指针操作。 
- 忘记终止重新排序的列表可能会意外地创建循环。 

## 方法

 ### 蛮力方法

 一种直接的方法是重复取出最后一个节点并将其插入到当前前端节点之后。 

例如：```
1 → 2 → 3 → 4 → 5
```第一次迭代：```
1 → 5 → 2 → 3 → 4
```第二次迭代：```
1 → 5 → 2 → 4 → 3
```要在单链表中执行此操作，我们必须重复遍历该列表以找到倒数第二个节点，以便我们可以分离最后一个节点。 

这是正确的，因为每次迭代都会将正确的节点从末尾放置到所需的位置。 

然而，这种方法效率低下。 每次提取最后一个节点都需要遍历剩余列表的大部分。 由于这种情况发生了很多次，因此总时间复杂度变成了二次方。 

高达`50,000`节点，一个`O(n^2)`解决办法太慢了。 

### 最佳方法

 关键的见解是重新排序的序列在以下之间交替：

 - 从头开始的节点
 - 从末尾开始的节点

 我们可以将列表重新组织为两半，而不是重复搜索尾部：

 1. 找到列表的中间位置。 
2. 反转下半场。 
3. 交替合并两半。 

例如：```
1 → 2 → 3 → 4 → 5
```找到中间后：```
First half:  1 → 2 → 3
Second half: 4 → 5
```后半部分反转：```
5 → 4
```交替合并：```
1 → 5 → 2 → 4 → 3
```这很有效，因为：

 - 寻找中间点`O(n)`- 倒车`O(n)`- 合并需要`O(n)`总时间复杂度变为线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复遍历到尾部|
 | 最佳| O(n) | O(1) | O(1) | 拆分、反转和合并列表 |

 ## 算法演练

 1. 使用慢指针和快指针技术找到链表的中间位置。 

这`slow`指针一次移动一步，而`fast`指针一次移动两步。 什么时候`fast`到达终点，`slow`将在中间。 

例子：```
1 → 2 → 3 → 4 → 5
        ^
      slow
```2. 将列表分成两半。 

找到中间后，将前半部分与后半部分断开。```
First half:  1 → 2 → 3
Second half: 4 → 5
```3. 反转下半场。 

使用标准链表反转来反转后半部分的节点。```
4 → 5
```变成：```
5 → 4
```反转很重要，因为重新排序模式会从前面和后面交替出现。 
4. 交替合并两半。 

从前半部分的第一个节点开始，然后附加相反后半部分的一个节点。 

合并过程示例：```
First half:  1 → 2 → 3
Second half: 5 → 4
```逐步合并：```
1 → 5
1 → 5 → 2 → 4
1 → 5 → 2 → 4 → 3
```5. 确保最终节点指向`None`。 

这可以防止链表中出现意外循环。 

### 为什么它有效

 该算法之所以有效，是因为重新排序的模式本质上是列表的前半部分和反转的后半部分之间的交替合并。 反转后半部分将尾节点按照交替插入所需的确切顺序放置。 由于每个节点都被访问并重新定位一次，因此最终的结构符合所需的顺序。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        """
        Do not return anything, modify head in-place instead.
        """

        if not head or not head.next:
            return

        # Step 1: Find the middle
        slow = head
        fast = head

        while fast.next and fast.next.next:
            slow = slow.next
            fast = fast.next.next

        # Step 2: Reverse second half
        second_half = slow.next
        slow.next = None

        prev = None
        current = second_half

        while current:
            next_node = current.next
            current.next = prev
            prev = current
            current = next_node

        second_half = prev

        # Step 3: Merge two halves
        first_half = head

        while second_half:
            temp1 = first_half.next
            temp2 = second_half.next

            first_half.next = second_half
            second_half.next = temp1

            first_half = temp1
            second_half = temp2
```实现遵循算法的三个主要阶段。 

第一阶段使用慢指针和快指针找到中点。 循环条件`fast.next and fast.next.next`确保`slow`对于奇数和偶数长度列表，都停止在正确的中点。 

第二阶段原地逆转下半场。 使用了三个指针：

 -`prev`存储反转部分
 -`current`遍历剩余节点
 -`next_node`temporarily stores the next node before changing pointers

 逆转之后，`prev`成为逆转半场的新头。 

最后阶段交替合并两个列表。 临时指针在重新连接链接之前保留下一个节点。 这可以防止失去对列表其余部分的访问。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func reorderList(head *ListNode) {
    if head == nil || head.Next == nil {
        return
    }

    // Step 1: Find middle
    slow := head
    fast := head

    for fast.Next != nil && fast.Next.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }

    // Step 2: Reverse second half
    secondHalf := slow.Next
    slow.Next = nil

    var prev *ListNode
    current := secondHalf

    for current != nil {
        nextNode := current.Next
        current.Next = prev
        prev = current
        current = nextNode
    }

    secondHalf = prev

    // Step 3: Merge two halves
    firstHalf := head

    for secondHalf != nil {
        temp1 := firstHalf.Next
        temp2 := secondHalf.Next

        firstHalf.Next = secondHalf
        secondHalf.Next = temp1

        firstHalf = temp1
        secondHalf = temp2
    }
}
```Go 实现在结构上几乎与 Python 版本相同。 主要区别是显式指针处理`*ListNode`。 

Go 使用`nil`而不是Python的`None`。 变量声明也更加明确。 由于两种语言中的链表操作都是基于指针的，因此整体逻辑保持不变。 

不存在整数溢出问题，因为该算法不执行指针遍历之外的算术运算。

 ## 边缘情况

 ### 单节点列表

 仅包含一个节点的列表已处于有效的重新排序形式。 如果算法盲目地尝试拆分或反转列表，这种情况很容易导致问题。 实现立即处理这个问题：```
if not head or not head.next:
    return
```这可以防止不必要的指针操作。 

### 奇数长度列表

 奇数长度列表包含一个中间节点，该节点应保留在重新排序结构的末尾。 

例子：```
1 → 2 → 3 → 4 → 5
```变成：```
1 → 5 → 2 → 4 → 3
```中间节点`3`停留在最后。 不正确的中点处理可能会重复或丢失该节点。 慢-快指针技术确保分割正确发生。 

### 防止循环

 最常见的链表错误之一是意外创建循环。 

如果我们在反转之前不断开前半部分：```
slow.next = None
```原来的链接可能会保持连接状态，导致合并后出现无限遍历循环。 

明确终止前半部分可保证正确的最终结构。 

### 两节点列表

 两个节点的列表已经正确排序：```
1 → 2
```某些实现错误地不必要地反转或重新连接指针，可能会破坏列表。 当前的解决方案自然地处理这种情况，无需特殊逻辑，因为后半部分仅包含一个节点，并且合并阶段仍然有效。
