[LeetCode 第 138 题](https://leetcode.com/problems/copy-list-with-random-pointer/)

 **难度：** 🟡 中等
 **主题：** 哈希表、链表

 ## 解决方案

 ## 问题理解

 这个问题要求我们创建一个完全独立的链表副本，其中每个节点包含两个指针：

 -`next`，它指向列表中的下一个节点
 -`random`，它可以指向列表中的任何节点或`null`关键要求是复制的列表必须是真正的深复制。 这意味着新列表中的每个节点都必须重新分配，并且复制列表中的任何指针都不能引用原始列表中的节点。 

输入在概念上以对列表的形式给出：```
[val, random_index]
```这里：

-`val`是节点的值
 -`random_index`告诉我们哪个节点`random`指针引用
 -`null`意味着`random`指针没有指向任何地方

 但是，实际函数不接收此数组表示形式。 相反，它仅接收链表的头节点。 我们必须自己遍历该结构并重建两个指针关系。 

挑战来自于`random`指针。 与普通链表不同，节点可以向后、向前，甚至指向它们自己。 这意味着简单的顺序复制是不够的，因为当我们复制一个节点时，它的`random`目标可能还不存在。 

限制相对较小：

 - 最多 1000 个节点
 - 节点值范围为`-10^4`到`10^4`这些限制允许`O(n)`甚至`O(n^2)`解决方案通过，但问题从根本上是关于正确保留指针关系而不是处理巨大的输入大小。 

一些边缘情况很重要：

 - 列表可能为空
 - 一个节点的`random`指针可能是`null`- 多个节点可能指向同一个随机目标
 - 一个节点可以通过以下方式指向自己：`random`- 随机指针可能会产生与`next`链条

 由于意外地重用原始节点或丢失原始节点和复制节点之间的映射，幼稚的实现很容易失败。 

## 方法

 ### 蛮力方法

 暴力策略将尝试重新创建每个节点，然后对于每个原始节点，搜索复制的列表以找到相应的随机目标。 

该过程如下所示：

 1. 使用以下命令依次复制所有节点`next`指针。 
2. 对于每个原始节点：

 - 找到引用的节点`random`- 搜索原始列表以确定其位置
 - 再次遍历复制链表，定位到对应的复制节点
 - 分配复制的`random`指针

 这是可行的，因为每个原始节点都有一个对应的复制节点。 通过重复搜索这两个列表，我们最终可以正确地重建随机关系。 

然而，这种方法效率低下，因为每次随机指针分配都可能需要再次遍历列表。 和`n`节点，这可能导致`O(n^2)`时间复杂度。 

### 最佳方法

 关键的见解是我们需要一种快速的方法来绘制地图：```
original node -> copied node
```哈希映射完美地解决了这个问题。 

我们对列表执行两次遍历：

 1.第一遍：

 - 创建每个节点的副本
 - 将映射存储在哈希映射中
 2.第二遍：

 - 使用哈希映射来分配：

 -`next`-`random`由于哈希图查找是`O(1)`平均而言，我们避免了重复遍历并实现了线性时间复杂度。 

这种方法是理想的，因为每个原始节点仅被处理恒定的次数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复搜索列表以定位随机目标 |
 | 最佳| O(n) | O(n) | 使用从原始节点到复制节点的哈希映射 |

 ## 算法演练

 ### 最优哈希图算法

 1、立即处理空表情况。 

如果`head`是`null`，没有什么可以复制的，所以我们返回`null`。 
2. 创建哈希图。 

哈希映射将存储：```
original node -> copied node
```这种映射使我们能够立即找到任何原始节点的复制版本。 
3、第一次遍历原链表。 

对于每个原始节点：

 - 创建一个具有相同值的新节点
 - 将映射存储在哈希映射中

 在此阶段，我们仅复制节点值。 我们还没有分配`next`或者`random`。 
4、再次遍历原链表。 

对于每个原始节点：

 - 从哈希映射中检索其复制的节点
 - 设置：

 -`copy.next = hashmap[original.next]`-`copy.random = hashmap[original.random]`由于每个节点都已存在于哈希图中，因此所有指针分配都变得简单。 
5. 返回复制的头。 

复制的头部很简单：```
hashmap[head]
```### 为什么它有效

 该算法之所以有效，是因为每个原始节点都接收到一个复制节点，并且哈希图在整个过程中保留了这种关系。 

在第二次遍历期间，使用映射将每个指针分配从原始节点重定向到复制节点。 因此：

 - 所有复制的节点引用其他复制的节点
 - 没有复制的节点引用原始节点
 - 两者的确切结构`next`和`random`关系被保留

 这保证了有效的深层复制。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, x: int, next: 'Node' = None, random: 'Node' = None):
        self.val = int(x)
        self.next = next
        self.random = random
"""

from typing import Optional

class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        if not head:
            return None

        old_to_new = {}

        current = head
        while current:
            old_to_new[current] = Node(current.val)
            current = current.next

        current = head
        while current:
            copy_node = old_to_new[current]

            copy_node.next = old_to_new.get(current.next)
            copy_node.random = old_to_new.get(current.random)

            current = current.next

        return old_to_new[head]
```实现首先处理空列表的情况。 这可以防止不必要的工作并避免取消引用`None`。 

字典`old_to_new`是核心数据结构。 每个原始节点用作键，其复制的节点成为值。 

第一次遍历创建所有复制的节点。 此时，仅复制节点值，因为某些引用的节点可能尚不存在。 

第二次遍历建立了指针关系。 由于每个复制的节点已经存在于字典中，因此分配`next`和`random`变成直接查找操作。 

使用`.get()`很重要，因为`current.next`或者`current.random`或许`None`。 在这种情况下，查找会安全返回`None`。 

最后，从哈希映射中返回复制的头节点。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Next *Node
 *     Random *Node
 * }
 */

func copyRandomList(head *Node) *Node {
    if head == nil {
        return nil
    }

    oldToNew := make(map[*Node]*Node)

    current := head
    for current != nil {
        oldToNew[current] = &Node{
            Val: current.Val,
        }
        current = current.Next
    }

    current = head
    for current != nil {
        copyNode := oldToNew[current]

        copyNode.Next = oldToNew[current.Next]
        copyNode.Random = oldToNew[current.Random]

        current = current.Next
    }

    return oldToNew[head]
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

Go 映射用于将原始节点指针与复制的节点指针关联起来：```go
map[*Node]*Node
```当键不存在时，Go 映射返回零值。 由于指针的零值是`nil`，我们可以安全地分配：```go
copyNode.Next = oldToNew[current.Next]
```即使当`current.Next`是`nil`。 

与 Python 不同，Go 需要使用显式指针分配`&Node{}`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | Each node is visited twice |
 | 空间| O(n) | 哈希映射为每个原始节点存储一个复制节点 |

 该算法对链表执行两次线性遍历。 哈希图中每个节点的插入和查找都是`O(1)`平均而言，因此总运行时间保持线性。 

额外的空间来自哈希图和复制的节点本身。 由于我们为每个原始节点创建一个复制节点，因此辅助空间复杂度为`O(n)`。

 ## 边缘情况

 ### 空列表

 输入头可以是`null`。 这是最简单的输入，但忘记处理它可能会导致遍历期间取消引用错误。 

实施立即检查：```
if not head:
    return None
```这保证了在任何哈希映射操作发生之前的安全处理。 

### 自引用随机指针

 一个节点可以通过`random`指针。 

例如：```
A.random = A
```浅复制会意外保留原始引用，这违反了深复制要求。 

哈希映射方法可以自然地处理这个问题，因为：```
copy.random = hashmap[original.random]
```什么时候`original.random`是原始节点本身，复制的节点接收对其自身复制副本的引用。 

### 多个节点共享相同的随机目标

 多个节点可以通过以下方式指向同一个节点`random`。 

例如：```
A.random = C
B.random = C
```有缺陷的实现可能会意外地创建重复的副本`C`。 

哈希图保证了唯一性，因为每个原始节点都被复制一次。 对同一原始节点的每次查找都会返回相同的复制节点。 

### 重复的节点值

 不同的节点可能包含相同的值。 

例如：```
[3, 3, 3]
```如果我们尝试通过值来识别节点，映射就会变得不明确。 

该实现通过使用节点引用作为哈希映射键而不是节点值来完全避免这种情况。 即使值相同，节点对象仍然不同。
