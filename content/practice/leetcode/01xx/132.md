[LeetCode 第 132 题](https://leetcode.com/problems/palindrome-partitioning-ii/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们将字符串拆分为子字符串，使得每个子字符串都是回文。 在所有有效的回文分区中，我们必须返回所需的最小切割次数。 

切割将绳子分成两部分。 例如，如果字符串是`"aab"`，我们可以将其划分为：

 -`"a" | "a" | "b"`使用 2 次切割
 -`"aa" | "b"`使用 1 次切割

 自从`"aa"`本身就是回文，第二个分区更好，所以答案是`1`。 

输入是单个字符串`s`仅由小写英文字母组成。 长度可以大到`2000`，这是一个重要的约束，因为它排除了高指数解。 任何算法明显比`O(n^2)`或者`O(n^3)`可能会超时。 

输出是一个整数，表示每个结果子串都是回文所需的最小切割次数。 

一些边缘情况很重要：

 - 已经是回文的字符串，例如`"racecar"`，需要`0`削减。 
- 没有多字符回文的字符串，例如`"abc"`，需要`n - 1`削减。 
- 非常短的字符串，例如`"a"`或者`"ab"`如果基本情况不正确，很容易处理不当。 
- 重复的字符，例如`"aaaaa"`创建许多重叠的回文子串，这使得记忆或动态编程尤其重要。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试一切可能的方法来划分字符串并检查所有生成的子字符串是否都是回文。 

在每个位置，我们可以剪切或继续扩展当前子字符串。 这将创建指数数量的可能分区。 对于每个分区，我们必须验证每个子串是否是回文。 

例如，对于`"aab"`:

 -`"a" | "a" | "b"`-`"aa" | "b"`暴力解决方案评估所有可能性并保持有效分区之间的最小切割次数。 

这种方法是正确的，因为它详尽地探索了每个分区配置。 然而，对于`n = 2000`。 分区的数量呈指数级增长，这使得这是不可行的。 

### 最佳解决方案的关键见解

 主要观察结果是许多回文检查重复。 

假设我们已经知道是否`s[i:j]`是一个回文。 然后，每当我们考虑涉及该子字符串的分区时，我们就可以重用该信息。 

这自然会导致动态规划。 

最优解采用两种DP结构：

 1. 回文表`is_palindrome[i][j]`- 存储是否为子串`s[i:j+1]`是一个回文。 
- 允许稍后进行恒定时间回文检查。 
2. 剪切数组`dp[i]`- 表示子串所需的最少切割次数`s[0:i+1]`。 

递归的工作原理如下：

 - 如果`s[0:i]`本身是回文，那么`dp[i] = 0`。 
- 否则，尝试每个可能的分区点`j`。 

- 如果`s[j:i]`是回文，那么：

 -`dp[i] = min(dp[i], dp[j-1] + 1)`这将指数搜索转换为多项式时间动态规划解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × n) | O(2^n × n) | O(n) | 递归地探索每个分区 |
 | 最佳| O(n^2) | O(n^2) | O(n^2) | O(n^2) | 使用回文预处理和 DP |

 ## 算法演练

 ### 第 1 步：创建回文查找表

 我们创建一个二维表`is_palindrome`在哪里：```
is_palindrome[i][j] = True
```表示子串`s[i:j+1]`是一个回文。 

这种预处理至关重要，因为直接重复检查回文会显着增加运行时间。 

如果满足以下条件，则子串是回文串：

 - 两端的字符匹配
 - 内部子串也是回文

 所以：```
s[i] == s[j] AND is_palindrome[i+1][j-1]
```对于长度为 1 或 2 的子串：

 - 长度 1 始终是回文数
 - 如果两个字符匹配，则长度 2 是回文

 ### 步骤2：初始化DP数组

 我们创造：```
dp[i]
```它存储子串所需的最小切割`s[0:i+1]`。 

最初，位置的最坏情况`i`是：```
dp[i] = i
```因为我们可以在每个角色之间进行切换。 

例如：```
"abcd"
```需要：```
a | b | c | d
```使用 3 次切割。 

### 步骤 3：在计算切割时填充回文表

 我们迭代每个结束索引`end`。 

对于每个`end`，我们检查所有可能的起始索引`start`。 

如果`s[start:end+1]`是一个回文：

 - 标记它`is_palindrome`- 更新最小削减

 有两种情况：

 1. 回文从索引开始`0`- 无需削减
 -`dp[end] = 0`2. 回文开始较晚

 - 在这个回文之前添加一个剪切
 - 候选值变为：```
dp[start - 1] + 1
```我们在所有有效分区中取最小值。 

### 第四步：返回最终答案

 结果是：```
dp[n - 1]
```因为它代表整个字符串的最小切割次数。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的回文分区都必须以某个回文子串结尾。 

对于每个职位`end`，我们考虑所有以此处结尾的回文子串。 如果我们知道该子串之前所有内容的最佳解决方案，那么添加一次剪切就会产生一个有效的候选解决方案。 

动态规划保证了最优性，因为每个状态都是由较小的最优子​​问题构建的。 

## Python 解决方案```python
class Solution:
    def minCut(self, s: str) -> int:
        n = len(s)

        # is_palindrome[i][j] tells whether s[i:j+1] is a palindrome
        is_palindrome = [[False] * n for _ in range(n)]

        # dp[i] = minimum cuts needed for s[0:i+1]
        dp = [0] * n

        for end in range(n):
            # Worst case: cut before every character
            dp[end] = end

            for start in range(end + 1):
                if (
                    s[start] == s[end]
                    and (
                        end - start <= 2
                        or is_palindrome[start + 1][end - 1]
                    )
                ):
                    is_palindrome[start][end] = True

                    # Entire substring is a palindrome
                    if start == 0:
                        dp[end] = 0
                    else:
                        dp[end] = min(dp[end], dp[start - 1] + 1)

        return dp[-1]
```该实现将回文检测和最小割计算组合到单个嵌套循环结构中。 

外循环迭代子字符串的每个可能的结束位置。 对于每个结束位置，我们初始化最坏情况下的切割次数。 

内循环尝试每个可能的起始位置。 每当找到回文时，我们都会更新回文表，以便将来的计算可以有效地重用它。 

如果回文从索引开始`0`，则不需要剪切，因为整个前缀已经有效。 否则，我们在回文前添加一次剪切并与当前最佳值进行比较。 

这种方法避免了重新计算回文并确保每个子串都得到有效处理。 

## 解决方案```go
func minCut(s string) int {
	n := len(s)

	isPalindrome := make([][]bool, n)
	for i := range isPalindrome {
		isPalindrome[i] = make([]bool, n)
	}

	dp := make([]int, n)

	for end := 0; end < n; end++ {
		// Worst case: cut before every character
		dp[end] = end

		for start := 0; start <= end; start++ {
			if s[start] == s[end] &&
				(end-start <= 2 || isPalindrome[start+1][end-1]) {

				isPalindrome[start][end] = true

				if start == 0 {
					dp[end] = 0
				} else {
					dp[end] = min(dp[end], dp[start-1]+1)
				}
			}
		}
	}

	return dp[n-1]
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现与 Python 版本非常相似，但有一些特定于语言的细节。 

Go 没有提供内置的`min`整数函数，因此我们手动定义一个。 

回文表被创建为切片的切片。 每行必须单独分配。 

Go 中的字符串是可字节索引的，这里可以正常工作，因为问题只保证小写英文字母。 如果可以使用 Unicode 字符，则索引将需要符文转换。

 ## 边缘情况

 ### 单字符串

 像这样的字符串`"a"`需要零切割，因为单个字符始终是回文。 

这种情况很重要，因为不正确的初始化可能会意外产生`1`而不是`0`。 该实现通过设置来处理这个问题`dp[end] = 0`每当回文从索引处开始时`0`。 

### 没有大回文的字符串

 字符串如`"abcdef"`不包含超过一个字符的回文。 

在这种情况下，算法应该产生`n - 1`削减。 该实现自然会处理这个问题，因为发现的唯一有效回文是单字符子字符串。 

### 整个字符串已经是回文

 对于像这样的输入`"racecar"`或者`"abba"`，正确答案是`0`。 

如果算法总是假设至少需要一次切割，那么这种情况可能会被错误处理。 该实现可以正确检测子字符串何时来自`0`到`end`是一个回文并且立即设置`dp[end] = 0`。 

### 重复字符

 字符串像`"aaaaaa"`包含许多重叠的回文。 

朴素的递归解决方案在这里表现不佳，因为它们反复重新计算相同的回文检查。 DP 回文表通过存储先前计算的结果来消除冗余工作。
