[LeetCode 第 122 题](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、贪心

 ## 解决方案

 ## 问题理解

 这个问题要求我们在连续几天的股票交易中最大化利润。 我们得到一个数组`prices`， 在哪里`prices[i]`代表股票价格`i`那天。 我们可以根据需要进行任意数量的买卖交易，但有一个重要的限制：在任何时候，我们最多只能持有一股股票。 

与原来的“买卖股票的最佳时机”问题不同，这里只允许一笔交易，这里我们可以重复买卖。 此外，该问题明确指出，只要我们一次持有的股票不超过一股，就允许在同一天出售和购买。 这个细节很重要，因为它意味着我们可以不受限制地将盈利机会链接在一起。 

目标是计算可实现的**最大总利润**。 如果股价只下跌，那么最好的决定是不进行交易，从而获得利润`0`。 

这些约束提供了有关预期效率的有用提示：

 -`1 <= prices.length <= 3 * 10^4`-`0 <= prices[i] <= 10^4`输入大小最多可以增长到 30,000 个元素，这在实践中排除了指数或二次方法。 理想情况下，我们应该以线性时间解决方案为目标`O(n)`。 

预先识别一些边缘情况很重要。 如果数组只包含一天，则不会发生任何交易，因为买卖至少需要两天。 如果价格严格下降，答案应该是`0`因为每笔交易都会赔钱。 如果价格严格上涨，则最佳策略实际上是在开始时买入一次并在最后卖出，尽管该算法在概念上可能会执行较小的中间交易。 重复相同的价格也需要小心处理，因为以相同的价格买卖不会带来任何收益。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试探索所有可能的买卖决策序列。 每天，我们可以选择是买入、卖出还是什么都不做，同时遵守一次只能持有一只股票的限制。 

这可以表述为递归搜索或动态编程探索，其中我们考虑每种可能的交易组合。 例如，在某一天买入后，我们可以尝试在未来的每一天卖出，并递归地解决剩余的问题。 

暴力法保证了正确性，因为它详尽地考虑了每一个有效的交易序列并选择利润最大的一个。 然而，由于每天都会引入分支决策，因此它的运行时间呈指数级增长。 由于时间长达 30,000 天，这在计算上变得不可行。 

### 最优贪心法

 关键的观察是**每一次有利可图的向上运动都可以独立安全地捕获**。 

假设股票价格从`1 → 2 → 3 → 4`。 我们可以在`1`并出售于`4`, 赚取`3`。 或者：

 - 购买于`1`，出售于`2`， 利润`1`- 购买于`2`，出售于`3`， 利润`1`- 购买于`3`，出售于`4`， 利润`1`总计仍为`3`。 

这种洞察力意味着我们不需要明确地寻找完美的山谷和峰值。 相反，每当今天的价格高于昨天的价格时，我们只需将差额添加到我们的利润中即可。 我们有效地收集每一个积极的收益。 

这是有效的，因为任何长的盈利区间都可以分解为较小的每日盈利增长，而不会改变总利润。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试所有买入/卖出决策组合 |
 | 最优贪心 | O(n) | O(1) | O(1) | 添加每日积极的价格上涨 |

 ## 算法演练

 1. 初始化一个名为`total_profit`到`0`。 

该变量将存储所有成功交易所赚取的累积利润。 
2. 从第二天开始迭代数组。 

我们将每天的价格与前一天的价格进行比较，因为只有当价格上涨时才会出现盈利机会。 
3. 检查今天的价格是否大于昨天的价格。 

如果`prices[i] > prices[i - 1]`，那么就可以从这种向上的运动中获利。 
4. 将正差值添加到`total_profit`。 

具体来说，添加：```
prices[i] - prices[i - 1]
```这代表昨天买入并今天卖出，或者相当于获取该部分利润。 
5.忽略非盈利性的变动。 

如果今天的价格等于或低于昨天的价格，我们会跳过它，因为交易不会增加利润。 
6. 继续直到数组末尾。 

经过一整天的处理，`total_profit`包含可实现的最大利润。 

### 为什么它有效

 该算法之所以有效，是因为任何有利可图的价格上涨序列都可以分解为个人每日收益。 对于不断增长的细分市场：```
buy at a, sell at d
profit = d - a
```这在数学上等价于：```
(b - a) + (c - b) + (d - c) = d - a
```通过对所有正日差异进行求和，我们获得了与最佳买卖序列完全相同的利润。 由于无法从下降区间中获取额外利润，因此跳过它们始终是最佳选择。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        total_profit = 0

        for i in range(1, len(prices)):
            if prices[i] > prices[i - 1]:
                total_profit += prices[i] - prices[i - 1]

        return total_profit
```实现从初始化开始`total_profit`为零。 该变量累积迭代期间发现的所有盈利收益。 

循环从索引开始`1`因为每天的价格都要和前一天进行比较。 对于每个头寸，我们都会检查当天的价格是否超过前一天的价格。 如果是这样，我们会将差额添加到运行利润中。 

价格下降或不变的价格被忽略，因为它们不能贡献正利润。 循环完成后，累加值将作为最大可能利润返回。 

该实现直接反映了前面描述的贪婪推理。 它没有明确模拟买卖操作，而是捕获每个价格上涨部分的利润。 

## 解决方案```go
func maxProfit(prices []int) int {
    totalProfit := 0

    for i := 1; i < len(prices); i++ {
        if prices[i] > prices[i-1] {
            totalProfit += prices[i] - prices[i-1]
        }
    }

    return totalProfit
}
```Go 实现遵循与 Python 版本相同的逻辑。 我们从索引开始迭代切片`1`，比较相邻价格，并积累正差异。 

周围没有什么特别担心的`nil`与空切片相比，因为问题保证至少有一个元素。 整数溢出也不是问题，因为最大可能利润仍然在 Go 的范围内`int`给定约束下的范围。

 ## 边缘情况

 单日输入是一个重要的边界情况。 由于盈利需要买入和卖出操作，单靠一天是无法产生任何交易的。 假设至少有两个元素的简单实现可能会触发越界访问。 这个实现自然地处理它，因为循环从索引处开始`1`，意味着没有迭代发生并且`0`被返回。 

严格递减的价格序列也可能导致错误解决方案中的错误。 一些实现错误地强制至少一项交易或尝试错误地跟踪峰值和谷值。 对于诸如这样的输入`[7,6,4,3,1]`，每天的差异都是负数，因此算法简单地跳过所有日期并返回`0`。 

重复相同的价格值得特别注意，因为以相同的价格买卖不会产生收益。 例如，`[2,2,2,2]`应该返回`0`。 由于实施仅在以下情况下增加利润：`prices[i] > prices[i - 1]`，相等的值将被自动忽略。 

交替上升和下降的序列是另一个微妙的情况。 例如，`[1,3,2,5,4,7]`需要多次独立交易才能最大化利润。 只买一次、卖一次的幼稚策略会错失盈利机会。 通过对每个正增长进行求和，实现可以正确捕获所有可用的收益。
