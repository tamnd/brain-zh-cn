 # LeetCode 163 - 缺失范围

 ## 问题理解

 这个问题给了我们三个输入：

 - 已排序的数组`nums`- 下限`lower`- 上限`upper`数组包含唯一的整数，并且数组中的每个数字都在包含范围内`[lower, upper]`。 

我们必须找到该范围内未出现的每个数字`nums`。 我们必须将连续的缺失数字压缩到范围内，而不是单独返回每个缺失的数字。 

例如，如果缺失的数字是：```
2, 4,5,6,7,8,9
```那么输出应该是：```
[[2,2],[4,9]]
```结果必须满足几个条件：

 - 每个缺失的数字必须恰好出现在一个返回范围内
 - 没有号码来自`nums`可能出现在返回的范围内
 - 范围必须排序
 - 表示必须是最小的，这意味着连续缺失的数字被合并在一起

 限制相对较小：

 -`nums.length <= 100`- 值范围为`-10^9`到`10^9`小输入量意味着即使效率较低的解决方案在技术上也可以通过，但该问题旨在测试仔细的区间处理和边缘情况管理。 

一些边缘情况尤其重要：

 -`nums`可以为空
 - 可能没有缺失的号码
 - 缺失的范围可能出现在第一个元素之前
 - 缺失范围可能出现在最后一个元素之后
 - 相邻元素之间可能存在缺失范围
 - 连续数字不应创建范围
 - 单个缺失数字仍必须表示为`[x, x]`因为这些值可以大到`10^9`，我们应该避免在整个数值范围内进行强力迭代。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是迭代每个整数`lower`到`upper`并检查它是否存在于`nums`。 

为了提高会员资格检查的效率，我们可以将所有号码放在`nums`到一个哈希集中。 然后，对于区间内的每个值：

 1.检查是否缺失
 2. 将连续的缺失值分组在一起
 3. 将完整的范围附加到答案中

 这种方法是正确的，因为它明确检查范围内的每个数字并识别所有缺失值。 

然而，当间隔非常大时，这变得不切实际。 之间的区别`upper`和`lower`可以达到`2 * 10^9`，因此迭代整个范围会太慢。 

### 最佳方法

 关键的观察是我们不需要单独检查每个整数。 

自从`nums`已经排序并且是唯一的，缺失的范围只能存在：

 - 第一个数字之前
 - 两个连续数字之间
 - 最后一个数字之后

 我们不需要检查每个值，而只需检查数字之间的差距。 

假设我们当前期望下一个有效数字是`current`。 

当我们遇到一个数字`num`：

- 如果`num > current`，那么区间`[current, num - 1]`失踪了
 - 加工后`num`，下一个期望值变为`num + 1`处理完整个数组后，如果`current <= upper`，则剩余范围`[current, upper]`失踪了。 

这将问题从扫描巨大的数字区间转变为简单地扫描输入数组一次。

 ## 算法演练

 1. 初始化一个空结果列表，用于存储所有缺失的范围。 
2. 创建一个名为`current`并将其设置为等于`lower`。 这个变量代表我们仍然需要考虑的最小数字。 
3. 迭代每个数字`num`在`nums`。 
4. 对于每个`num`，将其与`current`。 
5. 如果`num > current`，那么每个值来自`current`通过`num - 1`失踪了。 添加范围`[current, num - 1]`到结果。 
6. 移动`current`转发至`num + 1`， 因为`num`其本身存在于数组中并且不再需要考虑。 
7. 对中的每个元素继续此过程`nums`。 
8. 循环结束后，末尾可能仍然缺少范围。 如果`current <= upper`, 附加`[current, upper]`。 
9. 返回完成的结果列表。 

### 为什么它有效

 该算法保持了所有小于的数字的不变性`current`已经被正确处理了。 

每当我们遇到一个大于`current`，它们之间的间隙必须完全由缺失的数字组成，因为数组已排序并且包含唯一值。 

通过一次处理一个间隙，我们可以准确地覆盖每个缺失的数字一次，而不会重叠或遗漏。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMissingRanges(
        self,
        nums: List[int],
        lower: int,
        upper: int
    ) -> List[List[int]]:
        
        missing_ranges = []
        current = lower

        for num in nums:
            if num > current:
                missing_ranges.append([current, num - 1])

            current = num + 1

        if current <= upper:
            missing_ranges.append([current, upper])

        return missing_ranges
```实现直接遵循算法。 

变量`missing_ranges`存储最终答案。 

变量`current`跟踪尚未考虑的下一个值。 最初，这是`lower`。 

迭代期间：

 - 如果`num > current`，则存在缺失区间
 - 该间隔立即附加
 - 然后`current`前进到`num + 1`前进至`num + 1`有效是因为`num`其本身存在于数组中，因此不能是缺失范围的一部分。 

处理完所有数字后，我们执行最后一项检查以确定是否仍存在尾随缺失区间`current`和`upper`。 

该算法从不迭代实际的数值范围，这即使在区间大小非常大时也能保持高效。 

## 解决方案```go
func findMissingRanges(nums []int, lower int, upper int) [][]int {
    result := [][]int{}
    current := lower

    for _, num := range nums {
        if num > current {
            result = append(result, []int{current, num - 1})
        }

        current = num + 1
    }

    if current <= upper {
        result = append(result, []int{current, upper})
    }

    return result
}
```Go 实现密切反映了 Python 逻辑。 

结果存储为整数切片的切片，`[][]int`。 

与 Python 不同，Go 区分`nil`切片和空切片，但两者对于 LeetCode 输出都是可接受的。 初始化为`[][]int{}`确保当不存在范围时我们返回一个空切片。 

整数溢出在这里不是问题，因为约束安全地保持在 Go 的标准整数范围内。

 ## 边缘情况

 ### 空输入数组

 当`nums`是空的，从`lower`到`upper`失踪了。 

这种情况很容易破坏假设至少存在一个数组元素的实现。 当前的实现自然地处理它，因为循环永远不会运行，并且最终检查会附加`[lower, upper]`。 

### 没有缺失的数字

 如果区间中的每个值都存在于`nums`，正确的输出是一个空列表。 

一个常见的错误是意外生成无效范围，例如`[x, x - 1]`。 该实现通过仅在以下情况下附加范围来避免这种情况：`num > current`。 

### 末尾缺少范围

 许多实现正确地处理元素之间的间隙，但忘记检查最终数字之后的剩余间隙。 

例如：```
nums = [1,2]
lower = 1
upper = 5
```缺失的范围`[3,5]`循环结束后出现。 最终条件：```
if current <= upper:
```确保正确处理尾随范围。 

### 单个缺失号码

 缺失的范围可能只包含一个数字。 

例如：```
nums = [1,3]
lower = 1
upper = 3
```缺失值是`2`，必须表示为`[2,2]`。 

某些实现错误地将特殊情况的单个值转换为不同的格式。 该解决方案统一处理所有范围，从而保持逻辑简单且正确。
