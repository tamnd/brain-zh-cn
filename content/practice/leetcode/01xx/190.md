[LeetCode 第 190 题](https://leetcode.com/problems/reverse-bits/)

 **难度：** 🟢简单
 **主题：** 分而治之、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们反转 **32 位整数**的二进制表示形式。 我们不是反转数字的十进制数字，而是反转其各个位的顺序。 

例如，假设数字的二进制表示形式为：`00000010100101000001111010011100`将32位全部反转后，变为：`00111001011110000010100101000000`然后将得到的反转二进制值转换回整数并返回。 

一个关键细节是，我们必须始终将输入视为 **32 位值**，即使存在前导零。 通常，二进制数会忽略前导零，但在这个问题中它们很重要，因为反转位会改变它们的位置。 例如，倒车`1`不是`1`，则变为：`00000000000000000000000000000001`→ 反转 →`10000000000000000000000000000000`这会产生一个完全不同的整数。 

输入`n`表示受以下约束的非负整数：

 -`0 <= n <= 2³¹ - 2`-`n`保证是均匀的

 尽管提示提到了一个有符号整数，但实际操作纯粹是对固定 32 位表示形式的位操作。 由于输入范围有界并固定为 32 位，因此我们知道任何有效的解决方案在理想情况下都应该恰好处理 32 个位置。 

预先考虑几个边缘情况很重要。 输入为`0`应该保留`0`因为每一位都是零。 仅具有单个设置位的数字（例如 2 的幂）可以在反转后将该位移动到 32 位表示的另一侧。 具有许多前导零的输入也很重要，因为这些零在反转后会变成尾随零，反之亦然。 最后，由于该问题始终适用于 32 位，因此忘记处理所有 32 位将产生错误的答案。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是首先将数字转换为 32 位二进制字符串，反转该字符串，然后将反转后的二进制表示形式转换回整数。 

例如：

 1. 转换`43261596`为 32 个字符的二进制字符串。 
2. 反转字符串。 
3. 将反转的二进制字符串解析为整数。 

这种方法之所以有效，是因为反转字符串正好反映了所需的位反转操作。 然而，字符串操作会带来不必要的开销。 我们正在解决位操作问题，因此在整数和字符串之间重复转换比直接对位进行操作效率较低且不太优雅。 

由于二进制表示的长度始终为 32，因此暴力方法在实践中仍然以恒定的时间运行。 然而，从概念上讲，它执行额外的转换工作并使用额外的内存。 

### 最佳方法

 关键的见解是我们可以使用**位操作**直接构造反转数。 

我们处理的位`n`从右到左一次一个。 每一步：

 - 提取最低有效位`n`- 将结果左移，为下一位腾出空间
 - 将提取的位添加到结果中
 - 转变`n`继续处理的权利

 为什么这有效？ 

当反转位时，原始数的最低有效位变成结果的最高有效位。 通过重复从右到左取出位并将它们附加到答案的左侧，我们自然地构建了反转的二进制表示。 

由于输入始终恰好是 32 位，因此我们精确地重复此过程**32 次**。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(32) | O(32) | 转换为二进制字符串，反转，再转换回来 |
 | 最佳| O(32) | O(1) | O(1) | 直接使用位运算反转位 |

 尽管两者在技术上都是恒定时间，因为 32 是固定的，但最佳方法是首选，因为它不使用额外的存储空间并演示了正确的位操作。 

## 算法演练

 1. 初始化一个名为`result`到`0`。 当我们增量构建它时，该变量将存储反转的位序列。 
2. 精确迭代 **32 次**。 我们必须始终处理所有 32 位，包括前导零，因为它们会影响最终的反转结果。 
3. 提取最低有效位`n`使用`n & 1`。 按位与运算`1`隔离最右边的位。 
4. 转变`result`使用向左移动一个位置`result << 1`。 这为我们要添加的新位创建了空间。 
5. 将提取的位添加到`result`使用按位或 (`|`）。 这会将当前位插入到正确的位置。 
6. 转变`n`使用向右一个位置`n >> 1`。 这将删除已处理的位并将下一位移动到位。 
7.完成全部32次迭代后，返回`result`。 

这样做的原因是每个提取的位都以相反的顺序附加。 第一个位被删除`n`成为最终答案中位置最高的位。 

## Python 解决方案```python
class Solution:
    def reverseBits(self, n: int) -> int:
        result = 0

        for _ in range(32):
            bit = n & 1
            result = (result << 1) | bit
            n >>= 1

        return result
```实现从初始化开始`result`到`0`，它充当反转数的累加器。 

该循环恰好运行 32 次，因为该问题明确适用于固定的 32 位表示。 在每次迭代期间，我们隔离最右边的位`n`使用`n & 1`。 

下一个，`result`向左移动一位，为新位腾出空间。 然后，我们使用按位或运算插入提取的位。 

最后，`n`向右移动，为下一次迭代做准备。 这将持续下去，直到每一位都被处理完毕。 

到循环结束时，已完全重建并返回反转的 32 位整数。 

## 解决方案```go
func reverseBits(n int) int {
	result := 0

	for i := 0; i < 32; i++ {
		bit := n & 1
		result = (result << 1) | bit
		n >>= 1
	}

	return result
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 整数直接支持按位运算，因此实现仍然简洁。 

一个重要的考虑因素是整数类型。 LeetCode 的原始问题通常使用`uint32`，但是提供的函数签名使用`int`，所以我们严格遵循它。 由于约束保证有效的 32 位非负数，因此移位操作在这里表现得安全。 

与 Python 不同，Go 根据架构具有固定宽度的整数行为，但由于我们仅处理 32 位并保持在有效范围内，因此溢出不是问题。

## 边缘情况

 ### 输入为零

 如果`n = 0`，所有 32 位均为零。 反转它们仍然会导致零。 粗心的实现可能会在数字变为零时提前终止，但我们的实现显式运行 32 次迭代，以确保正确性。 

### 带有单个设置位的数字

 考虑`n = 1`。 

二进制表示：`00000000000000000000000000000001`逆转后：`10000000000000000000000000000000`这说明了为什么处理所有 32 位是至关重要的。 如果我们只处理直到`n == 0`，我们会错误地返回`1`。 

### 带有前导零的数字

 一些数字，例如`8`:`00000000000000000000000000001000`变成：`00010000000000000000000000000000`前导零在此问题中很重要，因为它们会影响反转后的位位置。 我们的固定 32 次迭代循环可确保它们得到正确处理。 

### 最大约束值

 对于接近上限的值，例如`2³¹ - 2`，设置了许多位。 由于该算法仅执行固定大小的位操作 32 次，因此无论有多少位，性能都保持恒定且高效。`1`。 

### 跟进：针对多次调用进行优化

 如果这个函数被调用很多次，我们可以通过使用**memoization on bytes**来优化。 由于一个字节只有`256`可能的值，我们可以预先计算每个 8 位数字的反转版本。 

然后：

 1. 将 32 位整数拆分为 4 个字节。 
2. 使用查找表反转每个字节。 
3. 按相反顺序重新组装。 

这减少了重复计算并使频繁调用的速度显着加快。
