[LeetCode 第 161 题](https://leetcode.com/problems/one-edit-distance/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定两个字符串是否恰好相距一次编辑。 编辑可以是以下三种操作之一：

 1. 插入单个字符
 2.删除单个字符
 3. 用不同的字符替换一个字符

 关键细节是“exactly”这个词。 字符串必须精确地相差一项有效编辑。 如果它们已经相同，则答案是`false`因为需要零编辑。 如果它们因两次或多次编辑而不同，答案也是`false`。 

输入由两个字符串组成，`s`和`t`。 它们的长度范围可以是`0`到`10^4`，因此解决方案必须有效地处理空字符串和相当大的输入。 

输出是一个布尔值：

 - 返回`true`如果一次编辑将一个字符串转换为另一个字符串
 - 返回`false`否则

 这些约束表明有效的线性扫描是合适的。 由于字符串可能很大，因此重复构建修改的字符串或探索所有可能的编辑将不必要地昂贵。 

一些边缘情况尤其重要：

 - 两个字符串都是空的，应该返回`false`- 字符串已经相同，也应该返回`false`- 长度差大于`1`，这立即得出答案`false`- 一个字符串可能为空，而另一个字符串只包含一个字符
 - 不同的字符可能出现在字符串的开头、中间或结尾

 正确的解决方案必须仔细区分替换和插入/删除场景。 

## 方法

 ### 蛮力方法

 强力解决方案将明确尝试所有可能的编辑操作。 

对于替换，我们可以迭代中的每个位置`s`并尝试用每个可能的有效字符替换该字符，然后将结果与`t`。 

对于插入，我们可以在每个可能的位置插入每个可能的字符。 

对于删除，我们可以一次删除每个字符。 

如果任何生成的字符串等于目标字符串，我们返回`true`。 

这种方法是正确的，因为它详尽地检查了每个有效的一次性编辑转换。 然而，它的效率非常低。 每个生成的字符串构造都会花费线性时间，并且有许多可能的修改。 

因为字符串长度可以达到`10^4`，生成和比较大量修改后的字符串会太慢。 

### 最佳两指针方法

 关键的观察是我们不需要显式地模拟所有编辑。 

如果两个字符串恰好相距一次编辑，则：

 - 它们的长度最多相差`1`- 从左到右扫描时最多可以有一个不匹配

 这自然会导致两指针解决方案。 

我们对人物进行一一比较：

 - 如果字符匹配，则两个指针都向前移动
 - 如果它们不同，我们将使用单个允许的编辑

 - 如果长度相等，则将其视为替换件
 - 如果长度不同，则将其视为插入/删除

 使用一次编辑后，字符串的其余部分必须完全匹配。 

这使我们能够在具有恒定额外空间的线性时间内解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × 字母表大小 × n) | O(n) | 显式生成编辑后的字符串 |
 | 最佳| O(n) | O(1) | O(1) | 带两个指针的单次线性扫描 |

 ## 算法演练

 1. 首先，计算长度`s`和`t`。 

如果它们的长度之间的绝对差大于`1`， 返回`false`立即地。 一次编辑无法弥补大于一个字符的差距。 
2. 确保`s`是较短的字符串。 

如果`s`长于`t`，交换它们。 这简化了逻辑，因为我们只需要处理较短字符串的插入，而不是分别处理插入和删除。 
3. 初始化两个指针。 

使用：

-`i`用于遍历`s`-`j`用于遍历`t`4. 将两个字符串一起遍历。 

当两个指针都在边界内时：

 - 如果`s[i] == t[j]`，将两个指针向前移动
 - 否则，我们发现第一个不匹配
 5. 小心处理不匹配的情况。 

第一次不匹配时：

 - 如果字符串具有相同的长度，则这种不匹配必须表示替换，因此将两个指针都向前推进
 - 否则，这种不匹配必须表示插入到较短的字符串中，因此只能前进`j`6. 完成编辑后，验证剩余部分。 

比较剩余的子串：

 -`s[i:]`-`t[j:]`它们必须相同，字符串才能精确地分开一次编辑。 
7、未发现不匹配的情况进行处理。 

如果循环完成且没有不匹配：

 - 仅当字符串的长度完全不同时，字符串才会被单独编辑`1`例如：

-`"abc"`和`"ab"`有效
 -`"abc"`和`"abc"`不是

 ### 为什么它有效

 该算法依赖于这样一个事实：一次编辑最多会在字符串之间产生一个结构分歧。 一旦遇到第一个不匹配，在考虑编辑类型后，其余部分必须完美对齐。 通过区分等长和不等长的情况，该算法可以正确地模拟替换与插入/删除操作。 

## Python 解决方案```python
class Solution:
    def isOneEditDistance(self, s: str, t: str) -> bool:
        m = len(s)
        n = len(t)

        # Length difference greater than 1 is impossible
        if abs(m - n) > 1:
            return False

        # Make sure s is the shorter string
        if m > n:
            return self.isOneEditDistance(t, s)

        i = 0
        j = 0

        while i < m and j < n:
            if s[i] != t[j]:
                # Replacement case
                if m == n:
                    return s[i + 1:] == t[j + 1:]

                # Insertion/deletion case
                return s[i:] == t[j + 1:]

            i += 1
            j += 1

        # No mismatch found
        return m + 1 == n
```实现首先检查长度差是否超过 1。 如果是，则立即返回`False`因为一次编辑无法弥补这样的差距。 

接下来，该函数确保`s`始终是较短的字符串。 这种规范化简化了逻辑，因为我们只需要考虑插入较短的字符串，而不需要单独处理插入和删除。 

两个指针同时遍历字符串。 当字符匹配时，两个指针都会正常前进。 

当发生不匹配时，算法立即确定应用哪种编辑类型：

 - 如果长度相等，则不匹配的部分必须是替换的
 - 否则，它必须是插入到较短的字符串中

 该实现不是手动逐个字符地继续，而是直接比较剩余的后缀。 如果这些后缀匹配，则只需一次编辑即可解释其中的差异。 

如果循环结束时没有任何不匹配，则唯一有效的一次性编辑场景是较长字符串包含一个附加尾随字符时。 

## 解决方案```go

    n := len(t)

    // Length difference greater than 1 is impossible
    if abs(m-n) > 1 {

        i++
        j++
    }

    // No mismatch found
    return m+1 == n

func abs(x int) int {
    if x < 0 {
        return -x
    }
    return x
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置的整数绝对值函数，因此我们定义了一个小辅助函数`abs`。 

对于此用例，Go 中的字符串切片与 Python 切片的工作方式类似，允许在检测到第一个不匹配后进行简洁的后缀比较。 

Go 字符串是基于字节的，但问题约束仅指定字母和数字，因此字节索引在这里是完全安全的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符最多检查一次 |
 | 空间| O(1) | O(1) | 仅使用了少量的指针和变量 |

 该算法对字符串执行单次线性遍历。 尽管后缀比较出现在不匹配处理中，但它们最多只检查一次剩余字符，因此总复杂度保持线性。 

没有分配与输入大小成比例的辅助数据结构，因此空间复杂度是恒定的。

 ## 边缘情况

 ### 两个字符串都是空的

 当`s = ""`和`t = ""`，字符串是相同的。 幼稚的实现可能会错误地返回`true`因为字符串已经相等。 然而，该问题只需要一次编辑，而不是零次编辑。 

该实现正确地处理了这个问题，因为循环完成时没有不匹配，并且最终条件检查长度是否恰好相差一。 

### 长度差大于一

 案例如下：```
s = "abc"
t = "abcde"
```不可能通过一次编辑来解决。 

如果不进行早期长度检查，实现可能会浪费时间扫描字符串或意外地允许多次插入。 

算法立即返回`false`什么时候：```
abs(len(s) - len(t)) > 1
```这可以防止无效案件进一步进行。 

### 最后一个字符不匹配

 考虑：```
s = "abc"
t = "abx"
```字符串匹配直到最终位置。 一些不正确的实现会错误地处理尾随不匹配，因为循环随后立即终止。 

此解决方案正确识别不匹配，识别字符串具有相等的长度，并比较剩余的后缀：```
s[i+1:] == t[j+1:]
```两个后缀都是空字符串，因此替换有效。
