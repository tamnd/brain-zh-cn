[LeetCode 第 191 题](https://leetcode.com/problems/number-of-1-bits/)

 **难度：** 🟢简单
 **主题：** 分而治之、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少位被设置为`1`正整数的二进制表示`n`。 设置位只是一个位，其值为`1`。 

例如，数字`11`二进制为：```
1011
```该二进制表示包含三个`1`位，所以答案是`3`。 

输入是单个正整数。 输出应该是总数`1`以二进制形式写入数字时出现的位。 该量也称为汉明权重。 

约束条件告诉我们：```
1 <= n <= 2^31 - 1
```这意味着输入始终位于 32 位有符号整数范围内。 该值保证为正数，因此我们无需担心此问题中的负数或补码行为。 

尽管约束大小足够小，几种方法都可以有效地工作，但该问题旨在测试对位操作技术的理解。 一种简单的方法是有效的，但是有一种更优雅、更有效的方法可以一次删除一个设置位。 

有几个重要的边缘情况需要记住：

 - 只有一位设置位的数字，例如`128`，应该正确返回`1`。 
- 几乎所有位都已设置的数字，例如`2147483645`，仍应有效处理。 
- 最小的有效输入，`1`，应该返回`1`。 
- 2 的幂是有用的测试用例，因为它们恰好包含一个设置位。 

## 方法

 ### 蛮力方法

 最直接的解决方案是单独检查每个位的位置。 

我们可以使用以下方法重复检查最低有效位：```
n & 1
```如果结果是`1`，然后设置当前位。 检查完当前位后，我们将第一个位置向右移动：```
n >>= 1
```这个过程一直持续到数字变成`0`。 

这种方法是正确的，因为每次迭代都只检查二进制表示的一位。 由于 32 位整数最多有 32 位，因此算法在检查完所有这些位后结束。 

尽管这种方法对于给定的约束来说已经足够快了，但它仍然对每个位位置执行工作，即使当许多位被占用时也是如此。`0`。 

### 最佳方法

 关键的观察结果是表达式：```
n & (n - 1)
```从数字中删除最低设置位。 

例如：```
n      = 101100
n - 1  = 101011
----------------
AND    = 101000
```最右边的`1`消失。 

这意味着我们可以一次重复删除一组位，而不是单独检查每一位。 每一次迭代都直接对应一个`1`数字中的位。 

因此，迭代次数等于设置的位数。 

这更有效，因为运行时间仅取决于有多少`1`位存在，而不是总位数。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(32) 或 O(log n) | O(1) | O(1) | 使用移位单独检查每一位 |
 | 最佳| O(k) | O(1) | O(1) | 每次迭代删除一个设置位，其中 k 是设置位的数量 |

 这里，`k`代表数量`1`二进制表示中的位。 

## 算法演练

 ### 最优算法使用`n & (n - 1)`1. 初始化一个计数器变量为`0`。 

该变量将存储我们找到的设置位的数量。 
2. 继续循环 while`n`大于`0`。 

每次迭代都会从数字中恰好删除一组位。 
3. 在循环内应用：```
n = n & (n - 1)
```该操作清除最右边的设置位`n`。 
4. 增加计数器。 

由于删除了一组位，我们将答案增加了`1`。 
5. 重复直到`n`变成`0`。 

一旦数字变为零，就没有剩余的设置位。 
6. 返回计数器。 

计数器现在等于总数`1`原始数字中的位。 

该算法很优雅，因为它直接将循环计数与设置的位数联系起来。 

## Python 解决方案```python
class Solution:
    def hammingWeight(self, n: int) -> int:
        count = 0

        while n > 0:
            n = n & (n - 1)
            count += 1

        return count
```实现从初始化开始`count`到`0`。 该变量跟踪已删除的设置位数量。 

这`while`循环继续只要`n`不为零。 在循环内部，表达式：```python
n = n & (n - 1)
```从当前数字中删除最低设置位。 

删除设置位后，代码递增`count`因为恰好有一个`1`一点消失了。 

最终，所有设置的位都被删除并且`n`变成`0`。 此时，循环终止并且函数返回总计数。 

该实现简洁、高效，直接体现了位运算的数学特性。 

## 解决方案```go
func hammingWeight(n int) int {
    count := 0

    for n > 0 {
        n = n & (n - 1)
        count++
    }

    return count
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

主要区别在于语法。 Go 使用：```go
count := 0
```用于变量声明并使用`for`循环而不是Python的`while`环形。 

由于该问题保证 32 位范围内的正整数，因此整数溢出在这里不是问题。 该算法仅使用恒定的额外内存，并在计算过程中直接修改输入值。

## 边缘情况

 ### 边缘情况 1：最小有效输入

 考虑：```
n = 1
```二进制表示：```
1
```这是最小的有效输入并且仅包含一个设置位。 该算法正确执行一次迭代，删除该位，然后返回`1`。 

### 边缘情况 2：2 的幂

 考虑：```
n = 128
```二进制表示：```
10000000
```2 的幂恰好包含一个设置位。 这可能会暴露错误实现中的错误，这些错误计算位位置而不是实际设置的位。 这`n & (n - 1)`操作立即将值减少为零，因此实现正确返回`1`。 

### 边缘情况 3：设置所有或几乎所有位

 考虑：```
n = 2147483645
```该数字包含许多设置位。 操作字符串或使用不必要的数据结构的简单实现可能会变得低效。 位操作方法通过每次迭代删除一组位来有效地处理这个问题。 

### 边缘情况 4：具有交替位的数字

 考虑：```
n = 10
```二进制表示：```
1010
```设置的位由零位分隔。 该算法仍然可以正常工作，因为它每次仅删除最右边的设置位，而不管周围的位模式如何。
