[LeetCode 第 112 题](https://leetcode.com/problems/path-sum/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们确定二叉树是否包含至少一个有效的根到叶路径，其节点值总计达到给定的目标总和。 

二叉树由节点组成，其中每个节点可以有一个左子节点和一个右子节点。 每个节点还存储一个整数值。 输入提供树的根节点和一个称为`targetSum`。 

根到叶路径意味着：

 - 路径必须从根节点开始。 
- 路径必须以叶节点结束。 
- 叶节点是没有左子节点和右子节点的节点。 

目标是检查是否存在至少一条这样的路径，其中该路径上所有节点值的总和等于`targetSum`。 

例如，假设树包含路径：```
5 -> 4 -> 11 -> 2
```总和是：```
5 + 4 + 11 + 2 = 22
```如果`targetSum = 22`，那么答案就是`true`。 

一个重要的细节是路径必须以叶子结束。 在到达叶子之前达到目标总和的部分路径不计入在内。 

限制相对较小：

 - 最多 5000 个节点
 - 节点值可以为负数
 - 目标总和也可以为负数

 由于树可以包含负数，因此我们不能依赖诸如“总和变得太大时停止”之类的剪枝策略。 每一条有效路径都必须仔细探索。 

一些边缘情况很重要：

 - 树可能是空的。 在这种情况下，不存在从根到叶的路径，因此答案始终是`false`。 
- 应该返回具有单个节点的树`true`如果节点值等于`targetSum`。 
- 负值可能会导致总和不可预测地增加或减少。 
- 非叶节点处的匹配总和不得被视为成功。 

## 方法

 ### 蛮力方法

 暴力策略将生成树中的每条从根到叶的路径，计算每条路径的总和，然后将结果与`targetSum`。 

一种方法是：

 1.使用DFS遍历探索所有路径。 
2. 将当前路径存储在数组中。 
3. 每当到达叶节点时，计算路径数组的总和。 
4. 检查总和是否等于`targetSum`。 

这是有效的，因为每个可能的根到叶路径都会被检查。 如果任何路径具有所需的总和，则算法返回`true`。 

然而，这种方法效率低下，因为路径和是从头开始为每个叶节点重复重新计算的。 如果树很大，则会发生许多重叠计算。 

### 最佳解决方案的关键见解

 重要的观察是我们不需要存储整个路径或重复重新计算总和。 

相反，在遍历树时，我们可以不断地从剩余的目标总和中减去当前节点的值。 

假设我们当前处于一个具有 value 的节点`x`。 

如果我们还需要剩余的金额`target`，那么在访问这个节点之后我们只需要检查它的子节点之一是否可以提供：```
target - x
```当我们最终到达叶节点时，我们只需检查剩余的总和是否等于叶节点的值。 

这使我们能够使用干净的递归 DFS 遍历来解决问题，无需额外的路径存储。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(N²) | O(H) | 重复重新计算路径总和 |
 | 最优 DFS | O(N) | O(H) | 使用运行剩余总和处理每个节点一次 |

 这里：

-`N`是节点数。 
-`H`是树的高度。 

## 算法演练

 ### 最优深度优先搜索算法

 1、从根节点开始遍历。 

根是每个有效的根到叶路径的起点。 
2. 处理空树箱。 

如果`root`是`None`， 返回`False`立即，因为不存在路径。 
3. 从剩余的目标总和中减去当前节点的值。 

这将问题从：```
"Can this subtree produce targetSum?"
```进入：```
"Can one of the child paths produce the remaining sum?"
```4. 检查当前节点是否为叶子节点。 

如果满足以下条件，则节点是叶子：```
node.left is None and node.right is None
```5. 如果当前节点是叶子节点，则将其值与剩余目标进行比较。 

如果：```
remaining_sum == node.val
```然后我们找到了有效的根到叶路径，所以返回`True`。 
6. 否则，递归地探索左子树和右子树。 

传递更新后的剩余金额：```
targetSum - node.val
```7. 如果任一子树返回`True`，将结果向上传播。 

由于我们只需要一条有效路径，逻辑或就足够了。 
8. 如果两个子树都不包含有效路径，则返回`False`。 

### 为什么它有效

 在每次递归调用时，算法都会保持不变式：```sql
targetSum represents the remaining sum required from the current node to a leaf.
```每个递归步骤都会减去当前节点的值，从而正确减少剩余的要求。 

当到达叶节点时，当叶节点的值与剩余的所需总和匹配时，路径恰好有效。 由于每条从根到叶的路径都会被探索一次，因此算法保证找到一条有效路径（如果存在）。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def hasPathSum(self, root: Optional[TreeNode], targetSum: int) -> bool:
        if root is None:
            return False

        # Check leaf node
        if root.left is None and root.right is None:
            return root.val == targetSum

        remaining_sum = targetSum - root.val

        return (
            self.hasPathSum(root.left, remaining_sum)
            or self.hasPathSum(root.right, remaining_sum)
        )
```实现直接遵循递归DFS策略。 

第一个条件处理空树情况。 由于没有节点，因此不存在根到叶路径。 

接下来，代码检查当前节点是否是叶子。 这就是递归的终止条件。 在叶节点，我们只需将节点值与剩余目标总和进行比较。 

如果该节点不是叶子，则算法从中减去当前节点的值`targetSum`。 这会产生子树所需的剩余总和。 

最后，该函数递归搜索两个子树。 如果任一递归调用返回`True`，整个函数返回`True`。 

实现很简洁，因为递归结构自然地反映了树结构。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func hasPathSum(root *TreeNode, targetSum int) bool {
    if root == nil {
        return false
    }

    // Check leaf node
    if root.Left == nil && root.Right == nil {
        return root.Val == targetSum
    }

    remainingSum := targetSum - root.Val

    return hasPathSum(root.Left, remainingSum) ||
        hasPathSum(root.Right, remainingSum)
}
```Go 实现与 Python 版本几乎相同。 

主要的语言特定差异是使用`nil`而不是`None`。 

Go 还使用指针作为树节点，因此递归调用自然会在子树引用上进行操作。 

整数溢出不是问题，因为约束足够小，可以安全地符合 Go 的标准`int`类型。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | 每个节点最多被访问一次 |
 | 空间| O(H) | 递归调用堆栈最多存储树高度 |

 DFS 遍历只对每个节点处理一次，从而导致时间复杂度为线性。 

空间复杂度来自递归深度。 在倾斜树的最坏情况下，高度可以变为`N`，生产`O(N)`递归栈的使用。 在平衡树中，高度约为`O(log N)`。

 ## 边缘情况

 ### 空树

 一棵空树表示为`root = None`。 这种情况很容易处理不当，因为某些实现可能会错误地处理目标总和`0`作为成功。 

然而，该问题特别需要根到叶的路径，而空树根本不包含任何路径。 

实现立即处理这个问题：```
if root is None:
    return False
```### 到达叶子之前匹配总和

 一个常见的错误是返回`True`一旦运行总和等于目标。 

考虑：```
    1
   /
  2
```如果`targetSum = 1`，根单独与目标匹配，但根不是叶子。 所以，答案一定还是`False`。 

该实现通过仅在到达叶节点时检查总和来避免此错误。 

### 负值

 由于节点值可能为负，因此运行总和可能会不可预测地增加或减少。 

例如：```
-2 -> -3
```产生：```
-5
```当总和变得“太小”或“太大”时停止遍历的错误优化将在此类输入上失败。 

无论中间和如何，该实现都会正确探索所有根到叶路径。
