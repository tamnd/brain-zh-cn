[LeetCode 第 154 题](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array-ii/)

 **难度：** 🔴难
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 这个问题要求我们在已**旋转**的排序数组中找到**最小值**，同时还允许**重复值**。 

旋转排序数组是通过采用升序排序数组并将数组的某些后缀移到前面来创建的。 例如，排序后的数组`[0,1,4,4,5,6,7]`旋转四次变成`[4,5,6,7,0,1,4]`。 尽管顺序看起来被打乱，但数组仍然保留了一个重要的属性：它由**两个已排序的部分**组成，最小的元素标记旋转点。 

由于数组可能包含**重复项**，因此挑战变得更加困难。 在这个问题的简单版本中，没有重复项，二分搜索可以干净地工作，因为比较总是揭示哪一侧包含最小值。 对于重复项，某些比较会变得不明确，因为相等的值可能会隐藏旋转边界。 

输入是一个整数数组`nums`，满足以下保证：

 - 原始数组按升序排序。 
- 它在之间轮换`1`和`n`次。 
- 允许重复值。 
- 数组始终包含至少一个元素。 

预期输出是一个整数，即数组中的**最小元素**。 

这些约束告诉我们一些有用的信息：

 -`1 <= n <= 5000`，意味着数组大小适中。 
-`nums[i]`范围介于`-5000`和`5000`，因此值可能为负数。 
- 由于问题明确要求我们尽可能减少操作数量，因此对于输入大小来说，简单的线性扫描在技术上是可以接受的，但不满足问题的精神。 基于二分搜索的方法是首选。 

有几种重要的边缘情况可能会导致简单的实现失败。 具有所有相同值的数组，例如`[2,2,2,2]`使得无法立即确定哪一侧包含最小值。 未有效旋转的数组，例如`[1,2,3,4]`，仍应返回第一个元素。 一个单元素数组，例如`[7]`也必须正确处理。 另一个微妙的情况是当重复项出现在枢轴附近时，例如`[2,2,2,0,1]`，粗心的二分查找可能会丢弃错误的一半。 

## 方法

 ### 蛮力方法

 最简单的解决方案是从左到右扫描数组并跟踪遇到的最小值。 

因为每个元素都被检查一次，所以这种方法总能找到正确的答案。 由于最小元素必须存在于数组中的某个位置，因此检查所有值可以保证正确性。 

然而，这种方法忽略了数组最初是排序和旋转的事实。 它根本不利用输入的结构，因此与二分搜索可能实现的效果相比效率较低。 

### 最优方法，改进的二分搜索

 关键的观察结果是旋转排序的数组仍然保留足够的排序信息以允许二分搜索。 

在没有重复的普通旋转排序数组中，比较`nums[mid]`和`nums[right]`显示哪一侧包含最小值：

 - 如果`nums[mid] < nums[right]`，最小值在左半部分，包括`mid`。 
- 如果`nums[mid] > nums[right]`，最小值位于右半部分。 

重复使事情变得复杂。 考虑：```
[2,2,2,0,2]
```如果`nums[mid] == nums[right]`，我们无法确定哪一边包含最小值，因为两半仍然有效。 

我们的见解是，当发生相等时，我们可以通过递减来安全地减少搜索空间`right`一个。 即使`nums[right]`是最小值，另一个相同的值仍然存在`mid`，所以我们不会失去答案。 

这种修改后的二分搜索保留了正确性，同时在许多情况下保持对数行为。 然而，在最坏的情况下，大量重复可能会将性能降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描每个元素并跟踪最小值 |
 | 最佳| 平均 O(log n)，最坏 O(n) | O(1) | O(1) | 修改二分查找，重复项可能会强制线性收缩 |

 ## 算法演练

 ### 最优算法

 1.初始化两个指针，`left = 0`和`right = len(nums) - 1`。 

这些指针代表当前搜索范围，其中最小值可能存在。 
2.继续搜索`left < right`。 

一旦两个指针相遇，我们就知道最小元素已被隔离。 
3. 计算中间索引：```
mid = left + (right - left) // 2
```这避免了 Go 或 Java 等语言中的溢出问题，尽管 Python 不需要它。 
4. 比较`nums[mid]`和`nums[right]`。 

如果`nums[mid] < nums[right]`，则对右半部分进行排序，且最小值一定位于左半部分，包括`mid`。 

更新：```
right = mid
```5. 如果`nums[mid] > nums[right]`，那么旋转点必须位于`mid`，这意味着最小值不能为`mid`。 

更新：```
left = mid + 1
```6.如果`nums[mid] == nums[right]`，我们无法确定哪一侧包含最小值，因为重复会产生歧义。 

安全地减少搜索空间：```
right -= 1
```这是有效的，因为删除一个重复项并不能消除唯一出现的最小值。 
7. 当循环结束时，`left == right`，并且该位置包含最小值。 
8、退货：```
nums[left]
```### 为什么它有效

 该算法保持了最小元素始终保持在搜索范围内的不变性`[left, right]`。 

什么时候`nums[mid] < nums[right]`，右侧已排序且较大，因此最小值必须位于`mid`或之前。 什么时候`nums[mid] > nums[right]`，枢轴位于右侧，因此最小值必定存在。 当值相等时，通过删除来缩小范围`right`不会因为其他地方仍然存在相同的候选者而失去最小值。 由于每次迭代间隔都会缩小，因此算法最终收敛到最小元素。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMin(self, nums: List[int]) -> int:
        left = 0
        right = len(nums) - 1

        while left < right:
            mid = left + (right - left) // 2

            if nums[mid] < nums[right]:
                right = mid
            elif nums[mid] > nums[right]:
                left = mid + 1
            else:
                right -= 1

        return nums[left]
```实现首先初始化两个指针，`left`和`right`，表示搜索间隔。 该算法不断缩小这一间隔，直到只剩下一个候选者。 

在循环内部，`mid`被计算为中间索引。 之间的比较`nums[mid]`和`nums[right]`确定搜索空间应如何缩小。 

什么时候`nums[mid] < nums[right]`，右侧已排序，最小值必须位于左侧，包括`mid`， 所以`right = mid`。 

什么时候`nums[mid] > nums[right]`，旋转点必须位于右侧，这意味着最小值不能位于`mid`， 所以`left = mid + 1`。 

当两个值相等时，重复项会阻止我们确定哪一半包含最小值。 在那种情况下，`right -= 1`安全地删除一个重复的候选者。 

最终，`left`和`right`收敛到包含最小值的相同索引。 

## 解决方案```go
func findMin(nums []int) int {
    left := 0
    right := len(nums) - 1

    for left < right {
        mid := left + (right-left)/2

        if nums[mid] < nums[right] {
            right = mid
        } else if nums[mid] > nums[right] {
            left = mid + 1
        } else {
            right--
        }
    }

    return nums[left]
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 由于 Go 切片总是知道它们的长度，因此数组与切片不需要特殊处理。 

中点计算使用：```go
mid := left + (right-left)/2
```这避免了具有固定宽度整数的语言中的整数溢出。 尽管该问题至少保证一个元素，但该实现假定 LeetCode 约束提供的有效输入。

 ## 边缘情况

 ### 单元素数组

 单元素数组，例如`[7]`是一个重要的边缘情况，因为二分搜索循环永远不会执行。 粗心的实现可能会意外地假设至少存在两个元素并导致索引问题。 这个实现很自然地处理它，因为`left == right`立即，并返回单个值。 

### 所有元素都相同

 像这样的输入`[2,2,2,2,2]`特别棘手，因为每次比较都变得模棱两可。 自从`nums[mid] == nums[right]`每次，算法都无法确定哪一半包含最小值，并且必须一次缩小范围。 该实现使用正确处理这个问题`right -= 1`，尽管运行时间降级为`O(n)`。 

### 围绕旋转点重复

 数组就像`[10,10,1,10,10]`很危险，因为重复可能会隐藏枢轴。 如果天真的二分搜索假设相等揭示了排序信息，则可能会错误地丢弃错误的一半。 该实现通过在出现相等值时保守地减小搜索间隔来安全地处理歧义。 

### 已经排序的数组

 一个数组，例如`[1,2,3,4,5]`从技术上讲可能已经轮换了`n`次，导致没有可见的旋转。 一些实现错误地假设枢轴必须存在于中间的某个位置。 这里，二分查找自然收敛到索引`0`，正确返回第一个元素作为最小值。
