[LeetCode 第 125 题](https://leetcode.com/problems/valid-palindrome/)

 **难度：** 🟢简单
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们在应用两次转换后确定给定字符串是否为回文：

 1. 将所有大写字母转换为小写。 
2. 删除所有非字母数字字符。 

字母数字字符是任何英文字母 (`a-z`,`A-Z`) 或数字 (`0-9`）。 应完全忽略空格、标点符号、逗号、冒号和符号等字符。 

预处理之后，我们必须检查得到的字符串向前和向后读取是否相同。 如果是，我们返回`true`; 否则，我们返回`false`。 

例如，输入字符串：```
"A man, a plan, a canal: Panama"
```变成：```
"amanaplanacanalpanama"
```由于该字符串在两个方向上读取相同，因此答案是`true`。 

约束条件很重要：

 - 字符串长度可以大到`2 * 10^5`- 输入仅包含可打印的 ASCII 字符

 由于输入可能非常大，低效的解决方案可能会变得太慢或消耗不必要的内存。 我们应该以线性时间解决方案为目标。 

一些边缘情况值得预先识别。 该字符串可能仅包含标点符号或空格，这意味着过滤结果将变为空字符串。 该问题明确指出空字符串应被视为回文。 输入还可能包含混合的大写和小写字母，需要大小写标准化。 另一个棘手的情况涉及数字，因为数字被视为字母数字字符并且必须参与回文比较。 

## 方法

 ### 蛮力方法

 解决此问题的一个直接方法是首先构建字符串的清理版本。 

我们迭代原始字符串并仅保留字母数字字符，同时将字母转换为小写。 一旦我们有了这个干净的字符串，我们就创建它的反向并比较两个字符串。 

如果清理后的字符串等于其反转，则输入是回文。 

这种方法是正确的，因为预处理与问题定义完全匹配。 但是，它使用额外的内存来构造过滤后的字符串及其反转版本。 

对于非常大的输入，创建字符串的多个副本是不必要的，并且可以避免。 

### 最佳方法的关键见解

 关键的观察是我们实际上不需要构造清理过的字符串。 

相反，我们可以直接在原始字符串上使用**双指针**技术：

 - 一个指针从头开始。 
- 一个指针从末尾开始。 
- 跳过任何非字母数字字符。 
- 将有效字符转换为小写后进行比较。 
- 比较成功后向内移动。 

这是有效的，因为回文本质上是一种对称性检查。 我们只关心镜像位置的匹配字符在标准化后是否相等。 

通过就地处理字符，我们可以避免构建额外的字符串并减少内存使用。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 构建过滤后的字符串并与反转版本进行比较 |
 | 最佳| O(n) | O(1) | O(1) | 两个指针就地处理字符串 |

 ## 算法演练

 1.初始化两个指针，`left`在字符串的开头和`right`在最后。 

这些指针代表我们想要从字符串两端进行比较的字符。 
2. 从左侧跳过非字母数字字符。 

如果`s[left]`不是字母或数字，增量`left`。 由于根据问题陈述这些字符应该被忽略，因此它们不参与回文检查。 
3. 从右侧跳过非字母数字字符。 

同样，如果`s[right]`不是字母数字，递减`right`。 
4. 比较规范化的字符。 

一旦两个指针都定位到有效字符，将它们都转换为小写并进行比较。 

如果不同，立即返回`false`，因为回文需要镜像字符来匹配。 
5. 将两个指针向内移动。 

如果字符匹配，则递增`left`并减少`right`继续检查字符串的剩余部分。 
6. 继续直至指针交叉。 

如果所有有效字符对都匹配，则返回`true`。 

### 为什么它有效

 该算法保持了当前字符之外的每对有效字符的不变性`[left, right]`范围已被验证匹配。 在每一步中，我们都会比较标准化后的下一个有效镜像字符。 如果任何对不同，则该字符串不能是回文。 如果指针交叉而没有发现不匹配，则每个镜像对都匹配，证明该字符串是有效的回文。 

## Python 解决方案```python
class Solution:
    def isPalindrome(self, s: str) -> bool:
        left = 0
        right = len(s) - 1

        while left < right:
            while left < right and not s[left].isalnum():
                left += 1

            while left < right and not s[right].isalnum():
                right -= 1

            if s[left].lower() != s[right].lower():
                return False

            left += 1
            right -= 1

        return True
```实现完全遵循算法。 

我们首先初始化两个指针，`left`和`right`，位于字符串的两端。 主要`while`只要指针没有交叉，循环就会继续。 

在循环内部，我们使用跳过无效字符`isalnum()`，它检查字符是否是字母数字。 这可确保标点符号、空格和符号被忽略。 

将两个指针定位在有效字符上后，我们使用以下方法标准化比较`lower()`。 如果字符不同，我们立即返回`False`。 

如果匹配，则两个指针向内移动以继续检查剩余的子字符串。 

如果循环完成时没有检测到不匹配，则每个相关字符对都匹配成功，因此我们返回`True`。 

## 解决方案```go
import "unicode"

func isPalindrome(s string) bool {
	left := 0
	right := len(s) - 1

	for left < right {
		for left < right && !unicode.IsLetter(rune(s[left])) && !unicode.IsDigit(rune(s[left])) {
			left++
		}

		for left < right && !unicode.IsLetter(rune(s[right])) && !unicode.IsDigit(rune(s[right])) {
			right--
		}

		leftChar := unicode.ToLower(rune(s[left]))
		rightChar := unicode.ToLower(rune(s[right]))

		if leftChar != rightChar {
			return false
		}

		left++
		right--
	}

	return true
}
```Go 实现遵循与 Python 相同的两指针策略。 

一种实现差异是字符处理。 Go 字符串是字节序列，因此可以使用索引来访问各个字符。 由于问题保证了可打印的 ASCII 输入，因此按字节索引是安全的。 

Go 不提供`isalnum()`直接相当于字符串，所以我们使用`unicode.IsLetter()`和`unicode.IsDigit()`以检查有效性。 我们还使用`unicode.ToLower()`用于不区分大小写的比较。 

与Python不同，两者之间没有区别`nil`这里是空字符串，因为输入保证是有效的字符串。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符最多被任一指针 | 访问一次。 
| 空间| O(1) | O(1) | 无论输入大小如何，仅使用几个变量 |

 时间复杂度是线性的，因为每个指针向内移动而不重新访问字符。 尽管存在用于跳过无效字符的嵌套循环，但每个字符最多被跳过一次。 

空间复杂度是恒定的，因为没有分配与输入大小成比例的附加数据结构。

 ## 边缘情况

 ### 仅包含非字母数字字符的字符串

 输入如`"!@#$"`可能会很棘手，因为所有字符都会被忽略。 幼稚的实现可能会意外返回`false`如果它需要至少一个有效字符。 在此解决方案中，两个指针都会跳过无效字符直到它们交叉，并且函数正确返回`true`。 

### 混合大小写字符

 输入如`"RaceCar"`尽管字母大小写不同，但仍应算作回文。 如果没有标准化，`'R'`和`'r'`不会匹配。 该实现通过在比较之前将两个字符转换为小写来解决这个问题。 

### 包含数字的字符串

 数字是回文定义的一部分，不能被忽略。 像这样的输入`"12321"`应该返回`true`， 尽管`"12a21"`应该返回`false`。 由于该实现将字母和数字都视为有效的字母数字字符，因此可以正确处理数字回文。
