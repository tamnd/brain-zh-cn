[LeetCode 609 题](https://leetcode.com/problems/find-duplicate-file-in-system/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个目录描述列表，其中每个字符串代表一个目录以及其中的文件。 每个文件条目包括文件名及其内容。 

例如：```
"root/a 1.txt(abcd) 2.txt(efgh)"
```意思是：

 - 目录路径是`root/a`- 在此目录中：

 -`1.txt`包含`"abcd"`-`2.txt`包含`"efgh"`我们的任务是识别具有相同内容的文件并返回其完整文件路径组。 

重要的细节是重复文件**仅由内容**决定，而不是文件名。 如果名称完全不同或位于不同目录中的两个文件内容匹配，则它们是重复的。 

例如：```
root/a/1.txt -> "abcd"
root/c/3.txt -> "abcd"
```它们属于同一重复组，因为内容相同。 

输出应仅包含至少具有**两个文件**的组，因为具有唯一内容的单个文件不被视为重复。 

这些约束给出了有关规模的有用提示：

 -`paths.length <= 2 * 10^4`- 总输入大小最多为`5 * 10^5`人物。 

这意味着我们应该避免文件之间昂贵的成对比较。 由于字符串操作和哈希映射非常高效，因此基于对文件内容进行分组的方法是合适的。 

一些重要的保证简化了实施：

 - 目录名称是唯一的。 
- 同一目录中的文件永远不会共享相同的名称。 
- 输入格式有效。 
- 每个目录至少包含一个文件。 

重要的边缘情况包括仅包含一个文件的目录、同时存在的多个重复组、所有文件都是唯一的或许多文件共享完全相同的内容。 幼稚的实现可能会意外地包含单例组或错误地解析文件名和内容。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是解析每个文件并将其与其他每个文件进行比较。 

我们首先将所有文件提取到以下列表中：```
(full_path, content)
```然后，对于每个文件，将其内容与其他每个文件进行比较以确定重复项。 

例如：```
[
    ("root/a/1.txt", "abcd"),
    ("root/a/2.txt", "efgh"),
    ("root/c/3.txt", "abcd")
]
```我们比较：

 - 文件 1 与文件 2
 - 文件 1 与文件 3
 - 文件 2 与文件 3

 如果内容匹配，则将它们分组在一起。 

这是有效的，因为最终每对文件都会被检查。 然而，它太慢了。 如果有`n`文件，成对比较需要`O(n²)`比较，这对于大量输入来说变得昂贵。 

### 最优方法，哈希图分组

 关键的见解是重复检测本质上是一个**分组问题**。 

我们可以使用哈希映射，而不是成对比较文件：```
content -> list of file paths
```当我们解析每个文件时：

 1. 提取其内容。 
2. 构建其完整文件路径。 
3. 将路径存储在该内容下的哈希映射中。 

例如：```
{
    "abcd": ["root/a/1.txt", "root/c/3.txt"],
    "efgh": ["root/a/2.txt", "root/c/d/4.txt"]
}
```处理完所有文件后，我们只需收集列表长度大于的值`1`。 

这完全避免了冗余比较。 哈希图插入和查找是`O(1)`平均而言，使解决方案相对于输入大小呈线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × k) | O(n² × k) | O(n) | 比较每个文件对，`k`是平均内容长度 |
 | 最佳| O(S)| O(S)| 哈希图分组，`S`是总输入大小 |

 这里，`S`表示所有输入字符串的字符总数。 

## 算法演练

 ### 最优算法

 1. 创建一个哈希映射，其中：

 - key = 文件内容
 - 值 = 文件路径列表

 这使我们可以立即将具有相同内容的文件分组。 
2. 遍历每个目录字符串`paths`。 
3. 用空格分割字符串。 

第一个标记是目录路径：```
root/a
```其余标记是文件描述：```
1.txt(abcd)
2.txt(efgh)
```4. 对于每个文件描述：

 - 找到索引`'('`- 之前提取文件名`'('`- 提取括号内的内容

 示例：```
"1.txt(abcd)"
```变成：```
filename = "1.txt"
content = "abcd"
```5.构建完整文件路径：```
directory + "/" + filename
```6. 将路径存储在里面：```
content_to_paths[content]
```7. 处理完所有目录后，迭代哈希图。 
8. 仅添加长度大于的组`1`到结果。 
9. 返回最终结果。 

### 为什么它有效

 该算法依赖于这样一个不变量：每个已处理的文件都被准确地放入与其内容相对应的一个存储桶中。 由于重复项仅由相同的内容定义，因此所有重复文件自然会累积在相同的哈希映射条目中。 通过仅返回包含至少两个文件路径的条目，我们保证每个返回的组仅包含重复项，并且不会丢失任何重复文件。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def findDuplicate(self, paths: List[str]) -> List[List[str]]:
        content_to_paths = defaultdict(list)

        for path_info in paths:
            parts = path_info.split(" ")
            directory = parts[0]

            for file_info in parts[1:]:
                left_paren_index = file_info.index("(")

                file_name = file_info[:left_paren_index]
                content = file_info[left_paren_index + 1:-1]

                full_path = f"{directory}/{file_name}"
                content_to_paths[content].append(full_path)

        result = []

        for file_paths in content_to_paths.values():
            if len(file_paths) > 1:
                result.append(file_paths)

        return result
```实现直接遵循算法。 

我们首先创建一个`defaultdict(list)`因此我们可以附加文件路径，而无需手动检查密钥是否已存在。 

对于每个目录字符串，我们用空格分隔。 第一个元素成为目录路径，而其余元素表示文件描述。 

对于每个文件描述，我们找到左括号来分隔文件名和内容。 由于问题保证了有效的格式，因此我们可以安全地对字符串进行切片。 

完整的文件路径是通过连接创建的：```python
directory/file_name
```然后，我们按哈希映射内的内容对路径进行分组。 

最后，我们迭代分组的值，并只保留包含多个文件路径的列表，因为它们代表重复项。 

## 解决方案```go
func findDuplicate(paths []string) [][]string {
	contentToPaths := make(map[string][]string)

	for _, pathInfo := range paths {
		parts := strings.Split(pathInfo, " ")
		directory := parts[0]

		for _, fileInfo := range parts[1:] {
			leftParenIndex := strings.Index(fileInfo, "(")

			fileName := fileInfo[:leftParenIndex]
			content := fileInfo[leftParenIndex+1 : len(fileInfo)-1]

			fullPath := directory + "/" + fileName
			contentToPaths[content] = append(contentToPaths[content], fullPath)
		}
	}

	result := [][]string{}

	for _, filePaths := range contentToPaths {
		if len(filePaths) > 1 {
			result = append(result, filePaths)
		}
	}

	return result
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于 Go 需要显式使用`map[string][]string`而不是`defaultdict`。 附加到不存在的映射键很自然，因为丢失的切片默认为`nil`， 和`append`正确处理它。 

字符串切片也稍微手动一些。 我们使用`strings.Index()`查找左括号并使用索引范围提取子字符串。

 ## 边缘情况

 ### 无重复文件

 一个常见的错误是意外返回仅包含一个文件的组。 例如：```
["root/a 1.txt(abcd)"]
```由于只有一个包含内容的文件`"abcd"`，它不应出现在输出中。 我们的实现使用以下方式显式过滤组：```
if len(file_paths) > 1
```这保证了单例组被排除在外。 

### 多个文件共享相同内容

 当许多文件共享相同的内容时，算法必须正确地将它们全部放在一个组中，而不是创建单独的重复对。 

例子：```
root/a/1.txt(x)
root/b/2.txt(x)
root/c/3.txt(x)
```我们的哈希映射自然会处理这个问题，因为所有路径都附加到相同的内容键。 

### 深度嵌套目录

 目录路径可能包含多个嵌套文件夹：```
root/a/b/c/d
```脆弱的实现可能会错误地重建路径。 我们的解决方案使用以下方式安全地构建文件路径：```
directory + "/" + filename
```无论目录深度如何，它都有效。 

### 多个重复组

 不同的内容值可以各自形成单独的重复组。 有缺陷的实现可能会合并不相关的组。 

例子：```
"a" -> files 1, 2
"b" -> files 3, 4
```由于哈希映射使用文件内容作为密钥，因此不相关的内容保持完全分离，保证了正确的分组。 

## 后续讨论

 在实际的文件系统中，DFS和BFS都可以用于遍历。 DFS 通常是首选，因为它在遍历深层嵌套目录时使用较少的内存，特别是在递归实现或使用显式堆栈实现时。 如果目录包含许多同级文件夹，BFS 可能会消耗大量内存。 

对于非常大的文件内容，直接比较原始内容会变得昂贵。 相反，我们可以首先按文件大小对文件进行分组，因为不同大小的文件不能重复。 然后我们计算具有匹配大小的文件的哈希值，例如 SHA-256。 这可以避免不必要地加载大文件。 

如果文件只能读入`1 KB`块，我们在流式传输文件时增量计算哈希。 现代哈希函数支持分块更新，因此不需要将整个文件加载到内存中。 

在修改后的大文件解决方案中，最耗时的部分变成了磁盘I/O和哈希，而不是遍历。 由于文件是流式传输而不是完全加载，因此内存使用率得到改善。 为了减少误报，尤其是哈希冲突的误报，我们可以在共享相同哈希的文件之间执行最终的逐字节比较，然后再声明它们重复。
