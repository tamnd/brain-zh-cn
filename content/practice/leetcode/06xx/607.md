[LeetCode 607 题](https://leetcode.com/problems/sales-person/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们查找**从未处理过名为该公司的订单的所有销售人员的姓名`"RED"`**。 

我们得到三个数据库表：

 -`SalesPerson`包含每个销售人员的信息，包括他们独特的`sales_id`和`name`。 
-`Company`包含公司信息，包括`com_id`和公司`name`。 
-`Orders`记录每个订单，链接销售人员（`sales_id`）到一家公司（`com_id`）。 

关键的关系是订单将销售人员和公司联系起来。 我们的目标是找出**未出现在涉及公司的任何订单中的销售人员`"RED"`**。 

换句话说，我们需要：

 1. 找到关联的公司ID`"RED"`。 
2. 确定哪些销售人员已向该公司下了订单。 
3. 返回 ID **不**属于该集合的每个销售人员。 

输出应仅包含一列：```
name
```代表所有合格的销售人员。 结果的顺序并不重要。 

由于这是一个标记为 **Easy** 的数据库问题，因此效率限制通常并不严格。 然而，我们仍然应该避免不必要的昂贵操作。 这些表可能包含许多行，因此重复扫描每个销售人员的订单可能会变得低效。 

需要考虑一些重要的边缘情况：

 - 如果`"RED"`**没有订单**，那么每个销售人员都应该被退回。 
- 如果`"RED"`不存在于`Company`表中，所有销售人员也应该返回，因为没有人可以接受不存在的公司的订单。 
- 销售人员可能有不同公司的许多订单。 如果**甚至一个**订单与`"RED"`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是单独检查每个销售人员。 

对于每个销售人员，我们都会扫描`Orders`表以查看他们是否有任何订单连接到`"RED"`公司。 为此，我们首先确定`com_id`为了`"RED"`从`Company`桌子。 

然后，对于每个销售人员：

 1. 迭代所有订单。 
2. 检查订单是否属于两者：

 - 现任销售人员，以及
 - 的`"RED"`公司。 
3. 如果存在这样的订单，则排除该销售人员。 
4. 否则，将它们包含在结果中。 

这种方法是正确的，因为每个销售人员都根据每个相关订单进行明确验证。 然而，它通过执行不必要的重复扫描`Orders`表，使其对于较大的数据集效率低下。 

### 最佳方法

 关键的观察结果是，我们**不需要**需要重复检查每个销售人员的订单。 

相反，我们可以首先计算**确实销售给的销售人员集合`"RED"`**，然后将它们从最终结果中排除。 

在 SQL 中，这很自然地使用子查询来表达：

 - 首先，找到`sales_id`与订单相关的`"RED"`。 
- 然后，选择所有销售人员姓名`sales_id`**不在**该集合中。 

这种方法避免了重复工作，既干净又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(S × O) | O(1) | O(1) | 检查每个销售人员的每个订单 |
 | 最佳| O(S + O + C) | O(O)| 计算排除的销售人员一次 |

 在哪里：

-`S`= 销售人员数量
 -`O`= 订单数量
 -`C`= 公司数量

 ## 算法演练

 最优的 SQL 算法如下：

 1. 首先，确定公司名称为`"RED"`。 

我们查询的是`Company`表并检索匹配的`com_id`。 由于公司名称在此问题的上下文中是唯一的，因此这为我们提供了匹配订单所需的标识符。 
2. 接下来，查找所有有订单的销售人员`"RED"`。 

我们检查`Orders`表并收集每个`sales_id`谁`com_id`对应于`"RED"`。 
3. 从概念上讲，将这些销售人员 ID 存储为排除集。 

出现在该组中的任何销售人员不得出现在最终结果中。 
4.最后扫描`SalesPerson`桌子。 

仅返回那些行`sales_id`**不是**排除集的一部分。 

### 为什么它有效

 正确性来自于将销售人员分为两组：

 - 至少有一份订单的人`"RED"`- 那些不这样做的人

 子查询精确地标识了第一组。 通过选择 ID 不在该组中的销售人员，我们保证每个返回的销售人员从未向`"RED"`，而每个被排除在外的销售人员都有。 

## Python 解决方案

 LeetCode 数据库问题使用 **SQL**，但为了满足请求的语言格式，下面的 Python 部分将 SQL 查询包含为字符串。```python
class Solution:
    def salesPerson(self) -> str:
        return """
        SELECT name
        FROM SalesPerson
        WHERE sales_id NOT IN (
            SELECT o.sales_id
            FROM Orders o
            JOIN Company c
                ON o.com_id = c.com_id
            WHERE c.name = 'RED'
        );
        """
```该实现使用一个`NOT IN`子查询。 

内部查询连接`Orders`和`Company`所以我们可以识别与相关的订单`"RED"`。 从这些订单中，我们收集相关信息`sales_id`是。 
外部查询扫描`SalesPerson`表并过滤掉 ID 出现在子查询结果中的所有销售人员。 

由于 SQL 可以有效地处理集合成员资格，因此该解决方案简洁且易于理解。

```Go 版本在功能上与 Python 版本相同，因为实际的解决方案是 SQL。 这里不存在特定于语言的问题，例如切片、整数溢出或 nil 处理。 主要逻辑完全位于 SQL 查询中。 

## SQL 解决方案```sql
SELECT name
FROM SalesPerson
WHERE sales_id NOT IN (
    SELECT o.sales_id
    FROM Orders o
    JOIN Company c
        ON o.com_id = c.com_id
    WHERE c.name = 'RED'
);
```另一种解决方案使用`LEFT JOIN`带过滤：```sql
SELECT s.name
FROM SalesPerson s
LEFT JOIN Orders o
    ON s.sales_id = o.sales_id
LEFT JOIN Company c
    ON o.com_id = c.com_id
    AND c.name = 'RED'
WHERE c.com_id IS NULL;
```这`NOT IN`对于这个问题，版本通常更简单并且更容易推理。

 ## 边缘情况

 一种重要的边缘情况发生时`"RED"`公司存在，但**没有订单**。 如果假设每个公司都出现在中，则幼稚的实现可能会错误地返回空结果`Orders`。 这`NOT IN`子查询可以正确处理这个问题，因为内部查询变为空，这意味着每个销售人员都有资格。 

另一个重要的情况是当销售人员有多个公司的订单时，包括`"RED"`。 有缺陷的实施可能只检查销售人员是否有非 RED 销售，并错误地将其包含在内。 我们的查询通过排除任何人来避免这种情况`sales_id`在红色顺序中至少出现一次。 

最后的边缘情况发生时`"RED"`公司不存在于`Company`。 在这种情况下，子查询不会生成任何行，并且会返回每个销售人员。 这种行为是正确的，因为任何销售人员都不可能向一家不存在的公司销售产品。
