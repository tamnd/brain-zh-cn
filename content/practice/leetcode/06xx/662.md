[LeetCode 662 题](https://leetcode.com/problems/maximum-width-of-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们计算二叉树所有层之间的最大宽度。 重要的细节是宽度不仅仅是某一层非空节点的数量。 相反，宽度必须包括如果树表示为完整二叉树时可能存在的缺失节点的位置。 

在完全二叉树中，每个节点都有一个概念上的位置索引。 如果一个节点有索引`i`，那么：

 - 它的左孩子将有索引`2 * i`- 它的右子节点将有索引`2 * i + 1`即使有些孩子失踪了，他们的位置对于计算宽度仍然很重要。 

例如，考虑这个级别：```
5, 3, null, 9
```虽然实际节点只有三个，但最左边节点之间的距离（`5`）和最右边的节点（`9`）跨越完整二叉树表示中的四个位置。 因此，宽度为`4`。 

输入是二叉树的根节点。 输出是一个整数，表示所有级别的最大宽度。 

约束条件相对较小，最多`3000`节点。 这意味着`O(n)`或者`O(n log n)`解决方案绰绰有余。 然而，有一个重要的实施细节涉及头寸指数。 如果我们在每个级别上连续加倍索引，那么对于深树来说，值可能会变得非常大。 尽管最终答案适合 32 位有符号整数，但如果我们不小心，中间索引可能会变大。 

一些边缘情况很重要：

 - 只有一个节点的树应该返回宽度`1`- 倾斜的树仍然有宽度`1`在各个层面
 - 节点之间间隙较大的稀疏树可以产生较大的宽度
 - 如果索引未标准化，深树可能会导致索引溢出

 ## 方法

 ### 蛮力方法

 一个天真的想法是逐级显式构建完整的二叉树表示，包括空占位符。 在每个级别，我们可以存储每个节点位置，包括丢失的节点，然后测量第一个和最后一个非空节点之间的距离。 

这种方法之所以有效，是因为它直接对问题定义进行建模。 然而，它变得非常低效，因为占位符空节点的数量随着树深度呈指数增长。 深度稀疏树`h`可能需要存储最多`2^h`职位。 

尽管实际的节点数最多只有`3000`，概念完整树可以变得更大。 因此，显式表示丢失的节点是浪费且不必要的。 

### 最佳方法

 关键的见解是我们不需要显式存储丢失的节点。 我们只需要他们的概念立场。 

我们可以逐级执行广度优先搜索，同时为每个节点分配一个完整的二叉树索引：

 - 根获取索引`0`- 左边的孩子得到`2 * index`- 右孩子得到`2 * index + 1`在每个级别：

 - 第一个节点的索引给出左边界
 - 最后一个节点的索引给出了正确的边界
 - 宽度变为：```
last_index - first_index + 1
```为了防止指数变得过大，我们通过减去该级别的第一个指数来标准化每个级别的指数。 这可以使数字保持较小，同时保持相对距离。 

这给出了一个干净的`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^h) | O(2^h) | O(2^h) | O(2^h) | 在完整的树表示中显式存储空位置 |
 | 最佳| O(n) | O(n) | 具有概念指数和水平标准化的 BFS |

 ## 算法演练

 1. 使用队列启动广度优先搜索。 
2. 将节点及其概念索引存储在队列中。 开始于：

 -`root`在索引处`0`3. 一次处理树​​一层。 

- 每次迭代开始时的队列大小告诉我们有多少节点属于当前级别。 
4. 记录级别中的第一个索引。 

- 这成为标准化基础。 
- 从级别中的每个索引中减去它可以防止大整数增长。 
5. 对于当前级别的每个节点：

 - 将其从队列中删除
 - 标准化其索引
 - 添加具有计算索引的子项：

 - 左孩子：`2 * normalized_index`- 右孩子：`2 * normalized_index + 1`6. 跟踪以下各项的标准化指数：

 - 关卡中的第一个节点
 - 关卡中的最后一个节点
 7. 计算宽度：```
width = last_index - first_index + 1
```8. 更新全局最大宽度。 
9. 继续，直到队列变空。 

### 为什么它有效

 该算法之所以有效，是因为分配的索引与节点在完整二叉树中占据的位置完全匹配。 因此，最左边和最右边索引之间的差异捕获了它们之间的所有间隙，包括丢失的节点。 

标准化索引不会影响宽度，因为从所有位置减去相同的值可以保留相对距离。 

## Python 解决方案```python
from collections import deque
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def widthOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0

        max_width = 0
        queue = deque([(root, 0)])

        while queue:
            level_size = len(queue)
            level_start_index = queue[0][1]

            first_index = 0
            last_index = 0

            for i in range(level_size):
                node, index = queue.popleft()

                normalized_index = index - level_start_index

                if i == 0:
                    first_index = normalized_index

                if i == level_size - 1:
                    last_index = normalized_index

                if node.left:
                    queue.append((node.left, 2 * normalized_index))

                if node.right:
                    queue.append((node.right, 2 * normalized_index + 1))

            current_width = last_index - first_index + 1
            max_width = max(max_width, current_width)

        return max_width
```该实现从标准 BFS 队列开始。 每个队列条目都存储节点及其概念索引。 

在每个级别开始时，最左边的索引记录为`level_start_index`。 通过减去该值来标准化该级别中的每个节点索引。 这可以防止不必要的整数增长，同时保留位置关系。 

该算法跟踪级别中的第一个和最后一个标准化索引。 它们的差加一就是宽度。 

使用完全二叉树索引规则插入子项。 由于 BFS 逐级处理节点，因此每个级别的宽度都是独立且正确计算的。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

type Pair struct {
	node  *TreeNode
	index int
}

func widthOfBinaryTree(root *TreeNode) int {
	if root == nil {
		return 0
	}

	queue := []Pair{{root, 0}}
	maxWidth := 0

	for len(queue) > 0 {
		levelSize := len(queue)
		levelStartIndex := queue[0].index

		firstIndex := 0
		lastIndex := 0

		for i := 0; i < levelSize; i++ {
			pair := queue[0]
			queue = queue[1:]

			node := pair.node
			normalizedIndex := pair.index - levelStartIndex

			if i == 0 {
				firstIndex = normalizedIndex
			}

			if i == levelSize-1 {
				lastIndex = normalizedIndex
			}

			if node.Left != nil {
				queue = append(queue, Pair{
					node:  node.Left,
					index: 2 * normalizedIndex,
				})
			}

			if node.Right != nil {
				queue = append(queue, Pair{
					node:  node.Right,
					index: 2*normalizedIndex + 1,
				})
			}
		}

		currentWidth := lastIndex - firstIndex + 1

		if currentWidth > maxWidth {
			maxWidth = currentWidth
		}
	}

	return maxWidth
}
```Go 实现遵循与 Python 版本相同的 BFS 策略。 由于 Go 没有元组，因此有一个自定义`Pair`struct 将节点和索引存储在一起。 

Go 使用`nil`缺少子指针而不是 Python 的`None`。 队列是使用切片实现的，通过切片操作从前面删除元素。 

索引规范化在 Go 中特别有用，因为否则整数溢出可能会成为非常深的树中的问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 队列可以存储整个树级别 |

 BFS 遍历每个节点一次，使得总运行时间与节点数量呈线性关系。 队列最多可以包含树最宽层中的所有节点，在最坏的情况下与`n`。

 ## 边缘情况

 ### 单节点树

 仅包含根节点的树是最小可能的有效输入。 有错误的实现可能会错误地返回`0`如果宽度初始化处理不当。 此实现正确处理根级别并返回宽度`1`。 

### 高度倾斜的树

 每个节点只有左子节点或只有右子节点具有宽度的树`1`在各个层面。 一些实现错误地将增加的位置索引解释为增加的宽度。 由于该算法从同一级别的第一个和最后一个节点计算宽度，因此倾斜树可以正确生成宽度`1`。 

### 稀疏的树木，间隙较大

 最重要的边缘情况是稀疏树，其中节点在概念上相距很远。 例如：```
        1
      /   \
     2     3
    /       \
   4         5
```底层只有两个节点，但它们的概念位置跨越四个槽。 简单的节点计数解决方案会错误地返回`2`。 位置索引方法正确计算空间隙并返回`4`。 

### 深树和整数增长

 由于子索引在每个级别都会加倍，因此深树可以产生非常大的数字。 尽管 Python 整数可以增长任意大，但其他语言可能会溢出。 该实现通过标准化每个级别的索引、保持较小的数字并保持节点之间的距离来避免此问题。
