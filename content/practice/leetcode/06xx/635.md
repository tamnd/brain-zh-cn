 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、设计、有序集

 ## 解决方案

 ## 问题理解

 问题是要求我们设计一个支持两种主要操作的日志存储系统：存储具有唯一ID和时间戳的日志，以及基于时间戳范围和粒度检索日志。 每个时间戳都表示为以下格式的字符串`YYYY:MM:DD:HH:MM:SS`，它是零填充的并保证字典顺序与时间顺序对齐。 

这`put`操作只是存储一个日志及其 ID 和时间戳。 这`retrieve`操作更加细致：给定开始时间戳、结束时间戳和粒度，我们必须返回时间戳落在包含范围内的所有日志 ID，仅考虑时间戳到指定粒度的部分。 例如，如果粒度是`Day`，我们忽略`Hour`,`Minute`， 和`Second`比较时间戳时。 

这些约束确保日志和操作的数量适中（最多 500 个），因此我们不需要对海量数据集进行极端优化。 每个 ID 都是唯一的，年份在 2000 年到 2017 年之间，并且时间戳格式良好。 边缘情况包括使用最大粒度查询与日志时间戳完全匹配的范围`Year`，或最小粒度`Second`，以及有效范围边缘的时间戳。 

## 方法

 暴力方法将日志存储在一个简单的列表中`(id, timestamp)`对。 为了进行检索，我们迭代整个列表，根据粒度对时间戳进行切片，并包含落在该范围内的 ID。 这是正确的，因为我们可以在切片后直接按字典顺序比较时间戳字符串，但如果日志数量变大，效率就会很低，因为检索会扫描所有条目。 

优化的关键见解是时间戳可以以其字符串形式自然地按字典顺序排序，并且不同粒度级别的数量是固定的且很小。 因此，我们可以维护一个简单的列表，并对时间戳进行切片以进行粒度比较。 由于限制，不需要像树或索引这样更复杂的结构。 这里的优化是最小的，但在利用时间戳字符串的字典属性的同时确保了正确性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次检索 O(n) | O(n) | 将所有日志存储在列表中； 比较查询时的每个时间戳 |
 | 最佳| 每次检索 O(n) | O(n) | 由于限制较小，与暴力破解相同，但字典顺序字符串切片确保了正确性和简单性 |

 ## 算法演练

 1. 初始化`LogSystem`具有空列表的对象来存储日志。 
2. 在`put(id, timestamp)`，追加元组`(id, timestamp)`到列表中。 
3. 在`retrieve(start, end, granularity)`，将每个粒度映射到时间戳字符串中对应的索引：`Year`→ 4,`Month`→ 7,`Day`→ 10,`Hour`→ 13，`Minute`→ 16,`Second`→ 19。 
4.切片`start`和`end`根据粒度索引的时间戳。 这有效地忽略了时间戳中不太重要的部分。 
5. 迭代所有存储的日志并类似地对它们的时间戳进行切片。 如果分片日志时间戳落在分片范围内`start`和`end`时间戳（含），将日志ID添加到结果列表中。 
6. 返回符合条件的ID列表。 

工作原理：零填充时间戳的字典顺序属性可确保字符串比较正确反映时间顺序。 通过根据粒度对时间戳进行切片，我们可以有效地截断不太重要的单元并将日志包含在请求的范围内。 这保证了正确性，而无需复杂的数据结构。 

## Python 解决方案```python
from typing import List

class LogSystem:

    def __init__(self):
        self.logs = []
        self.granularity_index = {
            "Year": 4,
            "Month": 7,
            "Day": 10,
            "Hour": 13,
            "Minute": 16,
            "Second": 19
        }

    def put(self, id: int, timestamp: str) -> None:
        self.logs.append((id, timestamp))

    def retrieve(self, start: str, end: str, granularity: str) -> List[int]:
        idx = self.granularity_index[granularity]
        start_slice, end_slice = start[:idx], end[:idx]
        result = []
        for log_id, timestamp in self.logs:
            ts_slice = timestamp[:idx]
            if start_slice <= ts_slice <= end_slice:
                result.append(log_id)
        return result
```Python 实现使用列表来存储日志，并使用字典将粒度映射到正确的切片索引。 这`retrieve`方法对查询时间戳和日志时间戳进行切片，并按字典顺序对它们进行比较，如果 ID 落在指定范围内，则将 ID 附加到结果列表中。 

## 解决方案```go
type LogSystem struct {
	logs             [][2]string
	granularityIndex map[string]int
}

func Constructor() LogSystem {
	return LogSystem{
		logs: make([][2]string, 0),
		granularityIndex: map[string]int{
			"Year":  4,
			"Month": 7,
			"Day":   10,
			"Hour":  13,
			"Minute": 16,
			"Second": 19,
		},
	}
}

func (this *LogSystem) Put(id int, timestamp string) {
	this.logs = append(this.logs, [2]string{fmt.Sprint(id), timestamp})
}

func (this *LogSystem) Retrieve(start string, end string, granularity string) []int {
	idx := this.granularityIndex[granularity]
	startSlice := start[:idx]
	endSlice := end[:idx]
	result := []int{}
	for _, log := range this.logs {
		tsSlice := log[1][:idx]
		if startSlice <= tsSlice && tsSlice <= endSlice {
			id, _ := strconv.Atoi(log[0])
			result = append(result, id)
		}
	}
	return result
}
```在 Go 中，我们将日志存储为切片`[2]string`用于保存 ID 和时间戳的对。 我们使用字符串切片进行时间戳比较，在附加到结果切片时将 ID 转换回整数，并维护粒度索引以确保一致性。 

## 工作示例

 示例1：

 1.`put(1, "2017:01:01:23:59:59")`→ 日志 =`[(1, "2017:01:01:23:59:59")]`2.`put(2, "2017:01:01:22:59:59")`→ 日志 =`[(1, ...), (2, ...)]`3.`put(3, "2016:01:01:00:00:00")`→ 日志 =`[(1, ...), (2, ...), (3, ...)]`4.`retrieve("2016:01:01:01:01:01", "2017:01:01:23:00:00", "Year")`切片为“2016”和“2017”，所有日志都在此范围内，结果 =`[3, 2, 1]`。 
5.`retrieve("2016:01:01:01:01:01", "2017:01:01:23:00:00", "Hour")`切片为“2016:01:01:01”和“2017:01:01:23”。 只有日志 2 和 1 在此范围内，结果 =`[2, 1]`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每次检索 O(n) | 我们迭代每个检索调用的所有存储日志 |
 | 空间| O(n) | 将所有日志存储在列表中； 最坏情况下结果列表可能存储所有ID |

 复杂度是可以接受的，因为 n ≤ 500。由于字符串是固定长度的，所以切片时间戳和比较字符串都是 O(1) 操作。
