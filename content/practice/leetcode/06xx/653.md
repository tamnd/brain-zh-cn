 # LeetCode 653, Two Sum IV - Input is a BST

 ## 问题理解

 这个问题给了我们二叉搜索树（BST）的根和一个整数`k`。 我们必须确定树中是否有两个不同的节点，其值之和为`k`。 

输入是 BST，这意味着树满足 BST 排序属性：

 - 左子树中的每个节点的值都小于当前节点。 
- 右子树中的每个节点都有比当前节点更大的值。 

尽管该树是 BST，但该问题并不要求我们返回实际的数字对。 我们只需要返回一个布尔值：

 -`true`如果存在这样的一对
 -`false`否则

 例如，考虑树：```
    5
   / \
  3   6
 / \   \
2   4   7
```如果`k = 9`，这对`(2, 7)`存在，所以答案是`true`。 

如果`k = 28`，不存在两个节点的和等于`28`，所以答案是`false`。 

约束条件很重要：

 - 树最多可以包含`10^4`节点。 
- 节点值可以为负数。 
- BST保证有效。 

由于树可能相当大，低效的二次解可能会变得太慢。 我们应该寻求接近线性时间的解决方案。 

需要考虑一些重要的边缘情况：

 - 只有一个节点的树永远无法形成有效的对。 
- 有效对可能包含负数。 
- 同一节点不能使用两次。 
- 匹配对可能出现在树的完全不同的分支中。 
- 标准 BST 中通常不存在重复值，但我们的逻辑仍应正确确保需要两个单独的节点。 

## 方法

 ### 蛮力方法

 最直接的方法是使用树遍历将所有节点值收集到列表中，然后检查每个可能的对。 

我们可以执行 DFS 或 BFS 遍历来将所有值提取到数组中。 之后，我们使用两个嵌套循环：

 - 外循环选择第一个数字。 
- 内循环选择第二个数字。 
- 对于每一对，我们检查它们的总和是否等于`k`。 

这种方法是正确的，因为它明确地测试了每对可能的节点。 如果存在有效的对，最终会找到它。 

然而，这种方法效率低下。 和`n`节点，大约有`n² / 2`配对进行检查。 为了`10^4`节点，这变得太昂贵了。 

### 最佳方法

 关键的观察是，这个问题本质上是应用于树的经典“二和”问题。 

在标准的二和问题中，我们迭代数字，同时将之前看到的值存储在哈希集中。 对于每个当前值`x`，我们检查是否`k - x`已经被看到了。 

完全相同的想法在这里也适用。 

我们使用 DFS 或 BFS 来遍历 BST。 遍历过程中：

 - 对于当前节点值`x`- 计算`target = k - x`- 检查是否`target`哈希集中已存在
 - 如果是，我们找到两个数字，其总和为`k`- 否则，添加`x`到集合并继续遍历

 这将时间复杂度从二次降低到线性，因为哈希集查找大约是`O(1)`。 

即使输入是 BST，我们实际上并不需要此解决方案特定于 BST 的排序属性。 我们只需遍历每个节点一次即可。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 存储所有值，然后测试每对 |
 | 最佳| O(n) | O(n) | 使用哈希集查找进行 DFS 遍历 |

 ## 算法演练

 ### 最优DFS+哈希集算法

 1. 创建一个名为的空哈希集`seen`。 

该集合存储我们在遍历期间已经访问过的值。 哈希集提供恒定时间平均查找，这使得补码检查高效。 
2. 从根开始DFS遍历。 

我们可以使用递归或显式堆栈。 对于树问题，递归 DFS 简单而自然。 
3. 对于当前节点，计算补集。 

如果当前节点值为`x`，那么我们需要的值为：$\text{complement} = k - x$4. 检查哈希集中是否已存在补码。 

如果是，那么我们之前访问过另一个节点，其值加上当前值等于`k`。 我们立即返回`True`。 
5. 否则，将当前节点值添加到哈希集中。 

这使得当前值可以作为未来节点的潜在补充。 
6. 递归遍历左子树。 

如果左子树返回`True`，立即向上传播结果。 
7. 递归遍历右子树。 

如果右子树返回`True`，立即向上传播结果。 
8. 如果遍历完成后没有找到有效的对，则返回`False`。 

### 为什么它有效

 该算法保持一个不变量：

 - 在处理节点之前，哈希集恰好包含先前访问过的节点的值。 

对于每个节点值`x`，我们检查是否`k - x`已存在于先前访问过的值中。 如果是，则两个不同的节点之和为`k`。 

由于每个节点都被访问一次，因此每个可能的对都以补码形式被考虑一次。 因此，该算法可以正确检测是否存在有效对。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, Set

class Solution:
    def findTarget(self, root: Optional[TreeNode], k: int) -> bool:
        seen: Set[int] = set()

        def dfs(node: Optional[TreeNode]) -> bool:
            if not node:
                return False

            complement = k - node.val

            if complement in seen:
                return True

            seen.add(node.val)

            return dfs(node.left) or dfs(node.right)

        return dfs(root)
```该实现首先创建一个名为的哈希集`seen`。 该集合存储遍历过程中遇到的所有节点值。 

嵌套的`dfs`函数执行递归深度优先遍历。 底壳手柄`None`通过返回节点`False`。 

对于每个节点，代码计算补集`k - node.val`。 如果这个补集已经存在于哈希集中，我们立即返回`True`因为已经找到了有效的对。 

如果不存在匹配，则将当前节点值插入到集合中，以便将来的节点可以将其用作补集候选。 

最后，该函数递归地探索两个子树。 逻辑的运用`or`确保一旦找到有效的对就提前终止。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func findTarget(root *TreeNode, k int) bool {
    seen := make(map[int]bool)

    var dfs func(node *TreeNode) bool

    dfs = func(node *TreeNode) bool {
        if node == nil {
            return false
        }

        complement := k - node.Val

        if seen[complement] {
            return true
        }

        seen[node.Val] = true

        return dfs(node.Left) || dfs(node.Right)
    }

    return dfs(root)
}
```Go 解决方案遵循与 Python 版本相同的算法结构。 

而不是Python的`set`, Go 使用`map[int]bool`模拟哈希集。 

Nil 检查取代了 Python 的检查`None`检查。 递归 DFS 是使用函数变量声明来实现的，因为 Go 要求在赋值之前声明递归匿名函数。 

整数溢出在这里不是一个问题，因为与 Go 的整数范围相比，问题约束很小。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 哈希集可以存储所有节点值 |

 遍历最多触及每个节点一次，并且每个哈希集查找或插入平均花费恒定时间。 因此，总时间复杂度是线性的。 

空间复杂度也是线性的，因为在最坏的情况下，哈希集存储每个节点值。 此外，递归 DFS 可能会使用最多`O(h)`调用堆栈空间，其中`h`是树的高度。 在倾斜树的最坏情况下，这变成`O(n)`。

 ## 边缘情况

 ### 单节点树

 一棵只包含一个节点的树不可能包含两个不同的元素，其总和等于`k`。 

有缺陷的实现可能会意外地允许同一节点被重复使用两次。 例如，如果节点值为`5`和`k = 10`，不正确的算法可能会错误地返回`True`。 

此实现避免了该问题，因为它在将当前节点插入哈希集中之前检查补集。 因此，同一节点无法与自身匹配。 

### 负值

 树可能包含负数，并且目标`k`也可能是负数。 

一些不正确的实现假设所有值都是正数，或者以破坏负数的方式依赖 BST 排序。 

哈希集方法对所有整数统一工作，因为它仅依赖于补码算术和哈希查找。 

### 倾斜的树

 BST 可能会变得完全倾斜，本质上表现为链表。 

例如：```
1
 \
  2
   \
    3
     \
      4
```这将创建等于节点数的递归深度。 

该算法仍然可以正常工作，因为 DFS 可以自然地处理任意树形状。 然而，在最坏情况的树中，递归深度可能会变大。 在给定的约束下，这种递归解决方案对于 LeetCode 来说仍然是可以接受的。
