 ## 解决方案

 ## 问题理解

 LeetCode 669，修剪二叉搜索树，要求我们修改二叉搜索树，使每个剩余节点的值都在包含范围内`[low, high]`。 

输入由三部分组成：

 -`root`，有效二叉搜索树的根节点
 -`low`, 最小允许值
 -`high`，最大允许值

 二叉搜索树（通常缩写为 BST）具有重要的排序属性：

 - 左子树中的每个值都小于当前节点
 - 右子树中的每个值都大于当前节点

 目标是删除值超出允许区间的每个节点。 但是，我们不可以随意重建树。 其余节点的相对结构必须保持完整。 如果一个节点在修剪过程中幸存下来，则其所有幸存的后代仍必须以相同的相对排列出现在该节点下方。 

返回的结果是修剪后的树的根。 一个微妙但重要的细节是原始根本身可能会被移除。 在这种情况下，它的后代之一成为新的根。 

这些约束告诉我们一些有用的信息：

 - 树最多可以包含`10^4`节点足够大，应避免低效的重复遍历。 
- 所有节点值都是唯一的。 
- 输入树保证已经满足 BST 排序规则。 
- 边界满足`low <= high`。 

BST 保证是实现高效解决方案的关键观察。 如果没有它，我们将需要更仔细地检查每个子树，因为节点排序不会提供任何修剪机会。 

一些边缘情况尤其重要：

 - 根本身可能超出有效范围。 
- 每个节点都可能被删除。 
- 没有节点可能需要删除。 
- 一个节点在修剪后只能有一个有效的子树。 
- 在某些语言中，深度倾斜的树可能会产生递归深度问题。 

在不考虑 BST 结构的情况下删除节点的简单实现可能会意外断开有效的后代或违反原始的父子关系。 

## 方法

 暴力解决方案将遍历整个树并重建一个仅包含该范围内的值的全新 BST。 一种方法是：

 1. 对原树进行遍历。 
2. 收集每个值`[low, high]`。 
3. 将这些值插入到新的 BST 中。 

这种方法最终会生成有效的修剪树，但它不会保留原始结构。 该问题明确要求后代保持相同的相对排列。 从头开始重建树可以完全改变树的形状。 

另一种暴力变体将递归地检查每个节点并手动重新连接子树，而不使用 BST 排序属性。 这工作正常，但它仍然探索许多不必要的分支，因为它将结构视为任意二叉树。 

最佳解决方案的关键见解直接来自 BST 排序属性。 

假设我们当前正在检查一个节点：

 - 如果`node.val < low`，那么整个左子树也必须小于`low`，因为左子树中的每个值都小于当前节点。 因此，整个左子树可以立即丢弃。 
- 如果`node.val > high`，那么整个右子树也必须大于`high`，所以整个右子树也可以立即丢弃。 
- 如果当前节点位于范围内，则该节点应该保留，并且我们递归地修剪两个子节点。 

这种修剪行为使递归解决方案变得优雅且高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 遍历所有节点并可能重建树或存储额外的值 |
 | 最佳 | O(n) | O(h) | 使用 BST 排序有效修剪无效子树 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 从当前节点开始，最初是树的根。 
2. 如果当前节点是`None`， 返回`None`。 

这是递归基本情况。 空子树在修剪后仍然为空。 
3. 检查当前节点的值是否小于`low`。 

如果是，则当前节点及其整个左子树都必须无效，因为所有左子树值都更小。 因此，我们丢弃当前节点并仅递归处理右子树。 
4. 检查当前节点的值是否大于`high`。 

如果是，则当前节点及其整个右子树都必须无效，因为所有右子树值都更大。 因此，我们丢弃当前节点并仅递归处理左子树。 
5. 如果当前节点在有效范围内，则保留。 

我们现在递归地修剪两个孩子：

 - 将左子树的修剪结果赋值给`node.left`- 将右子树的修剪结果赋值给`node.right`6. 子节点更新后返回当前节点。 

此时，以此节点为根的子树满足修剪要求。 

### 为什么它有效

 正确性依赖于 BST 排序不变量。 

每当一个节点小于`low`，其左子树中的每个节点也保证小于`low`，因此删除整个左子树总是安全的。 类似地，每当一个节点大于`high`，其右子树中的每个节点都保证也大于`high`。 

对于有效范围内的节点，递归地修剪子节点可确保每个剩余的后代也位于该范围内。 由于该算法仅删除无效节点并通过递归返回重新连接有效后代，因此保留了幸存节点的原始相对结构。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def trimBST(
        self,
        root: Optional[TreeNode],
        low: int,
        high: int
    ) -> Optional[TreeNode]:

        if root is None:
            return None

        if root.val < low:
            return self.trimBST(root.right, low, high)

        if root.val > high:
            return self.trimBST(root.left, low, high)

        root.left = self.trimBST(root.left, low, high)
        root.right = self.trimBST(root.right, low, high)

        return root
```实现直接遵循递归策略。 

第一个条件处理基本情况。 如果子树为空，则没有任何可修剪的内容，因此函数返回`None`。 

接下来的两个条件实现 BST 剪枝。 

什么时候`root.val < low`，当前节点及其左子树中的每个节点都保证是无效的。 唯一可能的有效节点必须存在于右子树中，因此该函数递归修剪并返回`root.right`。 

什么时候`root.val > high`，相反的推理适用。 当前节点及其右子树中的每个节点都无效，因此函数递归修剪并返回`root.left`。 

如果当前节点位于有效范围内，我们保留该节点并递归修剪两个子节点。 递归调用更新`root.left`和`root.right`直接删除无效的后代。 

最后，返回当前节点作为修剪后的子树的根。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func trimBST(root *TreeNode, low int, high int) *TreeNode {
    if root == nil {
        return nil
    }

    if root.Val < low {
        return trimBST(root.Right, low, high)
    }

    if root.Val > high {
        return trimBST(root.Left, low, high)
    }

    root.Left = trimBST(root.Left, low, high)
    root.Right = trimBST(root.Right, low, high)

    return root
}
```Go 实现在结构上与 Python 版本相同。 

主要区别在于 Go 使用指针和`nil`而不是 Python 参考文献和`None`。 递归调用返回`*TreeNode`指针，它们被分配回`Left`和`Right`。 

不需要特殊的整数溢出处理，因为节点值很小并且比较很简单。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点最多被访问一次 |
 | 空间| O(h) | 递归调用堆栈取决于树的高度 |

 该算法处理每个节点一次。 每个递归调用要么立即删除子树，要么继续修剪有效分支。 由于没有重新访问节点，因此总运行时间与节点数量呈线性关系。 

辅助空间复杂度来自递归深度。 在平衡 BST 中，高度为`O(log n)`。 在最坏的情况下，完全倾斜的树的高度`O(n)`。

 ## 边缘情况

 当根本身超出有效范围时，就会出现一种重要的边缘情况。 幼稚的实现可能会错误地保留原始根或断开有效的后代。 在此解决方案中，当根值小于`low`，算法立即返回修剪后的右子树。 同样，当根值大于`high`，它返回修剪后的左子树。 这自然会将有效的后代提升到新的根位置。 

另一个关键情况是必须丢弃整个子树。 因为这是一个 BST，如果一个节点太小，那么它的左子树中的每个节点也太小。 一些不正确的解决方案仍然递归地处理无效的子树，浪费工作或引入重新连接错误。 此实现完全安全地跳过这些子树。 

第三个重要的边缘情况是高度不平衡的树，例如链表形状的 BST。 如果不仔细实现递归，递归树算法有时可能会在深层结构上失败。 该解决方案仍然可以正常工作，因为每个递归调用只处理一个子树并返回一个有效的修剪子树。 唯一的后果是递归深度可能达到`O(n)`在最坏的情况下。 

当根本不需要修剪时，就会出现最终的微妙边缘情况。 某些实现会意外地重建节点或不必要地更改子引用。 在该方案中，直接保留有效范围内的节点，并且仅递归更新其子节点，因此原始结构保持不变。
