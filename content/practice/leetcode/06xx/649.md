[LeetCode 第 649 题](https://leetcode.com/problems/dota2-senate/)

 **难度：** 🟡 中等
 **主题：** 字符串、贪婪、队列

 ## 解决方案

 ## 问题理解

 该问题描述了 Dota2 参议院中两党之间的轮流投票过程，代表为 Radiant 党`'R'`以及以可怕党为代表的`'D'`。 

我们得到一个字符串`senate`其中每个字符代表一位参议员及其党派关系。 字符串中的字符顺序很重要，因为参议员在每轮中从左到右按顺序行事。 

每个活跃参议员都有两种可能的行动：

 1. 禁止一名反对的参议员，使被禁止的参议员失去所有未来的投票权。 
2. 如果所有剩余的活跃参议员都属于同一政党，则宣布胜利。 

这个过程循环重复，直到一方完全消除另一方的行动能力。 

关键细节是每位参议员都为自己的政党采取最佳行动。 这意味着每位参议员总是会选择最大化其政党获胜机会的行动。 实际上，这意味着参议员将尽可能战略性地禁止对手。 

输入大小可以大到`10^4`，它足够大，以至于使用昂贵的操作（例如从字符串中删除字符或扫描下一个活跃参议员）重复模拟参议院可能会变得低效。 

预期输出很简单：

 -`"Radiant"`如果光辉党最终获胜
 -`"Dire"`如果可怕的一方最终获胜

 尽早识别一些边缘情况很重要：

 - 只有一名参议员的参议院，例如`"R"`或者`"D"`，立即导致该方获胜。 
- 交替模式，例如`"RDRDRD"`创建多轮交互并测试模拟是否正确保留顺序。 
- 像这样的大块`"RRRRDDDD"`测试算法是否有效处理重复禁令。 
- 一方获得早期位置优势的情况至关重要，因为在一轮中较早采取行动通常会决定获胜者。 

该问题保证每个字符都是`'R'`或者`'D'`，因此除了算法本身之外不需要输入验证。 

## 方法

 ### 暴力模拟

 一种直接的方法是完全按照所描述的方式模拟该过程。 

我们可以维护一个活跃参议员的列表，并从左到右重复处理它们。 当参议员采取行动时，他们会寻找下一个可用的对手并禁止他们。 被禁止的参议员将在未来几轮中被跳过。 

这种方法在概念上很简单，因为它直接反映了规则。 然而，它变得低效，因为找到下一个有效对手可能需要重复扫描列表。 罢免参议员或将其标记为不活跃也会带来开销。 

在最坏的情况下，每个参议员可能会在多轮中重复扫描几乎整个参议院名单。 这会导致二次时间复杂度或更糟。 

尽管强力模拟产生了正确的结果，但对于接近上限的较大输入来说，速度太慢。 

### 基于队列的最优贪婪模拟

 关键的见解是，唯一重要的是参议员行动的相对顺序。 

我们可以使用队列来跟踪双方活跃参议员的位置，而不是显式模拟回合并删除参议员。 

这个想法是这样的：

 - 将所有 Radiant 参议员的索引存储在一个队列中。 
- 将所有 Dire 参议员的索引存储在另一个队列中。 
- 比较每个队列中的前参议员。 
- 指数较小的参议员首先行动，因为他们在本轮中出现较早。 
- 该参议员禁止对方参议员。 
- 幸存的参议员被重新添加到带有索引的队列中`current_index + n`，代表参与下一轮。 

这有效地保留了轮流顺序，而无需重复重建参议院状态。 

贪婪的观察是，尽早行动总是最佳的，因为禁止对手会阻止他们采取行动。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复扫描、禁止操作|
 | 最佳| O(n) | O(n) | 队列模拟有效保持排序 |

 ## 算法演练

 1. 创建两个队列，一个用于光辉参议员，一个用于暗夜参议员。 

每个队列存储该政党参议员的索引。 例如，对于`"RDD"`，辐射队列开始为`[0]`Dire 队列开始为`[1, 2]`。 
2. 遍历一次输入字符串。 

对于每个角色：

 - 如果角色是`'R'`，将其索引添加到 Radiant 队列中。 
- 如果角色是`'D'`，将其索引添加到 Dire 队列中。 

此预处理步骤将参议员按政党分开，同时保留其原始顺序。 
3. 当两个队列都非空时开始模拟回合。 

只要双方仍有活跃参议员，投票过程就会继续。 
4. 从两个队列中删除前面的参议员。 

这些是各党派下一批活跃的参议员。 

- 较小的指数首先行动，因为参议员按顺序行动。 
- 首先行动的参议员禁止对方参议员。 
5. 将幸存的参议员重新插入队列。 

假设参议院长度为`n`。 

- 如果光辉参议员首先采取行动，请附加`radiant_index + n`到辐射队列。 
- 如果可怕的参议员首先采取行动，请附加`dire_index + n`到可怕的队列。 

添加`n`模拟该参议员在所有当前参议员轮流结束后再次参与下一轮。 
6. 重复此操作，直到一个队列变空。 

如果光辉队列变空，则夜魇获胜。 

如果可怕队列变空，则辐射获胜。 

### 为什么它有效

 该算法保持了队列始终代表各方正确的未来行动顺序的不变性。 

在每一步中，指数较小的参议员首先采取行动，并在对方参议员采取行动之前禁止他们。 重新添加幸存参议员的索引`index + n`正确地将它们放置在未来回合顺序的末尾。 

因为每个参议员总是从立即禁止下一个可用对手中受益，所以贪婪的选择是最优的。 最终，一方彻底消除了另一方的行动能力。 

## Python 解决方案```python
from collections import deque

class Solution:
    def predictPartyVictory(self, senate: str) -> str:
        n = len(senate)

        radiant_queue = deque()
        dire_queue = deque()

        for index, senator in enumerate(senate):
            if senator == 'R':
                radiant_queue.append(index)
            else:
                dire_queue.append(index)

        while radiant_queue and dire_queue:
            radiant_index = radiant_queue.popleft()
            dire_index = dire_queue.popleft()

            if radiant_index < dire_index:
                radiant_queue.append(radiant_index + n)
            else:
                dire_queue.append(dire_index + n)

        return "Radiant" if radiant_queue else "Dire"
```实施从导入开始`deque`从`collections`模块，因为队列需要从前端高效移除。 使用常规的 Python 列表会使前面的删除变得昂贵。 

变量`n`存储参议院长度。 稍后在将幸存的参议员重新插入未来的轮次时将使用该值。 

第一个循环处理一次参议院字符串并将参议员索引分配到适当的队列中。 这保留了原始的回合顺序。 

当双方仍有活跃参议员时，主要模拟循环仍在继续。 

循环内部：

 - 每个队列中的前参议员被删除。 
- 比较它们的指数。 
- 指数较小的参议员先行动并生存。 
- 幸存的参议员被重新插入索引`+ n`，将它们放入下一个循环周期。 

一旦一个队列变空，剩下的一方就被宣布为获胜者。 

## 解决方案```go
func predictPartyVictory(senate string) string {
	n := len(senate)

	radiantQueue := []int{}
	direQueue := []int{}

	for i, senator := range senate {
		if senator == 'R' {
			radiantQueue = append(radiantQueue, i)
		} else {
			direQueue = append(direQueue, i)
		}
	}

	for len(radiantQueue) > 0 && len(direQueue) > 0 {
		radiantIndex := radiantQueue[0]
		direIndex := direQueue[0]

		radiantQueue = radiantQueue[1:]
		direQueue = direQueue[1:]

		if radiantIndex < direIndex {
			radiantQueue = append(radiantQueue, radiantIndex+n)
		} else {
			direQueue = append(direQueue, direIndex+n)
		}
	}

	if len(radiantQueue) > 0 {
		return "Radiant"
	}

	return "Dire"
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于Go标准库中没有内置的双端队列结构，因此切片被用作队列。 通过索引访问前面的元素`0`，并且使用切片重新分配来模拟移除`queue = queue[1:]`。 

整数溢出不是问题，因为最大参议院大小仅为`10^4`，并且指数在模拟过程中线性增长。 

Go 字符串可以作为符文进行迭代，但由于输入仅包含 ASCII 字符`'R'`和`'D'`，直接比较是安全的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个参议员进入和离开队列的次数有限 |
 | 空间| O(n) | 队列存储参议员索引 |

 该算法是线性的，因为每个参议员都通过队列操作进行处理，每个操作都需要恒定的时间。 

尽管参议员可以多次重新插入，但每次迭代都会永久删除一名反对的参议员。 由于只有`n`参议员总数，迭代总数的界限为`n`。 

空间复杂度也是线性的，因为两个队列一起最多存储`n`指数。

 ## 边缘情况

 一种重要的边缘情况是参议院仅包含一名参议员，例如`"R"`或者`"D"`。 幼稚的实现可能仍会尝试模拟回合或在禁止操作后访问空队列。 基于队列的解决方案可以自然地处理这一问题，因为一个队列立即开始为空，因此算法会在不进入模拟循环的情况下终止。 

另一个重要的情况是当所有参议员都属于同一政党时，例如`"RRRR"`或者`"DDDD"`。 某些实现错误地假设双方始终都在场。 在此解决方案中，一个队列在初始化后仍为空，因此获胜者会立即返回。 

交替图案如`"RDRDRDRD"`是错误的另一个常见来源，因为它们需要仔细维护多轮的回合顺序。 如果索引未正确重新插入`index + n`，参议员可能会以错误的顺序行事。 队列方法通过将参议院视为循环结构来保留准确的未来排序。 

一个更微妙的边缘情况涉及位置优势。 考虑`"RDD"`。 尽管双方几乎平衡，但早期的可怕参议员最终因为回合顺序动态而获得了控制权。 仅比较聚会规模的基于计数的简单解决方案在这里会失败。 队列模拟正确地模拟了早期行动通常比拥有相同数量更重要。
