[LeetCode 第 677 题](https://leetcode.com/problems/map-sum-pairs/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、设计、Trie

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个自定义数据结构，其行为类似于从字符串到整数的映射，同时还支持高效的基于前缀的求和查询。 

有两种操作：

 1.`insert(key, val)`此操作存储带有整数值的字符串键。 如果键已经存在，则必须用新值替换其旧值。 
2.`sum(prefix)`此操作返回键以给定前缀开头的所有值的总和。 

例如，如果我们插入：

 -`"apple" -> 3`-`"app" -> 2`然后打电话`sum("ap")`应该返回`5`，因为两者`"apple"`和`"app"`开始于`"ap"`。 

重要的细节是密钥可以被覆盖。 如果`"apple"`之前已分配`3`并后来更新为`5`，未来的前缀和必须反映新值，而不是将两个值相加。 

限制相对较小：

 - 密钥和前缀长度最多为`50`- 至多`50`总运营

 尽管输入大小足够小，可以通过更简单的解决方案，但问题从根本上测试了对基于前缀的数据结构的理解，尤其是尝试。 

一些重要的观察结果和边缘情况立即脱颖而出：

 - 密钥可能会被插入多次，因此我们必须正确处理更新。 
- 前缀可能匹配零个键，在这种情况下答案应该是`0`。 
- 前缀本身可以是完整的键，同时也可以匹配更长的键。 
- 键仅由小写英文字母组成，这使得基于 trie 的实现变得简单。 
- 前缀查询可能会严重重叠，因此在问题的大规模版本中重复重新计算总和可能会变得低效。 

## 方法

 ### 蛮力方法

 最简单的解决方案是将每个键值对存储在哈希映射中。 

为了`insert`，我们只需更新字典条目：```
map[key] = val
```为了`sum(prefix)`，我们迭代字典中的每个键并检查该键是否以给定的前缀开头。 如果是，我们将其值添加到结果中。 

这是有效的，因为在前缀查询期间显式检查每个存储的键，从而保证正确性。 

然而，缺点是每`sum`操作需要扫描所有按键。 如果键的数量变大，重复的前缀查询就会变得昂贵。 

### 最优方法，带有前缀和的 Trie

 关键的见解是前缀查询自然地与特里树（也称为前缀树）对齐。 

trie 逐个字符存储字符串。 每个节点代表一个前缀。 例如：```
root
 └── a
      └── p
           └── p
                └── l
                     └── e
```如果我们在每个 trie 节点存储通过该节点的所有键的总和，那么回答前缀查询就会变得非常高效。 

例如：

 - 代表的节点`"ap"`存储以以下开头的所有单词的总价值`"ap"`。 
- 代表的节点`"app"`存储以以下开头的所有单词的总价值`"app"`。 

然后：

-`insert`沿遍历路径更新总和
 -`sum(prefix)`只需走到前缀节点并返回其存储的总数

 棘手的部分是正确处理更新。 由于密钥可以被覆盖，我们必须计算差异：```
delta = new_value - old_value
```然后我们将此增量添加到键路径上的每个 trie 节点。 

如果不进行此调整，重复插入同一键将错误地累积值。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 插入：O(1)，求和：O(N × L) | O(N × L) | 扫描每个前缀查询的所有键 |
 | 最优特里树 | 插入：O(L)，求和：O(L) | O(N × L) | 将前缀和直接存储在 trie 节点中 |

 在哪里：

-`N`= 钥匙数量
 -`L`= 最大字符串长度

 ## 算法演练

 ### 最优 Trie 算法

 1. 创建trie节点结构。 

每个节点存储：

 - 子节点的字典
 - 运行前缀和

 前缀总和表示通过该节点的所有键的总值。 
2. 为精确的键值维护一个单独的哈希映射。 

这是必要的，因为密钥可以更新。 当再次插入一个键时，我们需要知道它之前的值。 
3.期间`insert(key, val)`，计算值差。 

如果密钥已经存在：```
delta = val - old_value
```否则：```
delta = val
```4. 更新哈希图中存储的键值。 

这可确保将来的更新使用最新值。 
5. 逐个字符地遍历 trie。 

对于每个字符：

 - 如果子节点不存在则创建
 - 移动到子节点
 - 添加`delta`到该节点的前缀和

 这会将值更改传播到每个相关前缀。 
6.期间`sum(prefix)`，使用前缀字符遍历 trie。 

如果在任何时候字符路径不存在，则返回`0`。 
7. 到达最终前缀节点后，返回其存储的前缀和。 

由于每次插入都正确更新了该节点，因此存储的总和已经代表了答案。 

### 为什么它有效

 trie 维护每个节点存储的总和等于共享该前缀的所有键的总值的不变式。 

插入键时，我们仅传播值的变化，而不是整个值。 这保证了即使密钥被多次覆盖，更新也保持准确。 

因此，当我们到达某个前缀对应的节点时，它存储的和正是所有匹配键的总和。 

## Python 解决方案```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.prefix_sum = 0

class MapSum:

    def __init__(self):
        self.root = TrieNode()
        self.values = {}

    def insert(self, key: str, val: int) -> None:
        old_value = self.values.get(key, 0)
        delta = val - old_value

        self.values[key] = val

        current = self.root

        for char in key:
            if char not in current.children:
                current.children[char] = TrieNode()

            current = current.children[char]
            current.prefix_sum += delta

    def sum(self, prefix: str) -> int:
        current = self.root

        for char in prefix:
            if char not in current.children:
                return 0

            current = current.children[char]

        return current.prefix_sum

# Your MapSum object will be instantiated and called as such:
# obj = MapSum()
# obj.insert(key, val)
# param_2 = obj.sum(prefix)
```实施开始于`TrieNode`班级。 每个节点包含：

 -`children`，将字符映射到子节点
 -`prefix_sum`，存储共享该前缀的所有键的总和

 里面`MapSum`，我们维持：

 -`root`, 真根
 -`values`，存储每个键的最新值的字典

 的`insert`方法首先检索键的旧值。 这很重要，因为该问题允许覆盖现有密钥。 

我们计算：```python
delta = new_value - old_value
```该增量表示所有相关前缀和应更改的量。 

当我们遍历特里树时，我们创建缺失的节点并添加`delta`到每个节点的`prefix_sum`。 

这`sum`方法只是使用前缀字符沿着 trie 遍历。 如果路径存在，则最终节点已包含所需的总数。 

## 解决方案```go
package main

type TrieNode struct {
	children  map[byte]*TrieNode
	prefixSum int
}

type MapSum struct {
	root   *TrieNode
	values map[string]int
}

func Constructor() MapSum {
	return MapSum{
		root: &TrieNode{
			children: make(map[byte]*TrieNode),
		},
		values: make(map[string]int),
	}
}

func (this *MapSum) Insert(key string, val int) {
	oldValue := this.values[key]
	delta := val - oldValue

	this.values[key] = val

	current := this.root

	for i := 0; i < len(key); i++ {
		char := key[i]

		if _, exists := current.children[char]; !exists {
			current.children[char] = &TrieNode{
				children: make(map[byte]*TrieNode),
			}
		}

		current = current.children[char]
		current.prefixSum += delta
	}
}

func (this *MapSum) Sum(prefix string) int {
	current := this.root

	for i := 0; i < len(prefix); i++ {
		char := prefix[i]

		if _, exists := current.children[char]; !exists {
			return 0
		}

		current = current.children[char]
	}

	return current.prefixSum
}

/**
 * Your MapSum object will be instantiated and called as such:
 * obj := Constructor()
 * obj.Insert(key, val)
 * param_2 := obj.Sum(prefix)
 */
```Go 实现遵循与 Python 版本相同的逻辑。 

一些特定于 Go 的细节值得注意：

 - Trie 孩子存储为`map[byte]*TrieNode`因为输入只包含小写英文字母。 
- 地图必须使用初始化`make`。 
- 访问 Go 映射中缺失的键会返回零值，这可以方便地给出`0`对于不存在的先前键值。 
- trie 节点使用指针以避免不必要的复制。

 ## 边缘情况

 一种重要的边缘情况是重新插入具有不同值的相同密钥。 幼稚的实现可能只是再次添加新值，导致前缀总和随着时间的推移而膨胀。 例如，插入`"apple"`和`3`后来与`5`应导致总贡献`5`， 不是`8`。 该实现通过存储先前的值并仅使用旧值和新值之间的差异来更新特里树总和来处理此问题。 

另一个重要的情况发生在查询 trie 中不存在的前缀时。 在遍历过程中，算法可能会在完成前缀之前遇到丢失的子节点。 在这种情况下，执行立即返回`0`，因为没有存储的密钥可以共享不存在的前缀路径。 

当一个键本身是另一个键的前缀时，就会发生第三种微妙的边缘情况。 例如：```
"app"
"apple"
```两者都应有助于`sum("app")`。 trie 自然地处理这个问题，因为每个节点存储所有后代键的累积和，而不仅仅是以该节点结尾的键。 

最后的边缘情况涉及非常短的键和前缀，尤其是长度`1`。 由于遍历逻辑无论字符串长度如何都逐个字符地工作，因此单字符输入的处理方式与较长的字符串相同，无需任何特殊情况代码。
