 **主题：** 数组、堆栈、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们模拟一个具有一组不寻常规则的棒球计分系统。 我们从一个空的分数记录开始，并逐一处理一系列操作。 每个操作要么添加一个新分数，要么修改以前记录的分数的历史记录。 

输入是一个字符串数组，称为`operations`。 每个字符串代表要执行的一个操作。 有四种可能的操作类型：

 - 数字字符串，例如`"5"`或者`"-2"`意味着我们用该值记录一个新分数。 
-`"+"`意味着我们创建一个新分数，等于前两个有效分数的总和。 
-`"D"`意味着我们创建一个新分数，等于之前有效分数的两倍。 
-`"C"`意味着我们无效并删除之前的有效分数。 

重要的细节是，每个操作都会影响当前有效分数的记录。 未来的运营取决于这段不断演变的历史。 例如，当我们看到`"+"`，我们不对最后两个输入操作求和，而是对当前记录中的最后两个有效分数求和。 

最后，我们返回记录中剩余的所有有效分数的总和。 

约束条件告诉我们`operations.length`最多可以是`1000`，相对较小。 这意味着即使是效率较低的方法仍然可以在限制范围内舒适地运行。 然而，问题的根本在于维护动态历史记录，因此选择正确的数据结构可以使实现简洁直观。 

该问题还保证所有操作都是有效的。 这意味着：

-`"+"`始终至少有两个先前的有效分数。 
-`"D"`和`"C"`始终至少有一个先前的有效分数。 
- 中间结果适合 32 位整数。 

这些保证简化了实现，因为我们不需要对无效操作或空历史记录进行防御性检查。 

有几种边缘情况值得预先考虑。 一条记录可能会在一段时间后变空`"C"`操作，例如`["1", "C"]`。 负数可能会出现，应该正确处理，尤其是`"D"`和`"+"`。 多个连续的特殊操作，例如`"D"`其次是`"+"`可以对新添加的值创建依赖关系，因此我们必须始终使用最新的有效状态。 

## 方法

 ### 蛮力方法

 解决此问题的一种直接方法是，每当操作依赖于先前的分数时，就重复重建当前的分数记录。 

例如，在每次操作之后，我们可以重新计算整个分数的总和或重复遍历列表以确定最后的有效条目。 如果我们使用基本数组并在遇到任何情况时从头开始重新计算信息`"+"`,`"D"`， 或者`"C"`，我们仍然得到了正确的结果，因为我们忠实地模拟了规则。 

这种方法之所以有效，是因为每个操作仅依赖于先前处理的操作，并且重新计算状态可以保证正确性。 然而，反复重新计算总数或遍历历史会带来不必要的重复工作。 

例如，如果在每次插入或删除后我们重新计算整个记录的总和，则在最坏的情况下总运行时间将变为二次。 

### 最佳解决方案的关键见解

 关键的观察是这个问题自然地表现得像一个堆栈。 

我们只与最新的有效分数进行交互：

 -`"C"`删除最近的分数。 
-`"D"`使用最新的分数。 
-`"+"`使用两个最近的分数。 

这种后进先出的行为与堆栈完美匹配。 

我们维护一堆有效分数。 当我们处理每个操作时：

 - 数字被压入堆栈。 
-`"C"`弹出顶部值。 
-`"D"`将最高值推至两倍。 
-`"+"`压入前两个值的总和。 

最后，我们对堆栈求和。 

这避免了重新计算并在恒定时间内处理每个操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复重新计算分数状态或总计 |
 | 最佳 | O(n) | O(n) | 使用堆栈高效维护分数历史 |

 ## 算法演练

 1. 初始化一个空堆栈来存储有效分数。 

堆栈代表当前的分数记录。 由于所有特殊操作仅依赖于最近的值，因此该数据结构提供了高效的访问。 
2. 迭代每个操作`operations`。 

我们按顺序处理操作，因为每个操作都取决于先前操作创建的当前状态。 
3. 如果操作是`"C"`，删除最近的分数。 

我们从堆栈中弹出顶部值，因为`"C"`使最后一个有效分数无效。 
4. 如果操作是`"D"`，是之前分数的两倍。 

我们查看栈顶元素，将其乘以`2`，并将结果推回堆栈。 
5. 如果操作是`"+"`，将前两个分数相加。 

我们访问堆栈中的最后两个元素，将它们加在一起，然后推送结果。 
6. 否则，将运算视为整数。 

将字符串转换为整数并将其压入堆栈。 
7. 处理完所有操作后，返回堆栈的和。 

该堆栈准确地包含记录中保留的有效分数。 

### 为什么它有效

 核心不变量是，处理完每个操作后，堆栈与问题陈述定义的有效分数记录完全匹配。 

每个操作都保留这个不变量：

 - 数值正确附加新分数。 
-`"C"`正确删除最新分数。 
-`"D"`从最新的有效分数正确得出分数。 
-`"+"`从最新的两个有效分数中正确得出分数。 

由于不变量在每一步后都成立，因此最终堆栈代表正确的分数历史记录，并将其相加得出正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def calPoints(self, operations: List[str]) -> int:
        scores = []

        for operation in operations:
            if operation == "C":
                scores.pop()
            elif operation == "D":
                scores.append(scores[-1] * 2)
            elif operation == "+":
                scores.append(scores[-1] + scores[-2])
            else:
                scores.append(int(operation))

        return sum(scores)
```实现直接遵循基于堆栈的算法。 

我们首先创建一个名为的空列表`scores`，它充当堆栈。 Python 列表从末尾提供高效的追加和弹出操作，使它们成为自然的选择。 

在循环内，我们检查每个操作。 为了`"C"`，我们称`pop()`删除最近的分数。 为了`"D"`，我们使用以下方法读取最后的分数`scores[-1]`，将其加倍，然后附加结果。 为了`"+"`，我们使用负索引访问最后两个元素并附加它们的总和。 

如果运算不是特殊符号，则必须是数字字符串。 我们使用以下方法将其转换为整数`int()`并将其追加到堆栈中。 

所有操作处理完毕后，`scores`包含最终的有效记录，所以我们只需返回`sum(scores)`。 

## 解决方案```go
func calPoints(operations []string) int {
	scores := []int{}

	for _, operation := range operations {
		switch operation {
		case "C":
			scores = scores[:len(scores)-1]

		case "D":
			scores = append(scores, scores[len(scores)-1]*2)

		case "+":
			n := len(scores)
			scores = append(scores, scores[n-1]+scores[n-2])

		default:
			var value int
			fmt.Sscanf(operation, "%d", &value)
			scores = append(scores, value)
		}
	}

	total := 0
	for _, score := range scores {
		total += score
	}

	return total
}
```Go 解决方案遵循相同的逻辑，但使用切片而不是 Python 列表。 这`scores`切片充当堆栈。 

删除最后一个分数`"C"`，我们使用重新切片`scores[:len(scores)-1]`。 为了`"D"`和`"+"`，我们通过索引访问最近的元素。 

Go 特有的一个细节是整数解析。 这里我们使用`fmt.Sscanf()`将字符串值转换为整数。 或者，`strconv.Atoi()`也可以使用。 由于该问题保证了有效的输入，因此在实践中不需要错误处理。 

Go 切片根据需要动态调整大小，因此我们可以在整个执行过程中安全地附加新分数。

 ## 边缘情况

 ### 记录变空

 像这样的案例`["1", "C"]`从记录中删除唯一的分数，留下一个空堆栈。 幼稚的实现可能会意外访问删除的值，或者在计算最终总和时失败。 我们的实现正确处理了这个问题，因为`pop()`干净地删除元素，并且`sum([])`正确评估为`0`。 

### 负数

 分数可以为负数，例如`["-2", "D"]`。 粗心的实现可能会假设所有分数都是正数或错误处理字符串转换。 由于我们显式转换数字字符串`int()`，自然地解析负值，并且加倍保留正确的符号。 

### 连锁特种作战

 类似的情况`["1", "2", "+", "D"]`很容易出错，因为特殊操作依赖于最近生成的值。 基于堆栈的方法始终从最新的有效状态开始工作，确保新创建的分数立即可用于未来的操作。 

### 连续无效

 输入如`["5", "3", "C", "C"]`反复删除最近的值。 某些实现意外地删除了错误的元素或丢失了历史记录。 因为堆栈始终存储准确有效的分数序列，所以连续`pop()`操作自然保持正确性。
