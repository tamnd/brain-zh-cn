[LeetCode 第 630 题](https://leetcode.com/problems/course-schedule-iii/)

 **难度：** 🔴难
 **主题：** 数组、贪婪、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题给出了在线课程列表，其中每门课程表示为`[duration, lastDay]`。 

这`duration`告诉我们需要连续多少天才能完成课程。 这`lastDay`告诉我们课程必须完成的最晚日期。 

你从一天开始`1`，并且一次只能选修一门课程。 一旦开始一门课程，您必须连续完成该课程，然后才能继续学习另一门课程。 

目标是确定在不违反任何截止日期的情况下可以完成的最大课程数量。 

换句话说，我们要仔细选择和订购课程，以便：

 - 总运行时间绝不会超过完成任何课程的截止日期。 
- 所选课程的数量尽可能多。 

约束条件很重要：

 - 最多`10^4`课程
 - 每个持续时间和截止日期也可以长达`10^4`尝试每个子集或每个排序的强力解决方案是不可行的，因为组合的数量呈指数增长。 

一些重要的观察立即脱颖而出：

 - 有些课程是不可能单独修读的，例如一门课程`[5,3]`因为它已经超过了自己的最后期限。 
- 尽早参加长课程可能会阻碍稍后的几门较小的课程。 
- 课程的顺序非常重要。 
- 贪婪决策是必要的，因为输入量很大。 

重要的边缘情况包括：

 - 单一不可能的课程
 - 多个课程共享相同的截止日期
 - 应该跳过的持续时间非常长的课程
 - 将先前选择的一门课程替换为较短的课程可以增加课程总数的情况
 - 最佳时间表与按最短持续时间排序不同的输入

 ## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的课程子集，并确定每个子集是否可以合理安排。 

一种可能的策略是：

 1. 生成课程的每个子集。 
2. 对于每个子集，尝试每种可能的排序。 
3. 模拟一门课程的学习。 
4. 检查是否满足所有期限。 
5. 跟踪最大有效子集大小。 

这是有效的，因为它探索了每一个可能的有效时间表，因此保证了最佳答案。 

然而，其复杂性是巨大的。 

为了`n`课程：

 - 有`2^n`子集。 
- 每个子集可能需要排列检查。 
- 即使经过优化的修剪仍然呈指数级增长。 

和`n = 10^4`，这是完全不切实际的。 

### 最佳解决方案的关键见解

 关键的观察是，最后期限自然意味着贪婪的排序。 

如果我们按截止日期升序处理课程：

 - 较早的截止日期更具限制性。 
- 如果我们能够首先满足早期的截止日期，我们就可以为以后的课程保留灵活性。 

然而，仅仅贪婪地学习每门课程并不总是有效。 

假设添加课程导致总时间超过当前截止日期。 在这种情况下，我们需要决定应该删除哪门课程。 

为了最大化所修课程的数量，我们应该删除持续时间最长的课程。 

为什么？ 

因为删除最长的课程可以释放最大的时间，同时只牺牲一门课程。 

这直接导致了贪婪+最大堆策略：

 - 按截止日期对课程进行排序。 
- 跟踪最大堆中选定的课程持续时间。 
- 保持当前总时间。 
- 如果总时间超过当前截止日期，则删除迄今为止最长的课程。 

这确保我们始终保持最省时的课程集。

 ## 算法演练

 1. 按课程对所有课程进行排序`lastDay`按升序排列。 

这确保我们始终首先处理最紧急的截止日期。 如果课程的截止日期较早，则必须在截止日期较晚的课程之前考虑。 
2. 初始化变量`total_time = 0`。 

这会跟踪所选课程当前占用的天数。 
3. 初始化最大堆。 

堆存储所选课程的持续时间。 自从Python的`heapq`是最小堆，我们存储负持续时间来模拟最大堆。 
4. 将排序好的课程一一迭代。 

对于每门课程：

 - 将其持续时间添加到`total_time`- 将持续时间压入堆中

 此时，我们暂时假设我们将参加该课程。 
5.检查当前日程是否违反期限。 

如果`total_time > lastDay`，时间表不再可行。 
6. 删除迄今为止最长的课程。 

从堆中弹出最大持续时间并从中减去`total_time`。 

这就是贪心优化步骤。 删除最长的课程可以节省最多的时间，并最大限度地提高我们适应未来课程的机会。 
7. 继续处理所有课程。 

堆始终包含当前选择的可行课程集的持续时间。 
8. 返回堆大小。 

堆中元素的数量等于可以完成的最大课程数。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 在每一步中，选定的课程集是所有相同规模的课程集中总持续时间可能最短的可行集。 

当发生截止日期违规时，删除最长的课程始终是最佳选择，因为它可以最大限度地减少总时间，同时保留尽可能多的课程。 

按截止日期排序可确保一旦我们满足所有较早的截止日期，未来的决策只需要考虑维持较晚截止日期的可行性。 

这种贪婪的替换策略保证了课程的最大数量。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def scheduleCourse(self, courses: List[List[int]]) -> int:
        # Sort by deadline
        courses.sort(key=lambda course: course[1])

        total_time = 0

        # Max heap implemented using negative values
        max_heap = []

        for duration, last_day in courses:
            total_time += duration
            heapq.heappush(max_heap, -duration)

            # If schedule becomes invalid,
            # remove the longest course
            if total_time > last_day:
                longest_duration = -heapq.heappop(max_heap)
                total_time -= longest_duration

        return len(max_heap)
```实施首先根据截止日期对课程进行排序。 这保证了首先处理具有更严格约束的课程。 

变量`total_time`存储所有当前选定课程的累积持续时间。 

堆存储所选课程的持续时间。 由于Python仅提供最小堆，因此会插入负值，因此在弹出时首先出现最大的持续时间。 

对于每门课程：

 - 算法暂时包含它。 
- 总时间增加。 
- 课程持续时间添加到堆中。 

如果违反截止日期，最长的课程将立即被删除。 这可能会删除新添加的课程或一些先前选择的较长课程。 

最后，堆恰好包含在最大化计数的同时可以完成的课程。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func scheduleCourse(courses [][]int) int {
	sort.Slice(courses, func(i, j int) bool {
		return courses[i][1] < courses[j][1]
	})

	totalTime := 0
	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	for _, course := range courses {
		duration := course[0]
		lastDay := course[1]

		totalTime += duration
		heap.Push(maxHeap, duration)

		if totalTime > lastDay {
			longest := heap.Pop(maxHeap).(int)
			totalTime -= longest
		}
	}

	return maxHeap.Len()
}
```Go 实现使用`container/heap`包来构建自定义最大堆。 

与 Python 不同，Go 不需要负值，因为可以通过以下方式自定义比较行为`Less`方法。 

切片自然地用于堆存储，并且整数溢出不是问题，因为最大累积持续时间保持在 Go 整数类型的合理范围内。

 ## 边缘情况

 当课程无法满足其截止日期时，就会出现一种重要的边缘情况，例如`[10,5]`。 幼稚的实现可能会错误地暂时包含它，并且无法正确删除它。 在此解决方案中，首先添加课程，然后由于总时间超过截止日期而立即删除课程。 这自然可以处理没有特殊情况逻辑的不可能的课程。 

另一个关键的边缘情况涉及截止日期相同但持续时间不同的课程。 例如，`[[5,10],[2,10],[3,10]]`。 天真的贪婪策略可能会选择遇到的第一门课程，而错过参加更多短期课程的机会。 基于堆的替换策略保证首先丢弃最长的持续时间，从而保留最大课程数。 

当添加新的短期课程应取代先前选择的长期课程时，会发生第三种重要情况。 考虑`[[5,5],[4,6],[2,6]]`。 如果我们贪心地保留之前的长课程，我们只能完成一门课程。 最佳算法用较短的持续时间代替较长的持续时间，从而使更多的总课程能够在截止日期内完成。 

另一个微妙的边缘情况是所有课程都恰好在截止日期前完成。 该算法正确地允许相等，因为条件仅在以下情况下删除课程：`total_time > lastDay`，而不是当它们相等时。 这可确保保留有效的时间表。
