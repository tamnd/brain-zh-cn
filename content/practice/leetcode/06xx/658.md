 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找、滑动窗口、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题给了我们一个排序的整数数组`arr`，以及两个整数，`k`和`x`。 我们需要准确返回`k`数组中最接近的元素`x`。 

“最接近”的定义很重要：

 - 一个元素`a`比`b`如果`|a - x| < |b - x|`- 如果两个元素距离相同`x`，则较小的元素被认为更接近

 返回的结果也必须保持升序排序。 

由于输入数组已经排序，这是我们应该避免不必要的排序操作并利用排序结构的主要线索。 

例如，如果：```
arr = [1,2,3,4,5]
k = 4
x = 3
```那么四个最接近的值`3`是：```
[1,2,3,4]
```虽然`5`也近`3`，它比`1`。 

限制条件是：

 -`1 <= k <= arr.length`-`arr.length <= 10^4`-`arr`已经排序了

 数组大小为`10^4`不是很大，所以即使`O(n log n)`解决方案会很顺利地通过。 然而，因为数组是有序的，所以我们可以用二分查找做得更好。 

一些边缘情况很重要：

 -`x`可能小于数组中的每个元素
 -`x`可能比每个元素都大
 - 多个元素可能具有相同的距离`x`-`k`可能等于整个数组的长度
 - 可能存在重复值

 如果绑定处理不正确或者边界管理不仔细，这些情况很容易破坏简单的实现。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是计算每个元素与`x`，然后根据以下条件对数组进行排序：

 1. 绝对距离`x`2. 打破平局的元素值本身

 排序后，我们取第一个`k`元素，最后再次对这些选定的元素进行排序以满足输出排序要求。 

这种方法之所以有效，是因为它直接遵循问题定义。 每个元素都会根据与元素的接近程度进行排名`x`。 

然而，该解决方案执行了不必要的排序工作。 即使数组已经排序，我们也会忽略该结构并从头开始重新排序所有内容。 

### 最佳解决方案的关键见解

 重要的观察是答案必须形成长度为连续的子数组`k`。 

因为数组是排序的，所以如果我们在跳过中间元素的同时选择两个相距较远的元素，则跳过的元素将始终至少与所选端点之一一样近。 因此，最佳答案始终是连续窗口。 

这将问题从：```
"Which individual elements should we pick?"
```到：```
"Where should the window of size k start?"
```如果窗口有大小`k`，那么它的起始索引范围可以是：```
0 to len(arr) - k
```我们可以对这些可能的起始位置进行二分搜索。 

对于从索引开始的候选窗口`mid`，我们比较：```
arr[mid]
```和```
arr[mid + k]
```这些代表了竞争窗口之外的元素。 

如果：```
x - arr[mid] > arr[mid + k] - x
```那么右侧更近，所以我们应该将窗口向右移动。 

否则，我们保持或向左移动。 

这给了一个优雅的`O(log(n-k) + k)`解决方案。

 ## 算法演练

 ### 最优二分搜索窗口算法

 1.初始化两个指针，`left = 0`和`right = len(arr) - k`。 

我们正在寻找最佳大小窗口的起始索引`k`。 
2. 执行二分查找`left < right`。 

在每一步中，计算：```
mid = (left + right) // 2
```3. 比较之间的距离`x`和竞争的边界元素。 

两个相关要素是：```
arr[mid]
arr[mid + k]
```它们对应于两个重叠的窗口：

 - 窗口开始于`mid`- 窗口开始于`mid + 1`4. 决定哪个方向更好。 

如果：```
x - arr[mid] > arr[mid + k] - x
```那么右边界元素更接近`x`，因此向右移动窗口可以改善结果。 

移动：```
left = mid + 1
```5. 否则，保留当前窗口或向左搜索。 

移动：```
right = mid
```6. 继续直到`left == right`。 

至此，我们已经找到了最优的起始索引。 
7. 返回子数组：```
arr[left:left+k]
```### 为什么它有效

 二分搜索之所以有效，是因为窗口的质量单调变化。 当我们将窗口从左向右移动时，会出现一个过渡点，窗口停止改善并开始恶化。 

通过比较`arr[mid]`和`arr[mid + k]`，我们确定哪个相邻窗口更好。 由于数组已排序，因此这种比较足以消除每次迭代的一半搜索空间。 

最终窗口保证包含`k`最接近的元素，因为在二分搜索过程中，每个被丢弃的窗口都被证明更糟糕。 

## Python 解决方案```python
from typing import List

class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:
        left = 0
        right = len(arr) - k

        while left < right:
            mid = (left + right) // 2

            if x - arr[mid] > arr[mid + k] - x:
                left = mid + 1
            else:
                right = mid

        return arr[left:left + k]
```实现直接遵循二分搜索窗口策略。 

变量`left`和`right`定义可能的窗口起始索引的搜索空间。 由于窗口长度固定为`k`，最大的有效起始索引是`len(arr) - k`。 

在循环内部，`mid`代表候选起始位置。 

关键对比：```python
x - arr[mid] > arr[mid + k] - x
```检查当前窗口右侧之外的元素是否更接近`x`比当前窗口内最左边的元素。 

如果正确的候选者更好，则最佳窗口必须从更右侧开始，因此我们移动`left`。 

否则，当前窗口至少与移动后的窗口一样好，因此我们继续向左搜索。 

当循环终止时，`left`存储最佳起始索引。 然后我们返回对应长度的切片`k`。 

## 解决方案```go
func findClosestElements(arr []int, k int, x int) []int {
	left := 0
	right := len(arr) - k

	for left < right {
		mid := (left + right) / 2

		if x-arr[mid] > arr[mid+k]-x {
			left = mid + 1
		} else {
			right = mid
		}
	}

	return arr[left : left+k]
}
```Go 的实现非常接近地反映了 Python 的逻辑。 

Go 切片使得提取最终子数组变得高效，因为切片不会立即复制元素。 返回的切片引用原始数组的适当部分。 

与 Python 不同，Go 不需要导入类型实用程序。 整数运算也很简单，因为约束足够小，可以避免溢出问题。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`x`小于数组中的每个元素。 在这种情况下，最接近的元素只是第一个`k`价值观。 有缺陷的实现可能会由于负算术或不正确的比较而错误地向右移动窗口。 二分搜索比较自然地处理这种情况，因为所有左侧元素都比最右侧元素更接近。 

另一个关键的边缘情况发生在`x`大于每个数组元素。 这里，答案应该是最终的窗口大小`k`。 不正确的边界计算很容易在数组末尾附近产生索引错误。 使用`right = len(arr) - k`保证每个候选窗口都保持有效。 

领带情况也特别重要。 认为`x = 2`候选人是`1`和`3`。 两者距离相同`2`，但问题需要选择较小的元素。 比较：```
if x - arr[mid] > arr[mid + k] - x
```使用严格的大于运算符而不是大于或等于。 这个微妙的细节确保领带偏向左侧，对应较小的元素。 

另一种边缘情况涉及重复值。 如果周围有许多相同的值`x`，某些实现可能会错误地缩小或扩大窗口。 由于该算法仅比较窗口边界，并且从不单独删除中间元素，因此可以自然且正确地处理重复项。 

最后，当`k`等于整个数组长度，只有一个有效窗口。 该算法立即返回整个数组，因为二分搜索范围折叠为单个起始索引`0`。
