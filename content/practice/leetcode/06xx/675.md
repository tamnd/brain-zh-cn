[LeetCode 第 675 题](https://leetcode.com/problems/cut-off-trees-for-golf-event/)

 **难度：** 🔴难
 **主题：** 数组、广度优先搜索、堆（优先级队列）、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个代表森林的二维网格。 每个单元格包含三个可能值之一：

 -`0`表示该牢房已被封锁，无法进入。 
-`1`表示单元格是空的并且可以穿过。 
- 任何大于的值`1`代表一棵树，该值本身就是树的高度。 

我们从位置开始`(0, 0)`并且必须严格按照高度递增的顺序砍伐每棵树。 树木被砍伐后，该单元格将成为具有价值的正常可步行单元格`1`。 

目标是计算按所需顺序砍伐所有树木所需的最少总步骤数。 如果连一棵树都够不到，我们就必须返回`-1`。 

运动规则很重要。 从任何位置，我们一次只能向四个基本方向移动一步：

 - 向上
 - 向下
 - 左
 - 右

 不允许对角移动。 

限制相对较小：

 -`m, n <= 50`- 网格最多包含`2500`细胞。 

这立即表明诸如广度优先搜索之类的图遍历算法是可行的。 由于每次移动的成本相等，因此 BFS 是这里理想的最短路径算法。 

另一个重要的观察结果是树木必须按高度排序进行砍伐。 该问题保证所有树的高度都是唯一的，这意味着只有一个有效的切割顺序。 

一些边缘情况很重要：

 - 起始单元本身可能包含一棵树。 
- 有些树木可能被障碍物完全隔离。 
- 森林可能包含许多需要重复最短路径计算的树木。 
- 如果最短路径重新计算得不好，那么幼稚的全局寻路策略可能会变得非常低效。 
- 两棵树之间的最短路线可能需要穿过包含尚未砍伐的较高树木的单元格。 这是允许的，因为所有非零单元格都是可步行的。 

## 方法

 ### 蛮力方法

 蛮力的想法是尝试树之间所有可能的路径，同时保持所需的切割顺序。 

我们首先按高度对所有树进行排序。 然后，对于每一对连续的目标，我们尝试枚举从当前位置到下一棵树的每条可能的路线，并选择最短的有效路线。 

这种方法是正确的，因为检查每条可能的路线可以保证我们最终找到每对树之间的最小距离。 将这些最小距离相加即可得出最佳总路径长度。 

然而，这在计算上是不可行的。 网格中可能的路径数量随着路径长度呈指数增长。 即使对于中等大小的网格，枚举所有路径也是不可能的。 

### 最佳方法

 关键的观察结果是，该问题自然地分解为未加权网格上的多个最短路径问题。 

由于每次移动只花费一步，因此广度优先搜索可以有效地计算两个位置之间的最短路径。 

算法变为：

 1. 收集所有树木。 
2. 按高度排序。 
3. 从`(0, 0)`，重复运行 BFS 到下一棵树。 
4. 将最短距离添加到答案中。 
5. 移动到该树的位置并继续。 

如果任何 BFS 未能达到目标，则返回`-1`。 

这很有效，因为：

 - 网格尺寸足够小，足以进行重复的 BFS 遍历。 
- BFS 保证未加权图中的最短路径。 
- 树排序是固定且确定的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 枚举树之间许多可能的路径 |
 | 最佳 | O((mn)^2) | O((mn)^2) | O(百万) | 在连续排序的树之间使用 BFS |

 ## 算法演练

 1. 穿越整个森林并收集每一棵树。 

树是任何值大于`1`。 对于每棵树，存储其高度和坐标。 我们需要用于寻路的坐标和用于排序的高度。 
2. 按高度对所有树进行排序。 

由于必须按递增顺序砍伐树木，因此排序决定了我们必须遵循的确切顺序。 
3. 将当前位置初始化为`(0, 0)`。 

这是我们砍伐树木之前的起点。 
4. 对于按排序顺序的每棵树，从当前位置到该树运行 BFS。 

BFS 是理想的，因为：

 - 每条边的权重相等。 
- 我们需要最少的移动次数。 
- 网格可以建模为未加权的图。 
5. 在 BFS 期间，保持：

 - 用于级别顺序遍历的队列。 
- 访问过的集合或矩阵以避免重新访问单元格。 
- 通过 BFS 级别的距离信息。 
6. 从每个单元格尝试向四个方向移动。 

仅移动到以下单元格：

 - 保持在界限内。 
- 未被阻止（`forest[r][c] != 0`）。 
- 尚未访问过。 
7. 如果BFS到达目标树，则返回最短距离。 

BFS 保证我们第一次达到目标的步数是最少的。 
8.如果BFS穷举所有可达单元仍未找到目标，则返回`-1`。 

这意味着无法到达该树。 
9. 将 BFS 距离添加到总答案中。 

然后将当前位置更新为新砍的树。 
10. 继续，直到处理完所有树。 
11. 返回累计总距离。 

### 为什么它有效

 正确性依赖于两个属性。 

首先，砍伐树木必须严格按照高度递增的顺序，因此目标的顺序是固定的。 对于接下来要访问哪棵树没有优化选择。 

其次，BFS 始终计算未加权图中的最短路径。 由于每次移动只花费一步，因此连续树之间的 BFS 距离是最佳的。 

结合这两个事实可以保证所有 BFS 距离的总和是所需的最小步数。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def cutOffTree(self, forest: List[List[int]]) -> int:
        rows = len(forest)
        cols = len(forest[0])

        trees = []

        for r in range(rows):
            for c in range(cols):
                if forest[r][c] > 1:
                    trees.append((forest[r][c], r, c))

        trees.sort()

        def bfs(start_row: int, start_col: int,
                target_row: int, target_col: int) -> int:

            if start_row == target_row and start_col == target_col:
                return 0

            queue = deque([(start_row, start_col, 0)])
            visited = {(start_row, start_col)}

            directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

            while queue:
                row, col, distance = queue.popleft()

                for dr, dc in directions:
                    next_row = row + dr
                    next_col = col + dc

                    if (
                        0 <= next_row < rows
                        and 0 <= next_col < cols
                        and forest[next_row][next_col] != 0
                        and (next_row, next_col) not in visited
                    ):
                        if next_row == target_row and next_col == target_col:
                            return distance + 1

                        visited.add((next_row, next_col))
                        queue.append(
                            (next_row, next_col, distance + 1)
                        )

            return -1

        total_steps = 0
        current_row = 0
        current_col = 0

        for _, tree_row, tree_col in trees:
            distance = bfs(
                current_row,
                current_col,
                tree_row,
                tree_col
            )

            if distance == -1:
                return -1

            total_steps += distance
            current_row = tree_row
            current_col = tree_col

        return total_steps
```该实现首先扫描网格并将所有树单元收集到`trees`列表。 每个条目都存储树的高度及其坐标。 

然后对树进行排序，以便按照所需的顺序进行处理。 

嵌套的`bfs`函数计算两个位置之间的最短路径。 它使用队列进行级别顺序遍历，并使用`visited`设置以避免重新访问单元格。 

对于从队列中删除的每个位置，算法都会探索四个相邻的单元格。 只有有效的、非阻塞的、未访问的单元才会添加到队列中。 

如果到达目标位置，则立即返回当前最短距离。 如果队列先变空，则目标无法到达，函数返回`-1`。 

外循环按顺序处理树。 每次成功的 BFS 后，总步数都会更新，并且当前位置移动到新切割的树。 

如果无法到达任何一棵树，算法立​​即返回`-1`。 

## 解决方案```go
package main

import "container/list"

func cutOffTree(forest [][]int) int {
	rows := len(forest)
	cols := len(forest[0])

	type Tree struct {
		height int
		row    int
		col    int
	}

	trees := []Tree{}

	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			if forest[r][c] > 1 {
				trees = append(trees, Tree{
					height: forest[r][c],
					row:    r,
					col:    c,
				})
			}
		}
	}

	// Simple insertion sort because constraints are small
	for i := 1; i < len(trees); i++ {
		key := trees[i]
		j := i - 1

		for j >= 0 && trees[j].height > key.height {
			trees[j+1] = trees[j]
			j--
		}

		trees[j+1] = key
	}

	bfs := func(startRow, startCol, targetRow, targetCol int) int {
		if startRow == targetRow && startCol == targetCol {
			return 0
		}

		type State struct {
			row      int
			col      int
			distance int
		}

		queue := list.New()
		queue.PushBack(State{
			row:      startRow,
			col:      startCol,
			distance: 0,
		})

		visited := make([][]bool, rows)
		for i := range visited {
			visited[i] = make([]bool, cols)
		}

		visited[startRow][startCol] = true

		directions := [][]int{
			{1, 0},
			{-1, 0},
			{0, 1},
			{0, -1},
		}

		for queue.Len() > 0 {
			front := queue.Front()
			queue.Remove(front)

			current := front.Value.(State)

			for _, dir := range directions {
				nextRow := current.row + dir[0]
				nextCol := current.col + dir[1]

				if nextRow >= 0 &&
					nextRow < rows &&
					nextCol >= 0 &&
					nextCol < cols &&
					forest[nextRow][nextCol] != 0 &&
					!visited[nextRow][nextCol] {

					if nextRow == targetRow &&
						nextCol == targetCol {
						return current.distance + 1
					}

					visited[nextRow][nextCol] = true

					queue.PushBack(State{
						row:      nextRow,
						col:      nextCol,
						distance: current.distance + 1,
					})
				}
			}
		}

		return -1
	}

	totalSteps := 0
	currentRow := 0
	currentCol := 0

	for _, tree := range trees {
		distance := bfs(
			currentRow,
			currentCol,
			tree.row,
			tree.col,
		)

		if distance == -1 {
			return -1
		}

		totalSteps += distance
		currentRow = tree.row
		currentCol = tree.col
	}

	return totalSteps
}
```Go 实现遵循与 Python 版本相同的整体结构。 

一个显着的区别是使用`container/list`实现BFS队列。 Go 不提供像 Python 那样的内置双端队列结构`collections.deque`。 

访问的结构被实现为二维布尔切片而不是哈希集。 对于固定网格尺寸，这可以提高内存效率并且速度更快。 

Go 整数足以解决这个问题，因为最大路径长度受到网格大小的限制。

 ## 边缘情况

 ### 起始位置包含一棵树

 起始单元格`(0,0)`本身可能包含一棵树。 如果实现假设在砍伐第一棵树之前始终需要移动，那么这很容易导致错误。 

该实现自然地处理了这个问题，因为 BFS 函数立即返回`0`当起始位置和目标位置相同时。 

### 遥不可及的树

 一棵树可能会被障碍物隔离。 如果 BFS 无法到达下一个目标树，算法必须立即终止`-1`。 

这是通过允许 BFS 耗尽所有可到达的单元来处理的。 如果队列在到达目标之前变空，则函数返回`-1`，直接传播到最终结果。 

### 穿过更高的树木

 一个简单的误解是认为较高的树木会阻碍运动，直到被砍伐为止。 这是不正确的。 无论树的高度如何，任何非零单元格都是可步行的。 

实现仅正确检查：```
forest[r][c] != 0
```这允许遍历未砍伐的树木，同时仍然执行所需的砍伐顺序。 

### 大量树木

 在茂密的森林中，几乎每个单元都可能包含一棵树。 糟糕的实现可能会导致效率低下或使用过多的内存。 

BFS 方法仍然高效，因为每个 BFS 最多探索整个网格一次，并且最大网格大小仅为`50 x 50`。
