[LeetCode 第 647 题](https://leetcode.com/problems/palindromic-substrings/)

 **难度：** 🟡 中等
 **主题：** 两个指针、字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定字符串内存在多少个**回文子串**`s`。 

子字符串是字符串的任何**连续段**。 这意味着我们无法重新排列字符或跳过位置。 例如，在`"abc"`,`"ab"`是一个子串，但是`"ac"`不是因为字符不相邻。 

回文是从左到右和从右到左读取相同内容的序列。 单个字符始终是回文，因为反转它们会产生相同的字符。 较长的子串可能是也可能不是回文，具体取决于它们的字符是否围绕中心镜像。 

输入是单个字符串`s`，仅由小写英文字母组成。 输出是一个整数，表示 **回文子串** 的总数**`s`。 

一个重要的细节是，**如果重复的子字符串出现在不同的位置**，则它们会单独计数。 例如，在`"aaa"`, 子串`"a"`出现三次，并且所有三次出现都是独立计数的。 

限制条件是：

 -`1 <= s.length <= 1000`-`s`仅包含小写英文字母

 最大长度为`1000`告诉我们三次时间解可能会变得太慢。 二次解更为合适。 

有几个重要的边缘情况需要考虑。 一个长度的字符串`1`应该返回`1`因为单个字符本身就是一个回文。 具有所有不同字符的字符串，例如`"abc"`，仅贡献单字符回文。 包含重复字符的字符串，例如`"aaa"`，生成许多重叠的回文，并且通常是不正确的实现失败的地方。 偶数长度回文，例如`"abba"`和奇数长度回文，例如`"aba"`两者都必须正确处理。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是生成**每个可能的子串**并检查它是否是回文。 

对于一个长度的字符串`n`， 有`O(n²)`可能的子字符串，因为每个子字符串都是由开始和结束位置定义的。 对于每个子串，我们可以通过从两端向中心比较字符来验证它是否是回文，这需要`O(n)`最坏情况下的时间。 

这种方法是正确的，因为它显式检查每个子字符串并仅计算那些满足回文条件的子字符串。 然而，它的效率很低，因为单独检查所有子串会导致三次时间复杂度。 

### 最佳解决方案的关键见解

 我们可以利用回文的一个重要属性，而不是生成每个子串并独立测试它：

 **每个回文都从中心向外扩展。**

 例如：

 -`"aba"`围绕中心展开`'b'`-`"abba"`围绕两者之间的差距扩大`'b'`人物

 这一观察意味着，我们可以从每个可能的中心开始，只要字符匹配就向外扩展，而不是先枚举子字符串。 

由于每个扩展都直接检查匹配字符，因此我们避免了多余的回文检查并显着降低了复杂性。 

有两种中心：

 1. **奇数回文中心**，其中字符本身是中心。 
2. **偶数长度回文中心**，中心位于两个字符之间。 

对于一个长度的字符串`n`， 有`2n - 1`可能的中心。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 生成每个子字符串并手动检查每个回文 |
 | 最优，围绕中心展开 | O(n²) | O(1) | O(1) | 从每个有效的回文中心向外扩展 |

 ## 算法演练

 ### 最优算法，围绕中心展开

 1. 初始化一个计数器变量来跟踪找到的回文子串的数量。 
2. 迭代字符串中的每个位置，并将其视为**奇数长度回文**的中心。 例如，在`"aba"`，中心是`'b'`。 
3. 使用两个指针从此中心向外扩展，`left`和`right`。 最初，两个指针都指向同一个索引。 
4. 当指针停留在字符串内部并且两个位置的字符匹配时，我们找到了回文。 增加计数器并继续向外扩展。 
5. 对于相同的索引，还要检查**偶数长度回文中心**。 在这种情况下，中心位于相邻字符之间，因此初始化`left = i`和`right = i + 1`。 
6. 重复相同的扩展过程。 每当字符匹配时，就计算一个回文并进一步向外扩展。 
7. 继续，直到处理完所有可能的中心。 
8. 返回最终计数。 

同时检查奇数和偶数中心的原因是回文可以有任何一种形式。 例如，`"aba"`有一个单字符中心，而`"abba"`有两个字符之间的中心。 

### 为什么它有效

 该算法之所以有效，是因为每个回文都有一个唯一的中心。 通过迭代所有可能的中心并向外扩展，我们保证每个有效的回文都被精确地计算一次。 由于扩展仅在镜像字符匹配时继续，因此每个计数的子字符串都保证是回文。 

## Python 解决方案```python
class Solution:
    def countSubstrings(self, s: str) -> int:
        def expand_from_center(left: int, right: int) -> int:
            palindrome_count = 0

            while left >= 0 and right < len(s) and s[left] == s[right]:
                palindrome_count += 1
                left -= 1
                right += 1

            return palindrome_count

        total_palindromes = 0

        for index in range(len(s)):
            total_palindromes += expand_from_center(index, index)
            total_palindromes += expand_from_center(index, index + 1)

        return total_palindromes
```实施直接遵循围绕中心扩展的策略。 

一个辅助函数，`expand_from_center`，处理回文扩展逻辑。 它接收两个指针，`left`和`right`，代表当前中心。 只要指针保留在字符串内并且字符匹配，该函数就会不断向外扩展。 

每次成功的扩展都代表一个有效的回文，因此计数器会递增。 

在主循环内，我们将每个索引处理为奇数长度和偶数长度的中心。 对于奇数长度回文，两个指针都从相同的索引开始。 对于偶数长度回文，指针从相邻位置开始。 

最终答案累积了扩展过程中发现的所有回文。 

## 解决方案```go
func countSubstrings(s string) int {
	n := len(s)
	totalPalindromes := 0

	expandFromCenter := func(left, right int) int {
		palindromeCount := 0

		for left >= 0 && right < n && s[left] == s[right] {
			palindromeCount++
			left--
			right++
		}

		return palindromeCount
	}

	for i := 0; i < n; i++ {
		totalPalindromes += expandFromCenter(i, i)
		totalPalindromes += expandFromCenter(i, i+1)
	}

	return totalPalindromes
}
```Go 实现密切反映了 Python 逻辑。 本地函数，`expandFromCenter`，封装了扩展行为。 

Go 特有的一项考虑因素是字符串索引。 由于问题保证小写英文字母，因此使用字节位置索引字符串是安全的，因为每个字符占用一个字节。 如果涉及 Unicode 字符，则需要转换为符文切片。 

无需担心整数溢出，因为长度为 的字符串的回文子串的最大数量`1000`至多是`1000 × 1001 / 2`，可以轻松放入 Go 中`int`。

 ## 边缘情况

 ### 单字符串

 一个字符串，例如`"a"`是最小的有效输入。 如果实现假设至少存在两个字符用于扩展，则这种情况可能会暴露错误。 我们的实现自然地处理了这个问题，因为每个索引都被视为奇数长度的中心，恰好产生一个回文。 

### 所有角色都不同

 一个字符串，例如`"abcd"`不包含多字符回文。 有缺陷的实现可能会意外地过度计数或错误地将相邻字符视为回文。 在这里，每一次超越长度的扩展`1`由于相邻字符不匹配，因此立即失败。 

### 重复字符和重叠回文

 字符串像`"aaaa"`特别重要，因为它们包含许多重叠的回文。 幼稚的实现可能会错过重复项或无法正确计算重叠区域。 Expand-around-center 方法可以自然地处理这个问题，因为每个中心独立地向外扩展并计算每个有效的出现次数。 

### 偶数回文

 类似的情况`"abba"`可以破坏仅检查奇数长度中心的实现。 由于回文中心位于两个字符之间，仅靠奇数中心逻辑就会错过它。 我们的实现明确地检查了两者`(i, i)`和`(i, i + 1)`中心，保证偶数长度的回文被正确计数。
