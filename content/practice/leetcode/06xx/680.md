[LeetCode 第 680 题](https://leetcode.com/problems/valid-palindrome-ii/)

 **难度：** 🟢简单
 **主题：** 两个指针、字符串、贪婪

 ## 解决方案

 ## 问题理解

 问题询问给定的字符串是否`s`删除**最多一个字符**后可以成为回文。 

回文是向前和向后读取相同的字符串。 例如，`"aba"`和`"racecar"`是回文，因为它们的字符从两端对称匹配。 

输入由单个字符串组成`s`仅由小写英文字母组成。 输出是一个布尔值：

 - 返回`true`如果字符串已经是回文，或者删除**一个字符或零个字符**可以使其成为回文。 
- 返回`false`如果需要删除多个字符。 

例如，`"abca"`回报`true`因为删除`'c'`产生`"aba"`，这是一个回文。 然而，`"abc"`回报`false`因为只删除一个字符仍然会留下一个非回文字符串。 

约束条件`1 <= s.length <= 10^5`尤为重要。 字符串长度为 100,000 意味着具有二次时间复杂度的算法（例如单独检查每个可能的删除）可能会太慢。 这强烈表明我们需要一种有效的线性时间方法。 

一些边缘情况值得关注。 已经是回文的字符串应该立即返回`true`。 非常短的字符串，例如 length`1`或者`2`也应该正常工作，因为删除零个或一个字符很容易产生回文。 另一个重要的情况是当第一次不匹配出现时，因为我们只有一次删除机会，所以选择正确的字符来跳过变得至关重要。 

## 方法

 ### 蛮力方法

 解决此问题的一种直接方法是尝试一次删除所有可能的字符，并检查生成的字符串是否为回文。 

对于一个长度的字符串`n`，我们会生成`n`修改后的字符串。 每次回文检查都需要扫描字符串，这需要`O(n)`时间。 由于我们对每个索引重复此操作，因此总时间复杂度变为`O(n²)`。 

这种方法是正确的，因为它详尽地检查了每一种有效的删除可能性，包括不需要删除的情况。 然而，随着`n = 10^5`，二次时间太慢。 

### 最优方法，带有贪心验证的两个指针

 关键的观察结果是，只有当对称位置的字符停止匹配时，回文才会失败。 

我们可以使用两个指针：

 - 一个指针从左端开始。 
- 一个指针从右端开始。 

只要角色匹配，我们就继续向内推进。 如果我们遇到不匹配，我们只有一个可用的删除，所以有两种可能性：

 1. 跳过左边的字符。 
2. 跳过正确的字符。 

如果任一结果子串形成回文，则答案是`true`。 

这是有效的，因为第一个不匹配是删除唯一重要的地方。 在此之前，前缀和后缀已经完美匹配，因此删除其他位置无助于解决不匹配问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 尝试删除每个字符并检查回文 |
 | 最佳 | O(n) | O(1) | O(1) | 最多一次验证通过的两个指针 |

 ## 算法演练

 1.初始化两个指针，`left`在字符串的开头和`right`在最后。 
2. 当字符匹配时，将两个指针向内移动。 这是有效的，因为匹配的字符已经是有效的回文对，不需要修改。 
3. 如果指针交叉或相交且没有不匹配，则返回`true`。 该字符串已经是回文字符串。 
4. 如果位置不匹配`left`和`right`，我们必须决定删除一个字符是否可以修复字符串。 
5. 通过验证子串来检查跳过左侧字符是否会创建回文`s[left + 1:right + 1]`。 
6. 通过验证子串来检查跳过正确的字符是否会创建回文`s[left:right]`。 
7. 返回`true`如果任一检查成功。 否则，返回`false`。 

要验证子字符串是否为回文，请使用另一个带有两个指针的辅助函数。 它向内扫描并返回`false`不匹配时立即。 

### 为什么它有效

 正确性来自于第一个不匹配是唯一有意义的决策点这一事实。 在不匹配之前，所有字符都已经满足回文条件。 由于只允许删除一个字符，因此唯一合理的选择是删除左侧不匹配的字符或右侧不匹配的字符。 如果两个选项都不能产生回文，则不存在有效的解决方案。 

## Python 解决方案```python
class Solution:
    def validPalindrome(self, s: str) -> bool:
        def is_palindrome(left: int, right: int) -> bool:
            while left < right:
                if s[left] != s[right]:
                    return False
                left += 1
                right -= 1
            return True

        left = 0
        right = len(s) - 1

        while left < right:
            if s[left] != s[right]:
                return (
                    is_palindrome(left + 1, right)
                    or is_palindrome(left, right - 1)
                )

            left += 1
            right -= 1

        return True
```实现首先定义一个辅助函数，`is_palindrome`，它检查两个索引之间的子字符串是否形成回文。 它不创建新的子字符串，而是直接使用索引，避免不必要的内存使用。 

主要逻辑使用两个指针来比较字符串两端的字符。 当字符匹配时，两个指针都向内移动。 

如果发生不匹配，算法会立即尝试仅有的两种有效可能性：跳过左侧字符或跳过右侧字符。 辅助函数验证剩余的子字符串是否是回文。 

如果没有发现不匹配，则原始字符串已经是回文，因此函数返回`True`。 

## 解决方案```go
func validPalindrome(s string) bool {
	isPalindrome := func(left, right int) bool {
		for left < right {
			if s[left] != s[right] {
				return false
			}
			left++
			right--
		}
		return true
	}

	left := 0
	right := len(s) - 1

	for left < right {
		if s[left] != s[right] {
			return isPalindrome(left+1, right) ||
				isPalindrome(left, right-1)
		}

		left++
		right--
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 本地辅助函数使用索引而不是切片来检查子字符串是否是回文，这避免了不必要的分配。 

Go 字符串是字节索引的，这在这里是安全的，因为问题只保证小写英文字母。 由于仅使用 ASCII 字符，因此按字节进行索引可以正常工作。 

不需要对整数溢出进行特殊处理，因为索引保留在字符串范围内。

 ## 边缘情况

 一个重要的边缘情况是字符串已经是回文。 有错误的实现可能会强制执行不必要的删除或错误处理终止条件。 例如，`"aba"`应立即返回`true`。 该实现自然地处理了这个问题，因为两个指针相遇而不会遇到不匹配。 

另一个重要的情况是可移动字符出现在字符串的开头或结尾。 输入如`"deeee"`或者`"eeeed"`要求跳过一个边界字符。 某些实现错误地假设删除仅发生在中间。 在这里，检查了两种跳过的可能性，因此边界删除工作正常。 

当第一个不匹配提供两个可能的删除，但只有一个是正确的时，就会出现第三种棘手的情况。 例如，`"abca"`需要删除`'c'`， 不是`'b'`。 只尝试一侧的贪婪方法将会失败。 此实现显式检查两种可能性并返回`true`如果任一产生回文。 

最后的边缘情况是非常大的输入字符串接近极限`10^5`人物。 二次解可能会超时。 由于此实现仅执行恒定数量的线性扫描，因此即使对于允许的最大输入，它仍然保持高效。
