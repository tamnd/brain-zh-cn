[LeetCode 645 题](https://leetcode.com/problems/set-mismatch/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、位操作、排序

 ## 解决方案

 ## 问题理解

 该问题描述了一组损坏的整数。 最初，该集合包含来自`1`通过`n`正好一次。 由于出现错误，一个号码重复，这意味着另一个号码消失了。 

输入数组`nums`代表该集合的损坏版本。 由于一个数字出现两次而另一个数字缺失，因此数组仍然有长度`n`，但它不再包含来自的数字的完美排列`1`到`n`。 

任务是确定两个值：

 - 出现两次的数字
 - 丢失的号码

 结果应以数组形式返回：```
[duplicate, missing]
```例如，如果数组是：```
[1,2,2,4]
```数量`2`出现两次，数量`3`缺失，所以答案是：```
[2,3]
```限制相对较小：

 -`2 <= nums.length <= 10^4`-`1 <= nums[i] <= 10^4`这告诉我们，即使是`O(n^2)`从技术上讲，解决方案可以通过上限`10^4`，但这会是低效且不必要的。 由于该问题具有非常规则的结构，特别是数字`1`到`n`，我们应该以线性时间解决方案为目标。 

有几个重要的边缘情况需要记住。 重复项可能出现在范围的开头或结尾。 缺失值可能是`1`或者`n`。 数组可能很小，比如`[1,1]`。 在这些情况下，仅部分检查频率的简单实现可能无法正确检测缺失值。 

该问题保证恰好有一个重复的数字和恰好有一个缺失的数字。 这种保证大大简化了逻辑，因为我们不需要处理具有多个重复值或多个缺失值的格式错误的输入。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查每个数字`1`到`n`并计算它在数组中出现的次数。 

对于每个数字：

 - 如果出现两次，则为重复项
 - 如果出现零次，则为缺失的数字

 这是可行的，因为原始集合应该包含每个数字一次。 任何频率偏差`1`立即识别重复值或缺失值。 

主要问题是效率。 计算每个数字的出现次数需要重复扫描数组。 如果数组有长度`n`，我们对其中的每个值执行完整扫描`1`到`n`，总复杂度变为`O(n^2)`。 

尽管限制不是很大，但与可能的方法相比，这种方法效率较低。 

### 最佳方法

 关键的观察是我们只需要知道每个数字出现的次数。 

哈希集或频率数组允许我们一次性处理输入。 迭代时`nums`:

 - 如果某个数字已经出现过，则该数字是重复的
 - 否则，按所见记录

 处理完数组后，我们迭代`1`到`n`找出哪个数字从未见过。 该数字就是缺失值。 

这可以有效地工作，因为哈希集中的查找操作是`O(1)`平均而言。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复计算每个值的出现次数 |
 | 最佳| O(n) | O(n) | 使用哈希集有效跟踪所见数字 |

 ## 算法演练

 1. 创建一个空集，名为`seen`。 

该集合将存储遍历数组时遇到的每个数字。 集合是理想的，因为它提供恒定时间查找。 
2. 初始化一个名为`duplicate`。 

该变量最终将保存出现两次的数字。 
3.遍历数组`nums`。 

对于每个数字：

 - 如果号码已经存在`seen`，那么这就是重复值。 
- 否则，将数字插入`seen`。 

此步骤识别单遍中的重复数字。 
4. 遍历其中的整数`1`通过`n`。 

由于原始集合应包含该范围内的每个值，因此我们检查哪个数字没有出现在`seen`。 
5. 未找到该号码`seen`是缺失值。 

将此值存储在名为的变量中`missing`。 
6. 返回`[duplicate, missing]`。 

### 为什么它有效

 该数组最初只包含每个数字一次。 由于恰好有一个数字被重复并且恰好有一个数字被删除，因此除 1 之外的每个有效数字都恰好出现一次。 

该集合跟踪所有遇到的值。 第一次重复插入会识别重复项，因为集合不能包含重复项。 处理完数组后，集合中唯一不存在的数字必定是缺失的数字。 

由于该问题精确地保证了一个重复值和一个缺失值，因此该逻辑始终会产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findErrorNums(self, nums: List[int]) -> List[int]:
        seen = set()
        duplicate = -1
        
        for number in nums:
            if number in seen:
                duplicate = number
            else:
                seen.add(number)
        
        missing = -1
        
        for value in range(1, len(nums) + 1):
            if value not in seen:
                missing = value
                break
        
        return [duplicate, missing]
```该实现紧密遵循前面描述的算法。 

这`seen`设置存储已经出现的数字。 在第一次遍历期间，每个新数字都会插入到集合中。 如果集合中已经存在一个数字，则它一定是重复的值。 

识别出重复项后，第二个循环检查来自的每个整数`1`通过`n`。 由于数组中缺少一个值，因此集合中不会恰好出现一个值。 该值变为`missing`。 

最后，该方法按所需顺序返回两个值。 

## 解决方案```go
func findErrorNums(nums []int) []int {
    seen := make(map[int]bool)
    duplicate := -1

    for _, number := range nums {
        if seen[number] {
            duplicate = number
        } else {
            seen[number] = true
        }
    }

    missing := -1

    for value := 1; value <= len(nums); value++ {
        if !seen[value] {
            missing = value
            break
        }
    }

    return []int{duplicate, missing}
}
```Go 解决方案使用`map[int]bool`而不是集合，因为 Go 没有内置的集合类型。 

其他方面的逻辑与 Python 版本相同。 遍历过程中会在地图中跟踪号码，并通过扫描来识别丢失的号码`1`通过`n`。 

不存在整数溢出问题，因为这些值相对于 Go 的整数范围非常小。 该函数始终返回一个恰好包含两个整数的切片。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 一次检测重复，一次检测缺失 |
 | 空间| O(n) | 该集合最多可存储`n`数字|

 该算法执行两次线性扫描。 第一次扫描处理数组中的每个元素一次，第二次扫描检查来自`1`通过`n`。 由于这两个操作都是线性的，因此总时间复杂度为`O(n)`。 

辅助空间复杂度为`O(n)`因为该集合可能包含数组中每个不同的数字。

 ## 边缘情况

 一种重要的边缘情况是尽可能最小的输入大小，例如`[1,1]`。 在这种情况下，重复值和缺失值在有效范围内紧邻。 某些实现错误地假设数组具有更多多样性或无法正确初始化变量。 该实现可以自然地处理这种情况，因为该集合检测到重复的`1`，第二遍确定`2`失踪了。 

当缺失的数字是时，会出现另一个重要的边缘情况`1`， 例如`[2,2]`。 某些算法错误地假设最小值必须始终存在。 在第二遍期间，此实现显式检查从以下位置开始的每个值：`1`，所以它正确地识别出`1`从未出现过。 

当缺失的数字为`n`， 例如`[1,2,3,4,4]`。 当循环停止得太早或使用不正确的边界时，通常会出现错误。 这个实现迭代了`range(1, len(nums) + 1)`，确保包含上边界并允许正确检测缺失的最大值。
