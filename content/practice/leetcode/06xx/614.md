[LeetCode 第 614 题](https://leetcode.com/problems/second- Degree-follower/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们从由单个表表示的社交网络中识别**二级关注者**`Follow`。 该表包含两列：`followee`和`follower`。 每行表示一个用户（`follower`) 关注了另一个用户 (`followee`）。 重要的是，每个用户都无法关注自己，并且这些用户的组合`followee`和`follower`是独一无二的。 

**二级关注者**定义为**关注至少一个其他用户**并且**被至少一个用户**关注的用户。 换句话说，用户在表中同时显示为关注者和被关注者。 

输入是任意大小的关系表，其中每一行都是关注者-被关注者关系。 预期输出是一个表格，其中包含二级追随者及其拥有的追随者数量（`num`)，按关注者姓名的字母顺序排列。 

约束告诉我们数据集可能很大，因此依赖于重复扫描表（不进行过滤的强力连接）的解决方案可能效率低下。 此外，由于用户无法关注自己，因此我们不需要处理自循环。 

重要的边缘情况包括仅关注但未被关注的用户、仅被关注但不关注任何人的用户以及空的`Follow`桌子。 

## 方法

 **暴力方法**将检查表中的每个用户是否至少作为关注者出现一次以及作为关注者至少出现一次。 这需要多次扫描表或执行自连接，这对于大型数据集来说效率很低。 虽然这种方法是正确的，但它做了不必要的重复工作。 

**最佳方法**利用 SQL 聚合。 我们首先计算每个用户的关注者数量（按关注者分组），然后过滤这些计数以仅包括那些也显示为关注者的用户。 这确保了我们只考虑二级追随者并避免重复扫描表格。 按关注者字母顺序排序很简单`ORDER BY`条款。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 重复检查所有行中的每个用户，看看他们是否既是关注者又是被关注者。 |
 | 最佳| O(n) | O(n) | 按关注者聚合关注者，然后根据关注者集中是否存在进行过滤； 单次扫描并分组。 |

 ## 算法演练

 1. 通过选择不同的关注者来识别所有关注者`follower`列从`Follow`桌子。 
2. 通过对表进行分组来计算每个用户的关注者数量`followee`并使用`COUNT(follower)`。 
3. 过滤计数以仅包括出现在步骤 1 中确定的关注者集中的用户。这确保我们只选择二级关注者。 
4. 按以下顺序对结果行进行排序`follower`按字母升序排列的列。 

**为什么有效：** 此方法保证了正确性，因为 SQL`GROUP BY`和`COUNT`确保每个统计的用户都有关注者。 这`WHERE`子句确保用户还关注至少一个其他用户，满足成为二级关注者的两个条件。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def second_degree_followers(conn: sqlite3.Connection) -> List[Tuple[str, int]]:
    query = """
        SELECT f.followee AS follower, COUNT(f.follower) AS num
        FROM Follow f
        WHERE f.followee IN (SELECT DISTINCT follower FROM Follow)
        GROUP BY f.followee
        ORDER BY f.followee
    """
    cursor = conn.cursor()
    cursor.execute(query)
    return cursor.fetchall()
```此 Python 解决方案利用 SQLite 直接执行 SQL 查询。 首先，它创建一个子查询来标识所有显示为关注者的用户。 然后，它计算每个也是关注者的关注者的关注者数量。 最后，它按字母顺序对结果进行排序。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func SecondDegreeFollowers(db *sql.DB) (*sql.Rows, error) {
    query := `
        SELECT f.followee AS follower, COUNT(f.follower) AS num
        FROM Follow f
        WHERE f.followee IN (SELECT DISTINCT follower FROM Follow)
        GROUP BY f.followee
        ORDER BY f.followee
    `
    return db.Query(query)
}
```在 Go 中，方法几乎相同。 主要区别在于处理`sql.DB`对象并返回一个`*sql.Rows`对象而不是列表。 与 Python 不同，Go 需要显式错误处理，并且不允许从查询中直接返回列表。 

## 工作示例

 考虑示例表：```
+----------+----------+
| followee | follower |
+----------+----------+
| Alice    | Bob      |
| Bob      | Cena     |
| Bob      | Donald   |
| Donald   | Edward   |
+----------+----------+
```一步一步：

 1. 独特的追随者：鲍勃、塞纳、唐纳德、爱德华。 
2. 计算每个关注者的关注者数量：

 - 爱丽丝：1（鲍勃）
 - 鲍勃：2（塞纳、唐纳德）
 - 唐纳德：1（爱德华）
 3. 过滤显示为关注者的关注者：Bob、Donald
 4. 按字母顺序排列：鲍勃、唐纳德

 输出：```
+----------+-----+
| follower | num |
+----------+-----+
| Bob      | 2   |
| Donald   | 1   |
+----------+-----+
```## 复杂度分析

 ## 边缘情况

 **空表：**`Follow`表可能没有行。 该算法正确返回空结果，因为关注者的子查询和聚合不会产生任何行。 

**没有关注者的用户：** 关注其他人但未被关注的用户不应出现。 这是通过使用一组不同的关注者过滤关注者来处理的。 

**用户关注多个用户：**如果一个用户关注多个用户，他们仍应被计为二级关注者。 聚合正确计算所有关注者的数量，过滤确保仅包含二级关注者。 

这种方法可以有效地处理这些边缘情况并确保正确性。
