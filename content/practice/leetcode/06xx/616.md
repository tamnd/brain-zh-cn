 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、Trie、字符串匹配

 ## 解决方案

 ## 问题理解

 该问题要求我们在子字符串与给定单词词典中的任何单词匹配时将 HTML 样式的粗体标签插入到字符串中。 

我们得到：

 - 一根绳子`s`- 一个数组`words`，其中每个元素都是我们想要突出显示的模式

 对于里面每个单词的每次出现`s`，我们必须将匹配部分包裹起来`<b>`和`</b>`标签。 

棘手的部分是重叠或相邻的匹配必须合并到一个粗体部分中。 

例如，如果一个单词与索引匹配`[0,2]`和另一场比赛`[2,4]`，我们不创建嵌套或单独的标签。 相反，我们将它们组合成一个连续的粗体区域，覆盖`[0,4]`。 

输出是插入了最少数量的粗体标签对的原始字符串。 

限制相对较小：

 -`s.length <= 1000`-`words.length <= 100`-`words[i].length <= 1000`由于输入大小适中，我们可以提供直接检查许多子字符串的解决方案。 我们不一定需要像 KMP 或 Aho-Corasick 这样非常先进的字符串匹配算法，尽管它们也可以解决问题。 

一些边缘情况很重要：

 - 多个单词可以重叠
 - 多个单词可以连续
 - 一个词可能出现多次
 -`words`可能为空
 - 一个单词可能是另一个单词的子串
 - 整个字符串可能会变成粗体
 - 没有任何单词可以匹配

 在找到匹配项后立即插入标签的简单实现很容易产生不正确的嵌套或碎片标签。 关键的挑战是在生成最终字符串之前正确合并间隔。 

## 方法

 ### 蛮力方法

 蛮力方法是检查每个子串`s`并检查它是否等于任何单词`words`。 

每当找到匹配项时，我们都会将该子字符串覆盖的索引标记为粗体。 

处理完所有可能的子字符串后，我们通过插入来构建最终结果`<b>`在进入粗体区域之前`</b>`离开后一位。 

这种方法是正确的，因为每个可能的匹配子字符串都会被显式检查。 属于匹配单词的任何字符都会标记为粗体。 

然而，生成所有子字符串的成本很高。 一个长度的字符串`n`有`O(n^2)`子串，并将它们与所有单词进行比较会进一步增加成本。 

### 最佳方法

 更好的方法是迭代中的每个位置`s`并直接测试是否有单词从那里开始。 

我们不生成所有子字符串，而是仅检查长度与实际单词相对应的子字符串。 

我们维护一个布尔数组`bold`， 在哪里：

-`bold[i] = True`意味着性格`s[i]`应该加粗
 -`bold[i] = False`意味着它应该保持正常

 对于每个索引`i`以及每一个字：

 - 如果`s[i:i+len(word)] == word`- 然后将该范围内的所有字符标记为粗体

 处理完所有匹配项后，我们遍历字符串一次以构造最终答案。 

主要见解是该问题本质上是一个区间合并问题。 我们不是在匹配期间插入标签，而是首先确定哪些字符属于粗体间隔，然后仅在正常区域和粗体区域之间转换时才生成标签。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × m × k) | O(n² × m × k) | O(n) | 生成所有子字符串并与所有单词进行比较 |
 | 最佳| O(n × m × k) | O(n × m × k) | O(n) | 仅检查相关字长并标记粗体间隔 |

 在哪里：

-`n = len(s)`-`m = len(words)`-`k = average word length`## 算法演练

 1. 创建一个布尔数组，名为`bold`长度`len(s)`。 

每个位置代表该字符是否应出现在粗体标签内。 
2. 遍历每个起始索引`i`在字符串中。 

在每个位置，测试每个单词`words`。 
3. 对于每个单词，检查子串是否以`i`匹配这个词。 

这是使用以下方法完成的：```
s[i:i+len(word)] == word
```4. 如果找到匹配项，则将该单词覆盖的所有字符标记为粗体。 

例如，如果`"abc"`从索引开始的匹配`2`，然后指数`2`,`3`， 和`4`变得大胆。 
5. 处理完所有匹配项后，再次遍历字符串以构建结果。 
6. 追加字符前`s[i]`，确定我们是否正在进入粗体区域。 

我们插入`<b>`什么时候：

-`bold[i] == True`- 以及任一`i == 0`或者`bold[i-1] == False`7. 追加当前字符。 
8. 添加字符后，确定是否留下粗体区域。 

我们插入`</b>`什么时候：

-`bold[i] == True`- 以及任一`i == len(s)-1`或者`bold[i+1] == False`9. 返回构造好的字符串。 

### 为什么它有效

 该算法之所以有效，是因为每个匹配的单词都明确地将其覆盖的字符标记为粗体。 

重叠匹配自然会合并，因为重叠范围标记相同的布尔位置`True`。 

连续匹配也会自动合并，因为相邻位置保持连续粗体，因此在它们之间不会插入结束和重新打开标签。 

最终的遍历恰好在正常区域和粗体区域之间的过渡处插入标签，保证标签对的最小有效数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def addBoldTag(self, s: str, words: List[str]) -> str:
        n = len(s)
        bold = [False] * n

        # Mark all bold positions
        for i in range(n):
            for word in words:
                word_len = len(word)

                if s[i:i + word_len] == word:
                    for j in range(i, i + word_len):
                        if j < n:
                            bold[j] = True

        # Build final result
        result = []

        for i in range(n):
            # Start of bold region
            if bold[i] and (i == 0 or not bold[i - 1]):
                result.append("<b>")

            result.append(s[i])

            # End of bold region
            if bold[i] and (i == n - 1 or not bold[i + 1]):
                result.append("</b>")

        return "".join(result)
```实现直接遵循算法。 

这`bold`数组是核心数据结构。 它存储每个字符是否属于任何匹配的单词。 

第一个嵌套循环扫描每个位置和每个单词。 每当发生匹配时，就会标记相应的索引`True`。 

第二次遍历构造输出字符串。 

条件：```python
bold[i] and (i == 0 or not bold[i - 1])
```检测粗体区域的开始。 

相似地：```python
bold[i] and (i == n - 1 or not bold[i + 1])
```检测粗体区域的末尾。 

由于标签仅在转换时插入，因此重叠和连续间隔会自动合并。 

## 解决方案```go
func addBoldTag(s string, words []string) string {
	n := len(s)
	bold := make([]bool, n)

	// Mark bold positions
	for i := 0; i < n; i++ {
		for _, word := range words {
			wordLen := len(word)

			if i+wordLen <= n && s[i:i+wordLen] == word {
				for j := i; j < i+wordLen; j++ {
					bold[j] = true
				}
			}
		}
	}

	// Build result
	result := make([]byte, 0)

	for i := 0; i < n; i++ {
		// Start bold region
		if bold[i] && (i == 0 || !bold[i-1]) {
			result = append(result, []byte("<b>")...)
		}

		result = append(result, s[i])

		// End bold region
		if bold[i] && (i == n-1 || !bold[i+1]) {
			result = append(result, []byte("</b>")...)
		}
	}

	return string(result)
}
```Go 实现密切反映了 Python 逻辑。 

一个重要的区别是边界处理。 在 Go 中，超出字符串长度的切片会导致运行时恐慌，因此我们显式检查：```go
i + wordLen <= n
```在比较子字符串之前。 

为了提高效率，结果是使用字节切片构造的，因为 Go 中重复的字符串连接可能会很昂贵。

    def addBoldTag(self, s: str, words: List[str]) -> str:
        n = len(s)
        bold = [False] * n

            for word in words:
                if s[i:i + len(word)] == word:

 ## 边缘情况

 一种重要的边缘情况是重叠匹配。 例如，在`"aaaaa"`和`["aa"]`，匹配发生在索引处`[0,1]`,`[1,2]`,`[2,3]`， 和`[3,4]`。 简单的实现可能会生成多个嵌套标签。 布尔标记方法完全避免了这种情况，因为所有重叠位置都变成了`True`，产生一个连续的粗体间隔。 

另一个关键的边缘情况是连续比赛。 假设一个单词恰好在另一个单词开始的地方结束。 该问题需要将连续的粗体部分合并为一个更大的部分。 由于该算法仅在粗体和非粗体字符之间转换时插入标签，因此相邻匹配项会自动合并到单个区域中。 

第三个重要的情况是根本没有单词与字符串匹配。 某些实现会意外插入空标签或产生格式错误的输出。 在此解决方案中，`bold`数组完全保留`False`，因此不会插入任何标签，并且原始字符串不变地返回。 

当整个字符串变为粗体时，会出现最后一个微妙的边缘情况。 不正确的实现有时会忘记关闭最终的`</b>`标签。 此解决方案显式检查当前索引是否是字符串中的最后一个字符，确保结束标记正确插入到末尾。
