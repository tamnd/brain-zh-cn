[LeetCode 第 696 题](https://leetcode.com/problems/count-binary-substrings/)

 **难度：** 🟢简单
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串，这意味着该字符串仅包含字符`'0'`和`'1'`。 我们需要统计有多少子串同时满足两个条件：

 1、子串包含相同个数`0`沙`1`s。 
2. 全部`0`s 被分组在一起并且所有`1`s 被分组在一起。 

第二个条件极其重要。 这意味着子字符串必须看起来像一个连续的块`0`s 后面跟着一个连续的块`1`s，或一个连续的块`1`s 后面跟着一个连续的块`0`s。 

有效的例子包括：

 -`"0011"`-`"01"`-`"1100"`-`"10"`无效的示例包括：

 -`"001100"`因为之间有多个转换`0`和`1`-`"0101"`因为字符不是连续分组的

 输入大小可以大到`10^5`，它立即告诉我们`O(n^2)`或者`O(n^3)`解决方案可能会太慢。 我们需要一个高效的线性时间解决方案。 

一个关键的观察是有效的子字符串总是恰好跨越两个连续的字符组。 例如：```
00110011
```可以分为：```
00 | 11 | 00 | 11
```如果两个相邻的组有长度`a`和`b`，那么他们贡献：```
min(a, b)
```有效的子串。 

例如：```
00 and 11
```有长度`2`和`2`，所以他们贡献：

 -`"01"`-`"0011"`这是`min(2, 2) = 2`。 

重要的边缘情况包括非常短的字符串、仅包含一个重复字符的字符串以及组大小显着不同的字符串。 

例如：

-`"0"`产生`0`-`"11111"`产生`0`-`"0001111"`产生`3`该问题保证字符串非空并且仅包含有效的二进制字符。 

## 方法

 ### 蛮力方法

 暴力解决方案将生成每个可能的子字符串并检查它是否满足所需的条件。 

对于每个子字符串，我们需要验证：

 - 数量`0`s 等于数量`1`s
 - 全部`0`s 连续出现
 - 全部`1`s 连续出现

 有`O(n^2)`子字符串，验证每个子字符串可以花费`O(n)`最坏情况下的时间。 这导致`O(n^3)`解决方案。 

即使进行了优化，暴力方法仍然太慢`n = 10^5`。 

### 最佳方法

 关键的见解是有效的子字符串仅存在于相邻的相同字符组之间。 

考虑字符串：```
001110000
```这些团体是：```
00 | 111 | 0000
```长度：```
2, 3, 4
```尺寸组之间`2`和`3`，我们可以形成：```
min(2, 3) = 2
```有效的子串。 

尺寸组之间`3`和`4`，我们可以形成：```
min(3, 4) = 3
```有效的子串。 

所以答案是：```
2 + 3 = 5
```我们不需要直接检查每个子字符串，而是只需要跟踪连续字符组的大小。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 生成所有子字符串并验证每个子字符串 |
 | 最佳| O(n) | O(1) | O(1) | 计算相邻字符组并求和最小值 |

 ## 算法演练

 1. 初始化变量以跟踪连续字符组的长度。 

我们维持：

 -`previous_group_length`-`current_group_length`-`result`最初，当前组长度为`1`因为字符串非空并且第一个字符开始第一个组。 
2.从index开始从左到右遍历字符串`1`。 

在每个位置，将当前字符与前一个字符进行比较。 
3. 如果当前字符与前一个字符匹配，则扩展当前组。 

例子：```
000
```不断增加当前组的长度。 
4. 如果当前字符与前一个字符不同，则开始新的组。 

此时：

 - 当前组成为上一个组
 - 新的当前组以长度开始`1`5. 每次我们在组之间转换时，添加：```
min(previous_group_length, current_group_length)
```到结果。 

这是有效的，因为每对相邻组都贡献了同样多的有效子串。 
6. 继续，直到处理完整个字符串。 
7. 返回累加结果。 

### 为什么它有效

 每个有效的子字符串恰好由两组连续的字符组成。 如果两个相邻的组有长度`a`和`b`，则它们之间形成的平衡子串的个数为`min(a, b)`。 

该算法对每个组只处理一次，并累积每个相邻组的贡献。 由于每个有效子串恰好属于一个相邻组对，因此计数是完整且正确的。 

## Python 解决方案```python
class Solution:
    def countBinarySubstrings(self, s: str) -> int:
        previous_group_length = 0
        current_group_length = 1
        result = 0

        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                current_group_length += 1
            else:
                result += min(previous_group_length, current_group_length)
                previous_group_length = current_group_length
                current_group_length = 1

        result += min(previous_group_length, current_group_length)

        return result
```实现直接遵循算法。`previous_group_length`存储当前组之前的组的大小。`current_group_length`遍历字符串时跟踪活动组的大小。 

当连续的字符匹配时，当前组就会变得更大。 

当角色发生变化时，当前组结束。 此时，该算法使用以下方法添加前一个相邻对贡献的有效子串的数量：```python
min(previous_group_length, current_group_length)
```然后当前组成为前一组，并开始新的组。 

循环完成后，必须添加一个最终贡献，因为最后一组转换不会在循环内处理。 

该算法使用恒定的额外内存，并且仅扫描字符串一次。 

## 解决方案```go
func countBinarySubstrings(s string) int {
    previousGroupLength := 0
    currentGroupLength := 1
    result := 0

    for i := 1; i < len(s); i++ {
        if s[i] == s[i-1] {
            currentGroupLength++
        } else {
            if previousGroupLength < currentGroupLength {
                result += previousGroupLength
            } else {
                result += currentGroupLength
            }

            previousGroupLength = currentGroupLength
            currentGroupLength = 1
        }
    }

    if previousGroupLength < currentGroupLength {
        result += previousGroupLength
    } else {
        result += currentGroupLength
    }

    return result
}
```Go 的实现与 Python 解决方案非常相似。 

Go 没有提供内置的`min`函数用于整数，因此代码在添加较小的组长度时使用显式比较。 

Go 中的字符串是字节切片，并且由于输入仅包含 ASCII 字符`'0'`和`'1'`，直接索引到字符串中是安全且高效的。 

该实现仅使用整数变量和常量额外空间。

 ## 边缘情况

 一种重要的边缘情况是仅包含一个字符的字符串，例如`"0"`或者`"1"`。 由于有效的子字符串需要两者`0`沙`1`是，正确答案是`0`。 幼稚的实现可能会错误地假设每个组至少贡献一个子字符串。 此实现可以自然地处理这种情况，因为永远不会有第二个组与第一个组配对。 

另一个重要的边缘情况是只有一组的字符串，例如`"11111"`或者`"00000"`。 尽管字符串很长，但字符类型之间没有转换，因此不存在有效的子字符串。 算法正确返回`0`因为`previous_group_length`遗迹`0`整个执行过程中。 

当相邻组具有不同大小时，会出现更微妙的边缘情况。 例如：```
0001111
```团体规模为`3`和`4`。 仅有的`3`有效子串可以存在，因为较小的组限制了可以形成的平衡子串的数量。 使用`min(previous_group_length, current_group_length)`正确地捕捉到了这个约束。 

另一个棘手的情况是完全交替的字符串，例如`"1010101"`。 每个组都有大小`1`，因此每一相邻对都恰好贡献一个有效子串。 该算法可以有效地处理这个问题，而无需显式生成子字符串。
