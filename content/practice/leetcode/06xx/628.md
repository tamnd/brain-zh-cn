[LeetCode 第 628 题](https://leetcode.com/problems/maximum-product-of-two-numbers/)

 **难度：** 🟢简单
 **主题：** 数组、数学、排序

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`并要求我们恰好选择三个乘积尽可能大的数字。 我们必须返还最大的产品价值。 

简单来说，在数组中三个元素的所有可能组合中，我们需要确定哪种组合产生最大的乘法结果。 

输入是整数数组，整数可以是正数、负数或零。 输出是一个整数，表示从任意三个不同元素可获得的最大乘积。 

约束条件很重要：

 - 数组长度至少为 3，因此总有有效答案。 
- 该数组最多可以包含`10^4`元素，它足够大，以至于非常慢的算法变得不切实际。 
- 值范围为`-1000`到`1000`，这意味着负数很常见，必须小心处理。 

负值是这个问题的关键复杂性。 天真的直觉可能会建议取三个最大的数字，但这并不总是正确的。 两个非常小的负数相乘就变成一个很大的正数。 例如：```
[-10, -10, 5, 2]
```最大乘积为：```
(-10) * (-10) * 5 = 500
```不是：```
5 * 2 * (-10) = -100
```这意味着最佳答案可能来自以下两种可能性之一：

 - 三个最大的数字
 - 两个最小的数字（均为负数）与最大的正数相结合

 重要的边缘情况包括包含所有负数的数组、包含零的数组以及最佳乘积来自负对而不是最大正值的数组。 该问题保证至少三个元素，因此我们永远不需要处理无效的输入大小。 

## 方法

 ### 蛮力方法

 暴力解决方案检查数组中三个数字的每种可能的组合。 对于每个三元组，我们计算乘积并跟踪迄今为止看到的最大值。 

这是有效的，因为它详尽地评估了所有有效的选择，保证最终会找到最大的产品。 

然而，对于较大的输入来说，时间复杂度太昂贵。 如果数组有`n`元素，则有：```
n choose 3 = n * (n - 1) * (n - 2) / 6
```可能的三胞胎。 

为了`n = 10^4`，这变得太大而无法有效计算。 

### 最佳方法

 关键的见解是只有少数数字真正重要。 

为了最大化三个数字的乘积，只有两个有意义的候选者：

 1.数组中最大的三个值
 2. 两个最小值和最大值

 第二种情况的原因是两个负数相乘成一个正数。 如果负值的幅值很大，它们的乘积可能会超过第三大正数形成的乘积。 

例如：```
[-100, -99, 1, 2, 3]
```最好的产品是：```
(-100) * (-99) * 3 = 29700
```而不是：```
3 * 2 * 1 = 6
```我们可以通过对数组进行一次排序来有效地解决这个问题。 排序后：

 - 最大的三个数字在最后
 - 两个最小的数字在开头

 然后我们计算两个候选产品并返回较大的一个。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 检查每个可能的三元组 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(n) 取决于排序实现 | 使用排序并仅比较两个候选产品 |

 ## 算法演练

 1. 对数组进行非降序排序。 

排序将最小值放在开头，将最大值放在末尾。 这种安排可以很容易地识别出能够产生最大产品的唯一候选组合。 
2. 计算三个最大数的乘积。 

排序后，这些值是：```
nums[-1], nums[-2], nums[-3]
```这代表了大正数产生最佳结果的简单情况。 
3. 计算两个最小数和最大数的乘积。 

排序后，最小的两个值是：```
nums[0], nums[1]
```如果这些数字均为负数，则它们的乘积将为正数。 将该正值乘以最大数可能会产生总体最大乘积。 
4. 比较两个候选产品。 

正确答案必须是这两个值中较大的一个。 
5. 返回最大乘积。 

### 为什么它有效

 该算法之所以有效，是因为任何最佳三元组都必须属于以下两类之一：

 - 它使用三个数值最大值
 - 它使用两个极端负值，其正积超过第三大正数

 没有其他组合可以产生更大的结果。 排序保证我们可以直接访问这些候选者，并且比较两个产品确保我们选择最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumProduct(self, nums: List[int]) -> int:
        nums.sort()

        product_largest = nums[-1] * nums[-2] * nums[-3]
        product_smallest = nums[0] * nums[1] * nums[-1]

        return max(product_largest, product_smallest)
```实现首先按升序对数组进行排序。 这是可以轻松获取最大值和最小值的核心操作。 

排序后，代码计算两个候选产品：

 -`product_largest`使用数组中的三个最大值
 -`product_smallest`使用两个最小值和最大值

 最后，`max()`函数返回较大的乘积。 

实现很简洁，因为数学洞察力将问题简化为仅评估两种可能性。 

## 解决方案```go
package main

import "sort"

func maximumProduct(nums []int) int {
	sort.Ints(nums)

	n := len(nums)

	productLargest := nums[n-1] * nums[n-2] * nums[n-3]
	productSmallest := nums[0] * nums[1] * nums[n-1]

	if productLargest > productSmallest {
		return productLargest
	}

	return productSmallest
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于 Go 需要显式长度处理并使用`sort.Ints()`标准库中的函数。 

因为输入约束足够小，所以 Go 中不存在整数溢出问题。 最大可能的乘积是：```go
1000 * 1000 * 1000 = 10^9
```它安全地符合 Go 的标准整数范围。

 ## 边缘情况

 当数组包含较大的负值时，会出现一种重要的边缘情况。 简单地选择三个最大数字的简单解决方案在这里会失败。 例如：```
[-10, -10, 5, 2]
```最好的答案是将两个负数相乘。 该实现通过显式检查两个最小值和最大值形成的乘积来正确处理此问题。 

另一个重要的边缘情况是所有数字均为负数。 在这种情况下，结果本身也可能是否定的。 例如：```
[-1, -2, -3]
```一些实现错误地假设答案必须是肯定的。 我们的实现没有做出这种假设，只是比较两个数学上有效的候选产品。 

包含零的数组是错误的另一个常见来源。 考虑：```
[-5, -4, 0, 1]
```粗心的实施可能会意外地优先考虑负乘积而不是零。 由于该算法直接在数值上比较两个候选产品，因此它自然可以正确处理零，而不需要特殊情况逻辑。 

最后的边缘情况涉及重复值。 数组如：```
[1, 1, 1, 1]
```或者：```
[-2, -2, -2, -2]
```仍然必须表现得正确。 由于该算法仅依赖于排序位置而不是唯一性，因此可以自然地处理重复项并产生正确的最大乘积。
