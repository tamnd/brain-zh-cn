[LeetCode 第 655 题](https://leetcode.com/problems/print-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们将二叉树转换为格式化的二维字符串矩阵表示。 每个节点必须根据其在树中的位置出现在特定的行和列中。 输出不仅仅是一个遍历顺序，它是树结构的可视化布局。 

我们给出了二叉树的根。 从这棵树中，我们必须构造一个矩阵`res`其中：

 - 行数取决于树的高度。 
- 列数与高度呈指数关系。 
- 每个节点值都放置在仔细计算的列中，以便树看起来居中且对称。 

树的高度定义为从根到叶的最长路径上的边数。 然而，在这个问题中，矩阵行数是`height + 1`，它实际上对应于树中的层数。 

宽度公式为：$$n = 2^{height+1} - 1$$这个宽度保证了每个子树有足够的水平间距。 

放置规则是问题中最重要的部分：

 - 根位于第一行的中心列。 
- 每个左子节点都放置在其子树左边界的中间。 
- 每个右子节点都放置在其子树右边界的中间。 

这种递归间距创建了视觉上平衡的树表示。 

限制相对较小：

 - 最多210个节点
 - 最大深度为 10

 这些限制告诉我们，效率并不是极其关键，但定位的正确性至关重要。 由于最大深度很小，因此即使矩阵大小仍然可以管理：$$2^{11} - 1 = 2047$$所以最大可能的宽度只有2047列。 

一些边缘情况很重要：

 - 一棵只有一个节点的树
 - 完全倾斜的树，其中每个节点只有左或右子节点
 - 树木稀疏，儿童失踪
 - 负节点值
 - 子树高度差异很大的树

 如果不仔细处理递归偏移，简单的实现可能会错误计算间距或将节点放置在矩阵边界之外。 

## 方法

 ### 蛮力方法

 强力方法将尝试通过重复计算每个节点放置的子树宽度来显式模拟布局。 

对于每个节点，我们可以：

 1. 计算其左子树所需的宽度。 
2. 计算其右子树所需的宽度。 
3. 根据这些宽度确定节点的列位置。 
4. 递归地重复该过程。 

这是可行的，因为每个节点的放置取决于其下方的可用水平空间。 

然而，这种方法变得低效，因为子树维度被重新计算了很多次。 如果每个递归调用都重新计算后代的高度或宽度，则会在树上重复重复相同的工作。 

尽管输入大小足够小，这仍然可以通过，但它不必要地昂贵并且更难以推理。 

### 最佳方法

 关键的见解是矩阵维度完全由树高决定。 

一旦我们知道高度：

 - 总行数是固定的。 
- 总列数是固定的。 
- 每个节点位置都可以使用递归中点范围直接计算。 

我们不是重复地重新计算子树宽度，而是递归地将节点分配到区间中：

 - 每个节点拥有一个列范围`[left, right]`。 
- 节点本身放置在中点。 
- 左孩子接收间隔的左半部分。 
- 右边的孩子收到右半边。 

这很自然，因为二叉树布局是递归对称的。 

递归间隔策略很优雅，因为：

 - 每个子树都会自动接收正确的空间量。 
- 不需要重新计算宽度。 
- 放置逻辑变成简单的中点算术。

 ## 算法演练

 ### 步骤 1：计算树高

 我们首先使用 DFS 递归计算树的高度。 

对于每个节点：

 - 空节点的高度为`-1`- 叶节点的高度为`0`- 否则：$$1 + \max(leftHeight, rightHeight)$$我们需要高度，因为它决定了矩阵尺寸和节点间距。 

### 步骤 2：计算矩阵维度

 一旦知道高度：

 - 行数：$$rows = height + 1$$- 列数：$$cols = 2^{height+1} - 1$$然后我们用空字符串初始化矩阵。 

### 第 3 步：开始递归放置

 我们递归地将节点放入矩阵中。 

每个递归调用都会收到：

 - 当前节点
 - 当前行
 - 左列边界
 - 右列边界

 该节点属于中点：$$mid = (left + right) // 2$$我们将节点值放置在：```
matrix[row][mid]
```### 步骤 4：递归到左子树

 左子节点接收当前间隔的左半部分：```
[left, mid - 1]
```这保证了子树在其分配的空间内保持居中。 

### 步骤 5：递归到右子树

 右孩子收到右半部分：```
[mid + 1, right]
```同样，这保持了对称性。 

### 第 6 步：继续，直到放置完所有节点

 递归在以下情况下停止：

 - 节点是`None`- 间隔无效

 最后，每个节点占据其正确的矩阵位置。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 每个子树都被分配一个足够大的列间隔，以对称地包含整个子树。 

由于每个节点始终放置在其间隔的中点，因此其左子树和右子树自然在两侧具有相等的间距。 由于递归精确地反映了树结构，因此所有节点都放置在正确的相对位置。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import List, Optional

class Solution:
    def printTree(self, root: Optional[TreeNode]) -> List[List[str]]:
        
        def get_height(node: Optional[TreeNode]) -> int:
            if not node:
                return -1
            
            return 1 + max(
                get_height(node.left),
                get_height(node.right)
            )
        
        height = get_height(root)
        
        rows = height + 1
        cols = (1 << (height + 1)) - 1
        
        result = [["" for _ in range(cols)] for _ in range(rows)]
        
        def place(
            node: Optional[TreeNode],
            row: int,
            left: int,
            right: int
        ) -> None:
            
            if not node or left > right:
                return
            
            mid = (left + right) // 2
            
            result[row][mid] = str(node.val)
            
            place(node.left, row + 1, left, mid - 1)
            place(node.right, row + 1, mid + 1, right)
        
        place(root, 0, 0, cols - 1)
        
        return result
```实现首先使用递归 DFS 助手计算树的高度。 返回`-1`为了`None`简化了高度公式，因为叶子节点自然就变成了高度`0`。 

计算高度后，矩阵尺寸直接从问题陈述中给出的公式导出。 

矩阵完全用空字符串初始化，因为每个未使用的单元格必须包含`""`。 

递归`place`函数执行实际的布局逻辑。 每次调用都会接收当前子树的有效列范围。 该范围的中点成为节点的位置。 然后将区间分为左子树和右子树两个较小的区间。 

这种递归区间细分完全符合所需的格式化规则。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func printTree(root *TreeNode) [][]string {

    var getHeight func(node *TreeNode) int

    getHeight = func(node *TreeNode) int {
        if node == nil {
            return -1
        }

        leftHeight := getHeight(node.Left)
        rightHeight := getHeight(node.Right)

        if leftHeight > rightHeight {
            return leftHeight + 1
        }

        return rightHeight + 1
    }

    height := getHeight(root)

    rows := height + 1
    cols := (1 << (height + 1)) - 1

    result := make([][]string, rows)

    for i := 0; i < rows; i++ {
        result[i] = make([]string, cols)
    }

    var place func(
        node *TreeNode,
        row int,
        left int,
        right int,
    )

    place = func(
        node *TreeNode,
        row int,
        left int,
        right int,
    ) {
        if node == nil || left > right {
            return
        }

        mid := (left + right) / 2

        result[row][mid] = strconv.Itoa(node.Val)

        place(node.Left, row+1, left, mid-1)
        place(node.Right, row+1, mid+1, right)
    }

    place(root, 0, 0, cols-1)

    return result
}
```Go 实现遵循与 Python 版本相同的递归间隔策略。 

Go 特有的一个重要细节是切片会自动用空字符串初始化，因此我们不需要手动填充矩阵。 

另一个区别是整数到字符串的转换。 Go 需要`strconv.Itoa()`在将节点值存储到矩阵之前转换它们。 

递归结构和中点计算保持相同。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + 2^h) | O(n + 2^h) | DFS 访问每个节点一次，矩阵初始化支配宽度 |
 | 空间| O(2^h × h) | O(2^h × h) | 矩阵存储加递归栈|

 DFS高度计算需要`O(n)`时间。 放置 DFS 也会访问每个节点一次，从而贡献另一个节点`O(n)`。 

然而，初始化矩阵需要分配：$$(height + 1) \times (2^{height+1} - 1)$$单元格，它在大高度的运行时中占主导地位。 

空间复杂度同样由输出矩阵本身决定。 递归栈最多添加`O(h)`额外的空间。

 ## 边缘情况

 单节点树是可能的最小输入，并且很容易暴露高度或宽度计算中的差一错误。 如果高度计算不正确，算法可能会分配零列或将节点放置在矩阵之外。 此实现可以正确处理它，因为叶节点具有高度`0`，产生一个`1 × 1`矩阵。 

完全倾斜的树是另一个重要的边缘情况。 在左偏或右偏树中，递归间隔在一侧变得非常窄，而在另一侧保持空。 不正确的中点计算可能会导致重叠放置或无效索引。 递归间隔细分保证每个节点仍然收到有效位置。 

缺少孩子的稀疏树特别容易出错，因为递归放置必须跳过`None`节点而不破坏子树对齐。 此实现通过在节点出现时立即返回来自然地处理丢失的子节点。`None`，同时仍然保留现有后代的正确间隔。 

负节点值也值得关注，因为输出矩阵存储字符串，而不是整数。 忘记转换会产生类型错误。 两种实现都在插入矩阵之前显式地将节点值转换为字符串。
