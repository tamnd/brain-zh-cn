[LeetCode 第 646 题](https://leetcode.com/problems/maximum-length-of-pair-chain/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、贪心、排序

 ## 解决方案

 ## 问题理解

 该问题给了我们一个整数对数组，其中每对代表一种类似于区间的关系，其形式为`[left, right]`。 每对都满足条件`left < right`。 

我们想要构建尽可能最长的配对链。 一对`[c, d]`可以跟随另一对`[a, b]`仅当：```
b < c
```这个条件很严格。 平等还不够。 例如，`[1,2]`不能跟随`[2,3]`因为`2 < 2`是假的。 

重要的细节是这些对可以以任何方式重新排序。 我们不限于原始输入顺序。 因此，我们的任务是选择对的子集并对其进行排列，以便每个相邻的对都满足链接条件。 

输出是一个整数，表示该链的最大可能长度。 

限制相对较小：

 -`1 <= n <= 1000`- 对值范围为`-1000`到`1000`1000 的大小足够大，以至于指数暴力是不切实际的，但也足够小，以至于`O(n^2)`动态规划解决方案是可以接受的。 它还允许我们在排序后考虑贪婪的解决方案。 

一些边缘情况很重要：

 - 接触但未正确重叠的对，例如`[1,2]`和`[2,3]`，无法链接，因为条件严格`<`。 
- 允许负值，因此排序逻辑也必须对负数正确工作。 
- 多个重叠货币对可能会迫使我们在短期收益和长期收益之间谨慎选择。 
- 应返回单对输入`1`。 
- 完全不相交的对可以全部链接在一起。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试每个可能的子集和每个可能的对排序，以确定是否可以形成有效的链。 

考虑这个问题的一种方法是将其视为递归回溯过程：

 - 从每一对开始。 
- 尝试附加可以合法跟随它的所有剩余对。 
- 递归地继续构建链。 
- 跟踪找到的最大链长度。 

这种方法是正确的，因为它探索了每一种有效的可能性。 最终，最长的有效链将会被发现。 

然而，这种解决方案效率极低。 可能的排序数量会呈阶乘增长，即使对于中等大小的输入，递归分支也会变得巨大。 对于多达 1000 对，这种方法是完全不可行的。 

### 关键见解

 该问题在结构上与间隔调度非常相似。 

假设我们按结束值对对进行排序。 如果我们总是选择最早完成的一对，我们就会为未来的配对留下尽可能多的空间。 

这与经典活动选择问题中使用的贪心原则相同：

 - 选择最终值较小的对可以为未来的链接提供更多机会。 
- 选择最终价值较大的货币对可能会不必要地阻止未来的选择。 

一旦对按第二个值排序，我们就可以通过始终采用下一个兼容对来贪婪地构建最长的链。 

这是有效的，因为在我们接下来可以选择的所有候选对中，具有最小最终值的候选对总是至少与任何其他选择一样好。

 ## 算法演练

 ### 最优贪心算法

 1. 按结束值对所有对进行排序。 

我们使用每对的第二个元素进行排序。 这确保了先完成的对被首先考虑。 较早完成的配对更加灵活，因为它们为未来的配对留下了更多空间。 
2. 初始化链长。 

我们保留一个名为`chain_length`来计算我们在链中包含了多少对。 
3. 跟踪最后选择的一对的末尾。 

我们维护一个名为`current_end`。 最初，这可能是负无穷大，因为尚未选择任何对。 
4. 迭代已排序的对。 

对于每对`[left, right]`，检查它是否可以跟随先前选择的对。 
5. 检查链接情况。 

如果：```
current_end < left
```那么这一对就可以合法地延长链条。 
6. 选择有效的配对。 

当配对兼容时：

 - 增量`chain_length`- 更新`current_end = right`这意味着当前对成为链的新尾部。 
7. 继续，直到处理完所有对。 

到遍历结束时，`chain_length`包含最大可能的链大小。 

### 为什么它有效

 贪婪策略之所以有效，是因为选择最终值最小的对总是保留最大可能的未来搜索空间。 

假设接下来可以选择两个候选对：

 - A组提前结束
 - B组稍后结束

 如果我们选择 A 组，则每对可以跟随 B 组的人也可以跟随 A 组，甚至可能更多对。 因此，选择较早结束的一对永远不会更糟糕。 

这种贪婪选择性质保证了最优性。 

## Python 解决方案```python
from typing import List

class Solution:
    def findLongestChain(self, pairs: List[List[int]]) -> int:
        pairs.sort(key=lambda pair: pair[1])

        chain_length = 0
        current_end = float("-inf")

        for left, right in pairs:
            if current_end < left:
                chain_length += 1
                current_end = right

        return chain_length
```实现首先根据结束值对对进行排序。 这是启用贪婪策略的关键预处理步骤。 

变量`chain_length`跟踪链中包含多少对。 变量`current_end`存储最近选择的对的结束值。 

在迭代过程中，每对都会根据链接规则进行检查。 如果该对在当前链端点之后开始，则它被选择并成为新的链尾。 

因为这些对是按照最终值递增的顺序处理的，所以每个选定的对都是最佳的局部选择，并导致全局最优解。 

## 解决方案```go
package main

import "sort"

func findLongestChain(pairs [][]int) int {
	sort.Slice(pairs, func(i, j int) bool {
		return pairs[i][1] < pairs[j][1]
	})

	chainLength := 0
	currentEnd := -1001

	for _, pair := range pairs {
		left := pair[0]
		right := pair[1]

		if currentEnd < left {
			chainLength++
			currentEnd = right
		}
	}

	return chainLength
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

主要区别在于排序语法。 Go 使用`sort.Slice`具有自定义比较功能。 

Go 解决方案没有使用负无穷大，而是初始化`currentEnd`到`-1001`，它安全地小于基于约束的最小可能输入值。 

切片很自然地被使用，因为 LeetCode 将输入表示为`[][]int`。

 ## 边缘情况

 一种重要的边缘情况是在边界处接触但不满足严格链接条件的对。 例如，`[1,2]`和`[2,3]`无法形成链，因为条件需要`2 < 2`，这是错误的。 一个常见的错误是使用`<=`而不是`<`。 实施明确检查`current_end < left`，它正确地执行了严格的不平等。 

另一个重要的边缘情况是存在与许多较小间隔重叠的非常大的间隔。 例如，`[1,100]`尽早选择似乎很诱人，但这样做可以防止多个较短的兼容间隔链接在一起。 贪心策略通过对结束值进行排序并自然地优先选择较短的结束间隔来避免此错误。 

负数也很重要，因为排序和比较必须独立于符号进行。 输入如`[[-10,-5],[-4,-1],[0,3]]`证明该算法可以正确处理低于零的值，而不需要任何特殊情况逻辑。 

重复的间隔形成了另一个微妙的情况。 如果存在多个相同的对，则通常只有一对可以参与链，因为它们的范围完全重叠。 贪婪遍历自然地通过选择第一个兼容间隔并在不满足链接条件时拒绝其余间隔来处理此问题。
