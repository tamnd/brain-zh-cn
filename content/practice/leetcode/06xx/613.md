 # LeetCode 613，直线最短距离

 ## 问题理解

 这个问题给了我们一个名为`Point`包含 X 轴上的整数坐标。 每一行代表一个点，每一列代表一个点`x`是唯一的，因为它是主键。 

任务是计算表中任意两点之间的最小绝对距离。 

从数学上来说，对于每对点`(a, b)`，我们要计算：$$|a - b|$$并返回所有可能对中的最小值。 

例如，如果点是：```
-1, 0, 2
```两两距离为：```
|-1 - 0| = 1
|-1 - 2| = 3
|0 - 2| = 2
```最小距离是`1`，因此输出应包含：```
+----------+
| shortest |
+----------+
| 1        |
+----------+
```重要的观察结果是该表包含一维线上的点。 在一个维度中，对值进行排序后，最近的一对点必须相邻。 

后续询问如果表已经按升序排序，我们如何优化解决方案。 这一暗示强烈表明排序或邻接是关键的见解。 

有几种边缘情况值得考虑：

 - 该表可能只包含两个点，在这种情况下，答案只是它们的距离。 
- 点数可能包含负数，因此需要绝对差。 
- 这些点是独一无二的，因为`x`是主键，因此不会出现重复的坐标。 
- 排序后，最小距离可能出现在任何相邻值之间，不一定是第一对或最后一对。 

## 方法

 ### 蛮力方法

 最直接的解决方案是比较每一对点。 

对于每个点`p1`，我们将其与其他所有点进行比较`p2`，计算：$$|p1.x - p2.x|$$并记录找到的最小值。 

这是有效的，因为它会详尽地检查所有可能的对，保证发现最小距离。 

然而，如果有`n`点，有：$$\frac{n(n-1)}{2}$$可能的对。 这会导致时间复杂度呈二次方，对于大型数据集来说效率很低。 

在 SQL 中，这可以通过自连接来实现：```sql
SELECT MIN(ABS(p1.x - p2.x)) AS shortest
FROM Point p1
JOIN Point p2
ON p1.x < p2.x;
```尽管这种方法是正确的，但它会进行不必要的比较。 

### 最佳方法

 关键的见解是，对点进行排序后，最小距离只能出现在相邻点之间。 

考虑排序值：```
x1 < x2 < x3 < x4
```如果`x1`和`x3`是最接近的一对，那么：```
x2 - x1 < x3 - x1
```这意味着`x1`和`x3`实际上不可能是最接近的一对，因为`x2`位于他们之间。 

因此，我们只需在排序后比较相邻点即可。 

在 SQL 中，我们可以使用以下方法有效地实现这一点：`LEAD()`窗口函数：```sql
SELECT MIN(next_x - x) AS shortest
FROM (
    SELECT x,
           LEAD(x) OVER (ORDER BY x) AS next_x
    FROM Point
) t
WHERE next_x IS NOT NULL;
```这种方法避免了不必要的成对比较并直接计算相邻差异。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 比较每对点 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(n) | 对点进行排序并仅检查相邻差异 |

 ## 算法演练

 ### 最优算法

 1. 将所有点按照它们的升序排序`x`协调。 

排序很重要，因为一维中最接近的点对在排序后必须彼此相邻出现。 
2. 从左到右迭代排序后的点。 

对于每个点，仅将其与排序顺序中的下一个点进行比较。 
3. 计算相邻点之间的差异。 

由于数组已排序：```
next_x - current_x
```始终为非负数，因此不需要绝对值。 
4. 保持最小跑步距离。 

每次发现较小的相邻差异时，更新答案。 
5. 返回遍历过程中发现的最小距离。 

### 为什么它有效

 该算法依赖于线上点的基本排序属性。 排序后，任何不相邻的对之间必须至少有一个点。 该中间点产生的距离小于或等于非相邻点对的距离。 因此，全局最小距离必须按排序顺序出现在相邻点之间。 

由于该算法仅检查所有相邻对一次，因此可以保证找到正确的最小距离。 

## Python 解决方案```python
class Solution:
    def shortestDistance(self, points: List[int]) -> int:
        points.sort()

        minimum_distance = float("inf")

        for index in range(1, len(points)):
            current_distance = points[index] - points[index - 1]
            minimum_distance = min(minimum_distance, current_distance)

        return minimum_distance
```实现首先对点列表进行排序。 这确保了最接近的一对（如果存在）必须连续出现。 

变量`minimum_distance`存储迄今为止找到的最佳答案。 它被初始化为无穷大，以便在第一次比较期间任何实际距离都将取代它。 

循环从索引处开始`1`因为每个点都会与前一个点进行比较。 由于列表已排序，因此减去连续元素可以直接得出它们之间的距离。 

对于每个相邻对，该算法计算距离并更新运行最小值。 

最后，返回发现的最小距离。 

虽然最初的 LeetCode 问题被归类为数据库并需要 SQL，但这个 Python 实现清楚地展示了核心算法思想。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func shortestDistance(points []int) int {
	sort.Ints(points)

	minimumDistance := math.MaxInt32

	for i := 1; i < len(points); i++ {
		currentDistance := points[i] - points[i-1]

		if currentDistance < minimumDistance {
			minimumDistance = currentDistance
		}
	}

	return minimumDistance
}
```Go 实现遵循与 Python 版本相同的逻辑。 

切片使用排序`sort.Ints`。 由于 Go 没有内置的整数无穷大值，`math.MaxInt32`用作初始大值`minimumDistance`。 

该循环将每个元素与其前一个邻居进行比较，并在找到较小值时更新最小差异。 

由于点首先排序，因此减法始终会产生非负值。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 排序在运行时占据主导地位
 | 空间| O(1) 或 O(n) | 取决于排序实现 |

主要成本来自于对点进行排序。 大多数排序算法需要`O(n log n)`时间。 

额外的空间取决于语言和排序实现。 一些排序算法就地运行，而另一些则分配临时内存。

 ## 边缘情况

 ### 只有两点

 最小的有效输入恰好包含两个点。 在这种情况下，只有一对可能的，因此算法必须正确返回它们的距离，而无需额外的假设。 

该实现自然地处理了这个问题，因为循环只执行一次并计算两个排序值之间的差异。 

### 负坐标

 点可以为负数，因为它们代表 X 轴上的位置。 假设正数的简单实现可能会产生不正确的结果。 

排序可确保值按数字顺序排序，并且减去相邻的排序值始终会产生正确的非负距离。 

### 未排序的输入

 输入点最初可能不会按升序出现。 如果算法仅比较相邻元素而不首先排序，则可能会错过真正的最小距离。 

例如：```
[8, 1, 3]
```实际最短距离为`1`和`3`，不在原始相邻值之间。 

该实现通过在进行任何比较之前进行排序来避免此问题。 

### 大坐标间隙

 某些输入可能在大多数点之间包含非常大的距离，只有一个小间隙隐藏在列表中的某处。 

由于该算法在排序后系统地检查每个相邻对，因此无论坐标间隔多么不均匀，它都不会错过真正的最小值。
