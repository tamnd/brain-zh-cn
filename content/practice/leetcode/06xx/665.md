[LeetCode 第 665 题](https://leetcode.com/problems/non-decreasing-array/)

 **难度：** 🟡 中等
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题询问是否可以通过最多修改一个元素将给定的整数数组转换为非递减数组。 

非递减数组意味着每个元素都小于或等于它后面的元素。 形式上，对于每个有效索引`i`，条件`nums[i] <= nums[i + 1]`必须持有。 

输入是一个数组`nums`含有`n`整数。 我们最多可以将一个元素的值更改为我们想要的任何整数。 目标是确定这样的修改是否可以使整个数组不减。 

例如，考虑数组`[4,2,3]`。 该问题可以通过更改第一个元素来解决`4`到`1`，生产`[1,2,3]`，这是非递减的。 然而，数组`[4,2,1]`无法仅通过一项修改来修复，因为存在多种递减关系。 

约束条件很重要：

 - 数组长度最大可达`10^4`- 值的范围可以是`-10^5`到`10^5`一个`O(n^2)`技术上解决方案仍然会通过`10^4`在某些语言中，但这是低效且不必要的。 该问题是为线性时间贪婪解决方案而设计的。 

一些边缘情况很重要：

 - 长度数组`1`始终有效，因为没有相邻比较。 
- 已经非递减的数组应立即返回`true`。 
- 数组开头或结尾附近的违规行为需要小心处理。 
- 具有重复值的数组仍必须算作非递减数组，因为允许相等。 
- 某些数组仅包含一个反转，但错误地修改任一侧可能会产生新的违规。 

简单的实现常常会失败，因为修复一个递减的对可能会意外破坏数组的另一部分。 

## 方法

 ### 蛮力方法

 蛮力策略会尝试每一种可能的修改。 

对于数组中的每个索引，我们假装将该元素修改为每个可能有用的值，然后检查数组是否变为非递减。 由于值不受限制，因此实际的强力实现通常会尝试用可以解决违规问题的相邻值替换元素。 

另一种暴力变体是通过创建数组的修改副本并验证它们来测试单独消除每个反转的影响。 

这种方法是正确的，因为它明确地探索了所有可能的单元素修复。 然而，它的效率很低，因为每次尝试的修改都需要再次扫描数组以验证有效性。 

重复的重新扫描导致时间复杂度成二次方。 

### 最优贪心法

 关键的观察是，如果非递减数组可以通过一次修改来修复，那么它最多可以包含一次违规。 

当出现以下情况时，就会发生违规：```
nums[i] > nums[i + 1]
```当我们遇到这样的一对时，我们必须决定修改哪个元素：

 - 较低`nums[i]`- 增加`nums[i + 1]`重要的见解是，我们可以通过向后看一步来在本地确定正确的选择。 

如果`nums[i - 1] <= nums[i + 1]`，然后降低`nums[i]`是安全的。 

否则，我们必须提高`nums[i + 1]`。 

这种贪婪的决定之所以有效，是因为我们只关心保留已处理的前缀，同时消除当前的违规。 

一旦我们遇到不止一次违规行为，答案必须是`false`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 尝试修复每个位置并重新检查数组 |
 | 最佳 | O(n) | O(1) | O(1) | 在单次传递中贪婪地修复最多一次违规 |

 ## 算法演练

 1. 开始从左到右扫描阵列。 

我们比较每一个相邻的对`nums[i]`和`nums[i + 1]`检测是否违反非递减条件。 
2. 设立违规柜台。 

每次我们发现`nums[i] > nums[i + 1]`，我们递增计数器。 如果计数器超过`1`，我们立即返回`false`因为需要进行不止一项修改。 
3. 决定修改哪个元素。 

当发现违规行为时，我们必须以最安全的方式进行修复。 

假设我们检测到：```
nums[i] > nums[i + 1]
```我们检查前一个元素：

 - 如果`i == 0`，没有前一个元素，所以降低`nums[i]`总是安全的。 
- 如果`nums[i - 1] <= nums[i + 1]`，我们降低`nums[i]`到`nums[i + 1]`。 
- 否则，我们提出`nums[i + 1]`到`nums[i]`。 
4.修改后继续扫描。 

该阵列已就地更新，因此将来的比较可以看到修复后的版本。 
5. 返回`true`如果没有发现超过一处违规行为。 

### 为什么它有效

 该算法保持了不变式，即到目前为止处理的前缀在最多一次修改后始终不减少。 

每当出现违规时，贪婪修复都会最大限度地减少对早期元素的破坏。 当左侧元素保留与前一个元素的顺序时，首选降低左侧元素。 否则，需要提高正确的元素。 

由于每一次违规都需要至少进行一次修改，因此遇到不止一次违规就证明仅通过一次更改无法修复数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def checkPossibility(self, nums: List[int]) -> bool:
        violations = 0

        for i in range(len(nums) - 1):
            if nums[i] > nums[i + 1]:
                violations += 1

                if violations > 1:
                    return False

                if i == 0 or nums[i - 1] <= nums[i + 1]:
                    nums[i] = nums[i + 1]
                else:
                    nums[i + 1] = nums[i]

        return True
```实现首先初始化一个名为`violations`。 这跟踪已找到多少个递减对。 

循环从左到右扫描相邻元素。 每当`nums[i] > nums[i + 1]`，该数组违反了非递减要求。 

如果发生不止一次违规，该函数立即返回`False`因为一次修改无法修复多个独立的问题。 

修复逻辑是算法的核心。 如果前一个元素不冲突`nums[i + 1]`，我们降低`nums[i]`。 否则，我们提出`nums[i + 1]`。 

该数组已就地修改，以便将来的比较使用更正后的值。 这使得算法能够在恒定的额外空间中运行。 

如果扫描完成时最多出现一次违规，则该函数返回`True`。 

## 解决方案```go
func checkPossibility(nums []int) bool {
    violations := 0

    for i := 0; i < len(nums)-1; i++ {
        if nums[i] > nums[i+1] {
            violations++

            if violations > 1 {
                return false
            }

            if i == 0 || nums[i-1] <= nums[i+1] {
                nums[i] = nums[i+1]
            } else {
                nums[i+1] = nums[i]
            }
        }
    }

    return true
}
```Go 实现遵循与 Python 解决方案相同的贪婪策略。 

Go 中的切片是对底层数组的可变引用，因此修改自然会发生。 不需要额外的内存分配。 

整数溢出不是问题，因为该算法仅执行比较和赋值，而不执行算术运算。 

自动返回空或单元素切片`true`因为循环永远不会发现违规。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 从左到右扫描一次数组 |
 | 空间| O(1) | O(1) | 无论输入大小如何，仅使用几个变量 |

 该算法对数组执行单次遍历，对每个相邻对进行一次比较。 每个元素都会被处理固定次数，因此运行时间是线性的。 

不使用辅助数据结构。 所有修改都直接发生在输入数组内部，因此额外的空间使用量保持不变。

 ## 边缘情况

 当违规出现在数组开头时，就会出现一种重要的边缘情况。 例如，`[4,2,3]`之前没有前一个元素`4`。 粗心的实现可能会尝试访问`nums[-1]`或者错误地应用正常逻辑。 该实现使用条件显式处理此问题`i == 0`，允许安全降低第一个元件。 

当降低左侧元素会与前一个值产生新的冲突时，会发生另一个棘手的情况。 考虑`[3,4,2,3]`。 如果我们降低`4`到`2`，数组变为`[3,2,2,3]`，这仍然无效，因为`3 > 2`。 该算法通过检查是否`nums[i - 1] <= nums[i + 1]`。 如果没有，它会引发正确的元素。 

具有重复值的数组是微妙错误的另一个来源。 某些实现错误地强制执行严格的递增顺序而不是非递减顺序。 例如，`[2,2,2]`应该返回`true`。 实现正确使用了条件`>`而不是`>=`，允许相邻值相等。 

最后一个边缘案例涉及多次远程违规。 例如，`[5,1,4,2]`包含两个单独的递减对。 天真的贪婪算法可能会修复第一个问题并错误地假设成功。 此实现跟踪违规总数并立即返回`false`一旦计数超过一。`
