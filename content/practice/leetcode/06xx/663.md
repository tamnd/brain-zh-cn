[LeetCode 第 663 题](https://leetcode.com/problems/equal-tree-partition/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题询问是否可以将二叉树拆分为两棵独立的树，使得两棵生成的树具有相同的节点值之和。 分裂必须通过从原始树中恰好删除一条边来进行。 

二叉树通过其根节点给出。 每个节点都包含一个整数值，并且每个节点可能有一个左子节点和一个右子节点。 当删除一条边时，树会分成两个不相连的组件。 每个分量形成一棵有效的树，我们必须确定这两棵树中的值之和是否相等。 

另一种思考问题的方式是：如果整棵树的总和是`S`，然后在删除一条边后，我们需要一棵具有总和的子树`S / 2`，因为树的剩余部分自动具有总和`S - S / 2 = S / 2`。 

约束条件很重要：

 - 树最多可以包含`10^4`节点。 
- 节点值可能为负。 
- 值范围为`-10^5`到`10^5`。 

这些限制立即排除了效率极低的方法。 由于树可能相当大，因此从头开始重复重新计算子树和会变得太慢。 

还有几个重要的边缘情况：

 - 一棵只有一个节点的树不能被分割，因为没有边可以删除。 
- 总和为奇数的树永远不能被平均划分。 
- 负值可以创建重复或相互抵消的子树和。 
- 总和为零需要特殊处理，因为可能存在多个零和子树。 
- 整个树本身不能算作分区的一侧，因为删除边缘必须产生两棵非空树。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是考虑树中的每个边并模拟删除它。 对于每个可能的删除，我们计算断开的子树的总和并将其与剩余的树总和进行比较。 

为了简单地做到这一点，我们可以遍历每个节点并将以该节点为根的子树视为分区的一侧。 对于每个节点，我们从头开始递归计算子树和。 

这种方法是正确的，因为每个可移动边都对应于一个子树。 如果任何子树之和等于总树之和的一半，则删除连接该子树与其父树的边会生成两棵等和树。 

问题是效率。 假设树包含`n`节点。 计算子树和需要`O(n)`最坏情况下的时间，对每个节点执行此操作会导致`O(n^2)`复杂。 高达`10^4`节点，这变得太慢了。 

### 最佳方法

 关键的观察结果是子树和严重重叠。 我们可以使用后序深度优先搜索将每个子树总和精确计算一次，而不是重复地重新计算它们。 

在后序遍历期间：

 - 我们首先计算左子树和。 
- 然后计算右子树和。 
- 最后计算当前节点的子树和。 

当我们计算子树总和时，我们将它们存储在哈希集或列表中。 一旦我们知道了树的总和，我们只需要检查是否有任何真子树的总和等于总和的一半。 

这是有效的，因为删除子树上方的边可以将该子树与树的其余部分完全分开。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 重复重新计算子树和 |
 | 最佳 | O(n) | O(n) | 使用 DFS | 计算每个子树和一次

 这里，`h`代表树的高度。 

## 算法演练

 1. 从树的后序深度优先遍历开始。 

后序遍历很重要，因为子树的总和取决于其子树的总和。 我们必须在父节点之前处理子节点。 
2. 对于每个节点，递归计算左子树的和。 

如果该节点没有左子节点，则贡献为`0`。 
3. 递归计算右子树的和。 

同样，缺失的右孩子也有贡献`0`。 
4. 计算当前子树之和。 

子树之和为：$\text{subtreeSum} = \text{node.val} + \text{leftSum} + \text{rightSum}$将此值存储在列表或哈希集中。 
5. 继续直到遍历完成。 

遍历结束时，最终计算出的和就是整棵树的总和。 
6. 不考虑树的总和。 

整个树本身不能用作分区的一侧，因为没有边缘去除会隔离整个树。 
7. 检查总和是否为偶数。 

如果总和是奇数，则不可能进行等分，因为两个相等的整数相加不可能是奇数。 
8. 搜索`totalSum / 2`在存储的子树和中。 

如果存在这样的子树，则删除将该子树连接到其父树的边会创建两棵总和相等的树。 

### 为什么它有效

 每个可移动边恰好对应一个子树。 删除子树上方的边会将该子树与树的其余部分分开。 因此，问题简化为确定任何真子树的总和是否等于总树总和的一半。 

后序 DFS 可确保正确计算每个子树总和，因为子树总和在处理父树之前就已确定。 由于每个子树和都计算一次并检查一次，因此该算法既正确又高效。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, List

class Solution:
    def checkEqualTree(self, root: Optional[TreeNode]) -> bool:
        if not root:
            return False

        subtree_sums: List[int] = []

        def dfs(node: Optional[TreeNode]) -> int:
            if not node:
                return 0

            left_sum = dfs(node.left)
            right_sum = dfs(node.right)

            current_sum = node.val + left_sum + right_sum
            subtree_sums.append(current_sum)

            return current_sum

        total_sum = dfs(root)

        # Remove the total sum of the whole tree
        subtree_sums.pop()

        # Equal partition impossible if total sum is odd
        if total_sum % 2 != 0:
            return False

        target = total_sum // 2

        return target in subtree_sums
```该实现遵循最优算法的精确结构。 

这`dfs`函数执行后序遍历。 对于每个节点，它首先计算左子树和和右子树和。 一旦两者都知道，它就会计算当前子树的总和并将其存储在`subtree_sums`。 

遍历完成后，`total_sum`包含整棵树的总和。 由于完整的树不能代表分区的一侧，因此添加到的最后一个值`subtree_sums`被删除`pop()`。 

然后算法检查总和是否为偶数。 如果是奇数，则立即给出答案`False`。 

最后，代码搜索`total_sum // 2`在存储的子树和中。 如果找到，则存在有效分区。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func checkEqualTree(root *TreeNode) bool {
    if root == nil {
        return false
    }

    subtreeSums := []int{}

    var dfs func(node *TreeNode) int

    dfs = func(node *TreeNode) int {
        if node == nil {
            return 0
        }

        leftSum := dfs(node.Left)
        rightSum := dfs(node.Right)

        currentSum := node.Val + leftSum + rightSum
        subtreeSums = append(subtreeSums, currentSum)

        return currentSum
    }

    totalSum := dfs(root)

    // Remove total tree sum
    subtreeSums = subtreeSums[:len(subtreeSums)-1]

    if totalSum%2 != 0 {
        return false
    }

    target := totalSum / 2

    for _, sum := range subtreeSums {
        if sum == target {
            return true
        }
    }

    return false
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用切片而不是 Python 列表。 子树总和存储在名为的切片中`subtreeSums`。 

Go不直接支持嵌套命名函数，因此递归DFS是使用函数变量声明的：```go
var dfs func(node *TreeNode) int
```Nil 指针使用显式处理`node == nil`。 

由于 Go 整数除法会自动截断为零，因此检查`totalSum % 2 != 0`首先保证目标总和的安全划分。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(n) | 存储子树和和递归堆栈 |

 DFS 遍历对每个节点只处理一次，给出线性时间复杂度。 

空间使用有两个来源：

 - 递归栈，可能达到`O(h)`在哪里`h`是树的高度。 
- 这`subtree_sums`列表，每个节点存储一个总和。 

在倾斜树的最坏情况下，递归深度可以变为`O(n)`。

 ## 边缘情况

 ### 单节点树

 一棵只有一个节点的树无法分区，因为没有可以删除的边。 幼稚的实现可能会错误地认为子树总和等于总数的一半就足够了，但问题明确需要删除一条边。 

此实现可以正确处理这种情况，因为存储的唯一子树总和是总树总和本身，在检查有效分区之前将其删除。 

### 总和为零

 零是一个棘手的情况，因为如果总和为零，则目标子树和也为零。 多个子树的总和可能为零，重要的是不要计算整个树本身。 

例如：```
    0
   / \
  0   0
```该实现在搜索之前从列表中删除总树总和，确保只考虑正确的子树。 

### 负节点值

 负值可能会产生意外的子树总和。 例如，正值和负值可能会相互抵消。 

假设所有总和均为正数的解决方案在这里可能会严重失败。 此实现可以正常工作，因为它将子树和视为普通整数，而不对符号或顺序进行假设。 

### 高度倾斜的树

 倾斜树的行为类似于链表，并产生最大递归深度。 

例如：```
1
 \
  1
   \
    1
```该算法仍然运行在`O(n)`时间，因为每个节点都被处理一次。 递归堆栈可能会增长到`O(n)`在最坏的情况下，这已经反映在空间复杂度分析中。
