 ## 解决方案

 ## 问题理解

 该问题要求我们计算数字的排列有多少种`1`通过`n`是有效的混乱。 混乱是一种排列，其中没有元素保留在其原始位置。 

例如，当`n = 3`，原数组是`[1, 2, 3]`。 像这样的排列`[2, 3, 1]`有效，因为：

 -`1`不在索引处`0`-`2`不在索引处`1`-`3`不在索引处`2`然而，`[1, 3, 2]`不是精神错乱，因为`1`保持在原来的位置。 

输入由单个整数组成`n`，输出应该是有效排列总数模`10^9 + 7`。 

约束条件很重要：

 -`1 <= n <= 10^6`值为`10^6`对于组合生成来说非常大。 这立即告诉我们显式生成排列是不可能的。 由于排列数为`n!`，即使很小的值也会很快变得很大。 

这意味着我们需要一种具有线性或接近线性复杂度的数学或动态规划方法。 

一些边缘情况尤其重要：

 -`n = 1`，没有办法在不将一个元素保持在原位的情况下重新排列它，所以答案是`0`-`n = 2`， 仅有的`[2,1]`有效，所以答案是`1`- 非常大`n`，其中溢出成为一个问题，这意味着在计算过程中必须应用模算术
 - 未经优化的递归解决方案可能会导致堆栈溢出`n`## 方法

 ### 蛮力方法

 强力解决方案将生成数组的每个排列`[1,2,...,n]`并检查每个元素是否与其原始位置不同。 

对于每个排列：

 1.将每个位置与原数组进行比较
 2. 如果没有位置匹配，则增加答案

 这种方法是正确的，因为它详尽地检查了每种可能的安排。 

然而，排列的数量是`n!`，增长速度极快：

 -`10! = 3,628,800`-`15!`已经超过一万亿

 自从`n`可以大到`10^6`，暴力破解是完全行不通的。 

### 最优动态规划方法

 关键的观察是，紊乱遵循众所周知的递归关系。 

让`D(n)`代表混乱的数量`n`元素。 

我们推导递归如下：

 取元`1`。 

因为它无法保持原位`1`，它必须进入另一个`n - 1`职位。 

假设它就位`k`。 

现在考虑最初位于位置的元素`k`。 

有两种可能：

 1. 该元件移动到位`1`2. 该元件未移动到位`1`这两种情况直接导致复发：$$D(n) = (n - 1) \times (D(n - 1) + D(n - 2))$$与基本情况：$$D(1) = 0$$

$$D(2) = 1$$这种递归使我们能够在线性时间内迭代计算答案。$D(n)=(n-1)(D(n-1)+D(n-2))$## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n) | O(n! × n) | O(n!) | 生成每个排列并检查有效性 |
 | 最优动态规划| O(n) | O(1) | O(1) | 使用混乱递推关系 |

 ## 算法演练

 1. 定义模常数`MOD = 10^9 + 7`。 

由于结果增长得非常快，因此必须在每个计算步骤中应用模运算以避免溢出。 
2. 处理小型基本案例。 

递归取决于先前的值，因此我们必须初始化：

 -`D(1) = 0`-`D(2) = 1`3. 存储前两次混乱计数。 

我们不需要维护整个 DP 数组，而只需要两个最新的值：

 -`prev2 = D(n-2)`-`prev1 = D(n-1)`这降低了空间复杂度`O(n)`到`O(1)`。 
4. 迭代自`3`到`n`。 

对于每个值：$$D(i) = (i - 1) \times (D(i-1) + D(i-2))$$计算值后立即应用模运算。 
5. 向前移动变量。 

计算当前的混乱计数后：

 -`prev2 = prev1`-`prev1 = current`6. 返回最终计算值。 

循环完成后，`prev1`包含`D(n)`。 

### 为什么它有效

 递归之所以有效，是因为每个混乱都可以根据第一个元素移动的位置进行分类。 

如果元素`1`移动到位置`k`，然后：

 - 位于的元素`k`交换回位置`1`，产生大小的子问题`n-2`- 或者它移动到其他地方，产生大小的子问题`n-1`有`n-1`选择`k`，所以乘以`n-1`一次就解释了所有有效的可能性。 

## Python 解决方案```python
class Solution:
    def findDerangement(self, n: int) -> int:
        MOD = 10**9 + 7

        if n == 1:
            return 0

        if n == 2:
            return 1

        prev2 = 0  # D(1)
        prev1 = 1  # D(2)

        for i in range(3, n + 1):
            current = (i - 1) * (prev1 + prev2) % MOD
            prev2 = prev1
            prev1 = current

        return prev1
```实现首先定义模常数并直接处理最小的边缘情况。 

变量`prev2`和`prev1`表示递归关系所需的两个先前计算的混乱值。 

该循环迭代地计算混乱计数`3`最多`n`。 在每一步中，都会应用递推关系，并进行模运算以确保值保持在界限内。 

因为只需要前两个状态，所以该实现避免了存储完整的 DP 数组并实现了恒定的额外内存使用。 

## 解决方案```go
func findDerangement(n int) int {
    const MOD int = 1000000007

    if n == 1 {
        return 0
    }

    if n == 2 {
        return 1
    }

    prev2 := 0 // D(1)
    prev1 := 1 // D(2)

    for i := 3; i <= n; i++ {
        current := ((i - 1) * (prev1 + prev2)) % MOD
        prev2 = prev1
        prev1 = current
    }

    return prev1
}
```Go 实现遵循与 Python 版本相同的迭代动态编程逻辑。 

一个重要的区别是显式整数处理。 由于 Go 整数可能会根据平台大小而溢出，因此在计算过程中会立即应用模运算。 

该实现还避免了递归，这很重要，因为递归深度`n = 10^6`会不安全。

 ## 边缘情况

 一个重要的边缘情况是`n = 1`。 如果只有一个元素，则不可能在该元素改变位置时进行重新排列。 幼稚的循环实现可能会意外返回`1`如果不仔细处理基本情况。 实现显式返回`0`对于这个案例。 

另一个重要的边缘情况是`n = 2`。 这是最小的非平凡的混乱场景。 唯一有效的排列是`[2,1]`。 由于递归取决于较早的值，因此错误地初始化基本情况将导致所有后续计算变得不正确。 实施集`D(2) = 1`明确地。 

第三个关键边缘情况是非常大的输入值，例如`n = 10^6`。 递归实现可能会超出递归深度限制或消耗过多的内存。 同样，存储完整的 DP 表也是不必要的开销。 该实现使用只有两个变量的迭代方法，确保了内存效率和可扩展性。 

另一个微妙的问题是整数溢出。 混乱计数增长得非常快，远远超出了标准整数限制。 该实现在每次迭代期间应用模算术，因此中间值根据问题要求保持可管理和正确。
