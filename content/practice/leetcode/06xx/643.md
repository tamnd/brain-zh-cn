[LeetCode 第 643 题](https://leetcode.com/problems/maximum-average-subarray-i/)

 **难度：** 🟢简单
 **主题：** 数组、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们找到固定长度的所有连续子数组中的**最大平均值**`k`。 

换句话说，给定一个整数数组`nums`，我们必须检查每个可能的子数组，其大小恰好是**`k`**，计算其平均值，并返回找到的**最大平均值**。 

一个关键细节是子数组必须是**连续的**，这意味着它的元素在原始数组中彼此相邻。 我们不能跳过元素或重新排列它们。 

例如，如果：```
nums = [1,12,-5,-6,50,3]
k = 4
```length 的有效子数组`4`是：```
[1,12,-5,-6]
[12,-5,-6,50]
[-5,-6,50,3]
```我们计算每一项的平均值并返回最大值。 

输入包括：

 -`nums`，长度的整数数组`n`-`k`，我们必须考虑的子数组的确切长度

 预期输出是一个浮点数，表示所有有效子数组中的最大平均值。 

约束条件很重要：

 -`1 <= k <= n <= 10^5`-`-10^4 <= nums[i] <= 10^4`自从`n`可以大到`100,000`，重复重新计算重叠子数组之和的低效解决方案可能会太慢。 我们需要一种能够有效扩展的算法。 

问题约束保证了几种边缘情况是有效的：

 -`k`总是至少`1`，所以总有一个有效的子数组。 
-`k`可以等于`n`，这意味着唯一可能的子数组是整个数组。 
- 值可能为负，这意味着最大平均值也可能为负。 
- 数组只能包含一个元素。 

由于连续的窗口严重重叠，简单的实现可能会变得低效。 从头开始重新计算每个子数组的总和将重复大量工作。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个连续大小的子数组`k`。 

对于每个起始位置，我们计算下一个位置的总和`k`元素，除以`k`，并跟踪遇到的最大平均值。 

这种方法是正确的，因为它显式检查每个有效的候选子数组。 由于答案必须来自这些窗口之一，因此比较所有窗口可以保证正确性。 

然而，问题是性能。 如果我们独立地重新计算每个窗口的总和，则每个子数组都需要`O(k)`工作。 

大致有`n - k + 1`windows，因此总复杂度变为：```
O((n - k + 1) × k) ≈ O(nk)
```在最坏的情况下，当双方`n`和`k`接近于`10^5`，这变得太慢了。 

### 最优方法，滑动窗口

 关键的观察是长度的相邻子数组`k`几乎完全重叠。 

例如：```
[1,12,-5,-6]
[12,-5,-6,50]
```第二个窗口与第一个窗口的区别仅在于：

 - 删除最左边的元素（`1`）
 - 添加新的最右边元素（`50`）

 我们可以有效地更新先前的窗口总和，而不是重新计算整个总和：```
new_sum = old_sum - outgoing + incoming
```这就是**滑动窗口技术**的本质。 

我们首先计算初始窗口大小的总和`k`。 然后，当窗口向右移动一步时，我们减去离开窗口的元素并添加进入窗口的新元素。 

这将每次转换减少为**恒定时间**，使整个算法呈线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(1) | O(1) | 独立地重新计算每个窗口总和 |
 | 最佳| O(n) | O(1) | O(1) | 使用滑动窗口增量更新总和 |

 ## 算法演练

 ### 最优滑动窗口算法

 1. 计算第一个的总和`k`元素。 

这给了我们第一个有效子数组的总和。 由于每个候选子数组都有长度`k`，这提供了我们的起点。 
2. 初始化一个变量来跟踪最大窗口总和。 

我们将第一个窗口总和存储为初始最大值，因为它已经是有效的候选者。 
3.从index开始滑动窗口`k`到数组的末尾。 

每一步，窗口都会向右移动一个位置。 
4. 更新当前窗口总和。 

删除离开窗口的元素并添加进入窗口的新元素：```
current_sum =
    current_sum
    - nums[i - k]
    + nums[i]
```这是有效的，因为窗口大小保持固定。 
5. 如果需要，更新最大总和。 

如果当前窗口总和超过迄今为止看到的最佳窗口总和，则更新最大值。 
6. 返回最大平均值。 

由于每个窗口都有长度`k`，最大平均值为：```
max_sum / k
```### 为什么它有效

 该算法保持一个不变量：

 >`current_sum`始终表示当前窗口长度的精确总和`k`。 

我们通过正确计算第一个窗口总和来建立这个不变量。 每次后续更新都会删除传出元素并添加传入元素，从而保持正确性。 

由于该算法对每个有效子数组只计算一次并跟踪最大总和，因此最终结果必须对应于最大平均子数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaxAverage(self, nums: List[int], k: int) -> float:
        current_sum = sum(nums[:k])
        max_sum = current_sum

        for right in range(k, len(nums)):
            current_sum += nums[right]
            current_sum -= nums[right - k]

            max_sum = max(max_sum, current_sum)

        return max_sum / k
```实现首先计算第一个的总和`k`元素。 这形成了初始滑动窗口并建立了基线最大总和。 

然后我们从索引迭代`k`向前。 每一步，窗口都会向右移动一个位置。 我们不是从头开始重新计算总和，而是通过添加新元素并减去超出窗口的元素来增量更新它。 

变量`max_sum`跟踪迄今为止遇到的最佳窗口总和。 由于每个窗口的大小相同`k`，比较总和相当于比较平均值。 

最后，我们将最大总和除以`k`返回最大平均值。 

## 解决方案```go
func findMaxAverage(nums []int, k int) float64 {
	currentSum := 0

	for i := 0; i < k; i++ {
		currentSum += nums[i]
	}

	maxSum := currentSum

	for right := k; right < len(nums); right++ {
		currentSum += nums[right]
		currentSum -= nums[right-k]

		if currentSum > maxSum {
			maxSum = currentSum
		}
	}

	return float64(maxSum) / float64(k)
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 特有的一个细节是返回结果时的显式类型转换。 由于整数除法会截断小数，因此`maxSum`和`k`被转换为`float64`划分之前。 

无需处理`nil`或单独的空切片，因为约束保证：```go
1 <= k <= n
```这意味着输入始终有效且非空。

 ## 边缘情况

 ### 什么时候`k = 1`这种情况实际上要求最大的单个元素，因为每个子数组只包含一个数字。 有缺陷的实现可能会使这种情况变得过于复杂，但滑动窗口自然可以处理它，因为每个窗口都包含一个值并正常移动。 

＃＃＃ 什么时候`k = n`如果窗口大小等于数组长度，则仅存在一个有效子数组，即整个数组。 某些实现会意外地尝试超出范围。 我们的实现避免了这种情况，因为循环开始于`k`，以及当`k == len(nums)`，循环永远不会运行。 

### 仅包含负数的数组

 负值可能会很棘手，因为“最大”平均值仍然为负。 一个简单的实现，将最大值初始化为`0`会失败的。 我们的解决方案初始化`max_sum`使用第一个有效窗口，即使每个值都是负数，也能确保正确性。
