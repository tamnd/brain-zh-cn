[LeetCode 第 617 题](https://leetcode.com/problems/merge-two-binary-trees/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们将两个二叉树组合成一个合并树。 每棵树都由节点组成，其中每个节点都包含一个值以及指向左子节点和右子节点的指针。 

合并过程从两棵树的根开始，并递归地遍历树中的相应位置。 每当两棵树在同一位置包含一个节点时，它们的值就会加在一起以创建合并节点的值。 如果只有一棵树在某个位置包含一个节点，而另一棵树有`null`，则在合并树中直接使用现有节点。 

例如，假设第一棵树有一个值为`3`在特定位置，第二棵树也有一个具有值的节点`5`在同一个位置。 合并的树将包含一个具有值的节点`8`那里。 如果只有一棵树包含一个节点，则该节点在合并结果中保持不变。 

输入以两个二叉树根的形式给出，`root1`和`root2`。 每个根可能是`null`，它代表一棵空树。 输出必须是合并二叉树的根。 

约束告诉我们两棵树的节点总数最多为`2000`。 这足够小，遍历每个节点是完全可以接受的。 由于该问题自然涉及递归比较相应节点，因此深度优先遍历是非常自然的选择。 

一些边缘情况很重要：

 - 一棵或两棵树可能是空的。 
- 树木可能有非常不同的形状。 
- 节点可能存在于一棵树中，但不存在于另一棵树中。 
- 节点值可能为负。 
- 树可能高度不平衡，从而创建深度递归路径。 

该问题保证了有效的二叉树输入，因此我们不需要验证树结构的正确性。 

## 方法

 ### 蛮力方法

 强力方法首先将两棵树复制到辅助数据结构中，例如由遍历位置作为键控的数组或哈希图。 将两棵树转换为可比较的表示后，我们可以迭代所有位置，对重叠值求和，并重建一棵全新的树。 

这是有效的，因为每个节点位置最终都可以明确地进行比较。 然而，它引入了不必要的开销。 二叉树已经是递归结构，因此将它们展平为另一种表示形式会浪费时间和内存。 

此外，事后重建树会使实现变得非常复杂。 问题可以直接在遍历过程中解决。 

### 最佳方法

 关键的观察是合并可以在递归遍历期间自然发生。 

在每对节点处：

 - 如果两个节点都是`null`，合并后的节点也是`null`。 
- 如果一个节点是`null`，直接返回另一个节点。 
- 如果两个节点都存在，则创建或更新一个节点，其值是两个节点值之和。 
- 递归合并左孩子。 
- 递归合并右子节点。 

由于每个节点对只处理一次，因此该解决方案既简单又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n + m) | O(n + m) | 重建前将树木转换为辅助结构 |
 | 最佳| O(n + m) | O(h) | 遍历时直接递归合并节点 |

 这里，`n`和`m`是两棵树中的节点数，并且`h`是递归堆栈的高度。 

## 算法演练

 1. 从两棵树的根节点开始。 

我们比较根，因为合并过程总是从两棵树的顶部开始。 
2. 检查两个节点是否都`null`。 

如果两个节点都为空，则没有任何内容可以合并，因此返回`null`。 
3、检查某个节点是否存在`null`。 

如果一棵树不包含该位置的节点，则直接返回另一棵树的现有节点。 这保留了子树结构。 
4. 合并当前节点值。 

如果两个节点都存在，则将它们的值相加。 我们可以重用现有节点之一，而不是分配一个全新的节点。 
5. 递归合并左子树。 

调用合并函数`root1.left`和`root2.left`。 将返回的节点分配给合并节点的左子节点。 
6. 递归合并右子树。 

调用合并函数`root1.right`和`root2.right`。 将返回的节点分配给合并节点的右子节点。 
7. 返回合并后的节点。 

处理完两个子树后，当前子树将完全合并。 

### 为什么它有效

 该算法之所以有效，是因为每个递归调用都正确地合并了两棵树中相应的节点对。 递归保留了树的相对结构，同时在每个节点本地应用合并规则。 由于每个子树在向上返回之前都已正确合并，因此保证整个最终树是正确的。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def mergeTrees(
        self,
        root1: Optional[TreeNode],
        root2: Optional[TreeNode]
    ) -> Optional[TreeNode]:

        if root1 is None:
            return root2

        if root2 is None:
            return root1

        root1.val += root2.val

        root1.left = self.mergeTrees(root1.left, root2.left)
        root1.right = self.mergeTrees(root1.right, root2.right)

        return root1
```实现直接遵循递归策略。 

前两个条件检查处理其中一棵树在当前位置为空的情况。 立即返回非空节点可以避免不必要的工作并保留现有的子树结构。 

当两个节点都存在时，将当前节点值相加。 实现重用`root1`作为合并节点以减少内存使用。 

递归调用独立地合并左子节点和右子节点。 每次递归调用都会返回合并子树的根，该根被分配回`root1.left`和`root1.right`。 

最后将合并后的节点通过递归链向上返回。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func mergeTrees(root1 *TreeNode, root2 *TreeNode) *TreeNode {
    if root1 == nil {
        return root2
    }

    if root2 == nil {
        return root1
    }

    root1.Val += root2.Val

    root1.Left = mergeTrees(root1.Left, root2.Left)
    root1.Right = mergeTrees(root1.Right, root2.Right)

    return root1
}
```Go 实现在概念上与 Python 版本几乎相同。 

Go 使用`nil`而不是`None`对于空指针。 树节点是通过指针操作的，所以修改`root1.Val`直接更新现有节点。 

由于 Go 整数可以轻松处理给定值约束，因此整数溢出在这里不是问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 两棵树中的每个节点最多被访问一次 |

 ## 边缘情况

 ### 两棵树都是空的

 如果两者都`root1`和`root2`是`null`，算法应该返回`null`。 这种情况很重要，因为如果不首先检查基本条件，递归解决方案可能会意外取消引用空指针。 该实现通过初始空检查立即处理此问题。 

### 一棵树比另一棵大得多

 一棵树可能包含许多节点，而另一棵树仅包含几个节点。 有缺陷的实现可能会错误地丢弃不匹配的子树。 该解决方案正确地保留了所有不匹配的节点，因为每当一个节点被`null`，算法直接返回非空子树。 

### 高度倾斜的树

 树可能类似于链表而不是平衡树。 这会创建深度递归链并测试递归逻辑是否一次正确处理一个子级。 该实现工作正常，因为每个递归调用都会独立合并相应的左子节点和右子节点，而不管树平衡如何。 

### 负节点值

 节点值可以为负数，因此合并操作不能假设正和。 该实现只是执行整数加法，而不对符号施加限制，使其自然地兼容负值。
