 **难度：** 🟡 中等
 **主题：** 数学、位操作、深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 问题描述了一个房间，其中包含`n`灯泡，每个灯泡都从`on`状态。 有四个按钮可用，每个按钮都会翻转特定的灯泡子集。 翻转意味着改变`on`到`off`或者`off`到`on`。 

四个按钮的作用如下：

 - 按钮 1 翻转每个灯泡。 
- 按钮 2 翻转指数偶数的灯泡。 
- 按钮 3 翻转带有奇数索引的灯泡。 
- 按钮 4 翻转位置满足的灯泡`j = 3k + 1`，表示位置`1, 4, 7, 10, ...`。 

我们必须准确执行`presses`按钮按下。 一个按钮可以被按下多次，并且按下的顺序在操作上很重要，尽管许多顺序最终会产生相同的最终灯泡配置。 

任务是确定在准确之后可能有多少种不同的最终灯泡状态`presses`运营。 

灯泡状态可以表示为二进制模式。 例如：

-`[on, off, on]`-`[off, off, off]`如果两次按下按钮序列产生相同的最终配置，则它们被视为相同的结果。 

约束条件很重要：

 -`n`可以大到`1000`-`presses`也可以大到`1000`对所有可能序列的简单模拟将是巨大的，因为有`4^presses`可能的按钮序列。 即使对于中等值，这在计算上也是不可行的。 

关键的观察结果是，独特灯泡图案的数量实际上非常少，因为：

 - 按同一按钮两次可取消其效果。 
- 只有印刷机的平等才重要。 
- 灯泡图案周期性重复。 
- 在最初的几个灯泡之后，额外的灯泡不会引入新的行为。 

重要的边缘情况包括：

 -`presses = 0`，其中原始配置必须保持不变。 
-`n = 1`，其中许多按钮变得等效，因为它们影响同一个灯泡。 
- 非常大`n`，其中简单的模拟会浪费时间处理重复行为的灯泡。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是生成每种可能的按钮按下顺序。 由于每台印刷机都有四种选择，因此有`4^presses`序列。 

对于每个序列：

 1. 首先打开所有灯泡。 
2. 按顺序按下每个按钮。 
3. 将生成的灯泡配置记录在一组中。 
4. 返回集合的大小。 

这种方法是正确的，因为它显式枚举了每个可能的序列，因此不会错过任何可到达的配置。 

然而，复杂性很快就变得不可接受。 例如：

-`presses = 20`已经产生了超过一万亿个序列。 

即使许多序列崩溃到相同的最终状态，暴力仍然浪费时间探索所有可能性。 

### 最佳解决方案的关键见解

 重要的数学观察是，按两次按钮总体上没有效果。 

例如：

 - 将所有灯泡翻转一次 → 更换灯泡
 - 再次翻转所有灯泡→灯泡恢复原始状态

 因此，每个按钮仅对模 2 起作用：

 - 按偶数次 → 无净效应
 - 按奇数次→效果应用一次

 由于只有四个按钮，每个按钮可以是：

 - 使用过
 - 未使用

 这最多会创建：$$2^4 = 16$$独特的按钮组合。 

另一个重要的观察结果是，灯泡行为在前三个灯泡之后会重复。 在所有按钮操作下，位置 3 之外的任何灯泡的行为与较早灯泡之一的行为相同。 

因此：

 - 我们只需要分析第一个`min(n, 3)`灯泡
 - 我们只需要枚举16个按钮掩码

 这可以将问题从指数级减少到`presses`至恒定时间。

 ## 算法演练

 1. 将灯泡数量减少至最多 3 个。 

灯泡的行为会定期重复。 除了前三个灯泡之外，没有出现新的独立状态信息。 因此我们计算：```
effectiveBulbs = min(n, 3)
```2. 枚举所有可能的按钮组合。 

由于每个按钮要么对最终状态有贡献，要么没有贡献，因此我们使用 4 位掩码`0`到`15`。 

每个位代表按钮是否被按下奇数次。 
3. 计算掩码中有多少个按钮处于活动状态。 

对于每个掩码，计算：```
numberOfPressedButtons
```这很重要，因为我们必须准确地执行`presses`运营。 
4. 检查面罩是否可达。 

掩码仅在以下情况下有效：

 - 活动按钮的数量不超过`presses`- 奇偶校验匹配

 为什么平等很重要：

 - 额外的按压总是可以成对取消
 - 因此只有奇/偶校验很重要

 条件变为：```
activeButtons <= presses
and
(activeButtons % 2) == (presses % 2)
```5. 模拟灯泡状态。 

首先打开所有灯泡。 

对于每个灯泡位置：

 - 确定每个活动按钮是否翻转它
 - 使用 XOR 逻辑计算最终状态
 6. 存储生成的图案。 

将灯泡状态转换为元组或字符串并插入到集合中。 

使用集合会自动删除重复项。 
7. 返回唯一状态的数量。 

答案很简单：```
len(states)
```### 为什么它有效

 每个按钮操作都是其自身的相反操作，这意味着按两次按钮会完全取消效果。 因此，只有按钮使用的对等性才重要。 由于只有四个按钮，因此只有 16 种有意义的组合。 

此外，灯泡图案在前三个灯泡之后重复，因此更大`n`价值观不会创造额外的独特行为。 枚举所有有效的奇偶校验兼容按钮组合可确保每个可到达的最终配置仅被考虑一次。 

## Python 解决方案```python
class Solution:
    def flipLights(self, n: int, presses: int) -> int:
        n = min(n, 3)

        states = set()

        for mask in range(16):
            button_count = bin(mask).count("1")

            if button_count > presses:
                continue

            if button_count % 2 != presses % 2:
                continue

            bulbs = [1] * n

            for i in range(n):
                bulb_index = i + 1

                # Button 1
                if mask & 1:
                    bulbs[i] ^= 1

                # Button 2
                if (mask & 2) and bulb_index % 2 == 0:
                    bulbs[i] ^= 1

                # Button 3
                if (mask & 4) and bulb_index % 2 == 1:
                    bulbs[i] ^= 1

                # Button 4
                if (mask & 8) and bulb_index % 3 == 1:
                    bulbs[i] ^= 1

            states.add(tuple(bulbs))

        return len(states)
```实施从减少开始`n`至多 3，因为较大的灯泡索引不会引入新的行为模式。 

一组名为`states`存储所有不同的灯泡配置。 

该循环迭代所有 16 个可能的按钮掩码。 每个掩码代表哪些按钮被按下奇数次。 

对于每个面具：

 -`button_count`计算有多少按钮处于活动状态。 
- 超过允许按压次数的口罩将被丢弃。 
- 奇偶校验不正确的掩码也会被丢弃。 

灯泡阵列开始为所有`1`s，代表灯泡打开。 

每个按钮的状态都是独立检查的：

 -`mask & 1`表示按钮 1 处于活动状态。 
-`mask & 2`表示按钮 2 处于活动状态。 
-`mask & 4`表示按钮 3 处于活动状态。 
-`mask & 8`表示按钮 4 处于活动状态。 

异或运算（`^= 1`) 翻转灯泡状态。 

最后，灯泡配置被转换为元组并添加到集合中。 集合的大小作为答案返回。 

## 解决方案```go
package main

import (
	"math/bits"
)

func flipLights(n int, presses int) int {
	if n > 3 {
		n = 3
	}

	states := make(map[[3]int]bool)

	for mask := 0; mask < 16; mask++ {
		buttonCount := bits.OnesCount(uint(mask))

		if buttonCount > presses {
			continue
		}

		if buttonCount%2 != presses%2 {
			continue
		}

		var bulbs [3]int

		for i := 0; i < n; i++ {
			bulbs[i] = 1
		}

		for i := 0; i < n; i++ {
			bulbIndex := i + 1

			// Button 1
			if mask&1 != 0 {
				bulbs[i] ^= 1
			}

			// Button 2
			if mask&2 != 0 && bulbIndex%2 == 0 {
				bulbs[i] ^= 1
			}

			// Button 3
			if mask&4 != 0 && bulbIndex%2 == 1 {
				bulbs[i] ^= 1
			}

			// Button 4
			if mask&8 != 0 && bulbIndex%3 == 1 {
				bulbs[i] ^= 1
			}
		}

		states[bulbs] = true
	}

	return len(states)
}
```Go 的实现与 Python 解决方案非常相似。 主要区别在于 Go 使用固定大小的数组`[3]int`作为设置键，因为数组是可散列且可比较的。 

这`math/bits`套餐提供`bits.OnesCount()`用于有效地计算掩码中的活动位。 

Go 没有 Python 的动态元组类型，因此固定数组充当状态表示。

 ## 边缘情况

 ### 零按

 当`presses = 0`，不能执行任何操作。 唯一有效的配置是每个灯泡保持打开的原始状态。 

如果实现假设必须应用至少一个按钮组合，那么这种情况很容易导致错误。 奇偶校验可以正确处理此问题，因为只有空掩码才有效。 

### 单灯泡

 当`n = 1`，许多按钮变得难以区分：

 - 按钮 1 翻转灯泡 1
 - 按钮 3 翻转灯泡 1
 - 按钮 4 翻转灯泡 1
 - 按钮 2 不执行任何操作

 幼稚的实现可能会多次错误地计算重复配置。 使用一组可以保证重复项被折叠成一个唯一的状态。 

### 大值`n`约束条件允许`n`最多 1000 个。简单的模拟可能会浪费时间重复处理每个灯泡。 

数学观察表明，只有前三个灯泡很重要，可以防止不必要的工作。 该实现显式减少了：```
n = min(n, 3)
```无论输入大小如何，这都确保了恒定的运行时间。 

### 大值`presses`约束条件也允许`presses`最多 1000。所有序列的暴力枚举是不可能的。 

奇偶校验观察解决了这个问题，因为按同一按钮两次会抵消。 因此，只有每个按钮的奇数/偶数使用很重要，从而将搜索空间减少到只有 16 种组合。
