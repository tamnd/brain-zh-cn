[LeetCode 第 632 题](https://leetcode.com/problems/smallest-range-covering-elements-from-k-lists/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、贪婪、滑动窗口、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 问题给了我们`k`排序的整数列表，我们必须找到最小的包含范围`[a, b]`这样该范围至少包含每个列表中的一个元素。 

每个列表都已经按非降序排序，这是一个非常重要的属性。 我们可以利用顺序来有效地在列表中移动，而不是考虑元素的任意组合。 

输出不是单个数字，而是表示为二元素数组的范围`[start, end]`。 如果范围的宽度较小，则该范围被视为“较小”。 正式地，`[a, b]`比`[c, d]`如果：

-`b - a < d - c`- 或者宽度相等并且`a < c`第二个条件意味着如果两个范围具有相同的大小，我们更喜欢较早开始的范围。 

约束足够大，以至于暴力枚举变得不切实际：

 - 最多`3500`列表
 - 每个列表最多可以包含`50`元素
 - 总元素因此可以达到`175,000`尝试所有列表中每种可能的组合的天真的方法会导致组合爆炸。 

有几个重要的边缘情况：

 - 多个列表可能包含相同的值，这意味着答案可能是零宽度范围，例如`[1,1]`。 
- 列表可以包含负数。 
- 列表的长度可能有很大不同。 
- 某些列表可能仅包含一个元素。 
- 最佳范围可能会出现在遍历的末尾附近，因此提前停止是不安全的，除非用尽一个列表。 

该问题保证每个列表都非空且已排序，这使得基于堆的技术特别有效。 

## 方法

 ### 蛮力方法

 蛮力的想法是考虑每一种可能的选择，从每个列表中选择一个元素。 对于每个组合，我们计算最小和最大选定值，这定义了候选范围。 然后我们保留遇到的最小范围。 

这种方法是正确的，因为每个有效答案都对应于至少一个这样的组合。 

然而，组合的数量是巨大的。 如果每个列表大约包含`m`元素并且有`k`列表，则组合总数大致为：$$m^k$$即使值很小，这在计算上也是不可能的。 

另一个稍微改进的蛮力策略是将所有数字展平，对它们进行排序，然后重复测试范围，但如果没有有效的方法来维持所有列表的覆盖范围，这仍然会变得太慢。 

### 关键见解

 关键的观察是我们只需要随时跟踪每个列表中的一个活动元素。 

假设我们当前从每个列表中选择了一个数字。 最小的选定数字定义当前范围的左边界，而最大的选定数字定义右边界。 

如果我们想要潜在地改善范围，唯一有用的举措是推进包含当前最小值的列表。 

为什么？ 

因为当前最小值决定了左边界。 移动任何其他指针只会增加或保留最大值，同时保持最小值不变，而不能缩小范围。 

这自然会导致最小堆解决方案：

 - 将每个列表中的一个活动元素存储在最小堆中
 - 单独跟踪当前最大值
 - 反复删除最小元素
 - 将该列表前进到其下一个值
 - 更新迄今为止看到的最佳范围

 这保证了我们始终保持所有列表的覆盖范围，同时有效地探索候选范围。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m^k) | O(m^k) | O(k) | 尝试每个列表中一个元素的所有可能组合 |
 | 最佳| O(N log k) | O(N log k) | O(k) | 使用最小堆来维护每个列表中的一个活动元素 |

 这里，`N`是所有列表中的元素总数。 

## 算法演练

 ### 基于堆的最优算法

 1. 使用每个列表中的第一个元素初始化最小堆。 

每个堆条目存储：

 - 价值
 - 它来自的列表的索引
 - 该列表中的索引

 这保证了堆始终包含每个列表中的一个活动元素。 
2. 跟踪所有活动元素中当前的最大值。 

堆有效地为我们提供了最小元素，但我们还需要最大值来定义当前候选范围。 
3. 使用初始堆状态初始化最佳答案。 

当前范围是：$$[\text{heap minimum}, \text{current maximum}]$$4. 反复从堆中弹出最小元素。 

该最小元素定义了范围的当前左边界。 
5. 将当前范围与迄今为止找到的最佳范围进行比较。 

如果出现以下情况，请更新答案：

 - 电流范围更小
 - 或者宽度相等且当前起始值较小
 6. 推进贡献最小元素的列表。 

这是关键的贪心步骤。 

由于最小元素限制了范围的大小，因此改善范围的唯一可能方法是将列表向前移动。 
7. 如果列表没有更多元素，则停止算法。 

此时，我们无法再维护所有列表的覆盖范围，因为一个列表已用尽。 
8. 否则，将该列表中的下一个元素推入堆中。 

如有必要，请更新当前最大值。 
9. 继续直至终止。 

### 为什么它有效

 该算法保持一个不变量：

 - 堆始终包含每个列表中的一个活动元素。 

因此，每个堆状态对应于覆盖所有列表的有效范围。 

在每一步中，最小的活动元素确定左边界。 任何更好的范围都必须增加这个最小值，因为保持它不变不能缩小间隔。 因此，推进拥有最少的名单是唯一富有成效的举措。 

由于此过程生成的每个有效候选都会被检查，并且我们始终保留遇到的最小范围，因此最终答案是最佳的。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def smallestRange(self, nums: List[List[int]]) -> List[int]:
        min_heap = []
        current_max = float("-inf")

        # Initialize heap with first element from each list
        for list_index, values in enumerate(nums):
            value = values[0]
            heapq.heappush(min_heap, (value, list_index, 0))
            current_max = max(current_max, value)

        best_start = min_heap[0][0]
        best_end = current_max

        while True:
            current_min, list_index, element_index = heapq.heappop(min_heap)

            # Update best range if current one is better
            if (
                current_max - current_min < best_end - best_start
                or (
                    current_max - current_min == best_end - best_start
                    and current_min < best_start
                )
            ):
                best_start = current_min
                best_end = current_max

            # Move to next element in the same list
            next_index = element_index + 1

            # Cannot maintain coverage anymore
            if next_index == len(nums[list_index]):
                break

            next_value = nums[list_index][next_index]

            heapq.heappush(
                min_heap,
                (next_value, list_index, next_index)
            )

            current_max = max(current_max, next_value)

        return [best_start, best_end]
```实现首先将每个列表中的第一个元素插入堆中。 这会创建初始有效范围，因为我们立即从每个列表中获得一个元素。 

堆存储以下元组：

 - 价值
 - 列表索引
 - 元素索引

 元组结构使我们能够在每次弹出操作后准确识别哪个列表贡献了最小元素。`current_max`是单独维护的，因为最小堆只能直接访问最小值。 一起，堆最小值和`current_max`定义当前候选区间。 

在循环内，我们弹出最小元素并将结果范围与最佳答案进行比较。 然后我们尝试在同一个列表中前进。 

如果该列表已用尽，则算法将终止，因为不可能继续形成包含所有列表的有效范围。 

否则，下一个元素被推入堆中，并且`current_max`如果需要的话会更新。 

该过程一直持续到一个列表用完所有元素为止。 

## 解决方案```go
package main

import (
	"container/heap"
)

type Node struct {
	value      int
	listIndex  int
	valueIndex int
}

type MinHeap []Node

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].value < h[j].value
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(Node))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func smallestRange(nums [][]int) []int {
	minHeap := &MinHeap{}
	heap.Init(minHeap)

	currentMax := -100001

	// Initialize heap
	for listIndex, values := range nums {
		value := values[0]

		heap.Push(minHeap, Node{
			value:      value,
			listIndex:  listIndex,
			valueIndex: 0,
		})

		if value > currentMax {
			currentMax = value
		}
	}

	bestStart := (*minHeap)[0].value
	bestEnd := currentMax

	for {
		current := heap.Pop(minHeap).(Node)

		currentMin := current.value

		// Update best range
		if currentMax-currentMin < bestEnd-bestStart ||
			(currentMax-currentMin == bestEnd-bestStart &&
				currentMin < bestStart) {

			bestStart = currentMin
			bestEnd = currentMax
		}

		nextIndex := current.valueIndex + 1

		// Cannot continue coverage
		if nextIndex == len(nums[current.listIndex]) {
			break
		}

		nextValue := nums[current.listIndex][nextIndex]

		heap.Push(minHeap, Node{
			value:      nextValue,
			listIndex:  current.listIndex,
			valueIndex: nextIndex,
		})

		if nextValue > currentMax {
			currentMax = nextValue
		}
	}

	return []int{bestStart, bestEnd}
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但需要使用以下自定义堆实现`container/heap`包裹。 

一个`Node`struct 存储当前值及其位置信息。 这`MinHeap`type 实现所需的堆接口方法。 

与Python内置的不同`heapq`，Go的堆实现使用接口方法和显式类型断言。 

Go 的整数没有负无穷大，所以`currentMax`使用小于最小可能约束的值进行初始化。

 ## 边缘情况

 当所有列表共享相同的值时，就会出现一种重要的边缘情况。 例如：```
[[1,2],[1,3],[1,4]]
```最优答案是`[1,1]`。 一些不正确的实现无法识别零宽度间隔是有效的。 此实现可以正确处理这种情况，因为它不断比较间隔宽度并允许相等的端点。 

另一个重要的情况涉及包含负数的列表。 由于范围仅取决于相对顺序，因此必须像处理正值一样处理负值。 堆排序自然地处理这个问题，无需特殊逻辑。 正在初始化`currentMax`即使所有值都是负数，也要仔细确保正确性。 

当一个列表非常短时，就会出现第三种关键边缘情况。 例如：```
[[1],[2,3,4],[5,6]]
```一旦单元素列表用尽，就不可能再有进一步的有效范围。 当任何列表用完元素时，该算法会显式停止，以防止无法包含所有列表的无效间隔。 

第四个微妙的情况涉及打破平局。 考虑两个宽度相同的范围：```
[1,3]
[2,4]
```两者都有宽度`2`， 但`[1,3]`是首选，因为它的起点较小。 该实现使用辅助比较条件来处理此问题：```
current_min < best_start
```这保证了遵守问题的确切排序规则。
