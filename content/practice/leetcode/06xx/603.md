[LeetCode Problem 603](https://leetcode.com/problems/consecutive-available-seats/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`Cinema`有两列：

 | 专栏 | 意义|
 | --- | --- |
 |`seat_id`| 座位的唯一标识符 |
 |`free`| Whether the seat is available, where`1`意味着免费并且`0`means occupied |

 我们需要找到属于至少一个连续的空闲座位序列的所有座位。 如果两个席位是连续的`seat_id`值完全不同`1`。 

重要的细节是我们不仅仅是在寻找配对。 如果存在更长的序列，则应返回该序列中的每个座位。 例如，如果座位`3`,`4`， 和`5`都是空闲的，那么所有三个座位都属于连续的可用块，并且全部都应该出现在输出中。 

The result must contain only the`seat_id`列，行必须按升序排列`seat_id`。 

输入表表示电影院的当前占用状态。 Every row corresponds to exactly one seat. 自从`seat_id`是自动递增的，座位号按顺序增加，这使我们能够使用简单的算术比较来检测邻接性，例如`seat_id + 1`。 

问题陈述中的一项重要保证是测试用例包含长于两个座位的序列。 这意味着解决方案必须正确识别参与任何连续空闲段的所有座位，而不仅仅是孤立的对。 

Several edge cases are important to consider. 不应包括空闲座位本身，因为它与另一个空闲座位不连续。 连续的序列可以出现在表的开头或结尾，因此边界处理很重要。 当一个座位属于多个相邻对时，会发生另一种微妙的情况。 For example, in the sequence`3, 4, 5`， 座位`4`与两者连续`3`和`5`，但它仍然应该在输出中只出现一次。 

## 方法

 ### 蛮力方法

 一种简单的方法是单独检查每个座位并检查其相邻的座位。 对于每个空闲座位，我们可以通过以下方式搜索座位`seat_id - 1`另一个与`seat_id + 1`。 如果任一相邻座位也空闲，则当前座位属于连续的空闲块。 

这种方法是正确的，因为如果至少一个相邻座位也空闲，则该座位被视为有效。 通过显式检查每个座位的两个邻居，我们保证检测到所有符合条件的座位。 

然而，如果每个邻居查找都需要扫描整个表，那么简单的实现可能会变得低效。 在这种情况下，对于每一行，我们都可以执行另一次完整遍历，从而导致时间复杂度为二次。 

### 最佳方法

 关键的观察结果是连续座位的差异恰好是`1`在他们的`seat_id`价值观。 我们可以使用自连接，而不是重复扫描表。 

我们加入`Cinema`桌子本身，使得一个座位与另一个座位相邻：

 -`c1.seat_id = c2.seat_id + 1`- 或者`c1.seat_id = c2.seat_id - 1`我们还要求两个座位都是空闲的。 

如果一个座位至少有一个相邻的空闲座位，那么它属于连续的可用序列，应该返回。 

这种方法工作效率很高，因为关系数据库针对连接和索引比较进行了优化。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复扫描桌子上的相邻座位 |
 | 最佳| 通常为 O(n log n) | O(1) 额外 | 使用自连接有效检测相邻的空闲座位 |

 ## 算法演练

 1. 从`Cinema`表并将每个席位视为候选结果。 
2. 在表和自身之间创建自联接。 一份代表当前座位，另一份代表潜在的相邻座位。 
3. 使用席位标识符定义邻接。 如果有一个座位，则两个座位是连续的`seat_id`与另一个完全不同`1`。 
4. 限制仅限于免费座位的比较。 一对中的两个座位都必须有`free = 1`。 
5. 如果某个座位至少有一个相邻的空闲座位，则将其包含在结果集中。 这确保了参与连续块的每个席位都被返回。 
6. 使用`DISTINCT`以避免重复。 较长序列中间的座位可能会匹配多个相邻座位，而我们只想返回一次。 
7. Sort the final result by`seat_id`按升序排列以满足输出要求。 

### 为什么它有效

 核心不变量是每个有效座位必须至少有一个相邻座位，其`seat_id`完全不同`1`并且也是免费的。 自连接显式检查每个席位的此条件。 任何满足条件的座位都保证属于连续的空闲序列，任何不满足条件的座位不能属于这样的序列。 因此，算法会准确返回正确的座位。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT DISTINCT c1.seat_id
FROM Cinema c1
JOIN Cinema c2
ON ABS(c1.seat_id - c2.seat_id) = 1
WHERE c1.free = 1
AND c2.free = 1
ORDER BY c1.seat_id;
```查询首先创建同一个表的两个别名，`c1`和`c2`。 这使我们能够将座位与表中的其他座位进行比较。 

连接条件使用`ABS(c1.seat_id - c2.seat_id) = 1`，这确保两个座位相邻。 使用`ABS`简化了逻辑，因为它在单个表达式中处理左邻居和右邻居。 

这`WHERE`条款保证两个席位都是免费的。 如果其中一个座位被占用，则该对座位将被忽略。 

因为一个座位可能与多个相邻座位匹配，`DISTINCT`删除重复的条目。 最后，查询对结果进行排序`seat_id`按升序排列。

 ## 边缘情况

 一个重要的边缘情况是孤立的空闲座位。 例如，如果座位`3`是免费的但是有座位`2`和`4`已被占用，则座位`3`不得出现在输出中。 有缺陷的实现可能会错误地包含所有空闲席位而不验证邻接性。 自连接可以防止这种情况发生，因为只有当一个席位与另一个空闲席位匹配且相差恰好为`1`。 

另一个重要的情况是长连续序列，例如`1, 2, 3, 4, 5`。 中间的座位参加多个相邻的对。 例如，座位`3`匹配两者`2`和`4`。 没有`DISTINCT`，结果中会出现重复的行。 该实现通过显式删除重复项来正确处理此问题。 

边界位置也很重要。 编号范围开头或结尾的座位只有一个可能的邻居。 例如，座位`1`只能匹配座位`2`。 一些实现错误地假设两个邻居都存在。 自连接方法自然可以处理丢失的邻居，因为只有有效的匹配行参与连接。 

当所有座位都被占用或桌子仅包含一排时，会出现最后一种微妙的边缘情况。 在这些情况下，不存在有效的相邻自由对，因此查询正确返回空结果集。
