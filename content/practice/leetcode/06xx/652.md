[LeetCode 652 题](https://leetcode.com/problems/find-duplicate-subtrees/)

 **难度：** 🟡 中等
 **主题：** 哈希表、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉树的根，并要求我们识别其中的所有重复子树。 子树定义为任何节点及其所有后代。 如果两个子树具有完全相同的结构并且每个对应节点包含相同的值，则它们被视为重复。 

输出应包含每种类型的重复子树的一个代表性根节点。 如果子树出现多次，我们只返回其中一个根。 返回节点的顺序并不重要。 

例如，考虑这棵树：```
        1
       / \
      2   3
     /   / \
    4   2   4
       /
      4
```以 value 为根的子树`4`出现多次。 子树：```
  2
 /
4
```也出现两次。 因此，两个子树根都应该出现在结果中。 

约束告诉我们树最多可以包含 5000 个节点。 这个值足够大，如果实施不当，简单的子树比较可能会变得昂贵。 由于二叉树可以有许多重叠的子树，直接重复比较子树结构会导致过多的重复工作。 

一些边缘情况很重要：

 - 只有一个节点的树不能包含重复项。 
- 具有相同值的多个叶节点是重复的子树。 
- 深度倾斜的树可能会强调递归深度和序列化大小。 
- 具有相同值的不同结构不重复。 
- 具有不同值的相同结构不重复。 
- 重复的子树只能在答案中添加一次，即使它出现多次。 

该问题保证输入是有效的二叉树，并且节点值保持在较小的整数范围内，但结构本身可能会发生很大变化。 

## 方法

 ### 蛮力方法

 强力解决方案会将每个子树与其他每个子树进行比较。 

对于树中的每个节点，我们可以生成其子树，并将其与以每个其他节点为根的子树进行结构比较。 为了确定两个子树是否相等，我们将递归地比较节点值并递归地比较左子树和右子树。 

这种方法是正确的，因为直接检查每对可能的子树。 如果两个子树在结构和值上匹配，则它们是重复的。 

然而，这种方法效率很低。 一棵树与`n`节点包含`O(n)`子树。 比较两个子树可能需要`O(n)`最坏情况下的时间。 由于我们可以比较每对子树，因此总复杂度可以接近`O(n^3)`。 

对于多达 5000 个节点，这会变得太慢。 

### 最佳方法

 关键的见解是，可以通过为每个子树提供唯一的表示来检测重复的子树。 

如果两个子树序列化为相同的表示，则它们是重复的。 我们可以执行后序遍历并为每个子树构建序列化字符串：```
(value,left_subtree,right_subtree)
```例如：```
4,#,#
2,4,#,#,#
```遍历过程中：

 - 每个子树都被序列化一次。 
- 哈希图跟踪每个序列化出现的次数。 
- 当序列化第二次出现时，我们将该子树根添加到答案中。 

后序遍历很重要，因为我们必须先完全处理子级，然后才能序列化父级子树。 

这大大减少了重复比较。 我们不是重复比较结构，而是为每个子树计算一次规范表示。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 直接比较每个子树对 |
 | 最佳| O(n^2) | O(n^2) | O(n^2) | O(n^2) | 使用带有散列的子树序列化 |

 ## 算法演练

 1. 创建一个哈希图，存储每个子树序列化出现的次数。 

键是序列化字符串，值是频率计数。 这使我们能够快速确定之前是否见过相同的子树。 
2. 创建一个空结果列表。 

每当我们第一次发现重复的子树时，我们都会将其根节点附加到该列表中。 
3. 执行后序DFS 遍历。 

我们首先处理左子树，然后处理右子树，最后处理当前节点。 此顺序可确保在构建父级序列化之前已计算子级序列化。 
4. 定义序列化格式。 

对于每个节点：```
value,left_serial,right_serial
```空孩子使用特殊标记表示，例如`#`。 

例如：```
4,#,#
```唯一代表一个有值的叶节点`4`。 
5. 递归序列化左右子节点。 

递归调用返回表示整个子子树的序列化字符串。 
6. 构建当前子树序列化。 

将当前节点值与左右序列化合并为一个字符串。 
7.更新频率图。 

增加当前序列化的计数。 
8. 检测重复项。 

如果频率恰好变为`2`，将当前节点追加到结果列表中。 

我们只添加节点一次。 如果计数后来变成`3`或者`4`，我们不添加额外的副本。 
9. 遍历完成后返回最终结果列表。 

### 为什么它有效

 该算法之所以有效，是因为序列化唯一地捕获子树结构和节点值。 当且仅当两个子树结构相同并且在相应位置包含相同的值时，它们才会产生相同的序列化。 

由于每个子树在 DFS 遍历期间只序列化一次，因此哈希映射会正确计算每个子树类型的出现次数。 每当序列化出现多次时，我们就会发现重复的子树。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, List
from collections import defaultdict

class Solution:
    def findDuplicateSubtrees(
        self,
        root: Optional[TreeNode]
    ) -> List[Optional[TreeNode]]:

        subtree_count = defaultdict(int)
        duplicates = []

        def dfs(node: Optional[TreeNode]) -> str:
            if not node:
                return "#"

            left_serial = dfs(node.left)
            right_serial = dfs(node.right)

            serial = (
                f"{node.val},{left_serial},{right_serial}"
            )

            subtree_count[serial] += 1

            if subtree_count[serial] == 2:
                duplicates.append(node)

            return serial

        dfs(root)

        return duplicates
```该实现遵循前面描述的后序序列化策略。 

这`subtree_count`字典存储每个序列化子树出现的次数。 这`duplicates`list 存储重复子树类型的根。 

递归`dfs`函数处理子树序列化。 如果节点是`None`，它返回空标记`"#"`。 

对于非空节点，该函数首先递归序列化左子树和右子树。 这就是为什么遍历是后序的。 一旦两个子序列化都可用，就构建当前的子树序列化。 

然后将序列化字符串插入到频率图中。 如果它的频率恰好变成`2`，子树刚刚变成了副本，因此当前节点被追加到答案列表中。 

最后，从根开始遍历，并返回收集到的重复项。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

import "strconv"

func findDuplicateSubtrees(root *TreeNode) []*TreeNode {
    subtreeCount := make(map[string]int)
    duplicates := []*TreeNode{}

    var dfs func(node *TreeNode) string

    dfs = func(node *TreeNode) string {
        if node == nil {
            return "#"
        }

        leftSerial := dfs(node.Left)
        rightSerial := dfs(node.Right)

        serial := strconv.Itoa(node.Val) +
            "," +
            leftSerial +
            "," +
            rightSerial

        subtreeCount[serial]++

        if subtreeCount[serial] == 2 {
            duplicates = append(duplicates, node)
        }

        return serial
    }

    dfs(root)

    return duplicates
}
```Go 解决方案密切反映了 Python 实现。 

Go 使用`map[string]int`而不是Python的`defaultdict`。 访问时丢失的键会自动默认为零。 

递归 DFS 函数被声明为函数变量，因为 Go 中的递归匿名函数需要事先声明。 

空节点用以下表示`"#"`与 Python 版本完全相同。 

字符串连接是使用显式处理的`+`，并且整数节点值使用转换为字符串`strconv.Itoa`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^2) | O(n^2) | 序列化字符串可以与子树大小成比例增长 |

 尽管每个节点都被访问一次，但序列化构建并不是恒定的时间。 子树序列化可能包含许多字符，并且在最坏的情况下重复连接这些字符串可能会导致总成本呈二次方。 

对于平衡树，实际性能通常要好得多，但形式上的最坏情况仍然存在`O(n^2)`。 

高级优化会将整数 ID 分配给子树结构而不是完整字符串，从而将复杂性降低到接近`O(n)`。

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树不可能包含重复的子树，因为总共只有一棵子树。 

如果序列化跟踪处理不当，有缺陷的实现可能会错误地将单个子树计为重复。 此实现仅在子树的计数恰好达到时添加子树`2`，因此从未报告过单个事件。 

### 重复的叶节点

 叶节点是最小的可能子树。 具有相同值的多个叶子被视为重复子树，因为它们的结构和值都匹配。 

这种情况很重要，因为某些实现仅关注较大的子树，而忘记叶子也是有效的子树。 序列化格式自然地使用以下方式处理此问题：```
value,#,#
```它唯一地代表叶节点。 

### 相同的值但不同的结构

 两个子树可能包含相同的值但具有不同的形状。 

例如：```
    2          2
   /            \
  3              3
```这些不是重复的，因为它们的结构不同。 

序列化显式包含空标记，因此它们会产生不同的序列化：```
2,3,#,#,#
2,#,3,#,#
```这保证了结构差异得以保留。 

### 大倾斜树

 高度不平衡的树的行为类似于链表。 递归实现可能会带来递归深度过深的风险。 

该算法仍然可以正常工作，因为每个节点只处理一次，并且即使在退化树中，空标记也可以准确地保留子树结构。
