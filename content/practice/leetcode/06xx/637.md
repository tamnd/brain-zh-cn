[LeetCode 637 题](https://leetcode.com/problems/average-of-levels-in-binary-tree/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了二叉树的根节点，我们需要计算树的每个深度级别的所有节点的平均值。 

二叉树被组织成多个级别。 根节点处于级别`0`，它的孩子们处于水平`1`，他们的孩子处于同一水平`2`， 等等。 对于每个级别，我们必须计算：

 - 该级别上所有节点值的总和
 - 该级别的节点数
 - 平均值，即`sum / count`结果应作为浮点数数组返回，其中索引处的元素`i`表示该级别所有节点的平均值`i`。 

例如，考虑这棵树：```
        3
      /   \
     9     20
          /  \
         15   7
```级别为：

 - 0级：`[3]`, 平均值 =`3`- 1 级：`[9, 20]`, 平均值 =`(9 + 20) / 2 = 14.5`- 2 级：`[15, 7]`, 平均值 =`(15 + 7) / 2 = 11`所以输出变成：```
[3.0, 14.5, 11.0]
```约束告诉我们树最多可以包含`10^4`节点。 这意味着该解决方案必须足够高效，能够仅处理每个节点少量的次数。 由于每个节点只对一个级别的平均值做出贡献，因此`O(n)`解决方案是理想的。 

节点值也可能非常大，包括负值。 这意味着我们应该避免诸如所有总和均为正数之类的假设。 

一些边缘情况很重要：

 - 一棵只有一个节点的树
 - 一棵完全倾斜的树，其中每个节点只有一个子节点
 - 包含负值的树
 - 多层次的大树
 - 包含非常大金额的级别

 该问题保证树至少包含一个节点，因此我们永远不会收到一棵空树。 

## 方法

 ### 蛮力方法

 暴力解决方案首先确定树的高度，然后分别针对每个级别，再次遍历整个树以收集属于该级别的所有节点。 

例如：

 1.计算树高
 2. 对于级别`0`，遍历整棵树并收集深度节点`0`3. 对于级别`1`，再次遍历整棵树
 4.继续直到最深处

 这是有效的，因为每次遍历都能正确识别属于特定深度的节点。 然而，它的效率很低，因为相同的节点被重新访问很多次。 

如果树有`n`节点和高度`h`，复杂度变为`O(n * h)`。 在最坏的情况下，倾斜的树有高度`n`，导致`O(n^2)`时间复杂度。 

这是不必要的昂贵，因为我们可以在一次遍历中处理所有级别。 

### 最佳方法

 关键的观察结果是二叉树天生适合使用广度优先搜索 (BFS) 进行级别顺序遍历。 

BFS逐级处理节点：

 - 从根开始
 - 处理当前队列中的所有节点
 - 将他们的孩子添加到队列中
 - 进入下一个级别

 因为队列已经按遍历级别对节点进行分组，所以我们可以计算：

 - 当前级别的总和
 - 当前级别的节点数

 然后我们直接计算平均值，然后再进入下一个级别。 

每个节点都被访问一次，使得这种方法的时间复杂度呈线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * h) | O(h) | 为每个级别分别重新遍历树 |
 | 最佳| O(n) | O(w) | 使用 BFS 对每个节点只处理一次 |

 这里：

-`n`是节点数
 -`h`是树的高度
 -`w`是树的最大宽度

 ## 算法演练

 ### BFS 层级顺序遍历

 1. 创建一个空结果数组来存储每个级别的平均值。 
2. 以根节点初始化队列。 队列是理想的选择，因为 BFS 需要先进先出处理。 
3. 当队列不为空时，一次处理一层。 
4. 确定当前队列中的节点数。 该计数代表属于当前级别的所有节点。 
5. 初始化一个变量来存储当前级别的值之和。 
6. 准确处理`level_size`节点：

 - 从队列前面删除一个节点
 - 将其值添加到当前级别总和中
 - 如果该节点有左子节点，则将其添加到队列中
 - 如果该节点有右子节点，则将其添加到队列中
 7. 处理完整个关卡后，计算：```
average = level_sum / level_size
```8. 将计算出的平均值附加到结果数组中。 
9. 继续，直到处理完所有级别。 
10. 返回结果数组。 

### 为什么它有效

 队列始终包含按遍历顺序分组的节点。 在每次迭代开始时，队列恰好保存一个树级别的节点。 通过精确加工`level_size`在继续前进之前，我们保证计算出的总和和计数仅属于该级别。 由于每个节点都被访问一次并且恰好贡献一个级别总和，因此所有平均值都被正确计算。 

## Python 解决方案```python
from collections import deque
from typing import List, Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def averageOfLevels(self, root: Optional[TreeNode]) -> List[float]:
        result = []
        queue = deque([root])

        while queue:
            level_size = len(queue)
            level_sum = 0

            for _ in range(level_size):
                node = queue.popleft()
                level_sum += node.val

                if node.left:
                    queue.append(node.left)

                if node.right:
                    queue.append(node.right)

            result.append(level_sum / level_size)

        return result
```实现首先创建一个用根节点初始化的队列。 队列支持级别顺序遍历，这是独立处理树级别的自然方式。 

在主循环内部，`level_size`捕获有多少个节点属于当前级别。 这很重要，因为在处理过程中添加的新子节点属于下一个级别，并且不应影响当前平均值。 

内循环处理当前级别的每个节点。 每个节点都贡献自己的价值`level_sum`，及其子项将添加到队列中以供将来处理。 

处理完当前级别的所有节点后，计算平均值并将其附加到结果列表中。 

最后，一旦队列变空，所有级别都已处理完毕并返回结果。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func averageOfLevels(root *TreeNode) []float64 {
    result := []float64{}
    queue := []*TreeNode{root}

    for len(queue) > 0 {
        levelSize := len(queue)
        levelSum := 0

        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]

            levelSum += node.Val

            if node.Left != nil {
                queue = append(queue, node.Left)
            }

            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }

        average := float64(levelSum) / float64(levelSize)
        result = append(result, average)
    }

    return result
}
```Go 实现遵循与 Python 解决方案相同的 BFS 策略。 

而不是Python的`deque`，Go使用切片来模拟队列。 使用以下方法从前面删除节点：```go
queue = queue[1:]
```由于 Go 中的整数除法会截断小数，因此总和和大小都会转换为`float64`划分之前。 

Go 也使用显式`nil`在将子节点添加到队列之前检查它们。

 ## 边缘情况

 ### 单节点树

 仅包含根节点的树是最小的有效输入。 这种情况很重要，因为某些实现意外地假设存在子节点或多个级别。 

例如：```
    5
```正确的结果是：```
[5.0]
```该实现自然地处理这个问题，因为队列最初只包含根。 BFS 循环处理一级并干净地终止。 

### 倾斜树

 倾斜树的行为与链表类似：```
1
 \
  2
   \
    3
```在这种情况下，每一层都包含一个节点。 一些不正确的实现可能假设每个级别有多个节点或错误处理队列更新。 

BFS 解决方案可以正常工作，因为`level_size`变成`1`对于每次迭代，每个级别都会产生一个平均值。 

### 负节点值

 该问题允许负整数：```
      -10
      / \
   -20  -30
```第二级的平均值变为：```
(-20 + -30) / 2 = -25
```某些实现错误地初始化总和或假定非负值。 所提出的解决方案仅执行正常算术，因此无需任何特殊逻辑即可处理负数。 

### 非常广泛的水平

 完全二叉树可以在单个级别上包含许多节点。 这测试队列是否正确管理大批量节点。 

由于该算法逐级处理节点并且仅存储当前边界，因此它可以有效地处理大宽度，同时保持线性时间复杂度。
