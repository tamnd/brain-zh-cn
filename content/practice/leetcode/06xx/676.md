[LeetCode 第 676 题](https://leetcode.com/problems/implement-magic-dictionary/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、深度优先搜索、设计、Trie

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个类似字典的数据结构，支持两种操作。 首先，我们将不同单词的集合加载到结构中。 其次，给定一个查询字符串，我们确定是否可以精确修改查询中的一个字符，以便结果字符串与存储的字典单词之一匹配。 

重要的细节是“恰好一个字符”这一短语。 这意味着：

 - 我们必须改变一个角色。 
- 我们不能让这个词保持不变。 
- 我们无法插入或删除字符。 
- 修改后的单词必须与原始查询具有相同的长度。 

例如，如果字典包含`"hello"`查询是`"hhllo"`，我们可以改变第二个字符`'h'`到`'e'`，生产`"hello"`。 因此答案是`true`。 

但是，如果查询已经`"hello"`，答案是`false`因为需要零次修改，而不是一次。 

输入包括：

 - 独特的小写英语单词的字典数组。 
- 多个搜索查询。 

每个搜索查询的输出是一个布尔值，指示是否恰好一个字符替换可以将查询转换为字典单词。 

限制相对较小：

 - 最多 100 个字典单词。 
- 每个单词长度最多为 100。 
- 最多 100 次搜索操作。 

这些限制足够小，即使是效率较低的解决方案也可以轻松通过。 这很重要，因为它使我们能够优先考虑简单性和清晰度，而不是高度优化的基于 trie 的实现。 

一些边缘情况尤其重要：

 - 搜索词可能已经存在于字典中，但仍必须返回`false`除非另一个字典单词恰好有一个字符不同。 
- 不同长度的单词永远无法匹配，因为只允许替换操作。 
- 多个词典单词可能共享前缀或彼此相差一个字符。 
- 非常短的单词（例如长度 1）需要小心处理，因为替换唯一的字符是有效的。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将搜索词与词典中的每个词进行比较。 

对于每个字典单词：

 - 如果长度不同，请立即跳过，因为替换操作无法更改长度。 
- 否则，逐个字符比较两个单词。 
- 计算有多少个位置包含不同的字符。 
- 如果差异的个数恰好为 1，则返回`true`。 

如果字典中没有单词满足条件，则返回`false`。 

这种方法是正确的，因为它明确地检查问题陈述中的确切要求。 每个候选单词都会被测试，只有当一个字符完全不同时才接受匹配。 

虽然这种方法在技术上是蛮力的，但约束足够小，对于 LeetCode 来说已经足够高效了。 

### 优化观察

 思考这个问题的一种更结构化的方法是，只有相同长度的单词才是相关的。 因此，我们可以按长度对单词进行分组，而不是盲目地扫描字典中的每个单词。 

这种优化避免了与永远无法匹配的单词进行不必要的比较。 

关键的见解是：

 - 替换操作保留字长。 
- 因此，查询只需与相同长度的字典单词进行比较。 

我们可以将字典单词存储在哈希映射中，其中键是单词长度，值是具有该长度的单词列表。 

然后在搜索过程中：

 - 仅检索长度匹配的单词。 
- 比较字符并计算不匹配的数量。 
- 返回`true`如果恰好存在一个不匹配。 

这减少了不必要的工作，同时保持实现简单和可读。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次搜索 O(N × L) | O(N × L) | 将搜索词与每个词典词进行比较 |
 | 最佳 | 每次搜索 O(K × L) | O(N × L) | 仅与长度匹配的单词进行比较 |

 这里：

-`N`是字典单词的数量。 
-`K`是与查询长度相同的字典单词的数量。 
-`L`是字长。 

## 算法演练

 ### 最优算法

 1. 初始化一个哈希映射，根据单词的长度对单词进行分组。 

按长度分组的原因是只有长度相同的单词在一次替换后才有可能匹配。 这会立即排除不可能的候选人。 
2. 期间`buildDict`，迭代每个字典单词。 

对于每个单词：

 - 计算它的长度。 
- 将单词插入与该长度相关的列表中。 

此预处理步骤可以有效地组织字典以供将来的搜索使用。 
3.期间`search`，首先确定查询词的长度。 

如果字典中没有该长度的单词，则立即返回`false`因为替换操作不能改变字符串长度。 
4. 迭代所有具有匹配长度的字典单词。 

对于每个候选词：

 - 将不匹配计数器初始化为零。 
- 比较每个索引处的字符。 
5. 比较字符时：

 - 如果字符不同，则增加不匹配计数器。 
- 如果不匹配计数器超过1，则尽早停止检查该单词，因为它已经违反了要求。 

提前终止可以提高效率并避免不必要的比较。 
6. 比较全字后：

 - 如果不匹配计数恰好为1，则返回`true`。 
- 否则继续检查其他候选词。 
7. 如果没有候选者产生恰好一个不匹配，则返回`false`。 

### 为什么它有效

 该算法是正确的，因为它检查可能与搜索词匹配的每个字典词。 不同长度的单词是不可能的候选者，并且会被安全地忽略。 对于每个有效长度候选者，该算法精确地计算不同的字符位置。 仅当不匹配计数等于 1（恰好符合问题要求）时才接受单词。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class MagicDictionary:

    def __init__(self):
        self.words_by_length = defaultdict(list)

    def buildDict(self, dictionary: List[str]) -> None:
        for word in dictionary:
            self.words_by_length[len(word)].append(word)

    def search(self, searchWord: str) -> bool:
        target_length = len(searchWord)

        if target_length not in self.words_by_length:
            return False

        for candidate in self.words_by_length[target_length]:
            differences = 0

            for index in range(target_length):
                if searchWord[index] != candidate[index]:
                    differences += 1

                    if differences > 1:
                        break

            if differences == 1:
                return True

        return False

# Your MagicDictionary object will be instantiated and called as such:
# obj = MagicDictionary()
# obj.buildDict(dictionary)
# param_2 = obj.search(searchWord)
```实施首先创建一个`defaultdict(list)`命名的`words_by_length`。 这会根据字典单词的长度对单词进行分组，从而允许搜索操作立即忽略不可能的候选单词。 

这`buildDict`方法迭代每个字典单词并将其附加到与其长度相对应的列表中。 

这`search`方法首先计算查询长度。 如果不存在该长度的单词，则立即返回`False`。 

接下来，该方法迭代具有相同长度的每个候选单词。 对于每个候选者，它都会计算字符不匹配的数量。 如果发生多个不匹配，则循环会提前停止，因为候选者不再满足要求。 

如果比较所有字符后恰好存在一个不匹配，则该方法返回`True`。 否则，在检查完所有候选者之后，该方法返回`False`。 

## 解决方案```go
package main

type MagicDictionary struct {
	wordsByLength map[int][]string
}

func Constructor() MagicDictionary {
	return MagicDictionary{
		wordsByLength: make(map[int][]string),
	}
}

func (this *MagicDictionary) BuildDict(dictionary []string) {
	for _, word := range dictionary {
		length := len(word)
		this.wordsByLength[length] = append(this.wordsByLength[length], word)
	}
}

func (this *MagicDictionary) Search(searchWord string) bool {
	targetLength := len(searchWord)

	candidates, exists := this.wordsByLength[targetLength]
	if !exists {
		return false
	}

	for _, candidate := range candidates {
		differences := 0

		for i := 0; i < targetLength; i++ {
			if searchWord[i] != candidate[i] {
				differences++

				if differences > 1 {
					break
				}
			}
		}

		if differences == 1 {
			return true
		}
	}

	return false
}

/**
 * Your MagicDictionary object will be instantiated and called as such:
 * obj := Constructor();
 * obj.BuildDict(dictionary);
 * param_2 := obj.Search(searchWord);
 */
```Go 的实现与 Python 解决方案非常相似。 主要区别在于 Go 使用`map[int][]string`而不是Python的`defaultdict`。 

Go 字符串是字节可索引的，这里可以正常工作，因为问题只保证小写英文字母。 不需要 Unicode 处理。 

映射查找返回候选切片和指示键是否存在的布尔值。 当不存在所需长度的单词时，这可以避免不必要的迭代。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每次搜索 O(K × L) | 仅与相同长度的单词进行比较 |
 | 空间| O(N × L) | 存储所有字典单词 |

 这里：

-`N`是字典单词的数量。 
-`L`是最大字长。 
-`K`是与搜索词具有相同长度的单词数。 

预处理步骤存储按长度分组的所有单词，需要与字典总大小成比例的线性空间。 

在搜索过程中，逐字符扫描匹配长度的每个候选词。 由于一旦计数超过一，不匹配就会提前终止，因此实际性能通常比最坏情况要好。

 ## 边缘情况

 ### 字典中存在精确匹配

 当搜索词已存在于词典中时，就会出现一种微妙的情况。 幼稚的实现可能会错误地返回`true`因为这个词被发现了。 

然而，该问题只需要修改一个字符。 不允许零修改。 

例如：```
Dictionary: ["hello"]
Search: "hello"
```该实现正确地计算出零差异并拒绝匹配，因为不匹配计数必须恰好等于 1。 

### 不同的字长

 另一个重要的边缘情况涉及不同长度的字符串。 

由于只允许字符替换，因此插入和删除操作无效。 因此，不同长度的单词永远无法匹配。 

例如：```
Dictionary: ["hello"]
Search: "hell"
```该实现通过按长度对单词进行分组并立即返回来有效地处理这个问题`false`如果不存在相同长度的候选者。 

### 多重差异

 候选词可能在多个位置上有所不同。 

例如：```
Dictionary: ["hello"]
Search: "world"
```有多个不匹配的位置，所以答案一定是`false`。 

该实现会在比较期间跟踪不匹配情况，并在计数超过 1 时提前退出。 这既提高了效率又保证了正确性。
