[LeetCode 第 659 题](https://leetcode.com/problems/split-array-into-consecutive-subsequences/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题给了我们一个排序的整数数组`nums`，并询问我们是否可以将每个元素划分为一个或多个满足两个条件的子序列。 

首先，每个子序列必须由连续递增的整数组成。 这意味着每个下一个值必须准确无误`1`比之前的值大。 例如，`[3,4,5]`是有效的，同时`[3,5,6]`不是。 

其次，每个子序列必须至少有长度`3`。 短子序列如`[1,2]`即使它们是连续的，也是无效的。 

重要的细节是数组中的每个数字都必须恰好属于一个子序列。 我们不允许丢弃元素。 

因为输入数组已经按非降序排序，所以我们可以从左到右贪婪地处理数字。 排序顺序非常重要，因为连续的子序列自然依赖于在较大的数字之前处理较小的数字。 

约束相对较小，`nums.length <= 10^4`，但足够大以至于指数或重型回溯解决方案将无法有效工作。 我们需要接近线性时间的东西。 

一些边缘情况很重要：

 - 重复的数字可能会出现多次，这意味着我们可能需要维护多个以相同值结尾的子序列。 
- 某些数字可能无法扩展为有效的子序列，尤其是在数组末尾附近。 
- 始终启动新子序列的幼稚策略可能会失败，因为可能会保留较短的未完成子序列。 
- 总元素少于三个的数组自动是不可能的，除非它们为空，而约束不允许。 

例如，`[1,2,3,4,4,5]`失败是因为一`4`可以延长`[1,2,3]`进入`[1,2,3,4,5]`，但是第二个`4`不能形成至少长度的有效子序列`3`。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的方法将每个数字分配给一个子序列。 对于每个元素，我们可以决定是将其附加到现有子序列还是开始一个新子序列。 

这种方法是正确的，因为它探索了数组的每种可能的分区。 最终，如果存在有效的排列，搜索就会发现它。 

然而，可能的分配数量呈指数增长。 由于重复和许多分支选择，递归树变得巨大。 即使是中等的输入大小也变得不可行。 

例如，如果几个子序列可以合法地接受当前数字，则蛮力会独立探索所有子序列。 这导致指数时间复杂度。 

### 最优贪心法

 关键的观察结果是，扩展现有的子序列总是比开始新的子序列更重要。 

假设我们已经有一个以`x-1`。 当我们遇到`x`，扩展该子序列比创建从以下位置开始的新子序列更安全`x`。 为什么？ 因为短子序列是危险的。 长度的子序列`1`或者`2`仍然需要未来的数字才能生效。 

如果我们不必要地开始新的子序列，我们可能会在达到长度之前让旧的子序列陷入困境`3`。 

这自然会导致贪婪策略：

 - 始终尝试扩展以以下结尾的现有子序列`num - 1`。 
- 仅当无法扩展时才开始新的子序列。 
- 当开始一个新的子序列时，立即验证`num + 1`和`num + 2`存在，因为每个子序列最终必须至少达到长度`3`。 

我们维护两个哈希图：

 -`frequency[num]`跟踪每个号码有多少份未使用。 
-`subsequences[num]`跟踪当前有多少个子序列结束`num`。 

这允许在线性时间内进行高效的贪婪决策。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) 或更糟 | O(n) | 尝试所有可能的子序列分配 |
 | 最佳| O(n) | O(n) | 在创建新子序列之前贪婪地扩展现有子序列 |

 ## 算法演练

 1. 统计数组中每个数字出现的频率。 

我们使用一个名为的哈希图`frequency`。 这告诉我们每个值有多少个未使用的副本仍然可用。 

例如：```
nums = [1,2,3,3,4,5]

frequency:
1 -> 1
2 -> 1
3 -> 2
4 -> 1
5 -> 1
```2. 创建另一个哈希映射来跟踪活动子序列。 

我们使用`subsequences[end]`表示当前有多少个子序列以该值结尾`end`。 

最初，不存在任何子序列。 
3. 从左到右处理数组。 

由于数组是排序的，因此我们总是在处理较大的数字之前处理较小的数字。 
4. 跳过已经使用过的号码。 

如果`frequency[num] == 0`，那么该数字的所有副本都已分配给子序列，因此我们继续。 
5. 尝试扩展现有的结束于的子序列`num - 1`。 

如果`subsequences[num - 1] > 0`，则存在一个可以接受的子序列`num`。 

我们贪婪地扩展它，因为扩展旧的子序列可以防止它们变成无效的短序列。 

步骤：

 - 减少`subsequences[num - 1]`- 增加`subsequences[num]`- 减少`frequency[num]`6. 如果无法扩展，请尝试开始新的子序列。 

要创建有效的新子序列，我们必须立即保留：

 -`num`-`num + 1`-`num + 2`如果其中任何一个不可用，答案会立即`false`。 
7. 创建新的子序列。 

如果所有必需的数字都存在：

 - 减少频率`num`,`num+1`， 和`num+2`- 记录结束于的子序列`num+2`8. 如果无法扩展或创建，则返回`false`。 

这意味着当前数字不能属于任何有效的子序列排列。 
9. 如果所有号码都处理成功，则返回`true`。 

### 为什么它有效

 贪婪不变量是扩展现有子序列总是比开始新子序列更安全。 现有的子序列可能仍然太短，需要未来的数字才能有效。 如果我们忽略它们并创建新的子序列，我们就有可能留下未完成的序列。 

通过始终优先考虑扩展，我们可以最大限度地减少未完成子序列的数量，并保证每个开始的子序列最终至少可以达到长度`3`。 

## Python 解决方案```python
from collections import Counter, defaultdict
from typing import List

class Solution:
    def isPossible(self, nums: List[int]) -> bool:
        frequency = Counter(nums)
        subsequences = defaultdict(int)

        for num in nums:
            if frequency[num] == 0:
                continue

            # Use current number to extend an existing subsequence
            if subsequences[num - 1] > 0:
                subsequences[num - 1] -= 1
                subsequences[num] += 1
                frequency[num] -= 1

            # Otherwise, try to create a new subsequence
            elif frequency[num + 1] > 0 and frequency[num + 2] > 0:
                frequency[num] -= 1
                frequency[num + 1] -= 1
                frequency[num + 2] -= 1

                subsequences[num + 2] += 1

            # Neither extending nor creating is possible
            else:
                return False

        return True
```该实现首先使用以下方法计算每个数字存在多少个副本`Counter`。 这允许恒定时间查找剩余未使用的值。 

这`subsequences`map 跟踪每个数字结束的子序列数量。 如果`subsequences[4] == 2`，这意味着当前有两个子序列以`4`并且可能会被延长`5`。 

在循环内部，我们首先跳过先前操作已经消耗的数字。 

最重要的部分是贪婪扩展步骤。 如果子序列结束于`num - 1`存在，我们立即扩展它。 这可以防止短子序列被搁浅。 

如果扩展不可能，我们尝试开始一个全新的子序列。 但是，我们仅在以下情况下才这样做`num + 1`和`num + 2`可用。 这保证了新的子序列已经满足最小长度要求。 

如果这两个操作都不可能，则配置无效，因此我们返回`False`。 

如果循环成功完成，则每个数字都已分配给有效的子序列。 

## 解决方案```go
func isPossible(nums []int) bool {
	frequency := make(map[int]int)
	subsequences := make(map[int]int)

	for _, num := range nums {
		frequency[num]++
	}

	for _, num := range nums {
		if frequency[num] == 0 {
			continue
		}

		// Extend an existing subsequence
		if subsequences[num-1] > 0 {
			subsequences[num-1]--
			subsequences[num]++
			frequency[num]--

		// Create a new subsequence
		} else if frequency[num+1] > 0 && frequency[num+2] > 0 {
			frequency[num]--
			frequency[num+1]--
			frequency[num+2]--

			subsequences[num+2]++

		// Impossible to place current number
		} else {
			return false
		}
	}

	return true
}
```Go 的实现与 Python 解决方案非常相似。 Go 映射会针对缺失的键返回零值，这很方便，因为不存在的条目会自动表现得像频率一样`0`。 

与Python不同`defaultdict`，Go 不需要对缺失的键进行显式初始化。 访问不存在的键只会返回`0`。 

由于约束很小，因此不存在整数溢出问题。 切片直接用于迭代输入数组。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个数字都会被处理固定次数 |
 | 空间| O(n) | 哈希映射存储频率和子序列计数 |

 该算法是线性的，因为哈希映射上的每个操作平均时间都是恒定的，并且每个数组元素在处理过程中都会被访问一次。 

空间复杂度是线性的，因为频率图和子序列图可能各自包含最多`n`在最坏的情况下不同的键。

 ## 边缘情况

 一种重要的边缘情况是数组太短而无法形成有效的子序列。 例如，`[1,2]`不可能满足最小长度要求`3`。 幼稚的实现可能会错误地将任何连续序列视为有效。 此实现正确地拒绝了此类情况，因为它仅在以下情况下启动新的子序列：`num+1`和`num+2`两者都存在。 

另一个棘手的边缘情况涉及重复值。 考虑`[1,1,2,2,3,3]`。 糟糕的贪婪策略可能会让两者都`1`进入相同的子序列尝试，稍后留下不匹配的数字。 频率图和子序列跟踪确保每个副本独立使用并正确分布在多个子序列中。 

当出现一个数字既不能扩展现有子序列也不能启动新的有效子序列时，就会出现第三种重要的边缘情况。 例如，在`[1,2,3,4,4,5]`，第二个`4`变得搁浅，因为没有子序列结束于`3`， 和`6`不存在可创建`[4,5,6]`。 该实现立即检测到这一点并返回`False`。 

另一个微妙的边缘情况涉及负数。 由于该问题允许值小至`-1000`，算法不得假设数字为正数。 由于该解决方案使用以整数为键的哈希映射而不是数组索引，因此可以自然地处理负值，无需特殊逻辑。
