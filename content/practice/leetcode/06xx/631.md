[LeetCode 第 631 题](https://leetcode.com/problems/design-excel-sum-formula/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、字符串、图论、设计、拓扑排序、矩阵

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个类似于 Microsoft Excel 的微型电子表格系统。 电子表格包含按行和列排列的单元格，其中行从`1`并且列使用大写字母标记，例如`A`,`B`,`C`， 等等。 

每个单元可以存储：

 - 直接整数值
 - 表示其他单元格或单元格范围之和的公式

 关键的挑战是公式是动态的。 如果公式单元格依赖于其他单元格，并且这些源单元格之一稍后发生更改，则公式单元格必须自动反映更新后的值。 

例如，假设细胞`C3`存储公式：```
=A1 + A1:B2
```如果引用范围内的任何单元格稍后发生更改，`C3`也必须自动改变。 

该类必须支持四种操作：

 ### 初始化

 我们创建一个具有固定高度和宽度的电子表格。 每个细胞都以价值开始`0`。 

### 集合（行、列、值）

 此操作将直接值分配给单元格。 

如果单元格以前包含公式，则必须删除该公式并用显式值替换。 

### 获取（行，列）

 这将返回单元格的当前值。 

如果单元格包含公式，则其值必须反映所有当前依赖项。 

### sum(行、列、数字)

 此操作定义单元格的公式。 

这`numbers`列表可能包含：

 - 单细胞，例如`"A1"`- 矩形范围，例如`"B2:D5"`该公式一直持续到另一个`set`或者`sum`覆盖单元格。 

一个重要的保证是循环引用永远不存在。 因此，我们永远不需要处理无限依赖循环。 

限制条件故意很小：

 - 最大网格尺寸为`26 x 26`- 至多`100`操作发生

 这意味着我们不需要极其先进的优化技术。 一个干净的依赖图解决方案就足够了。 

一些边缘情况很重要：

 - 一个公式可以多次引用同一单元格
 - 一个范围可能与另一个范围重叠
 - 更新源单元格必须更新所有依赖公式单元格
 - 重写公式`set()`必须完全删除旧的依赖项
 - 公式可能递归地依赖于其他公式单元格

 这些案例使得依赖跟踪成为问题的核心难点。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是在每次更新后从头开始重新计算每个公式单元格。 

这个想法很简单：

 - 存储细胞的原始公式
 - 每当`set()`更改值，扫描整个电子表格
 - 递归地重新计算每个公式

 这是有效的，因为由于无循环保证，公式形成有向无环图。 

然而，这种方法效率低下，因为每次更新都可能触发许多不相关单元的重新计算。 尽管限制很小，但重复扫描整个电子表格是不必要的且效率低下。 

蛮力解决方案也变得更难以管理，因为递归重新计算可能会多次重新访问相同的公式。 

### 最佳方法

 更好的解决方案将电子表格视为依赖图。 

每个公式单元格存储：

 - 它依赖于哪些细胞
 - 每个依赖项贡献了多少次

 例如：```
=A1 + A1:B2
```方法：```
A1 contributes twice
B1 contributes once
A2 contributes once
B2 contributes once
```我们不是急切地更新所有单元格，而是使用深度优先搜索来延迟计算公式值。 

关键的观察结果是公式单元格的值完全由其依赖项的当前值决定。 

所以：

-`set()`存储原始值并删除任何旧公式
 -`sum()`存储依赖关系映射
 -`get()`需要时递归计算公式

 因为没有循环，所以递归是安全的。 

这创建了一个干净且可维护的设计。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次更新 O(H × W × D) | O(高 × 宽) | 重复重新计算许多不相关的公式 |
 | 最佳| 每次评估的 O(D) | O(高 × 宽 + 东) | 使用具有递归求值的依赖图 |

 这里：

-`H × W`是电子表格大小
 -`D`是引用的依赖项总数
 -`E`是依赖边的数量

 ## 算法演练

 ### 1. 唯一地表示每个单元格

 我们使用元组表示每个单元格：```
(row, column)
```例如：```
(1, 'A')
```这使得单元格很容易用作字典键。 

### 2. 将直接值与公式分开存储

 我们维护两种结构：

 -`values[cell]`存储直接整数值
 -`formulas[cell]`存储依赖关系映射

 公式映射如下所示：```
{
    dependency_cell: frequency
}
```例如：```
{
    (1, 'A'): 2,
    (1, 'B'): 1,
    (2, 'A'): 1,
    (2, 'B'): 1
}
```这可以正确处理重复引用。 

### 3. 将范围解析为单个单元格

 当处理字符串时，例如：```
"B2:D4"
```我们将矩形扩展到所有单独的单元格。 

这简化了以后的评估，因为公式只需要显式的依赖关系映射。 

### 4.句柄set()

 直接赋值时：

 - 删除任何现有的公式
 - 存储新值

 这很重要，因为公式会一直存在直到被覆盖。 

### 5. 处理 sum()

 创建公式时：

 - 解析每个范围或单个单元格
 - 计算每个引用单元格出现的次数
 - 存储依赖关系映射
 - 返回评估值

 ### 6. 递归计算单元格`get()`递归地工作。 

如果单元格包含直接值：

 - 立即归还

 如果单元格包含公式：

 - 递归评估每个依赖项
 - 乘以它的频率
 - 对结果求和

 由于该图是非循环的，因此递归总是安全终止。 

### 7.自然支持嵌套公式

 公式可能依赖于另一个公式单元格。 

自从`get()`递归地评估依赖关系，嵌套公式自动工作，无需特殊处理。 

### 为什么它有效

 该算法保持了每个公式单元格都存储其依赖关系的精确映射的不变性。 

每当`get()`评估一个单元格时，它会递归地计算所有依赖项的当前值。 由于公式永远不会形成循环，因此递归计算始终终止并始终反映最新的电子表格状态。 

因此每个返回值都是正确的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Excel:

    def __init__(self, height: int, width: str):
        self.values = {}
        self.formulas = {}
        self.height = height
        self.width = width

    def set(self, row: int, column: str, val: int) -> None:
        cell = (row, column)

        if cell in self.formulas:
            del self.formulas[cell]

        self.values[cell] = val

    def get(self, row: int, column: str) -> int:
        cell = (row, column)

        if cell not in self.formulas:
            return self.values.get(cell, 0)

        total = 0

        for dep_cell, count in self.formulas[cell].items():
            total += self.get(dep_cell[0], dep_cell[1]) * count

        return total

    def sum(self, row: int, column: str, numbers: List[str]) -> int:
        cell = (row, column)

        formula = defaultdict(int)

        for item in numbers:
            if ':' not in item:
                r, c = self.parse_cell(item)
                formula[(r, c)] += 1
            else:
                start, end = item.split(':')

                r1, c1 = self.parse_cell(start)
                r2, c2 = self.parse_cell(end)

                for r in range(r1, r2 + 1):
                    for c in range(ord(c1), ord(c2) + 1):
                        formula[(r, chr(c))] += 1

        self.formulas[cell] = formula

        if cell in self.values:
            del self.values[cell]

        return self.get(row, column)

    def parse_cell(self, s: str):
        column = s[0]
        row = int(s[1:])
        return row, column
```该实现将直接值和公式分离到不同的字典中。 这清楚地区分了存储原始整数的单元和存储计算表达式的单元。 

这`set()`方法在存储新值之前删除任何现有公式。 这与公式一旦被覆盖就会消失的问题陈述相符。 

这`sum()`方法解析每个引用字符串。 直接添加单个单元格，而范围则扩展到所有包含的单元格。 频率图很重要，因为同一单元格可能在公式中出现多次。 

递归`get()`方法是解决问题的核心。 如果单元格包含公式，它会递归地评估所有依赖关系并根据它们的频率组合它们。 

由于公式从不包含循环，因此递归仍然是安全的。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

type Cell struct {
	row int
	col byte
}

type Excel struct {
	values   map[Cell]int
	formulas map[Cell]map[Cell]int
	height   int
	width    byte
}

func Constructor(height int, width byte) Excel {
	return Excel{
		values:   make(map[Cell]int),
		formulas: make(map[Cell]map[Cell]int),
		height:   height,
		width:    width,
	}
}

func (this *Excel) Set(row int, column byte, val int) {
	cell := Cell{row, column}

	delete(this.formulas, cell)
	this.values[cell] = val
}

func (this *Excel) Get(row int, column byte) int {
	cell := Cell{row, column}

	formula, exists := this.formulas[cell]

	if !exists {
		val, ok := this.values[cell]
		if !ok {
			return 0
		}
		return val
	}

	total := 0

	for depCell, count := range formula {
		total += this.Get(depCell.row, depCell.col) * count
	}

	return total
}

func (this *Excel) Sum(row int, column byte, numbers []string) int {
	cell := Cell{row, column}

	formula := make(map[Cell]int)

	for _, item := range numbers {
		if !strings.Contains(item, ":") {
			r, c := parseCell(item)
			formula[Cell{r, c}]++
		} else {
			parts := strings.Split(item, ":")

			r1, c1 := parseCell(parts[0])
			r2, c2 := parseCell(parts[1])

			for r := r1; r <= r2; r++ {
				for c := c1; c <= c2; c++ {
					formula[Cell{r, c}]++
				}
			}
		}
	}

	this.formulas[cell] = formula
	delete(this.values, cell)

	return this.Get(row, column)
}

func parseCell(s string) (int, byte) {
	col := s[0]
	row, _ := strconv.Atoi(s[1:])
	return row, col
}
```Go 实现遵循与 Python 版本相同的设计，但对单元格使用显式结构类型，因为 Go 不支持元组作为映射键。 

Go 映射自动返回零值，这简化了一些查找。 递归求值逻辑保持相同。 

整数溢出不是问题，因为约束非常小。

 ## 边缘情况

 ### 覆盖公式单元格

 当公式单元格稍后通过以下方式收到直接值时，就会出现一个微妙的问题：`set()`。 

例如：```
C1 = SUM(A1:B1)
```其次是：```
set(C1, 10)
```如果旧公式不删除，以后更新为`A1`或者`B1`会错误地继续影响`C1`。 

该实现通过删除公式条目来处理此问题`set()`被称为。 

### 公式中的重复引用

 公式可以多次引用同一单元格：```
["A1", "A1"]
```使用集合的简单实现会错误地计数`A1`只有一次。 

该解决方案使用频率图，因此每个依赖项都存储它贡献的次数。 

### 嵌套公式依赖关系

 一个公式可能依赖于另一个公式：```
B1 = SUM(A1)
C1 = SUM(B1)
```什么时候`A1`变化，两者`B1`和`C1`必须反映更新。 

递归`get()`实现自然会处理这个问题，因为评估`C1`递归地评估`B1`，递归地评估`A1`。 

### 范围内的空单元格

 范围可能包括从未明确分配的未触及的单元格。 

这些细胞必须做出贡献`0`。 

该实现使用以下方法安全地处理这个问题：```
self.values.get(cell, 0)
```因此缺失的单元格自动默认为零。
