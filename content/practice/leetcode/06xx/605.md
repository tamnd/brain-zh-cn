[LeetCode 第 605 题](https://leetcode.com/problems/can-place-flowers/)

 **难度：** 🟢简单
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为的二进制数组`flowerbed`， 在哪里：

-`0`代表一个空的图
 -`1`代表已经包含一朵花的地块

 我们还得到一个整数`n`，代表我们想要种植多少**新花**。 

关键的限制是**花不能种植在相邻的地块**。 这意味着如果一个地块包含一朵花，则紧邻其左侧和右侧的地块不能包含花朵。 

任务是确定是否可以准确种植`n`新花不打破这个邻接规则。 我们不需要归还改装后的花坛，只需要归还是否种植`n`花是可以的。 

换句话说，我们想要贪婪地找到可以种植花朵的有效空位置，同时确保没有两朵花相邻。 

输入大小受如下约束：

 -`1 <= flowerbed.length <= 2 * 10^4`- 每个值都是`0`或者`1`- 花坛已经满足无相邻花条件
 -`0 <= n <= flowerbed.length`这些约束告诉我们输入可能相当大，最多可达两万个元素。 由于这是一个简单的问题并且数组大小适中，因此`O(n)`解决方案是理想且易于实施的。 

在设计解决方案之前，需要考虑几个重要的边缘情况。 

花坛的长度`1`很特别。 例如，`[0]`可以接受一朵花，同时`[1]`不能。 边界位置很棘手，因为它们只有一个邻居而不是两个。 

另一个重要的情况发生在数组的开头或结尾。 例如，`[0,0,1]`或者`[1,0,0]`由于一侧缺失，因此需要小心处理。 

我们还需要考虑`n = 0`。 在这种情况下，答案应该始终是`true`，因为我们不需要种植任何东西。 

最后，如果在种植后没有正确更新花坛，幼稚的实现可能会在迭代期间意外地允许相邻放置。 

## 方法

 ### 蛮力方法

 A brute-force approach would try every possible planting combination and check whether at least`n`可以在不违反相邻规则的情况下放置鲜花。 

对于每个空位置，我们可以递归地决定是放置一朵花还是跳过它，然后验证所得的排列是否仍然有效。 这保证了正确性，因为每个有效的配置都会被探索。 

然而，这种方法变得非常昂贵，因为每个图都会引入多种可能性。 在最坏的情况下，组合的数量随着花坛的大小呈指数增长。 由于数组最多可以包含`20,000`元素，这种方法是完全不切实际的。 

### 最优贪心法

 关键的观察是**只要一个位置可以种植，我们就应该立即种植**。 

为什么这样安全？ 

如果一块地可以合法地种植花卉，那么在那里种植永远不会降低我们以后以有益的方式种植花卉的能力。 由于鲜花不能相邻，因此延迟有效的放置并不会创造更好的未来机会。 尽早贪婪地种植可以最大化我们可以放置的花朵总数。 

在每个位置，我们只需要检查三件事：

 - 当前地块是空的（`0`）
 - 左边的邻居是空的，或者情节在开始处
 - 右邻居是空的，或者情节在最后

 如果这三个条件都满足，我们就种一朵花，减少`n`，然后继续扫描。 

立刻`n`达到`0`，我们可以立即返回`true`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试所有种植组合 |
 | Optimal Greedy | O(n) | O(1) | O(1) | 扫描一次，有效贪婪种植 |

 ## 算法演练

 1. 处理琐碎的情况`n == 0`。 

如果不需要种花，我们可以立即返回`true`。 
2. 从左到右遍历花坛。 

在每个索引处，确定种植花卉是否合法。 
3. 检查当前绘图是否为空。 

如果`flowerbed[i] == 1`，跳过它，因为它已经被占用了。 
4. 检查左侧。 

只有当左边的邻居是空的时才能种花。 对于索引`0`，没有左邻居，因此我们将其视为有效。 

我们定义：`left_empty = (i == 0 or flowerbed[i - 1] == 0)`5. 检查右侧。 

同样，右邻居必须为空。 如果当前图是最终索引，我们将丢失的邻居视为空。 

我们定义：`right_empty = (i == len(flowerbed) - 1 or flowerbed[i + 1] == 0)`6. 如果双方都有效，就种一朵花。 

如果当前地块和两个邻居都满足规则，则放置一朵花：

 - 设置`flowerbed[i] = 1`- 递减`n`更新阵列很重要，因为未来的检查必须尊重新种植的花卉。 
7. 如果可能的话，尽早停止。 

如果`n == 0`， 返回`true`目标已经实现后立即。 
8. 完成扫描。 

循环结束后，返回是否`n <= 0`。 

### 为什么它有效

 该算法之所以有效，是因为贪心不变量：只要一个位置可以安全地容纳一朵花，在那里种植就不会减少我们以后可以放置的最大数量的花。 

由于邻近限制纯粹是本地的，因此有效的种植决策仅取决于邻近的地块。 在最早的有效位置种植永远不会妨碍以后更好的排列，这意味着贪婪策略总是最大化放置的花朵数量。 

因此，如果贪婪扫描无法放置`n`鲜花，没有其他布置可以。 

## Python 解决方案```python
from typing import List

class Solution:
    def canPlaceFlowers(self, flowerbed: List[int], n: int) -> bool:
        if n == 0:
            return True

        length = len(flowerbed)

        for index in range(length):
            if flowerbed[index] == 0:
                left_empty = (
                    index == 0 or flowerbed[index - 1] == 0
                )
                right_empty = (
                    index == length - 1
                    or flowerbed[index + 1] == 0
                )

                if left_empty and right_empty:
                    flowerbed[index] = 1
                    n -= 1

                    if n == 0:
                        return True

        return n <= 0
```实施从提前返回开始`n == 0`，因为不需要做任何工作。 

接下来，我们对花坛进行一次迭代。 对于每个空地块，我们检查相邻的地块是否都是空的。 通过将缺失的邻居视为空来自然地处理边界索引。 

找到有效位置后，我们通过将值更改为来模拟种植`1`。 这种修改至关重要，因为未来的职位必须尊重迭代早期种植的花朵。 

种植后，我们减少`n`。 如果`n`达到零时，我们立即返回，避免不必要的工作。 

如果循环结束并且`n`仍然是积极的，我们知道不可能放置足够的鲜花。 

## 解决方案```go
func canPlaceFlowers(flowerbed []int, n int) bool {
	if n == 0 {
		return true
	}

	length := len(flowerbed)

	for i := 0; i < length; i++ {
		if flowerbed[i] == 0 {
			leftEmpty := i == 0 || flowerbed[i-1] == 0
			rightEmpty := i == length-1 || flowerbed[i+1] == 0

			if leftEmpty && rightEmpty {
				flowerbed[i] = 1
				n--

				if n == 0 {
					return true
				}
			}
		}
	}

	return n <= 0
}
```Go 实现几乎完全反映了 Python 逻辑。 由于 Go 切片是可变的，因此更新`flowerbed[i] = 1`自然地工作并确保以后的检查看到修改后的状态。 

无需担心整数溢出，因为所有值都非常小并且受输入大小的限制。 Go也不区分`nil`和空切片在这里很重要，因为约束保证至少有一个元素。

 ## 边缘情况

 ### 单块花坛

 长度为一的花坛很容易处理不当，因为没有邻居。 例如，`[0]`应允许种植一朵花，同时`[1]`不应该。 有错误的实现可能会尝试访问无效索引。 

此实现通过通过条件将丢失的邻居视为空来处理该问题`index == 0`和`index == length - 1`。 

### 在边界种植

 第一个和最后一个位置只有一个真正的邻居，这使得它们成为差一错误的常见来源。 

例如，在`[0,0,1]`，第一个位置有效，因为它的右邻居为空并且没有左邻居。 同样，在`[1,0,0]`, the final position can be planted.

 该实现明确将不存在的邻居视为空，确保边界放置正确工作。 

### 新种的花会影响未来的决定

 如果算法在种植后不更新花坛，就会出现一个微妙的错误。 考虑`[0,0,0]`。 

如果我们在索引处种植`0`但忘记将其标记为已占用，索引`1`可能会错误地显示为可用，从而违反了邻接规则。 

此实施立即更新`flowerbed[index] = 1`，确保未来的检查反映新种植的花卉并保持正确性。
