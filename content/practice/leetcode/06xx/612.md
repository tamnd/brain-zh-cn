 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为`Point2D`，其中每一行代表 2D 笛卡尔平面上的一个唯一点。 每个点包含两个整数坐标，`x`和`y`。 这对`(x, y)`保证是唯一的，因为它是主键。 

我们被要求计算表中任意两个不同点之间的最短欧几里得距离。 两点之间的欧几里得距离：

 -`p1(x1, y1)`-`p2(x2, y2)`定义为：$$\sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$$最终答案必须四舍五入到小数点后两位。 

尽管这被归类为数据库问题，但底层算法任务是几何的。 我们必须比较点对并确定哪对点的距离最小。 

输入在概念上是点的集合。 输出是一个名为`shortest`，表示最小成对距离。 

一个重要的细节是，一个点不能与其自身进行比较。 由于该表包含唯一的坐标，因此我们永远不会有重复的点，这意味着最小距离将始终大于零。 

该问题没有明确说明行数，但典型的 LeetCode 数据库问题足够小，以至于`O(n²)`成对比较解决方案是可以接受的。 在 SQL 中，这自然会转化为自连接。 

需要考虑一些重要的边缘情况：

 - 如果两个点共享相同的点`x`坐标或相同`y`坐标，距离公式仍然正确。 
- 负坐标必须妥善处理，因为涉及减法和平方。 
- 多对可能共享相同的最小距离，但我们只需要距离值本身。 
- 由于坐标是唯一的，我们永远不会遇到距离`0.00`。 

## 方法

 ### 蛮力方法

 最直接的方法是将每个点与其他点进行比较。 对于每一对，我们使用距离公式计算欧几里德距离并跟踪遇到的最小值。 

在传统的编程语言中，这将涉及两个嵌套循环。 在 SQL 中，这变成了`Point2D`表和它本身。 

然而，我们必须避免将一个点与它本身进行比较。 我们还希望避免对同一对进行两次计数。 例如：

-`(A, B)`和`(B, A)`代表同一对。 

为了消除重复，我们可以强制执行排序条件，例如：```
p1.x < p2.x OR (p1.x = p2.x AND p1.y < p2.y)
```这确保了每个无序对都被恰好考虑一次。 

这种方法是正确的，因为它详尽地检查了所有可能的点对。 由于最小距离必须属于这些对之一，因此算法不会错过正确答案。 

缺点是比较次数随着点数的增加而呈二次方增长。 

### 关键见解

 重要的观察是，这个问题从根本上需要成对比较。 与使用分而治之优化的高级计算几何问题不同，SQL 设置和预期约束使二次方法既实用又标准。 

真正的优化不是降低渐近复杂度，而是避免冗余比较：

 - 不要将一个点与其自身进行比较。 
- 不要对同一对进行两次比较。 

通过仔细构建自连接条件，我们减少了不必要的工作，同时仍然保证了正确性。

 ## 算法演练

 1. 从`Point2D`表并创建两个别名，通常`p1`和`p2`。 这些别名代表正在比较的两个不同点。 
2. 在表和自身之间执行自连接。 这使得每个点都可以与其他点配对。 
3. 添加条件以避免无效比较。 具体来说：

 - 点不应与其自身配对。 
- 每个无序对只能出现一次。 

一个常见的条件是：```
p1.x < p2.x OR (p1.x = p2.x AND p1.y < p2.y)
```这在点之间创建了严格的顺序。 
4. 对于每个有效对，使用以下方法计算欧几里得距离：$$\sqrt{(p1.x - p2.x)^2 + (p1.y - p2.y)^2}$$5.使用SQL聚合函数`MIN()`跟踪所有对之间的最小距离。 
6. 使用以下方法将结果四舍五入到小数点后两位`ROUND(distance, 2)`。 
7. 返回最终值和列名`shortest`。 

### 为什么它有效

 该算法仅检查每对独特的不同点一次。 由于最短距离必须属于这些对之一，因此取所有计算距离的最小值可以保证正确的答案。 排序条件可防止重复比较而不排除任何有效对。 

## Python 解决方案

 即使这是一个数据库问题，我们仍然可以用Python表达底层逻辑。```python
from typing import List
from math import sqrt

class Solution:
    def shortestDistance(self, points: List[List[int]]) -> float:
        n = len(points)
        minimum_distance = float("inf")

        for i in range(n):
            x1, y1 = points[i]

            for j in range(i + 1, n):
                x2, y2 = points[j]

                distance = sqrt((x2 - x1) ** 2 + (y2 - y1) ** 2)

                minimum_distance = min(minimum_distance, distance)

        return round(minimum_distance, 2)
```该实现首先将最小距离初始化为无穷大，以便任何计算出的距离将取代它。 

外循环选择点对中的第一个点，而内循环选择第二个点。 请注意，内循环开始于`i + 1`，这可以防止：

 - 自我比较
 - 重复对比较

 对于每一对，直接评估欧几里德距离公式。 只要发现更小的距离，就会更新当前最小值。 

最后，在返回之前，答案会四舍五入到小数点后两位。 

## 解决方案```go
package main

import (
	"math"
)

func shortestDistance(points [][]int) float64 {
	n := len(points)
	minimumDistance := math.Inf(1)

	for i := 0; i < n; i++ {
		x1, y1 := points[i][0], points[i][1]

		for j := i + 1; j < n; j++ {
			x2, y2 := points[j][0], points[j][1]

			dx := float64(x2 - x1)
			dy := float64(y2 - y1)

			distance := math.Sqrt(dx*dx + dy*dy)

			if distance < minimumDistance {
				minimumDistance = distance
			}
		}
	}

	return math.Round(minimumDistance*100) / 100
}
```Go 版本遵循与 Python 实现相同的逻辑。 一个重要的区别是显式类型转换。 自从`math.Sqrt`运行于`float64`，在平方之前必须将坐标差从整数转换为浮点值。 

使用以下方法手动对结果进行舍入：```go
math.Round(value * 100) / 100
```因为Go没有为数字返回值提供内置的两位小数格式化函数。 

## SQL 解决方案```sql
SELECT
    ROUND(
        MIN(
            SQRT(
                POW(p1.x - p2.x, 2) +
                POW(p1.y - p2.y, 2)
            )
        ),
        2
    ) AS shortest
FROM Point2D p1
JOIN Point2D p2
ON p1.x < p2.x
OR (p1.x = p2.x AND p1.y < p2.y);
```此查询在表别名之间执行自连接`p1`和`p2`。 

连接条件确保：

 - 没有点与其自身匹配
 - 没有重复的对被计算两次

 对于每个有效对，欧几里得距离的计算方法为`SQRT`和`POW`。 这`MIN`聚合找到最小距离，并且`ROUND(..., 2)`正确设置答案格式。

 ## 边缘情况

 当点共享相同时，就会出现一种重要的边缘情况`x`协调。 在这种情况下，水平差变为零，只有垂直差对距离有贡献。 不正确的实现有时会错误地处理零差或在使用基于斜率的逻辑时意外除以零。 我们的实现直接应用欧几里得公式，因此自然可以处理零坐标差异。 

另一个关键的边缘情况涉及负坐标。 由于负值之间的减法可能容易出错，尤其是在手动操作公式时，因此实现可能会意外地计算出不正确的差异。 通过完全按照定义使用标准平方距离公式，实现可以正确处理负值，因为平方消除了符号问题。 

当多个点对共享相同的最短距离时，会出现第三种边缘情况。 某些实现在找到第一个最小值后会错误地停止或不正确地覆盖值。 我们的算法比较每个独特的对，并使用不断更新全局最小值`min()`，确保无论有多少对共享它，都保留正确的最小距离。
