[LeetCode 第 651 题](https://leetcode.com/problems/4-keys-keyboard/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个具有四种操作的键盘：

 - 按`A`，插入一个字符`'A'`- 按`Ctrl-A`，选择当前屏幕上的所有内容
 - 按`Ctrl-C`，它将选定的文本复制到剪贴板缓冲区中
 - 按`Ctrl-V`，将剪贴板内容粘贴到屏幕上

 我们给定一个整数`n`，代表我们允许的最大按键次数。 目标是确定最大数量`'A'`最多之后可以出现在屏幕上的字符`n`运营。 

乍一看，反复按`A`看起来很简单。 如果`n = 5`，我们可以简单地按`A`五次并最终得到五个字符。 然而，复制和粘贴操作带来了指数增长的可能性。 例如，在构建合理数量的文本后，我们可以复制整个屏幕并多次粘贴，从而比单独输入要快得多的字符数倍增。 

输入由单个整数组成：

 -`n`, 允许的按键次数

 输出是：

 - 最大数量`'A'`这些按键可实现的字符

 限制很小：

 -`1 <= n <= 50`这立即表明动态规划是可行的。 由于输入尺寸很小，即使是`O(n^2)`或者`O(n^3)`解决方案将在限制内舒适地运行。 

一些边缘情况很重要：

 - 非常小的值，例如`n = 1`,`n = 2`， 或者`n = 3`，其中复制和粘贴操作毫无用处，因为它们消耗了太多的压力。 
- 过早复制会降低总输出的情况，因为剪贴板操作本身需要按两次按键（`Ctrl-A`和`Ctrl-C`）。 
- 确保粘贴操作仅在有效的复制序列之后发生。 

该问题保证了`n`总是至少`1`，所以我们永远不需要处理无效或空的输入。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的操作序列，直至达到长度`n`。 在每一步中，我们可以选择四种操作：

 - 类型`A`- 选择全部
 - 复制
 - 粘贴

 为了实现这项工作，我们需要跟踪：

 - 当前屏幕内容长度
 - 剪贴板大小
 - 是否选择文本

 递归树增长得非常快，因为每个按键都会分支成多个可能的操作。 即使进行修剪，状态的数量也会变得巨大。 

这种方法是正确的，因为它探索了每个有效的操作序列，因此不会错过最佳答案。 然而，由于指数增长，这在计算上是不可行的。 

### 关键见解

 重要的观察是，最佳策略总是如下所示：

 1. 输入一些数字`A`s
 2. 执行：

 -`Ctrl-A`-`Ctrl-C`3.多次粘贴

 当我们决定开始复制时，我们应该随后重复粘贴。 交错进行额外的打字操作永远不会比有效地使用剪贴板更好。 

这自然会导致动态规划。 

让`dp[i]`代表最大数量`'A'`可以使用完全使用获得的字符`i`按键。 

对于每一个`i`，我们有两种可能性：

 - 按`A`再一次：

-`dp[i] = dp[i - 1] + 1`- 使用复制粘贴序列：

 - 假设我们在某个较早的时间点停下来`j`- 在步骤`j`，我们已经有`dp[j]`人物
 - 我们花费两次操作：

 -`Ctrl-A`-`Ctrl-C`- 剩下的操作都是粘贴
 - 如果我们粘贴`k`次，屏幕变成`dp[j] * (k + 1)`这将指数蛮力转化为多项式时间 DP 解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^n) | O(4^n) | O(n) | 探索每一种可能的操作顺序 |
 | 最优动态规划| O(n²) | O(n) | 为每次按键次数构建最佳答案 |

 ## 算法演练

 1.创建一个DP数组，其中`dp[i]`存储最大数量`'A'`完全使用可实现的字符`i`按键。 
2. 初始化基本案例。 对于较小的值`i`，最好的策略就是简单地按`A`反复。 所以：

-`dp[1] = 1`-`dp[2] = 2`-`dp[3] = 3`3. 对于每一次按键次数`1`到`n`，首先假设我们只是输入另一个`A`。 

这给出：```
dp[i] = dp[i - 1] + 1
```4. 接下来，考虑每个可能的早期断点`j`我们停止打字并开始复制粘贴序列。 

在位置`j`:

 - 我们已经有了`dp[j]`人物
 - 我们花费：

 - 一次操作`Ctrl-A`- 一次操作`Ctrl-C`- 剩下的操作都是粘贴
 5、粘贴操作次数为：```
i - j - 2
```6. 每一种浆糊都会添加另一种浆糊`dp[j]`人物。 由于原始屏幕已经包含`dp[j]`，最终总数变为：```
dp[j] * (i - j - 1)
```7.更新最大值：```
dp[i] = max(dp[i], dp[j] * (i - j - 1))
```8. 继续，直到所有值达到`n`被计算。 
9. 返回`dp[n]`。 

### 为什么它有效

 DP 之所以有效，是因为每个最优解都可以分解为更小的最优解。 在第一次复制操作之前，我们必须已经为该按键次数构建了最佳的屏幕。 复制后，每个剩余的操作都应该是粘贴，因为粘贴比键入单个字符更有效地增加现有工作。 通过评估每个可能的断点`j`，算法保证考虑全局最优策略。 

## Python 解决方案```python
class Solution:
    def maxA(self, n: int) -> int:
        dp = [0] * (n + 1)

        for i in range(1, n + 1):
            # Option 1: press 'A'
            dp[i] = dp[i - 1] + 1

            # Option 2: use copy-paste sequence
            for j in range(1, i - 2):
                current = dp[j] * (i - j - 1)
                dp[i] = max(dp[i], current)

        return dp[n]
```该实现直接遵循先前开发的递归关系。 

DP 数组存储每一次按键的最佳可能答案`0`到`n`。 

对于每个位置`i`，该算法首先假设我们只需按`A`，这给出了`dp[i - 1] + 1`。 

然后内循环考虑每个较早的断点`j`。 到那时，我们已经有了`dp[j]`屏幕上的字符。 我们花了两次操作进行选择和复制，剩下的操作就变成了粘贴操作。 

公式：```python
dp[j] * (i - j - 1)
```表示重复粘贴后的字符总数。 

所有可能性的最大值变为`dp[i]`。 

因为`n`至多是`50`，二次复杂度非常有效。 

## 解决方案```go
func maxA(n int) int {
	dp := make([]int, n+1)

	for i := 1; i <= n; i++ {
		// Option 1: press 'A'
		dp[i] = dp[i-1] + 1

		// Option 2: copy-paste sequence
		for j := 1; j <= i-3; j++ {
			current := dp[j] * (i - j - 1)

			if current > dp[i] {
				dp[i] = current
			}
		}
	}

	return dp[n]
}
```Go 实现几乎完全反映了 Python 逻辑。 

使用切片而不是 Python 列表。 由于 Go 没有提供内置的`max`对于整数函数，我们使用简单的条件比较来更新 DP 值。 

整数溢出不是问题，因为最大答案`n <= 50`很容易符合 Go 的标准整数范围。

 ## 边缘情况

 一个重要的边缘情况是非常小的值`n`， 尤其`n <= 3`。 在这些情况下，任何尝试使用`Ctrl-A`和`Ctrl-C`浪费了太多的操作。 幼稚的实现可能会错误地过早地强制执行复制粘贴策略。 DP 公式自然可以处理这个问题，因为只需键入`A`始终是候选过渡之一。 

当最佳断点不是紧接在最终操作之前时，会出现另一个关键的边缘情况。 例如，在`n = 9`，最好的策略是越晚不复制。 总是在临近结束时进行复制的贪婪方法可能会严重失败。 DP 解决方案通过评估每个可能的断点来避免这个问题`j`。 

第三种边缘情况涉及确保复制后保留足够的操作。 表演`Ctrl-A`和`Ctrl-C`没有至少一种粘贴是没有用的。 不正确的循环边界可能会意外地允许无效状态。 该实现仅通过考虑来防止这种情况发生`j`至少保留三种操作的值：一种用于选择，一种用于复制，以及至少一种用于粘贴。
