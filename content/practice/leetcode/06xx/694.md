[LeetCode 第 694 题](https://leetcode.com/problems/number-of-distinct-islands/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、深度优先搜索、广度优先搜索、并查找、排序、矩阵、哈希函数

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二元矩阵，称为`grid`，其中每个单元格包含`0`或者`1`。 值为`1`代表土地，价值为`0`代表水。 岛屿是通过在四个基本方向上连接相邻的陆地单元而形成的：上、下、左、右。 对角线连接不算数。 

我们的目标不仅仅是计算存在多少个岛屿。 相反，我们必须确定网格中出现了多少_不同的岛屿形状_。 如果两个岛可以移动或平移以与另一个岛完全重叠，则认为两个岛是相同的。 不允许旋转和反射。 

这种区别极其重要。 考虑两个 L 形岛屿。 如果一个相对于另一个旋转，则它们被视为不同，因为只允许平移。 但是，如果两个岛相对于其起点具有完全相同的单元排列，则即使它们出现在网格中的不同位置，它们也会被视为相同的形状。 

输入约束相对较小：

 -`1 <= m, n <= 50`- 网格仅包含`0`和`1`由于网格最多可以包含`2500`细胞，完全遍历矩阵是完全可行的。 这强烈表明深度优先搜索（DFS）或广度优先搜索（BFS）等图遍历算法是合适的。 

立即识别一些边缘情况非常重要。 没有土地的网格应该返回`0`。 每个岛屿都有独特形状的网格应该单独计数。 相同但位于不同位置的多个岛屿只能对最终答案贡献一次。 另一个微妙的情况是两个岛包含相同数量的细胞但具有不同的结构。 在这种情况下，它们仍然必须被视为不同的。 

## 方法

 暴力方法首先会识别网格中的每个岛屿并存储其所有单元的坐标。 然后，对于每个新发现的岛屿，我们可以将其与之前发现的每个岛屿进行比较，以确定它们的形状在翻译后是否匹配。 

为了比较两个岛屿，我们将通过减去参考单元（通常是第一个发现的陆地单元）的位置来标准化它们的坐标。 如果标准化坐标集完全匹配，则这些岛是相同的。 

这种方法是正确的，因为标准化消除了位置的影响，同时保留了岛屿的结构。 然而，随着岛屿数量的增加，反复比较岛屿就会变得低效。 最坏的情况下，可能存在很多个孤岛，每次比较可能涉及很多个小区。 

更高效解决方案的关键在于，每个岛屿都可以在遍历过程中直接转换为规范表示。 我们不是逐对比较岛屿，而是计算每个岛屿的唯一签名并将该签名插入到哈希集中。 由于集合会自动消除重复项，因此唯一签名的数量等于不同岛屿的数量。 

最常见的规范表示是相对坐标列表。 在遍历岛屿时，我们记录每个单元相对于岛屿起始单元的位置。 具有相同形状的两个岛屿将产生相同的相对坐标列表，无论它们出现在网格中的哪个位置。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k² * s) | O(k * s) | 将每个岛屿与之前发现的岛屿进行比较 |
 | 最佳| O(m * n) | O(m * n) | 使用 DFS/BFS 并将标准化岛形状存储在哈希集中 |

 这里：

-`k`是岛屿的数量
 -`s`是平均岛屿大小
 -`m * n`是网格中的单元总数

 ## 算法演练

 1. 初始化一个名为`distinct_shapes`。 

该集合将存储每个独特岛屿形状的规范表示。 由于集合会自动删除重复项，因此相同的岛屿只会出现一次。 
2. 创建一个`visited`就地构建或修改网格。 

我们需要确保每个陆地单元只被处理一次。 如果不跟踪访问过的单元，DFS 可能会重复访问相同的位置，并可能进入无限递归。 
3. 遍历网格中的每个单元格。 

对于每个位置`(row, col)`:

 - 如果细胞是水（`0`），跳过它。 
- 如果该单元已被访问过，则跳过它。 
- 否则，我们已经发现了一个新岛。 
4. 从当前陆地单元启动 DFS。 

将起始位置记录为`(base_row, base_col)`。 这成为用于标准化的参考点。 
5. 在DFS过程中，记录相对坐标。 

对于每个访问过的陆地单元`(r, c)`，计算：```
(r - base_row, c - base_col)
```这些相对偏移描述了岛屿的形状，与其绝对位置无关。 
6. 探索所有四个方向。 

从每个单元格，递归访问：

 - 向上
 - 向下
 - 左
 - 右

 仅当邻居位于网格内、包含土地且尚未被访问时才继续遍历。 
7. 存储完成的形状。 

DFS完成后，将收集到的相对坐标转换为不可变的结构，例如元组。 将此元组插入`distinct_shapes`。 
8. 继续扫描网格。 

对每个未访问的陆地单元重复该过程，直到处理整个矩阵。 
9. 返回集合的大小。 

不同规范表示的数量等于不同岛屿形状的数量。 

### 为什么它有效

 该算法之所以有效，是因为平移仅影响绝对坐标，而不影响相对坐标。 通过存储相对于岛的起始位置的每个单元格，我们消除了位置差异，同时保留了结构差异。 因此，当且仅当两个岛在平移时具有完全相同的形状时，它们才会生成相同的签名。 

## Python 解决方案```python
from typing import List, Tuple, Set

class Solution:
    def numDistinctIslands(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        visited = set()
        distinct_shapes: Set[Tuple[Tuple[int, int], ...]] = set()

        def dfs(r: int, c: int,
                base_r: int,
                base_c: int,
                shape: List[Tuple[int, int]]) -> None:

            visited.add((r, c))

            shape.append((r - base_r, c - base_c))

            directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

            for dr, dc in directions:
                nr = r + dr
                nc = c + dc

                if (
                    0 <= nr < rows and
                    0 <= nc < cols and
                    grid[nr][nc] == 1 and
                    (nr, nc) not in visited
                ):
                    dfs(nr, nc, base_r, base_c, shape)

        for row in range(rows):
            for col in range(cols):

                if grid[row][col] == 1 and (row, col) not in visited:

                    shape = []

                    dfs(row, col, row, col, shape)

                    distinct_shapes.add(tuple(shape))

        return len(distinct_shapes)
```实现首先确定网格尺寸并初始化两个重要结构：`visited`集和一个`distinct_shapes`放。 

这`visited`set 确保每个陆地单元仅被处理一次。 这`distinct_shapes`设置存储标准化岛屿表示。 每个表示都存储为元组，因为元组是不可变的且可散列的，这使得它们成为有效的集合元素。 

这`dfs`辅助函数执行岛屿遍历。 它接收当前单元格、岛屿的基础坐标以及当前正在构建的形状列表。 

每当 DFS 访问一个新的陆地单元时，它都会计算相对坐标：```python
(current_row - base_row, current_col - base_col)
```此归一化步骤是算法的核心，因为它消除了岛屿之间的位置差异。 

然后，DFS 探索四个相邻方向。 边界检查确保我们留在网格内，而访问检查可以防止重复遍历。 

在主遍历循环中，每个未访问的陆地单元都会启动一个新的 DFS。 遍历完成后，生成的形状将转换为元组并插入到不同形状的集合中。 

最后，算法返回存储在集合中的唯一形状的数量。 

## 解决方案```go
package main

func numDistinctIslands(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	visited := make(map[[2]int]bool)
	distinctShapes := make(map[string]bool)

	var dfs func(int, int, int, int, *[][2]int)

	dfs = func(r, c, baseR, baseC int, shape *[][2]int) {
		visited[[2]int{r, c}] = true

		*shape = append(*shape, [2]int{r - baseR, c - baseC})

		directions := [][2]int{
			{1, 0},
			{-1, 0},
			{0, 1},
			{0, -1},
		}

		for _, dir := range directions {
			nr := r + dir[0]
			nc := c + dir[1]

			if nr >= 0 &&
				nr < rows &&
				nc >= 0 &&
				nc < cols &&
				grid[nr][nc] == 1 &&
				!visited[[2]int{nr, nc}] {

				dfs(nr, nc, baseR, baseC, shape)
			}
		}
	}

	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {

			if grid[r][c] == 1 && !visited[[2]int{r, c}] {

				shape := make([][2]int, 0)

				dfs(r, c, r, c, &shape)

				shapeKey := ""

				for _, point := range shape {
					shapeKey += string(rune(point[0]+100)) + "," +
						string(rune(point[1]+100)) + ";"
				}

				distinctShapes[shapeKey] = true
			}
		}
	}

	return len(distinctShapes)
}
```Go 实现遵循与 Python 版本相同的算法结构，但一些特定于语言的细节有所不同。 

Go 不直接支持元组，因此坐标对使用固定大小的数组表示，例如`[2]int`。 

由于切片是可变的，但按值传递，因此 DFS 函数接收一个指向`shape`切片，以便修改在递归调用中持续存在。 

Go 地图需要类似的键。 由于切片不具有可比性，因此岛形状必须先序列化为字符串，然后才能插入到切片中`distinctShapes`地图。 该字符串充当岛屿的规范表示。 

这里整数溢出不是问题，因为网格尺寸非常小，最大坐标偏移量远低于 Go 的整数限制。

class Solution:
    def numDistinctIslands(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        visited = set()
        distinct_shapes = set()

        def dfs(r, c, base_r, base_c, shape):
            visited.add((r, c))
            shape.append((r - base_r, c - base_c))

            for dr, dc in [(1,0), (-1,0), (0,1), (0,-1)]:
                nr, nc = r + dr, c + dc

                    shape = []
                    dfs(r, c, r, c, shape)
                    distinct_shapes.add(tuple(shape))

        return len(distinct_shapes)

 ## 边缘情况

 一个重要的边缘情况是完全不包含土地的网格。 幼稚的实现可能会错误地初始化答案`1`或者尝试对水细胞进行 DFS。 当前的实现安全地跳过所有水单元并将不同的形状设置为空，从而得到正确的答案`0`。 

另一个微妙的边缘情况涉及具有相同数量的单元但不同结构的岛屿。 例如，L形岛和直线岛都可以包含三个单元。 仅计算岛屿大小会产生错误的结果。 该实现通过存储每个岛屿的精确相对坐标结构来避免此错误。 

当岛屿相互镜像或旋转时，就会出现第三种重要的边缘情况。 由于该问题仅允许翻译，因此应将它们视为不同的。 由于该算法保留了精确的相对坐标，而没有通过旋转或反射进行归一化，因此镜像岛自然会产生不同的签名并单独计数。 

最后的边缘情况涉及非常大的相连岛屿。 如果访问跟踪实施不正确，递归 DFS 可能会重复访问单元格。 该解决方案通过在进入 DFS 后立即将单元标记为已访问来防止这种情况发生，从而保证每个陆地单元仅被处理一次。
