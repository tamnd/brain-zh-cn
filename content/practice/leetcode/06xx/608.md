[LeetCode 第 608 题](https://leetcode.com/problems/tree-node/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为`Tree`，其中每一行代表树结构中的一个节点。 每个节点都有一个唯一的标识符`id`和一个`p_id`存储其父节点标识符的列。 

任务是将每个节点分为三个类别之一：

 -`"Root"`如果该节点没有父节点，则意味着`p_id IS NULL`-`"Leaf"`如果该节点没有子节点
 -`"Inner"`如果该节点同时具有父节点和至少一个子节点

 简而言之，我们需要检查每个节点并确定其在树中的结构角色。 

输入代表一棵有效的树。 这一保证很重要，因为它意味着：

 - 只有一个根节点
 - 没有循环
 - 每个非根节点只有一个父节点
 - 关系形成一棵相连的树

 预期输出是包含两列的结果表：

 -`id`, 节点标识符
 -`type`，其中之一`"Root"`,`"Leaf"`， 或者`"Inner"`返回行的顺序并不重要。 

关键的挑战是确定节点是否有子节点。 这`p_id`列告诉我们一个节点的父节点是谁，但是要知道一个节点是叶子节点还是内部节点，我们必须确定它是否是`id`显示为另一个节点的`p_id`。 

有几个边缘情况需要考虑。 一棵只有一个节点的树从技术上讲既是根又是叶，但问题定义优先`"Root"`，所以正确的分类是`"Root"`。 另一个重要的情况是有子节点但没有父节点的节点，必须始终对其进行标记`"Root"`。 最后，有父母但没有孩子的节点`"Leaf"`节点。 

由于这是一个数据库问题，因此目标是用 SQL 有效地表达这种分类。 

## 方法

 ### 蛮力方法

 解决此问题的一种直接方法是独立检查每个节点并使用重复搜索来确定其类型。 

对于中的每一行`Tree`表，我们可以：

 1. 检查是否`p_id IS NULL`。 If yes, classify it as`"Root"`。 
2. 否则，扫描表以查看是否有行`p_id = current id`。 
3. 如果存在子项，则将其分类为`"Inner"`。 
4. 否则，分类为`"Leaf"`。 

这种方法是正确的，因为每个节点都是根据确切的问题定义进行评估的。 然而，它的效率很低，因为每个节点可能需要扫描整个表来确定它是否有子节点。 

如果有`n`节点，检查每个节点的子节点需要`O(n)`工作，产生总复杂度`O(n²)`。 

### 最佳方法

 关键的观察是我们不需要重复搜索子关系。 相反，我们可以使用单个查询来识别作为父节点出现的所有节点 ID。 

一个节点是父节点，如果`id`存在于非空集合中`p_id`价值观。 

使用 SQL，这自然会转化为`CASE`声明：

 - 如果`p_id IS NULL`，分类为`"Root"`- 否则如果`id`存在于父ID中，分类为`"Inner"`- 否则，分类为`"Leaf"`重要的优化是数据库可以使用子查询或连接有效地评估成员资格，从而避免重复的手动扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描表中的每个节点 |
 | 最佳| O(n) | O(n) | 通过子查询使用父 ID 查找 |

 ## 算法演练

 1. 首先遍历节点中的每个节点`Tree`桌子。 
2. 对于每个节点，首先检查是否`p_id IS NULL`。 此条件标识根节点，因为根没有父节点。 
3. 如果该节点不是根节点，则判断其是否有子节点。 我们通过检查当前节点是否是`id`出现在所有非空集合中`p_id`价值观。 如果它出现在那里，则意味着至少有一个节点将其引用为父节点。 
4. 如果该节点有子节点，则将其分类为`"Inner"`因为它既不是根，也不是叶。 
5. 否则，分类为`"Leaf"`因为没有节点依赖它。 
6.返回带有列的结果表`id`和`type`。 

### 为什么它有效

 正确性直接来自节点类型的定义。 每个节点恰好属于三个互斥类别之一：

 -`p_id IS NULL`唯一标识根。 
- 作为另一个节点的父节点出现的节点必须有子节点，使其成为内部节点，除非它是根节点。 
- 任何剩余的节点都没有子节点，使其成为叶子。 

由于每个节点都是根据这些精确的规则进行分类的，因此算法始终会产生正确的结果。 

## Python 解决方案

 尽管这是 LeetCode 上的 SQL 问题，但该平台有时会要求使用 Python 表示以保持一致性。 实际接受的解决方案是 SQL 查询。```python
class Solution:
    def treeNode(self):
        return """
        SELECT
            id,
            CASE
                WHEN p_id IS NULL THEN 'Root'
                WHEN id IN (
                    SELECT DISTINCT p_id
                    FROM Tree
                    WHERE p_id IS NOT NULL
                ) THEN 'Inner'
                ELSE 'Leaf'
            END AS type
        FROM Tree
        """
```该实现使用 SQL`CASE`用于对节点进行分类的表达式。 

第一个条件检查`p_id IS NULL`，立即识别根节点。 

第二个条件检查父ID中是否存在该节点ID。 子查询检索所有不同的非空`p_id`值，对应于至少有一个子节点的节点。 

如果两个条件都不匹配，则该节点没有子节点，因此被标记为`"Leaf"`。 

使用`DISTINCT`并不严格要求正确性，但它避免了冗余的重复父 ID。

 ## 边缘情况

 ### 单节点树

 仅具有一个节点的树是一种重要的极端情况。 从技术上讲，该节点没有父节点，也没有子节点，这可能会使分类不明确。 问题定义通过优先级来解决这个问题`"Root"`。 自实施检查以来`p_id IS NULL`首先，节点被正确标记`"Root"`。 

### 带子节点的根节点

 根节点也可以有子节点。 幼稚的实现可能会错误地将其分类为`"Inner"`因为它出现在父集中。 此实现通过首先检查 root 状态来避免该错误。 一次`p_id IS NULL`为真，该节点立即被分类为`"Root"`。 

### 没有子节点的节点

 叶节点通过排除间接识别。 不是根且不作为父 ID 出现的节点必定是叶子。 即使许多节点共享相同的父节点或树高度不平衡，此逻辑也能确保正确性。
