[LeetCode 第 636 题](https://leetcode.com/problems/exclusive-time-of-functions/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈

 ## 解决方案

 ## 问题理解

 此问题模拟函数如何在单线程 CPU 上执行。 由于 CPU 是单线程的，因此在任何给定时刻只有一个函数可以主动执行。 但是，函数可以调用其他函数，包括对其自身的递归调用。 每当一个函数调用另一个函数时，当前运行的函数就会暂停，新调用的函数立即开始执行。 

输入包括：

 - 一个整数`n`，表示来自的不同函数 ID 的总数`0`到`n - 1`- 日志字符串列表，其中每个日志记录：

 - 函数ID
 - 函数是否开始或结束
 - 事件的时间戳

 每个日志都遵循以下格式：```
"{function_id}:{start|end}:{timestamp}"
```一个关键细节是时间戳的工作原理：

 -`"start"`表示函数在该时间戳的开头开始执行
 -`"end"`表示函数在该时间戳结束时完成执行

 这意味着结束时间戳是包含在内的。 如果函数在某个时间启动`2`并于时间结束`5`，它执行：```
5 - 2 + 1 = 4
```目标是计算每个函数的独占执行时间。 独占时间是指函数主动运行所花费的时间，不包括子函数调用所花费的时间。 

限制相对较小：

 -`n <= 100`-`logs.length <= 500`这意味着即使优化程度较低的方法也可能通过，但问题旨在测试堆栈模拟和仔细的时间戳记。 

一些边缘情况尤其重要：

 - 递归调用，即同一函数在堆栈中多次出现
 - 功能启动后立即结束
 - 多层嵌套调用
 - 正确处理包含的结束时间戳
 - 子进程完成后恢复父进程的执行

 该问题保证：

 - 每个`"start"`有一个匹配的`"end"`- 日志有效并按时间顺序排列
 - 没有两个开始事件共享相同的时间戳
 - 没有两个结束事件共享相同的时间戳

 这些保证使我们能够安全地使用堆栈模拟执行。 

## 方法

 ### 蛮力方法

 强力解决方案将单独模拟每个时间单位。 

这个想法是按时间顺序处理日志并确定每个时间戳期间哪个功能处于活动状态。 对于每个执行时间单位，我们都会增加当前正在执行的函数的计数器。 

为此，我们可以：

 - 解析所有日志
 - 维护一系列活动函数
 - 按时间戳迭代时间戳
 - 将每个时间单位归因于当前位于堆栈顶部的函数

 这种方法之所以有效，是因为 CPU 在每个时间戳精确地执行一个函数。 通过直接模拟时间线，我们可以准确统计独占执行时间。 

然而，当时间戳非常大时，这种方法就会变得低效。 由于时间戳可以大到`10^9`，迭代每个单独的时间单位是不可行的。 

### 基于堆栈的最佳方法

 关键的观察是我们不需要单独模拟每个时间单位。 相反，我们只需要跟踪事件之间的转换。 

在两个连续的日志时间戳之间，当前运行的函数保持不变。 因此，我们可以分块计算时间间隔，而不是一步一步地计算。 

堆栈是理想的数据结构，因为函数调用自然遵循后进先出行为：

 - 当某个功能启动时，它会暂停当前功能并变为活动状态
 - 当一个函数结束时，继续执行前一个函数

 我们还维护一个`previous_time`变量来跟踪最后一个执行间隔的开始位置。 

处理日志时：

 - A`"start"`event 表示当前运行的函数获取到新时间戳的执行时间
 - 安`"end"`event 表示当前函数获取到结束时间戳（含）的执行时间

 这使我们能够在线性时间内处理日志。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(T)| O(n) | 单独模拟每个时间戳，其中 T 是最大时间戳范围 |
 | 最佳| O(logs.length) | O(logs.length) | O(n) | 使用堆栈并处理每个日志一次 |

 ## 算法演练

 1.初始化一个大小为answer的数组`n`充满零。 

该数组存储每个函数 ID 的独占执行时间。 
2. 创建一个空堆栈。 

堆栈表示正在执行的函数的当前调用堆栈。 顶部的功能是当前活动的功能。 
3. 初始化`previous_time`到`0`。 

该变量跟踪当前执行间隔的开始。 
4. 按顺序处理每条日志。 

每个日志分为：

 -`function_id`-`event_type`-`timestamp`5. 手柄`"start"`日志。 

如果一个新函数开始：

 - 当前位于栈顶的函数一直在执行`previous_time`最多`timestamp - 1`- 添加`timestamp - previous_time`到当前运行的函数
 - 将新函数压入堆栈
 - 更新`previous_time = timestamp`6. 手柄`"end"`日志。 

如果函数结束：

 - 当前函数已从执行`previous_time`通过`timestamp`- 添加`timestamp - previous_time + 1`到当前函数
 - 从堆栈中弹出函数
 - 设置`previous_time = timestamp + 1`这`+1`调整是必要的，因为结束时间戳是包含在内的。 
7. 继续，直到处理完所有日志。 
8. 返回结果数组。 

### 为什么它有效

 该算法保持了栈顶函数始终是当前正在执行的函数的不变性。 每次由于开始或结束事件而切换执行时，算法都会准确计算先前活动函数运行的时间。 

由于连续日志事件之间的每个间隔完全属于一个函数，并且每个间隔只计算一次，因此生成的执行时间是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def exclusiveTime(self, n: int, logs: List[str]) -> List[int]:
        result = [0] * n
        stack = []
        previous_time = 0

        for log in logs:
            function_id_str, event_type, timestamp_str = log.split(":")
            
            function_id = int(function_id_str)
            timestamp = int(timestamp_str)

            if event_type == "start":
                if stack:
                    result[stack[-1]] += timestamp - previous_time

                stack.append(function_id)
                previous_time = timestamp

            else:
                result[stack[-1]] += timestamp - previous_time + 1
                stack.pop()
                previous_time = timestamp + 1

        return result
```实现首先初始化结果数组和堆栈。 结果数组存储每个函数的独占执行时间，而堆栈则跟踪当前活动的函数调用。 

每个日志字符串都使用解析`split(":")`。 这为我们提供了函数 ID、事件类型和时间戳。 

当遇到一个`"start"`event，当前正在运行的函数，如果存在，则从以下位置接收执行时间`previous_time`直到新的时间戳。 然后新函数被压入堆栈，因为它成为活动函数。 

当遇到一个`"end"`事件时，堆栈顶部的函数通过包含的结束时间戳接收执行时间。 更新结果后，函数从堆栈中删除，并在以下位置恢复执行：`timestamp + 1`。 

这`previous_time`变量很重要，因为它可以防止重复计算执行间隔。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

func exclusiveTime(n int, logs []string) []int {
	result := make([]int, n)
	stack := []int{}
	previousTime := 0

	for _, log := range logs {
		parts := strings.Split(log, ":")

		functionID, _ := strconv.Atoi(parts[0])
		eventType := parts[1]
		timestamp, _ := strconv.Atoi(parts[2])

		if eventType == "start" {
			if len(stack) > 0 {
				result[stack[len(stack)-1]] += timestamp - previousTime
			}

			stack = append(stack, functionID)
			previousTime = timestamp

		} else {
			result[stack[len(stack)-1]] += timestamp - previousTime + 1

			stack = stack[:len(stack)-1]
			previousTime = timestamp + 1
		}
	}

	return result
}
```Go 的实现与 Python 解决方案非常相似。 切片用于结果数组和堆栈。 

Go 需要使用显式解析`strconv.Atoi`，并且日志使用分割`strings.Split`。 

堆栈操作是通过切片追加和重新切片来实现的：

 - 推：`append(stack, value)`- 流行音乐：`stack[:len(stack)-1]`Go 整数就足够了，因为时间戳很适合 LeetCode 上的标准整数范围。

 ## 边缘情况

 ### 递归函数调用

 递归调用是最重要的边缘情况之一，因为相同的函数 ID 可能会在调用堆栈中同时出现多次。 仅跟踪功能是否处于活动状态的简单实现在这里会失败。 

基于堆栈的方法自然地处理递归，因为每个函数调用实例都被单独推入堆栈。 即使函数 ID 相同，每次调用也有自己的执行间隔。 

### 包含结束时间戳

 错误的一个常见来源是忘记包含结束时间戳。 

例如：```
0:start:5
0:end:5
```该函数执行一个完整的时间单位，而不是零。 

该实现使用以下方式正确处理此问题：```
timestamp - previous_time + 1
```这`+1`确保结束时间戳本身被计算在内。 

### 父函数恢复

 子函数完成后，父函数会在子函数结束时间戳后立即恢复执行。 

这很容易导致重复计算，如果`previous_time`未正确更新。 

例如：```
0:start:0
1:start:2
1:end:5
0:end:6
```后功能`1`结束于时间`5`， 功能`0`恢复时间`6`。 

实现正确设置：```
previous_time = timestamp + 1
```这保证了恢复执行在正确的下一个时间戳开始。
