[LeetCode 第 689 题](https://leetcode.com/problems/maximum-sum-of-3-non-overlapping-subarrays/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们从输入数组中恰好选择三个不重叠的子数组`nums`，其中每个子数组都有长度`k`。 在所有有效选择中，我们必须最大化这三个子数组中包含的所有元素的总和。 

输出不是子数组本身，而是这三个子数组的起始索引。 由于间隔不得重叠，因此如果一个子数组从索引处开始`i`，那么下一个有效子数组必须至少从索引处开始`i + k`。 

字典顺序要求极其重要。 如果多个解产生相同的最大总和，我们必须返回从左到右比较时索引最小的一个。 例如，`[0,3,5]`按字典顺序小于`[1,3,5]`因为第一个不同的索引较小。 

输入约束足够大，以至于暴力枚举变得不切实际。 数组长度可以大到`2 * 10^4`，这意味着任何三次甚至二次重的解决方案都将陷入困境。 这强烈表明我们需要一种线性或近线性算法。 

有几个细节很重要：

 - 每个子数组都有精确的长度`k`- 我们必须恰好选择三个子数组
 - 所选子数组不能重叠
 - 可能存在多个最佳答案，我们必须返回字典顺序最小的一个
 - 约束保证至少可以存在三个子数组，因为`k <= floor(nums.length / 3)`幼稚的实现很容易在决胜场景中失败。 另一个常见的错误是在独立计算最佳组合时意外地允许重叠间隔。 

## 方法

 ### 蛮力方法

 最直接的解决方案是枚举三个子数组的每种可能的组合。 

首先，我们计算每个窗口大小的总和`k`。 如果有`m = n - k + 1`可能的窗口，我们可以尝试所有三元组`(i, j, l)`这样：

 -`i + k <= j`-`j + k <= l`对于每个有效的三元组，我们计算：```
windowSum[i] + windowSum[j] + windowSum[l]
```我们跟踪最大总数，并在找到更好的组合时更新答案。 

这种方法是正确的，因为它详尽地检查了每一种有效的可能性。 然而，它太慢了。 大致可以有`O(n)`每个子数组可能的起始位置，导致`O(n^3)`搜索空间。 

和`n = 2 * 10^4`，立方复杂度是不可行的。 

### 最佳解决方案的关键见解

 关键的观察是，一旦我们修复了中间子数组，左右选择就成为独立的优化问题。 

假设中间子数组从索引处开始`mid`。 

然后：

 - 左子数组必须先于`mid`- 右子数组必须开始于`mid + k - 1`对于每个可能的中间位置，我们希望：

 - 前面最好的左边窗口
 - 之后最好的右窗

 如果我们有效地预先计算这些，那么可以在恒定时间内评估每个中间位置。 

这将问题从尝试所有三元组转变为：

 - 预先计算所有窗口总和
 - 预先计算每个位置的最佳左索引
 - 预先计算每个位置的最佳正确索引
 - 迭代可能的中间窗口

 这将复杂性降低到线性时间。

 ## 算法演练

 ### 步骤 1：计算所有窗口总和

 首先，计算每个长度子数组的总和`k`。 

我们使用滑动窗口，因为独立地重新计算每个总和是低效的。 

如果：```
nums = [1,2,1,2,6,7,5,1]
k = 2
```那么窗口总和就变成：```
[3,3,3,8,13,12,6]
```每个条目代表一个大小的总和 -`k`从该索引开始的子数组。 

### 第 2 步：构建最佳左数组

 我们创建一个名为的数组`bestLeft`。 

对于每个职位`i`,`bestLeft[i]`存储范围内最大和窗口的索引`[0, i]`。 

如果多个窗口具有相同的总和，我们将保留较早的索引以保留字典顺序。 

例子：```
windowSums = [3,3,3,8,13,12,6]
bestLeft   = [0,0,0,3,4,4,4]
```在位置`5`，迄今为止看到的最佳窗口从索引处开始`4`因为总和`13`是最大的。 

### 第 3 步：构建最佳正确数组

 现在创建`bestRight`。 

对于每个职位`i`,`bestRight[i]`存储范围内最大和窗口的索引`[i, end]`。 

该数组是从右到左构建的。 

打破平局在这里很微妙。 我们使用`>=`而不是`>`因此，在平局期间优先选择较早的指数。 

例子：```
bestRight = [4,4,4,4,4,5,6]
```### 步骤 4：枚举中间窗口

 现在迭代每个有效的中间窗口。 

如果中间开始于`mid`:

 - 左边的候选人是`bestLeft[mid - k]`- 正确的候选人是`bestRight[mid + k]`这保证了不重叠。 

总计变为：```
windowSums[left] + windowSums[mid] + windowSums[right]
```跟踪最大总数并在必要时更新答案。 

### 第 5 步：返回最佳三元组

 因为我们的打破平局规则`bestLeft`和`bestRight`，遇到的第一个最优解自动按字典顺序最小。 

### 为什么它有效

 该算法之所以有效，是因为每个有效解都可以由其中间区间唯一地表示。 一旦中间区间固定，最优左右区间就成为独立的子问题。`bestLeft`保证我们总是选择最大和的有效左区间。`bestRight`保证正确的间隔相同。 因此，每个中间位置都与最佳可能的周围间隔配对。 

由于我们评估所有有效的中间区间，因此必须找到全局最优值。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSumOfThreeSubarrays(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)

        # Compute all window sums
        window_sums = []
        current_sum = sum(nums[:k])
        window_sums.append(current_sum)

        for i in range(k, n):
            current_sum += nums[i]
            current_sum -= nums[i - k]
            window_sums.append(current_sum)

        m = len(window_sums)

        # best_left[i] = index of best window in [0..i]
        best_left = [0] * m
        best_index = 0

        for i in range(m):
            if window_sums[i] > window_sums[best_index]:
                best_index = i
            best_left[i] = best_index

        # best_right[i] = index of best window in [i..m-1]
        best_right = [0] * m
        best_index = m - 1

        for i in range(m - 1, -1, -1):
            if window_sums[i] >= window_sums[best_index]:
                best_index = i
            best_right[i] = best_index

        max_total = 0
        answer = []

        # Enumerate middle window
        for mid in range(k, m - k):
            left = best_left[mid - k]
            right = best_right[mid + k]

            total = (
                window_sums[left]
                + window_sums[mid]
                + window_sums[right]
            )

            if total > max_total:
                max_total = total
                answer = [left, mid, right]

        return answer
```该实现首先使用滑动窗口计算所有固定长度窗口的总和。 这将原始问题转换为从`window_sums`大批。 

下一个，`best_left`是通过从左到右扫描构建的。 在每个位置，它存储迄今为止遇到的最大窗口和的索引。 由于我们仅更新严格更大的总和，因此在平局期间保留较早的指数。 

这`best_right`数组的构建方式类似，但从右到左。 这里我们使用`>=`这样，在向后扫描时，较早的指数就能赢得抢七局。 

最后，我们迭代每个可能的中间区间。 对于每个中间索引，我们立即使用预先计算的数组检索最佳不重叠的左右间隔。 这避免了嵌套搜索并将复杂性降低到线性时间。 

## 解决方案```go
func maxSumOfThreeSubarrays(nums []int, k int) []int {
	n := len(nums)

	// Compute window sums
	windowSums := []int{}
	currentSum := 0

	for i := 0; i < k; i++ {
		currentSum += nums[i]
	}

	windowSums = append(windowSums, currentSum)

	for i := k; i < n; i++ {
		currentSum += nums[i]
		currentSum -= nums[i-k]
		windowSums = append(windowSums, currentSum)
	}

	m := len(windowSums)

	// bestLeft[i] = best window index in [0..i]
	bestLeft := make([]int, m)
	bestIndex := 0

	for i := 0; i < m; i++ {
		if windowSums[i] > windowSums[bestIndex] {
			bestIndex = i
		}
		bestLeft[i] = bestIndex
	}

	// bestRight[i] = best window index in [i..m-1]
	bestRight := make([]int, m)
	bestIndex = m - 1

	for i := m - 1; i >= 0; i-- {
		if windowSums[i] >= windowSums[bestIndex] {
			bestIndex = i
		}
		bestRight[i] = bestIndex
	}

	maxTotal := 0
	answer := []int{}

	// Enumerate middle window
	for mid := k; mid < m-k; mid++ {
		left := bestLeft[mid-k]
		right := bestRight[mid+k]

		total := windowSums[left] +
			windowSums[mid] +
			windowSums[right]

		if total > maxTotal {
			maxTotal = total
			answer = []int{left, mid, right}
		}
	}

	return answer
}
```Go 的实现与 Python 版本非常相似。 使用切片而不是 Python 列表，并且需要显式初始化`make`。 

整数溢出不是一个问题，因为约束使总和在 Go 的范围内保持舒适`int`范围。 

一个微妙的细节是保留字典顺序。 使用相同的平局打破逻辑：

 -`>`为了`bestLeft`-`>=`为了`bestRight`这保证了字典顺序最小的最佳答案。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个数组都会被处理固定次数 |
 | 空间| O(n) | 附加数组存储窗口总和和最佳索引 |

 该算法执行多次线性遍历：

 - 一次计算窗口总和
 - 一张通行证`bestLeft`- 一张通行证`bestRight`- 一次评估中间间隔

 由于每次传递中的所有操作都是恒定时间，因此整体运行时间是线性的。 

额外的空间来自存储：

 -`window_sums`-`best_left`-`best_right`每个的大小与`n`。

 ## 边缘情况

 ### 所有窗口总和都相等

 当每个窗口具有相同的总和时，许多解决方案都是同样最优的。 粗心的实现可能会根据遍历顺序返回任意索引。 

此实现通过仔细选择打破平局条件来正确处理这种情况：

 -`bestLeft`仅更新严格更大的金额
 -`bestRight`向后扫描时更新大于或等于总和

 这些规则共同确保返回字典顺序最小的解决方案。 

### 最小可能的窗口尺寸

 当`k = 1`，每个元素都成为它自己的子数组。 该问题简化为选择具有最大总价值的三个单独元素。 

某些实现意外地假设窗口包含多个元素，并且可能会引入相差一错误。 该解决方案自然有效，因为滑动窗口逻辑仍然正确适用于大小`1`。 

### 最大重叠风险

 一个常见的错误是在组合独立优化的间隔时意外选择重叠窗口。 

例如，如果中间间隔开始于`mid`，那么：

 - 左必须来自索引直到`mid - k`- 权利必须来自于从以下位置开始的索引`mid + k`此实现明确强制执行这些边界，保证不会发生重叠。
