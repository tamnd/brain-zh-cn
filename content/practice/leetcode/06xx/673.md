 **难度：** 🟡 中等

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定整数数组中存在多少个最长严格递增子序列。 

子序列是通过删除零个或多个元素而不改变剩余元素的相对顺序而形成的。 例如，从`[1,3,5,4,7]`，子序列`[1,3,4,7]`有效，因为顺序被保留。 

递增子序列意味着每个下一个元素必须严格大于前一个元素。 序列中不允许有相同的值。 

目标不仅是找到最长递增子序列（通常称为 LIS）的长度，而且还要计算有多少个不同的子序列达到了最大长度。 

例如：

 - 在`[1,3,5,4,7]`，LIS长度为`4`- 有两个这样的子序列：

 -`[1,3,5,7]`-`[1,3,4,7]`- 因此，答案是`2`输入约束很重要：

 -`1 <= nums.length <= 2000`- 值的范围可以是`-10^6`到`10^6`数组大小为`2000`是比较适中的。 这意味着`O(n^2)`动态规划解决方案是可以接受的，因为`2000^2 = 4,000,000`，这是可以管理的。 然而，指数解是完全不可行的。 

一些边缘情况尤其重要：

 - 所有元素都相等的数组，例如`[2,2,2,2]`- 每个元素形成一个长度为 LIS 的 LIS`1`- 答案变成元素的数量
 - 严格增加数组

 - 仅存在一个 LIS
 - 严格递减数组

 - 每个元素单独形成一个长度的LIS`1`- 重复值与增加值混合

 - 必须注意不要将相等的值错误地算作递增

 该问题保证最终答案适合 32 位整数，因此我们不需要特殊的大整数处理。 

## 方法

 ### 蛮力方法

 暴力解决方案生成数组的每个可能的子序列并检查它是否严格递增。 

对于每个子序列：

 1.验证子序列是否严格递增
 2. 跟踪目前为止看到的最大子序列长度
 3. 计算有多少子序列达到该长度

 这种方法是正确的，因为它显式地评估每个有效的子序列。 然而，长度的数组`n`有`2^n`可能的子序列，使得这种方法的成本呈指数级增长。 

为了`n = 2000`，这样的解决方案不可能在时间限制内运行。 

### 最佳解决方案的关键见解

 重要的观察是每个以索引结尾的递增子序列`i`必须来自一些较早的索引`j`在哪里：```
j < i and nums[j] < nums[i]
```这自然意味着动态规划。 

对于每个位置`i`，我们想知道：

 -`length[i]`- 结束于的最长递增子序列的长度`i`-`count[i]`- 结束于的LIS序列的数量`i`迭代以前的索引时：

 - 如果从`j`创建一个比之前已知的更长的子序列`i`，我们更新长度和计数
 - 如果从`j`创建另一个具有相同最佳长度的子序列，我们添加它的计数

 这使我们能够计算答案`O(n^2)`时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 生成每个子序列并验证它 |
 | 最优动态规划| O(n^2) | O(n^2) | O(n) | 跟踪 LIS 长度和以每个索引结尾的计数 |

 ## 算法演练

 ### 第 1 步：初始化 DP 数组

 我们创建两个数组：

 -`lengths[i]`- 以索引结尾的 LIS 长度`i`-`counts[i]`- 以索引结尾的 LIS 序列数`i`最初：

 - 每个元素单独形成一个长度子序列`1`- 恰好有一个这样的子序列

 所以：```
lengths = [1] * n
counts = [1] * n
```### 第 2 步：迭代每个位置

 对于每个索引`i`，我们检查所有早期的指数`j`。```
for i in range(n):
    for j in range(i):
```我们只关心以下位置：```
nums[j] < nums[i]
```因为子序列必须保持严格递增。 

### 第 3 步：检查我们是否找到了更好的 LIS

 如果扩展结束于`j`给出更长的子序列`i`:```
lengths[j] + 1 > lengths[i]
```那么：

 - 我们发现了一个更好的 LIS 结局`i`- 替换当前最佳长度
 - 复制来自的路数`j`

```
lengths[i] = lengths[j] + 1
counts[i] = counts[j]
```### 步骤 4：处理等长替代方案

 如果延伸自`j`给出另一个具有相同最佳长度的子序列：```
lengths[j] + 1 == lengths[i]
```然后我们添加计数：```
counts[i] += counts[j]
```这是有效的，因为我们发现了另一种独特的方式来构建以`i`。 

### 步骤 5：找到全局 LIS 长度

 处理完所有索引后：```
max_length = max(lengths)
```### 步骤 6：所有最大长度子序列的总和计数

 我们将 LIS 长度等于全局最大值的所有计数相加。```
answer = sum(counts[i] for i in range(n) if lengths[i] == max_length)
```### 为什么它有效

 该算法在处理索引后保持了不变式`i`,`lengths[i]`存储结束于的最长递增子序列`i`， 和`counts[i]`准确存储存在多少个这样的最优子序列。 

每个递增子序列结束于`i`必须来自某个较早的有效位置`j`在哪里`nums[j] < nums[i]`。 通过考虑所有这些`j`，我们保证每个可能的 LIS 都以`i`被占。 更新规则确保我们仅保留最佳长度，同时正确累积同样最佳结构的计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def findNumberOfLIS(self, nums: List[int]) -> int:
        n = len(nums)

        lengths = [1] * n
        counts = [1] * n

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    if lengths[j] + 1 > lengths[i]:
                        lengths[i] = lengths[j] + 1
                        counts[i] = counts[j]
                    elif lengths[j] + 1 == lengths[i]:
                        counts[i] += counts[j]

        longest_length = max(lengths)

        total = 0

        for i in range(n):
            if lengths[i] == longest_length:
                total += counts[i]

        return total
```该实现严格遵循前面描述的动态编程策略。 

这`lengths`数组跟踪在每个位置结束的最长递增子序列。 这`counts`array 跟踪有多少个最佳子序列结束。 

对于每对`(j, i)`在哪里`j < i`，我们尝试扩展结束于的子序列`j`使用`nums[i]`。 

当我们发现一个严格更好的子序列长度时，我们会覆盖长度和计数。 当我们发现另一个具有相同最佳长度的子序列时，我们会累积计数。 

最后，计算全局 LIS 长度，并将与该最大长度相关的所有计数相加。 

## 解决方案```go
func findNumberOfLIS(nums []int) int {
	n := len(nums)

	lengths := make([]int, n)
	counts := make([]int, n)

	for i := 0; i < n; i++ {
		lengths[i] = 1
		counts[i] = 1
	}

	for i := 0; i < n; i++ {
		for j := 0; j < i; j++ {
			if nums[j] < nums[i] {
				if lengths[j]+1 > lengths[i] {
					lengths[i] = lengths[j] + 1
					counts[i] = counts[j]
				} else if lengths[j]+1 == lengths[i] {
					counts[i] += counts[j]
				}
			}
		}
	}

	longestLength := 0

	for _, length := range lengths {
		if length > longestLength {
			longestLength = length
		}
	}

	total := 0

	for i := 0; i < n; i++ {
		if lengths[i] == longestLength {
			total += counts[i]
		}
	}

	return total
}
```Go 实现在逻辑和结构上与 Python 版本几乎相同。 

使用切片而不是 Python 列表。 由于 Go 数组是用零值初始化的，因此我们显式地设置了每个位置`lengths`和`counts`到`1`。 

Go 使用标准整数运算，并且问题保证答案适合 32 位整数，因此这里不存在溢出问题。

from typing import List

class Solution:
    def findNumberOfLIS(self, nums: List[int]) -> int:
        n = len(nums)

        lengths = [1] * n
        counts = [1] * n

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:

                        lengths[i] = lengths[j] + 1
                        counts[i] = counts[j]
                    elif lengths[j] + 1 == lengths[i]:
                        counts[i] += counts[j]

        longest_length = max(lengths)

        return sum(

            for i in range(n)

 ## 边缘情况

 当所有元素都相同时，就会出现一种重要的边缘情况，例如`[2,2,2,2]`。 由于该问题需要严格增加子序列，因此相等的值不能相互扩展。 有缺陷的实现可能会错误地将相等的值视为有效扩展。 该解决方案显式检查`nums[j] < nums[i]`，防止这种错误。 每个元素独立地贡献一个长度的子序列`1`。 

另一个关键的边缘情况是严格递减的数组，例如`[5,4,3,2,1]`。 在这种情况下，增加子序列的长度不会超过`1`存在。 正确的答案是元素的数量，因为每个单独的值都形成自己的 LIS。 的初始化`lengths`和`counts`到`1`保证这种情况自然处理，无需特殊逻辑。 

更微妙的边缘情况涉及重复值与增加的子序列混合，例如`[1,1,1,2,2,2]`。 多个不同的索引组合产生有效的 LIS 序列。 计数逻辑必须正确累积来自多个前任的计数，而不会错误地覆盖它们。 这`elif lengths[j] + 1 == lengths[i]`分支确保所有同样最佳的路径都被计数。 

另一个重要的情况是单元素数组。 最长递增子序列的长度`1`，并且恰好存在一个这样的子序列。 由于 DP 数组初始化为`1`，执行立即产生正确答案。
