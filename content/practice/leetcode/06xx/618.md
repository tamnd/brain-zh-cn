 ## 解决方案

 ## 问题理解

 该问题要求我们将学生姓名及其所在洲的表格转换为透视报告，其中每个洲成为一列，学生姓名按字母顺序显示在各自洲下。 输入是一个`Student`包含两列的表：`name`和`continent`。 该表可能包含重复的条目，除了每行代表一个学生之外，这不会影响透视结果。 

预期输出是一个包含三列的表：`America`,`Asia`， 和`Europe`。 每列下，来自该大陆的学生姓名按字母顺序列出。 行是对齐的，如果一个大陆的学生多于另一个大陆，则较短的列具有`NULL`缺失行的值。 

约束告诉我们`America`将至少有与其他大陆一样多的学生，这简化了行对齐，但后续要求提供一个更通用的解决方案，其中大陆计数未知。 边缘情况包括空大陆、重复大陆以及每个大陆的学生数量不同。 

## 方法

 暴力方法是手动查询每个大陆，按字母顺序对学生进行排序，然后逐行连接结果。 虽然这在逻辑上可行，但它需要多个自联接或手动索引来对齐行，这在大陆计数未知时很麻烦且难以扩展。 

最佳解决方案使用**窗口函数**`ROW_NUMBER()`为每个大陆的每个学生分配一个顺序索引，按字母顺序排序。 建立索引后，**完全外连接**（如果保证一个大陆拥有最多学生，则使用左连接）按学生的行号对齐学生。 这保证了正确的字母顺序和行对齐，同时轻松扩展到每个大陆的未知学生数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个大陆 O(n log n) + O(n) 连接 | O(n) | 排序并手动对齐，对于未知的大陆大小很麻烦 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用`ROW_NUMBER()`和用于动态对齐的枢轴连接 |

 ## 算法演练

 1. 使用`ROW_NUMBER()`窗口函数为每个学生在其大陆组内分配一个索引，按字母顺序排序。 这为每个大陆的每个学生提供了唯一的行号。 
2. 按洲将学生分成三个派生表（或 CTE）。 每个表都有学生的姓名和行索引。 
3. 对所有三个大陆表的行索引执行**完全外连接**。 这会将同一行索引中的学生对齐在一起。 
4. 选择`name`每个大陆表中的列并将它们别名为`America`,`Asia`， 和`Europe`。 
5. 按行索引对最终结果进行排序以保持对齐。 

**为什么有效：**`ROW_NUMBER()`保证学生在其所在大陆按字母顺序排序。 连接行索引可确保每个大洲的第一个学生在第一行中对齐，第二个学生在第二行中对齐，依此类推。 缺失值会自动填充`NULL`在加入期间。 

## Python 解决方案```python
class Solution:
    def pivotStudents(self, conn) -> None:
        """
        Execute SQL on the given connection to pivot students by continent.
        """
        query = """
        WITH ranked AS (
            SELECT
                name,
                continent,
                ROW_NUMBER() OVER (PARTITION BY continent ORDER BY name) AS rn
            FROM Student
        )
        SELECT
            a.name AS America,
            b.name AS Asia,
            c.name AS Europe
        FROM
            (SELECT name, rn FROM ranked WHERE continent = 'America') a
        LEFT JOIN
            (SELECT name, rn FROM ranked WHERE continent = 'Asia') b
        ON a.rn = b.rn
        LEFT JOIN
            (SELECT name, rn FROM ranked WHERE continent = 'Europe') c
        ON a.rn = c.rn
        ORDER BY a.rn;
        """
        with conn.cursor() as cursor:
            cursor.execute(query)
            result = cursor.fetchall()
            for row in result:
                print(row)
```在此 Python 实现中，公共表表达式 (CTE)`ranked`用于分配行号。 每个大陆的单独子查询在行号上左连接。 这`ORDER BY a.rn`确保行正确对齐。 

## 解决方案```go
package main

import (
    "database/sql"
    "fmt"
    _ "github.com/go-sql-driver/mysql"
)

func PivotStudents(db *sql.DB) error {
    query := `
    WITH ranked AS (
        SELECT
            name,
            continent,
            ROW_NUMBER() OVER (PARTITION BY continent ORDER BY name) AS rn
        FROM Student
    )
    SELECT
        a.name AS America,
        b.name AS Asia,
        c.name AS Europe
    FROM
        (SELECT name, rn FROM ranked WHERE continent = 'America') a
    LEFT JOIN
        (SELECT name, rn FROM ranked WHERE continent = 'Asia') b
    ON a.rn = b.rn
    LEFT JOIN
        (SELECT name, rn FROM ranked WHERE continent = 'Europe') c
    ON a.rn = c.rn
    ORDER BY a.rn;
    `
    rows, err := db.Query(query)
    if err != nil {
        return err
    }
    defer rows.Close()
    for rows.Next() {
        var america, asia, europe sql.NullString
        if err := rows.Scan(&america, &asia, &europe); err != nil {
            return err
        }
        fmt.Println(america.String, asia.String, europe.String)
    }
    return rows.Err()
}
```在围棋中，`sql.NullString`用于安全处理`NULL`价值观。 逻辑反映了 Python，并且`WITH`CTE 结合`LEFT JOIN`正确对齐行。

 ## 边缘情况

 一种极端情况是某个大陆没有学生。 使用`LEFT JOIN`或者`FULL OUTER JOIN`确保丢失的行返回为`NULL`没有错误。 

另一个极端情况是学生姓名重复。 自从`ROW_NUMBER()`根据大陆和字母顺序的组合进行操作，重复项被分配不同的行号，以防止冲突。 

第三个边缘情况是美国没有最多的学生，正如后续所允许的那样。 最佳解决方案可以扩展到动态枢轴，使用`FULL OUTER JOIN`以及所有大陆的最大行数，确保正确对齐，无论最大的大陆如何。
