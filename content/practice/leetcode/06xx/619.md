[LeetCode 第 619 题](https://leetcode.com/problems/biggest-single-number/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`MyNumbers`包含单个列，`num`。 由于没有主键限制，该表可能包含重复值。 我们的任务是找到表中只出现一次的最大数字。 

如果一个数字在表中出现的频率恰好为 1，则该数字被视为“单个数字”。 如果多个数字满足这个条件，我们必须返回其中最大的一个。 如果没有数字恰好出现一次，则查询应返回`null`。 

输入不像传统算法问题那样以数组或对象的形式提供。 相反，输入表示为 SQL 表中的行。 每一行包含一个整数值。 输出预计是一个单行表，其中一列名为`num`。 

例如，如果表包含：

 | 编号 |

 |---|---|

 | 1 |

 | 2 |

 | 2 |

 | 5 |

 然后`1`和`5`是单个数字，因为它们每个都出现一次。 自从`5`更大，结果应该是：

 | 编号 |

 |---|---|

 | 5 |

 一个重要的细节是，即使不存在有效数字，结果仍必须包含行。 在这种情况下，SQL 应该返回`null`。 

问题约束很小而且很简单，因为这主要是一个 SQL 聚合问题。 关键操作是计算每个数字出现的次数。 

有几个重要的边缘情况：

 - 每个数字出现多次，所以答案应该是`null`。 
- 表中只有一个数字，因此它自动成为最大的单个数字。 
- 可能会出现负数，因此我们不能假设所有值都是正数。 
- 可能存在多个唯一值，需要我们选择其中的最大值。 
- 该表可能包含许多重复项，因此简单的重复扫描方法会变得低效。 

## 方法

 ### 蛮力方法

 强力解决方案将单独检查每个不同的数字，并使用嵌套查询计算它在表中出现的次数。 

从概念上讲，该算法的工作原理如下：

 1. 迭代每个不同的数字。 
2. 对于每个数字，再次扫描整个表以计算出现次数。 
3. 记录计数等于 1 的数字。 
4. 返回其中的最大值。 

这种方法是正确的，因为它明确地验证了每个数字的频率。 然而，它的效率很低，因为可能会重复扫描表以查找每个不同的值。 

如果有`n`行和许多唯一数字，重复计数操作会导致二次行为。 

### 最佳方法

 更好的解决方案是使用 SQL 聚合函数。 

关键的见解是 SQL 已经通过以下方式提供了高效的分组和计数操作：`GROUP BY`和`COUNT`。 我们可以在一次聚合过程中计算所有数字的频率，而不是重复扫描表。 

优化后的流程为：

 1. 行分组依据`num`。 
2. 计算每个数字出现的次数。 
3. 使用以下方法过滤计数等于 1 的组`HAVING`。 
4. 选择剩余数字中的最大值。 

这是高效的，因为计数工作集中到一组聚合中，而不是重复扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描表格中的每个数字 |
 | 最佳| O(n) | O(n) | 使用 SQL 聚合`GROUP BY`和`COUNT`|

 ## 算法演练

 ### 最优 SQL 算法

 1. 将所有行按`num`柱子。 

此步骤将相同的数字收集在一起，以便我们可以有效地计算它们的频率。 
2. 计算每个组有多少行。 

使用`COUNT(*)`，我们确定每个数字在表中出现的次数。 
3. 过滤频率恰好为1的组。 

这`HAVING COUNT(*) = 1`子句删除所有重复的数字并仅保留单个数字。 
4. 计算最大剩余数。 

在所有有效的单个数字中，我们使用以下方法选择最大的一个`MAX()`聚合函数。 
5. 返回结果。 

如果过滤后没有留下有效行，`MAX()`自然回归`NULL`，符合问题要求。 

### 为什么它有效

 该算法之所以有效，是因为分组将表划分为相同数字的集合。 每组的计数准确地代表了该数字在表中出现的频率。 过滤依据`COUNT(*) = 1`保证仅保留单个数字。 因此，取这些剩余值中的最大值会产生最大的单个数字。 

## Python 解决方案

 虽然这是一个 SQL 问题，但 LeetCode 数据库问题通常直接用 SQL 解决。 没有实际的 Python 类存根用于执行。 不过，为了完整起见，这里是在 Python 字符串中表示的 SQL 查询。```python
query = """
SELECT MAX(num) AS num
FROM (
    SELECT num
    FROM MyNumbers
    GROUP BY num
    HAVING COUNT(*) = 1
) AS single_numbers;
"""
```该查询分两个阶段进行。 

内部查询对表进行分组`num`并过滤掉所有频率不完全为 1 的数字。 完成此步骤后，只剩下有效的单个号码。 

外部查询适用`MAX(num)`检索最大的单个数字。 如果内部查询没有返回行，`MAX()`自动返回`NULL`。 

## 解决方案

 与 Python 部分一样，LeetCode 上的数据库问题是使用 SQL 而不是 Go 来解决的。 为了完整起见，这里是将 SQL 查询表示为 Go 字符串。```go
package main

func main() {
	query := `
SELECT MAX(num) AS num
FROM (
    SELECT num
    FROM MyNumbers
    GROUP BY num
    HAVING COUNT(*) = 1
) AS single_numbers;
`
	_ = query
}
```Go 版本只是将 SQL 查询存储为原始字符串文字。 实际逻辑完全保留在 SQL 内部。 

Go 特有的一个小细节是对多行原始字符串使用反引号，这可以避免转义引号或换行符。

 ## 边缘情况

 ### 不存在单一数字

 当每个数字多次出现时，就会出现最重要的边缘情况之一。 幼稚的实现可能会意外返回`0`、空行，或者完全失败。 SQL 解决方案自然地处理这个问题，因为`MAX()`应用于空结果集返回`NULL`。 

### 表中只有一行

 如果表只包含一行，则该数字会自动出现一次并且必须返回。 一些不正确的解决方案使计数逻辑过于复杂，并且在最小输入上失败。 分组方法可以正常工作，因为单个组的计数为 1。 

### 多个单号

 当几个数字恰好出现一次时，就会出现另一种微妙的情况。 该问题特别要求最大的单个数字，而不仅仅是任何有效数字。 使用`MAX(num)`保证正确选择最高有效值。 

### 负值

 尽管示例仅显示正整数，但 SQL 整数列可能包含负数。 不正确的实现可能会用以下方式初始化答案`0`，如果所有数字均为负数，则会失败。 使用 SQL`MAX()`直接避免了这个问题，因为它正确地比较所有整数值，无论符号如何。
