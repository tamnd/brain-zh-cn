[LeetCode 第 674 题](https://leetcode.com/problems/longest-continuous-increasing-subsequence/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们找到数组中最长的严格递增连续段的长度。 关键细节是子序列必须是连续的，这意味着元素必须在原始数组中彼此相邻出现。 

给定一个整数数组`nums`，我们需要确定任何子数组的最大长度，其中每个元素都严格大于其前面的元素。 换句话说，对于所选子数组内的每个相邻对，条件`nums[i] < nums[i + 1]`必须持有。 

例如，在数组中`[1,3,5,4,7]`，序列`[1,3,5]`是连续且严格递增的，所以它的长度是`3`。 虽然`[1,3,5,7]`正在增加，它不连续，因为元素`4`出现在之间`5`和`7`。 

输入尺寸相对较小，`nums.length`最多`10^4`，但这仍然足够大，以至于低效的二​​次解变得不可取。 数组内的值的范围可以是`-10^9`到`10^9`，但数字的实际大小并不重要，因为我们只比较相邻的值。 

该问题保证数组至少包含一个元素。 这很重要，因为这意味着答案至少总是`1`。 

需要考虑一些重要的边缘情况：

 - 应返回只有一个元素的数组`1`。 
- 所有元素都相等的数组也应该返回`1`，因为序列必须严格递增。 
- 完全递增的数组应返回完整的数组长度。 
- 应该返回一个完全递减的数组`1`。 
- 重复的值打破了增加的趋势，因为相等不满足严格的增加。 

## 方法

 ### 蛮力方法

 一种简单的方法是检查每个可能的连续子数组并检查它是否严格递增。 

我们可以选择每个起始索引`i`，然后将子数组扩展到每个结束索引`j`。 对于每个子数组，我们验证每个相邻对是否满足递增条件。 

这种方法是正确的，因为它显式检查所有可能的连续子序列并跟踪找到的最大有效长度。 

然而，这种方法效率低下。 有`O(n^2)`可能的子数组，并检查每个子数组是否在增加可以采取另一个`O(n)`最坏情况下的时间。 这导致总复杂度为`O(n^3)`。 即使进行了小的优化，与可能的情况相比，该方法仍然不必要地缓慢。 

### 最佳方法

 关键的观察是我们不需要重复地重新检查早期的元素。 由于子序列必须是连续的，因此我们只关心当前元素是否延续前一个元素的增加趋势。 

我们可以从左到右扫描一次数组，同时保持：

 - 当前增加的条纹长度
 - 迄今为止看到的最大条纹长度

 如果`nums[i] > nums[i - 1]`，增加的序列继续，所以我们延长当前的连续。 

否则，连胜就被打破了，我们将当前的连胜长度重置回`1`因为当前元素本身启动了一个新的潜在序列。 

这是有效的，因为每个连续增加的子序列完全由相邻比较确定。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 检查每个子数组并验证递增顺序 |
 | 最佳 | O(n) | O(1) | O(1) | 跟踪当前连胜的同时单次通过 |

 ## 算法演练

 1.初始化两个变量：

 -`current_length = 1`-`max_length = 1`由于保证数组至少包含一个元素，因此最小可能的递增子序列的长度`1`。 
2. 从索引开始迭代数组`1`。 

我们从索引开始`1`因为每次比较都需要查看前一个元素。 
3. 对于每个位置`i`， 比较`nums[i]`和`nums[i - 1]`。 

这决定了增长趋势是否继续。 
4. 如果`nums[i] > nums[i - 1]`, 增量`current_length`。 

这意味着当前元素扩展了现有的递增子序列。 
5. 否则，重置`current_length`到`1`。 

递增序列已被破坏，因此当前元素成为新的可能子序列的开始。 
6.更新后`current_length`， 更新`max_length`。 

如果当前连续记录大于迄今为止看到的最佳连续记录，则存储新的最大值。 
7.循环结束后，返回`max_length`。 

这表示数组中最长连续递增子序列的长度。 

### 为什么它有效

 该算法保持不变式`current_length`始终表示当前以索引结尾的严格递增连续段的长度`i`。 

每当两个相邻元素满足递增条件时，条纹就会自然延伸。 当条件失败时，没有连续增加的子序列可以跨越该边界，因此重置为`1`是正确的。 

通过跟踪达到的最大值`current_length`，我们保证最终答案是数组中最长的有效子序列。 

## Python 解决方案```python
from typing import List

class Solution:
    def findLengthOfLCIS(self, nums: List[int]) -> int:
        current_length = 1
        max_length = 1

        for i in range(1, len(nums)):
            if nums[i] > nums[i - 1]:
                current_length += 1
            else:
                current_length = 1

            max_length = max(max_length, current_length)

        return max_length
```实现首先初始化两个`current_length`和`max_length`到`1`。 这反映了这样一个事实：任何单个元素都形成有效的长度递增子序列`1`。 

循环从索引处开始`1`因为每个元素都必须与前一个元素进行比较。 如果当前元素大于前一个元素，则增加条纹继续，所以`current_length`是递增的。 

如果条件失败，则连胜被打破，算法将重置`current_length`回到`1`。 

每次更新后，算法都会比较`current_length`和`max_length`以确保迄今为止发现的最长连续记录得以保留。 

由于数组只被遍历一次并且只使用了几个整型变量，因此该实现既节省时间又节省空间。 

## 解决方案```go
func findLengthOfLCIS(nums []int) int {
    currentLength := 1
    maxLength := 1

    for i := 1; i < len(nums); i++ {
        if nums[i] > nums[i-1] {
            currentLength++
        } else {
            currentLength = 1
        }

        if currentLength > maxLength {
            maxLength = currentLength
        }
    }

    return maxLength
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 Go 使用显式变量声明`:=`和标准`for`循环语法。 

一个重要的细节是，该问题保证数组至少有一个元素，因此不需要对空切片进行特殊处理。 

Go 切片是数组上动态大小的视图，因此索引的工作方式与 Python 列表类似。 整数溢出不是问题，因为最大子序列长度最多为`10^4`。

 ## 边缘情况

 单元素数组是最小的有效输入。 幼稚的实现可能会意外返回`0`如果它假设必须至少进行一次比较。 此实现正确地初始化了两者`current_length`和`max_length`到`1`，即使循环从未执行，也确保答案有效。 

具有重复值的数组是另一个重要的边缘情况。 由于该问题需要严格增加，因此相等的相邻值必须打破连续。 例如，`[2,2,2]`应该返回`1`， 不是`3`。 实现使用条件`nums[i] > nums[i - 1]`，这正确地排除了平等。 

完全递减的数组，例如`[5,4,3,2,1]`可能会暴露实现错误地累积长度的错误。 在这种情况下，每次比较都会失败，因此当前的条纹重置为`1`步步。 该实现通过重置逻辑自然地处理这个问题。 

当最长的条纹出现在数组的末尾时，会发生另一种微妙的情况，例如`[1,2,0,3,4,5]`。 某些实现仅在连续结束时错误地更新最大值。 此解决方案更新`max_length`在每次迭代期间，确保正确计算最终的连胜。
