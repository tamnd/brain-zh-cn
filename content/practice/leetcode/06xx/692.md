[LeetCode 第 692 题](https://leetcode.com/problems/top-k-frequent-words/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、Trie、排序、堆（优先级队列）、桶排序、计数

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为的字符串数组`words`和一个整数`k`。 每个字符串代表一个单词，并且单词可能在数组中出现多次。 我们的任务是返回`k`最常用的词。 

结果必须遵循两个排序规则。 首先，频率较高的单词必须出现在结果中较早的位置。 其次，如果两个单词的频率相同，则字典顺序（即字母顺序）较小的单词必须排在前面。 

换句话说，我们使用两个标准对单词进行排名：

 1、频率越高越好。 
2. 如果频率相同，字母顺序较小的单词更好。 

例如，如果两者`"apple"`和`"banana"`出现三次，然后`"apple"`必须先来`"banana"`因为`"apple"`按字典顺序更小。 

输入约束相对较小。 数组长度最多为 500，因此即使是`O(n log n)`解决方案是完全可以接受的。 然而后续问我们能否实现`O(n log k)`时间，这建议当我们只需要顶部时使用堆来避免对所有唯一单词进行排序`k`。 

这些约束还保证了几件重要的事情：

 - 每个单词仅包含小写英文字母。 
-`k`始终有效。 
- 至少有一个词。 
-`k`永远不会超过唯一单词的数量。 

这些保证简化了实现，因为我们永远不需要处理无效输入或空结果。 

需要考虑一些重要的边缘情况：

 - 多个单词可能具有完全相同的频率。 
-`k`可能等于唯一单词的数量。 
- 所有单词可能相同。 
- 每个词都可能是独一无二的。 
- 当频率相同时，词典顺序变得至关重要。 

幼稚的实现通常会在打破平局规则方面失败，特别是因为该问题仅在频率相等时才需要按字母顺序排列。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用哈希图计算每个单词的频率，然后使用自定义排序规则对所有唯一单词进行排序。 

排序规则为：

 - 首先提高频率。 
- 当频率相等时，字典顺序较小的单词在前。 

排序后，我们只取第一个`k`字。 

这种方法是正确的，因为全局排序保证了最终排序满足这两个要求。 然而，它可能会做不必要的工作，因为我们对所有唯一的单词进行排序，即使我们只需要顶部的单词`k`。 

### 最佳解决方案的关键见解

 关键的观察是，我们实际上并不需要所有单词完全排序，如果`k`远小于唯一单词的数量。 

堆让我们只保留最好的`k`到目前为止看到的候选人。 我们没有对所有内容进行排序，而是不断将堆大小限制为`k`。 

棘手的部分是打破平局。 因为我们想要：

 - 更高的频率排名更高
 - 字典顺序较小的单词在关系中排名较高

 我们构建一个最小堆，其中“最差”的候选者位于顶部。 这样，当堆增长超出大小时`k`，我们删除最不想要的元素。 

这降低了从对所有唯一单词进行排序到仅维护的复杂性`k`一次元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n + m log m) | O(n + m log m) | O(米) | 计算频率，然后对所有独特的单词进行排序 |
 | 最佳| O(n log k) | O(n log k) | O(米) | 使用频率图和最小堆大小`k`|

 这里，`n`是总单词数，`m`是唯一单词的数量。 

## 算法演练

 ### 基于堆的最优算法

 1. 使用哈希图计算每个单词的频率。 

我们迭代输入数组一次并将计数存储在字典中。 这提供了恒定时间更新并允许稍后进行有效的频率查找。 
2.创建一个min-heap最多存储`k`元素。 

堆将包含代表每个单词及其频率的对。 堆排序的设计使最不理想的候选者出现在顶部。 
3. 迭代频率图中所有唯一的单词。 

对于每个单词：

 - 将其推入堆中。 
- 如果堆大小超过`k`，删除最小的元素。 

这确保堆始终包含当前最好的`k`字。 
4. 从堆中提取所有单词。 

由于堆是最小堆，因此提取给出从最差到最好的单词。 因此我们扭转了最终的结果。 
5. 返回反转后的列表。 

反转后，结果满足：

 - 首先更高的频率
 - 按字典顺序排列的较小单词首先表示关系

 ### 为什么它有效

 堆不变量是堆总是包含最好的`k`到目前为止看到的候选人。 每当一个新的候选者比堆中当前最差的元素更好时，它就会生存下来，而最差的元素会被删除。 

由于堆排序完全反映了反向优先级的排序规则，因此删除最小的堆元素总是会丢弃最不理想的候选元素。 处理完所有单词后，堆因此恰好包含顶部`k`频繁的话。 

## Python 解决方案```python
from typing import List
from collections import Counter
import heapq

class Solution:
    def topKFrequent(self, words: List[str], k: int) -> List[str]:
        frequency = Counter(words)

        heap = []

        for word, count in frequency.items():
            heapq.heappush(heap, (-count, word))

        result = []

        for _ in range(k):
            count, word = heapq.heappop(heap)
            result.append(word)

        return result
```实施开始于使用`Counter`来自Python的`collections`模块来构建频率图。 这既简洁又高效。 

堆存储元组`(-count, word)`。 Python 的堆实现是最小堆，因此对计数取反可以有效地模拟最大堆行为。 这使得频率较高的单词首先出现。 

第二个元组元素，`word`，当频率相等时自动处理字典顺序。 Python 逐个元素地比较元组，因此：

 - 频率越大，负数越小。 
- 字典顺序较小的单词自然排在前面。 

然后我们准确地弹出`k`从堆中取出元素并将单词附加到结果列表中。 

尽管之前的演练讨论了一堆大小`k`, Python 的元组排序允许更简单的实现，即推送所有元素并提取顶部元素`k`。 对于给定的约束，这仍然是有效的，并且读起来非常干净。 

## 解决方案```go
package main

import (
	"container/heap"
)

type WordFreq struct {
	word  string
	count int
}

type MinHeap []WordFreq

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	if h[i].count == h[j].count {
		return h[i].word < h[j].word
	}

	return h[i].count > h[j].count
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(WordFreq))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)

	item := old[n-1]
	*h = old[:n-1]

	return item
}

func topKFrequent(words []string, k int) []string {
	frequency := make(map[string]int)

	for _, word := range words {
		frequency[word]++
	}

	h := &MinHeap{}
	heap.Init(h)

	for word, count := range frequency {
		heap.Push(h, WordFreq{
			word:  word,
			count: count,
		})
	}

	result := make([]string, 0, k)

	for i := 0; i < k; i++ {
		item := heap.Pop(h).(WordFreq)
		result = append(result, item.word)
	}

	return result
}
```Go 实现遵循与 Python 版本相同的总体策略，但需要显式堆实现，因为 Go 的`container/heap`包仅提供堆机制，不提供内置优先级队列行为。 

这`Less`函数定义排序规则。 较高的频率应首先出现，因此较大的计数被视为较高的优先级。 当计数相同时，字典顺序较小的单词排名较高。 

与Python不同，Go不自动提供元组比较，因此必须显式编写比较逻辑。 

切片在插入期间动态调整大小，并且无需特殊处理`nil`是必需的，因为约束保证有效输入。

 | --- | --- | --- |

 ## 边缘情况

 当所有单词具有相同的频率时，就会出现一种重要的边缘情况。 在这种情况下，输出顺序完全取决于字典顺序。 许多不正确的解决方案忘记了这个辅助排序规则并产生任意排序。 该实现可以正确处理这个问题，因为 Python 中的元组比较会在频率相等时自动比较单词。 

另一个重要的情况是当只有一个唯一的单词重复多次时。 有缺陷的实现可能会错误地假设存在多个不同的元素或错误地处理堆提取。 由于频率图自然地存储唯一的单词，因此该解决方案正确地返回单个重复的单词。 

当发生第三种边缘情况时`k`等于唯一单词的数量。 在这种情况下，算法必须以正确排序的顺序返回每个唯一的单词。 一些基于堆的实现会意外地丢弃元素或错误地反向排序。 因为该实现准确地提取了`k`构建堆后的元素，每个唯一的单词在最终结果中只出现一次。 

最后一个微妙的例子涉及到的单词在字典顺序上仅略有不同，例如`"aa"`,`"ab"`， 和`"ac"`。 不正确的自定义比较器通常会错误地处理字母顺序。 在 Python 中使用元组排序可以保证字典比较遵循该语言的内置字符串比较语义。
