 # LeetCode 644 - 最大平均子数组 II

 ## 问题理解

 该问题要求我们在长度至少为**的所有连续子数组中找到**最大可能的平均值**`k`**。 

我们得到一个整数数组`nums`和一个整数`k`。 子数组是数组的连续部分，这意味着元素必须连续出现。 与子数组长度固定的简单滑动窗口问题不同，这里子数组可以是**大于或等于的任何长度`k`**。 我们的任务是确定可获得的最高平均值并将其作为浮点数返回。 

只要误差小于，结果就被接受`10^-5`，这强烈表明精确的有理值是不必要的。 这种容忍度是一个主要线索，表明**答案空间上的二分搜索**可能是合适的。 

这些约束条件也指导解决方案的设计：

 -`1 <= k <= n <= 10^4`-`-10^4 <= nums[i] <= 10^4`自从`n`可以达到`10^4`，检查每个子数组并直接计算每个平均值的强力解决方案将非常昂贵。 我们需要比二次时间更好的东西。 

几个重要的边缘情况值得关注：

 首先，数组可能包含**负数**。 这可以防止仅仅基于正积累的贪婪策略。 有效的最大平均值可以来自平衡正值和负值。 

其次，最佳子数组可能具有**精确的长度`k`**，或者可能会更长。 我们不能假设固定的窗口大小。 

三、当`n = 1`和`k = 1`，答案就是唯一的元素本身。 该算法必须优雅地处理这个最小的输入。 

最后，数组可能包含所有相同的值或所有负值。 实现仍必须正确确定最大平均值。 

## 方法

 ### 蛮力方法

 一种简单的方法是枚举每个可能的子数组，其长度至少为`k`，计算其平均值，并跟踪最大值。 

我们可以生成每个起始索引和每个结束索引，计算子数组的总和，然后除以它的长度。 为了避免重复重新计算总和，前缀总和可以将每个子数组总和计算减少到`O(1)`。 

即使有前缀和，仍然有`O(n²)`可能的子数组。 由于必须检查每个子数组，因此总时间复杂度变为`O(n²)`。 

为了`n = 10^4`，这变得太慢了，因为大致`10^8`在最坏的情况下可能需要进行操作。 

### 最优方法，对答案进行二分搜索

 关键的观察是我们没有被要求返回子数组本身，只返回**最大平均值**。 

我们可以二分搜索答案，而不是直接搜索子数组。 假设我们猜测一个平均值`mid`。 问题变成：

 **我们能找到一个至少长度的子数组吗`k`其平均值至少为`mid`？**

 如果是，那么正确答案至少是`mid`，所以我们应该搜索更高的位置。 

如果没有，那么`mid`太大了，我们应该搜索更低的。 

为了有效地测试可行性，我们对数组进行了转换：$$transformed[i] = nums[i] - mid$$现在问题变成判断是否存在至少长度的子数组`k`其总和是**非负**。 

为什么这有效？ 

如果：$$\frac{sum(subarray)}{length} \ge mid$$然后：$$sum(subarray) - mid \cdot length \ge 0$$这正是变换后的子数组的总和。 

我们可以使用前缀和和运行的最小前缀值在线性时间内验证这一点。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 使用前缀和枚举所有有效子数组 |
 | 最佳| O(n log R) | O(n log R) | O(1) | O(1) | 在答案空间上进行二分搜索，其中`R`是数值范围 |

 这里，`R`表示数组中最小值和最大值之间的精度范围。 

## 算法演练

 ### 最优算法

 1. 初始化二分查找范围。 

由于答案必须位于最小值和最大值之间`nums`， 放：

-`left = min(nums)`-`right = max(nums)`最大平均值不能小于最小元素或大于最大元素。 
2. 定义辅助函数`can_find(guess)`。 

该函数判断是否存在至少长度的子数组`k`平均至少`guess`。 
3. 转换运行总和。 

无需显式创建转换后的数组，而是计算：$$nums[i] - guess$$迭代时。 
4. 计算第一个窗口的大小`k`。 

计算第一个变换后的总和`k`元素。 

如果该和为非负数，则已存在有效的子数组。 
5. 跟踪当前窗口之前的前缀贡献。 

维持：

-`prefix_sum`, 累积变换和
 -`min_prefix_sum`，迄今为止看到的最小前缀

 存储最小前缀的原因是减去较小的前缀可以最大化子数组和。 
6. 迭代剩余的元素。 

对于每个新职位：

 - 扩展当前转换的总和。 
- 更新前缀信息。 
- 检查是否：$$current\_sum - min\_prefix\_sum \ge 0$$如果为 true，则存在有效的子数组。 
7. 执行二分查找。 

如果`can_find(mid)`是真的：

 - 向上移动左边界。 

否则：

 - 向下移动右边界。 
8. 继续，直到精度足够。 

停止时：$$right - left < 10^{-5}$$返回`left`。 

### 为什么它有效

 该算法之所以有效，是因为二分查找不断缩小包含最大平均值的范围。 辅助函数通过将平均约束转换为子数组和约束来正确确定可行性。 通过从每个数字中减去猜测的平均值，任何具有非负变换总和的子数组都精确对应于其平均值至少为猜测值的子数组。 由于可行性是单调的，这意味着一旦较大的猜测可行，较小的猜测仍然可行，因此二分搜索是有效的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMaxAverage(self, nums: List[int], k: int) -> float:
        def can_find(target_average: float) -> bool:
            current_sum = 0.0

            for index in range(k):
                current_sum += nums[index] - target_average

            if current_sum >= 0:
                return True

            prefix_sum = 0.0
            min_prefix_sum = 0.0

            for index in range(k, len(nums)):
                current_sum += nums[index] - target_average

                prefix_sum += nums[index - k] - target_average
                min_prefix_sum = min(
                    min_prefix_sum,
                    prefix_sum
                )

                if current_sum - min_prefix_sum >= 0:
                    return True

            return False

        left = float(min(nums))
        right = float(max(nums))
        precision = 1e-5

        while right - left > precision:
            middle = (left + right) / 2

            if can_find(middle):
                left = middle
            else:
                right = middle

        return left
```实现首先定义`can_find`辅助函数，它确定候选平均值是否可以实现。 

该函数不是显式构造转换后的数组，而是计算`nums[i] - target_average`在飞行中。 这减少了内存使用并保持实现简洁。 

第一个`k`变换后的元素立即求和，因为最小的有效子数组大小是`k`。 如果这个初始变换和已经是非负的，则存在有效的子数组。 

对于较长的子数组，实现会跟踪前缀和。`prefix_sum`存储落在当前有效窗口之外的转换值，而`min_prefix_sum`保留遇到的最小前缀。 减去最小前缀可以最大化以当前位置结尾的可能子数组和。 

最后，二分查找反复缩小候选平均范围，直到满足精度要求。 

## 解决方案```go
import "math"

func findMaxAverage(nums []int, k int) float64 {
	canFind := func(targetAverage float64) bool {
		currentSum := 0.0

		for i := 0; i < k; i++ {
			currentSum += float64(nums[i]) - targetAverage
		}

		if currentSum >= 0 {
			return true
		}

		prefixSum := 0.0
		minPrefixSum := 0.0

		for i := k; i < len(nums); i++ {
			currentSum += float64(nums[i]) - targetAverage

			prefixSum += float64(nums[i-k]) - targetAverage
			minPrefixSum = math.Min(
				minPrefixSum,
				prefixSum,
			)

			if currentSum-minPrefixSum >= 0 {
				return true
			}
		}

		return false
	}

	left := float64(nums[0])
	right := float64(nums[0])

	for _, num := range nums {
		value := float64(num)

		left = math.Min(left, value)
		right = math.Max(right, value)
	}

	precision := 1e-5

	for right-left > precision {
		middle := (left + right) / 2

		if canFind(middle) {
			left = middle
		} else {
			right = middle
		}
	}

	return left
}
```Go 的实现与 Python 版本非常相似。 由于 Go 不会自动将整数转换为浮点值，因此显式`float64()`每当算术涉及平均值时，就需要进行转换。 

实现使用`math.Min`和`math.Max`有效地计算边界并维护最小前缀和。 Go 切片自然地处理迭代，因此不需要对空数组进行特殊处理，因为约束保证`n >= 1`。

 ### 示例 1

 | 窗口| 总和 |

 | 变量| 价值|
 | --- | --- |
 | 当前总和| -11.75 | -11.75

 | 最小前缀总和 | -11.75 | -11.75

 ## 边缘情况

 ### 单元素数组

 当`nums`仅包含一个元素并且`k = 1`，答案一定就是该元素本身。 由于对较长窗口或前缀计算的假设，某些实现可能会失败。 此实现可以自然地处理这种情况，因为二分搜索边界立即崩溃。 

### 所有负数

 一个常见的错误是假设更大的金额总是会提高平均水平。 对于负值，最小的负数可能会产生最好的结果。 由于该算法对数值范围进行二进制搜索并以数学方式检查转换后的总和，因此无论符号如何，它都可以正常工作。 

### 最佳子数组长于`k`简单的滑动窗口解决方案可能仅精确检查窗口大小`k`。 然而，该问题允许长度大于`k`。 前缀最小技术确保每个有效子数组的大小至少`k`被考虑的不仅仅是固定长度的窗口。 

### 相同的值

 如果所有值都相等，则最大平均值等于该重复值。 二分搜索仍然正确收敛，因为每个子数组产生相同的平均值，并且可行性测试在整个搜索范围内仍然有效。
