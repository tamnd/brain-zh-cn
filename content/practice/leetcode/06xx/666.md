[LeetCode 第 666 题](https://leetcode.com/problems/path-sum-iv/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题将二叉树编码为三位数整数的紧凑数组。 每个整数存储三条信息：

 - 百位数字表示节点的深度。 
- 十位数表示节点在该深度级别内的位置。 
- 个位代表节点的实际值。 

例如，整数`215`意思是：

 - 深度=`2`- 位置=`1`- 值=`5`这些位置遵循完整二叉树的索引规则。 这意味着：

 - 位置处的节点`p`有：

 - 左孩子在该位置`2 * p - 1`- 右孩子在位置`2 * p`输入数组已经排序并表示深度小于的有效连接树`5`。 

目标是计算每个根到叶路径的总和。 根到叶路径总和是从根向下移动到叶节点时遇到的所有节点值的总和。 

例如，如果树有两条从根到叶的路径：

 -`3 -> 5`-`3 -> 1`那么总的答案就是：```
(3 + 5) + (3 + 1) = 12
```限制非常小：

 - 至多`15`节点
 - 最大深度为`4`这意味着即使是相对低效的解决方案仍然可以快速运行。 然而，问题主要是测试我们是否正确解释树编码并正确遍历结构。 

一些边缘情况很重要：

 - 树可能只包含根节点。 
- 一个节点只能有一个子节点。 
- 叶子没有明确标记，我们必须检测它们。 
- 由于树是稀疏的，位置可能会跳过值。 
- 我们不能单独使用数组索引来构造子项，因为编码使用逻辑树位置，而不是连续存储。 

该问题保证输入代表有效的连接二叉树，因此我们不需要验证格式错误的结构。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是首先使用实际的树节点对象重建整个二叉树。 我们将解析每个编码数字，创建节点，根据深度位置关系连接父节点和子节点，然后运行标准 DFS 遍历来计算所有根到叶路径总和。 

这种方法是正确的，因为一旦树被重建，问题就变成了标准的二叉树路径和遍历问题。 

然而，构造显式树节点是不必要的开销。 输入已经包含足够的信息，可以通过深度和位置值的算术直接识别父子关系。 

尽管约束足够小，该解决方案可以轻松通过，但它会执行额外的工作并使用比必要的更多的内存。 

### 最佳方法

 关键的观察是我们实际上不需要构建二叉树结构。 

每个节点可以使用以下方式唯一标识：```
(depth, position)
```我们可以将所有节点存储在哈希图中，其中：```
key = depth * 10 + position
value = node value
```然后，在 DFS 期间：

 - 我们计算当前路径总和。 
- 我们以数学方式推导潜在的左右子位置。 
- 如果哈希图中两个子节点都不存在，则当前节点是叶子节点。 
- 否则，我们递归地继续遍历。 

这是有效的，因为编码本身已经包含树的完整结构。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 在 DFS 之前显式构造二叉树 |
 | 最佳 | O(n) | O(n) | 使用哈希图并直接从编码坐标进行遍历 |

 ## 算法演练

 1. 创建一个哈希图来存储所有节点。 

对于每一个数字`nums`，提取：

 - 深度：`num // 100`- 位置：`(num // 10) % 10`- 价值：`num % 10`使用以下方法存储节点值：```
key = depth * 10 + position
```这允许对任何节点进行恒定时间查找。 
2. 定义DFS 函数。 

DFS 函数应该接受：

 - 当前深度
 - 当前位置
 - 当前累计路径总和

 在每一步中，我们将当前节点的值添加到运行总和中。 
3. 计算子位置。 

对于位置处的节点`p`:

 - 左子位置=`2 * p - 1`- 右子位置 =`2 * p`两个孩子都深陷其中`d + 1`。 
4. 检查是否存在children。 

为潜在的孩子建立钥匙：```
left_key = (d + 1) * 10 + (2 * p - 1)
right_key = (d + 1) * 10 + (2 * p)
```使用哈希映射来确定每个子项是否存在。 
5. 检测叶节点。 

如果两个子节点都不存在，则当前节点是叶子节点。 

将当前路径总和添加到最终答案中。 
6. 递归遍历现有子项。 

如果存在子级，则使用更新的路径总和继续 DFS。 
7. 从根目录启动DFS。 

根始终是排序输入中的第一个节点。 

### 为什么它有效

 该算法之所以有效，是因为每个节点的位置唯一地确定其子节点必须位于完整二叉树索引系统中的位置。 通过将节点存储在由以下键控的哈希图中`(depth, position)`，我们可以直接导航隐式树结构，而无需构造实际的树节点。 DFS 保证每条从根到叶的路径都被精确地探索一次，并且每个叶将其路径总和精确地贡献给最终答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def pathSum(self, nums: List[int]) -> int:
        nodes = {}

        for num in nums:
            depth = num // 100
            position = (num // 10) % 10
            value = num % 10

            key = depth * 10 + position
            nodes[key] = value

        total_sum = 0

        def dfs(depth: int, position: int, current_sum: int) -> None:
            nonlocal total_sum

            key = depth * 10 + position
            current_sum += nodes[key]

            left_key = (depth + 1) * 10 + (2 * position - 1)
            right_key = (depth + 1) * 10 + (2 * position)

            has_left = left_key in nodes
            has_right = right_key in nodes

            if not has_left and not has_right:
                total_sum += current_sum
                return

            if has_left:
                dfs(depth + 1, 2 * position - 1, current_sum)

            if has_right:
                dfs(depth + 1, 2 * position, current_sum)

        root_depth = nums[0] // 100
        root_position = (nums[0] // 10) % 10

        dfs(root_depth, root_position, 0)

        return total_sum
```该实现首先解析每个编码的整数并将其存储在字典中以进行恒定时间访问。 字典键将深度和位置组合成一个紧凑的标识符。 

DFS函数在向下遍历树的同时累加运行路径总和。 该函数不使用实际的树节点引用，而是使用完整的二叉树索引规则以数学方式计算子坐标。 

当字典中不存在计算出的子键时，就会发生叶子检测。 此时，累积的路径和将添加到全局答案中。 

由于递归仅访问现有节点，因此遍历保持高效且干净。 

## 解决方案```go
func pathSum(nums []int) int {
	nodes := make(map[int]int)

	for _, num := range nums {
		depth := num / 100
		position := (num / 10) % 10
		value := num % 10

		key := depth*10 + position
		nodes[key] = value
	}

	totalSum := 0

	var dfs func(depth int, position int, currentSum int)

	dfs = func(depth int, position int, currentSum int) {
		key := depth*10 + position
		currentSum += nodes[key]

		leftKey := (depth+1)*10 + (2*position - 1)
		rightKey := (depth+1)*10 + (2 * position)

		_, hasLeft := nodes[leftKey]
		_, hasRight := nodes[rightKey]

		if !hasLeft && !hasRight {
			totalSum += currentSum
			return
		}

		if hasLeft {
			dfs(depth+1, 2*position-1, currentSum)
		}

		if hasRight {
			dfs(depth+1, 2*position, currentSum)
		}
	}

	rootDepth := nums[0] / 100
	rootPosition := (nums[0] / 10) % 10

	dfs(rootDepth, rootPosition, 0)

	return totalSum
}
```Go 实现遵循与 Python 版本相同的结构。 一个`map[int]int`用于节点查找。 递归 DFS 是使用函数变量实现的，因为 Go 需要显式声明递归匿名函数。 

不用担心整数溢出，因为在给定的约束下最大可能的路径和非常小。 

Go 映射返回第二个布尔值来指示存在，这使得叶子检测变得简单。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | DFS过程中每个节点插入一次、访问一次
 | 空间| O(n) | 哈希映射存储所有节点，递归堆栈使用额外空间 |

 该算法执行一次遍历来构建哈希图，并执行另一次遍历，仅访问每个节点一次。 由于 DFS 内的每个操作都是恒定时间，因此总运行时间与节点数量呈线性关系。 

空间使用也是线性的，因为哈希映射为每个节点存储一个条目。 递归深度最多为`4`，因此在给定的约束下堆栈使用实际上是恒定的。

 ## 边缘情况

 ### 单节点树

 一棵树可能只包含一个节点，例如：```
[111]
```在这种情况下，根也是叶。 一个常见的错误是忘记没有子节点的节点应该立即贡献其路径和。 该实现自然地处理了这个问题，因为两个子查找都失败，导致 DFS 将根视为叶子。 

### 左孩子或右孩子失踪

 这棵树不一定是完整的。 一个节点可能只有一个子节点：```
[113, 221]
```在这里，根只有一个右孩子。 不正确的实现有时会假设子级成对存在或依赖于数组索引。 该解决方案通过哈希映射查找独立检查子项是否存在，从而避免了该问题。 

### 稀疏位置值

 位置对应于完整的二叉树布局，而不是紧凑索引。 这意味着位置可以跳过值：```
[114, 225, 337]
```尝试使用连续数组重建树的简单实现可能会失败，因为逻辑位置与存储位置不匹配。 哈希图方法可以正确处理稀疏布局，因为节点关系是根据深度和位置而不是物理阵列放置以数学方式计算的。
