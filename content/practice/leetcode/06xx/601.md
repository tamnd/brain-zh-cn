[LeetCode 601 题](https://leetcode.com/problems/ human-traffic-of-stadium/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们从一个数组中提取所有连续的记录`Stadium`表，其中`people`count 至少为 100，并且连续条纹的长度为 3 或更多。 每行都有一个独特的`id`以及相应的`visit_date`。 这里的连续是指连续`id`值，而不是连续的日期。 输出应该是属于这些条纹的所有记录，按以下顺序排序`visit_date`。 

输入是一个包含三列的 SQL 表：`id`（递增整数），`visit_date`（唯一的日期），以及`people`（代表出席率的整数）。 预期输出是该表的子集，其中每一行都是三个或更多连续行序列的一部分（通过`id`） 和`people >= 100`。 

重要的限制包括`visit_date`是独一无二的并且`id`是严格增加的。 边缘情况可能涉及表开头或结尾的序列、长度恰好为 3 的序列或被一行中断的序列`people < 100`。 此外，日期之间的差距并不重要——连续性仅由`id`。 

## 方法

 ### 暴力方法

 一种简单的方法是扫描表，并针对每一行检查接下来的两行是否也有`people >= 100`。 对于较长的序列，这将需要迭代所有可能的长度为 3 或以上的子数组。 这种方法是正确的，但效率低下，因为它重复检查重叠序列，导致 n 行可能进行 O(n^2) 比较。 

### 最佳方法

 关键的见解是使用带有累积计数的**窗口技术**。 首先，我们用以下标记行`people >= 100`。 然后，通过使用 SQL 窗口函数，例如`LEAD`和`LAG`，我们可以确定一行是否是满足条件的三个或更多连续行的连续行的一部分。 另一种方法是为连续合格行的每个条纹分配一个“组”标识符，并过滤大小至少为三的组。 这减少了重复扫描并利用基于 SQL 集的操作来提高效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 手动检查每个可能的连续三元组，多余的工作 |
 | 最佳| O(n) | O(n) | 使用窗口函数或分组来有效地识别合格条纹 |

 ## 算法演练

 1. **按出勤率过滤行：** 标记所有行`people >= 100`识别潜在的条纹。 
2. **识别连续组：** 计算之间的差异`id`以及过滤集的行号，为每个条纹分配唯一的组号。 连续的行将具有相同的差值。 
3. **计算每组的条纹大小：** 使用`COUNT(*) OVER (PARTITION BY group_id)`找出每个组的大小。 
4. **过滤大小 >= 3 的组：** 仅包含组大小为 3 或更多的行。 
5. **订购依据`visit_date`:** 确保输出符合所需的顺序。 

**为什么有效：** 之间的区别`id`行号为连续的合格行创建稳定的组标识符，因为对于连续的序列，`id - row_number`是恒定的。 按组大小过滤可确保我们仅返回长度为 3 或以上的序列。 

## Python 解决方案```python
# SQL-based solution represented in Python-friendly syntax for LeetCode
SELECT id, visit_date, people
FROM (
    SELECT *,
           id - ROW_NUMBER() OVER (ORDER BY id) AS grp
    FROM Stadium
    WHERE people >= 100
) AS t
WHERE grp IN (
    SELECT grp
    FROM (
        SELECT id - ROW_NUMBER() OVER (ORDER BY id) AS grp, COUNT(*) AS cnt
        FROM Stadium
        WHERE people >= 100
        GROUP BY grp
    ) AS sub
    WHERE cnt >= 3
)
ORDER BY visit_date;
```**说明：** 我们首先使用以下内容过滤行`people >= 100`。 这`ROW_NUMBER()`根据分配连续的数字`id`。 从中减去这个`id`给出一个常数`grp`连续序列的值。 内部查询计算组大小，外部查询仅选择长度为 3 或以上的组，排序依据`visit_date`。

## 工作示例

 **示例1：**```
id | visit_date | people
1  | 2017-01-01 | 10
2  | 2017-01-02 | 109
3  | 2017-01-03 | 150
4  | 2017-01-04 | 99
5  | 2017-01-05 | 145
6  | 2017-01-06 | 1455
7  | 2017-01-07 | 199
8  | 2017-01-09 | 188
```逐步：

 1. 过滤行`people >= 100`：第 2、3、5、6、7、8 行。 
2. 计算`grp = id - row_number()`:

 - 第 2 行：2 - 1 = 1
 - 第 3 行：3 - 2 = 1
 - 第 5 行：5 - 3 = 2
 - 第 6 行：6 - 4 = 2
 - 第 7 行：7 - 5 = 2
 - 第 8 行：8 - 6 = 2
 3. 计算组大小：

 - 第 1 组：尺寸 2（第 2、3 行）→ 太小，丢弃
 - 第 2 组：尺寸 4（第 5、6、7、8 行）→ 包含
 4. 输出行排序`visit_date`：第 5、6、7、8 行。

 ## 边缘情况

 一种重要的边缘情况是条纹正好是三行长。 这是最小有效连胜，必须包含在内。 如果计算错误，实现可能会忽略它们。 另一个边缘情况是表格开头或结尾处出现条纹； SQL 窗口函数可以正确处理这些，但简单的循环可能会错过它们。 最后，行与`people < 100`打破长序列必须正确终止一个组； 我们的组 ID 方法自然地分离了这些序列，无需额外的逻辑。
