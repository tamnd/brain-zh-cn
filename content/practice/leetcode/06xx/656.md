[LeetCode 第 656 题](https://leetcode.com/problems/coin-path/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们在考虑跳跃约束和阻塞位置的同时找到通过数组的最便宜的有效路径。 

数组`coins`在问题陈述中是 1 索引的，尽管编程语言将在内部使用 0 索引的数组。 每个位置包含：

 - 一个非负整数，表示登陆该指数的成本
 -`-1`，表示该位置被封锁，无法访问

 你从索引开始`1`并且必须达到索引`n`。 从当前任意位置`i`，你可以向前跳到任何位置`i + k`在哪里：

-`1 <= k <= maxJump`-`i + k <= n`- 目的地位置未被封锁

 每当您到达某个位置时，您就需要支付其硬币成本。 目标是最小化路径的总成本。 

产出本身并不是最低成本。 相反，我们必须返回沿着最优路径访问的索引序列。 

另一个复杂因素是字典顺序要求。 如果多条路径具有相同的最小总成本，我们必须返回字典顺序最小的一条。 

例如：

-`[1,2,5]`按字典顺序小于`[1,3,4]`因为在第一个不同的位置，`2 < 3`-`[1,2]`按字典顺序小于`[1,2,3]`因为当一个序列是另一个序列的前缀时，较短的序列获胜

 限制相对较小：

 -`n <= 1000`-`maxJump <= 100`这些限制强烈表明`O(n * maxJump)`动态规划解决方案是合适的。 

几个重要的边缘情况立即出现：

 - 目的地可能无法到达
 - 中间位置可能全部被封锁
 - 可能存在多个最小成本路径
 -`maxJump`可能太小而无法绕过阻塞的单元
 - 数组只能包含一个元素
 - 大片的`-1`值可能会迫使仔细的路径验证

 该问题保证起始位置始终有效，这意味着`coins[1] != -1`。 

## 方法

 ### 蛮力方法

 强力解决方案将递归地探索索引中的每条可能的路径`1`索引`n`。 

在每个位置，我们都会尝试从`1`到`maxJump`，递归计算所有可达路径，并跟踪：

 - 总成本最低
 - 关系中字典顺序最小的路径

 这种方法是正确的，因为它详尽地枚举了每条有效路径，并根据问题规则直接进行比较。 

然而，可能的路径数量呈指数增长。 在每个位置我们可以分支到`maxJump`选择，导致巨大的搜索树。 即使使用记忆，重复比较整个路径也会变得昂贵。 

为了`n = 1000`，蛮力是完全不切实际的。 

### 最优动态规划方法

 关键的观察结果是，到达某个位置的最便宜路径仅取决于到达较早可到达位置的最便宜路径。 

这自然会导致动态规划。 

我们定义：

 -`dp[i]`= 达到指标的最低成本`i`-`parent[i]`= 之前用于达到的索引`i`最佳地

 我们从数组末尾向开头向后计算解决方案。 

为什么向后 DP 在这里特别有效：

 - 从位置`i`，我们选择最好的下一跳
 - 我们已经知道后面位置的最佳解决方案
 - 词典排序变得更容易处理

 当多个下一个位置产生相同的成本时，我们选择较小的下一个索引。 由于路径是向前构建的，因此选择较小的下一步可以保证按字典顺序排列较小的结果。 

这给出了一个有效的`O(n * maxJump)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(最大跳跃^n) | O(n) | 递归探索每条可能的路径 |
 | 最佳| O(n * 最大跳跃) | O(n) | 具有路径重构的动态规划|

 ## 算法演练

 ### 第 1 步：初始化 DP 数组

 我们创建两个数组：

 -`dp[i]`存储从索引开始到达终点所需的最小成本`i`-`next_index[i]`存储从中选择的下一个位置`i`最初：

 - 所有值都是无穷大，因为我们假设位置无法到达
 - 目标位置被特别初始化

 如果最后一个位置没有被封锁：

 -`dp[n-1] = coins[n-1]`这意味着完成最后一个索引的成本只是其本身的硬币价值。 

### 第 2 步：向后处理位置

 我们迭代自`n-2`下降到`0`。 

向后遍历很重要，因为在评估从`i`，我们已经知道所有可到达目的地的最优未来成本。 

对于每个位置：

 - 跳过它，如果`coins[i] == -1`- 否则检查每个跳跃长度`1`到`maxJump`### 第 3 步：评估可达到的下一个职位

 对于每个可达到的位置`j`:

 - 忽略被阻止或无法到达的位置
 - 计算候选人成本：```
coins[i] + dp[j]
```如果此成本小于当前最佳成本：

 - 更新`dp[i]`- 记录`next_index[i] = j`### 步骤 4：处理词典编排的平局

 如果两种选择产生相同的总成本：

 - 选择较小的下一个索引

 由于路径是贪婪地向前重建的，因此选择较小的直接下一步可以保证整体路径按字典顺序更小。 

### 步骤 5：检查可达性

 DP完成后：

 - 如果`dp[0]`仍然无穷大，不存在有效路径
 - 返回一个空数组

 ### 第 6 步：重建路径

 从索引开始`0`:

 - 将当前位置附加到答案中
 - 移至`next_index[current]`- 继续前进直至到达目的地

 请记住在返回之前将索引转换回 1 索引格式。 

### 为什么它有效

 动态规划状态保证`dp[i]`始终存储位置的最小可能成本`i`到最后。 

由于位置是向后处理的，因此每个未来状态在使用之前都已被最佳计算。 

满足字典顺序规则是因为当成本平局时，算法总是选择尽可能小的下一个索引。 由于字典顺序比较取决于最早的不同元素，因此这种贪婪的平局打破策略会产生字典顺序最小的最佳路径。 

## Python 解决方案```python
from typing import List

class Solution:
    def cheapestJump(self, coins: List[int], maxJump: int) -> List[int]:
        n = len(coins)

        INF = float("inf")

        dp = [INF] * n
        next_index = [-1] * n

        if coins[n - 1] != -1:
            dp[n - 1] = coins[n - 1]

        for i in range(n - 2, -1, -1):
            if coins[i] == -1:
                continue

            for j in range(i + 1, min(n, i + maxJump + 1)):
                if dp[j] == INF:
                    continue

                candidate_cost = coins[i] + dp[j]

                if candidate_cost < dp[i]:
                    dp[i] = candidate_cost
                    next_index[i] = j
                elif (
                    candidate_cost == dp[i]
                    and (next_index[i] == -1 or j < next_index[i])
                ):
                    next_index[i] = j

        if dp[0] == INF:
            return []

        path = []
        current = 0

        while current != -1:
            path.append(current + 1)

            if current == n - 1:
                break

            current = next_index[current]

        return path
```实现首先初始化 DP 和父跟踪数组。`dp[i]`存储索引中的最小成本`i`到目的地。 每个值都以无穷大开始，表示无法到达的状态。`next_index[i]`记录下一次跳转产生最佳路径。 

首先初始化目标索引，因为它的成本已经直接知道。 

主 DP 循环向后处理索引。 对于每个有效位置，算法会检查范围内的每个合法跳转目的地`maxJump`。 

每当找到更便宜的路径时，DP 值和下一个指针就会更新。 

如果两个候选路径具有相同的成本，则算法会选择较小的下一个索引来保留字典顺序。 

最后，通过重复遵循来重建路径`next_index`从起点到到达目的地的指针。 

## 解决方案```go
package main

import "math"

func cheapestJump(coins []int, maxJump int) []int {
	n := len(coins)

	const INF = math.MaxInt32

	dp := make([]int, n)
	nextIndex := make([]int, n)

	for i := 0; i < n; i++ {
		dp[i] = INF
		nextIndex[i] = -1
	}

	if coins[n-1] != -1 {
		dp[n-1] = coins[n-1]
	}

	for i := n - 2; i >= 0; i-- {
		if coins[i] == -1 {
			continue
		}

		end := i + maxJump
		if end >= n {
			end = n - 1
		}

		for j := i + 1; j <= end; j++ {
			if dp[j] == INF {
				continue
			}

			candidateCost := coins[i] + dp[j]

			if candidateCost < dp[i] {
				dp[i] = candidateCost
				nextIndex[i] = j
			} else if candidateCost == dp[i] &&
				(nextIndex[i] == -1 || j < nextIndex[i]) {
				nextIndex[i] = j
			}
		}
	}

	if dp[0] == INF {
		return []int{}
	}

	result := []int{}
	current := 0

	for current != -1 {
		result = append(result, current+1)

		if current == n-1 {
			break
		}

		current = nextIndex[current]
	}

	return result
}
```Go 的实现与 Python 版本非常相似。 

一个重要的区别是无穷大的处理。 Go 不提供直接的整数无穷大值，所以`math.MaxInt32`被用作足够大的哨兵。 

切片用于动态数组，空切片`[]int{}`当不存在路径时返回。 

Go 在计算跳跃范围时还需要显式边界处理。

 ## 边缘情况

 当目的地无法到达时，就会出现一种重要的边缘情况。 这可能是由于位置受阻或跳跃距离不足而发生的。 有缺陷的实现可能仍会尝试重建路径或返回部分路径。 DP 方法通过检查是否`dp[0]`计算后仍为无穷大。 如果是，算法立即返回一个空数组。 

另一个微妙的边缘情况涉及字典顺序。 多条路径可能产生相同的最小总成本。 如果不仔细处理平局，算法可能会返回有效的最小成本路径，但不是字典顺序最小的路径。 此实现通过在 DP 转换期间始终选择较小的下一个索引来解决关系。 

第三个重要的边缘情况是单元素数组。 如果`coins`仅包含一个值，起点已经是目的地。 该算法正确初始化目的地成本并重建路径为`[1]`不需要任何跳跃。 

中间位置受阻也是错误的常见来源。 该算法小心地跳过任何索引`coins[i] == -1`，无论是在 DP 计算期间还是在考虑跳转目的地时。 这保证了路径中永远不会包含无效位置。 

最后，大的跳跃范围可能会暴露相差一的错误。 该实现仔细地限制了跳跃范围，使用`min(n, i + maxJump + 1)`Python 中的显式范围限制和 Go 中的显式范围限制，确保不会发生越界访问。
