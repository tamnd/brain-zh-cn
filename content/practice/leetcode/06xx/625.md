[LeetCode 第 625 题](https://leetcode.com/problems/minimum-factorization/)

 **难度：** 🟡 中等
 **主题：** 数学、贪心

 ## 解决方案

 ## 问题理解

 问题要求我们找到**最小的正整数**`x`使其所有数字的乘积等于给定的整数`num`。 

换句话说，我们想要分解`num`转化为十进制数字的乘法`1`到`9`，然后排列这些数字以形成数字上最小的可能整数。 

例如：

 - 如果`num = 48`，我们可以将其表示为`6 × 8 = 48`，产生数字`68`。 
- 另一个有效的分解是`2 × 3 × 8 = 48`，生产`238`， 但`68 < 238`， 所以`68`是正确的答案。 

重要的细节是，我们不是单独最小化位数，而是最小化结果整数值。 由于较短的数字通常比较长的数字小，因此我们通常需要较少的数字，但数字排列也很重要。 

输入是单个正整数`num`， 在哪里：

-`1 <= num <= 2^31 - 1`输出应该是：

 - 数字相乘的最小正整数`num`-`0`如果不存在这样的整数
 -`0`如果结果超出 32 位有符号整数范围

 约束很重要，因为`num`可能非常大，高达约 21 亿。 对候选人编号进行强力搜索是不可行的。 

有几个重要的边缘情况：

 - 如果`num`是一位数字`1`到`9`，答案很简单`num`，因为该数字已经满足条件。 
- 有些数字不能分解为数字`2`通过`9`。 例如，`11`是素数且大于`9`，所以没有有效的答案。 
- 结果数字可能超出 32 位有符号整数限制（`2,147,483,647`），即使存在有效的数字分解。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试每个正整数`x`，计算其数字的乘积，并检查是否等于`num`。 

对于每个候选人编号：

 1. 提取所有数字。 
2. 将它们相乘。 
3. 将结果与`num`。 
4. 当找到第一个有效号码时停止。 

这是可行的，因为最终我们会发现最小的有效数字（如果存在）。 

然而，这种方法速度极其缓慢。 搜索空间是巨大的，因为在找到解决方案之前我们可能需要检查多少个数字，并没有实际的上限。 即使对于中等值`num`，候选人的数量就变成了天文数字。 

我们需要数学观察来避免穷举搜索。 

### 关键见解

 我们可以逆向思考，而不是通过数字搜索：

 我们想要其乘积等于的数字`num`。 

由于数字只能是`2`通过`9`为了有意义的乘法，我们应该反复除法`num`从**最大可能的数字开始**，`9`下降到`2`。 

为什么先最大呢？ 

使用较大的因子会减少位数。 较少的数字通常会产生较小的整数。 然而，因为我们想要数字上最小的最终整数，所以我们首先收集较大的因子，然后在构造数字时颠倒它们的顺序。 

例如：`48`- 除以`8`→ 剩余`6`- 除以`6`→ 剩余`1`收集到的数字：`[8, 6]`要得到最小的整数，请将它们按升序排列：`68`如果去除所有因素后`9`到`2`，我们仍然有一个大于`1`，那么某个素因数超过`9`，意味着不存在有效的数字分解。

 ## 算法演练

 1.处理特殊情况`num`小于`10`。 

如果`num`已经是一个数字，它通常是最小的有效答案，因为数字本身乘以`num`。 
2. 创建一个空列表来存储数字因子。 

我们将反复提取数字因子`9`下降到`2`。 
3. 从数字开始迭代`9`下降到`2`。 

对于每个数字：

 - 虽然`num`能被数字整除：

 - 将数字添加到列表中。 
- 划分`num`按那个数字。 

这会贪婪地提取尽可能大的数字因子。 
4. 检查分解是否成功。 

处理完所有数字后，如果`num`仍然大于`1`，那么它包含一个大于的质因数`9`，因此不存在有效答案。 返回`0`。 
5.构造最小的数。 

由于首先收集较大的数字，因此在构建最终数字时颠倒顺序。 

例如：`[8, 6] → 68`我们逐位构造整数。 
6. 检查32位溢出。 

如果结果超过`2^31 - 1`， 返回`0`。 
7. 返回构造的整数。 

### 为什么它有效

 贪婪策略之所以有效，是因为较大的数字因子将因式分解压缩为更少的数字。 位数较少的数字几乎总是比位数较多的数字小。 在贪婪地提取较大的数字后，将它们按升序排列可以保证所有有效分解中字典顺序最小的可能数字。 

每当`num`可以完全分解为数字`2`通过`9`。 如果任何剩余因子大于`9`，不存在有效的数字表示。 

## Python 解决方案```python
class Solution:
    def smallestFactorization(self, num: int) -> int:
        if num < 10:
            return num

        digits = []

        for digit in range(9, 1, -1):
            while num % digit == 0:
                digits.append(digit)
                num //= digit

        if num != 1:
            return 0

        result = 0

        for digit in reversed(digits):
            result = result * 10 + digit

        return result if result <= 2**31 - 1 else 0
```实现从处理最简单的情况开始，当`num`已经是个位数了。 在这种情况下，答案是立即的。 

接下来，我们创建一个名为的列表`digits`存储提取的数字因子。 循环运行自`9`下降到`2`, 贪婪地划分`num`只要有可能。 

嵌套的`while`循环很重要，因为数字因子可能会出现多次。 例如，`72`可以除以`8`然后再次通过`3`。 

因式分解后，我们验证是否`num`成为`1`。 如果不是，则剩余的一些质因数无法表示为十进制数字。 

最后，我们通过逆序遍历收集到的数字来重建答案，产生最小的有效整数。 返回之前，我们验证结果是否符合 32 位有符号整数。 

## 解决方案```go
func smallestFactorization(num int) int {
	if num < 10 {
		return num
	}

	digits := []int{}

	for digit := 9; digit >= 2; digit-- {
		for num%digit == 0 {
			digits = append(digits, digit)
			num /= digit
		}
	}

	if num != 1 {
		return 0
	}

	result := 0
	maxInt32 := 2147483647

	for i := len(digits) - 1; i >= 0; i-- {
		result = result*10 + digits[i]

		if result > maxInt32 {
			return 0
		}
	}

	return result
}
```Go 实现遵循与 Python 解决方案完全相同的贪婪策略。 

Go 特有的一个区别是显式的溢出处理。 由于 Go 整数因架构而异，我们与常量进行比较`2147483647`直接强制执行 LeetCode 对有符号 32 位整数的要求。 

数字存储使用切片（`[]int`），随着因子的添加而动态增长。 反转是使用切片末尾的索引循环来处理的。

 ## 边缘情况

 ### 单个数字输入

 当`num`介于`1`和`9`，答案应该很简单`num`。 有缺陷的实现可能会不必要地分解这些值并意外返回不同的数字。 该实现通过立即返回来避免这种情况`num`什么时候`num < 10`。 

### 不可能因式分解

 像这样的数字`11`或者`13`包含大于的质因数`9`。 由于数字仅限于十进制数字，因此这些数字不能表示为数字的乘积。 贪心除法之后，执行检查是否`num == 1`。 如果没有，则正确返回`0`。 

### 32 位整数溢出

 即使存在有效的数字分解，生成的整数也可能超出带符号的 32 位范围。 返回这样的值将违反问题规范。 该实现显式验证构造的数量不超过`2,147,483,647`并返回`0`如果发生溢出。
