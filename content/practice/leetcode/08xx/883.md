[LeetCode 问题 883](https://leetcode.com/problems/projection-area-of-3d-shapes/)

 **难度：** 🟢简单
 **主题：** 数组、数学、几何、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`n x n`矩阵称为`grid`。 每个细胞`grid[i][j]`代表有多少个`1 x 1 x 1`立方体垂直堆叠在适当的位置`(i, j)`在平坦的表面上。 

我们必须计算这个 3D 结构在三个平面上的投影的总面积：

 - 的`xy`平面，这是俯视图
 - 的`yz`平面，这是前视图
 - 的`zx`平面，这是侧视图

 投影本质上是从特定方向观看时结构的可见阴影。 

为了清楚地理解预测：

 - 的`xy`投影从上面看。 任何包含至少一个立方体的单元都贡献`1`面积单位，因为堆栈占据地板上的该位置。 
- 这`yz`投影沿着行从侧面看。 对于每一行，只有最高的堆栈很重要，因为较短的堆栈隐藏在其后面。 
- 这`zx`投影沿着柱子从前面看。 对于每一列，只有最高的堆栈对可见区域有贡献。 

最终的答案就是这三个投影面积的总和。 

限制很小：

 -`1 <= n <= 50`-`0 <= grid[i][j] <= 50`这意味着矩阵最多是`50 x 50`，仅包含 2500 个细胞。 由于输入大小很小，即使效率较低的解决方案也可以工作，但该问题有一个非常干净的最优方法，该方法以相对于单元数量的线性时间运行。 

一个重要的细节是细胞可能含有`0`，意味着该位置不存在立方体。 这些单元格对顶部投影没有任何贡献，并且不会影响行或列最大值，除非该行或列中的每个值都为零。 

一些边缘情况很重要：

 - 应返回包含全零的网格`0`- A`1 x 1`网格必须正确组合单个堆栈中的所有三个投影
 - 具有多个相同最大高度的行或列应该只贡献一次最大高度
 - 具有许多零的稀疏网格仍应正确计算行和列投影

 ## 方法

 ### 蛮力方法

 思考该问题的一种强力方法是逐个立方体显式模拟投影。 

对于顶部投影，我们可以迭代每个单元并计算是否至少存在一个立方体。 

对于侧面和正面投影，我们可以想象构建堆栈的完整 3D 表示，然后确定从每个方向可见哪些立方体。 这可能涉及扫描每一行和每一列的每个可能的高度水平。 

尽管此方法会产生正确的答案，但它会执行不必​​要的工作，因为我们实际上不需要对单个立方体进行建模。 投影仅取决于堆栈是否存在以及每行和每列的最大高度。 

如果最大堆叠高度为`H`，这种强力模拟可能需要迭代所有高度级别，产生更接近的复杂性`O(n² × H)`。 

由于问题约束很小，这仍然可以通过，但效率低下，而且概念上比必要的更加复杂。 

### 最佳方法

 关键的观察是每个投影都可以使用网格的简单属性独立计算：

 - 的`xy`投影对非零单元进行计数
 - 的`yz`投影使用每行中的最大值
 - 的`zx`投影使用每列中的最大值

 这意味着我们只需要对矩阵进行一次遍历。 

遍历网格时：

 - 计算顶部投影的每个非零单元格
 - 跟踪每行中的最大值
 - 跟踪每列中的最大值

 最后：

 - 对所有行最大值求和
 - 对所有列最大值求和
 - 将它们与非零细胞计数相加

 这避免了不必要的立方体级模拟，并提供了高效且优雅的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × H) | O(1) | O(1) | 逐级模拟立方体可见性 |
 | 最佳| O(n²) | O(1) | O(1) | 使用行最大值、列最大值和非零计数 |

 ## 算法演练

 1.初始化三个变量：

 -`top_area`为`xy`投影
 -`front_area`为`yz`投影
 -`side_area`为`zx`投影
 2. 遍历网格中的每一行。 
3. 对于每一行：

 - 找到该行中的最大值
 - 添加到`front_area`这是有效的，因为行中最高的堆栈决定了侧视图的可见高度。 
4. 处理行中的每个单元格时：

 - 如果该值大于零，则增加`top_area`这是可行的，因为任何非零堆栈都会在顶部投影中占据一个正方形。 
5. 处理完行后，处理每一列。 
6. 对于每一列：

 - 查找该列所有行中的最大值
 - 添加到`side_area`这是有效的，因为列中最高的堆栈决定了前视图的可见高度。 
7、退货：`top_area + front_area + side_area`### 为什么它有效

 该算法之所以有效，是因为每个投影仅取决于一个方向的可见性。 

- 从上方看，每个占据的单元格恰好贡献一个可见的方块
 - 从侧面看，只有每行中最高的一叠仍然可见
 - 从正面看，只有每列中最高的一叠仍然可见

 由于这些投影是独立的，因此将它们的贡献相加即可得出正确的总投影面积。 

## Python 解决方案```python
from typing import List

class Solution:
    def projectionArea(self, grid: List[List[int]]) -> int:
        n = len(grid)

        top_area = 0
        front_area = 0
        side_area = 0

        # Process rows
        for row in grid:
            front_area += max(row)

            for value in row:
                if value > 0:
                    top_area += 1

        # Process columns
        for col in range(n):
            column_max = 0

            for row in range(n):
                column_max = max(column_max, grid[row][col])

            side_area += column_max

        return top_area + front_area + side_area
```实现直接遵循前面描述的算法。 

变量`top_area`计算有多少个单元包含至少一个立方体。 每个非零单元在顶部投影中贡献一个可见的正方形。 

变量`front_area`累加每行的最大堆叠高度。 使用`max(row)`有效地找到侧视图的可见贡献。 

列处理循环计算每列中最高的堆栈。 该最大值对前投影有贡献，并将结果添加到`side_area`。 

最后，该方法返回所有三个投影面积的总和。 

## 解决方案```go
func projectionArea(grid [][]int) int {
	n := len(grid)

	topArea := 0
	frontArea := 0
	sideArea := 0

	// Process rows
	for _, row := range grid {
		rowMax := 0

		for _, value := range row {
			if value > 0 {
				topArea++
			}

			if value > rowMax {
				rowMax = value
			}
		}

		frontArea += rowMax
	}

	// Process columns
	for col := 0; col < n; col++ {
		colMax := 0

		for row := 0; row < n; row++ {
			if grid[row][col] > colMax {
				colMax = grid[row][col]
			}
		}

		sideArea += colMax
	}

	return topArea + frontArea + sideArea
}
```Go 的实现与 Python 解决方案非常相似。 

因为 Go 没有提供内置的`max`标准语言语法中的整数函数，我们在计算行和列最大值时手动比较值。 

切片自然地用于 2D 网格表示。 除了几个整数变量之外，不需要额外的内存分配，因此空间复杂度保持不变。 

整数溢出不是问题，因为最大可能的答案很小。 当每个单元格都包含高度时，投影面积最大`50`，给予：

 顶部投影：`2500`- 行投影：`2500`- 柱投影：`2500`总计仅`7500`，完全在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况是仅包含零的网格。 在这种情况下，结构中的任何地方都没有立方体。 如果最大值初始化不正确，幼稚的实现可能会意外地错误地计算行或列。 该实现可以安全地处理这个问题，因为行和列的最大值保持为零，并且顶部投影仅计算大于零的值。 

另一个重要的情况是单单元网格，例如`[[5]]`。 在这里，同一个堆栈同时对所有三个投影做出贡献。 顶视图有贡献`1`，而行和列投影各自贡献`5`。 该实现自然地处理这个问题，因为它独立地计算每个投影。 

第三个重要的边缘情况是稀疏网格，高堆栈之间有许多零。 例如：```
[
    [0, 0, 10],
    [0, 0, 0],
    [5, 0, 0]
]
```在计算行或列最大值时，有缺陷的实现可能会错误地忽略孤立的堆栈。 该解决方案独立地正确扫描每一行和每一列，确保所有可见堆栈正确贡献最终答案。 

最后的边缘情况涉及行或列中重复的最大值。 例如：```
[
    [4, 4],
    [4, 4]
]
```行投影应仅计算每行的一个最大值，而不是两个单元格。 实现使用`max(row)`和列最大跟踪，因此无论有多少个单元格共享相同的最大高度，每行和每列都只贡献一次。
