 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们确定最小进食速度`k`对于 Koko 来说，她可以在给定的小时内吃完所有成堆的香蕉`h`。 输入由一个数组组成`piles`， 在哪里`piles[i]`代表香蕉的数量`i`第堆，和一个整数`h`这表示最长可用时间。 输出是一个整数`k`，代表 Koko 每小时必须吃完所有香蕉的最少数量`h`小时。 

理解要点：每小时，Koko 都会选择一堆并准确地吃掉`k`香蕉或剩余的一堆（如果少于）`k`剩下香蕉了。 她无法在一小时内把吃的东西分成好几堆。 约束表明，堆的数量和每堆香蕉的数量都可以非常大，最多可达`10^4`桩和`10^9`香蕉。 还有，小时数`h`可以大到`10^9`。 这表明暴力解决方案会迭代所有可能的方法`k`太慢了，我们必须找到一种高效的搜索方法。 

边缘情况包括：如果`h`等于堆的数量，科科必须在一小时内吃掉最大的一堆； 如果`h`非常大，她可以吃得很慢； 当所有堆都有相同的香蕉时，解决方案很简单，但不应该破坏算法。 

## 方法

 暴力方法会尝试一切可能的方法`k`从`1`直到一堆香蕉的最大数量。 对于每个`k`，我们通过将上限相加来计算所需的总小时数`pile / k`对于所有桩。 第一个`k`这使得科科能够在`h`小时就是答案。 虽然正确，但效率很低，因为最大堆尺寸可达`10^9`，导致多达十亿次迭代。 

最佳方法是在可能的进食速度范围内利用二分搜索。 关键的观察是，所需的总时间随着增加而单调减少`k`。 如果科科能快速吃完所有香蕉`k`，她也可以以任何更高的速度完成。 相反，如果她不能完成`k`，她无法以任何较低的速度完成。 这个属性允许我们应用二分搜索`k`有效地找到最小可行速度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(最大(桩) * n) | O(1) | O(1) | 迭代所有可能的情况`k`从 1 到最大堆尺寸和总小时数 |
 | 最佳| O(n * log(max(桩))) | O(1) | O(1) | 对进食速度进行二分搜索； 每位候选人的总工时 |

 ## 算法演练

 1. 初始化搜索范围`k`和`low = 1`和`high = max(piles)`。`low`代表最小可能的速度，并且`high`最大桩尺寸。 
2. 虽然`low < high`, 计算中间速度`mid = low + (high - low) // 2`。 
3.计算速度所需的总时间`mid`通过迭代每一堆并求和`ceil(pile / mid)`。 
4. 如果总小时数小于或等于`h`，这意味着Koko可以以这个速度或更慢的速度吃饭，所以调整上限`high = mid`。 
5. 否则Koko无法以这个速度完成，所以增加下限`low = mid + 1`。 
6. 当循环结束时，`low`等于`high`，这是最小速度`k`让科科在时间内完成比赛`h`小时。 

**为什么有效**：该算法保持了最小可行速度所在的不变量`[low, high]`。 通过根据当前中速是否允许按时完成反复缩小范围，二分搜索保证收敛到最小可行值`k`。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        def hours_needed(speed: int) -> int:
            total_hours = 0
            for pile in piles:
                total_hours += math.ceil(pile / speed)
            return total_hours
        
        low, high = 1, max(piles)
        
        while low < high:
            mid = low + (high - low) // 2
            if hours_needed(mid) <= h:
                high = mid
            else:
                low = mid + 1
        
        return low
```功能`hours_needed`计算 Koko 在给定速度下所需的总小时数。 主循环在速度范围内执行二分搜索。 如果`hours_needed(mid)`是在极限之内`h`，我们知道我们可能会降低速度，所以我们减少`high`。 否则，我们增加`low`。 最终值`low`是满足约束条件的最小速度。 

## 解决方案```go
import "math"

func minEatingSpeed(piles []int, h int) int {
    hoursNeeded := func(speed int) int {
        totalHours := 0
        for _, pile := range piles {
            totalHours += int(math.Ceil(float64(pile) / float64(speed)))
        }
        return totalHours
    }

    low, high := 1, 0
    for _, pile := range piles {
        if pile > high {
            high = pile
        }
    }

    for low < high {
        mid := low + (high - low) / 2
        if hoursNeeded(mid) <= h {
            high = mid
        } else {
            low = mid + 1
        }
    }
    return low
}
```在 Go 中，我们使用闭包`hoursNeeded`来计算所需的时间。 我们初始化`high`通过扫描堆来找到最大值。 我们小心地使用整数除法并将值转换为`float64`用于天花板操作。 二分搜索逻辑反映了 Python 实现。
