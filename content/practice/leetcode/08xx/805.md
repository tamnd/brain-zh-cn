 ## 解决方案

 ## 问题理解

 问题问我们是否可以划分给定的数组`nums`分成两个非空组，使得两个组具有相同的平均值。 

假设数组被分成子集`A`和`B`。 让：

-`sum(A)`是元素的总和`A`-`len(A)`是元素的数量`A`-`sum(B)`和`len(B)`类似地定义

 条件是：$$\frac{sum(A)}{len(A)} = \frac{sum(B)}{len(B)}$$因为`A`和`B`一起包含原始数组的每个元素，我们也知道：$$sum(A) + sum(B) = totalSum$$和$$len(A) + len(B) = n$$利用这些关系，条件可以重写为：$$\frac{sum(A)}{len(A)} = \frac{totalSum}{n}$$这是关键的数学简化。 我们不需要直接尝试构造两个平均值相等的子集，而只需判断是否存在一个非空子集，其平均值等于整个数组的平均值。 

如果存在这样的子集，则其余元素自动形成具有相同平均值的另一个子集。 

输入大小足够小，可以使用指数式技术进行优化：

 -`1 <= nums.length <= 30`-`0 <= nums[i] <= 10^4`30 的长度对于暴力枚举所有子集来说太大了，因为有：$$2^{30} \approx 10^9$$可能的子集。 

然而，对于中间相遇策略、子集 DP 或基于位掩码的优化来说，30 已经足够小了。 

几个重要的边缘情况立即出现：

 - 只有两个元素的数组，其中拆分的可能性极其有限。 
- 没有子集大小的数组可以产生整数目标和。 
- 具有重复值的数组。 
- 具有所有相同值的数组，其中任何非空分割都有效。 
- 总和对于任何子集大小都不可整除的数组。 

实现必须小心避免浮点精度问题。 平均比较应始终转换为整数方程。 

## 方法

 ### 蛮力方法

 最直接的解决方案是枚举数组的每个可能的子集。 

对于每个子集：

 1. 计算其总和和大小。 
2. 计算补集子集的总和和大小。 
3. 比较平均值。 

如果满足以下条件，则子集有效：$$sum(subset) \times (n - size) = (totalSum - sum(subset)) \times size$$这保证了精确的整数运算，没有浮点错误。 

这种方法是正确的，因为每个可能的分区都会被检查。 如果存在有效的分割，暴力最终会找到它。 

问题是子集的数量是指数级的：$$2^n$$和`n = 30`，这大约变成十亿个子集，这太慢了。 

### 最优方法，子集大小和总和的动态规划

 关键的观察结果是，相等的平均值意味着：$$\frac{subsetSum}{subsetSize} = \frac{totalSum}{n}$$重新排列给出：$$subsetSum = \frac{totalSum \times subsetSize}{n}$$对于大小的子集`k`，因此所需的总和是固定的：$$target = \frac{totalSum \times k}{n}$$这导致了一个重要的修剪规则：

 大小的子集`k`仅当满足以下条件时才可能：$$(totalSum \times k) \bmod n = 0$$否则，目标总和是小数且不可能的。 

现在问题就变成了：

 我们能找到尺寸的子集吗`k`谁的总和等于所需的目标？ 

我们使用动态规划来解决这个问题。 

定义：

-`dp[k]`作为精确使用可实现的所有总和的集合`k`元素。 

最初：

-`dp[0] = {0}`然后对于每个数字，按照子集大小的相反顺序更新 DP，以避免多次重用元素。 

如果在任何时候所需的目标总和出现在`dp[k]`，我们返回`true`。 

这极大地减少了搜索空间并在限制内有效地工作。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(1) | O(1) | 显式枚举每个子集 |
 | 最佳DP | 实践中的 O(n^2 * S) | O(n * S) | 按子集大小跟踪可实现的总和 |

 这里，`S`表示可达子集和的范围。 

## 算法演练

 1. 计算数组及其长度的总和。 

让：

-`n = len(nums)`-`totalSum = sum(nums)`这些值在整个算法中使用。 
2. 确定哪些子集大小在数学上是可能的。 

对于每个子集大小`k`从`1`到`n // 2`，计算：$$totalSum \times k$$如果这个值可以被整除`n`，然后是大小的子集`k`可能具有与整个阵列相同的平均值。 

否则，完全跳过它。 
3. 初始化动态规划结构。 

创造：```
dp[k]
```在哪里`dp[k]`准确地存储所有可实现的金额`k`元素。 

从以下开始：```
dp[0] = {0}
```因为大小为零的子集的和为零。 
4. 处理数组中的每个数字。 

对于每个数字`num`，以相反的顺序更新子集大小：```sql
for k from maxSize down to 1
```反向迭代至关重要，因为它可以防止在单次更新过程中多次使用同一元素。 
5. 生成新的总和。 

对于每个现有金额`prevSum`在`dp[k - 1]`， 添加：```
prevSum + num
```进入`dp[k]`。 

这代表选择当前元素。 
6. 检查目标金额是否有效。 

对于每个有效的子集大小`k`，计算：$$target = \frac{totalSum \times k}{n}$$如果`target`存在于`dp[k]`， 返回`true`。 
7. 如果处理完所有数字后没有找到有效的子集，则返回`false`。 

### 为什么它有效

 DP 保留了可实现的每一笔金额的完整记录，并且准确无误`k`元素。 

对于任何子集大小`k`，等平均条件唯一确定所需的总和：$$subsetSum = \frac{totalSum \times k}{n}$$如果该目标总和出现在`dp[k]`，则存在一个子集，其平均值等于整个数组平均值。 其余元素自动形成具有相同平均值的互补子集。 

因为每一个可以实现的`(subsetSize, subsetSum)`组合被探索了一次，算法是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def splitArraySameAverage(self, nums: List[int]) -> bool:
        n = len(nums)
        total_sum = sum(nums)

        possible = False

        for k in range(1, n // 2 + 1):
            if (total_sum * k) % n == 0:
                possible = True
                break

        if not possible:
            return False

        dp = [set() for _ in range(n + 1)]
        dp[0].add(0)

        for num in nums:
            for size in range(n // 2, 0, -1):
                for prev_sum in list(dp[size - 1]):
                    dp[size].add(prev_sum + num)

        for k in range(1, n // 2 + 1):
            if (total_sum * k) % n != 0:
                continue

            target = (total_sum * k) // n

            if target in dp[k]:
                return True

        return False
```实现首先计算数组长度和总和。 在构建 DP 表之前，它会执行数学可行性检查。 如果没有子集大小可以产生整数目标和，则答案是立即`False`。 

然后DP数组被初始化。 每个索引代表一个子集大小，相应的集合存储该大小的所有可达总和。 

该算法一次处理每个数字一个。 对子集大小的反向迭代至关重要，因为它可以防止当前数字在同一迭代中被多次计数。 

最后，算法检查任何有效子集大小是否包含其所需的目标总和。 如果是这样，则存在有效的分割。 

## 解决方案```go
package main

func splitArraySameAverage(nums []int) bool {
	n := len(nums)

	totalSum := 0
	for _, num := range nums {
		totalSum += num
	}

	possible := false

	for k := 1; k <= n/2; k++ {
		if (totalSum*k)%n == 0 {
			possible = true
			break
		}
	}

	if !possible {
		return false
	}

	dp := make([]map[int]bool, n+1)

	for i := 0; i <= n; i++ {
		dp[i] = make(map[int]bool)
	}

	dp[0][0] = true

	for _, num := range nums {
		for size := n / 2; size >= 1; size-- {
			current := make([]int, 0)

			for prevSum := range dp[size-1] {
				current = append(current, prevSum+num)
			}

			for _, newSum := range current {
				dp[size][newSum] = true
			}
		}
	}

	for k := 1; k <= n/2; k++ {
		if (totalSum*k)%n != 0 {
			continue
		}

		target := (totalSum * k) / n

		if dp[k][target] {
			return true
		}
	}

	return false
}
```Go 实现遵循与 Python 版本相同的逻辑，但 Go 不提供内置的集合类型。 相反，类型的地图`map[int]bool`用于表示总和的集合。 

另一个重要的区别是，在以取决于新插入的值的方式迭代 Go 映射时，不应修改它们。 为了避免在更新期间意外重用元素，在插入之前将中间总和收集到临时切片中。 

这里整数溢出不是问题，因为对于标准 Go 整数来说约束足够小。

 ## 边缘情况

 当数组长度非常小时，尤其是当数组长度非常小时，就会出现一种重要的边缘情况`n = 2`。 在这种情况下，可能的分区非常少。 幼稚的实现可能会错误地假设每个二元素数组都可以均匀分割。 该算法通过检查大小的子集是否可以达到所需的目标总和来正确处理此问题。 

另一个重要的情况是数组，其中没有子集大小可以在数学上产生整数目标和。 例如，如果：$$(totalSum \times k) \bmod n \neq 0$$那么所需的子集和将不是整数。 在这些情况下，许多低效的解决方案仍然尝试 DP 探索。 此实现执行早期修剪步骤并立即返回`False`如果不存在有效的子集大小。 

具有重复值的数组还会在子集生成逻辑中产生细微的错误。 如果按正向顺序执行更新，则同一元素可能会在一次迭代中意外地重复使用多次。 该实现通过以相反顺序迭代子集大小来避免此问题，确保每个数字在每个子集构造中最多贡献一次。 

最后，包含所有相同值的数组很特殊，因为每个子集都具有相同的平均值。 某些实现意外地拒绝了这些，因为它们错误地禁止了某些子集大小或错误地处理了补集子集。 该解决方案自然可以正确处理它们，因为始终可以达到所需的目标总和。
