 **难度：** 🔴难
 **主题：** 数学、二分查找

 ## 解决方案

 ## 问题理解

 问题要求我们找到`n`可被其中之一整除的第一个正整数`a`或者`b`。 如果至少满足以下条件之一，则该数字被视为神奇数字：

 - 它可以被除以`a`- 它可以被除以`b`我们得到三个整数：

 -`n`，我们想要的神奇数字的位置
 -`a`, 一个除数
 -`b`, 另一个除数

 任务是返回`n`神奇的数字模数`10^9 + 7`。 

例如，如果`a = 2`和`b = 3`，神奇的数字是：`2, 3, 4, 6, 8, 9, 10, 12, ...`第四个神奇的数字是`6`。 

关键的挑战来自于限制。 的价值`n`可以大到`10^9`，它立即告诉我们，一一生成神奇的数字是不可能的。 即使对整数进行线性扫描也太慢了。 

的价值观`a`和`b`最多小得多`4 * 10^4`，但这并不会显着降低难度，因为产生的神奇数字本身可能会变得非常大。 

一个重要的细节是数字可以被两者整除`a`和`b`应该只计算一次。 这意味着我们需要仔细处理重叠的倍数。 最小公倍数（LCM）变得非常重要，因为任何数字都可以被两者整除`a`和`b`必须能整除`lcm(a, b)`。 

一些边缘情况很重要：

 - 当`a == b`，每个神奇数字只是该值的倍数。 
- 当一个除数是另一个除数的倍数时，许多数字会重叠。 
- 什么时候`n`非常大，中间计算可能会超出 32 位整数限制。 
- 结果本身可能很大，这就是需要模运算的原因。 

## 方法

 ### 蛮力方法

 一种简单的方法是迭代正整数并计算有多少个整数可以被其中任何一个整除`a`或者`b`。 

对于每个数字`x`：

- 如果`x % a == 0`或者`x % b == 0`，增加魔法计数。 
- 一旦计数达到`n`， 返回`x`。 

这是有效的，因为它显式地按排序顺序构造了神奇数字的序列。 

然而，这种方法太慢了。 这`n`第一个神奇数字可能非常大，尤其是当`n = 10^9`。 迭代数十亿个整数是不可行的。 

即使我们通过生成多个来优化`a`和`b`单独并合并它们，运行时间仍然与`n`，太大了。 

### 最佳方法

 关键的见解是，我们可以二分搜索来找到答案，而不是直接生成神奇的数字。 

假设我们选择一些数字`x`。 我们可以有效地计算有多少个神奇的数字小于或等于`x`。 

计数为：$\left\lfloor\frac{x}{a}\right\rfloor + \left\lfloor\frac{x}{b}\right\rfloor - \left\lfloor\frac{x}{\mathrm{lcm}(a,b)}\right\rfloor$这是有效的，因为：

 -`x // a`计算的倍数`a`-`x // b`计算的倍数`b`- 可被两者整除的数字被计算两次，因此我们使用包含-排除将它们减去一次

 现在我们可以问：

 “至少有没有`n`神奇数字高达`x`？”

 如果是的话，答案可能会更小。 

如果不是，我们需要一个更大的值。 

这种单调性质使得二分查找成为可能。

 ## 算法演练

 1. 计算最大公约数 (GCD)`a`和`b`。 

需要最小公倍数才能正确计算重叠倍数。 我们使用以下方法计算它：$\mathrm{lcm}(a,b)=\frac{a\times b}{\gcd(a,b)}$2. 定义二分查找范围。 

最小可能的神奇数字是`min(a, b)`。 

最大可能的答案是`n * min(a, b)`因为即使每个神奇数字只是较小除数的倍数，`n`th 不能超过该值。 
3. 执行二分查找。 

对于中点`mid`,计算有多少个神奇的数字小于或等于`mid`。 

计数公式为：$\left\lfloor\frac{mid}{a}\right\rfloor + \left\lfloor\frac{mid}{b}\right\rfloor - \left\lfloor\frac{mid}{\mathrm{lcm}(a,b)}\right\rfloor$4. 将计数与`n`。 

如果计数至少为`n`， 然后`mid`可能已经是答案了，所以将右边界向左移动。 

否则，还没有足够的魔法数字，因此将左边界向右移动。 
5. 继续直到搜索收敛。 

二分查找停止时`left == right`。 至此，我们已经找到了至少包含的最小数`n`神奇的数字，这一定是`n`神奇的数字。 
6. 返回模数答案`10^9 + 7`。 

### 为什么它有效

 正确性依赖于计数函数的单调性。 

作为`x`增加，神奇数字的数量小于或等于`x`永远不会减少。 因此，存在一个最小值`x`使得计数至少为`n`。 

二分查找可以有效地定位这个边界。 

包含-排除公式保证重叠倍数只计算一次，确保计数准确。 

## Python 解决方案```python
class Solution:
    def nthMagicalNumber(self, n: int, a: int, b: int) -> int:
        MOD = 10**9 + 7

        def gcd(x: int, y: int) -> int:
            while y:
                x, y = y, x % y
            return x

        lcm = (a * b) // gcd(a, b)

        left = min(a, b)
        right = n * min(a, b)

        while left < right:
            mid = (left + right) // 2

            count = (
                mid // a +
                mid // b -
                mid // lcm
            )

            if count >= n:
                right = mid
            else:
                left = mid + 1

        return left % MOD
```该实现首先定义一个用于计算最大公约数的辅助函数。 这用于安全有效地计算最小公倍数。 

接下来，初始化二分搜索范围。 下界是较小的除数，因为第一个神奇数字不能小于该除数。 上限是`n * min(a, b)`。 

在二分搜索循环内，计算中点。 该代码计算最多存在多少个神奇数字`mid`使用包含-排除。 

如果存在足够的神奇数字，算法会将搜索范围缩小到左半部分，因为我们想要最小的有效值。 否则，它将搜索右半部分。 

搜索完成后，`left`包含准确的`n`第一个神奇的数字。 模运算仅在最后应用，以在二分搜索计算期间保持正确性。 

## 解决方案```go
func nthMagicalNumber(n int, a int, b int) int {
    const MOD int = 1_000_000_007

    gcd := func(x int, y int) int {
        for y != 0 {
            x, y = y, x%y
        }
        return x
    }

    lcm := (a * b) / gcd(a, b)

    left := min(a, b)
    right := n * min(a, b)

    for left < right {
        mid := left + (right-left)/2

        count := mid/a + mid/b - mid/lcm

        if count >= n {
            right = mid
        } else {
            left = mid + 1
        }
    }

    return left % MOD
}

func min(x int, y int) int {
    if x < y {
        return x
    }
    return y
}
```Go 实现遵循与 Python 版本相同的逻辑，但有一些特定于语言的注意事项。 

Go 不包含内置的`min`整数函数，因此我们手动定义一个。 

二分查找中点的计算方法为：```go
mid := left + (right-left)/2
```此模式避免了具有固定整数大小的语言中潜在的溢出。 

在现代 LeetCode 环境中，Go 整数足够大来解决这个问题，但使用仔细的算术仍然是很好的做法。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`a == b`。 在这种情况下，每个神奇数字只是该单个值的倍数。 有缺陷的实现可能会重复计算每个数字，因为它同时添加了两个数字`mid // a`和`mid // b`。 使用 LCM 的包含-排除减法会自动修复此问题，因为 LCM 等于除数本身。 

当一个除数是另一个除数的倍数时，会发生另一种棘手的情况，例如`a = 2`和`b = 4`。 许多数字同时属于这两组倍数。 如果不减去 LCM 的倍数，计数就会膨胀，二分查找就会收敛到错误的答案。 该公式确保每个神奇数字都被精确计算一次。 

大值`n`造成另一个潜在问题。 答案可能超出 32 位整数限制。 例如，`n = 10^9`和`a = 40000`产生周围的价值`4 * 10^13`。 如果计算处理不仔细，具有固定宽度整数的语言可能会溢出。 该实现通过使用足够大的整数类型来安全地存储中间值来避免这种情况。 

最后的边缘情况涉及模运算。 在二分搜索期间应用模会破坏正确性所需的排序关系。 该实现仅在找到确切答案后才应用模数，从而保持搜索过程的完整性。
