[LeetCode 811 题](https://leetcode.com/problems/subdomain-visit-count/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到一个字符串列表，其中每个字符串代表与域名配对的访问计数。 每个输入条目的形式如下：```
"count domain"
```例如：```
"9001 discuss.leetcode.com"
```表示域`discuss.leetcode.com`被访问过`9001`次。 

重要的细节是，访问某个域也算作访问其所有父子域。 对于域：```
discuss.leetcode.com
```以下域被视为已访问：```
discuss.leetcode.com
leetcode.com
com
```因此，必须将访问计数添加到从原始域生成的每个子域中。 

任务是计算每个可能的子域的访问总数，并以相同的方式返回它们`"count domain"`格式。 输出顺序并不重要。 

输入尺寸相对较小：

 - 最多 100 个域名条目
 - 每个字符串长度最多100个字符

 这些限制告诉我们，性能要求并不高。 即使效率较低的字符串操作仍然可以顺利进行。 然而，我们仍然需要一个干净且可扩展的解决方案。 

一个关键的观察结果是，每个域最多包含三个部分，因为约束指定了如下格式：```
d1.d2
d1.d2.d3
```这意味着每个输入仅生成少量子域。 

有几个重要的边缘情况需要考虑：

 - 多个域可以贡献于同一个子域，例如`google.mail.com`和`intel.mail.com`两者都有助于`mail.com`- 域名可能已经是顶级域名，例如`com`- 计数可以在多个条目中累积
 - 输出顺序是任意的，所以我们不应该依赖排序

 该问题保证了有效的格式，因此我们不需要处理格式错误的输入。 

## 方法

 ### 蛮力方法

 强力解决方案将为每个输入域显式生成每个可能的子域，然后重复扫描整个结果集以合并计数。 

例如，给定：```
"900 google.mail.com"
```我们生成：```
google.mail.com
mail.com
com
```然后，对于每个生成的子域，我们搜索先前存储的结果以确定它是否已经存在。 如果是，我们会更新其计数。 否则，我们插入一个新条目。 

这种方法是正确的，因为每个有效的子域都会生成，并且每个计数都会正确累积。 然而，重复的线性搜索使其效率低下。 

如果有`N`输入域和`K`生成的子域总数，重复搜索现有结果可能会导致二次行为。 

### 最佳方法

 关键的见解是这个问题本质上是一个计数问题。 

每当我们需要按键累积频率时，哈希图就是自然的数据结构。 我们可以直接以恒定的平均时间更新计数，而不是重复扫描现有结果。 

对于每个输入字符串：

 1.将其拆分为计数和域。 
2. 生成各个后缀子域名。 
3. 将计数添加到哈希映射中的该子域。 

例如：```
google.mail.com
```产生：```
google.mail.com
mail.com
com
```其中每一个都成为哈希映射中的键。 

处理完所有条目后，我们将哈希图转换回所需的输出格式。 

由于每个域最多具有三个组件，因此每个输入的工作量非常小。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(K) | 重复搜索累积结果|
 | 最佳 | O(N × L) | O(K) | 使用哈希图进行直接频率累积 |

 这里：

-`N`是输入域的数量
 -`L`是域段的数量
 -`K`是唯一子域的数量

 自从`L`在这个问题中非常小，最优解实际上是线性的。 

## 算法演练

 1. 创建一个哈希映射来存储每个子域的访问计数。 

键是子域字符串，值是累计访问次数。 
2. 遍历每个条目`cpdomains`。 

每个字符串包含一个计数和一个由空格分隔的域。 
3. 将绳子分成两部分。 

例如：```
"900 google.mail.com"
```变成：```
count = 900
domain = "google.mail.com"
```4. 分割域`"."`。 

例子：```
["google", "mail", "com"]
```5. 生成每个有效的子域。 

从每个位置开始，连接剩余的组件：

 -`"google.mail.com"`-`"mail.com"`-`"com"`6. 将访问计数添加到哈希映射中的每个生成的子域。 

这会自动合并来自共享同一父域的不同域的计数。 
7. 处理完所有输入后，迭代哈希映射。 

将每个键值对转换为所需的格式：```
"count domain"
```8. 返回结果列表。 

### 为什么它有效

 该算法之所以有效，是因为对域的每次访问都必然意味着对所有后缀子域的访问。 通过显式生成所有后缀并将访问计数添加到每个后缀，我们确保每次隐含访问都被精确计数一次。 

哈希映射保证来自多个域的计数对于共享子域正确累积。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def subdomainVisits(self, cpdomains: List[str]) -> List[str]:
        visit_counts = defaultdict(int)

        for entry in cpdomains:
            count_str, domain = entry.split()
            count = int(count_str)

            parts = domain.split(".")

            for i in range(len(parts)):
                subdomain = ".".join(parts[i:])
                visit_counts[subdomain] += count

        result = []

        for domain, count in visit_counts.items():
            result.append(f"{count} {domain}")

        return result
```实施首先创建一个`defaultdict(int)`这样丢失的键就会自动从零开始。 这简化了计数逻辑，因为我们可以直接递增计数，而无需检查键是否已存在。 

对于每个输入字符串，我们将其分为数字计数和域名。 将计数转换为整数以进行算术运算。 

接下来，我们使用以下方法将域拆分为其组件`"."`。 通过迭代每个起始索引，我们使用以下命令生成所有后缀子域`".".join(parts[i:])`。 

每个生成的子域都会接收哈希映射中的当前访问计数。 

最后，我们迭代哈希映射并构造所需的输出字符串`"count domain"`格式。 

## 解决方案```go
package main

import (
	"fmt"
	"strconv"
	"strings"
)

func subdomainVisits(cpdomains []string) []string {
	visitCounts := make(map[string]int)

	for _, entry := range cpdomains {
		parts := strings.Split(entry, " ")

		count, _ := strconv.Atoi(parts[0])
		domain := parts[1]

		domainParts := strings.Split(domain, ".")

		for i := 0; i < len(domainParts); i++ {
			subdomain := strings.Join(domainParts[i:], ".")
			visitCounts[subdomain] += count
		}
	}

	result := []string{}

	for domain, count := range visitCounts {
		result = append(result, fmt.Sprintf("%d %s", count, domain))
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[string]int`使用而不是 Python 字典。 字符串分割的处理方式是`strings.Split`，整数转换使用`strconv.Atoi`。 

与Python不同`defaultdict`，Go 映射对于缺失的键返回零值，因此增加不存在的条目自然有效。 

输出切片是使用动态构建的`append`。

 ## 边缘情况

 ### 共享同一个父域的多个域

 错误的一个常见来源是无法正确累积来自共享父子域的不同域的计数。 

例如：```
"900 google.mail.com"
"1 intel.mail.com"
```两者都有助于`mail.com`和`com`。 

幼稚的实现可能会覆盖计数而不是添加它们。 使用具有增量更新的哈希图可确保正确累积计数。 

### 只有一个段的域

 像这样的域：```
"10 com"
```已经代表顶级域名。 

某些实现错误地假设每个域都包含点，并且可能会尝试无效的切片操作。 这个实现自然地处理这种情况，因为分裂`"com"`生成一个单元素列表，并且循环恰好生成一个子域。 

### 重复精确的域条目

 相同的域可能会在输入中出现多次：```
"3 x.y.com"
"7 x.y.com"
```该算法必须将两次出现的情况合并为一个总数。 

因为每个生成的子域都存储在哈希映射中并用`+=`，重复的域可以正确累积，无需任何额外处理。
