[LeetCode 第 838 题](https://leetcode.com/problems/push-dominoes/)

 **难度：** 🟡 中等
 **主题：** 两个指针、字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题模拟了倒下的多米诺骨牌的连锁反应。 我们得到一个字符串，其中每个字符代表一行多米诺骨牌的初始状态。 

多米诺骨牌可以处于以下三种状态之一：

 -`'L'`意味着多米诺骨牌已被推向左侧。 
-`'R'`意味着多米诺骨牌已被推到右侧。 
-`'.'`表示多米诺骨牌直立，尚未被推动。 

重要的细节是，所有最初推动的多米诺骨牌同时开始移动。 每一秒，倒下的多米诺骨牌都会将力沿运动方向传递到相邻的多米诺骨牌。 向左倒下的多米诺骨牌会将多米诺骨牌立即推向左侧，向右倒下的多米诺骨牌会立即将多米诺骨牌推向右侧。 

然而，如果站立的多米诺骨牌同时受到来自两个方向的相等力，则力会抵消，多米诺骨牌保持直立。 

目标是计算所有运动停止后的最终稳定排列。 

例如：```
Input: ".L.R...LR..L.."
```一些多米诺骨牌立即倒下，另一些则随后受到连锁反应的影响，还有一些因为相反的力量相互平衡而保持站立。 最终输出变为：```
"LL.RR.LLRRLL.."
```约束告诉我们字符串长度可以大到`10^5`。 这很重要，因为它排除了每秒重复更新多米诺骨牌的低效模拟方法。 具有二次复杂度的算法可能会超时。 我们需要接近线性时间的东西。 

一些边缘情况很容易破坏简单的实现：

 - 根本没有力量的多米诺骨牌，例如`"..."`，应保持不变。 
- 向同一方向连续推动，例如`"R...."`，应该一路传播。 
- 反对推动像`"R...L"`需要小心处理，因为中间的多米诺骨牌可能会保持平衡。 
- 等距离碰撞，例如`"R.L"`，如果力量同时相遇，必须保留中心多米诺骨牌。 
- 前导点或尾随点，例如`"...L"`或者`"R..."`，需要特殊处理，因为力仅来自一侧。 

## 方法

 ### 暴力模拟

 一个简单的想法是逐秒模拟多米诺骨牌。 

在每个时间步，我们扫描该行并根据其邻居确定接下来会倒下的多米诺骨牌。 由于所有更改同时发生，因此我们必须将更新计算到临时结构中，而不是就地修改行。 

例如，如果多米诺骨牌仅从左侧受到力，它就会变成`'R'`。 如果它只受到右侧的力，它就会变成`'L'`。 如果它同时受到两侧的力，它就会保持直立。 

我们重复这个过程，直到没有多米诺骨牌改变状态。 

这种方法是正确的，因为它直接遵循问题的规则。 然而，它的效率很低。 在最坏的情况下，力可能每秒在整行上传播一张多米诺骨牌，并且每次迭代都会扫描所有`n`骨牌。 这导致了二次复杂度。 

### 最佳解决方案的关键见解

 我们可以考虑**已确定的多米诺骨牌之间的力量**，而不是模拟每一秒。 

关键的观察结果是，只有最近的非点多米诺骨牌才重要。 

考虑力源之间的分段：```
R.....R
```两端都向右推，所以中间的每张多米诺骨牌都变成了`'R'`。```
L.....L
```两端向左推，所以一切都变成`'L'`。```
L.....R
```这些力彼此远离，因此没有任何变化。```
R.....L
```力量相互靠近。 多米诺骨牌更接近`R`向右倒下，多米诺骨牌更接近`L`如果间隙长度为奇数，则向左倒下，中间的多米诺骨牌保持直立。 

我们可以通过处理字符串`'L'`和`'R'`作为边界并一次性解决它们之间的部分。 

一个常见的技巧是添加**虚拟边界**：

 - 添加虚拟`'L'`在字符串之前。 
- 添加虚拟`'R'`在字符串之后。 

这消除了前缀和后缀的边缘情况处理。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 我们将使用两指针方法来处理有意义的多米诺骨牌之间的片段。 

1. 将输入字符串转换为字符列表，以便高效修改。 
2.概念上添加虚拟边界：

 - 将左侧视为有一个`'L'`索引之前`0`。 
- Treat the right side as if there is an`'R'`在最后一个索引之后。 

这可以防止前缀和后缀的特殊逻辑。 
3. 扫描多米诺骨牌并识别每个非点字符 (`'L'`或者`'R'`）。 
4. 使用指针跟踪先前的力源`left`。 
5. 每当发现另一个力源时`right`，解析之间的段`left`和`right`。 

有四种可能的情况：

 **情况1：相同方向**

 如果两个边界都是`'L'`或者两者都是`'R'`，中间的每张多米诺骨牌都朝同一方向倒下。 

例子：```
R....R
```变成：```
RRRRRR
```因为力量不断地传播。 

**情况 2：左边界是`'L'`右边界是`'R'`**

例子：```
L....R
```力向外移动，因此中间的多米诺骨牌永远不会受到任何力。 

无需更改。 

**情况 3：左边界是`'R'`右边界是`'L'`**

例子：```
R.....L
```力量相互靠近。 

对称地填充多米诺骨牌：

 - 左侧变为`'R'`- 右侧变为`'L'`- 当指针相遇时停止

 如果它们之间的多米诺骨牌数量为奇数，则中心保持直立。 
6. 更新`left`将指针指向当前力源并继续扫描。 
7. 将修改后的字符列表转换回字符串。 

### 为什么它有效

 该算法之所以有效，是因为每张多米诺骨牌的最终状态仅取决于来自左侧和右侧的最近的力。 通过处理连续的非点多米诺骨牌之间的间隔，我们可以一次完全确定每个未定多米诺骨牌的结果。 由于间隔不重叠，并且每种情况都根据力传播的物理规则来解决，因此保证了所得配置的正确性。 

## Python 解决方案```python
class Solution:
    def pushDominoes(self, dominoes: str) -> str:
        chars = ['L'] + list(dominoes) + ['R']
        left = 0

        for right in range(1, len(chars)):
            if chars[right] == '.':
                continue

            if right - left > 1:
                if chars[left] == chars[right]:
                    for i in range(left + 1, right):
                        chars[i] = chars[left]

                elif chars[left] == 'R' and chars[right] == 'L':
                    l = left + 1
                    r = right - 1

                    while l < r:
                        chars[l] = 'R'
                        chars[r] = 'L'
                        l += 1
                        r -= 1

            left = right

        return ''.join(chars[1:-1])
```该实现首先创建一个可变的字符列表并插入虚拟边界。 我们前置`'L'`并附加`'R'`，这简化了边缘处的多米诺骨牌处理。 

变量`left`存储前一个力源的索引。 然后我们迭代使用`right`定位下一个非点多米诺骨牌。 

每当找到有效的边界对时，我们就会解析它们之间的线段。 如果两个方向匹配，则整个间隔将充满相同的力。 如果区间的边界为`'R'`和`'L'`，我们用两个向内移动的指针来赋值`'R'`和`'L'`对称地。 

最后，我们删除人为边界并重建字符串。 

## 解决方案```go
func pushDominoes(dominoes string) string {
	chars := make([]byte, 0, len(dominoes)+2)
	chars = append(chars, 'L')
	chars = append(chars, []byte(dominoes)...)
	chars = append(chars, 'R')

	left := 0

	for right := 1; right < len(chars); right++ {
		if chars[right] == '.' {
			continue
		}

		if right-left > 1 {
			if chars[left] == chars[right] {
				for i := left + 1; i < right; i++ {
					chars[i] = chars[left]
				}
			} else if chars[left] == 'R' && chars[right] == 'L' {
				l, r := left+1, right-1

				for l < r {
					chars[l] = 'R'
					chars[r] = 'L'
					l++
					r--
				}
			}
		}

		left = right
	}

	return string(chars[1 : len(chars)-1])
}
```Go 解决方案遵循与 Python 实现完全相同的逻辑。 由于 Go 字符串是不可变的，我们将输入转换为可变的`[]byte`片。 这允许就地修改多米诺骨牌状态。 

与 Python 列表不同，Go 切片需要显式构造和附加。 否则，算法保持不变。 整数溢出不是问题，因为索引仍然受`10^5`。

 ## 边缘情况

 ### 敌对势力之间的平衡碰撞

 输入如下：```
"R.L"
```很容易处理不当，因为中间的多米诺骨牌同时受到两侧的力。 幼稚的实现可能会意外偏向某个方向。 我们的实现正确地处理了这个问题，因为向内的两指针循环仅在 while 时执行`l < r`。 当指针在中心相遇时，多米诺骨牌仍然存在`'.'`。 

### 无外力

 输入例如：```
"...."
```不包含`'L'`或者`'R'`根本不。 由于没有力源，多米诺骨牌永远不会移动。 哨兵边界确保算法仍然自然地工作，并且间隔分辨率不会改变任何字符。 

### 前导和尾随多米诺骨牌链

 案例如下：```
"R...."
```或者```
"....L"
```可能会出现问题，因为力仅从一侧传播。 如果没有仔细的边界处理，实现常常会错过这些部分。 虚拟的`'L'`在前面和`'R'`后面通过将边缘段转换为与字符串中间相同逻辑处理的普通区间，优雅地解决了这个问题。
