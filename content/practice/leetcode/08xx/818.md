 # LeetCode 818 - 赛车

 ## 问题理解

 这个问题要求我们控制一辆在无限一维数轴上移动的汽车。 汽车在指定位置启动`0`与速度`+1`。 我们可以发出两种指令：

 -`"A"`为了加速
 -`"R"`用于反向

 的`"A"`指令使小车按照当前速度向前移动，然后将速度加倍。 如果当前速度为负值，则汽车向后移动，速度大小加倍。 

这`"R"`指令根本不会移动汽车。 相反，它会重置速度方向：

 - 正速度变为`-1`- 负速度变为`+1`目标是使用尽可能少的指令精确到达目标位置。 

例如，如果目标是`3`，序列`"AA"`作品：

 - 开始于`(position=0, speed=1)`- 第一的`"A"`→`(1, 2)`- 第二`"A"`→`(3, 4)`因此答案是`2`。 

约束条件很重要：

 -`1 <= target <= 10^4`达到一万的目标已经足够大，以至于简单的暴力探索变得不切实际。 我们需要一种解决方案，避免盲目探索每个可能的指令序列。 

一个重要的观察结果是，重复加速会产生以下形式的位置：$$1, 3, 7, 15, 31, ...$$这些都是：$$2^k - 1$$后`k`连续加速。 

一些边缘情况使这个问题变得棘手：

 - 目标可能已经精确地位于仅通过加速度即可到达的位置。 
- 最佳路径可能会超出目标并返回。 
- 最佳路径可能会在目标之前停下来，倒转，稍微原路返回，然后再次继续前进。 
- 搜索空间包括负位置和交替方向，它们可能在朴素解决方案中组合爆炸。 

由于这些行为，简单的贪婪策略无法可靠地发挥作用。 

## 方法

 ### 蛮力方法

 最直接的想法是将问题建模为图搜索问题。 

每个状态由：

 - 当前位置
 - 当前速度

 从每个状态，我们可以生成两个下一个状态：

 - 申请`"A"`- 申请`"R"`我们可以运行广度优先搜索，因为每条指令只花费一步。 BFS 保证我们第一次到达目标的时间是最短序列。 

这种方法是正确的，因为 BFS 按指令计数递增的顺序探索状态。 

然而，状态空间增长得非常快。 由于重复加倍，位置和速度可能变得非常大。 即使进行修剪，可达状态的数量也会变得巨大。 

对于附近的目标`10^4`，强力 BFS 变得低效。 

### 最优动态规划方法

 关键的见解是加速创造了非常结构化的运动模式。 

后`k`加速度：$$position = 2^k - 1$$这意味着我们可以用二的幂来思考。 

对于任何目标：

 - 要么我们仅使用加速度来准确地达到目标
 - 或者我们超越它并反转
 - 或者我们在它前面停下来，短暂倒车，然后继续

 这自然会导致动态规划。 

定义：$$dp[t]$$作为达到目标所需的最少指令`t`。 

对于每个目标，我们计算最小的`k`这样：$$2^k - 1 \ge t$$然后我们考虑两种可能性：

 1. 超越目标并反向返回
 2. 在目标前停下来，倒车一段距离，然后再向前行驶

 因为每个子问题都涉及较小的目标，所以记忆或自下而上的 DP 可以有效地工作。

 ## 算法演练

 ### 第 1 步：定义 DP 状态

 让`dp[t]`表示到达位置所需的最少指令数`t`。 

我们想要计算：$$dp[target]$$### 步骤 2：找到最小的超调功率

 对于给定的目标`t`，确定最小加速次数`k`这样：$$2^k - 1 \ge t$$这对应于加速`k`连续次数。 

结果位置是：$$full = 2^k - 1$$### 步骤 3：处理精确匹配

 如果：$$full = t$$那么我们可以直接达到目标`k`加速度。 

所以：$$dp[t] = k$$### 步骤 4：考虑超调

 如果`full > t`，我们可以：

 1. 加速`k`次
 2.反转一次
 3. 递归求解剩余距离

 剩余距离变为：$$full - t$$指令数为：$$k + 1 + dp[full - t]$$在哪里：

-`k`加速指令
 -`1`反向指令

 ### 步骤 5：考虑在目标之前停下来

 我们可以停在：$$2^{k-1} - 1$$然后：

 1. 反转
 2. 向后移动`m`加速度
 3.再次反转
 4. 继续朝着目标前进

 之后向后移动`m`加速度涵盖：$$2^m - 1$$剩余前进距离变为：$$t - (2^{k-1} - 1) + (2^m - 1)$$总的指令是：$$(k - 1) + 1 + m + 1 + dp[\text{remaining}]$$我们尝试所有有效的`m`值并取最小值。 

### 第 6 步：记住结果

 由于许多子问题重复，记忆可以避免重新计算。 

这大大降低了复杂性。 

### 为什么它有效

 该算法之所以有效，是因为每个最佳序列最终都必须落入以下两类之一：

 - 超越目标并反向
 - 在目标之前停止，部分原路返回，然后继续

 DP 递归详尽地考虑了这两种可能性。 由于每个递归调用解决一个严格较小的目标，因此记忆保证了高效计算和最优性。 

## Python 解决方案```python
class Solution:
    def racecar(self, target: int) -> int:
        memo = {0: 0}

        def dp(t: int) -> int:
            if t in memo:
                return memo[t]

            k = t.bit_length()
            full_distance = (1 << k) - 1

            # Exact match
            if full_distance == t:
                memo[t] = k
                return k

            # Case 1: Overshoot and reverse
            result = k + 1 + dp(full_distance - t)

            # Case 2: Stop before target, reverse, backtrack, reverse again
            partial_distance = (1 << (k - 1)) - 1

            for m in range(k - 1):
                backward_distance = (1 << m) - 1

                remaining = (
                    t
                    - partial_distance
                    + backward_distance
                )

                instructions = (
                    (k - 1)     # forward accelerations
                    + 1         # reverse
                    + m         # backward accelerations
                    + 1         # reverse again
                    + dp(remaining)
                )

                result = min(result, instructions)

            memo[t] = result
            return result

        return dp(target)
```该实现使用自上而下的记忆动态编程。 

这`memo`字典存储先前计算的答案。 这可以防止重叠子问题的指数重新计算。 

表达式：```python
t.bit_length()
```计算最小的`k`这样：$$2^k > t$$这有助于确定达到或超过目标的第一个加速序列。 

变量`full_distance`表示之后到达的位置`k`加速度：```python
(1 << k) - 1
```如果这恰好等于目标，那么答案很简单`k`。 

否则，代码将评估两个重复选项：

 - 超调和反转
 - 提早停止、倒转、部分原路返回，然后继续

 循环结束`m`在再次向前转向之前探索每一个可能的向后加速度计数。 

最后，存储并返回最小结果。 

## 解决方案```go
package main

func racecar(target int) int {
	memo := map[int]int{
		0: 0,
	}

	var dp func(int) int

	dp = func(t int) int {
		if val, exists := memo[t]; exists {
			return val
		}

		k := 0
		for (1<<k)-1 < t {
			k++
		}

		fullDistance := (1 << k) - 1

		// Exact match
		if fullDistance == t {
			memo[t] = k
			return k
		}

		// Case 1: Overshoot and reverse
		result := k + 1 + dp(fullDistance-t)

		partialDistance := (1 << (k - 1)) - 1

		// Case 2: Stop before target
		for m := 0; m < k-1; m++ {
			backwardDistance := (1 << m) - 1

			remaining := t - partialDistance + backwardDistance

			instructions :=
				(k - 1) +
					1 +
					m +
					1 +
					dp(remaining)

			if instructions < result {
				result = instructions
			}
		}

		memo[t] = result
		return result
	}

	return dp(target)
}
```Go 实现遵循与 Python 版本相同的递归结构。 

由于 Go 不提供 Python 的`bit_length()`方法，我们计算`k`手动使用循环。 

记忆表使用`map[int]int`。 Go 中的递归闭包需要在分配实现之前声明函数变量。 

整数溢出不是问题，因为目标约束只是`10^4`，并且所有中间值都安全地保持在 Go 的整数范围内。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(目标日志目标) | 每个目标最多探索对数个转变 |

 ## 边缘情况

 当目标恰好具有以下形式时，就会出现一种重要的边缘情况：$$2^k - 1$$例子包括`1`,`3`,`7`,`15`， 和`31`。 仅使用加速度即可到达这些位置，无需任何反转。 有缺陷的实现可能仍然会尝试不必要的递归转换。 该解决方案通过检查立即处理该案例：```
if full_distance == t:
```并返回`k`直接地。 

当超调达到最佳状态时，会发生另一个重要的边缘情况。 例如，目标`6`通过达到最有效地解决`7`首先，然后反转一次。 试图避免超调的贪婪方法在这里常常会失败。 DP 递归明确评估超调场景并保证它被考虑。 

第三个棘手的边缘情况涉及部分回溯。 解决某些目标的最佳方法是在目标之前停下来，短暂倒车，然后再次继续前进。 例如，某些中程目标需要加速和反转的仔细平衡组合。 所有可能的向后加速计数的循环确保正确评估每个此类策略。 

最后，附近的大目标`10^4`强调低效的递归和重复的重新计算。 如果没有记忆，递归结构将呈指数级增长。 备忘录表保证每个子问题都解决一次，从而使运行时在问题约束内保持可控。
