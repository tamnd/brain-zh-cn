[LeetCode 830 题](https://leetcode.com/problems/positions-of-large-groups/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们识别给定字符串中的所有**大组**，并将它们的位置作为间隔返回。 

**组**是一系列连续的相同字符。 例如，在字符串中`abbxxxxzzy`，这些组是：

 -`"a"`-`"bb"`-`"xxxx"`-`"zz"`-`"y"`每个组都可以由其**起始索引**和**结束索引**（含）来表示。 例如，`"xxxx"`从索引开始`3`并以索引结束`6`，所以它的区间是`[3,6]`。 

如果一个组包含**至少 3 个连续的相同字符**，则该组被视为**大**。 我们的目标是扫描字符串并返回所有此类间隔，按增加的起始索引排序。 

输入是单个字符串`s`仅由小写英文字母组成。 输出是一个间隔列表，其中每个间隔代表一个大组。 

限制相对较小：

 -`1 <= s.length <= 1000`- 只出现小写英文字母

 由于输入量很小，即使效率较低的方法在技术上也可以工作。 然而，这个问题自然需要一个简单且最优的线性时间解决方案。 

预先识别一些边缘情况很重要。 字符串可能根本不包含大组，例如`"abc"`。 一大组可能出现在字符串的开头或末尾，这可能会暴露出差一错误。 整个字符串可能由单个重复字符组成，例如`"aaaaa"`，这意味着我们必须正确识别涵盖整个指数范围的组。 另一个微妙的情况是当多个大群体连续出现时，需要仔细跟踪边界。 

## 方法

 ### 蛮力方法

 强力解决方案将检查每个可能的子串并确定它是否形成有效的大组。 

对于每个起始位置，我们可以在字符保持不变的情况下向外扩展并测量组长度。 识别出一个组后，我们将检查其大小是否至少为`3`并在必要时附加其间隔。 

尽管这种方法在限制范围内仍然有效，但它可能会多次重复检查相同的字符。 在最坏的情况下，例如具有重复字符的字符串，嵌套扫描可能会带来不必要的开销。 

蛮力方法是正确的，因为每个可能的连续组都会被明确检查，确保不会遗漏任何大组。 然而，它的效率很低，因为重复的比较是多余的。 

### 最佳方法，单通道两指针扫描

 关键的观察是**组自然是连续的**，这意味着我们在跟踪当前组的边界时只需要遍历字符串一次。 

我们维护一个标记当前组开始的指针，而不是重复地重新扫描字符。 我们继续移动字符串，直到字符发生变化。 那时，我们知道该群体的确切规模，并可以确定它是否符合规模。 

这可以有效地工作，因为每个字符都属于一个组，因此每个字符仅被访问一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描字符串的重叠部分 |
 | 最佳| O(n) | O(1) 不包括输出 | 单次遍历，每个字符处理一次 |

 ## 算法演练

 1. 初始化一个空的结果列表来存储大组的间隔。 
2. 创建变量`start`标记当前组的开始。 最初，这是`0`因为第一个字符开始第一组。 
3.使用索引遍历字符串`i`开始于`1`。 
4. 在每个位置进行比较`s[i]`和`s[i - 1]`。 

- 如果相同，则当前组继续。 
- 如果不同，则前一组已结束。 
5. 当一个组结束时，计算其大小：```
length = i - start
```如果长度至少为`3`, 附加`[start, i - 1]`到结果。 
6. 重置`start = i`开始跟踪下一组。 
7. 完成循环后，单独处理最后一组，因为循环结束时不会触发字符更改。 
8. 计算最后一组的长度。 如果至少是`3`，加上它的区间。 
9. 返回结果列表。 

### 为什么它有效

 该算法保持不变式`start`始终指向当前连续组的开头。 每当角色发生变化时，当前组都是完全已知的，并且可以准确地评估一次。 由于每个字符都属于一个组，并且每个组在结束时都会被精确检查，因此该算法可以正确识别所有大组，而不会丢失或重复任何间隔。 

## Python 解决方案```python
from typing import List

class Solution:
    def largeGroupPositions(self, s: str) -> List[List[int]]:
        result = []
        start = 0

        for i in range(1, len(s)):
            if s[i] != s[i - 1]:
                if i - start >= 3:
                    result.append([start, i - 1])
                start = i

        if len(s) - start >= 3:
            result.append([start, len(s) - 1])

        return result
```实现首先创建一个空的`result`列表并初始化`start`到`0`，代表当前组的开始。 

这`for`循环从索引处迭代字符串`1`向前。 在每一步中，当前字符都会与前一个字符进行比较。 如果字符不同，我们就知道当前组已经结束。 然后我们使用以下方法计算组的长度`i - start`。 如果组长度至少为`3`，我们将其间隔附加到结果中。 

处理完结束组后，`start`更新为`i`，开始一个新的组。 

循环完成后，仍然剩下一个未处理的组，即字符串中的最后一组。 由于最后一个字符之后没有发生字符更改，因此我们在循环后显式检查它，并在足够大时追加它。 

最后返回结果列表。 

## 解决方案```go
func largeGroupPositions(s string) [][]int {
	result := [][]int{}
	start := 0

	for i := 1; i < len(s); i++ {
		if s[i] != s[i-1] {
			if i-start >= 3 {
				result = append(result, []int{start, i - 1})
			}
			start = i
		}
	}

	if len(s)-start >= 3 {
		result = append(result, []int{start, len(s) - 1})
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 整数切片的切片，`[][]int`，用于存储间隔。 

Go 特有的一个细节是切片初始化。 我们初始化`result`作为一个空切片而不是`nil`，尽管两者都可以在 LeetCode 中工作。 附加间隔是使用完成的`append`。 

不用担心整数溢出，因为最大字符串长度仅为`1000`。 Go 中的字符串索引访问字节，这在这里是安全的，因为问题只保证小写英文字母。

 ## 边缘情况

 ### 整个字符串是一个大组

 当整个字符串包含相同的字符时，会出现常见的错误来源，例如`"aaaaa"`。 由于从未发生过字符更改，因此幼稚的实现可能会忘记处理最终组。 该实现通过显式的循环后检查正确处理该问题，产生`[[0,4]]`。 

### 字符串末尾的大组

 类似的情况`"baaa"`很棘手，因为最后一组不会通过字符更改自然终止。 未经最终检查，该小组`"aaa"`可能会被完全错过。 该实现显式评估遍历后的最终段以避免此问题。 

### 不存在大群体

 输入如`"abc"`仅包含大小的组`1`。 粗心的实现可能会由于不正确的比较逻辑或相差一的错误而意外地包含间隔。 此实现仅在组大小至少为`3`，确保正确返回空列表。 

### 恰好处于阈值的组

 一组长度正好`3`， 例如`"aaa"`，必须算大。 使用时经常出现差一错误`>`而不是`>=`。 此实现显式检查`>= 3`，确保阈值案件得到妥善处理。
