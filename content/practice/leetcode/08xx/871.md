[LeetCode 问题 871](https://leetcode.com/problems/minimum-number-of-refueling-stops/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 问题描述了一辆汽车从位置行驶`0`前往位于的目的地`target`数英里之外。 汽车开始于`startFuel`升燃油，每行驶一英里仅消耗一升燃油。 沿途，加油站距离起点越来越远。 

每个加油站表示为：```
stations[i] = [positioni, fueli]
```在哪里：

-`positioni`是车站距起点的距离
 -`fueli`是该站可用的燃油量

 每当汽车到达一个车站时，它可能会选择停下来并从该车站获取所有可用的燃料。 该车的油箱容量实际上是无限的，因此它可以容纳的燃油量没有上限。 

目标是确定到达目的地所需的最少加油站次数。 如果不可能到达目的地，算法必须返回`-1`。 

关键的挑战是选择在哪里加油会影响未来的可达性。 看似局部最优的贪婪选择可能会阻止稍后到达更远的站点。 

约束条件很重要：

 -`stations.length <= 500`- 燃油量和距离可以大到`10^9`500 个站的数量对于二次动态规划来说足够小，但对于指数暴力来说又足够大而不可行。 较大的燃料和距离值也意味着基于各个英里的模拟方法是不可能的。 

一些边缘情况尤其重要：

 - 汽车可能已经有足够的燃料无需停下来即可到达目标。 
- 第一站可能无法到达。 
- 在做出任何加油决定之前，可以到达多个加油站。 
- 准确到达车站或目标`0`燃油仍然有效。 
- 除非精心设计，否则仅基于最近或最大站点的贪婪决策可能会失败。 

## 方法

 ### 蛮力方法

 强力解决方案将探索可能发生加油的所有可能的加油站组合。 

每个车站有两种选择：

 1. 加油
 2. 跳过车站

 这将创建一个决策树。 对于每个站点子集，我们可以模拟汽车是否成功到达目标并计算使用了多少个站点。 在所有有效路径中，我们选择最少的停靠点。 

这种方法是正确的，因为它检查了加油决策的每个可能的顺序。 如果存在有效的解决方案，蛮力最终会找到它。 

然而，时间复杂度是指数级的。 由于站点多达 500 个，探索所有子集变得完全不切实际。 

### 最优贪婪 + 最大堆方法

 关键的见解是我们不需要立即决定是否在加油站加油。 

相反，当我们向前行驶时，我们可以将所有可到达的站点存储在最大堆中。 每当我们在到达下一个位置之前耗尽燃料时，我们就会追溯选择我们已经经过的所有加油站中最大的加油站。 

这种贪婪策略之所以有效，是因为：

 - 如果需要加油，选择燃料最多的加油站可以最大限度地提高未来的可达性。 
- 推迟决策可以保持灵活性。 
- 提前加油永远不会带来优势，因为油箱是无限的。 

该堆有效地跟踪过去可用的最佳加油选项。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试电台的每个子集 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用最大堆的贪婪策略 |

 ## 算法演练

 ### 最优贪心堆算法

 1. 初始化当前可达距离为`startFuel`。 

这代表了汽车目前无需额外加油即可行驶的最远距离。 
2. 创建一个最大堆来存储已经过站点的燃油量。 

蟒蛇的`heapq`是最小堆，因此存储负值以模拟最大堆行为。 
3.初始化：

 -`station_index = 0`-`refuel_stops = 0`4. 当当前可达距离小于目标时：

 我们还没有到达目的地，所以我们可能需要更多的燃料。 
5. 将所有可到达的站点添加到堆中。 

尽管：

-`station_index < len(stations)`-`stations[station_index][0] <= current_fuel`将该站的燃料推入堆中。 

我们用现有的燃料已经可以到达这些站点。 
6.如果此时堆为空，则返回`-1`。 

这意味着：

 - 我们无法达到目标
 - 之前没有可到达的加油站
 7. 从堆中取出最大的燃料量。 

这代表了之前经过的最佳加油站。 
8. 将燃料添加到当前可到达的距离。 

这延长了汽车的行驶距离。 
9. 增加加油停止次数。 
10. 重复此操作，直到可以到达目标。 
11. 返回加油站总数。 

### 为什么它有效

 该算法保持了这样的不变性：使用迄今为止积累的燃料可以到达当前堆中的所有站。 

每当需要额外燃料时，选择燃料最多的加油站可以最大程度地延长覆盖范围。 任何较小的选择只能减少未来的选择，而永远不会增加停靠站的数量。 

由于加油决策被推迟到绝对必要时，该算法保留了最大的灵活性，同时始终做出局部最优选择。 这种贪婪策略可以通过交换论证来证明是最优的：任何最优解决方案都可以转化为每当需要加油时总是使用最大的可用加油站的解决方案。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minRefuelStops(
        self,
        target: int,
        startFuel: int,
        stations: List[List[int]]
    ) -> int:

        max_heap = []
        current_reach = startFuel
        station_index = 0
        refuel_stops = 0

        while current_reach < target:

            while (
                station_index < len(stations)
                and stations[station_index][0] <= current_reach
            ):
                fuel = stations[station_index][1]
                heapq.heappush(max_heap, -fuel)
                station_index += 1

            if not max_heap:
                return -1

            current_reach += -heapq.heappop(max_heap)
            refuel_stops += 1

        return refuel_stops
```该实现首先初始化一个最大堆，该堆存储来自可到达站点的燃料量。 自从Python的`heapq`仅支持最小堆，负值将被推入堆中。`current_reach`跟踪当前燃料供应可到达的最远距离。 最初，这等于`startFuel`。 

外循环继续进行，直到目的地可达。 在循环内，所有位置小于或等于`current_reach`被添加到堆中。 这意味着它们可以作为未来的加油候选者。 

如果堆中没有可用的站点并且尚未到达目标，则旅程是不可能的，因此算法返回`-1`。 

否则，算法会通过从堆中弹出来贪婪地选择燃油量最大的加油站。 该燃料被添加到`current_reach`，并且加油计数器递增。 

最终，要么目标变得可达，要么算法确定不存在有效路径。 

## 解决方案```go
package main

import (
	"container/heap"
)

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

func minRefuelStops(target int, startFuel int, stations [][]int) int {
	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	currentReach := startFuel
	stationIndex := 0
	refuelStops := 0

	for currentReach < target {

		for stationIndex < len(stations) &&
			stations[stationIndex][0] <= currentReach {

			heap.Push(maxHeap, stations[stationIndex][1])
			stationIndex++
		}

		if maxHeap.Len() == 0 {
			return -1
		}

		currentReach += heap.Pop(maxHeap).(int)
		refuelStops++
	}

	return refuelStops
}
```Go 解决方案使用`container/heap`包，需要手动实现堆接口。 

与 Python 不同，Go 不提供内置的最大堆，因此`Less`函数被反转以创建最大堆行为。 

Go 切片自然地处理动态调整大小，使它们适合堆存储。 由于燃料值可以达到`10^9`， 标准`int`在 LeetCode 的 64 位运行时上仍然安全。

 ## 边缘情况

 当汽车已经有足够的燃料来到达目标时，就会出现一种重要的边缘情况。 幼稚的实现可能仍然会尝试不必要的堆操作或站处理。 当前的实现自然地处理了这个问题，因为主循环只执行 while`current_reach < target`。 

当第一个加油站无法到达时，会发生另一个关键的边缘情况。 在这种情况下，没有站可以添加到堆中，并且算法必须正确返回`-1`。 堆空性检查保证了这种行为。 

一个微妙的边缘情况是到达一个加油站时剩余燃料恰好为零。 一些不正确的实现将此视为失败。 然而，该问题明确允许以零燃料加油。 条件：```
stations[station_index][0] <= current_reach
```正确包括准确到达的车站。 

当需要加油之前可以到达多个加油站时，就会出现另一种棘手的情况。 立即在第一个可用加油站加油的贪婪实现可能会产生非最佳答案。 基于堆的策略通过延迟决策直到实际需要燃料来避免这种情况，从而保留选择先前可到达的最大站点的能力。
