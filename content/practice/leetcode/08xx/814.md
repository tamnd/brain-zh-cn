 # LeetCode 814 - 二叉树修剪

 ## 问题理解

 该问题要求我们通过删除不包含至少一个具有值的节点的每个子树来修改二叉树`1`。 

子树由一个节点及其所有后代组成。 如果整个子树只包含`0`值，那么应该从树中删除该子树。 最终结果应保留满足以下任一条件的所有节点：

 - 有价值`1`, 或
 - 拥有至少一名有价值的后代`1`输入是二叉树的根节点。 每个节点包含`0`或者`1`。 输出应该是删除所有无效子树后修剪树的根。 

限制比较小，最多200个节点。 这意味着即使优化程度较低的方法在技术上也可以通过，但问题的结构强烈建议递归深度优先遍历，因为是否删除节点的决定取决于来自其子节点的信息。 

最重要的观察是，一个节点是否应该保留在树中完全取决于它的后代。 具体来说：

 - 如果左子树和右子树都被删除，
 - 当前节点的值为`0`,
 - 那么当前节点也必须被删除。 

这种依赖性意味着我们无法在处理子节点之前正确处理节点。 这自然会导致后序遍历，即子级在父级之前处理。 

一些边缘情况很重要：

 - 整个树可能只包含零，在这种情况下答案应该是`null`。 
- 具有值的叶节点`0`应始终删除。 
- 具有价值的节点`0`如果它有有价值的后代，则必须保留`1`。 
- 树可能已经满足条件并且不需要修剪。 

## 方法

 ### 蛮力方法

 暴力解决方案将重复扫描树以查找可移动的子树。 对于每个节点，我们可以执行另一次遍历来确定其子树是否包含`1`。 

例如，我们可能：

 1. 遍历树中的每个节点。 
2. 对于每个节点，递归检查其子树是否包含`1`。 
3. 如果没有则删除子树`1`存在。 
4. 重复直到不再发生任何变化。 

这种方法是正确的，因为每个子树都被显式检查。 然而，它执行了多余的工作。 在重复的包含检查期间，同一子树可能会被扫描多次。 

在最坏的情况下，每个节点都可能触发对树的大部分的另一次遍历，从而导致二次复杂度。 

### 最佳方法

 关键的见解是，可以在单个后序遍历期间确定是否应该保留子树。 

只有当我们知道一个节点的左子树和右子树是否包含一个节点时，才应该删除该节点。`1`。 这意味着我们必须在处理父母之前处理孩子。 

递归策略为：

 - 递归修剪左子树。 
- 递归修剪右子树。 
- 修剪子节点后，确定是否应保留当前节点。 
- 如果当前节点有值`0`两个孩子都是`null`，将其删除。 

这避免了重复的子树扫描，因为每个节点只被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 反复检查子树是否包含 1 |
 | 最佳| O(n) | O(h) | 单后序DFS遍历|

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 从根节点开始递归深度优先遍历。 
2. 对于每个节点，先递归处理左子树。 递归调用返回：

 - 原始子树根（如果应该保留），或者
 -`null`是否应删除子树。 
3. 使用相同的逻辑递归处理右子树。 
4. 处理完两个子节点后，更新当前节点的`left`和`right`带有返回值的指针。 这有效地删除了无效的子树。 
5. 判断是否删除当前节点本身。 如果出现以下情况，则应删除节点：

 - 其值为`0`- 它的左孩子是`null`- 它的右孩子是`null`这意味着以此节点为根的整个子树不包含`1`。 
6. 如果需要删除该节点，则返回`null`。 
7. 否则，返回当前节点。 
8. 根调用的最终返回值成为答案。 

### 为什么它有效

 该算法之所以有效，是因为后序遍历。 当我们评估一个节点时，它的两个子树都已经被完全修剪。 因此：

 - 保证任何剩余的子子树至少包含一个`1`。 
- 任何删除的子子树不包含`1`。 

这保证了当我们评估一个节点时，我们有关于它的整个子树是否包含一个节点的完整信息。`1`。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def pruneTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        def dfs(node: Optional[TreeNode]) -> Optional[TreeNode]:
            if not node:
                return None

            node.left = dfs(node.left)
            node.right = dfs(node.right)

            if node.val == 0 and not node.left and not node.right:
                return None

            return node

        return dfs(root)
```实现直接遵循递归后序策略。 

辅助函数`dfs`一次处理一个子树。 如果当前节点是`None`，它立即返回`None`。 

递归调用：```python
node.left = dfs(node.left)
node.right = dfs(node.right)
```在评估当前节点之前修剪两个子子树。 

修剪子级后，代码检查：```python
if node.val == 0 and not node.left and not node.right:
```这个条件意味着：

 - 当前节点是`0`- 没有有效的后代

 因此，子树不包含`1`，所以应该通过返回来删除它`None`。 

否则，当前节点仍然是最终树的一部分。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func pruneTree(root *TreeNode) *TreeNode {
    if root == nil {
        return nil
    }

    root.Left = pruneTree(root.Left)
    root.Right = pruneTree(root.Right)

    if root.Val == 0 && root.Left == nil && root.Right == nil {
        return nil
    }

    return root
}
```Go 实现在结构上与 Python 版本相同。 由于 Go 使用指针作为树节点，因此返回`nil`有效地删除子树。 

与 Python 不同，Go 没有 true 或 false 对象评估，因此明确`nil`需要进行比较：```go
root.Left == nil && root.Right == nil
```不存在整数溢出问题，因为节点值被限制为`0`和`1`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用堆栈最多存储树高帧 |

 该算法执行单次 DFS 遍历。 每个节点都被处理一次，并且节点上的每个操作都需要恒定的时间。 

空间复杂度来自递归深度。 在平衡树中，高度为`O(log n)`。 在倾斜树的最坏情况下，高度变为`O(n)`。

 ## 边缘情况

 一个重要的边缘情况是完全由零组成的树。 在这种情况下，每个子树都缺少一个`1`，因此必须删除整棵树。 幼稚的实现可能会错误地保留根或无法向上传播删除。 递归解决方案自然地处理这个问题，因为每个叶子`0`首先被移除，最终导致根本身满足移除条件。 

另一个重要的边缘情况是具有价值的节点`0`其后代包含`1`。 立即删除节点似乎很直观，因为它自己的值是`0`，但这会错误地断开树的有效部分。 该算法通过首先修剪子节点来避免这种错误。 如果保留任何后代子树，则父节点也必须保留以保持连接性。 

第三种边缘情况涉及叶节点。 有值的叶节点`0`应该始终被删除，因为它不包含后代，也不包含`1`。 相反，具有值的叶节点`1`必须始终保留。 条件：```
node.val == 0 and not node.left and not node.right
```正确区分这两种情况。 

最后的边缘情况是高度不平衡的树，类似于链表。 如果约束非常大，递归树算法有时可能会在深度递归上失败。 然而，该问题将树限制为 200 个节点，因此递归深度对于 Python 和 Go 实现来说仍然是安全的。
