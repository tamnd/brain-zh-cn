[LeetCode 问题 857](https://leetcode.com/problems/minimum-cost-to-hire-k-workers/)

 **难度：** 🔴难
 **主题：** 数组、贪婪、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有两个数组，`quality`和`wage`，其中每个索引代表一个工人。 价值`quality[i]`描述了有多少工作或贡献`i-th`工人提供，同时`wage[i]`描述了工人愿意接受的最低金额。 

我们必须准确聘用`k`工人和团体必须同时满足两条规则。 

首先，每个工人都必须至少获得他们期望的最低工资。 

其次，团队内部的薪酬结构必须与质量成正比。 如果工人 A 的质量是工人 B 的两倍，那么工人 A 的工资必须是工人 B 的两倍。 

这种比例约束是问题的核心难点。 一旦选择了一个组，整个组实际上共享一个“每个质量单位的工资率”。 如果利率是`r`，然后是一个有素质的工人`q`必须支付：$$\text{pay} = r \times q$$为了使工人接受该报价，我们必须确保：$$r \times q_i \geq wage_i$$重新排列可以得出：$$r \geq \frac{wage_i}{quality_i}$$这个比例非常重要。 它告诉我们每个工人要求的最低按质量付费率。 

对于任何选定的组，实际费率`r`必须至少是该组中所有工人的最大比例。 一旦这个比率确定，每个工人的工资就会自动确定。 

雇用一个团队的总成本变为：$$\text{total cost} = r \times (\text{sum of qualities})$$约束足够大，以至于无法对所有可能的组进行强力枚举。 自从`n`可以大到`10^4`，任何指数或组合方法都会超时。 我们需要一些接近的东西`O(n log n)`。 

一些边缘情况很重要：

 - 当`k = 1`，我们只是选择工资最低的工人。 
- 工人可以有相同的比率。 
- 工人的素质可能截然不同，这会严重影响总成本。 
- 工资低但素质极高的工人总体上可能仍然很昂贵。 
- 浮点精度很重要，因为答案接受的误差容限为`10^-5`。 

## 方法

 ### 蛮力方法

 蛮力解决方案将生成每个可能的组`k`工人。 对于每个组，我们将通过取以下最大值来确定所需的工资率：$$\frac{wage_i}{quality_i}$$在集团所有员工中。 

一旦知道比率，我们就可以计算：$$\text{cost} = \text{rate} \times \text{sum of qualities}$$我们将跟踪所有组的最低成本。 

这是有效的，因为每个有效组都必须使用至少与该组中最高要求比率一样大的工资率。 准确地使用该最大比率可以最大限度地降低所选组的总成本。 

然而，这种方法太慢了。 组合数为：$$\binom{n}{k}$$即使对于中等值，这也会变得巨大`n`。 

### 最优贪婪+堆方法

 关键的观察是，如果我们固定一组中的最高比率，那么总成本仅取决于质量的总和。 

假设工人`i`组内比例最高：$$r_i = \frac{wage_i}{quality_i}$$然后，必须使用相同的费率向该组中的每个工人支付工资`r_i`。 

总成本变为：$$r_i \times (\text{sum of qualities})$$对于固定比率，最小化成本意味着最小化质量总和。 

这导致了贪婪策略：

 - 按比率升序对工人进行排序。 
- 按比例从最小到最大处理工人。 
- 将当前工人的比例视为该组的最大比例。 
- 在迄今为止看到的所有工人中，保留`k`工人的综合素质最低。 

为了有效地保持最小的质量总和，我们使用最大堆。 每当堆增长超出大小时`k`，我们删除质量最高的工人，因为该工人对增加总成本的贡献最大。 

这给出了一个有效的`O(n log n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 |$O\left(\binom{n}{k} \cdot k\right)$| O(k) | 枚举每个可能的组 |
 | 最佳| O(n log n) | O(n log n) | O(k) | 使用最大堆的贪婪排序 |

 ## 算法演练

 1. 创建一个worker列表，每个worker存储：

 - 他们的工资与质量的比率
 - 他们的品质

 比例为：$$\frac{wage[i]}{quality[i]}$$该比率代表工人可接受的最低按质量付费率。 
2. 按比例升序对所有工人进行排序。 

分拣后，加工工人时`i`，他们的比例成为迄今为止考虑的所有工人中最高的比例。 
3. 维护包含工人素质的最大堆。 

堆帮助我们有效地跟踪候选工作人员中尽可能小的总质量。 
4. 保持持续的品质。 

每次我们向堆中添加一个工人时，我们都会增加质量总和。 
5. 按排序的比率顺序迭代工作人员。 

对于每个工人：

 - 将它们的质量添加到堆中
 - 将他们的质量添加到运行总和中
 6. 如果堆大小超过`k`，移除质量最大的工人。 

我们删除了最大的质量，因为它对增加总成本的贡献最大。 删除它可以为当前比率提供尽可能小的质量总和。 
7. 每当堆大小恰好变为`k`，计算总成本：$$\text{cost} = (\text{current ratio}) \times (\text{quality sum})$$如果此成本较小，则更新最小答案。 
8. 继续，直到处理完所有工人。 

### 为什么它有效

 正确性来自于当前工人的比例是当前组允许的最大比例。 由于在此之前的所有工人的比率都小于或等于当前比率，因此他们都可以使用该比率合法地获得报酬。 

对于固定比率，最小化总成本相当于最小化总质量。 堆保证在迄今为止看到的所有有效候选人中，我们始终保留`k`工人的总体素质尽可能最小。 

因此，考虑的每个候选组对于其最大比率都是最优的，并且检查所有可能的最大比率保证了全局最优。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def mincostToHireWorkers(
        self,
        quality: List[int],
        wage: List[int],
        k: int
    ) -> float:

        workers = []

        for q, w in zip(quality, wage):
            ratio = w / q
            workers.append((ratio, q))

        workers.sort()

        max_heap = []
        quality_sum = 0
        minimum_cost = float("inf")

        for ratio, q in workers:
            heapq.heappush(max_heap, -q)
            quality_sum += q

            if len(max_heap) > k:
                removed_quality = -heapq.heappop(max_heap)
                quality_sum -= removed_quality

            if len(max_heap) == k:
                total_cost = ratio * quality_sum
                minimum_cost = min(minimum_cost, total_cost)

        return minimum_cost
```实施过程首先构建一个包含其比例和质量的工人列表。 我们只需要这两个值，因为一旦知道比率，工资本身就不再是必要的。 

工作人员按比率排序，以便在迭代时，当前工作人员始终定义候选组中的最大比率。 

蟒蛇的`heapq`模块实现了最小堆，但我们需要一个最大堆，因此我们存储负质量。 当堆大小超过时，这可以有效地删除最大质量`k`。 

变量`quality_sum`跟踪当前堆内工作人员的总体质量。 当我们移除一个工人时，我们会从运行总和中减去他们的质量。 

每当堆恰好包含`k`对于工作人员，我们使用当前比率和当前质量总和来计算候选总成本。 由于堆始终保持该比率的最小可能质量总和，因此计算的成本对于该比率是最佳的。 

返回所有此类候选成本中的最小值。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

type Worker struct {
	ratio   float64
	quality int
}

func mincostToHireWorkers(quality []int, wage []int, k int) float64 {

	n := len(quality)

	workers := make([]Worker, n)

	for i := 0; i < n; i++ {
		workers[i] = Worker{
			ratio:   float64(wage[i]) / float64(quality[i]),
			quality: quality[i],
		}
	}

	sort.Slice(workers, func(i, j int) bool {
		return workers[i].ratio < workers[j].ratio
	})

	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	qualitySum := 0
	answer := 1e18

	for _, worker := range workers {

		heap.Push(maxHeap, worker.quality)
		qualitySum += worker.quality

		if maxHeap.Len() > k {
			removed := heap.Pop(maxHeap).(int)
			qualitySum -= removed
		}

		if maxHeap.Len() == k {
			cost := worker.ratio * float64(qualitySum)

			if cost < answer {
				answer = cost
			}
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的算法结构。 主要区别在于 Go 需要使用显式堆实现`container/heap`界面。 

通过反转内部比较，将堆实现为最大堆`Less`方法。 

Go 在除法时还需要显式浮点转换，否则会发生整数除法。 

与 Python 不同，Go 没有内置的元组排序，因此需要自定义`Worker`结构和`sort.Slice`使用比较器。

from typing import List
import math

class Solution:
    def mincostToHireWorkers(
        self,
        quality: List[int],
        wage: List[int],
        k: int
    ) -> float:

        import heapq

        workers = []

        for q, w in zip(quality, wage):
            workers.append((w / q, q))

        workers.sort()

        heap = []
        quality_sum = 0
        answer = float("inf")

        for ratio, q in workers:
            heapq.heappush(heap, -q)
            quality_sum += q

            if len(heap) > k:
                quality_sum -= -heapq.heappop(heap)

            if len(heap) == k:
                answer = min(answer, ratio * quality_sum)

        return answer

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 在这种情况下，比例付款限制变得微不足道，因为只雇用一名工人。 有缺陷的实现可能仍然会使比率处理过于复杂。 当前的实现自然会处理这种情况，因为堆达到了大小`1`立即，成本就变成了工人所需的工资。 

另一个重要的边缘案例涉及具有相同工资与质量比率的工人。 由于他们都接受相同的工资率，因此最佳解决方案应该简单地选择素质最低的工人。 堆结构会自动处理这个问题，因为每当堆变得太大时，它就会不断地删除最大的质量。 

当工人的素质极高但比率相对较低时，就会出现第三种关键边缘情况。 幼稚的贪婪算法可能会错误地只支持低比率，即使巨大的质量会显着增加总成本。 此实现避免了该错误，因为它同时优化了两个组成部分：当前比率和总质量总和。 

浮点精度是另一个微妙的问题。 结果可能包含重复的小数，因此使用整数算术会产生错误的答案。 两种实现都使用浮点除法进行比率和总成本计算，确保满足所需容差的足够精度。
