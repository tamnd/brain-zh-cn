[LeetCode 第 877 题](https://leetcode.com/problems/stone-game/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、动态规划、博弈论

 ## 解决方案

 ## 问题理解

 该问题描述了在一系列石堆上进行的两人游戏。 每堆包含正数的石子，并且堆排列成一排。 Alice 和 Bob 交替轮流，Alice 总是先移动。 在每个回合中，当前玩家只能从该行的左端或右端拿取该堆。 所选的石堆将被永久移除，玩家将这些石子添加到他们的分数中。 

目标是确定假设两名玩家都发挥最佳状态，爱丽丝是否可以保证获胜。 由于棋子总数保证为奇数，因此不可能出现平局。 因此该函数应该返回`true`如果爱丽丝最终可以比鲍勃拥有更多的石头，否则`false`。 

输入是一个整数数组`piles`， 在哪里`piles[i]`代表宝石的数量`i-th`桩。 数组的长度始终是偶数，这很重要，因为两个玩家将进行相同的回合数。 约束允许最多 500 个堆，这立即告诉我们指数暴力搜索将太慢。 

几个重要的保证简化了问题：

 - 堆的数量始终是偶数。 
- 每堆包含正数的石子。 
- 棋子总数为奇数，因此不会出现平局。 
- 两名球员总是发挥最佳状态。 

当尝试贪婪地对未来决策进行建模时，幼稚的实现很容易失败。 例如，在每一步中选择两端中较大的一个并不总是最佳的，因为较小的直接选择可能会迫使对手在未来处于更糟糕的位置。 因此，该解决方案需要推理多个回合的最佳游戏。 

一个有趣的细节是，这个特定的 LeetCode 问题有一个数学属性：当两个玩家都发挥最佳状态时，Alice 总是获胜。 然而，理解动态规划公式仍然很有价值，因为它教授了许多区间 DP 问题中使用的一般博弈论模式。 

## 方法

 ### 蛮力方法

 蛮力解决方案探索了每一种可能的移动顺序。 在每个回合中，当前玩家有两个选择：

 - 取出最左边的一堆
 - 取出最右边的一堆

 递归继续进行，直到没有剩余的堆为止。 对于每个状态，假设对手也发挥最佳状态，算法会计算最佳可能结果。 

这种方法是正确的，因为它明确地检查了所有可能的游戏状态和最佳响应。 然而，它的效率极低，因为相同的子问题被重新计算很多次。 游戏状态的数量呈指数增长，大约`O(2^n)`，当`n`可以达到500。 

### 最优动态规划方法

 关键的见解是游戏存在重叠的子问题。 游戏状态完全由当前区间决定`[left, right]`。 

我们不直接存储总得分，而是存储当前玩家在给定时间间隔内与对手的得分差。 

定义：

-`dp[left][right]`= 当前玩家可以从堆中获得的最大分数差`left`通过`right`如果当前玩家选择左边一堆：```
piles[left] - dp[left + 1][right]
```出现减法是因为在拿完一堆后，对手在剩余的时间间隔内成为当前玩家。 

同样，如果玩家选择了正确的一堆：```
piles[right] - dp[left][right - 1]
```最佳选择是这两个值中的最大值。 

最后：

 - 如果`dp[0][n - 1] > 0`，Alice 可以保证比 Bob 更多的石头。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索每个可能的游戏序列 |
 | 最优动态规划| O(n²) | O(n²) | 存储间隔结果并避免重新计算 |

 ## 算法演练

 1.创建二维DP表其中`dp[left][right]`表示当前玩家使用指数之间的桩数可以比对手获得的最大分数差`left`和`right`。 
2. 初始化基本情况，其中`left == right`。 如果只剩下一堆，当前玩家立即拿走它，所以：```
dp[i][i] = piles[i]
```3. 按长度递增的顺序处理间隔。 这种排序很重要，因为较大的间隔取决于已计算的较小间隔。 
4. 对于每个间隔`[left, right]`，计算取左边一堆的结果：```
take_left = piles[left] - dp[left + 1][right]
```减法之所以有效，是因为当前玩家拿走左边的牌堆后，对手在剩余的时间间隔内发挥最佳。 
5. 计算取右堆的结果：```
take_right = piles[right] - dp[left][right - 1]
```6. 存储两个选择中较好的一个：```
dp[left][right] = max(take_left, take_right)
```7.填表后，检查最终间隔：```
dp[0][n - 1]
```如果这个值为正数，那么Alice可以保证比Bob获得更高的分数。 

### 为什么它有效

 DP 状态始终代表当前玩家可以从子数组中强制获得的最佳得分优势。 每一步都会转变为一个较小的子问题，其中对手成为当前玩家。 因为递归模型两个玩家都表现最佳，所以计算结果正确地代表了完美的游戏。 通过自下而上评估每个区间，该算法保证所有必需的子问题在使用之前都已得到解决。 

## Python 解决方案```python
from typing import List

class Solution:
    def stoneGame(self, piles: List[int]) -> bool:
        n = len(piles)

        dp = [[0] * n for _ in range(n)]

        # Base case: one pile remaining
        for i in range(n):
            dp[i][i] = piles[i]

        # Build solutions for larger intervals
        for length in range(2, n + 1):
            for left in range(n - length + 1):
                right = left + length - 1

                take_left = piles[left] - dp[left + 1][right]
                take_right = piles[right] - dp[left][right - 1]

                dp[left][right] = max(take_left, take_right)

        return dp[0][n - 1] > 0
```实现首先创建一个大小为 DP 表`n x n`。 每个单元格存储当前玩家在特定时间间隔内可以获得的最佳分数差。 

首先初始化对角线条目，因为长度为 1 的区间是最简单的可能子问题。 如果只有一堆存在，当前玩家立即拿走它。 

然后，该算法按长度递增的顺序处理间隔。 这种排序确保了计算时`dp[left][right]`，较小的间隔`dp[left + 1][right]`和`dp[left][right - 1]`已经解决了。 

对于每个间隔，代码都会评估两种可能的移动：

 - 拿走左边的一堆
 - 取出正确的一堆

 对手的最优反应是通过减去相应的DP值来表示的。 当前玩家选择能产生较大分数优势的棋步。 

最后，算法检查 Alice 是否可以在整个数组中强制获得比 Bob 正的分数差异。 

## 解决方案```go
func stoneGame(piles []int) bool {
	n := len(piles)

	dp := make([][]int, n)
	for i := range dp {
		dp[i] = make([]int, n)
	}

	// Base case: single pile
	for i := 0; i < n; i++ {
		dp[i][i] = piles[i]
	}

	// Build intervals of increasing length
	for length := 2; length <= n; length++ {
		for left := 0; left <= n-length; left++ {
			right := left + length - 1

			takeLeft := piles[left] - dp[left+1][right]
			takeRight := piles[right] - dp[left][right-1]

			if takeLeft > takeRight {
				dp[left][right] = takeLeft
			} else {
				dp[left][right] = takeRight
			}
		}
	}

	return dp[0][n-1] > 0
}
```Go 实现遵循与 Python 版本相同的 DP 逻辑。 主要区别在于二维 DP 表的手动切片分配。 

Go 数组是固定大小的，因此使用切片是为了灵活性。 由于所有值都在 Go 的范围内`int`在给定的限制下，整数溢出不是问题。 

与 Python 不同，Go 不提供内置的`max`函数用于整数，因此实现使用显式条件比较。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 每个间隔仅计算一次 |
 | 空间| O(n²) | DP 表存储所有间隔的结果 |

 DP表包含`n²`状态因为每对`(left, right)`代表一个可能的区间。 每个状态都是使用先前解决的子问题在恒定时间内计算的。 因此，总运行时间是二次方。 

内存使用量也是二次的，因为该算法将每个间隔的结果存储在二维表中。

 ## 边缘情况

 一种重要的边缘情况是最小有效输入大小，其中数组仅包含两堆。 在这种情况下，爱丽丝只需选择较大的一堆并立即获胜。 一些实现错误地假设至少有一个递归层或区间扩展是必要的，但 DP 初始化自然地处理了这一点，因为长度为 2 的区间是直接从基本情况计算出来的。 

另一个重要的边缘情况涉及重复或几乎相同的桩值，例如`[4,4,4,5]`。 当值相似时，朴素的贪婪策略可能会表现得不可预测，因为选择局部较大的堆并不总是最大化最终分数。 DP 公式正确地评估了未来的后果而不是眼前的收益。 

当最大的桩最初不位于两端时，会出现第三种重要的边缘情况，例如`[1,100,3,4]`。 过于简单化的方法可能会失败，因为最佳行动是由长期定位决定的，而不是立即获取最大值。 区间动态规划正确地模拟了未来的回合和对手的反应，确保始终选择最佳策略。 

另一个微妙的情况是对称数组，例如`[100,1,1,100]`。 这些可能会暴露区间索引或转换逻辑中的错误，因为两端最初看起来是相等的。 由于该实现使用相同的递归关系系统地评估这两种选择，因此可以正确处理对称性，而无需任何特殊情况逻辑。
