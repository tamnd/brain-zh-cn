[LeetCode 834 题](https://leetcode.com/problems/sum-of-distances-in-tree/)

 **难度：** 🔴难
 **主题：** 动态规划、树、深度优先搜索、图论

 ## 解决方案

 ## 问题理解

 这个问题给了我们一棵无向树`n`节点标记为`0`到`n - 1`。 树是一个连通图，其精确`n - 1`边缘且无循环。 每条边双向连接两个节点。 

对于每个节点`i`，我们必须计算总距离`i`到树中的每个其他节点。 结果应作为数组返回，其中：

 -`answer[i]`等于距节点的最短路径距离之和`i`到所有其他节点。 

树中两个节点之间的距离只是连接它们的唯一路径上的边数。 

例如，考虑这棵树：```
    0
   / \
  1   2
     /|\
    3 4 5
```距节点的距离`0`是：

 - 到`1`= 1
 - 到`2`= 1
 - 到`3`= 2
 - 到`4`= 2
 - 到`5`= 2

 他们的总和是`8`， 所以`answer[0] = 8`。 

约束条件很重要：

 -`n`可以大到`30,000`- 该图保证是一棵有效的树
 - 正好有`n - 1`边缘

 这些约束立即排除了昂贵的全对最短路径算法。 一个`O(n^2)`解决方案会太慢，因为：```
30,000^2 = 900,000,000
```这远远超出了可接受的运行时间限制。 

重要的边缘情况包括：

 - 单节点树，答案是`[0]`- 双节点树，两个答案都是`1`- 高度不平衡的树，例如直链
 - 星形树，其中一个节点连接到每个其他节点

 树保证非常有用，因为：

 - 任意两个节点之间只有一条路径
 - DFS遍历可以高效计算子树信息
 - 树上的动态编程成为可能

 ## 方法

 ### 蛮力方法

 最直接的解决方案是独立计算每个节点到其他每个节点的距离。 

对于每个节点：

 1. 运行BFS或DFS
 2. 计算到所有其他节点的距离
 3. 距离总和
 4. 存储结果

 由于 BFS 或 DFS 遍历需要`O(n)`树中的时间，并且我们必须对每个节点执行此操作，总复杂度变为`O(n^2)`。 

这种方法是正确的，因为 BFS 计算未加权图中的最短路径距离。 然而，对于`n = 30,000`。 

### 最佳方法

 关键的见解是相邻节点的答案密切相关。 

假设我们已经知道某个节点的总距离和`u`。 如果我们将根从`u`给它的一个孩子`v`，距离以可预测的方式变化：

 - 内部节点`v`的子树变得更近了 1 步
 - 外部节点`v`的子树又向前移动了 1 步

 如果：

 -`subtree_size[v]`是节点数`v`的子树
 -`n`是节点总数

 那么：```
answer[v] = answer[u] - subtree_size[v] + (n - subtree_size[v])
```这一观察结果使我们能够使用两次 DFS 遍历在线性时间内计算所有答案：

 1.第一次DFS：

 - 计算子树大小
 - 计算任意根（通常是节点）的答案`0`2.第二个DFS：

 - 重用根转换公式
 - 计算所有节点的答案

 这将问题从重复的图遍历转变为树上的动态规划。

 ## 算法演练

 ### 第 1 步：构建邻接表

 我们使用邻接表来表示树。 

由于图是无向的：

 - 如果有边缘`[u, v]`- 然后`u`被添加到`v`的邻居列表
 - 和`v`被添加到`u`的邻居列表

 这种结构允许有效地遍历树。 

### 步骤 2：初始化数组

 我们维护两个重要的数组：

 -`count[node]`- 存储以 为根的子树中存在多少个节点`node`- 最初每个节点都计算自己，因此初始化为`1`-`answer[node]`- 存储距离的总和`node`到所有节点

 ### 步骤 3：首先 DFS，计算子树大小和根答案

 我们在节点处建立树根`0`。 

DFS 期间：

 - 递归处理所有子项
 - 累积子树大小
 - 累积距离总和

 对于一个孩子`child`的`node`：```
count[node] += count[child]
answer[node] += answer[child] + count[child]
```为什么这有效？ 

-`answer[child]`已经包含孩子子树内的距离
 - 该子树中的每个节点都远离 1 个边`node`- 有`count[child]`这样的节点

 在此 DFS 之后：

 -`count[node]`每个节点都是已知的
 -`answer[0]`成为根的总距离和`0`### 步骤 4：第二次 DFS，重新确定树的根

 现在我们将答案从父母传播给孩子。 

假设我们将根从`node`到`child`。 

两组节点发生变化：

 1. 内部节点`child`的子树

 - 更近了1步
 - 总计减少`count[child]`2. 外部节点`child`的子树

 - 又前进了1步
 - 总计增加`n - count[child]`所以：```
answer[child] = answer[node] - count[child] + (n - count[child])
```我们在整个树中递归地应用这个公式。 

### 第 5 步：返回最终答案

 在第二次DFS之后，每个节点都有其正确的距离和。 

返回`answer`大批。 

### 为什么它有效

 该算法依赖于重根动态规划不变量。 

第一个DFS计算完整的子树信息假设节点`0`是根。 第二个 DFS 利用了这样一个事实：将根移动到一条边上会均匀地改变距离：

 - 一棵子树越来越近
 - 树的其余部分变得更远

 由于每条边仅处理固定次数，因此整个计算保持线性。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def sumOfDistancesInTree(self, n: int, edges: List[List[int]]) -> List[int]:
        graph = defaultdict(list)

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)

        count = [1] * n
        answer = [0] * n

        def dfs1(node: int, parent: int) -> None:
            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                dfs1(neighbor, node)

                count[node] += count[neighbor]
                answer[node] += answer[neighbor] + count[neighbor]

        def dfs2(node: int, parent: int) -> None:
            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                answer[neighbor] = (
                    answer[node]
                    - count[neighbor]
                    + (n - count[neighbor])
                )

                dfs2(neighbor, node)

        dfs1(0, -1)
        dfs2(0, -1)

        return answer
```实现首先使用构造邻接表`defaultdict(list)`。 由于树是无向的，因此每条边都在两个方向上插入。 

这`count`数组初始化为`1`因为每个节点都是其自己的子树的一部分。 这`answer`数组以零开始，并在 DFS 期间逐渐填充。 

第一个 DFS 同时计算两件事：

 - 子树大小
 - 根的总距离和`0`每个子节点都贡献其子树大小和已计算的内部距离。 

第二个DFS执行重新根动态规划。 它不是从头开始重新计算距离，而是使用派生公式将父答案转换为子答案。 

由于每个 DFS 访问每条边一次，因此解决方案保持线性。 

## 解决方案```go
package main

func sumOfDistancesInTree(n int, edges [][]int) []int {
	graph := make([][]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	count := make([]int, n)
	answer := make([]int, n)

	for i := 0; i < n; i++ {
		count[i] = 1
	}

	var dfs1 func(int, int)
	dfs1 = func(node int, parent int) {
		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			dfs1(neighbor, node)

			count[node] += count[neighbor]
			answer[node] += answer[neighbor] + count[neighbor]
		}
	}

	var dfs2 func(int, int)
	dfs2 = func(node int, parent int) {
		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			answer[neighbor] =
				answer[node] -
					count[neighbor] +
					(n - count[neighbor])

			dfs2(neighbor, node)
		}
	}

	dfs1(0, -1)
	dfs2(0, -1)

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片而不是 Python 列表和字典。 

邻接表表示为`[][]int`，其中每个索引存储相邻节点。 

递归 DFS 函数是使用函数变量声明的，因为 Go 要求在使用之前分配命名递归闭包。 

整数溢出不是问题，因为最大可能距离总和完全符合 Go 的标准`int`问题约束下的范围。

 ## 边缘情况

 ### 单节点树

 一棵只有一个节点的树没有边，也没有邻居。 这种情况很容易处理不当，因为 DFS 逻辑通常假设子项存在。 

该实现自然地处理了这个问题，因为：

 - 节点的邻接表`0`是空的
 - 两次 DFS 遍历都立即终止
 -`answer[0]`遗迹`0`不需要特殊情况代码。 

### 高度倾斜的树

 链状树，例如：```
0 - 1 - 2 - 3 - 4
```创建最大递归深度和不对称子树大小。 

简单的实现可能会重复地重新计算距离并退化为二次时间。 

该解决方案仍然以线性时间运行，因为：

 - 每条边仅处理两次
 - 重新定位在每条边的恒定时间内更新答案

 ### 星形树

 一棵树的一个中心节点连接到所有其他节点，会导致子树大小严重不平衡。 

例如：```
    1
    |
2 - 0 - 3
    |
    4
```中心节点的距离非常小，而叶节点的距离之和则大得多。 

重根公式可以正确处理这个问题，因为子树大小直接决定移动根时距离如何变化。
