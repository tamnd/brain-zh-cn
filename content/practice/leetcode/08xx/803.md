[LeetCode 803 题](https://leetcode.com/problems/bricks-falling-when-hit/)

 **难度：** 🔴难
 **主题：** 数组、并查集、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们在二维网格中模拟一系列砖块移除，同时确定每次移除后有多少额外的砖块变得不稳定并掉落。 

网格仅包含`0`和`1`价值观：

 -`1`代表一块砖
 -`0`代表一个空单元格

 如果砖块至少满足以下条件之一，则被认为是稳定的：

 1.直接连接顶排
 2.它通过相邻的砖块连接到另一个稳定的砖块

 邻接有上、下、左、右四个方向。 

当一块砖块因撞击而被移除时，周围的一些砖块可能会失去与顶部的连接。 任何不再连接到顶部的砖块都会变得不稳定并立即掉落。 掉落的砖块永久消失。 

重要的细节是，我们只计算因移除而掉落的砖块，而不计算直接被击中的砖块。 

对于每一次点击`hits`数组中，我们必须返回应用该命中后掉落的砖块数量。 

约束在这里非常重要：

 - 网格尺寸可达`200 x 200`- 点击次数最多可达`4 * 10^4`每次命中后的简单模拟都太慢了。 由于网格最多可以包含`40,000`细胞，也可以有`40,000`命中，我们需要比每次从头开始重新计算稳定性更有效的东西。 

一些边缘情况尤其重要：

 - 命中可能会针对已经为空的单元格
 - 从顶行移除一块砖块可能会破坏大型连接组件的稳定性
 - 多次点击可能会以复杂的方式断开和重新连接区域
 - 由于较早的跌倒，一块砖可能已经消失了
 - 操作顺序很重要

 关键的挑战是有效地跟踪每次操作后哪些砖块仍然连接到顶部。 

## 方法

 ### 蛮力方法

 一种简单的方法是逐一处理每个命中。 

对于每次点击：

 1. 移除砖块
 2. 通过从顶行执行 BFS 或 DFS 重新计算哪些砖块是稳定的
 3.任何无法从顶部到达的砖块都会掉落
 4. 计算掉落的砖块

 这是有效的，因为当一块砖块能够通过相连的砖块到达顶部时，它就处于稳定状态。 

然而，这种方法极其昂贵。 

假设：

 - 有`H`点击数
 - 网格包含`M * N`细胞

 对于每次点击，我们可能需要扫描整个网格并遍历所有砖块。 这导致：

 -`O(H * M * N)`或者更糟

 约束条件高达`40,000`细胞和`40,000`击中，这变得不可行。 

### 最优方法，联合查找逆向处理

 关键的见解是，删除很难动态处理，但添加要容易得多。 

Union-Find，也称为不相交集并集或 DSU，非常擅长在添加边或节点时处理连接性。 它自然不适合删除。 

因此，我们不是向前处理点击，而是向后处理它们。 

这个想法是这样的：

 1. 首先，从网格中移除所有被击中的砖块
 2. 为剩余的稳定砖构建连接结构
 3. 以相反的顺序处理命中
 4.将每块砖添加回去
 5. 测量有多少新砖块由于添加而连接到顶部

 如果添加一块砖将断开的组件重新连接到天花板，那么当最初移除砖时，这些砖就会掉落。 

这种转换将困难的删除问题转换为更容易的添加问题。 

我们引入一个特殊的虚拟节点，称为“屋顶”或“天花板”。 连接到顶行的每个砖块都与该虚拟节点结合。 

然后：

 - 屋顶组件的大小告诉我们当前存在多少稳定的砖块
 - 添加回砖块时，我们会比较之前和之后的屋顶组件尺寸
 - 增加告诉我们有多少砖块变得稳定
 - 我们减去一是因为修复后的砖块本身不应算作掉落的砖块

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(H * M * N) | O(M * N) | 每次命中后重新计算稳定性 |
 | 最佳 | O(M * N + H * α(M * N)) | O(M * N + H * α(M * N)) | O(M * N) | 使用 Union-Find 进行逆向处理 |

 这里，`α`是阿克曼反函数，在实践中它实际上是常数。 

## 算法演练

 1. 创建原始网格的副本。 

我们不想直接改变原始网格，因为我们需要知道命中最初是针对砖块还是空单元格。 
2. 将所有命中应用到复制的网格。 

对于每一个`(r, c)`在`hits`:

 - 如果单元格包含砖块，请将其设置为`0`- 如果已经为空，则保持不变

 在此步骤之后，网格表示应用所有命中后的最终状态。 
3. 初始化并查结构。 

我们为每个网格单元创建一个节点，再加上一个代表屋顶的额外虚拟节点。 

如果网格有`m * n`细胞，则：

 - 细胞指数 =`r * n + c`- 屋顶指数 =`m * n`4. 为剩余的积木建立连接。 

遍历修改后的网格。 

对于每块砖：

 - 如果它在顶行，则将其与屋顶节点合并
 - 将其与相邻的砖块结合起来

 此时，并查结构正确地表示了每次命中发生后的所有稳定组件。 
5. 以相反的顺序处理命中。 

我们向后迭代`hits`。 

对于每次点击：

 - 如果原始网格没有砖块，则附加`0`- 否则：

 - 记录屋顶组件的当前尺寸
 - 恢复砖块
 - 将其与相邻的砖块结合起来
 - 如果它位于顶行，请将其与屋顶结合起来
 - 记录新的屋顶组件尺寸
 6. 计算新稳定的砖块。 

认为：

-`before`= 修复前的屋顶组件尺寸
 -`after`= 修复后屋顶构件尺寸

 然后：```
newly_connected = after - before
```这包括修复后的砖块本身，因此：```
fallen = max(0, newly_connected - 1)
```7. 反转结果数组。 

由于我们向后处理了命中，因此在返回之前反转收集到的答案。 

### 为什么它有效

 关键的不变量是并查结构始终代表所有未来命中已经发生后的连接状态。 

当我们以相反的顺序添加一块砖时，任何新连接到屋顶的组件都必须依赖该砖来保持向前的稳定性。 

因此，新连接的砖块数量与最初移除砖块时掉落的砖块数量完全匹配。 

## Python 解决方案```python
from typing import List

class UnionFind:
    def __init__(self, size: int):
        self.parent = list(range(size))
        self.component_size = [1] * size

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, x: int, y: int) -> None:
        root_x = self.find(x)
        root_y = self.find(y)

        if root_x == root_y:
            return

        if self.component_size[root_x] < self.component_size[root_y]:
            root_x, root_y = root_y, root_x

        self.parent[root_y] = root_x
        self.component_size[root_x] += self.component_size[root_y]

    def size(self, x: int) -> int:
        return self.component_size[self.find(x)]

class Solution:
    def hitBricks(self, grid: List[List[int]], hits: List[List[int]]) -> List[int]:
        rows = len(grid)
        cols = len(grid[0])

        roof = rows * cols

        copied_grid = [row[:] for row in grid]

        for r, c in hits:
            if copied_grid[r][c] == 1:
                copied_grid[r][c] = 0

        uf = UnionFind(rows * cols + 1)

        def index(r: int, c: int) -> int:
            return r * cols + c

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        for r in range(rows):
            for c in range(cols):
                if copied_grid[r][c] == 0:
                    continue

                current = index(r, c)

                if r == 0:
                    uf.union(current, roof)

                for dr, dc in [(1, 0), (0, 1)]:
                    nr = r + dr
                    nc = c + dc

                    if (
                        0 <= nr < rows
                        and 0 <= nc < cols
                        and copied_grid[nr][nc] == 1
                    ):
                        uf.union(current, index(nr, nc))

        result = []

        for r, c in reversed(hits):
            if grid[r][c] == 0:
                result.append(0)
                continue

            before_roof_size = uf.size(roof)

            copied_grid[r][c] = 1
            current = index(r, c)

            if r == 0:
                uf.union(current, roof)

            for dr, dc in directions:
                nr = r + dr
                nc = c + dc

                if (
                    0 <= nr < rows
                    and 0 <= nc < cols
                    and copied_grid[nr][nc] == 1
                ):
                    uf.union(current, index(nr, nc))

            after_roof_size = uf.size(roof)

            fallen_bricks = max(0, after_roof_size - before_roof_size - 1)

            result.append(fallen_bricks)

        return result[::-1]
```该实现首先定义具有路径压缩和按大小并集的并查数据结构。 这些优化确保了几乎恒定的时间连接操作。 

这`component_size`数组尤其重要，因为我们必须有效地确定任意时刻有多少块砖连接到屋顶。 

网格在修改之前被复制，因此我们可以区分：

 - 原本包含砖块的单元格
 - 始终为空的单元格

 所有命中都会首先应用于复制的网格。 这给出了每次移除后的最终网格状态。 

然后使用剩余的砖块建造 Union-Find 结构。 每个顶行砖都连接到虚拟屋顶节点。 

逆向加工时：

 - 我们一次修复一块砖
 - 将它们与相邻的砖块结合起来
 - 测量有多少新砖连接到屋顶

 屋顶组件尺寸的差异准确地告诉我们有多少砖块恢复了稳定性。 

最后，我们反转答案列表，因为命中是向后处理的。 

## 解决方案```go
package main

func hitBricks(grid [][]int, hits [][]int) []int {
	rows := len(grid)
	cols := len(grid[0])

	roof := rows * cols

	copiedGrid := make([][]int, rows)
	for r := 0; r < rows; r++ {
		copiedGrid[r] = make([]int, cols)
		copy(copiedGrid[r], grid[r])
	}

	for _, hit := range hits {
		r, c := hit[0], hit[1]
		if copiedGrid[r][c] == 1 {
			copiedGrid[r][c] = 0
		}
	}

	parent := make([]int, rows*cols+1)
	size := make([]int, rows*cols+1)

	for i := range parent {
		parent[i] = i
		size[i] = 1
	}

	var find func(int) int

	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}

	union := func(x, y int) {
		rootX := find(x)
		rootY := find(y)

		if rootX == rootY {
			return
		}

		if size[rootX] < size[rootY] {
			rootX, rootY = rootY, rootX
		}

		parent[rootY] = rootX
		size[rootX] += size[rootY]
	}

	getSize := func(x int) int {
		return size[find(x)]
	}

	index := func(r, c int) int {
		return r*cols + c
	}

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			if copiedGrid[r][c] == 0 {
				continue
			}

			current := index(r, c)

			if r == 0 {
				union(current, roof)
			}

			rightDown := [][]int{
				{1, 0},
				{0, 1},
			}

			for _, dir := range rightDown {
				nr := r + dir[0]
				nc := c + dir[1]

				if nr >= 0 && nr < rows &&
					nc >= 0 && nc < cols &&
					copiedGrid[nr][nc] == 1 {

					union(current, index(nr, nc))
				}
			}
		}
	}

	result := []int{}

	for i := len(hits) - 1; i >= 0; i-- {
		r, c := hits[i][0], hits[i][1]

		if grid[r][c] == 0 {
			result = append(result, 0)
			continue
		}

		before := getSize(roof)

		copiedGrid[r][c] = 1

		current := index(r, c)

		if r == 0 {
			union(current, roof)
		}

		for _, dir := range directions {
			nr := r + dir[0]
			nc := c + dir[1]

			if nr >= 0 && nr < rows &&
				nc >= 0 && nc < cols &&
				copiedGrid[nr][nc] == 1 {

				union(current, index(nr, nc))
			}
		}

		after := getSize(roof)

		fallen := after - before - 1
		if fallen < 0 {
			fallen = 0
		}

		result = append(result, fallen)
	}

	left, right := 0, len(result)-1
	for left < right {
		result[left], result[right] = result[right], result[left]
		left++
		right--
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一些特定于 Go 的细节值得注意：

 - 使用切片代替动态数组
 - 递归路径压缩是在`find`- 并查数组被显式初始化
 - 网格复制必须逐行完成，因为切片是引用
 - 结果反转是手动实现的，因为Go没有内置的反转助手

 整数溢出不是问题，因为最大单元数仅为`40,000`。

 ## 边缘情况

 当命中目标已经为空的单元格时，就会出现一种重要的边缘情况。 一个幼稚的实现可能会在逆向处理期间意外地恢复一个砖块，即使那里最初不存在砖块。 此实现通过在恢复之前检查原始网格来避免该错误。 如果原来的细胞是`0`，答案立即`0`。 

另一个关键的边缘情况涉及即使在撞击发生之前也没有连接到顶部的砖块。 这些砖块在概念上已经不稳定，尽管它们在受到影响之前一直存在。 反向联合查找方法自然可以处理这个问题，因为只有连接到屋顶的砖块才属于稳定组件。 断开的砖块永远不会导致屋顶尺寸的变化。 

当多个路径将组件连接到屋顶时，会出现一个特别棘手的情况。 移除一块砖可能看起来很重要，但仍然留下了替代的稳定路径。 如果未正确重新计算连接性，基于 DFS 的模拟很容易对此进行错误处理。 并查结构自然地处理了这个问题，因为连接性是全局性的，而不是局部性的。 

另一个微妙的情况是在逆向处理过程中恢复顶行砖块时。 这些砖块必须立即连接到虚拟屋顶节点。 忘记此步骤会导致所有下游稳定性计算变得不正确。 该实现在初始化和恢复过程中明确地将每个顶行砖块与屋顶结合起来。
