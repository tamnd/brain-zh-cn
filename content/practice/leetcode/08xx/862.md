[LeetCode 862 题](https://leetcode.com/problems/shortest-subarray-with-sum-at-least-k/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、队列、滑动窗口、堆（优先级队列）、前缀和、单调队列

 ## 解决方案

 ## 问题理解

 该问题要求我们找到最短连续子数组的长度，其总和至少为`k`。 

我们得到一个整数数组`nums`，可以包含正数和负数，以及一个整数`k`。 我们必须返回所有非空连续子数组中的最小长度，其总和大于或等于`k`。 如果不存在这样的子数组，我们返回`-1`。 

关键细节是子数组必须是连续的。 我们不允许跳过元素。 

例如，如果：```
nums = [2, -1, 2], k = 3
```整个数组的总和为`3`，所以答案是`3`。 

负数的存在使得这个问题变得困难。 如果所有数字都是正数，则标准滑动窗口将起作用，因为扩展窗口总是会增加总和。 对于负数，删除或添加元素可能会不可预测地增加或减少总数，因此正常的两指针方法会失败。 

限制条件很大：

 -`nums.length`可以达到`100000`- 值可以为负数
 -`k`可以大到`10^9`这些约束立即排除了二次解。 任何接近的算法`O(n^2)`会超时。 

几个重要的边缘情况自然会出现：

 - 不存在有效的子数组
 - 单个元素本身至少是`k`- 负值减少前缀和
 - 存在多个重叠的候选子数组
 - 非常大的正值和负值一起出现

 由于数组可以包含负数，因此我们需要一种策略来有效地找到有效的子数组，而无需检查每个可能的范围。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组。 

对于每个起始索引`i`，我们计算以每个结尾的子数组的总和`j >= i`。 每当总和至少变为`k`，我们更新找到的最短长度。 

这是有效的，因为它显式地评估每个连续的子数组，因此它不会错过最佳答案。 

然而，有`O(n^2)`子数组。 和`n = 100000`，这变得太慢了。 

甚至使用前缀和来计算每个子数组的和`O(1)`时间仍然留给我们`O(n^2)`总子数组。 

### 最佳解决方案的关键见解

 关键的观察是前缀和允许我们转换子数组条件。 

定义：```
prefix[i] = sum of first i elements
```然后子数组的和`[j, i)`是：```
prefix[i] - prefix[j]
```我们需要：```
prefix[i] - prefix[j] >= k
```重新排列：```
prefix[j] <= prefix[i] - k
```对于每个当前前缀和`prefix[i]`，我们想要找到最早有效的`j`产生最短的子数组。 

挑战在于有效地做到这一点。 

最佳解决方案使用单调双端队列：

 - 双端队列存储前缀和的索引
 - 双端队列中的前缀和按递增顺序维护
 - 如果新的前缀和小于旧的前缀和，则旧的前缀和无用，可以删除
 - 当当前前缀和与双端队列的前面形成一个有效的子数组时，我们更新答案并从前面弹出

 这保证了线性时间复杂度。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个可能的子数组 |
 | 最佳| O(n) | O(n) | 使用带有单调双端队列的前缀和 |

 ## 算法演练

 ### 第 1 步：构建前缀和

 我们创建一个前缀和数组，其中：```
prefix[i] = sum of nums[0:i]
```前缀数组有长度`n + 1`。 

这允许在恒定时间内计算任何子数组总和。 

### 步骤 2：初始化单调双端队列

 我们使用双端队列来存储前缀和的索引。 

双端队列维护递增的前缀和值。 

为什么增加订单很重要：

 如果我们已经有两个索引：```
i < j
```和：```
prefix[j] <= prefix[i]
```然后索引`i`再也没有用处了。 

任何未来的子数组使用`i`与使用相比会更长并且具有更大或相等的前缀和`j`。 

所以我们删除主导前缀和。 

### 步骤 3：迭代前缀和

 对于每个索引`i`在前缀数组中：

 #### 第一个条件：检查有效子数组

 同时：```
prefix[i] - prefix[deque[0]] >= k
```我们找到了一个有效的子数组。 

子数组长度为：```
i - deque[0]
```我们更新答案并从前面弹出。 

为什么流行？ 

因为一旦这个索引产生一个有效的子数组，任何未来使用相同起点的子数组只会更长。 

### 步骤 4：保持单调顺序

 虽然双端队列不为空并且：```
prefix[i] <= prefix[deque[-1]]
```我们删除后面的元素。 

当前的前缀和更好，因为：

 - 它更小
 - 稍后发生
 - 它可能会创建更短的未来子数组

 ### 步骤 5：添加当前索引

 将当前索引附加到双端队列。 

###第6步：返回结果

 如果我们从未找到有效的子数组，则返回`-1`。 

否则返回找到的最小长度。 

### 为什么它有效

 双端队列始终按前缀和的升序存储候选起始索引。 

对于每个当前前缀和：

 - 双端队列的前面给出了最早的有效子数组
 - 从后面删除较大的前缀和保证我们永远不会保留占主导地位的候选者
 - 每个索引最多进入和离开双端队列一次

 因为我们按顺序处理前缀和并始终维护最佳的候选者，所以该算法可以正确找到最短的有效子数组。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def shortestSubarray(self, nums: List[int], k: int) -> int:
        n = len(nums)

        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + nums[i]

        answer = n + 1
        mono_queue = deque()

        for i in range(n + 1):
            while mono_queue and prefix[i] - prefix[mono_queue[0]] >= k:
                answer = min(answer, i - mono_queue.popleft())

            while mono_queue and prefix[i] <= prefix[mono_queue[-1]]:
                mono_queue.pop()

            mono_queue.append(i)

        return answer if answer <= n else -1
```实现首先构建前缀和数组。 前缀数组有一个额外的元素，以便从索引开始的子数组`0`可以自然处理。 

变量`answer`存储迄今为止找到的最短有效长度。 它被初始化为`n + 1`，它充当一个不可能的大值。 

双端队列将索引存储到前缀和数组中，而不是前缀和本身。 

在主循环中，第一个`while`循环检查当前前缀和是否构成一个有效的子数组，其中最小的前缀和位于双端队列的前面。 如果是，我们更新答案并删除该索引，因为任何未来使用它的子数组都会更长。 

第二个`while`循环在双端队列中维护递增的前缀和。 任何更大或相等的前缀和都会被删除，因为当前的前缀和绝对更好。 

最后，附加当前索引。 

最后，如果`answer`从未更新过，我们回来了`-1`。 

## 解决方案```go
func shortestSubarray(nums []int, k int) int {
	n := len(nums)

	prefix := make([]int64, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + int64(nums[i])
	}

	answer := n + 1
	deque := make([]int, 0)

	for i := 0; i <= n; i++ {
		for len(deque) > 0 &&
			prefix[i]-prefix[deque[0]] >= int64(k) {

			length := i - deque[0]

			if length < answer {
				answer = length
			}

			deque = deque[1:]
		}

		for len(deque) > 0 &&
			prefix[i] <= prefix[deque[len(deque)-1]] {

			deque = deque[:len(deque)-1]
		}

		deque = append(deque, i)
	}

	if answer == n+1 {
		return -1
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个重要的区别是整数溢出处理。 由于前缀和可能会变大，因此前缀数组使用`int64`。 

Go 没有内置的双端队列结构，因此使用切片来代替。 从前面移除是通过以下方式完成的：```go
deque = deque[1:]
```并从后面删除使用切片截断。 

否则，算法保持不变。

 ## 边缘情况

 ### 不存在有效子数组

 当没有连续子数组达到总和时，会出现一个重要的边缘情况`k`。 

例如：```
nums = [1, 2]
k = 10
```有缺陷的实现可能会错误地返回较大的默认值或意外返回`0`。 

此实现将答案初始化为`n + 1`并且仅在找到有效的子数组时才更新它。 如果答案不变，算法正确返回`-1`。 

### 负数破坏标准滑动窗口逻辑

 负值是这个问题困难的主要原因。 

例如：```
nums = [2, -1, 2]
```正常的滑动窗口依赖于扩展窗口总是增加总和的假设。 这个假设在这里失败了，因为添加`-1`减少总数。 

单调双端队列方法通过使用前缀和而不是动态调整窗口边界来完全避免这个问题。 

### 具有非递增值的多个前缀和

 考虑：```
prefix = [0, 5, 3]
```前缀和`5`一次没用`3`稍后出现，因为：

 -`3`较小
 - 稍后出现
 - 它产生更短的未来子数组

 如果我们无法删除主导前缀和，我们可能会错过最佳答案或浪费时间处理不必要的候选者。 

第二个`while`循环确保双端队列始终保持单调，保证正确性和线性性能。
