[LeetCode 808 题](https://leetcode.com/problems/soup-servings/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划、概率与统计

 ## 解决方案

 ## 问题理解

 该问题给了我们两种汤，A 和 B，每种都以完全相同的开头`n`毫升。 每次，都会随机选择四个服务操作之一。 每个操作同时从 A 和 B 中删除不同的数量。 

四种可能的操作是：

 - 从 A 中取出 100 mL，从 B 中取出 0 mL
 - 从 A 中取出 75 mL，从 B 中取出 25 mL
 - 从 A 中取出 50 mL，从 B 中取出 50 mL
 - 从 A 中取出 25 mL，从 B 中取出 75 mL

 每个操作都有概率`0.25`。 

这个过程一直持续到至少一汤变空为止。 所需的返回值为：

 - A 在 B 之前变空的概率
 - 加上在同一操作期间两者都变空的概率的一半

 换句话说：

 - 如果A先空，则贡献`1`- 如果两者都空了，则贡献`0.5`- 如果B先空，则贡献`0`最终答案是所有可能的随机服务序列的预期概率值。 

一个非常重要的细节是，如果某个操作需要的汤多于剩余的汤，我们只需倒掉剩下的汤即可。 例如，如果 A 只剩下 20 mL，而我们尝试移除 100 mL，则 A 恰好变为 0。 

约束条件非常大：```
0 <= n <= 10^9
```对以毫升为单位测量的所有可能状态进行直接模拟是完全不可行的。 该解决方案必须利用数学结构和概率行为来显着减少状态空间。 

一些边缘情况很重要：

 -`n = 0`，两个汤都已经空了，所以答案应该是`0.5`- 非常大`n`，其中概率非常接近于收敛`1`- 两种汤同时变空的状态
 - 试图去除的汤多于剩余的汤的操作

 该问题保证答案只需要在`10^-5`，这对于优化至关重要。 

## 方法

 ### 蛮力方法

 简单的递归解决方案将显式地对每个可能的服务序列进行建模。 

来自一个州`(a, b)`，我们递归地尝试所有四个服务操作并平均它们的概率。 递归自然是由每个操作的相等概率得出的。 

递归关系将是：$$P(a,b)=\frac14\sum P(\text{next state})$$与基本情况：

 - 如果`a <= 0`和`b <= 0`， 返回`0.5`- 如果`a <= 0`， 返回`1`- 如果`b <= 0`， 返回`0`这给出了正确的答案，因为它精确地模拟了概率过程。 

然而，如果不进行优化，状态数量会呈指数级增长。 即使有记忆，使用原始毫升值仍然会创建太多状态`n`可以大到`10^9`。 

### 关键见解

 关键的观察是所有的份量都是`25`。 

操作是：

 -`(100, 0)`→`(4, 0)`-`(75, 25)`→`(3, 1)`-`(50, 50)`→`(2, 2)`-`(25, 75)`→`(1, 3)`除以之后`25`。 

这意味着我们可以通过将汤转换为 25 毫升的单位来缩小整个问题的规模。 

我们不跟踪精确的毫升，而是跟踪：$$m = \left\lceil \frac{n}{25} \right\rceil$$这极大地减少了状态空间。 

一个更重要的见解是，作为`n`变大，概率接近`1`。 发生这种情况是因为每次操作从 A 中移除的汤至少与从 B 中移除的汤一样多，并且平均而言 A 消耗得更快。 

根据经验和数学，一旦`n > 4800`，答案不同于`1`小于`10^-5`。 既然问题接受了这个容忍度，我们就可以直接返回`1.0`对于足够大的`n`。 

这将问题转化为可管理的记忆化动态编程解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 递归探索所有服务序列 |
 | 最佳 | O(平方米) | O(平方米) | 缩放状态上的记忆 DP |

 这里`m = ceil(n / 25)`并且有效地受约`200`因为大`n`优化。 

## 算法演练

 1.处理大的`n`首先优化。 

什么时候`n`变得足够大，答案非​​常接近`1`。 实证分析表明，对于`n > 4800`，错误已经在下面`10^-5`。 

所以：```
if n > 4800:
    return 1.0
```这避免了不必要的递归并保持算法的效率。 
2. 将问题转换为 25 mL 的单位。 

由于每个份量都可以被 25 整除，因此我们缩放状态空间：$$m = \left\lceil \frac{n}{25} \right\rceil$$在代码中：```
m = (n + 24) // 25
```这极大地减少了独特状态的数量。 
3. 定义递归DP函数。 

让：```
dp(a, b)
```表示 A 首先清空的概率加上平局概率的一半，从`a`A 的单位和`b`单位 B.
 4. 仔细定义基本案例。 

这些是停止条件：

 - 如果两个汤同时空了：```
return 0.5
```- 如果只有 A 为空：```
return 1.0
```- 如果只有 B 为空：```
return 0.0
```5. 递归地评估这四个操作。 

每个操作都有概率发生`0.25`。 

转变变成：

 -`(a-4, b)`-`(a-3, b-1)`-`(a-2, b-2)`-`(a-1, b-3)`其递归式为：$$dp(a,b)=\frac14\left( dp(a-4,b)+ dp(a-3,b-1)+ dp(a-2,b-2)+ dp(a-1,b-3) \right)$$6. 使用记忆法。 

许多状态在递归期间重复。 如果没有缓存，递归树将会呈指数级爆炸。 

记忆缓存存储先前计算的状态，因此每个状态仅计算一次。 
7. 返回最终答案。 

最终状态是：```
dp(m, m)
```### 为什么它有效

 该算法之所以有效，是因为递归精确地模拟了问题中描述的概率过程。 每个状态转换对应一个可能的服务操作，并且每个操作以概率同等贡献`0.25`。 

基本情况正确编码评分规则：

 -`1`当A先空时
 -`0.5`当两者都空时
 -`0`当B先空时

 记忆化保证每个状态被评估一次，并且按 25 缩放可以保持正确性，因为每个服务操作仅以 25 的倍数改变汤量。 

## Python 解决方案```python
class Solution:
    def soupServings(self, n: int) -> float:
        if n > 4800:
            return 1.0

        units = (n + 24) // 25
        memo = {}

        def dp(a: int, b: int) -> float:
            if a <= 0 and b <= 0:
                return 0.5

            if a <= 0:
                return 1.0

            if b <= 0:
                return 0.0

            if (a, b) in memo:
                return memo[(a, b)]

            probability = 0.25 * (
                dp(a - 4, b) +
                dp(a - 3, b - 1) +
                dp(a - 2, b - 2) +
                dp(a - 1, b - 3)
            )

            memo[(a, b)] = probability
            return probability

        return dp(units, units)
```实现从大输入优化开始。 对于足够大的`n`，概率有效地为`1`，所以我们立即返回。 

接下来，将汤量换算成 25 mL 单位。 这种压缩至关重要，因为它大大减少了状态数量。 

递归`dp`函数计算给定状态的概率`(a, b)`。 

基本案例直接编码问题需求：

 - 都是空的 →`0.5`- 只有A空→`1.0`- 只有B空→`0.0`备忘录字典缓存先前计算的状态。 这可以防止冗余递归计算并将指数递归转换为多项式复杂度。 

最后，递归对四个同样可能的服务操作进行平均，并将结果存储在缓存中。 

## 解决方案```go
func soupServings(n int) float64 {
    if n > 4800 {
        return 1.0
    }

    units := (n + 24) / 25

    memo := make(map[[2]int]float64)

    var dp func(int, int) float64

    dp = func(a int, b int) float64 {
        if a <= 0 && b <= 0 {
            return 0.5
        }

        if a <= 0 {
            return 1.0
        }

        if b <= 0 {
            return 0.0
        }

        key := [2]int{a, b}

        if value, exists := memo[key]; exists {
            return value
        }

        probability := 0.25 * (
            dp(a-4, b) +
                dp(a-3, b-1) +
                dp(a-2, b-2) +
                dp(a-1, b-3),
        )

        memo[key] = probability
        return probability
    }

    return dp(units, units)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

具有固定大小数组键的 Go 映射用于记忆：```go
map[[2]int]float64
```这是记忆二维 DP 状态的有效且惯用的方法。 

Go 不直接支持嵌套命名函数，因此递归闭包声明为：```go
var dp func(int, int) float64
```分配之前。 

整数溢出不是问题，因为优化截止后缩放后的状态大小仍然非常小。 

## 工作示例

 ### 示例 1

 输入：```
n = 50
```缩放单位：$$m = \lceil 50/25 \rceil = 2$$初始状态：```
dp(2, 2)
```可能的操作：

 | 运营| 下一个状态 | 结果 |
 | ---| ---| ---|
 | (4,0) | (-2,2) | (-2,2) | 首先是一个空 → 1 |
 | (3,1) | (-1,1) | (-1,1) | 首先是一个空 → 1 |
 | (2,2) | (0,0) | (0,0) | 均为空 → 0.5 |
 | (1,3) | (1,-1) | (1,-1) | B先空→0|

 最终概率：$$0.25 \times (1 + 1 + 0.5 + 0)$$

$$= 0.625$$### 示例 2

 输入：```
n = 100
```缩放单位：$$m = 4$$初始状态：```
dp(4,4)
```递归求值扩展到更小的状态。 

| 过渡 | 下一个状态 |
 | --- | --- |
 | (4,0) | (0,4) |
 | (3,1) | (1,3) |
 | (2,2) | (2,2) |
 | (1,3) | (3,1) |

 递归评估：

 | 状态| 概率 |
 | --- | --- |
 | dp(0,4) | dp(0,4) | 1 |
 | dp(1,3) | dp(1,3) | 0.875 | 0.875
 | dp(2,2) | dp(2,2) | 0.625 | 0.625
 | dp(3,1) | dp(3,1) | 0.375 | 0.375

 最终结果：$$0.25 \times (1 + 0.875 + 0.625 + 0.375)$$

$$= 0.71875$$## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(平方米) | 每个缩放状态`(a,b)`计算一次 |

 这里：$$m = \left\lceil \frac{n}{25} \right\rceil$$然而，因为我们立即返回`n > 4800`,`m`有效地受约`192`。 这使得该解决方案在实践中速度极快。 

递归仅探索可达状态，并且记忆化确保不会重新计算任何状态。

 ## 边缘情况

 一个重要的边缘情况是`n = 0`。 在这种情况下，在上菜之前，两种汤都已经空了。 根据问题陈述，同时清空有助于`0.5`到最终的概率。 幼稚的实现可能会错误地返回`1`或者`0`。 该实现通过基本情况正确处理了这个问题：```
if a <= 0 and b <= 0:
    return 0.5
```当上菜操作去除的汤多于剩余的汤时，就会出现另一个关键的边缘情况。 例如，如果只剩下 10 mL 的 A，而我们尝试除去 100 mL，则汤就会变空。 假设没有钳位的精确减法的实现可能会产生无效的负状态逻辑。 该解决方案通过允许负值并使用检查基本情况自然地避免了该问题`<= 0`。 

非常大的输入是另一个主要的边缘情况。 自从`n`可以大到`10^9`，任何尝试建立与 DP 表成比例的解决方案`n`会立即失败。 该实现使用两种优化来处理这个问题：

 - 缩放 25
 - 提前返回`n > 4800`如果没有这种优化，即使是记忆也可能变得不必要的昂贵。 

一个微妙的边缘情况涉及缩放期间的舍入。 由于操作以 25 mL 为增量进行，因此值如`n = 1`仍然表现得像一个完整的 25 mL 装置。 使用楼层划分会错误地将此类情况映射到零。 该实现正确地使用了上限除法：```
(n + 24) // 25
```它保留了正确的概率行为。
