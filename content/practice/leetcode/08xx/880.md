[LeetCode 第 880 题](https://leetcode.com/problems/decoded-string-at-index/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈

 ## 解决方案

 ## 问题理解

 问题给了我们一个编码字符串`s`这代表了一个潜在的巨大的解码字符串。 解码过程从左到右递增进行。 

当我们遇到一个字母时，我们将其直接附加到解码的磁带上。 当我们遇到一个数字时`d`，我们重复整个当前解码的磁带`d`总共次数。 换句话说，现有磁带被复制`d - 1`额外的时间。 

任务不是完全解码字符串。 相反，我们只需要确定位于位置的字符`k`在完全解码的字符串中，索引从 1 开始。 

例如，考虑：```
s = "leet2code3"
```解码过程变为：```
"leet"
"leetleet"
"leetleetcode"
"leetleetcodeleetleetcodeleetleetcode"
```第10个字符是`"o"`。 

最重要的限制是解码后的字符串可能会变得非常大。 该问题保证解码后的长度小于`2^63`，这意味着它仍然太大而无法在内存中显式构造。 尽管输入字符串长度最多为 100，但重复数字相乘可以创建包含数万亿或五亿字符的解码字符串。 

这立即告诉我们任何实际构建解码字符串的方法都是不可行的。 

一些边缘情况很重要：

 - 单个字符可以通过重复乘法扩展多次。 
- 答案可能隐藏在重复部分的深处。 
-`k`可以指向与扩展之前的较早前缀相对应的位置。 
- 解码长度可能超出标准 32 位整数范围，因此实现必须小心处理大数字。 
- 字符串始终以字母开头，这简化了初始化逻辑。 
- 该问题保证`k`在解码的字符串长度内始终有效。 

## 方法

 ### 蛮力方法

 最直接的解决方案是逐字解码字符串。 

我们迭代通过`s`逐个字符。 如果字符是字母，我们将其附加到不断增长的解码字符串中。 如果字符是数字`d`，我们重复当前解码的字符串`d`次。 

一旦构建了解码的字符串，我们只需返回索引处的字符`k - 1`。 

这种方法是正确的，因为它直接模拟问题陈述中描述的解码规则。 

然而，对于给定的约束，这是完全不切实际的。 解码后的字符串可能包含多达近`2^63`人物。 构造这样的字符串需要大量的内存和时间。 

### 最佳方法

 关键的见解是我们实际上不需要解码的字符串本身。 我们只需要知道哪个原始角色对`k`th 位置。 

我们在处理字符时只跟踪解码字符串的长度，而不是向前解码。 

假设解码后的长度变为`size`。 

- 如果我们看到一个字母，大小就会增加 1。 
- 如果我们看到一个数字`d`，整个当前字符串被重复`d`次，所以尺寸变成`size * d`。 

计算出最终的解码长度后，我们向后处理编码字符串。 

这种反向遍历是至关重要的观察。 

向后移动时：

 - 如果我们遇到一个数字`d`，这意味着当前解码的字符串是通过重复较早的字符串形成的`d`次。 
- 因此，位置`k`里面重复的字符串对应于：```
k % previous_size
```这有效地“倒回”了扩展。 

如果我们遇到一封信并且`k`正是指向那个位置，我们已经找到了答案。 

这种方法完全避免了构造解码字符串，并且在线性时间内工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(解码长度) | O(解码长度) | 显式构建完整的解码字符串 |
 | 最佳| O(n) | O(1) | O(1) | 无需解码即可跟踪长度并向后工作 |

 ## 算法演练

 1. 初始化变量`decoded_length`到`0`。 

该变量表示当前处理点的解码字符串的长度。 
2. 从左到右遍历编码后的字符串。 

对于每个字符：

 - 如果是字母，则递增`decoded_length`经过`1`。 
- 如果是数字`d`, 乘以`decoded_length`经过`d`。 

经过这一关后，`decoded_length`等于完全解码的字符串的总长度。 
3. 再次遍历编码后的字符串，这次是从右向左。 

我们现在向后确定哪个原始字符映射到位置`k`。 
4. 在每一步中，减少`k`使用模运算。 

计算：```
k = k % decoded_length
```此步骤至关重要，因为重复的部分会环绕。 如果解码后的字符串由重复的副本组成，则位置`k`重复块内对应于原始块内的等效位置。 
5. 如果当前字符是字母，检查是否是答案。 

如果：```
k == 0
```或者```
k == decoded_length
```那么当前的字母正是我们要搜索的字符。 
6.如果当前字符是数字`d`, 除`decoded_length`经过`d`。 

这将反转扩展操作并恢复重复之前的大小。 
7. 如果当前字符是字母并且不是答案，则递减`decoded_length`经过`1`。 

这会逆转在正向处理期间添加该字母的效果。 
8. 继续，直到找到答案。 

### 为什么它有效

 该算法依赖于重复创建循环结构的事实。 当一个字符串长度`L`被重复`d`次，扩展字符串内的任何位置都对应于原始字符串内的模数位置`L`。 

通过向后遍历并反复缩小解码长度，我们映射目标索引`k`回溯每个扩展，直到它对应于原始编码中的具体字母。 由于每个反向步骤都精确地撤消一个前向解码步骤，因此映射在整个过程中保持正确。 

## Python 解决方案```python
class Solution:
    def decodeAtIndex(self, s: str, k: int) -> str:
        decoded_length = 0

        # Compute total decoded length
        for char in s:
            if char.isdigit():
                decoded_length *= int(char)
            else:
                decoded_length += 1

        # Work backward to find the kth character
        for char in reversed(s):
            k %= decoded_length

            if k == 0 and char.isalpha():
                return char

            if char.isdigit():
                decoded_length //= int(char)
            else:
                decoded_length -= 1

        return ""
```该实现遵循算法演练中描述的确切逻辑。 

第一个循环计算总解码长度，而不构造实际的解码字符串。 字母将大小增加一，而数字将当前大小增加一倍。 

第二个循环以相反的顺序处理字符串。 在每次迭代中，`k %= decoded_length`将当前索引映射到上一个未展开部分中的适当位置。 

当遇到一封信并且`k == 0`，该字母一定是答案，因为模运算已将搜索范围缩小到该确切位置。 

如果当前字符是数字，我们通过除以解码长度来反转扩展。 如果当前字符是字母，我们通过减一来反转之前的增量。 

一旦识别出正确的字母，算法就会终止。 

## 解决方案```go
func decodeAtIndex(s string, k int) string {
    decodedLength := 0

    // Compute total decoded length
    for _, ch := range s {
        if ch >= '0' && ch <= '9' {
            decodedLength *= int(ch - '0')
        } else {
            decodedLength++
        }
    }

    // Work backward
    for i := len(s) - 1; i >= 0; i-- {
        ch := s[i]

        k %= decodedLength

        if k == 0 && (ch >= 'a' && ch <= 'z') {
            return string(ch)
        }

        if ch >= '0' && ch <= '9' {
            decodedLength /= int(ch - '0')
        } else {
            decodedLength--
        }
    }

    return ""
}
```Go 实现与 Python 版本非常相似，但有一些特定于语言的注意事项。 

Go 没有提供内置的`isdigit`或者`isalpha`字节方法，因此使用 ASCII 比较手动检查字符范围。 

使用索引向后遍历字符串，因为 Go 字符串是字节切片。 由于输入仅包含小写英文字母和数字，因此字节索引安全高效。 

整数运算使用 Go 的`int`类型。 该问题保证解码长度符合`2^63`，因此这可以在 LeetCode 通常使用的现代 64 位系统上正常工作。

 ## 边缘情况

 当解码的字符串变得非常大时，就会出现一种重要的边缘情况。 构造字符串的简单解决方案很快就会耗尽内存或时间。 例如，`"a2345678999999999999999"`膨胀到一个天文数字般的大小。 最佳解决方案通过仅存储解码的长度而不是实际的字符串来完全避免这种情况。 

另一个微妙的边缘情况发生在`k`正好落在重复块的边界处。 在向后遍历期间，算法使用：```
k %= decoded_length
```如果结果变成`0`，表示目标字符对应当前前缀的最后一个字符。 许多不正确的实现都会错误地处理这种情况并产生相差一的错误。 条件：```
if k == 0 and char.isalpha():
```正确识别了这种情况。 

第三个重要的边缘情况涉及乘法器的重复嵌套。 考虑一个像这样的字符串`"ha22"`。 解码后的字符串从先前扩展的内容中扩展了多次。 前向解码模拟将重复复制大字符串。 反向遍历自然地处理了这个问题，因为每个数字只是通过除法和模运算来减少问题的大小。 

错误的另一个潜在来源是整数溢出。 解码长度可以超出标准 32 位整数范围。 两种实现都使用能够在问题约束下安全处理大值的整数类型。
