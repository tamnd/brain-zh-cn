[LeetCode 第 879 题](https://leetcode.com/problems/profitable-schemes/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算有多少犯罪子集同时满足两个约束：

 1、使用会员总数最多为`n`2. 赚取的总利润至少为`minProfit`每个犯罪都有两个属性：

 -`group[i]`, 所需成员数量
 -`profit[i]`，产生的利润

 一个成员不能参与多项犯罪，这意味着所选犯罪所使用的成员总数不能超过`n`。 

我们并不是试图最大化利润或最小化会员。 相反，我们必须计算所有有效的犯罪子集。 

重要的细节是这是一个子集选择问题。 每项犯罪都可以：

 - 纳入计划
 - 或被排除在外

 这立即表明了一个大小的组合搜索空间`2^m`， 在哪里`m = len(group)`。 

输出是有效子集的数量，其：

 - 使用的会员总数`<= n`- 利润总额`>= minProfit`因为答案可能变得非常大，所以我们返回模数结果`10^9 + 7`。 

约束条件至关重要：

 -`n <= 100`-`minProfit <= 100`- 犯罪数量`<= 100`这些值对于暴力子集枚举来说太大了，因为`2^100`是一个天文数字。 然而，它们对于动态规划来说足够小，索引如下：

 - 使用的成员数量
 - 累计利润

 一个重要的观察是利润值大于`minProfit`不需要区分。 一旦我们到达`minProfit`，额外利润不会改变有效性。 这使我们能够将利润范围限制在`minProfit`。 

一些重要的边缘情况包括：

 -`minProfit = 0`，其中甚至空子集也是有效的
 - 犯罪行为`profit[i] = 0`- 犯罪需要比目前更多的成员
 - 许多不同子集产生相同利润和成员数量的组合
 - 确保我们在 DP 转换期间不会重复计算子集

 ## 方法

 ### 蛮力

 暴力解决方案会尝试所有可能的犯罪子集。 

对于每个子集：

 1. 计算使用的成员总数
 2. 计算赚取的总利润
 3. 检查是否：

 - 使用会员`<= n`- 利润`>= minProfit`如果两个条件都成立，则增加答案。 

这是有效的，因为每个可能的方案都被明确地检查一次。 

然而，如果有`m`犯罪行为，有`2^m`子集。 自从`m`可以大到100，这种做法是完全不可行的。 

### 关键见解

 关键的观察结果是，这是一个约束子集计数问题，是类似于 0/1 背包的经典动态规划模式。 

每项犯罪都会造成：

 - 一些会员费用
 - 一些利润增长

 在每一步中，我们都会决定是否包含或排除该犯罪行为。 

DP 状态必须跟踪：

 - 目前有多少会员在使用
 - 已经积累了多少利润

 因为任何利润大于`minProfit`就有效性而言是等效的，我们使用以下方法限制利润：```
newProfit = min(minProfit, currentProfit + crimeProfit)
```这极大地减少了 DP 状态空间。 

我们在以下情况下使用动态规划：```
dp[members][profit]
```存储数量的实现方法：

 - 正是`members`使用会员
 - 至少`profit`累计利润，上限为`minProfit`这将指数子集枚举问题转换为多项式时间 DP 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^m * m) | O(2^m * m) | O(1) | O(1) | 列举犯罪的每个子集 |
 | 最佳| O(m * n * 最小利润) | O(n * 最小利润) | 具有利润上限的动态规划|

 这里，`m`是犯罪数量。 

## 算法演练

 ### 第 1 步：定义 DP 状态

 我们创建一个 2D DP 表：```
dp[members][profit]
```在哪里：

-`members`范围从`0`到`n`-`profit`范围从`0`到`minProfit`每个单元存储实现该状态的方案的数量。 

利润维度上限为`minProfit`因为大于这个的利润是等价的。 

### 第 2 步：初始化基本案例

 首先，在选择任何犯罪之前：

 - 我们使用`0`会员
 - 我们赚到`0`利润

 所以：```
dp[0][0] = 1
```这代表空子集。 

### 步骤 3：一一处理犯罪行为

 对于每项犯罪：

 - 所需成员=`g`- 产生的利润=`p`我们决定是否将其纳入现有计划中。 

这是一个经典的 0/1 背包过渡。 

### 步骤 4：向后迭代

 我们向后迭代成员计数：```sql
for members from n down to g
```向后迭代可以防止在同一迭代中多次重复使用相同的犯罪行为。 

同样，我们向后迭代利润。 

### 步骤 5：过渡状态

 假设我们已经有：```
dp[oldMembers][oldProfit]
```如果我们包括当前的犯罪：```
newMembers = oldMembers + g
newProfit = min(minProfit, oldProfit + p)
```然后：```
dp[newMembers][newProfit] += dp[oldMembers][oldProfit]
```我们取模`10^9 + 7`。 

### 第 6 步：计算最终答案

 任何具有以下条件的州：```
profit == minProfit
```代表一个有效的盈利方案。 

所以答案是：```
sum(dp[members][minProfit] for members in range(n + 1))
```### 为什么它有效

 DP 在处理完第一个数据后保持不变量`i`罪行：```
dp[members][profit]
```等于那些准确使用的犯罪的子集数量`members`会员并达到上限利润水平`profit`。 

每个犯罪行为只处理一次，并且向后迭代保证犯罪行为不能多次重复使用。 由于每个子集对应于包含/排除决策的唯一序列，因此每个有效方案仅计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def profitableSchemes(
        self,
        n: int,
        minProfit: int,
        group: List[int],
        profit: List[int]
    ) -> int:
        
        MOD = 10**9 + 7
        
        dp = [[0] * (minProfit + 1) for _ in range(n + 1)]
        dp[0][0] = 1
        
        for required_members, earned_profit in zip(group, profit):
            
            for members in range(n, required_members - 1, -1):
                for current_profit in range(minProfit, -1, -1):
                    
                    previous_members = members - required_members
                    
                    new_profit = min(
                        minProfit,
                        current_profit + earned_profit
                    )
                    
                    dp[members][new_profit] = (
                        dp[members][new_profit]
                        + dp[previous_members][current_profit]
                    ) % MOD
        
        answer = 0
        
        for members in range(n + 1):
            answer = (answer + dp[members][minProfit]) % MOD
        
        return answer
```实施过程首先创建一个按会员数量和利润水平索引的 2D DP 表。 

基本情况：```python
dp[0][0] = 1
```代表空子集。 

对于每一项犯罪，我们都会向后迭代可能的会员数量和利润。 向后迭代至关重要，因为它可以防止在单次迭代期间多次重复使用相同的犯罪行为。 

该转换将当前犯罪添加到之前可到达的状态。 利润的上限使用：```python
min(minProfit, current_profit + earned_profit)
```这使 DP 表保持有界。 

最后，我们将利润指数等于的所有州相加`minProfit`，因为这代表所有计划至少实现所需的利润。 

## 解决方案```go
func profitableSchemes(n int, minProfit int, group []int, profit []int) int {
	const MOD int = 1000000007

	dp := make([][]int, n+1)

	for i := 0; i <= n; i++ {
		dp[i] = make([]int, minProfit+1)
	}

	dp[0][0] = 1

	for i := 0; i < len(group); i++ {
		requiredMembers := group[i]
		earnedProfit := profit[i]

		for members := n; members >= requiredMembers; members-- {
			for currentProfit := minProfit; currentProfit >= 0; currentProfit-- {

				previousMembers := members - requiredMembers

				newProfit := currentProfit + earnedProfit
				if newProfit > minProfit {
					newProfit = minProfit
				}

				dp[members][newProfit] =
					(dp[members][newProfit] +
						dp[previousMembers][currentProfit]) % MOD
			}
		}
	}

	answer := 0

	for members := 0; members <= n; members++ {
		answer = (answer + dp[members][minProfit]) % MOD
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 

Go对DP表使用切片，并且避免了整数溢出，因为所有操作都减少了模数`1e9 + 7`。 

与 Python 不同，Go 需要显式初始化 2D 切片结构。 

向后迭代逻辑保持相同，并且对于正确性同样重要。

## 测试用例```python
from typing import List

class Solution:
    def profitableSchemes(
        self,
        n: int,
        minProfit: int,
        group: List[int],
        profit: List[int]
    ) -> int:
        
        MOD = 10**9 + 7
        
        dp = [[0] * (minProfit + 1) for _ in range(n + 1)]
        dp[0][0] = 1
        
        for required_members, earned_profit in zip(group, profit):
            for members in range(n, required_members - 1, -1):
                for current_profit in range(minProfit, -1, -1):
                    
                    previous_members = members - required_members
                    
                    new_profit = min(
                        minProfit,
                        current_profit + earned_profit
                    )
                    
                    dp[members][new_profit] = (
                        dp[members][new_profit]
                        + dp[previous_members][current_profit]
                    ) % MOD
        
        return sum(dp[m][minProfit] for m in range(n + 1)) % MOD

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`minProfit = 0`。 在这种情况下，即使是空子集也被认为是有利可图的，因为至少赚取零利润总是令人满意的。 许多不正确的实现忘记计算空方案。 此实现通过基本初始化自然地处理它：```
dp[0][0] = 1
```当犯罪活动需要的成员数量超出可用数量时，就会发生另一种棘手的情况。 例如：```
n = 5
group[i] = 6
```这样的犯罪是绝对不能选择的。 后向成员迭代：```
for members in range(n, required_members - 1, -1):
```自动跳过不可能的转换。 

第三个重要的边缘情况涉及利润大于`minProfit`。 认为：```
minProfit = 5
current profit = 4
crime profit = 10
```新的利润变为 14，但我们不需要为 6、7、8 等单独的状态。 它们都是等效的，因为它们已经满足要求。 该实施使用以下方式正确限制利润：```
min(minProfit, current_profit + earned_profit)
```这使 DP 表保持紧凑并防止不必要的状态爆炸。 

另一个微妙的问题是避免多次重复使用同一犯罪行为。 如果我们向前迭代而不是向后迭代，则新更新的状态可以立即在同一迭代中重用，从而有效地允许无限制地使用犯罪。 向后迭代保证每个方案最多对每个犯罪计数一次。
