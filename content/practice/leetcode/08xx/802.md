[LeetCode 802 题](https://leetcode.com/problems/find-eventual-safe-states/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个表示为邻接表的有向图。 每个节点代表一种状态，每个有向边代表从一个节点到另一个节点的可能转换。 

输入`graph[i]`包含从节点可以直接到达的所有节点`i`。 如果`graph[i]`为空，则节点`i`是终端节点，因为没有传出边。 

目标是确定哪些节点“最终安全”。 如果从该节点开始的每条可能路径最终都在终端节点结束，则该节点被认为是安全的。 换句话说，无论我们遵循哪条出边，我们都不会陷入循环。 

这个定义很重要，因为即使一条可能的路径导致循环，节点也会变得不安全。 循环意味着我们可以永远继续遍历而不会到达终端节点。 

考虑以下情况：

 - 终端节点总是安全的，因为它已经立即结束。 
- 只指向安全节点的节点也是安全的。 
- 能够到达环路的节点是不安全的。 
- 循环内的任何节点都是不安全的。 

约束条件告诉我们：

 - 最多可以有`10^4`节点。 
- 最多可以有`4 * 10^4`边缘。 

这意味着我们需要一个接近线性时间的算法，具体来说`O(V + E)`， 在哪里：

-`V`是顶点数
 -`E`是边数

 独立地重复探索来自每个节点的路径的简单方法可能会变得太慢。 

有几个边缘情况值得注意：

 - 自循环，例如`0 -> 0`创建循环，因此这些节点是不安全的。 
- 可能存在断开的组件，因此我们必须独立评估每个节点。 
- 一个节点可能有多个出边，其中只有一个会导致环路。 该节点仍然不安全。 
- 大图需要尽可能避免重复的 DFS 遍历。 

关键的挑战是确定哪些节点保证不参与或到达任何周期。 

## 方法

 ### 蛮力方法

 一种直接的方法是从每个节点独立地启动 DFS，并确定该遍历最终是否达到循环。 

对于每个节点：

 1. 执行DFS。 
2. 跟踪当前的递归路径。 
3. 如果我们重新访问当前 DFS 路径中已有的节点，我们会发现一个循环。 
4. 如果所有路径都安全终止，则将该节点标记为安全。 

这是可行的，因为 DFS 自然地探索从节点开始的所有可能的可达路径。 

然而，这种方法变得低效，因为许多子图被重复探索。 如果多个节点共享相同的后代，我们会一遍又一遍地重新计算相同的结果。 

在最坏的情况下，每个节点的 DFS 可能会遍历几乎整个图。 

### 最优方法，带有状态着色的 DFS

 关键的见解是图的安全性完全取决于循环检测。 

当且仅当一个节点无法到达环时，它才是安全的。 

我们可以在 DFS 期间将节点分类为状态，而不是重复重新计算结果：

 -`0`= 未访问过
 -`1`= 正在访问，当前位于递归堆栈中
 -`2`= 安全，已验证

 DFS 期间：

 - 如果我们遇到一个被标记的节点`1`，我们发现了一个循环。 
- 如果我们遇到一个被标记的节点`2`，我们已经知道它是安全的。 
- 只有当一个节点的所有邻居都被确认安全后，该节点才变得安全。 

这避免了重复计算，因为每个节点都被处理一次。 

该算法有效地记忆了 DFS 结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(V × (V + E)) | O(V) | 对许多节点重复 DFS 工作 |
 | 最佳| O(V + E) | O(V) | 具有记忆节点状态的 DFS |

 ## 算法演练

 ### 最优DFS状态着色算法

 1. 创建一个`state`大小数组`n`。 

每个节点可以处于以下三种状态之一：

 -`0`= 未访问过
 -`1`= 访问
 -`2`= 安全

 该数组使我们能够检测循环并避免重复工作。 
2. 为节点定义DFS函数。 

DFS函数返回`True`如果节点是安全的并且`False`否则。 
3. 如果该节点当前被标记为`1`， 返回`False`。 

这意味着我们在探索该节点时再次遇到该节点，这表明存在循环。 
4. 如果该节点已经被标记为`2`， 返回`True`。 

我们之前已经证明了这个节点是安全的。 
5. 将当前节点标记为`1`。 

这表明该节点当前位于递归堆栈内。 
6. 探索所有外出邻居。 

对于每个邻居：

 - 递归运行 DFS。 
- 如果任何邻居不安全，请立即返回`False`。 

仅当每个可能的传出路径都是安全的时，节点才是安全的。 
7. 所有邻居都验证安全后，将当前节点标记为`2`。 

这会将该节点永久记录为安全节点。 
8. 对每个节点运行 DFS`0`到`n - 1`。 

如果DFS返回`True`，将节点追加到结果列表中。 
9. 返回结果列表。 

由于我们按升序处理节点，因此输出会自动排序。 

### 为什么它有效

 该算法保持一个关键的不变量：

 - 仅当来自该节点的每条可达路径都被验证为安全后，该节点才会被标记为安全。 

循环检测之所以有效，是因为对当前递归堆栈中的节点的任何重新访问都表明有向循环。 

记忆化之所以有效，是因为一旦节点被证明是安全的，其结果就永远不会改变。 未来的每个 DFS 都可以立即重用该信息。 

由于每个节点和边最多被处理一次，因此该算法既正确又高效。 

## Python 解决方案```python
from typing import List

class Solution:
    def eventualSafeNodes(self, graph: List[List[int]]) -> List[int]:
        n = len(graph)

        # 0 = unvisited
        # 1 = visiting
        # 2 = safe
        state = [0] * n

        def dfs(node: int) -> bool:
            # Found a cycle
            if state[node] == 1:
                return False

            # Already known to be safe
            if state[node] == 2:
                return True

            # Mark as visiting
            state[node] = 1

            # Explore neighbors
            for neighbor in graph[node]:
                if not dfs(neighbor):
                    return False

            # All neighbors are safe
            state[node] = 2
            return True

        result = []

        for node in range(n):
            if dfs(node):
                result.append(node)

        return result
```实施首先创建`state`array，它跟踪每个节点的DFS状态。 

嵌套的`dfs`功能执行实际循环检测和安全验证。 

第一个条件检查当前是否正在访问该节点。 如果是这样，我们就发现了一个循环，因为该节点再次出现在活动递归路径中。 

第二个条件检查节点是否已被确认安全。 这起到记忆作用并防止重复遍历。 

当访问一个新节点时，我们将其标记为`1`在探索邻居之前。 这对于循环检测至关重要。 

该循环遍历每个传出邻居。 如果任何邻居不安全，则当前节点也必定不安全，因为至少有一条路径导致环路。 

如果所有邻居都是安全的，我们将该节点标记为`2`，这意味着它被永久验证为安全的。 

最后，我们从每个节点运行 DFS 并收集 DFS 返回的所有节点`True`。 

## 解决方案```go
func eventualSafeNodes(graph [][]int) []int {
	n := len(graph)

	// 0 = unvisited
	// 1 = visiting
	// 2 = safe
	state := make([]int, n)

	var dfs func(int) bool

	dfs = func(node int) bool {
		// Found a cycle
		if state[node] == 1 {
			return false
		}

		// Already known safe
		if state[node] == 2 {
			return true
		}

		// Mark as visiting
		state[node] = 1

		// Explore neighbors
		for _, neighbor := range graph[node] {
			if !dfs(neighbor) {
				return false
			}
		}

		// Mark as safe
		state[node] = 2
		return true
	}

	result := []int{}

	for node := 0; node < n; node++ {
		if dfs(node) {
			result = append(result, node)
		}
	}

	return result
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

切片用于邻接列表和状态数组。 Go 不像 Python 那样区分列表和数组，因此切片是自然的选择。 

递归 DFS 函数是使用函数变量声明的，因此它可以递归引用自身。 

不存在整数溢出问题，因为节点索引受到问题约束的限制。 

一个空的邻接表自然地代表终端节点，就像在 Python 中一样。

 ## 边缘情况

 ### 自循环

 一个节点可能会指向它自己，比如`0 -> 0`。 

这是一个长度为一的循环。 仅检查重复邻居而不跟踪递归状态的简单实现可能无法正确检测到它。 

DFS 着色方法自然地处理了这个问题，因为节点被标记为`visiting`在探索邻居之前。 当DFS再次到达同一节点时，算法立即检测到循环。 

### 具有混合传出路径的节点

 一个节点可能有多个传出边，其中一些路径是安全的，而其他路径则到达循环。 

例如：```
0 -> 1
0 -> 2
2 -> 2
```尽管从一条路`0`是安全的，循环路径的存在使得节点`0`不安全。 

该实现正确地处理了这个问题，因为每个邻居都必须返回`True`在当前节点可以被标记为安全之前。 

### 断开连接的图组件

 该图可能包含几个不相连的部分。 

有些组件可能是完全安全的，而另一些组件则包含循环。 

仅从单个节点启动 DFS 的解决方案会丢失部分图。 

该实现显式地为每个节点运行 DFS`0`到`n - 1`，确保所有组件都得到独立评估。
