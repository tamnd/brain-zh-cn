 **难度：** 🟡 中等
 **主题：** 数组、哈希表、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们找到形成类斐波那契序列的严格递增数组中最长子序列的长度。 

类斐波那契数列遵循以下规则：$x_i + x_{i+1} = x_{i+2}$对于序列中的每个有效索引，并且序列必须至少包含三个数字。 

与经典的斐波那契数列不同，这里的数列不必以`1, 1`。 只要每个后续数字都是前两个数字之和，任何起始对都是有效的。 

输入是严格递增的正整数数组。 由于数组是严格递增的，因此每个值最多出现一次，这对于高效的查找策略变得极其重要。 我们可以在保留顺序的同时删除元素，这意味着我们正在寻找子序列而不是连续的子数组。 

输出是最长有效的类斐波那契子序列的长度。 如果不存在长度至少为 3 的子序列，我们返回`0`。 

这些约束告诉我们很多关于预期解决方案的信息：

 -`arr.length <= 1000`- 值可以大到`10^9`一个`O(n^3)`解决方案在实践中可能是边缘或太慢`n = 1000`，尤其是在 Python 中。 这强烈表明我们需要一个动态规划解决方案`O(n^2)`。 

一些边缘情况很重要：

 - 该数组可能根本不包含类似斐波那契的子序列。 
- 可能存在多个子序列，但我们只需要最大长度。 
- 大整数值阻止我们使用基于按值进行数组索引的方法。 
- 由于数组是严格递增的，如果`arr[k] >= arr[j]`， 然后`arr[i] = arr[k] - arr[j]`不能出现在之前`j`。 这一观察结果对于修剪无效状态非常有用。 

## 方法

 ### 蛮力方法

 蛮力的想法是尝试每对可能的起始元素并贪婪地扩展类似斐波那契的序列。 

对于每对`(arr[i], arr[j])`，我们反复检查数组中是否存在它们的和。 如果是，我们扩展序列并继续。 为了提高查找效率，我们可以将所有数组值存储在哈希集中。 

例如：

 - 开始于`(1, 2)`- 下一个期望值是`3`- 然后`(2, 3)`产生`5`- 然后`(3, 5)`产生`8`这会正确生成有效的类斐波那契子序列。 

问题是我们尝试每一对起点，这给出了`O(n^2)`起始组合。 每个序列扩展最多可以占用`O(n)`最坏情况下的步骤，产生的总体复杂度为`O(n^3)`。 

尽管这可能在优化的语言中通过，但对于给定的约束来说它并不理想。 

### 最优动态规划方法

 关键的观察是斐波那契式序列完全由其最后两个元素决定。 

假设我们知道一个以以下结尾的序列：```
..., a, b
```那么下一个数字必须是：```
a + b
```这自然表明对索引对进行动态规划。 

我们定义：```
dp[j][k]
```作为以索引结尾的最长斐波那契式子序列的长度`j`和`k`。 

扩展以以下结尾的序列`(i, j)`进入`(j, k)`，我们需要：```
arr[i] + arr[j] = arr[k]
```重新排列：```
arr[i] = arr[k] - arr[j]
```由于数组是严格递增的，我们可以使用从值到索引的哈希映射来即时定位`arr[i]`。 

这减少了检查所有有序对的问题`(j, k)`在`O(1)`每次，产生一个整体`O(n^2)`解决方案。

 ## 算法演练

 1. 创建从数组值到其索引的哈希映射。 

这允许恒定时间查找来确定所需的前驱是否存在。 由于该数组是严格递增的并且包含唯一值，因此每个值恰好映射到一个索引。 
2. 初始化动态规划表。 

我们使用：```
dp[j][k]
```表示最长的类似斐波那契子序列的长度`arr[j]`和`arr[k]`。 

每对最初都有长度`2`，因为任何两个数字都可以形成潜在序列的开始。 
3. 迭代每一对`(j, k)`在哪里`j < k`。 

我们对待`arr[k]`作为当前结束元素并尝试找到有效的前导元素。 
4. 计算所需的先前值。 

对于类斐波那契关系：$arr[i] + arr[j] = arr[k]$重新排列给出：$arr[i] = arr[k] - arr[j]$我们计算这个值并检查它是否存在于哈希图中。 
5. 确保索引排序有效。 

即使该值存在，我们也必须验证：```
i < j
```因为子序列必须保留数组顺序。 
6. 扩展之前的序列。 

如果有效`i`存在：```
dp[j][k] = dp[i][j] + 1
```这意味着我们扩展结束于的序列`(i, j)`通过附加`arr[k]`。 
7. 跟踪全局最大值。 

每次我们更新 DP 状态时，我们都会更新迄今为止找到的最大序列长度。 
8.返回答案。 

如果最大长度仍然小于`3`， 返回`0`。 否则返回最大值。 

### 为什么它有效

 动态编程状态捕获扩展类似斐波那契子序列所需的确切信息：其最后两个元素。 每个有效的扩展仅取决于这两个值。 因为我们处理所有对`(j, k)`并正确识别他们的前任`i`，每个可能的类斐波那契子序列都被仅考虑一次。 递归关系保证更长的序列是从已经正确的较短序列构建的。 

## Python 解决方案```python
from typing import List

class Solution:
    def lenLongestFibSubseq(self, arr: List[int]) -> int:
        n = len(arr)

        value_to_index = {
            value: index for index, value in enumerate(arr)
        }

        dp = [[2] * n for _ in range(n)]

        longest = 0

        for k in range(n):
            for j in range(k):
                previous_value = arr[k] - arr[j]

                if previous_value in value_to_index:
                    i = value_to_index[previous_value]

                    if i < j:
                        dp[j][k] = dp[i][j] + 1
                        longest = max(longest, dp[j][k])

        return longest if longest >= 3 else 0
```实现首先构建一个名为的哈希图`value_to_index`。 这允许对数组值位置进行恒定时间查找。 
这`dp`表初始化为`2`因为任何一对数字都会形成长度为 2 的平凡子序列。 仅当存在有效的斐波那契扩展时，我们才会增加此值。 

嵌套循环迭代每个有序对`(j, k)`。 对于每一对，我们使用以下方法计算所需的前驱值：```python
arr[k] - arr[j]
```如果该前驱存在并且出现在索引之前`j`，我们扩展现有的子序列：```python
dp[j][k] = dp[i][j] + 1
```变量`longest`跟踪处理过程中发现的最大序列长度。 

最后，我们返回`0`如果不存在长度至少为 3 的类斐波那契子序列。 

## 解决方案```go
func lenLongestFibSubseq(arr []int) int {
	n := len(arr)

	valueToIndex := make(map[int]int)

	for i, value := range arr {
		valueToIndex[value] = i
	}

	dp := make([][]int, n)

	for i := range dp {
		dp[i] = make([]int, n)

		for j := range dp[i] {
			dp[i][j] = 2
		}
	}

	longest := 0

	for k := 0; k < n; k++ {
		for j := 0; j < k; j++ {
			previousValue := arr[k] - arr[j]

			i, exists := valueToIndex[previousValue]

			if exists && i < j {
				dp[j][k] = dp[i][j] + 1

				if dp[j][k] > longest {
					longest = dp[j][k]
				}
			}
		}
	}

	if longest >= 3 {
		return longest
	}

	return 0
}
```Go 的实现与 Python 版本非常相似。 一个`map[int]int`使用而不是 Python 字典进行值查找。 

DP 表被表示为一个二维切片，初始化为`2`。 

Go 没有内置 Python`max`函数用于整数，因此我们手动比较和更新`longest`。 

整数溢出不是问题，因为最大可能值是`10^9`，它很容易适合 Go 的内部`int`在 LeetCode 环境中输入。

 ## 边缘情况

 当根本不存在类斐波那契子序列时，就会出现一种重要的边缘情况。 例如：```
[1,4,10,22]
```有错误的实现可能会错误地返回`2`，因为每对最初都有 DP 长度`2`。 然而，该问题需要长度至少为`3`。 该实现通过返回来处理这个问题`0`每当发现的最大长度小于`3`。 

另一个重要的边缘情况是最小有效数组大小：```
[1,2,3]
```这是最小的可能的类斐波那契子序列。 某些实现在更新答案之前意外地需要额外的扩展。 我们的解决方案立即正确识别序列，因为每个有效的扩展都会更新 DP 表的长度`3`。 

第三个关键边缘情况涉及当前索引之后出现的有效值。 认为：```
arr = [1,3,5,8]
```加工时`(3,5)`，所需的前导是`2`，它不存在。 在其他情况下，前驱值可能存在但出现在`j`，这会违反后续顺序。 条件：```
if i < j:
```确保我们只形成保留原始数组顺序的子序列。 

另一个微妙的边缘情况涉及接近的大整数值`10^9`。 由于我们从不构建按值索引的数组，而仅使用哈希映射和算术减法，因此即使对于非常大的数字，实现仍然高效并避免内存问题。
