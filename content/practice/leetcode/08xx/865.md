[LeetCode 865 题](https://leetcode.com/problems/smallest-subtree-with-all-the-deepest-nodes/)

 **难度：** 🟡 中等
 **主题：** 哈希表、树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉树的根，并要求我们找到包含树中所有最深节点的最小子树。 

节点的深度定义为该节点与根之间的边数。 根本身就有深度`0`。 最深节点是深度等于树中任何位置存在的最大深度的任何节点。 

重要的细节是可能有多个最深的节点。 我们不是在寻找单个最深节点，而是在寻找同时包含每个最深节点的最小子树。 

以某个节点为根的子树包括该节点及其所有后代。 因此，答案实际上是树中的最低节点，其子树包含每个最深节点。 

这个问题相当于寻找所有最深叶子的最低共同祖先（LCA）。 如果所有最深的节点都位于一个分支中，则答案可能是这些最深的节点本身之一。 如果最深的节点出现在不同的分支中，则答案将成为这些分支相交的节点。 

限制相对较小，最多`500`节点，因此即使效率较低的方法也可能会通过。 然而，目标是设计一个干净且最优的树算法。 节点值是唯一的，如果需要映射，这会有所帮助，尽管最佳解决方案不需要它们。 

一些边缘情况很重要：

 - 一棵只有一个节点的树。 该节点显然是最深的节点，也是答案。 
- 一棵完全倾斜的树，其中每个节点只有一个子节点。 最深的节点本身就是答案。 
- 平衡树，其中最深的节点同时存在于左子树和右子树中。 答案成为更高的祖先。 
- 一个子树比另一棵子树更深的树。 答案必须完全来自更深层的一面。 

## 方法

 ### 蛮力方法

 强力解决方案将首先确定树中的最大深度并收集该深度的所有节点。 然后，对于树中的每个节点，我们可以检查其子树是否包含所有最深的节点。 

一种可能的实现是：

 1. 运行 DFS 或 BFS 计算最大深度。 
2. 收集所有最深的节点。 
3. 对于树中的每个节点：

 - 遍历它的子树。 
- 检查是否包含所有最深的节点。 
4. 返回最小的有效子树。 

这种方法之所以有效，是因为它明确地验证了问题的定义。 然而，它重复遍历子树，导致大量的冗余工作。 

如果有`N`节点，对于每个节点我们可以遍历到`N`再次节点，复杂性可以降级为`O(N²)`。 

### 最佳方法

 关键的见解是答案完全取决于子树深度。 

对于任意节点：

 - 如果左子树和右子树具有相同的最大深度，则两个方向都存在最深的节点。 因此，当前节点是包含它们的最小子树。 
- 如果一个子树更深，则所有最深的节点必须完全位于该更深的子树内。 

这自然表明后序 DFS 遍历。 

对于每个节点，我们返回两件事：

 - 其子树中最深节点的深度。 
- 包含所有最深节点的子树根。 

通过组合左右子节点的结果，我们可以在一次遍历中确定当前节点的正确答案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(N) | 反复扫描子树以验证最深的节点 |
 | 最佳| O(N) | O(H) | 利用子树深度信息进行单次DFS遍历|`H`代表树的高度。 

## 算法演练

 1. 定义一个递归DFS函数，处理子树并返回两个值：

 - 表示包含所有最深节点的最小子树的节点。 
- 该子树内最深节点的深度。 
2. 从根开始递归。 递归按后序进行，这意味着我们处理左子树，然后处理右子树，然后处理当前节点。 
3. 对于空节点：

 - 返回`(None, 0)`。 
- 空子树有深度`0`。 
4. 递归处理左孩子：

 - 从左侧接收候选子树根。 
- 从左侧接收最大深度。 
5. 递归处理右孩子：

 - 从右侧接收候选子树根。 
- 从右侧接收最大深度。 
6. 比较深度：

 - 如果`left_depth > right_depth`，那么所有最深的节点都在左子树内。 返回左侧候选者和深度`left_depth + 1`。 
- 如果`right_depth > left_depth`，那么所有最深的节点都在右子树内。 返回正确的候选者和深度`right_depth + 1`。 
- 如果深度相等，则两个子树中都存在最深的节点。 当前节点成为所有最深节点的最低公共祖先。 返回当前节点和深度`left_depth + 1`。 
7. 在根处完成 DFS 后，返回递归生成的子树节点。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 对于每个子树，DFS 函数返回包含该子树内所有最深节点的最小子树。 

如果一侧更深，则每个最深的节点都必须位于那里，因此我们将结果向上传播不变。 如果两侧的深度相等，则两个方向都存在最深的节点，这意味着当前节点是连接它们的第一个节点。 这使得它成为正确的最小子树根。 

因为每个节点都被处理一次并且递归地维护不变量，所以最终的答案是正确的。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, Tuple

class Solution:
    def subtreeWithAllDeepest(
        self,
        root: Optional[TreeNode]
    ) -> Optional[TreeNode]:

        def dfs(node: Optional[TreeNode]) -> Tuple[Optional[TreeNode], int]:
            if not node:
                return None, 0

            left_node, left_depth = dfs(node.left)
            right_node, right_depth = dfs(node.right)

            if left_depth > right_depth:
                return left_node, left_depth + 1

            if right_depth > left_depth:
                return right_node, right_depth + 1

            return node, left_depth + 1

        result, _ = dfs(root)
        return result
```实现直接遵循递归策略。 

这`dfs`函数返回一个元组，其中包含：

 - 包含所有最深节点的最小子树根。 
- 当前子树内的最大深度。 

基本情况通过返回深度来处理空节点`0`。 

递归调用独立地计算左子树和右子树的结果。 两次递归调用完成后，当前节点比较子树深度。 

如果一个子树更深，则最深的节点必须全部属于该侧，因此我们向上传播其候选节点。 

如果两个深度相等，则两个分支中都存在最深的节点，使当前节点成为它们的最低公共祖先。 因此，当前节点成为正确的子树根。 

最后，外部函数仅提取并返回子树节点。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func subtreeWithAllDeepest(root *TreeNode) *TreeNode {

    var dfs func(node *TreeNode) (*TreeNode, int)

    dfs = func(node *TreeNode) (*TreeNode, int) {
        if node == nil {
            return nil, 0
        }

        leftNode, leftDepth := dfs(node.Left)
        rightNode, rightDepth := dfs(node.Right)

        if leftDepth > rightDepth {
            return leftNode, leftDepth + 1
        }

        if rightDepth > leftDepth {
            return rightNode, rightDepth + 1
        }

        return node, leftDepth + 1
    }

    result, _ := dfs(root)
    return result
}
```Go 的实现与 Python 解决方案非常相似。 

Go 自然地使用多个返回值，这很适合这个问题，因为每个 DFS 调用都需要返回子树节点和深度。 

基本情况返回`nil`对于缺失的节点。 深度计算直接使用整数，并且不存在溢出问题，因为树最多包含`500`节点。 

与 Python 元组不同，Go 将递归函数签名显式声明为：```go
func(node *TreeNode) (*TreeNode, int)
```这使得返回的子树根和深度类型明确。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | 每个节点都被访问一次 |
 | 空间| O(H) | 递归调用堆栈取决于树的高度 |

 该算法执行单次 DFS 遍历。 每个节点在处理其子节点后都会持续工作，因此总运行时间与节点数量呈线性关系。 

空间复杂度来自递归深度。 在完全倾斜的树的最坏情况下，递归堆栈可以增长到`O(N)`。 在平衡树中，它变成`O(log N)`。

 ## 边缘情况

 单节点树是一种重要的边缘情况，因为根同时是最浅和最深的节点。 某些实现错误地假设至少存在一个子级，并且可能错误地处理递归终止。 该解决方案正确返回根，因为两个子树深度相等`0`，使当前节点成为答案。 

完全倾斜的树可能会暴露递归或深度传播错误。 在这样一棵树中，每个节点只有一个子节点，因此只有一个最深的节点。 该算法正确地不断向上传播更深的子树，直到最深的叶子本身成为最终答案。 

当最深的节点同时存在于同一深度的左子树和右子树中时，会发生另一种微妙的边缘情况。 幼稚的实现可能会错误地返回一个最深的节点，而不是它们的最低公共祖先。 此实现显式检查子树深度是否相等，并在这种情况下返回当前节点，保证选择正确的最小子树。 

最后一个重要的情况是一个子树比另一棵子树深得多。 该算法必须完全忽略较浅的一侧。 由于 DFS 总是向上传播更深的子树，因此该解决方案自然可以处理这种情况，无需额外的逻辑。
