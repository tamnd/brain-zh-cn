[LeetCode 854 题](https://leetcode.com/problems/k-similar-strings/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题要求我们确定将一个字符串转换为另一个字符串所需的最小交换次数，其中两个字符串都是彼此的字谜词。 单个操作包括交换任意两个字符`s1`。 目标是使`s1`完全等于`s2`使用尽可能少的交换。 

因为这些字符串是字谜词，所以它们包含具有相同频率的完全相同的字符。 这保证了有效的转换始终存在。 挑战不在于转变是否可能，而在于如何以最少的交换次数实现转变。 

输入由两个字符串组成：

 -`s1`, 起始字符串
 -`s2`, 目标字符串

 预期输出是一个整数，表示所需的最小交换次数。 

约束条件很重要：

 - 最大字符串长度仅为20
 - 字符仅来自六个可能的字母：`a`通过`f`20 的长度足够小，以至于指数算法在经过大量修剪后仍然可以工作，但对于简单的排列生成来说就太大了。 有限的字母表还意味着可能会出现许多重复的字符，这可以创建许多等效的交换状态。 

一些边缘情况很重要：

 - 字符串可能已经相等，在这种情况下答案是`0`- 多个相同的角色可以创建许多冗余的交换选择
 - 某些交换可能会同时修复多个不匹配问题
 - 贪婪的局部选择并不总是导致最优的全局解决方案

 这个问题本质上是字符串状态上的最短路径搜索问题。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的交换序列，直到`s1`变成`s2`。 在每一步中，我们都可以通过交换每对索引来生成所有可获得的字符串。 

这种方法是正确的，因为它最终会探索每个可到达的配置，因此它最终必须发现最小交换数量。 

然而，可能的状态数量呈爆炸式增长。 一个长度的字符串`n`最多有`n!`排列，每个状态都可以生成`O(n²)`来自互换的新状态。 即使与`n = 20`，这是完全不可行的。 

蛮力方法变得太慢，因为它浪费时间探索明显远离目标的状态或重复已经访问过的配置。 

### 最优方法，带剪枝的广度优先搜索

 关键的见解是我们只关心立即修复不匹配的交换。 

假设我们扫描当前字符串并找到第一个索引`i`它的不同之处在于`s2`。 任何最优解最终都必须放置正确的字符`s2[i]`到这个位置。 

因此，我们只交换索引，而不是尝试所有交换`i`有职位`j`在哪里：

-`current[j] == s2[i]`-`current[j] != s2[j]`这大大减少了分支。 

然后我们使用广度优先搜索（BFS）：

 - 每个节点都是一个字符串配置
 - 每条边代表一次交换
 - BFS保证我们第一时间到达`s2`，我们使用了最小交换次数

 由于 BFS 逐级探索状态，因此第一个成功的转换是最优的。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n! × n²) | O(n! × n²) | O(n!) | 探索几乎所有排列 |
 | 带剪枝的最优 BFS | O(n! / 剪枝) | O(n!) | 只探索有用的交换 |

 最优方法仍然具有指数最坏情况行为，但修剪策略极大地减少了实际搜索空间，足以通过约束。 

## 算法演练

 1. 首先检查是否`s1`已经等于`s2`。 如果是，则返回`0`立即，因为不需要交换。 
2. 使用起始字符串初始化 BFS 队列`s1`和交换计数`0`。 
3. 创建一个`visited`设置以避免多次重新访问相同的字符串配置。 这可以防止无限循环和冗余工作。 
4. 反复从队列中移除最前面的状态。 
5、对于当前字符串，从左到右扫描，找到第一个索引`i`当前字符串与当前字符串不同的地方`s2`。 
6. 所在位置的字符`i`最终必须成为`s2[i]`。 因此，搜索索引`j > i`这样：

 -`current[j] == s2[i]`-`current[j] != s2[j]`第二个条件避免破坏已经正确的字符。 
7. 对于每个有效的`j`，通过交换位置处的字符来创建一个新字符串`i`和`j`。 
8. 如果新字符串等于`s2`，返回当前交换计数加一。 
9. 否则，如果新字符串之前未被访问过：

 - 添加到`visited`- 将其推入 BFS 队列，交换计数加一
 10. 继续直到 BFS 到达目标字符串。 

### 为什么它有效

 在每个 BFS 级别，所有状态都表示可通过相同数量的交换到达的字符串。 由于BFS逐级探索，我们第一次遇到`s2`必须对应于最小交换次数。 

修剪规则也是安全的。 任何最佳解决方案最终都必须修复第一个不匹配的位置，因此仅考虑在那里放置正确字符的交换并不能排除最佳路径。 

## Python 解决方案```python
from collections import deque
from typing import Set

class Solution:
    def kSimilarity(self, s1: str, s2: str) -> int:
        if s1 == s2:
            return 0

        queue = deque([(s1, 0)])
        visited: Set[str] = {s1}

        while queue:
            current, swaps = queue.popleft()

            i = 0
            while current[i] == s2[i]:
                i += 1

            current_list = list(current)

            for j in range(i + 1, len(current)):
                if (
                    current[j] == s2[i]
                    and current[j] != s2[j]
                ):
                    next_list = current_list[:]
                    next_list[i], next_list[j] = (
                        next_list[j],
                        next_list[i],
                    )

                    next_string = "".join(next_list)

                    if next_string == s2:
                        return swaps + 1

                    if next_string not in visited:
                        visited.add(next_string)
                        queue.append((next_string, swaps + 1))

        return -1
```实施从快速相等性检查开始。 这可以有效地处理最简单的情况。 

BFS 队列存储包含以下内容的元组：

 - 当前字符串状态
 - 用于达到该目标的交换次数

 的`visited`set 可以防止重复探索。 

在 BFS 循环内，算法找到第一个不匹配的索引`i`。 这是关键的剪枝优化。 我们不尝试任意交换，而只尝试将正确的字符放置到位的交换`i`。 

由于 Python 字符串是不可变的，因此字符串会暂时转换为列表。 执行交换后，列表将转换回字符串。 

每当生成新的有效状态时，如果匹配则立即返回`s2`，或者添加到 BFS 前沿以进行进一步探索。 

## 解决方案```go
package main

import (
	"container/list"
)

type State struct {
	str   string
	swaps int
}

func kSimilarity(s1 string, s2 string) int {
	if s1 == s2 {
		return 0
	}

	queue := list.New()
	queue.PushBack(State{s1, 0})

	visited := make(map[string]bool)
	visited[s1] = true

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		current := front.Value.(State)

		i := 0
		for current.str[i] == s2[i] {
			i++
		}

		currentBytes := []byte(current.str)

		for j := i + 1; j < len(current.str); j++ {
			if current.str[j] == s2[i] &&
				current.str[j] != s2[j] {

				nextBytes := make([]byte, len(currentBytes))
				copy(nextBytes, currentBytes)

				nextBytes[i], nextBytes[j] =
					nextBytes[j], nextBytes[i]

				nextString := string(nextBytes)

				if nextString == s2 {
					return current.swaps + 1
				}

				if !visited[nextString] {
					visited[nextString] = true
					queue.PushBack(
						State{
							nextString,
							current.swaps + 1,
						},
					)
				}
			}
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的 BFS 逻辑。 

由于 Go 字符串是不可变的，因此代码在交换字符之前将字符串转换为字节切片。 每次修改之前都会创建切片的副本，以便不同的 BFS 分支不会相互干扰。 

BFS队列的实现使用`container/list`，提供高效的前端移除操作。 

这`visited`结构是用一个实现的`map[string]bool`。

 ## 边缘情况

 当字符串已经相等时，就会出现一种重要的边缘情况。 粗心的 BFS 实现可能仍然会使状态排队并执行不必要的工作。 该实现立即处理这个问题并提前返回`0`。 

另一个棘手的情况涉及重复字符。 例如，改造`"aabc"`进入`"abca"`可以产生许多等效的交换序列。 如果没有仔细的修剪和访问集，该算法可以重复探索相同的状态。 该实现通过存储每个访问过的字符串配置来避免这种情况。 

第三个重要的边缘情况是当同一不匹配存在多个交换候选者时。 有些交换可能看起来很有用，但实际上会增加未来的工作量。 BFS 在这里保证了正确性，因为它在深入之前探索具有相同交换计数的所有状态。 即使一个分支不是最优的，最优路径仍然会首先被发现。 

最后一个微妙的边缘情况涉及交换已经处于正确位置的字符。 这样做可能会撤销之前的进度并扩大搜索空间。 条件`current[j] != s2[j]`防止这些不必要的交换并显着提高性能，同时保持正确性。
