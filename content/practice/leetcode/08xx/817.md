[LeetCode 817 题](https://leetcode.com/problems/linked-list-components/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、链表

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个单链表，其中每个节点都包含唯一的整数值。 我们还得到了一个数组`nums`，以及中的每个值`nums`保证出现在链表中的某个位置。 

我们需要计算其值所属的节点之间存在多少个连通分量`nums`。 

如果满足以下条件，则认为两个节点已连接：

 1. 两个节点值都存在于`nums`2、两个节点在链表中连续出现

 这意味着我们并不是在寻找任意的图连接性。 连通性完全由链表中的邻接关系决定。 

例如，假设链表是：```
0 -> 1 -> 2 -> 3
```和：```
nums = [0,1,3]
```节点`0`和`1`在链表中是连续的并且都属于`nums`，因此它们形成一个组件：```
[0,1]
```节点`3`是孤立的，因为节点`2`不在`nums`， 所以`3`形成另一个组件：```
[3]
```因此，答案是`2`。 

约束条件很重要：

 - 链表长度可以大到`10^4`- 所有节点值都是唯一的
 - 所有值在`nums`是独一无二的

 唯一性保证大大简化了问题，因为我们永远不需要担心重复的值或不明确的匹配。 

主要挑战是有效地确定节点是否属于`nums`，以及它是继续现有组件还是启动新组件。 

一些边缘情况很重要：

 -`nums`可能只包含一个值
 - 所有链表节点可能属于`nums`- 每个选定的节点都可以被隔离
 - 组件可能出现在链表的开头或结尾
 - 连续序列可能有不同的长度

 反复搜索的简单实现`nums`对于大输入来说，线性将变得低效。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是遍历链表，对于每个节点，检查其值是否存在于`nums`使用线性扫描。 

每当我们遇到一个属于`nums`，我们确定它是否启动一个新组件。 如果满足以下条件，则节点启动新组件：

 - 它属于`nums`- 下一个节点是：

 -`None`, 或
 - 不存在于`nums`这种逻辑之所以有效，是因为每个连接的组件恰好在邻接中断的地方结束。 

然而，如果通过重复线性扫描来实现，成员资格检查会变得昂贵`nums`。 

如果：

-`n`是链表长度
 -`m`的大小是`nums`那么每张会员支票的费用`O(m)`，我们的表现达到`O(n)`检查，导致`O(n * m)`时间复杂度。 

约束条件高达`10^4`，这不必要地慢。 

### 最佳方法

 关键的观察是我们只需要快速的成员资格测试。 

哈希集提供`O(1)`平均查找时间。 

我们首先存储来自`nums`成一个集合。 然后我们遍历一次链表。 

对于每个节点：

 - 如果节点值在集合中
 - 下一个节点要么不存在，要么不在集合中

 那么这个节点标志着连接组件的结束，所以我们增加答案。 

这是可行的，因为每个组件都有一个结束节点。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 线性搜索`nums`对于每个节点 |
 | 最佳 | O(n + m) | O(米) | 使用哈希集进行恒定时间成员资格检查 |

 ## 算法演练

 1. 创建一个哈希集`nums`。 

我们使用集合是因为​​哈希集中的成员资格检查非常快，通常`O(1)`平均而言。 这避免了重复扫描阵列。 
2. 初始化一个名为`components`到`0`。 

该变量存储迄今为止发现的连接组件的数量。 
3. 遍历链表自`head`到最后。 

我们只检查每个节点一次。 
4. 对于每个节点，检查其值是否属于集合。 

如果该值不在集合中，则该节点与问题无关，我们继续。 
5、如果当前节点属于集合，则判断是否为某个组件的末尾。 

如果满足以下条件，则节点结束组件：

 -`current.next`是`None`， 或者
-`current.next.val`不在集合中

 这意味着连接的节点链在此停止。 
6. 如果当前节点结束一个组件，则递增`components`。 

每个组件都贡献一个结束节点，因此正确计算结尾即可计算组件。 
7. 继续直到遍历完成。 
8. 返回`components`。 

### 为什么它有效

 该问题中的连通分量只是节点的最大连续序列，其值属于`nums`。 

每个这样的序列都恰好有一个最后一个节点。 通过计算节点数，其中：

 - 当前值属于`nums`, 和
 - 下一个节点不继续序列，

 我们对每个组件只计数一次。 

没有一个组件被遗漏，也没有一个组件被多次计数。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import List, Optional

class Solution:
    def numComponents(self, head: Optional[ListNode], nums: List[int]) -> int:
        nums_set = set(nums)

        components = 0
        current = head

        while current:
            if current.val in nums_set:
                if current.next is None or current.next.val not in nums_set:
                    components += 1

            current = current.next

        return components
```实现从转换开始`nums`到一个名为的哈希集`nums_set`。 这提供了恒定时间的成员资格检查。 

然后我们初始化`components`存储遍历过程中发现的连接组件的数量。 

指针`current`逐个节点遍历链表。 

对于每个节点，我们首先检查它的值是否属于集合。 如果没有，我们会跳过它，因为它无法对组件做出贡献。 

如果该值确实属于该集合，我们将确定该节点是否标记连接序列的结尾。 当出现以下任一情况时就会发生这种情况：

 - 没有下一个节点，或者
 - 下一个节点的值不在集合中

 每当这个条件成立时，我们就会增加组件计数器。 

最后，遍历整个列表后，我们返回组件的总数。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func numComponents(head *ListNode, nums []int) int {
    numsSet := make(map[int]bool)

    for _, num := range nums {
        numsSet[num] = true
    }

    components := 0
    current := head

    for current != nil {
        if numsSet[current.Val] {
            if current.Next == nil || !numsSet[current.Next.Val] {
                components++
            }
        }

        current = current.Next
    }

    return components
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

由于 Go 没有内置的哈希集类型，我们使用以下方法模拟一个`map[int]bool`。 

链表遍历使用一个名为`current`。 Go 使用`nil`而不是Python的`None`对于缺少的指针。 

其余逻辑是相同的：

 - 识别属于的节点`nums`- 确定他们是否终止一个组件
 - 相应地增加计数器

 这里不存在整数溢出问题，因为最大节点数仅为`10^4`。

 ## 边缘情况

 ### 整个链表形成一个组件

 如果每个节点值都属于`nums`，整个链表成为一个连通分量。 

例如：```
head = [0,1,2,3]
nums = [0,1,2,3]
```有缺陷的实现可能会错误地将每个节点视为单独的组件。 我们的解决方案通过仅计算终止组件的节点来避免这种情况。 在这种情况下，只有最终节点满足该条件。 

### 每个选定的节点都是隔离的

 考虑：```
head = [0,1,2,3,4]
nums = [0,2,4]
```没有两个选定的节点是相邻的。 因此，每个选定的节点形成其自己的组件。 

这种情况很重要，因为简单的邻接处理可能会意外地合并不连续的节点。 我们的实现通过检查实际的链表邻接性`current.next`，因此孤立节点的计数正确。 

### 组件在尾部结束

 考虑：```
head = [0,1,2,3]
nums = [2,3]
```该组件到达列表的最后一个节点。 

这是错误的常见来源，因为最终节点没有`next`指针。 我们的实现明确检查：```
current.next is None
```它正确地识别了最终组件的结尾。
