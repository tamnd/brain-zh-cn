 **难度：** 🟢简单
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 这个问题模拟了一个柠檬水摊，每个柠檬水的成本`⟦PROTECT_3⟧5`,`⟦PROTECT_4⟧20`账单。 面临的挑战是在每位顾客付款时为他们提供准确的零钱。 输入是一个整数列表`bills`，其中每个元素代表客户给出的账单。 输出是一个布尔值：`true`是否可以为每位顾客提供正确的零钱，以及`false`否则。 

约束表明数组可以非常大，最多 100,000 个元素。 每张账单都保证是其中之一`5`,`10`， 或者`20`，所以我们不需要处理无效面额。 这个问题还意味着我们手头上的现金为零，因此我们的初始交易仅限于精确付款或积累小额账单以备将来找零。 

可能导致简单解决方案失败的边缘情况包括连续的高额账单，例如`[10, 20]`没有首字母的`⟦PROTECT_5⟧20`账单出现在足够之前`⟦PROTECT_6⟧5`账单已收集。 

## 方法

 暴力方法会尝试模拟每一种可能的找零方式，尝试所有可用账单的组合来满足每个客户。 这是不必要的，因为问题仅限于三种票据类型，并且成本固定为`$5`。 虽然正确，但这种强力方法可能涉及递归检查或回溯，这对于大输入量来说效率低下。 

关键的见解是，贪婪策略在这里发挥作用：始终使用可用的最大钞票进行找零。 对于一个`⟦PROTECT_7⟧5`。 对于一个`⟦PROTECT_8⟧10`和一个`⟦PROTECT_9⟧5`账单。 这确保我们为未来的交易保留较小的钞票，并避免用完必要的零钱。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 考虑所有的找零组合； 正确但对于大 n | 不可行
 | 最佳| O(n) | O(1) | O(1) | 使用计数器进行贪婪模拟`⟦PROTECT_10⟧10`账单； 线性传递输入|

 ## 算法演练

 1.初始化两个计数器，`five`和`ten`, 为零。 这些将跟踪数量`⟦PROTECT_11⟧10`手中的账单。 
2. 迭代每个`bill`在`bills`大批。 
3.如果`bill`是`$5`，增加`five`柜台。 不需要改变。 
4. 如果`bill`是`⟦PROTECT_12⟧5`可用。 如果是，则递减`five`加一并递增`ten`一个。 如果没有`$5`可用，返回`false`。 
5. 如果`bill`是`⟦PROTECT_13⟧10`和一个`⟦PROTECT_14⟧5`账单。 如果两个选项都不可行，则返回`false`。 
6. 如果循环完成没有返回`false`，所有客户都收到了正确的零钱。 返回`true`。 

**为什么有效：** 贪婪方法确保首先使用最大的钞票进行找零，为后续交易保留较小的钞票。 该算法保持不变：在任何时候，计数器都会反映可找零的钞票的确切数量，这保证了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def lemonadeChange(self, bills: List[int]) -> bool:
        five = 0
        ten = 0
        
        for bill in bills:
            if bill == 5:
                five += 1
            elif bill == 10:
                if five == 0:
                    return False
                five -= 1
                ten += 1
            else:  # bill == 20
                if ten > 0 and five > 0:
                    ten -= 1
                    five -= 1
                elif five >= 3:
                    five -= 3
                else:
                    return False
        return True
```Python 实现完全遵循该算法。 计数器`⟦PROTECT_15⟧10`跟踪可用账单，条件检查处理每种类型的传入账单。 贪心选择确保在不使用额外空间或复杂数据结构的情况下给出正确的改变。 

## 解决方案```go
func lemonadeChange(bills []int) bool {
    five, ten := 0, 0

    for _, bill := range bills {
        switch bill {
        case 5:
            five++
        case 10:
            if five == 0 {
                return false
            }
            five--
            ten++
        case 20:
            if ten > 0 && five > 0 {
                ten--
                five--
            } else if five >= 3 {
                five -= 3
            } else {
                return false
            }
        }
    }
    return true
}
```在 Go 中，为了清晰起见，我们使用 switch 语句并维护两个整数计数器。 切片可以有效地处理迭代，并且无需在输入切片之外进行动态分配。 逻辑反映了 Python 版本。
