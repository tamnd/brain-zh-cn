[LeetCode 第 894 题](https://leetcode.com/problems/all-possible-full-binary-trees/)

 **难度：** 🟡 中等
 **主题：** 动态规划、树、递归、记忆、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们生成每个可能的完全二叉树，其中包含`n`节点。 满二叉树是一种特殊的二叉树，其中每个节点要么恰好有两个子节点，要么根本没有子节点。 换句话说，一个节点永远不可能只有一个子节点。 

输入是单个整数`n`，表示每个生成的树中必须出现的节点总数。 每棵树中的每个节点都必须包含该值`0`，所以实际的节点值是无关的。 唯一重要的是树的结构。 

输出是一个列表，其中包含每个不同的完整二叉树的根节点，可以使用精确的方法形成该二叉树`n`节点。 由于该问题允许以任何顺序返回树，因此我们无需担心排序或确定性排序。 

一个非常重要的观察来自满二叉树的定义。 每次我们添加一个内部节点时，它都会贡献两个子节点。 由于此属性，满二叉树始终包含奇数个节点。 这意味着如果`n`是偶数，答案必须立即是一个空列表。 

约束条件`1 <= n <= 20`相对较小，这强烈表明生成所有有效树是可行的。 然而，可能的树的数量增长很快，因此重复重新计算相同的子树组合效率很低。 这暗示记忆或动态编程将很重要。 

一些边缘情况很重要：

 - 如果`n`是偶数，则不存在满二叉树。 
- 如果`n == 1`，唯一有效的树是没有子节点的单个节点。 
- 递归生成可以重复解决相同的子问题，导致指数重新计算而无需记忆。 
- 树的构造必须避免在重用后意外修改共享子树引用。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试递归地构造每个可能的二叉树`n`节点，然后过滤掉不是满二叉树的树。 

对于每个节点，我们可以尝试对左子树和右子树之间的剩余节点进行所有可能的分割。 生成所有组合后，我们将检查每个节点是否满足完整二叉树属性。 

这种方法是正确的，因为它详尽地探索了所有可能的结构。 然而，它的效率极低，因为：

 - 许多无效树的生成只是为了以后被丢弃。 
- 重复重新计算相同的子树大小。 
- 递归分支呈爆炸式增长`n`增加。 

即使与`n <= 20`，没有记忆的简单递归会执行过多的冗余工作。 

### 最佳方法

 关键的见解是完整二叉树具有严格的结构属性：

 - 每个节点要么贡献零个子节点，要么贡献恰好两个子节点。 
- 因此，左子树和右子树的大小必须都是奇数。 
- 如果根消耗了一个节点，则剩余的`n - 1`节点必须分为两个奇数大小的组。 

这自然会导致递归构造：

 - 对于每个奇数分裂`n - 1`,
 - 生成所有可能的左子树，
 - 生成所有可能的右子树，
 - 将每个左子树与每个右子树组合。 

由于相同的子树大小在递归期间重复出现，因此记忆化显着提高了性能。 一旦我们计算出特定节点数的所有完整二叉树，我们就会存储并重用结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 呈指数级增长，比必要的情况严重得多 | 指数| 生成许多​​无效树并重复重新计算子问题 |
 | 最佳 | O(Cn) 其中 Cn 是生成树的数量 | O(Cn)| 使用记忆并仅构造有效的完整二叉树 |

 ## 算法演练

 1.首先检查是否`n`是均匀的。 满二叉树总是包含奇数个节点，所以如果`n % 2 == 0`，立即返回一个空列表。 
2. 创建一个记忆映射，其中键是节点数，值是具有该数量节点的所有可能的完整二叉树的列表。 这可以防止重复重新计算相同的子树结构。 
3. 定义递归函数`build(node_count)`返回所有完全包含的完整二叉树`node_count`节点。 
4. 在递归函数内部，首先检查结果是否已存在于记忆映射中。 如果是，则立即返回缓存列表。 
5. 处理基本情况。 如果`node_count == 1`，唯一可能的完整二叉树是单个叶节点。 返回包含一个的列表`TreeNode(0)`。 
6. 对于较大的奇数值`node_count`，迭代每个可能的奇数大小的左子树：

 - 根消耗一个节点。 
- 其余`node_count - 1`节点必须划分在左子树和右子树之间。 
- 两个子树大小必须保持奇数。 
7. 对于每个有效的分割：

 - 递归生成所有左子树。 
- 递归生成所有右子树。 
8. 将每个左子树与每个右子树组合：

 - 创建一个新的根节点。 
- 附加所选的左子树。 
- 附加所选的右子树。 
- 将完成的树添加到结果列表中。 
9. 在返回之前将完成的结果列表存储在记忆映射中。 
10. 返回所有生成的树的列表。 

### 为什么它有效

 该算法之所以有效，是因为每个完整二叉树都可以唯一地分解为：

 - 一个根节点，
 - 一棵完整的左子树，
 - 一棵完整的右子树。 

通过递归生成每个有效的奇数大小的左子树和右子树组合，我们将每个可能的完整二叉树恰好枚举一次。 记忆化保证每个子树大小仅计算一次。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import List, Optional

class Solution:
    def allPossibleFBT(self, n: int) -> List[Optional[TreeNode]]:
        memo = {}

        def build(node_count: int) -> List[Optional[TreeNode]]:
            if node_count in memo:
                return memo[node_count]

            if node_count == 1:
                return [TreeNode(0)]

            trees = []

            for left_nodes in range(1, node_count, 2):
                right_nodes = node_count - 1 - left_nodes

                left_subtrees = build(left_nodes)
                right_subtrees = build(right_nodes)

                for left_tree in left_subtrees:
                    for right_tree in right_subtrees:
                        root = TreeNode(0)
                        root.left = left_tree
                        root.right = right_tree
                        trees.append(root)

            memo[node_count] = trees
            return trees

        if n % 2 == 0:
            return []

        return build(n)
```实现从处理记忆开始`memo`字典。 每个键存储特定节点数的所有可能的完整二叉树。 

递归辅助函数`build()`执行实际的树生成。 基本情况发生在仅需要一个节点时，这会生成单个叶节点。 

主要的递归逻辑迭代所有奇数大小的左子树可能性。 由于总节点数必须保持奇数，因此左子树和右子树的大小也必须是奇数。 

对于每个左子树和右子树组合，都会创建一个新的根节点并将其连接到这些子树。 然后，完成的树将附加到结果列表中。 

最后，记忆化确保每个子树大小仅生成一次，这避免了指数重新计算。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func allPossibleFBT(n int) []*TreeNode {
    if n%2 == 0 {
        return []*TreeNode{}
    }

    memo := make(map[int][]*TreeNode)

    var build func(int) []*TreeNode

    build = func(nodeCount int) []*TreeNode {
        if trees, exists := memo[nodeCount]; exists {
            return trees
        }

        if nodeCount == 1 {
            return []*TreeNode{
                &TreeNode{Val: 0},
            }
        }

        var trees []*TreeNode

        for leftNodes := 1; leftNodes < nodeCount; leftNodes += 2 {
            rightNodes := nodeCount - 1 - leftNodes

            leftSubtrees := build(leftNodes)
            rightSubtrees := build(rightNodes)

            for _, leftTree := range leftSubtrees {
                for _, rightTree := range rightSubtrees {
                    root := &TreeNode{
                        Val:   0,
                        Left:  leftTree,
                        Right: rightTree,
                    }

                    trees = append(trees, root)
                }
            }
        }

        memo[nodeCount] = trees
        return trees
    }

    return build(n)
}
```Go 实现遵循与 Python 解决方案相同的递归记忆策略。 主要区别在于切片和指针的使用。 

Go 使用`nil`失踪孩子的指针，而Python使用`None`。 记忆映射存储以下片段`*TreeNode`。 

因为 Go 需要显式的指针分配，所以每个新节点都是使用`&TreeNode{}`句法。 

整数溢出不是一个问题，因为约束`n <= 20`非常小。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n`是均匀的。 完整二叉树始终包含奇数个节点，因为每个内部节点恰好贡献两个子节点。 幼稚的实现可能仍会尝试对偶数值进行递归，从而浪费时间或生成无效的结构。 该实现立即通过提前返回空列表来处理此问题。 

另一个重要案例是`n == 1`。 这是最小的有效完整二叉树，并用作递归基本情况。 如果没有这个条件，递归将永远不会正确终止。 该实现返回包装在列表中的单个叶节点。 

更微妙的边缘情况涉及重复的子树计算。 例如，在生成树时`n = 9`，该算法重复需要所有大小的树`3`,`5`， 和`7`。 如果没有记忆，这些子问题将被多次重新计算，导致性能严重下降。 记忆字典确保每个子树大小只生成一次。 

错误的另一个潜在来源是不正确的子树分割。 如果在递归期间甚至允许子树大小，则可能会生成无效的非完整树。 该实现通过仅迭代奇数子树大小来避免这种情况，使用：```
for left_nodes in range(1, node_count, 2):
```这保证了两个子树始终包含奇数个节点，从而在整个递归过程中保留完整的二叉树属性。
