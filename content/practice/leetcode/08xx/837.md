[LeetCode 837 题](https://leetcode.com/problems/new-21-game/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划、滑动窗口、概率与统计

 ## 解决方案

 ## 问题理解

 在这个问题中，Alice 反复抽取随机数，直到她的分数至少达到`k`。 每次抽奖都会独立产生一个介于`1`和`maxPts`，包含在内，并且每个值的可能性均等。 

我们被要求计算 Alice 的最终分数小于或等于的概率`n`。 

关键细节是，一旦 Alice 的分数达到至少`k`。 这意味着所有最终分数都在以下范围内：

 -`k`到`k + maxPts - 1`因为最后抽奖最多可以加`maxPts`。 

输入参数代表如下：

 -`n`是成功所允许的最大最终分数。 
-`k`是停止阈值。 
-`maxPts`是爱丽丝在单回合中可以抽取的最大值。 

输出应该是一个浮点概率`0`和`1`。 

约束条件很重要：

 -`n`,`k`， 和`maxPts`都可以大到`10^4`- 这立即排除了指数模拟方法。 
- 我们需要一种接近线性时间的算法。 

有几个重要的边缘情况：

 - 如果`k == 0`，爱丽丝从不抽牌，所以她的分数总是`0`。 自从`0 <= n`，答案总是`1.0`。 
- 如果`n >= k + maxPts - 1`，那么每个可能的最终得分都是有效的，因此概率为`1.0`。 
- 小值`k`可能会导致游戏在一场平局后立即终止。 
- 大范围的可能状态需要仔细优化以避免二次动态规划。 

## 方法

 ### 蛮力方法

 一种简单的方法是递归地对每个可能的绘制序列进行建模。 

从目前的分数来看`x < k`，Alice 可以过渡到：

 -`x + 1`-`x + 2`- ...
 -`x + maxPts`每个都有概率`1 / maxPts`。 

我们可以递归地计算最终以有效分数结束的概率。 这就形成了一个概率树。 

重现看起来像：

 - 如果`x >= k`， 返回`1`如果`x <= n`， 否则`0`- 否则，对所有接下来的状态的概率进行平均

 这种方法是正确的，因为它精确地模拟了游戏过程。 然而，状态和转换的数量增长得非常快。 即使记忆仍然会导致昂贵的转换成本，因为每个状态都会检查`maxPts`未来的状态。 

一个简单的 DP 重现是：$$dp[i] = \frac{dp[i+1] + dp[i+2] + ... + dp[i+maxPts]}{maxPts}$$计算这个直接成本`O(maxPts)`每个状态，产生总的复杂性`O(k * maxPts)`，可以达到`10^8`运营。 

对于约束来说这太慢了。 

### 最优方法，滑动窗口动态规划

 关键的观察是每个状态都会计算连续概率范围的平均值。 

我们维护一个滑动窗口，而不是每次都重新计算总和。 

定义：

-`dp[i]`= 准确达到分数的概率`i`最初：

-`dp[0] = 1`如果 Alice 目前有分数`i`，那么每个未来的分数来自：

 -`i + 1`到`i + maxPts`收到概率贡献：$$\frac{dp[i]}{maxPts}$$然而，转换仅发生在`i < k`。 

关键的优化是：$$dp[i] = \frac{windowSum}{maxPts}$$在哪里`windowSum`存储前面的总和`maxPts`DP 状态可以转变为`i`。 

这将二次递归转换为线性时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k × maxPts) 或更差 | O(k) | 重复重新计算大概率范围 |
 | 最佳| O(n) | O(n) | 使用滑动窗口来维持滚动概率和 |

 ## 算法演练

 1.创建DP阵列`dp`尺寸的`n + 1`。`dp[i]`表示 Alice 准确达到分数的概率`i`。 
2. 初始化启动状态。 

爱丽丝从分数开始`0`， 所以：```
dp[0] = 1.0
```3. 维持滑动窗口总和。 

窗口表示可以转换到当前状态的概率之和。 

最初：```
windowSum = 1.0
```因为只有`dp[0]`一开始就对未来状态做出贡献。 
4. 迭代分数`1`到`n`。 

对于每个分数`i`：$$dp[i] = \frac{windowSum}{maxPts}$$这是有效的，因为窗口中之前每个可达到的分数的贡献是相等的。 
5.如果`i < k`，Alice 仍然可以从该状态进行抽奖。 

所以，`dp[i]`应添加到窗口中以供将来的转换。 
6.如果`i >= k`，爱丽丝停止画画。 

这意味着`dp[i]`直接贡献于最终答案，而不是未来的转换。 
7. 从窗口中删除过期状态。 

一旦一个状态变得超过`maxPts`当前指数落后，无法再过渡到未来分数。 

所以当：```
i >= maxPts
```减去：```
dp[i - maxPts]
```从窗口。 
8. 积累答案。 

每个州从`k`到`n`代表有效的停止分数。 

将这些概率相加。 

### 为什么它有效

 该算法之所以有效，是因为每个状态都将其概率均匀地分布到下一个状态`maxPts`州。 滑动窗口不是重复对相同范围求和，而是保持可达概率的精确滚动总和。 

在每一步，窗口不变量是：$$windowSum = dp[i-1] + dp[i-2] + ... + dp[i-maxPts]$$仅限于仍允许抽签的州。 所以：$$dp[i] = \frac{windowSum}{maxPts}$$正确计算达到分数的概率`i`。 

## Python 解决方案```python
class Solution:
    def new21Game(self, n: int, k: int, maxPts: int) -> float:
        if k == 0 or n >= k + maxPts - 1:
            return 1.0

        dp = [0.0] * (n + 1)
        dp[0] = 1.0

        window_sum = 1.0
        result = 0.0

        for score in range(1, n + 1):
            dp[score] = window_sum / maxPts

            if score < k:
                window_sum += dp[score]
            else:
                result += dp[score]

            if score >= maxPts:
                window_sum -= dp[score - maxPts]

        return result
```实施从两个重要的早期退出开始。 

如果`k == 0`，爱丽丝从不画画，所以概率是立即`1.0`。 

如果`n >= k + maxPts - 1`，那么每个可能的停止分数都是有效的，这意味着答案也是`1.0`。 

DP 数组存储达到每个精确分数的概率。 滑动窗口维护可以转变为当前分数的概率之和。 

对于每个分数：```python
dp[score] = window_sum / maxPts
```这将计算精确达到该分数的概率。 

如果分数仍然低于`k`，Alice 可能会继续绘画，因此这个概率通过添加到窗口中来有助于未来的转换。 

否则，分数就是最终分数，直接影响最终答案。 

最后，一旦最旧的值移出有效转换范围，它就会从滑动窗口中删除。 

## 解决方案```go
func new21Game(n int, k int, maxPts int) float64 {
    if k == 0 || n >= k+maxPts-1 {
        return 1.0
    }

    dp := make([]float64, n+1)
    dp[0] = 1.0

    windowSum := 1.0
    result := 0.0

    for score := 1; score <= n; score++ {
        dp[score] = windowSum / float64(maxPts)

        if score < k {
            windowSum += dp[score]
        } else {
            result += dp[score]
        }

        if score >= maxPts {
            windowSum -= dp[score-maxPts]
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别是显式类型转换：```go
float64(maxPts)
```因为 Go 不会自动将整数转换为浮点值。 

DP 数组是使用切片实现的`float64`。 由于所有概率都是十进制值，因此整个解决方案都需要浮点运算。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k == 0`。 在这种情况下，爱丽丝永远不会抽牌，因为她已经满足了停止条件。 她的分数仍然`0`，它总是小于或等于`n`。 一个常见的错误是继续进入 DP 逻辑并产生不正确的概率。 该实现立即处理这个问题并提前返回`1.0`。 

另一个棘手的情况发生在`n >= k + maxPts - 1`。 最大可能的停止分数是`k + maxPts - 1`，因为最终抽签最多增加`maxPts`。 如果`n`至少有这么大，那么每个可能的最终分数都是有效的。 如果没有这种优化，DP 仍然可以工作，但会发生不必要的计算。 执行返回`1.0`立即地。 

一个微妙的边缘情况涉及从滑动窗口中删除过时的概率。 如果移除指数相差 1，概率可能会在窗口中停留太久或消失得太早，从而导致平均值不正确。 该实现小心地删除了：```
dp[score - maxPts]
```确切的时间：```
score >= maxPts
```它在每次迭代时保留正确的过渡范围。
