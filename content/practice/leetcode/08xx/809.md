[LeetCode 第 809 题](https://leetcode.com/problems/expressive-words/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定有多少个单词`words`数组可以转换为目标字符串`s`使用非常特定类型的扩展操作。 

关键概念是，单词中的字符只有属于最终大小至少为 3 的组时才能扩展。 组是相邻相同字符的序列。 例如，在字符串中`"heeellooo"`，这些组是：

 -`"h"`长度为 1
 -`"eee"`长度为 3
 -`"ll"`长度为 2
 -`"ooo"`长度为 3

 如果我们可以重复扩展某个单词的某些组，直到它完全等于`s`。 

重要的限制是，只有当结果组处于`s`has size at least 3. This creates three critical rules:

- The characters in both strings must appear in the same order.
 - Corresponding groups must contain the same character.
 - 如果一组在`s`长度小于 3，则该单词必须已经具有完全相同的组长度。 
- 如果一组在`s`长度至少为 3，则单词的组长度可能更小，因为它可以扩展。 

输入包括：

 - 目标字符串`s`- 一个数组`words`输出是满足拉伸条件的单词数。 

限制很小：

 - 长度`s`最多 100
 - 字数最多100个
 - 每个单词长度最多100

 这些限制意味着即使`O(n * m)`风格解决方案是完全可以接受的，其中`n`是单词数，`m`是字符串长度。 

一些边缘情况很重要：

 - 具有不同字符顺序的单词永远无法匹配。 
- 一个较小的团体`s`无法吸收多余的字符。 
- 单字符组尤其受到限制。 
- 完全相同的字符串应该算作有弹性。 
- 非常简短的话语可能会失败，因为它们无法合法地扩大足够的群体。 

## 方法

 ### 蛮力方法

 暴力策略将尝试模拟每个单词的所有可能的扩展操作，直到：

 - 这个词变得等于`s`- 单词变得太大或无法匹配

 这种方法在理论上是正确的，因为它探索了所有有效的转换。 然而，它很快就变得不切实际，因为每个可扩展组都可以以多种不同的方式增长，从而创建一个大的分支搜索空间。 

例如，如果一个单词包含多个可扩展组，则需要测试多种扩展长度组合。 尽管约束很小，但详尽的生成是不必要的且效率低下。 

重要的观察是我们实际上不需要模拟扩展。 我们只需要比较两个字符串的组结构即可。 

### 最佳方法

 最佳方案是使用两个指针逐组扫描两个字符串。 

关键的见解是，弹性行为完全取决于相应字符组的长度。 

对于每个组：

 - 如果字符不同，则单词无法匹配。 
- 如果该组在`s`小于 3，则两组的大小必须完全相同。 
- 如果该组在`s`至少为 3，单词的组可以更小，但不能更大。 

这使我们能够在一次线性扫描中验证一个单词。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 模拟所有可能的扩展 |
 | 最佳 | O(宽×N) | O(1) | O(1) | 直接比较字符组 |

 这里：

-`W`是单词数
 -`N`是最大字符串长度

 ## 算法演练

 ### 最优两指针算法

 1.初始化两个指针，一个用于`s`and one for the current word.

 这些指针允许我们从左到右处理两个字符串，同时将连续的相同字符分组在一起。 
2. At each step, compare the current characters.

 如果字符不同，则字符串不可能匹配，因为扩展永远不会改变字符顺序。 
3. 计算两个字符串中当前字符组的大小。 

例如：

-`"eee"`团体人数为 3
 -`"ll"`团体人数为 2

 我们继续前进，直到角色发生变化。 
4. 应用弹性规则。 

让：

-`countS`是组长度`s`-`countW`是单词中的组长度

 无效的情况有两种：

 -`countS < countW`该词的字符数已超过`s`，不能通过扩展来修复。 
-`countS != countW`和`countS < 3`如果目标组小于3，则扩展是非法的，因此长度必须完全匹配。 
5. 继续处理所有组。 

每个组都必须满足单词有弹性的规则。 
6. 处理后，确保两个字符串都被完全消耗。 

如果一个字符串仍有剩余字符，则结构不同，该单词无效。 
7. 对每个单词重复并计算有多少个成功。 

### 为什么它有效

 该算法之所以有效，是因为拉伸仅影响组大小，而不会影响字符顺序或组顺序。 

通过直接比较相应的组，我们准确验证较小的单词是否可以合法扩展为`s`。 

这些规则完全描述了所有有效转换的特征：

 - 团体在`s`小于3的不能扩展。 
- 团体在`s`大小至少为 3 的字符可以吸收额外的重复字符。 

由于每个组都是独立检查的并且所有组都必须匹配，因此该算法是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def expressiveWords(self, s: str, words: List[str]) -> int:
        
        def is_stretchy(word: str) -> bool:
            i = 0
            j = 0
            
            while i < len(s) and j < len(word):
                
                if s[i] != word[j]:
                    return False
                
                char_s = s[i]
                count_s = 0
                
                while i < len(s) and s[i] == char_s:
                    i += 1
                    count_s += 1
                
                char_w = word[j]
                count_w = 0
                
                while j < len(word) and word[j] == char_w:
                    j += 1
                    count_w += 1
                
                if count_s < count_w:
                    return False
                
                if count_s != count_w and count_s < 3:
                    return False
            
            return i == len(s) and j == len(word)
        
        stretchy_count = 0
        
        for word in words:
            if is_stretchy(word):
                stretchy_count += 1
        
        return stretchy_count
```该实现定义了一个辅助函数`is_stretchy`检查单个单词是否可以扩展为`s`。 

两个指针，`i`和`j`，跟踪位置`s`和当前的单词。 该代码重复提取匹配的字符组并计算它们的长度。 

第一个验证条件检查该单词在组中的字符数是否多于`s`。 这是不可能的，因为扩展只会添加字符。 

第二个验证条件强制执行扩展规则。 如果群体规模不同，则目标群体`s`尺寸必须至少为 3。 

处理完所有组后，两个指针必须到达各自字符串的末尾。 这保证了整个结构的正确匹配。 

最后，主函数迭代每个单词并计算有效单词。 

## 解决方案```go
func expressiveWords(s string, words []string) int {
    
    isStretchy := func(word string) bool {
        i := 0
        j := 0
        
        for i < len(s) && j < len(word) {
            
            if s[i] != word[j] {
                return false
            }
            
            charS := s[i]
            countS := 0
            
            for i < len(s) && s[i] == charS {
                i++
                countS++
            }
            
            charW := word[j]
            countW := 0
            
            for j < len(word) && word[j] == charW {
                j++
                countW++
            }
            
            if countS < countW {
                return false
            }
            
            if countS != countW && countS < 3 {
                return false
            }
        }
        
        return i == len(s) && j == len(word)
    }
    
    result := 0
    
    for _, word := range words {
        if isStretchy(word) {
            result++
        }
    }
    
    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

因为 Go 字符串是字节索引的，所以直接索引在这里可以安全地工作，因为问题只保证小写英文字母。 

辅助函数作为内部的闭包实现`expressiveWords`。 组计数使用简单循环和整数计数器。 

由于字符串长度非常小，因此不存在特殊的溢出问题。

 ## 边缘情况

 ### 目标群体规模小于三人

 错误的一个非常常见的来源是忘记了大小为 1 或 2 的组`s`无法扩展。 

例如：```
s = "ll"
word = "l"
```即使单词仅相差一个字符，这种转换也是非法的，因为目标组的大小仅为 2。仅当结果组的大小至少为 3 时才允许扩展。 

该实现通过以下方式处理此问题：```
if count_s != count_w and count_s < 3:
    return False
```### 单词包含的字符多于目标字符

 当一个单词已经拥有比`s`。 

例如：```
s = "helo"
word = "helllo"
```没有操作会删除字符，因此这永远不会匹配。 

实现正确地拒绝此类情况，使用：```
if count_s < count_w:
    return False
```### 不同的字符排序

 拉伸永远不会改变字符顺序。 

例如：```
s = "heeellooo"
word = "heeleloo"
```即使组数看起来相似，但组的顺序不同，因此无法进行转换。 

该算法立即使用以下方法检测到这一点：```
if s[i] != word[j]:
    return False
```这保证了不匹配的结构会尽早失败。
