[LeetCode 816 题](https://leetcode.com/problems/ambigously-coordinates/)

 **难度：** 🟡 中等
 **主题：** 字符串、回溯、枚举

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二维坐标的压缩字符串表示。 最初，坐标看起来像`"(1, 3)"`或者`"(2, 0.5)"`，但所有逗号、空格和小数点都被删除。 我们的任务是重建每个可能的有效原始坐标对。 

例如：```
"(1, 3)" -> "(13)"
"(2, 0.5)" -> "(205)"
```给定压缩字符串，我们必须返回所有可能产生它的坐标对。 

坐标由两个数字组成：```
(x, y)
```两个都`x`和`y`可以是整数或小数。 但是，该问题施加了严格的格式规则：

 1. 数字不能包含不必要的前导零。 
2. 数字小数点后不能包含不必要的尾随零。 
3. 十进制数必须在小数点前至少包含一位数字。 

这意味着以下内容无效：```
"00"
"01"
"1.0"
"0.00"
".5"
```但这些都是有效的：```
"0"
"0.1"
"10"
"1.23"
```输入长度非常小：```
4 <= s.length <= 12
```由于字符串很小，我们可以列举许多可能性。 挑战不在于计算规模，而在于正确处理所有格式规则和涉及零的边缘情况。 

最重要的观察是，每个有效坐标都来自将数字分成两个非空部分：```
(left_part, right_part)
```然后，对于每个部分，我们通过选择插入小数点来生成所有有效的数字表示。 

一些边缘情况很容易破坏简单的实现：

 - 带有前导零的数字，例如`"012"`- 以零结尾的十进制数，例如`"1.20"`- 完全由零组成的字符串，例如`"000"`- 个位数，始终有效
 - 以零开头和结尾的数字，几乎所有小数位都无效

 该问题保证输入仅包含括号括起来的数字，因此我们永远不需要验证字符。 

## 方法

 ### 蛮力方法

 暴力破解的想法是尝试一切可能的方法来重建原始字符串。 

我们可以：

 1. 去掉最外面的括号。 
2. 将剩余的数字拆分为每个可能的左右子串。 
3. 对于每个子字符串，尝试插入所有可能的小数点。 
4. 验证生成的数字是否遵循所有格式规则。 
5. 将所有有效的左右数字组合成坐标字符串。 

这是有效的，因为每个有效答案都必须来自某个分割位置和某个小数位。 

然而，天真的暴力实现会重复构造无效字符串并执行不必要的检查。 如果不仔细编码格式化规则，实现就会变得混乱且容易出错。 

尽管限制足够小，在技术上可以通过暴力破解，但我们可以设计一个更干净、更系统的解决方案。 

### 关键见解

 关键的见解是每个子字符串都可以独立生成所有有效的数字表示。 

对于像这样的子字符串`"123"`:

 -`"123"`有效
 -`"1.23"`有效
 -`"12.3"`有效

 但对于`"012"`:

 -`"012"`由于前导零而无效
 -`"0.12"`有效
 -`"01.2"`无效

 我们可以直接生成有效的数字，而不是生成任意字符串并稍后进行验证。 

这导致了一个干净的辅助函数：```
generateCandidates(substring)
```该助手返回该子字符串的每个有效表示。 

那么完整的解决方案就变成了：

 1. 将数字分成左右部分。 
2. 生成所有有效的左数。 
3. 生成所有有效的正确数字。 
4. 将它们组合起来。 

由于输入很小，因此这种枚举方法非常有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n^3) | O(n^3) | 通过重复验证尝试所有分割和小数位 |
 | 最佳 | O(n^3) | O(n^3) | O(n^3) | O(n^3) | 直接生成仅有效的数字形式 |

 ## 算法演练

 1. 从输入字符串中删除最外层的括号。 

如果输入是`"(123)"`，我们与：```
"123"
```2. 迭代每个可能的分割位置。 

对于一个长度的字符串`n`，分割索引范围为`1`到`n - 1`。 

例子：```
"123"
```可能的分裂：```
"1" | "23"
"12" | "3"
```3. 对于每个子字符串，生成所有有效的数字表示。 

我们创建一个处理一个子字符串的辅助函数。 

帮助器首先检查整个子字符串是否是有效的整数表示。 

规则：

 - 个位数始终有效
 - 多位整数不能以`'0'`4. 生成十进制表示形式。 

对于每个可能的小数点位置：```
left = s[:i]
right = s[i:]
```十进制数是：```
left + "." + right
```仅当满足以下条件时才有效：

 - 整数部分没有前导零，除非它恰好是`"0"`- 小数部分不以`'0'`5. 合并有效的左右候选者。 

对于每个有效的左数和每个有效的右数：```
"(" + left + ", " + right + ")"
```将结果添加到答案列表中。 
6. 返回完成的列表。 

### 为什么它有效

 每个有效坐标必须恰好来自左坐标和右坐标之间的一个分割位置。 对于每一侧，每个有效的数字表示都由辅助函数生成一次。 由于使用格式规则过滤无效表示，因此该算法会生成所有有效坐标，而不会生成无效坐标。 

## Python 解决方案```python
from typing import List

class Solution:
    def ambiguousCoordinates(self, s: str) -> List[str]:
        digits = s[1:-1]

        def generate_candidates(part: str) -> List[str]:
            candidates = []

            # Integer form
            if len(part) == 1 or part[0] != '0':
                candidates.append(part)

            # Decimal forms
            for i in range(1, len(part)):
                integer_part = part[:i]
                fractional_part = part[i:]

                # Leading zero rule
                if len(integer_part) > 1 and integer_part[0] == '0':
                    continue

                # Trailing zero rule
                if fractional_part[-1] == '0':
                    continue

                candidates.append(integer_part + "." + fractional_part)

            return candidates

        result = []

        for split_index in range(1, len(digits)):
            left_part = digits[:split_index]
            right_part = digits[split_index:]

            left_candidates = generate_candidates(left_part)
            right_candidates = generate_candidates(right_part)

            for left in left_candidates:
                for right in right_candidates:
                    result.append(f"({left}, {right})")

        return result
```实现首先删除外面的括号，这样我们就可以直接使用数字序列。 

这`generate_candidates`helper 是解决方案的核心。 它生成子字符串的每个有效表示。 首先，它检查子字符串本身是否可以用作整数。 带有前导零的多位整数将被拒绝。 

接下来，助手尝试插入每个小数点。 对于每个分割：```python
integer_part.fractional_part
```它验证格式规则：

 - 整数部分不能有不必要的前导零。 
- 小数部分不能以零结尾。 

只有有效的代表才会添加到候选列表中。 

主循环迭代每个可能的分割`x`和`y`坐标。 每一方独立生成有效的表示，并将每一对组合成最终的坐标字符串。 

## 解决方案```go
func ambiguousCoordinates(s string) []string {
	digits := s[1 : len(s)-1]

	generateCandidates := func(part string) []string {
		candidates := []string{}

		// Integer form
		if len(part) == 1 || part[0] != '0' {
			candidates = append(candidates, part)
		}

		// Decimal forms
		for i := 1; i < len(part); i++ {
			integerPart := part[:i]
			fractionalPart := part[i:]

			// Leading zero rule
			if len(integerPart) > 1 && integerPart[0] == '0' {
				continue
			}

			// Trailing zero rule
			if fractionalPart[len(fractionalPart)-1] == '0' {
				continue
			}

			candidate := integerPart + "." + fractionalPart
			candidates = append(candidates, candidate)
		}

		return candidates
	}

	result := []string{}

	for splitIndex := 1; splitIndex < len(digits); splitIndex++ {
		leftPart := digits[:splitIndex]
		rightPart := digits[splitIndex:]

		leftCandidates := generateCandidates(leftPart)
		rightCandidates := generateCandidates(rightPart)

		for _, left := range leftCandidates {
			for _, right := range rightCandidates {
				result = append(result, "("+left+", "+right+")")
			}
		}
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 切片用于有效地提取子字符串。 由于 Go 字符串是不可变的字节切片，因此子字符串操作非常简单，因为输入仅包含 ASCII 数字。 

辅助函数返回有效表示的切片。 最终答案是使用左右候选切片上的嵌套循环来累积的。 

不需要特殊的整数溢出处理，因为我们从不将字符串转换为数值。

 ## 边缘情况

 ### 前导零

 输入如：```
"01"
"001"
```很棘手，因为带有前导零的整数无效。 幼稚的实现可能会错误地允许`"01"`作为有效整数。 

该解决方案通过仅在以下情况下接受多位整数来处理此问题：```
part[0] != '0'
```否则，子字符串只能以十进制形式出现，例如`"0.1"`。 

### 小数中的尾随零

 价值观如：```
"1.0"
"2.30"
```必须被拒绝，因为原始表示从未包含不必要的尾随零。 

实施检查：```
fractional_part[-1] == '0'
```如果为 true，则跳过该十进制表示形式。 

### 以零开头和结尾的数字

 子串如：```
"000"
"0001"
```特别容易出错，因为大多数小数位都变得无效。 

例如：```
"0001"
```不能成为：```
"00.01"
"000.1"
```因为整数部分将包含前导零。 

该实现仔细地独立验证整数和小数部分，确保只有有效的形式，例如：```
"0.001"
```已正确生成。
