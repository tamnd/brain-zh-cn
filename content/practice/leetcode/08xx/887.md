[LeetCode 第 887 题](https://leetcode.com/problems/super-egg-drop/)

 **难度：** 🔴难
 **主题：** 数学、二分查找、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们确定使用有限数量的鸡蛋来识别建筑物中的关键楼层所需的最少移动次数。 

我们有两个整数：

 -`k`, 相同鸡蛋的数量
 -`n`, 建筑物的层数

 存在一些未知的楼层`f`这样：

 - 任何从高于以下楼层掉落的鸡蛋`f`会打破
 - 任何从地板上掉落的鸡蛋`f`或以下将生存

 我们的任务是确定`f`确定性，同时最大限度地减少最坏情况下的移动次数。 

一次移动包括从选定的楼层掉落一个鸡蛋。 掉落后：

 - 如果鸡蛋破裂，则不能再使用
 - 如果它幸存下来，仍然可以重复使用

 关键词是“确定”。 这意味着该策略必须适用于每个可能的价值`f`从`0`到`n`。 

约束条件很重要：

 -`1 <= k <= 100`-`1 <= n <= 10^4`由于状态数量急剧增长，对所有楼层进行简单的递归搜索很快就会变得太慢。 自从`n`可以大到 10,000，我们需要高度优化的动态规划方法。 

一些边缘情况尤其重要：

 - 当`k = 1`，我们只能从下到上依次测试楼层
 - 当`n = 1`，答案总是`1`- 当相对于楼层有很多鸡蛋时，最优策略变得非常高效
 - 大值，例如`k = 100`和`n = 10000`需要避免二次或三次动态规划解决方案

 ## 方法

 ### 暴力动态规划

 一个简单的方法是定义：`dp(eggs, floors)`= 所需的最小移动次数`eggs`鸡蛋和`floors`地板。 

对于每一个可能的楼层`x`我们扔鸡蛋的地方：

 - 如果鸡蛋破了，我们必须在下面寻找`x`，这给出：`dp(eggs - 1, x - 1)`- 如果蛋存活下来，我们必须在上面搜索`x`，这给出：`dp(eggs, floors - x)`由于我们必须保证最坏情况下的正确性，因此我们取两个结果中的最大值：```
1 + max(
    dp(eggs - 1, x - 1),
    dp(eggs, floors - x)
)
```然后我们尝试一切可能`x`从`1`到`floors`并选择最小结果。 

这种递归是正确的，因为每次删除都会将搜索空间划分为两个互斥的可能性。 然而，它太慢了，因为每个状态都会遍历所有楼层，产生粗略的结果`O(k * n^2)`即使有记忆也很复杂。 

为了`n = 10000`，这变得不切实际。 

### 通过移动进行最优动态规划

 关键的洞察力是扭转问题。 

而不是问：

 > “最少需要多少步`n`楼层？”

 我们问：

 >“与`m`移动和`k`鸡蛋，我们可以测试多少层？”

 定义：```
dp[m][k] = maximum number of floors that can be determined
           using m moves and k eggs
```假设我们丢了一个鸡蛋：

 - 如果它坏了，我们可以测试`dp[m-1][k-1]`以下楼层
 - 如果它幸存下来，我们可以测试`dp[m-1][k]`以上楼层
 - 加上当前楼层本身

 这给出了递归式：$dp[m][k] = dp[m-1][k-1] + dp[m-1][k] + 1$这种公式的效率显着提高，因为所需的移动次数增长相对缓慢。 我们反复增加移动次数，直到可测试楼层数达到或超过`n`。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k * n²) | O(k * n²) | O(k * n) | 尝试每个州的每个下降楼层|
 | 最佳| O(k * 米) | O(k) | 使用基于移动的 DP，其中`m`就是答案|

 自从`m`通常比`n`，最佳方法在实践中速度极快。 

## 算法演练

 ### 最优动态规划算法

 1. 创建一维DP数组其中`dp[e]`表示使用当前移动次数可以测试的最大楼层数，`e`鸡蛋。 
2. 将所有值初始化为`0`因为零移动我们无法确定任何楼层。 
3. 开始一项一项地增加动作数量。 
4. 对于每次移动，从右到左更新 DP 数组。 从右到左更新很重要，因为每个状态都取决于上一次移动迭代的值。 
5. 应用递归：$dp[e] = dp[e] + dp[e-1] + 1$这里：

-`dp[e]`更新前代表`dp[m-1][e]`-`dp[e-1]`代表`dp[m-1][e-1]`-`+1`占当前楼层
 6. 更新当前移动的所有鸡蛋计数后，检查是否`dp[k] >= n`。 
7.一次`dp[k]`达到或超过`n`，返回当前的移动次数。 

### 为什么它有效

 递归正确地计算了我们在额外移动一次后可以区分的所有楼层。 掉落会产生两个子问题：

 - 如果鸡蛋破裂，则低于掉落地板
 - 如果鸡蛋幸存，则位于掉落地板上方

 由于这些区域是不相交的，并且当前楼层本身也被测试，因此可区分楼层的总数是两个区域的总和加一。 通过逐步增加移动，第一个移动计数至少覆盖`n`楼层保证是最低答案。 

## Python 解决方案```python
class Solution:
    def superEggDrop(self, k: int, n: int) -> int:
        dp = [0] * (k + 1)
        moves = 0

        while dp[k] < n:
            moves += 1

            for eggs in range(k, 0, -1):
                dp[eggs] = dp[eggs] + dp[eggs - 1] + 1

        return moves
```该实现使用一维动态规划数组来节省空间。`dp[eggs]`存储当前可以使用给定数量的鸡蛋和当前移动计数测试的最大楼层数。 

该算法反复增加移动次数，直到覆盖范围足够大以包含所有`n`地板。 

更新循环向后运行，因为每个状态都取决于前一步的值。 如果我们从左到右更新，我们将覆盖同一迭代中稍后需要的值。 

复发：$dp[e] = dp[e] + dp[e-1] + 1$编码了掉落鸡蛋的两种可能结果：

 - 鸡蛋打碎，少用一个鸡蛋
 - 鸡蛋存活，保留相同数量的鸡蛋

 一旦可以测试足够的楼层，算法就会立即停止。 

## 解决方案```go
func superEggDrop(k int, n int) int {
    dp := make([]int, k+1)
    moves := 0

    for dp[k] < n {
        moves++

        for eggs := k; eggs >= 1; eggs-- {
            dp[eggs] = dp[eggs] + dp[eggs-1] + 1
        }
    }

    return moves
}
```Go 实现密切反映了 Python 逻辑。 

使用切片而不是 Python 列表。 由于 Go 整数是固定宽度的，因此值得注意的是，这些值安全地保持在给定约束的范围内。 

向后迭代顺序在 Go 中同样重要，因为递归取决于先前迭代状态的值。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k * 米) |`m`移动，每次更新`k`鸡蛋 |
 | 空间| O(k) | 一个大小为 DP 的数组`k + 1`|

 移动次数`m`是算法返回的最小答案。 在实践中，`m`增长速度比`n`，使得该解决方案即使对于大型建筑也极其高效。 

空间优化之所以有效，是因为每个 DP 状态仅取决于前一个移动的值，从而允许压缩为单个数组。

 ## 边缘情况

 ### 单蛋

 当只有一个鸡蛋可用时，算法不能使用分而治之的策略，因为打破鸡蛋会结束所有未来的测试。 唯一安全的方法是从下向上的线性搜索。 

这种情况是错误优化的常见原因。 DP 公式可以自然地处理它，因为：$dp[m][1] = m$意思是一个鸡蛋和`m`动作可以准确测试`m`地板。 

### 楼层数很少

 类似的情况`n = 1`或者`n = 2`很容易因差一错误而误处理。 初始化 DP 状态时，某些实现会意外返回一层的零步数或过量计数步数。 

此实现避免了这些问题，因为 DP 从零覆盖率开始，并且仅在执行移动后才递增。 

### 大量鸡蛋

 当`k`比需要的大得多，一些递归方法浪费了大量的计算来探索冗余状态。 

基于移动的 DP 仍然高效，因为它只跟踪每次移动后可以覆盖的楼层数。 即使与`k = 100`，答案为`n = 10000`非常小，因此算法很快完成。 

### 就地 DP 更新

 从左到右更新 DP 数组会破坏同一迭代中稍后所需的值。 这是一个微妙的错误，会产生不正确的结果。 

该实现从右向左更新，专门是为了在计算过程中保留前一步的状态。
