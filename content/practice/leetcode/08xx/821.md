[LeetCode 821 题](https://leetcode.com/problems/shortest-distance-to-a-character/)

 **难度：** 🟢简单
 **主题：** 数组、两个指针、字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`和一个目标角色`c`。 对于字符串中的每个索引，我们必须计算到最近出现的距离`c`。 

两个索引之间的距离定义为：$$|i - j|$$在哪里`i`是当前索引并且`j`是某些事件发生的索引`c`。 

结果应该是一个整数数组，其中：

 -`answer[i]`表示距索引的最小距离`i`任何出现的字符`c`- 返回的数组必须与字符串长度相同

 例如，如果：```
s = "loveleetcode"
c = "e"
```然后是角色`'e'`出现在索引处：```
3, 5, 6, 11
```对于索引`0`，最近的`'e'`位于索引处`3`，所以距离为：```
abs(0 - 3) = 3
```对于索引`4`，有两个同样接近的`'e'`索引处的字符`3`和`5`, 两者都有距离`1`。 

限制相对较小：

 -`1 <= s.length <= 10^4`- 所有字符均为小写英文字母
 -`c`保证至少出现一次

 保证`c`至少出现一次很重要，因为这意味着我们永远不需要处理不存在有效距离的不可能情况。 

有几种边缘情况需要尽早识别：

 - 目标角色只能出现一次
 - 目标字符可能出现在字符串的开头或结尾
 - 连续出现`c`可能存在
 - 字符串中的每个字符都可以等于`c`- 距离必须始终相对于最近的出现来计算，而不仅仅是第一次或最后一次出现

 如果仅沿一个方向扫描，则简单的实现很容易失败，因为最近的出现可能在左侧或右侧。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立计算每个位置的答案。 

对于每个索引`i`在字符串中：

 1. 迭代整个字符串
 2. 查找每一个出现的`c`3. 计算距离`i`对每一次出现
 4.保持最小距离

 这是有效的，因为它明确地检查所有可能的目标位置并选择最小距离。 

例如：```
s = "aaab"
c = "b"
```对于索引`0`，我们扫描整个字符串并找到`'b'`在索引处`3`:```
abs(0 - 3) = 3
```这会产生正确的结果，但效率很低，因为对于每个字符，我们都会再次扫描整个字符串。 

如果字符串长度为`n`，那么：

 - 外循环运行`n`次
 - 内循环也运行`n`次

 这给出了时间复杂度：$$O(n^2)$$虽然`10^4`不是很大，一个`O(n^2)`这里不需要解，因为存在更有效的线性解。 

### 最佳两遍方法

 关键的观察结果是最近出现的`c`可以来自：

 - 最接近的出现在左边
 - 右侧最接近的出现位置

 我们可以处理字符串两次，而不是重复搜索整个字符串：

 1.从左到右
 2.从右到左

 在从左到右的传递过程中：

 - 跟踪最近发生的情况`c`- 计算到最近的距离`c`在左边

 在从右向左传递期间：

 - 跟踪最近发生的事件`c`在右边
 - 用以下最小值更新每个答案：

 - 现有左侧距离
 - 合适的距离

 这是可行的，因为每个最接近的出现点都必须位于当前位置的左侧或右侧。 

由于每次传递都会接触每个字符一次，因此总运行时间变为线性。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 | 最佳 | O(n) | O(1) 不包括输出 | 使用两个定向传递来计算最近距离 |

 ## 算法演练

 ### 最佳两遍算法

 1. 创建结果数组`answer`尺寸的`n`。 

该数组最终将存储每个索引的最小距离。 
2. 执行从左到右的传递。 

维护一个变量`previous_position`代表最近的索引 where 字符`c`出现了。 

最初，将其设置为一个非常大的负数，以便第一次出现之前的位置产生较大的距离。 
3. 对于每个索引`i`从左到右：

 - 如果`s[i] == c`， 更新`previous_position = i`- 计算：```
i - previous_position
```- 将此值存储在`answer[i]`在此刻，`answer[i]`表示到最近的距离`c`在左侧。 
4. 执行从右到左的传递。 

维护另一个变量`next_position`代表最近出现的`c`在右侧。 

最初，将其设置为一个非常大的正数。 
5. 对于每个索引`i`从右到左：

 - 如果`s[i] == c`， 更新`next_position = i`- 计算：```
next_position - i
```- 更新：```
answer[i] = min(answer[i], next_position - i)
```现在`answer[i]`包含距任一侧的最小距离。 
6.返回填写完毕的`answer`大批。 

### 为什么它有效

 第一次通过后，每个索引都知道到最近出现的距离`c`在其左侧。 

在第二遍之后，每个索引还考虑其右侧最近的出现。 

由于最近发生的`c`必须位于左侧或右侧，取这两个距离中的最小值即可保证正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def shortestToChar(self, s: str, c: str) -> List[int]:
        n = len(s)
        answer = [0] * n

        previous_position = -n

        # Left-to-right pass
        for i in range(n):
            if s[i] == c:
                previous_position = i

            answer[i] = i - previous_position

        next_position = 2 * n

        # Right-to-left pass
        for i in range(n - 1, -1, -1):
            if s[i] == c:
                next_position = i

            answer[i] = min(answer[i], next_position - i)

        return answer
```实现首先初始化结果数组并存储字符串长度。 

变量`previous_position`跟踪最近发生的`c`从左到右扫描时。 最初它被设置为`-n`，它的行为就像字符串开始之前很远的地方。 

在第一遍期间：

 - 当当前字符等于`c`，我们更新`previous_position`- 否则我们计算从当前索引到左侧最近出现的位置的距离

 在这一遍之后，每个元素存储最短的左侧距离。 

第二遍使用从右到左扫描`next_position`，它跟踪最近出现的`c`在右侧。 

对于每个索引：

 - 计算右侧距离
 - 取现有左侧距离和新右侧距离之间的最小值

 最后，数组包含最短的可能距离。 

## 解决方案```go
func shortestToChar(s string, c byte) []int {
	n := len(s)
	answer := make([]int, n)

	previousPosition := -n

	// Left-to-right pass
	for i := 0; i < n; i++ {
		if s[i] == c {
			previousPosition = i
		}

		answer[i] = i - previousPosition
	}

	nextPosition := 2 * n

	// Right-to-left pass
	for i := n - 1; i >= 0; i-- {
		if s[i] == c {
			nextPosition = i
		}

		rightDistance := nextPosition - i

		if rightDistance < answer[i] {
			answer[i] = rightDistance
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

一些特定于 Go 的细节值得注意：

 - Go 中的字符串是字节切片，因此索引为`s[i]`直接返回一个字节
 - 目标字符给出为`byte`-`make([]int, n)`初始化结果切片
 - Go不提供内置的`min`整数函数，因此我们手动比较值

 不存在整数溢出问题，因为最大字符串长度仅为`10^4`。

 ## 边缘情况

 ### 目标角色仅出现一次

 错误的常见来源是假设存在多次出现。 考虑：```
s = "aaab"
c = "b"
```每个距离都必须相对于相同的指数来测量。 两次传递算法自然地处理这个问题，因为两次传递最终都引用单个有效的出现。 

### 开头或结尾的目标字符

 边界位置常常会产生相差一的误差。 

例子：```
s = "baaa"
c = "b"
```在从左到右传递期间，第一个字符立即设置最​​近的位置。 在从右到左传递期间，距离被正确保留，因为最小操作保持较小的值。 

类似地，当目标位于末端时，从右到左的传递可以正确处理距离。 

### 目标连续出现

 考虑：```
s = "abbbba"
c = "b"
```当存在多个相邻目标时，幼稚的实现可能会意外地错误地覆盖距离。 

在此解决方案中，每当`s[i] == c`，当前位置成为最新的最近出现的位置。 由于距离在这些索引处变为零，因此周围位置会在两个方向上自动正确计算。 

### 每个字符都等于目标

 示例：```
s = "aaaa"
c = "a"
```每个索引都应该产生距离`0`。 

两次遍历都会在每一步不断更新最近的事件，因此每个计算的距离立即变为零。 这验证了该实现是否正确处理密集目标分布。
