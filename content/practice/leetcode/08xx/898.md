[LeetCode 第 898 题](https://leetcode.com/problems/bitwise-ors-of-subarrays/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们计算由给定数组的所有非空连续子数组组成的每个可能的按位或值`arr`，然后返回存在多少个不同的值。 

子数组是数组的任何连续切片。 例如，如果`arr = [1,2,4]`，有效的子数组是：

 -`[1]`-`[2]`-`[4]`-`[1,2]`-`[2,4]`-`[1,2,4]`对于每个子数组，我们计算其所有元素的按位或。 按位 OR 运算符将位组合起来，使得一个位变成`1`如果它被设置在至少一个操作数中。 

例如：

-`1 | 2 = 3`-`2 | 4 = 6`-`1 | 2 | 4 = 7`目标不是计算子数组，而是计算出现了多少个唯一的 OR 结果。 

输入是一个整数数组：

 -`1 <= arr.length <= 5 * 10^4`-`0 <= arr[i] <= 10^9`这些限制非常重要。 显式计算每个子数组的 OR 的简单解决方案将大致涉及`O(n^2)`子数组，当`n = 50,000`。 

该问题保证：

 - 数组非空。 
- 值是非负的。 
- 值非常适合标准 32 位整数运算。 

一些边缘情况很重要：

 - 仅包含零的数组，因为重复的 OR 运算永远不会改变值。 
- 具有重复值的数组，因为许多子数组可以产生相同的 OR 结果。 
- OR 值快速饱和为大掩码的数组，例如`7`,`15`， 或者`31`。 
- 单元素数组，因为答案仍必须包含该元素的值。 

## 方法

 ### 蛮力方法

 最直接的方法是生成每个可能的子数组并计算其按位或。 

对于每个起始索引`i`，我们将子数组向右扩展一次一个元素：

 - 开始于`current_or = 0`- 对于每个结束索引`j >= i`- 更新`current_or |= arr[j]`- 将结果插入集合中

 使用集合可以自动保证唯一性。 

这种方法是正确的，因为它显式枚举每个有效子数组并仅计算其 OR 一次。 

然而，有`O(n^2)`子数组。 和`n = 50,000`，这变得太慢了。 Even though OR computation itself is constant time, iterating over billions of subarrays is not practical.

 ### 最佳解决方案的关键见解

 The critical observation is that the number of distinct OR values generated from subarrays ending at a fixed index is actually very small.

 假设我们从左到右处理数组。 在位置`i`，考虑所有以`i`。 

每个这样的子数组可以通过以下方式形成：

 - 取一个结束于的子数组`i - 1`- 与它进行或运算`arr[i]`或者：

 - 启动一个全新的子数组，仅包含`arr[i]`按位或的关键属性是单调性：

 - 一旦一点点变成`1`，它永远不会成为`0`这意味着 OR 值只能随着子数组的增长而增加。 

Because integers contain at most around 30 meaningful bits here, the number of distinct OR values for subarrays ending at a given position is bounded by approximately 30 to 32 unique states.

 我们不存储所有子数组，而是只存储从以当前索引结尾的子数组中获得的不同 OR 值。 

这大大降低了复杂性。

 ## 算法演练

 1. 初始化一个名为的全局集`all_results`。 

该集合存储整个数组中所有子数组中看到的每个不同的 OR 值。 
2. 初始化另一组名为`previous`。 

该集合表示以前一个索引结尾的子数组的所有不同 OR 值。 
3. 迭代每个数字`num`在数组中。 

在每一步中，我们都希望计算以当前位置结尾的子数组的所有不同 OR 值。 
4. 创建一个新集合，名为`current`。 

开始它`{num}`因为仅包含当前元素的子数组始终有效。 
5. 扩展之前的每个子数组。 

对于每个值`value`在`previous`:

 - 计算`value | num`- 将结果插入`current`这模拟了将结束于前一位置的每个子数组扩展一个附加元素。 
6. 将新生成的OR值合并为`all_results`。 

这会累积全球所有唯一的 OR 值。 
7. 更新`previous = current`。 

当前集合现在成为在此位置结束的子数组的 OR 值集合。 
8.处理完整个数组后，返回大小`all_results`。 

### 为什么它有效

 不变量是：

 -`previous`始终包含由以前一个索引结尾的所有子数组生成的一组不同的 OR 值。 

加工时`arr[i]`，每个子数组结束于`i`是：

 - 单元素子数组`[arr[i]]`- 结束于的子数组的扩展`i - 1`通过 OR 运算`arr[i]`与每个值`previous`，我们为以以下结尾的子数组生成每个可能的 OR 值`i`。 

因为我们将值存储在集合中，所以重复项会被自动删除。 

由于每个子数组都在某个地方结束，因此收集所有中间集可以保证我们捕获每个不同的 OR 值。 

## Python 解决方案```python
from typing import List

class Solution:
    def subarrayBitwiseORs(self, arr: List[int]) -> int:
        all_results = set()
        previous = set()

        for num in arr:
            current = {num}

            for value in previous:
                current.add(value | num)

            all_results.update(current)
            previous = current

        return len(all_results)
```该实现紧密遵循前面描述的算法。`all_results`存储迄今为止发现的每个不同的 OR 值。 这是我们返回其大小的最终集合。`previous`跟踪以前一个索引结尾的子数组的所有 OR 值。 对于每个新元素`num`，我们构建了一个新的集合，称为`current`。 

该行：```python
current = {num}
```处理以当前索引开头和结尾的单元素子数组。 

接下来，我们扩展所有先前的子数组：```python
for value in previous:
    current.add(value | num)
```每个 OR 结果对应于追加`num`到较早的子数组。 

生成在此位置结束的所有可能的 OR 值后，我们将它们合并到全局答案集中：```python
all_results.update(current)
```最后：```python
previous = current
```将滑动状态向前移动以进行下一次迭代。 

实现很简洁，因为 Python 设置自然处理唯一性。 

## 解决方案```go
func subarrayBitwiseORs(arr []int) int {
    allResults := make(map[int]bool)
    previous := make(map[int]bool)

    for _, num := range arr {
        current := make(map[int]bool)
        current[num] = true

        for value := range previous {
            current[value|num] = true
        }

        for value := range current {
            allResults[value] = true
        }

        previous = current
    }

    return len(allResults)
}
```Go 解决方案使用`map[int]bool`模拟集合，因为 Go 没有提供内置的集合类型。 

整体逻辑与Python实现相同。 

一个新的`current`map 在每次迭代期间创建，用于存储以当前索引结尾的子数组的 OR 值。 

Go 整数安全地处理约束范围，因为`arr[i] <= 10^9`，完全在 32 位有符号整数限制内。 

与 Python 不同，Go 需要对映射键进行显式迭代：```go
for value := range previous
```最终的答案很简单：```go
len(allResults)
```因为映射只存储唯一的键。

实际上，即使对于最大输入大小，该算法也表现得非常高效。

 ## 边缘情况

 ### 仅包含零的数组

 如果数组是这样的`[0,0,0]`，每个子数组 OR 的计算结果为`0`。 

有缺陷的实现可能会重复计算重复项或无法正确删除重复项。 

此实现可以自然地处理这种情况，因为所有 OR 结果都插入到集合中。 不管多少次`0`出现后，最后一组仅包含一个值。 

### 重复值

 数组就像`[1,1,1]`可以生成许多重复的子数组 OR。 

例如：

-`[1] -> 1`-`[1,1] -> 1`-`[1,1,1] -> 1`简单的算法可能会浪费时间重复地重新计算相同的状态。 

优化方法避免了这个问题，因为`previous`只存储不同的 OR 值，而不是单独存储每个子数组。 

### 快速位饱和

 考虑一个像这样的数组`[1,3,7,15]`。 

一旦设置了许多位，扩展子数组通常会停止生成新的 OR 值。 

暴力解决方案仍然显式处理每个子数组。 

优化的解决方案受益于 OR 值快速稳定的事实。 滚动集的大小仍然很小，这使得即使对于大输入也能保持算法的效率。
