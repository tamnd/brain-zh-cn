[LeetCode 804 题](https://leetcode.com/problems/unique-morse-code-words/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定单词列表中存在多少个**独特的莫尔斯电码转换**。 

每个小写英文字母都映射到特定的莫尔斯电码表示形式。 通过将每个字符替换为其对应的莫尔斯电码并将结果连接到单个字符串中，可以将单词转换为莫尔斯电码。 

例如，假设我们有单词`"cab"`:

 -`'c'`变成`"-.-."`-`'a'`变成`".-"`-`'b'`变成`"-..."`连接这些给出：```
"-.-..--..."
```目标不是计算有多少个单词，而是计算每个单词转换后存在多少个**不同的莫尔斯电码转换**。 

例如，两个不同的单词可能会产生相同的莫尔斯序列。 在示例 1 中：

 -`"gin"`变成`"--...-."`-`"zen"`也变成`"--...-."`虽然单词不同，但它们共享相同的莫尔斯变换，因此它们算作一个唯一的结果。 

输入由一个数组组成`words`， 在哪里：

-`words.length`范围从`1`到`100`- 每个字的长度范围为`1`到`12`- 每个单词仅包含小写英文字母

 这些限制相当小。 即使是相对低效的解决方案也可能在限制范围内舒适地运行。 然而，由于该问题被归类为“简单”并且自然地映射到基于哈希的方法，因此我们应该致力于干净且高效的实现。 

一个重要的观察是单词可能映射到相同的莫尔斯字符串，因此我们需要一种有效消除重复的方法。 手动检查转换是否已经出现的幼稚实现可能会变得不必要的低效。 

一些边缘情况值得预先考虑。 单字输入应始终返回`1`，因为只有一个变换。 多个相同的单词仍应算作一种唯一的转换。 不同的单词也可能意外地映射到相同的莫尔斯电码表示形式，这意味着仅比较原始单词是不正确的。 该问题仅保证有效的小写字母，因此我们不需要处理无效字符、大写字母或空字符串。 

## 方法

 ### 蛮力方法

 暴力解决方案首先将每个单词转换为其莫尔斯变换并将这些变换后的字符串存储在列表中。 对于每个新生成的莫尔斯电码字符串，我们将扫描现有列表以检查该转换是否已存在。 

这是有效的，因为我们明确避免了重复的转换。 每个单词都会被翻译，在添加转换之前，我们会验证它是否已经存在。 

但是，检查列表内的重复项需要线性扫描。 如果有`n`换句话说，如果我们将每个转换与之前看到的转换进行比较，总运行时间可以呈二次方增长。 

尽管约束足够小，这仍然可以通过，但这不是最有效或最优雅的方法。 

### 关键见解

 关键的见解是，这个问题从根本上讲是关于计算**唯一值**。 

每当我们需要唯一性检查时，**哈希集**通常是理想的数据结构，因为插入和成员资格检查大约是`O(1)`。 

我们可以：

 1. 将每个单词转换为摩尔斯电码。 
2. 将变换插入到集合中。 
3. 返回集合的大小。 

由于集合会自动删除重复项，因此生成相同莫尔斯字符串的单词自然会折叠成单个条目。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × m) | O(n × m) | 转换单词并扫描列表中的重复项 |
 | 最佳 | O(n × m) | O(n × m) | 使用哈希集有效跟踪唯一的转换 |

 这里：

-`n`= 字数
 -`m`= 单词的平均长度

 由于每个单词的长度最多为`12`,`m`非常小，但最优解决方案仍然更干净且更具可扩展性。 

## 算法演练

 1. 为所有创建摩尔斯电码查找表`26`小写字母。 

我们按照以下顺序给出莫尔斯映射`'a'`到`'z'`。 由于字母是小写英文字符，我们可以使用字符索引来快速找到每个莫尔斯电码表示。 
2. 初始化一个空的哈希集。 

该集合的目的是仅自动存储不同的莫尔斯变换。 重复的转换不会创建额外的条目。 
3. 迭代中的每个单词`words`。 

对于每个单词，我们需要计算它的莫尔斯变换。 
4. 将单词转换为摩尔斯电码。 

对于每个字符：

 - 使用以下方法计算其字母索引：```
ord(character) - ord('a')
```- 从查找表中检索摩尔斯电码。 
- 将其附加到临时字符串。 
5. 将完成的莫尔斯变换添加到集合中。 

如果另一个单词已经产生了相同的转换，则该集合会自动忽略重复项。 
6. 处理完所有单词后，返回集合的大小。 

唯一转换的数量恰好是存储的唯一元素的数量。 

### 为什么它有效

 该算法之所以有效，是因为每个单词都被确定性地转换为一个摩尔斯电码字符串。 哈希集保持不变性，即它包含迄今为止遇到的每个唯一转换，没有重复项。 由于每个单词都被处理一次并且每个转换都插入到集合中，因此最终集合的大小必须等于不同莫尔斯电码转换的数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def uniqueMorseRepresentations(self, words: List[str]) -> int:
        morse_codes = [
            ".-", "-...", "-.-.", "-..", ".", "..-.", "--.", "....",
            "..", ".---", "-.-", ".-..", "--", "-.", "---", ".--.",
            "--.-", ".-.", "...", "-", "..-", "...-", ".--", "-..-",
            "-.--", "--.."
        ]

        unique_transformations = set()

        for word in words:
            morse_word = "".join(
                morse_codes[ord(char) - ord("a")]
                for char in word
            )
            unique_transformations.add(morse_word)

        return len(unique_transformations)
```该实现首先将所有小写英文字母的莫尔斯电码表示形式存储在列表中。 由于列表是按字母顺序排序的，因此我们可以使用字符的字母索引直接将字符映射到其莫尔斯电码。 

然后我们初始化一个名为`unique_transformations`。 该集负责自动消除重复项。 

对于输入中的每个单词，我们使用生成器表达式结合`"".join()`。 每个字符都转换为一个索引：```python
ord(char) - ord("a")
```这给出了之间的值`0`和`25`，对应字母`'a'`通过`'z'`。 

生成单词的莫尔斯电码字符串后，我们将其插入到集合中。 如果另一个单词产生相同的莫尔斯序列，则该集合仅保留一个副本。 

最后，我们使用以下命令返回集合中唯一条目的数量`len()`。 

## 解决方案```go
func uniqueMorseRepresentations(words []string) int {
	morseCodes := []string{
		".-", "-...", "-.-.", "-..", ".", "..-.", "--.", "....",
		"..", ".---", "-.-", ".-..", "--", "-.", "---", ".--.",
		"--.-", ".-.", "...", "-", "..-", "...-", ".--", "-..-",
		"-.--", "--..",
	}

	uniqueTransformations := make(map[string]bool)

	for _, word := range words {
		morseWord := ""

		for _, char := range word {
			index := char - 'a'
			morseWord += morseCodes[index]
		}

		uniqueTransformations[morseWord] = true
	}

	return len(uniqueTransformations)
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有内置的集合类型，我们使用`map[string]bool`。 

每个莫尔斯变换都用作映射中的密钥。 分配`true`只是将转换标记为当前。 

Go 特有的一个细节是字符处理。 迭代字符串`range`产生符文，所以我们使用以下方法计算字母表索引：```go
index := char - 'a'
```这可以安全地工作，因为问题保证小写英文字母。 

与 Python 不同，对于非常大的输入，循环内的 Go 字符串连接效率可能较低。 然而，由于每个字的长度有上限`12`，这个实现对于问题约束是完全可以接受的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n × m) | 每个单词中的每个字符都被处理一次 |

 ## 边缘情况

 一个重要的边缘情况是**单字输入**。 由于只有一种转换可能，因此答案必须始终是`1`。 粗心的实现可能会意外地错误处理初始化或返回`0`对于空结构，但我们的方法正确地将转换插入到集合中并返回其大小。 

另一个重要的案例涉及**多个相同的单词**，例如`["a", "a", "a"]`。 由于每个单词的变换都是相同的，所以预期的答案仍然是`1`。 这正是哈希集有用的地方，因为重复插入不会增加集合大小。 

当**不同的单词映射到相同的莫尔斯变换**时，会出现更微妙的边缘情况，例如`"gin"`和`"zen"`。 计算唯一单词而不是唯一莫尔斯字符串的简单实现在这里会失败。 我们的算法首先正确地转换单词，并且仅跟踪莫尔斯级别的唯一性。 

最后，问题包括**字母边界字符**，特别是`'a'`和`'z'`。 由于索引取决于减法`'a'`，可能存在相差一的错误。 我们的实现安全地计算索引`0`到`25`，与莫尔斯查找表完全一致。
