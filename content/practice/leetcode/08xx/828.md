[LeetCode 第 828 题](https://leetcode.com/problems/count-unique-characters-of-all-substrings-of-a-given-string/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、动态编程

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定字符串的每个可能子字符串中唯一字符的总数。 

如果某个字符在该子字符串中恰好出现一次，则该字符被认为在该子字符串中是唯一的。 例如，在子串中`"ABA"`， 仅有的`"B"`是独一无二的，因为`"A"`出现两次。 

我们得到一个字符串`s`仅由大写英文字母组成，我们必须考虑`s`。 对于每个子字符串，我们计算有多少个字符恰好出现一次，然后将所有这些计数加在一起。 

例如，如果`s = "ABC"`，子串是：

 -`"A"`→ 1 个独特角色
 -`"B"`→ 1 个独特角色
 -`"C"`→ 1 个独特角色
 -`"AB"`→ 2 个独特的角色
 -`"BC"`→ 2 个独特的角色
 -`"ABC"`→ 3 个独特的角色

 总计为`1 + 1 + 1 + 2 + 2 + 3 = 10`。 

字符串长度可以大到`10^5`，它立即告诉我们显式生成所有子字符串的成本太高。 一个长度的字符串`n`有`O(n^2)`子串，并且独立地检查每个子串将导致至少二次或三次复杂度。 

重要的挑战是避免重复重新计算重叠子字符串的字符频率。 

一些边缘情况很重要：

 - 包含所有相同字符的字符串，例如`"AAAA"`产生的独特角色很少。 
- 包含所有不同字符的字符串，例如`"ABCDE"`最大化唯一计数。 
- 字符多次出现且间隔不规则，很容易造成计数错误。 
- 非常大的输入需要接近线性时间的算法。 

该问题保证：

 - 字符串长度至少为 1。 
- 仅使用大写英文字母。 
- 最终答案适合 32 位整数。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个子字符串并计算其中有多少个字符是唯一的。 

对于每个起始索引`i`，我们将子字符串向右扩展一次一个字符。 我们维护当前子字符串内字符的频率图。 每次扩展后，我们都会计算当前有多少个字符的频率恰好为 1，并将其添加到答案中。 

这种方法是正确的，因为它完全按照问题陈述中的定义明确地评估每个子字符串。 

然而，对于限制而言，它太慢了。 有`O(n^2)`子字符串，并确定唯一字符的数量最多需要`O(26)`甚至`O(n)`取决于实施。 和`n = 10^5`，二次处理是不可行的。 

### 最佳方法

 关键的见解是扭转观点。 

而不是问：

 > 对于每个子字符串，它包含多少个唯一字符？ 

我们问：

 > 对于每个字符的每次出现，在多少个子字符串中该出现被视为唯一？ 

这个改造是核心优化。 

假设一个字符出现在索引处`i`。 这种情况会影响所有子字符串，其中：

 - 包括在内，
 - 不包括相同字符的其他出现。 

如果我们知道：

 - 先前出现的相同字符，
 - 下一次出现相同的字符，

 然后我们可以准确计算有多少子字符串将这次出现视为唯一。 

认为：

-`prev`是先前出现的索引，
 -`next`是下一个出现的索引。 

然后：

 - 子串的左边界可以选择`(prev + 1)`通过`i`,
 - 可以选择正确的边界`i`通过`(next - 1)`。 

因此，唯一计数该出现的子串的数量为：$$(i - prev) \times (next - i)$$我们计算每个字符出现的贡献并将它们全部相加。 

这完全避免了枚举子串并将复杂性降低到线性时间。

 ## 算法演练

 1. 创建一个数据结构来存储每个字符的所有出现索引。 

由于字符串仅包含大写英文字母，因此我们可以维护一个字典或数组，其中每个字符映射到它出现的索引列表。 
2. 添加哨兵边界以简化计算。 

对于每个字符的索引列表，在前面添加`-1`并附加`n`， 在哪里`n`是字符串长度。 

这些标记值表示字符串开始之前和结束之后的虚拟边界。 
3. 独立处理每个事件。 

对于位置处出现的字符`curr`， 让：

-`prev`是先前出现的索引，
 -`next`是下一个出现的索引。 
4. 计算有多少子字符串使用此出现作为唯一。 

左边界可以从以下任意位置开始：`prev + 1`和`curr`。 

剩余选择数：$$curr - prev$$右边界可能在以下任意位置结束`curr`和`next - 1`。 

正确选择数：$$next - curr$$5. 将两个计数相乘。 

每个有效的左侧选择都可以与每个有效的右侧选择配对。 

贡献：$$(curr - prev) \times (next - curr)$$6. 添加对全局答案的贡献。 
7. 对所有出现的字符重复此操作。 
8. 返回最终的累计金额。 

### 为什么它有效

 每个子字符串为其中出现一次的每个字符贡献一个计数。 

该算法不是遍历子字符串，而是计算唯一包含每个字符每次出现的子字符串的数量。 

每个子字符串字符唯一性关系都只计算一次，因为每个唯一出现都有一个由相邻相同字符确定的精确定义的有效范围。 

因此，总贡献额等于所需答案。 

## Python 解决方案```python
class Solution:
    def uniqueLetterString(self, s: str) -> int:
        positions = {}

        for index, char in enumerate(s):
            if char not in positions:
                positions[char] = []

            positions[char].append(index)

        total = 0
        n = len(s)

        for char_positions in positions.values():
            indices = [-1] + char_positions + [n]

            for i in range(1, len(indices) - 1):
                prev_index = indices[i - 1]
                current_index = indices[i]
                next_index = indices[i + 1]

                total += (
                    (current_index - prev_index)
                    * (next_index - current_index)
                )

        return total
```该实现首先记录每个字符出现的每个索引。 

例如，对于`"ABA"`:```python
{
    'A': [0, 2],
    'B': [1]
}
```接下来，对于每个字符列表，添加标记值。 这消除了对第一次和最后一次出现的特殊边缘处理。 

为了`"A"`:```python
[-1, 0, 2, 3]
```现在，每个实际发生的事件都有前一个和下一个边界。 

该循环使用以下方式独立计算每次出现的贡献：```python
(current_index - prev_index) * (next_index - current_index)
```最后，所有的贡献都累计到`total`。 

该算法从不显式生成子字符串，这就是为什么即使对于非常大的输入，它仍然保持高效。 

## 解决方案```go
func uniqueLetterString(s string) int {
    positions := make(map[byte][]int)

    for i := 0; i < len(s); i++ {
        positions[s[i]] = append(positions[s[i]], i)
    }

    total := 0
    n := len(s)

    for _, charPositions := range positions {
        indices := make([]int, 0, len(charPositions)+2)

        indices = append(indices, -1)

        for _, index := range charPositions {
            indices = append(indices, index)
        }

        indices = append(indices, n)

        for i := 1; i < len(indices)-1; i++ {
            prevIndex := indices[i-1]
            currentIndex := indices[i]
            nextIndex := indices[i+1]

            total += (currentIndex - prevIndex) *
                (nextIndex - currentIndex)
        }
    }

    return total
}
```Go 解决方案遵循与 Python 版本完全相同的逻辑。 

一个`map[byte][]int`存储每个字符的出现索引。 由于输入仅包含大写英文字母，因此使用`byte`是充足且高效的。 

切片用于构造包含哨兵值的增强索引数组。 

整数溢出不是问题，因为该问题保证最终答案适合 32 位整数，并且 Go 的`int`type 在现代系统上可以轻松处理这个范围。

 ## 边缘情况

 ### 单字符串

 像这样的字符串`"A"`是可能的最小输入。 

有缺陷的实现可能会错误地处理哨兵边界，或者当某个字符仅出现一次时会失败。 

此实现可以自然地处理它，因为增强索引列表变为：```
[-1, 0, 1]
```贡献公式仍然正确：```
(0 - (-1)) × (1 - 0) = 1
```### 所有字符都相同

 对于`"AAAAA"`，大多数子字符串都包含重复的字符，因此只有单字符子字符串有贡献。 

朴素的逻辑很容易过度计数，因为许多重叠的子字符串包含重复项。 

贡献方法完全避免了这种情况，因为每次出现仅在相邻相同字符所限定的范围内做出贡献。 

### 字符重复相隔很远

 考虑`"ABCA"`。 

第一个和最后一个`"A"`由几个字符分隔。 不正确的实现有时会计算包含两次出现的子字符串，即使该字符不再是唯一的。 

使用上一个和下一个出现边界可确保为出现次数计数的任何子字符串排除同一字符的所有其他副本。
