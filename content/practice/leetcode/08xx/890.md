[LeetCode 890 题](https://leetcode.com/problems/find-and-replace-pattern/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 # 问题理解

 该问题为我们提供了一个单词列表和一个目标模式字符串。 我们需要确定哪些单词遵循与模式完全相同的结构字符关系。 

如果模式中的字符与单词中的字符之间存在一对一的映射，则单词与模式匹配。 该映射必须是双射，这意味着：

 - 每个模式字符恰好映射到一个单词字符
 - 没有两个不同的模式字符映射到相同的单词字符

 实际的字母并不重要。 重要的是重复结构是否相同。 

例如，考虑以下模式`"abb"`:

 - 第一个角色`'a'`出现一次
 - 第二个和第三个角色都是`'b'`因此任何匹配的单词都必须具有：

 - 索引处有一个唯一字符`0`- 另一个字符在索引处重复`1`和`2`这个词`"mee"`匹配是因为：

 -`'a' -> 'm'`-`'b' -> 'e'`这保留了结构。 

这个词`"ccc"`不匹配，因为：

 -`'a' -> 'c'`-`'b' -> 'c'`现在，两个不同的模式字符映射到同一个单词字符，这违反了双射要求。 

输入约束很小：

 -`pattern.length <= 20`-`words.length <= 50`这告诉我们，即使是相对简单的检查解决方案也能在限制范围内顺利运行。 我们不需要先进的优化技术。 基于干净哈希图的解决方案是理想的。 

该问题还保证：

 - 每个单词的长度与模式相同
 - 所有字符均为小写英文字母

 这消除了匹配过程中长度验证的需要。 

一些重要的边缘情况包括：

 - 多个模式字符映射到同一单词字符
 - 单一模式字符映射不一致
 - 单字符图案
 - 包含所有重复字符的单词
 - 每个角色都是独一无二的模式

 在这些情况下，仅检查映射的一个方向的简单实现可能会失败。 

# 方法

 ## 蛮力方法

 暴力破解的想法是尝试为每个单词构建模式字符和单词字符之间的每种可能的映射。 

对于每个单词，我们逐个位置地比较字符并维护所有可能的替换。 在每一步中，我们都会验证当前映射是否保持一致。 

为了正确验证双射，我们必须检查：

 - 模式字符始终映射到相同的单词字符
 - 单词字符尚未分配给另一个模式字符

 这种方法已经可行，因为限制很小。 然而，如果不小心地使用重复搜索或重建映射来实现，它可能会变得不必要的低效。 

蛮力方法在概念上很简单，但它会做额外的工作，因为它会从头开始反复验证角色关系。 

## 最佳方法

 关键的见解是模式匹配完全取决于保留角色关系。 

我们可以通过维护两个哈希图来有效地验证这一点：

 -`pattern_to_word`-`word_to_pattern`当我们从左到右扫描字符时：

 - 如果映射已经存在，则它必须保持一致
 - 如果尚不存在映射，我们将创建它
 - 如果任一方向冲突，则该单词不匹配

 使用两个映射可以保证真正的双射。 

该解决方案非常高效，因为每个单词的每个字符都会被处理一次。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(W × N²) | O(N) | 通过额外检查反复验证映射 |
 | 最佳| O(宽×N) | O(N) | 使用两个哈希映射进行直接双射验证 |

 在哪里：

-`W`= 字数
 -`N`= 每个单词和模式的长度

 # 算法演练

 1. 初始化一个空的结果列表。 

该列表将存储成功匹配该模式的所有单词。 
2. 对于其中的每个单词`words`，检查是否与模式匹配。 

由于每个单词的长度与模式相同，因此我们可以直接逐个索引地比较字符。 
3. 创建两个哈希图。 

第一个地图存储：

 - 模式字符 -> 单词字符

 第二张地图存储：

 - 单词字符 -> 模式字符

 我们需要两个贴图，因为双射在两个方向上都起作用。 
4. 迭代每个字符位置。 

在索引处`i`：

- 让`p = pattern[i]`- 让`w = word[i]`5. 检查是否`p`已经有了映射。 

如果是这样的话：

 - 映射的字符必须等于`w`否则：

 - 创建新的映射`p -> w`6. 检查是否`w`已经有了反向映射。 

如果是这样的话：

 - 映射的模式字符必须等于`p`否则：

 - 创建一个新的反向映射`w -> p`7. 如果任一一致性检查失败，则停止处理该字。 

该单词无法与模式匹配。 
8. 如果整个单词处理成功，则将其追加到结果列表中。 
9. 处理完所有单词后返回结果列表。 

## 为什么它有效

 该算法在整个扫描过程中保持模式字符和单词字符之间严格的一对一对应关系。 

在每个位置：

 - 一个模式字符只能映射到一个单词字符
 - 一个单词字符只能映射到一个模式字符

 由于两个方向同时验证，因此保证映射是双射的。 因此，任何接受的单词都保留了精确的结构模式关系。 

# Python 解决方案```python
from typing import List

class Solution:
    def findAndReplacePattern(self, words: List[str], pattern: str) -> List[str]:
        def matches(word: str) -> bool:
            pattern_to_word = {}
            word_to_pattern = {}

            for p_char, w_char in zip(pattern, word):
                if p_char in pattern_to_word:
                    if pattern_to_word[p_char] != w_char:
                        return False
                else:
                    pattern_to_word[p_char] = w_char

                if w_char in word_to_pattern:
                    if word_to_pattern[w_char] != p_char:
                        return False
                else:
                    word_to_pattern[w_char] = p_char

            return True

        result = []

        for word in words:
            if matches(word):
                result.append(word)

        return result
```该解决方案定义了一个辅助函数`matches()`确定单个单词是否遵循与模式相同的结构。 

在这个助手里面：

 -`pattern_to_word`跟踪从模式字符到单词字符的映射
 -`word_to_pattern`跟踪反向映射

 该算法使用以下方式迭代相应的字符`zip(pattern, word)`。 

对于每对：

 - 如果映射已经存在，则必须保持一致
 - 否则，创建映射

 反方向也用同样的方法检查。 

如果出现任何不一致，函数立即返回`False`。 

如果整个单词的处理没有冲突，则该单词与模式匹配并返回`True`。 

主函数只是将此验证应用于每个单词并收集有效的匹配项。 

# Go Solution```go
func findAndReplacePattern(words []string, pattern string) []string {
    matches := func(word string) bool {
        patternToWord := make(map[byte]byte)
        wordToPattern := make(map[byte]byte)

        for i := 0; i < len(pattern); i++ {
            pChar := pattern[i]
            wChar := word[i]

            if mappedChar, exists := patternToWord[pChar]; exists {
                if mappedChar != wChar {
                    return false
                }
            } else {
                patternToWord[pChar] = wChar
            }

            if mappedChar, exists := wordToPattern[wChar]; exists {
                if mappedChar != pChar {
                    return false
                }
            } else {
                wordToPattern[wChar] = pChar
            }
        }

        return true
    }

    result := []string{}

    for _, word := range words {
        if matches(word) {
            result = append(result, word)
        }
    }

    return result
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

A few Go specific details are worth noting:

 - Go 字符串以字节为索引，因为输入仅包含小写英文字母
 -`map[byte]byte`用于字符映射
 - 辅助函数作为内联闭包实现
 - 结果切片开始为空并使用`append`由于该问题仅使用 ASCII 小写字母，因此字节索引是完全安全且高效的。

 # 边缘情况

 ## 多个模式字符映射到同一单词字符

 一个常见的错误是仅检查模式字符映射是否一致，而忽略两个不同的模式字符是否映射到同一单词字符。 

例如：```
pattern = "abb"
word = "ccc"
```单向地图会错误地允许：```
a -> c
b -> c
```这违反了双射规则，因为两个模式字符映射到同一个字符。 

该实现通过维护反向映射来避免此错误`word_to_pattern`。 

## 一种模式字符映射不一致

 当模式字符映射到单词中后面的不同字符时，会出现另一个重要的边缘情况。 

例子：```
pattern = "abb"
word = "abc"
```最初：```
b -> b
```之后：```
b -> c
```这破坏了一致性。 

该实现在分配新映射之前会检查现有映射，因此会立即检测到不一致的情况。 

## 单字符输入

 当图案长度为`1`，每个单个字符单词都应该匹配。 

例子：```
pattern = "a"
words = ["x", "y", "z"]
```因为只涉及一个字符，所以始终存在有效的一对一映射。 

该实现自然地处理了这个问题，因为循环只处理一个字符对并创建一个没有冲突的有效映射。
