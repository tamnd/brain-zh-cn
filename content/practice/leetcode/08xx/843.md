 # LeetCode 843 - 猜单词

 ## 问题理解

 这是一个交互式问题，我们必须从给定的候选单词列表中识别出隐藏的六个字母单词。 我们不可以直接检查密语。 相反，我们可以与提供的进行交互`Master`通过调用API`master.guess(word)`。 

每次调用都会返回我们猜测的单词和秘密单词之间的值和位置完全匹配的字符数。 例如，如果秘密是`"acckzz"`我们猜测`"abcczz"`，返回值为`4`因为四个位置包含相同的字符。 

重要的细节是猜测的单词必须来自提供的单词`words`列表。 如果我们猜测列表之外的内容，API 将返回`-1`。 

目标是在有限的猜测次数内发现秘密单词。 该问题保证了合理的策略总能在允许的猜测次数内成功。 

输入包括：

 -`words`，唯一的六字符字符串列表
 -`master`、交互式API
 - 一个隐藏的`secret`保证存在于的单词`words`该函数本身不返回任何内容。 相反，成功取决于我们的猜测之一是否完全等于允许调用次数内的秘密单词。 

限制相对较小：

 - 最多100字
 - 每个单词的长度为 6
 - 最多允许 30 次猜测

 这些限制很重要，因为它们表明我们可以进行单词之间的成对比较。 由于字长固定为6，列表大小最多为100，即使是`O(n^2)`预处理策略是完全实用的。 

一些边缘情况很重要：

 - 候选列表只能包含一个单词
 - 许多单词可能极其相似
 - 糟糕的猜测策略可能会淘汰极少数候选人并超出猜测限制
 - 我们绝不能猜测所提供列表之外的单词
 - 秘密保证存在，因此根据匹配计数过滤候选者始终有效

 ## 方法

 ### 蛮力方法

 幼稚的策略会以任意顺序重复猜测单词，例如总是选择第一个剩余的候选者。 

每次猜测后，我们都会收到匹配计数。 然后，我们过滤剩余的候选列表，仅保留相对于猜测的单词产生相同匹配计数的单词。 

这种方法是正确的，因为秘密必须与迄今为止收到的所有反馈一致。 任何与之前的匹配计数不一致的单词都不可能是秘密。 

然而，这种策略在实践中表现不佳，因为猜测的单词可能提供的信息很少。 如果所选的猜测不能代表剩余的候选者，则候选者池会缓慢缩小。 在最坏的情况下，我们可能会超出允许的猜测次数。 

### 最佳方法

 关键的见解是每次猜测都应该最大化信息增益。 

假设我们猜测一个与许多其他候选词非常相似的词。 如果返回的匹配计数没有提供信息，我们可能仍然会留下一个很大的候选集。 

相反，我们希望选择一个尽可能均匀地划分剩余候选者的猜测。 

一种常见且有效的策略是极小极大方法：

 - 对于每个可能的猜测，计算每个可能的匹配计数剩余多少候选词
 - 最坏情况下的剩余组大小代表该猜测的最坏结果
 - 选择最坏情况组尽可能小的猜测

 该策略积极减少不确定性并可靠地收敛于猜测限制内。 

由于约束很小，我们可以对所有单词进行成对比较。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(G × n²) | O(G × n²) | O(n) | 随意猜测可能会慢慢淘汰候选人 |
 | 最佳| O(G × n²) | O(G × n²) | O(n²) | 使用极小极大式候选缩减 |

 这里：

-`n`是单词数
 -`G`是猜测的数量
 - 每次比较仅需花费`O(6)`因为单词有固定长度

 ## 算法演练

 ### 第 1 步：定义匹配计数辅助函数

 我们需要一个函数来比较两个六个字母的单词并返回有多少个位置包含相同的字符。 

例如：

-`"acckzz"`与`"abcczz"`回报`4`此功能很重要，因为所有过滤决策都取决于精确的位置匹配。 

### 第 2 步：维护候选列表

 最初，每一个字`words`可能是秘密。 

我们将当前所有可能性存储在一个名为的列表中`candidates`。 

### 第 3 步：选择下一个最佳猜测

 对于当前候选列表中的每个单词：

 1. 将其与其他所有候选者进行比较
 2. 按匹配次数对候选人进行分组
 3. 跟踪最大组的大小

 如果我们选择该词，最大的组代表剩余候选者的最坏情况数量。 

我们选择最坏情况组规模最小的单词。 

这就是极小极大原则，最小化最坏的可能结果。 

### 第四步：猜测

 致电：```
matches = master.guess(best_word)
```如果结果是`6`，我们发现了密语，可以立即停止。 

### 第 5 步：筛选候选人

 只有与反馈一致的词语才可能存在。 

如果满足以下条件，候选人将幸存：```
match(candidate, guessed_word) == matches
```所有不一致的单词都会被丢弃。 

### 第 6 步：重复

 继续选择最佳猜测并缩小候选集，直到找到秘密。 

### 为什么它有效

 在每一步中，候选列表都包含与之前所有反馈一致的单词。 

极小极大选择策略保证每次猜测在最坏情况下尽可能减少不确定性。 由于候选集不断缩小，并且保证秘密存在于原始列表中，因此算法最终隔离出正确的单词。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

# """
# This is Master's API interface.
# You should not implement it, or speculate about its implementation
# """
# class Master:
#     def guess(self, word: str) -> int:

class Solution:
    def findSecretWord(self, words: List[str], master: 'Master') -> None:
        
        def match_count(word1: str, word2: str) -> int:
            matches = 0
            for i in range(6):
                if word1[i] == word2[i]:
                    matches += 1
            return matches
        
        candidates = words[:]
        
        while candidates:
            best_word = None
            best_score = float('inf')
            
            # Choose the word with the smallest worst-case partition
            for word in candidates:
                groups = defaultdict(int)
                
                for other in candidates:
                    if word != other:
                        matches = match_count(word, other)
                        groups[matches] += 1
                
                worst_group = max(groups.values(), default=0)
                
                if worst_group < best_score:
                    best_score = worst_group
                    best_word = word
            
            matches = master.guess(best_word)
            
            if matches == 6:
                return
            
            next_candidates = []
            
            for word in candidates:
                if match_count(word, best_word) == matches:
                    next_candidates.append(word)
            
            candidates = next_candidates
```实施开始于`match_count`辅助功能。 由于每个单词的长度固定为 6，因此我们只需逐个位置比较字符并计算相等的位置即可。 

这`candidates`列表跟踪与之前的猜测仍然一致的所有单词。 

对于每次迭代，我们使用极小极大策略搜索最佳的下一个猜测。 我们通过根据匹配计数对剩余候选词进行分组来模拟猜测每个候选词的效果。 最大的组代表了猜测后最坏的情况。 

我们选择最坏情况组规模最小的词，因为它可以最大程度地保证减少不确定性。 

打电话后`master.guess`，如果匹配数为 6，我们立即停止。 

否则，我们通过仅保留与返回的反馈一致的单词来重建候选列表。 

这个过程不断重复，直到发现秘密。 

## 解决方案```go
package main

import "math"

/**
 * // This is the Master's API interface.
 * // You should not implement it, or speculate about its implementation
 * type Master struct {
 * }
 *
 * func (this *Master) Guess(word string) int {}
 */

func matchCount(word1 string, word2 string) int {
	count := 0

	for i := 0; i < 6; i++ {
		if word1[i] == word2[i] {
			count++
		}
	}

	return count
}

func findSecretWord(words []string, master *Master) {
	candidates := make([]string, len(words))
	copy(candidates, words)

	for len(candidates) > 0 {
		bestWord := ""
		bestScore := math.MaxInt32

		// Choose word with minimum worst-case partition size
		for _, word := range candidates {
			groups := make(map[int]int)

			for _, other := range candidates {
				if word != other {
					matches := matchCount(word, other)
					groups[matches]++
				}
			}

			worstGroup := 0

			for _, size := range groups {
				if size > worstGroup {
					worstGroup = size
				}
			}

			if worstGroup < bestScore {
				bestScore = worstGroup
				bestWord = word
			}
		}

		matches := master.Guess(bestWord)

		if matches == 6 {
			return
		}

		nextCandidates := []string{}

		for _, word := range candidates {
			if matchCount(word, bestWord) == matches {
				nextCandidates = append(nextCandidates, word)
			}
		}

		candidates = nextCandidates
	}
}
```Go 的实现与 Python 解决方案非常相似。 

主要差异来自语言语法和容器管理：

 - Go 使用切片而不是 Python 列表
 - 我们使用一个`map[int]int`计算分区大小
 -`math.MaxInt32`初始化最佳极小极大分数
 - 切片重建是显式使用的`append`不存在整数溢出问题，因为所有计数仍然很小。

 ## 边缘情况

 ### 只有一个候选词

 如果输入恰好包含一个单词，算法应该立即猜测它。 有错误的实现可能会尝试不必要的分区逻辑，或者由于比较组为空而失败。 

此实现可以自然地处理这种情况，因为单个单词成为最佳候选并立即被猜测。 

### 极其相似的词

 许多单词可能只有一两个位置不同。 在这种情况下，糟糕的猜测策略会消除很少的候选者，并且可能会超出猜测限制。 

极小极大划分策略通过选择最小化最大剩余模糊组的猜测来专门解决这个问题。 

### 匹配计数为零

 猜测可能与秘密词不共享匹配位置。 不正确的过滤逻辑可能会意外保留不一致的候选人。 

该实现正确地仅保留计算出的匹配计数完全等于 API 响应的单词，包括零。 这保证了每次猜测后的一致性。
