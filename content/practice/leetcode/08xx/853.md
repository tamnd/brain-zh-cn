[LeetCode 853 题](https://leetcode.com/problems/car-fleet/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、排序、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题描述了一组驶向同一目的地的汽车，用整数表示`target`。 每辆车都从一个独特的位置开始并以恒定的速度移动。 汽车不能互相超越。 如果一辆较快的汽车追上了前面较慢的汽车，则较快的汽车必须减速并与较慢的汽车一起继续行驶。 一旦发生这种情况，他们就会组成一个车队。 

任务是确定有多少不同的舰队最终将到达目标。 

输入包括：

 -`target`，道路上的目的地位置。 
-`position[i]`, 的起始位置`i-th`车。 
-`speed[i]`，速度`i-th`车。 

输出是一个整数，表示到达目标的车队数量。 

一个关键细节是，如果两辆车恰好在目标位置相遇，它们仍然被视为同一车队的一部分。 这会影响确定汽车是否并道时的比较。 

这些约束很重要，因为它们排除了低效的模拟：

 - 最多`10^5`汽车可以存在。 
- 位置和速度都可以很大。 
- 所有职位都是独一无二的。 

自从`n`可能非常大，任何解决方案都比粗略地更糟糕`O(n log n)`可能会超时。 这立即表明随着时间的推移反复模拟运动是不切实际的。 

一些边缘情况很重要：

 - 一辆汽车应该始终只生产一个车队。 
- 已经通过增加到达时间订购的汽车永远不会合并。 
- 多辆汽车可以合并成一个大型车队。 
- 一辆较快的汽车落后于较慢的汽车可能会在目的地准确地赶上它，并且这仍然算作一个车队。 
- 因为位置是独特的，所以我们永远不需要处理起始位置的平局。 

## 方法

 ### 蛮力方法

 一个简单的想法是模拟汽车随着时间的推移向目标移动。 每时每刻，我们都可以检查一辆​​车是否追上了另一辆车，并将它们动态地合并到车队中。 

这种方法在概念上是正确的，因为它直接对问题定义进行建模。 然而，它变得极其低效。 汽车不断移动，要准确确定碰撞何时发生，需要在汽车之间进行反复比较，并在并道后重新计算。 

另一种暴力变体是比较每一对汽车，并确定其中一辆是否在目标之前赶上另一辆。 这需要考虑传递性的相互作用，因为早期形成的车队会影响后来的汽车。 

在最坏的情况下，这些方法需要`O(n^2)`比较或复杂的模拟，这对于`n = 10^5`。 

### 最佳方法

 关键的见解是我们实际上不需要模拟运动。 

对于每辆车，我们可以计算到达目标所需的时间：$$\text{time} = \frac{target - position}{speed}$$现在考虑从距离目标最近到最远的顺序排列的汽车。 

如果后面的汽车到达目的地的时间少于或等于前面的汽车，它最终必须在目标之前或正好赶上目标。 因此，他们组成了同一支舰队。 

如果后面的汽车需要更长的时间，它永远无法赶上前面的车队，因此它会形成一个新的车队。 

这一观察结果使我们能够以相反的位置顺序处理汽车，同时跟踪迄今为止看到的最大到达时间。 该模式的行为类似于单调堆栈，因为当我们向后移动时，车队时间不会减少。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) 或 O(n) | 模拟交互或比较所有对 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 按位置排序，贪婪地处理到达时间 |

 ## 算法演练

 1. 将每辆车的位置与其速度配对。 

我们需要根据汽车在道路上的位置来处理它们。 由于位置是唯一的，排序给出了明确的驱动顺序。 
2. 按位置升序对汽车进行排序。 

排序后，距离目标最近的汽车出现在最后。 这种顺序允许我们在反向迭代时从前到后处理汽车。 
3. 从右到左遍历汽车。 

我们从距离目标最近的汽车开始，因为没有汽车可以从前方影响它。 
4. 计算当前车的到达时间。 

公式为：$t = \frac{target - position}{speed}$这表示如果汽车不减速，则需要多长时间才能到达目的地。 
5. 将当前到达时间与最晚车队到达时间进行比较。 

- 如果当前车辆的时间较长，则无法赶上前面的车队。 因此，它组成了一支新的舰队。 
- 如果当前汽车的时间小于或等于前面车队的时间，则它会合并到该车队中。 
6. 保持迄今为止遇到的最大到达时间。 

该值代表最近车队的到达时间。 
7. 计算形成了多少个不同的舰队。 

每当我们遇到更长的到达时间时，我们就会增加车队数量。 

### 为什么它有效

 从最近到最远的处理是关键的想法。 前方的每支舰队都像一个移动的屏障。 后面的汽车只能要么并入该车队，要么保持独立。 

如果后面的车比前面的车队更早到达目标，它必须在到达之前赶上。 由于不可能超车，后面的车会并入该车队并继承其较慢的到达时间。 

因此，当向后扫描已排序的车辆时，车队到达时间的序列是单调递增的。 计算到达时间增加了多少倍就可以得出确切的车队数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def carFleet(self, target: int, position: List[int], speed: List[int]) -> int:
        cars = sorted(zip(position, speed))

        fleets = 0
        latest_time = 0.0

        for pos, spd in reversed(cars):
            arrival_time = (target - pos) / spd

            if arrival_time > latest_time:
                fleets += 1
                latest_time = arrival_time

        return fleets
```实现首先使用将位置和速度组合成对`zip`。 按位置对这些对进行排序可以得出汽车的道路顺序。 

该循环反向迭代，因为我们想要从距离目标最近到最远的位置处理汽车。 对于每辆车，代码计算到达目标所需的时间。 

变量`latest_time`存储当前前方车队的到达时间。 如果当前车辆晚于该车队到达，则它无法赶上，必须组成一个新车队。 否则，它将合并到现有舰队中。 

变量`fleets`计算存在多少个不同的舰队。 

## 解决方案```go
package main

import (
	"sort"
)

func carFleet(target int, position []int, speed []int) int {
	type Car struct {
		position int
		speed    int
	}

	n := len(position)
	cars := make([]Car, n)

	for i := 0; i < n; i++ {
		cars[i] = Car{
			position: position[i],
			speed:    speed[i],
		}
	}

	sort.Slice(cars, func(i, j int) bool {
		return cars[i].position < cars[j].position
	})

	fleets := 0
	latestTime := 0.0

	for i := n - 1; i >= 0; i-- {
		arrivalTime := float64(target-cars[i].position) / float64(cars[i].speed)

		if arrivalTime > latestTime {
			fleets++
			latestTime = arrivalTime
		}
	}

	return fleets
}
```Go 实现遵循与 Python 版本相同的逻辑。 定制`Car`struct 将每辆车的位置和速度存储在一起。 

汽车按以下方式分类`sort.Slice`。 由于 Go 默认执行整数除法，因此代码显式地将值转换为`float64`在计算到达时间之前。 

不需要对 nil 切片进行特殊处理，因为该问题保证了长度相等的有效输入数组。

 ## 边缘情况

 当一辆车恰好在目的地赶上另一辆车时，就会出现一个重要的边缘情况。 一个幼稚的实现可能要求后面的车严格提前到达才能并道。 然而，问题明确指出，在目标处相遇仍会形成一支舰队。 该实现可以正确处理此问题，因为只要汽车的到达时间小于或等于前方车队的时间，它们就会合并。 

另一个微妙的情况涉及相同的速度。 如果两辆车以相同的速度行驶并在不同的位置出发，后车永远追不上前车。 如果仅比较速度，有缺陷的解决方案可能会错误地合并它们。 此实现通过比较到达时间而不是原始速度来完全避免该问题。 

第三个重要的案例是级联合并。 一辆汽车可能会合并到一个车队中，该车队本身是由早期合并形成的。 例如，汽车 A 并入汽车 B，然后汽车 C 并入最终车队。 错误地模拟这一点可能会很复杂，但单调到达时间方法可以自然地处理它。 一旦车队形成，其有效到达时间就固定下来，所有后来的车辆都会与该车队时间进行比较。 

另一个边缘情况是已经排序或反向排序的输入。 由于该算法在处理之前显式对汽车进行排序，因此它不依赖于任何初始排序，并且对于所有有效输入都保持正确。
