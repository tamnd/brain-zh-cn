[LeetCode 882 题](https://leetcode.com/problems/reachable-nodes-in-subdivided-graph/)

 **难度：** 🔴难
 **主题：** 图论、堆（优先级队列）、最短路径

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个无向图`n`原始节点。 每条边都有一个关联的细分计数，这意味着该边被中间节点链替换。 

对于边缘`[u, v, cnt]`，原来的直接连接`u`和`v`不再作为单一边缘存在。 相反，边缘变为：```
u -> x1 -> x2 -> ... -> xcnt -> v
```此转换插入`cnt`之间的新节点`u`和`v`，原始端点之间的总路径长度变为`cnt + 1`。 

我们从节点开始`0`并且最多可以移动`maxMoves`步骤。 目标是计算完全细分的图中有多少个节点是可到达的。 

一个重要的细节是细分的节点没有明确出现在输入中。 该图仅存储原始节点和细分计数。 物理上构建每个细分节点的简单实现可能会变得巨大，因为：

 -`n`可以达到`3000`-`edges.length`可以达到`10000`-`cnti`可以达到`10000`在最坏的情况下，细分节点的数量可能达到数千万，这对于直接构建来说太大了。 

关键的观察是遍历一条边`cnt`细分成本`cnt + 1`从一个原始节点移动到另一个原始节点。 这将问题转化为原始图上的最短路径问题。 

输出必须包括：

 - 所有可达的原始节点
 - 沿每条边的所有可到达的细分节点

 这些约束强烈表明我们需要一种高效的最短路径算法，特别是带有优先级队列的 Dijkstra 算法。 

一些边缘情况很重要：

 - 节点`0`可能与图表断开连接
 -`maxMoves`或许`0`- 某些边缘可能有`cnt = 0`- 细分边缘可以从一侧部分可达，从另一侧部分可达
 - 当两个端点都可以到达同一条边时，我们必须避免重复计算细分节点

 ## 方法

 ### 蛮力方法

 蛮力解决方案显式地构建了完全细分的图。 

对于每一个边缘`[u, v, cnt]`，我们创造`cnt`中间节点并将它们连接成一条链。 构建扩展图后，我们从节点运行标准 BFS 或 Dijkstra 遍历`0`计算所有可到达的节点。 

这种方法是正确的，因为它直接对问题陈述中描述的图进行建模。 展开图中的每一步都与问题定义中的一步完全对应。 

然而，这种方法对于给定的约束是不可行的。 如果每条边都包含许多细分，则展开后的图就会变得巨大。 高达`10000`边，并且每条边最多包含`10000`新节点，该图可能包含数千万个节点和边。 

内存使用和运行时间都变得不可接受。 

### 最佳方法

 关键的见解是我们实际上不需要构建细分的节点。 

假设一条边有`cnt`细分节点。 从一个端点移动到另一个端点需要精确`cnt + 1`移动。 因此，我们可以将原始图视为加权图，其中：```
weight(u, v) = cnt + 1
```现在我们从节点运行 Dijkstra 算法`0`计算到每个原始节点的最短距离。 

一旦我们知道最短距离：

 - 每个原始节点都有距离`<= maxMoves`可达
 - 对于每条边，我们确定从每个端点可以到达多少个细分节点

 如果：```
remainingFromU = max(0, maxMoves - dist[u])
remainingFromV = max(0, maxMoves - dist[v])
```那么：

 - 我们最多可以进入`remainingFromU`从侧面细分节点`u`- 我们最多可以进入`remainingFromV`从侧面细分节点`v`但边缘只包含`cnt`细分节点总数，因此可达的细分节点为：```
min(cnt, remainingFromU + remainingFromV)
```这可以避免重复计算。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(V' + E') | O(V' + E') | O(V' + E') | O(V' + E') | 显式构建细分图 |

 这里，`V'`和`E'`表示展开图的大小，它可以变得非常大。 

## 算法演练

 1. 为原始图构建邻接表。 

每条边`[u, v, cnt]`变成：```
u -> (v, cnt + 1)
v -> (u, cnt + 1)
```我们使用`cnt + 1`因为遍历所有细分节点加上最终端点需要花费很多移动。 
2.从节点开始运行Dijkstra算法`0`。 

我们维持：

 - 最小堆存储`(distance, node)`- 初始化为无穷大的距离数组
 -`dist[0] = 0`Dijkstra 是合适的，因为所有边权重都是正的。 
3. 以最短距离递增的顺序处理节点。 

对于每个弹出的节点：

 - 如果我们已经找到了更短的路径，请跳过它
 - 否则，松弛所有相邻边缘

 如果：```
newDist = currentDist + weight
```和`newDist < dist[neighbor]`，更新距离并将邻居推入堆中。 
4. 统计可达的原始节点。 

每个节点具有：```
dist[node] <= maxMoves
```贡献一个可达节点。 
5. 统计每条边上可达的细分节点。 

对于边缘`[u, v, cnt]`:```
reachableFromU = max(0, maxMoves - dist[u])
reachableFromV = max(0, maxMoves - dist[v])
```总的可达细分节点为：```
min(cnt, reachableFromU + reachableFromV)
```当两侧都到达同一边缘时，这可以正确处理重叠。 
6. 返回总计数。 

### 为什么它有效

 Dijkstra保证距节点的最短路径距离`0`到每个原始节点，因为所有边权重都是正的。 

如果我们可以从任一端点进入细分节点的边缘足够远，则可以到达细分节点。 公式：```
min(cnt, reachableFromU + reachableFromV)
```精确计算该边上可到达的唯一细分节点的数量。 由于每条边都是独立处理的，并且原始节点是单独计数的，所以最终的答案是正确的。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def reachableNodes(self, edges: List[List[int]], maxMoves: int, n: int) -> int:
        graph = [[] for _ in range(n)]

        for u, v, cnt in edges:
            weight = cnt + 1
            graph[u].append((v, weight))
            graph[v].append((u, weight))

        INF = float("inf")
        dist = [INF] * n
        dist[0] = 0

        min_heap = [(0, 0)]

        while min_heap:
            current_dist, node = heapq.heappop(min_heap)

            if current_dist > dist[node]:
                continue

            for neighbor, weight in graph[node]:
                new_dist = current_dist + weight

                if new_dist < dist[neighbor]:
                    dist[neighbor] = new_dist
                    heapq.heappush(min_heap, (new_dist, neighbor))

        reachable_count = 0

        # Count reachable original nodes
        for d in dist:
            if d <= maxMoves:
                reachable_count += 1

        # Count reachable subdivided nodes
        for u, v, cnt in edges:
            reachable_from_u = max(0, maxMoves - dist[u])
            reachable_from_v = max(0, maxMoves - dist[v])

            reachable_count += min(
                cnt,
                reachable_from_u + reachable_from_v
            )

        return reachable_count
```该实现首先构建一个邻接列表，其中每个边的权重是`cnt + 1`。 这对两个原始端点之间所有细分节点的遍历成本进行建模。 

这`dist`数组存储距节点的最短已知距离`0`到每个原始节点。 Dijkstra 算法使用最小堆以距离递增的顺序处理节点。 

过时条目检查：```python
if current_dist > dist[node]:
    continue
```当已经发现更好的路径时，可以防止不必要的处理。 

计算出最短路径后，算法会计算在该时间内可到达的所有原始节点`maxMoves`。 

对边的第二次遍历计算每条边上可到达的细分节点数量。 由于移动可能从两个端点发生，因此该算法将可到达的部分添加在一起，但将结果限制为`cnt`以避免重复计算。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

type Pair struct {
	node int
	dist int
}

type MinHeap []Pair

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].dist < h[j].dist
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(Pair))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func reachableNodes(edges [][]int, maxMoves int, n int) int {
	graph := make([][][2]int, n)

	for _, edge := range edges {
		u, v, cnt := edge[0], edge[1], edge[2]
		weight := cnt + 1

		graph[u] = append(graph[u], [2]int{v, weight})
		graph[v] = append(graph[v], [2]int{u, weight})
	}

	dist := make([]int, n)

	for i := 0; i < n; i++ {
		dist[i] = math.MaxInt
	}

	dist[0] = 0

	minHeap := &MinHeap{}
	heap.Init(minHeap)
	heap.Push(minHeap, Pair{node: 0, dist: 0})

	for minHeap.Len() > 0 {
		current := heap.Pop(minHeap).(Pair)

		if current.dist > dist[current.node] {
			continue
		}

		for _, neighbor := range graph[current.node] {
			nextNode := neighbor[0]
			weight := neighbor[1]

			newDist := current.dist + weight

			if newDist < dist[nextNode] {
				dist[nextNode] = newDist
				heap.Push(minHeap, Pair{
					node: nextNode,
					dist: newDist,
				})
			}
		}
	}

	reachableCount := 0

	for _, d := range dist {
		if d <= maxMoves {
			reachableCount++
		}
	}

	for _, edge := range edges {
		u, v, cnt := edge[0], edge[1], edge[2]

		reachableFromU := 0
		reachableFromV := 0

		if dist[u] <= maxMoves {
			reachableFromU = maxMoves - dist[u]
		}

		if dist[v] <= maxMoves {
			reachableFromV = maxMoves - dist[v]
		}

		reachableCount += min(
			cnt,
			reachableFromU+reachableFromV,
		)
	}

	return reachableCount
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的逻辑，但需要使用显式堆实现`container/heap`包裹。 

邻接表使用固定大小数组的切片：```go
[][2]int
```每个条目存储的位置：```go
[neighbor, weight]
```Go 不提供内置的整数无穷大值，因此实现使用以下方式初始化距离`math.MaxInt`。 

堆存储自定义`Pair`包含节点及其当前最短距离的结构。

from typing import List

class Solution:
    def reachableNodes(self, edges: List[List[int]], maxMoves: int, n: int) -> int:
        import heapq

        graph = [[] for _ in range(n)]

        for u, v, cnt in edges:
            graph[u].append((v, cnt + 1))
            graph[v].append((u, cnt + 1))

        INF = float("inf")
        dist = [INF] * n
        dist[0] = 0

        heap = [(0, 0)]

        while heap:
            d, node = heapq.heappop(heap)

            if d > dist[node]:
                continue

            for nei, weight in graph[node]:
                nd = d + weight

                if nd < dist[nei]:
                    dist[nei] = nd
                    heapq.heappush(heap, (nd, nei))

        ans = sum(d <= maxMoves for d in dist)

        for u, v, cnt in edges:
            ans += min(
                cnt,
                max(0, maxMoves - dist[u]) +
                max(0, maxMoves - dist[v])
            )

        return ans

 ## 边缘情况

 当节点`0`与图表的其余部分断开连接。 在这种情况下，Dijkstra 永远不会到达任何其他节点，并且除了节点之外的所有距离都保持无穷大`0`。 有缺陷的实现可能会意外地计算不可到达边缘上的细分节点，但此实现可以正确计算零个可到达细分，因为：```
max(0, maxMoves - dist[u])
```变为零时`dist[u]`是无穷大。 

另一个重要的边缘情况发生在`maxMoves = 0`。 在这种情况下，我们根本无法遍历任何边。 唯一节点`0`应该算。 该实现自然地处理了这个问题，因为没有相邻节点可以满足距离约束，并且每个可达细分计算的计算结果为零。 

微妙的边缘情况涉及从边缘两端的重叠遍历。 假设一条边包含`5`细分节点，两个端点都可以到达`4`节点进入边缘。 幼稚的实现可能会错误地计数`8`细分节点。 公式：```
min(cnt, reachableFromU + reachableFromV)
```通过将可到达的细分节点总数限制为边缘上的实际细分数来防止重复计算。 

另一个重要的场景是当`cnt = 0`。 在这种情况下，边的行为类似于具有权重的普通图边`1`。 实现正确地对此进行建模：```
weight = cnt + 1
```这变成`1`。 没有将细分节点添加到答案中，因为：```
min(0, anything) = 0
```
