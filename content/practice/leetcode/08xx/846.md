[LeetCode 第 846 题](https://leetcode.com/problems/hand-of-straights/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪心、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们确定是否可以将给定的卡片集合重新排列成连续数字组，每个数字的大小`groupSize`。 每张卡由数组中的一个整数表示`hand`，Alice 想要分组，使得每个组中的卡号是连续的，并且每组中的卡总数等于`groupSize`。 该函数应该返回`true`如果这样的重新安排是可能的，并且`false`否则。 

这些约束告诉我们几个关键点。 长度为`hand`可以达到 10,000，这使得$O(n^2)$接近可能太慢。 卡面值可以大到$10^9$，所以我们不能依赖数组索引来直接表示值，而是需要像哈希图这样的数据结构来计算出现次数。 最后，`groupSize`可以小到 1 或等于手的长度，这意味着我们需要处理最小和最大组场景。 

重要的边缘情况包括：`groupSize`未划分卡片总数、相同卡片值的多个重复以及未排序的输入。 在这些情况下，简单地查找连续序列而不计算重复项的简单实现将失败。 

## 方法

 暴力方法会反复尝试通过挑选剩余的最小卡片并检查连续的卡片来形成组，直到使用所有卡片或无法形成组为止。 这在逻辑上是有效的，因为它强制执行连续条件，但效率低下。 每次我们扫描剩余的卡片以检查连续值时，复杂性就会变成$O(n^2)$，这对于最大输入大小来说太慢了。 

最佳解决方案的关键见解是，计算卡片出现次数并始终从最小的卡片开始，确保我们永远不会“锁定”可能属于有效序列一部分的卡片。 使用哈希图来跟踪频率并按排序顺序迭代卡片使我们能够有效地贪婪地形成序列。 通过减少连续序列中每张卡片的计数，我们确保同一张卡片不会被不当重复使用，任何剩余的计数都表明不可能进行分组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 通过扫描剩余的卡片来重复搜索连续序列 |

 ## 算法演练

 1. 统计每张牌出现的次数`hand`使用哈希映射或字典。 这样可以快速访问卡的可用次数。 
2. 对唯一的卡值进行排序。 排序确保我们始终从最小的可用卡片开始形成序列，这是保持连续性所必需的。 
3. 迭代排序后的唯一卡值。 对于每张卡：

 1. 在地图上查看其频率。 如果频率为零，则它已经在之前的序列中被完全使用，因此跳过它。 
2. 否则，尝试形成一个长度的序列`groupSize`从这张卡开始。 
3. 对于每张卡`current`在序列中，检查它是否至少以所需的频率存在于地图中。 如果缺少任何卡，请退回`false`。 
4. 将序列中每张牌的数量减去起始牌的数量。 这可确保正确计算重复项。 
4. 如果所有卡牌都按顺序使用成功，则返回`true`。 

**为什么有效：** 该算法保持了不变式，即我们始终使用最小的可用卡来形成序列，从而防止连续序列中出现“漏洞”。 减少频率计数可确保不会错误地重复使用卡。 排序保证我们按升序处理序列，因此不会违反连续要求。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def isNStraightHand(self, hand: List[int], groupSize: int) -> bool:
        if len(hand) % groupSize != 0:
            return False
        
        count = Counter(hand)
        for card in sorted(count):
            if count[card] > 0:
                freq = count[card]
                for i in range(card, card + groupSize):
                    if count[i] < freq:
                        return False
                    count[i] -= freq
        return True
```该实现首先检查手的长度是否可以整除`groupSize`。 如果没有，就不可能形成团体。 使用`Counter`，我们跟踪卡片计数。 对钥匙进行排序可确保我们始终从最小的可用卡开始。 对于每张计数为正数的卡片，我们尝试形成一个序列`groupSize`，适当减少计数。 如果所需的卡丢失或不足，该函数立即返回`false`。 如果所有序列都成功，则函数返回`true`。 

## 解决方案```go
import "sort"

func isNStraightHand(hand []int, groupSize int) bool {
    if len(hand)%groupSize != 0 {
        return false
    }

    count := make(map[int]int)
    for _, card := range hand {
        count[card]++
    }

    unique := make([]int, 0, len(count))
    for card := range count {
        unique = append(unique, card)
    }
    sort.Ints(unique)

    for _, card := range unique {
        freq := count[card]
        if freq > 0 {
            for i := 0; i < groupSize; i++ {
                nextCard := card + i
                if count[nextCard] < freq {
                    return false
                }
                count[nextCard] -= freq
            }
        }
    }
    return true
}
```在 Go 中，我们使用映射来计算卡片频率，并使用切片来存储排序的唯一卡片值。 该算法与 Python 几乎相同。 Go 特定的注意事项包括显式为唯一键创建切片并使用`sort.Ints`用于排序。 映射访问是安全的，对于丢失的键返回零，与 Python 匹配`Counter`行为。
