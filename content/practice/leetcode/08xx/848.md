[LeetCode 第 848 题](https://leetcode.com/problems/shifting-letters/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们对一串小写英文字母重复应用字符移位。 

我们有两个输入：

 - 一根绳子`s`，仅由小写英文字母组成。 
- 整数数组`shifts`， 在哪里`shifts[i]`告诉我们应该将 **first 移动多少次`i + 1`字符串的字符**。 

单次移位意味着将一个字符移动到下一个字母，从`'z'`回到`'a'`。 

例如：

-`'a' → 'b'`-`'c' → 'd'`-`'z' → 'a'`关键细节是每个操作都会影响字符串的前缀。 如果`shifts[i] = x`，那么第一个`i + 1`字符被移动`x`次。 

我们必须在**应用所有操作**后返回最终字符串。 

乍一看，这看起来像是一个我们反复修改前缀的模拟问题。 然而，这些限制揭示了为什么这种方法是危险的。 

字符串的长度可以大到`10^5`，每个移位值可以大到`10^9`。 

这告诉我们两件重要的事情：

 1. 我们不能逐一进行轮班，因为`10^9`每个字符的操作是不可能的。 
2. 我们不能重复修改一个前缀`O(n²)`方式因为`n = 10^5`会使那太慢。 

相反，我们需要一种方法来有效地确定**每个角色总共接收多少个转变**。 

### 重要观察

 索引处的一个字符`i`受索引中所有操作的影响`i`到最后。 

例如：```
s = "abc"
shifts = [3,5,9]
```特点`'a'`在索引处`0`被转移：```
3 + 5 + 9 = 17 times
```特点`'b'`在索引处`1`被转移：```
5 + 9 = 14 times
```特点`'c'`在索引处`2`被转移：```
9 times
```这意味着我们需要一个**后缀总和**，而不是重复的前缀更新。 

### 边缘情况

 有一些情况很容易导致简单的实现失败。 

如果字符串有长度`1`，该算法仍应正常工作，因为仅移动了一个字符。 

非常大的移位值，例如`10^9`需要模运算。 由于字母表只有`26`字母、移动`26`次返回相同的字符。 因此，我们只关心：```
shift % 26
```包含的字符串`'z'`需要环绕处理。 例如，转移`'z'`经过`1`应该成为`'a'`，不是无效字符。 

该问题保证：

 -`s`仅包含小写英文字母。 
-`shifts.length == s.length`-`s.length >= 1`因此我们不需要处理无效的输入或不匹配的长度。 

## 方法

 ### 蛮力方法

 最直接的方法是完全按照描述模拟问题。 

对于每个索引`i`:

 1. 采取`shifts[i]`。 
2. 移动第一个`i + 1`角色很多次。 
3. 继续下一步操作。 

为了避免重复的单字符移位，我们可以计算：```
effective_shift = shifts[i] % 26
```并将其直接应用于前缀中的每个字符。 

虽然这会产生正确的答案，但速度太慢了。 

对于每一个`i`，我们修改为`i + 1`人物。 

总工作量变为：```
1 + 2 + 3 + ... + n = O(n²)
```和`n = 10^5`，这太昂贵了。 

### 关键见解

 我们可以问：

 **每个角色总共接受多少轮班？**

 位置上的一个字符`i`受到每个班次操作的影响`i`向前。 

这意味着：```
total_shift[i] =
shifts[i] + shifts[i+1] + ... + shifts[n-1]
```这是一个**后缀和**问题。 

我们可以从右到左处理数组，同时保持轮班的运行总数。 

对于每个字符：

 1. 将当前移位值添加到运行后缀和中。 
2. 对它进行模减`26`。 
3. 将该转变应用于当前字符。 

这避免了重复接触前缀并将复杂性降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复更新前缀 |
 | 最佳| O(n) | O(n) | 使用后缀班次总和 |

 ## 算法演练

 1. 将字符串转换为可变字符列表。 

Python中的字符串是不可变的，因此直接修改字符效率很低。 转换为列表允许就地更新。 
2. 初始化运行后缀和。 

我们保留一个名为`total_shift`存储影响当前角色的累积位移。 
3. 从右向左遍历字符串。 

我们向后退，因为每个位置都取决于所有未来的移位值。 
4. 更新正在运行的班次总计。 

添加：```
shifts[i]
```到`total_shift`。 

自从转移以来`26`不改变任何内容，减少结果：```
total_shift %= 26
```5. 将当前字符转换为数字。 

我们绘制地图：```
'a' → 0
'b' → 1
...
'z' → 25
```使用 ASCII 算术。 
6. 应用班次。 

计算：```
new_position =
(old_position + total_shift) % 26
```模数处理字母表环绕。 
7. 转换回字符。 

将移位后的数值恢复为小写字母。 
8. 将字符列表连接成字符串。 

返回最终转换后的字符串。 

### 为什么它有效

 核心不变量是在处理索引时`i`,`total_shift`包含影响字符的所有移位操作的总和`i`。 

因为索引处的每个操作`j ≥ i`影响性格`i`，从右向左遍历可确保我们准确累积适用于当前字符的移位。 应用模数`26`保持正确性，因为字母表重复每个`26`轮班。 

## Python 解决方案```python
from typing import List

class Solution:
    def shiftingLetters(self, s: str, shifts: List[int]) -> str:
        characters = list(s)
        total_shift = 0

        for i in range(len(s) - 1, -1, -1):
            total_shift = (total_shift + shifts[i]) % 26

            current_position = ord(characters[i]) - ord('a')
            new_position = (current_position + total_shift) % 26

            characters[i] = chr(new_position + ord('a'))

        return ''.join(characters)
```实现首先将输入字符串转换为字符列表，因为 Python 中的字符串无法就地修改。 

我们维持`total_shift`，它存储影响当前字符的累积后缀移位。 通过从右到左迭代，我们自然地构建后缀和。 

对于每个字符，我们使用 ASCII 减法将其转换为数字字母索引。 应用模移位后`26`，我们将结果转换回字符并覆盖原始位置。 

最后，我们将列表连接回字符串并返回结果。 

## 解决方案```go
func shiftingLetters(s string, shifts []int) string {
	chars := []byte(s)
	totalShift := 0

	for i := len(s) - 1; i >= 0; i-- {
		totalShift = (totalShift + shifts[i]) % 26

		currentPosition := int(chars[i] - 'a')
		newPosition := (currentPosition + totalShift) % 26

		chars[i] = byte(newPosition) + 'a'
	}

	return string(chars)
}
```Go 实现遵循相同的逻辑，但使用`[]byte`切片是因为 Go 中的字符串是不可变的。 

Go 特有的一项重要细节是类型转换。 由于字节是无符号整数，因此涉及字符的算术必须转换为`int`在应用模运算之前。 

溢出不是问题，因为我们使用以下方法不断减少累积偏移`% 26`，保持值非常小。

 ## 边缘情况

 一个长度的字符串`1`是一个重要的边界条件。 由于只有一个字符，因此仅适用一次移位操作。 有缺陷的实现可能会在向后遍历时意外地错误处理索引。 该解决方案正确处理索引`0`并返回移位后的结果。 

如果按字面意思处理，非常大的移位值可能会出现问题。 自从`shifts[i]`可以大到`10^9`，一次一步地重复移动字符会非常慢。 该实现通过减少累积移位模数来避免这种情况`26`，因为每一个`26`将循环移回原始字符。 

靠近字母表末尾的字符，尤其是`'z'`，需要适当的环绕逻辑。 没有模运算，移位`'z'`经过`1`可能会产生无效字符。 通过计算：```
(current_position + total_shift) % 26
```该实现正确地将值映射回有效的字母表范围。
