[LeetCode 833 题](https://leetcode.com/problems/find-and-replace-in-string/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`和三个并行数组：

 -`indices[i]`告诉我们哪里可能会发生替换
 -`sources[i]`是我们期望在该索引处找到的子字符串
 -`targets[i]`如果匹配有效，我们应该替换它的字符串

 对于每个操作，我们必须检查是否`sources[i]`实际上出现在原始字符串中`s`开始于`indices[i]`。 如果是，我们将该子字符串替换为`targets[i]`。 如果没有，我们将对该操作保留该字符串不变。 

重要的细节是所有替换同时发生。 这意味着替换不会影响后来替换的位置。 每项检查都必须针对原始字符串执行，而不是部分修改的字符串。 

例如：

-`s = "abcd"`-`indices = [0, 2]`-`sources = ["a", "cd"]`-`targets = ["eee", "ffff"]`在索引处`0`, 子串`"a"`匹配，所以我们将其替换为`"eee"`。 

在索引处`2`, 子串`"cd"`匹配，所以我们将其替换为`"ffff"`。 

最终结果变成`"eeebffff"`。 

限制相对较小：

 -`s.length <= 1000`-`k <= 100`-`sources[i].length <= 50`这些限制意味着我们不需要后缀数组或滚动哈希等非常先进的算法。 简单的字符串扫描解决方案就足够高效了。 

该问题还保证有效的替换区域永远不会重叠。 这非常重要，因为这意味着我们永远不需要解决接触相同字符的多个替换之间的冲突。 

一些边缘情况很重要：

 - 源字符串的索引可能不匹配。 
- 替换可能以任意顺序出现。 
- 一些替换可能发生在字符串末尾附近。 
- 目标字符串可能比源字符串更长或更短。 
- 可能存在多个有效替换，但保证它们不会重叠。 

在迭代时立即修改字符串的简单实现可能会破坏以后替换的索引，这就是“同时”要求很重要的原因。 

## 方法

 ### 蛮力方法

 最直接的做法就是直接在字符串上一一处理替换。 

对于每个操作：

 1. 检查源是否在指定索引处匹配。 
2. 如果匹配，立即修改该字符串。 

然而，这会产生一个问题。 一旦字符串改变长度，所有后续索引可能会变得无效，因为原始索引不再与更新后的字符串匹配。 

一种可能的解决方法是按索引降序对操作进行排序，以便右侧的修改不会影响左侧的位置。 这是可行的，但重复的字符串切片和连接仍然会产生不必要的开销。 

尽管约束足够小，该解决方案可以通过，但它并不是对同时替换要求的最清晰的解释。 

### 最佳方法

 关键的见解是每个替换决策仅取决于原始字符串。 

我们可以：

 1. 预先计算哪些索引具有有效的替换。 
2. 从左到右扫描原始字符串。 
3. 逐步构建答案。 

在每个位置：

 - 如果从那里开始有效的替换，则附加目标字符串并跳过源长度。 
- 否则正常附加当前字符。 

这种方法自然地保留了同时行为，因为所有检查都是在构造开始之前针对原始字符串进行的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k * n) | O(n) | 每次替换后重复字符串重建 |
 | 最佳| O(n + 源总长度) | O(k + n) | 单次从左到右扫描并进行预处理替换 |

 ## 算法演练

 1. 创建一个存储有效替换的哈希映射。 

关键将是替换的起始索引。 该值将包含：

 - 源字符串
 - 目标字符串

 我们只存储其源实际上与该索引处的原始字符串匹配的替换。 
2. 迭代所有替换操作。 

对于每个操作：

 - 让`start = indices[i]`- 让`source = sources[i]`- 检查是否：```
s[start:start + len(source)] == source
```如果子字符串匹配，则将此替换存储在哈希映射中。 
3. 初始化一个空的结果列表。 

我们使用列表是因为重复连接 Python 字符串效率低下。 
4. 使用指针从左到右开始扫描字符串`i`。 
5. 在每个位置，检查有效替换是否从`i`。 

如果`i`存在于替换地图中：

 - 追加对应的目标字符串
 - 提前`i`由源字符串的长度决定

 否则：

 - 追加`s[i]`- 进步`i`经过`1`6. 继续，直到处理完整个字符串。 
7. 将结果列表连接到最终字符串中并返回。 

### 为什么它有效

 该算法之所以有效，是因为每个替换决策都是在发生任何修改之前确定的。 由于所有检查都是针对原始字符串执行的，因此保留了同时替换的要求。 

在从左到右扫描期间，每个字符位置仅处理一次。 由于保证替换不会重叠，因此跳过替换的子字符串始终是安全的，并且永远不会错过另一个有效的替换。 

## Python 解决方案```python
from typing import List

class Solution:
    def findReplaceString(
        self,
        s: str,
        indices: List[int],
        sources: List[str],
        targets: List[str]
    ) -> str:

        replacements = {}

        # Store only valid replacements
        for index, source, target in zip(indices, sources, targets):
            if s[index:index + len(source)] == source:
                replacements[index] = (source, target)

        result = []
        i = 0

        while i < len(s):
            if i in replacements:
                source, target = replacements[i]

                result.append(target)

                # Skip the matched source substring
                i += len(source)
            else:
                result.append(s[i])
                i += 1

        return "".join(result)
```实现首先预处理所有有效的替换。 我们同时迭代并行数组`zip`。 

对于每个替换操作，我们都会验证源字符串是否确实存在于原始字符串中的指定索引处。 如果是，我们将替换存储在`replacements`字典。 

字典允许在稍后扫描字符串时进行恒定时间查找。 

接下来，我们使用从左到右的遍历来构建最终结果。 指针`i`表示原始字符串中的当前位置。 

如果更换开始于`i`，我们追加目标字符串并跳过整个源子字符串长度。 否则，我们将当前字符直接复制到结果中。 

最后，我们将收集到的片段连接到最终的输出字符串中。 

## 解决方案```go
package main

import "strings"

func findReplaceString(s string, indices []int, sources []string, targets []string) string {
	type Replacement struct {
		source string
		target string
	}

	replacements := make(map[int]Replacement)

	// Store only valid replacements
	for i := 0; i < len(indices); i++ {
		index := indices[i]
		source := sources[i]

		if s[index:index+len(source)] == source {
			replacements[index] = Replacement{
				source: source,
				target: targets[i],
			}
		}
	}

	var builder strings.Builder

	for i := 0; i < len(s); {
		if replacement, exists := replacements[i]; exists {
			builder.WriteString(replacement.target)
			i += len(replacement.source)
		} else {
			builder.WriteByte(s[i])
			i++
		}
	}

	return builder.String()
}
```Go 实现遵循与 Python 版本相同的算法结构。 

Go 不使用 Python 元组，而是使用一个小的`Replacement`结构体用于存储源字符串和目标字符串。 

结果字符串是使用构造的`strings.Builder`，这是在 Go 中增量构建字符串的惯用且有效的方法。 

由于问题约束很小，因此不存在整数溢出问题。 Go 字符串切片也可以有效地进行子字符串比较。

 ## 边缘情况

 ### 替换源不匹配

 错误的一个常见来源是假设每个替换操作都是有效的。 该问题明确指出，只有当源字符串与给定索引处的子字符串完全匹配时，才应进行替换。 

例如：```
s = "abcd"
index = 1
source = "zz"
```自从`"zz"`不出现在索引处`1`，替换必须被忽略。 

该实现通过检查以下内容在预处理期间安全地处理此问题：```
s[index:index + len(source)] == source
```仅存储有效的替换。 

### 替换索引未排序

 不保证输入数组按索引排序。 

如果替换出现乱序，在修改字符串的同时按顺序处理替换的简单实现可能会产生不正确的结果。 

当前的解决方案通过以下方式完全避免了这种情况：

 1. 独立验证替换
 2. 使用以索引为键的字典
 3.从左到右扫描原始字符串

 由于这种结构，输入顺序并不重要。 

### 目标字符串有不同的长度

 另一个常见问题是处理目标字符串长度与源长度不同的替换。 

例如：```
source = "ab"
target = "xyzxyz"
```或者```
source = "abcdef"
target = "x"
```如果解决方案在迭代时直接修改字符串，则索引移位很容易破坏以后的替换。 

此实现避免了所有索引问题，因为它从不就地编辑原始字符串。 相反，它增量地构造一个全新的结果字符串。
