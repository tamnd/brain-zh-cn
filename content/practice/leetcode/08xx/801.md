[LeetCode 问题 801](https://leetcode.com/problems/minimum-swaps-to-make-sequences-increasing/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们两个数组，`nums1`和`nums2`，两者长度相同。 在每个索引处`i`，我们可以保持值不变，或者交换`nums1[i]`和`nums2[i]`。 

我们的目标是使两个数组严格递增，同时执行最少次数的交换。 

严格递增数组意味着：

 -`arr[i] < arr[i + 1]`对于每个有效索引
 - 不允许相邻值相等
 - 不允许减小值

 重要的细节是，仅允许在同一指数上进行掉期。 我们不能任意重新排列元素。 在每个位置，我们都会做出二元决定：

 - 请勿交换
 - 在此索引处交换货币对

 输出是使两个结果数组严格递增所需的最小交换次数。 

例如：```
nums1 = [1,3,5,4]
nums2 = [1,2,3,7]
```在索引处`3`，这对`(4,7)`打破了递增条件，因为`5 < 4`是假的。 交换它们可以得到：```
nums1 = [1,3,5,7]
nums2 = [1,2,3,4]
```现在两个数组都严格递增，并且我们只使用了一次交换。 

约束条件非常重要：

 -`n`可以大到`100000`- 对所有交换组合进行强力探索是不可能的
 - 我们需要一个接近线性时间的解决方案

 该问题还保证有效答案始终存在。 这意味着我们不需要处理最终输出中的不可能状态。 

一些边缘情况很重要：

 - 已经严格递增的数组
 - 需要在多个位置交换的数组
 - 最优解在交换和不交换之间交替的情况
 - 交换状态和非交换状态在某个位置都保持有效的情况
 - 相等的值可能会使严格的增加条件无效

 由于每个决策在很大程度上取决于先前的索引，因此这自然表明动态规划。 

## 方法

 ### 蛮力方法

 最直接的方法是尝试所有可能的交换组合。 

对于每个索引，我们有两种选择：

 1.不要交换
 2. 交换该索引处的元素

 由于有`n`索引，这会创建`2^n`可能的配置。 

对于每种配置，我们可以构造结果数组并验证两者是否严格递增。 在所有有效配置中，我们选择交换次数最少的配置。 

这种方法是正确的，因为它探索了每一个可能的有效决策序列。 然而，这在计算上是不可行的。 

如果`n = 100000`， 甚至`2^50`已经是天文数字了，所以`2^100000`是完全不可能的。 

### 最优动态规划方法

 关键的见解是索引处的决策`i`仅取决于索引处的状态`i - 1`。 

我们不需要记住互换的整个历史。 我们只需要知道：

 - 如果我们不交换到前一个索引，那么最少交换次数是多少？ 
- 如果我们确实进行了交换，那么与之前的索引的最小交换次数是多少？ 

这给了我们两个 DP 状态：

 -`keep[i]`= 达到指数所需的最小掉期`i`如果索引`i`没有被交换
 -`swap[i]`= 达到指数所需的最小掉期`i`如果索引`i`被交换了

 我们可以进一步优化空间，而不是存储完整的数组，因为只有先前的状态才重要。 

在每个位置，我们检查两种可能的转换：

 1.自然秩序持续增强
 2. 转仓后交叉订单持续增加

 这导致`O(n)`动态规划解决方案。

 ## 算法演练

 1.初始化两个变量：

 -`keep = 0`-`swap = 1`

`keep`表示如果我们不交换索引，则需要的最小交换量`0`。`swap`表示交换索引时所需的最小交换量`0`，这需要一次操作。 
2. 从索引开始迭代数组`1`到`n - 1`。 
3. 对于每个索引，初始化：

 -`next_keep = infinity`-`next_swap = infinity`这些代表了当前指数的最佳结果。 
4. 检查数组是否保持严格递增而不更改交换奇偶校验。 

这个条件是：```
nums1[i] > nums1[i - 1]
nums2[i] > nums2[i - 1]
```如果为真：

 - 如果之前的索引也未交换，我们可以保持当前索引未交换。 
- 如果之前的索引也被交换了，我们可以交换当前的索引。 

所以：```
next_keep = min(next_keep, keep)
next_swap = min(next_swap, swap + 1)
```5. 如果交换两个相邻索引之一，检查数组是否保持递增状态。 

这个条件是：```
nums1[i] > nums2[i - 1]
nums2[i] > nums1[i - 1]
```如果为真：

 - 我们可以在保留先前索引的同时交换当前索引
 - 我们可以在交换之前的索引时保留当前索引

 所以：```
next_keep = min(next_keep, swap)
next_swap = min(next_swap, keep + 1)
```6.更新：```
keep = next_keep
swap = next_swap
```7. 处理完所有索引后，返回：```
min(keep, swap)
```### 为什么它有效

 该算法之所以有效，是因为索引处的每个有效配置`i`仅取决于索引是否`i - 1`是否被交换。 严格增加条件仅比较相邻元素，因此一旦知道其最佳状态，就不需要重新考虑较早的位置。 

DP 状态始终保持每个可能的先前状态配置所需的最小交换。 由于每个有效转换都会被检查一次，因此该算法保证了全局最优答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSwap(self, nums1: List[int], nums2: List[int]) -> int:
        n = len(nums1)

        keep = 0
        swap = 1

        for i in range(1, n):
            next_keep = float('inf')
            next_swap = float('inf')

            # Case 1:
            # No cross swap needed
            if nums1[i] > nums1[i - 1] and nums2[i] > nums2[i - 1]:
                next_keep = min(next_keep, keep)
                next_swap = min(next_swap, swap + 1)

            # Case 2:
            # Cross swap relationship works
            if nums1[i] > nums2[i - 1] and nums2[i] > nums1[i - 1]:
                next_keep = min(next_keep, swap)
                next_swap = min(next_swap, keep + 1)

            keep = next_keep
            swap = next_swap

        return min(keep, swap)
```实现直接遵循动态规划策略。 

变量`keep`和`swap`表示在两种不同状态下达到前一个指数所需的最小掉期。 

在循环内部，`next_keep`和`next_swap`计算当前索引的最佳值。 

第一个条件检查如果两个索引使用相同的交换状态，数组是否保持增加状态。 在这种情况下：

 - 保持过渡以保持
 - 交换转换到交换

 第二个条件检查相邻索引之间切换交换奇偶校验是否仍然保留递增顺序。 在这种情况下：

 - 交换过渡以保留
 - 保持转换到交换

 每次迭代结束时，当前结果将成为下一步的先前结果。 

最后，两种状态中的最小值给出最优答案。
