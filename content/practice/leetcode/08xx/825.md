[LeetCode 825 题](https://leetcode.com/problems/friends-of-property-ages/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个数组`ages`，其中每个值代表社交媒体平台上一个人的年龄。 我们必须根据一组特定的规则来确定人与人之间发送的好友请求数量。 

一个人`x`可以向某人发送好友请求`y`仅当所有无效条件均为假时。 如果满足以下任一条件，则请求将被拒绝：

 -`age[y] <= 0.5 * age[x] + 7`-`age[y] > age[x]`-`age[y] > 100 && age[x] < 100`如果这些条件都不成立，那么`x`发送请求至`y`。 

重要的细节是友谊请求是定向的。 如果人`A`可以向某人发送请求`B`，这并不自动意味着`B`可以寄一份回去。 我们必须单独计算每个有效的定向请求。 

我们还被告知，一个人不能向自己发送请求。 

输入大小最多为`2 * 10^4`，它足够大，以至于直接使用嵌套循环检查每一对都会变得昂贵。 由于年龄限制在范围内`1`到`120`，这个约束强烈暗示基于计数或排序的优化可能是有用的。 

有几个重要的边缘情况需要记住：

 - 年龄小于`15`永远无法发送请求，因为`0.5 * age + 7`变得过于严格。 
- 多个人可能年龄相同，并且经常可以互相发送请求。 
- 请求是定向的，因此必须仔细计算有效对。 
- 这`>100`规则看起来很特殊，但实际上已经暗示了`age[y] > age[x]`大多数情况下的情况。 尽管如此，它仍然必须在逻辑上受到尊重。 
- 重复的年龄可能会产生许多有效的请求，因此有效地计算频率很重要。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个有序对`(x, y)`在哪里`x != y`。 

对于每一对，我们直接评估三个条件。 如果没有一个为真，我们就增加答案。 

这种方法是正确的，因为它从字面上准确地模拟了问题定义。 每个可能的定向请求都会被单独检查。 

然而，对于较大的输入来说，时间复杂度太高。 和`n = 20,000`，检查每一对大约需要`400 million`在最坏的情况下进行比较，效率很低。 

### 最佳解决方案的关键见解

 重要的观察是，请求的有效性仅取决于年龄，而不取决于个人身份。 

由于年龄是有界限的`1`和`120`，我们可以对数组进行排序并使用二分搜索或两个指针来有效地计算有效范围。 

对于固定的发件人年龄`a`，有效的接收者必须满足：

 -`recipient_age > 0.5 * a + 7`-`recipient_age <= a`这样排序后就形成了一个连续的有效区间。 

我们可以使用二分搜索来确定有多少人落入有效范围，而不是单独检查每个人。 

这大大降低了复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 直接检查每个订购的对 |

 ## 算法演练

 ### 最优排序+二分查找算法

 1. 排序`ages`大批。 

排序使我们能够有效地找到每个人的连续有效年龄范围。 排序后，发件人的所有有效收件人都会显示在连续的段中。 
2. 遍历作为发送者的每个人。 

假设当前发送者年龄是`age`。 
3. 计算最低有效收件人年龄。 

无效的条件是：$age_y \leq 0.5 \cdot age_x + 7$因此，有效的接收者必须满足：$age_y > 0.5 \cdot age_x + 7$我们计算：```
lower = 0.5 * age + 7
```4. 使用二分查找查找第一个有效收件人。 

由于数组是有序的，我们可以找到第一个值大于的索引`lower`。 
5. 使用二分查找查找最后一个有效收件人。 

有效的收件人还必须满足：$age_y \leq age_x$我们发现第一个索引大于`age`，这给了我们唯一的上限。 
6.统计有效区间内有多少人。 

如果：```
left = first valid index
right = first index greater than age
```然后：```
valid_people = right - left
```7. 排除发件人本身。 

由于一个人无法向自己发送请求，因此减一：```
valid_people - 1
```8. 将结果添加到总答案中。 

对每个发件人重复此过程。 

### 为什么它有效

 排序后，发件人的每个有效收件人形成一个连续的年龄范围。 二分查找正确地找到了该范围的边界。 由于每个发件人都是独立处理的，并且排除了自身请求，因此每个有效的定向请求只会被计数一次。 

## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def numFriendRequests(self, ages: List[int]) -> int:
        ages.sort()

        total_requests = 0

        for age in ages:
            if age < 15:
                continue

            lower_bound = 0.5 * age + 7

            left = bisect_right(ages, lower_bound)
            right = bisect_right(ages, age)

            total_requests += right - left - 1

        return total_requests
```实现首先对年龄数组进行排序。 这是至关重要的，因为二分搜索仅适用于排序数据。 

对于每个年龄，我们首先跳过年龄小于`15`。 这些人永远无法发送有效的请求，因为下限条件变得不可能满足。 

然后我们计算可接受的最低接受者年龄。 使用`bisect_right`，我们找到第一个严格大于该阈值的索引。 

另一个二分搜索找到第一个大于发件人年龄的索引。 这定义了有效收件人的上限。 

有效收件人的数量就是这个间隔的大小。 我们减一以排除发件人本身。 

最后，所有有效请求计数都会累积到结果中。 

## 解决方案```go
package main

import (
	"sort"
)

func numFriendRequests(ages []int) int {
	sort.Ints(ages)

	totalRequests := 0

	for _, age := range ages {
		if age < 15 {
			continue
		}

		lowerBound := float64(age)/2.0 + 7

		left := sort.Search(len(ages), func(i int) bool {
			return float64(ages[i]) > lowerBound
		})

		right := sort.Search(len(ages), func(i int) bool {
			return ages[i] > age
		})

		totalRequests += right - left - 1
	}

	return totalRequests
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

而不是Python的`bisect_right`, Go 使用`sort.Search`与自定义谓词。 第一个搜索找到大于下限的第一个有效收件人年龄，而第二个搜索找到严格大于发件人年龄的第一个年龄。 

Go 切片是数组的动态视图，因此除了排序之外不需要额外的内存分配。 

整数溢出不是问题，因为最大可能的请求数量完全在 Go 的整数范围内。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 排序占主导地位，每次迭代都执行二分搜索 |
 | 空间| O(1) 或 O(log n) | 取决于排序实现细节 |

 排序步骤需要`O(n log n)`时间。 排序后，每个人执行两次二分搜索，每次花费`O(log n)`。 既然这发生在所有人身上`n`人，总剩余`O(n log n)`。 

该算法仅使用输入数组之外的一些额外变量。 一些排序实现使用递归堆栈空间，这可能有助于`O(log n)`辅助空间。

 ## 边缘情况

 一个重要的边缘情况是所有用户的年龄都小于`15`。 例如，`[14, 14, 14]`。 幼稚的实现可能会错误地计算相同年龄之间的请求。 然而，条件`age[y] <= 0.5 * age[x] + 7`阻止发送任何有效的请求。 该实现通过立即跳过下面的年龄来有效地处理这个问题`15`。 

另一个重要的案例涉及许多重复的年龄，例如`[16, 16, 16]`。 每个人都可以向除自己之外的其他人发送请求。 由于有三个人，每个人向另外两个人发送请求，产生`6`请求总数。 不正确地处理重复项或自计数很容易产生错误的答案。 二分搜索间隔与减一相结合可以正确处理这种情况。 

第三种边缘情况发生在年龄左右`100`边界。 例如，`[99, 100, 101]`。 年龄以上的特殊情况`100`可能会令人困惑。 该实现自然会处理这个问题，因为接收者必须已经满足`recipient_age <= sender_age`。 因此，`101`可以发送至`100`， 但`99`无法发送至`101`。 排序范围逻辑自动执行这些规则。
