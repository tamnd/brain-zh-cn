[LeetCode 847 题](https://leetcode.com/problems/shortest-path-visiting-all-nodes/)

 **难度：** 🔴难
 **主题：** 动态规划、位操作、广度优先搜索、图论、位掩码

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个无向连通图`n`节点标记为`0`到`n - 1`。 该图表示为邻接列表，其中`graph[i]`包含直接连接到节点的所有节点`i`。 

我们必须计算至少访问每个节点一次的最短路径的长度。 该路径可以在任何节点开始并且可以在任何节点结束。 我们还可以多次重新访问节点并重用边。 

关键细节是我们没有被要求找到哈密顿路径。 哈密​​顿路径要求每个节点恰好访问一次，这是一个 NP 难题。 这里，允许重新访问节点，这使得可以使用基于状态的图遍历技术来解决问题。 

输出是访问所有节点所遍历的最小边数。 

例如，在第一个示例中：```
0 connected to 1, 2, 3
```一种有效的最短遍历是：```
1 -> 0 -> 2 -> 0 -> 3
```这条路径使用 4 条边，所以答案是`4`。 

约束条件尤其重要：

 -`1 <= n <= 12`- 图形已连接
 - 该图是无向的

 自从`n`最多为 12，则节点子集总数为：```
2^12 = 4096
```这对于基于位掩码的动态编程或状态上的广度优先搜索来说足够小。 

重要的边缘情况包括：

 - 只有一个节点的图。 由于我们已经从该节点开始，所以答案是`0`。 
- 需要重新访问节点的稀疏图。 
- 存在许多遍历选择的密集图。 
- 必须反复重新访问中心节点的星形图。 
- 可能存在多个最短遍历的循环图。 

该问题保证了图是连通的，因此我们永远不需要处理不可达的节点。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试从每个节点开始的所有可能路径，并跟踪哪些节点已被访问。 

在每一步中，我们都可以递归地移动到相邻节点并继续，直到所有节点都被访问过。 然后我们将记录所有有效遍历中的最小路径长度。 

这种方法是正确的，因为它详尽地探索了每一个可能的遍历序列。 最终，它会发现最短的一个。 

然而，可能的遍历序列的数量呈指数增长。 由于允许重新访问节点，搜索空间变得巨大。 即使进行了修剪，状态的数量也会迅速爆炸。 

这种方法对于`n = 12`。 

### 最佳方法，带位掩码的多源 BFS

 关键的见解是，重要的信息不仅仅是当前节点，还包括哪些节点已经被访问过。 

这意味着真实状态是：```
(current_node, visited_nodes_mask)
```我们可以使用位掩码表示访问过的节点：

 - 位`i`是`1`如果节点`i`已被访问过。 
- 少量`i`是`0`否则。 

例如：```
mask = 1011
```表示节点`0`,`1`， 和`3`已被访问过。 

然后我们对这些状态执行广度优先搜索。 

由于 BFS 逐级探索状态，因此当我们第一次到达所有节点都被访问过的状态时，我们保证找到最短路径长度。 

另一个重要的优化是多源BFS。 

我们不是单独尝试每个起始节点，而是同时初始化所有节点的 BFS 队列：```
(node=i, mask=(1 << i))
```这意味着 BFS 并行探索所有可能的起始位置。 

状态总数为：```
n * 2^n
```这是可以管理的`n <= 12`。

 ## 算法演练

 1. 计算最终目标掩模。 

我们想要一个每个节点都被访问过的位掩码。 

如果有`n`节点：```
target_mask = (1 << n) - 1
```例如，如果`n = 4`:```
target_mask = 1111
```2. 初始化每个节点的 BFS 队列。 

由于我们可以从任何节点开始，因此我们同时从所有节点开始 BFS。 

对于每个节点`i`:```
state = (i, 1 << i)
```这意味着：

 - 我们目前处于节点`i`- 唯一节点`i`已被访问过
 3. 维护访问状态结构。 

我们必须避免重复访问同一个状态。 

状态通过以下方式唯一标识：```
(current_node, visited_mask)
```即使我们重新访问同一个节点，如果访问集发生变化，状态仍然可能不同。 
4.逐级进行BFS。 

每个 BFS 级别代表一次额外的边遍历。 

对于每个州：

 - 提取物`(node, mask)`- 拜访所有邻居
 - 创建一个新蒙版：```
new_mask = mask | (1 << neighbor)
```这将邻居标记为已访问。 
5. 检查是否所有节点都被访问过。 

如果：```
new_mask == target_mask
```那么我们就访问了每个节点。 

由于 BFS 首先保证最短距离，因此我们立即返回当前距离加一。 
6. 继续，直到找到答案。 

因为图是连通的，所以BFS保证最终达到全掩码状态。 

### 为什么它有效

 BFS 总是按长度递增的顺序探索路径。 每个状态都完全捕获我们当前的位置以及已经访问过的节点。 因此，当BFS第一次达到所有节点都被访问过的状态时，该路径一定是访问每个节点的最短可能遍历。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def shortestPathLength(self, graph: List[List[int]]) -> int:
        n = len(graph)

        if n == 1:
            return 0

        target_mask = (1 << n) - 1

        queue = deque()
        visited = set()

        for node in range(n):
            mask = 1 << node
            queue.append((node, mask, 0))
            visited.add((node, mask))

        while queue:
            current_node, mask, distance = queue.popleft()

            for neighbor in graph[current_node]:
                new_mask = mask | (1 << neighbor)

                if new_mask == target_mask:
                    return distance + 1

                state = (neighbor, new_mask)

                if state not in visited:
                    visited.add(state)
                    queue.append((neighbor, new_mask, distance + 1))

        return -1
```实现从处理最简单的边缘情况开始。 如果图只包含一个节点，则不需要遍历，所以答案是立即的`0`。 

接下来，我们计算目标位掩码，其中每个位都设置为`1`。 这代表所有节点都被访问过的状态。 

队列以以下形式存储 BFS 状态：```python
(current_node, visited_mask, distance)
```我们用每个节点初始化队列，因为遍历可能从任何地方开始。 这就是该算法成为多源 BFS 的原因。 

这`visited`设置可以防止多余的工作。 使用相同的掩码重新访问相同的节点没有任何好处，因为 BFS 已经以尽可能短的距离达到了该状态。 

在 BFS 循环内，我们处理邻居并使用按位 OR 更新访问的掩码：```python
new_mask = mask | (1 << neighbor)
```如果更新后的掩码等于目标掩码，则每个节点都已被访问过。 由于 BFS 首先探索最短路径，所以我们立即返回。 

否则，如果新状态尚未被处理，我们会将其放入队列。 

## 解决方案```go
package main

import "container/list"

func shortestPathLength(graph [][]int) int {
	n := len(graph)

	if n == 1 {
		return 0
	}

	targetMask := (1 << n) - 1

	type State struct {
		node     int
		mask     int
		distance int
	}

	queue := list.New()

	visited := make(map[[2]int]bool)

	for i := 0; i < n; i++ {
		mask := 1 << i

		queue.PushBack(State{
			node:     i,
			mask:     mask,
			distance: 0,
		})

		visited[[2]int{i, mask}] = true
	}

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		current := front.Value.(State)

		for _, neighbor := range graph[current.node] {
			newMask := current.mask | (1 << neighbor)

			if newMask == targetMask {
				return current.distance + 1
			}

			stateKey := [2]int{neighbor, newMask}

			if !visited[stateKey] {
				visited[stateKey] = true

				queue.PushBack(State{
					node:     neighbor,
					mask:     newMask,
					distance: current.distance + 1,
				})
			}
		}
	}

	return -1
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

由于Go没有提供内置的双端队列，我们​​使用`container/list`实现BFS队列。 

访问状态结构使用具有固定大小数组键的映射：```go
map[[2]int]bool
```数组存储的位置：```go
[node, mask]
```Go 整数就足够了，因为最大位掩码大小仅为`2^12`。

 ## 边缘情况

 ### 单节点图

 如果图表仅包含一个节点，则我们在进行任何移动之前已经访问了每个节点。 有缺陷的实现可能仍然会不必要地运行 BFS 或返回不正确的正距离。 

实现立即处理这个问题：```
if n == 1:
    return 0
```### 重新访问节点是必要的

 某些图需要重新访问先前访问过的节点才能到达剩余的未访问过的节点。 星图是一个典型的例子。 

例如：```
    1
    |
2 - 0 - 3
```要访问每个节点，我们必须重复返回节点`0`。 

错误地假设每个节点只能被访问一次的解决方案将会失败。 我们的状态表示仅跟踪节点是否至少被访问过一次，而不是是否可以重新访问。 

### 到达同一节点的多种方式

 有可能使用不同的访问节点集到达同一节点。 

例如：```
(node=2, mask=0111)
(node=2, mask=1011)
```这些是完全不同的状态，因为访问的节点集不同。 

仅通过当前顶点跟踪访问过的节点的有缺陷的实现会错误地修剪有效路径。 我们的实现存储了完整的`(node, mask)`配对，确保正确性。 

### 具有许多循环的密集图

 密集图可以产生许多重复遍历的机会。 

如果没有适当的状态重复数据删除，BFS 将重复处理相同的状态并变得非常慢。 

这`visited`集保证每个都是唯一的`(node, mask)`状态仅处理一次，防止指数重复。
