 # LeetCode 842 - 将数组拆分为斐波那契数列

 ## 问题理解

 该问题给了我们一个仅由数字组成的字符串，并要求我们将其拆分为一个类似于斐波那契数列的整数序列。 

类斐波那契数列遵循三个重要规则：

 1. 每个数字都必须位于有符号的 32 位整数内，这意味着每个值必须小于`2^31`。 
2. 该序列必须至少包含三个数字。 
3. 从第三个数字开始，每个值必须等于前两个值之和。 

例如，序列：```
[123, 456, 579]
```有效，因为：```
123 + 456 = 579
```挑战在于输入是作为单个字符串给出的，因此我们必须确定在哪里将其拆分为数字。 

该问题还引入了一个涉及前导零的重要限制。 像这样的数字`"0"`是有效的，但是`"01"`或者`"00"`作为多位数字无效。 这意味着一旦子字符串以`'0'`，该位置唯一有效的数字正是`0`。 

输入大小可以高达 200 位数字，这对于对每个可能的分区进行强力枚举来说太大了。 然而，32 位整数约束极大地限制了我们实际需要考虑的有效候选数字的数量。 自从`2^31 - 1`只有 10 位数字，每个生成的数字最多可以包含 10 位数字。 

一些边缘情况尤其重要：

 - 以零开头的字符串，例如`"0123"`。 
- 有效序列以多种形式存在的情况。 
- 超出 32 位有符号整数范围的非常大的数字。 
- 几乎形成斐波那契序列但迟到失败的输入。 
- 输入太短，无法形成有效序列。 

该问题仅保证输入包含数字，仅此而已。 

## 方法

 ### 蛮力方法

 暴力破解的思路是尝试一切可能的方法将字符串拆分为子字符串，将每个子字符串转换为整数，然后检查得到的序列是否满足斐波那契规则。 

假设字符串有长度`n`。 在每对字符之间，我们可以分裂也可以不分裂。 这大约产生`2^(n-1)`可能的分区。 

对于每个分区：

 - 将所有部分转换为整数。 
- 拒绝带有前导零的分区。 
- 拒绝溢出分区。 
- 检查斐波那契属性是否成立。 

这种方法是正确的，因为它会检查每个可能的分区，因此如果存在有效序列，它最终会找到它。 

然而，这对于`n = 200`。 分区的数量呈指数增长。 

### 最优回溯方法

 关键的观察结果是斐波那契数列受到高度约束。 

一旦我们选择了前两个数字，后面的每个数字就完全确定了。 之后就没有分支了，因为：```
next = previous1 + previous2
```因此，我们不需要到处尝试任意分区，我们只需要：

 1. 尝试第一个数字的所有可能性。 
2. 尝试第二个数字的所有可能性。 
3. 递归地验证字符串的其余部分是否与所需的总和匹配。 

这极大地减少了搜索空间。 

另一个重要的优化来自 32 位整数限制。 由于每个有效数字都必须位于带符号的 32 位范围内，因此每个数字最多可以包含 10 位数字。 这限制了分支因子。 

回溯在这里很自然地起作用，因为：

 - 我们逐步构建序列。 
- 我们立即放弃无效路径。 
- 一旦我们找到一个有效的序列，我们就会停止。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试所有可能的分区 |
 | 最优回溯| 实践中的 O(n^2) | O(n) | 前两个数字决定其余的 |

 ## 算法演练

 1. 初始化一个空序列，用于存储我们在递归过程中构建的斐波那契数。 
2.使用从索引开始的回溯`0`在字符串中。 在每次递归调用时，尝试用新数字扩展当前序列。 
3. 使用子串扩展逐位构建当前数字。 这可以避免提前生成所有子字符串。 
4. 如果当前子字符串开头为`'0'`并且包含超过一位数字，停止从该位置探索进一步的扩展。 这强制执行无前导零规则。 
5. 将子字符串转换为整数。 如果该值超过`2^31 - 1`，立即停止，因为更长的子串只会变得更大。 
6. 如果序列已包含至少两个数字：

 - 计算预期的下一个斐波那契值：```
expected = sequence[-1] + sequence[-2]
```- 如果当前数字小于预期，则继续扩展子字符串，因为我们可能需要更多数字。 
- 如果当前数字大于预期，请停止探索此分支，因为数字只会随着我们附加数字而增加。 
- 如果数字与期望值匹配，则继续递归。 
7. 将有效数字附加到序列中，并使用字符串中的下一个索引进行递归。 
8. 如果递归成功并且到达字符串末尾且至少包含三个数字，则立即返回成功。 
9. 否则，从序列中删除最后一个数字并继续探索其他可能性。 
10. 如果所有可能性均失败，则返回空列表。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的斐波那契分解都必须从第一个和第二个数字的某种选择开始。 一旦这些被修复，每个剩余的数字都由斐波那契规则唯一确定。 

回溯过程系统地探索所有可能的第一个和第二个数字，同时通过以下方式尽早修剪不可能的分支：

 - 领先的零验证，
 - 溢出检查，
 - 斐波那契总和比较。 

因此，如果存在有效序列，算法就会找到它。 如果不存在有效序列，则所有分支最终都将被拒绝。 

## Python 解决方案```python
from typing import List

class Solution:
    def splitIntoFibonacci(self, num: str) -> List[int]:
        MAX_INT = 2**31 - 1
        sequence = []

        def backtrack(index: int) -> bool:
            # Successfully consumed entire string
            if index == len(num):
                return len(sequence) >= 3

            current_number = 0

            for end in range(index, len(num)):
                # Leading zero check
                if end > index and num[index] == '0':
                    break

                current_number = (
                    current_number * 10 + int(num[end])
                )

                # 32-bit integer overflow check
                if current_number > MAX_INT:
                    break

                # Fibonacci validation
                if len(sequence) >= 2:
                    expected = sequence[-1] + sequence[-2]

                    if current_number < expected:
                        continue

                    if current_number > expected:
                        break

                # Choose
                sequence.append(current_number)

                # Explore
                if backtrack(end + 1):
                    return True

                # Undo choice
                sequence.pop()

            return False

        if backtrack(0):
            return sequence

        return []
```该实现使用递归回溯来增量地构造序列。 

这`sequence`list 存储当前正在探索的类斐波那契数字。 

递归函数`backtrack(index)`尝试从位置开始构建有效的序列`index`在字符串中。 

在递归中，我们逐位逐步构造数字，而不是重复切片子字符串。 这更有效，因为我们避免了重复的整数转换。 

前导零检查至关重要：```python
if end > index and num[index] == '0':
    break
```这确保了像这样的数字`"01"`立即被拒绝。 

溢出条件可防止无效的 32 位值进入序列。 

斐波那契验证逻辑执行积极的修剪：

 - 如果当前数字太小，我们继续扩展子字符串。 
- 如果它变得太大，我们会立即停止，因为额外的数字只会增加值。 
- 只有精确匹配才会递归进行。 

最后，回溯使用以下方法删除失败的选择`sequence.pop()`以便可以干净地探索其他可能性。 

## 解决方案```go
func splitIntoFibonacci(num string) []int {
	const MAX_INT = 1<<31 - 1

	sequence := []int{}

	var backtrack func(index int) bool

	backtrack = func(index int) bool {
		if index == len(num) {
			return len(sequence) >= 3
		}

		currentNumber := 0

		for end := index; end < len(num); end++ {

			// Leading zero check
			if end > index && num[index] == '0' {
				break
			}

			currentNumber = currentNumber*10 + int(num[end]-'0')

			// Overflow check
			if currentNumber > MAX_INT {
				break
			}

			// Fibonacci validation
			if len(sequence) >= 2 {
				expected := sequence[len(sequence)-1] +
					sequence[len(sequence)-2]

				if currentNumber < expected {
					continue
				}

				if currentNumber > expected {
					break
				}
			}

			// Choose
			sequence = append(sequence, currentNumber)

			// Explore
			if backtrack(end + 1) {
				return true
			}

			// Undo choice
			sequence = sequence[:len(sequence)-1]
		}

		return false
	}

	if backtrack(0) {
		return sequence
	}

	return []int{}
}
```Go 实现遵循与 Python 版本相同的递归结构。 

一个重要的区别是整数处理。 Go 使用显式整数运算，因此我们仔细确保值永远不会超过`2^31 - 1`。 

使用以下方法处理切片回溯：```go
sequence = sequence[:len(sequence)-1]
```与 Python 不同，Go 不区分`nil`和 LeetCode 输出中的空切片，因此返回`[]int{}`是完全可以接受的。

 ## 边缘情况

 ### 前导零

 输入如`"0123"`很棘手，因为`"01"`转换后看起来数字有效，但违反了问题规则。 

幼稚的实现可能会意外解析`"01"`作为整数`1`并错误地接受序列。 

该实现使用以下方法来防止这种情况发生：```
if end > index and num[index] == '0':
    break
```这保证了一旦数字以`'0'`，它只能包含该单个数字。 

### 整数溢出

 该问题明确将值限制为带符号的 32 位整数。 

如果没有溢出检查，很长的子字符串可能会产生大于允许的整数，从而导致不正确的结果或特定于语言的溢出行为。 

实施过程不断检查：```
if current_number > 2**31 - 1:
    break
```由于附加数字只会增加数字，因此可以立即安全地放弃该分支。 

### 多个有效答案

 某些输入可以产生多个有效的斐波那契分解。 

例如：```
"1101111"
```可以生成：```
[11,0,11,11]
```或者：```
[110,1,111]
```该问题允许返回任何有效序列。 

回溯实现自然会返回它发现的第一个有效序列，这满足了要求。
