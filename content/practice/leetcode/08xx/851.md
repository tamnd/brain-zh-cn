[LeetCode 851 题](https://leetcode.com/problems/loud-and-rich/)

 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题描述了一群人，其中一些人比其他人更富有。 这`richer`数组表示人与人之间的有向关系。 如果`richer[i] = [a, b]`, 表示人`a`肯定比人有钱`b`。 

每个人还有一个安静度分数存储在`quiet`大批。 值越小意味着人越安静。 目标是确定每个人`x`，在所有人中，哪一个人至少和`x`具有最小的安静值。 

“等于或更多的钱”这句话很重要。 每个人都被认为至少与自己一样富有，因此每个人始终是自己结果的候选答案。 

输出数组`answer`应满足：```
answer[x] = the quietest person among everyone richer than or equal to x
```这本质上是一个图问题。 更丰富的关系形成有向图：```
a -> b means a is richer than b
```由于该问题保证数据逻辑上一致，因此不存在循环。 这意味着该图是有向无环图（DAG）。 

限制相对较小：

 -`n <= 500`- 图可以很密集
 - 安静值是独一无二的

 尽管`500`虽然不是很大，但重复探索每个节点的整个图的简单解决方案仍然会变得低效。 DAG 属性强烈建议使用记忆 DFS 或拓扑图处理。 

一些边缘情况很重要：

 - 一个人可能根本就没有更富有的人
 - 的`richer`数组可能为空
 - 最安静的富人可能是图中上方的多个级别
 - 图表可能包含断开连接的组件
 - 每个人都有独特的安静值，因此永远不会发生联系

 由于图是非循环的，因此具有记忆功能的递归 DFS 可以安全地工作，而无需担心无限递归。 

## 方法

 ### 蛮力方法

 强力解决方案是为每个人独立计算所有较富有的人。 

对于每个人`x`，我们可以运行 DFS 或 BFS 向上遍历所有更丰富的关系。 在遍历过程中，我们跟踪遇到的最安静的人。 

这种方法是正确的，因为它明确地探索了每一个比他更富有的人。`x`，因此保证能够找到这些人之间的最低限度的安静。 

然而，该方法独立地从每个节点开始执行图遍历。 由于多次遍历重复访问相同的子图，存在大量的重复工作。 

在最坏的情况下，该图可能包含几乎`O(n²)`边缘。 从每个节点运行遍历大约会导致`O(n * (n + e))`复杂性，从而变得低效。 

### 最佳解决方案的关键见解

 关键的观察是，许多人共享重叠的更丰富的子图。 

假设我们已经知道节点中最安静的富人`3`。 如果另一个节点指向`3`，我们应该重用该结果而不是重新计算它。 

因为图是 DAG，所以我们可以将 DFS 与记忆结合使用：

 - 对于每个人`x`，计算一次最安静的富人
 - 存储结果
 - 再次需要时重复使用存储的答案

 这将重复的图遍历转换为 DAG 上的动态规划问题。 

递归关系为：```
answer[x] = quietest among:
- x itself
- all answers of richer neighbors
```这避免了重新计算并且仅处理每个节点和边一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × (n + e)) | O(n × (n + e)) | O(n + e) | 对每个节点运行一次新的遍历 |
 | 最佳| O(n + e) | O(n + e) | DFS 与 DAG 上的记忆化 |

 这里，`e`代表更丰富关系的数量。 

## 算法演练

 1. 构建一个有向图，其中边从穷人指向富人。 

如果`a`比`b`，那么对于人`b`我们想要访问`a`。 所以我们存储：```
b -> a
```这个方向让DFS自然而然地走向了富裕人群。 
2. 创建一个答案数组，初始化为`-1`。 

该数组有两个用途：

 - 存储每个人的最终答案
 - 充当记忆缓存

 如果`answer[x] != -1`，我们已经计算出结果`x`。 
3. 为person定义一个DFS函数`x`。 

DFS 返回富裕于或等于的所有人中最安静的人的指数`x`。 
4. 初始化答案`x`作为`x`本身。 

每个人至少和自己一样富有，所以他们永远是候选人。 
5.拜访所有较富裕的邻居`x`。 

对于每一个富有的人`r`:

 - 递归计算`dfs(r)`- 将返回的候选者的安静程度与当前最佳答案进行比较
 - 如果发现更安静的人，请更新答案
 6. 将计算结果存储在记忆数组中。 

一旦计算完成，未来的 DFS 调用可以立即返回缓存的结果。 
7. 为每个人运行 DFS`0`到`n - 1`。 

某些节点可能已经从早期的遍历中缓存起来，因此它们会立即返回。 
8. 返回完整的答案数组。 

### 为什么它有效

 该图是非循环的，因此递归 DFS 总是终止。 对于每个人`x`，DFS 恰好探索了所有富裕于或等于`x`。 递归结合了所有较富裕邻居的最佳答案，确保最小安静值通过图表向下传播。 

记忆化保证每个节点的答案只计算一次，从而消除了冗余工作，同时保持了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def loudAndRich(self, richer: List[List[int]], quiet: List[int]) -> List[int]:
        n = len(quiet)

        graph = [[] for _ in range(n)]

        for richer_person, poorer_person in richer:
            graph[poorer_person].append(richer_person)

        answer = [-1] * n

        def dfs(person: int) -> int:
            if answer[person] != -1:
                return answer[person]

            quietest_person = person

            for richer_person in graph[person]:
                candidate = dfs(richer_person)

                if quiet[candidate] < quiet[quietest_person]:
                    quietest_person = candidate

            answer[person] = quietest_person
            return quietest_person

        for person in range(n):
            dfs(person)

        return answer
```实现首先构建一个邻接表。 与输入关系相比，该图是相反的，因为我们希望在 DFS 过程中有效地从一个人转移到更富有的人。 

这`answer`数组初始化为`-1`价值观。 这充当记忆缓存。 一旦计算出一个人最安静、最富有的候选人，它就会被永久存储。 

这`dfs`函数执行核心逻辑。 如果答案已经存在，它会立即返回缓存的值。 否则，当前人被视为最初的最佳候选人。 

然后该函数递归地探索所有更丰富的邻居。 每个递归调用都会返回从该较丰富的节点可到达的最安静的人。 通过比较安静度值，该算法可以跟踪全球最安静的可联系到的人。 

最后将计算结果存入缓存并返回。 

外循环确保每个人都得到处理，包括断开连接的图形组件。 

## 解决方案```go
func loudAndRich(richer [][]int, quiet []int) []int {
	n := len(quiet)

	graph := make([][]int, n)

	for _, edge := range richer {
		richerPerson := edge[0]
		poorerPerson := edge[1]

		graph[poorerPerson] = append(graph[poorerPerson], richerPerson)
	}

	answer := make([]int, n)

	for i := 0; i < n; i++ {
		answer[i] = -1
	}

	var dfs func(int) int

	dfs = func(person int) int {
		if answer[person] != -1 {
			return answer[person]
		}

		quietestPerson := person

		for _, richerPerson := range graph[person] {
			candidate := dfs(richerPerson)

			if quiet[candidate] < quiet[quietestPerson] {
				quietestPerson = candidate
			}
		}

		answer[person] = quietestPerson
		return quietestPerson
	}

	for person := 0; person < n; person++ {
		dfs(person)
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 切片用于邻接列表和答案数组。 

与 Python 不同，Go 不提供自动初始化`-1`，因此答案数组必须显式填充`-1`。 

递归DFS是使用函数变量声明来实现的，因为Go要求在赋值之前声明递归匿名函数。 

整数溢出不是问题，因为所有值都受以下限制`500`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + e) | 每个节点和边都被处理一次 |
 | 空间| O(n + e) | 邻接表、递归堆栈和记忆数组 |

 邻接表仅将所有边存储一次，要求`O(e)`空间。 记忆数组需要`O(n)`空间。 

由于记忆化确保每个节点仅计算一次，因此 DFS 在整个执行过程中仅遍历每个边一次。 这给出了相对于图大小的线性复杂度。

        for richer_person, poorer_person in richer:
            graph[poorer_person].append(richer_person)

 ## 边缘情况

 一种重要的边缘情况发生时`richer`数组为空。 在这种情况下，没有人比其他人更富有。 因此，每个人只能与自己相比。 有缺陷的实现可能会错误地假设每个节点都有邻居，或者无法正确初始化答案。 此实现可以自然地处理这种情况，因为每个 DFS 都以人本身作为初始最佳候选者开始。 

另一个重要的例子是更丰富的关系的长传递链。 例如：```
4 > 3 > 2 > 1 > 0
```最安静的富人`0`可能比上面很多级别。 仅检查直接邻居的简单解决方案在这里会失败。 递归 DFS 正确地探索所有可触及的富人，确保包括传递关系。 

断开连接的图形组件是另一个常见的错误来源。 有些人可能属于完全独立的富裕阶层。 仅从单个节点启动 DFS 的实现可能会丢失整个组件。 该解决方案显式地为每个人运行 DFS，保证图的完全覆盖。 

最后一个微妙的情况是重叠子图。 多个人可能依赖同一个更丰富的子树。 如果没有记忆，算法将重复重新计算相同的答案，导致效率严重低下。 缓存的`answer`数组确保每个人的结果只计算一次。
