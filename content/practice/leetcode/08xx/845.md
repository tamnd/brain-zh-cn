 ## 解决方案

 ## 问题理解

 该问题要求我们找到形成有效山的最长连续子数组的长度。 

一座山是一个严格上升到顶峰，然后严格下降的序列。 峰不能是子数组的第一个或最后一个元素，因为山必须同时包含上坡部分和下坡部分。 

更正式地说，对于某些索引`i`:

 - 之前的元素`i`正在严格增加
 - 之后的元素`i`严格递减
 - 子数组长度必须至少为`3`输入是一个整数数组`arr`，输出是一个整数，表示最长山子数组的长度。 如果不存在有效的山，我们返回`0`。 

约束条件很重要：

 -`1 <= arr.length <= 10^4`-`0 <= arr[i] <= 10^4`一个`O(n^2)`经过仔细优化，解决方案可能仍会通过，但后续特别要求：

 - 一张通行证
 -`O(1)`额外的空间

 这强烈表明我们应该以线性扫描为目标。 

一些边缘情况尤其重要：

 - 数组短于`3`不能容纳一座山。 
- 平坦部分，例如`[2,2,2]`无效，因为山坡必须严格增加或减少。 
- 纯粹增加数组，例如`[1,2,3,4]`无效，因为没有血统。 
- 纯递减数组，例如`[4,3,2,1]`无效，因为没有上升。 
- 多个山峰可能重叠，因此我们必须正确识别每个候选山峰。 

## 方法

 ### 蛮力方法

 暴力解决方案检查每个可能的子数组并确定它是否形成有效的山。 

对于每个起始索引`i`和结束索引`j`，我们可以：

 1.提取子数组`arr[i:j+1]`2. 验证其严格增加到一个峰值
 3. 验证之后是否严格减少
 4.跟踪最大有效长度

 这是有效的，因为每个可能的子数组都会被检查，所以不会错过任何一座山。 

然而，检查所有子数组的成本很高。 有`O(n^2)`子数组，验证每个子数组可能需要`O(n)`时间。 这导致`O(n^3)`最坏情况下的时间复杂度。 

即使进行了优化，对于这个问题来说，暴力破解也太慢了。 

### 最佳方法

 关键的观察是一座山完全由它的峰顶决定。 

如果我们可以确定一个峰值：

 -`arr[i-1] < arr[i]`-`arr[i] > arr[i+1]`那么我们可以向外扩展：

 - 当值严格增加时向左移动
 - 当值严格递减时向右移动

 总跨度给出了山的长度。 

更好的优化是在跟踪时扫描一次数组：

 - 当前上坡序列的长度
 - 当前下坡序列的长度

 每当上坡和下坡长度均为正值时，我们就有一座有效的山。 

这是有效的，因为有效的山总是由以下部分组成：

 - 至少增加一步
 - 随后至少有一个递减步骤

 我们可以在线性时间和常数空间中计算它。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 检查每个子数组并验证山形 |
 | 最佳| O(n) | O(1) | O(1) | 单程跟踪上坡和下坡 |

 ## 算法演练

 ### 最优单遍算法

 1.初始化三个变量：

 -`up = 0`，电流增加斜率的长度
 -`down = 0`，电流下降斜率的长度
 -`longest = 0`，迄今为止发现的最佳山长
 2. 从索引开始迭代数组`1`。 
3. 在每个位置，首先确定当前的山地状态是否应该重置。 

我们在以下情况下重置：

 - 序列变得平坦，`arr[i] == arr[i-1]`- 下坡已经开始后，新的上坡开始

 无论哪种情况：

 - 设置`up = 0`- 放`down = 0`4.如果`arr[i] > arr[i-1]`，我们正在向上攀登。 

- 增量`up`5. 如果`arr[i] < arr[i-1]`，我们正在下降。 

- 增量`down`，但前提是我们已经有上坡路了
 6. 每当两者：

 -`up > 0`-`down > 0`我们有一座有效的山。 

山的长度为：```
up + down + 1
```额外的`1`占峰值元素。 
7. 更新`longest`每当发现一座更大的山时。 
8.处理完数组后，返回`longest`。 

### 为什么它有效

 该算法保持以下不变量：

 -`up`存储严格递增边的数量
 -`down`存储增加后严格减少的边数

 当两者都为正时，一座有效的山就存在。 由于每个数组元素都被处理一次，并且每个可能的山都必须包含一个递增阶段和一个递减阶段，因此该算法可以正确识别最长的山。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestMountain(self, arr: List[int]) -> int:
        n = len(arr)

        up = 0
        down = 0
        longest = 0

        for i in range(1, n):
            if (down > 0 and arr[i] > arr[i - 1]) or arr[i] == arr[i - 1]:
                up = 0
                down = 0

            if arr[i] > arr[i - 1]:
                up += 1
            elif arr[i] < arr[i - 1]:
                if up > 0:
                    down += 1

            if up > 0 and down > 0:
                longest = max(longest, up + down + 1)

        return longest
```实现直接遵循单通道策略。 

变量`up`和`down`代表当前山的增加和减少部分的长度。 这些是边的计数，而不是元素的计数，这就是为什么最终的山脉长度计算为`up + down + 1`。 

复位条件很关键。 如果我们已经在下降并遇到另一次上升，那么之前的山已经结束，新的潜在山开始了。 平坦的值也会使山脉结构失效，因为需要严格的不平等。 

每当两者`up`和`down`是积极的，我们知道我们目前有一座有效的山，所以我们更新答案。 

## 解决方案```go
func longestMountain(arr []int) int {
	n := len(arr)

	up := 0
	down := 0
	longest := 0

	for i := 1; i < n; i++ {

		if (down > 0 && arr[i] > arr[i-1]) || arr[i] == arr[i-1] {
			up = 0
			down = 0
		}

		if arr[i] > arr[i-1] {
			up++
		} else if arr[i] < arr[i-1] {
			if up > 0 {
				down++
			}
		}

		if up > 0 && down > 0 {
			length := up + down + 1
			if length > longest {
				longest = length
			}
		}
	}

	return longest
}
```Go 实现密切反映了 Python 逻辑。 

Go 在这里不需要对空切片进行特殊处理，因为循环自然会处理长度小于的数组`2`。 整数溢出不是问题，因为最大数组长度仅为`10^4`。 

该实现使用普通整数变量和常量额外内存。

 ## 边缘情况

 一种重要的边缘情况是包含平坦部分的数组，例如`[2,2,2]`或者`[1,2,2,1]`。 山脉需要严格的不平等，因此相等的相邻值会立即使当前序列无效。 一个常见的错误是意外地将非递减或非递增序列视为有效山。 该实现通过在遇到相等值时重置两个计数器来避免这种情况。 

另一个重要的边缘情况是仅增加或仅减少的序列。 数组如`[1,2,3,4]`或者`[4,3,2,1]`不包含有效的山脉，因为需要上升和下降。 该实现正确地处理了这个问题，因为只有当两个`up > 0`和`down > 0`。 

第三个棘手的情况是重叠的山脉。 考虑`[1,2,1,2,3,2,1]`。 当算法完成从一座山的下降并遇到另一座不断增加的坡度时，它必须正确重置并开始跟踪一座新山。 复位条件：```
if (down > 0 and arr[i] > arr[i - 1]) or arr[i] == arr[i - 1]:
```确保新的山脉从正确的点开始，而不会延续上一次下降的陈旧状态。
