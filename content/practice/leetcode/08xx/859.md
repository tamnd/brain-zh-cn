[LeetCode 第 859 题](https://leetcode.com/problems/buddy-strings/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题询问是否可以通过对第一个字符串执行一次交换操作来使两个字符串相等`s`。 

交换操作意味着选择两个不同的指数`i`和`j`在`s`并交换这些位置处的字符。 执行单次交换后，结果字符串必须匹配`goal`。 

输入由两个小写字符串组成：

 -`s`，我们可以修改的字符串
 -`goal`，我们要获取的目标字符串

 输出是一个布尔值：

 -`true`如果正好有一个有效的交换`s`可以使其等于`goal`-`false`否则

 一个非常重要的细节是互换必须涉及两个不同的指数。 不允许将字符与其自身交换。 

约束告诉我们字符串长度可以大到`2 * 10^4`，因此解决方案必须是有效的。 二次或三次强力方法可能会变得太慢。 由于字符串仅包含小写英文字母，因此我们可以在需要时利用较小的字母大小。 

有几个重要的边缘情况：

 如果字符串的长度不同，则答案立即`false`因为没有交换可以改变字符串的长度。 

如果字符串已经相等，则不会自动得出答案`true`。 由于我们仍然必须在两个不同索引之间执行交换，因此只有在至少有一个重复字符的情况下，字符串才能保持不变。 例如：

-`"aa"`可以交换两个`'a'`字符并保留`"aa"`-`"ab"`变成`"ba"`交换后，所以它不能留下来`"ab"`当字符串的位置有两个以上不同时，就会出现另一个重要的情况。 一次交换最多可以修复两个不匹配的位置，因此任何较大的不匹配计数都会立即得出答案`false`。 

## 方法

 ### 蛮力方法

 蛮力的想法是尝试每一个可能的索引对`s`，执行交换，并检查结果字符串是否等于`goal`。 

对于一个长度的字符串`n`，大约有`n^2`可能的互换。 对于每次交换，构造新字符串并将其与`goal`需要`O(n)`时间。 

这保证了正确性，因为每个可能的合法交换都经过测试。 如果有任何交换产生`goal`，我们返回`true`。 

然而，总复杂度变为`O(n^3)`最坏的情况：

 -`O(n^2)`掉期
 -`O(n)`每次交换的工作量

 与`n`最多`20,000`，这太慢了。 

### 最佳方法

 关键的观察是一次交换仅影响两个头寸。 

这意味着：

 - 如果`s`和`goal`两个以上的位置不同，一次交换无法修复它们。 
- 如果它们恰好有两个位置不同，则这些不匹配必须完全交叉匹配。 
- 如果它们在零位置上不同，我们需要至少一个重复字符，以便可以在不更改字符串的情况下进行交换。 

我们不需要尝试所有交换，只需检查两个字符串之间的不匹配位置。 

这将问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 尝试所有可能的交换并重建字符串 |
 | 最佳| O(n) | O(1) | O(1) | 跟踪不匹配的位置和重复的字符 |

 ## 算法演练

 1.首先检查长度是否`s`和`goal`是不同的。 如果是，则返回`false`立即，因为交换字符不能改变字符串长度。 
2. 逐个字符比较两个字符串，并记录所有不同的位置。 将这些不匹配项存储在列表中。 
3. 如果有两个以上不匹配，则返回`false`。 一次交换只能纠正两个位置。 
4. 如果正好有两个不匹配，假设不匹配对是：

 -`(s[i], goal[i])`-`(s[j], goal[j])`仅当满足以下条件时，单次交换才有效：

 -`s[i] == goal[j]`-`s[j] == goal[i]`这意味着交换后不匹配可以完美交叉匹配。 
5. 如果有零个不匹配，则字符串已经相等。 在这种情况下，我们必须确定交换是否可以使字符串保持不变。 

仅当某个字符至少出现两次时才有可能。 我们可以通过检查是否有任何字符重复来检测这一点`s`。 
6. 如果以上条件均不成立，则返回`false`。 

### 为什么它有效

 交换仅交换两个字符，因此它只能修改字符串中的两个位置。 因此：

 - 两个以上的不匹配永远无法修复。 
- 仅当交换这两个字符同时解决两个位置时，才可以修复恰好两个不匹配。 
- 零不匹配需要重复字符，因为交换仍然必须发生在不同索引之间。 

这些条件完全表征了所有有效的解决方案。 

## Python 解决方案```python
class Solution:
    def buddyStrings(self, s: str, goal: str) -> bool:
        if len(s) != len(goal):
            return False

        mismatches = []

        for i in range(len(s)):
            if s[i] != goal[i]:
                mismatches.append(i)

        if len(mismatches) == 2:
            i, j = mismatches
            return s[i] == goal[j] and s[j] == goal[i]

        if len(mismatches) == 0:
            seen = set()

            for ch in s:
                if ch in seen:
                    return True
                seen.add(ch)

        return False
```实现从长度检查开始，因为不相等的长度会使转换变得不可能。 

接下来，代码同时扫描两个字符串并记录字符不同的每个索引。 该不匹配列表是算法的核心信息。 

如果恰好存在两个不匹配，则代码将验证交叉匹配条件。 交换这两个位置的字符`s`应该产生相应的字符`goal`。 

如果没有不匹配，则字符串已经相等。 然后，代码使用集合检查重复字符。 如果存在重复，则交换两个相同的字符不会使字符串保持不变，这满足了问题要求。 

最后，所有其他情况返回`False`。 

## 解决方案```go
func buddyStrings(s string, goal string) bool {
    if len(s) != len(goal) {
        return false
    }

    mismatches := []int{}

    for i := 0; i < len(s); i++ {
        if s[i] != goal[i] {
            mismatches = append(mismatches, i)
        }
    }

    if len(mismatches) == 2 {
        i := mismatches[0]
        j := mismatches[1]

        return s[i] == goal[j] && s[j] == goal[i]
    }

    if len(mismatches) == 0 {
        seen := make(map[byte]bool)

        for i := 0; i < len(s); i++ {
            if seen[s[i]] {
                return true
            }
            seen[s[i]] = true
        }
    }

    return false
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个小的区别是使用`map[byte]bool`而不是用于重复检测的 Python 集。 由于输入仅包含小写英文字母，因此使用字节既高效又简单。 

Go 字符串是字节索引的，因此可以使用以下方式访问字符`s[i]`对于小写 ASCII 输入可以正常工作。

 ## 边缘情况

 当字符串已经相等时，就会出现一种重要的边缘情况。 许多不正确的实现立即返回`true`在这种情况下。 然而，该问题需要在两个不同的索引之间进行交换。 如果每个字符都是唯一的，则任何交换都会更改字符串。 该实现通过在返回之前检查重复字符来正确处理此问题`true`。 

另一种棘手的情况是字符串仅在一个位置不同。 一次交换总是同时改变两个位置，因此永远无法修复一个不匹配的情况。 该算法自然会处理这个问题，因为它只接受恰好零个或恰好两个不匹配。 

第三个重要的边缘情况是字符串在两个以上位置不同时。 一些幼稚的解决方案可能会在心里尝试多次修复，但只允许一次交换。 由于交换恰好影响两个索引，因此超过两个不匹配会使转换变得不可能。 实施立即拒绝此类输入。 

一个微妙的情况涉及两个未正确交叉匹配的不匹配。 例如：```
s = "ab"
goal = "cd"
```有两个不匹配，但是交换`'a'`和`'b'`无法创建`'c'`和`'d'`。 该实现验证确切的交叉匹配条件以确保正确性。 

最后，单字符字符串需要特别注意。 由于交换需要两个不同的索引，因此长度为 1 的字符串永远无法执行有效的交换。 该实现自然地处理了这个问题，因为不能有重复的字符，也不能有有效的不匹配索引对。
