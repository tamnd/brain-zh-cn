[LeetCode 807 题](https://leetcode.com/problems/max-increase-to-keep-city-skyline/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`n x n`网格，其中每个单元格代表城市中建筑物的高度。 可以从北、南、东、西四个方向观看这座城市。 从这些角度来看，天际线是由每行或每列中可见的最高建筑物决定的。 

当从西边或东边观察城市时，一行的天际线只是该行中的最大值。 同样，当从北或南查看时，列的天际线是该列中的最大值。 

我们可以增加建筑高度，但不可以改变任何天际线。 这意味着：

 - 每行的最大值必须保持不变。 
- 每列中的最大值必须保持不变。 

我们的目标是最大化建筑物高度增加的总量，同时保留所有行和列的最大值。 

输入包括：

 - 方阵`grid`-`grid[r][c]`表示该行建筑物的高度`r`和列`c`输出是：

 - 代表所有建筑物最大总增量的单个整数

 限制相对较小：

 -`2 <= n <= 50`-`0 <= grid[r][c] <= 100`由于网格最多`50 x 50`，甚至一个`O(n^3)`解决方案是可以接受的。 这告诉我们，我们不需要先进的优化技术，但我们仍然应该以干净高效的解决方案为目标。 

一些边缘情况很重要：

 - 充满零的网格。 不可能增加任何数量，因为任何增加都会改变天际线。 
- 多个单元格已共享最大高度的行或列。 
- 非常小的网格，例如`2 x 2`。 
- 已达到最大允许高度的建筑物。 

该问题保证网格是正方形且非空的，因此我们不需要处理格式错误的输入。 

## 方法

 ### 蛮力方法

 一种强力解决方案将独立检查每座建筑物，并尝试一次增加一个单位的高度，直到天际线发生变化。 

对于每个单元格：

 1. 暂时增加高度。 
2. 重新计算所有行和列天际线。 
3. 检查天际线是否发生变化。 
4、继续增加，直至增加无效。 

这种方法是正确的，因为它在保留天际线约束的同时明确验证了每种可能的增加。 然而，它的效率很低，因为每次尝试增加都需要重复重新计算行和列的最大值。 

如果建筑物高度可以增长到 100 左右，并且我们每次都重新计算天际线，则运行时间会变得不必要的大。 

### 关键见解

 天际线约束立即告诉我们每座建筑物允许的最大高度。 

对于位于位置的建筑物`(r, c)`:

 - 行天际线是行中的最大值`r`- 列天际线是列中的最大值`c`为了保护这两条天际线，建筑物不能超过任何一个限制。 

因此，最大有效高度为：```
min(rowMax[r], colMax[c])
```建筑物的增量变为：```
min(rowMax[r], colMax[c]) - grid[r][c]
```我们只需计算每个单元格的该值并对增量求和。 

这一观察结果将问题转化为简单的矩阵遍历。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^4) 或更糟 | O(1) | O(1) | 反复增加单元并重新计算天际线 |
 | 最佳 | O(n^2) | O(n^2) | O(n) | 预先计算行和列的最大值 |

 ## 算法演练

 1. 计算每一行的最大值。 

我们创建一个数组`row_max`在哪里`row_max[r]`存储行中最高的建筑物`r`。 这些值定义了从东或西观看时的天际线。 
2. 计算每列的最大值。 

我们创建另一个数组`col_max`在哪里`col_max[c]`将最高的建筑物存储在列中`c`。 这些值定义了从北或南观看时的天际线。 
3. 遍历网格中的每个单元格。 

对于每个建筑物`(r, c)`，确定在不改变任何天际线的情况下可以安全达到的最高高度。 
4. 计算允许的最大高度。 

建筑物不能超过行最大值或列最大值，因此其限制为：```
min(row_max[r], col_max[c])
```5. 计算当前建筑物的增量。 

增加量为：```
allowed_height - current_height
```由于允许的高度始终至少为当前高度，因此该值永远不会为负。 
6. 将增加的部分添加到总答案中。 

对所有单元格重复此操作。 
7. 返回增量总和。 

### 为什么它有效

 行的天际线仅取决于行最大值，列的天际线仅取决于列最大值。 通过限制每座建筑物最多`min(rowMax[r], colMax[c])`，我们保证行或列的最大值不会增加。 同时，为每座建筑物选择这个最大可能值可确保总增量尽可能大。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxIncreaseKeepingSkyline(self, grid: List[List[int]]) -> int:
        n = len(grid)

        row_max = [max(row) for row in grid]

        col_max = [
            max(grid[r][c] for r in range(n))
            for c in range(n)
        ]

        total_increase = 0

        for r in range(n):
            for c in range(n):
                allowed_height = min(row_max[r], col_max[c])
                total_increase += allowed_height - grid[r][c]

        return total_increase
```该实现首先使用列表理解计算每行的最大建筑物高度。 这些值代表行天际线。 

接下来，它计算每列的最大高度。 由于 Python 按行存储网格，因此我们迭代每个列索引的所有行。 

预处理完天际线限制后，我们再次遍历网格。 对于每座建筑物，我们使用行和列限制的最小值来计算最大安全高度。 

该允许高度与当前高度之间的差值就是建筑物可以增长的量。 我们将这些增量累积成`total_increase`。 

最后，我们返回总数。 

## 解决方案```go
func maxIncreaseKeepingSkyline(grid [][]int) int {
	n := len(grid)

	rowMax := make([]int, n)
	colMax := make([]int, n)

	for r := 0; r < n; r++ {
		for c := 0; c < n; c++ {
			if grid[r][c] > rowMax[r] {
				rowMax[r] = grid[r][c]
			}

			if grid[r][c] > colMax[c] {
				colMax[c] = grid[r][c]
			}
		}
	}

	totalIncrease := 0

	for r := 0; r < n; r++ {
		for c := 0; c < n; c++ {
			allowedHeight := rowMax[r]
			if colMax[c] < allowedHeight {
				allowedHeight = colMax[c]
			}

			totalIncrease += allowedHeight - grid[r][c]
		}
	}

	return totalIncrease
}
```Go 实现遵循与 Python 版本相同的逻辑。 而不是使用像这样的内置函数`max()`和`min()`，我们手动比较整数。 

Go 切片会自动用零值初始化，这可以正常工作，因为建筑物高度是非负的。 

整数溢出不是问题，因为最大总增量很小：

 - 每个单元格的最大增加量最多为 100
 - 最大细胞数为`50 * 50 = 2500`- 最大总数约为`250000`这很容易适合 Go 的`int`类型。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n^2) | O(n^2) | 我们遍历网格固定次数 |
 | 空间| O(n) | 我们存储行和列最大数组 |

 该算法在网格上执行三个主要遍历：

 1. 计算行最大值
 2. 计算列最大值
 3. 计算总增量

 每次通过都会接触每个单元一次，从而导致`O(n^2)`时间复杂度。 

The only extra memory used is two arrays of size`n`, 给予`O(n)`辅助空间复杂度。

 ## 边缘情况

 一个重要的边缘情况是网格完全充满零。 在这种情况下，每行天际线和列天际线都为零。 增加任何建筑物都会立即改变天际线，因此正确答案是零。 有缺陷的实现可能会错误地假设零高度建筑物总是会增加。 

另一个重要的情况是当一行或一列中的每个建筑物都已经等于天际线最大值时。 在这些情况下，不允许增加这些建筑物。 该实现自然地处理了这个问题，因为：```
allowed_height - current_height = 0
```当建筑物更多地受到其列天际线的限制而不是其行天际线的限制时，就会出现第三种重要的边缘情况，反之亦然。 例如：```
[
    [1,10],
    [5,2]
]
```该建筑位于`(1,1)`无法增长到 10，因为列最大值仅为 10，而行最大值为 5。使用两个限制中的最小值可确保两条天际线保持不变。 

最后，非常小的网格，例如`2 x 2`可能会暴露索引错误或关于维度的错误假设。 由于实施始终使用`n = len(grid)`并仔细迭代行和列，这些情况都得到正确处理。
