[LeetCode 822 题](https://leetcode.com/problems/card-flipping-game/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到了一组卡片，其中每张卡片都有两个数字，一个在正面，一个在背面。 最初，每张卡片的正面朝上放置。 我们可以翻转任何卡片子集，包括不翻转任何卡片或翻转全部卡片。 选择每张卡片的最终方向后，我们想要确定一个**好的整数**。 

如果一个数字同时满足两个条件，则该数字被认为是**好**。 首先，数字必须**面朝下**出现在至少一张卡片上。 其次，相同的数字**不能正面朝上出现在任何卡片上**。 在所有这些有效数字中，我们必须返回**最小的可能**。 如果无论我们如何翻牌都没有数字可以满足这些条件，我们返回`0`。 

输入由两个整数数组组成，`fronts`和`backs`， 在哪里`fronts[i]`代表当前显示在前面的数字`i-th`卡和`backs[i]`代表打印在反面的数字。 这些卡片的索引来自`0`到`n - 1`。 

限制相对较小。 我们知道`n ≤ 1000`，每张卡的值介于`1`和`2000`。 这告诉我们，即使二次解也可能是可行的，但我们仍然应该以一种干净、高效的方法为目标。 

最重要的观察涉及卡片，其中`fronts[i] == backs[i]`。 这些数字是有问题的，因为无论卡片如何翻转，相同的数字总是在一侧可见。 因此，这些值永远不可能成为好的整数，因为它们保证在某个地方面朝上。 

一些边缘情况值得关注。 一张正面和背面值相同的卡片会立即迫使答案`0`，因为数字永远不会从可见侧消失。 另一种棘手的情况是，所有候选号码都无效，因为它们出现在相同的正反面卡片上。 我们还必须处理翻转卡片创建多个有效候选者的情况，并确保我们返回最少的一个。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的翻转配置。 由于每张卡可以保持原样或翻转，因此有`2^n`可能的状态。 

对于每种配置，我们都会确定哪些数字朝上，哪些数字朝下。 然后，我们将识别所有面朝下但从未面朝上出现的数字，选择最小的数字，并将其与所有配置中的全局最小值进行比较。 

这种方法是正确的，因为它明确地评估了纸牌的每一种合法排列。 然而，它很快在计算上变得不可行。 即使只有`n = 30`，已经有超过十亿种可能的状态。 自从`n`可以大到`1000`，穷举搜索是不可能的。 

### 最佳方法

 关键的见解是识别哪些数字**永久无效**。 

如果一张卡的两面数字相同，例如`[4,4]`，那么无论我们是否翻转卡片，数字`4`将始终在该卡上可见。 所以，`4`永远不可能是一个好的整数，因为要求之一是该数字不能在任何地方面朝上出现。 

我们首先将所有这些永久无效的数字收集到一个名为的集合中`banned`。 

识别出无效数字后，我们检查两个中出现的每个数字`fronts`和`backs`。 任何**未被禁止**的数字都有可能成为一个好的整数。 由于我们只需要最小的有效数字，因此我们只需跟踪最小的候选者。 

这是有效的，因为对于任何非禁止的号码，我们总是可以以某种方式定位卡片，防止它面朝上出现，同时仍然允许它面朝下存在于某处。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 枚举每个翻转配置 |
 | 最佳 | O(n) | O(n) | 使用一组永久无效的数字 |

 ## 算法演练

 1. 创建一个名为`banned`存储永远无法成为好整数的数字。 
2. 遍历所有卡一次。 如果`fronts[i] == backs[i]`，将该数字添加到`banned`。 这样做是因为无论卡片如何翻转，这些数字始终可见。 
3. 初始化变量`minimum_good`具有非常大的值，例如无穷大。 
4. 遍历两者中的每个数字`fronts`和`backs`。 
5. 对于每个数字，检查它是否缺席`banned`。 如果有效则更新`minimum_good`具有较小的值。 
6. 处理完所有数字后，检查是否`minimum_good`已更新。 如果没有，则返回`0`因为不存在好的整数。 
7. 否则，返回最小的有效数字。 

### 为什么它有效

 核心不变量是，出现在卡片上且正面和背面值相同的任何数字永远不会从可见面隐藏。 因此，此类号码将被永久取消资格。 

对于不在禁止组中的任何数字，我们始终可以选择卡片的方向，以便该数字仅出现在至少一张卡片的隐藏侧，而不会出现在可见侧。 由于我们检查所有可能的候选值并返回最小的有效值，因此该算法始终会生成正确的最小好整数。 

## Python 解决方案```python
from typing import List

class Solution:
    def flipgame(self, fronts: List[int], backs: List[int]) -> int:
        banned = set()

        for front, back in zip(fronts, backs):
            if front == back:
                banned.add(front)

        minimum_good = float("inf")

        for number in fronts:
            if number not in banned:
                minimum_good = min(minimum_good, number)

        for number in backs:
            if number not in banned:
                minimum_good = min(minimum_good, number)

        return 0 if minimum_good == float("inf") else minimum_good
```实现首先构建`banned`放。 我们使用以下方法迭代相应的前值和后值`zip(fronts, backs)`。 每当卡片的两面都包含相同的数字时，我们就会将其添加到集合中，因为该数字永远无法隐藏。 

接下来，我们搜索最小的候选数。 我们遍历两个数组并忽略任何禁止的值。 如果数字有效，我们会将其与当前最小值进行比较。 

最后，如果没有找到有效的数字，答案仍然是无穷大，我们返回`0`。 否则，我们返回发现的最小候选者。 

## 解决方案```go
func flipgame(fronts []int, backs []int) int {
	banned := make(map[int]bool)

	for i := 0; i < len(fronts); i++ {
		if fronts[i] == backs[i] {
			banned[fronts[i]] = true
		}
	}

	const INF = int(1e9)
	minimumGood := INF

	for _, number := range fronts {
		if !banned[number] && number < minimumGood {
			minimumGood = number
		}
	}

	for _, number := range backs {
		if !banned[number] && number < minimumGood {
			minimumGood = number
		}
	}

	if minimumGood == INF {
		return 0
	}

	return minimumGood
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有内置的集合类型，我们使用`map[int]bool`模拟禁止号码的哈希集。 

而不是Python的`float("inf")`，我们使用一个大的哨兵整数值（`1e9`) 因为所有卡牌的面值最多为`2000`。 这安全地代表了一个不可能的上限。 

不需要对整数溢出进行特殊处理，因为相对于 Go 的整数限制，值仍然非常小。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 我们遍历数组固定次数 |
 | 空间| O(n) | 禁止组最多可存储`n`独特的号码|

 该算法仅对输入数组执行线性扫描。 构建被禁止的场景需要`O(n)`，并且扫描两个数组以查找最小候选也需要`O(n)`。 由于哈希集查找是`O(1)`平均而言，整体运行时间保持线性。 

额外的内存来自禁止的集合。 在最坏的情况下，每张卡都可能贡献一个唯一的禁号，从而导致`O(n)`额外的空间。

 ## 边缘情况

 当一张卡的两面具有相同的值时，就会出现一种重要的边缘情况。 例如，`[4,4]`表示数字`4`永远不会被隐藏，因为翻转卡片不会改变任何事情。 天真的实现可能会错误地对待`4`有效，但我们的算法明确地将这些值放在`banned`放。 

当所有可能的号码都被禁止时，就会发生另一个棘手的情况。 考虑`fronts = [2,2]`和`backs = [2,2]`。 自从`2`总是可见的，不存在好的整数。 我们的实现通过离开来正确处理这个问题`minimum_good`不变并返回`0`。 

当最小有效数字仅出现在卡片背面时，就会出现第三种边缘情况。 例如，`fronts = [3,5,7]`和`backs = [2,4,6]`应该返回`2`。 仅检查前面值的有缺陷的解决方案将在这里失败。 我们的实现扫描两个数组，确保考虑所有有效的候选者。
