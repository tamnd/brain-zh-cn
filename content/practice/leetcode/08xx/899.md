 # LeetCode 899 - 有序队列

 ## 问题理解

 这个问题给了我们一个字符串`s`和一个整数`k`。 我们可以重复执行一项操作：

 - 选择第一个中的一个`k`字符串的字符。 
- 从当前位置删除该字符。 
- 将其附加到字符串的末尾。 

我们的目标是确定执行此操作任意次后可以生成的按字典顺序排列的最小字符串。 

按字典顺序排列较小的字符串是按字典顺序出现较早的字符串。 例如：

-`"abc"`小于`"acb"`-`"aaabc"`小于`"aacab"`输入包括：

 - 小写英文字符串`s`- 一个整数`k`限制条件是：

 -`1 <= k <= s.length <= 1000`- 字符串仅包含小写英文字母

 小输入尺寸表明即使`O(n^2)`解决方案是可以接受的，但是对所有可能状态的指数探索仍然太慢。 

关键的困难是理解允许的操作如何根据值的变化而变化`k`。 

什么时候`k = 1`，我们只能将第一个字符移到最后。 这意味着每个操作都只是字符串的旋转。 

什么时候`k > 1`，行为发生巨大变化。 访问多个前导字符可以提供足够的自由来将字符串重新排列成任何排列。 这意味着按字典顺序排列的最小可能结果就是排序后的字符串。 

一些边缘情况很重要：

 - 单字符字符串应返回自身。 
- 具有重复字符的字符串需要仔细的字典顺序比较。 
- 什么时候`k = 1`，我们必须只考虑旋转，而不是任意重新排列。 
- 当字符串已经最小时，算法应该正确地将其返回不变。 

## 方法

 ### 蛮力方法

 暴力解决方案会将问题视为对所有可到达字符串的图形搜索。 

从初始字符串开始，我们可以通过选择每个第一个状态来生成每个可能的下一个状态`k`字符并将其移动到最后。 使用 BFS 或 DFS，我们可以探索所有可到达的配置，同时跟踪遇到的最小字典字符串。 

这种方法是正确的，因为它显式枚举了每个可到达的状态。 

然而，这在计算上是不可行的。 一个长度的字符串`n`最多可以有`n!`排列。 尽管并非所有排列都可以达到每个`k`，状态空间呈爆炸式增长。 和`n <= 1000`，穷举探索是不可能的。 

### 关键见解

 关键的观察是，问题的表现完全不同，具体取决于是否`k`等于`1`或大于`1`。 

什么时候`k = 1`，唯一允许的移动是获取第一个字符并将其附加到末尾。 重复此操作只会生成字符串的所有循环旋转，而不会生成其他内容。 

例如：```
"cba"
-> "bac"
-> "acb"
-> "cba"
```所以对于`k = 1`，答案就是弦的最小旋转。 

什么时候`k > 1`，我们获得了更大的灵活性。 事实上，我们可以模拟相邻交换并最终生成字符串的任意排列。 由于任何排列都是可到达的，因此字典顺序上最小的可能排列是完全排序的字符串。 

这将问题转化为：

 -`k = 1`：求最小旋转
 -`k > 1`：返回排序后的字符

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 探索所有可到达的字符串状态 |
 | 最佳 | 当 k=1 时为 O(n²)，当 k>1 时为 O(n log n) | O(n) | 使用旋转属性或排序洞察力 |

 ## 算法演练

 ### 案例 1：`k == 1`什么时候`k`等于`1`，每个操作都会将第一个字符移动到末尾。 这意味着我们只能产生原始字符串的旋转。 

要查找字典顺序最小的结果：

 1. 将答案初始化为原始字符串。 
2. 生成每一个可能的旋转。 
3. 将每次旋转与当前最佳答案进行比较。 
4. 每当发现较小的旋转时更新答案。 
5. 返回最小的旋转。 

对于一个长度的字符串`n`，正好有`n`不同的旋转。 

### 案例 2：`k > 1`什么时候`k`大于`1`，我们可以自由地重新排列字符。 

重要的观察是，通过访问至少两个主要角色，我们可以通过重复操作有效地执行相邻交换。 由于相邻交换可以生成任何排列，因此字符的每个排序都是可以实现的。 

要获取按字典顺序排列的最小可能字符串：

 1. 将字符串转换为字符列表。 
2. 按升序对字符进行排序。 
3. 将它们重新连接成字符串。 
4. 返回结果。 

### 为什么它有效

 对于`k = 1`，该操作保留了字符的循环顺序，因此只能进行旋转。 因此，最小可达串一定是最小旋转。 

为了`k > 1`，操作集足够强大，可以模拟任意排列。 由于字符串的字典顺序最小排列是其排序顺序，因此排序会产生最佳答案。 

## Python 解决方案```python
class Solution:
    def orderlyQueue(self, s: str, k: int) -> str:
        if k == 1:
            smallest = s
            n = len(s)

            for i in range(1, n):
                rotation = s[i:] + s[:i]
                if rotation < smallest:
                    smallest = rotation

            return smallest

        return "".join(sorted(s))
```实施首先检查是否`k`等于`1`。 

在这种特殊情况下，代码会枚举字符串的每次旋转。 通过在索引处分割字符串来形成旋转`i`并交换两半：```python
s[i:] + s[:i]
```每个生成的旋转都会按字典顺序与当前最佳答案进行比较。 

如果`k`大于`1`，该实现立即返回字符串的排序版本，因为所有排列都是可达的。 

使用Python的内置`sorted()`function 使实现简洁高效。 

## 解决方案```go
package main

import (
	"sort"
)

func orderlyQueue(s string, k int) string {
	if k == 1 {
		smallest := s
		n := len(s)

		for i := 1; i < n; i++ {
			rotation := s[i:] + s[:i]

			if rotation < smallest {
				smallest = rotation
			}
		}

		return smallest
	}

	chars := []byte(s)
	sort.Slice(chars, func(i, j int) bool {
		return chars[i] < chars[j]
	})

	return string(chars)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

为了`k == 1`，它使用字符串切片生成每次旋转并跟踪字典顺序最小的结果。 

为了`k > 1`，字符串被转换为字节切片，以便可以使用它就地排序`sort.Slice`。 

由于输入仅包含小写英文字母，因此基于字节的排序是完全安全且高效的。

 ## 边缘情况

 一种重要的边缘情况是单字符字符串。 由于只有一种可能的排列，因此旋转逻辑和排序逻辑都应返回原始字符串不变。 该实现自然地处理了这个问题，因为旋转循环执行零次迭代，并且对单字符字符串进行排序不会改变任何内容。 

另一个重要的情况是重复字符。 当许多前缀相同时，词典比较可能会变得很棘手。 例如，`"baaca"`包含多个`'a'`人物。 该实现正确地依赖于标准字符串比较操作，该操作按顺序比较字符直到发现差异。 

第三个重要的边缘情况发生在以下情况：`k = 1`。 一个常见的错误是假设任何排列都是可达的。 这是不正确的，因为该操作仅产生循环旋转。 该实现显式地分离了这种情况并仅检查有效的轮换。 

第四种微妙的情况是原始字符串已经是最小的可能结果。 例如，`"abc"`和`k = 1`已经代表最小旋转。 该实现使用原始字符串初始化答案，确保在不存在更小的旋转的情况下它保持不变。
