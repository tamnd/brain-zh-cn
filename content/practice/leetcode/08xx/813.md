[LeetCode 813 题](https://leetcode.com/problems/largest-sum-of-averages/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 我们最多可以将数组分成`k`连续的、非空的子数组。 对于每个子数组，我们计算其平均值，然后将所有这些平均值相加。 我们的目标是最大化总分。 

重要的细节是分区必须相邻并且必须覆盖整个阵列。 我们不能跳过元素、重新排序值或创建空组。 每个元素必须恰好属于一个分区。 

例如，如果：```
nums = [9,1,2,3,9]
k = 3
```一种有效的分区是：```
[9] [1,2,3] [9]
```分数变为：```
9 + (1+2+3)/3 + 9 = 20
```该问题要求我们在所有有效分区中找到最大可能的分数。 

限制相对较小：

 -`1 <= nums.length <= 100`-`1 <= nums[i] <= 10^4`-`1 <= k <= nums.length`由于数组大小仅为 100，这强烈表明多项式时间动态规划解决方案是合适的。 指数暴力搜索仍然太慢，因为可能的分区数量快速增长。 

一些边缘情况很重要：

 - 当`k = 1`，我们根本无法分区，所以答案只是整个数组的平均值。 
- 什么时候`k = nums.length`，每个元素都可以成为自己的子数组。 由于单个元素的平均值是元素本身，因此答案变为所有元素的总和。 
- 具有重复值的数组可以产生许多等效的分区。 
- 长度为 1 的小数组必须仍能正常工作。 
- 由于平均值是小数，因此我们必须小心使用浮点运算。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试一切可能的方法将数组划分为最多`k`组。 

在每个索引处，我们可以继续当前子数组或开始一个新分区。 分区完成后，我们计算每个分段的平均值并跟踪最大分数。 

这种方法是正确的，因为它探索了所有可能的有效分区，保证最终找到最佳答案。 

然而，可能的分区数量随着数组的大小呈指数增长。 即使只有 100 个元素，这在计算上也是不可行的。 

此外，除非使用前缀和，否则重复计算子数组平均值会引入不必要的重复工作。 

### 动态规划洞察

 关键的观察结果是该问题具有最优子结构。 

假设我们决定最后一个分区从索引开始`j`并以索引结束`i`。 然后：

 - 最后一个分区贡献的分数是平均值`nums[j:i+1]`- 之前的一切`j`必须已经被最佳地划分为更少的组

 这自然会导致动态规划。 

我们定义：```
dp[p][i]
```作为通过划分第一个可获得的最大分数`i`元素精确地`p`组。 

过渡：```
dp[p][i] = max(
    dp[p-1][j] + average(nums[j:i])
)
```对于所有有效的`j`。 

为了有效地计算平均值，我们使用前缀和数组。 

这将复杂性从指数时间降低到多项式时间。

 ## 算法演练

 1. 创建一个前缀和数组，以便可以在恒定时间内计算任何子数组和。 

我们定义：```
prefix[i]
```作为第一个的总和`i`元素。 

那么总和`nums[l:r]`变成：```
prefix[r] - prefix[l]
```这使我们能够在 DP 转换期间有效地计算平均值。 
2. 定义DP状态。 

让：```
dp[p][i]
```表示划分第一组可获得的最大分数`i`元素精确地`p`组。 

这里：

-`p`范围从`1`到`k`-`i`范围从`1`到`n`3. 初始化基本情况。 

当只有一个分区时：```
dp[1][i] = average(nums[0:i])
```由于整个前缀必须属于一个组。 
4. 填充额外分区的 DP 表。 

对于每个分区数`p`从`2`到`k`:

 - 考虑每个结束位置`i`- 尝试每一个可能的起点`j`对于最后一个分区

 递归变为：```
dp[p][i] = max(
    dp[p-1][j] + average(nums[j:i])
)
```5. 使用前缀和计算子数组平均值。 

平均数为`nums[j:i]`是：```
(prefix[i] - prefix[j]) / (i - j)
```这避免了重复地重新计算总和。 
6. 返回最终答案。 

因为我们最多可能会用到`k`分区，最佳解决方案将始终受益于额外的分区，因为所有数字都是正数。 

所以：```
dp[k][n]
```是最终的答案。 

### 为什么它有效

 该算法之所以有效，是因为每个最佳划分都可以分解为两部分：

 - 前缀的最佳划分
 - 一个最终子数组

 DP 递归详尽地考虑了最终分区可能开始的每个有效位置。 由于每个较小的子问题在重用之前都已得到最优解决，因此通过动态规划原理可以保证最终结果是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestSumOfAverages(self, nums: List[int], k: int) -> float:
        n = len(nums)

        # Prefix sums
        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + nums[i]

        # dp[p][i] = maximum score using first i elements with p groups
        dp = [[0.0] * (n + 1) for _ in range(k + 1)]

        # Base case: one partition
        for i in range(1, n + 1):
            dp[1][i] = prefix[i] / i

        # Fill DP table
        for p in range(2, k + 1):
            for i in range(p, n + 1):
                for j in range(p - 1, i):
                    current_average = (
                        prefix[i] - prefix[j]
                    ) / (i - j)

                    dp[p][i] = max(
                        dp[p][i],
                        dp[p - 1][j] + current_average
                    )

        return dp[k][n]
```实现首先构建一个前缀和数组。 这允许对任何子数组和进行恒定时间计算，这是至关重要的，因为在 DP 转换期间会重复评估平均值。 

接下来，DP表被初始化。 每个条目`dp[p][i]`存储使用第一个可达到的最佳分数`i`元素精确划分为`p`组。 

基本情况处理只允许一个分区的情况。 在这种情况下，分数只是整个前缀的平均值。 

然后，嵌套循环逐渐填充 DP 表。 对于每个可能的分区数量和每个数组前缀，该算法会尝试最后一个分区的每个可能的分割点。 

转换计算：

 - 较早前缀的最佳分数
 - 最终分区的平均值

 并将它们结合起来。 

最后算法返回`dp[k][n]`，它表示使用所有元素的最佳分数，最多`k`分区。 

## 解决方案```go
func largestSumOfAverages(nums []int, k int) float64 {
	n := len(nums)

	// Prefix sums
	prefix := make([]float64, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + float64(nums[i])
	}

	// dp[p][i] = max score using first i elements with p groups
	dp := make([][]float64, k+1)

	for i := range dp {
		dp[i] = make([]float64, n+1)
	}

	// Base case
	for i := 1; i <= n; i++ {
		dp[1][i] = prefix[i] / float64(i)
	}

	// Fill DP table
	for p := 2; p <= k; p++ {
		for i := p; i <= n; i++ {
			for j := p - 1; j < i; j++ {
				currentAverage := (prefix[i] - prefix[j]) / float64(i-j)

				candidate := dp[p-1][j] + currentAverage

				if candidate > dp[p][i] {
					dp[p][i] = candidate
				}
			}
		}
	}

	return dp[k][n]
}
```Go 的实现与 Python 版本非常相似。 由于 Go 严格区分整数和浮点值，因此前缀和数组存储为`float64`从一开始就简化平均计算。 

切片用于 DP 表，所有涉及平均值的算术都使用显式`float64`转换。 

与 Python 不同，Go 没有内置的`max`对于浮点数，因此实现使用手动比较。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k * n^2) | O(k * n^2) | 对于每个分区计数和结束索引，都会探索所有分割点 |
 | 空间| O(k * n) | DP 表存储每个分区计数和前缀长度的状态 |

 外循环迭代分区计数`1`到`k`。 中间循环迭代数组位置，内部循环尝试每个可能的分割点。 这创建了`O(k * n^2)`运行时。 

DP表存储`(k + 1) * (n + 1)`浮点值，导致`O(k * n)`空间使用情况。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 在这种情况下，不允许分区，因此算法必须返回整个数组的平均值。 有缺陷的实现可能仍会尝试转换其他组或错误处理初始化。 基本情况初始化通过直接将每个前缀的平均值分配给来正确处理这个问题`dp[1][i]`。 

另一个重要的情况发生在`k = nums.length`。 在这里，每个元素都可以成为自己的分区，这总是使分数最大化，因为所有数字都是正数。 该实现自然会处理这个问题，因为 DP 会探索所有有效的分割点，包括大小为 1 的分区。 

长度为 1 的数组也很容易被错误处理。 由于只有一个有效分区，因此算法必须返回该元素本身。 该实现工作正常，因为前缀和和 DP 初始化都支持最小大小的数组。 

更微妙的边缘情况涉及重复值。 当许多分区产生相同的分数时，浮点比较可能会变得很棘手。 由于该实现使用标准浮点运算并且仅要求精度在`10^-6`，它可以安全地处理这些情况。 

最后，包含大值与非常小值混合的数组可能会暴露不正确的平均逻辑或整数除法错误。 两种实现都明确使用浮点除法，确保无论值分布如何都能获得准确的平均值。
