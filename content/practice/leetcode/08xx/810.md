 # LeetCode 810，黑板异或游戏

 ## 问题理解

 该问题描述了在整数数组上玩的两人游戏。 这些数字写在黑板上，玩家轮流擦掉一个数字。 爱丽丝先移动，然后是鲍勃，两个玩家都发挥最佳状态。 

关键规则是不寻常的。 如果删除一个数字的行为导致所有剩余数字的 XOR 变为`0`。 

还有另一个重要的规则。 如果玩家开始回合并且所有剩余数字的异或已经`0`，那么该玩家立即获胜。 

输入是一个整数数组`nums`。 每个元素都是非负整数。 任务是确定假设两个玩家都做出最佳决策，爱丽丝是否可以强行获胜。 

限制相对较小：

 -`1 <= nums.length <= 1000`-`0 <= nums[i] < 2^16`即使数组长度最多可达`1000`，游戏本身有指数级的多种可能的移动序列。 简单的递归游戏模拟很快就会变得不可行，因为每一步都会分支到许多未来的可能性。 

最重要的是要了解删除元素时 XOR 的行为方式。 

假设整个数组的异或为：```
total_xor = nums[0] XOR nums[1] XOR ... XOR nums[n-1]
```如果我们删除一个值`x`，新的 XOR 变为：```
new_xor = total_xor XOR x
```这是有效的，因为 XOR 会取消相同的值：```
a XOR a = 0
```幼稚的实现很容易陷入尝试模拟所有可能的游戏状态的困境。 重要的边缘情况是：

 - 总异或已经是的数组`0`- 只有一个元素的数组
 - 偶数长度与奇数长度的数组
 - 每一个动作都显得危险的阵列
 - 包含重复数字的数组

 这些案例揭示了游戏的数学结构。 

## 方法

 ### 蛮力方法

 暴力解决方案将游戏视为完整的游戏树搜索。 

每一次：

 1. 计算当前所有数字的异或。 
2. 尝试删除每个可能的元素。 
3. 如果删除一个元素使得剩余的异或等于`0`，那一招立刻就输了。 
4. 否则根据结果状态递归判断对手是否能够获胜。 
5. 如果任何一步导致对手失败，则当前玩家获胜。 

这种方法是正确的，因为它明确地探索了每一个可能的合法移动序列，并使用极小极大风格递归应用最佳游戏逻辑。 

然而，它太慢了。 对于大小的数组`n`，最多可以有：```
n * (n-1) * (n-2) * ...
```可能的移动顺序。 

状态总数呈阶乘增长，即使对于中等输入大小，这也变得不切实际。 

### 最佳方法

 关键的见解是该游戏的数学结果非常简单。 

只有两种情况：

 1. 如果数组的总异或为`0`，爱丽丝立即获胜。 
2. 否则，当且仅当数组长度为偶数时，Alice 获胜。 

这个结果来自博弈论和异或性质。 

假设当前 XOR 非零。 

如果数组长度是偶数，则当前玩家总是可以迫使游戏进入一种状态，即对手最终面对非零异或的奇数大小的数组。 

如果数组长度为奇数且异或非零，则当前玩家在最佳玩法下陷入失败位置。 

值得注意的是我们根本不需要模拟动作。 整个游戏简化为检查：```
(total_xor == 0) OR (len(nums) is even)
```## 方法比较

 ## 算法演练

 1. 计算数组中每个数字的异或。 

我们迭代数组并连续将所有值异或在一起。 这给出了整个板状态的异或。 
2. 检查总异或是否等于`0`。 

如果异或已经`0`在爱丽丝的回合开始时，规则规定当前玩家立即获胜。 因此爱丽丝立即获胜。 
3. 如果异或不是`0`，检查数组长度奇偶校验。 

如果元素数量是偶数，Alice 可以强制获胜策略。 

如果元素的数量是奇数，则爱丽丝在最佳游戏下会失败。 
4. 返回结果。 

最终的条件是：```
total_xor == 0 OR len(nums) % 2 == 0
```### 为什么它有效

 核心不变量基于奇偶校验。 

当总异或非零时：

 - 每个合法的移动都会将 XOR 更改为另一个值。 
- 元素数量为偶数时，第一名玩家始终可以保持有利的奇偶配置。 
- 由于元素数量为奇数，第一个玩家最终被迫采取失败的行动。 

形式化证明表明，当异或非零时，获胜条件完全取决于剩余数是偶数还是奇数。 

因此，比赛结果完全由以下因素决定：

 - 起始异或是否是`0`- 数组长度是否为偶数

 ## Python 解决方案```python
from typing import List

class Solution:
    def xorGame(self, nums: List[int]) -> bool:
        total_xor = 0

        for num in nums:
            total_xor ^= num

        return total_xor == 0 or len(nums) % 2 == 0
```该实现非常紧凑，因为数学观察消除了模拟的需要。 

首先我们初始化`total_xor`到`0`。 然后我们迭代每个数字并将其异或到累加器中。 到循环结束时，`total_xor`包含整个数组的异或。 

计算完异或后，我们直接评估获胜条件。 

如果`total_xor == 0`，按照规则，Alice 立即获胜。 

否则，我们检查数组长度是否为偶数。 如果是平局，爱丽丝就可以强行获胜。 如果很奇怪，她就输了。 

该解决方案使用恒定的额外空间，并且仅扫描数组一次。 

## 解决方案```go
func xorGame(nums []int) bool {
    totalXor := 0

    for _, num := range nums {
        totalXor ^= num
    }

    return totalXor == 0 || len(nums)%2 == 0
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 切片自然会处理空和非空集合，尽管这个问题保证了至少一个元素。 整数溢出不是问题，因为异或运算保持在整数位宽度内并且输入值很小。 

该循环使用 Go 的`range`语法来有效地迭代切片。

 ## 边缘情况

 一种重要的边缘情况是数组仅包含一个元素。 如果该元素非零，则总异或非零且长度为奇数。 Alice 只有一种可能的举动，删除该元素，剩下 XOR`0`并让她立刻就输了。 该实现通过奇偶校验和异或条件自然地处理这个问题。 

当总异或已经是时，会出现另一个关键的边缘情况`0`在采取任何行动之前。 根据规则，轮到XOR开始的玩家`0`立即获胜。 幼稚的模拟可能会错误地尝试先采取行动。 实施明确检查`total_xor == 0`，确保这种情况得到正确处理。 

第三个重要的边缘情况涉及通过 XOR 取消的重复值。 例如：```
[5,5,7,7]
```总异或`0`因为相同的数字会互相抵消。 有缺陷的实现可能只关注数组长度或不同的值。 该解决方案正确计算整个数组的实际 XOR，因此取消行为是自动处理的。 

另一个微妙的情况是具有任意值的大型数组。 由于最佳解决方案从不模拟博弈树，因此即使对于最大输入大小，性能也保持高效`1000`。 该算法仅需要一次遍历数组，因此速度快且内存效率高。
