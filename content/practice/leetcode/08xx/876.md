[LeetCode 第 876 题](https://leetcode.com/problems/middle-of-the-linked-list/)

 **难度：** 🟢简单
 **主题：** 链表、两个指针

 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表的头，并要求我们返回中间节点。 单链表是一个节点序列，其中每个节点包含一个值和一个指向下一个节点的指针。 与数组不同，链表不支持直接索引，因此我们无法立即跳转到中间元素。 

这个问题的重要细节是如何处理具有偶数个节点的列表。 如果有两个可能的中间节点，我们必须返回第二个。 例如，在列表中`[1,2,3,4,5,6]`，中间的两个节点是`3`和`4`，正确答案是包含的节点`4`。 

输入表示链表的头节点。 输出不仅仅是中间节点的值，而是实际节点本身。 在 LeetCode 的表示中，返回节点意味着输出将显示从该节点开始的链表。 

约束告诉我们列表长度介于`1`和`100`。 这是一个非常小的输入大小，因此即使效率较低的解决方案仍然可以快速运行。 然而，该问题旨在教授链表遍历技术，特别是快指针和慢指针方法。 

有几个重要的边缘情况需要考虑。 仅包含一个节点的列表应立即返回该节点作为中间节点。 具有两个节点的列表应返回第二个节点，因为问题指定应选择第二个中间节点。 奇数长度和偶数长度的列表都必须正确处理。 由于该问题保证至少有一个节点，因此我们不需要处理空列表。 

## 方法

 一个简单的暴力解决方案是首先遍历链表并计算它包含多少个节点。 一旦我们知道了长度，我们就可以使用整数除法来计算中间索引。 然后我们再次遍历列表，直到到达该索引并返回相应的节点。 

这种方法之所以有效，是因为长度列表的中间位置`n`总是`n // 2`使用从零开始的索引时。 对于奇数长度的列表，这自然指向确切的中间节点。 对于偶数长度列表，整数除法会自动给出第二个中间节点。 

虽然这个解决方案是正确的，但它需要两次单独遍历链表。 虽然运行时仍然是线性的，但从概念上讲，它并不是最优雅或最有效的方法。 

更好的解决方案的关键观察是，我们可以通过使用以不同速度移动的两个指针在单次遍历中定位中间节点。 一个指针每次移动一步，而另一个指针一次移动两步。 当快指针到达链表末尾时，慢指针将位于链表的中间。 

这是有效的，因为快指针覆盖的距离是慢指针的两倍。 当快指针遍历完整个链表时，慢指针就遍历了正好一半的链表。 对于偶数长度的列表，停止条件自然将慢指针放在第二个中间节点上，这符合问题要求。

 | 蛮力 | O(n) | O(1) | O(1) | 先统计节点，然后再遍历到中间 |
 | 最佳| O(n) | O(1) | O(1) | 在单次遍历中使用快指针和慢指针 |

 ## 算法演练

 1.初始化两个指针，`slow`和`fast`，都从链表的头部开始。 这`slow`指针一次会移动一个节点，而`fast`指针一次会移动两个节点。 
2. 继续遍历列表，同时`fast`和`fast.next`不是`None`。 此条件确保快速指针可以安全地向前移动两步，而不会导致错误。 
3. 在每次迭代期间，移动`slow`指针向前移动一个节点。 同时，移动`fast`指针向前移动两个节点。 
4. 随着遍历的进行，快指针在列表中的移动速度是慢指针的两倍。 这意味着当快指针到达列表末尾时，慢指针将到达中间。 
5. 循环终止后，返回`slow`指针。 此时，它指向中间节点。 对于偶数长度的列表，由于循环条件的工作原理，它自然会落在第二个中间节点上。 

### 为什么它有效

 正确性来自于两个指针的相对速度。 快指针每遍历两个节点，慢指针就遍历一个节点。 因此，当快指针覆盖了整个列表时，慢指针正好覆盖了一半的距离。 这个不变量保证慢指针在中间节点结束。 在偶数长度列表中，只有在慢速指针前进到第二个中间位置后，快指针才能到达末尾。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def middleNode(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = head
        fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        return slow
```该实现首先初始化列表头部的两个指针。 这`slow`指针一次前进一个节点，而`fast`指针一次前进两个节点。 

这`while`只要快指针仍能安全地向前移动，循环就会继续。 在循环内，两个指针都会根据其预期速度进行更新。 

当循环结束时，快速指针要么到达最后一个节点，要么完全移出列表。 就在那一刻，慢指针位于中间节点。 返回`slow`直接满足问题要求。 

实现很简洁，因为快慢指针技术自然可以处理奇数长度和偶数长度的列表，而不需要单独的逻辑。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func middleNode(head *ListNode) *ListNode {
    slow := head
    fast := head

    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }

    return slow
}
```Go 实现遵循与 Python 版本完全相同的算法。 主要区别在于显式使用`nil`而不是`None`。 

Go 需要稍微详细一点的指针语法，使用`fast.Next`而不是`fast.next`。 否则，逻辑是相同的。 由于该问题保证至少有一个节点，因此无需对空列表进行特殊处理。

 ## 边缘情况

 单节点列表是最小的有效输入。 这种情况很重要，因为某些实现可能会错误地假设存在多个节点。 在这个实现中，两者`slow`和`fast`从唯一的节点开始，循环永远不会执行，因为`fast.next`是`None`。 该函数正确返回单个节点。 

偶数长度列表是另一个关键的边缘情况，因为该问题明确要求返回第二个中间节点。 幼稚的实现可能会意外地返回第一个中间节点。 快慢指针方法自然避免了这个错误，因为慢指针在循环终止之前额外前进了一步。 

两节点列表是偶数长度列表的一种特别棘手的特例。 一些不正确的解决方案过早停止并返回第一个节点。 在此实现中，循环执行一次，移动`slow`到第二个节点并且`fast`超出列表。 因此返回的节点是正确的。 

具有交替遍历长度的较长列表对于验证指针移动逻辑也很重要。 如果循环条件写错了，比如只检查`fast`没有检查`fast.next`，该实现可能会尝试访问不存在的节点并崩溃。 使用条件`while fast and fast.next`安全地防止这个问题。
