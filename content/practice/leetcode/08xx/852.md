[LeetCode 852 题](https://leetcode.com/problems/peak-index-in-a-mountain-array/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 这个问题给了我们一种特殊类型的数组，称为山数组。 山阵严格增加，直到达到单个峰值元素，然后严格减少。 

换句话说，存在一些索引`i`这样：

 -`arr[0] < arr[1] < ... < arr[i]`-`arr[i] > arr[i + 1] > ... > arr[n - 1]`我们的任务是返回这个峰值元素的索引。 

例如，在数组中`[0, 10, 5, 2]`，值从`0`到`10`，然后从`10`到`5`到`2`。 因此，峰值元素为`10`，其索引为`1`。 

重要的要求是解决方案必须运行在`O(log n)`时间复杂度。 这立即表明线性扫描不足以实现预期的最佳解决方案。 由于数组具有先递增后递减的结构化属性，二分查找成为自然的候选者。 

这些限制也强化了这个想法：

 - 数组长度可以大到`10^5`- 明确需要对数解
 - 该数组保证是有效的山数组

 最终保证极其重要，因为它意味着：

 - 总是只有一个峰值
 - 峰值永远不会出现在第一个或最后一个索引处
 - 我们永远不需要处理无效的输入形状

 简单的实现仍然可能在数组边界附近出错，特别是在检查相邻元素时。 由于二分查找经常比较`arr[mid]`和`arr[mid + 1]`，仔细的边界管理对于避免超出范围的错误是必要的。 

另一个微妙的问题是确定二分搜索期间移动的方向。 关键的观察是，如果我们处于不断增加的斜率，则峰值位于右侧。 如果我们处于下降的斜坡上，则峰值位于左侧或当前位置。 

## 方法

 ### 蛮力方法

 最简单的解决方案是扫描数组并找到大于其两个邻居的元素。 

我们从索引迭代`1`到`n - 2`并检查：```
arr[i] > arr[i - 1] and arr[i] > arr[i + 1]
```因为该问题保证了一个有效的山数组，所以第一个满足这个条件的索引就是峰。 

这种方法是正确的，因为山区属性恰好保证了一个局部最大值。 

然而，时间复杂度为`O(n)`，不满足要求`O(log n)`复杂性约束。 

### 最佳二分搜索方法

 山体结构给了我们一个单调的模式：

 - 在达到峰值之前，价值正在增加
 - 峰值过后，数值逐渐下降

 这意味着我们可以使用二分搜索来确定我们当前位于峰值的哪一侧。 

在任意中点：

 - 如果`arr[mid] < arr[mid + 1]`，我们处于渐增的斜率，因此峰值必须位于右侧
 - 如果`arr[mid] > arr[mid + 1]`，我们处于下降斜率，所以峰值位于`mid`或向左

 这使我们能够重复消除一半的搜索空间，从而产生`O(log n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描数组并找到局部最大值 |
 | 最佳| O(log n) | O(1) | O(1) | 在山体结构上使用二分搜索 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`，表示当前的搜索范围。 

我们从以下开始：```
left = 0
right = len(arr) - 1
```2.继续搜索`left < right`。 

仅当两个指针都收敛到峰值索引时，循环才会停止。 
3. 计算中点：```
mid = (left + right) // 2
```4. 比较`arr[mid]`和`arr[mid + 1]`。 

这种比较告诉我们我们是在山的上升一侧还是下降一侧。 
5. 如果`arr[mid] < arr[mid + 1]`，我们正处于上升的斜坡上。 

由于这些值仍在上升，因此峰值必定位于`mid`。 

移动搜索范围：```
left = mid + 1
```6. 否则，我们就处于下降趋势。 

这意味着`mid`可能已经是峰值，或者峰值位于更左边。 

移动搜索范围：```
right = mid
```7. 最终，`left`和`right`收敛到同一个索引。 

该指数就是峰值指数。 
8. 返回`left`或者`right`，因为它们是相等的。 

### 为什么它有效

 该算法保持峰值始终位于当前搜索区间内的不变性`[left, right]`。 

什么时候`arr[mid] < arr[mid + 1]`，斜率不断增加，因此峰值必定存在于右侧。 我们安全地丢弃左半部分。 

什么时候`arr[mid] > arr[mid + 1]`，斜率正在减小，这意味着峰值位于`mid`或向左。 我们安全地丢弃超出范围的右半部分`mid`。 

由于每次迭代都会删除一半的剩余搜索空间，因此该算法在对数时间内有效地收敛到峰值。 

## Python 解决方案```python
from typing import List

class Solution:
    def peakIndexInMountainArray(self, arr: List[int]) -> int:
        left = 0
        right = len(arr) - 1

        while left < right:
            mid = (left + right) // 2

            if arr[mid] < arr[mid + 1]:
                left = mid + 1
            else:
                right = mid

        return left
```实现首先初始化二分搜索边界，`left`和`right`。 

在循环内部，我们计算中点并进行比较`arr[mid]`和`arr[mid + 1]`。 

如果序列仍在增加`mid`，峰必须位于右侧，所以我们移动`left`向前。 

否则，序列正在递减，这意味着峰值位于`mid`或者更早，所以我们搬家`right`向后到`mid`。 

循环继续缩小搜索间隔，直到两个指针相遇。 此时，收敛指标保证为峰值。 

该实现使用恒定的额外内存并避免不必要的检查，因为山数组保证确保有效的相邻比较。 

## 解决方案```go
func peakIndexInMountainArray(arr []int) int {
    left := 0
    right := len(arr) - 1

    for left < right {
        mid := (left + right) / 2

        if arr[mid] < arr[mid+1] {
            left = mid + 1
        } else {
            right = mid
        }
    }

    return left
}
```Go 实现遵循与 Python 版本完全相同的二分搜索逻辑。 

Go 切片提供类似于 Python 列表的直接索引访问，因此翻译很简单。 

没有特殊的 nil 检查，因为问题保证数组长度至少为`3`。 

整数溢出在这里不是一个实际问题，因为最大数组大小仅为`10^5`，但是使用`(left + right) / 2`在这些限制下仍然是安全的。

 ## 边缘情况

 一个重要的边缘情况是尽可能最小的山脉阵列，例如`[0, 1, 0]`。 当数组大小很小时，二分搜索实现很容易出现边界错误。 此实现可以正确处理它，因为循环条件`left < right`一旦两个指针收敛，就安全终止。 

另一个重要的情况是当峰值非常接近开始时，例如`[0, 5, 3, 2, 1]`。 一些不正确的实现假设峰值位于中间附近，并且无法正确移动搜索边界。 这里，比较`arr[mid]`和`arr[mid + 1]`正确识别坡度正在下降并向左缩小搜索范围。 

第三个重要的情况是当峰值接近尾声时，例如`[0, 1, 2, 3, 4, 2]`。 在这种情况下，在搜索收敛之前，在增加的斜率上会发生多次迭代。 算法正确地保持移动`left`前进，直到到达顶峰。 

另一个微妙的边缘情况涉及非常大的值，例如`[0, 1000000, 999999]`。 由于该算法仅执行比较，不计算涉及数组值的算术，因此大数字不会造成溢出或精度问题。 

最后，具有长递增和递减部分的数组可能会导致低效的实现。 线性扫描需要`O(n)`时间，但这种二分搜索解决方案仍然有效，因为每次迭代将剩余搜索空间减半。
