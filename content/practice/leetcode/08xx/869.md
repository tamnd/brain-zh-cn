 ## 解决方案

 ## 问题理解

 问题给了我们一个正整数`n`并询问其数字是否可以重新排列以形成 2 的幂。 重新排列可能会保持数字的原始顺序或将它们放置在任何其他顺序，但结果数字不能包含前导零。 

二的幂是以下形式的任意数：$2^k$对于一些非负整数`k`。 

例如，如果`n = 128`，我们可以将其数字重新排列为`128`，它已经是 2 的幂了，所以答案是`true`。 如果`n = 821`，我们可以将数字重新排列成`128`，所以答案也是`true`。 然而，如果数字的排列不形成 2 的幂，则答案是`false`。 

重要的细节是我们不允许引入或删除数字。 每个数字在重新排序的数字中出现的次数必须完全相同。 这意味着问题本质上是关于比较数字频率分布。 

限制相对较小：$1 \leq n \leq 10^9$自从`10^9`并不是很大，我们只需要考虑有限数量的 2 的幂。 两者的最大相关幂为：$2^{30} = 1073741824$因为`2^30`略大于`10^9`，并且所有较小的幂涵盖了我们需要的每个可能的数字长度。 

一些边缘情况很重要：

 - 包含零的数字可能会很棘手，因为不允许使用前导零。 
- 具有重复数字的数字需要精确的频率匹配。 
- 个位数输入，例如`1`,`2`,`4`， 和`8`应立即返回`true`。 
- 已经是二的幂的数字应该仍然有效，无需特殊处理。 
- 附近非常大的值`10^9`仍须有效处理。 

## 方法

 ### 蛮力方法

 一个简单的解决方案将生成以下数字的所有可能的排列`n`，将每个排列转换为整数，拒绝带有前导零的排列，并检查所得数字是否为 2 的幂。 

这种方法是正确的，因为它详尽地测试了每个有效的数字排列。 如果任何排列形成 2 的幂，我们返回`true`; 否则，我们返回`false`。 

然而，这种方法很快就变得不切实际。 如果该数字包含`d`位数，最多可达：$d!$不同的排列。 

尽管约束仅达到 10 位数，但阶乘增长的成本极其昂贵。 重复的数字在一定程度上减少了唯一排列的数量，但最坏情况的运行时间对于有效的解决方案来说仍然太大。 

### 最佳方法

 关键的观察是，两个数字可以彼此重新排列，当且仅当它们包含具有相同频率的完全相同的数字。 

例如：

-`128`和`821`两者都包含一个`1`， 一`2`，和一个`8`-`1024`和`2041`两者都包含一个`0`， 一`1`， 一`2`，和一个`4`我们可以计算数字的规范表示，而不是生成排列。 最简单的选择是对数字进行排序。 

如果两个数字具有相同的排序数字字符串，则可以将一个数字重新排列为另一个数字。 

我们预先计算有效范围内的所有 2 的幂，对它们的数字进行排序，并将这些签名存储在哈希集中。 然后我们对数字进行排序`n`并检查其签名是否存在于集合中。 

这完全避免了排列生成，并将问题减少到快速查找操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(d! × d) | O(d!) | 生成每个排列并检查每个排列 |
 | 最佳| O(30 × d log d) | O(30 × d log d) | O(30) | 比较 2 的幂的排序数字签名 |

 这里，`d`是数字的个数`n`，以及常数`30`来自二的相关幂的数量。 

## 算法演练

 1.转换输入的数字`n`转换为规范的数字表示形式。 

我们需要一种方法来唯一地识别数字的数字组成。 对数字进行排序非常有效，因为相同数字的任何排列都会产生相同的排序字符串。 

例如：

-`821 → "128"`-`128 → "128"`由于两个签名匹配，因此数字是彼此的重新排列。 
2. 生成 2 的所有相关幂。 

自从：$2^{30} > 10^9$我们只需要检查权力：$2^0, 2^1, \dots, 2^{30}$这是一个非常小的有限集。 
3. 计算每个 2 的幂的排序数字签名。 

对于每一种力量：

 - 将其转换为字符串
 - 对数字进行排序
 - 将生成的签名存储在哈希集中

 选择哈希集是因为成员资格检查非常快，平均时间恒定。 
4. 计算签名`n`。 

我们应用完全相同的变换`n`:

 - 转换为字符串
 - 对数字进行排序
 - 加入规范表示
 5. 检查签名集中是否存在。 

如果存在签名，则 2 的某个幂具有与以下完全相同的数字频率：`n`，这意味着数字可以重新排序以形成 2 的幂。 

否则，不存在有效的重排。 

### 为什么它有效

 该算法依赖于排列的基本属性：当且仅当两个数字的数字频率计数相同时，它们才是彼此的排列。 

对数字进行排序会为每个排列类创建规范表示。 相同数字的每次重新排列都会产生相同的排序序列，不同的数字组合会产生不同的序列。 

因此，如果排序后的数字`n`匹配 2 的某个幂的排序数字，然后`n`可以重新排序为 2 的幂。 相反，如果不存在匹配，则任何有效的重新排列都不能产生 2 的幂。 

## Python 解决方案```python
class Solution:
    def reorderedPowerOf2(self, n: int) -> bool:
        def signature(value: int) -> str:
            return "".join(sorted(str(value)))

        power_signatures = set()

        for exponent in range(31):
            power_of_two = 1 << exponent
            power_signatures.add(signature(power_of_two))

        return signature(n) in power_signatures
```实现首先定义一个名为的辅助函数`signature`。 该函数通过对数字进行排序并将它们重新连接回字符串，将数字转换为其规范的数字表示形式。 

例如：

-`821`变成`"128"`-`1024`变成`"0124"`接下来，我们创建一个名为的哈希集`power_signatures`。 该集合存储有效范围内所有2的幂的数字签名。 

该循环迭代指数`0`到`30`。 使用位移位：```python
1 << exponent
```有效地计算：$2^{\text{exponent}}$每个权力的签名都会添加到该集中。 

最后，我们计算签名`n`并检查集合中是否存在。 由于集合成员资格非常快，因此整体解决方案非常高效。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
)

func reorderedPowerOf2(n int) bool {
	signature := func(value int) string {
		digits := []byte(strconv.Itoa(value))

		sort.Slice(digits, func(i, j int) bool {
			return digits[i] < digits[j]
		})

		return string(digits)
	}

	powerSignatures := make(map[string]bool)

	for exponent := 0; exponent <= 30; exponent++ {
		powerOfTwo := 1 << exponent
		powerSignatures[signature(powerOfTwo)] = true
	}

	return powerSignatures[signature(n)]
}
```Go 实现遵循与 Python 版本相同的总体策略，但存在一些特定于语言的差异。 

Go没有内置的排序字符串函数，因此我们将字符串转换为字节切片并使用`sort.Slice`手动对数字进行排序。 

我们不使用 Python 集，而是使用：```go
map[string]bool
```模拟哈希集行为。 

位移位的工作方式与 Python 中相同，可以有效地生成 2 的幂。 

由于最大相关功率是`2^30`，整数溢出在 Go 的标准整数范围内不是问题。

 ## 边缘情况

 一种重要的边缘情况涉及包含零的数字，例如`10`或者`100`。 幼稚的基于排列的实现可能会意外地允许前导零并错误地对待`"01"`作为`1`。 该问题明确禁止前导零，因此`10`不能成为`1`。 我们的实现自然地避免了这个问题，因为排序的数字签名必须完全匹配，包括全零。 

另一个棘手的情况是重复的数字。 例如，`222`即使二的幂可能包含数字，也不能形成任何二的幂`2`。 准确的频率计数必须匹配。 通过对所有数字进行排序，我们的算法可确保正确保留重复计数。 

个位数输入也很重要。 值如`1`,`2`,`4`， 和`8`应该返回`true`，而像这样的值`3`,`5`， 和`7`应该返回`false`。 由于我们的方法将数字签名直接与 2 的所有幂进行比较，因此这些情况会自动处理，无需特殊的分支逻辑。 

附近的大边界值`10^9`是错误的另一个可能来源。 某些实现可能无法生成足够的 2 的幂并意外地错过有效匹配。 通过检查所有指数`0`通过`30`，我们保证完全覆盖整个约束范围。
