[LeetCode 第 826 题](https://leetcode.com/problems/most-profit-assigning-work/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大化分配工作给工人所获得的总利润，在一个特定的规则下：每个工人只能完成难度小于或等于其能力的工作。 

我们得到三个数组：

 -`difficulty[i]`代表着难度有多大`i-th`乔布斯是。 
-`profit[i]`代表完成该任务赚了多少钱`i-th`工作。 
-`worker[j]`代表了该人的能力水平`j-th`工人。 

一名工人最多可以执行一项工作**，但同一工作可以分配给**多名工人**。 这是一个非常重要的细节，因为它改变了问题的本质。 我们并不是将工人与工作进行专门匹配。 相反，每个工人都会独立选择他们能完成的最佳工作。 

对于每个工人，我们希望在所有难度不超过工人能力的工作中找到**利润最高的工作**。 如果不存在这样的工作，则该工人贡献`0`利润。 

最终的答案是**所有工人赚取的利润总和**。 

限制条件是：

 -`1 <= n, m <= 10^4`-`1 <= difficulty[i], profit[i], worker[i] <= 10^5`这些限制足够大，以至于天真的人`O(n * m)`解决方案在某些语言中可能仍然可以通过，但它并不理想，并且错过了优化的机会。 自排序以来`10^4`元素成本低廉，我们应该考虑一种涉及排序和高效遍历的解决方案。 

有几个重要的边缘情况需要预先考虑。 

工人可能太虚弱而无法完成任何工作。 在这种情况下，他们的贡献应该是`0`。 

多个工作可能有相同的难度但不同的利润。 我们必须确保我们始终选择最有利可图的。 

事实上，较困难的工作可能比较容易的工作薪水要低。 例如：```
difficulty = [2, 4]
profit = [50, 20]
```一个有能力的工人`4`还是应该选择难度`2`工作，因为薪水更高。 这意味着我们不能简单地选择难度最高的工作。 我们需要**迄今为止看到的最大利润**，以满足工人的能力。 

该问题保证了有效的输入大小和正值，因此我们不需要处理空数组或无效输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立处理每个工人。 

对于每个工作人员，我们迭代所有作业并检查该工作人员是否可以完成该工作。 如果可以的话，我们会将其利润与迄今为止的最佳利润进行比较。 

在扫描所有工作的最后，我们将工人的最大可能利润添加到总答案中。 

这是有效的，因为每个工人都是独立的。 由于工作可以无限重复，因此工人之间不存在冲突。 我们只是最大化每个工人的个人利润。 

然而，这种方法效率很低，因为我们会扫描每个工人的所有作业。 

如果有`m`工人和`n`作业，总时间复杂度变为：```
O(n * m)
```和`10^4`工作岗位和`10^4`工人，这可能会导致`10^8`在最坏的情况下进行操作，这会造成不必要的昂贵。 

### 最佳解决方案的关键见解

 重要的观察是工人只关心：

 > 低于或等于其能力的任何难度可获得的最高利润。 

这建议排序。 

如果我们按难度对工作进行排序，按能力对工人进行排序，我们可以使用双指针策略按升序处理这两者。 

当我们更换工作时，我们坚持：```
best_profit_so_far
```这代表当前工人可以执行的所有工作中的最大利润。 

由于工作人员是按排序顺序处理的，因此一旦某项工作可供一名工作人员使用，它仍然可供所有实力较强的工作人员使用。 

这使我们只需扫描作业一次，从而使解决方案更快。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(1) | O(1) | 检查每个工人的每项工作 |
 | 最佳| O(n log n + m log m) | O(n log n + m log m) | O(n) | 对jobs和workers进行排序，然后使用两个指针 |

 ## 算法演练

 ### 使用排序和两个指针的最优算法

 1. 结合`difficulty`和`profit`进入工作对列表。 

我们创建以下形式的元组：```
(difficulty, profit)
```这让我们能够对工作进行分类，同时将其相关利润放在一起。 
2. 按难度对作业进行排序。 

排序后，作业将按照从最简单到最难的顺序排列。 这使我们能够有效地处理随着工人能力的提高而出现的工作岗位。 
3. 排序`worker`大批。 

从最弱到最强的顺序处理工人可以确保一旦我们处理了一名工人的工作，我们就不需要重新访问它。 
4. 初始化跟踪变量。 

我们维持：

 -`job_index`, 指向当前工作
 -`best_profit`，存储可用工作中最大利润
 -`total_profit`，累加最终答案
 5. 按递增顺序处理工人。 

对于每个工人：

 - 移动`job_index`在工人可以完成工作的同时向前推进。 
- 更新`best_profit`与遇到的最大利润。 
- 添加`best_profit`到`total_profit`。 

由于作业已排序，因此之前的每个作业`job_index`保证当前工人可以完成。 
6. 返回`total_profit`。 

当所有的worker都处理完后，我们返回累积的结果。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 >`best_profit`始终代表当前工人可以执行的所有工作中的最高利润。 

由于工人是按升序处理的，因此可行的工作组只会增加。 我们永远不会错过任何一份有效的工作，也不会不必要地重新考虑旧的工作。 每个工人独立获得最大可能的利润，保证了总利润最优。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProfitAssignment(
        self,
        difficulty: List[int],
        profit: List[int],
        worker: List[int]
    ) -> int:
        jobs = sorted(zip(difficulty, profit))
        worker.sort()

        total_profit = 0
        best_profit = 0
        job_index = 0

        for ability in worker:
            while (
                job_index < len(jobs)
                and jobs[job_index][0] <= ability
            ):
                best_profit = max(
                    best_profit,
                    jobs[job_index][1]
                )
                job_index += 1

            total_profit += best_profit

        return total_profit
```实施首先使用将每个工作难度与其相应的利润配对`zip()`。 然后，我们按难度对这些工作对进行排序，以便按升序排列可用的工作。 

这`worker`数组也经过排序，以便从最弱到最强处理工作人员。 

变量`job_index`充当已排序作业列表的指针。 当每个工作人员被处理时，我们将这个指针向前移动并包含他们可以完成的每一项工作。 

我们不会存储每一个有效的工作，而是只保留单个最有价值的利润`best_profit`。 这已经足够了，因为工人只关心可实现的最大利润。 

对于每个工人，我们将最佳可用利润添加到`total_profit`。 

由于每个作业最多被访问一次，并且每个worker都被处理一次，因此排序后的遍历是线性的。 

## 解决方案```go
package main

import "sort"

func maxProfitAssignment(difficulty []int, profit []int, worker []int) int {
	type Job struct {
		difficulty int
		profit     int
	}

	n := len(difficulty)
	jobs := make([]Job, n)

	for i := 0; i < n; i++ {
		jobs[i] = Job{
			difficulty: difficulty[i],
			profit:     profit[i],
		}
	}

	sort.Slice(jobs, func(i, j int) bool {
		return jobs[i].difficulty < jobs[j].difficulty
	})

	sort.Ints(worker)

	totalProfit := 0
	bestProfit := 0
	jobIndex := 0

	for _, ability := range worker {
		for jobIndex < len(jobs) &&
			jobs[jobIndex].difficulty <= ability {

			if jobs[jobIndex].profit > bestProfit {
				bestProfit = jobs[jobIndex].profit
			}

			jobIndex++
		}

		totalProfit += bestProfit
	}

	return totalProfit
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用自定义`Job`结构将难度和利润值配对在一起。 

排序是用`sort.Slice`为了工作和`sort.Ints`对于工人来说。 

与 Python 不同，Go 不直接提供元组排序，因此使用结构体可以保持实现的简洁和可读性。 

这里整数溢出不是问题，因为最大总利润是：```go
10^4 × 10^5 = 10^9
```可以安全地放入 Go 中`int`在标准 LeetCode 环境中输入。

 ## 边缘情况

 ### 工人无法执行任何工作

 工人的能力可能小于最低工作难度。 幼稚的实施可能会意外地分配无效的工作或产生不正确的利润。 

例如：```
difficulty = [10]
worker = [5]
```该实现正确地处理了这个问题，因为`while`循环永远不会执行，离开`best_profit = 0`。 该工人的利润为零。 

### 较轻松的工作比较难的工作薪水更高

 一个常见的错误是假设工人应该总是选择最难的工作。 

考虑：```
difficulty = [2, 4]
profit = [50, 20]
worker = [4]
```最好的答案是`50`， 不是`20`。 

我们的实现使用运行最大值来处理这个问题`best_profit`，它总是存储所有可行工作中利润最高的。 

### 重复难度不同收益

 多个工作可能具有相同的难度，但提供不同的奖励。 

例如：```
difficulty = [5, 5, 5]
profit = [10, 20, 30]
worker = [5]
```有缺陷的解决方案可能会在第一个匹配作业处停止。 

我们的实施以允许的难度处理所有作业并不断更新`best_profit`，确保工人获得尽可能高的奖励。 

### 多个工人执行相同的工作

 由于工作可以无限重复，多个工人可能会选择同一份薪水最高的工作。 

例如：```
difficulty = [2]
profit = [100]
worker = [2, 2, 2]
```正确答案是`300`。 

我们的实现自然支持这一点，因为作业永远不会被删除或标记为已使用。 每个工人都独立地获得最佳的可用利润。
