 # LeetCode 888 - 公平糖果交换

 ## 问题理解

 问题给了我们两个数组，`aliceSizes`和`bobSizes`，代表爱丽丝和鲍勃拥有的糖果盒。 数组中的每个元素都是特定盒子中糖果的数量。 

爱丽丝和鲍勃想分别交换一盒糖果，这样交换后，他们各自拥有的糖果总数就相等。 

我们需要返回一对整数：

 -`answer[0]`是爱丽丝赠送的糖果盒
 -`answer[1]`是鲍勃赠送的糖果盒

 该问题保证至少存在一个有效的解决方案。 

为了更清楚地理解问题，假设：

 - 爱丽丝目前的糖果总数`sumAlice`- 鲍勃目前的糖果总数`sumBob`如果爱丽丝赠送一个盒子`a`糖果并收到一个盒子`b`糖果，然后：

 - 爱丽丝的新总数变为`sumAlice - a + b`- 鲍勃的新总数变为`sumBob - b + a`我们希望这些总数相等。 

输入约束很重要：

 - 每个数组最多可以包含`10^4`元素
 - 糖果数量可以达到`10^5`这些约束足够大，以至于二次解在实践中可能变得太慢，特别是如果两个数组都包含`10^4`元素。 接近线性时间的解决方案是优选的。 

该问题还保证：

 - 爱丽丝和鲍勃最初的糖果总数不同
 - 有效的答案总是存在的

 这种保证简化了实施，因为我们不需要处理失败情况。 

一些重要的边缘情况包括：

 - 长度数组`1`- 总数之间存在较大差异
 - 重复的糖果盒尺寸
 - 多个有效答案
 - 匹配交换涉及最大值或最小值的情况

 如果比较每个可能的框对，幼稚的实现可能会变得低效。 

## 方法

 ### 蛮力方法

 最直接的方法是尝试一切可能的交换。 

每个糖果盒`a`在爱丽丝的收藏中，我们尝试了每一个糖果盒`b`在鲍勃的收藏中。 模拟交换后，我们检查两个总数是否相等。 

条件是：```
sumAlice - a + b == sumBob - b + a
```如果条件成立，我们返回`[a, b]`。 

这种方法保证有效，因为它详尽地检查了所有可能的交换。 

然而，如果 Alice 和 Bob 各有`10^4`框，那么我们可以执行：```
10^4 × 10^4 = 10^8
```比较。 

这对于有效的解决方案来说太慢了。 

### 最佳方法

 关键的见解来自于简化等式。 

我们从以下开始：```
sumAlice - a + b = sumBob - b + a
```重新排列术语：```
sumAlice - sumBob = 2a - 2b
```两边除以`2`:```
a - b = (sumAlice - sumBob) / 2
```这个方程准确地告诉我们交换的盒子之间必须存在什么关系。 

如果我们定义：```
difference = (sumAlice - sumBob) // 2
```然后：```
b = a - difference
```现在问题变成：

 对于每个`a`在 Alice 的数组中，检查 Bob 是否拥有一个等于：```
a - difference
```这是哈希集的理想用例，因为成员资格检查是`O(1)`平均而言。 

我们将 Bob 的所有糖果盒尺寸存储在一个集合中，然后迭代 Alice 的盒子并搜索所需的匹配值。 

## 方法比较

 | --- | --- | --- | --- |

 ## 算法演练

 1. 计算 Alice 和 Bob 拥有的糖果总数。 

我们计算：```
sumAlice = sum(aliceSizes)
sumBob = sum(bobSizes)
```这些总数决定了当前糖果分配的不平衡程度。 
2. 计算所需的差值。 

从推导出来的方程：```
a - b = (sumAlice - sumBob) / 2
```我们计算：```
difference = (sumAlice - sumBob) // 2
```这准确地告诉我们爱丽丝的交换盒子必须比鲍勃的大多少。 
3. 将 Bob 的糖果大小存储在哈希集中。 

我们创造：```
bobSet = set(bobSizes)
```哈希集允许恒定时间的成员资格检查。 
4. 迭代爱丽丝的糖果盒。 

对于每个糖果盒`a`，我们计算鲍勃必须提供的盒子：```
target = a - difference
```5. 检查Bob 是否拥有所需的盒子。 

如果`target`存在于`bobSet`，然后交换`a`和`target`使总数相等。 
6. 返回有效的对。 

由于问题保证存在有效答案，因此可以立即返回第一个有效对。 

### 为什么它有效

 该算法是正确的，因为它直接推导出交换后总数相等所需的精确数学条件。 

等式：```
a - b = (sumAlice - sumBob) / 2
```充分描述每个有效交换的特征。 通过搜索匹配的`b`每个的价值`a`，如果存在的话，我们保证能找到正确的解决方案。 

哈希集确保此搜索高效。 

## Python 解决方案```python
from typing import List

class Solution:
    def fairCandySwap(self, aliceSizes: List[int], bobSizes: List[int]) -> List[int]:
        sum_alice = sum(aliceSizes)
        sum_bob = sum(bobSizes)

        difference = (sum_alice - sum_bob) // 2

        bob_set = set(bobSizes)

        for alice_box in aliceSizes:
            target = alice_box - difference

            if target in bob_set:
                return [alice_box, target]

        return []
```该实现首先计算 Alice 和 Bob 拥有的糖果总数。 需要这些总计才能以数学方式导出交换条件。 

接下来，代码计算交换框之间所需的差异。 这个值代表了爱丽丝交换的盒子必须有多大。 

然后，该解决方案将 Bob 的糖果尺寸转换为一组。 这是一项关键的优化，因为与搜索列表相比，集合成员资格检查速度非常快。 

该算法迭代爱丽丝拥有的每个糖果盒。 对于每个盒子，它都会计算鲍勃必须提供的确切糖果数量作为回报。 

如果鲍勃拥有这样一个盒子，则该对将立即归还。 

决赛`return []`语句在技术上是不必要的，因为问题保证了解决方案的存在，但包含它使得函数在语法上完整。 

## 解决方案```go
func fairCandySwap(aliceSizes []int, bobSizes []int) []int {
    sumAlice := 0
    sumBob := 0

    for _, value := range aliceSizes {
        sumAlice += value
    }

    for _, value := range bobSizes {
        sumBob += value
    }

    difference := (sumAlice - sumBob) / 2

    bobSet := make(map[int]bool)

    for _, value := range bobSizes {
        bobSet[value] = true
    }

    for _, aliceBox := range aliceSizes {
        target := aliceBox - difference

        if bobSet[target] {
            return []int{aliceBox, target}
        }
    }

    return []int{}
}
```Go 实现遵循与 Python 版本相同的逻辑。 

因为 Go 没有内置的集合类型，`map[int]bool`用于模拟哈希集。 

整数运算在这里是安全的，因为最大可能的糖果总数完全在 Go 的整数范围内。 

为了完整性，该函数在末尾返回一个空切片，即使问题保证存在有效答案。

 ## 边缘情况

 一种重要的边缘情况是每个数组仅包含一个元素。 在这种情况下，算法仍然必须正确计算总数并识别唯一可能的交换。 由于无论数组大小如何，该解决方案都使用相同的数学推导，因此它可以自然地处理这种情况，无需任何特殊逻辑。 

另一个重要的边缘情况涉及重复的糖果盒尺寸。 例如，鲍勃可能拥有几个糖果数量相同的盒子。 幼稚的实现可能会意外地执行冗余工作或错误地跟踪索引。 基于哈希集的解决方案完全避免了这个问题，因为它只需要知道有效的糖果计数是否存在，而不是它出现了多少次。 

大量糖果也需要考虑。 由于值可以达到`10^5`，总金额可能会变得相当大。 然而，Python 和 Go 中的最大可能总数仍然在标准整数限制内。 该实现使用正常的整数算术安全地处理这些值。 

当存在多个有效答案时，就会出现最后的边缘情况。 该问题明确允许返回任何有效的对。 该实现返回迭代期间遇到的第一个有效匹配，这满足了要求，但没有增加复杂性。
