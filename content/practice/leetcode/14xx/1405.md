[LeetCode 第 1405 题](https://leetcode.com/problems/longest-happy-string/)

 **难度：** 🟡 中等
 **主题：** 字符串、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题要求我们仅使用字符构造最长的字符串`'a'`,`'b'`， 和`'c'`，同时满足一个非常重要的限制：字符串不能包含三个连续的相同字符。 换句话说，像这样的子串`"aaa"`,`"bbb"`， 和`"ccc"`被禁止。 

我们得到三个整数：

 -`a`，最大数量`'a'`我们可能使用的字符
 -`b`，最大数量`'b'`我们可能使用的字符
 -`c`，最大数量`'c'`我们可能使用的字符

 目标是构建尽可能最长的有效字符串。 我们不需要使用每个字符。 有时不可能使用所有可用的字母，因为这样做会强制将三个相同的字符排成一行。 

例如，如果我们还有更多`'c'`字符比其他字符多，我们不能简单地连续附加所有字符。 我们必须有策略地在它们之间插入其他字母，以避免违反快乐字符串条件。 

限制相对较小：

 -`0 <= a, b, c <= 100`-`a + b + c > 0`由于字符总数最多为`300`，即使是相当昂贵的算法也可以工作。 然而，问题的结构强烈建议采用贪婪策略，因为在每一步中，我们都希望选择有助于最大化最终字符串长度而不创建无效序列的字符。 

一些边缘情况很重要：

 - 一两个字符计数可能为零。 
- 一个字符数可能会严重支配其他字符数，例如`(7,1,0)`。 
- 所有计数可能已经平衡。 
- 天真的贪婪策略可能会意外地造成死胡同，无法附加有效字符，即使另一个较早的选择将允许更长的结果。 

该问题保证至少有一个字符可用，因为`a + b + c > 0`。 

## 方法

 ### 蛮力方法

 暴力解决方案将递归地尝试每个可能的有效字符串。 在每个位置，我们可以尝试附加`'a'`,`'b'`， 或者`'c'`如果：

 1. 我们还有该角色的剩余计数。 
2. 附加它不会创建三个连续的相同字母。 

我们将递归地探索每个有效的延续并跟踪找到的最长结果。 

这种方法是正确的，因为它检查每个可能的有效快乐字符串，因此不会错过最佳答案。 

然而，它的效率极低。 可能的字符串数量随着字符总数呈指数增长。 即使进行了修剪，随着计数的增加，递归搜索空间也会变得非常大`100`。 

### 最优贪心法

 关键的观察是，我们应该始终尝试使用剩余数量最多的字符，因为稍后未使用的单个字符的太多副本可能会使它们无法放置。 

但是，我们不能每次都盲目地附加最常见的字符。 如果当前结果中的最后两个字符已经与该字符相同，则添加另一个字符将违反快乐字符串规则。 

这自然会导致具有最大堆的贪婪策略：

 - 存储按剩余频率排序的可用字符。 
- 重复选择剩余数量最多的角色。 
- 如果它将创建三个连续的相同字符，请暂时使用第二个最常见的字符。 
- 使用一个字符后，减少其计数，如果仍有副本，则将其推回到堆中。 

该策略始终优先考虑最丰富的字符，同时安全地避免无效的三元组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(3^(a+b+c)) | O(3^(a+b+c)) | O(a+b+c) | 递归地探索每个有效字符串 |
 | 最佳| O((a+b+c) log 3) | O(1) | O(1) | 贪婪的基于堆的构造 |

 因为只有三个角色，`log 3`实际上是恒定的，使得该解决方案在实践中极其有效。 

## 算法演练

 ### 最优贪心堆算法

 1. 创建一个最大堆，其中包含剩余计数为正数的所有字符。 

每个堆条目存储：

 - 负数，因为Python的`heapq`是一个最小堆
 - 角色本身

 例如：```
[(-7, 'c'), (-1, 'a'), (-1, 'b')]
```2. 初始化一个空的结果列表。 

我们使用列表而不是重复的字符串连接，因为附加到列表更有效。 
3. 重复提取剩余计数最大的字符。 

这种贪婪的选择尝试首先使用最丰富的字符，这样我们就不会在以后陷入许多无法使用的副本。 
4. 在追加字符之前，检查是否会创建三个连续的相同字母。 

具体来说：

 - 如果结果中的最后两个字符都等于候选字符
 - 然后附加它会违反快乐字符串条件
 5. 如果角色无法安全使用：

 - 从堆中删除第二个最常见的字符
 - 改为附加该字符
 - 减少其数量
 - 如果仍有副本，则将其推回
 - 最后将原来被阻塞的字符推回堆中
 6. 如果不存在替代字符，则停止。 

这意味着字符串的有效扩展是不可能的。 
7. 如果该字符可以安全附加：

 - 将其附加到结果中
 - 减少其剩余数量
 - 如果仍有副本，则将其推回
 8. 继续，直到堆变空或不存在有效的移动。 
9. 将结果列表连接成最终字符串并返回。 

### 为什么它有效

 该算法保持了一个重要的不变量：当前字符串始终有效，并且永远不会包含三个连续的相同字符。 

在每一步中，我们都会尽可能地贪婪地使用剩余计数最高的字符。 这可以最大程度地减少稍后留下过多的一个角色副本未使用的风险。 如果无法安全地使用最佳字符，算法会暂时使用下一个最佳替代字符来保持有效性。 

因为每一步要么安全地使用最丰富的字符，要么使用最佳的可用后备，因此该算法会构造一个最长的可能的快乐字符串。 

## Python 解决方案```python
from heapq import heappush, heappop
from typing import List

class Solution:
    def longestDiverseString(self, a: int, b: int, c: int) -> str:
        max_heap = []

        if a > 0:
            heappush(max_heap, (-a, 'a'))

        if b > 0:
            heappush(max_heap, (-b, 'b'))

        if c > 0:
            heappush(max_heap, (-c, 'c'))

        result = []

        while max_heap:
            count1, char1 = heappop(max_heap)

            # Check whether adding this character
            # would create three consecutive letters
            if (
                len(result) >= 2 and
                result[-1] == char1 and
                result[-2] == char1
            ):
                # No alternative character exists
                if not max_heap:
                    break

                count2, char2 = heappop(max_heap)

                result.append(char2)
                count2 += 1

                if count2 < 0:
                    heappush(max_heap, (count2, char2))

                heappush(max_heap, (count1, char1))

            else:
                result.append(char1)
                count1 += 1

                if count1 < 0:
                    heappush(max_heap, (count1, char1))

        return ''.join(result)
```该实现首先构建一个包含所有具有正计数的字符的最大堆。 自从Python的`heapq`实现最小堆，使用负计数，以便首先出现较大的频率。 

这`result`list 递增地存储最终字符串的字符。 列表优于重复的字符串连接，因为附加到列表更有效。 

在主循环内，算法删除剩余频率最高的字符。 在追加之前，代码会检查当前结果中的最后两个字符是否已与该字符匹配。 如果这样做，附加它会创建一个无效的子字符串，例如`"aaa"`。 

发生这种情况时，算法会暂时选择第二个最常见的字符。 使用替代字符后，被阻止的字符将被推回堆中，以便稍后重新考虑。 

如果没有替代方案，施工就会停止，因为不可能进行有效的扩展。 

每次追加操作后都会更新计数。 由于计数存储为负数，因此增加值会将其移向零。 

最后，将结果列表连接成字符串并返回。 

## 解决方案```go
package main

import (
	"container/heap"
)

type Node struct {
	count int
	char  byte
}

type MaxHeap []Node

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i].count > h[j].count
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(Node))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func longestDiverseString(a int, b int, c int) string {
	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	if a > 0 {
		heap.Push(maxHeap, Node{count: a, char: 'a'})
	}

	if b > 0 {
		heap.Push(maxHeap, Node{count: b, char: 'b'})
	}

	if c > 0 {
		heap.Push(maxHeap, Node{count: c, char: 'c'})
	}

	result := make([]byte, 0)

	for maxHeap.Len() > 0 {
		first := heap.Pop(maxHeap).(Node)

		n := len(result)

		if n >= 2 &&
			result[n-1] == first.char &&
			result[n-2] == first.char {

			if maxHeap.Len() == 0 {
				break
			}

			second := heap.Pop(maxHeap).(Node)

			result = append(result, second.char)
			second.count--

			if second.count > 0 {
				heap.Push(maxHeap, second)
			}

			heap.Push(maxHeap, first)

		} else {
			result = append(result, first.char)
			first.count--

			if first.count > 0 {
				heap.Push(maxHeap, first)
			}
		}
	}

	return string(result)
}
```Go 实现遵循与 Python 版本相同的贪婪堆策略。 由于 Go 没有提供内置的最大堆，因此我们实现了`heap.Interface`手动并反转比较`Less`方法，以便较大的计数具有较高的优先级。 

该实现不是直接将字符存储在字符串生成器中，而是使用`[]byte`用于高效追加操作的切片。 最后，字节切片被转换为字符串。 

与 Python 的负计数技巧不同，Go 实现将计数存储为正整数，因为自定义堆排序已经表现得像最大堆。

 ## 边缘情况

 当只有一种字符类型可用时，会出现一种重要的边缘情况，例如`(3,0,0)`。 一个幼稚的实现可能会附加所有三个`'a'`人物和产物`"aaa"`，这是无效的。 基于堆的算法可以防止这种情况，因为它在每次追加之前显式检查最后两个字符。 一次`"aa"`已经形成，再添加一个`'a'`被禁止，算法停止。 

另一种重要的情况是当一个字符数远大于其他字符数时，例如`(100,1,1)`。 如果没有仔细的平衡，许多角色将变得无法使用。 贪婪策略通过在必要时重复插入分隔符来正确处理此问题。 最终，分隔符用完，算法以可实现的最长有效字符串终止。 

当最常用的字符暂时无法使用，但另一个有效字符仍然存在时，就会发生第三种边缘情况。 例如，构建后`"cc"`， 其他`'c'`无法立即添加。 天真的贪婪解决方案可能会错误地在此时停止。 相反，该算法从堆中删除第二个最常见的字符并将其用作分隔符，从而允许继续构建。 

当所有计数已经平衡时，会出现最后一个微妙的情况，例如`(2,2,2)`。 该算法仍然可以正确工作，因为它始终优先选择当前最丰富的字符，同时保持有效性。 由于没有一个角色会成为压倒性的主导角色，因此所有角色通常都可以成功使用。
