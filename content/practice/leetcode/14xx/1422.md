[LeetCode 第 1422 题](https://leetcode.com/problems/maximum-score-after-splitting-a-string/)

 **难度：** 🟢简单
 **主题：** 字符串、前缀和

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`，表示字符串仅包含字符`'0'`和`'1'`。 我们必须将该字符串拆分为两个非空部分，一个左子字符串和一个右子字符串。 

对于每个可能的分割位置，我们计算一个分数，定义为：

 - 数量`'0'`左子串中的字符
 - 加上数量`'1'`右子串中的字符

 我们的任务是返回所有有效分割中的最大可能分数。 

分割只能发生在字符之间，并且两边必须至少包含一个字符。 如果字符串长度为`n`，那么有效的分割位置来自索引`1`通过`n - 1`。 

例如，考虑：```
s = "011101"
```如果我们在第一个字符之后分割：```
left  = "0"
right = "11101"
```左边有一个零，右边有四个一，所以分数是：```
1 + 4 = 5
```我们必须检查每一个可能的分割并确定最高分。 

限制很小：

 -`2 <= s.length <= 500`由于字符串长度最多为 500，即使是`O(n^2)`解决方案在技术上会通过。 然而，该问题旨在鼓励更有效的线性解决方案。 

一些边缘情况很重要：

 - 包含所有 1 的字符串，例如`"1111"`- 开头包含多个零的字符串
 - 长度为 2 的非常短的字符串
 - 在字符串的开头或结尾附近分割
 - 确保两个子字符串均不为空

 该问题保证字符串仅包含二进制数字，因此我们永远不需要处理无效字符。 

## 方法

 ### 蛮力方法

 蛮力解决方案会尝试所有可能的分割位置。 

对于每个分割：

 1. 构建左子串。 
2. 构建正确的子字符串。 
3. 计算左子串中的零。 
4. 计算右侧子串中的个数。 
5. 计算分数。 
6. 追踪最高分。 

这种方法是正确的，因为它详尽地检查了每个有效的分割并直接根据问题陈述计算分数定义。 

然而，重复扫描子串变得低效。 如果字符串长度为`n`， 有`n - 1`分割位置，每个分割可能需要扫描最多`n`人物。 这导致`O(n^2)`时间复杂度。 

尽管限制足够小，可以通过，但我们可以做得更好。 

### 最佳方法

 关键的观察结果是，从左向右移动分割点会以可预测的方式改变分数。 

假设我们最初计算字符串中除第一个字符的位置之外的所有字符。 然后我们一次移动分割的一个角色。 

当一个字符从右子串移动到左子串时：

 - 如果角色是`'0'`，左侧得一零，因此分数加 1。 
- 如果角色是`'1'`，右侧输一一，因此得分减1。 

这意味着我们可以增量地维护分数，而不是从头开始重新计算计数。 

我们只需要：

 - 左侧连续计数零
 - 右侧的连续计数
 - 迄今为止看到的最高分数

 这产生了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重新计算每个分割的计数 |
 | 最佳 | O(n) | O(1) | O(1) | 扫描一次时保持运行计数 |

 ## 算法演练

 1. 统计总数量`'1'`字符串中的字符。 

这为我们提供了处理分割之前右侧可用的初始数量。 
2.初始化两个变量：

 -`left_zeros = 0`-`right_ones = total number of ones`这些代表当前分数组成部分。 
3. 从索引处迭代字符串`0`到`n - 2`。 

我们停在`n - 2`因为右子串必须保持非空。 
4. 对于每个字符：

 - 如果角色是`'0'`, 增量`left_zeros`。 
- 如果角色是`'1'`, 递减`right_ones`。 

这模拟将当前字符从右子字符串移动到左子字符串。 
5. 计算当前分数：```
score = left_zeros + right_ones
```6. 如果当前分数更大，则更新最大分数。 
7.处理完所有有效的分割位置后，返回最大分数。 

### 为什么它有效

 在每次迭代中，算法都会保持一个不变量：

 -`left_zeros`等于左子串中零的数量
 -`right_ones`等于右子串中的个数

 由于每个有效的分割都被处理一次，并且每个分割的分数都被正确计算，所以记录的最大分数一定是正确的答案。 

## Python 解决方案```python
class Solution:
    def maxScore(self, s: str) -> int:
        right_ones = s.count("1")
        left_zeros = 0
        max_score = 0

        for i in range(len(s) - 1):
            if s[i] == "0":
                left_zeros += 1
            else:
                right_ones -= 1

            current_score = left_zeros + right_ones
            max_score = max(max_score, current_score)

        return max_score
```实现首先对字符串中的所有数字进行计数。 最初，每个字符都属于右侧子字符串，因此该计数表示右侧子字符串的起始数量。 

变量`left_zeros`从零开始，因为左子串最初是空的。 

循环仅迭代到`len(s) - 2`，确保正确的子字符串永远不会变空。 

在每次迭代期间：

 - 零增加左贡献
 - 一减少正确的贡献

 更新计数后立即计算当前分数。 该算法使用以下方式跟踪迄今为止找到的最佳分数`max_score`。 

由于计数是增量更新的，因此该解决方案避免了重新扫描子字符串并实现了线性性能。 

## 解决方案```go
func maxScore(s string) int {
	rightOnes := 0

	for _, ch := range s {
		if ch == '1' {
			rightOnes++
		}
	}

	leftZeros := 0
	maxScore := 0

	for i := 0; i < len(s)-1; i++ {
		if s[i] == '0' {
			leftZeros++
		} else {
			rightOnes--
		}

		currentScore := leftZeros + rightOnes

		if currentScore > maxScore {
			maxScore = currentScore
		}
	}

	return maxScore
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个小小的区别是 Go 字符串以字节为索引。 由于字符串仅包含 ASCII 字符`'0'`和`'1'`，直接字节索引`s[i]`完全安全高效。 

由于最大字符串长度仅为 500，因此不需要对整数溢出进行特殊处理。

 ## 边缘情况

 ### 所有人

 像这样的字符串`"1111"`很容易导致错误，因为左子串永远不会为零。 得分完全取决于右侧还有多少人。 

该实现正确地处理了这个问题，因为每次`'1'`移动到左边的子串，`right_ones`减少一。 因此，最好的分裂尽可能早地发生。 

### 全零

 像这样的字符串`"0000"`根本没有。 幼稚的实现可能会错误地假设分数必须至少包括一个右侧分数。 

该算法可以正确工作，因为`right_ones`从零开始，并在整个过程中保持为零。 分数完全取决于左侧累积了多少个零。 

### 最小长度输入

 最小可能的字符串长度为 2。示例包括`"01"`和`"10"`。 

这种情况很重要，因为只有一个有效的分割位置。 循环条件`range(len(s) - 1)`正确地处理一次拆分并避免无效的空子字符串。
