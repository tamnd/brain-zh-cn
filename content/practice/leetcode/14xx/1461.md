[LeetCode 问题 1461](https://leetcode.com/problems/check-if-a-string-contains-all-binary-codes-of-size-k/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、位操作、滚动哈希、哈希函数

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`和一个整数`k`。 二进制字符串仅包含字符`'0'`和`'1'`。 我们必须确定是否每个可能的二进制代码长度`k`出现在里面的某个地方`s`作为子串。 

长度的二进制代码`k`只是任意序列`k`位。 由于每个位置都可以独立`0`或者`1`，正好有：$2^k$可能的二进制码长度`k`。 

例如，如果`k = 2`，可能的代码是：

 -`"00"`-`"01"`-`"10"`-`"11"`我们需要检查所有这些是否都出现在字符串中的某个位置。 

子字符串表示字符串的连续部分。 如果`s = "00110110"`和`k = 2`，长度为2的子串是：

 -`"00"`-`"01"`-`"11"`-`"10"`-`"01"`-`"11"`-`"10"`所有四种可能的二进制代码都出现了，所以答案是`true`。 

约束条件很重要：

 -`s.length`可以大到`500,000`-`k`可以达到`20`这些限制立即排除了低效的解决方案。 重复搜索字符串以查找每个可能的二进制代码的简单方法在以下情况下会变得太慢：`k`很大。 

另一个重要的观察结果来自可能的子串的总数。 一个长度的字符串`n`至多包含：$n-k+1$长度子串`k`。 

如果这个数量小于`2^k`，那么不可能所有的代码都存在。 这为我们提供了重要的早期优化。 

一些重要的边缘情况包括：

 - 非常小的弦
 -`k = 1`- 包含许多重复模式的字符串
 - 可用子串数量小于的情况`2^k`- 大值`k`，显式生成所有二进制字符串变得昂贵

 该问题保证字符串仅包含`'0'`和`'1'`，这简化了实施。 

## 方法

 ### 蛮力方法

 最直接的方法是生成每个可能的长度的二进制字符串`k`，然后检查每一个是否作为子串存在于内部`s`。 

例如，如果`k = 3`，我们将生成：

 -`"000"`-`"001"`-`"010"`-`"011"`-`"100"`-`"101"`-`"110"`-`"111"`对于每个生成的字符串，我们可以使用子字符串搜索来确定它是否出现在`s`。 

这种方法是正确的，因为它显式验证了每个所需的二进制代码。 然而，对于给定的约束来说它太慢了。 

有`2^k`可能的代码，子串搜索成本高达`O(n)`每次。 总复杂度变为：$O(n\cdot 2^k)$什么时候`k = 20`，有超过一百万种可能的二进制代码，这使得这是不可行的。 

### 最佳方法

 关键的见解是我们不需要显式生成所有二进制字符串。 相反，我们可以扫描输入字符串一次并记录每个不同长度的子字符串`k`。 

如果我们发现的不同子串的数量等于`2^k`，则每个二进制代码都存在。 

滚动散列或位掩码技术使得这一点特别有效。 

因为字符串只包含二进制数字，所以每个子串的长度`k`可以表示为之间的整数`0`和`2^k - 1`。 

例如：

 | 二进制| 整数 |
 | ---| ---|
 |`00`| 0 |
 |`01`| 1 |
 |`10`| 2 |
 |`11`| 3 |

 当我们在字符串上滑动窗口时，我们使用位操作在恒定时间内不断更新这个整数表示。 

这避免了重复的子串构造并给出了有效的线性时间解决方案。

 ## 算法演练

 1. 首先，计算我们必须找到的二进制代码的总数。 

有：$2^k$可能的二进制字符串长度`k`。 
2. 检查字符串是否足够长以包含所有代码。 

一个长度的字符串`n`至多包含：$n-k+1$长度子串`k`。 

如果这个数字小于`2^k`，立即返回`false`。 
3. 创建一个集合来存储遇到的所有不同的二进制代码。 

我们使用集合是因为​​我们只关心代码是否出现，而不关心出现了多少次。 
4. 维护一个代表当前窗口大小的滚动整数值`k`。 

当我们浏览字符串时：

 - 将当前值左移一位
 - 从字符串中添加新位
 - 删除超出长度的位`k`使用面罩
 5. 掩码确保只有最后一个`k`保留位。 

掩码值为：$2^k-1$这使得滚动值精确地保持在`k`位。 
6.一旦我们至少处理了`k`字符，将当前滚动值添加到集合中。 
7. 如果设定的尺寸达到`2^k`， 返回`true`立即地。 

这意味着我们已经发现了所有可能的二进制代码。 
8. 如果循环结束而没有找到所有代码，则返回`false`。 

### 为什么它有效

 每个子串的长度`k`唯一对应于`k`位整数。 滚动位掩码始终准确地表示当前子字符串窗口。 通过扫描每个可能的窗口一次并存储所有不同的值，我们精确地收集了字符串中存在的二进制代码集。 如果不同代码的数量等于`2^k`，那么所有可能的二进制代码都出现了。 

## Python 解决方案```python
class Solution:
    def hasAllCodes(self, s: str, k: int) -> bool:
        n = len(s)
        total_codes = 1 << k
        
        # Not enough substrings to contain all codes
        if n - k + 1 < total_codes:
            return False
        
        seen = set()
        current = 0
        mask = total_codes - 1
        
        for i, char in enumerate(s):
            current = ((current << 1) & mask) | int(char)
            
            # Start recording once window size reaches k
            if i >= k - 1:
                seen.add(current)
                
                # Early exit if all codes found
                if len(seen) == total_codes:
                    return True
        
        return False
```该实现首先使用计算可能的二进制代码的总数`1 << k`，它计算`2^k`。 

早期的不可能检查极其重要。 如果字符串没有足够的长度 -`k`子串，无需继续。 

这`seen`set 存储已发现的二进制子串的整数表示。 

变量`current`充当滚动哈希。 每次迭代都会将先前的位左移并插入字符串中的新位。 

表达式：```python
((current << 1) & mask)
```删除超出长度的任何额外位`k`。 

一旦指数达到`k - 1`，我们知道当前滚动值代表大小的完整子串`k`，所以我们将其添加到集合中。 

一旦发现所有代码，早期返回优化可以避免不必要的工作。 

## 解决方案```go
func hasAllCodes(s string, k int) bool {
	n := len(s)
	totalCodes := 1 << k

	// Not enough substrings to contain all codes
	if n-k+1 < totalCodes {
		return false
	}

	seen := make(map[int]bool)
	current := 0
	mask := totalCodes - 1

	for i := 0; i < n; i++ {
		bit := int(s[i] - '0')

		current = ((current << 1) & mask) | bit

		// Start recording once window size reaches k
		if i >= k-1 {
			seen[current] = true

			// Early exit if all codes found
			if len(seen) == totalCodes {
				return true
			}
		}
	}

	return false
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 使用的不是 Python 集`map[int]bool`跟踪观察到的二进制代码。 

字符转换略有不同，因为 Go 字符串是字节切片。 表达式：```go
int(s[i] - '0')
```转换字符`'0'`或者`'1'`化为整数`0`或者`1`。 

Go 整数对于约束来说足够大，因为`k <= 20`，表示最大存储值小于`2^20`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个字符被处理一次 |
 | 空间| O(2^k) | O(2^k) | 该集合可以存储所有可能的二进制代码 |

 该算法只扫描字符串一次。 循环内的每个操作都是恒定时间，因为位操作和哈希集插入都是高效的。 

空间复杂度取决于存储了多少个唯一的二进制代码。 在最坏的情况下，我们可能会存储所有`2^k`可能的代码。

 ## 边缘情况

 当字符串太短而无法包含所有二进制代码时，就会出现一种重要的边缘情况。 例如，如果`s = "000"`和`k = 3`，只有一个长度为3的子串，但需要八个不同的二进制代码。 幼稚的实现可能仍然会执行不必​​要的工作。 早期的不可能性检查可以防止这种低效率并立即返回`false`。 

另一个重要的例子涉及重复模式。 考虑`s = "111111"`和`k = 2`。 遇到的唯一子字符串是`"11"`反复。 如果没有正确处理重复项，实现可能会错误地将重复出现的次数计为新代码。 使用集合可保证每个二进制代码仅计算一次。 

当出现第三种边缘情况时`k = 1`。 在这种情况下，算法必须简单地验证两者`'0'`和`'1'`出现在字符串中的某处。 滚动位掩码实现仍然可以正常工作，因为掩码变为`1`，在处理过程中仅保留一位。 

最后一个微妙的边缘情况涉及较大的值`k`，特别是在最大值附近`20`。 重复构造子字符串会在时间和内存方面变得昂贵。 通过位操作将每个子字符串表示为整数可以避免不必要的字符串分配，并且即使在最大约束下也能保持算法的效率。
