 # LeetCode 1407 - 顶级旅行者

 ## 问题理解

 这个问题给了我们两个数据库表，`Users`和`Rides`。 

这`Users`表包含有关每个用户的信息。 每个用户都有独特的`id`以及相应的`name`。 

这`Rides`表包含乘车记录。 每个骑行都有其独特之处`id`, 一个`user_id`指示哪个用户乘坐了行程，以及`distance`代表行程的距离。 

目标是计算每个用户的总行驶距离。 这意味着我们必须将属于同一用户的所有骑行距离相加。 

需求中有几个重要的细节：

 1. 每个用户都必须出现在最终结果中，即使他们从未乘坐过。 
2. 没有乘车的用户的行驶距离应为`0`。 
3. 结果必须按以下顺序排序：

 -`travelled_distance`按降序排列
 -`name`当距离相等时按字母升序排列

 从概念上讲，这是一个经典的 SQL 聚合问题，涉及：

 - 连接两个表
 - 按用户分组游乐设施
 - 距离求和
 - 处理丢失的乘车记录
 - 对最终输出进行排序

 对于这个简单级别的问题，输入大小相对较小，但主要挑战是理解 SQL 连接和聚合如何交互。 

简单的实现很容易在以下几个方面失败：

 - 使用`INNER JOIN`而不是`LEFT JOIN`，这将排除没有乘车的用户。 
- 忘记更换`NULL`与`0`。 
- 仅按距离排序，忽略次要字母顺序规则。 
- 分组不正确并产生重复的用户。 

该问题保证：

 -`Users.id`是独一无二的。 
-`Rides.id`是独一无二的。 
-`Rides.user_id`引用有效用户。 

这意味着我们不需要担心无效的外键。 

## 方法

 ### 蛮力方法

 暴力方法将独立处理每个用户。 

对于每个用户`Users`表：

 1. 扫描整个`Rides`桌子。 
2. 收集属于该用户的所有游乐设施。 
3. 将它们的距离相加。 
4. 存储结果。 

计算每个用户的总数后，根据所需的排序规则对最终列表进行排序。 

这种方法是正确的，因为每次骑行都会针对每个用户进行检查，确保所有相关距离都包含在总数中。 

然而，这种方法效率低下，因为`Rides`重复扫描表。 如果有`U`用户和`R`乘车，总工作量变为`O(U × R)`。 

### 最佳方法

 关键的观察是我们应该只聚合一次骑行距离。 

我们可以：

 1. 团体乘车`user_id`。 
2. 计算单次传递中每个用户的距离总和。 
3. 将聚合结果与`Users`桌子。 

在 SQL 中，这自然可以使用以下方法解决：

 -`LEFT JOIN`-`GROUP BY`-`SUM`-`COALESCE`这`LEFT JOIN`确保没有乘车的用户仍然出现。 

聚合只计算一次每个用户的总行驶距离，从而使解决方案更加高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(U × R) | O(1) 额外 | 扫描每个用户的所有游乐设施 |
 | 最佳 | O(U + R) | O(U) | 聚合骑行一次并高效加入 |

 ## 算法演练

 1. 从`Users`表，因为每个用户都必须出现在输出中，包括没有乘车的用户。 
2. 执行`LEFT JOIN`之间`Users`和`Rides`使用：```
Users.id = Rides.user_id
```一个`LEFT JOIN`保留所有行`Users`，即使不存在匹配的行程。 
3. 按以下方式对连接的行进行分组：```
Users.id, Users.name
```分组允许我们聚合属于同一用户的所有游乐设施。 
4. 使用以下公式计算总行驶距离：```
SUM(Rides.distance)
```这会将每个用户的所有距离加在一起。 
5、没有乘车的用户会产生`NULL`从`SUM`聚合。 将这些值转换为`0`使用：```
COALESCE(SUM(Rides.distance), 0)
```6. 将聚合列重命名为：```
travelled_distance
```7.对最终结果进行排序：

 - 首先由`travelled_distance DESC`- 然后通过`name ASC`8. 返回结果表。 

### 为什么它有效

 该算法之所以有效，是因为每次乘坐都与一个用户相关联`user_id`。 这`GROUP BY`操作将属于同一用户的所有游乐设施收集到一组中，并且`SUM`计算该组的总距离。 

使用`LEFT JOIN`保证没有乘车的用户仍然包含在内。`COALESCE`将缺失的总数转换为`NULL`到`0`，满足问题要求。 

排序步骤强制执行问题陈述中指定的确切顺序。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT
    u.name,
    COALESCE(SUM(r.distance), 0) AS travelled_distance
FROM Users u
LEFT JOIN Rides r
    ON u.id = r.user_id
GROUP BY u.id, u.name
ORDER BY travelled_distance DESC, u.name ASC;
```查询开始于`Users`表，因为每个用户都必须出现在输出中。 

这`LEFT JOIN`将每个用户与他们的游乐设施连接起来。 如果用户没有行程，则加入的行程列将变为`NULL`，但用户行仍然保留。 

这`GROUP BY`子句为每个用户创建一个组。 在每个组内，`SUM(r.distance)`计算总行驶距离。 

对于没有乘车的用户，总和变为`NULL`。 这`COALESCE`函数将其替换为`0`。 

最后，`ORDER BY`子句应用所需的排序：

 - 按行驶距离递减
 - 当距离相等时按名称字母顺序升序

 ## 边缘情况

 ### 没有乘车的用户

 一个非常常见的错误是使用`INNER JOIN`。 这将完全排除从未乘车的用户。 

例如，Donald 在样本输入中没有乘车。 没有一个`LEFT JOIN`，唐纳德将从结果中完全消失。 

该实现通过显式使用以下方式避免了此问题：```
LEFT JOIN
```这保证了每个用户都保留在输出中。 

### NULL 聚合结果

 当用户没有乘车时，`SUM(distance)`回报`NULL`， 不是`0`。 

如果我们不小心处理这个问题，输出将包含`NULL`值而不是所需的数字距离。 

该查询使用以下方法解决了这个问题：```
COALESCE(SUM(r.distance), 0)
```这会将缺失的总数正确转换为零。 

### 具有相等总距离的多个用户

 两个或多个用户可以行进相同的总距离。 

例如：

 - 埃尔维斯旅行了 450 次
 - 李旅行了 450 次

 当距离相等时，该问题需要按字母顺序排序。 

该实现通过以下方式处理此问题：```
ORDER BY travelled_distance DESC, u.name ASC
```这保证了确定性和正确的排序。 

### 多次乘坐的用户

 一个用户可能会出现多次`Rides`桌子。 

如果分组被省略或不正确，结果可能包含重复的行，而不是每个用户总共包含一个行。 

使用：```
GROUP BY u.id, u.name
```确保同一用户的所有行程都聚合到最后一行。
