[LeetCode 问题 1489](https://leetcode.com/problems/find-ritic-and-pseudo-ritic-edges-in-minimum-spanning-tree/)

 **难度：** 🔴难
 **主题：**并查集、图论、排序、最小生成树、强连通分量

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个连通的、加权的、无向的图，其中`n`顶点和边列表。 每条边都表示为`[u, v, weight]`，意味着顶点之间存在双向连接`u`和`v`与给定的成本。 

目标不仅仅是计算一棵最小生成树 (MST)。 相反，我们必须将每条边分为两类之一：

 - 关键边缘
 - 伪关键边缘

 要理解这些类别，我们首先需要回顾一下 MST 是什么。 

MST 是边的子集：

 - 连接所有顶点
 - 不包含循环
 - 总重量尽可能小

 如果多条边共享相同的权重，则连通图可能具有多个不同的 MST。 

临界边是必须出现在每个有效 MST 中的边。 如果删除这条边会导致最小可实现的 MST 权重增加，或者根本无法形成生成树，那么这条边就至关重要。 

伪临界边是可以出现在至少一个MST中但不是所有MST中都需要的边。 换句话说，存在某个包含该边的最优 MST，但也存在另一个不包含该边的最优 MST。 

输出必须包含两个列表：

 - 第一个列表包含所有关键边缘索引
 - 第二个列表包含所有伪临界边索引

 原始边缘索引很重要，因为边缘将在处理过程中在内部进行排序。 

约束条件很重要：

 -`n <= 100`-`edges.length <= 200`这些限制足够小，我们可以多次运行 MST 构建。 这里不需要高度优化的近线性 MST 算法。 相反，我们可以在不同条件下重复运行 Kruskal 算法。 

一些重要的边缘情况立即脱颖而出：

 - 多个边可以具有相同的权重，从而导致多个有效的 MST
 - 边缘可能看起来是可选的，即使它在本地看起来很重要
 - 删除某些边可能会完全断开图表
 - 具有许多等权边的密集图可以产生许多伪临界边
 - 保证图一开始就是连通的，这意味着至少有一个MST总是存在

 关键挑战是确定每条边如何影响 MST 的结构和成本。 

## 方法

 ### 蛮力方法

 蛮力的想法是枚举图的每个可能的生成树，计算其总权重，确定其中的最小值，然后检查哪些边出现在所有最小生成树中，而不是仅出现在某些最小生成树中。 

生成树为`n`顶点恰好包含`n - 1`边缘。 理论上我们可以生成以下的每种组合`n - 1`边，检查它是否形成有效的生成树，计算其权重，并将其与全局最小值进行比较。 

这是可行的，因为关键边缘和伪关键边缘的定义直接基于所有 MST 的集合。 

然而，这种方法在计算上是不可行的。 具有最多 200 条边的图需要检查大量边子集：$$\binom{200}{99}$$即使验证每个子集也需要图遍历或并查操作。 总运行时间变得非常大。 

### 最佳方法

 关键的见解是我们不需要枚举所有 MST。 相反，我们可以利用克鲁斯卡尔算法的属性。 

Kruskal 算法通过以下方式构建 MST：

 1. 按权重对边进行排序
 2. 如果边不形成环则贪婪地添加边

 这会产生一个有效的 MST。 

现在考虑一个边缘`e`。 

判断是否`e`很关键：

 - 删除`e`- 重新计算MST
 - 如果新的MST权重增加，或者不存在MST，则`e`很关键

 为什么这有效？ 

因为如果排除`e`强制使用更昂贵的生成树，那么每个最优 MST 必须包含`e`。 

判断是否`e`是伪临界的：

 - 力量`e`首先被纳入
 - 然后使用Kruskal正常完成MST
 - 如果生成的 MST 与原始 MST 的总权重相同，则`e`可以属于某个 MST

 这是有效的，因为我们显式地构建了包含该边的最佳 MST。 

约束足够小，每个边运行一次 Kruskal 是完全可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 枚举所有生成树|
 | 最佳 | O(E² log E) | O(E² log E) | O(E) | 使用包含/排除检查重复 Kruskal |

 ## 算法演练

 ### 第 1 步：附上原始索引

 边将按权重排序，但答案必须返回原始索引。 

因此，我们将每条边转换为：```
[u, v, w]
```进入：```
[u, v, w, original_index]
```这允许我们对边进行排序，同时仍然记住它们在输入中的位置。 

### 第 2 步：按权重对边进行排序

 Kruskal 算法要求按权重非递减顺序处理边。 

排序确保我们总是首先尝试添加最便宜的有效边。 

### 步骤 3：实施并查

 Union-Find，也称为不相交集并集 (DSU)，可以有效地跟踪连接的组件。 

我们需要两个操作：

 -`find(x)`返回组件的代表
 -`union(x, y)`如果两个组件不同，则合并它们

 Union-Find 在这里是理想的选择，因为 Kruskal 反复询问：

 - 这些顶点是否已经连接？ 
- 如果没有，则合并它们

 使用路径压缩和按等级并集可以使操作保持几乎恒定的时间。 

### 步骤 4：构建通用 Kruskal 函数

 我们创建一个辅助函数，在两个可选条件下计算 MST 权重：

 - 排除特定边缘
 - 强制包含特定边缘

 这种抽象避免了重复 MST 逻辑。 

该函数的工作原理如下：

 1.初始化DSU
 2. 如果必须包含边：

 - 添加其重量
 - 联合其端点
 3. 迭代所有已排序的边
 4. 跳过排除的边
 5. 添加连接不同组件的边
 6. 跟踪 MST 总权重和边数
 7. 如果我们无法连接所有顶点，则返回无穷大

 返回无穷大很有用，因为断开连接的图无法形成有效的 MST。 

### 步骤 5：计算基线 MST 权重

 运行一次标准 Kruskal，无需排除或强制边缘。 

这给出了图表的最小可能 MST 权重。 

调用这个：```
base_weight
```以后所有的比较都是根据这个值来衡量的。 

### 第 6 步：识别关键边缘

 对于每条边：

 1. 重新计算 MST，同时排除该边
 2. 将所得重量与`base_weight`如果：```
new_weight > base_weight
```或者图变得断开，那么边就很关键。 

这意味着边缘对于实现最低成本是必不可少的。 

### 步骤 7：识别伪关键边缘

 对于每个非关键边：

 1. 将边缘强行放入 MST
 2、正常完成MST建设
 3. 比较总重量`base_weight`如果权重保持相等，则边缘可以参与某些最佳 MST。 

因此它是伪临界的。 

### 为什么它有效

 Kruskal 算法总是构建具有最小可能权重的 MST。 

如果删除一条边会增加最佳权重，则每个 MST 都必须包含该边，这使其变得至关重要。 

如果强制边缘仍然允许构造具有最佳权重的 MST，则至少一个有效的 MST 包含它，使其成为伪关键。 

这些检查直接匹配两个类别的数学定义。 

## Python 解决方案```python
from typing import List

class UnionFind:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x: int) -> int:
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x: int, y: int) -> bool:
        root_x = self.find(x)
        root_y = self.find(y)

        if root_x == root_y:
            return False

        if self.rank[root_x] < self.rank[root_y]:
            root_x, root_y = root_y, root_x

        self.parent[root_y] = root_x

        if self.rank[root_x] == self.rank[root_y]:
            self.rank[root_x] += 1

        return True

class Solution:
    def findCriticalAndPseudoCriticalEdges(
        self,
        n: int,
        edges: List[List[int]]
    ) -> List[List[int]]:

        indexed_edges = []

        for index, (u, v, w) in enumerate(edges):
            indexed_edges.append([u, v, w, index])

        indexed_edges.sort(key=lambda edge: edge[2])

        def kruskal(exclude_edge: int = -1,
                    include_edge: int = -1) -> int:

            uf = UnionFind(n)
            total_weight = 0
            edges_used = 0

            if include_edge != -1:
                u, v, w, _ = indexed_edges[include_edge]

                if uf.union(u, v):
                    total_weight += w
                    edges_used += 1

            for i, (u, v, w, _) in enumerate(indexed_edges):

                if i == exclude_edge:
                    continue

                if uf.union(u, v):
                    total_weight += w
                    edges_used += 1

                if edges_used == n - 1:
                    break

            if edges_used != n - 1:
                return float("inf")

            return total_weight

        base_weight = kruskal()

        critical = []
        pseudo_critical = []

        for i in range(len(indexed_edges)):

            if kruskal(exclude_edge=i) > base_weight:
                critical.append(indexed_edges[i][3])

            elif kruskal(include_edge=i) == base_weight:
                pseudo_critical.append(indexed_edges[i][3])

        return [critical, pseudo_critical]
```该实现首先用其原始索引来增加每条边。 这是必要的，因为排序会改变边缘顺序，但输出必须引用原始位置。 

这`UnionFind`类支持 MST 构建期间的高效连接检查。 路径压缩优化重复`find`操作，而按等级联合可以防止树变得不平衡。 

这`kruskal`辅助函数是解决方案的核心。 它支持两种可选行为：

 - 不包括一条边
 - 强制一条边进入 MST

 如果强制使用边缘，则会在正常处理开始之前添加边缘。 然后，按照与标准 Kruskal 完全相同的排序顺序处理其余边。 

当图无法完全连接时，助手返回无穷大。 这允许断开连接的情况自动失败比较检查。 

基线 MST 权重计算一次。 然后每条边都经过两次测试：

 - 关键性排除测试
 - 伪临界性的包含测试

 最终答案包含各自类别中的原始边缘索引。 

## 解决方案```go
package main

import "sort"

type UnionFind struct {
	parent []int
	rank   []int
}

func NewUnionFind(n int) *UnionFind {
	parent := make([]int, n)
	rank := make([]int, n)

	for i := 0; i < n; i++ {
		parent[i] = i
	}

	return &UnionFind{
		parent: parent,
		rank:   rank,
	}
}

func (uf *UnionFind) Find(x int) int {
	if uf.parent[x] != x {
		uf.parent[x] = uf.Find(uf.parent[x])
	}

	return uf.parent[x]
}

func (uf *UnionFind) Union(x, y int) bool {
	rootX := uf.Find(x)
	rootY := uf.Find(y)

	if rootX == rootY {
		return false
	}

	if uf.rank[rootX] < uf.rank[rootY] {
		rootX, rootY = rootY, rootX
	}

	uf.parent[rootY] = rootX

	if uf.rank[rootX] == uf.rank[rootY] {
		uf.rank[rootX]++
	}

	return true
}

func findCriticalAndPseudoCriticalEdges(n int, edges [][]int) [][]int {

	indexedEdges := make([][]int, 0)

	for i, edge := range edges {
		indexedEdges = append(indexedEdges,
			[]int{edge[0], edge[1], edge[2], i})
	}

	sort.Slice(indexedEdges, func(i, j int) bool {
		return indexedEdges[i][2] < indexedEdges[j][2]
	})

	kruskal := func(excludeEdge int, includeEdge int) int {

		uf := NewUnionFind(n)

		totalWeight := 0
		edgesUsed := 0

		if includeEdge != -1 {
			edge := indexedEdges[includeEdge]

			if uf.Union(edge[0], edge[1]) {
				totalWeight += edge[2]
				edgesUsed++
			}
		}

		for i, edge := range indexedEdges {

			if i == excludeEdge {
				continue
			}

			if uf.Union(edge[0], edge[1]) {
				totalWeight += edge[2]
				edgesUsed++
			}

			if edgesUsed == n-1 {
				break
			}
		}

		if edgesUsed != n-1 {
			return 1 << 30
		}

		return totalWeight
	}

	baseWeight := kruskal(-1, -1)

	critical := []int{}
	pseudoCritical := []int{}

	for i := 0; i < len(indexedEdges); i++ {

		if kruskal(i, -1) > baseWeight {
			critical = append(critical, indexedEdges[i][3])
		} else if kruskal(-1, i) == baseWeight {
			pseudoCritical = append(
				pseudoCritical,
				indexedEdges[i][3],
			)
		}
	}

	return [][]int{critical, pseudoCritical}
}
```Go 实现遵循与 Python 版本相同的逻辑，但存在一些特定于语言的差异。 

Go不直接支持类，所以`UnionFind`被实现为具有关联方法的结构。 

使用切片而不是 Python 列表。 由于 Go 数组具有固定大小的语义，因此切片为动态边缘存储提供了所需的灵活性。 

断开连接的图情况返回一个大的哨兵值（`1 << 30`) 而不是无穷大，因为 Go 整数不支持整数运算的特殊浮点无穷大值。 

Go 还需要使用显式排序`sort.Slice`，而Python可以直接用key函数排序。

 ## 边缘情况

 当图恰好具有一个可能的 MST 时，就会出现一种重要的边缘情况。 在这种情况下，MST 中的每条边都自动成为关键边，因为删除其中任何一条边都会断开图的连接或强制使用更昂贵的边。 如果错误的实现仅检查一条边是否可以出现在 MST 中，则可能会意外地将此类边分类为伪关键边。 该解决方案通过始终首先通过排除测试检查关键性来避免该问题。 

另一个重要的情况涉及许多边共享相同权重的图。 相等的权重创建多个有效的 MST，这意味着某些边可能看起来是可选的，即使它们经常参与最优解决方案。 天真的贪婪实现可能会错误地假设第一个选定的边是强制性的。 通过强制包含并独立重新计算 MST，该实现可以正确识别伪关键边缘。 

当排除一条边使图完全断开连接时，就会出现第三种边缘情况。 在这种情况下，无法形成生成树。 一些实现错误地将不完整的 MST 权重与基线进行比较，并且未能将断开连接视为关键性的证据。 该解决方案明确检查是否完全`n - 1`使用了边缘。 如果不是，它返回无穷大，保证断开连接的情况被视为严重故障。 

微妙的边缘情况涉及从不属于任何 MST 的边缘。 例如，连接已经可以通过更便宜的路径到达的顶点的非常昂贵的边不应该被标记为关键或伪关键。 强制包含测试自然会过滤掉这些边缘，因为包含这样的边缘会增加 MST 总权重超出基线。
