 ## 解决方案

 # LeetCode 1415，所有长度为 n 的快乐字符串的第 k 个词典字符串

 ## 问题理解

 该问题要求我们生成长度的字符串`n`仅使用字符`'a'`,`'b'`， 和`'c'`，有一个重要的限制：两个相邻的字符不能相同。 这些有效的字符串称为快乐字符串。 

生成所有长度有效的快乐字符串后`n`，我们按字典顺序对它们进行排序，然后返回`k`该顺序中的第 th 字符串。 如果少于`k`快乐的字符串存在，我们返回一个空字符串。 

字典顺序与字典中使用的顺序相同。 例如：```
"aba" < "abc" < "aca"
```因为比较是从左到右逐个字符进行的。 

输入由两个整数组成：

 -`n`，快乐弦的所需长度
 -`k`，排序后我们想要的字符串的 1 索引位置

 限制相对较小：```
1 <= n <= 10
1 <= k <= 100
```这些限制很重要，因为它们告诉我们可能的字符串总数是可以管理的。 事实上：

 - 第一个角色有3个选择
 - 每个后面的字符都有 2 个选择，因为它不能等于前面的字符

 所以长度为快乐字符串的总数`n`是：$$3 \times 2^{n-1}$$为了`n = 10`，这变成：$$3 \times 2^9 = 1536$$这足够小，生成所有有效字符串是完全可行的。 

一些边缘情况很重要：

 - 如果`k`大于快乐字符串的数量，我们必须返回`""`- 为了`n = 1`, 每个字符串都是有效的
 - 字典顺序很重要，因此必须仔细控制生成顺序
 - 相邻的重复项，例如`"aa"`或者`"bcc"`无效且绝不能生成

 ## 方法

 ### 蛮力方法

 强力解决方案将生成所有可能长度的字符串`n`使用字符`'a'`,`'b'`， 和`'c'`。 

由于每个位置有3个选择，因此有：$$3^n$$可能的字符串。 

对于每个生成的字符串，我们将检查相邻字符是否不同。 如果有效，我们会将其添加到列表中。 生成所有可能性后，我们将按字典顺序对有效字符串进行排序并返回`k`如果存在的话。 

这种方法是正确的，因为它详尽地检查了每个候选字符串。 但是，它会执行不必​​要的工作，因为大多数生成的字符串可能无效。 

例如，当`n = 10`，暴力生成：$$3^{10} = 59049$$字符串，尽管只有 1536 个是有效的快乐字符串。 

### 最佳方法

 更好的解决方案是使用回溯。 

我们不是生成所有可能的字符串并随后进行过滤，而是从头开始仅构建有效的字符串。 

每一步：

 - 尝试添加`'a'`,`'b'`， 或者`'c'`- 跳过与前一个字符相同的任何字符
 - 继续递归，直到字符串长度变为`n`因为我们按排序顺序尝试字符：```
'a' -> 'b' -> 'c'
```生成的字符串自动按字典顺序出现。 

一旦我们生成了，我们就可以立即停止`k`th happy string，避免了不必要的计算。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n * n) | O(3^n * n) | O(3^n * n) | O(3^n * n) | 生成每个可能的字符串，然后过滤 |
 | 最佳 | O(2^n) | O(2^n) | O(n) | 使用回溯仅生成有效字符串 |

 ## 算法演练

 ### 第 1 步：初始化存储

 我们维持：

 - 存储生成的快乐字符串的列表
 - 表示当前正在构建的字符串的可变路径

 递归期间路径会增长和收缩。 

### 第 2 步：开始回溯

 我们逐个字符递归地构建字符串。 

在每个递归级别：

 - 如果当前路径长度等于`n`，我们组成了一条完整的幸福绳
 - 将其添加到结果列表中
 - 返回探索其他可能性

 ### 步骤 3：尝试按字典顺序排列字符

 对于每个位置，尝试：```
'a', 'b', 'c'
```按照那个确切的顺序。 

这保证了生成的字符串已经按字典顺序排序。 

### 步骤 4：执行快乐字符串规则

 添加字符之前：

 - 如果路径不为空
 - 新字符等于最后一个字符

 跳过该选择。 

这可确保相邻字符不完全相同。 

### 步骤 5：递归

 选择有效字符后：

 - 将其附加到路径中
 - 递归地继续构建字符串
 - 之后删除角色以回溯

 这探索了所有有效的可能性。 

### 步骤 6：返回第 k 个字符串

 生成后：

 - 如果少于`k`字符串存在，返回`""`- 否则返回`result[k - 1]`减一是必要的，因为列表使用从零开始的索引，而问题使用从一开始的索引。 

### 为什么它有效

 该算法始终保持当前部分字符串有效的不变量。 由于永远不会探索无效状态，因此每个完整的字符串都保证是一个快乐的字符串。 

由于在每个位置都按字典顺序探索字符，因此最终生成的序列会自动按字典顺序排序。 因此，`k`th 生成的字符串正是`k`字典顺序的快乐字符串。 

## Python 解决方案```python
class Solution:
    def getHappyString(self, n: int, k: int) -> str:
        result = []
        path = []

        def backtrack() -> None:
            if len(path) == n:
                result.append("".join(path))
                return

            for char in "abc":
                if path and path[-1] == char:
                    continue

                path.append(char)
                backtrack()
                path.pop()

        backtrack()

        if k > len(result):
            return ""

        return result[k - 1]
```该实现遵循前面描述的精确递归结构。 

这`path`list 存储当前正在构造的字符串。 使用列表而不是重复的字符串连接更有效，因为列表是可变的。 

这`backtrack`函数递归地探索所有有效的延续。 

基本情况发生在以下情况：```python
len(path) == n
```在那一刻，我们形成了一个完整的快乐字符串，因此我们将字符连接起来并附加结果。 

循环遍历`"abc"`按排序顺序。 这保证了自动按字典顺序排序。 

条件：```python
if path and path[-1] == char:
```防止相邻的重复字符。 

递归返回后，`path.pop()`删除最后一个字符，以便算法可以尝试另一个分支。 这就是回溯的本质。 

最后我们验证一下是否符合要求`k`th 字符串在返回之前就已存在。 

## 解决方案```go
func getHappyString(n int, k int) string {
    result := []string{}
    path := []byte{}

    var backtrack func()

    backtrack = func() {
        if len(path) == n {
            result = append(result, string(path))
            return
        }

        for _, char := range []byte{'a', 'b', 'c'} {
            if len(path) > 0 && path[len(path)-1] == char {
                continue
            }

            path = append(path, char)
            backtrack()
            path = path[:len(path)-1]
        }
    }

    backtrack()

    if k > len(result) {
        return ""
    }

    return result[k-1]
}
```Go 的实现与 Python 版本非常相似。 

Go 不使用 Python 列表和字符串，而是使用`[]byte`当前路径的切片。 这是有效的，因为字节是可变的并且在递归期间易于添加和删除。 

回溯是通过调整切片大小来实现的：```go
path = path[:len(path)-1]
```Go 不像 Python 那样支持嵌套命名函数，因此我们首先声明一个函数变量：```go
var backtrack func()
```然后将递归函数分配给它。 

返回空字符串很简单，因为 Go 字符串默认为`""`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k`超过快乐字符串的总数。 有错误的实现可能会尝试访问无效索引并崩溃。 该解决方案通过显式检查来避免这种情况：```
if k > len(result):
    return ""
```在索引到结果列表之前。 

另一个重要案例是`n = 1`。 由于没有相邻字符，因此每个单字符串自动有效。 某些实现意外地错误地应用了邻接检查并拒绝有效的单字符字符串。 这里，条件：```
if path and path[-1] == char:
```仅当路径非空时运行，因此长度为 1 的字符串可以正常工作。 

第三个重要的边缘情况涉及字典顺序。 如果以任意顺序探索字符，生成的字符串可能与字典顺序不匹配，从而导致给定的结果返回错误的答案`k`。 此实现通过始终按顺序迭代字符来保证正确性：```
"a", "b", "c"
```递归期间。 

另一个微妙的情况是适当的回溯清理。 忘记在递归后删除字符会导致未来的递归分支继承错误的状态。 明确的`path.pop()`操作确保每个递归调用在探索另一个分支之前将路径精确恢复到之前的状态。
