 # LeetCode 1470 - 打乱数组

 ## 问题理解

 问题给了我们一个数组`nums`恰好与`2n`元素。 数组的结构保证遵循非常特定的模式：```
[x1, x2, ..., xn, y1, y2, ..., yn]
```这意味着数组的前半部分包含所有`x`值，后半部分包含所有`y`价值观。 

我们的任务是将数组重新排列成以下格式：```
[x1, y1, x2, y2, ..., xn, yn]
```换句话说，我们必须将数组的两半交错。 我们从前半部分取出一个元素，然后从后半部分取出一个元素，重复此过程，直到使用所有元素。 

例如，如果：```
nums = [2,5,1,3,4,7]
n = 3
```然后：```
First half  = [2,5,1]
Second half = [3,4,7]
```将它们交错产生：```
[2,3,5,4,1,7]
```限制相对较小：

 -`1 <= n <= 500`-`nums.length == 2n`-`1 <= nums[i] <= 1000`由于最大数组大小仅为`1000`，即使效率较低的解决方案仍然可以在限制内舒适地运行。 然而，目标仍然是设计一个干净高效的算法。 

一个重要的观察是输入格式始终有效。 该问题保证：

 - 数组长度恰好是`2n`- 前半部分和后半部分分别包含`n`元素
 - 没有格式错误的输入

 这消除了防御性验证逻辑的需要。 

潜在的边缘情况包括非常小的数组，例如：```
nums = [1,2]
n = 1
```其中只有一对要交错。 

另一个可能的错误来源是索引处理。 由于我们同时访问两半，不正确的索引很容易产生相差一的错误。 

重复的值也很重要。 即使数字重复，算法也必须准确地保持顺序。 

## 方法

 ### 蛮力方法

 强力解决方案将显式地将数组分成两个临时数组：

 - 上半场一个阵列
 - 下半场一组

 拆分后，我们可以同时迭代两个数组，并将元素交替附加到结果数组中。 

这种方法简单易懂。 由于问题规模很小，因此它在约束范围内表现得非常好。 

然而，这个解决方案使用了不必要的额外内存，因为我们在构造最终答案之前创建了额外的数组来分别存储两半。 

### 最佳方法

 关键的观察是我们实际上不需要将数组拆分为单独的结构。 

上半场已经从索引处开始`0`，下半场已经从索引处开始`n`。 

这意味着：

-`x_i`位于`nums[i]`-`y_i`位于`nums[i + n]`因此我们可以迭代`0`到`n - 1`并直接附加：```
nums[i]
nums[i + n]
```到结果数组。 

这避免了不必要的中间数组并保持实现简洁高效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 在合并之前将数组拆分为两个临时数组 |
 | 最佳 | O(n) | O(n) | 直接交错两半的元素 |

 ## 算法演练

 1. 创建一个空结果数组来存储打乱后的序列。 
2. 迭代索引`0`到`n - 1`。 每次迭代对应于应该一起出现在输出中的一对元素。 
3. 对于当前索引`i`，使用以下命令从前半部分访问相应的元素`nums[i]`。 这代表`x_i`。 
4. 使用以下命令访问后半部分的匹配元素`nums[i + n]`。 这代表`y_i`。 
5. 按顺序将两个元素附加到结果数组中：

 - 首先追加`nums[i]`- 然后追加`nums[i + n]`6. 继续，直到处理完所有对。 
7. 返回完成的结果数组。 

### 为什么它有效

 输入数组保证包含恰好两个长度相等的连续半部分。 对于每个有效索引`i`：

 -`nums[i]`对应于上半部分的下一个元素
 -`nums[i + n]`对应于后半部分的匹配元素

 通过在每次迭代期间将这两个值附加在一起，我们可以精确地重现所需的交错顺序：```
[x1, y1, x2, y2, ..., xn, yn]
```由于每个元素都被处理一次并以正确的相对顺序插入，因此该算法始终会产生正确的输出。 

## Python 解决方案```python
from typing import List

class Solution:
    def shuffle(self, nums: List[int], n: int) -> List[int]:
        shuffled = []

        for i in range(n):
            shuffled.append(nums[i])
            shuffled.append(nums[i + n])

        return shuffled
```实现首先创建一个名为的空列表`shuffled`这将保存最终重新排序的数组。 

循环完全运行`n`次因为有`n`对进行处理。 在每次迭代期间：

 -`nums[i]`从上半部分检索下一个元素
 -`nums[i + n]`从后半部分检索对应的元素

 这两个值都会立即附加以保留所需的顺序。 

处理完所有对后，返回完成的打乱数组。 

该实现直接反映了前面描述的算法，因此很容易验证正确性。 

## 解决方案```go
func shuffle(nums []int, n int) []int {
    shuffled := make([]int, 0, 2*n)

    for i := 0; i < n; i++ {
        shuffled = append(shuffled, nums[i])
        shuffled = append(shuffled, nums[i+n])
    }

    return shuffled
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是使用：```go
make([]int, 0, 2*n)
```这会为结果切片预分配容量，从而避免附加元素时不必要的重新分配。 

Go 切片根据需要动态增长，但预分配预期大小更有效。 

不用担心整数溢出，因为约束非常小。 

该函数还自然地处理类似空的行为，尽管约束保证至少存在一对。

 ## 边缘情况

 一种重要的边缘情况是最小有效输入大小：```
nums = [1,2]
n = 1
```这种情况很有用，因为当仅存在一对时，许多索引错误就会变得明显。 该实现自然地处理了这一问题，因为循环只运行一次并从每一半中添加一个元素。 

另一个重要的边缘情况涉及重复值：```
nums = [5,5,5,5]
```当所有数字都相同时，就不可能从视觉上区分元素是否已正确重新排序。 一些不正确的实现可能会意外地跳过或重复元素。 由于该算法严格按顺序处理索引，因此可以安全、正确地处理重复项。 

第三个边缘情况是允许的最大输入大小。 和`n = 500`，数组包含`1000`元素。 具有过多嵌套循环或重复插入的低效算法可能会变得不必要的缓慢。 当前的实现仅执行一次线性遍历，因此即使在最大输入大小下它仍然保持高效。 

另一个微妙的边缘情况涉及精确保留顺序。 考虑：```
nums = [1,2,3,4,5,6]
```输出必须是：```
[1,4,2,5,3,6]
```不正确的索引公式很容易产生：```
[1,4,2,6,3,5]
```或其他无效的订单。 通过持续配对`nums[i]`和`nums[i+n]`，该实现保证了两半之间的正确对齐。
