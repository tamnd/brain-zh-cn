[LeetCode 问题 1401](https://leetcode.com/problems/circle-and-rectangle-overlapping/)

 **难度：** 🟡 中等
 **主题：** 数学、几何

 ## 解决方案

 ## 问题理解

 该问题给出了两个几何形状：

 1. 圆，定义为：

 -`radius`- 中心坐标`(xCenter, yCenter)`2. 轴对齐的矩形，定义为：

 - 左下角`(x1, y1)`- 右上角`(x2, y2)`目标是确定圆形和矩形是否重叠。 如果存在至少一个点同时属于两个形状，则两个形状重叠。 

该矩形是轴对齐的，这意味着它的边平行于 x 轴和 y 轴。 这显着简化了几何图形，因为矩形边界很容易与坐标进行比较。 

重要的细节是触摸算作重叠。 如果圆只接触矩形的一条边或一个角，答案仍然是`true`。 

约束在数值上相对较小，但坐标范围跨越负值和正值。 最大半径为`2000`，坐标可以达到`10^4`在幅度上。 这些约束表明期望得到恒定时间几何解。 

幼稚的实现可能会错误地处理几种边缘情况：

 - 圆心可能已经位于矩形内部。 
- 圆可能恰好接触矩形角。 
- 圆可能恰好沿着边缘接触。 
- 矩形可以完全位于圆内。 
- 坐标可能为负值。 
- 使用平方根的距离计算可能会引入浮点精度问题。 

该问题保证：

 -`x1 < x2`-`y1 < y2`所以矩形总是有效且非退化的。 

## 方法

 ### 蛮力方法

 一个蛮力的想法是检查矩形上的点并检查是否有任何点位于圆内。 对于每个采样点`(x, y)`:

 - 计算到圆心的平方距离：$$(x - xCenter)^2 + (y - yCenter)^2$$- 如果该值小于或等于`radius^2`，则该点位于圆内。 

这种方法在概念上是正确的，因为如果存在任何共享点，则存在重叠。 

然而，问题是连续几何，而不是离散几何。 矩形包含无限多个点。 仅当坐标离散化时，强力网格扫描才有效，即使如此，它也会变得低效且可能不准确。 

例如，迭代矩形内的每个整数坐标仍然可能会错过整数点之间发生的重叠。 

### 最佳几何观察

 关键的见解是这样的：

 要判断圆是否与矩形重叠，我们只需找到矩形内距离圆心最近的点即可。 

如果矩形中最近的点在圆内，则存在重叠。 

如果即使最近的点也在圆之外，则不存在重叠。 

对于轴对齐的矩形，可以使用夹紧独立计算 x 坐标和 y 坐标的最近点：

 - 如果中心的 x 坐标位于矩形的左侧，则使用`x1`- 如果它位于矩形的右侧，请使用`x2`- 否则使用`xCenter`本身

 相同的逻辑适用于 y 坐标。 

这给出了最近的矩形点`(closestX, closestY)`。 

然后计算从圆心到该点的平方距离。 如果：$$(closestX - xCenter)^2 + (closestY - yCenter)^2 \le radius^2$$然后形状重叠。 

这完全避免了浮点运算并以恒定时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(宽 × 高) | O(1) | O(1) | 扫描矩形内部的点，对于连续几何体效率低且不可靠 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 使用最近点几何和平方距离比较 |

 ## 算法演练

 1.从圆心开始`(xCenter, yCenter)`和矩形边界。 
2. 找到矩形内最接近的 x 坐标。 

- 如果`xCenter < x1`，最接近的 x 值为`x1`- 如果`xCenter > x2`，最接近的 x 值为`x2`- 否则中心已经水平位于矩形内部，所以使用`xCenter`3. 使用相同的逻辑找到矩形内最接近的 y 坐标。 

- 如果`yCenter < y1`， 使用`y1`- 如果`yCenter > y2`， 使用`y2`- 否则使用`yCenter`4. 结果点`(closestX, closestY)`保证是矩形内距离圆心最近的点。 
5. 计算欧氏距离平方：$$dx = closestX - xCenter$$

$$dy = closestY - yCenter$$

$$distanceSquared = dx^2 + dy^2$$6. 将该距离与半径平方进行比较：$$radius^2$$7.如果`distanceSquared <= radius^2`，圆到达矩形，所以返回`true`。 
8.否则返回`false`。 

### 为什么它有效

 该算法之所以有效，是因为矩形内最近的点最小化了到圆心的欧几里德距离。 如果圆心到矩形的最小可能距离小于或等于半径，则至少有一个矩形点位于圆内。 

相反，如果即使最近的矩形点比半径更远，则每个其他矩形点也必须更远，因此重叠是不可能的。 

## Python 解决方案```python
class Solution:
    def checkOverlap(
        self,
        radius: int,
        xCenter: int,
        yCenter: int,
        x1: int,
        y1: int,
        x2: int,
        y2: int
    ) -> bool:
        
        closest_x = max(x1, min(xCenter, x2))
        closest_y = max(y1, min(yCenter, y2))
        
        dx = closest_x - xCenter
        dy = closest_y - yCenter
        
        return dx * dx + dy * dy <= radius * radius
```其实现直接遵循几何观察。 

前两行计算距离圆心最近的矩形点。 表达式：```python
max(x1, min(xCenter, x2))
```有效夹紧`xCenter`进入矩形的水平范围。 

如果`xCenter`小于`x1`，结果变为`x1`。 

如果`xCenter`大于`x2`，结果变为`x2`。 

否则它保持不变。 

同样的逻辑适用于`closest_y`。 

接下来，代码计算从中心到最近点的水平和垂直偏移。 

最后，该实现不是使用平方根计算实际的欧几里德距离，而是比较平方值。 这避免了不必要的浮点运算，并且在数学上是等效的。 

## 解决方案```go
func checkOverlap(radius int, xCenter int, yCenter int, x1 int, y1 int, x2 int, y2 int) bool {
    
    closestX := max(x1, min(xCenter, x2))
    closestY := max(y1, min(yCenter, y2))
    
    dx := closestX - xCenter
    dy := closestY - yCenter
    
    return dx*dx+dy*dy <= radius*radius
}

func min(a int, b int) int {
    if a < b {
        return a
    }
    return b
}

func max(a int, b int) int {
    if a > b {
        return a
    }
    return b
}
```Go 实现密切反映了 Python 逻辑。 

由于 Go 没有提供内置整数`min`和`max`所有版本的函数，辅助函数都是手动定义的。 

所有计算仍然基于整数，因此不存在浮点精度问题。 整数溢出也不是问题，因为坐标边界对于标准 Go 整数来说足够小。

 ## 边缘情况

 ### 圆心在矩形内

 当圆心已经位于矩形内部时，会发生一种重要的情况。 在这种情况下，距离中心最近的矩形点就是中心本身。 

有缺陷的实现可能会错误地仅搜索边缘或角落，并完全错过这种情况。 

夹紧逻辑自然会正确处理这个问题，因为两个坐标都保持不变。 计算出的距离变为零，这始终满足重叠条件。 

### 圆正好接触一个角

 当圆仅接触矩形的一个角时，会发生另一种微妙的情况。 

例如：```
Circle center = (0,0)
Radius = 5
Rectangle corner = (3,4)
```距离正好等于`5`。 

使用浮点运算的实现可能会引入精度问题并意外地拒绝相等的情况。 

此实现通过直接比较整数平方来避免这种情况：$$3^2 + 4^2 = 25$$

$$5^2 = 25$$由于允许相等，因此可以正确检测重叠。 

### 沿一个轴完全在外侧画圆

 当圆与矩形水平或垂直分离时，会出现一个常见错误。 

例如：```
Circle center = (-10, 0)
Rectangle x-range = [0, 5]
```最接近的 x 坐标必须变为`0`。 

夹紧操作可以精确地处理这一点。 Instead of checking every edge manually, the algorithm directly computes the nearest valid rectangle coordinate.

 This guarantees correct behavior for all outside positions, including diagonal separation cases.
