[LeetCode 第 1423 题](https://leetcode.com/problems/maximum-points-you-can-obtain-from-cards/)

 **难度：** 🟡 中等
 **主题：** 数组、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们最大化从一排卡片中收集到的总分，其中每张卡片都有一个分值。 您可以准确选择`k`卡，并且每个选择必须来自该行的**开始**或**结束**。 目标是计算通过做出这些选择可获得的最大可能总和。 

输入由一个整数数组组成`cardPoints`，代表每张卡上的点数，以及一个整数`k`，代表要拿的牌总数。 输出是一个整数，表示可实现的最大总和。 

约束条件告诉我们，`cardPoints`最高可达100,000，每张卡的积分值最高可达10,000。 这表明一种低效的解决方案，例如以暴力方式尝试左右选择的所有组合的解决方案，由于指数复杂性而速度太慢。 

重要的边缘情况包括`k`等于数组的长度（取出所有卡），当所有卡值都相同时，并且当`k`为 1 或阵列只有一张卡。 该问题保证至少一张卡并且`k`总是有效的，所以我们不需要处理空数组或无效数组`k`。 

## 方法

 **暴力方法**将迭代所有可能的组合`i`从左边开始的卡片和`k-i`所有人从右边开始的卡片`i`从 0 到`k`。 对于每种组合，我们计算所选卡片的总和并跟踪最大值。 这种方法是正确的，但效率低下，因为它需要`O(k)`为每个人工作`k`组合，导致`O(k^2)`时间复杂度。 为了`k`达到10万，这是不可能的。 

**最佳方法**依赖于观察`k`从末端开始的卡片相当于留下一个长度为**连续的子数组`n-k`** 中间某处未选中。 我们可以找到长度的子数组，而不是尝试左右选择的所有组合`n-k`**最小总和**，因为总分是`totalSum - minSubarraySum`。 这是高效的，因为它只需要一次计算前缀和或使用滑动窗口来查找最小和子数组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(k^2) | O(k^2) | O(1) | O(1) | 尝试左/右选择的每种组合 |
 | 最佳 | O(n) | O(1) | O(1) | 使用滑动窗口求长度为 n-k 的最小子数组和 |

 ## 算法演练

 1. 计算所有牌的总和。 如果我们能拿走所有的牌，这代表了最高分。 
2. 确定未选取的子数组的长度：`n - k`， 在哪里`n`的长度是`cardPoints`。 
3.使用长度的滑动窗口`n - k`找到该长度的任何连续子数组的最小总和。 用第一个初始化窗口总和`n - k`元素并将其滑过数组，更新总和并跟踪最小值。 
4. 从总和中减去最小子数组和。 这给出了通过采取可达到的最高分数`k`卡片从末端开始。 
5. 返回结果。 

**为什么它有效：** 问题简化为保留中间可能最小的块未被拾取。 由于我们被迫从两端进行选择，因此最大总和来自于排除最小的中间子数组。 该属性保证了最优性。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxScore(self, cardPoints: List[int], k: int) -> int:
        n = len(cardPoints)
        total_sum = sum(cardPoints)
        window_size = n - k
        
        if window_size == 0:
            return total_sum
        
        current_sum = sum(cardPoints[:window_size])
        min_window_sum = current_sum
        
        for i in range(window_size, n):
            current_sum += cardPoints[i] - cardPoints[i - window_size]
            min_window_sum = min(min_window_sum, current_sum)
        
        return total_sum - min_window_sum
```代码首先计算总点数，然后使用滑动窗口求最小子数组长度和`n - k`。 通过从总分中减去这个最小总和，我们得到了可达到的最大分数。 

## 解决方案```go
func maxScore(cardPoints []int, k int) int {
    n := len(cardPoints)
    totalSum := 0
    for _, val := range cardPoints {
        totalSum += val
    }
    
    windowSize := n - k
    if windowSize == 0 {
        return totalSum
    }
    
    currentSum := 0
    for i := 0; i < windowSize; i++ {
        currentSum += cardPoints[i]
    }
    minWindowSum := currentSum
    
    for i := windowSize; i < n; i++ {
        currentSum += cardPoints[i] - cardPoints[i - windowSize]
        if currentSum < minWindowSum {
            minWindowSum = currentSum
        }
    }
    
    return totalSum - minWindowSum
}
```在 Go 中，我们处理切片的方式与 Python 列表类似。 鉴于限制，整数溢出在这里不是问题。 滑动窗口逻辑是直接从Python翻译过来的。 

## 工作示例

 **示例1：**`cardPoints = [1,2,3,4,5,6,1], k = 3`总和 = 22，窗口大小 = 7 - 3 = 4。 

长度为 4 的滑动窗口总和：`[1+2+3+4=10, 2+3+4+5=14, 3+4+5+6=18, 4+5+6+1=16]`最小总和 = 10

 最高分 = 22 - 10 = 12

 **示例2：**`cardPoints = [2,2,2], k = 2`总和 = 6，窗口大小 = 3 - 2 = 1

 滑动窗口总和：`[2,2,2]`最小总和 = 2

 最高分 = 6 - 2 = 4

 **示例3：**`cardPoints = [9,7,7,9,7,7,9], k = 7`窗口大小 = 0，因此我们拿走所有卡片。 

最高分 = 总和 = 55

 ## 边缘情况

 **单元素数组：** 如果`cardPoints`只有一个元素，最大分数通常就是该元素本身。 Python 和 Go 解决方案都处理此问题，因为总和计算和窗口大小逻辑正确返回总和。 

**k 等于数组长度：** 如果`k`等于`n`，算法正确返回自窗口大小以来所有卡片的总和`n - k`变为零，并且早期返回可以有效地处理它。 

**所有卡片具有相同的值：** 在这种情况下，最小和子数组与任何长度的子数组相同`n-k`，所以算法自然会计算出正确的结果。 不需要特殊处理，但这是一项重要的测试，以确保最小计算不会引入相差一的错误。
