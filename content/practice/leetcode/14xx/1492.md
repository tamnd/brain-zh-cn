 **难度：** 🟡 中等

 ## 解决方案

 ## 问题理解

 问题要求我们找到`kth`正整数的因数`n`，其中因素按升序排列。 

一个因数`n`是任意整数`i`这样：$n \bmod i = 0$例如，如果`n = 12`，因素有：```
[1, 2, 3, 4, 6, 12]
```如果`k = 3`，答案是`3`， 因为`3`是排序因子列表中的第三个元素。 

重要的细节是必须按升序考虑因素。 我们不是简单地计算除数，我们必须确定位置处的精确除数`k`。 

限制条件是：```
1 <= k <= n <= 1000
```这些限制相对较小，这意味着即使是简单的线性扫描`1`到`n`会在时间限制内起作用。 然而，后续行动明确询问我们是否可以做得更好`O(n)`复杂性，这表明预期的最佳解决方案使用了对因素的数学观察。 

立即识别一些边缘情况很重要。 

如果`n`是质数，它只有两个因数，`1`和`n`。 任何`k > 2`必须返回`-1`。 

如果`n = 1`，唯一的因素是`1`， 所以`k = 1`回报`1`，以及任何更大的`k`回报`-1`。 

完全平方是另一个重要的情况，因为它们的平方根仅作为因子对出现一次。 例如：$16 = 4 \times 4$我们必须避免重复计算平方根因子。 

## 方法

 ### 蛮力方法

 最简单的解决方案是迭代每个整数`1`到`n`。 

对于每个数字`i`，我们检查它是否可以划分`n`均匀。 如果是这样，我们就减少`k`。 一次`k`变为零，我们发现`kth`因子并可以立即返回它。 

这种方法是正确的，因为检查每个整数可以保证我们遇到按升序排列的所有因素。 

例如，与`n = 12`：```
1 -> factor
2 -> factor
3 -> factor
4 -> factor
...
```当我们遇到第三个因素的时候，我们就返回`3`。 

尽管该解决方案简单且易于实现，但它需要扫描最多可达的所有数字`n`在最坏的情况下。 这给出了时间复杂度`O(n)`。 

### 最佳方法

 关键的数学观察是因素成对出现。 

如果`i`划分`n`， 然后：$i \times \frac{n}{i} = n$例如，因子对`12`是：```
(1, 12)
(2, 6)
(3, 4)
```请注意，一旦我们传递了平方根`n`，我们开始以相反的顺序重复相同的对。 

这意味着我们只需要迭代到：$\sqrt{n}$在本次迭代期间：

 - 小因素自然地按升序出现。 
- 它们配对的大因子按降序出现。 

我们可以暂时存储较大的配对因子，然后反向处理它们以恢复整体升序。 

这降低了时间复杂度`O(n)`到`O(sqrt(n))`。

 ## 算法演练

 ### 最优算法

 1. 初始化一个空列表，名为`larger_factors`。 

该列表将存储每个因子对中较大的因子。 我们推迟处理它们，因为它们自然按降序排列。 
2. 迭代自`1`到`sqrt(n)`包容性。 

我们只需要搜索到平方根，因为每个大于平方根的因子都有一个相应的较小的配对因子。 
3. 对于每个数字`i`，检查是否可除`n`。 

如果：$n \bmod i = 0$然后`i`是一个因素。 
4. 当找到一个小的因子时，递减`k`。 

由于我们是向上迭代，因此这些因素已经按升序排列。 
5.如果`k == 0`， 返回`i`。 

这意味着当前的小因子是`kth`整体因素。 
6. 计算配对因子：$\frac{n}{i}$如果这个配对因子不同于`i`，将其附加到`larger_factors`。 

这避免了重复计算完全平方根。 
7. 循环结束后，处理`larger_factors`以相反的顺序。 

反转可恢复较大一半因子的升序。 
8. 对于每个反转的较大因子，递减`k`。 

如果`k == 0`，返回当前因子。 
9. 如果所有因素都用尽并且`k`仍为正值，返回`-1`。 

这意味着`n`少于`k`因素。 

### 为什么它有效

 的每一个因素`n`恰好属于一个因子对：$(i, \frac{n}{i})$通过仅迭代到平方根，我们可以发现每对恰好一次。 

在前向迭代过程中，小因素按升序出现。 大因素按降序排列，因此反转它们即可恢复升序。 

因为该算法按排序顺序访问每个因素一次，因此递减`k`正确识别`kth`因素。 

## Python 解决方案```python
class Solution:
    def kthFactor(self, n: int, k: int) -> int:
        larger_factors = []

        i = 1
        while i * i <= n:
            if n % i == 0:
                k -= 1

                if k == 0:
                    return i

                paired_factor = n // i

                if paired_factor != i:
                    larger_factors.append(paired_factor)

            i += 1

        for factor in reversed(larger_factors):
            k -= 1

            if k == 0:
                return factor

        return -1
```实施首先创建`larger_factors`，它存储每个因子对中较大的除数。 

这`while`循环仅在以下情况下迭代：$i^2 \leq n$这相当于迭代到平方根`n`。 

每当`i`划分`n`，我们立即通过递减将其视为有效因子`k`。 

如果`k`达到零，我们返回`i`因为较小的因素已经按升序排列。 

接下来，我们使用整数除法计算配对因子：```python
paired_factor = n // i
```如果配对因子不同于`i`，我们将其附加到`larger_factors`。 此条件可防止重复计算完全平方根。 

循环后，较大的因素按降序排列。 反转它们会恢复升序，使我们能够继续正确计算因子。 

如果我们穷尽所有因素仍未达到`kth`一、我们回来`-1`。 

## 解决方案```go
func kthFactor(n int, k int) int {
    largerFactors := []int{}

    for i := 1; i*i <= n; i++ {
        if n%i == 0 {
            k--

            if k == 0 {
                return i
            }

            pairedFactor := n / i

            if pairedFactor != i {
                largerFactors = append(largerFactors, pairedFactor)
            }
        }
    }

    for i := len(largerFactors) - 1; i >= 0; i-- {
        k--

        if k == 0 {
            return largerFactors[i]
        }
    }

    return -1
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

使用切片而不是 Python 列表来存储更大的因子。 反向遍历是使用索引循环手动完成的，因为 Go 不提供内置的反向迭代器。 

整数运算很简单，因为问题约束很小，因此不存在溢出问题。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n = 1`。 数量`1`只有一个因素，它本身。 许多实现意外地假设至少存在两个因素，因为大多数正整数都具有`1`和`n`作为单独的除数。 该实现正确处理了这种情况，因为循环处理`i = 1`，立即递减`k`，并返回`1`在适当的时候。 

另一个关键的边缘情况涉及完全平方，例如`16`或者`25`。 在这些情况下，平方根显示为因子对的两个成员：$4 \times 4 = 16$简单的因子对实现可能会意外地计算平方根两次。 条件：```
if paired_factor != i:
```防止重复插入并保证因子列表保持正确。 

第三个重要的边缘情况发生在以下情况：`k`大于因子总数。 例如：```
n = 4, k = 4
```自从`4`只有三个因素，算法必须返回`-1`。 该实现自然地通过耗尽小因子扫描和反向较大因子列表来处理这个问题，而无需减少`k`为零。 

最后一个微妙的情况涉及素数。 质数恰好有两个因数：```
1 and n
```该算法正确地识别了这一点，因为只有`1`在平方根之前均匀划分。 配对因子`n`被存储并稍后返回，如果`k == 2`。 任何更大的`k`正确返回`-1`。
