 **难度：** 🟡 中等
 **主题：** 数学、贪心

 ## 解决方案

 ## 问题理解

 该问题要求我们找到总和等于给定整数的斐波那契数的最小数量`k`。 斐波那契数列是一个序列，其中每个数字都是前两个数字之和，从 1 和 1 开始。输入`k`是最大 10 亿的正整数。 输出是一个整数，表示斐波那契数的最小计数，其总和正好等于`k`。 重要的是，同一个斐波那契数可以多次使用，并且问题保证这样的总和始终存在。 

关键点包括了解我们不会生成斐波那契数的所有组合，这将是低效的。 我们还需要考虑较大的值`k`，这意味着暴力方法会太慢。 需要考虑的边缘情况是`k`本身就是斐波那契数列，当`k`很小，并且当`k`需要很多斐波那契数列来求和。 

## 方法

 The brute-force approach would attempt to generate all subsets of Fibonacci numbers up to`k`并检查哪个组合总和为`k`具有最小长度。 这是正确的，但效率非常低，因为子集的数量随着斐波那契数的数量呈指数增长，这使得它不可行`k`最多 10^9。 

最佳解决方案的关键见解是贪婪：始终选择小于或等于剩余数的最大斐波那契数`k`，从中减去它`k`，并重复直到`k`达到零。 这是因为泽肯多夫定理，该定理指出每个正整数都可以唯一地表示为非连续斐波那契数之和。 通过始终采用最大的可用斐波那契数，我们可以最大限度地减少使用的数字数量。

 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 生成斐波那契数列的所有组合以求和为 k |
 | 最佳 | O(log k) | O(log k) | 重复使用最大斐波那契数 ≤ k 的贪婪方法 |

 ## 算法演练

 1. 生成所有斐波那契数`k`。 开始于`1, 1`并迭代地将下一个斐波那契数添加为最后两个斐波那契数的总和，当数字超过时停止`k`。 
2. 初始化一个计数器来跟踪所使用的斐波那契数的数量。 
3. 迭代同时`k > 0`。 在每次迭代中，找到小于或等于的最大斐波那契数`k`。 
4. 减去这个斐波那契数`k`并将计数器加 1。 
5. 重复步骤3，直到`k`变为零。 
6. 返回计数器作为总和等于的斐波那契数的最小数量`k`。 

**为什么有效**：通过始终选择尽可能大的斐波那契数，我们确保使用尽可能少的数字。 该过程一定会终止，因为斐波那契数呈指数增长，减少了`k`每一步都高效。 

## Python 解决方案```python
class Solution:
    def findMinFibonacciNumbers(self, k: int) -> int:
        fibs = [1, 1]
        while fibs[-1] < k:
            fibs.append(fibs[-1] + fibs[-2])
        
        count = 0
        idx = len(fibs) - 1
        while k > 0:
            if fibs[idx] <= k:
                k -= fibs[idx]
                count += 1
            idx -= 1
        
        return count
```Python 解决方案首先生成斐波那契数列`k`。 然后从最大的斐波那契数向下迭代，减去其中的数字`k`每当它们小于或等于当前值时`k`。 每次减法都会增加计数。 这完全按照描述实现了贪婪算法。 

## 解决方案```go
func findMinFibonacciNumbers(k int) int {
    fibs := []int{1, 1}
    for fibs[len(fibs)-1] < k {
        fibs = append(fibs, fibs[len(fibs)-1]+fibs[len(fibs)-2])
    }

    count := 0
    idx := len(fibs) - 1
    for k > 0 {
        if fibs[idx] <= k {
            k -= fibs[idx]
            count++
        }
        idx--
    }
    
    return count
}
```在 Go 中，我们使用切片来存储斐波那契数最多`k`。 该算法逻辑与 Python 类似，使用循环减去可用的最大斐波那契数。 请注意安全地处理切片索引。 Go 不存在整数溢出问题`k`最多 10^9 自`int`在大多数平台上足够大。 

## 工作示例

 **示例1**：`k = 7`斐波那契数 ≤ 7: [1, 1, 2, 3, 5]

 步骤：减 5 → k = 2，减 2 → k = 0。计数 = 2

 **示例2**：`k = 10`斐波那契数 ≤ 10：[1, 1, 2, 3, 5, 8]

 步骤：减8→k = 2，减2→k = 0。计数= 2

 **示例3**：`k = 19`斐波那契数 ≤ 19：[1, 1, 2, 3, 5, 8, 13]

 步骤：减 13 → k = 6，减 5 → k = 1，减 1 → k = 0。计数 = 3

 ## 边缘情况

 一种边缘情况是当`k`恰好是一个斐波那契数。 贪心算法通过选择来正确处理这个问题`k`第一次迭代中的自身，计数为 1。 

另一个边缘情况是较小的值`k`，例如 1 或 2。该算法生成的斐波那契数最多可达`k`并可以立即选择最大的一个，即数字本身。 

第三种边缘情况是当`k`是多个斐波那契数的和，要求算法迭代地减去可能的最大数。 这测试循环是否正确处理多次迭代和递减`k`准确。 该算法保证了正确性，因为它总是减少`k`具有最大的有效斐波那契数。
