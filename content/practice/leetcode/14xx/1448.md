[LeetCode 问题 1448](https://leetcode.com/problems/count-good-nodes-in-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题给了我们二叉树的根，并要求我们计算有多少节点被认为是“好”的。 

如果沿着从根到该节点的路径，不存在值大于当前节点值的节点，则该节点被称为好节点。 换句话说，当前节点必须大于或等于从根开始的路径上先前看到的每个值。 

例如，假设从根到节点的路径是：```
3 -> 1 -> 3
```最终有值的节点`3`很好，因为沿路径遇到的最大值也是`3`。 没有比它大的更早节点。 

然而，在这条道路上：```
3 -> 3 -> 2
```有值的节点`2`不好是因为价值`3`已经出现在路径的较早位置，并且`3 > 2`。 

输入是一个二叉树，其中每个节点包含：

 - 整数值
 - 左子指针
 - 右子指针

 输出是一个整数，表示整个树中好节点的总数。 

约束条件很重要：

 - 树最多可以包含`10^5`节点
 - 节点值范围为`-10^4`到`10^4`这些限制告诉我们：

 - 我们需要一种接近线性时间的算法
 - 为每个节点重复重新计算信息可能会变得太慢
 - 对于高度倾斜的树，递归深度可能会变大

 有几种边缘情况值得立即考虑。 

一棵只有一个节点的树应该返回`1`，因为根总是好的。 完全递减的路径，例如`5 -> 4 -> 3 -> 2`，应该只计算根。 完全递增的路径应该计算每个节点。 负值也很重要，因为无论符号如何，比较逻辑都必须起作用。 

该问题保证树至少有一个节点，因此我们永远不需要处理空输入树。 

## 方法

 ### 蛮力方法

 蛮力的想法是独立评估每个节点。 

对于树中的每个节点，我们可以跟踪从根到该节点的路径，并确定沿该路径遇到的最大值。 如果节点的值至少为该最大值，则该节点是好的。 

一种可能的实现是：

 1. 对于每个节点，从根开始重建路径
 2. 扫描该路径中的所有值
 3.判断节点是否良好

 这是正确的，因为它直接遵循问题定义。 

然而，它的效率很低。 在最坏的情况下，树可能完全倾斜，表现得像链表。 那么，对于每个节点，我们可能需要再次遍历几乎整个树的高度。 

对于一棵树来说`n`节点：

 - 每个节点可能需要`O(n)`工作
 - 总复杂度变为`O(n^2)`和`10^5`nodes, this is too slow.

 ### 最佳方法

 关键的观察是，当从根向下遍历时，我们只需要一条信息：

 > 当前路径上迄今为止看到的最大值。 

When we visit a node:

 - 如果`node.val >= max_so_far`，节点良好
 - 然后我们更新：```
new_max = max(max_so_far, node.val)
```- 这个更新的最大值被传递给孩子们

 这消除了重复的工作，因为每个节点只被处理一次。 

深度优先搜索在这里很自然地起作用，因为问题取决于根到节点的路径。 在DFS遍历的过程中，我们总是知道当前的路径信息。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(h) | 重复重新计算路径最大值 |
 | 最佳| O(n) | O(h) | DFS 遍历期间跟踪路径最大值 |

 这里：

-`n`是节点数
 -`h`是树的高度

 ## 算法演练

 ### 最优DFS算法

 1. 从根节点开始深度优先搜索。 

根总是好的，因为其路径上没有较早的节点。 
2. 维护一个名为`max_so_far`。 

该变量表示从根到当前节点遇到的最大值。 
3. 在每个节点，将该节点的值与`max_so_far`。 

如果：```
node.val >= max_so_far
```那么当前节点是好的，所以增加答案。 
4. 更新子树的最大值。 

孩子们继承沿路径看到的最大值：```
updated_max = max(max_so_far, node.val)
```5. 使用递归处理左子树`updated_max`。 
6. 使用递归处理右子树`updated_max`。 
7. 当到达空节点时，返回`0`。 

空节点不参与计数。 
8. 对以下计数求和：

 - 当前节点
 - 左子树
 - 右子树
 9. 返回最终总数。 

### 为什么它有效

 该算法保持一个关键的不变量：

 >`max_so_far`始终等于从根到当前节点的路径上的最大节点值。 

由于这个不变量，检查节点是否良好就变成了与节点的简单比较`max_so_far`。 

每个节点只被访问一次，并且在遍历过程中始终可以获得正确的路径最大值。 因此，每个节点都被正确分类为好或不好。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def goodNodes(self, root: TreeNode) -> int:
        def dfs(node: Optional[TreeNode], max_so_far: int) -> int:
            if not node:
                return 0

            good = 1 if node.val >= max_so_far else 0

            updated_max = max(max_so_far, node.val)

            left_good = dfs(node.left, updated_max)
            right_good = dfs(node.right, updated_max)

            return good + left_good + right_good

        return dfs(root, root.val)
```该实现使用递归 DFS 辅助函数。 

辅助函数接收：

 - 当前节点
 - 当前根到节点路径上看到的最大值

 基本情况通过返回来处理空节点`0`。 

对于每个有效节点：

 - 我们确定它是否好
 - 我们更新运行最大值
 - 我们递归地处理两个孩子

 递归调用返回每个子树中的好节点数，并将当前节点的贡献添加到该总数中。 

初始调用开始于：```python
dfs(root, root.val)
```因为根本身定义了初始最大值。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func goodNodes(root *TreeNode) int {
    var dfs func(node *TreeNode, maxSoFar int) int

    dfs = func(node *TreeNode, maxSoFar int) int {
        if node == nil {
            return 0
        }

        good := 0
        if node.Val >= maxSoFar {
            good = 1
        }

        updatedMax := maxSoFar
        if node.Val > updatedMax {
            updatedMax = node.Val
        }

        leftGood := dfs(node.Left, updatedMax)
        rightGood := dfs(node.Right, updatedMax)

        return good + leftGood + rightGood
    }

    return dfs(root, root.Val)
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

一些特定于 Go 的细节很重要：

 -`nil`被用来代替`None`- Go不提供内置的`max`函数为整数，所以最大更新是手动写的
 - 递归闭包需要首先声明变量：```go
var dfs func(...)
```算法和复杂性保持相同。

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树是最小的有效输入。 根始终被认为是好的，因为路径上没有较早的节点。 

这种情况可能会暴露假设子节点存在或错误初始化运行最大值的实现中的错误。 

该实现自然地处理了这个问题，因为 DFS 开始于：```
dfs(root, root.val)
```根立即满足：```
node.val >= max_so_far
```所以答案就变成了`1`。 

### 完全减少树

 考虑一棵树：```
5 -> 4 -> 3 -> 2
```只有根才算好的。 

有缺陷的实现可能会在向下遍历时意外重置最大值，从而导致较小的节点被错误地计数。 

该解决方案避免了该问题，因为`max_so_far`通过每次递归调用向下传播并且永远不会减少。 

### 重复值

 该定义表示，如果没有较早的节点具有大于该节点的值，则该节点是良好的。 

这意味着允许相等的值。 

例如：```
2 -> 2 -> 2
```所有节点都很好。 

一个常见的错误是使用：```
node.val > max_so_far
```而不是：```
node.val >= max_so_far
```实现正确使用`>=`，确保正确计算重复项。
