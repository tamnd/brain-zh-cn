[LeetCode 问题 1441](https://leetcode.com/problems/build-an-array-with-stack-operations/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、模拟

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个严格递增的数组，称为`target`和一个整数`n`。 我们还可以访问从以下位置开始的整数流`1`并结束于`n`。 数字按顺序到达，一旦跳过某个数字，我们就无法返回它。 

我们从一个空堆栈开始，只允许执行两个操作：

 -`"Push"`将当前流编号添加到堆栈中。 
-`"Pop"`从堆栈中删除顶部元素。 

目标是生成一系列操作，使最终堆栈内容与`target`从下到上排列。 

重要的细节是，流中的每个数字必须首先被推送，然后才能被删除。 这意味着如果一个数字出现在流中但在流中不需要`target`，我们还必须`"Push"`然后立即`"Pop"`它。 

输入包括：

 -`target`，一个严格递增的整数数组
 -`n`，流中的最大值`[1, n]`输出是按顺序表示堆栈操作的字符串列表。 

限制相对较小：

 -`target.length <= 100`-`n <= 100`这些小限制意味着效率不是主要问题，但我们仍然想要一个干净且最佳的模拟。 

事实是`target`严格递增是极其重要的。 它保证流完全按照一个向前的方向进行处理，并且我们永远不需要重新考虑之前的数字。 

一些边缘情况很重要：

 - 目标可能包含连续的数字，例如`[1,2,3]`，意思是没有`"Pop"`需要进行操作。 
- 目标可能会跳过类似的数字`[1,3]`，需要临时推送和弹出。 
- 一旦堆栈等于，我们必须立即停止`target`，即使流中还有更多数字。 
- 尽可能最小的输入，例如`target = [1]`，应该仍然可以正常工作。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试模拟每个可能的序列`"Push"`和`"Pop"`操作，同时检查结果堆栈是否与目标数组匹配。 

对于流中的每个传入数字，我们可以选择是将其保留在堆栈中还是将其删除。 这将创建一个分支决策树，其中每个数字都可能使可能的操作序列数量加倍。 

这种方法是正确的，因为它探索了所有有效的操作组合。 最终，这些组合之一将产生所需的目标堆栈。 

然而，这种方法效率极低。 对于每个数字，可能有两种选择：

 - 保留它
 - 删除它

 这导致可能性呈指数级增长，大约`O(2^n)`最坏情况下的序列。 

尽管实际的约束很小，但暴力是不必要的，因为问题的结构给了我们一个确定性的策略。 

### 最佳方法

 关键的观察结果是流按排序顺序到达，并且`target`也是严格增加的。 

这意味着我们对要做什么永远不会含糊不清：

 - 如果当前流编号与下一个所需的目标编号匹配，我们通过执行来保留它`"Push"`。 
- 否则，我们必须使用丢弃它`"Push"`其次是`"Pop"`。 

我们按顺序处理数字`1`向上直到我们完成目标数组的构建。 

这是有效的，因为每个流编号必须按顺序消耗，并且任何不存在于`target`不能保留在堆栈中。

 | 最佳| O(n) | O(n) | 使用流顺序的贪婪模拟 |

 ## 算法演练

 ### 分步过程

 1. 初始化一个用于存储操作的空结果列表。 

该列表代表了确切的顺序`"Push"`和`"Pop"`我们执行的操作。 
2. 维护一个指向`target`大批。 

该指针跟踪我们当前正在尝试构建的目标值。 
3. 迭代从以下位置开始的流编号`1`。 

我们继续处理，直到我们匹配了所有元素`target`。 
4. 对于每个流编号，始终执行`"Push"`第一的。 

在做出任何决定之前，必须读取并推送每个流值。 
5. 将当前流编号与当前目标值进行比较。 

如果它们相等，我们将值保留在堆栈中并将目标指针向前移动。 
6. 如果数字不匹配，立即执行`"Pop"`。 

这将从堆栈中删除不需要的值，因为它不是目标数组的一部分。 
7. 当所有目标元素都匹配后停止。 

该问题明确指出，一旦堆栈等于目标，我们就应该停止读取流。 

### 为什么它有效

 该算法之所以有效，是因为流和`target`严格增加。 

在每一步中，当前流编号只有两种可能：

 - 它属于目标，所以我们保留它。 
- 它不属于目标，所以我们立即丢弃它。 

由于流不能向后移动，因此必须立即删除每个跳过的数字。 因此，贪婪策略是被迫的，并且总是产生有效的解决方案。 

## Python 解决方案```python
from typing import List

class Solution:
    def buildArray(self, target: List[int], n: int) -> List[str]:
        operations = []
        target_index = 0

        for current_number in range(1, n + 1):
            if target_index >= len(target):
                break

            operations.append("Push")

            if current_number == target[target_index]:
                target_index += 1
            else:
                operations.append("Pop")

        return operations
```实施直接遵循模拟策略。 

我们首先创建一个空的`operations`列表来存储答案。 变量`target_index`跟踪其中的值`target`我们目前正在尝试匹配。 

我们迭代来自的数字`1`到`n`。 对于每个数字，我们总是附加`"Push"`因为自动读取流值需要将其推入堆栈。 

然后我们将当前数字与预期目标值进行比较。 

如果值匹配，我们保留数字并前进目标指针。 

如果值不匹配，我们追加`"Pop"`立即删除不需要的号码。 

一旦所有目标值都匹配，循环就会提前停止，这避免了超出所需目标的不必要的处理。 

## 解决方案```go
func buildArray(target []int, n int) []string {
    operations := []string{}
    targetIndex := 0

    for currentNumber := 1; currentNumber <= n; currentNumber++ {
        if targetIndex >= len(target) {
            break
        }

        operations = append(operations, "Push")

        if currentNumber == target[targetIndex] {
            targetIndex++
        } else {
            operations = append(operations, "Pop")
        }
    }

    return operations
}
```Go 的实现非常接近地反映了 Python 的逻辑。 

切片用于动态存储操作。 由于 Go 切片会自动调整大小`append`，不需要手动内存管理。 

与 Python 不同，Go 不需要显式类型提示，因为编译器从变量声明推断类型。 

不存在溢出问题，因为在问题约束下所有值都非常小。

 ## 边缘情况

 当目标包含连续的每个数字时，就会出现一种重要的边缘情况`1`往后，例如`[1,2,3]`。 在这种情况下，不`"Pop"`需要进行操作。 有缺陷的实现可能仍会尝试不必要的删除。 当前的实现仅正确执行`"Push"`操作，因为每个流编号都与当前目标值匹配。 

另一个重要的边缘情况是在达到所需的目标值之前必须跳过许多数字，例如`[5]`。 这可能会暴露跳过的值未从堆栈中正确删除的错误。 该算法通过始终执行来处理这个问题`"Push"`首先然后立即`"Pop"`每当当前数字与目标不匹配时。 

第三个关键的边缘情况是提前终止。 例如，与`target = [1,2]`和`n = 100`，我们必须在建立目标后立即停止。 幼稚的实现可能会不必要地继续处理流。 该解决方案通过在所有目标元素匹配后立即中断循环来避免这种情况。
