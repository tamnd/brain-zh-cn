[LeetCode 问题 1440](https://leetcode.com/problems/evaluate-boolean-expression/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算存储在数据库表中的布尔表达式。 我们有两张表：`Variables`，它存储变量名称及其对应的整数值，以及`Expressions`，它存储由两个操作数和一个比较运算符组成的布尔表达式。 

中的每一行`Expressions`表示以下形式的条件：```
left_operand operator right_operand
```例如：```
x > y
```操作数是变量名，而不是原始数字。 它们的实际整数值必须从`Variables`桌子。 检索值后，我们使用给定的运算符评估表达式，该运算符只能是以下之一：

 -`<`-`>`-`=`任务是返回一个结果表，其中包含所有原始表达式列以及一个名为`value`，它指示表达式的计算结果是否为`true`或者`false`。 

例如，如果：```
x = 66
y = 77
```然后：```
x < y
```变成：```
66 < 77
```其评估结果为`true`。 

关键的观察是表达式引用变量名称，而不是它们的实际数值。 因此，在计算任何表达式之前，我们必须将每个操作数连接到`Variables`表来检索其整数值。 

该问题保证出现在的每个操作数`Expressions`存在于`Variables`桌子。 这意味着我们永远不需要处理丢失的变量或空查找。 此外，该运算符仅限于三个有效的比较运算符，因此评估逻辑仍然简单。 

一个重要的边缘情况是两个操作数是相同的变量，例如：```
x = x
```在这种情况下，表达式的两侧必须使用相同的值进行计算。 另一种边缘情况涉及不同变量之间的相等数值，其中`<`和`>`变成假的同时`=`成为现实。 如果重复扫描，幼稚的实现也可能会失败`Variables`每个表达式的表，而不是通过连接有效匹配值。 

## 方法

 ### 蛮力方法

 暴力解决方案将通过重复扫描来评估每个表达式`Variables`表来查找两个操作数的值。 

对于每一行`Expressions`，我们会：

 1. 搜索`Variables`找到 的值`left_operand`2. 搜索`Variables`再次求出的值`right_operand`3. 应用运算符来比较两个值
 4. 存储布尔结果

 这种方法之所以有效，是因为每个表达式都是使用正确的变量值独立计算的。 然而，它的效率很低，因为每个表达式都需要多次扫描`Variables`。 

如果有`E`表达式和`V`变量，那么对于每个表达式，我们可能会扫描所有变量两次，产生的时间复杂度为`O(E × V)`。 

### 最佳方法

 关键的见解是关系数据库旨在使用联接有效地匹配相关行。 

我们可以加入`Expressions`表与`Variables`两次：

 - 一次检索值`left_operand`- 一次检索值`right_operand`获得这两个数值后，我们使用`CASE`语句根据运算符计算表达式。 

这可以有效地工作，因为连接允许我们直接将变量名称与值匹配，而无需重复扫描逻辑。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(E × V) | O(1) | O(1) | 重复扫描每个表达式的变量 |
 | 最佳| O(E + V) | O(1) | O(1) | 使用联接有效检索操作数值 |

 ## 算法演练

 1. 从`Expressions`表，因为每一行代表一个我们必须计算的布尔表达式。 
2. 加入`Variables`左操作数的表。 我们匹配：```
Expressions.left_operand = Variables.name
```这给了我们左侧的数值。 
3. 加入`Variables`第二次表以获得正确的操作数。 由于我们需要独立地为两个操作数提供值，因此我们使用不同的别名：```
Expressions.right_operand = Variables.name
```现在我们有两个可用的操作数值。 
4. 使用`CASE`表达式来计算运算符。 由于操作员只能`<`,`>`， 或者`=`，我们检查出现了哪个运算符并应用相应的比较。 
5. 返回原始表达式列加上计算的布尔结果作为`value`柱子。 

### 为什么它有效

 该算法之所以有效，是因为每个操作数都保证存在于`Variables`，这意味着每个连接总是产生一个有效的数值。 通过连接两次，我们检索两个操作数的精确值，并且`CASE`语句根据运算符评估正确的比较。 由于每个表达式都是独立处理的，并且每个运算符都是显式处理的，因此保证输出是正确的。 

## Python 解决方案

 尽管这是一个数据库问题，并且 LeetCode 需要 SQL 查询而不是 Python 代码，但下面以编程方式演示了等效逻辑。```python
from typing import List, Dict

class Solution:
    def evaluateExpressions(
        self,
        variables: List[List[str]],
        expressions: List[List[str]]
    ) -> List[List[str]]:
        variable_map: Dict[str, int] = {
            name: value
            for name, value in variables
        }

        result = []

        for left_operand, operator, right_operand in expressions:
            left_value = variable_map[left_operand]
            right_value = variable_map[right_operand]

            if operator == "<":
                value = left_value < right_value
            elif operator == ">":
                value = left_value > right_value
            else:
                value = left_value == right_value

            result.append([
                left_operand,
                operator,
                right_operand,
                str(value).lower()
            ])

        return result
```实现首先将`Variables`表转换为哈希映射。 这允许恒定时间查找任何变量的数值。 如果没有这个预处理步骤，我们将重复扫描变量列表中的每个表达式。 

接下来，我们迭代每个表达式。 对于每个表达式，我们从哈希映射中检索两个操作数的数值。 一旦我们获得了数字，我们就可以使用标准比较逻辑来应用运算符。 

最后，我们将计算结果附加到输出列表，同时保留原始表达式结构。 

### LeetCode 的 SQL 解决方案

 这是 LeetCode 期望的实际查询：```sql
SELECT
    e.left_operand,
    e.operator,
    e.right_operand,
    CASE
        WHEN e.operator = '>' THEN v1.value > v2.value
        WHEN e.operator = '<' THEN v1.value < v2.value
        ELSE v1.value = v2.value
    END AS value
FROM Expressions e
JOIN Variables v1
    ON e.left_operand = v1.name
JOIN Variables v2
    ON e.right_operand = v2.name;
```此查询执行两个连接来检索操作数值，然后使用`CASE`陈述。 

## 解决方案

 同样，这个问题是基于 SQL 的，但这里有一个 Go 中的等效实现。```go
package main

type Solution struct{}

func (s Solution) EvaluateExpressions(
	variables [][]interface{},
	expressions [][]string,
) [][]string {

	variableMap := make(map[string]int)

	for _, variable := range variables {
		name := variable[0].(string)
		value := variable[1].(int)
		variableMap[name] = value
	}

	result := [][]string{}

	for _, expression := range expressions {
		leftOperand := expression[0]
		operator := expression[1]
		rightOperand := expression[2]

		leftValue := variableMap[leftOperand]
		rightValue := variableMap[rightOperand]

		value := false

		if operator == "<" {
			value = leftValue < rightValue
		} else if operator == ">" {
			value = leftValue > rightValue
		} else {
			value = leftValue == rightValue
		}

		boolString := "false"
		if value {
			boolString = "true"
		}

		result = append(result, []string{
			leftOperand,
			operator,
			rightOperand,
			boolString,
		})
	}

	return result
}
```Go 的实现与 Python 解决方案非常相似。 一个`map[string]int`用于恒定时间变量查找。 由于 Go 没有 Python 风格的动态类型，因此我们在读取输入数据时显式转换值。 布尔值转换为`"true"`或者`"false"`插入结果之前的字符串。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(E + V) | 构建变量查找的成本为 O(V)，计算所有表达式的成本为 O(E) |
 | 空间| O(V) | 哈希映射存储所有变量 |

 该算法非常高效，因为每个变量都只插入到查找结构中一次，并且每个表达式只计算一次。 由于哈希映射查找平均时间是恒定的，因此整体复杂性随着输入大小线性增长。

 ## 边缘情况

 ### 将变量与其自身进行比较

 一个表达式，例如：```
x = x
```如果实现错误地假设操作数始终不同，则可能会暴露错误。 由于两个操作数引用相同的变量，因此两次查找应检索完全相同的值。 我们的实现自然地处理了这个问题，因为两个操作数名称都是通过查找结构或连接独立解析的。 

### 具有相同值的不同变量

 两个不同的变量名可以存储相同的数值：```
a = 10
b = 10
```在这种情况下：```
a = b
```应该评估为`true`， 尽管：```
a > b
```和：```
a < b
```都应该评估为`false`。 该实现避免了此处的错误，因为比较完全基于数值，而不是变量名称。 

### 大量表达式

 重复扫描的简单实现`Variables`随着表达式数量的增加，每个表达式的表将变得低效。 最佳方法通过在 SQL 中使用联接或在代码中使用哈希映射来避免此问题，确保每次查找保持恒定时间并保持总工作线性。
