[LeetCode 第 1446 题](https://leetcode.com/problems/consecutive-characters/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们计算字符串的**幂**。 幂定义为仅包含一个不同字符的最长连续子串的长度。 

简单来说，我们需要找到字符串中连续出现的相同字符的最长条纹。 我们并不是在寻找整体上最常见的字符，而是在寻找最长的不间断序列。 

例如，在`"leetcode"`, 字符`'e'`连续出现为`"ee"`，其长度为`2`。 没有其他字符形成更长的连续序列，所以答案是`2`。 

在`"abbcccddddeeeeedcba"`, 子串`"eeeee"`包含五个连续的`'e'`人物。 即使也有重复`'d'`人物 （`"dddd"`），序列`'e'`更长，所以结果是`5`。 

输入是单个字符串`s`仅由小写英文字母组成。 输出是一个整数，表示任何连续的相同字符块的最大长度。 

限制相对较小：

 -`1 <= s.length <= 500`-`s`仅包含小写英文字母

 这些限制告诉我们，性能并不是主要问题，因为字符串很短。 即使是二次解也能轻松通过。 然而，该问题有一个非常自然的线性时间解决方案，即扫描一次字符串。 

有几个重要的边缘情况需要考虑。 一个长度的字符串`1`应该返回`1`，因为单个字符本身形成一个有效的子字符串。 每个字符都相同的字符串，例如`"aaaaaa"`，应该返回字符串的完整长度。 没有连续重复的字符串，例如`"abcdef"`，应该返回`1`。 该问题保证字符串永远不会为空，因此我们永远不需要处理无效或空的输入。 

## 方法

 ### 蛮力方法

 解决此问题的一种直接方法是检查每个可能的子字符串并检查它是否仅包含一个唯一字符。 

对于每个起始位置，我们可以一次将子字符串扩展一个字符，并验证所有字符是否保持相同。 如果子字符串由单个重复字符组成，我们将更新最大长度。 

该方法是正确的，因为它详尽地考虑了每个候选子串。 最终，它会遇到最长的有效子串并记录其长度。 

然而，这种方法效率低下。 有`O(n²)`总共有几个子字符串，验证每个子字符串可能需要额外的工作。 即使进行了优化，对于仅需要跟踪连续相同字符的问题来说，时间复杂度也会变得不必要的大。 

### 最佳方法，单遍跟踪

 关键的观察是我们只关心字符的**连续运行**。 

我们可以从左到右扫描字符串并计算当前相同字符的长度，而不是检查每个子字符串。 

每当当前字符与前一个字符匹配时，我们就会延长连胜。 否则，我们开始一个新的长度连续`1`。 在此过程中，我们不断跟踪迄今为止遇到的最大条纹长度。 

这是可行的，因为由一个重复字符组成的每个有效子字符串都属于一个连续的运行。 通过测量每次运行一次，我们自然会找到最长的一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 检查所有可能的子字符串并验证重复字符 |
 | 最佳| O(n) | O(1) | O(1) | 单次扫描同时计算连续相同字符 |

 ## 算法演练

 1.初始化两个变量：`current_length`和`max_length`，都开始于`1`。 由于保证字符串非空，因此最小有效幂始终为`1`。 
2.从index开始迭代字符串`1`，将每个字符与前一个字符进行比较。 
3. 如果当前字符与前一个字符相同，则递增`current_length`因为连续的连胜仍在继续。 
4. 如果当前字符不同，则重置`current_length`到`1`因为新的连胜是从当前角色开始的。 
5、每次更新后，进行比较`current_length`和`max_length`。 如果当前条纹较大，则更新`max_length`。 
6.处理完整个字符串后，返回`max_length`。 

### 为什么它有效

 该算法保持了一个重要的不变量：在字符串中的每个位置，`current_length`表示以当前字符结束的连续序列的长度，而`max_length`stores the largest sequence seen so far. 由于每个连续块都被处理一次，并且每当我们发现更长的条纹时我们都会更新最大值，因此最终值`max_length`一定是弦的力量。 

## Python 解决方案```python
class Solution:
    def maxPower(self, s: str) -> int:
        current_length = 1
        max_length = 1

        for index in range(1, len(s)):
            if s[index] == s[index - 1]:
                current_length += 1
            else:
                current_length = 1

            max_length = max(max_length, current_length)

        return max_length
```实现首先初始化两个`current_length`和`max_length`到`1`，因为字符串始终至少包含一个字符。 

循环从索引开始`1`因为每个字符都必须与其前一个字符进行比较。 如果当前字符与前一个字符匹配，则连续字符会继续并且`current_length`增加一。 

当字符不同时，当前的连胜结束，因此我们重置`current_length`到`1`，代表新字符开始其自己的序列。 

每次迭代后，我们都会更新`max_length`使用`max()`确保我们始终保留遍历过程中遇到的最长条纹。 

最后，一旦扫描完成，我们返回`max_length`。 

## 解决方案```go
func maxPower(s string) int {
	currentLength := 1
	maxLength := 1

	for i := 1; i < len(s); i++ {
		if s[i] == s[i-1] {
			currentLength++
		} else {
			currentLength = 1
		}

		if currentLength > maxLength {
			maxLength = currentLength
		}
	}

	return maxLength
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 由于Go中的字符串可以直接按字节索引，并且问题保证小写英文字母，因此字符比较很简单。 

不用担心整数溢出，因为最大字符串长度仅为`500`。 由于保证输入非空，因此我们安全地将两个计数器初始化为`1`无需对空字符串进行特殊处理。

 ## 边缘情况

 一个重要的边缘情况是仅包含单个字符的字符串，例如`"a"`。 粗心的实现可能会错误地初始化计数器或假设至少有两个字符需要比较。 该实现通过将两个计数器初始化为自然地处理这种情况`1`并完全跳过循环，返回正确答案。 

另一种重要的情况是整个字符串由一个重复的字符组成，例如`"aaaaaa"`。 有缺陷的实现可能会忘记在扩展条纹后更新最大值，尤其是在字符串末尾。 由于此解决方案更新`max_length`在每次迭代期间，最终最长的条纹都会被正确记录。 

当没有重复的相邻字符时，会出现第三种边缘情况，例如`"abcdef"`。 在这种情况下，每条条纹都有长度`1`。 实施正确重置`current_length`到`1`在每个角色转换时，以及`max_length`永远不会超过`1`。 

最后一个棘手的情况是多个条纹具有相同的最大长度，例如`"aaabbbccc"`。 该算法不需要跟踪哪个字符创建了条纹，只需要跟踪最大长度。 因为`max_length`存储迄今为止看到的最佳结果，自动处理平局并返回正确的值。
