[LeetCode 第 1428 题](https://leetcode.com/problems/leftmost-column-with-at-least-a-one/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、矩阵、交互

 ## 解决方案

 ## 问题理解

 这个问题使我们能够访问一个二进制矩阵，其中每一行都按非降序排序。 这意味着每一行看起来都像一些`0`s 后面跟着一些`1`s。 例如：```
[0, 0, 0, 1, 1]
```有效，同时：```
[0, 1, 0, 1]
```不是。 

目标是找到至少包含一个的最左边的列索引`1`。 如果矩阵不包含`1`根本没有，我们回来`-1`。 

重要的限制是这是一个交互问题。 我们无法直接访问矩阵。 相反，我们通过提供的交互`BinaryMatrix`应用程序编程接口：

 -`binaryMatrix.get(row, col)`检索单个值。 
-`binaryMatrix.dimensions()`回报`[rows, cols]`。 

法官还限制了数量`get()`最多调用`1000`，所以效率很重要。 即使矩阵维度最多为`100 x 100`，我们仍然应该避免不必要地扫描每个单元格。 

因为每一行都是排序的，一旦我们遇到一个`1`在一行中，其右侧的所有元素也是`1`。 同样，如果我们看到一个`0`，其左侧的所有内容也是`0`。 这种排序属性是实现高效解决方案的关键观察结果。 

一些边缘情况很重要：

 - 矩阵可能只包含`0`s，所以答案应该是`-1`。 
- 最左边的列本身可能已经包含`1`，所以答案可能是`0`。 
- 一行可能不包含`1`根本没有。 
- 一行只能包含`1`s。 
- 矩阵可以只有一行或一列。 

该问题保证所有行都已排序，这允许我们使用二分搜索或更智能的遍历策略。 

## 方法

 ### 蛮力方法

 最直接的解决方案是从左到右逐列扫描矩阵。 对于每一列，我们检查每一行以查看是否`1`存在。 

当我们找到一个`1`在一列中，我们立即返回该列索引，因为我们是从左到右扫描，所以它必须是最左边的有效列。 

这种方法是正确的，因为它按顺序显式检查每个可能的候选列。 但是，它会执行许多不必要的 API 调用。 在最坏的情况下，我们检查矩阵中的每个单元格。 

与一个`100 x 100`矩阵，这意味着最多`10,000`打电话给`get()`，超出了允许的限制`1000`。 

### 最佳方法

 关键的见解来自行排序属性。 

我们可以从矩阵的右上角开始：

 - 如果当前单元格是`1`，则该列是有效的候选答案，但左侧可能有更小的列索引。 所以我们向左移动。 
- 如果当前单元格是`0`，那么该行左边的所有内容也是`0`，所以这一行不能帮助我们进一步。 我们向下移动。 

这将创建一个穿过矩阵的楼梯。 

因为我们只向左或向下移动，所以每一行和每一列最多被访问一次。 总移动次数最多为：```
rows + cols
```这是非常有效的。

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|

 ## 算法演练

 1. 使用以下方法检索矩阵维度`binaryMatrix.dimensions()`。 

在遍历开始之前我们需要行数和列数。 
2. 从右上角开始。 

初始化：

 -`row = 0`-`col = cols - 1`右上角很有用，因为它为我们提供了方向信息：

 - A`1`意味着我们可以向左移动。 
- A`0`意味着我们必须向下移动。 
3.维护一个变量来存储当前的最佳答案。 

初始化：```
answer = -1
```如果我们遇到一个`1`，我们更新这个值。 
4. 当我们留在矩阵内时进行遍历。 

继续，同时：```
row < rows and col >= 0
```5. 查询当前单元格使用`binaryMatrix.get(row, col)`。 

有两种可能：

 - 如果该值为`1`:

 - 将当前列记录为候选答案。 
- 向左移动，因为我们想要更小的列索引。 
- 如果该值为`0`:

 - 向下移动，因为该行左侧的所有值也都是`0`。 
6. 返回最终答案。 

如果我们从未遇到过`1`，答案依然是`-1`。 

### 为什么它有效

 该算法依赖于每行的排序结构。 

At any position:

- If we see a`0`，那么该行左边的所有内容也必须是`0`，所以向左移动是没有意义的。 我们向下移动。 
- If we see a`1`，则当前列有效，但可能还有其他列`1`再往左。 我们向左移动以搜索较小的列索引。 

因为每一步都会从考虑中消除一行或一列，所以我们永远不会重新访问单元格。 遍历保证最左边的列包含`1`将会被发现。 

## Python 解决方案```python
# """
# This is BinaryMatrix's API interface.
# You should not implement it, or speculate about its implementation
# """
# class BinaryMatrix(object):
#     def get(self, row: int, col: int) -> int:
#     def dimensions(self) -> list[]:

from typing import List

class Solution:
    def leftMostColumnWithOne(self, binaryMatrix: 'BinaryMatrix') -> int:
        rows, cols = binaryMatrix.dimensions()

        row = 0
        col = cols - 1

        leftmost_col = -1

        while row < rows and col >= 0:
            if binaryMatrix.get(row, col) == 1:
                leftmost_col = col
                col -= 1
            else:
                row += 1

        return leftmost_col
```实现首先检索矩阵维度。 然后我们在右上角初始化遍历。 

变量`leftmost_col`存储迄今为止找到的最佳答案。 它开始于`-1`，这也正确处理了没有的情况`1`存在于矩阵中。 

在循环内，每个 API 调用都会确定下一个移动方向：

 - A`1`更新答案并向左移动。 
- A`0`向下移动。 

由于循环仅沿这两个方向之一移动，因此迭代总数受下式限制：`rows + cols`。 

该实现直接反映了算法演练中解释的楼梯遍历。 

## 解决方案```go
/**
 * // This is the BinaryMatrix's API interface.
 * // You should not implement it, or speculate about its implementation
 * type BinaryMatrix struct {
 *     Get func(int, int) int
 *     Dimensions func() []int
 * }
 */

func leftMostColumnWithOne(binaryMatrix BinaryMatrix) int {
    dimensions := binaryMatrix.Dimensions()

    rows := dimensions[0]
    cols := dimensions[1]

    row := 0
    col := cols - 1

    leftmostCol := -1

    for row < rows && col >= 0 {
        if binaryMatrix.Get(row, col) == 1 {
            leftmostCol = col
            col--
        } else {
            row++
        }
    }

    return leftmostCol
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于语法和 API 访问风格。 

维度作为切片检索，因此我们使用索引访问行和列`0`和`1`。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有索引都保留在矩阵范围内。 

遍历逻辑保持不变，`row++`和`col--`通过矩阵控制运动。

 ## 边缘情况

 当矩阵不包含任何内容时，就会出现一种重要的边缘情况`1`根本没有。 幼稚的实现可能会错误地返回`0`或另一个列索引（如果它没有仔细初始化答案变量）。 在这个解决方案中，`leftmost_col`开始为`-1`并且仅在以下情况下更新`1`是实际遇到的，所以全零的情况处理正确。 

另一个重要的边缘情况是当第一列已经包含`1`。 一些实现在发现任何问题后过早停止`1`，但这会产生不正确的结果，因为我们特别需要最左边的列。 每当遇到以下情况时，该实现都会继续向左移动`1`，保证找到最小的有效列索引。 

第三种边缘情况涉及只有一行或一列的矩阵。 遍历算法有时假设两个维度都大于一维，这可能导致索引错误或不正确的循环终止。 这里，循环条件：```
while row < rows and col >= 0:
```自然地处理这些小尺寸，而不需要特殊情况的逻辑。 

当某些行不包含任何内容时，会发生另一种微妙的情况`1`而其他人则这样做。 因为算法在看到 a 之后向下移动`0`，它正确地跳过无法提供更好答案的行，同时仍然探索下面可能包含较早内容的行`1`s`。
