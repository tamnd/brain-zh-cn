[LeetCode 问题 1466](https://leetcode.com/problems/reorder-routes-to-make-all-paths-lead-to-the-city-zero/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、图论

 ## 解决方案

 ## 问题理解

 该问题为我们提供了由道路连接的城市的有向图。 有`n`城市编号为`0`到`n - 1`，并且准确地说`n - 1`道路。 由于该图包含`n - 1`边，并且任意一对城市之间只有一条路径，该图形成一棵树。 

目前每条路都有一个方向。 一个连接`[a, b]`表示道路是从城市出发的`a`到城市`b`。 

目标是确保每个城市都能到达城市`0`遵循道路指示。 我们可以改变道路的方向，并且我们想找到所需的最少逆转次数。 

另一种思考问题的方式是：在进行所有更改之后，树中的每条路径最终都必须通向城市`0`。 

输入包括：

 -`n`, 城市数量
 -`connections`，有向道路列表

 输出是一个整数，表示必须更改方向的道路的最小数量。 

约束很重要，因为它们决定哪种类型的解决方案是可行的。 

城市数量最多可达`5 * 10^4`，这意味着我们需要一个接近线性时间的解决方案。 任何重复遍历图或尝试多种边反转组合的方法都会太慢。 

该图保证是一棵树，这为我们提供了几个有用的属性：

 - 没有循环
 - 任意两个城市之间只有一条路径
 - 每个边缘对于连接都是至关重要的

 这些保证大大简化了问题，因为我们永远不需要担心多个替代路线。 

一些边缘情况很重要：

 - 一些道路可能已经指向城市`0`，不需要改变
 - 所有道路可能远离城市`0`，需要多次反转
 - 树可能高度不平衡，类似于链表
 - 该图可能已经满足条件，产生的答案为`0`这个问题还保证了总是可以重新安排道路，以便每个城市都可以到达城市`0`。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试不同的边缘反转组合，然后检查每个城市是否可以到达城市`0`。 

一种可能的实现是迭代边的子集，反转这些边，并使用每个节点的 BFS 或 DFS 运行可达性检查。 如果所有节点都能到达城市`0`，子集有效。 最小的有效子集就是答案。 

这种方法是正确的，因为它最终会检查每组可能的逆转。 然而，这在计算上是不可行的。 

一棵树与`n - 1`边缘有`2^(n-1)`可能的逆转组合。 对于每种组合，我们可能需要图遍历来验证连通性。 和`n`最多`50000`，这种做法是完全不切实际的。 

### 最佳方法

 关键的见解来自于对树结构的理解。 

由于图是一棵树，因此从每个节点到城市都有一条路径`0`。 因此，对于每条边，如果我们希望所有路径都通向，则只有一个正确方向`0`。 

我们可以将图视为无向以进行遍历，同时记住原始边缘方向。 

从城市出发`0`，我们通过树进行DFS或BFS。 

每当我们遍历一条边时：

 - 如果边缘最初指向远离城市的方向`0`，必须颠倒过来
 - 如果边缘已经指向城市`0`，这是正确的

 遍历自然会恰好访问每条边一次，并且每条方向错误的边都会对答案产生一次反转。 

这是有效的，因为在树中，每个节点都有相对于城市的唯一父关系`0`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 尝试所有反转组合 |
 | 最佳 | O(n) | O(n) | DFS/BFS 遍历计数错误方向 |

 ## 算法演练

 1. 构建图的邻接列表表示。 

由于我们需要在两个方向上遍历树，因此我们创建了一个无向表示。 然而，我们还需要记住每条边最初是否是远离当前节点的。 

对于每个有向边`[a, b]`：

- 添加`(b, 1)`到`a`的邻接列表，因为从`a`到`b`遵循原来的方向，这意味着如果我们远离城市，这条边缘将需要逆转`0`- 添加`(a, 0)`到`b`的邻接列表，因为从`b`到`a`与原来的方向相反，意味着边缘已经正确指向城市`0`2.从城市启动DFS或BFS`0`。 

城市`0`是所有路径的目的地，因此它成为我们遍历的根。 
3. 维护访问集或家长跟踪。 

由于图在我们的遍历结构中是无向的，因此我们必须避免重新访问节点并创建无限循环。 
4. 遍历各个邻近城市。 

对于每个相邻节点：

 - 如果边成本是`1`，道路目前远离城市`0`，所以增加答案
 - 继续递归或迭代遍历
 5. 继续，直到访问完所有节点。 

由于该图是连通的并且包含`n - 1`边缘，从城市穿越`0`每个节点恰好到达一次。 
6. 返回计数的反转总数。 

### 为什么它有效

 该算法之所以有效，是因为树中的每个节点都有一条通往城市的路径`0`。 在遍历过程中，如果一条边远离根方向，则该边将阻止其子树中的节点到达城市`0`。 扭转它是必要且充分的。 

由于每条边都被检查一次，并且每个方向错误的边都被计算一次，因此最终计数是所需的最小反转次数。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def minReorder(self, n: int, connections: List[List[int]]) -> int:
        graph = defaultdict(list)

        for a, b in connections:
            graph[a].append((b, 1))
            graph[b].append((a, 0))

        visited = set()

        def dfs(city: int) -> int:
            visited.add(city)

            changes = 0

            for neighbor, needs_reversal in graph[city]:
                if neighbor not in visited:
                    changes += needs_reversal
                    changes += dfs(neighbor)

            return changes

        return dfs(0)
```实现首先构建一个邻接表。 每个条目都存储相邻节点和一个标志，该标志指示遍历该边是否遵循原始方向。 

对于原始边缘`a -> b`：

 - 搬自`a`到`b`表示远离城市的边缘点`0`，所以可能需要反转
 - 搬自`b`到`a`意味着边缘已经指向城市`0`DFS遍历从城市开始`0`。 访问集可以防止重新访问节点，因为遍历图是无向的。 

在 DFS 内部，每个未访问过的邻居都会被探索。 如果边缘方向相对于城市遍历不正确`0`，算法增加反转计数器。 

递归调用会累积整个树的反转总数。 

## 解决方案```go
package main

func minReorder(n int, connections [][]int) int {
	graph := make([][][2]int, n)

	for _, edge := range connections {
		a, b := edge[0], edge[1]

		graph[a] = append(graph[a], [2]int{b, 1})
		graph[b] = append(graph[b], [2]int{a, 0})
	}

	visited := make([]bool, n)

	var dfs func(int) int

	dfs = func(city int) int {
		visited[city] = true

		changes := 0

		for _, neighbor := range graph[city] {
			nextCity := neighbor[0]
			needsReversal := neighbor[1]

			if !visited[nextCity] {
				changes += needsReversal
				changes += dfs(nextCity)
			}
		}

		return changes
	}

	return dfs(0)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

Go 使用固定大小的数组，而不是 Python 元组`[2]int`来存储邻居信息。 

使用布尔切片而不是集合来跟踪访问的节点，因为城市标签的范围为`0`到`n - 1`，使索引查找更加高效。 

DFS 函数被实现为闭包，因此它可以直接访问图和访问过的切片。 

因为最大答案最多是`n - 1`, Go 的标准不关心整数溢出`int`类型。

 ## 边缘情况

 当所有道路都指向城市时，就会出现一种重要的边缘情况`0`。 在这种情况下，正确答案是`0`。 有缺陷的实现可能会错误地计算边，因为它们是在 DFS 期间遍历的。 此实现通过显式存储边缘是否需要反转并仅在必要时增加答案来避免该问题。 

另一个关键的边缘情况是完全不正确的链，例如`0 -> 1 -> 2 -> 3`。 每条边都必须反转。 递归遍历正确识别每个向外的边缘，因为每个 DFS 步骤都远离城市`0`遵循原来的方向。 

高度不平衡的树也可能会出现问题，因为递归 DFS 可能会变得很深。 该算法仍然可以正常工作，因为每个节点都被访问一次。 在 Python 中，理论上，递归深度对于极深的树来说可能会成为一个问题，尽管问题约束在 LeetCode 的环境中通常是可以管理的。 如果考虑递归限制，则可以使用迭代 DFS 或 BFS。 

以城市为中心的星形图`0`是另一个有用的边缘情况。 如果所有边都从`0`，每条边都必须反转。 如果所有边缘都指向内，则不应反转任何边缘。 邻接编码干净地处理这两种情况，因为每条边独立记录它相对于从城市的遍历是否正确定向`0`。
