 # LeetCode 1434 - 互相戴不同帽子的方法数

 ## 问题理解

 这个问题要求我们计算在两个约束下有多少种有效的方法来为人们分配帽子：

 1. 每个人必须收到一顶自己喜欢的帽子。 
2. 任何两个人不得戴同一顶帽子。 

输入是一个二维数组，称为`hats`。 

-`hats[i]`包含个人喜欢的所有帽子号码`i`- 帽子号码范围为`1`到`40`- 最多有`10`人

 目标是计算不同有效分配的总数并返回模数答案`10^9 + 7`。 

有效的分配意味着：

 - 每个人都会收到一顶帽子
 - 指定的帽子属于该人的偏好列表
 - 每顶分配的帽子都是独一无二的

 例如：```
hats = [[3,5,1],[3,5]]
```人`0`喜欢帽子`3`,`5`， 和`1`。 

人`1`喜欢帽子`3`和`5`。 

有效的分配是：```
(3,5)
(5,3)
(1,3)
(1,5)
```所以答案是`4`。 

约束条件极其重要：

 -`n <= 10`- 帽子标签仅限于`40`乍一看，这看起来像是一个二分匹配计数问题。 重要的观察是，人数很少，而帽子类型的数量固定为`40`。 

这强烈建议使用位掩码来表示哪些人已经收到了帽子。 

主要的边缘情况包括：

 - 多人喜欢同一小套帽子
 - 一个人只有一顶可能的帽子
 - 不存在有效分配的情况
 - 偏好之间存在较大重叠
 - 最大尺寸首选项列表

 由于分配数量呈指数级增长，简单的暴力解决方案变得不可行。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试了所有可能的帽子分配给人们。 

实现这一点的一种方法是：

 - 一位一位地处理人
 - 对于每个人来说，尝试他们喜欢的每一顶帽子
 - 跳过已经用过的帽子
 - 递归继续，直到分配完所有人员

 这保证了正确性，因为每个有效的分配都会被探索一次。 

然而，复杂性变得非常大。 

如果每个人都喜欢很多帽子，我们可以粗略探讨一下：```
40 * 39 * 38 * ...
```的可能性。 

在最坏的情况下，这会变得过于昂贵。 

虽然`n <= 10`，分支因子很大。 

### 关键见解

 批判性的观察是，只有`10`people，这意味着我们可以使用大小的位掩码来表示赋值状态`2^10`。 

我们不是给人们分配帽子，而是扭转思维：

 - 迭代帽子`1`到`40`- 对于每一顶帽子，决定是否将其送给一位符合条件的人
 - 使用位掩码跟踪哪些人已经拥有帽子

 这种转变之所以强大，是因为：

 - 帽子的数量固定为`40`- 州的人数仅为`2^10 = 1024`这允许动态编程：```
(current_hat, assigned_people_mask)
```DP状态代表：

 > 考虑到当前一组已经分配了帽子的人，我们可以从该帽子编号开始分配多少种帽子？ 

这大大减少了搜索空间。

 ## 算法演练

 ### 第 1 步：构建反向映射

 而不是存储：```
person -> hats
```我们建造：```
hat -> people
```这使我们能够有效地确定哪些人可以戴特定的帽子。 

例如：```
hats = [[3,4],[4,5],[5]]
```变成：```
3 -> [0]
4 -> [0,1]
5 -> [1,2]
```这很有用，因为我们按顺序处理帽子。 

### 步骤 2：定义位掩码

 我们使用位掩码来表示哪些人已经拥有帽子。 

为了`n = 3`:```
mask = 101
```意思是：

 - 人`0`有帽子
 - 人`1`不
 - 人`2`有帽子

 最终目标状态为：```
(1 << n) - 1
```这意味着所有人都有分配的帽子。 

### 步骤 3：定义 DP 状态

 我们定义：```
dp[mask]
```如：

 > 处理一些帽子后达到此分配状态的方法数量。 

最初：```
dp[0] = 1
```因为有一种方法可以不分配帽子。 

### 步骤 4：一一处理帽子

 对于每一顶帽子`1`到`40`:

 - 要么跳过帽子
 - 或将其分配给一名符合条件的未分配人员

 我们为每个帽子创建一个新的 DP 数组。 

这可以防止在一次迭代中多次重复使用同一顶帽子。 

### 步骤 5：尝试分配当前帽子

 对于每个当前掩码：

 - 检查每个喜欢这顶帽子的人
 - 如果该人在当前掩码中未分配：

 - 创建一个分配给该人的新面具
 - 将当前计数添加到新状态中

 过渡看起来像：```
new_mask = mask | (1 << person)
```### 第 6 步：返回最终状态

 处理完所有帽子后：```
dp[all_people_assigned]
```包含有效分配的数量。 

返回该值的模数`10^9 + 7`。 

## 为什么它有效

 该算法之所以有效，是因为每个帽子都只处理一次，并且每个有效的分配都对应于唯一的 DP 转换序列。 

位掩码保证：

 - 没有人收到超过一顶帽子
 - 帽子不会重复使用

 由于每个可能的合法分配都是通过 DP 转换进行探索的，因此最终计数是正确的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def numberWays(self, hats: List[List[int]]) -> int:
        MOD = 10**9 + 7
        n = len(hats)

        hat_to_people = defaultdict(list)

        for person, preferred_hats in enumerate(hats):
            for hat in preferred_hats:
                hat_to_people[hat].append(person)

        total_masks = 1 << n
        dp = [0] * total_masks
        dp[0] = 1

        for hat in range(1, 41):
            next_dp = dp[:]

            for mask in range(total_masks):
                if dp[mask] == 0:
                    continue

                for person in hat_to_people[hat]:
                    if mask & (1 << person):
                        continue

                    new_mask = mask | (1 << person)

                    next_dp[new_mask] = (
                        next_dp[new_mask] + dp[mask]
                    ) % MOD

            dp = next_dp

        return dp[total_masks - 1]
```实现首先构建从帽子到人的反向映射。 这样可以有效地访问所有可以戴特定帽子的人。 

DP数组有大小`2^n`，其中每个索引代表指定人员的位掩码。`dp[mask]`存储实现该分配状态的方法数量。 

对于每一顶帽子`1`到`40`，我们创建一个名为`next_dp`。 

副本很重要，因为它确保每个帽子在过渡期间最多使用一次。 

对于每个面具：

 - 如果状态计数为零，我们跳过它
 - 否则，我们尝试将当前的帽子分配给每个符合条件的未分配人员

 新的赋值状态是通过按位或运算创建的。 

最后，处理完所有帽子后，答案将存储在设置所有位的掩码中。 

## 解决方案```go
package main

func numberWays(hats [][]int) int {
	const MOD = 1000000007

	n := len(hats)

	hatToPeople := make([][]int, 41)

	for person, preferredHats := range hats {
		for _, hat := range preferredHats {
			hatToPeople[hat] = append(hatToPeople[hat], person)
		}
	}

	totalMasks := 1 << n

	dp := make([]int, totalMasks)
	dp[0] = 1

	for hat := 1; hat <= 40; hat++ {
		nextDP := make([]int, totalMasks)
		copy(nextDP, dp)

		for mask := 0; mask < totalMasks; mask++ {
			if dp[mask] == 0 {
				continue
			}

			for _, person := range hatToPeople[hat] {
				if (mask & (1 << person)) != 0 {
					continue
				}

				newMask := mask | (1 << person)

				nextDP[newMask] =
					(nextDP[newMask] + dp[mask]) % MOD
			}
		}

		dp = nextDP
	}

	return dp[totalMasks-1]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

切片的切片用于反向映射：```go
hatToPeople := make([][]int, 41)
```在 Go 中，位运算自然适用于整数。 

这`copy`函数用于为每次帽子迭代复制 DP 数组。 

每次更新后都会执行模运算以防止溢出。

 ## 边缘情况

 ### 很多人想要同一顶帽子

 考虑：```
[[1],[1]]
```两个人都只喜欢帽子`1`。 

由于帽子必须是独一无二的，因此只有一个人可以收到这顶帽子。 

不存在有效的分配。 

幼稚的实现可能会意外地计算无效的重复分配。 位掩码 DP 可以防止这种情况发生，因为一旦分配了帽子，转换仅更新一个新状态。 

### 一个人有很多选择

 考虑：```
[[1,2,3,4,5]]
```虽然只有一个人，但是可以接受的帽子有很多。 

该算法正确地将每个帽子计数为单独的有效分配，因为从空掩码的每次转换都会产生唯一的最终状态。 

### 没有足够独特的帽子

 考虑：```
[[1,2],[1,2],[1,2]]
```三个人，但只有两顶不同的帽子。 

尽管每个人都有偏好，但不可能为所有人分配独特的帽子。 

DP 自然会处理这个问题，因为最终的完整分配掩码永远不会达到。 

### 偏好重叠较大

 考虑：```
[[1,2,3],[1,2,3],[1,2,3]]
```每个人都喜欢同样的帽子。 

这创造了许多重叠的递归可能性。 

强力 DFS 会反复重新计算类似的状态。 

DP 避免了重新计算，因为每个分配状态都由其位掩码表示一次。
