[LeetCode 1416 题](https://leetcode.com/problems/restore-the-array/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`表示多个不带空格连接在一起的正整数。 最初，该数组包含范围内的整数`[1, k]`，并且所有整数都没有前导零。 

我们的任务是确定有多少个不同的有效数组可以生成该字符串`s`。 

例如，如果：```
s = "1317"
k = 2000
```那么几个有效的分割是可能的：```
[1317]
[131,7]
[13,17]
[1,317]
[13,1,7]
[1,31,7]
[1,3,17]
[1,3,1,7]
```因此答案是`8`。 

关键的挑战是决定在哪里分割字符串。 每个子串必须满足两个条件：

 1. 不得包含前导零。 
2.其数值必须介于`1`和`k`。 

约束条件极其重要：

 -`s.length`可以大到`10^5`-`k`可以达到`10^9`尝试所有可能的分裂的强力解决方案将呈指数级缓慢，因为每个位置都可能分裂或不分裂。 

输入保证`s`本身不以前导零开头，但在分割过程中形成的子串仍可能以`'0'`，并且这些子字符串无效。 

一些边缘情况很重要：

 - 在困难位置包含零的字符串，例如`"1000"`- 非常小`k`，这会使许多子字符串无效
 - 大量输入，没有记忆的递归会超时
 - 不存在有效分割的情况
 - 每个数字都可以独立分割的情况

 因为答案可能变得非常大，所以我们必须将其模数返回：```
10^9 + 7
```## 方法

 ### 蛮力方法

 蛮力策略是递归地尝试每一个可能的分割。 

在每个索引处，我们考虑从该位置开始的所有子字符串：```
s[i:j]
```如果子字符串有效，则意味着：

 - 它不开始于`'0'`- 其整数值最多为`k`然后我们递归地解决剩余的后缀。 

这种方法是正确的，因为它探索了字符串的每个可能的分区。 

然而，它太慢了。 在最坏的情况下，每个位置都可以分支为多个递归调用，从而导致指数级的复杂性。 和`10^5`字符，这变得完全不可行。 

### 关键见解

 该问题具有重叠的子问题。 

如果我们定义：```
dp[i] = number of ways to restore the substring s[i:]
```然后许多递归路径重复计算相同的后缀结果。 

这自然意味着动态规划。 

在每个索引处`i`，我们尝试逐位扩展当前数字，直到：

 - 数量超过`k`- 或者我们到达字符串的末尾

 对于形成的每个有效数字，我们添加：```
dp[next_position]
```到答案。 

因为`k <= 10^9`，任何有效数字最多可以包含 10 位数字。 这非常重要，因为它限制了每个职位的工作量。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试每一个可能的分割 |
 | 最优动态规划| O(n * log10(k)) | O(n * log10(k)) | O(n) | 有效地重用重叠子问题 |

 ## 算法演练

 1.创建一个DP数组，其中`dp[i]`表示恢复从索引开始的子字符串的有效方法数`i`。 
2. 初始化基本情况：```
dp[n] = 1
```在哪里`n`是字符串的长度。 

这意味着只有一种方法可以恢复空后缀，即不选择任何内容。 
3. 从右向左处理字符串。 

我们向后退，因为每个状态都取决于未来的状态。 
4. 在每个索引处`i`，首先检查是否：```
s[i] == '0'
```如果是这样，则此处不能开头有效数字，因为禁止使用前导零。 

所以：```
dp[i] = 0
```5. 否则，开始逐位构造数字。 

从以下开始：```
current_number = 0
```然后一次扩展子字符串一个字符。 
6. 对于每个分机：```
current_number = current_number * 10 + digit
```7.如果`current_number > k`，立即停止。 

任何更长的子串只会变得更大。 
8. 否则，从下一个位置开始添加路数：```
dp[i] += dp[j + 1]
```9. 每次加法后应用模运算。 
10.处理完所有索引后，返回：```
dp[0]
```### 为什么它有效

 该算法之所以有效，是因为每个有效的数组恢复都对应于选择一个有效的第一个数字，然后独立地恢复剩余的后缀。 

对于每个索引`i`，DP状态对所有有效分解进行计数`s[i:]`。 通过尝试每个有效的下一个数字并对剩余后缀的解决方案求和，我们将每个合法分区恰好枚举一次。 

其递归式为：$dp[i] = \sum dp[j+1]$其中每个子串`s[i:j]`形成一个有效整数`[1, k]`。 

## Python 解决方案```python
class Solution:
    def numberOfArrays(self, s: str, k: int) -> int:
        MOD = 10**9 + 7
        n = len(s)

        dp = [0] * (n + 1)
        dp[n] = 1

        for i in range(n - 1, -1, -1):
            if s[i] == '0':
                continue

            current_number = 0

            for j in range(i, n):
                current_number = current_number * 10 + int(s[j])

                if current_number > k:
                    break

                dp[i] = (dp[i] + dp[j + 1]) % MOD

        return dp[0]
```实现直接遵循前面描述的动态编程策略。 

数组`dp`存储恢复每个后缀的方法数。 基本情况`dp[n] = 1`代表空后缀。 

外循环向后迭代字符串，因为每个位置都取决于未来的状态。 

当一个数字`'0'`遇到这种情况时，循环会跳过处理，因为数字不能以前导零开头。 

内部循环通过每次扩展子字符串一位数字来逐渐构造数字。 一旦数量超过`k`，循环停止，因为任何进一步的扩展只会增加该值。 

对于每个有效数字，算法都会添加下一个索引的恢复方式的数量。 

模运算防止整数溢出，满足问题要求。 

## 解决方案```go
func numberOfArrays(s string, k int) int {
	const MOD int = 1_000_000_007

	n := len(s)

	dp := make([]int, n+1)
	dp[n] = 1

	for i := n - 1; i >= 0; i-- {
		if s[i] == '0' {
			continue
		}

		currentNumber := 0

		for j := i; j < n; j++ {
			currentNumber = currentNumber*10 + int(s[j]-'0')

			if currentNumber > k {
				break
			}

			dp[i] = (dp[i] + dp[j+1]) % MOD
		}
	}

	return dp[0]
}
```Go 实现密切反映了 Python 逻辑。 

因为 Go 默认情况下没有 Python 的任意精度整数，所以我们依赖以下事实：`k <= 10^9`， 所以`int`就足够了。 

使用以下命令执行字符到数字的转换：```go
int(s[j] - '0')
```DP切片初始化为大小`n + 1`，以及基本情况`dp[n] = 1`与 Python 解决方案相同。

 ## 边缘情况

 一种重要的边缘情况涉及以以下内容开头的子字符串`'0'`。 由于禁止使用前导零，因此必须立即拒绝任何以零开头的分区。 一个常见的错误是意外地允许子字符串，例如`"01"`或者`"000"`。 该实现通过在任何时候跳过处理来处理这个问题`s[i] == '0'`。 

当数量超过时，会出现另一个关键的边缘情况`k`。 一旦当前构造的数量大于`k`，继续扩展子字符串是没有意义的，因为额外的数字只会进一步增加值。 实现立即跳出内循环，既正确又高效。 

第三个重要的边缘情况是根本不存在有效的修复体。 例如：```
s = "1000"
k = 10
```每个可能的分割最终都会产生一个带有前导零或大于的数字的段`k`。 DP 自然地向上传播零，从而得到最终答案`0`。 

大量投入也很重要。 自从`s.length`可以达到`10^5`，没有记忆的递归暴力解决方案将导致指数运行时间或堆栈溢出。 自下而上的 DP 方法完全避免了递归，即使在最大输入大小下也能高效运行。
