[LeetCode 问题 1439](https://leetcode.com/problems/find-the-kth-smallest-sum-of-a-matrix-with-sorted-rows/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、堆（优先级队列）、矩阵

 ## 解决方案

 ## 问题理解

 问题需要找到`kth`通过从矩阵的每一行中精确选择一个元素可获得的最小总和`mat`与排序的行。 每行都按非降序排序，我们必须探索跨行元素的组合以形成总和。 输入是一个二维矩阵`m x n`和一个整数`k`。 输出是一个整数，表示`kth`所有有效组合的最小总和。 

约束告诉我们矩阵最多可以有 40 行和 40 列（`1 <= m, n <= 40`），每个元素都是正数且最多 5000 个，并且`k`的边界是`min(200, n^m)`。 这意味着对于大输入来说，暴力生成所有可能的组合是不切实际的，因为`n^m`可能是巨大的，但是`k`相对较小，允许对优先级队列或对总和进行二分搜索等优化。 重要的边缘情况包括最小维度 (1x1) 的矩阵、所有元素都相同的矩阵以及`k`大于不同和的数量。 

## 方法

 暴力方法通过从每一行中选取一个元素来生成所有可能的数组，计算它们的总和，对总和进行排序，然后返回`kth`最小的。 虽然正确，但效率很低，因为它需要生成`n^m`求和，这对于大型矩阵来说在计算上是不可行的。 

最佳方法的关键观察是行是排序的，因此对于任何给定的行，最小的总和组合涉及首先获取较小的元素。 这使我们能够使用最小堆（优先级队列）来有效地按顺序生成最小的总和，而无需枚举所有可能性。 在每一步中，我们通过将一行中的一个元素替换为该行中的下一个元素，将新的和推入堆中，并仅维护`k`最小的总和。 这是使用最小堆的 k 路合并的经典应用。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^m log(n^m)) | O(n^m log(n^m)) | O(n^m) | O(n^m) | 生成所有总和、排序并选择第 k 个 |
 | 最小堆合并 | O(m * k * log k) | O(m * k * log k) | O(k) | 逐步合并行，仅保留 k 个最小和 |

 ## 算法演练

 1. 用矩阵的第一行初始化一个最小堆。 这表示仅该行可能的最小总和。 
2. 迭代矩阵中的剩余行。 对于每一行，通过将当前行的每个元素添加到上一步的堆中的总和中来生成新的候选总和。 
3. 保持最大大小的最小堆`k`对于这些新的金额。 这确保我们只记录尽可能小的总和。 
4. 处理完所有行后，最小堆包含`k`所有组合中的最小总和。 
5. 如果为前 k 个和维护最大堆，则返回堆中最大的元素，或者从最小堆中弹出`k`如果使用标准最小堆，则为 1 倍。 

**为什么有效：** 通过迭代合并行，并且由于排序属性始终只考虑下一个最小的元素，该算法保证堆将始终包含`k`每次合并后的最小总和。 这可以保持正确性，而无需枚举所有可能的总和。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def kthSmallest(self, mat: List[List[int]], k: int) -> int:
        # Initialize with the first row
        heap = mat[0][:]  # Make a copy
        heapq.heapify(heap)
        
        for i in range(1, len(mat)):
            new_heap = []
            row = mat[i]
            for prev_sum in heap:
                for num in row:
                    new_sum = prev_sum + num
                    heapq.heappush(new_heap, new_sum)
            # Keep only the k smallest sums
            heap = heapq.nsmallest(k, new_heap)
        
        # The kth smallest sum
        return heap[k - 1]
```**实现演练：** 我们首先将第一行复制到堆中。 对于每个后续行，我们计算先前总和加上当前行元素的所有可能总和。 为了防止堆变得太大，我们只保留`k`每个阶段的最小总和使用`heapq.nsmallest`。 合并所有行后，`kth`堆中的元素对应于`kth`最小的总和。 

## 解决方案```go
import (
    "container/heap"
    "sort"
)

func kthSmallest(mat [][]int, k int) int {
    heapSums := append([]int(nil), mat[0]...)
    
    for i := 1; i < len(mat); i++ {
        row := mat[i]
        newHeap := []int{}
        for _, prevSum := range heapSums {
            for _, num := range row {
                newHeap = append(newHeap, prevSum+num)
            }
        }
        sort.Ints(newHeap)
        if len(newHeap) > k {
            newHeap = newHeap[:k]
        }
        heapSums = newHeap
    }
    
    return heapSums[k-1]
}
```**Go 特定注释：** 由于 Go 没有方便的`nsmallest`像Python一样的函数，我们将所有新的总和附加到一个切片中，对其进行排序，然后将其截断到第一个`k`元素。 这保持了与 Python 解决方案相同的正确性不变性。 我们还复制第一行以避免修改输入矩阵。 

## 工作示例

 **示例1：**`mat = [[1,3,11],[2,4,6]], k = 5`一步一步：

 1.从堆开始`[1,3,11]`。 
2.合并行`[2,4,6]`:

 -`[1+2, 1+4, 1+6, 3+2, 3+4, 3+6, 11+2, 11+4, 11+6] = [3,5,7,5,7,9,13,15,17]`- 保留 5 个最小的：`[3,5,5,7,7]`3. 第 5 个最小的和是`7`。 

**示例2：**`mat = [[1,3,11],[2,4,6]], k = 9`- 合并后的所有总和：`[3,5,5,7,7,9,9,11,13,15,17]`- 第 9 个最小的和是`17`。 

**示例3：**`mat = [[1,10,10],[1,4,5],[2,3,6]], k = 7`- 逐行合并，保持 k 最小：

 1. 开始`[1,10,10]`2. 合并`[1,4,5]`→`[2,5,6,11,14,15]`→ 保留 7 个最小的`[2,5,6,11,14,15]`3. 合并`[2,3,6]`→`[4,5,6,7,8,8,9,10,11,13,14,17,16,19,21,13,16,17]`→ 保留 7 个最小的`[4,5,5,6,6,7,8]`- 第七小的总和：`9`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m * k * n log k) | O(m * k * n log k) | 对于每一行，我们将 k 个先前的和与 n 个元素组合起来，使用以下方法仅保留 k 个最小的`heapq.nsmallest`或排序+切片 |
 | 空间| O(k) | 任何时候只存储 k 个最小和 |

 主要的节省来自于将注意力限制在 k 个最小总和上，而不是所有可能的总和上，从而将指数增长减少到可管理的线性增长`k`。
