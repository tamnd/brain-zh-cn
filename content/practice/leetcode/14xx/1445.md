[LeetCode Problem 1445](https://leetcode.com/problems/apples-oranges/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题提供了一个数据库表，名为`Sales`存储每天销售的水果数量。 每行代表特定日期的单个水果销售摘要。 该表包含三列：

 | 专栏 | 意义|
 | ---| ---|
 |`sale_date`| 销售日期 |
 |`fruit`| 任何一个`"apples"`或者`"oranges"`|
 |`sold_num`| 售出单位数量 |

 主键是`(sale_date, fruit)`，这保证对于给定的日期和水果类型，只有一行。 这意味着我们永远不会看到重复的条目，例如两个单独的条目`"apples"`同一日期的行。 

目标是计算每日差异：```
apples sold - oranges sold
```对于表中的每个日期。 

输出应包含：

 | 专栏 | 意义|
 | ---| ---|
 |`sale_date`| 日期 |
 |`diff`| 苹果销量减去橙子销量|

 结果必须按以下顺序排序`sale_date`。 

例如，如果某一天卖出了 10 个苹果和 8 个橙子，则差异为：```
10 - 8 = 2
```如果橙子超过苹果，结果就会变成负数。 

重要的观察结果是，由于问题设置，每天恰好包含一排苹果和一排橙子。 这种保证大大简化了解决方案，因为我们不需要处理缺失的水果类别。 

一个幼稚的实现可能会尝试将每一行与其他每一行进行比较以找到匹配的日期，但这会不必要地昂贵。 由于表结构干净且可预测，因此我们可以更有效地按日期聚合。 

重要的边缘情况包括以下日子：

 - 苹果和橙子的销量相同，产量相同`0`- 橙子超过苹果，产生负面结果
 - 一种水果的价值为`0`- 该表仅包含一个日期

 该问题保证有效的输入格式和只有两个水果类别，因此我们不需要额外的验证逻辑。 

## 方法

 ### 蛮力方法

 强力解决方案会将每一行与其他每一行进行比较，以找到匹配的日期。 对于每个苹果行，我们将再次扫描表格以找到具有相同值的橙子行。`sale_date`，然后计算差值。 

这种方法之所以有效，是因为每个苹果条目最终都会找到其对应的橙子条目。 但是，它的效率很低，因为它会重复扫描相同的行。 

如果有`n`行，嵌套比较导致`O(n²)`时间复杂度。 

### 最佳方法

 关键的见解是我们可以将减法转化为分组聚合问题。 

我们可以使用条件聚合，而不是手动配对行：

 - 添加`sold_num`当水果是`"apples"`- 减法`sold_num`当水果是`"oranges"`然后将结果分组`sale_date`。 

这是可行的，因为每个日期都包含一行苹果和一行橙子。 通过将苹果转换为正值，将橙子转换为负值，数据库可以在聚合过程中直接计算差异。 

这种方法只扫描一次表并有效地使用 SQL 聚合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 将每一行与其他每一行进行比较以查找匹配的日期 |
 | 最佳| O(n) | O(1) 或 O(k) | 使用按日期分组的条件聚合 |

 ## 算法演练

 ### 最优SQL聚合算法

 1. 读取每一行`Sales`桌子。 

每行包含一种水果类型和在特定日期销售的数量。 
2. 将苹果销量转化为正值。 

如果水果是`"apples"`， 保持`sold_num`为正，因为苹果对最终差异有积极贡献。 
3. 将橙子销量转换为负值。 

如果水果是`"oranges"`, 乘以`sold_num`经过`-1`so oranges reduce the final difference.
 4. 行分组依据`sale_date`。 

分组可确保同一天的所有水果销售都合并到一个结果行中。 
5. 对转换后的值求和。 

由于苹果为正，橙子为负，因此总和直接变为：```sql
apples - oranges
```6. 返回排序结果`sale_date`。 

该问题明确需要按时间顺序排列。 

### 为什么它有效

 该算法依赖于数学属性：```
(apples) + (-oranges) = apples - oranges
```Because every date contains exactly one apples row and one oranges row, grouping by date and summing transformed values always produces the correct difference.

 ## Python 解决方案

 尽管这是一个数据库问题，但 LeetCode 数据库问题是使用 SQL 解决的。 下面的“Python 解决方案”部分以 Python 格式的块呈现 SQL 查询，以与请求的结构保持一致。```python
SELECT
    sale_date,
    SUM(
        CASE
            WHEN fruit = 'apples' THEN sold_num
            ELSE -sold_num
        END
    ) AS diff
FROM Sales
GROUP BY sale_date
ORDER BY sale_date;
```The query processes each row exactly once. 这`CASE`表达式将苹果转化为正贡献，将橙子转化为负贡献。 

这`SUM()`聚合合并同一日期的所有转换值。 由于每个日期都有一个苹果行和一个橙子行，因此所得的总和就是所需的差值。 

这`GROUP BY sale_date`子句确保每个日期一个输出行，并且`ORDER BY sale_date`保证所需的排序输出。

 ## 边缘情况

 ### 苹果和橙子的销量相等

 当两种水果具有相同的销售价值时，就会出现一种常见的边缘情况。 在这种情况下，结果应该恰好为零。 

例如：```
apples = 15
oranges = 15
diff = 0
```一些不正确的实现可能会意外地遗漏一种水果或使用绝对差异。 聚合方法可以自然地处理这个问题，因为：```
15 + (-15) = 0
```### 橙子超过苹果

 另一个重要的边缘情况是橙子销量大于苹果销量。 结果必须变为负数。 

例如：```
apples = 10
oranges = 16
diff = -6
```有缺陷的实现可能会错误地强制结果保持正值。 条件聚合解决方案正确保留了负号，因为橙子直接贡献负值。 

### 一种水果零销量

 问题允许`sold_num = 0`。 因此，一个日期可能包含零个橙子或零个苹果。 

例如：```
apples = 20
oranges = 0
diff = 20
```The SQL aggregation handles this correctly because adding or subtracting zero does not affect the result.

 ### 单日输入

 该表可能只包含一个日期。 Some implementations incorrectly assume multiple groups exist.

 The aggregation query still works correctly because`GROUP BY sale_date`只是产生一组分组的行。
