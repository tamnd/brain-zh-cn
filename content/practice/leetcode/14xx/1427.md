[LeetCode 问题 1427](https://leetcode.com/problems/perform-string-shifts/)

 **难度：** 🟢简单
 **主题：** 数组、数学、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们模拟给定字符串上的一系列字符串移位操作`s`。 

每个操作在`shift`矩阵包含两个值：

 -`direction`-`0`意思是左移
 -`1`意味着右移
 -`amount`- 要移动的位置数量

 左移会删除前面的字符并将它们附加到后面。 例如：```
"abcde" -> left shift by 2 -> "cdeab"
```右移会从后面删除字符并将它们插入到前面：```
"abcde" -> right shift by 2 -> "deabc"
```目标是按顺序应用所有操作并返回最终转换后的字符串。 

输入约束很小：

 -`s.length <= 100`-`shift.length <= 100`这意味着即使是直接模拟方法也会在一定范围内发挥作用。 然而，这个问题有一个数学观察，可以提供更干净、更有效的解决方案。 

重要的见解是多次轮班可能会相互抵消。 例如：

 - 还剩 3
 - 右转 3

 结果根本没有改变。 

另一个重要的细节是，移动字符串的长度会再次产生原始字符串。 例如：```
"abcdef" shifted right by 6 -> "abcdef"
```所以只对移位量取模`len(s)`很重要。 

一些边缘情况很重要：

 - 移位量可能是`0`，表示没有变化。 
- 如果左移占主导地位，则总有效移位可能会变为负值。 
- 总移位可能会超出字符串长度很多倍。 
- 字符串可能有长度`1`，每次移位都会使字符串保持不变。 

该问题保证了输入格式有效，因此我们不需要处理格式错误的操作。 

## 方法

 ### 蛮力方法

 暴力解决方案直接模拟每一个操作，完全按照描述。 

对于每个操作：

 - 如果是左移，则重复从前到后移动字符。 
- 如果是右移，则重复从后到前移动字符。 

这会产生正确的结果，因为它严格遵循问题陈述。 

然而，重复的角色移动效率很低。 如果字符串有长度`n`并且有`m`操作，每个操作的成本可能高达`O(n)`时间。 在最坏的情况下，总复杂度变为`O(m * n)`。 

尽管约束足够小，可以通过，但它会执行不必​​要的重复工作。 

### 最佳方法

 关键的观察结果是所有班次都可以合并为一个净班次。 

右移会增加有效移动量，而左移会减少有效移动量。 

例如：```
left 2
right 5
left 1
```变成：```
-2 + 5 - 1 = +2
```这意味着最终结果只是右移`2`。 

计算总位移后：

 - 以字符串长度为模减少它。 
- 执行最后一次旋转。 

这避免了重复的中间转换并使实现更加清晰。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m × n) | O(n) | 直接模拟每个班次操作 |
 | 最佳| O(m + n) | O(n) | 将所有轮班合并为一次净轮换 |

 在哪里：

-`m`是移位操作的数量
 -`n`是字符串的长度

 ## 算法演练

 1. 初始化一个名为`net_shift`到`0`。 

该变量存储所有操作的综合效果。 
2. 迭代每一个操作`shift`。 

每个操作包含：

 -`direction`-`amount`3. 根据方向更新净位移。 

- 如果`direction == 1`， 添加`amount`因为右移会将字符移向前面。 
- 如果`direction == 0`, 减去`amount`因为左移会将字符移到后面。 
4. 使用模数减少总移位。 

由于将字符串旋转其自身长度会返回原始字符串，因此计算：```
net_shift %= len(s)
```这使偏移保持在有效范围内。 

1. 构建最终的旋转字符串。 

右移由`k`意思是：

 - 拿最后一个`k`人物
 - 将它们放在前面
 - 附加剩余的前缀

 这变成：```
s[-k:] + s[:-k]
```1. 返回结果字符串。 

### 为什么它有效

 每一次左移和右移都是一次循环旋转。 循环旋转是可加的，这意味着多个旋转可以组合成单个等效旋转。 

因为：

 - 右移有积极贡献
 - 左移有负面影响

 所有操作的总和代表最终的净旋转。 

模算术保证大于字符串长度的旋转被减少到其等效的最小旋转。 因此，执行最后一次旋转会产生与单独执行每个操作完全相同的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def stringShift(self, s: str, shift: List[List[int]]) -> str:
        net_shift = 0
        n = len(s)

        for direction, amount in shift:
            if direction == 1:
                net_shift += amount
            else:
                net_shift -= amount

        net_shift %= n

        return s[-net_shift:] + s[:-net_shift]
```实现从初始化开始`net_shift`，累加所有操作的总效果。 

循环处理每个移位指令。 右移会增加该值，而左移会减少该值。 这将许多运算转换为一个数学结果。 

处理完所有运算后，模运算可确保移位量保持在字符串长度内。 

最后，字符串切片表达式有效地执行旋转：

 -`s[-net_shift:]`提取移到前面的后缀
 -`s[:-net_shift]`提取剩余的前缀

 连接它们会产生正确旋转的字符串。 

一个微妙的细节是 Python 切片句柄`0`干净地：```python
s[-0:] == s
s[:-0] == ""
```因此，即使有效移位为零，该实施也能发挥作用。 

## 解决方案```go
func stringShift(s string, shift [][]int) string {
    netShift := 0
    n := len(s)

    for _, operation := range shift {
        direction := operation[0]
        amount := operation[1]

        if direction == 1 {
            netShift += amount
        } else {
            netShift -= amount
        }
    }

    netShift %= n

    if netShift < 0 {
        netShift += n
    }

    return s[n-netShift:] + s[:n-netShift]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个重要的区别是模行为。 在 Python 中，负模结果会自动转换为正值。 在 Go 中，负值仍然为负，因此我们明确调整：```go
if netShift < 0 {
    netShift += n
}
```Go 字符串是不可变的，就像 Python 字符串一样，因此构造最终答案需要将切片连接成新字符串。

 ## 边缘情况

 当总移位大于字符串长度时，会出现一种重要的边缘情况。 例如，移动长度的字符串`5`经过`12`位置相当于移动`2`。 重复旋转字符的幼稚实现可能会浪费时间做不必要的工作。 该实现通过减少模运算的最终移位来正确处理该问题。 

另一个重要的情况是左移和右移相互抵消。 例如：```
left 3
right 3
```应保持字符串不变。 当实现过程独立变化而不是通过数学方式组合时，经常会出现错误。 通过累积单个`net_shift`，算法自然会正确处理取消。 

第三种边缘情况涉及长度的字符串`1`。 对单字符字符串的任何移位操作都必须返回原始字符串。 某些实现可能会意外地产生无效的切片边界或冗余工作。 因为模结果变为`0`，切片表达式安全地返回原始字符串不变。 

最后一个微妙的情况是有效转变变为负值。 例如：```
left 4
right 1
```产生净转移`-3`。 模运算将其转换为等效的正旋转。 这保证了最终切片索引保持有效且一致。
