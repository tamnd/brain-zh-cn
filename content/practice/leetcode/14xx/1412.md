[LeetCode 第 1412 题](https://leetcode.com/problems/find-the-quiet-students-in-all-exams/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们找出在参加的所有考试中“安静”的学生。如果一个学生在每次参加的考试中都没有取得最高分或最低分，则被认为是安静的。 

我们有两张表：

 - 的`Student`表包含学生 ID 和姓名。 
- 这`Exam`表记录考试参与情况和分数。 

中的每一行`Exam`表代表一名学生在一项特定考试中的分数。 多个学生可以参加同一考试。 

重要的细节是，我们并不是在寻找至少在一场考试中保持安静的学生。 相反，我们希望学生在每次考试中都能保持安静。 

对于每次考试：

 - 任何获得最高分的学生将被取消资格。 
- 任何获得最低分数的学生将被取消资格。 
- 如果学生曾经出现在任一类别中，则他们不能成为最终结果的一部分。 

最终答案应包括：

 - 至少参加过一次考试的学生
 - 从来都不是最高分的学生
 - 从来不是得分最低的学生

 输出必须按以下顺序排序`student_id`。 

仔细考虑样本：

 - 学生 1 多次获得最低分数。 
- 学生 3 和学生 4 获得最高分。 
- 学生 2 参与并且从未成为最高或最低。 
- 学生 5 从未参加过考试。 

因此：

 - 包括学生 2。 
- 学生 5 被排除，因为问题明确指出没有考试的学生不应出现。 

一些边缘情况在这里很重要。 

如果考试只有一名参与者，则该学生同时是最高和最低的，这意味着他们将立即被取消资格。 

如果多名学生获得最高或最低分数，则每个并列的学生都被视为不安静，必须被排除在外。 

一个学生可以参加多次考试，只需要失败一次就作废。 

问题的根本在于根据总体考试行为过滤学生。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是独立处理每个学生。 

对于每个学生：

 1. 查找他们参加的所有考试。 
2. 对于每项考试：

 - 计算最低分数
 - 计算最高分
 - 将学生的分数与这些值进行比较
 3. 如果学生的分数等于任一极端，则将其标记为不安静。 

这是有效的，因为它直接遵循问题定义。 然而，它的效率很低，因为同一考试的最低和最高分数会针对不同的学生重复计算。 

假设一次考试有 1000 名学生。 如果我们独立地重新计算每个参与者的最小值/最大值，我们就会多次重复扫描相同的数据。 

这会产生不必要的重复工作并导致可扩展性较差。 

### 最佳方法

 关键的观察是考试级别信息应该计算一次。 

对于每次考试：

 - 确定最低分数
 - 确定最高分
 - 将所有符合任一边界分数的学生标记为不合格

 处理完所有检查后：

 - 收集至少参加过一项考试的学生
 - 排除所有不合格的学生
 - 返回剩余的学生

 这种方法很有效，因为：

 - 每项考试分析一次
 - 每行被处理固定次数
 - 我们使用基于集合的过滤而不是重复重新扫描

 在 SQL 中，这自然映射为：

 - 窗口函数或聚合
 - 一组不合格的学生
 - 最终过滤使用`NOT IN`或加入

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(S × E) | O(1) | O(1) | 为每个学生重复重新计算最小值/最大值 |
 | 最佳 | O(E) | O(E) | 一次计算考试边界并有效过滤 |

 这里：

-`S`是学生人数
 -`E`是考试行数

 ## 算法演练

 ### 使用 SQL 聚合和过滤

 1. 首先，计算每次考试的最低和最高分数。 

我们对行进行分组`exam_id`并计算：

 -`MIN(score)`-`MAX(score)`这为我们提供了每次考试的分数范围。 
2. 接下来，找出不安静的学生。 

我们加入原版`Exam`包含考试统计数据的表格并检查：

 -`score = min_score`-`score = max_score`任何匹配的学生将被取消资格。 
3. 保存所有不合格的学生证。 

一个学生只需要一次考试不好就会失效，所以我们用`DISTINCT`以避免重复。 
4. 确定实际参加考试的学生。 

这个问题明确排除了从未参加过考试的学生。 
5. 加入`Student`桌子。 

这使我们能够检索学生姓名。 
6. 排除所有不合格的学生。 

我们只保留其 ID 不存在于不合格组中的学生。 
7. 对最终输出进行排序`student_id`。 

### 为什么它有效

 该算法之所以有效，是因为每次考试都独立定义了一组无效学生：

 - 最低分数的学生
 - 得分最高的学生

 一个安静的学生必须在每次考试中避免这两个类别。 

通过收集所有无效学生的并集并将其从参与学生中排除，我们准确地捕获了所需的定义。 

## Python 解决方案

 虽然这是一个数据库问题，但以下 Python 实现在算法上演示了相同的逻辑。```python
from collections import defaultdict
from typing import List

class Solution:
    def quietStudents(
        self,
        students: List[List],
        exams: List[List[int]]
    ) -> List[List]:
        
        exam_scores = defaultdict(list)

        for exam_id, student_id, score in exams:
            exam_scores[exam_id].append((student_id, score))

        disqualified = set()
        participated = set()

        for exam_id, entries in exam_scores.items():
            scores = [score for _, score in entries]

            min_score = min(scores)
            max_score = max(scores)

            for student_id, score in entries:
                participated.add(student_id)

                if score == min_score or score == max_score:
                    disqualified.add(student_id)

        result = []

        for student_id, student_name in students:
            if (
                student_id in participated
                and student_id not in disqualified
            ):
                result.append([student_id, student_name])

        result.sort(key=lambda x: x[0])

        return result
```实施首先按以下条件对考试记录进行分组：`exam_id`。 这使我们能够独立处理每项考试。 

对于每次考试，我们都会计算：

 - 最低分数
 - 最高分

 然后，我们遍历该考试的所有参与者。 任何分数符合任一边界的学生都会被取消资格。 

同时，我们跟踪哪些学生至少参加了一项考试。 

最后，我们遍历学生列表并仅保留符合以下条件的学生：

 - 参加考试
 - 从未出现在被取消资格的组中

 返回之前对结果进行排序。 

## 解决方案```go
package main

import (
	"sort"
)

type Student struct {
	ID   int
	Name string
}

func quietStudents(
	students []Student,
	exams [][]int,
) [][]interface{} {

	examScores := make(map[int][][]int)

	for _, exam := range exams {
		examID := exam[0]
		studentID := exam[1]
		score := exam[2]

		examScores[examID] = append(
			examScores[examID],
			[]int{studentID, score},
		)
	}

	disqualified := make(map[int]bool)
	participated := make(map[int]bool)

	for _, entries := range examScores {

		minScore := entries[0][1]
		maxScore := entries[0][1]

		for _, entry := range entries {
			score := entry[1]

			if score < minScore {
				minScore = score
			}

			if score > maxScore {
				maxScore = score
			}
		}

		for _, entry := range entries {
			studentID := entry[0]
			score := entry[1]

			participated[studentID] = true

			if score == minScore || score == maxScore {
				disqualified[studentID] = true
			}
		}
	}

	result := [][]interface{}{}

	for _, student := range students {
		if participated[student.ID] &&
			!disqualified[student.ID] {

			result = append(result, []interface{}{
				student.ID,
				student.Name,
			})
		}
	}

	sort.Slice(result, func(i, j int) bool {
		return result[i][0].(int) < result[j][0].(int)
	})

	return result
}
```Go 实现遵循与 Python 版本相同的整体结构。 

由于 Go 没有 Python 的灵活元组支持，因此我们使用嵌套整数切片表示考试条目。 

我们使用映射作为哈希集：

 -`map[int]bool`对于不合格的学生
 -`map[int]bool`用于参与跟踪

 排序需要`sort.Slice`带有自定义比较器。 

与 Python 不同，Go 需要显式初始化和类型处理，尤其是在将混合输出值存储在`[][]interface{}`。 

## SQL 解决方案```sql
WITH exam_stats AS (
    SELECT
        exam_id,
        MIN(score) AS min_score,
        MAX(score) AS max_score
    FROM Exam
    GROUP BY exam_id
),
disqualified AS (
    SELECT DISTINCT e.student_id
    FROM Exam e
    JOIN exam_stats s
        ON e.exam_id = s.exam_id
    WHERE e.score = s.min_score
       OR e.score = s.max_score
)

SELECT
    s.student_id,
    s.student_name
FROM Student s
JOIN Exam e
    ON s.student_id = e.student_id
WHERE s.student_id NOT IN (
    SELECT student_id
    FROM disqualified
)
GROUP BY s.student_id, s.student_name
ORDER BY s.student_id;
```该 SQL 解决方案首先使用聚合计算考试边界。 

这`disqualified`CTE 收集在任何考试中获得最低或最高分数的每位学生。 

最终查询：

 - 让学生参加考试以确保参与
 - 排除不合格的学生
 - 对连接引起的重复进行分组
 - 按学生 ID 排序结果

 ## 边缘情况

 ### 只有一名参与者的考试

 包含单个学生的考试很棘手，因为该学生同时是最低得分者和最高得分者。 

幼稚的实现可能会错误地假设学生不能两者兼而有之。 

我们的实现正确处理了这个问题，因为条件检查：```
score == min_score or score == max_score
```当两个值相同时，学生仍然被取消资格。 

### 多名学生并列最高或最低

 一些实现错误地假设只有一名学生可以保持最低或最高分数。 

然而，平局是可能的，并且每个平局的学生都必须被排除在外。 

我们的算法会扫描每个参与者，并将分数直接与计算出的边界进行比较，确保所有并列的学生都被取消资格。 

### 从不参加考试的学生

 很容易意外地包括从未参加过的学生，因为他们也从未达到最高或最低。 

这个问题明确排除了他们。 

我们的实现使用`participated`组，并且仅包括该组中存在的学生，保证正确的行为。
