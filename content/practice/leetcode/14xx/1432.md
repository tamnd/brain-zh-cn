[LeetCode 问题 1432](https://leetcode.com/problems/max-difference-you-can-get-from-changing-an-integer/)

 **难度：** 🟡 中等
 **主题：** 数学、贪心

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数`num`，并且我们可以独立执行两次数字替换操作。 

在一项操作中，我们：

 1. 选择一个数字`x`2. 选择另一个数字`y`3. 替换每个出现的数字`x`的十进制表示形式`num`和`y`这两个操作是完全独立的。 这意味着第二次操作从原来的开始`num`，不是来自第一个操作的结果。 

执行这两个操作后，我们得到两个数字：

 -`a`，第一次替换的结果
 -`b`，第二次替换的结果

 我们的目标是最大化：```
a - b
```有两个重要的限制：

 - 两个结果都不能包含前导零
 - 这两种结果都不会成为`0`输入大小非常小，因为：```
1 <= num <= 10^8
```这意味着该数字最多有 9 位数字，因此即使效率相对较低的解决方案仍然可以快速运行。 然而，挑战在于确定保证最大差异的贪婪结构。 

关键的观察是最大化`a - b`意思是：

 - 制作`a`尽可能大
 - 制作`b`尽可能小

 由于每个操作都是独立的，因此我们可以单独优化它们。 

一些边缘情况很重要：

 - 一位数字，例如`9`- 第一位数字已经是的数字`1`- 包含零的数字
 - 替换数字可能会产生前导零的情况
 - 所有数字都相同的情况

 例如，当最小化一个数字时，我们不能用`0`，因为禁止使用前导零。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的替换对`(x, y)`用于生成`a`，以及每个可能的替换对`(x, y)`用于生成`b`。 

有 10 个可能的数字`x`和 10 为`y`，因此每个变换都有：```
10 * 10 = 100
```可能的操作。 

由于我们需要两个独立的操作，我们可以：

 - 生成所有可能的转换值
 - 计算每一个可能的差异
 - 返回最大值

 这是有效的，因为搜索空间非常小。 

对于每个转换：

 - 将数字转换为字符串
 - 替换所有出现的`x`- 验证结果没有前导零并且不为零

 尽管可行，但这种方法执行了不必要的工作，因为最优变换遵循非常清晰的贪婪模式。 

### 最优贪心法

 最佳的见解是，最大化差异可以分为两个独立的贪婪目标：

 - 构造尽可能大的数字
 - 构造尽可能小的数字

 要最大化数量：

 - 找到第一个不是的数字`9`- 将所有出现的该数字替换为`9`为什么这有效？ 

最左边的数字对最终值的贡献最大。 改变第一个非`9`数字到`9`产生最大的增幅。 

要最小化数量：

 有两种情况。 

如果第一个数字不是`1`:

 - 将所有出现的第一个数字替换为`1`这会在不创建前导零的情况下尽可能地减少最高有效数字。 

如果第一个数字已经是`1`:

 - 找到前导数字之后的第一个数字，但两者都不是`0`也不`1`- 将所有出现的该数字替换为`0`这可以在保持有效性的同时最大限度地减少数量。 

这种贪婪策略会在线性时间内产生最优答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(100 × n) | O(100 × n) | O(n) | 尝试所有可能的数字替换 |
 | 最佳 | O(n) | O(n) | 贪婪地构造最大值和最小值 |

 这里，`n`是数字的个数`num`。 

## 算法演练

 ### 第 1 步：将数字转换为字符串

 使用字符串操作来处理数字要容易得多。 

例如：```
num = 9288
s = "9288"
```### 第 2 步：构造最大可能数

 我们想要尽可能最大的结果。 

从左到右扫描字符串，找到第一个不是的数字`9`。 

为什么是第一个？ 

因为更改更有效的数字对数字的影响更大。 

假设我们找到数字`2`。 

替换所有出现的`2`和`9`。 

例子：```
9288 -> 9988
```如果所有数字都已经`9`，无需更改。 

### 第 3 步：构造最小可能数

 现在我们独立地最小化原始数字。 

#### 情况 A：第一个数字不是`1`前导数字对数字的贡献最大，因此减少它会带来最大的减少。 

将每次出现的第一个数字替换为`1`。 

例子：```
555 -> 111
```我们不能使用`0`因为前导零是被禁止的。 

#### 情况 B：第一个数字已经是`1`我们无法进一步减少前导数字。 

现在扫描剩余的数字并找到第一个都不是的数字`0`也不`1`。 

将所有出现的该数字替换为`0`。 

例子：```
109090 -> 100000
```这可以在不引入前导零的情况下最大限度地减少数字。 

### 步骤 4：计算差异

 将两个转换后的字符串转换回整数并返回：```
max_value - min_value
```### 为什么它有效

 该算法依赖于位置数字重要性。 

左边的数字比右边的数字对总值的贡献更大。 因此：

 - 为了最大化数字，我们最大化最早可能的数字
 - 为了最小化数字，我们在不违反约束的情况下最小化最早可能的数字

 由于每次替换都会影响数字的所有出现，因此选择最早的有益数字可以保证最大可能的影响。 

## Python 解决方案```python
class Solution:
    def maxDiff(self, num: int) -> int:
        s = str(num)

        # Build maximum value
        max_s = s
        for ch in s:
            if ch != '9':
                max_s = s.replace(ch, '9')
                break

        # Build minimum value
        min_s = s

        if s[0] != '1':
            min_s = s.replace(s[0], '1')
        else:
            for ch in s[1:]:
                if ch != '0' and ch != '1':
                    min_s = s.replace(ch, '0')
                    break

        return int(max_s) - int(min_s)
```实现首先将整数转换为字符串，以便数字替换变得简单。 

为了构建最大值，代码从左到右扫描，寻找第一个不是的数字`9`。 一旦找到，该数字的每次出现都会被替换为`9`。 

为了构造最小值，代码首先检查前导数字。 如果不是`1`，该数字的所有出现都被替换为`1`。 否则，代码将在其余数字中搜索第一个既不是数字也不是数字的数字。`0`也不`1`，并将所有出现的该数字替换为`0`。 

最后，两个转换后的字符串都被转换回整数并返回它们的差值。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

func maxDiff(num int) int {
	s := strconv.Itoa(num)

	// Build maximum value
	maxS := s
	for _, ch := range s {
		if ch != '9' {
			maxS = strings.ReplaceAll(s, string(ch), "9")
			break
		}
	}

	// Build minimum value
	minS := s

	if s[0] != '1' {
		minS = strings.ReplaceAll(s, string(s[0]), "1")
	} else {
		for i := 1; i < len(s); i++ {
			if s[i] != '0' && s[i] != '1' {
				minS = strings.ReplaceAll(s, string(s[i]), "0")
				break
			}
		}
	}

	maxVal, _ := strconv.Atoi(maxS)
	minVal, _ := strconv.Atoi(minS)

	return maxVal - minVal
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于使用：

 -`strconv.Itoa`和`strconv.Atoi`用于转换
 -`strings.ReplaceAll`用于数字替换

 Go 字符串是字节索引的，因此访问`s[i]`直接安全地工作，因为所有字符都是数字。 

整数溢出不是问题，因为约束很小。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|

 ## 边缘情况

 ### 单位数字

 单个数字输入，例如`9`或者`8`可能很棘手，因为替换数字可能会产生无效结果，例如`0`。 

该实现通过将数字替换为来正确处理这个问题`1`当最小化时。 这保证了结果保持非零并且不包含前导零。 

### 开头的数字`1`输入如`10023`很重要，因为我们无法在不违反无前导零规则的情况下进一步减少前导数字。 

该算法通过在剩余数字中搜索第一个既不是数字也不是的数字来正确处理这个问题`0`也不`1`，然后将其替换为`0`。 

### 数字已经最大化

 对于像这样的输入`99999`，没有数字可以进一步增加这个数字。 

该实现自然地检测到这一点，因为扫描非`9`数字失败，保持号码不变。 

### 包含许多零的数字

 输入如`909090`如果替换意外创建前导零，可能会导致错误。 

该算法永远不会将前导数字替换为`0`，确保所有转换后的数字仍然有效。
