 # LeetCode 1480 - 一维数组的运行总和

 ## 问题理解

 该问题要求我们计算一维整数数组的运行和，也称为前缀和。 

对于每个索引`i`, 位置处的结果`i`应等于索引中所有元素的总和`0`通过索引`i`在原始数组中。 换句话说，每个位置都会累积之前的所有内容，包括当前元素。 

如果输入是：```
[1,2,3,4]
```那么：

 - 第一个值是`1`- 第二个值是`1 + 2 = 3`- 第三个值是`1 + 2 + 3 = 6`- 第四个值是`1 + 2 + 3 + 4 = 10`所以输出变成：```
[1,3,6,10]
```输入由一个整数数组组成`nums`，输出应该是另一个相同长度的数组，其中每个索引存储到该位置的累积总数。 

限制相对较小：

 - 数组长度最多为`1000`- 每个值的范围可以是`-10^6`到`10^6`这些限制告诉我们，性能要求并不高，但我们仍然应该以高效的线性解决方案为目标。 由于数组可以包含负数，因此运行总和不一定递增。 该算法必须正确处理正值、负值和零值。 

一种重要的边缘情况是只有一个元素的数组。 在这种情况下，运行总和就是原始值本身。 另一个重要的情况是包含负数的数组，因为累积总数可能会减少。 包含零的数组也很重要，因为不同位置的运行总计可能保持不变。 

## 方法

 ### 蛮力方法

 暴力解决方案独立计算每个运行总和。 

对于每个索引`i`，我们从索引迭代`0`通过`i`并手动计算总和。 然后计算出的总和存储在结果数组中。 

例如，计算索引处的值`3`，我们总结一下：```
nums[0] + nums[1] + nums[2] + nums[3]
```这种方法是正确的，因为它直接遵循运行总和的定义。 但是，它会重复重新计算之前已经计算过的总和。 

如果数组有`n`要素：

 - 计算第一个前缀和需要`1`操作
 - 第二个需要`2`- 第三个需要`3`等等。 

总工作量变为：```
1 + 2 + 3 + ... + n = O(n^2)
```虽然这对于小型阵列来说是可以接受的，但与可能的情况相比，效率较低。 

### 最优前缀和方法

 关键的观察结果是，每个运行总和都直接建立在前一个运行总和的基础上。 

假设我们已经知道：```
runningSum[i - 1]
```那么下一个值就是：```
runningSum[i] = runningSum[i - 1] + nums[i]
```这意味着我们永远不需要从头开始重新计算之前的总和。 我们可以在从左到右遍历数组一次的同时维护累积总数。 

这将时间复杂度从二次降低到线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复重新计算前缀和 |
 | 最佳 | O(n) | O(n) | 保持累计运行总计 |

 ## 算法演练

 1. 创建一个空结果数组来存储运行总和。 
2. 初始化一个名为`current_sum`到`0`。 该变量跟踪迄今为止看到的累积总数。 
3. 从左到右遍历输入数组。 
4. 对于每个元素：

 - 将当前号码添加到`current_sum`- 附加更新的内容`current_sum`到结果数组
 5. 处理完所有元素后，返回结果数组。 

该算法只需要遍历一次数组，因为每个运行总和仅取决于先前的累积总数。 

### 为什么它有效

 该算法保持不变式`current_sum`始终等于迄今为止处理的所有元素的总和。 

处理后指标`i`，我们知道：```
current_sum = nums[0] + nums[1] + ... + nums[i]
```因为这与索引处的运行总和的定义完全匹配`i`, 附加`current_sum`to the result array guarantees correctness.

 ## Python 解决方案```python
from typing import List

class Solution:
    def runningSum(self, nums: List[int]) -> List[int]:
        result = []
        current_sum = 0

        for number in nums:
            current_sum += number
            result.append(current_sum)

        return result
```实现首先创建一个名为的空列表`result`，它存储最终的运行总和。 

变量`current_sum`迭代数组时跟踪累积总数。 

在每次迭代期间：

 - 当前号码被添加到`current_sum`- 更新后的累计总数将附加到结果列表中

 由于运行总计是增量更新的，因此每个前缀总和都是在恒定时间内计算的。 该算法对每个元素只处理一次。 

## 解决方案```go
func runningSum(nums []int) []int {
    result := make([]int, len(nums))
    currentSum := 0

    for i, num := range nums {
        currentSum += num
        result[i] = currentSum
    }

    return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个小区别是 Go 需要使用显式分配结果切片`make`。 由于最终大小已知，我们分配长度为切片`len(nums)`立即地。 

变量`currentSum`存储累计总计，每个更新值直接写入结果切片对应的索引中。 

Go 整数足以满足给定的约束，因为最大可能的累积和保持在标准整数类型的范围内。

 ## 边缘情况

 一种重要的边缘情况是单元素数组。 由于没有之前的元素可供累加，因此运行总和应该等于原始值。 该实现自然地处理了这个问题，因为循环执行一次，将元素添加到`current_sum`，并将其附加到结果中。 

另一个重要的情况涉及负数。 一个常见的错误是假设运行总和总是增加。 如果值为负，则累计总数可能会减少。 由于该算法直接将每个数字添加到当前总数中，而不对符号进行假设，因此它可以正确处理正和负转换。 

包含零的数组也很重要。 添加零应该保留之前的累计总数。 该实现正确处理了这个问题，因为添加零叶子`current_sum`未更改，并且该未更改的值将附加到结果中。 

最后的边缘情况涉及约束边界附近的非常大的值。 即使数字接近`10^6`，该算法仍然可以正常工作，因为它只执行整数加法，并且累积总数仍然安全地保持在 Python 和 Go 的标准整数限制内。
