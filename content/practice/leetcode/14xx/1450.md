[LeetCode 第 1450 题](https://leetcode.com/problems/number-of-students-doing-homework-at-a-given-time/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们确定在特定时间点有多少学生正在做作业，给定代表每个学生开始和完成作业的时间的数组。 更具体地说，我们有两个数组`startTime`和`endTime`相同长度的。 各指标`i`代表一名学生：`startTime[i]`是他们开始的时候，并且`endTime[i]`当他们完成的时候。 我们还给出了一个整数`queryTime`并需要计算在该确切时间有多少学生处于活动状态。 时间间隔是包容性的，这意味着学生被认为在两个时间段都活跃`startTime[i]`和`endTime[i]`。 

约束很简单：数组的长度在 1 到 100 之间，并且值都是不超过 1000 的正整数。这些约束表明简单的线性解决方案是可以接受的，因为即使对所有学生进行强力检查也是有效的。 需要注意的边缘情况包括同时开始和结束的学生、queryTime 位于所有开始时间之前、所有结束时间之后，或者与间隔的开始或结束完全匹配。 

## 方法

 最直接的方法是蛮力：迭代每个学生并检查是否`queryTime`落在他们的区间内`[startTime[i], endTime[i]]`。 如果是，则增加一个计数器。 该方法简单并且在问题限制内有效。 

最佳方法的关键观察是不需要复杂的数据结构或排序。 由于数组很小，因此迭代每个元素并检查条件是有效的。 任何使用更高级技术（例如前缀和或区间树）的尝试对于这个问题来说都是矫枉过正的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 遍历每个学生并计算是否`queryTime`是在`[startTime[i], endTime[i]]`|
 | 最佳| O(n) | O(1) | O(1) | 与暴力破解相同； 小输入量使得线性迭代足够 |

 ## 算法演练

 1.初始化一个计数器变量`count`为零。 这将存储活跃学生的数量`queryTime`。 
2. 使用索引迭代所有学生。 
3. 对于每个学生`i`，检查是否`queryTime`大于或等于`startTime[i]`且小于或等于`endTime[i]`。 
4. 如果条件为真，则递增`count`一个。 
5.处理完所有学生后，返回值`count`。 

为什么有效：每个学生的时间间隔都经过明确检查`queryTime`。 由于时间间隔是包含在内的，因此开始和结束时间包括在内的任何学生`queryTime`只计算一次。 没有学生被重复计算，所有相关学生都被包括在内，保证了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def busyStudent(self, startTime: List[int], endTime: List[int], queryTime: int) -> int:
        count = 0
        for i in range(len(startTime)):
            if startTime[i] <= queryTime <= endTime[i]:
                count += 1
        return count
```这个 Python 实现完全遵循该算法。 我们初始化一个计数器，迭代其索引`startTime`和`endTime`，检查包含条件`queryTime`，并在满足条件时递增计数器。 最后，我们返回总数。 

## 解决方案```go
func busyStudent(startTime []int, endTime []int, queryTime int) int {
    count := 0
    for i := 0; i < len(startTime); i++ {
        if startTime[i] <= queryTime && queryTime <= endTime[i] {
            count++
        }
    }
    return count
}
```Go 版本反映了 Python 解决方案。 初始化一个计数器，简单`for`循环迭代切片索引，并且包含比较检查每个学生的间隔。 Go 安全地处理切片，因此在考虑到问题限制的情况下不需要 nil 检查。

 ## 边缘情况

 一个重要的边缘情况是当`queryTime`是在所有开始时间之前。 如果所有学生在查询后开始，并且算法必须正确返回零，则可能会发生这种情况。 另一个边缘情况是当`queryTime`等于间隔的开始或结束。 由于间隔包含在内，因此应计算这些学生。 最后，所有学生同时活跃的边缘情况测试了该算法可以处理最大数组长度并正确地同时计算多个学生而没有错误。 该实现通过使用直接比较来处理所有这些情况`<=`和`>=`。
