[LeetCode 1436 题](https://leetcode.com/problems/destination-city/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到了城市之间有向路径的列表。 每个条目在`paths`有形式`[cityA, cityB]`，这意味着有一条单向路径`cityA`到`cityB`。 

这些路径形成的图形保证代表一条没有循环的直线行进链。 这一保证极其重要，因为它意味着：

 - 旅程只有一个城市结束。 
- 每个其他城市都至少有一个传出边缘。 
- 没有城市可以带回之前访问过的城市。 

任务是找到目的地城市，这是唯一一个从未出现在任何路径中的起点的城市。 

例如，如果我们有：```
London -> New York
New York -> Lima
Lima -> Sao Paulo
```然后`Sao Paulo`是目的地城市，因为没有路径从它开始。 

输入大小非常小，最多 100 条路径，因此效率不是主要问题。 然而，这个问题的目的是测试我们是否能够识别关键图属性，而不是使解决方案过于复杂。 

来自约束和保证的一些重要观察结果：

 - 每一条路都是有方向的。 
- 只有一个有效答案。 
- 不存在循环。 
- 城市名称是字符串，因此基于哈希的结构（例如集合或地图）是理想的。 
- 由于图形成一条线，因此我们不需要像 DFS 或 BFS 这样的图遍历算法。 

重要的边缘情况包括：

 - 单一路径，例如`["A", "Z"]`- 多次作为中间站出现的城市
 - 目的地城市在整个输入中仅出现一次
 - 以任意顺序给出的路径

 因为输入的顺序不能保证代表旅行顺序，所以我们不能简单地从最终路径返回最后一个城市。 

## 方法

 ### 蛮力方法

 一种简单的方法是检查每个目的地城市并检查它是否曾经作为出发城市出现。 

对于每条路径`[fromCity, toCity]`，我们可以再次扫描整个列表来判断是否`toCity`作为任何存在`fromCity`。 

如果我们找到一个从未作为源城市出现的城市，那么该城市一定是目的地城市。 

这是正确的，因为目的地城市被精确定义为具有零传出路径的城市。 

然而，这种方法会执行不必​​要的重复扫描。 对于每个城市，我们可能会再次遍历整个列表，导致时间复杂度为二次。 

### 最佳方法

 关键点在于，目的地城市是唯一一个从未作为出发城市出现的城市。 

我们可以将所有源城市存储在哈希集中，而不是重复扫描输入。 然后我们迭代目的地城市并返回集合中不存在的城市。 

哈希集提供平均值`O(1)`查找时间，使解决方案非常高效且简单。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描每个目的地城市的所有路径 |
 | 最佳| O(n) | O(n) | 使用哈希集进行恒定时间查找 |

 ## 算法演练

 1. 创建一个名为的空哈希集`starting_cities`。 

该集合将存储路径中显示为源城市的每个城市。 我们使用哈希集是因为成员资格检查非常快。 
2. 迭代所有路径。 

对于每条路径`[from_city, to_city]`， 插入`from_city`进入集合。 
3. 再次迭代所有路径。 

对于每条路径`[from_city, to_city]`，检查是否`to_city`存在于`starting_cities`。 
4. 如果`to_city`不在套装内，请立即退回。 

由于该图保证只有一个目的地城市，因此我们遇到的第一个这样的城市就是正确答案。 
5. 如果没有找到城市，则返回空字符串。 

实际上，这条线永远不会到达，因为该问题保证了有效的目的地城市。 

### 为什么它有效

 目的地城市定义为没有外出路径的城市。 每个具有传出路径的城市都会在输入中的某个位置显示为源城市。 因此，源城市集中唯一缺少的城市必定是目的地城市。 

因为问题保证恰好有一个这样的城市，所以算法总是返回正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def destCity(self, paths: List[List[str]]) -> str:
        starting_cities = set()

        for from_city, to_city in paths:
            starting_cities.add(from_city)

        for from_city, to_city in paths:
            if to_city not in starting_cities:
                return to_city

        return ""
```实现直接遵循算法。 

首先，我们创建一个名为`starting_cities`。 在第一个循环中，每个源城市都会插入到集合中。 

在第二个循环中，我们检查每个目的地城市。 如果集合中没有目的地城市，则意味着该城市从未作为起点出现，因此它一定是最终目的地。 

决赛`return ""`存在只是为了完整性。 根据问题约束，有效的目的地城市总是存在的。 

## 解决方案```go
func destCity(paths [][]string) string {
    startingCities := make(map[string]bool)

    for _, path := range paths {
        fromCity := path[0]
        startingCities[fromCity] = true
    }

    for _, path := range paths {
        toCity := path[1]

        if !startingCities[toCity] {
            return toCity
        }
    }

    return ""
}
```Go 解决方案使用`map[string]bool`模拟哈希集，因为 Go 没有内置的集合类型。 

逻辑与Python版本相同：

 - 存储地图中所有起始城市
 - 扫描目的地城市
 - 返回地图中未找到的

 不需要对整数溢出进行特殊处理，因为问题仅涉及字符串和小输入大小。

 ## 边缘情况

 ### 单路径输入

 最小的有效输入仅包含一条路径，例如`["A", "Z"]`。 幼稚的实现可能会使遍历逻辑过于复杂或假设存在多个连接。 我们的实现自然地处理了这个问题，因为源集仅包含`"A"`， 和`"Z"`立即被识别为唯一没有传出路径的城市。 

### 以随机顺序给出的路径

 不保证输入路径按行进顺序出现。 例如：```
["C", "D"]
["A", "B"]
["B", "C"]
```假设列表中的最后一个目的地城市就是答案的天真方法将会失败。 我们的实现完全避免了这个问题，因为它只依赖于源城市成员资格，而不是路径排序。 

### 多次出现的中间城市

 一些城市可能既作为目的地又作为来源地出现。 例如：```
"A" -> "B"
"B" -> "C"
```这里，`"B"`出现在两个角色中。 有缺陷的实现可能会错误地识别`"B"`在将其视为目的地一次后，将其视为目的地。 我们的算法在返回之前正确检查该城市是否也存在于源集中。
