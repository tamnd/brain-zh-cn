[LeetCode 第 1413 题](https://leetcode.com/problems/minimum-value-to-get-positive-step-by-step-sum/)

 **难度：** 🟢简单
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`并要求我们确定**最小正起始值**，这样当我们重复添加元素时`nums`到这个起始值，运行总数永远不会低于`1`。 

换句话说，想象我们从一些称为`startValue`。 我们从左到右处理数组，每一步更新一个运行总和：```
running_sum = startValue + nums[0]
running_sum = running_sum + nums[1]
running_sum = running_sum + nums[2]
...
```要求很严格：**在此过程中的每个点**，运行总和必须保持**至少为 1**。 我们的任务是找到满足这个条件的**最小正整数**。 

输入数组表示运行总计的变化。 正数增加总和，而负数减少总和。 因为负值会使总和低于`1`，我们需要仔细确定起始值必须有多大才能防止这种情况发生。 

限制很小：

 -`1 <= nums.length <= 100`-`-100 <= nums[i] <= 100`这告诉我们输入大小很小，这意味着即使效率较低的方法也可以工作。 然而，我们仍然应该追求最干净、最优化的解决方案。 

一个重要的观察是，唯一重要的是遍历数组时遇到的**最低前缀和**。 如果在某个时刻累计总和达到`-4`，那么我们的起始值必须至少是`5`使得运行总计变为`1`在那一点上。 

一些边缘情况可能会导致简单的实现失败。 如果数组仅包含正数，则答案仍应为`1`，因为该问题明确要求起始值为正，并且运行总计永远不会低于`1`。 具有大负前缀的数组可能需要更大的起始值。 暂时低于零并随后恢复的数组也很重要，因为我们必须保证**每一步**的安全，而不仅仅是最终的总和。 

## 方法

 ### 蛮力方法

 一个简单的想法是尝试从以下位置开始的所有可能的正起始值：`1`。 

对于每位候选人`startValue`，我们模拟整个数组的运行总和。 如果在任何一步总和变得小于`1`，我们拒绝该起始值并尝试下一个。 在整个遍历过程中成功幸存下来的第一个值就是答案。 

这种方法是正确的，因为它按升序详尽地检查所有正起始值。 由于我们停在第一个有效的答案处，因此返回的答案保证是最小的。 

然而，这种方法可能效率低下，因为在找到正确答案之前，我们可能会重复遍历数组来查找许多候选值。 

### 最优前缀和方法

 关键的观察是我们实际上不需要测试不同的起始值。 

相反，我们可以计算数组的**最小前缀和**。 

假设累计和`nums`达到最低值`minimumPrefix`。 

如果：```
startValue + minimumPrefix >= 1
```那么运行总和永远不会低于`1`。 

重新排列：```
startValue >= 1 - minimumPrefix
```因此：

 - 如果最小前缀和为负，我们需要足够的起始值来抵消它。 
- 如果最小前缀和已经是正数，`1`就足够了。 

这给了我们一个直接的公式：```
answer = max(1, 1 - minimumPrefix)
```我们只需要一次遍历数组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × k) | O(n × k) | O(1) | O(1) | 尝试每个可能的起始值，直到其中一个有效为止 |
 | 最佳 | O(n) | O(1) | O(1) | 跟踪一次遍历中的最小前缀和 |

 这里，`n`的长度是`nums`， 和`k`是尝试起始值的数量。 

## 算法演练

 1.初始化两个变量：

 -`running_sum = 0`，跟踪累积前缀和。 
-`minimum_prefix = 0`，存储遇到的最小前缀和。 
2. 从左到右遍历数组。 
3. 对于每个数字：

 - 添加到`running_sum`。 
- 更新`minimum_prefix`其中较小者：

 - 当前`minimum_prefix`- 当前`running_sum`4.处理完所有元素后，计算所需的起始值：

 - 如果`minimum_prefix`是`0`或正数，返回`1`。 
- 否则，返回`1 - minimum_prefix`。 
5. 返回计算结果。 

### 为什么它有效

 该算法之所以有效，是因为任意位置的运行总计等于：```
startValue + prefixSum
```最危险的时刻是前缀和最小的时刻。 如果我们保证这个最低点至少仍然是`1`，那么其他所有步骤也将是安全的，因为它们的前缀和更大。 

因此，选择：```
startValue = 1 - minimumPrefix
```是防止运行总和低于以下的最小值`1`。 

## Python 解决方案```python
from typing import List

class Solution:
    def minStartValue(self, nums: List[int]) -> int:
        running_sum = 0
        minimum_prefix = 0

        for num in nums:
            running_sum += num
            minimum_prefix = min(minimum_prefix, running_sum)

        return max(1, 1 - minimum_prefix)
```实现严格遵循最优算法。 

我们从`running_sum = 0`因为还没有处理任何数字。 变量`minimum_prefix`也开始于`0`，表示处理数组之前的空前缀。 

当我们迭代时`nums`，每个值都被添加到`running_sum`。 更新累积和后，我们将其与当前最小前缀进行比较，并保留较小者。 

遍历完成后，我们使用以下方法计算最小的有效起始值：```python
max(1, 1 - minimum_prefix)
```这`max(1, ...)`确保结果始终为正，即使所有前缀和均为非负数。 

## 解决方案```go
func minStartValue(nums []int) int {
    runningSum := 0
    minimumPrefix := 0

    for _, num := range nums {
        runningSum += num

        if runningSum < minimumPrefix {
            minimumPrefix = runningSum
        }
    }

    result := 1 - minimumPrefix
    if result < 1 {
        return 1
    }

    return result
}
```Go 实现几乎完全反映了 Python 逻辑。 由于Go没有内置的`min`对于整数函数，我们使用一个简单的条件语句来更新`minimumPrefix`。 

不用担心整数溢出，因为约束非常小。 累积总和的界限为：```go
100 × 100 = 10,000
```which easily fits within Go's integer range.

 The function safely handles all valid inputs, including arrays with only positive numbers and arrays containing large negative prefixes.

 ## 边缘情况

 ### 数组仅包含正数

 如果每个数字都是正数，则运行总和只会增加。 一个常见的错误是计算的起始值大于所需的值。 由于运行总计永远不会低于`1`，最小有效答案就是`1`。 

例如：```
nums = [2, 3, 4]
```前缀和始终为正，因此实现返回`1`。 

### 数组早期的大负前缀

 最危险的情况通常发生在数组的开头附近，其中一个大的负值会立即降低运行总和。 

例如：```
nums = [-8, 2, 3]
```仅检查最终总和的简单实现将会失败，因为总和最终会变为正值。 我们的解决方案正确跟踪**最小前缀和**，确保每个中间步骤保持有效。 

### 前缀和稍后恢复

 有时，累积总和会变得非常负，然后由于正值而恢复。 

例如：```
nums = [-4, -2, 10]
```尽管最终的累计和为正数，但运行总和暂时达到`-6`。 该实现通过记住遇到的最小前缀和并从该最小点计算必要的起始值来正确处理此问题。
