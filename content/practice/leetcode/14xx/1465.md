 # LeetCode 1465 - 水平和垂直切割后一块蛋糕的最大面积

 ## 问题理解

 这个问题给了我们一个长方形蛋糕，其高度`h`和宽度`w`。 我们还得到两个数组：

 -`horizontalCuts`，其中包含从顶部边缘测量的水平切割的位置
 -`verticalCuts`，其中包含从左边缘测量的垂直切割的位置

 每一次切割都沿着蛋糕的方向完全切开。 完成所有切割后，蛋糕被分成多个矩形块。 任务是确定最大所得碎片的面积。 

重要的观察是每件作品都是矩形的。 其高度由两个连续水平边界之间的距离确定，其宽度由两个连续垂直边界之间的距离确定。 

输出应该是所有结果块中最大可能的面积。 由于面积可能变得非常大，因此我们必须返回模数结果`10^9 + 7`。 

约束条件很重要：

 -`h`和`w`可以大到`10^9`- 切割次数可以大到`10^5`这些限制立即告诉我们，我们无法显式模拟每个生成的矩形。 检查每一个可能的部分的幼稚方法会太慢。 

该问题还保证：

 - 所有切口均不同
 - 每一个切口都严格位于蛋糕内部
 - 每个方向至少有一个切口

 一些边缘情况很重要：

 - 最大的一块可能位于蛋糕边界上，因此我们必须考虑从边缘到最近的切口的距离。 
- 剪辑可能无法排序。 
- 最大水平间隙和最大垂直间隙可能出现在不同位置。 
- 乘法可能会溢出普通的 32 位整数，尤其是在 Go 中。 

## 方法

 ### 蛮力方法

 强力解决方案首先确定每个水平线段和每个垂直线段，然后生成通过组合它们形成的每个可能的矩形。 

例如：

 - 如果有`m`水平段
 - 以及`n`垂直段

 然后还有`m * n`蛋糕片。 

我们可以单独计算每个矩形面积并跟踪最大值。 

这是可行的，因为每个结果块都是由一个水平间隔和一个垂直间隔形成的。 

然而，这种方法不必要地昂贵。 段数可达`10^5`，这意味着矩形的数量可以接近`10^10`。 这是不可能在时限内处理的。 

### 最佳方法

 关键的见解是最大矩形面积很简单：

 - 最大水平间隙
 - 乘以最大垂直间隙

 我们不需要单独检查每个矩形。 

为什么这有效？ 

每一块的面积是：```
piece_area = horizontal_gap * vertical_gap
```为了最大化产品，我们独立最大化：

 - 段的高度
 - 线段的宽度

 所以问题就简化为：

 1. 对水平切割进行排序
 2. 找到连续水平边界之间的最大距离
 3. 垂直切割排序
 4. 找到连续垂直边界之间的最大距离
 5. 将两个最大差距相乘

 蛋糕本身的边界也必须包括在内：

 -`0`和`h`用于水平切割
 -`0`和`w`用于垂直切割

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m * n) | O(1) | O(1) | 检查每个生成的矩形 |
 | 最佳 | O(m log m + n log n) | O(m log m + n log n) | O(1) 或 O(log n) 取决于排序 | 只找到最大的差距 |

 ## 算法演练

 1. 排序`horizontalCuts`数组，以便可以按顺序检查连续的切割。 
2. 计算最大水平间隙。 

首先，考虑顶部边缘之间的间隙（`0`）和第一次切割。 然后检查每对连续的切口。 最后，考虑最后一次切割与底部边缘之间的间隙（`h`）。 
3. 排序`verticalCuts`出于同样的原因数组。 
4. 计算最大垂直间隙。 

再次包括左边缘 (`0`）和右边缘（`w`）计算距离时。 
5. 将最大水平间隙乘以最大垂直间隙。 

这给出了可能的最大矩形块。 
6. 返回模数结果`10^9 + 7`。 

### 为什么它有效

 每一块最终的蛋糕片都是由一个水平间隔和一个垂直间隔形成的。 一块的面积是这两个维度的乘积。 

由于乘法对于正值是单调的，因此最大面积必须来自：

 - 最大水平间隔
 - 和最大垂直间隔

 没有其他组合可以产生更大的面积。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxArea(self, h: int, w: int, horizontalCuts: List[int], verticalCuts: List[int]) -> int:
        MOD = 10**9 + 7

        horizontalCuts.sort()
        verticalCuts.sort()

        max_horizontal_gap = horizontalCuts[0]

        for i in range(1, len(horizontalCuts)):
            gap = horizontalCuts[i] - horizontalCuts[i - 1]
            max_horizontal_gap = max(max_horizontal_gap, gap)

        max_horizontal_gap = max(
            max_horizontal_gap,
            h - horizontalCuts[-1]
        )

        max_vertical_gap = verticalCuts[0]

        for i in range(1, len(verticalCuts)):
            gap = verticalCuts[i] - verticalCuts[i - 1]
            max_vertical_gap = max(max_vertical_gap, gap)

        max_vertical_gap = max(
            max_vertical_gap,
            w - verticalCuts[-1]
        )

        return (max_horizontal_gap * max_vertical_gap) % MOD
```实现首先对两个切割数组进行排序。 排序是必要的，因为只有按顺序处理切割时才能正确识别最大间隙。 

然后代码计算最大水平间隔。 它首先考虑从顶部边缘到第一次切割的距离。 之后，它会检查剪切之间的所有连续间隙。 最后，它检查从最后一次切割到底部边缘的距离。 

垂直切割重复相同的逻辑。 

一旦知道两个最大间隙，算法就会将它们相乘以获得最大面积。 最后应用模运算来满足问题要求。 

## 解决方案```go
package main

import "sort"

func maxArea(h int, w int, horizontalCuts []int, verticalCuts []int) int {
	const MOD int64 = 1_000_000_007

	sort.Ints(horizontalCuts)
	sort.Ints(verticalCuts)

	maxHorizontalGap := horizontalCuts[0]

	for i := 1; i < len(horizontalCuts); i++ {
		gap := horizontalCuts[i] - horizontalCuts[i-1]
		if gap > maxHorizontalGap {
			maxHorizontalGap = gap
		}
	}

	if h-horizontalCuts[len(horizontalCuts)-1] > maxHorizontalGap {
		maxHorizontalGap = h - horizontalCuts[len(horizontalCuts)-1]
	}

	maxVerticalGap := verticalCuts[0]

	for i := 1; i < len(verticalCuts); i++ {
		gap := verticalCuts[i] - verticalCuts[i-1]
		if gap > maxVerticalGap {
			maxVerticalGap = gap
		}
	}

	if w-verticalCuts[len(verticalCuts)-1] > maxVerticalGap {
		maxVerticalGap = w - verticalCuts[len(verticalCuts)-1]
	}

	area := (int64(maxHorizontalGap) * int64(maxVerticalGap)) % MOD

	return int(area)
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

主要区别在于整数溢出处理。 由于两个间隙的乘积可能超出 32 位整数的范围，因此使用以下命令执行乘法`int64`。 

Go 还需要使用显式排序`sort.Ints`。

 ## 边缘情况

 当最大的部分位于蛋糕的边界而不是位于两个切口之间时，就会出现一种重要的边缘情况。 例如，如果第一个水平切割距离顶部边缘很远，则最大间隙可能是`horizontalCuts[0]`。 仅检查连续剪切的有缺陷的实现会错过这一点。 该解决方案显式检查两个外部边界。 

另一个重要的情况是未排序的输入。 该问题不保证按排序顺序提供剪切。 如果我们计算间隙而不先排序，我们可能会得到负距离或不正确的最大值。 该实现在任何计算之前对两个数组进行排序。 

第三个重要的边缘情况涉及整数溢出。 蛋糕尺寸可达`10^9`，因此该区域可能接近`10^18`。 这超出了 32 位整数限制。 Go 解决方案使用`int64`在乘法期间，Python 解决方案自然可以安全地处理大整数。 

当一个方向上只有一个切口时，就会出现最后一种微妙的边缘情况。 在这种情况下，只有两个段，切口的每一侧各一个。 该实现正确地处理了这个问题，因为它分别检查到两个边界的距离。
