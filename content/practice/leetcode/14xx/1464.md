[LeetCode 问题 1464](https://leetcode.com/problems/maximum-product-of-two-elements-in-an-array/)

 **难度：** 🟢简单
 **主题：** 数组、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`，并要求我们选择两个不同的指数`i`和`j`。 对于这两个元素，我们计算表达式：$(nums[i]-1)(nums[j]-1)$我们的目标是返回该表达式的最大可能值。 

简单来说，我们需要找到数组中相减后产生最大乘积的两个数字`1`来自他们每个人。 由于减去`1`保留正数的相对顺序，最佳对始终是数组中的两个最大值。 

输入是一个整数数组，其中：

 - 数组长度介于`2`和`500`- 每个元素都介于`1`和`1000`这些限制相对较小，这意味着即使是强力解决方案也能在限制范围内发挥作用。 然而，这个问题的目的是测试我们是否能够认识到只有两个最大元素才重要的数学观察结果。 

一个重要的细节是两个索引必须不同。 我们不能使用同一个元素两次，除非它在数组中出现多次。 

有几种边缘情况值得尽早考虑：

 - 恰好有两个元素的数组，因为只有一对可能的元素
 - 包含重复最大值的数组，例如`[5,5]`- 包含许多小值的数组，例如`1`，其中减去`1`产生`0`- 遍历中最大值出现较晚的数组，用于测试跟踪逻辑是否正确更新

 这些约束保证数组始终包含至少两个数字，因此我们永远不需要处理空数组或单元素数组。 

## 方法

 ### 暴力方法

 最直接的解决方案是尝试每一个可能的索引对`(i, j)`在哪里`i != j`。 

对于每对：

 1. 计算`(nums[i] - 1) * (nums[j] - 1)`2. 将其与当前最大值进行比较
 3. 保留找到的最大结果

 这种方法是正确的，因为它明确地检查每个有效对，因此不会错过真正的最大值。 

然而，时间复杂度是二次的，因为对于每个元素，我们都与其他每个元素进行比较。 虽然这里的输入大小足够小，这仍然可以通过，但它不是最有效的解决方案。 

### 最佳方法

 关键的观察结果是表达式仅取决于两个最大的数字。 

假设两个最大的元素是：

 -`max1`-`max2`那么答案是：$(max1-1)(max2-1)$为什么这有效？ 

因为所有的数字都是正整数。 如果一个数比另一个数大，则减去`1`仍然保留顺序。 因此，最大化乘积仅仅意味着选择两个最大值。 

我们可以在跟踪时扫描一次，而不是对数组进行排序：

 - 迄今为止看到的最大值
 - 迄今为止看到的第二大值

 这给出了最佳线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每一个可能的对 |
 | 最佳 | O(n) | O(1) | O(1) | 一次跟踪两个最大的元素 |

 ## 算法演练

 ### 最优一次性算法

 1.初始化两个变量，`largest`和`second_largest`， 到`0`。 

这些变量将存储遍历过程中遇到的两个最大数字。 
2. 迭代数组中的每个数字。 

在每一步中，确定当前数字是否应成为新的最大值或第二大值。 
3. 如果当前数量大于`largest`，更新两个变量。 

上一个`largest`变成`second_largest`，当前号码成为新号码`largest`。 
4. 否则，如果当前数量大于`second_largest`, 仅更新`second_largest`。 

这确保了我们始终保持迄今为止看到的前两个数字。 
5. 处理完整个数组后，计算：$(largest-1)(second\_largest-1)$6. 返回结果。 

### 为什么它有效

 在每次迭代中，算法都会保持以下不变量：

 -`largest`是迄今为止看到的最大数字
 -`second_largest`是迄今为止看到的第二大数字

 因为每个元素都被处理一次并且每次更新后都会保留不变量，所以最终值`largest`和`second_largest`保证是数组中最大的两个数。 由于通过选择两个最大的数字来最大化表达式，因此该算法始终会产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        largest = 0
        second_largest = 0

        for num in nums:
            if num > largest:
                second_largest = largest
                largest = num
            elif num > second_largest:
                second_largest = num

        return (largest - 1) * (second_largest - 1)
```实现首先初始化两个跟踪变量，`largest`和`second_largest`。 

该循环只对每个数字处理一次。 如果当前数字超过当前最大值，则先前的最大值将降级为第二大值，当前数字将成为新的最大值。 

如果该数字不大于最大值但仍大于第二大值，则仅`second_largest`已更新。 

遍历完成后，算法使用两个存储的最大值计算所需的表达式。 

此实现完全避免了排序，从而保持运行时线性和内存使用量恒定。 

## 解决方案```go
func maxProduct(nums []int) int {
    largest := 0
    secondLargest := 0

    for _, num := range nums {
        if num > largest {
            secondLargest = largest
            largest = num
        } else if num > secondLargest {
            secondLargest = num
        }
    }

    return (largest - 1) * (secondLargest - 1)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 主要区别在于语法和迭代风格。 

Go 使用一个`for _, num := range nums`循环遍历切片。 整数运算在这里很简单，因为约束足够小，溢出不是 Go 标准的问题`int`类型。 

由于该问题保证至少有两个元素，因此不需要额外的 nil 或空切片检查。

 ## 边缘情况

 一种重要的边缘情况是仅包含两个元素的数组。 在这种情况下，只有一对可供选择。 某些实现在更新跟踪变量时会意外地假定存在其他元素。 当前的解决方案自然地处理了这个问题，因为即使只有两次迭代，遍历逻辑也能正确工作。 

另一个重要的情况涉及重复的最大值，例如`[5,5]`或者`[1,5,4,5]`。 有缺陷的实现可能会错误地覆盖一个最大值，并且无法保留第二次出现的情况。 该解决方案正确更新`second_largest`每当出现另一个等于最大值的值时。 

数组包含很多`1`价值观也很重要。 由于减去`1`从`1`产生`0`，最终产品可能会变为零。 例如，`[1,1]`应该返回`0`。 该实现可以正确处理这个问题，因为它在识别两个最大值后直接计算数学表达式。 

最后的边缘情况是最大元素出现在数组末尾附近。 例如，`[1,2,3,1000]`需要在遍历后期更新两个跟踪变量。 该算法正确地将先前的最大值转换为`second_largest`每当出现新的最大值时。
