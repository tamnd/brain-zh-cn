[LeetCode 问题 1411](https://leetcode.com/problems/number-of-ways-to-paint-n-3-grid/)

 **难度：** 🔴难
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们确定绘制大小网格的方法数量`n × 3`恰好使用三种颜色（红色、黄色和绿色），这样相邻的两个单元格就不会共享相同的颜色。 相邻意味着水平或垂直连接，因此同一行中的邻居和上方或下方列中的邻居必须不同。 

输入是单个整数`n`，表示网格中的行数。 输出是一个整数，表示有效着色方案总数的模数`10^9 + 7`。 

约束在这里至关重要：`n`可以大到 5000，因此暴力枚举所有可能的颜色在计算上是不可行的。 问题保证`n >= 1`，因此网格始终至少有一行，从而消除了对空输入的担忧。 重要的边缘情况包括最小的网格（`n = 1`），它应该返回着色的基数和大网格，这测试了我们解决方案的效率。 

## 方法

 ### 蛮力

 一种简单的方法是递归地为每个单元格生成所有可能的颜色，并检查任何相邻单元格是否共享相同的颜色。 对于每个单元格，有三种选择，导致`3^(3n)`总配置。 生成每个配置后，我们验证邻接约束。 虽然这种方法是正确的，但效率极低，因为`3^(3n)`呈指数级增长，无法计算`n`最多 5000。 

### 最佳方法

 关键的见解是要注意一行的颜色仅取决于前一行，而不是整个网格。 这允许我们使用动态规划。 如果我们将行颜色分类为模式，我们可以大大减少问题：

 1. **A型（ABA模式）：** 该行第一和第三个单元格颜色相同，中间单元格颜色不同。 例子：`Red-Green-Red`。 
2. **B 型（ABC 模式）：** 该行中的所有三个单元格都有不同的颜色。 例子：`Red-Green-Yellow`。 

对于每一行，我们跟踪使用类型 A 和类型 B 为其着色的方法数量。可以通过检查前一行的类型如何约束当前行的类型来导出转换规则：

 - 如果前一行是 A 型，则当前行可以是 A 型或 B 型，各有 3 种方式。 
- 如果前一行是 B 型，则当前行可以分别以 2 种和 2 种方式为 A 型或 B 型。 

通过逐行迭代并使用这些转换更新计数，我们可以在线性时间内有效地计算答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(3^(3n)) | O(3^(3n)) | O(n * 3^3) | O(n * 3^3) | 递归生成所有可能的着色； n 达到 5000 时不切实际 |
 | 最佳| O(n) | O(1) | O(1) | 使用动态规划和行类型分类； 跟踪仅计数，而不是完整配置 |

 ## 算法演练

 1. 定义`mod = 10^9 + 7`处理大量数据。 
2. 为第一行初始化两个计数器：

 -`countA`对于 ABA 模式：有 6 种有效配置。 
-`countB`对于 ABC 模式：有 6 种有效配置。 
3. 从第 2 行迭代到`n`:

 - 使用先前的行计数计算当前行的新计数：

 -`newCountA = (2 * countA + 2 * countB) % mod`-`newCountB = (2 * countA + 3 * countB) % mod`- 更新`countA`和`countB`和`newCountA`和`newCountB`。 
4. 循环结束后，总路数为`(countA + countB) % mod`。 
5. 返回结果。 

**为什么有效：**

 该算法之所以有效，是因为当前行的状态仅取决于前一行的类型。 通过对行模式进行分类并计算类型之间的转换，我们可以考虑所有有效的颜色，而无需枚举每个配置。 模运算确保数字保持可控。 

## Python 解决方案```python
class Solution:
    def numOfWays(self, n: int) -> int:
        mod = 10**9 + 7
        countA, countB = 6, 6  # ABA and ABC patterns for the first row
        
        for _ in range(1, n):
            newCountA = (2 * countA + 2 * countB) % mod
            newCountB = (2 * countA + 3 * countB) % mod
            countA, countB = newCountA, newCountB
        
        return (countA + countB) % mod
```Python 实现直接遵循该算法。`countA`和`countB`分别跟踪用模式 ABA 和 ABC 为每行着色的方法数量。 对于每个后续行，我们根据转换计算新计数，确保模运算的效率。 

## 解决方案```go
func numOfWays(n int) int {
    mod := 1000000007
    countA, countB := 6, 6 // ABA and ABC patterns for the first row

    for i := 1; i < n; i++ {
        newCountA := (2*countA + 2*countB) % mod
        newCountB := (2*countA + 3*countB) % mod
        countA, countB = newCountA, newCountB
    }

    return (countA + countB) % mod
}
```在 Go 中，在每一步中使用模运算来防止整数溢出。 该逻辑与 Python 相似，通过一个简单的 for 循环迭代行并有效更新计数。 

## 工作示例

 **示例1：**`n = 1`初始计数：`countA = 6`,`countB = 6`。 自从`n = 1`，不执行循环。 总方式 =`6 + 6 = 12`。 

**示例2：**`n = 2`初始计数：`countA = 6`,`countB = 6`。 

第 2 行的迭代：

 -`newCountA = 2*6 + 2*6 = 24`-`newCountB = 2*6 + 3*6 = 30`更新次数：`countA = 24`,`countB = 30`总方式 =`24 + 30 = 54`。 

**示例3：**`n = 3`以前的计数：`countA = 24`,`countB = 30`第 3 行的迭代：

 -`newCountA = 2*24 + 2*30 = 108`-`newCountB = 2*24 + 3*30 = 138`更新次数：`countA = 108`,`countB = 138`总方式 =`108 + 138 = 246`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 我们对每行迭代一次，对计数执行恒定时间计算 |
 | 空间| O(1) | O(1) | 我们只为每种行类型的计数存储两个整数； 不需要额外的结构|

 这种线性时间和恒定空间方法可以有效地处理大型`n`值，最多 5000，而不生成所有颜色。

 ## 边缘情况

 1. **最小尺寸网格（`n = 1`)**：错误的常见来源是假设前一行存在。 我们的解决方案通过初始化第一行的计数并跳过循环来正确处理它`n = 1`。 
2. **大网格（`n = 5000`)**：如果没有模运算，可能会发生整数溢出。 我们的解决方案应用模数`10^9 + 7`采取每一步来防止这个问题。 
3. **统一的行模式**：ABA 与 ABC 的区别至关重要。 对行进行错误分类可能会导致无效的着色。 我们对计数的明确跟踪确保只考虑有效的转换。 

这种方法保证了所有有效输入的正确性、效率和稳健性。
