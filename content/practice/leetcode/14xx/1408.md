## 问题理解

 这个问题给了我们一个唯一的字符串数组，称为`words`。 我们需要找到该数组中作为同一数组中另一个字符串的子字符串出现的每个字符串。 

子字符串是另一个字符串中连续的字符序列。 例如，`"hero"`是一个子串`"superhero"`因为它连续出现在较大的字符串内部。 然而，`"her"`也将是一个子字符串，而类似的东西`"hro"`不会，因为字符不连续。 

输入由一个数组组成`words`，其中每个元素都是小写英文字符串。 输出应该是一个列表，其中包含作为数组中至少一个其他单词的子字符串的所有字符串。 返回列表的顺序并不重要。 

限制相对较小。 该数组最多可以包含`100`单词，每个单词最多有长度`30`。 这些限制很重要，因为它们告诉我们，即使是效率较低的基于比较的方法仍然足够快。 由于成对比较的最大次数仅为`100 × 100 = 10,000`，我们不需要KMP或Rabin-Karp等高级字符串匹配算法来满足性能要求。 

有几种边缘情况值得尽早识别。 一个单词可能是多个单词的子串，但它只能在答案中出现一次。 由于所有输入字符串都保证是唯一的，因此我们不需要处理重复的单词。 另一个重要的情况是当没有字符串是另一个字符串的子字符串时，在这种情况下答案应该是一个空列表。 我们还必须避免将单词视为其自身的子串，因为每个字符串都简单地包含其自身。 

## 方法

 ### 蛮力方法

 解决这个问题的一个简单方法是将数组中的每个单词与其他单词进行比较。 

对于每个单词`words[i]`，我们检查每个其他单词`words[j]`。 如果`i != j`和`words[i]`出现在里面`words[j]`， 然后`words[i]`是一个有效的答案。 一旦找到匹配项，我们就可以停止检查该特定字符串的更多单词，并转到下一个候选者。 

这种方法之所以有效，是因为它明确地验证了问题的定义。 检查每对可能的字符串，确保不会遗漏任何有效的子字符串关系。 

尽管这在技术上是一个蛮力解决方案，但考虑到限制，它已经足够有效了。 由于最大输入大小很小，因此总工作量仍然是可控的。 

### 改进解决方案的关键见解

 关键的观察是我们不需要复杂的模式匹配，因为输入大小很小。 内置的子字符串操作已经高度优化，并且检查每一对的成本很低。 

我们可以简单地迭代所有单词对并使用语言的内置子字符串包含检查，而不是生成所有子字符串或构建复杂的数据结构。 这使实现保持干净、可读且足够快，以满足问题的限制。 

我们可以通过在找到单词的子字符串匹配后尽早中断来进行小的优化，从而避免不必要的比较。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² × 平方米) | O(1) | O(1) | 比较每一对并手动检查子字符串 |
 | 最佳 | O(n² × m) | O(1) | O(1) | 使用内置子字符串搜索比较每一对 |

 这里，`n`是单词数，`m`是平均单词长度。 由于字长上限为`30`，实际运行时间很小。 

## 算法演练

 1. 初始化一个空的结果列表来存储有效的子串单词。 
2. 迭代数组中的每个单词。 将当前单词视为我们要测试的候选子串。 
3. 对于每个候选单词，迭代数组中的所有其他单词。 
4. 当两个单词是同一个对象时跳过比较，因为字符串不应被视为其自身的子字符串。 
5. 使用子串包含检查来确定候选词是否出现在当前比较词的内部。 
6. 如果找到匹配项，则将候选单词添加到结果列表中，并停止检查该候选单词的其他单词。 我们提前停下来，因为问题只问它是否是至少一个其他单词的子串。 
7. 继续，直到处理完每个单词。 
8. 返回最终结果列表。 

### 为什么它有效

 该算法检查每对可能的不同单词。 对于每个单词，它确定是否存在另一个包含它作为子串的单词。 由于每个有效比较都被检查一次，因此不会遗漏任何子串关系。 同时，排除自我比较，防止错误匹配。 因此，算法准确地返回满足问题条件的单词集合。 

## Python 解决方案```python
from typing import List

class Solution:
    def stringMatching(self, words: List[str]) -> List[str]:
        result: List[str] = []

        for current_word in words:
            for other_word in words:
                if current_word == other_word:
                    continue

                if current_word in other_word:
                    result.append(current_word)
                    break

        return result
```实现直接遵循算法。 我们首先创建一个空的`result`列表来存储匹配的单词。 

外循环选择我们要测试的当前单词。 内部循环将该单词与数组中的每个其他单词进行比较。 如果单词相同，我们会跳过比较，因为单词不应该与自身匹配。 

关键操作是表达式`current_word in other_word`，它检查候选单词是否作为另一个单词的子串存在。 一旦我们找到有效的匹配项，我们就会将该单词附加到结果中，并立即`break`从内循环。 这可以避免不必要的工作，因为一场比赛就足够了。 

最后返回结果列表。 

## 解决方案```go
func stringMatching(words []string) []string {
    result := []string{}

    for i := 0; i < len(words); i++ {
        currentWord := words[i]

        for j := 0; j < len(words); j++ {
            if i == j {
                continue
            }

            if contains(words[j], currentWord) {
                result = append(result, currentWord)
                break
            }
        }
    }

    return result
}

func contains(text string, pattern string) bool {
    return len(pattern) <= len(text) &&
        (pattern == text ||
            len(pattern) == 0 ||
            indexOf(text, pattern) != -1)
}

func indexOf(text string, pattern string) int {
    for i := 0; i <= len(text)-len(pattern); i++ {
        match := true

        for j := 0; j < len(pattern); j++ {
            if text[i+j] != pattern[j] {
                match = false
                break
            }
        }

        if match {
            return i
        }
    }

    return -1
}
```更惯用的 Go 解决方案可以使用`strings.Contains`标准库中的函数，但上面的实现显式地显示了子字符串逻辑。 

与 Python 的主要区别是 Go 没有内置的`in`用于子字符串检查的运算符。 相反，我们要么手动实现辅助函数，要么使用`strings.Contains`。 Go 还使用切片作为动态数组，因此结果是使用`append`。 

一个更简洁的 LeetCode 提交是：```go
import "strings"

func stringMatching(words []string) []string {
    result := []string{}

    for i := 0; i < len(words); i++ {
        for j := 0; j < len(words); j++ {
            if i == j {
                continue
            }

            if strings.Contains(words[j], words[i]) {
                result = append(result, words[i])
                break
            }
        }
    }

    return result
}

 ## 边缘情况

 一个重要的边缘情况是输入仅包含单个单词时。 由于单词不能被视为其自身的子串，因此答案必须始终是空列表。 该实现自然地处理了这个问题，因为每个自我比较都会被跳过。 

当一个单词是多个其他单词的子串时，会出现另一种微妙的情况。 例如，`"cat"`可能会出现在两者中`"scatter"`和`"concatenate"`。 粗心的实现可能会在答案中添加重复项。 该解决方案通过在第一次成功匹配后立即中断来避免该问题。 

第三个重要的边缘情况涉及具有相似前缀或后缀但不是实际子串的单词。 例如，`"abc"`和`"abd"`共享一个共同的前缀，但两者都不包含对方。 子字符串包含检查确保仅计算连续的精确匹配。 

最后，嵌套遏制案例，例如`["a", "ab", "abc", "abcd"]`可以暴露仅检查直接邻居的错误。 由于该实现会比较每对单词，因此无论深度如何，它都可以正确识别所有有效的子串关系。
