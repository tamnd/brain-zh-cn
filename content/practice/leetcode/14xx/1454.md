[LeetCode 1454 题](https://leetcode.com/problems/active-users/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们从包含两个表的数据库中识别**活动用户**：`Accounts`和`Logins`。 这`Accounts`表列出了所有用户及其`id`和`name`，以及`Logins`表记录所有登录事件，包括同一用户每天的重复登录和多次登录。 如果用户连续登录**五天或更长时间**，则该用户被定义为活跃用户。 预期输出是一个列表`id`和`name`对于这些活跃用户，排序依据`id`。 

输入是关系表，因此解决方案最好使用 SQL。 挑战来自识别连续日期，这需要仔细处理，因为日期可能有间隙、重复或无序条目。 边缘情况包括每天多次登录的用户、恰好连续五天登录的用户以及从未达到连续五天的间歇性登录的用户。 

后续将问题概括为检测`n`连续几天，这意味着需要一种灵活的参数化方法。 

## 方法

 强力方法是检索每个用户的所有登录日期，对它们进行排序，然后迭代这些日期以计算连续序列。 如果找到连续五天或更多天的序列，则该用户被标记为活跃。 虽然这种方法可行，但它需要迭代潜在的大型数据集并执行多次排序，这对于大规模日志来说效率低下。 

最佳方法利用 SQL 中的**间隙和岛屿技术**。 关键的见解是，用户的连续日期形成一个“岛”，其中日期和连续行号之间的差异是恒定的。 通过计算此差异，可以对连续日期进行分组，并计算每个组的大小来识别连续五天或更多天的序列。 此方法避免了显式循环，并使用窗口函数有效地进行缩放。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(u * d log d) | O(d) | 对于每个用户，对登录日期进行排序（d = 每个用户的登录天数）并检查连续序列 |
 | 最佳 | O(L) | O(L) | 使用 SQL 窗口函数分配行号、计算差异、按用户分组以及过滤长度 >= 5 的序列（L = 总登录行数）|

 ## 算法演练

 1. **重复登录**：删除每个用户每天的重复登录事件，以简化连续天数的计算。 
2. **分配行号**：对于每个用户，对登录日期进行排序并使用分配行号`ROW_NUMBER()`。 
3. **计算间隙**：计算登录日期（转换为整数或纪元）与行号之间的差异。 这种差异对于连续的日期来说是恒定的，有效地创建了一个“岛屿 ID”。 
4. **按岛屿分组**：分组依据`user_id`以及计算出的差异来识别连续序列。 
5. **计算序列长度**：对于每个组，计算天数。 过滤计数为 5 或更多的组。 
6. **检索用户信息**：将过滤后的用户 ID 与`Accounts`表来获取名称。 
7. **订单结果**：排序方式`id`以匹配预期的输出。 

**为什么有效：** 用户的连续日期每行相差一天。 通过从日期中减去行号（转换为整数），所有连续序列都会产生相同的差值。 根据这种差异进行分组可以有效地隔离序列，并通过计算天数来识别活跃用户。 

## Python 解决方案```python
import sqlite3

def active_users(n: int = 5):
    query = f"""
    WITH DistinctLogins AS (
        SELECT DISTINCT id, login_date
        FROM Logins
    ),
    NumberedLogins AS (
        SELECT id,
               login_date,
               ROW_NUMBER() OVER(PARTITION BY id ORDER BY login_date) AS rn
        FROM DistinctLogins
    ),
    Grouped AS (
        SELECT id,
               MIN(login_date) AS start_date,
               MAX(login_date) AS end_date,
               COUNT(*) AS consecutive_days
        FROM NumberedLogins
        GROUP BY id, DATE(login_date, '-' || rn || ' days')
    )
    SELECT a.id, a.name
    FROM Accounts a
    JOIN (
        SELECT id
        FROM Grouped
        WHERE consecutive_days >= {n}
    ) active
    ON a.id = active.id
    ORDER BY a.id;
    """
    return query
```此 Python 函数使用标准 SQL 窗口函数和日期算术构造 SQL 查询字符串。 它会删除重复登录、分配行号、计算间隙以检测连续序列、计算序列长度、过滤活动用户以及与`Accounts`表返回`id`和`name`。

## 工作示例

 对于输入：```
Accounts:
1, Winston
7, Jonathan

Logins:
7, 2020-05-30
1, 2020-05-30
7, 2020-05-31
7, 2020-06-01
7, 2020-06-02
7, 2020-06-02
7, 2020-06-03
1, 2020-06-07
7, 2020-06-10
```**一步一步：**

 1. 重复登录：`2020-06-02`对于用户 7 出现两次，减少到一次。 
2. 每个用户按日期排序的行数：

 | 编号 | 登录日期 | RN |
 | ---| ---| ---|
 | 1 | 2020-05-30 | 1 |
 | 1 | 2020-06-07 | 2 |
 | 7 | 2020-05-30 | 1 |
 | 7 | 2020-05-31 | 2 |
 | 7 | 2020-06-01 | 3 |
 | 7 | 2020-06-02 | 4 |
 | 7 | 2020-06-03 | 5 |
 | 7 | 2020-06-10 | 6 |

 1. 计算`login_date - rn`对序列进行分组。 
2. 计算每组的连续天数。 用户 7 有一组连续 5 天。 
3. 过滤序列 >= 5 天 → 用户 7 处于活动状态。 
4. 加入`Accounts`→ 返回`id=7, name=Jonathan`。

 ## 边缘情况

 **情况1：同一天重复登录**。 用户每天可能会登录多次。 计算原始行的幼稚实现可能会错误地过度计算连续天数。 重复数据删除方式`(id, login_date)`确保准确的序列。 

**情况 2：用户具有完全`n`连续几天**。 如果阈值是`n`（主问题中的 5），序列完全等于`n`必须包括在内。 溶液过滤`>= n`正确处理这个问题。 

**情况 3：由间隙分隔的非连续登录序列**。 具有间歇性登录模式的用户可能有很多登录天数，但没有顺序`n`连续几天。 间隙计算确保只计算真正的连续序列。 

这种方法可以正确处理这些边缘情况，并有效地扩展到大型登录数据集
