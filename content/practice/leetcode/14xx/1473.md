 # LeetCode 1473 - 油漆屋 III

 ## 问题理解

 这个问题要求我们粉刷一排房子，同时满足两个约束：

 1. 每座房子最终都必须涂上一种可用的颜色。 
2. 最终安排必须准确包含`target`社区。 

邻里被定义为漆成相同颜色的最大连续房屋组。 例如，序列：```
[1,1,2,2,3,1,1]
```包含四个街区：```
[1,1], [2,2], [3], [1,1]
```输入提供了三个重要信息：

 -`houses[i]`- 如果非零，则房屋已被粉刷且无法更改。 
- 如果为零，则房子未粉刷，我们可以为其选择任何颜色。 
-`cost[i][j]`- 粉刷房屋的费用`i`有颜色`j + 1`。 
-`target`- 最终配置中所需的社区的确切数量。 

目标是最大限度地减少总涂装成本，同时确保最终安排准确无误`target`社区。 

约束条件很重要：

 -`m <= 100`-`n <= 20`-`target <= 100`这些限制立即表明，暴力枚举所有颜色分配是不可能的。 即使对于中等值，例如：```
20^100
```可能性的数量变得巨大。 

该问题还包含几个棘手的边缘情况：

 - 有些房屋已经粉刷完毕，无法修改。 
- 现有的油漆房屋可能已经超过目标社区数量。 
- 每当当前房屋颜色与之前房屋颜色不同时，就会形成一个新的社区。 
- 多种绘画选择可能会导致相同数量的社区但不同的成本。 
- 可能无法准确实现`target`社区。 

因为我们需要最优成本最小化和精确的邻域结构跟踪，所以这强烈指向动态规划。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试为未粉刷的房屋尝试所有可能的着色分配。 

对于每个未粉刷的房子，我们递归地选择其中一个`n`颜色。 为所有房屋分配颜色后，我们计算社区的数量并计算总成本。 如果邻域计数等于`target`，我们更新最小答案。 

这种方法是正确的，因为它探索了每一种有效的绘画配置。 最终，将找到最低成本的有效安排。 

然而，它太慢了。 

假设有`k`未粉刷的房屋。 那么作业总数为：```
n^k
```在最坏的情况下：```
20^100
```这是完全不可行的。 

### 最佳解决方案的关键见解

 关键的观察是，当从左到右处理房屋时，未来仅取决于：

 - 当前位置
 - 以前的房子颜色
 - 迄今为止形成的社区数量

 这意味着我们可以定义动态编程状态。 

让：```
dp[i][c][t]
```代表粉刷房屋达到指数的最低成本`i`这样：

 - 房子`i`有颜色`c`- 我们已经准确地形成了`t`街区

 仅当当前颜色与先前颜色不同时，邻域计数才会更改。 

这将指数搜索转换为多项式时间动态规划解决方案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^m) | O(n^m) | O(米) | 尝试每一个着色作业|
 | 最优动态规划| O(m × n² × 目标) | O(m × n × 目标) | 追踪位置、颜色和社区 |

 ## 算法演练

 ### 第 1 步：定义 DP 状态

 我们定义：```
dp[i][color][groups]
```作为处理房屋的最低成本`0`到`i`其中：

 - 房子`i`结束于`color`- 确切地`groups`存在邻里关系

 如果一个状态是不可能的，我们就存储无穷大。 

该状态捕获未来转换所需的所有信息。 

### 第 2 步：初始化第一栋房子

 对于房子`0`：

 - 如果已经涂漆，则只允许使用一种颜色。 
- 否则，我们会尝试所有可能的颜色。 

第一栋房子的每一种有效颜色都会准确地创建一个社区。 

### 步骤 3：从左到右处理房屋

 对于每一个房子`i`，我们检查当前所有可能的颜色。 

有两种情况：

 #### 与以前的房子颜色相同

 如果：```
current_color == previous_color
```那么邻域数不会增加。 

过渡：```
dp[i][current][groups]
=
min(
    dp[i][current][groups],
    dp[i-1][previous][groups] + paint_cost
)
```#### 与以前的房子颜色不同

 如果：```
current_color != previous_color
```然后一个新的社区开始了。 

过渡：```
dp[i][current][groups]
=
min(
    dp[i][current][groups],
    dp[i-1][previous][groups-1] + paint_cost
)
```### 步骤 4：尊重预涂房屋

 如果房子已经粉刷过：

 - 我们不能选择其他颜色。 
- 由于不进行任何涂装，因此涂装成本为零。 

此限制在转换期间强制执行。 

### 步骤 5：提取最终答案

 处理完所有房屋后，我们检查：```
dp[m-1][color][target]
```适用于所有颜色。 

最小值就是答案。 

如果每个值都是无穷大，则不存在有效的排列，因此我们返回`-1`。 

### 为什么它有效

 该算法之所以有效，是因为每个 DP 状态都代表达到特定配置的最佳方式：

 - 直到某个房子
 - 以某种颜色结束
 - 拥有一定数量的街区

 每个有效的绘画排列都对应于一个 DP 转换序列。 由于每个状态都存储可实现的最小成本，因此最终答案必须是最优的。 

邻域计数得到正确处理，因为过渡显式检查当前颜色是否与前一个颜色匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCost(
        self,
        houses: List[int],
        cost: List[List[int]],
        m: int,
        n: int,
        target: int
    ) -> int:
        
        INF = float('inf')
        
        # dp[i][color][groups]
        dp = [[[INF] * (target + 1) for _ in range(n)] for _ in range(m)]
        
        # Initialize first house
        if houses[0] != 0:
            color = houses[0] - 1
            dp[0][color][1] = 0
        else:
            for color in range(n):
                dp[0][color][1] = cost[0][color]
        
        # Process remaining houses
        for i in range(1, m):
            
            for curr_color in range(n):
                
                # Skip invalid colors for pre-painted houses
                if houses[i] != 0 and houses[i] - 1 != curr_color:
                    continue
                
                paint_cost = 0 if houses[i] != 0 else cost[i][curr_color]
                
                for prev_color in range(n):
                    for groups in range(1, target + 1):
                        
                        if dp[i - 1][prev_color][groups] == INF:
                            continue
                        
                        # Same neighborhood
                        if curr_color == prev_color:
                            dp[i][curr_color][groups] = min(
                                dp[i][curr_color][groups],
                                dp[i - 1][prev_color][groups] + paint_cost
                            )
                        
                        # New neighborhood
                        elif groups < target:
                            dp[i][curr_color][groups + 1] = min(
                                dp[i][curr_color][groups + 1],
                                dp[i - 1][prev_color][groups] + paint_cost
                            )
        
        answer = min(dp[m - 1][color][target] for color in range(n))
        
        return -1 if answer == INF else answer
```该实现首先创建一个初始化为无穷大的三维 DP 表。 无穷大代表当前无法达到的状态。 

第一个房子是单独处理的，因为它总是创建第一个社区。 如果房子已经粉刷过，则只有一种颜色有效。 否则，每个颜色选择都会以其相应的绘画成本进行初始化。 

主循环从左到右处理房屋。 对于每个房子，算法都会迭代每种可能的当前颜色和每种可能的先前颜色。 

如果当前房屋已预先粉刷，则会立即跳过无效的颜色选择。 这可以防止非法转换。 

对于每个有效的转换：

 - 如果颜色保持不变，则邻域计数保持不变。 
- 如果颜色发生变化，邻域计数就会增加一。 

DP表存储到达每个状态的所有可能方式中的最小成本。 

最后，该算法精确地扫描最后一座房子的所有颜色`target`邻域并返回最小值。 

## 解决方案```go
package main

import "math"

func minCost(houses []int, cost [][]int, m int, n int, target int) int {
	INF := math.MaxInt32

	// dp[i][color][groups]
	dp := make([][][]int, m)

	for i := 0; i < m; i++ {
		dp[i] = make([][]int, n)

		for j := 0; j < n; j++ {
			dp[i][j] = make([]int, target+1)

			for k := 0; k <= target; k++ {
				dp[i][j][k] = INF
			}
		}
	}

	// Initialize first house
	if houses[0] != 0 {
		color := houses[0] - 1
		dp[0][color][1] = 0
	} else {
		for color := 0; color < n; color++ {
			dp[0][color][1] = cost[0][color]
		}
	}

	// Process remaining houses
	for i := 1; i < m; i++ {

		for currColor := 0; currColor < n; currColor++ {

			// Skip invalid colors for pre-painted houses
			if houses[i] != 0 && houses[i]-1 != currColor {
				continue
			}

			paintCost := 0
			if houses[i] == 0 {
				paintCost = cost[i][currColor]
			}

			for prevColor := 0; prevColor < n; prevColor++ {

				for groups := 1; groups <= target; groups++ {

					if dp[i-1][prevColor][groups] == INF {
						continue
					}

					// Same neighborhood
					if currColor == prevColor {

						if dp[i][currColor][groups] >
							dp[i-1][prevColor][groups]+paintCost {

							dp[i][currColor][groups] =
								dp[i-1][prevColor][groups] + paintCost
						}

					} else if groups < target {

						// New neighborhood
						if dp[i][currColor][groups+1] >
							dp[i-1][prevColor][groups]+paintCost {

							dp[i][currColor][groups+1] =
								dp[i-1][prevColor][groups] + paintCost
						}
					}
				}
			}
		}
	}

	answer := INF

	for color := 0; color < n; color++ {
		if answer > dp[m-1][color][target] {
			answer = dp[m-1][color][target]
		}
	}

	if answer == INF {
		return -1
	}

	return answer
}
```Go 实现遵循与 Python 解决方案相同的 DP 结构，但对三维 DP 数组使用显式切片分配。 

Go 没有为整数提供内置的无穷大值，所以`math.MaxInt32`被用作一个大的哨兵值。 

与Python不同`min()`函数中，Go 需要在更新 DP 状态之前进行显式比较。 

两种实现之间的逻辑和状态转换保持相同。

 ## 边缘情况

 当房屋的粉刷方式已经超出了目标社区数量时，就会出现一个重要的边缘情况。 例如：```
[1,2,3]
target = 2
```这些房屋已经包含三个街区，不允许重新粉刷。 一个幼稚的解决方案可能仍会尝试转换，但正确的答案是立即不可能的。 DP 自然会处理这个问题，因为没有有效状态到达目标。 

当所有房屋都未粉刷并且多种颜色产生相同数量的社区时，会发生另一个棘手的情况。 该算法必须选择成本最低的配置，而不是遇到的第一个有效配置。 DP 表通过存储每个状态的最小成本来解决这个问题。 

第三个重要的边缘情况涉及邻里边界。 每当当前颜色与先前颜色不同时，邻域计数必须恰好增加一次。 不正确的实现通常会重复计算或无法正确计算转换。 DP 转换逻辑明确区分：

 - 相同的颜色过渡
 - 不同的颜色过渡

 这保证了准确的邻里跟踪。 

当出现最后一个微妙的情况时`target == m`。 在这种情况下，每对相邻的房屋都必须具有不同的颜色。 DP 正确地处理了这个问题，因为每次颜色变化都会增加邻域计数，使得最终目标只能通过交替颜色来实现。
