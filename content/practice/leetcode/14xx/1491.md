[LeetCode 问题 1491](https://leetcode.com/problems/average-salary-execution-the-minimum-and-maximum-salary/)

 **难度：** 🟢简单
 **主题：** 数组、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`salary`，其中每个元素代表员工的工资。 每个薪资值都是独一无二的，这意味着没有两名员工的薪资相同。 我们的任务是从数组中精确排除一项最低工资和一项最高工资后计算平均工资。 

换句话说，我们必须：

 1. 找出最低的工资。 
2.找到最大的薪水。 
3.忽略他们两个。 
4. 计算所有剩余工资的平均值。 

返回值必须是浮点数。 问题陈述还指定了答案`10^-5`的正确值被接受，因此标准浮点运算就足够了。 

输入尺寸很小：

 -`3 <= salary.length <= 100`-`1000 <= salary[i] <= 10^6`这些限制告诉我们一些重要的事情：

 - 该数组始终包含至少三个元素，因此在删除最低和最高工资后，总会至少有一个值需要平均。 
- 由于所有工资都是独一无二的，因此只有一个最低工资和一个最高工资。 
- 输入大小很小，因此即使效率较低的方法仍然可以轻松通过。 

幼稚的实现可能会意外地在总和中包含最小值或最大值，或者错误地除以原始数组长度而不是减少的长度。 另一个常见的错误是执行整数除法而不是浮点除法，尤其是在像 Go 这样的语言中。 

该问题保证：

 - 总有一个有效的答案。 
- 最低和最高工资是不同的，因为所有工资都是唯一的。 
- 我们永远不需要处理空的剩余数组。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是首先对数组进行排序。 排序后：

 - 第一个要素是最低工资。 
- 最后一个元素是最高工资。 
- 中间的每个元素都应包含在平均值中。 

然后我们可以迭代排序数组的中间部分，计算总和，然后除以剩余元素的数量。 

这种方法是正确的，因为排序将所有工资按递增顺序排列，从而使识别最小值和最大值变得很简单。 

然而，排序需要`O(n log n)`时间，这比必要的工作更多。 我们实际上并不关心所有工资的相对顺序，我们只需要最小值、最大值和总和。 

### 最佳方法

 关键的观察是我们可以在一次遍历数组的过程中计算出我们需要的一切。 

在一次遍历过程中：

 - 追踪迄今为止的最低工资。 
- 跟踪迄今为止看到的最高工资。 
- 维护运行总和。 

最后：

 - 从总和中减去最小值和最大值。 
- 除以`n - 2`，因为排除了两项工资。 

这是有效的，因为平均值仅取决于：$$\text{average} = \frac{\text{total sum} - \text{min} - \text{max}}{n - 2}$$我们永远不需要重新排列数组，因此不需要排序。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(1) 或 O(n) | 对数组进行排序，然后对中间元素求平均值 |
 | 最佳 | O(n) | O(1) | O(1) | 单程跟踪总和、最小值和最大值 |

 ## 算法演练

 ### 最优算法

 1.初始化三个变量：

 -`total_sum`存储所有工资的总和。 
-`minimum_salary`跟踪最小值。 
-`maximum_salary`跟踪最大值。 
2. 遍历数组一次。 

- 将每项工资添加到`total_sum`。 
- 更新`minimum_salary`如果现在的工资比较低。 
- 更新`maximum_salary`如果现在的工资比较高的话。 
3、遍历完成后：

 - 减法`minimum_salary`和`maximum_salary`从`total_sum`。 
- 只剩下应该对平均水平有所贡献的工资。 
4. 计算剩余工资数。 

- 由于恰好排除了两个工资，因此计数为`len(salary) - 2`。 
5. 将调整后的总和除以调整后的计数。 

- 以浮点数形式返回结果。 

### 为什么它有效

 该算法之所以有效，是因为每份工资都属于以下三个类别之一：

 - 最低工资
 - 最高工资
 - 工资应贡献于平均水平

 通过计算所有工资的总和，然后删除最小值和最大值，我们就得到了我们想要平均的工资。 由于我们还除以正确的剩余元素数量，因此结果在数学上是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def average(self, salary: List[int]) -> float:
        total_sum = 0
        minimum_salary = float("inf")
        maximum_salary = float("-inf")

        for current_salary in salary:
            total_sum += current_salary
            minimum_salary = min(minimum_salary, current_salary)
            maximum_salary = max(maximum_salary, current_salary)

        adjusted_sum = total_sum - minimum_salary - maximum_salary
        remaining_count = len(salary) - 2

        return adjusted_sum / remaining_count
```该实现直接遵循最佳单遍方法。 

变量`total_sum`累计所有工资的总和。 同时，`minimum_salary`和`maximum_salary`跟踪遍历过程中遇到的最小值和最大值。 

使用`float("inf")`和`float("-inf")`确保正确处理的第一份薪水初始化最小值和最大值。 

循环结束后，代码从总和中删除最低和最高工资。 剩下的工资正是应该贡献到平均水平的工资。 

最后，将调整后的总和除以`len(salary) - 2`，表示排除两个值后剩余的工资数。 

## 解决方案```go
func average(salary []int) float64 {
    totalSum := 0
    minimumSalary := salary[0]
    maximumSalary := salary[0]

    for _, currentSalary := range salary {
        totalSum += currentSalary

        if currentSalary < minimumSalary {
            minimumSalary = currentSalary
        }

        if currentSalary > maximumSalary {
            maximumSalary = currentSalary
        }
    }

    adjustedSum := totalSum - minimumSalary - maximumSalary
    remainingCount := len(salary) - 2

    return float64(adjustedSum) / float64(remainingCount)
}
```Go 实现与 Python 版本非常相似，但有一些特定于语言的注意事项。 

当两个操作数都是整数时，Go 执行整数除法，因此两者`adjustedSum`和`remainingCount`必须转换为`float64`划分之前。 

Go 解决方案没有使用无穷大值，而是初始化了两者`minimumSalary`和`maximumSalary`与切片的第一个元素。 这是跟踪最小值和最大值时的常见 Go 模式。 

由于这些限制保证至少三份薪水，因此访问`salary[0]`总是安全的。

 ## 边缘情况

 一种重要的边缘情况是允许的三个元素的最小数组大小。 在这种情况下，去掉最低和最高工资后，只剩下一份工资。 有缺陷的实现可能会错误地除以零或错误地处理减小的数组大小。 这个实现正确地除以`len(salary) - 2`，这变成`1`。 

另一个重要的边缘情况是工资已经按升序或降序排序。 一些实现意外地假设随机排序或过于依赖位置逻辑。 由于该解决方案在遍历期间显式跟踪最小值和最大值，因此原始排序对正确性没有影响。 

第三个重要的边缘情况涉及非常大的工资值，接近上限`10^6`。 如果一种语言使用小整数类型，溢出可能会成为一个问题。 Python 整数和 Go 的标准`int`类型可以轻松地处理这些约束下的最大可能总和，因此实现保持安全和正确。 

最后一个微妙的边缘情况是分数平均值。 并非每个调整后的总和都能除以剩余计数。 使用整数除法的实现会截断小数部分并产生不正确的结果。 两种解决方案都明确使用浮点除法来保持精度。
