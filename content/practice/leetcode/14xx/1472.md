 **难度：** 🟡 中等
 **主题：** 数组、链表、堆栈、设计、双向链表、数据流

 ## 解决方案

 ## 问题理解

 问题是要求我们模拟具有历史记录机制的单选项卡浏览器。 你开始于`homepage`，从那里，你可以`visit`新的网址，`back`跟踪一定数量的步数，或者`forward`一定数量的步骤。 

输入由方法调用组成：`BrowserHistory(homepage)`使用主页 URL 初始化浏览器，`visit(url)`导航到新页面并清除所有转发历史记录，`back(steps)`历史上移至`steps`次，以及`forward(steps)`历史上前进到`steps`次。 输出为`back`和`forward`始终是移动后的当前 URL。 

约束表明输入是长度最多为 20 的小字符串，步骤最多为 100，并且最多可以有 5000 个调用。 这意味着我们可以明确地存储完整的历史记录。 边缘情况包括尝试向后或向前移动比历史记录中存在的更多步骤、向后移动后访问新页面（这应该丢弃向前历史记录）以及重复访问同一 URL。 

## 方法

 一种强力方法是维护已访问 URL 的列表和指向当前索引的指针。 在每个`visit(url)`，您追加 URL 并删除当前指针之外的所有 URL。 在`back(steps)`或者`forward(steps)`，您相应地调整指针。 这可以正常工作，但如果重复切片列表以删除转发历史记录，则可能效率低下。 

最佳方法是使用带有当前指针的动态数组（或 Go 中的切片），而不物理删除前向元素。 我们只是在每次访问后跟踪历史记录的有效长度。 这避免了昂贵的列表操作，并使所有操作在最坏的情况下保持 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下每次访问 O(n) | O(n) | 清除前向历史记录时列表切片操作可能会很昂贵 |
 | 最佳 | 每次操作 O(1) | O(n) | 带有指针和有效长度跟踪的数组/列表，避免切片 |

 ## 算法演练

 1. 使用包含以下内容的列表初始化浏览器`homepage`并设置一个指针`current`到索引 0。还维护一个变量`last`跟踪当前历史记录中的最后一个有效页面。 
2. 什么时候`visit(url)`称为增量`current`1，用以下内容覆盖该索引处的元素`url`，并设置`last`等于`current`。 这确保了前向历史记录被有效丢弃，而无需物理删除元素。 
3. 什么时候`back(steps)`被称为，移动`current`向后通过`steps`，但不要低于 0。返回位于`current`指针。 
4. 什么时候`forward(steps)`被称为，移动`current`转发通过`steps`，但不要超出`last`。 返回位于`current`指针。 

为什么它有效：通过维护`current`指针和`last`索引，我们确保浏览器始终为后退和前进操作返回正确的页面。 当访问新页面时，转发历史记录在逻辑上被丢弃，这是通过更新来处理的`last`。 

## Python 解决方案```python
class BrowserHistory:

    def __init__(self, homepage: str):
        self.history = [homepage]
        self.current = 0
        self.last = 0

    def visit(self, url: str) -> None:
        self.current += 1
        if self.current < len(self.history):
            self.history[self.current] = url
        else:
            self.history.append(url)
        self.last = self.current

    def back(self, steps: int) -> str:
        self.current = max(0, self.current - steps)
        return self.history[self.current]

    def forward(self, steps: int) -> str:
        self.current = min(self.last, self.current + steps)
        return self.history[self.current]
```此实现使用单个列表`history`存储 URL 和两个指针：`current`对于活动页面和`last`有效历史的结束。 在`visit`，转发历史记录被覆盖或扩展。`back`和`forward`只需调整`current`在有效范围内。 

## 解决方案```go
type BrowserHistory struct {
	history []string
	current int
	last    int
}

func Constructor(homepage string) BrowserHistory {
	return BrowserHistory{
		history: []string{homepage},
		current: 0,
		last:    0,
	}
}

func (this *BrowserHistory) Visit(url string) {
	this.current++
	if this.current < len(this.history) {
		this.history[this.current] = url
	} else {
		this.history = append(this.history, url)
	}
	this.last = this.current
}

func (this *BrowserHistory) Back(steps int) string {
	this.current -= steps
	if this.current < 0 {
		this.current = 0
	}
	return this.history[this.current]
}

func (this *BrowserHistory) Forward(steps int) string {
	this.current += steps
	if this.current > this.last {
		this.current = this.last
	}
	return this.history[this.current]
}
```Go 实现镜像 Python。 主要区别在于使用切片而不是动态数组，并且边界检查需要显式比较而不是使用`max`或者`min`功能。

 ## 边缘情况

 当尝试向后移动比历史记录更多的步骤时，就会出现一种边缘情况。 该实现正确地限制了`current`指针指向零。 另一个边缘情况是返回后访问新页面； 超出的所有前向历史`current`更新时索引被丢弃`last`。 第三种边缘情况是重复访问同一页面； 该算法通过覆盖或附加自然地处理它，确保前向/后向操作中不会出现重复错误。 这些边缘情况表明该算法在所有有效约束下都是稳健的。
