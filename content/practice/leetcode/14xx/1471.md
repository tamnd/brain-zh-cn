[LeetCode 问题 1471](https://leetcode.com/problems/the-k-strongest-values-in-an-array/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到`k`根据“强度”的自定义定义，数组中最强的值。 

第一个重要的细节是阵列中心的定义。 我们不使用数学意义上的平均值或中位数。 相反，我们首先对数组进行排序，然后选择索引处的元素：$$\frac{n - 1}{2}$$使用整数除法。 该值成为中心`m`。 

一旦我们知道了中心，值的强度就由两个规则决定：

 1. 距中心的绝对距离越大，该值越强。 
2. 如果两个值到中心的距离相同，则较大的数值被认为更强。 

例如，如果中心是`3`：

 -`5`和`1`都是距离`2`远离中心。 
- 由于距离相等，`5`更强，因为`5 > 1`。 

输出可以按任何顺序返回，这简化了实现，因为我们不需要在结果中保留特定的顺序。 

约束条件很重要：

 -`arr.length`可以大到`10^5`- 值的范围可以是`-10^5`到`10^5`这立即告诉我们，极其缓慢的方法，例如重复扫描数组或使用嵌套比较，将不够有效。 

有几个边缘情况值得注意：

 - 具有重复值的数组
 - 带有负数的数组
 - 许多元素具有相同强度的数组
 - 大小的数组`1`- 情况`k == arr.length`，意味着必须返回每个元素
 - 偶数长度数组，排序后仍使用整数除法定义中心

 该问题保证：

 - 数组非空
 -`k`始终有效
 - 中心始终存在

 这些保证简化了实现，因为我们永远不需要处理无效输入。 

## 方法

 ### 蛮力方法

 解决问题最直接的方法是：

 1. 对数组进行排序以计算中心。 
2. 计算每个元素的强度。 
3. 使用自定义比较器再次对所有元素进行排序：

 - 更大`|x - m|`首先
 - 如果绑在一起，则更大`x`首先
 4.返回第一个`k`元素。 

这是有效的，因为自定义排序与强度的问题定义完全匹配。 

然而，虽然正确，但这种方法在已经排序一次以找到中心之后对所有元素执行完全自定义排序。 第二种类型在运行时占主导地位。 

虽然`O(n log n)`是可以接受的`10^5`，我们可以通过避免排序后不必要的比较来在概念上做得更好。 

### 关键见解

 对数组进行排序后，最强的值必须来自排序数组的末尾。 

为什么？ 

因为距离中心最远的元素自然会出现在排序顺序中的最小值和最大值附近。 

这意味着我们可以使用两指针技术：

 - 一个指针从左端开始
 - 一个指针从右端开始
 - 每一步都比较哪一方更强
 - 选取较强的元素并将指针向内移动

 这是有效的，因为：

 - 数组已经排序
 - 距中心的距离向边缘增加
 - 打破平局有利于更大的值，这自然意味着在平局中更喜欢右侧

 这让我们可以选择最强的`k`排序后线性时间内的元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 按自定义强度比较器排序 |
 | 最佳 | O(n log n) | O(n log n) | O(1) 不包括输出 | 排序一次，然后使用两个指针 |

 ## 算法演练

 1. 将数组按升序排序。 

排序是必要的，因为中心取决于排序顺序。 它还启用了两指针策略。 
2. 计算中心。 

中心索引为：$$(n - 1) // 2$$中心值为：$$m = arr[(n - 1) // 2]$$3. 初始化两个指针。 

-`left = 0`-`right = n - 1`这些指针代表最小和最大剩余值。 
4. 反复选择较强的值。 

虽然我们还需要更多元素：

 - 计算：

 -`abs(arr[left] - m)`-`abs(arr[right] - m)`- 比较优势：

 - 如果正确的值更强，就接受它
 - 否则，取左边的值

 请记住，平局是通过较大的数值来解决的，因此当距离相等时，右侧获胜，因为数组已排序。 
5. 向内移动相应的指针。 

- 如果我们取左边的值，则增加`left`- 如果我们采用正确的值，则减少`right`6. 继续直到我们收集`k`元素。 

### 为什么它有效

 排序后的数组保证最强的剩余元素必须始终位于两端之一。 

越靠近中心的元素与其他元素的绝对差异越小`m`，而距离较远的元素则位于排序数组的最末端。 

在每一步中，仅比较两端就足够了，因为所有内部元素必然弱于至少一个边界元素。 

平局打破规则也与排序顺序完全一致：

 - 距离相等，值越大
 - 较大的值总是在右侧

 因此，在每一步贪婪地选择更强的端点总是会产生正确的最强元素集。 

## Python 解决方案```python
from typing import List

class Solution:
    def getStrongest(self, arr: List[int], k: int) -> List[int]:
        arr.sort()

        n = len(arr)
        median = arr[(n - 1) // 2]

        left = 0
        right = n - 1

        result = []

        while len(result) < k:
            left_strength = abs(arr[left] - median)
            right_strength = abs(arr[right] - median)

            if right_strength > left_strength:
                result.append(arr[right])
                right -= 1
            elif right_strength < left_strength:
                result.append(arr[left])
                left += 1
            else:
                if arr[right] >= arr[left]:
                    result.append(arr[right])
                    right -= 1
                else:
                    result.append(arr[left])
                    left += 1

        return result
```实现首先对数组进行排序，因为中心计算和两指针策略都依赖于排序顺序。 

排序后，我们使用索引计算中心`(n - 1) // 2`。 

然后初始化两个指针：

 -`left`从最小值开始
 -`right`从最大值开始

 在每次迭代中，代码都会比较两端值的强度。 较强的值被追加到结果列表中，并且相应的指针向内移动。 

平局打破规则是明确处理的：

 - 如果两个距离相等，则较大的值获胜
 - 由于数组已排序，较大的值通常位于右侧

 循环继续直到恰好`k`元素被收集。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func getStrongest(arr []int, k int) []int {
	sort.Ints(arr)

	n := len(arr)
	median := arr[(n-1)/2]

	left := 0
	right := n - 1

	result := make([]int, 0, k)

	for len(result) < k {
		leftStrength := int(math.Abs(float64(arr[left] - median)))
		rightStrength := int(math.Abs(float64(arr[right] - median)))

		if rightStrength > leftStrength {
			result = append(result, arr[right])
			right--
		} else if rightStrength < leftStrength {
			result = append(result, arr[left])
			left++
		} else {
			if arr[right] >= arr[left] {
				result = append(result, arr[right])
				right--
			} else {
				result = append(result, arr[left])
				left++
			}
		}
	}

	return result
}
```Go 的实现与 Python 解决方案非常相似。 

一个显着的区别是使用`math.Abs`，其运行于`float64`，因此在取绝对值之前必须先转换整数值，然后再转换回整数。 

结果切片已预先分配容量`k`以减少追加期间的重新分配。 

Go 切片是数组的动态视图，因此附加元素对于这个问题来说是高效且自然的。

 ## 边缘情况

 一种重要的边缘情况是数组仅包含一个元素。 在这种情况下，该元素自动成为中心，也是最强的值。 有缺陷的实现可能会错误地移动指针或假设存在多个元素。 当前的实现自然地处理了这个问题，因为循环只是选择单个可用值。 

另一个重要的情况是当许多元素具有相同的强度时。 例如，在`[1,2,4,5]`，值`1`和`5`距中心的距离相等。 该问题要求数值越大才被认为更强。 该实现通过在强度相等时选择较大的值来明确处理这种平局打破规则。 

具有许多重复值的数组也可能导致问题。 例如，`[4,4,4,4]`每个元素到中心的距离为零。 粗心的实现可能会意外地跳过值或错误处理指针移动。 由于该算法每次迭代总是仅消耗一个端点，因此无需特殊情况即可正确处理重复项。 

偶数长度数组是另一个微妙的边缘情况。 中心不是两个中间值的平均值。 相反，该问题具体将中心定义为索引处的元素`(n - 1) // 2`排序后。 实现完全遵循这个定义，避免了错误的中值计算。
