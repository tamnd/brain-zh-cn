[LeetCode 问题 1469](https://leetcode.com/problems/find-all-the-lonely-nodes/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们遍历二叉树并识别每个被认为是“孤独”的节点。 如果一个节点是其父节点的唯一子节点，则该节点是孤独的。 换句话说，如果父节点只有一个子节点，则该子节点是孤独的。 

输入是二叉树的根。 每个节点可能有：

 - 一个左孩子，
 - 一个正确的孩子，
 - 两个孩子，
 - 或没有孩子。 

输出应该是一个列表，其中包含按任意顺序的所有孤独节点的值。 

重要的细节是孤独性完全取决于父节点。 节点本身并不能确定它是否是孤独的。 相反，我们检查父级：

 - 如果父母只有一个左孩子，那么左孩子很孤独，
 - 如果父母只有一个右孩子，那么右孩子是孤独的，
 - 如果父母有两个孩子，那么两个孩子都不会感到孤独。 

根节点永远不会孤独，因为它没有父节点。 

约束告诉我们树最多包含 1000 个节点。 这足够小，完全遍历树是完全可以接受的。 由于可能需要检查每个节点，因此`O(n)`解决方案是理想且简单的。 

一些边缘情况很重要：

 - 只有一个节点的树应该返回一个空列表，因为根不可能是孤独的。 
- 完全平衡的树可能不包含孤独的节点。 
- 形状像链表的树会使每个非根节点变得孤独。 
- 必须小心处理只有一个子节点的节点，这样我们就不会意外错过它们或计数错误的节点。 

## 方法

 ### 蛮力方法

 暴力式解决方案将检查每个节点，并通过检查其父关系来重复确定每个节点是否是孤独的。 一种方法是：

 1. 遍历树并将父引用存储在映射中。 
2、再次遍历，判断每个节点是否是其父节点的唯一子节点。 

这是有效的，因为每个节点最终都会与其父节点配对，从而使我们能够确定它是否有兄弟节点。 

然而，这种方法会执行不必​​要的额外工作。 我们实际上不需要第二次遍历或父映射，因为父映射在我们访问它的那一刻就已经知道它是否有一个或两个子映射。 

### 最佳方法

 关键的观察是，在遍历树时可以立即确定孤独度。 

访问节点时：

 - 如果它有左孩子但没有右孩子，则左孩子是孤独的，
 - 如果它有右孩子但没有左孩子，则右孩子是孤独的。 

这意味着一次深度优先搜索遍历就足够了。 当我们递归处理每个节点时，我们直接将孤独的子值附加到结果列表中。 

这消除了对额外簿记结构（例如父地图）的需要。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 使用额外的父映射和多次遍历 |
 | 最佳 | O(n) | O(h) | 单次DFS遍历，其中h为树高 |

 ## 算法演练

 1. 创建一个名为的空列表`lonely_nodes`来存储答案。 
2. 从根节点开始深度优先搜索。 
3. 对于每个节点，检查它是否只有一个子节点。 

- 如果该节点有左子节点但没有右子节点，则将左子节点的值追加到结果列表中。 
- 如果该节点有右子节点但没有左子节点，则将右子节点的值追加到结果列表中。 
4. 递归地继续对左子树进行遍历。 
5. 递归地继续遍历右子树。 
6. 遍历完成后，返回收集到的结果列表。 

DFS 遍历是一种自然的选择，因为每个节点必须恰好被访问一次，并且树的递归结构直接映射到递归 DFS。 

### 为什么它有效

 该算法之所以有效，是因为每个孤独节点都是由其父节点唯一确定的。 在遍历过程中，每个父节点只检查一次。 在那一刻，我们可以确定它的一个孩子是否缺少兄弟姐妹。 由于树中的每条边都被检查一次，因此所有孤独的节点都被识别出来，并且不会遗漏任何节点。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def getLonelyNodes(self, root: Optional[TreeNode]) -> List[int]:
        lonely_nodes = []

        def dfs(node):
            if not node:
                return

            if node.left and not node.right:
                lonely_nodes.append(node.left.val)

            if node.right and not node.left:
                lonely_nodes.append(node.right.val)

            dfs(node.left)
            dfs(node.right)

        dfs(root)

        return lonely_nodes
```实施首先创建`lonely_nodes`将存储所有孤独节点值的列表。 

嵌套的`dfs`函数执行递归遍历。 第一个条件处理基本情况。 如果当前节点是`None`，递归立即停止。 

接下来的两个条件检查当前节点是否只有一个子节点：

 -`node.left and not node.right`-`node.right and not node.left`每当这些条件之一为真时，相应的子项就是孤独的，因此它的值将被附加到结果列表中。 

最后，递归继续进入两个子树，以便处理树中的每个节点。 

遍历完成后，返回累积的列表。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func getLonelyNodes(root *TreeNode) []int {
    result := []int{}

    var dfs func(node *TreeNode)

    dfs = func(node *TreeNode) {
        if node == nil {
            return
        }

        if node.Left != nil && node.Right == nil {
            result = append(result, node.Left.Val)
        }

        if node.Right != nil && node.Left == nil {
            result = append(result, node.Right.Val)
        }

        dfs(node.Left)
        dfs(node.Right)
    }

    dfs(root)

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别是使用切片而不是 Python 列表和显式`nil`检查而不是 Python 的真实性。 

递归 DFS 函数是使用函数变量声明的，因此它可以递归调用自身。 

Go 切片随着值的附加而动态增长，使它们成为收集孤独节点值的自然选择。 

整数溢出不是问题，因为节点值仅存储和返回，不用于算术运算。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用堆栈存储至树高|

 该算法对树执行一次 DFS 遍历。 由于每个节点都被处理一次，因此总时间复杂度与节点数量呈线性关系。 

空间复杂度来自递归深度。 在平衡树中，高度约为`log n`。 在最坏的情况下，例如完全倾斜的树，高度变为`n`。

 ## 边缘情况

 ### 单节点树

 仅包含根节点的树是一种重要的边缘情况，因为根没有父节点，因此不可能是孤独的。 如果一个有缺陷的实现只检查子项计数而不考虑父项是否存在，则可能会意外地包含它。 该实现自然地处理了这个问题，因为只有在检查父节点时才确定孤独度。 

### 完全平衡树

 在完美二叉树中，每个内部节点都有两个子节点。 因此，没有一个节点是孤独的。 这个案例验证了算法不会仅仅因为节点是叶子而错误地包含它们。 在将任何内容附加到结果之前，该实现正确地检查了一个子项。 

### 高度倾斜的树

 形状像链表的树导致每个非根节点都是孤独的。 这是一个有用的压力情况，因为递归深度达到了其最大可能值。 该算法仍然可以正常工作，因为每个父节点独立地将其单个子节点识别为孤独的。 

### 左孩子或右孩子失踪

 某些实现意外地仅处理左子案例或仅处理右子案例。 这个问题需要检测孤独感，无论方向如何。 该解决方案显式检查以下两项：

 - 左孩子存在而右孩子不存在，
 - 右孩子存在，左孩子不存在。 

这保证了不对称树的正确性。
