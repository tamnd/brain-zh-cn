[LeetCode 1418 题](https://leetcode.com/problems/display-table-of-food-orders-in-a-restaurant/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、排序、有序集

 ## 解决方案

 ## 问题理解

 该问题给出了餐厅订单列表。 每个订单包含三部分信息：

 - 客户姓名
 - 桌号
 - 食品

 订单如下所示：```
[customerName, tableNumber, foodItem]
```目标是建立一个显示表，总结每张桌子上每种食物的订购次数。 

输出格式很重要：

 - 第一行是标题行。 
- 标题的第一列是`"Table"`。 
- 其余的列都是按字母顺序排序的独特食品。 
- 剩余的每一行代表一个表。 
- 每行的第一个值是表号。 
- 剩余值是该餐桌上订购的每种食品的计数。 
- 表行必须按表编号按数字顺序排序。 

例如，如果表`3`已订购`"Ceviche"`两次并且`"Fried Chicken"`一旦，其行应包含：```
["3", "2", "1"]
```按照正确的食物栏顺序。 

客户名称与最终结果无关。 它们仅出现在输入格式中。 

约束条件很重要：

 - 最多可以有`5 * 10^4`订单。 
- 表号范围为`1`到`500`。 
- 食物名称是字符串。 

这些限制强烈表明我们需要一种有效的计数解决方案。 重复扫描每张桌子和食物组合的整个订单列表将带来不必要的昂贵费用。 

有几个重要的边缘情况：

 - 同桌的多个顾客可以点同一商品。 
- 食物只能出现在一张桌子上。 
- 有些餐桌可能只点一种食物。 
- 表编号是输入中的字符串，但排序必须是数字，而不是字典顺序。 例如，`"10"`必须在之后`"5"`，不是之前`"2"`。 
- 同一客户可能会出现多次，但客户身份并不重要。 

## 方法

 ### 蛮力方法

 暴力解决方案将首先收集所有独特的桌子和所有独特的食物。 然后，对于每张桌子和每种食品，我们可以扫描整个订单列表并计算存在多少匹配订单。 

该过程如下所示：

 1. 提取所有独特的食物并对其进行分类。 
2. 提取所有唯一的表并按数字对它们进行排序。 
3. 对于每张桌子：

 - 对于每种食品：

 - 扫描所有订单并计算匹配项。 

这是有效的，因为每个计数都是直接根据输入数据计算的。 然而，由于订单列表被重复扫描多次，因此效率较低。 

如果：

-`T`是表的数量，
 -`F`是食物的数量，
 -`N`是订单数量，

 那么仅计数阶段的成本`O(T * F * N)`。 

高达`50,000`订单，这变得不必要的昂贵。 

### 最佳方法

 关键的观察是我们只需要处理每个订单一次。 

我们可以在迭代订单时构建频率表，而不是重复扫描输入。 

我们使用：

 - 一套收集独特食物的套装。 
- 用于存储计数的嵌套哈希图：

 - 外图键=表号
 - 内部地图钥匙=食物
 - 值 = 计数

 结构示例：```
table_orders = {
    "3": {
        "Ceviche": 2,
        "Fried Chicken": 1
    }
}
```处理完所有订单后：

 1. 按字母顺序对食物进行排序。 
2. 按数字对表格编号进行排序。 
3. 使用存储的计数构建最终显示表。 

这避免了重复扫描并提供了有效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(T * F * N) | O(T + F) | 重复扫描每对餐桌食物的所有订单 |
 | 最佳 | O(N + F log F + T log T + T * F) | O(N + F log F + T log T + T * F) | O(T * F + F) | 使用哈希映射一次性计算订单数量 |

 ## 算法演练

 1. 创建一个集合来存储所有独特的食物。 

我们需要按字母顺序排列的食物列。 集合可以有效地收集独特的食物名称。 
2. 为表计数创建嵌套哈希映射。 

外部映射存储餐桌编号，内部映射存储每种食物的计数。 

例子：```
table_counts["3"]["Ceviche"] = 2
```3. 迭代每个订单。 

对于每个订单：

 - 忽略客户姓名。 
- 提取桌号和食品项目。 
- 将食物添加到食物组中。 
- 增加该表和食品的计数。 
4. 按字母顺序对所有食物进行排序。 

该问题明确要求食物列按字母顺序出现。 
5. 按数字对表格编号进行排序。 

由于表号存储为字符串，因此在排序时我们必须将它们转换为整数。 
6. 构建标题行。 

标题开头为`"Table"`接下来是所有分类的食品。 
7. 构建每个表行。 

对于每个排序表：

 - 以桌号开始行。 
- 对于每种食品：

 - 从哈希映射中检索计数。 
- 使用`0`如果那张桌子上从未点过食物。 
8. 返回完成的显示表。 

### 为什么它有效

 该算法对每个订单只处理一次，并记录每张桌子上每种食品的准确频率。 由于所有食物名称都是全局收集和排序的，因此每行都使用相同的一致列顺序。 以数字方式对表编号进行排序可保证所需的行排序。 由于每次计数都是直接根据输入数据累积的，因此最终表准确地代表了所有餐厅订单。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def displayTable(self, orders: List[List[str]]) -> List[List[str]]:
        food_items = set()

        table_counts = defaultdict(lambda: defaultdict(int))

        for _, table_number, food_item in orders:
            food_items.add(food_item)
            table_counts[table_number][food_item] += 1

        sorted_foods = sorted(food_items)
        sorted_tables = sorted(table_counts.keys(), key=int)

        result = [["Table"] + sorted_foods]

        for table in sorted_tables:
            row = [table]

            for food in sorted_foods:
                row.append(str(table_counts[table].get(food, 0)))

            result.append(row)

        return result
```实现首先创建一个名为`food_items`存储每个不同的食物名称。 这确保了唯一性并允许按字母顺序排序。 

这`table_counts`结构使用嵌套`defaultdict`对象。 外部字典将表号映射到另一个字典，而内部字典存储食物数量。 

单次遍历期间`orders`，代码忽略客户名称，因为它与输出无关。 每个食物项都会添加到集合中，并且相应的计数会增加。 

处理完所有订单后，食品将按字母顺序排序。 表号按数字排序`key=int`因为它们存储为字符串。 

然后逐行构建结果表。 标题行包含`"Table"`接下来是所有分类的食物。 每个表行都附加每个食物项的计数，将计数转换为字符串，因为输出格式需要字符串。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
)

func displayTable(orders [][]string) [][]string {
	foodSet := make(map[string]bool)
	tableCounts := make(map[string]map[string]int)

	for _, order := range orders {
		table := order[1]
		food := order[2]

		foodSet[food] = true

		if _, exists := tableCounts[table]; !exists {
			tableCounts[table] = make(map[string]int)
		}

		tableCounts[table][food]++
	}

	var foods []string
	for food := range foodSet {
		foods = append(foods, food)
	}

	sort.Strings(foods)

	var tables []string
	for table := range tableCounts {
		tables = append(tables, table)
	}

	sort.Slice(tables, func(i, j int) bool {
		a, _ := strconv.Atoi(tables[i])
		b, _ := strconv.Atoi(tables[j])
		return a < b
	})

	result := [][]string{}

	header := append([]string{"Table"}, foods...)
	result = append(result, header)

	for _, table := range tables {
		row := []string{table}

		for _, food := range foods {
			count := tableCounts[table][food]
			row = append(row, strconv.Itoa(count))
		}

		result = append(result, row)
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

一个`map[string]bool`用作食物的集合，因为 Go 不提供内置的集合类型。 嵌套映射用于存储餐桌食物频率。 

Go 需要显式的切片构造和排序。 表排序用途`sort.Slice`和`strconv.Atoi`确保数字排序而不是字典顺序。 

与Python不同`defaultdict`，Go 地图在使用前必须手动初始化。 因此，实现在增加计数之前检查映射中是否已存在表。

 ## 边缘情况

 一种重要的边缘情况是数值表排序。 由于表号以字符串形式提供，因此简单的字典排序将放置`"10"`前`"2"`。 这将违反问题要求。 该实现使用整数转换显式排序，确保正确的数字排序。 

当餐桌从未点过特定食品时，就会出现另一个重要的边缘情况。 如果实现直接访问缺失的键而不处理默认值，则可能会引发错误或产生不完整的行。 该解决方案安全使用`.get(food, 0)`在 Python 中，并依赖 Go 的零值行为来查找缺失的映射条目。 

第三个重要的边缘情况是在同一张桌子上重复订购相同的食物。 多个客户可能会订购相同的商品，算法必须正确累积计数而不是覆盖它们。 嵌套的哈希映射结构会增加每次出现的计数，从而保证准确的总数。 

第四种边缘情况涉及只有一张桌子或只有一种食物。 某些实现意外地假设存在多行或多列。 该解决方案根据收集的数据动态构建表，因此即使输入最少也能正常工作。
