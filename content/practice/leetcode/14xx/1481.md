[LeetCode 问题 1481](https://leetcode.com/problems/least-number-of-unique-integers-after-k-removals/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪心、排序、计数

 ## 解决方案

 ## 问题理解

 这个问题要求我们在精确删除后最小化数组中唯一整数的数量`k`元素。 换句话说，我们得到了一个列表`arr`和一个数字`k`，我们需要战略性地删除`k`元素，以便数组中剩余的不同整数的数量尽可能小。 

输入数组`arr`包含的整数可以大到`10^9`并且最多可以有`10^5`元素。 这意味着解决方案必须在时间和空间上都有效。 整数`k`准确地表示我们必须删除多少个元素，因此我们不能删除更少或更多。 

预期输出是一个整数，表示删除后数组中剩余的唯一元素的最小数量。 

重要的边缘情况包括以下场景：`k`为零（不删除）或`k`等于数组的长度（删除所有元素），并且当多个数字具有相同的频率时，这可能会影响删除策略。 

## 方法

 ### 蛮力方法

 一种简单的方法会尝试删除所有可能组合中的元素，以查看哪种组合使唯一整数的数量最小化。 这可以通过生成大小的所有子集来实现`k`从数组中删除它们，并对每个结果中的不同整数进行计数。 这种方法保证找到正确答案，因为它探索了每种可能性，但在计算上是不可行的。 对于长度的数组`n`和`k`删除，要考虑的子集数量是`C(n, k)`，它的阶乘增长为`n`太大了`n = 10^5`。 

### 最佳方法

 更好的解决方案的关键是基于频率的去除。 我们应该首先删除出现次数最少的整数，因为删除它们可以最有效地减少唯一整数的计数。 通过计算每个整数的出现频率并按出现频率对它们进行排序，我们可以贪婪地删除从出现次数最少的整数开始，直到`k`元素被删除。 这种方法是最优的，因为首先删除频率较高的整数会消耗更多的`k`而不有效地减少唯一整数的数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(C(n, k) * n) | O(C(n, k) * n) | O(n) | 尝试所有移除组合； 对于大型阵列不可行|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 频数统计排序，然后贪心去除 |

 ## 算法演练

 1. **计数频率：** 迭代数组并创建哈希映射或字典来计算每个整数出现的次数。 这使我们能够了解哪些整数可以便宜地删除。 
2. **按频率排序：** 将频率字典转换为（数字，频率）对的列表，并按频率升序排序。 这确保我们优先删除频率最小的整数。 
3. **贪婪去除：** 初始化唯一整数数量的计数器。 迭代排序后的频率列表，对于每个整数，检查其频率是否小于或等于剩余的`k`。 如果是，则完全删除它，减少`k`通过其频率，并减少唯一计数器。 如果频率大于`k`， 消除`k`该整数中的元素并停止，因为我们已经使用了所有删除操作。 
4. **返回结果：** 完成迭代或使用所有`k`删除后，唯一整数的剩余计数就是答案。 

**为什么它起作用：** 该算法保证了唯一整数的最小数量，因为按频率增加的顺序删除整数可以确保每个单位`k`最大限度地减少唯一计数。 这种贪婪的选择保持了最优​​的不变量。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:

    def findLeastNumOfUniqueInts(self, arr: List[int], k: int) -> int:
        # Step 1: Count frequencies
        freq = Counter(arr)
        
        # Step 2: Sort integers by frequency
        freq_list = sorted(freq.values())
        
        # Step 3: Greedy removal
        unique_count = len(freq_list)
        for f in freq_list:
            if k >= f:
                k -= f
                unique_count -= 1
            else:
                break
        
        return unique_count
```该代码首先计算每个整数的频率`arr`使用`Counter`，然后对频率进行排序。 通过迭代排序列表，我们贪婪地删除最不频繁的整数，直到`k`已耗尽，每次都会减少唯一整数的计数。 其余`unique_count`被返回。 

## 解决方案```go
import "sort"

func findLeastNumOfUniqueInts(arr []int, k int) int {
    freq := make(map[int]int)
    for _, num := range arr {
        freq[num]++
    }

    freqList := make([]int, 0, len(freq))
    for _, count := range freq {
        freqList = append(freqList, count)
    }

    sort.Ints(freqList)

    uniqueCount := len(freqList)
    for _, f := range freqList {
        if k >= f {
            k -= f
            uniqueCount--
        } else {
            break
        }
    }

    return uniqueCount
}
```在 Go 中，我们使用映射来计算频率，并使用切片来对频率进行排序。 逻辑与 Python 版本相同，关注切片创建和映射迭代。

 ## 边缘情况

 一个重要的边缘情况是当`k = 0`。 在这种情况下，算法应立即返回唯一整数的总数，因为没有元素被删除。 Python 和 Go 实现自然地处理这个问题，因为循环永远不会递减`k`。 

另一种边缘情况发生在`k`等于数组的长度。 这意味着必须删除所有元素，从而产生零个唯一整数。 两种实现都减少了`
