[LeetCode 1462 题](https://leetcode.com/problems/course-schedule-iv/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题为我们提供了一个表示课程依赖性的有向无环图。 每门课程都是一个节点，并且有前提关系`[a, b]`意味着有一条有向边`a`到`b`。 换句话说，当然`a`必须在课程之前完成`b`。 

重要的细节是先决条件是传递的。 如果当然`0`课程开始前需要`1`，当然`1`课程开始前需要`2`，那么当然`0`当然也被认为是先决条件`2`。 这个问题要求我们有效地回答许多此类可达性问题。 

对于每个查询`[u, v]`，我们必须确定是否存在一条路径`u`到`v`在图中。 如果存在这样的路径，那么`u`是一个先决条件`v`。 

输入包括：

 -`numCourses`，图中的节点总数
 -`prerequisites`，有向边
 -`queries`，我们需要回答的可达性检查

 输出是一个布尔数组，其中每个位置对应一个查询。 

约束对于选择正确的算法非常重要：

 -`numCourses <= 100`-`queries <= 10^4`图本身很小，但查询数量可能很大。 这强烈建议对图进行一次预处理，然后在恒定时间内回答每个查询。 

该图保证没有循环，这意味着它是有向无环图（DAG）。 这种保证简化了遍历逻辑，因为我们永远不需要担心循环引起的无限循环。 

一些边缘情况很重要：

 - 可能根本没有先决关系。 
- 查询可能会询问不相关的节点。 
- 许多中级课程之间的依赖性可能是间接的。 
- 多个先决条件链可能会汇聚到同一门课程中。 
- 图表可以断开。 

对每个查询执行全新遍历的简单解决方案可能仍然适用于这些约束，但有一种更优雅的预处理方法可以有效地回答每个查询。 

## 方法

 ### 蛮力方法

 蛮力的想法很简单。 对于每个查询`[u, v]`，从以下位置开始执行图遍历`u`并检查是否`v`是可达的。 

我们可以对每个查询使用深度优先搜索或广度优先搜索：

 1. 根据先决条件对构建邻接表。 
2. 对于每个查询：

 - 启动DFS或BFS`u`- 搜索直到`v`找到或遍历结束
 3.返回是否`v`可以到达

 这是有效的，因为图遍历正确地确定了有向图中的可达性。 

然而，当有很多查询时，这会变得低效。 如果我们对每个查询执行遍历，我们就会多次重复探索相同的图结构。 

与：

 - 最多`10^4`查询
 - 最多`100`节点

 重复的遍历会产生不必要的开销。 

### 最佳方法

 关键的见解是图很小，但查询数量很大。 

我们可以提前预处理所有先决关系，而不是独立回答查询。 

我们创建一个矩阵：```
reachable[a][b]
```其中存储是否课程`a`当然是前提条件`b`。 

由于该图只有 100 个节点，因此我们可以有效地计算所有节点对的传递可达性。 

一种优雅的方法是 Floyd-Warshall 传递闭包技术。 

这个想法是：

 - 初始化直接先决关系
 - 逐渐允许中间节点
 - 如果：

 -`a -> k`- 和`k -> b`- 然后：

-`a -> b`预处理后，每个查询都变成恒定时间查找。 

这是理想的，因为：

 - 预处理成本很小`n <= 100`- 查询回答变得非常快

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(q × (V + E)) | O(V + E) | 为每个查询运行 DFS/BFS |
 | 最佳 | O(V³ + q) | O(V²) | 预先计算所有先决关系 |

 ## 算法演练

 我们使用 Floyd-Warshall 风格的传递闭包计算。 

### 第 1 步：创建可达性矩阵

 我们创建一个二维布尔矩阵：```
reachable[i][j]
```该矩阵表示课程是否`i`当然是前提条件`j`。 

最初，每个值都是`False`。 

### 第 2 步：标记直接先决条件

 对于每个先决条件对`[a, b]`:```
reachable[a][b] = True
```这将建立图中的所有直接边。 

### 步骤 3：使用中间节点

 我们现在尝试通过允许中间节点来改进可达性信息。 

对于每门中级课程`k`：

 1.检查每一个可能的起始路线`i`2. 检查每一个可能的目的地航线`j`3. 如果：

 -`i`可以达到`k`- 和`k`可以达到`j`4.然后：

 -`i`还可以达到`j`更新后变为：```
reachable[i][j] |= reachable[i][k] and reachable[k][j]
```这将逐步计算间接先决条件链。 

### 第 4 步：回答问题

 对于每个查询`[u, v]`，只需返回：```
reachable[u][v]
```现在这是一个 O(1) 查找。 

### 为什么它有效

 该算法之所以有效，是因为 Floyd-Warshall 系统地将每个节点视为可能的中间连接点。 

后处理节点`k`，矩阵正确表示仅使用节点的所有路径`0..k`作为中间体。 

最后，图中每条可能的路径都已被考虑。 所以，`reachable[a][b]`当且仅当存在从`a`到`b`。 

## Python 解决方案```python
from typing import List

class Solution:
    def checkIfPrerequisite(
        self,
        numCourses: int,
        prerequisites: List[List[int]],
        queries: List[List[int]]
    ) -> List[bool]:

        reachable = [
            [False] * numCourses
            for _ in range(numCourses)
        ]

        # Direct prerequisites
        for prereq, course in prerequisites:
            reachable[prereq][course] = True

        # Floyd-Warshall transitive closure
        for intermediate in range(numCourses):
            for start in range(numCourses):
                if reachable[start][intermediate]:
                    for end in range(numCourses):
                        if reachable[intermediate][end]:
                            reachable[start][end] = True

        # Answer queries
        result = []

        for u, v in queries:
            result.append(reachable[u][v])

        return result
```实现首先分配一个`numCourses × numCourses`布尔矩阵。 每个条目代表一门课程是否可以从另一门课程到达。 

接下来，我们从输入数组填充所有直接先决条件关系。 

该算法的核心是三重嵌套循环。 外循环选择一个中间节点。 内部循环确定是否可以通过经过该中间节点来改进路径。 

包括优化：```python
if reachable[start][intermediate]:
```如果起始节点甚至无法到达中间节点，则没有理由检查所有目的地。 

最后，使用直接矩阵查找来回答查询，这使得每个查询都非常快。 

## 解决方案```go
func checkIfPrerequisite(numCourses int, prerequisites [][]int, queries [][]int) []bool {

	reachable := make([][]bool, numCourses)

	for i := 0; i < numCourses; i++ {
		reachable[i] = make([]bool, numCourses)
	}

	// Direct prerequisites
	for _, edge := range prerequisites {
		prereq := edge[0]
		course := edge[1]

		reachable[prereq][course] = true
	}

	// Floyd-Warshall transitive closure
	for intermediate := 0; intermediate < numCourses; intermediate++ {
		for start := 0; start < numCourses; start++ {

			if reachable[start][intermediate] {

				for end := 0; end < numCourses; end++ {

					if reachable[intermediate][end] {
						reachable[start][end] = true
					}
				}
			}
		}
	}

	// Answer queries
	result := make([]bool, 0, len(queries))

	for _, query := range queries {
		u := query[0]
		v := query[1]

		result = append(result, reachable[u][v])
	}

	return result
}
```Go 的实现与 Python 版本非常相似。 

主要区别在于显式切片分配。 Go 需要使用嵌套手动构造 2D 布尔矩阵`make`来电。 

Go 切片默认为零值，因此所有条目自然开始为`false`。 

不存在整数溢出问题，因为所有操作都涉及小索引和布尔值。

class Solution:
    def checkIfPrerequisite(
        self,
        numCourses: int,
        prerequisites: List[List[int]],
        queries: List[List[int]]
    ) -> List[bool]:

        reachable = [
            [False] * numCourses
            for _ in range(numCourses)
        ]

        for prereq, course in prerequisites:
            reachable[prereq][course] = True

        for intermediate in range(numCourses):
            for start in range(numCourses):
                if reachable[start][intermediate]:
                    for end in range(numCourses):
                        if reachable[intermediate][end]:
                            reachable[start][end] = True

        return [reachable[u][v] for u, v in queries]

 ## 边缘情况

 一种重要的边缘情况是根本没有先决条件。 在这种情况下，每个课程都是独立的，每个查询都应该返回`False`。 有缺陷的实现可能会意外地从未初始化的内存或不正确的默认值中推断出关系。 我们的实现正确地处理了这个问题，因为可达性矩阵完全开始于`False`，并且没有更新发生。 

另一个重要的例子是长的间接先决条件链。 例如：```
0 -> 1 -> 2 -> 3 -> 4
```仅检查直接边缘的幼稚实现将无法识别这一点`0`是一个先决条件`4`。 Floyd-Warshall 传递闭包计算正确地在任意长的链上传播可达性。 

第三个重要的边缘情况是断开连接的图形组件。 有些课程可能属于完全独立的依赖关系树。 例如：```
0 -> 1

2 -> 3
```两个组件之间的查询应始终返回`False`。 由于该算法仅在存在有效连接路径时更新可达性，因此断开连接的组件在整个计算过程中保持隔离。 

另一个微妙的边缘情况涉及相同节点之间的多条路径。 考虑：```
0 -> 1 -> 3
0 -> 2 -> 3
```算法仍然必须正确标记`0 -> 3`无论存在多少条不同的路径，都只执行一次。 布尔可达性矩阵自然会处理这个问题，因为一旦条目变成`True`，重复发现不影响正确性。
