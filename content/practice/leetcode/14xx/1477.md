[LeetCode 问题 1477](https://leetcode.com/problems/find-two-non-overlapping-sub-arrays-each-with-target-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、二分查找、动态规划、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们在给定数组中找到两个不同的子数组，这样：

 1. 每个子数组的总和恰好等于`target`2.两个子数组不重叠
 3、选择的两个子数组的总长度尽可能小

 子数组是数组的连续部分。 由于子数组不得重叠，因此如果一个子数组使用索引`[l1, r1]`和另一个用途`[l2, r2]`，那么要么`r1 < l2`或者`r2 < l1`。 

输入包括：

 -`arr`，正整数数组
 -`target`，每个子数组的所需总和

 输出是：

 - 总和相等的两个非重叠子数组的最小可能长度总和`target`-`-1`如果不存在这样的对

 约束条件非常重要：

 -`arr.length`可以大到`10^5`- 每个元素都是积极的
 -`target`也可以很大

 由于数组大小很大，任何算法都比粗略地慢`O(n log n)`或者`O(n)`可能太慢了。 检查每个可能的子数组对的简单解决方案将过于昂贵。 

一个重要的属性是所有数字都是正数。 这使我们能够有效地使用滑动窗口，因为增加窗口总是会增加总和，而缩小窗口总是会减少总和。 

一些边缘情况很重要：

 - 数组可能只包含一个有效的子数组，在这种情况下答案是`-1`- 多个有效子数组可以重叠，但不允许重叠对
 - 最佳答案可能涉及数组中相距很远的两个非常小的子数组
 - 可能有很多有效的子数组，需要我们仔细追踪目前为止看到的最小长度

 ## 方法

 ### 蛮力方法

 一个简单的解决方案是生成每个总和等于的子数组`target`，然后比较每对这样的子数组以找到非重叠对之间的最小组合长度。 

我们可以通过几个步骤来完成此操作：

 1. 枚举所有子数组
 2. 存储每个总和等于的子数组`target`3. 比较每一对
 4.检查是否重叠
 5. 追踪最小组合长度

 这种方法是正确的，因为它明确地检查了每一个有效的可能性。 

然而，它太慢了。 

有`O(n^2)`可能的子数组。 比较所有有效子数组对也可以采用`O(n^2)`最坏情况下的时间。 这可能导致整体复杂性接近`O(n^4)`在天真的版本中，或者`O(n^2)`即使有优化。 

和`n = 100000`，这是完全不可行的。 

### 最佳方法

 关键的见解是我们不需要明确地比较每一对。 

相反，在从左到右扫描数组时，我们可以：

 1. 使用滑动窗口查找总和等于的子数组`target`2. 跟踪在每个位置或之前结束的最短有效子数组
 3. 每当我们找到一个新的有效子数组时，将其与最佳的早期非重叠子数组组合

 由于所有数字都是正数，因此滑动窗口可以在线性时间内高效工作。 

我们维持：

 -`best[i]`，在索引处或之前结束的有效子数组的最小长度`i`- 代表迄今为止找到的最佳配对的运行答案

 当我们发现一个子数组时`[left, right]`：

 - 它的长度是`right - left + 1`- 任何先前的有效子数组必须在之前结束`left`- 所以我们将当前长度与`best[left - 1]`这避免了直接比较每一对。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 ### 第 1 步：初始化变量

 我们使用：

 -`left`用于滑动窗口启动
 -`current_sum`当前窗口总和
 -`best`数组，其中`best[i]`存储在索引处或之前结束的最短有效子数组`i`-`answer`初始化为无穷大

 的`best`数组很重要，因为它可以让我们立即检索最短的早期有效子数组。 

### 步骤 2：展开滑动窗口

 使用迭代遍历数组`right`。 

每一步：

 - 添加`arr[right]`到`current_sum`由于所有值都是正数，因此窗口总和仅在我们扩展时才会增加。 

### 步骤 3：需要时缩小窗口

 如果`current_sum > target`，从左侧缩小窗口：

 - 减法`arr[left]`- 增量`left`我们继续缩小直到`current_sum <= target`。 

因为数字是正数，一旦总和超过目标，就会移动`left`前进是减少它的唯一方法。 

### 步骤 4：检测有效子数组

 每当`current_sum == target`，我们找到了一个有效的子数组`[left, right]`。 

计算：```
length = right - left + 1
```### 步骤 5：与之前的不重叠子数组合并

 为避免重叠：

 - 任何较早的子数组必须在此之前结束`left`如果`left > 0`和`best[left - 1]`有效，则：```
answer = min(answer, length + best[left - 1])
```这会将当前子阵列与最佳的早期兼容子阵列结合起来。 

### 步骤 6：更新最佳阵列

 我们更新：```
best[right] = min(best[right - 1], length)
```这意味着：

 - 要么先前最好的解决方案仍然是最优的
 - 或者当前子数组较短

 如果没有有效的子数组结束于`right`， 然后：```
best[right] = best[right - 1]
```### 第7步：返回结果

 如果`answer`仍为无穷大，返回`-1`。 

否则返回`answer`。 

### 为什么它有效

 该算法之所以有效，是因为在每个索引处，我们维护在该位置或之前结束的最短有效子数组。 当找到新的有效子数组时，我们立即将其与最佳的早期非重叠子数组组合。 由于每个有效的子数组都被处理一次，并且每个兼容的早期子数组都被总结在里面`best`，算法永远不会错过最佳对。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSumOfLengths(self, arr: List[int], target: int) -> int:
        n = len(arr)

        INF = float('inf')

        best = [INF] * n

        left = 0
        current_sum = 0
        answer = INF

        for right in range(n):
            current_sum += arr[right]

            while current_sum > target:
                current_sum -= arr[left]
                left += 1

            if current_sum == target:
                current_length = right - left + 1

                if left > 0 and best[left - 1] != INF:
                    answer = min(
                        answer,
                        current_length + best[left - 1]
                    )

                best[right] = current_length

            if right > 0:
                best[right] = min(best[right], best[right - 1])

        return -1 if answer == INF else answer
```实现直接遵循算法。 

这`best`array 存储到目前为止看到的每个位置的最小有效子数组长度。 最初，每个条目都是无穷大，因为没有找到有效的子数组。 

滑动窗口的维护使用`left`和`right`。 由于所有元素都是正数，因此可以有效地调整窗口，而无需过多地重新访问元素。 

每当发现一个有效的子数组时，我们首先计算它的长度。 然后我们使用以下方法检查是否存在不重叠的较早子数组`best[left - 1]`。 

最后，我们将最小值向前传播到`best`数组，因此每个位置都包含在该索引处或之前结束的最短有效子数组。 

## 解决方案```go
package main

import "math"

func minSumOfLengths(arr []int, target int) int {
	n := len(arr)

	const INF = math.MaxInt32

	best := make([]int, n)

	for i := 0; i < n; i++ {
		best[i] = INF
	}

	left := 0
	currentSum := 0
	answer := INF

	for right := 0; right < n; right++ {
		currentSum += arr[right]

		for currentSum > target {
			currentSum -= arr[left]
			left++
		}

		if currentSum == target {
			currentLength := right - left + 1

			if left > 0 && best[left-1] != INF {
				if currentLength+best[left-1] < answer {
					answer = currentLength + best[left-1]
				}
			}

			best[right] = currentLength
		}

		if right > 0 && best[right-1] < best[right] {
			best[right] = best[right-1]
		}
	}

	if answer == INF {
		return -1
	}

	return answer
}
```Go 实现密切反映了 Python 逻辑。 

Go 没有内置的整数无穷大值，所以`math.MaxInt32`用作哨兵值。 

切片是显式初始化的，最小比较是手动编写的，因为 Go 没有提供内置的`min`旧版本中的整数函数。 

由于这些约束完全适合 32 位整数，因此这里不必担心整数溢出。

 ## 边缘情况

 当仅存在一个有效子数组时，就会出现一种重要的边缘情况。 幼稚的实现可能会意外返回其长度，而不是认识到需要两个不重叠的子数组。 此实现避免了该错误，因为仅当先前的有效子数组已存在于`best`大批。 

另一个重要的边缘情况涉及重叠子数组。 例如，在`[1,1,1,1]`有目标`2`，许多有效窗口重叠。 算法仔细检查`best[left - 1]`，确保较早的子数组严格在当前子数组开始之前结束。 

当最佳解决方案使用数组中相距很远的非常小的子数组时，就会出现第三种边缘情况。 总是选择第一个有效子数组的贪婪方法在这里可能会失败。 这`best`array 通过连续跟踪迄今为止看到的最短有效子数组来解决这个问题，保证每个未来窗口都与全局最优的早期选择配对。 

最后的边缘情况涉及根本没有有效子数组的数组。 在这种情况下，答案变量在整个执行过程中保持无穷大，并且算法正确返回`-1`。
