[LeetCode 问题 1403](https://leetcode.com/problems/minimum-subsequence-in-non-increasing-order/)

 **难度：** 🟢简单
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`并要求我们构建一个子序列，其总和严格大于不包含在子序列中的所有元素的总和。 

子序列意味着我们可以从数组中删除元素，同时保留剩余元素。 但是，最终答案必须以非递增顺序返回，因此我们可以在返回所选值之前有效地自由对它们进行排序。 

该问题引入了两个优化要求：

 1. 子序列必须具有尽可能小的大小。 
2. 如果多个子序列的最小大小相同，我们必须选择总和最大的一个。 

输入尺寸相对较小：

 -`1 <= nums.length <= 500`-`1 <= nums[i] <= 100`这些限制告诉我们一些重要的事情：

 - 数组足够小，排序是完全可以接受的。 
- 值只能是正整数，这一点非常重要。 
- 因为所有数字都是正数，所以首先取较大的数字总是尽快增加子序列和。 
- 问题保证最终答案是唯一的。 

核心条件可以用数学方式重写。 

如果：

-`selected_sum`是所选子序列的总和
 -`total_sum`是整个数组的总和

 那么要求就变成：```
selected_sum > total_sum - selected_sum
```简化为：```
2 * selected_sum > total_sum
```所以我们的目标是选择尽可能少的数字，使它们的总和超过数组总和的一半。 

一些边缘情况很重要：

 - 仅包含一个元素的数组，其中该元素单独自动满足条件。 
- 多个大元素相等的数组。 
- 子序列和完全等于剩余和的数组，这是不够的，因为条件严格更大。 
- 数组已按升序或降序排序。 
- 有许多小数字的数组需要在超过总和的一半之前选择多个元素。 

## 方法

 ### 蛮力方法

 强力解决方案将生成数组的每个可能的子序列并测试它是否满足所需的条件。 

对于每个子序列：

 1. 计算所选元素的总和。 
2. 计算未选定元素的总和。 
3. 检查选择的总和是否严格大于。 
4. 在所有有效子序列中，选择：

 - 尺寸最小的那一个
 - 如果大小相等，则取总和最大的那个

 这种方法是正确的，因为它详尽地检查了每个可能的子序列，保证最终找到最佳答案。 

但是，数组的子序列数`n`元素是：```
2^n
```和`n = 500`，这变得天文数字般巨大并且完全不可行。 

### 最优贪心法

 关键的观察结果是所有数字都是正数。 

如果我们希望子序列超过总和的一半，同时使用尽可能少的元素，我们应该首先选择最大的可用数字。 

为什么这有效？ 

- 数字越大，子序列和的增加速度越快。 
- 使用较大的值可以最大限度地减少我们需要的元素数量。 
- 如果两个子序列的大小相同，选择较大的数字自然会产生较大的总和。 

这导致了一个简单的贪婪策略：

 1. 将数组按降序排序。 
2. 继续从最大到最小取数字。 
3. 一旦选定的总和严格大于剩余总和，就停止。 

由于数字是从最大到最小处理的，因此生成的子序列自动按非递增顺序排列。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 生成并检查所有子序列 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 降序排序并贪婪地选择最大值 |

 ## 算法演练

 1. 计算数组的总和。 

我们需要它来将子序列和与剩余元素进行比较。 由于剩余金额等于`total_sum - selected_sum`，知道总数就可以进行常量时间比较。 
2. 对数组进行降序排序。 

贪婪的洞察力是，更大的数字可以帮助我们更快地达到目标条件。 降序排序可确保我们始终首先考虑最大的可用元素。 
3.初始化：

 -`current_sum = 0`- 空结果列表`current_sum`跟踪所选子序列的总和。 
4. 迭代已排序的数组。 

对于每个数字：

 - 将其添加到结果中
 - 将其价值添加到`current_sum`5. 每次添加后，检查是否：```
current_sum > total_sum - current_sum
```如果为真，我们就找到了一个有效的子序列。 
6. 立即返回结果。 

因为我们从最大到最小处理数字：

 - 我们使用尽可能少的元素
 - 在同等大小的解决方案中，我们获得了最大可能的总和

 ### 为什么它有效

 贪心策略是最优的，因为每个数字都是正数。 选择较大的数字总是比选择较小的数字对超过总和的一半贡献更大。 

假设有一个比贪婪方法使用更少元素的更好解决方案。 这意味着较小的数字比较大的数字以某种方式更快地实现目标，而这对于严格的正值来说是不可能的。 

此外，如果两个解决方案使用相同数量的元素，则采用最大的可用数量可以保证最大的子序列和。 

因此，降序排序和贪婪选择元素会产生唯一的最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSubsequence(self, nums: List[int]) -> List[int]:
        total_sum = sum(nums)

        nums.sort(reverse=True)

        result = []
        current_sum = 0

        for num in nums:
            result.append(num)
            current_sum += num

            if current_sum > total_sum - current_sum:
                return result

        return result
```该实现首先计算数组总和。 这使得我们可以随时确定剩余金额，而无需重复重新计算。 

接下来，将数组按降序排序。 这是核心的贪婪步骤，因为我们想首先获取最大的数字。 

这`result`list 存储选择的子序列，而`current_sum`跟踪所选元素的总和。 

在迭代过程中，每个数字都会添加到子序列和运行总和中。 每次加法之后，我们都会检查所选的总和是否严格大于剩余的总和。 

当条件成立时，我们立即返回结果，因为：

 - 我们使用了尽可能少的元素
 - 所选元素是最大的可用元素
 - 子序列已经是非递增顺序

 决赛`return result`在问题保证下，技术上是不必要的，但包含它可以使功能完整且安全。 

## 解决方案```go
package main

import "sort"

func minSubsequence(nums []int) []int {
	totalSum := 0

	for _, num := range nums {
		totalSum += num
	}

	sort.Slice(nums, func(i, j int) bool {
		return nums[i] > nums[j]
	})

	result := []int{}
	currentSum := 0

	for _, num := range nums {
		result = append(result, num)
		currentSum += num

		if currentSum > totalSum-currentSum {
			return result
		}
	}

	return result
}
```Go 实现遵循与 Python 版本完全相同的贪婪策略。 

主要区别在于排序语法。 Go 使用`sort.Slice`使用自定义比较器函数按降序对数组进行排序。 

结果子序列存储在切片中。 当数字被附加时，运行总和会被更新并与剩余总和进行检查。 

整数溢出不是问题，因为约束非常小。 最大可能的总和为：```go
500 * 100 = 50000
```很容易适合 Go 的内部`int`类型。

 ## 边缘情况

 当数组仅包含单个元素时，会出现一种重要的边缘情况。 由于所有数字都是正数，因此该单个元素自动大于其余元素的总和（为零）。 该实现自然地处理这个问题，因为第一次迭代立即满足条件。 

另一个微妙的情况是当选定的总和完全等于剩余的总和时。 该问题要求所选总和严格大于，而不是大于或等于。 例如，在`[4,4,7,6,7]`，选择`[7,7]`产生总和`14`和`14`，这是无效的。 该实现正确地使用了`>`运算符而不是`>=`。 

第三个重要案例涉及许多相同的值。 对于像这样的数组`[5,5,5,5]`，选择两个元素给出`10`相对`10`，这仍然不符合条件。 该算法会继续选择值，直到不等式严格为真，即使许多值相等也能确保正确性。 

当一个值主导整个数组时，会出现另一种边缘情况，例如`[10,1,1,1]`。 在这种情况下，最优子序列仅包含一个元素。 由于该算法按降序处理数字，因此它会立即识别出这个最小解决方案。 

最后，已经按升序或降序排序的数组应该仍然可以正常工作。 由于算法在处理之前显式对数组进行排序，因此原始排序不会影响正确性。
