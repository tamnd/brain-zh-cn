 **难度：** 🔴难
 **主题：** 二分查找、动态规划、位操作、树、深度优先搜索、广度优先搜索、设计

 ## 解决方案

 ## 问题理解

 这个问题给了我们一棵有根的树`n`节点标记为`0`到`n - 1`。 输入不是以邻接列表或边的形式提供树，而是使用`parent`大批。 对于每个节点`i`,`parent[i]`告诉我们哪个节点是它的直接父节点。 根节点是`0`，并且由于根没有父级，`parent[0] = -1`。 

我们需要设计一个可以有效回答以下形式的查询的数据结构：

 > 什么是`kth`节点的祖先`node`？ 

祖先是向上向根移动时遇到的节点。 第一个祖先是父母，第二个祖先是祖父母，依此类推。 

例如，如果从一个节点向上的路径是：```
7 -> 5 -> 2 -> 0
```那么：

 - 第一个祖先是`5`- 第二个祖先是`2`- 第三个祖先是`0`- 第四祖先不存在，所以答案是`-1`约束条件极其重要：

 -`n`可以大到`5 * 10^4`- 最多还可以有`5 * 10^4`查询

 对于每个查询一次向上走一步的幼稚方法在最坏的情况下可能会变得太慢。 想象一棵链状树，其中每个节点都只有一个子节点。 单个查询可能需要遍历数万个节点。 

该问题保证输入始终形​​成以节点为根的有效树`0`。 这意味着：

 - 除根节点外的每个节点都只有一个父节点
 - 没有循环
 - 每个节点都可以从根到达

 重要的边缘情况包括：

 - 查询高于根的祖先，应该返回`-1`- 查询根节点本身，其中每个正数`k`回报`-1`- 深链状树，这是天真的遍历的最坏情况输入
 - 非常大的值`k`- 重复查询，强烈表明预处理是值得的

 ## 方法

 ### 蛮力方法

 最直接的解决方案是通过在父数组中重复向上移动来回答每个查询。 

对于查询`(node, k)`：

 1. 移动自`node`到`parent[node]`2. 减少`k`3. 继续直到：

 -`k == 0`，意味着我们找到了祖先
 - 节点变为`-1`，意味着不存在这样的祖先

 这是有效的，因为每一个向上的步骤都直接遵循祖先的定义。 

然而，这种方法对于大量输入来说效率低下。 在最坏的情况下，树可能看起来像一个长度的链表`n`。 单个查询可能需要`O(n)`时间。 由于可能有`5 * 10^4`查询，总运行时间可能会变成`O(n * q)`，这太慢了。 

### 最佳方法，二元提升

 关键的观察结果是，一次重复向上移动一个节点是一种浪费。 

我们可以预处理更大的跳转，而不是只存储每个节点的直接父节点：

 - 1步祖先
 - 2步祖先
 - 4步祖先
 - 8步祖先
 - 等等

 这种技术称为二元提升。 

这个想法来自数字的二进制表示。 任意整数`k`可以写成二的幂之和。 

例如：```
13 = 8 + 4 + 1
```因此，我们不必单独向上移动 13 次，而是可以：

 - 跳跃8个祖先
 - 然后跳4个祖先
 - 然后跳1个祖先

 这极大地减少了查询时间。 

我们预处理一个表：```
up[node][j]
```在哪里：```
up[node][j] = 2^j-th ancestor of node
```使用动态规划：```
up[node][j] = up[ up[node][j-1] ][j-1]
```这意味着：

 - 第四个祖先是第二个祖先的第二个祖先
 - 第八祖是第四祖的第四祖

 由于 2 的幂呈指数增长，因此每个查询只需要`O(log n)`跳跃。

 ## 算法演练

 ### 二进制提升预处理

 我们构建一个表，其中每个条目存储两倍距离的祖先。 

认为：```
up[node][j]
```意味着`2^j-th`的祖先`node`。 

### 步骤

 1. 计算所需的最大级别数。 

自从`n <= 5 * 10^4`，与查询相关的最大高度小于`2^16`。 

因此我们大约需要：$\log_2(5 \times 10^4) \approx 16$二进制升降台中的水平。 
2. 初始化表的第一列。 

直接父级是`2^0 = 1`祖先。 

所以：```
up[node][0] = parent[node]
```3. 使用动态规划填充表的其余部分。 

如果我们已经知道`2^(j-1)`祖先，那么`2^j`跳跃两次即可找到祖先。$up[node][j] = up[up[node][j-1]][j-1]$这是有效的，因为：```
2^j = 2^(j-1) + 2^(j-1)
```4. 使用二进制分解处理查询`k`。 

对于每一位`k`：

 - 如果该位被设置，则向上跳跃相应的2的幂
 - 继续，直到处理完所有位
 5. 如果节点变为`-1`。 

这意味着我们移到了根之上，并且不存在祖先。 

### 为什么它有效

 该算法之所以有效，是因为每个整数都可以唯一地以二进制形式表示。 

如果：```
k = b0 * 2^0 + b1 * 2^1 + b2 * 2^2 + ...
```那么`kth`可以通过组合与设置位相对应的大小的跳转来找到祖先`k`。 

预处理表保证每个`2^j`祖先查找是正确的。 由于较大的跳转是由较小的已验证跳转构建的，因此动态编程关系保持了整个表的正确性。 

## Python 解决方案```python
from typing import List

class TreeAncestor:

    def __init__(self, n: int, parent: List[int]):
        self.max_power = n.bit_length()

        # up[node][j] = 2^j-th ancestor of node
        self.up = [[-1] * self.max_power for _ in range(n)]

        # First ancestor (2^0 = 1 step)
        for node in range(n):
            self.up[node][0] = parent[node]

        # Build binary lifting table
        for j in range(1, self.max_power):
            for node in range(n):
                prev_ancestor = self.up[node][j - 1]

                if prev_ancestor != -1:
                    self.up[node][j] = self.up[prev_ancestor][j - 1]

    def getKthAncestor(self, node: int, k: int) -> int:

        bit_index = 0

        while k > 0 and node != -1:

            # If current bit is set, jump upward
            if k & 1:
                node = self.up[node][bit_index]

            k >>= 1
            bit_index += 1

        return node

# Your TreeAncestor object will be instantiated and called as such:
# obj = TreeAncestor(n, parent)
# param_1 = obj.getKthAncestor(node,k)
```实现首先计算所需的二进制提升级别的数量。 蟒蛇的`bit_length()`给出表示所需的位数`n`，对应于二的最大有用功率。 

这`up`然后将表初始化为`-1`价值观。 每一行对应一个节点，每一列对应一个跳跃大小。 

第一列存储直接父母。 之后，动态编程转换从较小的跳跃构建较大的跳跃。 

查询函数处理二进制表示`k`。 每个设置的位都意味着我们应该向上跳跃相应的 2 的幂。 由于每次跳转将剩余搜索空间减半，因此该运算是对数的。 

提前终止条件`node != -1`一旦我们移动到根之上，就可以防止无效的表查找。 

## 解决方案```go
package main

type TreeAncestor struct {
	up       [][]int
	maxPower int
}

func Constructor(n int, parent []int) TreeAncestor {

	maxPower := 0
	temp := n

	for temp > 0 {
		maxPower++
		temp >>= 1
	}

	up := make([][]int, n)

	for i := 0; i < n; i++ {
		up[i] = make([]int, maxPower)

		for j := 0; j < maxPower; j++ {
			up[i][j] = -1
		}
	}

	// First ancestor
	for node := 0; node < n; node++ {
		up[node][0] = parent[node]
	}

	// Build binary lifting table
	for j := 1; j < maxPower; j++ {
		for node := 0; node < n; node++ {

			prevAncestor := up[node][j-1]

			if prevAncestor != -1 {
				up[node][j] = up[prevAncestor][j-1]
			}
		}
	}

	return TreeAncestor{
		up:       up,
		maxPower: maxPower,
	}
}

func (this *TreeAncestor) GetKthAncestor(node int, k int) int {

	bitIndex := 0

	for k > 0 && node != -1 {

		if (k & 1) == 1 {
			node = this.up[node][bitIndex]
		}

		k >>= 1
		bitIndex++
	}

	return node
}

/**
 * Your TreeAncestor object will be instantiated and called as such:
 * obj := Constructor(n, parent);
 * param_1 := obj.GetKthAncestor(node,k);
 */
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供 Python 的直接等价物`bit_length()`，级别数是使用重复右移手动计算的。 

这`up`表使用二维切片表示。 所有条目都初始化为`-1`因为 Go 切片默认为`0`，这会错误地暗示节点`0`是一个祖先。 

查询逻辑使用与 Python 中完全相同的按位运算。

 ## 边缘情况

 一种重要的边缘情况是查询根以上的祖先。 例如，在长度为 3 的链中，询问第 10 个祖先应该返回`-1`。 如果实现在到达根后继续跳转，则很容易导致无效索引错误。 该解决方案通过在当前节点变为`-1`。 

另一个关键情况是仅包含根节点的树。 由于根没有父级，因此每个祖先查询都必须返回`-1`。 某些实现错误地假设至少存在一个有效的祖先。 在这里，二进制提升表正确地将根的祖先初始化为`-1`，因此所有查询都表现正常。 

深链状树也很重要，因为它暴露了朴素遍历的弱点。 在这样的树中，每个查询可能需要遍历数万个节点。 二进制提升通过将跳转分解为 2 的幂来完全避免这种情况，即使在最糟糕的树结构中也能保证对数查询时间。 

最后一个微妙的边缘情况涉及非常大的值`k`。 即使`k`大大超过了树的高度，该算法仍然有效，因为它只处理`k`。 一旦遍历移动到根之上，该节点就变成`-1`并且进一步的处理安全停止。
