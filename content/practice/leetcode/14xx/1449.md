 # LeetCode 1449 - 用相加达到目标的数字组成最大整数

 ## 问题理解

 这个问题要求我们构建数字上最大的可能整数，使得其数字的总绘制成本恰好等于给定的`target`。 

我们得到一个数组`cost`长度为 9。每个索引对应于一个数字`1`到`9`:

 -`cost[0]`是数字的成本`1`-`cost[1]`是数字的成本`2`- ...
 -`cost[8]`是数字的成本`9`我们可以使用任何数字任意次数，只要所选数字成本的总和等于`target`。 

关键要求是我们想要数值上最大的整数，而不一定是数字和最大的整数。 表示为字符串的整数之间的数值比较遵循两个重要规则：

 1.位数越多的数字总是越大。 
2. 如果两个数字的位数相同，则字典序较大的数字较大。 

例如：

-`"7772"`大于`"977"`因为它有 4 位数字而不是 3 位数字。 
-`"98"`大于`"89"`因为第一个不同的数字更大。 

约束条件很重要：

 -`target`最大可达 5000
 - 只有 9 个可能的数字

 这些限制强烈表明，详尽地生成所有可能的数字组合是不可行的。 相反，我们需要一个动态编程解决方案，能够有效地计算每个中间目标值的最佳可能结果。 

一些边缘情况很重要：

 - 可能不可能形成任何完全等于的数字`target`，在这种情况下我们返回`"0"`。 
- 多个数字可以具有相同的成本。 
- 贪婪地选择最大的数字并不总是有效。 
- 最大化位数比最大化单个数字值更重要。 

例如，`"11111"`大于`"99"`因为它的位数更多。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的数字序列，其成本总和为`target`。 

在每一步中，我们可以选择任意数字`1`到`9`，从剩余目标中减去其成本，并递归地继续构建数字。 每当剩余目标变为零时，我们就会将构建的数字与当前的最佳答案进行比较。 

这种方法是正确的，因为它探索了每个有效的数字组合。 最终，它会找到最佳答案。 

然而，搜索空间呈指数增长。 由于我们可以任意重复使用数字，因此对于 5000 这样的大型目标，可能的组合数量会变得巨大。即使进行剪枝，这种方法也太慢了。 

### 最优动态规划方法

 关键的观察是，这本质上是一个无界背包问题。 

对于每个目标值`0`到`target`，我们想知道：

 - 用这个成本我们能形成的最佳数字是多少？ 

我们首先优化位数，而不是立即存储实际字符串。 

为什么？ 

因为任何位数较多的数字总是比位数较少的数字大。 

所以我们定义：

 -`dp[t] = maximum number of digits possible using total cost t`一旦我们知道了最大可能的位数，我们就会贪婪地重建实际的最大数字。 

重建期间：

 - 我们尝试来自的数字`9`下降到`1`- 我们选择仍然允许最佳解决方案的最大数字

 这保证了词典编排的最大性，同时保留了最佳的位数。

 ## 算法演练

 1.创建一个大小为DP的数组`target + 1`。 

我们定义`dp[t]`作为总成本可以形成的最大位数`t`。 

初始化：

 -`dp[0] = 0`，因为零成本形成零数字
 - 所有其他条目都变为负无穷大，代表不可能的状态
 2. 迭代所有目标值`1`到`target`。 

对于每个目标值`t`，尝试每个数字`1`到`9`。 

如果该数字的成本小于或等于`t`，并且之前的状态有效，更新：```
dp[t] = max(dp[t], dp[t - digit_cost] + 1)
```这一转变意味着：

 - 建立最佳的成本数字`t - digit_cost`- 添加一位数字
 3.填写完DP表后，检查`dp[target]`。 

如果为负数，则不存在有效数字，因此返回`"0"`。 
4. 重构实际最大数。 

我们现在知道可能的最大位数。 

从数字开始`9`下降到`1`。 

对于每个数字：

 - 设其成本为`c`- 检查选择该数字是否保持最优性：```
dp[current_target] == dp[current_target - c] + 1
```如果为真：

 - 将此数字附加到答案中
 - 将目标降低`c`- 继续
 5. 继续，直到剩余目标变为零。 

由于我们总是首先尝试更大的数字，同时保留最佳数字计数，因此构造的数字是字典顺序上最大的有效答案。 

### 为什么它有效

 DP 阶段保证`dp[t]`存储每个目标成本的最大可能位数`t`。 

位数较多的数字在数值上总是大于位数较少的数字，因此最大化位数可以保证最高的量值。 

在重建过程中，我们贪婪地选择仍然保留最佳位数的最大数字。 由于字典顺序决定了等长数字中较大的数字，因此这会产生全局最大的有效整数。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestNumber(self, cost: List[int], target: int) -> str:
        dp = [-10**9] * (target + 1)
        dp[0] = 0

        # Build DP table
        for current_target in range(1, target + 1):
            for digit in range(1, 10):
                digit_cost = cost[digit - 1]

                if current_target >= digit_cost:
                    dp[current_target] = max(
                        dp[current_target],
                        dp[current_target - digit_cost] + 1
                    )

        # Impossible case
        if dp[target] < 0:
            return "0"

        # Reconstruct largest number
        result = []
        remaining_target = target

        for digit in range(9, 0, -1):
            digit_cost = cost[digit - 1]

            while (
                remaining_target >= digit_cost
                and dp[remaining_target] ==
                dp[remaining_target - digit_cost] + 1
            ):
                result.append(str(digit))
                remaining_target -= digit_cost

        return "".join(result)
```实现首先初始化 DP 数组。 不可能的状态用一个非常负的数来表示，因此它们永远不会意外地变成最佳状态。 

嵌套循环填充 DP 表。 对于每个可能的目标成本，我们尝试将每个数字相加。 由于数字可以无限次地重复使用，因此这是无界背包转换。 

计算完 DP 表后，我们检查是否`target`是可达的。 如果没有，我们立即返回`"0"`。 

重建阶段是贪婪的。 我们从数字开始迭代`9`下降到`1`，因为较大的数字应尽可能较早出现。 

临界条件：```python
dp[remaining_target] == dp[remaining_target - digit_cost] + 1
```确保选择数字仍然可以让我们保持最佳的位数。 

最后，我们将所有选定的数字连接到最终的字符串中。 

## 解决方案```go
package main

import "strings"

func largestNumber(cost []int, target int) string {
	dp := make([]int, target+1)

	for i := 1; i <= target; i++ {
		dp[i] = -1000000000
	}

	dp[0] = 0

	// Build DP table
	for currentTarget := 1; currentTarget <= target; currentTarget++ {
		for digit := 1; digit <= 9; digit++ {
			digitCost := cost[digit-1]

			if currentTarget >= digitCost {
				candidate := dp[currentTarget-digitCost] + 1

				if candidate > dp[currentTarget] {
					dp[currentTarget] = candidate
				}
			}
		}
	}

	// Impossible case
	if dp[target] < 0 {
		return "0"
	}

	// Reconstruct answer
	var builder strings.Builder
	remainingTarget := target

	for digit := 9; digit >= 1; digit-- {
		digitCost := cost[digit-1]

		for remainingTarget >= digitCost &&
			dp[remainingTarget] == dp[remainingTarget-digitCost]+1 {

			builder.WriteByte(byte('0' + digit))
			remainingTarget -= digitCost
		}
	}

	return builder.String()
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个重要的区别是字符串结构。 由于 Go 字符串是不可变的，因此重复连接字符串效率很低。 反而，`strings.Builder`用于高效的增量建设。 

DP数组被初始化为一个大的负数来表示不可能的状态，类似于Python的实现。 

Go 还需要显式的手动最大比较，而不是使用 Python 的内置`max()`功能。

 ## 边缘情况

 当不存在有效组合时，就会出现一种重要的边缘情况。 例如，如果所有数字成本都大于目标，或者如果目标不能由任何成本组合形成，则该目标的 DP 条目仍然无效。 幼稚的实现可能会意外构造空字符串或在重建过程中崩溃。 此实现显式检查`dp[target] < 0`并返回`"0"`立即地。 

当多个数字共享相同的成本时，会出现另一种微妙的边缘情况。 在这种情况下，我们必须选择较大的数字来最大化字典顺序。 在重建过程中，迭代自`9`下降到`1`保证当存在多个最优解时，首先选择较大的数字。 

第三个重要的边缘情况涉及数字计数和数字值之间的区别。 许多贪婪的解决方案错误地尝试首先最大化大数字。 然而，较长的数字总是比较短的数字大。 例如，`"11111"`大于`"99"`。 在考虑字典顺序之前，DP 公式正确地优先考虑了最大化位数。 

当答案变得非常大时，就会出现第四种边缘情况。 自从`target`可以达到5000，得到的数字可能包含数千位数字。 将此类值转换为整数会溢出标准数字类型。 以字符串形式返回答案可以完全避免溢出问题并符合问题要求。
