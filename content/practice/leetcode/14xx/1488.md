[LeetCode 问题 1488](https://leetcode.com/problems/avoid-flood-in-the-city/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、二分查找、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题要求我们模拟一系列湖泊的降雨并防止洪水。 每一天都由一个整数表示`rains`大批。 如果`rains[i] > 0`, 意思是湖`rains[i]`受雨而饱。 如果已经满了，就会发生洪水，这是我们必须避免的。 如果`rains[i] == 0`，那天阳光明媚，我们可以选择干燥我们选择的一个湖泊。 目标是返回一个数组`ans`代表日常行动：`-1`下雨天，晴天把湖水晒干。 如果无法避免洪水，我们返回一个空数组。 

要点是：

 - 湖泊编号最多为 10^9，因此我们不能使用按湖泊编号索引的固定大小数组。 相反，我们需要一个哈希图来跟踪完整的湖泊。 
- 必须有策略地利用晴天来干燥未来会降雨的湖泊，以避免洪水泛滥。 
- 可能存在多个有效输出，因为该问题允许任何无溢流干燥序列。 
- 输入大小最多可达 10^5 天，因此简单的方法会太慢。 

重要的边缘情况包括同一湖泊连续下雨而中间没有旱天、连续多个晴天以及湖泊干涸后再也不会填满。 

## 方法

 暴力方法将模拟每一天，并在阳光明媚的日子里，尝试使所有可能的湖泊变干，以防止未来发生洪水。 在下雨天，我们会检查所有当前已满的湖泊，看看下一场雨是否会导致洪水泛滥。 这在逻辑上是正确的，但对于每个阳光明媚的日子，我们可能需要搜索所有完整的湖泊，这使得大输入量的速度变得非常慢。 复杂度至少为 O(n^2)，这对于 n = 10^5 来说是不可行的。 

最佳方法使用两个关键观察结果。 首先，我们只需要在湖水满了的时候将其再次下雨的湖泊干掉即可。 其次，我们可以使用哈希图跟踪每个湖泊的下一个雨天，并安排在下一次雨之前最早的晴天进行干燥。 这可以通过完整湖的哈希图和排序数据结构（如`SortedList`在 Python 或最小堆中），适合阳光明媚的日子。 这样，对于每次降雨，我们都可以快速找到最近的晴天，在湖水泛滥之前将其晒干。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 尝试在阳光明媚的日子里干燥所有可能的湖泊，但对于大量投入来说速度太慢 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用哈希图和排序集/最小堆有效地分配下一次雨前的干燥天数 |

 ## 算法演练

 1. 初始化哈希图`full_lakes`追踪湖水被填满的最后一天。 
2. 初始化排序列表或最小堆`dry_days`跟踪可用于干燥的晴天指数。 
3.初始化一个数组`ans`长度`n`使用默认值`1`晴天（可以覆盖）和`-1`下雨天。 
4. 迭代`rains`按索引和值排列。 
5.如果`rains[i] > 0`（雨天）：

 - 检查湖是否已经满了`full_lakes`。 如果是的话，搜索一下`dry_days`最后一次填水后的一个阳光明媚的日子，使这个湖干涸。 
- 如果不存在这样的晴天，则返回`[]`因为洪水是不可避免的。 
- 否则，指定一个阳光明媚的日子来干这个湖`ans`并从中删除这一天`dry_days`。 
- 更新`full_lakes[lake] = i`。 
6. 如果`rains[i] == 0`（晴天）：

 - 添加当前索引`i`到`dry_days`作为稍后干涸一些湖泊的可用日期。 
7、迭代后，所有下雨天都是`-1`晴天要么指定为干湖，要么可以保持任意（例如，`1`）。 
8. 返回`ans`。 

**为什么有效**：通过始终在再次下雨之前最早的晴天干燥湖泊，我们可以确保湖泊不会发生洪水。 排序集/最小堆确保有效检索正确的日期。 

## Python 解决方案```python
from typing import List
import bisect

class Solution:
    def avoidFlood(self, rains: List[int]) -> List[int]:
        full_lakes = {}
        dry_days = []
        ans = [-1 if rain > 0 else 1 for rain in rains]
        
        for i, lake in enumerate(rains):
            if lake > 0:
                if lake in full_lakes:
                    idx = bisect.bisect_right(dry_days, full_lakes[lake])
                    if idx == len(dry_days):
                        return []
                    dry_day_index = dry_days.pop(idx)
                    ans[dry_day_index] = lake
                full_lakes[lake] = i
            else:
                dry_days.append(i)
        
        return ans
```**解释**：我们初始化`full_lakes`记住每个湖都被填满的最后一天。 在阳光明媚的日子里，我们追踪它们`dry_days`。 当雨落在满湖时，我们使用二分搜索`dry_days`找到最后一个填水日以干涸湖面之后最早的可用晴天。 如果不存在，洪水是不可避免的。 否则，我们会安排那个阳光明媚的日子让湖水干涸。 

## 解决方案```go
package main

import (
	"sort"
)

func avoidFlood(rains []int) []int {
	n := len(rains)
	ans := make([]int, n)
	for i, rain := range rains {
		if rain == 0 {
			ans[i] = 1
		} else {
			ans[i] = -1
		}
	}

	fullLakes := make(map[int]int)
	var dryDays []int

	for i, lake := range rains {
		if lake > 0 {
			if lastDay, ok := fullLakes[lake]; ok {
				idx := sort.Search(len(dryDays), func(j int) bool { return dryDays[j] > lastDay })
				if idx == len(dryDays) {
					return []int{}
				}
				dryDayIndex := dryDays[idx]
				ans[dryDayIndex] = lake
				dryDays = append(dryDays[:idx], dryDays[idx+1:]...)
			}
			fullLakes[lake] = i
		} else {
			dryDays = append(dryDays, i)
		}
	}

	return ans
}
```**Go 特定注释**：由于 Go 没有带有二分搜索插入的内置排序列表，因此我们维护`dryDays`作为切片并使用`sort.Search`找到合适的索引。 移除一个元素需要slice切片。 

## 工作示例

 **示例2：`rains = [1,2,0,0,2,1]`**

 | 日 | 下雨[i] | 全湖 | 干燥天 | 回答 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | {1:0} | []| -1 |
 | 1 | 2 | {1:0, 2:1} | []| -1 |
 | 2 | 0 | {1:0, 2:1} | [2] | 1（默认1）|
 | 3 | 0 | {1:0, 2:1} | [2,3]| 1（默认1）|
 | 4 | 2 | {1:0, 2:4} | [3] | 将第 2 天分配给干涸的湖泊 2 → ans[2]=2 |
 | 5 | 1 | {1:5,2:4} | [3] | 将第 3 天分配给干涸的湖泊 1 → ans[3]=1 |

 最终输出：`[-1,-1,2,1,-1,-1]`## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 每个下雨天都可能触发二分查找`dry_days`长度 ≤ n |
 | 空间| O(n) |`full_lakes`哈希映射和`dry_days`列表最多存储 n 个元素 |

 该算法非常高效，因为每次下雨每个湖泊仅跟踪一次，并且每个晴天最多使用一次。
