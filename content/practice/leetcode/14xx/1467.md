[LeetCode 问题 1467](https://leetcode.com/problems/probability-of-a-two-boxes-having-the-same-number-of-distinct-balls/)

 **难度：** 🔴难
 **主题：** 数组、数学、动态规划、回溯、组合学、概率和统计

 ## 解决方案

 ## 问题理解

 这个问题给了我们几种颜色的球，其中`balls[i]`代表颜色存在多少个球`i`。 球的总数总是偶数，比如说`2n`。 我们随机洗牌所有球并放置第一个`n`将球放入盒子 1 中，其余的`n`将球放入方框 2。 

我们必须计算两个盒子最终包含相同数量的不同颜色的概率。 

不同的颜色意味着盒子中至少出现一个该颜色的球。 例如，如果一个盒子包含`[red, red, blue]`，那么它包含`2`不同的颜色。 

重要的细节是所有有效的洗牌可能性均等。 由于盒子是有序的，交换两个盒子的内容会产生不同的结果。 

限制很小：

 -`balls.length <= 8`-`balls[i] <= 6`这立即表明，如果仔细优化，指数或组合枚举可能是可行的。 最大球总数为：```
8 * 6 = 48
```由于颜色数量最多为`8`，颜色的回溯解决方案变得实用。 

主要的挑战不是生成球的所有物理排列，因为那将是一个天文数字。 相反，我们必须组合地计算分布。 

一些边缘情况很重要：

 - 所有颜色只出现一次，例如`[1,1,1,1]`。 每个平衡分割都会自动给出相等的不同计数。 
- 一种颜色占主导地位，例如`[6,1,1]`。 许多分裂变得不可能或不平等。 
- 递归期间颜色可能全部进入一个框中，这会影响不同颜色的计数。 
- 我们必须使用组合正确计算多重性，因为多个物理排列对应于相同的颜色分配。 

## 方法

 ### 蛮力方法

 暴力解决方案将明确生成所有可能的选择方式`n`球出`2n`第一个盒子的总球数。 剩余的球自动进入第二个盒子。 

对于每个发行版：

 1. 计算方框 1 中出现了多少种不同的颜色。 
2. 计算方框 2 中出现了多少种不同的颜色。 
3. 如果计数相等，则增加有利计数。 
4. 将有利结果除以总结果。 

这是有效的，因为每个同等大小的分割都对应于有效的洗牌结果。 

然而，组合总数增长得非常快：```
C(48, 24)
```这太大了，无法直接枚举。 

此外，构建明确的球列表并重复检查每个分布将是极其低效的。 

### 关键见解

 关键的观察是我们不关心盒子内球的顺序。 我们只关心：

 - 每种颜色有多少个球进入盒子 1
 - 有多少进入方框 2
 - 每个盒子包含多少种不同的颜色

 我们可以枚举每种颜色如何在两个盒子之间分配，而不是枚举单个球。 

对于每种颜色`balls[i]`球，我们决定：```
x balls -> box 1
balls[i] - x balls -> box 2
```这会创建一个更小的状态空间。 

对于每个分割，我们使用组合计算它代表了多少个实际排列：```
C(balls[i], x)
```将这些颜色相乘即可得到与该分割相对应的物理配置的数量。 

这将问题转化为组合回溯问题。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(C(2n, n)) | O(C(2n, n)) | O(n) | 枚举球的每种可能的平衡分布 |
 | 最佳 | O(积(球[i] + 1)) | O(k) | 枚举颜色分割而不是物理排列 |

 ## 算法演练

 ### 第 1 步：计算每个盒子的球总数

 球的总数为：```
total = sum(balls)
```每个盒子必须包含：```
half = total // 2
```这成为递归期间的硬约束。 

### 步骤 2：预先计算组合值

 我们反复需要这样的值：```
C(n, r)
```这些计算了我们可以选择将某种颜色的球放入方框 1 的方式有多少种。 

我们使用Python的`math.comb()`或预先计算的帕斯卡三角形。 

### 步骤 3：回溯颜色

 我们将颜色一一处理。 

对于颜色`i`，假设它有`balls[i] = c`。 

我们尝试每一种可能的分割：```
0 -> box1, c -> box2
1 -> box1, c-1 -> box2
2 -> box1, c-2 -> box2
...
c -> box1, 0 -> box2
```对于每个分组，我们跟踪：

 - 方框 1 中的当前球数
 - 方框 2 中的当前球数
 - 盒子 1 中的颜色不同
 - 盒子 2 中的颜色不同
 - 组合方式的数量

 ### 步骤 4：追踪不同的颜色

 如果`x > 0`，然后框 1 获得这种颜色。 

如果`c - x > 0`，然后方框 2 获得这种颜色。 

我们相应地增加不同的计数。 

### 第 5 步：跟踪路线数量

 对于拆分选择`x`球进入盒子 1：```
ways *= C(c, x)
```这会计算有多少物理分配对应于该颜色分割。 

### 步骤 6：修剪无效状态

 如果任一框超过`half`球，状态无效。 

我们提前停止递归。 

### 步骤 7：评估完整分布

 处理完所有颜色后：

 - 两个盒子必须准确包含`half`球
 - 如果不同的计数匹配，则添加有利的方式数量
 - 始终将方式数量添加到总数中

 ### 步骤 8：返回概率

 最后：```
probability = favorable / total
```### 为什么它有效

 每个有效的物理排列都唯一对应于两个盒子之间每种颜色的特定划分。 递归将所有此类拆分仅枚举一次。 

组合乘数：```
C(c, x)
```正确计算有多少物理分配产生了该分裂。 

因为我们按照精确的重数加权计算有利的概率和总的概率，所以得到的比率就是真实的概率。 

## Python 解决方案```python
from typing import List
from math import comb

class Solution:
    def getProbability(self, balls: List[int]) -> float:
        total_balls = sum(balls)
        half = total_balls // 2

        favorable = 0
        total = 0

        def backtrack(
            index: int,
            box1_count: int,
            box2_count: int,
            distinct1: int,
            distinct2: int,
            ways: int
        ) -> None:
            nonlocal favorable, total

            if box1_count > half or box2_count > half:
                return

            if index == len(balls):
                if box1_count == half and box2_count == half:
                    total += ways

                    if distinct1 == distinct2:
                        favorable += ways
                return

            current = balls[index]

            for take in range(current + 1):
                new_box1 = box1_count + take
                new_box2 = box2_count + (current - take)

                new_distinct1 = distinct1 + (1 if take > 0 else 0)
                new_distinct2 = distinct2 + (1 if current - take > 0 else 0)

                new_ways = ways * comb(current, take)

                backtrack(
                    index + 1,
                    new_box1,
                    new_box2,
                    new_distinct1,
                    new_distinct2,
                    new_ways
                )

        backtrack(0, 0, 0, 0, 0, 1)

        return favorable / total
```该实现遵循前面描述的递归组合枚举。 

递归函数一次处理一种颜色。 对于每种颜色，它会尝试所有可能数量的球进入框 1。剩余的球会自动进入框 2。 

变量`distinct1`和`distinct2`跟踪每个框中当前出现的独特颜色数量。 

变量`ways`存储有多少个物理排列对应于当前的部分分布。 每次分割都会将该值乘以：```python
comb(current, take)
```它计算特定分裂可以发生的方式。 

当递归到达末尾时，代码检查：

 1. 两个盒子正好包含一半的球
 2. 不同颜色数是否相等

 如果这两个条件都成立，则该配置有助于有利计数。 

最后，概率计算如下：```python
favorable / total
```## 解决方案```go
package main

import "math"

func comb(n, r int) float64 {
	if r > n-r {
		r = n - r
	}

	result := 1.0

	for i := 1; i <= r; i++ {
		result *= float64(n-r+i)
		result /= float64(i)
	}

	return result
}

func getProbability(balls []int) float64 {
	totalBalls := 0

	for _, x := range balls {
		totalBalls += x
	}

	half := totalBalls / 2

	var favorable float64
	var total float64

	var backtrack func(
		index int,
		box1Count int,
		box2Count int,
		distinct1 int,
		distinct2 int,
		ways float64,
	)

	backtrack = func(
		index int,
		box1Count int,
		box2Count int,
		distinct1 int,
		distinct2 int,
		ways float64,
	) {
		if box1Count > half || box2Count > half {
			return
		}

		if index == len(balls) {
			if box1Count == half && box2Count == half {
				total += ways

				if distinct1 == distinct2 {
					favorable += ways
				}
			}
			return
		}

		current := balls[index]

		for take := 0; take <= current; take++ {
			newBox1 := box1Count + take
			newBox2 := box2Count + (current - take)

			newDistinct1 := distinct1
			newDistinct2 := distinct2

			if take > 0 {
				newDistinct1++
			}

			if current-take > 0 {
				newDistinct2++
			}

			newWays := ways * comb(current, take)

			backtrack(
				index+1,
				newBox1,
				newBox2,
				newDistinct1,
				newDistinct2,
				newWays,
			)
		}
	}

	backtrack(0, 0, 0, 0, 0, 1.0)

	return favorable / total
}
```Go 实现密切反映了 Python 逻辑。 

由于 Go 没有像 Python 那样提供内置的组合函数`math.comb`，我们使用乘法计算手动实现辅助函数。 

递归使用`float64`用于避免整数溢出并简化最后除法的计数方法。 

Go 切片通过引用语义高效传递，因此无需特殊优化`balls`大批。

 ## 边缘情况

 当每种颜色只出现一次时，就会出现一个重要的边缘情况，例如`[1,1,1,1]`。 在这种情况下，每个有效的平衡分割都会自动在两个框中产生相同数量的不同颜色。 幼稚的实现可能会使计数过于复杂或对称性处理不当。 该解决方案可以自然地处理它，因为每种颜色都会为一个盒子或另一个盒子贡献一个不同的计数。 

另一个重要的情况是当一种颜色占主导地位时，例如`[6,1,1]`。 许多分布将大多数主颜色的球放入一个盒子中，这很容易产生不相等的不同颜色计数。 不正确的修剪逻辑可能会意外丢弃有效状态。 仅当框大小超过所需的一半大小时，该实现才会进行修剪，因此所有合法的分布都会被保留。 

第三种棘手的情况涉及完全分配给一个盒子的颜色。 例如，分割可能会将所有颜色的球放入框 1 中，而不会将任何球放入框 2 中。某些实现会错误地增加两个框中的不同计数。 该解决方案仔细检查：```
take > 0
```和```
current - take > 0
```在增加不同颜色数量之前，确保准确性。 

最后一个微妙的问题是组合多重性。 不同的物理洗牌可以对应于相同的颜色分割。 如果我们平等地计算每个分割，概率将是不正确的。 乘以：```
comb(current, take)
```根据产生分割的物理排列数量，正确地对每个分割进行加权。
