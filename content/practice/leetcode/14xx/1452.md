[LeetCode 问题 1452](https://leetcode.com/problems/people-whose-list-of-favorite-companies-is-not-a-subset-of-another-list/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题需要识别一组中最喜欢的公司列表**不是任何其他人的列表的子集**的所有人。 每个人都有一个他们喜欢的公司列表，我们希望其列表中的人员索引是唯一的，因为没有其他列表完全包含他们的列表。 

输入是一个二维数组`favoriteCompanies`， 在哪里`favoriteCompanies[i]`是公司人员名单`i`喜欢。 输出是一个排序后的索引列表，这些人的列表没有完全包含在其他人的列表中。 

约束条件为投入的规模和结构提供了重要指导：人数（`favoriteCompanies.length`) 最多 100 个，每个人的列表最多可以包含 500 个公司。 每个字符串都是不同的并且是小写的。 重要的是，列表本身都是不同的，因此我们不必担心重复的列表。 

可能导致幼稚实现失败的边缘情况包括空列表（尽管约束保证每个列表至少有一个公司）、具有单个元素的列表或作为多个其他列表的子集的列表。 这些保证可以防止重复和空字符串，从而简化处理。 

## 方法

 ### 蛮力

 暴力方法会检查每对列表`(i, j)`看看是否`favoriteCompanies[i]`是一个子集`favoriteCompanies[j]`。 这需要迭代中的每个元素`i`并检查成员资格`j`，这可以使用列表来完成，但速度很慢。 为了`n`人，最多`m`每人的公司，这是`O(n^2 * m)`时间复杂度。 它之所以有效，是因为它直接测试每对的子集属性，但效率低下，因为许多成员资格检查都是重复的。 

### 最佳方法

 关键的见解是**使用集合检查子集成员身份会更快**。 通过将每个人的公司列表转换为一个集合，我们可以检查子集成员资格`O(1)`每个元素的平均时间。 然后，我们迭代所有对`(i, j)`并检查是否`i`是一个子集`j`。 如果没有`j`完全包含`i`，我们包括`i`在答案中。 

这种方法很简单，利用 Python（或 Go）的集合操作进行快速子集检查，并避免手动迭代列表进行成员资格测试。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2 * m) | O(n^2 * m) | O(1) | O(1) | 使用列表成员资格直接检查子集 |
 | 最佳| O(n^2 * m) | O(n^2 * m) | O(n * m) | 使用集合来加速子集检查，相同的渐近时间但在实践中更快 |

 ## 算法演练

 1. 将每个人最喜欢的公司列表转换为一组。 这允许持续时间的成员资格检查。 
2.初始化一个空列表`result`存储列表不是子集的人员的索引。 
3. 对于每个人`i`，假设他们的列表不是子集（`is_subset = False`）。 
4. 比较`i`与其他人的设置相同`j`。 跳过如果`i == j`。 
5. 如果`i`的集合是`j`已设置，标记`is_subset = True`并跳出内循环。 
6. 检查所有其他组后，如果`is_subset`遗迹`False`, 附加`i`到`result`。 
7.返回排序后的结果`result`。 

**为什么有效：** 该算法会根据所有其他列表系统地检查子集属性。 由于我们标记并排除作为任何其他列表的子集的列表，因此最终结果仅包含列表在这个意义上是唯一的索引。 集合的使用保证了子集检查的正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def peopleIndexes(self, favoriteCompanies: List[List[str]]) -> List[int]:
        company_sets = [set(companies) for companies in favoriteCompanies]
        result = []
        
        for i, comp_set_i in enumerate(company_sets):
            is_subset = False
            for j, comp_set_j in enumerate(company_sets):
                if i != j and comp_set_i.issubset(comp_set_j):
                    is_subset = True
                    break
            if not is_subset:
                result.append(i)
                
        return result
```**说明：** 我们首先将所有列表转换为集合以进行快速子集检查。 然后，对于每个人，我们将他们的集合与所有其他集合进行比较。 如果当前人员的集合不是任何其他集合的子集，我们将他们的索引添加到`result`。 使用`issubset`确保正确性和可读性。 

## 解决方案```go
func peopleIndexes(favoriteCompanies [][]string) []int {
    n := len(favoriteCompanies)
    companySets := make([]map[string]struct{}, n)
    for i := 0; i < n; i++ {
        companySets[i] = make(map[string]struct{})
        for _, company := range favoriteCompanies[i] {
            companySets[i][company] = struct{}{}
        }
    }

    result := []int{}
    for i := 0; i < n; i++ {
        isSubset := false
        for j := 0; j < n; j++ {
            if i == j {
                continue
            }
            subset := true
            for company := range companySets[i] {
                if _, exists := companySets[j][company]; !exists {
                    subset = false
                    break
                }
            }
            if subset {
                isSubset = true
                break
            }
        }
        if !isSubset {
            result = append(result, i)
        }
    }

    return result
}
```**Go 特定说明：** Go 使用映射来模拟集合，因此子集检查需要迭代`companySets[i]`。 空结构用于节省内存。 否则，逻辑与 Python 类似。 

## 工作示例

 **示例1**

 输入：`[["leetcode","google","facebook"],["google","microsoft"],["google","facebook"],["google"],["amazon"]]`- 将每个列表转换为一组。 
- 0人组：`{leetcode, google, facebook}`- 不是其他任何人的子集。 
- 1人组：`{google, microsoft}`- 不是其他任何人的子集。 
- 2人组：`{google, facebook}`- 人 0 的子集 → 跳过。 
- 3人组：`{google}`- 人 0 和 1 的子集 → 跳过。 
- 4人组：`{amazon}`- 不是其他任何人的子集。 

输出：`[0,1,4]`## 复杂度分析

 ## 边缘情况

 一种极端情况是所有列表中都只有一家公司。 每个公司都是不同的，所以每个人都会留在结果中。 另一种是子集链，例如`[["a"], ["a","b"], ["a","b","c"]]`，仅保留最大的集合； 该算法正确地检查所有其他列表并过滤掉子集。 最后一种边缘情况是多个列表可能是多个其他列表的子集； 该算法在第一个检测到的超集处停止并正确避免冗余检查。 不同列表和非空元素的保证可以防止索引错误或重复处理。
