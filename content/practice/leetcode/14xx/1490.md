 # LeetCode 1490 - 克隆 N 叉树

 ## 问题理解

 这个问题要求我们创建一个 N 叉树的深层副本。 N 叉树是每个节点可以有零个或多个子节点的树，与限制每个节点最多有两个子节点的二叉树不同。 

每个节点包含两个字段：

 -`val`, 节点中存储的整数值
 -`children`，包含对子节点的引用的列表

 深层复制意味着克隆的树必须完全由新创建的节点组成。 复制的树中的任何节点都不能引用原始树中的节点。 但是，克隆树的结构和值必须与原始树完全匹配。 

输入是原始N叉树的根节点。 预期的输出是完全独立的克隆树的根节点。 

例如，如果原始树包含一个值为`3`和孩子们`5`和`6`，那么克隆的树还必须包含一个具有值的新节点`3`连接到具有值的新节点`5`和`6`。 克隆节点不得与原始节点共享内存引用。 

约束条件很重要：

 - 树深度可以大到1000
 - 节点总数最多可达10,000个

 这些约束告诉我们解决方案必须是有效的。 指数或重复复制方法会太慢。 由于每个节点必须在克隆树中恰好出现一次，因此最佳解决方案应该理想地处理每个节点一次。 

有几个重要的边缘情况：

 - 输入树可能为空，意味着`root == None`- 一个节点可能有零个子节点
 - 树可能很深，这会强调递归解决方案
 - 树可能很宽，这意味着节点可以包含许多子节点

 该问题保证输入是有效的树，而不是带有循环的图。 这简化了克隆过程，因为我们不需要对此版本的问题进行循环检测。 

## 方法

 ### 蛮力方法

 一种幼稚的方法会尝试逐级重建树，同时重复遍历原始树的某些部分以重建子关系。 例如，我们可以将树序列化为中间表示，然后将其反序列化为新树。 

这是可行的，因为序列化保留了树的结构和值。 然而，这会带来不必要的开销。 我们将多次遍历树，为序列化表示分配额外的存储空间，并执行重建节点的冗余工作。 

此外，N 叉树的序列化逻辑可能会变得很麻烦，因为必须正确保留子边界。 

尽管这种方法最终产生了正确的克隆树，但它效率低下并且不必要地复杂。 

### 最佳方法

 关键的见解是克隆树自然地与递归遍历相匹配。 

对于原始树中的每个节点：

 1.新建一个相同值的节点
 2. 递归克隆每个孩子
 3. 将克隆的子节点附加到新节点

 这是可行的，因为树是递归数据结构。 每个子树本身就是一棵 N 叉树。 如果我们能够正确克隆以节点为根的子树，那么递归克隆整个结构就会变得简单。 

深度优先搜索特别适合这里，因为：

 - 我们只访问每个节点一次
 - 我们在穿越时立即构建克隆结构
 - 亲子关系通过递归自然保留

 由于输入保证是没有循环的树，因此我们不需要访问集或哈希图来解决此问题。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 到 O(n²) | O(n) | 序列化和重构引入了不必要的开销 |
 | 最佳 DFS 克隆 | O(n) | O(h) | 只访问每个节点一次，其中 h 是树高 |

 ## 算法演练

 1、检查root是否为`None`。 

如果树是空的，则没有任何可克隆的内容，因此返回`None`。 
2. 为当前根创建一个新节点。 

克隆节点应包含与原始节点相同的值。 在此阶段，克隆的节点有一个空的子节点列表。 
3. 遍历当前节点的每个子节点。 

由于子级本身是较小子树的根，因此递归克隆每个子级子树。 
4. 将克隆的子节点追加到新节点。 

递归克隆子节点后，将克隆的子节点添加到克隆的父节点中`children`列表。 
5. 返回克隆的节点。 

一旦处理完所有子节点，克隆的子树就完成了。 
6. 递归调用继续进行，直到树中的每个节点都被克隆为止。 

### 为什么它有效

 该算法之所以有效，是因为树上的结构递归。 

对于每个原始节点，我们精确地创建一个对应的克隆节点。 递归步骤保证每个子子树在附加到克隆的父树之前也被完全克隆。 

由于树不包含循环，因此递归最终在叶节点处终止。 父子关系之所以得以准确保留，是因为克隆的子项按照与原始子项相同的顺序附加。 

因此，生成的树在结构上与原始树相同，同时包含完全独立的节点对象。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, val: Optional[int] = None, children: Optional[List['Node']] = None):
        self.val = val
        self.children = children if children is not None else []
"""

class Solution:
    def cloneTree(self, root: 'Node') -> 'Node':
        if root is None:
            return None

        cloned_root = Node(root.val)

        for child in root.children:
            cloned_child = self.cloneTree(child)
            cloned_root.children.append(cloned_child)

        return cloned_root
```实现首先处理空树的情况。 如果`root`是`None`，函数立即返回`None`。 

接下来，使用当前节点的值创建一个新节点。 这确保了克隆节点完全独立于原始节点。 

然后该函数迭代原始节点中的每个子节点`children`列表。 通过调用递归地克隆每个子子树`cloneTree(child)`。 

返回的克隆子节点将附加到克隆节点的子节点列表中。 这保留了子级的结构和顺序。 

最后，将完全构造好的克隆节点通过递归栈向上返回。 

由于算法的递归结构直接反映了树本身的递归结构，因此实现很简洁。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Children []*Node
 * }
 */

func cloneTree(root *Node) *Node {
	if root == nil {
		return nil
	}

	clonedRoot := &Node{
		Val:      root.Val,
		Children: []*Node{},
	}

	for _, child := range root.Children {
		clonedChild := cloneTree(child)
		clonedRoot.Children = append(clonedRoot.Children, clonedChild)
	}

	return clonedRoot
}
```Go 实现遵循与 Python 解决方案相同的递归结构。 

主要区别在于显式指针处理。 节点使用以下方式表示为指针`*Node`，并且新节点被分配`&Node{}`。 

这`Children`字段初始化为空切片，以允许安全地附加克隆的子节点。 

Go不像Python的递归限制那样有递归深度保护，但深度最多1000的问题约束一般是可以管理的。 

由于 Go 切片会动态调整大小，因此附加克隆的子切片既简单又高效。

### 递归克隆流程

 | 节点| 儿童 |
 | --- | --- |
 | 1 | 2、3、4、5 |
 | 3 | 6, 7 |
 | 7 | 11 | 11
 | 4 | 8 |
 | 5 | 9, 10 |
 | 9 | 12 | 12
 | 10 | 10 13 |
 | 13 | 14 | 14

 该算法递归地克隆每个子树：

 1.克隆节点1
 2.克隆孩子2、3、4、5
 3. 在克隆 3 的同时，递归克隆 6 和 7
 4. 在克隆 7 的同时，递归克隆 11
 5. 对所有剩余的子树继续递归

 由于每个子树在附加之前都是独立克隆的，因此最终的结构与原始结构完全匹配。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用栈最多存储树高 h |

 时间复杂度是线性的，因为该算法对每个节点执行恒定的工作。 每个节点都被克隆一次，每条边都被遍历一次。 

空间复杂度来自递归深度。 在完全倾斜的树的最坏情况下，递归堆栈可以增长到`O(n)`。 在平衡树中，递归深度要小得多。

def serialize(root):
    if not root:
        return []

    result = []

        result.append(node.val)
        for child in node.children:
            dfs(child)

    dfs(root)
    return result

 ## 边缘情况

 ### 空树

 一种重要的边缘情况是当输入根是`None`。 幼稚的实现可能会尝试访问`root.val`立即，导致运行时错误。 

该实现通过检查来安全地处理这个问题`if root is None`在开始和返回时`None`立即地。 

### 叶节点

 叶节点不包含子节点。 某些实现意外地假设每个节点都有子节点，并且可能会错误地迭代或初始化无效的引用。 

该解决方案自然地处理叶节点，因为迭代空子列表仅执行零递归调用。 

### 深树

 高度倾斜的树可以创建接近 1000 的递归深度。意外地为每个子节点递归多次或重复工作的递归解决方案可能会变得低效或不稳定。 

此实现对每个子级执行一次递归调用并保持线性复杂性。 递归深度仅随着实际树深度而增长。 

### 深度复制验证

 当开发人员不小心重用原始树中的子引用而不是创建新节点时，就会出现一个微妙的错误。 

这个实现总是分配一个全新的`Node`递归克隆子对象之前的对象。 因此，克隆树完全独立于原始树。
