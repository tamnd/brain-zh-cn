 ## 解决方案

 # LeetCode 1474，删除链表 M 个节点后的 N 个节点

 ## 问题理解

 这个问题给了我们一个单链表的头和两个整数，`m`和`n`。 我们必须在重复应用固定模式的同时遍历链表：

 1.保留下一个`m`节点。 
2.删除以下内容`n`节点。 
3. 继续重复此过程，直到列表结束。 

重要的细节是，删除是通过重新连接链表中的指针来进行的。 我们不会被要求创建一个包含剩余值的新列表。 相反，我们修改现有的链接结构。 

例如，如果列表是：```
1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7
```和`m = 2`,`n = 2`，我们：

 - 保留`1, 2`- 删除`3, 4`- 保持`5, 6`- 删除`7`最终列表变为：```
1 -> 2 -> 5 -> 6
```输入包括：

 -`head`，单链表的第一个节点
 -`m`, 每个循环中要保留的节点数
 -`n`，保留部分之后要删除的节点数

 输出是修改后的链表的头。 

约束告诉我们列表大小可以大到`10^4`节点。 对于线性遍历解决方案来说，这足够小，但又足够大，不需要重复重建列表或执行昂贵的操作。 由于这是一个链表问题，因此预期的解决方案是指针操作。 

一些边缘情况很重要：

 - 当我们仍处于“保留”阶段时，该列表可能会结束。 
- 当我们删除节点时，列表可能会结束。 
-`m`可能等于`1`，这意味着我们每个周期只保留一个节点。 
-`n`可能大于剩余节点数。 
- 该列表可能只包含一个节点。 
- 约束保证`m >= 1`，所以我们永远不需要处理每个节点都被立即删除的情况。 

后续询问能否就地解决。 由于链表天然支持指针重连，因此最优方案直接修改链表，无需额外存储。 

## 方法

 ### 蛮力方法

 暴力方法首先将所有节点值复制到数组中。 然后我们可以使用索引模拟保留/删除过程并构建仅包含保留值的第二个数组。 最后，我们将从过滤后的值构造一个全新的链表。 

这是可行的，因为数组使索引遍历变得简单。 我们可以轻松确定哪些元素属于“保留”部分，哪些属于“删除”部分。 

然而，这种方法效率低下，因为：

 - 它使用与列表大小成比例的额外内存。 
- 它不必要地重建整个链表。 
- 该问题特别暗示就地解决方案是首选。 

虽然时间复杂度仍然是线性的，但是额外的内存使用是可以避免的。 

### 最优就地链表遍历

 关键的观察是我们实际上不需要一一删除节点。 相反，保留后`m`节点，我们可以简单地重新连接`next`最后保留的节点指向被删除节之后的节点的指针。 

这与链表完美配合，因为删除节点序列只需要更改单个指针。 

该算法重复执行两个阶段：

 1. 前进`m - 1`到达我们想要保留的最后一个节点的时间。 
2. 跳过下一个`n`通过重新连接指针来连接节点。 

由于每个节点最多被访问一次，因此该解决方案以线性时间和恒定的额外空间运行。

 ## 算法演练

 1. 从一个名为`current`指向链表的头部。 
2.遍历下一个`m - 1`节点，因为我们想准确保留`m`每个循环中的节点。 经过这次穿越之后，`current`指向应保留在列表中的最后一个节点。 
3.如果`current`变成`None`在keep阶段，我们已经到达了列表的末尾，可以立即停止。 
4. 创建另一个指针，名为`temp`开始于`current.next`。 该指针将移过必须删除的节点。 
5. 移动`temp`向前`n`次跳过应删除的节点。 如果列表在完成删除阶段之前结束，这是可以接受的。 
6. 通过设置重新连接列表：```
current.next = temp
```这有效地从链表中删除所有跳过的节点。 

1. 移动`current`到`temp`并重复该过程，直到到达列表末尾。 

### 为什么它有效

 该算法保持了之前每个节点的不变性`current`已根据保留/删除模式正确处理。 在每个周期中，我们准确地保留`m`节点并精确旁路`n`通过重新连接单个指针来连接节点。 由于每个节点恰好属于一个保留或删除段，并且遍历严格向前进行，因此最终的链表符合所需的结构。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def deleteNodes(self, head: Optional[ListNode], m: int, n: int) -> Optional[ListNode]:
        current = head

        while current:
            # Keep m nodes
            for _ in range(m - 1):
                if current is None:
                    return head
                current = current.next

            # If we reached the end, stop
            if current is None:
                break

            # Delete next n nodes
            temp = current.next

            for _ in range(n):
                if temp is None:
                    break
                temp = temp.next

            # Connect kept part to remaining list
            current.next = temp

            # Move current forward
            current = temp

        return head
```实现从初始化开始`current`到链表的头部。 外层`while`循环继续，直到遍历到达列表末尾。 

在循环内部，第一个`for`循环前进`current`通过`m`应保留在列表中的节点。 我们搬家`m - 1`次因为`current`已经在第一个保留的节点上启动。 

保留所需的节点后，我们创建一个名为的临时指针`temp`从第一个要删除的节点开始。 第二个`for`循环前进`temp`经过`n`节点，有效地跳过已删除的部分。 

关键操作是：```python
current.next = temp
```这会将保留的部分直接重新连接到已删除节点之后的剩余列表。 

最后，`current`移动到`temp`因此该过程可以在下一个周期重复。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func deleteNodes(head *ListNode, m int, n int) *ListNode {
	current := head

	for current != nil {
		// Keep m nodes
		for i := 0; i < m-1; i++ {
			if current == nil {
				return head
			}
			current = current.Next
		}

		// Reached end of list
		if current == nil {
			break
		}

		// Delete next n nodes
		temp := current.Next

		for i := 0; i < n; i++ {
			if temp == nil {
				break
			}
			temp = temp.Next
		}

		// Connect kept nodes to remaining list
		current.Next = temp

		// Move forward
		current = temp
	}

	return head
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别是显式指针处理`nil`而不是`None`。 

由于 Go 使用结构指针作为链表，因此修改`current.Next`直接就地更新原始列表。 除了一些指针变量之外，不需要额外的内存分配。 

整数溢出不是问题，因为约束很小并且算法仅执行有界循环迭代。

 ## 边缘情况

 当链表在保持阶段结束时，会出现一种重要的边缘情况。 例如，如果列表仅剩下三个节点，但是`m = 5`，我们应该简单地保留列表的其余部分并停止。 有缺陷的实现可能会尝试继续遍历末尾并取消引用空指针。 该解决方案通过检查是否`current`变成`None`或者`nil`遍历过程中。 

当删除阶段超出剩余节点时，会发生另一个棘手的情况。 假设我们保留两个节点，并且必须再删除十个，但只剩下三个节点。 该算法自然地处理这个问题，因为删除循环停止一次`temp`变成`None`。 重新连接`current.next`到`None`正确终止列表。 

第三个重要的边缘情况是`m = 1`。 在这种情况下，我们每个周期只保留一个节点并删除下一个节点`n`节点。 某些实现在保留阶段错误地移动了一个额外的步骤，并意外地跳过了保留的节点。 使用`m - 1`迭代确保当前节点本身算作第一个保留的节点。 

另一个微妙的情况是单节点链表。 由于头之后没有节点，因此删除阶段实际上不会删除任何内容。 该算法正确地返回原始头部不变。
