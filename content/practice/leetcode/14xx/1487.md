[LeetCode 问题 1487](https://leetcode.com/problems/making-file-names-unique/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们模拟当出现重复名称时文件系统如何分配文件夹名称。 

我们得到一个数组`names`， 在哪里`names[i]`代表请求的文件夹名称`i-th`分钟。 文件系统必须确保每个创建的文件夹都有唯一的名称。 

如果请求的名称以前从未使用过，系统会直接接受。 但是，如果该名称已存在，系统会附加一个后缀，格式为`(k)`在哪里`k`是产生唯一名称的最小正整数。 

例如，如果`"gta"`已经存在：

 - 系统首先尝试`"gta(1)"`- 如果也存在，它会尝试`"gta(2)"`- 持续增加`k`直到找到未使用的名称

 解决所有冲突后，输出应包含实际分配的文件夹名称。 

约束条件很重要：

 -`names.length`可以大到`5 * 10^4`- 每个字符串的长度最多为`20`二次解对于上限来说太慢了。 由于许多名称可能重复，因此我们需要一种方法来快速确定名称是否存在以及接下来要尝试的后缀。 

一些边缘情况尤其重要：

 - 重复相同的名称，例如`["a", "a", "a", "a"]`- 已经包含后缀的名称，例如`"gta(1)"`- 交错名称，其中后缀在重复发生之前被占用
 - 已经采用许多后缀的情况，迫使算法有效地跳过多个值

 该问题保证所有名称仅包含小写英文字母、数字和括号，因此我们不需要验证格式。 

## 方法

 ### 蛮力方法

 最直接的解决方案是维护一组已使用的名称。 

对于每个传入的名称：

 - 如果未使用，请将其插入集合中
 - 否则，从`k = 1`- 重复生成`name + "(" + k + ")"`直到找到未使用的名称
 - 将新的唯一名称插入集合中

 这种方法是正确的，因为它直接遵循问题陈述中描述的规则。 

然而，它可能会变得非常慢。 假设我们重复插入`"a"`很多次。 每次插入都会从以下位置重新开始检查`k = 1`，即使我们已经知道较小的后缀被占用。 

例如：```
"a"
"a(1)"
"a(2)"
"a(3)"
...
```当插入另一个`"a"`，强力解决方案可能会再次扫描许多以前使用过的后缀。 

在最坏的情况下，这会导致二次行为。 

### 最佳方法

 关键的见解是我们应该记住下一个后缀来尝试每个基本名称。 

而不是从重新启动`1`每次，我们维护一个哈希图：```
name -> next available suffix
```例如：```
"a" -> 4
```意味着当`"a"`再次出现，我们应该立即从后缀开始检查`4`。 

此优化避免了重复扫描已知的无效后缀。 

我们仍然使用哈希映射或集合来跟踪已分配的名称，但现在我们还缓存每个基本名称的进度。 

因为哈希图操作大约是`O(1)`，整个算法对于问题约束变得足够高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 从 1 | 开始重复扫描后缀
 | 最佳 | O(n) 平均 | O(n) | 存储下一个可用后缀以进行快速查找 |

 ## 算法演练

 1. 创建一个名为的哈希图`name_count`。 

这张地图有两个目的：

 - 它告诉我们一个名字是否已经存在
 - 它存储下一个后缀来尝试基本名称
 2. 创建一个名为的答案数组`result`。 

这将按顺序存储实际分配的文件夹名称。 
3. 迭代中的每个名称`names`。 

对于每个请求的文件夹名称，确定它是否已被使用。 
4. 如果该名称不存在于`name_count`：

 - 直接添加到`result`- 店铺`name_count[name] = 1`价值`1`意味着如果这个基名稍后再次出现，我们应该首先尝试后缀`(1)`。 
5. 如果该名称已存在：

 - 从中检索下一个后缀候选者`name_count[name]`- 构建候选人姓名：```
name(k)
```- 当该候选者已经存在时，增加`k`- 继续，直到找到唯一的候选人
 6. 一旦发现唯一的名称：

 - 将其附加到`result`- 将新名称标记为已使用
 - 更新`name_count[name]`所以未来的搜索从下一个后缀开始
 7.处理完所有名字后，返回`result`。 

### 为什么它有效

 该算法保持每个分配的文件夹名称都是唯一的并记录在哈希映射中的不变性。 

对于每个基本名称，存储的后缀指针始终表示尚未确认无效的最小后缀。 这保证了我们永远不会跳过有效的较小后缀，并且永远不会不必要地重试我们已经知道已被占用的后缀。 

因此，每个生成的名称都是唯一且最小的，完全符合问题要求。 

## Python 解决方案```python
from typing import List

class Solution:
    def getFolderNames(self, names: List[str]) -> List[str]:
        name_count = {}
        result = []

        for name in names:
            if name not in name_count:
                result.append(name)
                name_count[name] = 1
            else:
                k = name_count[name]

                while f"{name}({k})" in name_count:
                    k += 1

                new_name = f"{name}({k})"

                result.append(new_name)

                name_count[name] = k + 1
                name_count[new_name] = 1

        return result
```该实现使用一个名为`name_count`。 

当一个名字第一次出现时，它会被直接插入到结果数组中，并在字典中进行标记。 

当出现重复项时，算法会从字典中检索下一个要尝试的后缀。 而不是从重新启动`1`，它从之前存储的值恢复，这避免了冗余检查。 

这`while`循环继续搜索，直到找到唯一的生成名称。 一旦找到，算法就会更新：

 - 原始基本名称的下一个后缀指针
 - 生成的唯一名称本身

 这确保了所有未来的运营保持高效。 

## 解决方案```go
package main

import "fmt"

func getFolderNames(names []string) []string {
	nameCount := make(map[string]int)
	result := make([]string, 0, len(names))

	for _, name := range names {
		if _, exists := nameCount[name]; !exists {
			result = append(result, name)
			nameCount[name] = 1
		} else {
			k := nameCount[name]

			for {
				newName := fmt.Sprintf("%s(%d)", name, k)

				if _, exists := nameCount[newName]; !exists {
					result = append(result, newName)

					nameCount[name] = k + 1
					nameCount[newName] = 1

					break
				}

				k++
			}
		}
	}

	return result
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

Go 没有 Python 风格的 f 字符串，所以`fmt.Sprintf`用于构造后缀名。 

哈希映射是使用以下实现的`map[string]int`。 存在性检查使用标准的 Go 习惯用法：```go
value, exists := map[key]
```动态附加切片来存储结果。 

不存在整数溢出问题，因为后缀值保持在输入大小限制的实际范围内。

 ## 边缘情况

 当名称已包含括号时，会出现一种重要的边缘情况，例如`"gta(1)"`。 幼稚的实现可能会尝试将其解析为基本名称加后缀。 然而，这个问题从字面上对待每个字符串。`"gta(1)"`只是另一个文件夹名称。 该实现正确地处理了这个问题，因为它从不尝试解析或规范化名称。 每个字符串都按照收到的原样存储。 

另一个棘手的情况是重复的重复，例如：```
["a", "a", "a", "a", "a"]
```如果不进行优化，算法将重复重试后缀`(1)`对于每个重复项，都会继续进行，从而导致性能二次方。 哈希映射优化通过记住下一个可用后缀来避免这种情况`"a"`。 

当后缀名称在重复项出现之前已经存在时，会发生第三种重要的边缘情况：```
["doc", "doc(1)", "doc"]
```当第二个`"doc"`出现时，算法必须跳过`"doc(1)"`并生成`"doc(2)"`。 该实现可以正确处理此问题，因为每个生成的名称或原始名称都插入到同一哈希映射中，从而允许对原始名称和先前生成的名称进行冲突检查。
