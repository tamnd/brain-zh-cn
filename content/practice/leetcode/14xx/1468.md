[LeetCode 第 1468 题](https://leetcode.com/problems/calculate-salaries/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算每个员工的税后工资`Salaries`桌子。 然而，税率并不是针对每个员工单独确定的。 相反，税率是在**公司级别**根据**该公司内的最高工资**确定的。 

输入表中的每一行代表一名员工，包含四条信息：

 -`company_id`，识别员工属于哪家公司
 -`employee_id`，唯一标识公司内的员工
 -`employee_name`, 员工姓名
 -`salary`, 雇员的税前原始工资

 关键细节是，适用于公司所有员工的税率取决于该公司任何员工赚取的最高工资。 

税收规则是：

 - 如果公司的最高工资低于`1000`，则不征税，这意味着税率为`0%`。 
- 如果最高工资介于`1000`和`10000`，包含在内，则税率为`24%`。 
- 如果最高工资超过`10000`，那么税率为`49%`。 

在确定公司的正确税率后，我们使用以下公式将其应用于该公司的每位员工：$$\text{new salary} = \text{salary} - (\text{salary} \times \text{tax rate})$$所得工资必须四舍五入到最接近的整数。 

输出应包含相同的员工信息，但包含更新的税后工资。 

由于这是一个数据库问题，因此我们应该编写 SQL 查询，而不是用传统的编程语言实现算法。 主要挑战是有效确定每个公司的最高工资，然后对所有员工应用适当的税率。 

一个重要的观察是，公司中的每个员工都享有相同的税级。 因此，为每个员工单独重新计算税收分类将是一种浪费。 

一些边缘情况很重要：

 - 一家公司只能包含一名员工。 在这种情况下，该员工的工资决定了税级。 
- 边界值很重要，因为范围是包含在内的。 一家公司的最高工资正好`1000`或者确切地说`10000`应该收到`24%`税率。 
- 税后工资可能包含小数，因此需要进行适当的四舍五入。 例如，`5910.52`变成`5911`。 
- 薪资低于以下的公司`1000`应该保持不变，因为税率是`0%`。 

## 方法

 ### 蛮力方法

 强力方法将分别确定每位员工的公司税率。 

对于每个员工行，我们可以运行一个子查询来计算该员工所在公司的最高工资。 一旦我们得到了公司的最高工资，我们就确定税率并计算调整后的工资。 

从概念上讲，这是可行的，因为每个员工都能独立获取正确的公司税务信息。 然而，由于同一公司的员工重复计算公司的最高工资，因此效率低下。 

例如，如果一家公司有 1,000 名员工，则相同的最高工资计算将执行 1,000 次。 这种冗余使得查询不必要地昂贵。 

### 最佳方法

 关键的见解是，税率仅取决于**每家公司的最高工资**，并且该值由公司所有员工共享。 

我们不再重复重新计算最高工资，而是首先使用聚合计算每个公司的最高工资一次（`GROUP BY company_id`和`MAX(salary)`）。 

得到每个公司的最高工资后，我们把这些信息连接回原来的`Salaries`桌子。 一旦加入，每个员工行都可以获得其公司的最高工资，使我们能够确定正确的税级并计算调整后的工资。 

这种方法避免了冗余计算并有效扩展。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重新计算公司每位员工的最高工资|
 | 最佳 | O(n) | O(c) | 每个公司计算一次公司最大数量 |

 这里，`n`是员工人数，`c`是公司数量。 

## 算法演练

 ### 逐步过程

 1. 对员工进行分组`company_id`并使用以下方法计算每个公司的最高工资`MAX(salary)`。 
2. 对于每个公司，确定税级：

 -`< 1000`→`0%`-`1000 to 10000`→`24%`-`> 10000`→`49%`3.将计算出的公司信息加入回`Salaries`表中的每个员工行都可以访问其公司的税率。 
4. 使用以下方法计算税后工资：$$\text{salary} \times (1 - \text{tax rate})$$5. 使用以下方法将计算值舍入为最接近的整数`ROUND()`。 
6. 返回所需的列：

 -`company_id`-`employee_id`-`employee_name`- 调整后`salary`### 为什么它有效

 正确性来自于公司所有员工享有相同的税率，而税率仅取决于公司的最高工资。 通过计算每个公司的最高工资一次并将其加回来，每个员工都会收到正确的税级。 由于薪资调整公式一致应用并适当舍入，因此最终输出满足问题要求。 

## SQL 解决方案```sql
WITH CompanyTax AS (
    SELECT
        company_id,
        CASE
            WHEN MAX(salary) < 1000 THEN 0
            WHEN MAX(salary) <= 10000 THEN 24
            ELSE 49
        END AS tax_rate
    FROM Salaries
    GROUP BY company_id
)

SELECT
    s.company_id,
    s.employee_id,
    s.employee_name,
    ROUND(s.salary * (100 - ct.tax_rate) / 100) AS salary
FROM Salaries s
JOIN CompanyTax ct
    ON s.company_id = ct.company_id;
```### 实现说明

 该查询以名为的公共表表达式开始`CompanyTax`。 该中间结果计算每个公司的税率。 

我们对行进行分组`company_id`并计算`MAX(salary)`。 这`CASE`表达式将公司最高工资转换为适当的税率。 

接下来我们一起加入`CompanyTax`回到`Salaries`使用`company_id`。 这使每位员工都可以了解其公司的税率。 

最后，调整后的工资计算公式为：$$\text{salary} \times \frac{100 - \text{tax rate}}{100}$$这`ROUND()`函数确保工资完全按照要求四舍五入到最接近的整数。

 ## 边缘情况

 ### 最高薪资恰好为 1000 或 10000 的公司

 边界条件是错误的常见来源。 幼稚的实现可能会错误地使用`< 10000`而不是`<= 10000`，这将使公司的最高工资恰好为`10000`进入错误的税级。 这`CASE`语句通过使用显式处理包容性`<= 10000`。 

### 只有一名员工的公司

 一些实现意外地假设每个公司存在多名员工。 由于单个员工公司的最高工资就是该员工的工资，因此聚合的行为仍然正确。 这`GROUP BY`操作自然支持这种情况。 

### 小数工资四舍五入

 税收计算通常会产生小数值。 如果不进行舍入，结果将与预期的输出格式不匹配。 使用`ROUND()`确保诸如以下的值`5910.52`正确地成​​为`5911`。 

### 无税务公司

 最高工资低于以下的公司`1000`应保持原工资不变。 通过分配一个`0%`税率，公式自然保留了原始工资，不需要任何特殊情况逻辑。
