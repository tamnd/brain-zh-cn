 # LeetCode 1444 - 切披萨的多种方法

 ## 问题理解

 这个问题要求我们计算将长方形披萨精确分割成的有效方法的数量`k`使得每块至少包含一个苹果。 

披萨被表示为字符网格，其中`'A'`表示一个苹果和`'.'`表示一个空单元格。 我们必须准确执行`k - 1`削减产量`k`件。 每个切口可以是水平的或垂直的。 

A horizontal cut splits the pizza into an upper piece and a lower piece. The upper piece is immediately given away to a person, while the lower piece remains for future cuts. A vertical cut splits the pizza into a left piece and a right piece. The left piece is given away, while the right piece continues to be cut.

 The important detail is that every resulting piece must contain at least one apple. A cut is only valid if the piece being handed out contains an apple, and after all cuts are complete, the final remaining piece also contains at least one apple.

 The output is the total number of distinct valid cutting sequences, modulo`10^9 + 7`。 

这些约束对于理解哪种类型的解决方案是可行的非常重要：

 -`rows, cols <= 50`-`k <= 10`对每个可能的切割序列进行强力递归搜索将导致组合爆炸。 然而，相对较小的值`k`表明动态规划可能有效。 由于我们需要反复回答子矩形是否包含苹果，因此高效的子矩阵查询也是必要的。 

一个重要的观察结果是，每次切割后，仅继续处理一侧。 因此，状态可以通过当前披萨剩余的左上角坐标和剩余的切割次数来描述。 

一些边缘情况值得关注。 没有苹果的披萨无法分割成有效的块。 比萨饼中苹果的数量少于`k`永远不能产生`k`有效件。 什么时候`k = 1`，我们根本不切，答案很简单，就是整个披萨是否至少含有一个苹果。 另一个微妙的情况是，当许多可能的切割在几何上存在时，但有些会产生没有苹果的空部分，必须将其排除。 

## 方法

 ### 蛮力方法

 暴力解决方案将在每个阶段递归地尝试所有可能的水平和垂直切割。 

在任何时候，我们都会检查当前的披萨矩形并尝试每个合法的水平切割和每个合法的垂直切割。 进行切割后，我们递归地处理剩下的部分，少切割一次。 

为了确保正确性，我们需要在继续之前检查两个结果块是否至少包含一个苹果。 

这种方法是正确的，因为它明确枚举了每个可能的切割序列，并且仅计算满足苹果约束的序列。 

问题是许多相同的子问题重复出现。 例如，可以通过不同的切割顺序来达到相同的剩余子矩形。 如果没有记忆，我们会以指数方式多次重新计算相同的结果。 

此外，通过每次扫描该区域来检查矩形是否包含苹果又增加了一层低效率。 

### 最优方法，带有记忆和前缀和的动态规划

 关键的见解是，一旦进行了削减，只有剩下的部分才重要。 我们不关心如何到达该子矩形，只关心它的起始位置和剩余的切割次数。 

这自然意味着记忆。 

我们定义一个动态规划状态：`dp(row, col, cuts_left)`这表示从以下位置开始切割子矩形的有效方法数`(row, col)`进入`cuts_left + 1`件。 

为了使转换高效，我们还预先计算了一个后缀式前缀和矩阵，它告诉我们在恒定时间内任何子矩形内存在多少个苹果。 

这使我们能够快速回答：

 - 当前矩形中是否包含苹果？ 
- 提议的削减有效吗？ 

对于每个状态，我们尝试所有可能的水平和垂直切割。 如果赠送的苹果至少包含一个苹果，则切分有效。 然后我们递归计算剩余部分的路数。 

记忆化可以防止重新计算，使算法对于约束足够有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(k) 递归 | 反复尝试每个剪切顺序 |
 | 最佳| O(k × 行 × 列 × (行 + 列)) | O(k × 行 × 列) | 使用记忆和前缀和 |

 ## 算法演练

 1. **使用后缀和矩阵预先计算苹果数量**

 我们建立一个矩阵`apple_count`在哪里`apple_count[r][c]`存储从以下位置开始的子矩形中的苹果总数`(r, c)`并延伸到右下角。 

这使我们能够在恒定时间内确定任何子矩形是否包含苹果。 

其递归式为：```
apple_count[r][c] =
    apple_count[r+1][c]
    + apple_count[r][c+1]
    - apple_count[r+1][c+1]
    + (1 if pizza[r][c] == 'A' else 0)
```2. **定义记忆的DP状态**

 我们定义：```
dfs(row, col, cuts_remaining)
```这意味着：

 > 从以下位置开始切割子矩形的有效方法数`(row, col)`进入`cuts_remaining + 1`有效件。 
3. **处理基本情况**

 如果`cuts_remaining == 0`，我们正在创作最后的作品。 

如果当前子矩形至少包含一个苹果，则该子矩形有效。 

如果：```
apple_count[row][col] > 0
```然后返回`1`，否则返回`0`。 
4. **尝试所有水平切割**

 对于当前起始行下方的每一行，尝试水平剪切。 

赠送的上半部分仅在以下情况下有效：```
apple_count[row][col] - apple_count[next_row][col] > 0
```这意味着顶部至少包含一个苹果。 

如果有效，则递归求解：```
dfs(next_row, col, cuts_remaining - 1)
```5. **尝试所有垂直切割**

 同样，对于右侧的每一列：```
apple_count[row][col] - apple_count[row][next_col] > 0
```如果为 true，则左侧部分包含一个苹果。 

然后递归计算：```
dfs(row, next_col, cuts_remaining - 1)
```6. **记忆结果**

 由于许多状态重复，因此缓存每个状态的结果：```
(row, col, cuts_remaining)
```这避免了多余的递归。 
7. **应用模运算**

 由于有效方法的数量可能会变得非常大，因此始终计算：```
result % (10^9 + 7)
```### 为什么它有效

 正确性来自于在每个步骤中考虑每个可能的有效切割并递归地计算有效完成。 每个有效的切割序列都会被精确计数一次，因为每个递归分支对应一个唯一的切割顺序。 通过检查苹果的存在，立即排除无效的切割。 记忆可以保持正确性，因为相同的子问题总是产生相同的答案。 

## Python 解决方案```python
from functools import lru_cache
from typing import List

class Solution:
    def ways(self, pizza: List[str], k: int) -> int:
        MOD = 10**9 + 7
        rows = len(pizza)
        cols = len(pizza[0])

        # Suffix sum of apples
        apple_count = [[0] * (cols + 1) for _ in range(rows + 1)]

        for row in range(rows - 1, -1, -1):
            for col in range(cols - 1, -1, -1):
                apple_count[row][col] = (
                    apple_count[row + 1][col]
                    + apple_count[row][col + 1]
                    - apple_count[row + 1][col + 1]
                    + (1 if pizza[row][col] == 'A' else 0)
                )

        @lru_cache(None)
        def dfs(row: int, col: int, cuts_remaining: int) -> int:
            # No apples in current rectangle
            if apple_count[row][col] == 0:
                return 0

            # Final piece
            if cuts_remaining == 0:
                return 1

            ways_count = 0

            # Horizontal cuts
            for next_row in range(row + 1, rows):
                top_apples = (
                    apple_count[row][col]
                    - apple_count[next_row][col]
                )

                if top_apples > 0:
                    ways_count += dfs(
                        next_row,
                        col,
                        cuts_remaining - 1
                    )

            # Vertical cuts
            for next_col in range(col + 1, cols):
                left_apples = (
                    apple_count[row][col]
                    - apple_count[row][next_col]
                )

                if left_apples > 0:
                    ways_count += dfs(
                        row,
                        next_col,
                        cuts_remaining - 1
                    )

            return ways_count % MOD

        return dfs(0, 0, k - 1)
```实现首先构建后缀和矩阵。 该矩阵允许恒定时间的苹果查询，而不是重复地重新计算每个矩形的苹果数量。 

递归`dfs()`函数代表记忆的动态编程状态。 在尝试切割之前，它首先检查当前矩形是否有苹果。 如果不是，状态不可能，立即返回`0`。 

当没有剩余切口时，就会出现基本情况。 由于当前区域代表最终的披萨片，我们只需验证它是否包含一个苹果。 

递归步骤尝试所有可能的水平和垂直切割。 在递归之前，它会验证所分发的部分至少包含一个苹果。 这确保了只探索合法的切割路径。 

记忆通过`@lru_cache`保证重复状态仅计算一次。 

## 解决方案```go
func ways(pizza []string, k int) int {
	const MOD = 1000000007

	rows := len(pizza)
	cols := len(pizza[0])

	// Suffix sum of apples
	appleCount := make([][]int, rows+1)
	for i := range appleCount {
		appleCount[i] = make([]int, cols+1)
	}

	for row := rows - 1; row >= 0; row-- {
		for col := cols - 1; col >= 0; col-- {
			apple := 0
			if pizza[row][col] == 'A' {
				apple = 1
			}

			appleCount[row][col] =
				appleCount[row+1][col] +
					appleCount[row][col+1] -
					appleCount[row+1][col+1] +
					apple
		}
	}

	memo := make(map[[3]int]int)

	var dfs func(int, int, int) int

	dfs = func(row, col, cutsRemaining int) int {
		key := [3]int{row, col, cutsRemaining}

		if value, exists := memo[key]; exists {
			return value
		}

		// No apples
		if appleCount[row][col] == 0 {
			return 0
		}

		// Final piece
		if cutsRemaining == 0 {
			return 1
		}

		totalWays := 0

		// Horizontal cuts
		for nextRow := row + 1; nextRow < rows; nextRow++ {
			topApples :=
				appleCount[row][col] -
					appleCount[nextRow][col]

			if topApples > 0 {
				totalWays += dfs(
					nextRow,
					col,
					cutsRemaining-1,
				)
				totalWays %= MOD
			}
		}

		// Vertical cuts
		for nextCol := col + 1; nextCol < cols; nextCol++ {
			leftApples :=
				appleCount[row][col] -
					appleCount[row][nextCol]

			if leftApples > 0 {
				totalWays += dfs(
					row,
					nextCol,
					cutsRemaining-1,
				)
				totalWays %= MOD
			}
		}

		memo[key] = totalWays
		return totalWays
	}

	return dfs(0, 0, k-1)
}
```Go 实现遵循与 Python 相同的逻辑，但使用`map[[3]int]int`用于记忆，因为 Go 不提供内置函数缓存。 

累加期间应用模运算以避免整数溢出。 由于 Go 切片是基于引用的，因此在递归期间不会发生额外的复制。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k × 行 × 列 × (行 + 列)) | 每个 DP 状态都会尝试所有行和列切割 |
 | 空间| O(k × 行 × 列) | 记忆缓存加递归 |

rows × cols × k

O(rows + cols)
```自从`rows, cols <= 50`和`k <= 10`，这很容易就足够高效了。

 ## 边缘情况

 ### 案例 1：披萨不含苹果

 A pizza such as:```
["...", "..."]
```永远无法得出有效的答案，因为每块必须至少包含一个苹果。 

幼稚的实现可能仍然会尝试递归并浪费时间探索不可能的削减。 此实现通过立即返回来避免这种情况`0`每当：```
apple_count[row][col] == 0
```### 案例 2：`k = 1`什么时候`k = 1`，不需要削减。 答案完全取决于整个披萨是否含有苹果。 

如果递归假设至少总是发生一次切割，那么这种情况很容易处理不当。 在这里，基本情况：```
cuts_remaining == 0
```正确处理情况。 

### 情况 3：无效的几何切割

 有些切割可能在几何上看起来是有效的，但会产生一个没有苹果的空块。 

例如：```
A..
...
...
```第一行下方的水平切割会创建一个空的下部区域，其中没有苹果。 

该实现在递归之前使用后缀和仔细验证每次切割，确保只计算合法分区。 

### 情况 4：重复的子问题

 不同的切割路径可能会导致相同的剩余子矩形。 

如果没有记忆，这会产生指数重新计算。 通过缓存：```
(row, col, cuts_remaining)
```每个独特的状态仅求解一次，使得算法对于给定的限制足够有效。
