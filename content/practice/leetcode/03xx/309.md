[LeetCode 第 309 题](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-cooldown/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们在称为冷却期的特殊限制下最大化股票交易的利润。 

我们得到一个整数数组`prices`， 在哪里`prices[i]`代表当日股价`i`。 在任何一天，我们都可以选择买入一股、卖出一股，或者什么都不做。 我们可以执行任意数量的交易，但有两个重要的限制：

 1. 我们一次不能持有多于一只股票。 
2、卖出一只股票后，我们必须等待一整天才能再次买入。 

目标是计算所有交易日结束时可实现的最大总利润。 

与经典的无限交易库存问题相比，冷却时间限制显着改变了问题。 通常情况下，卖出后，我们可以在第二天立即再次买入。 在这里，这是被禁止的，所以我们某一天的决定会影响未来的选择。 

例如，与：```
prices = [1,2,3,0,2]
```一种最佳序列是：

 - 1 点购买
 - 3 点出售
 - 冷却时间为一天
 - 0 购买
 - 售价 2

 利润总额：```
(3 - 1) + (2 - 0) = 4
```然而，由于冷却时间的原因，合法过渡下实际的最佳可实现序列的利润为 3。 

限制条件是：

 -`1 <= prices.length <= 5000`-`0 <= prices[i] <= 1000`输入大小 5000 足够大，指数解决方案太慢。 我们需要一种高效的动态规划方法，最好是线性时间。 

重要的边缘情况包括：

 - 一天内无法进行交易
 - 严格降低价格，最好的行动就是永远不买
 - 峰谷交替，冷却时间很重要
 - 由于冷却时间限制而重叠的多个有利可图的交易

 该问题保证数组非空并且所有价格都是非负整数。 

## 方法

 ### 蛮力方法

 暴力解决方案探索全天所有可能的行动序列。 

每一天，我们都可以：

 - 购买
 - 出售
 - 跳过

 这些行为的合法性取决于我们目前是否持有股票以及我们是否处于冷却期。 

递归回溯解决方案可以模拟所有有效的交易路径。 每天，它都会分支到所有允许的决策，并递归地计算最佳的未来利润。 

这种方法是正确的，因为它详尽地探索了每一个合法的交易序列并选择其中利润最大的。 

然而，州的数量呈指数级增长。 每一天，多项决定都可能衍生出更多的可能性。 由于时间长达 5000 天，这在计算上很快变得不可行。 

### 最佳解决方案的关键见解

 重要的观察是，未来仅取决于当前的少量信息：

 - 我们目前是否持有股票
 - 我们是否处于冷却时间
 - 迄今为止取得的最佳利润

 我们不需要记住整个交易历史。 

这使得该问题非常适合动态规划。 

我们可以使用三种状态对系统进行建模：

 1.`hold`- 当前持有股票时的最大利润
 2.`sold`- 今天卖出股票后立即获得最大利润
 3.`rest`- 不持有库存且未处于冷却时间时获得最大利润

 这些状态充分捕获未来决策所需的所有必要信息。 

每天，我们都会根据有效的操作在状态之间进行转换：

 - 购买过渡`rest`到`hold`- 出售过渡`hold`到`sold`- 等待之前的转换`rest`或者`sold`因为每一天只依赖于前一天，所以我们可以用恒定的额外空间在线性时间内解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) 或更糟 | O(n) | 递归探索所有有效的交易序列 |
 | 最优动态规划| O(n) | O(1) | O(1) | 每天仅跟踪三个交易状态 |

 ## 算法演练

 ### 最优动态规划算法

 1. 初始化三个状态变量。 

我们维持：

 -`hold`, 持有股票时的最大利润
 -`sold`, 今天卖出后的最大利润
 -`rest`，闲置并允许购买时的最大利润

 最初：

 -`hold = -prices[0]`-`sold = 0`-`rest = 0`我们从负值开始`hold`因为购买股票需要花钱。 
2. 迭代剩余的每一天。 

对于第 0 天之后的每个价格，计算新状态。 
3. 计算新的`hold`状态。 

我们可以：

 - 继续持有之前的股票
 - 今天从`rest`状态

 过渡：```
hold = max(previous_hold, previous_rest - price)
```4. 计算新的`sold`状态。 

如果我们昨天持有股票，我们今天只能卖出。 

过渡：```
sold = previous_hold + price
```5. 计算新的`rest`状态。 

我们可以继续休息，或者在昨天的卖出之后进入休息。 

过渡：```
rest = max(previous_rest, previous_sold)
```6. 同时更新所有状态。 

由于所有转换都取决于先前的值，因此需要临时变量。 
7. 返回最终答案。 

最后，持有股票没有用，因为未实现的利润不算在内。 

因此，答案是：```
max(sold, rest)
```### 为什么它有效

 该算法之所以有效，是因为这三种状态完全描述了每天的每个合法交易条件。 

每个有效动作都会在这些状态之间转换，同时遵守冷却时间规则：

 - 只允许购买`rest`- 销售需要`hold`- 冷却自然发生，因为之后`sold`，第二天只能过渡到`rest`由于每个可能的合法交易序列都映射到这些状态转换的序列，并且每个状态都存储可实现的最大利润，因此保证最终结果是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        if not prices:
            return 0

        hold = -prices[0]
        sold = 0
        rest = 0

        for price in prices[1:]:
            previous_hold = hold
            previous_sold = sold
            previous_rest = rest

            hold = max(previous_hold, previous_rest - price)
            sold = previous_hold + price
            rest = max(previous_rest, previous_sold)

        return max(sold, rest)
```实现首先处理数组为空的边缘情况，尽管该问题保证至少有一个元素。 

三个状态变量代表不同交易条件下的最佳可能利润。`hold`存储当前拥有股票时可实现的最佳利润。 由于购买需要花钱，所以它开始于`-prices[0]`。`sold`代表卖出股票后立即获得的利润。 最初，我们没有出售任何东西，所以它从 0 开始。`rest`代表不持有股票且未处于冷却时间时的最佳利润。 

对于第一天之后的每个价格，我们在计算转换之前保留之前的状态值。 这是必要的，因为所有更新都取决于前一天的状态。 

转移方程直接模拟合法交易行为：

 -`hold`要么保留现有库存，要么今天购买
 -`sold`卖出昨天持有的股票
 -`rest`要么继续休息，要么完成冷却

 最后，我们返回最佳的非持有状态，因为任何剩余持有的股票尚未出售，因此不会对已实现的利润做出贡献。 

## 解决方案```go
func maxProfit(prices []int) int {
    if len(prices) == 0 {
        return 0
    }

    hold := -prices[0]
    sold := 0
    rest := 0

    for i := 1; i < len(prices); i++ {
        price := prices[i]

        previousHold := hold
        previousSold := sold
        previousRest := rest

        if previousRest-price > previousHold {
            hold = previousRest - price
        } else {
            hold = previousHold
        }

        sold = previousHold + price

        if previousSold > previousRest {
            rest = previousSold
        } else {
            rest = previousRest
        }
    }

    if sold > rest {
        return sold
    }

    return rest
}
```Go 实现遵循与 Python 解决方案相同的状态转换逻辑。 

Go 没有提供内置的`max`整数函数，因此比较是使用标准实现的`if`声明。 

Go 中的切片的行为与动态数组类似。 即使约束保证至少有一个元素，该函数也可以安全地处理空输入。 

整数溢出不是问题，因为最大利润完全在 Go 的整数范围内。

 ## 边缘情况

 一个重要的边缘情况是单元素数组，例如`[1]`。 由于买卖至少需要两天时间，因此不可能进行任何交易。 幼稚的实现可能会错误地尝试事务或访问无效索引。 此实现正确初始化状态并立即返回 0。 

另一个重要的边缘情况是严格降低价格，例如`[5,4,3,2,1]`。 任何购买都会导致损失，因此最佳策略是完全避免交易。 动态规划状态自然会保留 0 的最佳利润，因为出售永远不会有利可图。 

更微妙的边缘情况涉及冷却冲突，例如`[1,2,3,0,2]`。 贪婪的方法可能会在卖出后尝试立即买入，从而违反了冷却时间规则。 状态转换设计可以防止非法交易，因为只允许从`rest`状态，从不直接来自`sold`。 

恒定价格数组，例如`[0,0,0,0]`是另一个有用的边缘情况。 由于不存在有利可图的交易，因此最佳结果仍然为 0。算法正确地处理了这个问题，因为所有可能的卖出利润都是非正数，因此静止状态占主导地位。 

最后，具有多个重叠机会的案例，例如`[6,1,3,2,4,7]`，演示为什么动态规划是必要的。 由于冷却时间的原因，局部最优决策可能会阻止更有利可图的未来序列。 基于状态的DP有效地评估所有有效的转换并保证全局最优结果。
