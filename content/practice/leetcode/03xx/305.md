[LeetCode 第 305 题](https://leetcode.com/problems/number-of-islands-ii/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、并查

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个最初是空的`m x n`网格中的每个细胞都以水开始。 然后我们得到一系列操作`positions`，其中每个操作将特定单元格从水变成陆地。 

每次操作后，我们必须确定网格中当前存在多少个岛屿。 

岛屿由水平或垂直连接的陆地单元形成。 对角线连接不算数。 每个新添加的陆地单元都可以：

 - 创建一个全新的岛屿
 - 附着在现有岛屿上
 - 将多个现有岛屿合并为一个更大的岛屿

 输出是一个数组，其中`answer[i]`表示处理后的岛屿数量`i-th`手术。 

约束条件很重要：

 -`positions.length <= 10^4`-`m * n <= 10^4`每次操作后重新计算所有岛屿的简单方法会太慢，因为我们可能需要处理最多`10^4`操作，每个操作都可能扫描整个网格。 

这个问题从根本上来说是动态连接问题。 陆地单元是增量添加的，我们需要一种有效的方法来确定相邻单元是否属于同一连通分量。 

一些边缘情况尤其重要：

 - 将土地添加到已经是土地的位置
 - 一个新的单元同时连接多个岛屿
 - 非常小的网格，例如`1 x 1`- 长链相连的附加内容
 - 岛屿永远不会合并的稀疏补充

 如果不仔细处理连接，这些情况很容易产生不正确的岛屿计数。 

## 方法

 ### 蛮力方法

 最直接的解决方案是维护整个网格，并在每次添加土地后，使用 DFS 或 BFS 从头开始重新计算岛屿数量。 

该过程将如下所示：

 1. 添加新的陆地单元。 
2. 遍历整个网格。 
3.每当发现未访问过的陆地单元时，执行DFS/BFS来标记整个岛屿。 
4. 计算需要多少次单独的遍历。 

这种方法是正确的，因为 DFS/BFS 准确地识别了连接的陆地组件。 

然而，它的效率很低。 假设我们有`k`运营。 对于每个操作，我们可能会扫描所有`m * n`细胞并可能再次穿越其中的许多细胞。 

总复杂度变为：

 -`O(k * m * n)`限制允许最多`10^4`运营和`10^4`细胞，这变得太昂贵了。 

### 最优方法，并查

 关键的见解是我们不需要在每次操作后重新计算所有岛屿。 

每个操作仅更改一个单元格。 唯一的连接变化发生在新单元与其四个邻居之间。 

这使得并查数据结构（也称为不相交集并集 (DSU)）非常适合。 

统查高效支持：

 - 查找细胞属于哪个连接组件
 - 合并两个连接的组件
 - 检测两个cell是否已经连接

 我们将每个陆地单元视为图中的一个节点。 当添加新的陆地单元时：

 - 它最初形成一个新岛屿
 - 我们检查它的四个邻居
 - 如果相邻的陆地单元属于不同的岛屿，我们会将它们联合起来
 - 每一次成功的联合都会使岛屿数量减少一个

 通过路径压缩和按等级/大小并集，并查找操作几乎是恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(k * m * n)`|`O(m * n)`| 每次使用 DFS/BFS 操作后重新计算孤岛 |
 | 最佳|`O(k * α(m * n))`|`O(m * n)`| Union-Find 动态维护连接组件 |

 这里，`α`是阿克曼反函数，它增长得非常缓慢，以至于在实践中实际上是恒定的。 

## 算法演练

 1. 初始化并查结构。 

我们为以下目的创建数组：

 -`parent`，存储每个节点的代表
 -`rank`或者`size`，用于平衡联合

 最初，所有细胞都是水，因此还不存在有效的父细胞。 
2. 将 2D 坐标转换为 1D 索引。 

由于并查找最适用于整数节点 ID，因此我们映射：```
index = row * n + col
```这保证了每个单元都有唯一的标识符。 
3. 维护一组活跃的陆地单元。 

我们需要有效地区分水和土地。 

哈希集允许恒定时间检查单元是否已被激活。 
4. 处理每块土地的增加。 

对于每一个`(row, col)`在`positions`：

 - 如果单元已经是陆地：

 - 岛屿数量不变
 - 将当前计数附加到结果中
 - 否则：

 - 将单元格添加到土地集中
 - 将岛屿数量增加一，因为最初创建了一个新的孤岛
 5. 检查四个相邻小区。 

邻居是：

 - 向上
 - 向下
 - 左
 - 右

 对于每个有效的相邻陆地单元：

 - 找到当前单元和邻居的根
 - 如果根不同：

 - 联合他们
 - 由于两个岛屿合并，岛屿数量减少一个
 6. 追加当前岛屿数量。 

处理所有并集后，当前计数反映了正确的岛屿数量。 
7. 继续，直到处理完所有操作。 

### 为什么它有效

 关键的不变量是每个连通岛恰好对应于并查结构中的一个连通组件。 

每当添加新的陆地单元时：

 - 它作为自己的组件开始
 - 任何相邻的陆地单元代表应该连接的岛屿
 - 每个成功的联盟都会将两个不同的岛屿合并为一个

 因此，岛屿计数器始终与陆地单元之间连接的组件的数量相匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def numIslands2(self, m: int, n: int, positions: List[List[int]]) -> List[int]:
        parent = {}
        rank = {}

        def find(x: int) -> int:
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]

        def union(x: int, y: int) -> bool:
            root_x = find(x)
            root_y = find(y)

            if root_x == root_y:
                return False

            if rank[root_x] < rank[root_y]:
                parent[root_x] = root_y
            elif rank[root_x] > rank[root_y]:
                parent[root_y] = root_x
            else:
                parent[root_y] = root_x
                rank[root_x] += 1

            return True

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        land = set()
        island_count = 0
        result = []

        for row, col in positions:
            if (row, col) in land:
                result.append(island_count)
                continue

            land.add((row, col))

            current = row * n + col
            parent[current] = current
            rank[current] = 0

            island_count += 1

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    0 <= new_row < m
                    and 0 <= new_col < n
                    and (new_row, new_col) in land
                ):
                    neighbor = new_row * n + new_col

                    if union(current, neighbor):
                        island_count -= 1

            result.append(island_count)

        return result
```该实现使用字典`parent`和`rank`而不是固定大小的数组。 这避免了初始化所有`m * n`单元放在前面，因为只有陆地单元参与联合查找操作。 

这`find`函数执行路径压缩。 每次我们遍历父指针时，我们都会展平结构，以便将来的查找变得更快。 

这`union`函数使用按等级并集来合并两个组件。 这可以防止树木变得很高并保持运营效率。 

这`land`设置跟踪当前哪些单元格是陆地的。 这很重要，因为相邻坐标可能仍然是水。 

对于每个操作：

 - 重复的添加将被忽略
 - 新的陆地单元作为一个独立的岛屿开始
 - 邻居检查尝试合并相邻岛屿
 - 每次成功的合并都会减少岛屿数量

 结果数组记录每次操作后的岛屿数量。 

## 解决方案```go
package main

func numIslands2(m int, n int, positions [][]int) []int {
	parent := make(map[int]int)
	rank := make(map[int]int)

	var find func(int) int

	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}

	union := func(x int, y int) bool {
		rootX := find(x)
		rootY := find(y)

		if rootX == rootY {
			return false
		}

		if rank[rootX] < rank[rootY] {
			parent[rootX] = rootY
		} else if rank[rootX] > rank[rootY] {
			parent[rootY] = rootX
		} else {
			parent[rootY] = rootX
			rank[rootX]++
		}

		return true
	}

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	land := make(map[int]bool)

	islandCount := 0
	result := []int{}

	for _, pos := range positions {
		row := pos[0]
		col := pos[1]

		current := row*n + col

		if land[current] {
			result = append(result, islandCount)
			continue
		}

		land[current] = true

		parent[current] = current
		rank[current] = 0

		islandCount++

		for _, dir := range directions {
			newRow := row + dir[0]
			newCol := col + dir[1]

			if newRow < 0 || newRow >= m || newCol < 0 || newCol >= n {
				continue
			}

			neighbor := newRow*n + newCol

			if !land[neighbor] {
				continue
			}

			if union(current, neighbor) {
				islandCount--
			}
		}

		result = append(result, islandCount)
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用映射而不是字典和闭包来实现`find`和`union`功能。 

Go 没有内置元组，因此直接使用整数编码来处理位置。 这`land`地图使用其一维索引存储活动的陆地单元。 

整数溢出不是问题，因为最大索引最多是`10^4`。

 ## 边缘情况

 一种重要的边缘情况是重复增加土地。 当同一位置出现多次时，幼稚的实现可能会意外地再次增加岛数。 该解决方案通过维护一个来避免这种情况`land`放。 如果集合中已存在单元格，则直接附加当前岛计数，而不执行任何并集。 

当新添加的陆地单元同时连接多个岛屿时，会出现另一种关键的边缘情况。 例如，中心单元可能会接触多个侧面的陆地。 如果没有仔细的并查检查，实施可能会错误地多次减少同一连接组件的岛计数。 这`union`函数通过返回来防止这种情况发生`False`当两个单元格已经在同一组中时。 

小网格如`1 x 1`也很重要。 一些实现意外地假设相邻单元始终存在或错误处理边界检查。 该解决方案在尝试任何连接操作之前显式验证邻居坐标是否保持在有效的网格边界内。 

最后一个微妙的边缘情况涉及对角线单元。 该问题指定仅水平和垂直邻接才有效。 两个对角陆地单元必须保持独立的岛屿。 由于该算法仅检查四个方向，因此对角线单元永远不会错误地合并。
