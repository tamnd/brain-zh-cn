 ## 解决方案

 ## 问题理解

 该问题给了我们一个排序的整数数组`nums`和二次变换函数：$$f(x) = ax^2 + bx + c$$我们必须将此函数应用于数组中的每个元素，并按排序顺序返回转换后的值。 

重要的细节是原始数组已经按升序排序，但应用二次函数后，不能保证结果值保持排序。 二次函数可以向上或向下弯曲，具体取决于`a`，因此即使输入是有序的，转换后的序列也可能变得无序。 

例如，考虑：$$f(x) = x^2$$将此应用到：```
[-4, -2, 2, 4]
```产生：```
[16, 4, 4, 16]
```这是没有排序的。 

因此，任务不仅仅是转换数字，还要有效地按排序顺序生成转换后的值。 

限制相对较小：

 -`1 <= nums.length <= 200`- 值范围为`-100`到`100`由于数组尺寸很小，暴力解决方案很容易通过。 然而，后续行动明确要求`O(n)`解决方案，这意味着我们应该利用二次函数的属性以及输入数组已经排序的事实。 

一些边缘情况很重要：

 -`a > 0`，抛物线开口向上，这意味着大值出现在输入范围的末端附近。 
-`a < 0`，抛物线开口向下，意味着末端附近出现小值。 
-`a == 0`，函数变为线性。 
- 可能会出现重复的转换值。 
- 负输入和正输入可能映射到相同的变换值，因为二次函数围绕其顶点对称。 

了解抛物线的形状是实现最佳解决方案的关键见解。 

## 方法

 ### 蛮力方法

 最直接的解决办法是：

 1. 对每个数字应用二次函数。 
2. 将所有转换后的值存储在新数组中。 
3. 对结果数组进行排序。 
4. 返回排序后的结果。 

这是有效的，因为无论转换如何改变序列，排序都能保证最终顺序是正确的。 

例如：```
nums = [-4, -2, 2, 4]
f(x) = x^2 + 3x + 5
```变换给出：```
[9, 3, 15, 33]
```排序产生：```
[3, 9, 15, 33]
```主要缺点是排序步骤，这会花费`O(n log n)`时间。 

### Optimal Two Pointer Approach

 关键的观察结果是二次函数形成抛物线。 

什么时候`a > 0`，抛物线开口向上：

 - 最大的转换值出现在已排序输入数组的末尾。 
- 最小的变换值出现在顶点附近。 

什么时候`a < 0`，抛物线开口向下：

 - 最小的变换值出现在末端。 
- 最大值出现在顶点附近。 

由于输入数组已经排序，因此可以直接比较左右两端变换后的值。 这允许我们使用类似于合并排序数组的两指针技术。 

策略是：

 - 一开始就使用一个指针。 
- 最后使用另一个指针。 
- 比较两侧的转换值。 
- 将适当的值放入结果数组中。 
- 向内移动。 

如果`a > 0`，我们从后面填充结果，因为最大值首先出现。 

如果`a < 0`，我们从前面填充，因为最小值首先出现。 

这完全避免了排序并实现了线性时间复杂度。

The extra space comes from the output array. Aside from that, only a few variables are used.

## Edge Cases
One important edge case occurs when `a == 0`. In this situation, the quadratic function becomes linear:
$$f(x)=bx+c$$
A naive implementation that assumes a true parabola may behave incorrectly. The current solution handles this naturally because the two pointer logic still works. When `b >= 0`, transformed values increase with `x`. When `b < 0`, they decrease. Since the algorithm groups `a == 0` together with `a >= 0`, the correct ordering is still produced.
