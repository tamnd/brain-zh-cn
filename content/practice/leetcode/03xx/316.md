 # LeetCode 316，删除重复字母

 ## 问题理解

 该问题要求我们从输入字符串构造一个新字符串`s`这样每个不同的字符都只出现一次，同时还确保最终结果是按字典顺序排列的最小结果。 

输入是仅由小写英文字母组成的字符串。 字符可能会出现多次。 我们可以删除字符，但不能任意对剩余字符进行重新排序。 保留的字符的相对顺序仍然必须遵循原始字符串顺序，因为我们实际上是在选择子序列。 

挑战来自平衡两个相互竞争的目标：

 1. 每个独特的角色必须只出现一次。 
2. 在所有有效答案中，我们必须选择字典顺序最小的一个。 

例如，考虑：```
s = "bcabc"
```不同的字符是`a`,`b`， 和`c`。 包含所有三个恰好一次的一些有效子序列是：

 -`"bca"`-`"cab"`-`"abc"`其中，`"abc"`按字典顺序最小，所以这是正确答案。 

约束条件告诉我们：

 -`1 <= s.length <= 10^4`- 仅使用小写英文字母

 由于输入最多可包含一万个字符，因此指数或阶乘解决方案不可行。 我们需要一种接近线性时间的算法。 

一些边缘情况很重要：

 - 包含所有相同字符的字符串，例如`"aaaaa"`，应该返回`"a"`。 
- 已经处于最佳形式的字符串，例如`"abc"`，应保持不变。 
- 较小字符出现较晚且应替换较早较大字符的字符串，例如`"cbacdcbc"`，需要谨慎的贪婪决策。 
- 只出现一次的角色一旦选择就无法删除。 

核心困难是确定何时可以安全地删除先前选择的角色，转而使用稍后出现的较小角色。 

## 方法

 ### 蛮力方法

 强力解决方案将生成字符串的每个可能的子序列，然后仅过滤那些满足以下条件的子序列：

 1. 每个不同的字符只包含一次。 
2. 长度等于不同字符的数量。 

在所有有效候选者中，我们将返回字典顺序最小的候选者。 

这种方法是正确的，因为它详尽地检查了所有可能性。 然而，一个长度的字符串`n`有`2^n`子序列。 和`n`最多`10^4`，这在计算上是不可能的。 

即使我们尝试优化，搜索空间也会呈指数增长并很快变得难以管理。 

### 最优贪婪+单调堆栈方法

 关键的见解是我们想要最小的字典顺序结果，这意味着我们应该尽可能在答案中更早地选择较小的字符。 

假设我们已经在结果堆栈中放置了一个字符。 如果我们稍后遇到一个较小的角色，我们会删除较大的角色并将较小的角色放在前面。 但是，只有当删除的字符稍后再次出现在字符串中时，我们才能安全地执行此操作。 否则，我们就会彻底失去它。 

这导致了贪婪策略：

 - 使用堆栈逐步构建答案。 
- 尽可能保持堆栈按字典顺序递增。 
- 添加新角色之前：

 - 如果较大的字符稍后再次出现，则将其从堆栈顶部删除。 
- 通过确保每个字符在堆栈中仅出现一次来避免重复。 

这是有效的，因为每次贪婪删除都会改善字典顺序，而不会牺牲以后包含所有必需字符的能力。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 生成所有子序列并检查有效性 |
 | 最佳| O(n) | O(1) 或 O(n) | 使用单调堆栈的贪婪策略 |

 ## 算法演练

 1. 计算每个字符在字符串中出现的次数。 

我们需要知道某个角色稍后是否会再次出现。 频率图允许我们确定从堆栈中删除字符是否安全。 
2. 创建一个空堆栈来构建答案。 

堆栈代表当前的最佳子序列。 
3. 创建一个名为`in_stack`。 

这会跟踪堆栈中已经存在的字符，因此我们不会插入重复项。 
4. 迭代字符串中的每个字符。 

对于每个角色：

 - 减少其剩余频率计数，因为我们当前正在处理它。 
5. 如果该字符已在堆栈中，则跳过它。 

由于每个字符必须恰好出现一次，因此我们不希望重复。 
6. 当堆栈不为空时，检查是否应该删除顶部字符。 

如果所有三个条件都成立，我们将删除顶部字符：

 - 当前字符按字典顺序小于顶部字符。 
- 顶部字符稍后再次出现在字符串中。 
- 删除它会改善词典顺序。 

这就是贪心优化步骤。 
7. 将当前字符压入堆栈。 

删除任何不必要的较大字符后，将插入当前字符。 
8. 将字符标记为存在于堆栈中。 

将其添加到`in_stack`。 
9.处理完所有字符后，加入栈成为字符串。 

最终的堆栈是最小的有效子序列。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 堆栈始终表示使用迄今为止处理的字符可能的最小字典顺序。 

每当我们从堆栈中删除一个字符时，我们都知道它稍后会再次出现，因此我们不会失去将其包含在最终答案中的能力。 当较小的字符可以安全地替换它们时，通过始终删除较大的字符，我们贪婪地改进了字典顺序，同时保持了有效性。 

由于每个字符最多被压入和弹出一次，因此该算法仍然高效。 

## Python 解决方案```python
class Solution:
    def removeDuplicateLetters(self, s: str) -> str:
        remaining = {}

        for char in s:
            remaining[char] = remaining.get(char, 0) + 1

        stack = []
        in_stack = set()

        for char in s:
            remaining[char] -= 1

            if char in in_stack:
                continue

            while (
                stack
                and char < stack[-1]
                and remaining[stack[-1]] > 0
            ):
                removed = stack.pop()
                in_stack.remove(removed)

            stack.append(char)
            in_stack.add(char)

        return "".join(stack)
```该实现首先计算每个字符的剩余出现次数。 这允许算法确定是否可以安全地从堆栈中删除字符。 

这`stack`存储当前正在构建的答案。 这`in_stack`set 可以防止重复插入。 

对于字符串中的每个字符，我们首先减少其剩余计数，因为我们当前正在访问该字符。 

如果该字符已经在堆栈中，我们立即跳过它，因为每个字符只能出现一次。 

否则，我们将当前字符与堆栈顶部进行比较。 如果当前字符较小并且顶部字符稍后再次出现，我们将删除较大的字符。 这个过程一直持续到不可能再有任何有益的去除为止。 

最后，当前字符被追加到堆栈中并标记为存在。 

最后，加入堆栈会产生按字典顺序排列的最小有效子序列。 

## 解决方案```go
func removeDuplicateLetters(s string) string {
    remaining := make(map[byte]int)

    for i := 0; i < len(s); i++ {
        remaining[s[i]]++
    }

    stack := make([]byte, 0)
    inStack := make(map[byte]bool)

    for i := 0; i < len(s); i++ {
        char := s[i]
        remaining[char]--

        if inStack[char] {
            continue
        }

        for len(stack) > 0 &&
            char < stack[len(stack)-1] &&
            remaining[stack[len(stack)-1]] > 0 {

            removed := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            delete(inStack, removed)
        }

        stack = append(stack, char)
        inStack[char] = true
    }

    return string(stack)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 由于 Go 字符串是 ASCII 字符的字节切片，因此我们使用`byte`用于字符存储。 

堆栈是使用字节片实现的。 使用切片截断来删除顶部元素：```go
stack = stack[:len(stack)-1]
```这`inStack`映射跟踪字符是否已经存在。 

由于输入仅包含小写英文字母，因此此解决方案不存在 Unicode 复杂性。

 ## 边缘情况

 ### 所有角色都相同

 考虑：```
"aaaaaa"
```有缺陷的实现可能会重复添加相同的字符或无法正确删除重复项。 正确的结果很简单`"a"`。 

该实现使用以下方法处理此问题`in_stack`放。 一次`"a"`添加到堆栈中后，将立即跳过后面的每个事件。 

### 较大的字符无法删除

 考虑：```
"cbad"
```加工时`"a"`，堆栈包含`"b"`。 虽然`"a"`较小，`"b"`稍后不再出现。 去除`"b"`将永久丢失，使最终结果无效。 

条件：```
remaining[stack[-1]] > 0
```防止不安全的拆除。 

### 字符已处于最佳顺序

 考虑：```
"abc"
```堆栈已经形成了最小的字典顺序，因此不会发生弹出。 该算法只是简单地附加每个字符。 

这验证了贪婪逻辑不会过度优化或意外删除不必要的字符。 

### 重复字符与较小字符交错

 考虑：```
"bbcaac"
```该算法必须仔细决定何时删除字符以及何时保留它们。 在插入较小的字符之前，可能会依次发生多次弹出。 

单调堆栈结构自然地通过重复检查当前字符是否应替换较大的先前字符来处理此问题。
