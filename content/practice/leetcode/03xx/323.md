[LeetCode 第 323 题](https://leetcode.com/problems/number-of-connected-components-in-an-undirected-graph/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、并查找、图论

 ## 解决方案

 ## 问题理解

 该问题要求我们确定无向图中存在多少个连通分量。 

连接组件是一组节点，其中每个节点都可以通过某种路径到达其他每个节点。 如果两组节点之间没有路径，则它们属于不同的连通分量。 

输入由两部分组成：

 -`n`，图中的节点总数
 -`edges`，无向边列表，其中每条边`[a, b]`连接节点`a`和节点`b`该图使用的节点标签来自`0`到`n - 1`。 

例如，如果`n = 5`边缘是：```
0 - 1 - 2

3 - 4
```那么有两个断开连接的组：

 -`{0,1,2}`-`{3,4}`所以答案是`2`。 

因为图是无向的，所以边`[a, b]`意味着旅行可以从`a`到`b`和来自`b`到`a`。 

限制条件相对温和：

 - 最多`2000`节点
 - 最多`5000`边缘

 对于深度优先搜索、广度优先搜索或并查找等标准图遍历算法来说，这已经足够小了。 

尽早识别一些边缘情况很重要：

 - 完全没有边的图，每个节点都是其自己的连接组件。 
- 所有节点连接在一起的图，答案是`1`。 
- 孤立的节点仍必须算作组件。 
- 该图可能包含多个不同大小的断开连接的簇。 
- 该问题保证没有重复边，也没有自循环，从而简化了遍历逻辑。 

## 方法

 ### 暴力方法

 简单的暴力策略会尝试独立确定每对节点之间的连接性。 

对于每个节点，我们可以重复扫描所有边以确定哪些节点是可达的，可能会多次重新计算相同的连接信息。 例如，对于每个节点，我们可能会运行一次新的遍历，而无需记住以前访问过的组件。 

这种方法是正确的，因为最终每个可到达的节点关系都会被探索。 然而，它执行了大量的冗余工作。 可以一次又一次地遍历相同的连接区域。 

在最坏的情况下，从每个节点重复搜索会导致粗略的结果`O(n * (n + e))`复杂度，其中：

 -`n`是节点数
 -`e`是边数

 This becomes inefficient as the graph grows.

 ### 最佳方法

 关键的见解是每个连接的组件只需要探索一次。 

如果我们从一个未访问的节点开始并执行图遍历（DFS 或 BFS），我们将访问该连接组件中的每个节点。 一旦访问过，这些节点就不需要再次探索。 

算法变为：

 1. 构建图的邻接列表表示。 
2. 维持`visited`放。 
3. 迭代每个节点。 
4. 每当我们遇到未访问的节点时，就从它启动DFS/BFS。 
5. Mark all reachable nodes as visited.
 6. 增加组件数量。 

每个节点和边仅处理一次，从而提供有效的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × (n + e)) | O(n × (n + e)) | O(n) | Repeatedly traverses the same regions |
 | 最优 DFS/BFS | O(n + e) | O(n + e) | Visits each node and edge once |

 ## 算法演练

 ### Optimal DFS Algorithm

 1. Create an adjacency list for the graph.

 Since the graph is undirected, each edge`[a, b]`必须在两个方向上添加：

 -`a -> b`-`b -> a`选择邻接列表是因为它可以有效地存储稀疏图并允许快速遍历邻居。 
2. 创建一个`visited`放。 

这会跟踪哪些节点已经被探索过。 如果没有它，遍历可能会无限期地重新访问循环图中的节点。 
3. 初始化一个名为`components`到`0`。 

该变量存储迄今为止发现的连接组件的数量。 
4. Iterate through every node from`0`到`n - 1`。 

每个节点代表新连接组件的可能起点。 
5、如果当前节点没有被访问过，则从当前节点开始DFS遍历。 

这意味着我们发现了一个全新的连接组件。 
6. DFS期间：

 - 将当前节点标记为已访问。 
- 递归访问所有未访问过的邻居。 

递归探索整个连接区域。 
7. DFS 完成后，增加组件计数。 

至此，整个组件已经被充分探索了。 
8. 继续扫描剩余节点。 

任何已经访问过的节点都属于先前发现的组件，因此可以跳过它。 
9. 返回最终的组件计数。 

### 为什么它有效

 该算法依赖于基本的图属性：

 - 从任何节点开始的 DFS 恰好访问从该节点可到达的所有节点。 

因此：

 - 每次 DFS 遍历都会识别一个完整的连接组件。 
- 没有组件被计数两次，因为访问的节点被跳过。 
- 每个节点都属于一次遍历。 

这保证了最终计数的正确性。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countComponents(self, n: int, edges: List[List[int]]) -> int:
        graph = defaultdict(list)

        # Build adjacency list
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)

        visited = set()

        def dfs(node: int) -> None:
            visited.add(node)

            for neighbor in graph[node]:
                if neighbor not in visited:
                    dfs(neighbor)

        components = 0

        for node in range(n):
            if node not in visited:
                dfs(node)
                components += 1

        return components
```实现首先使用构造邻接表`defaultdict(list)`。 这允许对每个节点进行有效的邻居查找。 

因为图是无向的，所以每条边都在两个方向上插入。 

这`visited`set 防止重新访问节点。 这对于正确性和效率都至关重要，尤其是当图中存在循环时。 

嵌套的`dfs`函数递归地探索从当前节点可到达的所有节点。 每个访问过的邻居都会继续更深入地遍历相同的连接组件。 

外循环扫描每个节点。 每当发现一个未访问的节点时，它就代表一个新的连接组件，因此启动 DFS 并且组件计数增加。 

最后，返回连接组件的总数。 

## 解决方案```go
package main

func countComponents(n int, edges [][]int) int {
	graph := make([][]int, n)

	// Build adjacency list
	for _, edge := range edges {
		a := edge[0]
		b := edge[1]

		graph[a] = append(graph[a], b)
		graph[b] = append(graph[b], a)
	}

	visited := make([]bool, n)

	var dfs func(int)

	dfs = func(node int) {
		visited[node] = true

		for _, neighbor := range graph[node] {
			if !visited[neighbor] {
				dfs(neighbor)
			}
		}
	}

	components := 0

	for node := 0; node < n; node++ {
		if !visited[node] {
			dfs(node)
			components++
		}
	}

	return components
}
```Go 实现遵循与 Python 版本相同的整体结构。 

Go 没有使用基于哈希的邻接结构，而是使用切片的切片：```go
graph := make([][]int, n)
```这可以有效地工作，因为节点标签保证在`[0, n-1]`。 

这`visited`结构是使用布尔切片而不是集合来实现的：```go
visited := make([]bool, n)
```这提供了恒定时间访问且开销较低。 

Go 闭包需要在赋值之前显式声明递归函数变量：```go
var dfs func(int)
```由于约束很小，因此不存在整数溢出问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + e) | 每个节点和边最多被访问一次 |
 | 空间| O(n + e) | 邻接表加访问过的结构|

 由于图是无向的，邻接表将每条边存储两次，导致`O(e)`贮存。 

DFS 遍历访问每个节点一次并处理每条边一次，产生相对于图大小的线性运行时间。 

递归堆栈可能会增长到`O(n)`在最坏的情况下，对于长链形图。

 ## 边缘情况

 ### 无边图

 如果`edges`是空的，每个节点都是孤立的，因此形成自己的连通分量。 

有错误的实现可能会错误地返回`0`因为没有通过边进行遍历。 正确的方法仍然是单独迭代所有节点。 由于每个节点都未被访问，因此 DFS 每个节点都会启动一次，从而导致`n`成分。 

### 全连通图

 当所有节点都属于一个连通结构时，答案应该是`1`。 

如果未正确跟踪访问的节点，不正确的实现可能会意外地对组件进行重复计数。 这`visited`set 保证在第一次 DFS 遍历完成后，所有剩余的节点都会被跳过。 

### 包含循环的图

 循环在无向图中很常见。 

例如：```
0 - 1
|   |
2 - 3
```如果没有适当的访问跟踪，DFS 将通过反复重新访问已经探索过的节点来永远递归。 

该实现通过检查来防止这种情况：```
if neighbor not in visited:
```在递归之前。 

### 孤立节点的存在

 某些节点可能不会出现在`edges`完全列出。 

例如：```
n = 5
edges = [[0,1]]
```节点`2`,`3`， 和`4`被孤立。 

仅迭代邻接列表键的有缺陷的解决方案将完全错过这些节点。 正确的实现是循环遍历所有节点`0`到`n - 1`，确保正确计算孤立节点。
