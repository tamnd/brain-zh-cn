 # LeetCode 313 - 超级丑陋的数字

 ## 问题理解

 这个问题要求我们找到`nth`称为“超级丑数”的特殊序列中的数字。 

超级丑数是一个正整数，其质因数仅来自给定的数组`primes`。 这意味着数字的每次分解只能使用此列表中的素数。 

例如，如果：```
primes = [2,7,13,19]
```那么有效的超级难看的数字包括：```
1, 2, 4, 7, 8, 13, 14, 16, ...
```因为每个数字都可以仅使用素数组成`2`,`7`,`13`， 和`19`。 

数量`1`总是被认为是一个超级难看的数字，因为它没有质因数。 

输入包括：

 -`n`，我们想要找到的序列中的位置
 -`primes`, 允许的素因数

 输出是`nth`超级难看的数字。 

约束条件很重要：

 -`n`可以大到`100000`-`primes.length`可以达到`100`- 每个质数至多`1000`这些约束立即告诉我们，天真地生成数字并重复检查因式分解会太慢。 我们需要一个动态编程风格的解决方案来有效地构建序列。 

有几个重要的边缘情况：

 -`n = 1`，答案必须始终是`1`- 多个素数可能会生成相同的下一个数字，例如：

 -`2 * 7 = 14`-`7 * 2 = 14`如果不仔细处理重复项，序列将包含重复的值。 
- 大值`n`需要具有接近线性复杂度的高效算法。 
- primes 数组可能包含许多值，因此重复扫描或重新计算昂贵的操作可能会变得昂贵。 

该问题保证：

 - 所有素数都是唯一的
 - 素数数组已排序
 - 答案位于 32 位有符号整数内

 这些保证简化了实施细节。 

## 方法

 ### 蛮力方法

 最直接的方法是迭代所有正整数并测试每个正整数是否是超级难看的数字。 

为了测试一个数字，我们反复将其除以每个允许的素数。 如果这个数字最终可以减少到`1`，那么它的所有素因数都属于允许集合，所以它是一个超级难看的数。 

例如：```
28
= 2 * 2 * 7
```由于所有因素都属于`[2,7,13,19]`，它是有效的。 

然而，对于大型企业来说，这种方法变得极其低效。`n`。 

与我们必须检查的整数数量相比，该序列增长缓慢。 许多数字被拒绝，并且重复因式分解的成本很高。 

和`n`最多`100000`，这种蛮力方法并不实用。 

### 最优动态规划方法

 关键的见解是，每个超级丑数都来自将早期的超级丑数乘以允许的素数之一。 

假设我们已经知道序列：```
1, 2, 4, 7, 8
```然后，可以通过将这些数字乘以每个素数来生成未来的候选者。 

这与经典的“丑数 II”问题非常相似。 

我们维持：

 - 一个 DP 数组，按排序顺序存储生成的超级难看的数字
 - 每个素数一个指针
 - 每个指针跟踪接下来应该乘以该素数的 DP 值

 对于每次迭代：

 1. 计算所有候选值
 2. 选择最低候选人
 3. 将其添加到序列中
 4. 推进产生该最小值的每个指针

 推进所有匹配指针对于避免重复至关重要。 

这种方法直接按排序顺序生成数字，而不检查不相关的整数。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 太大了，不实用| O(1) | O(1) | 检查每个整数并重复分解 |
 | 最优动态规划| O(n * k) | O(n + k) | 高效地仅生成有效的超级难看的数字 |

 这里，`k = len(primes)`。 

## 算法演练

 ### 最优动态规划算法

 1. 创建一个DP数组，名为`ugly`尺寸的`n`。 

该数组将存储第一个`n`按顺序排列的超级难看的数字。 

初始化：```
ugly[0] = 1
```因为`1`永远是第一个超级难看的数字。 
2. 创建一个名为的指针数组`indices`。 

每个素数都有一个指针。```
indices[i]
```告诉我们在哪个位置`ugly`目前应该乘以`primes[i]`。 

最初：```
indices = [0, 0, 0, ...]
```3. 创建候选数组。 

For each prime:```
candidates[i] = ugly[indices[i]] * primes[i]
```这些是下一个可能的超级难看的数字。 
4. 对于每个位置`1`到`n - 1`:

 1. 找出所有候选值中的最小值。 
2. 将此最小值附加到 DP 数组中。 
3. 对于每个候选者等于该最小值的素数：

 - 前进其指针
 - 重新计算其候选者
 5. 继续，直到 DP 数组包含`n`数字。 
6、退货：```
ugly[n - 1]
```### 为什么它有效

 该算法之所以有效，是因为每个超级丑数都可以表示为：```
(previous super ugly number) * (allowed prime)
```DP 数组始终保持排序状态，因为我们反复选择最小的可用候选者。 

指针机制保证：

 - 每个有效数字最终都会生成
 - 数字按递增顺序出现
 - 通过前进所有匹配的指针来正确跳过重复值

 这确保生成的序列正是超级丑数的序列。 

## Python 解决方案```python
from typing import List

class Solution:
    def nthSuperUglyNumber(self, n: int, primes: List[int]) -> int:
        k = len(primes)

        ugly = [1] * n
        indices = [0] * k
        candidates = primes[:]

        for i in range(1, n):
            next_ugly = min(candidates)
            ugly[i] = next_ugly

            for j in range(k):
                if candidates[j] == next_ugly:
                    indices[j] += 1
                    candidates[j] = ugly[indices[j]] * primes[j]

        return ugly[-1]
```实现直接遵循动态规划方法。 

这`ugly`array 存储生成的序列。 它开始于`1`。 

这`indices`数组跟踪每个质数接下来要相乘的 DP 值。 

这`candidates`数组存储每个素数的当前下一个可能值。 

在每次迭代时：

 - 我们选择最小的候选人
 - 将其存储到序列中
 - 推进每个匹配的指针

 重复处理尤其重要。 考虑：```python
2 * 7 = 14
7 * 2 = 14
```如果只有一个指针前进，`14`会出现多次。 推进所有匹配的指针可以防止重复。 

该算法有效地按排序顺序生成序列，无需进行不必要的因式分解或验证。 

## 解决方案```go
func nthSuperUglyNumber(n int, primes []int) int {
	k := len(primes)

	ugly := make([]int, n)
	ugly[0] = 1

	indices := make([]int, k)
	candidates := make([]int, k)

	for i := 0; i < k; i++ {
		candidates[i] = primes[i]
	}

	for i := 1; i < n; i++ {
		nextUgly := candidates[0]

		for j := 1; j < k; j++ {
			if candidates[j] < nextUgly {
				nextUgly = candidates[j]
			}
		}

		ugly[i] = nextUgly

		for j := 0; j < k; j++ {
			if candidates[j] == nextUgly {
				indices[j]++
				candidates[j] = ugly[indices[j]] * primes[j]
			}
		}
	}

	return ugly[n-1]
}
```Go 实现密切反映了 Python 逻辑。 

一些特定于 Go 的细节值得注意：

 - 切片使用初始化`make`- 我们手动计算最小候选，因为 Go 没有提供内置的`min`用于切片
 - 整数溢出不是问题，因为该问题保证结果适合 32 位有符号整数
 - 数组和切片是可变的，使得指针更新高效

 ## 边缘情况

 ### 边缘情况 1，`n = 1`什么时候`n = 1`，正确答案始终是`1`。 

如果实现假设序列生成至少有一次迭代，这很容易导致错误。 我们的实现自然地处理了这个问题，因为 DP 数组以以下内容开头：```
ugly[0] = 1
```循环从索引开始`1`。 因此，该函数立即返回`1`。 

### 边缘情况 2，重复候选生成

 多个素数可以产生相同的值：```
2 * 7 = 14
7 * 2 = 14
```如果生成后只有一个指针前进`14`，下一次迭代将生成`14`再次，导致序列重复。 

我们的实现通过推进候选等于所选最小值的每个指针来避免这种情况。 

这保证了唯一性。 

### 边缘情况 3，单素数阵列

 如果 primes 数组仅包含一个值：```
primes = [2]
```那么序列就变成：```
1, 2, 4, 8, 16, ...
```某些实现错误地假设存在多个候选源。 

我们的实现工作正常，因为该算法不依赖于大于 1 的素数数量。 单个指针只是简单地推进每次迭代。
