[LeetCode 问题 355](https://leetcode.com/problems/design-twitter/)

 **难度：** 🟡 中等
 **主题：** 哈希表、链表、设计、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个类似于 Twitter 的简化版社交媒体平台。 The system must support four main operations:

1. Users can post tweets.
 2. Users can follow other users.
 3. 用户可以取消关注其他用户。 
4. 用户可以检索个性化新闻源，其中包含自己及其关注的用户的 10 条最新推文。 

关键的挑战是根据新近度有效维护推文排序，同时支持动态关注关系。 

每条推文都有其独特之处`tweetId`，并且推文根据发布顺序被认为是较新的。 该平台不直接提供时间戳，因此我们必须自己在内部跟踪推文排序。 

这`getNewsFeed(userId)`operation is the most important part of the problem. 返回的 Feed 必须：

 - Include tweets posted by the user themself.
 - 包括他们当前关注的用户发布的推文。 
- Be ordered from most recent to least recent.
 - Contain at most 10 tweets.

 限制相对较小：

 - 用户 ID 范围为`1`到`500`- 至多`3 * 10^4`操作发生

 尽管这些限制并不是很大，但如果每个新闻提要请求都扫描全球所有推文，则简单的实现仍然会变得低效。 

一些边缘情况很重要：

 - 用户可以在不关注任何人的情况下请求提要。 
- 用户可能从未发布过任何推文。 
- 一个用户可以通过许多推文关注许多用户。 
- 取消关注当前未关注的人不应导致实施崩溃。 
- 用户无法关注自己，这简化了一些逻辑。 
- 新闻源必须始终仅包含 10 条最新推文。 

核心困难是有效合并多个推文流，同时保持时间顺序。 

## 方法

 ### 蛮力方法

 强力解决方案按时间顺序在全球范围内存储每条推文。 当为用户生成新闻源时，我们向后扫描整个推文历史记录并收集通过以下方式发布的推文：

 - 用户自己
 - 他们关注的用户

 一旦我们收集到 10 条推文，我们就会停止。 

这种方法是正确的，因为从最新到最旧的扫描可以保证正确的排序。 然而，随着推文数量的增加，它变得效率低下。 每一个`getNewsFeed`操作可能需要检查数千条推文。 

如果有`T`推文总数，每个提要查询可能需要`O(T)`时间。 

### 最佳方法

 关键的观察结果是推文自然地按用户分组。 我们可以单独存储每个用户的推文，而不是全局扫描所有推文。 

在生成新闻源时，我们只关心：

 - 用户自己的推文
 - 来自关注用户的推文

 每个用户都已经按时间顺序排列了他们的推文。 因此，问题就变成了合并几个已排序的推文列表并提取 10 条最新的推文。 

最大堆对此非常理想。 

我们将每个相关用户的最新推文放入堆中。 然后，我们重复提取最新的推文并插入来自同一用户的下一条较旧的推文。 这与合并本质上是相同的想法`k`排序列表。 

因为我们只需要前 10 条推文，所以堆永远不会变得太大。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(T)`每个提要查询 |`O(T)`| 扫描全球所有推文 |
 | 最佳|`O(F log F)`每个提要查询 |`O(T + F)`| 使用堆合并关注用户的推文流 |

 这里：

-`T`= 推文总数
 -`F`= 关注用户数加上用户本身

 ## 算法演练

 ### 数据结构

 我们使用两个主要的哈希图：

 1.`follow_map`- 将用户映射到他们关注的用户集。 
- 允许`O(1)`关注和取消关注操作。 
2.`tweets`- 将用户映射到他们的推文列表。 
- 每条推文存储：

 - 时间戳
 - 推文 ID

 我们还维护一个全局时间戳计数器，每当发布推文时该计数器就会增加。 

### Feed 生成策略

 最重要的操作是有效地合并多个用户的推文列表。 

我们使用最大堆，其中每个堆条目包含：

 - 负时间戳
 - 推文 ID
 - 用户ID
 - 下一条旧推文的索引

 蟒蛇的`heapq`是最小堆，因此我们否定时间戳来模拟最大堆行为。 

### 逐步算法

 1.初始化：

 -`follow_map`作为集合的字典
 -`tweets`作为列表的字典
 -`timestamp = 0`2. 什么时候`postTweet(userId, tweetId)`称为：

 - 追加`(timestamp, tweetId)`到用户的推文列表
 - 增加时间戳
 3. 什么时候`follow(followerId, followeeId)`称为：

 - 添加`followeeId`到关注者的关注集
 4. 什么时候`unfollow(followerId, followeeId)`称为：

 - 删除`followeeId`来自以下集合（如果存在）
 5. 什么时候`getNewsFeed(userId)`称为：

 1. 构建一个包含以下内容的集合：

 - 所有关注的用户
 - 用户自己
 2. 对于每个相关用户：

 - 获取他们最近的推文
 - 将其推入堆中
 3. 同时：

 - 堆不为空
 - 收集的推文少于 10 条
 4. 弹出最新的推文
 5. 将其推文 ID 添加到结果中
 6. 如果该用户有较旧的推文：

 - 将下一条较旧的推文推入堆中
 7.返回结果列表

 ### 为什么它有效

 每个用户的推文列表都已按时间顺序排序。 堆始终包含每个用户流中最新的未处理的推文。 通过重复提取最大时间戳推文，我们保证按时间降序全局返回推文。 由于我们在提取后继续推送来自同一用户的旧推文，因此堆始终保留下一个最佳候选者。 这与合并排序列表中使用的正确性原则完全相同。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
import heapq

class Twitter:

    def __init__(self):
        self.timestamp = 0
        self.follow_map = defaultdict(set)
        self.tweets = defaultdict(list)

    def postTweet(self, userId: int, tweetId: int) -> None:
        self.tweets[userId].append((self.timestamp, tweetId))
        self.timestamp += 1

    def getNewsFeed(self, userId: int) -> List[int]:
        max_heap = []
        result = []

        users = set(self.follow_map[userId])
        users.add(userId)

        for user in users:
            if self.tweets[user]:
                index = len(self.tweets[user]) - 1
                timestamp, tweet_id = self.tweets[user][index]

                heapq.heappush(
                    max_heap,
                    (-timestamp, tweet_id, user, index - 1)
                )

        while max_heap and len(result) < 10:
            neg_timestamp, tweet_id, user, next_index = heapq.heappop(max_heap)

            result.append(tweet_id)

            if next_index >= 0:
                timestamp, next_tweet_id = self.tweets[user][next_index]

                heapq.heappush(
                    max_heap,
                    (-timestamp, next_tweet_id, user, next_index - 1)
                )

        return result

    def follow(self, followerId: int, followeeId: int) -> None:
        self.follow_map[followerId].add(followeeId)

    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.follow_map[followerId].discard(followeeId)

```实现首先初始化三个组件：

 - 时间戳计数器
 - 关注关系图
 - 每个用户的推文存储映射

 推文按时间顺序存储在每个用户的列表中。 每条推文都会收到一个唯一的时间戳，因此我们可以有效地比较新近度。 

这`postTweet`方法将推文附加到`O(1)`时间。 

这`follow`和`unfollow`操作使用集合，它提供恒定时间的插入和删除。 

最重要的逻辑就在里面`getNewsFeed`。 我们首先收集所有相关用户，包括用户本身。 然后我们将每个用户的最新推文插入到堆中。 

每个堆条目都会记住该用户的下一条旧推文所在的位置。 每当我们从堆中弹出一条推文时，我们都会立即插入来自同一用户的下一条旧推文（如果存在）。 

这种惰性合并策略避免了将每条推文一次插入堆中，并保持算法的高效。 

## 解决方案```go
package main

import (
	"container/heap"
)

type Tweet struct {
	time    int
	tweetId int
}

type HeapNode struct {
	time      int
	tweetId   int
	userId    int
	nextIndex int
}

type MaxHeap []HeapNode

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i].time > h[j].time
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(HeapNode))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

type Twitter struct {
	timestamp int
	followMap map[int]map[int]bool
	tweets    map[int][]Tweet
}

func Constructor() Twitter {
	return Twitter{
		timestamp: 0,
		followMap: make(map[int]map[int]bool),
		tweets:    make(map[int][]Tweet),
	}
}

func (this *Twitter) PostTweet(userId int, tweetId int) {
	this.tweets[userId] = append(
		this.tweets[userId],
		Tweet{time: this.timestamp, tweetId: tweetId},
	)

	this.timestamp++
}

func (this *Twitter) GetNewsFeed(userId int) []int {
	result := []int{}
	h := &MaxHeap{}
	heap.Init(h)

	users := map[int]bool{}
	users[userId] = true

	if follows, exists := this.followMap[userId]; exists {
		for user := range follows {
			users[user] = true
		}
	}

	for user := range users {
		tweetList := this.tweets[user]

		if len(tweetList) > 0 {
			index := len(tweetList) - 1
			tweet := tweetList[index]

			heap.Push(h, HeapNode{
				time:      tweet.time,
				tweetId:   tweet.tweetId,
				userId:    user,
				nextIndex: index - 1,
			})
		}
	}

	for h.Len() > 0 && len(result) < 10 {
		node := heap.Pop(h).(HeapNode)

		result = append(result, node.tweetId)

		if node.nextIndex >= 0 {
			nextTweet := this.tweets[node.userId][node.nextIndex]

			heap.Push(h, HeapNode{
				time:      nextTweet.time,
				tweetId:   nextTweet.tweetId,
				userId:    node.userId,
				nextIndex: node.nextIndex - 1,
			})
		}
	}

	return result
}

func (this *Twitter) Follow(followerId int, followeeId int) {
	if _, exists := this.followMap[followerId]; !exists {
		this.followMap[followerId] = make(map[int]bool)
	}

	this.followMap[followerId][followeeId] = true
}

func (this *Twitter) Unfollow(followerId int, followeeId int) {
	if _, exists := this.followMap[followerId]; exists {
		delete(this.followMap[followerId], followeeId)
	}
}

/**
 * Your Twitter object will be instantiated and called as such:
 * obj := Constructor()
 * obj.PostTweet(userId, tweetId)
 * param_2 := obj.GetNewsFeed(userId)
 * obj.Follow(followerId, followeeId)
 * obj.Unfollow(followerId, followeeId)
 */
```Go 实现遵循与 Python 版本相同的算法结构，但几个实现细节有所不同。 

Go 需要使用显式堆实现`container/heap`包裹。 因此我们定义了一个自定义的`MaxHeap`输入并实现所需的接口方法。 

我们使用以下结构代替 Python 元组`Tweet`和`HeapNode`。 

Go 映射不会自动初始化嵌套映射，因此`Follow`方法在插入追随者条目之前检查是否存在。 

整体算法和复杂性与 Python 实现保持相同。

 ## 边缘情况

 ### 用户没有推文并且没有关注任何人

 用户可以在发布推文或关注任何人之前请求他们的新闻源。 幼稚的实现可能会假设推文列表存在，并意外触发关键错误或索引错误。 

这个实现可以安全地处理这种情况，因为`follow_map`和`tweets`使用默认的空容器。 堆只是保持为空，并且该函数返回一个空列表。 

### 超过 10 条可用推文

 用户可能可以访问所关注用户的数百或数千条推文。 该问题具体要求仅返回最近 10 条推文。 

该实现使用以下方式强制执行此操作：```
while max_heap and len(result) < 10:
```这保证了 feed 永远不会超过所需的大小，并避免不必要的堆操作。 

### 取消关注当前未关注的用户

 呼唤`unfollow`当前未关注的用户可能会导致实现中盲目从集合中删除的错误。 

Python 解决方案使用：```
discard()
```而不是`remove()`。 不像`remove`,`discard`如果该元素不存在，则不会引发异常。 

类似地，Go 实现在删除之前检查映射是否存在。 

### 推文数量差异巨大的用户

 一位关注的用户可能拥有数千条推文，而另一位则只有一条。 幼稚的合并实现可能会将每条推文插入堆中，从而造成不必要的开销。 

此实现最初仅插入每个用户的最新推文。 仅在需要时才会延迟添加较旧的推文。 无论推文历史记录大小如何，这都可以保持堆的使用效率。
