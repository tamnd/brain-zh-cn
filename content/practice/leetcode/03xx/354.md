 # LeetCode 354，俄罗斯娃娃信封

 ## 问题理解

 该问题给出了一个信封列表，其中每个信封都表示为一对`[w, h]`。 价值`w`是宽度和`h`是高度。 仅当两个信封的尺寸都严格较小时，一个信封才能装入另一个信封内。 这就是信封的意思`A`可以放入信封内`B`仅当：

 -`A.width < B.width`-`A.height < B.height`任务是确定可以相互嵌套的信封的最大数量，类似于俄罗斯嵌套娃娃。 

重要的细节是不允许旋转。 一个信封`[5, 4]`不能成为`[4, 5]`。 宽度和高度必须保持其原始方向。 

输入的大小非常大。 信封数量最多可达`10^5`，它立即告诉我们二次解可能会太慢。 任何算法`O(n^2)`在这种规模下，复杂性可能会面临超时的风险。 这强烈表明我们需要一个接近于`O(n log n)`。 

一些边缘情况很重要：

 - 多个信封可能具有相同的尺寸。 
- 多个信封可以共享相同的宽度但具有不同的高度。 
- 由于比较必须在两个维度上严格大于，因此宽度或高度相等的信封无法嵌套。 
- 当宽度相等时，天真的排序策略可能会意外地允许无效嵌套。 
- 最小的可能输入仅包含一个信封，在这种情况下答案是`1`。 

了解等宽度的行为方式是使最佳解决方案正常工作的关键见解。 

## 方法

 ### 蛮力方法

 解决该问题的一种直接方法是将每个包络视为图或状态空间中的节点。 对于每个信封，我们尝试将每个较大的信封放在其后面，并递归计算最长的有效链。 

我们可以先对信封进行排序，然后使用动态规划：

 - 让`dp[i]`表示以信封结束的最大嵌套链`i`。 
- 对于每个信封`i`,检查所有以前的信封`j`。 
- 如果信封`j`可以放入信封内`i`， 更新：`dp[i] = max(dp[i], dp[j] + 1)`这是有效的，因为每个有效的链都被探索，并且最长的链被记录。 

然而，这需要检查每一对信封，从而导致`O(n^2)`时间复杂度。 和`n = 10^5`，这变得太慢了。 

### 最佳解决方案的关键见解

 关键的观察是该问题可以转化为最长递增子序列问题的变体。 

假设我们按以下方式对信封进行排序：

 1. 宽度升序排列
 2. 宽度相等时高度按降序排列

 这样排序后：

 - 宽度由订单自动处理。 
- 相等的宽度不会意外地形成有效的链，因为对于相等的宽度，高度是递减的。 
- 我们只需要找到高度上的最长递增子序列。 

相等宽度的降序排序非常重要。 

考虑：```
[5,4], [5,5]
```如果身高按升序排序，身高的 LIS 将错误地处理`4 -> 5`有效，即使宽度相等并且嵌套是非法的。 

按高度降序对相等的宽度进行排序可以防止出现此错误，因为高度变为：```
5, 4
```不能形成递增子序列。 

一旦转化，我们可以解决LIS问题`O(n log n)`使用二分查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 暴力动态规划| O(n²) | O(n) | 检查每个信封之前的每个信封 |
 | 最优 LIS + 二分查找 | O(n log n) | O(n log n) | O(n) | 仔细排序，然后对高度应用 LIS |

 ## 算法演练

 1. 按宽度升序对信封进行排序。 

这确保了当我们从左到右处理信封时，宽度不会减小。 
2. 对于宽度相同的信封，按高度降序排列。 

这可以防止宽度相同的信封显示为有效的高度增加子序列。 
3.排序后提取高度。 

排序后，宽度约束就已经处理好了。 问题变成了寻找高度中最长的严格递增子序列。 
4. 维护一个名为`lis`。 

价值`lis[i]`表示长度递增子序列的最小可能尾值`i + 1`。 
5、对每个高度进行一一处理。 

对于每个高度：

 - 使用二分查找找到可以插入此高度的最左边位置。 
- 如果高度大于所有现有尾部，则附加它。 
- 否则，替换现有值。 
6. 继续，直到处理完所有高度。 

长度为`lis`最后是嵌套信封的最大数量。 

### 为什么它有效

 在按高度升序对宽度进行排序以及按高度降序对等宽进行排序后，任何高度增加的子序列都会自动对应于有效的嵌套序列。 

LIS 算法为每个子序列长度维护尽可能小的结束高度。 尾部越小越好，因为它们为未来的信封扩展序列留下了更多空间。 二分搜索确保每次更新高效，同时保持正确性。 

## Python 解决方案```python
from typing import List
from bisect import bisect_left

class Solution:
    def maxEnvelopes(self, envelopes: List[List[int]]) -> int:
        # Sort by width ascending and height descending
        envelopes.sort(key=lambda envelope: (envelope[0], -envelope[1]))

        lis = []

        for _, height in envelopes:
            position = bisect_left(lis, height)

            if position == len(lis):
                lis.append(height)
            else:
                lis[position] = height

        return len(lis)
```实现首先使用自定义键对信封进行排序。 宽度按升序排序，而相同宽度的高度按降序排序。 此顺序对于正确性至关重要。 

这`lis`array 存储不同长度的递增子序列的最小可能尾部。 它不一定代表实际的嵌套序列，但其长度始终等于迄今为止找到的最长有效子序列的长度。 

对于每个信封高度，`bisect_left`找到可以插入高度同时保持排序顺序的第一个位置。 

如果高度大于所有现有尾部，则会扩展 LIS 并附加。 

否则，它将用较小的值替换现有的尾部。 这使得未来的延期机会尽可能灵活。 

最后，尺寸为`lis`作为答案返回。 

## 解决方案```go
package main

import (
	"sort"
)

func maxEnvelopes(envelopes [][]int) int {
	sort.Slice(envelopes, func(i, j int) bool {
		if envelopes[i][0] == envelopes[j][0] {
			return envelopes[i][1] > envelopes[j][1]
		}
		return envelopes[i][0] < envelopes[j][0]
	})

	lis := []int{}

	for _, envelope := range envelopes {
		height := envelope[1]

		position := sort.Search(len(lis), func(i int) bool {
			return lis[i] >= height
		})

		if position == len(lis) {
			lis = append(lis, height)
		} else {
			lis[position] = height
		}
	}

	return len(lis)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。`sort.Slice`用于自定义排序规则。 宽度相等的按高度降序排序。 

Go 没有内置的`bisect_left`像Python一样函数，所以`sort.Search`用于手动执行二分查找。 搜索找到存储的 LIS 尾部大于或等于当前高度的第一个索引。 

Go 中的切片会根据需要动态调整大小，因此附加新的 LIS 值非常简单。 

不存在整数溢出问题，因为信封尺寸最多为`10^5`，完全在 Go 的标准整数范围内。

 ## 边缘情况

 当多个信封具有相同宽度时，会出现一种重要的边缘情况。 由于嵌套需要严格增加宽度，因此宽度相同的信封绝不能一起出现在最终的链中。 幼稚的 LIS 高度方法可能会错误地允许这种情况发生。 高度降序排序通过确保等宽信封不能形成高度递增的子序列来防止该问题。 

另一个重要的情况是所有信封都相同。 例如：```
[[1,1],[1,1],[1,1]]
```每个信封都具有相同的宽度和高度，因此不可能嵌套。 LIS 算法正确地重复替换相同的位置，而不是扩展序列，结果是`1`。 

第三个关键情况是宽度增加但高度减少时：```
[[1,10],[2,9],[3,8],[4,7]]
```尽管宽度对于嵌套有效，但高度并不严格增加。 LIS 算法正确地识别出只能选择一个包络，因为每个新高度都会替换第一个 LIS 位置，而不是扩展子序列。 

当排序后最优序列不连续时，会发生另一种微妙的情况。 LIS 方法自然可以处理这个问题，因为它会全局搜索最佳子序列，而不是贪婪地获取每个可能的包络。 这就是二分搜索优化既高效又正确的原因。
