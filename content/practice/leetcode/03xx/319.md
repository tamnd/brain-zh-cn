[LeetCode 第 319 题](https://leetcode.com/problems/bulb-switcher/)

 **难度：** 🟡 中等
 **主题：** 数学、脑筋急转弯

 ## 解决方案

 ## 问题理解

 该问题描述了一系列`n`灯泡，最初全部关闭。 我们表演`n`对这些灯泡进行多轮操作。 在第一轮中，每个灯泡都打开。 在第二轮中，每隔一个灯泡就会切换一次，这意味着打开的灯泡会关闭，关闭的灯泡会打开。 在第三轮中，每三个灯泡被切换一次，依此类推，直到`n`第 轮，仅切换最后一个灯泡。 

目标是确定到底有多少灯泡仍然亮着`n`回合已完成。 

输入是单个整数`n`，代表灯泡数量和轮数。 输出是一个整数，表示最后仍然打开的灯泡数量。 

约束条件`0 <= n <= 10^9`非常重要。 这么大的值立即告诉我们直接模拟每个灯泡和每个切换操作是不切实际的。 时间复杂度接近的任何解决方案`O(n^2)`甚至`O(n log n)`对于上限来说太慢了。 这强烈表明该问题具有导致恒定时间或对数时间解决方案的数学观察或模式。 

一些边缘情况很重要：

 - 当`n = 0`，根本没有灯泡，所以答案一定是`0`。 
- 什么时候`n = 1`，唯一的灯泡打开一次，再也不会切换，所以答案是`1`。 
- 大值，例如`10^9`需要有效的数学解决方案，因为强力模拟是不可行的。 
- 完美平方的表现与其他数字不同，这成为最佳方法的关键见解。 

## 方法

 ### 蛮力方法

 解决这个问题最直接的方法就是完全按照描述模拟过程。 

我们可以创建一个数组`n`代表灯泡的布尔值。 最初，所有灯泡均`False`，意思是关闭。 每轮`i`，我们切换每个`i`th 灯泡。 所有回合完成后，我们计算剩余的灯泡数量。 

这种方法是正确的，因为它完全遵循问题陈述。 每个灯泡都会根据所需的轮次和切换规则进行更新。 

然而，性能却很差。 在最坏的情况下，我们大致执行：```
n + n/2 + n/3 + ... + n/n
```操作，大约是`O(n log n)`切换。 和`n`一样大`10^9`，这是不可能在时间限制内运行的。 内存使用量也很大，因为我们必须显式存储所有灯泡状态。 

### 关键数学见解

 我们不应该模拟切换，而应该问一个不同的问题：

 特定灯泡被切换了多少次？ 

考虑灯泡数量`k`。 每个除数都会切换一次`k`。 

例如，灯泡`12`在回合期间切换：```
1, 2, 3, 4, 6, 12
```因为那些是除数`12`。 

灯泡最终会变成：

 - 如果切换奇数次则开启
 - 如果切换偶数次则关闭

 大多数数字都有成对出现的约数。 

例如：```
12:
(1, 12)
(2, 6)
(3, 4)
```这给出了偶数个除数。 

但完全平方则不同。 

例如：```
9:
(1, 9)
(3, 3)
```平方根仅出现一次，而不是作为不同的对出现。 因此，完全平方数的因数为奇数。 

这意味着：

 - 只有处于完美方形位置的灯泡才会保持打开状态
 - 答案很简单，就是小于或等于的完全平方数`n`完全平方数小于或等于`n`是：$\lfloor\sqrt{n}\rfloor$所以整个问题简化为计算整数平方根`n`。

 ## 算法演练

 1.观察那个灯泡`k`对于每个除数都会切换一次`k`。 
2. 回想一下，除数通常成对出现。 例如，如果`2`划分`12`， 然后`6`也分`12`。 
3. 由于除数对贡献两次切换，因此大多数灯泡会切换偶数次并最终关闭。 
4. 完全平方是例外，因为它们的平方根除数是重复的。 例如，`16`有约数对`(4,4)`而不是两个不同的除数。 
5. 因此，完全平方数的约数为奇数，并且在所有轮之后仍然保持不变。 
6. 计算之间存在多少个完全平方数`1`和`n`。 
7.最大的完全平方数小于或等于`n`由整数平方根确定`n`。 
8. 返回`floor(sqrt(n))`。 

### 为什么它有效

 灯泡的最终状态完全取决于其指数有多少个除数。 具有偶数个除数的数字被切换偶数次并变为关闭。 具有奇数个除数的数字被切换奇数次并保持不变。 只有完美平方才有奇数个除数，因为一对除数在平方根处会折叠成单个重复除数。 因此，剩下的灯泡数量等于小于或等于的完全平方数`n`。 

## Python 解决方案```python
import math

class Solution:
    def bulbSwitch(self, n: int) -> int:
        return int(math.isqrt(n))
```实现故意非常小，因为数学观察消除了模拟的需要。 

这`math.isqrt()`函数计算整数平方根`n`，表示平方小于或等于的最大整数`n`。 

例如：

-`isqrt(9)`回报`3`-`isqrt(10)`也返回`3`这直接对应于小于或等于的完全平方数`n`。 

转换为`int`从技术上来说是不必要的，因为`isqrt()`已经返回一个整数，但它使意图明确并保持返回类型清晰。 

## 解决方案```go
package main

import "math"

func bulbSwitch(n int) int {
	return int(math.Sqrt(float64(n)))
}
```Go 实现使用`math.Sqrt`，其运行于`float64`价值观。 因此，我们首先转换`n`到`float64`，计算平方根，然后将结果转换回`int`。 

由于该问题只需要平方根的整数下限，因此通过以下方式截断浮点结果`int()`给出正确答案。 

与Python不同`math.isqrt`，Go 在标准库中没有提供专用的整数平方根函数，因此这种转换方法是标准做法。

 ## 边缘情况

 一个重要的边缘情况是`n = 0`。 一种幼稚的实现可能假设至少有一个灯泡并意外访问无效索引或返回`1`错误地。 数学解决方案可以自然地处理这个问题，因为`sqrt(0) = 0`。 

另一个关键的边缘情况是`n`本身是一个完美的正方形，例如`16`或者`25`。 这些值很重要，因为计数应包括平方本身。 正确使用平方根的整数下限包括这些情况。 例如，`floor(sqrt(25)) = 5`，这很重要`1, 4, 9, 16, 25`。 

第三个重要的边缘情况涉及正好低于完美平方的数字，例如`15`或者`24`。 这些案例验证了算法正确地对平方根取底而不是四舍五入。 例如，`sqrt(15)`大约是`3.87`，但只有完美的平方`1, 4, 9`有效，所以答案一定是`3`。 

大值，例如`10^9`也是重要的边缘情况，因为它们暴露了基于模拟的解决方案的低效率。 数学方法仍然有效，因为无论输入大小如何，它都只执行平方根计算。
