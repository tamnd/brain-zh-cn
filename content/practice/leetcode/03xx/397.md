 # LeetCode 397 - 整数替换

 ## 问题理解

 问题给了我们一个正整数`n`并要求将其转换为所需的最少操作次数`1`。 

在每一步中，我们都可以应用以下两个规则之一：

 - 如果数字是偶数，我们必须将其除以`2`- 如果数字是奇数，我们可以将其增加`1`或将其递减`1`目标是确定最终达到所需的尽可能少的操作数`1`。 

输入是单个整数`n`，输出是一个表示最小操作次数的整数。 

约束尤其重要：```
1 <= n <= 2^31 - 1
```这意味着输入可以大到`2147483647`，这是最大有符号 32 位整数。 因此，任何探索太多重复状态的强力搜索都将变得不可行。 该解决方案必须小心避免指数分支。 

一个微妙的细节是奇数引入了两种可能的选择，`n + 1`和`n - 1`。 一个幼稚的实现可能会递归地探索每个奇数的两种可能性，这很快就会变得昂贵。 

另一个重要的边缘情况是最大整数值`2^31 - 1`。 在具有固定宽度整数的语言中，添加`1`可能会溢出。 这在 Go 和许多其他编译语言中尤其重要。 

该问题保证输入始终为正，因此我们永远不需要处理零或负值。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用递归回溯。 

对于每个数字：

 - 如果是偶数，则递归求解`n / 2`- 如果是奇数，则递归计算两者：

 - 步骤`n + 1`- 步骤`n - 1`- 取最小结果

 这保证了正确性，因为它会探索每种可能的操作序列并选择最短的一个。 

然而，这种方法效率极低，因为许多状态被重复重新计算。 例如，不同的递归路径最终可能到达相同的中间数。 如果没有缓存，递归树会呈指数增长。 

对于附近的大值`2^31 - 1`，暴力解决方案变得太慢了。 

### 最佳方法

 关键的见解是，对于奇数，我们实际上不需要盲目地探索两个分支。 

我们希望尽快让数字可以被二的更高次幂整除，因为除以二会迅速缩小数字。 

对于奇数：

 - 如果减去`1`产生更多的尾随零位，通常更好
 - 如果添加`1`产生更多的尾随零位，通常更好

 这导致了贪婪的位操作观察：

 - 如果`n == 3`或者第二个最低有效位是`0`， 使用`n - 1`- 否则使用`n + 1`以二进制表示：

 - 结尾的数字`01`从减法中获益
 - 结尾的数字`11`受益于添加

 示例：```
5  = 101
5 - 1 = 100   -> divisible by 4

7  = 111
7 + 1 = 1000  -> divisible by 8
```该策略最大限度地减少了未来操作的数量。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|

 这里，`k`表示递归分支决策的数量。 

## 算法演练

 ### 最优贪婪位操作算法

 1.从输入整数开始`n`并初始化一个操作计数器`0`。 
2. 继续处理直至`n`变成`1`。 
3.如果`n`是偶数，除以`2`。 

这始终是最佳的，因为减半会尽快减少数量。 
4. 如果`n`是奇数，决定是递增还是递减。 

对于奇数，检查二进制表示：

 - 如果`n == 3`, 减去`1`- 否则如果最后两位是`11`， 添加`1`- 否则减去`1`5. 每次转换后增加操作计数器。 
6.返回一次总操作次数`n`达到`1`。 

### 为什么它有效

 该算法之所以有效，是因为二的幂是理想状态。 一旦一个数成为 2 的幂，重复除以`2`将其减少为`1`非常快。 

对于奇数，加或减`1`将数字转换为偶数。 贪心策略选择在二进制中创建最大数量的尾随零位的操作，因为这样可以实现未来的多次除法`2`。 

唯一的特殊情况是`3`：```
3 -> 2 -> 1   (2 steps)
3 -> 4 -> 2 -> 1   (3 steps)
```所以`3`必须用减法。 

## Python 解决方案```python
class Solution:
    def integerReplacement(self, n: int) -> int:
        operations = 0

        while n != 1:
            if n % 2 == 0:
                n //= 2
            else:
                if n == 3 or (n & 2) == 0:
                    n -= 1
                else:
                    n += 1

            operations += 1

        return operations
```实现直接遵循贪心算法。 

变量`operations`跟踪已执行的转换次数。 

循环内部：

 - 偶数立即减半
 - 使用位操作分析奇数

 表达式：```python
(n & 2) == 0
```检查第二个最低有效位。 

例如：```python
5 = 101
5 & 2 = 0
```这意味着二进制形式以`01`，因此最好减去。 

同时：```python
7 = 111
7 & 2 = 2
```这意味着二进制形式以`11`，所以最好添加。 

循环继续直到`n`变成`1`。 

## 解决方案```go
func integerReplacement(n int) int {
    operations := 0

    for n != 1 {
        if n%2 == 0 {
            n /= 2
        } else {
            if n == 3 || (n&2) == 0 {
                n--
            } else {
                n++
            }
        }

        operations++
    }

    return operations
}
```Go 实现与 Python 版本几乎相同。 

一个重要的考虑因素是整数溢出。 该问题允许值高达`2^31 - 1`，并添加`1`在某些语言中，达到此值可能会溢出有符号 32 位整数。 

去的`int`现代平台上的类型通常是 64 位，因此此实现可以安全地处理增量操作。 如果使用严格的 32 位整数类型，则需要额外小心。 

Go 中的位运算使用与许多 C 风格语言相同的语法，因此检查`(n & 2)`工作方式与 Python 中完全相同。

 ## 边缘情况

 ### 边缘情况 1：`n = 1`这是可能的最小输入，也是终止条件。 

有缺陷的实现可能会意外执行不必要的操作或错误地进入循环。 提供的解决方案可以自然地处理这个问题，因为循环条件：```
while n != 1:
```立即失败，返回`0`。 

### 边缘情况 2：`n = 3`这是贪婪的“以 11 结尾时相加”规则失败的唯一奇数。 

二进制：```
3 = 11
```通常，数字结尾为`11`增加。 然而：```
3 -> 4 -> 2 -> 1
```需要三个操作，同时：```
3 -> 2 -> 1
```只需要两个。 

实现明确检查：```
if n == 3
```以保证最优路径。 

### 边缘情况 3：最大整数值

 最大输入为：```
2147483647 = 2^31 - 1
```添加`1`产生：```
2147483648
```在使用 32 位有符号整数的语言中可能会溢出。 

该实现通过使用 Python 的任意精度整数和 Go 的平台大小来避免问题`int`，在现代系统上通常是 64 位。 

即使在约束范围的边界，这也确保了正确性。
