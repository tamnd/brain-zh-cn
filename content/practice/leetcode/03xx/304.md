[LeetCode 问题 304](https://leetcode.com/problems/range-sum-query-2d-immutable/)

 **难度：** 🟡 中等
 **主题：** 数组、设计、矩阵、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种数据结构，能够有效地回答固定二维矩阵上的多个矩形和查询。 

我们给出一个整数矩阵，每个查询指定四个坐标：

 -`(row1, col1)`代表矩形的左上角
 -`(row2, col2)`代表矩形的右下角

 对于每个查询，我们必须返回该矩形内所有元素的总和，包括两个边界。 

重要的细节是矩阵在初始化后永远不会改变。 这使得问题“不可变”，这意味着我们只需要对矩阵进行一次预处理，然后支持快速只读查询。 

一个简单的解决方案是通过迭代请求区域中的所有单元格来重新计算矩形和。 这在功能上是有效的，但是当执行许多查询时，它会变得低效。 该问题明确要求`sumRegion`跑进去`O(1)`时间，这强烈建议进行预处理。 

这些约束有助于阐明预期的解决方案：

 -`m, n <= 200`，所以矩阵不是很大
 - 最多`10^4`打电话给`sumRegion`可能发生
 - 矩阵值可以为负，因此我们不能依赖单调属性或剪枝
 - 保证矩阵至少包含一个元素

 与相对较小的矩阵大小相比，大量的查询告诉我们预处理是值得的。 开支`O(m * n)`如果之后允许常量查询，那么构建期间的时间是可以接受的。 

一些边缘情况很重要：

 - 查询可能需要单个单元格
 - 查询可能跨越整个矩阵
 - 查询可以从行开始`0`或列`0`- 矩阵值可能为负
 - 矩形可能只包含一行或一列

 最大的实施挑战是正确处理边界而不产生相差一的错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是直接计算每个查询的总和。 

对于每个`sumRegion(row1, col1, row2, col2)`调用，我们迭代每一行`row1`到`row2`，以及每列`col1`到`col2`，将所有值加在一起。 

这种方法是正确的，因为它明确地访问了所请求矩形内的每个元素一次。 

然而，当执行许多查询时，这会变得低效。 在最坏的情况下，查询可能覆盖整个矩阵，需要`O(m * n)`每个查询的工作量。 由于截至`10^4`如果允许查询，则总运行时间可能会变得非常大。 

### 最优方法，2D 前缀和

 关键的观察结果是矩阵永远不会改变。 因此，我们可以对累积和进行一次预处理，然后在每个查询中重复使用它们。 

我们构造一个 2D 前缀和矩阵，其中每个单元格存储从左上角开始的所有元素的总和`(0,0)`到当前位置。 

使用此结构，可以使用包含-排除来计算任何矩形和：

 - 从大矩形的总和开始`(0,0)`到`(row2,col2)`- 减去目标矩形上方的区域
 - 减去目标矩形左侧的区域
 - 添加回减去两次的重叠区域

 这将每个查询转换为恒定数量的算术运算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(m * n)`每个查询 |`O(1)`| 迭代矩形中的每个单元格 |
 | 最佳|`O(1)`预处理后的每个查询 |`O(m * n)`| 使用 2D 前缀和矩阵 |

 ## 算法演练

 ### 第 1 步：创建前缀和矩阵

 我们建立一个新的矩阵，称为`prefix`有尺寸`(rows + 1) x (cols + 1)`。 

额外的行和列简化了边界处理。 我们可以安全地使用索引算术，而不是不断检查索引是否为负数。 

每个`prefix[r][c]`存储矩形中所有值的总和`(0,0)`到`(r-1,c-1)`在原始矩阵中。 

### 步骤 2：填充前缀和矩阵

 对于原始矩阵中的每个单元，计算：$prefix[r][c]=matrix[r-1][c-1]+prefix[r-1][c]+prefix[r][c-1]-prefix[r-1][c-1]$这个公式之所以有效是因为：

 -`prefix[r-1][c]`包含上面的总和
 -`prefix[r][c-1]`包含左边的总和
 - 重叠`prefix[r-1][c-1]`被计算两次，所以我们减去一次
 - 最后添加当前矩阵值

 ### 步骤 3：使用包含-排除回答查询

 计算矩形的总和：

 - 从整个区域开始`(0,0)`到`(row2,col2)`- 删除目标矩形上方的行
 - 删除目标矩形左侧的列
 - 添加回重叠

 查询公式变为：$sum=prefix[row2+1][col2+1]-prefix[row1][col2+1]-prefix[row2+1][col1]+prefix[row1][col1]$现在每个查询都需要恒定的时间，因为它只使用四次表查找。 

### 为什么它有效

 前缀矩阵保持每个条目包含从原点到该位置的所有元素之和的不变式。 

由于矩形区域可以表示为重叠的较大矩形的组合，因此包含-排除可保证目标矩形内的每个元素都被精确计数一次，而所有外部元素都会被抵消。 

## Python 解决方案```python
from typing import List

class NumMatrix:

    def __init__(self, matrix: List[List[int]]):
        rows = len(matrix)
        cols = len(matrix[0])

        # Extra row and column for easier boundary handling
        self.prefix = [[0] * (cols + 1) for _ in range(rows + 1)]

        for r in range(1, rows + 1):
            for c in range(1, cols + 1):
                self.prefix[r][c] = (
                    matrix[r - 1][c - 1]
                    + self.prefix[r - 1][c]
                    + self.prefix[r][c - 1]
                    - self.prefix[r - 1][c - 1]
                )

    def sumRegion(self, row1: int, col1: int, row2: int, col2: int) -> int:
        return (
            self.prefix[row2 + 1][col2 + 1]
            - self.prefix[row1][col2 + 1]
            - self.prefix[row2 + 1][col1]
            + self.prefix[row1][col1]
        )

# Your NumMatrix object will be instantiated and called as such:
# obj = NumMatrix(matrix)
# param_1 = obj.sumRegion(row1, col1, row2, col2)
```该实现首先在初始化期间构造一个 2D 前缀和矩阵。 

添加额外的行和列，以便每个矩形计算保持统一，即使查询触及顶部或左侧边框也是如此。 如果没有这个填充，实现将需要多个条件检查。 

嵌套循环增量地计算累积和。 每个单元结合：

 - 当前矩阵值，
 - 上述累计总和，
 - 左边的累计总和，
 - 减去计算两次的重叠区域。 

这`sumRegion`方法然后直接应用包含-排除公式。 由于所有预处理都已完成，因此查询仅需要四次数组访问和三次算术运算。 

## 解决方案```go
type NumMatrix struct {
	prefix [][]int
}

func Constructor(matrix [][]int) NumMatrix {
	rows := len(matrix)
	cols := len(matrix[0])

	prefix := make([][]int, rows+1)

	for i := range prefix {
		prefix[i] = make([]int, cols+1)
	}

	for r := 1; r <= rows; r++ {
		for c := 1; c <= cols; c++ {
			prefix[r][c] =
				matrix[r-1][c-1] +
					prefix[r-1][c] +
					prefix[r][c-1] -
					prefix[r-1][c-1]
		}
	}

	return NumMatrix{
		prefix: prefix,
	}
}

func (this *NumMatrix) SumRegion(row1 int, col1 int, row2 int, col2 int) int {
	return this.prefix[row2+1][col2+1] -
		this.prefix[row1][col2+1] -
		this.prefix[row2+1][col1] +
		this.prefix[row1][col1]
}

/**
 * Your NumMatrix object will be instantiated and called as such:
 * obj := Constructor(matrix);
 * param_1 := obj.SumRegion(row1,col1,row2,col2);
 */
```Go 的实现与 Python 解决方案非常相似。 

使用切片而不是数组，因为矩阵维度是在运行时确定的。 Go 自动将整数切片初始化为零，这使得构造填充前缀矩阵变得简单。 

问题约束保证整数溢出对于标准 Go 来说不是问题`int`价值观。

 ## 边缘情况

 ### 触及顶部或左侧边框的查询

 从 row 开始的矩形`0`或列`0`是差一错误的常见来源。 

如果不小心处理，减法公式可能会尝试访问负索引。 该实现通过使用填充的前缀矩阵来完全避免这种情况，其中一个额外的行和列初始化为零。 

这允许每个查询统一使用相同的公式，无论矩形是否接触边框。 

### 单单元格查询

 一个矩形可能只包含一个元素。 

这很重要，因为某些实现意外地将范围视为排他性而不是包容性。 即使在以下情况下，前缀和公式也能正确工作：`row1 == row2`和`col1 == col2`，因为包含-排除算法仍然精确地隔离一个值。 

### 负数

 矩阵可以包含负整数。 

一些优化策略依赖于单调和或值非负的假设，但这些方法在这里会失败。 前缀和无论符号如何都有效，因为它们纯粹是算术累加。 

该实现可以正确处理负总数、混合值和取消效应，而不需要任何特殊逻辑。
