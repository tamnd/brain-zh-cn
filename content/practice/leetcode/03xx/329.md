[LeetCode 第 329 题](https://leetcode.com/problems/longest-increasing-path-in-a-matrix/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、深度优先搜索、广度优先搜索、图论、拓扑排序、记忆化、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二维整数网格，称为`matrix`。 网格中的每个位置都包含一个值，我们被要求找到最长严格递增路径的长度。 

路径从任何单元格开始，并沿四个方向之一每次移动一步：上、下、左或右。 不允许对角线移动，并且我们不能移动到矩阵边界之外。 仅当目标单元格包含严格大于当前单元格的值时，移动才有效。 

我们返回的结果不是路径本身，而是最长有效递增序列中的单元格数量。 

例如，考虑矩阵：```
[
  [9, 9, 4],
  [6, 6, 8],
  [2, 1, 1]
]
```一种有效的增长路径是：```
1 -> 2 -> 6 -> 9
```这条路有长度`4`，这是可能的最大值，所以答案是`4`。 

约束条件很重要：

 -`m`和`n`每个都可以大到`200`- 因此矩阵可能包含最多`40,000`细胞
 - 单元格值可以是非常大的整数

 由于许多子问题重叠，每个单元的简单递归探索很快就会变得非常昂贵。 在计算来自不同起始位置的路径时，可以重复地重新访问相同的单元。 

一些边缘情况尤其重要：

 - 应返回只有一个单元格的矩阵`1`- 还应该返回所有值都相同的矩阵`1`，因为不存在递增移动
 - 严格递减矩阵仍然返回`1`对于每一个起点
 - 多个路径可能会收敛到同一个子路径，这会在简单的解决方案中产生大量的重复计算
 - 大型矩阵需要有效的解决方案，因为指数探索会超时

 这个问题本质上是一个伪装成矩阵问题的图问题。 每个单元格都可以被视为一个节点，边从较小的值到较大的相邻值存在。 因为值必须严格增加，所以循环是不可能的，这使得该图成为有向无环图（DAG）。 

## 方法

 ### 蛮力方法

 最直接的解决方案是从矩阵中的每个单元格开始深度优先搜索。 

对于每个起始单元格，我们递归地尝试在所有四个方向上移动。 每当相邻像元包含较大值时，我们就继续从该邻居开始搜索。 我们计算从当前单元格可到达的最大路径长度并将其返回。 

这种方法是正确的，因为它详尽地探索了每条有效的增长路径。 

问题在于它多次重新计算相同的子问题。 假设多条路径到达同一个单元格。 每次到达该单元格时，我们都会递归地重新计算从该单元格开始的最长路径。 在最坏的情况下，这种重复会呈指数级增长。 

对于大小矩阵`200 x 200`，强力递归变得完全不切实际。 

### 关键见解

 关键的观察结果是，从特定单元格开始的最长增加路径始终相同，无论我们如何到达该单元格。 

这意味着该问题具有重叠的子问题，这使其成为记忆化的完美候选者。 

我们不会重复重新计算单元格的答案，而是计算一次并缓存结果。 未来的调用只需重用存储的值即可。 

因为路径必须严格递增，所以循环不可能存在。 因此，我们有一个 DAG 结构，并且具有记忆功能的 DFS 可以有效地计算来自每个节点的最长路径一次。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^(m*n)) 最坏情况 | O(m*n) 递归堆栈 | 重复重新计算相同的路径 |
 | 最佳 DFS + 记忆 | O(m*n) | O(m*n) | 每个单元格计算一次并缓存 |

 ## 算法演练

 ### 最优 DFS + 记忆算法

 1. 创建一个与矩阵尺寸相同的记忆表。 

每个条目`memo[row][col]`存储从该单元格开始的最长递增路径的长度。 最初，所有值都是`0`，意思是“尚未计算”。 
2. 定义四个可能的移动方向。 

我们只允许：

 - 向上
 - 向下
 - 左
 - 右

 这些方向存储在一个小列表中，以便我们可以在 DFS 期间干净地迭代。 
3. 定义DFS 函数。 

DFS 函数计算从特定单元开始的最长递增路径。 

如果当前单元格的结果已存在于备注表中，则立即返回它。 这避免了重新计算。 
4. 初始化当前单元的最佳路径长度为`1`。 

每个单元格本身形成一条有效的长度递增路径`1`。 
5. 探索所有四个相邻单元格。 

对于每个邻居：

 - 检查边界条件
 - 检查邻居值是否严格大于

 如果两个条件都满足，则递归计算来自邻居的最长路径。 
6. 更新当前单元格的答案。 

如果移动到邻居会产生更长的路径，则更新最佳值：```
best = max(best, 1 + dfs(neighbor))
```7. 将计算结果存储在备注表中。 

处理完所有邻居后，保存该单元格的最终答案。 
8. 从每个单元运行 DFS。 

由于最长的整体路径可以从任何地方开始，因此迭代整个矩阵并计算：```
answer = max(answer, dfs(row, col))
```9. 返回全局最大值。 

### 为什么它有效

 该算法之所以有效，是因为每条递增路径都形成一个 DAG。 由于值必须严格增加，循环是不可能的。 DFS 探索来自单元格的所有可到达的递增路径，而记忆化则保证每个单元格的结果仅计算一次。 

不变量是：```
memo[row][col] =
length of the longest increasing path starting at (row, col)
```由于所有递归依赖项都朝着严格更大的值移动，因此先前计算的结果始终有效且可重用。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestIncreasingPath(self, matrix: List[List[int]]) -> int:
        rows = len(matrix)
        cols = len(matrix[0])

        memo = [[0] * cols for _ in range(rows)]

        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1)
        ]

        def dfs(row: int, col: int) -> int:
            if memo[row][col] != 0:
                return memo[row][col]

            longest = 1

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    0 <= new_row < rows
                    and 0 <= new_col < cols
                    and matrix[new_row][new_col] > matrix[row][col]
                ):
                    candidate = 1 + dfs(new_row, new_col)
                    longest = max(longest, candidate)

            memo[row][col] = longest
            return longest

        answer = 0

        for row in range(rows):
            for col in range(cols):
                answer = max(answer, dfs(row, col))

        return answer
```实现首先确定矩阵维度并分配记忆表。 每个条目在`memo`存储从该单元格开始计算的最长路径。 

这`directions`list 集中了移动逻辑并避免了邻居遍历的重复代码。 

这`dfs`函数执行核心计算。 第一个操作检查当前单元格是否已被求解。 如果是，则立即返回缓存的结果。 

变量`longest`开始于`1`因为当前单元格本身就形成了一条有效的路径。 

然后该函数迭代所有相邻位置。 对于每个有效的递增邻居，它递归地计算邻居的最长路径并将其扩展一。 

探索完所有邻居后，计算结果存储在`memo[row][col]`。 

最后，外层循环从每个单元开始 DFS 并跟踪全局最大路径长度。 

## 解决方案```go
func longestIncreasingPath(matrix [][]int) int {
	rows := len(matrix)
	cols := len(matrix[0])

	memo := make([][]int, rows)
	for i := range memo {
		memo[i] = make([]int, cols)
	}

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	var dfs func(int, int) int

	dfs = func(row int, col int) int {
		if memo[row][col] != 0 {
			return memo[row][col]
		}

		longest := 1

		for _, dir := range directions {
			newRow := row + dir[0]
			newCol := col + dir[1]

			if newRow >= 0 &&
				newRow < rows &&
				newCol >= 0 &&
				newCol < cols &&
				matrix[newRow][newCol] > matrix[row][col] {

				candidate := 1 + dfs(newRow, newCol)

				if candidate > longest {
					longest = candidate
				}
			}
		}

		memo[row][col] = longest
		return longest
	}

	answer := 0

	for row := 0; row < rows; row++ {
		for col := 0; col < cols; col++ {
			current := dfs(row, col)

			if current > answer {
				answer = current
			}
		}
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 主要区别在于备忘录表的显式切片分配以及递归 DFS 的函数变量的使用。 

Go不直接支持嵌套命名函数，所以我们声明`dfs`在分配递归闭包之前作为变量。 

整数溢出不是问题，因为最大路径长度最多受单元数量限制`40,000`。 

使用 Go 切片而不是固定大小的数组，因为矩阵尺寸是在运行时确定的。

 ## 边缘情况

 ### 单细胞矩阵

 仅包含一个元素的矩阵是最小的有效输入。 幼稚的实现可能会意外返回`0`如果它假设至少需要一步。 

该实现正确地将每个路径长度初始化为`1`，意味着单个单元格单独形成有效路径。 

### 所有值都相等

 如果每个单元格包含相同的值，则不可能增加移动，因为移动需要严格更大的值。 

如果条件使用的话，这种情况很容易误处理`>=`而不是`>`。 

实现明确检查：```
matrix[new_row][new_col] > matrix[row][col]
```所以永远不会遍历相等的值。 

### 大型重叠子问题

 在大型矩阵中，许多路径可能会汇聚到同一区域。 如果没有记忆，相同的 DFS 计算将呈指数级重复多次。 

例如，几个相邻小区最终可能全部通向同一递增链。 记忆化保证一旦计算出单元的最长路径，它就可以在其他地方重用。 

这种优化将复杂性从相对于单元数量的指数时间降低到线性时间。
