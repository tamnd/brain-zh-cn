 **难度：** 🔴难
 **主题：** 数组、二分查找、分而治之、二叉索引树、线段树、归并排序、有序集

 ## 解决方案

 ## 问题理解

 该问题要求我们计算数组中的每个元素，其右侧有多少元素严格小于它。 

给定一个数组`nums`，我们必须返回另一个数组`counts`相同长度的。 对于每个索引`i`,`counts[i]`表示索引的数量`j`这样：

 -`j > i`-`nums[j] < nums[i]`换句话说，对于每个数字，我们只查看数组中出现在该数字之后的元素，并计算其中有多少个元素较小。 

例如，在数组中`[5,2,6,1]`:

 -`5`后面有两个较小的数字，`2`和`1`-`2`后面有一个较小的数字，`1`-`6`后面有一个较小的数字，`1`-`1`没有

 所以结果是`[2,1,1,0]`。 

约束条件很重要：

 - 该数组最多可以包含`10^5`元素
 - 值范围为`-10^4`到`10^4`比较每对元素的简单解决方案需要`O(n^2)`时间，当它变得太慢时`n = 100000`。 二次算法可能会执行以下操作`10^10`比较，这在典型的 LeetCode 时间限制内是不可行的。 

该问题保证输入数组非空，但一些边缘情况仍然很重要：

 - 具有一个元素的数组
 - 具有重复值的数组
 - 数组已经按升序排序
 - 数组按降序排序
 - 负数
 - 重复的负数

 正确处理重复项尤其重要，因为我们只计算严格较小的元素，而不计算相等的元素。 

## 方法

 ### 蛮力方法

 最简单的方法是独立处理每个索引。 

对于每个元素`nums[i]`，我们扫描其右侧的所有元素并计算有多少小于`nums[i]`。 这直接遵循问题定义并且易于实现。 

该算法之所以有效，是因为它显式检查每个有效对`(i, j)`在哪里`j > i`。 如果`nums[j] < nums[i]`，我们增加索引的计数`i`。 

然而，这种方法对于大型阵列表现不佳。 由于每个元素可能会扫描数组的几乎整个剩余部分，因此比较总数变为：$$1 + 2 + 3 + \dots + (n-1) = O(n^2)$$和`n = 100000`，这太慢了。 

### 最优方法，改进的归并排序

 关键的见解是这个问题类似于倒数计数。 

在归并排序过程中，数组按排序顺序重复划分和合并。 在合并两个已排序的一半时，我们可以确定右半部分中有多少元素小于左半部分的元素。 

假设我们要合并：

 - 左半部分：最初出现较早的已排序元素
 - 右半部分：最初出现较晚的已排序元素

 如果在合并过程中将右半部分的元素放置在左半部分的元素之前，则该右侧元素较小，并且最初出现在数组中左侧元素之后。 

这意味着我们可以在合并过程本身期间累积计数。 

重要的优化是合并排序已经按排序顺序组织元素，使我们能够一次计算许多关系，而不是单独检查每一对。 

因为归并排序运行在`O(n log n)`时间上，这种方法对于约束来说足够有效。

 ## 算法演练

 ### 最优归并排序算法

 1. 创建一个包含值及其原始索引的对数组。 

我们不能直接对数组进行排序，因为我们必须按原始顺序返回答案。 每个元素存储为：```
(value, original_index)
```例子：```
nums = [5,2,6,1]

pairs = [
    (5,0),
    (2,1),
    (6,2),
    (1,3)
]
```2. 初始化一个用零填充的结果数组。 

该数组存储每个原始索引的最终计数。```
result = [0,0,0,0]
```3. 使用归并排序递归划分数组。 

归并排序将数组分成两半，直到每个子数组包含一个元素。 

单元素数组已经排序。 
4. 合并已排序的两半，同时计算较小的元素。 

合并时，维护两个指针：

 - 左半部分有一个指针
 - 右半区的一根指针

 还维护一个变量：```
right_smaller_count
```这表示右半部分中有多少元素已放置在当前左元素之前。 
5. 比较两半的元素。 

如果右边的元素更小：```
right_value < left_value
```那么：

 - 应首先合并正确的元素
 - 它为所有剩余的左侧元素贡献一个较小的元素
 - 增量`right_smaller_count`6. 将左侧元素放入合并数组时，更新其答案。 

自从`right_smaller_count`右半部分的元素已经移到它前面，所有这些元素是：

 - 原来在它的右边
 - 比它小

 所以：```
result[left_index] += right_smaller_count
```7. 继续直至合并完成。 

最终，每个合并操作都会为适当的索引贡献计数。 
8. 归并排序结束后返回结果数组。 

### 为什么它有效

 正确性来自合并排序不变量。 

在每个合并步骤：

 - 左半部分包含最初出现较早的元素
 - 右半部分包含最初出现较晚的元素
 - 两半都已排序

 在合并过程中，只要右半部分的元素移动到左半部分元素的前面，它就表示原始数组中稍后出现的较小元素。 

因为合并排序只处理一次所有此类关系，所以每个较小右关系都会被正确计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def countSmaller(self, nums: List[int]) -> List[int]:
        n = len(nums)
        result = [0] * n
        
        indexed_nums = [(nums[i], i) for i in range(n)]
        
        def merge_sort(left: int, right: int) -> None:
            if left >= right:
                return
            
            mid = (left + right) // 2
            
            merge_sort(left, mid)
            merge_sort(mid + 1, right)
            
            merge(left, mid, right)
        
        def merge(left: int, mid: int, right: int) -> None:
            temp = []
            
            i = left
            j = mid + 1
            
            right_smaller_count = 0
            
            while i <= mid and j <= right:
                if indexed_nums[j][0] < indexed_nums[i][0]:
                    temp.append(indexed_nums[j])
                    right_smaller_count += 1
                    j += 1
                else:
                    value, original_index = indexed_nums[i]
                    result[original_index] += right_smaller_count
                    temp.append(indexed_nums[i])
                    i += 1
            
            while i <= mid:
                value, original_index = indexed_nums[i]
                result[original_index] += right_smaller_count
                temp.append(indexed_nums[i])
                i += 1
            
            while j <= right:
                temp.append(indexed_nums[j])
                j += 1
            
            for k in range(len(temp)):
                indexed_nums[left + k] = temp[k]
        
        merge_sort(0, n - 1)
        
        return result
```实现首先将每个值与其原始索引配对。 这是必要的，因为合并排序会重新排列元素，但最终答案必须与原始位置相对应。 

这`result`数组存储每个索引的较小元素的数量。 

递归`merge_sort`函数对数组进行划分，直到子数组仅包含一个元素。 由于单元素数组已经排序，因此递归开始向上合并。 

真正的逻辑发生在内部`merge`功能。 两个已排序的半部分被合并，同时跟踪有多少右半部分元素已放置在当前左半部分元素之前。 

每当右侧值较小时，它就会增加`right_smaller_count`。 稍后，当左侧元素插入到合并数组中时，该计数将添加到其答案中。 

最后将合并结果复制回`indexed_nums`，保留更高合并级别的排序顺序。 

## 解决方案```go
func countSmaller(nums []int) []int {
	n := len(nums)

	result := make([]int, n)

	type Pair struct {
		value int
		index int
	}

	indexedNums := make([]Pair, n)

	for i := 0; i < n; i++ {
		indexedNums[i] = Pair{
			value: nums[i],
			index: i,
		}
	}

	var mergeSort func(int, int)

	mergeSort = func(left int, right int) {
		if left >= right {
			return
		}

		mid := (left + right) / 2

		mergeSort(left, mid)
		mergeSort(mid+1, right)

		merge(left, mid, right)
	}

	merge := func(left int, mid int, right int) {
		temp := make([]Pair, 0, right-left+1)

		i := left
		j := mid + 1

		rightSmallerCount := 0

		for i <= mid && j <= right {
			if indexedNums[j].value < indexedNums[i].value {
				temp = append(temp, indexedNums[j])
				rightSmallerCount++
				j++
			} else {
				result[indexedNums[i].index] += rightSmallerCount
				temp = append(temp, indexedNums[i])
				i++
			}
		}

		for i <= mid {
			result[indexedNums[i].index] += rightSmallerCount
			temp = append(temp, indexedNums[i])
			i++
		}

		for j <= right {
			temp = append(temp, indexedNums[j])
			j++
		}

		for k := 0; k < len(temp); k++ {
			indexedNums[left+k] = temp[k]
		}
	}

	mergeSort(0, n-1)

	return result
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 主要区别在于 Go 需要显式的`Pair`结构体来存储值和原始索引。 

切片用于临时合并存储。 由于 Go 不支持与 Python 完全相同的嵌套函数声明，因此函数变量在赋值之前声明。 

整数溢出不是问题，因为对于 Go 的标准来说，约束足够小`int`类型。

 ## 边缘情况

 ### 具有重复值的数组

 重复处理是最容易引入错误的地方之一。 该问题要求严格较小的元素，而不是更小或等于的元素。 

例如：```
[-1,-1]
```应该产生：```
[0,0]
```在合并期间，算法仅在以下情况下增加计数：```
right_value < left_value
```不是当值相等时。 这保证了正确处理重复项。 

### 已按升序排序的数组

 在升序数组中，例如：```
[1,2,3,4]
```每个元素的右侧已经没有更小的元素了。 

错误的实现可能会在合并过程中意外地错误地计算反转。 在此实现中，仅当右侧元素严格较小时才会首先移动，因此不会添加计数。 

结果仍然正确：```
[0,0,0,0]
```### 降序数组

 降序数组创建最大可能的计数。 

例子：```
[4,3,2,1]
```每个元素都比它后面的所有元素都大。 

这种情况强调合并过程是否正确地跨递归合并级别累积许多较小的元素。 该算法自然地处理这个问题，因为每个右半插入都会递增`right_smaller_count`，然后将其添加到所有剩余的左半元素。 

最终结果变成：```
[3,2,1,0]
```这是正确的。
