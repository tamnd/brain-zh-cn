 ## 解决方案

 ## 问题理解

 该问题是经典的房屋强盗动态规划问题的变体，但房屋不是按直线排列，而是形成二叉树。 

二叉树中的每个节点代表一栋房子，节点中存储的值代表该房子的可用金额。 小偷想要最大化被盗的总金额，但有一个重要的限制：两栋直接相连的房屋不能在同一晚同时被抢劫。 在树术语中，这意味着父级及其子级不能同时被选择。 

输入是二叉树的根节点。 每个节点可能有一个左子节点、一个右子节点、两者都有或都没有。 输出应该是一个整数，表示在遵守邻接限制的情况下可以被盗的最大金额。 

这些约束告诉我们一些重要的事情：

 - 树最多可以包含`10^4`节点。 
- 节点值可以大到`10^4`。 
- 不保证树是平衡的。 

由于树可能很大，指数暴力解决方案将无法及时完成。 我们需要一种接近线性时间的算法。 

一些边缘情况很重要：

 - 一棵只有一个节点的树。 在这种情况下，答案就是该节点的值。 
- 行为类似于链表的倾斜树。 递归深度和重复计算成为重要的考虑因素。 
- 有价值的节点`0`。 有时，即使节点存在，跳过该节点也会更好。 
- 抢孙子比抢孩子更好的树。 
- 抢夺根部的树木会阻碍高价值儿童的接触。 

核心挑战是决定对于每个节点，抢劫它是否会比跳过它产生更好的总数。 

## 方法

 ### 蛮力方法

 一种简单的递归方法是在每个节点考虑两个选择：

 1.抢夺当前节点。 
2. 跳过当前节点。 

如果我们抢夺当前节点，我们就无法抢夺它的直接子节点，因此我们递归地计算孙子节点的最佳值。 

如果我们跳过当前节点，我们可以独立地抢夺或跳过每个子节点，因此我们递归地计算子节点的最佳值。 

从概念上讲，递归看起来像这样：

 -`rob(node) = node.val + rob(grandchildren)`-`skip(node) = rob(children)`- 答案是`max(rob(node), skip(node))`这种方法是正确的，因为它详尽地探索了所有有效的组合。 

然而，它的效率极低，因为相同的子树被重新计算很多次。 例如，子树可以作为“抢夺父项”场景的一部分被评估一次，并且作为“跳过父项”场景的一部分被再次评估。 这种重叠的工作会导致指数时间复杂度。 

### 最优动态规划方法

 关键的见解是每个节点只需要两条信息：

 1.该节点被抢后可获得的最大金钱。 
2.跳过该节点可获得的最大金钱。 

我们不是重复地重新计算子问题，而是使用后序遍历为每个节点计算一次这两个值。 

对于一个节点：

 - 如果我们抢劫它，我们就不能抢劫它的孩子。 
- 如果我们跳过它，每个孩子都可以独立地被抢劫或跳过，以给出更大的值为准。 

这自然会导致树动态规划。 

对于每个节点，我们返回一对：

 -`rob_current`-`skip_current`使用左右子节点的结果，我们计算当前节点在恒定时间内的最佳状态。 

因为每个节点都被处理一次，所以解变成线性的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(h) | 重复重新计算相同的子树 |
 | 最佳 | O(n) | O(h) | 使用后序遍历的树DP |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 定义一个每次处理一个节点的递归 DFS 函数。 

该函数应返回两个值：

 - 如果当前节点被抢劫，则可获得最大金钱。 
- 如果当前节点被跳过，则可获得最大金钱。 

同时返回两个值可以避免重新计算。 
2. 处理基本情况。 

如果节点是`None`， 返回`(0, 0)`因为无论我们抢劫还是跳过，空子树都不会贡献任何金钱。 
3. 递归处理左子树。 

递归调用返回：

 -`left_rob`-`left_skip`4. 递归处理右子树。 

递归调用返回：

 -`right_rob`-`right_skip`5. 计算抢当前节点时的值。 

如果我们抢夺当前节点，我们就无法抢夺任何一个子节点。 

所以：```
rob_current = node.val + left_skip + right_skip
```6. 计算跳过当前节点时的值。 

如果我们跳过当前节点，每个子节点都会独立选择其更好的选项。 

所以：```
skip_current = max(left_rob, left_skip) + max(right_rob, right_skip)
```7. 将两个值向上返回。 

父节点将使用这些结果来计算自己的状态。 
8. 处理完根后，取两个返回值中的最大值。 

根本身可能会也可能不会被抢劫，这取决于哪个会产生更大的结果。 

### 为什么它有效

 该算法之所以有效，是因为每个子树都得到了最优且独立的求解。 对于每个节点，唯一相关的信息是该节点本身是否被抢夺或被跳过。 一旦计算出孩子的这两个状态，父母就可以确定自己的最佳状态，而不需要任何额外的信息。 

这满足了动态规划所需的最优子结构性质。 由于每个节点只处理一次，因此该算法避免了重复工作并保证了最优结果。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, Tuple

class Solution:
    def rob(self, root: Optional[TreeNode]) -> int:
        
        def dfs(node: Optional[TreeNode]) -> Tuple[int, int]:
            if not node:
                return (0, 0)

            left_rob, left_skip = dfs(node.left)
            right_rob, right_skip = dfs(node.right)

            rob_current = node.val + left_skip + right_skip

            skip_current = (
                max(left_rob, left_skip) +
                max(right_rob, right_skip)
            )

            return (rob_current, skip_current)

        rob_root, skip_root = dfs(root)

        return max(rob_root, skip_root)
```实现直接遵循动态规划策略。 

嵌套的`dfs`函数执行后序遍历。 它首先处理子节点，因为当前节点取决于两个子树的结果。 

基本情况返回`(0, 0)`对于空节点。 这简化了递归逻辑，因为父节点可以在算术运算中安全地使用这些值。 

对于每个节点，算法计算两个状态：

 -`rob_current`，表示当前节点被抢了。 
-`skip_current`，表示当前节点被跳过。 

如果该节点被抢夺，则必须跳过两个子节点。 如果跳过该节点，则每个子节点都会独立贡献其最佳可能结果。 

最后，在处理完根之后，算法返回给出较大值的状态。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func rob(root *TreeNode) int {

    var dfs func(node *TreeNode) (int, int)

    dfs = func(node *TreeNode) (int, int) {
        if node == nil {
            return 0, 0
        }

        leftRob, leftSkip := dfs(node.Left)
        rightRob, rightSkip := dfs(node.Right)

        robCurrent := node.Val + leftSkip + rightSkip

        skipCurrent := max(leftRob, leftSkip) +
            max(rightRob, rightSkip)

        return robCurrent, skipCurrent
    }

    robRoot, skipRoot := dfs(root)

    return max(robRoot, skipRoot)
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```Go 的实现与 Python 解决方案非常相似。 

Go 不像 Python 那样直接支持元组文字，但多个返回值干净地提供相同的功能。 

基本情况检查`nil`节点而不是`None`。 

一个帮手`max`函数是必需的，因为 Go 没有为原始整数提供内置的整数最大值函数。 

由于节点值的边界为`10^4`并且树最多包含`10^4`节点，标准 Go`int`在这个问题中，值是完全安全的，不会溢出。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点只被处理一次 |
 | 空间| O(h) | 递归调用堆栈取决于树的高度 |

 DFS 遍历访问每个节点一次，并且每次访问时仅执行常量工作。 因此，总运行时间与节点数量呈线性关系。 

空间复杂度来自递归深度。 在平衡树中，高度为`O(log n)`。 在最坏的情况下，例如完全倾斜的树，高度变为`O(n)`。

 ## 边缘情况

 一个重要的边缘情况是仅包含单个节点的树。 幼稚的实现可能会错误地假设子级的存在或执行不必要的递归。 在此实现中，DFS 自然地处理叶节点，因为它们的子节点返回`(0, 0)`，使得该节点被抢的价值等于其自身的价值。 

另一个重要的情况是高度不平衡的树，其中每个节点只有一个子节点。 这种树的行为类似于链表。 在这种情况下，某些实现可能会意外地引入过多的重新计算或不正确的父子处理。 由于该解决方案仅处理每个节点一次并且仅使用递归状态传递，因此即使对于倾斜树，它仍然保持高效。 

当跳过节点比抢夺节点更好时，就会出现第三种重要的边缘情况。 例如，一个小价值的父母和一个非常大价值的孩子不应该被抢劫。 贪婪方法在这里经常会失败，因为获取当前节点可能会阻止对更有价值的后代的访问。 此实现显式计算每个节点的两种可能性并选择最佳结果，确保正确性。 

另一个微妙的边缘情况涉及零值节点。 有价值的节点`0`仍然可能影响有效抢劫的结构，因为抢劫它可以防止抢劫它的孩子。 该算法独立地正确评估两种状态，因此它永远不会仅仅因为节点存在而认为抢劫节点是有益的。
