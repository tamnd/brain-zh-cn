[LeetCode 第 325 题](https://leetcode.com/problems/maximum-size-subarray-sum-equals-k/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们找到最长的连续子数组，其总和恰好等于给定整数`k`。 

子数组是数组的连续部分。 这意味着我们无法对元素重新排序或跳过位置。 我们必须选择一个起始索引和一个结束索引，以便包含它们之间的每个元素。 

输入包括：

 -`nums`，一个可能包含正数、负数和零的整数数组
 -`k`，我们希望子数组等于的目标总和

 输出是一个整数，表示任何子数组的最大可能长度，其元素总和为`k`。 If no such subarray exists, we return`0`。 

负数的存在极其重要。 如果数组仅包含正数，则滑动窗口技术将起作用，因为扩大窗口总是会增加总和，而缩小窗口总是会减少总和。 然而，负值会破坏该属性。 窗口总和可能会不可预测地增加或减少，因此我们需要一种不同的方法。 

限制条件很大：

 -`nums.length`可以大到`2 * 10^5`- 值可以为负数
 -`k`也可以非常大或非常小

 这些限制强烈表明`O(n^2)`解决方案会太慢。 和`200,000`元素，在最坏的情况下，二次方法将需要数百亿次运算。 

一些重要的边缘情况包括：

 - 没有子数组相加的数组`k`- 包含负数的数组
 - 包含许多零的数组
 - 整个数组总和为的情况`k`- 多个子数组总和为的情况`k`，但只应返回最长的
 - 最优子数组从索引开始的情况`0`该问题保证数组至少包含一个元素，因此我们永远不需要处理空输入数组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组。 

对于每个起始索引，我们可以一次扩展子数组一个元素，同时保持运行总和。 每当运行总和等于`k`，我们计算该子数组的长度并更新最大答案。 

这是有效的，因为每个可能的连续子数组都被检查一次。 因此，如果存在有效的子数组，我们最终会找到它。 

然而，有`O(n^2)`可能的子数组。 即使使用增量求和计算，总运行时间仍然是二次的。 给定约束条件`2 * 10^5`元素，这种方法太慢了。 

### 最优方法，前缀和+哈希图

 关键的见解是前缀和允许我们有效地计算子数组和。 

认为：

-`prefixSum[i]`是索引中元素的总和`0`到`i`然后对索引中的子数组求和`j + 1`到`i`是：$$\text{prefixSum}[i] - \text{prefixSum}[j]$$我们希望这个子数组的总和等于`k`， 所以：$$\text{prefixSum}[i] - \text{prefixSum}[j] = k$$重新排列：$$\text{prefixSum}[j] = \text{prefixSum}[i] - k$$这意味着在处理索引时`i`，如果我们之前看到前缀和等于`currentPrefix - k`，那么这两个位置之间的子数组之和为`k`。 

哈希映射允许我们在恒定时间内查找先前的前缀和。 

一个重要的优化是我们只存储每个前缀和最早出现的部分。 较早的索引会产生更长的子数组，这正是我们想要的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个可能的子数组 |
 | 最佳 | O(n) | O(n) | 使用前缀和和哈希映射进行恒定时间查找 |

 ## 算法演练

 1. 初始化一个哈希映射，存储每个前缀和出现最早的索引。 

我们存储最早的索引的原因是较早出现的索引稍后会创建更长的子数组。 
2.插入对`{0: -1}`到哈希映射中。 

这处理有效子数组从索引开始的情况`0`。 如果运行前缀和本身变成`k`， 然后`currentPrefix - k`等于`0`，子数组长度变为`i - (-1)`。 
3.初始化：

 -`prefix_sum = 0`-`max_length = 0`4. 从左到右迭代数组。 
5. 在每个索引处：

 - 将当前号码添加到`prefix_sum`6. 计算：

 -`needed = prefix_sum - k`如果`needed`存在于哈希映射中，则存在一个先前的前缀和，使得这两个索引之间的子数组之和为`k`。 
7. 计算子数组长度：

 -`current_length = current_index - previous_index`更新`max_length`如果这个长度更大。 
8. 如果当前`prefix_sum`以前没有见过，将其存储在具有当前索引的哈希映射中。 

我们不会覆盖现有条目，因为最早出现的条目会给出最长的未来子数组。 
9. 继续，直到阵列完全处理完毕。 
10. 返回`max_length`。 

### 为什么它有效

 该算法依赖于前缀和的数学特性：$$\text{subarraySum}(j+1, i) = \text{prefixSum}[i] - \text{prefixSum}[j]$$每当我们发现前一个前缀和等于`currentPrefix - k`，我们知道这些位置之间的元素之和为`k`。 

通过存储每个前缀和的最早出现，我们保证找到的任何匹配子数组对于该结束位置来说都尽可能长。 由于我们只检查每个索引一次，因此最终答案是总体的最大有效子数组长度。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSubArrayLen(self, nums: List[int], k: int) -> int:
        prefix_to_index = {0: -1}

        prefix_sum = 0
        max_length = 0

        for index, num in enumerate(nums):
            prefix_sum += num

            needed = prefix_sum - k

            if needed in prefix_to_index:
                current_length = index - prefix_to_index[needed]
                max_length = max(max_length, current_length)

            if prefix_sum not in prefix_to_index:
                prefix_to_index[prefix_sum] = index

        return max_length
```实现首先创建一个名为的字典`prefix_to_index`。 这将每个前缀和映射到它出现的最早的索引。 

条目`{0: -1}`很关键。 它允许算法正确处理从索引开始的子数组`0`。 

当我们迭代数组时，我们不断更新`prefix_sum`。 对于每个位置，我们计算`needed = prefix_sum - k`。 如果该值已经存在于哈希映射中，那么我们就找到了以当前索引结尾的有效子数组。 

该子数组的长度是使用索引之间的差来计算的。 

我们只在前缀和第一次出现时存储它。 这保留了最早出现的情况，从而最大化了未来子数组的长度。 

最后，处理完所有元素后，我们返回找到的最大长度。 

## 解决方案```go
func maxSubArrayLen(nums []int, k int) int {
	prefixToIndex := map[int]int{
		0: -1,
	}

	prefixSum := 0
	maxLength := 0

	for index, num := range nums {
		prefixSum += num

		needed := prefixSum - k

		if previousIndex, exists := prefixToIndex[needed]; exists {
			currentLength := index - previousIndex

			if currentLength > maxLength {
				maxLength = currentLength
			}
		}

		if _, exists := prefixToIndex[prefixSum]; !exists {
			prefixToIndex[prefixSum] = index
		}
	}

	return maxLength
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

Go 使用一个`map[int]int`存储前缀和及其最早的索引。 这`exists`地图查找中的布尔值用于安全地确定前缀和是否已经出现。 

Go 中的整数对于给定的约束来说足够大，因此溢出不是这里的问题。 

与 Python 字典不同，Go 映射在读取值之前需要显式的存在性检查。

 ## 边缘情况

 当有效子数组从索引处开始时，会出现一种重要的边缘情况`0`。 如果实现仅在哈希映射中查找先前的前缀和，则很容易出现错误处理。 初始化`{0: -1}`通过假装数组开始之前的前缀和为零来解决此问题。 当运行前缀和恰好变为`k`，该算法正确计算从数组开头开始的完整长度。 

另一个棘手的情况涉及重复的前缀和。 例如，在`[1, -1, 1, -1]`，相同的前缀和可能会出现多次。 如果我们覆盖哈希图中较早的索引，我们将失去稍后形成最长可能子数组的能力。 该实现通过仅存储每个前缀和的第一次出现来避免这种情况。 

包含负数的数组也是错误的主要来源。 许多数组求和问题可以使用滑动窗口来解决，但该技术在这里失败，因为求和不是单调的。 添加负值可能会意外地减少总和。 无论数字是正数、负数还是零，前缀和方法都可以正常工作。 

最后一个重要的边缘情况是当没有子数组总和为`k`。 在这种情况下，算法永远不会更新`max_length`，所以它正确返回`0`。
