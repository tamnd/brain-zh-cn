 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个数据结构来管理固定的电话号码池。 最初，每个数字`0`到`maxNumbers - 1`可用。 该目录必须有效地支持三种操作。 

这`get()`操作应该分配并返回一个可用的号码。 如果没有数字剩余，它应该返回`-1`。 

这`check(number)`操作应该告诉我们当前是否有特定的号码可用。 

这`release(number)`操作应将先前分配的编号返回到池中，以便以后可以重复使用。 

重要的细节是数字可以在两种状态之间来回移动：

 - 可用
 - 已分配

 系统必须持续跟踪这些状态，同时有效地支持许多操作。 

约束条件相对较小，最多`10^4`电话号码和`2 * 10^4`运营。 尽管限制并不大，但问题本质上是设计一个高效的可重用资源分配器。 幼稚的实现在实践中仍然可能通过，但预期的解决方案应该提供接近恒定时间的操作。 

一些边缘情况立即很重要。 

如果所有数字都已分配，`get()`必须返回`-1`。 粗心的实现可能会尝试从空结构中弹出或返回无效数字。 

如果`release(number)`当调用一个已经可用的号码时，我们必须避免在可用池中插入重复的号码。 否则，同一个号码可能会同时被分配多次。 

另一个重要的情况是在重复释放和重新分配周期后检查数字。 该结构必须始终准确地反映当前的可用性状态。 

该问题保证了`number`传递到`check()`和`release()`总是在范围内，特别是`0 <= number < maxNumbers`。 这简化了实现，因为我们不需要额外的范围验证。 

## 方法

 ### 蛮力方法

 最直接的解决方案是维护一个数组，指示每个数字是否可用。 

例如：

-`True`表示该号码是免费的
 -`False`表示号码已分配

 对于`get()`，我们从左到右扫描整个数组，直到找到可用的数字。 然后我们将其标记为已分配并返回它。 

为了`check(number)`，我们只需返回该索引处的布尔值。 

为了`release(number)`，我们再次将该号码标记为可用。 

该解决方案是正确的，因为可用性数组始终反映每个电话号码的真实状态。 然而，问题是`get()`手术。 在最坏的情况下，我们可能需要扫描所有`maxNumbers`在找到空闲号码或确定不存在之前的条目。 

这使得`get()`拿`O(n)`时间。 

由于可能有很多操作，重复扫描数组变得低效。 

### 最佳方法

 关键的见解是，我们实际上不需要扫描所有数字来查找可用的数字。 相反，我们可以将所有当前可用的数字显式存储在队列或堆栈中。 

初始化时：

 - 每个号码都可用
 - 我们将所有号码放入队列中

 当`get()`称为：

 - 从队列中删除一个号码
 - 将其标记为已分配
 - 归还

 当`release(number)`称为：

 - 如果当前已分配该号码，则将其添加回队列中

 为了快速支持`check(number)`操作中，我们还维护一个包含所有当前可用数字的哈希集。 

这为我们提供了恒定时间操作，因为：

 - 队列删除是`O(1)`- 哈希集查找是`O(1)`- 哈希集插入/删除是`O(1)`队列管理分配顺序，而哈希集提供快速的成员资格测试。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`get(): O(n)`， 其他的`O(1)`|`O(n)`| 扫描整个数组以查找空闲号码 |
 | 最佳 |`O(1)`所有操作的平均值 |`O(n)`| 使用队列加哈希集进行恒定时间操作 |

 ## 算法演练

 1. 初始化一个包含所有电话号码的队列`0`到`maxNumbers - 1`。 

每个号码一开始都是可用的，因此队列代表空闲号码池。 
2. 初始化包含相同数字的哈希集。 

该集允许在检查号码是否可用时快速查找。 
3.为了`get()`：

 - 如果队列为空，则返回`-1`- 否则，从队列前面删除一个号码
 - 从可用性集中删除相同的号码
 - 返回号码

 从集合中删除该号码会将其标记为已分配。 
4. 对于`check(number)`：

 - 返回该号码是否存在于可用性集中

 由于集合支持恒定时间查找，因此该操作非常高效。 
5. 对于`release(number)`：

 - 首先检查该号码是否已经可用
 - 如果它已经在可用性集中，则不执行任何操作
 - 否则：

 - 将号码添加回队列中
 - 将其添加回可用性集中

 这可以防止队列中出现重复的条目。 

### 为什么它有效

 核心不变量是队列和可用性集始终包含完全相同的可用数字。 

每当通过分配一个号码时`get()`，它从两个结构中删除。 

每当释放一个数字时，它都会被添加回两个结构中。 

由于这个不变量：

 -`check(number)`总是准确的
 -`get()`总是返回未使用的号码
 - 号码不能同时分配两次

 ## Python 解决方案```python
from collections import deque

class PhoneDirectory:

    def __init__(self, maxNumbers: int):
        self.available_queue = deque(range(maxNumbers))
        self.available_set = set(range(maxNumbers))

    def get(self) -> int:
        if not self.available_queue:
            return -1

        number = self.available_queue.popleft()
        self.available_set.remove(number)

        return number

    def check(self, number: int) -> bool:
        return number in self.available_set

    def release(self, number: int) -> None:
        if number in self.available_set:
            return

        self.available_queue.append(number)
        self.available_set.add(number)

# Your PhoneDirectory object will be instantiated and called as such:
# obj = PhoneDirectory(maxNumbers)
# param_1 = obj.get()
# param_2 = obj.check(number)
# obj.release(number)
```该实现使用两种数据结构。 

这`deque`按分配顺序存储所有当前可用的号码。 我们使用`popleft()`因为它以恒定的时间运行。 

这`available_set`跟踪可用性状态。 这使得`check(number)`非常高效，因为哈希集成员资格测试是`O(1)`平均而言。 

里面`get()`，我们首先验证至少有一个号码仍然可用。 如果队列为空，我们返回`-1`。 

否则，我们从队列中删除前面的号码，并将其从集合中删除。 该转换将数字标记为已分配。 

这`release()`方法小心地避免重复。 如果该号码已经可用，我们什么都不做。 否则，我们将其追加回队列并将其添加回集合中。 

这确保队列和集合在所有操作中保持同步。 

## 解决方案```go
type PhoneDirectory struct {
	availableQueue []int
	availableSet   map[int]bool
	head           int
}

func Constructor(maxNumbers int) PhoneDirectory {
	queue := make([]int, maxNumbers)
	available := make(map[int]bool)

	for i := 0; i < maxNumbers; i++ {
		queue[i] = i
		available[i] = true
	}

	return PhoneDirectory{
		availableQueue: queue,
		availableSet:   available,
		head:           0,
	}
}

func (this *PhoneDirectory) Get() int {
	if this.head >= len(this.availableQueue) {
		return -1
	}

	number := this.availableQueue[this.head]
	this.head++

	delete(this.availableSet, number)

	return number
}

func (this *PhoneDirectory) Check(number int) bool {
	return this.availableSet[number]
}

func (this *PhoneDirectory) Release(number int) {
	if this.availableSet[number] {
		return
	}

	this.availableQueue = append(this.availableQueue, number)
	this.availableSet[number] = true
}

/**
 * Your PhoneDirectory object will be instantiated and called as such:
 * obj := Constructor(maxNumbers);
 * param_1 := obj.Get();
 * param_2 := obj.Check(number);
 * obj.Release(number);
 */
```Go版本使用切片来模拟队列。 我们不会重复地从前面删除元素，这会降低效率，而是维护一个`head`跟踪当前前端位置的指针。 

这`availableSet`是使用实现的`map[int]bool`。 

一个值得注意的实现细节是 Go 映射对于缺失的键返回零值。 由于零值`bool`是`false`,`this.availableSet[number]`自然可以起到会员资格检查的作用。 

与Python不同`deque`，Go 切片不提供高效的前端移除，因此使用头索引是首选方法。

 ## 边缘情况

 当所有数字都已分配时，就会出现一种重要的边缘情况。 在这种情况下，可用号码的队列变空。 有缺陷的实现可能会尝试删除某个元素，从而导致异常或无效行为。 该解决方案通过在删除号码之前显式检查队列是否为空来安全地处理此问题。 如果没有剩余数字，则返回`-1`。 

另一个微妙的边缘情况是发布一个已经可用的数字。 如果没有防止重复的保护，相同的号码可能会在队列中多次出现。 这最终将允许将同一个电话号码同时分配给多个用户。 该实现通过在重新插入之前首先检查该号码是否已存在于可用性集中来防止这种情况发生。 

第三个重要案例涉及重复的释放和重新分配周期。 一个号码可以被分配、释放、重新分配和再次释放多次。 该实现在每个操作中保持队列和集合之间的同步，确保可用性状态始终保持正确，无论数字更改状态多少次。
