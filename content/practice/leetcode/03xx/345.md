[LeetCode 第 345 题](https://leetcode.com/problems/reverse-vowels-of-a-string/)

 **难度：** 🟢简单
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们仅反转字符串中的元音，同时将所有非元音字符保留在其原始位置。 

元音定义为以下字符之一：

 -`a`-`e`-`i`-`o`-`u`该问题还指出元音可能以小写和大写形式出现。 这意味着像这样的字符`A`,`E`,`I`,`O`， 和`U`也必须被视为元音。 

输入是单个字符串`s`。 输出应该是一个新字符串，其中：

 - 每个辅音和非字母字符都保持在相同的位置。 
- 只有元音以相反的顺序互相交换位置。 

例如：

 - 输入：`"IceCreAm"`- 从左到右遇到的元音：`['I', 'e', 'e', 'A']`- 颠倒元音顺序：`['A', 'e', 'e', 'I']`- 最终字符串：`"AceCreIm"`约束条件很重要：

 - 字符串长度可以大到`3 * 10^5`- 字符串包含可打印的 ASCII 字符

 由于输入可能非常大，因此我们需要一种高效的算法。 二次时间解可能会变得太慢。 这强烈表明我们应该以线性时间方法为目标，理想情况下`O(n)`。 

需要考虑一些重要的边缘情况：

 - 没有元音的字符串，例如`"rhythm"`- 完全由元音组成的字符串，例如`"aeiou"`- 只有一个元音的字符串
 - 包含大写元音的字符串
 - 包含符号或空格的字符串
 - 接近最大约束大小的非常大的字符串

 正确的解决方案必须有效地处理所有这些问题。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是：

 1. 遍历字符串并将所有元音收集到一个单独的列表中。 
2. 颠倒该元音列表。 
3. 再次遍历字符串并重建结果：

 - 如果当前字符是元音，则将其替换为反转列表中的下一个元音。 
- 否则，保留原始字符。 

这种方法之所以有效，是因为它显式地提取元音，反转它们的顺序，然后将它们放回字符串中的元音位置。 

尽管此解决方案是正确的，但它需要额外遍历字符串以及与元音数量成比例的额外存储。 虽然这个问题仍然可以接受，但它不是最节省空间的方法。 

### 最佳方法

 关键的观察是我们只需要交换字符串两端的元音。 

这自然建议采用两指针策略：

 - 一个指针从左侧开始。 
- 另一个指针从右侧开始。 
- 将两个指针向内移动，直到它们指向元音。 
- 交换这些元音。 
- 继续，直到指针交叉。 

这是有效的，因为左边的第一个元音应该成为最终结果中的最后一个元音，左边的第二个元音应该成为倒数第二个元音，依此类推。 

通过直接就地交换元音，我们避免了单独存储所有元音并实现了高效的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 分别提取和反转元音 |
 | 最佳| O(n) | O(n) | 使用两个指针并直接交换元音 |

 最优方法仍然使用`O(n)`Python和Go中的空格因为字符串是不可变的，所以我们必须将字符串转换为可变字符数组。 

## 算法演练

 1. 创建一个包含所有小写和大写元音的集合。 

我们使用集合是因为​​成员资格检查非常快，平均`O(1)`时间。 由于我们需要反复询问一个字符是否是元音，因此集合是理想的选择。 
2. 将字符串转换为可变字符列表。 

Python 和 Go 中的字符串是不可变的，因此我们不能直接修改单个字符。 转换为字符数组可以实现高效交换。 
3.初始化两个指针：

 -`left = 0`-`right = len(characters) - 1`左指针从头开始扫描，右指针从末尾开始扫描。 
4. 向前移动左侧指针直至指向元音。 

非元音字符应保持不变，因此我们跳过它们。 
5. 向后移动右指针直至指向元音。 

同样，辅音和其他字符保持固定。 
6. 当两个指针都指向元音时，交换它们。 

这会将左元音置于其反转位置，将右元音置于其反转位置。 
7. 将两个指针向内移动。 

交换后，这些位置就已确定，不再需要处理。 
8. 继续直到`left >= right`。 

至此，所有元音交换就完成了。 
9. 将字符数组转换回字符串并返回。 

### 为什么它有效

 该算法保持了当前指针范围之外的所有元音都已被放置在其正确的反转位置的不变性。 

每次交换都会将左侧的下一个不匹配的元音与右侧的下一个不匹配的元音交换。 由于指针对称地向内移动，因此当指针相遇时，元音顺序完全相反。 

## Python 解决方案```python
class Solution:
    def reverseVowels(self, s: str) -> str:
        vowels = set("aeiouAEIOU")
        
        characters = list(s)
        
        left = 0
        right = len(characters) - 1
        
        while left < right:
            while left < right and characters[left] not in vowels:
                left += 1
            
            while left < right and characters[right] not in vowels:
                right -= 1
            
            characters[left], characters[right] = (
                characters[right],
                characters[left],
            )
            
            left += 1
            right -= 1
        
        return "".join(characters)
```该实现首先创建一组用于快速查找的元音。 同时包含小写和大写元音，因此算法可以正确处理大小写混合的字符串。 

由于Python字符串无法就地修改，因此字符串被转换为字符列表。 这允许高效的交换操作。 

然后初始化两个指针。 左指针向前扫描寻找元音，而右指针向后扫描。 

嵌套的`while`循环跳过非元音字符。 一旦两个指针都识别出元音，这些元音就会交换。 

交换后，两个指针都向内移动，因为当前的元音位置现已确定。 

最后，将修改后的字符列表重新连接成字符串并返回。 

## 解决方案```go
func reverseVowels(s string) string {
    vowels := map[byte]bool{
        'a': true,
        'e': true,
        'i': true,
        'o': true,
        'u': true,
        'A': true,
        'E': true,
        'I': true,
        'O': true,
        'U': true,
    }

    chars := []byte(s)

    left := 0
    right := len(chars) - 1

    for left < right {
        for left < right && !vowels[chars[left]] {
            left++
        }

        for left < right && !vowels[chars[right]] {
            right--
        }

        chars[left], chars[right] = chars[right], chars[left]

        left++
        right--
    }

    return string(chars)
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个重要的区别是 Go 字符串是不可变的并且按字节索引。 由于问题保证了可打印的 ASCII 字符，因此将字符串转换为`[]byte`安全高效。 

一个`map[byte]bool`用于元音查找。 这与 Python 集的目的相同。 

直接对字节片进行交换，最终结果在返回之前转换回字符串。

 ## 边缘情况

 ### 没有元音的字符串

 像这样的输入`"rhythm"`根本不包含元音。 有缺陷的实现可能会错误地尝试交换或将指针移出界限。 

此实现可以安全地处理这种情况，因为两个指针都会继续跳过字符直到它们交叉。 由于没有发生交换，因此原始字符串不变地返回。 

### 仅包含元音的字符串

 像这样的输入`"aeiou"`需要每个角色都参与逆转。 这强调了交换逻辑的正确性。 

两指针方法自然地处理这种情况，因为每个指针位置都立即符合元音的条件，因此交换直接发生，直到指针相遇。 

### 大写元音

 输入如`"IceCreAm"`包括大写元音。 一个常见的错误是仅检查小写元音。 

此实现通过在查找集或映射中显式包含小写和大写元音来避免该错误。 

### 带有符号和空格的字符串

 输入可能包含可打印的 ASCII 字符，而不仅仅是字母。 空格、标点符号和数字等字符必须保持不变。 

该算法可以正确处理此问题，因为只有在元音查找集中找到的字符才会被交换。 自动跳过所有其他字符。 

### 非常大的输入

 最大输入大小为`3 * 10^5`，因此低效的算法可能会变得太慢。 

两指针解决方案最多处理每个字符一次，即使对于非常大的字符串也能保证线性时间性能。
