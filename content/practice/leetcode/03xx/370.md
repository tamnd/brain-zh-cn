[LeetCode Problem 370](https://leetcode.com/problems/range-addition/)

 **难度：** 🟡 中等
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 The problem gives us an initially zero-filled array of size`length`。 我们还获得了更新操作的列表，其中每个更新的形式如下：```
[startIdx, endIdx, inc]
```这意味着我们必须添加`inc`到包含范围内的每个元素`startIdx`到`endIdx`。 

例如，如果数组是：```
[0, 0, 0, 0, 0]
```我们申请：```
[1, 3, 2]
```然后每个索引`1`通过`3`增加了`2`，生产：```
[0, 2, 2, 2, 0]
```目标是在应用所有更新操作后返回最终数组。 

重要的细节是更新影响范围，而不是单个位置。 一个幼稚的实现将显式地迭代每个范围内的每个索引并直接修改数组。 然而，这些限制使得这可能变得昂贵。 

限制条件是：

 -`length <= 10^5`-`updates.length <= 10^4`一次更新可能会影响几乎整个阵列。 在最坏的情况下，暴力解决方案可以执行：```
10^4 * 10^5 = 10^9
```操作，这太慢了。 

这些限制强烈表明我们需要更有效的范围更新策略。 

一些边缘情况很重要：

 - 更新数组可能为空，在这种情况下结果应保持全零。 
- 更新可能包含负增量。 
- 范围可以由单个元素组成，其中`startIdx == endIdx`。 
- 更新可能会触及数组的开头或结尾，这会产生边界处理问题。 
- 多个更新可能会严重重叠，因此算法必须有效地将它们组合起来。 

## 方法

 ### 蛮力方法

 最直接的解决方案是完全按照描述模拟每次更新。 

对于每次更新：```
[startIdx, endIdx, inc]
```我们迭代自`startIdx`通过`endIdx`并添加`inc`到每一个元素。 

这种方法很简单并且显然是正确的，因为它直接执行所需的修改。 

然而，其性能较差。 如果每次更新跨越数组的大部分，那么每次操作都会花费`O(length)`。 由于最多可能有`10^4`更新后，总运行时间变为：```
O(updates * length)
```可以达到`10^9`运营。 

对于问题约束来说这太慢了。 

### 最优方法，带前缀和的差分数组

 关键的观察是我们实际上并不需要立即更新每个元素。 

假设我们要添加`5`到索引中的每个元素`2`索引`6`。 

我们可以记录：

 - 在索引处`2`，效果开始，所以添加`+5`- 索引后`6`，效果停止，所以添加`-5`在索引处`7`稍后，当我们计算运行前缀和时，之间的所有索引`2`和`6`自动包含增量。 

这种技术称为差分阵列。 

对于每次更新：```
[start, end, inc]
```我们做：```
diff[start] += inc
diff[end + 1] -= inc
```如果`end + 1`是在界限之内。 

处理完所有更新后，我们计算差异数组的前缀和。 运行总计重建最终修改后的数组。 

这将范围更新从昂贵的`O(range length)`操作进入常数时间`O(1)`运营。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n) | O(1) 额外 | 显式更新每个范围中的每个索引 |
 | 最佳| O(m + n) | O(n) | 使用差异数组和前缀和 |

 这里：

-`n = length`-`m = len(updates)`## 算法演练

 1.创建大小不同的数组`length`，用零初始化。 

差异数组存储每个索引处运行值的变化情况，而不是直接存储最终值。 
2. 处理每个更新操作。 

对于更新：```
[start, end, inc]
```添加`inc`在`start`。 

这标志着增量效应的开始。 
3. 标记增量效果结束的位置。 

如果`end + 1`仍在数组边界内，减去`inc`在`end + 1`。 

这会在范围结束后取消效果。 
4. 处理完所有更新后，计算前缀和。 

从左到右遍历差异数组，同时保持运行总和。 

运行总和表示最终数组中每个索引处的实际值。 
5. 将运行总计存储回数组并返回。 

### 为什么它有效

 差异数组记录的是值的变化而不是绝对值。 

每当我们在某个索引处遇到正增量时，所有未来的前缀和都包含该增量。 当我们稍后遇到相应的负减量时，后续索引的效果就会被取消。 

因此，每次更新都会准确影响预期的间隔，而不影响其他间隔。 

前缀和重建保证所有重叠更新正确组合。 

## Python 解决方案```python
from typing import List

class Solution:
    def getModifiedArray(self, length: int, updates: List[List[int]]) -> List[int]:
        diff = [0] * length

        for start, end, increment in updates:
            diff[start] += increment

            if end + 1 < length:
                diff[end + 1] -= increment

        running_sum = 0

        for i in range(length):
            running_sum += diff[i]
            diff[i] = running_sum

        return diff
```实现首先创建名为的差异数组`diff`。 

在第一个循环期间，每次更新仅修改两个位置：

 - 范围的开始
 - 紧接范围之后的位置

 这可以有效地对范围修改进行编码，而无需触及每个元素。 

边界检查：```python
if end + 1 < length:
```很重要，因为当更新到达最终索引时，递减位置可能会落在数组之外。 

记录所有更新后，第二个循环计算前缀和。 变量`running_sum`累积每个位置的有效增量。 

当我们遍历数组时：```python
running_sum += diff[i]
```当前运行总计成为索引的实际值`i`。 

最后，返回重构后的数组。 

## 解决方案```go
func getModifiedArray(length int, updates [][]int) []int {
    diff := make([]int, length)

    for _, update := range updates {
        start := update[0]
        end := update[1]
        increment := update[2]

        diff[start] += increment

        if end+1 < length {
            diff[end+1] -= increment
        }
    }

    runningSum := 0

    for i := 0; i < length; i++ {
        runningSum += diff[i]
        diff[i] = runningSum
    }

    return diff
}
```Go 实现遵循与 Python 版本相同的逻辑。 

使用以下命令创建的切片：```go
make([]int, length)
```自动用零初始化。 

Go 切片是可变的，因此可以直接更新差异数组。 

边界条件的处理方式相同：```go
if end+1 < length
```Go 使用显式变量声明和索引访问，但整体算法保持不变。 

在给定的约束下，整数溢出不是问题，因为这些值完全在 Go 的标准整数范围内。

 ## 边缘情况

 ### 清空更新数组

 如果`updates`为空，不应进行任何修改。 有缺陷的实现可能会假设至少存在一个更新，或者错误地处理前缀和重建。 

此实现可以自然地处理这种情况，因为更新循环根本不执行任何操作。 全零差分数组上的前缀和仍然会产生全零。 

### 更新以最终索引结束

 当更新影响数组中的最后一个索引时，则没有有效位置`end + 1`。 

例如：```
[2, 5, 4]
```在长度数组中`6`。 

一个常见的错误正在尝试：```
diff[end + 1] -= increment
```不检查边界，这会导致超出范围的错误。 

该实现通过以下方式防止这种情况发生：```
if end + 1 < length:
```### 负增量值

 更新可能会减少值而不是增加值。 

例如：```
[1, 3, -2]
```设计不当的解决方案可能会错误地假设增量始终为正。 

差分数组技术同样适用于负数，因为前缀和自然会传播正数和负数变化。 

### 单元素范围

 更新可能只针对一个索引：```
[start, start, inc]
```容易出现错误的实现可能会错误地跳过范围或错误地处理停止点。 

差异数组方法可以干净地处理这个问题，因为：```
diff[start] += inc
diff[start + 1] -= inc
```创造一种只持续一个位置的效果。
