[LeetCode 第 373 题](https://leetcode.com/problems/find-k-pairs-with-smallest-sums/)

 **难度：** 🟡 中等
 **主题：** 数组、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题给了我们两个排序的整数数组，`nums1`和`nums2`，并要求我们返回`k`具有最小总和的对。 

一对是通过从其中取出一个元素而形成的`nums1`和一个元素`nums2`。 如果`nums1 = [1,7]`和`nums2 = [2,4]`，那么可能的对是：

 -`(1,2)`-`(1,4)`-`(7,2)`-`(7,4)`他们的总和是：

 -`1 + 2 = 3`-`1 + 4 = 5`-`7 + 2 = 9`-`7 + 4 = 11`目标是返回`k`具有最小总和的对，根据提取过程从最小总和到最大总和排序。 

重要的细节是两个数组已经按非降序排序。 此约束是设计有效解决方案的关键。 由于数组已排序，因此增加任一索引只能增加或维持对总和。 这种单调结构使我们能够避免生成每个可能的对。 

限制条件很大：

 - 每个数组最多可以包含`10^5`元素
 -`k`可以达到`10^4`- 总可能对可以大到`10^10`由于数组的笛卡尔积可能非常巨大，因此在时间和内存限制内，任何显式生成所有对的解决方案都是不可能的。 

一些边缘情况很重要：

 - 数组可能包含重复值，因此允许且期望存在重复对。 
- 值可能为负数，这意味着最小的和不一定是由最小的正数形成的。 
-`k`可能大于一个数组的大小。 
- 一个数组只能包含一个元素。 
- 保证数组非空。 

该问题保证了`k <= nums1.length * nums2.length`，因此总是有足够的对返回。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的对。 

对于中的每个元素`nums1`，我们将它与中的每个元素配对`nums2`。 这创造了`m * n`对，其中：

 -`m = len(nums1)`-`n = len(nums2)`对于每一对，我们计算其总和并存储它。 生成所有对后，我们按总和对它们进行排序并返回第一个`k`。 

这种方法是正确的，因为它明确地检查每个可能的对，因此最小的`k`保证存在对。 

然而，对于给定的约束，该解决方案太慢并且占用大量内存。 如果两个数组都包含`10^5`元素，对的数量变为`10^10`，这是完全不可行的。 

### 基于堆的最佳方法

 关键的见解来自两个数组都已排序的事实。 

假设我们修复一个元素`nums1[i]`。 然后这对相加：```
nums1[i] + nums2[0]
nums1[i] + nums2[1]
nums1[i] + nums2[2]
...
```形成一个排序序列，因为`nums2`已排序。 

这意味着每一行对和的行为就像一个排序列表。 

我们可以像合并多个排序列表一样处理该问题，而不是生成所有对。 我们使用最小堆来始终检索最小的可用对。 

我们首先从每行插入最小的对：```
(nums1[i], nums2[0])
```然后，每当我们弹出一对`(i, j)`从堆中，我们推送该行中的下一对：```
(i, j + 1)
```这是有效的，因为：

 - 同一行中的下一个候选者是该固定值的下一个较大总和`nums1[i]`- 堆总是给我们全局最小的剩余对

 因为我们只处理最多`k`对，算法对于约束变得足够有效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * log(m * n)) | O(m * n * log(m * n)) | O(m * n) | 生成并排序每对 |
 | 最佳 | O(k log min(m, k)) | O(k log min(m, k)) | O(min(m, k)) | 使用堆来探索仅需要的对 |

 ## 算法演练

 ### 基于堆的最优算法

 1. 初始化一个最小堆。 

每个堆条目存储：

 - 配对总和
 - 索引`i`在`nums1`- 指数`j`在`nums2`我们使用索引而不是直接存储值，因为索引可以让我们有效地生成相邻对。 
2. 插入每行的第一对。 

对于每一个`i`从`0`到`min(len(nums1), k) - 1`， 推：```
(nums1[i] + nums2[0], i, 0)
```我们最多只需要`k`行，因为我们永远不会返回超过`k`对。 
3. 反复从堆中提取最小的对。 

堆始终包含每个活动行中最小的未处理候选者。 

弹出最小的条目：```
(sum, i, j)
```添加对：```
[nums1[i], nums2[j]]
```到答案。 
4. 推动同一行的下一对。 

如果`j + 1 < len(nums2)`，然后推：```
(nums1[i] + nums2[j + 1], i, j + 1)
```这会在行中水平前进，同时保留排序顺序。 
5. 继续直到：

 - 我们收集`k`对，或
 - 堆变空

 ### 为什么它有效

 每行成对：```
(nums1[i], nums2[0])
(nums1[i], nums2[1])
(nums1[i], nums2[2])
...
```按递增总和排序，因为`nums2`已排序。 

堆始终存储每行中最小的未处理元素。 因此，删除堆最小值会给出全局最小的剩余对。 

当我们流行时`(i, j)`，该行的下一个候选者是`(i, j + 1)`。 由于该行中所有较早的对都已处理，因此仅插入下一个元素就足以保持正确性。 

这本质上与将排序列表与优先级队列合并所使用的原理相同。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def kSmallestPairs(self, nums1: List[int], nums2: List[int], k: int) -> List[List[int]]:
        if not nums1 or not nums2 or k == 0:
            return []

        min_heap = []
        result = []

        # Initialize heap with first element from each row
        for i in range(min(len(nums1), k)):
            heapq.heappush(
                min_heap,
                (nums1[i] + nums2[0], i, 0)
            )

        while min_heap and len(result) < k:
            current_sum, i, j = heapq.heappop(min_heap)

            result.append([nums1[i], nums2[j]])

            # Push next pair in the same row
            if j + 1 < len(nums2):
                heapq.heappush(
                    min_heap,
                    (
                        nums1[i] + nums2[j + 1],
                        i,
                        j + 1
                    )
                )

        return result
```实现从处理琐碎的边缘情况开始。 如果任一数组为空或`k`为零，则无法形成对。 

堆以以下形式存储元组：```python
(sum, i, j)
```蟒蛇的`heapq`自动按字典顺序对元组进行排序，因此总和最小的对总是首先弹出。 

初始化阶段插入每行的第一对。 由于每行都已排序，因此第一个元素是该行中最小的候选元素。 

主循环重复提取最小的对并将其附加到结果中。 

移除后`(i, j)`，算法插入`(i, j + 1)`如果存在的话。 这会在行内前进，同时保留排序的探索。 

算法停止一次`k`收集对。 

## 解决方案```go
package main

import "container/heap"

type Pair struct {
	sum int
	i   int
	j   int
}

type MinHeap []Pair

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].sum < h[j].sum
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(Pair))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func kSmallestPairs(nums1 []int, nums2 []int, k int) [][]int {
	if len(nums1) == 0 || len(nums2) == 0 || k == 0 {
		return [][]int{}
	}

	h := &MinHeap{}
	heap.Init(h)

	limit := min(len(nums1), k)

	for i := 0; i < limit; i++ {
		heap.Push(h, Pair{
			sum: nums1[i] + nums2[0],
			i:   i,
			j:   0,
		})
	}

	result := [][]int{}

	for h.Len() > 0 && len(result) < k {
		current := heap.Pop(h).(Pair)

		result = append(result, []int{
			nums1[current.i],
			nums2[current.j],
		})

		if current.j+1 < len(nums2) {
			heap.Push(h, Pair{
				sum: nums1[current.i] + nums2[current.j+1],
				i:   current.i,
				j:   current.j + 1,
			})
		}
	}

	return result
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 解决方案遵循与 Python 版本相同的算法结构，但 Go 需要使用显式堆实现`container/heap`包裹。 

定制`Pair`struct 存储总和和索引。 

与 Python 不同，Go 不为任意结构提供内置的最小堆，因此我们实现所需的堆接口方法：

 -`Len`-`Less`-`Swap`-`Push`-`Pop`其余逻辑保持不变。 

由于约束适合 32 位整数范围，但总和可能暂时超过它们，Go 的`int`type 在 LeetCode 的环境下就足够了。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k log min(m, k)) | O(k log min(m, k)) | 每个堆操作花费对数时间 |
 | 空间| O(min(m, k)) | 堆每行最多存储一个活动条目 |

 让：

-`m = len(nums1)`-`n = len(nums2)`堆最初最多包含`min(m, k)`条目。 

我们最多表现`k`堆删除最多`k`插入。 每个堆操作的成本：```
O(log min(m, k))
```因此总运行时间变为：```
O(k log min(m, k))
```这比生成所有的要好得多`m * n`对。

 ## 边缘情况

 ### 数组中的重复值

 Arrays may contain repeated numbers, which means identical pairs can appear multiple times. A common mistake is trying to eliminate duplicates with a set, which would produce incorrect results.

 例如：```
nums1 = [1,1]
nums2 = [1]
```正确答案为`k = 2`是：```
[[1,1],[1,1]]
```我们的实现正确地将来自不同索引的对视为不同的堆条目。 

### 非常大的数组

 每个数组最多可以包含`10^5`元素。 生成所有可能的对将需要大量的内存和运行时间。 

基于堆的方法通过仅探索实际上可能出现在最小的对中来避免这种情况`k`。 在任何时刻，堆最多存储`min(len(nums1), k)`条目。 

### 一个数组比另一个数组小得多

 考虑：```
nums1 = [1]
nums2 = [1,2,3,4,5]
```仅存在一行对。 

该算法仍然可以自然地工作，因为堆从单个条目开始并沿着该行重复前进。 

### 负数

 负值产生的总和比正值小，因此假设正值会破坏正确性。 

例如：```
nums1 = [-10, 1]
nums2 = [-5, 2]
```最小的一对是：```
(-10, -5)
```该算法仍然正确，因为它仅依赖于排序顺序，而不依赖于正性。
