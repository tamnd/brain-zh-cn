[LeetCode 第 399 题](https://leetcode.com/problems/evaluate-division/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、深度优先搜索、广度优先搜索、并查找、图论、最短路径

 ## 解决方案

 ## 问题理解

 这个问题给了我们变量之间的方程集合，其中每个方程代表一种除法关系。 例如，如果我们给出：```
a / b = 2.0
b / c = 3.0
```然后我们可以推断出其他关系，例如：```
a / c = 6.0
c / a = 1 / 6.0
```任务是回答以下形式的多个查询：```
x / y = ?
```对于每个查询，我们必须确定是否可以从已知方程中导出有效的除法值。 如果可以，我们返回计算值。 如果不能，我们返回`-1.0`。 

重要的观察是方程形成了变量之间的关系，这自然地创建了图形结构。 每个变量都可以被视为一个节点，每个方程在两个节点之间创建一个加权边。 

例如：```
a / b = 2.0
```创建：```
a -> b with weight 2.0
b -> a with weight 0.5
```存在倒数边是因为：```
b / a = 1 / 2.0
```输入由三个数组组成：

 -`equations`，其中每个条目包含两个变量
 -`values`，其中每个条目包含相应的除法结果
 -`queries`，其中每个条目都要求除法结果

 输出是一组浮点值，每个查询对应一个浮点值。 

限制相对较小：

 - 最多20个方程
 - 最多20个查询

 这意味着即使是 DFS 或 BFS 等图遍历方法也足够高效。 我们不需要高度优化的最短路径算法。 

一些边缘情况很重要：

 - 查询可能包含从未出现在任何方程中的变量
 - 查询可能要求自身除法，例如`a / a`- 两个变量可能属于断开连接的组件
 - 答案可能需要遍历多个中间变量

 该问题保证：

 - 不存在矛盾
 - 除零永远不会发生
 - 输入始终有效

 这些保证简化了实现，因为我们不需要处理不一致的方程。 

## 方法

 ### 蛮力方法

 简单的暴力解决方案会尝试从头开始为每个查询重新计算关系。 

对于每个查询：

 1. 尝试分子和分母之间所有可能的路径
 2.沿路径乘以比率
 3. 如果存在有效路径则返回结果

 这可以使用递归回溯来实现，而无需显式构建邻接列表。 对于每个方程，我们都会重复扫描整个方程数组以找到可用的连接。 

这种方法是正确的，因为最终每条可达路径都会被探索。 如果存在有效的方程链，算法就会发现它。 

然而，这是低效的，因为：

 - 每个查询都会重复扫描所有方程
 - 相同的子问题被重新计算多次
 - 图连接性未有效存储

 尽管这里的限制很小，但这种方法在概念上不能很好地扩展。 

### 最佳方法

 更好的解决方案将方程建模为加权图。 

每个变量成为一个节点。 

每个方程：```
a / b = k
```创建两个有向边：```
a -> b with weight k
b -> a with weight 1 / k
```回答查询：```
x / y
```我们执行 DFS 或 BFS`x`到`y`。 

当我们遍历边时，我们将边权重相乘。 乘积表示从起始变量到当前变量的累计比率。 

例如：```
a -> b = 2
b -> c = 3
```遍历：```
a -> b -> c
```产生：```
2 * 3 = 6
```这意味着：```
a / c = 6
```这是可行的，因为比率的乘法沿着图形路径自然地组合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(Q × E²) | O(E) | 重复扫描每个查询的方程 |
 | 最佳 | O(E + Q × (V + E)) | O(E + Q × (V + E)) | O(V + E) | 使用带 DFS/BFS 遍历的加权图 |

 在哪里：

-`Q`= 查询数
 -`V`= 变量数量
 -`E`= 方程数

 ## 算法演练

 ### 第 1 步：构建图表

 创建一个邻接列表，其中每个变量映射到相邻变量和边权重。 

对于每个方程：```
A / B = value
```插入：```
A -> (B, value)
B -> (A, 1/value)
```这允许双向遍历。 

例子：```
a / b = 2
```变成：```
graph["a"].append(("b", 2.0))
graph["b"].append(("a", 0.5))
```### 第 2 步：处理每个查询

 对于每个查询`[start, end]`：

 - 如果图中不存在任一变量，则返回`-1.0`- 如果`start == end`， 返回`1.0`- 否则，运行DFS或BFS

 ### 步骤3：执行DFS遍历

 DFS 函数跟踪：

 - 当前节点
 - 当前累计产品
 - 访问过的节点

 每一步：

 1. 如果当前节点等于目标节点，则返回累加积
 2. 将当前节点标记为已访问
 3.探索邻居
 4. 将当前乘积乘以边权重
 5.继续递归

 遍历示例：```
a -> b = 2
b -> c = 3
```DFS进展：```
Start at a with product 1
Move to b, product = 1 * 2 = 2
Move to c, product = 2 * 3 = 6
```返回`6`。 

### 步骤 4：处理无法访问的节点

 如果 DFS 完成但未达到目标，则返回`-1.0`。 

这意味着变量之间不存在有效关系。 

### 为什么它有效

 该图存储了所有已知的划分关系。 两个变量之间的每条路径都代表一个有效的乘法比率链。 由于除法关系以乘法方式组合，沿路径相乘边权重会产生正确的最终比率。 DFS 探索所有可达路径，因此如果存在有效关系，算法就会找到它。 

## Python 解决方案```python
from collections import defaultdict
from typing import List, Set

class Solution:
    def calcEquation(
        self,
        equations: List[List[str]],
        values: List[float],
        queries: List[List[str]]
    ) -> List[float]:

        graph = defaultdict(list)

        # Build weighted graph
        for (numerator, denominator), value in zip(equations, values):
            graph[numerator].append((denominator, value))
            graph[denominator].append((numerator, 1.0 / value))

        def dfs(
            current: str,
            target: str,
            current_product: float,
            visited: Set[str]
        ) -> float:

            if current == target:
                return current_product

            visited.add(current)

            for neighbor, weight in graph[current]:
                if neighbor in visited:
                    continue

                result = dfs(
                    neighbor,
                    target,
                    current_product * weight,
                    visited
                )

                if result != -1.0:
                    return result

            return -1.0

        answers = []

        for start, end in queries:

            if start not in graph or end not in graph:
                answers.append(-1.0)

            elif start == end:
                answers.append(1.0)

            else:
                visited = set()
                answers.append(dfs(start, end, 1.0, visited))

        return answers
```实现首先使用以下命令构建加权邻接表`defaultdict(list)`。 每个方程提供两个有向边，一个用于原始比率，一个用于倒数比率。 

DFS 辅助函数递归地搜索两个变量之间的路径。 这`current_product`参数存储迄今为止遇到的所有边权重的乘积。 一旦到达目标节点，这个累加的乘积就代表了最终的答案。 

这`visited`set 可以防止循环导致无限递归。 由于图遍历可能会通过倒数边重新访问变量，因此循环预防至关重要。 

主查询循环在运行 DFS 之前处理边缘情况。 未定义的变量立即返回`-1.0`，而相同的变量返回`1.0`只要变量存在于图中。 

## 解决方案```go
package main

func calcEquation(equations [][]string, values []float64, queries [][]string) []float64 {
	graph := make(map[string][][]interface{})

	// Build graph
	for i, equation := range equations {
		a := equation[0]
		b := equation[1]
		value := values[i]

		graph[a] = append(graph[a], []interface{}{b, value})
		graph[b] = append(graph[b], []interface{}{a, 1.0 / value})
	}

	var dfs func(
		current string,
		target string,
		product float64,
		visited map[string]bool,
	) float64

	dfs = func(
		current string,
		target string,
		product float64,
		visited map[string]bool,
	) float64 {

		if current == target {
			return product
		}

		visited[current] = true

		for _, neighborInfo := range graph[current] {
			neighbor := neighborInfo[0].(string)
			weight := neighborInfo[1].(float64)

			if visited[neighbor] {
				continue
			}

			result := dfs(
				neighbor,
				target,
				product*weight,
				visited,
			)

			if result != -1.0 {
				return result
			}
		}

		return -1.0
	}

	results := make([]float64, 0, len(queries))

	for _, query := range queries {
		start := query[0]
		end := query[1]

		_, startExists := graph[start]
		_, endExists := graph[end]

		if !startExists || !endExists {
			results = append(results, -1.0)
			continue
		}

		if start == end {
			results = append(results, 1.0)
			continue
		}

		visited := make(map[string]bool)

		result := dfs(start, end, 1.0, visited)
		results = append(results, result)
	}

	return results
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个显着的区别是 Go 不直接支持异构元组，因此邻接表使用`[][]interface{}`存储邻居和权重对。 

Go 中的 Map 自然支持使用二值赋值模式进行存在性检查：```go
value, exists := map[key]
```DFS 函数被实现为分配给变量的递归闭包。 

Go 切片的大小与 Python 列表类似，可以动态调整大小，因此附加结果非常简单。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(E + Q × (V + E)) | O(E + Q × (V + E)) | 一次构建图，每个查询 DFS |
 | 空间| O(V + E) | 图存储和访问集|

 图构建阶段只对每个方程处理一次，为每个方程生成两个有向边。

空间复杂度主要来自于DFS时使用的邻接表和递归栈。

from typing import List

class Solution:
    def calcEquation(
        self,
        equations: List[List[str]],
        values: List[float],
        queries: List[List[str]]
    ) -> List[float]:

        from collections import defaultdict

        graph = defaultdict(list)

        for (a, b), value in zip(equations, values):
            graph[a].append((b, value))
            graph[b].append((a, 1.0 / value))

        def dfs(current, target, product, visited):
            if current == target:
                return product

            visited.add(current)

            for neighbor, weight in graph[current]:
                if neighbor not in visited:
                    result = dfs(
                        neighbor,
                        target,
                        product * weight,
                        visited
                    )

                    if result != -1.0:
                        return result

            return -1.0

        answers = []

        for start, end in queries:

            if start not in graph or end not in graph:
                answers.append(-1.0)

            elif start == end:
                answers.append(1.0)

            else:
                answers.append(
                    dfs(start, end, 1.0, set())
                )

        return answers

 ## 边缘情况

 ### 未定义的变量

 查询可能引用从未出现在任何方程中的变量。 

例子：```
equations = [["a","b"]]
query = ["x","y"]
```幼稚的实现可能会错误地返回`1.0`为了`x / x`，但问题明确指出无法评估未定义的变量。 

该实现通过在 DFS 开始之前检查图成员资格来处理此问题。 

### 自分裂

 查询例如：```
a / a
```应该返回`1.0`如果`a`存在于图中。 

如果算法只搜索不同节点之间的路径，这种情况很容易被错误处理。 实现明确检查：```
elif start == end:
    answers.append(1.0)
```在DFS执行之前。 

### 断开的组件

 变量可能存在于单独的连接组件中。 

例子：```
a / b = 2
c / d = 3
```之间没有关系`a`和`d`。 

如果没有正确的遍历终止，有缺陷的实现可能会意外地产生无效结果。 DFS正确返回`-1.0`当没有路径到达目标时。 

### 图中的循环

 由于倒数边是自动添加的，因此自然会出现循环。 

例子：```
a -> b
b -> a
```如果没有访问集，DFS 将无限递归。 

该实现通过在遍历期间存储访问的节点并跳过已经探索的变量来防止这种情况。
