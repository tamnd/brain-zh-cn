 ## 解决方案

 ## 问题理解

 这个问题是经典猜数字游戏的一个变体，但有一点不同：错误的猜测花费的金钱等于猜测的值，目标是**最小化保证获胜所需的最大成本**。 换句话说，我们需要一种策略，确保在最坏的情况下我们总是能找到正确的数字，同时花费最少的钱。 

输入`n`表示数字范围的上限`[1, n]`。 输出是保证获胜所需的最低金额，无论选择哪个数字。 如果`n = 1`，不需要钱，因为只有一种选择。 为了`n = 2`，我们需要 1 美元，因为如果数字是 2，那么先猜 1 可能会导致支付 1。 

限制条件是`1 <= n <= 200`，它足够小以允许动态规划解决方案。 边缘情况包括`n = 1`（微不足道，成本 = 0），`n = 2`（简单计算），以及上限`n = 200`，它测试了该方法的效率。 

主要的挑战是天真的策略，例如总是猜测中间的数字，并没有考虑每次猜测的成本，该成本根据猜测的数字而变化。 该解决方案必须考虑猜测的值以及剩余范围内潜在的最坏情况成本。 

## 方法

 ### 蛮力方法

 蛮力方法会尝试范围内的**所有可能的第一个猜测**`[start, end]`，然后递归计算两个结果子范围的最坏情况成本（低于猜测的数字和高于猜测的数字）。 对于每一个猜测`x`，成本为：```
cost(x) = x + max(cost(start, x-1), cost(x+1, end))
```所有猜测中这些成本的最小值就是该范围的结果。 这保证了正确性，因为它考虑了所有可能的策略，但递归调用会导致指数时间复杂度`O(2^n)`由于子问题重叠，速度太慢`n = 200`。 

### 最佳方法

 关键的观察结果是，该问题表现出**最优子结构**和**重叠子问题**，使其成为**动态规划**的理想选择。 通过记忆子范围的结果`[start, end]`，我们避免了多余的计算。 DP 解决方案使用 2D 表`dp[start][end]`代表保证在该子范围内获胜的最低成本。 每个条目都通过记忆迭代或递归地填充。 

转换与暴力破解相同：```
dp[start][end] = min(
    x + max(dp[start][x-1], dp[x+1][end]) for x in range(start, end+1)
)
```记忆化大大降低了复杂性`O(n^3)`因为对于每个`O(n^2)`子范围，我们尝试`O(n)`可能的猜测。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归地尝试每一个可能的猜测而不需要记忆 |
 | 最优 (DP) | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 记住子范围结果以避免重新计算 |

 ## 算法演练

 1. **初始化一个DP表**：创建一个2D数组`dp`尺寸的`(n+1) x (n+1)`在哪里`dp[start][end]`存储范围内数字的最低保证成本`[start, end]`。 最初，所有条目均为 0。 
2. **迭代范围长度**：从小范围开始，逐渐增加范围的长度，因为范围的成本取决于较小的子范围。 
3. **考虑所有可能的猜测**：对于每个范围`[start, end]`,尝试每一个猜测`x`在范围内。 猜测的成本`x`是`x`加上两个结果子范围的最大成本：`[start, x-1]`和`[x+1, end]`。 
4. **更新 DP 表**：对该范围的所有可能猜测取最小值并将其存储在`dp[start][end]`。 
5. **返回最终结果**：`dp[1][n]`给出保证全范围获胜的最低金额。 

**为什么有效**：该算法之所以有效，是因为它使用动态规划来详尽考虑所有范围和所有可能的第一猜测，同时存储最佳成本。 通过取两个子范围中的最大值，它可以确保解决方案考虑到最坏的情况，而在所有猜测中取最小值可以确保我们找到最小化最大成本的策略。 

## Python 解决方案```python
class Solution:
    def getMoneyAmount(self, n: int) -> int:
        dp = [[0] * (n + 1) for _ in range(n + 1)]
        
        for length in range(2, n + 1):
            for start in range(1, n - length + 2):
                end = start + length - 1
                dp[start][end] = float('inf')
                for x in range(start, end + 1):
                    left = dp[start][x - 1] if x - 1 >= start else 0
                    right = dp[x + 1][end] if x + 1 <= end else 0
                    cost = x + max(left, right)
                    dp[start][end] = min(dp[start][end], cost)
                    
        return dp[1][n]
```该实现初始化 DP 表，迭代子范围长度，并根据所有可能的首次猜测的最小最坏情况成本填充每个单元格。 它处理边缘情况，例如`start == end`（成本 0）自然地，如`dp[start][start] = 0`通过初始化。 

## 解决方案```go
func getMoneyAmount(n int) int {
    dp := make([][]int, n+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
    }
    
    for length := 2; length <= n; length++ {
        for start := 1; start <= n-length+1; start++ {
            end := start + length - 1
            dp[start][end] = 1 << 30 // large number
            for x := start; x <= end; x++ {
                left := 0
                if x-1 >= start {
                    left = dp[start][x-1]
                }
                right := 0
                if x+1 <= end {
                    right = dp[x+1][end]
                }
                cost := x + max(left, right)
                if cost < dp[start][end] {
                    dp[start][end] = cost
                }
            }
        }
    }
    
    return dp[1][n]
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```Go 解决方案反映了 Python 方法，使用切片而不是列表，并初始化大量数字来模拟无穷大。 边缘情况的处理类似，并且`max`函数用于比较子范围成本。 

## 工作示例

 **示例 1：n = 10**

 | 步骤| 范围 | 猜猜x | 左| 对| 成本| dp[开始][结束] |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [1,2]| 1 | 0 | 0 | 1 | 1 |
 | 2 | [1,3]| 2 | 1 | 0 | 2 | 2 |
 | 3 | [1,10]| 7 | dp[1,6]=10 | dp[1,6]=10 | dp[8,10]=6 | 7+最大(10,6)=17 | dp[1,10]=16（检查所有猜测后）|

 DP表系统地计算每个子范围，确保最终结果`[1,10]`是 16，如问题中所述。 

**示例 2：n = 1**

 只有一个数字，成本 = 0。 

**示例 3：n = 2**`dp[1][2] = 1`因为如果数字是 2，首先猜测 1 给出的最坏情况成本为 1。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^3) | O(n^3) | 对于每个 O(n^2) 子范围，我们尝试 O(n) 种可能的猜测 |
 | 空间| O(n^2) | O(n^2) | 大小为 (n+1) x (n+1) 的 DP 表存储所有子范围的结果 |

 立方时间复杂度是可行的`n <= 200`因为它会产生大约 800 万次操作，这对于现代处理器来说是可以管理的。 由于存储所有子范围结果，空间使用量是二次的。
