[LeetCode 第 311 题](https://leetcode.com/problems/sparse-matrix-multiplication/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们将两个矩阵相乘，但有一个重要的细节：两个矩阵都是稀疏的。 稀疏矩阵是大多数条目为零的矩阵。 目标是利用这个属性，以避免涉及零值的不必要的计算。 

我们得到：

 -`mat1`， 一个`m x k`矩阵
-`mat2`, 一个`k x n`矩阵

 因为列数`mat1`匹配行数`mat2`，矩阵乘法有效。 

结果矩阵将具有维度`m x n`。 

回想一下矩阵乘法是如何工作的。 对于每个细胞`(i, j)`在结果矩阵中：$$result[i][j] = \sum_{x=0}^{k-1} mat1[i][x] \times mat2[x][j]$$这意味着每个输出单元都是通过以下点积计算的：

 - 行`i`从`mat1`- 柱子`j`从`mat2`约束相对较小，因为每个维度最多`100`。 因此，简单的解决方案在技术上是可以接受的。 然而，该问题特别关注稀疏矩阵，这意味着预期的优化是跳过涉及零的操作。 

这很重要，因为乘以零对最终答案没有任何贡献。 如果大部分矩阵项为零，那么暴力解决方案中的大多数乘法运算都是浪费的。 

一些边缘情况很重要：

 - 整行或整列只能包含零。 
- 一个或两个矩阵可以完全由零组成。 
- 允许负值，因此我们不能对正值做出假设。 
- 矩阵可以是矩形，不一定是正方形。 
- 多个非零条目可能会影响同一结果单元格。 

该问题保证维度始终与乘法兼容，因此我们永远不需要验证矩阵大小。 

## 方法

 ### 蛮力方法

 最直接的解决方案是标准矩阵乘法。 

对于每一行`i`在`mat1`和每一列`j`在`mat2`，我们迭代所有中间索引`x`从`0`到`k - 1`并计算：$$result[i][j] += mat1[i][x] \times mat2[x][j]$$这种方法是正确的，因为它直接实现了矩阵乘法的数学定义。 

然而，当矩阵稀疏时，它会执行许多不必要的操作。 即使`mat1[i][x]`或者`mat2[x][j]`为零，尽管没有任何贡献，乘法仍然执行。 

总工作量为：$$O(m \times k \times n)$$对于稠密矩阵，这是不可避免的，但对于稀疏矩阵，我们可以通过跳过零值来做得更好。 

### 最优稀疏矩阵方法

 关键的观察结果是乘以零没有效果。 

我们只处理非零值，而不是迭代每个可能的组合。 

认为`mat1[i][k]`是非零的。 只有这样才值得研究 row`k`的`mat2`， 因为：$$mat1[i][k] \times mat2[k][j]$$可以对结果做出贡献。 

如果`mat2[k][j]`也不为零，那么我们更新：$$result[i][j] += mat1[i][k] \times mat2[k][j]$$这避免了涉及零的不必要的操作。 

当矩阵包含很少的非零条目时，优化变得特别强大。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × k × n) | O(m × n) | 计算所有可能的乘法 |
 | 最佳| O(非零运算) | O(m × n) | 跳过零条目以减少工作 |

 最佳解决方案的确切运行时间取决于存在多少个非零值。 

## 算法演练

 1. 确定矩阵的维数。 

让：

-`m`= 中的行数`mat1`-`k`= 中的列数`mat1`-`n`= 中的列数`mat2`结果矩阵将具有维度`m x n`。 
2. 用零初始化结果矩阵。 

每个位置最初包含`0`因为还没有积累任何产品。 
3. 迭代每一行`i`的`mat1`。 

我们一次处理一行的贡献。 
4.对于每个列索引`x`在`mat1[i]`，检查是否`mat1[i][x]`是非零的。 

如果该值为零，则完全跳过它，因为它对任何结果单元格没有任何贡献。 
5. 当发现非零值时`mat1[i][x]`, 迭代行`x`的`mat2`。 

这是有效的，因为矩阵乘法对：

 -`mat1[i][x]`-`mat2[x][j]`6. 对于每一列`j`在`mat2[x]`，检查是否`mat2[x][j]`是非零的。 

同样，零值没有任何贡献，可以跳过。 
7. 更新结果矩阵。 

添加：$$mat1[i][x] \times mat2[x][j]$$到：$$result[i][j]$$8. 继续，直到处理完所有行和相关非零条目。 
9. 返回完成的结果矩阵。 

### 为什么它有效

 矩阵乘法定义为共享维度上的成对乘积之和。 优化算法仍然计算出与暴力解决方案完全相同的乘积，但它会跳过涉及零的乘积，因为这些项的计算结果始终为零并且不会影响最终的总和。 

因此，每一个有意义的贡献都被保留，并且最终的矩阵是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def multiply(self, mat1: List[List[int]], mat2: List[List[int]]) -> List[List[int]]:
        m = len(mat1)
        k = len(mat1[0])
        n = len(mat2[0])

        result = [[0] * n for _ in range(m)]

        for i in range(m):
            for x in range(k):
                if mat1[i][x] != 0:
                    for j in range(n):
                        if mat2[x][j] != 0:
                            result[i][j] += mat1[i][x] * mat2[x][j]

        return result
```实现首先提取矩阵维度。 这使我们能够正确调整结果矩阵的大小。 

结果矩阵用零初始化，因为矩阵乘法将和累加到每个单元格中。 

外循环遍历行`mat1`。 第二个循环迭代该行的列，这些列对应于中的行`mat2`。 

在执行任何乘法之前，代码检查是否`mat1[i][x]`是非零的。 如果它为零，则涉及该值的所有乘积也将为零，因此算法会跳过整个内部计算。 

如果该值非零，我们迭代相应的行`mat2`。 另一个零检查避免了不必要的乘法涉及`mat2[x][j]`。 

只要两个值都不为零，它们的乘积就会对结果矩阵产生影响。 

所有贡献累加后返回最终矩阵。 

## 解决方案```go
func multiply(mat1 [][]int, mat2 [][]int) [][]int {
    m := len(mat1)
    k := len(mat1[0])
    n := len(mat2[0])

    result := make([][]int, m)

    for i := 0; i < m; i++ {
        result[i] = make([]int, n)
    }

    for i := 0; i < m; i++ {
        for x := 0; x < k; x++ {
            if mat1[i][x] != 0 {
                for j := 0; j < n; j++ {
                    if mat2[x][j] != 0 {
                        result[i][j] += mat1[i][x] * mat2[x][j]
                    }
                }
            }
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

主要区别在于矩阵初始化。 在 Go 中，必须使用显式分配切片`make`。 

Go 整数足以解决问题约束，因为值保持在 32 位整数限制内。 

两种实现都避免了涉及零的不必要的乘法，从而保留了稀疏优化。

 ## 边缘情况

 ### 完全稀疏矩阵

 矩阵可能只包含零。 在这种情况下，每次乘法都会产生零，因此最终矩阵也应该只包含零。 

如果实现假设每一行都贡献值，则很容易产生错误。 优化的解决方案可以自然地处理这个问题，因为它会跳过其中的所有条目`mat1[i][x] == 0`。 

### 矩形矩阵

 不保证矩阵是方阵。 例如，一个`1 x 3`矩阵可以乘以`3 x 2`矩阵。 

一个常见的错误是假设各处尺寸相等。 实现正确提取：

 - 行来自`mat1`- 列来自`mat2`- 共享维度`k`这可确保所有矩形配置正常工作。 

### 对同一单元的多个贡献

 单个结果单元格可以接收来自多个中间索引的贡献。 

例如：$$result[i][j] = mat1[i][0] \times mat2[0][j] + mat1[i][1] \times mat2[1][j]$$有缺陷的实现可能会覆盖值而不是累积它们。 该解决方案正确使用`+=`所以每一项贡献都包括在内。
