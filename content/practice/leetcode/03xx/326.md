 # LeetCode 326 - 三的幂

 ## 问题理解

 该问题要求我们确定给定的整数是否`n`可以表示为三的幂。 用数学术语来说，我们需要检查是否存在一个整数`x`这样：$$n = 3^x$$三的幂数列如下所示：$$1, 3, 9, 27, 81, 243, \dots$$输入是单个整数`n`，输出应该是一个布尔值：

 - 返回`true`如果`n`正好等于三的某个幂。 
- 返回`false`否则。 

一个重要的细节是，在此问题上下文中，仅针对非负指数定义幂。 这意味着：

 -`3^0 = 1`被认为是三的有效幂。 
- 负数永远不可能是三的幂。 
- 零不是三的幂，因为没有指数满足`3^x = 0`。 

限制条件是：$$-2^{31} \le n \le 2^{31} - 1$$这告诉我们输入符合标准 32 位有符号整数范围。 由于三的幂呈指数增长，因此在此范围内只有少量有效的三的幂。 具体来说：$$3^{19} = 1162261467$$是有符号 32 位整数中最大的 3 的幂。 

一些边缘情况很重要：

 -`n <= 0`应该总是返回`false`。 
-`n = 1`应该返回`true`因为`1 = 3^0`。 
- 应该返回不是三的精确幂的大正数`false`。 
- 负值应立即返回`false`。 

## 方法

 ### 蛮力方法

 蛮力的想法很简单。 开始于`n`, 反复除以`3`而该数字可以被整除`3`。 

例如：

-`27 → 9 → 3 → 1`如果我们最终达到`1`，那么这个数字就是三的幂。 如果在某个时刻该数字不能被整除`3`，那么它就不是三的幂。 

这是可行的，因为三的每一个幂都可以化简为`1`通过重复除以`3`。 

尽管该解决方案对于给定的约束已经足够有效，但它仍然使用循环。 后续问题询问我们是否可以在没有循环或递归的情况下解决问题。 

### 最优数学观察

 关键的观察是三的所有幂都除以整数范围内三的最大幂。 

32 位有符号整数中 3 的最大幂为：$$3^{19} = 1162261467$$如果`n`是三的幂，那么它必须被整除`1162261467`。 

例如：

-`1162261467 % 27 == 0`-`1162261467 % 9 == 0`-`1162261467 % 12 != 0`这是有效的，因为三的幂不包含除质因数之外的质因数`3`。 因此，每一个较小的三的幂都是最大幂的约数。 

这为我们提供了一个没有循环或递归的恒定时间解决方案。

 ## 算法演练

 ### 最优数学解

 1.首先检查是否`n`是积极的。 

三的幂始终是正数。 如果`n <= 0`，立即返回`false`。 
2. 存储适合 32 位有符号整数的最大 3 次方。 

该值为：$$1162261467 = 3^{19}$$3. 检查是否`n`均匀地划分这个数字。 

如果：$$1162261467 \bmod n = 0$$然后`n`必须是三的幂。 
4. 返回整除性检查的结果。 

### 为什么它有效

 数量`1162261467`完全由素因数组成`3`。 该数字的任何除数也必须仅包含因子`3`。 因此，每个正因数`1162261467`本身就是三的幂。 这保证了检查整除性时可以正确识别 32 位整数范围内的所有 3 的幂。 

## Python 解决方案```python
class Solution:
    def isPowerOfThree(self, n: int) -> bool:
        MAX_POWER_OF_THREE = 1162261467  # 3^19

        return n > 0 and MAX_POWER_OF_THREE % n == 0
```该实现首先定义适合有符号 32 位整数的 3 的最大幂。 

条件`n > 0`过滤掉所有无效值，例如零和负数。 这是必要的，因为在某些情况下，单独的模运算会错误地允许负除数。 

第二个条件检查是否`n`划分`1162261467`均匀。 如果是的话，那么`n`必须是该数字因式分解中包含的三的幂之一。 

该解决方案很简洁，因为数学属性消除了对循环或递归的需要。 

## 解决方案```go
func isPowerOfThree(n int) bool {
	const maxPowerOfThree = 1162261467 // 3^19

	return n > 0 && maxPowerOfThree%n == 0
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 使用`%`类似于 Python 的模运算运算符。 由于 3 的最大幂很适合 32 位有符号整数，因此这里不存在溢出问题。 

该函数直接返回布尔表达式，这使得实现紧凑且高效。

 ## 边缘情况

 ### 边缘情况 1：零

 价值`0`是错误的常见来源，因为如果不小心处理，重复的除法逻辑可能会出现意外的行为。 三的指数不会产生零，所以正确的答案总是`false`。 

该实现使用以下条件安全地处理此问题：```
n > 0
```这会在执行模运算之前立即拒绝零。 

### 边缘情况 2：负数

 负整数永远不可能是三的幂，因为正底数升到整数指数仍然是正数。 

仅检查整除性的简单实现可能会意外地允许一些负值。 积极性检查完全可以防止这个问题。 

例如：```
n = -27
```回报`false`立即地。 

### 边缘情况 3：一

 价值`1`是一个重要的数学边缘情况，因为：$$1 = 3^0$$一些实现错误地假设权力必须从`3`，导致他们拒绝`1`。 

该解决方案可以正确处理它，因为：```
1162261467 % 1 == 0
```返回`true`。
