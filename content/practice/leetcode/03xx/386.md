 ## 解决方案

 ## 问题理解

 该问题要求我们生成所有整数`1`到`n`，但不是按正常的数字顺序。 相反，数字必须按字典顺序（也称为字典顺序）出现。 

字典顺序将数字作为字符串而不是数值进行比较。 例如：

-`"1"`出现在之前`"10"`-`"10"`出现在之前`"11"`-`"2"`之后`"13"`如果`n = 13`，字典顺序变为：```
1, 10, 11, 12, 13, 2, 3, 4, 5, 6, 7, 8, 9
```输入是单个整数`n`，表示范围的上限`[1, n]`。 

输出必须包含该范围内的每个整数一次，并按字典顺序排序。 

这个问题的重要部分不是简单地产生正确的排序，而是在严格的复杂性要求下这样做：

 - 时间复杂度必须是`O(n)`- 额外的空间复杂度必须是`O(1)`这些约束立即消除了将数字转换为字符串并直接排序的解决方案，因为排序需要`O(n log n)`时间和额外的内存。 

约束条件`1 <= n <= 5 * 10^4`不是很大，但问题明确需要最佳遍历策略，而不是依赖内置排序。 

一些边缘情况很重要：

 -`n = 1`，最小可能的输入
 - 结尾的数字`9`，其中遍历必须正确回溯
 - 乘以的数字`10`超过`n`- 过渡像`19 -> 2`，它们在数字上不相邻，但在字典顺序上相邻
 - 输入如`100`，存在深层词典分支的地方

 在前缀之间的这些转换期间，简单的实现通常会失败。 

## 方法

 ### 蛮力方法

 最简单的方法是：

 1. 生成所有整数`1`到`n`2. 将每个整数转换为字符串
 3. 按字典顺序对字符串进行排序
 4. 将它们转换回整数

 例如：```
numbers = [1, 2, 3, ..., n]
numbers.sort(key=str)
```这是可行的，因为字符串比较自然遵循字典顺序。 

然而，排序需要`O(n log n)`比较。 此外，将数字转换为字符串并存储它们会带来额外的内存开销。 

尽管该解决方案简单且正确，但它违反了要求`O(n)`时间限制。 

### 最佳方法

 关键的见解是词典顺序形成了虚拟树结构。 

例如，如果`n = 13`:```
1
├── 10
├── 11
├── 12
└── 13

2
3
4
...
9
```每个数字就像一个前缀。 

从目前的数字来看：

 - 深入树意味着乘以`10`- 移动到下一个兄弟意味着添加`1`- 回溯意味着除以`10`这种结构允许我们模拟深度优先遍历，而无需显式构建 trie 或递归堆栈。 

遍历规则为：

 1. 尝试通过乘以更深入`10`2. 如果不可能，通过添加移动到下一个同级`1`3. 如果兄弟姐妹无效或以`9`，回溯直到存在有效的同级

 这会直接按照字典顺序生成数字`O(n)`时间和`O(1)`额外的空间。

 ## 算法演练

 ### 第 1 步：从 1 开始

 字典顺序总是以`1`，所以初始化：```
current = 1
```我们将准确生成`n`数字。 

### 步骤 2：将当前数字添加到结果中

 在每次迭代时，将当前数字附加到答案列表中。 

这保证了数字按遍历顺序记录。 

### 第 3 步：尝试更深入

 数字的字典顺序最小的孩子是通过附加数字获得的`0`。 

数学上：```
current * 10
```例子：```
1 -> 10
10 -> 100
```如果`current * 10 <= n`，我们更深入：```
current *= 10
```这将 DFS 遍历镜像到子树中。 

### 第 4 步：移至下一个兄弟姐妹

 如果无法深入，请尝试水平移动。 

例子：```
10 -> 11
11 -> 12
```这是通过以下方式完成的：```
current += 1
```但是，这仅在以下情况下有效：

 - 下一个数字不超过`n`- 当前数字不以以下结尾`9`### 步骤 5：必要时回溯

 如果：

 -`current`结束于`9`， 或者
-`current + 1 > n`那么我们必须在树中向上移动。 

我们反复除以`10`:```
current //= 10
```直到存在有效的兄弟姐妹。 

例子：```
19 -> 1 -> 2
```回溯后，增量：```
current += 1
```### 步骤 6：重复直到生成 n 个数字

 我们继续这个遍历`n`次。 

因为每个数字都被访问一次，所以总复杂度保持线性。 

### 为什么它有效

 该算法对隐式词典树执行前序 DFS 遍历。 

每一步：

 - 乘以`10`访问最左边的孩子
 - 增加访问下一个兄弟姐妹的次数
 - 除以`10`回溯到父级

 这些操作准确地再现了字典顺序，而无需显式存储树结构。 

由于每个数字都来自`1`到`n`生成一次且仅一次，该算法是正确且最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def lexicalOrder(self, n: int) -> List[int]:
        result = []
        current = 1

        for _ in range(n):
            result.append(current)

            if current * 10 <= n:
                current *= 10
            else:
                while current % 10 == 9 or current + 1 > n:
                    current //= 10

                current += 1

        return result
```实施开始于`current = 1`，它始终是第一个字典序号。 

循环完全运行`n`次，确保每个数字都生成一次。 

循环内部：

 - 当前数字附加到结果中。 
- 该算法首先尝试通过乘以更深入地了解词典树`10`。 
- 如果不可能进行更深入的遍历，则代码将回溯，直到存在有效的同级。 
- 最后，它移动到下一个兄弟使用`current += 1`。 

这`while`循环处理遍历必须在树中向上移动的所有情况，例如从`19 -> 2`或者`199 -> 2`。 

不使用递归、排序或辅助数据结构，满足要求`O(1)`额外的空间限制。 

## 解决方案```go
func lexicalOrder(n int) []int {
    result := make([]int, 0, n)
    current := 1

    for i := 0; i < n; i++ {
        result = append(result, current)

        if current*10 <= n {
            current *= 10
        } else {
            for current%10 == 9 || current+1 > n {
                current /= 10
            }

            current++
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的遍历逻辑。 

具有容量的切片`n`为了提高效率而预先分配：```go
result := make([]int, 0, n)
```Go 中的整数运算自然可以安全地处理所有必需的操作，因为约束`n <= 5 * 10^4`远低于溢出限制`int`。 

与 Python 不同，Go 没有与 Python 列表相同的动态列表大小调整语义，因此预分配容量可以避免不必要的重新分配。

 ## 边缘情况

 ### 边缘情况 1：尽可能小的输入

 当`n = 1`，答案仅包含一个数字。 

有缺陷的实现可能会错误地尝试更深层次的遍历`10`或执行不必要的回溯。 

此实现可以自然地处理这种情况，因为循环执行一次并且仅附加`1`。 

### 边缘案例 2：从 19 到 2 的过渡

 这是最重要的词典编纂转变之一。 

从数字上看，`20`如下`19`，但按字典顺序`2`接下来是。 

基于增量的简单解决方案在这里会失败。 

实现正确回溯：```
19 -> 1 -> 2
```使用重复除以`10`。 

### 边缘情况 3：以 9 结尾的数字

 每当当前数字以`9`，该级别不再有兄弟姐妹。 

例如：```
9
19
29
199
```该算法使用以下方式检测这一点：```
current % 10 == 9
```并回溯直到存在有效的下一个同级。 

### 边缘情况 4：深度分支超过 n

 假设`n = 13`。 

从`13`, 乘以`10`给出`130`，这超过了`n`。 

该算法通过以下方式避免无效遍历：```
if current * 10 <= n:
```这保证了只生成有效的数字。
