[LeetCode 第 398 题](https://leetcode.com/problems/random-pick-index/)

 **难度：** 🟡 中等
 **主题：** 哈希表、数学、油藏采样、随机

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`可能包含重复值。 我们必须设计一个类，支持为给定的目标值重复选择随机索引。 

重要的要求是，如果目标出现多次，则每个有效索引必须具有相同的返回概率。 

例如，如果：```
nums = [1, 2, 3, 3, 3]
```我们称之为：```
pick(3)
```那么有效的索引是：```
2, 3, 4
```这些索引中的每一个都必须以概率返回`1/3`。 

构造函数接收一次完整的数组，然后`pick`此后可能会多次调用该方法。 该问题保证了目标始终存在于数组中，因此我们永远不需要处理丢失的目标。 

约束条件很重要：

 -`nums.length`可以达到`2 * 10^4`-`pick`最多可调用`10^4`次

 这些限制并不是很大，但它们足够大，以至于为每个查询重复扫描整个数组可能会变得低效。 

另一个重要的细节是，该问题专门将“水库采样”列为主题之一。 这强烈表明预期的最佳解决方案应该使用水库采样，特别是因为该技术允许统一随机选择而不存储所有匹配索引。 

一些可能导致错误的边缘情况是：

 - 目标只出现一次
 - 数组中的每个元素都是相同的
 - 目标出现多次
 - 存在负数
 - 随机选择必须保持均匀分布

 最大的逻辑挑战是确保所有匹配索引之间的概率相等。 

## 方法

 ### 蛮力方法

 最直接的解决方案是预处理数组并存储每个值的所有索引。 

我们可以使用哈希映射，其中：```
value -> list of indices
```例如：```
nums = [1, 2, 3, 3, 3]
```会变成：```
{
    1: [0],
    2: [1],
    3: [2, 3, 4]
}
```那么当`pick(target)`称为：

 1. 检索该目标的索引列表
 2. 从列表中随机选择一个索引
 3. 退货

 这种方法是正确的，因为每个有效索引都被显式存储，使得统一随机选择变得简单。 

但是，它使用与数组大小成比例的额外内存。 虽然这些限制是可以接受的，但该问题是专门为鼓励更优雅的储层采样解决方案而设计的。 

### 最佳方法，油藏采样

 关键的见解是我们实际上不需要存储所有匹配的索引。 

相反，在扫描数组时，我们可以维护当前的候选答案，并用精心选择的概率来更新它。 

假设我们遇到一一匹配的索引。 

- 应以概率选择第一个匹配索引`1`- 第二个匹配索引应该用概率替换第一个`1/2`- 第三个匹配索引应该用概率替换当前答案`1/3`- 第四个匹配索引应该用概率替换当前答案`1/4`等等。 

这是水库取样。 

显着的特性是，在处理完所有匹配索引后，每个有效索引被选择的概率完全相同。 

这允许：

 -`O(1)`额外的空间
 - 统一随机选择
 - 只有一次通过数组

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 预处理后每次选取 O(1) | O(n) | 将所有索引存储在哈希映射中 |
 | 最佳 | 每次选择 O(n) | O(1) | O(1) | 使用水库采样，无需额外存储 |

 ## 算法演练

 ### 水库采样算法

 1. 将原始数组存储在类中。 

我们需要在未来访问这些号码`pick`调用，因此我们将数组保留为实例变量。 
2. 期间初始化两个变量`pick(target)`。 

-`count`跟踪到目前为止我们看到目标的次数。 
-`chosen_index`存储当前选择的答案。 
3. 从左到右扫描数组。 

对于每个索引`i`：

- 如果`nums[i] != target`，跳过它。 
- 否则，我们找到了另一个有效的候选人。 
4. 增加发生计数器。 

如果这是`k`目标第 次出现，则：```
count = k
```5. 随机决定是否替换当前答案。 

生成范围内的随机整数：```
[1, count]
```如果生成的数字等于`1`，用当前索引替换当前答案。 

这意味着：

 - 以概率选择第一次出现`1`- 第二次出现用概率取代前一次`1/2`- 第三次出现用概率取代前一次`1/3`等等。 
6. 继续扫描直至结束。 

扫描完成后返回`chosen_index`。 

### 为什么它有效

 储层采样保证了均匀的概率。 

假设有`m`目标的出现次数。 

考虑任何特定的事件。 

- 有概率`1/k`第一次遇到时就被选中。 
- 然后它以正确的概率在未来的替换尝试中幸存下来。 

数学进行了简化，以便每次出现都以准确的概率结束：```
1/m
```因此，每个有效索引被返回的可能性是相同的。 

## Python 解决方案```python
import random
from typing import List

class Solution:

    def __init__(self, nums: List[int]):
        self.nums = nums

    def pick(self, target: int) -> int:
        count = 0
        chosen_index = -1

        for index, value in enumerate(self.nums):
            if value == target:
                count += 1

                # Replace current choice with probability 1/count
                if random.randint(1, count) == 1:
                    chosen_index = index

        return chosen_index

# Your Solution object will be instantiated and called as such:
# obj = Solution(nums)
# param_1 = obj.pick(target)
```构造函数只是存储输入数组，以便在将来的查询中可以重用它。 

里面`pick`，我们迭代数组并仅处理值等于目标的位置。 

变量`count`跟踪到目前为止已看到的有效事件数。 每次遇到另一个有效索引时，我们都会随机决定是否替换当前答案。 

表达式：```python
random.randint(1, count) == 1
```确保当前索引被概率选择`1/count`。 

遍历结束时，每个有效索引都有相同的概率存储在`chosen_index`。 

该实现使用恒定的额外空间，因为我们从不存储所有匹配的索引。 

## 解决方案```go
package main

import (
	"math/rand"
)

type Solution struct {
	nums []int
}

func Constructor(nums []int) Solution {
	return Solution{
		nums: nums,
	}
}

func (this *Solution) Pick(target int) int {
	count := 0
	chosenIndex := -1

	for index, value := range this.nums {
		if value == target {
			count++

			// Replace current choice with probability 1/count
			if rand.Intn(count) == 0 {
				chosenIndex = index
			}
		}
	}

	return chosenIndex
}

/**
 * Your Solution object will be instantiated and called as such:
 * obj := Constructor(nums);
 * param_1 := obj.Pick(target);
 */
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个小小的区别是随机 API：```go
rand.Intn(count)
```返回范围内的随机整数：```go
[0, count-1]
```所以检查：```go
== 0
```给出概率`1/count`。 

Go 中的切片自然地处理动态数组存储，因此我们只需将输入切片存储在结构体中即可。 

## 工作示例

 ### 示例 1```
nums = [1, 2, 3, 3, 3]
pick(3)
```有效索引是：```
2, 3, 4
```假设随机选择按如下方式进行。 

| 步骤| 索引 | 价值| 计数| 随机决策 | 选择索引 |
 | --- | --- | --- | --- | --- | --- |
 | 开始| - | - | 0 | - | -1 |
 | 0 | 0 | 1 | 0 | 跳过| -1 |
 | 1 | 1 | 2 | 0 | 跳过| -1 |
 | 2 | 2 | 3 | 1 | 自动选择 | 2 |
 | 3 | 3 | 3 | 2 | 替换为概率 1/2 | 3 |
 | 4 | 4 | 3 | 3 | 保留上一个 | 3 |

 最终答案：```
3
```另一个执行可能会返回`2`或者`4`。 

每一个都有概率`1/3`。 

### 示例 2```
nums = [1, 2, 3, 3, 3]
pick(1)
```仅存在一个匹配索引。 

| 步骤| 索引 | 价值| 计数| 选择索引 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 1 | 1 | 0 |
 | 1 | 1 | 2 | 1 | 0 |
 | 2 | 2 | 3 | 1 | 0 |
 | 3 | 3 | 3 | 1 | 0 |
 | 4 | 4 | 3 | 1 | 0 |

 最终答案：```
0
```由于仅存在一个有效索引，因此始终返回该索引。

 ## 边缘情况

 ### 目标仅出现一次

 一种常见的错误是意外地引入随机性，即使只有一个有效索引也是如此。 

例如：```
nums = [1, 2, 3]
target = 2
```答案必须始终是索引`1`。 

水库采样实现可以自然地处理这个问题，因为第一次出现是按概率选择的`1`，并且没有后来的事件可以取代它。 

### 所有元素都相同

 考虑：```
nums = [5, 5, 5, 5]
```每个索引必须具有相等的概率。 

有缺陷的实现可能会意外地偏向较早或较晚的索引。 

储层采样避免了这种情况，因为每次出现都会以完全正确的概率替换先前的答案。 

### 负数

 某些实现错误地假定值是非负的或使用值作为数组索引。 

例如：```
nums = [-1, -2, -1]
```我们的解决方案仅比较值是否相等，从不将它们用作索引，因此负数无需任何特殊处理即可工作。
