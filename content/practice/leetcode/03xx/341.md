[LeetCode 第 341 题](https://leetcode.com/problems/flatten-nested-list-iterator/)

 **难度：** 🟡 中等
 **主题：** 堆栈、树、深度优先搜索、设计、队列、迭代器

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个迭代器，它可以遍历深度嵌套的列表结构，就好像它是一个平面整数列表一样。 

输入不是普通数组。 里面的每个元素`nestedList`可以是以下两种情况之一：

 - 单个整数
 - 另一个包含更多内容的列表`NestedInteger`物体

 这些嵌套列表本身可能包含其他嵌套列表，可能深很多层。 

目标是使用标准迭代器接口实现迭代器：

 -`next()`按展平顺序返回下一个整数
 -`hasNext()`告诉我们另一个整数是否仍然存在

 迭代器的行为应该与整个嵌套结构从左到右展平为简单的一维数组一样。 

例如：```
[[1,1],2,[1,1]]
```应该表现得像：```
[1,1,2,1,1]
```和：```
[1,[4,[6]]]
```应该表现得像：```
[1,4,6]
```重要的细节是展平必须保留原始的从左到右的遍历顺序。 

限制条件适中：

 - 最多 500 个顶级元素
 - 任意嵌套深度
 - 整数值的范围可以是`-10^6`到`10^6`相对较小的输入大小意味着即使急切的扁平化方法也是可以接受的。 然而，问题本质上是关于迭代器设计的，因此惰性遍历解决方案通常被认为是更优雅且更受面试青睐的方法。 

一些边缘情况很重要：

 - 列表只能包含整数
 - 列表只能包含嵌套的空列表
 - 嵌套可能非常深
 - 列表可以在整数和子列表之间交替
 - 第一个元素本身可能是深度嵌套的

 如果幼稚的实现不能正确保留遍历顺序或者错误地处理嵌套空列表，则很容易失败。 

## 方法

 ### 蛮力方法

 强力解决方案是在初始化期间完全展平嵌套结构。 

我们对整个嵌套列表执行深度优先遍历，并将每个整数附加到普通数组中。 然后：

-`next()`简单地返回展平数组中的下一个元素
 -`hasNext()`checks whether the index is still within bounds

 这种方法简单且易于推理，因为预处理后迭代器逻辑变得微不足道。 

递归展平过程之所以有效，是因为深度优先遍历自然地保留了所需的从左到右的顺序。 

然而，这个解决方案会预先处理整个结构，即使调用者只请求几个元素。 它还将所有整数同时存储在内存中。 

### 最佳方法

 更好的解决方案是使用堆栈来延迟展平。 

我们只在必要时扩展嵌套列表，而不是预处理所有内容。 迭代器维护仍需要处理的元素堆栈。 

关键的见解是堆栈自然地模拟递归深度优先遍历。 

为了保持从左到右的顺序，每当我们遇到嵌套列表时，我们都会以相反的顺序将其内容推入堆栈。 这确保了最左边的元素出现在堆栈顶部并首先被处理。 

这种设计为我们提供了一个迭代器，可以增量地处理元素并避免不必要的前期工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 初始化期间完全展平结构 |
 | 最佳 | O(n) | O(d) average, O(n) worst case | Uses lazy DFS traversal with a stack |

 这里：

-`n`是整数和嵌套容器的总数
 -`d`是最大嵌套深度

 ## 算法演练

 ### 基于惰性堆栈的 DFS

 1. 以相反顺序使用所有顶级元素初始化堆栈。 

我们颠倒顺序，因为堆栈是 LIFO 结构。 反转可确保首先处理最左边的元素。 
2. 实施`hasNext()`这样就保证了栈顶是一个整数。 

这是算法中最重要的部分。 
3. 当堆栈不为空时：

 - 查看顶部元素而不将其移除。 
- 如果它是一个整数，我们准备返回`True`。 
- 如果是嵌套列表，则将其从堆栈中弹出并展开其内容。 
4. 展开嵌套列表时：

 - 检索包含的列表
 - 将其元素按相反顺序压入堆栈

 同样，反转保留了正确的遍历顺序。 
5. 如果栈最终变空，则返回`False`。 

这意味着没有整数剩余。 
6. 实施`next()`通过第一次调用`hasNext()`。 

这保证顶部元素在删除之前是整数。 
7. 从堆栈中弹出整数并返回其值。 

### 为什么它有效

 堆栈始终代表 DFS 遍历的剩余部分。 

不变量是：

 - 如果`hasNext()`回报`True`，栈顶保证是一个整数。 
- 元素以相反的顺序压入，因此弹出遵循原始的从左到右的遍历顺序。 

因为每个嵌套列表都恰好扩展一次，并且每个整数都恰好返回一次，所以迭代器会生成正确的展平序列。 

## Python 解决方案```python
# """
# This is the interface that allows for creating nested lists.
# You should not implement it, or speculate about its implementation
# """
# class NestedInteger:
#     def isInteger(self) -> bool:
#         pass
#
#     def getInteger(self) -> int:
#         pass
#
#     def getList(self) -> [NestedInteger]:
#         pass

from typing import List

class NestedIterator:
    def __init__(self, nestedList: [NestedInteger]):
        self.stack = nestedList[::-1]

    def next(self) -> int:
        self.hasNext()
        return self.stack.pop().getInteger()

    def hasNext(self) -> bool:
        while self.stack:
            top = self.stack[-1]

            if top.isInteger():
                return True

            self.stack.pop()

            nested = top.getList()

            for item in reversed(nested):
                self.stack.append(item)

        return False

# Your NestedIterator object will be instantiated and called as such:
# i, v = NestedIterator(nestedList), []
# while i.hasNext():
#     v.append(i.next())
```该实现使用单个堆栈来模拟递归 DFS 遍历。 

在初始化期间，我们反转顶级列表并将其存储在堆栈中。 这确保第一个元素出现在顶部。 

这`hasNext()`方法惰性地执行所有展平工作。 它反复检查顶部元素：

 - 如果已经是整数，则可以立即继续迭代。 
- 如果它是一个列表，则该列表将被扩展，并且其内容将以相反的顺序推回到堆栈中。 

这保证了当`hasNext()`成功完成后，栈顶元素始终是整数。 

这`next()`方法故意简单。 它首先通过调用确保存在有效的整数`hasNext()`，然后弹出并返回该整数。 

这种职责分离使迭代器逻辑保持干净和健壮。 

## 解决方案```go
/**
 * // This is the interface that allows for creating nested lists.
 * // You should not implement it, or speculate about its implementation
 * type NestedInteger struct {
 * }
 *
 * func (this NestedInteger) IsInteger() bool {}
 * func (this NestedInteger) GetInteger() int {}
 * func (this NestedInteger) GetList() []*NestedInteger {}
 */

type NestedIterator struct {
	stack []*NestedInteger
}

func Constructor(nestedList []*NestedInteger) *NestedIterator {
	stack := make([]*NestedInteger, 0)

	for i := len(nestedList) - 1; i >= 0; i-- {
		stack = append(stack, nestedList[i])
	}

	return &NestedIterator{
		stack: stack,
	}
}

func (this *NestedIterator) Next() int {
	this.HasNext()

	n := len(this.stack)
	val := this.stack[n-1].GetInteger()

	this.stack = this.stack[:n-1]

	return val
}

func (this *NestedIterator) HasNext() bool {
	for len(this.stack) > 0 {
		top := this.stack[len(this.stack)-1]

		if top.IsInteger() {
			return true
		}

		this.stack = this.stack[:len(this.stack)-1]

		nested := top.GetList()

		for i := len(nested) - 1; i >= 0; i-- {
			this.stack = append(this.stack, nested[i])
		}
	}

	return false
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

主要区别是显式切片操作：

 - 从堆栈中删除使用切片
 - 追加动态扩展切片

 Go 还需要指针处理，因为`GetList()`回报`[]*NestedInteger`。 

与 Python 不同，Go 不允许负索引，因此访问顶部元素需要显式长度计算。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个整数和列表最多被处理一次 |
 | 空间| 平均 O(d)，最坏情况 O(n) | 栈存储嵌套遍历状态|

 时间复杂度是线性的，因为每个元素恰好进入和离开堆栈一次。

class NestedInteger:
    def __init__(self, value=None):
        if isinstance(value, int):
            self.integer = value
            self.list = None
        else:
            self.integer = None
            self.list = value if value is not None else []

    def isInteger(self):
        return self.integer is not None

    def getInteger(self):
        return self.integer

    def getList(self):
        return self.list

def build_nested(data):
    if isinstance(data, int):
        return NestedInteger(data)

    return NestedInteger([build_nested(x) for x in data])

    nested = [build_nested(x) for x in data]

    iterator = NestedIterator(nested)

    result = []

    while iterator.hasNext():
        result.append(iterator.next())

    return result

 ## 边缘情况

 ### 深度嵌套单整数

 输入如下：```
[[[[[[1]]]]]]
```可能会暴露实现中无法正确递归或重复扩展嵌套列表的错误。 

基于堆栈的方法可以自然地处理这个问题，因为`hasNext()`不断扩展嵌套列表，直到顶部元素变成整数。 

### 嵌套空列表

 输入例如：```
[[[]]]
```特别危险，因为迭代器必须正确跳过空容器，而不会错误地报告可用整数。 

该实现通过重复扩展列表来处理此问题，直到：

 - 找到一个整数
 - 堆栈变空

 空列表只是不向堆栈贡献任何新元素。 

### 交替整数和列表

 输入如：```
[1,[2],3,[4,[5]]]
```如果元素不按相反顺序推送，可能会破坏顺序。 

该算法在推入堆栈之前显式反转每个扩展列表。 这保证了原始的从左到右的遍历顺序被准确地保留。
