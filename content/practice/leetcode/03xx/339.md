[LeetCode 第 339 题](https://leetcode.com/problems/nested-list-weight-sum/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个特殊的嵌套数据结构，称为`NestedInteger`。 输入中的每个元素可以是：

 1. 单个整数
 2. 另一个包含更多内容的列表`NestedInteger`物体

 目标是计算加权和，其中每个整数乘以它出现的深度。 

深度开始于`1`对于直接位于顶级列表内的元素。 每次我们将嵌套列表更深一层，深度就会增加`1`。 

例如，考虑：```
[1,[4,[6]]]
```整数`1`处于深度`1`, 整数`4`处于深度`2`，和整数`6`处于深度`3`。 

所以最终的答案就变成了：```
1 * 1 + 4 * 2 + 6 * 3 = 27
```输入使用以下表示`NestedInteger`界面。 我们自己不实现这个接口。 相反，我们通过提供的方法与它交互：

 -`isInteger()`告诉我们当前对象是否存储单个整数
 -`getInteger()`返回该整数
 -`getList()`返回嵌套列表

 限制相对较小：

 - 至多`50`顶级列表中的元素
 - 最大嵌套深度为`50`- 整数值范围为`-100`到`100`这些约束告诉我们，递归在这里是完全安全的，因为递归深度是有界的。 他们还告诉我们，一个`O(n)`遍历就足够了。 

一些边缘情况很重要：

 - 一个列表只能包含一个整数
 - 嵌套列表可能嵌套得很深
 - 值可以为负数
 - 可能会出现空嵌套列表
 - 结果可能是`0`即使元素存在

 正确的解决方案必须在遍历所有嵌套结构时正确跟踪深度。 

## 方法

 ### 蛮力方法

 强力方法会逐层重复扫描嵌套结构。 一种可能的实现可以首先将结构扁平化为成对的`(value, depth)`然后计算加权和。 

例如：```
[1,[4,[6]]]
```首先可以变成：```
[(1,1), (4,2), (6,3)]
```然后我们会计算：```
1*1 + 4*2 + 6*3
```这是正确的，因为每个整数最终都会连同它的深度一起被发现。 然而，根据实现的不同，重复遍历嵌套结构或存储所有中间对会增加不必要的工作和内存使用。 

主要的低效率是我们实际上不需要在计算结果之前存储所有值。 我们可以在遍历过程中立即计算贡献。 

### 关键见解

 重要的观察是每个整数对最终答案都有独立的贡献。 

一旦我们遇到一个整数，我们就已经知道：

 - 它的价值
 - 当前深度

 因此，我们可以立即添加：```
value * depth
```到运行总计。 

这自然会导致深度优先遍历，其中：

 - 输入嵌套列表可增加深度
 - 离开列表会通过递归自动减少深度

 递归 DFS 解决方案很干净，因为结构本身是递归的。 每个嵌套列表都包含同一问题的较小版本。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 在计算结果之前展平结构 |
 | 最优 DFS | O(n) | O(d) | 遍历期间计算加权和 |

 这里：

-`n`是嵌套元素的总数
 -`d`是最大深度

 ## 算法演练

 ### 最优DFS算法

 1. 初始化一个变量来存储总加权和。 
2. 创建一个递归辅助函数，它接受：

 - 清单`NestedInteger`物体
 - 当前深度
 3. 迭代当前列表中的每个元素。 
4. 对于每个元素：

 - 如果是整数：

 - 使用检索其值`getInteger()`- 将其乘以当前深度
 - 将结果添加到总数中
 - 否则：

 - 使用检索嵌套列表`getList()`- 递归地处理该列表`depth + 1`5. 使用原始函数开始递归`nestedList`和深度`1`。 
6. 遍历结束后，返回累计总数。 

### 为什么它有效

 该算法之所以有效，是因为每个整数都在正确的递归深度上被恰好访问一次。 

递归调用保持不变式：

 > 的`depth`参数始终与当前列表的实际嵌套级别匹配。 

每当递归进入更深的嵌套列表时，深度就会增加`1`。 因此，当处理整数时，乘以当前深度正好产生所需的加权贡献。 

由于遍历了每个嵌套元素并且每个整数贡献一次，因此最终的总和是正确的。 

## Python 解决方案```python
from typing import List

# """
# This is the interface that allows for creating nested lists.
# You should not implement it, or speculate about its implementation
# """
# class NestedInteger:
#     def isInteger(self) -> bool:
#         pass
#
#     def getInteger(self) -> int:
#         pass
#
#     def getList(self) -> List['NestedInteger']:
#         pass

class Solution:
    def depthSum(self, nestedList: List[NestedInteger]) -> int:
        def dfs(current_list: List[NestedInteger], depth: int) -> int:
            total = 0

            for nested in current_list:
                if nested.isInteger():
                    total += nested.getInteger() * depth
                else:
                    total += dfs(nested.getList(), depth + 1)

            return total

        return dfs(nestedList, 1)
```该解决方案使用名为的递归辅助函数`dfs`。 

助手接收当前嵌套列表和当前深度。 对于每个元素，它检查该元素是整数还是另一个嵌套列表。 

如果元素是整数，则其加权贡献会立即添加到运行总计中。 

如果该元素是另一个列表，则递归会在下一个深度级别处理该子列表。 

递归自然地反映了输入的嵌套结构。 每个递归调用独立处理一层嵌套，这使得实现简洁且易于推理。 

最后的通话从深度开始`1`因为最外面的列表对应深度`1`。 

## 解决方案```go
/**
 * // This is the interface that allows for creating nested lists.
 * // You should not implement it, or speculate about its implementation
 * type NestedInteger struct {
 * }
 *
 * func (n NestedInteger) IsInteger() bool {}
 * func (n NestedInteger) GetInteger() int {}
 * func (n NestedInteger) GetList() []*NestedInteger {}
 */

func depthSum(nestedList []*NestedInteger) int {
    var dfs func([]*NestedInteger, int) int

    dfs = func(currentList []*NestedInteger, depth int) int {
        total := 0

        for _, nested := range currentList {
            if nested.IsInteger() {
                total += nested.GetInteger() * depth
            } else {
                total += dfs(nested.GetList(), depth+1)
            }
        }

        return total
    }

    return dfs(nestedList, 1)
}
```Go 实现遵循与 Python 版本相同的递归 DFS 策略。 

一个区别是 Go 使用指向`NestedInteger`对象：```go
[]*NestedInteger
```而不是 Python 对象引用。 

递归助手是使用函数变量声明的，因此它可以递归引用自身。 

Go 切片已经是对底层数组的动态引用，因此将嵌套列表传递到递归调用中是高效的。 

整数溢出不是问题，因为约束非常小。

 ## 边缘情况

 ### 深度嵌套结构

 输入如下：```
[[[[[1]]]]]
```可以轻松暴露深度跟踪中的错误。 忘记在递归期间增加深度的解决方案将产生错误的加权贡献。 

此实现可以正确处理这种情况，因为每个递归调用都显式使用：```
depth + 1
```这保证了准确的嵌套级别。 

### 空嵌套列表

 嵌套结构可能包含空列表，例如：```
[[],[[]]]
```幼稚的实现可能会错误地假设每个嵌套列表都包含整数。 

该解决方案可以安全地处理空列表，因为迭代空列表不会执行任何工作并且会做出贡献`0`至总数。 

### 负值

 该问题允许整数在以下范围内：```
[-100, 100]
```负值会产生负加权和。 

例如：```
[-1,[-2]]
```产生：```
(-1 * 1) + (-2 * 2) = -5
```此实现自然地处理负数，因为乘法和加法对于正整数和负整数的工作方式相同。 

### 单个顶级整数

 仅包含一个整数的输入：```
[7]
```很重要，因为算法仍然必须将顶级深度视为`1`。 

该解决方案以递归开始：```
dfs(nestedList, 1)
```这保证了顶级整数的正确权重。
