 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们一棵无向树`n`节点标记为`0`到`n - 1`。 输入`edges`描述节点之间的连接，并且由于该图保证是一棵树，因此几个重要的属性立即成立。 

一棵树与`n`节点总是有精确的`n - 1`边，并且任意一对节点之间都只有一条路径。 这意味着该图是连通的并且不包含环。 

任务是确定可以选择哪个或哪些节点作为根，以使生成的有根树具有尽可能小的高度。 

有根树的高度定义为从根到任意叶节点的最长向下路径上的边数。 不同的根选择会产生截然不同的高度。 

例如，考虑一棵星形树：```
    0
    |
2 - 1 - 3
```如果节点`1`是根，高度是`1`，因为每个其他节点都直接连接到它。 如果改为节点`0`是根，高度变为`2`。 

该问题要求我们返回产生最小可能高度的所有节点。 

约束条件很重要：

 -`1 <= n <= 2 * 10^4`- 该图保证是一棵有效的树

 的上限`20,000`节点意味着低效的重复遍历可能会变得太慢。 任何算法明显比`O(n)`或者`O(n log n)`可能会挣扎。 

有几个重要的边缘情况：

 - 一棵只有一个节点的树
 - 具有两个节点的树
 - 线形树，中间节点或中间两个节点成为答案
 - 星形树，中心节点就是答案

 保证输入始终是树简化了问题，因为我们永远不需要处理断开连接的图或循环。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试将每个节点作为根。 

对于每个节点：

 1. 运行 BFS 或 DFS 来计算该节点的最大深度
 2. 将最大深度视为树高
 3. 记录遇到的最小高度
 4. 返回达到该最小值的所有节点

 这是有效的，因为我们直接评估问题的定义。 测试每个可能的根，并计算准确的高度。 

然而，这对于约束来说太慢了。 

如果我们从每个节点执行 BFS 或 DFS：

 - 每次穿越费用`O(n)`- 我们向所有人重复这一点`n`节点

 这导致`O(n^2)`时间复杂度。 

和`n = 20,000`，在最坏的情况下这会变成大约 4 亿次操作，这太昂贵了。 

### 最优方法，拓扑叶子修剪

 关键的见解是最小高度的树根始终位于树的中心附近。 

考虑重复删除所有叶节点：

 - 叶子是只有一个连接的节点
 - 去除外层使树逐渐向内收缩
 - 最终只剩下一个或两个中心节点

 这些剩余的节点正是最小高度树的根。 

这个过程与使用入度的拓扑排序非常相似：

 - 叶子有度数`1`- 我们反复删除当前的叶子
 - 他们的邻居可能会成为新叶
 - 继续直到最多剩下两个节点

 为什么最多两个？ 

一棵树可以有：

 - 1个中心节点
 - 两个中心节点

 这对应于树直径的长度是奇数还是偶数。 

由于每个边和节点仅处理一次，因此该解决方案以线性时间运行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 从每个节点运行 BFS/DFS 来计算高度 |
 | 最佳| O(n) | O(n) | 反复修剪叶子，直到保留树中心|

 ## 算法演练

 1. 处理单节点边缘情况。 

如果`n == 1`，没有边，唯一可能的根是节点`0`。 返回`[0]`。 
2. 构建邻接表。 

由于图是无向的，每条边`[u, v]`被添加到两个邻接列表中。 

我们还维护一个度数数组，其中`degree[i]`存储有多少个邻居节点`i`目前有。 
3. 识别所有初始叶子。 

叶子是度数等于的任何节点`1`。 

我们将所有叶子放入队列中，因为它们构成了树的最外层。 
4. 反复逐层去除叶子。 

在每次迭代时：

 - 计算当前存在多少叶子
 - 将它们从树上移除
 - 降低邻居的度数
 - 如果邻居成为学位`1`，它变成新叶

 这模拟了从外向内剥树。 
5. 当最多剩余两个节点时停止。 

其余节点是树的中心。 

这些中心保证生产最低高度的树木。 

### 为什么它有效

 该算法之所以有效，是因为有根树的高度取决于到任何叶子的最大距离。 靠近外部的节点自然会产生更大的高度，因为到相对侧的路径变得更长。 

通过反复删除叶子，我们消除了不可能是最佳根的节点。 该过程向树的几何中心收敛。 

一棵树只能有一个或两个中心，这些中心最小化到所有其他节点的最大距离。 因此，最终剩余的节点正是所有最小高度树的根。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def findMinHeightTrees(self, n: int, edges: List[List[int]]) -> List[int]:
        if n == 1:
            return [0]

        graph = [[] for _ in range(n)]
        degree = [0] * n

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)

            degree[u] += 1
            degree[v] += 1

        leaves = deque()

        for node in range(n):
            if degree[node] == 1:
                leaves.append(node)

        remaining_nodes = n

        while remaining_nodes > 2:
            leaf_count = len(leaves)
            remaining_nodes -= leaf_count

            for _ in range(leaf_count):
                leaf = leaves.popleft()

                for neighbor in graph[leaf]:
                    degree[neighbor] -= 1

                    if degree[neighbor] == 1:
                        leaves.append(neighbor)

        return list(leaves)
```实现首先处理树仅包含一个节点的特殊情况。 由于没有边，节点`0`一定是答案。 

接下来，构造邻接表和度数组。 邻接列表允许有效的邻居遍历，而度数组则跟踪每个节点当前有多少个活动连接。 

队列存储所有当前叶子。 使用队列是合适的，因为我们逐级处理叶子，类似于 BFS。 

变量`remaining_nodes`跟踪有多少节点仍然是活动树的一部分。 每次迭代都会删除整个外层。 

对于每一个被移除的叶子，我们都会减少其邻居的度数。 当邻居的学位变成`1`，它已成为新叶并被添加到队列中。 

一旦只剩下一两个节点，该过程就会停止。 这些节点作为答案返回。 

## 解决方案```go
func findMinHeightTrees(n int, edges [][]int) []int {
	if n == 1 {
		return []int{0}
	}

	graph := make([][]int, n)
	degree := make([]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)

		degree[u]++
		degree[v]++
	}

	queue := []int{}

	for i := 0; i < n; i++ {
		if degree[i] == 1 {
			queue = append(queue, i)
		}
	}

	remainingNodes := n

	for remainingNodes > 2 {
		leafCount := len(queue)
		remainingNodes -= leafCount

		nextQueue := []int{}

		for _, leaf := range queue {
			for _, neighbor := range graph[leaf] {
				degree[neighbor]--

				if degree[neighbor] == 1 {
					nextQueue = append(nextQueue, neighbor)
				}
			}
		}

		queue = nextQueue
	}

	return queue
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但使用切片而不是 Python 列表和双端队列。 

该实现不是使用库中的队列结构，而是通过构建一个逐级处理切片`nextQueue`用于下一次迭代。 

Go 切片自然地处理动态调整大小，使它们适合邻接列表和 BFS 层。 

不存在整数溢出问题，因为节点计数保持在标准整数限制内。

 ## 边缘情况

 ### 单节点树

 当`n = 1`，没有边并且只存在一个可能的根。 

这种情况很重要，因为正常的叶子修剪逻辑假设至少一个边缘和至少一个具有度数的叶子`1`。 在单节点树中，度为`0`。 

如果没有显式处理，算法可能会错误地返回空结果。 

实现立即正确处理这种情况：```
if n == 1:
    return [0]
```### 二节点树

 具有两个连接节点的树有两个有效的最小高度根。 

例子：```
0 - 1
```任一节点的生根都会产生高度`1`。 

这种情况很棘手，因为两个节点从一开始就是叶子节点。 该算法正确返回两者，因为修剪过程停止一次`remaining_nodes <= 2`。 

### 长线性链条

 考虑：```
0 - 1 - 2 - 3 - 4
```如果修剪逻辑不对称，简单的实现可能会错误地偏向一侧。 

重复的叶子去除过程自然会向中心收敛：```
[0,4] -> [1,3] -> [2]
```这保证了返回中间节点。 

对于偶数长度的链，保留两个中间节点，这也可以通过停止条件正确处理。
