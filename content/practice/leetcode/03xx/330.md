 # LeetCode 330 - 修补数组

 ## 问题理解

 这个问题给了我们一个正整数的排序数组，`nums`，和一个目标整数`n`。 我们可以在数组中插入额外的数字，称为补丁。 目标是确保范围内的每个数字`[1, n]`可以形成为数组元素的某个子集的总和。 

我们需要返回实现此目标所需的最小补丁数。 

重要的细节是我们并不试图显式地生成所有子集。 相反，我们需要保证覆盖范围内的每个整数。 例如，如果我们可以形成所有数字`1`通过`6`，则覆盖范围是连续的。 如果`7`无法形成，则有间隙。 

输入数组已经按升序排序，这对于贪婪解决方案极其重要。 由于所有数字都是正数，一旦可表示范围内出现缺口，除非我们进行适当的修补，否则后面更大的数字将无法填补它。 

约束条件也很重要：

 -`nums.length <= 1000`-`n <= 2^31 - 1`目标值`n`可能非常大，因此任何显式跟踪所有可能的子集和的解决方案都是不可行的。 我们需要一个更有效的策略。 

一些边缘情况很重要：

 - 数组可能不以`1`。 在这种情况下，我们甚至无法形成这个数字`1`，因此需要立即打补丁。 
- 阵列可能已经覆盖整个范围，需要零补丁。 
- 数字之间的较大差距可能会强制使用多个补丁。 
- 自从`n`可以接近`2^31 - 1`，在像 Go 这样的具有固定大小整数的语言中必须考虑整数溢出。 
- 最佳策略必须最大限度地减少补丁，而不仅仅是实现覆盖。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试跟踪可以从数组形成的每个可能的子集和。 每当范围内出现间隙时`[1, n]`，我们可以尝试插入候选补丁并重新计算可达总和。 

一种可能的实现方式是使用动态规划或一组可达总和。 开始于`{0}`，对于每个数字，我们添加通过包含该数字而形成的所有新总和。 如果有一些值`[1, n]`丢失，我们尝试修补数字，直到实现完全覆盖。 

这种方法是正确的，因为它显式地计算了所有可实现的总和。 然而，当`n`很大。 自从`n`可以超过 20 亿，维持可达状态高达`n`在记忆和时间限制内是不可能的。 

### 最优贪心法

 关键的见解是我们不需要知道每个单独的子集总和。 相反，我们只需要跟踪我们已经可以构建的连续值范围。 

假设我们现在可以形成范围内的每个数字`[1, x - 1]`。 然后：

 - 如果下一个数组值是`<= x`，我们可以扩大覆盖范围。 
- 如果下一个数组值是`> x`， 然后`x`它本身无法形成，所以我们必须修补。 

最优补丁正是`x`。 

为什么？ 因为添加`x`扩展了可达范围`[1, x - 1]`到`[1, 2x - 1]`，这是单个补丁的最大可能扩展。 

这种贪婪的观察导致了非常有效的对数式解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 目标) 或更糟 | O（目标）| 明确跟踪所有子集总和 |
 | 最佳 | O(len(nums)) | O(len(nums)) | O(1) | O(1) | 贪婪地扩大可达范围 |

 ## 算法演练

 ### 核心贪婪不变量

 每一步，维护一个变量`miss`，表示当前无法形成的最小值。 

如果我们可以组成中的所有数字`[1, miss - 1]`，那么：

 - 使用号码`num <= miss`，我们可以将覆盖范围扩展到`[1, miss + num - 1]`。 
- 如果`num > miss`， 然后`miss`除非我们直接修补它，否则无法形成。 

### 逐步算法

 1.初始化：

 -`miss = 1`-`index = 0`-`patches = 0`最初，我们无法形成任何正数，因此最小的缺失值是`1`。 
2. 继续`miss <= n`。 

如果`miss > n`，那么中的每个值`[1, n]`已经被覆盖了。 
3. 检查当前数组值是否有帮助。 

如果`index < len(nums)`和`nums[index] <= miss`，那么这个数字就可以安全地扩展可达范围。 
4. 使用当前数组值扩展覆盖范围。 

既然我们已经介绍了`[1, miss - 1]`，添加`nums[index]`让我们涵盖：`[1, miss + nums[index] - 1]`所以：```
miss += nums[index]
```移至下一个数组元素。 
5. 否则，使用以下命令修补阵列`miss`。 

如果下一个数字大于`miss`， 然后`miss`无法形成。 

最优补丁正是`miss`。 
6. 修补后更新覆盖范围。 

添加`miss`将可达范围扩展为：`[1, miss - 1]`到：`[1, 2 * miss - 1]`所以：```
miss += miss
```增加补丁计数器。 
7. 重复直到覆盖范围超过`n`。 

### 为什么它有效

 不变的是，在每次迭代之前，我们可以将每个数字形成为`[1, miss - 1]`。 

如果下一个数组值最多为`miss`，然后将其与现有可达到的金额相结合，连续无间隙地扩大覆盖范围。 

如果下一个数组值大于`miss`，则无法形成子集`miss`。 任何有效的解决方案最多只能修补一个值`miss`。 准确选择`miss`最大化新覆盖的范围，使其成为贪婪的最优选择。 

由于每一步要么消耗一个数组元素，要么将可达范围加倍，因此该算法既正确又高效。 

## Python 解决方案```python
from typing import List

class Solution:
    def minPatches(self, nums: List[int], n: int) -> int:
        miss = 1
        index = 0
        patches = 0

        while miss <= n:
            if index < len(nums) and nums[index] <= miss:
                miss += nums[index]
                index += 1
            else:
                miss += miss
                patches += 1

        return patches
```实现直接遵循贪婪策略。 

变量`miss`代表我们当前无法构建的最小值。 最初，这是`1`。 

这`index`变量跟踪我们当前正在处理的数组元素。 由于数组已排序，因此每个可用数字均按升序排列。 

在循环内部，我们首先检查当前数组元素是否足够小以扩展可达范围。 如果是，我们将其添加到`miss`。 

否则，我们必须打补丁。 最优补丁正是`miss`，所以我们通过执行将可达范围加倍`miss += miss`。 

循环终止一次`miss > n`，表示直到`n`具有代表性。 

## 解决方案```go
func minPatches(nums []int, n int) int {
    miss := int64(1)
    patches := 0
    index := 0
    target := int64(n)

    for miss <= target {
        if index < len(nums) && int64(nums[index]) <= miss {
            miss += int64(nums[index])
            index++
        } else {
            miss += miss
            patches++
        }
    }

    return patches
}
```Go 实现与 Python 版本几乎相同，但有一个重要区别。 

自从`n`可以大到`2^31 - 1`，重复加倍可能会溢出 32 位整数。 为了避免这种情况，实现中使用`int64`为了`miss`和`target`。 

输入切片可能为零或为空，但逻辑自然会正确处理这两种情况。

 ## 边缘情况

 ### 空数组

 如果`nums`为空，我们最初无法形成任何正数。 该算法重复修补当前缺失值：```
1 -> 2 -> 4 -> 8 ...
```这会产生 2 的幂并每次都最大程度地扩大覆盖范围。 该实现自然会处理这个问题，因为数组访问条件立即失败。 

### 缺少首字母 1

 如果第一个元素大于`1`，然后是数字`1`无法形成。 这是错误的常见来源，因为某些实现假设数组已经以`1`。 

例如：```
nums = [2]
```算法正确修补`1`首先在处理之前`2`。 

### 非常大 n

 自从`n`可以接近`2^31 - 1`，在某些语言中，重复加倍可能会溢出 32 位整数。 

Go 实现通过使用避免了这种情况`int64`对于所有涉及的算术`miss`。 Python 整数会自动扩展，因此不需要特殊处理。 

### 数字之间的巨大差距

 数组如：```
[1, 100]
```包含大的无法到达的区域。 幼稚的策略可能会低效地插入任意值。 

贪心方法总是修补最小的缺失值，保证最大程度扩展可达覆盖范围并最小化修补数量。
