 # LeetCode 358 - 重新排列字符串 k 距离

 ## 问题理解

 问题给了我们一个字符串`s`和一个整数`k`。 我们必须重新排列字符串中的字符，以便相同的字符至少由`k`职位。 

短语“至少距离`k`" 表示如果同一个字符出现多次，则它们在最终字符串中的索引之间的差必须大于或等于`k`。 

例如，如果`k = 3`，然后两个`'a'`字符不能出现在彼此相邻的两个位置内。 有效的展示位置如下所示：```
a _ _ a
```因为第二个`'a'`距离第一个正好 3 个位置。 

输入包括：

 - 一根绳子`s`仅包含小写英文字母
 - 一个整数`k`输出应该是：

 - 满足距离要求的字符串的重新排列版本，或者
 - 空字符串`""`如果不存在有效的安排

 约束条件很重要：

 -`s.length`可以大到`3 * 10^5`- 只出现小写英文字母
 -`k`范围可以从`0`到`len(s)`这些约束立即告诉我们，强力排列生成是不可能的。 即使是温和指数算法对于大输入也会失败。 

只有 26 个小写字母这一事实很有用，因为频率计数变得非常有效。 

一些边缘情况很重要：

 -`k = 0`，不存在任何限制，意味着原始字符串已经有效
 - 具有一个重复字符的字符串，例如`"aaaa"`- 一个字符出现过于频繁而导致间距不够的情况
 - 非常短的弦
 - 存在多个有效答案的情况，因为问题接受任何有效的安排

 关键的挑战是平衡字符放置，以便高频字符正确分布。 

## 方法

 ### 蛮力方法

 强力解决方案将生成字符串的所有可能排列，并检查每个排列是否满足距离约束。 

对于每个排列：

 1.遍历字符串
 2.记录每个字符最后出现的索引
 3. 验证重复字符至少`k`分开

 如果找到有效的排列，则返回它。 

这种方法是正确的，因为它详尽地检查了每种可能的安排。 如果存在有效的安排，暴力最终会发现它。 

然而，排列的数量是字符串长度的阶乘：```
O(n!)
```即使对于长度为 15 或 20 的字符串，这在计算上也是不可行的。 由于该问题允许长度达到`300000`，蛮力是完全不切实际的。 

### 最优贪婪 + 最大堆方法

 关键的见解是频率最高的角色是最难放置的。 

假设我们有：```
aaabc
```和`k = 3`。 

人物`'a'`出现 3 次，因此出现次数之间需要足够的间距。 如果我们不仔细放置高频字符，我们可能会达到没有有效放置的地步。 

这表明了一种贪婪策略：

 - 始终放置当前最常用的可用角色
 - 暂时防止下次重复使用`k`职位

 最大堆非常适合选择具有最高剩余频率的字符。 

我们还需要一种机制来强制角色重新使用之前的冷却时间。 队列可以很好地解决这个问题：

 - 使用角色后，将其放入冷却队列
 - 一次`k`位置已经过去，如果仍有剩余出现，则将其重新插入堆中

 这种方法有效地模拟了间距约束，同时贪婪地构建了有效的答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! * n) | O(n! * n) | O(n!) | 生成所有排列并验证每个 |
 | 最佳| O(n log 26) = O(n) | O(n log 26) = O(n) | O(26) = O(1) | O(26) = O(1) | 使用带有堆和冷却队列的贪婪调度 |

 ## 算法演练

 ### 最优贪心堆算法

 1. 处理琐碎的情况`k <= 1`。 

如果`k`是`0`或者`1`，每一种排列都自动有效，因为相同的字符已经至少相隔一个位置。 在这种情况下，我们可以立即返回原始字符串。 
2.统计每个字符出现的频率。 

我们使用哈希图或频率计数器来确定每个字符出现的次数。 这告诉我们哪些角色最难安排。 
3. 使用字符频率构建最大堆。 

蟒蛇的`heapq`是最小堆，因此我们存储负频率来模拟最大堆行为。 

每个堆条目包含：

 - 剩余频率
 - 角色

 堆总是为我们提供剩余计数最大的字符。 
4. 创建冷却队列。 

当一个字符被使用后，它不能在下一个字符中重复使用`k - 1`职位。 

我们将最近使用的字符存储在队列中，其中包含：

 - 更新了剩余频率
 - 角色
 - 再次可用时的未来索引
 5. 反复构建答案。 

每一步：

 - 从堆中删除最常用的可用字符
 - 将其附加到结果中
 - 减少剩余频率
 - 如果仍有更多事件发生，请将其置于冷却状态
 6.释放过期的冷却角色。 

在每次放置之前，检查冷却队列中是否有任何角色已经等待了足够长的时间。 

如果它们的冷却时间已过，则将它们推回堆中。 
7. 检测不可能的情况。 

如果在结果长度达到之前堆变空`len(s)`，则接下来不能放置有效字符。 

这意味着安排不可能，所以返回`""`。 
8. 返回构造好的字符串。 

如果我们成功放置所有字符，则保证结果满足间距要求。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 至少直到`k`自上次使用以来位置已经过去。 

最大堆贪婪地优先考虑剩余频率最高的字符，这可以防止困难的字符累积到最后。 

如果算法无法继续，因为堆是空的，而未完成的字符仍然存在于冷却中，则不可能进行有效的排列。 剩下的每个字符都违反了距离要求，因此返回`""`是正确的。 

## Python 解决方案```python
from collections import Counter, deque
import heapq
from typing import Deque, List, Tuple

class Solution:
    def rearrangeString(self, s: str, k: int) -> str:
        if k <= 1:
            return s

        frequency = Counter(s)

        max_heap: List[Tuple[int, str]] = []
        for char, count in frequency.items():
            heapq.heappush(max_heap, (-count, char))

        cooldown: Deque[Tuple[int, int, str]] = deque()
        result = []

        position = 0

        while max_heap or cooldown:
            while cooldown and cooldown[0][0] <= position:
                _, remaining_count, char = cooldown.popleft()
                heapq.heappush(max_heap, (remaining_count, char))

            if not max_heap:
                return ""

            remaining_count, char = heapq.heappop(max_heap)

            result.append(char)

            remaining_count += 1

            if remaining_count < 0:
                available_position = position + k
                cooldown.append(
                    (available_position, remaining_count, char)
                )

            position += 1

        return "".join(result)
```实施从快速优化开始`k <= 1`。 在这种情况下，原始字符串已经满足要求。 

下一个，`Counter`计算每个字符的频率。 这些频率使用负计数插入到最大堆中，因为 Python 的`heapq`实现最小堆。 

冷却队列存储最近使用过且暂时不可用的角色。 每个条目跟踪：

 - 角色最早可以重复使用的位置
 - 剩余频率
 - 角色本身

 主循环每次重复构建一个字符的答案。 

在选择下一个角色之前，算法会释放所有等待期已过的冷却条目。 这些字符被推回到堆中并再次变得符合条件。 

如果构造未完成时堆变空，算法立即返回`""`因为不存在有效的延续。 

否则，将选择最常见的可用字符并将其附加到结果中。 它的频率会降低，如果还有额外的副本，它会进入冷却时间，直到`position + k`。 

最后，将结果列表连接成字符串并返回。 

## 解决方案```go
package main

import (
	"container/heap"
)

type Item struct {
	count int
	char  byte
}

type MaxHeap []Item

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i].count > h[j].count
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(Item))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

type CooldownItem struct {
	availablePos int
	count        int
	char         byte
}

func rearrangeString(s string, k int) string {
	if k <= 1 {
		return s
	}

	frequency := make(map[byte]int)

	for i := 0; i < len(s); i++ {
		frequency[s[i]]++
	}

	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	for char, count := range frequency {
		heap.Push(maxHeap, Item{
			count: count,
			char:  char,
		})
	}

	cooldown := []CooldownItem{}
	result := make([]byte, 0, len(s))

	position := 0

	for maxHeap.Len() > 0 || len(cooldown) > 0 {
		for len(cooldown) > 0 &&
			cooldown[0].availablePos <= position {

			item := cooldown[0]
			cooldown = cooldown[1:]

			heap.Push(maxHeap, Item{
				count: item.count,
				char:  item.char,
			})
		}

		if maxHeap.Len() == 0 {
			return ""
		}

		item := heap.Pop(maxHeap).(Item)

		result = append(result, item.char)

		item.count--

		if item.count > 0 {
			cooldown = append(cooldown, CooldownItem{
				availablePos: position + k,
				count:        item.count,
				char:         item.char,
			})
		}

		position++
	}

	return string(result)
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但需要使用显式堆实现`container/heap`包裹。 

与Python不同，Go不提供内置的优先级队列，因此我们定义一个自定义的`MaxHeap`实现堆接口方法的类型。 

冷却结构是使用充当队列的切片来实现的。 由于只存在小写英文字母，因此内存占用仍然非常小。 

Go 字符串是不可变的，因此结果是使用字节切片构建的，并在最后转换为字符串。

 ## 边缘情况

 ### 案例 1：`k = 0`什么时候`k`为零，则根本没有间距限制。 幼稚的实现可能仍然不必要地运行完整的堆逻辑，甚至由于冷却处理而失败。 

实现明确检查：```
if k <= 1:
    return s
```这保证了即时正确性并避免不必要的处理。 

### 情况2：某个角色出现太频繁

 考虑：```
s = "aaaaab"
k = 2
```没有足够的其他字符来分隔所有字符`'a'`发生。 

有缺陷的实现可能会贪婪地继续，直到后期失败或意外地产生无效的间距。 

当堆变空而冷却时间仍包含被阻止的字符时，基于堆的方法可以正确检测到不可能性。 此时，不存在合法的下一个字符。 

### 案例 3：非常大`k`认为：```
s = "abc"
k = 10
```由于所有字符都是唯一的，因此即使`k`超过字符串长度。 

一些不正确的解决方案假设很大`k`自动使问题变得不可能。 

当前的实现并不依赖于这样的假设。 它仅强制相同字符之间的间距，因此独特的字符自然有效。 

### 情况 4：所有字符都相同

 示例：```
s = "aaaa"
k = 2
```仅存在一种字符类型，因此除非字符串长度为一，否则不可能有空格。 

该算法自然地处理这个问题：

 - 一个`'a'`被放置
 -`'a'`进入冷却时间
 - 堆变空
 - 施工立即失败

 这正确返回`""`。
