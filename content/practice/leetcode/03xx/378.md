 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`n x n`行和列均按升序排序的矩阵。 这意味着两个订购保证同时存在：

 - 每行从左到右排序。 
- 每列都从上到下排序。 

我们被要求归还`kth`当所有元素按排序顺序一起考虑时，整个矩阵中的最小元素。 

重要的细节是我们正在寻找`kth`整体上最小的元素，而不是`kth`独特的价值。 重复值单独计数。 例如，如果矩阵包含两个`13`s，两者独立参与排序。 

对于第一个例子：```
[
  [1, 5, 9],
  [10,11,13],
  [12,13,15]
]
```如果我们对所有值进行扁平化和排序，我们会得到：```
[1,5,9,10,11,12,13,13,15]
```第 8 个最小元素是`13`。 

这些约束很重要，因为它们强烈影响哪些算法是可行的：

 -`n`可以大到`300`- 因此矩阵最多可以包含`90,000`元素
 - 值可能为负数，范围可达`10^9`- 内存使用率必须优于`O(n^2)`一种简单的解决方案，将每个值复制到另一个数组中并对其进行排序，但它忽略了矩阵的排序结构。 该问题是专门设计的，因此我们可以利用该结构来获得更有效的解决方案。 

一些边缘情况很重要：

 - A`1 x 1`矩阵，其中必须返回唯一的元素。 
- 重复值，因为该问题单独计算重复值。 
- 负数，可能会暴露不正确的二分搜索边界。 
- 情况`k = 1`，这意味着我们需要全局最小值。 
- 情况`k = n^2`，这意味着我们需要全局最大值。 

保证矩阵是方形的并且排序正确，因此我们不需要验证输入结构。 

## 方法

 ### 蛮力方法

 最简单的解决方案是将矩阵展平为单个数组，对数组进行排序，然后返回索引处的元素`k - 1`。 

该算法很简单：

 1. 遍历矩阵中的每个单元格。 
2. 将所有值存储在列表中。 
3. 对列表进行排序。 
4. 返回`k - 1`索引元素。 

这是有效的，因为排序会产生所有矩阵元素的精确全局排序。 

然而，这种方法忽略了矩阵已经部分排序的事实。 由于矩阵最多可以包含`90,000`元素，对所有元素进行排序成本`O(n^2 log(n^2))`，这是不必要的昂贵。 

它还使用`O(n^2)`额外的内存，违反了后续更好的内存使用要求。 

### 最优方法，对值范围进行二分搜索

 关键的见解是矩阵按行和列排序。 这使我们能够有效地确定有多少数字小于或等于所选值。 

我们不是二分搜索索引，而是二分搜索数值范围本身。 

最小可能的答案是：```
matrix[0][0]
```最大可能的答案是：```
matrix[n-1][n-1]
```假设我们选择一些值`mid`。 

如果我们可以有效地计算矩阵中有多少个元素`<= mid`，那么：

 - 如果少于`k`元素是`<= mid`，答案一定更大。 
- 否则，答案可能是`mid`或更小。 

这创建了适合二分搜索的经典单调条件。 

关键的优化是有效地计算元素`O(n)`时间而不是扫描全部`n^2`细胞。 

因为行和列是排序的，所以我们可以从左下角开始：

 - 如果当前值为`<= mid`，那么该列中其上方的所有内容也是`<= mid`。 
- 如果当前值为`> mid`，向上移动。 

这个计数过程在每次二分搜索迭代中以线性时间运行。

 ## 算法演练

 ### 最优算法，对值进行二分查找

 1. 使用矩阵中的最小值和最大值初始化二分搜索边界。 

最小的元素总是在`matrix[0][0]`因为行和列是按升序排序的。 

最大的元素总是在`matrix[n-1][n-1]`。 
2. 对数值范围执行二分查找。 

计算：```
mid = (left + right) // 2
```我们现在需要确定矩阵中有多少元素小于或等于`mid`。 
3. 计数元素`<= mid`使用左下遍历技术。 

开始于：```
row = n - 1
col = 0
```每一步：

 - 如果`matrix[row][col] <= mid`，那么同一列中它上面的每个元素也是`<= mid`。 

因此，添加：```
row + 1
```到计数，然后向右移动。 
- 否则，由于当前值太大，向上移动。 
4. 比较计数`k`。 

- 如果`count < k`，那么答案一定大于`mid`。 

移动：```
left = mid + 1
```- 否则，答案是`mid`或更小。 

移动：```
right = mid
```5. 继续直到`left == right`。 

此时，二分搜索已收敛到矩阵中的秩至少为的最小值`k`。 
6. 返回`left`。 

### 为什么它有效

 该算法依赖于单调性。 

对于任何值`x`， 定义：```
count(x) = number of elements <= x
```作为`x`增加，`count(x)`永远不会减少。 

这意味着我们可以二分查找最小值，这样：```
count(x) >= k
```该值正是`kth`最小元素。 

矩阵排序保证了可以在线性时间内有效地完成计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def kthSmallest(self, matrix: List[List[int]], k: int) -> int:
        n = len(matrix)

        def count_less_equal(target: int) -> int:
            row = n - 1
            col = 0
            count = 0

            while row >= 0 and col < n:
                if matrix[row][col] <= target:
                    count += row + 1
                    col += 1
                else:
                    row -= 1

            return count

        left = matrix[0][0]
        right = matrix[n - 1][n - 1]

        while left < right:
            mid = (left + right) // 2

            if count_less_equal(mid) < k:
                left = mid + 1
            else:
                right = mid

        return left
```实现首先定义一个名为的辅助函数`count_less_equal`。 该函数确定有多少矩阵元素小于或等于目标值。 

它不是扫描每个元素，而是从左下角开始。 该位置很有用，因为向上移动会减少值，而向右移动会增加值。 

当当前值小于或等于目标时，高于该值的整个列部分也有效，因为列已排序。 因此我们可以添加`row + 1`元素一次。 

主要算法在值范围而不是索引上执行二分搜索。`left`从全局最小值开始并且`right`从全局最大值开始。 

对于每个中点：

 - 如果少于`k`元素小于或等于`mid`，答案一定更大。 
- 否则，答案就在`mid`或以下。 

最终，搜索空间崩溃为单个值，即`kth`最小元素。 

## 解决方案```go
func kthSmallest(matrix [][]int, k int) int {
	n := len(matrix)

	countLessEqual := func(target int) int {
		row := n - 1
		col := 0
		count := 0

		for row >= 0 && col < n {
			if matrix[row][col] <= target {
				count += row + 1
				col++
			} else {
				row--
			}
		}

		return count
	}

	left := matrix[0][0]
	right := matrix[n-1][n-1]

	for left < right {
		mid := left + (right-left)/2

		if countLessEqual(mid) < k {
			left = mid + 1
		} else {
			right = mid
		}
	}

	return left
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个小差异是中点计算：```go
mid := left + (right-left)/2
```这避免了潜在的整数溢出，这是 Go 和其他静态类型语言中常见的防御做法。 

Go 切片直接用于矩阵访问，除了一些整数变量之外不需要额外的内存分配，保留了`O(1)`额外的空间复杂度。

 ## 边缘情况

 ### 单元素矩阵

 一个`1 x 1`矩阵是最小的有效输入。 粗心的实现可能会错误地假设存在多行或多列。 

例如：```
[[-5]]
```该实现自然地处理了这个问题，因为二分搜索边界都变成了`-5`，因此循环立即终止并返回唯一的值。 

### 重复值

 该问题明确指出重复项单独计数。 这很重要，因为一些不正确的解决方案会意外地将值视为唯一。 

例如：```
[
  [1,2],
  [2,3]
]
```排序后的顺序为：```
[1,2,2,3]
```第二和第三小的元素都是`2`。 

计数功能可以正确地独立计算每次出现的次数，因此可以自动处理重复项。 

### 负数

 负值可能会暴露二分搜索实现中的错误，尤其是在边界初始化不正确的情况下。 

例如：```
[
  [-10,-5],
  [-4,0]
]
```该算法安全地初始化：```
left = matrix[0][0]
right = matrix[n-1][n-1]
```由于这些是实际的矩阵值，因此无论数字是正数还是负数，搜索空间始终保持有效。 

### 所有元素都相等

 当每个值都相同时，如果边界更新不正确，许多二分搜索实现就会面临无限循环的风险。 

例子：```
[
  [7,7],
  [7,7]
]
```该实现避免了这个问题，因为：

 -`mid`总是等于`7`-`right = mid`最终缩小搜索范围
 - 循环条件使用`left < right`这保证了终止。
