 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个数据结构来模拟`n x n`两个玩家之间的井字游戏。 我们需要实现一个支持两种操作的类：

 - 初始化一个大小的游戏板`n`- 一次处理一个动作并立即确定当前动作是否导致玩家获胜

 一次移动由三个值表示：

 -`row`，玩家放置标记的行索引
 -`col`，玩家放置标记的列索引
 -`player`， 任何一个`1`或者`2`每次移动后，我们必须返回：

 -`0`如果还没有人获胜
 -`1`如果玩家 1 获胜
 -`2`如果玩家 2 获胜

 获胜条件是标准的 Tic-Tac-Toe 逻辑：

 - 完整的一排
 - 完整的专栏
 - 主对角线
 - 反对角线

 这个问题的重要部分是后续问题。 一个幼稚的实现会在每次移动后检查整个棋盘，这可能会很昂贵。 这个问题明确询问我们是否可以做得更好`O(n^2)`每一步。 

这些约束有助于指导预期的解决方案：

 -`2 <= n <= 100`- 至多`n^2`动作
 - 每一个动作都是有效的
 - 没有重复的动作
 - 有人获胜后不能再移动

 这些保证简化了实现，因为我们不需要验证动作或处理无效的游戏状态。 

一些边缘情况很重要：

 - 玩家可能在主对角线上获胜
 - 玩家可能会在反对角线上获胜
 - 一步棋可能同时属于两条对角线，例如奇数棋盘的中心单元
 - 小板如`2 x 2`可以快速取得胜利
 - 大棋盘需要高效的移动处理

 关键的挑战是设计`move()`这样每个调用都会以恒定的时间运行，而不是重复扫描棋盘。 

## 方法

 ### 蛮力方法

 最直接的实现是存储整个棋盘，并在每次移动后扫描：

 - 整排
 - 整个专栏
 - 主对角线（如果适用）
 - 反对角线（如果适用）

 这是有效的，因为只有当这些行之一中的所有单元格都属于该玩家时，该玩家才会获胜。 

例如，在放置标记后`(row, col)`:

 - 检查每个单元格是否`board[row]`属于同一玩家
 - 检查列中的每个单元格是否`col`属于同一玩家
 - 如果`row == col`，检查主对角线
 - 如果`row + col == n - 1`，检查反对角线

 这种做法是正确的，因为它直接验证每一步棋后的获胜条件。 

然而，它的效率很低。 每次移动可能需要扫描最多`O(n)`行、列和对角线的单元格。 如果不小心通过扫描整个板来实现，它甚至可能变成`O(n^2)`每一步。 

### 最佳方法

 关键的见解是我们不需要重复存储或检查整个电路板。 

玩家只有在完全填满时才获胜：

 - 一排
 - 一栏
 - 一条对角线

 我们可以维护运行计数，而不是存储板状态：

 -`rows[i]`跟踪行的累积分数`i`-`cols[j]`跟踪列的累积分数`j`-`diagonal`跟踪主对角线
 -`anti_diagonal`追踪反对角线

 我们使用这个技巧：

 - 玩家 1 贡献`+1`- 玩家 2 贡献`-1`如果任何计数器达到：

 -`+n`, 玩家 1 获胜
 -`-n`, 玩家 2 获胜

 这是有效的，因为只有一个玩家的标记可以完全占据一条线。 

例如，假设`n = 3`。 

如果第 2 行变为：```
X X X
```那么行计数器就变成：```
+1 +1 +1 = +3
```类似地，如果玩家 2 填满一列：```
O O O
```列计数器变为：```
-1 -1 -1 = -3
```这使得每个动作都能在恒定的时间内运行。

 | 方法| 时间复杂度| 空间复杂度| 笔记|

 ## 算法演练

 1.初始化四个跟踪结构：

 -`rows`，一个大小的数组`n`-`cols`，一个大小的数组`n`-`diagonal`, 一个整数
 -`anti_diagonal`, 一个整数

 这些结构保留了棋盘上每条线的累积分数。 
2. 将玩家转换为数值。 

- 玩家1变成`+1`- 玩家2变成`-1`使用相反的符号可以让两个玩家干净地共享相同的计数器。 
3. 更新行计数器。 

将玩家的价值添加到`rows[row]`。 
4. 更新列计数器。 

将玩家的价值添加到`cols[col]`。 
5. 检查移动是否位于主对角线上。 

当满足以下条件时，单元格属于主对角线：$row = col$如果为真，则更新对角线计数器。 
6. 检查移动是否位于反对角线上。 

当满足以下条件时，单元格属于反对角线：$row + col = n - 1$如果为 true，则更新反对角计数器。 
7. 检查获胜条件。 

如果任何更新的计数器的绝对值变为`n`，然后一名玩家完全填满了该线。$|counter| = n$8. 如果找到获胜者，则将其归还。 

- 返回`1`如果计数器为正
 - 返回`2`如果计数器为负
 9. 如果没有计数器到达`n`或者`-n`， 返回`0`。 

### 为什么它有效

 该算法保持一个不变量：

 - 每行、每列和对角线计数器都等于该行中移动的贡献之和。 

因为玩家 1 做出了贡献`+1`玩家 2 贡献了`-1`，一条线可以达到大小`n`仅当所有`n`单元格属于同一玩家。 因此，检查计数器是否等于`n`或者`-n`每次移动后立即正确确定获胜者。 

## Python 解决方案```python
class TicTacToe:

    def __init__(self, n: int):
        self.n = n
        self.rows = [0] * n
        self.cols = [0] * n
        self.diagonal = 0
        self.anti_diagonal = 0

    def move(self, row: int, col: int, player: int) -> int:
        value = 1 if player == 1 else -1

        self.rows[row] += value
        self.cols[col] += value

        if row == col:
            self.diagonal += value

        if row + col == self.n - 1:
            self.anti_diagonal += value

        if (
            abs(self.rows[row]) == self.n
            or abs(self.cols[col]) == self.n
            or abs(self.diagonal) == self.n
            or abs(self.anti_diagonal) == self.n
        ):
            return player

        return 0

# Your TicTacToe object will be instantiated and called as such:
# obj = TicTacToe(n)
# param_1 = obj.move(row, col, player)
```构造函数初始化簿记数组和对角计数器。 我们不存储完整的棋盘，因为问题只需要获胜者检测。 

里面`move()`，当前玩家被转换为`+1`或者`-1`。 这使得两个玩家可以优雅地共享相同的计数器。 

行计数器和列计数器立即更新。 如果移动位于任一对角线上，则相应的对角计数器也会更新。 

最后，该方法检查任何相关计数器是否具有大小`n`。 如果是，则当前玩家已完成获胜线，因此我们返回该玩家编号。 否则，游戏继续，我们返回`0`。 

## 解决方案```go
type TicTacToe struct {
	n            int
	rows         []int
	cols         []int
	diagonal     int
	antiDiagonal int
}

func Constructor(n int) TicTacToe {
	return TicTacToe{
		n:            n,
		rows:         make([]int, n),
		cols:         make([]int, n),
		diagonal:     0,
		antiDiagonal: 0,
	}
}

func (this *TicTacToe) Move(row int, col int, player int) int {
	value := 1
	if player == 2 {
		value = -1
	}

	this.rows[row] += value
	this.cols[col] += value

	if row == col {
		this.diagonal += value
	}

	if row+col == this.n-1 {
		this.antiDiagonal += value
	}

	if abs(this.rows[row]) == this.n ||
		abs(this.cols[col]) == this.n ||
		abs(this.diagonal) == this.n ||
		abs(this.antiDiagonal) == this.n {
		return player
	}

	return 0
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}

/**
 * Your TicTacToe object will be instantiated and called as such:
 * obj := Constructor(n)
 * param_1 := obj.Move(row, col, player)
 */
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有提供内置整数`abs()`函数，我们手动定义一个助手。 

切片用于`rows`和`cols`，其行为类似于 Python 中的动态数组。 该结构直接存储所有计数器。 

因为 Go 默认情况下按值传递结构，`Move()`方法使用指针接收器，因此更新在方法调用中持续存在。

 | 空间| O(n) | 两个大小的数组`n`被维护|

 该算法实现了恒定时间移动处理，因为每个操作只涉及直接索引更新和恒定时间检查。 不需要板扫描。 

空间复杂度是线性的，因为我们存储行和列计数器，每个计数器的大小`n`。 对角计数器仅需要恒定的额外空间。

 ## 边缘情况

 当一步棋同时位于两条对角线上时，就会出现一种重要的边缘情况。 这种情况仅发生在奇数尺寸板的中心单元上。 有缺陷的实现可能只更新一个对角计数器。 我们的实现显式地独立检查这两个条件，因此两个计数器都会正确更新。 

另一个边缘情况是非常小的板，尤其是`2 x 2`。 同一玩家只需走两步即可获胜。 一些实现意外地假设需要更多的移动。 由于我们的算法在每次移动后立即检查计数器，因此无论棋盘大小如何，都能正确检测胜利。 

第三个重要的边缘情况是同一行或同一列中不同玩家的交替贡献。 例如，如果玩家 1 和玩家 2 都在一行中放置标记，则计数器值会部分抵消。 这就是为什么`+1`和`-1`技术如此有效。 一行可以达到数量级`n`仅当每个单元都属于同一玩家时。 

另一个微妙的边缘情况是避免不必要的电路板存储。 一个幼稚的实现可能会分配整个`n x n`矩阵，即使获胜者检测不需要它。 我们的解决方案仅存储聚合计数器，从而减少内存使用`O(n²)`到`O(n)`。
