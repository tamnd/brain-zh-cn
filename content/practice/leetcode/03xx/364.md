[LeetCode 第 364 题](https://leetcode.com/problems/nested-list-weight-sum-ii/)

 **难度：** 🟡 中等
 **主题：** 堆栈、深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个嵌套列表结构，其中每个元素可以是：

 - 单个整数
 - 另一个包含附加整数或列表的嵌套列表

 目标是计算所有整数的加权和，但与标准“嵌套列表权重和”问题不同，权重是相反的。 

通常，更深的整数获得更大的权重。 在这个问题中，较浅的整数获得较大的权重。 

如果深度出现一个整数`d`，结构中任意位置的最大深度为`maxDepth`，则其权重为：$\text{weight} = \text{maxDepth} - d + 1$这意味着：

 - 最深层次的整数获得权重`1`- 高一级的整数获得权重`2`- 靠近根的整数接收最大的权重

 例如，考虑：```
[1,[4,[6]]]
```深度是：

 -`1`在深度`1`-`4`在深度`2`-`6`在深度`3`最大深度为`3`，因此权重变为：

 -`1 -> weight 3`-`4 -> weight 2`-`6 -> weight 1`最终的答案是：```
1*3 + 4*2 + 6*1 = 17
```输入尺寸相对较小：

 - 最多 50 个顶级元素
 - 最大嵌套深度最多为 50
 - 整数值范围为`-100`到`100`这些约束告诉我们，递归是完全安全的，因为递归深度永远不会超过 50。时间效率仍然很重要，但我们不需要极其高级的优化。 

一些边缘情况很重要：

 - 仅包含一个整数的结构
 - 非常深的嵌套列表
 - 负整数
 - 不同深度的多个列表
 - 所有整数出现在同一深度
 - 嵌套列表仅重复包含一个子项

 该问题还保证不存在空列表，这简化了遍历逻辑，因为每个列表至少包含一个元素。 

## 方法

 ### 蛮力方法

 最直接的解决方案是两遍深度优先遍历。 

在第一次遍历中，我们计算嵌套结构的最大深度。 每次我们递归到另一个列表时，我们都会增加深度计数器。 每当我们遇到一个整数时，我们都会根据需要更新全局最大深度。 

一旦我们知道了最大深度，我们就进行第二次遍历。 在此遍历过程中，我们再次跟踪当前深度。 对于每个整数，我们使用以下方法计算其权重：$\text{contribution} = \text{value} \times (\text{maxDepth} - d + 1)$然后我们将贡献添加到最终答案中。 

这种方法是正确的，因为每个整数的贡献取决于我们在第一遍中发现的全局最大深度。 

尽管这种方法对于约束来说足够有效，但它会遍历整个结构两次。 

### 最佳方法

 更优雅的解决方案使用广度优先遍历并避免显式计算权重。 

关键的见解是可以累积模拟逆加权。 

假设我们逐层处理嵌套列表：

 - 在每个级别，我们将在该级别找到的所有整数添加到`unweighted`运行总和。 
- 处理完一个关卡后，我们添加`unweighted`进入最终答案。 

为什么这有效？ 

浅深度的整数保留在`unweighted`对于更多级别，因此它们会被多次添加。 更深层次的整数出现得更晚，因此贡献的次数更少。 

这自然地再现了逆深度加权，而无需显式计算最大深度。 

例如：```
[1,[4,[6]]]
```等级处理：

 - 1 级：

 -`unweighted = 1`-`answer += 1`- 2 级：

 -`unweighted = 1 + 4 = 5`-`answer += 5`- 3 级：

 -`unweighted = 5 + 6 = 11`-`answer += 11`最终答案：```
1 + 5 + 11 = 17
```注意：

-`1`贡献了3次
 -`4`贡献过两次
 -`6`贡献过一次

 正是所需的逆权重。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N) | O(D) | 两次 DFS 遍历，第一次是最大深度，第二次是加权和 |
 | 最佳| O(N) | O(W) | 使用累积和进行 BFS 级别遍历 |

 这里：

-`N`是嵌套元素和整数的总数
 -`D`is maximum depth
 -`W`是 BFS 期间级别的最大宽度

 ## 算法演练

 ### 最优 BFS 算法

 1.初始化三个变量：

 -`unweighted = 0`-`weighted = 0`-`current_level = nestedList`这`unweighted`变量存储迄今为止看到的所有整数的累积和。 这`weighted`变量存储最终答案。 
2. 当当前层不为空时开始循环。 

每次迭代都会处理嵌套结构的一个深度级别。 
3. 创建一个名为的空列表`next_level`。 

这将存储属于下一个深度级别的所有嵌套列表。 
4.遍历中的每一个元素`current_level`。 

对于每个元素：

 - 如果是整数，则将其值添加到`unweighted`- 如果它是一个列表，则将其所有子项附加到`next_level`5.完成关卡后，添加`unweighted`进入`weighted`。 

这是至关重要的见解。 

迄今为止发现的每个整数对每个剩余级别贡献一次，自动创建逆深度加权。 
6. 更换`current_level`和`next_level`。 

这将 BFS 遍历推进到下一个深度。 
7. 继续，直到处理完所有级别。 
8. 返回`weighted`。 

### 为什么它有效

 不变的是`unweighted`始终包含截至当前深度发现的每个整数的总和。 

每个 BFS 级别都会添加`unweighted`进入答案一次。 因此：

 - 浅整数保留在`unweighted`对于许多迭代
 - 保留深整数以减少迭代次数

 深度整数`d`准确贡献：```
maxDepth - d + 1
```次，这与所需的逆权重定义相匹配。 

## Python 解决方案```python
# """
# This is the interface that allows for creating nested lists.
# You should not implement it, or speculate about its implementation
# """
#class NestedInteger:
#    def __init__(self, value=None):
#        pass
#
#    def isInteger(self):
#        pass
#
#    def add(self, elem):
#        pass
#
#    def setInteger(self, value):
#        pass
#
#    def getInteger(self):
#        pass
#
#    def getList(self):
#        pass

from typing import List

class Solution:
    def depthSumInverse(self, nestedList: List[NestedInteger]) -> int:
        unweighted_sum = 0
        weighted_sum = 0
        
        current_level = nestedList
        
        while current_level:
            next_level = []
            
            for nested in current_level:
                if nested.isInteger():
                    unweighted_sum += nested.getInteger()
                else:
                    next_level.extend(nested.getList())
            
            weighted_sum += unweighted_sum
            current_level = next_level
        
        return weighted_sum
```该实现紧密遵循前面描述的 BFS 算法。 

变量`current_level`存储当前深度的所有节点。 在遍历过程中，整数立即贡献给`unweighted_sum`，而子列表被收集到`next_level`。 

关键的观察出现在这一行中：```python
weighted_sum += unweighted_sum
```这会导致浅整数在多个级别上重复贡献。 

一旦不再有嵌套列表需要处理，算法就会自然终止。 

该实现是迭代的，完全避免递归，并且仅使用简单的列表操作。 

## 解决方案```go
/**
 * // This is the interface that allows for creating nested lists.
 * // You should not implement it, or speculate about its implementation
 * type NestedInteger struct {
 * }
 *
 * // Return true if this NestedInteger holds a single integer, rather than a nested list.
 * func (n NestedInteger) IsInteger() bool {}
 *
 * // Return the single integer that this NestedInteger holds, if it holds a single integer
 * func (n NestedInteger) GetInteger() int {}
 *
 * // Set this NestedInteger to hold a single integer.
 * func (n *NestedInteger) SetInteger(value int) {}
 *
 * // Set this NestedInteger to hold a nested list and adds a nested integer to it.
 * func (n *NestedInteger) Add(elem NestedInteger) {}
 *
 * // Return the nested list that this NestedInteger holds, if it holds a nested list
 * func (n NestedInteger) GetList() []*NestedInteger {}
 */

func depthSumInverse(nestedList []*NestedInteger) int {
    unweightedSum := 0
    weightedSum := 0

    currentLevel := nestedList

    for len(currentLevel) > 0 {
        nextLevel := []*NestedInteger{}

        for _, nested := range currentLevel {
            if nested.IsInteger() {
                unweightedSum += nested.GetInteger()
            } else {
                nextLevel = append(nextLevel, nested.GetList()...)
            }
        }

        weightedSum += unweightedSum
        currentLevel = nextLevel
    }

    return weightedSum
}
```Go 实现几乎完全反映了 Python 解决方案。 

切片用于表示 BFS 级别。 表达式：```go
append(nextLevel, nested.GetList()...)
```将嵌套列表中的所有子级附加到下一个 BFS 层。 

与 Python 不同，Go 需要显式的切片初始化和指针处理，因为`GetList()`回报`[]*NestedInteger`。 

整数溢出不是问题，因为约束非常小。

 ## 边缘情况

 ### 单个整数输入

 结构如下：```
[5]
```很重要，因为最大深度是`1`。 整数应该接收权重`1`，而不是某个更大的值。 

BFS 实现自然地处理这个问题，因为只存在一层，所以`unweighted_sum`被添加到`weighted_sum`正好一次。 

### 非常深的嵌套

 输入例如：```
[[[[[1]]]]]
```如果不仔细管理递归深度，可能会暴露 DFS 实现中的递归问题。 

迭代 BFS 解决方案完全避免了递归，即使对于深度嵌套的输入也具有鲁棒性。 

### 负整数

 负值可能会暴露错误，其中实现错误地假设所有贡献都是正的。 

例如：```
[1,[-2,[3]]]
```需要对正值和负值进行适当的加权累加。 

由于该算法仅执行算术累加，没有任何符号假设，因此可以自动正确处理负值。
