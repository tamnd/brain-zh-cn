 **难度：** 🟡 中等

 ## 解决方案

 ## 问题理解

 该问题要求我们在不使用算术运算符的情况下计算两个整数的和`+`和`-`。 我们必须使用位操作来模拟加法在二进制级别的工作原理，而不是依赖于普通算术。 

输入由两个整数组成，`a`和`b`。 这些整数可以是正数、负数或零。 预期输出是表示它们之和的单个整数。 

虽然限制相对较小，但从`-1000`到`1000`，问题的目的不是有效处理大量输入。 相反，目标是展示对二进制算术和按位运算的理解。 

关键的挑战来自对使用的限制`+`和`-`。 直接使用这些运算符的简单实现是无效的。 我们必须使用 XOR、AND 和左移等位运算手动重建加法过程。 

预先考虑几个边缘情况很重要。 添加零应该返回其他数字不变。 添加负数会带来复杂性，因为与许多其他语言不同，Python 整数不限于 32 位。 如果不仔细处理有符号整数，同时涉及正值和负值的情况也可能会产生无限循环。 最后，溢出行为必须与 32 位有符号整数运算一致地进行模拟。 

## 方法

 ### 蛮力方法

 解决问题的直接方法，无需直接使用`+`就是在调整另一个数字的同时重复增加或减少一个数字。 

例如，如果`b`是正数，我们可以反复增加`a`减一并减少`b`减一直到`b`变为零。 同样，如果`b`为负数，我们可以反复减少`a`并增加`b`。 

这种方法在概念上很简单，因为它模仿计数。 然而，它的效率很低，因为操作的数量直接取决于所涉及数字的大小。 尽管这个问题的约束很小，但该解决方案的扩展性不佳，并且错过了预期的位操作洞察力。 

### 最佳位操作方法

 重要的观察是二进制加法可以分为两个独立的运算。 

首先，异或（`^`) 计算位和而不考虑进位。 例如：

-`0 ^ 0 = 0`-`1 ^ 0 = 1`-`1 ^ 1 = 0`最后一种情况与普通加法匹配，只是忽略进位。 

其次，与（`&`) 标识发生进位的位置。 如果两个位都是`1`，进位必须传播到下一个位置。 将结果左移一位将进位置于正确的位置。 

这导致了一个重复的过程：

 1. 使用 XOR 计算部分和。 
2. 使用 AND 和左移计算进位。 
3. 重复，直到没有剩余进位。 

该方法有效地模拟了二进制加法，并且对于固定宽度的整数在恒定时间内运行。

 ## 算法演练

 1. 从两个整数开始，`a`和`b`。 
2. 使用异或 (`a ^ b`) 计算不带进位的总和。 XOR 的行为类似于二进制加法，其中`1 + 1`变成`0`而不是产生进位。 
3. 使用 AND (`a & b`) 来识别生成进位的所有位位置。 将结果左移一位，因为进位影响下一个高位位置。 
4. 更换`a`与部分总和并替换`b`与持有价值。 这有效地准备了下一次加法迭代。 
5. 当进位非零时继续重复该过程。 每次迭代都会解决一级进位。 
6. 由于 Python 整数是无界的，因此在计算期间应用 32 位掩码。 这可确保负数的行为类似于 C++ 或 Java 等语言中的标准有符号整数。 
7. 循环完成后，如有必要，将结果转换回正确的有符号整数表示形式。 

### 为什么它有效

 该算法之所以有效，是因为二进制加法总是可以分解为两部分：当前数字和和进位。 XOR 正确计算不带进位的数字和，而 AND 后跟左移正确计算进位贡献。 重复这个过程最终消除所有进位，此时剩下的值就是最终的和。 

## Python 解决方案```python
class Solution:
    def getSum(self, a: int, b: int) -> int:
        MASK = 0xFFFFFFFF
        MAX_INT = 0x7FFFFFFF

        while b != 0:
            partial_sum = (a ^ b) & MASK
            carry = ((a & b) << 1) & MASK

            a = partial_sum
            b = carry

        # Convert from unsigned to signed integer
        if a <= MAX_INT:
            return a

        return ~(a ^ MASK)
```该实现遵循算法演练中描述的确切位操作过程。 

这`MASK`常量确保所有中间值保持在 32 位以内。 这是必要的，因为 Python 整数可以增长任意大，这与许多编程语言中的固定宽度整数不同。 

在循环内部，`partial_sum`存储 XOR 结果，表示不带进位的加法。 这`carry`变量存储移入正确位置的所有进位位。 

循环继续，直到没有进位剩余。 那时，`a`包含完成的结果。 

最后，代码将无符号 32 位表示形式转换回有符号整数。 值大于`MAX_INT`以二进制补码形式表示负数，因此转换会恢复正确的带符号结果。 

## 解决方案```go
func getSum(a int, b int) int {
	const mask = 0xFFFFFFFF
	const maxInt = 0x7FFFFFFF

	for b != 0 {
		partialSum := (a ^ b) & mask
		carry := ((a & b) << 1) & mask

		a = partialSum
		b = carry
	}

	if a <= maxInt {
		return a
	}

	return ^(a ^ mask)
}
```Go 的实现与 Python 版本非常相似，因为 Go 也直接支持按位运算符。 

一个显着的区别是 Go 整数是固定宽度的，与 Python 整数不同。 然而，显式使用掩码仍然可以确保一致的 32 位行为并匹配预期的 LeetCode 解决方案模式。 

从无符号到有符号表示的转换的处理方式与 Python 中使用按位求反的方式相同。

 ## 边缘情况

 一个重要的边缘情况是将零添加到另一个数字。 有错误的实现可能会不必要地修改该值或无法正确终止。 在这个实现中，如果`b`最初为零，循环永远不会执行，并且函数立即返回`a`。 

另一个关键的边缘情况涉及负数。 Python 使用任意长度整数而不是固定宽度整数，因此负值的位运算的行为可能与 C++ 或 Java 等语言不同。 如果不将中间结果屏蔽为 32 位，进位值可能永远不会变为零，从而导致无限循环。 该实现通过一致应用 32 位掩码来避免这种情况。 

第三个重要的边缘情况是进位跨多个位传播时。 例如，添加`3`和`1`二进制产生重复的进位传播：```
011
001
---
100
```该算法可以正确处理这个问题，因为它会重复重新计算进位，直到没有进位位为止。 这个迭代过程保证在返回结果之前解决所有级联进位。
