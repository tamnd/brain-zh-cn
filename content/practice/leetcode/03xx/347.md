 **难度：** 🟡 中等
 **主题：** 数组、哈希表、分而治之、排序、堆（优先级队列）、桶排序、计数、快速选择

 ## 解决方案

 ## 问题理解

 问题要求我们返回`k`整数数组中最常出现的元素。 我们得到一个数组`nums`，其中可能包含重复项和一个整数`k`。 我们的任务是确定哪些值最常出现并准确返回`k`其中。 

例如，如果数组是`[1,1,1,2,2,3]`, 数量`1`出现三次，`2`出现两次，并且`3`出现一次。 自从`k = 2`，我们返回两个最频繁的元素，`[1,2]`。 

重要的细节是输出顺序并不重要。 我们只关心返回的值是正确的top`k`频繁元素。 

这些约束很重要，因为它们引导我们走向预期的解决方案。 数组长度可以大到`10^5`，这意味着低效的方法可能会超时。 后续明确要求一个比以下更好的解决方案`O(n log n)`，这排除了在最坏情况下按频率对所有元素进行完全排序的情况。 

该问题还保证了答案是唯一的。 这意味着哪些元素属于顶部永远不会有歧义`k`。 例如，我们不会遇到多个元素以创建多个有效答案的方式绑定最终位置的情况。 

一些边缘情况值得预先考虑。 该数组可能只包含一个元素，因此算法必须正确处理最小输入大小。 所有元素都可以相同，这意味着无论数组大小如何，都只有一个唯一值。 另一个重要的情况是当`k`等于唯一元素的数量，在这种情况下我们必须返回每个不同的数字。 也允许使用负整数，因此解决方案不能假设值为正。 

## 方法

 ### 蛮力方法

 一种简单的方法是首先使用哈希图计算每个数字的频率。 一旦我们知道了频率，我们就可以按频率降序对所有唯一元素进行排序，并返回第一个`k`元素。 

这是有效的，因为排序保证最频繁的元素首先出现。 排序后，选择最上面的`k`元素是微不足道的。 

然而，这种方法对于后续要求来说太慢了。 如果有`m`独特的元素，排序需要`O(m log m)`时间。 在最坏的情况下，每个元素都是唯一的，所以`m = n`，给出总复杂度`O(n log n)`。 

这个问题特别需要比这种复杂性更好的东西。 

### 最佳方法，桶排序

 关键的观察结果是频率受阵列长度限制。 任何元素不能出现超过`n`次。 

我们可以根据元素出现的频率将元素分组到桶中，而不是按频率对元素进行排序。 每个桶索引代表一个频率，桶存储具有该频率的所有数字。 

例如：

 - 桶`1`包含出现过一次的数字
 - 桶`2`包含出现两次的数字
 - 桶`3`包含出现三次的数字

 构建这些存储桶后，我们从最高可能频率迭代到最低频率并收集元素，直到我们有`k`结果。 

这完全避免了排序并实现了线性时间复杂度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 计算频率，然后按频率排序 |
 | 最佳| O(n) | O(n) | 使用基于频率计数的桶排序 |

 ## 算法演练

 1. 使用哈希表创建频率图。 

我们迭代数组并计算每个数字出现的次数。 哈希图是理想的，因为它提供了平均值`O(1)`插入和查找时间。 

例子：```
nums = [1,1,1,2,2,3]

frequency_map = {
    1: 3,
    2: 2,
    3: 1
}
```2. 创建按频率索引的桶。 

由于最大可能频率是`len(nums)`，我们创建一个大小为桶的数组`n + 1`。 

每个索引代表一个频率。 

例子：```
buckets[1] = [3]
buckets[2] = [2]
buckets[3] = [1]
```3. 填充存储桶。 

对于每一个`(number, frequency)`哈希图中的pair，将数字追加到与其频率对应的桶中。 

这将按出现次数对数字进行分组，而不进行排序。 
4. 以相反的顺序遍历桶。 

我们从最高频率迭代到`1`。 

遇到的第一个桶包含最常见的元素。 
5. 收集元素直到我们有`k`结果。 

当我们遍历存储桶时，我们将数字附加到结果列表中。 一旦结果大小达到`k`，我们立即退货。 

### 为什么它有效

 该算法之所以有效，是因为每个数字都被放入与其确切频率相对应的桶中。 通过从最高频率到最低频率遍历存储桶，我们会遇到按出现次数降序排列的元素。 因为我们收集后就停下来`k`元素，返回的列表必然包含`k`最常见的元素。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        # Step 1: Count frequencies
        frequency_map = {}

        for num in nums:
            frequency_map[num] = frequency_map.get(num, 0) + 1

        # Step 2: Create buckets
        buckets = [[] for _ in range(len(nums) + 1)]

        # Step 3: Place numbers into frequency buckets
        for num, frequency in frequency_map.items():
            buckets[frequency].append(num)

        # Step 4: Collect top k frequent elements
        result = []

        for frequency in range(len(buckets) - 1, 0, -1):
            for num in buckets[frequency]:
                result.append(num)

                if len(result) == k:
                    return result

        return result
```实现首先构建频率图。 数组中的每个数字都使用字典进行计数，其中键是数字，值是其出现次数。 

接下来，代码创建一个存储桶数组`len(nums) + 1`插槽。 额外的插槽是必要的，因为频率范围可以是`1`到`n`。 

然后，该算法迭代频率图，并将每个数字插入与其频率相对应的桶中。 这可以有效地按出现次数对元素进行分组。 

最后，代码以相反的顺序遍历存储桶。 由于较高的索引对应于较高的频率，这保证了首先处理最频繁的元素。 该算法一旦停止`k`元素已收集。 

## 解决方案```go
func topKFrequent(nums []int, k int) []int {
    // Step 1: Count frequencies
    frequencyMap := make(map[int]int)

    for _, num := range nums {
        frequencyMap[num]++
    }

    // Step 2: Create buckets
    buckets := make([][]int, len(nums)+1)

    // Step 3: Place numbers into buckets
    for num, frequency := range frequencyMap {
        buckets[frequency] = append(buckets[frequency], num)
    }

    // Step 4: Collect top k frequent elements
    result := []int{}

    for frequency := len(buckets) - 1; frequency >= 1; frequency-- {
        for _, num := range buckets[frequency] {
            result = append(result, num)

            if len(result) == k {
                return result
            }
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个`map[int]int`用于频率计数，整数切片代表桶。 

Go 特有的一个细节是，切片在使用时会动态调整大小`append`，这使得存储桶插入变得简单。 与 Python 列表不同，Go 切片必须显式初始化`make`。 

不存在整数溢出问题，因为频率计数受以下限制`10^5`，它很容易符合 Go 的整数范围。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 频率计数、桶插入、桶遍历都是线性的 |
 | 空间| O(n) | 哈希图和桶最多可以存储 n 个元素 |

 时间复杂度是线性的，因为每个元素都会被处理恒定的次数。 我们完全避免排序，这是满足后续需求的关键优化。 

空间复杂度也是线性的，因为频率图存储所有唯一元素，并且存储桶集中存储每个不同的数字一次。

 ## 边缘情况

 当数组仅包含单个元素时，会出现一种重要的边缘情况。 一种幼稚的实现可能会假设存在多个存储桶或多个唯一值，但这里只有一个有效答案。 该实现自然地处理了这一问题，因为频率图包含一个条目，并且存储桶遍历立即返回该值。 

另一个棘手的情况是每个元素都只出现一次。 在这种情况下，所有数字最终都在同一个桶中。 有些实现错误地依赖频率唯一性，但这个问题只能保证最终答案的唯一性，而不是每个频率的唯一性。 基于桶的解决方案仍然有效，因为所有元素都有频率`1`组合在一起并根据需要返回。 

负整数是错误的另一个常见来源。 一些计数方法错误地尝试直接使用值本身的数组索引，这会因负数而中断。 此实现使用哈希映射，因此正整数和负整数都可以得到统一且正确的处理。 

最后的边缘情况发生在以下情况：`k`等于唯一元素的总数。 在这种情况下，算法必须返回每个不同的值。 反向桶遍历自然会继续，直到收集到所有唯一元素，从而确保正确性而不需要特殊处理。
