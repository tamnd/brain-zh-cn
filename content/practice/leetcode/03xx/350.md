 **难度：** 🟢简单

 ## 解决方案

 ## 问题理解

 该问题要求我们找到两个整数数组的交集，但有一个重要的细节：重复问题。 如果一个数字在两个数组中出现多次，则它在结果中出现的次数必须与它在两个数组中出现的次数相同。 

例如，如果`2`出现两次`nums1`并三次`nums2`，那么结果应该包含`2`正好两次。 交集出现的次数由两个数组中的最小频率决定。 

输入由两个整数数组组成：

 -`nums1`-`nums2`输出是另一个包含所有公共元素（包括重复项）的数组。 输出的顺序并不重要。 

限制相对较小：

 - 每个数组长度介于`1`和`1000`- 每个值都介于`0`和`1000`这些限制告诉我们一些重要的事情：

 - 安`O(n * m)`由于阵列很小，暴力解决方案在技术上是可行的
 - 然而，该问题旨在测试哈希表、排序和两指针技术的知识
 - 由于值是有界的，频率计数就特别自然

 有几种边缘情况值得尽早考虑：

 - 没有公共元素的数组，结果应该为空
 - 每个元素都相同的数组
 - 具有大量重复的数组
 - 大小差异很大的数组
 - 数组已经排序，可以实现两指针优化
 - 一个数组比另一个数组小得多，这可能会影响哪种数据结构更可取

 该问题保证了有效的整数数组，并且不需要保留顺序，这简化了实现。 

## 方法

 ### 蛮力方法

 蛮力解决方案比较中的每个元素`nums1`针对其中的每一个元素`nums2`。 为了避免多次重复使用同一个元素，我们还需要一种机制来标记元素`nums2`因为已经匹配了。 

实现这一点的一种方法是：

 - 遍历每个元素`nums1`- 对于每个元素，扫描`nums2`- 如果找到匹配的未使用元素：

 - 将其添加到结果中
 - 将该位置标记为已使用
 - 停止搜索该元素

 这种方法是正确的，因为每个有效的匹配都被明确地找到并消耗一次。 

然而，它的效率很低，因为每个元素可能需要扫描整个第二个数组。 时间复杂度变为`O(n * m)`。 

### 使用哈希图的最佳方法

 关键的见解是这个问题从根本上来说与频率有关。 

我们可以计算每个数字在一个数组中出现的次数，而不是重复搜索匹配项。 然后，在迭代第二个数组时，我们检查该数字是否仍有剩余未使用的出现次数。 

哈希映射在这里完美地工作，因为：

 - 它提供平均`O(1)`查找
 - 它自然地存储频率
 - 它允许我们在使用匹配时减少计数

 算法变为：

 1. 统计其中所有数字的出现频率`nums1`2. 遍历`nums2`3. 如果当前数字存在于频率图中且 count 大于零：

 - 将其添加到结果中
 - 减少其数量

 这避免了重复扫描并将复杂度降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(米) | 比较每一对并跟踪使用的元素 |
 | 最佳| O(n + m) | O(min(n, m)) | 使用哈希图有效地计算频率 |

 ## 算法演练

 ### 最优哈希图算法

 1. 为其中一个阵列创建频率图。 

我们选择一个数组（通常是较小的数组以提高内存效率），并计算每个数字出现的次数。 键是数字本身，值是它的频率。 

例子：```
nums1 = [1,2,2,1]

frequency_map = {
    1: 2,
    2: 2
}
```2. 初始化一个空结果数组。 

当我们发现有效匹配时，该数组将存储交集元素。 
3. 遍历第二个数组。 

对于每个数字`nums2`，检查频率图中是否存在，以及其剩余计数是否大于零。 
4. 如果存在有效计数，则将该数字添加到结果中。 

这意味着该数字仍然具有来自第一个数组的不匹配的出现次数。 
5. 减少频率计数。 

使用一次后，减少其次数，以免错误地重复使用。 
6. 继续，直到处理完所有元素。 

最后，结果恰好包含具有正确重数的共享元素。 

### 为什么它有效

 该算法保持不变，即频率图始终表示第一个数组中每个数字剩余的未使用次数。 

每当我们在第二个数组中遇到一个数字时：

 - 如果计数为正，则存在有效的不匹配事件
 - 使用后，我们减少计数
 - 一旦计数达到零，就不能添加更多副本

 这保证了每个元素准确地出现在结果中`min(count_in_nums1, count_in_nums2)`次。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def intersect(self, nums1: List[int], nums2: List[int]) -> List[int]:
        # Always build the frequency map from the smaller array
        if len(nums1) > len(nums2):
            nums1, nums2 = nums2, nums1

        frequency = Counter(nums1)
        result = []

        for num in nums2:
            if frequency[num] > 0:
                result.append(num)
                frequency[num] -= 1

        return result
```实现首先确保较小的阵列用于频率图。 这是一个小的优化，当数组大小差异很大时，可以减少内存使用量。`Counter`来自Python的`collections`模块自动构建频率图。 每个键都是一个数字，每个值都是出现的次数。 

然后算法会迭代`nums2`。 对于每个数字：

 - 如果其频率仍然为正，则意味着存在未使用的匹配出现
 - 数字附加到结果中
 - 计数递减以将一次事件标记为已消耗

 处理完所有元素后，返回最终结果数组。 

## 解决方案```go
func intersect(nums1 []int, nums2 []int) []int {
    // Use the smaller array for the frequency map
    if len(nums1) > len(nums2) {
        nums1, nums2 = nums2, nums1
    }

    frequency := make(map[int]int)

    for _, num := range nums1 {
        frequency[num]++
    }

    result := []int{}

    for _, num := range nums2 {
        if frequency[num] > 0 {
            result = append(result, num)
            frequency[num]--
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别是 Go 没有提供内置的`Counter`类型，所以我们手动构造一个`map[int]int`来存储频率。 

Go 中的切片自然支持动态追加`append`，使它们适合增量构建结果。 

这里不存在整数溢出问题，因为约束非常小。 

当不存在交集时，会自动返回一个空切片，这符合 LeetCode 的预期。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 每个数组都被遍历一次 |
 | 空间| O(min(n, m)) | 频率图存储较小数组的计数 |

 时间复杂度是线性的，因为两个数组中的每个元素都被处理一次。 

空间复杂度取决于频率图中存储的不同元素的数量。 由于我们从较小的数组构建地图，因此辅助空间的边界为`O(min(n, m))`。

 ## 边缘情况

 ### 没有公共元素的数组

 错误的常见来源是由于频率图中不正确的默认行为而意外地包含不匹配的值。 

例子：```
nums1 = [1,2,3]
nums2 = [4,5,6]
```该实现正确地处理了这个问题，因为它仅在频率计数大于零时附加一个数字。 由于地图中不存在这些值，因此结果仍为空。 

### 大量重复计数

 重复是这个问题的核心挑战。 

例子：```
nums1 = [2,2,2,2]
nums2 = [2,2]
```一个简单的基于集合的解决方案将错误地仅返回`[2]`。 我们的实现跟踪每次比赛后的准确频率和递减计数，确保结果变为`[2,2]`。 

### 大小不同的数组

 当一个数组比另一个数组大得多时，内存使用就变得很重要。 

例子：```
nums1 = [1]
nums2 = [1,1,1,1,1,1]
```该实现通过始终从较小的阵列构建频率图来对此进行优化。 这可以最大限度地减少辅助空间，同时保持线性时间复杂度。 

### 已经排序的数组

 如果数组已经排序，则两指针解决方案可以完全避免额外的哈希映射内存。 

例子：```
nums1 = [1,2,2,3]
nums2 = [2,2,4]
```使用两个指针：

 - 比较当前元素
 - 推进较小的指针
 - 记录相等时的比赛

 这样就达到了`O(n + m)`时间与`O(1)`除了输出数组之外的额外空间。
