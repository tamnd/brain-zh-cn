[LeetCode 第 388 题](https://leetcode.com/problems/longest-absolute-file-path/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、深度优先搜索

 ## 解决方案

 ## 问题理解

 该问题为我们提供了文件系统层次结构的字符串表示形式。 每一行代表一个目录或一个文件。 层次结构使用换行符进行编码（`\n`) 来分隔条目和制表符 (`\t`) 来指示嵌套深度。 

深度处存在没有前导制表符的行`0`，这意味着它直接位于根目录下。 前一深度内存在带有一个前导制表符的行`0`目录中，有两个选项卡的行存在于更深一层，依此类推。 

文件通过点（`.`）在其名称中。 目录不包含点。 任务是计算通向文件的最长绝对路径的长度。 

例如，考虑以下结构：```
dir
    subdir2
        file.ext
```对应的绝对路径为：```
dir/subdir2/file.ext
```答案是该路径中的字符数，包括`/`分隔符。 

约束很重要，因为输入长度可达`10^4`，这意味着我们应该避免重复重建长字符串或执行昂贵的递归遍历。 预计会出现线性时间解决方案。 

有几种边缘情况如果处理不当很容易导致错误。 

文件系统可能根本不包含任何文件。 在这种情况下，正确答案是`0`。 

文件可以直接存在于根目录下，没有嵌套文件夹。 

同一深度可能存在多个目录，因此我们在向上移动层次结构时需要正确丢弃以前的分支。 

目录名和文件名可能包含空格和数字，这意味着我们不能依赖制表符和换行符之外的简单解析假设。 

输入保证代表有效的文件系统，并且每个文件或目录名都具有正长度。 

## 方法

 ### 蛮力方法

 一种简单的方法是显式重建每个文件的完整路径。 

我们可以逐行处理，根据前导选项卡的数量确定其深度，并在堆栈中维护当前的目录层次结构。 每当我们遇到一个文件时，我们都会使用以下命令将所有目录名和文件名连接在一起`/`分隔符并计算结果字符串长度。 

这种方法是正确的，因为堆栈始终表示从根到当前条目的当前路径。 每次我们看到一个文件时，从堆栈构建路径都会给出准确的绝对路径。 

然而，这种方法效率低下，因为重复连接字符串的成本可能会很高。 如果有很多深度嵌套的文件，我们可能会重复重建几乎相同的路径。 最坏情况下，每个文件路径的构建成本`O(n)`，导致总体复杂度为二次方。 

### 最佳方法

 关键的见解是我们实际上不需要构建完整路径字符串。 我们只需要它们的长度。 

我们可以存储每个深度级别的累积路径长度，而不是存储完整路径分量。 

对于每一行：

 - 确定其深度
 - 删除前导标签
 - 根据父目录长度计算当前路径长度
 - 如果条目是文件，则更新最大答案
 - 如果条目是目录，则为未来的子目录存储其累积长度

 这是有效的，因为每个绝对路径都很简单：```
parent_path + "/" + current_name
```因此，如果我们已经知道直到父目录的总长度，我们就可以在常数时间内计算出新的长度。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复重建完整路径字符串 |
 | 最佳| O(n) | O(n) | 按深度存储累积路径长度 |

 ## 算法演练

 1. 用换行符分割输入字符串。 

结果的每一行代表一个文件或一个目录。 
2.维护从深度到累积路径长度的映射。 

例如：```
depth_lengths[2] = 15
```表示到深度的绝对路径的总长度`2`是`15`。 
3. 初始化根深度长度。 

我们设定：```
depth_lengths[0] = 0
```这表示处理任何条目之前的空基本路径。 
4. 单独处理每一行。 

对于每一行：

 - 计算领先的数量`\t`人物
 - 这个计数代表深度
 - 删除选项卡以获取实际名称
 5. 计算当前路径长度。 

假设当前条目位于深度`d`。 

其父目录位于深度`d - 1`。 

总路径长度变为：```
parent_length + len(name)
```如果深度大于`0`，我们还添加`1`为`/`分隔符。 
6. 检查条目是否为文件。 

如果名称包含点 (`.`），它是一个文件。 

如果该路径比之前的最佳路径长，则更新最大路径长度。 
7. 否则，存储目录长度。 

如果条目是目录，则未来的子级将使用此路径长度作为其父级长度。 
8. 继续，直到处理完所有行。 
9. 返回找到的最大文件路径长度。 

### 为什么它有效

 该算法保持不变式`depth_lengths[d]`始终存储直到深度的总绝对路径长度`d`。 

处理子节点时，其全路径长度仅取决于其父路径长度和自身名称长度。 由于父路径长度已知，因此可以在恒定时间内计算出每个新路径长度。 

因为每一行都只处理一次，并且累积长度始终反映正确的文件系统层次结构，所以该算法可以正确计算最长的绝对文件路径。 

## Python 解决方案```python
class Solution:
    def lengthLongestPath(self, input: str) -> int:
        depth_lengths = {0: 0}
        max_length = 0

        for line in input.split("\n"):
            depth = line.count("\t")
            name = line.lstrip("\t")

            current_length = depth_lengths[depth] + len(name)

            if "." in name:
                max_length = max(max_length, current_length)
            else:
                depth_lengths[depth + 1] = current_length + 1

        return max_length
```实现首先创建一个名为的字典`depth_lengths`。 该字典将每个深度级别映射到到达该深度的累积路径长度。 

深度值`0`被初始化为`0`，它表示处理任何目录之前的空起点。 

使用换行符分割输入字符串，以便可以独立处理每个文件系统条目。 

对于每一行，前导制表符的数量决定了深度。 通过删除这些选项卡可以获得实际的文件或目录名称。 

变量`current_length`表示当前条目的总路径长度。 它是使用存储的父名称长度加上当前名称的长度来计算的。 

如果当前条目包含点，则将其视为文件。 算法更新`max_length`如果此文件路径是迄今为止遇到的最长的。 

否则，该条目是一个目录。 在这种情况下，算法会存储下一个深度级别的累积长度。 额外的`1`占`/`未来的孩子将需要的分隔符。 

最后，算法返回遍历过程中找到的最大文件路径长度。 

## 解决方案```go
package main

import (
	"strings"
)

func lengthLongestPath(input string) int {
	depthLengths := map[int]int{
		0: 0,
	}

	maxLength := 0

	lines := strings.Split(input, "\n")

	for _, line := range lines {
		depth := strings.Count(line, "\t")
		name := strings.TrimLeft(line, "\t")

		currentLength := depthLengths[depth] + len(name)

		if strings.Contains(name, ".") {
			if currentLength > maxLength {
				maxLength = currentLength
			}
		} else {
			depthLengths[depth+1] = currentLength + 1
		}
	}

	return maxLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 地图存储按深度索引的累积路径长度。 

主要的语言特定差异与字符串处理有关。 Go 使用以下函数`strings`软件包用于计数制表符、删除前导制表符和检测文件名。 

Go 字符串是不可变的，就像 Python 字符串一样，因此修剪和分割等操作会产生新值。 

不需要特殊的整数溢出处理，因为最大输入大小相对于 Go 的整数容量来说很小。

 ## 边缘情况

 ### 文件系统中没有文件

 文件系统可能只包含目录，根本不包含文件。 这很重要，因为天真的实现可能会错误地返回最长的目录路径而不是`0`。 

例如：```
dir
    subdir
```由于没有条目包含点，因此正确答案是`0`。 

该实现正确处理了这个问题，因为`max_length`仅当遇到文件时才更新。 

### 根级别的文件

 文件可能会直接出现在深度处`0`没有任何父目录。 

例如：```
file.txt
```如果算法假设每个文件都有一个父目录，这种情况很容易处理不当。 

该实现避免了这个问题，因为`depth_lengths[0]`被初始化为`0`，允许自然计算根级文件长度。 

### 向上移动目录层次结构

 从更深的嵌套级别返回后处理同级目录时会出现一个常见错误。 

例如：```
dir
    a
        file1.txt
    b
        file2.txt
```加工时`b`，算法必须忽略之前嵌套的路径`a`。 

该实现可以正确处理这个问题，因为路径长度是按深度索引的。 当新目录出现在相同深度时，它会覆盖该深度的前一个条目，确保未来的子目录使用正确的父路径。
