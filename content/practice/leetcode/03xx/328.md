 # LeetCode 328 - 奇偶链表

 ## 问题理解

 这个问题要求我们对单链表重新排序，使得位于奇数索引的所有节点首先出现，然后是位于偶数索引的所有节点。 

重要的细节是分组是基于节点在列表中的位置，而不是节点的值。 第一个节点被认为是奇数，第二个节点是偶数，第三个节点又是奇数，依此类推。 

例如，给定列表：```
1 -> 2 -> 3 -> 4 -> 5
```奇数位置的节点是：```
1, 3, 5
```偶数位置的节点是：```
2, 4
```最终重新排序的列表变为：```
1 -> 3 -> 5 -> 2 -> 4
```该问题还要求每个组内的相对顺序保持不变。 这意味着奇数索引节点必须按照它们最初出现的顺序出现，这同样适用于偶数索引节点。 

输入是单链表的头指针。 输出应该是重新排序后修改列表的头部。 

约束表明链表最多可以包含`10^4`节点。 这立即表明`O(n)`解决方案是适当且符合预期的。 该问题还明确要求`O(1)`额外的空间，这意味着我们无法创建与输入大小成比例的额外数组或链表。 

一些边缘情况很重要：

 - 一个空列表应该简单地返回`None`。 
- 具有一个节点的列表已经正确排序。 
- 具有两个节点的列表也已正确排序。 
- 奇数和偶数长度的列表必须都能正常工作。 
- 指针操作错误很容易造成循环或断开列表的某些部分。 

因为这是一个链表问题，小心处理`next`指针是关键的挑战。 

## 方法

 ### 蛮力方法

 一种直接的解决方案是遍历链表，并将奇数位置节点和偶数位置节点分别存储在辅助数据结构（例如数组或单独的链表）中。 

我们可以：

 1. 遍历列表，同时跟踪当前位置。 
2. 将奇数位置的节点追加到一个列表中。 
3. 将偶数位置的节点追加到另一个列表。 
4. 将奇数列表连接到末尾的偶数列表。 

这种方法之所以有效，是因为它根据节点的位置显式地分离节点，同时保留其原始顺序。 

然而，这种方法需要与节点数量成比例的额外内存。 由于问题明确要求`O(1)`额外的空间，该解决方案违反了空间限制。 

### 最佳方法

 关键的见解是我们不需要额外的存储，因为节点已经存在。 我们只需要重新排列指针即可。 

我们可以维护两条正在运行的链：

 - 奇数索引节点的一条链
 - 偶数索引节点的一条链

 当我们遍历列表时，我们重新连接指针，以便：

 - 每个奇数节点都指向下一个奇数节点
 - 每个偶数节点都指向下一个偶数节点

 最后，我们将偶数链附加在奇数链之后。 

重要的观察是，我们可以在仅遍历列表一次的情况下就地执行此重新链接。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用辅助存储分离奇数和偶数节点 |
 | 最佳 | O(n) | O(1) | O(1) | 就地重新排列指针，无需额外存储 |

 ## 算法演练

 1. 首先处理琐碎的边缘情况。 

如果列表为空或仅包含一个节点，则无需重新排序。 立即返回头部。 
2. 初始化奇数链和偶数链的指针。 

第一个节点是奇数，因此初始化：

 -`odd = head`第二个节点是偶数，因此初始化：

 -`even = head.next`我们还存储：

 -`even_head = even`这个指针很重要，因为一旦我们完成处理，我们需要将奇数链重新连接到偶数链的开头。 
3. 在奇数和偶数节点都存在的情况下遍历链表。 

循环条件为：```
while even and even.next:
```这确保了始终有另一个奇数节点可用。 
4. 将当前奇数节点连接到下一个奇数节点。 

自从`even.next`表示下一个奇数位置节点：```
odd.next = even.next
```然后将奇数指针向前移动：```
odd = odd.next
```5. 将当前偶数节点连接到下一个偶数节点。 

移动奇数指针后，下一个偶数节点变为：```
odd.next
```所以：```
even.next = odd.next
```然后向前移动偶数指针：```
even = even.next
```6. 将偶数链连接到奇数链之后。 

遍历完成后，所有奇数节点连接在一起，所有偶数节点连接在一起。 

我们简单地连接：```
odd.next = even_head
```7. 返回修改后的列表头。 

### 为什么它有效

 该算法在整个执行过程中维护两条独立的链接链：

 - 奇数链始终包含按正确顺序处理的所有奇数位置节点。 
- 偶数链始终包含按正确顺序处理的所有偶数位置节点。 

每次迭代都会从剩余的未处理部分中删除一个奇数节点和一个偶数节点，并将它们附加到各自的链中。 由于节点是按原始顺序处理的，因此保留了相对顺序。 最后，将偶数链附加在奇数链之后即可产生所需的排列。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def oddEvenList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return head

        odd = head
        even = head.next
        even_head = even

        while even and even.next:
            odd.next = even.next
            odd = odd.next

            even.next = odd.next
            even = even.next

        odd.next = even_head

        return head
```该实现首先处理空列表和单节点列表。 这些情况不需要任何重新排序。 

这`odd`指针从第一个节点开始，而`even`指针从第二个节点开始。 这`even_head`变量存储偶数链的开头，以便稍后可以将其附加到奇数链之后。 

在循环内部，算法首先跳过偶数节点，将当前奇数节点连接到下一个奇数节点。 然后它推进奇数指针。 

接下来，它通过将当前偶节点连接到下一个偶节点并推进偶指针，对偶链执行相同的操作。 

循环继续，直到不再有偶数节点或没有下一个奇数节点可用。 

最后，奇数链的尾部连接到偶数链的头部，完成重新排序的列表。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func oddEvenList(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head
    }

    odd := head
    even := head.Next
    evenHead := even

    for even != nil && even.Next != nil {
        odd.Next = even.Next
        odd = odd.Next

        even.Next = odd.Next
        even = even.Next
    }

    odd.Next = evenHead

    return head
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 主要区别是 Go 显式使用`nil`而不是Python的`None`。 

指针操作在两种语言中的行为相似，因为链接列表自然依赖于引用。 不需要额外的内存分配，满足`O(1)`空间要求。

 ## 边缘情况

 ### 空列表

 空列表表示为`head = None`。 如果实现立即尝试读取，这种情况很容易导致空指针访问错误`head.next`。 

该解决方案通过初始保护子句避免了这个问题：```
if not head or not head.next:
    return head
```这确保了在任何指针操作开始之前的安全处理。 

### 单节点列表

 仅包含一个节点的列表已正确排序，因为该单个节点位于奇数位置。 

有缺陷的实现可能会错误地尝试访问或修改甚至不存在的节点。 相同的初始保护子句可以安全地处理这种情况并立即返回原始列表。 

### 偶数长度列表

 具有偶数个节点的列表可能会暴露指针更新错误。 例如：```
1 -> 2 -> 3 -> 4 -> 5 -> 6
```如果循环条件不正确，实现可能会尝试访问`even.next`什么时候`even`已经是`None`。 

条件：```
while even and even.next:
```确保每个指针访问保持有效并防止运行时错误。 

### 保持相对顺序

 该问题需要保留奇数组和偶数组内的原始相对顺序。 

在临时列表前面插入节点的简单实现会意外颠倒顺序。 

该解决方案始终通过按遍历顺序重新链接指针来顺序附加节点，从而保证两个组内的稳定排序。
