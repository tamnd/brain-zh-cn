[LeetCode 问题 307](https://leetcode.com/problems/range-sum-query-mutable/)

 **难度：** 🟡 中等
 **主题：** 数组、分而治之、设计、二叉索引树、线段树

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个可变范围和数据结构。 我们得到一个整数数组`nums`，我们必须有效地支持两种操作：

 1. 更新特定索引处的值。 
2.查询范围内元素的总和`[left, right]`。 

重要的细节是更新在初始化后动态发生。 这意味着数组会随着时间的推移而变化，并且每个未来的范围总和查询都必须反映最新的更新。 

一个简单的实现可以简单地存储数组并在任何时候重新计算总和`sumRange()`被称为。 虽然这在功能上有效，但当有很多操作时，它会变得低效。 约束允许最多`3 * 10^4`打电话给`update`和`sumRange`，因此重复扫描阵列的某些部分可能会变得过于昂贵。 

输入包括：

 - 初始整数数组`nums`- 多次致电：

 -`update(index, val)`-`sumRange(left, right)`预期输出为`sumRange(left, right)`是包含总和：$$nums[left] + nums[left+1] + \dots + nums[right]$$这些约束揭示了几个重要特征：

 - 数组大小可以大到`30,000`- 最多还可以有`30,000`运营
 - 值可能为负
 - 更新可能发生在任何位置

 这些限制强烈表明`O(n)`查询解决方案并不理想。 在最坏的情况下，`30,000`查询每次采取`30,000`操作将导致大约`9 * 10^8`操作，速度太慢。 

一些边缘情况很重要：

 - 长度数组`1`- 重复更新相同的索引
 - 查询单个元素范围，其中`left == right`- 负值导致总和减少
 - 全数组范围查询，例如`[0, n-1]`该问题保证所有索引都是有效的，因此我们不需要处理越界访问。 

## 方法

 ### 蛮力方法

 最简单的解决方案是直接存储数组。 

为了`update(index, val)`，我们简单地赋值：```
nums[index] = val
```为了`sumRange(left, right)`，我们迭代自`left`到`right`并手动计算总和。 

这种方法非常简单并且始终正确，因为每个查询都直接从数组中读取当前值。 然而，每个范围总和查询需要`O(n)`最坏情况下的时间。 

由于最多可能有`30,000`查询，此解决方案可能会变得太慢。 

### 最佳解决方案的关键见解

 核心问题是我们两者都需要：

 - 快速更新
 - 快速范围求和查询

 仅前缀总和是不够的，因为更新需要重建前缀数组`O(n)`时间。 

重要的观察是，我们需要一种能够在支持修改的同时有效维护部分和的数据结构。 

二叉索引树，也称为 Fenwick 树，正好解决了这个问题。 

芬威克树以压缩结构存储累积频率信息。 它不会在每次更新后重新计算整个前缀，而是仅更新对数数量的树节点。 

这给出：

 -`O(log n)`更新
 -`O(log n)`范围求和查询

 该结构的工作原理是存储由二进制索引操作确定的精心选择的范围的总和。

 ## 算法演练

 ### 二元索引树结构

 Fenwick 树使用 1 索引内部数组维护前缀和。 

每个树位置存储特定范围值的总和。 该范围的大小取决于索引的最低有效设置位。 

### 逐步算法

 1. 初始化两个数组。 

我们存储：

 - 原始值`nums`- 芬威克树在`tree`树形数组的大小`n + 1`因为索引`0`未使用。 
2. 构建芬威克树。 

对于输入数组中的每个数字：

 - 将其值插入 Fenwick 树
 - 通过相关树节点向上传播贡献

 这为将来高效的查询准备了结构。 
3. 高效处理更新。 

更新索引时：

 - 计算差异：$$delta = newValue - oldValue$$- 更新原始数组
 - 添加`delta`到负责该索引的每个 Fenwick Tree 节点

 我们只接触`O(log n)`节点，因为每次跳转都会删除一个二进制贡献。 
4. 计算前缀和。 

计算到索引的前缀总和`i`：

 - 通过芬威克树父母向上移动
 - 累积存储的部分金额

 每个步骤都会删除最低有效设置位。 
5. 计算范围总和。 

任何范围之和都可以写成：$$prefix(right) - prefix(left - 1)$$这会将任意范围查询转换为两个前缀查询。 

### 为什么它有效

 芬威克树保持了每个节点存储特定连续范围元素之和的不变性。 

二进制索引操作确保每个数组元素都有助于正确的树节点集合。 由于更新通过所有受影响的节点传播，并且查询精确地组合了必要的部分和，因此返回的范围和始终是正确的。 

## Python 解决方案```python
from typing import List

class NumArray:

    def __init__(self, nums: List[int]):
        self.n = len(nums)
        self.nums = nums[:]
        self.tree = [0] * (self.n + 1)

        for i, value in enumerate(nums):
            self._add(i + 1, value)

    def _add(self, index: int, delta: int) -> None:
        while index <= self.n:
            self.tree[index] += delta
            index += index & -index

    def _prefix_sum(self, index: int) -> int:
        total = 0

        while index > 0:
            total += self.tree[index]
            index -= index & -index

        return total

    def update(self, index: int, val: int) -> None:
        delta = val - self.nums[index]
        self.nums[index] = val

        self._add(index + 1, delta)

    def sumRange(self, left: int, right: int) -> int:
        return self._prefix_sum(right + 1) - self._prefix_sum(left)
```该实现首先存储原始数组的副本。 这是必要的，因为更新需要知道旧值才能计算差异。 

这`tree`数组是芬威克树结构。 它使用从 1 开始的索引，因为二进制运算变得更加干净和一致。 

这`_add()`辅助函数通过所有受影响的树节点向上传播值更改。 表达式：```python
index += index & -index
```移动到下一个负责节点。 

这`_prefix_sum()`helper 计算索引的累积和`1`通过`index`。 表达式：```python
index -= index & -index
```在收集贡献的同时向上向根移动。 

这`update()`方法计算旧值和新值之间的增量，更新存储的数组，并通过树传播更改。 

这`sumRange()`方法将范围查询转换为两个前缀和。 

## 解决方案```go
type NumArray struct {
	nums []int
	tree []int
	n    int
}

func Constructor(nums []int) NumArray {
	n := len(nums)

	obj := NumArray{
		nums: make([]int, n),
		tree: make([]int, n+1),
		n:    n,
	}

	copy(obj.nums, nums)

	for i, value := range nums {
		obj.add(i+1, value)
	}

	return obj
}

func (this *NumArray) add(index int, delta int) {
	for index <= this.n {
		this.tree[index] += delta
		index += index & -index
	}
}

func (this *NumArray) prefixSum(index int) int {
	total := 0

	for index > 0 {
		total += this.tree[index]
		index -= index & -index
	}

	return total
}

func (this *NumArray) Update(index int, val int) {
	delta := val - this.nums[index]
	this.nums[index] = val

	this.add(index+1, delta)
}

func (this *NumArray) SumRange(left int, right int) int {
	return this.prefixSum(right+1) - this.prefixSum(left)
}

/**
 * Your NumArray object will be instantiated and called as such:
 * obj := Constructor(nums);
 * obj.Update(index,val);
 * param_2 := obj.SumRange(left,right);
 */
```Go 实现遵循与 Python 版本相同的逻辑。 

一个重要的区别是显式内存分配。 Go 需要初始化切片`make()`使用前。 

这`copy()`函数复制输入数组，因此更新不会意外修改原始切片引用。 

Go 整数足以解决这个问题，因为约束将总和保持在 32 位范围内。

 ## 边缘情况

 ### 单元素数组

 当数组只包含一个元素时，每个查询都变成单值范围查询。 某些实现错误地假设范围包含多个元素或错误处理索引零处的前缀减法。 

此实现可以自然地处理这种情况，因为：```
_prefix_sum(right + 1) - _prefix_sum(left)
```当两个索引引用同一元素时仍然可以正常工作。 

### 将索引更新为相同值

 如果新值等于旧值，则计算出的增量为零。 

有缺陷的实现可能会不必要地重建结构或意外地重复计数值。 在这里，传播零增量不会改变任何内容，因此会自动保留正确性。 

### 负数

 负值很重要，因为总和不是单调的。 

一些不正确的实现假设累积总和总是增加。 芬威克树不依赖于积极性。 它只存储算术和，因此负贡献与正贡献完全相同。 

### 全数组查询

 查询例如：```
sumRange(0, n - 1)
```是常见的边界情况。 

不正确的前缀逻辑通常会导致左边界出现相差一的错误。 此实现通过一致使用来避免该问题：```
prefix(right + 1) - prefix(left)
```具有 1 索引的 Fenwick 树表示形式。
