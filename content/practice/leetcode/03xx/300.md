[LeetCode 300 题](https://leetcode.com/problems/longest-increasing-subsequence/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们找到整数数组中最长严格递增子序列的长度。 

子序列是通过从数组中删除零个或多个元素而不改变剩余元素的顺序而形成的。 这与子数组不同，子数组必须保持连续。 由于这种区别，只要相对顺序保持不变，我们就可以跳过元素。 

子序列也必须是严格递增的。 这意味着下一个元素必须大于前一个元素。 序列中不允许有相同的值。 

例如，在数组中`[10,9,2,5,3,7,101,18]`，一个有效的递增子序列是`[2,3,7,101]`。 它的长度是`4`，这是可能的最大值，所以答案是`4`。 

输入包括：

 - 整数数组`nums`- 数组长度之间`1`和`2500`- 值的范围可以是`-10^4`到`10^4`输出是一个整数，表示任何严格递增子序列的最大长度。 

这些约束很重要，因为它们指导算法的选择。 自从`n`可以大到`2500`，指数暴力解决方案会太慢。 甚至一个`O(n^2)`对于这个约束大小，动态规划解决方案是可以接受的，但后续特别要求`O(n log n)`解决方案。 

一些边缘情况很重要：

 - 具有所有相同值的数组，例如`[7,7,7,7]`，应该返回`1`- 已经严格递增的数组应返回完整长度
 - 严格递减的数组也应该返回`1`- 必须正确处理负数
 - 非常短的数组，尤其是长度`1`，应该可以正常工作，没有特殊的处理错误

 理解子序列和连续子数组之间的区别是这个问题的关键概念挑战。 

## 方法

 ### 蛮力方法

 暴力解决方案探索数组的每个可能的子序列，并检查每个子序列是否严格递增。 

对于长度的数组`n`，每个元素都可以被包含或排除，从而导致`2^n`可能的子序列。 对于每个子序列，我们需要验证它是否在增加并跟踪最大有效长度。 

这种方法是正确的，因为它检查所有可能的子序列，保证最终找到最佳的子序列。 

然而，时间复杂度是指数级的，很快就变得不可行。 即使是为了`n = 50`，子序列的数量变得巨大。 既然问题允许`n = 2500`，蛮力是完全不切实际的。 

### 最佳解决方案的关键见解

 重要的观察是我们不需要显式存储每个子序列。 

相反，我们可以维护一个结构，跟踪最小可能的尾部值，以增加不同长度的子序列。 

假设我们知道：

 - 长度递增子序列的最小尾部`1`- 长度递增子序列的最小尾部`2`- 长度递增子序列的最小尾部`3`- 等等

 尾部越小越好，因为它为未来元素扩展子序列留下了更多空间。 

这导致了经典的贪婪加二分搜索解决方案。 

我们维护一个名为`tails`在哪里：

-`tails[i]`存储长度递增子序列的最小可能结束值`i + 1`当我们处理每个数字时：

 - 如果数字大于所有当前尾部，我们扩展子序列
 - 否则，我们替换第一个大于或等于数字的尾部

 二分查找可以让我们高效地找到替换位置`O(log n)`时间。 

长度为`tails`最后等于最长递增子序列的长度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n)`|`O(n)`| 生成所有可能的子序列 |
 | 最佳 |`O(n log n)`|`O(n)`| 使用二分搜索的贪心策略 |

 ## 算法演练

 1. 初始化一个空数组，名为`tails`。 

目的`tails`是为了增加不同长度的子序列而保持尽可能小的尾部值。 

例如：

-`tails[0]`表示长度子序列的最小尾部`1`-`tails[1]`表示长度子序列的最小尾部`2`较小的尾值是首选，因为它们为以后的扩展提供了更多机会。 
2. 迭代中的每个数字`nums`。 

我们从左到右处理数组，因为子序列必须保留原始顺序。 
3. 使用二分查找查找插入位置。 

对于当前号码：

 - 找到最左边的位置`tails`其中该值大于或等于当前数字
 - 这个位置告诉我们哪些子序列长度可以改进

 二分查找是合适的，因为`tails`始终按排序顺序维护。 
4. 更新`tails`。 

有两种情况：

 - 如果当前数字大于所有现有尾部，则将其附加到`tails`- 否则，替换二分查找位置处现有的尾部

 替换不会减少 LIS 长度。 相反，它通过创造更小的尾巴来提高未来的潜力。 
5. 继续，直到处理完所有元素。 

最终尺寸为`tails`表示最长递增子序列的长度。 

### 为什么它有效

 关键的不变量是`tails[i]`始终存储长度递增的子序列的最小可能结束值`i + 1`。 

如果我们可以使子序列以较小的数字结尾，则该子序列以后会更容易扩展。 因此，用较小的尾巴替换较大的尾巴总是安全且有益的。 

虽然`tails`它本身可能并不代表数组中的实际子序列，它的长度始终与迄今为止发现的最长递增子序列的长度匹配。 

## Python 解决方案```python
from typing import List
import bisect

class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        tails = []

        for num in nums:
            position = bisect.bisect_left(tails, num)

            if position == len(tails):
                tails.append(num)
            else:
                tails[position] = num

        return len(tails)
```实施首先创建`tails`数组，它存储各种长度的递增子序列的最小可能尾部值。 

对于输入数组中的每个数字，我们使用`bisect_left`执行二分查找。 这会找到可以插入当前数字的第一个索引，同时保留排序顺序。 

如果插入位置等于当前长度`tails`，该数字扩展了迄今为止找到的最长子序列，因此我们将其附加。 

否则，我们将替换该位置的现有值。 此替换通过创建较小的尾部值而不更改子序列长度来改进子序列。 

最后，长度为`tails`返回，因为它等于最长递增子序列的长度。 

## 解决方案```go
func lengthOfLIS(nums []int) int {
    tails := []int{}

    for _, num := range nums {
        left := 0
        right := len(tails)

        for left < right {
            mid := left + (right-left)/2

            if tails[mid] < num {
                left = mid + 1
            } else {
                right = mid
            }
        }

        if left == len(tails) {
            tails = append(tails, num)
        } else {
            tails[left] = num
        }
    }

    return len(tails)
}
```Go 实现遵循与 Python 版本相同的算法逻辑。 由于 Go 没有提供 Python 的直接等价物`bisect_left`对于切片，我们手动实现二分搜索。 

这`tails`随着发现更长的子序列，切片会动态增长。 替换操作直接修改现有索引。 

不存在整数溢出问题，因为这些值完全在 Go 的整数范围内。 空数组和单元素数组自然可以处理，无需特殊情况逻辑。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log n)`| 每个元素执行二分搜索`tails`|
 | 空间|`O(n)`| 这`tails`数组可以增长到一定大小`n`|

 该算法只对每个数字处理一次。 对于每个元素，我们对`tails`数组，它需要`O(log n)`时间。 

由于有`n`元素总数，完整的运行时间变为`O(n log n)`。 

这`tails`在序列已经增加的情况下，数组可能会增长到完整数组大小，从而导致`O(n)`额外的空间使用。

 ## 边缘情况

 一个重要的边缘情况是所有元素都相同的数组，例如`[7,7,7,7]`。 一个常见的错误是意外地将非递减序列视为递增序列。 由于该问题需要严格升序，因此重复项无法扩展子序列。 该实现通过使用正确处理这个问题`bisect_left`，它替换现有值而不是附加重复项。 

另一个关键情况是严格递减的数组，例如`[5,4,3,2,1]`。 在这种情况下，每个新元素都会替换第一个位置`tails`，并且数组永远不会超出长度`1`。 这确保了算法正确返回`1`而不是错误地计算多个元素。 

第三个重要的情况是已经增加的数组，例如`[1,2,3,4,5]`。 在这里，每个元素都比前面的尾部大，因此每个数字都会被附加。 算法正确增长`tails`到完整的数组长度，产生最佳答案。 

负值也值得关注，因为比较必须独立于符号进行。 数组就像`[-4,-3,-2,-1]`行为与正增数组完全相同。 由于该算法仅依赖于排序比较，因此它自然可以处理负整数，而无需额外的逻辑。 

最后，非常小的输入（例如单元素数组）可能会在某些实现中暴露初始化错误。 该解决方案完全避免了特殊情况的代码，因为`tails`数组开始时为空，并在迭代过程中自然增长。
