[LeetCode 第 306 题](https://leetcode.com/problems/additive-number/)

 **难度：** 🟡 中等
 **主题：** 字符串、回溯

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的数字串是否可以划分为有效的加法序列。 

加法序列是一个数字序列，其中：

 - 至少有三个数字。 
- 前两个数字之后的每个数字都等于前两个数字的总和。 
- 任何数字都不允许包含前导零，除非数字本身恰好是`"0"`。 

输入是单个字符串`num`仅包含数字字符。 我们没有给定数字之间的分隔符，因此我们的任务是确定是否存在某种方法将字符串拆分为满足加性属性的有效数字。 

例如，字符串`"112358"`可以拆分为：

 -`1`-`1`-`2`-`3`-`5`-`8`每个数字都是前两个数字的总和：

 -`1 + 1 = 2`-`1 + 2 = 3`-`2 + 3 = 5`-`3 + 5 = 8`因此结果是`true`。 

限制相对较小：

 -`1 <= num.length <= 35`这很重要，因为它表明我们有能力尝试前两个数字的许多可能的分割。 但是，这些值本身可能会变得非常大，可能超出某些语言中的正常整数范围。 这就是为什么后续询问溢出处理的原因。 

一些边缘情况尤其重要：

 - 带有前导零的数字无效，除非该数字完全正确`"0"`。 
- 非常短的字符串无法形成加法序列，因为至少需要三个数字。 
- 可能存在多个可能的分区，因此我们不能贪婪地只选择一个分区。 
- 在 Go 或 Java 等语言中，大数值可能会溢出固定宽度整数类型。 

关键的挑战是正确尝试所有有效的起始对，同时有效验证序列的其余部分。 

## 方法

 ### 蛮力方法

 暴力破解的想法是尝试将字符串划分为多个数字的所有可能的方法，并检查结果序列是否满足加法条件。 

对于一个长度的字符串`n`，数字之间的每个位置可以包含分割或不包含分割。 这大约创建了`2^(n-1)`可能的分区。 对于每个分区，我们将解析数字并验证每个数字是否等于前两个数字的总和。 

这种方法是正确的，因为它详尽地检查了每个可能的序列。 如果存在有效的附加序列，蛮力最终会找到它。 

然而，它太慢了。 可能的分区数量随着字符串长度呈指数增长，即使对于中等输入大小也是不切实际的。 

### 最佳回溯/模拟方法

 关键的观察是，一旦选择了前两个数字，整个序列就完全确定了。 

假设我们选择：

 - 第一个数字=`a`- 第二个数字=`b`然后：

 - 第三个数字必须是`a + b`- 第四个数字必须是`b + (a + b)`- 等等

 这意味着我们只需要枚举前两个数字的所有可能选择。 之后，我们可以确定性地验证剩余的字符串是否与预期的总和匹配。 

由于前两个数字唯一地定义了序列，因此我们大大减少了搜索空间。 

我们还小心地处理前导零：

 -`"0"`有效
 -`"01"`无效

 这种方法使用受控回溯和字符串匹配，对于问题约束来说足够有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试字符串的每个可能的分区 |
 | 最佳| O(n^3) | O(n^3) | O(n) | 尝试所有第一个和第二个数字，然后确定性地验证 |

 ## 算法演练

 ### 最优算法

 1. 迭代第一个数字的所有可能的结尾。 

第一个数字从索引开始`0`。 我们尝试了所有可能的长度。 如果号码开头为`'0'`并且超过一位数字，我们立即停止，因为前导零无效。 
2. 对于每个第一个数字，迭代第二个数字的所有可能的结尾。 

第二个数字紧接第一个数字之后开始。 再说一次，如果它开始于`'0'`并且有多个数字，我们跳过它。 
3. 将第一和第二子字符串转换为整数。 

它们成为加法序列的起始对。 
4. 开始验证字符串的其余部分。 

计算：```
next_number = first + second
```将此总和转换为字符串，因为我们需要将其直接与中相应的子字符串进行比较`num`。 
5. 检查剩余的字符串是否以预期的和开头。 

如果不完全匹配，则该起始对无效。 
6. 如果预期总和匹配，则在字符串中向前推进。 

更新：```
first = second
second = next_number
```继续检查下一个期望值。 
7. 如果我们成功消费整个字符串，则返回`true`。 

这意味着每个部分都匹配附加属性。 
8. 如果所有起始对都失败，则返回`false`。 

### 为什么它有效

 正确性来自于这样的事实：加法序列完全由其前两个数字决定。 一旦这些被修复，后面的每个数字都只有一个有效值。 因此，尝试所有可能的第一个和第二个数字可以保证我们找到一个有效的序列（如果存在）。 

该算法还正确拒绝无效的前导零，并确保消耗整个字符串而没有剩余数字。 

## Python 解决方案```python
class Solution:
    def isAdditiveNumber(self, num: str) -> bool:
        n = len(num)

        def is_valid(first: int, second: int, start: int) -> bool:
            while start < n:
                next_num = first + second
                next_str = str(next_num)

                if not num.startswith(next_str, start):
                    return False

                start += len(next_str)
                first, second = second, next_num

            return True

        for i in range(1, n):
            if num[0] == '0' and i > 1:
                break

            first = int(num[:i])

            for j in range(i + 1, n):
                if num[i] == '0' and j - i > 1:
                    break

                second = int(num[i:j])

                if is_valid(first, second, j):
                    return True

        return False
```该实现首先存储字符串的长度，以便可以有效地重用它。 

辅助函数`is_valid`执行确定性验证阶段。 它接收前两个数字和字符串中的当前索引。 在循环内部，它重复计算下一个期望值，将其转换为字符串，并检查剩余的子字符串是否以该值开头。 

表达式：```python
num.startswith(next_str, start)
```特别有用，因为它避免了手动子串切片逻辑并直接检查期望的总和是否出现在当前位置。 

外部循环枚举第一个和第二个数字的每个有效选择。 前导零检查至关重要：```python
if num[0] == '0' and i > 1:
```防止无效的第一个数字，例如`"01"`。 

相似地：```python
if num[i] == '0' and j - i > 1:
```防止无效的第二个数字，例如`"02"`。 

一旦有效序列消耗了整个字符串，该函数就会返回`True`。 如果没有起始对有效，答案是`False`。 

## 解决方案```go
package main

import "strconv"

func isAdditiveNumber(num string) bool {
	n := len(num)

	isValid := func(first, second int64, start int) bool {
		for start < n {
			nextNum := first + second
			nextStr := strconv.FormatInt(nextNum, 10)

			if start+len(nextStr) > n {
				return false
			}

			if num[start:start+len(nextStr)] != nextStr {
				return false
			}

			start += len(nextStr)
			first, second = second, nextNum
		}

		return true
	}

	for i := 1; i < n; i++ {
		if num[0] == '0' && i > 1 {
			break
		}

		first, _ := strconv.ParseInt(num[:i], 10, 64)

		for j := i + 1; j < n; j++ {
			if num[i] == '0' && j-i > 1 {
				break
			}

			second, _ := strconv.ParseInt(num[i:j], 10, 64)

			if isValid(first, second, j) {
				return true
			}
		}
	}

	return false
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用`int64`和`strconv`整数转换包。 

一个重要的区别是溢出处理。 Python 整数自动扩展到任意精度，但 Go 的`int64`有一个固定的限制。 对于非常大的输入，可能会发生溢出。 生产级解决方案可以完全避免整数解析，而是执行基于字符串的加法。 

子字符串检查是使用切片手动实现的：```go
num[start:start+len(nextStr)]
```因为Go没有Python的`startswith`帮手。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^3) | O(n^3) | 两个嵌套循环选择第一个和第二个数字，验证可能会扫描剩余的字符串 |

因此该算法运行在`O(n^3)`总体时间。 

辅助空间主要是由于计算预期总和时的字符串转换造成的。

 ## 边缘情况

 ### 前导零

 前导零是此问题中最常见的错误来源。 例如：```
"1023"
```幼稚的实现可能会错误地接受：```
1, 02, 3
```然而，`"02"`无效，因为数字不能包含前导零，除非数字本身恰好是`"0"`。 

该实现通过在多位数开头时立即停止探索来处理此问题`'0'`。 

### 全零

 输入：```
"000"
```实际上是有效的，因为它可以解释为：```
0, 0, 0
```和：```
0 + 0 = 0
```某些实现错误地拒绝所有以零开头的数字。 正确的规则是允许使用个位数零。 

### 大整数值

 字符串长度可达35位，可能超过64位整数范围。 

Python 自然地处理这个问题，因为整数具有任意精度。 在 Go 或 Java 中，使用固定宽度整数可能会溢出。 

对于生产系统来说，更强大的方法是实现基于字符串的加法而不是整数转换。 这完全避免了溢出并正确支持任意大的值。
