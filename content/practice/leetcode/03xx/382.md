 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表的头，并要求我们返回一个随机节点值，使得列表中的每个节点都有完全相同的被选择概率。 

该类有两个操作：

 1.`Solution(head)`使用链表初始化对象。 
2.`getRandom()`返回随机统一选择的一个节点值。 

重要的要求是每个节点返回的可能性必须相同。 如果列表包含`n`节点，那么每个节点必须有概率`1 / n`。 

链表是单向链接的，这意味着我们只能从一个节点向前移动到下一个节点。 我们不能像使用数组那样直接对列表进行索引。 这个细节很重要，因为除非我们对列表进行预处理，否则随机访问会变得昂贵。 

约束条件告诉我们：

 - 该列表包含之间`1`和`10^4`节点。 
- 最多`10^4`打电话给`getRandom()`可能会发生。 
- 节点值可以是负值或正值。 

后续问题是问题中最重要的部分。 它询问如果发生以下情况会发生什么：

 - 链接列表非常大。 
- 长度未知。 
- 我们希望避免额外的空间。 

这些提示强烈表明预期的最佳解决方案是储层采样。 

一些边缘情况很重要：

 - 仅包含一个节点的链表。 该算法必须始终返回该值。 
- 非常大的链表可能不希望将所有元素存储在数组中。 
- 重复值。 选择必须基于节点，而不是不同的值。 
- 列表长度未知。 我们不能依赖预先计算节点数。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是在初始化期间遍历链表一次，并将所有节点值存储在数组中。 

然后，每次调用`getRandom()`只需从数组中选择一个随机索引并返回相应的值。 

这是可行的，因为数组支持恒定时间索引，并且选择统一随机索引可以保证每个节点具有相同的概率。 

例如：

 - 链接列表：`1 -> 2 -> 3`- 存储为数组：`[1, 2, 3]`- 生成之间的随机索引`0`和`2`每个值都以概率返回`1/3`。 

这种方法易于实现，并且对于重复查询非常有效。 然而，它使用`O(n)`额外的空间，因为必须存储所有节点值。 后续明确询问我们是否可以避免额外的空间，因此我们需要更好的东西。 

### 最佳方法，油藏采样

 关键的观察是我们实际上不需要提前知道链表的总长度。 

储层采样允许我们一次处理一个元素，同时在迄今为止看到的所有元素中保持均匀的随机选择。 

这个想法是这样的：

 - 从第一个节点开始作为当前答案。 
- 当我们访问`i-th`节点，用概率替换当前答案`1 / i`。 
- 继续直到列表末尾。 

这就保证了处理完所有节点后，每个节点被选择的概率相等。 

水库采样的优点在于：

 - 每次调用我们只遍历列表一次。 
- 我们使用恒定的额外空间。 
- 我们不需要事先知道列表长度。 

这正是后续要求的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 初始化，O(1) 每次查询 | O(n) | 将所有节点值存储在数组中 |
 | 最佳 | 每个查询 O(n) | O(1) | O(1) | 水库采样，无需额外存储 |

 ## 算法演练

 ### 水库采样算法

 1、初始化时存储链表头。 

我们保留对链表的引用，因为我们每次都会遍历它`getRandom()`被称为。 
2. 初始化变量以保存所选值。 

最初，我们选择第一个节点的值作为暂定答案。 
3、逐个节点遍历链表。 

我们维护一个计数器，表示到目前为止已看到的节点数量。 
4. 对于`i-th`节点，生成范围内的随机整数`[1, i]`。 

如果随机数等于`1`，用当前节点的值替换当前答案。 
5. 继续直到遍历完成。 

最后，返回选择的值。 

### 为什么它有效

 正确性来自于概率保存。 

考虑节点`k`。 

- 当节点`k`被访问，以概率被选择`1/k`。 
- 为了保持选中状态，它必须在所有后续节点的替换中幸存下来。 
- 节点`k+1`用概率代替`1/(k+1)`，所以它有概率生存`k/(k+1)`。 
- 节点`k+2`用概率代替`1/(k+2)`，所以它有概率生存`(k+1)/(k+2)`。 

将所有概率相乘：$$\frac{1}{k} \times \frac{k}{k+1} \times \frac{k+1}{k+2} \times \cdots \times \frac{n-1}{n} = \frac{1}{n}$$因此，每个节点以相同的概率结束`1/n`。 

## Python 解决方案```python
import random
from typing import Optional

# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:

    def __init__(self, head: Optional[ListNode]):
        self.head = head

    def getRandom(self) -> int:
        current = self.head
        chosen_value = current.val

        node_index = 1

        while current:
            if random.randint(1, node_index) == 1:
                chosen_value = current.val

            current = current.next
            node_index += 1

        return chosen_value

# Your Solution object will be instantiated and called as such:
# obj = Solution(head)
# param_1 = obj.getRandom()
```该实现在初始化期间仅存储头指针。 不发生预处理或数组转换。 

里面`getRandom()`，我们从头到尾遍历链表。 

变量`chosen_value`存储当前的储层样本。 最初，它包含第一个节点的值。 

变量`node_index`跟踪到目前为止有多少个节点已被访问。 

对于每个节点：

 - 生成一个随机整数`1`到`node_index`- 仅当随机数等于时才替换所选值`1`这个替换概率正好是`1 / node_index`，这是油藏采样的核心规则。 

遍历完成后，返回最终选择的值。 

## 解决方案```go
import (
	"math/rand"
)

/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
type Solution struct {
	head *ListNode
}

func Constructor(head *ListNode) Solution {
	return Solution{
		head: head,
	}
}

func (this *Solution) GetRandom() int {
	current := this.head
	chosenValue := current.Val

	nodeIndex := 1

	for current != nil {
		if rand.Intn(nodeIndex) == 0 {
			chosenValue = current.Val
		}

		current = current.Next
		nodeIndex++
	}

	return chosenValue
}

/**
 * Your Solution object will be instantiated and called as such:
 * obj := Constructor(head);
 * param_1 := obj.GetRandom();
 */
```Go 实现遵循与 Python 版本相同的储层采样逻辑。 

一个小的区别是随机数生成 API：

 - Python使用`random.randint(1, node_index) == 1`- Go 使用`rand.Intn(nodeIndex) == 0`自从`rand.Intn(nodeIndex)`生成一个数字`[0, nodeIndex - 1]`，检查是否等于`0`给出概率`1 / nodeIndex`。 

Go 还需要显式的结构字段，因此链表头存储在`Solution`结构。

 ## 边缘情况

 ### 单节点链表

 仅包含一个节点的列表是最小的有效输入。 这种情况可能会暴露假设至少存在两个节点的算法中的错误。 

例如：```
5
```正确的行为是始终返回`5`。 

该实现自然地处理了这个问题，因为遍历循环运行一次，并且以概率选择第一个节点`1`。 

### 重复的节点值

 链接列表可能包含重复的值。 

例如：```
7 -> 7 -> 7
```一个常见的错误是根据唯一值而不是节点来思考。 该问题需要每个节点的概率相等，而不是每个不同值的概率相等。 

油藏采样单独对节点进行操作，因此即使值重复，每个节点仍然具有相等的概率。 

### 极大的链表

 后续内容特别提到了大小未知的非常大的链表。 

强力数组转换可能会消耗大量内存。 它还需要提前了解完整的列表内容。 

储层采样完全避免了这一问题，因为它一次处理一个节点，并且仅使用恒定的额外内存。 

这使得该算法具有可扩展性，并且适用于流数据或未知长度的数据。 

### 列表长度未知

 一些随机算法依赖于事先了解元素的总数。 这在流媒体场景中是不可能的。 

储层采样不需要事先了解列表长度。 当遇到节点时，替换概率会动态调整。 

这个属性正是该算法非常适合该问题的原因。
