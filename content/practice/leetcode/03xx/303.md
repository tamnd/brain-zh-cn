[LeetCode 问题 303](https://leetcode.com/problems/range-sum-query-immutable/)

 **难度：** 🟢简单
 **主题：** 数组、设计、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种数据结构，支持在固定数组上进行高效的范围求和查询。 我们得到一个整数数组`nums`，初始化后，数组永远不会改变。 目标是回答以下形式的多个查询：

 > 索引之间所有元素的总和是多少`left`和索引`right`，包容性？ 

该类必须支持两种操作：

 - 使用输入数组进行初始化
 - 查询任意连续子数组的总和

 例如，如果数组是：```
[-2, 0, 3, -5, 2, -1]
```我们查询`sumRange(0, 2)`，我们计算：```
-2 + 0 + 3 = 1
```重要的细节是数组是不可变的。 这意味着值在构建后永远不会改变。 由于可能存在很多范围求和查询，因此从头开始重复重新计算求和会浪费时间。 

限制相对较小：

 -`nums.length <= 10^4`- 最多`10^4`打电话给`sumRange`尽管这些限制是可以管理的，但简单的解决方案仍然可以执行以下操作：```
10^4 queries × 10^4 elements = 10^8 operations
```对于这样一个简单的问题来说，这是不必要的昂贵。 

一些边缘情况很重要：

 - 包含负数的数组
 - 覆盖整个数组的查询
 - 查询地点`left == right`，意味着结果是单个元素
 - 长度数组`1`- 重复查询重叠范围

 该问题保证有效索引并保证`left <= right`，所以我们不需要处理无效输入。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是每次计算总和`sumRange`被称为。 

对于每个查询，我们从索引迭代`left`到`right`并累计总数。 

这种方法是正确的，因为它确实遵循了问题的定义。 每个请求的元素在计算中只包含一次。 

然而，当查询较多时，性能效率较低。 如果每个查询最多扫描`n`元素，那么每次操作的成本`O(n)`时间。 

高达`10^4`查询，重复迭代变得昂贵。 

### 最优方法，前缀和

 关键的观察结果是数组永远不会改变。 

由于值是不可变的，因此我们可以在初始化期间对信息进行一次预处理，然后将其重新用于每个查询。 

我们构建一个前缀和数组，其中：```
prefix[i]
```存储索引之前所有元素的总和`i`。 

更具体地说：```
prefix[0] = 0
prefix[1] = nums[0]
prefix[2] = nums[0] + nums[1]
...
```使用这种结构，任何范围的总和`[left, right]`可以在常数时间内计算：```
prefix[right + 1] - prefix[left]
```为什么这有效？ 

-`prefix[right + 1]`包含索引的总和`0`通过`right`-`prefix[left]`包含索引的总和`0`通过`left - 1`- 减去它们会删除之前的所有内容`left`这将每个查询从`O(n)`时间到`O(1)`时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n) | O(1) | O(1) | 每次重新计算范围总和 |
 | 最佳| 预处理后每个查询的 O(1) | O(n) | 使用前缀和进行恒定时间查询 |

 ## 算法演练

 1.初始化时，创建一个长度为前缀和的数组`len(nums) + 1`。 

开头的额外元素简化了计算并避免了从索引开始的范围的边缘情况处理`0`。 
2. 将第一个前缀值设置为`0`。 

这表示零元素的总和。 
3. 迭代输入数组并构建累积和。 

对于每个索引`i`：```
prefix[i + 1] = prefix[i] + nums[i]
```这意味着每个位置存储所有先前元素的总和。 
4. 什么时候`sumRange(left, right)`被称为，计算：```
prefix[right + 1] - prefix[left]
```减法删除之前的所有元素`left`，只留下所需的范围总和。 
5. 立即返回计算结果。 

查询期间不需要对该范围进行迭代。 

### 为什么它有效

 正确性来自于前缀和数组的定义。`prefix[i]`始终存储索引中元素的总和`0`通过`i - 1`。 

所以：```
prefix[right + 1]
```包含以下元素的总和`0`通过`right`。 

相似地：```
prefix[left]
```包含目标范围之前的元素之和。 

将两者相减，删除不需要的元素，并留下精确的总和`left`到`right`。 

数学上：$\sum_{i=left}^{right} nums[i] = prefix[right+1] - prefix[left]$## Python 解决方案```python
from typing import List

class NumArray:

    def __init__(self, nums: List[int]):
        self.prefix = [0] * (len(nums) + 1)

        for i in range(len(nums)):
            self.prefix[i + 1] = self.prefix[i] + nums[i]

    def sumRange(self, left: int, right: int) -> int:
        return self.prefix[right + 1] - self.prefix[left]

# Your NumArray object will be instantiated and called as such:
# obj = NumArray(nums)
# param_1 = obj.sumRange(left, right)
```该实现首先在初始化期间构造一个前缀和数组。 该数组在开头有一个额外的槽，初始化为`0`。 

对于每个索引`nums`，我们计算到该位置的累积和。 此预处理步骤的成本`O(n)`时间但只发生一次。 

这`sumRange`然后，方法使用前缀和执行简单的减法。 由于已经预先计算了必要的信息，因此每个查询都会以恒定的时间运行。 

公式：```python
prefix[right + 1] - prefix[left]
```直接提取所请求子数组的总和。 

## 解决方案```go
type NumArray struct {
	prefix []int
}

func Constructor(nums []int) NumArray {
	prefix := make([]int, len(nums)+1)

	for i := 0; i < len(nums); i++ {
		prefix[i+1] = prefix[i] + nums[i]
	}

	return NumArray{
		prefix: prefix,
	}
}

func (this *NumArray) SumRange(left int, right int) int {
	return this.prefix[right+1] - this.prefix[left]
}

/**
 * Your NumArray object will be instantiated and called as such:
 * obj := Constructor(nums);
 * param_1 := obj.SumRange(left,right);
 */
```Go 实现遵循与 Python 解决方案相同的逻辑。 一个名为`prefix`存储累计金额。 

Go 切片是对数组的动态大小引用，使其非常适合此用例。 构造函数分配一个长度的切片`len(nums) + 1`。 

与某些语言不同，Go 整数是平台相关的，但这里的约束足够小，因此不必担心整数溢出。 

这`SumRange`方法执行与 Python 中使用的相同的恒定时间减法。

 ## 边缘情况

 当查询范围仅包含单个元素时，会出现一种重要的边缘情况。 在这种情况下，`left == right`。 有缺陷的实现可能会意外排除端点或错误处理减法边界。 前缀和公式可以正确工作，因为：```
prefix[right + 1] - prefix[left]
```精确地隔离一个值。 

另一个重要的边缘情况是当查询从索引处开始时`0`。 没有额外的领先`0`在前缀和数组中，特殊情况逻辑是必要的。 通过存储初始`0`，该实现自然会处理从数组开头开始的范围。 

包含负值的数组也很重要。 一些不正确的方法假设累积总和总是增加，但这在这里是不正确的。 前缀和仍然可以完美地工作，因为该方法仅依赖于算术减法，而不依赖于单调行为。 

最后，长度数组`1`测试初始化​​和索引是否安全实现。 由于前缀数组总是有长度`n + 1`，即使是最小的有效输入也能正常工作，无需越界访问。
