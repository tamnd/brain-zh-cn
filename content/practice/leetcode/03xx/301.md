[LeetCode 问题 301](https://leetcode.com/problems/remove-invalid-parentheses/)

 **难度：** 🔴难
 **主题：** 字符串、回溯、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题要求我们从字符串中删除最少数量的无效括号，以便剩余的字符串变得有效。 输入字符串除括号外还可以包含小写英文字母。 字母不会影响有效性，并且应始终保留在结果字符串中，除非它们作为更广泛的删除过程的一部分被删除。 目标是返回可以通过尽可能少的删除生成的每个唯一的有效字符串。 

有效的括号字符串遵循标准匹配规则。 每个左括号`(`最终必须与右括号匹配`)`，并且在从左到右扫描期间，右括号的数量决不能超过左括号的数量。 字母可以出现在任何地方，在检查有效性时会被忽略。 

这个问题的关键细节是我们不被要求只返回一个有效的字符串。 我们必须返回删除最少数量的括号后可以形成的所有唯一有效字符串。 这意味着有两件事同时重要：

 - 结果字符串必须有效。 
- 移除的数量必须尽可能少。 

限制相对较小。 字符串长度最多为25，括号最多为20个。 这些限制强烈表明，如果仔细修剪，指数探索是可以接受的。 在最坏的情况下，生成每个可能的子序列的强力解决方案仍然太大，但是使用回溯或广度优先搜索的仔细控制的搜索变得实用。 

一些边缘情况很重要：

 - 已经有效的字符串，例如`"()()"`，应返回原始字符串不变。 
- 仅包含无效括号的字符串，例如`")("`，应该返回`[""]`。 
- 必须避免重复的结果，因为不同的删除路径可能会产生相同的字符串。 
- 包含与括号混合的字母的字符串需要正确保留字母，同时仅验证括号。 
- 如果不仔细处理修剪，具有许多重复括号的输入可能会创建巨大的重复搜索树。 

## 方法

 ### 蛮力方法

 暴力策略是通过决定每个字符是保留还是删除来生成字符串的每个可能的子序列。 生成候选字符串后，我们检查它是否形成有效的括号序列。 在所有有效候选者中，我们只保留最大长度的候选者，因为最大化长度相当于最小化删除。 

这种方法是正确的，因为它探索了所有可能的删除字符的方法。 由于每个有效结果都出现在搜索空间中的某个位置，因此该算法最终会找到所有最小移除解决方案。 

问题在于子序列的数量呈指数增长。 对于一个长度的字符串`n`， 有`2^n`可能的子序列。 即使与`n = 25`，这变得太昂贵了。 此外，验证每个生成的字符串需要另一次线性扫描，使得总复杂度极高。 

### 最佳方法

 更好的解决方案是使用广度优先搜索，缩写为 BFS。 

关键的观察结果是 BFS 自然地逐层探索状态。 每个级别对应于比前一个级别多删除一个字符。 这个属性非常有价值，因为当我们第一次遇到有效的字符串时，我们知道它们是使用最少的删除次数生成的。 

我们不是生成每个子序列，而是：

 - 从原始字符串开始。 
- 通过删除每个位置的一个括号来生成相邻状态。 
- 使用 BFS 探索括号越来越少的字符串。 
- 一旦找到有效的字符串，就停止探索更深层次。 

这保证了最小的删除，因为 BFS 处理所有状态`k`在考虑具有以下特征的状态之前进行删除`k + 1`搬迁。 

哈希集用于避免重新访问重复的字符串。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × n) | O(2^n × n) | O(2^n × n) | O(2^n × n) | 生成每个子序列并验证每个子序列 |
 | 最优 BFS | O(2^n × n) 最坏情况 | O(2^n × n) | O(2^n × n) | 在实践中速度要快得多，因为 BFS 会停止在最小移除级别 |

 尽管最坏情况的复杂性仍然是指数级的，但 BFS 极大地减少了不必要的探索，因为一旦发现最小移除解决方案，它就会终止。 

## 算法演练

 ### BFS 策略

 1. 首先将原始字符串放入队列中。 

队列代表等待处理的状态。 每个状态都是经过一些删除后形成的候选字符串。 
2. 创建一个名为的哈希集`visited`。 

不同的删除路径可以产生相同的字符串。 如果没有重复数据删除，搜索树将会呈指数级爆炸。 这`visited`set 确保每个字符串仅被处理一次。 
3. 定义一个辅助函数来验证字符串。 

验证逻辑从左到右扫描，同时维护一个计数器：

 - 增量为`(`。 
- 递减`)`。 
- 如果计数器变为负值，则该字符串无效。 
- 最后，计数器必须为零。 
4. 使用 BFS 逐级处理字符串。 

每一级都对应删除一个额外的角色。 这是保证最小移除量的关键属性。 
5. 对于从队列中移除的每个字符串，检查它是否有效。 

如果有效：

 - 将其添加到答案列表中。 
- 标记已找到有效级别。 
6. 一旦在当前级别找到有效字符串，就不要生成更深的状态。 

由于 BFS 通过删除计数进行探索，因此任何更深的级别都需要更多的删除，因此不是最佳的。 
7. 如果当前字符串无效并且在该级别尚未找到有效字符串，则生成邻居。 

邻居是通过在每个可能的位置删除一个括号字符来创建的。 
8. 在删除生成过程中跳过非括号字符。 

删除字母永远没有好处，因为字母不会影响有效性。 
9. 将未见过的邻居字符串添加到队列中并将其标记为已访问。 

这可以有效地继续 BFS 探索，而无需冗余处理。 
10. 返回所有收集到的有效字符串。 

由于 BFS 在第一个有效级别停止，因此每个返回的字符串都使用最小的删除次数。 

### 为什么它有效

 正确性来自于 BFS 的层序性质。 每个 BFS 级别都对应于相同删除次数后生成的字符串。 因此，包含有效字符串的第一级必须表示所需的最小删除次数。 由于探索了该级别的每个可能的删除组合，因此找到了所有有效的最小删除字符串。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def removeInvalidParentheses(self, s: str) -> List[str]:
        
        def is_valid(string: str) -> bool:
            balance = 0
            
            for char in string:
                if char == '(':
                    balance += 1
                elif char == ')':
                    balance -= 1
                    
                    if balance < 0:
                        return False
            
            return balance == 0
        
        result = []
        visited = set([s])
        queue = deque([s])
        found = False
        
        while queue:
            current = queue.popleft()
            
            if is_valid(current):
                result.append(current)
                found = True
            
            if found:
                continue
            
            for i in range(len(current)):
                if current[i] not in '()':
                    continue
                
                next_string = current[:i] + current[i + 1:]
                
                if next_string not in visited:
                    visited.add(next_string)
                    queue.append(next_string)
        
        return result
```实施开始于`is_valid`辅助功能。 该函数使用简单的计数器检查字符串是否具有平衡的括号。 每个左括号都会增加计数器，每个右括号都会减少计数器。 如果计数器变为负数，则在匹配的左括号之前会出现右括号，从而使字符串立即无效。 

BFS 部分使用用原始输入字符串初始化的队列。 这`visited`设置可防止重复处理。 

在每次 BFS 迭代期间，都会验证当前字符串。 如果有效，则将其添加到结果列表中，并`found`标志变成`True`。 一旦发生这种情况，就不会探索更深的层次，因为更深的层次将涉及额外的删除。 

如果尚未找到有效字符串，算法将通过删除每个可能位置处的一个括号来生成所有相邻状态。 字母会被跳过，因为删除它们无助于创建有效的括号。 

最终结果包含需要最少删除次数的每个唯一有效字符串。 

## 解决方案```go
package main

func removeInvalidParentheses(s string) []string {
    
    isValid := func(str string) bool {
        balance := 0
        
        for _, ch := range str {
            if ch == '(' {
                balance++
            } else if ch == ')' {
                balance--
                
                if balance < 0 {
                    return false
                }
            }
        }
        
        return balance == 0
    }
    
    result := []string{}
    visited := make(map[string]bool)
    queue := []string{s}
    
    visited[s] = true
    found := false
    
    for len(queue) > 0 {
        current := queue[0]
        queue = queue[1:]
        
        if isValid(current) {
            result = append(result, current)
            found = true
        }
        
        if found {
            continue
        }
        
        for i := 0; i < len(current); i++ {
            if current[i] != '(' && current[i] != ')' {
                continue
            }
            
            nextString := current[:i] + current[i+1:]
            
            if !visited[nextString] {
                visited[nextString] = true
                queue = append(queue, nextString)
            }
        }
    }
    
    return result
}
```Go 实现遵循与 Python 版本相同的 BFS 结构。 由于 Go 没有像 Python 那样内置的双端队列结构`collections.deque`，使用切片作为队列。 

这`visited`结构是使用从字符串到布尔值的映射来实现的。 字符串切片用于在删除一个字符后生成邻居状态。 

Go 字符串是不可变的，因此创建`nextString`安全地生成一个新字符串而不修改原始字符串。

 ## 边缘情况

 一个重要的边缘情况是字符串已经有效。 幼稚的实现可能会继续删除不必要的括号并生成更短的有效字符串。 BFS 解决方案避免了这种情况，因为它首先检查原始字符串。 如果原始字符串有效，BFS 会立即返回它，并且不会探索更深层次。 

另一个重要的边缘情况是仅包含无效括号的字符串，例如`")("`或者`"((("`。 这些情况通常会暴露验证逻辑中的错误，因为可能没有有效的非空解决方案。 该实现通过继续 BFS 直到到达空字符串（始终有效）来正确处理此问题。 

第三个关键边缘情况涉及重复的生成路径。 例如，字符串`"())"`可以产生相同的结果`"()"`删除两个右括号中的任何一个。 没有一个`visited`设置后，算法将重复处理重复的状态，从而导致不必要的工作和可能的重复输出。 The hash set guarantees that each generated string is explored exactly once.

 另一个微妙的边缘情况是包含与括号混合的字母的字符串。 由于字母不影响有效性，因此删除它们是不必要且浪费的。 该实现在生成邻居时会跳过非括号字符，从而在保持正确性的同时提高了效率。
