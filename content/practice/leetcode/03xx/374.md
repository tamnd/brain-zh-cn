[LeetCode 第 374 题](https://leetcode.com/problems/guess-number-higher-or-lower/)

 **难度：** 🟢简单
 **主题：** 二分查找、交互

 ## 解决方案

 ## 问题理解

 该问题描述了一个经典的互动猜谜游戏。 一个隐藏号码叫`pick`被选择在范围内的某个地方`1`到`n`，包含在内。 我们无权访问`pick`直接地。 相反，我们只能与提供的 API 函数进行交互：```
guess(num)
```这个 API 告诉我们当前的猜测是太高、太低还是完全正确。 

返回值的含义如下：

 -`-1`表示猜测的数字大于隐藏的数字
 -`1`表示猜测的数字小于隐藏的数字
 -`0`意味着猜测是正确的

 我们的任务是确定隐藏的数字并返回它。 

输入由单个整数组成`n`，它定义了搜索范围`[1, n]`。 预期输出是游戏选择的确切隐藏数字。 

约束在这里尤其重要：```
1 <= n <= 2^31 - 1
```这意味着搜索空间可能非常大，可能超过 20 亿个数字。 因此，线性扫描`1`到`n`在最坏的情况下将是低效的。 该问题的设计目的是为了鼓励使用二分搜索。 

该问题的一个重要属性是 API 响应创建了单调关系：

 - 如果猜测太高，则每个较大的数字也太高。 
- 如果猜测太低，则每个较小的数字也太低。 

这种有序结构正是二分查找所需要的。 

有几种边缘情况值得预先认识。 隐藏的数字可能是最小的可能值，`1`，或最大可能值，`n`。 该范围也可以仅包含一个数字，例如`n = 1`。 另一个微妙的问题是在 Go 或 Java 等语言中计算中点时的整数溢出。 使用：```
mid = left + (right - left) / 2
```比以下更安全：```
mid = (left + right) / 2
```因为后者可能会溢出`left`和`right`非常大。 

## 方法

 ### 蛮力方法

 最直接的解决方案是依次尝试每个数字`1`到`n`。 

对于每个数字：

 - 打电话`guess(current)`- 如果API返回`0`，我们找到了隐藏的数字
 - 否则继续下一个值

 这种方法是正确的，因为它最终会检查每个可能的候选者。 由于隐藏数保证存在于范围内，因此算法最终必须找到它。 

然而，对于较大的值，此解决方案太慢`n`。 在最坏的情况下，如果隐藏的数字是`n`，我们需要做`n`API 调用。 和`n`可能等于`2^31 - 1`，这变得不切实际。 

关键的低效率是暴力方法忽略了API提供的信息。 当 API 表示猜测过高或过低时，我们可以立即消除大部分搜索空间。 

### 最佳方法

 重要的观察是搜索空间是隐式排序的。 

如果`guess(mid)`返回：

 -`-1`，则隐藏数小于`mid`-`1`，则隐藏数大于`mid`-`0`，然后我们找到了答案

 这意味着我们可以反复将剩余的搜索范围减半。 这正是二分搜索策略。 

二分查找极大地减少了猜测的次数。 我们不是一一检查数字，而是在每次 API 调用后消除一半的剩余可能性。 

例如：

 - 从范围开始`[1, n]`- 检查中间值
 - 根据API结果，丢弃左半部分或右半部分
 - 重复直到找到号码

 这将时间复杂度从线性降低到对数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 依次测试每个数字 |
 | 最佳 | O(log n) | O(1) | O(1) | 使用二分查找重复将搜索空间减半 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`，表示当前的搜索范围。 

最初：```
left = 1
right = n
```我们知道隐藏的数字一定存在于这个区间内的某个地方。 
2.继续搜索`left <= right`。 

此条件确保搜索范围内仍然存在有效的候选者。 
3. 计算中间值。 

使用：```
mid = left + (right - left) // 2
```而不是`(left + right) // 2`以避免某些语言中可能出现的整数溢出。 
4. 致电`guess(mid)`API。 

API 告诉我们如何`mid`与隐藏数字进行比较。 
5. 如果API返回`0`， 返回`mid`。 

这说明我们猜对了。 
6. 如果API返回`-1`，移动右边界。 

自从`mid`太大，隐藏数必须在：```
[left, mid - 1]
```更新：```
right = mid - 1
```7. 如果API返回`1`，移动左边界。 

自从`mid`太小，隐藏数必须在：```
[mid + 1, right]
```更新：```
left = mid + 1
```8. 重复直到找到隐藏的号码。 

### 为什么它有效

 该算法之所以有效，是因为在每次 API 调用之后，我们都会消除一半的剩余候选者，同时保留隐藏数字始终保留在当前搜索区间内的不变量。 

每一步：

 - 如果猜测太高，则所有更大的数字都是不可能的。 
- 如果猜测太低，则所有较小的数字都是不可能的。 

由于每次迭代搜索间隔都会正确缩小，并且保证隐藏数存在，因此算法最终必须收敛到正确答案。 

## Python 解决方案```python
# The guess API is already defined for you.
# @param num, your guess
# @return -1 if num is higher than the picked number
#          1 if num is lower than the picked number
#          otherwise return 0
# def guess(num: int) -> int:

class Solution:
    def guessNumber(self, n: int) -> int:
        left = 1
        right = n

        while left <= right:
            mid = left + (right - left) // 2
            result = guess(mid)

            if result == 0:
                return mid
            elif result == -1:
                right = mid - 1
            else:
                left = mid + 1

        return -1
```实现首先定义搜索边界，`left`和`right`。 这些代表隐藏数字可能仍然存在的最小和最大可能值。 

在循环内部，使用以下方法仔细计算中点：```python
mid = left + (right - left) // 2
```此公式避免了具有固定大小整数的语言中的溢出问题。 

这`guess(mid)`然后调用API并将其存储在`result`。 

如果`result == 0`，我们立即返回`mid`因为已经找到了正确的号码。 

如果`result == -1`，猜测太大，所以我们通过移动来缩小搜索范围`right`到`mid - 1`。 

如果`result == 1`，猜测太小，所以我们移动`left`到`mid + 1`。 

循环继续缩小间隔，直到找到隐藏的数字。 

决赛`return -1`从技术上讲是无法到达的，因为该问题保证隐藏数字存在于范围内。 

## 解决方案```go
/** 
 * Forward declaration of guess API.
 * @param  num   your guess
 * @return       -1 if num is higher than the picked number
 *                1 if num is lower than the picked number
 *                otherwise return 0
 * func guess(num int) int;
 */

func guessNumber(n int) int {
    left := 1
    right := n

    for left <= right {
        mid := left + (right-left)/2
        result := guess(mid)

        if result == 0 {
            return mid
        } else if result == -1 {
            right = mid - 1
        } else {
            left = mid + 1
        }
    }

    return -1
}
```Go 实现遵循与 Python 版本相同的二分搜索逻辑。 一个重要的细节是中点计算：```go
mid := left + (right-left)/2
```这可以避免整数溢出`left`和`right`非常大。 

与 Python 不同，Go 使用固定大小的整数类型，因此溢出预防的重要性更加明确。 

否则，两种实现之间的逻辑和控制流程是相同的。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n = 1`。 在这种情况下，搜索范围恰好包含一个数字。 粗心的实现可能会错误地跳过循环或错误地处理边界条件。 当前的实现可以自然地处理这个问题，因为循环条件`left <= right`仍然成立，中点变为`1`，立即返回。 

另一个重要的边缘情况是当隐藏数字位于范围的极端边界时，`1`或者`n`。 这些情况是差一错误的常见来源。 例如，如果实现错误地使用更新边界`mid`而不是`mid - 1`或者`mid + 1`，循环可能会变得无限。 该实现通过始终从未来的搜索中排除已经测试的中点来避免这种情况。 

第三个关键边缘情况涉及非常大的值`n`，特别是靠近`2^31 - 1`。 在具有固定大小整数的语言中，使用以下方法计算中点：```
(left + right) / 2
```可以溢出。 该实现通过计算来避免这种情况：```
left + (right - left) / 2
```即使对于极大的搜索范围也能保证安全的算术。
