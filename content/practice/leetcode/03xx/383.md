[LeetCode 问题 383](https://leetcode.com/problems/ransom-note/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 本题询问是否可以构造字符串`ransomNote`使用从字符串中获取的字符`magazine`。 中的每个角色`magazine`只能使用一次，这意味着字符频率很重要。 如果`ransomNote`需要一个字母出现的次数多于`magazine`包含，答案一定是`false`。 

换句话说，我们需要验证所需的每个字母`ransomNote`存在于`magazine`数量充足。 

输入由两个小写英文字符串组成：

 -`ransomNote`，我们要构造的字符串
 -`magazine`，可用字母的来源

 预期输出是一个布尔值：

 -`true`如果可以提供所有必需的字母
 -`false`否则

 约束条件很重要：

 - 两个字符串都可以大到`10^5`- 仅使用小写英文字母

 大的输入大小告诉我们，低效的重复搜索可能会太慢。 由于字母表仅限于 26 个小写字母，因此计算频率成为一种非常自然且有效的策略。 

需要考虑一些重要的边缘情况：

 -`ransomNote`可能需要一个不存在的字母`magazine`-`ransomNote`可能需要一封信的多份副本`magazine`包含较少的副本
 -`magazine`可能包含许多额外未使用的字母
 - 字符串可能非常大，因此需要重复扫描`magazine`应该避免

 由于该问题仅保证小写英文字母，因此我们可以使用哈希映射或长度为 26 的固定大小数组。 

## 方法

 ### 蛮力方法

 一个简单的方法是处理每个字符`ransomNote`并一一搜索里面匹配的未使用的字符`magazine`。 

一种可能的实现是：

 1. 转换`magazine`进入可变列表
 2. 对于每个字符`ransomNote`- 搜索`magazine`- 如果找到该字符，请将其删除或标记为已使用
 - 如果没有找到，则返回`false`3. 如果所有字符都匹配，则返回`true`这种方法是正确的，因为它明确地模拟一次从杂志中取出一封信。 

然而，它的效率很低。 对于每一个角色`ransomNote`，我们可以扫描大部分`magazine`。 如果两个字符串都是长度`n`，总工作量可以变为`O(n^2)`。 

输入尺寸高达`10^5`，二次时间太慢了。 

### 最佳方法

 关键的观察结果是字符的顺序并不重要，只有每个字符出现的次数才重要。 

我们可以计算每个字母在其中出现的次数，而不是重复搜索字母`magazine`，然后在处理时减去计数`ransomNote`。 

例如：

-`magazine = "aab"`产生计数：

 -`a -> 2`-`b -> 1`然后在读书的时候`ransomNote = "aa"`:

 - 使用一个`a`，剩余计数变为`1`- 使用另一个`a`，剩余计数变为`0`由于任何计数都不会变为负数，因此构建是可能的。 

这将重复搜索转换为恒定时间频率更新。 

由于只有 26 个小写字母，因此该解决方案非常高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m) | O(米) | 反复搜索并删除杂志中的人物 |
 | 最佳| O(n + m) | O(1) | O(1) | 使用固定大小的数组计算字符频率 |

 ## 算法演练

 1. 创建一个大小为 26 的频率数组。 

由于输入只包含小写英文字母，我们可以映射：

 -`'a'`索引`0`-`'b'`索引`1`- ...
 -`'z'`索引`25`这提供了对字符计数的恒定时间访问。 
2. 遍历`magazine`字符串并计算每个字符。 

对于每个角色：

 - 使用计算其索引`ord(char) - ord('a')`- 增加相应的计数

 在此步骤之后，数组存储每个字母的可用副本数。 
3. 遍历`ransomNote`细绳。 

对于每个角色：

 - 计算其指数
 - 减少相应的计数

 这代表使用杂志中该角色的一份副本。 
4. 检查是否有计数变为负值。 

如果计数变为负数，则意味着`ransomNote`需要的信件份数多于`magazine`提供。 

在这种情况下，请立即返回`false`。 
5. 如果循环成功完成，则返回`true`。 

这意味着每个所需的角色都有足够的数量。 

### 为什么它有效

 该算法保持了频率数组始终代表剩余未使用字母的不变性`magazine`。 

每次减量对应于赎金字条消耗一个字符。 如果任何计数变为负数，则我们消耗的角色副本比最初可用的数量多，这使得构建变得不可能。 

如果在不违反此条件的情况下处理所有字符，则每个所需的字母都有足够的数量，因此可以构造勒索字条。 

## Python 解决方案```python
class Solution:
    def canConstruct(self, ransomNote: str, magazine: str) -> bool:
        char_counts = [0] * 26

        for char in magazine:
            index = ord(char) - ord('a')
            char_counts[index] += 1

        for char in ransomNote:
            index = ord(char) - ord('a')
            char_counts[index] -= 1

            if char_counts[index] < 0:
                return False

        return True
```实现首先创建一个名为的固定大小数组`char_counts`。 每个位置代表一个小写英文字母。 

第一个循环过程`magazine`并记录每个字符出现的次数。 这将准备可用的信件清单。 

第二个循环处理`ransomNote`。 每个字符都会减少相应的计数，因为正在消耗一份副本。 

当计数变为负数时，函数返回`False`。 这表明赎金字条需要的角色副本数量比杂志中包含的数量还要多。 

如果成功处理整个勒索字条，该函数将返回`True`。 

这种实现非常高效，因为每个字符都只被处理一次。 

## 解决方案```go
func canConstruct(ransomNote string, magazine string) bool {
    charCounts := make([]int, 26)

    for _, char := range magazine {
        index := char - 'a'
        charCounts[index]++
    }

    for _, char := range ransomNote {
        index := char - 'a'
        charCounts[index]--

        if charCounts[index] < 0 {
            return false
        }
    }

    return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 

长度为 26 的切片存储字符频率。 Go 字符在迭代过程中被表示为符文`range`，所以减去`'a'`正确地将每个小写字母映射到索引。 

不需要对空值或 nil 值进行特殊处理，因为问题约束保证有效的非空小写字符串。 

整数溢出不是问题，因为计数永远不会超过`10^5`，它很容易适合 Go 的整数类型。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`ransomNote`需要一个不存在的字符`magazine`根本不。 例如，`"a"`和`"b"`。 有错误的实现可能会继续不必要的搜索或无法正确检测缺失。 在此解决方案中，频率计数为`'a'`从零开始，在处理过程中立即变为负值，从而正确返回`false`。 

另一个重要的情况是当一个角色存在于`magazine`但次数不够。 例如，`"aa"`和`"ab"`。 一些幼稚的实现只检查字符是否存在，而不检查频率是否足够。 该解决方案自然地处理了该问题，因为每次使用都会减少计数。 第二次减量使计数为负，表示失败。 

第三种边缘情况涉及额外未使用的字符`magazine`。 例如，`"abc"`和`"abccccc"`。 该算法应该忽略不必要的字母，只关注所需的字母是否可用。 由于未使用的计数只是保持正数，因此实现正确返回`true`。 

最后的边缘情况涉及接近约束极限的非常大的输入。 重复扫描杂志的二次解可能会超时。 此实现完全避免了重复搜索，并在线性时间内处理两个字符串，即使对于长度较长的字符串也非常高效`10^5`。
