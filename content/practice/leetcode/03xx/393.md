[LeetCode 第 393 题](https://leetcode.com/problems/utf-8-validation/)

 **难度：** 🟡 中等
 **主题：** 数组、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们确定整数序列是否表示有效的 UTF-8 编码字节流。 

输入数组中的每个整数代表一个字节，这意味着只有最低 8 位重要。 UTF-8 是一种可变长度编码系统，其中一个字符可以占用 1 到 4 个字节。 前导位的结构决定了一个字符有多少个字节。 

有效的 UTF-8 编码遵循以下规则：

 - 1 字节字符开头为`0`- 2 字节字符开头为`110`- 3 字节字符开头为`1110`- 4 字节字符开头为`11110`- 每个连续字节必须以`10`任务是扫描数组并验证每个字节序列是否与这些合法的 UTF-8 模式之一匹配。 

例如：

-`11000101 10000010`有效，因为第一个字节表示 2 字节字符，第二个字节正确地以`10`-`11101011 10001100 00000100`无效，因为第三个字节也应以`10`，但它开始于`00`约束告诉我们输入长度最多可达`2 * 10^4`，它足够大，我们应该以线性时间解决方案为目标。 幸运的是，UTF-8 验证只需要在本地检查位模式，因此我们可以一次性处理数据。 

一些边缘情况很重要：

 - 在出现足够的连续字节之前，多字节字符可能会提前结束
 - 可能出现连续字节而没有有效的前导字节
 - 前导字节可能表示无效长度，例如五个前导字节`1`位
 - 连续字节不能以`10`- 单字节字符和多字节字符可能混合出现

 该问题保证每个整数都已经在有效字节范围内`0`到`255`，所以我们不需要担心屏蔽更大的整数。 

## 方法

 ### 蛮力方法

 暴力策略会将每个整数显式转换为 8 个字符的二进制字符串，然后使用字符串操作验证 UTF-8 结构。 

对于每个字节：

 - 将其转换为二进制形式
 - 计算领先的`1`s
 - 确定是否以有效的UTF-8字符开头
 - 验证所需的连续字节

 这是可行的，因为 UTF-8 有效性完全取决于位前缀。 通过直接检查这些前缀作为字符串，我们可以确定正确性。 

然而，这种方法效率低下，因为：

 - 重复将整数转换为二进制字符串会产生额外的开销
 - 字符串切片和比较比直接位操作慢
 - 为每次转换分配额外的内存

 尽管渐近复杂度仍然是线性的，但与直接使用按位运算相比，实现不太优雅且效率明显较低。 

### 最佳方法

 关键的见解是 UTF-8 验证仅取决于每个字节的最高几位。 位操作允许我们直接检查这些位，而无需将任何内容转换为字符串。 

我们从左到右处理数组，同时跟踪仍需要多少个连续字节。 

当我们遇到新的前导字节时：

 - 我们确定它是否代表 1 字节、2 字节、3 字节或 4 字节字符
 - 我们记录必须跟随多少个连续字节

 处理连续字节时：

 - 我们验证该字节以`10`这种方法工作效率很高，因为每个字节都被处理一次，并且每个验证步骤都使用恒定时间位操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用二进制字符串转换和字符串处理 |
 | 最佳 | O(n) | O(1) | O(1) | 在单次传递中使用直接位操作 |

 ## 算法演练

 1. 初始化一个名为`remaining_bytes`到`0`。 

此变量跟踪当前 UTF-8 字符仍需要多少个连续字节。 
2. 迭代输入数组中的每个字节。 

我们按顺序处理字节，因为 UTF-8 字符是按顺序编码的。 
3.如果`remaining_bytes == 0`，当前字节必须开始一个新字符。 

我们检查前导位以确定字符长度。 
4. 使用位掩码检查字节模式。 

这些模式是：

 -`0xxxxxxx`→ 单字节字符
 -`110xxxxx`→ 期望 1 个连续字节
 -`1110xxxx`→ 预计有 2 个连续字节
 -`11110xxx`→ 预计有 3 个连续字节

 任何其他前导模式均无效。 
5. 如果该字节以多字节字符开头，则设置`remaining_bytes`因此。 

例如：

-`110xxxxx`表示需要一个连续字节
 -`1110xxxx`意味着需要两个连续字节
 6. 如果`remaining_bytes > 0`，当前字节必须是连续字节。 

连续字节必须匹配：$10xxxxxx$我们使用位掩码来验证这一点。 
7. 如果连续字节有效，则递减`remaining_bytes`。 

这意味着一个预期的连续字节已被成功消耗。 
8. 处理完所有字节后，确保`remaining_bytes == 0`。 

如果仍然需要连续字节，则编码提前结束并且无效。 

### 为什么它有效

 该算法保持一个简单的不变量：

 -`remaining_bytes`始终表示完成当前 UTF-8 字符所需的连续字节的确切数量。 

每当我们遇到前导字节时，我们就确定所需的连续计数。 每个连续字节都会将该计数减一。 如果任何字节违反UTF-8格式规则，我们立即返回`False`。 

因为每个 UTF-8 字符都必须严格遵循这些位前缀规则，所以成功处理整个数组`remaining_bytes == 0`保证编码有效。 

## Python 解决方案```python
from typing import List

class Solution:
    def validUtf8(self, data: List[int]) -> bool:
        remaining_bytes = 0

        for byte in data:
            if remaining_bytes == 0:
                # 1-byte character: 0xxxxxxx
                if (byte >> 7) == 0:
                    continue

                # 2-byte character: 110xxxxx
                elif (byte >> 5) == 0b110:
                    remaining_bytes = 1

                # 3-byte character: 1110xxxx
                elif (byte >> 4) == 0b1110:
                    remaining_bytes = 2

                # 4-byte character: 11110xxx
                elif (byte >> 3) == 0b11110:
                    remaining_bytes = 3

                else:
                    return False

            else:
                # Continuation byte must start with 10
                if (byte >> 6) != 0b10:
                    return False

                remaining_bytes -= 1

        return remaining_bytes == 0
```该实现直接反映了前面描述的算法。 

变量`remaining_bytes`跟踪仍需要多少个连续字节。 

什么时候`remaining_bytes == 0`，当前字节必须开始一个新的UTF-8字符。 该代码使用右移来检查前导位：

 -`byte >> 7 == 0`检查单字节字符
 -`byte >> 5 == 0b110`检查 2 字节序列
 -`byte >> 4 == 0b1110`检查 3 字节序列
 -`byte >> 3 == 0b11110`检查 4 字节序列

 如果这些模式都不匹配，则该字节无效。 

当需要连续字节时，实现会检查：$(byte >> 6) = 0b10$这确认了该字节以所需的开头`10`前缀。 

最后，该算法确保在处理整个数组后不会留下未完成的多字节序列。 

## 解决方案```go
func validUtf8(data []int) bool {
    remainingBytes := 0

    for _, b := range data {
        if remainingBytes == 0 {
            // 1-byte character: 0xxxxxxx
            if (b >> 7) == 0 {
                continue
            }

            // 2-byte character: 110xxxxx
            if (b >> 5) == 0b110 {
                remainingBytes = 1

            // 3-byte character: 1110xxxx
            } else if (b >> 4) == 0b1110 {
                remainingBytes = 2

            // 4-byte character: 11110xxx
            } else if (b >> 3) == 0b11110 {
                remainingBytes = 3

            } else {
                return false
            }

        } else {
            // Continuation byte must start with 10
            if (b >> 6) != 0b10 {
                return false
            }

            remainingBytes--
        }
    }

    return remainingBytes == 0
}
```Go 实现几乎与 Python 版本相同，因为逻辑基本上很简单并且与语言无关。 

一个小小的区别是 Go 使用显式整数类型并且`:=`变量初始化语法。 Go 也使用切片而不是 Python 列表，但迭代的工作方式类似`range`。 

不需要对整数溢出进行特殊处理，因为所有输入值都保证在`0`和`255`。

 ## 边缘情况

 ### 首先出现的连续字节

 一个字节开头`10`无法开始新的 UTF-8 字符。 这是一个常见的错误来源，因为连续字节仅在有效前导字节之后才合法。 

例如：```
[145]
```二进制：```
10010001
```实现正确地拒绝了这一点，因为当`remaining_bytes == 0`，该字节与任何有效的前导字节模式不匹配。 

### 不完整的多字节字符

 多字节字符可能正确开始，但在所有连续字节出现之前结束。 

例如：```
[240, 162, 138]
```第一个字节表示 4 字节字符，这意味着需要三个连续字节。 接下来仅两个连续字节。 

该实现通过检查是否`remaining_bytes == 0`处理完整个数组后。 

### 无效的连续字节

 连续字节必须始终以`10`。 

例如：```
[226, 130, 1]
```最后一个字节开始于`00`而不是`10`。 

这种边缘情况很重要，因为简单的实现可能只计算字节而不验证连续字节前缀。 该算法明确检查`(byte >> 6) == 0b10`，保证正确性。
