 # LeetCode 321 - 创建最大数量

 ## 问题理解

 这个问题要求我们构建字典顺序上最大可能的长度数`k`使用从两个数组中获取的数字，`nums1`和`nums2`。 

每个数组代表一个数字中的一系列数字。 我们可以选择一些数字`nums1`和一些数字`nums2`，但我们必须保留每个数组内数字的原始相对顺序。 

关键细节是我们不会任意重新排列数字。 如果我们从中选取数字`nums1`，它们的出现顺序必须与最初出现的顺序相同`nums1`。 同样的规则适用于`nums2`。 

最终结果必须准确包含`k`数字。 

例如：```
nums1 = [3,4,6,5]
nums2 = [9,1,2,5,8,3]
k = 5
```一种最佳选择是：

 - 采取`[6,5]`从`nums1`- 拿`[9,8,3]`从`nums2`然后小心地将它们合并到：```
[9,8,6,5,3]
```这形成了尽可能大的数字。 

约束条件很重要：

 -`m`和`n`每个都可以达到`500`-`k`可以大到`m + n`这立即告诉我们，暴力生成所有子序列是不可能的。 子序列的数量呈指数增长。 

这个问题结合了几个想法：

 - 贪心选择
 - 单调堆栈
 - 词典比较
 - 小心合并

 有几种边缘情况很容易破坏简单的实现：

 - 一个数组可能贡献所有数字，而另一个数组则不贡献任何数字
 - 可能存在许多重复的数字，使合并决策变得棘手
 - 两个候选序列可以共享长的相等前缀
 - 选择局部最大的数字并不总是全局最优的
 - 数组已经可以减少，这意味着不应该发生任何删除

 该问题保证：

 - 数字之间`0`和`9`-`k`始终有效
 - 数组不包含前导零作为数字，但允许使用内部零

 ## 方法

 ### 蛮力方法

 蛮力的想法是从两个数组生成每个有效长度的每个可能的子序列。 

对于每个分割：```sql
take i digits from nums1
take k - i digits from nums2
```我们会：

 1.生成所有长度的子序列`i`从`nums1`2.生成所有长度的子序列`k - i`从`nums2`3. 合并每一对
 4.保留字典顺序最大的结果

 这种方法是正确的，因为它探索了每一种可能的有效构造。 

然而，它太慢了。 

长度的数组`500`有大量的子序列。 甚至生成所有长度的子序列`250`在计算上是不可能的。 

我们需要更明智的策略。 

### 关键见解

 该问题可以分为三个较小的贪心问题：

 1. 从一个数组中选取固定长度的最大子序列
 2. 将两个子序列合并成最大可能的结果
 3. 尝试两个数组之间的每个有效分割

 关键的见解是长度的最佳子序列`t`可以使用单调递减堆栈贪婪地从一个数组中找到。 

构建子序列时：

 - 如果当前数字大于先前选择的数字
 - 我们还有足够的剩余数字
 - 然后删除较小的数字可以提高最终的数字

 这与单调堆栈问题中使用的逻辑完全相同。 

从两个数组中提取最佳子序列后，我们贪婪地合并它们：

 - 在每一步中，比较剩余的后缀
 - 按字典顺序选择较大的后缀

 这确保了全局最优合并。

 ## 算法演练

 ### 第 1 步：迭代所有有效的分割

 我们想尽一切办法来划分`k`两个数组之间的数字。 

如果我们采取`i`数字来自`nums1`，那么我们必须采取`k - i`数字来自`nums2`。 

有效范围是：```
max(0, k - n) <= i <= min(k, m)
```这保证了我们请求的数字永远不会超过数组包含的数字。 

### 第 2 步：从一个数组构建最大子序列

 对于固定长度`t`，我们使用单调堆栈贪婪地构造最大子序列。 

我们可以丢弃：```
len(nums) - t
```数字。 

当我们扫描数组时：

 1. 当堆栈非空时
 2. 当前数字比顶部大
 3.我们仍有可移除的空间

 我们弹出较小的数字。 

然后我们压入当前数字。 

这确保了较早的位置包含尽可能大的数字。 

例如：```
nums = [3,4,6,5]
t = 2
```我们可以删除 2 位数字。 

流程：

 | 数字| 堆栈| 行动|
 | --- | --- | --- |
 | 3 | [3] | 推|
 | 4 | [4] | 弹出 3，推送 4 |
 | 6 | [6] | 弹出 4，推送 6 |
 | 5 | [6,5]| 推|

 结果：```
[6,5]
```### 步骤 3：合并两个子序列

 现在我们合并两个最优子序列。 

贪心规则是：

 - 按字典顺序比较剩余后缀
 - 从较大的后缀中获取

 假设：```
a = [6,7]
b = [6,0,4]
```在第一个位置：```
[6,7] > [6,0,4]
```因为第二个数字`7 > 0`。 

所以我们取自`a`。 

这一点至关重要。 仅比较当前数字是不够的。 

### 第 4 步：保持最佳总体结果

 为每个分割生成合并候选后：

 - 按字典顺序将其与当前最佳答案进行比较
 - 保留较大的一个

 最终，找到全局最大值。 

### 为什么它有效

 该算法之所以有效，是因为每个阶段都是独立最优的。 

单调堆栈保证给定长度的字典顺序最大的子序列。 合并步骤保证了两个所选子序列的字典顺序最大可能的交错。 尝试每个有效的分割可以保证不会错过任何有效的构造。 

这些特性共同确保了全局最优答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxNumber(self, nums1: List[int], nums2: List[int], k: int) -> List[int]:
        
        def max_subsequence(nums: List[int], length: int) -> List[int]:
            drop = len(nums) - length
            stack = []

            for digit in nums:
                while drop and stack and stack[-1] < digit:
                    stack.pop()
                    drop -= 1

                stack.append(digit)

            return stack[:length]

        def greater(nums1: List[int], i: int,
                    nums2: List[int], j: int) -> bool:
            
            while i < len(nums1) and j < len(nums2) and nums1[i] == nums2[j]:
                i += 1
                j += 1

            if j == len(nums2):
                return True

            if i < len(nums1) and nums1[i] > nums2[j]:
                return True

            return False

        def merge(nums1: List[int], nums2: List[int]) -> List[int]:
            merged = []
            i = 0
            j = 0

            while i < len(nums1) or j < len(nums2):
                if greater(nums1, i, nums2, j):
                    merged.append(nums1[i])
                    i += 1
                else:
                    merged.append(nums2[j])
                    j += 1

            return merged

        m = len(nums1)
        n = len(nums2)

        best = []

        start = max(0, k - n)
        end = min(k, m)

        for i in range(start, end + 1):
            subseq1 = max_subsequence(nums1, i)
            subseq2 = max_subsequence(nums2, k - i)

            candidate = merge(subseq1, subseq2)

            if candidate > best:
                best = candidate

        return best
```该实现分为三个辅助函数。 

这`max_subsequence`函数使用单调递减堆栈构造指定长度的最大子序列。 变量`drop`跟踪仍然可以删除多少位数字。 

这`greater`函数执行后缀之间的字典顺序比较。 这是该解决方案最重要的部分之一。 当前缀相等时，简单地比较当前数字会产生不正确的结果。 

这`merge`函数贪婪地构建最终的合并序列。 在每一步中，它都会选择剩余后缀较大的序列。 

主循环迭代两个数组之间的每个有效分割。 对于每个分割：

 - 计算最优子序列
 - 合并它们
 - 更新最佳结果

 因为 Python 列表直接支持字典顺序比较，所以我们可以使用以下方式比较候选者：```python
candidate > best
```这使代码保持简洁和干净。 

## 解决方案```go
func maxNumber(nums1 []int, nums2 []int, k int) []int {

	maxSubsequence := func(nums []int, length int) []int {
		drop := len(nums) - length
		stack := []int{}

		for _, digit := range nums {
			for drop > 0 && len(stack) > 0 && stack[len(stack)-1] < digit {
				stack = stack[:len(stack)-1]
				drop--
			}

			stack = append(stack, digit)
		}

		return stack[:length]
	}

	var greater func([]int, int, []int, int) bool

	greater = func(nums1 []int, i int, nums2 []int, j int) bool {

		for i < len(nums1) && j < len(nums2) && nums1[i] == nums2[j] {
			i++
			j++
		}

		if j == len(nums2) {
			return true
		}

		if i < len(nums1) && nums1[i] > nums2[j] {
			return true
		}

		return false
	}

	merge := func(nums1 []int, nums2 []int) []int {
		merged := []int{}
		i := 0
		j := 0

		for i < len(nums1) || j < len(nums2) {
			if greater(nums1, i, nums2, j) {
				merged = append(merged, nums1[i])
				i++
			} else {
				merged = append(merged, nums2[j])
				j++
			}
		}

		return merged
	}

	maxLex := func(a []int, b []int) bool {
		for i := 0; i < len(a) && i < len(b); i++ {
			if a[i] != b[i] {
				return a[i] > b[i]
			}
		}
		return len(a) > len(b)
	}

	m := len(nums1)
	n := len(nums2)

	best := []int{}

	start := max(0, k-n)
	end := min(k, m)

	for i := start; i <= end; i++ {
		subseq1 := maxSubsequence(nums1, i)
		subseq2 := maxSubsequence(nums2, k-i)

		candidate := merge(subseq1, subseq2)

		if len(best) == 0 || maxLex(candidate, best) {
			best = candidate
		}
	}

	return best
}

func max(a int, b int) int {
	if a > b {
		return a
	}
	return b
}

func min(a int, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的逻辑，但需要显式辅助函数来进行字典比较，因为切片无法直接比较。 

Go 切片是数组的动态视图，因此堆栈操作是使用切片语法实现的：```go
stack = stack[:len(stack)-1]
```与 Python 不同，Go 不提供内置的切片字典比较，因此`maxLex`辅助函数手动执行逐个元素比较。 

整数溢出不是问题，因为所有数字都在`0`和`9`。

 ## 边缘情况

 ### 边缘情况 1：所有数字都来自一个数组

 考虑：```
nums1 = [9,8,7]
nums2 = [1,2,3]
k = 3
```最优解忽略`nums2`完全。 

有缺陷的实现可能会错误地强制使用两个阵列。 我们的实现正确地迭代每个有效的分割，包括从单个数组中获取所有数字。 

### 边缘情况 2：合并期间前缀相等

 考虑：```
nums1 = [6,7]
nums2 = [6,0,4]
```在第一个位置，两个数组都以`6`。 

如果我们只比较当前的数字，选择就会变得模糊，并可能产生错误的答案。 

我们的实现按字典顺序比较整个剩余的后缀，这正确地确定了：```
[6,7] > [6,0,4]
```因为`7 > 0`。 

### 边缘情况 3：重复的数字

 考虑：```
nums1 = [5,5,1]
nums2 = [5,5,2]
```重复数字很困难，因为许多本地决策看起来是相同的。 

后缀比较逻辑确保当前缀匹配时，算法继续比较更深的位置，直到找到差异。 

这保证了全局最优合并。 

### 边缘情况 4：严格递减数组

 考虑：```
nums1 = [9,8,7,6]
```单调堆栈永远不会弹出元素，因为接下来的每个数字都较小。 

有缺陷的实现可能会过度删除数字或错误处理剩余的删除计数。 

我们的实现安全地保留了最佳前缀，并且仅在必要时使用以下方法进行截断：```
stack[:length]
```这保证了正确的子序列长度。
