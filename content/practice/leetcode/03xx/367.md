[LeetCode 第 367 题](https://leetcode.com/problems/valid-perfect-square/)

 **难度：** 🟢简单
 **主题：** 数学、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的正整数是否`num`是一个完全平方数，无需使用内置平方根函数，例如`sqrt()`。 

完全平方数可以写成：$n = k^2$在哪里`k`是一个整数。 例如，`16`是一个完全平方数，因为`4 * 4 = 16`， 尽管`14`不是因为没有整数平方等于`14`。 

输入由单个正整数组成`num`。 输出应该是一个布尔值：

 - 返回`true`如果存在一个整数，其平方等于`num`- 返回`false`否则

 约束条件是：```
1 <= num <= 2^31 - 1
```这告诉我们几件重要的事情。 首先，输入规模可能非常大，可达超过 20 亿。 朴素的线性搜索在实践中可能仍然适用于较小的输入，但对于上限来说并不理想。 其次，由于在某些语言中数字的平方可能会超过 32 位整数限制，因此我们需要小心整数溢出，尤其是在 Go 中。 

一些边缘情况很重要：

 -`num = 1`，最小的有效输入，是一个完全平方数
 - 接近上限的非常大的完美正方形
 - 非常大的非完美正方形
 - 两个连续方块之间的数字，例如`15`- 计算时溢出`mid * mid`在二分查找期间

 该问题保证输入始终为正，因此我们不需要处理零或负值。 

## 方法

 ### 蛮力方法

 最简单的方法是尝试从以下位置开始的每个整数`1`并检查它的平方是否等于`num`。 

我们反复计算：$i^2$如果`i * i == num`， 然后`num`是一个完美的正方形。 如果`i * i`变得大于`num`，我们可以停下来，因为平方只会增加`i`增加。 

这种方法是正确的，因为检查了每个可能的整数平方根候选。 但是，对于较大的值，它可能会太慢。 在最坏的情况下，我们可能需要测试大约以下的数字：$\sqrt{num}$对于接近的值`2^31 - 1`，这意味着数万次迭代。 

### 最优方法，二分搜索

 关键的观察结果是平方数单调增加。 如果：$mid^2 < num$那么正确的平方根（如果存在）必须大于`mid`。 同样，如果：$mid^2 > num$那么正确的值必须小于`mid`。 

这种单调的行为使得二分搜索非常适合。 

二分查找不是一一检查每个数字，而是反复将搜索范围减半。 这大大降低了时间复杂度，从线性变为对数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(√n) | O(√n) | O(1) | O(1) | 检查每个可能的整数平方根 |
 | 最佳| O(log n) | O(1) | O(1) | 对可能的平方根范围使用二分搜索 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`。 

最小可能的平方根是`1`，以及最大可能的平方根`num`不能超过`num`本身。 所以我们从以下开始：```
left = 1
right = num
```2.继续搜索`left <= right`。 

这确保我们检查每个可能的候选范围。 
3. 计算中间值。```
mid = left + (right - left) // 2
```这种形式避免了具有固定大小整数的语言中的溢出。 
4. 计算`mid * mid`。 

这告诉我们是否`mid`太小、太大或完全正确。 
5. 比较`mid * mid`和`num`。 

- 如果相等，则返回`true`- 如果较小，则将左边界向上移动，因为我们需要更大的正方形
 - 如果更大，则将右边界向下移动，因为我们需要一个更小的正方形
 6. 如果循环结束时没有找到精确的正方形，则返回`false`。 

这意味着不存在整数平方根。

 对于正整数是严格递增的。 一旦一个正方形超过`num`，所有较大的正方形也将超过`num`。 类似地，一旦一个正方形小于`num`，所有较小的正方形也会太小。 这种有序结构保证二分搜索可以安全地消除每一步剩余搜索空间的一半。 

## Python 解决方案```python
class Solution:
    def isPerfectSquare(self, num: int) -> bool:
        left = 1
        right = num

        while left <= right:
            mid = left + (right - left) // 2
            square = mid * mid

            if square == num:
                return True
            elif square < num:
                left = mid + 1
            else:
                right = mid - 1

        return False
```实现首先初始化二分搜索边界。 搜索空间包括每个可能的整数平方根候选`1`到`num`。 

在循环内部，使用以下方法安全地计算中点：```python
mid = left + (right - left) // 2
```这可以防止其他语言中的溢出，并且被认为是最佳实践，即使 Python 整数是无界的。 

变量`square`商店`mid * mid`因此每次迭代仅执行一次乘法。 

如果`square == num`，我们立即返回`True`因为我们找到了一个其平方等于目标的整数。 

如果`square < num`， 然后`mid`太小了，所以我们通过设置丢弃左半部分：```python
left = mid + 1
```如果`square > num`， 然后`mid`太大了，所以我们通过设置丢弃右半部分：```python
right = mid - 1
```如果循环结束，不存在整数平方根，因此函数返回`False`。 

## 解决方案```go
func isPerfectSquare(num int) bool {
    left := 1
    right := num

    for left <= right {
        mid := left + (right-left)/2
        square := mid * mid

        if square == num {
            return true
        } else if square < num {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }

    return false
}
```Go 实现遵循与 Python 版本相同的二分搜索逻辑。 

Go 中的一个重要考虑因素是整数溢出。 自从`mid * mid`在某些环境中可能会溢出 32 位整数，使用`int64`在生产代码中会更安全。 然而，在 LeetCode 的 Go 环境上，`int`通常足够大来解决这个问题。 

与Python不同，Go默认不支持任意精度整数，因此溢出意识更为重要。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(log n) | 二分搜索每次迭代将搜索空间减半 |
 | 空间| O(1) | O(1) | 仅使用了几个变量 |

 时间复杂度是对数的，因为每次迭代都会删除剩余搜索间隔的一半。 从一个尺寸范围开始`n`，二分查找大约需要：$\log_2 n$迭代。 

空间复杂度是恒定的，因为无论输入大小如何，该算法仅存储固定数量的整数变量。

 ## 边缘情况

 一个重要的边缘情况是`num = 1`。 自从`1`既是最小的有效输入又是完美的平方，错误地初始化边界或循环条件的实现可能会在这里失败。 我们的二分搜索可以正确处理它，因为初始范围包括`1`，第一个中点立即与目标匹配。 

另一个重要的情况涉及与完美平方直接相邻的数字，例如`15`或者`26`。 如果二分搜索错误地更新边界，这些值很容易被错误处理。 我们的实施小心翼翼`left`和`right`每次比较后移动一个位置，确保循环正确终止，而不会跳过可能的答案。 

第三个关键边缘情况是接近最大约束的非常大的输入，特别是`2147483647`。 在某些语言中，对大中点值进行平方可能会溢出固定大小的整数。 该算法避免了不必要的操作并使用安全的中点计算。 在生产 Go 代码中，使用`int64`对于乘法将提供额外的溢出保护。
