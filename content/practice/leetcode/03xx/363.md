[LeetCode 第 363 题](https://leetcode.com/problems/max-sum-of-rectangle-no-larger-than-k/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、矩阵、前缀和、有序集

 ## 解决方案

 ## 问题理解

 该问题要求我们找到一个矩形子矩阵，其总和尽可能大，同时仍小于或等于给定整数`k`。 

矩阵中的矩形是通过选择一系列行和一系列列形成的任何连续的单元格块。 该矩形可以小到单个元素，也可以大到整个矩阵。 

我们得到：

 - 二维整数矩阵`matrix`- 一个整数`k`我们必须返回最大矩形和，使得：```
rectangle_sum <= k
```在所有有效矩形中，我们想要总和最大的一个。 

例如，考虑：```
matrix = [
  [1, 0, 1],
  [0, -2, 3]
]
k = 2
```一个有效的矩形是：```
[
  [0, 1],
  [-2, 3]
]
```其总和为：```
0 + 1 - 2 + 3 = 2
```自从`2 <= k`并且不存在更大的有效矩形和，答案是`2`。 

约束条件很重要：

 -`m, n <= 100`- 值可以为负数
 -`k`也可以是负数

 显式检查每个矩形的简单暴力方法变得极其昂贵，因为可能的矩形数量随着矩阵大小而快速增长。 

负数的存在尤其重要。 如果所有数字都是正数，我们可以使用滑动窗口技术。 负值会破坏单调的行为，因此我们需要一种更高级的方法。 

该问题还保证至少有一个矩形之和小于或等于`k`。 这意味着我们永远不需要处理“无有效答案”的情况。 

一些边缘情况很重要：

 - 单细胞矩阵
 - 所有负值
 -`k`消极的
 - 最佳矩形只有一个元素
 - 跨越整个矩阵的最佳矩形
 - 精确值的情况`k`存在，这是最好的答案

 ## 方法

 ### 蛮力方法

 最直接的解决方案是枚举矩阵中每个可能的矩形。 

矩形定义为：

 - 顶排
 - 底排
 - 左栏
 - 右栏

 这已经给出了四个嵌套循环。 

对于每个矩形，我们计算其总和并检查是否：```
sum <= k
```如果有效，我们会更新答案。 

为了加速矩形和计算，我们可以预先计算一个二维前缀和数组，这样每个矩形和就可以在恒定时间内查询。 

即使有前缀和，矩形的总数也是：```
O(m² * n²)
```由于每个矩形都是单独检查的，因此对于矩阵来说这变得太慢了`100 x 100`。 

### 最佳解决方案的关键见解

 关键的观察是我们可以将二维问题简化为一系列一维问题。 

假设我们修复两个列边界：```
left and right
```对于每一行，我们计算这些列之间的元素之和。 

这会将矩阵压缩为一维数组，其中：```
row_sums[i]
```代表行的总和`i`列之间`left`和`right`。 

现在问题变成：

 > 求最大子数组和不大于`k`。 

这是一个经典的前缀和+有序集问题。 

对于前缀和数组：```
current_prefix
```我们想要一个先前的前缀：```
previous_prefix
```这样：```
current_prefix - previous_prefix <= k
```重新排列：```
previous_prefix >= current_prefix - k
```因此，对于每个当前前缀和，我们搜索最小的先前前缀和，该前缀和至少为：```
current_prefix - k
```有序结构允许高效地进行此查询。 

这将问题从昂贵的矩形枚举转变为更快的方法。

 ## 算法演练

 ### 最优算法

 1. 判断是行小还是列小。 

由于该算法修复了边界对，因此我们希望最小化平方维数。 如果行大于列，我们将迭代列对。 否则，我们迭代行对。 
2. 修复左边界。 

从列索引开始`left`。 
3. 展开右边界。 

对于每一个`right >= left`，维护一个正在运行的数组：```
row_sums
```其中每个条目存储列之间元素的总和`left`和`right`对于该行。 
4. 将问题转化为一维最大子数组和问题。 

我们现在需要：```
max subarray sum <= k
```对于数组`row_sums`。 
5. 使用前缀和。 

当我们迭代时`row_sums`， 维持：```
current_prefix
```子数组和可以计算为：```
current_prefix - previous_prefix
```6. 使用先前前缀和的有序集合。 

我们需要最大的有效子数组和：```
current_prefix - previous_prefix <= k
```重新排列给出：```
previous_prefix >= current_prefix - k
```所以我们寻找大于或等于的最小前缀和：```
current_prefix - k
```7. 使用二分查找。 

按排序顺序存储前缀和。 Python使用`bisect_left`在排序列表上。 
8.更新答案。 

如果存在有效的先前前缀，则计算：```
current_prefix - previous_prefix
```并更新全局最大值。 
9. 将当前前缀和插入有序结构中。 

这使得它可用于未来的子阵列。 
10. 对所有边界对重复此操作。 

通过边界压缩考虑每个可能的矩形。 

### 为什么它有效

 固定两个列边界唯一地确定了矩形的水平范围。 压缩行将每个矩形转换为连续子数组问题。 

前缀和恒等式保证每个子数组和可以表示为：```
current_prefix - previous_prefix
```有序集确保我们有效地找到最佳的先前前缀，使子数组总和保持在`k`。 由于考虑了每个可能的边界对和每个可能的子数组，因此该算法总是找到最佳矩形。 

## Python 解决方案```python
from typing import List
from bisect import bisect_left, insort

class Solution:
    def maxSumSubmatrix(self, matrix: List[List[int]], k: int) -> int:
        rows = len(matrix)
        cols = len(matrix[0])

        # Ensure we iterate over the smaller dimension squared
        if rows > cols:
            matrix = list(zip(*matrix))
            rows, cols = cols, rows

        best_sum = float("-inf")

        for left in range(cols):
            row_sums = [0] * rows

            for right in range(left, cols):
                for r in range(rows):
                    row_sums[r] += matrix[r][right]

                prefix_sum = 0
                sorted_prefix = [0]

                current_best = float("-inf")

                for value in row_sums:
                    prefix_sum += value

                    target = prefix_sum - k
                    index = bisect_left(sorted_prefix, target)

                    if index < len(sorted_prefix):
                        current_best = max(
                            current_best,
                            prefix_sum - sorted_prefix[index]
                        )

                    insort(sorted_prefix, prefix_sum)

                best_sum = max(best_sum, current_best)

        return best_sum
```实现首先确定矩阵是否应该转置。 这种优化很重要，因为该算法在一维上执行二次工作。 对较小尺寸进行平方可显着减少运行时间。 

对于每对列边界，我们维护`row_sums`，它存储当前左列和右列之间的压缩行值。 

那么问题就变成了找到不大于的最大子数组和`k`。 

前缀和技术将子数组和转换为前缀和之间的差。 排序的前缀结构允许有效地二进制搜索最佳候选前缀。`bisect_left`查找大于或等于的最小前缀和：```python
prefix_sum - k
```这保证了结果子数组的总和不超过`k`。 

最后，每个有效的候选人都会更新全局答案。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func maxSumSubmatrix(matrix [][]int, k int) int {
	rows := len(matrix)
	cols := len(matrix[0])

	// Transpose if rows > cols
	if rows > cols {
		transposed := make([][]int, cols)

		for c := 0; c < cols; c++ {
			transposed[c] = make([]int, rows)

			for r := 0; r < rows; r++ {
				transposed[c][r] = matrix[r][c]
			}
		}

		matrix = transposed
		rows, cols = cols, rows
	}

	bestSum := math.MinInt32

	for left := 0; left < cols; left++ {
		rowSums := make([]int, rows)

		for right := left; right < cols; right++ {

			for r := 0; r < rows; r++ {
				rowSums[r] += matrix[r][right]
			}

			prefixSum := 0
			sortedPrefix := []int{0}

			currentBest := math.MinInt32

			for _, value := range rowSums {
				prefixSum += value

				target := prefixSum - k

				index := sort.SearchInts(sortedPrefix, target)

				if index < len(sortedPrefix) {
					candidate := prefixSum - sortedPrefix[index]

					if candidate > currentBest {
						currentBest = candidate
					}
				}

				insertIndex := sort.SearchInts(sortedPrefix, prefixSum)

				sortedPrefix = append(sortedPrefix, 0)
				copy(sortedPrefix[insertIndex+1:], sortedPrefix[insertIndex:])
				sortedPrefix[insertIndex] = prefixSum
			}

			if currentBest > bestSum {
				bestSum = currentBest
			}
		}
	}

	return bestSum
}
```Go 版本遵循与 Python 解决方案相同的算法结构。 

由于Go在标准库中没有提供内置的平衡树或有序多重集，因此我们手动维护排序切片。`sort.SearchInts`执行二分搜索来定位插入点和有效的前缀候选。 

插入已排序的切片需要使用手动移动元素`copy`。 

Go 整数足以解决这个问题，因为约束将总和安全地保持在 32 位整数范围内。

 ## 边缘情况

 ### 所有负数

 仅包含负值的矩阵很容易破坏假设较大矩形总是产生较大总和的算法。 

例如：```
[
  [-3, -2],
  [-5, -1]
]
```和：```
k = -2
```最好的答案是`-2`，而不是更大的矩形。 

前缀和方法可以自然地处理这个问题，因为它会计算每个可能的子数组和，而不管符号如何。 

### 单元素矩阵

 当矩阵仅包含一个单元格时，该单元格本身就是唯一可能的矩形。 

例子：```
matrix = [[5]]
k = 5
```该算法仍然有效，因为压缩后的数组长度变为一，并且前缀逻辑正确识别了有效子数组。 

### 与 k 精确匹配

 如果矩形和等于`k`，这自动成为最佳答案，因为不存在更大的有效总和。 

例子：```
matrix = [
  [2, 1]
]
k = 3
```该算法在前缀和评估期间自然会检测到这一点。 无需特殊处理。 

### 具有负值的大矩形

 负数可能会使更大的矩形出乎意料地成为最佳选择。 

例如：```
[
  [5, -4],
  [-3, 2]
]
```天真的贪婪策略可能会失败，因为添加单元格会减少总和。 

前缀和公式保证所有可能的连续范围都得到正确评估，包括那些负值提高可行性的范围`k`。
