 # LeetCode 318 - 字长的最大乘积

 ## 问题理解

 该问题给了我们一系列小写英语单词。 我们需要找到两个不同的单词，使它们不共享任何公共字母，然后返回它们长度的最大可能乘积。 

更正式地说，对于每对索引`(i, j)`在哪里`i != j`，我们检查是否`words[i]`和`words[j]`包含任何重叠字符。 如果他们不共享任何字母，我们计算：$$\text{len(words[i])} \times \text{len(words[j])}$$在所有有效对中，我们返回最大的乘积。 

例如，如果单词是：```
["abcw","baz","foo","bar","xtfn","abcdef"]
```这对`"abcw"`和`"xtfn"`没有共同的性格。 它们的长度是`4`和`4`，所以产品是：```
4 * 4 = 16
```这是最大可能的答案。 

约束条件很重要：

 - 最多可以有`1000`字。 
- 每个单词的长度可达`1000`。 
- 单词仅包含小写英文字母。 

比较每对字符的简单方法可能会变得昂贵，因为最多有：$$1000 \times 1000 = 10^6$$单词对，每次比较都可能涉及扫描许多字符。 

关键的观察结果是，只有`26`小写英文字母。 这使得位操作极其有效。 

一些边缘情况很重要：

 - 所有单词可能至少有一个共同的字符，产生答案`0`。 
- 非常短的单词（例如单个字符）仍然可以形成最大乘积。 
- 同一个单词内的重复字母应该不重要。 例如，`"aaaa"`仍然只包含这封信`'a'`。 
- 具有重复字符的大单词仍应得到有效处理。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每对单词并确定它们是否具有共同的字符。 

对于每对：

 1. 将一个或两个单词转换为字符集。 
2. 检查集合是否相交。 
3. 如果它们不相交，则计算长度的乘积。 
4. 跟踪找到的最大产品。 

这种方法是正确的，因为它显式地检查每个可能的对并验证该对是否满足条件。 

然而，它的效率很低。 有`O(n^2)`单词对，并且检查字符重叠可能会花费高达`O(L)`在哪里`L`是字长。 对于长单词和很多对，这会变得很慢。 

### 使用位操作的最佳方法

 重要的一点是，每个单词只包含小写英文字母，这意味着只有 26 个可能的字符。 

我们可以使用 26 位整数掩码来表示单词中的字符集。 

例如：

 - 位`0`代表`'a'`- 少量`1`代表`'b'`- 少量`2`代表`'c'`- 等等

 如果一个单词包含一个字母，我们将相应的位设置为`1`。 

例子：```
"abc"
```变成：```
111
```前三位为二进制。 

现在考虑两个词：

 - 如果他们没有共同的字母，他们的面具将不会重叠`1`位。 
- 我们可以使用按位与来检查：```
mask1 & mask2 == 0
```这使得重叠检查变得非常快，从而大大降低了字符比较成本。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × L) | O(L) | 比较每一对并直接检查字符重叠 |
 | 最佳| O(n × L + n²) | O(n × L + n²) | O(n) | 使用位掩码进行恒定时间重叠检查 |

 这里：

-`n`是单词数
 -`L`是平均单词长度

 ## 算法演练

 ### 第 1 步：为每个单词创建一个位掩码

 对于每个单词，构建一个整数掩码来表示单词中出现的字母。 

从以下开始：```
mask = 0
```对于每个字符：```
bit = ord(char) - ord('a')
mask |= (1 << bit)
```这会设置适当的位。 

例如：```
"abc"
```产生：```
000...0111
```### 步骤 2：存储字长

 与每个掩码一起存储单词的长度。 

这可以防止重复调用`len()`在配对比较期间。 

### 步骤 3：比较每对单词

 使用两个嵌套循环：```
for i in range(n):
    for j in range(i + 1, n):
```这会检查每个唯一的对一次。 

### 步骤 4：检查共享角色

 对于一副面具：```
if masks[i] & masks[j] == 0:
```那么这些单词不共享字母。 

为什么这有效？ 

- 共享字母会产生重叠`1`位。 
- 按位与仅保留重叠位。 
- 结果`0`意味着不存在重叠。 

### 步骤 5：计算乘积

 如果该对有效：```
product = lengths[i] * lengths[j]
```如有必要，请更新最大答案。 

### 步骤 6：返回最大乘积

 检查完所有对后，返回存储的最大值。 

### 为什么它有效

 每个单词掩码准确地代表该单词中存在的字母集。 当且仅当两个单词的掩码没有重叠位时，它们不共享公共字符。 该算法会检查每个可能的单词对，因此不会错过任何有效的候选单词。 因为每当找到更好的有效对时就会更新最大乘积，因此最终答案保证是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProduct(self, words: List[str]) -> int:
        n = len(words)

        masks = [0] * n
        lengths = [0] * n

        # Build bitmask for each word
        for i, word in enumerate(words):
            mask = 0

            for char in word:
                bit = ord(char) - ord('a')
                mask |= (1 << bit)

            masks[i] = mask
            lengths[i] = len(word)

        max_product = 0

        # Compare every pair
        for i in range(n):
            for j in range(i + 1, n):
                # No common letters
                if masks[i] & masks[j] == 0:
                    product = lengths[i] * lengths[j]
                    max_product = max(max_product, product)

        return max_product
```实现首先分配两个数组：

 -`masks`，它存储每个单词的位表示
 -`lengths`，它存储每个单词的长度

 对于每个单词，我们迭代其字符并在掩码中设置相应的位。 表达式：```python
mask |= (1 << bit)
```确保角色的位置变为`1`。 

预处理后，我们使用嵌套循环比较所有单词对。 

关键的优化是：```python
masks[i] & masks[j] == 0
```这会在恒定时间内执行重叠检查，而不是重复扫描字符。 

每当找到有效的对时，我们就计算长度的乘积并更新`max_product`。 

最后，我们返回发现的最大的产品。 

## 解决方案```go
func maxProduct(words []string) int {
	n := len(words)

	masks := make([]int, n)
	lengths := make([]int, n)

	// Build bitmask for each word
	for i, word := range words {
		mask := 0

		for _, ch := range word {
			bit := ch - 'a'
			mask |= (1 << bit)
		}

		masks[i] = mask
		lengths[i] = len(word)
	}

	maxProduct := 0

	// Compare every pair
	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ {
			// No common letters
			if masks[i]&masks[j] == 0 {
				product := lengths[i] * lengths[j]

				if product > maxProduct {
					maxProduct = product
				}
			}
		}
	}

	return maxProduct
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个区别是 Go 使用以下方式迭代字符串：```go
for _, ch := range word
```它返回 Unicode 符文。 由于输入仅包含小写英文字母，因此这是完全安全的。 

Go 也没有提供内置的`max()`整数函数，因此代码在更新时使用标准条件比较`maxProduct`。 

Go 中的整数类型足够大来解决这个问题，因为最大乘积是：```go
1000 * 1000 = 1,000,000
```它很容易适合 32 位整数。

 ## 边缘情况

 ### 所有单词都有一个共同的字符

 一个常见的错误是假设至少存在一对有效的。 考虑：```
["a", "aa", "aaa"]
```每个字都包含`'a'`，所以每一对都重叠。 该实现正确地处理了这个问题，因为`max_product`开始于`0`并且仅在找到有效对时更新。 

### 具有重复字符的单词

 单词可能包含重复的字母：```
["aaaa", "bbbb"]
```幼稚的实现可能会不必要地重复处理重复项。 位掩码方法自然避免了这个问题，因为多次设置相同的位没有效果。 

例如：```
mask |= (1 << bit)
```只需将位设置为`1`。 

### 非常大的单词

 单词的长度可达`1000`。 反复比较字符对之间的字符可能会变得昂贵。 

优化的解决方案通过将每个单词预处理为紧凑的整数表示来避免此问题。 预处理后，无论字长如何，重叠检查都变成恒定时间的按位操作。
