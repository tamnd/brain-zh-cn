[LeetCode 问题 331](https://leetcode.com/problems/verify-preorder-serialization-of-a-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、树、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个表示二叉树的前序序列化的字符串。 每个值都用逗号分隔。 普通整数代表真实的树节点，而字符`'#'`代表一个空指针。 

在前序遍历中，我们总是按以下顺序访问节点：

 1.当前节点
 2. 左子树
 3. 右子树

 例如，序列化：```
9,3,4,#,#,1,#,#,2,#,6,#,#
```方法：

-`9`是根
 -`3`是的左孩子`9`-`4`是的左孩子`3`-`#,#`方法`4`没有孩子
 -`1`成为的右孩子`3`- 等等

 任务是确定给定的序列化是否可以表示有效的二叉树，而无需实际重建树。 

约束条件很重要：

 - 输入长度可达`10^4`- 值已经保证在语法上有效
 - 我们被明确告知不要重建树

 这些限制强烈建议我们应该在一次传递中直接处理字符串。 

一些边缘情况尤其重要：

 - 单一`"#"`是一棵有效树，代表一棵空树。 
-`"1,#"`无效，因为根节点还需要一个子节点。 
-`"9,#,#,1"`无效，因为在额外节点出现之前树已经完整。 
- 完成树后的额外节点必须立即使序列化无效。 
- 仅空结构仍必须遵守先序结构规则。 

尝试部分重建树的简单实现可能会变得不必要的复杂并浪费内存。 

## 方法

 ### 蛮力方法

 一种直接的方法是在读取前序遍历的同时重建二叉树。 

我们可以递归地处理令牌：

 - 如果当前令牌是`'#'`， 返回`None`- 否则创建一个节点
 - 递归构建左子树
 - 递归构建右子树

 构建后，仅当所有令牌都被消耗一次时，序列化才有效。 

这是有效的，因为当包含空标记时，前序遍历唯一地确定树结构。 

然而，这种方法违反了问题的精神，因为我们被明确告知不要重建树。 它还使用不必要的内存进行节点分配和递归。 

### 最佳方法，槽计数

 关键的观察是二叉树中的每个节点都占用一个传入连接槽。 

最初，根需要一个插槽。 

然后：

 - 非空节点消耗一个槽并创建两个新槽
 - 空节点消耗一个槽并创建零个新槽

 这导致了一个非常优雅的验证规则。 

我们从一个可用的插槽开始。 

对于每个令牌：

 1. 消耗1个slot
 2.如果slots变为负数，则序列化无效
 3. 如果令牌不是`'#'`, 添加两个新插槽

 最后：

 - 仅当所有槽都完全用完时序列化才有效
 - 因此，最终的槽数必须为零

 该解决方案完全避免了树的构建并一次性处理输入。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 递归地重建树 |
 | 最佳 | O(n) | O(1) | O(1) | 使用槽计数而不构建树 |

 ## 算法演练

 ### 使用时隙计数的最佳算法

 1. 将输入字符串用逗号分割，得到所有的前序标记。 

每个标记代表一个真实节点或空节点。 
2. 初始化一个名为`slots`到`1`。 

一棵二叉树根总是需要一个可用的父槽。 
3. 按顺序迭代每个标记。 

在处理令牌之前，请消耗一个槽，因为每个节点（包括空节点）都必须在树中占据一个位置。 
4. 如果`slots`任意点变为负值，返回`False`。 

这意味着我们遇到的节点数量超出了树结构所能支持的数量。 
5. 如果当前token不是`'#'`，添加两个新插槽。 

真实节点为左子节点和右子节点创建空间。 
6. 继续处理，直到消耗完所有令牌。 
7.处理完所有token后，检查是否`slots == 0`。 

如果剩余零个槽，则序列化完全使用正确数量的子位置。 
8. 返回该检查的结果。 

### 为什么它有效

 该算法保持一个不变量：

 -`slots`始终表示部分处理的树中仍然可用的子位置数。 

每个节点必须恰好占用一个插槽。 然后真实节点生成两个额外的子位置。 

有效的预购序列化必须准确消耗所有可用位置。 如果槽变为负数，则遍历尝试将节点放置在不存在父位置的位置。 如果最后插槽仍然为正，则永远不会提供一些预期的孩子。 

由于前序遍历以与树结构扩展相同的顺序处理节点，因此槽计算完美地捕获了结构有效性。 

## Python 解决方案```python
class Solution:
    def isValidSerialization(self, preorder: str) -> bool:
        slots = 1

        for token in preorder.split(","):
            slots -= 1

            if slots < 0:
                return False

            if token != "#":
                slots += 2

        return slots == 0
```其实现直接遵循时隙计数算法。 

我们从根节点的一个可用槽开始。 然后我们迭代预序序列化中的每个令牌。 

每个令牌消耗一个槽，因为每个节点都必须占据树中的一个位置。 如果槽计数变为负数，我们立即知道该结构无效，因为没有可用的父位置。 

每当令牌代表真实节点而不是`'#'`，我们为其子项添加两个新插槽。 

最后，我们验证所有插槽是否都已准确消耗。 有效的树序列化不能留下未使用的子位置。 

这种实现很简洁，因为槽计数观察完全消除了对堆栈、递归或树构造的需要。 

## 解决方案```go
package main

import "strings"

func isValidSerialization(preorder string) bool {
    slots := 1
    tokens := strings.Split(preorder, ",")

    for _, token := range tokens {
        slots--

        if slots < 0 {
            return false
        }

        if token != "#" {
            slots += 2
        }
    }

    return slots == 0
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于 Go 使用`strings.Split`对输入字符串进行标记。 槽逻辑保持相同。 

由于问题约束很小并且节点值有限，因此不存在整数溢出问题。 我们也不需要额外的数据结构，因为槽计数方法使用恒定的额外内存。

 ## 边缘情况

 一种重要的边缘情况是空树序列化：```
"#"
```这是有效的，因为空根代表空二叉树。 幼稚的实现可能会错误地拒绝它，因为没有实际的节点值。 槽计数方法可以自然地处理这个问题。 我们从一个插槽开始，`'#'`消耗它，并且我们以恰好零个插槽结束。 

当树在处理所有标记之前完成时，会发生另一种关键的边缘情况：```
"9,#,#,1"
```加工后`"9,#,#"`，槽数变为零，这意味着整个树已经完成。 额外的`"1"`尝试消耗不存在的槽，导致计数变为负数。 该算法立即拒绝序列化。 

第三个棘手的边缘情况是不完整的树：```
"1,#"
```根节点仍需要一个子节点，但输入结束得太早。 最终的槽计数仍然为正，表明未解决的子位置。 执行正确返回`False`因为有效的二叉树必须准确地消耗每个槽。 

另一个微妙的情况涉及连续的空标记：```
"#,#"
```第一个`'#'`已经完成了整个树。 第二个`'#'`尝试消耗额外的槽，使槽计数为负。 这可以防止无效的序列化被漏掉。
