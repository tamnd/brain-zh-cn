[LeetCode 第 377 题](https://leetcode.com/problems/combination-sum-iv/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个不同的正整数数组，称为`nums`和一个名为的目标整数`target`。 我们必须确定有多少个不同的有序数字序列`nums`精确地求和到`target`。 

关键细节是顺序很重要。 这使得该问题与经典的组合和问题非常不同，在经典的组合和问题中，无论顺序如何，组合都被认为是相同的。 

例如，如果`nums = [1,2,3]`和`target = 4`，序列`(1,2,1)`和`(2,1,1)`由于顺序不同，所以单独计算。 

中的每个数字`nums`可以无限次使用。 我们不是选择子集，而是构建总数等于目标的序列。 

输入约束很重要：

 -`nums.length <= 200`-`target <= 1000`- 所有数字均为正数
 - 所有数字都是不同的

 积极性约束尤其重要，因为它保证了实现目标的进展。 每添加一个数字，剩余的总和就会减少。 这可以防止无限递归循环。 

目标大小最多为`1000`强烈表明动态规划是可行的。 一个解决方案大致为`O(target * len(nums))`复杂性足够高效。 

一些边缘情况很重要：

 - 如果没有组合可以形成目标，则答案应该是`0`- 如果数字大于当前剩余目标，则无法贡献
 - 由于顺序很重要，我们必须单独计算排列
 - 因为数字是正数，所以递归自然终止
 - 结果适合 32 位整数，因此在 Python 中溢出不是问题，尽管在 Go 中了解它仍然是件好事

 ## 方法

 ### 蛮力方法

 一种简单的方法是在每一步递归地尝试每个可能的数字。 

对于剩余目标`remain`，我们尝试减去中的每个值`nums`。 每个递归调用都会探索序列的所有可能的延续。 

例如：

 - 从目标开始`4`- 选择`1`, 递归`3`- 选择`2`, 递归`2`- 选择`3`, 递归`1`每当剩余目标变为`0`，我们找到一个有效的序列并返回`1`。 

这种强力方法是正确的，因为它探索了每一个可能的有序序列。 然而，它执行了大量的重复工作。 

例如，形成目标的方式数量`3`可以从不同的递归路径计算多次。 随着目标的增长，递归树呈指数级扩展。 

这会导致性能极差。 

### 优化的关键见解

 关键的观察是该问题包含重叠的子问题。 

形成剩余目标的方式数`x`总是一样的，无论我们如何达到`x`。 

例如：

 - 形成方式`3`- 形成方式`2`- 形成方式`1`这些值在强力解决方案中被重复重新计算。 

这使得该问题非常适合动态规划。 

我们定义：`dp[i] = number of ordered combinations that sum to i`计算`dp[i]`，我们尝试其中的每个数字`nums`：

- 如果`num <= i`- 然后各种方式形成`i - num`可以通过附加来扩展`num`所以：`dp[i] += dp[i - num]`这种自下而上的动态编程方法消除了重复计算，并有效地从较小的子问题中构建答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k^目标) | O（目标）| 探索每一个递归序列，指数增长|
 | 最优动态规划| O(目标 * n) | O（目标）| 重用先前计算的子问题 |

 这里，`n`是`len(nums)`和`k`代表分支因子。 

## 算法演练

 1.创建一个大小为DP的数组`target + 1`。 

我们使用`dp[i]`存储总和为的有序组合的数量`i`。 
2. 初始化基本情况。 

放`dp[0] = 1`。 

这代表空序列。 只有一种方法可以创建总和`0`，什么都不选择。 
3. 迭代所有目标值`1`到`target`。 

我们从较小的金额到较大的金额逐步构建解决方案。 
4. 对于每个目标值`current`，尝试中的每个数字`nums`。 

如果`num <= current`， 然后`num`可以是序列的最后一个元素，总和为`current`。 
5.添加形成数量的方式`current - num`。 

形成的每个有效序列`current - num`可以扩展为`num`。 

所以：`dp[current] += dp[current - num]`6. 继续，直到填满整个 DP 表。 

当我们计算时`dp[target]`，所有较小的状态都是已知的。 
7. 返回`dp[target]`。 

这包含有序组合的总数。 

### 为什么它有效

 该算法之所以有效，是因为每个有序序列都以 sum 结尾`current`必须以某个数字结尾`num`从`nums`。 

如果我们删除最后一个数字，则剩余序列的总和必须为`current - num`。 

自从`dp[current - num]`已经存储了形成较小总和的方法数量，将所有这些可能性添加到每个有效的`num`对每个有序序列精确计数一次。 

自下而上的排序保证了计算时`dp[current]`，所有所需的较小状态都已可用。 

## Python 解决方案```python
from typing import List

class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        dp = [0] * (target + 1)
        dp[0] = 1

        for current in range(1, target + 1):
            for num in nums:
                if num <= current:
                    dp[current] += dp[current - num]

        return dp[target]
```该实现首先创建一个用零初始化的 DP 数组。 每个索引代表一个目标总和，该索引处的值代表产生该总和的有序组合的数量。 

基本情况`dp[0] = 1`是必不可少的。 它代表了一种使用空序列产生和为零的有效方法。 

外循环迭代自`1`通过`target`，逐步构建解决方案。 对于每个当前目标值，内循环检查中的每个数字`nums`。 

每当`num <= current`，算法添加`dp[current - num]`进入`dp[current]`。 这对应于通过附加来扩展形成较小总和的所有序列`num`。 

最后该方法返回`dp[target]`，其中包含有序序列的总数。 

## 解决方案```go
func combinationSum4(nums []int, target int) int {
	dp := make([]int, target+1)
	dp[0] = 1

	for current := 1; current <= target; current++ {
		for _, num := range nums {
			if num <= current {
				dp[current] += dp[current-num]
			}
		}
	}

	return dp[target]
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

DP数组是使用长度为slice的切片创建的`target + 1`。 Go 整数就足够了，因为问题保证答案适合 32 位整数。 

与 Python 不同，Go 没有针对此用例的动态列表大小调整，因此我们使用预先显式分配切片大小`make`。 

迭代结构和递归关系保持相同。

 ## 边缘情况

 当没有组合可以形成目标时，就会出现一种重要的边缘情况。 例如，`nums = [9]`和`target = 3`。 幼稚的递归实现可能会继续不必要地探索无用的分支。 在 DP 解决方案中，当不存在有效转换时，状态简单地保持为零，因此正确的答案变为`0`。 

另一种重要的情况是数组仅包含一个数字。 例如，`nums = [1]`和`target = 5`。 恰好有一个序列：重复五次`1`。 该实现自然地处理这个问题，因为每个状态仅依赖于前一个状态。 

一个微妙的边缘情况涉及排序。 为了`nums = [1,2]`和`target = 3`，序列`(1,2)`和`(2,1)`两者必须分开计算。 这就是为什么外循环首先迭代目标值，然后迭代数字。 反转循环顺序会计算无序组合。 

最后一个重要的边缘情况与大目标值有关。 自从`target`可以大到`1000`，指数递归解决方案将会超时。 DP 实现通过存储中间结果来避免重复工作，即使对于大量输入也能确保高效执行。 

关于负数的后续问题也很重要。 如果不受限制地允许负值，则无限组合成为可能。 例如，与`[1, -1]`和目标`1`，我们可以无休止地附加`(1, -1)`对。 为了安全地允许负数，我们需要额外的约束，例如限制最大序列长度。
