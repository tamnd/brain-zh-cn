 ## 解决方案

 ## 问题理解

 该问题为数组定义了一个称为旋转函数的特殊值。 给定一个整数数组`nums`长度`n`，我们顺时针旋转数组`k`创建新数组的位置`arrk`。 对于每一个可能的旋转`0`到`n - 1`，我们计算：$$F(k) = 0 \cdot arr_k[0] + 1 \cdot arr_k[1] + 2 \cdot arr_k[2] + \dots + (n-1) \cdot arr_k[n-1]$$任务是返回所有可能的旋转函数中的最大值。 

顺时针旋转意味着最后一个元素移到前面。 例如，如果：```
nums = [4,3,2,6]
```然后：```
Rotation 1 -> [6,4,3,2]
Rotation 2 -> [2,6,4,3]
Rotation 3 -> [3,2,6,4]
```对于每个旋转版本，我们计算加权和，其中权重等于索引。 

约束很重要，因为它们决定了哪种解决方案是可行的：

 - 数组长度可以大到`10^5`- 每个元素都介于`-100`和`100`- 结果始终适合 32 位整数

 安`O(n^2)`解决方案一开始可能看起来很简单，但是`n = 100000`，大约需要`10^10`操作，这太慢了。 这强烈表明我们需要一种线性时间或近线性时间的方法。 

有几个重要的边缘情况需要考虑：

 - 单元素数组，其中每次旋转都是相同的，答案必须是`0`- 包含负数的数组，其中最大旋转函数可能与视觉上最大的排列不对应
 - 具有所有相同值的数组，其中每次旋转都会产生相同的结果
 - 大型数组，每次旋转都从头开始重新计算旋转函数变得非常昂贵

 该问题保证数组非空，因此我们永远不需要处理空输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是显式生成每个旋转并独立计算其旋转函数。 

对于每次旋转`k`：

 1. 将阵列顺时针旋转`k`2. 计算加权和
 3. 跟踪遇到的最大值

 这种方法是正确的，因为它直接遵循问题定义。 由于该问题要求所有旋转函数中的最大值，因此评估每个可能的旋转可以保证正确性。 

然而，性能较差。 有`n`旋转，计算每个旋转函数需要`O(n)`工作。 这产生了整体复杂性`O(n^2)`。 

和`n = 100000`，这种方法太慢了。 

### 最佳方法

 关键的观察是连续旋转函数在数学上是相关的。 

认为：$$F(0) = 0 \cdot nums[0] + 1 \cdot nums[1] + \dots + (n-1) \cdot nums[n-1]$$当我们顺时针旋转数组一次时，最后一个元素会移到前面。 我们可以从前一个值导出下一个值，而不是从头开始重新计算整个加权和。 

让：

-`totalSum = sum(nums)`-`F(k)`是当前旋转值

 那么递推关系为：$$F(k) = F(k-1) + totalSum - n \cdot nums[n-k]$$该公式之所以有效，是因为旋转后：

 - 每个元素的索引增加`1`- 除了移动到前面的元素，其贡献变为`0`使用这种递归，可以在恒定时间内计算每个新的旋转值。 

这将总复杂度降低到`O(n)`。

 ## 算法演练

 1. 计算数组的总和。 

我们存储：```
totalSum = sum(nums)
```该值在递归公式中重复使用，因此预先计算它可以避免多余的工作。 
2. 计算初始旋转函数`F(0)`。 

我们计算：$$F(0) = \sum_{i=0}^{n-1} i \cdot nums[i]$$这将作为所有后续计算的起点。 
3. 初始化答案。 

自从`F(0)`是一个有效的旋转值，我们从以下开始：```
maxValue = F(0)
```4. 使用递归关系生成后续旋转值。 

对于每次旋转，从`1`到`n - 1`，计算：$$F(k) = F(k-1) + totalSum - n \cdot nums[n-k]$$这里：

-`F(k-1)`是之前的旋转值
 -`totalSum`考虑向前移动一个位置的每个元素
 -`nums[n-k]`是从末尾移动到前面的元素，其权重贡献变化显着
 5. 每次计算后更新最大值。 

由于每个旋转函数仅被考虑一次，因此遇到的最大值就是最终答案。 

### 为什么它有效

 递推关系正确地模拟了顺时针旋转后加权和如何变化。 

旋转时：

 - 除一个元素外的每个元素都会向前移动一个索引，通过其值增加其贡献
 - 最后一个元素环绕到索引`0`，失去了之前的贡献`(n - 1) * value`递推公式精确地捕捉了这种净变化，使得每个旋转函数都可以在恒定时间内从前一个旋转函数导出。 

因为我们对每个可能的旋转只评估一次，所以算法总是返回正确的最大值。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxRotateFunction(self, nums: List[int]) -> int:
        n = len(nums)

        total_sum = sum(nums)

        current_value = 0
        for index, value in enumerate(nums):
            current_value += index * value

        max_value = current_value

        for rotation in range(1, n):
            current_value = (
                current_value
                + total_sum
                - n * nums[n - rotation]
            )

            max_value = max(max_value, current_value)

        return max_value
```实现首先计算数组长度和总和。 每次轮换更新时都会重复使用总和，因此计算一次可以提高效率。 

接下来，代码计算`F(0)`通过迭代数组`enumerate`。 每个元素都贡献`index * value`到加权和。 

变量`max_value`存储迄今为止看到的最佳旋转函数值。 

然后主循环迭代所有剩余的旋转。 递归关系不是重建旋转的数组，而是在恒定时间内更新当前的旋转值。 

表达式：```python
current_value + total_sum - n * nums[n - rotation]
```实现从数学转换`F(k-1)`到`F(k)`。 

最后，该算法返回所有旋转中找到的最大值。 

## 解决方案```go
func maxRotateFunction(nums []int) int {
    n := len(nums)

    totalSum := 0
    currentValue := 0

    for i, value := range nums {
        totalSum += value
        currentValue += i * value
    }

    maxValue := currentValue

    for rotation := 1; rotation < n; rotation++ {
        currentValue = currentValue +
            totalSum -
            n*nums[n-rotation]

        if currentValue > maxValue {
            maxValue = currentValue
        }
    }

    return maxValue
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一些特定于 Go 的细节值得注意：

 - Go 使用显式整数变量而不是 Python 的任意精度整数
 - 该问题保证结果符合 32 位整数，因此标准`int`使用安全
 - 直接使用切片，不执行数组复制或旋转
 - 递归关系允许所有计算保持在恒定的额外空间中

 ## 边缘情况

 单元素数组是最重要的边缘情况之一。 由于旋转单个元素不会改变任何内容，因此每个旋转函数值必然是`0`。 有缺陷的实现可能会错误地尝试额外的轮换或错误地处理索引逻辑。 当前的实现自然地处理了这个问题，因为旋转循环永远不会在以下情况下执行：`n == 1`。 

包含负数的数组也可能导致微妙的问题。 一些解决方案错误地假设最大化旋转函数意味着将更大的数字放置在更大的索引处。 负值会使这种直觉无效，因为将负数移动到权重较高的位置会降低总分。 基于递归的解决方案避免了此类假设并准确评估每次旋转。 

所有元素都相同的数组形成了另一种有用的边缘情况。 在这种情况下，每次旋转都会产生相同的数组结构，因此所有旋转函数值都相等。 一些不正确的实现可能会由于递归公式中的索引错误而意外地引入漂移。 由于此实现以数学方式从前一个旋转导出每个旋转，因此所有计算值保持一致。 

非常大的阵列也很关键。 和`n = 100000`，暴力重新计算变得不可行。 优化的解决方案完全避免了构造旋转数组，并在恒定时间内计算每个新的旋转值，确保算法即使在最大输入大小下也保持高效。
