 # LeetCode 320，通用缩写

 ## 问题理解

 这个问题要求我们生成给定单词的所有可能的广义缩写。 

通过用其计数替换字符串中的某些字符来创建通用缩写，同时保留其余字符的顺序。 重要的限制是缩写部分必须不重叠且不相邻。 实际上，这意味着必须将连续的缩写字符合并为一个数字，而不是生成单独的相邻数字。 

例如，考虑这个词`"word"`:

 -`"w1r1"`方法：

-`"o"`缩写为`"1"`-`"d"`缩写为`"1"`-`"2rd"`方法：

-`"wo"`缩写为`"2"`-`"4"`意思是：

 - 整个单词被缩写

 然而，`"11rd"`无效，因为两个相邻的缩写部分应该合并到`"2rd"`。 

输入是单个字符串`word`，仅包含小写英文字母。 单词的长度最多为 15，这个长度足够小，指数解是可以接受的。 

输出应以任何顺序包含每个有效的通用缩写。 

约束条件很重要：

 -`1 <= word.length <= 15`- 因为每个角色都可以：

 - 保持角色身份
 - 或成为缩写的一部分
 - 可能结果的总数为`2^n`。 

为了`n = 15`， 这是：```
2^15 = 32768
```这对于使用回溯或位操作进行完整枚举来说足够小。 

一些边缘情况很重要：

 - 一个单字词，例如`"a"`- 每个字符都缩写的单词
 - 没有缩写字符的单词
 - 连续的缩写字符，必须折叠成一个数字
 - 正确处理字符串末尾的缩写计数

 当将挂起的缩写计数刷新到输出字符串时，幼稚的实现通常会失败。 

## 方法

 ### 蛮力方法

 蛮力的想法是考虑每个字符子集并决定每个字符是否：

 - 保留为字面字符
 - 或缩写

 由于每个角色都有两个选择，因此有`2^n`总组合。 

实现此目的的一种方法是使用位掩码：

 -`0`意味着保持角色
 -`1`表示缩写字符

 对于每个掩码，我们构建相应的缩写字符串。 

例如，对于`"word"`:```
mask = 1010
```意思是：

 - 缩写`'w'`- 保持`'o'`- 缩写`'r'`- 保持`'d'`变成：```
1o1d
```这种方法是正确的，因为每个有效缩写都对应于一个二元决策模式。 

然而，暴力方法从头开始重复重建字符串，并不能自然地表达问题的递归结构。 推断正确性和未决缩写计数也变得更加困难。 

### 最优回溯方法

 关键的观察是，在每个位置我们只有两个决定：

 1. 保留当前角色
 2. 缩写当前字符

 回溯是理想的选择，因为：

 - 我们递归地探索所有组合
 - 我们有效地维护当前的缩写
 - 我们自然地使用运行计数来合并连续的缩写字符

 我们没有立即附加数字，而是维护：

 - 当前索引
 - 当前缩写字符串
 - 当前连续缩写字符的计数

 当我们决定保留一个角色时：

 - 我们首先附加任何待处理的计数
 - 然后附加字符本身

 当我们缩写一个字符时：

 - 我们只是增加运行计数

 这会自动避免无效的相邻数字。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × n) | O(2^n × n) | O(n) | 枚举所有位掩码并手动构建字符串 |
 | 最佳| O(2^n × n) | O(2^n × n) | O(n) | 回溯自然且干净地生成缩写 |

 尽管两种方法具有相同的渐近复杂度，但回溯解决方案更清晰、更容易推理并且在实践中更高效。 

## 算法演练

 1. 初始化一个空的结果列表。 
2.定义一个递归回溯函数，有四个参数：

 -`index`, 单词中的当前位置
 -`current`, 当前正在构建的缩写字符串
 -`count`, 连续缩写字符的数量
 -`result`，最终输出列表
 3. 在每次递归调用时，检查是否到达单词末尾。 

- 如果是：

 - 附加任何待处理的缩写计数
 - 将完整的缩写添加到结果列表中
 - 返回
 4. 对于当前角色，探索两种选择。 
5.第一选择，缩写字符。 

- 暂时不要添加任何内容。 
- 增量`count`。 
- 移至下一个索引。 
6.第二选择，保持性格。 

- 如果`count > 0`，首先将计数附加到字符串中。 
- 附加实际字符。 
- 重置`count`到`0`。 
- 移至下一个索引。 
7. 继续递归，直到探索完所有组合。 
8. 递归完成后返回结果列表。 

### 为什么它有效

 该算法保持了一个关键的不变量：

 -`count`始终表示尚未写入输出字符串的连续缩写字符数。 

每当我们保留一个真实字符时，我们都会首先刷新计数，确保相邻的缩写区域正确合并为一个数字。 

因为每个角色都会独立选择：

 - 缩写
 - 或保留

 递归探索了所有有效的通用缩写。 

## Python 解决方案```python
from typing import List

class Solution:
    def generateAbbreviations(self, word: str) -> List[str]:
        result = []

        def backtrack(index: int, current: str, count: int) -> None:
            if index == len(word):
                if count > 0:
                    current += str(count)

                result.append(current)
                return

            # Option 1: Abbreviate current character
            backtrack(index + 1, current, count + 1)

            # Option 2: Keep current character
            next_current = current

            if count > 0:
                next_current += str(count)

            next_current += word[index]

            backtrack(index + 1, next_current, 0)

        backtrack(0, "", 0)

        return result
```其实现紧密遵循递归决策过程。 

这`backtrack`函数从给定索引开始探索所有可能性。 

这`count`变量是关键思想。 该算法不会立即将缩写数字写入字符串，而是将它们延迟到需要时为止。 这可以防止无效的相邻数字，例如`"11"`。 

当递归到达单词末尾时，将在存储结果之前附加任何剩余的待处理计数。 

递归树每个字符恰好有两个分支：

 - 缩写它
 - 保留它

 这保证了所有有效缩写的完整枚举。 

## 解决方案```go
func generateAbbreviations(word string) []string {
    result := []string{}

    var backtrack func(index int, current string, count int)

    backtrack = func(index int, current string, count int) {
        if index == len(word) {
            if count > 0 {
                current += intToString(count)
            }

            result = append(result, current)
            return
        }

        // Option 1: Abbreviate current character
        backtrack(index+1, current, count+1)

        // Option 2: Keep current character
        nextCurrent := current

        if count > 0 {
            nextCurrent += intToString(count)
        }

        nextCurrent += string(word[index])

        backtrack(index+1, nextCurrent, 0)
    }

    backtrack(0, "", 0)

    return result
}

func intToString(num int) string {
    return fmt.Sprintf("%d", num)
}
```Go 实现遵循与 Python 版本相同的递归结构。 

一个显着的区别是整数到字符串的转换。 Go 需要使用显式格式化`fmt.Sprintf`。 

Go 中的字符串是不可变的，就像 Python 一样，因此每个递归分支都会安全地构建自己的字符串值。 

结果切片随着缩写的生成而动态增长。

 ## 边缘情况

 ### 单字符输入

 一个单字词，例如`"a"`是最小的有效输入。 

这种情况很重要，因为递归在做出一个决定后立即到达基本情况。 许多实现在递归结束时意外地错误地处理了挂起计数。 

该实现通过在附加结果之前刷新基本情况下的计数来正确处理此问题。 

### 整个单词缩写

 用于输入`"abc"`, 缩写`"3"`必须出现。 

这测试连续的缩写字符是否合并为一个计数，而不是产生无效的形式，如`"111"`。 

该实现通过将缩写长度存储在`count`变量，并且仅在必要时附加它。 

### 以缩写结尾

 用于输入`"abc"`, 缩写如`"a2"`是有效的。 

这种情况通常存在错误，因为算法可能会忘记在递归完成时附加最终计数。 

实现明确检查：```
if count > 0:
    current += str(count)
```在基本情况内部，确保正确保留尾随缩写。 

### 交替字符和计数

 输入产生缩写，例如`"1b1"`验证算法是否正确地在文字字符和缩写计数之间交替。 

这可以确保：

 - 计数在正确的时刻刷新
 - 添加字符后正确重置计数
 - 递归分支保持独立

 该实现为每个递归分支创建单独的字符串状态，防止路径之间的意外突变。
