 **难度：** 🟡 中等
 **Topics:** Array, Hash Table, Design, Queue, Simulation

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个可变数据结构来模拟经典的贪吃蛇游戏。 The game is played on a rectangular grid with dimensions`height x width`。 蛇从左上角开始`(0, 0)`并且最初有长度`1`。 

The game receives a predefined sequence of food positions. Only one food item exists on the board at a time. When the snake moves onto the current food position, two things happen:

 1. 分数增加`1`2. 蛇变长一单位

 的`move(direction)`操作使蛇在指定方向上前进一个单元格：

 -`"U"`向上移动
 -`"D"`向下移动
 -`"L"`向左移动
 -`"R"`向右移动

 每次移动后，我们必须确定蛇是否还活着。 游戏在两种情况下结束：

 - 蛇移动到网格边界之外
 - 蛇与自己的身体相撞

 碰撞规则的微妙部分极其重要。 在正常移动过程中，蛇的尾巴向前移动。 这意味着头部可以移动到尾部当前占据的单元格中，因为尾部在同一移动过程中会腾出该位置。 许多不正确的实现都在这个细节上失败了。 

输入包括：

 -`width`和`height`，定义板尺寸
 -`food`，食物坐标的有序列表
 - 多次致电`move(direction)`每个动作的输出为：

 - 如果移动有效，则当前分数
 -`-1`如果该举动导致游戏结束

 这些约束告诉我们一些重要的事情：

 - 最多`10^4`打电话给`move`- 网格尺寸也可以大到`10^4`- 食物数量相对较少，最多`50`由于可能有很多移动操作，因此每次移动都必须高效。 如果蛇变大，每次移动都会扫描整个蛇身的解决方案可能会变得太慢。 

一些边缘情况在前期很重要：

 - 移入墙内
 - 进入蛇自己的身体
 - 移动到当前尾部位置，这在非增长移动期间实际上有效
 - 正确饮食和生长
 - 当没有更多食物剩余时处理过渡
 - 保持蛇身体各部分的正确顺序

 ## 方法

 ### 蛮力方法

 一个简单的实现将明确地将蛇体存储为坐标列表。 在每一步行动中，我们都会：

 1. 计算新的头部位置
 2.检查墙壁碰撞
 3.通过扫描整个蛇体来检查自碰撞
 4. 插入新头
 5.如果没有吃食物，就把尾巴去掉

 这种方法是正确的，因为它完全按照描述直接模拟游戏机制。 

然而，自碰撞检测变得昂贵。 如果蛇有长度`k`，检查新头部是否与身体重叠需要`O(k)`时间。 由于最多可能有`10^4`移动操作，在最坏的情况下总运行时间可能会变成二次方。 

### 最佳方法

 关键的见解是碰撞检测应该是恒定时间。 

我们同时需要两种能力：

 - 从蛇体两端高效插入/移除
 - 快速隶属度测试以确定坐标是否被占用

 双端队列是维护蛇序的理想选择：

 - 前面代表头部
 - 背部代表尾巴

 哈希集非常适合占用率检查：

 -`O(1)`平均时间碰撞检测

 棘手的部分是正确处理进入尾部细胞的运动。 在正常移动期间，尾部在碰撞检查完成之前消失。 因此，我们暂时将尾部从集合中移除，然后再检查新的头部是否与身体发生碰撞。 

这为我们提供了恒定时间的移动操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次移动 O(k) | O(k) | 线性自碰撞扫描|
 | 最佳| 每次移动 O(1) | O(k) | 使用双端队列加哈希集 |

 这里，`k`是当前蛇的长度。 

## 算法演练

 1.初始化蛇体坐标`(0, 0)`。 

我们将蛇存储在双端队列中，因为我们经常添加新的头并删除尾部。 这两种操作在双端队列中都是高效的。 
2. 将所有占用的单元存储在哈希集中。 

该集合允许恒定时间碰撞检测。 每个坐标都被编码为元组或唯一的整数表示形式。 
3. 维护食物指数指针。 

由于食物是按顺序出现的，因此我们只需要跟踪当前处于活动状态的食物即可。 
4. 在每次移动过程中，确定新的头部位置。 

根据方向字符，计算下一行和下一列。 
5. 检查墙壁碰撞。 

如果新坐标位于网格边界之外，则返回`-1`。 
6、判断蛇是否吃食物。 

将新的头部坐标与当前的食物坐标进行比较。 
7、如果不吃食物，先把尾巴去掉。 

这是整个问题中最重要的细节。 尾部细胞在运动过程中变空，因此头部可以合法地移动到该位置。 
8. 使用哈希集检查自冲突。 

尾巴调整后，如果新的头已经存在于占用的集合中，则蛇与自身相撞，游戏结束。 
9. 将新头添加到双端队列和哈希集中。 

这会在成功移动后更新蛇的状态。 
10. 如果食物被吃掉，则前进食物指针并增加分数。 

在这种情况下，尾巴没有被去除，这导致蛇增长了一段。 
11. 返回当前分数。 

### 为什么它有效

 该算法维护蛇的两个同步表示：

 - 双端队列保留了主体段的确切顺序
 - 哈希集跟踪占用的单元

 在进行碰撞检查之前，尾部在非生长移动期间被移除。 这准确地反映了尾部与头部同时移开的游戏规则。 因此，随后检测到的任何碰撞都真实地代表头部进入了被占据的身体细胞。 

由于每次移动都会一致地更新两个结构，因此蛇状态始终保持正确。 

## Python 解决方案```python
from collections import deque
from typing import List, Deque, Set, Tuple

class SnakeGame:

    def __init__(self, width: int, height: int, food: List[List[int]]):
        self.width = width
        self.height = height
        self.food = food
        self.food_index = 0

        # Head is at the front
        self.snake: Deque[Tuple[int, int]] = deque([(0, 0)])

        # Stores occupied positions
        self.occupied: Set[Tuple[int, int]] = {(0, 0)}

        self.score = 0

    def move(self, direction: str) -> int:
        head_row, head_col = self.snake[0]

        if direction == "U":
            new_row, new_col = head_row - 1, head_col
        elif direction == "D":
            new_row, new_col = head_row + 1, head_col
        elif direction == "L":
            new_row, new_col = head_row, head_col - 1
        else:  # "R"
            new_row, new_col = head_row, head_col + 1

        # Check wall collision
        if (
            new_row < 0
            or new_row >= self.height
            or new_col < 0
            or new_col >= self.width
        ):
            return -1

        new_head = (new_row, new_col)

        # Check whether food is eaten
        eating_food = (
            self.food_index < len(self.food)
            and self.food[self.food_index] == [new_row, new_col]
        )

        # Remove tail first if not growing
        if not eating_food:
            tail = self.snake.pop()
            self.occupied.remove(tail)

        # Check self collision
        if new_head in self.occupied:
            return -1

        # Add new head
        self.snake.appendleft(new_head)
        self.occupied.add(new_head)

        # Handle food consumption
        if eating_food:
            self.food_index += 1
            self.score += 1

        return self.score
```该实现首先存储棋盘尺寸、食物位置和当前食物索引。 蛇身使用双端队列表示，头部始终存储在前面。 

这`occupied`哈希集反映了蛇的身体位置。 这允许恒定时间的碰撞检查。 

里面`move`，第一步是根据方向输入计算下一个头部坐标。 之后，代码立即检查棋步是否离开棋盘。 

下一个重要步骤确定蛇是否正在吃食物。 该决定控制是否应去除尾部。 如果蛇没有生长，则在自碰撞检查之前将尾巴移除。 这确保允许移动到旧的尾部位置。 

一旦冲突检测通过，新的头就会被插入到双端队列和集合中。 最后，如果食物被吃掉，分数和食物指针就会更新。 

## 解决方案```go
package main

type SnakeGame struct {
	width     int
	height    int
	food      [][]int
	foodIndex int
	score     int

	snake [][2]int
	body  map[[2]int]bool
}

func Constructor(width int, height int, food [][]int) SnakeGame {
	start := [2]int{0, 0}

	return SnakeGame{
		width:     width,
		height:    height,
		food:      food,
		foodIndex: 0,
		score:     0,
		snake:     [][2]int{start},
		body: map[[2]int]bool{
			start: true,
		},
	}
}

func (this *SnakeGame) Move(direction string) int {
	head := this.snake[0]

	newRow := head[0]
	newCol := head[1]

	switch direction {
	case "U":
		newRow--
	case "D":
		newRow++
	case "L":
		newCol--
	case "R":
		newCol++
	}

	// Wall collision
	if newRow < 0 || newRow >= this.height ||
		newCol < 0 || newCol >= this.width {
		return -1
	}

	newHead := [2]int{newRow, newCol}

	// Check if food is eaten
	eatingFood := false

	if this.foodIndex < len(this.food) {
		foodPos := this.food[this.foodIndex]

		if foodPos[0] == newRow && foodPos[1] == newCol {
			eatingFood = true
		}
	}

	// Remove tail if not growing
	if !eatingFood {
		tail := this.snake[len(this.snake)-1]
		this.snake = this.snake[:len(this.snake)-1]
		delete(this.body, tail)
	}

	// Self collision
	if this.body[newHead] {
		return -1
	}

	// Add new head
	this.snake = append([][2]int{newHead}, this.snake...)
	this.body[newHead] = true

	// Handle food
	if eatingFood {
		this.foodIndex++
		this.score++
	}

	return this.score
}

/**
 * Your SnakeGame object will be instantiated and called as such:
 * obj := Constructor(width, height, food)
 * param_1 := obj.Move(direction)
 */
```Go 实现遵循与 Python 版本相同的逻辑，但有一些特定于语言的细节。 

Go不提供内置的双端队列，因此蛇体使用切片来表示。 使用切片串联将头部插入到前面。 考虑到问题的限制，这仍然是可以接受的。 

坐标使用固定大小的数组表示`[2]int`，它们是可散列的，因此可以用作映射中的键。 

占用结构采用`map[[2]int]bool`模拟哈希集。

 ## 边缘情况

 当蛇移动到其尾巴当前占据的位置时，就会出现一种重要的边缘情况。 幼稚的实现可能会错误地将其视为自冲突。 然而，在正常移动过程中，尾巴会同时移开。 当未吃食物时，该实现通过在碰撞检测之前从占用集中移除尾部来处理此问题。 

另一个关键的边缘情况是吃食物。 当蛇吃食物时，尾巴在该回合中不得移动。 忘记这一点会导致蛇的长度保持不变。 该实现通过在吃食物时有条件地跳过尾巴去除来解决这个问题。 

墙壁碰撞是错误的另一个常见来源。 由于棋盘坐标是零索引的，因此有效行是`[0, height - 1]`有效列是`[0, width - 1]`。 该实现在更新蛇状态之前显式检查所有四个边界。 

当没有食物剩余时，就会发生一种微妙的情况。 有些实现会意外地访问超出食物列表末尾的内容。 该解决方案通过检查来防止这种情况发生`food_index < len(food)`在尝试比较食物之前。 

最后，保持双端队列和哈希集之间的同步至关重要。 它们之间的任何不一致都可能产生不可能的状态，使碰撞检查变得不正确。 该实现在每次移动时一起更新两个结构，确保它们始终代表相同的蛇体。
