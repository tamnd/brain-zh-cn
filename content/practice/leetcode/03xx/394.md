 # LeetCode 394 - 解码字符串

 ## 问题理解

 该问题给了我们一个字符串，其中包含以下形式的编码模式`k[encoded_string]`。 整数`k`告诉我们括号内的子字符串应该重复多少次。 我们的任务是完全解码字符串并返回扩展结果。 

例如，输入：```
3[a]
```表示字符串`"a"`应重复 3 次，产生：```
aaa
```这个问题变得更有趣，因为编码的子字符串可以嵌套。 考虑：```
3[a2[c]]
```内部图案`2[c]`变成`"cc"`，因此外部模式变为：```
3[acc]
```最终扩展到：```
accaccacc
```输入字符串仅由小写字母、数字和方括号组成。 该问题保证输入始终有效。 这意味着：

 - 每个左括号都有一个匹配的右括号
 - 数字总是出现在括号之前
 - 数字仅用于重复计数
 - 没有畸形的图案

 最大输入长度仅为 30 个字符，但解码输出可以变得更大，最多可达`10^5`人物。 这告诉我们，即使编码的字符串很短，我们也必须仔细有效地构建解码结果。 

一些边缘情况很重要：

 - 嵌套编码，例如`"2[a3[b]]"`- 多位数重复计数，例如`"12[a]"`- 包含编码部分之外的普通字符的字符串，例如`"abc3[cd]xyz"`- 深层嵌套级别
 - 不带括号的单字符输入

 简单的解析器在处理嵌套结构或多位数字时很容易失败，因此我们需要一种结构化方法。 

## 方法

 ### 蛮力方法

 暴力解决方案会重复搜索最里面的括号对，对其进行解码，将其替换到字符串中，然后继续，直到没有括号为止。 

例如：```
3[a2[c]]
```首先会找到：```
2[c]
```将其替换为：```
cc
```导致：```
3[acc]
```然后它会再次解码以产生：```
accaccacc
```这种方法之所以有效，是因为解码最里面的表达式首先保证嵌套表达式以正确的顺序解析。 

然而，重复扫描和重建字符串效率很低。 每次替换可能需要复制字符串的大部分。 对于深度嵌套或大量重复的输入，这会变得昂贵。 

### 最佳方法，基于堆栈的解析

 关键的观察结果是解码自然遵循嵌套结构，这使得堆栈成为理想的数据结构。 

每当我们遇到新的括号表达式时：

 - 我们保存当前部分构建的字符串
 - 我们保存重复次数
 - 我们开始构建内部子串

 当我们到达右括号时：

 - 我们完成当前的子字符串
 - 重复所需的次数
 - 将其附加回之前的字符串上下文

 这反映了嵌套表达式的数学工作方式。 

堆栈允许我们有效地暂停和恢复先前的解码上下文，而无需重复重新扫描字符串。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(n) | 反复重新扫描和字符串重建 |
 | 最佳 | O(n + 输出) | O(n + 输出) | 使用堆栈的单遍 |

 ## 算法演练

 ### 第 1 步：初始化数据结构

 我们维持：

 - 重复计数堆栈
 - 先前构建的字符串的堆栈
 - 当前正在解析的数字的变量
 - 当前解码子字符串的变量

 堆栈帮助我们在完成嵌套表达式后返回到之前的上下文。 

### 步骤 2：逐字符遍历字符串

 我们迭代输入字符串中的每个字符。 

每个角色属于以下四个类别之一：

 - 数字
 - 开口支架`[`- 闭合支架`]`- 字母字符

 ### 步骤 3：处理数字

 如果字符是数字，我们更新当前数字。 

这很重要，因为重复计数可能包含多个数字。 

例如：```
12[a]
```必须解析为`12`， 不是`1`和`2`。 

我们计算：```
current_number = current_number * 10 + digit
```### 步骤 4：处理左括号

 当我们遇到`[`，这意味着一个新的嵌套子字符串开始。 

此时：

 1.将当前重复计数压入计数栈
 2.将当前构建的字符串压入字符串栈
 3.重置当前字符串
 4.重置当前号码

 这有效地为内部子串启动了一个新的解码上下文。 

### 步骤 5：处理字母字符

 如果该字符是普通字母，则将其附加到当前子字符串。 

例子：```
current_string += char
```### 步骤 6：处理右括号

 当我们遇到`]`，当前子串已完成。 

然后我们：

 1.弹出重复计数
 2.弹出前一个字符串上下文
 3. 重复当前子串
 4. 将重复结果附加到前一个字符串

 这将逐层重建解码的字符串。 

### 步骤 7：返回最终字符串

 处理整个输入后，当前字符串包含完全解码的结果。 

### 为什么它有效

 该算法在每个嵌套级别维护正确的解码上下文。 每当新的括号开始时，当前状态都会被保存。 每当括号结束时，内部解码的子字符串就会与其父上下文组合。 由于括号是按正确的嵌套顺序处理的，因此堆栈始终会恢复正确的先前状态。 这保证了嵌套表达式被正确解码。 

## Python 解决方案```python
class Solution:
    def decodeString(self, s: str) -> str:
        count_stack = []
        string_stack = []

        current_num = 0
        current_string = ""

        for char in s:
            if char.isdigit():
                current_num = current_num * 10 + int(char)

            elif char == "[":
                count_stack.append(current_num)
                string_stack.append(current_string)

                current_num = 0
                current_string = ""

            elif char == "]":
                repeat_count = count_stack.pop()
                previous_string = string_stack.pop()

                current_string = previous_string + current_string * repeat_count

            else:
                current_string += char

        return current_string
```实现直接遵循算法。 

这`count_stack`存储嵌套表达式的重复计数。 这`string_stack`存储进入嵌套部分之前构建的字符串。 

变量`current_num`累积数字以正确处理多位重复计数。 变量`current_string`存储当前正在解码的子字符串。 

当出现左括号时，当前状态被推入堆栈，因为我们正在进入更深的嵌套级别。 然后重置当前变量以开始独立解码内部子串。 

当出现右括号时，我们弹出保存的重复计数和前一个字符串。 当前子字符串将被重复并附加到先前的上下文中。 

由于遍历发生在单次传递中，因此该算法可以有效地处理嵌套结构，而无需重新扫描字符串。 

## 解决方案```go
func decodeString(s string) string {
	countStack := []int{}
	stringStack := []string{}

	currentNum := 0
	currentString := ""

	for _, char := range s {
		if char >= '0' && char <= '9' {
			currentNum = currentNum*10 + int(char-'0')

		} else if char == '[' {
			countStack = append(countStack, currentNum)
			stringStack = append(stringStack, currentString)

			currentNum = 0
			currentString = ""

		} else if char == ']' {
			repeatCount := countStack[len(countStack)-1]
			countStack = countStack[:len(countStack)-1]

			previousString := stringStack[len(stringStack)-1]
			stringStack = stringStack[:len(stringStack)-1]

			repeated := ""
			for i := 0; i < repeatCount; i++ {
				repeated += currentString
			}

			currentString = previousString + repeated

		} else {
			currentString += string(char)
		}
	}

	return currentString
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片作为堆栈。 

Go 字符串是不可变的，因此重复连接会创建新字符串。 在问题限制内这是可以接受的，尽管在更大规模的场景中`strings.Builder`可以提高效率。 

出栈是通过切片实现的：```go
stack = stack[:len(stack)-1]
```与 Python 不同，Go 在附加字符时需要显式的符文到字符串转换。

 ## 边缘情况

 ### 多位数重复计数

 输入如下：```
12[a]
```如果独立处理数字，可能会导致错误。 一个幼稚的实现可能会将其解释为`1`其次是`2`。 

该解决方案使用以下方法正确累积数字：```
current_num = current_num * 10 + int(char)
```这可确保所有数字都组合成正确的整数值。 

### 深度嵌套编码

 输入例如：```
2[a3[b2[c]]]
```包含多个嵌套级别。 递归或管理不善的实现可能会丢失哪个子字符串属于哪个重复计数。 

基于堆栈的方法通过独立保存每个解码上下文来干净地解决这个问题。 每个左括号都会创建一个新级别，每个右括号都会正确恢复之前的级别。 

### 编码部分之外的纯字符

 输入如：```
abc3[cd]xyz
```在编码模式之前和之后包含正常字符。 

在解码括号内的部分时，有错误的实现可能会意外覆盖较早的文本。 该解决方案通过将较早的字符串存储在堆栈上并在处理括号后将解码的子字符串附加回其中来保留先前的内容。
