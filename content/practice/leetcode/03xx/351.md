[LeetCode 第 351 题](https://leetcode.com/problems/android-unlock-patterns/)

 **难度：** 🟡 中等
 **主题：** 动态规划、回溯、位操作、位掩码

 ## 解决方案

 ## 问题理解

 该问题将 Android 锁屏建模为`3 x 3`包含数字的网格`1`通过`9`。 有效的解锁图案是遵循特殊移动规则的一系列不同点。 

第一条规则很简单：每个点在图案中只能使用一次。 这意味着每个模式实际上都是唯一数字的排列。 

第二条规则是问题的核心挑战。 当从一个点移动到另一个点时，如果它们之间的直线穿过另一个点的中心，则该中间点一定已经在模式中较早访问过。 

例如：

 - 搬自`1`到`3`经过`2`， 所以`2`必须已经选择。 
- 搬自`1`到`9`经过`5`， 所以`5`必须已经选择。 
- 搬自`2`到`9`直接允许，因为该线不穿过另一个点的中心。 

输入由两个整数组成：

 -`m`, 允许的最小模式长度
 -`n`，最大允许模式长度

 目标是计算有多少个唯一的有效模式的长度介于`m`和`n`，包含在内。 

限制非常小：

 -`1 <= m, n <= 9`由于总共只有 9 个点，因此完整的搜索空间是有限且相对较小的。 然而，盲目地生成所有可能的排列仍然会产生不必要的工作，因为许多序列过早变得无效。 这表明在构建过程中修剪无效路径是有效解决方案的关键。 

一些边缘情况很重要：

 - 长度图案`1`始终有效，因为没有发生任何移动。 
- 过渡像`1 -> 3`,`1 -> 7`,`3 -> 9`， 和`7 -> 9`需要中间节点。 
- 对角线过渡，例如`1 -> 9`和`3 -> 7`要求`5`。 
- 有些动作出现对角线但不经过另一个中心，例如`2 -> 9`，因此它们立即有效。 
- 自从`n <= 9`，每个图案长度都受到可用点数的限制。 

## 方法

 ### 蛮力方法

 蛮力的想法是生成数字的所有可能的排列`1`通过`9`对于长度之间`m`和`n`。 对于每个生成的序列，我们将验证每个连续的移动是否满足 Android 锁定约束。 

这种方法是正确的，因为它详尽地检查了每个可能的候选模式并仅计算有效的模式。 

然而，它的效率很低，因为排列的数量增长很快。 尽管总搜索空间可以管理 9 位数字，但验证每个排列会浪费时间探索很早就失效的序列。 

例如，一旦我们生成`[1, 3]`，我们已经知道该模式是无效的，除非`2`之前曾访问过。 继续扩展此类无效序列是没有必要的。 

### 最佳方法

 更好的方法使用回溯和修剪。 

我们不是先生成完整排列然后再验证，而是逐步构建模式。 在每一步中，我们只选择立即有效的动作。 

关键的见解是每个受限制的移动都可以使用中间所需的节点来表示。 

例如：

-`1 -> 3`需要`2`-`1 -> 9`需要`5`-`4 -> 6`需要`5`我们可以预先计算这些关系`skip`矩阵：

-`skip[a][b] = x`意思是从`a`到`b`需要`x`已经被访问过
 -`skip[a][b] = 0`意味着不需要中间节点

 然后我们进行带回溯的DFS：

 - 跟踪访问过的节点
 - 尝试下一个有效的动作
 - 计算长度介于之间的模式`m`和`n`另一个优化来自对称性：

 -`1`,`3`,`7`,`9`是对称的
 -`2`,`4`,`6`,`8`是对称的
 -`5`是独一无二的

 因此，不要单独计算所有起始位置：

 - 计算模式从`1`并乘以`4`- 计算模式从`2`并乘以`4`- 计算模式从`5`一次

 这显着减少了重复计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(9!) | O(9) | 生成排列并随后验证 |
 | 最佳| 最坏情况为 O(9!)，实际中要小得多 | O(9) | 使用 DFS 进行剪枝和对称性优化 |

 ## 算法演练

 1. 创建一个`skip`大小矩阵`10 x 10`。 

网格使用数字`1`通过`9`，所以索引`0`为方便起见未使用。 

每个条目存储移动所需的中间节点。 

例如：

-`skip[1][3] = 2`-`skip[1][9] = 5`-`skip[7][9] = 8`如果不需要中间节点，则该值保持不变`0`。 
2. 创建一个`visited`大批。 

这会跟踪哪些点已包含在当前图案中。 

由于点不能重复，因此这种结构对于增强唯一性至关重要。 
3. 定义DFS 函数。 

DFS 函数采用：

 -`current`，当前节点
 -`remaining`，还需要添加多少个节点

 该函数返回可以从此状态形成的有效模式的数量。 
4. 处理基本情况。 

如果`remaining == 0`，那么就构建了一个完整的有效模式。 

返回`1`。 
5. 将当前节点标记为已访问。 

这可以防止稍后在递归路径中重新访问同一节点。 
6. 尝试每一个可能的下一个节点`1`到`9`。 

对于每个候选节点：

 - 如果已经访问过，请跳过它。 
- 否则检查运动有效性。 

如果满足以下条件，则移动有效：

 - 不需要中间节点，或者
 - 所需的中间节点已经被访问过

 使用以下方法检查此条件：```
skip[current][next_node] == 0
or visited[skip[current][next_node]]
```7. 递归探索有效的动作。 

对于每个有效的下一个节点：

 - 递归`remaining - 1`累积返回的计数。 
8.原路返回。 

返回之前，取消当前节点已访问的标记。 

这将恢复其他递归分支的状态。 
9. 使用对称优化。 

而不是单独从所有 9 个节点启动 DFS：

 - 计算一个角点结果并乘以 4
 - 计算一个边缘结果并乘以 4
 - 计算中心结果一次
 10. 所有长度的总结果`m`到`n`。 

对于每个有效长度：

 - 计算该精确尺寸的所有图案
 - 将它们添加到最终答案中

 ### 为什么它有效

 该算法对每个有效的解锁模式仅探索一次。 这`visited`数组保证没有重复的节点，而`skip`矩阵保证每一步都满足Android锁约束。 回溯系统地枚举所有有效序列，并且对称乘法保留正确性，因为对称起始位置产生相同的计数。 

## Python 解决方案```python
class Solution:
    def numberOfPatterns(self, m: int, n: int) -> int:
        skip = [[0] * 10 for _ in range(10)]

        skip[1][3] = skip[3][1] = 2
        skip[1][7] = skip[7][1] = 4
        skip[3][9] = skip[9][3] = 6
        skip[7][9] = skip[9][7] = 8

        skip[1][9] = skip[9][1] = 5
        skip[3][7] = skip[7][3] = 5
        skip[4][6] = skip[6][4] = 5
        skip[2][8] = skip[8][2] = 5

        visited = [False] * 10

        def dfs(current: int, remaining: int) -> int:
            if remaining == 0:
                return 1

            visited[current] = True
            patterns = 0

            for next_node in range(1, 10):
                intermediate = skip[current][next_node]

                if not visited[next_node]:
                    if intermediate == 0 or visited[intermediate]:
                        patterns += dfs(next_node, remaining - 1)

            visited[current] = False
            return patterns

        total_patterns = 0

        for length in range(m, n + 1):
            total_patterns += dfs(1, length - 1) * 4
            total_patterns += dfs(2, length - 1) * 4
            total_patterns += dfs(5, length - 1)

        return total_patterns
```实现首先构建`skip`矩阵。 该矩阵对需要中间节点的所有运动进行编码。 因此，可以在 DFS 期间以恒定的时间检查每个无效的直接跳转。 

这`visited`数组跟踪哪些节点已经是当前模式的一部分。 由于解锁图案不能重复使用点，因此该数组对于正确性至关重要。 

递归`dfs`函数探索当前节点的所有有效延续。 参数`remaining`表示还需要选择多少个节点。 当该值达到零时，就形成了完整的有效模式。 

在 DFS 循环内，每个候选下一个节点都会被测试。 如果满足以下条件，则此举是合法的：

 - 不存在中间节点，或者
 - 所需的中间节点已经被访问过

 递归完成后，当前节点将被取消标记。 这是回溯步骤，用于恢复未来递归分支的状态。 

最后，对称优化减少了冗余计算。 由于四个角的行为相同且四个边缘中心的行为相同，因此每个图案长度仅需要三次 DFS 计算。 

## 解决方案```go
func numberOfPatterns(m int, n int) int {
	skip := make([][]int, 10)
	for i := 0; i < 10; i++ {
		skip[i] = make([]int, 10)
	}

	skip[1][3], skip[3][1] = 2, 2
	skip[1][7], skip[7][1] = 4, 4
	skip[3][9], skip[9][3] = 6, 6
	skip[7][9], skip[9][7] = 8, 8

	skip[1][9], skip[9][1] = 5, 5
	skip[3][7], skip[7][3] = 5, 5
	skip[4][6], skip[6][4] = 5, 5
	skip[2][8], skip[8][2] = 5, 5

	visited := make([]bool, 10)

	var dfs func(int, int) int

	dfs = func(current int, remaining int) int {
		if remaining == 0 {
			return 1
		}

		visited[current] = true
		patterns := 0

		for nextNode := 1; nextNode <= 9; nextNode++ {
			intermediate := skip[current][nextNode]

			if !visited[nextNode] {
				if intermediate == 0 || visited[intermediate] {
					patterns += dfs(nextNode, remaining-1)
				}
			}
		}

		visited[current] = false
		return patterns
	}

	totalPatterns := 0

	for length := m; length <= n; length++ {
		totalPatterns += dfs(1, length-1) * 4
		totalPatterns += dfs(2, length-1) * 4
		totalPatterns += dfs(5, length-1)
	}

	return totalPatterns
}
```Go 实现遵循与 Python 解决方案相同的结构。 主要区别在于使用切片而不是 Python 列表。 

DFS 函数被实现为闭包，因此它可以访问共享`visited`和`skip`无需额外参数的结构。 

由于最大可能计数很容易满足 Go 的要求`int`范围内，不需要特殊的溢出处理。

 ## 边缘情况

 一种重要的边缘情况是长度模式`1`。 在这种情况下，不会发生任何移动，因此每个节点独立地形成一个有效的模式。 即使不存在转换，有缺陷的实现也可能错误地要求移动验证。 该实现正确处理了这个问题，因为 DFS 立即返回`1`什么时候`remaining == 0`。 

另一个关键的边缘情况涉及受限跳转，例如`1 -> 3`或者`1 -> 9`。 仅当中间节点已被访问时，这些移动才有效。 没有正确检查`skip`矩阵，算法会过多计算无效模式。 该实现在允许递归之前显式验证中间节点。 

第三个重要的边缘情况发生在最大递归深度附近，特别是对于`m = 9`和`n = 9`。 在这种情况下，每个节点必须恰好出现一次。 无法正确回溯的递归实现可能会意外地将节点永久标记为已访问，从而导致计数丢失。 该解决方案通过在从 DFS 返回之前始终取消标记当前节点来避免此问题。 

另一个微妙的情况涉及出现对角线但不穿过节点中心的移动，例如`2 -> 9`。 一些简单的几何实现错误地拒绝了这些移动。 这`skip`矩阵避免了这个错误，因为只对真正受限的动作进行编码。 矩阵中未列出的任何对均被视为立即有效。
